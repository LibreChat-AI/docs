El Intérprete de código ejecuta código en un entorno aislado (sandbox). Los agentes lo utilizan para realizar cálculos matemáticos que de otro modo tendrían que estimar, analizar una hoja de cálculo que subas, convertir archivos o generar gráficos y documentos. También puedes ejecutar tú mismo un bloque de código de un mensaje del chat con **Ejecutar código**.

El sandbox es un servicio independiente, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (de código abierto, Apache 2.0), que tu administrador despliega junto a LibreChat. Admite Python, Node.js (JavaScript y TypeScript), Go, C y C++, Java, PHP, Rust y Fortran.

## Dar a un agente la ejecución de código [#give-an-agent-code-execution]

En el Agent Builder, selecciona **Add** junto a **Tools** y añade **Run Code**. Guarda el agente. A partir de ese momento, el agente decide cuándo ejecutar código; no necesitas pedirlo explícitamente, aunque "usa código para comprobar esto" ayuda cuando quieres una respuesta exacta.

Mientras el código se ejecuta, el mensaje muestra una fila plegable que dice **Starting sandbox environment** la primera vez, luego **Analyzing** y **Finished analyzing** cuando termina. Expándela para ver el código que escribió el agente y su **Output**.

## Trabajar con archivos [#working-with-files]

Adjunta un archivo y elige **Subir al entorno de código** para que esté disponible en el sandbox para esa conversación. Los archivos que añadas en la configuración Run Code del agente estarán disponibles en todos los chats con ese agente. Antes de cada ejecución, LibreChat restaura los archivos de la conversación en el sandbox; si no se puede restaurar ninguno de los archivos que la ejecución necesita, la ejecución se detiene y te pide que los vuelvas a adjuntar en lugar de trabajar con copias obsoletas.

Los archivos que genera el código aparecen como filas en el mensaje. Haz clic en una fila para abrirla en el panel de [Artifacts](/docs/features/artifacts), o descárgala. Los archivos HTML, Markdown, texto plano, código fuente, CSV y de Office (Word, Excel, OpenDocument, presentaciones y plantillas de PowerPoint) muestran una vista previa en línea. Los archivos más grandes no muestran vista previa y solo se pueden descargar; el límite predeterminado es de 2 MiB de archivo fuente. Las imágenes que el agente lee desde el sandbox (PNG, JPEG, GIF, WebP) se muestran en línea hasta 1 MiB; las más grandes permanecen en el sandbox, donde el agente aún puede procesarlas.

## Ejecuta un bloque de código tú mismo [#run-a-code-block-yourself]

Los bloques de código en los mensajes del chat tienen un botón **Run Code** junto a **Copy code** cuando el lenguaje del bloque es uno que el sandbox puede ejecutar (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust o Fortran). Haz clic en él y la salida aparece debajo del bloque. Esto funciona en cualquier conversación, no solo con agentes.

## Código de larga duración [#long-running-code]

Si tu administrador ha habilitado las herramientas en segundo plano, la configuración de Ejecutar código del agente muestra **Ejecución en segundo plano**, activada de forma predeterminada. El agente puede iniciar código lento, seguir conversando contigo y recuperar la salida y los archivos cuando la ejecución termina; de forma predeterminada, el resultado llega por sí solo en un mensaje de seguimiento. Desactiva la opción para los agentes que siempre deban esperar a que termine su código.

La memoria, el tiempo de CPU, el tamaño de carga y el acceso a la red los establece quien ejecuta el servicio de sandbox, no LibreChat. Si el código falla con un error de recursos, consulta con tu administrador cuáles son los límites.

## Sesiones de código con estado [#stateful-code-sessions]

Por defecto, cada ejecución es sin estado: no cuentes con que las variables o los paquetes instalados sobrevivan a la siguiente ejecución. Las sesiones de código con estado, una función experimental que tu administrador debe activar, dan a un agente un espacio de trabajo que conserva sus archivos en `/mnt/data` entre ejecuciones. Aun así, cada ejecución inicia un proceso nuevo, y el espacio de trabajo puede restablecerse en cualquier momento, por lo que conviene tratarlo como un área temporal y no como almacenamiento.

Activa **Sesiones de código con estado** en la configuración de Ejecutar código del agente y selecciona un **Entorno con estado**:

- **Espacio de trabajo del usuario (recomendado)**: un espacio de trabajo para ti, compartido por todos los agentes con estado que utilices.
- **Espacio de trabajo del agente y del usuario**: un espacio de trabajo separado para cada agente.
- **Espacio de trabajo de conversación**: un espacio de trabajo nuevo para cada conversación.

Los nuevos agentes comienzan con el alcance definido en **Configuración > Datos y privacidad > Ejecución de código > Espacio de trabajo con estado predeterminado**; cambiar esa configuración no afecta a los agentes existentes. Los archivos que el agente crea o edita en un espacio de trabajo con estado aparecen listados en una fila **Cambios en el espacio de trabajo** de su respuesta, con una descarga para cada uno.

## Ejecutar código en tu propia máquina [#running-code-on-your-own-machine]

Los administradores también pueden ofrecer entornos de ejecución de código: una máquina virtual o una estación de trabajo que ejecuta el worker `@librechat/code`, el cual se conecta hacia LibreChat. Cuando lo hacen, el Agent Builder muestra un selector **Execution environment** y **Machines available in new chats** permite que un agente ofrezca varias máquinas para que cada nuevo chat pueda elegir una con **Choose another machine**.

Si tienes permiso para gestionar entornos de código, añade los tuyos en **Settings > Data & Privacy > Code execution > Code environments**: ponles un nombre, selecciona **Connect VM** y ejecuta en tu máquina el comando de una sola vez que se muestra. Si tu administrador habilitó la configuración desde el navegador, el comando de configuración puede abrir en su lugar una página de **Approve Machine Setup**, donde confirmas la solicitud mientras has iniciado sesión.

En una máquina conectada, el agente puede explorar, leer, buscar y editar archivos, y ejecutar comandos de shell en el espacio de trabajo seleccionado. Los adjuntos de chat que subas se copian en `.librechat/attachments` dentro de ese espacio de trabajo antes de que el agente comience. Como estas acciones modifican una máquina real, el compositor muestra un **Modo de aprobación de código** para la conversación.

- **Preguntar antes de cambios**: pregunta antes de editar archivos y ejecutar comandos.
- **Aceptar ediciones**: edita archivos sin preguntar, pero sigue pidiendo confirmación antes de ejecutar comandos.
- **Acceso completo**: edita y ejecuta comandos sin solicitudes rutinarias. Los límites del sandbox en la máquina siguen aplicándose.

Los modos que puedes elegir dependen de la política de tu administrador. Vincular una máquina autentica al worker frente a LibreChat; no aísla nada en un sandbox, así que debes aislar el worker como lo harías con cualquier máquina que ejecute código no confiable.

## Llamar herramientas de MCP desde el código [#calling-mcp-tools-from-code]

Con Programmatic Tool Calling, un agente puede llamar a herramientas MCP seleccionadas desde dentro del sandbox: escribe un script que recorre las entradas, llama a las herramientas, filtra los resultados y devuelve solo lo que importa. Esto evita un viaje de ida y vuelta por el modelo en cada llamada a una herramienta. Los interruptores de Programmatic permanecen deshabilitados hasta que el agente tenga Run Code, y al quitar Run Code se desactivan. Mientras el script se ejecuta, expande su fila para ver el registro **Tool calls**; este registro no se conserva tras recargar la página. Solo se pueden llamar de esta manera las herramientas registradas en el agente. Consulta [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling) para saber cómo marcar las herramientas.

## Configuración [#setup]

La ejecución de código requiere que un administrador despliegue el servicio Code Interpreter y apunte LibreChat hacia él; hasta entonces, las ejecuciones fallan. El botón **Run Code** y la capacidad del agente también pueden desactivarse por rol. La ejecución en segundo plano, las sesiones con estado y los entornos de código son, cada uno, opcionales. Consulta [Configuración de Code Interpreter](/docs/configuration/tools/code_interpreter).
