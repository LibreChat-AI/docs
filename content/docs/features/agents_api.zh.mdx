Agents API 让 LibreChat 外部的代码能够与你的智能体进行通信。将任意 OpenAI SDK 指向你的实例,把智能体 ID 作为 model 参数传入,即可通过熟悉的 API 获得该智能体的完整配置(指令、工具、文件)。你可以用它将智能体接入脚本、CI 任务或其他产品中。

- **推理**：Chat Completions 和 Open Responses，使用 API 密钥进行身份验证（如果管理员已配置，也可以使用您自己的 OIDC 令牌）。
- **Agent Events**：将来自其他系统（例如 webhook）的工作交给智能体处理，并跟踪其是否已完成。仅支持 API 密钥。
- **Agent Management**:使用机器 OIDC 令牌,从受信任的服务创建和编辑代理(agents)与技能(skills)。

## 获取 API key [#get-an-api-key]

打开 **设置**,进入 **数据与隐私**,在 **API 密钥** 下找到 **Agent API Keys**。点击 **管理**,然后点击 **创建 API 密钥**,为其命名,并选择过期时间(从 7 天到 1 年,或选择永不过期)。创建后请立即复制该密钥,因为它只会显示一次。

密钥代表你本人行事。任何你能通过 API 访问的内容,持有该密钥的人也都能访问,因此请删除不再使用的密钥。删除密钥会立即切断正在使用该密钥的应用程序的访问。

如果您看不到该部分,说明您的角色尚未被授予访问 Agents API 的权限。

## 你可以调用哪些智能体 [#which-agents-you-can-call]

你可以调用自己拥有的或已共享给你的智能体。对于其他人的智能体,所有者必须通过智能体构建器页脚中的 **Remote Access**(远程访问)按钮(地球图标)授予你访问权限。这与普通共享是分开的:能够在 LibreChat 中与某个智能体聊天,并不代表你可以通过 API 调用它。

您需要智能体 ID,它显示在构建器的 **Advanced Settings** 下方,并带有复制按钮。`GET /api/agents/v1/models` 会列出您的密钥可以调用的智能体,`GET /api/agents/v1/models/{model}` 则返回单个智能体。

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions` 遵循 OpenAI Chat Completions 格式,因此现有的 OpenAI 客户端只需更改基础 URL 即可使用。

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

The same request with curl:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` 实现了 [Open Responses](https://www.openresponses.org/) 规范,该规范专为智能体工作负载设计:推理、工具调用和流式事件是格式本身的一部分,而非后期附加的功能。这也是 LibreChat 今后所基于的接口,因此在新的集成中请优先使用它。

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` 返回已存储的响应,`GET /api/agents/v1/responses/models` 列出此处可用的智能体(agents)。

### 你自己的函数工具 [#your-own-function-tools]

您可以在 Responses 请求中传递标准的 `function` 工具。LibreChat 会将这些工具展示给模型,但不会运行它们:当模型选择某个工具时,响应中会包含一个 `function_call` 项,由您自行运行该函数。若要继续,请发送一个新的请求,其 `input` 中需重复该 `function_call` 项,并随后附上一个具有相同 `call_id` 的 `function_call_output`:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

在两次请求之间不会保留任何打开的状态,仅依靠 `previous_response_id` 是不够的;你必须重放该调用及其输出。工具名称可以使用字母、数字、下划线和连字符,必须唯一,且不能与智能体自身的工具同名。一轮对话中若调用了你的工具,则不能同时调用智能体的工具;系统会要求模型重试。

### 通过 API 进行工具审批 [#tool-approval-over-the-api]

如果管理员要求某些工具需要审批,API 调用无法暂停以等待任何人确认。需要审批的工具或被拒绝的工具将被直接阻止。管理员应明确允许无人值守客户端运行的工具。

## Agent 事件 [#agent-events]

Agent Events 允许另一个系统将任务交给智能体,并稍后回来查看执行结果。此功能处于测试版(beta)。事件使用您的 Agents API 密钥,该密钥用于标识您及事件来源;仅配置 OIDC 的环境无法使用此功能。此外,Agent Events 还有独立的速率限制,参见 [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits)。

一个事件会以以下三种模式之一到达:

- `fire` 会与智能体开始一段新的对话。
- `continue` 会为你之前绑定的子 Agent 添加一轮对话(见下文)。
- `steer` 会为仍在进行中的运行添加指导信息,该运行通过 `fire` 返回的会话和生成标识进行识别。

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

每个请求都需要一个 `Idempotency-Key`(1 到 256 个字符,可使用字母、数字以及 `._~:/+=-`)。重试同一次投递时请复用该值;若用于不同内容则会产生冲突。LibreChat 会根据您的 API 密钥设置事件的来源,并忽略您发送的任何来源值。负载会被存储,因此请勿在其中包含机密信息。当同一对象相关的事件必须按顺序处理时,请使用 `orderingKey`。

响应为 `202 Accepted`,并返回一个投递 ID 以及一个 `Location`,可使用相同的密钥进行轮询:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

A投递状态为 `pending`、`leased`、`succeeded` 或 `dead`。对于已绑定的 `continue`,`succeeded` 仅表示该轮次已启动。随后其 `handling` 状态会从 `started` 转变为 `applied`、`completed_no_action`、`failed` 或 `cancelled` 之一。如果你发送了 `expectedAction`(包含工具名称,以及可选的部分参数),那么 `applied` 表示 LibreChat 已确认该工具被以匹配的参数调用;模型在文本中的表述不算数。

Agent Events 并不是公开的 webhook 接收端。如果事件来自会对 webhook 进行签名的提供方,请在您自己的适配器中先验证签名,然后再转发这些事件。

### 事件驱动的子代理 [#event-driven-child-agents]

要在多个事件中持续与子智能体保持同一对话,请先建立一次绑定,然后将 `continue` 事件发送到该绑定:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

The parent must be a normal agent conversation, and the target must be one of that agent's direct subagents (or the agent itself, if self-spawn is allowed). `actorId` is up to 128 characters. A new binding returns `201` and a replay returns `200`, both with the binding `id`. Later turns reference it:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

每个绑定一次只处理一个事件:只有当前一轮达到最终处理状态后,才会处理下一个事件;不同绑定之间则并行运行。已绑定的子代理可能会因“询问用户”或工具审批而暂停,其后续事件会一直等待,直到有人在 LibreChat 中作出回应。这一机制需要持久化的 MongoDB 检查点存储器(即默认配置)。在父会话中,每个已绑定的子代理都会以一行的形式显示在拥有该绑定的消息下方,并可打开子代理活动面板。

一个绑定仅与创建它的 API 密钥、用户和租户相关联。子线程不会显示在聊天列表中,并且在应用中为只读状态。

对于仅作为观察记录的事件（例如“某局游戏已推进”），为其设置相同的 `coalesce.key`，LibreChat 会在 750 毫秒和 512 KiB 的限制内，最多将 8 个此类事件合并为一个回合。每个事件仍会生成各自的回执。命令、审批或任何带有 `expectedAction` 的事件不会被合并。

## Agent Management API [#agent-management-api]

Agent Management API 允许受信任的服务在没有浏览器会话的情况下创建、修改和删除智能体（agents）与技能（skills）。该功能处于测试版，并使用其自有的身份验证方式：来自管理员在 [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) 下列出的客户端的机器 OIDC 令牌。每个客户端都与一个现有的 LibreChat 用户和租户绑定，每个请求都以该用户的身份执行，并遵循该用户的权限和访问范围。它不会使任何人成为管理员。

| 方法 | 路由 | 用途 |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | 创建智能体 |
| `GET` | `/api/agents/v1/agents` | 列出可访问的智能体 |
| `GET` | `/api/agents/v1/agents/{id}` | 读取智能体 |
| `PATCH` | `/api/agents/v1/agents/{id}` | 更新智能体 |
| `DELETE` | `/api/agents/v1/agents/{id}` | 删除智能体 |
| `POST` | `/api/agents/v1/agents/{id}/files` | 上传并附加文件 |
| `GET` | `/api/agents/v1/agents/{id}/files` | 列出已附加的文件 |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | 分离文件 |
| `GET` | `/api/agents/v1/skills` | 列出可访问的技能 |
| `POST` | `/api/agents/v1/skills` | 创建技能 |
| `GET` | `/api/agents/v1/skills/{id}` | 读取技能 |
| `PATCH` | `/api/agents/v1/skills/{id}` | 更新技能 |
| `DELETE` | `/api/agents/v1/skills/{id}` | 删除技能 |
| `GET` | `/api/agents/v1/skills/{id}/files` | 列出技能的文件 |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | 读取技能文件 |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | 创建或替换技能文件 |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | 删除技能文件 |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agent 请求体接受与 Agent Builder 相同的字段,并会拒绝未知字段;创建时 `model` 为必填项。列表接口接受 `limit`(1 到 100,默认 20)和 `cursor`;当 `has_more` 为 true 时,将返回的 `after` 作为下一个 cursor 传入。文件上传使用 `multipart/form-data` 格式,包含一个 `file` 字段和一个 `tool_resource` 字段(如 `context`、`file_search` 或 `execute_code`),并受常规上传限制约束。

Skill create 接受 `name`、`description`、`body`，以及可选的 `displayTitle`、`frontmatter`、`category` 和 `alwaysApply`。更新时必须将技能的当前版本作为 `expectedVersion` 发送，这样两个写入方就不会相互静默覆盖。

错误使用以下代码:`invalid_request`、`not_found`、`permission_denied`、`conflict` 和 `internal_error`。您无权访问的资源可能会返回 `not_found`。凭据错误或缺失时返回 `401`。

如果管理员启用该功能,管理路由的 OpenAPI 描述将在 `/api/openapi.json` 提供,交互式文档位于 `/api/docs`。它不涵盖推理或事件相关内容。请参阅 [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi)。

## 用量与计费 [#usage-and-billing]

API 请求与应用内的聊天一样，会计入您的令牌余额。响应中的用量总计包括子智能体调用，并分别提供 `primary` 和 `subagent` 的明细，在服务提供商有报告时还包括缓存和推理令牌。参见 [令牌用量](/docs/configuration/token_usage)。

## 设置 [#setup]

在管理员通过[管理面板](/docs/features/admin_panel)或使用 [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents) 为其角色授予 Remote Agents 权限之前,普通用户无法使用 Agents API。管理员默认拥有该权限。API 密钥认证默认开启;如果要接受来自您自有 OIDC 提供商的令牌(替代或与密钥并用),请参阅 [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi)。Management API 需要在 [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) 下单独配置,事件投递相关设置位于 [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven) 下。
