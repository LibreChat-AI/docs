MCP (Model Context Protocol) est un standard ouvert permettant d'exposer des outils à un modèle. Un serveur MCP peut donner au modèle accès à un système de fichiers, à un navigateur, à une base de données ou à l'API interne de votre entreprise, et LibreChat peut utiliser n'importe quel serveur qui respecte ce protocole. Vous pouvez attacher des serveurs à une conversation classique pour un usage rapide, ou ajouter leurs outils à un agent.

## Utiliser un serveur dans le chat [#use-a-server-in-chat]

Sur tout endpoint autre qu'Agents ou Assistants, ouvrez la palette **+** du compositeur (**Joindre et outils**) et consultez la section **MCP Servers**. Cliquez sur un serveur pour l'activer pour la conversation. Il apparaît sous forme de puce sur le compositeur, et tous les outils exposés par le serveur deviennent disponibles pour le modèle. La palette reste ouverte, vous pouvez donc activer plusieurs serveurs d'un coup ; cliquez à nouveau sur un serveur, ou supprimez sa puce, pour le désactiver. Consultez [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) pour le reste de la palette.

La palette affiche quelques serveurs à la fois, avec un point coloré pour indiquer le statut de chaque serveur. **Afficher tout** dans l'en-tête **Serveurs MCP** ouvre la liste complète avec un champ de recherche et trois vues : **Tous**, **Créés par vous** et **Favoris**.

![La boîte de dialogue des serveurs MCP ouverte avec Afficher tout, listant un serveur Github marqué Déconnecté et un serveur Spotify marqué Authentification requise, avec les filtres Tous, Créés par vous et Favoris](/images/mcp/mcp_servers_catalog.png)

Si le serveur n'est pas encore connecté, un clic sur celui-ci lance la connexion au lieu de le sélectionner immédiatement. Un serveur qui nécessite vos propres identifiants ouvre d'abord une boîte de dialogue pour les saisir ; un serveur qui utilise OAuth vous redirige vers la page de connexion. Une fois connecté, LibreChat le sélectionne automatiquement pour vous.

Choisissez un modèle qui prend en charge les appels d'outils, sinon le modèle n'appellera jamais les outils du serveur. Les Agents et les Assistants disposent de leur propre configuration des outils ; le sélecteur de modèle est donc masqué sur ces points de terminaison, et un administrateur peut masquer des serveurs individuels dans le chat afin qu'ils ne soient disponibles que pour les agents.

## Ajouter un serveur à un agent [#add-a-server-to-an-agent]

Dans le Constructeur d'agents, cliquez sur **Ajouter** à côté de **Outils** pour ouvrir la **Bibliothèque d'outils**, puis filtrez par **Serveurs MCP**. L'ajout d'un serveur affiche la liste des outils qu'il expose ; conservez ceux que l'agent doit utiliser et retirez les autres, ou utilisez **Tout sélectionner** et **Tout désélectionner**. Un serveur comptant des dizaines d'outils n'occupe malgré tout qu'une seule entrée dans la liste des outils de l'agent.

Chaque outil MCP d'un agent possède aussi ses propres options (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Consultez [Agents](/docs/features/agents) pour savoir ce qu'elles modifient.

Certains serveurs dépendent de valeurs qui n'existent que pendant une requête de chat ; leurs outils ne peuvent donc pas être listés à l'avance. Pour ces serveurs, la Tool Library attache l'ensemble du serveur et indique que ses outils sont résolus à l'exécution, pendant le chat.

Si un agent est configuré pour utiliser des outils MCP et qu'aucun d'entre eux n'est disponible au démarrage d'une exécution (le serveur est hors service ou vous avez perdu l'accès), l'exécution s'arrête avec une erreur vous demandant de vérifier la connexion et vos accès, plutôt que de répondre sans les outils. Appuyer sur **Stop** pendant un appel d'outil annule également l'appel sur le serveur MCP, à condition que le serveur prenne en charge l'annulation.

## Statut de la connexion [#connection-status]

Dans la palette et dans **MCP Settings**, le statut est indiqué par un point coloré : gris lorsque le serveur est déconnecté, ambre lorsqu'il nécessite une connexion de votre part. Le statut complet est lu à voix haute par les lecteurs d'écran, et la Tool Library ainsi que la liste **Show All** l'affichent en toutes lettres à côté de chaque serveur.

- **Connecté** : prêt à l'emploi.
- **Authentification requise** : le serveur utilise OAuth et vous ne vous êtes pas connecté, ou votre connexion a expiré.
- **Connexion** / **Initialisation** : une tentative de connexion est en cours.
- **Déconnecté** ou **Erreur** : il n'y a aucune connexion active, ou la dernière tentative a échoué. Utilisez **Connecter** pour réessayer.
- **À la demande** : le serveur se connecte séparément pour chaque requête. Il n'existe donc aucune connexion permanente à signaler.
- **Inconnu** : aucun statut n'a encore été renvoyé.

Lorsqu'une connexion échoue, l'erreur indique la cause : le serveur n'a pas pu être joint, il nécessite des variables que vous n'avez pas définies (nommées dans le message), ou il vous demande de vous reconnecter. Corrigez le problème, puis connectez-vous à nouveau ; il n'est pas nécessaire de supprimer et de rajouter le serveur. Un serveur peut également ajouter ou retirer des outils pendant son exécution, et LibreChat prend en compte la nouvelle liste sans redémarrage.

Les connexions sont propres à chaque utilisateur. Vos jetons OAuth et identifiants enregistrés ne sont jamais utilisés pour quelqu'un d'autre, et une connexion inactive est fermée par défaut après 15 minutes, puis rouverte la prochaine fois que vous utilisez le serveur.

## Se connecter avec OAuth [#sign-in-with-oauth]

Lorsqu'un serveur nécessite OAuth, sa connexion ouvre une boîte de dialogue **Connect**. Cliquez sur **Continue with OAuth** pour ouvrir la page de connexion du fournisseur dans un nouvel onglet, ou utilisez **Copy link** ou **Show QR Code** pour terminer sur un autre appareil. Une fois l'accès approuvé, l'onglet affiche **Authentication Successful** puis se ferme automatiquement, et le serveur passe à **Connected**.

Pendant qu'une connexion est en attente, le serveur affiche un spinner ; survolez-le pour annuler. Dans les paramètres du serveur MCP du Créateur d'agents, **Connecter** devient **Annuler** dans le même but. Vous disposez de 10 minutes pour terminer la connexion avant que la tentative n'expire (l'administrateur peut modifier cette durée).

Si le fournisseur émet des jetons d'actualisation, LibreChat renouvelle votre accès en arrière-plan. Lorsqu'un serveur rejette votre jeton en cours de session, LibreChat tente une actualisation et une reconnexion, puis vous demande de vous reconnecter si cela échoue. Les fournisseurs qui n'émettent pas de jetons d'actualisation vous demandent de vous reconnecter à l'expiration du jeton.

Par défaut, la fenêtre de connexion apparaît lorsque votre message est envoyé. Un administrateur peut configurer certains serveurs pour qu'ils attendent que l'agent appelle pour la première fois l'un de leurs outils, afin que vous ne soyez invité à vous connecter que lorsque le serveur est réellement nécessaire.

## Identifiants et variables [#credentials-and-variables]

Certains serveurs ont besoin d'une valeur propre à chaque utilisateur, comme une clé API personnelle ou un identifiant de projet. Lorsque vous vous connectez à l'un de ces serveurs, LibreChat demande ces valeurs avant d'établir la connexion. Pour les modifier ultérieurement, utilisez **Configure** sur le serveur dans le sélecteur du chat ou dans **MCP Settings**. Chaque champ comporte les boutons **Save** et **Revoke**. L'un ou l'autre ferme votre connexion actuelle à ce serveur, de sorte que la prochaine utilisation se connectera avec les nouvelles valeurs ; révoquer désactive également le serveur dans le chat en cours.

Les valeurs sont stockées par utilisateur et ne sont envoyées qu'au serveur pour lequel elles ont été saisies.

## Panneau des paramètres MCP [#mcp-settings-panel]

**MCP Settings** dans le panneau latéral répertorie chaque serveur que vous pouvez utiliser, avec un point de statut sur l'icône de chaque serveur. Selon l'état du serveur, chaque carte propose **Connect**, **Reconnect**, **Configure** (pour vos variables) ou **Revoke** (pour supprimer vos jetons OAuth). Les serveurs que vous êtes autorisé à modifier disposent également de **Edit**.

## Créer un serveur depuis l'interface utilisateur [#create-a-server-from-the-ui]

Si votre rôle le permet, cliquez sur **Add MCP** (le bouton **+**) dans **MCP Settings** pour enregistrer un serveur distant sans modifier `librechat.yaml` ni redémarrer.

<Steps>
<Step>
### Décrire le serveur [#describe-the-server]

Saisissez un **Nom**, une **Description** facultative et une icône si vous le souhaitez. Renseignez l'**URL du serveur MCP** et choisissez un **Transport** : **Streamable HTTPS** ou **SSE**.
</Step>
<Step>
### Choisir l'authentification [#choose-authentication]

Sous **Authentification**, choisissez l'une des options suivantes :

- **Aucun (détection automatique)** : LibreChat sonde le serveur et passe à OAuth si celui-ci le demande.
- **Clé API** : saisissez une clé partagée, ou cochez **Chaque utilisateur fournit sa propre clé** afin que chaque utilisateur saisisse la sienne via **Configurer**. Choisissez le **Format d'en-tête** : **Bearer**, **Basic**, ou **Personnalisé** avec le nom d'en-tête de votre choix.
- **OAuth** : saisissez le **Client ID**, le **Client Secret**, l'**Authorization URL**, la **Token URL** et le **Scope**. Laissez les champs du client vides si le fournisseur prend en charge l'enregistrement dynamique de client. La **Token Exchange Method** est définie sur **Auto** par défaut : elle utilise la méthode annoncée par le fournisseur et se replie sur un en-tête d'autorisation Basic en cas d'échec. Choisissez **Default (POST request)** ou **Basic authorization header** pour forcer l'une des deux méthodes.
- **On-Behalf-Of (OBO)** : affiché uniquement si un administrateur vous a accordé cette permission, et ne fonctionne que lorsque LibreChat authentifie les utilisateurs avec OpenID Connect (par exemple Entra ID). Saisissez les scopes à demander ; LibreChat échange votre jeton OpenID contre un jeton limité au serveur MCP.
</Step>
<Step>
### Créer-le [#create-it]

Cochez **I trust this application** et cliquez sur **Create**. Le serveur est disponible immédiatement. Pour les serveurs OAuth, la boîte de dialogue suivante affiche le **Redirect URI** à enregistrer auprès de votre fournisseur OAuth, et le serveur reste déconnecté tant que vous ne vous êtes pas connecté une fois.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="La boîte de dialogue Ajouter un serveur MCP avec un nom et une URL renseignés, Transport défini sur Streamable HTTPS, et Authentification défini sur Clé API avec Chaque utilisateur fournit sa propre clé coché"
/>

Les serveurs créés de cette manière ne peuvent atteindre que des URL distantes ; les serveurs `stdio` locaux doivent être définis dans `librechat.yaml`. Ils ne peuvent pas non plus utiliser les variables d'environnement du serveur ni les espaces réservés de profil utilisateur : les valeurs telles que `${API_TOKEN}` ou `{{LIBRECHAT_USER_EMAIL}}` figurant dans leurs en-têtes sont supprimées, car un serveur partagé recevrait sinon ces valeurs. Si vous modifiez ultérieurement l'URL ou l'authentification d'un serveur, les utilisateurs ayant saisi leur propre clé doivent la saisir à nouveau, et les utilisateurs OAuth doivent se reconnecter. Lorsque vous modifiez l'URL ou les points de terminaison OAuth d'un serveur disposant d'un secret client enregistré, vous devez également saisir à nouveau le secret. Si un serveur à clé API créé avec une version antérieure reste bloqué sur **Needs Auth**, ouvrez-le avec **Edit** et enregistrez-le une fois.

## Partager un serveur [#share-a-server]

Les serveurs créés dans l'interface appartiennent à la personne qui les a créés. Le propriétaire peut en partager un depuis sa boîte de dialogue **Modifier** avec des utilisateurs, des groupes, des rôles ou tout le monde, avec le rôle de lecteur (peut le voir et l'utiliser), d'éditeur (peut également le modifier) ou de propriétaire. Les serveurs définis dans `librechat.yaml` sont disponibles pour tous les utilisateurs autorisés à utiliser MCP. Consultez [Contrôle d'accès](/docs/features/access_control) pour savoir comment les niveaux d'autorisation se combinent.

## Instructions du serveur [#server-instructions]

Un administrateur peut associer des instructions à un serveur, soit les instructions propres au serveur, soit un texte personnalisé. Lorsqu'une conversation ou un agent dispose des outils de ce serveur, ces instructions sont ajoutées au contexte du modèle, ce qui est utile pour les serveurs dont les outils n'ont de sens que s'ils sont utilisés dans un ordre précis.

## Applications MCP [#mcp-apps]

Certains serveurs renvoient une vue interactive avec un résultat d'outil. Lorsque les MCP Apps sont activées, l'appel d'outil affiche un bouton **Open app**, qui charge la vue dans un cadre isolé (sandbox), et **Close app**, qui la masque à nouveau. Seules quelques applications peuvent être ouvertes en même temps ; si vous atteignez la limite, fermez d'abord une application.

Une application ne peut pas agir de sa propre initiative. Lorsqu'elle souhaite exécuter un outil, vous voyez **Run tool from app?**, et lorsqu'elle souhaite publier un message, **Send message from app?**. Rien ne se produit tant que vous n'avez pas approuvé. L'envoi d'un message lance une réponse du modèle dans la conversation en cours, de sorte que l'agent sélectionné et ses outils peuvent être utilisés. Les applications ne s'affichent pas dans les conversations partagées.

## Configuration [#setup]

MCP nécessite au moins un serveur. Les administrateurs définissent les serveurs sous `mcpServers` dans `librechat.yaml`, ce qui nécessite un redémarrage pour être appliqué, et les utilisateurs disposant des autorisations nécessaires peuvent ajouter des serveurs distants depuis **MCP Settings**. Consultez [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) pour les options de serveur, l'URL de rappel OAuth et les transports, [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) pour les domaines autorisés et les MCP Apps, [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) pour les limites des applications, et [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) pour savoir qui peut utiliser, créer et partager des serveurs. Les guides de configuration de serveurs spécifiques se trouvent sous [MCP Servers](/docs/mcp_servers), et [Agent Plugins](/docs/features/agent_plugins) explique comment regrouper des serveurs MCP avec des compétences.
