MCP (Model Context Protocol) es un estándar abierto para exponer herramientas a un modelo. Un servidor MCP puede darle al modelo acceso a un sistema de archivos, a un navegador, a una base de datos o a la API interna de tu empresa, y LibreChat puede usar cualquier servidor que hable el protocolo. Puedes adjuntar servidores a un chat normal para un uso rápido, o añadir sus herramientas a un agente.

## Usar un servidor en el chat [#use-a-server-in-chat]

En cualquier endpoint distinto de Agents o Assistants, abre la paleta **+** del compositor (**Adjuntar y herramientas**) y busca en **Servidores MCP**. Haz clic en un servidor para activarlo en la conversación. Aparecerá como un chip en el compositor, y todas las herramientas que exponga el servidor estarán disponibles para el modelo. La paleta permanece abierta, por lo que puedes activar varios servidores de una vez; haz clic de nuevo en un servidor, o elimina su chip, para desactivarlo. Consulta [Compositor](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) para ver el resto de la paleta.

La paleta muestra algunos servidores a la vez, con un punto de color para el estado de cada servidor. **Mostrar todos** en el encabezado **MCP Servers** abre la lista completa con un campo de búsqueda y tres vistas: **Todos**, **Creados por ti** y **Favoritos**.

![El cuadro de diálogo de servidores MCP abierto con Mostrar todos, que muestra un servidor de Github marcado como Desconectado y un servidor de Spotify marcado como Requiere autenticación, con los filtros Todos, Creados por ti y Favoritos](/images/mcp/mcp_servers_catalog.png)

Si el servidor aún no está conectado, al hacer clic en él se inicia la conexión en lugar de seleccionarlo de inmediato. Un servidor que requiere tus propias credenciales abre un cuadro de diálogo para que las introduzcas primero; un servidor que usa OAuth te redirige al inicio de sesión. Una vez conectado, LibreChat lo selecciona por ti.

Elige un modelo que admita llamadas a herramientas; de lo contrario, el modelo nunca llamará a las herramientas del servidor. Los Agentes y los Asistentes tienen su propia configuración de herramientas, por lo que el selector se oculta en esos endpoints, y un administrador puede ocultar servidores individuales del chat para que solo estén disponibles para los agentes.

## Añadir un servidor a un agente [#add-a-server-to-an-agent]

En el Agent Builder, haz clic en **Add** junto a **Tools** para abrir la **Tool Library**, y luego filtra por **MCP servers**. Al agregar un servidor, se muestran las herramientas que expone; conserva las que el agente debe tener y elimina el resto, o usa **Select all** y **Deselect all**. Un servidor con decenas de herramientas sigue ocupando una única entrada en la lista de herramientas del agente.

Cada herramienta MCP de un agente también tiene sus propias opciones (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Consulta [Agents](/docs/features/agents) para ver qué cambian.

Algunos servidores dependen de valores que solo existen durante una solicitud de chat, por lo que sus herramientas no pueden listarse de antemano. Para estos casos, la Biblioteca de Herramientas adjunta el servidor completo y señala que sus herramientas se resuelven en tiempo de ejecución, durante el chat.

Si un agente está configurado para usar herramientas MCP y ninguna de ellas está disponible cuando se inicia una ejecución (el servidor no funciona o perdiste el acceso), la ejecución se detiene con un error que te indica que revises la conexión y tu acceso, en lugar de responder sin las herramientas. Al presionar **Stop** durante una llamada a una herramienta, también se cancela la llamada en el servidor MCP, siempre que el servidor admita la cancelación.

## Estado de la conexión [#connection-status]

En la paleta y en **MCP Settings**, el estado se muestra como un punto de color: gris cuando el servidor está desconectado, ámbar cuando necesita que inicies sesión. El estado completo se anuncia a los lectores de pantalla, y la Tool Library y la lista **Show All** lo indican con texto junto a cada servidor:

- **Conectado**: listo para usar.
- **Necesita autenticación**: el servidor usa OAuth y no has iniciado sesión, o tu sesión caducó.
- **Conectando** / **Inicializando**: hay un intento de conexión en curso.
- **Desconectado** o **Error**: no hay una conexión activa, o el último intento falló. Usa **Conectar** para volver a intentarlo.
- **Bajo demanda**: el servidor se conecta por separado para cada solicitud, por lo que no hay una conexión permanente que informar.
- **Desconocido**: aún no se ha recibido ningún estado.

Cuando una conexión falla, el error indica el motivo: el servidor no pudo ser alcanzado, necesita variables que no has configurado (que se mencionan en el mensaje), o necesita que vuelvas a iniciar sesión. Corrige eso y vuelve a conectarte; no es necesario eliminar y volver a añadir el servidor. Un servidor también puede añadir o quitar herramientas mientras se ejecuta, y LibreChat detecta la nueva lista sin necesidad de reiniciar.

Las conexiones son por usuario. Tus tokens de OAuth y tus credenciales guardadas nunca se usan para nadie más, y una conexión inactiva se cierra por defecto tras 15 minutos y se vuelve a abrir la próxima vez que uses el servidor.

## Iniciar sesión con OAuth [#sign-in-with-oauth]

Cuando un servidor necesita OAuth, al conectarlo se abre un cuadro de diálogo **Connect**. Haga clic en **Continue with OAuth** para abrir la página de inicio de sesión del proveedor en una nueva pestaña, o use **Copy link** o **Show QR Code** para completar el proceso en otro dispositivo. Después de aprobar el acceso, la pestaña muestra **Authentication Successful** y se cierra automáticamente, y el servidor cambia a **Connected**.

Mientras un inicio de sesión está pendiente, el servidor muestra un indicador de carga; pásale el cursor encima para cancelarlo. En la configuración del servidor MCP del Agent Builder, **Connect** cambia a **Cancel** con el mismo propósito. Tienes 10 minutos para completar el inicio de sesión antes de que el intento caduque (el administrador puede cambiar este tiempo).

Si el proveedor emite tokens de actualización, LibreChat renueva tu acceso en segundo plano y, cuando un servidor rechaza tu token durante la sesión, intenta una actualización y una reconexión antes de pedirte que vuelvas a iniciar sesión. Los proveedores que no emiten tokens de actualización te piden que vuelvas a iniciar sesión cuando el token expira.

Por defecto, la solicitud de inicio de sesión aparece cuando se envía tu mensaje. Un administrador puede configurar algunos servidores para que esperen a que el agente llame por primera vez a una de sus herramientas, de modo que solo se te pida iniciar sesión cuando el servidor realmente sea necesario.

## Credenciales y variables [#credentials-and-variables]

Algunos servidores necesitan un valor de cada usuario, como una clave de API personal o un ID de proyecto. Cuando conectas uno de estos servidores, LibreChat solicita los valores antes de establecer la conexión. Para cambiarlos más adelante, usa **Configure** en el servidor, ya sea en el selector del chat o en **MCP Settings**. Cada campo tiene **Save** y **Revoke**. Cualquiera de las dos acciones cierra tu conexión actual con ese servidor, de modo que el siguiente uso se conectará con los nuevos valores; además, revocar también desactiva el servidor en el chat actual.

Los valores se almacenan por usuario y solo se envían al servidor para el que fueron introducidos.

## Panel de configuración de MCP [#mcp-settings-panel]

**Configuración de MCP** en el panel lateral enumera todos los servidores que puedes usar, con un punto de estado en el icono de cada servidor. Según el estado del servidor, cada tarjeta ofrece **Conectar**, **Reconectar**, **Configurar** (para tus variables) o **Revocar** (para eliminar tus tokens de OAuth). Los servidores que tienes permiso para editar también tienen **Editar**.

## Crear un servidor desde la interfaz [#create-a-server-from-the-ui]

Si tu rol lo permite, haz clic en **Add MCP** (el botón **+**) en **MCP Settings** para registrar un servidor remoto sin modificar `librechat.yaml` ni reiniciar.

<Steps>
<Step>
### Describir el servidor [#describe-the-server]

Ingresa un **Nombre**, una **Descripción** opcional y un ícono si lo deseas. Completa la **URL del servidor MCP** y elige un **Transporte**: **Streamable HTTPS** o **SSE**.
</Step>
<Step>
### Elegir autenticación [#choose-authentication]

En **Authentication**, elige una de las siguientes opciones:

- **Ninguno (detección automática)**: LibreChat sondea el servidor y cambia a OAuth si el servidor lo solicita.
- **Clave de API**: introduce una clave compartida, o marca **Cada usuario proporciona su propia clave** para que cada usuario introduzca la suya mediante **Configurar**. Elige el **Formato de encabezado**: **Bearer**, **Basic** o **Custom** con el nombre de encabezado que prefieras.
- **OAuth**: introduce el **Client ID**, el **Client Secret**, la **Authorization URL**, la **Token URL** y el **Scope**. Deja los campos de cliente vacíos si el proveedor admite el registro dinámico de clientes. El **Token Exchange Method** está en **Auto** por defecto, que utiliza lo que anuncie el proveedor y recurre a un encabezado de autorización Basic; elige **Default (POST request)** o **Basic authorization header** para forzar uno de ellos.
- **On-Behalf-Of (OBO)**: solo se muestra si un administrador te concedió ese permiso, y solo funciona cuando LibreChat inicia la sesión de los usuarios con OpenID Connect (por ejemplo, Entra ID). Introduce los scopes que quieres solicitar; LibreChat intercambia tu token de OpenID por uno con scope para el servidor MCP.
</Step>
<Step>
### Crear [#create-it]

Marque **Confío en esta aplicación** y haga clic en **Crear**. El servidor está disponible de inmediato. Para servidores OAuth, el siguiente cuadro de diálogo muestra el **Redirect URI** que debe registrar en su proveedor OAuth, y el servidor permanece desconectado hasta que inicie sesión una vez.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="El diálogo Add MCP Server con un nombre y una URL completados, Transport configurado como Streamable HTTPS y Authentication configurado como API Key con Each user provides their own key marcado"
/>

Los servidores creados de esta manera solo pueden conectarse a URL remotas; los servidores `stdio` locales deben definirse en `librechat.yaml`. Tampoco pueden usar variables de entorno del servidor ni marcadores de perfil de usuario: los valores como `${API_TOKEN}` o `{{LIBRECHAT_USER_EMAIL}}` en sus encabezados se eliminan, ya que un servidor compartido los recibiría de otro modo. Si cambias más adelante la URL o la autenticación de un servidor, los usuarios que introdujeron su propia clave deberán volver a introducirla, y los usuarios de OAuth deberán iniciar sesión de nuevo. Cuando cambies la URL o los endpoints de OAuth de un servidor que tiene un client secret guardado, también tendrás que volver a introducir el secret. Si un servidor con clave de API creado con una versión anterior se queda bloqueado en **Needs Auth**, ábrelo con **Edit** y guárdalo una vez.

## Compartir un servidor [#share-a-server]

Los servidores creados en la interfaz pertenecen a quien los creó. El propietario puede compartir uno desde su cuadro de diálogo **Edit** con usuarios, grupos, roles o todos, con el rol de visor (puede verlo y usarlo), editor (también puede modificarlo) o propietario. Los servidores definidos en `librechat.yaml` están disponibles para todos los que tengan permiso para usar MCP. Consulta [Access Control](/docs/features/access_control) para ver cómo se combinan los niveles de permiso.

## Instrucciones del servidor [#server-instructions]

Un administrador puede adjuntar instrucciones a un servidor, ya sean las propias del servidor o un texto personalizado. Cuando una conversación o un agente cuenta con las herramientas de ese servidor, las instrucciones se añaden al contexto del modelo, lo que resulta útil para servidores cuyas herramientas solo tienen sentido si se usan en un orden determinado.

## Aplicaciones MCP [#mcp-apps]

Algunos servidores devuelven una vista interactiva junto con el resultado de una herramienta. Cuando las MCP Apps están activadas, la llamada a la herramienta muestra un botón **Open app**, que carga la vista en un marco aislado (sandbox), y **Close app**, que la oculta de nuevo. Solo se pueden tener abiertas algunas aplicaciones a la vez; si alcanzas el límite, cierra primero una de ellas.

Una aplicación no puede actuar por sí sola. Cuando quiere ejecutar una herramienta, verás **¿Ejecutar herramienta desde la aplicación?**, y cuando quiere publicar un mensaje, **¿Enviar mensaje desde la aplicación?**. No pasa nada hasta que lo apruebes. Enviar un mensaje inicia una respuesta del modelo en la conversación actual, por lo que es posible que se utilicen el agente seleccionado y sus herramientas. Las aplicaciones no se muestran en las conversaciones compartidas.

## Configuración [#setup]

MCP necesita al menos un servidor. Los administradores definen los servidores en `mcpServers` dentro de `librechat.yaml`, lo que requiere reiniciar para aplicar los cambios, y los usuarios con permiso pueden agregar servidores remotos desde **MCP Settings**. Consulta [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) para las opciones de servidor, la URL de callback de OAuth y los transportes; [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) para los dominios permitidos y MCP Apps; [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) para los límites de las apps; y [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) para saber quién puede usar, crear y compartir servidores. Las guías de configuración de servidores específicos se encuentran en [MCP Servers](/docs/mcp_servers), y [Agent Plugins](/docs/features/agent_plugins) explica cómo agrupar servidores MCP con skills.
