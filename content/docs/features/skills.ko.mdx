스킬은 `SKILL.md` 파일입니다. 스킬에는 스킬이 언제 적용되는지를 설명하는 짧은 프런트매터 블록과 지침이 담긴 마크다운 본문이 있습니다. 스타일 가이드, 코드 리뷰 체크리스트, 반복되는 보고서의 작성 단계처럼 채팅에 계속 붙여넣게 되는 내용이라면 스킬로 만들어 두고 사용하세요. 에이전트는 관련이 있을 때에만 스킬을 불러오므로, 모든 프롬프트를 불필요하게 늘리지 않고도 많은 스킬을 보관해 둘 수 있습니다.

LibreChat에는 기본으로 제공되는 스킬이 없습니다. 각 스킬은 사용자가 작성하거나 업로드하거나, 채팅 중 에이전트가 생성하거나, 관리자가 제공합니다.

## 스킬 만들기 [#create-a-skill]

사이드 패널에서 **Skills**를 연 다음 **+**를 클릭하세요. 편집기에서 직접 작성하려면 **Write skill instructions**를 선택하고, `SKILL.md` 파일이 포함된 `.md` 파일 또는 `.zip`이나 `.skill` 아카이브를 가져오려면 **Upload a skill**을 선택하세요. 사이드 패널에 Skills가 보이지 않는다면 관리자가 이 기능을 비활성화했거나 현재 역할로는 사용할 수 없는 상태입니다.

A minimal skill:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing copy that must follow the company voice and terminology.
---

Write in a concise, practical tone.
Prefer active voice.
Say "workspace", never "project space".
```

이름은 케밥 케이스(소문자 알파벳, 숫자, 대시)여야 하며, 최대 64자이고, 사용자의 다른 스킬 사이에서 고유해야 합니다. 이미 사용 중인 이름으로 스킬을 업로드하면 기존 스킬을 덮어쓰지 않고 실패합니다. `anthropic-` 또는 `claude-`로 시작하는 이름과 `help`, `settings`와 같은 명령어는 예약되어 있습니다.

설명은 파일에서 다른 무엇보다 중요합니다. 모델은 이 설명을 읽고 스킬이 적용되는지 판단하기 때문입니다. "Use when writing release notes for the mobile app"이라고 쓰면 스킬이 호출되지만, "Writing helper"라고 쓰면 호출되지 않습니다. 트리거 문구를 맨 앞에 두고 250자 미만으로 유지하세요. 모델이 보는 목록에서는 더 긴 설명이 잘리기 때문입니다. 설명의 최대 길이는 1,024자, 본문의 최대 길이는 100,000자입니다.

### Frontmatter 옵션 [#frontmatter-options]

스킬에는 `name`과 `description` 외에도 다음 항목을 설정할 수 있습니다:

- `always-apply: true`: 모델이 요청할 때까지 기다리지 않고, 매 턴마다 스킬을 로드합니다.
- `user-invocable: false`: `$` 메뉴에서 숨깁니다.
- `disable-model-invocation: true`: 모델이 선택하는 목록에서 제외합니다. 여전히 `$`로 호출할 수 있습니다.
- `allowed-tools`: 스킬이 `$`로 호출되거나 항상 적용될 때, 에이전트가 평소에는 가지고 있지 않더라도 해당 턴에 사용할 수 있도록 부여되는 도구 목록입니다(예: `["execute_code"]`).
- `compatibility`: 스킬에 필요한 사항(예: 특정 MCP 서버)을 기술하는 자유 형식 메모입니다. LibreChat은 이 값을 보관하지만 강제하지는 않습니다.

`when-to-use`는 `description`을 대신하며, `alwaysApply`는 `always-apply`를 대신합니다. 키는 대소문자를 구분하지 않으며, 추가한 다른 키는 메타데이터로 유지됩니다.

### 번들된 파일 [#bundled-files]

스킬은 둘 이상의 파일을 포함할 수 있습니다. 일반적인 구조는 긴 문서를 위한 `references/`, 에이전트가 실행할 수 있는 코드를 위한 `scripts/`, 템플릿을 위한 `assets/`입니다. 에이전트는 스킬이 사용 중일 때 이러한 파일을 읽으므로, `SKILL.md`는 간결하게 유지하고 이 파일들을 가리키도록 할 수 있습니다. 코드 실행(Run Code)이 켜져 있으면 이 파일들은 샌드박스의 `/mnt/data/skills/<skill-name>/` 경로에서도 사용할 수 있습니다. 스킬 뷰어에서는 스킬의 Markdown 파일 간 상대 링크를 클릭하면 연결된 파일이 열립니다.

아카이브에서 `SKILL.md`는 최상위 수준이나 정확히 하나의 폴더 안에 있어야 합니다. 업로드는 기본적으로 50 MB로 제한되며(관리자가 이 값을 변경할 수 있습니다), 파일은 최대 500개, 파일당 최대 10 MB입니다. 안전하지 않은 경로를 가진 파일은 건너뛰고 그 사실이 보고됩니다. 번들 파일이 포함된 스킬은 Skills 사이드바에서 이름 옆에 화살표가 표시되며, 이를 펼치면 파일을 찾아보고 파일을 열 수 있습니다.

## 스킬 사용하기 [#use-a-skill]

스킬이 대화에 전달되는 방식은 세 가지가 있습니다:

- **원하는 스킬을 직접 선택하세요.** 채팅 입력창에 `$`를 입력한 다음 스킬을 선택하세요. 입력한 텍스트에는 아무것도 추가되지 않으며, 선택한 스킬은 입력창 위에 칩(chip) 형태로 표시되고 해당 메시지에 대해 로드됩니다.
- **모델이 선택합니다.** 에이전트는 사용 가능한 스킬의 이름과 설명을 확인하고, 요청이 스킬과 일치하면 해당 스킬을 로드합니다.
- **항상 적용됩니다.** `always-apply: true`가 설정된 Skills는 모든 턴에서 로드됩니다.

스킬이 로드되는 동안 메시지에는 **Loading**과 함께 스킬 이름이 표시되며, 스킬이 컨텍스트에 포함되면 **Loaded**가 표시됩니다.

모델은 목록에 있는 이름과 설명만 보며(최대 100개 스킬), 지침은 보지 못합니다. 직접 선택했거나 항상 적용되는 스킬은 해당 턴에 전체 `SKILL.md`를 불러옵니다. 한 턴에는 최대 10개의 선택 스킬과 20개의 항상 적용 스킬, 총 30개까지 포함될 수 있습니다. 이를 초과하면 항상 적용 스킬부터 제외됩니다.

## 에이전트가 사용할 수 있는 스킬 [#which-skills-an-agent-can-use]

두 가지가 결정합니다.

먼저, 내 목록에서. 각 스킬에는 **Available to agent** 스위치가 있습니다. 이 스위치를 끄면 스킬은 삭제되지 않고 `$` 메뉴, 모델이 선택할 수 있는 항목, 그리고 항상 적용(always-apply)에서 사라집니다. 직접 만든 스킬은 기본적으로 켜진 상태로 시작합니다. 다른 사용자가 공유한 스킬은 관리자가 공유 스킬을 기본 활성화하도록 설정하지 않았다면 꺼진 상태로 시작합니다.

둘째, 에이전트입니다. 에이전트 빌더의 **Skills** 섹션에는 세 가지 설정이 있습니다:

- **Off**: 에이전트는 어떤 스킬도 사용하지 않습니다.
- **All**: 활성화한 모든 스킬.
- **선택됨**: 목록에 추가한 스킬만 해당됩니다.

**Selected**는 집중된 에이전트에 더 나은 선택입니다. 40개의 스킬 중에서 고르게 되는 지원 에이전트는 필요한 3개만 가진 에이전트보다 잘못된 스킬을 선택할 가능성이 더 높습니다.

## 에이전트가 작성한 스킬 [#skills-written-by-agents]

스킬이 활성화된 에이전트는 작업 중에 스킬을 직접 작성할 수도 있습니다. 예를 들어 방금 성공적으로 수행한 절차를 저장하는 식입니다. 역할에 스킬 생성 권한이 있으면 새 스킬을 만들 수 있고, 기존 스킬을 편집할 권한이 있고 해당 스킬이 에이전트의 범위에 포함되어 있을 때만 편집할 수 있습니다. 관리자가 제공한 스킬은 읽기 전용으로 유지됩니다. **Selected**를 선택하고 목록이 비어 있으면, 에이전트는 기존 스킬을 하나도 볼 수 없지만 새 스킬은 여전히 생성할 수 있습니다.

## 공유 [#sharing]

Skills는 에이전트 및 프롬프트와 같은 방식으로 공유되며, Viewer(사용 가능, 편집 불가), Editor, Owner 역할이 있습니다. 공유하려면 사용자 역할에 share 권한이 필요하며, 이 권한은 일반 사용자에게 기본적으로 비활성화되어 있습니다. [액세스 제어](/docs/features/access_control)를 참조하십시오.

관리자는 서버 파일 시스템, [Agent Plugins](/docs/features/agent_plugins), 또는 GitHub 저장소에서 미러링한 스킬도 제공할 수 있습니다. 이러한 스킬은 LibreChat에서 읽기 전용이며, 변경하려면 원본에서 수정해야 합니다. 파일 시스템과 플러그인의 스킬은 기본적으로 켜진 상태로 시작합니다.

## 설정 [#setup]

모든 사용자에게 Skills 기능이 기본적으로 활성화되어 있습니다. 관리자는 `skills` 에이전트 기능(자세한 내용은 [에이전트 엔드포인트 구성](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) 참조)을 사용하여 이 기능을 끌 수 있습니다. [관리자 패널](/docs/features/admin_panel) 또는 [`interface.skills`](/docs/configuration/librechat_yaml/object_structure/interface#skills)에서 Skills를 생성하고 공유할 수 있는 사용자를 제어할 수 있습니다. [Skill Sync](/docs/configuration/librechat_yaml/object_structure/skill_sync)에 설명된 대로 디스크 또는 GitHub에서 Skills를 제공할 수 있으며, [`fileConfig.skills`](/docs/configuration/librechat_yaml/object_structure/file_config#skills)를 사용하여 업로드 크기 제한을 변경할 수 있습니다.
