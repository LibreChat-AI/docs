アクセス制御は3つのことを決定します。ユーザーが利用できる機能、特定のエージェント、プロンプト、MCPサーバー、スキルを誰が閲覧または変更できるか、そして誰に管理者権限を与えるかです。小規模なチームであれば、デフォルトのままにして自由に共有することができます。大規模な環境では、ロールごとに機能を制限したり、Entra IDから同期されたグループと共有したり、完全な管理者アカウントを渡さずに管理の一部を委任したりできます。

## ユーザー、グループ、ロール、そして全員 [#users-groups-roles-and-everyone]

権限は4種類のプリンシパル(主体)に付与されます:

- A user, meaning one LibreChat account.
- ユーザーのグループです。グループは管理者が作成するか、OpenID トークン再利用を有効にした状態で Entra ID 経由でユーザーがサインインした際に Entra ID から同期されます。グループへの共有は 1 件のエントリとして扱われ、Entra ID でのメンバーシップの変更は、各メンバーが次回ログインした時点で反映されます。
- ユーザーには必ず1つのロールが割り当てられます。デフォルトは `USER` です。シングルテナントのインスタンスで最初に作成されたアカウントは `ADMIN` になります。また、管理者が作成したカスタムロールが割り当てられる場合もあります。ロールを指定して共有すると、そのロールを現在保持しているすべてのユーザーに共有されます。
- 全員、つまりインスタンスにサインインしているすべてのユーザーを指します。

## 機能の権限 [#feature-permissions]

各ロールには、機能ごとのオン/オフのスイッチが用意されています。具体的には、そのロールのユーザーがエージェントを利用できるか、作成できるか、特定のユーザーと共有できるか、全員と共有できるかといった設定です。プロンプト、MCPサーバー、スキル、共有リンクについても同様です。その他のスイッチでは、スケジュールチャット、メモリ、ブックマーク、一時チャット、マルチ会話、コードインタープリター、ウェブ検索、ファイル検索、引用、Agent Marketplace、人物ピッカーを制御できます。

スイッチがオフの場合、そのロールに対応するUIの部分は表示されなくなります。エージェントを作成する権限がないユーザーには、エージェント作成のオプションが表示されません。「全員と共有」の権限がないユーザーには、**全員と共有**のトグルが表示されません。

デフォルトでは、ユーザーはエージェント、プロンプト、MCPサーバー、スキルを使用および作成できますが、共有はできません。共有は管理者が有効にする必要があります。デフォルト値を含む完全な一覧は、[アクセス制御の設定](/docs/configuration/access_control#feature-permissions)ページにあります。

管理者はこれらのスイッチを再起動なしで変更できます。LibreChatでは、エージェント、プロンプト、MCPサーバー、メモリ、スキルの各パネルに**Admin Settings**ボタンがあり、クリックすると該当機能のスイッチが開きます。画面上部には**Role**ピッカーがあります。[Admin Panel](/docs/features/admin_panel)では、カスタムロールを含むすべてのロールについて、同じスイッチを編集できます。

## リソースの共有 [#sharing-a-resource]

エージェント、プロンプト、MCPサーバー、スキル、共有リンクは、それぞれ独自のアクセス権限リストを持っています。([Agents API](/docs/features/agents_api) を通じて使用されるエージェントや、デプロイ所有者が管理するコード環境も、同じリストを使用しますが、共有ダイアログの外で管理されます。)作成者がそのリソースの所有者となり、他に誰がアクセスできるかを決定します。

<Steps>
  <Step>リソースを開き、**共有**ボタンをクリックします。リソースを所有している場合(またはそのリソースに対するオーナーロールを持っている場合、もしくは管理者の場合)で、かつ自分のロールでその種類のリソースの共有が許可されている場合にのみ表示されます。</Step>
  <Step>**共有**ダイアログで、名前またはメールアドレスによって人やグループを検索します。管理者によって非表示にされていない限り、ロールも検索結果に表示されます。</Step>
  <Step>追加する人またはグループごとに、アクセスロールを選択します。</Step>
  <Step>自分のロールで許可されている場合は、**全員と共有**をオンにして、**全員の権限レベル**を選択します。</Step>
  <Step>**保存**をクリックします。</Step>
</Steps>

アクセスロールは、すべてのリソースタイプで共通です:

| アクセスロール | 実行できること |
| -------------- | -------------- |
| Viewer | リソースを検索して利用できます。たとえば、エージェントを選んでチャットできます。変更することはできません。 |
| Editor | Viewer ができることすべてに加えて、設定、指示、ツール、ファイルを変更できます。 |
| Owner | Editor ができることすべてに加えて、削除したり、共有先を変更したりできます。 |

共有リンクには閲覧者と所有者のみがあります。リソースには常に少なくとも1人の所有者が必要なため、ダイアログでは最後の所有者を削除することはできません。

エージェントには、これらのロールのいずれにも含まれない追加の権限が1つあります。それが **View insights** です。この権限を持つユーザーは、すでにそのエージェントを閲覧できる場合に、[Insights](/docs/features/insights) を開くことができます。この切り替えは共有ダイアログで管理者にのみ表示され、全員に付与することはできません。

エージェントに編集者（Editor）またはオーナー（Owner）の権限を付与する前に、その人はエージェントに設定されているすべての内容（指示文や添付ファイルを含む）を閲覧できることに注意してください。閲覧者（Viewer）であっても、チャットを通じて添付コンテンツを引き出すことができます。そのため、共有エージェントには、その閲覧対象者が読むべきではない内容を添付しないでください。

## 管理者と委任された管理権限 [#admins-and-delegated-admin-powers]

`ADMIN` ロールを持つユーザーは、インスタンス上のすべてのリソースを閲覧・管理でき、任意のロールの機能権限を変更できます。また、管理パネルの URL が設定されている場合は、**設定 > 一般** に **Admin Panel** リンクが表示されます。

完全な管理者にせずに管理作業の一部を任せたい場合は、代わりに権限(capability)を付与してください。たとえば、ユーザーの管理、グループの管理、設定の編集(すべて、または `interface` などの単一セクションのみ)、すべてのエージェントのInsightsの閲覧、すべてのエージェント、プロンプト、スキル、共有リンクのモデレーションなどが可能です。委任された管理者がAdmin Panelにサインインするには、`access:admin` の権限も必要です。権限はユーザー、グループ、またはロールに付与でき、Admin Panelの **Grants** ページから設定します。「manage」権限を保持すると、対応する「read」権限も自動的に含まれます。

管理者は、ロールやグループに独自の設定を与えることもできます。たとえば、リサーチグループ向けに、`librechat.yaml` に追加する形で追加のエンドポイントを設定できます。この設定も管理パネルから行います。

## セットアップ [#setup]

デフォルト設定は追加の設定なしで動作します。最初のアカウントが管理者となり、それ以外のユーザーは利用はできますが共有はできません。`librechat.yaml` で機能のデフォルト値を変更したり、ユーザーピッカーに表示される範囲を制限したり、Entra ID グループを同期したり、別の管理者を昇格させたり、v0.8.0-rc3 より前からアップグレードしたインスタンスを移行したりする場合は、[Access Control configuration](/docs/configuration/access_control) を参照してください。カスタムロール、グループ、権限付与、およびグループごとの設定には [Admin Panel](/docs/features/admin_panel) が必要です。
