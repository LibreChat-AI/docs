Un agent est une configuration enregistrée : un modèle, une invite système, ainsi que les outils et fichiers auxquels il a accès. Vous le créez une seule fois dans le Générateur d'agents, puis vous le sélectionnez chaque fois que vous démarrez une conversation. Les agents fonctionnent avec n'importe quel fournisseur que vous avez configuré, et pas seulement OpenAI.

## Créer un agent [#create-an-agent]

<Steps>
  <Step>
    Ouvrez **Agent Builder** depuis le panneau latéral et cliquez sur **Créer un nouvel agent**.
  </Step>
  <Step>
    Donnez-lui un nom, une description facultative, puis choisissez un **Modèle** et une **Catégorie**. Le modèle et la catégorie sont obligatoires.
  </Step>
  <Step>
    Rédigez les instructions. Vous pouvez les saisir directement, ou passer la source sur **Prompt** pour utiliser un prompt enregistré depuis votre bibliothèque de prompts (voir ci-dessous).
  </Step>
  <Step>
    Ajoutez des outils sous **Outils** (voir ci-dessous), puis cliquez sur **Créer**.
  </Step>
</Steps>

Le téléversement de fichiers pour la recherche de fichiers ou le contexte de fichiers ne fonctionne qu'une fois l'agent créé.

Pour discuter avec un agent, sélectionnez-le dans le sélecteur de modèle, ouvrez-le depuis la [Place de marché des agents](#agent-marketplace), ou tapez `@` dans la zone de chat et choisissez-le dans la liste. Dans le sélecteur d'agent du générateur, **Mes agents** limite la liste aux agents que vous avez créés.

### Instructions issues d'une invite enregistrée [#instructions-from-a-saved-prompt]

Avec la source des instructions définie sur **Prompt**, sélectionnez un prompt sous **Select a prompt** ainsi qu'une **Version** : soit la version de production, qui suit le prompt marqué comme production par son propriétaire, soit une version enregistrée fixe. Vous devez avoir accès à la bibliothèque de prompts pour ce faire. Si quelqu'un d'autre ouvre l'agent sans accès au prompt lié, le générateur affiche **Restricted prompt** et lui permet de remplacer le prompt ou de revenir aux instructions en ligne.

Les instructions, en ligne ou liées, peuvent utiliser `{{current_date}}`, `{{current_datetime}}` et `{{iso_datetime}}`. Ils sont renseignés une seule fois au début de chaque tour et restent identiques pendant les appels d'outils, les sous-agents et les pauses d'approbation. Les deux premiers utilisent votre fuseau horaire ; `{{iso_datetime}}` est en UTC.

### Paramètres du modèle [#model-parameters]

Le panneau du modèle expose les mêmes paramètres que pour un chat normal avec ce fournisseur (température, nombre maximal de tokens en sortie, etc.), ainsi que **Image Detail** pour l'entrée visuelle. Les valeurs enregistrées ici s'appliquent à toutes les conversations avec l'agent.

### Exemples de démarrages de conversation [#conversation-starters]

Sous **Conversation Starters**, vous pouvez ajouter jusqu'à quatre invites. Elles apparaissent sous forme de boutons sur l'écran de chat vide lorsqu'un utilisateur démarre une nouvelle conversation avec l'agent, et un clic sur l'une d'elles l'envoie immédiatement. Les starters d'un agent remplacent tous les starters définis dans la spécification de modèle utilisée. Ils apparaissent également dans les détails de l'agent sur la Marketplace.

### Historique des versions [#version-history]

Chaque enregistrement qui modifie l'agent ajoute une entrée à l'**Historique des versions**, qui indique quand chaque version a été enregistrée ainsi que les outils et fonctionnalités qu'elle contenait. **Restaurer** remplace la configuration actuelle par cette version, après une confirmation. Seuls les utilisateurs autorisés à modifier l'agent peuvent voir cette fonctionnalité.

## Outils [#tools]

Cliquez sur **Add** à côté du titre **Tools** dans le constructeur (il affiche **No tools yet** tant que vous n'en avez pas ajouté) pour ouvrir la **Tool Library**. Recherchez-y un outil, ou filtrez par **Native**, **Tools**, **MCP servers** ou **Actions**. **Made by you** regroupe les serveurs MCP et les Actions que vous avez créés, et **Favorites** conserve les éléments marqués d'une étoile à portée de main d'un agent à l'autre (jusqu'à 100). Le menu **Create new…** permet d'ajouter un serveur MCP ou une Action sans quitter la boîte de dialogue, si votre rôle vous autorise à en créer. Ce que vous voyez dépend des fonctionnalités activées par votre administrateur et des autorisations associées à votre rôle ; un élément qui nécessite encore une clé API affiche **Needs setup**.

Run Code, File Search et File Context contiennent des fichiers. Tant qu'ils ont encore des fichiers attachés, les supprimer ouvre le gestionnaire de fichiers à la place, et ils restent sur l'agent jusqu'à ce que ces fichiers soient supprimés.

### Code Interpreter [#code-interpreter]

Répertorié sous **Run Code**. L'agent écrit et exécute du code dans un bac à sable, ce qui est idéal pour les calculs, l'analyse de données et la production de fichiers tels que des graphiques ou des tableurs. Les fichiers que vous joignez à cet outil dans le créateur sont disponibles dans le bac à sable à chaque exécution. Si aucun des fichiers de code d'une conversation ne peut être restauré dans le bac à sable, l'agent s'arrête avant d'appeler le modèle et vous demande de les joindre à nouveau. Voir [Code Interpreter](/docs/features/code_interpreter).

#### Sessions de code avec état [#stateful-code-sessions]

Si votre administrateur les a activées, les **sessions de code avec état** dans les paramètres d'exécution de code (Run Code) conservent un espace de travail en bac à sable entre deux exécutions, de sorte que les fichiers et les paquets installés sont reportés d'une exécution à l'autre. **L'environnement avec état** définit qui partage cet espace de travail : **Espace de travail utilisateur (recommandé)** pour tous vos agents avec état, **Espace de travail agent + utilisateur** pour un espace par agent, ou **Espace de travail de conversation** pour un espace par discussion. Les nouveaux agents démarrent à partir de l'**Espace de travail avec état par défaut**, accessible dans **Paramètres > Données et confidentialité > Exécution de code**. Lorsque l'administrateur a configuré plusieurs backends, **Environnement d'exécution** détermine celui qui exécute le code, ce qui peut inclure un worker que vous appairez sur votre propre machine.

L'espace de travail peut être réinitialisé à tout moment ; ne le considérez donc pas comme un espace de stockage. Dans les environnements gérés, enregistrez les résultats dont vous avez besoin sous `/mnt/data`. Les fichiers écrits par l'agent à l'aide de ses outils de fichiers sont listés pour chaque message sous **Modifications de l'espace de travail**, où vous pouvez les télécharger. Avec un environnement attaché, le compositeur propose **Demander avant les modifications**, **Accepter les modifications** ou **Accès complet** comme mode d'approbation pour cette conversation, dans les limites définies par votre administrateur.

Cette fonctionnalité est très expérimentale. Consultez [les sessions de code avec état](/docs/features/code_interpreter#stateful-code-sessions) pour plus de détails.

### Recherche Web [#web-search]

L'agent effectue des recherches sur le web et cite ses sources. Il nécessite un fournisseur de recherche configuré par votre administrateur, ou votre propre clé si l'administrateur l'a configuré de cette manière. Voir [Recherche web](/docs/features/web_search).

### Recherche de fichiers [#file-search]

Transforme les fichiers que vous joignez en une base de connaissances consultable. L'agent extrait les passages les plus pertinents lorsqu'il en a besoin, de sorte qu'il gère bien de grands ensembles de documents. Il convient mal aux données structurées comme les CSV ou les Excel, pour lesquelles Run Code donne de meilleurs résultats. Nécessite l'[API RAG](/docs/features/rag_api).

### Contexte de fichier [#file-context]

Les fichiers ajoutés sous **File Context** ont leur texte extrait une seule fois, au moment du téléversement, et ce texte est intégré au contexte de l'agent à chaque message. Utilisez-le pour quelques documents clés que l'agent doit toujours avoir sous les yeux. L'extraction fonctionne de la même manière que [Upload as Text](/docs/features/upload_as_text) : analyse de texte brut par défaut, avec de meilleurs résultats sur les documents numérisés et les images si [OCR](/docs/features/ocr) est configuré.

Parce que le texte accompagne chaque message, les fichiers volumineux ici coûtent des jetons à chaque tour. Toute personne pouvant discuter avec l'agent peut aussi lui soutirer ce texte.

### Artifacts [#artifacts]

Permet à l'agent d'afficher React, HTML, SVG, Markdown et Mermaid dans un panneau latéral au lieu de les présenter sous forme de blocs de code. Le paramètre **Mode** sélectionne les instructions intégrées : **Normal**, **shadcn/ui** (ajoute des instructions pour la bibliothèque de composants shadcn/ui) ou **Custom**, qui n'injecte rien ; vos propres instructions doivent donc expliquer la syntaxe des artefacts. Consultez [Artifacts](/docs/features/artifacts) pour cette syntaxe.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

Les serveurs MCP configurés par votre administrateur, ou ceux que vous avez ajoutés vous-même, apparaissent sous **MCP servers**. Ajouter un serveur associe tous ses outils ; développez-le sous **Tools in this server** pour ne sélectionner que ceux dont l'agent a besoin. Voir [MCP](/docs/features/mcp).

Certains serveurs ne peuvent lister leurs outils qu'au cours d'une conversation, car ceux-ci dépendent de valeurs issues de la requête. Pour ces serveurs, le générateur propose une sélection unique pour l'ensemble des outils du serveur, au lieu d'interrupteurs par outil. Si tous les outils MCP sélectionnés pour un agent ne parviennent pas à se charger au démarrage d'une exécution, celle-ci s'arrête et vous invite à reconnecter le serveur ou à vous y connecter, plutôt que de poursuivre sans eux.

Chaque outil MCP dispose d'un menu **Tool Options** comportant quelques options par outil :

- **Différer** : voir [Outils différés](#deferred-tools). **Différer tous les outils** le fait pour l'ensemble du serveur.
- **Programmatique** : voir [Appel d'outils programmatique](#programmatic-tool-calling).
- **Contexte** : voir [Appels d'outils en arrière-plan](#background-tool-calls).
- **Étiquette d'intention** : l'agent rédige une description d'une ligne pour chaque appel, affichée en direct comme statut de l'appel à la place d'un libellé générique. Cela ajoute quelques tokens à chaque requête. Les outils natifs reçoivent automatiquement des étiquettes d'intention. Cela ne s'applique pas aux outils programmatiques.

**Background** et **Intent label** n'apparaissent que si votre administrateur les a activés.

### Outils différés [#deferred-tools]

Un agent doté de plusieurs serveurs MCP peut facilement disposer de dizaines de définitions d'outils, et les envoyer toutes à chaque requête consomme du contexte et nuit à la capacité du modèle à choisir le bon outil. Un outil différé est omis de la requête initiale. L'agent reçoit à la place un outil de recherche d'outils, qui lui permet de trouver les outils différés par leur nom ou leur description lorsqu'il en a besoin, et d'utiliser un outil trouvé pour le reste de la conversation.

### Appel d'outils programmatique [#programmatic-tool-calling]

Avec **Programmatic** activé pour un outil MCP (ou pour un serveur entier), le modèle n'appelle pas directement cet outil. Il écrit du code dans le bac à sable de l'interpréteur de code, qui appelle l'outil comme une fonction. Il peut ainsi boucler, paginer, réessayer et filtrer les résultats avant de répondre. Cela est utile pour des tâches comme « vérifie ces 40 tickets et résume ceux qui sont ouverts », qui nécessiteraient autrement 40 appels d'outil distincts passant par le modèle.

Les commutateurs **Programmatique** restent désactivés tant que Exécuter le code n'est pas activé, et leur désactivation de Exécuter le code les réinitialise. Le bac à sable ne peut appeler que les outils enregistrés sur l'agent. Pendant son exécution, développez la carte du code pour suivre en direct une trace de chaque appel d'outil interne ; cette trace n'est pas conservée après le rechargement de la page. Cette fonctionnalité est désactivée par défaut ; votre administrateur doit l'activer.

### Appels d'outils en arrière-plan [#background-tool-calls]

Un outil compatible avec l'exécution en arrière-plan renvoie immédiatement une référence de tâche, afin que l'agent puisse continuer à travailler pendant son exécution. Une fois la tâche terminée, le résultat est livré automatiquement dans un tour de conversation ultérieur (affiché sous forme de carte de tâche repliable), ou l'agent peut en vérifier l'état à l'aide de son outil de tâche. Les sorties et fichiers produits en arrière-plan apparaissent sur l'appel d'outil d'origine. Outils pouvant s'exécuter en arrière-plan :

- **Exécuter le code** : le code et les commandes shell sont éligibles par défaut ; désactivez **Exécution en arrière-plan** dans ses paramètres pour vous désabonner.
- **Outils MCP** : marquez un outil ou un serveur entier comme **Arrière-plan**.
- **Autres outils et actions** : activez l'**exécution en arrière-plan**. Les actions qui utilisent OAuth ne la proposent pas.

Ces commutateurs permettent l'exécution en arrière-plan ; le modèle décide toujours à chaque appel. Le travail en arrière-plan s'exécute dans le processus serveur qui l'a lancé et est perdu si ce processus s'arrête. Votre administrateur doit activer la fonctionnalité.

### Actions [#actions]

Les actions transforment une spécification OpenAPI en outils. Choisissez **Créer nouveau…** puis **Actions**, collez le schéma, et configurez l'**Authentification** si l'API en a besoin. Chaque opération de la spécification devient un outil que l'agent peut appeler.

Si vous utilisez un modèle OpenAI, ajoutez `x-strict: true` à une opération dans la spécification et LibreChat demandera l'appel de fonction en mode strict pour cette opération. Le mode strict n'accepte qu'un sous-ensemble de JSON Schema ; consultez le [guide des sorties structurées](https://platform.openai.com/docs/guides/structured-outputs) d'OpenAI.

Les actions ne peuvent accéder qu'aux domaines autorisés par votre administrateur, et les adresses de réseau privé sont bloquées sauf autorisation explicite.

### Compétences [#skills]

La section **Skills** du constructeur contrôle les [Skills](/docs/features/skills) que l'agent peut utiliser : **Désactivé**, **Tous** (toutes les Skills que vous avez activées) ou **Sélectionnés** (uniquement celles que vous ajoutez).

### Mémoire [#memory]

**Mémoire** permet à l'agent d'enregistrer, de mettre à jour et de supprimer des souvenirs vous concernant lorsque vous lui demandez de retenir ou d'oublier quelque chose. Elle nécessite que la mémoire soit configurée sur l'instance et autorisée pour votre rôle. Par défaut, l'agent partage vos souvenirs personnels avec vos autres conversations ; activez **Conserver les souvenirs séparés pour cet agent** pour lui donner ses propres souvenirs, qu'il est le seul à lire et à écrire. Voir [Mémoire](/docs/features/memory).

### Demande à l'utilisateur et approbation des outils [#ask-user-and-tool-approval]

**Demander à l'utilisateur** permet à l'agent de suspendre une exécution en cours pour vous poser une question et attendre votre réponse. Une seule pause peut contenir jusqu'à quatre questions, affichées une à la fois avec **Précédent** et **Suivant** ; chacune accepte une réponse libre ou l'un des choix proposés par l'agent. **Ignorer** refuse toutes les questions. L'exécution reprend dès que vous soumettez vos réponses, et vos réponses sont conservées même si vous arrêtez l'exécution pendant son redémarrage.

Votre administrateur peut également exiger une approbation avant l'exécution de certains outils. L'exécution se met alors en pause, vous examinez l'appel dans un panneau situé au-dessus de la zone de saisie des messages (approuver, rejeter ou, pour certains outils, modifier les arguments), puis elle reprend. Si l'administrateur a activé les modes d'approbation par agent, chaque outil de l'agent reçoit un **Mode d'approbation de l'outil** : **Utiliser la politique héritée**, **Toujours demander**, **Toujours approuver**, **Demander une fois par conversation** ou **Demander une fois, puis toujours approuver**. Les règles de l'administrateur s'appliquent toujours en complément, et **Réinitialiser mes approbations mémorisées** efface les approbations que vous avez accordées auparavant.

### Autres outils [#other-tools]

La catégorie **Tools** regroupe les intégrations intégrées que votre administrateur a activées, comme la [génération d'images](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search) et [Azure AI Search](/docs/configuration/tools/azure_ai_search). Chacune se configure séparément ; voir [Tools](/docs/configuration/tools).

## Travailler avec d'autres agents [#working-with-other-agents]

**Les sous-agents** permettent à l'agent de confier une sous-tâche ciblée à une copie fraîche de lui-même, ou à un autre agent, dans une fenêtre de contexte distincte. Seul le résultat revient, de sorte que les longues sorties d'outils restent en dehors de la conversation principale. Voir [Sous-agents](/docs/features/subagents).

### Transferts [#handoffs]

**Les transferts (handoffs)** donnent à l'agent un outil de transfert pour chaque agent que vous listez, afin qu'il puisse transmettre la conversation à un spécialiste lorsque le sujet l'exige. Pour chaque transfert, vous pouvez ajouter une description (quand transférer) et un contenu de transmission (ce que l'agent doit générer et transmettre), ainsi que renommer le paramètre dans lequel ce contenu est transmis (`instructions` par défaut). Un agent peut avoir jusqu'à 10 transferts. Les transferts sont toujours disponibles ; ils ne dépendent d'aucun paramètre d'administration.

### Chaîne d'agents [#agent-chain]

Les chaînes d'agents sont obsolètes. Les chaînes existantes continuent de fonctionner, et le générateur les affiche sous **Paramètres avancés** avec un bouton **Remove chain**, mais vous ne pouvez plus en créer de nouvelles. Utilisez plutôt des sous-agents ou des transferts (handoffs).

## Nombre maximal d'étapes de l'agent [#max-agent-steps]

**Paramètres avancés** comporte un champ **Max Agent Steps** qui limite le nombre d'étapes que l'agent peut effectuer avant de devoir fournir une réponse finale. Une étape correspond à une requête au modèle ou à un tour d'appels d'outils ; ainsi, un seul appel d'outil coûte généralement trois étapes : la requête, le tour d'outil et la requête de suivi.

Laissez ce champ vide pour utiliser la valeur par défaut du serveur, qui est de 50 sauf si votre administrateur l'a modifiée. Votre administrateur peut également définir un plafond que ce champ ne peut pas dépasser.

Lorsqu'un tour manque d'étapes, vous conservez ce que l'agent a fait jusqu'à présent, et le message propose **Continuer** (un nouveau tour avec un budget neuf) ou **Répondre maintenant** (l'agent répond à partir du travail déjà effectué, sans utiliser d'autres outils). Si cela se produit souvent sur de longues chaînes d'outils, augmentez la limite.

## Suivre une exécution longue [#following-a-long-run]

Les cartes d'outils affichent **Préparation** pendant qu'un appel est en attente (par exemple en attente d'approbation), puis **Appel en cours** jusqu'à ce que le résultat soit renvoyé. La sortie de l'interpréteur de commandes est affichée au format terminal et réduite aux 15 dernières lignes ; **Afficher plus** l'étend, et une commande ayant échoué affiche son code de sortie, son signal ou son délai d'expiration.

### Groupes d'activités [#activity-groups]

Si votre administrateur les a activés, chaque séquence de raisonnement et d'appels d'outils se replie sous un en-tête généré d'une seule ligne, si bien qu'une exécution comportant 30 appels d'outils s'affiche comme quelques lignes seulement. Développez un en-tête pour voir les appels qu'il contient. Un second niveau peut regrouper plusieurs de ces groupes dans une phase accompagnée de son propre résumé, ce qui donne aux longues exécutions une structure en plan. Dès que deux groupes sont terminés, ils se replient immédiatement ensemble, l'en-tête le plus récent faisant office de substitut jusqu'à l'arrivée du résumé. La réponse finale reste toujours en dehors du repli, et les fichiers produits au sein d'une phase sont affichés en ligne sous celle-ci plutôt que masqués. Avec le [Smooth Streaming](/docs/features/smooth_streaming) activé, le repli est animé, sauf si votre appareil demande une réduction des animations.

Les étiquettes de raisonnement en direct constituent une option associée : au lieu d'un titre générique **Thinking**, le bloc de raisonnement affiche un résumé court et mis à jour de ce sur quoi le modèle travaille.

Les en-têtes, les résumés de phase et les étiquettes de raisonnement entraînent chacun des appels de modèle supplémentaires, qui sont enregistrés comme n'importe quelle autre utilisation. Les administrateurs les configurent dans les [groupes d'activité de l'agent](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) et les [étiquettes de raisonnement en direct](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Orientation et messages en file d'attente [#steering-and-queued-messages]

Pendant qu'un agent répond, vous pouvez toujours envoyer des messages :

- **Steer** insère le message dans l'exécution en cours au prochain point sûr, afin que l'agent puisse s'ajuster avant de terminer.
- **Interrompre** annule les appels d'outils et le raisonnement en cours, conserve ce qui a déjà été effectué, puis poursuit avec votre message. Les effets qui se sont déjà produits en dehors de LibreChat ne peuvent pas être annulés. Certaines exécutions, par exemple celles utilisant la recherche intégrée d'un fournisseur, ne peuvent pas être interrompues, et le message est alors mis en attente sous forme de steer.
- **Queue** conserve le message et l'envoie comme un tour normal une fois la réponse terminée.

**While generating, Enter will** under **Settings > Chat** picks the default, and the send button menu overrides it per message; `Alt + Enter` interrupts. Queued messages are listed above the composer, where you can edit, remove, reorder, **Send now**, or **Interrupt now**. Files and quoted excerpts go along with the message; skills you picked with `$` wait for the next full turn. Queued messages in a saved agent chat are stored on the server and survive a closed browser.

Un chat peut contenir jusqu'à 100 messages en file d'attente (16 000 caractères et 10 fichiers chacun), et une exécution accepte jusqu'à 10 orientations en attente. Consultez [Composer](/docs/features/composer) pour le détail des accusés de réception et des contrôles.

## Fichiers dans un chat [#files-in-a-chat]

Lorsque vous discutez avec un agent, le menu de pièces jointes propose :

- **Télécharger une image** : envoyée au modèle pour la vision.
- **Télécharger en tant que texte** : le texte intégral est transmis uniquement dans cette conversation. Voir [Télécharger en tant que texte](/docs/features/upload_as_text).
- **Téléversement pour la recherche de fichiers** : indexé pour la récupération, comme les fichiers de recherche de fichiers propres à l'agent, mais limité à cette conversation.
- **Télécharger dans l'environnement de code** : copié dans le bac à sable pour Exécuter le code. Idéal pour les fichiers CSV, Excel et JSON.

Les options n'apparaissent que lorsque la fonctionnalité correspondante est activée.

## Partage et autorisations [#sharing-and-permissions]

Les agents sont privés pour leur auteur tant qu'ils ne sont pas partagés. Cliquez sur **Partager** dans le pied de page du générateur pour accorder l'accès à des utilisateurs, des groupes ou des rôles, chacun avec l'un des trois rôles suivants :

| Rôle | Ce qu'il peut faire |
| ---- | ------------------- |
| Lecteur | Discuter avec l'agent. Ne peut pas l'ouvrir dans le générateur ni voir ses instructions, outils ou fichiers. |
| Éditeur | Tout ce qu'un lecteur peut faire, plus modifier les instructions, le modèle, les outils et les fichiers. |
| Propriétaire | Tout ce qu'un éditeur peut faire, plus supprimer l'agent et modifier les personnes avec qui il est partagé. |

**Partager avec tout le monde** rend l'agent disponible à tous les utilisateurs de l'instance ; cette option nécessite l'autorisation de partage public. L'auteur et les administrateurs conservent toujours le contrôle total.

Un spectateur ne peut pas voir les instructions ou les fichiers dans le générateur, mais le modèle peut tout de même les répéter dans une conversation si on le lui demande. Ne placez rien dans un agent que ses spectateurs ne devraient jamais voir.

Séparément, le bouton en forme de globe (**Remote Access**) contrôle qui peut appeler l'agent via l'[API Agents](/docs/features/agents_api).

Les cartes d'agent affichent le contact de support défini dans le générateur. Sans contact défini, elles peuvent afficher le nom du propriétaire, mais jamais son adresse e-mail, sauf si celle-ci a été saisie comme contact.

Voir [Contrôle d'accès](/docs/features/access_control) pour savoir comment les utilisateurs, les groupes et les rôles se combinent.

### Contrôles administrateur [#administrator-controls]

La possibilité pour un rôle d'utiliser, de créer, de partager ou de partager publiquement des agents se définit par rôle dans le [Panneau d'administration](/docs/features/admin_panel). Les administrateurs disposent également d'un bouton **Paramètres d'administration** en bas du Constructeur d'agents, avec les mêmes options, par rôle. Sur une instance mono-locataire, le premier compte enregistré est un administrateur ; pour en ajouter d'autres, consultez [Promouvoir un autre administrateur](/docs/configuration/access_control#promote-another-admin).

## Place de marché des agents [#agent-marketplace]

**Agent Marketplace** dans la barre latérale liste les agents auxquels vous avez accès, si votre rôle vous permet de l'utiliser. Recherchez par nom ou description, filtrez par catégorie (**Top Picks**, **All**, ou une catégorie spécifique), et modifiez l'ordre avec **Sort by** : **Newest first**, **Oldest first**, **Popular**, ou **By creator name**. **My agents** n'affiche que vos propres agents. La recherche, le tri et le filtre sont conservés dans l'URL, vous pouvez donc mettre en favori ou partager une vue.

Cliquez sur une carte pour accéder aux détails et aux actions **Épingler** ou **Désépingler**, **Copier le lien** (un lien qui ouvre une nouvelle conversation avec l'agent) et **Démarrer la conversation**. Cliquer sur l'un des exemples de démarrage de conversation de l'agent ouvre une nouvelle conversation avec le texte de la requête dans la zone de saisie, sans l'envoyer, afin que vous puissiez la modifier au préalable.

## API des agents [#agents-api]

Les agents peuvent également être appelés depuis des scripts et d'autres applications via une API compatible OpenAI, gérés par des services de confiance et déclenchés par des événements provenant d'autres systèmes. Voir [API des agents](/docs/features/agents_api). Les [Conversations planifiées](/docs/features/scheduled_chats) lancent des exécutions d'agents selon un minuteur, et les [Plugins d'agents](/docs/features/agent_plugins) permettent à un opérateur de livrer des compétences et des serveurs MCP aux agents sous la forme d'un seul paquet.

## Configuration [#setup]

Les agents sont activés par défaut. Les administrateurs choisissent les fonctionnalités proposées, les limites d'étapes et les fournisseurs autorisés dans la [configuration de l'endpoint agents](/docs/configuration/librechat_yaml/object_structure/agents), ainsi que les domaines auxquels les Actions peuvent accéder dans la [configuration des Actions](/docs/configuration/librechat_yaml/object_structure/actions). Les instances mises à niveau depuis une version antérieure à la v0.8.0-rc3 doivent effectuer la [migration des permissions](/docs/configuration/access_control#migrating-from-pre-acl-versions).
