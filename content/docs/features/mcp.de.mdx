MCP (Model Context Protocol) ist ein offener Standard, um einem Modell Werkzeuge zur Verfügung zu stellen. Ein MCP-Server kann dem Modell beispielsweise ein Dateisystem, einen Browser, eine Datenbank oder die interne API Ihres Unternehmens bereitstellen. LibreChat kann jeden Server nutzen, der das Protokoll unterstützt. Sie können Server für eine schnelle Nutzung an einen regulären Chat anhängen oder ihre Werkzeuge einem Agenten hinzufügen.

## Einen Server im Chat verwenden [#use-a-server-in-chat]

Bei jedem Endpoint außer Agents oder Assistants öffnen Sie die **+**-Palette des Eingabefelds (**Anhängen und Werkzeuge**) und suchen unter **MCP Servers** nach dem gewünschten Server. Klicken Sie auf einen Server, um ihn für die Unterhaltung zu aktivieren. Er erscheint als Chip im Eingabefeld, und jedes Werkzeug, das der Server bereitstellt, steht dem Modell zur Verfügung. Die Palette bleibt geöffnet, sodass Sie mehrere Server auf einmal aktivieren können. Klicken Sie erneut auf einen Server oder entfernen Sie dessen Chip, um ihn wieder zu deaktivieren. Weitere Informationen zur Palette finden Sie unter [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers).

Die Palette zeigt jeweils einige wenige Server an, wobei für jeden Server ein farbiger Punkt seinen Status angibt. **Alle anzeigen** im Kopfbereich **MCP Servers** öffnet die vollständige Liste mit einem Suchfeld und drei Ansichten: **Alle**, **Von dir erstellt** und **Favoriten**.

![Der MCP Servers-Dialog, geöffnet mit Show All, listet einen Github-Server mit der Markierung Disconnected und einen Spotify-Server mit der Markierung Needs Auth auf, mit den Filtern All, Made by you und Favorites](/images/mcp/mcp_servers_catalog.png)

Wenn der Server noch nicht verbunden ist, startet ein Klick auf ihn die Verbindung, anstatt ihn sofort auszuwählen. Ein Server, der deine eigenen Zugangsdaten benötigt, öffnet zuerst einen Dialog, in dem du diese eingeben kannst; ein Server, der OAuth verwendet, leitet dich zur Anmeldung weiter. Sobald die Verbindung hergestellt ist, wählt LibreChat ihn automatisch für dich aus.

Wähle ein Modell, das Tool-Aufrufe unterstützt, da das Modell andernfalls niemals die Tools des Servers aufruft. Agenten und Assistenten verfügen über ihre eigene Tool-Konfiguration, weshalb die Modellauswahl bei diesen Endpunkten ausgeblendet ist. Außerdem kann ein Administrator einzelne Server im Chat ausblenden, sodass sie nur für Agenten verfügbar sind.

## Einen Server zu einem Agenten hinzufügen [#add-a-server-to-an-agent]

Im Agent Builder auf **Add** neben **Tools** klicken, um die **Tool Library** zu öffnen, und dann nach **MCP servers** filtern. Beim Hinzufügen eines Servers werden die von ihm bereitgestellten Tools aufgelistet; behalten Sie diejenigen, die der Agent haben soll, und entfernen Sie die übrigen, oder verwenden Sie **Select all** und **Deselect all**. Ein Server mit dutzenden Tools benötigt in der Tool-Liste des Agenten trotzdem nur einen einzigen Eintrag.

Jedes MCP-Tool eines Agenten verfügt außerdem über eigene Optionen (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Siehe [Agents](/docs/features/agents), um zu erfahren, was diese verändern.

Einige Server sind auf Werte angewiesen, die nur während einer Chat-Anfrage existieren. Deshalb können ihre Tools nicht im Voraus aufgelistet werden. Für diese Server hängt die Tool-Bibliothek den gesamten Server an und vermerkt, dass ihre Tools zur Laufzeit, also während des Chats, aufgelöst werden.

Wenn ein Agent für die Verwendung von MCP-Tools eingerichtet ist und keines davon beim Start eines Durchlaufs verfügbar ist (der Server ist nicht erreichbar oder Sie haben keinen Zugriff mehr), wird der Durchlauf mit einer Fehlermeldung abgebrochen, die Sie auffordert, die Verbindung und Ihren Zugriff zu überprüfen, anstatt ohne die Tools zu antworten. Wenn Sie während eines Tool-Aufrufs auf **Stop** drücken, wird der Aufruf auch auf dem MCP-Server abgebrochen, sofern der Server Abbrüche unterstützt.

## Verbindungsstatus [#connection-status]

In der Palette und in den **MCP Settings** wird der Status als farbiger Punkt angezeigt: grau, wenn der Server getrennt ist, bernsteinfarben, wenn eine Anmeldung von Ihnen erforderlich ist. Der vollständige Status wird Screenreadern vorgelesen, und die Tool Library sowie die Liste **Show All** geben ihn neben jedem Server auch als Text aus:

- **Verbunden**: einsatzbereit.
- **Needs Auth**: Der Server verwendet OAuth, und Sie sind nicht angemeldet, oder Ihre Anmeldung ist abgelaufen.
- **Verbindung wird hergestellt** / **Initialisierung**: Ein Verbindungsversuch läuft gerade.
- **Getrennt** oder **Fehler**: Es besteht keine aktive Verbindung, oder der letzte Verbindungsversuch ist fehlgeschlagen. Verwenden Sie **Verbinden**, um es erneut zu versuchen.
- **On-Demand**: Der Server verbindet sich für jede Anfrage separat, daher gibt es keine dauerhafte Verbindung, die angezeigt werden könnte.
- **Unbekannt**: Es ist noch kein Status zurückgekommen.

Wenn eine Verbindung fehlschlägt, zeigt die Fehlermeldung den Grund an: Der Server war nicht erreichbar, er benötigt Variablen, die Sie nicht gesetzt haben (in der Meldung benannt), oder Sie müssen sich erneut anmelden. Beheben Sie das und verbinden Sie erneut; es ist nicht nötig, den Server zu entfernen und erneut hinzuzufügen. Ein Server kann außerdem während des Betriebs Tools hinzufügen oder entfernen, und LibreChat übernimmt die neue Liste ohne Neustart.

Verbindungen sind pro Benutzer. Deine OAuth-Tokens und gespeicherten Zugangsdaten werden niemals für andere verwendet, und eine inaktive Verbindung wird standardmäßig nach 15 Minuten geschlossen und beim nächsten Verwenden des Servers wieder geöffnet.

## Mit OAuth anmelden [#sign-in-with-oauth]

Wenn ein Server OAuth benötigt, öffnet die Verbindung einen **Connect**-Dialog. Klicken Sie auf **Continue with OAuth**, um die Anmeldeseite des Anbieters in einem neuen Tab zu öffnen, oder verwenden Sie **Copy link** bzw. **Show QR Code**, um die Anmeldung auf einem anderen Gerät abzuschließen. Nachdem Sie den Zugriff genehmigt haben, zeigt der Tab **Authentication Successful** an und schließt sich selbstständig, und der Server wechselt zu **Connected**.

Während eine Anmeldung aussteht, zeigt der Server einen Ladeindikator. Bewegen Sie den Mauszeiger darüber, um abzubrechen. In den MCP-Server-Einstellungen des Agent Builders wird **Connect** für denselben Zweck zu **Cancel**. Sie haben 10 Minuten Zeit, die Anmeldung abzuschließen, bevor der Versuch abläuft (der Administrator kann dies ändern).

Wenn der Anbieter Refresh-Tokens ausstellt, erneuert LibreChat Ihren Zugriff im Hintergrund. Lehnt ein Server Ihr Token während einer Sitzung ab, versucht LibreChat einen Refresh und eine erneute Verbindung, bevor Sie aufgefordert werden, sich erneut anzumelden. Anbieter, die keine Refresh-Tokens ausstellen, fordern Sie zur erneuten Anmeldung auf, sobald das Token abläuft.

Standardmäßig erscheint die Anmeldeaufforderung, sobald deine Nachricht gesendet wird. Ein Administrator kann einige Server so konfigurieren, dass sie warten, bis der Agent zum ersten Mal eines ihrer Tools aufruft. So wirst du nur dann zur Anmeldung aufgefordert, wenn der Server tatsächlich benötigt wird.

## Zugangsdaten und Variablen [#credentials-and-variables]

Manche Server benötigen einen Wert von jedem Benutzer, etwa einen persönlichen API-Schlüssel oder eine Projekt-ID. Wenn Sie eine dieser Verbindungen herstellen, fragt LibreChat vor dem Verbinden nach den Werten. Um sie später zu ändern, verwenden Sie **Configure** beim Server im Chat-Auswahlmenü oder in den **MCP Settings**. Jedes Feld hat **Save** und **Revoke**. Beide Aktionen schließen Ihre aktuelle Verbindung zu diesem Server, sodass die nächste Nutzung mit den neuen Werten verbindet. Mit **Revoke** wird der Server außerdem im aktuellen Chat deaktiviert.

Werte werden pro Benutzer gespeichert und nur an den Server gesendet, für den sie eingegeben wurden.

## MCP-Einstellungen-Panel [#mcp-settings-panel]

**MCP-Einstellungen** im Seitenbereich listet jeden Server auf, den Sie verwenden können, mit einem Statuspunkt auf dem Symbol jedes Servers. Je nach Zustand des Servers bietet jede Karte **Verbinden**, **Erneut verbinden**, **Konfigurieren** (für Ihre Variablen) oder **Widerrufen** (um Ihre OAuth-Tokens zu entfernen). Server, die Sie bearbeiten dürfen, haben außerdem **Bearbeiten**.

## Einen Server über die Benutzeroberfläche erstellen [#create-a-server-from-the-ui]

Falls Ihre Rolle es erlaubt, klicken Sie in den **MCP-Einstellungen** auf **Add MCP** (die Schaltfläche **+**), um einen Remote-Server zu registrieren, ohne `librechat.yaml` zu bearbeiten oder neu zu starten.

<Steps>
<Step>
### Server beschreiben [#describe-the-server]

Gib einen **Namen**, optional eine **Beschreibung** und ein Symbol ein, falls gewünscht. Trage die **MCP Server URL** ein und wähle einen **Transport**: **Streamable HTTPS** oder **SSE**.
</Step>
<Step>
### Authentifizierung auswählen [#choose-authentication]

Unter **Authentifizierung** wählst du eine der folgenden Optionen:

- **Keine (automatische Erkennung)**: LibreChat prüft den Server und wechselt zu OAuth, wenn der Server dies verlangt.
- **API-Schlüssel**: Gib einen gemeinsamen Schlüssel ein oder aktiviere **Jeder Benutzer stellt seinen eigenen Schlüssel bereit**, damit jeder Benutzer seinen Schlüssel über **Konfigurieren** eingibt. Wähle das **Header-Format**: **Bearer**, **Basic** oder **Custom** mit einem eigenen Header-Namen.
- **OAuth**: Geben Sie die **Client ID**, das **Client Secret**, die **Authorization URL**, die **Token URL** und den **Scope** ein. Lassen Sie die Client-Felder leer, wenn der Anbieter die dynamische Client-Registrierung unterstützt. Die **Token Exchange Method** ist standardmäßig auf **Auto** eingestellt, wodurch die vom Anbieter angegebene Methode verwendet wird und bei Bedarf auf einen Basic-Authorization-Header zurückgegriffen wird. Wählen Sie **Default (POST request)** oder **Basic authorization header**, um eine der beiden Methoden zu erzwingen.
- **On-Behalf-Of (OBO)**: Wird nur angezeigt, wenn ein Administrator Ihnen diese Berechtigung erteilt hat, und funktioniert nur, wenn LibreChat Benutzer über OpenID Connect anmeldet (zum Beispiel Entra ID). Geben Sie die anzufordernden Scopes ein; LibreChat tauscht Ihr OpenID-Token gegen ein Token ab, das auf den MCP-Server ausgerichtet ist.
</Step>
<Step>
### Erstellen [#create-it]

Aktivieren Sie **Ich vertraue dieser Anwendung** und klicken Sie auf **Erstellen**. Der Server ist sofort verfügbar. Bei OAuth-Servern zeigt der nächste Dialog die **Redirect URI** an, die Sie bei Ihrem OAuth-Anbieter registrieren müssen. Bis Sie sich einmal angemeldet haben, bleibt der Server getrennt.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="Das Dialogfeld „Add MCP Server“ mit ausgefülltem Namen und URL, Transport auf „Streamable HTTPS“ gesetzt und Authentifizierung auf „API Key“ mit aktiviertem Kontrollkästchen „Each user provides their own key“"
/>

Auf diese Weise erstellte Server können nur entfernte URLs erreichen; lokale `stdio`-Server müssen in `librechat.yaml` definiert werden. Sie können außerdem keine Umgebungsvariablen des Servers oder Platzhalter für Benutzerprofile verwenden: Werte wie `${API_TOKEN}` oder `{{LIBRECHAT_USER_EMAIL}}` in ihren Headern werden entfernt, da ein gemeinsam genutzter Server sie sonst erhalten würde. Wenn Sie später die URL oder Authentifizierung eines Servers ändern, müssen Benutzer, die ihren eigenen Schlüssel eingegeben haben, diesen erneut eingeben, und OAuth-Benutzer müssen sich erneut anmelden. Wenn Sie die URL oder die OAuth-Endpunkte eines Servers mit einem gespeicherten Client-Secret ändern, müssen Sie auch das Secret erneut eingeben. Wenn ein API-Key-Server, der mit einer älteren Version erstellt wurde, im Status **Needs Auth** hängen bleibt, öffnen Sie ihn mit **Edit** und speichern Sie ihn einmal.

## Einen Server teilen [#share-a-server]

Im UI erstellte Server gehören demjenigen, der sie erstellt hat. Der Eigentümer kann einen Server über seinen Dialog **Edit** gezielt mit bestimmten Benutzern, Gruppen, Rollen oder allen teilen, und zwar als Viewer (kann ihn sehen und verwenden), als Editor (kann ihn zusätzlich ändern) oder als Owner. Server, die in `librechat.yaml` definiert sind, stehen allen Benutzern zur Verfügung, die die Berechtigung zur Nutzung von MCP haben. Wie sich die Berechtigungsstufen kombinieren, erfährst du unter [Access Control](/docs/features/access_control).

## Serveranweisungen [#server-instructions]

Ein Administrator kann einem Server Anweisungen zuweisen, entweder die eigenen Anweisungen des Servers oder benutzerdefinierten Text. Wenn eine Unterhaltung oder ein Agent die Tools dieses Servers verwendet, werden die Anweisungen dem Kontext des Modells hinzugefügt. Das hilft bei Servern, deren Tools nur in einer bestimmten Reihenfolge sinnvoll eingesetzt werden können.

## MCP Apps [#mcp-apps]

Einige Server liefern zusammen mit einem Tool-Ergebnis eine interaktive Ansicht. Wenn MCP Apps aktiviert sind, zeigt der Tool-Aufruf eine Schaltfläche **Open app**, die die Ansicht in einem Sandbox-Frame lädt, und **Close app** blendet sie wieder aus. Es können nur einige wenige Apps gleichzeitig geöffnet sein; wenn Sie das Limit erreichen, schließen Sie zuerst eine App.

Eine App kann nicht selbstständig handeln. Wenn sie ein Tool ausführen möchte, siehst du **Run tool from app?**, und wenn sie eine Nachricht senden möchte, **Send message from app?**. Es passiert nichts, bis du zustimmst. Das Senden einer Nachricht startet eine Modellantwort in der aktuellen Unterhaltung, sodass der ausgewählte Agent und seine Tools verwendet werden können. Apps werden in geteilten Unterhaltungen nicht gerendert.

## Einrichtung [#setup]

MCP benötigt mindestens einen Server. Administratoren definieren Server unter `mcpServers` in `librechat.yaml`, was einen Neustart zur Übernahme erfordert, und Benutzer mit entsprechender Berechtigung können über **MCP Settings** Remote-Server hinzufügen. Siehe [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) für Serveroptionen, die OAuth-Callback-URL und Transporte, [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) für erlaubte Domains und MCP Apps, [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) für App-Limits sowie [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) für die Frage, wer Server verwenden, erstellen und teilen darf. Einrichtungsanleitungen für bestimmte Server finden sich unter [MCP Servers](/docs/mcp_servers), und [Agent Plugins](/docs/features/agent_plugins) beschreibt das Bündeln von MCP-Servern mit Skills.
