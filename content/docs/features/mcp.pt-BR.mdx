O Model Context Protocol (MCP) é um protocolo aberto que padroniza a forma como as aplicações fornecem contexto para Large Language Models (LLMs). Pense no MCP como o **"USB-C da IA"** - assim como o USB-C fornece um padrão de conexão universal para dispositivos eletrônicos, o MCP oferece uma maneira padronizada de conectar modelos de IA a diversas ferramentas, fontes de dados e serviços.

O LibreChat utiliza o MCP para expandir drasticamente o que seus agentes de IA podem fazer, permitindo que você integre desde acesso ao sistema de arquivos, navegadores web e APIs especializadas, até ferramentas de negócios personalizadas.

## Por que o MCP é importante [#why-mcp-matters]

LLMs são limitados às suas capacidades integradas. Com o MCP, o LibreChat derruba essas barreiras ao:

- **Conectando a qualquer ferramenta ou serviço** que forneça um servidor MCP
- **Padronizando integrações** para que você não precise editar o código do LibreChat para cada ferramenta
- **Suporte a ambientes multiusuário** com autenticação e isolamento adequados
- **Adicionando e atualizando servidores em tempo de execução** a partir do painel de Configurações do MCP, sem editar um arquivo de configuração ou reiniciar

## Como o MCP funciona no LibreChat [#how-mcp-works-in-librechat]

O LibreChat oferece duas maneiras de usar servidores MCP, seja na área de chat ou com agentes.

Você pode configurar servidores MCP manualmente em seu arquivo `librechat.yaml` ou usando o [smithery.ai](https://smithery.ai) para encontrar e instalar servidores MCP no `librechat.yaml` ([veja o exemplo abaixo](#basic-configuration)). Sempre que você adicionar ou editar um servidor no `librechat.yaml`, será necessário reiniciar o LibreChat para inicializar as conexões. Servidores adicionados através do [painel de Configurações MCP](#adding-mcp-servers-in-the-ui) entram em vigor sem a necessidade de reinicialização. Um servidor criado pelo painel que utiliza OAuth é registrado ao salvar, mas inicia desconectado: [autentique-o](#step-3-check-connection-status-and-authenticate) uma vez para conectá-lo.

### URL de Callback OAuth [#oauth-callback-url]

Para servidores MCP com OAuth habilitado, a URL de callback do LibreChat é:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>` é a chave usada em `mcpServers` no `librechat.yaml` ou o nome do servidor criado na interface de configurações de MCP. Por exemplo, um servidor chamado `salesforce` com `DOMAIN_SERVER=https://chat.example.com` usa `https://chat.example.com/api/mcp/salesforce/oauth/callback`.

Registre esta URL de retorno exata no provedor OAuth. Instalações locais do Docker geralmente usam `http://localhost:3080` como a URL base.

### Na Área de Chat [#in-chat-area]

![O catálogo de servidores MCP aberto a partir da paleta do composer, mostrando o status de conexão de cada servidor](/images/mcp/mcp_servers_catalog.png)

O LibreChat exibe servidores MCP configurados diretamente na área de chat ao usar endpoints tradicionais (OpenAI, Anthropic, Google, Bedrock, etc.):

- Selecione primeiro qualquer endpoint que não seja de agente e um modelo compatível com ferramentas
- Os servidores MCP aparecem na seção **MCP Servers** da [paleta **+** do composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers), e cada servidor selecionado é exibido como um chip no composer
- Quando selecionado, todas as ferramentas daquele servidor tornam-se disponíveis para o seu modelo atual
- Acesso rápido a ferramentas MCP sem a necessidade de criar um agente, permitindo o uso de múltiplos servidores simultaneamente

Para manter um servidor MCP fora da seleção regular de chat, defina [`chatMenu: false`](/docs/configuration/librechat_yaml/object_structure/mcp_servers#chatmenu) em sua configuração:

```yaml
mcpServers:
  internal-tools:
    command: npx
    args: ['-y', 'internal-mcp-server']
    chatMenu: false # Not selectable in regular chat
```

Esta configuração é aplicada em solicitações de chat, bem como no seletor, para que uma seleção salva obsoleta não possa continuar usando um servidor oculto. Ela não remove o servidor de Agents salvos ou de um model spec que o atribua explicitamente. O LibreChat também omite servidores que um usuário só pode alcançar por meio de um Agent autorizado do seletor de chat regular e do caminho de solicitação.

### Com Agents [#with-agents]

Servidores MCP integram-se perfeitamente aos Agents do LibreChat:

1. Criar ou editar um agente
2. Abra **Add tools** no Agent Builder e selecione **MCP**
3. Selecione um servidor MCP; cada servidor aparece como uma única entrada de catálogo
4. Expanda o servidor selecionado para ativar ou desativar ferramentas individuais
5. Salve seu agente

![Ferramentas MCP no Construtor de Agentes](/images/mcp/mcp_ui_agent.png)

Essa organização de nível superior mantém a interface gerenciável - até mesmo servidores com mais de 20 ferramentas (como o Spotify) aparecem como entradas únicas que podem ser expandidas para um controle granular.

### Configuração Básica [#basic-configuration]

Adicione servidores MCP ao seu arquivo `librechat.yaml` manualmente:

```yaml
mcpServers:
  # ClickHouse Cloud
  clickhouse-cloud:
    type: streamable-http
    url: https://mcp.clickhouse.cloud/mcp

  # File system access
  filesystem:
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /path/to/your/documents

  # Web browser automation
  puppeteer:
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'

  # Production-ready cloud service
  business-api:
    type: streamable-http
    url: https://api.yourbusiness.com/mcp
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
    serverInstructions: true
```

### Adicionando Servidores MCP na UI [#adding-mcp-servers-in-the-ui]

Você também pode adicionar e configurar servidores MCP diretamente da interface do LibreChat sem editar arquivos de configuração ou reiniciar o servidor.

#### Passo 1: Abra o painel de configurações do MCP [#step-1-open-the-mcp-settings-panel]

Navegue até o painel **MCP Settings** na barra lateral direita. Você verá todos os servidores MCP existentes listados aqui, juntamente com um botão **+** para adicionar novos.

![Painel de Configurações do MCP](/images/mcp/mcp_ui_settings_panel.png)

#### Passo 2: Preencha os detalhes do servidor [#step-2-fill-out-server-details]

Pressione o botão **+** e preencha o nome do seu servidor MCP, descrição, URL, tipo de transporte e método de autenticação, e então clique em **Create**.

![Diálogo Adicionar Servidor MCP](/images/mcp/mcp_ui_configure.png)

Seu novo servidor aparecerá no painel de MCP Settings com uma notificação de confirmação.

![Servidor MCP criado com sucesso](/images/mcp/mcp_ui_success_registered.png)

#### Passo 3: Verifique o Status da Conexão e Autentique [#step-3-check-connection-status-and-authenticate]

Revise o [indicador de status da conexão](#connection-status-indicators) para o seu novo servidor. Se o servidor exigir autenticação OAuth, o status será exibido como desconectado. Selecione o servidor MCP na paleta **+** do compositor para iniciar o fluxo de autenticação.

![Status da Conexão - Desconectado](/images/mcp/mcp_ui_unconnected.png)

Uma vez iniciado, o indicador de status será atualizado para mostrar que a autenticação está em andamento.

![Status da Conexão - Autenticando](/images/mcp/mcp_ui_authenticating.png)

#### Passo 4: Continue com OAuth [#step-4-continue-with-oauth]

O LibreChat apresenta um prompt de confirmação de **Connect**. Revise o destino e selecione **Continue with OAuth** para abrir a página de autorização do provedor em uma nova aba do navegador. Conclua o fluxo de login e consentimento do provedor lá.

Se um fluxo iniciado neste navegador estiver pendente, o LibreChat mantém esse servidor em um estado de autorização/conexão, mesmo que o status da conexão em cache ainda indique **Connected**. O prompt não deve ser fechado apenas porque um status antigo relata uma autorização durável; o sucesso, falha, tempo limite ou cancelamento do terminal encerra o fluxo pendente. Um fluxo iniciado em outra aba ou navegador não possui estado pendente local nesta visualização.

![Prompt de Continuação OAuth](/images/mcp/mcp_ui_callback_confirm.png)

#### Passo 5: Autenticação Bem-sucedida [#step-5-authentication-successful]

Após autenticar, você verá uma confirmação de sucesso. Esta janela será fechada automaticamente e redirecionará você de volta ao LibreChat.

![Autenticação bem-sucedida](/images/mcp/mcp_ui_success_redirect.png)

#### Passo 6: Servidor pronto para uso [#step-6-server-ready-for-use]

O LibreChat reconhece a autenticação bem-sucedida e seleciona automaticamente o servidor MCP para uso dentro da sua conversa. O servidor agora exibe um indicador de status conectado e aparece como um chip selecionado no compositor.

![Servidor MCP autenticado e selecionado automaticamente](/images/mcp/mcp_ui_done.png)

Seu novo servidor MCP também está disponível no Agent Builder, onde você pode adicionar suas ferramentas a qualquer agente e personalizar qual subconjunto de ferramentas é permitido.

![Servidor MCP disponível no Construtor de Agentes](/images/mcp/mcp_ui_agent.png)

#### Variáveis de Credencial para Servidores Criados na UI [#credential-variables-for-ui-created-servers]

Ao adicionar um servidor MCP através da interface do usuário, você pode exigir que os usuários forneçam suas próprias chaves de API. Na seção Authentication da caixa de diálogo MCP Server Builder, selecione "API Key" e marque **"User provides key"**. Escolha o formato do cabeçalho (Bearer, Basic ou Custom) e salve o servidor.

Nos bastidores, o LibreChat cria uma entrada `customUserVars` vinculada ao destino chamada `MCP_API_KEY_<hash>` e configura o cabeçalho de autenticação correspondente. O nome é gerenciado automaticamente; os usuários ainda inserem sua chave na Caixa de Diálogo de Seleção de Ferramentas MCP ou no painel de Configurações MCP. Servidores existentes podem manter o nome legado `MCP_API_KEY` enquanto o limite de suas solicitações permanecer inalterado. Isso utiliza a mesma interface de usuário de inserção de chave que as [`customUserVars` definidas em YAML](#user-provided-credentials).

Alterar a URL (incluindo caminho ou consulta), proxy, transporte, formato de autorização, cabeçalho de autenticação personalizado ou cliente/destino OAuth configurado de um servidor criado pela interface exige que cada usuário insira uma chave para o novo limite. Chaves antigas salvas não são encaminhadas para esse destino de substituição. Edições cosméticas, URLs normalizadas equivalentes e edições de URL de saída apenas de fragmento preservam a chave existente. Servidores compartilhados podem resolver apenas variáveis de credencial declaradas por sua configuração atual, portanto, um editor não pode referenciar um nome gerado anteriormente para recuperar uma chave anterior. Nenhuma migração de credenciais em massa é necessária. Atualize **cada réplica da API**, incluindo réplicas que atendem a solicitações de edição de servidor, antes de confiar nesta proteção; um escritor mais antigo ainda pode recriar uma configuração não vinculada.

Quando uma chave de API de administrador ou de usuário é configurada, o LibreChat trata o servidor como autenticado por chave de API e ignora a detecção automática de OAuth. Uma configuração explícita de OAuth ainda tem precedência. Se um servidor com chave de API criado pela interface foi salvo por uma versão mais antiga do LibreChat e permanece travado em **OAuth Required**, edite e salve o servidor uma vez para que seus metadados de conexão armazenados sejam atualizados.

<Callout type="warning">
Por motivos de segurança, servidores MCP criados pela UI (provenientes do banco de dados) **apenas** podem resolver placeholders `customUserVars` (`{{VAR_NAME}}`). Variáveis de ambiente do lado do servidor (`${ENV_VAR}`), campos de perfil de usuário (`{{LIBRECHAT_USER_*}}`) e tokens OIDC (`{{LIBRECHAT_OPENID_*}}`) são bloqueados intencionalmente para evitar acesso não autorizado a segredos do servidor ou dados de outros usuários. Para suporte completo a placeholders, configure o servidor no `librechat.yaml` em vez disso.
</Callout>

## Gerenciamento de Servidor MCP [#mcp-server-management]

O LibreChat fornece ferramentas abrangentes para gerenciar conexões de servidor MCP com rastreamento de status de conexão e suporte a autenticação e inicialização OAuth na interface do usuário.

### Indicadores de Status de Conexão [#connection-status-indicators]

O LibreChat exibe ícones de status dinâmicos que mostram o estado atual de cada servidor MCP na paleta **+** do compositor e no painel de configurações:

![Ícones de Status do Servidor MCP](/images/mcp/mcp_server_status_icons.png)

**Tipos de Status:**

- **Conectado** (engrenagem verde): O servidor está conectado e possui customUserVars configuráveis
- **OAuth Required** (chave âmbar): O servidor requer autenticação OAuth
- **Desconectado** (plugue laranja): Conexão com o servidor falhou ou foi perdida
- **Inicializando** (carregador azul): O servidor está iniciando ou reconectando
- **Erro** (triângulo vermelho): O servidor encontrou um erro
- **Cancelando** (x vermelho): O fluxo de OAuth está sendo cancelado

### Cancelando OAuth a partir da caixa de diálogo da Agent Tool [#cancelling-oauth-from-the-agent-tool-dialog]

Em **Agent Builder → Tool Library → MCP server configuration**, **Connect** torna-se uma ação **Cancel** habilitada enquanto o gerenciador de servidor compartilhado reporta um fluxo OAuth cancelável. Isso inclui um fluxo pendente descoberto a partir de outro painel do LibreChat. Escolha **Cancel** para interromper esse fluxo, fechar o prompt de OAuth local e limpar sua seleção automática de ferramentas pendente. Um resultado de conexão tardio após o cancelamento não anexa ferramentas automaticamente nesta caixa de diálogo. Você pode escolher **Connect** novamente para uma nova tentativa. A inicialização que não é cancelável ainda mostra seu estado de ocupado desabilitado em vez de uma ação de cancelamento.

       <Video src="/videos/mcp_config_dialog_auth.mp4" title="Autenticação da caixa de diálogo de configuração MCP" />

  **Do Painel de Configurações do MCP:**

- Configure variáveis de usuário personalizadas e clique no botão Authenticate/Initialize dependendo do tipo de autenticação do servidor

  <Video src="/videos/mcp_settings_init.mp4" title="Inicialização do painel de configurações MCP" />

As falhas de inicialização agora distinguem um servidor inacessível, `customUserVars` ausentes, uma conexão OAuth que precisa ser autenticada novamente e uma falha de inicialização genérica. Use as variáveis ausentes nomeadas ou a ação de reautenticação na mensagem antes de tentar novamente; o servidor não precisa mais ser removido e adicionado novamente para esses casos.

O carregamento passivo do catálogo consolida tentativas de descoberta OAuth e reduz progressivamente a frequência após falhas, para que uma integração desconectada não tente realizar a descoberta a cada solicitação. As alterações de credenciais são protegidas por geração entre réplicas, impedindo que um resultado de descoberta mais antigo sobrescreva uma autenticação mais recente. Os operadores podem ajustar a política de recuperação limitada em [`mcpSettings.catalogRecovery`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#catalogrecovery); os padrões são adequados para a maioria das implantações.

Se um Agent espera explicitamente ferramentas MCP, mas nenhuma pode ser resolvida no início da execução, o LibreChat falha a execução com orientações de conexão e acesso em vez de executar silenciosamente sem essas ferramentas.

Servidores MCP que emitem `notifications/tools/list_changed` podem atualizar seu catálogo de ferramentas sem a necessidade de reiniciar o LibreChat. O LibreChat busca a lista atual da conexão ativa, publica as ferramentas adicionadas e para de anunciar as ferramentas que o servidor removeu. Reconexões também sincronizam o catálogo antes que a conexão seja considerada pronta. Atualizações de snapshot gerenciadas e a descoberta de servidores inativos compartilham um gate de três operações em todo o processo. Uma vez admitida, cada operação permanece limitada pelo seu prazo de lista de ferramentas ou de descoberta por servidor, incluindo qualquer `initTimeout` mais curto, para que o trabalho lento no catálogo não possa ocupar um slot indefinidamente.

Para servidores HTTP com suporte a streaming, uma reconexão pode retornar brevemente um HTTP `409` quando o servidor ainda mantém um fluxo SSE autônomo obsoleto para a sessão antiga. O LibreChat trata isso como transitório, encerra a sessão obsoleta e restabelece a conexão automaticamente; nenhuma ação do operador é necessária quando a recuperação é bem-sucedida. Se a conexão restabelecida também falhar, o LibreChat continuará a exibir o erro de conexão subjacente.

O LibreChat classifica respostas HTTP transmissíveis (Streamable) a partir do tipo de mídia `Content-Type` analisado, em vez de uma correspondência de substring. Parâmetros não podem fazer com que uma resposta que não seja SSE pareça ser `text/event-stream`, portanto, erros de tamanho de resposta continuam através do caminho de tratamento correto para SSE ou não-SSE.

### Visibilidade do Painel de Configurações MCP [#mcp-settings-panel-visibility]

O Painel de Configurações MCP aparece na barra lateral direita quando o LibreChat detecta servidores MCP que podem exigir intervenção do usuário durante sua inicialização. O painel ficará visível quando qualquer servidor configurado atender a um destes critérios:

- **Variáveis de Usuário Personalizadas**: O servidor possui `customUserVars` definidas, que podem conter credenciais fornecidas pelo usuário
- **Autenticação OAuth**: O servidor é detectado como exigindo autenticação OAuth durante a inicialização
- **Inicialização Manual**: O servidor está configurado com `startup: false`, exigindo inicialização manual

## Recursos específicos do LibreChat [#librechat-specific-features]

A implementação de MCP do LibreChat foi projetada para ambientes multiusuário do mundo real altamente configuráveis.

### Conexões Específicas do Usuário [#user-specific-connections]

- Cada usuário obtém sua própria conexão isolada com os servidores MCP
- A autenticação de usuário e as permissões são respeitadas
- Dados pessoais e contexto permanecem privados

### Compartilhando Servidores MCP [#sharing-mcp-servers]

Os servidores MCP participam do sistema de [controle de acesso granular](/docs/features/access_control) do LibreChat. Além dos servidores definidos no `librechat.yaml` (que são gerenciados por administradores e regidos pelas permissões de recurso [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)), os servidores MCP criados pelo usuário possuem sua própria ACL e podem ser compartilhados com **usuários**, **grupos**, **funções** ou **publicamente**, no nível de Visualizador, Editor ou Proprietário.

As flags de recurso `USE`, `CREATE`, `SHARE` e `SHARE_PUBLIC` em `interface.mcpServers` controlam quem tem permissão para criar e compartilhar servidores MCP. Consulte [Access Control](/docs/features/access_control) para saber como as camadas de permissão se compõem.

### Contexto Dinâmico do Usuário [#dynamic-user-context]

Os servidores MCP podem acessar informações do usuário por meio de placeholders em **URLs e headers** (para transportes SSE e HTTP Streamable):

```yaml
mcpServers:
  user-api:
    type: streamable-http
    url: https://api.example.com/users/{{LIBRECHAT_USER_USERNAME}}/mcp
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
      X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
      Authorization: 'Bearer ${API_TOKEN}'
```

Os placeholders disponíveis incluem:

- `{{LIBRECHAT_USER_ID}}` - Identificador único de usuário
- `{{LIBRECHAT_USER_EMAIL}}` - Endereço de e-mail do usuário
- `{{LIBRECHAT_USER_ROLE}}` - Função do usuário (admin, user, etc.)
- `{{LIBRECHAT_USER_USERNAME}}` - Nome de usuário
- E muitos outros (veja [Configuração de Servidores MCP](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers) para a lista completa)

Servidores MCP definidos em YAML também podem usar os placeholders `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}` e `{{LIBRECHAT_BODY_*}}`. Os valores de `{{LIBRECHAT_BODY_*}}` são delimitados pelo escopo da requisição, portanto, o LibreChat cria conexões para a execução ativa, reutiliza-as em chamadas de ferramentas durante essa execução e as encerra quando a requisição termina. Servidores com escopo de requisição são excluídos do cache persistente de ferramentas para que cabeçalhos e URLs específicos da requisição não sejam reutilizados fora da execução ativa. Como sua lista de ferramentas não pode ser resolvida antes que uma requisição de chat exista, o Agent Builder expõe uma seleção de ferramentas de tempo de execução para o servidor completo e resolve suas ferramentas no momento da execução. A conclusão do OAuth armazena a autorização, mas adia a conexão até que a primeira execução forneça o contexto da requisição. Os placeholders de usuário, OpenID e Graph são delimitados pelo escopo do usuário; transportes HTTP atualizam seus cabeçalhos resolvidos antes de cada chamada de ferramenta sem exigir uma reconexão por conta própria.

Operadores confiáveis podem usar `Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'` em um servidor remoto definido via YAML para transmitir o token de acesso OpenID ativo do usuário. Autenticação explícita via MCP OAuth, troca "on-behalf-of" e chaves de API de administrador têm precedência. Após um `401` ou `403`, o LibreChat pode atualizar a conexão uma vez, mas nunca repete automaticamente a chamada de ferramenta rejeitada. Consulte a [referência de placeholders de servidor MCP](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers) para orientações de configuração e segurança.

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` troca o token de acesso OpenID reutilizável do usuário através do fluxo on-behalf-of da Microsoft. [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration) define os escopos solicitados separados por espaço e tem como padrão `https://graph.microsoft.com/.default`. Isso é independente de `OPENID_GRAPH_SCOPES`, que configura a pesquisa de pessoas e grupos.

O placeholder `{{LIBRECHAT_BODY_PARENTMESSAGEID}}` é preenchido para chats de Agentes nativos, chamadas da API de Agentes compatíveis com OpenAI e execuções de Assistants legados. O Open Responses não possui uma identidade de mensagem pai equivalente e falha de forma segura (fails closed) quando um servidor MCP requer esse valor. Veja a [referência de placeholders do servidor MCP](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers).

### Instruções do Servidor [#server-instructions]

`serverInstructions` é um recurso do LibreChat que adiciona dinamicamente instruções configuradas quando qualquer ferramenta daquele servidor MCP é selecionada:

```yaml
mcpServers:
  filesystem:
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem', '/docs']
    serverInstructions: |
      When accessing files:
      - Always check file permissions first
      - Use absolute paths for reliability
      - Handle errors gracefully
```

Opções:

- `true`: Use as instruções anunciadas pelo servidor quando disponíveis
- `false`: Desativar instruções
- `string`: Use as instruções personalizadas literalmente (mostradas acima)

O LibreChat preserva esta declaração configurada separadamente das instruções obtidas durante a inspeção do servidor. Portanto, uma declaração `true` permanece habilitada durante a inspeção e recarregamentos do registro em cache, enquanto uma string personalizada permanece como autoritativa.

### Configuração de Timeout [#timeout-configuration]

Para operações MCP de longa duração, configure timeouts apropriados tanto para a inicialização quanto para as operações de ferramentas.

```yaml
mcpServers:
  data-processor:
    type: streamable-http
    url: https://api.example.com/mcp
    initTimeout: 15000 # 15 seconds for server initialization
    timeout: 60000 # 60 seconds for tool operations
```

**Nota**: Se as operações ainda estiverem sendo interrompidas, verifique a configuração do seu proxy (por exemplo, nginx, traefik, etc.), que pode estar encerrando conexões prematuramente devido a timeouts padrão.

Quando um usuário pressiona **Stop** durante uma chamada de ferramenta de Agent em primeiro plano, o LibreChat encaminha o sinal de cancelamento da execução para o MCP. Para servidores HTTP transmissíveis (Streamable), o SDK do MCP envia `notifications/cancelled`; o servidor deve honrar essa notificação para interromper seu próprio trabalho. Chamadas em segundo plano (detached) mantêm intencionalmente um ciclo de vida separado e não são canceladas com o turno em primeiro plano.

### Credenciais Fornecidas pelo Usuário [#user-provided-credentials]

Você pode permitir que os usuários forneçam suas próprias credenciais para servidores MCP por meio de `customUserVars`. Isso possibilita uma autenticação segura e específica do usuário, sem armazenar credenciais em arquivos de configuração.

```yaml
mcpServers:
  my-api-server:
    type: streamable-http
    url: 'https://api.example.com/mcp'
    headers:
      X-Auth-Token: '{{MY_API_KEY}}' # Uses the user-provided value
    customUserVars:
      MY_API_KEY:
        title: 'API Key'
        description: "Enter your personal API key from <a href='https://example.com/keys' target='_blank'>your account settings</a>"
```

Os usuários podem configurar estas credenciais:

- **Da Área de Chat**: Escolha **Configure** na linha de um servidor MCP configurável na paleta **+** do compositor
- **No painel de configurações do MCP**: Acesse "MCP Settings" no painel direito para gerenciar as credenciais de todos os servidores configurados

#### Reinicializando servidores MCP com credenciais de usuário [#reinitializing-mcp-servers-with-user-credentials]

Para servidores MCP que exigem credenciais específicas do usuário antes de poderem ser usados (por exemplo, `PAT_TOKEN` no [servidor MCP oficial do GitHub](https://github.com/github/github-mcp-server)), o LibreChat permite que os usuários forneçam essas credenciais e, em seguida, reinicializem o servidor MCP a partir da interface do usuário sem reiniciar toda a aplicação:

1. Ao selecionar um MCP que utiliza `customUserVars`, você poderá **Salvar** ou **Revogar** o valor de uma `customUserVar` para o servidor MCP selecionado a partir do Painel MCP.
2. Após salvar um valor para uma `customUserVar`, clique no botão de reinicialização (um ícone com setas circulares ao lado de cada nome de servidor no Painel MCP).
3. O LibreChat tentará se conectar ao servidor usando suas credenciais fornecidas e o notificará com um aviso (toast) se o processo de reinicialização foi bem-sucedido ou falhou.

> _Dica: Se você sabe que um servidor exigirá credenciais que não estão disponíveis na inicialização, você pode adicionar `startup: false` à sua configuração. Isso instrui o LibreChat a não tentar se conectar a esse servidor até que ele seja reinicializado manualmente na interface do usuário._

**Exemplo:**

```yaml
mcpServers:
  github-mcp:
    type: streamable-http
    url: 'https://api.githubcopilot.com/mcp/'
    headers:
      Authorization: '{{PAT_TOKEN}}'
    customUserVars:
      PAT_TOKEN:
        title: 'GitHub PAT Token'
        description: 'GitHub Personal Access Token'
    startup: false
```

### Autenticação OAuth [#oauth-authentication]

O LibreChat oferece suporte à autenticação OAuth para servidores MCP, seguindo a recomendação da Anthropic para conexões MCP seguras. O OAuth fornece uma maneira padronizada e segura de autenticar sem armazenar credenciais de longa duração.

#### Fluxos OAuth Suportados [#supported-oauth-flows]

Os servidores MCP do LibreChat suportam OAuth 2.0 com:

- **Authorization Code Flow with PKCE**: Recomendado para segurança máxima
- **Descoberta de Cliente**: Registro automático de cliente quando suportado pelo provedor OAuth
- **Refresh Tokens**: Renovação automática de token quando disponível
- **Descoberta do endpoint de token**: Clientes pré-configurados podem descobrir se o provedor espera credenciais de cliente no corpo da requisição POST ou em um cabeçalho de autorização HTTP Basic

No MCP Builder, o **Token Exchange Method** oferece **Auto**, **Default (POST request)** e **Basic authorization header**. O Auto deixa o método não definido para que o LibreChat possa usar metadados de provedores confiáveis, recorrendo à autenticação Basic quando o provedor não anuncia um método.

#### Exemplos de configuração [#configuration-examples]

```yaml
mcpServers:
  # Public remote MCP server for PayPal, uses OAuth Client Discovery
  # ❌ Refresh Tokens: you may need to re-authenticate periodically
  # More info: https://developer.paypal.com/tools/mcp-server/
  paypal:
    type: 'sse'
    initTimeout: 150000 # higher timeout to allow for initial authentication
    url: 'https://mcp.paypal.com/sse'

  # Example self-hosted remote MCP server for Spotify, uses OAuth Client Discovery
  # ✅ Refresh Tokens: refreshes token for authentication automatically
  # Hosted on Cloudflare Workers, more info: https://github.com/LibreChat-AI/spotify-mcp
  spotify:
    type: 'streamable-http'
    initTimeout: 150000
    url: 'https://mcp-spotify-oauth-example.account.workers.dev/mcp'
```

#### Fluxo de Autenticação OAuth [#oauth-authentication-flow]

Ao configurar pela primeira vez um servidor MCP habilitado para OAuth:

1. **Conexão Inicial**: O LibreChat tenta se conectar ao servidor MCP
2. **Autenticação Necessária**: Se nenhum token válido existir, você verá um status de autenticação OAuth para esse servidor na paleta **+** do compositor.
3. **Iniciar Login**: Selecione o servidor para iniciar o fluxo OAuth
4. **Continue ou use outro dispositivo**: Continue no navegador atual, copie o link de autorização ou exiba um QR code para abri-lo em outro dispositivo
5. **Redirecionamento de Navegador**: Conclua a autenticação com o provedor OAuth
6. **Tratamento de Retorno**: O LibreChat processa automaticamente o callback de OAuth assim que você se autentica
7. **Armazenamento de Tokens**: O LibreChat armazena os tokens de forma segura para uso futuro
8. **Conexão Estabelecida**: Uma vez autenticado, o servidor MCP estará conectado e você poderá usá-lo em seu chat

#### URL de Callback OAuth [#oauth-callback-url-1]

Quando um servidor MCP utiliza OAuth, o LibreChat expõe um endpoint de callback para o qual o provedor de OAuth redireciona após uma autorização bem-sucedida.

A URL de callback deve seguir este formato:

`${baseUrl}/api/mcp/${serverName}/oauth/callback`

Onde `${serverName}` é a chave do servidor MCP definida na sua configuração `librechat.yaml`. O LibreChat gerencia o redirecionamento neste endpoint, conclui a troca de token e associa as credenciais ao servidor MCP correspondente.

<Callout type="info" title="Exemplo de URL de Callback OAuth">
Dada a seguinte configuração de servidor MCP:

```yaml
mcpServers:
  # Example self-hosted remote MCP server for Spotify, uses OAuth Client Discovery
  # ✅ Refresh Tokens: refreshes token for authentication automatically
  # Hosted on Cloudflare Workers, more info: https://github.com/LibreChat-AI/spotify-mcp
  spotify:
    type: 'streamable-http'
    initTimeout: 150000
    url: 'https://mcp-spotify-oauth-example.account.workers.dev/mcp'
```

A URL de callback seria `${baseUrl}/api/mcp/spotify/oauth/callback`.

</Callout>

Nota:

- A URL de callback deve ser registrada exatamente com o provedor OAuth para que o fluxo funcione.
- Outros caminhos como `/api/oauth/callback` ou `/api/oauth/openid/callback` não são válidos para fluxos de OAuth do MCP.

#### Gerenciamento de Tokens [#token-management]

O LibreChat gerencia tokens OAuth de forma inteligente:

- **Armazenamento Seguro**: Os tokens são criptografados e armazenados de forma segura
- **Atualização Automática**: Quando tokens de atualização estão disponíveis, o LibreChat renova automaticamente tokens de acesso expirados
- **Recuperação Silenciosa de 401**: Se uma conexão MCP OAuth receber uma rejeição de autenticação no meio da sessão, o LibreChat coordena uma tentativa limitada de atualização e reconexão por usuário e servidor. Chamadores simultâneos compartilham esse resultado de recuperação antes que o LibreChat exiba um novo prompt de autenticação.
- **Gerenciamento de Sessão**: Cada usuário mantém suas próprias sessões OAuth para ambientes multiusuário

Se um fluxo de Agent salvo for recarregado ou retomado enquanto uma solicitação de autorização MCP ainda estiver pendente, o LibreChat reconstrói essa solicitação a partir do estado de geração durável. Solicitações concluídas, canceladas, falhas ou expiradas não são restauradas.

Clientes OAuth e tokens armazenados estão vinculados à URL do servidor MCP e às configurações de cliente/endpoint OAuth. Alterar essas configurações exige que os usuários se autentiquem novamente. Ao editar um servidor criado pela interface que retém um `client_secret` armazenado, insira novamente o segredo ao alterar um campo de vinculação, como a URL do servidor, ID do cliente, URL de autorização, URL do token ou método de autenticação de token.

Em implantações com escalonamento horizontal, o status do fluxo OAuth e a prontidão do token vinculado podem ser reconciliados entre os pods do LibreChat. A UI relata que um servidor está pronto apenas após a inicialização pós-OAuth ser bem-sucedida, mesmo quando o callback e a sondagem de status atingem pods diferentes. Callbacks de tentativas substituídas são rejeitados.

Quando o Redis está habilitado, as gerações de catálogo MCP em nível de aplicação e as revisões de publicação são coordenadas entre as réplicas. Implantações de Redis Cluster utilizam chaves de catálogo e atualizações seguras para slots, portanto, a sincronização na inicialização e as atualizações de `tools/list_changed` não exigem um layout de Redis de nó único.

Cada usuário será solicitado a autenticar com seu próprio login OAuth ao usar um servidor MCP habilitado para OAuth pela primeira vez. Isso garante que os detalhes de conexão e autenticação sejam exclusivos para cada usuário, mantendo a segurança e a privacidade em ambientes multiusuário.

#### Tempo de OAuth [#oauth-timing]

A conclusão do OAuth do MCP usa seu próprio tempo limite configurado no servidor em vez de reutilizar o `initTimeout` do servidor MCP. Por padrão, o LibreChat aguarda até 10 minutos para que um usuário conclua o OAuth do MCP e mantém o estado do fluxo por 15 minutos.

Use estas variáveis de ambiente quando um provedor OAuth ou fluxo de trabalho do usuário precisar de mais tempo:

```bash filename=".env"
MCP_OAUTH_HANDLING_TIMEOUT=600000
MCP_OAUTH_FLOW_TTL=900000
```

`MCP_OAUTH_FLOW_TTL` é limitado para durar mais que `MCP_OAUTH_HANDLING_TIMEOUT`, para que callbacks próximos ao prazo final ainda possam encontrar seu estado de fluxo. A janela de polling do server-card do MCP segue o timeout de manipulação configurado.

> Nota: Os tokens exibidos durante a inicialização do aplicativo são apenas para a inicialização em nível de aplicativo e não são usados para conexões individuais de usuários.

Exemplo de atualização automática de token:

```bash

[MCP][spotify] Attempting to refresh token
[MCP][spotify] Successfully refreshed and stored OAuth tokens

```

#### Melhores Práticas [#best-practices]

1. **Use OAuth quando disponível**: Prefira OAuth em vez de chaves de API para melhor segurança
2. **Configure timeouts apropriados**: Use `MCP_OAUTH_HANDLING_TIMEOUT` e `MCP_OAUTH_FLOW_TTL` para janelas de conclusão de OAuth; use `initTimeout` para a inicialização do servidor
3. **Monitorar expiração de tokens**: Verifique os logs para problemas de autenticação
4. **Plano para reautenticação**: Alguns provedores não suportam tokens de atualização

## Server Transports [#server-transports]

Servidores MCP podem ser configurados para usar diferentes mecanismos de transporte:

**Servidores STDIO**

- Funciona bem para ambientes locais de usuário único
- Não escalável para implantações remotas ou em nuvem
- O SDK MCP integrado limita cada mensagem STDIO individual a 10 MB. Um único resultado maior fecha o transporte com um erro; este limite é separado do tamanho total de uma sessão ou stream.

**Servidores Server-Sent Events (SSE)**

- Mecanismo de transporte remoto, mas não recomendado para ambiente de produção

**Servidores HTTP com Suporte a Streaming**

- Usa HTTP POST para enviar mensagens e suporta respostas em streaming
- Opera como um processo independente que pode lidar com múltiplas conexões de clientes
- Suporta tanto requisições básicas quanto streaming via Server-Sent Events (SSE)
- Alternativa de maior desempenho ao transporte HTTP+SSE legado
- Suporta configurações de servidor multiusuário adequadas

**Para ambientes de produção**, apenas servidores MCP com ["Streamable HTTP" transports](https://modelcontextprotocol.io/specification/draft/basic/transports/streamable-http) são recomendados. Diferente do SSE, que mantém conexões de longa duração, o Streamable HTTP oferece opções sem estado (stateless) que são mais adequadas para implantações escaláveis e multiusuário.
