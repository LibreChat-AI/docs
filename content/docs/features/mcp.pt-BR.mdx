MCP (Model Context Protocol) é um padrão aberto para expor ferramentas a um modelo. Um servidor MCP pode dar ao modelo acesso a um sistema de arquivos, a um navegador, a um banco de dados ou à API interna da sua empresa, e o LibreChat pode usar qualquer servidor que siga o protocolo. Você pode anexar servidores a um chat comum para uso rápido ou adicionar as ferramentas deles a um agente.

## Usar um servidor no chat [#use-a-server-in-chat]

Em qualquer endpoint diferente de Agents ou Assistants, abra a paleta **+** do compositor (**Anexar e ferramentas**) e procure em **Servidores MCP**. Clique em um servidor para ativá-lo na conversa. Ele aparece como um chip no compositor, e todas as ferramentas expostas pelo servidor ficam disponíveis para o modelo. A paleta permanece aberta, então você pode ativar vários servidores de uma vez; clique em um servidor novamente, ou remova o chip dele, para desativá-lo. Veja [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) para o restante da paleta.

A paleta mostra alguns servidores por vez, com um ponto colorido para o status de cada servidor. **Show All** no cabeçalho **MCP Servers** abre a lista completa com um campo de pesquisa e três visualizações: **All**, **Made by you** e **Favorites**.

![O diálogo Servidores MCP aberto com Mostrar Tudo, listando um servidor Github marcado como Desconectado e um servidor Spotify marcado como Precisa de Autenticação, com os filtros Todos, Criados por você e Favoritos](/images/mcp/mcp_servers_catalog.png)

Se o servidor ainda não estiver conectado, clicar nele inicia a conexão em vez de selecioná-lo imediatamente. Um servidor que exige suas próprias credenciais abre uma caixa de diálogo para que você as informe primeiro; um servidor que usa OAuth encaminha você para o login. Assim que a conexão for estabelecida, o LibreChat o seleciona automaticamente para você.

Escolha um modelo que suporte chamadas de ferramentas, caso contrário o modelo nunca chamará as ferramentas do servidor. Agents e Assistants possuem sua própria configuração de ferramentas, por isso o seletor fica oculto nesses endpoints, e um administrador pode ocultar servidores individuais do chat para que fiquem disponíveis apenas para os agents.

## Adicionar um servidor a um agente [#add-a-server-to-an-agent]

No Agent Builder, clique em **Add** ao lado de **Tools** para abrir a **Tool Library** e, em seguida, filtre por **MCP servers**. Ao adicionar um servidor, são listadas as ferramentas que ele expõe; mantenha as que o agente deve ter e remova as demais, ou use **Select all** e **Deselect all**. Um servidor com dezenas de ferramentas ainda ocupa uma única entrada na lista de ferramentas do agente.

Cada ferramenta MCP em um agente também possui suas próprias opções (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Consulte [Agents](/docs/features/agents) para saber o que cada uma altera.

Alguns servidores dependem de valores que só existem durante uma requisição de chat, por isso suas ferramentas não podem ser listadas com antecedência. Para esses casos, a Biblioteca de Ferramentas anexa o servidor inteiro e indica que suas ferramentas são resolvidas em tempo de execução, durante o chat.

Se um agente estiver configurado para usar ferramentas MCP e nenhuma delas estiver disponível quando uma execução começar (o servidor está fora do ar ou você perdeu o acesso), a execução é interrompida com um erro orientando você a verificar a conexão e o seu acesso, em vez de responder sem as ferramentas. Pressionar **Stop** durante uma chamada de ferramenta também cancela a chamada no servidor MCP, desde que o servidor ofereça suporte a cancelamento.

## Status da conexão [#connection-status]

Na paleta e em **MCP Settings**, o status é indicado por um ponto colorido: cinza quando o servidor está desconectado e âmbar quando é necessário que você faça login. O status completo é lido para leitores de tela, e a Tool Library e a lista **Show All** descrevem o status por extenso ao lado de cada servidor.

- **Conectado**: pronto para uso.
- **Precisa de Autenticação**: o servidor usa OAuth e você ainda não fez login, ou seu login expirou.
- **Conectando** / **Inicializando**: uma tentativa de conexão está em andamento.
- **Desconectado** ou **Erro**: não há conexão ativa, ou a última tentativa falhou. Use **Conectar** para tentar novamente.
- **Sob demanda**: o servidor se conecta separadamente a cada requisição, portanto não há nenhuma conexão permanente a ser reportada.
- **Desconhecido**: nenhum status foi retornado ainda.

Quando uma conexão falha, o erro informa o motivo: o servidor não pôde ser alcançado, ele precisa de variáveis que você não definiu (nomeadas na mensagem) ou precisa que você faça login novamente. Corrija isso e conecte-se novamente; não é necessário remover e adicionar o servidor de novo. Um servidor também pode adicionar ou remover ferramentas enquanto está em execução, e o LibreChat carrega a nova lista sem precisar reiniciar.

As conexões são individuais por usuário. Seus tokens OAuth e credenciais salvas nunca são usados por outras pessoas, e uma conexão ociosa é encerrada por padrão após 15 minutos e reaberta na próxima vez que você usar o servidor.

## Entrar com OAuth [#sign-in-with-oauth]

Quando um servidor precisa de OAuth, conectá-lo abre uma caixa de diálogo **Connect**. Clique em **Continue with OAuth** para abrir a página de login do provedor em uma nova aba, ou use **Copy link** ou **Show QR Code** para concluir em outro dispositivo. Depois que você aprovar o acesso, a aba exibe **Authentication Successful** e se fecha automaticamente, e o servidor muda para **Connected**.

Enquanto um login estiver pendente, o servidor exibe um spinner; passe o mouse sobre ele para cancelar. Nas configurações do servidor MCP do Agent Builder, **Connect** se transforma em **Cancel** com a mesma finalidade. Você tem 10 minutos para concluir o login antes que a tentativa expire (o administrador pode alterar esse tempo).

Se o provedor emitir refresh tokens, o LibreChat renova o seu acesso em segundo plano. Quando um servidor rejeita seu token no meio da sessão, o LibreChat tenta uma renovação e reconexão antes de pedir que você faça login novamente. Provedores que não emitem refresh tokens pedem que você faça login novamente quando o token expira.

Por padrão, a solicitação de login aparece quando sua mensagem é enviada. Um administrador pode configurar alguns servidores para aguardar até que o agente chame pela primeira vez uma de suas ferramentas, de modo que você só seja solicitado a fazer login quando o servidor for realmente necessário.

## Credenciais e variáveis [#credentials-and-variables]

Alguns servidores precisam de um valor de cada usuário, como uma chave de API pessoal ou um ID de projeto. Ao conectar um desses servidores, o LibreChat solicita os valores antes de estabelecer a conexão. Para alterá-los depois, use **Configure** no servidor, no seletor do chat ou em **MCP Settings**. Cada campo tem os botões **Save** e **Revoke**. Qualquer um dos dois encerra sua conexão atual com esse servidor, de modo que o próximo uso se conecta com os novos valores; além disso, revogar também desativa o servidor no chat atual.

Os valores são armazenados por usuário e enviados somente para o servidor para o qual foram informados.

## Painel de configurações do MCP [#mcp-settings-panel]

**Configurações do MCP** no painel lateral lista todos os servidores que você pode usar, com um ponto de status no ícone de cada servidor. Dependendo do estado do servidor, cada cartão oferece **Conectar**, **Reconectar**, **Configurar** (para suas variáveis) ou **Revogar** (para descartar seus tokens OAuth). Os servidores que você tem permissão para editar também têm **Editar**.

## Criar um servidor pela interface [#create-a-server-from-the-ui]

Se o seu perfil permitir, clique em **Adicionar MCP** (o botão **+**) em **Configurações do MCP** para registrar um servidor remoto sem alterar o `librechat.yaml` nem reiniciar.

<Steps>
<Step>
### Descreva o servidor [#describe-the-server]

Insira um **Nome**, uma **Descrição** opcional e um ícone, se desejar. Preencha a **URL do Servidor MCP** e escolha um **Transporte**: **Streamable HTTPS** ou **SSE**.
</Step>
<Step>
### Escolha a autenticação [#choose-authentication]

Em **Autenticação**, escolha uma das opções:

- **Nenhum (Detecção automática)**: O LibreChat verifica o servidor e alterna para OAuth caso o servidor o solicite.
- **Chave de API**: insira uma chave compartilhada, ou marque **Cada usuário fornece sua própria chave** para que cada usuário insira a dele por meio de **Configurar**. Escolha o **Formato do Cabeçalho**: **Bearer**, **Basic** ou **Custom** com o nome de cabeçalho de sua preferência.
- **OAuth**: informe o **Client ID**, o **Client Secret**, a **Authorization URL**, a **Token URL** e o **Scope**. Deixe os campos de cliente vazios se o provedor oferecer suporte a registro dinâmico de cliente. O **Token Exchange Method** é **Auto** por padrão, que usa o que o provedor anuncia e recorre a um cabeçalho de autorização Basic caso contrário; escolha **Default (POST request)** ou **Basic authorization header** para forçar um dos métodos.
- **On-Behalf-Of (OBO)**: exibido somente se um administrador tiver concedido essa permissão a você, e só funciona quando o LibreChat autentica os usuários com OpenID Connect (por exemplo, Entra ID). Informe os escopos a serem solicitados; o LibreChat troca o seu token OpenID por um token com escopo para o servidor MCP.
</Step>
<Step>
### Criar [#create-it]

Marque **Eu confio nesta aplicação** e clique em **Criar**. O servidor fica disponível imediatamente. Para servidores OAuth, a próxima caixa de diálogo mostra o **Redirect URI** a ser registrado no seu provedor OAuth, e o servidor permanece desconectado até que você faça login uma vez.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="A caixa de diálogo Adicionar servidor MCP com um nome e uma URL preenchidos, Transporte definido como Streamable HTTPS e Autenticação definida como Chave de API com Cada usuário fornece sua própria chave marcado"
/>

Servidores criados desta forma só podem acessar URLs remotas; servidores `stdio` locais precisam ser definidos no `librechat.yaml`. Eles também não podem usar variáveis de ambiente do servidor nem marcadores de perfil do usuário: valores como `${API_TOKEN}` ou `{{LIBRECHAT_USER_EMAIL}}` em seus cabeçalhos são removidos, pois um servidor compartilhado os receberia de outra forma. Se você alterar a URL ou a autenticação de um servidor posteriormente, os usuários que inseriram sua própria chave precisarão inseri-la novamente, e os usuários de OAuth precisarão fazer login novamente. Ao alterar a URL ou os endpoints OAuth de um servidor com um client secret salvo, você também precisará inserir o secret novamente. Se um servidor com chave de API criado em uma versão anterior estiver preso em **Needs Auth**, abra-o com **Edit** e salve-o uma vez.

## Compartilhar um servidor [#share-a-server]

Servidores criados na interface pertencem a quem os criou. O proprietário pode compartilhar um servidor a partir da caixa de diálogo **Editar**, com usuários específicos, grupos, funções ou todos, como visualizador (pode ver e usar), editor (também pode alterá-lo) ou proprietário. Os servidores definidos em `librechat.yaml` ficam disponíveis para todos os que têm permissão para usar MCP. Consulte [Controle de Acesso](/docs/features/access_control) para saber como os níveis de permissão se combinam.

## Instruções do servidor [#server-instructions]

Um administrador pode anexar instruções a um servidor, sejam as próprias instruções do servidor ou um texto personalizado. Quando uma conversa ou agente possui as ferramentas desse servidor, as instruções são adicionadas ao contexto do modelo, o que ajuda em servidores cujas ferramentas só fazem sentido quando utilizadas em uma determinada ordem.

## Aplicativos MCP [#mcp-apps]

Alguns servidores retornam uma visualização interativa junto com o resultado de uma ferramenta. Quando os MCP Apps estão ativados, a chamada da ferramenta exibe um botão **Open app**, que carrega a visualização em um frame isolado (sandboxed), e **Close app**, que a oculta novamente. Apenas alguns apps podem estar abertos ao mesmo tempo; se você atingir o limite, feche um primeiro.

Um app não pode agir por conta própria. Quando ele quiser executar uma ferramenta, você verá **Run tool from app?**, e quando quiser enviar uma mensagem, **Send message from app?**. Nada acontece até que você aprove. Enviar uma mensagem inicia uma resposta do modelo na conversa atual, portanto o agente selecionado e suas ferramentas podem ser utilizados. Os apps não são renderizados em conversas compartilhadas.

## Configuração [#setup]

O MCP precisa de pelo menos um servidor. Os administradores definem servidores em `mcpServers` no `librechat.yaml`, o que exige uma reinicialização para aplicar, e usuários com permissão podem adicionar servidores remotos em **MCP Settings**. Consulte [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) para as opções de servidor, a URL de callback do OAuth e os transportes, [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) para domínios permitidos e MCP Apps, [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) para os limites dos apps, e [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) para saber quem pode usar, criar e compartilhar servidores. Os guias de configuração de servidores específicos estão em [MCP Servers](/docs/mcp_servers), e [Agent Plugins](/docs/features/agent_plugins) explica como agrupar servidores MCP com skills.
