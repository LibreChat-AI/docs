Agents API를 사용하면 LibreChat 외부의 코드에서 에이전트와 통신할 수 있습니다. 어떤 OpenAI SDK든 인스턴스를 가리키도록 설정하고 모델로 에이전트 ID를 전달하면, 익숙한 API를 통해 해당 에이전트의 전체 구성(지침, 도구, 파일)을 사용할 수 있습니다. 이를 활용해 스크립트, CI 작업 또는 다른 제품에 에이전트를 연결할 수 있습니다.

There are three parts:

- **추론**: API 키로 인증하는 Chat Completions 및 Open Responses (관리자가 설정한 경우 자체 OIDC 토큰 사용 가능).
- **Agent Events**: 다른 시스템의 작업(예: webhook)을 에이전트에 전달하고, 해당 작업이 완료되었는지 추적합니다. API 키 전용입니다.
- **Agent Management**: 신뢰할 수 있는 서비스에서 머신 OIDC 토큰을 사용하여 에이전트와 스킬을 생성하고 편집합니다.

<Callout type="warning" title="베타">
  엔드포인트, 요청 형식, 응답은 릴리스 간에 여전히 변경될 수 있습니다.
</Callout>

## API 키 발급받기 [#get-an-api-key]

**설정**을 열고 **Data & Privacy**로 이동한 다음, **API keys** 아래에서 **Agent API Keys**를 찾으세요. **Manage**를 클릭한 후 **Create API Key**를 클릭하고, 이름을 입력한 뒤 만료 기간(7일부터 1년까지, 또는 never)을 선택하세요. 키는 한 번만 표시되므로 생성 즉시 복사하세요.

키는 당신을 대신합니다. API를 통해 당신이 접근할 수 있는 모든 것은 키를 가진 누구든지 접근할 수 있으므로, 더 이상 사용하지 않는 키는 삭제하세요. 키를 삭제하면 해당 키를 사용하는 애플리케이션이 즉시 차단됩니다.

섹션이 보이지 않는다면, 귀하의 역할에 Agents API 접근 권한이 부여되지 않은 것입니다.

## 호출할 수 있는 에이전트 [#which-agents-you-can-call]

당신이 소유하거나 공유받은 에이전트는 호출할 수 있습니다. 다른 사람의 에이전트의 경우, 소유자가 Agent Builder 하단의 **Remote Access** 버튼(지구본 아이콘)을 사용하여 액세스 권한을 부여해야 합니다. 이는 일반 공유와는 별개입니다. LibreChat에서 에이전트와 채팅할 수 있다고 해서 API를 통해 해당 에이전트를 호출할 수 있는 것은 아닙니다.

에이전트 ID가 필요합니다. 이 ID는 빌더의 **Advanced Settings**에 복사 버튼과 함께 표시됩니다. `GET /api/agents/v1/models`는 사용자의 키로 호출할 수 있는 에이전트 목록을 반환하며, `GET /api/agents/v1/models/{model}`은 하나의 에이전트를 반환합니다.

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions`는 OpenAI Chat Completions 형식을 따르므로, 기존 OpenAI 클라이언트는 base URL만 변경하면 그대로 동작합니다:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

같은 요청을 curl로 보내기:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses`는 [Open Responses](https://www.openresponses.org/) 사양을 구현하며, 이 사양은 에이전트 워크로드를 위해 설계되었습니다. 추론, 도구 호출, 스트리밍 이벤트가 형식에 덧붙여진 것이 아니라 형식 자체의 일부입니다. 이는 LibreChat이 앞으로 기반으로 삼는 인터페이스이므로, 새로운 연동에는 이 인터페이스를 사용하는 것을 권장합니다.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}`는 저장된 응답을 반환하며, `GET /api/agents/v1/responses/models`는 여기에서 사용할 수 있는 에이전트 목록을 나열합니다.

### 자체 함수 도구 [#your-own-function-tools]

Responses 요청에서 표준 `function` 도구를 전달할 수 있습니다. LibreChat은 이러한 도구를 모델에게 보여주지만 실행하지는 않습니다. 모델이 도구를 선택하면 응답에 `function_call` 항목이 포함되며, 이 함수는 사용자가 직접 실행해야 합니다. 이어서 진행하려면, `input`에 해당 `function_call` 항목을 그대로 포함하고 그 뒤에 동일한 `call_id`를 가진 `function_call_output`을 넣어 새 요청을 보내십시오.

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

두 요청 사이에는 아무것도 열린 상태로 유지되지 않으며, `previous_response_id`만으로는 충분하지 않습니다. 호출과 그 출력을 모두 다시 재생(replay)해야 합니다. 도구 이름에는 문자, 숫자, 밑줄, 하이픈을 사용할 수 있으며, 고유해야 하고, 에이전트 자체 도구 중 하나와 같은 이름이어서는 안 됩니다. 도구를 호출하는 턴에서는 에이전트의 도구를 동시에 호출할 수 없으며, 이 경우 모델에 재시도를 요청합니다.

### API를 통한 도구 승인 [#tool-approval-over-the-api]

관리자가 일부 도구에 승인을 요구하는 경우, API 호출은 누군가에게 확인을 요청하기 위해 멈출 수 없습니다. 승인이 필요하거나 거부된 도구는 대신 차단됩니다. 관리자는 무인 클라이언트가 실행하도록 의도된 도구를 명시적으로 허용해야 합니다.

## Agent Events [#agent-events]

Agent Events는 다른 시스템이 에이전트에게 작업을 넘긴 뒤, 나중에 돌아와서 무슨 일이 일어났는지 확인할 수 있게 해 줍니다. 이 기능은 베타 버전입니다. 이벤트는 사용자와 요청 출처를 식별하는 Agents API 키를 사용하며, OIDC만 설정된 환경에서는 사용할 수 없습니다. 또한 이벤트에는 별도의 요청 제한이 있으며, 이는 [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits)에서 설정합니다.

이벤트는 세 가지 모드 중 하나로 들어옵니다:

- `fire`는 에이전트와 새로운 대화를 시작합니다.
- `continue`는 앞서 바인딩한 하위 에이전트(child agent)에 턴을 추가합니다 (아래 참조).
- `steer`는 `fire`가 반환한 대화 및 생성 ID로 식별되는, 아직 진행 중인 실행에 지침을 추가합니다.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

모든 요청에는 하나의 `Idempotency-Key`가 필요합니다(문자, 숫자 또는 `._~:/+=-`로 이루어진 1~256자). 같은 전송을 재시도할 때는 이 키를 다시 사용하세요. 서로 다른 내용에 같은 키를 재사용하면 충돌이 발생합니다. LibreChat은 API 키를 기준으로 이벤트의 출처(source)를 설정하며, 요청에 포함된 출처 값은 무시합니다. 페이로드는 저장되므로 비밀 정보는 포함하지 마세요. 같은 대상에 관한 이벤트를 순서대로 처리해야 한다면 `orderingKey`를 사용하세요.

응답은 전송 ID와 함께 `202 Accepted`이며, 동일한 키로 폴링할 `Location`이 포함됩니다:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

### 이벤트 기반 하위 에이전트 [#event-driven-child-agents]

여러 이벤트에 걸쳐 하위 에이전트와 계속 대화를 이어가려면, 먼저 바인딩을 한 번 설정한 뒤 해당 바인딩으로 `continue` 이벤트를 보내면 됩니다.

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

The parent must be a normal agent conversation, and the target must be one of that agent's direct subagents (or the agent itself, if self-spawn is allowed). `actorId` is up to 128 characters. A new binding returns `201` and a replay returns `200`, both with the binding `id`. Later turns reference it:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

각 바인딩은 한 번에 하나의 이벤트만 처리하며, 현재 턴이 최종 처리 상태에 도달할 때까지 다음 이벤트는 대기합니다. 서로 다른 바인딩은 병렬로 실행됩니다. 바인딩된 자식은 Ask User 또는 도구 승인을 위해 일시 중지될 수 있으며, 이후 이벤트는 LibreChat에서 누군가 응답할 때까지 대기합니다. 이 기능에는 내구성 있는 MongoDB 체크포인터(기본값)가 필요합니다. 부모 대화에서 바인딩된 각 자식은 해당 바인딩을 소유한 메시지 아래에 한 행으로 표시되며, 하위 에이전트 활동 패널을 엽니다.

바인딩은 이를 생성한 API 키, 사용자 및 테넌트에서만 작동합니다. 하위 스레드는 채팅 목록에 표시되지 않으며 앱에서 읽기 전용입니다.

관찰 이벤트(예: "게임이 진행됨")에는 동일한 `coalesce.key`를 지정할 수 있으며, 이 경우 LibreChat은 750ms 이내이고 512KiB 이내인 최대 8개의 이벤트를 하나의 턴으로 묶습니다. 각 이벤트는 여전히 자체 영수증을 받습니다. 명령, 승인, 또는 `expectedAction`이 있는 항목은 묶지 않습니다.

## 에이전트 관리 API [#agent-management-api]

에이전트 관리 API를 사용하면 신뢰할 수 있는 서비스가 브라우저 세션 없이 에이전트와 스킬을 생성, 변경, 삭제할 수 있습니다. 이 API는 베타 버전이며 자체 인증 방식을 사용합니다. 관리자가 [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi)에 나열한 클라이언트의 머신 OIDC 토큰을 사용합니다. 각 클라이언트는 기존 LibreChat 사용자 한 명 및 테넌트 한 곳과 연결되며, 모든 요청은 해당 사용자의 권한과 접근 범위로 수행됩니다. 이 API로 누군가가 관리자가 되는 것은 아닙니다.

| 메서드 | 경로 | 용도 |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | 에이전트 생성 |
| `GET` | `/api/agents/v1/agents` | 접근 가능한 에이전트 목록 조회 |
| `GET` | `/api/agents/v1/agents/{id}` | 에이전트 조회 |
| `PATCH` | `/api/agents/v1/agents/{id}` | 에이전트 업데이트 |
| `DELETE` | `/api/agents/v1/agents/{id}` | 에이전트 삭제 |
| `POST` | `/api/agents/v1/agents/{id}/files` | 파일 업로드 및 첨부 |
| `GET` | `/api/agents/v1/agents/{id}/files` | 첨부된 파일 목록 조회 |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | 파일 첨부 해제 |
| `GET` | `/api/agents/v1/skills` | 접근 가능한 스킬 목록 조회 |
| `POST` | `/api/agents/v1/skills` | 스킬 생성 |
| `GET` | `/api/agents/v1/skills/{id}` | 스킬 조회 |
| `PATCH` | `/api/agents/v1/skills/{id}` | 스킬 업데이트 |
| `DELETE` | `/api/agents/v1/skills/{id}` | 스킬 삭제 |
| `GET` | `/api/agents/v1/skills/{id}/files` | 스킬의 파일 목록 조회 |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | 스킬 파일 조회 |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | 스킬 파일 생성 또는 교체 |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | 스킬 파일 삭제 |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agent payloads take the same fields as the Agent Builder and reject unknown ones; `model` is required on create. Lists take `limit` (1 to 100, default 20) and a `cursor`; when `has_more` is true, pass the returned `after` as the next cursor. File uploads are `multipart/form-data` with one `file` and a `tool_resource` such as `context`, `file_search`, or `execute_code`, subject to the usual upload limits.

Skill create는 `name`, `description`, `body`를 필수로 받고, 선택적으로 `displayTitle`, `frontmatter`, `category`, `alwaysApply`를 받습니다. 업데이트 요청에는 스킬의 현재 버전을 `expectedVersion`으로 함께 보내야 하며, 이를 통해 두 작성자가 서로의 변경 사항을 조용히 덮어쓰는 일을 방지합니다.

오류는 `invalid_request`, `not_found`, `permission_denied`, `conflict`, `internal_error` 코드를 사용합니다. 접근 권한이 없는 리소스는 `not_found`로 반환될 수 있습니다. 잘못되었거나 누락된 자격 증명은 `401`을 반환합니다.

관리자가 이 기능을 활성화하면, 관리 라우트에 대한 OpenAPI 설명이 `/api/openapi.json`에서 제공되며, 대화형 문서는 `/api/docs`에서 확인할 수 있습니다. 추론(inference)이나 이벤트는 포함되지 않습니다. [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi)를 참고하세요.

## 사용량 및 과금 [#usage-and-billing]

API 요청은 앱에서의 채팅과 정확히 같은 방식으로 토큰 잔액에서 차감됩니다. 응답의 사용량 합계에는 서브에이전트 호출이 포함되며, 이는 `primary` 및 `subagent`로 나뉘어 표시됩니다. 또한 제공업체가 보고하는 경우 캐시 토큰과 추론 토큰도 함께 포함됩니다. 자세한 내용은 [토큰 사용량](/docs/configuration/token_usage)을 참조하세요.

## 설정 [#setup]

Agents API는 관리자가 Remote Agents 권한을 해당 역할에 부여하기 전까지 일반 사용자에게 비활성화되어 있습니다. 권한 부여는 [관리자 패널](/docs/features/admin_panel)에서 하거나 [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents)를 사용하여 설정할 수 있습니다. 관리자는 기본적으로 이 권한을 가지고 있습니다. API 키 인증은 기본적으로 활성화되어 있습니다. 키 대신 또는 키와 함께 자체 OIDC 공급자의 토큰을 허용하려면 [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi)를 참조하십시오. Management API는 [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi)에서 별도로 구성하며, 이벤트 전달 설정은 [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven)에서 확인할 수 있습니다.
