---
title: サブエージェント
icon: Network
description: エージェントが集中したサブタスクを子エージェントに委任できるようにし、子エージェントは独自のコンテキストウィンドウ内で実行され、要約を報告します。
---

サブエージェントとは、エージェントが自身の作業の途中で開始する子の実行です。子は新しいクリーンなコンテキストウィンドウを与えられ、作業（検索、ファイルの読み取り、ツール呼び出しなど）を行い、その結果のみを返します。親のコンテキストは小さいまま保たれます。これは、中間作業によって親が見る必要のない大量のツール出力が生成される場合に重要です。

サブエージェントは、タスクが多くのノイズを生む複数の部分に分かれる場合に使いましょう。たとえば、複数のトピックを調査する場合、ファイル群をレビューする場合、メインの回答の前にツールを多用する確認作業を行う場合などです。

## エージェントで有効にする [#turn-it-on-for-an-agent]

<Steps>
  <Step>
    Agent Builderで、**Tools**の横にある**Add**をクリックし、Tool Libraryから**Subagents**を追加します。**Subagents**カードの歯車アイコンをクリックすると、その設定が開きます。
  </Step>
  <Step>
    **Subagents**スイッチ(Betaと表示)がオンになっていることを確認してください。**Allow self-spawn**はデフォルトでオンになっており、エージェントはサブタスクのために自分自身の新しいコピーを起動できます。
  </Step>
  <Step>
    オプションで、**Additional subagents** の下にある **Add subagent** をクリックすると、表示されている他のエージェントに処理を委任できるようになります。その後、保存してください。
  </Step>
</Steps>

セルフスポーンは、エージェントが既にその作業向けに設定されており、まっさらな状態から始めるだけでよい場合に十分です。サブタスクに別のモデル、別の指示、別のツールが必要な場合は、他のエージェントを追加してください。例えば、検索用の安価で高速なモデルや、厳格なチェックリストを持つレビューエージェントなどです。親エージェントは名前と説明をもとにこれらの中から選択するため、各エージェントには何のためのものかを説明する記述を付けてください。

子エージェントは、親エージェントが実際にそれを選択したときにのみ読み込まれます。そのため、複数の子エージェントを一覧に登録しても、いずれかが実行されるまでコストは発生しません。エージェントは、デフォルトで最大10個の子エージェントを一覧に登録できます。自己生成(self-spawn)をオフにしてエージェントを一つも登録しない場合は、生成できる対象がないため、ビルダーがその旨を通知します。

### サブエージェントとのファイル共有 [#sharing-files-with-subagents]

管理者によって有効化されている場合、**サブエージェントとファイルを共有**スイッチが表示されます。このスイッチをオンにすると、現在のメッセージに添付されたファイルが、親が起動するサブエージェントから利用できるようになります。サブエージェントがサンドボックス内で作成したファイルは、どのバージョンを返すかをサブエージェントが選択するまで、そのサブエージェント専用として非公開のままです。

## チャット画面に表示される内容 [#what-you-see-in-the-chat]

サブエージェントの各実行は、親の応答内に、子の名前とステータスを示すコンパクトな行として表示されます。実行中は**Running agent**、完了すると**Ran agent**と表示されます。この行を開くと、アクティビティサイドパネルで子の動作を追跡できます。無視して親の回答を読むことも可能です。キャンセルされた実行には**Agent stopped**、失敗した実行には**Agent failed**と表示されます。バックグラウンドで開始された子(下記参照)は、代わりに**Agent activity**ブロックにまとめて表示されます。

## 動作の仕組み [#how-it-behaves]

- 子エージェントは独自のコンテキストで起動します。親の会話履歴や、親がツール検索で見つけたツールを引き継ぐことはなく、親が書いたタスクを受け取ります。
- 子実行（child run）のトークン使用量は、あなたの残高に計上されます。親の実行がまだ動いている間に完了した子実行は親の合計に加算され、後から完了したデタッチされた子実行は、それぞれ独立して記録されます。
- アクセスできなくなった子エージェントはスキップされます。アクセスできないエージェントを追加することはできません。子エージェントを開始する際に、アクセス権と保存済みの設定が再度確認されます。実行中にいずれかが変更されていた場合、その子エージェントは実行されません。
- 各子エージェントは、それぞれ独自のモデル、指示、ツール、MCP認証情報、スキル、ファイル、メモリを保持します。
- ステップ上限はサブエージェントにも適用されるため、**Max Agent Steps** の値を低く設定すると、子エージェントが実行できる処理量も制限されます。
- サブエージェントは、さらに独自のサブエージェントを起動でき、最大5階層まで深くすることができます。

## 保存済みエージェントチーム [#saved-agent-teams]

親エージェントは、保存済みの「チーム」を開始することもできます。チームとは、複数のエージェントを連携させて一つの小さなワークフローとしたものを指します。たとえば、調査結果をレビュー担当に渡す調査担当のような構成です。チームは一つの独立した子プロセスとして実行され、結果エージェントの回答のみが親に返されます。チームには最大32人のメンバーを含めることができます。いずれかのメンバーが存在しない場合、またはそのメンバーを参照できない場合は、チームの一部だけを実行するのではなく、チーム全体をスキップします。

チームはAgent Builderではなく、APIを通じて定義されます。ビルダーは、エージェントのその他のサブエージェント設定を編集しても、チームをそのまま維持します。定義形式については、[agentsエンドポイント設定](/docs/configuration/librechat_yaml/object_structure/agents#subagents)を参照してください。

## Detached Subagent Threads [#detached-subagent-threads]

管理者がバックグラウンド実行を有効にしている場合、親は subagent を開始した後、その完了を待たずに作業を続けられます。子の作業内容は閲覧専用のスレッドとして保存され、親のアクティビティパネルから開くことができます。このスレッドはチャット一覧や検索には表示されません。非常に長い履歴は切り詰められ、それより前のアクティビティが表示されていない場合はパネルにその旨が表示されます。

### 実行中の子プロセスを制御する [#control-a-running-child]

実行中の切り離された子タスクがあるとき、アクティビティパネルの入力欄に入力して、そのタスクを誘導できます。

- **Steer** は、子タスクの次の安全なポイントであなたの指示を追加します。これがデフォルトです。
- **Queue** を押すと、子の次のターンまで保持されます。
- **Interrupt** は現在のステップを停止し、ガイダンスを適用します。
- 入力欄が空のとき、送信ボタンは**Cancel task**に変わります。

各メッセージには、そのガイダンスが適用されたかどうかが表示されます。キューに入ったガイダンスは、子エージェントがそれを取り込む前であれば **Withdraw** で取り消すことができます。ガイダンスは 4 KB までに制限されています。直下の子エージェントの処理が完了すると、**Continue in a new chat** でその会話が通常のチャットにコピーされ、そのまま作業を続けられます。元のスレッドは読み取り専用のままになります。

共有された会話には、共有に含まれるアクティビティのみが表示され、操作用のコントロールは表示されません。

### 親の自動継続 [#automatic-parent-continuation]

切り離された子エージェントが完了すると、LibreChatはデフォルトで、結果を折りたたみ可能なタスクカードとして表示しながら、同じブランチ上の親エージェントを再び起動します。親エージェントがまだ処理中の場合、再起動は親の処理が終わるまで待機します。キャンセルされた子エージェントは親を再起動しません。また、この機能は保存済みエージェントに対してのみ動作し、モデルスペックから作成されたエージェントでは動作しません。管理者はこの機能を無効にすることができます。その場合、親エージェントは子エージェントの状態を自分で確認する必要があります。

外部システムが[Agents API](/docs/features/agents_api#event-driven-child-agents)を通じて動作させる子エージェントも、同じように親メッセージの下に行として表示され、同じパネルを開きます。

## Subagents と handoffs の比較 [#subagents-compared-with-handoffs]

サブエージェントは制御を親に返します。親が問い合わせ、子が回答し、親が返信を書きます。[ハンドオフ](/docs/features/agents#working-with-other-agents)は会話を別のエージェントに引き渡し、そのエージェントが自ら返信します。サブタスクには サブエージェント を、専門家へルーティングする場合は ハンドオフ を使用してください。

## セットアップ [#setup]

サブエージェントはデフォルトで利用可能です。管理者は、`subagents` 機能を使ってサブエージェントを無効にしたり、`maxSubagents` でエージェントごとの上限を引き上げたり、ファイル共有を有効にしたり、オプトインの `run_in_background` 機能によって切り離された子エージェントを許可したりできます。これらはすべて[エージェントエンドポイントの設定](/docs/configuration/librechat_yaml/object_structure/agents#subagents)で行います。親エージェントの自動継続は [`backgroundTasks`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) で制御します。また、保存済みの親エージェントがない場合でも、モデルスペックでサブエージェントを有効にできます。詳しくは [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs#subagents) を参照してください。
