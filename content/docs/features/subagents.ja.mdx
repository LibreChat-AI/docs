Subagentsを使用すると、LibreChat Agentは特定のタスクに集中させるための分離された子実行を生成できます。子エージェントは独自のコンテキストウィンドウとツール実行フローを持ちます。親エージェントは、すべての中間的なツール呼び出し、トレース、または冗長なファイル操作を自身のコンテキストに取り込むことなく、子エージェントの結果のみを受け取ります。

以下にサブエージェントを使用します：

- 長い中間出力を生成する可能性のあるリサーチサブタスク
- 専門エージェントによるレビューの合格
- 親コンテキストの外に留めるべき、ツールを多用する作業
- 1つの委任されたタスクの背後で実行されるべきマルチエージェントチームのワークフロー
- 親が調整と要約を行う並列スタイルの分解

## Subagents と Handoffs の違い [#how-subagents-differ-from-handoffs]

ハンドオフは、会話の主導権をプライマリエージェントから専門エージェントへ移し、その専門エージェントが以降のやり取りを引き継ぎます。サブエージェントは、実行中にエージェントがツール呼び出しとして起動するもので、独立した環境で作業を行い、その結果をコンパクトにまとめて親に返します。

- **ハンドオフ**: 会話が別のエージェントに引き継がれます
- **Subagents**: 親エージェントから分離された子実行への実行時委譲です。親エージェントが制御を保持し続けます。

両方とも既存のエージェントを利用できますが、サブエージェントは単一エージェントの推論ループ内からスコープを限定した委譲を行うために設計されています。従来のエージェントチェーン(Agent Chains)は非推奨となっています。新しいオーケストレーションには、ハンドオフ(Handoffs)またはサブエージェント(Subagents)を使用してください。詳しくは[エージェント](/docs/features/agents#handoffs)をご覧ください。

## 機能の有効化 [#enable-the-capability]

`subagents` 機能はデフォルトで有効になっています。管理者は、agents エンドポイントの機能リストからこれを削除することで、この機能を無効にできます。デフォルトの機能リストは次のとおりです:

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'ocr'
```

If you set `capabilities` yourself, list every capability you want to keep, because your list replaces the default. Background execution (`run_in_background`) is not in the default list; see [Detached Subagent Threads](#detached-subagent-threads).

## エージェントの設定 [#configure-an-agent]

Agent Builderで**Add tools**を開き、ツールライブラリから**Subagents**を選択して、有効化スイッチ(**Enable subagents**)をオンにします。

利用可能な設定:

- **Enable subagents**: エージェントにサブエージェント生成ツールを追加します。
- **Allow self-spawn**: エージェントが分離されたコンテキスト内で自身の新しいコピーを生成できるようにします。これは、サブエージェントが有効な場合にデフォルトで有効になります。
- **ファイルをサブエージェントと共有**: メッセージのファイルを、許可されたフォアグラウンドのサブエージェントと共有します。このオプションは `endpoints.agents.fileSharing.enabled` が true の場合にのみ表示されます。
- **Additional subagents**: 親エージェントが生成できる特定のサブエージェントを選択します。

保存されたエージェントチームは、エージェントの作成または更新のペイロード内に `subagents.graphs` として埋め込まれます。現在の Agent Builder は、自己生成（self-spawn）設定や個別のエージェント設定を編集する間もこれらの定義を保持しますが、グラフ定義自体の作成は行いません。各チームは、有向非巡回グラフ（DAG）の境界、そのエントリとなるエージェント、および親に結果が返されるエージェントを指定します。

```yaml filename="agent saved-team subagent"
subagents:
  enabled: true
  allowSelf: false
  graphs:
    - type: 'research_team'
      name: 'Research team'
      description: 'Researches a topic and reviews the findings'
      agent_ids:
        - 'agent_researcher'
        - 'agent_reviewer'
      entry_agent_id: 'agent_researcher'
      result_agent_id: 'agent_reviewer'
      edges:
        - from: 'agent_researcher'
          to: 'agent_reviewer'
          edgeType: 'direct'
```

同等のエージェント形状:

```yaml filename="agent subagents"
subagents:
  enabled: true
  allowSelf: true
  agent_ids:
    - 'agent_researcher'
    - 'agent_reviewer'
```

## Model Spec の設定 [#configure-a-model-spec]

管理者は、Model Specsから作成された一時的なエージェントに対してSubagentsを有効にすることもできます。これは、ユーザーが永続的な親エージェントを作成または選択することなく、Model Specを特定の目的に特化したエージェントプロファイルのように動作させたい場合に便利です。

```yaml filename="modelSpecs / subagents"
modelSpecs:
  list:
    - name: 'research-assistant'
      label: 'Research Assistant'
      subagents:
        enabled: true
        allowSelf: true
        agent_ids: []
      preset:
        endpoint: 'agents'
        model: 'gpt-4o'
```

起動時の設定において、クライアントに送信されるのは `enabled` と `allowSelf` のみです。`agent_ids` の許可リストはサーバー側に保持され、有効なサブエージェント制限に対して検証されます。この制限はデフォルトで10に設定されており、[`endpoints.agents.maxSubagents`](/docs/configuration/librechat_yaml/object_structure/agents#maxsubagents) で構成可能です。クライアントのリクエストペイロードによって、Model Specs のサブエージェント設定を提供したり、上書きしたりすることはできません。

## ランタイムの動作 [#runtime-behavior]

サブエージェントが有効な場合、親エージェントは `subagent` ツールを受け取ります。このツールは以下を生成できます：

- `self`（`allowSelf` が false でない場合）
- `agent_ids` で設定されたすべての子エージェント
- `graphs` 内の保存された完全な Agent チーム

子エージェントは分離されたコンテキストで実行されます。親のツール検索状態および蓄積されたコンテキストは、子エージェントの実行にはコピーされません。フォアグラウンドの子モデルの使用量は親のトランザクションおよび使用量合計に含まれますが、親リクエスト終了後に完了するデタッチされた子呼び出しは、個別に記録されます。コンパクトな子カードは、フォアグラウンド、グラフ、レガシー、およびデタッチされた実行のための統合アクティビティサイドパネルを開き、そのトランスポートに適した境界付きライフサイクル、推論、ツール、承認、および結果の詳細を表示します。名前付きエージェントの設定された名前とアバターは、ストリーミング完了後およびリロード後もカードとパネル上に保持されます。保存された識別情報を持たない古いレコードは、汎用のフォールバックを使用します。

明示的な子エージェントは、軽量な記述子として親にアドバタイズされ、選択された場合にのみ完全に初期化されます。使用されていない子エージェントは、モデル、ツール、MCPサーバー、ファイル、またはスキルを読み込みません。呼び出し時に、LibreChatは閲覧権限と子エージェントのバージョン管理された構成IDを再確認します。アクセス権が取り消されていた場合、または実行中に保存された構成が変更された場合、子エージェントは古い設定で実行されるのではなく、安全に失敗（fail closed）します。

並列ブランチが同じ子Agentを参照する場合、LibreChatは各トラバーサルパスに対して独立してサイクル制限と深さ制限を評価します。したがって、一方のブランチでサイクルが発生しても、もう一方のブランチ上の有効なネストされたAgentリンクが破棄されることはありません。

保存されたチームは、個々の子エージェントと同じ遅延解決およびアクセスチェックに従います。選択されると、各メンバーは独自のモデル、指示、ツール、MCP認証情報、スキル、ファイル、メモリ、Code Interpreterプロファイル、および課金IDを保持します。LibreChatはチームを1つの分離された子グラフとして実行し、メンバーを認識した進捗状況をストリーミングし、設定された結果エージェントの出力を返します。永続化されたメンバーが欠落している、アクセスできない、または無効である場合、LibreChatは部分的なグラフを実行するのではなく、チーム全体をスキップします。

その後のターンにおいて、LibreChatは到達可能な子ツールおよびチームツールからの以前の呼び出しを、必要に応じて解決済みのMCPサーバーIDを含む構造化されたツール呼び出し形式で保持します。到達できなくなったツールは、履歴に表示されているという理由だけでアクティブな実行に追加されることはありません。

## Detached Subagent Threads [#detached-subagent-threads]

`run_in_background` はオプトインです。`endpoints.agents.capabilities` に追加すると、Agents エンドポイントで有効になります。有効にすると、親の Agent はサブエージェントの処理を切り離し、その完了を待たずに処理を続けることができます。LibreChat は切り離された各子スレッドを、非公開の実行系統情報と正規化されたトランスクリプトとともに保存します。子スレッドは通常の会話のナビゲーションや検索には表示されず、直接読み取ることもできません。認可された親のビューには、制限された範囲の子の活動のみが表示されます。

子スレッドは閲覧専用の実行記録です。ユーザーは、正規の子スレッドをその場で編集または削除することはできません。完了した永続的なダイレクトAgentの子スレッドに対して「**新しいチャットで続行**」を実行すると、完了したブランチがそのまま別の通常の書き込み可能なAgent会話へとフォークされ、元の子供は非表示かつ読み取り専用の状態で残ります。アクティビティパネルは、実行中およびタスクの配信中を通じて1つのコンポーザーをマウントし続け、新しいタスクビューの読み込み中もフォーカスと入力途中のガイダンスを保持します。タスクが制御を受け入れられるようになるまで、送信は利用できません。確定後に入力されたテキストはフォークに引き継がれ、フォークに失敗した場合はパネル内のドラフトが復元されます。このアクションは、実行中、グラフ、匿名Agent、および共有ビューでは利用できません。親を削除すると、その子系統にも削除が連鎖します。親Agentは、タスクツールを通じて正規の子スレッドをポーリング、操作、キューイング、中断、キャンセル、収集、および後続の継続を行うことができます。Mongoでバックアップされたリースは、APIレプリカ間でそれらの継続をシリアライズします。

アクティビティパネルには、選択された子要素のターンがブランチを認識した履歴として表示されます。「**Load earlier activity**」を使用して履歴を遡り、ターン上の「**Show full activity**」を使用して、そのターンの完全な境界付き実行詳細を表示します。ツール呼び出し、承認、結果、コントロール、およびユーザーが確認可能な推論が表示される場合があります。推論テキストは他のプロジェクションと同様に境界が設定され、切り詰められた場合にはその旨が示されます。古いサーバーによって永続化されたアクティビティでは、推論マーカーのみが表示されることがあります。通常の永続化アクティビティは、プライベートな子要素のアクティビティと同じアイテムごとの制限を使用し、連続する最新のサフィックスを64 KBのシリアル化されたアクティビティ予算内に収めるため、意味のあるコンテンツが省略された場合にのみ短縮通知が表示されます。履歴が切り詰められているか利用できない場合、パネルは不完全なビューを完全なものとして提示する代わりに、その旨を表示します。新しいイベントターンは履歴の最下部に配置され、実行中のターンは経過時間を表示し、アクター行は固定位置のステータスドットを使用するため、ステータスの変更によってレイアウトがずれることはありません。コンパクトなフローティングヘッダーにより、その下で履歴をスクロールでき、コンポーザーはメインチャットの寸法に従います。実行中の作業は、個別の実行ステータスチップではなく、ストリーミングアクティビティによって伝達され、異常な終了状態にはラベルが付けられたままになります。

Redisを有効にすると、LibreChatはアクティブな実行オーナーを記録し、ポーリング、リスト、ステア、キュー、割り込み、キャンセル、収集の各リクエストを、境界付きの期限切れリクエスト/リプライメッセージを通じて、任意のAPIレプリカからそのプロセスへとルーティングします。開いているアクティビティパネルもタスクスコープのライブ更新を受け取ります。イベントの取りこぼし、再接続、またはRedisの停止時には、2秒間の永続クエリがフォールバックとして機能します。単一プロセスおよび非Redis環境のデプロイメントでは、インメモリの高速パスが使用されます。ライブエグゼキュータは、そのオーナープロセスが再起動または消失した後に移行されることはありませんが、MongoDBでバックアップされた子トランスクリプト、ターミナル状態、使用状況、履歴、およびその後のエージェント主導の継続は独立して存続します。これは、デタッチされたタスクをパブリックなバックグラウンドジョブAPIに変えるものではありません。

### 実行中の子プロセスを制御する [#control-a-running-child]

認証済みの親会話で、Subagentアクティビティパネルを開き、永続的な子タスクを選択します。そのタスクの実行中にガイダンスを入力して送信すると、デフォルトでステアリング（誘導）が行われます。ホバー操作が可能なデスクトップ環境では、送信コントロールのアクションメニューに**Steer**（誘導）、**Queue**（キュー）、**Interrupt**（中断）が表示され、現在のユーザーのキーボード設定で有効なショートカットのみが表示されます。タッチデバイスやモーダルパネルでは、キューと中断はアイコンコントロールとして引き続き利用可能です。ガイダンスが入力されていない場合、送信コントロールは**Cancel task**（タスクのキャンセル）になります。

- **Steer**は、子プロセスの次の安全な境界でガイダンスを追加します。
- **Queue** は、子タスクの後のターンに向けたガイダンスを保持します。
- **Interrupt** は、子プロセスの現在の作業を安全な境界で停止し、新しいガイダンスを適用します。
- **Cancel task** は、ガイダンスを送信せずにキャンセルをリクエストします。

承認されたコントロールは、タスク固有の履歴に「送信中」、「待機中」、「適用済み」、「未適用」、または「失敗」として表示され、利用可能な場合はその理由も示されます。子プロセスが適用する前にキューに入れられたガイダンスを削除するには、**Withdraw**（取り消し）を選択してください。ガイダンスは4 KBに制限されています。各タスクは最大64件の権限付きレシートを保存し、アクティビティパネルには最大32件が表示されます。古い完了済み履歴はアクティブな承認済みコントロールよりも前に省略され、UIは省略された履歴や表示用に短縮されたガイダンスにラベルを付けます。

実行中のコントロールは、子（child）が落ち着くと終了し、同じコンポーザーが新しいチャットで適格な子を継続するように切り替わります。LibreChatは、すべてのリクエストにおいて、サインインしているユーザーの親（parent）および子へのアクセス権、それらの親子関係、およびテナントの所有権を検証し、設定されたコンテンツフィルターとモデレーションチェックをガイダンスに適用します。同じ承認済みコントロールを繰り返し送信した場合、指示を2回適用する代わりに、その権威ある領収書が返されます。共有された会話は読み取り専用のままであり、これらのコントロールを公開することはありません。

共有された会話には、共有ペイロードに含まれている範囲内のアクティビティのみが表示されます。これらは読み取り専用のビューであり、承認コントロールや永続的な子セレクターは省略され、認証が必要な子スレッドのクエリパスが開かれることはありません。

### イベント駆動型の子アクティビティ [#event-driven-child-activity]

[Agents API event binding](/docs/features/agents_api#event-driven-child-agents) を通じて継続されるChild Agentsは、`subagent` ツールカードから発生するものではありません。認証済みの親会話において、LibreChatは代わりに、バインディングを所有するメッセージの下に1つのコンパクトなアクター行を追加します。これを開くと、Subagentアクティビティパネルが再利用され、アクターとそのターン、さらにライブの実行ステップ、ツール、メッセージ、および推論マーカーのアクティビティを選択できるようになります。外部イベントトリガーは、展開可能なイベントタイプ、ソース、発生時刻、および期待されるアクションの詳細を含む、通常のユーザートリガー行としてレンダリングされます。新しい配信が同じ子スレッド内の別のタスクを選択した場合、既存のターンは表示されたまま新しいタスクが読み込まれ、そのストリーミングプレースホルダーのみが追加されます。タスク固有のステータスやコントロールが、保持されているビューから流用されることはありません。以前のページやターンごとの完全なアクティビティは、同じ制限付きの読み取り専用の子履歴を使用します。

親プロジェクションは意図的に制限されています。最大64個の子スレッドを返し、共有された制限付きソースウィンドウから子ごとに最大20個の最近のタスクを保持し、応答を96 KBに制限します。UIは、制限を超えたビューが完全であると誤認させるのではなく、履歴が切り捨てられたことを報告します。別のターンを開始すると、古いアクターが最近の子ウィンドウに昇格します。これらの子スレッドは通常のナビゲーションからは非表示のままであり、他の親やテナントから発見することはできません。

### 自動親継続 (Automatic Parent Continuation) [#automatic-parent-continuation]

デタッチされた子プロセスが終了すると、LibreChatはそのターミナル結果またはエラーを永続化し、デフォルトでは、それを起動した正確なブランチ上の保存済み親Agentに対して冪等な継続（continuation）を送信します。配信は、その親ブランチが実行中、一時停止中、または終了処理中の間待機します。再開された親は、兄弟タスクをビジーポーリングする代わりに、関連するタスクの限定的なマニフェストを受け取り、チャット画面では折りたたみ可能なタスクカードとしてウェイクアップが表示されます。

[`endpoints.agents.backgroundTasks.completionWakeups`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) が省略されているか `true` に設定されている場合、自動完了配信が有効になります。これを `false` に設定すると、デタッチされた子プロセスはポーリングのみの状態になります。キャンセルされた子プロセスは無視され、一時的な親Agentはサポートされません（復元するための保存された設定が存在しないため）。デタッチされた子プロセスの実行は独自の実行コンテキストを所有するため、元の親リクエストを終了または中断しても、独立して所有されている作業はキャンセルされません。親は引き続き、タスクツールを通じて永続的な子の結果を収集できます。

  ]}
/>

エージェントごとのサブエージェント数のみ設定可能です。`librechat.yaml` の `endpoints.agents.maxSubagents` を設定することで、デフォルトの10から最大50までの上限に引き上げることができます：

```yaml filename="librechat.yaml"
endpoints:
  agents:
    maxSubagents: 20
```

設定された値は、`subagents.agent_ids` および `subagents.graphs` の両方に対するエージェントの作成、更新、複製リクエスト、モデルスペックの `subagents.agent_ids` 許可リスト、およびエージェントビルダー内のサブエージェントピッカーに適用されます。詳細なリファレンスについては、[maxSubagents](/docs/configuration/librechat_yaml/object_structure/agents#maxsubagents) を参照してください。上記のチームメンバーごと、深さ、グラフノード、および実行設定の制限は固定されています。

## アクセス制御 [#access-control]

構成された子エージェントおよび保存されたすべてのチームメンバーは、ユーザーから参照可能である必要があります。ユーザーが参照されている個別のエージェントに対する閲覧権限を持っていない場合、LibreChatはそのサブエージェントをスキップします。保存されたチームは「すべてか無か」の形式であり、メンバーのいずれかが利用できない場合はスキップされます。作成および更新リクエストでは、欠落している参照や権限のない参照、重複するスポーンタイプ、循環または切断されたチームグラフ、無効なエントリまたは結果メンバー、および上記の制限を超える構成は拒否されます。

## デザインのヒント [#design-tips]

- 親エージェントのスコープが十分に定義されており、サブタスクのために新しいコンテキストが必要な場合に、self-spawnを有効にします。
- タスクに異なるモデル、指示セット、ツールセット、またはスキル許可リストが必要な場合は、特定のチャイルドエージェントを追加してください。
- 複数のエージェントを単一の委任ワークフローとして実行し、親に対して単一の結果を返す必要がある場合は、保存済みのチームを使用してください。
- 子要素の説明を明確に保ってください。親要素は各子要素の名前と説明を使用して、適切な委任先を選択します。
- 中間作業にはサブエージェントを使用し、コンパクトな結果を返すようにしてください。別の会話パスへの恒久的な引き継ぎには使用しないでください。
