A prompt group is a saved prompt with one or more revisions. Open **Prompts** from the side panel to browse your prompt library, or type `/` in the chat box to pick one without leaving the conversation.

## Overview

Each card in the library shows the prompt's name, category, and a one-line snippet from its description or its Production revision. Click a card to open it in chat (it resolves its content, fills in any variables, and sends it when **Send prompts on select** is on, the default) or to edit it, depending on where you are.

In the chat box, type `/` to open the same list. Each prompt can also have a short command alias; the menu searches both the name and the alias.

## Create and edit prompts

Open a prompt from the library to edit it. Saving a change adds a new revision; earlier revisions stay in the version list. One revision per group is marked **Production**.

With **Advanced prompts editor** off, the version list stays hidden and every save becomes the new **Production** revision. Turning the editor off also turns on **Always make new prompt versions production**. This is a normal per-browser setting, not a locked one. Turn on **Advanced prompts editor** to show the version list and the **Deploy** button. With the editor on, **Always make new prompt versions production** becomes a regular switch you can turn off, so you can promote a specific revision manually with **Deploy** instead. Cards and the slash command resolve to whichever revision currently holds the **Production** mark. An agent linked to **Production** picks up a new revision on a later turn, usually the next one, subject to the [native cache](#when-instructions-are-resolved).

Write `{{variable_name}}` placeholders in the prompt text, or `{{name:option1|option2}}` for a dropdown of choices. Using the prompt from the library or the `/` menu opens a dialog that asks for each variable's value before sending. The special placeholders `{{current_date}}`, `{{current_datetime}}`, `{{iso_datetime}}`, and `{{current_user}}` are filled in automatically. Everything else is left as literal text if nothing fills it in.

## Sharing and permissions

A prompt group's owner can share it with specific users, groups, or roles, each as Viewer, Editor, or Owner, the same pattern as agents and other shared resources. See [Access Control](/docs/features/access_control) for how that sharing works and how an admin can delegate parts of it.

Two things gate a prompt group beyond its own share list:

- Your role's `PROMPTS` permission must include `USE` to use any prompt at all. Sharing one also needs `SHARE` (specific users, groups, or roles) or `SHARE_PUBLIC` (everyone). Admins set these per role in the [Admin Panel](/docs/features/admin_panel) or under [feature permissions](/docs/configuration/access_control#feature-permissions).
- The `manage:prompts` capability lets a delegated admin view and link any prompt group as agent instructions, without an individual VIEW grant. Linking still needs the role's `PROMPTS` `USE` permission. Turning on Langfuse prompt-catalog sync needs admin access plus Langfuse configuration management; starting a sync additionally needs `manage:prompts`. See [Langfuse configuration](/docs/configuration/langfuse#prompt-catalog) and [Admin capabilities](/docs/configuration/access_control#admin-capabilities).

## Prompts from Langfuse

When your admin turns on Langfuse prompt-catalog sync, LibreChat imports Langfuse's **text** prompts into the library as read-only groups, each carrying a **Managed in Langfuse** badge. You can open, preview, and use one like any other prompt, but you cannot edit its content, promote a revision, or delete it; do that in Langfuse. Chat-type Langfuse prompts are not imported. Sync is append-only: deleting a prompt in Langfuse does not remove its synced group from LibreChat, and a link to that group then fails.

A synced group resolves the same way an agent instructions link does: by the `production` label in Langfuse, or by a pinned version number. Opening the prompt resolves it live from Langfuse at that moment; nothing is cached.

## Use a prompt as agent instructions

An agent's instructions can be a saved prompt instead of inline text: either a native prompt group or a synced Langfuse group.

### In the Agent Builder

In the agent's instructions field, switch **Inline** to **Prompt**. Pick a prompt under **Select a prompt**, then pick a **Version**:

- **Production** follows whatever the group's owner currently marks production: the Production revision for a native group, or the `production` label in Langfuse.
- A pinned version (a specific revision or Langfuse version number) stays fixed even after a new revision is promoted or labeled.

### Who can link and who can run

Saving a new or changed link needs your role's `PROMPTS` `USE` permission, plus VIEW on the prompt group you are linking to. It also needs the access the agent itself always requires to be saved: `AGENTS` `CREATE` for a new agent, or EDIT access for an existing one. Keeping an unchanged link, removing a link, or switching back to inline instructions needs only that same agent-level access. It never re-checks the linked group.

Someone who can only chat with the agent needs no access to the linked prompt; the server resolves it on their behalf. A co-editor who can edit the agent but cannot view the linked group sees **Restricted prompt** in the instructions field instead of the group's name, and can replace it or switch to inline instructions, but not see what it currently points to. A viewer of the agent never sees the link.

### When instructions are resolved

A linked prompt is resolved on every turn: for the main agent, for a handoff or subagent, for the memory agent, for an added conversation (multi-convo), and through the OpenAI-compatible and Responses APIs. The prompt text is not copied into the agent on save; the save only checks that the prompt resolves. `{{current_date}}` and the other special placeholders are filled in the same way as in inline instructions. A linked prompt's own `{{variable_name}}` placeholders are not filled in; they reach the model as literal text.

A native link's resolved content is cached for `native.cacheTtlMs` (5 minutes by default). Saving a new Production revision, or deleting a revision or the whole group, triggers a cache clear. That clear waits up to `native.cacheClearTimeoutMs` to finish. On timeout it continues in the background, so stale content can keep serving until the cache's normal TTL ends. Without Redis, each server instance keeps its own cache. A Langfuse link is never cached: it is fetched from Langfuse on every turn, so a newly promoted `production` label shows up on the next turn. Each turn's link resolution, including a Langfuse fetch, is limited by `timeoutMs` (2000 ms by default), so a slow Langfuse response leaves the agent with empty instructions once that time passes.

### If the prompt can't be resolved

If the linked prompt cannot be resolved in time, the agent runs that turn with **empty** instructions, not the inline text it would otherwise have used. The memory agent is the exception: when its link can't be resolved, memory falls back to its default instructions instead of running with none. The server logs a warning naming the agent and group.

Causes include: the group or revision was deleted; the content is blocked by policy; the request timed out; Langfuse linking is turned off; the tenant's Langfuse prompt-catalog sync is turned off; the Langfuse connection was removed or changed to a different project; Langfuse returned an error; the prompt or version no longer exists in Langfuse; or the linked group became a chat prompt.

### Usage count

Each agent that links a prompt group adds one use to that group's usage count when it finishes initializing, the same counter cards and the slash command add to; a handoff or subagent that links the same group can add more than one use in a single turn. A use is recorded only if the agent's initialization succeeds. Resuming a paused run re-initializes the agent but does not add another use. The memory agent never adds a use.

### Langfuse links

Linking a Langfuse group requires `endpoints.agents.linkedInstructions.langfuse.enabled` (off by default) and a group already synced from the Prompt Catalog. See [Langfuse configuration](/docs/configuration/langfuse#prompts-as-agent-instructions). A saved link keeps working only while the tenant's Langfuse prompt-catalog sync stays enabled.

<Callout type="warning" title="Rollout">
  Enable the switch only after every LibreChat server instance runs LibreChat `v0.8.9-rc1` or
  later. During a mixed rollout or a rollback:

  - A server without Langfuse links rejects the save with `400`.
  - A server without prompt links at all (`v0.8.8` and earlier) saves the agent and drops the link.
  - The Builder's version list fails with `404` for any linked prompt, native or Langfuse, on a
    server without the revisions route.
  - At run time, a server without Langfuse links runs the agent's stored inline instructions.
</Callout>

Turning the switch off:

- Rejects any new or changed Langfuse link.
- Hides Langfuse groups from the Agent Builder's prompt picker, except the one already saved on the agent you are editing.
- Shows a note on a saved Langfuse link that the agent runs without it until the switch is back on.
- Does not fall back to inline instructions; the agent runs without linked instructions that turn.

Turning the switch back on resolves saved Langfuse links again once the server loads the config change, with no agent edit required.

### Version history, duplicate and revert

Changing the link (picking a different prompt or version, or switching to or from inline instructions) creates a new entry in the agent's version history, like any other change. **Duplicate** and **Revert** both copy a stored link exactly as it was saved, with no USE or VIEW check. If the copy lands somewhere its new editor cannot view, it shows as **Restricted prompt** there instead of being blocked.

### Limitations

The Management API and its OpenAPI spec do not accept or return `instructionsPrompt`; a linked prompt can only be set from the Agent Builder. Editing `instructions` through the Management API has no effect on the run while a prompt link is set: initialization uses the resolved link content instead of the inline text. A Langfuse link only ever points at a text prompt: a chat-type Langfuse prompt cannot be selected or synced for this. Native prompt groups have no such restriction.

### Troubleshooting

| Message in the Builder | Cause | Fix |
| --- | --- | --- |
| "This prompt selection isn't available right now." | Saving the link failed because the prompt can't currently be resolved: the revision was deleted, the content is blocked, the Langfuse request failed, Langfuse prompt linking is turned off, or the group's source changed. | Pick a different prompt or version, or try again once the prompt is resolvable. |
| "You don't have permission to link this prompt." | Your role lacks `PROMPTS` `USE`, or you lack VIEW on the group you tried to link. | Ask an admin for the permission, or ask the group's owner for VIEW access. |
| "You don't have access to the prompt library." | Opening the prompt picker or its revision list failed because your role lacks `PROMPTS` `USE`, or you lack VIEW on the group. | Ask an admin for the permission, or ask the group's owner for VIEW access. |
| "This prompt's source isn't available right now." | Loading the version list for a selected Langfuse group failed: sync is disabled, not configured, the group's source changed, or the prompt became a chat prompt. | Check Langfuse prompt-sync configuration, or replace the link. |
| "Couldn't load prompts." | Loading the prompt list or a version list failed for an unexpected reason, not a permission or source problem. | Try again. Check server logs if it keeps happening. |
| "Selected version (no longer available)" | The pinned native revision was deleted. | Pick **Production** or another listed version. |
| "Version N (no longer available)" | The linked Langfuse version no longer appears in the group's revision list. | Pick **Production** or another listed version. |
| "Restricted prompt" | You can edit this agent but cannot view the linked group, or the linked group was deleted; this shows even to the agent's owner. | Ask for VIEW access to see it, or replace it, or switch to inline instructions. |
| "Prompt not found" | You hold `manage:prompts` or the `ADMIN` role, so you are never shown **Restricted prompt**; the linked group was deleted. | Pick a different prompt, or switch to inline instructions. |
| "Couldn't validate the linked prompt. Please try again." | An unexpected error happened while validating the link during save. | Try saving again. |

## Configuration reference

- [`endpoints.agents.linkedInstructions`](/docs/configuration/librechat_yaml/object_structure/agents#linkedinstructions): timeout, native cache, and the Langfuse linking switch.
- [Feature permissions](/docs/configuration/access_control#feature-permissions): role-level `USE`/`CREATE`/`SHARE`/`SHARE_PUBLIC` permissions for prompts. [`interface.prompts`](/docs/configuration/librechat_yaml/object_structure/interface#prompts) only seeds the default role's permissions in `librechat.yaml`.
- [Langfuse Prompt Catalog](/docs/configuration/langfuse#prompt-catalog): syncing Langfuse text prompts into the library.
