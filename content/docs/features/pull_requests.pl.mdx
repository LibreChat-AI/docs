Gdy agent pracuje nad repozytorium w dołączonym obszarze roboczym kodu, LibreChat znajduje pull request dla gałęzi, na której znajduje się obszar roboczy, i wyświetla go obok czatu. Możesz sprawdzić, czy jest gotowy do scalenia, czy przechodzą kontrole, oraz przejść do niego bez opuszczania rozmowy. Funkcja obsługuje GitHub, GitLab (gdzie nazywa się to merge request) oraz Bitbucket Cloud, przy czym w każdym wdrożeniu używany jest jeden dostawca.

Tylko czaty, które uruchamiają kod w dołączonym obszarze roboczym, mogą mieć pull request. Zwykły czat lub obszar roboczy, który jeszcze nie zgłosił gałęzi, nie wyświetla niczego.

## W nagłówku czatu [#in-the-chat-header]

Na szerokim ekranie po lewej stronie nagłówka znajduje się etykieta (chip), która pokazuje ikonę żądania ściągnięcia (pull request), małą kropkę statusu CI w jej rogu oraz tytuł żądania ściągnięcia. Najechanie kursorem lub ustawienie fokusu na etykiecie otwiera kartę ze szczegółami. Karta pozostaje otwarta, dopóki kursor myszy lub fokus klawiatury znajduje się wewnątrz niej.

Na małym ekranie nie ma chipa. Otwórz menu z trzema kropkami w nagłówku i wybierz pozycję `PR #number` (na GitLab `MR !number`), aby wyświetlić tę samą kartę w oknie dialogowym.

Nagłówek sam dba o aktualność danych: sprawdza stan około co 20 sekund, gdy trwają kontrole lub dostawca nadal ustala, czy gałąź może zostać scalona, a w pozostałych przypadkach około co 60 sekund. Sprawdzanie zatrzymuje się, gdy pull request zostanie scalony lub zamknięty i nic nie będzie już uruchomione.

## W pasku bocznym [#in-the-sidebar]

Rozmowy, które mają pull request, otrzymują tę samą ikonę i kropkę CI na końcu swojego wiersza. Wiersz zachowuje własny tytuł rozmowy. Najedź kursorem na wiersz albo ustaw fokus lub kliknij znacznik, aby otworzyć kartę obok niego; kliknięcie znacznika nie otwiera rozmowy.

Pasek boczny nie odpytuje serwera w tle. Wiersz jest tak aktualny, jak ostatnie załadowanie listy, i odświeża się, gdy wracasz do okna, a jego dane są starsze niż minuta. Jeśli odświeżenie nie powiedzie się dla pull requesta, który został już wcześniej znaleziony, znacznik pozostaje, a karta wyświetla komunikat „Nie udało się odświeżyć pull requesta” wraz z przyciskiem **Ponów**. Rozmowa, której pull request nigdy nie został znaleziony, nie pokazuje żadnego znacznika, nawet gdy wyszukiwanie się nie powiodło.

## Odczytywanie karty [#reading-the-card]

Karta pokazuje `PR #number` (`MR !number` w GitLab), liczbę dodanych linii w kolorze zielonym i usuniętych w kolorze czerwonym, link **Open in GitHub**, **Open in GitLab** lub **Open in Bitbucket**, tytuł oraz dwie odznaki:

- Stan: Otwarty, Konflikty, Szkic, Scalony lub Zamknięty. Konflikty zastępuje stan Otwarty, gdy gałąź nie może zostać scalona w sposób czysty.
- Checks: Passing, Failing, Running lub None. W GitLab jest to główny pipeline (head pipeline), ale tylko wtedy, gdy został uruchomiony dla bieżącego commita. W Bitbucket są to statusy commitów.

Kolor ikony i kropka CI przedstawiają te same informacje na pierwszy rzut oka:

| Pull request | Ikona | Kropka CI |
| ------------------------------------ | ------- | --------------- |
| Otwarty, można scalić | Zielona | Z sprawdzeń |
| Otwarty, zgodność scalenia jeszcze nieznana | Neutralna | Z sprawdzeń |
| Otwarty, konflikty scalania | Czerwona | Z sprawdzeń |
| Wersja robocza | Neutralna | Z sprawdzeń |
| Scalony | Fioletowa | Brak |
| Zamknięty | Neutralna | Brak |

Kropka jest zielona dla zaliczonych sprawdzeń, czerwona dla niezaliczonych i bursztynowa dla uruchomionych. Gdy repozytorium nie zgłasza żadnych sprawdzeń, kropka nie jest wyświetlana. Niezaliczone sprawdzenie ma wyższy priorytet niż sprawdzenie, które wciąż trwa.

## Którą pull request widzisz [#which-pull-request-you-see]

Workspace raportuje repozytorium, gałąź i commit, na których czat był ostatnio uruchamiany, a LibreChat szuka pull requesta z tej gałęzi:

- Jeśli wynik polecenia w czacie wypisał link do pull requesta w tym samym repozytorium (na przykład adres, który wypisuje `gh pr create`), używany jest ten pull request, o ile pochodzi z gałęzi czatu.
- W przeciwnym razie otwarte pull requesty dla danej gałęzi mają pierwszeństwo przed zamkniętymi, więc stary, zamknięty pull request o tej samej nazwie gałęzi nie ukryje bieżącego.
- Pull request liczy się tylko wtedy, gdy zawiera commit, na którym ostatnio uruchomiono czat. Usunięcie gałęzi i ponowne użycie jej nazwy nie przywraca starego pull requesta.
- Nowa gałąź bez żadnych commitów niczego nie dopasowuje.

Repozytoria, do których serwer nie ma uprawnień do odczytu, zachowują się dokładnie tak samo jak repozytoria bez pull requesta: brak oznaczenia i brak błędu.

## Podłącz własne konto [#connect-your-own-account]

Jeśli administrator to skonfigurował, możesz wyszukiwać pull requesty przy użyciu własnego konta GitHub, GitLab lub Bitbucket. Otwórz **Ustawienia**, przejdź do **Konto**, a następnie w sekcji **Połączone konta** kliknij **Połącz** obok **Konto do pull requestów**. Otworzy się okno logowania u dostawcy; zatwierdź je, a wiersz pokaże status **Połączono**. Jeśli okno nie otworzy się, zezwól na wyskakujące okna dla LibreChat i spróbuj ponownie.

Po połączeniu wyszukiwania korzystają z Twojego konta, dzięki czemu widzisz pull requesty w każdym repozytorium, do którego masz dostęp do odczytu, w ramach Twojego własnego limitu zapytań. **Rozłącz** usuwa połączenie, a Ty możesz połączyć się ponownie w dowolnym momencie. Jeśli serwer nie może odświeżyć Twojego połączenia (na przykład gdy dostawca jest niedostępny), Twoje pull requesty są oznaczane jako niedostępne, zamiast po cichu przełączać się na token serwera. Jeśli cofniesz autoryzację aplikacji u dostawcy, LibreChat usunie połączenie i wrócisz do stanu niepołączonego.

Jeśli w wierszu widnieje **Not in use**, administrator wyłączył połączenia kont, a wyszukiwania nie korzystają już z Twojego konta. Kliknij **Disconnect**, aby usunąć zapisane połączenie.

## Konfiguracja [#setup]

Funkcja jest domyślnie włączona, ale pozostaje ukryta, dopóki administrator nie poda LibreChat tokenu oraz listy repozytoriów, w których może wyszukiwać, lub nie skonfiguruje aplikacji, aby użytkownicy mogli połączyć własne konta. Wymaga ona również podłączonego obszaru roboczego kodu, który raportuje swoją gałąź git. Zobacz [Konfiguracja Pull Requests](/docs/configuration/pull_requests).
