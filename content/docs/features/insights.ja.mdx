Admin Insightsは、オプトインで利用できるダッシュボードであり、デプロイ先のプライマリMongoDBに保存されたアクティビティをもとに、Agentがどのように利用されているかを確認できます。閲覧者が参照できるAgentについて、会話数、ユニークユーザー数、保存されたメッセージ数、記録されたトークン数を時系列で表示し、トップユーザー、離脱、最近の会話の各ビューも提供します。

## Insightsを有効にする [#enable-insights]

`.env` で `ENABLE_INSIGHTS=true` を設定し、LibreChat を再起動してください：

```sh filename=".env"
ENABLE_INSIGHTS=true
```

アカウントが少なくとも 1 つのエージェントのインサイトを閲覧できる場合に有効にすると、デスクトップのサイドバーとモバイルのパネル切り替えに **Insights** が表示されます。無効にすると、アクセス用およびデータ用のルートは `404` を返し、ナビゲーション項目は非表示のままになります。

## アクセス要件 [#access-requirements]

サインインしたアカウントがレビューできるエージェントは、そのアカウントの種類によって異なります。

- `ADMIN`ロールを持つアカウントは、すべてのAgentを閲覧できます。
- `read:insights` システム機能を持つアカウントは、すべてのエージェントを閲覧できます。
- 他のすべてのユーザーには、エージェントのアクセスリストで**VIEW**と**View insights**の両方の権限が付与されているエージェントのみが表示されます。

`GET /api/insights/access` は、アカウントからアクセス可能な Agent が一つもない場合にのみ `403` を返します。また、ダッシュボードのルートは、リクエストがそのセットに含まれない Agent を指定した場合に `403` を返します。

Agentの**インサイトを表示**を付与できるのは、管理者のみです。これはAgentの共有ダイアログにある個別のトグルで、他のユーザーには表示されず、公開プリンシパルに付与することはできません。管理者は常にアクセス権を持っています。`read:insights`権限を割り当てるには[管理パネル](/docs/features/admin_panel)を使用してください。権限ビットについては[アクセス制御](/docs/features/access_control)を参照してください。

すべての Insights クエリは、認証済みアカウントからテナントのスコープを導出します。テナントアカウントは自身のテナントに属する Agents およびレコードのみを参照でき、テナントに属さないアカウントはスコープ指定のないレコードのみを参照できます。

<Callout type="warning" title="機密性の高い運用データ">
  ユーザー名とメールアドレス、会話ID、最近の会話の最初のメッセージが Insights に表示されることがあります。`read:insights` または **View insights** は、このデータを確認する必要がある人にのみ付与してください。
</Callout>

## ダッシュボードメトリクス [#dashboard-metrics]

メトリクスは、閲覧者が参照できるエージェントとの会話に限定され、エージェントフィルターでさらに絞り込まれます。4つの要約メトリクスとその日次スパークラインには、選択された日付範囲が使用されます。

- **会話:** 指定した期間に作成された、選択したエージェントとの会話
- **ユニークユーザー:** これらの会話において、保存されたメッセージのアクティビティが一致するユーザー
- **メッセージ:** それらの会話に保存されたユーザーおよびアシスタントのメッセージ
- **トークン:** 記録されたメッセージの `tokenCount` 値の合計

ダッシュボードには以下も含まれています：

- **トップユーザー:** メッセージ数で順位付けされた最大8名のユーザー。各ユーザーの会話数とメッセージ数の合計が表示されます。
- **離脱ユーザー:** 選択した期間中に、選択したいずれかのエージェントに送信した最新のメッセージが28日経過したユーザー(最大8名)
- **最新の会話:** 日付、所有者、最初のメッセージ、永続化されたメッセージ数、および記録されたトークン数を含むページネーションされた会話

これらはデータベースのアクティビティメトリクスであり、課金やLangfuseの分析ではありません。トークンの合計はメッセージと共に永続化された値に依存しており、金銭的なコストを計算するものではありません。

## 日付範囲と検索 [#date-ranges-and-search]

デフォルトの範囲は7日間です。プリセットでは過去24時間、7日間、または30日間をカバーしています。カスタム範囲は最大で30暦日まで指定可能で、ブラウザの現在のタイムゾーンでグループ化されます。

Agentフィルターは、アクセス可能なすべてのAgentを選択または解除するための固定された **All agents** コントロールを備えたチェックボックスを使用します。10個以上のAgentが利用可能な場合、検索フィルターは現在の検索結果に含まれていない選択項目を解除することなく、大文字と小文字を区別せずに名前を検索します。

最近の会話検索は、会話IDまたはユーザーIDと一致します。検索は3文字から開始され、最大200文字まで受け付けます。また、最新の会話テーブルは1ページあたり10行のページネーションが維持されます。サマリーカード、トップユーザー、およびチャーンメトリクスは、検索結果のサブセットではなく、選択された日付範囲を引き続き反映します。

## データとデプロイに関する注意点 [#data-and-deployment-notes]

Insightsは、既存のConversation、Message、およびUserコレクションを直接クエリするため、個別の分析用データベースを必要としません。結果には永続化されたレコードのみが反映されます。MongoDB内に存在しなくなった一時データや削除済みデータは表示されません。APIは、集計を実行する前に、カスタム範囲、結果リスト、ページサイズ、検索入力、およびテナントスコープを制限します。

デプロイメントのスイッチについては、[`ENABLE_INSIGHTS`](/docs/configuration/dotenv#admin-insights) を参照してください。
