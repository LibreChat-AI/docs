An Agent Plugin 是 LibreChat 服务器上的一个文件夹，它将相关的 [Skills](/docs/features/skills)、[MCP servers](/docs/features/mcp) 以及可选的命令钩子（command hooks）打包在一起。管理员只需将该文件夹放入插件目录并重启 LibreChat，无需在 UI 中进行任何安装操作。LibreChat 遵循开放的 Agent Plugins `1.0.0` 包格式，因此同一个插件包可以与其他支持该格式的工具共享。

Agent Plugins 目前处于实验阶段,其包格式和行为可能会发生变化。

## 用户所见 [#what-users-see]

用户从不会直接看到插件本身,他们看到的是插件所包含的内容。

- 它们的 Skills 会与其他 Skills 一起出现在 Skills 列表中。它们是只读的，遵循常规的 Skills 权限设置，并且可以像其他 Skill 一样通过 **Available to agent** 开关进行启用或禁用。
- 其 MCP 服务器会显示在工具库中,并且可以像在 `librechat.yaml` 中定义的服务器一样添加到智能体中。
- 它的钩子在服务器上运行,位于智能体运行的特定节点,例如工具调用之前或运行停止时。钩子可以阻止工具调用、向提示词添加上下文或停止运行,用户只会看到其产生的效果。

如果技能或 MCP 服务器的名称与其他位置定义的名称冲突,则以另一个定义为准:独立部署的技能目录中的技能优先于插件技能,`librechat.yaml` 中的服务器优先于插件服务器。

## 插件可以包含哪些内容 [#what-a-plugin-can-contain]

一个插件文件夹包含一个 `plugin.json` 清单文件，以及以下任意内容：

- `skills/`，每个技能对应一个文件夹，每个文件夹中包含一个 `SKILL.md`。
- `mcp.json`,MCP 服务器定义。本地(`stdio`)服务器在插件文件夹内运行,并拥有各自的持久化数据目录。
- `ai.librechat/hooks/hooks.json`,命令钩子(command hooks)。这些钩子以进程形式在 API 主机上运行,除非运维人员主动启用,否则默认处于禁用状态。

每个部分都可以独立加载,因此损坏的 `mcp.json` 不会阻止插件的 Skills 加载。问题会记录在启动日志中。

## 设置 [#setup]

插件默认从项目根目录下的 `./plugin` 加载,命令钩子默认处于关闭状态。有关目录设置、包结构、清单和 MCP 验证规则以及钩子执行约定,请参阅 [Agent Plugins 配置](/docs/configuration/agent_plugins)。
