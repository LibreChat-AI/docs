Password reset lets a user pick a new password without asking an admin. It is off by default, and it only makes sense once the server can send email.

## Resetting a password

<Steps>
  <Step>On the login page, click **Forgot Password?**.</Step>
  <Step>Enter the account's email address and click **Continue**. The page always answers with the same "If an account with that email exists..." message, so it does not reveal which addresses have accounts.</Step>
  <Step>Open the email and follow the link. It is valid for 15 minutes, and requesting a new one invalidates the old one.</Step>
  <Step>Enter and confirm the new password. You then see **Password Reset Success** and can sign in with it.</Step>
</Steps>

A successful reset signs the account out of every other session and revokes its tokens. If email is configured, the user also gets a confirmation email.

## Limits

- Requests are rate limited per IP (2 every 2 minutes by default), and the link submissions are limited separately.
- If the admin restricted registration to certain email domains, addresses outside those domains cannot request a reset.

<Callout type="warning" title="Do not enable it without email">
  If password reset is turned on but no email service is configured, LibreChat skips the email and shows the reset link directly on the page, to whoever typed the address. Anyone who knows a user's email can then take over that account. The server logs a warning at startup when it detects this setup.
</Callout>

## Setup

An admin enables it with `ALLOW_PASSWORD_RESET` and configures Mailgun or an SMTP server. See [Email setup](/docs/configuration/authentication/email); the rate limits are on the [Automated Moderation](/docs/configuration/mod_system) configuration page.
