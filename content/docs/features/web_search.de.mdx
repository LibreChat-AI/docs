Die Websuche gibt dem Modell ein Werkzeug `web_search`. Wenn eine Frage aktuelle Informationen erfordert, formuliert das Modell eine Suchanfrage, LibreChat ruft Ergebnisse ab, liest die wichtigsten Seiten und die Antwort wird zusammen mit den verwendeten Quellen zurückgegeben.

## In einem Chat aktivieren [#turn-it-on-in-a-chat]

Klicken Sie auf **+** im [Nachrichteneditor](/docs/features/composer), um die Palette zu öffnen, und wählen Sie dann **Web Search** im Abschnitt **Tools** aus. Sie wird als Chip im Nachrichteneditor angezeigt, solange sie aktiviert ist. Um sie zu deaktivieren, entfernen Sie den Chip oder wählen Sie sie in der Palette erneut aus. Sie können sie außerdem anheften, sodass der Chip auch dann im Nachrichteneditor bleibt, wenn die Funktion deaktiviert ist.

Mit aktivierter Websuche entscheidet das Modell trotzdem selbst, ob eine Nachricht eine Suche erfordert. Die Frage „Was hat sich im neuesten Node.js-Release geändert?“ löst in der Regel eine Suche aus, die Bitte, einen Absatz umzuschreiben, dagegen nicht.

Für Agenten ist die Websuche eine Funktion, die Sie im Agent-Builder aktivieren. Jeder, der mit diesem Agenten chattet, erhält das Tool ohne eigene Einstellungen vornehmen zu müssen.

## Was Sie in der Antwort sehen [#what-you-see-in-the-answer]

Während das Tool läuft, zeigt die Nachricht den Fortschritt an („Searching the web“, dann „Reading results“). Sobald es fertig ist, wird sie zu **Searched the web** eingeklappt; klappen Sie sie auf, um die gefundenen Seiten zu sehen, oder verwenden Sie die Schaltfläche **Search details** daneben, um die Suchanfrage anzuzeigen, die das Modell gesendet hat.

Inline-Zitate im Text verweisen auf diese Seiten, sodass Sie eine Aussage anhand der Seite überprüfen können, aus der sie stammt. Wenn mehrere Agenten nebeneinander antworten, sammelt eine **Sources**-Zeile oberhalb der Antworten zusätzlich die Ergebnisse, mit **All** sowie den Tabs **News** und **Images**, sofern die Suche diese Ergebnisse geliefert hat.

## Wie eine Suche abläuft [#how-a-search-runs]

Jede Suche durchläuft bis zu drei Dienste:

- Ein Suchanbieter liefert eine Liste von Ergebnissen zurück: Serper, SearXNG, Tavily oder Keenable.
- Ein Scraper ruft die Seiten hinter diesen Ergebnissen ab und extrahiert deren Text: Firecrawl, Serper Scrape, Tavily Extract oder Keenable Fetch.
- Ein Reranker (Jina oder Cohere) wählt die Passagen aus, die für die Anfrage am relevantesten sind. Das Reranking kann auf **None** gesetzt werden, um diesen Schritt zu überspringen.

Nur die extrahierten Passagen gelangen an das Modell, nicht ganze Seiten. Seiten, die ein Timeout auslösen oder das Scraping blockieren, werden übersprungen, sodass eine Antwort möglicherweise weniger Quellen zitiert, als die Suche zurückgegeben hat.

Die Sicherheitssuche ist standardmäßig auf „moderat“ eingestellt. Ihr Administrator kann die Stufe für alle erhöhen oder senken; Tavily bildet die Ausnahme und filtert nur dann, wenn der Administrator dessen eigene Sicherheitssuche-Option aktiviert.

## Eigene API-Schlüssel hinzufügen [#adding-your-own-api-keys]

Wenn Ihr Administrator nicht für jeden Dienst Schlüssel bereitgestellt hat, öffnet sich beim Aktivieren von **Web Search** ein Dialog, der diese abfragt. Er enthält einen Abschnitt für jeden Dienst, den der Administrator den Benutzern überlassen hat, aus **Search Provider**, **Scraper** und **Reranker**. Wählen Sie in jedem Abschnitt einen Dienst aus, geben Sie die Schlüssel ein (jedes Feld verlinkt auf die Stelle, an der Sie einen Schlüssel erhalten) und klicken Sie auf **Save**. SearXNG fragt nach Ihrer Instanz-URL; der Schlüssel ist optional. Keenable funktioniert ohne Schlüssel; das Hinzufügen eines Schlüssels erhöht lediglich die Ratenlimits.

Die Schlüssel werden mit deinem Konto gespeichert und nur für deine Suchanfragen verwendet. Um später den Anbieter zu ändern oder einen Schlüssel zu ersetzen, öffne die Palette und klicke in der Zeile **Web Search** auf **Configure** (das Zahnrad). Sobald du Schlüssel gespeichert hast, löscht **Revoke** im selben Dialog sie. Wenn der Administrator alle Schlüssel auf dem Server gesetzt hat, gibt es weder einen Dialog noch ein Zahnrad.

Eine von Ihnen eingegebene URL wird niemals mit einem Schlüssel kombiniert, den der Administrator auf dem Server festgelegt hat. Wenn der Administrator einen Firecrawl- oder SearXNG-Schlüssel gesetzt hat und Sie für diesen Dienst Ihre eigene URL eingeben, geben Sie auch Ihren eigenen Schlüssel ein. Andernfalls ignoriert Firecrawl Ihre URL und verwendet stattdessen den Standard-Endpunkt, und SearXNG wird nicht ausgeführt. Eine SearXNG-Instanz ohne Schlüssel funktioniert weiterhin: Wenn kein Schlüssel im Spiel ist, reicht Ihre URL allein aus.

## Die Option „Websuche“ ist nicht sichtbar [#web-search-option-is-not-visible]

Es gibt keine separate Schaltfläche für die Websuche; die Option erscheint nur im Abschnitt **Tools** der Palette. Sie fehlt, wenn:

- Sie chatten mit einem Agenten oder im Assistants-Endpoint. Agenten bringen ihre eigenen Tools mit, daher wird die Websuche stattdessen im Agent Builder aktiviert.
- Die ausgewählte Model Spec blendet die Zeile mit den Tools aus.
- Deine Rolle hat nicht die Berechtigung „Websuche“. Dadurch wird auch die integrierte Suche blockiert, die einige Anbieter bereitstellen.
- Ihr Administrator hat `web_search` aus den Agent-Funktionen entfernt.

## Einrichtung [#setup]

Die Websuche ist für Agenten und Chats standardmäßig verfügbar, benötigt jedoch einen Suchanbieter und einen Scraper, bevor sie Ergebnisse liefert. Ein Administrator hinterlegt die Schlüssel entweder auf dem Server oder überlässt deren Eingabe den Benutzern. Selbst gehostete Anbieter unter einer privaten Adresse sind blockiert, bis der Administrator sie in [`allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) auflistet. Informationen zu Anbietern, Schlüsseln und Optionen finden Sie unter [Web Search configuration](/docs/configuration/librechat_yaml/object_structure/web_search), und [Setting up SearXNG](/docs/configuration/librechat_yaml/object_structure/web_search#setting-up-searxng) zeigt, wie Sie den Suchanbieter selbst hosten.
