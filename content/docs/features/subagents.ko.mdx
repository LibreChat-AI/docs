Subagents를 사용하면 LibreChat Agent가 집중적인 작업을 위해 격리된 하위 실행(child run)을 생성할 수 있습니다. 하위 에이전트는 자체 컨텍스트 창과 도구 실행 흐름을 갖습니다. 부모 에이전트는 모든 중간 도구 호출, 추적 또는 장황한 파일 작업을 자신의 컨텍스트에 포함하지 않고 하위 에이전트의 결과만 전달받습니다.

다음 용도로 서브 에이전트(subagents)를 사용하세요:

- 긴 중간 출력을 생성할 수 있는 연구 하위 작업
- 특수 에이전트를 통한 검토 통과
- 부모 컨텍스트 외부에 유지되어야 하는 도구 중심 작업
- 단일 위임 작업 뒤에서 실행되어야 하는 멀티 에이전트 팀 워크플로우
- 부모가 조정하고 요약하는 병렬 스타일 분해

## Subagents와 Handoffs의 차이점 [#how-subagents-differ-from-handoffs]

핸드오프(Handoffs)는 대화를 기본 에이전트에서 전문 에이전트로 넘기고, 이후 전문 에이전트가 대화를 이어갑니다. 서브에이전트(Subagents)는 실행 중에 에이전트가 도구 호출로 생성하며, 격리된 상태에서 작업을 수행한 뒤 간결한 결과를 상위 에이전트에게 반환합니다.

- **Handoffs**: 대화가 다른 에이전트로 넘어갑니다
- **Subagents**: 상위 에이전트에서 격리된 하위 실행(child run)으로의 런타임 위임이며, 상위 에이전트가 계속 제어권을 유지합니다

둘 다 기존 에이전트를 사용할 수 있지만, 서브에이전트는 단일 에이전트의 추론 루프 내부에서 범위가 지정된 위임을 수행하도록 설계되었습니다. 레거시 에이전트 체인은 더 이상 사용되지 않습니다(deprecated). 새로운 오케스트레이션에는 핸드오프 또는 서브에이전트를 사용하세요. [에이전트](/docs/features/agents#handoffs)를 참조하세요.

## 기능 활성화 [#enable-the-capability]

`subagents` 기능은 기본적으로 활성화되어 있습니다. 관리자는 agents 엔드포인트의 기능 목록에서 이를 제거하여 해당 기능을 비활성화할 수 있습니다. 기본 기능 목록은 다음과 같습니다:

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'ocr'
```

직접 `capabilities`를 설정하는 경우, 유지하려는 모든 capability를 나열해야 합니다. 목록이 기본값을 대체하기 때문입니다. 백그라운드 실행(`run_in_background`)은 기본 목록에 포함되어 있지 않으므로 [Detached Subagent Threads](#detached-subagent-threads)를 참고하세요.

## 에이전트 구성하기 [#configure-an-agent]

Agent Builder에서 **Add tools**를 열고, 도구 라이브러리에서 **Subagents**를 선택한 다음 활성화 스위치(**Enable subagents**)를 켜세요.

사용 가능한 설정:

- **Enable subagents**: 에이전트에 subagent spawn 도구를 추가합니다.
- **Allow self-spawn**: 에이전트가 격리된 컨텍스트에서 자신의 새로운 복사본을 생성할 수 있도록 합니다. 이는 subagents가 활성화되면 기본적으로 활성화됩니다.
- **파일 공유 대상 서브에이전트**: 메시지의 파일을 인증된 포그라운드 서브에이전트와 공유합니다. 이 옵션은 `endpoints.agents.fileSharing.enabled`가 true인 경우에만 표시됩니다.
- **추가 하위 에이전트(Additional subagents)**: 부모 에이전트가 생성할 수 있는 특정 에이전트를 선택합니다.

저장된 Agent 팀은 Agent 생성 또는 업데이트 페이로드 내에 `subagents.graphs`로 포함됩니다. 현재 Agent Builder는 self-spawn 및 개별 Agent 설정을 편집하는 동안 이러한 정의를 유지하지만, 그래프 정의를 직접 작성하지는 않습니다. 각 팀은 경계가 지정된 비순환 방향 그래프(DAG), 해당 그래프의 진입점 Agent, 그리고 부모에게 결과가 반환되는 Agent를 지정합니다:

```yaml filename="agent saved-team subagent"
subagents:
  enabled: true
  allowSelf: false
  graphs:
    - type: 'research_team'
      name: 'Research team'
      description: 'Researches a topic and reviews the findings'
      agent_ids:
        - 'agent_researcher'
        - 'agent_reviewer'
      entry_agent_id: 'agent_researcher'
      result_agent_id: 'agent_reviewer'
      edges:
        - from: 'agent_researcher'
          to: 'agent_reviewer'
          edgeType: 'direct'
```

동일한 에이전트 형태:

```yaml filename="agent subagents"
subagents:
  enabled: true
  allowSelf: true
  agent_ids:
    - 'agent_researcher'
    - 'agent_reviewer'
```

## Model Spec 구성하기 [#configure-a-model-spec]

관리자는 Model Specs에서 생성된 일회성 에이전트에 대해 Subagents를 활성화할 수도 있습니다. 이는 사용자가 영구적인 상위 에이전트를 생성하거나 선택할 필요 없이, Model Specs가 특정 목적에 집중된 에이전트 프로필처럼 작동해야 할 때 유용합니다.

```yaml filename="modelSpecs / subagents"
modelSpecs:
  list:
    - name: 'research-assistant'
      label: 'Research Assistant'
      subagents:
        enabled: true
        allowSelf: true
        agent_ids: []
      preset:
        endpoint: 'agents'
        model: 'gpt-4o'
```

`enabled` 및 `allowSelf`만 시작 구성에서 클라이언트로 전송됩니다. `agent_ids` 허용 목록은 서버 측에 유지되며, 기본값이 10이고 [`endpoints.agents.maxSubagents`](/docs/configuration/librechat_yaml/object_structure/agents#maxsubagents)를 통해 구성되는 유효 Subagent 제한에 따라 검증됩니다. 클라이언트 요청 페이로드는 모델 사양(Model Specs) Subagent 구성을 제공하거나 재정의할 수 없습니다.

## 런타임 동작 [#runtime-behavior]

서브 에이전트(subagents)가 활성화되면, 상위 에이전트는 `subagent` 도구를 받게 됩니다. 이 도구는 다음을 생성할 수 있습니다:

- `self` (`allowSelf`가 false가 아닐 때)
- `agent_ids`에 구성된 모든 하위 에이전트
- `graphs`에 저장된 모든 완성된 Agent 팀

하위 에이전트는 격리된 컨텍스트에서 실행됩니다. 상위 도구 검색 상태와 누적된 컨텍스트는 하위 실행으로 복사되지 않습니다. 포그라운드 하위 모델 사용량은 상위 트랜잭션 및 총 사용량에 포함되지만, 상위 요청이 종료된 후 완료되는 분리된(detached) 하위 호출은 사용량을 독립적으로 기록합니다. 컴팩트한 하위 카드는 포그라운드, 그래프, 레거시 및 분리된 실행을 위한 통합 활동 사이드 패널을 열며, 해당 전송 방식에 적합한 제한된 수명 주기, 추론, 도구, 승인 및 결과 세부 정보를 표시합니다. 명명된 에이전트의 구성된 이름과 아바타는 스트리밍이 완료된 후와 새로고침 후에도 해당 카드와 패널에 유지됩니다. 저장된 식별 정보가 없는 이전 기록은 일반적인 대체(fallback) 항목을 사용합니다.

명시적 하위 에이전트(child agents)는 경량 설명자(lightweight descriptors)로서 상위 에이전트에게 광고되며, 선택되었을 때만 완전히 초기화됩니다. 사용되지 않는 하위 에이전트는 모델, 도구, MCP 서버, 파일 또는 스킬을 로드하지 않습니다. 호출 시 LibreChat은 보기 권한과 하위 에이전트의 버전이 지정된 구성 ID를 재확인합니다. 만약 실행 중에 액세스 권한이 취소되었거나 저장된 구성이 변경된 경우, 하위 에이전트는 오래된 설정으로 실행되는 대신 실패 처리(fails closed)됩니다.

병렬 분기가 동일한 하위 Agent를 참조할 때, LibreChat은 각 탐색 경로에 대해 순환(cycle) 및 깊이(depth) 제한을 독립적으로 평가합니다. 따라서 한 분기에서의 순환이 다른 분기에 있는 유효한 중첩 Agent 링크를 폐기하지 않습니다.

저장된 팀은 개별 하위 에이전트와 동일한 지연 해결(lazy resolution) 및 액세스 확인 방식을 따릅니다. 팀이 선택되면 각 구성원은 고유한 모델, 지침, 도구, MCP 자격 증명, 기술(Skills), 파일, 메모리, Code Interpreter 프로필 및 결제 ID를 유지합니다. LibreChat은 팀을 하나의 격리된 하위 그래프로 실행하고, 구성원별 진행 상황을 스트리밍하며, 구성된 결과 에이전트의 출력을 반환합니다. 영구 저장된 구성원 중 누락되거나, 액세스할 수 없거나, 유효하지 않은 구성원이 있는 경우, LibreChat은 부분적인 그래프를 실행하는 대신 팀 전체를 건너뜁니다.

이후 턴에서 LibreChat은 도달 가능한 하위 도구 및 팀 도구의 이전 호출을 구조화된 도구 호출 형식으로 유지하며, 필요한 경우 확인된 MCP 서버 ID를 포함합니다. 더 이상 도달할 수 없는 도구는 단순히 기록에 나타난다는 이유만으로 활성 실행에 추가되지 않습니다.

## 분리된 서브에이전트 스레드 (Detached Subagent Threads) [#detached-subagent-threads]

`run_in_background`은 옵트인 기능입니다. 이를 Agents 엔드포인트에서 사용하려면 `endpoints.agents.capabilities`에 추가하세요. 활성화되면 상위 Agent는 하위 에이전트 작업을 분리(detach)하여 결과를 기다리지 않고 계속 진행할 수 있습니다. LibreChat은 분리된 각 하위 스레드를 비공개 실행 계보(execution lineage)와 정식 트랜스크립트와 함께 저장합니다. 하위 스레드는 일반 대화 탐색 및 검색에서 제외되며 직접 읽을 수 없습니다. 권한이 부여된 상위 뷰에서는 제한된 범위의 하위 활동만 노출됩니다.

하위 스레드(Child threads)는 읽기 전용 실행 기록입니다. 사용자는 정식 하위 스레드를 그 자리에서 편집하거나 삭제할 수 없습니다. 완료된 내구성 있는 직접 에이전트(durable direct-Agent) 하위 스레드의 경우, **Continue in a new chat**을 선택하면 완료된 해당 분기를 별도의 일반적인 쓰기 가능한 에이전트 대화로 포크(fork)하며, 원본 하위 스레드는 숨겨진 읽기 전용 상태로 남습니다. 활동 패널은 실행 전반과 작업 전달 과정에서 하나의 작성기(composer)를 유지하여, 새로운 작업 뷰가 로드되는 동안에도 포커스와 작성 중이던 안내 문구를 보존합니다. 작업이 제어권을 수락할 수 있을 때까지 제출은 불가능합니다. 완료 후 입력된 텍스트는 포크로 전달되며, 포크에 실패할 경우 패널의 초안이 복원됩니다. 이 작업은 실행 중이거나, 그래프, 익명 에이전트, 공유 뷰에서는 사용할 수 없습니다. 부모를 삭제하면 하위 계보까지 연쇄적으로 삭제됩니다. 부모 에이전트는 작업 도구를 통해 정식 하위 스레드를 폴링, 조종, 대기열 추가, 중단, 취소, 수집 및 추후 계속할 수 있으며, Mongo 기반 임대(lease)는 API 복제본 전반에서 이러한 연속 작업을 직렬화합니다.

활동 패널은 선택된 하위 항목의 턴을 하나의 브랜치 인식 기록으로 표시합니다. **Load earlier activity**를 사용하여 이전 기록을 불러오고, 특정 턴에서 **Show full activity**를 사용하여 해당 턴의 전체 경계 실행 세부 정보를 확인할 수 있습니다. 도구 호출, 승인, 결과, 제어 및 사용자에게 표시되는 추론 내용이 나타날 수 있습니다. 추론 텍스트는 나머지 프로젝션과 마찬가지로 경계가 지정되며 잘린 경우 표시가 나타납니다. 이전 서버에서 유지된 활동은 추론 마커만 표시될 수 있습니다. 일반적인 유지 활동은 비공개 하위 활동과 동일한 항목별 제한을 사용하며, 64KB 직렬화 활동 예산 내에서 연속적인 최신 접미사를 맞추므로, 의미 있는 콘텐츠가 생략된 경우에만 단축 알림이 나타납니다. 기록이 잘렸거나 사용할 수 없는 경우, 패널은 부분적인 뷰를 완전한 것처럼 표시하는 대신 해당 상태를 알립니다. 새로운 이벤트 턴은 기록 하단에 정렬되며, 실행 중인 턴은 경과 시간을 표시하고, 액터 행은 고정 위치 상태 점을 사용하여 상태 변경 시 레이아웃이 밀리지 않도록 합니다. 컴팩트한 플로팅 헤더를 통해 기록을 그 아래로 스크롤할 수 있으며, 작성기는 메인 채팅의 크기를 따릅니다. 실행 중인 작업은 별도의 실행 상태 칩이 아닌 스트리밍 활동을 통해 전달되며, 비정상적인 종료 상태는 계속해서 레이블이 지정됩니다.

Redis가 활성화되면, LibreChat은 활성 실행 소유자를 기록하고 모든 API 복제본에서 발생하는 폴(poll), 목록(list), 조종(steer), 대기열(queue), 중단(interrupt), 취소(cancel) 및 수집(collect) 요청을 제한적이고 만료되는 요청/응답 메시지를 통해 해당 프로세스로 라우팅합니다. 열려 있는 활동 패널 또한 작업 범위의 실시간 업데이트를 수신하며, 2초간 지속되는 쿼리는 누락된 이벤트, 재연결 또는 Redis 중단 시 대체 수단으로 유지됩니다. 단일 프로세스 및 Redis를 사용하지 않는 배포 환경에서는 메모리 내 빠른 경로(in-memory fast path)를 사용합니다. 라이브 실행기는 소유자 프로세스가 재시작되거나 사라진 후에도 마이그레이션되지 않지만, MongoDB 기반의 하위 트랜스크립트, 터미널 상태, 사용량, 기록 및 이후의 에이전트 기반 연속성은 독립적으로 유지됩니다. 이는 분리된 작업을 공개 백그라운드 작업 API로 전환하는 것은 아닙니다.

### 실행 중인 자식 프로세스 제어 [#control-a-running-child]

인증된 상위 대화에서 Subagent 활동 패널을 열고 지속형 하위 작업을 선택하세요. 해당 작업이 실행되는 동안 안내(guidance)를 입력하고 제출하여 기본적으로 제어할 수 있습니다. 마우스 오버가 가능한 데스크톱에서는 전송 컨트롤의 작업 메뉴에서 **Steer**, **Queue**, **Interrupt**를 제공하며, 사용자의 현재 키보드 설정에서 활성화된 단축키만 표시합니다. 터치 기기 및 모달 패널에서는 Queue와 Interrupt를 아이콘 컨트롤로 계속 사용할 수 있습니다. 입력된 안내가 없으면 전송 컨트롤은 **Cancel task**로 변경됩니다.

- **Steer**는 자식의 다음 안전 경계에서 안내를 추가합니다.
- **Queue**는 하위 작업의 이후 차례를 위한 지침을 보관합니다.
- **Interrupt**는 하위 프로세스의 현재 작업을 안전한 경계에서 중단하고 새로운 지침을 적용합니다.
- **Cancel task**는 가이던스를 전송하지 않고 작업을 취소하도록 요청합니다.

허용된 제어 항목은 작업별 기록에 전송됨, 대기 중, 적용됨, 적용되지 않음 또는 실패로 표시되며, 가능한 경우 그 이유도 함께 나타납니다. 하위 작업이 적용되기 전에 대기 중인 지침을 제거하려면 **Withdraw**를 선택하십시오. 지침은 4 KB로 제한됩니다. 각 작업은 최대 64개의 권한 있는 영수증을 저장하며, 활동 패널에는 최대 32개가 표시됩니다. 오래된 완료 기록은 활성 상태인 허용된 제어 항목보다 먼저 생략되며, UI는 생략된 기록이나 표시를 위해 단축된 지침에 라벨을 표시합니다.

실행 중인 컨트롤은 하위 항목이 정리되면 닫히며, 동일한 작성기가 새 채팅에서 적격한 하위 항목을 계속 진행하도록 전환합니다. LibreChat은 모든 요청 시 로그인한 사용자의 상위 및 하위 항목에 대한 액세스 권한, 상위-하위 관계, 테넌트 소유권을 확인하며, 구성된 콘텐츠 필터 및 조정 검사를 지침에 적용합니다. 동일한 승인된 컨트롤을 반복해서 전달하면 지침을 두 번 적용하는 대신 권한 있는 영수증이 반환됩니다. 공유 대화는 읽기 전용으로 유지되며 이러한 컨트롤을 노출하지 않습니다.

공유된 대화는 공유 페이로드에 이미 포함된 제한된 활동만 표시할 수 있습니다. 해당 뷰는 읽기 전용이며, 승인 제어 및 영구 하위 선택기(durable child selectors)가 생략되고, 인증된 하위 스레드 쿼리 경로를 절대 열지 않습니다.

### 이벤트 기반 자식 활동 (Event-Driven Child Activity) [#event-driven-child-activity]

[Agents API event binding](/docs/features/agents_api#event-driven-child-agents)을 통해 계속되는 Child Agents는 `subagent` 도구 카드에서 시작되지 않습니다. 인증된 부모 대화에서 LibreChat은 대신 해당 바인딩을 소유한 메시지 아래에 하나의 간결한 액터 행을 추가합니다. 이를 열면 액터와 해당 턴에 대한 선택기, 그리고 실시간 실행 단계(run-step), 도구, 메시지 및 추론 마커 활동이 포함된 Subagent 활동 패널이 재사용됩니다. 외부 이벤트 트리거는 확장 가능한 이벤트 유형, 소스, 발생 시간 및 예상 작업 세부 정보가 포함된 일반적인 사용자 트리거 행으로 렌더링됩니다. 새로운 전달이 동일한 하위 스레드에서 다른 작업을 선택하면, 기존 턴은 계속 표시되는 상태에서 새 작업이 로드되고 해당 작업의 스트리밍 플레이스홀더만 추가됩니다. 작업별 상태 및 제어는 유지된 뷰에서 가져오지 않습니다. 이전 페이지와 턴별 전체 활동은 동일한 제한된 읽기 전용 하위 기록을 사용합니다.

상위 프로젝션은 의도적으로 제한되어 있습니다. 최대 64개의 하위 스레드를 반환하고, 공유된 제한적 소스 창에서 하위 스레드당 최대 20개의 최근 작업을 유지하며, 응답 크기를 96KB로 제한합니다. UI는 제한을 초과한 보기가 완전하다고 암시하는 대신 잘린 기록임을 보고합니다. 새로운 턴을 시작하면 더 오래된 액터가 최근 하위 스레드 창으로 승격됩니다. 이러한 하위 스레드는 일반적인 탐색에서는 숨겨져 있으며, 다른 상위 항목이나 테넌트에서는 검색할 수 없습니다.

### 자동 부모 이어가기 (Automatic Parent Continuation) [#automatic-parent-continuation]

분리된(detached) 자식 작업이 완료되면, LibreChat은 해당 터미널 결과나 오류를 유지하며, 기본적으로 이를 시작한 정확한 브랜치의 저장된 부모 Agent에게 멱등성(idempotent) 연속 작업을 보냅니다. 전달은 해당 부모 브랜치가 실행 중이거나, 일시 중지되었거나, 마무리되는 동안 대기합니다. 재개된 부모는 관련 형제 작업들을 바쁘게 폴링(busy-polling)하는 대신 제한된 매니페스트를 수신하며, 채팅창에는 접을 수 있는 작업 카드 형태로 깨어남(wake-up) 알림이 표시됩니다.

[`endpoints.agents.backgroundTasks.completionWakeups`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks)가 생략되거나 `true`로 설정되면 자동 완성 전달이 활성화됩니다. 분리된(detached) 자식 작업을 폴링 전용으로 유지하려면 이를 `false`로 설정하십시오. 취소된 자식 작업은 무시되며, 복원할 저장된 구성이 없기 때문에 일시적인(ephemeral) 부모 Agent는 지원되지 않습니다. 분리된 자식 실행은 자체 실행 컨텍스트를 소유하므로, 원래 부모 요청을 완료하거나 중단해도 독립적으로 소유된 작업은 취소되지 않습니다. 부모는 여전히 작업 도구를 통해 지속적인 자식 결과를 수집할 수 있습니다.

## Access Control [#access-control]

구성된 하위 에이전트와 모든 저장된 팀 멤버는 사용자에게 보여야 합니다. 사용자가 참조된 개별 에이전트에 대한 보기 권한이 없는 경우, LibreChat은 해당 하위 에이전트를 건너뜁니다. 저장된 팀은 전부 아니면 전무(all-or-nothing) 방식으로 처리되며, 멤버 중 하나라도 사용할 수 없는 경우 건너뜁니다. 생성 및 업데이트 요청은 누락되었거나 권한이 없는 참조, 중복된 생성 유형, 순환적이거나 연결되지 않은 팀 그래프, 유효하지 않은 진입 또는 결과 멤버, 그리고 위 제한을 초과하는 구성을 거부합니다.

## 디자인 팁 [#design-tips]

- 부모 에이전트의 범위가 이미 잘 설정되어 있고 하위 작업을 위해 새로운 컨텍스트만 필요한 경우 self-spawn을 활성화하세요.
- 작업에 다른 모델, 지침 세트, 도구 세트 또는 기술 허용 목록이 필요한 경우 특정 하위 에이전트를 추가하세요.
- 여러 에이전트가 단일 결과값을 상위 항목으로 반환하는 위임된 워크플로우로 실행되어야 할 때 저장된 팀(saved team)을 사용하세요.
- 하위 설명(child descriptions)을 명확하게 유지하세요. 부모는 각 하위 이름과 설명을 사용하여 올바른 위임 대상을 선택합니다.
- 중간 작업에는 하위 에이전트(subagents)를 사용하되, 다른 대화 경로로 영구적으로 전환하는 용도가 아닌 간결한 결과를 반환하는 용도로 사용하세요.
