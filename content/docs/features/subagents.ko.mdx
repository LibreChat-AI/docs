서브에이전트는 에이전트가 자신의 작업 도중에 시작하는 하위 실행(child run)입니다. 하위 실행은 깨끗한 컨텍스트 창을 할당받아 작업(검색, 파일 읽기, 도구 호출)을 수행하고, 최종 결과만 반환합니다. 이렇게 하면 상위 에이전트의 컨텍스트가 작게 유지되며, 중간 작업에서 생성된 수많은 도구 출력을 상위 에이전트가 볼 필요가 없어진다는 점에서 중요합니다.

작업이 각각 많은 중간 출력을 만들어내는 여러 조각으로 나뉠 때 서브에이전트를 활용하세요. 예를 들어 여러 주제를 조사하거나, 파일 묶음을 검토하거나, 본 답변 전에 도구를 많이 사용하는 검사를 실행하는 경우가 해당합니다.

## 에이전트에서 활성화하기 [#turn-it-on-for-an-agent]

<Steps>
  <Step>
    에이전트 빌더에서 **Tools** 옆의 **Add**를 클릭한 다음, 도구 라이브러리에서 **Subagents**를 추가합니다. **Subagents** 카드의 톱니바퀴 아이콘을 클릭하여 설정을 엽니다.
  </Step>
  <Step>
    **Subagents** 스위치(Beta 표시)가 켜져 있는지 확인하세요. **Allow self-spawn**은 기본적으로 켜져 있으며, 이 옵션이 켜져 있으면 에이전트가 하위 작업을 위해 자신의 새 사본을 시작할 수 있습니다.
  </Step>
  <Step>
    선택적으로 **Additional subagents** 아래에서 **Add subagent**를 클릭하면, 사용자가 볼 수 있는 다른 에이전트에게 작업을 위임할 수 있습니다. 그다음 저장합니다.
  </Step>
</Steps>

자기 자신 생성(self-spawn)은 에이전트가 이미 해당 작업에 맞게 설정되어 있고 깨끗한 상태에서 시작하기만 하면 될 때 충분합니다. 하위 작업에 다른 모델, 다른 지침, 또는 다른 도구가 필요할 때는 다른 에이전트를 추가하세요. 예를 들어 검색에는 저렴하고 빠른 모델을, 엄격한 체크리스트가 있는 검토 에이전트를 사용하는 경우가 이에 해당합니다. 상위 에이전트는 이름과 설명을 보고 그중에서 선택하므로, 각 에이전트에는 그 용도가 무엇인지 설명하는 설명을 부여하세요.

하위 에이전트는 상위 에이전트가 실제로 선택할 때에만 로드되므로, 여러 개를 나열해도 하나가 실행되기 전까지는 비용이 들지 않습니다. 에이전트는 기본적으로 최대 10개의 하위 에이전트를 나열할 수 있습니다. 자기 생성(self-spawn)을 끄고 에이전트를 하나도 나열하지 않으면 생성할 대상이 없으므로, 빌더가 이를 알려줍니다.

### 하위 에이전트와 파일 공유 [#sharing-files-with-subagents]

관리자가 이 기능을 활성화한 경우 **하위 에이전트와 파일 공유** 스위치가 표시됩니다. 이 스위치를 켜면 현재 메시지에 첨부된 파일을 상위 에이전트가 시작한 하위 에이전트들이 사용할 수 있습니다. 하위 에이전트가 샌드박스에서 생성한 파일은 해당 에이전트가 반환할 버전을 선택하기 전까지 그 에이전트에게만 비공개로 유지됩니다.

## 채팅 화면에서 보이는 것 [#what-you-see-in-the-chat]

각 서브에이전트 실행은 부모 응답에 자식 이름과 상태가 표시된 간략한 행으로 나타납니다. 작업 중에는 **Running agent**, 완료되면 **Ran agent**로 표시됩니다. 행을 열어 활동 사이드 패널에서 자식의 진행 상황을 확인하거나, 무시하고 부모의 답변을 읽을 수 있습니다. 취소된 실행은 **Agent stopped**, 실패한 실행은 **Agent failed**로 표시됩니다. 백그라운드에서 시작된 자식(아래 참조)은 대신 **Agent activity** 블록에 그룹화되어 표시됩니다.

## 동작 방식 [#how-it-behaves]

- 자식 에이전트는 자체 컨텍스트로 시작합니다. 부모의 대화 기록이나 부모가 도구 검색으로 찾아낸 도구를 상속받지 않으며, 부모가 작성해 전달한 작업 내용을 받습니다.
- 자식 실행(child run)에서 발생한 토큰 사용량은 사용자의 잔액에 반영됩니다. 상위 실행(parent run)이 아직 진행 중일 때 완료된 자식 실행은 상위 실행의 총계에 추가되며, 나중에 완료되는 분리된(detached) 자식 실행은 각각 독립적으로 기록됩니다.
- 접근 권한이 없는 하위 에이전트는 건너뜁니다. 볼 수 없는 에이전트는 추가할 수 없습니다. 접근 권한과 하위 에이전트의 저장된 구성은 실행이 시작될 때 다시 확인되며, 실행 중에 둘 중 하나라도 변경되었다면 해당 하위 에이전트는 실행되지 않습니다.
- 각 하위 항목은 고유한 모델, 지침, 도구, MCP 자격 증명, 스킬, 파일, 메모리를 각각 유지합니다.
- 서브에이전트에도 단계 제한이 적용되므로, **Max Agent Steps** 값을 낮게 설정하면 하위 에이전트가 수행할 수 있는 작업량도 제한됩니다.
- 서브에이전트는 최대 5단계까지 자체 서브에이전트를 시작할 수 있습니다.

## 저장된 Agent 팀 [#saved-agent-teams]

부모는 저장된 팀을 시작할 수도 있습니다. 팀은 하나의 작은 워크플로로 연결된 여러 에이전트로 구성되며, 예를 들어 조사 결과를 검토자에게 넘기는 조사자 에이전트가 포함될 수 있습니다. 팀은 하나의 격리된 자식으로 실행되며, 결과 에이전트의 답변만 부모에게 돌아갑니다. 팀은 최대 32명의 구성원을 가질 수 있습니다. 구성원 중 하나라도 없거나 볼 수 없는 경우, 일부만 실행하지 않고 팀 전체를 건너뜁니다.

팀은 Agent Builder가 아닌 API를 통해 정의됩니다. 에이전트의 다른 서브에이전트 설정을 편집해도 Builder는 팀을 그대로 유지합니다. 정의 형식은 [agents 엔드포인트 구성](/docs/configuration/librechat_yaml/object_structure/agents#subagents)에서 확인할 수 있습니다.

## 분리된 서브에이전트 스레드 (Detached Subagent Threads) [#detached-subagent-threads]

관리자가 백그라운드 실행을 활성화한 경우, 상위 에이전트는 서브에이전트를 시작한 뒤 해당 작업을 기다리지 않고 계속 진행할 수 있습니다. 하위 에이전트의 작업 내용은 보기 전용 스레드로 저장되며, 상위 에이전트의 활동 패널에서 이 스레드에 접근할 수 있습니다. 이 스레드는 채팅 목록이나 검색 결과에 표시되지 않습니다. 매우 긴 기록은 일부가 잘려 표시되며, 이전 활동이 표시되지 않는 경우 패널에 그 사실이 안내됩니다.

### 실행 중인 자식 프로세스 제어 [#control-a-running-child]

분리된 자식 작업이 실행되는 동안, 활동 패널의 입력창에 입력하여 해당 작업을 안내하세요:

- **Steer**는 하위 항목의 다음 안전 지점에서 사용자의 지침을 추가합니다. 이것이 기본값입니다.
- **Queue**는 이를 하위 항목의 다음 턴을 위해 보관합니다.
- **Interrupt**는 현재 단계를 중지하고 안내 내용을 적용합니다.
- 아무것도 입력하지 않은 상태에서는 전송 버튼이 **작업 취소**로 바뀝니다.

각 메시지에는 적용 여부가 표시됩니다. 대기 중인 안내(guidance)는 하위 에이전트가 가져가기 전에 **Withdraw**를 눌러 회수할 수 있습니다. 안내는 4 KB로 제한됩니다. 직접 하위 에이전트 작업이 완료되면 **Continue in a new chat**을 눌러 해당 대화를 일반 채팅으로 복사할 수 있으며, 이후 그 채팅에서 계속 작업할 수 있습니다. 원래 스레드는 읽기 전용으로 유지됩니다.

공유된 대화에는 공유에 포함된 활동만 표시되며, 어떠한 제어 기능도 제공되지 않습니다.

### 자동 부모 연속 처리 [#automatic-parent-continuation]

분리된 자식(detached child)이 작업을 마치면, LibreChat은 기본적으로 같은 브랜치에서 부모 에이전트를 깨워 그 결과를 전달합니다. 결과는 접을 수 있는 작업 카드(task card)로 표시됩니다. 부모가 아직 다른 작업으로 바쁘다면, 깨우기는 부모가 여유로워질 때까지 대기합니다. 취소된 자식은 부모를 깨우지 않습니다. 또한 이 기능은 저장된 에이전트에서만 작동하며, 모델 스펙(Model Specs)으로 만든 에이전트에서는 동작하지 않습니다. 관리자는 이 기능을 끌 수 있으며, 이 경우 부모가 직접 자식의 상태를 확인해야 합니다.

[Agents API](/docs/features/agents_api#event-driven-child-agents)를 통해 외부 시스템이 구동하는 하위 에이전트도 동일한 방식으로 표시되며, 상위 메시지 아래에 행으로 나타나 같은 패널을 엽니다.

## Subagents와 handoffs 비교 [#subagents-compared-with-handoffs]

서브에이전트는 제어권을 부모에게 돌려줍니다. 부모가 질문하면 자식이 답하고, 부모가 최종 응답을 작성합니다. [핸드오프](/docs/features/agents#working-with-other-agents)는 대화를 다른 에이전트에게 넘기며, 이후 해당 에이전트가 직접 응답합니다. 하위 작업에는 서브에이전트를 사용하고, 전문 에이전트로 라우팅할 때는 핸드오프를 사용하세요.

## 설정 [#setup]

서브에이전트는 기본적으로 사용할 수 있습니다. 관리자는 `subagents` 기능으로 이를 끌 수 있고, `maxSubagents`로 에이전트당 한도를 높일 수 있으며, 파일 공유를 활성화할 수 있고, 옵트인 방식의 `run_in_background` 기능으로 분리된 하위 에이전트를 허용할 수 있습니다. 이러한 설정은 모두 [agents 엔드포인트 구성](/docs/configuration/librechat_yaml/object_structure/agents#subagents)에서 할 수 있습니다. 상위 에이전트의 자동 연속 실행은 [`backgroundTasks`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks)로 제어합니다. 저장된 상위 에이전트 없이 모델 스펙에 대해서도 서브에이전트를 활성화할 수 있습니다. 자세한 내용은 [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs#subagents)를 참조하세요.
