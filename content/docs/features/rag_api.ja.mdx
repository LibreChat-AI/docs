ファイル検索を使うと、ドキュメントをアップロードして、その内容をチャットに貼り付けることなく質問できます。LibreChat は各ファイルを RAG API に送信し、RAG API はファイルをチャンクに分割してインデックスを作成します。質問を入力すると、モデルはそのインデックスを検索し、見つかったパッセージをもとに回答します。

ドキュメントが長すぎて毎回すべてを読み込めない場合や、複数のファイルにまたがって回答を得たい場合に、これを利用してください。

## ファイル検索用にファイルをアップロードする [#upload-a-file-for-search]

[メッセージ作成欄](/docs/features/composer)の**+**をクリックしてパレットを開き、**その他のアップロードオプション**を展開してから、**ファイル検索用にアップロード**を選択し、ファイルを選んでください。パレットで検索して見つけることもできます。この方法でアップロードすると、そのチャットの**ファイル検索**も有効になります。大きなファイルはインデックス作成に少し時間がかかる場合があります。インデックス作成が完了すると、アップロードも完了します。

会話内のファイルにインデックスが作成されると、モデルは `file_search` ツールを利用できるようになります。いつ呼び出すかはモデルが判断します。ドキュメントに関する質問では検索が実行され、雑談では実行されません。返信の生成中は「Searching your files」というステップが表示されます。引用が有効になっている場合、使用された箇所はファイル名とともに **Sources** の下に表示されるので、ドキュメントを開いて内容を確認できます。

## 検索の仕組み [#how-search-works]

モデルが `file_search` を呼び出すと、検索クエリを作成します。LibreChat は添付された各ファイルについて、最も近い 5 件のチャンクを RAG API に問い合わせ、全体で最も近い 10 件を保持します。それらのチャンクは、ファイル名と関連性スコアとともにモデルに返され、モデルはそれらを基に回答します。

検索は、クエリと意味的に近い文章を見つけ出すため、大規模なドキュメントの中から特定の事実を探し出すのに適しています。要約のように、ドキュメント全体を一度に必要とする質問の場合は、通常「Upload as Text」の方が良い結果が得られます。

LibreChatでファイルを削除すると、そのベクトルもRAG APIから削除されます。

## 以前にアップロードしたファイルを再利用する [#reuse-files-you-already-uploaded]

インデックス化されたファイルはお使いのアカウントに保持されます。パレットを開き、**Your files**の下からファイルを選択すると、再アップロードすることなく新しいメッセージや会話に添付できます。

Assistantsエンドポイントの使用中にアップロードされたファイルは、OpenAIに保存され、RAG APIによるインデックス化は行われず、他のエンドポイントに添付することはできません。

## エージェントでのファイル検索 [#file-search-in-agents]

エージェントの場合、エージェントビルダーで[**File Search**](/docs/features/agents#file-search)を有効にし、そこにファイルをアップロードします。これらのファイルがエージェントのナレッジベースになります。エージェントとチャットするすべてのユーザーは、自分でファイルをアップロードしなくても、エージェントにそれらのファイルを検索させることができます。ファイルを追加するには、先にエージェントを保存しておく必要があります。

## ファイル検索またはテキストとしてのアップロード [#file-search-or-upload-as-text]

[**テキストとしてアップロード**](/docs/features/upload_as_text)も同じメニューにあります。ファイルからテキストを抽出し、その全文を会話に追加します。モデルがすべての単語を読む必要がある短い文書に適しています。ファイル検索は、各クエリに一致する部分だけを送信するため、長い文書や多数のファイルにも対応できますが、取得されなかった部分はモデルには見えません。

RAG API も、組み込みのパーサーで読み取れないファイル形式のテキスト抽出器として、Upload as Text を提供します。詳しくは[テキストの抽出方法](/docs/features/upload_as_text#how-the-text-is-extracted)をご覧ください。

## セットアップ [#setup]

ファイル検索には RAG API サービスとベクトルデータベースが必要です。デフォルトの Docker 構成にはその両方が含まれています。管理者は埋め込みプロバイダーを設定し、その他のインストールの場合は `RAG_API_URL` を設定します。詳細は [RAG API configuration](/docs/configuration/rag_api) を、サービス自体のエンドポイントと変数については [RAG API repository](https://github.com/LibreChat-AI/rag-api) を参照してください。
