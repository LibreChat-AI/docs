Die Zugriffskontrolle legt drei Dinge fest: welche Funktionen ein Benutzer überhaupt nutzen darf, wer einen bestimmten Agenten, Prompt, MCP-Server oder Skill, der geteilt wurde, sehen oder ändern kann, und wer Administratorrechte erhält. Ein kleines Team kann die Standardeinstellungen beibehalten und frei teilen; eine größere Bereitstellung kann Funktionen pro Rolle einschränken, Freigaben mit aus Entra ID synchronisierten Gruppen vornehmen und Teile der Administration delegieren, ohne vollständige Administratorkonten zu vergeben.

## Benutzer, Gruppen, Rollen und alle [#users-groups-roles-and-everyone]

Berechtigungen werden vier Arten von Prinzipalen gewährt:

- Ein Benutzer, also ein LibreChat-Konto.
- Eine Gruppe von Benutzern. Gruppen werden von Administratoren erstellt oder aus Entra ID synchronisiert, wenn sich Benutzer über Entra mit aktivierter OpenID-Token-Wiederverwendung anmelden. Die Freigabe für eine Gruppe ist ein einzelner Eintrag, und Änderungen der Mitgliedschaft in Entra werden beim nächsten Login jedes Mitglieds wirksam.
- Eine Rolle. Jeder Benutzer hat genau eine Rolle: standardmäßig `USER`, `ADMIN` für das erste Konto auf einer Single-Tenant-Instanz oder eine benutzerdefinierte Rolle, die ein Administrator erstellt hat. Das Teilen mit einer Rolle erreicht alle Personen, die diese Rolle derzeit innehaben.
- Jeder, also alle angemeldeten Benutzer der Instanz.

## Funktionsberechtigungen [#feature-permissions]

Jede Rolle verfügt über eine Reihe von Ein- und Ausschaltern für jede Funktion: ob ihre Benutzer Agenten verwenden, sie erstellen, mit bestimmten Personen teilen oder mit allen teilen können, und dasselbe gilt für Prompts, MCP-Server, Skills und geteilte Links. Weitere Schalter steuern geplante Chats, Erinnerungen, Lesezeichen, temporäre Chats, Mehrfachkonversationen, den Code-Interpreter, die Websuche, die Dateisuche, Zitate, den Agent Marketplace und die Personenauswahl.

Wenn ein Schalter deaktiviert ist, verschwindet der entsprechende Teil der Benutzeroberfläche für diese Rolle. Ein Benutzer ohne Berechtigung zum Erstellen von Agenten sieht die Option zum Erstellen eines Agenten nicht; ein Benutzer ohne Berechtigung zum "Mit allen teilen" erhält den Schalter **Mit allen teilen** nicht.

Standardmäßig können Benutzer Agenten, Prompts, MCP-Server und Skills verwenden und erstellen, sie aber nicht teilen; das Teilen ist etwas, das ein Administrator explizit aktivieren muss. Die vollständige Liste mit Standardwerten finden Sie auf der Seite [Access Control configuration](/docs/configuration/access_control#feature-permissions).

Administratoren ändern diese Schalter ohne Neustart. In LibreChat verfügen die Bereiche für Agenten, Prompts, MCP-Server, Erinnerungen und Skills über eine Schaltfläche **Admin-Einstellungen**, die die Schalter für diese Funktion öffnet. Oben befindet sich eine Auswahl **Rolle**. Das [Admin-Panel](/docs/features/admin_panel) bearbeitet dieselben Schalter für jede Rolle, einschließlich benutzerdefinierter Rollen.

## Eine Ressource teilen [#sharing-a-resource]

Agents, Prompts, MCP-Server, Skills und Shared Links führen jeweils eine eigene Liste, wer Zugriff darauf hat. (Agents, die über die [Agents API](/docs/features/agents_api) genutzt werden, sowie vom Deployment verwaltete Code-Umgebungen verwenden dieselben Listen, die jedoch außerhalb des Freigabedialogs verwaltet werden.) Die Person, die eines davon erstellt hat, ist dessen Eigentümer:in und entscheidet, wer sonst Zugang erhält.

<Steps>
  <Step>Öffnen Sie die Ressource und klicken Sie auf die Schaltfläche **Teilen**. Diese sehen Sie nur, wenn Sie Eigentümer der Ressource sind (oder die Rolle „Owner“ darauf innehaben oder Administrator sind) und Ihre Rolle das Teilen dieser Art von Ressource erlaubt.</Step>
  <Step>Suchen Sie im Dialog **Teilen** nach Personen oder Gruppen anhand von Name oder E-Mail-Adresse. Rollen werden bei der Suche ebenfalls angezeigt, sofern der Administrator sie nicht ausgeblendet hat.</Step>
  <Step>Wählen Sie für jede hinzugefügte Person oder Gruppe eine Zugriffsrolle aus.</Step>
  <Step>Falls Ihre Rolle dies erlaubt, aktivieren Sie **Mit allen teilen** und wählen Sie **Berechtigungsstufe für alle**.</Step>
  <Step>Klicken Sie auf **Speichern**.</Step>
</Steps>

Die Zugriffsrollen sind für jeden Ressourcentyp gleich:

| Zugriffsrolle | Was sie tun können |
| ------------- | ------------------ |
| Betrachter | Die Ressource finden und verwenden, zum Beispiel den Agenten auswählen und mit ihm chatten. Sie können sie nicht ändern. |
| Bearbeiter | Alles, was ein Betrachter kann, zusätzlich Einstellungen, Anweisungen, Tools und Dateien ändern. |
| Eigentümer | Alles, was ein Bearbeiter kann, zusätzlich löschen und ändern, mit wem sie geteilt wird. |

Freigegebene Links haben nur die Rollen Viewer und Owner. Eine Ressource benötigt immer mindestens einen Owner, daher lässt der Dialog nicht zu, dass der letzte Owner entfernt wird.

Agents haben eine zusätzliche Berechtigung, die in keiner dieser Rollen enthalten ist: **Insights anzeigen**. Damit kann jemand, der den Agenten bereits sehen kann, dessen [Insights](/docs/features/insights) öffnen. Nur Administratoren sehen diesen Schalter im Freigabedialog, und er kann nicht allen gewährt werden.

Bevor Sie jemandem die Rolle Editor oder Owner für einen Agenten zuweisen, bedenken Sie, dass diese Person alles sehen kann, was an dem Agenten konfiguriert ist, einschließlich seiner Anweisungen und angehängten Dateien. Auch Viewer können angehängte Inhalte über den Chat herauslocken. Hängen Sie daher an einen geteilten Agenten nichts an, was sein Publikum nicht lesen soll.

## Administratoren und delegierte Administratorrechte [#admins-and-delegated-admin-powers]

Benutzer mit der Rolle `ADMIN` können jede Ressource auf der Instanz einsehen und verwalten sowie die Funktionsberechtigungen jeder Rolle ändern. Außerdem erhalten sie unter **Einstellungen > Allgemein** einen Link zum **Admin-Panel**, sofern eine Admin-Panel-URL konfiguriert ist.

Wenn Sie jemandem einen Teil der Administration übertragen möchten, ohne ihn zu einem vollwertigen Administrator zu machen, vergeben Sie stattdessen eine Berechtigung (Capability), etwa zum Verwalten von Benutzern, zum Verwalten von Gruppen, zum Bearbeiten der Konfiguration (vollständig oder nur einen einzelnen Abschnitt wie `interface`), zum Einsehen der Insights aller Agenten oder zum Moderieren aller Agenten, Prompts, Skills und geteilten Links. Delegierte Administratoren benötigen außerdem die Berechtigung `access:admin`, um sich am Admin-Panel anzumelden. Berechtigungen können einem Benutzer, einer Gruppe oder einer Rolle zugewiesen werden und werden auf der Seite **Grants** des Admin-Panels vergeben. Wer eine „manage“-Berechtigung besitzt, hat automatisch die entsprechende „read“-Berechtigung.

Administratoren können einer Rolle oder Gruppe außerdem eine eigene Konfiguration zuweisen, zum Beispiel zusätzliche Endpoints für eine Forschungsgruppe, die zusätzlich zu `librechat.yaml` gelten. Auch dies erfolgt über das Admin-Panel.

## Einrichtung [#setup]

Die Standardeinstellungen funktionieren ohne jede Einrichtung: Das erste Konto ist der Administrator, alle anderen können die Anwendung nutzen, aber nicht teilen. Um die Funktionsstandards über `librechat.yaml` zu ändern, die Auswahl der Personensuche einzuschränken, Entra-ID-Gruppen zu synchronisieren, einen weiteren Administrator zu ernennen oder eine Instanz zu migrieren, die von einer Version vor v0.8.0-rc3 aktualisiert wurde, siehe [Access Control configuration](/docs/configuration/access_control). Benutzerdefinierte Rollen, Gruppen, Berechtigungen und gruppenspezifische Konfigurationen erfordern das [Admin Panel](/docs/features/admin_panel).
