Model Context Protocol (MCP) is een open protocol dat standaardiseert hoe applicaties context bieden aan Large Language Models (LLMs). Zie MCP als de **"USB-C van AI"** - net zoals USB-C een universele verbindingsstandaard biedt voor elektronische apparaten, biedt MCP een gestandaardiseerde manier om AI-modellen te verbinden met diverse tools, databronnen en services.

LibreChat maakt gebruik van MCP om de mogelijkheden van uw AI-agents aanzienlijk uit te breiden, waardoor u alles kunt integreren, van bestandssysteemtoegang, webbrowsers en gespecialiseerde API's tot aangepaste zakelijke tools.

## Waarom MCP belangrijk is [#why-mcp-matters]

LLMs zijn beperkt tot hun ingebouwde mogelijkheden. Met MCP doorbreekt LibreChat deze muren door:

- **Verbinding maken met elk hulpmiddel of elke dienst** die een MCP server aanbiedt
- **Standaardisatie van integraties** zodat je de code van LibreChat niet voor elke tool hoeft aan te passen
- **Ondersteuning voor omgevingen met meerdere gebruikers** met de juiste authenticatie en isolatie
- **Servers toevoegen en bijwerken tijdens runtime** vanuit het MCP Settings-paneel, zonder een configuratiebestand te bewerken of opnieuw op te starten

## Hoe MCP werkt in LibreChat [#how-mcp-works-in-librechat]

LibreChat biedt twee manieren om MCP servers te gebruiken, hetzij in het chatgedeelte of met agents.

Je kunt MCP-servers handmatig configureren in je `librechat.yaml` bestand of [smithery.ai](https://smithery.ai) gebruiken om MCP-servers te vinden en te installeren in `librechat.yaml` ([zie onderstaand voorbeeld](#basic-configuration)). Elke keer dat je een server toevoegt of bewerkt in `librechat.yaml`, moet je LibreChat herstarten om de verbindingen te initialiseren. Servers die via het [MCP-instellingenpaneel](#adding-mcp-servers-in-the-ui) zijn toegevoegd, worden zonder herstart van kracht. Een via het paneel aangemaakte server die OAuth gebruikt, wordt bij het opslaan geregistreerd, maar start in een niet-verbonden status: [authenticeer deze](#step-3-check-connection-status-and-authenticate) eenmaal om verbinding te maken.

### OAuth Callback URL [#oauth-callback-url]

Voor MCP-servers met OAuth-ondersteuning is de LibreChat callback-URL:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>` is de sleutel die wordt gebruikt onder `mcpServers` in `librechat.yaml` of de servernaam die is aangemaakt in de MCP Settings UI. Bijvoorbeeld, een server genaamd `salesforce` met `DOMAIN_SERVER=https://chat.example.com` gebruikt `https://chat.example.com/api/mcp/salesforce/oauth/callback`.

Registreer deze exacte callback-URL bij de OAuth-provider. Lokale Docker-installaties gebruiken meestal `http://localhost:3080` als de basis-URL.

### In het chatgebied [#in-chat-area]

![De MCP Servers catalogus geopend vanuit het composer palet, met de verbindingsstatus van elke server](/images/mcp/mcp_servers_catalog.png)

LibreChat geeft geconfigureerde MCP-servers direct weer in het chatgedeelte bij gebruik van traditionele endpoints (OpenAI, Anthropic, Google, Bedrock, enz.):

- Selecteer eerst een niet-agent endpoint en een model dat compatibel is met tools
- MCP-servers verschijnen in de sectie **MCP Servers** van het [**+** palet van de composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers), en elke geselecteerde server wordt weergegeven als een chip in de composer
- Wanneer geselecteerd, worden alle tools van die server beschikbaar voor je huidige model
- Snelle toegang tot MCP tools zonder een agent aan te maken, waardoor meerdere servers tegelijkertijd kunnen worden gebruikt

Om een MCP server buiten de reguliere chatselectie te houden, stelt u [`chatMenu: false`](/docs/configuration/librechat_yaml/object_structure/mcp_servers#chatmenu) in uw configuratie in:

```yaml
mcpServers:
  internal-tools:
    command: npx
    args: ['-y', 'internal-mcp-server']
    chatMenu: false # Not selectable in regular chat
```

Deze instelling wordt afgedwongen bij chatverzoeken en in de kiezer, zodat een verouderde opgeslagen selectie niet kan blijven gebruikmaken van een verborgen server. Het verwijdert de server niet uit opgeslagen Agents of uit een Model Specs die deze expliciet toewijst. LibreChat laat ook servers weg die een gebruiker alleen kan bereiken via een geautoriseerde Agent in de reguliere chatkiezer en het verzoekpad.

### Met Agents [#with-agents]

MCP servers integreren naadloos met LibreChat Agents:

1. Een agent aanmaken of bewerken
2. Open **Add tools** in de Agent Builder en selecteer **MCP**
3. Selecteer een MCP server; elke server verschijnt als een enkel catalogusitem
4. Vouw de geselecteerde server uit om individuele tools in of uit te schakelen
5. Sla je agent op

![MCP Tools in Agent Builder](/images/mcp/mcp_ui_agent.png)

Deze organisatie op hoger niveau houdt de interface overzichtelijk - zelfs servers met meer dan 20 tools (zoals Spotify) verschijnen als enkele items die kunnen worden uitgevouwen voor gedetailleerde controle.

### Basisconfiguratie [#basic-configuration]

Voeg MCP-servers handmatig toe aan je `librechat.yaml` bestand:

```yaml
mcpServers:
  # ClickHouse Cloud
  clickhouse-cloud:
    type: streamable-http
    url: https://mcp.clickhouse.cloud/mcp

  # File system access
  filesystem:
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /path/to/your/documents

  # Web browser automation
  puppeteer:
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'

  # Production-ready cloud service
  business-api:
    type: streamable-http
    url: https://api.yourbusiness.com/mcp
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
    serverInstructions: true
```

LibreChat toont een **Connect** bevestigingsprompt. Controleer de bestemming en selecteer **Continue with OAuth** om de autorisatiepagina van de provider in een nieuw browsertabblad te openen. Voltooi daar het aanmeld- en toestemmingsproces van de provider.

Als een flow die in deze browser is gestart in afwachting is, houdt LibreChat die server in een autoriserende/verbindende status, zelfs als de status van de gecachte verbinding nog steeds **Connected** aangeeft. De prompt mag niet sluiten enkel omdat een oude status een duurzame autorisatie rapporteert; terminale successen, fouten, time-outs of annuleringen beëindigen de lopende flow. Een flow die in een ander tabblad of een andere browser is gestart, heeft in deze weergave geen lokale status in afwachting.

![MCP Server geauthenticeerd en automatisch geselecteerd](/images/mcp/mcp_ui_done.png)

#### Referentievariabelen voor in de UI aangemaakte servers [#credential-variables-for-ui-created-servers]

Wanneer je een MCP server toevoegt via de UI, kun je vereisen dat gebruikers hun eigen API-sleutels opgeven. Selecteer in het gedeelte Authentication van het MCP Server Builder-dialoogvenster "API Key" en vink **"User provides key"** aan. Kies het header-formaat (Bearer, Basic of Custom) en sla de server op.

Achter de schermen maakt LibreChat een bestemmingsgebonden `customUserVars` item aan genaamd `MCP_API_KEY_<hash>` en configureert het de bijbehorende authenticatie-header. De naam wordt automatisch beheerd; gebruikers voeren hun sleutel nog steeds in via het MCP Tool Select Dialog of het MCP Settings paneel. Bestaande servers kunnen de verouderde `MCP_API_KEY` naam behouden zolang hun request boundary ongewijzigd blijft. Dit gebruikt dezelfde UI voor sleutelinvoer als [YAML-gedefinieerde `customUserVars`](#user-provided-credentials).

Het wijzigen van de URL (inclusief pad of query), proxy, transport, autorisatieformaat, aangepaste autorisatie-header of geconfigureerde OAuth-client/bestemming van een via de UI aangemaakte server, vereist dat elke gebruiker een sleutel invoert voor de nieuwe grens. Oude opgeslagen sleutels worden niet doorgestuurd naar die vervangende bestemming. Cosmetische wijzigingen, equivalente genormaliseerde URL's en wijzigingen aan uitgaande URL's die enkel een fragment bevatten, behouden de bestaande sleutel. Gedeelde servers kunnen alleen referentievariabelen oplossen die door hun huidige configuratie zijn gedeclareerd, dus een editor kan niet verwijzen naar een oude gegenereerde naam om een eerdere sleutel te herstellen. Er is geen bulk-migratie van inloggegevens nodig. Upgrade **elke API-replica**, inclusief replica's die server-bewerkingsverzoeken afhandelen, voordat u op deze beveiliging vertrouwt; een oudere writer kan nog steeds een ongebonden configuratie opnieuw aanmaken.

Wanneer een API-sleutel voor een beheerder of gebruiker is geconfigureerd, behandelt LibreChat de server als API-sleutel-geauthenticeerd en slaat het de automatische OAuth-detectie over. Een expliciete OAuth-configuratie krijgt nog steeds voorrang. Als een via de UI aangemaakte API-sleutelserver is opgeslagen door een oudere LibreChat-versie en vast blijft zitten in **OAuth Required**, bewerk en sla de server dan eenmaal op zodat de opgeslagen verbindingsmetadata wordt vernieuwd.

<Callout type="warning">
Om veiligheidsredenen kunnen MCP-servers die via de UI zijn aangemaakt (en uit de database afkomstig zijn) **alleen** `customUserVars` placeholders (`{{VAR_NAME}}`) omzetten. Omgevingsvariabelen aan de serverzijde (`${ENV_VAR}`), gebruikersprofielvelden (`{{LIBRECHAT_USER_*}}`) en OIDC-tokens (`{{LIBRECHAT_OPENID_*}}`) zijn opzettelijk geblokkeerd om ongeautoriseerde toegang tot servergeheimen of gegevens van andere gebruikers te voorkomen. Configureer de server in `librechat.yaml` voor volledige ondersteuning van placeholders.
</Callout>

## MCP Server Management [#mcp-server-management]

LibreChat biedt uitgebreide tools voor het beheren van MCP serververbindingen, inclusief het bijhouden van de verbindingsstatus en ondersteuning voor OAuth-authenticatie en initialisatie in de UI.

### Verbindingsstatus-indicatoren [#connection-status-indicators]

LibreChat toont dynamische statuspictogrammen die de huidige status van elke MCP server weergeven in het **+** palet van de composer en in het instellingenpaneel:

![MCP Server Status Icons](/images/mcp/mcp_server_status_icons.png)

**Status-typen:**

- **Verbonden** (groen tandwiel): Server is verbonden en heeft configureerbare customUserVars
- **OAuth vereist** (amberkleurige sleutel): Server vereist OAuth-authenticatie
- **Verbinding verbroken** (oranje stekker): Serververbinding mislukt of verloren
- **Initialiseren** (blauwe lader): Server is aan het opstarten of opnieuw verbinding aan het maken
- **Fout** (rode driehoek): Server ondervond een fout
- **Annuleren** (rode x): OAuth-flow wordt geannuleerd

### OAuth annuleren vanuit het Agent Tool-dialoogvenster [#cancelling-oauth-from-the-agent-tool-dialog]

In **Agent Builder → Tool Library → MCP server configuration** wordt **Connect** een ingeschakelde **Cancel**-actie terwijl de gedeelde servermanager een annuleerbaar OAuth-proces rapporteert. Dit omvat een lopend proces dat is ontdekt vanuit een ander LibreChat-paneel. Kies **Cancel** om dat proces te stoppen, de lokale OAuth-prompt te sluiten en de lopende automatische toolselectie te wissen. Een laat verbindingsresultaat na annulering koppelt niet automatisch tools in dit dialoogvenster. Je kunt opnieuw **Connect** kiezen voor een nieuwe poging. Initialisatie die niet annuleerbaar is, toont nog steeds de uitgeschakelde bezet-status in plaats van een annuleringsactie.

  **Vanuit het MCP-instellingenpaneel:**

- Klik op een server in de sectie met de serverlijst van het MCP Settings Panel om toegang te krijgen tot de configuratie- en initialisatiebesturingselementen.
- Configureer aangepaste gebruikersvariabelen en klik op de knop Authenticate/Initialize, afhankelijk van het type serverauthenticatie.

  <Video src="/videos/mcp_settings_init.mp4" title="Initialisatie van het MCP-instellingenpaneel" />

Initialisatiefouten maken nu onderscheid tussen een onbereikbare server, ontbrekende `customUserVars`, een OAuth-verbinding die opnieuw moet worden geauthenticeerd, en een algemene initialisatiefout. Gebruik de benoemde ontbrekende variabelen of de herauthenticatie-actie in het bericht voordat je het opnieuw probeert; de server hoeft voor deze gevallen niet langer te worden verwijderd en opnieuw te worden toegevoegd.

Passieve catalogus-loads voegen OAuth-ontdekkingspogingen samen en bouwen deze stapsgewijs af na fouten, zodat een losgekoppelde integratie niet bij elk verzoek opnieuw probeert te ontdekken. Wijzigingen in inloggegevens zijn generatie-afgeschermd over replica's heen, wat voorkomt dat een ouder ontdekkingsresultaat nieuwere authenticatie overschrijft. Operators kunnen het beleid voor begrensd herstel aanpassen onder [`mcpSettings.catalogRecovery`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#catalogrecovery); de standaardinstellingen zijn geschikt voor de meeste implementaties.

Als een Agent expliciet MCP tools verwacht, maar er geen kunnen worden opgelost bij de start van de run, dan beëindigt LibreChat de run met begeleiding over verbinding en toegang in plaats van deze stilzwijgend uit te voeren zonder die tools.

MCP-servers die `notifications/tools/list_changed` uitzenden, kunnen hun toolcatalogus bijwerken zonder dat LibreChat opnieuw hoeft te worden opgestart. LibreChat haalt de huidige lijst op van de live-verbinding, publiceert toegevoegde tools en stopt met het adverteren van tools die de server heeft verwijderd. Bij herverbindingen wordt de catalogus ook gesynchroniseerd voordat de verbinding als gereed wordt beschouwd. Beheerde snapshot-verversingen en cold-server discovery delen één procesbrede gate met drie operaties. Eenmaal toegelaten, blijft elke operatie begrensd door de deadline van de tool-lijst of de per-server discovery, inclusief een eventuele kortere `initTimeout`, zodat traag cataloguswerk geen slot voor onbepaalde tijd kan bezet houden.

Voor streamable HTTP-servers kan een herverbinding kortstondig een HTTP `409` retourneren wanneer de server nog een verouderde standalone SSE-stream voor de oude sessie vasthoudt. LibreChat behandelt dit als tijdelijk, verbreekt de verouderde sessie en bouwt de verbinding automatisch opnieuw op; er is geen actie van de operator nodig wanneer het herstel slaagt. Als de opnieuw opgebouwde verbinding ook faalt, blijft LibreChat de onderliggende verbindingsfout tonen.

LibreChat classificeert Streamable HTTP-antwoorden op basis van het geparseerde `Content-Type` mediatype in plaats van een substring-overeenkomst. Parameters kunnen er niet voor zorgen dat een niet-SSE antwoord verschijnt als `text/event-stream`, dus fouten met betrekking tot de antwoordgrootte worden afgehandeld via het correcte SSE of niet-SSE afhandelingspad.

### Zichtbaarheid van het MCP-instellingenpaneel [#mcp-settings-panel-visibility]

Het MCP Settings Panel verschijnt in de rechterzijbalk wanneer LibreChat MCP-servers detecteert die mogelijk gebruikersinterventie vereisen tijdens hun initialisatie. Het paneel is zichtbaar wanneer een geconfigureerde server aan een van deze criteria voldoet:

- **Aangepaste gebruikersvariabelen**: De server heeft `customUserVars` gedefinieerd die door de gebruiker verstrekte inloggegevens kunnen bevatten
- **OAuth-authenticatie**: Server wordt gedetecteerd als zijnde vereist voor OAuth-authenticatie tijdens het opstarten
- **Handmatige initialisatie**: Server heeft `startup: false` geconfigureerd, wat handmatige initialisatie vereist

## LibreChat-specifieke functies [#librechat-specific-features]

De MCP-implementatie van LibreChat is ontworpen voor zeer configureerbare, praktijkgerichte omgevingen met meerdere gebruikers.

### Gebruikersspecifieke verbindingen [#user-specific-connections]

- Elke gebruiker krijgt zijn eigen geïsoleerde verbinding met MCP servers
- Gebruikersauthenticatie en -rechten worden gerespecteerd
- Persoonlijke gegevens en context blijven privé

### MCP-servers delen [#sharing-mcp-servers]

MCP-servers nemen deel aan het [granulaire toegangscontrolesysteem](/docs/features/access_control) van LibreChat. Naast servers die zijn gedefinieerd in `librechat.yaml` (die worden beheerd door beheerders en worden bestuurd door [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) functie-rechten), hebben door gebruikers gemaakte MCP-servers hun eigen ACL en kunnen ze worden gedeeld met specifieke **gebruikers**, **groepen**, **rollen**, of **openbaar**, op het niveau van Viewer, Editor of Owner.

De `USE`, `CREATE`, `SHARE` en `SHARE_PUBLIC` feature flags onder `interface.mcpServers` bepalen wie überhaupt MCP-servers mag aanmaken en delen. Zie [Access Control](/docs/features/access_control) voor hoe de permissielagen zijn opgebouwd.

### Dynamische gebruikerscontext [#dynamic-user-context]

MCP-servers hebben toegang tot gebruikersinformatie via placeholders in **URL's en headers** (voor SSE- en Streamable HTTP-transports):

```yaml
mcpServers:
  user-api:
    type: streamable-http
    url: https://api.example.com/users/{{LIBRECHAT_USER_USERNAME}}/mcp
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
      X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
      Authorization: 'Bearer ${API_TOKEN}'
```

Beschikbare placeholders zijn onder andere:

- `{{LIBRECHAT_USER_ID}}` - Unieke gebruikers-ID
- `{{LIBRECHAT_USER_EMAIL}}` - E-mailadres van de gebruiker
- `{{LIBRECHAT_USER_ROLE}}` - Gebruikersrol (admin, user, etc.)
- `{{LIBRECHAT_USER_USERNAME}}` - Gebruikersnaam
- En nog veel meer (zie [MCP Servers Configuration](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers) voor de volledige lijst)

YAML-gedefinieerde MCP-servers kunnen ook gebruikmaken van `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}` en `{{LIBRECHAT_BODY_*}}` placeholders. `{{LIBRECHAT_BODY_*}}` waarden zijn request-scoped, dus LibreChat maakt verbindingen aan voor de actieve run, hergebruikt deze bij tool-aanroepen binnen die run, en ruimt ze op wanneer het verzoek eindigt. Request-scoped servers worden uitgesloten van de persistente tool-cache, zodat verzoek-specifieke headers en URL's niet buiten de actieve run worden hergebruikt. Omdat hun tool-lijst niet kan worden opgelost voordat er een chatverzoek bestaat, stelt de Agent Builder één runtime-tools selectie beschikbaar voor de volledige server en lost deze tools op tijdens runtime. Het voltooien van OAuth slaat de autorisatie op, maar stelt de verbinding uit totdat de eerste run de request-context levert. User-, OpenID- en Graph-placeholders zijn user-scoped; HTTP-transports verversen hun opgeloste headers vóór elke tool-aanroep zonder dat ze zelf opnieuw verbinding hoeven te maken.

Vertrouwde operators kunnen `Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'` op een in YAML gedefinieerde externe server gebruiken om het live OpenID-toegangstoken van de gebruiker door te geven. Expliciete MCP OAuth, on-behalf-of uitwisseling en authenticatie via administrator API-sleutels krijgen voorrang. Na een `401` of `403` kan LibreChat de verbinding één keer verversen, maar de geweigerde tool-aanroep wordt nooit automatisch opnieuw uitgevoerd. Zie de [MCP server placeholder reference](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers) voor instructies over configuratie en beveiliging.

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` wisselt het herbruikbare OpenID-toegangstoken van de gebruiker uit via de Microsoft on-behalf-of flow. [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration) stelt de gevraagde, door spaties gescheiden scopes in en is standaard `https://graph.microsoft.com/.default`. Dit staat los van `OPENID_GRAPH_SCOPES`, dat het zoeken naar personen en groepen configureert.

De `{{LIBRECHAT_BODY_PARENTMESSAGEID}}` placeholder wordt ingevuld voor native Agent-chats, OpenAI-compatibele Agents API-aanroepen en legacy Assistants-runs. Open Responses heeft geen equivalent voor de parent-message identiteit en faalt (fails closed) wanneer een MCP-server die waarde vereist. Zie de [MCP server placeholder referentie](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers).

### Serverinstructies [#server-instructions]

`serverInstructions` is een LibreChat-functie die dynamisch geconfigureerde instructies toevoegt wanneer een tool van die MCP-server wordt geselecteerd:

```yaml
mcpServers:
  filesystem:
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem', '/docs']
    serverInstructions: |
      When accessing files:
      - Always check file permissions first
      - Use absolute paths for reliability
      - Handle errors gracefully
```

Opties:

- `true`: Gebruik instructies die door de server worden geadverteerd wanneer deze beschikbaar zijn
- `false`: Schakel instructies uit
- `string`: Gebruik de aangepaste instructies letterlijk (hierboven weergegeven)

LibreChat bewaart deze geconfigureerde declaratie afzonderlijk van instructies die worden opgehaald tijdens het inspecteren van de server. Een `true` declaratie blijft daarom ingeschakeld tijdens inspecties en het opnieuw laden van het cache-register, terwijl een aangepaste string autoritatief blijft.

### Timeout-configuratie [#timeout-configuration]

Voor langlopende MCP-bewerkingen moet u de juiste time-outs configureren voor zowel initialisatie als tool-bewerkingen.

```yaml
mcpServers:
  data-processor:
    type: streamable-http
    url: https://api.example.com/mcp
    initTimeout: 15000 # 15 seconds for server initialization
    timeout: 60000 # 60 seconds for tool operations
```

**Opmerking**: Als bewerkingen nog steeds voortijdig worden afgebroken, controleer dan uw proxyconfiguratie (bijv. nginx, traefik, enz.), aangezien deze verbindingen voortijdig kan verbreken vanwege standaard time-outs.

Wanneer een gebruiker op **Stop** drukt tijdens een Agent tool-aanroep op de voorgrond, stuurt LibreChat het annuleringssignaal voor de run door naar MCP. Voor Streamable HTTP-servers verstuurt de MCP SDK `notifications/cancelled`; de server moet die notificatie respecteren om zijn eigen werk te stoppen. Losgekoppelde achtergrondaanroepen behouden opzettelijk een afzonderlijke levenscyclus en worden niet geannuleerd met de beurt op de voorgrond.

### Door de gebruiker verstrekte inloggegevens [#user-provided-credentials]

Je kunt gebruikers toestaan hun eigen inloggegevens voor MCP servers op te geven via `customUserVars`. Dit maakt veilige, gebruikersspecifieke authenticatie mogelijk zonder inloggegevens op te slaan in configuratiebestanden.

```yaml
mcpServers:
  my-api-server:
    type: streamable-http
    url: 'https://api.example.com/mcp'
    headers:
      X-Auth-Token: '{{MY_API_KEY}}' # Uses the user-provided value
    customUserVars:
      MY_API_KEY:
        title: 'API Key'
        description: "Enter your personal API key from <a href='https://example.com/keys' target='_blank'>your account settings</a>"
```

Gebruikers kunnen deze inloggegevens configureren:

- **Vanuit het Chat-gebied**: Kies **Configure** op de rij van een configureerbare MCP-server in het **+** palet van de composer
- **Vanuit het MCP-instellingenpaneel**: Open "MCP Settings" in het rechterpaneel om inloggegevens voor alle geconfigureerde servers te beheren

#### MCP-servers opnieuw initialiseren met gebruikersreferenties [#reinitializing-mcp-servers-with-user-credentials]

Voor MCP-servers die gebruikersspecifieke inloggegevens vereisen voordat ze kunnen worden gebruikt (bijv. `PAT_TOKEN`'s in [GitHub’s officiële MCP-server](https://github.com/github/github-mcp-server)), stelt LibreChat gebruikers in staat om deze inloggegevens op te geven en vervolgens de MCP-server opnieuw te initialiseren vanuit de UI zonder de volledige applicatie opnieuw op te starten:

1. Wanneer je een MCP selecteert die gebruikmaakt van `customUserVars`, kun je de waarde van een `customUserVar` voor de geselecteerde MCP-server **Opslaan** of **Intrekken** vanuit het MCP-paneel.
2. Nadat je een waarde voor een `customUserVar` hebt opgeslagen, klik je op de knop voor opnieuw initialiseren (een icoon met cirkelvormige pijlen naast elke servernaam in het MCP Panel).
3. LibreChat zal proberen verbinding te maken met de server met behulp van uw opgegeven inloggegevens en u via een toast-melding laten weten of het herinitialisatieproces is geslaagd of mislukt.

> _Tip: Als je weet dat een server inloggegevens vereist die bij de eerste opstart nog niet beschikbaar zijn, kun je `startup: false` toevoegen aan de configuratie. Dit vertelt LibreChat om niet te proberen verbinding te maken met die server totdat deze handmatig opnieuw wordt geïnitialiseerd in de UI._

**Voorbeeld:**

```yaml
mcpServers:
  github-mcp:
    type: streamable-http
    url: 'https://api.githubcopilot.com/mcp/'
    headers:
      Authorization: '{{PAT_TOKEN}}'
    customUserVars:
      PAT_TOKEN:
        title: 'GitHub PAT Token'
        description: 'GitHub Personal Access Token'
    startup: false
```

### OAuth-authenticatie [#oauth-authentication]

LibreChat ondersteunt OAuth-authenticatie voor MCP-servers, volgens de aanbeveling van Anthropic voor veilige MCP-verbindingen. OAuth biedt een gestandaardiseerde, veilige manier om te authenticeren zonder langdurige inloggegevens op te slaan.

#### Ondersteunde OAuth-flows [#supported-oauth-flows]

LibreChat MCP servers ondersteunen OAuth 2.0 met:

- **Authorization Code Flow with PKCE**: Aanbevolen voor maximale beveiliging
- **Client Discovery**: Automatische clientregistratie wanneer ondersteund door de OAuth-provider
- **Refresh Tokens**: Automatische tokenvernieuwing indien beschikbaar
- **Token endpoint discovery**: Vooraf geconfigureerde clients kunnen ontdekken of de provider client-credentials verwacht in de POST-body of in een HTTP Basic-autorisatieheader

In de MCP Builder biedt **Token Exchange Method** de opties **Auto**, **Default (POST request)** en **Basic authorization header**. Auto laat de methode oningesteld zodat LibreChat vertrouwde provider-metadata kan gebruiken, waarbij wordt teruggevallen op Basic-authenticatie wanneer de provider geen methode adverteert.

#### Configuratievoorbeelden [#configuration-examples]

```yaml
mcpServers:
  # Public remote MCP server for PayPal, uses OAuth Client Discovery
  # ❌ Refresh Tokens: you may need to re-authenticate periodically
  # More info: https://developer.paypal.com/tools/mcp-server/
  paypal:
    type: 'sse'
    initTimeout: 150000 # higher timeout to allow for initial authentication
    url: 'https://mcp.paypal.com/sse'

  # Example self-hosted remote MCP server for Spotify, uses OAuth Client Discovery
  # ✅ Refresh Tokens: refreshes token for authentication automatically
  # Hosted on Cloudflare Workers, more info: https://github.com/LibreChat-AI/spotify-mcp
  spotify:
    type: 'streamable-http'
    initTimeout: 150000
    url: 'https://mcp-spotify-oauth-example.account.workers.dev/mcp'
```

#### OAuth-authenticatiestroom [#oauth-authentication-flow]

Wanneer je voor het eerst een MCP-server met OAuth-ondersteuning configureert:

1. **Initiële verbinding**: LibreChat probeert verbinding te maken met de MCP server
2. **Authenticatie vereist**: Als er geen geldig token bestaat, zie je een OAuth-authenticatiestatus voor die server in het **+** palet van de composer.
3. **Start Sign-In**: Selecteer de server om de OAuth-flow te starten
4. **Doorgaan of een ander apparaat gebruiken**: Ga door in de huidige browser, kopieer de autorisatielink of toon een QR-code om deze op een ander apparaat te openen
5. **Browser-omleiding**: Voltooi de authenticatie bij de OAuth-provider
6. **Afhandeling van de return**: LibreChat verwerkt automatisch de OAuth-callback zodra je bent geauthenticeerd
7. **Token Storage**: LibreChat slaat de tokens veilig op voor toekomstig gebruik
8. **Verbinding tot stand gebracht**: Zodra je bent geauthenticeerd, wordt de MCP server verbonden en kun je deze gebruiken in je chat

#### OAuth Callback URL [#oauth-callback-url-1]

Wanneer een MCP server OAuth gebruikt, stelt LibreChat een callback endpoint bloot waarnaar de OAuth-provider doorverwijst na een succesvolle autorisatie.

De callback URL moet dit formaat volgen:

`${baseUrl}/api/mcp/${serverName}/oauth/callback`

Waarbij `${serverName}` de MCP server-sleutel is die is gedefinieerd in uw `librechat.yaml` configuratie. LibreChat handelt de redirect af op dit endpoint, voltooit de token-uitwisseling en koppelt de inloggegevens aan de bijbehorende MCP server.

<Callout type="info" title="Voorbeeld van OAuth Callback URL">
Gezien de volgende MCP server configuratie:

```yaml
mcpServers:
  # Example self-hosted remote MCP server for Spotify, uses OAuth Client Discovery
  # ✅ Refresh Tokens: refreshes token for authentication automatically
  # Hosted on Cloudflare Workers, more info: https://github.com/LibreChat-AI/spotify-mcp
  spotify:
    type: 'streamable-http'
    initTimeout: 150000
    url: 'https://mcp-spotify-oauth-example.account.workers.dev/mcp'
```

De callback URL zou `${baseUrl}/api/mcp/spotify/oauth/callback` zijn.

</Callout>

Let op:

- De callback URL moet exact worden geregistreerd bij de OAuth-provider om de flow te laten werken.
- Andere paden zoals `/api/oauth/callback` of `/api/oauth/openid/callback` zijn niet geldig voor MCP OAuth-flows.

#### Tokenbeheer [#token-management]

LibreChat verwerkt OAuth-tokens op intelligente wijze:

- **Veilige opslag**: Tokens worden versleuteld en veilig opgeslagen
- **Automatische vernieuwing**: Wanneer refresh tokens beschikbaar zijn, vernieuwt LibreChat automatisch verlopen access tokens
- **Stille 401-herstel**: Als een OAuth MCP-verbinding halverwege een sessie een authenticatieweigering ontvangt, coördineert LibreChat één begrensde verversings- en herverbindingspoging per gebruiker en server. Gelijktijdige aanroepers delen dat herstelresultaat voordat LibreChat een nieuwe authenticatieprompt toont.
- **Sessiebeheer**: Elke gebruiker onderhoudt zijn eigen OAuth-sessies voor omgevingen met meerdere gebruikers

Als een opgeslagen Agent-stream opnieuw wordt geladen of hervat terwijl een MCP-autorisatieprompt nog in behandeling is, reconstrueert LibreChat die prompt vanuit de duurzame generatiestatus. Voltooide, geannuleerde, mislukte of verlopen prompts worden niet hersteld.

Opgeslagen OAuth-clients en tokens zijn gebonden aan de MCP server-URL en de OAuth-client/endpoint-instellingen. Het wijzigen van deze instellingen vereist dat gebruikers zich opnieuw authenticeren. Wanneer u een via de UI aangemaakte server bewerkt die een opgeslagen `client_secret` behoudt, moet u het secret opnieuw invoeren bij het wijzigen van een bindingsveld zoals de server-URL, client-ID, autorisatie-URL, token-URL of token-authenticatiemethode.

Bij horizontaal geschaalde implementaties kunnen de status van de OAuth-flow en de gereedheid van gebonden tokens worden afgestemd tussen LibreChat-pods. De UI rapporteert een server pas als gereed nadat de initialisatie na OAuth is geslaagd, zelfs wanneer de callback en de status-poll verschillende pods bereiken. Callbacks van vervangen pogingen worden geweigerd.

Wanneer Redis is ingeschakeld, worden MCP-catalogusgeneraties op applicatieniveau en publicatierevisies gecoördineerd tussen replica's. Redis Cluster-implementaties gebruiken slot-safe catalogussleutels en -updates, waardoor opstartsynchronisatie en `tools/list_changed` verversingen geen Redis-layout met één knooppunt vereisen.

Elke gebruiker wordt gevraagd om te authenticeren met hun eigen OAuth-login wanneer ze voor het eerst een MCP server met OAuth-ondersteuning gebruiken. Dit zorgt ervoor dat verbindings- en authenticatiegegevens uniek zijn voor elke gebruiker, waardoor de beveiliging en privacy in omgevingen met meerdere gebruikers gewaarborgd blijven.

#### OAuth-timing [#oauth-timing]

De voltooiing van MCP OAuth gebruikt zijn eigen, door de server geconfigureerde time-out in plaats van de `initTimeout` van de MCP-server te hergebruiken. Standaard wacht LibreChat maximaal 10 minuten tot een gebruiker de MCP OAuth heeft voltooid en behoudt de flow-status gedurende 15 minuten.

Gebruik deze omgevingsvariabelen wanneer een OAuth-provider of gebruikersworkflow meer tijd nodig heeft:

```bash filename=".env"
MCP_OAUTH_HANDLING_TIMEOUT=600000
MCP_OAUTH_FLOW_TTL=900000
```

`MCP_OAUTH_FLOW_TTL` wordt begrensd om langer te duren dan `MCP_OAUTH_HANDLING_TIMEOUT`, zodat callbacks die dicht bij de deadline liggen hun flow-status nog kunnen vinden. Het polling-venster van de MCP server-card volgt de geconfigureerde handling timeout.

![Gebruikersspecifieke OAuth-authenticatiestroom](/images/agents/mcp_oauth_flow.png)

> Let op: De tokens die worden getoond tijdens het opstarten van de app zijn alleen voor initialisatie op app-niveau en worden niet gebruikt voor individuele gebruikersverbindingen.

Voorbeeld van automatische tokenvernieuwing:

```bash
[MCP][spotify] Access token missing
[MCP][spotify] Attempting to refresh token
[MCP][spotify] Successfully refreshed and stored OAuth tokens
[MCP][spotify] ✓ Initialized
```

#### Best Practices [#best-practices]

1. **Gebruik OAuth indien beschikbaar**: Geef de voorkeur aan OAuth boven API-sleutels voor betere beveiliging
2. **Configureer de juiste time-outs**: Gebruik `MCP_OAUTH_HANDLING_TIMEOUT` en `MCP_OAUTH_FLOW_TTL` voor OAuth-voltooiingsvensters; gebruik `initTimeout` voor serverinitialisatie
3. **Monitor token expiration**: Controleer logs op authenticatieproblemen
4. **Plan voor opnieuw authenticeren**: Sommige providers ondersteunen geen refresh tokens

## Server Transports [#server-transports]

MCP servers kunnen worden geconfigureerd om verschillende transportmechanismen te gebruiken:

**STDIO Servers**

- Werkt goed voor lokale omgevingen met één gebruiker
- Niet schaalbaar voor remote of cloud-implementaties
- De gebundelde MCP SDK beperkt elk individueel STDIO-bericht tot 10 MB. Een groter enkelvoudig resultaat sluit het transport met een foutmelding; deze limiet staat los van de totale grootte van een sessie of stream.

**Server-Sent Events (SSE) Servers**

- Extern transportmechanisme, maar niet aanbevolen voor productieomgevingen

**Streamable HTTP-servers**

- Gebruikt HTTP POST voor het verzenden van berichten en ondersteunt streaming-antwoorden
- Werkt als een onafhankelijk proces dat meerdere clientverbindingen kan afhandelen
- Ondersteunt zowel basisverzoeken als streaming via Server-Sent Events (SSE)
- Performanter alternatief voor het verouderde HTTP+SSE transport
- Ondersteunt correcte multi-user serverconfiguraties

**Voor productieomgevingen** worden alleen MCP-servers met ["Streamable HTTP"-transporten](https://modelcontextprotocol.io/specification/draft/basic/transports/streamable-http) aanbevolen. In tegenstelling tot SSE, dat langdurige verbindingen onderhoudt, biedt Streamable HTTP stateless opties die beter geschikt zijn voor schaalbare implementaties met meerdere gebruikers.

LibreChat loopt voorop bij het implementeren van flexibele, schaalbare MCP server-integraties om diverse gebruiksscenario's te ondersteunen en u te helpen bij het bouwen van de AI-workflows van morgen.
