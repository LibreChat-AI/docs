MCP (Model Context Protocol) is een open standaard om tools beschikbaar te maken voor een model. Een MCP-server kan het model bijvoorbeeld een bestandssysteem, een browser, een database of de interne API van je bedrijf geven, en LibreChat kan elke server gebruiken die het protocol spreekt. Je koppelt servers aan een gewone chat voor snel gebruik, of voegt hun tools toe aan een agent.

## Een server gebruiken in de chat [#use-a-server-in-chat]

Op elk endpoint behalve Agents of Assistants opent u het **+**-palet van de composer (**Bijlagen en tools**) en zoekt u onder **MCP Servers**. Klik op een server om deze voor het gesprek in te schakelen. Die verschijnt als een chip in de composer, en alle tools die de server aanbiedt worden beschikbaar voor het model. Het palet blijft open, zodat u in één keer meerdere servers kunt inschakelen; klik nogmaals op een server, of verwijder de chip ervan, om deze uit te schakelen. Zie [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) voor de rest van het palet.

Het palet toont telkens een paar servers, met voor elke server een gekleurde stip die de status aangeeft. **Alles tonen** op de koptekst **MCP Servers** opent de volledige lijst met een zoekveld en drie weergaven: **Alle**, **Gemaakt door jou** en **Favorieten**.

![Het MCP Servers-dialoogvenster geopend met Show All, met een Github-server gemarkeerd als Disconnected en een Spotify-server gemarkeerd als Needs Auth, met de filters All, Made by you en Favorites](/images/mcp/mcp_servers_catalog.png)

Als de server nog niet is verbonden, start een klik erop de verbinding in plaats van hem meteen te selecteren. Een server die je eigen inloggegevens nodig heeft, opent eerst een dialoogvenster waarin je deze invoert; een server die OAuth gebruikt, stuurt je door naar de aanmeldpagina. Zodra de verbinding tot stand is gebracht, selecteert LibreChat de server voor je.

Kies een model dat tool calls ondersteunt, anders zal het model de tools van de server nooit aanroepen. Agents en Assistants hebben hun eigen toolconfiguratie, dus de modelkiezer is op die endpoints verborgen, en een beheerder kan afzonderlijke servers verbergen in de chat, zodat ze alleen beschikbaar zijn voor agents.

## Een server toevoegen aan een agent [#add-a-server-to-an-agent]

In de Agent Builder klik je op **Toevoegen** naast **Tools** om de **Tool Library** te openen, en filter je vervolgens op **MCP servers**. Wanneer je een server toevoegt, worden de tools die deze aanbiedt weergegeven; behoud de tools die de agent moet hebben en verwijder de overige, of gebruik **Alles selecteren** en **Alles deselecteren**. Een server met tientallen tools neemt in de toollijst van de agent nog steeds slechts één vermelding in beslag.

Elke MCP-tool op een agent heeft ook eigen opties (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Zie [Agents](/docs/features/agents) voor wat ze veranderen.

Sommige servers zijn afhankelijk van waarden die alleen tijdens een chatverzoek bestaan, waardoor hun tools niet vooraf kunnen worden weergegeven. Voor deze servers voegt de Tool Library de volledige server toe en vermeldt dat de tools tijdens de chat tijdens runtime worden opgelost.

Als een agent is ingesteld om MCP-tools te gebruiken en geen van die tools beschikbaar is wanneer een run start (de server is uitgevallen, of je hebt de toegang verloren), stopt de run met een foutmelding waarin je wordt gevraagd de verbinding en je toegang te controleren, in plaats van zonder de tools een antwoord te geven. Als je tijdens een toolaanroep op **Stop** drukt, wordt de aanroep ook op de MCP-server geannuleerd, mits de server annulering ondersteunt.

## Verbindingsstatus [#connection-status]

In het palet en in **MCP Settings** wordt de status weergegeven als een gekleurde stip: grijs wanneer de server niet verbonden is, amberkleurig wanneer je moet inloggen. De volledige status wordt voorgelezen aan schermlezers, en de Tool Library en de **Show All**-lijst schrijven de status voluit uit naast elke server.

- **Verbonden**: klaar voor gebruik.
- **Vereist authenticatie**: de server gebruikt OAuth en je bent niet ingelogd, of je aanmelding is verlopen.
- **Verbinden** / **Initialiseren**: er is een verbindingspoging bezig.
- **Losgekoppeld** of **Fout**: er is geen actieve verbinding, of de laatste poging is mislukt. Gebruik **Verbinden** om het opnieuw te proberen.
- **On-demand**: de server maakt voor elk verzoek afzonderlijk verbinding, dus er is geen permanente verbinding om te rapporteren.
- **Onbekend**: er is nog geen status ontvangen.

Wanneer een verbinding mislukt, vertelt de foutmelding waarom: de server kon niet worden bereikt, er zijn variabelen nodig die u nog niet hebt ingesteld (genoemd in het bericht), of u moet opnieuw inloggen. Los dat op en maak opnieuw verbinding; het is niet nodig de server te verwijderen en opnieuw toe te voegen. Een server kan tijdens het draaien ook tools toevoegen of verwijderen, en LibreChat neemt de nieuwe lijst over zonder herstart.

Verbindingen zijn per gebruiker. Uw OAuth-tokens en opgeslagen inloggegevens worden nooit voor iemand anders gebruikt, en een inactieve verbinding wordt standaard na 15 minuten gesloten en opnieuw geopend de volgende keer dat u de server gebruikt.

## Inloggen met OAuth [#sign-in-with-oauth]

Wanneer een server OAuth vereist, opent het verbinden ervan een **Verbinden**-dialoogvenster. Klik op **Doorgaan met OAuth** om de aanmeldpagina van de provider in een nieuw tabblad te openen, of gebruik **Link kopiëren** of **QR-code tonen** om op een ander apparaat af te ronden. Nadat je de toegang hebt goedgekeurd, toont het tabblad **Authenticatie geslaagd** en sluit het zichzelf, en schakelt de server over naar **Verbonden**.

Terwijl een aanmelding in behandeling is, toont de server een laadindicator; beweeg de muis erover om te annuleren. In de MCP-serverinstellingen van de Agent Builder verandert **Connect** voor hetzelfde doel in **Cancel**. Je hebt 10 minuten om het aanmelden af te ronden voordat de poging verloopt (de beheerder kan dit wijzigen).

Als de provider refresh tokens uitgeeft, vernieuwt LibreChat uw toegang op de achtergrond. Wanneer een server uw token tijdens een sessie afwijst, probeert LibreChat eerst één keer te vernieuwen en opnieuw te verbinden voordat u wordt gevraagd opnieuw in te loggen. Providers die geen refresh tokens uitgeven, vragen u opnieuw in te loggen zodra het token verloopt.

Standaard verschijnt de aanmeldingsprompt zodra je bericht wordt verzonden. Een beheerder kan sommige servers zo instellen dat ze wachten totdat de agent voor het eerst een van hun tools aanroept, zodat je alleen om aanmelding wordt gevraagd wanneer de server daadwerkelijk nodig is.

## Inloggegevens en variabelen [#credentials-and-variables]

Sommige servers hebben van elke gebruiker een waarde nodig, zoals een persoonlijke API-sleutel of een project-ID. Wanneer je een van deze verbindt, vraagt LibreChat om de waarden voordat er verbinding wordt gemaakt. Om ze later te wijzigen, gebruik je **Configure** bij de server in de chatkiezer of in **MCP Settings**. Elk veld heeft **Save** en **Revoke**. Beide sluiten je huidige verbinding met die server, zodat het volgende gebruik verbinding maakt met de nieuwe waarden, en intrekken schakelt de server ook uit in de huidige chat.

Waarden worden per gebruiker opgeslagen en alleen naar de server verzonden waarvoor ze zijn ingevoerd.

## MCP-instellingenpaneel [#mcp-settings-panel]

**MCP-instellingen** in het zijpaneel toont elke server die je kunt gebruiken, met een statusstip op het pictogram van elke server. Afhankelijk van de status van de server bieden de kaarten **Verbinden**, **Opnieuw verbinden**, **Configureren** (voor je variabelen) of **Intrekken** (om je OAuth-tokens te verwijderen). Servers die je mag bewerken, hebben ook **Bewerken**.

## Een server aanmaken via de UI [#create-a-server-from-the-ui]

Als je rol dit toestaat, klik je op **Add MCP** (de **+**-knop) in **MCP Settings** om een externe server te registreren zonder `librechat.yaml` aan te passen of opnieuw op te starten.

<Steps>
<Step>
### Beschrijf de server [#describe-the-server]

Voer een **Name** in, een optionele **Description**, en een icoon als je dat wilt. Vul de **MCP Server URL** in en kies een **Transport**: **Streamable HTTPS** of **SSE**.
</Step>
<Step>
### Kies authenticatie [#choose-authentication]

Onder **Authenticatie**, kies een van:

- **None (Auto-detect)**: LibreChat test de server en schakelt over naar OAuth als de server daarom vraagt.
- **API Key**: voer één gedeelde sleutel in, of vink **Each user provides their own key** aan zodat elke gebruiker de eigen sleutel invoert via **Configure**. Kies het **Header Format**: **Bearer**, **Basic**, of **Custom** met een eigen headernaam.
- **OAuth**: vul de **Client ID**, **Client Secret**, **Authorization URL**, **Token URL** en **Scope** in. Laat de clientvelden leeg als de provider dynamische clientregistratie ondersteunt. **Token Exchange Method** staat standaard op **Auto**, waarbij de methode wordt gebruikt die de provider aangeeft en wordt teruggevallen op een Basic-autorisatieheader; kies **Default (POST request)** of **Basic authorization header** om een van beide af te dwingen.
- **On-Behalf-Of (OBO)**: wordt alleen getoond als een beheerder je die toestemming heeft gegeven, en werkt alleen wanneer LibreChat gebruikers aanmeldt met OpenID Connect (bijvoorbeeld Entra ID). Voer de scopes in die je wilt aanvragen; LibreChat wisselt je OpenID-token in voor een token met die scopes voor de MCP-server.
</Step>
<Step>
### Maak het aan [#create-it]

Vink **Ik vertrouw deze applicatie** aan en klik op **Create**. De server is direct beschikbaar. Voor OAuth-servers toont het volgende dialoogvenster de **Redirect URI** die je bij je OAuth-provider moet registreren, en blijft de server niet-verbonden totdat je eenmaal bent ingelogd.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="Het dialoogvenster Add MCP Server met een ingevulde naam en URL, Transport ingesteld op Streamable HTTPS, en Authentication ingesteld op API Key met Each user provides their own key aangevinkt"
/>

Servers die op deze manier zijn aangemaakt kunnen alleen externe URL's bereiken; lokale `stdio`-servers moeten in `librechat.yaml` worden gedefinieerd. Ze kunnen ook geen serveromgevingsvariabelen of gebruikersprofielplaceholders gebruiken: waarden zoals `${API_TOKEN}` of `{{LIBRECHAT_USER_EMAIL}}` in hun headers worden verwijderd, omdat een gedeelde server ze anders zou ontvangen. Als je later de URL of authenticatie van een server wijzigt, moeten gebruikers die hun eigen sleutel hebben ingevoerd deze opnieuw invoeren, en OAuth-gebruikers moeten opnieuw inloggen. Wanneer je de URL of OAuth-endpoints van een server met een opgeslagen clientgeheim wijzigt, moet je ook het geheim opnieuw invoeren. Als een API-key-server die met een oudere versie is aangemaakt vastzit op **Needs Auth**, open deze dan met **Edit** en sla hem één keer op.

## Een server delen [#share-a-server]

Servers die in de UI worden aangemaakt, behoren toe aan degene die ze heeft aangemaakt. De eigenaar kan er via het dialoogvenster **Bewerken** mee delen met specifieke gebruikers, groepen, rollen of iedereen, als viewer (kan deze zien en gebruiken), als editor (kan deze daarnaast wijzigen) of als owner. Servers die zijn gedefinieerd in `librechat.yaml` zijn beschikbaar voor iedereen die toestemming heeft om MCP te gebruiken. Zie [Access Control](/docs/features/access_control) voor hoe de toegangsniveaus met elkaar worden gecombineerd.

## Serverinstructies [#server-instructions]

Een beheerder kan instructies koppelen aan een server, hetzij de eigen instructies van de server, hetzij aangepaste tekst. Wanneer een gesprek of agent de tools van die server heeft, worden de instructies toegevoegd aan de context van het model. Dit helpt bij servers waarvan de tools alleen zinvol zijn wanneer ze in een bepaalde volgorde worden gebruikt.

## MCP Apps [#mcp-apps]

Sommige servers geven een interactieve weergave terug samen met een toolresultaat. Wanneer MCP Apps is ingeschakeld, toont de toolaanroep een knop **Open app** die de weergave laadt in een gesandboxt frame, en **Close app** verbergt deze weer. Er kunnen maar enkele apps tegelijk open zijn; als je de limiet bereikt, sluit er dan eerst een.

Een app kan niet zelfstandig handelen. Wanneer hij een tool wil uitvoeren, zie je **Run tool from app?**, en wanneer hij een bericht wil plaatsen, **Send message from app?**. Er gebeurt niets totdat je goedkeurt. Het verzenden van een bericht start een modelreactie in het huidige gesprek, waarbij de geselecteerde agent en zijn tools mogelijk worden gebruikt. Apps worden niet weergegeven in gedeelde gesprekken.

## Setup [#setup]

MCP heeft minimaal één server nodig. Beheerders definiëren servers onder `mcpServers` in `librechat.yaml`, wat een herstart vereist om toegepast te worden, en gebruikers met de juiste rechten kunnen externe servers toevoegen vanuit **MCP Settings**. Zie [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) voor serveropties, de OAuth-callback-URL en transports, [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) voor toegestane domeinen en MCP Apps, [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) voor app-limieten, en [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) voor wie servers kan gebruiken, aanmaken en delen. Installatiehandleidingen voor specifieke servers staan onder [MCP Servers](/docs/mcp_servers), en [Agent Plugins](/docs/features/agent_plugins) behandelt het bundelen van MCP-servers met skills.
