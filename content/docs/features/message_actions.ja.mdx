# メッセージアクション [#message-actions]

メッセージアクションは、利用可能な場合に会話のターンの下に表示されます。ユーザーのターンは右寄せの吹き出しを使用し、アシスタントのターンは全幅のレスポンスレイアウトを維持します。ストリーミング中にレスポンスに適用できないアクションは、レスポンスが完了するまで非表示になります。ポインティングデバイスでは、メッセージのメタデータとコントロールはクリックを必要とせず、ホバーまたはキーボードフォーカスによって表示されます。

## 編集と再実行 [#edit-and-rerun]

**Edit**を選択して、ユーザーメッセージまたは編集可能なアシスタントの応答を変更します。エディターには、変更を適用するための2つの方法が用意されています。

- **Save** は、別の応答を生成することなく、既存のメッセージを更新します。
- **Update & rerun** は、編集されたメッセージから新しい兄弟（sibling）レスポンスを作成します。

構造化されたアシスタントの応答では、編集可能なすべてのテキストと推論部分に対して1つのエディタを使用します。ツール呼び出し、エラー、アーティファクト、およびツール呼び出しに付随するテキストは表示されますが、読み取り専用となります。空の編集済みパーツを保存することはできません。

複数のアシスタントパートが変更された場合、再実行せずに編集内容を保存してください。1回の再実行で反映できる編集済みアシスタントパートは1つまでです。複数パートの保存は順番に適用され、エラーが発生する前に保存されたパートは会話に反映されたままとなります。

編集されたユーザーメッセージを再実行すると、そのファイル、選択された手動のSkills、および引用されたコンテキストが保持されます。編集されたアシスタントの応答を再実行すると、その親となるユーザーのターンが、選択された手動のSkillsおよび引用とともに再実行されます。

編集中に `Ctrl`/`Cmd` + `S` を押すと保存、`Ctrl`/`Cmd` + `Enter` を押すと更新して再実行、`Escape` を押すとキャンセルできます。

## コピーとフォーク [#copy-and-fork]

**Copy** は、メッセージテキストをクリップボードにコピーし、サポートされている引用を読み取り可能な参照に変換します。構造化されたアシスタントの応答に対して、LibreChat はユーザーから見えるテキスト部分のみを順番に結合します。推論、ツール呼び出し、エラー、アーティファクト、およびツール呼び出しに付随するテキストは省略されます。このアクションは、ストリーミング中やコピー可能なテキストがない応答では利用できないため、クリップボードの内容が不完全または空の値で置き換えられることはありません。

設定で **Copy messages as rich text** を有効にすると、プレーンなMarkdownとレンダリングされたHTMLの両方をクリップボードに配置できます。これにより、Teams、Outlook、Wordなどのアプリに貼り付ける際、見出し、リスト、テーブル、コードの書式設定を保持できるようになります。

**Fork**を使用して、選択したメッセージから会話を分岐させます。詳細は[Forking Conversations](/docs/features/fork)を参照してください。編集、再実行、継続、フィードバック、読み上げ、およびフォークのアクションが利用可能かどうかは、endpointとメッセージの状態によって決まります。

## 引用の抜粋 [#quote-excerpts]

メッセージ内のテキストを選択し、**Add to chat** を選択すると、引用コンテキストとしてステージングできます。1つのメッセージにつき最大10個の抜粋を添付でき、各抜粋は最大1,500文字までです。LibreChatは、メッセージテキストやファイルとともに、これらの抜粋をMarkdownのブロック引用として送信します。

アクティブなエージェントの実行中、引用された抜粋は **Steer**、**Queue**、**Interrupt** のメッセージに続いて表示され、再接続後も保留中のアクションに関連付けられたままになります。最新のサーバーでは、通常のキュー登録されたフォローアップメッセージも、アプリの再起動やレプリカの引き継ぎを経ても引用された抜粋を保持します。ローリングデプロイ中に古いレプリカが引用されたコンテキストを受け付けられない場合、LibreChat はそれをサイレントに破棄するのではなく、コンポーザーに戻します。手動で選択されたスキルは、実行中のステアリングメッセージに追加されるのではなく、次の完全なターンのために待機状態のまま保持されます。詳細は [Steering and Queued Messages](/docs/features/agents#steering-and-queued-messages) を参照してください。

## コードブロックのアクション [#code-block-actions]

コードブロックには、内容のコピー、[Code Interpreter](/docs/features/code_interpreter) を介したサポート対象コードの実行、またはブロックのローカルファイルとしてのダウンロードを行うアクションが用意されています。ダウンロード時のファイル名は、可能な限りフェンスされた言語を使用します（例: `code.py` や `code.tsx`）。不明な安全な言語ヒントは拡張子となり、ヒントが存在しない、または無効な場合は `code.txt` にフォールバックされます。エラーブロックにはダウンロードアクションは表示されません。

## 長い貼り付けテキスト [#long-pasted-text]

ブラウザローカルの **Paste long text as a file** 設定が有効で、[Upload as Text context uploads](/docs/features/upload_as_text#paste-long-text-as-a-file) が利用可能な場合、2,500文字を超えるクリップボードからの貼り付けは、コンポーザーに入力されるのではなく `pasted-text.txt` という添付ファイルになります。それ以外の場合、貼り付けたテキストはインラインのままとなります。送信前に添付ファイルを選択すると、より大きなダイアログでテキストを編集したり、**Move back into message** を選択してコンポーザーに戻したりすることができます。

LibreChatは、通常のドラフト復元において、貼り付けられたテキストのドラフトとメッセージの来歴を保持します。編集を行うと、置換の準備が整うまで元の添付ファイルが保持され、明示的に**New Chat**を開始すると、他のドラフトとともに貼り付けられたテキストもクリアされます。

## Attachment-Only Turns [#attachment-only-turns]

プレースホルダーテキストを入力せずに、1つ以上のファイルを添付して送信できます。添付ファイルのみのメッセージは、編集や再実行の際にも有効であり、LibreChatはタイトルのコンテキストが必要な場合に添付ファイルのファイル名を使用します。

ファイルが含まれていない空のドラフトは、依然として拒否されます。また、エージェントが一時停止した **Ask User** フォームに回答する際、ファイルはテキストの代わりにはなりません。これは、その応答パスがメッセージの添付ファイルではなく、回答値を受け入れるためです。
