Quando um agente trabalha em um repositório de um workspace de código anexado, o LibreChat encontra o pull request do branch em que o workspace está e o exibe ao lado do chat. Você pode ver se ele está pronto para merge, se as verificações passam e acessá-lo diretamente, sem sair da conversa. Funciona com GitHub, GitLab (onde é chamado de merge request) e Bitbucket Cloud, com um provedor por implantação.

Somente chats que executam código em um workspace anexado podem ter um pull request. Um chat comum, ou um workspace que ainda não informou uma branch, não exibe nada.

## No cabeçalho do chat [#in-the-chat-header]

Em uma tela larga, um chip à esquerda do cabeçalho mostra o ícone do pull request, um pequeno ponto de CI no canto e o título do pull request. Passe o cursor sobre o chip ou dê foco a ele para abrir um cartão com os detalhes. O cartão permanece aberto enquanto o ponteiro ou o foco do teclado estiver dentro dele.

Em uma tela pequena não há chip. Abra o menu de três pontos no cabeçalho e escolha a entrada `PR #number` (`MR !number` no GitLab) para exibir o mesmo cartão em um diálogo.

O cabeçalho se mantém atualizado: ele verifica novamente a cada 20 segundos aproximadamente enquanto as verificações estão em execução ou enquanto o provedor ainda está determinando se a branch pode ser mesclada, e a cada 60 segundos aproximadamente nos demais casos, parando quando o pull request é mesclado ou fechado e não há mais nada em execução.

## Na barra lateral [#in-the-sidebar]

As conversas que têm um pull request recebem o mesmo ícone e o mesmo ponto de CI no final da linha. A linha mantém o título próprio da conversa. Passe o cursor sobre a linha, ou dê foco ou clique na marcação, para abrir o cartão ao lado dela; clicar na marcação não abre a conversa.

  light="/images/pull-requests/side-rows-light.png"

A barra lateral não faz polling. Cada linha está tão atualizada quanto a última vez em que a lista foi carregada, e ela é atualizada quando você volta para a janela e seus dados têm mais de um minuto. Se uma atualização falhar para um pull request que já havia sido encontrado, a marcação permanece e o cartão exibe "Não foi possível atualizar o pull request" com um botão **Tentar novamente**. Uma conversa cujo pull request nunca foi encontrado não exibe nenhuma marcação, mesmo quando a consulta falhou.

## Lendo o cartão [#reading-the-card]

O card exibe `PR #number` (`MR !number` no GitLab), as linhas adicionadas em verde e removidas em vermelho, um link **Open in GitHub**, **Open in GitLab** ou **Open in Bitbucket**, o título e dois selos:

- Estado: Aberto, Conflitos, Rascunho, Mesclado ou Fechado. "Conflitos" substitui "Aberto" quando a branch não pode ser mesclada automaticamente.
- Checks: Passing, Failing, Running ou None. No GitLab, este é o pipeline principal (head pipeline), e somente se ele tiver sido executado para o commit atual. No Bitbucket, são os status de commit.

A cor do ícone e o ponto de CI resumem a mesma informação de relance:

| Pull request | Ícone | Ponto de CI |
| ------------------------------------ | ------- | --------------- |
| Aberto, pode ser mesclado | Verde | Dos checks |
| Aberto, mergeabilidade ainda não conhecida | Neutro | Dos checks |
| Aberto, com conflitos de merge | Vermelho | Dos checks |
| Rascunho | Neutro | Dos checks |
| Mesclado | Roxo | Nenhum |
| Fechado | Neutro | Nenhum |

O ponto é verde para verificações aprovadas, vermelho para verificações reprovadas e âmbar para verificações em execução. Não há ponto quando o repositório não informa nenhuma verificação. Uma verificação reprovada tem prioridade sobre uma que ainda está em execução.

## Qual pull request você vê [#which-pull-request-you-see]

O workspace informa o repositório, a branch e o commit em que o chat foi executado pela última vez, e o LibreChat procura um pull request dessa branch:

- Se a saída de comando do próprio chat exibir um link para um pull request no mesmo repositório (por exemplo, a URL que `gh pr create` imprime), esse pull request será usado, desde que venha da branch do chat.
- Caso contrário, pull requests abertos para a branch têm preferência sobre os fechados, de modo que um pull request antigo e fechado em um nome de branch reutilizado não oculta o atual.
- Um pull request só é considerado válido se contiver o commit em que o chat foi executado pela última vez. Excluir uma branch e reutilizar o seu nome não restaura o pull request antigo.
- Uma branch nova, sem commits, não corresponde a nada.

Repositórios que o servidor não tem permissão para consultar se comportam exatamente como repositórios sem pull request: nenhuma marcação e nenhum erro.

## Conecte sua própria conta [#connect-your-own-account]

Se o seu administrador tiver configurado, você pode consultar pull requests com a sua própria conta do GitHub, GitLab ou Bitbucket. Abra **Settings**, vá até **Account** e, em **Connected accounts**, clique em **Connect** ao lado de **Pull request account**. Uma janela de login será aberta no provedor; aprove-a e a linha exibirá **Connected**. Se a janela não abrir, permita pop-ups para o LibreChat e tente novamente.

Depois de conectado, as consultas usam a sua conta, então você vê pull requests em qualquer repositório que possa ler, sob o seu próprio limite de taxa. **Desconectar** remove a conexão, e você pode conectar novamente a qualquer momento. Se o servidor não conseguir atualizar a sua conexão (por exemplo, quando o provedor está indisponível), os seus pull requests aparecem como indisponíveis, em vez de trocar silenciosamente para o token do servidor. Se você revogar o aplicativo no provedor, o LibreChat remove a conexão e você volta ao estado não conectado.

Se a linha disser **Not in use**, seu administrador desativou as conexões de conta e as consultas não utilizam mais sua conta. Clique em **Disconnect** para remover a conexão armazenada.

## Configuração [#setup]

A funcionalidade vem ativada por padrão, mas permanece oculta até que um administrador forneça ao LibreChat um token e uma lista de repositórios que ele pode consultar, ou configure um aplicativo para que os usuários possam conectar suas próprias contas. Ela também exige um workspace de código anexado que informe a sua branch do git. Consulte [Configuração de Pull Requests](/docs/configuration/pull_requests).
