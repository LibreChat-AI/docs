Insights is a dashboard for answering "who is using this agent, and how much?". It counts conversations, users, messages, and tokens for the agents you are allowed to review, and lists the people and recent conversations behind those numbers. It is off by default and meant for admins and agent owners, not every user.

## Opening the dashboard

When Insights is enabled and you can review at least one agent, **Insights** appears in the sidebar (and in the panel switcher on mobile). If you cannot review any agent, the entry does not show up.

Who can review which agents:

- Users with the `ADMIN` role, and anyone granted the `read:insights` capability, see every agent.
- Everyone else sees only the agents on which they have both access to the agent and the **View insights** permission.

**View insights** is a separate toggle in an agent's share dialog. Only admins see it and can turn it on, it is not part of the Viewer, Editor, or Owner roles, and it cannot be given to everyone. In multi-tenant deployments, each account only sees agents and data from its own tenant.

Insights shows user names, email addresses, conversation IDs, and the first message of recent conversations. Treat **View insights** and `read:insights` as access to that data, not just to charts.

## Reading the numbers

Pick a range with **24h**, **7d** (the default), or **30d**, or choose your own start and end date, up to 30 days apart. The agent picker starts on **All agents**; you can narrow it to specific agents, and search by name when you have more than ten.

The four cards at the top cover the selected range and agents, each with a small chart per day:

- **Conversations**: conversations with those agents created in the range.
- **Unique users**: users with saved messages in those conversations.
- **Messages**: user and assistant messages saved in those conversations.
- **Tokens**: the token counts recorded on those messages. This is not a cost figure.

Below them:

- **Top users** lists up to eight people with the most messages, with their chat and message totals.
- **Churned users** lists up to eight people whose last message to any selected agent turned 28 days old during the range, which is a quick way to spot who stopped coming back.
- **Latest conversations** is a paged table (10 per page) with the date, the user, the first message, and message and token counts. **Search by chat id or user** filters this table once you type three characters; the cards and user lists above it keep showing the whole range.

## What it does and does not count

Insights reads the conversations, messages, and users already in LibreChat's MongoDB database. There is no separate analytics store, so anything deleted, and temporary chats once they expire, are gone from Insights too. It is not connected to Langfuse traces or to balance and billing data.

## Setup

An admin turns it on with `ENABLE_INSIGHTS=true` and a restart; after that, admins have access right away and can hand it to others with `read:insights` or the **View insights** toggle. See [Admin Insights configuration](/docs/configuration/access_control#admin-insights).
