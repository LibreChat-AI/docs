Admin Insights is an opt-in dashboard for reviewing how Agents are used, from activity stored in the deployment's primary MongoDB. It reports conversations, unique users, persisted messages, and recorded tokens over time for the Agents the viewer can see, with top-user, churn, and recent-conversation views.

## Enable Insights

Set `ENABLE_INSIGHTS=true` in `.env`, then restart LibreChat:

```sh filename=".env"
ENABLE_INSIGHTS=true
```

When enabled for an account that can see at least one Agent's insights, **Insights** appears in the desktop sidebar and mobile panel switcher. When disabled, the access and data routes return `404` and the navigation item stays hidden.

## Access Requirements

Which Agents a signed-in account can review depends on who it is:

- Accounts with the `ADMIN` role see all Agents.
- Accounts that hold the `read:insights` system capability see all Agents.
- Everyone else sees only the Agents on which they hold both **VIEW** and **View insights** through the Agent's access list.

`GET /api/insights/access` returns `403` only when no Agent is accessible to the account, and the dashboard routes return `403` when a request names an Agent outside that set.

Only administrators can grant **View insights** on an Agent. It is a separate toggle in the Agent's share dialog that other users do not see, and it cannot be granted to public principals. Administrators always have access. Use the [Admin Panel](/docs/features/admin_panel) to assign the `read:insights` capability, and see [Access Control](/docs/features/access_control) for the permission bits.

Every Insights query derives tenant scope from the authenticated account. Tenant accounts only see Agents and records for their own tenant; an account without a tenant sees only unscoped records.

<Callout type="warning" title="Sensitive operational data">
  Insights can display user names and email addresses, conversation IDs, and the first message from
  recent conversations. Grant `read:insights` or **View insights** only to people who should review this data.
</Callout>

## Dashboard Metrics

Metrics are scoped to conversations with the Agents the viewer can see, narrowed by the Agent filter. The four summary metrics and their daily sparklines use the selected date range:

- **Conversations:** conversations with the selected Agents created in the range
- **Unique users:** users represented by matching persisted message activity in those conversations
- **Messages:** persisted user and assistant messages in those conversations
- **Tokens:** the sum of recorded message `tokenCount` values

The dashboard also includes:

- **Top users:** up to eight users ordered by message count, with their conversation and message totals
- **Churned users:** up to eight users whose latest message sent to any selected Agent became 28 days old during the selected range
- **Latest conversations:** paginated conversations with date, owner, first message, persisted message count, and recorded tokens

These are database activity metrics, not billing or Langfuse analytics. Token totals depend on the values persisted with messages and do not calculate monetary cost.

## Date Ranges and Search

The default range is seven days. Presets cover the last 24 hours, 7 days, or 30 days. A custom range can span at most 30 calendar days and is grouped in the browser's current time zone.

The Agent filter uses explicit checkboxes with a fixed **All agents** control for selecting or clearing every accessible Agent. When more than ten Agents are available, search filters names case-insensitively without dropping selections outside the current results.

Recent-conversation search matches a conversation ID or user identity. Search starts at three characters, accepts up to 200 characters, and keeps the latest-conversation table paginated at 10 rows per page. Summary cards, top users, and churn metrics continue to represent the selected date range rather than the search result subset.

## Data and Deployment Notes

Insights queries the existing Conversation, Message, and User collections directly and requires no separate analytics database. Results reflect persisted records only: temporary or deleted data that is no longer in MongoDB cannot appear. The API bounds custom ranges, result lists, page sizes, search input, and tenant scope before running its aggregations.

See [`ENABLE_INSIGHTS`](/docs/configuration/dotenv#admin-insights) for the deployment switch.
