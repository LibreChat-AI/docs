Vous pouvez ajouter des paramètres de requête à l'URL d'une conversation pour choisir l'endpoint et le modèle, charger un agent ou une spécification de modèle, pré-remplir le prompt ou modifier les paramètres du modèle avant le début de la conversation. C'est ainsi que vous créez un signet, un raccourci de lancement (Raycast, Alfred, un mot-clé de navigateur) ou un lien depuis une autre application qui amène directement quelqu'un vers la configuration appropriée.

```
https://chat.example.com/c/new?endpoint=anthropic&model=claude-sonnet-4-5&prompt=Summarize%20this%20article
```

Les paramètres fonctionnent sur une nouvelle conversation (`/c/new`) comme sur une conversation existante (`/c/<conversation-id>`). Une fois que LibreChat les a lus, il les supprime de la barre d'adresse, de sorte que le rechargement de la page ne les réapplique pas.

## Choisir l'endpoint et le modèle [#pick-the-endpoint-and-model]

`endpoint` et `model` ensemble constituent la combinaison la plus prévisible.

- `endpoint` seul bascule vers cet endpoint et utilise le modèle que vous avez sélectionné en dernier pour celui-ci, ou le premier modèle de sa liste.
- `model` seul change le modèle au sein de l'endpoint actuel, si celui-ci le propose.

Les valeurs d'endpoint intégrées sont `openAI`, `azureOpenAI`, `google`, `anthropic`, `bedrock`, `agents`, `assistants` et `azureAssistants`. Pour un [endpoint personnalisé](/docs/quick_start/custom_endpoints), utilisez le nom défini dans votre configuration ; la correspondance ne tient pas compte de la casse, donc `endpoint=openrouter` trouve un endpoint nommé `OpenRouter`.

## Charger un agent, un assistant ou une spécification de modèle [#load-an-agent-assistant-or-model-spec]

```
/c/new?agent_id=agent_abc123
/c/new?assistant_id=asst_abc123
/c/new?spec=meeting-notes
```

`agent_id` et `assistant_id` définissent l'endpoint à votre place. `spec` charge une [spécification de modèle](/docs/configuration/librechat_yaml/object_structure/model_specs) par son `name`. Tous les autres paramètres présents dans la même URL sont appliqués par-dessus le préréglage de la spécification. Si votre administrateur impose des spécifications de modèle, incluez `spec` dans chaque lien et attendez-vous à ce que les valeurs propres à la spécification prévalent sur celles de l'URL.

## Remplir ou envoyer le prompt [#fill-in-or-send-the-prompt]

`prompt` (ou le plus court `q`) place le texte dans la zone de message. Si les deux sont présents, `prompt` prévaut.

Ajoutez `submit=true` pour l'envoyer dès que le chat est prêt :

```
/c/new?endpoint=openAI&model=gpt-4o&prompt=Explain%20quantum%20computing&submit=true
```

Si les paramètres demandés ne peuvent pas être appliqués en quelques secondes, le prompt reste dans la zone de message au lieu d'être envoyé. Votre administrateur peut aussi désactiver l'envoi automatique ; dans ce cas, `submit=true` se contente de remplir le prompt, et vous appuyez vous-même sur envoyer.

Les valeurs doivent être encodées en URL. En JavaScript, `encodeURIComponent()` s'en charge :

```js
const url = `/c/new?prompt=${encodeURIComponent('Write a function: def hello()')}`;
// /c/new?prompt=Write%20a%20function%3A%20def%20hello()
```

## Modifier les paramètres du modèle [#change-model-settings]

Chacun de ces paramètres peut être ajouté à l'URL. Chacun ne prend effet que sur les endpoints qui le prennent en charge, et les valeurs sont vérifiées avant d'être appliquées ; toute valeur invalide est ignorée sans générer d'erreur.

| Endpoint | Paramètres |
| --- | --- |
| Tous | `maxContextTokens`, `resendFiles`, `promptPrefix` (instructions personnalisées) |
| OpenAI, Azure OpenAI, personnalisé | `temperature`, `top_p`, `presence_penalty`, `frequency_penalty`, `stop`, `max_tokens`, `reasoning_effort`, `reasoning_summary`, `verbosity`, `useResponsesApi`, `disableStreaming`, `imageDetail` (`low`, `auto`, `high`) |
| OpenAI Responses API | `reasoning_mode` (`standard`, `pro`), `reasoning_context` (`auto`, `current_turn`, `all_turns`) |
| OpenAI, Anthropic, Google | `web_search` (`true`/`false`), `fileTokenLimit` (plafond de jetons pour le contenu des fichiers) |
| Anthropic, Google | `temperature`, `topP`, `topK`, `maxOutputTokens`, `thinking`, `thinkingBudget`, `thinkingLevel` |
| Anthropic | `effort` (`low`, `medium`, `high`, `xhigh`, `max`), `thinkingDisplay` (`auto`, `summarized`, `omitted`, ou `updates` pour uniquement les notes de progression entre les appels d'outils) |
| Anthropic, Bedrock (modèles Anthropic), OpenRouter | `promptCache` (`true`/`false`), `promptCacheTtl` (`5m` ou `1h`) |
| Google | `url_context=true` permet à Gemini de lire les URL présentes dans votre message |
| Bedrock | `region`, `maxTokens`, `temperature`, `topP`, `reasoning_effort` |
| Assistants | `instructions` (remplace les instructions de l'assistant pour cette exécution), `append_current_datetime=true` |

La signification et les valeurs autorisées de chaque champ sont listées dans [champs des préréglages de spécification de modèle](/docs/configuration/librechat_yaml/object_structure/model_specs). Si vous transmettez une valeur que le fournisseur rejette (un `max_tokens` supérieur à la limite du modèle, par exemple), vous obtenez une erreur d'API à l'envoi ; démarrez une **Nouvelle conversation** pour la effacer.

## Définir le mode de couleur [#set-the-color-mode]

Si votre administrateur l'active, `theme=light`, `theme=dark` ou `theme=system` dans un lien définit votre mode de couleur, afin qu'une application qui renvoie vers LibreChat puisse lui transmettre son propre thème. Ce choix est enregistré comme votre préférence jusqu'à ce que vous le modifiiez dans les paramètres.

## Configuration [#setup]

Les paramètres de requête fonctionnent sans configuration. Les administrateurs peuvent empêcher l'envoi automatique de `submit=true` avec [`interface.autoSubmitFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#autosubmitfromurl), et activer le paramètre `theme` avec [`interface.colorModeFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#colormodefromurl).
