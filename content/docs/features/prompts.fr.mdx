Enregistrez les prompts que vous utilisez souvent, comme un modèle de résumé ou un ensemble d'instructions pour un agent. Chaque prompt enregistré conserve ses versions antérieures. LibreChat appelle cela un **groupe de prompts**.

### Variables [#variables]

Utilisez `{{notes}}` pour demander du texte, ou `{{length:3 bullets|5 bullets}}` pour proposer des choix :

```text
Summarize these notes in {{length:3 bullets|5 bullets}}.

Notes: {{notes}}
```

LibreChat vous demande ces valeurs lorsque vous utilisez le prompt dans le chat. Les variables spéciales telles que `{{current_date}}`, `{{current_datetime}}`, `{{iso_datetime}}` et `{{current_user}}` sont remplies automatiquement. Les autres variables restent sous forme de texte littéral si rien ne les remplit.

### Versions et production [#versions-and-production]

Enregistrer une modification crée une nouvelle version. Une version est marquée **Production**. La bibliothèque et le menu `/` utilisent cette version.

| Paramètre de l'éditeur | Ce qui se passe lors de l'enregistrement |
| --- | --- |
| **Éditeur de prompts avancé** désactivé | La liste des versions est masquée. Chaque enregistrement devient Production. |
| Éditeur avancé activé ; **Toujours créer de nouvelles versions de prompt en production** activé | Chaque enregistrement devient Production. Vous pouvez également parcourir les versions antérieures. |
| Éditeur avancé activé ; Production automatique désactivée | Enregistrez une version, puis utilisez **Deploy** pour la passer en Production. |

Ces paramètres s'appliquent à votre navigateur. Désactiver l'éditeur avancé active également automatiquement la Production. Vous pouvez à nouveau modifier ce paramètre en réactivant l'éditeur avancé.

### Production ou une version épinglée ? [#production-or-a-pinned-version]

Choisissez **Production** pour suivre les mises à jour du propriétaire du prompt. Choisissez une version spécifique pour conserver les mêmes instructions jusqu'à ce que vous modifiiez le lien.

![Avant que la version 4 ne soit promue, les deux agents utilisent la version 3. Après la promotion, l'agent qui suit Production utilise la version 4, tandis que l'agent épinglé à la version 3 reste sur la version 3. Les paramètres de cache natifs peuvent retarder la mise à jour de Production.](/images/features/prompts/production-vs-pinned.svg)

Pour les prompts LibreChat, **Production** désigne la révision marquée Production. Pour les prompts Langfuse, il s'agit de la version portant le label `production`.

### Quand les instructions sont résolues [#when-instructions-are-resolved]

L'enregistrement de l'agent vérifie le prompt mais ne copie pas son texte. LibreChat résout le lien à chaque tour de conversation. Les mises à jour natives des prompts peuvent être retardées par le [cache](/docs/configuration/librechat_yaml/object_structure/agents#linkedinstructions) ; les liens Langfuse sont récupérés à chaque fois.

Les variables spéciales fonctionnent comme dans les [instructions d'agent en ligne](/docs/features/agents#instructions-from-a-saved-prompt). Les variables personnalisées, comme `{{notes}}`, ne sont **pas remplies** pour les instructions liées. Le modèle les reçoit sous forme de texte littéral.

<Callout type="warning" title="Si l'invite n'est pas disponible">
  L'agent s'exécute pour ce tour avec des **instructions vides**. Il n'utilise pas son texte intégré enregistré.
  L'agent de mémoire fait exception : il utilise ses instructions par défaut.
</Callout>

## Prompts depuis Langfuse [#prompts-from-langfuse]

Les prompts synchronisés depuis Langfuse affichent une icône de nuage accompagnée de la mention **Géré dans Langfuse**. Vous pouvez les prévisualiser et les utiliser dans LibreChat. Modifiez leur contenu, promouvez des versions et supprimez-les directement dans Langfuse.

Seuls les **prompts texte** Langfuse sont pris en charge. L'ouverture de l'un d'eux récupère son contenu depuis Langfuse sans le mettre en cache. Si vous le supprimez dans Langfuse, son entrée dans la bibliothèque de LibreChat reste en place, mais elle ne peut plus être résolue.

### Liens Langfuse [#langfuse-links]

Un administrateur doit activer la [synchronisation du catalogue de prompts](/docs/configuration/langfuse#prompt-catalog) et les [instructions d'agent Langfuse](/docs/configuration/langfuse#prompts-as-agent-instructions). La liaison est désactivée par défaut. La synchronisation du catalogue doit rester activée pour que les liens enregistrés fonctionnent.

Si la liaison est désactivée, les prompts Langfuse disparaissent du sélecteur du Builder, à l'exception de la sélection enregistrée de l'agent. Le Builder affiche une note sur cette sélection. Le lien reste enregistré, mais l'agent s'exécute sans ces instructions. Réactiver la liaison la restaure sans qu'il soit nécessaire de modifier l'agent.

## Partage et autorisations [#sharing-and-permissions]

Un propriétaire de prompt peut le partager avec des utilisateurs, des groupes ou des rôles en tant que **Viewer**, **Editor** ou **Owner**. Voir [Access Control](/docs/features/access_control).

### Qui peut lier et qui peut exécuter [#who-can-link-and-who-can-run]

| Tâche | Accès requis |
| --- | --- |
| Utiliser la bibliothèque de prompts | La permission `PROMPTS` `USE` de votre rôle et l'accès au prompt. |
| Ajouter ou modifier le lien de prompt d'un agent | `PROMPTS` `USE` et VIEW sur le prompt, ainsi que `AGENTS` `CREATE` pour un nouvel agent ou EDIT pour un agent existant. |
| Conserver ou supprimer un lien ; passer aux instructions en ligne | Les mêmes accès au niveau de l'agent. L'accès au prompt n'est pas vérifié à nouveau. |
| Discuter avec un agent qui utilise un prompt | Accès pour discuter avec l'agent. L'accès au prompt lié n'est pas requis. |
| Partager un prompt | `SHARE` pour des utilisateurs, groupes ou rôles sélectionnés ; `SHARE_PUBLIC` pour tout le monde. |

Un co-éditeur sans accès à l'invite voit **Invite restreinte**. Il peut remplacer le lien ou passer à des instructions en ligne. Il ne peut pas voir sa cible. Un lecteur de type agent ne voit jamais le lien.

Les administrateurs définissent les permissions des rôles dans le [Panneau d'administration](/docs/features/admin_panel) ou dans la [configuration du contrôle d'accès](/docs/configuration/access_control#feature-permissions). Les administrateurs délégués disposant de `manage:prompts` peuvent consulter et lier n'importe quel groupe sans autorisation VIEW distincte. La liaison nécessite toujours `PROMPTS` `USE`.

## Détails et dépannage [#details-and-troubleshooting]

<Accordions type="single" collapsible>
  <Accordion title="Historique des versions, duplication et restauration">
    Modifier le prompt, sa version ou la source des instructions ajoute une entrée à l'historique des versions de l'agent.

    **Dupliquer** et **Rétablir** copient le lien enregistré sans nouvelle vérification d'UTILISATION ou d'AFFICHAGE. Si le nouvel éditeur ne peut pas afficher le prompt, le Builder affiche **Prompt restreint**.
  </Accordion>
  <Accordion title="Ce que signifie le nombre d'utilisations">
    Chaque agent lié ajoute une utilisation une fois son initialisation terminée avec succès. Il s'agit du même compteur que celui utilisé par les cartes de prompts et le menu slash. Les transferts (handoffs) et les sous-agents peuvent ajouter plusieurs utilisations au cours d'un même tour.

    Reprendre une exécution suspendue n'ajoute aucune utilisation supplémentaire. L'agent de mémoire n'ajoute jamais d'utilisation.
  </Accordion>
  <Accordion title="Limitations de l'API de gestion">
    Définissez des liens de prompt dans le Agent Builder. L'API de gestion et sa spécification OpenAPI n'acceptent pas et ne renvoient pas `instructionsPrompt`.

    Modifier `instructions` via cette API ne modifie pas ce qu'utilise un agent lié. Le lien prend la priorité. Les liens Langfuse ne prennent en charge que les prompts textuels ; les groupes de prompts natifs n'ont pas cette restriction.
  </Accordion>
