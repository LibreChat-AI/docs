Ein Subagent ist ein untergeordneter Lauf, den ein Agent mitten in seiner eigenen Arbeit startet. Das Kind erhält ein sauberes Kontextfenster, erledigt die Aufgabe (Suchen, Lesen von Dateien, Aufrufen von Tools) und gibt nur sein Ergebnis zurück. Der Kontext des übergeordneten Agenten bleibt dadurch klein, was wichtig ist, wenn die Zwischenarbeit seitenweise Tool-Ausgaben erzeugt, die der übergeordnete Agent nie sehen muss.

Greife auf Subagenten zurück, wenn sich eine Aufgabe in Teile zerlegen lässt, die jeweils viel Ballast erzeugen: die Recherche zu mehreren Themen, die Prüfung einer Reihe von Dateien oder einen werkzeugintensiven Check vor der eigentlichen Antwort.

## Für einen Agenten aktivieren [#turn-it-on-for-an-agent]

<Steps>
  <Step>
    Im Agent Builder klicken Sie neben **Tools** auf **Add** und fügen **Subagents** aus der Tool-Bibliothek hinzu. Klicken Sie auf das Zahnrad auf der **Subagents**-Karte, um deren Einstellungen zu öffnen.
  </Step>
  <Step>
    Stelle sicher, dass der Schalter **Subagents** (als Beta gekennzeichnet) aktiviert ist. **Allow self-spawn** ist standardmäßig aktiviert: Der Agent kann eine neue Kopie seiner selbst für eine Teilaufgabe starten.
  </Step>
  <Step>
    Optional kannst du unter **Zusätzliche Subagenten** auf **Subagent hinzufügen** klicken, damit der Agent Aufgaben an andere Agenten delegieren kann, die du sehen kannst. Speichere anschließend.
  </Step>
</Steps>

Selbst-Spawning reicht aus, wenn der Agent bereits für die Aufgabe eingerichtet ist und nur einen sauberen Neustart braucht. Füge weitere Agenten hinzu, wenn eine Teilaufgabe ein anderes Modell, andere Anweisungen oder andere Tools erfordert, zum Beispiel ein günstiges, schnelles Modell für Suchen oder einen Reviewer-Agenten mit einer strikten Checkliste. Der übergeordnete Agent wählt sie anhand ihres Namens und ihrer Beschreibung aus. Gib daher jedem Agenten eine Beschreibung, die angibt, wofür er gedacht ist.

Untergeordnete Agenten werden nur dann geladen, wenn der übergeordnete Agent sie tatsächlich auswählt. Das Auflisten mehrerer Agenten kostet daher nichts, solange keiner ausgeführt wird. Ein Agent kann standardmäßig bis zu 10 Subagenten auflisten. Wenn Sie die Selbst-Erzeugung deaktivieren und keine Agenten auflisten, gibt es nichts zu erzeugen, und der Builder weist Sie darauf hin.

### Dateien mit Subagenten teilen [#sharing-files-with-subagents]

Wenn Ihr Administrator dies aktiviert hat, erscheint ein Schalter **Dateien mit Subagenten teilen**. Ist er eingeschaltet, stehen die Dateien, die der aktuellen Nachricht angehängt sind, den Subagenten zur Verfügung, die der übergeordnete Agent startet. Dateien, die ein Subagent in der Sandbox erstellt, bleiben nur für ihn selbst sichtbar, bis er auswählt, welche Versionen er zurückgibt.

## Was du im Chat siehst [#what-you-see-in-the-chat]

Jeder Subagent-Lauf wird in der Antwort des übergeordneten Agenten als kompakte Zeile mit dem Namen und dem Status des untergeordneten Agenten angezeigt: **Agent läuft**, während er arbeitet, und danach **Agent ausgeführt**, wenn er fertig ist. Sie können die Zeile öffnen, um dem untergeordneten Agenten im Seitenpanel für Aktivitäten zu folgen, oder sie ignorieren und die Antwort des übergeordneten Agenten lesen. Ein abgebrochener Lauf zeigt **Agent gestoppt**, ein fehlgeschlagener **Agent fehlgeschlagen**. Im Hintergrund gestartete untergeordnete Agenten (siehe unten) werden stattdessen in einem Block **Agentenaktivität** gruppiert.

## So verhält es sich [#how-it-behaves]

- Das Kind beginnt mit einem eigenen Kontext. Es übernimmt weder den Gesprächsverlauf des Elternelements noch die Tools, die das Elternelement mit der Tool-Suche gefunden hat. Es erhält die Aufgabe, die das Elternelement für es formuliert.
- Token-Verbrauch aus untergeordneten Läufen wird auf Ihr Guthaben angerechnet. Untergeordnete Läufe, die abgeschlossen werden, während der übergeordnete Lauf noch läuft, werden zu den Gesamtwerten des übergeordneten Laufs addiert; losgelöste untergeordnete Läufe, die später abgeschlossen werden, werden separat erfasst.
- Ein untergeordneter Agent, auf den Sie keinen Zugriff mehr haben, wird übersprungen. Einen Agenten, den Sie nicht sehen können, können Sie nicht hinzufügen. Zugriff und die gespeicherte Konfiguration des untergeordneten Agenten werden beim Start erneut geprüft; wenn sich eines von beiden während der Ausführung geändert hat, wird der untergeordnete Agent nicht ausgeführt.
- Jedes Kind behält sein eigenes Modell, seine eigenen Anweisungen, Tools, MCP-Zugangsdaten, Skills, Dateien und seinen eigenen Speicher.
- Das Schrittlimit gilt auch für Subagenten. Ein niedriger Wert für **Max Agent Steps** begrenzt daher auch, wie viel ein Kind-Agent tun kann.
- Subagenten können eigene Subagenten starten, bis zu 5 Ebenen tief.

## Gespeicherte Agenten-Teams [#saved-agent-teams]

Ein übergeordneter Agent kann auch ein gespeichertes Team starten: mehrere Agenten, die miteinander verknüpft sind und als ein kleiner Workflow zusammenarbeiten, etwa ein Rechercheagent, dessen Ergebnisse an einen Prüfagenten weitergegeben werden. Das Team läuft als ein einziges isoliertes Kind-Element, und nur die Antwort des Ergebnisagenten wird an den übergeordneten Agenten zurückgegeben. Ein Team kann bis zu 32 Mitglieder haben. Fehlt ein Mitglied oder ist es für Sie nicht sichtbar, wird das gesamte Team übersprungen, anstatt es nur teilweise auszuführen.

Teams werden über die API definiert, nicht im Agent Builder. Der Builder behält ein Team unverändert bei, wenn Sie die anderen Subagent-Einstellungen des Agenten bearbeiten. Das Format der Definition finden Sie in der [Konfiguration des Agents-Endpunkts](/docs/configuration/librechat_yaml/object_structure/agents#subagents).

## Abgelöste Subagent-Threads [#detached-subagent-threads]

Wenn Ihr Administrator die Ausführung im Hintergrund aktiviert hat, kann der übergeordnete Agent einen Subagenten starten und weiterarbeiten, ohne auf dessen Ergebnis zu warten. Die Arbeit des Kindagenten wird als reiner Lesemodus-Thread gespeichert, den Sie über das Aktivitätsfenster des übergeordneten Agenten aufrufen; er erscheint weder in Ihrer Chatliste noch in der Suche. Sehr lange Verläufe werden gekürzt, und das Fenster weist darauf hin, wenn ältere Aktivitäten nicht angezeigt werden.

### Ein laufendes Kind steuern [#control-a-running-child]

Während ein losgelöstes Kind-Element läuft, gib im Eingabefeld des Aktivitätsbereichs eine Nachricht ein, um es zu steuern:

- **Steer** fügt deine Anweisung am nächsten sicheren Punkt des Kindprozesses hinzu. Dies ist die Standardeinstellung.
- **Queue** hält es für den nächsten Zug des Kindes bereit.
- **Interrupt** stoppt den aktuellen Schritt und wendet die Anweisung an.
- Bei leerem Eingabefeld wird die Senden-Schaltfläche zu **Aufgabe abbrechen**.

Jede Nachricht zeigt an, ob sie angewendet wurde. Wartende Anleitungen können mit **Withdraw** zurückgezogen werden, bevor das Kind sie aufnimmt. Die Anleitung ist auf 4 KB begrenzt. Wenn ein direktes Kind fertig ist, kopiert **Continue in a new chat** dessen Unterhaltung in einen normalen Chat, in dem du weiterarbeiten kannst; der ursprüngliche Thread bleibt schreibgeschützt.

Geteilte Unterhaltungen zeigen nur die Aktivität, die in der Freigabe enthalten ist, ohne jegliche Steuerelemente.

### Automatische Fortsetzung des übergeordneten Elements [#automatic-parent-continuation]

Wenn ein losgelöstes Kind-Element abgeschlossen ist, weckt LibreChat standardmäßig den übergeordneten Agenten auf demselben Branch mit dem Ergebnis auf, angezeigt als einklappbare Aufgabenkarte. Ist der übergeordnete Agent noch beschäftigt, wartet das Aufwecken, bis er wieder verfügbar ist. Abgebrochene Kind-Elemente wecken den übergeordneten Agenten nicht auf, und dies funktioniert nur für gespeicherte Agenten, nicht für solche, die aus einer Model Spec erstellt wurden. Ihr Administrator kann dies deaktivieren; in diesem Fall muss der übergeordnete Agent den Status des Kind-Elements selbst überprüfen.

Kinder, die externe Systeme über die [Agents API](/docs/features/agents_api#event-driven-child-agents) ansteuern, werden genauso angezeigt: als Zeile unter der übergeordneten Nachricht, die dasselbe Panel öffnet.

## Subagents im Vergleich zu Handoffs [#subagents-compared-with-handoffs]

Ein Subagent gibt die Kontrolle an den übergeordneten Agenten zurück: Der übergeordnete Agent stellt eine Frage, der untergeordnete Agent antwortet, und der übergeordnete Agent formuliert die Antwort. Eine [Übergabe (Handoff)](/docs/features/agents#working-with-other-agents) übergibt die Unterhaltung an einen anderen Agenten, der dann selbst antwortet. Verwenden Sie einen Subagenten für eine Teilaufgabe und eine Übergabe, um an einen Spezialisten weiterzuleiten.

## Einrichtung [#setup]

Subagenten sind standardmäßig verfügbar. Administratoren können sie mit der Fähigkeit `subagents` deaktivieren, das Limit pro Agent mit `maxSubagents` erhöhen, die Dateifreigabe aktivieren und getrennte untergeordnete Agenten mit der optionalen Fähigkeit `run_in_background` zulassen. Alle diese Einstellungen finden Sie in der [Konfiguration des Agents-Endpunkts](/docs/configuration/librechat_yaml/object_structure/agents#subagents). Die automatische Fortsetzung des übergeordneten Agenten wird über [`backgroundTasks`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) gesteuert. Subagenten können auch für eine Modellspezifikation aktiviert werden, ohne dass ein gespeicherter übergeordneter Agent vorhanden ist; siehe [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs#subagents).
