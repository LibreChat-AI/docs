title: 网页搜索

LibreChat 的网页搜索功能允许您搜索互联网并检索相关信息，以增强您的对话体验。该功能由三个主要组件组成，它们协同工作以提供全面的搜索结果。

## 快速开始 [#quick-start]

要开始使用网页搜索，请配置搜索提供商和抓取工具。大多数提供商需要 API 密钥；Keenable 在搜索和页面抓取方面无需密钥即可工作，但提供可选密钥以提高其公共速率限制。重排序（Reranking）可以使用 Jina 或 Cohere，也可以通过 `rerankerType: "none"` 禁用。您可以通过以下两种方式配置该堆栈：

<Callout type="warning" title="私有自托管 endpoint">
  默认情况下，Web 搜索、抓取和重排序连接会阻止访问私有地址、回环地址、链路本地地址以及云元数据目标。如果 SearXNG、Firecrawl、Jina 或其他已配置的提供商 endpoint 属于私有地址，请将其确切的主机名和端口添加到 [`webSearch.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) 中。
</Callout>

1. **环境变量**（推荐管理员使用）：
   ```bash
   # Search Provider (choose one)
   SERPER_API_KEY=your_serper_api_key
   # or
   SEARXNG_INSTANCE_URL=your_searxng_instance_url
   SEARXNG_API_KEY=your_searxng_api_key  # Optional
   # or
   TAVILY_API_KEY=your_tavily_api_key
   # or use Keenable keyless; this optional key raises public rate limits
   KEENABLE_API_KEY=your_keenable_api_key

   # Scraper (choose one)
   FIRECRAWL_API_KEY=your_firecrawl_api_key
   # Optional: Custom Firecrawl API URL
   FIRECRAWL_API_URL=your_firecrawl_api_url
   # Optional: Firecrawl API version (v0 or v1)
   # FIRECRAWL_VERSION=v1
   # or
   TAVILY_API_KEY=your_tavily_api_key
   # or use Keenable keyless with the same optional key

   # Reranker (Optional - choose one, or set rerankerType: "none")
   JINA_API_KEY=your_jina_api_key
   # Optional: Custom Jina API URL
   JINA_API_URL=your_jina_api_url
   # or
   COHERE_API_KEY=your_cohere_api_key
   ```

   在不使用环境密钥的情况下使用 Keenable，仍需要在 `librechat.yaml` 中进行提供商选择：

   ```yaml filename="librechat.yaml"
   webSearch:
     searchProvider: keenable
     scraperProvider: keenable
     rerankerType: none
   ```

   请参阅 [完整的 Keenable 配置](/docs/configuration/librechat_yaml/object_structure/web_search#keenablescraperoptions)，了解可选的搜索、抓取和速率限制设置。

2. **用户界面** (如果未设置环境变量):
   - 当用户首次使用网页搜索功能时，系统将提示他们输入所需的 API 密钥。
   - 他们可以选择使用哪种搜索提供商（Serper、SearXNG、Tavily 或 Keenable）、抓取工具以及重排序服务（Jina、Cohere 或不使用）。

用户提供的 Firecrawl 和 SearXNG URL 无法与部署的 API 密钥配对使用。请提供您自己的 URL/密钥对，或由管理员同时进行配置。否则，Firecrawl 将忽略用户可选的 URL 并使用其默认的 endpoint；SearXNG 无法初始化这种混合所有权的配置，因为它必须要求提供 URL。无密钥的 SearXNG 仍然受支持。请参阅 [Credential Ownership](/docs/configuration/librechat_yaml/object_structure/web_search#credential-ownership)。

## 获取 API Keys [#obtaining-api-keys]

每个启用的外部服务都需要其各自的 API key。以下是获取它们的方法：

### 搜索提供商 [#search-providers]

#### Serper [#serper]
1. 访问 [Serper.dev](https://serper.dev)
2. 注册账户
3. 导航至 API Key 部分
4. 复制您的 API key
5. 在环境变量中设置它，或通过 UI 提供它

#### SearXNG [#searxng]
1. 请按照 [Web Search Configuration](/docs/configuration/librechat_yaml/object_structure/web_search#setting-up-searxng) 文档中的设置说明进行操作。
2. 将 `SEARXNG_INSTANCE_URL` 设置为您的实例 URL
3. 如果您的实例需要身份验证，可以选择性地设置 `SEARXNG_API_KEY`。
4. 如果您的实例位于私有地址或回送地址上，请将其确切的 `host:port` 添加到 [`allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) 中，否则 LibreChat 将会阻止该连接。
5. 您可以选择通过 [`searxngSearchOptions`](/docs/configuration/librechat_yaml/object_structure/web_search#searxngsearchoptions) 来调整您的实例所查询的引擎。默认设置仅包含三个引擎，其中包括 DuckDuckGo，它会向大多数自托管实例发送验证码，因此如果搜索结果为空，扩大引擎范围会有所帮助。

#### Tavily [#tavily]
1. 访问 [Tavily](https://app.tavily.com/home)
2. 注册账户
3. 复制您的 API key
4. 在环境变量中设置 `TAVILY_API_KEY` 或通过 UI 提供它。
5. Tavily 既可以用作搜索提供商，也可以用作抓取提供商。

#### Keenable [#keenable]

1. 选择 Keenable 作为搜索提供商、抓取工具，或两者兼顾
2. 公共搜索和获取 endpoint 不需要 API key。
3. 可以选择设置 `KEENABLE_API_KEY` 以提高公共速率限制
4. 仅在需要覆盖搜索 endpoint 时使用 `KEENABLE_API_URL`，仅在需要覆盖页面获取 endpoint 时使用 `KEENABLE_FETCH_URL`

### 抓取工具：Firecrawl [#scraper-firecrawl]

1. 访问 [Firecrawl.dev](https://docs.firecrawl.dev/introduction#api-key)
2. 注册账户
3. 导航至 API Key 部分
4. 复制您的 API key
5. 在环境变量中设置它，或通过 UI 提供它
6. （可选）如果您正在使用自定义的 Firecrawl 实例，您还需要设置 API URL

### 重排序器 (Rerankers) [#rerankers]

#### Jina [#jina]
1. 访问 [Jina.ai](https://jina.ai/api-dashboard/)
2. 注册账户
3. 导航至 API Dashboard
4. 复制您的 API key
5. 在环境变量中设置它，或通过 UI 提供它

#### Cohere [#cohere]
1. 访问 [Cohere Dashboard](https://dashboard.cohere.com/welcome/login)
2. 注册账户
3. 导航至 API Keys 部分
4. 复制您的 API key
5. 在环境变量中设置它，或通过 UI 提供它

## 组件 [#components]

### 1. 搜索提供商 [#1-search-providers]

搜索提供商负责执行初始网络搜索并返回相关结果。

**可用提供商：**
- **Serper**: 一个提供高质量搜索结果的 Google 搜索 API
  - 从 [Serper.dev](https://serper.dev/api-keys) 获取您的 API key
- **SearXNG**：开源、自托管的元搜索引擎
  - 自托管您自己的实例
  - 注重隐私的搜索结果
  - 可配置的引擎、结果语言、时间范围和请求超时
- **Tavily**: AI 优化搜索 API
  - 从 [Tavily](https://app.tavily.com/home) 获取您的 API key
  - 支持可配置的搜索深度、主题过滤、域名过滤等功能
  - 也可以作为抓取工具提供商使用
- **Keenable**: 无需密钥的网页搜索，支持可选的高频认证
  - 支持域名受限搜索、结果限制、归属标题和请求超时
  - 也可以作为抓取工具提供商使用

### 2. Scrapers [#2-scrapers]

Scrapers 会从搜索提供商返回的网页中提取实际内容。

**可用抓取工具：**
- **Firecrawl**：一个强大的网页抓取服务，可从网页中提取内容
  - 从 [Firecrawl.dev](https://docs.firecrawl.dev/introduction#api-key) 获取您的 API key。
  - API URL 是可选的（默认为 Firecrawl 的托管服务）

- **Tavily**: 通过 Tavily Extract API 进行批量 URL 提取
  - 使用与搜索提供商相同的 `TAVILY_API_KEY`
  - 支持可配置的提取深度、图像提取和网站图标提取

- **Keenable**: 无密钥页面获取
  - 使用与 Keenable 搜索相同的可选 API 密钥
  - 支持归属标题和请求超时

**计划中的爬虫：**
- **Local Firecrawl**: Firecrawl 的自托管版本
- 其他第三方抓取服务

### 3. Rerankers [#3-rerankers]

Rerankers 会分析抓取的内容，以确定最相关的部分并对其进行重新排序，从而获得更好的结果。

**可用的重排序模型 (Rerankers)：**
- **Jina**: 基于 AI 的重排序服务
  - 从 [Jina.ai](https://jina.ai/api-dashboard/) 获取您的 API key
  - API URL 是可选的（默认为 Jina 的托管服务）
- **Cohere**: 高级重排序服务
  - 从 [Cohere Dashboard](https://dashboard.cohere.com/welcome/login) 获取您的 API key
- **None**: 当 `rerankerType` 设置为 `"none"` 时，跳过重排序。

**计划中的重排序模型 (Rerankers)：**
- **RAG API**: 使用 RAG（检索增强生成）的开源重排序 (reranking)
- 其他第三方重排序服务

## 配置 [#configuration]

### 管理员配置 [#admin-configuration]

管理员可以使用环境变量配置网页搜索功能。YAML 配置允许您为每个组件指定自定义的环境变量名称。

⚠️ **重要提示：切勿将实际的 API 密钥或值放入 YAML 文件中（它们无法生效）——请仅使用环境变量名称。**

```yaml
webSearch:
  # Search Provider Configuration
  serperApiKey: "${CUSTOM_SERPER_API_KEY}"  # ✅ Correct: Using environment variable name
  # serperApiKey: "sk-123..."               # ❌ Wrong: Never put actual API keys here
  # or
  searxngInstanceUrl: "${CUSTOM_SEARXNG_INSTANCE_URL}"  # ✅ Correct: Using environment variable name
  searxngApiKey: "${CUSTOM_SEARXNG_API_KEY}"            # ✅ Correct: Using environment variable name
  # searxngInstanceUrl: "http://..."        # ❌ Wrong: Never put actual URLs here
  # searxngApiKey: "sk-123..."              # ❌ Wrong: Never put actual API keys here
  searxngSearchOptions:                     # Query options, not secrets, so real values belong here
    engines: "google,bing,startpage"
    language: "en"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${CUSTOM_TAVILY_API_KEY}"
  tavilySearchUrl: "${CUSTOM_TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${CUSTOM_TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; keyless by default)
  keenableApiKey: "${CUSTOM_KEENABLE_API_KEY}" # Optional; raises rate limits
  keenableApiUrl: "${CUSTOM_KEENABLE_API_URL}" # Optional search URL override
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${CUSTOM_FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${CUSTOM_FIRECRAWL_API_URL}"
  # firecrawlApiKey: "fc-123..."            # ❌ Wrong: Never put actual API keys here
  # firecrawlApiUrl: "https://..."          # ❌ Wrong: Never put actual URLs here

  # Reranker Configuration
  jinaApiKey: "${CUSTOM_JINA_API_KEY}"
  jinaApiUrl: "${CUSTOM_JINA_API_URL}"
  cohereApiKey: "${CUSTOM_COHERE_API_KEY}"
  # jinaApiKey: "jn-123..."                 # ❌ Wrong: Never put actual API keys here
  # jinaApiUrl: "https://..."               # ❌ Wrong: Never put actual URLs here
  # cohereApiKey: "ch-123..."               # ❌ Wrong: Never put actual API keys here

  # General Settings
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
```

**注意：** YAML 配置应仅包含环境变量名称（格式为 `${VARIABLE_NAME}`）。这种灵活性实现了：
- 在不同环境中使用不同的变量名称
- 为不同用户组支持多种配置
- 未来与基于角色的配置的集成

如果您想限制系统仅使用特定的服务，您可以指定服务类型：

```yaml
webSearch:
  # ... variable configurations ...
  searchProvider: "serper"    # Only use Serper for search
  # searchProvider: "searxng" # Only use SearXNG for search
  # searchProvider: "tavily"  # Only use Tavily for search
  # searchProvider: "keenable" # Use keyless Keenable search
  scraperProvider: "firecrawl"    # Only use Firecrawl for scraping
  # scraperProvider: "tavily" # Only use Tavily for scraping
  # scraperProvider: "keenable" # Use keyless Keenable page fetch
  rerankerType: "jina"        # Options: "jina", "cohere", "none"
```

### 用户配置 [#user-configuration]

如果管理员尚未配置所有必要的 API 密钥，系统将提示用户通过 UI 提供这些密钥。该界面允许用户：

1. 选择他们偏好的重排序模型（Jina、Cohere 或无）
2. 输入所需服务的 API 密钥
3. 如果需要，请配置 Firecrawl API URL（可选）
4. 如果需要，配置 Jina API URL（可选）
5. 如果需要，配置 Tavily 或 Keenable endpoint 覆盖（可选）

## 使用方法 [#usage]

配置完成后，您可以通过以下两种方式使用网页搜索：

1. **聊天界面**：在[消息编辑器](/docs/features/composer)中打开 **+** 面板并选择 **Web Search**，即可为当前对话开启该功能。开启后，它会以小标签（chip）的形式出现在编辑器上；移除该标签即可将其关闭。如果缺少任何必要的 API 密钥，系统会提示您输入。
2. **Agents**: 在 Agent Builder 中为智能体启用 **Web Search** [capability](/docs/features/agents#agent-capabilities)，以便智能体能够进行网络搜索。

### 网页搜索选项不可见 [#web-search-option-is-not-visible]

没有单独的网页搜索按钮。该选项位于 **+** 面板的 **Tools** 部分，且仅在满足以下所有条件时才会出现：

- 所选的 endpoint 不是 Agents 或 Assistants。Agents 拥有其自带的工具配置，因此对于 agent，您需要在 Agent Builder 中启用 Web Search。
- `web_search` 包含在 [`endpoints.agents.capabilities`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) 中。它是默认包含的，因此仅当您设置自定义列表时才需要关注此项。
- 用户角色拥有网页搜索权限。请在 [Admin Panel](/docs/features/admin_panel) 中进行管理；[`interface.webSearch`](/docs/configuration/librechat_yaml/object_structure/interface#websearch) 仅在启动时为默认的 `USER` 角色进行初始化设置。
- 所选的 Model Specs 未设置 [`hideBadgeRow: true`](/docs/configuration/librechat_yaml/object_structure/model_specs#hidebadgerow)，该设置用于隐藏 **Tools** 部分。

## 注意事项 [#notes]

- 必须配置搜索提供商和抓取工具；可以通过 `rerankerType: "none"` 禁用重排序。
- Firecrawl API URL 是可选的，默认为其托管服务。
- Jina API URL 是可选的，默认为其托管服务。
- Tavily Search 和 Extract API URL 是可选的，默认使用 Tavily 的托管服务。
- 默认情况下，Keenable 搜索和页面获取无需密钥；使用可选密钥可提高公共速率限制。
- `KEENABLE_API_URL` 仅覆盖搜索，而 `KEENABLE_FETCH_URL` 仅覆盖页面获取。
- 搭配 `searchProvider: "keenable"`, `scraperProvider: "keenable"` 和 `rerankerType: "none"` 以实现完全无需密钥的堆栈。
- 安全搜索提供三个级别的内容过滤：OFF (0)、MODERATE (1 - 默认) 和 STRICT (2)
- Tavily 默认不会继承全局 `safeSearch` 设置；仅当您的 Tavily 账户支持 `safe_search` 时，才使用 `tavilySearchOptions.safeSearch`。
- 爬虫超时时间默认设置为 7.5 秒 (7500ms)。
- API keys 可以随时通过 UI 进行撤销。
- 未来的更新将包含更多适用于所有组件的开源、自托管选项
- 计划提供更多的自定义选项，包括：
  - 控制抓取链接的数量
  - 用于抓取的域名允许列表/黑名单
  - 自定义抓取规则和过滤器
  - 高级结果过滤和排序选项
  - 速率限制和请求节流控制
