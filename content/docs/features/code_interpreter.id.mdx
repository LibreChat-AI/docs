## Pendahuluan [#introduction]

API Code Interpreter LibreChat menyediakan cara yang aman dan bebas hambatan untuk mengeksekusi kode dan mengelola file melalui antarmuka API yang sederhana. Baik Anda menggunakannya melalui Agen LibreChat atau mengintegrasikannya langsung ke dalam aplikasi Anda, API ini menawarkan lingkungan sandbox yang canggih untuk menjalankan kode dalam berbagai bahasa pemrograman.

## Memulai [#getting-started]

1. Deploy layanan [code-interpreter](https://github.com/ClickHouse/code-interpreter) (Docker Compose atau Helm, lihat README repositori tersebut)
2. Arahkan LibreChat ke sana dengan `LIBRECHAT_CODE_BASEURL`
3. Konfigurasikan [LibreChat JWT authentication](#self-hosted-jwt-authentication) untuk layanan open-source saat ini, atau atur `LIBRECHAT_CODE_API_KEY` untuk deployment yang kompatibel dengan API-key.
4. Untuk bereksperimen dengan sesi Agent yang *stateful*, gunakan rute Code Interpreter dengan profil `stateful` yang terpisah dan konfigurasikan `LIBRECHAT_CODE_BASEURL_STATEFUL` atau [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) yang telah ditentukan.
5. Mulai jalankan kode dan buat file secara aman melalui Agen LibreChat atau tombol "Run Code"

## Fitur Utama [#key-features]

### Bahasa yang Didukung [#supported-languages]

Jalankan kode dalam berbagai bahasa pemrograman:

- Python, Node.js (JS/TS), Go, C/C++, Java, PHP, Rust, Fortran, Rscript

### Penanganan File yang Mulus [#seamless-file-handling]

- Unggah file untuk diproses
- Unduh output yang dihasilkan
- Manajemen file yang aman
- Pengorganisasian file berbasis sesi

LibreChat memulihkan file percakapan yang direferensikan ke dalam lingkungan Code Interpreter yang dikelola sebelum menjalankan Agent. Jika semua file Code Interpreter yang diperlukan gagal dipulihkan, proses eksekusi akan berhenti sebelum pemanggilan model dan meminta pengguna untuk melampirkan kembali file tersebut alih-alih melanjutkan dengan referensi yang kedaluwarsa. Dalam ruang kerja (workspace) yang dipilih, unggahan obrolan **tidak** disalin ke dalam ruang kerja pengguna, dan alat ruang kerja serta Bash tidak dapat membukanya di sana. Jika worker mengiklankan Programmatic Bash dengan file relay, alat tersebut justru akan melihat unggahan yang dipentaskan di bawah `$LIBRECHAT_CODE_DATA_DIR` selama durasi eksekusinya.

Unggahan Code API pulih dari limit rate `429` dengan mematuhi `Retry-After`, membuka kembali stream sumber untuk setiap percobaan, dan berbagi anggaran tunggu yang terbatas. Administrator dapat menyesuaikan pemulihan per-pengguna dan per-rute dengan [`codeApiUploadConcurrency` dan `codeApiMaxRetryWaitMs`](/docs/configuration/librechat_yaml/object_structure/agents#code-api-upload-recovery).

Ketika input percakapan akan dipasang (mount) pada tujuan sandbox yang sama, LibreChat akan menyelesaikan konflik tersebut sebelum eksekusi. File percakapan bersama ditetapkan sebelum file pribadi Agen; dalam setiap cakupan, penulisan konten terbaru akan mempertahankan tujuan aslinya. Jalur yang berkonflik akan diratakan jika diperlukan atau menerima akhiran yang diturunkan dari identitas, dan jalur `/mnt/data/...` yang telah diselesaikan akan disertakan dalam konteks file Agen. Hal ini juga mencakup unggahan dan output yang dihasilkan yang memiliki nama file yang sama, sehingga satu konflik tidak akan menolak setiap eksekusi Code Interpreter berikutnya dalam percakapan tersebut. Referensi seed duplikat yang tetap merujuk ke tujuan yang sudah diklaim akan dilewati alih-alih menggagalkan seluruh permintaan.

Gambar sandbox ditransfer dalam jendela terbatas. Atur [`LIBRECHAT_CODE_SANDBOX_OUTPUT_MAX_SIZE`](/docs/configuration/dotenv#code-interpreter) agar sesuai dengan `SANDBOX_OUTPUT_MAX_SIZE` milik worker; LibreChat memperoleh jendela gambar aman terbesar dari anggaran tersebut dan dapat mempelajari batas per-layanan yang lebih kecil setelah satu kali pembacaan gagal. Gunakan `LIBRECHAT_CODE_IMAGE_CHUNK_BYTES` hanya jika penggantian jendela (override) yang tepat diperlukan. Artefak yang dihasilkan dan diunduh sebelumnya digunakan kembali dalam permintaan jika memungkinkan, sehingga menghindari pembacaan sandbox lainnya.

Dalam grafik multi-Agent, berikan nama file yang berbeda untuk file yang bersifat pribadi bagi Agent yang berbeda. Setiap Agent menyelesaikan jalur file pribadinya sebelum grafik menggabungkan input mereka, sehingga file pribadi yang benar-benar berbeda yang secara independen mengklaim tujuan yang sama belum dapat diubah namanya secara konsisten pada saat penggabungan; tujuan yang pertama kali di-seed yang akan menang.

### Keamanan & Kenyamanan [#security--convenience]

- Lingkungan eksekusi sandbox yang aman
- Mode isolasi yang kuat (NsJail atau microVM melalui libkrun)
- Tidak diperlukan pengaturan lokal untuk pengguna akhir
- Penyimpanan file berbasis sesi yang terisolasi

### Pemanggilan Alat Secara Programatis [#programmatic-tool-calling]

Programmatic Tool Calling memungkinkan Agen LibreChat untuk merutekan alat MCP yang dipilih melalui sandbox Code Interpreter. Alih-alih meminta model untuk memanggil setiap alat secara langsung, LibreChat menyediakan alat orkestrasi yang didukung oleh Code Interpreter; kode sandbox yang dihasilkan dapat memanggil stub alat yang terdaftar, menggunakan perulangan dan kondisional, memproses hasil antara, dan mengembalikan jawaban akhir.

Sandbox masih belum menerima akses jaringan umum. Panggilan alat (tool calls) diperantarai melalui Code Interpreter Tool Call Server. LibreChat memotong proyeksi kemampuan pemanggil langsung dengan registri tepercayanya, sehingga hanya alat terprogram aktif yang sudah terdaftar untuk Agen tersebut yang dapat dipanggil dan sebuah permintaan tidak dapat memperluas aksesnya sendiri.

Alat terprogram memerlukan Code Interpreter pada Agent. Tombol pengalihnya tetap dinonaktifkan hingga Code Interpreter dipilih, dan menghapus Code Interpreter akan menghapus pilihan terprogram yang ada. LibreChat juga akan menghapus opsi pemanggil terprogram yang kedaluwarsa dari operasi pembuatan, pembaruan, duplikasi, dan pemulihan versi Agent ketika `execute_code` atau alat Code Interpreter tidak tersedia.

Selama eksekusi terprogram, perluas kartu Code Interpreter untuk melihat pelacakan gaya terminal langsung dari panggilan alat internal dengan pratinjau argumen yang dibatasi, status, durasi, dan kegagalan. Pelacakan ini membantu memeriksa program saat dijalankan, tetapi tidak disimpan setelah halaman dimuat ulang.

### Eksekusi Kode Latar Belakang [#background-code-execution]

Eksekusi latar belakang memungkinkan Agen untuk mengirimkan kode atau pekerjaan shell yang berjalan lama dan melanjutkan percakapan. Untuk Agen yang disimpan, penyelesaian khusus konten yang didukung dikirimkan secara otomatis dalam kelanjutan tindak lanjut secara default. `check_background_task` tetap tersedia untuk status eksplisit, kontrol, artefak langsung, dan pemulihan. Dalam obrolan LibreChat, saat pekerjaan selesai, stdout dan file yang dihasilkan muncul pada panggilan kode asli dan dipertahankan untuk giliran berikutnya. Penyelesaian latar belakang dan pemeriksaan eksplisit merender kartu tugas dengan status, status pengiriman, dan hasil yang dapat dibaca; hasil asli yang tepat tetap tersedia untuk disalin. Header obrolan mengelompokkan tugas yang sedang berjalan dan tugas terbaru serta menawarkan kontrol individu atau hentikan-semua jika diizinkan oleh kebijakan pembatalan penyebaran.

Fitur ini bersifat opt-in pada tingkat deployment. Tambahkan `run_in_background` bersama dengan `execute_code` di [kapabilitas endpoint Agents](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), lalu aktifkan Code Interpreter pada agen tersebut. Eksekusi kode dan panggilan shell akan secara otomatis memenuhi syarat untuk dijalankan di latar belakang; nonaktifkan **Background execution** di pengaturan alat Code Interpreter jika agen ingin memilih untuk tidak menggunakannya. Model tetap akan memutuskan per panggilan apakah akan mengirimkan pekerjaan yang memenuhi syarat ke latar belakang.

Eksekusi latar belakang biasa tetap bersifat lokal pada proses dan tidak bertahan jika pekerja aplikasi (app worker) terputus. Setelah hasil terminal yang hanya berisi konten disimpan, pengiriman otomatisnya bersifat persisten dan dapat berlanjut pada replika lain; tugas dengan artefak aktif masih memerlukan polling pada run pemiliknya. Atur [`endpoints.agents.backgroundTasks.completionWakeups: false`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) untuk mewajibkan polling bagi setiap hasil. Pengiriman latar belakang tidak memperpanjang batas eksekusi layanan Code Interpreter; batas waktu sisi server (server-side timeout) normal pada deployment tetap berlaku.

Dengan [`ordinaryToolCancellation: true`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks), pemilik dapat meminta pembatalan kooperatif untuk alat Code latar belakang biasa, termasuk Bash yang dilampirkan. Tugas tersebut tetap aktif dan mengonsumsi kapasitas hingga pemanggilan selesai; alat yang mengabaikan pembatalan mungkin tetap akan berjalan hingga selesai.

### Sesi Kode Stateful [#stateful-code-sessions]

Sesi kode stateful memungkinkan Agen LibreChat untuk menggunakan kembali satu ruang kerja sandbox Code Interpreter di seluruh eksekusi. File, paket yang diinstal, dan status kerja biasanya terbawa, membuat analisis iteratif dan pembuatan file multi-langkah menjadi lebih efisien. Setiap agen memilih satu cakupan ruang kerja:

- **Ruang kerja pengguna (disarankan):** satu ruang kerja untuk pengguna yang masuk di seluruh agen yang mengaktifkan stateful
- **Ruang kerja agen + pengguna:** satu ruang kerja untuk setiap kombinasi pengguna dan agen
- **Ruang kerja percakapan:** satu ruang kerja untuk setiap pengguna dan percakapan

Untuk Agen yang baru dibuat, cakupan awal berasal dari **Settings > Data Controls > Code execution > Default stateful workspace**. Pengaturan pribadi secara default adalah **User workspace**; mengubahnya tidak akan memodifikasi Agen yang sudah ada atau mengaktifkan sesi stateful. Administrator penyebaran dapat membatasi cakupan yang dapat dipilih dengan [`statefulCodeSessions.allowedEnvironments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Jika default pribadi yang disimpan menjadi tidak tersedia, Agen baru akan menggunakan cakupan pertama yang diizinkan; Agen yang sudah diaktifkan dengan cakupan yang kini tidak diizinkan harus dikonfigurasi ulang sebelum dapat dijalankan.

Cakupan ruang kerja terpisah dari backend eksekusinya. Saat administrator mengonfigurasi [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) bernama, Agent Builder akan menambahkan pemilih **Execution environment**:

- **Managed:** Code API stateful yang dioperasikan oleh deployment
- **Dilampirkan:** sebuah bridge jarak jauh Code API yang kompatibel yang menyewakan pekerjaan ke worker `@librechat/code` outbound, seperti VM yang dikelola operator
- **Personal:** pekerja `@librechat/code` yang terikat pada pemilik dan dipasangkan oleh pengguna terotorisasi melalui pengaturan LibreChat
- **Deployment default:** satu lingkungan yang dikonfigurasi yang ditandai sebagai default

<Callout type="warning" title="Sangat eksperimental">
  Stateful Code Sessions saat ini berada dalam tahap eksperimen awal. Perilaku, konfigurasi, karakteristik persistensi, dan integrasi dasarnya dapat berubah secara substansial. Jangan menganggap implementasi saat ini sebagai kontrak produksi yang stabil.
</Callout>

Fitur ini bersifat opt-in. Aktifkan `execute_code` dan `stateful_code_sessions` di [kapabilitas endpoint Agents](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), konfigurasikan rute stateful khusus dengan [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) atau lingkungan bernama, aktifkan Code Interpreter pada agen, lalu nyalakan **Stateful code sessions** dan pilih backend eksekusi serta cakupan ruang kerjanya di bawah pengaturan Lanjutan (Advanced settings).

Permintaan stateful akan gagal (fail closed) jika lingkungan yang dipilih tidak ada, tidak dapat diakses, atau tidak kompatibel; LibreChat tidak akan mengirimkannya ke `LIBRECHAT_CODE_BASEURL` atau secara diam-diam memilih backend bernama lainnya. Ketika tidak ada lingkungan bernama yang dikonfigurasi, `LIBRECHAT_CODE_BASEURL_STATEFUL` tetap menjadi rute stateful. Agen stateless akan terus menggunakan endpoint normal. LibreChat juga mengirimkan `X-CodeAPI-Expected-Profile: stateful`, sehingga layanan khusus tersebut harus mengiklankan profil `stateful`.

Sesi stateful dan stateless tidak berbagi ruang kerja (workspace) yang sama. Ruang kerja stateful dapat diatur ulang kapan saja, terlepas dari cakupan yang dipilih. Dalam lingkungan Code Interpreter yang dikelola, simpan output penting di bawah `/mnt/data`, dan jangan mengandalkan status sesi sebagai penyimpanan permanen. Ruang kerja yang dilampirkan adalah direktori terpisah milik worker; unggahan tidak ditempatkan di sana secara default.

File yang dibuat oleh panggilan `create_file` dan `edit_file` yang stateful akan muncul pada pesan asisten di bawah baris **Workspace changes** yang dapat diperluas. Baris ini mencantumkan setiap jalur yang diubah secara unik untuk respons tersebut dan menyediakan tindakan unduhan terautentikasi. Unduhan menggunakan alur file persisten LibreChat jika tersedia dan fallback Code Interpreter yang aman jika tidak. Baris tersebut merupakan catatan dari output yang dibuat, bukan snapshot workspace yang tahan lama; output stateless akan terus muncul sebagai lampiran inline biasa.

#### Lingkungan terlampir dan pemasangan [#attached-environments-and-pairing]

Attached environments require a matching experimental Code Interpreter remote-bridge build. The bridge remains LibreChat's authenticated policy, queue, and result boundary, while the `@librechat/code` worker connects outbound from the attached machine; the machine does not need an inbound public worker port. LibreChat does not prewarm attached environments.

Operator dapat menyematkan (pin) lingkungan terlampir milik deployment ke satu worker dengan `workerId`, dan dapat menambahkan `pairing.workerId` ketika LibreChat harus mengeluarkan kode pairing administrator untuk rute yang sama. `pairing.tokenEnv` menamai variabel lingkungan yang berisi token administrator bridge; rahasia itu sendiri tidak boleh ada di dalam YAML. Control plane yang dipasangkan (paired) memerlukan HTTPS di luar pengembangan loopback.

Untuk pekerja swalayan (self-service), konfigurasikan control plane terlampir milik deployment dengan `pairing.allowPrincipalWorkers: true` dan `pairing.tokenEnv`. Konfigurasi ini dapat menghilangkan ID pekerja dan hanya ada sebagai control plane pendaftaran; entri semacam itu tidak dapat dipilih untuk eksekusi dan tidak dapat menjadi default deployment.

Pengguna dengan izin pengelolaan Code Environment kemudian dapat membuka **Settings > Code environments**, memberi nama lingkungan, memilih control plane yang disetujui, dan memilih **Connect VM**. LibreChat akan menampilkan perintah `librechat-code pair ...` satu kali pakai yang berumur pendek. Jalankan perintah tersebut pada VM pengguna, lalu mulai `@librechat/code` dengan `LIBRECHAT_CODE_SANDBOX_ENDPOINT` yang mengarah ke layanan sandbox mesin tersebut. UI akan mencantumkan lingkungan pengguna dan dapat mencabut serta menghapusnya nanti; file sandbox akan tetap berada di VM.

Administrator dapat membatasi pendaftaran dengan [`statefulCodeSessions.principalWorkers`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Pendaftaran diaktifkan secara default dengan maksimal lima lingkungan terdaftar per pengguna jika blok ini dihilangkan. Jumlah tersebut mencakup pekerja offline di seluruh control plane. Konfigurasi deployment adalah batas maksimal: konfigurasi khusus principal dapat menurunkannya atau menonaktifkannya, tetapi tidak dapat menaikkannya. Memperketat kebijakan tidak akan mencabut mesin yang sudah terdaftar.

Lingkungan pribadi terikat pada pengguna dan penyewa yang terautentikasi, dilindungi oleh ACL Lingkungan Kode, dan hanya diberikan ID yang divalidasi server serta URL dasar yang disetujui. LibreChat tidak mengekspos token administrator bridge atau URL operator arbitrer kepada klien. Menghapus lingkungan akan mencabut kredensial worker sebelum menghapus entri registri, dan penghapusan pengguna akan menjadwalkan pencabutan serta pembersihan yang sama dengan rekonsiliasi latar belakang untuk upaya yang terputus. Rute worker yang dipilih diterapkan secara konsisten pada Code Interpreter, shell, akses file yang dihasilkan, dan Pemanggilan Alat Terprogram (Programmatic Tool Calling).

Agen yang menggunakan workspace terlampir dapat mencantumkan struktur direktori, membaca file, mencari isi file, membuat atau mengedit file, serta menjalankan Bash pada worker yang dipilih. Sitasi file menggunakan path yang relatif terhadap workspace, file yang dibuat akan muncul di baris **Workspace changes** pada respons, dan kegagalan alat akan tetap mempertahankan diagnostik HTTP terbatas milik worker. Agen juga dapat menyimpan nama dan email Git per-Agen untuk commit yang dibuat di dalam workspace tersebut; nilai-nilai ini hanya mengonfigurasi kepenulisan dan tidak menyediakan kredensial repositori.

Di dalam obrolan, perintah Bash workspace yang dilampirkan dan gagal akan menampilkan kode keluar (exit code), sinyal terminasi, atau timeout-nya, dan stderr-nya diberi gaya yang berbeda dari stdout. Lihat [Activity Groups](/docs/features/agents#activity-groups) untuk mengetahui bagaimana output Bash ditampilkan.

Worker yang terlampir mengiklankan root workspace yang disediakannya. Composer memungkinkan pengguna untuk memilih satu workspace untuk setiap lingkungan terlampir yang dapat dijangkau melalui Agent atau Subagent-nya; satu workspace yang tidak ambigu akan dipilih secara otomatis untuk percakapan baru. LibreChat menyimpan pilihan ini pada percakapan, memvalidasi ulang terhadap worker yang aktif sebelum eksekusi, dan menjaganya tetap terpasang selama jeda persetujuan dan eksekusi yang dilanjutkan. Pengiriman diblokir ketika pilihan yang diperlukan tidak ada atau tidak tersedia, dan LibreChat tidak pernah secara diam-diam mengganti workspace lain. Pada awal eksekusi, LibreChat dapat memuat instruksi repositori dari workspace yang dipilih agar Agent mengikuti panduan repositori tersebut; administrator dapat membatasi penemuan dengan [`repositoryInstructions.timeoutMs`](/docs/configuration/librechat_yaml/object_structure/agents#repositoryinstructions). Alat workspace file dan Bash bawaan dapat menggunakan root yang diiklankan bahkan ketika worker tidak mendukung sesi runtime yang dapat digunakan kembali. Programmatic Bash yang sadar-workspace tersedia pada Code API dan build worker yang kompatibel ketika konfigurasi programmatic-tool Agent mengizinkannya, worker terlampir yang diotorisasi sudah siap dan mengiklankan `programmaticLanguages: ['bash']`, serta workspace dan worker yang dipilih keduanya mengizinkan `execute_command`. LibreChat meneruskan ID workspace yang divalidasi server dan ID instance-workspace percakapan, jika ada, ke alat programatik; argumen model tidak dapat menggantikan pilihan tersebut. Tanpa kemampuan ini, Programmatic Bash dinonaktifkan; gunakan Bash langsung untuk perintah yang sadar-workspace. Ketika worker mendukung relay file, unggahan chat dipentaskan secara terpisah di bawah `$LIBRECHAT_CODE_DATA_DIR` untuk eksekusi programatik, tidak disalin ke dalam workspace yang dipilih. **Stop** membatalkan perintah BYOM yang sedang berjalan dan sadar-sinyal tanpa membatalkan validasi workspace untuk perintah selanjutnya; pekerjaan yang terlepas (detached) mempertahankan siklus hidup pembatalannya sendiri.

Untuk lingkungan eksekusi yang terlampir, Agent Builder dapat menetapkan **Workspace default** ke salah satu root yang saat ini diiklankan. Ini divalidasi terhadap lingkungan yang terlampir tersebut dan digunakan untuk menginisialisasi percakapan baru untuk Agent tersebut. Pilih **Last used** untuk menggunakan preferensi lokal browser pengguna yang masuk untuk Agent dan lingkungan tersebut; ini hanyalah petunjuk kenyamanan, bukan pemberian otorisasi atau pengikatan percakapan. Mengubah lingkungan eksekusi akan menghapus default eksplisit, dan root tersimpan yang tidak lagi diiklankan akan tetap terlihat tetapi tidak dapat dipilih sampai dikonfigurasi ulang.

#### Perubahan ruang kerja obrolan yang disimpan [#saved-chat-workspace-changes]

Secara default, keputusan ruang kerja (workspace) yang dilampirkan pada percakapan yang disimpan akan dikunci. Dengan [`statefulCodeSessions.conversationMoves.enabled`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) diaktifkan, pemilik dapat secara eksplisit berpindah ke ruang kerja lain yang diotorisasi atau memulihkan ruang kerja yang hilang. Pemulihan akan mempertahankan riwayat obrolan, **bukan** file ruang kerja yang hilang. Mengatur `allowAttachDetach: true` juga memungkinkan pemilik untuk melampirkan ruang kerja ke obrolan non-coding yang disimpan atau meninggalkan ruang kerja yang terlampir untuk melanjutkan obrolan normal; mengaktifkan perpindahan saja tidak mengaktifkan fitur lampir/lepas (attach/detach). Transisi ini tidak dapat dilakukan saat pembuatan (generation) sedang berjalan dan divalidasi ulang di server. Tingkatkan semua replika API dan aktifkan `CODE_ENVIRONMENT_DECISION_VERSION=1` sebelum memilih untuk menggunakannya. Tanpa tombol pengalih tersebut, perilaku perpindahan saja dan percakapan terkunci yang sudah ada tidak akan berubah.

Bash yang dilampirkan menggunakan batas waktu 30 detik secara default. Sebuah lingkungan dapat mengekspos anggaran yang dapat diminta model yang lebih besar dengan [`configSchema.limits.maxCommandTimeoutMs`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions), hingga batas protokol lima menit. Batas waktu yang diminta tidak akan pernah melebihi batas penerapan. Administrator dapat membatasi percobaan ulang kapasitas secara terpisah dengan [`configSchema.limits.maxQueueWaitMs`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions); waktu tunggu antrean ini tidak membatalkan perintah yang sudah diterima atau sedang berjalan. Untuk mengizinkan upaya penerimaan **individu** yang lebih lama, gunakan `configSchema.limits.maxRequestTimeoutMs` hanya setelah Code API memenuhi alokasi antrean per-permintaan dan batas waktu proksi terpendek pada rute langsung telah diverifikasi. Opsi `configSchema.limits.minCommandAdmissionMs` mencadangkan 10 detik secara default (berlaku 1–300 detik) untuk penerimaan sebelum perintah. Batas waktu Bash yang diiklankan disesuaikan dengan anggaran permintaan setelah cadangan ini dan tambahan 10 detik untuk penyelesaian dan pengiriman. Anggaran ini tidak menggantikan `maxQueueWaitMs`.

#### Jalur linked-worktree [#linked-worktree-lanes]

Lingkungan yang dilampirkan dapat memilih untuk menggunakan [per-worktree request scheduling](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) dengan `configSchema.workspaces.linkedWorktrees: true`. Pertama, tingkatkan versi LibreChat, lalu terapkan bridge Code API yang kompatibel dan jalankan worker dengan `--linked-worktree-lanes`; aktifkan pengaturan YAML hanya setelah worker tersebut mengiklankan `git_linked_worktree`. Permintaan yang secara struktural menargetkan `.worktrees/<name>/` akan menggunakan lane worktree tersebut tanpa mengubah jalur relatif checkout yang ditampilkan ke Agent. Untuk Bash, teruskan direktori worktree dalam argumen `cwd` alat tersebut; menjalankan `cd .worktrees/<name>` di dalam perintah akan tetap berada di lane root. Operasi checkout-root, tindakan lingkungan, dan instans workspace percakapan juga tetap berada dalam lingkup root. Tanpa opsi ini, semua permintaan akan tetap menggunakan penjadwalan seluruh checkout yang ada saat ini.

#### Pencocokan dan konflik pengeditan Workspace [#workspace-edit-matching-and-conflicts]

`edit_file` menerima `replace_all` tingkat atas untuk penggantian `old_text`/`new_text` tunggal, atau flag per-entri saat batch `edits` diberikan. Tanpanya, setiap `old_text` harus merujuk ke satu lokasi. Batch yang diberikan harus tidak kosong dan valid; LibreChat akan menolak nilai `edits` yang kosong atau cacat alih-alih kembali ke kolom penggantian tingkat atas. Batch string JSON yang valid dan flag penggantian boolean dinormalisasi sebelum persetujuan alat asli, sehingga pratinjau dan eksekusi menggunakan edit kanonik yang sama, termasuk penulisan ulang hook yang telah ditinjau. Edit skill-file dan managed-sandbox mendukung penggantian semua kecocokan dalam batas ukuran dan jumlah kecocokan LibreChat; workspace yang dilampirkan memerlukan worker yang mengiklankan `replace_all` dan menolak permintaan yang tidak didukung sebelum pengiriman.

Pada pekerja (workers) terlampir yang mengiklankan `tolerant_match`, pengeditan dan pratinjau yang dilindungi akan mencoba pencocokan eksak terlebih dahulu, kemudian strategi toleran-spasi untuk spasi tambahan, CRLF, pergeseran indentasi, atau spasi yang dinormalisasi. Administrator dapat mewajibkan pencocokan eksak dengan [`configSchema.edits.tolerantMatching: false`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Pesan keberhasilan akan mengidentifikasi pencocokan non-eksak atau penggantian ganda. Batch yang gagal bersifat atomik: tidak ada yang ditulis, dan LibreChat melaporkan alasan per-edit yang dibatasi, jumlah, nomor baris kandidat, atau peringatan perubahan file tanpa meneruskan teks pekerja atau kutipan file yang arbitrer.

Fitur *attached-worker* ini memerlukan Code API dan *build worker* yang kompatibel yang mengimplementasikan [Code Interpreter #271](https://github.com/LibreChat-AI/code-interpreter/pull/271). LibreChat hanya mengirimkan kolom-kolom baru setelah negosiasi kapabilitas. Dengan *build* yang lebih lama, format permintaan dan perilaku pencocokan tetap tidak berubah; memperbarui LibreChat saja tidak akan mengaktifkan *tolerant attached edits* atau `replace_all`.

#### Izin alat attached-environment [#attached-environment-tool-permissions]

Lingkungan terlampir (attached) dan pribadi (personal) menggunakan kebijakan persetujuan "tanya secara default" (ask-by-default) untuk penulisan file serta eksekusi perintah atau kode. Operasi baca-saja (read-only) dan pencarian tetap berjalan di bawah kebijakan alat reguler penyebaran tersebut. Jika administrator mengekspos salah satu kategori melalui [`configSchema.permissions`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions), pengguna dengan izin manajemen Code Environment dapat memilih di antara nilai **Allow**, **Ask**, atau **Deny** yang diizinkan di bawah **Settings > Code environments**. Pengaturan yang hilang, kedaluwarsa, atau tidak diizinkan akan kembali secara aman ke **Ask**.

Komposer menampilkan **Mode persetujuan kode** tingkat percakapan kapan pun lingkungan terlampir yang dipilih mendukungnya:

- **Ask before changes** meminta konfirmasi sebelum melakukan pengeditan file atau menjalankan perintah.
- **Accept edits** mengizinkan pengeditan file tetapi tetap meminta konfirmasi sebelum menjalankan perintah.
- **Full access** mengizinkan kedua kategori tanpa perintah rutin.

Mode yang dipilih akan terbawa bersama percakapan tersebut dan diiriskan dengan nilai yang diizinkan pada deployment serta kebijakan lingkungan. **Full access** hanya muncul ketika `fileWrite` dan `commandExecution` keduanya mengizinkan `allow`; hal ini tidak melewati isolasi sandbox, pemberian peran, aturan `ask` atau `deny` endpoint yang eksplisit, konfirmasi Skill-file, atau hook persetujuan.

Impor percakapan tidak dapat memilih mode persetujuan Kode untuk penerimanya. Percakapan baru yang diimpor atau disalin secara massal menggunakan preferensi/default penerima berdasarkan kebijakan saat ini; pembaruan massal mempertahankan pilihan apa pun yang disimpan secara lokal. Percakapan yang sudah ada tidak diatur ulang secara retroaktif, dan memilih mode secara eksplisit di LibreChat tetap akan menyimpannya.

Kontrol ini mencakup alat penulisan file, eksekusi shell dan kode, pemeriksaan kompilasi, dan Programmatic Tool Calling. Penulisan ke file Skill persisten masih memerlukan konfirmasi saat penulisan Skill tersedia, bahkan ketika penulisan file biasa diizinkan. Pengaturan ini tidak mengubah isolasi VM, jaringan, mount, eksekusi istimewa (privileged execution), ingress, egress, atau akses rahasia.

Pengaturan eksplisit [`toolApproval.enabled: false`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval) pada deployment adalah penggantian darurat (emergency override) yang menonaktifkan garis dasar ini. Tanpa penggantian tersebut, pemanggil yang tidak dapat menyajikan dan melanjutkan permintaan persetujuan akan gagal secara tertutup (fails closed) alih-alih mengeksekusi alat lingkungan terlampir secara diam-diam.

Pairing mengautentikasi transport pekerja jarak jauh; ini bukan batas sandbox. Jaga endpoint eksekusi lokal pekerja pada loopback atau jaringan pribadi dan gunakan mode isolasi yang sesuai untuk kode yang tidak tepercaya.

Saat eksekusi aktif, panel detail kode dan shell yang diperluas akan mengikuti argumen yang di-stream ke bagian bawah. Menggulir ke atas akan menjeda perilaku mengikuti tersebut sehingga Anda dapat memeriksa output sebelumnya tanpa panel menarik tampilan menjauh.

## Menggunakan API [#using-the-api]

### Di LibreChat [#in-librechat]

API memiliki dukungan kelas satu di LibreChat melalui metode-metode utama berikut:

1. **[AI Agents](/docs/features/agents#code-interpreter)**: Aktifkan Code Interpreter dalam konfigurasi agen Anda agar agen tersebut dapat menjalankan kode dan memproses file secara otomatis.

2. **Eksekusi Manual**: Gunakan tombol "Run Code" di dalam blok kode di antarmuka obrolan, seperti yang ditunjukkan di sini:

3. **[Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling)**: Aktifkan kapabilitas `programmatic_tools` dan tandai alat MCP yang dipilih sebagai Programmatic agar agen dapat mengatur alat-alat tersebut dari kode yang di-sandbox.

4. **[Background Tool Calls](/docs/features/agents#background-tool-calls)**: Izinkan agen untuk mengirimkan kode yang memenuhi syarat di latar belakang dan melanjutkannya saat kode tersebut berjalan.

5. **[Stateful Code Sessions](/docs/features/agents#stateful-code-sessions)**: Menggunakan kembali ruang kerja (workspace) yang dicakup oleh pengguna, agen-dan-pengguna, atau percakapan secara eksperimental di seluruh eksekusi kode agen.

![Code Interpreter in LibreChat](/images/agents/run_code.png)

### Menyiapkan API key [#set-up-api-key]

- **Penyiapan per-pengguna:** Masukkan kunci API Anda di LibreChat saat diminta.
- **Pengaturan global:** Atur `LIBRECHAT_CODE_API_KEY` di dalam `.env` LibreChat untuk menyediakan satu kunci bagi semua pengguna.

Layanan [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) saat ini menggunakan autentikasi JWT LibreChat di luar mode lokal. Kunci API tetap tersedia untuk deployment Code Interpreter yang kompatibel.

### Autentikasi JWT yang di-host sendiri (self-hosted) [#self-hosted-jwt-authentication]

Dengan autentikasi JWT, LibreChat menandatangani token bearer berumur pendek untuk pengguna yang terautentikasi pada setiap permintaan Code Interpreter. Layanan Code Interpreter memverifikasi kunci publik yang cocok dan menggunakan konteks pengguna dan penyewa yang telah ditandatangani untuk mengisolasi file dan sesi. Kunci penandatanganan privat tetap berada di LibreChat; Code Interpreter hanya menerima verifikator publiknya.

Konfigurasikan LibreChat dengan:

```env
CODEAPI_AUTH_PROVIDER=librechat-jwt
CODEAPI_JWT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"
CODEAPI_JWT_ALGORITHM=EdDSA
CODEAPI_JWT_KID=lc-codeapi-2026-05
CODEAPI_JWT_ISSUER=librechat
CODEAPI_JWT_AUDIENCE=codeapi
CODEAPI_JWT_TTL_SECONDS=300
CODEAPI_JWT_MINT_CACHE_SECONDS=30
CODEAPI_JWT_SINGLE_TENANT_ID=legacy
```

`CODEAPI_JWT_PRIVATE_KEY_BASE64` dapat menampung PEM yang dienkode base64 sebagai gantinya, dan `CODEAPI_JWT_PRIVATE_JWK_JSON` menerima JWK privat. LibreChat mendukung penandatanganan Ed25519 (`EdDSA`, default) dan RSA (`RS256`). Lihat [referensi variabel lingkungan](/docs/configuration/dotenv#code-interpreter-jwt-authentication) untuk setiap pengaturan di sisi LibreChat.

Konfigurasikan Code Interpreter dengan verifier yang sesuai:

```env
LOCAL_MODE=false
CODEAPI_AUTH_PROVIDER=librechat-jwt
CODEAPI_JWT_ISSUER=librechat
CODEAPI_JWT_AUDIENCE=codeapi
CODEAPI_JWT_ALLOWED_ALGS=EdDSA
CODEAPI_JWT_JWKS_JSON={"keys":[{"kty":"OKP","crv":"Ed25519","x":"...","kid":"lc-codeapi-2026-05","alg":"EdDSA"}]}
CODEAPI_JWT_SINGLE_TENANT_ID=legacy
```

Penerbit, audiens, ID kunci, algoritma, dan kunci publik harus cocok dengan penanda tangan LibreChat. Code Interpreter juga dapat memuat kunci verifikator dari `CODEAPI_JWT_PUBLIC_KEY` ditambah `CODEAPI_JWT_KID`, atau dari `CODEAPI_JWT_PUBLIC_KEYS_DIR`; JWKS inline sangat praktis untuk rotasi. Jaga agar TTL token tetap pada atau di bawah `CODEAPI_JWT_MAX_TTL_SECONDS` layanan Code Interpreter, yang secara default diatur dan dibatasi pada 300 detik.

Untuk checkout lokal, repositori Code Interpreter menyertakan helper yang menghasilkan kunci penandatanganan Ed25519 dan kunci execution-manifest yang cocok serta memperbarui kedua file `.env`:

```bash
node scripts/setup-local-auth-env.js --librechat /path/to/LibreChat
```

Penyebaran single-tenant dapat membiarkan `CODEAPI_JWT_SINGLE_TENANT_ID=legacy`, namun nilainya harus sama pada kedua layanan. Penyebaran multi-tenant harus menyediakan konteks tenant yang terautentikasi dan mengaktifkan `TENANT_ISOLATION_STRICT=true` di LibreChat serta `CODEAPI_TENANT_ISOLATION_STRICT=true` di Code Interpreter. Mode ketat (strict mode) akan menolak permintaan tanpa konteks tenant alih-alih menggunakan fallback single-tenant.

### Integrasi API Langsung [#direct-api-integration]

Layanan yang di-hosting sendiri saat ini memerlukan bearer token yang memenuhi kontrak klaim JWT LibreChat. Integrasi langsung harus membuat token berumur pendek yang kompatibel dan mengirimkannya di header `Authorization: Bearer <token>`. Penyebaran yang kompatibel dengan API-key sebaliknya menerima kunci yang dikonfigurasi di header `x-api-key`. Jangan pernah menggunakan mode lokal tanpa autentikasi Code Interpreter pada endpoint publik atau produksi.

### URL dasar self-hosted [#self-hosted-base-url]

Atur `LIBRECHAT_CODE_BASEURL` untuk mengarahkan LibreChat ke instans [code-interpreter](https://github.com/ClickHouse/code-interpreter) yang Anda host sendiri, kemudian konfigurasikan [JWT authentication](#self-hosted-jwt-authentication). Untuk layanan yang kompatibel dengan API-key, atur `LIBRECHAT_CODE_API_KEY` sebagai gantinya. Sesi Agen stateful yang sangat eksperimental memerlukan rute profil `stateful` terpisah yang dikonfigurasi melalui [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) atau bernama [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions).

## Fungsionalitas Inti [#core-functionality]

### Eksekusi Kode [#code-execution]

- Jalankan cuplikan kode dalam bahasa yang didukung
- Menerima output stdout/stderr
- Dapatkan statistik eksekusi (penggunaan memori, waktu CPU)
- Menangani argumen program
- Akses status eksekusi dan hasil

### Operasi File [#file-operations]

- Unggah file input
- Unduh output yang dihasilkan
- Pratinjau file Office yang dihasilkan, termasuk presentasi PowerPoint `.pptx` dan templat `.potx`, serta artefak CSV, teks, dan PDF secara inline saat LibreChat dapat mengekstrak/merendernya dengan aman
- Menampilkan gambar PNG, JPEG, GIF, dan WebP yang dikembalikan oleh alat `read_file` Agen sebagai artefak yang dapat dilihat
- Daftar file yang tersedia
- Hapus file yang tidak diperlukan
- Kelola sesi file

Pratinjau artefak yang dihasilkan sengaja dibatasi ukurannya. Atur [`FILE_PREVIEW_MAX_EXTRACT_BYTES`](/docs/configuration/dotenv#inline-file-previews) di dalam `.env` LibreChat untuk mengubah batas ukuran file sumber untuk ekstraksi pratinjau inline; file yang lebih besar tetap tersedia untuk diunduh.

Gambar sandbox yang dikembalikan melalui `read_file` memiliki batas inline 1 MiB. Gambar yang lebih besar tetap berada di dalam sandbox untuk diproses dengan `bash_tool`. `LIBRECHAT_CODE_IMAGE_CHUNK_BYTES` hanya mengontrol ukuran potongan transport yang digunakan saat membaca gambar yang memenuhi syarat; pengaturan ini tidak menaikkan batas inline.

<Callout type="warning" title="Pemeriksaan peningkatan untuk output kode lama">
  Deployment yang membuat ulang nama file Code Interpreter yang sama sebelum indeks file output unik ditambahkan mungkin memiliki catatan MongoDB duplikat yang mencegah indeks tersebut dibuat. Pratinjau perbaikan dengan `npm run migrate:code-file-duplicates:dry-run`, lalu terapkan dengan `npm run migrate:code-file-duplicates`. Migrasi ini mempertahankan nama file kanonik terbaru, mengganti nama catatan lama dengan akhiran numerik, dan membuat indeks unik setelah proses berhasil dijalankan.
</Callout>

### Batasan [#limitations]
- Kode tidak dapat mengakses jaringan
- Hanya 10 file yang dapat dibuat per eksekusi
- Batas sumber daya (RAM per eksekusi, ukuran unggahan file, dan kuota permintaan) bergantung pada bagaimana Anda menyediakan dan mengonfigurasi deployment Anda.

## Open Source & Self-Hosting [#open-source--self-hosting]

Layanan Code Interpreter bersifat sumber terbuka di bawah lisensi Apache 2.0 di [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter). Menjaga eksekusi kode sebagai layanan terpisah membuat aplikasi inti LibreChat tetap ringan: Anda hanya perlu men-deploy infrastruktur sandbox saat membutuhkannya, dan Anda dapat menskalakannya secara independen dari aplikasi chat.

Layanan ini berjalan sebagai sekumpulan komponen yang dapat diskalakan secara independen (gateway API, worker dalam sandbox, dan server file) serta mendukung mode isolasi yang kuat (NsJail atau microVM melalui libkrun) sehingga Anda dapat menjalankan kode yang tidak tepercaya dengan aman. Lihat README repositori untuk instruksi penyebaran Docker Compose dan Helm.
