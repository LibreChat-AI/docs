Code Interpreter menjalankan kode di dalam sandbox yang terisolasi. Agen menggunakannya untuk melakukan perhitungan matematika yang seharusnya hanya diperkirakan, menganalisis spreadsheet yang Anda unggah, mengonversi file, atau membuat grafik dan dokumen. Anda juga dapat menjalankan sendiri blok kode dari pesan obrolan dengan **Run Code**.

Sandbox adalah layanan terpisah, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (open source, Apache 2.0), yang di-deploy oleh admin Anda di samping LibreChat. Layanan ini mendukung Python, Node.js (JavaScript dan TypeScript), Go, C dan C++, Java, PHP, Rust, dan Fortran.

## Berikan kemampuan eksekusi kode kepada agen [#give-an-agent-code-execution]

Di Agent Builder, pilih **Add** di samping **Tools**, lalu tambahkan **Run Code**. Simpan agen. Setelah itu, agen akan memutuskan sendiri kapan menjalankan kode; Anda tidak perlu memintanya secara eksplisit, meskipun "gunakan kode untuk memeriksa ini" berguna ketika Anda menginginkan jawaban yang tepat.

Saat kode berjalan, pesan menampilkan baris yang dapat diciutkan bertuliskan **Starting sandbox environment** untuk pertama kali, kemudian **Analyzing**, dan **Finished analyzing** ketika sudah selesai. Perluas baris tersebut untuk melihat kode yang ditulis oleh agen dan **Output**-nya.

## Bekerja dengan berkas [#working-with-files]

Lampirkan file dan pilih **Upload to Code Environment** agar file tersedia untuk sandbox pada percakapan tersebut. File yang Anda tambahkan di bawah pengaturan Run Code agen akan tersedia di setiap chat dengan agen tersebut. Sebelum setiap eksekusi, LibreChat memulihkan file percakapan ke dalam sandbox; jika tidak ada satu pun file yang dibutuhkan untuk eksekusi tersebut yang dapat dipulihkan, eksekusi akan dihentikan dan meminta Anda melampirkan kembali file tersebut, alih-alih bekerja dengan salinan yang sudah usang.

File yang ditulis oleh kode akan muncul kembali sebagai baris dalam pesan. Klik sebuah baris untuk membukanya di panel [Artifacts](/docs/features/artifacts), atau unduh filenya. HTML, Markdown, teks biasa, kode sumber, CSV, dan file Office (Word, Excel, OpenDocument, dek dan template PowerPoint) mendapatkan pratinjau inline. File yang lebih besar akan melewati pratinjau dan hanya tersedia untuk diunduh; batas default adalah 2 MiB untuk file sumber. Gambar yang dibaca agent dari sandbox (PNG, JPEG, GIF, WebP) ditampilkan secara inline hingga 1 MiB; gambar yang lebih besar tetap berada di sandbox tempat agent masih dapat memprosesnya.

## Jalankan blok kode sendiri [#run-a-code-block-yourself]

Blok kode dalam pesan obrolan memiliki tombol **Run Code** di samping **Copy code** ketika bahasa blok tersebut didukung oleh sandbox (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust, atau Fortran). Klik tombol tersebut dan keluarannya akan muncul di bawah blok. Fitur ini berfungsi di setiap percakapan, tidak hanya dengan agen.

## Kode yang Berjalan Lama [#long-running-code]

Jika admin Anda telah mengaktifkan alat latar belakang, pengaturan Run Code agen menampilkan **Background execution**, yang aktif secara default. Agen dapat memulai kode yang berjalan lambat, tetap berkomunikasi dengan Anda, dan mengambil output serta file saat eksekusi selesai; secara default, hasilnya akan muncul sendiri dalam pesan lanjutan. Nonaktifkan pengaturan ini untuk agen yang seharusnya selalu menunggu kodenya selesai.

Memori, waktu CPU, ukuran unggahan, dan akses jaringan ditetapkan oleh pihak yang menjalankan layanan sandbox, bukan oleh LibreChat. Jika kode gagal dengan error sumber daya, tanyakan kepada admin Anda mengenai batas-batas yang berlaku.

## Sesi kode yang stateful [#stateful-code-sessions]

Secara default, setiap run bersifat stateless: jangan mengandalkan variabel atau paket yang terinstal untuk bertahan hingga run berikutnya. Sesi kode stateful, sebuah fitur eksperimental yang harus diaktifkan oleh admin Anda, memberi agen sebuah workspace yang menyimpan file-filenya di `/mnt/data` di antara run. Setiap run tetap memulai proses baru, dan workspace dapat direset kapan saja, sehingga perlakukan workspace sebagai area sementara (scratch) dan bukan sebagai penyimpanan.

Aktifkan **Stateful code sessions** di pengaturan Run Code agen dan pilih **Stateful environment**:

- **Workspace pengguna (direkomendasikan)**: satu workspace untuk Anda, yang dibagikan oleh setiap agen stateful yang Anda gunakan.
- **Ruang kerja agen + pengguna**: ruang kerja terpisah untuk setiap agen.
- **Ruang kerja percakapan**: ruang kerja baru untuk setiap percakapan.

Agen baru dimulai dengan cakupan yang diatur di **Settings > Data & Privacy > Code execution > Default stateful workspace**; mengubah pengaturan tersebut tidak memengaruhi agen yang sudah ada. File yang dibuat atau diedit agen dalam workspace stateful ditampilkan di bawah baris **Workspace changes** pada balasannya, dengan tautan unduh untuk setiap file.

## Menjalankan kode di mesin Anda sendiri [#running-code-on-your-own-machine]

Admin juga dapat menyediakan lingkungan kode: sebuah VM atau workstation yang menjalankan worker `@librechat/code`, yang terhubung ke LibreChat. Ketika hal ini dilakukan, Agent Builder menampilkan pemilih **Execution environment**, dan **Machines available in new chats** memungkinkan sebuah agen menawarkan beberapa mesin sehingga setiap chat baru dapat memilih salah satunya dengan **Choose another machine**.

Jika Anda memiliki izin untuk mengelola lingkungan kode, tambahkan lingkungan Anda sendiri di **Settings > Data & Privacy > Code execution > Code environments**: beri nama, pilih **Connect VM**, lalu jalankan perintah satu kali yang ditampilkan pada mesin Anda. Jika admin Anda mengaktifkan penyiapan melalui browser, perintah penyiapan dapat membuka halaman **Approve Machine Setup**, tempat Anda mengonfirmasi permintaan saat sudah masuk.

Pada mesin yang terpasang, agen dapat menelusuri, membaca, mencari, dan mengedit file serta menjalankan perintah shell di workspace yang dipilih. Lampiran chat yang Anda unggah akan disalin ke `.librechat/attachments` di workspace tersebut sebelum agen mulai. Karena tindakan ini mengubah mesin yang sebenarnya, composer menampilkan **Code approval mode** untuk percakapan tersebut:

- **Tanya sebelum perubahan**: meminta konfirmasi sebelum melakukan pengeditan file dan menjalankan perintah.
- **Terima perubahan**: mengedit file tanpa bertanya, tetap bertanya sebelum menjalankan perintah.
- **Akses penuh**: mengedit dan menjalankan perintah tanpa permintaan konfirmasi rutin. Batasan sandbox pada mesin tetap berlaku.

Mode mana yang dapat Anda pilih bergantung pada kebijakan admin Anda. Memasangkan mesin (pairing) hanya mengautentikasi worker ke LibreChat; itu tidak menjalankan sandboxing apa pun, jadi isolasi worker seperti halnya Anda mengisolasi mesin mana pun yang menjalankan kode yang tidak tepercaya.

## Memanggil alat MCP dari kode [#calling-mcp-tools-from-code]

Dengan Programmatic Tool Calling, agen dapat memanggil alat MCP tertentu dari dalam sandbox: agen menulis skrip yang melakukan perulangan atas input, memanggil alat, menyaring hasil, dan hanya mengembalikan bagian yang penting. Cara ini menghemat satu putaran melalui model untuk setiap pemanggilan alat. Sakelar Programmatic tetap nonaktif hingga agen memiliki Run Code, dan menghapus Run Code akan menghapus sakelar tersebut. Saat skrip berjalan, perluas barisnya untuk melihat jejak **Tool calls**; jejak ini tidak disimpan setelah halaman dimuat ulang. Hanya alat yang terdaftar pada agen yang dapat dipanggil dengan cara ini. Lihat [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling) untuk mengetahui cara menandai alat.

## Pengaturan [#setup]

Eksekusi kode memerlukan admin untuk men-deploy layanan Code Interpreter dan mengarahkan LibreChat ke layanan tersebut; sampai itu dilakukan, eksekusi akan gagal. Tombol **Run Code** dan kemampuan agent juga dapat dinonaktifkan per peran. Eksekusi di latar belakang, sesi stateful, dan lingkungan kode masing-masing bersifat opt-in. Lihat [Konfigurasi Code Interpreter](/docs/configuration/tools/code_interpreter).
