Ein Agent ist eine gespeicherte Konfiguration: ein Modell, ein System-Prompt sowie die Tools und Dateien, die er verwenden kann. Du erstellst ihn einmal im Agent Builder und wählst ihn anschließend aus, sobald du einen Chat startest. Agenten funktionieren mit jedem Anbieter, den du konfiguriert hast, nicht nur mit OpenAI.

## Einen Agenten erstellen [#create-an-agent]

<Steps>
  <Step>
    Öffnen Sie im Seitenpanel den **Agent Builder** und klicken Sie auf **Create New Agent**.
  </Step>
  <Step>
    Gib ihm einen Namen, optional eine Beschreibung, und wähle ein **Model** und eine **Kategorie** aus. Das Model und die Kategorie sind erforderlich.
  </Step>
  <Step>
    Schreibe die Anweisungen. Du kannst sie direkt eingeben oder die Quelle auf **Prompt** umstellen, um einen gespeicherten Prompt aus deiner Prompt-Bibliothek zu verwenden (siehe unten).
  </Step>
  <Step>
    Füge Tools unter **Tools** hinzu (siehe unten) und klicke dann auf **Create**.
  </Step>
</Steps>

Das Hochladen von Dateien für Dateisuche oder Dateikontext funktioniert erst, nachdem der Agent erstellt wurde.

Um mit einem Agenten zu chatten, wählen Sie ihn im Modellauswahlmenü aus, öffnen Sie ihn über den [Agent Marketplace](#agent-marketplace), oder geben Sie `@` in das Chatfeld ein und wählen Sie ihn aus der Liste aus. Im Agentenauswahlmenü des Builders grenzt **My agents** die Liste auf die von Ihnen erstellten Agenten ein.

### Anweisungen aus einem gespeicherten Prompt [#instructions-from-a-saved-prompt]

Mit der Instruktionsquelle **Prompt** wählst du unter **Select a prompt** einen Prompt und eine **Version** aus: entweder die Produktionsversion, die dem folgt, was der Eigentümer des Prompts als Produktion markiert, oder eine feste gespeicherte Version. Um dies zu tun, benötigst du Zugriff auf die Prompt-Bibliothek. Wenn jemand anderes den Agenten ohne Zugriff auf den verknüpften Prompt öffnet, zeigt der Builder **Restricted prompt** an und ermöglicht es, den Prompt zu ersetzen oder zu den Inline-Instruktionen zurückzuwechseln.

Anweisungen, ob inline oder verlinkt, können `{{current_date}}`, `{{current_datetime}}` und `{{iso_datetime}}` verwenden. Sie werden einmal zu Beginn jedes Durchlaufs ausgefüllt und bleiben während Tool-Aufrufen, Subagenten und Genehmigungspausen unverändert. Die ersten beiden verwenden deine Zeitzone; `{{iso_datetime}}` ist UTC.

### Modellparameter [#model-parameters]

Das Modell-Panel stellt dieselben Parameter bereit wie ein normaler Chat für diesen Anbieter (Temperatur, maximale Ausgabe-Tokens usw.), zusätzlich **Image Detail** für Bildeingaben. Hier gespeicherte Werte gelten für jede Unterhaltung mit dem Agenten.

### Gesprächsanfänge [#conversation-starters]

Unter **Conversation Starters** können Sie bis zu vier Prompts hinzufügen. Sie erscheinen als Schaltflächen auf dem leeren Chat-Bildschirm, wenn jemand einen neuen Chat mit dem Agenten startet, und ein Klick darauf sendet sie sofort. Die Starter eines Agenten ersetzen alle Starter, die in der verwendeten Model Spec definiert sind. Außerdem werden sie in den Marketplace-Details des Agenten angezeigt.

### Versionsverlauf [#version-history]

Jedes Speichern, das den Agenten verändert, fügt einen Eintrag im **Versionsverlauf** hinzu, der zeigt, wann jede Version gespeichert wurde und welche Tools und Funktionen sie hatte. **Wiederherstellen** ersetzt die aktuelle Konfiguration nach einer Bestätigung durch diese Version. Dies sehen nur Benutzer, die den Agenten bearbeiten können.

## Werkzeuge [#tools]

Klicken Sie im Builder neben der Überschrift **Tools** auf **Hinzufügen** (dort steht **No tools yet**, solange noch kein Tool hinzugefügt wurde), um die **Tool-Bibliothek** zu öffnen. Durchsuchen Sie sie oder filtern Sie nach **Native**, **Tools**, **MCP servers** oder **Actions**. **Made by you** enthält die von Ihnen erstellten MCP-Server und Actions, und **Favorites** hält markierte Elemente agentenübergreifend griffbereit (bis zu 100). Über das Menü **Create new…** können Sie einen MCP-Server oder eine Action hinzufügen, ohne den Dialog zu verlassen, sofern Ihre Rolle dazu berechtigt ist. Was Sie sehen, hängt davon ab, was Ihr Administrator aktiviert hat, und von den Berechtigungen Ihrer Rolle. Ein Element, das noch einen API-Schlüssel benötigt, wird mit **Needs setup** gekennzeichnet.

Code ausführen, Dateisuche und Dateikontext verwalten Dateien. Solange diesen noch Dateien angehängt sind, öffnet das Entfernen stattdessen den Dateimanager, und sie bleiben beim Agenten, bis diese Dateien entfernt werden.

### Code Interpreter [#code-interpreter]

Aufgeführt als **Run Code**. Der Agent schreibt und führt Code in einer Sandbox aus, was sich für Berechnungen, Datenanalysen und die Erstellung von Dateien wie Diagrammen oder Tabellen eignet. Dateien, die Sie in der Builder-Ansicht an dieses Tool anhängen, stehen bei jeder Ausführung in der Sandbox zur Verfügung. Wenn keine der Code-Dateien einer Unterhaltung in der Sandbox wiederhergestellt werden kann, stoppt der Agent, bevor er das Modell aufruft, und bittet Sie, die Dateien erneut anzuhängen. Siehe [Code Interpreter](/docs/features/code_interpreter).

#### Zustandsbehaftete Code-Sitzungen [#stateful-code-sessions]

Wenn Ihr Administrator sie aktiviert hat, behalten **Stateful code sessions** in den Einstellungen für Run Code einen Sandbox-Arbeitsbereich zwischen den Ausführungen bei, sodass Dateien und installierte Pakete erhalten bleiben. **Stateful environment** legt fest, wer diesen Arbeitsbereich teilt: **User workspace (recommended)** für alle Ihre Stateful-Agenten, **Agent + user workspace** für einen pro Agent oder **Conversation workspace** für einen pro Chat. Neue Agenten starten mit dem **Default stateful workspace** unter **Settings > Data & Privacy > Code execution**. Hat der Administrator mehrere Backends eingerichtet, wählt **Execution environment** aus, welches davon den Code ausführt; dazu kann auch ein Worker gehören, den Sie auf Ihrem eigenen Rechner koppeln.

Der Arbeitsbereich kann jederzeit zurückgesetzt werden. Betrachten Sie ihn daher nicht als Speicher. In verwalteten Umgebungen speichern Sie benötigte Ausgaben unter `/mnt/data`. Dateien, die der Agent mit seinen Dateiwerkzeugen schreibt, werden pro Nachricht unter **Workspace changes** aufgelistet, wo Sie sie herunterladen können. Bei einer angehängten Umgebung bietet das Eingabefeld **Ask before changes**, **Accept edits** oder **Full access** als Genehmigungsmodus für diesen Chat an, innerhalb der von Ihrem Administrator festgelegten Grenzen.

Diese Funktion ist noch sehr experimentell. Einzelheiten finden Sie unter [zustandsbehaftete Code-Sitzungen](/docs/features/code_interpreter#stateful-code-sessions).

### Websuche [#web-search]

Der Agent durchsucht das Web und gibt seine Quellen an. Dafür ist ein von Ihrem Administrator konfigurierter Suchanbieter erforderlich oder, falls der Administrator es so eingerichtet hat, Ihr eigener Schlüssel. Siehe [Websuche](/docs/features/web_search).

### Dateisuche [#file-search]

Wandelt die Dateien, die Sie anhängen, in eine durchsuchbare Wissensdatenbank um. Der Agent ruft bei Bedarf die jeweils relevantesten Passagen ab, sodass er auch mit umfangreichen Dokumentensammlungen gut zurechtkommt. Für strukturierte Daten wie CSV oder Excel eignet sich dies weniger gut; dafür ist Run Code besser geeignet. Erfordert die [RAG API](/docs/features/rag_api).

### Dateikontext [#file-context]

Dateien, die unter **File Context** hinzugefügt werden, werden beim Hochladen einmalig extrahiert, und dieser Text wird bei jeder Nachricht in den Kontext des Agenten aufgenommen. Verwende diese Funktion für einige wenige Schlüsseldokumente, die der Agent stets im Blick haben soll. Die Extraktion funktioniert genauso wie bei [Upload as Text](/docs/features/upload_as_text): Standardmäßig erfolgt eine reine Textanalyse, bei Scans und Bildern werden bessere Ergebnisse erzielt, wenn [OCR](/docs/features/ocr) konfiguriert ist.

Da der Text bei jeder Nachricht mitgeschickt wird, verursachen große Dateien hier bei jedem Schritt Token-Kosten. Außerdem kann jeder, der mit dem Agenten chatten darf, diesen Text auch aus ihm herauslocken.

### Artifacts [#artifacts]

Ermöglicht dem Agenten, React, HTML, SVG, Markdown und Mermaid in einem seitlichen Bereich darzustellen, anstatt sie als Codeblöcke anzuzeigen. Die Einstellung **Modus** wählt die integrierten Anweisungen aus: **Normal**, **shadcn/ui** (fügt Anweisungen für die Komponentenbibliothek shadcn/ui hinzu) oder **Benutzerdefiniert**. Letzteres fügt nichts ein, daher müssen Ihre eigenen Anweisungen die Artefakt-Syntax vermitteln. Die Syntax dafür finden Sie unter [Artefakte](/docs/features/artifacts).

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP-Server, die von Ihrem Administrator konfiguriert wurden oder die Sie selbst hinzugefügt haben, erscheinen unter **MCP servers**. Beim Hinzufügen eines Servers werden alle seine Tools angehängt. Erweitern Sie ihn unter **Tools in this server**, um nur die Tools auszuwählen, die der Agent benötigt. Siehe [MCP](/docs/features/mcp).

Einige Server können ihre Tools nur während eines Chats auflisten, da sie von Werten aus der Anfrage abhängen. Für diese bietet der Builder eine einzige Auswahl für alle Tools des Servers an, anstatt Schalter pro Tool. Wenn beim Start eines Durchlaufs alle ausgewählten MCP-Tools eines Agenten nicht geladen werden können, wird der Durchlauf angehalten, und du erhältst die Aufforderung, die Verbindung zum Server neu herzustellen oder dich anzumelden, anstatt ohne sie fortzufahren.

Jedes MCP-Tool verfügt über ein **Tool-Optionen**-Menü mit einigen werkzeugspezifischen Schaltern:

- **Defer**: siehe [Deferred tools](#deferred-tools). **Defer all tools** erledigt dies für den gesamten Server.
- **Programmatisch**: siehe [Programmatischer Tool-Aufruf](#programmatic-tool-calling).
- **Hintergrund**: siehe [Hintergrund-Tool-Aufrufe](#background-tool-calls).
- **Intent-Label**: Der Agent schreibt zu jedem Aufruf eine einzeilige Beschreibung, die live als Status des Aufrufs angezeigt wird, anstelle eines generischen Labels. Dies erhöht die Anzahl der Tokens pro Anfrage um einige wenige. Native Tools erhalten Intent-Labels automatisch. Dies gilt nicht für programmatische Tools.

**Hintergrund** und **Absichtsbezeichnung** werden nur angezeigt, wenn Ihr Administrator sie aktiviert hat.

### Verzögerte Tools [#deferred-tools]

Ein Agent mit mehreren MCP-Servern kann leicht Dutzende Tool-Definitionen umfassen. Werden bei jeder Anfrage alle davon gesendet, belegt das viel Kontext und verschlechtert die Fähigkeit des Modells, das richtige Tool auszuwählen. Ein verzögertes Tool (Deferred Tool) wird deshalb nicht in die initiale Anfrage aufgenommen. Stattdessen erhält der Agent ein Tool-Suchwerkzeug, mit dem er verzögerte Tools bei Bedarf anhand von Name oder Beschreibung findet. Ein gefundenes Tool kann dann für den restlichen Verlauf der Unterhaltung verwendet werden.

### Programmatische Tool-Aufrufe [#programmatic-tool-calling]

Mit aktiviertem **Programmatic** für ein MCP-Tool (oder einen ganzen Server) ruft das Modell dieses Tool nicht direkt auf. Stattdessen schreibt es Code in der Code-Interpreter-Sandbox, der das Tool als Funktion aufruft. So kann es Ergebnisse vor der Antwort durchlaufen, paginieren, wiederholen und filtern. Das hilft bei Aufgaben wie „Prüfe diese 40 Tickets und fasse die offenen zusammen“, die sonst 40 einzelne Tool-Aufrufe über das Modell erfordern würden.

Die **Programmatic**-Schalter bleiben deaktiviert, solange Run Code nicht aktiviert ist, und das Entfernen von Run Code setzt sie zurück. Die Sandbox kann nur Tools aufrufen, die beim Agenten registriert sind. Während sie läuft, können Sie die Code-Karte aufklappen, um einen Live-Trace jedes inneren Tool-Aufrufs zu verfolgen; dieser Trace wird nach dem Neuladen der Seite nicht gespeichert. Diese Funktion ist standardmäßig deaktiviert; Ihr Administrator muss sie aktivieren.

### Hintergrund-Tool-Aufrufe [#background-tool-calls]

Ein hintergrundfähiges Tool gibt sofort eine Aufgabenreferenz zurück, sodass der Agent weiterarbeiten kann, während die Aufgabe läuft. Sobald die Aufgabe abgeschlossen ist, wird das Ergebnis automatisch in einem Folgeschritt zugestellt (dargestellt als einklappbare Aufgabenkarte), oder der Agent kann den Status über sein Aufgaben-Tool abfragen. Hintergrundausgaben und Dateien erscheinen beim ursprünglichen Tool-Aufruf. Welche Tools im Hintergrund ausgeführt werden dürfen:

- **Code ausführen**: Code und Shell-Befehle sind standardmäßig zulässig; deaktivieren Sie **Hintergrundausführung** in den zugehörigen Einstellungen, um dies abzulehnen.
- **MCP-Tools**: Markieren Sie ein Tool oder einen ganzen Server als **Background**.
- **Andere Tools und Aktionen**: Aktiviere **Hintergrundausführung**. Aktionen, die OAuth verwenden, bieten diese Option nicht an.

Diese Schalter ermöglichen die Ausführung im Hintergrund; das Modell entscheidet trotzdem bei jedem Aufruf. Hintergrundaufgaben laufen im Serverprozess, der sie gestartet hat, und gehen verloren, wenn dieser Prozess beendet wird. Ihr Administrator muss die Funktion aktivieren.

### Actions [#actions]

Aktionen wandeln eine OpenAPI-Spezifikation in Werkzeuge um. Wähle **Neu erstellen…** und dann **Aktionen**, füge das Schema ein und richte bei Bedarf die **Authentifizierung** ein, falls die API dies erfordert. Jeder Vorgang in der Spezifikation wird zu einem Werkzeug, das der Agent aufrufen kann.

Wenn Sie ein OpenAI-Modell verwenden, fügen Sie einer Operation in der Spezifikation `x-strict: true` hinzu. LibreChat fordert dann strikte Funktionsaufrufe für diese Operation an. Der strikte Modus akzeptiert nur eine Teilmenge von JSON Schema; weitere Informationen finden Sie im [Leitfaden zu strukturierten Ausgaben](https://platform.openai.com/docs/guides/structured-outputs) von OpenAI.

Aktionen können nur Domains erreichen, die Ihr Administrator erlaubt, und private Netzwerkadressen sind blockiert, sofern sie nicht ausdrücklich freigegeben wurden.

### Skills [#skills]

Der Abschnitt **Skills** im Builder steuert, welche [Skills](/docs/features/skills) der Agent verwenden kann: **Aus**, **Alle** (jeder Skill, den Sie aktiviert haben) oder **Ausgewählt** (nur die Skills, die Sie hinzufügen).

### Memory [#memory]

**Speicher** ermöglicht dem Agenten, Erinnerungen über dich zu speichern, zu aktualisieren und zu löschen, wenn du ihn bittest, sich etwas zu merken oder etwas zu vergessen. Dafür muss der Speicher auf der Instanz eingerichtet und für deine Rolle freigegeben sein. Standardmäßig teilt der Agent deine persönlichen Erinnerungen mit deinen anderen Chats; aktiviere **Speicher für diesen Agenten getrennt halten**, damit er eigene Erinnerungen erhält, die nur er liest und schreibt. Siehe [Speicher](/docs/features/memory).

### Benutzerabfrage und Tool-Genehmigung [#ask-user-and-tool-approval]

**Ask User** ermöglicht es dem Agenten, einen laufenden Durchlauf zu unterbrechen, um Ihnen eine Frage zu stellen, und auf Ihre Antwort zu warten. Eine Unterbrechung kann bis zu vier Fragen umfassen, die jeweils einzeln mit **Zurück** und **Weiter** angezeigt werden; jede Frage akzeptiert eine freie Texteingabe oder eine der vom Agenten vorgegebenen Auswahlmöglichkeiten. **Überspringen** lehnt alle Fragen ab. Der Durchlauf wird fortgesetzt, sobald Sie absenden, und Ihre Antworten bleiben erhalten, auch wenn Sie während des Neustarts abbrechen.

Ihr Administrator kann außerdem verlangen, dass bestimmte Tools erst nach einer Genehmigung ausgeführt werden. Die Ausführung wird dann angehalten, Sie prüfen den Aufruf in einem Panel oberhalb des Nachrichtenfelds (genehmigen, ablehnen oder bei einigen Tools die Argumente bearbeiten), und danach wird sie fortgesetzt. Wenn der Administrator Genehmigungsmodi pro Agent aktiviert hat, erhält jedes Tool des Agenten einen **Tool-Genehmigungsmodus**: **Vererbte Richtlinie verwenden**, **Immer fragen**, **Immer genehmigen**, **Einmal pro Chat fragen** oder **Einmal fragen, dann immer genehmigen**. Administratorregeln gelten zusätzlich weiterhin, und **Meine gespeicherten Genehmigungen zurücksetzen** löscht, was Sie zuvor genehmigt haben.

### Andere Werkzeuge [#other-tools]

Die Kategorie **Tools** enthält die eingebauten Integrationen, die dein Administrator aktiviert hat, etwa [Bildgenerierung](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search) und [Azure AI Search](/docs/configuration/tools/azure_ai_search). Jede davon wird separat eingerichtet; siehe [Tools](/docs/configuration/tools).

## Mit anderen Agenten arbeiten [#working-with-other-agents]

**Subagenten** ermöglichen es dem Agenten, eine fokussierte Teilaufgabe an eine neue Kopie seiner selbst oder an einen anderen Agenten zu übergeben, und zwar in einem separaten Kontextfenster. Nur das Ergebnis wird zurückgegeben, sodass lange Tool-Ausgaben nicht in der Hauptunterhaltung landen. Siehe [Subagenten](/docs/features/subagents).

### Übergaben [#handoffs]

**Handoffs** geben dem Agenten für jeden aufgelisteten Agenten ein Übergabe-Tool, sodass er das Gespräch bei passendem Thema an einen Spezialisten weitergeben kann. Für jede Übergabe können Sie eine Beschreibung (wann übergeben werden soll) und passthrough-Inhalte (was der Agent generieren und weitergeben soll) hinzufügen sowie den Parameter umbenennen, in den diese Inhalte übergeben werden (standardmäßig `instructions`). Ein Agent kann bis zu 10 Übergaben haben. Handoffs sind immer verfügbar; sie hängen nicht von einer Administratoreinstellung ab.

### Agentenkette [#agent-chain]

Agent-Ketten sind veraltet. Bestehende Ketten werden weiterhin ausgeführt, und der Builder zeigt sie unter **Advanced Settings** mit einer Schaltfläche **Remove chain** an, aber es lassen sich keine neuen mehr erstellen. Verwenden Sie stattdessen Subagenten oder Handoffs.

## Maximale Agentenschritte [#max-agent-steps]

**Erweiterte Einstellungen** enthält ein Feld **Max Agent Steps**, mit dem begrenzt wird, wie viele Schritte der Agent ausführen darf, bevor er eine endgültige Antwort geben muss. Ein Schritt ist entweder eine Modellanfrage oder eine Runde von Tool-Aufrufen. Ein einzelner Tool-Aufruf verbraucht daher in der Regel drei Schritte: die Anfrage, die Tool-Runde und die anschließende Folgeanfrage.

Lassen Sie das Feld leer, um den Standardwert des Servers zu verwenden, der 50 beträgt, sofern Ihr Administrator ihn nicht geändert hat. Ihr Administrator kann außerdem eine Obergrenze festlegen, die das Feld nicht überschreiten darf.

Wenn einem Durchlauf die Schritte ausgehen, bleibt das erhalten, was der Agent bis dahin getan hat, und die Nachricht bietet **Weitermachen** (ein neuer Durchlauf mit frischem Budget) oder **Jetzt antworten** (der Agent antwortet auf Grundlage der bereits geleisteten Arbeit, ohne weitere Tools zu verwenden). Wenn dies bei langen Tool-Ketten häufig auftritt, sollte das Limit erhöht werden.

## Nach einem langen Lauf [#following-a-long-run]

Tool-Karten zeigen **Vorbereitung** an, solange ein Aufruf wartet (zum Beispiel auf eine Genehmigung), und danach **Aufruf läuft**, bis das Ergebnis zurückkommt. Die Ausgabe von Shell-Befehlen wird im Terminal-Stil dargestellt und auf die letzten 15 Zeilen reduziert; mit **Mehr anzeigen** wird sie erweitert. Ein fehlgeschlagener Befehl zeigt seinen Exit-Code, sein Signal oder ein Timeout an.

### Aktivitätsgruppen [#activity-groups]

Wenn Ihr Administrator diese aktiviert hat, wird jeder Abschnitt aus Argumentation und Tool-Aufrufen unter einer generierten einzeiligen Überschrift eingeklappt, sodass ein Lauf mit 30 Tool-Aufrufen als wenige Zeilen erscheint. Klappen Sie eine Überschrift auf, um die darin enthaltenen Aufrufe zu sehen. Eine zweite Ebene kann mehrere dieser Gruppen zu einer Phase mit eigener Zusammenfassung bündeln, wodurch lange Läufe eine Gliederung erhalten. Sobald zwei Gruppen abgeschlossen sind, werden sie sofort zusammengefasst, wobei die neueste Überschrift so lange angezeigt wird, bis die Zusammenfassung vorliegt. Die endgültige Antwort bleibt immer außerhalb der Einklappung, und in einer Phase erzeugte Dateien werden unterhalb davon in einer Reihe angezeigt, statt verborgen zu werden. Mit aktiviertem [Smooth Streaming](/docs/features/smooth_streaming) wird das Einklappen animiert, sofern Ihr Gerät keine reduzierte Bewegung verlangt.

Live-Reasoning-Labels sind eine verwandte Option: Anstelle einer generischen **Thinking**-Überschrift zeigt der Denkblock eine kurze, sich laufend aktualisierende Zusammenfassung dessen, woran das Modell gerade arbeitet.

Überschriften, Phasenzusammenfassungen und Begründungsbezeichnungen verursachen zusätzliche Modellaufrufe, die wie jede andere Nutzung erfasst werden. Administratoren konfigurieren sie unter [Agent-Aktivitätsgruppen](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) und [Live-Begründungsbezeichnungen](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Steuerung und Nachrichten in der Warteschlange [#steering-and-queued-messages]

Während ein Agent antwortet, können Sie trotzdem weitere Nachrichten senden:

- **Steer** schiebt die Nachricht beim nächsten sicheren Punkt in den laufenden Durchlauf, sodass der Agent sich anpassen kann, bevor er fertig ist.
- **Unterbrechen** bricht die laufenden Tool-Aufrufe und das Reasoning ab, behält bereits Erledigtes bei und fährt mit deiner Nachricht fort. Wirkungen, die außerhalb von LibreChat bereits eingetreten sind, lassen sich nicht rückgängig machen. Einige Durchläufe, zum Beispiel solche, die die integrierte Suche eines Anbieters verwenden, können nicht unterbrochen werden; stattdessen wartet die Nachricht als Steer.
- **Queue** hält die Nachricht zurück und sendet sie als normalen Durchgang, nachdem die Antwort abgeschlossen ist.

**Während der Generierung** legt unter **Einstellungen > Chat** fest, was **Enter** tut; das Menü der Senden-Schaltfläche überschreibt dies pro Nachricht, und `Alt + Enter` unterbricht. Eingereihte Nachrichten werden oberhalb des Eingabefelds aufgelistet, wo Sie sie bearbeiten, entfernen, neu anordnen, **Jetzt senden** oder **Jetzt unterbrechen** können. Dateien und zitierte Auszüge werden zusammen mit der Nachricht übermittelt; Skills, die Sie mit `$` ausgewählt haben, warten auf den nächsten vollständigen Durchlauf. Eingereihte Nachrichten in einem gespeicherten Agenten-Chat werden auf dem Server gespeichert und überstehen ein geschlossenes Browserfenster.

Ein Chat kann bis zu 100 eingereihte Nachrichten enthalten (jeweils 16.000 Zeichen und 10 Dateien), und ein Durchlauf nimmt bis zu 10 ausstehende Steers auf. Einzelheiten zu den Belegen und Steuerelementen finden Sie unter [Composer](/docs/features/composer).

## Dateien im Chat [#files-in-a-chat]

Wenn Sie mit einem Agenten chatten, bietet das Anhängen-Menü Folgendes an:

- **Bild hochladen**: wird zur Bilderkennung an das Modell gesendet.
- **Als Text hochladen**: Der vollständige Text wird nur in diese Unterhaltung übernommen. Siehe [Als Text hochladen](/docs/features/upload_as_text).
- **Für Dateisuche hochladen**: wird für die Abfrage indexiert, ähnlich wie die eigenen Dateisuchdateien des Agenten, jedoch auf diesen Chat beschränkt.
- **Upload to Code Environment**: wird in die Sandbox für Run Code kopiert. Ideal für CSV-, Excel- und JSON-Dateien.

Optionen erscheinen nur, wenn die entsprechende Funktion aktiviert ist.

## Teilen und Berechtigungen [#sharing-and-permissions]

Agents sind für ihren Autor privat, bis sie geteilt werden. Klicken Sie im Footer des Builders auf **Teilen**, um Benutzern, Gruppen oder Rollen Zugriff zu gewähren, wobei jede Rolle eine von drei Berechtigungsstufen hat:

| Rolle | Was sie tun können |
| ----- | ------------------ |
| Betrachter | Mit dem Agenten chatten. Kann ihn nicht im Builder öffnen oder seine Anweisungen, Tools oder Dateien einsehen. |
| Bearbeiter | Alles, was ein Betrachter kann, zusätzlich die Anweisungen, das Modell, die Tools und die Dateien ändern. |
| Eigentümer | Alles, was ein Bearbeiter kann, zusätzlich den Agenten löschen und ändern, mit wem er geteilt wird. |

**Mit allen teilen** macht den Agenten für jeden Benutzer der Instanz verfügbar; dafür ist die öffentliche Freigabeberechtigung erforderlich. Der Autor und die Administratoren behalten stets die volle Kontrolle.

Ein Betrachter kann die Anweisungen oder Dateien im Builder nicht sehen, das Modell kann sie in einer Unterhaltung aber trotzdem wiederholen, wenn es danach gefragt wird. Füge einem Agenten nichts hinzu, das seine Betrachter niemals sehen sollten.

Separat davon steuert die Schaltfläche mit dem Globus (**Remote Access**), wer den Agenten über die [Agents API](/docs/features/agents_api) aufrufen kann.

Agent-Karten zeigen den Support-Kontakt an, der im Builder festgelegt wurde. Ohne einen solchen Kontakt können sie den Namen des Eigentümers anzeigen, jedoch niemals die E-Mail-Adresse des Eigentümers, es sei denn, diese wurde als Kontakt eingetragen.

Siehe [Zugriffskontrolle](/docs/features/access_control), wie Benutzer, Gruppen und Rollen zusammenwirken.

### Administratorsteuerung [#administrator-controls]

Ob eine Rolle Agenten verwenden, erstellen, teilen oder öffentlich teilen kann, wird pro Rolle im [Admin-Panel](/docs/features/admin_panel) festgelegt. Administratoren erhalten außerdem unten im Agent-Builder eine Schaltfläche **Admin-Einstellungen** mit denselben Schaltern, ebenfalls pro Rolle. Auf einer Single-Tenant-Instanz ist das zuerst registrierte Konto ein Administrator; um weitere hinzuzufügen, siehe [Weiteren Administrator ernennen](/docs/configuration/access_control#promote-another-admin).

## Agent-Marktplatz [#agent-marketplace]

**Agent Marketplace** in der Seitenleiste listet die Agenten auf, die dir zur Verfügung stehen, sofern deine Rolle sie verwenden darf. Du kannst nach Name oder Beschreibung suchen, nach Kategorie filtern (**Top Picks**, **All** oder eine bestimmte Kategorie) und die Reihenfolge mit **Sort by** ändern: **Newest first**, **Oldest first**, **Popular** oder **By creator name**. **My agents** zeigt nur deine eigenen Agenten an. Suche, Sortierung und Filter werden in der URL gespeichert, sodass du eine Ansicht als Lesezeichen speichern oder teilen kannst.

Klicken Sie auf eine Karte, um Details sowie die Aktionen **Pin** bzw. **Unpin**, **Copy Link** (ein Link, der einen neuen Chat mit dem Agenten öffnet) und **Start Chat** anzuzeigen. Ein Klick auf einen der Gesprächsstarter des Agenten öffnet einen neuen Chat mit dem Prompt im Nachrichtenfeld, ohne dass er gesendet wird, sodass Sie ihn vorher bearbeiten können.

## Agents API [#agents-api]

Agenten können außerdem über eine OpenAI-kompatible API aus Skripten und anderen Anwendungen aufgerufen, von vertrauenswürdigen Diensten verwaltet und durch Ereignisse aus anderen Systemen ausgelöst werden. Siehe [Agents API](/docs/features/agents_api). [Scheduled Chats](/docs/features/scheduled_chats) starten Agenten-Läufe zeitgesteuert, und [Agent Plugins](/docs/features/agent_plugins) ermöglichen es einem Betreiber, Skills und MCP-Server als ein gemeinsames Paket an Agenten auszuliefern.

## Einrichtung [#setup]

Agents sind standardmäßig aktiviert. Administratoren legen fest, welche Funktionen angeboten werden, die Schrittlimits und die erlaubten Anbieter in der [Agents-Endpoint-Konfiguration](/docs/configuration/librechat_yaml/object_structure/agents) fest, sowie welche Domains Actions erreichen dürfen, in der [Actions-Konfiguration](/docs/configuration/librechat_yaml/object_structure/actions). Instanzen, die von einer Version vor v0.8.0-rc3 aktualisiert wurden, benötigen die [Berechtigungsmigration](/docs/configuration/access_control#migrating-from-pre-acl-versions).
