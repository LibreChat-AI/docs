# Carica file come testo [#upload-files-as-text]

Hai mai desiderato consegnare un PDF, un file di codice o un foglio di calcolo all'AI e dire semplicemente _"leggi questo"_? L'uploader unificato di LibreChat instrada il file al provider o ne estrae automaticamente il testo in base al suo tipo e all'endpoint selezionato.

Alleghi un file, LibreChat ne estrae il testo e l'intero contenuto viene incollato direttamente nella tua conversazione. L'IA può quindi leggerne ogni parola: niente plugin, niente database vettoriali, nessun servizio aggiuntivo da configurare. Funziona immediatamente.

<Callout type="info" title="Nessuna configurazione richiesta">
  Upload as Text funziona immediatamente su qualsiasi istanza LibreChat. Utilizza l'analisi del testo integrata: non hai bisogno di OCR, di una pipeline RAG o di alcun servizio esterno per iniziare.
</Callout>

---

## Come utilizzarlo [#how-to-use-it]

<Steps>
  <Step>
    ### Apri la palette [#open-the-palette]

    Fai clic su **+** nel [compositore di messaggi](/docs/features/composer#add-files). Puoi anche trascinare il file sul compositore.
  </Step>
  <Step>
    ### Scegli una sorgente [#choose-a-source]

    Nella sezione **Attach**, seleziona **From Local Computer** o **From SharePoint** quando è configurato. L'uploader predefinito non richiede di scegliere un modello o una destinazione dello strumento.

    Se il tuo amministratore ha abilitato [`legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), scegli tu stesso la destinazione: seleziona **More upload options**, quindi **Upload as Text**.
  </Step>
  <Step>
    ### Scegli il tuo file [#choose-your-file]

    Seleziona il file. LibreChat sceglie la consegna tramite provider nativo, l'estrazione del testo o l'archiviazione solo per strumenti in base al tipo di file e alle funzionalità dell'endpoint.
  </Step>
  <Step>
    ### Fai la tua domanda [#ask-your-question]

    Digita il tuo prompt come al solito. Gli strumenti File Search e Code selezionati ricevono il file solo quando ne hanno bisogno.
  </Step>
</Steps>

Quando selezioni diversi file, LibreChat salta i duplicati individuali e i file che superano il limite di dimensione per singolo file, nomina i file saltati in un avviso e continua a caricare i file validi. I limiti relativi al numero di file e alla dimensione totale del batch si applicano comunque ai file rimanenti; se il batch risultante supera uno dei due limiti, l'intero batch viene rifiutato. Il comportamento per i singoli file rimane invariato.

<Callout type="warn" title="Non vedi l'opzione?">
  Con `legacyFileUploadUX` abilitato, se **Carica come testo** non appare sotto **Altre opzioni di caricamento**, la funzionalità `context` potrebbe essere stata disabilitata dal tuo amministratore. È attiva per impostazione predefinita, ma se l'elenco delle funzionalità è stato personalizzato, `context` deve essere incluso esplicitamente. Vedi la [sezione di configurazione](#the-context-capability) qui sotto.
</Callout>

## Incolla testo lungo come file [#paste-long-text-as-a-file]

Nel normale compositore di messaggi, LibreChat può trasformare un incolla più lungo di 2.500 caratteri in un allegato Carica come testo. Questo mantiene un incolla di grandi dimensioni fuori dall'input, fornendo comunque i suoi contenuti al modello attraverso il contesto della conversazione. Il primo allegato viene denominato `pasted-text.txt`; gli allegati di testo incollati aggiuntivi ricevono nomi numerati.

L'impostazione locale del browser **Incolla testo lungo come file** è abilitata per impostazione predefinita in **Impostazioni > Chat > Invio**. Le incollate più brevi e il testo incollato durante la risposta a un modulo **Chiedi all'utente** di un Agente rimangono inline. Se i caricamenti di contesto non sono disponibili, il testo rimane anch'esso inline. Se il caricamento di un allegato fallisce, LibreChat ripristina il testo nel compositore quando può farlo senza sovrascrivere una bozza più recente.

Gli allegati di testo incollati seguono le stesse regole di dimensione del file, token e [`fileTokenLimit`](#token-limits-and-truncation) degli altri file caricati come testo.

## Cosa succede dietro le quinte [#what-happens-under-the-hood]

Quando un caricamento viene indirizzato al testo, LibreChat non inserisce byte grezzi nel prompt. Viene eseguito attraverso una pipeline di elaborazione per estrarre testo pulito e leggibile:

1. **Rilevamento del tipo MIME** — LibreChat controlla il tipo di file caricato (PDF, immagine, audio, codice sorgente, ecc.) ispezionando il suo tipo MIME.
2. **Selezione del metodo** — In base al tipo di file e ai servizi disponibili, sceglie il miglior metodo di estrazione utilizzando questa priorità:

<Tabs items={["Ordine di priorità", "Esempi di decisione"]}>
  <Tabs.Tab>
    | Priorità | Metodo | Quando viene utilizzato |
    |----------|--------|---------------|
    | 1° | **OCR** | Il file è un'immagine o un documento scansionato, _e_ l'OCR è configurato |
    | 2° | **STT** (Speech-to-Text) | Il file è audio, _e_ l'STT è configurato |
    | 3° | **Analisi del testo** | Il file corrisponde a un tipo MIME di testo noto |
    | 4° | **Fallback** | Nessuno dei precedenti ha avuto esito positivo — tenta comunque l'analisi del testo |
  </Tabs.Tab>
  <Tabs.Tab>
    **Un `.pdf` su un'istanza con OCR configurato:**
    → L'OCR entra in funzione. Ottimo per documenti scansionati e layout complessi.

    **Un `.pdf` su un'istanza predefinita (senza OCR):**
    → L'analisi del testo lo gestisce. Funziona bene per i PDF creati digitalmente.

    **Un file Python `.py`:**
    → Parsing diretto del testo. Il codice sorgente è già testo: non è necessaria alcuna conversione.

    **Un `.mp3` su un'istanza con STT configurato:**
    → Speech-to-Text lo trascrive in testo per la conversazione.

    **Uno screenshot `.png` senza OCR configurato:**
    → Ricorre all'analisi del testo (risultati limitati — considera di configurare l'OCR per le immagini).
  </Tabs.Tab>
</Tabs>

3. **Troncamento dei token** — Il testo estratto viene ridotto al `fileTokenLimit` (predefinito: 100.000 token) in modo che non superi la finestra di contesto del modello.
4. **Prompt injection** — Il testo viene incluso nel contesto della conversazione, esattamente insieme al tuo messaggio.

Quando visualizzi in anteprima o scarichi un allegato come Carica come Testo (Upload as Text), LibreChat fornisce il testo estratto archiviato con il record del file. I download utilizzano un nome file `.txt` anche quando l'OCR o un altro parser hanno prodotto il testo archiviato e non esiste un file originale di supporto da trasmettere.

## Quali file sono supportati [#which-files-are-supported]

<Tabs items={["Testo e codice", "Documenti", "Immagini", "Audio"]}>
  <Tabs.Tab>
    Questi vengono analizzati direttamente — sono già testo, quindi non è necessaria alcuna conversione.

    - Testo semplice (`.txt`), Markdown (`.md`), CSV, JSON, XML, HTML, CSS
    - Linguaggi di programmazione — Python, JavaScript, TypeScript, Java, C#, PHP, Ruby, Go, Rust, Kotlin, Swift, Scala, Perl, Lua
    - File di configurazione — YAML, TOML, INI
    - Script shell, file SQL
  </Tabs.Tab>
  <Tabs.Tab>
    L'analisi del testo gestisce queste situazioni nativamente. Se l'OCR è configurato, subentra per una maggiore precisione su layout complessi.

    - **PDF** — digitali e scansionati (i PDF scansionati beneficiano dell'OCR)
    - **Word** — `.docx`, `.doc`
    - **PowerPoint** — `.pptx`, `.potx`, `.ppt`
    - **Excel** — `.xlsx`, `.xls`
    - Libri **EPUB**
  </Tabs.Tab>
  <Tabs.Tab>
    Le immagini **richiedono l'OCR** per produrre testo utile. Senza di esso, i risultati saranno scadenti.

    - JPEG, PNG, GIF, WebP
    - HEIC, HEIF (formati Apple)
    - Screenshot, foto di documenti, pagine scansionate
  </Tabs.Tab>
  <Tabs.Tab>
    I file audio **richiedono che STT** sia configurato. Non esiste un fallback: l'audio non può essere "analizzato come testo".

    - MP3, WAV, OGG, FLAC
    - M4A, WebM
    - Registrazioni vocali, clip di podcast
  </Tabs.Tab>
</Tabs>

LibreChat normalizza le varianti MIME di shell-script segnalate da Chrome su Linux (`application/x-shellscript`) e libmagic (`text/x-shellscript`) nel formato canonico `application/x-sh` prima di verificare la whitelist dell'endpoint. Le regole personalizzate [`supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) devono comunque consentire `application/x-sh`.

## Caricamenti unificati e provisioning degli strumenti [#unified-uploads-and-tool-provisioning]

Per impostazione predefinita, un'azione di allegato sostituisce il vecchio selettore di destinazione. LibreChat decide come il file raggiunge il modello, mentre gli strumenti vengono forniti in modo lazy:

<Cards>
  <Card title="Contesto del modello" href="#what-happens-under-the-hood">
    I file supportati raggiungono il modello tramite la consegna nativa del provider o tramite testo estratto, in base al tipo MIME, alla funzionalità dell'endpoint e alla configurazione della distribuzione.
  </Card>
  <Card title="Caricamento per Ricerca File (RAG)" href="/docs/features/rag_api">
    Quando File Search è selezionato, LibreChat indicizza gli allegati idonei solo quando l'esecuzione necessita dello strumento.
  </Card>
  <Card title="Caricamento standard" href="/docs/features/agents">
    Quando Code è selezionato, LibreChat rende gli allegati idonei disponibili all'ambiente Code solo quando l'esecuzione ne ha bisogno.
  </Card>
</Cards>

Gli operatori possono ripristinare il precedente selettore di destinazione con [`fileConfig.legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), oppure controllare il routing automatico con [`defaultLLMDeliveryPath`](/docs/configuration/librechat_yaml/object_structure/file_config#defaultllmdeliverypath).

**Routing tipico:**

| Situazione | Opzione migliore |
|-----------|-------------|
| _"Leggi questo contratto di 5 pagine e riassumilo"_ | Consegna PDF nativa o testo estratto |
| _"Ho 50 PDF, trova cosa menziona i prezzi"_ | Provisioning Lazy File Search |
| _"Cosa c'è in questo screenshot?"_ | Consegna immagine nativa |
| _"Esegui questo script Python"_ | Provisioning Lazy Code |
| _"Controlla questo file di codice per bug"_ | Testo estratto |

## La funzionalità `context` [#the-context-capability]

Sotto il cofano, Upload as Text è alimentato dalla **funzionalità `context`**. È questo che controlla se la funzione appare nella tua interfaccia di chat.

<Callout type="info">
  La funzionalità `context` è **abilitata per impostazione predefinita**. È necessario intervenire solo se l'amministratore ha personalizzato l'elenco delle funzionalità e l'ha accidentalmente omessa.
</Callout>

```yaml title="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - "context"  # This is what enables "Upload as Text"
```

La stessa funzionalità `context` alimenta anche **Agent File Context** (caricamento di file tramite l'Agent Builder per incorporare testo nelle istruzioni di sistema di un agente). La differenza sta in _dove_ finisce il testo:

| | Caricamento come testo | Contesto file dell'agente |
|---|---|---|
| **Dove** | Input della chat (qualsiasi conversazione) | Pannello Agent Builder |
| **Ambito** | Solo conversazione corrente | Persiste nelle istruzioni dell'agente |
| **Caso d'uso** | Domande su documenti una tantum | Creazione di agenti specializzati con conoscenza integrata |

## Limiti dei token e troncamento [#token-limits-and-truncation]

Quando un file è troppo lungo per rientrare nella finestra di contesto del modello, LibreChat tronca il testo estratto per rimanere entro i limiti. Questo avviene automaticamente: non devi preoccupartene, ma è utile sapere come funziona.

```yaml title="librechat.yaml"
fileConfig:
  fileTokenLimit: 100000  # Default: 100,000 tokens
```

<Callout type="warn" title="Il troncamento comporta la perdita di contenuti">
  Se il tuo file supera il limite, il testo viene troncato alla fine. Se ricevi risposte incomplete, questo potrebbe essere il motivo. Puoi aumentare `fileTokenLimit`, ma tieni presente che valori più grandi utilizzano più token per messaggio, il che aumenta i costi e potrebbe raggiungere il limite di contesto del modello stesso.
</Callout>

**Regole generali:**
- 100k token ≈ un libro di 300 pagine (più che sufficiente per la maggior parte dei casi d'uso)
- Se stai lavorando con file molto grandi, prendi in considerazione [File Search (RAG)](/docs/features/rag_api) — recupera solo le sezioni pertinenti invece di inserire tutto nel contesto.

## Opzionale: potenziare l'estrazione con OCR [#optional-boosting-extraction-with-ocr]

L'analisi del testo funziona correttamente per i documenti creati digitalmente (PDF salvati da Word, file di codice, testo semplice). Tuttavia, se carichi **documenti scansionati, foto di pagine o immagini contenenti testo**, il parser integrato non otterrà risultati ottimali.

È qui che entra in gioco l'OCR. Quando configurato, LibreChat utilizza automaticamente l'OCR per i tipi di file che ne traggono vantaggio: non è necessario fare nulla di diverso come utente.

<Accordions>
  <Accordion title="Come chiedere al tuo amministratore di configurare l'OCR">
    Indicali verso la [documentazione di configurazione OCR](/docs/features/ocr). La versione breve:

    ```yaml title="librechat.yaml"
    ocr:
      strategy: "mistral_ocr"
      apiKey: "${OCR_API_KEY}"
      baseURL: "https://api.mistral.ai/v1"
      mistralModel: "mistral-ocr-latest"
    ```

    Una volta configurato, l'OCR gestisce automaticamente immagini e PDF scansionati: non sono necessarie modifiche da parte dell'utente.
  </Accordion>
  <Accordion title="Come chiedere al tuo amministratore di configurare STT (per i file audio)">
    Per la trascrizione di caricamenti audio, l'amministratore deve configurare un servizio Speech-to-Text. Consulta il [riferimento alla configurazione STT](/docs/configuration/librechat_yaml/object_structure/file_config#stt).
  </Accordion>
</Accordions>

## Riferimento alla configurazione della gestione dei file [#file-handling-configuration-reference]

Questa sezione è destinata agli amministratori che desiderano controllare quali tipi di file vengono elaborati con quale metodo. Le impostazioni predefinite funzionano bene: è necessario intervenire solo se si desidera ottimizzare il comportamento.

<Accordions>
  <Accordion title="Esempio completo di fileConfig">
    ```yaml title="librechat.yaml"
    fileConfig:
      # Max tokens extracted from a single file before truncation
      fileTokenLimit: 100000

      # Files matching these MIME patterns use OCR (if configured)
      ocr:
        supportedMimeTypes:
          - "^image/(jpeg|gif|png|webp|heic|heif)$"
          - "^application/pdf$"
          - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.presentation|spreadsheetml\\.sheet)$"
          - "^application/vnd\\.ms-(word|powerpoint|excel)$"
          - "^application/epub\\+zip$"

      # Files matching these MIME patterns use text parsing
      text:
        supportedMimeTypes:
          - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"

      # Files matching these MIME patterns use STT (if configured)
      stt:
        supportedMimeTypes:
          - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
    ```

    **Promemoria di priorità:** OCR > STT > analisi del testo > fallback.

    Per il riferimento completo, consultare [File Config Object Structure](/docs/configuration/librechat_yaml/object_structure/file_config).
  </Accordion>
</Accordions>

## Risoluzione dei problemi [#troubleshooting]

<Accordions>
  <Accordion title="L'opzione Carica come testo non appare">
    La funzionalità `context` è stata probabilmente rimossa dalla tua configurazione. Chiedi al tuo amministratore di riaggiungerla:

    ```yaml
    endpoints:
      agents:
        capabilities:
          - "context"
    ```
  </Accordion>
  <Accordion title="Il contenuto del file sembra errato o è quasi vuoto">
    Alcune cose da controllare:
    - **PDF / immagini scansionati** — Questi necessitano di OCR per estrarre correttamente il testo. Senza di esso, il parser potrebbe restituire dati errati o nulla. Chiedi al tuo amministratore di [configurare OCR](/docs/features/ocr).
    - **File audio** — Questi richiedono STT. Non esiste un fallback di testo per l'audio.
    - **File danneggiati** — Prova ad aprire il file localmente per assicurarti che non sia danneggiato.
    - **Formato non supportato** — Se il tipo MIME non corrisponde a nessun pattern configurato, LibreChat tenta un fallback di analisi del testo, che potrebbe non funzionare per i formati binari.
  </Accordion>
  <Accordion title="Il caricamento è stato rifiutato in quanto tipo di file non supportato">
    LibreChat restituisce il tipo MIME rifiutato nell'errore di caricamento. Controlla i pattern [`fileConfig.endpoints.<endpoint>.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) dell'endpoint attivo e consenti il tipo canonico che intendi accettare. Per gli script shell, usa `application/x-sh`; LibreChat normalizza le varianti comuni `application/x-shellscript` e `text/x-shellscript` prima di effettuare la corrispondenza.
  </Accordion>
  <Accordion title="L'IA sembra aver perso una parte del mio file">
    Il tuo file ha probabilmente superato il `fileTokenLimit`. Il testo è stato troncato.

    **Opzioni:**
    - Chiedi al tuo amministratore di aumentare `fileTokenLimit` in `librechat.yaml`
    - Usa invece [File Search (RAG)](/docs/features/rag_api), che recupera i chunk rilevanti invece di caricare l'intero file
    - Dividi il file in parti più piccole e caricale separatamente
  </Accordion>
  <Accordion title="Le immagini vengono caricate ma l'IA non riesce a leggere il testo al loro interno">
    Senza OCR, le immagini vengono elaborate tramite l'analisi del testo, che non è in grado di "vedere" effettivamente il testo in un'immagine. È necessario configurare l'OCR affinché ciò funzioni. Consulta [OCR for Documents](/docs/features/ocr).

    In alternativa, utilizza un **vision model** con il caricamento file standard: il modello stesso è in grado di leggere il testo nelle immagini.
  </Accordion>
</Accordions>
