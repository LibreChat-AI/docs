De Code Interpreter voert code uit in een geïsoleerde sandbox. Agents gebruiken deze om berekeningen uit te voeren waarvoor ze anders een schatting zouden moeten maken, een spreadsheet te analyseren die je hebt geüpload, bestanden te converteren, of grafieken en documenten te maken. Je kunt ook zelf een codeblok uit een chatbericht uitvoeren met **Run Code**.

De sandbox is een afzonderlijke service, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (open source, Apache 2.0), die je beheerder naast LibreChat implementeert. Deze ondersteunt Python, Node.js (JavaScript en TypeScript), Go, C en C++, Java, PHP, Rust en Fortran.

## Geef een agent code-uitvoering [#give-an-agent-code-execution]

In de Agent Builder selecteer je **Toevoegen** naast **Tools** en voeg je **Run Code** toe. Sla de agent op. Vanaf dat moment beslist de agent zelf wanneer er code wordt uitgevoerd; je hoeft er niet expliciet om te vragen, al helpt "gebruik code om dit te controleren" wanneer je een exact antwoord wilt.

Terwijl code wordt uitgevoerd, toont het bericht een inklapbare rij met de tekst **Starting sandbox environment** de eerste keer, daarna **Analyzing**, en **Finished analyzing** wanneer het klaar is. Vouw deze uit om de code te zien die de agent heeft geschreven en de **Output**.

## Werken met bestanden [#working-with-files]

Voeg een bestand toe en kies **Uploaden naar codeomgeving** om het beschikbaar te maken voor de sandbox in dat gesprek. Bestanden die je toevoegt onder de Run Code-instellingen van de agent zijn beschikbaar in elk gesprek met die agent. Voorafgaand aan elke uitvoering herstelt LibreChat de bestanden van het gesprek in de sandbox; als geen van de bestanden die de uitvoering nodig heeft kan worden hersteld, stopt de uitvoering en vraagt deze je om ze opnieuw bij te voegen, in plaats van te werken met verouderde kopieën.

Bestanden die de code schrijft, verschijnen als rijen in het bericht. Klik op een rij om deze te openen in het [Artifacts](/docs/features/artifacts)-paneel, of download deze. HTML, Markdown, platte tekst, broncode, CSV en Office-bestanden (Word, Excel, OpenDocument, PowerPoint-presentaties en -sjablonen) krijgen een inline voorbeeld. Grotere bestanden slaan de voorbeeldweergave over en blijven alleen beschikbaar als download; de standaardlimiet is 2 MiB aan bronbestand. Afbeeldingen die de agent uit de sandbox leest (PNG, JPEG, GIF, WebP) worden inline weergegeven tot 1 MiB; grotere bestanden blijven in de sandbox, waar de agent ze nog steeds kan verwerken.

## Voer zelf een codeblok uit [#run-a-code-block-yourself]

Codeblokken in chatberichten hebben naast **Copy code** een **Run Code**-knop wanneer de taal van het blok een taal is die de sandbox kan uitvoeren (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust of Fortran). Klik erop en de uitvoer verschijnt onder het blok. Dit werkt in elk gesprek, niet alleen met agents.

## Langlopende code [#long-running-code]

Als je beheerder achtergrondtools heeft ingeschakeld, tonen de Run Code-instellingen van de agent **Achtergronduitvoering**, standaard ingeschakeld. De agent kan trage code starten, met je blijven praten en de uitvoer en bestanden overnemen zodra de uitvoering is voltooid; standaard komt het resultaat vanzelf binnen in een vervolgbericht. Schakel de instelling uit voor agents die altijd op hun code moeten wachten.

Geheugen, CPU-tijd, uploadgrootte en netwerktoegang worden ingesteld door degene die de sandbox-service beheert, niet door LibreChat. Als code faalt met een resourcefout, vraag dan aan je beheerder wat de limieten zijn.

## Stateful code sessions [#stateful-code-sessions]

Standaard is elke run stateless: reken er niet op dat variabelen of geïnstalleerde pakketten bewaard blijven voor de volgende run. Stateful code sessions, een experimentele functie die je beheerder moet inschakelen, geven een agent een werkruimte die zijn bestanden tussen runs bewaart onder `/mnt/data`. Elke run start nog steeds een nieuw proces, en de werkruimte kan op elk moment worden gereset, dus behandel deze als een tijdelijke werkruimte en niet als opslag.

Schakel **Stateful code sessions** in de Run Code-instellingen van de agent in en kies een **Stateful environment**:

- **Gebruikersworkspace (aanbevolen)**: één workspace voor jou, gedeeld door elke stateful agent die je gebruikt.
- **Agent + gebruikersworkspace**: een afzonderlijke workspace voor elke agent.
- **Gesprekswerkruimte**: een nieuwe werkruimte voor elk gesprek.

Nieuwe agents starten met het bereik dat is ingesteld onder **Instellingen > Gegevens en privacy > Codeuitvoering > Standaard stateful werkruimte**; het wijzigen van die instelling heeft geen invloed op bestaande agents. Bestanden die de agent aanmaakt of bewerkt in een stateful werkruimte worden vermeld onder een rij **Werkruimtewijzigingen** in het antwoord, met een downloadknop voor elk bestand.

## Code uitvoeren op je eigen machine [#running-code-on-your-own-machine]

Beheerders kunnen ook codeomgevingen aanbieden: een VM of werkstation waarop de `@librechat/code`-worker draait, die naar buiten verbindt met LibreChat. Wanneer zij dat doen, toont de Agent Builder een selector voor **Execution environment**, en met **Machines available in new chats** kan een agent meerdere machines aanbieden, zodat elke nieuwe chat een machine kan kiezen via **Choose another machine**.

Als je toestemming hebt om codeomgevingen te beheren, voeg dan je eigen omgeving toe onder **Settings > Data & Privacy > Code execution > Code environments**: geef deze een naam, selecteer **Connect VM** en voer het eenmalige commando uit dat wordt getoond op je eigen machine. Als je beheerder het instellen via de browser heeft ingeschakeld, kan het installatiecommando in plaats daarvan een pagina **Approve Machine Setup** openen, waar je het verzoek bevestigt terwijl je bent ingelogd.

Op een gekoppelde machine kan de agent in de geselecteerde werkruimte bladeren, bestanden lezen, zoeken en bewerken, en shellopdrachten uitvoeren. Chatbijlagen die je uploadt, worden gekopieerd naar `.librechat/attachments` in die werkruimte voordat de agent start. Omdat deze acties een echte machine wijzigen, toont de composer een **Code-goedkeuringsmodus** voor het gesprek:

- **Vragen voor wijzigingen**: vraagt om toestemming voordat bestanden worden bewerkt en opdrachten worden uitgevoerd.
- **Wijzigingen accepteren**: bewerkt bestanden zonder te vragen, maar vraagt nog steeds om toestemming voordat er commando's worden uitgevoerd.
- **Volledige toegang**: bewerkt bestanden en voert opdrachten uit zonder routinematige bevestigingsvragen. Sandbox-beperkingen op de machine blijven van toepassing.

Welke modi je kunt kiezen hangt af van het beleid van je beheerder. Het koppelen van een machine authenticeert de worker bij LibreChat; het biedt geen sandbox, dus isoleer de worker zoals je elke machine zou isoleren die niet-vertrouwde code uitvoert.

## MCP-tools aanroepen vanuit code [#calling-mcp-tools-from-code]

Met Programmatic Tool Calling kan een agent geselecteerde MCP-tools aanroepen vanuit de sandbox: de agent schrijft een script dat over invoer loopt, tools aanroept, de resultaten filtert en alleen retourneert wat relevant is. Dit bespaart voor elke toolaanroep een heen-en-weer traject via het model. De Programmatic-schakelaars blijven uitgeschakeld totdat de agent Run Code heeft, en het verwijderen van Run Code wist ze. Terwijl het script draait, kunt u de rij uitklappen om een **Tool calls**-overzicht te volgen; dit overzicht wordt niet bewaard na het opnieuw laden van de pagina. Alleen tools die bij de agent zijn geregistreerd, kunnen op deze manier worden aangeroepen. Zie [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling) voor het markeren van tools.

## Setup [#setup]

Codeuitvoering vereist dat een beheerder de Code Interpreter-service implementeert en LibreChat ernaar laat verwijzen; totdat dat gebeurd is, mislukken uitvoeringen. De knop **Run Code** en de agentfunctie kunnen ook per rol worden uitgeschakeld. Achtergronduitvoering, stateful sessies en codeomgevingen zijn elk optioneel en moeten expliciet worden ingeschakeld. Zie [Code Interpreter-configuratie](/docs/configuration/tools/code_interpreter).
