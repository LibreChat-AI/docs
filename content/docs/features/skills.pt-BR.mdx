Uma skill é um arquivo `SKILL.md`: um pequeno bloco de frontmatter que indica quando a skill se aplica, e um corpo em markdown com as instruções. Use uma para qualquer coisa que você, de outra forma, colaria no chat repetidamente, como um guia de estilo, uma lista de verificação de revisão ou os passos de um relatório recorrente. Os agentes carregam uma skill somente quando ela é relevante, então você pode manter muitas delas disponíveis sem sobrecarregar cada prompt.

O LibreChat não vem com nenhuma skill. Cada uma é escrita ou enviada por um usuário, criada por um agente durante um chat ou fornecida pelo seu administrador.

## Criar uma skill [#create-a-skill]

Abra **Skills** no painel lateral e clique em **+**. Escolha **Write skill instructions** para escrever uma no editor, ou **Upload a skill** para importar um arquivo `.md`, ou um arquivo `.zip` ou `.skill` que contenha um `SKILL.md`. Se Skills não aparecer no painel lateral, significa que seu administrador desativou o recurso ou que sua função não tem permissão para usá-lo.

Uma habilidade mínima:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing copy that must follow the company voice and terminology.
---

Write in a concise, practical tone.
Prefer active voice.
Say "workspace", never "project space".
```

O nome deve estar em kebab-case (letras minúsculas, dígitos e hífens), ter no máximo 64 caracteres e ser único entre suas skills; enviar uma skill com um nome que você já utiliza falha em vez de sobrescrever. Nomes que começam com `anthropic-` ou `claude-`, e palavras de comando como `help` ou `settings`, são reservados.

A descrição importa mais do que qualquer outra parte do arquivo: é ela que o modelo lê para decidir se a skill se aplica. "Use quando escrever notas de versão para o aplicativo mobile" será acionada; "Auxiliar de escrita" não será. Coloque as frases de gatilho primeiro e mantenha-a com menos de 250 caracteres, porque descrições mais longas são cortadas na lista que o modelo vê. O limite máximo é de 1.024 caracteres para a descrição e 100.000 para o corpo.

### Opções de frontmatter [#frontmatter-options]

Além de `name` e `description`, uma skill pode definir:

- `always-apply: true`: carrega a skill em todo turno, em vez de esperar que o modelo a solicite.
- `user-invocable: false`: oculta-o do menu `$`.
- `disable-model-invocation: true`: deixe-o fora da lista da qual o modelo escolhe. Você ainda pode invocá-lo com `$`.
- `allowed-tools`: uma lista de ferramentas (por exemplo `["execute_code"]`) que o agente recebe para aquele turno quando a skill é invocada com `$` ou sempre aplicada, mesmo que o agente normalmente não as tenha.
- `compatibility`: notas em texto livre sobre o que a skill precisa, como um servidor MCP específico. O LibreChat mantém esse campo, mas não o aplica.

`when-to-use` funciona no lugar de `description`, e `alwaysApply` no lugar de `always-apply`. As chaves não diferenciam maiúsculas de minúsculas, e outras chaves que você adicionar são mantidas como metadados.

### Arquivos incluídos [#bundled-files]

Uma skill pode conter mais de um arquivo. Um layout comum é `references/` para documentos longos, `scripts/` para código que o agente pode executar e `assets/` para modelos. O agente lê esses arquivos quando a skill está em uso, então `SKILL.md` pode permanecer curto e apontar para eles. Quando o Run Code está ativado, os arquivos também ficam disponíveis no sandbox em `/mnt/data/skills/<skill-name>/`. No visualizador de skills, links relativos entre os arquivos Markdown da skill abrem o arquivo vinculado.

Em um arquivo compactado, `SKILL.md` deve estar no nível superior ou dentro de exatamente uma pasta. Um envio é limitado a 50 MB por padrão (seu administrador pode alterar esse valor), 500 arquivos e 10 MB por arquivo; arquivos com caminhos não seguros são ignorados e informados. Uma skill com arquivos agrupados exibe uma seta ao lado do seu nome na barra lateral de Skills; expanda-a para navegar pelos arquivos e abrir um deles.

## Usar uma skill [#use-a-skill]

Existem três formas de uma skill chegar à conversa:

- **Você escolhe.** Digite `$` na caixa de chat e selecione uma skill. Nada é adicionado ao seu texto; a skill aparece como um chip acima do compositor e é carregada para essa mensagem.
- **O modelo escolhe.** O agente vê os nomes e as descrições das skills disponíveis para ele e carrega uma quando a sua solicitação corresponde a uma delas.
- **Ele é sempre aplicado.** Skills com `always-apply: true` são carregadas em todos os turnos.

Enquanto uma skill é carregada, a mensagem exibe **Loading** seguido do nome da skill e, em seguida, **Loaded** quando ela já está no contexto.

O modelo vê apenas os nomes e as descrições na sua lista (até 100 skills), e não as instruções. Uma skill que você escolher ou que for sempre aplicada carrega o seu `SKILL.md` completo para aquele turno. Um turno comporta até 10 skills escolhidas e 20 skills sempre aplicadas, totalizando 30; ao exceder esse limite, as skills sempre aplicadas são descartadas primeiro.

## Quais habilidades um agente pode usar [#which-skills-an-agent-can-use]

Duas coisas decidem isso.

Primeiro, a sua própria lista. Cada skill tem uma chave **Available to agent**. Desative-a e a skill some do menu `$`, das opções que o modelo pode escolher e do modo always-apply, sem ser excluída. As skills que você cria começam ativadas. As skills compartilhadas com você começam desativadas, a menos que o seu administrador tenha ativado skills compartilhadas por padrão.

Em segundo lugar, o agente. A seção **Skills** no Agent Builder tem três configurações:

- **Desligado**: o agente não usa nenhuma skill.
- **Todas**: todas as habilidades que você ativou.
- **Selecionado**: apenas as skills que você adicionar à lista.

**Selecionados** é a melhor escolha para um agente focado. Um agente de suporte com 40 habilidades para escolher vai errar a seleção com mais frequência do que um com as três de que precisa.

## Skills escritas por agentes [#skills-written-by-agents]

Um agente com skills ativadas também pode escrever skills enquanto trabalha, por exemplo, para salvar um procedimento que acabou de funcionar. Ele pode criar uma nova skill se a sua função tiver permissão para criar skills, e editar skills existentes somente se você puder editá-las e elas estiverem no escopo do agente. Skills do seu administrador permanecem somente leitura. Com **Selecionadas** e uma lista vazia, o agente não vê nenhuma das suas skills existentes, mas ainda pode criar novas.

## Compartilhamento [#sharing]

As Habilidades são compartilhadas da mesma forma que os agentes e os prompts, com os papéis Visualizador (pode usar, mas não pode editar), Editor e Proprietário. Compartilhar exige a permissão de compartilhamento no seu papel, que vem desativada por padrão para usuários comuns. Consulte [Controle de Acesso](/docs/features/access_control).

Seu administrador também pode fornecer skills, a partir do sistema de arquivos do servidor, de [Agent Plugins](/docs/features/agent_plugins), ou espelhadas de um repositório do GitHub. Elas são somente leitura no LibreChat; altere-as na origem. Skills do sistema de arquivos e de plugins começam ativadas.

## Configuração [#setup]

Skills estão ativadas por padrão para todos os usuários. Os administradores podem desativar o recurso com a capacidade de agente `skills` (consulte [configuração do endpoint de agentes](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)), controlar quem pode criar e compartilhar skills no [Painel de Administração](/docs/features/admin_panel) ou em [`interface.skills`](/docs/configuration/librechat_yaml/object_structure/interface#skills), fornecer skills a partir do disco ou do GitHub conforme descrito em [Skill Sync](/docs/configuration/librechat_yaml/object_structure/skill_sync), e alterar o limite de tamanho de upload com [`fileConfig.skills`](/docs/configuration/librechat_yaml/object_structure/file_config#skills).
