Admin Panel은 브라우저에서 LibreChat 인스턴스를 운영하기 위한 별도의 웹 앱입니다. 이를 사용하면 사용자, 그룹, 역할을 관리하고, 각 역할이 수행할 수 있는 작업을 결정하며, 관리자 권한을 부여하고, `librechat.yaml`을 편집하고 재시작하지 않고도 설정을 변경할 수 있습니다(모든 사용자 대상 또는 특정 역할이나 그룹만 대상으로 설정 가능).

이것은 고유한 URL을 가진 독립된 서비스이며, [LibreChat-AI/admin-panel](https://github.com/LibreChat-AI/admin-panel)에서 개발되었습니다. 자체 데이터는 보관하지 않습니다. 모든 변경 사항은 LibreChat의 관리자 API를 거쳐 LibreChat 데이터베이스에 저장됩니다.

## 로그인 [#signing-in]

LibreChat 계정으로 로그인합니다. 이메일과 비밀번호를 사용하거나, 인스턴스에 구성된 OpenID Connect나 Google 같은 싱글 사인온(SSO)을 사용할 수 있습니다. 해당 계정에는 `ADMIN` 역할이 있거나, 계정에 직접 부여되었거나 그룹 또는 역할을 통해 부여된 `access:admin` 권한이 있어야 합니다. LibreChat은 모든 요청마다 이 권한을 확인하므로, 패널이 계정이 가진 권한보다 더 많은 접근 권한을 스스로 부여할 수는 없습니다. 세션은 기본적으로 30분 동안 활동이 없으면 종료됩니다. SSO를 사용하는 경우 패널은 백그라운드에서 LibreChat 세션을 갱신하며, 갱신할 때마다 계정이 차단되지 않았는지와 여전히 관리자 권한이 있는지를 다시 확인합니다. 권한을 잃으면 패널 세션도 종료됩니다.

관리자 패널 URL이 설정되면, 관리자 권한이 있는 사용자는 LibreChat의 **설정 > 일반**에서 **관리자 패널** 링크를 확인할 수 있습니다. 그 밖의 사용자에게는 이 링크가 표시되지 않습니다.

## 할 수 있는 것 [#what-you-can-do]

사이드바 섹션은 주요 작업과 다음과 같이 대응됩니다:

- **사용자**: 인스턴스의 모든 계정을 나열하고 검색하며, 역할별로 필터링하고, 사용자를 역할에 추가하거나 역할에서 제거할 수 있습니다. (패널에 삭제 작업이 있지만, 현재 LibreChat은 관리자 API를 통한 삭제를 아직 지원하지 않으므로 대신 사용자 삭제 스크립트를 사용하십시오.)
- **접근 권한**: `USER`와 `ADMIN` 외에 사용자 지정 역할을 만들고 각 역할의 기능 권한을 편집할 수 있으며, 그룹을 생성하고 구성원을 관리할 수 있습니다. 여기서 만든 그룹과 역할은 LibreChat의 공유 대화상자에서 선택할 수 있습니다.
- **설정**: LibreChat의 설정을 폼 형태로 보고 편집할 수 있습니다. 폼은 LibreChat 자체의 설정 스키마에서 생성되므로, 패널을 업데이트하지 않아도 새로운 설정이 표시됩니다.
- **Grants**: 사용자, 그룹 또는 역할에 사용자 관리나 구성의 특정 섹션 편집과 같은 개별 관리자 기능을 부여하되, 전체 관리자 권한은 주지 않습니다.

각 사용자가 패널에서 보는 내용은 해당 사용자의 권한(capabilities)에 따라 달라집니다. 예를 들어 `interface` 섹션만 관리할 수 있는 사용자에게는 그 섹션만 표시됩니다. 역할을 읽기만 할 수 있는 사용자는 역할을 볼 수 있지만 변경할 수는 없습니다. 접근 관련 권한이 하나도 없는 사용자에게는 해당 섹션에 대해 접근 거부 페이지가 표시됩니다.

## 특정 역할 및 그룹에 대한 구성 [#configuration-for-specific-roles-and-groups]

기본 프로필은 모든 사용자에게 적용되며, 그 밖에 특정 역할, 그룹 또는 사용자 하나에 대해 재정의 설정을 프로필로 저장할 수 있습니다. 프로필에는 변경한 설정만 저장되고, 나머지 설정은 상위 설정을 그대로 상속합니다. 각 프로필에는 우선순위가 있으며(역할 프로필은 기본값 10, 그룹 프로필은 20, 사용자 프로필은 100), LibreChat은 사용자의 설정을 구성할 때 `librechat.yaml`과 기본 프로필에서 시작하여 해당 사용자에게 일치하는 프로필을 가장 낮은 우선순위부터 가장 높은 우선순위 순으로 적용합니다. 따라서 기본적으로 사용자 프로필이 그룹 또는 역할 프로필보다 우선합니다. 이 방식을 사용하면 두 번째 인스턴스를 실행하지 않고도 연구 그룹에 추가 엔드포인트를 제공하거나, 외주 계약자에게 더 엄격한 인터페이스를 적용할 수 있습니다.

설정을 편집할 때 알아두어야 할 몇 가지 사항:

- 변경 사항은 `librechat.yaml`과 동일한 규칙으로 검사됩니다. 설정을 잘못되게 만드는 편집은 거부되며 아무것도 저장되지 않습니다. 업그레이드로 인해 이전에 저장된 값이 잘못된 값이 되면, LibreChat은 해당 필드를 무시하고 그 아래 계층의 값으로 대체한 뒤 경고를 로그에 남깁니다. 따라서 업그레이드 후에는 로그를 확인하세요.
- API 키와 웹 검색, 음성, OCR, Langfuse 또는 사용자 지정 엔드포인트 등에 입력한 기타 비밀 정보는 암호화되어 저장되며, 이후에는 마스킹된 상태로만 표시됩니다. 저장된 키가 전송되는 위치(예: 서버 또는 기본 URL)를 변경하는 경우에는 키를 다시 입력해야 합니다.
- `${ENV_VAR}` 참조는 LibreChat이 이미 인식하고 있거나 운영자가 허용한 변수에 대해서만 허용됩니다.
- 일부 설정은 `librechat.yaml`에서만 지정할 수 있습니다. 여기에는 로컬 프로세스를 실행하는 MCP 서버(`type: stdio`, 또는 `command`, `args`, `env`)와 Langfuse 게이트웨이 헤더가 포함됩니다. 패널에서는 이러한 설정을 추가, 변경, 삭제할 수 없습니다. 원격 MCP 서버는 일반적인 방식으로 관리할 수 있습니다.

기능 권한은 재정의(override)가 아닙니다. 역할이 에이전트, 프롬프트 등을 사용하거나 공유할 수 있는지를 결정하는 스위치는 역할 자체의 **Access**에서 편집합니다. 역할, 그룹, 기능이 어떻게 결합되는지는 [Access Control](/docs/features/access_control)을 참조하십시오. 에이전트별 사용량은 LibreChat 내부의 별도 [Insights](/docs/features/insights) 대시보드에 있습니다.

## 설정 [#setup]

이 패널은 LibreChat의 `docker-compose.yml` 및 `deploy-compose.yml`에 `admin-panel` 서비스로 포함되어 있으며, `.env`에 `ADMIN_PANEL_SESSION_SECRET`을 설정하기 전에는 시작되지 않습니다. LibreChat v0.8.5 이상이 필요합니다. 포트, 별도 도메인에서의 호스팅, SSO 리디렉션, 모든 환경 변수, 그리고 패널이 사용하는 관리자 API는 [Admin Panel 구성](/docs/configuration/admin_panel)에서 다룹니다.
