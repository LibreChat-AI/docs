Een Agent-plugin is een map op de LibreChat-server die [Skills](/docs/features/skills), [MCP-servers](/docs/features/mcp) en optionele command-hooks bundelt die bij elkaar horen. Een beheerder plaatst de map in de plugin-directory en herstart LibreChat; er is niets via de UI te installeren. LibreChat volgt het open Agent Plugins `1.0.0`-pakketformaat, zodat één pakket gedeeld kan worden met andere tools die dit ondersteunen.

Agent Plugins zijn experimenteel. Het pakketformaat en het gedrag kunnen veranderen.

## Wat gebruikers zien [#what-users-see]

Gebruikers zien nooit een plugin als zodanig. Ze zien wat erin zit:

- Hun vaardigheden verschijnen in de lijst met vaardigheden naast andere vaardigheden. Ze zijn alleen-lezen, volgen de gebruikelijke machtigingen voor vaardigheden en kunnen net als elke andere vaardigheid aan of uit worden gezet met **Beschikbaar voor agent**.
- Zijn MCP-servers verschijnen in de Tool Library en kunnen aan agents worden toegevoegd, net als servers die zijn gedefinieerd in `librechat.yaml`.
- De hooks draaien op de server op bepaalde momenten tijdens een agentrun, zoals vóór een toolaanroep of wanneer de run stopt. Een hook kan een toolaanroep blokkeren, context aan de prompt toevoegen of een run stoppen, en de gebruiker ziet alleen het resultaat ervan.

Als de naam van een skill of MCP-server overeenkomt met een naam die elders is gedefinieerd, wint de andere definitie: een skill in de zelfstandige skills-map van de deployment heeft voorrang op een plugin-skill, en een server in `librechat.yaml` heeft voorrang op een plugin-server.

## Wat een plugin kan bevatten [#what-a-plugin-can-contain]

Een plugin-map bevat een `plugin.json`-manifest en een of meer van:

- `skills/`, één map per skill, elk met een `SKILL.md`.
- `mcp.json`, MCP-serverdefinities. Lokale (`stdio`) servers draaien vanuit de plugin-map en krijgen hun eigen persistente gegevensmap.
- `ai.librechat/hooks/hooks.json`, command hooks. Deze worden als processen op de API-host uitgevoerd en zijn uitgeschakeld tenzij de beheerder ze inschakelt.

Elk onderdeel wordt afzonderlijk geladen, dus een defect `mcp.json` verhindert niet dat de skills van de plugin worden geladen. Problemen worden gerapporteerd in de opstartlogs.

## Setup [#setup]

Plugins worden standaard geladen uit `./plugin` in de hoofdmap van het project, en command hooks staan standaard uit. Zie [Agent Plugins configuration](/docs/configuration/agent_plugins) voor de instellingen van de map, de pakketstructuur, de validatieregels voor manifest en MCP, en het uitvoeringscontract van hooks.
