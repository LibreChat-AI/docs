临时聊天允许您在不保存记录的情况下进行提问。您可以将其用于敏感话题、快速实验或任何您无需保存的内容。临时聊天不会出现在您的历史记录侧边栏中，不会出现在搜索结果中，无法被收藏，并且会在保留期结束后（默认为 30 天）自动删除。

同样的机制也为管理员提供了**数据保留**功能：LibreChat 可以为每个对话设置过期日期，或者强制整个部署中的所有聊天记录均为临时会话。

<Callout type="info" title="同一页面上的两个受众">
  [使用临时聊天](#using-temporary-chat)适用于所有人。[数据保留](#data-retention)
及后续内容适用于配置 `librechat.yaml` 的管理员。每个选项也列在
[界面参考](/docs/configuration/librechat_yaml/object_structure/interface#temporarychat)中。
</Callout>

## 使用临时聊天 (Temporary Chat) [#using-temporary-chat]

### 开启临时聊天 [#start-a-temporary-chat]

开始一个新的聊天，然后在发送第一条消息之前开启 **Temporary Chat**：

- **桌面端：** 选择聊天标题最右侧的 **Temporary Chat** 按钮（一个帽子和眼镜的图标）。将鼠标悬停在其上可查看键盘快捷键。
- **移动端：** 打开页眉菜单并选择 **Temporary Chat**。出现勾选标记即表示已开启。
- **键盘：** 按 `Ctrl+Shift+Y`（macOS 上为 `Cmd+Shift+Y`）。

![聊天标题栏最右侧的临时聊天按钮及其工具提示](/images/temporary-chat/temporary-chat-button.png)

当该功能开启时，登录视图会显示 **Temporary Chat**，并附带提示“此对话不会出现在您的历史记录中，并将自动删除。”，同时消息框会带有色调。再次选择该按钮即可将其关闭。

![一个新的临时聊天：临时聊天着陆消息和带色调的消息框](/images/temporary-chat/temporary-chat-active.png)

该开关仅在第一条消息发送前可用。一旦对话开始，标题栏中会显示一个只读的 **Temporary Chat** 徽章，以便您随时确认该对话不会被保存。

### 将每个新对话设为临时对话 [#make-every-new-chat-temporary]

若要将所有新对话设为临时对话，请打开 **Settings > Chat** 并开启 **Temporary Chat by default**。此偏好设置存储在您的浏览器中，因此请在您使用的每台设备上进行设置。

### 临时对话的作用 [#what-a-temporary-chat-does]

- 它不会出现在聊天记录侧边栏中。
- 它已从搜索结果中排除。
- 它无法被收藏。
- 它不会获得自动生成的标题。
- 它会被保留至保留期结束，然后自动删除。默认期限为 30 天；您的管理员可能会设置不同的期限。

保留策略适用于对话、消息、文件和共享链接。[Memories](/docs/features/memory) 不会在临时聊天过期时被删除。

<Callout type="note" title="管理员强制执行的临时聊天">
  如果您的管理员已将所有聊天设置为临时聊天，则 **Temporary Chat** 按钮将始终处于开启状态且无法关闭。将鼠标悬停或聚焦于该按钮时，会显示“Temporary Chat is enabled for all chats by your administrator”，且键盘快捷键将不起作用。
</Callout>

## 数据保留 [#data-retention]

管理员可以通过 `librechat.yaml` 中 `interface` 下的几个选项来控制保留策略。其中主要的是 `retentionMode`，它决定了哪些对话会获得过期日期：

| 模式 | 过期内容 | 历史记录和搜索中是否可见聊天记录？ | 用户能否选择退出？ |
| ----------------------- | ------------------------------------ | --------------------------------------- | -------------------- |
| `temporary` _(默认)_ | 仅用户标记为临时的聊天 | 普通聊天可见，临时聊天不可见 | 是，可逐个聊天设置 |
| `all`                   | 所有聊天 | 是，直到每个聊天过期为止 | 否 |
| `ephemeral`             | 所有聊天 | 否，所有聊天均为临时 | 否，开关已锁定 |

默认值为 `temporary`，因此现有的部署将保持其当前行为，直到您对其进行更改。

### 配置 [#configuration]

```yaml filename="librechat.yaml"
interface:
  # Who may use the Temporary Chat toggle (seeds the TEMPORARY_CHAT permission for the USER role)
  temporaryChat: true

  # Which chats expire: "temporary" (default), "all", or "ephemeral"
  retentionMode: 'temporary'

  # Lifetime of temporary chats, in hours. Default 720 (30 days), range 1 to 8760.
  temporaryChatRetention: 720

  # Lifetime of regular chats under retentionMode "all", in hours. Defaults to temporaryChatRetention.
  # generalChatRetention: 2160

  # Under "all" or "ephemeral", keep files uploaded to agents (knowledge and context files) from expiring.
  retainAgentFiles: false
```

| 键 | 类型 | 默认值 | 描述 |
| ------------------------ | ----------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `retentionMode`          | `"temporary"` \| `"all"` \| `"ephemeral"` | `"temporary"`            | 哪些聊天会收到过期日期。请参阅 [The three modes](#the-three-modes)。 |
| `temporaryChatRetention` | number (小时)                            | `720`                    | 临时聊天在最后一次保存后保留的时长。同时也是 `ephemeral` 模式下每个聊天的生命周期。范围为 `1` 到 `8760`。 |
| `generalChatRetention`   | number (小时)                            | `temporaryChatRetention` | `all` 模式下常规聊天保留的时长。其他模式将忽略此项。范围为 `1` 到 `8760`。 |
| `retainAgentFiles`       | boolean                                   | `false`                  | 在 `all` 和 `ephemeral` 模式下，上传到智能体资源的文件不会过期。附加到消息的文件仍会随其聊天记录一同过期。 |
| `temporaryChat`          | boolean                                   | `true`                   | 在启动时为内置的 `USER` 角色植入 `TEMPORARY_CHAT` 权限。可在 [Admin Panel](/docs/features/admin_panel) 中按角色管理该权限。 |

`librechat.yaml` 中的值如果不在 `1` 到 `8760` 小时之间，将无法通过配置验证。

#### 环境变量 [#environment-variable]

临时聊天记录的生命周期也可以通过 `TEMP_CHAT_RETENTION_HOURS` 进行设置。当两者同时设置时，`interface.temporaryChatRetention` 具有优先权。无效的值将回退至 `720`，而超出 `1` 到 `8760` 范围的值将被限制在该范围内，并在服务器日志中发出警告。

<Callout type="warning" title="优先使用 librechat.yaml">
  `TEMP_CHAT_RETENTION_HOURS` 已弃用。请改用 `interface.temporaryChatRetention`。
</Callout>

### 三种模式 [#the-three-modes]

<Tabs items={['临时', '全部', '临时']}>
  <Tabs.Tab>
    **`temporary` (默认)。** 仅用户标记为临时的对话会过期，无论是通过开关还是通过 **Temporary Chat by default** 设置。它们在历史记录和搜索中被隐藏，并在 `temporaryChatRetention` 小时后被删除。普通对话永不过期。
  </Tabs.Tab>
  <Tabs.Tab>
    **`all`。** 每个对话和消息都会获得一个过期日期，但聊天体验不会改变：聊天记录会保留在历史记录和搜索中，直到它们过期为止。

    - 常规聊天使用 `generalChatRetention`，若未设置，则使用 `temporaryChatRetention`。
    - 用户标记为临时的对话仍会表现为临时对话，并使用 `temporaryChatRetention`。
    - 上传的文件和共享链接也会过期。代理资源文件仅在设置 `retainAgentFiles: true` 时才会保留。

    使用 `all` 来设置“保留所有内容 N 天，然后删除”的策略。

  </Tabs.Tab>
  <Tabs.Tab>
    **`ephemeral`。** 每次聊天都是临时的。这相当于为整个部署开启了“始终启用临时聊天”。

    - 每个聊天记录都会从历史记录和搜索中隐藏，不会生成标题，并在 `temporaryChatRetention` 小时后被删除。`generalChatRetention` 将被忽略。
    - **Temporary Chat** 开关对所有人强制开启，包括那些角色权限中缺少 `TEMPORARY_CHAT` 权限的用户。键盘快捷键已被禁用。
    - 服务器会强制执行此规则：客户端发送的 `isTemporary: false` 将会被覆盖。
    - 上传的文件和共享链接会随其聊天记录一起过期。代理资源文件仅在设置 `retainAgentFiles: true` 时才会保留。

    当不需要长期保存对话时，请使用 `ephemeral`。

  </Tabs.Tab>
</Tabs>

### 保留机制的工作原理 [#how-retention-works]

每个对话和消息都带有 `expiredAt` 日期，临时对话还会被标记为 `isTemporary: true`。隐藏和过期的记录在被删除之前，会从历史记录列表和搜索索引中过滤掉。

- **对话、消息和共享链接**由 MongoDB 的 `expiredAt` TTL 索引移除。MongoDB 会在后台运行此清理任务，通常在截止时间后的一分钟内完成。
- **Files** 会由 LibreChat 中的定期清理任务移除，该任务会删除存储的文件（本地磁盘、S3 等）及其记录。

截止日期在记录保存时设定。每次保存对话都会推迟其截止日期，因此活跃的聊天记录在被使用时会一直保留。每条消息都会保留其保存时获得的截止日期。

在 `all` 和 `ephemeral` 下，保留策略适用于所有写入聊天数据的地方：每个 endpoint 上的新消息、重新生成和分支、消息编辑、反馈、Artifact 编辑、恢复的响应、分叉、副本和导入。

- **Forks, duplicates and imports.** 在 `ephemeral` 下，它们始终是临时的。在 `all` 下，临时对话的副本仍保持临时状态，而其他副本和导入内容则会保留并带有过期日期。
- **Shared links** 的有效期取决于它们所指向的对话，因此链接的生命周期永远不会超过其对应的聊天记录。
- **Memories** 没有过期时间，也不受任何保留模式的影响。

### 切换模式 [#switching-modes]

更改 `retentionMode` 或保留期限只会影响之后保存的记录。LibreChat 不会重写现有的截止日期。

- **设置为 `all` 或 `ephemeral`：** 现有聊天记录将在下次写入时获得截止日期。在 `ephemeral` 模式下，当旧的常规聊天收到新消息、编辑、反馈或分支时，它会立即转换为临时聊天：它将脱离历史记录和搜索，并丢失其书签。无人触碰的聊天将保持其当前状态。
- **回到 `temporary`：** 在 `all` 下保存的聊天记录仍然带有截止日期，并且仍会被删除。在 `ephemeral` 下保存的聊天记录保持为临时聊天，并继续过期。

若要停止常规聊天在离开 `all` 或 `ephemeral` 后过期，请在 `mongosh` 中清除其截止日期：

```js filename="mongosh"
db.conversations.updateMany(
  { isTemporary: false, expiredAt: { $ne: null } },
  { $unset: { expiredAt: 1 } },
)
db.messages.updateMany(
  { isTemporary: false, expiredAt: { $ne: null } },
  { $unset: { expiredAt: 1 } },
)
```

<Callout type="info" title="升级后搜索索引">
  MongoDB 不会自动删除被取代的索引。一旦新的 `_meiliIndex_1_isTemporary_1_expiredAt_1` 索引在 `conversations` 和 `messages` 集合中创建完成，你就可以从这两个集合中删除旧的 `_meiliIndex_1_expiredAt_1` 索引了。
</Callout>

### 示例 [#examples]

在最后一次活动 90 天后删除所有聊天记录，并在此之前保持聊天记录可见：

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'all'
  generalChatRetention: 2160 # 90 days for regular chats
  temporaryChatRetention: 24 # 1 day for chats users mark as temporary
```

使每次聊天都变为临时聊天，并在 24 小时后将其删除：

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'ephemeral'
  temporaryChatRetention: 24
```

将所有聊天记录设置为一周后自动删除，但保留附加到 Agent 的文件：

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'ephemeral'
  temporaryChatRetention: 168
  retainAgentFiles: true
```

## 常见问题解答 [#faq]

<Accordions>

<Accordion title="保留期限是从创建聊天时开始计算，还是从最后一次使用时开始计算？">
  对话最后一次保存的时间。每条新消息都会推迟对话的截止日期，因此活跃的聊天记录在被使用时不会被删除。
</Accordion>

<Accordion title="聊天记录过期后会立即删除吗？">
  并非精确到秒。MongoDB 会在后台处理中删除过期的对话和消息，通常在一分钟内完成，而文件则由 LibreChat 的定期清理任务删除。在此之前，过期的聊天记录对用户而言已经是隐藏状态。
</Accordion>

<Accordion title="all 和 ephemeral 之间有什么区别？">
  `all` 会使聊天记录保持正常并可见，并带有按日期删除的功能。`ephemeral` 会使所有聊天记录变为临时状态：在历史记录和搜索中隐藏，且开关处于锁定开启状态。选择 `all` 可实现“N 天后删除”，选择 `ephemeral` 可实现“从不保留对话”。
</Accordion>

<Accordion title="用户可以在 ephemeral 下关闭 Temporary Chat 吗？">
  不可以。该开关已锁定为开启状态，服务器会覆盖任何将聊天记录保存为永久的请求。
</Accordion>

<Accordion title="共享链接的有效期可以超过其对应的对话吗？">
  不会。共享链接的过期时间不会晚于其所指向的对话的过期时间。
</Accordion>

</Accordions>
