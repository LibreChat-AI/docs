임시 채팅을 사용하면 대화 내용을 저장하지 않고 질문할 수 있습니다. 민감한 주제, 간단한 실험 또는 저장할 필요가 없는 모든 작업에 사용하세요. 임시 채팅은 기록 사이드바에 표시되지 않고, 검색 결과에도 나타나지 않으며, 즐겨찾기에 추가할 수 없습니다. 또한 보존 기간(기본값 30일)이 지나면 자동으로 삭제됩니다.

동일한 메커니즘이 관리자를 위한 **데이터 보존(data retention)** 기능을 지원합니다. LibreChat은 모든 대화에 만료 날짜를 설정하거나, 전체 배포 환경에서 모든 채팅을 일시적으로 강제할 수 있습니다.

<Callout type="info" title="한 페이지에 두 개의 대상">
  [임시 채팅 사용하기](#using-temporary-chat)는 모든 사용자를 위한 기능입니다. [데이터 보존](#data-retention)부터는 `librechat.yaml`을 구성하는 관리자를 위한 내용입니다. 각 옵션은 [인터페이스 참조](/docs/configuration/librechat_yaml/object_structure/interface#temporarychat)에도 나열되어 있습니다.
</Callout>

## 임시 채팅 사용하기 [#using-temporary-chat]

### 임시 채팅 시작하기 [#start-a-temporary-chat]

새 채팅을 시작한 다음, 첫 메시지를 보내기 전에 **Temporary Chat**을 켜세요:

- **Desktop:** 채팅 헤더 오른쪽 끝에 있는 **Temporary Chat** 버튼(모자와 안경 아이콘)을 선택하세요. 마우스를 올리면 키보드 단축키가 표시됩니다.
- **모바일:** 헤더 메뉴를 열고 **Temporary Chat**을 선택하세요. 체크 표시가 나타나면 활성화된 것입니다.
- **키보드:** `Ctrl+Shift+Y` (macOS에서는 `Cmd+Shift+Y`)를 누르세요.

![채팅 헤더 오른쪽 끝에 있는 임시 채팅(Temporary Chat) 버튼과 해당 툴팁](/images/temporary-chat/temporary-chat-button.png)

이 기능이 켜져 있는 동안, 랜딩 뷰에는 **Temporary Chat**이 표시되며 "This chat won't appear in your history and will be deleted automatically."라는 문구가 나타나고, 메시지 입력창의 색상이 변경됩니다. 버튼을 다시 선택하면 이 기능을 끌 수 있습니다.

![새로운 임시 채팅: 임시 채팅 랜딩 메시지와 색조가 적용된 메시지 상자](/images/temporary-chat/temporary-chat-active.png)

이 토글은 첫 번째 메시지를 보내기 전에만 사용할 수 있습니다. 대화가 시작되면 헤더에 읽기 전용 **Temporary Chat** 배지가 유지되므로, 해당 대화가 저장되지 않는다는 것을 항상 확인할 수 있습니다.

### 모든 새 채팅을 임시 채팅으로 만들기 [#make-every-new-chat-temporary]

모든 새 채팅을 임시 채팅으로 시작하려면 **Settings > Chat**을 열고 **Temporary Chat by default**를 켭니다. 이 설정은 브라우저에 저장되므로 사용하는 각 기기에서 설정해야 합니다.

### 임시 채팅의 기능 [#what-a-temporary-chat-does]

- 채팅 기록 사이드바에는 나타나지 않습니다.
- 검색 결과에서 제외됩니다.
- 북마크할 수 없습니다.
- 자동으로 생성된 제목이 지정되지 않습니다.
- 보존 기간이 끝날 때까지 보관된 후 자동으로 삭제됩니다. 기본 기간은 30일이며, 관리자가 다른 기간으로 설정했을 수 있습니다.

보존(Retention)은 대화, 메시지, 파일 및 공유 링크에 적용됩니다. [Memories](/docs/features/memory)는 임시 채팅이 만료되어도 삭제되지 않습니다.

<Callout type="note" title="관리자가 강제하는 임시 채팅">
  관리자가 모든 채팅을 임시 채팅으로 설정한 경우, **Temporary Chat** 버튼은 항상 켜져 있으며 끌 수 없습니다. 해당 버튼에 마우스를 올리거나 포커스를 맞추면 "Temporary Chat is enabled for all chats by your administrator"라는 메시지가 표시되며, 키보드 단축키는 작동하지 않습니다.
</Callout>

## 데이터 보존 [#data-retention]

관리자는 `librechat.yaml`의 `interface` 아래에 있는 몇 가지 옵션을 통해 보존 기간을 제어합니다. 주요 옵션은 `retentionMode`이며, 이는 어떤 채팅에 만료 날짜를 적용할지 결정합니다:

| 모드 | 만료 대상 | 기록 및 검색에서 채팅 표시 여부 | 사용자 선택 해제 가능 여부 |
| ----------------------- | ------------------------------------ | --------------------------------------- | -------------------- |
| `temporary` _(기본값)_ | 사용자가 임시로 표시한 채팅만 | 일반 채팅은 표시됨, 임시 채팅은 표시 안 됨 | 예, 채팅별로 가능 |
| `all` | 모든 채팅 | 예, 각 채팅이 만료될 때까지 | 아니요 |
| `ephemeral` | 모든 채팅 | 아니요, 모든 채팅이 임시로 처리됨 | 아니요, 토글이 고정됨 |

기본값은 `temporary`이므로, 설정을 변경하기 전까지 기존 배포는 현재 동작을 유지합니다.

### 구성 [#configuration]

```yaml filename="librechat.yaml"
interface:
  # Who may use the Temporary Chat toggle (seeds the TEMPORARY_CHAT permission for the USER role)
  temporaryChat: true

  # Which chats expire: "temporary" (default), "all", or "ephemeral"
  retentionMode: 'temporary'

  # Lifetime of temporary chats, in hours. Default 720 (30 days), range 1 to 8760.
  temporaryChatRetention: 720

  # Lifetime of regular chats under retentionMode "all", in hours. Defaults to temporaryChatRetention.
  # generalChatRetention: 2160

  # Under "all" or "ephemeral", keep files uploaded to agents (knowledge and context files) from expiring.
  retainAgentFiles: false
```

| 키 | 타입 | 기본값 | 설명 |
| ------------------------ | ----------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `retentionMode`          | `"temporary"` \| `"all"` \| `"ephemeral"` | `"temporary"`            | 만료일이 적용될 채팅을 설정합니다. [The three modes](#the-three-modes)를 참조하세요. |
| `temporaryChatRetention` | number (hours)                            | `720`                    | 임시 채팅이 마지막으로 저장된 후 유지되는 시간입니다. `ephemeral` 모드에서의 모든 채팅 수명이기도 합니다. 범위는 `1`에서 `8760`까지입니다. |
| `generalChatRetention`   | number (hours)                            | `temporaryChatRetention` | `all` 모드에서 일반 채팅이 유지되는 시간입니다. 다른 모드에서는 무시됩니다. 범위는 `1`에서 `8760`까지입니다. |
| `retainAgentFiles`       | boolean                                   | `false`                  | `all` 및 `ephemeral` 모드에서 에이전트 리소스에 업로드된 파일은 만료되지 않습니다. 메시지에 첨부된 파일은 여전히 채팅과 함께 만료됩니다. |
| `temporaryChat`          | boolean                                   | `true`                   | 시작 시 내장 `USER` 역할에 대한 `TEMPORARY_CHAT` 권한을 설정합니다. [Admin Panel](/docs/features/admin_panel)에서 역할별로 권한을 관리하세요. |

`librechat.yaml`의 값이 `1`에서 `8760` 시간 범위를 벗어나면 설정 유효성 검사에 실패합니다.

#### 환경 변수 [#environment-variable]

임시 채팅 유지 기간은 `TEMP_CHAT_RETENTION_HOURS`로도 설정할 수 있습니다. 두 설정이 모두 지정된 경우 `interface.temporaryChatRetention`이 우선합니다. 유효하지 않은 값이 설정되면 `720`으로 대체되며, `1`에서 `8760` 범위를 벗어나는 값은 해당 범위 내로 제한되고 서버 로그에 경고가 기록됩니다.

<Callout type="warning" title="librechat.yaml 우선 사용">
  `TEMP_CHAT_RETENTION_HOURS`는 더 이상 사용되지 않습니다. 대신 `interface.temporaryChatRetention`을 사용하세요.
</Callout>

### 세 가지 모드 [#the-three-modes]

<Tabs items={['임시', '모두', '일시적']}>
  <Tabs.Tab>
    **`temporary` (기본값).** 사용자가 토글을 통해 표시하거나 **Temporary Chat by default** 설정을 통해 표시한 임시 채팅만 만료됩니다. 이러한 채팅은 기록 및 검색에서 숨겨지며 `temporaryChatRetention` 시간이 지나면 삭제됩니다. 일반 채팅은 절대 만료되지 않습니다.
  </Tabs.Tab>
  <Tabs.Tab>
    **`all`.** 모든 대화와 메시지에 만료일이 설정되지만, 채팅 경험은 변하지 않습니다. 채팅은 만료될 때까지 기록 및 검색에 그대로 유지됩니다.

    - 일반 채팅은 `generalChatRetention`을 사용하며, 설정되지 않은 경우 `temporaryChatRetention`을 사용합니다.
    - 사용자가 임시로 표시한 채팅은 여전히 임시 채팅으로 동작하며 `temporaryChatRetention`을 사용합니다.
    - 업로드된 파일과 공유 링크도 만료됩니다. 에이전트 리소스 파일은 `retainAgentFiles: true`로 설정된 경우에만 유지됩니다.

    "N일 동안 모든 데이터를 보관한 후 삭제"하는 정책을 설정하려면 `all`을 사용하세요.

  </Tabs.Tab>
  <Tabs.Tab>
    **`ephemeral`.** 모든 대화는 일시적입니다. 이는 전체 배포에 대해 "항상 임시 대화(Temporary Chat always on)" 모드를 활성화하는 설정입니다.

    - 모든 채팅은 기록 및 검색에서 숨겨지며, 생성된 제목이 없고 `temporaryChatRetention` 시간이 지나면 삭제됩니다. `generalChatRetention`은 무시됩니다.
    - **Temporary Chat** 토글은 `TEMPORARY_CHAT` 권한이 없는 사용자를 포함한 모든 사용자에게 강제로 활성화되어 있습니다. 키보드 단축키는 비활성화되었습니다.
    - 서버가 이를 강제합니다: `isTemporary: false`를 전송하는 클라이언트는 재정의됩니다.
    - 업로드된 파일과 공유 링크는 해당 채팅과 함께 만료됩니다. 에이전트 리소스 파일은 `retainAgentFiles: true`로 설정된 경우에만 유지됩니다.

    대화 내용을 장기적으로 보관할 필요가 없을 때는 `ephemeral`을 사용하세요.

  </Tabs.Tab>
</Tabs>

### 보존(retention) 작동 방식 [#how-retention-works]

각 대화와 메시지에는 `expiredAt` 날짜가 포함되어 있으며, 임시 대화는 `isTemporary: true`로 표시됩니다. 숨겨진 레코드와 만료된 레코드는 삭제되기 전에 기록 목록 및 검색 인덱스에서 필터링됩니다.

- **대화, 메시지 및 공유 링크**는 `expiredAt`에 설정된 MongoDB TTL 인덱스에 의해 제거됩니다. MongoDB는 일반적으로 마감 시간으로부터 약 1분 이내에 백그라운드에서 이 정리 작업을 실행합니다.
- **Files**는 LibreChat에서 주기적인 스윕(sweep)을 통해 제거되며, 이 과정에서 저장된 파일(로컬 디스크, S3 등)과 해당 레코드가 삭제됩니다.

마감 기한은 레코드가 저장될 때 설정됩니다. 대화를 저장할 때마다 마감 기한이 뒤로 미뤄지므로, 활발하게 사용 중인 채팅은 유지됩니다. 각 메시지는 저장될 때 부여받은 마감 기한을 그대로 유지합니다.

`all` 및 `ephemeral` 하에서 보존 정책은 채팅 데이터가 기록되는 모든 곳에 적용됩니다: 모든 endpoint의 새 메시지, 재생성 및 브랜치, 메시지 수정, 피드백, 아티팩트 수정, 재개된 응답, 포크, 복제 및 가져오기.

- **Forks, duplicates and imports.** `ephemeral` 하에서는 항상 임시 상태로 유지됩니다. `all` 하에서는 임시 대화의 복사본은 임시 상태로 유지되며, 다른 복사본 및 가져오기(import)는 만료 날짜와 함께 계속 표시됩니다.
- **Shared links**의 만료 기한은 해당 링크가 가리키는 대화의 만료 기한을 따르므로, 링크가 채팅보다 오래 지속되지 않습니다.
- **Memories**는 만료 기한이 없으며 어떠한 보존 모드(retention mode)의 영향도 받지 않습니다.

### 모드 전환 [#switching-modes]

`retentionMode` 또는 보존 기간을 변경해도 이후에 저장된 기록에만 영향을 미칩니다. LibreChat은 기존 마감 기한을 다시 작성하지 않습니다.

- **`all` 또는 `ephemeral`로 설정 시:** 기존 채팅은 다음에 작성될 때 마감 기한이 설정됩니다. `ephemeral` 설정 하에서는 새로운 메시지, 수정, 피드백 또는 브랜치가 추가되는 기존 일반 채팅이 즉시 임시 채팅으로 변환됩니다. 이 경우 기록 및 검색에서 제외되며 북마크도 손실됩니다. 아무도 건드리지 않은 채팅은 현재 상태를 유지합니다.
- **`temporary`로 돌아가기:** `all` 아래에 저장된 채팅은 여전히 마감 기한이 적용되며 삭제됩니다. `ephemeral` 아래에 저장된 채팅은 임시 채팅으로 유지되며 계속해서 만료됩니다.

`all` 또는 `ephemeral`을 떠난 후 일반 채팅이 만료되지 않도록 하려면 `mongosh`에서 해당 마감 기한을 삭제하세요:

```js filename="mongosh"
db.conversations.updateMany(
  { isTemporary: false, expiredAt: { $ne: null } },
  { $unset: { expiredAt: 1 } },
)
db.messages.updateMany(
  { isTemporary: false, expiredAt: { $ne: null } },
  { $unset: { expiredAt: 1 } },
)
```

<Callout type="info" title="업그레이드 후 검색 인덱스">
  MongoDB는 대체된 인덱스를 스스로 삭제하지 않습니다. `conversations` 및 `messages` 컬렉션에 새로운 `_meiliIndex_1_isTemporary_1_expiredAt_1` 인덱스가 생성되면, 두 컬렉션에서 이전 `_meiliIndex_1_expiredAt_1` 인덱스를 삭제할 수 있습니다.
</Callout>

### 예시 [#examples]

마지막 활동 후 90일이 지난 모든 대화를 삭제하고, 그 전까지는 대화를 계속 표시합니다:

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'all'
  generalChatRetention: 2160 # 90 days for regular chats
  temporaryChatRetention: 24 # 1 day for chats users mark as temporary
```

모든 대화를 임시로 설정하고 24시간 후에 삭제합니다:

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'ephemeral'
  temporaryChatRetention: 24
```

모든 채팅을 일주일 동안만 임시로 유지하되, 에이전트에 첨부된 파일은 유지하세요:

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'ephemeral'
  temporaryChatRetention: 168
  retainAgentFiles: true
```

## FAQ [#faq]

<Accordions>

<Accordion title="보존 기간은 채팅이 생성된 시점부터 시작되나요, 아니면 마지막으로 사용된 시점부터 시작되나요?">
  대화가 마지막으로 저장된 시점입니다. 새로운 메시지가 추가될 때마다 대화의 마감 기한이 연장되므로, 활발히 사용 중인 대화는 삭제되지 않습니다.
</Accordion>

<Accordion title="채팅이 만료되는 즉시 삭제되나요?">
  초 단위까지 정확하지는 않습니다. MongoDB는 백그라운드 작업을 통해 만료된 대화와 메시지를 삭제하며, 보통 1분 정도 소요됩니다. 파일은 LibreChat의 주기적인 정리 작업을 통해 삭제됩니다. 만료된 채팅은 그 이전부터 이미 사용자에게 숨겨집니다.
</Accordion>

<Accordion title="all과 ephemeral의 차이점은 무엇인가요?">
  `all`은 채팅을 정상적으로 표시하며, 설정된 날짜에 따라 삭제합니다. `ephemeral`은 모든 채팅을 일시적으로 만들어 기록 및 검색에서 숨기고, 토글을 고정합니다. "N일 후 삭제"를 원하면 `all`을, "대화를 절대 저장하지 않음"을 원하면 `ephemeral`을 선택하세요.
</Accordion>

<Accordion title="사용자가 ephemeral 아래에서 Temporary Chat을 끌 수 있나요?">
  아니요. 토글은 켜진 상태로 고정되어 있으며, 서버는 대화를 영구적으로 저장하라는 모든 요청을 무시합니다.
</Accordion>

<Accordion title="공유 링크가 해당 채팅보다 오래 지속될 수 있나요?">
  아니요. 공유 링크는 해당 링크가 가리키는 대화보다 늦게 만료되지 않습니다.
</Accordion>

</Accordions>
