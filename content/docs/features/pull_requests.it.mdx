Quando un agente lavora su un repository in un workspace di codice collegato, LibreChat individua la pull request relativa al branch su cui si trova il workspace e la mostra accanto alla chat. Puoi vedere se è pronta per il merge, se i controlli sono superati e accedervi direttamente, senza uscire dalla conversazione. Funziona con GitHub, GitLab (dove viene chiamata merge request) e Bitbucket Cloud, con un solo provider per deployment.

Solo le chat che eseguono codice in un workspace collegato possono avere una pull request. Una chat semplice, o un workspace che non ha ancora segnalato un branch, non mostra nulla.

## Nell'intestazione della chat [#in-the-chat-header]

Su uno schermo ampio, un chip sul lato sinistro dell'intestazione mostra l'icona della pull request, un piccolo punto CI nell'angolo e il titolo della pull request. Passa con il mouse o metti il focus sul chip per aprire una scheda con i dettagli. La scheda rimane aperta finché il puntatore o il focus della tastiera si trovano al suo interno.

Su uno schermo piccolo non c'è il chip. Apri il menu a tre puntini nell'intestazione e scegli la voce `PR #number` (`MR !number` su GitLab) per mostrare la stessa scheda in una finestra di dialogo.

L'intestazione si mantiene aggiornata da sola: controlla di nuovo circa ogni 20 secondi mentre i controlli sono in esecuzione o il provider sta ancora verificando se il ramo può essere unito, e circa ogni 60 secondi negli altri casi. Si interrompe una volta che la pull request è stata unita o chiusa e non rimane nulla in esecuzione.

## Nella barra laterale [#in-the-sidebar]

Le conversazioni che hanno una pull request mostrano la stessa icona e il pallino CI alla fine della loro riga. La riga mantiene il titolo originale della conversazione. Passa il mouse sulla riga, oppure metti il focus o fai clic sul segno, per aprire la scheda accanto ad essa; fare clic sul segno non apre la conversazione.

La barra laterale non esegue alcun polling. Ogni riga è aggiornata quanto l'ultimo caricamento della lista, e si aggiorna quando torni alla finestra e i suoi dati hanno più di un minuto. Se un aggiornamento non riesce per una pull request già trovata, il contrassegno resta e la scheda mostra "Impossibile aggiornare la pull request" con un pulsante **Riprova**. Una conversazione la cui pull request non è mai stata trovata non mostra alcun contrassegno, anche quando la ricerca non è riuscita.

## Lettura della scheda [#reading-the-card]

La scheda mostra `PR #number` (`MR !number` su GitLab), le righe aggiunte in verde e quelle rimosse in rosso, un link **Open in GitHub**, **Open in GitLab** o **Open in Bitbucket**, il titolo e due badge:

- Stato: Aperto, Conflitti, Bozza, Unito o Chiuso. "Conflitti" sostituisce "Aperto" quando il ramo non può essere unito in modo pulito.
- Controlli: Superati, Non superati, In esecuzione o Nessuno. Su GitLab è la pipeline principale, e solo se è stata eseguita per il commit corrente. Su Bitbucket sono gli stati dei commit.

Il colore dell'icona e il punto CI riassumono le stesse informazioni a colpo d'occhio:

| Pull request | Icona | Punto CI |
| ------------------------------------ | ------- | --------------- |
| Aperta, può essere unita | Verde | Dai controlli |
| Aperta, mergeabilità non ancora nota | Neutro | Dai controlli |
| Aperta, conflitti di unione | Rosso | Dai controlli |
| Bozza | Neutro | Dai controlli |
| Unita | Viola | Nessuno |
| Chiusa | Neutro | Nessuno |

Il punto è verde per i controlli superati, rosso per quelli falliti e ambra per quelli in esecuzione. Non compare alcun punto quando il repository non segnala controlli. Un controllo fallito ha priorità su uno ancora in esecuzione.

## Quale pull request vedi [#which-pull-request-you-see]

Il workspace riporta il repository, il branch e il commit in cui la chat è stata eseguita per ultima, e LibreChat cerca una pull request da quel branch:

- Se l'output del comando della chat stessa ha stampato un link a una pull request nello stesso repository (ad esempio l'URL che stampa `gh pr create`), tale pull request viene utilizzata, a condizione che provenga dal branch della chat.
- Altrimenti, le pull request aperte per il branch hanno la precedenza su quelle chiuse, quindi una vecchia pull request chiusa su un nome di branch riutilizzato non nasconde quella attuale.
- Una pull request vale solo se contiene il commit con cui la chat è stata eseguita per ultima. Eliminare un branch e riutilizzarne il nome non ripristina la pull request precedente.
- Un ramo appena creato, senza commit, non corrisponde a nulla.

I repository a cui il server non è autorizzato a consultare si comportano esattamente come i repository senza una pull request: nessun contrassegno, nessun errore.

## Collega il tuo account [#connect-your-own-account]

Se l'amministratore ha configurato questa funzione, puoi cercare le pull request con il tuo account GitHub, GitLab o Bitbucket. Apri **Impostazioni**, vai su **Account** e, in **Account connessi**, fai clic su **Connetti** accanto a **Account per le pull request**. Si apre una finestra di accesso presso il provider; approvala e la riga mostrerà **Connesso**. Se la finestra non si apre, consenti i pop-up per LibreChat e riprova.

Una volta connesso, le ricerche utilizzano il tuo account, quindi vedi le pull request in qualsiasi repository che puoi leggere, con il tuo limite di frequenza personale. **Disconnetti** rimuove la connessione e puoi riconnetterti in qualsiasi momento. Se il server non riesce ad aggiornare la tua connessione (ad esempio perché il provider non è disponibile), le tue pull request vengono mostrate come non disponibili anziché passare silenziosamente al token del server. Se revochi l'app presso il provider, LibreChat rimuove la connessione e torni allo stato di non connesso.

Se la riga indica **Not in use**, il tuo amministratore ha disattivato le connessioni agli account e le ricerche non utilizzano più il tuo account. Fai clic su **Disconnect** per rimuovere la connessione salvata.

## Setup [#setup]

La funzionalità è attiva per impostazione predefinita, ma rimane nascosta finché un amministratore non fornisce a LibreChat un token e un elenco di repository in cui può effettuare ricerche, oppure configura un'app in modo che gli utenti possano collegare i propri account. Richiede inoltre uno spazio di lavoro del codice collegato che riporti il proprio branch git. Vedi [Configurazione delle Pull Request](/docs/configuration/pull_requests).
