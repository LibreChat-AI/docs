Agents API を使うと、LibreChat の外部にあるコードからエージェントを呼び出せます。任意の OpenAI SDK をご利用のインスタンスに向け、モデルとしてエージェント ID を指定するだけで、エージェントの設定一式（指示、ツール、ファイル）を使い慣れた API のまま利用できます。スクリプト、CI ジョブ、別のプロダクトにエージェントを組み込む用途にご活用ください。

- **推論**: Chat Completions と Open Responses。API キー(管理者が設定している場合は、ご自身の OIDC トークン)で認証します。
- **Agent Events**: 別のシステム(Webhookなど)からエージェントに作業を渡し、その作業が完了したかどうかを追跡します。APIキーのみ。
- **Agent Management**: 信頼されたサービスから、マシン OIDC トークンを使用してエージェントとスキルを作成・編集します。

## APIキーを取得する [#get-an-api-key]

**設定**を開き、**Data & Privacy**に移動して、**API keys**の下にある**Agent API Keys**を見つけます。**Manage**をクリックし、次に**Create API Key**をクリックして、名前を付け、有効期限を選択します(7日から1年まで、または無期限)。キーはすぐにコピーしてください。表示されるのは一度だけです。

<ThemeImage
  light="/images/features/agents_api/api-keys-light.png"
  dark="/images/features/agents_api/api-keys-dark.png"
  alt="Settings の Data & Privacy にある Agent API Keys。2 つのキーの有効期限と最終使用日を表示"
/>

キーはあなた本人として振る舞います。API を通じてあなたがアクセスできるものには、そのキーを持つ誰もがアクセスできます。そのため、もう使っていないキーは削除してください。キーを削除すると、そのキーを使用しているアプリケーションは即座に接続できなくなります。

セクションが表示されない場合は、お使いのロールに Agents API へのアクセス権が付与されていません。

## 呼び出し可能なエージェント [#which-agents-you-can-call]

あなたが所有している、または共有されているエージェントを呼び出すことができます。他の人のエージェントについては、所有者がエージェントビルダーのフッターにある**リモートアクセス**ボタン(地球儀アイコン)を使ってアクセス権を付与する必要があります。これは通常の共有とは別のものです。LibreChat でエージェントとチャットできることは、API を通じてそのエージェントを呼び出せることを意味しません。

エージェントIDが必要です。これはビルダーの**詳細設定**に、コピーボタン付きで表示されています。`GET /api/agents/v1/models` は、お使いのキーで呼び出せるエージェントの一覧を返し、`GET /api/agents/v1/models/{model}` は1つのエージェントを返します。

## チャット補完 [#chat-completions]

`POST /api/agents/v1/chat/completions` は OpenAI Chat Completions 形式に従うため、ベース URL を変更するだけで既存の OpenAI クライアントをそのまま利用できます。

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

同じリクエストをcurlで送信する場合:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` は [Open Responses](https://www.openresponses.org/) 仕様を実装しており、エージェントのワークロード向けに設計されています。推論、ツール呼び出し、ストリーミングイベントは後付けではなく、フォーマットの一部として組み込まれています。LibreChat は今後この インターフェース を基盤として開発を進めるため、新規の連携にはこちらを優先して利用することを推奨します。

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` は保存されたレスポンスを返し、`GET /api/agents/v1/responses/models` はここで利用可能なエージェントを一覧表示します。

### 独自の関数ツール [#your-own-function-tools]

Responses リクエストでは、標準の `function` ツールを渡すことができます。LibreChat はこれらのツールをモデルに提示しますが、実行はしません。モデルがいずれかのツールを選択すると、レスポンスには `function_call` アイテムが含まれるため、関数はご自身で実行してください。処理を続けるには、`function_call` アイテムを繰り返したうえで、同じ `call_id` を持つ `function_call_output` を `input` に含めた新しいリクエストを送信してください。

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

2つのリクエストの間で何も保持されず、`previous_response_id` だけでは不十分で、呼び出しとその出力を再送する必要があります。ツール名には英字、数字、アンダースコア、ハイフンを使用でき、一意である必要があり、エージェント自身のツールと同名にすることはできません。自分のツールを呼び出すターンでは、同時にエージェントのツールを呼び出すことはできず、モデルに再試行が求められます。

### API経由でのツール承認 [#tool-approval-over-the-api]

管理者が一部のツールに承認を必要としている場合、API呼び出しは誰かに確認するために停止することはできません。承認が必要なツールや拒否されたツールは、代わりにブロックされます。管理者は、無人のクライアントに実行させるツールを明示的に許可しておく必要があります。

## Agent Events [#agent-events]

Agent Eventsは、別のシステムがエージェントに作業を引き渡し、後から結果を確認できる機能です。これはベータ版です。イベントはAgents APIキーを使用し、これによって利用者とイベントの発生元が識別されます。OIDCのみの構成では利用できません。また、独自のレート制限([`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits))があります。

イベントは次の3つのモードのいずれかで届きます:

- `fire` で、エージェントとの新しい会話を開始します。
- `continue` は、先ほどバインドした子エージェントにターンを追加します(下記参照)。
- `steer` は、`fire` が返した会話と生成の識別子によって特定される、まだ実行中の処理に対してガイダンスを追加します。

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

すべてのリクエストには、`Idempotency-Key` を 1 つ含める必要があります(使用可能な文字は英字、数字、`._~:/+=-` で、長さは 1〜256 文字)。同じ配信を再試行する場合は、同じキーを再利用してください。異なる内容に対して同じキーを再利用すると、競合となります。LibreChat はイベントのソースを API キーから設定し、送信されたソースは無視します。ペイロードは保存されるため、シークレットは含めないでください。同じ対象に関するイベントを順番どおりに処理する必要がある場合は、`orderingKey` を使用してください。

レスポンスは `202 Accepted` で、配信 ID と、同じキーでポーリングするための `Location` が返されます:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

配信のステータスは `pending`、`leased`、`succeeded`、`dead` のいずれかです。バインドされた `continue` の場合、`succeeded` はターンが開始されたことのみを意味します。その後、その `handling` ステータスは `started` から `applied`、`completed_no_action`、`failed`、`cancelled` のいずれかに移行します。`expectedAction`(ツール名と、必要に応じてその引数の一部)を送信した場合、`applied` は LibreChat がその引数が一致するツールが呼び出されたことを確認したことを意味します。モデルがテキストで何を述べるかは考慮されません。

Agent Events は公開の Webhook 受信エンドポイントではありません。イベントを提供元が Webhook に署名している場合は、転送する前に独自のアダプターで署名を検証してください。

### イベント駆動型の子エージェント [#event-driven-child-agents]

子エージェントとの会話を複数のイベントにわたって継続するには、まず一度バインドし、その後そのバインディングに対して `continue` イベントを送信します。

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

The parent must be a normal agent conversation, and the target must be one of that agent's direct subagents (or the agent itself, if self-spawn is allowed). `actorId` is up to 128 characters. A new binding returns `201` and a replay returns `200`, both with the binding `id`. Later turns reference it:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

各バインディングは一度に1つのイベントを処理します。次のイベントは、現在のターンが最終的な処理ステータスになるまで待機しますが、異なるバインディングは並列に実行されます。バインドされた子エージェントは、Ask Userやツール承認のために一時停止することがあり、その後のイベントは、LibreChatで誰かが応答するまで待機します。これには、耐久性のあるMongoDBチェックポインター(デフォルト)が必要です。親の会話では、バインドされた各子エージェントは、そのバインディングを所有するメッセージの下に行として表示され、サブエージェントのアクティビティパネルが開きます。

バインディングは、それを作成した API キー、ユーザー、テナントに対してのみ機能します。子スレッドはチャット一覧に表示されず、アプリ内では読み取り専用になります。

観察イベント(例:「ゲームが進んだ」など)には同じ `coalesce.key` を付与します。すると LibreChat は、750 ms 以内かつ 512 KiB 以内で届いたものを最大 8 件まで 1 つのターンにまとめます。各イベントには引き続き個別のレシートが発行されます。コマンド、承認、または `expectedAction` を持つものはまとめないでください。

## エージェント管理 API [#agent-management-api]

Agent Management APIは、信頼されたサービスがブラウザセッションなしでエージェントとスキルを作成、変更、削除できるようにします。このAPIはベータ版であり、独自の認証方式を使用します。管理者が[`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi)の下に登録したクライアントによるマシンOIDCトークンを使用します。各クライアントは既存のLibreChatユーザーおよびテナントに1対1で紐付けられ、すべてのリクエストはそのユーザーの権限とアクセス範囲で実行されます。このAPIによって、誰かが管理者になることはありません。

| メソッド | ルート | 目的 |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | エージェントを作成 |
| `GET` | `/api/agents/v1/agents` | アクセス可能なエージェントを一覧表示 |
| `GET` | `/api/agents/v1/agents/{id}` | エージェントを読み取る |
| `PATCH` | `/api/agents/v1/agents/{id}` | エージェントを更新 |
| `DELETE` | `/api/agents/v1/agents/{id}` | エージェントを削除 |
| `POST` | `/api/agents/v1/agents/{id}/files` | ファイルをアップロードして添付 |
| `GET` | `/api/agents/v1/agents/{id}/files` | 添付ファイルを一覧表示 |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | ファイルの添付を解除 |
| `GET` | `/api/agents/v1/skills` | アクセス可能なスキルを一覧表示 |
| `POST` | `/api/agents/v1/skills` | スキルを作成 |
| `GET` | `/api/agents/v1/skills/{id}` | スキルを読み取る |
| `PATCH` | `/api/agents/v1/skills/{id}` | スキルを更新 |
| `DELETE` | `/api/agents/v1/skills/{id}` | スキルを削除 |
| `GET` | `/api/agents/v1/skills/{id}/files` | スキルのファイルを一覧表示 |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | スキルファイルを読み取る |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | スキルファイルを作成または置換 |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | スキルファイルを削除 |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

エージェントのペイロードは、エージェントビルダーと同じフィールドを受け付け、未知のフィールドはすべて拒否されます。作成時には `model` が必須です。一覧取得では `limit`(1～100、デフォルトは20)と `cursor` を指定できます。`has_more` が true の場合は、返された `after` を次の cursor として渡してください。ファイルのアップロードは `multipart/form-data` 形式で、`file` を1つと、`context`、`file_search`、`execute_code` などの `tool_resource` を指定します。通常のアップロード上限が適用されます。

Skill create は `name`、`description`、`body` を必須とし、`displayTitle`、`frontmatter`、`category`、`alwaysApply` は任意で指定できます。更新時には、スキルの現在のバージョンを `expectedVersion` として送信する必要があります。これにより、2 人の書き込み者が互いの変更を暗黙に上書きしてしまうことを防ぎます。

エラーは `invalid_request`、`not_found`、`permission_denied`、`conflict`、`internal_error` のコードを使用します。アクセス権のないリソースは `not_found` として返される場合があります。認証情報が不正または欠落している場合は `401` を返します。

管理者が有効にすると、管理用ルートのOpenAPI記述が`/api/openapi.json`で提供され、インタラクティブなドキュメントは`/api/docs`で利用できます。推論およびイベントは対象外です。詳細は[`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi)を参照してください。

## 使用量と課金 [#usage-and-billing]

APIリクエストは、アプリでのチャットと同様にトークン残高を消費します。レスポンスの使用量の合計には、サブエージェントの呼び出しが含まれ、`primary`と`subagent`に分けた内訳が示されます。また、プロバイダーが報告する場合は、キャッシュトークンと推論トークンも含まれます。詳しくは[Token Usage](/docs/configuration/token_usage)を参照してください。

## セットアップ [#setup]

Agents APIは、管理者がロールに Remote Agents の権限を付与するまで、一般ユーザーには無効になっています。権限の付与は、[管理パネル](/docs/features/admin_panel)から行うか、[`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents) を使用して設定できます。管理者はデフォルトでこの権限を持っています。APIキー認証はデフォルトで有効になっています。キーの代わりに、またはキーと併用して独自のOIDCプロバイダーからのトークンを受け入れる場合は、[`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi) を参照してください。Management APIは、[`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) の下で個別に設定します。イベント配信の設定は、[`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven) の下にあります。
