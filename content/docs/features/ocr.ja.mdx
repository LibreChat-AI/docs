OCRを使うと、LibreChatはピクセルとしてしか存在しないテキストを読み取れるようになります。たとえばレシートの写真、スキャンした契約書、スクリーンショットから作成したPDFなどです。管理者がOCRサービスを設定している場合、テキストとして追加されたファイルはまずそのサービスを通るため、モデルは空の結果ではなく文字そのものを受け取ります。

## OCRが適用される場所 [#where-ocr-applies]

OCRは、テキストがモデルのコンテキストに入力されるファイルに対して実行されます。

- **Upload as Text**(アップロード as Text)をチャットで使用します。明示的なアップロードメニューを表示するデプロイメントで利用できます。詳しくは [Upload as Text](/docs/features/upload_as_text) を参照してください。
- **File Context** を Agent Builder で使用すると、抽出されたテキストがメッセージごとにエージェントのコンテキストへ含まれます。

デフォルトで処理対象となるファイル形式は、画像（JPEG、PNG、GIF、WebP、HEIC、HEIF）、PDF、Word、PowerPoint、Excel、EPUB、およびOpenDocument形式のファイルです。それ以外のファイルはOCRを行わず、通常のテキスト抽出を使用します。

デフォルトの**From Local Computer**(ローカルコンピュータから)を選択した場合の動作は、ファイルの振り分け先によって異なります。プロバイダーが受け付ける画像とPDFはモデルに直接送信され、OCRは行われません。テキストとして振り分けられるファイル(たとえばWord文書や、管理者がテキストとして振り分けるよう設定したPDF)は、**Upload as Text**(テキストとしてアップロード)と同じ方法で抽出されます。そのファイル種別をOCRが処理する場合は、OCRを経由します。

## OCRなし [#without-ocr]

OCR サービスがなくても、テキスト抽出は引き続き機能します。LibreChat の組み込みパーサーは、実際のテキストレイヤーを持つ 15 MB 以下の PDF、DOCX、XLS、XLSX、ODT、ODS ファイルを読み取ることができ、エディタからエクスポートされたほとんどのドキュメントがこれに該当します。従来の `.doc`、PowerPoint、EPUB ファイルには OCR が必要です。また、パーサーは画像を読み取ることもできません。スキャンされた PDF やページの写真は、ドキュメントが画像ベースである可能性があり OCR サービスが必要である、というメッセージとともに失敗します。

OCRが設定されているにもかかわらず、サービスがドキュメントでエラーを返した場合、LibreChatはそのファイルに対して組み込みのパーサーにフォールバックします。

## OCR サービス [#ocr-services]

管理者は1つの戦略を選択します:

- Mistral の API を通じた Mistral OCR です。これがデフォルトの戦略です。
- Mistral OCR を Azure AI Foundry にデプロイする。
- Google Cloud Vertex AI にデプロイされた Mistral OCR。
- ローカルのドキュメントパーサーのみを使用し、外部サービスは利用しません。テキストレイヤーは読み取りますが、画像は読み取りません。

Mistralのいずれのオプションを使用する場合も、ファイルの内容は処理のためにそのサービスへ送信されるため、同サービスのデータ取り扱いに関する規約が適用されます。

## Provider へのアップロードを使用する [#upload-to-provider-instead]

多くのモデルは画像やPDFをそのまま読み取ることができます。添付ファイルとしてプロバイダーに送信されたファイルは、プロバイダー側で解析されるため、テキスト抽出では失われるレイアウトや画像も保持されます。デフォルトのアップローダーは、プロバイダーが対応している場合、画像とPDFに対してこれを自動的に行います。従来のアップロードメニューを使用する場合は、[コンポーザー](/docs/features/composer#add-files)で**Upload to Provider**を選択してください。

このような方法でファイルを受け付けるプロバイダー: OpenAI、Anthropic、Google と Vertex AI、AWS Bedrock、Mistral、DeepSeek、Moonshot、OpenRouter、xAI、およびカスタムエンドポイント。Azure OpenAI は、会話パラメーターで Responses API が有効になっている場合にのみ、この方法で PDF を受け付けます。Chat Completions を使用する場合は、画像のみを受け付けます。

プロバイダーごとに受け付ける内容は異なります:

- すべてのモデルが画像とPDFを入力として受け付けます。
- Google、Vertex AI、そしてOpenRouterも音声と動画を扱えます。
- AWS Bedrockは、CSV、DOC、DOCX、XLS、XLSX、HTML、TXT、Markdownにも対応しており、1ドキュメントあたり最大4.5 MBまでです。Claude 4以降向けのPDF、およびNova向けのPDFとDOCXは、管理者がより低いファイルサイズ上限を設定していない限り、最大32 MBまで利用できます。[AWS Bedrock](/docs/configuration/pre_configured_ai/bedrock)を参照してください。

## セットアップ [#setup]

OCRは、管理者が`librechat.yaml`に`ocr`セクションを追加するまでオフになっています。ストラテジー、キー、エンドポイントについては、[OCR設定リファレンス](/docs/configuration/librechat_yaml/object_structure/ocr)で説明しています。OCRに送信されるファイルタイプは、[`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr)内の`fileConfig.ocr.supportedMimeTypes`で設定します。エージェントでは`ocr`機能も必要で、この機能はデフォルトで有効になっています。
