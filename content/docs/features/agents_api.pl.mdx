Agents API pozwala kodowi działającemu poza LibreChat komunikować się z Twoimi agentami. Wystarczy skierować dowolny OpenAI SDK na swoją instancję, przekazać identyfikator agenta jako model i otrzymujesz pełną konfigurację agenta (instrukcje, narzędzia, pliki) za znajomym interfejsem API. Użyj go, aby podłączyć agenta do skryptu, zadania CI lub innego produktu.

- **Zdarzenia agenta**: przekaż agentowi pracę z innego systemu, na przykład przez webhook, i śledź, czy została wykonana. Tylko klucze API.
- **Zarządzanie agentami**: tworzenie i edycja agentów oraz umiejętności z zaufanej usługi przy użyciu maszynowych tokenów OIDC.

## Uzyskaj klucz API [#get-an-api-key]

Otwórz **Ustawienia**, przejdź do **Dane i prywatność** i znajdź **Klucze API agentów** w sekcji **Klucze API**. Kliknij **Zarządzaj**, a następnie **Utwórz klucz API**, nadaj mu nazwę i wybierz datę wygaśnięcia (od 7 dni do 1 roku lub bez wygaśnięcia). Skopiuj klucz od razu, ponieważ jest wyświetlany tylko raz.

Klucz działa w Twoim imieniu. Wszystko, do czego masz dostęp przez API, będzie dostępne również dla każdego, kto posiada klucz, dlatego usuwaj klucze, których już nie używasz. Usunięcie klucza natychmiast odcina aplikacje, które z niego korzystają.

Jeśli nie widzisz tej sekcji, Twoja rola nie ma dostępu do Agents API.

## Które agenty można wywołać [#which-agents-you-can-call]

Możesz wywoływać agentów, których jesteś właścicielem lub które zostały udostępnione Tobie. W przypadku agentów należących do innych osób właściciel musi przyznać Ci dostęp za pomocą przycisku **Remote Access** (ikona globusa) w stopce Agent Builder. Jest to odrębne od zwykłego udostępniania: możliwość czatowania z agentem w LibreChat nie pozwala na wywoływanie go przez API.

Potrzebujesz identyfikatora agenta, który jest widoczny w sekcji **Advanced Settings** w kreatorze, obok przycisku kopiowania. `GET /api/agents/v1/models` zwraca listę agentów, których może wywoływać Twój klucz, a `GET /api/agents/v1/models/{model}` zwraca jednego z nich.

## Uzupełnienia czatu [#chat-completions]

`POST /api/agents/v1/chat/completions` jest zgodny z formatem OpenAI Chat Completions, więc istniejące klienty OpenAI działają po zmianie adresu bazowego (base URL):

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

Takie samo żądanie z użyciem curl:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` implementuje specyfikację [Open Responses](https://www.openresponses.org/), która została stworzona z myślą o obciążeniach agentowych: rozumowanie, wywołania narzędzi i zdarzenia strumieniowe są częścią formatu, a nie dodatkiem. To jest interfejs, na którym LibreChat będzie się opierać w przyszłości, dlatego w nowych integracjach warto go preferować.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` zwraca zapisaną odpowiedź, a `GET /api/agents/v1/responses/models` zwraca listę agentów dostępnych w tym miejscu.

### Własne narzędzia funkcyjne [#your-own-function-tools]

Możesz przekazać standardowe narzędzia `function` w żądaniu Responses. LibreChat pokazuje je modelowi, ale ich nie uruchamia: gdy model wybierze jedno z nich, odpowiedź zawiera element `function_call`, a funkcję uruchamiasz samodzielnie. Aby kontynuować, wyślij nowe żądanie, którego `input` powtarza ten element `function_call`, a następnie `function_call_output` z tym samym `call_id`:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Między dwoma żądaniami nic nie jest utrzymywane otwarte, a sam `previous_response_id` nie wystarcza; trzeba ponowić wywołanie wraz z jego wynikiem. Nazwy narzędzi mogą zawierać litery, cyfry, znaki podkreślenia i myślniki, muszą być unikalne i nie mogą przesłaniać żadnego z własnych narzędzi agenta. Tura, w której wywoływane jest jedno z Twoich narzędzi, nie może jednocześnie wywoływać narzędzi agenta; model jest proszony o ponowienie próby.

### Zatwierdzanie narzędzi przez API [#tool-approval-over-the-api]

Jeśli administrator wymaga zatwierdzenia dla niektórych narzędzi, wywołania API nie mogą zatrzymać się, aby o nie zapytać. Narzędzia wymagające zatwierdzenia lub odrzucone są zamiast tego blokowane. Administratorzy powinni jawnie zezwolić na narzędzia, które niezależny klient ma uruchamiać bez nadzoru.

## Zdarzenia agenta [#agent-events]

Agent Events pozwalają innemu systemowi przekazać pracę agentowi i później wrócić, aby sprawdzić, co się wydarzyło. Ta funkcja jest w wersji beta. Zdarzenia wykorzystują Twój klucz API Agents, który identyfikuje Ciebie i źródło; konfiguracje oparte wyłącznie na OIDC nie mogą ich używać. Mają również własny limit żądań, [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Zdarzenie występuje w jednym z trzech trybów:

- `fire` rozpoczyna nową rozmowę z agentem.
- `continue` dodaje turę do agenta podrzędnego, którego wcześniej powiązano (zobacz poniżej).
- `steer` dodaje wskazówki do działającego jeszcze przebiegu, identyfikowanego przez konwersację i generację, które zwrócił `fire`.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Każde żądanie musi zawierać jeden nagłówek `Idempotency-Key` (od 1 do 256 liter, cyfr lub znaków `._~:/+=-`). Użyj tego samego klucza, gdy ponawiasz tę samą dostawę; użycie go dla innej treści jest konfliktem. LibreChat ustawia źródło zdarzenia na podstawie Twojego klucza API i ignoruje wszelkie źródło przesłane przez Ciebie. Ładunek jest przechowywany, dlatego nie umieszczaj w nim sekretów. Użyj `orderingKey`, gdy zdarzenia dotyczące tego samego obiektu mają być obsługiwane w kolejności.

Odpowiedź to `202 Accepted` z identyfikatorem dostarczenia oraz nagłówkiem `Location`, pod którym można odpytywać status przy użyciu tego samego klucza:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Dostawa może mieć status `pending`, `leased`, `succeeded` lub `dead`. W przypadku powiązanego `continue` status `succeeded` oznacza jedynie, że tura została rozpoczęta. Jego status `handling` przechodzi wtedy z `started` do jednego z: `applied`, `completed_no_action`, `failed` lub `cancelled`. Jeśli wysyłasz `expectedAction` (nazwę narzędzia i opcjonalnie niektóre jego argumenty), status `applied` oznacza, że LibreChat zarejestrował wywołanie tego narzędzia z pasującymi argumentami; to, co model przekazuje w tekście, nie jest w tym przypadku brane pod uwagę.

Agent Events nie są publicznym odbiornikiem webhooków. Jeśli zdarzenia pochodzą od dostawcy, który podpisuje swoje webhooki, zweryfikuj podpis we własnym adapterze, zanim przekażesz je dalej.

### Agenci podrzędni sterowani zdarzeniami [#event-driven-child-agents]

Aby utrzymać ciągłą rozmowę z agentem podrzędnym w wielu zdarzeniach, powiąż go raz, a następnie wysyłaj zdarzenia `continue` do powiązania:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

Rodzic musi być zwykłą konwersacją z agentem, a cel musi być jednym z bezpośrednich subagentów tego agenta (lub samym agentem, jeśli dozwolone jest self-spawn). `actorId` może mieć do 128 znaków. Nowe powiązanie zwraca `201`, a ponowne odtworzenie zwraca `200`, oba z `id` powiązania. Kolejne tury odwołują się do niego:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Każde powiązanie przetwarza jedno zdarzenie naraz: kolejne czeka, aż bieżąca tura otrzyma ostateczny status obsługi, natomiast różne powiązania działają równolegle. Powiązane podrzędne (child) może zatrzymać się na potrzeby Ask User lub zatwierdzenia narzędzia; jego późniejsze zdarzenia czekają, aż ktoś odpowie w LibreChat. Wymaga to trwałego checkpointera MongoDB (domyślnego). W konwersacji nadrzędnej każde powiązane podrzędne pojawia się jako wiersz pod wiadomością, która jest właścicielem powiązania, i otwiera panel aktywności subagenta.

Powiązanie działa wyłącznie z kluczem API, użytkownikiem i najemcą, którzy je utworzyli. Wątek podrzędny nie pojawia się na liście czatów i jest tylko do odczytu w aplikacji.

Dla zdarzeń będących jedynie obserwacjami, takich jak "gra przeszła dalej", nadaj im ten sam `coalesce.key`, a LibreChat zgrupuje do 8 z nich (w ciągu 750 ms i 512 KiB) w jedną turę. Każde zdarzenie nadal otrzymuje własne potwierdzenie odbioru. Nie łącz poleceń, zatwierdzeń ani czegokolwiek z `expectedAction`.

## Zarządzanie Agentami przez API [#agent-management-api]

Interfejs API zarządzania agentami pozwala zaufanej usłudze tworzyć, zmieniać i usuwać agentów oraz umiejętności bez sesji przeglądarki. Jest w wersji beta i wykorzystuje własne uwierzytelnianie: tokeny maszynowe OIDC z klientów, które administrator wymienia w sekcji [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi). Każdy klient jest powiązany z jednym istniejącym użytkownikiem LibreChat oraz najemcą (tenant), a każde żądanie działa w imieniu tego użytkownika, z jego uprawnieniami i dostępem. Nie nadaje to nikomu uprawnień administratora.

| Metoda | Ścieżka | Cel |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | Utworzenie agenta |
| `GET` | `/api/agents/v1/agents` | Lista dostępnych agentów |
| `GET` | `/api/agents/v1/agents/{id}` | Odczyt agenta |
| `PATCH` | `/api/agents/v1/agents/{id}` | Aktualizacja agenta |
| `DELETE` | `/api/agents/v1/agents/{id}` | Usunięcie agenta |
| `POST` | `/api/agents/v1/agents/{id}/files` | Przesłanie i dołączenie pliku |
| `GET` | `/api/agents/v1/agents/{id}/files` | Lista dołączonych plików |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | Odłączenie pliku |
| `GET` | `/api/agents/v1/skills` | Lista dostępnych umiejętności |
| `POST` | `/api/agents/v1/skills` | Utworzenie umiejętności |
| `GET` | `/api/agents/v1/skills/{id}` | Odczyt umiejętności |
| `PATCH` | `/api/agents/v1/skills/{id}` | Aktualizacja umiejętności |
| `DELETE` | `/api/agents/v1/skills/{id}` | Usunięcie umiejętności |
| `GET` | `/api/agents/v1/skills/{id}/files` | Lista plików umiejętności |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | Odczyt pliku umiejętności |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | Utworzenie lub zastąpienie pliku umiejętności |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | Usunięcie pliku umiejętności |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agent payloads take the same fields as the Agent Builder and reject unknown ones; `model` is required on create. Lists take `limit` (1 to 100, default 20) and a `cursor`; when `has_more` is true, pass the returned `after` as the next cursor. File uploads are `multipart/form-data` with one `file` and a `tool_resource` such as `context`, `file_search`, or `execute_code`, subject to the usual upload limits.

Skill create przyjmuje `name`, `description`, `body` oraz opcjonalnie `displayTitle`, `frontmatter`, `category` i `alwaysApply`. Aktualizacje muszą przesyłać bieżącą wersję skilla jako `expectedVersion`, dzięki czemu dwóch zapisujących nie nadpisze sobie zmian po cichu.

Błędy używają kodów `invalid_request`, `not_found`, `permission_denied`, `conflict` oraz `internal_error`. Zasób, do którego nie masz dostępu, może zostać zwrócony jako `not_found`. Nieprawidłowe lub brakujące dane uwierzytelniające zwracają kod `401`.

Jeśli administrator to włączy, opis OpenAPI tras zarządzania jest udostępniany pod adresem `/api/openapi.json`, a interaktywna dokumentacja pod adresem `/api/docs`. Nie obejmuje ona wnioskowania ani zdarzeń. Zobacz [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Użycie i rozliczenia [#usage-and-billing]

Żądania API są rozliczane w ramach Twojego salda tokenów dokładnie tak samo jak czaty w aplikacji. Sumy zużycia w odpowiedzi uwzględniają wywołania subagentów, z osobnym podziałem na `primary` i `subagent`, a także tokeny pamięci podręcznej i rozumowania, jeśli dostawca je raportuje. Zobacz [Token Usage](/docs/configuration/token_usage).

## Konfiguracja [#setup]

Interfejs Agents API jest wyłączony dla zwykłych użytkowników, dopóki administrator nie przyzna uprawnień Remote Agents do ich roli, czy to w [Panelu administracyjnym](/docs/features/admin_panel), czy za pomocą [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents). Administratorzy mają to uprawnienie domyślnie. Uwierzytelnianie kluczem API jest domyślnie włączone; aby akceptować tokeny od własnego dostawcy OIDC zamiast kluczy lub obok nich, zobacz [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi). Management API konfiguruje się osobno w sekcji [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi), a ustawienia dostarczania zdarzeń znajdują się w sekcji [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven).
