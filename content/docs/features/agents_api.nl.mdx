De Agents API laat code buiten LibreChat met je agents communiceren. Richt elke OpenAI SDK op je instantie, geef een agent-ID mee als model, en je krijgt de volledige configuratie van de agent (instructies, tools, bestanden) via een bekende API. Gebruik dit om een agent aan te sluiten op een script, een CI-job of een ander product.

Er zijn drie onderdelen:

- **Inferentie**: Chat Completions en Open Responses, geauthenticeerd met een API-sleutel (of je eigen OIDC-tokens, als de beheerder dat heeft ingesteld).
- **Agent Events**: laat een agent werk uitvoeren dat van een ander systeem komt, zoals een webhook, en houd bij of het is uitgevoerd. Alleen API-sleutels.
- **Agentbeheer**: maak en bewerk agents en skills via een vertrouwde service, met behulp van machine-OIDC-tokens.

<Callout type="warning" title="Beta">
  Eindpunten, aanvraagformaten en antwoorden kunnen nog wijzigen tussen releases.
</Callout>

## Een API-sleutel verkrijgen [#get-an-api-key]

Open **Instellingen**, ga naar **Gegevens en privacy**, en zoek **Agent API-sleutels** onder **API-sleutels**. Klik op **Beheren**, vervolgens op **API-sleutel maken**, geef de sleutel een naam, kies een vervaldatum (van 7 dagen tot 1 jaar, of nooit), en kopieer de sleutel meteen: deze wordt slechts één keer getoond.

Een sleutel handelt namens jou. Alles wat je via de API kunt bereiken, kan iedereen die de sleutel bezit ook bereiken, dus verwijder sleutels die je niet meer gebruikt. Het verwijderen van een sleutel sluit applicaties die deze gebruiken onmiddellijk af.

Als u de sectie niet ziet, heeft uw rol geen toegang tot de Agents API gekregen.

## Welke agents je kunt aanroepen [#which-agents-you-can-call]

U kunt agents aanroepen die u zelf bezit of die met u zijn gedeeld. Voor de agent van iemand anders moet de eigenaar u toegang verlenen via de knop **Remote Access** (het wereldbolpictogram) in de voettekst van de Agent Builder. Dit staat los van normaal delen: het feit dat u met een agent in LibreChat kunt chatten, betekent niet dat u deze via de API kunt aanroepen.

Je hebt de agent-ID nodig, die wordt weergegeven onder **Geavanceerde instellingen** in de builder, met een kopieerknop. `GET /api/agents/v1/models` geeft een lijst van de agents die je sleutel mag aanroepen, en `GET /api/agents/v1/models/{model}` geeft er één terug.

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions` volgt het OpenAI Chat Completions-formaat, zodat bestaande OpenAI-clients werken door alleen de basis-URL te wijzigen:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

De zelfde aanvraag met curl:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` implementeert de [Open Responses](https://www.openresponses.org/)-specificatie, die is ontworpen voor agentwerkbelastingen: redenering, toolaanroepen en gestreamde gebeurtenissen maken deel uit van het formaat in plaats van er achteraf aan te worden toegevoegd. Dit is de interface waarop LibreChat voortaan verder bouwt, dus geef er de voorkeur aan voor nieuwe integraties.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` geeft een opgeslagen antwoord terug, en `GET /api/agents/v1/responses/models` somt de agents op die hier beschikbaar zijn.

### Je eigen functietools [#your-own-function-tools]

U kunt standaard `function`-tools doorgeven in een Responses-verzoek. LibreChat toont deze aan het model maar voert ze niet uit: wanneer het model er een kiest, bevat het antwoord een `function_call`-item, en voert u de functie zelf uit. Om door te gaan, stuurt u een nieuw verzoek waarvan de `input` het `function_call`-item herhaalt, gevolgd door een `function_call_output` met dezelfde `call_id`:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Tussen de twee verzoeken wordt niets open gehouden, en `previous_response_id` alleen is niet voldoende; je moet de aanroep en de uitvoer opnieuw afspelen. Toolnamen mogen letters, cijfers, underscores en koppeltekens bevatten, moeten uniek zijn en mogen niet een van de eigen tools van de agent overschaduwen. Een beurt die een van jouw tools aanroept, kan tegelijkertijd geen tools van de agent aanroepen; het model wordt gevraagd het opnieuw te proberen.

### Toolgoedkeuring via de API [#tool-approval-over-the-api]

Als je beheerder goedkeuring vereist voor bepaalde tools, kunnen API-aanroepen niet stoppen om iemand om toestemming te vragen. Tools die goedkeuring nodig hebben, of die geweigerd zijn, worden in plaats daarvan geblokkeerd. Beheerders moeten de tools die een onbewaakte client mag uitvoeren daarom expliciet toestaan.

## Agent Events [#agent-events]

Agent Events laten een ander systeem werk aan een agent overdragen en later terugkomen om te zien wat er is gebeurd. Dit is beta. Events gebruiken je Agents API-sleutel, die jou en de bron identificeert; alleen-OIDC-configuraties kunnen ze niet gebruiken. Ze hebben ook hun eigen rate limit, [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Een gebeurtenis komt binnen in een van drie modi:

- `fire` start een nieuwe conversatie met de agent.
- `continue` voegt een beurt toe aan een onderliggende agent die je eerder hebt gekoppeld (zie hieronder).
- `steer` voegt richtlijnen toe aan een run die nog bezig is, geïdentificeerd door het gesprek en de generatie die een `fire` heeft teruggegeven.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Elke aanvraag heeft één `Idempotency-Key` nodig (1 tot 256 letters, cijfers of `._~:/+=-`). Gebruik dezelfde sleutel opnieuw wanneer u dezelfde levering opnieuw probeert; het hergebruiken ervan voor andere inhoud is een conflict. LibreChat stelt de bron van de gebeurtenis in op basis van uw API-sleutel en negeert elke bron die u meestuurt. De payload wordt opgeslagen, dus houd geheimen erbuiten. Gebruik `orderingKey` wanneer gebeurtenissen over hetzelfde onderwerp in volgorde moeten worden verwerkt.

De respons is `202 Accepted` met een leverings-ID en een `Location` om met dezelfde sleutel te pollen:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Een levering heeft de status `pending`, `leased`, `succeeded` of `dead`. Voor een gebonden `continue` betekent `succeeded` alleen dat de beurt is gestart. De `handling`-status verandert daarna van `started` naar een van `applied`, `completed_no_action`, `failed` of `cancelled`. Als je een `expectedAction` meestuurt (een toolnaam en eventueel enkele van de argumenten), betekent `applied` dat LibreChat heeft gezien dat die tool is aangeroepen met overeenkomende argumenten; wat het model in tekst zegt, telt niet mee.

Agent Events zijn geen publieke webhook-ontvanger. Als de events afkomstig zijn van een provider die zijn webhooks ondertekent, verifieer dan de handtekening in je eigen adapter voordat je ze doorstuurt.

### Event-gestuurde kindagenten [#event-driven-child-agents]

Om een doorlopend gesprek met een child agent over meerdere gebeurtenissen heen te behouden, bindt u deze eenmalig en stuurt u vervolgens `continue`-gebeurtenissen naar de binding:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

De ouderconversatie moet een normale agentconversatie zijn, en het doel moet een van de directe subagents van die agent zijn (of de agent zelf, als zelf-spawnen is toegestaan). `actorId` mag maximaal 128 tekens lang zijn. Een nieuwe binding retourneert `201`, en een herhaling retourneert `200`, beide met de binding `id`. Latere beurten verwijzen ernaar:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Elke binding verwerkt één gebeurtenis tegelijk: de volgende wacht totdat de huidige beurt een definitieve verwerkingsstatus heeft, terwijl verschillende bindings parallel draaien. Een gekoppeld kind-item kan pauzeren voor Ask User of goedkeuring van een tool; de latere gebeurtenissen wachten tot iemand in LibreChat antwoordt. Dat vereist de duurzame MongoDB-checkpointer (de standaard). In het bovenliggende gesprek verschijnt elk gekoppeld kind-item als een rij onder het bericht dat de binding bezit, en opent het paneel met subagent-activiteit.

Een binding werkt alleen met de API-sleutel, gebruiker en tenant die deze heeft aangemaakt. De childthread blijft uit de chatlijst en is alleen-lezen in de app.

Voor gebeurtenissen die alleen observaties zijn, zoals "een spel is verder gegaan", geef je ze dezelfde `coalesce.key`, en LibreChat batcht er tot 8 van (binnen 750 ms en 512 KiB) tot één beurt. Elke gebeurtenis krijgt nog steeds zijn eigen ontvangstbevestiging. Coalesceer geen commando's, goedkeuringen of iets met een `expectedAction`.

## Agent Management API [#agent-management-api]

De Agent Management API stelt een vertrouwde service in staat om agents en vaardigheden aan te maken, te wijzigen en te verwijderen zonder browsersessie. Deze API is in bèta en gebruikt zijn eigen authenticatie: machine-OIDC-tokens van clients die de beheerder vermeldt onder [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi). Elke client is gekoppeld aan één bestaande LibreChat-gebruiker en tenant, en elk verzoek handelt namens die gebruiker, met de rechten en toegang van die gebruiker. Hierdoor wordt niemand een beheerder.

| Methode | Route | Doel |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | Een agent aanmaken |
| `GET` | `/api/agents/v1/agents` | Toegankelijke agents weergeven |
| `GET` | `/api/agents/v1/agents/{id}` | Een agent lezen |
| `PATCH` | `/api/agents/v1/agents/{id}` | Een agent bijwerken |
| `DELETE` | `/api/agents/v1/agents/{id}` | Een agent verwijderen |
| `POST` | `/api/agents/v1/agents/{id}/files` | Een bestand uploaden en koppelen |
| `GET` | `/api/agents/v1/agents/{id}/files` | Gekoppelde bestanden weergeven |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | Een bestand ontkoppelen |
| `GET` | `/api/agents/v1/skills` | Toegankelijke skills weergeven |
| `POST` | `/api/agents/v1/skills` | Een skill aanmaken |
| `GET` | `/api/agents/v1/skills/{id}` | Een skill lezen |
| `PATCH` | `/api/agents/v1/skills/{id}` | Een skill bijwerken |
| `DELETE` | `/api/agents/v1/skills/{id}` | Een skill verwijderen |
| `GET` | `/api/agents/v1/skills/{id}/files` | Bestanden van een skill weergeven |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | Een skillbestand lezen |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | Een skillbestand aanmaken of vervangen |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | Een skillbestand verwijderen |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agentpayloads nemen dezelfde velden als de Agent Builder en weigeren onbekende velden; `model` is verplicht bij het aanmaken. Lijsten accepteren `limit` (1 tot 100, standaard 20) en een `cursor`; wanneer `has_more` true is, geef dan de geretourneerde `after` mee als volgende cursor. Bestandsuploads zijn `multipart/form-data` met één `file` en een `tool_resource` zoals `context`, `file_search` of `execute_code`, onderworpen aan de gebruikelijke uploadlimieten.

Skill create neemt `name`, `description`, `body` en optioneel `displayTitle`, `frontmatter`, `category` en `alwaysApply`. Updates moeten de huidige versie van de skill meesturen als `expectedVersion`, zodat twee schrijvers elkaars wijzigingen niet stilzwijgend kunnen overschrijven.

Fouten gebruiken de codes `invalid_request`, `not_found`, `permission_denied`, `conflict` en `internal_error`. Een resource waar je geen toegang toe hebt, kan worden teruggegeven als `not_found`. Onjuiste of ontbrekende inloggegevens geven `401` terug.

Indien de beheerder dit inschakelt, wordt een OpenAPI-beschrijving van de beheerroutes aangeboden op `/api/openapi.json`, met interactieve documentatie op `/api/docs`. Deze dekt geen inferentie of events. Zie [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Gebruik en facturering [#usage-and-billing]

API-verzoeken tellen net zo goed mee voor je tokensaldo als chats in de app. De gebruikstotalen in het antwoord bevatten ook subagent-aanroepen, met een afzonderlijke `primary`- en `subagent`-uitsplitsing, plus cache- en redeneertokens waar de provider die rapporteert. Zie [Tokengebruik](/docs/configuration/token_usage).

## Setup [#setup]

De Agents API is standaard uitgeschakeld voor gewone gebruikers totdat een beheerder de Remote Agents-rechten aan hun rol toekent, hetzij in het [Admin Panel](/docs/features/admin_panel), hetzij met [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents). Beheerders hebben deze rechten standaard. API-sleutelauthenticatie is standaard ingeschakeld; om tokens van je eigen OIDC-provider te accepteren in plaats van of naast sleutels, zie [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi). De Management API wordt afzonderlijk geconfigureerd onder [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi), en instellingen voor eventbezorging staan onder [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven).
