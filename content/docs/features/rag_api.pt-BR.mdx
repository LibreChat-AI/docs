A **API RAG (Retrieval-Augmented Generation)** é um serviço separado que indexa os arquivos que você envia ao LibreChat e retorna os trechos mais relevantes para uma pergunta, para que o modelo possa responder com base nos seus documentos, e não apenas nos dados do seu treinamento.

É um aplicativo FastAPI em Python construído sobre o LangChain, e armazena os embeddings no PostgreSQL com a extensão pgvector.

**Para configurá-lo, consulte [Configuração da RAG API](/docs/configuration/rag_api).**

No LibreChat, o RAG alimenta a capacidade de **Pesquisa em Arquivos** ([Agentes](/docs/features/agents#file-search)) dos agentes (`file_search`). Os arquivos anexados à Pesquisa em Arquivos de um agente, ou a uma execução que selecione a Pesquisa em Arquivos, são indexados pela API RAG e recuperados sob demanda. Outros endpoints de chat não utilizam a indexação ou a recuperação do RAG, embora ainda possam usar a API RAG para extrair texto, conforme descrito abaixo.

A API RAG também expõe uma rota `/text` que o LibreChat pode usar para extrair texto de uploads; veja [Upload as Text](/docs/features/upload_as_text#what-happens-under-the-hood) para saber quando ela se aplica.

## Como funciona [#how-it-works]

1. **Indexação.** Quando um arquivo precisa ser pesquisável (no upload para o File Search de um agente, ou quando uma execução de chat usa o File Search pela primeira vez em um anexo), o LibreChat o envia para a API RAG, que divide o texto em trechos sobrepostos (`CHUNK_SIZE` e `CHUNK_OVERLAP`), converte cada trecho em um embedding com o provedor configurado e armazena os vetores no pgvector.
2. **Recuperação.** Quando o modelo chama a Pesquisa de Arquivos, ele escreve uma consulta de pesquisa. O LibreChat solicita à API RAG os 5 fragmentos mais próximos de cada arquivo anexado e, em seguida, mantém os 10 mais próximos no total.
3. **Respondendo.** Esses trechos são devolvidos ao modelo com o nome do arquivo e uma pontuação de relevância, e o modelo responde com base neles. Quando as [citações de arquivos](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) estão habilitadas, a resposta pode citar os arquivos utilizados.

Excluir um arquivo no LibreChat também remove seus vetores da API RAG.

A recuperação só encontra trechos semanticamente próximos à consulta, por isso funciona melhor para buscar fatos específicos em documentos grandes. Para perguntas que precisam do documento inteiro de uma vez, como resumi-lo, [Upload as Text](/docs/features/upload_as_text) geralmente oferece melhores resultados.

## O que é RAG? [#what-is-rag]

A Geração Aumentada por Recuperação (RAG, na sigla em inglês) ancora um modelo de linguagem em uma fonte de conhecimento externa. Em vez de depender apenas do que o modelo aprendeu durante o treinamento, a aplicação primeiro recupera trechos relevantes dessa fonte e os adiciona ao prompt; em seguida, o modelo gera sua resposta a partir deles. Como o conhecimento fica fora do modelo, é possível adicionar ou atualizar documentos sem precisar retreinar nada.
