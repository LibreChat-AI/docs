A busca de arquivos permite enviar documentos e fazer perguntas sobre eles sem colar o conteúdo no chat. O LibreChat envia cada arquivo para a API RAG, que o divide em partes (chunks) e as indexa; quando você faz uma pergunta, o modelo pesquisa nesse índice e responde com base nas passagens encontradas.

Use-a quando um documento for longo demais para ser lido por completo a cada turno, ou quando você quiser respostas que abranjam vários arquivos ao mesmo tempo.

## Enviar um arquivo para pesquisa [#upload-a-file-for-search]

Clique em **+** no [compositor de mensagens](/docs/features/composer) para abrir a paleta, expanda **More upload options**, depois escolha **Upload for File Search** e selecione seus arquivos. Pesquisar por essa opção na paleta também funciona. Enviar arquivos desta forma também ativa o **File Search** para o chat. Arquivos grandes podem levar um momento para serem indexados; o upload é concluído quando a indexação termina.

Quando a conversa tiver arquivos indexados, o modelo recebe uma ferramenta `file_search`. Ele decide quando chamá-la: uma pergunta sobre o documento dispara uma busca, enquanto conversas casuais não. A resposta mostra uma etapa "Searching your files" enquanto a busca é executada e, quando as citações estão habilitadas, os trechos utilizados aparecem em **Sources** com o nome do arquivo, para que você possa abrir o documento e conferir.

## Como a pesquisa funciona [#how-search-works]

Quando o modelo chama `file_search`, ele escreve uma consulta de busca. O LibreChat pede à API RAG os 5 trechos mais próximos em cada arquivo anexado e mantém os 10 mais próximos no total. Esses trechos voltam para o modelo com o nome do arquivo e uma pontuação de relevância, e o modelo responde com base neles.

A recuperação encontra trechos cujo significado está próximo da consulta, por isso é eficaz para buscar fatos específicos em documentos grandes. Para perguntas que exigem o documento inteiro de uma vez, como um resumo, o Upload as Text geralmente tem um desempenho melhor.

Excluir um arquivo no LibreChat também remove seus vetores da API RAG.

## Reutilize arquivos que você já enviou [#reuse-files-you-already-uploaded]

Os arquivos indexados permanecem na sua conta. Abra a paleta e procure em **Seus arquivos** para anexar um deles a uma nova mensagem ou conversa sem precisar enviá-lo novamente.

Arquivos enviados enquanto um endpoint de Assistants estava ativo são armazenados na OpenAI, não são indexados pela RAG API e não podem ser anexados a outros endpoints.

## Pesquisa de arquivos em agentes [#file-search-in-agents]

Para um agente, ative a [**Pesquisa em arquivos**](/docs/features/agents#file-search) no Construtor de Agentes e faça o upload dos arquivos ali. Eles se tornam a base de conhecimento do agente: qualquer pessoa que converse com o agente pode fazer com que ele pesquise nesses arquivos, sem precisar enviar nada por conta própria. O agente precisa ser salvo antes que você possa adicionar arquivos a ele.

## Pesquisa de arquivos ou upload como texto [#file-search-or-upload-as-text]

[**Enviar como Texto**](/docs/features/upload_as_text) fica no mesmo menu. Ele extrai o texto do arquivo e coloca todo o conteúdo na conversa, o que funciona bem para documentos curtos em que o modelo deve ler cada palavra. A pesquisa em arquivos envia apenas os trechos que correspondem a cada consulta, por isso escala para documentos longos e muitos arquivos, mas o modelo nunca vê as partes que não foram recuperadas.

A API RAG também atende ao Upload como Texto, como extrator de texto para tipos de arquivo que o analisador integrado não consegue ler. Veja [como o texto é extraído](/docs/features/upload_as_text#how-the-text-is-extracted).

## Configuração [#setup]

A pesquisa de arquivos precisa do serviço RAG API e de um banco de dados vetorial. A configuração padrão do Docker inclui ambos; um administrador define o provedor de embeddings e, para outras instalações, `RAG_API_URL`. Consulte a [configuração da RAG API](/docs/configuration/rag_api) e o [repositório da RAG API](https://github.com/LibreChat-AI/rag-api) para os endpoints e variáveis próprios do serviço.
