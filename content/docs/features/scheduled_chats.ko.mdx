예약된 채팅은 타이머에 따라 저장된 에이전트 중 하나에 고정된 프롬프트를 보냅니다. 실행될 때마다 새로운 대화가 시작되므로, 돌아왔을 때 완성된 답변을 확인할 수 있습니다. 예를 들어 아침 뉴스 브리핑, 주간 보고서, 무언가를 확인해 주는 알림 등이 있습니다.

Scheduled Chats는 실험적 기능이며, 관리자가 이를 활성화해야 합니다.

## 일정 만들기 [#create-a-schedule]

<Steps>
  <Step>
    사이드 패널에서 **Scheduled chats**를 열고 **New schedule**을 클릭하세요.
  </Step>
  <Step>
    이름을 정하고 프롬프트를 작성하세요. 프롬프트는 일반 텍스트로 전송되며, 작성기 변수는 채워지지 않습니다.
  </Step>
  <Step>
    에이전트를 선택하세요. 해당 에이전트에 대한 보기 및 사용 권한이 있어야 하며, 저장된 에이전트여야 합니다.
  </Step>
  <Step>
    **빈도**, **시간대**, 그리고 Chat Projects를 사용하는 경우 새 채팅이 들어갈 프로젝트를 선택하세요. 저장하세요.
  </Step>
</Steps>

### 빈도 [#frequency]

- **시간 단위**: 지정한 시각의 정해진 분에 실행됩니다.
- **Daily**: 하루에 한 번, 특정 시각에 실행됩니다.
- **평일**: 특정 시간에, 월요일부터 금요일까지.
- **주간**: 선택한 요일에 한 번의 시간으로 실행됩니다. 최소 하루 이상의 요일을 선택하세요.
- **사용자 지정**: 다섯 개 필드(분, 시, 일, 월, 요일)로 구성된 cron 표현식입니다. 입력하는 동안 대화 상자에 다음 몇 번의 실행 시각이 표시됩니다. `0 9,17 * * 1-5`는 평일 오전 9시와 오후 5시에 실행되고, `0 9 1 * *`는 매월 1일 오전 9시에 실행됩니다. 초(second) 및 연도(year) 필드는 지원되지 않습니다.

실행 간격은 관리자가 더 짧은 간격을 허용하지 않는 한 최소 1시간이어야 하며, 이는 사용자 지정 cron에도 동일하게 적용됩니다. 기본 설정에서는 `*/15 * * * *`가 거부됩니다.

### 시간대 [#time-zone]

새 스케줄은 브라우저의 시간대로 시작됩니다. 브라우저 시간대와 UTC가 목록 상단에 고정되어 표시됩니다. 시간은 사용자의 현재 위치가 아니라 스케줄의 시간대를 따릅니다. 일광 절약 시간(DST)도 처리되며, 전환일에 존재하지 않는 시간은 첫 번째 유효한 순간에 실행되고, 두 번 발생하는 시간은 한 번만 실행됩니다.

시간은 [설정](/docs/features/settings#general)에서 지정한 12시간 또는 24시간 형식으로 표시되며, 주의 시작 요일 역시 해당 설정을 따릅니다. 이 설정은 표시 방식만 바꿀 뿐, 실행 시점에는 영향을 주지 않습니다.

## 일정 관리 [#manage-schedules]

각 스케줄 카드에는 다음 실행 시점, 마지막 실행 결과, 그리고 최신 대화로 이동하는 링크가 표시됩니다. 카드에서 스케줄을 편집하거나, 활성화 또는 일시 중지하거나, **Run now**를 실행하거나, 삭제할 수 있습니다. **Run now**는 스케줄이 일시 중지된 상태여도 한 번의 실행을 시작하며, 이후 실행을 다시 켜지는 않습니다. 패널에는 허용된 스케줄 중 사용한 개수도 함께 표시됩니다.

실행이 질문을 하거나 도구 호출에 대한 승인을 요청하며 멈추면, 상태에 **승인 필요**가 표시됩니다. 대화를 열어 응답하면 실행이 계속됩니다.

## 실행이 발생하지 않는 경우 [#when-a-run-does-not-happen]

한 번에 하나의 스케줄 실행만 진행됩니다. 이전 실행이 아직 진행 중이거나 잔액이 부족한 경우, 실행은 **Skipped**(건너뜀) 처리됩니다.

실행 전에 LibreChat은 서브에이전트가 사용하는 MCP 서버를 포함하여 에이전트의 모든 MCP 서버를 확인합니다. 서버에 연결할 수 없거나, 다시 로그인이 필요하거나, 해당 서버에 대한 권한을 잃은 경우에는 실행이 시작되지 않습니다. 이 문제를 해결하려면 일정에서 **Open agent to reconnect MCPs**를 사용하세요. 이처럼 차단된 상태에서도 일정을 편집할 수 있습니다.

스케줄이 다음 조건에 해당하면 스스로 비활성화되며, 그 이유가 스케줄 카드에 표시됩니다:

- 여러 번 연속으로 실패합니다.
- 에이전트가 삭제되었거나, 유효하지 않거나, 해당 에이전트에 대한 접근 권한을 잃었거나, 에이전트를 사용할 권한을 잃은 경우,
- 잔액이 바닥나면,
- 필수 프로젝트가 누락되었거나 삭제되었습니다.

원인을 해결하고 스케줄을 다시 켜세요.

### 무인 실행을 위한 MCP 도구 인증 [#authorizing-mcp-tools-for-unattended-runs]

일부 배포 환경에서는 일정이 사용자 없이도 해당 도구를 사용할 수 있도록 먼저 MCP 액세스를 승인해야 합니다. 이 경우 일정 편집기에 **예약된 MCP 승인** 섹션이 있습니다. **승인 유효 기간(시간)**을 설정하고 **승인 확인**을 클릭하십시오. 카드에는 정확한 만료 시간과 함께 **승인됨**이 표시됩니다. 승인은 해당 에이전트와 나열된 리소스에만 적용되며, 승인 기한이 지나면 만료됩니다. 에이전트, 일정 또는 리소스를 변경하면 승인이 해제되므로 다시 확인해야 합니다. **승인 취소**를 사용하면 언제든지 승인을 철회할 수 있습니다.

## 설정 [#setup]

기본적으로 예약된 채팅(Scheduled Chats)은 꺼져 있습니다. 관리자가 이 기능을 활성화하고, 사용자당 예약 수나 최소 실행 간격과 같은 제한을 설정하며, 다중 레플리카 배포를 위한 Redis 요구 사항을 충족해야 합니다. 자세한 내용은 [Scheduled Chats 구성](/docs/configuration/scheduled_chats)을 참조하세요.
