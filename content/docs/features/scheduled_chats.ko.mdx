Scheduled Chats를 사용하면 저장된 LibreChat Agent가 사용자가 제공한 프롬프트로 자동으로 새 대화를 시작할 수 있습니다. 정기 보고서, 알림, 조사 및 수동으로 대화를 시작할 필요 없이 실행되어야 하는 기타 Agent 워크플로우에 이 기능을 활용하세요.

<Callout type="warning" title="실험적 기능이며 기본적으로 비활성화됨">
  Scheduled Chats는 초기 실험 단계에 있습니다. 해당 기능의 동작, 구성 및 배포 요구 사항은 크게 변경될 수 있습니다. 예약된 실행은 모델, 도구 및 Code Interpreter 리소스를 소비할 수 있으므로, 관리자가 명시적으로 선택하지 않는 한 LibreChat은 이 기능을 활성화하지 않습니다.
</Callout>

## 예약된 채팅 활성화 [#enable-scheduled-chats]

`librechat.yaml`에 `interface.schedules`를 추가한 다음, LibreChat을 재시작하세요:

```yaml filename="librechat.yaml"
interface:
  schedules:
    use: true
    create: true
    maxPerUser: 10
    minIntervalMinutes: 60
    autoDisableAfterFailures: 5
    fireConcurrency: 5
    requireProject: false
    # projectId: '000000000000000000000000'
```

`use` 및 `create`는 시작 시 내장 `USER` 역할에 대한 `SCHEDULES` 권한을 시드(seed)합니다. 관리자는 [Admin Panel](/docs/features/admin_panel)에서 역할별로 해당 권한을 관리할 수 있습니다. 나머지 값은 런타임 제한입니다:

    ['minIntervalMinutes', 'Number', '발생 간 허용되는 최소 간격입니다.', '60'],

`schedules` 필드 전체는 기본적으로 존재하지 않습니다. `schedules: true`는 기본 제한으로 기능을 활성화하며, `schedules: false` 또는 `schedules: { use: false }`는 배포 전체에서 기능을 중단합니다. 비활성화된 기본 구성은 역할, 그룹 또는 사용자 구성 재정의를 통해 다시 활성화할 수 없습니다. `maxPerUser`는 슬롯 계산이 도입되기 전에 생성된 정의를 포함하여 소유한 모든 일정을 계산합니다. 전체 병합 및 권한 동작에 대해서는 [`interface.schedules`](/docs/configuration/librechat_yaml/object_structure/interface#schedules)를 참조하세요.

## 일정 생성 및 관리 [#create-and-manage-a-schedule]

사이드 내비게이션에서 **Scheduled Chats**를 열고 **New schedule**을 선택하세요. 일정에는 다음이 필요합니다:

- 이름과 프롬프트
- 보고 사용할 수 있는 저장된 Agent
- 매시간, 매일, 평일, 매주 또는 사용자 지정 cron 주기
- IANA 시간대
- 관리자가 요구하거나 고정하지 않는 한, 선택적으로 지정할 수 있는 Chat Project 대상입니다.

새로운 일정은 현재 브라우저의 IANA 시간대를 기준으로 시작됩니다. 브라우저 시간대와 UTC가 상단에 고정되어 있으며 각 옵션마다 현재 GMT 오프셋이 표시되므로, 지원되는 다른 IANA 시간대를 선택할 수 있습니다. 기존 일정은 저장된 시간대로 다시 열립니다. `Intl.supportedValuesOf`를 지원하지 않는 브라우저에서도 현재 시간대, UTC 또는 일정에 저장된 시간대를 계속 사용할 수 있습니다. 시간대만 변경하는 것은 타이밍 변경으로 간주됩니다. LibreChat은 다음 발생 시점을 다시 계산하고 배포의 최소 간격에 맞춰 주기를 재검증합니다.

구조화된 주기(cadence) 옵션은 다음과 같습니다:

- **매시간(Hourly)**: `00`에서 `59` 사이의 분을 선택하세요.
- **Daily**: 현지 시간 중 하나를 선택하세요.
- **평일**: 월요일부터 금요일까지 중 현지 시간 하나를 선택하세요.
- **Weekly**: 하나 이상의 요일과 현지 시간을 선택하세요. 최소 하루는 선택해야 합니다.

시간 제어는 브라우저의 [Clock Format preference](/docs/features/settings#general)를 따르며, 주간 요일 제어 및 요약은 브라우저의 **Week Starts On** 기본 설정을 따릅니다. 이러한 기본 설정은 표시 방식만 변경하며, 저장된 IANA 시간대와 선택된 요일이 실행을 결정합니다.

**Custom**을 선택하여 `minute hour day-of-month month day-of-week` 순서로 5개 필드의 cron 표현식을 입력하세요. 초(seconds) 및 연도(year) 필드는 허용되지 않으며, 256자를 초과하는 표현식이나 향후 실행 시점이 없는 표현식도 거부됩니다. 대화 상자는 서버와 동일한 파서를 사용하여 선택한 시간대에서 예정된 실행 시점을 검증하고 미리 보여줍니다. 예시로는 평일 09:00 및 17:00을 의미하는 `0 9,17 * * 1-5`와 매월 1일 09:00을 의미하는 `0 9 1 * *`가 있습니다. 모든 주기는 여전히 `minIntervalMinutes`를 충족해야 합니다. 예를 들어, `*/15 * * * *`를 사용하려면 관리자가 기본값인 60분보다 짧은 간격을 허용하도록 설정해야 합니다.

일광 절약 시간제 전환은 시간대 인식을 유지합니다. 존재하지 않는 현지 시간은 첫 번째 유효한 시점으로 이동하며, 반복되는 현지 시간은 한 번만 실행됩니다. 간격 유효성 검사는 효과적인 주기와 시간대를 함께 측정하며, 봄철 시간 앞당김(spring-forward) 전환 시 발생하는 단축된 실시간 간격을 포함합니다. 따라서 시간대를 변경하면 유효했던 표현식이 구성된 최소 기준값 미만으로 떨어질 수 있습니다. 예약된 프롬프트는 리터럴 텍스트이며, 이 형식에서는 메시지 작성기 변수 삽입을 사용할 수 없습니다.

각 발생 시점마다 선택된 Agent와 새로운 대화가 시작됩니다. 일정 카드는 다음 발생 시점과 최신 상태를 보여주며, 대화가 존재할 경우 최신 대화로 연결됩니다. `SCHEDULES: CREATE` 권한이 있는 사용자는 자신의 일정을 편집, 활성화 또는 비활성화, 즉시 실행 및 삭제할 수 있습니다. **지금 실행(Run now)**은 향후 발생을 다시 활성화하지 않고도 비활성화된 일정을 한 번 시작할 수 있지만, 여전히 권한, 배포 용량 및 전역 중지 설정을 따릅니다.

실행이 사용자에게 묻기(Ask User) 또는 도구 승인을 위해 일시 중지되면, 상태가 **승인 필요(Needs approval)**로 변경되며 대화창을 열어 결정을 완료할 수 있습니다. LibreChat은 동일한 일정의 중복 실행을 방지하며, 다른 실행이 활성화되어 있거나 계정 잔액이 부족한 경우 실행을 건너뛸 수 있습니다.

실행 가능한 생성 용량을 소비하기 전에, LibreChat은 예약된 Agent와 실행 가능한 Subagent 그래프에 필요한 선택된 모든 MCP 도구를 확인합니다. 도구가 없거나, 서버를 사용할 수 없거나, 권한이 취소되었거나, 카탈로그가 불완전하거나, 상호작용이 필요한 인증 흐름이 있는 경우 실행이 차단되며, 수리가 필요한 Agent가 식별됩니다. 예약 UI는 **Open agent to reconnect MCPs** 복구 작업을 제공합니다. 비활성화된 예약은 MCP 서버를 사용할 수 없는 동안에도 편집할 수 있습니다.

### 예약된 MCP 인증 [#scheduled-mcp-authorization]

배포에서 `interface.schedules.mcpConsent`를 활성화하면, MCP 도구를 사용하는 스케줄은 사람이 개입하지 않고(무인으로) 실행되기 전에 저장된 **예약된 MCP 승인(Scheduled MCP authorization)**이 필요합니다. 이 승인은 나열된 에이전트와 리소스에 대해서만, 고정된 만료 시점까지 유효합니다. 승인은 제공자(provider)를 다시 연결하거나, 스케줄을 활성화하거나, 쓰기 작업을 허용하지 않습니다.

스케줄 편집기에서 다음을 할 수 있습니다:

- **인증 유효 기간(시간)**을 설정합니다.
- **Confirm authorization**을 선택하여 기록합니다. 그러면 카드에 **Authorized**와 절대 만료 시간이 표시됩니다.
- 권한을 취소하려면 **Revoke authorization**을 선택하세요.

상태에는 확인하기 전까지 **Authorization required**가 표시되고, 기한이 지나면 **Authorization expired**, 취소 후에는 **Authorization revoked**가 표시됩니다. Agent, 일정 또는 리소스 바인딩을 변경하면 승인이 무효화되며, 다시 검토하고 확인해야 합니다.

관리자는 [`interface.schedules`](/docs/configuration/librechat_yaml/object_structure/interface#schedules)에서 이를 구성합니다:

- `mcpConsent.enabled`는 이 기능을 활성화합니다.
- `mcpConsent.maxLifetimeHours`는 인증 유효 기간의 상한을 설정합니다(1~8760시간).
- `mcpConsent.resources`는 인가될 수 있는 MCP 리소스를 바인딩합니다.
- `mcpConsent.readOnlyPolicy`는 서버와 업스트림 도구 이름을 키로 사용하여 신뢰할 수 있는 읽기 전용 도구 선언 목록을 정의합니다.
- `mcpReceiptRetry.baseMs`와 `mcpReceiptRetry.maxMs`는 동의 영수증(consent receipt)에 대한 상한이 있는 지수 백오프 재시도 간격을 설정하며, 지터(jitter)가 적용됩니다.

스케줄은 반복적인 실패가 발생하거나, 연결된 Agent가 삭제되거나, 구성이 유효하지 않거나, 액세스 권한이 취소되거나, 계정 잔액이 부족하거나, 필수 프로젝트가 누락되거나, 유효한 프로젝트가 삭제되었거나 스케줄 소유자가 해당 프로젝트를 소유하지 않은 경우 자동으로 비활성화될 수 있습니다. 프로젝트 정책은 매 실행 시마다 재확인되므로 `requireProject`를 강화하거나 핀(pin)을 변경하면 기존 스케줄에도 동일하게 적용됩니다. 스케줄을 다시 활성화하기 전에 근본적인 문제를 해결하십시오.

운영자 수준의 `projectId`는 각 일정에 저장된 프로젝트를 재정의하며 `requireProject`를 암시합니다. Chat Projects는 사용자가 소유하므로, 전역 고정(global pin)은 일반적으로 해당 프로젝트 소유자에게만 작동합니다. 서로 다른 소유자가 서로 다른 고정된 대상을 지정해야 하는 경우 역할 또는 사용자 구성 재정의를 사용하십시오.

## 권한 [#permissions]

`SCHEDULES: USE`는 사용자가 자신의 일정을 나열하고 조회할 수 있는지 여부를 제어합니다. `SCHEDULES: CREATE`는 추가적으로 일정 생성, 편집, 활성화, 실행 및 삭제 권한을 제어합니다. 예약된 실행은 실행 시점에 사용자의 Agent 기능 권한과 선택된 Agent에 대한 조회 권한을 다시 확인하며, 두 권한 중 하나라도 상실되면 해당 일정은 비활성화됩니다.

역할 권한 및 리소스 ACL에 대한 내용은 [Access Control](/docs/features/access_control)을 참조하세요.

## 배포 안전성 [#deployment-safety]

Scheduled Chats는 MongoDB 리스(lease), 멱등성 트리거 전달, 중복 방지 기능을 사용하여 적격 복제본이 지속적인 발생을 조정할 수 있도록 합니다. 다중 복제본 배포의 경우 `USE_REDIS_STREAMS=true`를 설정하여 Redis 기반의 재개 가능한 스트림을 활성화해야 합니다. 공유 스트림이 없으면 다른 복제본이 재개하거나 중지할 수 없는 작업을 허용하는 대신, 예약 쓰기가 실패하고 차단(fail closed)됩니다.

'Ask User' 또는 도구 승인을 위해 일시 중지할 수 있는 예약된 Agent는 공유 작업 상태를 위해 `USE_REDIS_STREAMS=true`가 필요하며, 단일 프로세스 배포 환경에서도 그래프 지속성을 위해 영구적인 공유 체크포인터가 필요합니다. 내장된 기본 MongoDB 체크포인터는 이 요구 사항을 충족하지만, `type: memory`는 그렇지 않습니다. 공유 저장소를 사용할 수 없는 경우 LibreChat은 모델 작업이 시작되기 전에 실행을 거부합니다.

Redis 없이 LibreChat 프로세스를 하나만 실행하는 배포 환경에서는 다음을 선택할 수 있습니다:

```bash filename=".env"
SCHEDULES_SINGLE_PROCESS=true
```

다중 프로세스 또는 다중 복제본 배포 환경에서는 이를 설정하지 마십시오. 레거시 실험적 클러스터 서버 진입점(entrypoint)은 스케줄 엔진을 활성화하지 않습니다. 수평적 확장을 위해서는 Redis 기반 스트림을 사용하는 LibreChat의 표준 서버 진입점을 사용하십시오.

즉각적인 배포 전체 중단을 위해서는 `SCHEDULES_DISABLED=true`로 설정하십시오. 이는 일정 정의를 삭제하지 않고 자동 실행 및 **지금 실행(Run now)**을 차단합니다. [Scheduled Chats environment variables](/docs/configuration/dotenv#scheduled-chats)를 참조하십시오.

[`admissionConcurrency`, `mcpPreflightConcurrency`, 및 `mcpPreflightTimeoutMs`](/docs/configuration/librechat_yaml/object_structure/interface#schedules)를 사용하여 생성 동시성과 독립적으로 스케줄 승인 및 MCP 준비 작업을 제한하십시오.
