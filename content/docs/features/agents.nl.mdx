Een agent is een opgeslagen configuratie: een model, een systeemprompt, en de tools en bestanden die het kan gebruiken. Je bouwt hem één keer in de Agent Builder en selecteert hem vervolgens wanneer je een chat start. Agents werken met elke provider die je hebt geconfigureerd, niet alleen met OpenAI.

## Een agent maken [#create-an-agent]

<Steps>
  <Step>
    Open **Agent Builder** in het zijpaneel en klik op **Create New Agent**.
  </Step>
  <Step>
    Geef het een naam, een optionele beschrijving, en kies een **Model** en **Categorie**. Het model en de categorie zijn verplicht.
  </Step>
  <Step>
    Schrijf de instructies. Je kunt ze inline typen, of de bron wijzigen naar **Prompt** om een opgeslagen prompt uit je promptbibliotheek te gebruiken (zie hieronder).
  </Step>
  <Step>
    Voeg tools toe onder **Tools** (zie hieronder) en klik vervolgens op **Create**.
  </Step>
</Steps>

Het uploaden van bestanden voor File Search of File Context werkt pas nadat de agent is aangemaakt.

Om met een agent te chatten, selecteer je deze in de modelkiezer, open je hem via de [Agent Marketplace](#agent-marketplace), of typ je `@` in het chatvak en kies je hem uit de lijst. In de agentselector van de builder beperkt **My agents** de lijst tot agents die je zelf hebt aangemaakt.

### Instructies uit een opgeslagen prompt [#instructions-from-a-saved-prompt]

Met de instructiebron ingesteld op **Prompt** kies je onder **Select a prompt** een prompt en een **Version**: ofwel de productieversie, die de markering van de eigenaar van de prompt volgt voor productie, ofwel een vaste opgeslagen versie. Hiervoor heb je toegang nodig tot de promptbibliotheek. Als iemand anders de agent opent zonder toegang tot de gekoppelde prompt, toont de builder **Restricted prompt** en kan die persoon de prompt vervangen of terugschakelen naar inline instructies.

Instructies, inline of via een link, kunnen `{{current_date}}`, `{{current_datetime}}` en `{{iso_datetime}}` gebruiken. Deze worden eenmalig ingevuld aan het begin van elke beurt en blijven gelijk gedurende toolaanroepen, subagents en goedkeuringspauzes. De eerste twee gebruiken je tijdzone; `{{iso_datetime}}` is UTC.

### Modelparameters [#model-parameters]

Het modelpaneel toont dezelfde parameters als een normale chat voor die provider (temperatuur, maximaal aantal uitvoertokens, enzovoort), plus **Image Detail** voor visuele invoer. Waarden die hier worden opgeslagen, gelden voor elk gesprek met de agent.

### Gespreksstarters [#conversation-starters]

Onder **Conversation Starters** kun je maximaal vier prompts toevoegen. Deze verschijnen als knoppen op het lege chatscherm wanneer iemand een nieuwe chat met de agent start, en door op een ervan te klikken wordt deze meteen verzonden. De starters van een agent vervangen alle starters die zijn gedefinieerd in de model spec die in gebruik is. Ze verschijnen ook in de Marketplace-details van de agent.

### Versiegeschiedenis [#version-history]

Elke keer dat je de agent opslaat met een wijziging, wordt er een item toegevoegd aan **Versiegeschiedenis**. Hierin zie je wanneer elke versie is opgeslagen en welke tools en mogelijkheden deze had. **Herstellen** vervangt de huidige configuratie door die versie, na een bevestiging. Alleen gebruikers die de agent kunnen bewerken, zien dit.

## Tools [#tools]

Klik op **Toevoegen** naast de kop **Tools** in de builder (er staat **Nog geen tools** totdat je er een toevoegt) om de **Toolbibliotheek** te openen. Zoek erin, of filter op **Native**, **Tools**, **MCP-servers** of **Actions**. **Door jou gemaakt** verzamelt de MCP-servers en Actions die je hebt aangemaakt, en **Favorieten** houdt met ster gemarkeerde items binnen handbereik over alle agents heen (tot 100). Via het menu **Nieuw maken…** voeg je een MCP-server of een Action toe zonder het dialoogvenster te verlaten, mits je rol dat toestaat. Wat je ziet, hangt af van wat je beheerder heeft ingeschakeld en van de rechten van je rol; een item dat nog een API-sleutel nodig heeft, toont **Instellen vereist**.

Run Code, File Search en File Context bevatten bestanden. Zolang ze nog bestanden gekoppeld hebben, opent het verwijderen ervan in plaats daarvan de bestandsbeheerder, en blijven ze aan de agent gekoppeld totdat die bestanden zijn verwijderd.

### Code Interpreter [#code-interpreter]

Vermeld als **Run Code**. De agent schrijft en voert code uit in een sandbox, wat je wilt voor berekeningen, data-analyse en het maken van bestanden zoals grafieken of spreadsheets. Bestanden die je in de builder aan deze tool koppelt, zijn bij elke uitvoering beschikbaar in de sandbox. Als geen van de codebestanden van een gesprek in de sandbox kan worden hersteld, stopt de agent voordat het model wordt aangeroepen en vraagt je om ze opnieuw te koppelen. Zie [Code Interpreter](/docs/features/code_interpreter).

#### Stateful code sessions [#stateful-code-sessions]

Als uw beheerder dit heeft ingeschakeld, bewaren **Stateful code sessions** in de instellingen van Run Code een sandbox-werkruimte tussen runs, zodat bestanden en geïnstalleerde pakketten behouden blijven. **Stateful environment** bepaalt wie die werkruimte deelt: **User workspace (recommended)** voor al uw stateful agents, **Agent + user workspace** voor één werkruimte per agent, of **Conversation workspace** voor één werkruimte per chat. Nieuwe agents beginnen met de **Default stateful workspace** onder **Settings > Data & Privacy > Code execution**. Als de beheerder meerdere backends heeft ingesteld, bepaalt **Execution environment** welke backend de code uitvoert. Dit kan ook een worker zijn die u op uw eigen machine koppelt.

De werkruimte kan op elk moment worden gereset, dus behandel deze niet als opslag. In beheerde omgevingen moet je de uitvoer die je nodig hebt opslaan onder `/mnt/data`. Bestanden die de agent schrijft met zijn bestandstools worden per bericht vermeld onder **Werkruimtewijzigingen**, waar je ze kunt downloaden. Met een gekoppelde omgeving biedt de invoervelden de opties **Vragen voordat wijzigingen worden aangebracht**, **Bewerkingen accepteren** of **Volledige toegang** als goedkeuringsmodus voor die chat, binnen de grenzen die je beheerder instelt.

Deze functie is zeer experimenteel. Zie [stateful code sessions](/docs/features/code_interpreter#stateful-code-sessions) voor details.

### Web Search [#web-search]

De agent zoekt op het web en vermeldt zijn bronnen. Hiervoor is een zoekprovider nodig die door je beheerder is ingesteld, of je eigen sleutel als de beheerder dat zo heeft ingericht. Zie [Web Search](/docs/features/web_search).

### Bestandszoekopdracht [#file-search]

Maakt van de bestanden die je toevoegt een doorzoekbare kennisbank. De agent haalt de meest relevante passages op wanneer dat nodig is, zodat het ook goed omgaat met grote documentsets. Het is minder geschikt voor gestructureerde gegevens zoals CSV of Excel, waarvoor Run Code beter werkt. Vereist de [RAG API](/docs/features/rag_api).

### Bestandscontext [#file-context]

Bestanden die onder **File Context** worden toegevoegd, worden één keer bij het uploaden geëxtraheerd, en die tekst wordt bij elk bericht aan de context van de agent toegevoegd. Gebruik dit voor een paar belangrijke documenten die de agent altijd voor zich moet hebben. De extractie werkt op dezelfde manier als bij [Upload as Text](/docs/features/upload_as_text): standaard via het parsen van platte tekst, en betere resultaten bij scans en afbeeldingen als [OCR](/docs/features/ocr) is geconfigureerd.

Omdat de tekst bij elk bericht wordt meegestuurd, kosten grote bestanden hier bij elke beurt tokens. Iedereen die met de agent kan chatten, kan die tekst ook uit de agent loskrijgen.

### Artifacts [#artifacts]

Laat de agent React, HTML, SVG, Markdown en Mermaid weergeven in een zijpaneel in plaats van als codeblokken. De instelling **Mode** bepaalt welke ingebouwde instructies worden gebruikt: **Normal**, **shadcn/ui** (voegt instructies toe voor de shadcn/ui-componentenbibliotheek) of **Custom**, waarbij niets wordt toegevoegd en je eigen instructies de artifact-syntaxis moeten uitleggen. Zie [Artifacts](/docs/features/artifacts) voor die syntaxis.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP-servers die je beheerder heeft geconfigureerd, of die je zelf hebt toegevoegd, verschijnen onder **MCP-servers**. Wanneer je een server toevoegt, worden alle bijbehorende tools gekoppeld; vouw deze uit onder **Tools in deze server** om alleen de tools te kiezen die de agent nodig heeft. Zie [MCP](/docs/features/mcp).

Sommige servers kunnen hun tools alleen tijdens een chat weergeven, omdat ze afhankelijk zijn van waarden uit het verzoek. Voor deze servers biedt de builder één selectie voor alle tools van de server, in plaats van schakelaars per tool. Als alle geselecteerde MCP-tools van een agent niet kunnen worden geladen wanneer een run start, stopt de run en wordt je gevraagd om opnieuw verbinding te maken met de server of je aan te melden, in plaats van zonder deze tools verder te gaan.

Elke MCP-tool heeft een menu **Tool Options** met een paar schakelaars per tool:

- **Uitstellen**: zie [Uitgestelde tools](#deferred-tools). **Alle tools uitstellen** doet dit voor de hele server.
- **Programmatisch**: zie [Programmatische toolaanroep](#programmatic-tool-calling).
- **Achtergrond**: zie [Achtergrondtoolaanroepen](#background-tool-calls).
- **Intentlabel**: de agent schrijft bij elke aanroep een beschrijving van één regel, die live wordt getoond als de status van de aanroep in plaats van een generiek label. Dit voegt enkele tokens toe aan elk verzoek. Native tools krijgen automatisch intentlabels. Dit geldt niet voor programmatische tools.

**Achtergrond** en **Intentlabel** verschijnen alleen als je beheerder deze heeft ingeschakeld.

### Uitgestelde tools [#deferred-tools]

Een agent met meerdere MCP-servers kan gemakkelijk tientallen tooldefinities bevatten, en als ze allemaal bij elke aanvraag worden meegestuurd, neemt dat context in beslag en wordt het model slechter in het kiezen van de juiste tool. Een uitgestelde tool wordt niet opgenomen in de initiële aanvraag. In plaats daarvan krijgt de agent een tool-zoektool, vindt hij uitgestelde tools op naam of beschrijving wanneer hij ze nodig heeft, en kan hij een gevonden tool gebruiken voor de rest van het gesprek.

### Programmatische toolaanroepen [#programmatic-tool-calling]

Met **Programmatic** ingeschakeld voor een MCP-tool (of een volledige server) roept het model die tool niet rechtstreeks aan. Het schrijft code in de Code Interpreter-sandbox die de tool als functie aanroept, zodat het resultaten kan doorlopen, pagineren, opnieuw proberen en filteren voordat het antwoordt. Dit helpt bij taken zoals "controleer deze 40 tickets en vat de open tickets samen", die anders 40 afzonderlijke toolaanroepen via het model zouden vergen.

De **Programmatic**-schakelaars blijven uitgeschakeld totdat Run Code is ingeschakeld, en het verwijderen van Run Code wist ze. De sandbox kan alleen tools aanroepen die zijn geregistreerd bij de agent. Terwijl deze draait, kun je de codekaart uitklappen om een live overzicht te zien van elke interne toolaanroep; dit overzicht wordt niet bewaard nadat je de pagina opnieuw laadt. Dit staat standaard uit; je beheerder moet dit inschakelen.

### Achtergrondtoolaanroepen [#background-tool-calls]

Een tool die op de achtergrond kan draaien, geeft meteen een taakreferentie terug, zodat de agent kan doorwerken terwijl deze loopt. Wanneer de taak klaar is, wordt het resultaat automatisch in een volgende beurt geleverd (weergegeven als een inklapbare taakkaart), of de agent kan de status controleren met zijn taaktool. Uitvoer en bestanden die op de achtergrond zijn gegenereerd, verschijnen bij de oorspronkelijke toolaanroep. Welke tools op de achtergrond mogen draaien:

- **Run Code**: code en shell-opdrachten komen standaard in aanmerking; schakel **Achtergronduitvoering** uit in de instellingen om dit te weigeren.
- **MCP-tools**: markeer een tool of een volledige server als **Achtergrond**.
- **Andere tools en Acties**: schakel **Achtergronduitvoering** in. Acties die OAuth gebruiken, bieden dit niet aan.

Deze schakelaars maken achtergronduitvoering mogelijk; het model beslist nog steeds per aanroep. Achtergrondtaken worden uitgevoerd in het serverproces dat ze heeft gestart en gaan verloren als dat proces stopt. Je beheerder moet de functie inschakelen.

### Actions [#actions]

Acties zetten een OpenAPI-specificatie om in tools. Kies **Nieuwe maken…** en vervolgens **Acties**, plak het schema en stel **Authenticatie** in als de API dit vereist. Elke bewerking in de specificatie wordt een tool die de agent kan aanroepen.

Als u een OpenAI-model gebruikt, voeg dan `x-strict: true` toe aan een operatie in de spec, dan vraagt LibreChat strikte functieaanroepen voor die operatie aan. De strikte modus accepteert alleen een subset van JSON Schema; zie de [gids voor gestructureerde uitvoer](https://platform.openai.com/docs/guides/structured-outputs) van OpenAI.

Acties kunnen alleen domeinen bereiken die je beheerder toestaat, en privénetwerkadressen worden geblokkeerd, tenzij dit expliciet is toegestaan.

### Skills [#skills]

De **Skills**-sectie in de builder bepaalt welke [Skills](/docs/features/skills) de agent kan gebruiken: **Uit**, **Alle** (elke skill die je actief hebt) of **Geselecteerd** (alleen de skills die je toevoegt).

### Memory [#memory]

**Geheugen** stelt de agent in staat om herinneringen over jou op te slaan, bij te werken en te verwijderen wanneer je de agent vraagt iets te onthouden of te vergeten. Hiervoor moet geheugen op de instantie zijn ingesteld en toegestaan zijn voor jouw rol. Standaard deelt de agent je persoonlijke herinneringen met je andere chats; schakel **Houd herinneringen gescheiden voor deze agent** in om de agent zijn eigen herinneringen te geven, die alleen hij leest en schrijft. Zie [Geheugen](/docs/features/memory).

### Vraag gebruiker en goedkeuring van tools [#ask-user-and-tool-approval]

**Ask User** laat de agent tijdens een run even pauzeren om je iets te vragen en te wachten op je antwoord. Eén pauze kan maximaal vier vragen bevatten, die één voor één worden getoond met **Back** en **Next**; bij elke vraag kun je een vrij antwoord geven of een van de keuzes van de agent kiezen. Met **Skip** wijs je alle vragen af. De run wordt direct hervat zodra je je antwoorden indient, en je antwoorden blijven bewaard, ook als je stopt terwijl de run opnieuw wordt gestart.

Uw beheerder kan ook vereisen dat goedkeuring wordt gegeven voordat bepaalde tools worden uitgevoerd. De run wordt dan gepauzeerd, u bekijkt de aanroep in een paneel boven het berichtvak (goedkeuren, afwijzen of, voor sommige tools, de argumenten bewerken), en daarna wordt de run voortgezet. Als de beheerder per-agent goedkeuringsmodi heeft ingeschakeld, krijgt elke tool van de agent een **Tool approval mode**: **Use inherited policy**, **Always ask**, **Always approve**, **Ask once per chat** of **Ask once, then always approve**. Beheerdersregels blijven hierbovenop van toepassing, en met **Reset my remembered approvals** wist u de goedkeuringen die u eerder heeft gegeven.

### Andere tools [#other-tools]

De **Tools**-categorie bevat de ingebouwde integraties die je beheerder heeft ingeschakeld, zoals [beeldgeneratie](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search) en [Azure AI Search](/docs/configuration/tools/azure_ai_search). Elk daarvan wordt afzonderlijk ingesteld; zie [Tools](/docs/configuration/tools).

## Werken met andere agents [#working-with-other-agents]

**Subagents** laten de agent een afgebakende subtaak doorgeven aan een nieuwe kopie van zichzelf, of aan een andere agent, in een afzonderlijk contextvenster. Alleen het resultaat komt terug, zodat lange tooluitvoer buiten het hoofdgesprek blijft. Zie [Subagents](/docs/features/subagents).

### Overdrachten [#handoffs]

**Handoffs** geven de agent voor elke agent die je opgeeft een overdrachtstool, zodat hij het gesprek kan doorgeven aan een specialist wanneer het onderwerp daarom vraagt. Voor elke handoff kun je een beschrijving toevoegen (wanneer moet worden overgedragen) en passthrough-inhoud (wat de agent moet genereren en doorgeven), en je kunt de parameter hernoemen waarin die inhoud wordt doorgegeven (standaard `instructions`). Een agent kan maximaal 10 handoffs hebben. Handoffs zijn altijd beschikbaar; ze zijn niet afhankelijk van een beheerdersinstelling.

### Agentketen [#agent-chain]

Agent-chains zijn verouderd. Bestaande chains worden nog steeds uitgevoerd, en de builder toont ze onder **Geavanceerde instellingen** met een knop **Chain verwijderen**, maar je kunt geen nieuwe meer aanmaken. Gebruik in plaats daarvan subagents of handoffs.

## Maximale agentstappen [#max-agent-steps]

**Geavanceerde instellingen** heeft een veld **Max. agentstappen** dat bepaalt hoeveel stappen de agent mag zetten voordat hij een definitief antwoord moet geven. Een stap is één modelverzoek of één ronde van toolaanroepen. Eén toolaanroep kost daarom meestal drie stappen: het verzoek, de toolronde en het vervolgverzoek.

Laat dit leeg om de standaardwaarde van de server te gebruiken, die 50 is tenzij uw beheerder deze heeft gewijzigd. Uw beheerder kan ook een maximumwaarde instellen die het veld niet kan overschrijden.

Wanneer een beurt geen stappen meer heeft, behoud je wat de agent tot dan toe heeft gedaan, en biedt het bericht de optie **Doorgaan** (een nieuwe beurt met een nieuw budget) of **Nu antwoorden** (de agent antwoordt op basis van het reeds uitgevoerde werk, zonder extra tools). Als dit vaak voorkomt bij lange toolketens, verhoog dan de limiet.

## Na een lange run [#following-a-long-run]

Toolkaarten tonen **Voorbereiden** terwijl een aanroep wacht (bijvoorbeeld op goedkeuring) en daarna **Aanroepen** totdat het resultaat terugkomt. Shell-uitvoer wordt in terminalstijl getoond en samengevouwen tot de laatste 15 regels; met **Toon meer** wordt deze uitgevouwen, en een opdracht die mislukt is, toont de exitcode, het signaal of de time-out.

### Activiteitsgroepen [#activity-groups]

Als uw beheerder ze heeft ingeschakeld, klappen elke reeks van redenering en toolaanroepen in onder een automatisch gegenereerde koptekst van één regel, zodat een run met 30 toolaanroepen als enkele regels wordt weergegeven. Vouw een koptekst uit om de aanroepen erin te zien. Een tweede niveau kan meerdere van die groepen samenvatten in een fase met een eigen samenvatting, waardoor lange runs een overzicht krijgen; zodra twee groepen zijn afgerond, worden ze meteen samengevoegd, waarbij de nieuwste koptekst de plaats inneemt tot de samenvatting beschikbaar is. Het uiteindelijke antwoord blijft altijd buiten de vouw, en bestanden die binnen een fase zijn geproduceerd, worden onder die fase op een rij getoond in plaats van verborgen. Met [Smooth Streaming](/docs/features/smooth_streaming) ingeschakeld wordt de vouw geanimeerd, tenzij uw apparaat om verminderde beweging vraagt.

Live redeneerlabels zijn een verwante optie: in plaats van een generieke **Thinking**-kop toont het redeneerblok een korte, bijgewerkte samenvatting van waar het model aan werkt.

Koppen, fasesamenvattingen en redeneringslabels brengen elk extra modelaanroepen met zich mee, die net als ander gebruik worden geregistreerd. Beheerders configureren ze in [agentactiviteitsgroepen](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) en [live redeneringslabels](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Sturing en wachtrijberichten [#steering-and-queued-messages]

Terwijl een agent antwoord geeft, kun je nog steeds berichten sturen:

- **Steer** voegt het bericht in de huidige run toe op het eerstvolgende veilige moment, zodat de agent kan bijsturen voordat deze klaar is.
- **Onderbreken** annuleert de lopende toolaanroepen en redenering, behoudt wat al is afgerond en gaat verder met je bericht. Effecten die al buiten LibreChat zijn opgetreden, kunnen niet ongedaan worden gemaakt. Sommige runs, bijvoorbeeld runs die gebruikmaken van de ingebouwde zoekfunctie van een provider, kunnen niet worden onderbroken; in dat geval wacht het bericht als een steer.
- **Queue** bewaart het bericht en verstuurt het als een normale beurt zodra het antwoord is voltooid.

**Tijdens het genereren** bepaalt **Enter** onder **Instellingen > Chat** de standaardactie, en het menu van de verzendknop overschrijft die per bericht; `Alt + Enter` onderbreekt. Berichten in de wachtrij worden boven de invoerbalk weergegeven, waar je ze kunt bewerken, verwijderen, opnieuw ordenen, **Nu verzenden** of **Nu onderbreken** kunt kiezen. Bestanden en geciteerde fragmenten worden met het bericht meegestuurd; vaardigheden die je met `$` hebt gekozen, wachten op de volgende volledige beurt. Berichten in de wachtrij in een opgeslagen agentchat worden op de server opgeslagen en blijven bewaard als je de browser sluit.

Een chat kan maximaal 100 berichten in de wachtrij bevatten (elk met 16.000 tekens en 10 bestanden), en een run accepteert maximaal 10 openstaande steers. Zie [Composer](/docs/features/composer) voor de bevestigingen en bedieningselementen in detail.

## Bestanden in een chat [#files-in-a-chat]

Wanneer je met een agent chat, biedt het bijvoegmenu de volgende opties:

- **Afbeelding uploaden**: wordt naar het model verzonden voor visuele analyse.
- **Upload als tekst**: de volledige tekst wordt alleen in dit gesprek opgenomen. Zie [Upload als tekst](/docs/features/upload_as_text).
- **Uploaden voor Bestandszoeken**: geïndexeerd voor ophalen, net als de eigen File Search-bestanden van de agent, maar beperkt tot deze chat.
- **Uploaden naar Code-omgeving**: gekopieerd naar de sandbox voor Code uitvoeren. Het beste voor CSV, Excel en JSON.

Opties worden alleen weergegeven wanneer de bijbehorende functionaliteit is ingeschakeld.

## Delen en rechten [#sharing-and-permissions]

Agents zijn privé voor hun maker totdat ze gedeeld worden. Klik op **Share** in de voettekst van de builder om gebruikers, groepen of rollen toegang te geven, elk met een van drie rollen:

| Rol | Wat ze kunnen doen |
| --- | --- |
| Viewer | Chatten met de agent. Kan de agent niet openen in de builder of de instructies, tools of bestanden zien. |
| Editor | Alles wat een viewer kan, plus de instructies, het model, de tools en de bestanden wijzigen. |
| Owner | Alles wat een editor kan, plus de agent verwijderen en wijzigen met wie deze wordt gedeeld. |

**Delen met iedereen** maakt de agent beschikbaar voor elke gebruiker op de instantie; hiervoor is de machtiging voor openbaar delen nodig. De auteur en beheerders behouden altijd volledige controle.

Een kijker kan de instructies of bestanden in de builder niet zien, maar het model kan ze wel herhalen in een gesprek als erom gevraagd wordt. Plaats daarom niets in een agent dat de kijkers nooit zouden mogen zien.

Apart daarvan bepaalt de wereldknop (**Remote Access**) wie de agent kan aanroepen via de [Agents API](/docs/features/agents_api).

Agentkaarten tonen het supportcontact dat in de builder is ingesteld. Zonder contact kunnen ze de naam van de eigenaar tonen, maar nooit het e-mailadres van de eigenaar, tenzij dat als contact is ingevoerd.

Zie [Toegangscontrole](/docs/features/access_control) voor hoe gebruikers, groepen en rollen samenwerken.

### Beheerdersbediening [#administrator-controls]

Of een rol agents mag gebruiken, aanmaken, delen of publiekelijk delen, wordt per rol ingesteld in het [Admin Panel](/docs/features/admin_panel). Beheerders krijgen daarnaast onderaan de Agent Builder een knop **Admin Settings** met dezelfde schakelaars, per rol. Op een single-tenant instance is het eerste account dat wordt geregistreerd een beheerder; om meer beheerders toe te voegen, zie [Promote another admin](/docs/configuration/access_control#promote-another-admin).

## Agent Marketplace [#agent-marketplace]

**Agent Marketplace** in de zijbalk toont de agents die voor jou beschikbaar zijn, als jouw rol deze mag gebruiken. Zoek op naam of beschrijving, filter op categorie (**Top Picks**, **All**, of een specifieke categorie) en wijzig de volgorde met **Sort by**: **Newest first**, **Oldest first**, **Popular** of **By creator name**. **My agents** toont alleen jouw eigen agents. De zoekopdracht, sortering en filter worden in de URL bewaard, zodat je een weergave kunt bookmarken of delen.

Klik op een kaart voor details en de acties **Pin** of **Unpin**, **Copy Link** (een link die een nieuwe chat met de agent opent), en **Start Chat**. Als u hier op een van de gespreksstarters van de agent klikt, wordt een nieuwe chat geopend met de prompt in het berichtvak, niet verzonden, zodat u deze eerst kunt bewerken.

## Agents API [#agents-api]

Agents kunnen ook worden aangeroepen vanuit scripts en andere apps via een OpenAI-compatibele API, worden beheerd door vertrouwde services en worden getriggerd door gebeurtenissen uit andere systemen. Zie [Agents API](/docs/features/agents_api). [Scheduled Chats](/docs/features/scheduled_chats) starten agent-runs op basis van een timer, en met [Agent Plugins](/docs/features/agent_plugins) kan een beheerder skills en MCP-servers als één pakket aan agents leveren.

## Setup [#setup]

Agents staan standaard aan. Beheerders kiezen welke mogelijkheden worden aangeboden, de stapslimieten en de toegestane providers in de [agents endpoint-configuratie](/docs/configuration/librechat_yaml/object_structure/agents), en welke domeinen Actions mogen bereiken in de [Actions-configuratie](/docs/configuration/librechat_yaml/object_structure/actions). Instanties die zijn bijgewerkt vanaf een versie vóór v0.8.0-rc3 hebben de [permissiemigratie](/docs/configuration/access_control#migrating-from-pre-acl-versions) nodig.
