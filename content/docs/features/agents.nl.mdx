# Agents: Bouw aangepaste AI-assistenten [#agents-build-custom-ai-assistants]

De AI Agents-functie van LibreChat biedt een flexibel framework voor het creëren van aangepaste AI-assistenten die worden aangedreven door verschillende modelproviders.

Deze functie is vergelijkbaar met OpenAI's Assistants API en ChatGPT's GPTs, maar met bredere modelondersteuning en een no-code implementatie, waardoor je geavanceerde assistenten met gespecialiseerde mogelijkheden kunt bouwen.

## Aan de slag [#getting-started]

Om een nieuwe agent aan te maken, selecteer je "Agents" in het endpoint-menu en open je het Agent Builder-paneel dat zich in het zijpaneel (Side Panel) bevindt.

![Agents - Endpoints Menu](/images/agents/endpoints_menu.png)

Het aanmaakformulier bevat:

- **Avatar**: Upload een aangepaste avatar om je agent te personaliseren
- **Naam**: Kies een onderscheidende naam voor je agent
- **Beschrijving**: Optionele details over het doel van je agent
- **Instructies**: Systeeminstructies die het gedrag van je agent definiëren
- **Model**: Selecteer uit beschikbare providers en modellen
- **Conversation Starters**: Maximaal vier voorgestelde prompts die worden getoond wanneer een gebruiker een nieuwe chat met de agent start

De **Tools** en **Skills** bedieningselementen openen doorzoekbare bibliotheken voor ingebouwde functionaliteiten, tools, MCP servers, Actions en Skills. Selecteer een item om het te configureren en sla vervolgens de agent op.

**Bestaande agents kunnen worden geselecteerd via het bovenste dropdown-menu in het zijpaneel.**

- **Ook door te vermelden met "@" in de chat-invoer.**

![Agents - Mention](/images/agents/mention.png)

### Tool Library [#tool-library]

De Agent Builder houdt ingeschakelde items in afzonderlijke **Tools**- en **Skills**-secties. Open **Add tools** om de volledige catalogus te doorzoeken of te filteren op **Official**, **Tools**, **MCP** of **Actions**. **Made by you** verzamelt MCP-servers en Actions die je hebt gemaakt, terwijl **Favorites** items met een ster beschikbaar houdt voor alle agents. Elke gebruiker kan maximaal 100 favorieten in de tool-bibliotheek opslaan.

Selecteer een item om het te configureren zonder de builder te verlaten. Het **Create new** menu verschijnt alleen wanneer de gebruiker toestemming heeft om MCP servers of Actions aan te maken. Het verwijderen van een op bestanden gebaseerde functionaliteit zoals File Search, File Context of Code Interpreter opent de bestandsbeheerder wanneer er nog bijgevoegde bestanden moeten worden beoordeeld. Een op bestanden gebaseerde functionaliteit blijft geselecteerd en behouden bij het opslaan zolang deze nog bestanden bezit; verwijder of wijs die bestanden opnieuw toe voordat u de functionaliteit zelf verwijdert.

Skills gebruiken hun eigen kiezer en kunnen individueel worden geselecteerd of worden ingeschakeld als de volledige toegankelijke catalogus. Zie [Skills](/docs/features/skills#agent-scope).

Operators kunnen ook experimentele [Agent Plugins](/docs/features/agent_plugins) gebruiken om deployment Skills en MCP servers te bundelen in pakketten die bij het opstarten worden geladen.

### Modelconfiguratie [#model-configuration]

De interface voor modelparameters maakt het verfijnen van de reacties van je agent mogelijk:

- Temperatuur (0-1 schaal voor creativiteit van het antwoord)
- Maximale context-tokens
- Maximaal aantal output tokens
- Afbeeldingsdetail (`low`, `auto`, of `high`) voor native vision-afbeeldingsinvoer
- Aanvullende provider-specifieke instellingen

Agent-instructies kunnen gebruikmaken van `{{current_date}}`, `{{current_datetime}}` en `{{iso_datetime}}`. LibreChat lost deze op vanaf het door de server vastgelegde begin van de logische beurt en houdt die tijdstempel stabiel gedurende provider-loops, Subagent-initialisatie en hervatting door de mens (human-in-the-loop). De eerste twee gebruiken de tijdzone van het verzoek; `{{iso_datetime}}` blijft UTC.

Gedetecteerde 'model-not-found'- en 'provider rate-limit'-fouten tonen gelokaliseerde begeleiding. Andere providerfouten behouden hun nuttige providertekst, maar laten LangChain-probleemoplossings-URL's weg voordat het bericht wordt opgeslagen. Wanneer [model-bound content protection](/docs/configuration/librechat_yaml/object_structure/message_filter#source-aware-filters) is ingeschakeld, krijgt de generieke beschermde foutmelding nog steeds voorrang.

### Versiegeschiedenis [#version-history]

Gebruikers met bewerkingsrechten kunnen **Version History** openen vanuit de Agent Builder om opgeslagen configuraties in een tijdlijn te bekijken. Elk item toont wanneer het is opgeslagen en geeft een samenvatting van de tools en mogelijkheden. Het herstellen van een eerder item vereist bevestiging en vervangt de huidige agentconfiguratie door die opgeslagen status. Opslaan past altijd de huidige wijzigingen van de Agent toe, zelfs wanneer de resulterende configuratie overeenkomt met het nieuwste geschiedenisitem en LibreChat geen dubbel item toevoegt.

### Gespreksstarters [#conversation-starters]

Gespreksstarters bieden gebruikers een snelle manier om een chat met een agent te beginnen. Elke agent kan er maximaal vier opslaan.

1. In de Agent Builder, zoek het veld **Conversation Starters**.
2. Typ een prompt en druk op **Enter**, of selecteer de **+**-knop. De invoer wordt uitgeschakeld zodra er vier starters zijn toegevoegd.
3. Bewerk een opgeslagen starter direct, of selecteer de **X**-knop om deze te verwijderen.
4. Sla de agent op.

Wanneer een gebruiker een nieuwe chat opent met de agent, verschijnen de starters als knoppen op het lege chatscherm. Door er een te selecteren, wordt deze onmiddellijk als het eerste bericht verzonden. Als de agent starters heeft, krijgen deze voorrang op alle [`conversation_starters`](/docs/configuration/librechat_yaml/object_structure/model_specs#conversation_starters) die zijn gedefinieerd in de gebruikte Model Specs. Starters verschijnen ook in het detailvenster van de [Marketplace](#agent-marketplace) van de agent.

## Agent-mogelijkheden [#agent-capabilities]

> **Let op:** Alle mogelijkheden kunnen worden in- of uitgeschakeld via het `librechat.yaml` configuratiebestand. Zie [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) voor meer informatie.

### Code Interpreter [#code-interpreter]

Wanneer ingeschakeld, stelt de Code Interpreter-functionaliteit je agent in staat om:

- Voer code uit in meerdere talen, waaronder:
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust en Fortran
- Verwerk bestanden veilig via de LibreChat Code Interpreter API
- Voer code uit zonder lokale installatie, configuratie of sandbox-implementatie
- Beheer bestandsuploads en -downloads naadloos
- [Meer informatie over de Code Interpreter API](/docs/features/code_interpreter)
  - **Aangedreven door de open-source [code-interpreter](https://github.com/ClickHouse/code-interpreter) service (self-hosted)**

Wanneer elk vereist Code Interpreter-bestand uit een conversatie niet kan worden hersteld in de huidige sandbox, stopt LibreChat de Agent voordat de model wordt aangeroepen en vraagt de gebruiker om de bestanden opnieuw te koppelen. Dit voorkomt dat de uitvoering doorgaat met verouderde of ontoegankelijke bestandsverwijzingen.

Wanneer gespreksbestanden dezelfde bestandsnaam voor de Code Interpreter delen, wijst LibreChat afzonderlijke sandbox-bestemmingen toe en vertelt het de Agent wat de opgeloste paden zijn. Zie [Seamless File Handling](/docs/features/code_interpreter#seamless-file-handling) voor het gedrag bij botsingen en de resterende beperking voor privébestanden bij meerdere Agents.

#### Stateful Code Sessions [#stateful-code-sessions]

Stateful code sessions stellen een agent in staat om een sandbox-werkruimte te hergebruiken tussen code-uitvoeringen door. Bestanden, geïnstalleerde pakketten en de werkstatus blijven doorgaans behouden, wat nuttig is voor iteratieve analyses en bestandswerkzaamheden in meerdere stappen. In de Agent Builder bepaalt de **Stateful environment**-selector wie die werkruimte deelt:

- **Gebruikerswerkruimte (aanbevolen):** de stateful agents van de ingelogde gebruiker delen één werkruimte
- **Agent + gebruikerswerkruimte:** elke gebruiker krijgt een aparte werkruimte voor elke agent
- **Gesprekswerkruimte:** elke gebruiker krijgt een aparte werkruimte voor elk gesprek

Beheerders kunnen ook benoemde backends configureren onder [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Wanneer aanwezig, kiest de afzonderlijke **Execution environment**-selector de beheerde Code API, de aan een operator gekoppelde VM, of de persoonlijke worker die de werkruimte bezit; **Deployment default** gebruikt de geconfigureerde standaard uitvoerbare omgeving. Het bovenstaande deelbereik blijft onafhankelijk van die backend-keuze.

Wanneer een implementatie self-service workers inschakelt, kunnen gebruikers met de machtiging voor Code Environment-beheer **Settings > Code environments** openen om een uitgaande `@librechat/code` worker op hun eigen VM te koppelen, deze te selecteren in de Agent Builder en deze later weer in te trekken. Persoonlijke omgevingen zijn gebonden aan de eigenaar en gebruiken dezelfde route voor code, shell en Programmatic Tool Calling. Zie [Attached environments and pairing](/docs/features/code_interpreter#attached-environments-and-pairing) voor de experimentele setup en het beveiligingsmodel.

Binnen een gekoppelde werkruimte kunnen Agents mappen weergeven, bestanden lezen, tekst doorzoeken, bestanden aanmaken en Bash uitvoeren via de geselecteerde worker. Een Git-naam en e-mailadres per Agent kunnen commits identificeren die daar zijn gemaakt zonder dat repository-inloggegevens hoeven te worden verstrekt. Implementaties kunnen nieuwe persoonlijke workers beperken met [`statefulCodeSessions.principalWorkers`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions).

Wanneer een gekoppelde worker meerdere workspace roots adverteert, vereist de chat composer één selectie voor elke gekoppelde omgeving die door de Agent of zijn Subagents wordt gebruikt. Het gesprek behoudt die selecties gedurende de beurten en bij het hervatten van goedkeuringen; LibreChat valideert ze tegen de actieve worker en blokkeert het verzenden als een vereiste workspace ontbreekt of niet beschikbaar is. Een worker die precies één workspace adverteert, wordt automatisch geselecteerd voor een nieuw gesprek. Zie [Attached environments and pairing](/docs/features/code_interpreter#attached-environments-and-pairing) voor details en huidige beperkingen.

Nieuwe Agents gebruiken in eerste instantie de **Standaard stateful workspace** van de ingelogde gebruiker via **Instellingen > Gegevensbeheer > Code-uitvoering**. De persoonlijke standaardinstelling is **Gebruikers-workspace** totdat deze wordt gewijzigd. Het bijwerken van deze voorkeur wijzigt geen bestaande Agents en schakelt Stateful Code Sessions niet uit zichzelf in. Beheerders kunnen de beschikbare scopes beperken met [`statefulCodeSessions.allowedEnvironments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions); wanneer een opgeslagen persoonlijke standaardinstelling niet langer is toegestaan, gebruiken nieuwe Agents de eerste toegestane scope.

<Callout type="warning" title="Zeer experimenteel">
  Stateful Code Sessions bevinden zich in een vroege experimentele fase. Hun gedrag, configuratie, persistentie-eigenschappen en onderliggende integratie kunnen aanzienlijk veranderen. Beschouw de huidige implementatie niet als een stabiel productiecontract.
</Callout>

Deze functie is opt-in. Een beheerder moet `stateful_code_sessions` toevoegen aan de [agent capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) en een specifieke stateful Code Interpreter-route configureren via [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) of genaamd [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Code Interpreter moet zijn ingeschakeld op de agent, en **Stateful code sessions** moet zijn ingeschakeld onder de geavanceerde instellingen.

Stateful verzoeken vallen niet terug op het normale stateless Code Interpreter endpoint wanneer de toegewezen URL ontbreekt of incompatibel is. Stateful en stateless sessies delen ook geen live bestanden of geïnstalleerde pakketten. De stateful workspace kan op elk moment worden gereset, ongeacht de scope. Sla in beheerde Code Interpreter-omgevingen belangrijke uitvoer op onder `/mnt/data`; een gekoppelde workspace is een afzonderlijke, door de worker beheerde map. Chat-uploads worden standaard niet naar die gekoppelde map gekopieerd. Vertrouw voor het overige niet op sessiestatus als duurzame opslag.

Wanneer stateful `create_file` of `edit_file` tools bestanden aanmaken tijdens een antwoord, toont het assistentbericht een compacte **Workspace changes** rij. Vouw deze uit om de unieke gewijzigde paden te bekijken en elk bestand te downloaden via de geauthenticeerde bestandsstroom van LibreChat. Dit is een per-bericht overzicht van bestanden die door die tools zijn aangemaakt, geen duurzame momentopname van de volledige workspace; stateless Code Interpreter-outputs blijven gebruikmaken van de reguliere inline bijlageninterface.

Voor gekoppelde omgevingen kan de composer **Vragen voor wijzigingen**, **Bewerkingen accepteren** en **Volledige toegang** blootstellen als een modus voor code-goedkeuring op gespreksniveau. De beschikbaarheid wordt beperkt door het door de beheerder gedefinieerde machtigingsschema van de omgeving; het kiezen van een ruimere modus overschrijft nooit roltoewijzingen, expliciete toolregels, hooks of sandbox-grenzen. Zie [Attached-environment tool permissions](/docs/features/code_interpreter#attached-environment-tool-permissions).

### Bestandszoekopdracht [#file-search]

De File Search-functionaliteit maakt het volgende mogelijk:

- RAG (Retrieval-Augmented Generation) functionaliteit
- Semantisch zoeken in geüploade documenten
- Context-bewuste antwoorden op basis van bestandsinhoud
- Ondersteuning voor bestandbijlagen op zowel agent- als chatthread-niveau

### Bestandscontext [#file-context]

De File Context-functionaliteit stelt je agent in staat om geëxtraheerde tekst uit bestanden op te slaan als onderdeel van zijn systeeminstructies:

- Extraheer tekst met behoud van documentstructuur en opmaak
- Verwerk complexe lay-outs, inclusief tekst met meerdere kolommen en gemengde inhoud
- Verwerk tabellen, vergelijkingen en andere gespecialiseerde inhoud
- Werken met meertalige inhoud
- Tekst wordt opgeslagen in de instructies van de agent in de database
- **Geen OCR-service vereist** - Gebruikt standaard tekstparsing met fallback-methoden
- **Verbeterd door OCR** - Als OCR is geconfigureerd, verbetert de extractiekwaliteit voor afbeeldingen en gescande documenten
- Gebruikt dezelfde verwerkingslogica als "Upload as Text": **OCR > STT > tekstverwerking**
- [Meer informatie over OCR-configuratie](/docs/features/ocr)

**Let op:** Bestandscontext bevat geëxtraheerde tekst in de systeeminstructies van de agent. Gebruik voor tijdelijke documentvragen in individuele gesprekken in plaats daarvan [Upload as Text](/docs/features/upload_as_text) vanuit de chat.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP is een open protocol dat standaardiseert hoe applicaties context bieden aan Large Language Models (LLM's), en fungeert als een universele adapter voor AI-tools en gegevensbronnen.

Voor meer informatie, zie de documentatie over [MCP](/docs/features/mcp).

#### Agents met MCP Tools [#agents-with-mcp-tools]

1. Configureer MCP servers in je `librechat.yaml` bestand
2. Herstart LibreChat om de verbindingen te initialiseren
3. Een agent aanmaken of bewerken
4. Open **Add tools** in de Agent Builder en selecteer **MCP**
5. Selecteer de MCP-server(s) die je wilt toevoegen; elke server verschijnt als een enkel item
6. Sla je wijzigingen aan de agent op

In dit voorbeeld hebben we de **[Spotify MCP server](https://github.com/LibreChat-AI/spotify-mcp)** toegevoegd aan een agent.

![Agents - MCP](/images/agents/mcp_tools_v2.png)

#### MCP Tools beheren [#managing-mcp-tools]

Zodra een MCP server is toegevoegd aan een agent, kun je nauwkeurig afstemmen welke specifieke tools beschikbaar zijn:

- Nadat je een MCP server hebt toegevoegd, vouw je deze uit om alle beschikbare tools te zien
- Schakel individuele tools naar behoefte in of uit
- Bijvoorbeeld, de Spotify MCP server biedt ~20 tools (zoeken, afspeelbediening, afspeellijstbeheer, enz.)
- Deze gedetailleerde controle stelt je in staat om agents te beperken tot alleen de tools die ze nodig hebben

Request-scoped servers die `{{LIBRECHAT_BODY_*}}` gebruiken, kunnen tools niet opsommen totdat een chat-run deze waarden levert. Agent Builder toont daarom één runtime-tools selectie voor de volledige server in plaats van schakelaars per tool; het wissen van die selectie ontkoppelt de server. Na OAuth behoudt LibreChat de autorisatie en wacht tot de eerste in aanmerking komende run om verbinding te maken.

Als een Agent expliciet MCP tools selecteert, maar er geen kunnen worden opgelost wanneer een run start, stopt LibreChat de run met instructies voor verbinding en toegang in plaats van stilzwijgend door te gaan zonder deze tools. Maak opnieuw verbinding of authenticeer de server, verifieer de toegang tot de tool en probeer de run opnieuw.

### Uitgestelde tools [#deferred-tools]

Deferred tools stellen agents in staat om toegang te hebben tot vele MCP tools zonder deze allemaal vooraf in de LLM-context te laden. In plaats daarvan zijn deferred tools tijdens runtime vindbaar via een **Tool Search**-mechanisme.

Dit is vooral nuttig wanneer een agent toegang heeft tot veel MCP servers met tientallen tools—het laden van al deze tools zou een groot deel van het contextvenster in beslag nemen en de kwaliteit van de antwoorden verminderen.

**Hoe het werkt:**

- Tools die als "deferred" zijn gemarkeerd, worden uitgesloten van de initiële LLM-context
- Een `ToolSearch` tool wordt automatisch toegevoegd, waardoor de LLM uitgestelde tools op aanvraag kan ontdekken en laden.
- Zodra de tool is ontdekt, is deze beschikbaar voor de rest van het gesprek

**Configuring deferred tools:**

1. Open de Agent Builder en voeg MCP tools toe
2. Klik op het dropdown-menu bij een MCP tool
3. Schakel "Defer Loading" in — uitgestelde tools tonen een klokicoon

**Let op:** De `deferred_tools` functionaliteit is standaard ingeschakeld. Deze kan worden in- of uitgeschakeld via de [`librechat.yaml` agents configuratie](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).

### Activiteitsgroepen [#activity-groups]

Activiteitsgroepen klappen elk aaneengesloten blok van Agent-redeneringen en tool-aanroepen in onder een gegenereerde kopregel van één regel, waardoor lange runs gemakkelijker te scannen zijn. Beheerders schakelen deze in met `activityLabel` en kunnen een sneller model, een ander geconfigureerd endpoint, een aangepaste prompt en limieten per run gebruiken. Het genereren van de kopregel is een afzonderlijke model-aanroep waarvan de tokens en kosten worden geregistreerd. Zie [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups).

Beheerders kunnen onafhankelijk `activityPhaseLabel` inschakelen om twee of meer logische activiteiten samen te voegen in een samengevouwen bovenliggende samenvatting vóór het definitieve antwoord. Dit geeft lange runs een overzicht op een hoger niveau, terwijl elke onderliggende activiteit behouden blijft. Fase-samenvattingen gebruiken hun eigen model, endpoint, prompt en limiet per run, met een fallback naar de activity-label en run-instellingen.

Zodra een aaneengesloten reeks ten minste twee voltooide gelabelde toolgroepen bevat, vouwt LibreChat deze samen in hetzelfde fasekaart-oppervlak, nog voordat er een optionele fasesamenvatting arriveert. Het nieuwste voltooide onderliggende label fungeert als de tijdelijke koptekst, terwijl live redeneringen en de tool-aanroep die nog in uitvoering is, buiten de vouw blijven. Geladen geschiedenis gebruikt dezelfde groepering, en een latere door de server gegenereerde fasesamenvatting vervangt de tijdelijke koptekst zonder een kaart te sluiten die de lezer heeft geopend.

Wanneer [Smooth Streaming](/docs/features/smooth_streaming) is ingeschakeld, vouwt een nieuw gegenereerde bovenliggende samenvatting de zichtbare activiteiten soepel samen in de ingeklapte groep. Geladen geschiedenis speelt deze overgang niet opnieuw af en LibreChat respecteert de voorkeur voor verminderde beweging van het apparaat.

Korte voortgangstekst blijft binnen de bovenliggende fase. Wanneer de Agent begint aan een substantieel antwoord, sluit LibreChat de fase vóór die tekst, zodat het resultaat voor de gebruiker buiten de ingeklapte samenvatting blijft. Eén run kan meerdere bovenliggende fasen creëren wanneer latere redeneringen of tools een nieuw logisch activiteitenblok starten. Opgeslagen fasegrenzen worden opnieuw gebaseerd wanneer misvormde of weggelaten inhoudsdelen worden gecomprimeerd, zodat de groepering na het herladen uitgelijnd blijft.

Bestanden die binnen een fase worden geproduceerd, blijven zichtbaar in een rij met media onder de ingeklapte kaart in plaats van erin verborgen te worden. Markdown-afbeeldingsverwijzingen die gebruikmaken van een kale bestandsnaam, `/mnt/data/...` of een `sandbox:`-pad, worden omgezet naar overeenkomstige bijlagen in de beurt. Een bestand wordt alleen weggelaten uit de rij met media wanneer een inline-afbeelding buiten de ingeklapte fase succesvol wordt omgezet, waardoor duplicaten worden voorkomen zonder te vertrouwen op defecte verwijzingen.

Generieke Agent- en MCP-toolkaarten maken onderscheid tussen **Voorbereiden** (vóór de SDK-overdracht, wat goedkeuring of ander wachten kan inhouden) en **Aanroepen** (SDK-overdracht tot resultaat). Voltooide kaarten tonen beide intervallen; het aanroepinterval is niet noodzakelijkerwijs de duur van de upstream MCP- of ClickHouse-uitvoering. Eerder opgeslagen berichten en gespecialiseerde Code-, Bash-, bestands- en geheugenkaarten behouden een duidelijk gelabelde **Totale verstreken** run-step duur. Gestopte, geannuleerde, mislukte en voltooide stappen behouden hun afzonderlijke statussen, ook na het opnieuw laden van een gesprek.

Terwijl een tool wordt uitgevoerd, volgen de uitgevouwen detailvensters voor Bash, Code uitvoeren en Bestandscreatie de gestreamde opdrachten, code of preview-inhoud naar beneden. Omhoog scrollen pauzeert dit volg-gedrag, zodat de huidige leespositie behouden blijft.

Bash-uitvoer wordt weergegeven als tekst in terminalstijl. Lange uitvoer wordt ingeklapt tot de laatste 15 regels, waar fouten meestal verschijnen; gebruik **Show more** en **Show less** om deze uit of in te klappen, en de **Copy**-knop om de uitvoer te kopiëren. Een commando dat niets heeft geprint, toont **No output**. Voor commando's die worden uitgevoerd in een [attached workspace](/docs/features/code_interpreter#attached-environments-and-pairing), wordt een mislukt commando gemarkeerd met de reden (**exit code N**, **terminated by** een signaal zoals `SIGKILL`, of **timed out**), en stderr wordt afzonderlijk van stdout gestyled. Een voltooid commando krijgt het label **Ran command**, en een toolgroep die een enkele aanroep bevat, opent direct met de details van die aanroep.

### Live Reasoning Labels [#live-reasoning-labels]

Live reasoning labels vervangen een algemene **Thinking** of **Thoughts** kop door een korte oriëntatie die evolueert naarmate de top-level reasoning streams voldoende lang worden. Het label werkt de bestaande reasoning kop ter plekke bij; het voegt geen berichtonderdelen toe en wijzigt de volgorde ervan niet.

Het nieuwste live redeneerlabel en de responstimer flikkeren terwijl de generatie actief is. Voltooide redeneringen, antwoorden van oudere siblings en labels die zich niet langer aan het live-einde bevinden, blijven statisch.

Beheerders schakelen dit in met `reasoningLabel` en kunnen een apart model, endpoint, prompt, update-drempelwaarden en een limiet voor het aantal aanroepen per run kiezen. Elke revisie is een extra modelaanroep waarvan de tokens en kosten worden geregistreerd. Zie [Live Reasoning Labels](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels) voor standaardinstellingen, routeringsprioriteit en privacyoverwegingen.

### Tool Intent Labels [#tool-intent-labels]

Tool intent labels vervangen algemene live tool-statussen door een korte beschrijving die door het model voor die specifieke aanroep is geschreven. Beheerders moeten de opt-in `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) toevoegen. Native tools gebruiken automatisch labels; in de Agent Builder vouwt u een MCP server uit en schakelt u **Intent label** in voor individuele tools of de volledige server.

Voor Model Specs kan [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) elke in aanmerking komende tool inschakelen of geselecteerde opgeloste tool-ID's selecteren. Intent-velden voegen toe aan het tool-schema dat naar het model wordt verzonden, dus selectieve inschakeling kan de overhead van schema-tokens verminderen.

Intent-labels zijn niet van toepassing op puur programmatische MCP-tools, omdat aanroepen die binnen sandbox-code worden gedaan geen individuele tool-kaarten renderen. Een uitgebreide programmatische uitvoering toont in plaats daarvan een compacte live-trace van de interne aanroepen.

### Programmatische Tool Calling [#programmatic-tool-calling]

Programmatic Tool Calling (PTC) stelt agents in staat om geselecteerde MCP tools uit te voeren vanuit de [Code Interpreter](/docs/features/code_interpreter) sandbox, in plaats van elke tool rechtstreeks vanuit het model aan te roepen. Het model ontvangt een door Code Interpreter ondersteunde orchestratietool, schrijft sandboxed code die gegenereerde toolfuncties aanroept, en kan lussen, voorwaardelijke logica, retries en resultaatverwerking gebruiken voordat er een antwoord wordt geretourneerd.

Dit is nuttig voor workflows met tools in meerdere stappen, zoals het bevragen van verschillende bronnen, het pagineren door resultaten, het vergelijken van outputs of het transformeren van tool-responses voordat de agent ze uitlegt.

**Programmatische tools configureren:**

1. Schakel zowel `programmatic_tools` als `execute_code` in de [`librechat.yaml` agents capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) in.
2. Schakel Code Interpreter in op de agent.
3. Voeg MCP-tools toe, breid een MCP-server uit en schakel **Programmatic** in voor individuele tools of voor de volledige server. Programmatic tools worden weergegeven met een code-icoon.

De Agent Builder houdt Programmatic-schakelaars uitgeschakeld totdat Code Interpreter is geselecteerd. Het verwijderen van Code Interpreter wist onmiddellijk de Programmatic-selecties van de agent. Bij het aanmaken, bijwerken, dupliceren en herstellen van versies verwijdert de server ook programmatic caller-opties wanneer de `execute_code` capability of de Code Interpreter-tool niet beschikbaar is; hierdoor kunnen oudere, inconsistente Agents worden geopend en gecorrigeerd zonder een onbruikbare configuratie te behouden.

**Let op:** `programmatic_tools` is opt-in en is niet opgenomen in de standaard lijst met agent-mogelijkheden. PTC vereist ook een Code Interpreter-implementatie met de Tool Call Server-component. Tijdens runtime kruist LibreChat de huidige projectie van aanroeper-mogelijkheden met zijn vertrouwde tool-register, waardoor gebeurtenisgegevens de beschikbare kaart kunnen beperken, maar geen tool kunnen verlenen. Alleen actieve, geregistreerde programmatic tools kunnen vanuit de sandbox worden aangeroepen; niet-geregistreerde aanroepen worden geweigerd.

Vouw de Code Interpreter-kaart uit tijdens een programmatische uitvoering om een terminal-stijl trace te zien van elke interne tool-aanroep, het voorbeeld van de argumenten, de status, de duur en eventuele fouten. De trace is live voor de huidige browsersessie en wordt niet hersteld na het opnieuw laden van de pagina.

### Background Tool Calls [#background-tool-calls]

Met achtergrond-tool-aanroepen kan een agent een langlopende, geschikte Code Interpreter, MCP, Plugin of Action tool starten en doorgaan met werken. De initiële aanroep keert onmiddellijk terug met een taakreferentie. Voor een opgeslagen Agent worden ondersteunde voltooiingen standaard automatisch geleverd in een vervolgactie; `check_background_task` blijft beschikbaar voor expliciete status, beheer, het verzamelen van artefacten en herstel.

`check_background_task` rapporteert `started_at` en de huidige `elapsed_ms` terwijl het proces-lokale werk wordt uitgevoerd. Na afwikkeling rapporteert het ook `settled_at` en bevriest het `elapsed_ms` op de voltooide duur. Een terminaal resultaat dat is hersteld vanuit duurzame opslag kan `settled_at` bevatten zonder een starttijd of verstreken duur wanneer de oorspronkelijke proces-lokale dispatch-tijdstempel niet beschikbaar is.

Om deze functie te gebruiken, moet een beheerder de opt-in `run_in_background` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) toevoegen. Configureer vervolgens de in aanmerking komende tools in de Agent Builder:

- **Code Interpreter:** Schakel Code Interpreter in op de agent. Code-uitvoering en shell-commando's komen standaard in aanmerking voor achtergrondverwerking; schakel **Background execution** uit in de tool-instellingen om je hiervoor af te melden.
- **MCP:** Open een MCP-server en markeer individuele tools, of de volledige server, als **Background**.
- **Plugin tools:** Open een geschikte tool en schakel **Background execution** in.
- **Actions:** Schakel **Background execution** in voor een Action om elke in aanmerking komende bewerking in die Action te activeren. OAuth Actions tonen deze schakelaar niet. Een bewerking wordt ook uitgesloten wanneer het eigen schema al een `run_in_background` parameter definieert, om een conflict met de dispatch-vlag van LibreChat te voorkomen.

Deze instellingen staan achtergronduitvoering toe, maar dwingen deze niet af. Het model beslist per aanroep of een in aanmerking komende tool op de achtergrond wordt uitgevoerd.

In LibreChat chat verschijnen de stdout en gegenereerde bestanden, wanneer achtergrondcode is voltooid, bij de oorspronkelijke code-aanroep in plaats van bij de latere poll. Gegenereerde bestanden worden ook bewaard voor volgende beurten. Automatische voortzettingen presenteren het voltooide werk in een inklapbare 'wake-up' taakkaart die gekoppeld is aan de oorspronkelijke taak.

Wanneer de server die voortzetting start nadat de voorgaande uitvoering op de voorgrond al is voltooid, wordt het open gesprek gekoppeld aan de nieuwe generatie en wordt de uitvoer van de voltooide taak vernieuwd zonder dat een herlaadbeurt nodig is.

Automatische voltooiings-wakeups zijn ingeschakeld, tenzij een beheerder [`endpoints.agents.backgroundTasks.completionWakeups: false`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) instelt, wat het gedrag terugzet naar alleen pollen. De host kan verschillende in aanmerking komende voltooiingen die alleen uit inhoud bestaan, groeperen in één voortzetting. Taken die een live artifact produceren, vereisen nog steeds polling op het proces dat de run beheert.

Beheerders kunnen ook kiezen voor annulering met eigenaar-scope via [`endpoints.agents.backgroundTasks.ordinaryToolCancellation: true`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks). De taak rapporteert dat annulering is aangevraagd totdat de onderliggende aanroep is afgerond, en de capaciteit blijft gedurende dat interval gereserveerd. Annulering is coöperatief: een tool die het afbreek-signaal negeert, kan nog steeds succesvol worden voltooid. Deze controle is van toepassing op gewone proces-lokale achtergrondtools, inclusief gekoppelde Bash, maar niet op onafhankelijk beheerde losgekoppelde Subagents.

Alleen in aanmerking komende tools stellen de instelling bloot. Gewone achtergronduitvoering is proces-lokaal en overleeft het verlies van het bijbehorende worker-proces niet. Zodra een terminal resultaat dat alleen uit inhoud bestaat is opgeslagen, is automatische aflevering echter duurzaam en kan deze worden voortgezet op een andere replica. Het proces-lokale register begrenst lopende taken en bewaarde resultaat-payloads per gesprek, gebruiker en proces; het verwijdert voltooide taken wanneer dit veilig is en retourneert een resultaat met beperkte capaciteit wanneer lopende verwerking veilige verwijdering verhindert. Als een aanroep annulering negeert, stopt LibreChat met het vernieuwen van de producer-lease na een respijtperiode van één minuut na de afbreking en beëindigt het de automatische voltooiingsaflevering zonder onzeker extern werk onterecht als time-out te markeren. Losgekoppelde subagents (Detached Subagents) gebruiken een apart duurzaam taak- en transcriptiepad met via Redis gerouteerde live-bedieningselementen; zie [Detached Subagent Threads](/docs/features/subagents#detached-subagent-threads).

### Vraag gebruiker en tool-goedkeuring [#ask-user-and-tool-approval]

De **Ask User** tool stelt een agent in staat om een run te pauzeren om ontbrekende informatie op te vragen, keuzes voor te leggen of te bevestigen hoe verder te gaan. Eén aanroep kan tot vier gerelateerde vragen groeperen. LibreChat presenteert één vraag tegelijk met Vorige, Volgende en klikbare voortgangsstappen; antwoorden blijven beschikbaar terwijl er tussen stappen wordt gewisseld, en antwoorden met een enkele selectie gaan automatisch door zonder in te dienen. Verzenden verschijnt bij de laatste stap nadat elke vraag is beantwoord, terwijl Overslaan de hele batch vanaf elke stap afwijst. Elke vraag accepteert een vrij antwoord of de keuzes voor enkelvoudige of meervoudige selectie van de agent. Terwijl het model de aanroep voorbereidt, streamt LibreChat de vragen naar een voortgangskaart; het interactieve formulier vervangt deze wanneer het klaar is. Na één verzending wordt dezelfde run hervat met de volledige antwoordkaart. Voeg **Ask User** toe vanuit de Tools marketplace; beheerders kunnen de standaard `ask_user_question` functionaliteit verwijderen om deze te verbergen.

Het inklappen van een kaart met meerdere vragen brengt de composer terug naar de normale stuur- of wachtrijmodus, terwijl de gepauzeerde kaart in de thread blijft staan. De kaart kan nog steeds worden uitgeklapt, beantwoord, overgeslagen of gestopt. Een pauze met één vraag blijft de gefocuste composer-antwoordmodus gebruiken.

Ingediende antwoorden worden behouden bij de resume actie, dus stoppen terwijl de hervatte run initialiseert, verwijdert geen geaccepteerde antwoorden.

Nadat een vraagrecord is verwerkt, wordt het standaard samengevouwen tot een tool-item van één regel, zodat lange antwoorden het transcript niet domineren. Open het om de vragen en behouden regeleinden in de antwoorden te bekijken. De bestaande voorkeur **Auto-expand tool details** regelt ook deze verwerkte weergave; het live-formulier blijft open zolang er nog invoer vereist is.

Elke vraag accepteert een optionele kop van maximaal 80 tekens, vraagtekst van maximaal 2.000 tekens, optionele ondersteunende context van maximaal 4.000 tekens en maximaal 12 keuzemogelijkheden. Keuzelabels zijn beperkt tot 280 tekens, keuzewaarden tot 500 tekens en elk ingediend antwoord tot 16.000 tekens.

Beheerders kunnen ook vereisen dat er een beoordeling plaatsvindt voordat overeenkomende tool-aanroepen worden uitgevoerd. Afhankelijk van de tool kunnen gebruikers goedkeuren, afwijzen, argumenten bewerken of direct reageren. Gepauzeerde uitvoeringen worden voorzien van een checkpoint, zodat ze na de beslissing kunnen worden hervat, inclusief op een andere replica wanneer de standaard MongoDB-checkpointer wordt gebruikt. Goedkeuring van tools op implementatieniveau is standaard uitgeschakeld, terwijl een Agent die een gekoppelde Code-omgeving gebruikt, het [ask-by-default veiligheidsbeleid](/docs/features/code_interpreter#attached-environment-tool-permissions) ontvangt, tenzij een beheerder dit expliciet uitschakelt. Zie [`toolApproval` en `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval).

Terwijl het beoordelingspaneel van de composer openstaat voor een wachtende goedkeuring, toont de bijbehorende thread-kaart het verzoek als een record in plaats van de beslissingsknoppen te dupliceren. Controleer de aanroepen in het paneel boven het berichtvenster en selecteer **Continue**. Het inklappen van het paneel via de composer-chip herstelt de besturingselementen van de thread-kaart met behoud van uw beslissingen; het opnieuw openen ervan geeft de beoordeling terug aan het paneel. Kaarten voor andere acties behouden hun eigen besturingselementen.

### Skills [#skills]

Skills stellen agents in staat om herbruikbare instructies te laden vanuit `SKILL.md` definities. Ze kunnen handmatig worden geselecteerd vanuit de chat met `$`, automatisch worden ontdekt door het model via de skill catalog, of altijd worden toegepast bij elke beurt. De Agent Builder kan ook standalone runtime authoring inschakelen: een agent kan een Skill aanmaken zonder de bestaande catalogus te ontvangen, of geselecteerde Skills bewerken wanneer de gebruiker de bijbehorende toestemming heeft.

Voor details over het creëren, aanroepen en toegangsbeheer, zie [Skills](/docs/features/skills).

### Memory [#memory]

De **Memory** tool stelt een agent in staat om gestructureerde gebruikersherinneringen op te slaan, bij te werken of te verwijderen wanneer de gebruiker expliciet vraagt om iets te onthouden of te vergeten. Memory moet geconfigureerd zijn voor de implementatie, toegestaan zijn door de rol en personalisatie-instellingen van de gebruiker, en ingeschakeld zijn op de agent.

Standaard gebruikt een agent de gedeelde persoonlijke geheugenpool van de gebruiker. Schakel **Keep memories separate for this agent** in om de agent een privépartitie per gebruiker en per agent te geven. De geïsoleerde agent zal geen bestaande gedeelde herinneringen zien, noch herinneringen die door andere geïsoleerde agents zijn aangemaakt. Gebruikers kunnen het Memory-paneel filteren op persoonlijke of agentspecifieke herinneringen. Voor het lezen, aanmaken of bijwerken van een Agent-partitie is huidige toegang tot die Agent vereist; verwijdering kan nog steeds een partitie opschonen nadat de bijbehorende Agent is verwijderd. Zie [User Memory](/docs/features/memory#agent-memory).

### Artifacts [#artifacts]

De Artifacts-functionaliteit stelt je agent in staat om interactieve inhoud te genereren en weer te geven:

- Maak React-componenten, HTML-code en Mermaid-diagrammen
- Toon inhoud in een speciaal paneel naast de chat, dat kan worden uitgevouwen naar volledig scherm of kan worden geopend in een eigen browservenster
- Configureer artifact-specifieke instructies op agent-niveau
- [Meer informatie over Artifacts](/docs/features/artifacts)

Wanneer ingeschakeld, kies een van de drie instructiemodi:

- **Normal**: Voegt de standaard artifact-instructies toe voor React, HTML, SVG, Markdown en Mermaid.
- **shadcn/ui**: Voegt de standaardinstructies toe, plus richtlijnen voor het bouwen van interfaces met de shadcn/ui componentenbibliotheek.
- **Custom**: Houdt artifact-rendering ingeschakeld, maar injecteert geen ingebouwde artifact-instructies, waardoor de eigen instructies van de agent volledige controle krijgen.

Het configureren van artifacts op agent-niveau is de geprefereerde aanpak, aangezien dit meer gedetailleerde controle mogelijk maakt in vergelijking met de verouderde configuratie voor de gehele app.

Als je **Custom** selecteert, neem dan minimaal het basis artifact-formaat op in je instructies.

Hier is een eenvoudig voorbeeld van de minimale instructies die nodig zijn:

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

### Overdrachten [#handoffs]

Handoffs stellen een primaire agent in staat om een gesprek over te dragen aan een gespecialiseerde agent met de relevante context. Open in **Advanced settings** de sectie orchestration en voeg maximaal 10 handoff-agents toe. Elke geconfigureerde handoff creëert een transfer-tool die het model dynamisch kan kiezen wanneer de expertise van de specialist nodig is.

Voor elke overdracht kun je een beschrijving toevoegen die het model helpt bij het kiezen van de juiste specialist. Je kunt ook passthrough-instructies opgeven die beschrijven welke inhoud de primaire agent voor de specialist moet genereren en optioneel de content-parameter hernoemen vanaf de standaardwaarde, `instructions`. Tool-aanroepen van bereikbare overdracht-agents blijven gestructureerd in latere beurten, zodat providers geldige tool-aanroepgeschiedenis ontvangen in plaats van platte tekst.

### Agent Chain [#agent-chain]

- **Let op:** Deze functie bevindt zich momenteel in bèta en kan aan verandering onderhevig zijn.
  - Het huidige maximum aantal agents dat kan worden gekoppeld is 10, maar dit kan in de toekomst configureerbaar worden.

### Subagents [#subagents]

Subagents stellen een agent in staat om een specifieke taak te delegeren aan een geïsoleerde child run of een opgeslagen Agent team. Elke child krijgt een geïsoleerde context en tool-executie, en stuurt vervolgens een compact resultaat terug naar de parent in plaats van de parent-context te vullen met elke tussenstap. Losgekoppeld child-werk wordt ook bewaard als een navigeerbare thread die alleen-lezen is.

Subagents verschillen van Agent Chain: chain runs coördineren meerdere agents als deelnemers in een graaf, terwijl subagents door een agent worden aangemaakt als een tool call voor gedelegeerde taken binnen een specifiek bereik. LibreChat behoudt de gestructureerde tool-call geschiedenis die nodig is voor bereikbare children en opgeslagen teamleden gedurende latere beurten, terwijl niet-beschikbare tools buiten de actieve run worden gehouden. Zie [Subagents](/docs/features/subagents) voor installatie en limieten.

### Geavanceerde instellingen [#advanced-settings]

Geavanceerde instellingen voor je agent (te vinden in de Geavanceerde weergave van het Agent-formulier) buiten "capabilities" om.

#### Max Agent Steps [#max-agent-steps]

Met deze instelling kun je het aantal stappen beperken dat een agent kan zetten in een "run", wat verwijst naar de agent-loop voordat een definitief antwoord wordt gegeven.

Indien niet geconfigureerd, is de standaardwaarde 25 stappen, maar je kunt dit aanpassen aan je behoeften. Voor beheerders is het mogelijk om zowel een globale standaardwaarde als een globaal maximum in te stellen in het [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit) bestand.

Wanneer een beurt zijn volledige stappenbudget verbruikt, behoudt LibreChat het gedeeltelijke antwoord en de tool-aanroepen in plaats van deze te vervangen door een foutmelding. Het bericht biedt **Keep going**, waarmee een nieuwe beurt met een vers toolbudget wordt gestart, en **Answer now**, waarmee de agent wordt gevraagd te antwoorden op basis van het reeds voltooide werk zonder verdere tools. Het sluiten van de melding heeft alleen invloed op de huidige browserweergave.

Beheerders kunnen ook gestreamde tool-call argumenten en model delta events begrenzen met [Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers).

Een "stap" verwijst naar ofwel een AI API-verzoek of een ronde van toolgebruik (1 of meerdere tools, afhankelijk van hoeveel tool-aanroepen de LLM verstrekt vanuit een enkel verzoek).

Een enkel antwoord zonder tool is 1 stap. Een enkele ronde van toolgebruik bestaat meestal uit 3 stappen:

1. API-verzoek -> 2. Toolgebruik (1 of meerdere tools) -> 3. Follow-up API-verzoek

## Bestandsbeheer [#file-management]

Agents ondersteunen meerdere manieren om met bestanden te werken:

### In de chatinterface [#in-chat-interface]

Wanneer je met een agent chat, heb je vier uploadopties:

1. **Afbeeldingen uploaden**
   - Uploadt afbeeldingen voor native vision model ondersteuning
   - Verstuurt afbeeldingen rechtstreeks naar de modelprovider

2. **Uploaden als tekst** (vereist `context` capability)
   - Extraheert en voegt de volledige documentinhoud toe aan het gesprek
   - Gebruikt standaard tekstparsing; verbeterd door OCR indien geconfigureerd
   - Inhoud bestaat alleen in de huidige conversatie
   - Zie [Upload as Text](/docs/features/upload_as_text)

3. **Upload voor File Search** (vereist `file_search` functionaliteit, ingeschakeld)
   - Gebruikt semantisch zoeken (RAG) met vector stores
   - Geeft relevante fragmenten terug via toolgebruik
   - Optimaal voor grote documenten/meerdere bestanden
   - Suboptimaal voor gestructureerde data (CSV, Excel, JSON, enz.)

4. **Upload voor Code Interpreter** (vereist `execute_code` functionaliteit, ingeschakeld)
   - Voegt bestanden toe aan de code interpreter-omgeving
   - Optimaal voor gestructureerde data (CSV, Excel, JSON, enz.)
   - Meer informatie over [Code Interpreter](/docs/features/code_interpreter)

### In Agent Builder [#in-agent-builder]

Bij het configureren van een agent kun je bestanden in verschillende categorieën toevoegen:

1. **Afbeelding uploaden**: Voor visuele inhoud waarnaar de agent kan verwijzen
2. **Bestandszoekopdracht uploaden**: Documenten voor RAG-mogelijkheden
3. **Code Interpreter Upload**: Bestanden voor codeverwerking
4. **Bestandscontext**: Documenten met geëxtraheerde tekst als aanvulling op agent-instructies

**File Context** maakt gebruik van de `context` functionaliteit en werkt precies zoals ["Upload as Text"](/docs/features/upload_as_text) - het gebruikt standaard tekstverwerking en wordt verbeterd door OCR wanneer dit is geconfigureerd. Tekst wordt geëxtraheerd op het moment van uploaden en opgeslagen in de instructies van de agent. Dit is ideaal om agents persistente kennis te geven uit documenten, PDF's, codebestanden of afbeeldingen met tekst.

**Verwerkingsprioriteit:** OCR > STT > tekstverwerking (hetzelfde als Uploaden als tekst)

**Let op:** De geëxtraheerde tekst wordt opgenomen als onderdeel van de systeeminstructies van de agent.

## Delen en rechten [#sharing-and-permissions]

Agents maken gebruik van het granulaire [access control](/docs/features/access_control) systeem van LibreChat. Elke agent heeft zijn eigen Access Control List (ACL) en kan worden gedeeld met specifieke **gebruikers**, **groepen**, **rollen**, of **openbaar**, elk op een gekozen permissieniveau.

Vertrouwde services kunnen ook Agents, bijgevoegde bestanden en Skills beheren via de bèta [Agent Management API](/docs/features/agents_api#agent-management-api). Beheerders koppelen elke OIDC machine-client aan één bestaande LibreChat-gebruiker en tenant; elk verzoek erft de huidige rolcapaciteiten en resource-ACL's van die gebruiker in plaats van afzonderlijke administratieve toegang te ontvangen.

### Toegangsrollen [#access-roles]

Bij het delen van een agent krijgt de ontvanger een van de drie volgende rollen toegewezen:

| Rol | Wat de ontvanger kan doen |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | De agent gebruiken in gesprekken; kan de builder niet openen of instructies, tools of bijgevoegde bestanden inzien |
| **Editor** | Bekijken + wijzigen van de instructies, het model, de tools en de bestanden van de agent |
| **Owner**  | Volledige controle: de agent bekijken, bewerken, verwijderen en opnieuw delen |

De oorspronkelijke auteur en beheerders behouden altijd de volledige controle, ongeacht de ACL.

### Een Agent delen [#sharing-an-agent]

1. Open de agent in de Agent Builder
2. Klik op de **Share**-knop in de voettekst (zichtbaar wanneer je de auteur bent, een beheerder bent, of `SHARE`-rechten hebt gekregen voor die specifieke agent)
3. Zoek naar gebruikers, groepen of rollen in de people picker en wijs aan elk een rol toe
4. Schakel optioneel **Public** in om de agent zichtbaar te maken voor iedereen op de instance (vereist de `SHARE_PUBLIC` functie-toestemming)

Agent-kaarten en landingsweergaven tonen het geconfigureerde ondersteuningscontact. Wanneer er geen is ingesteld, kan LibreChat terugvallen op de weergavenaam van de eerste oplosbare eigenaar, maar het e-mailadres van de eigenaar wordt niet getoond, tenzij dit expliciet is geconfigureerd als het ondersteuningscontact.

Gespreksoppervlakken behouden de Agent als de zichtbare identiteit en vallen niet terug op het onderliggende model of het Model Specs-label.

Voor volledige details over principals, permission bits en hoe ACL's zich verhouden tot op rollen gebaseerde functierechten, zie [Access Control](/docs/features/access_control).

## Steering en Queued Messages [#steering-and-queued-messages]

Terwijl een Agent aan het reageren is, kun je op twee manieren een nieuw bericht sturen vanuit de [composer](/docs/features/composer):

- **Steer** voegt het bericht in de huidige run in bij de volgende tool- of agentstap, zodat de agent zijn werk kan aanpassen voordat hij klaar is.
- **Queue** houdt het bericht vast en verstuurt het als een normale vervolgbeurt nadat de huidige reactie is voltooid.

Voor opgeslagen Agent-gesprekken op een huidige server worden gewone wachtrij-opvolgingen opgeslagen in MongoDB. LibreChat behoudt hun FIFO-volgorde en draagt hun tekst, bijlagen, geciteerde fragmenten en handmatig geselecteerde Skills over bij browser-verbindingen die worden verbroken, app-herstarts en replica-handoffs. De verwerking wacht tot het voorgaande antwoord is voltooid voordat de volgende beurt wordt toegelaten. Deze duurzaamheid is automatisch en heeft geen YAML- of omgevingsschakelaar; oudere servers en korte opstartvensters zonder een actieve generatie-epoch behouden de client-side compatibiliteitswachtrij.

Server-toelating wordt geserialiseerd binnen elke wachtrijbaan van het gesprek. Als bewijs van een voorganger of eigenaarschap van gemengde versies dubbelzinnig is, toont LibreChat **Awaiting reconciliation** en blokkeert of faalt de betreffende beurt in de wachtrij in plaats van te gokken en deze buiten de volgorde te starten.

**Steer sooner** vraagt de agent om het bericht op het eerstvolgende veilige punt te verwerken in plaats van te wachten op de volgende tool-stap. Als er nog geen antwoordtekst of tool-activiteit is die veilig kan worden behouden, wacht LibreChat een korte respijtperiode af, verwijdert de stille of enkel op redenering gebaseerde poging, voegt het bericht in en start het model opnieuw met die instructie. Zodra de antwoordtekst kan worden behouden, stopt LibreChat bij een voor de provider veilige grens, behoudt het gedeeltelijke antwoord, voegt het bericht in en hervat hetzelfde assistent-antwoord. Een lopende tool-aanroep wordt niet verwijderd of onderbroken door steering; het bericht wordt toegepast zodra dat werk een veilige grens bereikt.

Gebruik **Stop** om actief redeneren te beëindigen en een annulering van een foreground tool call aan te vragen. Stop stuurt de annulering door naar signaalbewuste foreground tools; losgekoppeld achtergrondwerk behoudt zijn onafhankelijke levenscyclus. Gebruik de speciale composer-besturing, kies deze uit het menu van de verzendknop, of druk op `Command/Ctrl + Shift + .`. De actie valt terug op gewone sturing wanneer de implementatie de actieve provider-stream niet kan onderbreken.

Onder **Settings → Chat** bepaalt **While generating, Enter will** de standaardactie. Het menu bij de verzendknop kan die keuze voor een individueel bericht overschrijven, en **Steer sooner on Enter** zorgt ervoor dat Enter om dat eerdere veilige punt verzoekt wanneer sturen de standaardinstelling is.

Bestanden en [geciteerde fragmenten](/docs/features/message_actions#quote-excerpts) reizen mee met steer-, queue- en interrupt-berichten. Handmatig geselecteerde Skills blijven klaarstaan voor de volgende volledige beurt in plaats van te worden gekoppeld aan een steer tijdens de uitvoering.

In afwachting zijnde steers verschijnen aan het einde van het streamende antwoord, waar ze blijven staan totdat de server ze in de run invoegt. De ontvangst ervan vordert van **Sending** naar **Delivered**, vervolgens naar **Steer sooner requested** wanneer een eerder veilig punt werd aangevraagd, en uiteindelijk naar **Applied** met een dubbel vinkje rechtsonder in het inline bericht. Bevestigde toegepaste ontvangstbewijzen blijven zichtbaar na het herladen en in gedeelde of zoekweergaven; onzekere of mislukte aflevering toont nooit een bevestigend vinkje. Zodra ze zijn erkend, kan het berichtmenu de steer terugvorderen voor bewerking, deze omzetten in een wachtrij-vervolgbericht, of deze annuleren en de tekst en bijlagen terugzetten in de composer. LibreChat voorkomt het overschrijven van een nieuwer concept; als de composer niet langer beschikbaar is, behoudt het het teruggevorderde bericht in de wachtrij. Een mislukte steer blijft beschikbaar om opnieuw te proberen, te bewerken, in de wachtrij te plaatsen of te verwijderen.

In de wachtrij geplaatste vervolgberichten verschijnen in een lijst boven de composer. Elk bericht kan worden bewerkt (**Edit message**), verwijderd (**Remove message**), direct worden verzonden met **Send now**, of worden verplaatst door de hendel te verslepen of de pijltjestoetsen erop te gebruiken. In de wachtrij geplaatste vervolgberichten kunnen ook worden omgezet in een steer terwijl de run nog actief is, of worden geëscaleerd met **Steer sooner**. Actieve steers bieden dezelfde escalatie wanneer ze nog wachten op een tool boundary. Het verwijderen van een door de server ondersteund bericht in de wachtrij annuleert eerst de duurzame bron en herstelt deze vervolgens naar een lege composer wanneer dit mogelijk is. Als het voorgaande antwoord wordt afgebroken of mislukt, markeert LibreChat de betreffende beurt in de wachtrij als mislukt voor beoordeling in plaats van deze stilletjes te verzenden.

Een conversatie kan maximaal 100 actieve wachtrij-beurten (queued turns) bevatten. Elke wachtrij-beurt accepteert maximaal 16.000 tekens en 10 bestanden. Daarnaast accepteert één actieve run maximaal 10 lopende 'steers'; elke 'steer' kan maximaal 10 bestanden bevatten en wordt beperkt door [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls). **Steer sooner** blijft gebruikmaken van het live steering-pad in plaats van een wachtrij-beurt naar de voorzijde van de duurzame FIFO-rij te verplaatsen.

Redis-ondersteunde multi-replica implementaties onderhandelen automatisch over generatieprotocol v2. Volg de [generatieprotocol compatibiliteitsrichtlijnen](/docs/configuration/redis#generation-protocol-compatibility) bij het upgraden vanaf een release ouder dan `v0.8.8-rc1`.

### Opmerkingen [#notes]

- Instructies, modelparameters, bijgevoegde bestanden en tools worden alleen aan de gebruiker getoond als deze over bewerkingsrechten beschikt.
  - Een agent kan alle bijgevoegde gegevens, of het nu instructies of bestanden zijn, lekken via het gesprek. Zorg er daarom voor dat uw instructies hiertegen bestand zijn voordat u Editor/Owner-toegang verleent of de agent openbaar maakt.
- Alleen oorspronkelijke auteurs, beheerders en ontvangers met eigenaarsrechten (Owner permission) kunnen gedeelde agents verwijderen.
- Agents zijn privé voor auteurs, tenzij ze gedeeld worden

## Agent Event Delivery [#agent-event-delivery]

LibreChat bevat een bron-neutrale afleverlaag voor asynchrone Agent-gebeurtenissen. Door de implementatie beheerde adapters kunnen een geverifieerde webhook, wachtrijbericht, MCP-gebeurtenis, kanaalgebeurtenis of interne productgebeurtenis normaliseren naar een nieuwe Agent-run (`fire`), een nieuwe beurt op een bestaande opgeslagen Agent en vertakking (`continue`), of een mutatie van een actieve run (`steer`). Adapters blijven verantwoordelijk voor het authenticeren van hun eigen bron, het opschonen van payloads en het selecteren van vertrouwde doelen voordat ze in de wachtrij worden geplaatst.

De bèta [Agents API event endpoints](/docs/features/agents_api#agent-events) stellen geauthenticeerde `fire`-, `continue`- en `steer`-toegang bloot aan Remote Agents API-sleutels. Externe systemen kunnen een bron-actor koppelen aan een directe onderliggende Agent en die actor voortzetten over events heen zonder een extra feature toggle. LibreChat leidt de gebruiker, tenant en bron-identiteit af van de API-sleutel, dwingt Agent-toegang en inhoudsfilters af, en vereist een idempotency-sleutel. Dit is geen niet-geauthenticeerde webhook-ontvanger voor algemeen gebruik; provider-specifieke adapters moeten nog steeds de native webhook-handtekeningen verifiëren voordat ze deze aanroepen.

De experimentele [Scheduled Chats](/docs/features/scheduled_chats) functie is de eerste ingebouwde producer van LibreChat voor deze laag. Het creëert terugkerende `fire` leveringen voor opgeslagen Agents en is uitgeschakeld totdat een beheerder zich hiervoor aanmeldt. Losgekoppelde Subagents gebruiken automatisch idempotente `continue` levering om een opgeslagen ouder-Agent te wekken nadat een kind-Agent is voltooid; geannuleerde kinderen en efemere ouder-Agents zijn uitgesloten.

MongoDB slaat begrensde versie-enveloppen, idempotentie-sleutels, ordeningsbanen, leases, retry-geschiedenis, duurzame ontvangstbevestigingen en dead letters op. Workers gebruiken at-least-once delivery met fenced claims en begrensde exponentiële backoff; succesvolle ontvangstbevestigingen verlopen na 90 dagen, terwijl dead letters een expliciete vertrouwde requeue vereisen. Fire-leveringen creëren een nieuw gesprek. Continue-leveringen creëren een nieuwe beurt op de exacte gesprekstak en stellen deze uit terwijl die tak wordt uitgevoerd, gepauzeerd of afgerond. Gebonden actoren hebben ook een automatische mailbox: één actor wacht op het resultaat van de afhandeling van zijn huidige beurt voordat het volgende event wordt verzonden, terwijl verschillende actoren parallel kunnen draaien. Steer-leveringen moeten het bestaande gesprek en de generatie identificeren en strikte toelating gebruiken, zodat ambigue retries niet tweemaal dezelfde instructie kunnen injecteren.

Voor gebonden continuaties start een succesvol transport een afzonderlijke duurzame afhandelingslevenscyclus. Een levering vordert van `started` naar `applied`, `completed_no_action`, `failed` of `cancelled`. Bronnen kunnen een exacte tool en een optionele subset van argumenten vereisen met `expectedAction`; LibreChat rapporteert `applied` alleen op basis van door de host waargenomen overeenkomend tool-bewijs, nooit op basis van door het model geschreven proza. Compatibele observationele gebeurtenissen kunnen een gebonden `coalesce.key` batch delen, terwijl ze één idempotentie-record en ontvangstbewijs per brongebeurtenis behouden. Checkpoint-continuatie wordt gebruikt wanneer dit compatibel is en valt anders terug op de duurzame berichtgeschiedenis.

Bound Event Actors kunnen pauzeren voor Ask User of tool-goedkeuring en de exacte ondertekende actor-aanroep hervatten via de normale human-in-the-loop interface van LibreChat. De mailbox van de actor blijft geblokkeerd totdat die pauze wordt hervat of afgehandeld, waardoor wordt voorkomen dat een latere gebeurtenis de beslissing inhaalt. Deze actors vereisen de durable MongoDB checkpointer. LibreChat selecteert automatisch checkpoint-voortzetting of durable-history reconstructie op basis van de actor-status en request capability; bestaand protocol-v1 werk blijft op het history-pad totdat dit is afgehandeld.

Detached Actions die door Event Actors worden gestart, worden automatisch ingeschakeld wanneer de ingebouwde generation store ondersteuning hiervoor adverteert. De actor blijft opgeschort totdat terminal evidence de oorspronkelijke aanroep hervat, dus een achtergrondstart alleen voldoet niet aan `expectedAction`. De in-memory store houdt deze levenscyclus coherent zolang het proces actief blijft. Redis voegt duurzaam herstel na een herstart en replica-overdracht toe. Voltooiingswerk dat eigendom is van een Capability wordt geïsoleerd van oudere workers tijdens een mixed-version drain; operators selecteren dit gedrag niet met een feature flag.

De execution host roept normaal gesproken de gebonden listener van het huidige proces aan. Configureer [`endpoints.agents.eventDriven.selfUrl`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven) alleen wanneer dit vertrouwde interne toelatingspad een andere HTTP-origin moet doorkruisen, zoals een TLS front door.

## Migratie vereist (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="Belangrijk: Migratie van agent-rechten vereist">
  Vanaf versie v0.8.0-rc3 gebruikt LibreChat een nieuw op Access Control List (ACL) gebaseerd permissiesysteem voor agents. Als je een upgrade uitvoert vanaf een eerdere versie, moet je de agent-permissiemigratie uitvoeren zodat bestaande agents toegankelijk blijven.
</Callout>

### Wat de migratie doet [#what-the-migration-does]

De migratie van agent-rechten zet uw agents over van een eenvoudig eigendomsmodel naar een geavanceerd op ACL gebaseerd systeem met meerdere rechtenniveaus:

- **OWNER**: Volledige controle over de agent
- **EDITOR**: Kan de agent bekijken en wijzigen
- **VIEWER**: Alleen-lezen toegang tot de agent

Zonder deze migratie uit te voeren, zullen bestaande agents ontoegankelijk zijn via de nieuwe permission-aware API endpoints.

### De migratie uitvoeren [#running-the-migration]

Kies het juiste commando op basis van je implementatiemethode:

#### 1. Voor de standaard `docker-compose.yml` (als je `docker compose up` gebruikt om de app te starten): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**Preview changes (dry run):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**Migratie uitvoeren:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**Aangepaste batchgrootte (voor grote datasets):**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. Voor de `deploy-compose.yml` [#2-for-the-deploy-composeyml]

Als je de [Ubuntu Docker Guide](/docs/remote/docker_linux) hebt gevolgd:

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**Migratie uitvoeren:**

```bash

```

### Wat er gebeurt tijdens de migratie [#what-happens-during-migration]

- **Private Agents**: Blijven alleen toegankelijk voor hun makers (krijgen OWNER-rechten)
- **Gedeelde Agents**: Als een agent voorheen was gedeeld, krijgt deze de juiste ACL-vermeldingen als een Publieke Agent (gedeeld met alle gebruikers)
- **Systeemdetectie**: LibreChat detecteert automatisch niet-gemigreerde agents bij het opstarten en toont een waarschuwing

Je kunt de resulterende agent-rechten aanpassen via de Agent Builder UI.

<Callout type="info" title="Let op">
  Hetzelfde migratieproces is van toepassing op prompts. Als je ook bestaande prompts hebt, voer dan de prompt-rechtenmigratie uit met dezelfde commando's, maar vervang `agent` door `prompt` in de namen van de commando's.
</Callout>

## Wat is de volgende stap? [#whats-next]

LibreChat Agents luiden een nieuw tijdperk in voor de app, waarin toekomstige pipelines kunnen worden gestroomlijnd via Agents voor specifieke taken en workflows binnen uw ervaring in LibreChat.

Toekomstige updates zullen het volgende bevatten:

- Algemene verbeteringen aan de huidige Agent-ervaring
- Multi-agent orchestratie voor complexe workflows
- Mogelijkheid om agents aan te passen voor verschillende functies: titels (het benoemen van chat-threads), geheugenbeheer (gebruikerscontext/geschiedenis) en prompt-verbetering (invoerassistentie/voorspellingen)
- Meer tools, configureerbare toolparameters, dynamische toolcreatie.

Bovendien introduceert de update een nieuw paradigma voor LibreChat, aangezien de onderliggende architectuur zorgt voor een broodnodige vernieuwing van de app, wat zowel de gebruikerservaring als de algehele app-prestaties optimaliseert.

Om één opmerkelijke optimalisatie uit te lichten: een AI-generatie van ongeveer 1000 tokens zal ongeveer 1 MB aan data overdragen bij gebruik van traditionele endpoints (op het moment van schrijven geldt dit voor elke endpoint-optie behalve Agents en AWS Bedrock).

Bij gebruik van een agent zal dezelfde generatie ongeveer 52 kb aan data overdragen, een vermindering van 95% in datatransfer, wat neerkomt op een aanzienlijk lagere belasting voor de server en het apparaat van de gebruiker.

AI Agents in LibreChat bieden een krachtige manier om gespecialiseerde assistenten te creëren zonder programmeerkennis, terwijl de flexibiliteit behouden blijft om met uw voorkeurs-AI-modellen en -providers te werken.
