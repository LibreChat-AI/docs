**RAG (Retrieval-Augmented Generation) API** adalah layanan terpisah yang mengindeks berkas yang Anda unggah ke LibreChat dan mengembalikan bagian-bagian teks yang paling relevan dengan sebuah pertanyaan, sehingga model dapat menjawab berdasarkan dokumen Anda, bukan hanya berdasarkan data pelatihannya.

Ini adalah aplikasi FastAPI Python yang dibangun di atas LangChain, dan menyimpan embedding di PostgreSQL dengan ekstensi pgvector.

**Untuk mengaturnya, lihat [Konfigurasi RAG API](/docs/configuration/rag_api).**

Di LibreChat, RAG menjadi dasar kemampuan **File Search** pada [Agents](/docs/features/agents#file-search) (`file_search`). File yang dilampirkan ke File Search sebuah agent, atau ke sebuah run yang memilih File Search, diindeks oleh RAG API dan diambil kembali sesuai kebutuhan. Endpoint chat lainnya tidak menggunakan pengindeksan maupun pengambilan RAG, namun tetap dapat memanfaatkan RAG API untuk mengekstrak teks, sebagaimana dijelaskan di bawah.

RAG API juga menyediakan rute `/text` yang dapat digunakan LibreChat untuk mengekstrak teks dari unggahan; lihat [Upload as Text](/docs/features/upload_as_text#what-happens-under-the-hood) untuk mengetahui kapan rute ini berlaku.

## Cara kerjanya [#how-it-works]

1. **Pengindeksan.** Ketika sebuah file perlu dapat dicari (saat diunggah ke File Search sebuah agen, atau ketika proses chat pertama kali menggunakan File Search pada lampiran), LibreChat mengirimkan file tersebut ke RAG API. RAG API kemudian memecah teks menjadi potongan-potongan yang saling tumpang tindih (`CHUNK_SIZE` dan `CHUNK_OVERLAP`), mengubah setiap potongan menjadi embedding dengan penyedia yang telah dikonfigurasi, dan menyimpan vektor-vektor tersebut di pgvector.
2. **Retrieval.** Ketika model memanggil File Search, model menulis sebuah kueri pencarian. LibreChat meminta RAG API untuk 5 potongan (chunk) terdekat dari setiap file yang dilampirkan, lalu menyimpan 10 potongan terdekat secara keseluruhan.
3. **Menjawab.** Potongan-potongan tersebut dikembalikan ke model beserta nama file dan skor relevansinya, lalu model menjawab berdasarkan potongan-potongan itu. Ketika [kutipan file](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) diaktifkan, respons dapat mengutip file yang digunakan.

Menghapus file di LibreChat juga menghapus vektornya dari RAG API.

Retrieval hanya menemukan bagian teks yang secara semantik mirip dengan kueri, sehingga paling efektif untuk mencari fakta spesifik dalam dokumen besar. Untuk pertanyaan yang membutuhkan seluruh dokumen sekaligus, seperti meringkasnya, [Upload as Text](/docs/features/upload_as_text) biasanya memberikan hasil yang lebih baik.

## Apa itu RAG? [#what-is-rag]

Retrieval-Augmented Generation memberikan landasan (*grounding*) pada sebuah model bahasa dengan sumber pengetahuan eksternal. Alih-alih hanya mengandalkan apa yang dipelajari model selama pelatihan, aplikasi terlebih dahulu mengambil cuplikan yang relevan dari sumber tersebut dan menambahkannya ke dalam prompt, lalu model menghasilkan jawabannya berdasarkan cuplikan tersebut. Karena pengetahuan berada di luar model, Anda dapat menambahkan atau memperbarui dokumen tanpa perlu melatih ulang apa pun.
