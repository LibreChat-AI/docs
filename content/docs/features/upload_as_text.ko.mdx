# 파일을 텍스트로 업로드 [#upload-files-as-text]

PDF, 코드 파일 또는 스프레드시트를 AI에게 전달하고 단순히 _"이거 읽어줘"_라고 말하고 싶었던 적이 있나요? LibreChat의 통합 업로더는 파일 유형과 선택한 endpoint에 따라 파일을 해당 제공업체로 라우팅하거나 자동으로 텍스트를 추출합니다.

파일을 첨부하면 LibreChat이 파일에서 텍스트를 추출하여 대화창에 전체 내용을 바로 붙여넣습니다. 그러면 AI가 해당 내용을 처음부터 끝까지 읽을 수 있습니다. 플러그인이나 벡터 데이터베이스, 추가적인 서비스 설정이 필요 없습니다. 즉시 바로 사용할 수 있습니다.

<Callout type="info" title="별도의 설정이 필요하지 않습니다">
  Upload as Text는 모든 LibreChat 인스턴스에서 즉시 작동합니다. 이 기능은 내장된 텍스트 파싱을 사용하므로, 시작하기 위해 OCR, RAG 파이프라인 또는 외부 서비스가 필요하지 않습니다.
</Callout>

---

## 사용 방법 [#how-to-use-it]

<Steps>
  <Step>
    ### 팔레트 열기 [#open-the-palette]

    [메시지 작성기](/docs/features/composer#add-files)에서 **+**를 클릭하세요. 파일을 작성기 위로 드래그할 수도 있습니다.
  </Step>
  <Step>
    ### 소스 선택 [#choose-a-source]

    **Attach** 섹션에서 **From Local Computer**를 선택하거나, 구성된 경우 **From SharePoint**를 선택하세요. 기본 업로더는 모델이나 도구 대상을 선택하라는 메시지를 표시하지 않습니다.

    관리자가 [`legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux)를 활성화한 경우, 직접 대상을 선택할 수 있습니다. **More upload options**를 선택한 다음 **Upload as Text**를 선택하세요.
  </Step>
  <Step>
    ### 파일 선택 [#choose-your-file]

    파일을 선택하세요. LibreChat은 파일 형식과 endpoint 기능에 따라 기본 제공자 전달, 텍스트 추출 또는 도구 전용 저장 방식을 선택합니다.
  </Step>
  <Step>
    ### 질문하기 [#ask-your-question]

    평소처럼 프롬프트를 입력하세요. 선택된 File Search 및 Code 도구는 필요할 때만 파일을 전달받습니다.
  </Step>
</Steps>

여러 파일을 선택하면, LibreChat은 중복된 파일과 파일당 크기 제한을 초과하는 파일을 건너뛰고, 건너뛴 파일의 이름을 알림으로 표시한 뒤 유효한 파일들의 업로드를 계속합니다. 파일 개수 및 전체 배치 크기 제한은 여전히 남은 파일들에 적용되며, 남은 배치 파일이 제한을 초과할 경우 해당 배치는 전체가 거부됩니다. 단일 파일에 대한 동작은 변경되지 않습니다.

<Callout type="warn" title="옵션이 보이지 않나요?">
  `legacyFileUploadUX`가 활성화된 상태에서 **추가 업로드 옵션(More upload options)** 아래에 **텍스트로 업로드(Upload as Text)**가 나타나지 않는다면, 관리자가 `context` 기능을 비활성화했을 수 있습니다. 이 기능은 기본적으로 켜져 있지만, 기능 목록이 사용자 정의된 경우 `context`를 명시적으로 포함해야 합니다. 아래의 [구성 섹션](#the-context-capability)을 참조하세요.
</Callout>

## 긴 텍스트를 파일로 붙여넣기 [#paste-long-text-as-a-file]

일반 메시지 작성기에서 LibreChat은 2,500자가 넘는 붙여넣기 내용을 '텍스트로 업로드(Upload as Text)' 첨부 파일로 변환할 수 있습니다. 이를 통해 긴 붙여넣기 내용을 입력창에서 제외하면서도 대화 컨텍스트를 통해 모델에 해당 내용을 제공할 수 있습니다. 첫 번째 첨부 파일의 이름은 `pasted-text.txt`로 지정되며, 추가적인 붙여넣기 텍스트 첨부 파일에는 번호가 매겨진 이름이 지정됩니다.

브라우저 로컬 **긴 텍스트를 파일로 붙여넣기(Paste long text as a file)** 설정은 **설정 > 채팅 > 전송(Settings > Chat > Sending)**에서 기본적으로 활성화되어 있습니다. 짧은 텍스트를 붙여넣거나 에이전트의 **사용자에게 질문(Ask User)** 양식에 응답하는 동안 붙여넣은 텍스트는 인라인으로 유지됩니다. 컨텍스트 업로드를 사용할 수 없는 경우에도 텍스트는 인라인으로 유지됩니다. 첨부 파일 업로드에 실패하면 LibreChat은 최신 초안을 덮어쓰지 않는 범위 내에서 텍스트를 작성기로 복원합니다.

붙여넣은 텍스트 첨부 파일은 다른 '텍스트로 업로드(Upload as Text)' 파일과 동일한 파일 크기, 토큰 및 [`fileTokenLimit`](#token-limits-and-truncation) 규칙을 따릅니다.

## 내부 작동 원리 [#what-happens-under-the-hood]

업로드가 텍스트로 라우팅되면, LibreChat은 원시 바이트를 프롬프트에 그대로 덤프하지 않습니다. 대신 처리 파이프라인을 거쳐 깔끔하고 읽기 쉬운 텍스트를 추출합니다:

1. **MIME type 감지** — LibreChat은 업로드한 파일의 MIME type을 검사하여 파일의 종류(PDF, 이미지, 오디오, 소스 코드 등)를 확인합니다.
2. **메서드 선택** — 파일 유형과 사용 가능한 서비스에 따라 다음 우선순위에 맞춰 최적의 추출 메서드를 선택합니다:

<Tabs items={["우선순위", "결정 예시"]}>
  <Tabs.Tab>
    | 우선순위 | 방식 | 사용 시점 |
    |----------|--------|---------------|
    | 1순위 | **OCR** | 파일이 이미지 또는 스캔된 문서이고, _그리고_ OCR이 구성된 경우 |
    | 2순위 | **STT** (Speech-to-Text) | 파일이 오디오이고, _그리고_ STT가 구성된 경우 |
    | 3순위 | **Text parsing** | 파일이 알려진 텍스트 MIME 유형과 일치하는 경우 |
    | 4순위 | **Fallback** | 위 항목 중 일치하는 것이 없는 경우 — 어쨌든 텍스트 파싱을 시도함 |
  </Tabs.Tab>
  <Tabs.Tab>
    **OCR이 구성된 인스턴스의 `.pdf` 파일:**
    → OCR이 작동합니다. 스캔된 문서나 복잡한 레이아웃에 매우 유용합니다.

    **기본 인스턴스에서의 `.pdf` (OCR 없음):**
    → 텍스트 파싱이 처리합니다. 디지털 방식으로 생성된 PDF에서 잘 작동합니다.

    **`.py` Python 파일:**
    → 텍스트 파싱으로 바로 이동합니다. 소스 코드는 이미 텍스트이므로 변환이 필요하지 않습니다.

    **STT가 구성된 인스턴스의 `.mp3` 파일:**
    → Speech-to-Text가 이를 대화를 위한 텍스트로 변환합니다.

    **OCR이 구성되지 않은 `.png` 스크린샷:**
    → 텍스트 파싱으로 대체됩니다(결과가 제한적임 — 이미지에 대한 OCR 설정을 고려하세요).
  </Tabs.Tab>
</Tabs>

3. **토큰 잘림(Token truncation)** — 추출된 텍스트는 모델의 컨텍스트 윈도우를 초과하지 않도록 `fileTokenLimit`(기본값: 100,000 토큰)에 맞춰 잘립니다.
4. **Prompt injection** — 해당 텍스트는 사용자의 메시지와 함께 대화 컨텍스트에 포함됩니다.

'Upload as Text' 첨부 파일을 미리 보거나 다운로드할 때, LibreChat은 파일 레코드와 함께 저장된 추출된 텍스트를 제공합니다. OCR이나 다른 파서가 저장된 텍스트를 생성했고 스트리밍할 원본 백업 파일이 없는 경우에도 다운로드 시에는 `.txt` 파일 이름이 사용됩니다.

## 지원되는 파일 형식 [#which-files-are-supported]

<Tabs items={["텍스트 및 코드", "문서", "이미지", "오디오"]}>
  <Tabs.Tab>
    이들은 직접 파싱되므로 이미 텍스트 상태이며, 별도의 변환이 필요하지 않습니다.

    - 일반 텍스트(`.txt`), 마크다운(`.md`), CSV, JSON, XML, HTML, CSS
    - 프로그래밍 언어 — Python, JavaScript, TypeScript, Java, C#, PHP, Ruby, Go, Rust, Kotlin, Swift, Scala, Perl, Lua
    - 설정 파일 — YAML, TOML, INI
    - Shell 스크립트, SQL 파일
  </Tabs.Tab>
  <Tabs.Tab>
    텍스트 파싱은 이를 기본적으로 처리합니다. OCR이 구성되어 있으면, 복잡한 레이아웃에서 더 나은 정확도를 위해 OCR이 이를 대신합니다.

    - **PDF** — 디지털 및 스캔본 (스캔된 PDF는 OCR을 사용하면 더 효과적입니다)
    - **Word** — `.docx`, `.doc`
    - **PowerPoint** — `.pptx`, `.potx`, `.ppt`
    - **Excel** — `.xlsx`, `.xls`
    - **EPUB** 도서
  </Tabs.Tab>
  <Tabs.Tab>
    이미지는 유용한 텍스트를 생성하기 위해 **OCR이 필요합니다**. OCR이 없으면 결과가 좋지 않을 것입니다.

    - JPEG, PNG, GIF, WebP
    - HEIC, HEIF (Apple 형식)
    - 스크린샷, 문서 사진, 스캔된 페이지
  </Tabs.Tab>
  <Tabs.Tab>
    오디오 파일은 **STT**가 구성되어 있어야 합니다. 대체 수단은 없으며, 오디오를 "텍스트로 파싱"할 수는 없습니다.

    - MP3, WAV, OGG, FLAC
    - M4A, WebM
    - 음성 녹음, 팟캐스트 클립
  </Tabs.Tab>
</Tabs>

LibreChat은 Linux의 Chrome(`application/x-shellscript`) 및 libmagic(`text/x-shellscript`)에서 보고하는 셸 스크립트 MIME 변형을 엔드포인트 허용 목록을 확인하기 전에 표준 `application/x-sh`로 정규화합니다. 사용자 지정 [`supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) 규칙은 여전히 `application/x-sh`를 허용해야 합니다.

## 통합 업로드 및 도구 프로비저닝 [#unified-uploads-and-tool-provisioning]

기본적으로 하나의 첨부 파일 작업이 이전 대상 선택기를 대체합니다. LibreChat은 파일이 모델에 도달하는 방식을 결정하며, 도구는 필요할 때 지연 로드(lazily) 방식으로 프로비저닝됩니다:

<Cards>
  <Card title="모델 컨텍스트" href="#what-happens-under-the-hood">
    지원되는 파일은 MIME 유형, endpoint 기능 및 배포 구성에 따라 기본 제공업체 전달 또는 추출된 텍스트를 통해 모델에 도달합니다.
  </Card>
  <Card title="파일 검색(RAG)을 위한 업로드" href="/docs/features/rag_api">
    File Search가 선택되면, LibreChat은 실행 시 도구가 필요할 때만 적격한 첨부 파일을 인덱싱합니다.
  </Card>
  <Card title="표준 업로드" href="/docs/features/agents">
    Code가 선택되면, LibreChat은 실행에 필요한 경우에만 적격한 첨부 파일을 Code 환경에서 사용할 수 있도록 합니다.
  </Card>
</Cards>

운영자는 [`fileConfig.legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux)를 사용하여 이전 대상 선택기를 복원하거나, [`defaultLLMDeliveryPath`](/docs/configuration/librechat_yaml/object_structure/file_config#defaultllmdeliverypath)를 통해 자동 라우팅을 제어할 수 있습니다.

**일반적인 라우팅:**

| 상황 | 최적의 옵션 |
|-----------|-------------|
| _"이 5페이지짜리 계약서를 읽고 요약해줘"_ | Native PDF delivery 또는 추출된 텍스트 |
| _"PDF가 50개 있는데, 가격 정보가 언급된 부분을 찾아줘"_ | Lazy File Search provisioning |
| _"이 스크린샷에 뭐가 있지?"_ | Native image delivery |
| _"이 Python 스크립트를 실행해줘"_ | Lazy Code provisioning |
| _"이 코드 파일에서 버그를 검토해줘"_ | 추출된 텍스트 |

## `context` 기능 [#the-context-capability]

내부적으로, '텍스트로 업로드(Upload as Text)'는 **`context` 기능**에 의해 구동됩니다. 이것이 채팅 UI에 해당 기능이 표시될지 여부를 제어합니다.

<Callout type="info">
  `context` 기능은 **기본적으로 활성화**되어 있습니다. 관리자가 기능 목록을 사용자 지정하다가 실수로 제외한 경우에만 이 설정을 수정하면 됩니다.
</Callout>

```yaml title="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - "context"  # This is what enables "Upload as Text"
```

동일한 `context` 기능은 **에이전트 파일 컨텍스트(Agent File Context)**(에이전트 빌더를 통해 파일을 업로드하여 에이전트의 시스템 지침에 텍스트를 임베딩하는 기능)도 지원합니다. 차이점은 텍스트가 최종적으로 도달하는 _위치_입니다:

| | 텍스트로 업로드 | 에이전트 파일 컨텍스트 |
|---|---|---|
| **위치** | 채팅 입력창 (모든 대화) | 에이전트 빌더 패널 |
| **범위** | 현재 대화에만 국한 | 에이전트 지침에 영구적으로 유지 |
| **사용 사례** | 일회성 문서 질문 | 내장된 지식을 갖춘 전문 에이전트 구축 |

## 토큰 제한 및 잘림(Truncation) [#token-limits-and-truncation]

파일이 모델의 컨텍스트 윈도우에 들어갈 수 없을 정도로 너무 길면, LibreChat은 제한 범위 내에 머물도록 추출된 텍스트를 자릅니다. 이는 자동으로 수행되므로 사용자가 신경 쓸 필요는 없지만, 작동 방식을 알아두면 좋습니다.

```yaml title="librechat.yaml"
fileConfig:
  fileTokenLimit: 100000  # Default: 100,000 tokens
```

<Callout type="warn" title="잘림은 콘텐츠 손실을 의미합니다">
  파일이 제한을 초과하면 텍스트의 끝부분이 잘립니다. 답변이 불완전하게 나오는 경우, 이것이 원인일 수 있습니다. `fileTokenLimit`를 늘릴 수 있지만, 값이 클수록 메시지당 더 많은 토큰을 사용하게 되며, 이는 비용을 증가시키고 모델 자체의 컨텍스트 제한에 도달할 수 있다는 점을 유념하세요.
</Callout>

**경험 법칙:**
- 100k 토큰 ≈ 300페이지 분량의 책 (대부분의 사용 사례에 충분함)
- 매우 큰 파일을 다루는 경우, 모든 내용을 컨텍스트에 채워 넣는 대신 관련 섹션만 검색하는 [File Search (RAG)](/docs/features/rag_api) 사용을 고려해 보세요.

## 선택 사항: OCR을 통한 추출 성능 향상 [#optional-boosting-extraction-with-ocr]

텍스트 파싱은 디지털로 생성된 문서(Word에서 저장된 PDF, 코드 파일, 일반 텍스트)에서는 잘 작동합니다. 하지만 **스캔한 문서, 페이지 사진 또는 텍스트가 포함된 이미지**를 업로드하는 경우, 내장 파서로는 좋은 결과를 얻기 어렵습니다.

바로 그 지점에서 OCR이 필요합니다. 설정이 완료되면 LibreChat은 OCR의 이점을 누릴 수 있는 파일 형식에 대해 자동으로 OCR을 사용합니다. 사용자는 별도로 수행해야 할 작업이 없습니다.

<Accordions>
  <Accordion title="관리자에게 OCR 설정을 요청하는 방법">
    [OCR 구성 문서](/docs/features/ocr)를 참조하도록 안내하세요. 요약하자면 다음과 같습니다:

    ```yaml title="librechat.yaml"
    ocr:
      strategy: "mistral_ocr"
      apiKey: "${OCR_API_KEY}"
      baseURL: "https://api.mistral.ai/v1"
      mistralModel: "mistral-ocr-latest"
    ```

    일단 구성이 완료되면, OCR은 이미지와 스캔된 PDF를 자동으로 처리하며 사용자 측에서 별도의 변경이 필요하지 않습니다.
  </Accordion>
  <Accordion title="관리자에게 STT(오디오 파일용) 설정을 요청하는 방법">
    오디오 업로드를 변환(transcribe)하려면 관리자가 Speech-to-Text 서비스를 구성해야 합니다. [STT 구성 참조](/docs/configuration/librechat_yaml/object_structure/file_config#stt)를 확인하세요.
  </Accordion>
</Accordions>

## 파일 처리 구성 참조 [#file-handling-configuration-reference]

이 섹션은 어떤 파일 형식이 어떤 방식으로 처리될지 제어하려는 관리자를 위한 것입니다. 기본 설정으로도 충분히 잘 작동하므로, 동작을 세밀하게 조정하려는 경우에만 이 설정을 변경하면 됩니다.

<Accordions>
  <Accordion title="전체 fileConfig 예시">
    ```yaml title="librechat.yaml"
    fileConfig:
      # Max tokens extracted from a single file before truncation
      fileTokenLimit: 100000

      # Files matching these MIME patterns use OCR (if configured)
      ocr:
        supportedMimeTypes:
          - "^image/(jpeg|gif|png|webp|heic|heif)$"
          - "^application/pdf$"
          - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.presentation|spreadsheetml\\.sheet)$"
          - "^application/vnd\\.ms-(word|powerpoint|excel)$"
          - "^application/epub\\+zip$"

      # Files matching these MIME patterns use text parsing
      text:
        supportedMimeTypes:
          - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"

      # Files matching these MIME patterns use STT (if configured)
      stt:
        supportedMimeTypes:
          - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
    ```

    **우선순위 알림:** OCR > STT > 텍스트 파싱 > 폴백(fallback).

    전체 참조를 보려면 [File Config Object Structure](/docs/configuration/librechat_yaml/object_structure/file_config)를 확인하세요.
  </Accordion>
</Accordions>

## 문제 해결 [#troubleshooting]

<Accordions>
  <Accordion title="텍스트로 업로드 옵션이 나타나지 않음">
    `context` 기능이 구성에서 제거되었을 가능성이 높습니다. 관리자에게 다시 추가해 달라고 요청하세요:

    ```yaml
    endpoints:
      agents:
        capabilities:
          - "context"
    ```
  </Accordion>
  <Accordion title="파일 내용이 잘못되었거나 거의 비어 있습니다">
    확인해야 할 몇 가지 사항:
    - **스캔된 PDF / 이미지** — 텍스트를 올바르게 추출하려면 OCR이 필요합니다. OCR이 없으면 파서가 잘못된 데이터를 반환하거나 아무것도 반환하지 않을 수 있습니다. 관리자에게 [OCR 구성](/docs/features/ocr)을 요청하세요.
    - **오디오 파일** — 이 파일들은 STT가 필요합니다. 오디오에 대한 텍스트 대체 수단은 없습니다.
    - **손상된 파일** — 파일을 로컬에서 열어 손상되지 않았는지 확인해 보세요.
    - **지원되지 않는 형식** — MIME 유형이 구성된 패턴과 일치하지 않는 경우, LibreChat은 텍스트 파싱 폴백(fallback)을 시도하지만, 이는 바이너리 형식에서는 작동하지 않을 수 있습니다.
  </Accordion>
  <Accordion title="지원되지 않는 파일 형식으로 인해 업로드가 거부되었습니다">
    LibreChat은 업로드 오류 시 거부된 MIME 타입을 반환합니다. 활성 endpoint의 [`fileConfig.endpoints.<endpoint>.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) 패턴을 확인하고 허용하려는 표준(canonical) 타입을 추가하세요. 셸 스크립트의 경우 `application/x-sh`를 사용하세요. LibreChat은 일치 여부를 확인하기 전에 일반적인 `application/x-shellscript` 및 `text/x-shellscript` 변형을 정규화합니다.
  </Accordion>
  <Accordion title="AI가 내 파일의 일부를 누락한 것 같습니다">
    파일이 `fileTokenLimit`을 초과했을 가능성이 높습니다. 텍스트가 잘렸습니다.

    **옵션:**
    - `librechat.yaml`의 `fileTokenLimit`을 늘려달라고 관리자에게 요청하세요.
    - 대신 [File Search (RAG)](/docs/features/rag_api)를 사용하세요. 이는 전체 파일을 로드하는 대신 관련 청크를 검색합니다.
    - 파일을 더 작은 부분으로 나누어 각각 업로드하세요.
  </Accordion>
  <Accordion title="이미지가 업로드되지만 AI가 이미지 내의 텍스트를 읽지 못함">
    OCR이 없으면 이미지는 텍스트 파싱을 통해 처리되는데, 이는 이미지 내의 텍스트를 실제로 "볼" 수 없습니다. 이 기능이 작동하려면 OCR을 구성해야 합니다. [OCR for Documents](/docs/features/ocr)를 참조하세요.

    또는 표준 파일 업로드를 사용하여 **vision model**을 사용하세요. 모델 자체가 이미지 내의 텍스트를 읽을 수 있습니다.
  </Accordion>
</Accordions>
