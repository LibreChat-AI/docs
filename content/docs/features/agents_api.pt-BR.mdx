A API de Agentes permite que código externo ao LibreChat converse com seus agentes. Aponte qualquer SDK da OpenAI para sua instância, passe o ID de um agente como o modelo e você terá toda a configuração do agente (instruções, ferramentas, arquivos) por trás de uma API conhecida. Use-a para integrar um agente a um script, a um job de CI ou a outro produto.

Existem três partes:

- **Inferência**: Chat Completions e Open Responses, autenticados com uma chave de API (ou com seus próprios tokens OIDC, caso o administrador tenha configurado isso).
- **Eventos de Agente**: entregue trabalho a um agente a partir de outro sistema, como um webhook, e acompanhe se ele foi concluído. Somente chaves de API.
- **Gerenciamento de Agentes**: crie e edite agentes e skills a partir de um serviço confiável, usando tokens OIDC de máquina.

<Callout type="warning" title="Beta">
  Endpoints, formatos de requisição e respostas ainda podem mudar entre versões.
</Callout>

## Obtenha uma API key [#get-an-api-key]

Abra **Configurações**, acesse **Dados e Privacidade** e localize **Chaves de API de Agentes** em **Chaves de API**. Clique em **Gerenciar** e, em seguida, em **Criar Chave de API**, dê um nome a ela, escolha uma validade (de 7 dias a 1 ano, ou sem expiração) e copie a chave imediatamente: ela é exibida apenas uma vez.

  light="/images/features/agents_api/api-keys-light.png"
  dark="/images/features/agents_api/api-keys-dark.png"
  alt="Chaves de API do Agente em Configurações, Dados e Privacidade, listando duas chaves com sua data de expiração e última utilização"

Uma chave age como você. Qualquer coisa que você possa acessar pela API, quem tiver a chave também poderá acessar, por isso exclua as chaves que você não usa mais. Excluir uma chave interrompe imediatamente as aplicações que a estão usando.

Se você não vir a seção, seu perfil não recebeu acesso à API de Agents.

## Quais agentes você pode chamar [#which-agents-you-can-call]

Você pode chamar agentes que você possui ou que são compartilhados com você. Para o agente de qualquer outra pessoa, o proprietário precisa conceder a você acesso pelo botão **Acesso Remoto** (o ícone de globo) no rodapé do Construtor de Agentes. Isso é separado do compartilhamento normal: poder conversar com um agente no LibreChat não permite que você o chame pela API.

Você precisa do ID do agente, que é exibido em **Configurações avançadas** no construtor, com um botão de copiar. `GET /api/agents/v1/models` lista os agentes que sua chave pode chamar, e `GET /api/agents/v1/models/{model}` retorna um deles.

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions` segue o formato do OpenAI Chat Completions, portanto clientes OpenAI existentes funcionam apenas alterando a URL base:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

A mesma requisição com curl:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Respostas Abertas [#open-responses]

`POST /api/agents/v1/responses` implementa a especificação [Open Responses](https://www.openresponses.org/), que foi criada para cargas de trabalho de agentes: raciocínio, chamadas de ferramentas e eventos em streaming fazem parte do formato, e não são adicionados posteriormente. Esta é a interface na qual o LibreChat está sendo construído daqui para frente, por isso prefira-a em novas integrações.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` retorna uma resposta armazenada, e `GET /api/agents/v1/responses/models` lista os agentes disponíveis aqui.

### Suas próprias ferramentas de função [#your-own-function-tools]

Você pode passar ferramentas `function` padrão em uma requisição Responses. O LibreChat as exibe ao modelo, mas não as executa: quando o modelo escolhe uma delas, a resposta contém um item `function_call`, e você mesmo executa a função. Para continuar, envie uma nova requisição cujo `input` repita esse item `function_call`, seguido de um `function_call_output` com o mesmo `call_id`:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Nada é mantido aberto entre as duas requisições, e apenas `previous_response_id` não é suficiente; é preciso repetir a chamada e a sua saída. Os nomes das ferramentas podem usar letras, números, sublinhados e hífens, devem ser únicos e não podem sobrepor uma das ferramentas próprias do agente. Um turno que chama uma das suas ferramentas não pode, ao mesmo tempo, chamar as ferramentas do agente; o modelo é solicitado a tentar novamente.

### Aprovação de ferramentas pela API [#tool-approval-over-the-api]

Se o seu administrador exigir aprovação para algumas ferramentas, as chamadas de API não podem parar para pedir a confirmação de ninguém. Ferramentas que exigiriam aprovação, ou que forem negadas, são bloqueadas em vez disso. Os administradores devem permitir explicitamente as ferramentas que um cliente não supervisionado deve executar.

## Eventos de Agente [#agent-events]

Agent Events permitem que outro sistema delegue trabalho a um agente e, depois, consulte o que aconteceu. Este recurso está em beta. Os eventos usam sua chave de API de Agentes, que identifica você e a origem; configurações somente com OIDC não podem utilizá-los. Eles também possuem seu próprio limite de taxa, [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Um evento chega em um de três modos:

- `fire` inicia uma nova conversa com o agente.
- `continue` adiciona um turno a um agente filho que você vinculou anteriormente (veja abaixo).
- `steer` adiciona orientações a uma execução que ainda está em andamento, identificada pela conversa e pela geração retornadas por um `fire`.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Toda requisição precisa de uma única `Idempotency-Key` (de 1 a 256 letras, números ou `._~:/+=-`). Reutilize-a ao tentar novamente a mesma entrega; reutilizá-la para conteúdo diferente é um conflito. O LibreChat define a origem do evento a partir da sua chave de API e ignora qualquer origem que você enviar. O payload é armazenado, portanto mantenha segredos fora dele. Use `orderingKey` quando eventos sobre a mesma coisa precisarem ser tratados em ordem.

A resposta é `202 Accepted` com um ID de entrega e um `Location` para consultar com a mesma chave:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Uma entrega pode estar `pending`, `leased`, `succeeded` ou `dead`. Para um `continue` vinculado, `succeeded` significa apenas que o turno foi iniciado. Seu status de `handling` then passa de `started` para um dos seguintes: `applied`, `completed_no_action`, `failed` ou `cancelled`. Se você enviar um `expectedAction` (o nome de uma ferramenta e, opcionalmente, alguns de seus argumentos), `applied` significa que o LibreChat viu essa ferramenta sendo chamada com argumentos correspondentes; o que o modelo diz em texto não conta.

Os eventos de agentes não são um receptor de webhooks público. Se os eventos vierem de um provedor que assina seus webhooks, verifique a assinatura no seu próprio adaptador antes de encaminhá-los.

### Agentes filhos orientados a eventos [#event-driven-child-agents]

Para manter uma conversa contínua com um agente filho ao longo de muitos eventos, vincule-o uma única vez e, em seguida, envie eventos `continue` para esse vínculo:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

The parent must be a normal agent conversation, and the target must be one of that agent's direct subagents (or the agent itself, if self-spawn is allowed). `actorId` is up to 128 characters. A new binding returns `201` and a replay returns `200`, both with the binding `id`. Later turns reference it:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Cada binding processa um evento por vez: o próximo aguarda até que o turno atual tenha um status final de tratamento, enquanto bindings diferentes são executados em paralelo. Um filho vinculado pode pausar para Ask User ou para aprovação de ferramenta; seus eventos posteriores aguardam até que alguém responda no LibreChat. Isso requer o checkpointer durável do MongoDB (o padrão). Na conversa principal, cada filho vinculado aparece como uma linha abaixo da mensagem que possui o binding e abre o painel de atividade do subagente.

Um binding só funciona com a chave de API, o usuário e o tenant que o criaram. A thread filha permanece fora da lista de chats e é somente leitura no aplicativo.

Para eventos que são apenas observações, como "um jogo avançou", atribua a eles o mesmo `coalesce.key` e o LibreChat agrupa até 8 deles (dentro de 750 ms e 512 KiB) em um único turno. Cada evento ainda recebe seu próprio recibo. Não agrupe comandos, aprovações nem nada que tenha um `expectedAction`.

## API de Gerenciamento de Agentes [#agent-management-api]

A API de Gerenciamento de Agentes permite que um serviço confiável crie, altere e exclua agentes e skills sem uma sessão de navegador. Ela está em beta e utiliza autenticação própria: tokens OIDC de máquina emitidos por clientes que o administrador lista em [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi). Cada cliente está vinculado a um usuário e tenant existentes do LibreChat, e toda requisição age em nome desse usuário, com as permissões e o acesso dele. Ela não torna ninguém administrador.

| Método | Rota | Finalidade |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | Criar um agente |
| `GET` | `/api/agents/v1/agents` | Listar agentes acessíveis |
| `GET` | `/api/agents/v1/agents/{id}` | Ler um agente |
| `PATCH` | `/api/agents/v1/agents/{id}` | Atualizar um agente |
| `DELETE` | `/api/agents/v1/agents/{id}` | Excluir um agente |
| `POST` | `/api/agents/v1/agents/{id}/files` | Enviar e anexar um arquivo |
| `GET` | `/api/agents/v1/agents/{id}/files` | Listar arquivos anexados |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | Desanexar um arquivo |
| `GET` | `/api/agents/v1/skills` | Listar habilidades acessíveis |
| `POST` | `/api/agents/v1/skills` | Criar uma habilidade |
| `GET` | `/api/agents/v1/skills/{id}` | Ler uma habilidade |
| `PATCH` | `/api/agents/v1/skills/{id}` | Atualizar uma habilidade |
| `DELETE` | `/api/agents/v1/skills/{id}` | Excluir uma habilidade |
| `GET` | `/api/agents/v1/skills/{id}/files` | Listar os arquivos de uma habilidade |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | Ler um arquivo de habilidade |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | Criar ou substituir um arquivo de habilidade |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | Excluir um arquivo de habilidade |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Os payloads de agentes aceitam os mesmos campos do Agent Builder e rejeitam os desconhecidos; `model` é obrigatório na criação. As listagens aceitam `limit` (de 1 a 100, padrão 20) e um `cursor`; quando `has_more` for verdadeiro, passe o `after` retornado como próximo cursor. Uploads de arquivos são `multipart/form-data` com um único `file` e um `tool_resource`, como `context`, `file_search` ou `execute_code`, sujeitos aos limites usuais de upload.

Skill create takes `name`, `description`, `body`, and optionally `displayTitle`, `frontmatter`, `category`, and `alwaysApply`. Updates must send the skill's current version as `expectedVersion`, so two writers cannot overwrite each other silently.

Os erros usam os códigos `invalid_request`, `not_found`, `permission_denied`, `conflict` e `internal_error`. Um recurso ao qual você não tem acesso pode ser retornado como `not_found`. Credenciais inválidas ou ausentes retornam `401`.

Se o administrador habilitar essa opção, uma descrição OpenAPI das rotas de gerenciamento é disponibilizada em `/api/openapi.json`, com a documentação interativa em `/api/docs`. Ela não abrange inferência nem eventos. Consulte [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Uso e faturamento [#usage-and-billing]

As requisições de API são debitadas do seu saldo de tokens exatamente como os chats no aplicativo. Os totais de uso na resposta incluem as chamadas de subagentes, com uma divisão separada entre `primary` e `subagent`, além dos tokens de cache e de raciocínio sempre que o provedor os informar. Consulte [Uso de Tokens](/docs/configuration/token_usage).

## Configuração [#setup]

A API de Agentes fica desativada para usuários comuns até que um administrador conceda as permissões de Agentes Remotos à sua função, seja no [Painel de Administração](/docs/features/admin_panel) ou com [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents). Os administradores têm essa permissão por padrão. A autenticação por chave de API está ativada por padrão; para aceitar tokens do seu próprio provedor OIDC em vez de chaves ou junto com elas, consulte [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi). A API de Gerenciamento é configurada separadamente em [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi), e as configurações de entrega de eventos ficam em [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven).
