**RAG(检索增强生成)API** 是一项独立的服务,它会对你上传到 LibreChat 的文件建立索引,并返回与问题最相关的段落,使模型能够基于你的文档作答,而不只是依赖其训练数据。

这是一个基于 LangChain 构建的 Python FastAPI 应用,使用安装了 pgvector 扩展的 PostgreSQL 存储嵌入向量。

**要进行设置，请参阅 [RAG API 配置](/docs/configuration/rag_api)。**

在 LibreChat 中,RAG 为[智能体](/docs/features/agents#file-search)的**文件搜索**功能(`file_search`)提供支持。附加到智能体文件搜索中的文件,或附加到选择了文件搜索的运行中的文件,会由 RAG API 进行索引,并按需检索。其他聊天端点不使用 RAG 索引或检索,但它们仍可按下文所述使用 RAG API 提取文本。

RAG API 还提供了一个 `/text` 路由,LibreChat 可借此从上传文件中提取文本;有关其适用场景,请参阅[以文本形式上传](/docs/features/upload_as_text#what-happens-under-the-hood)。

## 工作原理 [#how-it-works]

1. **索引。** 当文件需要可搜索时(在上传到智能体的文件搜索时,或聊天运行首次对附件使用文件搜索时),LibreChat 会将其发送至 RAG API。RAG API 将文本切分为相互重叠的分块(`CHUNK_SIZE` 和 `CHUNK_OVERLAP`),使用已配置的提供商为每个分块生成嵌入向量,并将这些向量存储在 pgvector 中。
2. **检索。** 当模型调用文件搜索时,它会编写一个搜索查询。LibreChat 会向 RAG API 请求每个附加文件中最接近的 5 个文本块,然后保留总体上最接近的 10 个。
3. **回答。** 这些文本块会连同其文件名和相关性分数一起返回给模型,模型基于这些内容进行回答。启用[文件引用](/docs/configuration/librechat_yaml/object_structure/interface#filecitations)后,响应可以引用其所使用的文件。

在 LibreChat 中删除文件时,也会同时从 RAG API 中移除其向量数据。

检索只会找到与查询语义相近的段落,因此它最适合在大型文档中查找特定事实。对于需要整篇文档才能回答的问题,例如对文档进行总结,[以文本形式上传](/docs/features/upload_as_text)通常能获得更好的结果。

## 什么是 RAG？ [#what-is-rag]

检索增强生成（Retrieval-Augmented Generation）让语言模型基于外部知识源进行回答。应用不再仅依赖模型在训练期间学到的内容，而是先从该知识源中检索相关片段并将其加入提示词，然后模型基于这些片段生成答案。由于知识存放在模型之外，你无需重新训练任何模型，即可添加或更新文档。
