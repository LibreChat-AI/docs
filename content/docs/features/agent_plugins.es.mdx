Un Plugin de Agente es una carpeta en el servidor de LibreChat que agrupa [Skills](/docs/features/skills), [servidores MCP](/docs/features/mcp) y hooks de comandos opcionales que pertenecen juntos. Un operador coloca la carpeta en el directorio de plugins y reinicia LibreChat; no hay nada que instalar desde la interfaz. LibreChat sigue el formato de paquete Agent Plugins `1.0.0` abierto, por lo que un mismo paquete puede compartirse con otras herramientas que lo admitan.

Los Plugins de Agentes son experimentales. El formato del paquete y su comportamiento pueden cambiar.

## Lo que ven los usuarios [#what-users-see]

Los usuarios nunca ven un plugin como tal. Lo que ven es su contenido.

- Sus Skills aparecen en la lista de Skills junto a otras skills. Son de solo lectura, siguen los permisos habituales de Skills y pueden activarse o desactivarse con **Available to agent**, como cualquier otra skill.
- Sus servidores MCP aparecen en la Biblioteca de herramientas y pueden añadirse a los agentes como los servidores definidos en `librechat.yaml`.
- Sus hooks se ejecutan en el servidor en puntos concretos de la ejecución de un agente, como antes de una llamada a una herramienta o cuando la ejecución se detiene. Un hook puede bloquear una llamada a una herramienta, añadir contexto al prompt o detener una ejecución, y el usuario solo ve el efecto.

Si el nombre de una skill o de un servidor MCP coincide con uno definido en otro lugar, prevalece la otra definición: una skill del directorio de skills de la implementación independiente tiene prioridad sobre una skill de plugin, y un servidor definido en `librechat.yaml` tiene prioridad sobre un servidor de plugin.

## Qué puede contener un plugin [#what-a-plugin-can-contain]

Una carpeta de plugin contiene un manifiesto `plugin.json` y cualquiera de los siguientes:

- `skills/`, una carpeta por skill, cada una con un `SKILL.md`.
- `mcp.json`, definiciones de servidores MCP. Los servidores locales (`stdio`) se ejecutan desde dentro de la carpeta del plugin y obtienen su propio directorio de datos persistente.
- `ai.librechat/hooks/hooks.json`, hooks de comandos. Estos se ejecutan como procesos en el host de la API y están deshabilitados a menos que el operador los active.

Cada parte se carga por separado, por lo que un `mcp.json` roto no impide que las skills del plugin se carguen. Los problemas se registran en los logs de inicio.

## Configuración [#setup]

Los plugins se cargan desde `./plugin` en la raíz del proyecto de forma predeterminada, y los hooks de comandos están desactivados de forma predeterminada. Consulta [Configuración de plugins de agentes](/docs/configuration/agent_plugins) para conocer la configuración de directorios, la estructura de paquetes, las reglas de validación del manifiesto y de MCP, y el contrato de ejecución de hooks.
