Code Interpreter는 격리된 샌드박스에서 코드를 실행합니다. 에이전트는 추측으로 답할 수밖에 없는 계산을 수행하거나, 업로드한 스프레드시트를 분석하거나, 파일을 변환하거나, 차트와 문서를 만드는 데 이를 사용합니다. 또한 채팅 메시지의 코드 블록은 **Run Code**를 통해 직접 실행할 수도 있습니다.

샌드박스는 별도의 서비스인 [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter)(오픈 소스, Apache 2.0)로, 관리자가 LibreChat과 함께 배포합니다. Python, Node.js(JavaScript 및 TypeScript), Go, C 및 C++, Java, PHP, Rust, Fortran을 지원합니다.

## 에이전트에 코드 실행 기능 부여하기 [#give-an-agent-code-execution]

Agent Builder에서 **Tools** 옆의 **Add**를 선택한 다음 **Run Code**를 추가하세요. 에이전트를 저장합니다. 이후에는 에이전트가 코드를 실행할 시점을 스스로 결정하므로 코드 실행을 명시적으로 요청할 필요는 없습니다. 다만 정확한 답이 필요할 때는 "이것을 확인하려면 코드를 사용해"라고 말하면 도움이 됩니다.

코드가 실행되는 동안 메시지에는 접을 수 있는 행이 표시되며, 처음에는 **Starting sandbox environment**라고 표시됩니다. 이후 **Analyzing**으로 바뀌고, 완료되면 **Finished analyzing**이 표시됩니다. 이 행을 펼치면 에이전트가 작성한 코드와 **Output**을 확인할 수 있습니다.

## 파일 작업하기 [#working-with-files]

파일을 첨부한 다음 **Upload to Code Environment**를 선택하면 해당 대화에서 샌드박스가 그 파일을 사용할 수 있습니다. 에이전트의 Run Code 설정에서 추가한 파일은 그 에이전트와의 모든 대화에서 사용할 수 있습니다. 각 실행 전에 LibreChat은 대화의 파일을 샌드박스로 복원합니다. 실행에 필요한 파일을 하나도 복원할 수 없으면 오래된 사본으로 작업하지 않고 실행을 중단한 뒤 파일을 다시 첨부하라고 요청합니다.

코드가 생성한 파일은 메시지에 행으로 표시됩니다. 행을 클릭하면 [Artifacts](/docs/features/artifacts) 패널에서 열거나 다운로드할 수 있습니다. HTML, Markdown, 일반 텍스트, 소스 코드, CSV, Office 파일(Word, Excel, OpenDocument, PowerPoint 프레젠테이션 및 템플릿)은 인라인 미리보기를 제공합니다. 더 큰 파일은 미리보기를 건너뛰고 다운로드만 가능하며, 기본 제한은 소스 파일 기준 2 MiB입니다. 에이전트가 샌드박스에서 읽은 이미지(PNG, JPEG, GIF, WebP)는 1 MiB까지 인라인으로 표시되며, 그보다 큰 이미지는 에이전트가 계속 처리할 수 있도록 샌드박스에 그대로 남아 있습니다.

## 코드 블록을 직접 실행하기 [#run-a-code-block-yourself]

채팅 메시지의 코드 블록에는, 블록의 언어가 샌드박스에서 실행 가능한 경우(Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust, Fortran) **Copy code** 버튼 옆에 **Run Code** 버튼이 표시됩니다. 이 버튼을 클릭하면 블록 아래에 실행 결과가 나타납니다. 이 기능은 에이전트와의 대화뿐 아니라 모든 대화에서 동작합니다.

## 장시간 실행 코드 [#long-running-code]

관리자가 백그라운드 도구를 활성화했다면, 에이전트의 Run Code 설정에 **Background execution**이 표시되며 기본값은 켜짐입니다. 에이전트는 오래 걸리는 코드를 시작한 뒤에도 계속 대화할 수 있고, 실행이 끝나면 출력과 파일을 가져올 수 있습니다. 기본적으로 결과는 후속 메시지로 자동 전달됩니다. 항상 코드 실행이 끝날 때까지 기다려야 하는 에이전트의 경우에는 이 설정을 끄세요.

메모리, CPU 시간, 업로드 크기, 네트워크 접근은 LibreChat이 아니라 샌드박스 서비스를 운영하는 관리자가 설정합니다. 코드 실행 중 리소스 오류가 발생하면 관리자에게 제한 값이 무엇인지 문의하세요.

## Stateful 코드 세션 [#stateful-code-sessions]

기본적으로 각 실행은 상태가 없습니다(stateless). 즉, 다음 실행까지 변수나 설치된 패키지가 유지된다고 기대하면 안 됩니다. 상태 저장 코드 세션(stateful code sessions)은 관리자가 활성화해야 하는 실험적 기능으로, 에이전트에게 실행 간에 `/mnt/data` 아래에 파일을 보관하는 작업 공간을 제공합니다. 다만 각 실행은 여전히 새로운 프로세스로 시작되며, 작업 공간은 언제든지 초기화될 수 있으므로 저장소가 아닌 임시 작업 영역으로 취급해야 합니다.

에이전트의 Run Code 설정에서 **Stateful code sessions**를 켜고 **Stateful environment**를 선택하세요:

- **사용자 워크스페이스(권장)**: 사용하는 모든 상태 저장형 에이전트가 공유하는 개인용 워크스페이스 하나를 제공합니다.
- **Agent + user 워크스페이스**: 에이전트마다 별도의 워크스페이스를 제공합니다.
- **대화 작업 공간**: 대화마다 새로운 작업 공간이 제공됩니다.

새로운 에이전트는 **설정 > 데이터 및 개인정보 보호 > 코드 실행 > 기본 상태 저장 작업 공간**에서 설정한 범위로 시작합니다. 이 설정을 변경해도 기존 에이전트에는 영향을 주지 않습니다. 에이전트가 상태 저장 작업 공간에서 생성하거나 편집한 파일은 응답의 **작업 공간 변경 사항** 행에 나열되며, 각 파일마다 다운로드 링크가 제공됩니다.

## 자신의 컴퓨터에서 코드 실행하기 [#running-code-on-your-own-machine]

관리자는 코드 환경도 제공할 수 있습니다. 이는 `@librechat/code` 워커를 실행하는 VM 또는 워크스테이션으로, LibreChat에 외부로 연결됩니다. 이 경우 에이전트 빌더에는 **Execution environment** 선택기가 표시되며, **Machines available in new chats**를 통해 에이전트가 여러 머신을 제공할 수 있고, 각 새 채팅에서 **Choose another machine**을 눌러 머신을 선택할 수 있습니다.

만약 코드 환경을 관리할 권한이 있다면, **Settings > Data & Privacy > Code execution > Code environments**에서 직접 추가할 수 있습니다. 환경 이름을 입력한 뒤 **Connect VM**을 선택하고, 화면에 표시되는 일회성 명령어를 본인의 컴퓨터에서 실행하세요. 관리자가 브라우저 설정을 활성화했다면, 설정 명령어 대신 **Approve Machine Setup** 페이지가 열릴 수 있으며, 로그인된 상태에서 요청을 승인하면 됩니다.

연결된 머신에서 에이전트는 선택한 워크스페이스에서 파일을 탐색, 읽기, 검색, 편집하고 셸 명령을 실행할 수 있습니다. 업로드한 채팅 첨부 파일은 에이전트가 시작되기 전에 해당 워크스페이스의 `.librechat/attachments`에 복사됩니다. 이러한 작업은 실제 머신을 변경하므로, 대화 입력창에는 해당 대화에 대한 **Code approval mode**가 표시됩니다.

- **Ask before changes**: 파일 편집 및 명령 실행 전에 확인을 요청합니다.
- **Accept edits**: 명령어 실행 전에는 여전히 확인을 요청하지만, 파일은 확인 없이 편집합니다.
- **전체 액세스**: 일상적인 확인 프롬프트 없이 편집하고 명령을 실행합니다. 머신의 샌드박스 제한은 여전히 적용됩니다.

사용할 수 있는 모드는 관리자의 정책에 따라 달라집니다. 머신을 페어링하면 워커가 LibreChat에 인증되지만, 그 자체로 샌드박스가 되지는 않습니다. 따라서 신뢰할 수 없는 코드를 실행하는 모든 머신과 마찬가지로 워커를 격리해서 운영하세요.

## 코드에서 MCP 도구 호출하기 [#calling-mcp-tools-from-code]

프로그래밍 방식 도구 호출을 사용하면 에이전트가 샌드박스 내부에서 선택된 MCP 도구를 호출할 수 있습니다. 에이전트는 입력을 순회하고, 도구를 호출하고, 결과를 필터링하여 중요한 내용만 반환하는 스크립트를 작성합니다. 이를 통해 도구 호출마다 모델을 거치는 왕복 과정을 줄일 수 있습니다. 프로그래밍 토글은 에이전트에 Run Code가 활성화되기 전까지 비활성화 상태로 유지되며, Run Code를 제거하면 토글이 해제됩니다. 스크립트가 실행되는 동안 해당 행을 펼치면 **Tool calls** 추적 내용을 확인할 수 있습니다. 이 추적 기록은 페이지를 새로 고치면 유지되지 않습니다. 에이전트에 등록된 도구만 이 방식으로 호출할 수 있습니다. 도구를 표시하는 방법은 [프로그래밍 방식 도구 호출](/docs/features/agents#programmatic-tool-calling)을 참조하세요.

## 설정 [#setup]

코드 실행을 사용하려면 관리자가 Code Interpreter 서비스를 배포하고 LibreChat이 이 서비스를 가리키도록 설정해야 합니다. 그전까지는 실행이 실패합니다. **Run Code** 버튼과 에이전트 기능은 역할별로 비활성화할 수도 있습니다. 백그라운드 실행, 상태 유지 세션, 코드 환경은 각각 옵트인 방식으로 제공됩니다. 자세한 내용은 [Code Interpreter 설정](/docs/configuration/tools/code_interpreter)을 참고하세요.
