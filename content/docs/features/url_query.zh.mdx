您可以在聊天 URL 中添加查询参数,在聊天开始前选择端点和模型、加载智能体或模型规范、填充提示词,或更改模型设置。借此可以创建书签、启动器快捷方式(Raycast、Alfred、浏览器关键字),或从其他应用生成直接进入正确配置的链接。

```
https://chat.example.com/c/new?endpoint=anthropic&model=claude-sonnet-4-5&prompt=Summarize%20this%20article
```

参数可用于新对话(`/c/new`)和已有对话(`/c/<conversation-id>`)。LibreChat 读取参数后会将其从地址栏中清除,因此重新加载页面时不会再次应用这些参数。

## 选择端点和模型 [#pick-the-endpoint-and-model]

`endpoint` 和 `model` 组合在一起时最具可预测性。

- `endpoint` 单独使用时会切换到该端点，并使用你在该端点上最后选择的模型，若没有记录，则使用其列表中的第一个模型。
- `model` 单独使用时，可在当前端点内切换模型（前提是该端点支持此功能）。

内置端点值包括 `openAI`、`azureOpenAI`、`google`、`anthropic`、`bedrock`、`agents`、`assistants` 和 `azureAssistants`。对于[自定义端点](/docs/quick_start/custom_endpoints),请使用配置中的名称;匹配不区分大小写,因此 `endpoint=openrouter` 可以匹配名为 `OpenRouter` 的端点。

## 加载代理、助手或模型规格 [#load-an-agent-assistant-or-model-spec]

```
/c/new?agent_id=agent_abc123
/c/new?assistant_id=asst_abc123
/c/new?spec=meeting-notes
```

`agent_id` 和 `assistant_id` 会为您设置端点。`spec` 通过 [模型规格](/docs/configuration/librechat_yaml/object_structure/model_specs) 的 `name` 加载对应规格。同一 URL 中的其他设置会应用在该规格的预设之上。如果您的管理员强制执行模型规格,请在每个链接中都包含 `spec`,并且要注意规格自身的值会覆盖 URL 中的设置。

## 填写或发送提示词 [#fill-in-or-send-the-prompt]

`prompt`(或更简短的 `q`)会将文本放入消息输入框。若两者同时存在,则以 `prompt` 为准。

将 `submit=true` 添加到参数中,即可在聊天准备就绪后立即发送:

```
/c/new?endpoint=openAI&model=gpt-4o&prompt=Explain%20quantum%20computing&submit=true
```

如果无法在几秒钟内应用所请求的设置,提示词会保留在消息输入框中而不会被发送。管理员也可以关闭自动发送功能,此时 `submit=true` 仅会填充提示词,需要您自行点击发送。

值必须进行 URL 编码。在 JavaScript 中,可以使用 `encodeURIComponent()` 完成编码:

```js
const url = `/c/new?prompt=${encodeURIComponent('Write a function: def hello()')}`;
// /c/new?prompt=Write%20a%20function%3A%20def%20hello()
```

## 更改模型设置 [#change-model-settings]

以上任意参数都可以添加到 URL 中。每个参数仅在支持它的端点上生效,并且在应用之前会对取值进行校验;任何无效的值都会被直接忽略,不会报错。

| 端点 | 参数 |
| --- | --- |
| 任意 | `maxContextTokens`、`resendFiles`、`promptPrefix`(自定义指令) |
| OpenAI、Azure OpenAI、自定义 | `temperature`、`top_p`、`presence_penalty`、`frequency_penalty`、`stop`、`max_tokens`、`reasoning_effort`、`reasoning_summary`、`verbosity`、`useResponsesApi`、`disableStreaming`、`imageDetail`(`low`、`auto`、`high`) |
| OpenAI Responses API | `reasoning_mode`(`standard`、`pro`)、`reasoning_context`(`auto`、`current_turn`、`all_turns`) |
| OpenAI、Anthropic、Google | `web_search`(`true`/`false`)、`fileTokenLimit`(文件内容的 token 上限) |
| Anthropic、Google | `temperature`、`topP`、`topK`、`maxOutputTokens`、`thinking`、`thinkingBudget`、`thinkingLevel` |
| Anthropic | `effort`(`low`、`medium`、`high`、`xhigh`、`max`)、`thinkingDisplay`(`auto`、`summarized`、`omitted`,或仅显示工具调用之间进度说明的 `updates`) |
| Anthropic、Bedrock(Anthropic 模型)、OpenRouter | `promptCache`(`true`/`false`)、`promptCacheTtl`(`5m` 或 `1h`) |
| Google | `url_context=true` 可让 Gemini 读取消息中的 URL |
| Bedrock | `region`、`maxTokens`、`temperature`、`topP`、`reasoning_effort` |
| Assistants | `instructions`(在本次运行中替换助手的指令)、`append_current_datetime=true` |

各字段的含义和允许值列在 [模型规格预设字段](/docs/configuration/librechat_yaml/object_structure/model_specs) 中。如果传入的值被提供商拒绝(例如 `max_tokens` 超过了模型的上限),发送时会收到 API 错误;此时开始一个 **New chat** 即可清除该设置。

## 设置颜色模式 [#set-the-color-mode]

如果您的管理员启用此功能,在链接中使用 `theme=light`、`theme=dark` 或 `theme=system` 即可设置您的颜色模式,因此链接到 LibreChat 的应用可以传递其自身的颜色模式。该设置会被保存为您的偏好,直到您在设置中更改为止。

## 设置 [#setup]

查询参数无需任何设置即可使用。管理员可以通过 [`interface.autoSubmitFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#autosubmitfromurl) 阻止 `submit=true` 自动发送,并可以通过 [`interface.colorModeFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#colormodefromurl) 启用 `theme` 参数。
