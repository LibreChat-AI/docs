File search lets you upload documents and ask questions about them without pasting their contents into the chat. LibreChat sends each file to the RAG API, which splits it into chunks and indexes them; when you ask something, the model searches that index and answers from the passages it finds.

Reach for it when a document is too long to read in full every turn, or when you want answers across several files at once.

## Upload a file for search

Click **+** in the [message composer](/docs/features/composer) to open the palette, expand **More upload options**, then choose **Upload for File Search** and pick your files. Searching the palette for it works too. Uploading this way also switches on **File Search** for the chat. Large files can take a moment to index; the upload finishes once indexing is done.

Once the conversation has indexed files, the model gets a `file_search` tool. It decides when to call it: a question about the document triggers a search, small talk does not. The reply shows a "Searching your files" step while it runs, and when citations are enabled the passages it used appear under **Sources** with the file name, so you can open the document and check.

## How search works

When the model calls `file_search`, it writes a search query. LibreChat asks the RAG API for the 5 closest chunks in each attached file and keeps the 10 closest overall. Those chunks go back to the model with their file name and a relevance score, and the model answers from them.

Retrieval finds passages that are close in meaning to the query, so it is good at looking up specific facts in large documents. For questions that need the whole document at once, such as a summary, Upload as Text usually does better.

Deleting a file in LibreChat also removes its vectors from the RAG API.

## Reuse files you already uploaded

Indexed files stay in your account. Open the palette and look under **Your files** to attach one to a new message or conversation without uploading it again.

Files uploaded while an Assistants endpoint was active are stored with OpenAI, not indexed by the RAG API, and cannot be attached to other endpoints.

## File search in agents

For an agent, turn on [**File Search**](/docs/features/agents#file-search) in the Agent Builder and upload files there. They become the agent's knowledge base: everyone who chats with the agent can have it search those files, without uploading anything themselves. The agent has to be saved before you can add files to it.

## File search or upload as text

[**Upload as Text**](/docs/features/upload_as_text) sits in the same menu. It extracts the file's text and puts all of it into the conversation, which works for short documents where the model should read every word. File search only sends the passages that match each query, so it scales to long documents and many files, but the model never sees the parts it did not retrieve.

The RAG API also serves Upload as Text, as the text extractor for file types the built-in parser cannot read. See [how the text is extracted](/docs/features/upload_as_text#how-the-text-is-extracted).

## Setup

File search needs the RAG API service and a vector database. The default Docker setup includes both; an admin sets the embeddings provider and, for other installs, `RAG_API_URL`. See [RAG API configuration](/docs/configuration/rag_api), and the [RAG API repository](https://github.com/LibreChat-AI/rag-api) for the service's own endpoints and variables.
