The **RAG (Retrieval-Augmented Generation) API** is a separate service that indexes the files you upload to LibreChat and returns the passages most relevant to a question, so the model can answer from your documents instead of from its training data alone.

It is a Python FastAPI app built on LangChain, and stores embeddings in PostgreSQL with the pgvector extension.

**To set it up, see [RAG API Configuration](/docs/configuration/rag_api).**

In LibreChat, RAG powers the [Agents](/docs/features/agents#file-search) **File Search** capability (`file_search`). Files attached to an agent's File Search, or to a run that selects File Search, are indexed by the RAG API and retrieved on demand. Other chat endpoints do not use RAG indexing or retrieval, though they can still use the RAG API to extract text, as described below.

The RAG API also exposes a `/text` route that LibreChat can use to extract text from uploads; see [Upload as Text](/docs/features/upload_as_text#what-happens-under-the-hood) for when it applies.

## How it works

1. **Indexing.** When a file needs to be searchable (on upload to an agent's File Search, or when a chat run first uses File Search on an attachment), LibreChat sends it to the RAG API, which splits the text into overlapping chunks (`CHUNK_SIZE` and `CHUNK_OVERLAP`), turns each chunk into an embedding with the configured provider, and stores the vectors in pgvector.
2. **Retrieval.** When the model calls File Search, it writes a search query. LibreChat asks the RAG API for the 5 closest chunks in each attached file, then keeps the 10 closest overall.
3. **Answering.** Those chunks are returned to the model with their file name and a relevance score, and the model answers from them. When [file citations](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) are enabled, the response can cite the files it used.

Deleting a file in LibreChat also removes its vectors from the RAG API.

Retrieval only finds passages that are semantically close to the query, so it works best for looking up specific facts in large documents. For questions that need a whole document at once, such as summarizing it, [Upload as Text](/docs/features/upload_as_text) usually gives better results.

## What is RAG?

Retrieval-Augmented Generation grounds a language model on an external knowledge source. Instead of relying only on what the model learned during training, the application first retrieves relevant snippets from that source and adds them to the prompt, and the model then generates its answer from them. Because the knowledge lives outside the model, you can add or update documents without retraining anything.
