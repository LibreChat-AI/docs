Puoi aggiungere parametri di query a un URL di chat per scegliere l'endpoint e il modello, caricare un agente o una model spec, compilare il prompt oppure modificare le impostazioni del modello prima dell'avvio della chat. È così che puoi creare un segnalibro, una scorciatoia di avvio (Raycast, Alfred, una parola chiave del browser) oppure un link da un'altra app che porta l'utente direttamente nella configurazione giusta.

```
https://chat.example.com/c/new?endpoint=anthropic&model=claude-sonnet-4-5&prompt=Summarize%20this%20article
```

I parametri funzionano sia in una nuova chat (`/c/new`) sia in una chat esistente (`/c/<conversation-id>`). Dopo che LibreChat li ha letti, li rimuove dalla barra degli indirizzi, quindi ricaricare la pagina non li applica di nuovo.

## Scegli l'endpoint e il modello [#pick-the-endpoint-and-model]

`endpoint` e `model` insieme sono la combinazione più prevedibile.

- `endpoint` da solo passa a quell'endpoint e usa il modello che hai scelto per ultimo lì, oppure il primo modello della sua lista.
- `model` da solo cambia il modello all'interno dell'endpoint corrente, se quell'endpoint lo supporta.

I valori degli endpoint integrati sono `openAI`, `azureOpenAI`, `google`, `anthropic`, `bedrock`, `agents`, `assistants` e `azureAssistants`. Per un [endpoint personalizzato](/docs/quick_start/custom_endpoints), usa il nome indicato nella tua configurazione; la corrispondenza non distingue tra maiuscole e minuscole, quindi `endpoint=openrouter` trova un endpoint chiamato `OpenRouter`.

## Caricare un agente, un assistente o una specifica di modello [#load-an-agent-assistant-or-model-spec]

```
/c/new?agent_id=agent_abc123
/c/new?assistant_id=asst_abc123
/c/new?spec=meeting-notes
```

`agent_id` e `assistant_id` impostano l'endpoint per te. `spec` carica una [model spec](/docs/configuration/librechat_yaml/object_structure/model_specs) tramite il suo `name`. Qualsiasi altra impostazione presente nello stesso URL viene applicata sopra il preset della spec. Se il tuo amministratore applica le model spec, includi `spec` in ogni link e aspettati che i valori propri della spec prevalgano su quelli dell'URL.

## Compila o invia il prompt [#fill-in-or-send-the-prompt]

`prompt` (o il più breve `q`) inserisce il testo nella casella dei messaggi. Se sono presenti entrambi, `prompt` ha la precedenza.

Aggiungi `submit=true` per inviarlo non appena la chat è pronta:

```
/c/new?endpoint=openAI&model=gpt-4o&prompt=Explain%20quantum%20computing&submit=true
```

Se le impostazioni richieste non possono essere applicate entro pochi secondi, il prompt viene lasciato nella casella dei messaggi invece di essere inviato. Il tuo amministratore può anche disattivare l'invio automatico; in tal caso `submit=true` si limita a compilare il prompt e sarai tu a premere invio.

I valori devono essere codificati in URL. In JavaScript, `encodeURIComponent()` esegue questa operazione:

```js
const url = `/c/new?prompt=${encodeURIComponent('Write a function: def hello()')}`;
// /c/new?prompt=Write%20a%20function%3A%20def%20hello()
```

## Modificare le impostazioni del modello [#change-model-settings]

Ognuno di questi parametri può essere aggiunto all'URL. Ciascuno ha effetto solo sugli endpoint che lo supportano, e i valori vengono verificati prima di essere applicati; qualsiasi valore non valido viene scartato senza generare un errore.

| Endpoint | Parametri |
| --- | --- |
| Qualsiasi | `maxContextTokens`, `resendFiles`, `promptPrefix` (istruzioni personalizzate) |
| OpenAI, Azure OpenAI, custom | `temperature`, `top_p`, `presence_penalty`, `frequency_penalty`, `stop`, `max_tokens`, `reasoning_effort`, `reasoning_summary`, `verbosity`, `useResponsesApi`, `disableStreaming`, `imageDetail` (`low`, `auto`, `high`) |
| OpenAI Responses API | `reasoning_mode` (`standard`, `pro`), `reasoning_context` (`auto`, `current_turn`, `all_turns`) |
| OpenAI, Anthropic, Google | `web_search` (`true`/`false`), `fileTokenLimit` (limite di token per il contenuto dei file) |
| Anthropic, Google | `temperature`, `topP`, `topK`, `maxOutputTokens`, `thinking`, `thinkingBudget`, `thinkingLevel` |
| Anthropic | `effort` (`low`, `medium`, `high`, `xhigh`, `max`), `thinkingDisplay` (`auto`, `summarized`, `omitted`, oppure `updates` per mostrare solo le note di avanzamento tra una chiamata di strumento e l'altra) |
| Anthropic, Bedrock (modelli Anthropic), OpenRouter | `promptCache` (`true`/`false`), `promptCacheTtl` (`5m` o `1h`) |
| Google | `url_context=true` consente a Gemini di leggere gli URL presenti nel tuo messaggio |
| Bedrock | `region`, `maxTokens`, `temperature`, `topP`, `reasoning_effort` |
| Assistants | `instructions` (sostituisce le istruzioni dell'assistente per questa esecuzione), `append_current_datetime=true` |

Il significato e i valori consentiti di ciascun campo sono elencati in [campi del preset di model spec](/docs/configuration/librechat_yaml/object_structure/model_specs). Passare un valore che il provider rifiuta (un `max_tokens` superiore al limite del modello, ad esempio) genera un errore API all'invio; avvia una **New chat** per cancellarlo.

## Imposta la modalità colore [#set-the-color-mode]

Se l'amministratore lo abilita, `theme=light`, `theme=dark` o `theme=system` in un link impostano la modalità colore, così un'app che rimanda a LibreChat può passare la propria. Viene salvato come preferenza finché non la modifichi nelle impostazioni.

## Setup [#setup]

I parametri di query funzionano senza configurazione. Gli amministratori possono impedire che `submit=true` invii automaticamente il messaggio tramite [`interface.autoSubmitFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#autosubmitfromurl), e abilitare il parametro `theme` con [`interface.colorModeFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#colormodefromurl).
