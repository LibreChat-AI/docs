L'**API RAG (Retrieval-Augmented Generation)** est un service distinct qui indexe les fichiers que vous importez dans LibreChat et renvoie les passages les plus pertinents pour une question, afin que le modèle puisse répondre à partir de vos documents plutôt qu'à partir de ses seules données d'entraînement.

C'est une application FastAPI en Python construite sur LangChain, qui stocke les embeddings dans PostgreSQL avec l'extension pgvector.

**Pour la configurer, consultez [Configuration de l'API RAG](/docs/configuration/rag_api).**

Dans LibreChat, RAG alimente la fonctionnalité **Recherche de fichiers** ([Agents](/docs/features/agents#file-search)) des agents (`file_search`). Les fichiers joints à la Recherche de fichiers d'un agent, ou à une exécution qui sélectionne la Recherche de fichiers, sont indexés par l'API RAG et récupérés à la demande. Les autres points de terminaison de chat n'utilisent pas l'indexation ni la récupération RAG, bien qu'ils puissent toujours utiliser l'API RAG pour extraire du texte, comme décrit ci-dessous.

L'API RAG expose également une route `/text` que LibreChat peut utiliser pour extraire le texte des fichiers téléversés ; consultez [Téléverser comme texte](/docs/features/upload_as_text#what-happens-under-the-hood) pour savoir quand elle s'applique.

## Fonctionnement [#how-it-works]

1. **Indexation.** Lorsqu'un fichier doit être consultable (lors du téléversement dans la recherche de fichiers d'un agent, ou lorsqu'une exécution de conversation utilise pour la première fois la recherche de fichiers sur une pièce jointe), LibreChat l'envoie à l'API RAG, qui découpe le texte en fragments qui se chevauchent (`CHUNK_SIZE` et `CHUNK_OVERLAP`), transforme chaque fragment en un embedding à l'aide du fournisseur configuré, puis stocke les vecteurs dans pgvector.
2. **Récupération.** Lorsque le modèle appelle File Search, il rédige une requête de recherche. LibreChat demande à l'API RAG les 5 fragments les plus proches dans chaque fichier joint, puis conserve les 10 plus proches au total.
3. **Réponse.** Ces fragments sont renvoyés au modèle avec leur nom de fichier et un score de pertinence, et le modèle répond à partir de ceux-ci. Lorsque les [citations de fichiers](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) sont activées, la réponse peut citer les fichiers utilisés.

Supprimer un fichier dans LibreChat supprime également ses vecteurs de l'API RAG.

La recherche ne retrouve que les passages sémantiquement proches de la requête. Elle est donc plus efficace pour rechercher des faits précis dans de grands documents. Pour les questions qui nécessitent un document entier à la fois, comme la synthèse, [Importer comme texte](/docs/features/upload_as_text) donne généralement de meilleurs résultats.

## Qu'est-ce que le RAG ? [#what-is-rag]

La génération augmentée par récupération (RAG, de l'anglais *Retrieval-Augmented Generation*) ancre un modèle de langage sur une source de connaissances externe. Au lieu de se fier uniquement à ce que le modèle a appris pendant l'entraînement, l'application récupère d'abord les extraits pertinents de cette source et les ajoute au prompt ; le modèle génère ensuite sa réponse à partir de ces extraits. Comme les connaissances résident en dehors du modèle, vous pouvez ajouter ou mettre à jour des documents sans rien réentraîner.
