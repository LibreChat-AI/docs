Un agente è una configurazione salvata: un modello, un prompt di sistema e gli strumenti e i file che può utilizzare. Lo crei una volta nell'Agent Builder, quindi lo selezioni ogni volta che avvii una chat. Gli agenti funzionano con qualsiasi provider configurato, non solo con OpenAI.

## Crea un agente [#create-an-agent]

<Steps>
  <Step>
    Apri **Agent Builder** dal pannello laterale e fai clic su **Create New Agent**.
  </Step>
  <Step>
    Assegnagli un nome, una descrizione facoltativa, e scegli un **Model** e una **Category**. Il model e la category sono obbligatori.
  </Step>
  <Step>
    Scrivi le istruzioni. Puoi digitarle direttamente, oppure cambiare l'origine in **Prompt** per collegare un prompt salvato (vedi [Prompt](/docs/features/prompts#use-a-prompt-as-agent-instructions)).
  </Step>
  <Step>
    Aggiungi gli strumenti in **Tools** (vedi sotto), quindi fai clic su **Create**.
  </Step>
</Steps>

Il caricamento dei file per File Search o File Context funziona solo dopo che l'agente è stato creato.

Per chattare con un agente, selezionalo nel selettore dei modelli, aprilo dal [Marketplace degli agenti](#agent-marketplace), oppure digita `@` nella casella di chat e scegliilo dall'elenco. Nel selettore degli agenti del builder, **I miei agenti** restringe l'elenco agli agenti che hai creato.

### Istruzioni da un prompt salvato [#instructions-from-a-saved-prompt]

Con l'origine delle istruzioni impostata su **Prompt**, le istruzioni di un agente possono collegarsi a un prompt salvato anziché a un testo inline. L'agente segue la versione di produzione del prompt oppure una versione fissata (pinned), e il prompt collegato può essere nativo di LibreChat o sincronizzato da Langfuse. Vedi [Usa un prompt come istruzioni dell'agente](/docs/features/prompts#use-a-prompt-as-agent-instructions).

Le istruzioni, inline o collegate, possono utilizzare `{{current_date}}`, `{{current_datetime}}` e `{{iso_datetime}}`. Questi vengono compilati una sola volta all'inizio di ogni turno e restano invariati durante le chiamate agli strumenti, i subagenti e le pause di approvazione. I primi due usano il tuo fuso orario; `{{iso_datetime}}` è in UTC.

### Parametri del modello [#model-parameters]

Il pannello del modello espone gli stessi parametri di una normale chat per quel provider (temperatura, numero massimo di token di output e così via), oltre a **Dettaglio immagine** per l'input visivo. I valori salvati qui si applicano a ogni conversazione con l'agente.

### Avvii di conversazione [#conversation-starters]

Nella sezione **Conversation Starters** puoi aggiungere fino a quattro prompt. Questi appaiono come pulsanti nella schermata vuota della chat quando un utente avvia una nuova conversazione con l'agente, e cliccando su uno di essi viene inviato immediatamente. I conversation starters di un agente sostituiscono quelli eventualmente definiti nella model spec in uso. Compaiono anche nei dettagli dell'agente nel Marketplace.

### Cronologia delle versioni [#version-history]

Ogni salvataggio che modifica l'agente aggiunge una voce alla **Cronologia versioni**, che mostra quando è stata salvata ciascuna versione e quali strumenti e funzionalità aveva. **Ripristina** sostituisce la configurazione corrente con quella versione dopo una conferma. Solo gli utenti che possono modificare l'agente vedono questa funzione.

## Strumenti [#tools]

Fai clic su **Aggiungi** accanto al titolo **Strumenti** nel builder (riporta **Nessuno strumento ancora** finché non ne aggiungi uno) per aprire la **Libreria degli strumenti**. Cercalo oppure filtra per **Nativi**, **Strumenti**, **Server MCP** o **Azioni**. **Creati da te** raccoglie i server MCP e le Azioni che hai creato, mentre **Preferiti** mantiene a portata di mano gli elementi contrassegnati con la stella tra un agente e l'altro (fino a 100). Il menu **Crea nuovo…** permette di aggiungere un server MCP o un'Azione senza lasciare la finestra di dialogo, se il tuo ruolo consente di crearli. Ciò che vedi dipende da quanto abilitato dal tuo amministratore e dai permessi del tuo ruolo; un elemento che richiede ancora una chiave API mostra **Richiede configurazione**.

Run Code, File Search e File Context contengono dei file. Finché hanno ancora dei file allegati, rimuoverli apre invece il gestore dei file, e restano collegati all'agente finché tali file non vengono rimossi.

### Code Interpreter [#code-interpreter]

Elencato come **Run Code**. L'agente scrive ed esegue codice in un sandbox, che è ciò che serve per calcoli, analisi dei dati e la produzione di file come grafici o fogli di calcolo. I file che alleghi a questo strumento nel builder sono disponibili nel sandbox a ogni esecuzione. Se nessuno dei file di codice di una conversazione può essere ripristinato nel sandbox, l'agente si ferma prima di chiamare il modello e ti chiede di allegarli di nuovo. Vedi [Code Interpreter](/docs/features/code_interpreter).

#### Sessioni di codice con stato [#stateful-code-sessions]

Se il tuo amministratore li ha abilitati, le **Sessioni di codice con stato** nelle impostazioni di Run Code mantengono un workspace sandbox tra un'esecuzione e l'altra, quindi file e pacchetti installati vengono conservati. **Ambiente con stato** definisce chi condivide quel workspace: **Workspace utente (consigliato)** per tutti i tuoi agenti con stato, **Workspace agente + utente** per uno per ogni agente, oppure **Workspace conversazione** per uno per ogni chat. I nuovi agenti partono dal **Workspace con stato predefinito** in **Impostazioni > Dati e privacy > Esecuzione del codice**. Quando l'amministratore ha configurato più backend, **Ambiente di esecuzione** sceglie quale di essi esegue il codice, anche includendo un worker che colleghi sulla tua macchina.

Lo spazio di lavoro può essere reimpostato in qualsiasi momento, quindi non va considerato come spazio di archiviazione. Negli ambienti gestiti, salva gli output che ti servono in `/mnt/data`. I file scritti dall'agente con i suoi strumenti per i file sono elencati per ogni messaggio in **Modifiche all'area di lavoro**, dove puoi scaricarli. Con un ambiente collegato, il compositore offre **Chiedi prima di modificare**, **Accetta modifiche** o **Accesso completo** come modalità di approvazione per quella chat, entro i limiti impostati dal tuo amministratore.

Questa funzionalità è altamente sperimentale. Consulta [sessioni di codice con stato](/docs/features/code_interpreter#stateful-code-sessions) per i dettagli.

### Ricerca Web [#web-search]

L'agente cerca sul web e cita le sue fonti. Serve un provider di ricerca configurato dal tuo amministratore, oppure una tua chiave se l'amministratore ha impostato questa modalità. Vedi [Ricerca web](/docs/features/web_search).

### Ricerca file [#file-search]

Trasforma i file che alleghi in una knowledge base ricercabile. L'agente recupera i passaggi più pertinenti quando ne ha bisogno, quindi gestisce bene grandi insiemi di documenti. Non è adatto a dati strutturati come CSV o Excel, per i quali Run Code dà risultati migliori. Richiede la [RAG API](/docs/features/rag_api).

### Contesto del file [#file-context]

I file aggiunti in **File Context** hanno il testo estratto una sola volta, al momento del caricamento, e tale testo viene inserito nel contesto dell'agente a ogni messaggio. Usala per alcuni documenti chiave che l'agente deve sempre avere a disposizione. L'estrazione funziona allo stesso modo di [Upload as Text](/docs/features/upload_as_text): per impostazione predefinita viene eseguita un'analisi del testo semplice, mentre con [OCR](/docs/features/ocr) configurato si ottengono risultati migliori su scansioni e immagini.

Poiché il testo viene inviato insieme a ogni messaggio, i file di grandi dimensioni qui comportano un costo in token a ogni turno. Chiunque possa chattare con l'agente può anche far sì che quel testo venga estratto da esso.

### Artifacts [#artifacts]

Consente all'agente di visualizzare React, HTML, SVG, Markdown e Mermaid in un pannello laterale invece che come blocchi di codice. L'impostazione **Mode** seleziona le istruzioni predefinite: **Normal**, **shadcn/ui** (aggiunge istruzioni per la libreria di componenti shadcn/ui) oppure **Custom**, che non inserisce nulla, quindi le tue istruzioni personalizzate devono insegnare la sintassi degli artefatti. Consulta [Artifacts](/docs/features/artifacts) per tale sintassi.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

I server MCP configurati dal tuo amministratore, o quelli che hai aggiunto tu stesso, compaiono sotto **MCP servers**. Aggiungere un server collega tutti i suoi strumenti; espandilo sotto **Tools in this server** per selezionare solo quelli di cui l'agente ha bisogno. Vedi [MCP](/docs/features/mcp).

Alcuni server possono elencare i propri strumenti solo durante una chat, perché dipendono da valori presenti nella richiesta. Per questi, il builder offre una sola selezione per tutti gli strumenti del server invece degli interruttori per singolo strumento. Se tutti gli strumenti MCP selezionati per un agente non riescono a caricarsi all'avvio di un'esecuzione, l'esecuzione si interrompe e ti invita a riconnetterti o ad accedere al server, anziché proseguire senza di essi.

Ogni strumento MCP dispone di un menu **Tool Options** con alcuni interruttori per singolo strumento:

- **Differisci**: vedi [Strumenti differiti](#deferred-tools). **Differisci tutti gli strumenti** lo applica a tutto il server.
- **Programmatica**: vedi [Chiamata programmatica di strumenti](#programmatic-tool-calling).
- **Contesto**: vedi [Chiamate agli strumenti in background](#background-tool-calls).
- **Etichetta di intento**: l'agente scrive una breve descrizione su una riga di ogni chiamata, mostrata in tempo reale come stato della chiamata al posto di un'etichetta generica. Aggiunge alcuni token a ogni richiesta. Gli strumenti nativi ricevono automaticamente le etichette di intento. Questo non vale per gli strumenti programmatici.

**Sfondo** e **Etichetta di intento** compaiono solo se il tuo amministratore li ha abilitati.

### Strumenti differiti [#deferred-tools]

Un agente con diversi server MCP può facilmente avere decine di definizioni di strumenti, e inviarle tutte a ogni richiesta consuma contesto e rende il modello meno preciso nella scelta di quello giusto. Uno strumento differito viene escluso dalla richiesta iniziale. Al suo posto, l'agente riceve uno strumento di ricerca degli strumenti, che gli permette di trovare gli strumenti differiti per nome o descrizione quando ne ha bisogno, e di utilizzare uno strumento trovato per il resto della conversazione.

### Chiamata programmatica di strumenti [#programmatic-tool-calling]

Con **Programmatic** attivato per uno strumento MCP (o per un intero server), il modello non chiama direttamente quello strumento. Scrive invece del codice nella sandbox di Code Interpreter che richiama lo strumento come funzione, così può eseguire cicli, paginare, ritentare e filtrare i risultati prima di rispondere. Questo è utile per attività come "controlla questi 40 ticket e riassumi quelli aperti", che altrimenti richiederebbero 40 chiamate separate allo strumento tramite il modello.

Gli interruttori **Programmatic** restano disattivati finché Run Code non è attivo, e disattivare Run Code li azzera. La sandbox può chiamare solo gli strumenti registrati sull'agente. Durante l'esecuzione, espandi la scheda del codice per seguire in tempo reale una traccia di ogni chiamata interna allo strumento; la traccia non viene conservata dopo il ricaricamento della pagina. Questa funzione è disattivata per impostazione predefinita; il tuo amministratore deve abilitarla.

### Chiamate agli strumenti in background [#background-tool-calls]

Uno strumento in grado di eseguire attività in background restituisce subito un riferimento all'attività, così l'agente può continuare a lavorare mentre questa è in esecuzione. Al termine dell'attività, il risultato viene consegnato automaticamente in un turno successivo (mostrato come una scheda attività comprimibile), oppure l'agente può verificarne lo stato con il suo strumento per le attività. L'output e i file dell'esecuzione in background compaiono sulla chiamata originale dello strumento. Strumenti che possono essere eseguiti in background:

- **Esegui codice**: codice e comandi shell sono idonei per impostazione predefinita; disattiva **Esecuzione in background** nelle sue impostazioni per escluderti.
- **Strumenti MCP**: contrassegna uno strumento o un intero server come **Background**.
- **Altri strumenti e Azioni**: attiva l'**Esecuzione in background**. Le Azioni che utilizzano OAuth non la offrono.

Questi interruttori consentono l'esecuzione in background; il modello decide comunque per ogni chiamata. Il lavoro in background viene eseguito nel processo del server che lo ha avviato e viene perso se tale processo si interrompe. Il tuo amministratore deve abilitare la funzionalità.

### Actions [#actions]

Le azioni trasformano una specifica OpenAPI in strumenti. Scegli **Crea nuovo…** e poi **Azioni**, incolla lo schema e configura l'**Autenticazione** se l'API la richiede. Ogni operazione della specifica diventa uno strumento che l'agente può chiamare.

Se stai utilizzando un modello OpenAI, aggiungi `x-strict: true` a un'operazione nella specifica e LibreChat richiederà per essa la chiamata di funzioni in modalità strict. La modalità strict accetta solo un sottoinsieme di JSON Schema; consulta la [guida agli output strutturati](https://platform.openai.com/docs/guides/structured-outputs) di OpenAI.

Le azioni possono raggiungere solo i domini consentiti dal tuo amministratore, e gli indirizzi di rete privata sono bloccati a meno che non siano esplicitamente consentiti.

### Skills [#skills]

La sezione **Skills** nel builder controlla quali [Skills](/docs/features/skills) l'agente può utilizzare: **Off**, **All** (ogni skill attiva), oppure **Selected** (solo quelle che aggiungi).

### Memoria [#memory]

**Memoria** consente all'agente di salvare, aggiornare ed eliminare ricordi su di te quando gli chiedi di ricordare o dimenticare qualcosa. Per funzionare, la memoria deve essere configurata sull'istanza e consentita per il tuo ruolo. Per impostazione predefinita, l'agente condivide i tuoi ricordi personali con le altre chat; attiva **Mantieni i ricordi separati per questo agente** per dargli ricordi propri, che solo lui legge e scrive. Vedi [Memoria](/docs/features/memory).

### Richiesta all'utente e approvazione degli strumenti [#ask-user-and-tool-approval]

**Chiedi all'utente** consente all'agente di mettere in pausa l'esecuzione a metà per farti una domanda e attendere la risposta. Una pausa può contenere fino a quattro domande, mostrate una alla volta con **Indietro** e **Avanti**; ciascuna accetta una risposta libera oppure una delle scelte proposte dall'agente. **Salta** rifiuta tutte le domande. L'esecuzione riprende non appena invii le risposte, e le tue risposte vengono conservate anche se interrompi l'operazione mentre si riavvia.

Il tuo amministratore può anche richiedere un'approvazione prima che determinati strumenti vengano eseguiti. L'esecuzione si mette in pausa, puoi esaminare la chiamata in un pannello sopra la casella del messaggio (approvare, rifiutare o, per alcuni strumenti, modificare gli argomenti), e poi continua. Se l'amministratore ha abilitato le modalità di approvazione per agente, a ciascuno strumento dell'agente viene assegnata una **Modalità di approvazione dello strumento**: **Usa la politica ereditata**, **Chiedi sempre**, **Approva sempre**, **Chiedi una volta per chat** oppure **Chiedi una volta, poi approva sempre**. Le regole dell'amministratore continuano ad applicarsi in aggiunta, e **Reimposta le approvazioni memorizzate** cancella le approvazioni concesse in precedenza.

### Altri strumenti [#other-tools]

La categoria **Tools** contiene le integrazioni integrate che il tuo amministratore ha abilitato, come [image generation](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search) e [Azure AI Search](/docs/configuration/tools/azure_ai_search). Ognuna di esse viene configurata separatamente; vedi [Tools](/docs/configuration/tools).

## Lavorare con altri agenti [#working-with-other-agents]

**Subagenti** permettono all'agente di affidare un sottocompito mirato a una copia nuova di sé stesso, oppure a un altro agente, in una finestra di contesto separata. Viene restituito solo il risultato, quindi l'output lungo degli strumenti resta fuori dalla conversazione principale. Vedi [Subagenti](/docs/features/subagents).

### Handoffs [#handoffs]

**Gli handoff** forniscono all'agente uno strumento di trasferimento per ciascun agente che elenchi, così può passare la conversazione a uno specialista quando l'argomento lo richiede. Per ogni handoff puoi aggiungere una descrizione (quando trasferire) e un contenuto passthrough (cosa deve generare l'agente e trasmettere), e rinominare il parametro in cui tale contenuto viene passato (`instructions` per impostazione predefinita). Un agente può avere fino a 10 handoff. Gli handoff sono sempre disponibili; non dipendono da un'impostazione dell'amministratore.

### Catena di agenti [#agent-chain]

Le catene di agenti sono obsolete. Le catene esistenti continuano a funzionare e il builder le mostra in **Impostazioni avanzate** con un pulsante **Remove chain**, ma non è più possibile crearne di nuove. Utilizza invece i subagenti o gli handoff.

## Passaggi massimi dell'agente [#max-agent-steps]

**Impostazioni avanzate** include un campo **Max Agent Steps** che limita il numero di passaggi che l'agente può compiere prima di dover fornire una risposta finale. Un passaggio corrisponde a una richiesta al modello o a un ciclo di chiamate agli strumenti; pertanto, una singola chiamata a uno strumento costa di solito tre passaggi: la richiesta, il ciclo dello strumento e la richiesta di follow-up.

Lascialo vuoto per usare il valore predefinito del server, che è 50 a meno che il tuo amministratore non lo abbia modificato. Il tuo amministratore può anche impostare un limite massimo che il campo non può superare.

Quando un turno esaurisce i passaggi disponibili, mantieni ciò che l'agente ha fatto finora, e il messaggio propone **Continua** (un nuovo turno con un nuovo budget) oppure **Rispondi ora** (l'agente risponde in base al lavoro già svolto, senza usare altri strumenti). Se questo accade spesso con catene di strumenti lunghe, aumenta il limite.

## Dopo una lunga esecuzione [#following-a-long-run]

Le schede degli strumenti mostrano **Preparing** mentre una chiamata è in attesa (ad esempio in attesa di approvazione) e poi **Calling** finché non arriva il risultato. L'output della shell viene visualizzato in stile terminale e ridotto alle ultime 15 righe; **Show more** lo espande, e un comando non riuscito mostra il suo codice di uscita, il segnale o il timeout.

### Gruppi di attività [#activity-groups]

Se il tuo amministratore le ha attivate, ogni tratto di ragionamento e di chiamate agli strumenti si comprime sotto un'intestazione generata di una sola riga, così un'esecuzione con 30 chiamate agli strumenti appare come poche righe. Espandi un'intestazione per vedere le chiamate al suo interno. Un secondo livello può raggruppare diversi di questi gruppi in una fase con un proprio riepilogo, offrendo alle esecuzioni lunghe una struttura a schema; una volta completati due gruppi, si uniscono immediatamente, con l'intestazione più recente che resta visibile finché non arriva il riepilogo. La risposta finale rimane sempre al di fuori della sezione compressa, e i file prodotti all'interno di una fase vengono mostrati in una riga sotto di essa anziché essere nascosti. Con [Smooth Streaming](/docs/features/smooth_streaming) attivo, la compressione è animata, a meno che il tuo dispositivo non richieda la riduzione del movimento.

Le etichette di ragionamento in tempo reale sono un'opzione correlata: invece di un generico titolo **Thinking**, il blocco di ragionamento mostra un riepilogo breve e aggiornato di ciò su cui il modello sta lavorando.

Intestazioni, riepiloghi delle fasi ed etichette di ragionamento comportano chiamate extra al modello, che vengono registrate come qualsiasi altro utilizzo. Gli amministratori le configurano in [gruppi di attività dell'agente](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) e [etichette di ragionamento in tempo reale](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Messaggi di guida e messaggi in coda [#steering-and-queued-messages]

Mentre un agente sta rispondendo, puoi comunque inviare dei messaggi:

- **Steer** inserisce il messaggio nell'esecuzione in corso al successivo punto sicuro, così l'agente può adattarsi prima di completare l'operazione.
- **Interrompi** annulla le chiamate agli strumenti e il ragionamento in corso, mantiene ciò che è già stato completato e prosegue con il tuo messaggio. Gli effetti già avvenuti al di fuori di LibreChat non possono essere annullati. Alcune esecuzioni, ad esempio quelle che usano la ricerca integrata di un provider, non possono essere interrotte e il messaggio viene invece accodato come steer.
- **Queue** contiene il messaggio e lo invia come un normale turno al termine della risposta.

**While generating, Enter will** under **Settings > Chat** picks the default, and the send button menu overrides it per message; `Alt + Enter` interrupts. Queued messages are listed above the composer, where you can edit, remove, reorder, **Send now**, or **Interrupt now**. Files and quoted excerpts go along with the message; skills you picked with `$` wait for the next full turn. Queued messages in a saved agent chat are stored on the server and survive a closed browser.

Una chat può contenere fino a 100 messaggi in coda (16.000 caratteri e 10 file ciascuno), e un'esecuzione può avere fino a 10 indicazioni in sospeso. Consulta [Composer](/docs/features/composer) per i dettagli su ricevute e controlli.

## File nella chat [#files-in-a-chat]

Quando chatti con un agente, il menu Allega offre:

- **Carica immagine**: inviata al modello per la visione.
- **Carica come testo**: il testo completo viene inserito solo in questa conversazione. Vedi [Carica come testo](/docs/features/upload_as_text).
- **Caricamento per la ricerca nei file**: indicizzato per il recupero, come i file di ricerca nei file dell'agente stesso, ma limitato a questa chat.
- **Carica nell'ambiente di codice**: copiati nella sandbox per Esegui codice. Ideale per CSV, Excel e JSON.

Le opzioni compaiono solo quando la funzionalità corrispondente è abilitata.

## Condivisione e permessi [#sharing-and-permissions]

Gli agenti sono privati per il loro autore finché non vengono condivisi. Fai clic su **Share** nel footer del builder per concedere l'accesso a utenti, gruppi o ruoli, ciascuno con uno dei tre ruoli disponibili:

| Ruolo | Cosa può fare |
| ----- | ------------- |
| Visualizzatore | Chattare con l'agente. Non può aprirlo nel builder né vedere le sue istruzioni, gli strumenti o i file. |
| Editor | Tutto ciò che può fare un visualizzatore, più modificare le istruzioni, il modello, gli strumenti e i file. |
| Proprietario | Tutto ciò che può fare un editor, più eliminare l'agente e modificare con chi è condiviso. |

**Condividi con tutti** rende l'agente disponibile a ogni utente dell'istanza; è necessario il permesso di condivisione pubblica. L'autore e gli amministratori mantengono sempre il controllo completo.

Uno spettatore non può vedere le istruzioni o i file nel builder, ma il modello può comunque ripeterli in una conversazione se glielo si chiede. Non inserire in un agente nulla che i suoi spettatori non dovrebbero mai vedere.

Separatamente, il pulsante a forma di globo (**Remote Access**) controlla chi può richiamare l'agente tramite le [Agents API](/docs/features/agents_api).

Le schede degli agenti mostrano il contatto di assistenza impostato nel builder. Se non è stato impostato alcun contatto, possono mostrare il nome del proprietario, ma non l'indirizzo email del proprietario, a meno che non sia stato inserito come contatto.

Consulta [Controllo degli accessi](/docs/features/access_control) per capire come utenti, gruppi e ruoli si combinano.

### Controlli dell'amministratore [#administrator-controls]

Se un ruolo può utilizzare, creare, condividere o condividere pubblicamente gli agenti è impostato per ciascun ruolo nel [Pannello di amministrazione](/docs/features/admin_panel). Gli amministratori dispongono inoltre di un pulsante **Impostazioni amministratore** in fondo al Costruttore di agenti, con gli stessi interruttori, per ciascun ruolo. Su un'istanza single-tenant il primo account registrato è un amministratore; per aggiungerne altri, consulta [Promuovere un altro amministratore](/docs/configuration/access_control#promote-another-admin).

## Marketplace degli Agenti [#agent-marketplace]

**Agent Marketplace** nella barra laterale elenca gli agenti disponibili per te, se il tuo ruolo ne consente l'uso. Cerca per nome o descrizione, filtra per categoria (**Top Picks**, **All**, oppure una specifica) e modifica l'ordine con **Sort by**: **Newest first**, **Oldest first**, **Popular** o **By creator name**. **My agents** mostra solo i tuoi. La ricerca, l'ordinamento e il filtro vengono mantenuti nell'URL, così puoi salvare nei preferiti o condividere una vista.

Fai clic su una scheda per visualizzare i dettagli e le azioni **Pin** o **Unpin**, **Copy Link** (un link che apre una nuova chat con l'agente) e **Start Chat**. Facendo clic su uno dei suggerimenti di conversazione dell'agente, si apre una nuova chat con il prompt nella casella del messaggio, non inviato, così da poterlo modificare prima dell'invio.

## Agents API [#agents-api]

Gli agenti possono anche essere richiamati da script e altre app tramite un'API compatibile con OpenAI, gestiti da servizi attendibili e attivati da eventi provenienti da altri sistemi. Vedi [Agents API](/docs/features/agents_api). [Scheduled Chats](/docs/features/scheduled_chats) avvia le esecuzioni degli agenti a intervalli di tempo, mentre [Agent Plugins](/docs/features/agent_plugins) consente a un operatore di distribuire skill e server MCP agli agenti come un unico pacchetto.

## Setup [#setup]

Gli agenti sono abilitati per impostazione predefinita. Gli amministratori scelgono quali funzionalità sono offerte, i limiti di passaggi e i provider consentiti nella [configurazione dell'endpoint agents](/docs/configuration/librechat_yaml/object_structure/agents), nonché i domini che le Actions possono raggiungere nella [configurazione delle Actions](/docs/configuration/librechat_yaml/object_structure/actions). Le istanze aggiornate da una versione precedente alla v0.8.0-rc3 necessitano della [migrazione dei permessi](/docs/configuration/access_control#migrating-from-pre-acl-versions).
