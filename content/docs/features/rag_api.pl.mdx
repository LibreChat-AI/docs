Wyszukiwanie plików pozwala przesyłać dokumenty i zadawać pytania na ich temat bez wklejania ich treści do czatu. LibreChat wysyła każdy plik do API RAG, które dzieli go na fragmenty i je indeksuje; gdy zadasz pytanie, model przeszukuje ten indeks i odpowiada na podstawie znalezionych fragmentów.

Sięgaj po to narzędzie, gdy dokument jest zbyt długi, aby czytać go w całości przy każdej turze, albo gdy chcesz uzyskać odpowiedzi na podstawie kilku plików jednocześnie.

## Prześlij plik do wyszukiwania [#upload-a-file-for-search]

Kliknij **+** w [kompozytorze wiadomości](/docs/features/composer), aby otworzyć paletę, rozwiń **More upload options**, a następnie wybierz **Upload for File Search** i wskaż pliki. Można też wyszukać tę opcję w palecie. Przesyłanie w ten sposób włącza również **File Search** dla czatu. Duże pliki mogą wymagać chwili na indeksowanie; przesyłanie zakończy się po zakończeniu indeksowania.

Gdy rozmowa ma już zindeksowane pliki, model otrzymuje narzędzie `file_search`. To on decyduje, kiedy je wywołać: pytanie dotyczące dokumentu uruchamia wyszukiwanie, a zwykła rozmowa towarzyska nie. Podczas działania narzędzia odpowiedź pokazuje krok „Searching your files”, a gdy cytowania są włączone, fragmenty, z których model skorzystał, pojawiają się w sekcji **Sources** wraz z nazwą pliku, dzięki czemu możesz otworzyć dokument i sprawdzić je samodzielnie.

## Jak działa wyszukiwanie [#how-search-works]

Gdy model wywołuje `file_search`, zapisuje zapytanie wyszukiwania. LibreChat prosi RAG API o 5 najbliższych fragmentów z każdego dołączonego pliku i zachowuje łącznie 10 najbliższych. Te fragmenty wraz z nazwą pliku i wynikiem trafności wracają do modelu, który na ich podstawie udziela odpowiedzi.

Wyszukiwanie (retrieval) znajduje fragmenty tekstu, których znaczenie jest zbliżone do zapytania, dlatego dobrze sprawdza się w wyszukiwaniu konkretnych faktów w dużych dokumentach. W przypadku pytań wymagających uwzględnienia całego dokumentu naraz, na przykład streszczenia, zwykle lepiej sprawdza się opcja Upload as Text.

Usunięcie pliku w LibreChat powoduje także usunięcie jego wektorów z RAG API.

## Ponowne użycie plików, które już przesłano [#reuse-files-you-already-uploaded]

Pliki zindeksowane pozostają na Twoim koncie. Otwórz paletę i sprawdź sekcję **Your files**, aby dołączyć plik do nowej wiadomości lub rozmowy bez ponownego przesyłania.

Pliki przesłane, gdy aktywny był endpoint Assistants, są przechowywane w OpenAI, nie są indeksowane przez RAG API i nie mogą być dołączane do innych endpointów.

## Wyszukiwanie plików w agentach [#file-search-in-agents]

Dla agenta włącz [**File Search**](/docs/features/agents#file-search) w Agent Builder i prześlij tam pliki. Staną się one bazą wiedzy agenta: każdy, kto rozmawia z agentem, może sprawić, że będzie on przeszukiwał te pliki, bez konieczności przesyłania czegokolwiek samodzielnie. Agent musi zostać zapisany, zanim będzie można dodać do niego pliki.

## Wyszukiwanie w plikach lub przesyłanie jako tekst [#file-search-or-upload-as-text]

[**Prześlij jako tekst**](/docs/features/upload_as_text) znajduje się w tym samym menu. Wyodrębnia ono tekst pliku i umieszcza cały jego zawartość w rozmowie, co sprawdza się w przypadku krótkich dokumentów, w których model powinien przeczytać każde słowo. Wyszukiwanie w plikach przesyła tylko te fragmenty, które pasują do każdego zapytania, dzięki czemu skaluje się do długich dokumentów i wielu plików, jednak model nigdy nie widzi tych części, których nie udało się pobrać.

Interfejs API RAG obsługuje również funkcję Upload as Text, jako ekstraktor tekstu dla typów plików, których wbudowany parser nie potrafi odczytać. Zobacz [jak wyodrębniany jest tekst](/docs/features/upload_as_text#how-the-text-is-extracted).

## Konfiguracja [#setup]

Wyszukiwanie plików wymaga usługi RAG API oraz bazy danych wektorowych. Domyślna konfiguracja Docker zawiera oba te elementy; administrator ustawia dostawcę embeddingów, a w przypadku innych instalacji — `RAG_API_URL`. Zobacz [konfiguracja RAG API](/docs/configuration/rag_api) oraz [repozytorium RAG API](https://github.com/LibreChat-AI/rag-api), aby poznać endpointy i zmienne samej usługi.
