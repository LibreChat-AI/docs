**RAG (Retrieval-Augmented Generation) API** to osobna usługa, która indeksuje pliki przesłane do LibreChat i zwraca fragmenty najbardziej trafne dla danego pytania, dzięki czemu model może odpowiadać na podstawie Twoich dokumentów, a nie wyłącznie na podstawie danych z treningu.

To jest aplikacja FastAPI w Pythonie oparta na LangChain, która przechowuje osadzenia (embeddings) w PostgreSQL z wykorzystaniem rozszerzenia pgvector.

**Aby to skonfigurować, zobacz [Konfiguracja RAG API](/docs/configuration/rag_api).**

W LibreChat, RAG zasila funkcjonalność [Agentów](/docs/features/agents#file-search) **File Search** (`file_search`). Pliki dołączone do File Search agenta lub do uruchomienia, które wybiera File Search, są indeksowane przez API RAG i pobierane na żądanie. Inne endpointy czatu nie korzystają z indeksowania ani pobierania RAG, mogą jednak nadal używać API RAG do wyodrębniania tekstu, jak opisano poniżej.

Interfejs RAG API udostępnia także trasę `/text`, z której LibreChat może korzystać do wyodrębniania tekstu z przesyłanych plików; zobacz [Przesyłanie jako tekst](/docs/features/upload_as_text#what-happens-under-the-hood), aby dowiedzieć się, kiedy ma to zastosowanie.

## Jak to działa [#how-it-works]

1. **Indeksowanie.** Gdy plik ma być przeszukiwalny (podczas przesyłania do funkcji File Search agenta lub gdy przebieg czatu po raz pierwszy używa File Search na załączniku), LibreChat przekazuje go do RAG API, które dzieli tekst na nakładające się fragmenty (`CHUNK_SIZE` i `CHUNK_OVERLAP`), przekształca każdy fragment w osadzenie (embedding) za pomocą skonfigurowanego dostawcy i zapisuje wektory w pgvector.
2. **Wyszukiwanie.** Gdy model wywołuje wyszukiwanie w plikach (File Search), zapisuje zapytanie wyszukiwania. LibreChat prosi API RAG o 5 najbliższych fragmentów z każdego załączonego pliku, a następnie zachowuje 10 najbliższych spośród wszystkich.
3. **Odpowiadanie.** Te fragmenty są zwracane modelowi wraz z nazwą pliku i wynikiem trafności, a model udziela odpowiedzi na ich podstawie. Gdy [cytowania plików](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) są włączone, odpowiedź może wskazywać pliki, z których model skorzystał.

Usunięcie pliku w LibreChat powoduje także usunięcie jego wektorów z RAG API.

Wyszukiwanie znajduje wyłącznie fragmenty semantycznie zbliżone do zapytania, dlatego sprawdza się najlepiej przy wyszukiwaniu konkretnych faktów w dużych dokumentach. W przypadku pytań wymagających przetworzenia całego dokumentu naraz, na przykład jego podsumowania, [Prześlij jako tekst](/docs/features/upload_as_text) zwykle daje lepsze wyniki.

## Czym jest RAG? [#what-is-rag]

Retrieval-Augmented Generation (RAG) opiera model językowy na zewnętrznym źródle wiedzy. Zamiast polegać wyłącznie na tym, czego model nauczył się podczas treningu, aplikacja najpierw pobiera odpowiednie fragmenty z tego źródła i dodaje je do promptu, a model generuje odpowiedź na ich podstawie. Ponieważ wiedza znajduje się poza modelem, możesz dodawać lub aktualizować dokumenty bez konieczności ponownego trenowania czegokolwiek.
