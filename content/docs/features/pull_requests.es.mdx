  Consulta la solicitud de extracción (pull request) del espacio de trabajo de
  código de un chat, con su tamaño, estado y verificaciones de CI, en el
  encabezado del chat y en la barra lateral.
---

Cuando un agente trabaja en un repositorio de un espacio de trabajo de código adjunto, LibreChat encuentra la pull request de la rama en la que se encuentra el espacio de trabajo y la muestra junto al chat. Puedes ver si está lista para fusionarse, si las comprobaciones pasan y acceder a ella directamente, sin salir de la conversación. Funciona con GitHub, GitLab (donde se denomina merge request) y Bitbucket Cloud, con un proveedor por despliegue.

Solo los chats que ejecutan código en un workspace adjunto pueden tener un pull request. Un chat sin workspace, o un workspace que aún no ha informado una rama, no muestra nada.

## En el encabezado del chat [#in-the-chat-header]

En una pantalla ancha, un chip a la izquierda del encabezado muestra el icono de la solicitud de extracción, un pequeño punto de CI en su esquina y el título de la solicitud de extracción. Pase el cursor sobre el chip o enfóquelo para abrir una tarjeta con los detalles. La tarjeta permanece abierta mientras el puntero o el foco del teclado estén dentro de ella.

En una pantalla pequeña no aparece el chip. Abre el menú de tres puntos del encabezado y elige la entrada `PR #number` (`MR !number` en GitLab) para mostrar la misma tarjeta en un diálogo.

El encabezado se mantiene actualizado por sí solo: vuelve a comprobar el estado aproximadamente cada 20 segundos mientras las verificaciones están en curso o el proveedor todavía está determinando si la rama puede fusionarse, y cada 60 segundos en los demás casos. Deja de hacerlo una vez que la solicitud de extracción se fusiona o se cierra y no queda nada en ejecución.

## En la barra lateral [#in-the-sidebar]

Las conversaciones que tienen una solicitud de extracción muestran el mismo icono y el mismo punto de CI al final de su fila. La fila conserva el título propio de la conversación. Pase el cursor sobre la fila, o enfoque o haga clic en la marca, para abrir la tarjeta junto a ella; hacer clic en la marca no abre la conversación.

  alt="Filas de la barra lateral con marcas de solicitudes de extracción: lista para fusionar, conflictos con comprobaciones fallidas, un borrador con comprobaciones en ejecución y una solicitud de extracción fusionada"

La barra lateral no consulta el servidor de forma periódica. Cada fila está tan actualizada como la última vez que se cargó la lista, y se actualiza cuando vuelves a la ventana y sus datos tienen más de un minuto. Si una actualización falla para una solicitud de extracción que ya se había encontrado, la marca se mantiene y la tarjeta muestra «No se pudo actualizar la solicitud de extracción» con un botón **Reintentar**. Una conversación cuya solicitud de extracción nunca se ha encontrado no muestra ninguna marca, incluso cuando la búsqueda falló.

## Leer la tarjeta [#reading-the-card]

La tarjeta muestra `PR #number` (`MR !number` en GitLab), las líneas añadidas en verde y las eliminadas en rojo, un enlace **Open in GitHub**, **Open in GitLab** o **Open in Bitbucket**, el título y dos insignias:

- Estado: Abierto, Conflictos, Borrador, Fusionado o Cerrado. Conflictos reemplaza a Abierto cuando la rama no puede fusionarse limpiamente.
- Comprobaciones: Aprobadas, Fallidas, En ejecución o Ninguna. En GitLab, esto corresponde a la canalización principal (head pipeline), y solo si se ejecutó para el commit actual. En Bitbucket, corresponde a los estados de los commits.

El color del icono y el punto de CI resumen la misma información de un vistazo:

| Pull request | Icono | Punto de CI |
| ------------------------------------ | ------- | --------------- |
| Abierta, se puede fusionar | Verde | Según las comprobaciones |
| Abierta, aún no se conoce si se puede fusionar | Neutral | Según las comprobaciones |
| Abierta, con conflictos de fusión | Rojo | Según las comprobaciones |
| Borrador | Neutral | Según las comprobaciones |
| Fusionada | Morado | Ninguno |
| Cerrada | Neutral | Ninguno |

El punto es verde para las comprobaciones que pasan, rojo para las que fallan y ámbar para las que están en ejecución. No aparece ningún punto cuando el repositorio no informa de comprobaciones. Una comprobación fallida tiene prioridad sobre una que todavía está en ejecución.

## Qué pull request ves [#which-pull-request-you-see]

El espacio de trabajo informa del repositorio, la rama y el commit en los que se ejecutó por última vez el chat, y LibreChat busca una pull request desde esa rama:

- Si la salida del propio comando del chat imprimió un enlace a una pull request del mismo repositorio (por ejemplo, la URL que imprime `gh pr create`), se usa esa pull request, siempre que provenga de la rama del chat.
- De lo contrario, se prefieren las pull requests abiertas para la rama sobre las cerradas, por lo que una pull request cerrada antigua con un nombre de rama reutilizado no oculta la actual.
- Una solicitud de extracción solo cuenta si contiene el commit en el que se ejecutó por última vez el chat. Eliminar una rama y reutilizar su nombre no restaura la solicitud de extracción anterior.
- Una rama nueva sin commits no coincide con nada.

Los repositorios a los que el servidor no tiene permiso para acceder se comportan exactamente igual que los repositorios sin pull request: sin marca y sin error.

## Conecta tu propia cuenta [#connect-your-own-account]

Si tu administrador lo ha configurado, puedes buscar pull requests con tu propia cuenta de GitHub, GitLab o Bitbucket. Abre **Configuración**, ve a **Cuenta** y, en **Cuentas conectadas**, haz clic en **Conectar** junto a **Cuenta de pull request**. Se abrirá una ventana de inicio de sesión en el proveedor; apruébala y la fila mostrará **Conectado**. Si la ventana no se abre, permite las ventanas emergentes para LibreChat e inténtalo de nuevo.

Una vez conectado, las búsquedas usan tu cuenta, por lo que ves las pull requests de cualquier repositorio que puedas leer, con tu propio límite de solicitudes. **Desconectar** elimina la conexión, y puedes volver a conectarte en cualquier momento. Si el servidor no puede renovar tu conexión (por ejemplo, porque el proveedor no está disponible), tus pull requests se muestran como no disponibles en lugar de cambiar silenciosamente al token del servidor. Si revocas la aplicación en el proveedor, LibreChat elimina la conexión y vuelves al estado de no conectado.

Si la fila indica **Not in use**, tu administrador ha desactivado las conexiones de cuenta y las búsquedas ya no utilizan tu cuenta. Haz clic en **Disconnect** para eliminar la conexión almacenada.

## Configuración [#setup]

La función está activada por defecto, pero permanece oculta hasta que un administrador proporcione a LibreChat un token y una lista de repositorios que puede consultar, o configure una aplicación para que los usuarios puedan conectar sus propias cuentas. También necesita un espacio de trabajo de código adjunto que informe su rama de git. Consulte [Configuración de Pull Requests](/docs/configuration/pull_requests).
