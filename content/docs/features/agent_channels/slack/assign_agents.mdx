Once an organization's Slack app is connected, agent owners decide which agent answers. A bot has one **default** agent for direct messages and mentions, and can use a different agent in any **specific channel**.

<FlowDiagram summary="How the bot picks an agent: a channel-specific assignment wins, otherwise the default assignment answers">
  <FlowNode icon="MessageSquare" title="A message arrives" label="A mention in a channel, or a direct message" />
  <FlowNode icon="Waypoints" title="Channel-specific agent?" label="Used when the channel has its own assignment" />
  <FlowNode icon="Bot" title="Default agent" label="Answers everything else, including direct messages" />
</FlowDiagram>

If neither exists, the bot replies privately: "No agent is configured for this Slack conversation."

## Before you start

- The workspace is [connected](/docs/features/agent_channels/slack/organization_setup) and shows **Connected**.
- Your role can use **Remote Agents**, and you can **share** the agent.
- An administrator has given you [bot management access](/docs/features/agent_channels/slack/organization_setup#7-grant-bot-management-access), or you are an administrator yourself.

</Callout>

### Replacing another agent

If another agent already answers in that place, the button changes to **Replace default agent** or **Replace channel agent**, and a warning names the current agent. Confirming moves the assignment to your agent. Conversations that already started in existing threads keep their original agent.

## Manage assignments

Hover over or focus the Slack row in the Channels section and select the gear button, **Manage connection**.

<ThemeImage
  light="/images/features/agent_channels/manage-workspace-connection-light.png"
  dark="/images/features/agent_channels/manage-workspace-connection-dark.png"
  alt="Manage connection dialog for the Acme Assistant bot listing the C0123456789 assignment with Remove, an Add assignment button, and Delete connection, Disable and Close buttons"
  width={672}
/>

| Action | What happens |
| --- | --- |
| **Add assignment** | Assign this agent to another channel, or make it the default. Not shown once the agent is the bot's default, since the default already covers every channel without its own agent. |
| **Remove** | Removes one assignment after confirmation. Mentions there fall back to the default agent, if there is one. |
| **Disable** | Stops the connection without deleting it. Assignments are kept. |
| **Activate channel** | Turns a disabled connection back on and restores its retained assignment. Everyone links and confirms their account again. |
| **Delete connection** | Removes the connection and all of its assignments, after confirmation. |

Only the person who created a connection can change its assignments. Other people see it as **Managed by another account**. Existing threads keep the agent they started with, whatever you change.

### Connection statuses

| Status | Meaning |
| --- | --- |
| Not assigned | The connection exists but has no assignment yet (shown as **Pending installation** for manual connections). |
| Active | The bot answers with this agent. |
| Disabled | The connection is paused. |
| Deleting | Removal is in progress. |
| Unavailable | The workspace was disconnected or the app was removed. The dialog explains what to do. |

## Plan your assignments

- **Start with a general default.** A broadly useful agent as the default means direct messages and new channels always get an answer.
- **Use channel agents for focus.** A support channel can use an agent with your help center tools, while an engineering channel uses one with code tools.
- **Match the agent to the audience.** Answers are visible to everyone in the channel. Assign agents that can reach sensitive data only to channels whose members should see it.
