title: Connect a Slack Workspace
description: Register your organization's Slack app in LibreChat, configure its callbacks and permissions, and install it in a workspace.

Organization workspaces let an administrator register a Slack app once, install it in your workspace, and let agent owners assign agents to it. This guide takes about 15 minutes and uses two browser tabs: Slack's app settings and LibreChat.

## Before you start

<Callout type="info" title="Checklist">
- Your operator has [deployed the shared gateway](/docs/features/agent_channels/deployment#organization-workspaces) and it reports ready.
- Your LibreChat account has the `access:admin` and `manage:agents` capabilities, for example through the `ADMIN` role.
- You can create apps in the Slack workspace, or a Slack admin can approve the installation.
</Callout>

If the **Slack** row does not appear in **Settings → Account**, organization workspaces are not enabled on this deployment. Ask your operator, or use a [manual connection](/docs/features/agent_channels/slack/manual_setup) instead.

## 1. Create the Slack app

Open [Your Apps](https://api.slack.com/apps) in Slack and select **Create New App → From scratch**. Name it, for example after your assistant, and pick the workspace to develop it in. You can also use an existing app that your organization controls.

If Slack shows the **Pick features** wizard, continue without selecting scopes or events, then select **Create → Create Anyway**. Do not install the app yet: LibreChat installs it for you in step 6.

## 2. Register the app in LibreChat

<Steps>
<Step>

Open **Settings → Account**. In **Connected accounts**, find **Slack** and select **Set up**.

  width={594}
/>

</Step>
<Step>

The **Manage Slack** dialog opens. Select **Add Slack app**.

<ThemeImage

  alt="Manage Slack dialog showing No Slack apps yet and an Add Slack app button"
  width={672}
/>

</Step>
<Step>

In Slack, open **Basic Information → App Credentials**. Select **Show** next to each secret, then copy the values into LibreChat:

| Slack field | LibreChat field |
| --- | --- |
| App ID | **Slack app ID** |
| Client ID | **Client ID** |
| Client Secret | **Client secret** |
| Signing Secret | **Signing secret** |

**Name** is optional. It labels the app inside LibreChat and in the Agent Builder's bot picker; it does not rename the bot in Slack.

Select **Save**. The app appears in the list with **Add to workspace** and a gear button for its connection settings.

  width={672}
/>

</Step>
</Steps>

The client secret and signing secret are encrypted in the LibreChat database. They are never shown again; leave a secret blank when editing the app to keep its saved value.

## 3. Configure the callback URLs

Slack needs three URLs: one to finish the installation, one to deliver events, and one for button clicks. Select the gear button, **Connection settings**, to see them for this app.

<ThemeImage
  light="/images/features/agent_channels/connection-settings-light.png"
  dark="/images/features/agent_channels/connection-settings-dark.png"
  alt="Connection settings dialog listing the OAuth redirect URL, Events URL and Interactivity URL, each with a copy button"
  width={576}
/>

Copy each one into the matching place in your Slack app:

| LibreChat value | Where it goes in Slack |
| --- | --- |
| OAuth redirect URL | **OAuth & Permissions → Redirect URLs**. Select **Add New Redirect URL**, paste, then **Save URLs**. |
| Events URL | **Event Subscriptions**. Turn on **Enable Events**, paste it into **Request URL**, and wait for **Verified**. |
| Interactivity URL | **Interactivity & Shortcuts**. Turn on **Interactivity**, paste it into **Request URL**, then **Save Changes**. |

Make sure **Socket Mode** is off in **Settings → Socket Mode**. Organization workspaces always use HTTPS callbacks.

<Callout type="warning" title="Copy the full URLs">
The Events and Interactivity URLs end with your tenant and the app ID (for example `/slack/events/_/A0123456789`). Copy them exactly, including any base path. Slack can only verify the Events URL while the gateway is running and reachable from the internet.
</Callout>

## 4. Add bot permissions

In **OAuth & Permissions → Scopes → Bot Token Scopes**, add these seven scopes:

```text
app_mentions:read
chat:write
reactions:read
reactions:write
files:write
im:write
im:history
```

Do not add user token scopes. LibreChat rejects an installation that is missing any of these bot scopes. The [Slack overview](/docs/features/agent_channels/slack#slack-app-permissions) explains what each one is for.

## 5. Subscribe to events and enable direct messages

<Steps>
<Step>

In **Event Subscriptions → Subscribe to bot events**, add the following events, then select **Save Changes**:

- `app_mention`
- `message.im`
- `reaction_added`
- `reaction_removed`
- `app_uninstalled`
- `tokens_revoked`

</Step>
<Step>

In **App Home → Show Tabs**, turn on the **Messages Tab** and check **Allow users to send Slash commands and messages from the messages tab**. This lets people message the bot directly.

</Step>
<Step>

Leave token rotation off under **OAuth & Permissions**, and do not enable organization-wide installation. LibreChat does not support rotating tokens or Enterprise Grid organization-wide installs.

</Step>
</Steps>

To show Slack's native agent status and Stop button as well, follow [native agent sessions](/docs/features/agent_channels/slack/using_slack#native-agent-sessions) after this guide.

## 6. Install the app

<Steps>
<Step>

Back in LibreChat's **Manage Slack** dialog, select **Add to workspace**. Slack's installation page opens in a new window, and LibreChat shows **Connecting to Slack…** with a **Cancel** button.

</Step>
<Step>

In Slack, choose the workspace and select **Allow**. Your workspace's app approval policy still applies, so a Slack admin may need to approve the request first.

</Step>
<Step>

When the window closes, the workspace appears under the app with a **Connected** badge.

<ThemeImage
  light="/images/features/agent_channels/manage-slack-connected-light.png"
  dark="/images/features/agent_channels/manage-slack-connected-dark.png"
  alt="Manage Slack dialog showing the Acme Inc workspace connected under the Acme Assistant app, with manage access, connection settings, reconnect and disconnect buttons"
  width={672}
/>

</Step>
</Steps>

If the installation fails, LibreChat explains why. The most common causes are listed in [Troubleshooting](/docs/features/agent_channels/slack/troubleshooting#installation-errors). Select **Add to workspace** again to retry, or **Cancel** to abandon a pending attempt.

Each registered app can be active in one workspace at a time. To connect a second workspace, create and register a second Slack app.

## 7. Grant bot management access

Agent owners who are not administrators need management access to the bot before they can assign their agents to it. Select the people icon, **Manage access**, on the workspace row, search for each person, and select **Save**.

<ThemeImage
  light="/images/features/agent_channels/manage-bot-access-light.png"
  dark="/images/features/agent_channels/manage-bot-access-dark.png"
  alt="Manage bot access dialog with Alex Morgan added as a bot manager"
  width={512}
/>

Bot management does not grant permission to share agents, and people who only talk to the bot do not need it. See [Security and permissions](/docs/features/agent_channels/security#bot-managers).

You are done. Back in **Settings → Account**, the Slack row now shows the number of connected workspaces.

<ThemeImage
  light="/images/features/agent_channels/settings-slack-connected-light.png"

  alt="Slack row in Account settings showing Connected workspaces: 1 and a Manage button"

/>

Next, [assign an agent](/docs/features/agent_channels/slack/assign_agents) to the bot.

## Manage apps and workspaces

All of these actions are in **Settings → Account → Slack → Manage**.

<Accordions type="single" collapsible>
<Accordion title="Edit an app's credentials">

Select the pencil button on the app. Leaving a secret blank keeps its saved value; if you change the client ID, enter the matching client secret too. To use a different App ID, register a new app instead.

</Accordion>
<Accordion title="Change scopes or events">

After changing permissions in Slack, select **Reconnect** on the workspace and approve the new grant. Existing tokens do not gain new scopes until the app is reinstalled. Reconnecting an active installation updates its grant and keeps its bot managers.

</Accordion>
<Accordion title="Disconnect a workspace">

Select **Disconnect workspace** on the workspace row and confirm. LibreChat stops using that installation, but the app stays installed in Slack; uninstall it there if you no longer need it.

After disconnecting, **Remove workspace** deletes the entry from the list. Installing the app again creates a new installation, so you will need to set up its bot managers and agent assignments again.

</Accordion>
<Accordion title="Remove an app registration">

Disconnect its workspace first, then select the trash button, **Remove app**, and confirm. This deletes the saved credentials from LibreChat; the app itself remains in Slack.

</Accordion>
</Accordions>

Removing the account that registered the app does not delete the organization's installation.
