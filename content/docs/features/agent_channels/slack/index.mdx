Talk to a LibreChat agent from Slack: mention it in a channel, message it directly, and approve its tool calls without leaving the conversation. Each person links their own LibreChat account once, and the agent then works with their permissions.

<Callout type="warning" title="Beta">
The Slack integration needs a running [channel gateway](/docs/features/agent_channels/deployment) and a transaction-capable database. Ask your LibreChat operator whether it is enabled before you start.
</Callout>

<Callout type="info" title="Operators start here">
The gateway must be running before anything on these pages works. Follow [Deploy the gateway](/docs/features/agent_channels/deployment) first.
</Callout>

## Choose a setup path

<Cards num={2}>
  <Card title="Organization workspaces" href="/docs/features/agent_channels/slack/organization_setup" icon={<Building2 />} arrow>
    Recommended. An administrator registers your organization's Slack app once, then agent owners assign agents to it from the Agent Builder. One bot can serve a default agent and a different agent per channel.
  </Card>
  <Card title="Manual connection" href="/docs/features/agent_channels/slack/manual_setup" icon={<Wrench />} arrow>
    Create a dedicated Slack app for one agent from a generated manifest. Works with Socket Mode, so the gateway needs no public URL, but each connection runs its own gateway process.
  </Card>
</Cards>

Your operator decides which path is available. Organization workspaces are enabled with `SLACK_WORKSPACES_ENABLED=true`; otherwise the Agent Builder offers the manual setup.

| | Organization workspaces | Manual connection |
| --- | --- | --- |
| Set up by | An organization administrator in **Settings → Account → Slack** | An agent owner in the Agent Builder |
| Slack apps | Existing app, registered with its credentials | New app per agent, created from a manifest |
| Agents per bot | One default agent plus one per channel | One |
| Who can use it | Every member who links their account | Every member, or only the connection owner |
| Gateway | One shared gateway, public HTTPS | One gateway per connection, Socket Mode or HTTPS |
| Slack workspaces | One active workspace per registered app | The workspace you install the app in |

## Who does what

<Steps>
<Step>

**Operator** runs the gateway and enables the required permissions. [Deploy the gateway](/docs/features/agent_channels/deployment).

</Step>
<Step>

**Administrator** registers the Slack app, installs it, and grants bot management access. [Connect a Slack workspace](/docs/features/agent_channels/slack/organization_setup).

</Step>
<Step>

**Agent owner** assigns an agent to the bot, as a default or for a specific channel, and grants Remote Access to its users. [Assign agents](/docs/features/agent_channels/slack/assign_agents).

</Step>
<Step>

**Every participant** links their account the first time and then asks away. [Use agents in Slack](/docs/features/agent_channels/slack/using_slack).

</Step>
</Steps>

## What the integration supports

| Capability | Supported | Notes |
| --- | --- | --- |
| Mentions in channels | Yes | In any channel the bot has been invited to. |
| Direct messages | Yes | Requires the app's **Messages** tab. |
| Follow-ups in a thread | Yes | In channels, mention the bot in the thread reply. |
| Tool approvals and agent questions | Yes | Private to the requester. Sign-ins open LibreChat in the browser. |
| Stop a running request | Yes | Only the requester can stop their request. |
| Code, tables, links, and files in answers | Yes | Long answers are split, very long ones are shortened with a notice. |
| Charts, cards, and carousels | Yes | With the [rich message format](/docs/features/agent_channels/rich_messages). |
| Feedback reactions | Yes | 👍 and 👎 on a reply, when feedback collection is enabled. |
| Slack native agent status and Stop | Optional | See [native agent sessions](/docs/features/agent_channels/slack/using_slack#native-agent-sessions). |
| Files and images sent to the bot | No | Only message text reaches the agent. A message with an attachment may be ignored entirely. |
| Reading earlier thread messages | No | The agent sees the message that mentions it. |
| Slash commands, App Home, shortcuts | No | |
| Enterprise Grid organization-wide installs | No | Install per workspace, with token rotation off. |

## Slack app permissions

Both setup paths use the same bot permissions. The manual manifest includes them automatically; for an organization app you add them yourself.

| Bot token scope | Why it is needed |
| --- | --- |
| `app_mentions:read` | Receive messages that mention the bot |
| `chat:write` | Post progress messages and answers |
| `im:history` | Receive direct messages sent to the bot |
| `im:write` | Open a direct conversation with a person when needed |
| `files:write` | Upload files the agent returns |
| `reactions:read` | Receive 👍 and 👎 feedback on replies |
| `reactions:write` | Add optional progress reactions |

| Bot event | Why it is needed |
| --- | --- |
| `app_mention` | A person mentioned the bot |
| `message.im` | A person sent the bot a direct message |
| `reaction_added`, `reaction_removed` | Feedback on a reply changed |
| `app_uninstalled`, `tokens_revoked` | The app was removed from Slack (organization workspaces) |
| `agent_session_stopped` | Slack's own Stop button was used (optional native sessions) |

No user token scopes are needed. LibreChat checks the granted scopes during installation and rejects an install that is missing any of the seven above.
