Find your symptom below. Most problems come from one of three places: the Slack app's settings, the gateway's reachability, or a missing LibreChat permission.

## Quick checks

Before digging in, confirm these five things. Together they explain most "the bot does nothing" reports.

1. The gateway is running and its `/readyz` endpoint returns `200`. See [Verify the gateway](/docs/features/agent_channels/deployment#verify-the-gateway).
2. The bot was invited to the channel (`/invite @your_bot`).
3. An agent is assigned to the bot, and the connection is **Active**.
4. The person's role has the **Agents** and **Remote Agents** use permissions, and they have [Remote Access](/docs/features/agent_channels/security#remote-access-to-the-agent) to the agent.
5. The person has linked **and confirmed** their account.

## Setup and installation

<Accordions type="multiple">
<Accordion title="The Channels section or the Slack row is missing">

- **Channels in the Agent Builder** appears only when Channels are enabled, your role has the Remote Agents use permission, and you can share the agent. New agents must be saved first.
- **Slack in Settings → Account** appears only when organization workspaces are enabled (`SLACK_WORKSPACES_ENABLED=true`) or a workspace is already connected.
- **Add Slack app** is shown only to administrators with the `access:admin` and `manage:agents` capabilities. Others see a note asking an administrator to connect workspaces.

</Accordion>
<Accordion title="Slack will not verify the Events URL">

Slack sends a test request when you paste the Events URL. It fails when:

- The gateway is not running, or not reachable from the internet over HTTPS with a trusted certificate.
- Your proxy does not forward `/slack/events/` and `/slack/interactions/` to the gateway, or strips the path after them.
- The URL was shortened. Copy it from **Connection settings** exactly, including the tenant and app ID at the end.
- The **Signing secret** saved in LibreChat belongs to a different app. Edit the app and enter it again.
- The server clock is off by more than five minutes. Signatures are rejected outside that window; synchronize the clock instead of loosening the check.

</Accordion>
<Accordion title="Installation errors" id="installation-errors">

When an installation fails, LibreChat shows **Authentication Failed** with one of these messages:

| Message | Fix |
| --- | --- |
| This Slack app is already connected to a workspace. | Each app supports one active workspace. Disconnect it first, or register another app for the second workspace. |
| This Slack installation is not supported. | Turn off token rotation and install the app to a single workspace, not organization-wide on Enterprise Grid. |
| The Slack app is missing required permissions. | Add all seven [bot scopes](/docs/features/agent_channels/slack/organization_setup#4-add-bot-permissions), then install again. |
| Choose the same Slack workspace when reconnecting. | Reconnect picked a different workspace. To add another workspace, start a new connection with another app. |
| This connection attempt is no longer current. | The install took too long (10 minutes by default) or was replaced. Start again from **Settings → Account → Slack**. |
| An organization administrator with agent management permission can connect and disconnect workspaces. | Your account lacks the `access:admin` and `manage:agents` capabilities. |
| Agent channels require a database with transaction support. | The operator needs to move to a MongoDB replica set. See the [database requirement](/docs/features/agent_channels/deployment#database-requirement). |

</Accordion>
<Accordion title="No Slack bots are available when assigning an agent">

The bot picker lists only connected workspaces whose bot you can manage. Ask an administrator to [grant you bot management access](/docs/features/agent_channels/slack/organization_setup#7-grant-bot-management-access), or to finish connecting the workspace.

</Accordion>
<Accordion title="Activation fails for a manual connection">

- **Invalid bot token**: copy the **Bot User OAuth Token** (`xoxb-`) again after installing the app; reinstalling issues a new one.
- **Signing secret required**: webhook transport needs the app's signing secret.
- The app ID and bot token must come from the same Slack app.

</Accordion>
</Accordions>

## The bot does not respond

<Accordions type="multiple">
<Accordion title="Nothing happens at all">

- The bot is not in the channel. Invite it with `/invite @your_bot`.
- Your thread reply did not mention the bot. In channels, every message to the agent needs `@your_bot`.
- The message carried a file or image, or had no text after the mention. Such messages can be ignored entirely; send your question as a separate text-only message.
- Organization apps: **Event Subscriptions** is off, an event is missing, or **Socket Mode** is on. Socket Mode must be off for organization workspaces.
- Manual connections: the gateway for that connection is not running. Ask your operator to check its logs and readiness.

</Accordion>
<Accordion title="No agent is configured for this Slack conversation">

The bot has no default agent and no assignment for this channel. Ask an agent owner to [assign an agent](/docs/features/agent_channels/slack/assign_agents).

</Accordion>
<Accordion title="This thread's agent connection is no longer available">

The agent that started this thread was unassigned, disabled, or deleted. Start a new thread to reach the agent that is assigned now.

</Accordion>
<Accordion title="Direct messages do not work">

In the Slack app, open **App Home** and turn on the **Messages Tab** with **Allow users to send messages**. Organization apps also need the `message.im` event and the `im:history` scope; reinstall after adding them.

</Accordion>
</Accordions>

## Account linking

<Accordions type="multiple">
<Accordion title="The browser says One more step in Slack">

That is expected. Return to Slack and select **Confirm account** in the bot's private message, from the same Slack account. If the message is gone or expired, mention the bot again for a fresh prompt.

</Accordion>
<Accordion title="This link can't be used">

The link expired (after 10 minutes by default), was replaced by a newer prompt, or the connection changed. Mention the bot again to get a new link.

</Accordion>
<Accordion title="This Slack identity is already linked or awaiting confirmation">

Your Slack account is already linked to a LibreChat account for this connection, or waiting for you to confirm. Confirm it in Slack, or disconnect it in **Settings → Account → Your channel account links** and link again.

</Accordion>
<Accordion title="Your account is linked, but this channel has not authorized this request">

Your link works, but LibreChat refused the request. Check that:

- Your role has the **Agents** and **Remote Agents** use permissions.
- You have **Remote Access** to the agent (the globe button in the Agent Builder footer). Normal sharing is not enough.
- Your account is active, and any required two-factor enrollment is complete.
- For a manual connection in **Channel owner only** mode, you are the connection owner.

</Accordion>
<Accordion title="I have to link again">

Links end when they expire (30 days by default), when you disconnect them, or when the connection is disabled, reactivated, or changes its identity mode. Link again and send a new request.

</Accordion>
</Accordions>

## Running requests

<Accordions type="multiple">
<Accordion title="Stop, Review request, or Confirm account does nothing">

These buttons use Slack's **Interactivity** callback, which is separate from Events. Turn on **Interactivity** in the Slack app and save the exact **Interactivity URL** from **Connection settings**. Also check that you are the person who sent the request: only they can use its controls.

</Accordion>
<Accordion title="The review is unavailable or expired">

Approvals expire after 24 hours by default, and a newer action may have replaced the one you clicked. Check the latest reply in the thread. If the server restarted while an approval was pending, the request is held instead of running the tool. Check the original result before asking again.

</Accordion>
<Accordion title="The status says it is unavailable after a restart">

LibreChat restarted while the request was running, and its final state could not be confirmed. Check whether the work was done before asking again, so a tool does not run twice. If it stays unavailable, your operator can reconcile it using the [recovery procedure](/docs/features/agent_channels/deployment/reference#delivery-recovery).

</Accordion>
<Accordion title="Something went wrong while talking to the agent">

The run failed in LibreChat, for example because of a model or tool error. Try again; if it keeps failing, test the same agent in LibreChat itself and share the run ID from the reply footer with your administrator.

</Accordion>
<Accordion title="The reply was shortened, or attachments are missing">

Answers are split into several messages up to a limit (`maxDeliveryParts`), and very long ones are shortened with a notice. Files are limited to 5 per answer and 10 MB each by default (`artifactMaxFiles`, `artifactMaxBytes`). The full answer is always kept in LibreChat.

</Accordion>
<Accordion title="New permissions do not take effect">

After you add scopes or events in Slack, reinstall the app. For organization apps, select **Reconnect** on the workspace in LibreChat and approve the new grant. Existing tokens never gain new scopes on their own.

</Accordion>
</Accordions>

## For operators

| Symptom | Check |
| --- | --- |
| Gateway calls to LibreChat return `401` | `CHANNEL_SERVICE_TOKEN` is identical in LibreChat and the gateway, at least 32 characters, and `LIBRECHAT_INTERNAL_URL` points to the right instance. |
| Gateway never becomes ready | Read its startup logs. Common causes: the transport in `librechat.yaml` does not match `SLACK_TRANSPORT`, a manual connection is not active, or the Socket Mode `SLACK_APP_TOKEN` belongs to another app. |
| LibreChat refuses to start with "Invalid shared Slack setup" | `DOMAIN_SERVER`, `DOMAIN_CLIENT`, and `SLACK_GATEWAY_URL` must be public HTTPS URLs, not localhost or private addresses. |
| The gateway exits at startup mentioning a removed setting | `SLACK_NATIVE_SESSIONS`, `SLACK_LIFECYCLE_REACTIONS`, and `SLACK_SIGNATURE_TOLERANCE_SECS` are no longer environment variables. Move them to `endpoints.agents.channels` in `librechat.yaml`. |
| Slack retries events, or the gateway returns `503` | The gateway is over capacity or LibreChat is unavailable. Slack redelivers; check API health and `slackApp.gateway.ingressConcurrency`. |

When you report a problem, include the run ID from the reply footer, the time, the gateway's recent logs, and the output of its `/readyz` endpoint.
