Agent Channels connect a LibreChat [agent](/docs/features/agents) to a messaging app. People mention the agent or send it a direct message, and it answers in place, with the same instructions, tools, and approval rules it has in LibreChat.

Every request runs as the person who sent it. Before the agent answers someone for the first time, they link their LibreChat account. From then on, the agent uses that person's permissions, files, and tool connections, never another participant's.

<Callout type="warning" title="Beta and opt-in">
Agent Channels are off by default. An operator has to run a separate channel gateway and use a database with transaction support before anyone can connect an agent. See [Deploy the gateway](/docs/features/agent_channels/deployment).
</Callout>

## Supported platforms

| Platform | Status | What you can connect |
| --- | --- | --- |
| [Slack](/docs/features/agent_channels/slack) | Beta | Organization-owned Slack apps managed in LibreChat, or a Slack app you configure for a single agent |

Slack is the only supported platform today. The concepts on this page and in [How it works](/docs/features/agent_channels/how_it_works) apply to every platform, while each platform's setup lives in its own section.

The gateway is a small service that runs next to LibreChat. It speaks Slack's protocol on one side and a private LibreChat API on the other, and it never connects to your database directly. [How it works](/docs/features/agent_channels/how_it_works) follows a message through each step.

## Get started

Setup is split across a few roles. In a small deployment, one person may do all of them.

<Steps>
<Step>

**Operator: deploy the gateway.** Run the channel gateway, enable a transaction-capable database, and turn on the **Remote Agents** permission (the same permission the [Agents API](/docs/features/agents_api) uses) for the roles that will use the bot. See [Deploy the gateway](/docs/features/agent_channels/deployment).

</Step>
<Step>

**Administrator: connect Slack.** Register your organization's Slack app in LibreChat and install it in your workspace. See [Connect a Slack workspace](/docs/features/agent_channels/slack/organization_setup).

</Step>
<Step>

**Agent owner: assign an agent.** Choose which agent answers by default, or in a specific channel, and grant **Remote Access** to the people who will use it. See [Assign agents](/docs/features/agent_channels/slack/assign_agents).

</Step>
<Step>

**Everyone: link an account and start asking.** The bot sends a private link the first time someone uses it. See [Use agents in Slack](/docs/features/agent_channels/slack/using_slack).

</Step>
</Steps>

## Key terms

| Term | Meaning |
| --- | --- |
| Channel gateway | The service that receives events from the messaging app and delivers the agent's replies. It runs separately from LibreChat. |
| Connection | The link between one agent and one bot. It has a status: pending, active, disabled, or deleting. |
| Assignment | Where a bot uses an agent: by **default** for direct messages and mentions, or in one **specific channel**. |
| Account link | A person's confirmed link between their messaging identity and their LibreChat account. It expires and can be revoked. |
| Run | One request from one person, from the moment it arrives until the reply is delivered. |

## Limits at a glance

- **Text only in, rich answers out.** The agent receives the text of the message that mentions it. Files and images are never passed to the agent, and a message that carries an attachment may be ignored entirely, so ask in a separate text message. The agent can still send files back.
- **No shared thread history.** The agent does not read earlier messages in a thread. Each person's follow-ups continue their own conversation with the agent.
- **One request at a time per person and thread.** A second request from the same person in the same thread waits until the first finishes.
- **Permissions are not granted by linking.** People still need the Agents and Remote Agents permissions, and **Remote Access** to the agent. See [Security and permissions](/docs/features/agent_channels/security).
