Um Plugin de Agente é uma pasta no servidor do LibreChat que reúne [Skills](/docs/features/skills), [servidores MCP](/docs/features/mcp) e hooks de comando opcionais que pertencem juntos. Um operador coloca a pasta no diretório de plugins e reinicia o LibreChat; não há nada para instalar pela interface. O LibreChat segue o formato de pacote Agent Plugins `1.0.0`, de código aberto, para que um mesmo pacote possa ser compartilhado com outras ferramentas que oferecem suporte a ele.

Os Plugins de Agente são experimentais. O formato do pacote e o comportamento podem mudar.

## O que os usuários veem [#what-users-see]

Os usuários nunca veem um plugin como tal. Eles veem o que ele contém:

- Suas Skills aparecem na lista de Skills junto com as demais skills. Elas são somente leitura, seguem as permissões habituais de Skills e podem ser ativadas ou desativadas com **Disponível para o agente**, como qualquer outra skill.
- Seus servidores MCP aparecem na Biblioteca de Ferramentas e podem ser adicionados aos agentes como os servidores definidos em `librechat.yaml`.
- Seus hooks são executados no servidor em pontos específicos de uma execução do agente, como antes de uma chamada de ferramenta ou quando a execução é encerrada. Um hook pode bloquear uma chamada de ferramenta, adicionar contexto ao prompt ou interromper uma execução, e o usuário vê apenas o efeito.

Se o nome de uma skill ou de um servidor MCP colidir com um definido em outro lugar, a outra definição prevalece: uma skill no diretório de skills da implantação independente tem precedência sobre uma skill de plugin, e um servidor definido em `librechat.yaml` tem precedência sobre um servidor de plugin.

## O que um plugin pode conter [#what-a-plugin-can-contain]

Uma pasta de plugin contém um manifesto `plugin.json` e qualquer um dos seguintes:

- `skills/`, uma pasta por skill, cada uma com um `SKILL.md`.
- `mcp.json`, definições de servidores MCP. Servidores locais (`stdio`) são executados a partir da pasta do plugin e recebem seu próprio diretório de dados persistentes.
- `ai.librechat/hooks/hooks.json`, hooks de comando. Estes são executados como processos no host da API e ficam desativados, a menos que o operador os habilite.

Cada parte é carregada de forma independente, então um `mcp.json` com problemas não impede que as skills do plugin sejam carregadas. Os problemas são registrados nos logs de inicialização.

## Configuração [#setup]

Os plugins são carregados de `./plugin` na raiz do projeto por padrão, e os hooks de comando vêm desativados por padrão. Consulte [Configuração de Agent Plugins](/docs/configuration/agent_plugins) para as configurações de diretório, o layout do pacote, as regras de validação de manifesto e MCP e o contrato de execução dos hooks.
