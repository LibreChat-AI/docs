「Upload as Text」は、ファイルからテキストを抽出してメッセージに追加するため、モデルは文書を検索するのではなく全体を読み込みます。ファイルがコンテキストに収まるほど小さく、すべての行を確実に考慮させたい場合に使用してください。たとえば、契約書、ログ、ソースコード、スプレッドシートのエクスポートなどが該当します。

## ファイルの添付 [#attaching-a-file]

[メッセージ作成欄](/docs/features/composer#add-files)で**+**をクリックし、**Attach**の下にある**From Local Computer**を選択します(サーバーに設定されている場合は**From SharePoint**も選択できます)。ファイルをメッセージ作成欄にドラッグ&ドロップすることもできます。保存先を指定する必要はありません。LibreChatが各ファイルを確認し、モデルにどのように渡すかを決定します。

- テキスト、コード、Markdown、CSV、JSON、Word、Excel ファイルは、抽出されたテキストとして送信されます。
- 画像、音声、動画、PDFは、そのモデルのプロバイダーが受け付ける場合、直接モデルに送られます。PDFを受け付けないプロバイダーの場合、LibreChatはPDFからテキストを抽出して送信します。

パレットで **File Search** または **Run Code** を有効にしている場合、それらのツールは実行時にファイルが実際に必要になったときにのみファイルを受け取ります。

管理者が古いアップロード先メニューを有効にしている場合は、明示的に選択します。**Upload as Text** は **Upload to Provider**(または **Upload Image**)および **Upload for File Search** と並んで表示されます。これらの一部は **More upload options** の中にあります。このモードでチャットに複数のファイルをドロップすると、同じ選択肢を含む **Select Upload Type** が開きます。

複数のファイルを一度に添付すると、重複しているファイルや1ファイルあたりのサイズ上限を超えたファイルはスキップされ、その旨が通知で名前付きで表示されます。残りのファイルはアップロードされます。ファイル数と合計サイズの上限は、残ったファイルに対して引き続き適用されます。残りのバッチがどちらかの上限を超える場合は、そのバッチのファイルは一切アップロードされません。

## 長いテキストの貼り付け [#pasting-long-text]

2,500文字を超える内容をメッセージ入力欄に貼り付けると、LibreChatはその貼り付けたテキストを `pasted-text.txt`(続けて `pasted-text-2.txt` など)という名前のテキストファイルに変換し、テキストとして添付します。その際、**Attached as text** と表示されます。メッセージ入力欄は読みやすい状態に保たれ、モデルには貼り付けた内容がそのまま渡されます。ファイルのチップを選択すると**Edit pasted text**で編集でき、**Move back into message**を使えば再びメッセージ内にインラインで戻すことができます。

エージェントの質問フォームへの貼り付けはインラインのまま残り、アップロードに失敗した場合、LibreChat はテキストをメッセージ入力欄に戻します。長い貼り付けをインラインのまま保つには、**Settings** > **Chat** > **Sending** で **Paste long text as a file** をオフにしてください。この設定はお使いのブラウザに保存されます。

## テキストの抽出方法 [#how-the-text-is-extracted]

LibreChat は以下を順番に試し、最初に該当するものを使用します:

1. OCR は、管理者が OCR サービスを設定しており、かつファイルの種類が OCR の対象（画像、PDF、Office ドキュメント、EPUB、OpenDocument）である場合に使用されます。詳しくは [OCR](/docs/features/ocr) を参照してください。
2. PDF、DOCX、XLS、XLSX、ODT、ODS ファイル（サイズ 15 MB まで）向けの組み込みドキュメントパーサーです。テキストレイヤーのみを読み取ります。
3. 音声ファイルの音声テキスト変換（管理者が STT を設定している場合）
4. プレーンテキストとして読み取れるものはすべてテキストとして扱います。ソースコード、Markdown、CSV、JSON、YAML、HTML などが該当します。

従来の`.doc`、PowerPoint、EPUB ファイルは組み込みのパーサーでは対応していません。これらのファイルには OCR が必要です。管理者が設定している場合は、RAG API のテキスト抽出を利用することもできます。

スキャンされたPDFやページの写真にはテキストレイヤーがないため、OCRを使わなければ抽出できる内容がなく、アップロードはOCRサービスが必要であることを示すメッセージとともに失敗します。**Upload to Provider**で送信すると、代わりにビジョンモデルが画像を直接読み取ることができます。

## モデルがファイルのどの程度を参照するか [#how-much-of-the-file-the-model-sees]

各ファイルのテキストは、ファイルトークン上限(デフォルトでは100,000トークン)で切り捨てられます。上限を超えた部分は警告なしに破棄されます。そのため、長い文書の末尾が回答に反映されていないように見える場合、この上限が原因である可能性が高いです。会話ごとにモデルパラメータの **File Token Limit** で上限を下げたり上げたりできます。ただし上限を大きくすると、そのファイルを含む各メッセージのトークン消費量が増えます。

LibreChatがファイルの元のデータではなく、抽出されたテキストのみを保持している場合、そのファイルをダウンロードすると、そのテキストが`.txt`ファイルとして得られます。

大きなドキュメントや多数のファイルを扱う場合は、通常は[ファイル検索](/docs/features/rag_api)の方が適しています。ファイル全体を毎回送信するのではなく、関連する箇所だけを取得するためです。

## セットアップ [#setup]

「テキストとしてアップロード」は、設定なしですぐに使えます。明示的な**テキストとしてアップロード**オプションは、エージェントの`context`機能に依存しており、この機能はデフォルトで有効です。機能リストをカスタマイズする管理者は、この機能を維持する必要があります。抽出、トークン上限、アップロードメニューの表示形式は[`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config)で、OCRは[`ocr`設定](/docs/configuration/librechat_yaml/object_structure/ocr)で管理者が制御します。
