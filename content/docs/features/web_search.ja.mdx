Web検索は、モデルに`web_search`ツールを提供します。現在の情報が必要な質問の場合、モデルが検索クエリを作成し、LibreChatが結果を取得して上位のページを読み込み、使用した情報源とともに回答を返します。

## チャットで有効にする [#turn-it-on-in-a-chat]

[message composer](/docs/features/composer) の **+** をクリックしてパレットを開き、**Tools** セクションの **Web Search** を選択してください。オンになっている間、コンポーザーにチップとして表示されます。チップを削除するか、パレットで再度選択するとオフになります。オフの状態でもチップがコンポーザーに残るように固定することもできます。

Web検索を有効にしていても、メッセージに検索が必要かどうかはモデルが自ら判断します。「最新の Node.js リリースで何が変わりましたか?」と尋ねると通常は検索が実行されますが、段落の書き直しを依頼した場合は実行されないことが一般的です。

エージェントの場合、ウェブ検索はエージェントビルダーで有効にできる機能です。そのエージェントとチャットする人は、何も切り替えることなくこのツールを利用できます。

## 回答に表示される内容 [#what-you-see-in-the-answer]

ツールの実行中、メッセージには進行状況が表示されます(「Searching the web」、続いて「Reading results」)。完了すると **Searched the web** に折りたたまれます。展開すると見つかったページを確認でき、その横にある **Search details** ボタンを使うと、モデルが送信したクエリを確認できます。

インライン引用は本文中で該当するページを指しているため、主張を元のページと照らし合わせて確認できます。複数のエージェントが並べて回答する場合、回答の上にある **Sources** の行にも結果がまとめて表示されます。検索結果にニュースや画像が含まれている場合は、**All** に加えて **News** タブと **Images** タブも表示されます。

## 検索の実行方法 [#how-a-search-runs]

各検索は最大3つのサービスを経由します:

- 検索プロバイダーは、結果のリストを返します。対象は Serper、SearXNG、Tavily、または Keenable です。
- スクレイパーは、それらの検索結果の背後にあるページを取得し、そのテキストを抽出します。対象となるのは Firecrawl、Serper Scrape、Tavily Extract、Keenable Fetch のいずれかです。
- リランカー(Jina または Cohere)は、クエリに最も関連性の高いパッセージを選び出します。リランキングは **None** に設定すると、この工程をスキップできます。

モデルに渡されるのは、抽出された本文の一部だけであり、ページ全体が渡されるわけではありません。タイムアウトしたり、スクレイピングをブロックしたりするページはスキップされるため、回答が引用する情報源は、検索で返された件数よりも少なくなる場合があります。

セーフサーチは、デフォルトで「moderate」に設定されています。管理者はすべてのユーザーに対してこのレベルを引き上げたり引き下げたりできます。ただし Tavily は例外で、管理者が Tavily 独自のセーフサーチオプションを有効にした場合にのみフィルタリングが行われます。

## 独自のAPIキーの追加 [#adding-your-own-api-keys]

管理者がすべてのサービスのキーを用意していない場合、**Web Search** をオンにすると、キーの入力を求めるダイアログが開きます。このダイアログには、管理者がユーザーに任せたサービスごとのセクションがあり、対象は **Search Provider**、**Scraper**、**Reranker** のうち該当するものです。各セクションでサービスを選択し、キーを入力して (各入力欄には、キーを取得できる場所へのリンクがあります)、**Save** をクリックしてください。SearXNG の場合はインスタンスの URL の入力が求められ、キーは任意です。Keenable はキーなしでも動作し、キーを追加するとレート制限が引き上げられるだけです。

キーはお客様のアカウントに保存され、お客様の検索にのみ使用されます。後でプロバイダーを変更したりキーを置き換えたりする場合は、パレットを開き、**Web Search** の行にある **Configure**(歯車アイコン)をクリックしてください。保存済みのキーは、同じダイアログの **Revoke** で削除できます。管理者がサーバー上のすべてのキーを設定している場合、ダイアログも歯車アイコンも表示されません。

管理者がサーバーに設定したキーが、入力したURLと組み合わされることはありません。管理者がFirecrawlまたはSearXNGのキーを設定している場合にこれらのサービス用に独自のURLを入力したときは、独自のキーも入力してください。そうしないと、Firecrawlは入力したURLを無視してデフォルトのエンドポイントを使用し、SearXNGは動作しません。キーを使用しないSearXNGインスタンスでも動作します。キーが関係しない場合は、URLだけで十分です。

## Web Search オプションが表示されない [#web-search-option-is-not-visible]

ウェブ検索の専用ボタンはありません。このオプションは、パレットの **Tools** セクションにのみ表示されます。次の場合には表示されません：

- エージェントとチャットしているか、Assistants エンドポイントを利用しています。エージェントは独自のツールを持つため、Web 検索はエージェントビルダーで有効にします。
- 選択されたモデルスペックは、ツール行を非表示にします。
- お使いのロールには Web Search の権限がありません。そのため、一部のプロバイダーが提供する組み込み検索も利用できなくなります。
- 管理者がエージェントの機能から`web_search`を削除しました。

## セットアップ [#setup]

Web検索はエージェントとチャットでデフォルトで利用可能ですが、結果を返すには検索プロバイダーとスクレイパーが必要です。管理者はサーバー上でキーを設定するか、ユーザーが入力できるように残しておくことができます。プライベートアドレス上のセルフホスト型プロバイダーは、管理者が[`allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers)に列挙するまでブロックされます。プロバイダー、キー、オプションについては[Web Search configuration](/docs/configuration/librechat_yaml/object_structure/web_search)を参照してください。検索プロバイダーをセルフホストする場合は[Setting up SearXNG](/docs/configuration/librechat_yaml/object_structure/web_search#setting-up-searxng)を参照してください。
