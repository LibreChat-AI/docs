Admin Panel は、ブラウザから LibreChat インスタンスを運用するための独立した Web アプリです。ユーザー、グループ、ロールを管理し、各ロールに許可する操作を決め、管理者権限を付与できます。また、`librechat.yaml` を編集して再起動することなく、設定を変更できます(全員向け、または特定のロールやグループ向けのみに変更することも可能です)。

それは独自のURLを持つ個別のサービスで、[LibreChat-AI/admin-panel](https://github.com/LibreChat-AI/admin-panel) で開発されています。独自のデータは一切保持しません。すべての変更はLibreChatの管理APIを経由して行われ、LibreChatのデータベースに反映されます。

## サインイン [#signing-in]

LibreChatアカウントでサインインします。メールアドレスとパスワードを使うか、インスタンスで設定されたシングルサインオン(OpenID ConnectやGoogleなど)を利用します。アカウントには`ADMIN`ロール、またはアカウントに直接、あるいはそのグループやロールを通じて付与された`access:admin`権限が必要です。LibreChatはリクエストごとにこれを確認するため、パネルがアカウントの持つ以上のアクセス権を自分自身に与えることはできません。セッションは、デフォルトでは30分間操作がないと終了します。SSOを使用している場合、パネルはバックグラウンドでLibreChatセッションを更新し、更新のたびにアカウントが停止されていないことと管理者アクセス権を引き続き持っていることを再確認します。アクセス権を失うと、パネルのセッションも終了します。

管理パネルの URL が設定されると、管理者権限を持つユーザーには LibreChat の **設定 > 一般** に **Admin Panel** リンクも表示されます。その他のユーザーには表示されません。

## できること [#what-you-can-do]

サイドバーのセクションは、主な機能に対応しています:

- **ユーザー**: インスタンス上のすべてのアカウントを一覧表示・検索し、ロールで絞り込み、ユーザーをロールに追加・削除できます。(パネルには削除アクションがありますが、現在の LibreChat は管理 API 経由での削除にはまだ対応していません。代わりに delete-user スクリプトを使用してください。)
- **アクセス**: `USER` と `ADMIN` 以外のカスタムロールを作成し、各ロールの機能権限を編集できます。また、グループを作成してメンバーを管理できます。ここで作成したグループやロールは、LibreChat の共有ダイアログで選択できます。
- **設定**: LibreChat の設定をフォームで表示・編集できます。フォームは LibreChat 独自の設定スキーマから生成されるため、パネルを更新しなくても新しい設定項目が自動的に表示されます。
- **Grants**: 個々の管理者機能（ユーザーの管理や設定のセクション編集など）を、フル管理者にすることなく、ユーザー、グループ、またはロールに付与します。

パネルに表示される内容は、各ユーザーの権限によって異なります。たとえば、`interface` セクションのみ管理できるユーザーには、そのセクションだけが表示されます。ロールの閲覧のみ許可されているユーザーはロールを確認できますが、変更はできません。アクセス関連の権限をいずれも持たないユーザーには、そのセクションについてアクセス拒否ページが表示されます。

## 特定のロールとグループの設定 [#configuration-for-specific-roles-and-groups]

ベースプロファイルは全員に適用されますが、それに加えて、単一のロール、グループ、またはユーザーに対して、上書き設定のプロファイルを保存できます。プロファイルには変更した設定のみが保存され、それ以外の設定は継承されます。各プロファイルには優先度があり（ロールプロファイルのデフォルトは10、グループは20、ユーザーは100）、LibreChatはユーザーの設定を構築する際に、`librechat.yaml`とベースプロファイルから開始し、そのユーザーに一致するプロファイルを優先度の低いものから高いものの順に適用します。そのため、デフォルトではユーザープロファイルがグループプロファイルやロールプロファイルよりも優先されます。これにより、インスタンスを追加で用意することなく、研究グループに追加のエンドポイントを提供したり、業務委託者により厳格なインターフェースを提供したりできます。

設定を編集する際に知っておくべきいくつかの事項:

- 変更は `librechat.yaml` と同じルールで検証されます。設定が無効になる編集は拒否され、何も保存されません。アップグレードによって以前に保存された値が無効になった場合、LibreChat はそのフィールドを無視し、その下位の値にフォールバックして警告をログに記録します。そのため、アップグレード後はログを確認してください。
- APIキーや、Web検索、音声、OCR、Langfuse、カスタムエンドポイントなどで入力したその他のシークレットは暗号化されて保存され、保存後は一部が伏せ字(マスク)で表示されます。保存済みのキーの送信先(サーバーやベースURLなど)を変更した場合は、キーを改めて入力する必要があります。
- `${ENV_VAR}` 形式の参照は、LibreChat がすでに認識している変数、またはオペレーターが許可した変数に対してのみ受け付けられます。
- 一部の設定は `librechat.yaml` でのみ管理されます。具体的には、ローカルプロセスを実行する MCP サーバー（`type: stdio`、または `command`、`args`、`env`）と、Langfuse ゲートウェイのヘッダーです。パネルからこれらを追加、変更、削除することはできません。リモートの MCP サーバーは通常どおり管理できます。

機能の権限はオーバーライドではありません。ロールがエージェントやプロンプトなどを使用または共有できるかどうかを決めるスイッチは、ロールそのものの **Access** で編集します。ロール、グループ、機能がどのように組み合わさるかについては、[Access Control](/docs/features/access_control) を参照してください。エージェントごとの使用状況は、LibreChat 内の独立した [Insights](/docs/features/insights) ダッシュボードにあります。

## セットアップ [#setup]

パネルは LibreChat の `docker-compose.yml` および `deploy-compose.yml` 内の `admin-panel` サービスとして提供されており、`.env` に `ADMIN_PANEL_SESSION_SECRET` を設定するまで起動しません。LibreChat v0.8.5 以降が必要です。ポート、専用ドメインでのホスティング、SSO リダイレクト、すべての環境変数、およびパネルが使用する管理 API については、[Admin Panel configuration](/docs/configuration/admin_panel) で説明しています。
