Ein Agent-Plugin ist ein Ordner auf dem LibreChat-Server, der [Skills](/docs/features/skills), [MCP-Server](/docs/features/mcp) und optionale Command-Hooks bündelt, die zusammengehören. Ein Operator legt den Ordner im Plugin-Verzeichnis ab und startet LibreChat neu; über die Benutzeroberfläche muss nichts installiert werden. LibreChat folgt dem offenen Agent-Plugins-Paketformat `1.0.0`, sodass ein Paket auch mit anderen Tools geteilt werden kann, die dieses Format unterstützen.

Agent-Plugins sind experimentell. Das Paketformat und das Verhalten können sich ändern.

## Was Benutzer sehen [#what-users-see]

Benutzer sehen niemals ein Plugin als solches. Sie sehen nur, was es enthält:

- Ihre Skills erscheinen in der Skills-Liste neben anderen Skills. Sie sind schreibgeschützt, unterliegen den üblichen Skills-Berechtigungen und können wie jeder andere Skill mit **Available to agent** ein- oder ausgeschaltet werden.
- Seine MCP-Server erscheinen in der Tool-Bibliothek und können wie in `librechat.yaml` definierte Server zu Agenten hinzugefügt werden.
- Die Hooks laufen auf dem Server an bestimmten Punkten eines Agentenlaufs, etwa vor einem Tool-Aufruf oder wenn der Lauf endet. Ein Hook kann einen Tool-Aufruf blockieren, dem Prompt Kontext hinzufügen oder einen Lauf beenden, und der Benutzer sieht nur die Auswirkung.

Wenn ein Skill- oder MCP-Server-Name mit einem an anderer Stelle definierten Namen kollidiert, gewinnt die andere Definition: Ein Skill im eigenständigen Skills-Verzeichnis der Bereitstellung hat Vorrang vor einem Plugin-Skill, und ein Server in `librechat.yaml` hat Vorrang vor einem Plugin-Server.

## Was ein Plugin enthalten kann [#what-a-plugin-can-contain]

Ein Plugin-Ordner enthält eine `plugin.json`-Manifestdatei sowie optional eines der folgenden:

- `skills/`, ein Ordner pro Skill, jeweils mit einer `SKILL.md`.
- `mcp.json`, MCP-Server-Definitionen. Lokale (`stdio`) Server laufen aus dem Plugin-Ordner heraus und erhalten ihr eigenes persistentes Datenverzeichnis.
- `ai.librechat/hooks/hooks.json`, Command-Hooks. Diese laufen als Prozesse auf dem API-Host und sind deaktiviert, solange der Betreiber sie nicht aktiviert.

Jeder Teil wird für sich geladen, sodass eine fehlerhafte `mcp.json` nicht verhindert, dass die Skills des Plugins geladen werden. Probleme werden in den Startprotokollen gemeldet.

## Einrichtung [#setup]

Plugins werden standardmäßig aus `./plugin` im Projektstammverzeichnis geladen, und Command-Hooks sind standardmäßig deaktiviert. Informationen zu den Verzeichniseinstellungen, dem Paketaufbau, den Validierungsregeln für Manifest und MCP sowie dem Ausführungsvertrag für Hooks finden Sie unter [Agent Plugins configuration](/docs/configuration/agent_plugins).
