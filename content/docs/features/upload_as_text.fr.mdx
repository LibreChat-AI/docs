# Téléverser des fichiers en tant que texte [#upload-files-as-text]

Vous avez toujours voulu donner un PDF, un fichier de code ou une feuille de calcul à l'IA et simplement lui dire _"lis ceci"_ ? L'outil de téléchargement unifié de LibreChat achemine le fichier vers le fournisseur ou extrait automatiquement son texte en fonction de son type et de l'endpoint sélectionné.

Vous joignez un fichier, LibreChat en extrait le texte, et le contenu complet est directement collé dans votre conversation. L'IA peut alors en lire chaque mot — sans plugins, sans bases de données vectorielles, ni services supplémentaires à configurer. Cela fonctionne immédiatement.

<Callout type="info" title="Aucune configuration requise">
  Upload as Text fonctionne immédiatement sur n'importe quelle instance LibreChat. Il utilise une analyse de texte intégrée — vous n'avez pas besoin d'OCR, de pipeline RAG ou de service externe pour commencer.
</Callout>

---

## Comment l'utiliser [#how-to-use-it]

<Steps>
  <Step>
    ### Ouvrir la palette [#open-the-palette]

    Cliquez sur **+** dans le [message composer](/docs/features/composer#add-files). Vous pouvez également faire glisser le fichier dans le composer.
  </Step>
  <Step>
    ### Choisir une source [#choose-a-source]

    Dans la section **Attach**, sélectionnez **From Local Computer**, ou **From SharePoint** lorsqu'il est configuré. Le téléverseur par défaut ne vous demande pas de choisir un modèle ou une destination d'outil.

    Si votre administrateur a activé [`legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), choisissez vous-même la destination : sélectionnez **More upload options**, puis **Upload as Text**.
  </Step>
  <Step>
    ### Choisissez votre fichier [#choose-your-file]

    Sélectionnez le fichier. LibreChat choisit la livraison native par le fournisseur, l'extraction de texte ou le stockage réservé aux outils en fonction du type de fichier et des capacités de l'endpoint.
  </Step>
  <Step>
    ### Posez votre question [#ask-your-question]

    Tapez votre prompt comme d'habitude. Les outils File Search et Code sélectionnés ne reçoivent le fichier que lorsqu'ils en ont besoin.
  </Step>
</Steps>

Lorsque vous sélectionnez plusieurs fichiers, LibreChat ignore les doublons individuels ainsi que les fichiers dépassant la limite de taille par fichier, indique le nom des fichiers ignorés dans une notification, et poursuit le téléchargement des fichiers valides. Les limites de nombre de fichiers et de taille totale par lot s'appliquent toujours aux fichiers restants ; si le lot résultant dépasse l'une ou l'autre de ces limites, l'ensemble du lot est rejeté. Le comportement pour un fichier unique reste inchangé.

<Callout type="warn" title="Vous ne voyez pas l'option ?">
  Avec `legacyFileUploadUX` activé, si **Upload as Text** n'apparaît pas sous **More upload options**, la capacité `context` a peut-être été désactivée par votre administrateur. Elle est activée par défaut, mais si la liste des capacités a été personnalisée, `context` doit être explicitement inclus. Voir la [section de configuration](#the-context-capability) ci-dessous.
</Callout>

## Coller un texte long sous forme de fichier [#paste-long-text-as-a-file]

Dans le compositeur de messages normal, LibreChat peut transformer un collage de plus de 2 500 caractères en une pièce jointe « Téléverser en tant que texte ». Cela permet de ne pas encombrer la zone de saisie avec un long texte tout en fournissant son contenu au modèle via le contexte de la conversation. La première pièce jointe est nommée `pasted-text.txt` ; les pièces jointes de texte collé supplémentaires reçoivent des noms numérotés.

Le paramètre local au navigateur **Coller un texte long en tant que fichier** est activé par défaut sous **Paramètres > Chat > Envoi**. Les collages plus courts et le texte collé pendant que vous répondez à un formulaire **Demander à l'utilisateur** d'un Agent restent intégrés. Si les téléchargements de contexte ne sont pas disponibles, le texte reste également intégré. Si le téléchargement d'une pièce jointe échoue, LibreChat restaure le texte dans le compositeur lorsqu'il peut le faire sans écraser un brouillon plus récent.

Les pièces jointes sous forme de texte collé suivent les mêmes règles de taille de fichier, de jetons et de [`fileTokenLimit`](#token-limits-and-truncation) que les autres fichiers importés en tant que texte (Upload as Text).

## Ce qui se passe en coulisses [#what-happens-under-the-hood]

Lorsqu'un téléchargement est acheminé vers du texte, LibreChat ne déverse pas les octets bruts dans l'invite. Il passe par un pipeline de traitement pour extraire un texte propre et lisible :

1. **Détection du type MIME** — LibreChat vérifie le type de fichier que vous avez téléchargé (PDF, image, audio, code source, etc.) en inspectant son type MIME.
2. **Sélection de la méthode** — En fonction du type de fichier et des services disponibles, il choisit la meilleure méthode d'extraction en utilisant cette priorité :

<Tabs items={["Ordre de priorité", "Exemples de décision"]}>
  <Tabs.Tab>
    | Priorité | Méthode | Quand est-elle utilisée |
|----------|--------|---------------|
| 1ère | **OCR** | Le fichier est une image ou un document numérisé, _et_ l'OCR est configuré |
| 2ème | **STT** (Speech-to-Text) | Le fichier est un audio, _et_ le STT est configuré |
| 3ème | **Analyse de texte** | Le fichier correspond à un type MIME de texte connu |
| 4ème | **Repli** | Aucune des méthodes ci-dessus n'a correspondu — tente l'analyse de texte malgré tout |
  </Tabs.Tab>
  <Tabs.Tab>
    **Un fichier `.pdf` sur une instance avec OCR configuré :**
    → L'OCR se déclenche. Idéal pour les documents numérisés et les mises en page complexes.

    **Un `.pdf` sur une instance par défaut (sans OCR) :**
    → L'analyse de texte le prend en charge. Fonctionne bien pour les PDF créés numériquement.

    **Un fichier Python `.py` :**
    → Analyse de texte directe. Le code source est déjà du texte — aucune conversion nécessaire.

    **Un fichier `.mp3` sur une instance avec STT configuré :**
    → Speech-to-Text le transcrit en texte pour la conversation.

    **Une capture d'écran `.png` sans OCR configuré :**
    → Utilise l'analyse de texte par défaut (résultats limités — envisagez de configurer l'OCR pour les images).
  </Tabs.Tab>
</Tabs>

3. **Troncature de jetons** — Le texte extrait est tronqué à la limite `fileTokenLimit` (par défaut : 100 000 jetons) afin de ne pas dépasser la fenêtre de contexte du modèle.
4. **Injection de prompt** — Le texte est inclus dans le contexte de la conversation, juste à côté de votre message.

Lorsque vous prévisualisez ou téléchargez une pièce jointe en tant que texte (Upload as Text), LibreChat fournit le texte extrait stocké avec l'enregistrement du fichier. Les téléchargements utilisent une extension de nom de fichier `.txt`, même lorsque l'OCR ou un autre analyseur a produit le texte stocké et qu'il n'existe aucun fichier source original à diffuser.

## Quels fichiers sont pris en charge [#which-files-are-supported]

<Tabs items={["Texte et code", "Documents", "Images", "Audio"]}>
  <Tabs.Tab>
    Ceux-ci sont analysés directement — ce sont déjà du texte, donc aucune conversion n'est nécessaire.

    - Texte brut (`.txt`), Markdown (`.md`), CSV, JSON, XML, HTML, CSS
    - Langages de programmation — Python, JavaScript, TypeScript, Java, C#, PHP, Ruby, Go, Rust, Kotlin, Swift, Scala, Perl, Lua
    - Fichiers de configuration — YAML, TOML, INI
    - Scripts shell, fichiers SQL
  </Tabs.Tab>
  <Tabs.Tab>
    L'analyse de texte gère ces éléments nativement. Si l'OCR est configuré, il prend le relais pour une meilleure précision sur les mises en page complexes.

    - **PDF** — numériques et numérisés (les PDF numérisés bénéficient de l'OCR)
    - **Word** — `.docx`, `.doc`
    - **PowerPoint** — `.pptx`, `.potx`, `.ppt`
    - **Excel** — `.xlsx`, `.xls`
    - Livres **EPUB**
  </Tabs.Tab>
  <Tabs.Tab>
    Les images **nécessitent l'OCR** pour produire du texte utile. Sans cela, les résultats seront médiocres.

    - JPEG, PNG, GIF, WebP
    - HEIC, HEIF (formats Apple)
    - Captures d'écran, photos de documents, pages numérisées
  </Tabs.Tab>
  <Tabs.Tab>
    Les fichiers audio **nécessitent que STT** soit configuré. Il n'y a pas de solution de secours — l'audio ne peut pas être « analysé en texte ».

    - MP3, WAV, OGG, FLAC
    - M4A, WebM
    - Enregistrements vocaux, extraits de podcasts
  </Tabs.Tab>
</Tabs>

LibreChat normalise les variantes MIME de scripts shell rapportées par Chrome sous Linux (`application/x-shellscript`) et libmagic (`text/x-shellscript`) vers le type canonique `application/x-sh` avant de vérifier la liste d'autorisation de l'endpoint. Les règles personnalisées [`supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) doivent toujours autoriser `application/x-sh`.

## Téléchargements unifiés et provisionnement d'outils [#unified-uploads-and-tool-provisioning]

Par défaut, une action de pièce jointe remplace l'ancien sélecteur de destination. LibreChat décide de la manière dont le fichier atteint le modèle, tandis que les outils sont provisionnés de manière différée :

<Cards>
  <Card title="Contexte du modèle" href="#what-happens-under-the-hood">
    Les fichiers pris en charge atteignent le modèle via une livraison native du fournisseur ou par du texte extrait, en fonction du type MIME, de la capacité de l'endpoint et de la configuration du déploiement.
  </Card>
  <Card title="Téléchargement pour la recherche de fichiers (RAG)" href="/docs/features/rag_api">
    Lorsque File Search est sélectionné, LibreChat indexe les pièces jointes éligibles uniquement lorsque l'exécution nécessite l'outil.
  </Card>
  <Card title="Téléchargement standard" href="/docs/features/agents">
    Lorsque Code est sélectionné, LibreChat rend les pièces jointes éligibles disponibles pour l'environnement Code uniquement lorsque l'exécution en a besoin.
  </Card>
</Cards>

Les opérateurs peuvent restaurer l'ancien sélecteur de destination avec [`fileConfig.legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), ou contrôler le routage automatique avec [`defaultLLMDeliveryPath`](/docs/configuration/librechat_yaml/object_structure/file_config#defaultllmdeliverypath).

**Routage typique :**

| Situation | Meilleure option |
|-----------|-------------|
| _"Read this 5-page contract and summarize it"_ | Native PDF delivery or extracted text |
| _"I have 50 PDFs, find what mentions pricing"_ | Lazy File Search provisioning |
| _"What's in this screenshot?"_ | Native image delivery |
| _"Run this Python script"_ | Lazy Code provisioning |
| _"Review this code file for bugs"_ | Extracted text |

## La fonctionnalité `context` [#the-context-capability]

Sous le capot, Upload as Text est propulsé par la **capacité `context`**. C'est ce qui contrôle si la fonctionnalité apparaît dans votre interface de chat.

<Callout type="info">
  La fonctionnalité `context` est **activée par défaut**. Vous n'avez besoin d'y toucher que si votre administrateur a personnalisé la liste des fonctionnalités et l'a omise par erreur.
</Callout>

```yaml title="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - "context"  # This is what enables "Upload as Text"
```

La même fonctionnalité de `context` alimente également le **Agent File Context** (le téléchargement de fichiers via le constructeur d'agents pour intégrer du texte dans les instructions système d'un agent). La différence réside dans l'_endroit_ où le texte finit par se trouver :

| | Télécharger en tant que texte | Contexte de fichier de l'agent |
|---|---|---|
| **Où** | Entrée de chat (n'importe quelle conversation) | Panneau du constructeur d'agent |
| **Portée** | Conversation actuelle uniquement | Persiste dans les instructions de l'agent |
| **Cas d'utilisation** | Questions ponctuelles sur un document | Création d'agents spécialisés avec des connaissances intégrées |

## Limites de jetons et troncature [#token-limits-and-truncation]

Lorsqu'un fichier est trop long pour tenir dans la fenêtre de contexte du modèle, LibreChat tronque le texte extrait pour rester dans les limites. Cela se produit automatiquement — vous n'avez pas à vous en soucier, mais il est bon de savoir comment cela fonctionne.

```yaml title="librechat.yaml"
fileConfig:
  fileTokenLimit: 100000  # Default: 100,000 tokens
```

<Callout type="warn" title="La troncature signifie une perte de contenu">
  Si votre fichier dépasse la limite, le texte est coupé à la fin. Si vous obtenez des réponses incomplètes, cela peut en être la raison. Vous pouvez augmenter `fileTokenLimit`, mais gardez à l'esprit que des valeurs plus élevées utilisent plus de jetons par message — ce qui augmente le coût et peut atteindre la limite de contexte du modèle lui-même.
</Callout>

**Règles empiriques :**
- 100k tokens ≈ un livre de 300 pages (suffisant pour la plupart des cas d'utilisation)
- Si vous travaillez avec des fichiers très volumineux, envisagez plutôt d'utiliser [File Search (RAG)](/docs/features/rag_api) — cela ne récupère que les sections pertinentes au lieu de tout intégrer dans le contexte.

## Optionnel : améliorer l'extraction avec l'OCR [#optional-boosting-extraction-with-ocr]

L'analyse de texte fonctionne bien pour les documents créés numériquement (PDF enregistrés depuis Word, fichiers de code, texte brut). Mais si vous téléchargez des **documents numérisés, des photos de pages ou des images contenant du texte**, l'analyseur intégré n'obtiendra pas de très bons résultats.

C'est là qu'intervient l'OCR. Une fois configuré, LibreChat utilise automatiquement l'OCR pour les types de fichiers qui en bénéficient — vous n'avez rien à faire de particulier en tant qu'utilisateur.

<Accordions>
  <Accordion title="Comment demander à votre administrateur de configurer l'OCR">
    Dirigez-les vers la [documentation de configuration OCR](/docs/features/ocr). La version courte :

    ```yaml title="librechat.yaml"
    ocr:
      strategy: "mistral_ocr"
      apiKey: "${OCR_API_KEY}"
      baseURL: "https://api.mistral.ai/v1"
      mistralModel: "mistral-ocr-latest"
    ```

    Une fois configuré, l'OCR gère automatiquement les images et les PDF numérisés — aucun changement n'est nécessaire du côté de l'utilisateur.
  </Accordion>
  <Accordion title="Comment demander à votre administrateur de configurer STT (pour les fichiers audio)">
    Pour la transcription de téléchargements audio, l'administrateur doit configurer un service de Speech-to-Text. Voir la [référence de configuration STT](/docs/configuration/librechat_yaml/object_structure/file_config#stt).
  </Accordion>
</Accordions>

## Référence de configuration de la gestion des fichiers [#file-handling-configuration-reference]

Cette section est destinée aux administrateurs qui souhaitent contrôler quels types de fichiers sont traités par quelle méthode. Les paramètres par défaut fonctionnent bien — vous n'avez besoin d'intervenir ici que si vous souhaitez affiner le comportement.

<Accordions>
  <Accordion title="Exemple complet de fileConfig">
    ```yaml title="librechat.yaml"
    fileConfig:
      # Max tokens extracted from a single file before truncation
      fileTokenLimit: 100000

      # Files matching these MIME patterns use OCR (if configured)
      ocr:
        supportedMimeTypes:
          - "^image/(jpeg|gif|png|webp|heic|heif)$"
          - "^application/pdf$"
          - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.presentation|spreadsheetml\\.sheet)$"
          - "^application/vnd\\.ms-(word|powerpoint|excel)$"
          - "^application/epub\\+zip$"

      # Files matching these MIME patterns use text parsing
      text:
        supportedMimeTypes:
          - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"

      # Files matching these MIME patterns use STT (if configured)
      stt:
        supportedMimeTypes:
          - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
    ```

    **Rappel de priorité :** OCR > STT > analyse de texte > secours.

    Pour la référence complète, consultez [File Config Object Structure](/docs/configuration/librechat_yaml/object_structure/file_config).
  </Accordion>
</Accordions>

## Dépannage [#troubleshooting]

<Accordions>
  <Accordion title="L'option Téléverser en tant que texte n'apparaît pas">
    La fonctionnalité `context` a probablement été supprimée de votre configuration. Demandez à votre administrateur de la rajouter :

    ```yaml
    endpoints:
      agents:
        capabilities:
          - "context"
    ```
  </Accordion>
  <Accordion title="Le contenu du fichier semble incorrect ou est presque vide">
    Quelques points à vérifier :
    - **PDFs / images numérisés** — Ceux-ci nécessitent l'OCR pour extraire correctement le texte. Sans cela, l'analyseur pourrait renvoyer des données corrompues ou rien du tout. Demandez à votre administrateur de [configurer l'OCR](/docs/features/ocr).
    - **Fichiers audio** — Ceux-ci nécessitent STT. Il n'y a pas de solution de repli textuelle pour l'audio.
    - **Fichiers corrompus** — Essayez d'ouvrir le fichier localement pour vous assurer qu'il n'est pas endommagé.
    - **Format non pris en charge** — Si le type MIME ne correspond à aucun modèle configuré, LibreChat tente une analyse textuelle de secours, qui peut ne pas fonctionner pour les formats binaires.
  </Accordion>
  <Accordion title="Le téléchargement est rejeté car le type de fichier n'est pas pris en charge">
    LibreChat renvoie le type MIME rejeté dans l'erreur de téléchargement. Vérifiez les modèles [`fileConfig.endpoints.<endpoint>.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) de l'endpoint actif et autorisez le type canonique que vous souhaitez accepter. Pour les scripts shell, utilisez `application/x-sh` ; LibreChat normalise les variantes courantes `application/x-shellscript` et `text/x-shellscript` avant d'effectuer la correspondance.
  </Accordion>
  <Accordion title="L'IA semble avoir ignoré une partie de mon fichier">
    Votre fichier a probablement dépassé la limite `fileTokenLimit`. Le texte a été tronqué.

    **Options :**
    - Demandez à votre administrateur d'augmenter `fileTokenLimit` dans `librechat.yaml`
    - Utilisez plutôt [File Search (RAG)](/docs/features/rag_api), qui récupère les segments pertinents au lieu de charger le fichier entier
    - Divisez le fichier en parties plus petites et téléchargez-les séparément
  </Accordion>
  <Accordion title="Les images sont téléchargées mais l'IA ne peut pas lire le texte qu'elles contiennent">
    Sans OCR, les images sont traitées par analyse textuelle, ce qui ne permet pas réellement de « voir » le texte dans une image. Vous devez configurer l'OCR pour que cela fonctionne. Voir [OCR for Documents](/docs/features/ocr).

    Alternativement, utilisez un **vision model** avec le téléchargement de fichiers standard — le modèle lui-même peut lire le texte dans les images.
  </Accordion>
</Accordions>
