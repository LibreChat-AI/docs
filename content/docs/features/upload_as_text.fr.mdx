Upload as Text extrait le texte d'un fichier et l'ajoute à votre message, afin que le modèle lise l'intégralité du document au lieu de le parcourir par recherche. Utilisez cette option lorsqu'un fichier est suffisamment petit pour tenir dans le contexte et que vous souhaitez que chaque ligne soit prise en compte : un contrat, un journal, un fichier source ou un export de tableur.

## Joindre un fichier [#attaching-a-file]

Cliquez sur **+** dans le [compositeur de messages](/docs/features/composer#add-files) et choisissez **From Local Computer** sous **Attach** (ou **From SharePoint**, si votre serveur le propose). Vous pouvez également glisser-déposer des fichiers dans le compositeur. Vous ne choisissez pas de destination : LibreChat analyse chaque fichier et décide de la manière dont le modèle le reçoit.

- Les fichiers texte, code, Markdown, CSV, JSON, Word et Excel sont envoyés sous forme de texte extrait.
- Les images, l'audio, la vidéo et les PDF sont envoyés directement au modèle lorsque son fournisseur les accepte. Pour un fournisseur qui ne peut pas recevoir de PDF, LibreChat extrait à la place le texte du PDF.

Si vous avez activé **File Search** ou **Run Code** dans la palette, ces outils ne reçoivent le fichier que lorsqu'une exécution en a réellement besoin.

Si votre administrateur a activé l'ancien menu de destination, vous choisissez explicitement : **Upload as Text** figure à côté de **Upload to Provider** (ou **Upload Image**) et de **Upload for File Search**. Certaines de ces options se trouvent sous **More upload options**. Si vous déposez plusieurs fichiers dans le chat dans ce mode, la fenêtre **Select Upload Type** s'ouvre avec les mêmes choix.

Lorsque vous joignez plusieurs fichiers à la fois, les doublons et les fichiers dépassant la limite de taille par fichier sont ignorés et leurs noms sont indiqués dans un avis, puis le reste est téléversé. Les limites de nombre de fichiers et de taille totale continuent de s'appliquer à ce qui reste ; si le lot restant dépasse l'une ou l'autre, aucun de ses fichiers n'est téléversé.

## Coller un long texte [#pasting-long-text]

Collez plus de 2 500 caractères dans la zone de message et LibreChat transforme le contenu collé en un fichier texte nommé `pasted-text.txt` (puis `pasted-text-2.txt`, et ainsi de suite), joint comme texte, et affiche **Attached as text**. Votre zone de message reste lisible et le modèle reçoit toujours le contenu collé exact. Sélectionnez la pastille du fichier pour **Edit pasted text**, ou utilisez **Move back into message** pour le replacer en ligne dans le message.

Les collages dans le formulaire de question d'un agent restent en ligne, et si le téléversement échoue, LibreChat remet le texte dans la zone de message. Pour conserver les longs collages en ligne, désactivez **Coller un long texte sous forme de fichier** dans **Paramètres** > **Chat** > **Envoi**. Ce paramètre est enregistré dans votre navigateur.

## Comment le texte est extrait [#how-the-text-is-extracted]

LibreChat essaie ces méthodes dans l'ordre et utilise la première qui s'applique :

1. OCR, si votre administrateur a configuré un service OCR et que le type de fichier est pris en charge par l'OCR (images, PDF, documents Office, EPUB, OpenDocument). Voir [OCR](/docs/features/ocr).
2. Le analyseur de documents intégré pour les fichiers PDF, DOCX, XLS et XLSX, ODT et ODS, jusqu'à 15 Mo. Il lit uniquement la couche de texte.
3. Synthèse vocale vers texte pour les fichiers audio, si votre administrateur a configuré la STT.
4. Lecture en texte brut pour tout contenu déjà sous forme de texte : code source, Markdown, CSV, JSON, YAML, HTML, etc.

Les fichiers `.doc` (ancien format Word), PowerPoint et EPUB ne sont pas pris en charge par l'analyseur intégré ; ils nécessitent une reconnaissance optique de caractères (OCR), ou l'extraction de texte de l'API RAG si votre administrateur l'a configurée.

Un PDF numérisé ou une photo de page ne contient pas de couche de texte. Sans OCR, il n'y a donc rien à extraire et le téléversement échoue avec un message indiquant qu'un service OCR est nécessaire. Un modèle de vision peut en revanche lire l'image directement si vous l'envoyez avec **Upload to Provider**.

## Quelle partie du fichier le modèle voit [#how-much-of-the-file-the-model-sees]

Chaque texte de fichier est tronqué à la limite de jetons par fichier, fixée par défaut à 100 000 jetons. Tout contenu au-delà de cette limite est supprimé sans avertissement. Si les réponses semblent ignorer la fin d'un long document, c'est probablement la raison. Vous pouvez abaisser ou augmenter cette limite pour une conversation avec **File Token Limit** dans les paramètres du modèle ; une limite plus élevée augmente toutefois le nombre de jetons consommés à chaque message incluant le fichier.

Lorsque LibreChat ne conserve que le texte extrait d'un fichier et non le fichier d'origine, le téléchargement vous fournit ce texte sous forme de fichier `.txt`.

Pour les documents volumineux ou un grand nombre de fichiers, la [recherche dans les fichiers](/docs/features/rag_api) est généralement mieux adaptée : elle récupère les passages pertinents au lieu d'envoyer l'intégralité du fichier à chaque tour.

## Configuration [#setup]

Upload as Text fonctionne immédiatement, sans configuration. L'option explicite **Upload as Text** dépend de la capacité d'agent `context`, activée par défaut ; un administrateur qui personnalise la liste des capacités doit la conserver. Les administrateurs contrôlent l'extraction, la limite de tokens et le style du menu de téléversement dans [`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config), ainsi que l'OCR dans la [configuration `ocr`](/docs/configuration/librechat_yaml/object_structure/ocr).
