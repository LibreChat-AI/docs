"Upload as Text"会从文件中提取文本并将其添加到您的消息中,因此模型会读取整个文档,而不是对其进行搜索。当文件足够小、可以放入上下文中,并且您希望模型考虑每一行内容时,请使用此功能,例如合同、日志、源代码文件或电子表格导出文件。

## 附加文件 [#attaching-a-file]

点击 [消息输入框](/docs/features/composer#add-files) 中的 **+**,然后在 **Attach** 下选择 **From Local Computer**(如果您的服务器已启用,也可以选择 **From SharePoint**)。您也可以将文件直接拖放到输入框中。您无需选择目标位置:LibreChat 会分析每个文件,并决定模型以何种方式获取该文件。

- 文本、代码、Markdown、CSV、JSON、Word 和 Excel 文件均以提取后的文本形式发送。
- 图片、音频、视频和 PDF 在模型提供商支持的情况下会直接发送给模型。若某个提供商不支持 PDF,LibreChat 会改为提取该 PDF 中的文本。

如果你在工具面板中开启了**文件搜索**或**运行代码**,这些工具只有在某次运行确实需要时才会获取该文件。

如果您的管理员启用了旧版上传目标菜单,您可以明确选择上传方式:**Upload as Text** 与 **Upload to Provider**(或 **Upload Image**)以及 **Upload for File Search** 并列显示。其中部分选项位于 **More upload options** 之下。在此模式下将多个文件拖放到聊天界面时,会打开 **Select Upload Type** 窗口,并提供相同的选项。

当你一次附加多个文件时,重复的文件和超过单文件大小限制的文件会被跳过,并在提示中注明文件名,其余文件将正常上传。文件数量和总大小限制仍然适用于剩余的文件;如果剩余的批次违反了其中任何一项限制,则所有文件都不会被上传。

## 粘贴长文本 [#pasting-long-text]

将粘贴内容超过 2,500 个字符的文本粘贴到消息框中,LibreChat 会将粘贴内容转换为名为 `pasted-text.txt` 的文本文件(之后依次为 `pasted-text-2.txt`,以此类推),并以文本附件的形式添加,同时显示 **Attached as text**。您的消息框保持清晰可读,模型仍会获取完整的原始粘贴内容。点击文件标签即可**编辑粘贴的文本**,或使用 **Move back into message** 将其重新放回消息中作为内联文本。

粘贴到代理问题表单中的内容保持内联显示,如果上传失败,LibreChat 会将文本放回消息框中。要让较长的粘贴内容保持内联,请在 **设置** > **聊天** > **发送** 下关闭 **将长文本粘贴为文件**。该设置存储在您的浏览器中。

## 文本是如何提取的 [#how-the-text-is-extracted]

LibreChat 会按以下顺序依次尝试这些方式,并使用第一个适用的方式:

1. 如果管理员配置了 OCR 服务,并且文件类型是 OCR 支持的类型(图片、PDF、Office 文档、EPUB、OpenDocument),则使用 OCR。请参阅 [OCR](/docs/features/ocr)。
2. 内置的文档解析器，用于解析最大 15 MB 的 PDF、DOCX、XLS 和 XLSX、ODT 以及 ODS 文件。它仅读取文本层。
3. 用于音频文件的语音转文本功能(前提是管理员已配置 STT)。
4. 纯文本阅读：适用于任何已经是文本格式的内容，例如源代码、Markdown、CSV、JSON、YAML、HTML 等。

旧版 `.doc`、PowerPoint 和 EPUB 文件不在内置解析器的支持范围内;这些文件需要 OCR 处理,或者在管理员已完成配置的情况下,使用 RAG API 的文本提取功能。

扫描版 PDF 或页面照片没有文本层,因此如果没有 OCR,就无法提取任何内容,上传会失败并提示需要 OCR 服务。如果使用 **Upload to Provider** 上传,视觉模型则可以直接读取图像。

## 模型能看到文件的多少内容 [#how-much-of-the-file-the-model-sees]

每个文件的文本都会按照文件 token 上限进行截断,默认上限为 100,000 个 token。超出部分会被直接丢弃,且不会给出任何提示。因此,如果回答似乎忽略了长文档的结尾,很可能就是这个原因。你可以在模型参数中通过 **File Token Limit** 为某次对话调整该上限;上限设置得越高,包含该文件的每条消息消耗的 token 就越多。

当 LibreChat 仅保存文件中提取出的文本而不保存原始文件时,下载该文件将得到一个包含该文本的 `.txt` 文件。

对于大型文档或大量文件,[文件搜索](/docs/features/rag_api)通常是更合适的选择:它只检索相关段落,而不是每次对话都发送整个文件。

## 设置 [#setup]

"Upload as Text" 开箱即用。显式的 **Upload as Text** 选项依赖于 `context` 智能体能力,该能力默认开启;如果管理员自定义了能力列表,则需要保留该能力。管理员可以在 [`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config) 中控制提取方式、令牌上限和上传菜单样式,并可以在 [`ocr` 配置](/docs/configuration/librechat_yaml/object_structure/ocr) 中设置 OCR。
