Agents API memungkinkan kode di luar LibreChat berkomunikasi dengan agen Anda. Arahkan OpenAI SDK mana pun ke instance Anda, berikan ID agen sebagai model, dan Anda akan mendapatkan seluruh konfigurasi agen (instruksi, alat, file) melalui API yang sudah familiar. Gunakan ini untuk menghubungkan agen ke skrip, pekerjaan CI, atau produk lain.

Ada tiga bagian:

- **Inferensi**: Chat Completions dan Open Responses, diautentikasi dengan kunci API (atau token OIDC Anda sendiri, jika admin telah mengaturnya).
- **Agent Events**: serahkan pekerjaan agen dari sistem lain, seperti webhook, dan lacak apakah pekerjaan tersebut telah diselesaikan. Hanya kunci API.
- **Manajemen Agen**: buat dan edit agen serta skill dari layanan tepercaya, menggunakan token OIDC mesin.

<Callout type="warning" title="Beta">
  Endpoint, format permintaan, dan respons masih dapat berubah antar rilis.
</Callout>

## Dapatkan API key [#get-an-api-key]

Buka **Settings**, pergi ke **Data & Privacy**, lalu temukan **Agent API Keys** di bagian **API keys**. Klik **Manage**, lalu **Create API Key**, beri nama, pilih masa berlaku (mulai dari 7 hari hingga 1 tahun, atau tidak pernah kedaluwarsa), dan segera salin kuncinya: kunci tersebut hanya ditampilkan sekali.

Kunci API bertindak atas nama Anda. Apa pun yang dapat Anda akses melalui API, siapa pun yang memegang kunci tersebut juga dapat mengaksesnya, jadi hapuslah kunci yang tidak lagi Anda gunakan. Menghapus kunci akan langsung memutus aplikasi yang menggunakannya.

Jika Anda tidak melihat bagian ini, peran Anda belum diberikan akses ke Agents API.

## Agen mana yang dapat Anda panggil [#which-agents-you-can-call]

Anda dapat memanggil agen yang Anda miliki atau yang dibagikan kepada Anda. Untuk agen milik orang lain, pemilik harus memberikan akses kepada Anda melalui tombol **Remote Access** (ikon globe) di footer Agent Builder. Ini terpisah dari berbagi biasa: kemampuan untuk mengobrol dengan agen di LibreChat tidak memungkinkan Anda memanggilnya melalui API.

Anda memerlukan ID agen, yang ditampilkan di bawah **Advanced Settings** pada builder dengan tombol salin. `GET /api/agents/v1/models` mencantumkan agen yang dapat dipanggil oleh kunci Anda, dan `GET /api/agents/v1/models/{model}` mengembalikan satu agen.

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions` mengikuti format OpenAI Chat Completions, sehingga klien OpenAI yang sudah ada dapat digunakan dengan cukup mengubah base URL:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

Permintaan yang sama dengan curl:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` mengimplementasikan spesifikasi [Open Responses](https://www.openresponses.org/), yang dirancang untuk beban kerja agen: penalaran, pemanggilan alat (tool calls), dan event yang di-stream merupakan bagian dari format itu sendiri, bukan tambahan yang dipasang belakangan. Ini adalah antarmuka yang akan terus dikembangkan oleh LibreChat ke depannya, sehingga disarankan untuk digunakan dalam integrasi baru.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` mengembalikan respons yang tersimpan, dan `GET /api/agents/v1/responses/models` menampilkan daftar agen yang tersedia di sini.

### Fungsi alat Anda sendiri [#your-own-function-tools]

Anda dapat meneruskan tool `function` standar dalam permintaan Responses. LibreChat menampilkannya kepada model tetapi tidak menjalankannya: ketika model memilih salah satu, respons akan berisi item `function_call`, dan Anda menjalankan fungsi tersebut sendiri. Untuk melanjutkan, kirim permintaan baru yang `input`-nya mengulangi item `function_call` tersebut, diikuti dengan `function_call_output` yang memiliki `call_id` yang sama:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Tidak ada yang disimpan secara terbuka di antara kedua permintaan, dan `previous_response_id` saja tidak cukup; Anda harus mengulang panggilan beserta outputnya. Nama tool boleh menggunakan huruf, angka, garis bawah, dan tanda hubung, harus unik, dan tidak boleh menimpa salah satu tool milik agent. Giliran yang memanggil salah satu tool Anda tidak dapat sekaligus memanggil tool milik agent; model akan diminta untuk mencoba lagi.

### Persetujuan alat melalui API [#tool-approval-over-the-api]

Jika administrator Anda mewajibkan persetujuan untuk beberapa alat, panggilan API tidak dapat berhenti untuk meminta persetujuan dari siapa pun. Alat yang memerlukan persetujuan, atau yang ditolak, akan diblokir. Administrator sebaiknya secara eksplisit mengizinkan alat yang dimaksudkan untuk dijalankan oleh klien tanpa pengawasan.

## Peristiwa Agen [#agent-events]

Agent Events memungkinkan sistem lain menyerahkan pekerjaan ke sebuah agen dan kembali nanti untuk melihat apa yang terjadi. Fitur ini masih dalam tahap beta. Event menggunakan API key Agents Anda, yang mengidentifikasi Anda dan sumbernya; pengaturan yang hanya menggunakan OIDC tidak dapat menggunakannya. Event juga memiliki batas laju (rate limit) tersendiri, [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Sebuah event hadir dalam salah satu dari tiga mode:

- `fire` memulai percakapan baru dengan agen.
- `continue` menambahkan giliran (turn) ke agen anak yang sebelumnya Anda ikat (lihat di bawah).
- `steer` menambahkan panduan ke proses yang masih berjalan, diidentifikasi melalui percakapan dan generasi yang dikembalikan oleh `fire`.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Setiap permintaan memerlukan satu `Idempotency-Key` (1 hingga 256 huruf, angka, atau `._~:/+=-`). Gunakan kembali kunci tersebut saat Anda mencoba ulang pengiriman yang sama; menggunakannya untuk konten yang berbeda merupakan konflik. LibreChat menetapkan sumber peristiwa dari API key Anda dan mengabaikan sumber apa pun yang Anda kirim. Payload disimpan, jadi jangan sertakan rahasia di dalamnya. Gunakan `orderingKey` ketika peristiwa tentang hal yang sama harus diproses secara berurutan.

Responsnya adalah `202 Accepted` dengan ID pengiriman dan `Location` untuk melakukan polling dengan kunci yang sama:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Sebuah pengiriman (delivery) berstatus `pending`, `leased`, `succeeded`, atau `dead`. Untuk `continue` yang terikat (bound), `succeeded` hanya berarti giliran (turn) telah dimulai. Status `handling`-nya kemudian berpindah dari `started` ke salah satu dari `applied`, `completed_no_action`, `failed`, atau `cancelled`. Jika Anda mengirim `expectedAction` (nama tool dan opsional beberapa argumennya), `applied` berarti LibreChat melihat tool tersebut dipanggil dengan argumen yang cocok; apa yang dikatakan model dalam teks tidak dihitung.

Agent Events bukan penerima webhook publik. Jika event berasal dari penyedia yang menandatangani webhook-nya, verifikasi tanda tangan tersebut di adapter Anda sendiri sebelum meneruskan event tersebut.

### Agen anak berbasis peristiwa [#event-driven-child-agents]

Untuk mempertahankan percakapan yang berkelanjutan dengan child agent di banyak event, ikat (bind) sekali terlebih dahulu, lalu kirim event `continue` ke binding tersebut:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

Induk harus berupa percakapan agen normal, dan target harus salah satu subagen langsung dari agen tersebut (atau agen itu sendiri, jika self-spawn diizinkan). `actorId` memiliki panjang hingga 128 karakter. Binding baru mengembalikan `201` dan pemutaran ulang (replay) mengembalikan `200`, keduanya dengan `id` binding. Giliran berikutnya merujuk ke binding tersebut:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Setiap binding memproses satu event dalam satu waktu: event berikutnya menunggu hingga giliran saat ini memiliki status penanganan akhir, sementara binding yang berbeda berjalan secara paralel. Child yang terikat dapat dijeda untuk Ask User atau persetujuan tool; event-event berikutnya darinya menunggu sampai seseorang memberikan jawaban di LibreChat. Hal ini memerlukan checkpointer MongoDB yang durable (default). Di percakapan induk, setiap child yang terikat ditampilkan sebagai satu baris di bawah pesan yang memiliki binding tersebut dan membuka panel aktivitas subagent.

Sebuah binding hanya berfungsi dengan API key, pengguna, dan tenant yang membuatnya. Thread turunan tetap tidak ditampilkan dalam daftar chat dan bersifat hanya-baca di dalam aplikasi.

Untuk event yang hanya berupa observasi, seperti "sebuah game maju", berikan `coalesce.key` yang sama dan LibreChat akan mengelompokkan hingga 8 event tersebut (dalam 750 ms dan 512 KiB) menjadi satu giliran. Setiap event tetap memiliki receipt-nya sendiri. Jangan menggabungkan command, approval, atau apa pun yang memiliki `expectedAction`.

## Manajemen API Agen [#agent-management-api]

API Manajemen Agent memungkinkan layanan tepercaya untuk membuat, mengubah, dan menghapus agent serta skill tanpa sesi browser. API ini berstatus beta dan menggunakan autentikasinya sendiri: token OIDC mesin dari klien yang didaftarkan admin di bawah [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi). Setiap klien dikaitkan dengan satu pengguna LibreChat dan tenant yang sudah ada, dan setiap permintaan bertindak atas nama pengguna tersebut, dengan izin dan akses milik pengguna tersebut. API ini tidak menjadikan siapa pun sebagai admin.

| Metode | Rute | Tujuan |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | Membuat agen |
| `GET` | `/api/agents/v1/agents` | Menampilkan daftar agen yang dapat diakses |
| `GET` | `/api/agents/v1/agents/{id}` | Membaca agen |
| `PATCH` | `/api/agents/v1/agents/{id}` | Memperbarui agen |
| `DELETE` | `/api/agents/v1/agents/{id}` | Menghapus agen |
| `POST` | `/api/agents/v1/agents/{id}/files` | Mengunggah dan melampirkan file |
| `GET` | `/api/agents/v1/agents/{id}/files` | Menampilkan daftar file yang dilampirkan |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | Melepas lampiran file |
| `GET` | `/api/agents/v1/skills` | Menampilkan daftar skill yang dapat diakses |
| `POST` | `/api/agents/v1/skills` | Membuat skill |
| `GET` | `/api/agents/v1/skills/{id}` | Membaca skill |
| `PATCH` | `/api/agents/v1/skills/{id}` | Memperbarui skill |
| `DELETE` | `/api/agents/v1/skills/{id}` | Menghapus skill |
| `GET` | `/api/agents/v1/skills/{id}/files` | Menampilkan daftar file skill |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | Membaca file skill |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | Membuat atau mengganti file skill |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | Menghapus file skill |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Payload agent menggunakan field yang sama dengan Agent Builder dan menolak field yang tidak dikenal; `model` wajib diisi saat membuat. Daftar (list) menerima `limit` (1 hingga 100, default 20) dan `cursor`; jika `has_more` bernilai true, teruskan `after` yang dikembalikan sebagai cursor berikutnya. Unggahan file menggunakan `multipart/form-data` dengan satu `file` dan `tool_resource` seperti `context`, `file_search`, atau `execute_code`, dengan tunduk pada batas unggahan yang berlaku.

Skill create menerima `name`, `description`, `body`, dan secara opsional `displayTitle`, `frontmatter`, `category`, serta `alwaysApply`. Pembaruan harus mengirimkan versi skill saat ini sebagai `expectedVersion`, sehingga dua penulis tidak dapat saling menimpa secara diam-diam.

Error menggunakan kode `invalid_request`, `not_found`, `permission_denied`, `conflict`, dan `internal_error`. Sumber daya yang tidak dapat Anda akses mungkin dikembalikan sebagai `not_found`. Kredensial yang salah atau tidak ada akan mengembalikan `401`.

Jika admin mengaktifkannya, deskripsi OpenAPI dari rute manajemen akan disajikan di `/api/openapi.json`, dengan dokumentasi interaktif di `/api/docs`. Deskripsi ini tidak mencakup inferensi atau event. Lihat [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Penggunaan dan penagihan [#usage-and-billing]

Permintaan API dihitung terhadap saldo token Anda sama seperti percakapan di aplikasi. Total penggunaan dalam respons mencakup panggilan subagent, dengan rincian terpisah `primary` dan `subagent`, serta token cache dan reasoning jika disediakan oleh penyedia. Lihat [Token Usage](/docs/configuration/token_usage).

## Pengaturan [#setup]

Agents API dinonaktifkan untuk pengguna biasa hingga admin memberikan izin Remote Agents pada peran mereka, baik melalui [Admin Panel](/docs/features/admin_panel) maupun dengan [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents). Admin memilikinya secara default. Autentikasi kunci API diaktifkan secara default; untuk menerima token dari penyedia OIDC Anda sendiri sebagai pengganti atau bersama kunci, lihat [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi). Management API dikonfigurasi secara terpisah di bawah [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi), dan pengaturan pengiriman event berada di bawah [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven).
