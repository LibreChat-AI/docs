파일 검색을 사용하면 문서를 업로드하고 그 내용을 채팅에 붙여넣지 않고도 문서에 대해 질문할 수 있습니다. LibreChat은 각 파일을 RAG API로 전송하며, RAG API는 파일을 청크로 나누고 인덱싱합니다. 질문을 하면 모델이 이 인덱스를 검색하여 찾은 구절을 바탕으로 답변합니다.

문서가 너무 길어 매번 전체를 읽기 어렵거나, 여러 파일에 걸친 답변이 필요할 때 이 기능을 사용하세요.

## 검색을 위해 파일 업로드 [#upload-a-file-for-search]

**+** 버튼을 [메시지 입력창](/docs/features/composer)에서 클릭하여 팔레트를 연 다음, **More upload options**를 펼치고 **Upload for File Search**를 선택한 후 파일을 고르세요. 팔레트에서 해당 항목을 검색해도 됩니다. 이 방식으로 업로드하면 해당 채팅에 대해 **File Search**도 함께 활성화됩니다. 대용량 파일은 인덱싱에 시간이 조금 걸릴 수 있으며, 인덱싱이 끝나야 업로드가 완료됩니다.

대화에 색인된 파일이 생기면 모델에 `file_search` 도구가 제공됩니다. 도구를 호출할지는 모델이 판단합니다. 문서에 관한 질문에는 검색이 실행되고, 일상적인 대화에는 검색하지 않습니다. 검색이 진행되는 동안 응답에는 "Searching your files" 단계가 표시되며, 인용이 활성화되어 있으면 사용된 본문 구절이 파일 이름과 함께 **Sources** 아래에 나타나므로 해당 문서를 열어 내용을 직접 확인할 수 있습니다.

## 검색 작동 방식 [#how-search-works]

모델이 `file_search`를 호출하면 검색 쿼리를 작성합니다. LibreChat은 RAG API에 요청해 첨부된 각 파일에서 가장 가까운 청크 5개를 가져오고, 전체에서 가장 가까운 청크 10개를 유지합니다. 이 청크들은 파일 이름과 관련성 점수와 함께 모델에 다시 전달되며, 모델은 이를 바탕으로 답변합니다.

검색(Retrieval)은 질의와 의미상 가까운 구절을 찾아내므로, 대용량 문서에서 특정 사실을 찾아보는 데 적합합니다. 요약처럼 문서 전체를 한꺼번에 이해해야 하는 질문에는 일반적으로 Upload as Text 방식이 더 나은 결과를 냅니다.

LibreChat에서 파일을 삭제하면 RAG API에 있는 해당 벡터도 함께 제거됩니다.

## 이미 업로드한 파일 재사용하기 [#reuse-files-you-already-uploaded]

인덱싱된 파일은 계정에 그대로 남습니다. 팔레트를 열고 **Your files** 아래에서 파일을 찾으면, 다시 업로드하지 않고도 새 메시지나 대화에 첨부할 수 있습니다.

Assistants 엔드포인트가 활성화된 상태에서 업로드된 파일은 OpenAI에 저장되며, RAG API에 의해 인덱싱되지 않고, 다른 엔드포인트에 첨부할 수 없습니다.

## 에이전트의 파일 검색 [#file-search-in-agents]

에이전트의 경우, 에이전트 빌더에서 [**파일 검색**](/docs/features/agents#file-search)을 켜고 파일을 업로드하세요. 업로드한 파일은 에이전트의 지식 베이스가 되며, 에이전트와 대화하는 모든 사용자는 직접 파일을 업로드하지 않아도 에이전트가 해당 파일을 검색하도록 할 수 있습니다. 파일을 추가하려면 먼저 에이전트를 저장해야 합니다.

## 파일 검색 또는 텍스트로 업로드 [#file-search-or-upload-as-text]

[**텍스트로 업로드**](/docs/features/upload_as_text)도 같은 메뉴에 있습니다. 이 기능은 파일의 텍스트를 추출하여 대화에 전체 내용을 넣으므로, 모델이 모든 단어를 읽어야 하는 짧은 문서에 적합합니다. 파일 검색은 각 쿼리와 일치하는 구절만 전송하므로 긴 문서와 많은 파일로 확장할 수 있지만, 검색되지 않은 부분은 모델이 전혀 보지 못합니다.

RAG API는 또한 내장 파서가 읽을 수 없는 파일 형식을 위한 텍스트 추출기로 Upload as Text 기능을 제공합니다. [텍스트가 추출되는 방식](/docs/features/upload_as_text#how-the-text-is-extracted)을 참고하세요.

## 설정 [#setup]

파일 검색에는 RAG API 서비스와 벡터 데이터베이스가 필요합니다. 기본 Docker 설정에는 두 가지가 모두 포함되어 있으며, 관리자가 임베딩 제공자를 설정합니다. 그 밖의 설치 환경에서는 `RAG_API_URL`을 설정합니다. 자세한 내용은 [RAG API 구성](/docs/configuration/rag_api)을, 서비스 자체의 엔드포인트 및 변수는 [RAG API 저장소](https://github.com/LibreChat-AI/rag-api)를 참고하세요.
