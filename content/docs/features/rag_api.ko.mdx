**RAG (Retrieval-Augmented Generation) API**는 LibreChat에 업로드한 파일을 색인하고, 질문과 가장 관련성이 높은 단락을 반환하는 별도의 서비스입니다. 이를 통해 모델은 학습 데이터에만 의존하지 않고 사용자의 문서를 근거로 답변할 수 있습니다.

이것은 LangChain 기반의 Python FastAPI 앱이며, pgvector 확장을 사용하는 PostgreSQL에 임베딩을 저장합니다.

**설정 방법은 [RAG API 구성](/docs/configuration/rag_api)을 참고하세요.**

LibreChat에서 RAG는 [에이전트](/docs/features/agents#file-search)의 **파일 검색**(`file_search`) 기능을 지원합니다. 에이전트의 파일 검색에 첨부된 파일이나 파일 검색을 선택한 실행(run)에 첨부된 파일은 RAG API에 의해 인덱싱되며, 필요할 때 검색됩니다. 다른 채팅 엔드포인트는 RAG 인덱싱이나 검색을 사용하지 않지만, 아래에서 설명하는 것처럼 텍스트 추출을 위해 RAG API를 사용할 수는 있습니다.

RAG API는 LibreChat이 업로드된 파일에서 텍스트를 추출하는 데 사용할 수 있는 `/text` 경로도 제공합니다. 적용되는 경우는 [텍스트로 업로드](/docs/features/upload_as_text#what-happens-under-the-hood)를 참조하십시오.

## 작동 방식 [#how-it-works]

1. **인덱싱.** 파일을 검색 가능하게 만들어야 할 때(에이전트의 File Search에 업로드할 때, 또는 채팅 실행에서 첨부 파일에 대해 File Search를 처음 사용할 때), LibreChat은 해당 파일을 RAG API로 전송합니다. RAG API는 텍스트를 겹치는 청크(`CHUNK_SIZE` 및 `CHUNK_OVERLAP`)로 나누고, 각 청크를 설정된 제공자를 통해 임베딩으로 변환한 다음, 벡터를 pgvector에 저장합니다.
2. **검색(Retrieval).** 모델이 파일 검색(File Search)을 호출하면 검색 쿼리를 작성합니다. LibreChat은 RAG API에 첨부된 각 파일에서 가장 가까운 청크 5개를 요청한 다음, 전체에서 가장 가까운 청크 10개를 유지합니다.
3. **답변 생성.** 이러한 청크는 파일 이름과 관련성 점수와 함께 모델에 반환되며, 모델은 이를 바탕으로 답변합니다. [파일 인용](/docs/configuration/librechat_yaml/object_structure/interface#filecitations)이 활성화되어 있으면, 응답에 사용된 파일을 인용할 수 있습니다.

LibreChat에서 파일을 삭제하면 RAG API에 있는 해당 벡터도 함께 제거됩니다.

검색은 질의와 의미상 가까운 구절만 찾아내므로, 대용량 문서에서 특정 사실을 찾아볼 때 가장 효과적입니다. 문서 전체를 한 번에 필요로 하는 질문, 예를 들어 문서 요약과 같은 경우에는 [Upload as Text](/docs/features/upload_as_text)를 사용하는 것이 일반적으로 더 나은 결과를 제공합니다.

## RAG란 무엇인가요? [#what-is-rag]

검색 증강 생성(Retrieval-Augmented Generation)은 언어 모델을 외부 지식 소스에 기반하도록 만듭니다. 모델이 학습 중에 익힌 내용에만 의존하는 대신, 애플리케이션이 먼저 해당 소스에서 관련 문장 조각을 검색하여 프롬프트에 추가하고, 모델은 이를 바탕으로 답변을 생성합니다. 지식이 모델 외부에 존재하므로, 모델을 다시 학습시키지 않고도 문서를 추가하거나 업데이트할 수 있습니다.
