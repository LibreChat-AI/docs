Admin Insights est un tableau de bord optionnel permettant d'examiner l'utilisation des Agents, à partir de l'activité stockée dans la base MongoDB principale du déploiement. Il présente les conversations, les utilisateurs uniques, les messages persistés et les jetons enregistrés au fil du temps pour les Agents visibles par l'utilisateur, ainsi que des vues sur les utilisateurs les plus actifs, le taux de désengagement et les conversations récentes.

## Activer Insights [#enable-insights]

Définissez `ENABLE_INSIGHTS=true` dans `.env`, puis redémarrez LibreChat :

```sh filename=".env"
ENABLE_INSIGHTS=true
```

Lorsqu'elle est activée pour un compte pouvant consulter les analyses d'au moins un Agent, **Analyses** apparaît dans la barre latérale du bureau et dans le sélecteur de panneaux mobile. Lorsqu'elle est désactivée, les routes d'accès et de données renvoient `404` et l'élément de navigation reste masqué.

## Exigences d'accès [#access-requirements]

Les Agents qu'un compte connecté peut consulter dépendent de son identité :

- Les comptes ayant le rôle `ADMIN` voient tous les Agents.
- Les comptes qui disposent de la capacité système `read:insights` peuvent voir tous les Agents.
- Tous les autres utilisateurs ne voient que les Agents sur lesquels ils disposent à la fois de l'autorisation **VIEW** et de l'autorisation **View insights** via la liste d'accès de l'Agent.

`GET /api/insights/access` renvoie `403` uniquement lorsqu'aucun Agent n'est accessible au compte, et les routes du tableau de bord renvoient `403` lorsqu'une requête désigne un Agent en dehors de cet ensemble.

Seuls les administrateurs peuvent accorder l'autorisation **Voir les analyses** sur un Agent. Il s'agit d'un interrupteur distinct dans la boîte de dialogue de partage de l'Agent, que les autres utilisateurs ne voient pas, et il ne peut pas être accordé à des principaux publics. Les administrateurs ont toujours accès. Utilisez le [Panneau d'administration](/docs/features/admin_panel) pour attribuer la capacité `read:insights`, et consultez [Contrôle d'accès](/docs/features/access_control) pour les bits d'autorisation.

Chaque requête Insights déduit le périmètre du tenant à partir du compte authentifié. Les comptes de tenant ne voient que les Agents et les enregistrements de leur propre tenant ; un compte sans tenant ne voit que les enregistrements non rattachés à un périmètre.

<Callout type="warning" title="Données opérationnelles sensibles">
  Les aperçus peuvent afficher les noms et adresses e-mail des utilisateurs, les identifiants de conversation et le premier message des conversations récentes. Accordez `read:insights` ou **Voir les aperçus** uniquement aux personnes qui doivent consulter ces données.
</Callout>

## Métriques du tableau de bord [#dashboard-metrics]

Les métriques sont limitées aux conversations avec les Agents que l'utilisateur peut voir, filtrées par le filtre Agent. Les quatre métriques récapitulatives et leurs mini-graphiques quotidiens utilisent la plage de dates sélectionnée :

- **Conversations :** conversations avec les Agents sélectionnés créées dans la plage
- **Utilisateurs uniques :** utilisateurs représentés par l'activité de messages persistés correspondante dans ces conversations
- **Messages :** les messages utilisateur et assistant enregistrés de manière persistante dans ces conversations
- **Tokens :** la somme des valeurs `tokenCount` des messages enregistrés

Le tableau de bord comprend également :

- **Utilisateurs principaux :** jusqu'à huit utilisateurs classés par nombre de messages, avec leurs totaux de conversations et de messages
- **Utilisateurs inactifs :** jusqu'à huit utilisateurs dont le dernier message envoyé à l'un des agents sélectionnés datait de 28 jours pendant la plage sélectionnée
- **Dernières conversations :** conversations paginées avec date, propriétaire, premier message, nombre de messages persistés et jetons enregistrés

Il s'agit de métriques d'activité de la base de données, et non de facturation ou d'analyses Langfuse. Les totaux de jetons dépendent des valeurs persistées avec les messages et ne calculent pas le coût monétaire.

## Plages de dates et recherche [#date-ranges-and-search]

La plage par défaut est de sept jours. Les préréglages couvrent les dernières 24 heures, 7 jours ou 30 jours. Une plage personnalisée peut s'étendre sur au plus 30 jours calendaires et est regroupée selon le fuseau horaire actuel du navigateur.

Le filtre d'Agent utilise des cases à cocher explicites avec une commande **All agents** fixe pour sélectionner ou désélectionner tous les Agents accessibles. Lorsque plus de dix Agents sont disponibles, la recherche filtre les noms sans tenir compte de la casse, sans pour autant supprimer les sélections effectuées en dehors des résultats actuels.

La recherche de conversations récentes correspond à un ID de conversation ou à une identité d'utilisateur. La recherche commence à partir de trois caractères, accepte jusqu'à 200 caractères et maintient la table des conversations récentes paginée à 10 lignes par page. Les cartes de résumé, les meilleurs utilisateurs et les métriques de désabonnement continuent de représenter la plage de dates sélectionnée plutôt que le sous-ensemble des résultats de recherche.

## Notes sur les données et le déploiement [#data-and-deployment-notes]

Insights interroge directement les collections Conversation, Message et User existantes et ne nécessite aucune base de données analytique distincte. Les résultats reflètent uniquement les enregistrements persistants : les données temporaires ou supprimées qui ne sont plus dans MongoDB ne peuvent pas apparaître. L'API délimite les plages personnalisées, les listes de résultats, les tailles de page, la saisie de recherche et la portée du locataire avant d'exécuter ses agrégations.

Voir [`ENABLE_INSIGHTS`](/docs/configuration/dotenv#admin-insights) pour le commutateur de déploiement.
