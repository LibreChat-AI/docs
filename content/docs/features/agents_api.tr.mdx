LibreChat dışındaki kodların agent'larınızla iletişim kurmasını Agents API sağlar. Herhangi bir OpenAI SDK'sını kendi instance'ınıza yönlendirin, model olarak bir agent ID'si iletin; agent'ın tüm yapılandırmasını (talimatlar, araçlar, dosyalar) tanıdık bir API arkasında elde edersiniz. Bunu bir agent'ı bir script'e, bir CI işine veya başka bir ürüne bağlamak için kullanın.

Üç bölüm vardır:

- **Çıkarım (Inference)**: Chat Completions ve Open Responses; bir API anahtarı (veya yönetici tarafından ayarlanmışsa kendi OIDC belirteçleriniz) ile kimlik doğrulaması yapılır.
- **Agent Olayları**: Bir webhook gibi başka bir sistemden bir agent'a iş verin ve yapılıp yapılmadığını takip edin. Yalnızca API anahtarları.
- **Agent Yönetimi**: güvenilir bir hizmetten, makine OIDC belirteçlerini kullanarak agent'ları ve skill'leri oluşturun ve düzenleyin.

<Callout type="warning" title="Beta">
  Uç noktalar, istek formatları ve yanıtlar sürümler arasında hâlâ değişebilir.
</Callout>

## Bir API anahtarı alın [#get-an-api-key]

**Ayarlar**'ı açın, **Veri ve Gizlilik** bölümüne gidin ve **API anahtarları** altında **Agent API Keys** seçeneğini bulun. **Yönet**'e tıklayın, ardından **Create API Key** seçeneğine tıklayın, anahtara bir ad verin, bir son kullanma süresi seçin (7 gün ile 1 yıl arası veya **süresiz**) ve anahtarı hemen kopyalayın: yalnızca bir kez gösterilir.

Bir anahtar sizin yerinize hareket eder. API üzerinden erişebildiğiniz her şeye, anahtarı elinde tutan herkes de erişebilir; bu nedenle artık kullanmadığınız anahtarları silin. Bir anahtarı silmek, onu kullanan uygulamaların erişimini anında keser.

Bölümü görmüyorsanız, rolünüze Agents API erişimi verilmemiş demektir.

## Hangi ajanları çağırabilirsiniz [#which-agents-you-can-call]

Sahip olduğunuz veya paylaşılan ajanları çağırabilirsiniz. Başkasına ait bir ajan için, sahibinin Agent Builder alt bilgisindeki **Uzak Erişim** düğmesini (dünya simgesi) kullanarak size erişim izni vermesi gerekir. Bu, normal paylaşımdan ayrıdır: LibreChat'te bir ajanla sohbet edebilmek, o ajanı API üzerinden çağırmanıza izin vermez.

Agent kimliğine ihtiyacınız var; bu kimlik, oluşturucuda **Gelişmiş Ayarlar** altında kopyalama düğmesiyle birlikte gösterilir. `GET /api/agents/v1/models` anahtarınızın çağırabileceği agent'ları listeler, `GET /api/agents/v1/models/{model}` ise tek bir agent'ı döndürür.

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions` uç noktası OpenAI Chat Completions formatını takip eder; bu nedenle mevcut OpenAI istemcileri yalnızca temel URL değiştirilerek kullanılabilir:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

Aynı isteği curl ile gönderin:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` uygulaması [Open Responses](https://www.openresponses.org/) spesifikasyonunu uygular. Bu spesifikasyon agent iş yükleri için tasarlanmıştır: akıl yürütme, araç çağrıları ve akış (streamed) olayları, sonradan eklenmiş özellikler olarak değil, formatın doğal bir parçası olarak yer alır. LibreChat'in bundan sonra üzerine inşa ettiği arayüz budur; yeni entegrasyonlar için bu arayüzü tercih edin.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` kayıtlı bir yanıtı döndürür ve `GET /api/agents/v1/responses/models` burada kullanılabilir olan agent'ları listeler.

### Kendi fonksiyon araçlarınız [#your-own-function-tools]

Bir Responses isteğinde standart `function` araçlarını geçirebilirsiniz. LibreChat bunları modele gösterir ancak çalıştırmaz: model bir tanesini seçtiğinde yanıt bir `function_call` öğesi içerir ve fonksiyonu kendiniz çalıştırırsınız. Devam etmek için, `input` alanında bu `function_call` öğesini tekrarlayan ve ardından aynı `call_id` ile bir `function_call_output` içeren yeni bir istek gönderin:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Hiçbir bağlantı iki istek arasında açık tutulmaz ve yalnızca `previous_response_id` yeterli değildir; çağrıyı ve çıktısını yeniden oynatmanız gerekir. Araç adları harf, rakam, alt çizgi ve tire içerebilir, benzersiz olmalıdır ve agent'ın kendi araçlarından birinin adını gölgeleyemez. Sizin araçlarınızdan birini çağıran bir tur, aynı anda agent'ın araçlarını çağıramaz; modelden yeniden deneme istenir.

### API üzerinden araç onayı [#tool-approval-over-the-api]

Yöneticiniz bazı araçlar için onay gerektiriyorsa, API çağrıları kimseye onay sormak için durdurulamaz. Onay gerektirecek veya reddedilecek araçlar bunun yerine engellenir. Yöneticiler, denetimsiz bir istemcinin çalıştırmasının amaçlandığı araçlara açıkça izin vermelidir.

## Agent Events [#agent-events]

Agent Events, başka bir sistemin bir agent'a iş devretmesine ve daha sonra geri dönüp ne olduğunu görmesine olanak tanır. Bu özellik beta aşamasındadır. Olaylar, sizi ve kaynağı tanımlayan Agents API anahtarınızı kullanır; yalnızca OIDC ile yapılandırılmış kurulumlar bu özelliği kullanamaz. Ayrıca kendi hız sınırlamaları vardır: [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Bir olay üç moddan birinde gelir:

- `fire` ile agent ile yeni bir konuşma başlatılır.
- `continue` bir önceki adımda bağladığınız bir alt ajana yeni bir tur ekler (aşağıya bakın).
- `steer`, bir `fire` işleminin döndürdüğü konuşma ve üretim kimliğiyle tanımlanan, hâlâ devam eden bir çalıştırmaya yönlendirme ekler.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Her istekte tek bir `Idempotency-Key` bulunmalıdır (1 ila 256 harf, rakam veya `._~:/+=-` karakterleri). Aynı teslimatı yeniden denediğinizde bu anahtarı yeniden kullanın; anahtarı farklı içerik için kullanmak bir çakışmadır. LibreChat, olayın kaynağını API anahtarınızdan belirler ve gönderdiğiniz herhangi bir kaynak değerini yok sayar. Yük (payload) saklandığı için gizli bilgileri içine koymayın. Aynı şeyle ilgili olayların sırayla işlenmesi gerektiğinde `orderingKey` kullanın.

Yanıt, bir teslimat kimliği ve aynı anahtarla yoklama yapmak için bir `Location` ile birlikte `202 Accepted` olur:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Bir teslimat `pending`, `leased`, `succeeded` veya `dead` durumlarından birinde olabilir. Bağlı bir `continue` için `succeeded` yalnızca turun başladığı anlamına gelir. Bu noktadan sonra `handling` durumu `started` değerinden `applied`, `completed_no_action`, `failed` veya `cancelled` değerlerinden birine geçer. Bir `expectedAction` (bir araç adı ve isteğe bağlı olarak bazı argümanları) gönderirseniz, `applied` değeri LibreChat'in o aracın eşleşen argümanlarla çağrıldığını gördüğü anlamına gelir; modelin metin içinde söylediği şeyler bu durumu etkilemez.

Agent Events, herkese açık bir webhook alıcısı değildir. Olaylar, webhook'larını imzalayan bir sağlayıcıdan geliyorsa, bunları yönlendirmeden önce imzayı kendi adaptörünüzde doğrulayın.

### Olay odaklı alt ajanlar [#event-driven-child-agents]

Birçok olay boyunca devam eden bir konuşmayı alt ajanla sürdürmek için, onu bir kez bağlayın, ardından bu bağlamaya `continue` olayları gönderin:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

The parent must be a normal agent conversation, and the target must be one of that agent's direct subagents (or the agent itself, if self-spawn is allowed). `actorId` is up to 128 characters. A new binding returns `201` and a replay returns `200`, both with the binding `id`. Later turns reference it:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Her bağlama bir seferde tek bir olayı işler: mevcut tur nihai bir işleme durumuna ulaşana kadar sıradaki olay bekler, ancak farklı bağlamalar paralel olarak çalışır. Bağlanmış bir alt öğe Ask User veya araç onayı için duraklayabilir; sonraki olayları, biri LibreChat'te yanıtlayana kadar bekler. Bunun için dayanıklı MongoDB checkpointer'ı (varsayılan) gerekir. Üst konuşmada, bağlanmış her alt öğe, bağlamanın ait olduğu mesajın altında bir satır olarak görünür ve alt ajan etkinlik panelini açar.

Bir bağlama (binding) yalnızca onu oluşturan API anahtarı, kullanıcı ve kiracı (tenant) ile çalışır. Alt konuşma (child thread), sohbet listesinde görünmez ve uygulamada salt okunurdur.

Gözlem niteliğindeki olaylar için, örneğin "bir oyun ilerledi" gibi, aynı `coalesce.key` değerini verin. LibreChat, bu olaylardan en fazla 8 tanesini (750 ms ve 512 KiB sınırları dahilinde) tek bir tura birleştirir. Her olay yine de kendi makbuzunu alır. Komutları, onayları ve `expectedAction` içeren hiçbir şeyi birleştirmeyin.

## Temsilci Yönetimi API'si [#agent-management-api]

Agent Management API, güvenilir bir servisin tarayıcı oturumu olmadan agent ve skill oluşturmasına, değiştirmesine ve silmesine olanak tanır. Bu API beta aşamasındadır ve kendi kimlik doğrulamasını kullanır: yönetici tarafından [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) altında listelenen istemcilerden alınan makine OIDC token'ları. Her istemci, mevcut tek bir LibreChat kullanıcısına ve tenant'a bağlıdır; her istek, o kullanıcının izinleri ve erişimiyle gerçekleştirilir. Bu API hiçbir kişiyi yönetici yapmaz.

| Yöntem   | Rota                                         | Amaç                               |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST`   | `/api/agents/v1/agents`                      | Bir agent oluşturun                |
| `GET`    | `/api/agents/v1/agents`                      | Erişilebilir agent'ları listeleyin |
| `GET`    | `/api/agents/v1/agents/{id}`                 | Bir agent'ı okuyun                 |
| `PATCH`  | `/api/agents/v1/agents/{id}`                 | Bir agent'ı güncelleyin            |
| `DELETE` | `/api/agents/v1/agents/{id}`                 | Bir agent'ı silin                  |
| `POST`   | `/api/agents/v1/agents/{id}/files`           | Bir dosya yükleyin ve ekleyin      |
| `GET`    | `/api/agents/v1/agents/{id}/files`           | Eklenmiş dosyaları listeleyin      |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}`  | Bir dosyayı ayırın                 |
| `GET`    | `/api/agents/v1/skills`                      | Erişilebilir becerileri listeleyin |
| `POST`   | `/api/agents/v1/skills`                      | Bir beceri oluşturun               |
| `GET`    | `/api/agents/v1/skills/{id}`                 | Bir beceriyi okuyun                |
| `PATCH`  | `/api/agents/v1/skills/{id}`                 | Bir beceriyi güncelleyin           |
| `DELETE` | `/api/agents/v1/skills/{id}`                 | Bir beceriyi silin                 |
| `GET`    | `/api/agents/v1/skills/{id}/files`           | Bir becerinin dosyalarını listeleyin |
| `GET`    | `/api/agents/v1/skills/{id}/files/{path}`    | Bir beceri dosyasını okuyun        |
| `PUT`    | `/api/agents/v1/skills/{id}/files/{path}`    | Bir beceri dosyası oluşturun veya değiştirin |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}`    | Bir beceri dosyasını silin         |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agent payloads take the same fields as the Agent Builder and reject unknown ones; `model` is required on create. Lists take `limit` (1 to 100, default 20) and a `cursor`; when `has_more` is true, pass the returned `after` as the next cursor. File uploads are `multipart/form-data` with one `file` and a `tool_resource` such as `context`, `file_search`, or `execute_code`, subject to the usual upload limits.

Skill create, `name`, `description`, `body` ve isteğe bağlı olarak `displayTitle`, `frontmatter`, `category` ve `alwaysApply` alanlarını kabul eder. Güncellemeler, skill'in mevcut sürümünü `expectedVersion` olarak göndermelidir; böylece iki yazar birbirinin değişikliklerinin üzerine sessizce yazamaz.

Hatalar `invalid_request`, `not_found`, `permission_denied`, `conflict` ve `internal_error` kodlarını kullanır. Erişiminiz olmayan bir kaynak `not_found` olarak dönebilir. Hatalı veya eksik kimlik bilgileri `401` döndürür.

Yönetici etkinleştirirse, yönetim rotalarının bir OpenAPI açıklaması `/api/openapi.json` adresinde sunulur ve etkileşimli dokümantasyon `/api/docs` adresinde bulunur. Çıkarım (inference) veya olayları (events) kapsamaz. Bkz. [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Kullanım ve faturalandırma [#usage-and-billing]

API istekleri, uygulamadaki sohbetlerle tam olarak aynı şekilde token bakiyenizden düşülür. Yanıttaki kullanım toplamları, alt ajan çağrılarını da içerir; bunlar ayrı `primary` ve `subagent` dökümleriyle gösterilir. Sağlayıcının bildirdiği durumlarda önbellek ve akıl yürütme token'ları da dahil edilir. Ayrıntılar için bkz. [Token Kullanımı](/docs/configuration/token_usage).

## Kurulum [#setup]

Agents API, normal kullanıcılar için, bir yönetici rollerine Remote Agents izinlerini verene kadar kapalıdır. Bu izin, [Yönetici Paneli](/docs/features/admin_panel) üzerinden veya [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents) ile verilebilir. Yöneticilerde bu izin varsayılan olarak bulunur. API anahtarı kimlik doğrulaması varsayılan olarak açıktır; anahtarların yerine ya da onlarla birlikte kendi OIDC sağlayıcınızdan gelen belirteçleri kabul etmek için [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi) bölümüne bakın. Management API ayrı olarak [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) altında yapılandırılır, olay iletimi ayarları ise [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven) altındadır.
