<Callout type="warning" title="Beta Özelliği">
Agents API şu anda beta aşamasındadır. Kararlı bir sürüme doğru ilerlerken endpoint'ler, istek/yanıt formatları ve davranışlar değişebilir.
</Callout>

LibreChat, çıkarım (inference) ve olay iletimi (event-delivery) API'leri aracılığıyla ajanları harici uygulamalara, betiklere ve servislere açar.

## Genel Bakış [#overview]

Agents API, iki çıkarım arayüzü, kimlik doğrulamalı olay iletimi ve beta yönetim rotaları sağlar:

- **OpenAI ile uyumlu Chat Completions** — `POST /api/agents/v1/chat/completions`
- **Open Responses API** — `POST /api/agents/v1/responses`
- **Ajan Etkinlikleri** — `POST /api/agents/v1/events`
- **Ajan Yönetimi** — `/api/agents/v1/agents`
- **Beceri Yönetimi** — `/api/agents/v1/skills`

Çıkarım arayüzleri, API anahtarı kimlik doğrulamasını, isteğe bağlı OIDC kimlik doğrulamasını ve akış yanıtlarını destekler. Agent Events, LibreChat'in her teslimatı kararlı bir kaynak kimliğine bağlayabilmesi için Remote Agents API anahtarı kimlik doğrulamasını kullanır. Yönetim rotaları ise bunun yerine, bir OIDC makine istemcisini mevcut bir LibreChat kullanıcısına ve kiracısına bağlayan bir dağıtım izin listesi kullanır.

LibreChat, ajanlara hizmet vermek için birincil API çerçevesi olarak [Open Responses](https://www.openresponses.org/) sistemini benimsiyor. Chat Completions endpoint'i, mevcut OpenAI uyumlu araçlarla geriye dönük uyumluluk sağlasa da, Open Responses endpoint'i gelecekteki yönü temsil etmektedir.

## Agents API'sini Etkinleştirme [#enabling-the-agents-api]

Agents API, `remoteAgents` arayüz yapılandırması ile sınırlandırılmıştır. Tüm izinler varsayılan olarak `false` değerindedir.

```yaml filename="librechat.yaml"
interface:
  remoteAgents:
    use: true
    create: true
```

Tüm mevcut seçenekler için [Interface Configuration — remoteAgents](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents) bölümüne bakın.

**Not:** Yönetici kullanıcılar, varsayılan olarak tüm uzak aracı (remote agent) izinlerine sahiptir.

### OpenAPI Spesifikasyonu ve Etkileşimli Dokümanlar [#openapi-specification-and-interactive-docs]

LibreChat, herkese açık Agents API spesifikasyonunu `/api/openapi.json` adresinde ve etkileşimli Swagger UI dokümantasyonunu `/api/docs` adresinde sunabilir. Her iki rota da varsayılan olarak devre dışıdır. Bunları üst düzey `openapi` ayarı ile etkinleştirin:

```yaml filename="librechat.yaml"
openapi:
  enabled: true
```

Bu teknik özellik, bu sayfada açıklanan genel çıkarım (inference), etkinlik (event), Ajan (Agent) yönetimi ve Beceri (Skill) yönetimi rotalarını kapsar. Dağıtımınız API dokümantasyonunu dışarıya açmayı amaçlamadığı sürece bu rotaları devre dışı bırakın.

## API Anahtarı Yönetimi [#api-key-management]

`remoteAgents.use` ve `remoteAgents.create` özellikleri etkinleştirildiğinde, kullanıcılar LibreChat arayüzünden API anahtarları oluşturabilirler. Bu anahtarlar, Agents API'sine yapılan isteklerin kimlik doğrulamasını sağlar.

## Kimlik Doğrulama [#authentication]

Agents API, bağımsız olarak veya birlikte kullanılabilen iki kimlik doğrulama yöntemini destekler.

### API Anahtarı [#api-key]

API anahtarı kimlik doğrulaması varsayılan olarak etkindir. `remoteAgents.use` ve `remoteAgents.create` etkinleştirildikten sonra LibreChat arayüzünden API anahtarları oluşturun.

```bash
Authorization: Bearer <YOUR_API_KEY>
```

### OIDC Bearer Token [#oidc-bearer-token]

Altyapınızın halihazırda bir OIDC sağlayıcısına sahip olduğu makineden makineye senaryolar için, bir LibreChat API anahtarı olmadan doğrudan OIDC Bearer token'ları ile kimlik doğrulaması yapabilirsiniz.

`librechat.yaml` içinde OIDC kimlik doğrulamasını yapılandırın:

```yaml filename="librechat.yaml"
endpoints:
  agents:
    remoteApi:
      auth:
        apiKey:
          enabled: false
        oidc:
          enabled: true
          issuer: https://auth.example.com/realms/myrealm
          # jwksUri is optional and auto-discovered from issuer if omitted
          audience: my-client-id
```

Ardından OIDC erişim belirtecinizle (access token) API'yi çağırın:

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_OIDC_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "Hello!"}'
```

<Callout type="info">
  OIDC belirteci, LibreChat içinde halihazırda var olan bir kullanıcıya ait olmalıdır. Eşleştirme işlemi önce `sub` talebini kullanır, ardından sırasıyla `email`, `preferred_username` veya `upn` değerlerine başvurur.
</Callout>

Tüm yapılandırma seçenekleri için [Agents Endpoint - remoteApi](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi) bölümüne bakın.

<Callout type="warning" title="Agent Events bir API anahtarı gerektirir">
  Yalnızca OIDC kimlik doğrulaması, Agent Events uç noktaları için desteklenmemektedir. Bağlamalar oluştururken, olayları kuyruğa alırken ve teslimat durumunu sorgularken bir Remote Agents API anahtarı kullanın.
</Callout>

## Temsilci Yönetimi API'si [#agent-management-api]

Beta Agent Management API, bir servisin tarayıcı oturumu olmadan Agent'ları ve onlara bağlı kaynakları yönetmesine olanak tanır. Bu API, çıkarım (inference) ve Agent Events'ten bağımsız olarak doğrulanır: yalnızca [`endpoints.agents.managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) altında yapılandırılmış OIDC makine belirteçleri (machine tokens) kabul edilir.

Yapılandırılmış her OAuth istemcisi, mevcut bir LibreChat `userId` ve `tenantId` değerine bağlanır. Belirteç doğrulamasından sonra, her istek o kullanıcı olarak çalıştırılır ve kullanıcının mevcut rol yetkilerini, Ajan ve Beceri ACL'lerini, sağlayıcı kısıtlamalarını, araç izinlerini, dosya sınırlarını ve kiracı izolasyonunu korur. Bir istemci bağlaması, kullanıcıyı yönetici yapmaz veya kullanıcının başka şekilde yönetemeyeceği kaynaklara erişim izni vermez.

### Ajan Rotaları [#agent-routes]

| Yöntem   | Rota                                       | Amaç                                         |
| -------- | ------------------------------------------ | -------------------------------------------- |
| `POST`   | `/api/agents/v1/agents`                    | Bir Agent oluşturun                          |
| `GET`    | `/api/agents/v1/agents`                    | Erişilebilir Agent'ları listeleyin          |
| `GET`    | `/api/agents/v1/agents/{id}`               | Erişilebilir bir Agent'ı okuyun             |
| `PATCH`  | `/api/agents/v1/agents/{id}`               | Bir Agent'ı güncelleyin                     |
| `DELETE` | `/api/agents/v1/agents/{id}`               | Bir Agent'ı silin                           |
| `POST`   | `/api/agents/v1/agents/{id}/files`         | Bir Agent kaynak dosyası yükleyin ve ekleyin |
| `GET`    | `/api/agents/v1/agents/{id}/files`         | Agent'ın erişilebilir ekli dosyalarını listeleyin |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | Bir ekli dosyayı Agent'tan kaldırın         |

Ajan oluşturma ve güncelleme yükleri (payloads), Ajan Oluşturucu (Agent Builder) ile aynı harici olarak desteklenen alanları kullanır ve bilinmeyen üst düzey alanları reddeder. Oluşturma işlemi bir `model` gerektirir; güncelleme işlemi ise yalnızca sağlanan alanları kabul eder. Yanıtlar, desteklenen Ajan yapılandırmasının yanı sıra `id`, `provider`, boş değer alabilen `model`, `version`, `createdAt` ve `updatedAt` alanlarını, kalıcılık sahipliği alanları olmaksızın açığa çıkarır.

Listeler 1 ile 100 arasında `limit` kabul eder, varsayılan değer 20'dir ve opak bir `cursor` kullanır. `has_more` değeri true olduğunda, döndürülen `after` değerini bir sonraki imleç (cursor) olarak iletin; istemcilerde imleçlerin kodunu çözmeyin veya oluşturmayın.

```bash
curl https://your-librechat-instance/api/agents/v1/agents?limit=20 \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN"
```

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Dosya yüklemeleri, bir `file` ve `context`, `file_search` veya `execute_code` gibi bir `tool_resource` değeri ile `multipart/form-data` kullanır. LibreChat, kaynağı eklemeden önce dağıtım yeteneği, rol ataması, yükleme hız sınırı, dosya başına sınır, dosya sayısı ve toplam boyut kontrollerini uygular. Bir dosyayı kaldırmak, Agent üzerinde düzenleme erişimi gerektirir ve temel dosya yetkilendirme kurallarını zayıflatmaz.

### Beceri Rotaları [#skill-routes]

| Metot | Rota | Amaç |
| ------- | ---------------------------------------------------- | ------------------------------------- |
| `GET`   | `/api/agents/v1/skills`                              | Erişilebilir Yetenekleri listele |
| `GET`   | `/api/agents/v1/skills/{id}`                         | Bir erişilebilir Yeteneği oku |
| `PATCH` | `/api/agents/v1/skills/{id}`                         | Desteklenen Yetenek meta verilerini güncelle |
| `GET`   | `/api/agents/v1/skills/{id}/files`                   | Yetenek içindeki dosyaları listele |
| `GET`   | `/api/agents/v1/skills/{id}/files/{relativePath}`    | Bir Yetenek dosyasını oku |
| `PUT`   | `/api/agents/v1/skills/{id}/files/{relativePath}`    | Desteklenen bir dosyayı oluştur veya değiştir |

Beceri işlemleri, ilişkili kullanıcı tarafından görülebilen Beceriler ile sınırlıdır. Okuma işlemleri Beceri erişimi gerektirirken, meta veri veya dosya yazma işlemleri ilgili düzenleme ve Beceri yazma izinlerini gerektirir. Yollar, Beceri kök dizini altında normalleştirilir; dizin geçişleri (traversal), desteklenmeyen dosyalar ve aşırı büyük içerikler reddedilir.

### Hatalar ve Kimlik Doğrulama [#errors-and-authentication]

Yönetim yanıtları `invalid_request`, `not_found`, `permission_denied`, `conflict` veya `internal_error` kodlarını içeren yapılandırılmış hatalar kullanır. Kaynak yetkilendirme hataları, çağıranların erişilemeyen kimlikleri (ID) sorgulamasını engellemek amacıyla `not_found` olarak döndürülebilir.

Makine belirteçlerinin (tokens) süresi dolmamış olmalı, yapılandırılmış yayıncıyla eşleşmeli, `azp` veya `client_id` aracılığıyla izin verilenler listesindeki bir istemciyi tanımlamalı ve yapılandırılmış konu kuralını karşılamalıdır. Varsayılan olarak, belirteçlerin yapılandırılmış hedef kitleyle (audience) de eşleşmesi gerekir. `aud` yerine `client_id` ile makine erişim belirteçleri veren Amazon Cognito gibi sağlayıcılar için `tokenUse: access` ayarını yapın, `audience` kısmını atlayın ve `requiredScopes` ile beklenen OAuth kapsamını zorunlu tutun. Eksik yapılandırma veya geçersiz kimlik bilgileri `401` hatası döndürür; silinme sürecindeki bağlı bir hesap ise `409` hatası döndürür. Eksiksiz talep ve bağlama kuralları için [`managementApi.auth.oidc`](/docs/configuration/librechat_yaml/object_structure/agents#managementapiauthoidc) ve [`managementApi.auth.clients`](/docs/configuration/librechat_yaml/object_structure/agents#managementapiauthclients) bölümlerine bakın.

## Endpoints [#endpoints]

### Chat Completions (OpenAI-compatible) [#chat-completions-openai-compatible]

```
POST /api/agents/v1/chat/completions
```

LibreChat örneğinizi işaret ederek herhangi bir OpenAI uyumlu SDK kullanın. `model` parametresi bir aracı (agent) kimliğine karşılık gelir.

**curl ile örnek:**
```bash
curl -X POST https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [
      {"role": "user", "content": "Hello, what can you help me with?"}
    ],
    "stream": true
  }'
```

**OpenAI SDK (Python) ile örnek:**
```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY"
)

response = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Hello!"}],
    stream=True
)

for chunk in response:
    print(chunk.choices[0].delta.content, end="")
```

### Modelleri Listele [#list-models]

```
GET /api/agents/v1/models
```

Mevcut ajanları modeller olarak döndürür. API anahtarınızla hangi ajanlara erişilebileceğini keşfetmek için kullanışlıdır.

### Open Responses API [#open-responses-api]

```
POST /api/agents/v1/responses
```

Open Responses endpoint'i, OpenAI tarafından başlatılan ve açık kaynaklı yapay zeka topluluğu tarafından oluşturulan bir açık çıkarım standardı olan [Open Responses specification](https://www.openresponses.org/) ile uyumludur. Akıl yürütme, araç kullanımı, yapılandırılmış çıktılar ve akış halindeki anlamsal olaylar için yerel destekle birlikte, etmen tabanlı (agentic) iş akışları için tasarlanmıştır.

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "input": "What is the weather today?"
  }'
```

#### Arayan Tarafından Yürütülen İşlev Araçları (Caller-Executed Function Tools) [#caller-executed-function-tools]

Open Responses endpoint'i, çağırıcı tarafından sağlanan standart `function` araçlarını kabul eder. LibreChat bu tanımları modele sunar ancak bunları yürütmez. Model birini seçtiğinde, yanıt, çağırıcının yürütmesi için bir `function_call` çıktı öğesi içerir.

Devam etmek için, döndürülen `function_call` öğesini ve ardından eşleşen bir `function_call_output` öğesini içeren `input` ile yeni bir istek gönderin. Bu devir işlemi durumsuzdur (stateless): askıya alınmış bir çalışma (suspended run) oluşturmaz ve yalnızca `previous_response_id`, yeniden oynatılan araç değişiminin yerini alamaz.

```json
{
  "model": "agent_abc123",
  "input": [
    {
      "type": "function_call",
      "call_id": "call_abc123",
      "name": "lookup_order",
      "arguments": "{\"order_id\":\"A-42\"}"
    },
    {
      "type": "function_call_output",
      "call_id": "call_abc123",
      "output": "{\"status\":\"shipped\"}"
    }
  ]
}
```

Çağırıcı araç adları harfler, rakamlar, alt çizgiler ve kısa çizgiler içerebilir. Adlar benzersiz olmalı ve sunucu tarafından sağlanan bir aracın yerini alamaz. Çağırıcı tarafından yürütülen bir araç, kendi sırasında seçilen tek araç olmalıdır; model bunu sunucu tarafından yürütülen araçlarla karıştırırsa, LibreChat modelden çağırıcı aracını tek başına yeniden denemesini ister.

LibreChat tarafından yürütülen Agent araçları için, her iki başsız (headless) çıkarım uç noktası da `deny`, `ask` ve programatik kancalar dahil olmak üzere etkinleştirilmiş bir [`endpoints.agents.toolApproval`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval) politikasını zorunlu kılar. Bu çağrıların etkileşimli bir onay/devam ettirme kanalı yoktur: `deny` ve `ask` seçenekleri, bir onay istemi açmak yerine aracı engeller. Yalnızca API istemcisinin gözetimsiz çalıştırabilmesi gereken araçlar için açık izinler yapılandırın; politika devre dışı bırakıldığında, onay kancaları çalışmaz. Arayan tarafından yürütülen işlev araçları, arayanın sorumluluğunda kalmaya devam eder.

## Agent Events [#agent-events]

Agent Events, kimliği doğrulanmış bir denetleyicinin veya kaynak bağdaştırıcısının bir Agent'a kalıcı iş iletmesini sağlar. Event teslimi beta aşamasında bir özelliktir ve istek, yanıt ve çalışma zamanı davranışı değişebilir.

Uç noktalar (endpoints) kimliği doğrulanmış kullanıcıyı, kiracıyı (tenant) ve API anahtarını kullanır; hedef Agent, mevcut Remote Agents izinleri kapsamında o kullanıcı tarafından görülebilir olmalıdır. Agent Event istekleri ayrıca özel [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits) havuzunu kullanır.

### Bir Etkinlik Sunun [#deliver-an-event]

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Tam olarak bir `Idempotency-Key` başlığı gönderin ve aynı kaynak-olay-hedef teslimatını yeniden denerken bunu tekrar kullanın. Anahtar 1-256 arası harf, rakam veya `._~:/+=-` karakterlerini içermelidir. Farklı teslimat içeriğiyle bir anahtarın yeniden kullanılması çakışma döndürür.

Arayan taraf `id`, `type`, `occurredAt` ve temizlenmiş `payload` değerlerini sağlar. LibreChat, arayan tarafın sağladığı tüm `event.source` değerlerini kimliği doğrulanmış API anahtarı kimliğiyle değiştirir ve kullanıcıyı, kiracıyı, istek kimliğini ve alınma zamanını türetir. Kabul edilen teslimatlar kalıcı hale getirildiğinden, etkinlik yüklerine (payloads) kimlik bilgileri veya taşıma sırları yerleştirmeyin.

`orderingKey` isteğe bağlıdır. Farklı kaynaklardan gelen teslimatların aynı kaynak için sıralı kalması gerektiğinde sabit bir değer kullanın.

Başarılı bir istek `202 Accepted` yanıtını, opak bir teslimat `id` değerini, mevcut durumunu ve bir `Location` başlığını döndürür. Bu konumu sorgulayın:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Teslimat `pending`, `leased`, `succeeded` veya `dead` durumunda olabilir. Durum yanıtı, denemeleri ve zaman damgalarını, ayrıca sonuçlandığında bir sonucu veya genel bir hatayı içerir; depolanan yükü, sıralama anahtarını, yeniden deneme geçmişini veya çalışan kimliğini açığa çıkarmaz. Durum erişimi aynı kullanıcı, kiracı ve API anahtarı kaynağı ile sınırlandırılmıştır.

Bağlı bir `continue` için `succeeded`, istenen işin bittiği anlamına değil, Ajan turunun kabul edildiği anlamına gelir. Bu nedenle durumu, kalıcı bir `handling` yaşam döngüsünü de açığa çıkarır: `started` ve ardından `applied`, `completed_no_action`, `failed` veya `cancelled` durumlarından tam olarak biri.

Eylem farkındalığına sahip kaynaklar, bir araç adı ve isteğe bağlı bağımsız değişken alt kümesi içeren bir `expectedAction` içerebilir. LibreChat, `applied` durumunu yalnızca o tam üretim, ana bilgisayar tarafından gözlemlenen ve sözleşmeyle eşleşen araç kanıtlarıyla tamamlandığında bildirir; model tarafından oluşturulan metinler asla kanıt olarak kabul edilmez. `fire`, `steer` ve sınırsız `continue` teslimleri `expectedAction` öğesini reddeder.

Başarılı `fire` sonuçları, daha sonraki bir `steer` etkinliğinin hedefleyebileceği konuşma ve üretim kimliğini içerir.

### Olay Güdümlü Alt Temsilciler (Event-Driven Child Agents) [#event-driven-child-agents]

Harici bir sistem, bir kaynak aktörü doğrudan bir alt Agent'a bağlayabilir ve ardından aynı alt konuşmayı olaylar boyunca sürdürebilir. Bağlı alt devamlılıklar; API anahtarı kimliği, bağlama sahipliği, üst ilişki ve Agent yetkilendirme kontrolleri başarılı olduktan sonra otomatik olarak gerçekleşir; bunun için ayrı bir özellik açma/kapama anahtarı yoktur.

Aktörü, sonraki sıralarını iletecek olan aynı API anahtarıyla kaydedin:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

`actorId` 128 karaktere kadar içerebilir. Ebeveyn, sıradan bir Agent konuşması olmalı ve hedef, o Agent'ın doğrudan Subagent'larından biri veya izin verilen bir self-spawn olarak yapılandırılmış olmalıdır. Yeni bir bağlama (binding) `201` döndürür; idempotent bir tekrar `200` döndürür. Her iki yanıt da `id`, `actorId`, `agentId` ve `threadId` içerir.

Döndürülen bağlama kimliği (binding ID) ile sonraki turları gönderin:

```http
POST /api/agents/v1/events
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
Idempotency-Key: game-12-ply-17-hanae
Content-Type: application/json

{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": {
    "id": "game-12-ply-17",
    "type": "chess.turn.ready",
    "occurredAt": 1786968000000,
    "payload": { "gameId": "game-12", "expectedPly": 17 }
  },
  "input": "Your clock is running. Read the position and submit one legal move.",
  "expectedAction": {
    "tool": "submit_move",
    "arguments": { "gameId": "game-12" }
  }
}
```

LibreChat, alt Agent, thread, en son dal yaprağı ve sıralama şeridini gönderimden hemen önce bağlamadan çözer. Çağıran tarafından sağlanan hedef ve sıralama alanları, bağlı bir devamı yeniden yönlendiremez. İsteğin `Idempotency-Key` değeri; teslimat yeniden denemeleri, nesil kiralama, kalıcı mesajlar, canlı etkinlik ve daha sonraki bir HITL devam ettirme süreci boyunca bu alt tur için kararlı genel kimlik haline gelir.

Her binding'in otomatik ve dayanıklı bir posta kutusu vardır. Bir sonraki etkinliği, mevcut tur `applied`, `completed_no_action`, `failed` veya `cancelled` durumuna ulaşana kadar kuyrukta bekletilir; farklı binding'ler birbirinden bağımsız kalır ve paralel olarak çalışabilir. Checkpoint devamlılığı yalnızca uyumlu ve başlatılmış bir tur için denenir. Eğer bir checkpoint eksikse veya geri yüklenemiyorsa, LibreChat; teslim alma, yetkilendirme veya beklenen eylem kontrollerini zayıflatmadan dayanıklı mesaj geçmişine geri döner.

Bağlı bir aktör, Kullanıcıya Sor (Ask User) veya araç onayı için duraklayabilir. LibreChat, bekleyen eylemi ortaya çıkarmadan önce tam imzalı askıya alma işlemini kalıcı hale getirir ve bağlamanın posta kutusu, aynı aktör çağrısı devam edene veya sonuçlanana kadar engellenmiş kalır. Event Actors, kalıcı MongoDB kontrol noktası (checkpointer) gerektirir; `type: memory` uyumlu değildir. LibreChat, nesil protokolü v2'yi müzakere eder ve kontrol noktası veya geçmiş devamlılığını otomatik olarak seçer. Mevcut protocol-v1 çalışmaları, tükenene kadar kalıcı geçmiş yolunda kalmaya devam eder. Karma sürüm dağıtım gereksinimleri için [Generation Protocol Compatibility](/docs/configuration/redis#generation-protocol-compatibility) bölümüne bakın.

### Gözlemsel Olayların Birleştirilmesi [#coalescing-observational-events]

Birkaç bağlı `continue` olayının birbirinin yerine geçebilen gözlemler olduğunu kanıtlayabilen kaynaklar, onlara aynı kaynak tanımlı `coalesce.key` değerini verebilir:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": {
    "id": "championship-7-game-12-move-18",
    "type": "chess.move.completed",
    "occurredAt": 1786968000750,
    "payload": { "gameId": "game-12", "ply": 18 }
  },
  "input": "A tournament game advanced.",
  "coalesce": { "key": "championship-commentary" }
}
```

LibreChat, uyumlu etkinlikleri 750 ms'ye kadar, en fazla 8 etkinlik ve toplam 512 KiB zarf olacak şekilde toplar. Alt öğe tek bir deterministik toplu belge alır, ancak her kaynak etkinlik kendi `Idempotency-Key` değerini, teslimat kaydını ve makbuzunu korur.

Yalnızca işlem gerektirmeyen gözlemler için birleştirme (coalescing) kullanın. `fire`, `steer`, sınırlandırılmamış `continue` ve `expectedAction` içeren teslimatlar için reddedilir; komutlar, onaylar, HITL istekleri, çitler (fences) veya bireysel zamanlaması önemli olan olaylar için kullanmayın.

Kimliği doğrulanmış ana konuşmada, her bağlı aktör kendi sahibi olan ana mesajın altında görünür. Subagent paneli, aktörler ve sıralar arasında geçiş yapabilir, önceki etkinlikleri yükleyebilir ve tam bağlı etkinliği göstermek için bir sırayı genişletebilir. Etkinlik detayları; türü, kaynağı, gerçekleşme zamanını ve beklenen eylemi içerir. Görünür çalışma adımları, araçlar, mesajlar ve mantık yürütme işaretleri, ham mantık yürütme metni olmadan dahil edilir. Ana dizin, sınırlı bir kaynak penceresinden çocuk başına en fazla 64 alt iş parçacığı ve 20 güncel görev döndürür, tamlık ima etmek yerine kesilmeyi bildirir ve yanıtı 96 KB ile sınırlar. Bu süreç ana, kullanıcı ve kiracı yetkilidir; bağlamalar, kaynak anahtar kimlikleri, kiralama belirteçleri ve çalışan durumu projeksiyona dahil edilmez.

Alt iş parçacığı, normal konuşma gezintisinde gizli kalır ve insan sohbet rotaları için salt okunurdur; üst öğenin geçici veya sona erme politikasını devralır ve bir doğrudan alt seviye ile sınırlıdır. Yalnızca bir bağlama kimliği (binding ID) erişim sağlamaz; devamlılıklar, onu oluşturan kullanıcı, kiracı ve API anahtarı ile kapsamlandırılmıştır.

### Ayrık Olay Aktörü Eylemleri [#detached-event-actor-actions]

Event Actor dönüşleri, uygun Eylemleri ayırabilir ve bunları kalıcı olarak tamamlayabilir. Eylem çalışırken teslimat, işleme yaşam döngüsü içinde kalır; kalıcı terminal kanıtı, orijinal imzalı actor çağrısını devam ettirir ve yalnızca sonuçta ortaya çıkan, ana bilgisayar tarafından gözlemlenen araç kanıtı `expectedAction` değerini karşılayabilir. Yeniden oynatmalar ve rakip kopyalar, aynı ayrılmış Eylemi iki kez başlatamaz. LibreChat, harici bir yan etkinin başlayıp başlamadığını belirleyemezse, başlatma işlemini körü körüne yeniden denemek yerine karantinaya alır.

LibreChat, seçilen yerleşik üretim deposu destek sunduğunda bu dahili tamamlama işlemini otomatik olarak etkinleştirir. Bellek içi depo; başlatma, tamamlama ve devam ettirme işlemlerini tek bir süreçte çalıştırır ve süreç sonlandıktan sonra bu çalışmaları kurtaramaz. Redis üretim akışları, dayanıklı yeniden başlatma kurtarma ve kopya devri ekler. Yetenek sahipliğindeki teslimat ve kurtarma kayıtları, karma sürümlü bir boşaltma sırasında eski talep sahipleri için görünmez kalır; operatör tarafından yönetilen bir üretici bayrağı yoktur.

## Token Kullanım Takibi [#token-usage-tracking]

Tüm Agent API çıkarım istekleri, token harcaması yapılandırıldığında kullanıcının bakiyesine karşı token kullanımını takip eder. Hem akış (streaming) hem de akış olmayan yanıtlar, faturalandırılan her bir birincil Agent ve Subagent model çağrısını en üst düzey toplamlar altında birleştirir. Yanıt ayrıca kimlik içermeyen `primary` ve `subagent` token dökümlerini de içerir. Sağlayıcı tarafından bildirildiği durumlarda önbellek (cache) ve muhakeme (reasoning) token detayları da dahil edilir.
