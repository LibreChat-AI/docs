Ein Skill ist eine `SKILL.md`-Datei: ein kurzer Frontmatter-Block, der festlegt, wann der Skill gilt, und ein Markdown-Hauptteil mit den Anweisungen. Verwende einen Skill für alles, was du sonst immer wieder in den Chat einfügen würdest, etwa einen Styleguide, eine Review-Checkliste oder die Schritte für einen wiederkehrenden Bericht. Agenten laden einen Skill nur dann, wenn er relevant ist, sodass du viele davon bereithalten kannst, ohne jeden Prompt aufzublähen.

LibreChat wird ohne jegliche Skills ausgeliefert. Jeder Skill wird von einem Benutzer geschrieben oder hochgeladen, von einem Agenten während eines Chats erstellt oder von Ihrem Administrator bereitgestellt.

## Eine Skill erstellen [#create-a-skill]

Öffnen Sie **Skills** im Seitenpanel und klicken Sie auf **+**. Wählen Sie **Write skill instructions**, um eine Anweisung direkt im Editor zu schreiben, oder **Upload a skill**, um eine `.md`-Datei oder ein `.zip`- bzw. `.skill`-Archiv mit einer `SKILL.md` zu importieren. Falls Skills im Seitenpanel nicht angezeigt wird, hat Ihr Administrator diese Funktion deaktiviert oder Ihre Rolle darf sie nicht verwenden.

Ein minimaler Skill:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing copy that must follow the company voice and terminology.
---

Write in a concise, practical tone.
Prefer active voice.
Say "workspace", never "project space".
```

Der Name muss in kebab-case angegeben werden (nur Kleinbuchstaben, Ziffern und Bindestriche), darf höchstens 64 Zeichen lang sein und muss unter Ihren Skills eindeutig sein. Beim Hochladen eines Skills mit einem bereits verwendeten Namen schlägt der Vorgang fehl, anstatt den vorhandenen Skill zu überschreiben. Namen, die mit `anthropic-` oder `claude-` beginnen, sowie Befehlswörter wie `help` oder `settings` sind reserviert.

Die Beschreibung ist wichtiger als alles andere in der Datei: Sie ist es, was das Modell liest, um zu entscheiden, ob die Skill zutrifft. „Verwenden, wenn Versionshinweise für die mobile App geschrieben werden“ löst aus; „Schreibhilfe“ tut es nicht. Setze die Auslösephrasen an den Anfang und halte die Beschreibung unter 250 Zeichen, da längere Beschreibungen in der Liste, die das Modell sieht, abgeschnitten werden. Die harten Grenzen liegen bei 1.024 Zeichen für die Beschreibung und 100.000 für den Textkörper.

### Frontmatter-Optionen [#frontmatter-options]

Neben `name` und `description` kann ein Skill außerdem Folgendes festlegen:

- `always-apply: true`: Lade den Skill bei jedem Durchlauf, anstatt darauf zu warten, dass das Modell ihn anfordert.
- `user-invocable: false`: aus dem `$`-Menü ausblenden.
- `disable-model-invocation: true`: Lass es aus der Liste weg, aus der das Modell auswählt. Du kannst es trotzdem mit `$` aufrufen.
- `allowed-tools`: eine Liste von Tools (zum Beispiel `["execute_code"]`), die der Agent für diesen Durchlauf erhält, wenn der Skill mit `$` aufgerufen oder immer angewendet wird, auch wenn der Agent diese Tools normalerweise nicht besitzt.
- `compatibility`: Freitextnotizen darüber, was die Skill benötigt, etwa einen bestimmten MCP-Server. LibreChat speichert diese Angabe, erzwingt sie jedoch nicht.

`when-to-use` funktioniert anstelle von `description`, und `alwaysApply` anstelle von `always-apply`. Schlüssel unterscheiden nicht zwischen Groß- und Kleinschreibung, und andere Schlüssel, die Sie hinzufügen, bleiben als Metadaten erhalten.

### Gebündelte Dateien [#bundled-files]

Ein Skill kann mehr als eine Datei enthalten. Ein gängiger Aufbau ist `references/` für lange Dokumente, `scripts/` für Code, den der Agent ausführen kann, und `assets/` für Vorlagen. Der Agent liest diese Dateien, wenn der Skill verwendet wird, sodass `SKILL.md` kurz bleiben und auf sie verweisen kann. Wenn Run Code aktiviert ist, sind die Dateien außerdem in der Sandbox unter `/mnt/data/skills/<skill-name>/` verfügbar. Im Skill-Viewer öffnen relative Links zwischen den Markdown-Dateien des Skills die verlinkte Datei.

In einem Archiv muss `SKILL.md` auf der obersten Ebene oder in genau einem Ordner liegen. Ein Upload ist standardmäßig auf 50 MB begrenzt (dieses Limit kann Ihr Administrator ändern), 500 Dateien und 10 MB pro Datei; Dateien mit unsicheren Pfaden werden übersprungen und gemeldet. Ein Skill mit mitgelieferten Dateien erhält in der Seitenleiste „Skills“ einen Pfeil neben seinem Namen; klappen Sie ihn auf, um die Dateien zu durchsuchen und eine davon zu öffnen.

## Einen Skill verwenden [#use-a-skill]

Es gibt drei Wege, wie ein Skill in die Unterhaltung gelangt:

- **Du wählst es aus.** Gib `$` in das Chatfeld ein und wähle einen Skill aus. Dem Text wird nichts hinzugefügt; der Skill wird als Chip über dem Eingabefeld angezeigt und für diese Nachricht geladen.
- **Das Modell wählt sie aus.** Der Agent sieht die Namen und Beschreibungen der ihm zur Verfügung stehenden Skills und lädt einen, sobald deine Anfrage dazu passt.
- **Sie wird immer angewendet.** Skills mit `always-apply: true` werden bei jedem Durchlauf geladen.

Während ein Skill geladen wird, zeigt die Nachricht **Loading** gefolgt vom Skill-Namen an, und danach **Loaded**, sobald er im Kontext verfügbar ist.

Das Modell sieht in seiner Liste nur Namen und Beschreibungen (bis zu 100 Skills), nicht die Anweisungen. Ein Skill, den Sie auswählen oder der immer angewendet wird, lädt für diesen Turn seine vollständige `SKILL.md`. Ein Turn umfasst bis zu 10 ausgewählte und 20 immer angewendete Skills, insgesamt 30; darüber hinaus werden immer angewendete Skills zuerst verworfen.

## Welche Skills ein Agent verwenden kann [#which-skills-an-agent-can-use]

Zwei Dinge entscheiden das.

Zuerst Ihre eigene Liste. Jeder Skill hat einen Schalter **Available to agent**. Wenn Sie ihn ausschalten, verschwindet der Skill aus dem `$`-Menü, aus der Auswahl, die das Modell treffen kann, und aus always-apply, ohne dass er gelöscht wird. Von Ihnen erstellte Skills sind standardmäßig eingeschaltet. Mit Ihnen geteilte Skills sind standardmäßig ausgeschaltet, sofern Ihr Administrator geteilte Skills nicht standardmäßig aktiviert hat.

Zweitens der Agent. Der Abschnitt **Skills** im Agent Builder umfasst drei Einstellungen:

- **Aus**: Der Agent verwendet keine Skills.
- **Alle**: jede Fähigkeit, die du aktiviert hast.
- **Ausgewählt**: nur die Fähigkeiten, die du zur Liste hinzufügst.

**Ausgewählt** ist die bessere Wahl für einen fokussierten Agenten. Ein Support-Agent mit 40 verfügbaren Skills wählt öfter den falschen aus als einer mit den drei, die er tatsächlich braucht.

## Von Agenten geschriebene Skills [#skills-written-by-agents]

Ein Agent mit aktivierten Skills kann Skills auch während seiner Arbeit schreiben, zum Beispiel um einen soeben erfolgreich ausgeführten Ablauf zu speichern. Er kann einen neuen Skill erstellen, wenn deine Rolle das Erstellen von Skills erlaubt, und bestehende Skills nur bearbeiten, wenn du sie bearbeiten darfst und sie im Geltungsbereich des Agenten liegen. Skills von deinem Administrator bleiben schreibgeschützt. Bei **Ausgewählt** mit einer leeren Liste sieht der Agent keinen deiner vorhandenen Skills, kann aber trotzdem neue erstellen.

## Teilen [#sharing]

Skills werden auf dieselbe Weise geteilt wie Agenten und Prompts, mit den Rollen Viewer (nutzen, kann nicht bearbeiten), Editor und Owner. Das Teilen erfordert die Berechtigung „share“ in deiner Rolle, die für reguläre Benutzer standardmäßig deaktiviert ist. Siehe [Access Control](/docs/features/access_control).

Ihr Administrator kann Skills auch bereitstellen, und zwar aus dem Dateisystem des Servers, aus [Agent Plugins](/docs/features/agent_plugins) oder gespiegelt aus einem GitHub-Repository. Diese sind in LibreChat schreibgeschützt; ändern Sie sie an der Quelle. Skills aus dem Dateisystem und Plugins sind standardmäßig eingeschaltet.

## Einrichtung [#setup]

Skills sind standardmäßig für alle Benutzer aktiviert. Administratoren können die Funktion mit der Agent-Fähigkeit `skills` deaktivieren (siehe [Agents-Endpunkt-Konfiguration](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)), festlegen, wer Skills erstellen und teilen darf, im [Admin-Panel](/docs/features/admin_panel) oder über [`interface.skills`](/docs/configuration/librechat_yaml/object_structure/interface#skills), Skills von der Festplatte oder aus GitHub bereitstellen, wie unter [Skill Sync](/docs/configuration/librechat_yaml/object_structure/skill_sync) beschrieben, und die Upload-Größenbeschränkung mit [`fileConfig.skills`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) ändern.
