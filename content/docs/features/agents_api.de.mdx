Die Agents API ermöglicht es Code außerhalb von LibreChat, mit deinen Agenten zu kommunizieren. Richte ein beliebiges OpenAI-SDK auf deine Instanz aus, übergib eine Agenten-ID als Modell, und du erhältst das vollständige Setup des Agenten (Anweisungen, Tools, Dateien) über eine vertraute API. Nutze sie, um einen Agenten in ein Skript, einen CI-Job oder ein anderes Produkt einzubinden.

Es gibt drei Teile:

- **Inferenz**: Chat Completions und Open Responses, authentifiziert mit einem API-Schlüssel (oder mit Ihren eigenen OIDC-Tokens, sofern der Administrator dies eingerichtet hat).
- **Agent Events**: Übergeben Sie einem Agenten Arbeit aus einem anderen System, etwa über einen Webhook, und verfolgen Sie, ob sie erledigt wurde. Nur API-Schlüssel.
- **Agentenverwaltung**: Erstellen und Bearbeiten von Agenten und Skills über einen vertrauenswürdigen Dienst mithilfe von maschinellen OIDC-Tokens.

<Callout type="warning" title="Beta">
  Endpunkte, Anfrageformate und Antworten können sich zwischen den Releases weiterhin ändern.
</Callout>

## Einen API-Schlüssel erhalten [#get-an-api-key]

Öffne **Einstellungen**, wechsle zu **Daten & Datenschutz** und suche unter **API-Schlüssel** nach **Agent-API-Schlüssel**. Klicke auf **Verwalten** und dann auf **API-Schlüssel erstellen**, vergib einen Namen und wähle eine Ablaufzeit (zwischen 7 Tagen und 1 Jahr oder „nie“). Kopiere den Schlüssel sofort, denn er wird nur einmal angezeigt.

  light="/images/features/agents_api/api-keys-light.png"
  dark="/images/features/agents_api/api-keys-dark.png"
  alt="Agent-API-Schlüssel in Einstellungen, Daten & Datenschutz, mit zwei Schlüsseln und deren Ablaufdatum sowie letztem Verwendungsdatum"

Ein Schlüssel handelt in Ihrem Namen. Alles, worauf Sie über die API zugreifen können, kann auch jeder erreichen, der den Schlüssel besitzt. Löschen Sie daher Schlüssel, die Sie nicht mehr verwenden. Das Löschen eines Schlüssels unterbricht sofort alle Anwendungen, die ihn verwenden.

Wenn Sie den Abschnitt nicht sehen, wurde Ihrer Rolle kein Zugriff auf die Agents API gewährt.

## Welche Agenten du aufrufen kannst [#which-agents-you-can-call]

Sie können Agenten aufrufen, die Ihnen gehören oder die Sie teilen können. Für Agenten anderer Nutzer muss der Eigentümer Ihnen den Zugriff über die Schaltfläche **Remote-Zugriff** (das Globus-Symbol) in der Fußzeile des Agenten-Builders gewähren. Dies ist unabhängig von der normalen Freigabe: Dass Sie in LibreChat mit einem Agenten chatten können, berechtigt Sie nicht dazu, ihn über die API aufzurufen.

Sie benötigen die Agent-ID, die im Builder unter **Erweiterte Einstellungen** mit einer Kopierschaltfläche angezeigt wird. `GET /api/agents/v1/models` listet die Agents auf, die Ihr Schlüssel aufrufen kann, und `GET /api/agents/v1/models/{model}` gibt einen einzelnen Agent zurück.

## Chat Completions [#chat-completions]

`POST /api/agents/v1/chat/completions` folgt dem OpenAI-Chat-Completions-Format, sodass bestehende OpenAI-Clients funktionieren, indem Sie lediglich die Basis-URL ändern:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

Die gleiche Anfrage mit curl:

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Open Responses [#open-responses]

`POST /api/agents/v1/responses` implementiert die [Open Responses](https://www.openresponses.org/)-Spezifikation, die für Agenten-Workloads entwickelt wurde: Reasoning, Tool-Aufrufe und gestreamte Events sind Bestandteil des Formats und nicht nachträglich angefügt. Dies ist die Schnittstelle, auf der LibreChat künftig aufbaut. Verwenden Sie sie daher bevorzugt für neue Integrationen.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` gibt eine gespeicherte Antwort zurück, und `GET /api/agents/v1/responses/models` listet die hier verfügbaren Agenten auf.

### Eigene Funktionswerkzeuge [#your-own-function-tools]

Sie können standardmäßige `function`-Tools in einer Responses-Anfrage übergeben. LibreChat zeigt sie dem Modell an, führt sie jedoch nicht aus: Wählt das Modell eines davon aus, enthält die Antwort ein `function_call`-Element, und Sie führen die Funktion selbst aus. Um fortzufahren, senden Sie eine neue Anfrage, deren `input` dieses `function_call`-Element wiederholt, gefolgt von einem `function_call_output` mit derselben `call_id`:

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Zwischen den beiden Anfragen wird nichts offen gehalten, und `previous_response_id` allein reicht nicht aus; Sie müssen den Aufruf und seine Ausgabe erneut übermitteln. Tool-Namen dürfen Buchstaben, Zahlen, Unterstriche und Bindestriche enthalten, müssen eindeutig sein und dürfen nicht eines der eigenen Tools des Agenten verdecken. Ein Turn, der eines Ihrer Tools aufruft, kann gleichzeitig keine Tools des Agenten aufrufen; das Modell wird aufgefordert, es erneut zu versuchen.

### Tool-Genehmigung über die API [#tool-approval-over-the-api]

Wenn Ihr Administrator für einige Tools eine Genehmigung verlangt, können API-Aufrufe nicht anhalten, um jemanden zu fragen. Tools, die eine Genehmigung benötigen würden, oder die abgelehnt sind, werden stattdessen blockiert. Administratoren sollten die Tools, die ein unbeaufsichtigter Client ausführen soll, ausdrücklich erlauben.

## Agent-Ereignisse [#agent-events]

Agent-Events ermöglichen es einem anderen System, einem Agenten Aufgaben zu übergeben, und später zurückzukommen, um zu sehen, was passiert ist. Dies ist eine Beta-Funktion. Events verwenden Ihren Agents-API-Schlüssel, der Sie und die Quelle identifiziert; reine OIDC-Konfigurationen können sie nicht nutzen. Sie haben außerdem ein eigenes Ratenlimit, [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Ein Ereignis tritt in einem von drei Modi auf:

- `fire` startet eine neue Unterhaltung mit dem Agenten.
- `continue` fügt einem zuvor gebundenen Kind-Agenten einen weiteren Durchlauf hinzu (siehe unten).
- `steer` fügt einem noch laufenden Durchlauf Hinweise hinzu. Der Durchlauf wird über die Konversation und die Generierung identifiziert, die ein `fire` zurückgegeben hat.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Jede Anfrage benötigt genau einen `Idempotency-Key` (1 bis 256 Buchstaben, Ziffern oder `._~:/+=-`). Verwenden Sie ihn erneut, wenn Sie dieselbe Zustellung wiederholen; die Wiederverwendung für abweichende Inhalte stellt einen Konflikt dar. LibreChat leitet die Quelle des Ereignisses aus Ihrem API-Schlüssel ab und ignoriert jede von Ihnen gesendete Quelle. Die Nutzlast wird gespeichert, daher sollten Sie keine Geheimnisse darin ablegen. Verwenden Sie `orderingKey`, wenn Ereignisse zu demselben Vorgang in der richtigen Reihenfolge verarbeitet werden müssen.

Die Antwort ist `202 Accepted` mit einer Zustellungs-ID und einem `Location`-Header, unter dem mit demselben Schlüssel abgefragt werden kann:

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Eine Zustellung hat den Status `pending`, `leased`, `succeeded` oder `dead`. Bei einem gebundenen `continue` bedeutet `succeeded` nur, dass der Turn gestartet wurde. Danach wechselt sein `handling`-Status von `started` zu einem der Werte `applied`, `completed_no_action`, `failed` oder `cancelled`. Wenn Sie ein `expectedAction` senden (einen Tool-Namen und optional einige seiner Argumente), bedeutet `applied`, dass LibreChat gesehen hat, dass dieses Tool mit übereinstimmenden Argumenten aufgerufen wurde; was das Modell im Text sagt, zählt nicht.

Agent Events sind kein öffentlicher Webhook-Empfänger. Wenn die Events von einem Anbieter stammen, der seine Webhooks signiert, verifiziere die Signatur in deinem eigenen Adapter, bevor du sie weiterleitest.

### Ereignisgesteuerte Kindagenten [#event-driven-child-agents]

Um eine fortlaufende Konversation mit einem Child-Agenten über viele Ereignisse hinweg aufrechtzuerhalten, binden Sie ihn einmal und senden Sie anschließend `continue`-Ereignisse an die Bindung:

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

Die übergeordnete Konversation muss eine normale Agenten-Konversation sein, und das Ziel muss einer der direkten Subagenten dieses Agenten sein (oder der Agent selbst, falls Selbst-Spawning erlaubt ist). `actorId` darf bis zu 128 Zeichen lang sein. Eine neue Bindung gibt `201` zurück, eine Wiederholung gibt `200` zurück; beide enthalten die Bindungs-`id`. Spätere Turns referenzieren sie:

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Jede Bindung verarbeitet jeweils ein Ereignis nach dem anderen: Das nächste wartet, bis der aktuelle Turn einen endgültigen Verarbeitungsstatus hat, während verschiedene Bindungen parallel laufen. Ein gebundenes Child-Element kann für „Ask User“ oder eine Tool-Genehmigung pausieren; seine späteren Ereignisse warten, bis jemand in LibreChat antwortet. Dafür ist der dauerhafte MongoDB-Checkpointer erforderlich (der Standard). In der übergeordneten Konversation wird jedes gebundene Child-Element als Zeile unter der Nachricht angezeigt, der die Bindung gehört, und öffnet das Panel für Subagenten-Aktivität.

Eine Bindung funktioniert nur mit dem API-Schlüssel, dem Benutzer und dem Mandanten, die sie erstellt haben. Der Kindthread bleibt aus der Chat-Liste ausgeblendet und ist in der App nur lesbar.

Bei Ereignissen, die lediglich Beobachtungen sind, etwa „ein Spiel wurde fortgesetzt“, vergeben Sie denselben `coalesce.key`. LibreChat fasst dann bis zu 8 davon (innerhalb von 750 ms und 512 KiB) zu einem einzigen Durchgang zusammen. Jedes Ereignis erhält weiterhin seine eigene Quittung. Befehle, Genehmigungen und alles mit einem `expectedAction` werden nicht zusammengefasst.

## Agent Management API [#agent-management-api]

Die Agent Management API ermöglicht es einem vertrauenswürdigen Dienst, Agenten und Skills ohne Browser-Sitzung zu erstellen, zu ändern und zu löschen. Sie befindet sich im Beta-Status und verwendet eine eigene Authentifizierung: Maschinen-OIDC-Token von Clients, die der Administrator unter [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) auflistet. Jeder Client ist an genau einen bestehenden LibreChat-Benutzer und Mandanten gebunden, und jede Anfrage handelt im Namen dieses Benutzers, mit dessen Berechtigungen und Zugriffsrechten. Dadurch wird niemand zum Administrator.

| Methode | Route | Zweck |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST` | `/api/agents/v1/agents` | Einen Agenten erstellen |
| `GET` | `/api/agents/v1/agents` | Zugängliche Agenten auflisten |
| `GET` | `/api/agents/v1/agents/{id}` | Einen Agenten abrufen |
| `PATCH` | `/api/agents/v1/agents/{id}` | Einen Agenten aktualisieren |
| `DELETE` | `/api/agents/v1/agents/{id}` | Einen Agenten löschen |
| `POST` | `/api/agents/v1/agents/{id}/files` | Eine Datei hochladen und anhängen |
| `GET` | `/api/agents/v1/agents/{id}/files` | Angehängte Dateien auflisten |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}` | Eine Datei lösen |
| `GET` | `/api/agents/v1/skills` | Zugängliche Skills auflisten |
| `POST` | `/api/agents/v1/skills` | Einen Skill erstellen |
| `GET` | `/api/agents/v1/skills/{id}` | Einen Skill abrufen |
| `PATCH` | `/api/agents/v1/skills/{id}` | Einen Skill aktualisieren |
| `DELETE` | `/api/agents/v1/skills/{id}` | Einen Skill löschen |
| `GET` | `/api/agents/v1/skills/{id}/files` | Dateien eines Skills auflisten |
| `GET` | `/api/agents/v1/skills/{id}/files/{path}` | Eine Skill-Datei abrufen |
| `PUT` | `/api/agents/v1/skills/{id}/files/{path}` | Eine Skill-Datei erstellen oder ersetzen |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}` | Eine Skill-Datei löschen |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agent payloads take the same fields as the Agent Builder and reject unknown ones; `model` is required on create. Lists take `limit` (1 to 100, default 20) and a `cursor`; when `has_more` is true, pass the returned `after` as the next cursor. File uploads are `multipart/form-data` with one `file` and a `tool_resource` such as `context`, `file_search`, or `execute_code`, subject to the usual upload limits.

Skill create nimmt `name`, `description`, `body` sowie optional `displayTitle`, `frontmatter`, `category` und `alwaysApply` entgegen. Aktualisierungen müssen die aktuelle Version des Skills als `expectedVersion` senden, damit zwei Schreibende einander nicht stillschweigend überschreiben können.

Fehler verwenden die Codes `invalid_request`, `not_found`, `permission_denied`, `conflict` und `internal_error`. Eine Ressource, auf die Sie keinen Zugriff haben, kann als `not_found` zurückgegeben werden. Fehlende oder ungültige Zugangsdaten führen zu `401`.

Wenn der Administrator es aktiviert, wird unter `/api/openapi.json` eine OpenAPI-Beschreibung der Verwaltungsrouten bereitgestellt, mit interaktiver Dokumentation unter `/api/docs`. Inferenz und Events sind davon nicht abgedeckt. Siehe [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Nutzung und Abrechnung [#usage-and-billing]

API-Anfragen werden von Ihrem Token-Guthaben genauso abgezogen wie Chats in der App. Die Nutzungssummen in der Antwort enthalten Aufrufe von Subagenten, mit einer getrennten Aufschlüsselung nach `primary` und `subagent`, sowie Cache- und Reasoning-Tokens, sofern der Anbieter diese meldet. Siehe [Token-Nutzung](/docs/configuration/token_usage).

## Einrichtung [#setup]

Die Agents API ist für reguläre Benutzer deaktiviert, bis ein Administrator die Berechtigungen für Remote-Agenten ihrer Rolle erteilt, entweder im [Admin-Panel](/docs/features/admin_panel) oder mit [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents). Administratoren haben sie standardmäßig. Die API-Schlüssel-Authentifizierung ist standardmäßig aktiviert; um Tokens von deinem eigenen OIDC-Provider anstelle von oder zusätzlich zu Schlüsseln zu akzeptieren, siehe [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi). Die Management API wird separat unter [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi) konfiguriert, und die Einstellungen für die ereignisgesteuerte Zustellung befinden sich unter [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven).
