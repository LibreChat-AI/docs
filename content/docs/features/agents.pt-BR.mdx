Um agente é uma configuração salva: um modelo, um prompt de sistema e as ferramentas e arquivos que ele pode usar. Você o cria uma vez no Agent Builder e depois o seleciona sempre que iniciar um chat. Os agentes funcionam com qualquer provedor configurado, e não apenas com a OpenAI.

## Criar um agente [#create-an-agent]

<Steps>
  <Step>
    Abra o **Agent Builder** no painel lateral e clique em **Create New Agent**.
  </Step>
  <Step>
    Dê um nome a ele, uma descrição opcional, e escolha um **Model** e uma **Category**. O model e a category são obrigatórios.
  </Step>
  <Step>
    Escreva as instruções. Você pode digitá-las diretamente, ou alternar a origem para **Prompt** para usar um prompt salvo da sua biblioteca de prompts (veja abaixo).
  </Step>
  <Step>
    Adicione as ferramentas em **Tools** (veja abaixo) e, em seguida, clique em **Create**.
  </Step>
</Steps>

O upload de arquivos para File Search ou File Context só funciona depois que o agente foi criado.

Para conversar com um agente, selecione-o no seletor de modelos, abra-o no [Agent Marketplace](#agent-marketplace) ou digite `@` na caixa de chat e escolha-o na lista. No seletor de agentes do builder, **My agents** filtra a lista para mostrar apenas os agentes que você criou.

### Instruções de um prompt salvo [#instructions-from-a-saved-prompt]

Com a fonte das instruções definida como **Prompt**, escolha um prompt em **Select a prompt** e uma **Version**: ou a versão de produção, que segue o que o proprietário do prompt marcar como produção, ou uma versão salva fixa. Você precisa ter acesso à biblioteca de prompts para fazer isso. Se outra pessoa abrir o agente sem acesso ao prompt vinculado, o construtor exibe **Restricted prompt** e permite substituí-lo ou voltar às instruções inline.

As instruções, inline ou vinculadas, podem usar `{{current_date}}`, `{{current_datetime}}` e `{{iso_datetime}}`. Elas são preenchidas uma única vez no início de cada turno e permanecem as mesmas durante as chamadas de ferramentas, subagentes e pausas para aprovação. As duas primeiras usam o seu fuso horário; `{{iso_datetime}}` está em UTC.

### Parâmetros de modelo [#model-parameters]

O painel de modelo expõe os mesmos parâmetros de um chat normal para esse provedor (temperatura, máximo de tokens de saída, e assim por diante), além de **Detalhe da imagem** para entrada de visão. Os valores salvos aqui se aplicam a todas as conversas com o agente.

### Iniciadores de conversa [#conversation-starters]

Em **Conversation Starters**, você pode adicionar até quatro prompts. Eles aparecem como botões na tela de chat vazia quando alguém inicia um novo chat com o agente, e clicar em um deles o envia imediatamente. Os starters de um agente substituem quaisquer starters definidos na model spec em uso. Eles também aparecem nos detalhes do agente no Marketplace.

### Histórico de versões [#version-history]

Toda vez que você salvar uma alteração no agente, uma entrada é adicionada ao **Histórico de versões**, que mostra quando cada versão foi salva e quais ferramentas e recursos ela tinha. **Restaurar** substitui a configuração atual pela versão selecionada, após uma confirmação. Somente usuários que podem editar o agente veem isso.

## Ferramentas [#tools]

Clique em **Adicionar** ao lado do título **Ferramentas** no construtor (ele exibe **Nenhuma ferramenta ainda** até que você adicione uma) para abrir a **Biblioteca de Ferramentas**. Pesquise nela ou filtre por **Nativas**, **Ferramentas**, **Servidores MCP** ou **Ações**. **Criado por você** reúne os servidores MCP e as Ações que você criou, e **Favoritos** mantém os itens marcados com estrela à mão em todos os agentes (até 100). O menu **Criar novo…** adiciona um servidor MCP ou uma Ação sem sair da caixa de diálogo, caso a sua função tenha permissão para criá-los. O que você vê depende do que o seu administrador habilitou e das permissões da sua função; um item que ainda precisa de uma chave de API exibe **Requer configuração**.

Run Code, File Search e File Context armazenam arquivos. Enquanto ainda tiverem arquivos anexados, removê-los abre o gerenciador de arquivos, e eles permanecem no agente até que esses arquivos sejam removidos.

### Code Interpreter [#code-interpreter]

Listado como **Run Code**. O agente escreve e executa código em um sandbox, o que é ideal para cálculos, análise de dados e geração de arquivos, como gráficos ou planilhas. Os arquivos que você anexa a esta ferramenta no builder ficam disponíveis no sandbox em todas as execuções. Se nenhum dos arquivos de código de uma conversa puder ser restaurado no sandbox, o agente interrompe a operação antes de chamar o modelo e pede que você anexe os arquivos novamente. Consulte [Code Interpreter](/docs/features/code_interpreter).

#### Sessões de código com estado [#stateful-code-sessions]

Se o seu administrador tiver habilitado essa opção, as **Sessões de código com estado** nas configurações de Executar código mantêm um espaço de trabalho em sandbox entre as execuções, de modo que arquivos e pacotes instalados são preservados. **Ambiente com estado** define quem compartilha esse espaço de trabalho: **Espaço de trabalho do usuário (recomendado)** para todos os seus agentes com estado, **Espaço de trabalho do agente + usuário** para um por agente, ou **Espaço de trabalho da conversa** para um por chat. Novos agentes começam a partir do **Espaço de trabalho com estado padrão** em **Configurações > Dados e Privacidade > Execução de código**. Quando o administrador tiver configurado vários backends, **Ambiente de execução** escolhe qual deles executa o código, o que pode incluir um worker que você emparelha na sua própria máquina.

O workspace pode ser redefinido a qualquer momento, portanto não o trate como armazenamento. Em ambientes gerenciados, salve os resultados de que você precisa em `/mnt/data`. Os arquivos que o agente grava com suas ferramentas de arquivo são listados por mensagem em **Alterações no workspace**, onde você pode baixá-los. Com um ambiente anexado, o compositor oferece **Perguntar antes de alterar**, **Aceitar edições** ou **Acesso total** como modo de aprovação para esse chat, dentro dos limites definidos pelo seu administrador.

Este recurso é altamente experimental. Consulte [sessões de código com estado](/docs/features/code_interpreter#stateful-code-sessions) para mais detalhes.

### Pesquisa na Web [#web-search]

O agente pesquisa na web e cita as suas fontes. Ele precisa de um provedor de pesquisa configurado pelo seu administrador, ou da sua própria chave, caso o administrador tenha configurado dessa forma. Consulte [Pesquisa na Web](/docs/features/web_search).

### File Search [#file-search]

Transforma os arquivos que você anexa em uma base de conhecimento pesquisável. O agente recupera as passagens mais relevantes quando precisa delas, por isso lida bem com grandes conjuntos de documentos. Não é uma boa opção para dados estruturados, como CSV ou Excel, nos quais Run Code tem melhor desempenho. Requer a [RAG API](/docs/features/rag_api).

### Contexto de Arquivo [#file-context]

Arquivos adicionados em **File Context** têm seu texto extraído uma única vez, no momento do upload, e esse texto é incluído no contexto do agente em todas as mensagens. Use-o para alguns documentos-chave que o agente deve sempre ter em vista. A extração funciona da mesma forma que [Upload as Text](/docs/features/upload_as_text): por padrão, é feita a análise de texto simples, com melhores resultados em digitalizações e imagens caso o [OCR](/docs/features/ocr) esteja configurado.

Como o texto acompanha cada mensagem, arquivos grandes aqui custam tokens a cada turno. Qualquer pessoa que possa conversar com o agente também pode extrair esse texto dele.

### Artifacts [#artifacts]

Permite que o agente renderize React, HTML, SVG, Markdown e Mermaid em um painel lateral, em vez de como blocos de código. A configuração **Mode** escolhe as instruções integradas: **Normal**, **shadcn/ui** (adiciona instruções para a biblioteca de componentes shadcn/ui) ou **Custom**, que não injeta nada, portanto suas próprias instruções devem ensinar a sintaxe dos artefatos. Consulte [Artifacts](/docs/features/artifacts) para ver essa sintaxe.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

Os servidores MCP configurados pelo seu administrador, ou os que você mesmo adicionou, aparecem em **MCP servers**. Ao adicionar um servidor, todas as suas ferramentas são anexadas; expanda-o em **Tools in this server** para escolher apenas as que o agente precisa. Consulte [MCP](/docs/features/mcp).

Alguns servidores só podem listar suas ferramentas durante um chat, pois dependem de valores da requisição. Para esses casos, o construtor oferece uma única seleção para todas as ferramentas do servidor, em vez de opções individuais por ferramenta. Se todas as ferramentas MCP selecionadas de um agente falharem ao carregar quando uma execução é iniciada, a execução é interrompida e informa que você deve reconectar ou fazer login no servidor, em vez de continuar sem elas.

Cada ferramenta MCP possui um menu **Tool Options** com algumas opções por ferramenta:

- **Defer**: veja [Ferramentas adiadas](#deferred-tools). **Adiar todas as ferramentas** faz isso para todo o servidor.
- **Programático**: veja [Chamada programática de ferramentas](#programmatic-tool-calling).
- **Plano de fundo**: veja [Chamadas de ferramentas em segundo plano](#background-tool-calls).
- **Rótulo de intenção**: o agente escreve uma descrição de uma linha para cada chamada, exibida em tempo real como o status da chamada em vez de um rótulo genérico. Isso adiciona alguns tokens a cada requisição. As ferramentas nativas recebem rótulos de intenção automaticamente. Isso não se aplica às ferramentas programáticas.

**Background** e **Intent label** aparecem somente se o seu administrador tiver habilitado essas opções.

### Ferramentas adiadas [#deferred-tools]

Um agente com vários servidores MCP pode facilmente carregar dezenas de definições de ferramentas, e enviar todas elas em cada requisição consome contexto e piora a capacidade do modelo de escolher a ferramenta certa. Uma ferramenta adiada fica de fora da requisição inicial. Em seu lugar, o agente recebe uma ferramenta de busca de ferramentas, que encontra as ferramentas adiadas pelo nome ou pela descrição quando precisa delas, e pode usar uma ferramenta encontrada durante o restante da conversa.

### Chamada programática de ferramentas [#programmatic-tool-calling]

Com **Programático** ativado para uma ferramenta MCP (ou para um servidor inteiro), o modelo não chama essa ferramenta diretamente. Em vez disso, ele escreve código no sandbox do Code Interpreter que chama a ferramenta como uma função, para que possa fazer loops, paginar, tentar novamente e filtrar resultados antes de responder. Isso ajuda em tarefas como "verifique estes 40 chamados e resuma os abertos", que, de outra forma, exigiriam 40 chamadas de ferramenta separadas passando pelo modelo.

Os interruptores **Programático** permanecem desativados até que Executar Código esteja ativado, e remover Executar Código os limpa. O sandbox só pode chamar ferramentas que estejam registradas no agente. Enquanto ele é executado, expanda o cartão de código para acompanhar em tempo real um rastreamento de cada chamada de ferramenta interna; o rastreamento não é mantido após você recarregar a página. Isso vem desativado por padrão; seu administrador precisa habilitá-lo.

### Chamadas de ferramentas em segundo plano [#background-tool-calls]

Uma ferramenta com suporte a execução em segundo plano retorna uma referência de tarefa imediatamente, para que o agente possa continuar trabalhando enquanto ela é executada. Quando a tarefa termina, o resultado é entregue automaticamente em um turno de acompanhamento (exibido como um cartão de tarefa recolhível), ou o agente pode verificar seu andamento com a sua ferramenta de tarefas. A saída e os arquivos em segundo plano aparecem na chamada original da ferramenta. Quais ferramentas podem ser executadas em segundo plano:

- **Executar Código**: código e comandos de shell são elegíveis por padrão; desative **Execução em segundo plano** nas configurações dela para optar por não participar.
- **Ferramentas MCP**: marque uma ferramenta ou um servidor inteiro como **Background**.
- **Outras ferramentas e Ações**: ative a **Execução em segundo plano**. Ações que usam OAuth não oferecem essa opção.

Estas opções permitem a execução em segundo plano; o modelo ainda decide a cada chamada. O trabalho em segundo plano roda no processo do servidor que o iniciou e é perdido se esse processo for encerrado. Seu administrador precisa habilitar o recurso.

### Actions [#actions]

Ações transformam uma especificação OpenAPI em ferramentas. Escolha **Create new…** e depois **Actions**, cole o esquema e configure a **Authentication** caso a API exija. Cada operação na especificação se torna uma ferramenta que o agente pode chamar.

Se você estiver usando um modelo da OpenAI, adicione `x-strict: true` a uma operação na especificação e o LibreChat solicitará chamadas de função estritas para ela. O modo estrito aceita apenas um subconjunto do JSON Schema; consulte o [guia de saídas estruturadas](https://platform.openai.com/docs/guides/structured-outputs) da OpenAI.

As Actions só podem acessar domínios que o seu administrador permitir, e endereços de rede privada são bloqueados, a menos que sejam explicitamente permitidos.

### Skills [#skills]

A seção **Skills** no construtor controla quais [Skills](/docs/features/skills) o agente pode usar: **Off** (desativado), **All** (todas as skills que você tem ativas) ou **Selected** (somente as que você adicionar).

### Memória [#memory]

**Memória** permite que o agente salve, atualize e exclua memórias sobre você quando você pedir para lembrar ou esquecer algo. É necessário que a memória esteja configurada na instância e permitida para a sua função. Por padrão, o agente compartilha suas memórias pessoais com seus outros chats; ative **Manter memórias separadas para este agente** para dar a ele memórias próprias, que somente ele lê e grava. Consulte [Memória](/docs/features/memory).

### Perguntar ao usuário e aprovação de ferramentas [#ask-user-and-tool-approval]

**Perguntar ao Usuário** permite que o agente pause durante a execução para fazer uma pergunta a você e aguardar sua resposta. Uma pausa pode conter até quatro perguntas, exibidas uma de cada vez com **Voltar** e **Avançar**; cada uma aceita uma resposta livre ou uma das opções do agente. **Pular** recusa todas elas. A execução é retomada assim que você enviar as respostas, e suas respostas são mantidas mesmo que você interrompa a execução durante a reinicialização.

Seu administrador também pode exigir aprovação antes que determinadas ferramentas sejam executadas. A execução é pausada, você revisa a chamada em um painel acima da caixa de mensagens (aprovar, rejeitar ou, para algumas ferramentas, editar os argumentos) e então ela continua. Se o administrador tiver habilitado modos de aprovação por agente, cada ferramenta do agente recebe um **Modo de aprovação da ferramenta**: **Usar política herdada**, **Sempre perguntar**, **Sempre aprovar**, **Perguntar uma vez por chat** ou **Perguntar uma vez e, depois, sempre aprovar**. As regras do administrador continuam valendo por cima disso, e **Redefinir minhas aprovações lembradas** limpa o que você aprovou anteriormente.

### Outras ferramentas [#other-tools]

A categoria **Ferramentas** reúne as integrações nativas que seu administrador habilitou, como [geração de imagens](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search) e [Azure AI Search](/docs/configuration/tools/azure_ai_search). Cada uma é configurada separadamente; consulte [Ferramentas](/docs/configuration/tools).

## Trabalhando com outros agentes [#working-with-other-agents]

**Subagentes** permitem que o agente delegue uma subtarefa específica a uma nova cópia de si mesmo, ou a outro agente, em uma janela de contexto separada. Apenas o resultado retorna, de modo que saídas longas de ferramentas ficam fora da conversa principal. Consulte [Subagentes](/docs/features/subagents).

### Handoffs [#handoffs]

**Handoffs** dão ao agente uma ferramenta de transferência para cada agente que você listar, para que ele possa passar a conversa a um especialista quando o assunto exigir. Para cada handoff, você pode adicionar uma descrição (quando transferir) e conteúdo de passagem (o que o agente deve gerar e repassar), além de renomear o parâmetro em que esse conteúdo é passado (`instructions` por padrão). Um agente pode ter até 10 handoffs. Os handoffs estão sempre disponíveis; eles não dependem de uma configuração do administrador.

### Cadeia de agentes [#agent-chain]

Agent chains foram descontinuadas. As cadeias existentes continuam funcionando, e o construtor as exibe em **Advanced Settings** com um botão **Remove chain**, mas não é possível criar novas. Use subagentes ou handoffs.

## Máximo de etapas do agente [#max-agent-steps]

**Configurações Avançadas** possui um campo **Max Agent Steps** que limita quantos passos o agente pode executar antes de precisar dar uma resposta final. Um passo é uma requisição ao modelo ou uma rodada de chamadas de ferramentas; assim, uma única chamada de ferramenta normalmente consome três passos: a requisição, a rodada da ferramenta e a requisição de acompanhamento.

Deixe o campo vazio para usar o padrão do servidor, que é 50, a menos que seu administrador tenha alterado esse valor. Seu administrador também pode definir um limite máximo que o campo não pode ultrapassar.

Quando um turno esgota os passos disponíveis, você mantém o que o agente fez até o momento, e a mensagem oferece **Continuar** (um novo turno com um orçamento novo) ou **Responder agora** (o agente responde com base no trabalho já realizado, sem mais ferramentas). Se isso acontecer com frequência em cadeias longas de ferramentas, aumente o limite.

## Seguindo uma longa execução [#following-a-long-run]

Os cartões de ferramenta mostram **Preparando** enquanto uma chamada aguarda (por exemplo, na aprovação) e, em seguida, **Chamando** até que o resultado retorne. A saída do shell é exibida no estilo terminal e recolhida para as últimas 15 linhas; **Mostrar mais** expande a saída, e um comando que falhou exibe seu código de saída, sinal ou tempo limite.

### Grupos de atividades [#activity-groups]

Se o seu administrador tiver ativado essas opções, cada trecho de raciocínio e cada chamada de ferramenta ficam recolhidos sob um cabeçalho de uma linha gerado automaticamente, de modo que uma execução com 30 chamadas de ferramenta aparece como apenas algumas linhas. Expanda um cabeçalho para ver as chamadas contidas nele. Um segundo nível pode agrupar vários desses grupos em uma fase, com resumo próprio, criando um esboço para execuções longas; assim que dois grupos forem concluídos, eles são recolhidos juntos imediatamente, e o cabeçalho mais recente permanece visível até o resumo ser gerado. A resposta final sempre fica fora do recolhimento, e os arquivos produzidos dentro de uma fase são exibidos em uma linha abaixo dela, em vez de ficarem ocultos. Com o [Smooth Streaming](/docs/features/smooth_streaming) ativado, o recolhimento é animado, a menos que o seu dispositivo solicite movimento reduzido.

Rótulos de raciocínio ao vivo são uma opção relacionada: em vez de um cabeçalho genérico **Thinking**, o bloco de raciocínio mostra um resumo curto e atualizado do que o modelo está trabalhando.

Cabeçalhos, resumos de fase e rótulos de raciocínio geram chamadas extras ao modelo, que são registradas como qualquer outro uso. Os administradores os configuram em [grupos de atividade do agente](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) e [rótulos de raciocínio ao vivo](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Direcionamento e mensagens em fila [#steering-and-queued-messages]

Enquanto um agente está respondendo, você ainda pode enviar mensagens:

- **Steer** insere a mensagem na execução atual no próximo ponto seguro, para que o agente possa ajustar o rumo antes de terminar.
- **Interromper** cancela as chamadas de ferramentas e o raciocínio em andamento, mantém o que já foi concluído e continua com a sua mensagem. Efeitos que já ocorreram fora do LibreChat não podem ser desfeitos. Algumas execuções, por exemplo as que usam a busca integrada de um provedor, não podem ser interrompidas, e a mensagem aguarda como um steer.
- **Queue** mantém a mensagem e a envia como um turno normal após a conclusão da resposta.

**Durante a geração, Enter fará** em **Configurações > Chat** escolhe o padrão, e o menu do botão de envio substitui essa escolha por mensagem; `Alt + Enter` interrompe. As mensagens na fila são listadas acima do campo de composição, onde você pode editar, remover, reordenar, **Enviar agora** ou **Interromper agora**. Arquivos e trechos citados são enviados junto com a mensagem; as habilidades escolhidas com `$` aguardam o próximo turno completo. As mensagens na fila de uma conversa salva com agente são armazenadas no servidor e continuam disponíveis mesmo após o navegador ser fechado.

Um chat comporta até 100 mensagens na fila (16.000 caracteres e 10 arquivos cada), e uma execução aceita até 10 direcionamentos pendentes. Consulte [Composer](/docs/features/composer) para ver em detalhes os recibos e os controles.

## Arquivos em um chat [#files-in-a-chat]

Quando você conversa com um agente, o menu de anexos oferece:

- **Enviar imagem**: enviada ao modelo para visão.
- **Enviar como Texto**: o texto completo é incluído somente nesta conversa. Consulte [Enviar como Texto](/docs/features/upload_as_text).
- **Upload para Pesquisa em Arquivos**: indexado para recuperação, como os arquivos de Pesquisa em Arquivos do próprio agente, mas restrito a este chat.
- **Upload para Ambiente de Código**: copiado para o sandbox ao usar Executar Código. Ideal para CSV, Excel e JSON.

As opções só aparecem quando o recurso correspondente está habilitado.

## Compartilhamento e permissões [#sharing-and-permissions]

Agentes são privados para o seu autor até serem compartilhados. Clique em **Share** no rodapé do construtor para conceder acesso a usuários, grupos ou funções, cada um com um dos três papéis disponíveis:

| Papel | O que podem fazer |
| ----- | ----------------- |
| Visualizador | Conversar com o agente. Não podem abri-lo no construtor nem ver suas instruções, ferramentas ou arquivos. |
| Editor | Tudo o que um visualizador pode fazer, além de alterar as instruções, o modelo, as ferramentas e os arquivos. |
| Proprietário | Tudo o que um editor pode fazer, além de excluir o agente e alterar com quem ele é compartilhado. |

**Compartilhar com todos** disponibiliza o agente para todos os usuários da instância; é necessária a permissão de compartilhamento público. O autor e os administradores sempre mantêm controle total.

Um visualizador não consegue ver as instruções ou os arquivos no construtor, mas o modelo ainda pode repeti-los em uma conversa se for solicitado. Não coloque em um agente nada que seus visualizadores nunca devam ver.

Separadamente, o botão de globo (**Remote Access**) controla quem pode chamar o agente por meio da [Agents API](/docs/features/agents_api).

Os cards dos agentes exibem o contato de suporte definido no builder. Sem um contato definido, eles podem exibir o nome do proprietário, mas nunca o e-mail do proprietário, a menos que ele tenha sido informado como contato.

Veja [Controle de Acesso](/docs/features/access_control) para saber como usuários, grupos e funções se combinam.

### Controles de administrador [#administrator-controls]

Se um perfil pode usar, criar, compartilhar ou compartilhar publicamente agentes é definido por perfil no [Painel de Administração](/docs/features/admin_panel). Administradores também recebem um botão **Configurações de Administrador** na parte inferior do Construtor de Agentes, com os mesmos controles, por perfil. Em uma instância de locatário único, a primeira conta registrada é um administrador; para adicionar mais, consulte [Promover outro administrador](/docs/configuration/access_control#promote-another-admin).

## Marketplace de Agentes [#agent-marketplace]

**Agent Marketplace** na barra lateral lista os agentes disponíveis para você, caso sua função permita usá-lo. Pesquise por nome ou descrição, filtre por categoria (**Top Picks**, **All** ou uma específica) e altere a ordem com **Sort by**: **Newest first**, **Oldest first**, **Popular** ou **By creator name**. **My agents** mostra apenas os seus. A pesquisa, a ordenação e o filtro ficam salvos na URL, para que você possa salvar nos favoritos ou compartilhar uma visualização.

Clique em um cartão para ver os detalhes e as ações **Pin** ou **Unpin**, **Copy Link** (um link que abre um novo chat com o agente) e **Start Chat**. Ao clicar em um dos conversation starters do agente, um novo chat é aberto com o prompt na caixa de mensagem, sem ser enviado, para que você possa editá-lo antes.

## API de Agentes [#agents-api]

Agentes também podem ser chamados por scripts e outros aplicativos por meio de uma API compatível com a OpenAI, gerenciados por serviços confiáveis e acionados por eventos de outros sistemas. Consulte [API de Agentes](/docs/features/agents_api). Os [Chats Agendados](/docs/features/scheduled_chats) iniciam execuções de agentes em um cronômetro, e os [Plugins de Agentes](/docs/features/agent_plugins) permitem que um operador distribua habilidades e servidores MCP para agentes em um único pacote.

## Configuração [#setup]

Os agentes vêm ativados por padrão. Os administradores escolhem quais recursos são oferecidos, os limites de etapas e os provedores permitidos na [configuração do endpoint de agentes](/docs/configuration/librechat_yaml/object_structure/agents), bem como quais domínios as Actions podem acessar na [configuração de Actions](/docs/configuration/librechat_yaml/object_structure/actions). Instâncias atualizadas de versões anteriores à v0.8.0-rc3 precisam da [migração de permissões](/docs/configuration/access_control#migrating-from-pre-acl-versions).
