# エージェント: カスタムAIアシスタントの構築 [#agents-build-custom-ai-assistants]

LibreChatのAIエージェント機能は、さまざまなモデルプロバイダーを活用したカスタムAIアシスタントを作成するための柔軟なフレームワークを提供します。

この機能はOpenAIのAssistants APIやChatGPTのGPTsと似ていますが、より幅広いモデルをサポートし、ノーコードで実装できるため、専門的な機能を備えた高度なアシスタントを構築できます。

## はじめに [#getting-started]

新しいエージェントを作成するには、endpointメニューから「Agents」を選択し、サイドパネルにあるAgent Builderパネルを開きます。

![Agents - Endpoints Menu](/images/agents/endpoints_menu.png)

作成フォームには以下が含まれます：

- **Avatar**: カスタムアバターをアップロードして、エージェントをパーソナライズします
- **Name**: エージェントに固有の名前を選択してください
- **Description**: エージェントの目的に関する詳細（任意）
- **Instructions**: エージェントの動作を定義するシステム指示
- **Model**: 利用可能なプロバイダーとモデルから選択してください
- **Conversation Starters**: ユーザーがエージェントとの新しいチャットを開始する際に表示される、最大4つまでの推奨プロンプト

**Tools**および**Skills**コントロールは、組み込み機能、ツール、MCPサーバー、Actions、およびSkillsのための検索可能なライブラリを開きます。項目を選択して設定し、エージェントを保存してください。

**既存のエージェントは、サイドパネル上部のドロップダウンから選択できます。**

- **チャット入力欄で「@」を使ってメンションすることでも可能です。**

![Agents - Mention](/images/agents/mention.png)

### Tool Library [#tool-library]

Agent Builderは、有効化された項目を**Tools**（ツール）と**Skills**（スキル）のセクションに分けて保持します。**Add tools**（ツールを追加）を開くと、カタログ全体を検索したり、**Official**（公式）、**Tools**（ツール）、**MCP**、**Actions**（アクション）でフィルタリングしたりできます。**Made by you**（作成済み）には、作成したMCPサーバーやActionsがまとめられ、**Favorites**（お気に入り）には、スターを付けた項目がエージェント間で利用可能な状態で保持されます。各ユーザーは、ツールライブラリのお気に入りを最大100個まで保存できます。

ビルダーを離れることなく項目を選択して設定できます。**Create new** メニューは、ユーザーがMCPサーバーまたはActionsを作成する権限を持っている場合にのみ表示されます。File Search、File Context、Code Interpreterなどのファイルベースの機能を削除すると、添付ファイルを確認する必要がある場合にファイルマネージャーが開きます。ファイルベースの機能は、ファイルが保持されている間は選択されたまま保存時に維持されます。機能を削除する前に、それらのファイルを削除または再割り当てしてください。

Skillsは独自のピッカーを使用しており、個別に選択することも、アクセス可能なカタログ全体として有効にすることもできます。詳細は[Skills](/docs/features/skills#agent-scope)を参照してください。

オペレーターは、実験的な [Agent Plugins](/docs/features/agent_plugins) を使用して、デプロイメントの Skills や MCP サーバーを起動時に読み込まれるパッケージにまとめることもできます。

### モデル設定 [#model-configuration]

モデルパラメータのインターフェースでは、エージェントの応答を微調整できます：

- Temperature (0-1の範囲で回答の創造性を調整)
- 最大コンテキストトークン数
- 最大出力トークン数
- ネイティブのビジョン画像入力に対する画像詳細設定 (`low`、`auto`、または `high`)
- プロバイダー固有の追加設定

エージェントの指示には `{{current_date}}`、`{{current_datetime}}`、および `{{iso_datetime}}` を使用できます。LibreChat は、サーバーで取得された論理ターンの開始時点からこれらを解決し、プロバイダーのループ、サブエージェントの初期化、およびヒューマン・イン・ザ・ループ（人間による介入）の再開を通じて、そのタイムスタンプを安定して保持します。最初の2つはリクエストのタイムゾーンを使用しますが、`{{iso_datetime}}` は UTC のままとなります。

認識された model-not-found エラーおよびプロバイダーのレート制限エラーは、ローカライズされたガイダンスを表示します。その他のプロバイダーエラーは、有用なプロバイダーのテキストを保持しますが、メッセージが永続化される前に LangChain のトラブルシューティング URL を省略します。[model-bound content protection](/docs/configuration/librechat_yaml/object_structure/message_filter#source-aware-filters) が有効な場合、その汎用的な保護エラーが引き続き優先されます。

### バージョン履歴 [#version-history]

編集権限を持つユーザーは、Agent Builderから**Version History**を開き、保存された設定をタイムライン上で確認できます。各エントリには保存日時が表示され、その時点でのツールや機能が要約されます。以前のエントリを復元するには確認が必要であり、実行すると現在のエージェント設定がその保存された状態に置き換わります。保存を行うと、結果として得られる設定が最新の履歴エントリと一致する場合であっても、LibreChatは重複したエントリを追加することなく、常にエージェントの現在の変更が適用されます。

### 会話のきっかけ (Conversation Starters) [#conversation-starters]

会話のきっかけ（Conversation starters）は、ユーザーがエージェントとのチャットを素早く開始するための方法を提供します。各エージェントには最大4つまで保存できます。

1. Agent Builderで、**Conversation Starters**フィールドを探します。
2. プロンプトを入力して **Enter** キーを押すか、**+** ボタンを選択してください。4つのスターターが追加されると、入力は無効になります。
3. 保存されたスターターをその場で編集するか、**X**ボタンを選択して削除します。
4. エージェントを保存します。

ユーザーがエージェントとの新しいチャットを開始すると、空のチャット画面にスターターがボタンとして表示されます。いずれかを選択すると、最初のメッセージとして即座に送信されます。エージェントにスターターが設定されている場合、使用中のModel Specsで定義された [`conversation_starters`](/docs/configuration/librechat_yaml/object_structure/model_specs#conversation_starters) よりも優先されます。スターターは、エージェントの [Marketplace](#agent-marketplace) 詳細ダイアログにも表示されます。

## エージェントの機能 [#agent-capabilities]

> **注:** すべての機能は `librechat.yaml` 設定ファイルを通じて切り替えることができます。詳細については、[docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) を参照してください。

### Code Interpreter [#code-interpreter]

有効にすると、Code Interpreter機能により、エージェントは以下のことが可能になります：

- 以下を含む複数の言語でコードを実行します：
  - Python、JavaScript、TypeScript、Go、C、C++、Java、PHP、Rust、およびFortran
- LibreChat Code Interpreter API を通じてファイルを安全に処理する
- ローカルでのセットアップ、設定、サンドボックスのデプロイなしでコードを実行します
- ファイルのアップロードとダウンロードをシームレスに処理します
- [Code Interpreter APIに関する詳細情報](/docs/features/code_interpreter)
  - オープンソースの [code-interpreter](https://github.com/ClickHouse/code-interpreter) サービス（セルフホスト）によって動作しています

会話から必要なすべての Code Interpreter ファイルを現在のサンドボックスに復元できなかった場合、LibreChat はモデルを呼び出す前にエージェントを停止し、ユーザーにファイルの再添付を求めます。これにより、古いファイル参照やアクセスできないファイル参照を使用して実行が継続されることを防ぎます。

会話ファイルが同じ Code Interpreter のファイル名を共有する場合、LibreChat は個別のサンドボックス送信先を割り当て、解決されたパスをエージェントに伝えます。競合時の動作や、マルチエージェントにおけるプライベートファイルの制限については、[Seamless File Handling](/docs/features/code_interpreter#seamless-file-handling) を参照してください。

#### ステートフルなコードセッション [#stateful-code-sessions]

Stateful code sessions（ステートフルなコードセッション）により、エージェントはコード実行間でサンドボックスワークスペースを再利用できるようになります。ファイル、インストール済みのパッケージ、および作業状態は通常引き継がれるため、反復的な分析や複数ステップにわたるファイル操作に役立ちます。Agent Builderの **Stateful environment** セレクターでは、そのワークスペースを誰が共有するかを制御します：

- **ユーザーワークスペース（推奨）:** サインインしたユーザーのステートフルなエージェントは、1つのワークスペースを共有します。
- **エージェント + ユーザーワークスペース:** 各ユーザーは、エージェントごとに個別のワークスペースを取得します
- **Conversation workspace:** 各ユーザーは、会話ごとに個別のワークスペースを取得します

管理者は [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) の下で名前付きバックエンドを設定することもできます。これらが存在する場合、個別の **Execution environment** セレクターによって、ワークスペースを所有する管理対象の Code API、オペレーターが接続した VM、またはパーソナルワーカーを選択します。**Deployment default** は、設定されたデフォルトの実行環境を使用します。上記の共有スコープは、そのバックエンドの選択とは独立しています。

デプロイメントでセルフサービスワーカーが有効になっている場合、Code Environment（コード環境）の管理権限を持つユーザーは、**Settings > Code environments** を開いて、自身のVM上のアウトバウンド `@librechat/code` ワーカーをペアリングし、Agent Builderでそれを選択し、後で取り消すことができます。パーソナル環境は所有者に紐付いており、コード、シェル、およびプログラムによるツール呼び出し（Programmatic Tool Calling）に同じルートを使用します。実験的なセットアップとセキュリティモデルについては、[Attached environments and pairing](/docs/features/code_interpreter#attached-environments-and-pairing) を参照してください。

アタッチされたワークスペース内で、Agentはディレクトリの一覧表示、ファイルの読み取り、テキスト検索、ファイルの作成、および選択したワーカーを通じたBashの実行を行うことができます。AgentごとのGit名とメールアドレスを設定することで、リポジトリの認証情報を提供することなく、そこで行われたコミットを識別できます。デプロイメントでは、[`statefulCodeSessions.principalWorkers`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions)を使用して、新しいパーソナルワーカーを制限することが可能です。

アタッチされたワーカーが複数のワークスペースルートをアドバタイズする場合、チャットコンポーザーは、エージェントまたはそのサブエージェントが使用する各アタッチ済み環境に対して1つの選択を要求します。会話はそれらの選択をターン間および承認の再開後も保持します。LibreChatはライブワーカーに対してそれらを検証し、必要なワークスペースが欠落しているか利用できない場合は送信をブロックします。正確に1つのワークスペースをアドバタイズするワーカーは、新しい会話に対して自動的に選択されます。詳細および現在の制限事項については、[Attached environments and pairing](/docs/features/code_interpreter#attached-environments-and-pairing) を参照してください。

新しいエージェントは、初期状態ではサインインしているユーザーの **設定 > データコントロール > コード実行** にある **デフォルトのステートフルワークスペース** を使用します。個人のデフォルト設定は、変更されるまで **ユーザーワークスペース** となっています。この設定を更新しても、既存のエージェントが変更されたり、ステートフルコードセッションが自動的に有効になったりすることはありません。管理者は [`statefulCodeSessions.allowedEnvironments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) を使用して、利用可能なスコープを制限できます。保存された個人のデフォルト設定が許可されなくなった場合、新しいエージェントは許可された最初のスコープを使用します。

<Callout type="warning" title="非常に実験的">
  Stateful Code Sessionsは初期の実験段階にあります。その動作、設定、永続性の特性、および基盤となる統合は大幅に変更される可能性があります。現在の実装を安定した本番環境向けの契約として扱わないでください。
</Callout>

この機能はオプトイン方式です。管理者は `stateful_code_sessions` を [エージェントの機能](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) に追加し、[`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) または指定された [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions) を通じて、専用のステートフルな Code Interpreter ルートを設定する必要があります。エージェントで Code Interpreter が有効になっている必要があり、その詳細設定で **Stateful code sessions** がオンになっている必要があります。

Statefulなリクエストは、専用のURLが存在しない、または互換性がない場合に、通常のstatelessなCode Interpreterエンドポイントへフォールバックすることはありません。また、Statefulなセッションとstatelessなセッションは、ライブファイルやインストール済みのパッケージを共有しません。Statefulなワークスペースは、そのスコープに関係なく、いつでもリセットされる可能性があります。管理されたCode Interpreter環境では、重要な出力は `/mnt/data` 配下に保存してください。アタッチされたワークスペースは、ワーカーが所有する別のディレクトリです。チャットのアップロードファイルは、デフォルトではそのアタッチされたディレクトリにコピーされません。それ以外の場合でも、セッションの状態を永続的なストレージとして信頼しないでください。

ステートフルな `create_file` または `edit_file` ツールが応答中にファイルを作成すると、アシスタントのメッセージにコンパクトな **Workspace changes** 行が表示されます。これを展開すると、変更された固有のパスを確認し、LibreChatの認証済みファイルフローを通じて各ファイルをダウンロードできます。これは、それらのツールによって作成されたファイルのメッセージごとの記録であり、ワークスペース全体の永続的なスナップショットではありません。ステートレスな Code Interpreter の出力は、引き続き通常のインライン添付ファイルインターフェースを使用します。

接続された環境（attached environments）の場合、コンポーザーは会話レベルのコード承認モードとして、**Ask before changes**（変更前に確認）、**Accept edits**（編集を許可）、**Full access**（フルアクセス）を公開できます。利用可能性は、環境の管理者が定義した権限スキーマによって制限されます。より許容度の高いモードを選択しても、ロールの付与、明示的なツールルール、フック、またはサンドボックスの境界が上書きされることはありません。詳細は [Attached-environment tool permissions](/docs/features/code_interpreter#attached-environment-tool-permissions) を参照してください。

### File Search [#file-search]

File Search機能により、以下が可能になります：

- RAG (Retrieval-Augmented Generation) 機能
- アップロードされたドキュメント全体に対するセマンティック検索
- ファイルの内容に基づいたコンテキスト認識型の応答
- エージェントおよびチャットスレッドの両レベルにおけるファイル添付のサポート

### ファイルコンテキスト [#file-context]

File Context機能を使用すると、エージェントはファイルから抽出したテキストをシステム指示の一部として保存できます。

- ドキュメントの構造と書式を維持しながらテキストを抽出する
- マルチカラムテキストや混合コンテンツを含む複雑なレイアウトを処理する
- テーブル、数式、およびその他の専門的なコンテンツを処理する
- 多言語コンテンツの操作
- テキストはデータベース内のエージェントの指示に保存されます
- **OCRサービスは不要** - デフォルトでテキスト解析を使用し、フォールバックメソッドを備えています
- **OCRによる強化** - OCRが設定されている場合、画像やスキャンされたドキュメントの抽出品質が向上します
- 「テキストとしてアップロード」と同じ処理ロジックを使用します：**OCR > STT > テキスト解析**
- [OCR設定の詳細はこちら](/docs/features/ocr)

**注:** File Contextには、エージェントのシステム指示に含まれる抽出テキストが含まれます。個別の会話で一時的なドキュメントの質問を行う場合は、チャットから [Upload as Text](/docs/features/upload_as_text) を使用してください。

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCPは、アプリケーションが大規模言語モデル（LLMs）にコンテキストを提供する仕組みを標準化するオープンプロトコルであり、AIツールやデータソースのためのユニバーサルアダプターとして機能します。

詳細については、[MCP](/docs/features/mcp) のドキュメントを参照してください。

#### MCPツールを使用するAgents [#agents-with-mcp-tools]

1. `librechat.yaml` ファイルで MCP サーバーを設定します
2. LibreChatを再起動して接続を初期化します
3. エージェントを作成または編集する
4. Agent Builderで **Add tools** を開き、**MCP** を選択します。
5. 追加したいMCPサーバーを選択してください。各サーバーは単一のエントリとして表示されます。
6. エージェントへの変更を保存します

この例では、エージェントに **[Spotify MCP server](https://github.com/LibreChat-AI/spotify-mcp)** を追加しました。

![Agents - MCP](/images/agents/mcp_tools_v2.png)

#### MCPツールの管理 [#managing-mcp-tools]

MCPサーバーをエージェントに追加した後、どの特定のツールが利用可能かを微調整できます：

- MCPサーバーを追加した後、それを展開して利用可能なすべてのツールを表示します。
- 必要に応じて個別のツールにチェックを入れるか、外してください
- 例えば、Spotify MCP serverは、約20個のツール（検索、再生制御、プレイリスト管理など）を提供します。
- このきめ細かな制御により、エージェントが必要とするツールのみに制限することができます。

`{{LIBRECHAT_BODY_*}}` を使用するリクエストスコープのサーバーは、チャットの実行によってそれらの値が提供されるまでツールを列挙できません。そのため、Agent Builder ではツールごとの切り替えではなく、サーバー全体に対して1つのランタイムツール選択が表示されます。その選択を解除すると、サーバーとの接続が切断されます。OAuth の後、LibreChat は認証情報を保持し、接続するために最初の適切な実行が行われるまで待機します。

Agentが明示的にMCPツールを選択したにもかかわらず、実行開始時にいずれのツールも解決できない場合、LibreChatはそれらを使用せずに黙って続行するのではなく、接続およびアクセスに関するガイダンスを表示して実行を停止します。サーバーの再接続や認証を行い、ツールへのアクセスを確認してから、実行を再試行してください。

![Agents - MCP Tools](/images/agents/mcp_agent_tools.png)

詳細はこちら:

- [MCPサーバーの設定](/docs/features/mcp)
- [Model Context Protocol 入門](https://modelcontextprotocol.io/introduction)

### Deferred Tools [#deferred-tools]

Deferred toolsを使用すると、エージェントはすべてのMCPツールを事前にLLMコンテキストに読み込むことなく、多数のツールにアクセスできるようになります。その代わり、deferred toolsは**Tool Search**メカニズムを通じて実行時に検出可能となります。

これは、エージェントが多数のツールを持つ多くのMCPサーバーにアクセスする場合に特に有用です。すべてを読み込むとコンテキストウィンドウの大部分を消費し、応答品質が低下するためです。

**仕組み:**

- 「deferred」とマークされたツールは、初期のLLMコンテキストから除外されます。
- `ToolSearch` ツールが自動的に追加され、LLM が必要に応じて遅延読み込みツールを検出して読み込めるようになります。
- 一度検出されると、そのツールは残りの会話で使用可能になります。

**deferred toolsの設定:**

1. Agent Builderを開き、MCPツールを追加します
2. 任意のMCPツールのドロップダウンをクリックします
3. 「読み込みを遅延」を切り替え — 遅延されたツールには時計アイコンが表示されます

**注:** `deferred_tools` 機能はデフォルトで有効になっています。これは [`librechat.yaml` エージェント設定](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)から切り替えることができます。

### Activity Groups [#activity-groups]

Activity groupsは、エージェントの推論とツール呼び出しの連続する各ブロックを生成された1行のヘッダーの下に折りたたみ、長い実行結果をスキャンしやすくします。管理者は `activityLabel` を使用してこれらを有効にでき、より高速なモデル、別の設定済みendpoint、カスタムプロンプト、および実行ごとの制限を使用できます。ヘッダーの生成は別のモデル呼び出しであり、そのトークンとコストは記録されます。詳細は [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) を参照してください。

管理者は `activityPhaseLabel` を個別に有効にすることで、最終的な回答の前に、2つ以上の論理的なアクティビティを折りたたみ可能な親サマリーにまとめることができます。これにより、各子アクティビティを保持しつつ、長時間実行される処理に対してより高レベルなアウトラインを提供します。フェーズサマリーは独自のモデル、endpoint、プロンプト、および実行ごとの上限を使用し、設定がない場合はアクティビティラベルと実行設定にフォールバックします。

連続した実行において少なくとも2つの完了したラベル付きツールグループが含まれるとすぐに、LibreChatはオプションのフェーズサマリーが到着する前であっても、それらを同じフェーズカードサーフェスに折りたたみます。最新の完了した子ラベルが暫定的なヘッダーとして機能し、ライブ推論および進行中のツール呼び出しは折りたたみの外側に残ります。読み込まれた履歴も同様のグループ化を使用し、後からサーバーによって生成されたフェーズサマリーが、読者が開いたカードを閉じることなく暫定的なヘッダーを置き換えます。

[Smooth Streaming](/docs/features/smooth_streaming) が有効な場合、新しく生成された親サマリーは、表示されているアクティビティを折りたたまれたグループへとスムーズに格納します。読み込まれた履歴ではこの遷移は再生されず、LibreChatはデバイスの「視差効果を減らす（reduced-motion）」設定を尊重します。

短い進捗テキストは、その親フェーズ内に留まります。エージェントが実質的な回答を開始すると、LibreChatはそのテキストの前にフェーズを閉じるため、ユーザー向けの回答結果は折りたたまれた要約の外側に保持されます。1回の実行で、後の推論やツールが別の論理的なアクティビティブロックを開始した際に、複数の親フェーズが作成されることがあります。永続化されたフェーズ境界は、不正な形式や省略されたコンテンツ部分が圧縮される際にリベースされるため、リロード後もグループ化は整合性を保ちます。

フェーズ内で生成されたファイルは、折りたたまれたカードの中に隠されるのではなく、その下のメディア行に表示されたままになります。ファイル名のみ、`/mnt/data/...`、または `sandbox:` パスを使用したMarkdownの画像参照は、対応するターンの添付ファイルとして解決されます。ファイルがメディア行から除外されるのは、折りたたまれたフェーズの外側にあるインライン画像が正常に解決された場合のみであり、これにより壊れた参照を信頼することなく重複を防ぎます。

Generic AgentおよびMCPツールカードは、**Preparing**（SDKへの引き渡し前、承認やその他の待機を含む場合があります）と**Calling**（SDKへの引き渡しから結果まで）を区別します。完了したカードには両方の間隔が表示されます。呼び出し間隔は、必ずしもアップストリームのMCPやClickHouseの実行時間とは一致しません。以前に保存されたメッセージや、特殊なCode、Bash、ファイル、メモリカードには、明確にラベル付けされた**Total elapsed**（合計経過時間）の実行ステップ時間が保持されます。停止、キャンセル、失敗、および完了したステップは、会話をリロードした後も個別のステータスを保持します。

ツールが実行されている間、展開されたBash、コード実行、およびファイル作成の詳細ペインは、ストリーミングされるコマンド、コード、またはプレビューコンテンツに合わせて一番下まで自動スクロールします。上にスクロールするとこの追従動作が一時停止され、現在の読み取り位置が保持されます。

Bashの出力はターミナル形式のテキストとしてレンダリングされます。長い出力は、エラーが表示されやすい最後の15行に折りたたまれます。**Show more**（もっと見る）および**Show less**（折りたたむ）を使用して展開または折りたたみができ、**Copy**（コピー）ボタンで出力をコピーできます。何も出力されなかったコマンドには**No output**（出力なし）と表示されます。[attached workspace](/docs/features/code_interpreter#attached-environments-and-pairing)で実行されたコマンドの場合、失敗したコマンドにはその理由（**exit code N**、`SIGKILL`などのシグナルによる**terminated by**、または**timed out**）がマークされ、stderrはstdoutとは別にスタイル設定されます。完了したコマンドには**Ran command**（コマンド実行済み）というラベルが付けられ、単一の呼び出しを含むツールグループは、その呼び出しの詳細を直接開きます。

### ライブ推論ラベル [#live-reasoning-labels]

ライブ推論ラベルは、汎用的な **Thinking** や **Thoughts** という見出しを、十分な長さのトップレベルの推論ストリームに応じて変化する短いオリエンテーション（方向付け）に置き換えます。このラベルは既存の推論見出しをその場で更新するものであり、メッセージパーツの追加や並べ替えは行いません。

生成がアクティブな間は、最新のライブ推論ラベルと応答タイマーがシマー表示されます。確定した推論、以前の兄弟応答、およびライブの末尾にないラベルは静止したままになります。

管理者は `reasoningLabel` を使用してこれを有効にでき、個別のモデル、endpoint、プロンプト、更新しきい値、および実行ごとの呼び出し上限を選択できます。各リビジョンは追加のモデル呼び出しとなり、そのトークンとコストが記録されます。デフォルト値、ルーティングの優先順位、およびプライバシーに関する考慮事項については、[Live Reasoning Labels](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels) を参照してください。

### ツールインテントラベル [#tool-intent-labels]

Tool intent labelsは、汎用的なライブツールステータスを、その特定の呼び出しに対してモデルが記述した短い説明に置き換えます。管理者は、オプトインの `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) を追加する必要があります。ネイティブツールは自動的にラベルを使用します。Agent Builderでは、MCPサーバーを展開し、個々のツールまたはサーバー全体に対して **Intent label** をオンにしてください。

Model Specsの場合、[`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) を使用することで、すべての対象ツールを有効にするか、解決されたツールIDを選択することができます。Intentフィールドはモデルに送信されるツールスキーマに追加されるため、選択的に有効化することでスキーマトークンのオーバーヘッドを削減できます。

インテントラベルは、プログラム専用のMCPツールには適用されません。これは、サンドボックスコード内で行われる呼び出しが個別のツールカードをレンダリングしないためです。拡張されたプログラム実行では、代わりに内部呼び出しのコンパクトなライブトレースが表示されます。

### Programmatic Tool Calling [#programmatic-tool-calling]

Programmatic Tool Calling (PTC) を使用すると、エージェントは各ツールをモデルから直接呼び出す代わりに、[Code Interpreter](/docs/features/code_interpreter) サンドボックス内から選択した MCP ツールを実行できるようになります。モデルは Code Interpreter によってバックアップされたオーケストレーションツールを受け取り、生成されたツール関数を呼び出すサンドボックス化されたコードを記述します。また、回答を返す前にループ、条件分岐、再試行、結果処理を使用することが可能です。

これは、複数のリソースへのクエリ、結果のページネーション、出力の比較、あるいはエージェントが説明する前にツールからの応答を変換するなど、マルチステップのツールワークフローにおいて有用です。

**プログラム可能なツールの設定:**

1. [`librechat.yaml` エージェントの機能](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)で、`programmatic_tools` と `execute_code` の両方を有効にします。
2. エージェントで Code Interpreter を有効にします。
3. MCPツールを追加し、MCPサーバーを拡張します。また、個々のツールまたはサーバー全体に対して**Programmatic**の切り替えを行います。Programmaticなツールにはコードアイコンが表示されます。

Agent Builderは、Code Interpreterが選択されるまで、プログラムによるトグルを無効に保ちます。Code Interpreterを削除すると、エージェントのプログラムによる選択項目は直ちにクリアされます。作成、更新、複製、およびバージョンの復元時に、サーバーは`execute_code`機能またはCode Interpreterツールが利用できない場合、プログラムによる呼び出し元オプションも削除します。これにより、使用不可能な構成を保持することなく、古い不整合なAgentを開いて修正できるようになります。

**注:** `programmatic_tools` はオプトイン機能であり、デフォルトのエージェント機能リストには含まれていません。PTCには、Tool Call Serverコンポーネントを備えたCode Interpreterのデプロイメントも必要です。実行時、LibreChatは現在の呼び出し元機能の投影と信頼されたツールレジストリを照合するため、イベントデータによって利用可能なマップを絞り込むことはできますが、ツールを付与することはできません。サンドボックスから呼び出せるのは、アクティブかつ登録済みのプログラムツールのみであり、未登録の呼び出しは拒否されます。

プログラム実行中に Code Interpreter カードを展開すると、各内部ツール呼び出しのターミナルスタイルのトレース、引数のプレビュー、ステータス、実行時間、およびエラーを確認できます。このトレースは現在のブラウザセッション中のみ有効であり、ページをリロードすると復元されません。

### Background Tool Calls [#background-tool-calls]

バックグラウンドツール呼び出し（Background tool calls）を使用すると、エージェントは長時間実行される適切なCode Interpreter、MCP、Plugin、またはActionツールを開始し、そのまま作業を継続できます。最初の呼び出しは即座にタスク参照を返します。保存されたエージェントの場合、サポートされている完了処理はデフォルトで後続の継続処理において自動的に配信されます。`check_background_task`は、明示的なステータス確認、制御、アーティファクトの収集、および復旧のために引き続き利用可能です。

`check_background_task` は、プロセスローカルの作業が実行されている間、`started_at` と現在の `elapsed_ms` を報告します。処理が完了（settlement）した後は、`settled_at` を報告し、`elapsed_ms` を完了時の期間で固定します。永続ストレージから復元された最終結果には、元のプロセスローカルでのディスパッチ時のタイムスタンプが利用できない場合、開始時刻や経過時間を含まずに `settled_at` のみが含まれることがあります。

この機能を使用するには、管理者がオプトインの `run_in_background` [エージェント機能](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)を追加する必要があります。その後、Agent Builderで対象となるツールを設定してください。

- **Code Interpreter:** エージェントで Code Interpreter を有効にします。コード実行とシェルコマンドはデフォルトでバックグラウンド実行の対象となります。これを無効にするには、ツール設定で **Background execution** をオフにしてください。
- **MCP:** MCPサーバーを開き、個別のツール、またはサーバー全体を **Background** としてマークします。
- **Plugin tools:** 適切なツールを開き、**Background execution** をオンにします。
- **Actions:** Actionの「**Background execution**（バックグラウンド実行）」をオンにすると、そのAction内のすべての対象オペレーションでこの機能が有効になります。OAuth Actionではこのスイッチは表示されません。また、オペレーションのスキーマ自体で `run_in_background` パラメータが定義されている場合、LibreChatのディスパッチフラグとの競合を避けるため、そのオペレーションは対象外となります。

これらの設定はバックグラウンド実行を許可しますが、強制するものではありません。モデルは呼び出しごとに、対象となるツールをバックグラウンドで実行するかどうかを判断します。

LibreChatのチャットにおいて、バックグラウンドのコード実行が完了すると、そのstdout（標準出力）と生成されたファイルは、後のポーリングではなく、元のコード呼び出し箇所に表示されます。生成されたファイルは、後続のターンでも保持されます。自動継続機能では、完了した作業が元のタスクにリンクされた折りたたみ可能なウェイクアップタスクカードとして表示されます。

前回のフォアグラウンド実行が終了した後にサーバーがその続きを開始すると、開いている会話は新しい生成にアタッチされ、リロードを必要とせずに完了したタスクの出力を更新します。

管理者が [`endpoints.agents.backgroundTasks.completionWakeups: false`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) を設定してポーリングのみの動作に戻さない限り、自動補完のウェイクアップは有効になっています。ホストは、対象となる複数のコンテンツのみの補完を1つの継続処理にバッチ処理する場合があります。ライブアーティファクトを生成するタスクについては、引き続きその実行を所有するプロセスでのポーリングが必要です。

管理者は、[`endpoints.agents.backgroundTasks.ordinaryToolCancellation: true`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) を設定することで、オーナー権限によるキャンセルを有効にすることもできます。タスクは、基盤となる呼び出しが完了するまでキャンセルが要求されたことを報告し、その間、容量は予約されたままとなります。キャンセルは協調的なプロセスです。つまり、中止シグナルを無視するツールは、そのまま正常に完了する可能性があります。この制御は、アタッチされたBashを含む、通常のプロセスローカルなバックグラウンドツールに適用されますが、独立して所有されるデタッチされたSubagentには適用されません。

対象となるツールのみがこの設定を公開します。通常のバックグラウンド実行はプロセスローカルであり、ワーカープロセスの喪失を生き延びることはできません。しかし、コンテンツのみのターミナル結果が永続化されると、自動配信は永続的なものとなり、別のレプリカで継続される可能性があります。プロセスローカルのレジストリは、会話、ユーザー、プロセスごとに実行中のタスクと保持された結果ペイロードを制限します。安全な場合に完了した作業を削除し、保留中の処理によって安全な削除が妨げられる場合は、スコープ制限された容量結果を返します。呼び出しがキャンセルを無視した場合、LibreChatは中止後の1分間の猶予期間が経過した後にプロデューサーリース（producer lease）の更新を停止し、不確実な外部作業を誤ってタイムアウトとしてマークすることなく、自動完了配信を終了します。Detached Subagentsは、Redisでルーティングされたライブ制御を備えた、個別の永続タスクおよびトランスクリプトパスを使用します。詳細は [Detached Subagent Threads](/docs/features/subagents#detached-subagent-threads) を参照してください。

### ユーザーへの質問とツール承認 (Ask User and Tool Approval) [#ask-user-and-tool-approval]

**Ask User** ツールを使用すると、エージェントは実行を一時停止して、不足している情報の要求、選択肢の提示、または進め方の確認を行うことができます。1回の呼び出しで、最大4つまでの関連する質問をグループ化できます。LibreChatは一度に1つの質問を表示し、「戻る」、「次へ」、およびクリック可能な進捗ステップを提供します。ステップ間を移動しても回答は保持され、単一選択の回答は送信しなくても自動的に進みます。すべての質問に回答すると最終ステップに「送信」が表示され、「スキップ」を選択するとどのステップからでもバッチ全体を拒否できます。各質問は、自由記述形式の回答、またはエージェントが設定した単一選択・複数選択のいずれにも対応しています。モデルが呼び出しを準備している間、LibreChatは質問を進捗カードにストリーミングし、準備が整うと対話型フォームに置き換わります。送信後、同じ実行が完全な回答マップとともに再開されます。**Ask User** はToolsマーケットプレイスから追加できます。管理者はデフォルトの `ask_user_question` 機能を削除することで、これを非表示にできます。

マルチ質問カードを折りたたむと、コンポーザーは通常のステア（誘導）またはキュー（待機）モードに戻りますが、一時停止されたカードはスレッド内に残ります。カードは引き続き展開、回答、スキップ、または停止が可能です。単一質問の一時停止は、引き続きフォーカスされたコンポーザー回答モードを使用します。

送信された回答は再開アクションとともに永続化されるため、再開された実行が初期化されている間に停止しても、受け入れられた回答が破棄されることはありません。

質問の記録が確定すると、長い回答がトランスクリプトを占有しないよう、デフォルトで1行のツールエントリに折りたたまれます。これを開くと、質問内容や回答内の保持された改行を確認できます。既存の **Auto-expand tool details** 設定でもこの確定時の表示を制御できます。入力が必要な間は、ライブフォームは開いたままになります。

各質問には、最大80文字のオプションの見出し、最大2,000文字の質問テキスト、最大4,000文字のオプションの補足コンテキスト、および最大12個の選択肢を設定できます。選択肢のラベルは280文字、選択肢の値は500文字、送信される各回答は16,000文字までに制限されています。

管理者は、一致したツール呼び出しが実行される前に承認を必須にすることもできます。ツールに応じて、ユーザーは承認、拒否、引数の編集、または直接の応答を行うことができます。一時停止された実行はチェックポイントが作成されるため、決定後に再開可能です。これには、デフォルトのMongoDBチェックポインターを使用している場合の別のレプリカ上での再開も含まれます。デプロイメント全体のツール承認はデフォルトで無効になっていますが、接続されたCode環境を使用するAgentは、管理者が明示的に無効にしない限り、[ask-by-default安全ポリシー](/docs/features/code_interpreter#attached-environment-tool-permissions)が適用されます。[`toolApproval`および`checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval)を参照してください。

承認待ちの状態でコンポーザーのレビューパネルが開いている間、対応するスレッドカードには決定ボタンを複製するのではなく、リクエストがレコードとして表示されます。メッセージボックスの上にあるパネルで呼び出しを確認し、**Continue** を選択してください。コンポーザーチップからパネルを折りたたむと、決定事項が保持された状態でスレッドカードのコントロールが復元されます。再度開くと、レビューはパネルに戻ります。他のアクションのカードは、それぞれのコントロールを保持します。

### Skills [#skills]

Skillsを使用すると、エージェントは `SKILL.md` 定義から再利用可能な指示を読み込むことができます。これらは、チャットから `$` を使用して手動で選択したり、スキルカタログを通じてモデルが自動的に検出したり、あるいはすべてのターンで常に適用したりすることが可能です。Agent Builderでは、スタンドアロンのランタイム作成を有効にすることもできます。つまり、エージェントは既存のカタログを受け取らずにSkillを作成したり、ユーザーが対応する権限を持っている場合に選択されたSkillを編集したりすることができます。

作成、呼び出し、およびアクセス制御の詳細については、[Skills](/docs/features/skills) を参照してください。

### Memory [#memory]

**Memory**ツールを使用すると、ユーザーが何かを記憶または忘れるように明示的に要求した際に、エージェントが構造化されたユーザーメモリを保存、更新、または削除できるようになります。Memoryは、デプロイメントに対して構成され、ユーザーのロールおよびパーソナライゼーション設定によって許可され、かつエージェント上で有効化されている必要があります。

デフォルトでは、エージェントはユーザーの共有個人メモリプールを使用します。**Keep memories separate for this agent**をオンにすると、ユーザーごと、エージェントごとにプライベートなパーティションが割り当てられます。分離されたエージェントは、既存の共有メモリや、他の分離されたエージェントによって作成されたメモリを参照できません。ユーザーはメモリパネルで、個人用メモリまたはエージェント固有のメモリをフィルタリングできます。エージェントのパーティションの読み取り、作成、更新には、そのエージェントへの現在のアクセス権が必要です。削除については、エージェントが削除された後でもパーティションをクリーンアップできます。[User Memory](/docs/features/memory#agent-memory)を参照してください。

### Artifacts [#artifacts]

Artifacts機能を使用すると、エージェントがインタラクティブなコンテンツを生成および表示できるようになります。

- Reactコンポーネント、HTMLコード、およびMermaidダイアグラムを作成する
- チャットの横にある専用パネルにコンテンツを表示します。このパネルは全画面表示に拡大したり、別のブラウザウィンドウで開いたりすることができます。
- エージェントレベルでアーティファクト固有の指示を設定する
- [Artifactsに関する詳細情報](/docs/features/artifacts)

有効にすると、3つの指示モードから1つを選択します：

- **Normal**: React、HTML、SVG、Markdown、および Mermaid 用の標準的なアーティファクト指示を追加します。
- **shadcn/ui**: 標準的な手順に加え、shadcn/ui コンポーネントライブラリを使用してインターフェースを構築するためのガイダンスを追加します。
- **Custom**: アーティファクトのレンダリングを有効にしたまま、組み込みのアーティファクト指示を注入しません。これにより、エージェント自身の指示が完全に制御できるようになります。

エージェントレベルでartifactsを設定する方が、従来のアプリ全体での設定よりもきめ細やかな制御が可能になるため、推奨されるアプローチです。

**Custom**を選択する場合は、指示の中に最低限の基本的なアーティファクト形式を含めてください。

最小限必要な指示の簡単な例を以下に示します：

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

#### 画像ツールを使用してエージェントを作成する [#create-an-agent-with-image-tools]

1. OpenAI Image Tools用の `IMAGE_GEN_OAI_API_KEY` など、画像ツールの認証情報を `.env` に追加します。
2. LibreChatを再起動して、新しい環境変数を読み込ませます。
3. endpointメニューから**Agents**を選択します。
4. サイドパネルからAgent Builderを開き、エージェントを作成または編集します。

`IMAGE_GEN_OAI_MODEL` などのモデル変数を含む画像設定の完全なガイドについては、[Image Generation & Editing](/docs/features/image_gen) を参照してください。

- ツールは [`librechat.yaml`](/docs/configuration/librechat_yaml) 設定ファイルを使用して無効化できます。

### Handoffs [#handoffs]

Handoffs（引き継ぎ）機能を使用すると、プライマリ・エージェントが関連するコンテキストを保持したまま、会話をスペシャリスト・エージェントに転送できます。**Advanced settings**（詳細設定）でオーケストレーションセクションを開き、最大10個までのHandoffエージェントを追加してください。設定された各Handoffは、スペシャリストの専門知識が必要になった際にモデルが動的に選択できる転送ツールを作成します。

各ハンドオフには、モデルが適切なスペシャリストを選択するのに役立つ説明を追加できます。また、プライマリ・エージェントがスペシャリストのためにどのようなコンテンツを生成すべきかを記述するパススルー指示を提供したり、オプションで `instructions` というデフォルトのコンテンツ・パラメータ名を変更したりすることも可能です。ハンドオフは常にAgent Builderで利用可能です。Agent Chainやサブエージェントとは異なり、エンドポイントの機能を有効にする必要はありません。到達可能なハンドオフ・エージェントからのツール呼び出しは、後のターンでも構造化されたまま維持されるため、プロバイダーはフラット化されたテキストではなく、有効なツール呼び出し履歴を受け取ることができます。

### Agent Chain [#agent-chain]

Agent Chain機能はMixture-of-Agents (MoA) アプローチを可能にし、連携して動作するエージェントのシーケンスを作成できるようにします：

- 複雑なタスクのために専門エージェントのチェーンを作成する
- チェーン内の各エージェントは、前のエージェントからの出力にアクセスできます。
- エージェントチェーンの最大ステップ数を設定する
- **注:** この機能には、Agent BuilderのAdvanced Settingsパネルからアクセスしてください。
- **注:** この機能は現在ベータ版であり、変更される可能性があります。
  - 現在チェーン可能なエージェントの最大数は10ですが、将来的に設定可能になる可能性があります。

  src="https://firebasestorage.googleapis.com/v0/b/superb-reporter-407417.appspot.com/o/agent_chain.png?alt=media&token=bfa209b9-d2ab-403f-b097-6300b4017fc8"
  alt="エージェントチェーン"
  width={488}
  height={269}
/>

この機能は、[同名の「Mixture-of-Agents」論文](https://arxiv.org/abs/2406.04692)で説明されているように、各エージェントが前の層のすべてのエージェントからの出力を補助情報として取り込み、応答を生成する階層型Mixture-of-AgentsアーキテクチャをLibreChatに導入します。

### Subagents [#subagents]

Subagentsを使用すると、エージェントは焦点を絞ったタスクを独立した子実行や保存済みのAgentチームに委任できます。各子エージェントは独立したコンテキストとツール実行環境を持ち、すべての中間ステップで親のコンテキストを埋め尽くす代わりに、簡潔な結果を親に返します。切り離された子エージェントの作業は、ナビゲート可能な閲覧専用のスレッドとして保存されます。

SubagentsはAgent Chainとは異なります。Chainは複数のエージェントをグラフの参加者として調整しますが、Subagentsはエージェントによってツール呼び出しとして生成され、スコープが限定された委任を行います。LibreChatは、到達可能な子エージェントや保存されたチームメンバーが必要とする構造化されたツール呼び出し履歴を、その後のターンにわたって保持しつつ、利用不可能なツールをアクティブな実行から除外します。設定や制限については、[Subagents](/docs/features/subagents)を参照してください。

### 高度な設定 [#advanced-settings]

「capabilities」以外の、エージェントの詳細設定（エージェントフォームの「詳細」ビューにあります）。

#### Max Agent Steps [#max-agent-steps]

この設定では、エージェントが「実行（run）」内で行えるステップ数を制限できます。これは、最終的な応答が返されるまでのエージェントのループ処理を指します。

設定しない場合、デフォルトは25ステップですが、必要に応じて調整可能です。管理者の方は、[`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit) ファイルでグローバルなデフォルト値およびグローバルな最大値を設定できます。

ターンがステップ予算を使い切った場合、LibreChatは部分的な応答やツール呼び出しをエラーで置き換えるのではなく、そのまま保持します。メッセージには、新しいツール予算で新しいターンを開始する **Keep going** と、これまでの作業内容からツールを使わずに回答するようエージェントに促す **Answer now** が表示されます。通知を閉じても、現在のブラウザ表示にのみ影響します。

管理者は、[Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers) を使用して、ストリーミングされるツール呼び出しの引数やモデルのデルタイベントに制限を設けることもできます。

「ステップ」とは、AI APIリクエスト、またはツール使用の1ラウンド（LLMが単一のリクエストから提供するツール呼び出しの数に応じて、1つまたは複数のツール）のいずれかを指します。

ツールを使用しない単一のレスポンスは1ステップです。ツール使用の1ラウンドは通常3ステップとなります：

1. APIリクエスト -> 2. ツール使用（1つまたは複数のツール） -> 3. フォローアップAPIリクエスト

## ファイル管理 [#file-management]

Agentsは、ファイルを扱うための複数の方法をサポートしています：

### チャットインターフェース内 [#in-chat-interface]

エージェントとチャットする際、4つのアップロードオプションがあります：

1. **画像のアップロード**
   - ネイティブのビジョンモデルサポートのために画像をアップロードします
   - 画像をモデルプロバイダーに直接送信します

2. **テキストとしてアップロード** (`context` 機能が必要)
   - 会話にドキュメントの全コンテンツを抽出して含めます
   - デフォルトでテキスト解析を使用します。設定されている場合はOCRによって強化されます。
   - 現在の会話にのみコンテンツが存在します
   - [テキストとしてアップロード](/docs/features/upload_as_text) を参照してください

3. **ファイル検索のためのアップロード** (`file_search` 機能が必要、ONに切り替え)
   - ベクトルストアを使用したセマンティック検索（RAG）を利用します
   - ツール使用を通じて関連するチャンクを返します
   - 大きなドキュメントや複数のファイルに最適
   - 構造化データ（CSV、Excel、JSONなど）には最適ではありません

4. **Code Interpreter用のアップロード** (`execute_code`機能が必要、ONに切り替えること)
   - コードインタープリター環境にファイルを追加します
   - 構造化データ（CSV、Excel、JSONなど）に最適
   - [Code Interpreter](/docs/features/code_interpreter) に関する詳細情報

### Agent Builderにて [#in-agent-builder]

エージェントを設定する際、異なるカテゴリのファイルを添付できます：

1. **画像アップロード**: エージェントが参照できる視覚的コンテンツ用
2. **File Search Upload**: RAG機能のためのドキュメント
3. **Code Interpreter Upload**: コード処理用のファイル
4. **File Context**: エージェントの指示を補足するために抽出されたテキストを含むドキュメント

**File Context**は`context`機能を使用し、["Upload as Text"](/docs/features/upload_as_text)と全く同じように動作します。デフォルトでテキスト解析を使用し、設定時にはOCRによって強化されます。テキストはアップロード時に抽出され、エージェントの指示（instructions）に保存されます。これは、ドキュメント、PDF、コードファイル、またはテキストを含む画像から、エージェントに永続的な知識を与えるのに最適です。

**処理の優先順位:** OCR > STT > テキスト解析 (「テキストとしてアップロード」と同じ)

**注:** 抽出されたテキストは、エージェントのシステム指示の一部として含まれます。

## 共有と権限 [#sharing-and-permissions]

エージェントはLibreChatのきめ細やかな[access control](/docs/features/access_control)システムを使用します。各エージェントは独自のアクセス制御リスト（ACL）を持ち、特定の**ユーザー**、**グループ**、**ロール**、または**公開**設定で共有でき、それぞれ選択した権限レベルを割り当てることが可能です。

信頼されたサービスは、ベータ版の [Agent Management API](/docs/features/agents_api#agent-management-api) を通じて、エージェント、添付ファイル、およびスキルを管理することもできます。管理者は各OIDCマシンクライアントを既存のLibreChatユーザーおよびテナントに紐付けます。すべてのリクエストは、個別の管理アクセス権を受け取るのではなく、そのユーザーの現在のロール機能とリソースACLを継承します。

### アクセスロール [#access-roles]

エージェントを共有する際、被共有者には以下の3つの役割のいずれかが割り当てられます。

| ロール | 被付与者ができること |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | 会話でエージェントを使用する。ビルダーを開いたり、指示、ツール、添付ファイルを確認することはできません |
| **Editor** | Viewerの権限 + エージェントの指示、モデル、ツール、ファイルの変更 |
| **Owner** | フルコントロール：エージェントの閲覧、編集、削除、再共有 |

元の作成者および管理者は、ACLに関係なく常に完全な制御権を保持します。

### エージェントの共有 [#sharing-an-agent]

1. Agent Builderでエージェントを開く
2. フッターにある **Share** ボタンをクリックします（あなたが作成者であるか、管理者であるか、またはその特定のAgentに対して `SHARE` 権限が付与されている場合に表示されます）。
3. ピープルピッカーでユーザー、グループ、またはロールを検索し、それぞれにロールを割り当てます
4. 必要に応じて **Public** を切り替えて、インスタンス上の全員がエージェントを閲覧できるようにします（`SHARE_PUBLIC` 機能の権限が必要です）。

エージェントカードおよびランディングビューには、設定されたサポート連絡先が表示されます。何も設定されていない場合、LibreChatは解決可能な最初のオーナーの表示名にフォールバックできますが、サポート連絡先として明示的に設定されていない限り、オーナーのメールアドレスは公開されません。

会話サーフェスは、Agentを可視のアイデンティティとして保持し、その基盤となるモデルやModel Specsのラベルにフォールバックすることはありません。

プリンシパル、権限ビット、およびACLがロールベースの機能権限とどのように構成されるかについての詳細は、[Access Control](/docs/features/access_control) を参照してください。

### Agent Marketplace [#agent-marketplace]

**Agent Marketplace**では、ユーザーが利用可能なエージェントを閲覧できます。サイドバーの**Agent Marketplace**から開くことができます。この項目は、Marketplaceの使用が許可されているロールを持つユーザーにのみ表示されます。

- **閲覧と検索**: エージェントはグリッド形式で表示されます。検索フィールドを使用して名前や説明からエージェントを探したり、カテゴリピル（**Top Picks**、**All**、または特定のカテゴリなど）を使用してリストを絞り込んだりできます。
- **並び替え**: **並び替え**を使用して、エージェントを**新しい順**（デフォルト）、**古い順**、**人気順**（ピン留め数）、または**作成者名順**で並び替えることができます。
- **My agents**: **My agents**をオンにすると、自分が作成したエージェントのみが表示されます。**Top Picks**からオンにすると、**All**に切り替わります。
- **共有可能なビュー**: 検索、並べ替え、および **My agents** フィルターはページURL (`?q=`, `?sort=`, `?mine=1`) に保持されるため、フィルター適用済みのビューをブックマークしたり共有したりできます。

エージェントカードを選択すると詳細ダイアログが開き、完全な説明とエージェントの連絡先、および以下の操作が表示されます：

- **ピン留め**または**ピン留め解除**: エージェントをピン留めされたエージェントに追加、またはそこから削除します。
- **リンクをコピー**: エージェントとの新しいチャットを開始するリンクをコピーします。
- **Start Chat**: エージェントとの新しい会話を開始します。
- **会話のきっかけを試す**: エージェントに [conversation starters](#conversation-starters) が設定されている場合、そのいずれかを選択すると、そのプロンプトがメッセージ入力欄に入力された状態で新しいチャットを開始できます。自動的には送信されないため、最初に編集することが可能です。

管理者は、[`interface.marketplace`](/docs/configuration/librechat_yaml/object_structure/interface#marketplace) 設定および [Access Control](/docs/features/access_control) で説明されているロール権限を使用してアクセスを制御できます。

### 管理者コントロール [#administrator-controls]

管理者は、エージェントビルダーUI内のグローバル権限設定にアクセスできます：

- すべてのユーザー間でのエージェント共有を有効/無効にする
- エージェントの使用権限を制御する
- エージェント作成権限の管理
- プラットフォーム全体の設定を構成する

スコープなしのシングルテナントデプロイメントでは、インスタンスで最初に作成されたアカウントが管理者となります。テナントスコープのデプロイメントでは、最初に登録されたユーザーが自動的に昇格されることはありません。信頼された管理フローを通じてテナント管理者をプロビジョニングしてください。手動で管理者を登録する必要がある場合は、[MongoDBにアクセス](/docs/configuration/mongodb/mongodb_auth)して、ユーザーのプロファイルを更新してください：

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

すべてのユーザーに対するエージェントの使用は、config経由で無効にすることも可能です。[詳細はこちら](/docs/configuration/librechat_yaml/object_structure/interface)。

機能レベルの権限（誰がエージェントを*使用*、*作成*、*共有*、または*公開共有*できるか）は、各ロール（カスタムロールを含む）に対して [**LibreChat Admin Panel**](/docs/features/admin_panel) から管理されます。`librechat.yaml` 内の [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) ブロックを使用して、起動時に組み込みの `USER` ロールのデフォルト値を設定することも可能ですが、今後の編集には Admin Panel を使用することが推奨されます。

### ユーザーレベルの共有 [#user-level-sharing]

個々のユーザーは以下が可能です：

- 特定のユーザー、グループ、またはロールとエージェントを共有する（そのロールに対して `SHARE` が有効になっている場合）
- インスタンス上の全員にエージェントを公開する（`SHARE_PUBLIC` が有効な場合）
- 各受信者に異なるアクセスレベル（Viewer / Editor / Owner）を付与します。
- 共有ダイアログからいつでもアクセスを再共有または取り消しできます

## ステアリングとキューイングされたメッセージ [#steering-and-queued-messages]

エージェントが応答している間、[composer](/docs/features/composer)から別のメッセージを送信するには、以下の2つの方法があります。

- **Steer**は、現在の実行における次のツールまたはエージェントのステップにメッセージを挿入するため、エージェントは作業を完了する前に調整を行うことができます。
- **Queue** はメッセージを保持し、現在の応答が完了した後に通常のフォローアップターンとして送信します。

現在のサーバー上の保存されたAgent会話において、通常のキューに入れられたフォローアップはMongoDBに保存されます。LibreChatはそれらのFIFO順序を保持し、ブラウザの切断、アプリの再起動、レプリカのハンドオフをまたいで、テキスト、添付ファイル、引用された抜粋、および手動で選択されたSkillsを引き継ぎます。処理は、次のターンを受け入れる前に、先行する応答が完了するのを待ちます。この永続性は自動的であり、YAMLや環境変数による切り替えはありません。古いサーバーやアクティブな生成エポックのない短い起動ウィンドウでは、クライアント側の互換性キューが保持されます。

サーバーへのリクエスト受付は、各会話キューレーン内でシリアル化（直列化）されます。先行するエビデンスや混在バージョンの所有権が曖昧な場合、LibreChatは**Awaiting reconciliation**（調整待ち）と表示し、推測で順序を誤って開始する代わりに、影響を受けるキュー内のターンをブロックまたは失敗させます。

**Steer sooner**は、次のツールステップを待つのではなく、次に安全なポイントでエージェントにメッセージを受け取らせるように要求します。まだ保持できる回答テキストやツールのアクティビティがない場合、LibreChatは短い猶予期間を待ち、沈黙または推論のみの試行を破棄し、メッセージを挿入して、その指示でモデルを再起動します。回答テキストを保持できるようになったら、LibreChatはプロバイダーにとって安全な境界で停止し、部分的な応答を保持してメッセージを挿入し、同じアシスタントの応答を再開します。実行中のツール呼び出しは、ステアリングによって破棄されたり中断されたりすることはありません。メッセージは、その作業が安全な境界に達したときに適用されます。

**Stop**を使用して、アクティブな推論を終了し、フォアグラウンドのツール呼び出しのキャンセルを要求します。Stopは、キャンセルを認識できるフォアグラウンドツールに対してキャンセル信号を転送します。切り離されたバックグラウンドの処理は、独立したライフサイクルを維持します。専用のコンポーザーコントロールを使用するか、送信ボタンのメニューから選択するか、または `Command/Ctrl + Shift + .` を押してください。デプロイメントがアクティブなプロバイダーストリームを中断できない場合、このアクションは通常のステアリングにフォールバックします。

**Settings → Chat** の **While generating, Enter will** では、デフォルトの動作を選択できます。送信ボタンのメニューから個別のメッセージに対してその選択を上書きすることができ、**Steer sooner on Enter** を有効にすると、Steer（ステアリング）がデフォルトの際に Enter キーを押すことで、より早い段階で安全なポイントをリクエストできるようになります。

ファイルおよび[引用された抜粋](/docs/features/message_actions#quote-excerpts)は、steer、queue、およびinterruptメッセージとともに送信されます。手動で選択されたSkillsは、実行中のsteerに添付されるのではなく、次の完全なターンに向けてステージングされたままになります。

保留中のステア（steer）は、ストリーミング返信の末尾に表示され、サーバーが実行に挿入するまでそこに留まります。その受信状況は、**Sending**（送信中）から **Delivered**（配信済み）へと進み、より早い安全なポイントが要求された場合は **Steer sooner requested**（早期ステア要求済み）となり、最終的にインラインメッセージの右下隅に二重チェックマークが表示される **Applied**（適用済み）となります。適用が確認されたレシートは、リロード後や共有・検索ビューでも表示されたままとなります。不確実な配信や失敗した配信には、確認のチェックマークは表示されません。一度承認されると、メッセージメニューからステアを再取得して編集したり、キューに入れられたフォローアップに変換したり、あるいはキャンセルしてテキストや添付ファイルをコンポーザーに戻したりすることができます。LibreChatは新しいドラフトを上書きしないように動作します。もしコンポーザーが利用できない場合は、再取得したメッセージを代わりにキュー内に保持します。失敗したステアは、再試行、編集、キューイング、または削除が可能です。

キューに入れられたフォローアップは、コンポーザーの上のリストに表示されます。それぞれを編集（**Edit message**）、削除（**Remove message**）、**Send now** で即座に送信、またはハンドルをドラッグするか矢印キーを押して並べ替えることができます。キューに入れられたフォローアップは、実行がアクティブな間にステア（steer）に変換したり、**Steer sooner** でエスカレーションしたりすることも可能です。進行中のステアも、ツール境界を待機している間は同様のエスカレーションが可能です。サーバー側でバックアップされたキュー内のメッセージを削除すると、まずその永続的なソースがキャンセルされ、可能な場合は空のコンポーザーに復元されます。先行する応答が中断または失敗した場合、LibreChat は影響を受けたキュー内のターンを、黙って送信するのではなく、確認のために失敗としてマークします。

1つの会話につき、最大100件のアクティブなキューイングされたターンを持つことができます。各キューイングされたターンは、最大16,000文字および10個のファイルを受け付けます。これとは別に、1つのアクティブな実行は最大10個の保留中のsteerを受け付けます。各steerには最大10個のファイルを含めることができ、[`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls)によって制限されます。**Steer sooner**は、キューイングされたターンを耐久性のあるFIFOレーンの先頭に移動させるのではなく、引き続きライブステアリングパスを使用します。

Redisでバックアップされたマルチレプリカ構成のデプロイメントは、生成プロトコルv2を自動的にネゴシエーションします。`v0.8.8-rc1`より前のリリースからアップグレードする場合は、[生成プロトコルの互換性ガイダンス](/docs/configuration/redis#generation-protocol-compatibility)に従ってください。

### 注記 [#notes]

- Instructions、model parameters、attached files、およびtoolsは、編集権限を持つユーザーにのみ公開されます。
  - エージェントは、指示やファイルなど、添付されたあらゆるデータを会話を通じて漏洩させる可能性があるため、Editor/Owner権限を付与したりエージェントを公開したりする前に、指示がそれに対して堅牢であることを確認してください。
- 共有エージェントを削除できるのは、元の作成者、管理者、および所有者（Owner）権限を持つ被付与者のみです。
- エージェントは共有されない限り、作成者のみが利用可能です

## エージェントイベント配信 [#agent-event-delivery]

LibreChatには、非同期のAgentイベントのためのソース中立的な配信レイヤーが含まれています。デプロイメント固有のアダプターは、検証済みのWebhook、キューメッセージ、MCPイベント、チャネルイベント、または内部製品イベントを、新しいAgentの実行（`fire`）、既存の保存済みAgentおよびブランチでの新しいターン（`continue`）、またはアクティブな実行の変更（`steer`）へと正規化できます。アダプターは、ネイティブソースの認証、ペイロードのサニタイズ、およびエンキュー前の信頼できるターゲットの選択に対して責任を負います。

ベータ版の [Agents API event endpoints](/docs/features/agents_api#agent-events) は、認証された `fire`、`continue`、および `steer` による Remote Agents API キーへのアクセスを公開します。外部システムは、ソースアクターを直接の子 Agent にバインドし、追加の機能トグルなしでイベントをまたいでそのアクターを継続させることができます。LibreChat は API キーからユーザー、テナント、およびソースの識別情報を導出し、Agent へのアクセスとコンテンツフィルターを強制し、べき等キー（idempotency key）を要求します。これは認証不要の汎用的な Webhook レシーバーではありません。プロバイダー固有のアダプターは、このエンドポイントを呼び出す前に、ネイティブの Webhook 署名を検証する必要があります。

実験的な [Scheduled Chats](/docs/features/scheduled_chats) 機能は、このレイヤーに対する LibreChat 初の組み込みプロデューサーです。これは、保存された Agent に対して定期的な `fire` デリバリーを作成するもので、管理者がオプトインするまで無効になっています。Detached Subagent は、子 Agent が終了した後に保存された親 Agent をウェイクアップさせるために、自動的に冪等な `continue` デリバリーを使用します。キャンセルされた子 Agent および一時的な親 Agent は除外されます。

MongoDBは、境界付きバージョン管理エンベロープ、冪等性キー、順序付けレーン、リース、リトライ履歴、永続的なレシート、およびデッドレターを保存します。ワーカーは、フェンシングされたクレームと境界付き指数バックオフを伴う「少なくとも1回（at-least-once）」の配信を使用します。成功したレシートは90日後に期限切れとなり、デッドレターには明示的で信頼された再キューイングが必要です。Fire配信は新しい会話を作成します。Continue配信は、正確な会話ブランチ上に新しいターンを作成し、そのブランチが実行中、一時停止中、または終了処理中の間は遅延させます。バインドされたアクターには自動メールボックスもあり、1つのアクターは現在のターンの処理結果を待ってから次のイベントをディスパッチしますが、異なるアクターは並行して実行可能です。Steer配信は、既存の会話と生成を特定し、厳密なアドミッションを使用しなければなりません。これにより、曖昧なリトライが同じ指示を二重に注入することを防ぎます。

バインドされた継続（bound continuations）の場合、転送の成功によって個別の永続的な処理ライフサイクルが開始されます。配信は `started` から `applied`、`completed_no_action`、`failed`、または `cancelled` へと進行します。ソースは `expectedAction` を使用して、特定のツールとオプションの引数サブセットを要求できます。LibreChat は、モデルが記述した文章からではなく、ホストが観測した一致するツールの証拠に基づいてのみ `applied` を報告します。互換性のある観測イベントは、ソースイベントごとに1つの冪等性レコードとレシートを保持しながら、バインドされた `coalesce.key` バッチを共有できます。チェックポイントの継続は、互換性がある場合に使用され、そうでない場合は永続的なメッセージ履歴にフォールバックします。

Bound Event Actorは、Ask User（ユーザーへの問い合わせ）やツールの承認のために一時停止し、LibreChatの通常のヒューマン・イン・ザ・ループ（人間による介入）インターフェースを通じて、署名された正確なアクター呼び出しを再開できます。アクターのメールボックスは、その一時停止が再開または解決されるまでブロックされたままとなり、後続のイベントが決定を追い越すことを防ぎます。これらのアクターには、永続的なMongoDBチェックポインターが必要です。LibreChatは、アクターの状態とリクエスト機能からチェックポイントの継続または永続的な履歴の再構築を自動的に選択します。既存のprotocol-v1の作業は、完了するまで履歴パス上に残ります。

Event Actorによって開始されたDetached Actionsは、組み込みの生成ストアがサポートを通知すると自動的に有効になります。Actorは、最終的なエビデンスが元の呼び出しを再開するまで中断されたままとなるため、バックグラウンド起動だけでは `expectedAction` を満たしません。インメモリ・ストアは、プロセスが生存している間、このライフサイクルの一貫性を維持します。Redisは、永続的な再起動リカバリとレプリカのハンドオフを追加します。Capabilityが所有する完了作業は、バージョン混在時のドレイン中に古いワーカーから分離されます。オペレーターが機能フラグでこの動作を選択することはありません。

実行ホストは通常、現在のプロセスのバインドされたリスナーを呼び出します。[`endpoints.agents.eventDriven.selfUrl`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven) は、この信頼された内部アドミッションパスが TLS フロントドアなどの別の HTTP オリジンを通過しなければならない場合にのみ設定してください。

## 移行が必要 (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="重要：エージェント権限の移行が必要です">
  v0.8.0-rc3以降、LibreChatはエージェントに対して新しいアクセス制御リスト（ACL）ベースの権限システムを使用しています。以前のバージョンからアップグレードする場合、既存のエージェントを引き続き利用できるようにするために、エージェント権限の移行を実行する必要があります。
</Callout>

### 移行の内容 [#what-the-migration-does]

エージェント権限の移行により、エージェントは単純な所有権モデルから、複数の権限レベルを備えた高度なACLベースのシステムへと移行します。

- **OWNER**: エージェントに対する完全な制御権
- **EDITOR**: エージェントの閲覧および変更が可能
- **VIEWER**: エージェントへの読み取り専用アクセス

この移行を実行しない場合、既存のAgentは新しい権限対応のAPI endpointからアクセスできなくなります。

### マイグレーションの実行 [#running-the-migration]

デプロイ方法に応じて適切なコマンドを選択してください：

#### 1. デフォルトの `docker-compose.yml` の場合 (`docker compose up` でアプリを起動している場合): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**変更のプレビュー (ドライラン):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**移行を実行:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**カスタムバッチサイズ（大規模データセット用）:**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. `deploy-compose.yml` の場合 [#2-for-the-deploy-composeyml]

[Ubuntu Docker Guide](/docs/remote/docker_linux) に従った場合：

**変更のプレビュー (ドライラン):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**移行を実行:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**カスタムバッチサイズ（大規模データセット用）:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. ローカル開発用（プロジェクトルートから）: [#3-for-local-development-from-project-root]

**変更のプレビュー (ドライラン):**

```bash
npm run migrate:agent-permissions:dry-run
```

**移行を実行:**

```bash
npm run migrate:agent-permissions
```

**カスタムバッチサイズ（大規模データセット用）:**

```bash

```

### 移行中に何が起こるか [#what-happens-during-migration]

- **Private Agents**: 作成者のみがアクセス可能（OWNER権限が付与されます）
- **共有エージェント**: エージェントが以前に共有されていた場合、パブリックエージェント（全ユーザーに共有）として適切なACLエントリが付与されます。
- **システム検出**: LibreChatは起動時に移行されていないエージェントを自動的に検出し、警告を表示します。

Agent Builder UI を介して、結果として得られるエージェントの権限を調整できます。

<Callout type="info" title="注記">
  プロンプトについても同様の移行プロセスが適用されます。既存のプロンプトがある場合は、同じコマンドを使用してプロンプト権限の移行を実行しますが、コマンド名に含まれる `agent` を `prompt` に置き換えてください。
</Callout>

さらに、今回のアップデートはLibreChatにとって新しいパラダイムをもたらします。その基盤となるアーキテクチャがアプリに待望の刷新を提供し、ユーザーエクスペリエンスとアプリ全体のパフォーマンスの両方を最適化するためです。

注目すべき最適化の1つとして、従来のendpoint（執筆時点でAgentsおよびAWS Bedrock以外のすべてのendpointオプション）を使用した場合、約1000トークンのAI生成で約1 MBのデータが転送されます。

エージェントを使用すると、同じ生成で転送されるデータは約52 kbとなり、データ転送量が95%削減されます。これは、サーバーおよびユーザーのデバイスにかかる負荷をそれだけ軽減することを意味します。
