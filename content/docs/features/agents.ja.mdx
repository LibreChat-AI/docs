エージェントとは、モデル、システムプロンプト、そして使用できるツールやファイルを保存した設定のことです。Agent Builder で一度作成すれば、チャットを開始するたびにそれを選択できます。エージェントは、OpenAI だけでなく、設定済みのあらゆるプロバイダーで動作します。

## エージェントを作成する [#create-an-agent]

<Steps>
  <Step>
    サイドパネルから**Agent Builder**を開き、**Create New Agent**をクリックします。
  </Step>
  <Step>
    名前、任意で説明を入力し、**Model**と**Category**を選択してください。ModelとCategoryは必須です。
  </Step>
  <Step>
    指示を書きます。インラインで直接入力するか、ソースを **Prompt** に切り替えて、プロンプトライブラリに保存されたプロンプトを使用することもできます（下記を参照）。
  </Step>
  <Step>
    **Tools** に（下記参照）ツールを追加し、**Create** をクリックします。
  </Step>
</Steps>

File Search や File Context 用のファイルのアップロードは、エージェントが作成された後にのみ可能です。

エージェントとチャットするには、モデルセレクターで選択するか、[エージェントマーケットプレイス](#agent-marketplace)から開くか、チャット入力欄に `@` と入力して一覧から選択します。ビルダーのエージェントセレクターでは、**My agents** を選ぶと、自分で作成したエージェントだけに絞り込まれます。

### 保存されたプロンプトからの指示 [#instructions-from-a-saved-prompt]

instructions ソースを **Prompt** に設定したら、**Select a prompt** からプロンプトを選び、**Version** を指定します。指定できるのは、プロンプトの所有者が本番用としてマークしたバージョンに追従する「production version」か、保存済みの特定バージョンの固定のいずれかです。これを行うには、プロンプトライブラリへのアクセス権が必要です。別のユーザーが、リンクされたプロンプトへのアクセス権を持たない状態でエージェントを開くと、ビルダーには **Restricted prompt** と表示され、そのユーザーはプロンプトを差し替えるか、インラインの instructions に戻すかを選べます。

指示文（インラインまたはリンク先のもの）では、`{{current_date}}`、`{{current_datetime}}`、`{{iso_datetime}}` を使用できます。これらは各ターンの開始時に一度だけ値が設定され、ツール呼び出し、サブエージェント、承認による一時停止をまたいでも同じ値のまま保たれます。最初の2つはお使いのタイムゾーンの時刻を使用し、`{{iso_datetime}}` は UTC です。

### モデルパラメータ [#model-parameters]

モデルパネルでは、そのプロバイダーの通常のチャットと同じパラメーター（temperature、最大出力トークン数など）に加え、ビジョン入力用の**Image Detail**を設定できます。ここで保存された値は、そのエージェントのすべての会話に適用されます。

### 会話のきっかけ [#conversation-starters]

**Conversation Starters** では、最大4つのプロンプトを追加できます。これらは、ユーザーがエージェントとの新しいチャットを開始した際に、空のチャット画面にボタンとして表示されます。ボタンをクリックすると、そのプロンプトが直ちに送信されます。エージェントのスターターは、使用中のモデルスペックで定義されたスターターを置き換えます。また、エージェントの Marketplace の詳細にも表示されます。

### バージョン履歴 [#version-history]

エージェントを変更するたびに保存されると、**バージョン履歴**にエントリが追加されます。このエントリには、各バージョンが保存された日時と、そのバージョンが持っていたツールや機能が表示されます。**復元**を実行すると、確認のあとに現在の設定がそのバージョンの内容に置き換えられます。この機能は、エージェントを編集できるユーザーにのみ表示されます。

## ツール [#tools]

ビルダーの **Tools** 見出しの横にある **Add** をクリックすると(1つも追加されていない場合は **No tools yet** と表示されています)、**Tool Library** が開きます。ライブラリでは検索するか、**Native**、**Tools**、**MCP servers**、**Actions** で絞り込むことができます。**Made by you** には、ご自身が作成した MCP サーバーと Actions が表示されます。**Favorites** では、スターを付けた項目をエージェントをまたいで手早く呼び出せます(最大100件)。**Create new…** メニューからは、ロールで許可されていれば、ダイアログを閉じることなく MCP サーバーや Action を追加できます。表示される内容は、管理者による有効化の設定とご自身のロールの権限によって異なります。API キーの設定が必要な項目には **Needs setup** と表示されます。

Run Code、File Search、File Context にはファイルが保持されます。これらにファイルが添付されている間は、削除するとファイルマネージャーが開き、それらのファイルが削除されるまでエージェントに残ります。

### Code Interpreter [#code-interpreter]

**Run Code** として表示されます。エージェントはサンドボックス内でコードを作成・実行します。これは計算、データ分析、グラフやスプレッドシートなどのファイル作成に適しています。ビルダーでこのツールに添付したファイルは、実行のたびにサンドボックス内で利用できます。会話内のコードファイルがサンドボックスに一つも復元できない場合、エージェントはモデルを呼び出す前に停止し、ファイルを再度添付するよう求めます。詳細は [Code Interpreter](/docs/features/code_interpreter) を参照してください。

#### ステートフルなコードセッション [#stateful-code-sessions]

管理者が有効にしている場合、Run Code 設定の **ステートフルなコードセッション** では、実行間でサンドボックスのワークスペースが保持されるため、ファイルやインストール済みパッケージが次回の実行にも引き継がれます。**ステートフル環境** では、そのワークスペースを誰と共有するかを設定します。すべてのステートフルなエージェントで共有する場合は **ユーザーワークスペース(推奨)**、エージェントごとに1つ用意する場合は **エージェント + ユーザーワークスペース**、チャットごとに1つ用意する場合は **会話ワークスペース** を選択します。新しいエージェントは、**設定 > データとプライバシー > コード実行** にある **デフォルトのステートフルワークスペース** から開始されます。管理者が複数のバックエンドを設定している場合は、**実行環境** でコードを実行するバックエンドを選択できます。その中には、お使いのマシン上でペアリングしたワーカーも含まれる場合があります。

ワークスペースはいつでもリセットされる可能性があるため、保存先として扱わないでください。管理された環境では、必要な出力を `/mnt/data` の下に保存してください。エージェントがファイルツールで書き込んだファイルは、各メッセージごとに **Workspace changes** に一覧表示され、そこからダウンロードできます。環境が添付されている場合、コンポーザーには、管理者が設定した範囲内で、そのチャットの承認モードとして **Ask before changes**、**Accept edits**、**Full access** が表示されます。

この機能は非常に実験的なものです。詳細については[ステートフルなコードセッション](/docs/features/code_interpreter#stateful-code-sessions)をご覧ください。

### Web Search [#web-search]

エージェントはウェブを検索し、情報の出典を引用します。管理者が設定した検索プロバイダー、または管理者がその設定を許可している場合はご自身のキーが必要です。詳しくは [Web Search](/docs/features/web_search) を参照してください。

### File Search [#file-search]

ファイルを添付すると、検索可能なナレッジベースに変換されます。エージェントは必要に応じて最も関連性の高い箇所を抽出するため、大量のドキュメントセットにも対応できます。CSV や Excel などの構造化データには不向きで、その場合は Run Code の方が適しています。[RAG API](/docs/features/rag_api) が必要です。

### ファイルコンテキスト [#file-context]

**ファイルコンテキスト**に追加されたファイルは、アップロード時に一度だけテキストが抽出され、そのテキストは毎回のメッセージでエージェントのコンテキストに含められます。エージェントが常に把握しておくべき重要なドキュメントを数点、このために使用してください。抽出の仕組みは[テキストとしてアップロード](/docs/features/upload_as_text)と同じで、デフォルトではプレーンテキストとして解析されます。[OCR](/docs/features/ocr)が設定されている場合は、スキャン画像や画像からのテキスト抽出の精度が向上します。

ファイルのテキストはすべてのメッセージに付随して送信されるため、ここで大きなファイルを扱うと、毎ターントークンを消費します。また、エージェントとチャットできる人は、そのテキストをエージェントから引き出すこともできます。

### Artifacts [#artifacts]

エージェントが、React、HTML、SVG、Markdown、Mermaid をコードブロックではなくサイドパネルでレンダリングできるようにします。**Mode** 設定で組み込みの指示を選択します。**Normal**、**shadcn/ui**(shadcn/ui コンポーネントライブラリ向けの指示を追加)、または **Custom** のいずれかです。**Custom** では何も挿入されないため、アーティファクトの構文は独自の指示で教える必要があります。その構文については [Artifacts](/docs/features/artifacts) を参照してください。

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

管理者が設定した、またはご自身で追加した MCP サーバーは、**MCP servers** の下に表示されます。サーバーを追加すると、そのサーバーのすべてのツールが紐付けられます。必要なツールのみを選択するには、**Tools in this server** の下でサーバーを展開してください。詳細は [MCP](/docs/features/mcp) を参照してください。

一部のサーバーは、リクエストの値に依存するため、チャット中にのみツールを一覧表示できます。そのようなサーバーの場合、ビルダーではツールごとのスイッチではなく、サーバーのすべてのツールをまとめて選択する項目が表示されます。エージェントで選択したMCPツールがすべて実行開始時に読み込めなかった場合、実行は中断され、ツールなしで続行するのではなく、サーバーへの再接続またはサインインを促すメッセージが表示されます。

各MCPツールには、ツールごとにいくつかのスイッチがある**Tool Options**メニューがあります。

- **Defer**: [Deferred tools](#deferred-tools)を参照してください。**Defer all tools**を使用すると、サーバー全体に対して適用されます。
- **プログラム的**: [プログラム的なツール呼び出し](#programmatic-tool-calling)を参照してください。
- **背景**: [背景のツール呼び出し](#background-tool-calls) を参照してください。
- **意図ラベル**: エージェントは各呼び出しについて一行の説明を記述し、それが汎用的なラベルの代わりに、呼び出しのステータスとしてリアルタイムに表示されます。リクエストごとに数トークンが追加されます。ネイティブツールには自動的に意図ラベルが付与されます。これはプログラムによるツールには適用されません。

**Background** と **Intent label** は、管理者が有効にした場合にのみ表示されます。

### 遅延ツール [#deferred-tools]

複数の MCP サーバーを持つエージェントには、簡単に数十個のツール定義が含まれることがあります。それらすべてを毎回のリクエストで送信すると、コンテキストを圧迫し、モデルが適切なツールを選ぶ精度も下がります。遅延ツール (deferred tool) は、初回のリクエストから除外されます。その代わりにエージェントはツール検索ツールを受け取り、必要になった時点で名前や説明から遅延ツールを探し出し、見つけたツールを以降の会話全体で使用できます。

### プログラムによるツール呼び出し [#programmatic-tool-calling]

**Programmatic** を有効にしたMCPツール（またはサーバー全体）では、モデルはそのツールを直接呼び出しません。代わりに Code Interpreter のサンドボックス内でコードを記述し、そのコードがツールを関数として呼び出します。これにより、回答する前にループ処理、ページネーション、リトライ、結果のフィルタリングを行うことができます。たとえば「これら40件のチケットを確認して、未対応のものを要約して」といった作業では、モデルを経由した40回の個別のツール呼び出しが必要になりますが、この方式ならそれを避けられます。

**Programmatic** のスイッチは、Run Code がオンになるまで無効のままで、Run Code をオフにするとクリアされます。サンドボックスが呼び出せるのは、エージェントに登録されたツールのみです。実行中はコードカードを展開すると、内部のツール呼び出しごとのライブトレースを確認できます。このトレースはページを再読み込みすると保持されません。この機能はデフォルトでオフになっており、有効にするには管理者による設定が必要です。

### バックグラウンドツール呼び出し [#background-tool-calls]

バックグラウンド実行に対応したツールは、すぐにタスク参照を返すため、エージェントはタスクの実行中も作業を続けられます。タスクが完了すると、結果は後続のターンで自動的に届けられ(折りたたみ可能なタスクカードとして表示されます)、またはエージェントがタスクツールを使って状況を確認することもできます。バックグラウンドの出力とファイルは、元のツール呼び出しに表示されます。バックグラウンドで実行できるツールは次のとおりです:

- **Run Code**: デフォルトでは、コードおよびシェルコマンドが実行対象になります。オプトアウトするには、その設定で **Background execution** をオフにしてください。
- **MCP tools**: ツールまたはサーバー全体を **Background** としてマークします。
- **その他のツールとアクション**: **バックグラウンド実行**をオンにします。OAuth を使用するアクションではこの機能は提供されません。

これらのスイッチによりバックグラウンド実行が可能になりますが、呼び出しごとの実行可否はモデルが判断します。バックグラウンドの処理は、それを開始したサーバープロセス内で実行され、そのプロセスが停止するとその処理は失われます。この機能を有効にするには、管理者による設定が必要です。

### Actions [#actions]

Actions は OpenAPI 仕様を、ツールに変換します。**Create new…** を選択してから **Actions** を選び、スキーマを貼り付けます。API に認証が必要な場合は **Authentication** を設定してください。仕様内の各オペレーションが、エージェントが呼び出せるツールになります。

OpenAI のモデルを使用している場合は、仕様内のオペレーションに `x-strict: true` を追加すると、LibreChat はそのオペレーションに対して厳格な関数呼び出し（strict function calling）をリクエストします。厳格モードでは JSON Schema のサブセットのみが受け付けられます。詳細は OpenAI の [structured outputs ガイド](https://platform.openai.com/docs/guides/structured-outputs) をご覧ください。

Actionsは、管理者が許可したドメインにのみアクセスできます。また、プライベートネットワークのアドレスは、明示的に許可されない限りブロックされます。

### Skills [#skills]

エージェントビルダーの **Skills** セクションでは、エージェントが使用できる [Skills](/docs/features/skills) を制御します。選択肢は **Off**(無効)、**All**(有効なすべてのスキル)、**Selected**(追加したスキルのみ)です。

### Memory [#memory]

**メモリ**を使うと、エージェントは、あなたが何かを覚えるよう、または忘れるよう依頼したときに、あなたについての記憶を保存、更新、削除できます。メモリを使うには、インスタンスでメモリが設定され、あなたのロールで許可されている必要があります。既定では、エージェントはあなたの個人的な記憶を他のチャットと共有します。エージェント専用の記憶を持たせ、そのエージェントだけが読み書きするようにするには、**このエージェントのメモリを分離する**をオンにしてください。詳しくは [Memory](/docs/features/memory) を参照してください。

### ユーザーへの質問とツール承認 [#ask-user-and-tool-approval]

**Ask User** は、エージェントが実行の途中で一時停止し、あなたに質問して回答を待つことを可能にします。1回の一時停止で最大4つの質問を表示でき、**Back** と **Next** で1問ずつ切り替えられます。各質問には自由記述で回答するか、エージェントが提示した選択肢のいずれかを選べます。**Skip** を選ぶと、すべての質問を辞退できます。回答を送信すると実行はすぐに再開され、再開の途中で停止した場合でも、回答は保持されます。

管理者は、特定のツールを実行する前に承認を必須にすることもできます。実行は一時停止し、メッセージ入力欄の上にあるパネルで呼び出し内容を確認します(承認、拒否、またはツールによっては引数の編集)。その後、実行が再開されます。管理者がエージェントごとの承認モードを有効にしている場合、エージェント上の各ツールには**ツール承認モード**が設定されます。選択肢は**継承されたポリシーを使用**、**常に確認**、**常に承認**、**チャットごとに一度確認**、**一度確認した後は常に承認**です。管理者のルールは引き続きその上に適用されます。また、**記憶した承認をリセット**を選ぶと、それまでに承認した内容がクリアされます。

### その他のツール [#other-tools]

**Tools**カテゴリには、管理者が有効にした組み込みの連携機能が含まれます。例としては、[画像生成](/docs/features/image_gen)、[Wolfram](/docs/configuration/tools/wolfram)、[Google Search](/docs/configuration/tools/google_search)、[Azure AI Search](/docs/configuration/tools/azure_ai_search)などがあります。それぞれ個別に設定する必要があります。詳しくは[Tools](/docs/configuration/tools)を参照してください。

## 他のエージェントとの連携 [#working-with-other-agents]

**サブエージェント**を使うと、エージェントは集中した subtask を、別のコンテキストウィンドウ内の新しいコピーの自分自身、または別のエージェントに引き渡すことができます。戻ってくるのは結果だけなので、長いツール出力がメインの会話に入り込むことはありません。詳しくは [サブエージェント](/docs/features/subagents) を参照してください。

### Handoffs [#handoffs]

**ハンドオフ**では、リストに追加した各エージェントに対してトランスファーツールがエージェントに与えられるため、話題に応じて専門のエージェントへ会話を引き継ぐことができます。ハンドオフごとに、説明(いつ引き継ぐか)とパススルー内容(エージェントが何を生成して引き渡すか)を追加でき、その内容を渡すパラメーター名を変更できます(デフォルトは `instructions`)。1つのエージェントに設定できるハンドオフは最大10件です。ハンドオフは常に利用可能で、管理者の設定に依存しません。

### エージェントチェーン [#agent-chain]

エージェントチェーンは非推奨になりました。既存のチェーンは引き続き実行され、ビルダーでは**詳細設定**の下に**チェーンを削除**ボタンとともに表示されますが、新しく作成することはできません。代わりにサブエージェントまたはハンドオフを使用してください。

## 最大エージェントステップ数 [#max-agent-steps]

**詳細設定**には、エージェントが最終回答を返すまでに実行できるステップ数の上限を定める**Max Agent Steps**フィールドがあります。1ステップはモデルへの1回のリクエスト、またはツール呼び出しの1ラウンドを指します。そのため、ツールを1回呼び出すと通常は3ステップ(リクエスト、ツールのラウンド、フォローアップのリクエスト)を消費します。

空欄のままにすると、サーバーのデフォルト値が使用されます。デフォルト値は管理者が変更していない限り50です。また、管理者はこのフィールドに入力できる値の上限を設定することもできます。

ターンのステップ数が上限に達すると、それまでにエージェントが行った作業はそのまま保持されます。メッセージには **Keep going**（新しい予算を持つ新しいターンを開始）と **Answer now**（ツールを追加で使わず、これまでの作業結果をもとにエージェントが回答）の選択肢が表示されます。長いツールチェーンでこれが頻繁に起こる場合は、上限値を引き上げてください。

## 長時間の実行の後に従う [#following-a-long-run]

ツールカードは、呼び出しの待機中（例：承認待ちなど）には**Preparing**を表示し、結果が返ってくるまでは**Calling**を表示します。シェルの出力はターミナル形式で表示され、最後の15行に折りたたまれます。**Show more**をクリックすると展開されます。コマンドが失敗した場合は、終了コード、シグナル、またはタイムアウトが表示されます。

### アクティビティグループ [#activity-groups]

もし管理者がこの機能を有効にしている場合、推論やツール呼び出しの各区間は、生成された一行の見出しの下にまとめて折りたたまれます。そのため、30回のツール呼び出しがあった実行も、数行の見出しとして表示されます。見出しを展開すると、その中の呼び出しが表示されます。第2レベルでは、複数のグループをまとめてフェーズとし、独自の要約を付けることができるため、長い実行もアウトラインとして把握できます。2つのグループが完了すると、要約が届くまでは最新の見出しが代表として表示された状態で、すぐに一緒に折りたたまれます。最終回答は常に折りたたみの外に表示され、フェーズ内で生成されたファイルは隠されず、そのフェーズの下に一列で表示されます。[Smooth Streaming](/docs/features/smooth_streaming)が有効な場合、デバイスがモーションの削減を要求していなければ、折りたたみはアニメーションで表示されます。

ライブ推論ラベルは関連するオプションです。汎用的な**Thinking**の見出しを表示する代わりに、推論ブロックにはモデルが取り組んでいる内容の短く更新される要約が表示されます。

ヘッダー、フェーズの要約、推論ラベルはそれぞれ追加のモデル呼び出しを必要とし、他の利用状況と同様に記録されます。管理者は[エージェントアクティビティグループ](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups)および[ライブ推論ラベル](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels)でこれらを設定します。

## ステアリングとキューに入れられたメッセージ [#steering-and-queued-messages]

エージェントが回答している間も、メッセージを送信できます。

- **Steer** は、次の安全なタイミングで現在の実行中に メッセージを挿入するため、エージェントは処理を終える前に調整できます。
- **Interrupt** は、進行中のツール呼び出しと推論をキャンセルし、完了済みの内容は保持したうえで、あなたのメッセージを使って処理を続行します。LibreChat の外で既に発生した影響は元に戻すことはできません。プロバイダーの組み込み検索を使用する実行などの一部の処理は中断できず、その場合はメッセージが steer として待機します。
- **Queue** は、メッセージを保持し、回答が完了した後に通常のターンとして送信します。

**生成中に Enter キーを押した場合** は、**設定 > チャット** で既定の動作を選択します。送信ボタンのメニューでは、メッセージごとにこの既定の動作を上書きできます。`Alt + Enter` で生成を中断します。キューに入ったメッセージは入力欄の上に一覧表示され、編集、削除、並べ替え、**すぐに送信**、または **今すぐ中断** を行えます。ファイルや引用された抜粋はメッセージと一緒に送信されます。`$` で選択したスキルは、次の完全なターンまで待機します。保存済みのエージェントチャットでキューに入ったメッセージはサーバーに保存されるため、ブラウザを閉じても残ります。

チャットには、それぞれ16,000文字と10ファイルまでのメッセージを最大100件キューに入れることができ、1回の実行には最大10件の保留中のステアリングを設定できます。受領表示や操作の詳細については、[Composer](/docs/features/composer)を参照してください。

## チャット内のファイル [#files-in-a-chat]

エージェントとチャットする際、添付メニューには以下のオプションが表示されます:

- **画像をアップロード**: ビジョン機能のためにモデルへ送信されます。
- **Upload as Text**: 全文がこの会話のみに送られます。詳細は [Upload as Text](/docs/features/upload_as_text) を参照してください。
- **ファイル検索用にアップロード**: エージェント自身のファイル検索用ファイルと同様に検索用にインデックス化されますが、このチャットに限定されます。
- **Upload to Code Environment**: Run Code 用にサンドボックスへコピーされます。CSV、Excel、JSON に最適です。

対応する機能が有効になっている場合にのみ、オプションが表示されます。

## 共有と権限 [#sharing-and-permissions]

Agents are private to their author until shared. Click **Share** in the builder footer to give users, groups, or roles access, each with one of three roles:

Agentsは、共有されるまでは作成者だけが利用できます。ビルダーのフッターにある**Share**をクリックすると、ユーザー、グループ、またはロールにアクセス権を付与できます。それぞれに次の3つのロールのいずれかを割り当てられます:

| 役割 | できること |
| ---- | ---------- |
| Viewer | エージェントとチャットできます。ビルダーで開いたり、その指示、ツール、ファイルを確認したりすることはできません。 |
| Editor | Viewer ができることに加えて、指示、モデル、ツール、ファイルを変更できます。 |
| Owner | Editor ができることに加えて、エージェントを削除したり、共有先を変更したりできます。 |

**Share with everyone** を選択すると、そのエージェントはインスタンス上のすべてのユーザーが利用できるようになります。この操作には公開共有の権限が必要です。作成者と管理者は常にエージェントを完全に管理できます。

閲覧者は、ビルダーにある指示やファイルを見ることはできません。しかし、会話の中で尋ねられれば、モデルはそれらを繰り返して伝えることができます。閲覧者に決して見せるべきではない内容を、エージェントに含めないでください。

別途、地球儀ボタン（**Remote Access**）では、[Agents API](/docs/features/agents_api) を通じてエージェントを呼び出せるユーザーを制御します。

エージェントカードには、ビルダーで設定されたサポート連絡先が表示されます。連絡先が設定されていない場合は、オーナーの名前が表示されることがありますが、連絡先として入力されていない限り、オーナーのメールアドレスが表示されることはありません。

[Access Control](/docs/features/access_control) で、ユーザー、グループ、ロールがどのように組み合わさるかを確認してください。

### 管理者向けコントロール [#administrator-controls]

ロールごとに、エージェントの利用、作成、共有、公開共有ができるかどうかを[管理パネル](/docs/features/admin_panel)で設定します。管理者は、エージェントビルダーの下部にある**Admin Settings**ボタンからも、同じスイッチをロールごとに設定できます。シングルテナントのインスタンスでは、最初に登録されたアカウントが管理者になります。管理者を追加する方法は、[別の管理者を昇格させる](/docs/configuration/access_control#promote-another-admin)を参照してください。

## エージェントマーケットプレイス [#agent-marketplace]

**Agent Marketplace**はサイドバーにあり、ご自身のロールで利用できるエージェントの一覧が表示されます。名前や説明で検索し、カテゴリ(**Top Picks**、**All**、または特定のカテゴリ)で絞り込み、**Sort by**で並び順を変更できます。並び順は**Newest first**(新しい順)、**Oldest first**(古い順)、**Popular**(人気順)、**By creator name**(作成者名順)から選択できます。**My agents**では、ご自身が作成したエージェントのみが表示されます。検索、並び替え、絞り込みの条件はURLに保持されるため、表示状態をブックマークしたり共有したりできます。

カードをクリックすると詳細と、以下のアクションが表示されます: **Pin**(ピン留め)または **Unpin**(ピン留め解除)、**Copy Link**(エージェントとの新しいチャットを開くリンク)、**Start Chat**(チャットを開始)。エージェントの会話スターターのいずれかをクリックすると、そのプロンプトがメッセージ入力欄に入った状態で新しいチャットが開きます。送信はされていないため、送信前に編集できます。

## Agents API [#agents-api]

エージェントは、OpenAI互換APIを通じてスクリプトや他のアプリケーションから呼び出すことも、信頼されたサービスによって管理することも、他のシステムからのイベントによってトリガーすることもできます。詳しくは[Agents API](/docs/features/agents_api)を参照してください。[スケジュールチャット](/docs/features/scheduled_chats)は、タイマーに基づいてエージェントの実行を開始します。[エージェントプラグイン](/docs/features/agent_plugins)を使うと、運用者はスキルやMCPサーバーを1つのパッケージとしてエージェントに提供できます。

## セットアップ [#setup]

エージェントはデフォルトで有効になっています。管理者は、[エージェントエンドポイント設定](/docs/configuration/librechat_yaml/object_structure/agents)で、提供する機能、ステップ上限、許可するプロバイダーを選択できます。また、[Actions設定](/docs/configuration/librechat_yaml/object_structure/actions)では、Actionsがアクセスできるドメインを指定できます。v0.8.0-rc3より前のバージョンからアップグレードしたインスタンスでは、[権限の移行](/docs/configuration/access_control#migrating-from-pre-acl-versions)が必要です。
