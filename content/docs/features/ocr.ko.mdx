OCR을 사용하면 LibreChat은 픽셀로만 존재하는 텍스트를 읽을 수 있습니다. 예를 들어 영수증 사진, 스캔한 계약서, 스크린샷으로 만든 PDF 등이 여기에 해당합니다. 관리자가 OCR 서비스를 설정해 두었다면, 텍스트로 추가된 파일은 먼저 OCR을 거치므로 모델은 빈 결과 대신 실제 텍스트를 받게 됩니다.

## OCR이 적용되는 위치 [#where-ocr-applies]

OCR은 파일의 텍스트가 모델의 컨텍스트에 포함되는 파일을 대상으로 실행됩니다:

- **Upload as Text** 채팅에서, 명시적 업로드 메뉴를 표시하는 배포 환경에서 사용할 수 있습니다. [Upload as Text](/docs/features/upload_as_text)를 참고하세요.
- **File Context**는 에이전트 빌더에서 추출된 텍스트가 모든 메시지마다 에이전트의 컨텍스트에 포함되는 방식입니다.

기본적으로 처리하는 파일 형식은 이미지(JPEG, PNG, GIF, WebP, HEIC, HEIF), PDF, Word, PowerPoint, Excel, EPUB, 그리고 OpenDocument 파일입니다. 그 외의 파일은 OCR을 건너뛰고 일반 텍스트 추출을 사용합니다.

기본 **From Local Computer** 항목을 사용할 때 어떤 일이 일어나는지는 파일이 어디로 라우팅되는지에 따라 달라집니다. 제공업체가 지원하는 이미지와 PDF는 OCR을 거치지 않고 모델에 직접 전송됩니다. 대신 텍스트로 라우팅되는 파일(예: Word 문서 또는 관리자가 텍스트로 라우팅하도록 설정한 PDF)은 **Upload as Text**와 같은 방식으로 텍스트가 추출되며, OCR이 해당 파일 유형을 처리하는 경우 OCR을 거칩니다.

## OCR 없이 [#without-ocr]

OCR 서비스가 없어도 텍스트 추출은 계속 작동합니다. LibreChat의 내장 파서는 텍스트 레이어가 실제로 포함된 최대 15 MB의 PDF, DOCX, XLS, XLSX, ODT, ODS 파일을 읽으며, 이는 편집기에서 내보낸 대부분의 문서에 해당합니다. 레거시 `.doc`, PowerPoint, EPUB 파일은 OCR이 필요합니다. 또한 파서는 이미지를 읽을 수 없습니다. 스캔한 PDF나 페이지 사진은 문서가 이미지 기반일 수 있으며 OCR 서비스가 필요하다는 메시지와 함께 실패합니다.

OCR이 설정되어 있지만 문서에서 서비스 오류가 발생하면, LibreChat은 해당 파일에 대해 내장 파서로 대체합니다.

## OCR 서비스 [#ocr-services]

관리자는 하나의 전략을 선택합니다:

- Mistral의 API를 통한 Mistral OCR입니다. 이것이 기본 전략입니다.
- Azure AI Foundry에 배포된 Mistral OCR.
- Mistral OCR는 Google Cloud Vertex AI에 배포됩니다.
- 로컬 문서 파서만 사용하며 외부 서비스는 사용하지 않습니다. 텍스트 레이어는 읽지만 이미지는 읽지 않습니다.

Mistral 옵션 중 어느 것을 사용하든, 파일 내용은 처리를 위해 해당 서비스로 전송되므로 해당 서비스의 데이터 처리 약관이 적용됩니다.

## 대신 제공자에 업로드 [#upload-to-provider-instead]

많은 모델은 이미지와 PDF를 직접 읽을 수 있습니다. 파일을 첨부 파일로 제공자에게 보내면, 제공자가 파일을 파싱하여 텍스트 추출로는 손실되는 레이아웃과 이미지를 유지합니다. 제공자가 이를 지원하는 경우 기본 업로더는 이미지와 PDF에 대해 이 작업을 자동으로 수행합니다. 이전 업로드 메뉴를 사용하는 경우에는 [컴포저](/docs/features/composer#add-files)에서 **Upload to Provider**를 선택하십시오.

이 방식으로 파일을 받을 수 있는 제공업체: OpenAI, Anthropic, Google 및 Vertex AI, AWS Bedrock, Mistral, DeepSeek, Moonshot, OpenRouter, xAI, 그리고 사용자 지정 엔드포인트. Azure OpenAI는 대화 매개변수에서 Responses API를 켠 경우에만 이 방식으로 PDF를 받을 수 있으며, Chat Completions를 사용하면 이미지만 받을 수 있습니다.

각 제공자(provider)가 허용하는 값은 서로 다릅니다:

- 모두 이미지와 PDF를 지원합니다.
- Google, Vertex AI, 그리고 OpenRouter도 오디오와 비디오를 입력으로 받습니다.
- AWS Bedrock도 CSV, DOC, DOCX, XLS, XLSX, HTML, TXT, Markdown 형식을 지원하며, 문서당 최대 4.5 MB까지 업로드할 수 있습니다. Claude 4 이상용 PDF와 Nova용 PDF 및 DOCX는 관리자가 더 낮은 파일 크기 제한을 설정하지 않은 경우 최대 32 MB까지 업로드할 수 있습니다. 자세한 내용은 [AWS Bedrock](/docs/configuration/pre_configured_ai/bedrock)을 참조하세요.

## 설정 [#setup]

OCR은 관리자가 `librechat.yaml`에 `ocr` 섹션을 추가하기 전까지 꺼져 있습니다. 전략, 키, 엔드포인트에 대한 설명은 [OCR 구성 참조](/docs/configuration/librechat_yaml/object_structure/ocr)에서 확인할 수 있습니다. OCR로 전송되는 파일 형식은 [`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr)의 `fileConfig.ocr.supportedMimeTypes`로 설정합니다. 에이전트에는 `ocr` 기능도 필요하며, 이 기능은 기본적으로 켜져 있습니다.
