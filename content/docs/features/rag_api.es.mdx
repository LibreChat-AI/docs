La **API de RAG (Retrieval-Augmented Generation)** es un servicio independiente que indexa los archivos que subes a LibreChat y devuelve los fragmentos más relevantes para una pregunta, de modo que el modelo pueda responder a partir de tus documentos y no únicamente de sus datos de entrenamiento.

Es una aplicación de FastAPI en Python construida sobre LangChain, que almacena los embeddings en PostgreSQL con la extensión pgvector.

**Para configurarlo, consulta [Configuración de RAG API](/docs/configuration/rag_api).**

En LibreChat, RAG potencia la capacidad de **Búsqueda de archivos** ([Agentes](/docs/features/agents#file-search)) de los agentes (`file_search`). Los archivos adjuntos a la Búsqueda de archivos de un agente, o a una ejecución que selecciona la Búsqueda de archivos, son indexados por la API de RAG y recuperados bajo demanda. Otros endpoints de chat no utilizan la indexación ni la recuperación de RAG, aunque sí pueden usar la API de RAG para extraer texto, como se describe a continuación.

La API de RAG también expone una ruta `/text` que LibreChat puede usar para extraer texto de los archivos subidos; consulta [Subir como texto](/docs/features/upload_as_text#what-happens-under-the-hood) para saber cuándo se aplica.

## Cómo funciona [#how-it-works]

1. **Indexación.** Cuando un archivo necesita poder buscarse (al subirlo a la Búsqueda de archivos de un agente, o cuando una ejecución de chat usa por primera vez la Búsqueda de archivos sobre un adjunto), LibreChat lo envía a la API de RAG, que divide el texto en fragmentos superpuestos (`CHUNK_SIZE` y `CHUNK_OVERLAP`), convierte cada fragmento en un embedding con el proveedor configurado y almacena los vectores en pgvector.
2. **Recuperación.** Cuando el modelo invoca File Search, escribe una consulta de búsqueda. LibreChat pide a la RAG API los 5 fragmentos más cercanos de cada archivo adjunto y luego conserva los 10 más cercanos en total.
3. **Respuesta.** Esos fragmentos se devuelven al modelo junto con su nombre de archivo y una puntuación de relevancia, y el modelo responde a partir de ellos. Cuando las [citas de archivos](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) están habilitadas, la respuesta puede citar los archivos que utilizó.

Eliminar un archivo en LibreChat también elimina sus vectores de la API de RAG.

La recuperación solo encuentra pasajes semánticamente cercanos a la consulta, por lo que funciona mejor para buscar datos específicos en documentos extensos. Para preguntas que requieren un documento completo, como resumirlo, [Cargar como texto](/docs/features/upload_as_text) suele dar mejores resultados.

## ¿Qué es RAG? [#what-is-rag]

La Generación Aumentada por Recuperación (RAG, por sus siglas en inglés) fundamenta un modelo de lenguaje en una fuente de conocimiento externa. En lugar de depender únicamente de lo que el modelo aprendió durante el entrenamiento, la aplicación primero recupera fragmentos relevantes de esa fuente y los añade al prompt; después, el modelo genera su respuesta a partir de ellos. Como el conocimiento reside fuera del modelo, puedes añadir o actualizar documentos sin necesidad de reentrenar nada.
