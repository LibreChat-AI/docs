Die **RAG-API** (Retrieval-Augmented Generation) ist ein eigenständiger Dienst, der die Dateien indiziert, die Sie in LibreChat hochladen, und die für eine Frage relevantesten Passagen zurückgibt. So kann das Modell seine Antworten auf Ihre Dokumente stützen und nicht allein auf seine Trainingsdaten.

Es ist eine Python-FastAPI-App, die auf LangChain aufbaut und Embeddings in PostgreSQL mit der Erweiterung pgvector speichert.

**Um dies einzurichten, siehe [RAG API-Konfiguration](/docs/configuration/rag_api).**

In LibreChat wird RAG für die **Dateisuche** (`file_search`) der [Agenten](/docs/features/agents#file-search) eingesetzt. Dateien, die an die Dateisuche eines Agenten oder an einen Lauf angehängt sind, der die Dateisuche auswählt, werden von der RAG-API indexiert und bei Bedarf abgerufen. Andere Chat-Endpunkte nutzen weder RAG-Indexierung noch -Abruf, können die RAG-API jedoch weiterhin zur Textextraktion verwenden, wie unten beschrieben.

Die RAG-API stellt außerdem eine `/text`-Route bereit, die LibreChat nutzen kann, um Text aus Uploads zu extrahieren; siehe [Upload as Text](/docs/features/upload_as_text#what-happens-under-the-hood) für die Fälle, in denen sie zum Einsatz kommt.

## So funktioniert es [#how-it-works]

1. **Indexierung.** Wenn eine Datei durchsuchbar sein muss (beim Hochladen in die File Search eines Agenten oder wenn ein Chat-Durchlauf die File Search zum ersten Mal für einen Anhang verwendet), sendet LibreChat sie an die RAG API. Diese teilt den Text in sich überlappende Chunks (`CHUNK_SIZE` und `CHUNK_OVERLAP`), wandelt jeden Chunk mit dem konfigurierten Anbieter in ein Embedding um und speichert die Vektoren in pgvector.
2. **Retrieval.** Wenn das Modell die Dateisuche aufruft, schreibt es eine Suchanfrage. LibreChat fragt die RAG-API nach den 5 nächstgelegenen Abschnitten in jeder angehängten Datei an und behält anschließend insgesamt die 10 nächstgelegenen.
3. **Beantworten.** Diese Abschnitte werden mit ihrem Dateinamen und einem Relevanzwert an das Modell zurückgegeben, und das Modell beantwortet die Frage anhand dieser Abschnitte. Wenn [Dateizitate](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) aktiviert sind, kann die Antwort die verwendeten Dateien zitieren.

Das Löschen einer Datei in LibreChat entfernt auch deren Vektoren aus der RAG API.

Retrieval findet nur Passagen, die dem Suchbegriff semantisch nahe sind. Daher funktioniert es am besten, um gezielt Fakten in großen Dokumenten nachzuschlagen. Für Fragen, die ein ganzes Dokument auf einmal erfordern, etwa eine Zusammenfassung, liefert [Als Text hochladen](/docs/features/upload_as_text) in der Regel bessere Ergebnisse.

## Was ist RAG? [#what-is-rag]

Retrieval-Augmented Generation (RAG) stützt ein Sprachmodell auf eine externe Wissensquelle. Anstatt sich nur auf das zu verlassen, was das Modell während des Trainings gelernt hat, ruft die Anwendung zunächst relevante Textausschnitte aus dieser Quelle ab und fügt sie dem Prompt hinzu. Anschließend generiert das Modell seine Antwort auf Grundlage dieser Ausschnitte. Da das Wissen außerhalb des Modells liegt, können Sie Dokumente hinzufügen oder aktualisieren, ohne irgendetwas neu trainieren zu müssen.
