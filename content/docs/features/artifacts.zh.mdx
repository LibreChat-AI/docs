Artifacts 让 LibreChat Agents 能够在专用的交互式视图中渲染生成的 React 组件、HTML、SVG、Markdown 和 Mermaid 内容。用户可以继续对话以修改结果，同时将生成的内容与聊天回复分离开来。

## 为 Agent 启用 Artifacts [#enable-artifacts-for-an-agent]

1. 创建或编辑一个 [Agent](/docs/features/agents)。
2. 打开 **Add tools** 并选择 **Artifacts**。
3. 选择一种 Artifact 指令模式。
4. 保存该智能体。

可用的模式有：

- **Normal**: 注入 LibreChat 针对 React、HTML、SVG、Markdown 和 Mermaid 工件的标准指令。
- **shadcn/ui**：添加了 shadcn/ui 组件库指南，以获得更精致的生成界面。
- **Custom**：保持 Artifact 渲染功能开启，但不注入任何内置指令。请将你想要的完整 Artifact 行为写入 Agent 的指令中。

优先推荐使用 Agent 级别的配置，因为每个 Agent 都可以使用适合其用途的模式和指令。管理员可以通过移除 `artifacts` [Agent 能力](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)来隐藏 Artifacts。

## Artifacts 支持的内容 [#what-artifacts-support]

- 交互式 React 组件和 HTML 页面
- SVG 图像和 Mermaid 图表
- 渲染的 Markdown 文档
- 通过后续消息进行迭代更新
- 任何可供已配置的 agent 使用的模型

## 预览与导出 [#preview-and-export]

在渲染的 artifact 预览中使用全屏控件将其扩展至整个浏览器显示区域。该控件遵循浏览器 Fullscreen API 状态，可通过 Escape 键或浏览器控件正常退出，并在全屏不可用时隐藏。

在桌面端，选择 Artifact 面板标题栏中的 **Open in new window**，即可将面板移动到独立的浏览器窗口中，例如将其放置在第二个屏幕上。当响应流式传输时，Artifact 会持续更新，且未保存的代码编辑内容和选定的标签页也会同步保留。若要将面板返回至聊天界面，请选择 **Dock back to panel** 或关闭该窗口。LibreChat 会记住窗口的大小和位置，以便下次使用。

- 保持聊天标签页打开：该窗口由聊天标签页控制，关闭该标签页也会关闭窗口。
- 如果浏览器拦截了窗口，LibreChat 会显示一条通知。请允许该网站的弹出窗口并重试。
- 该按钮不会在窄屏（移动端）布局中显示。

管理员可以通过设置 [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking) 来移除该按钮并将 Artifacts 保留在侧边栏中。

Mermaid 图表以紧凑的内联卡片形式显示，并可在 artifact 面板中打开。您可以从内联卡片或面板中将图表导出为 SVG 或 PNG 格式。Mermaid 预览会直接渲染，而无需加载 Sandpack 打包器；PNG 导出应用了受限的画布尺寸，以保护浏览器免受过大图表的影响。

由模型生成的工件将以其标题或 Markdown 标题命名进行下载，并带有与导出内容相匹配的扩展名。未编辑的基于文件的工件在可用时会下载完整的原始文件，并保留其原始文件名和格式。下载已编辑或缓存的预览内容时会使用 `.preview` 限定符，以防与原始文件混淆。

## Content-Security-Policy

您可能需要更新 Web 服务器的 Content-Security-Policy，以包含 `frame-src 'self' https://*.codesandbox.io`，从而在 Artifacts 面板中加载生成的 HTML 应用。这是 [sandpack](https://sandpack.codesandbox.io/) 库的依赖项。

## 自托管 Sandpack Bundler [#self-hosting-the-sandpack-bundler]

LibreChat 中的 Artifacts 使用 CodeSandbox 的 Sandpack 库来安全地渲染 HTML/JS 代码。默认情况下，LibreChat 会连接到 CodeSandbox 的公共 CDN，该 CDN 可能会传输其使用情况的遥测数据。

为了增强隐私性、满足安全合规要求或在隔离的网络环境中使用，您可以[自托管 bundler。](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)

### 为什么要自托管 Sandpack Bundler？ [#why-self-host-the-sandpack-bundler]

[Self-hosting the bundler](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler) 提供了几个优势：

- **隐私与安全**：将代码执行保持在您自己的基础设施内
- **可靠性**：移除对外部服务的依赖
- **性能**：通过在您的网络中托管打包程序来降低延迟
- **合规性**：满足组织的数据处理要求
- **Control**: 配置并根据您的特定需求进行自定义

### 配置 [#configuration]

一旦你设置好了自托管的 bundler，只需通过设置以下环境变量来配置 LibreChat 以使用它：

```bash
# `.env` file
SANDPACK_BUNDLER_URL=http://your-bundler-url
```

### 通用注意事项 [#general-considerations]

自托管 bundler 会带来一些额外的开销：

- **CORS Configuration**: 您需要管理跨源资源共享策略
- **安全管理**：您需负责 bundler 服务的安全性
- **维护**：更新和补丁需要手动应用
- **资源需求**：托管打包程序（bundler）将需要额外的服务器资源

有关设置和维护自托管 bundler 的详细说明，请参阅专为 LibreChat 部署定制的 [forked CodeSandbox repository](https://github.com/LibreChat-AI/codesandbox-client)，其中包括从 Sandpack 中移除遥测功能的相关内容。
