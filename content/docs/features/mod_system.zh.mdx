LibreChat 会监测滥用行为，例如对登录表单进行高频暴力尝试、发送消息的速度超过允许的频率，或通过脚本调用 API，并将每一次行为记录为该用户的一次违规。当用户的违规分数超过阈值时，该账户及其 IP 将被封禁一段时间。该机制旨在阻止一个或少数恶意使用者，而非应对大量流量洪峰；对于公开部署的实例，请在其前面部署反向代理或 DDoS 防护服务（例如 Cloudflare）。

## 什么算作违规行为 [#what-counts-as-a-violation]

大多数违规行为源于速率限制。当请求超出限制时,系统会以"请求过多"类错误予以拒绝,并且该次尝试会计入用户的违规分数。限制范围包括:

- 按 IP 地址限制登录和注册。登录失败次数过多时,会显示"短时间内登录尝试次数过多。"
- 消息:单个用户可同时运行的响应数量("同一时间只能运行一条消息"),以及每分钟可发送的消息数量,可按 IP 限制,也可选择按用户限制。
- 密码重置和邮箱验证请求，以及随后提交的链接。
- 两步验证码尝试与通行密钥注册。
- 对话导入(每个 IP 每 15 分钟 100 次,每个用户每 15 分钟 50 次)、分支(每个 IP 每分钟 30 次,每个用户每分钟 7 次)以及共享链接查看,均同时按每个 IP 和每个用户进行限制。
- 文件上传、文本转语音、语音转文本和工具调用。

以下情况即使未涉及任何速率限制，也属于违规行为：非浏览器发出的请求、针对端点并未提供的模型发出的请求（几乎都是脚本在探测服务器），以及尝试打开并非由该用户拥有的对话。

每种违规类型都有各自的分数。默认情况下,非浏览器请求的计分权重较高。示例 `.env` 中部分类型的分数设为 0,因此超出限制时会被拦截,但不会使用户朝封禁方向累积。

## 封禁 [#bans]

每当用户的总分达到封禁间隔(默认为 20)的又一个倍数时,就会触发一次封禁。该用户的会话会立即被终止,其账户以及发起请求的 IP 地址都会被锁定,锁定时长为封禁时长(默认为 2 小时)。被封禁的用户会看到提示"您的账户因违反服务条款而被暂时封禁。"封禁会自动到期。分数也会衰减:默认情况下,如果用户在一小时内没有新的违规行为,其分数将被重置;每次新的违规行为都会重新开始计算这一小时。

要提前解除封禁,管理员需要从 MongoDB 的 `logs` 集合中删除该封禁的记录。违规分数以及每个用户的违规历史记录保存在 LibreChat 目录下的 `data/violations.json` 和 `data/logs.json` 中(启用 Redis 后,分数会改存到 Redis 中,从而确保所有副本看到的分数一致;无论如何,封禁记录都保存在 MongoDB 中)。如果想了解某个用户被封禁的原因,应当查看这些文件。

## 消息审核 [#message-moderation]

除评分系统之外,管理员可以在聊天消息发送给模型之前,通过 OpenAI 审核 API 对其进行审核。此功能适用于常规聊天和智能体,不适用于托管的 Assistants 端点。被标记的消息不会被发送,用户将看到"此消息已被审核系统标记。"

## 设置 [#setup]

默认情况下，速率限制和封禁功能处于启用状态，并使用上述默认值。管理员可以通过环境变量调整所有限制、评分和封禁设置，并以同样的方式开启 OpenAI 审核功能；详见[自动审核配置](/docs/configuration/mod_system)。上传、语音和对话导入的限制也可以在 `librechat.yaml` 的 [`rateLimits`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits) 模块中设置。
