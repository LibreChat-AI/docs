L'OCR permet à LibreChat de lire le texte qui n'existe que sous forme de pixels : une photo de reçu, un contrat numérisé, un PDF composé de captures d'écran. Lorsque votre administrateur a configuré un service OCR, les fichiers ajoutés en tant que texte passent d'abord par celui-ci, afin que le modèle reçoive les mots au lieu d'un résultat vide.

## Où l'OCR s'applique [#where-ocr-applies]

La reconnaissance optique de caractères (OCR) s'exécute sur les fichiers dont le texte est ensuite intégré au contexte du modèle :

- **Importer comme texte** dans le chat, sur les déploiements qui affichent le menu d'importation explicite. Voir [Importer comme texte](/docs/features/upload_as_text).
- **Contexte du fichier** dans le Créateur d'agents, où le texte extrait est inclus dans le contexte de l'agent à chaque message.

Les types de fichiers qu'il prend en charge par défaut sont les images (JPEG, PNG, GIF, WebP, HEIC, HEIF), les PDF, Word, PowerPoint, Excel, EPUB et les fichiers OpenDocument. Les autres fichiers ignorent l'OCR et utilisent l'extraction de texte standard.

Avec l'entrée par défaut **From Local Computer**, le résultat dépend de l'endroit où le fichier est acheminé. Les images et les PDF acceptés par le fournisseur sont envoyés directement au modèle et ne passent pas par l'OCR. Un fichier acheminé vers le texte (un document Word, par exemple, ou un PDF que votre administrateur achemine vers le texte) est extrait de la même manière que pour Upload as Text ; il passe donc par l'OCR lorsque l'OCR prend en charge son type.

## Sans OCR [#without-ocr]

L'extraction de texte fonctionne toujours sans service OCR. L'analyseur intégré de LibreChat lit les fichiers PDF, DOCX, XLS et XLSX, ODT et ODS de 15 Mo maximum qui possèdent une véritable couche de texte, ce qui couvre la plupart des documents exportés depuis un éditeur. Les fichiers `.doc` au format ancien, PowerPoint et EPUB nécessitent un OCR. De même, l'analyseur ne peut pas lire une image : un PDF numérisé ou une photo de page échoue avec un message indiquant que le document est peut-être basé sur une image et qu'il nécessite un service OCR.

Si l'OCR est configuré mais que le service renvoie une erreur sur un document, LibreChat bascule sur l'analyseur intégré pour ce fichier.

## Services OCR [#ocr-services]

Les administrateurs choisissent une stratégie parmi les suivantes :

- Mistral OCR via l'API de Mistral. C'est la stratégie par défaut.
- Mistral OCR déployé sur Azure AI Foundry.
- Mistral OCR déployé sur Google Cloud Vertex AI.
- Le parseur de documents local uniquement, sans service externe. Il lit les couches de texte mais pas les images.

Avec l'une des options Mistral, le contenu des fichiers est envoyé à ce service pour traitement ; ses conditions de traitement des données s'appliquent donc.

## Télécharger plutôt vers le fournisseur [#upload-to-provider-instead]

De nombreux modèles peuvent lire eux-mêmes les images et les PDF. Envoyé au fournisseur sous forme de pièce jointe, le fichier est analysé par le fournisseur, qui conserve la mise en page et les images que l'extraction de texte perd. L'outil d'envoi par défaut le fait automatiquement pour les images et les PDF lorsque le fournisseur les prend en charge ; avec l'ancien menu d'envoi, choisissez **Upload to Provider** dans le [compositeur](/docs/features/composer#add-files).

Fournisseurs qui acceptent les fichiers de cette manière : OpenAI, Anthropic, Google et Vertex AI, AWS Bedrock, Mistral, DeepSeek, Moonshot, OpenRouter, xAI et les endpoints personnalisés. Azure OpenAI n'accepte les PDF de cette manière que lorsque l'API Responses est activée dans les paramètres de la conversation ; avec Chat Completions, seules les images sont acceptées.

Ce qu'accepte chaque fournisseur diffère :

- Tous prennent en charge les images et les PDF.
- Google, Vertex AI et OpenRouter prennent également en charge l'audio et la vidéo.
- AWS Bedrock accepte également les formats CSV, DOC, DOCX, XLS, XLSX, HTML, TXT et Markdown, jusqu'à 4,5 Mo par document. Les PDF pour Claude 4 et versions ultérieures, ainsi que les PDF et DOCX pour Nova, peuvent atteindre 32 Mo, sauf si votre administrateur a défini une limite de taille de fichier inférieure. Voir [AWS Bedrock](/docs/configuration/pre_configured_ai/bedrock).

## Configuration [#setup]

L'OCR est désactivé tant qu'un administrateur n'ajoute pas une section `ocr` à `librechat.yaml` ; les stratégies, les clés et les endpoints sont décrits dans la [référence de configuration OCR](/docs/configuration/librechat_yaml/object_structure/ocr). Les types de fichiers envoyés à l'OCR sont définis avec `fileConfig.ocr.supportedMimeTypes` dans [`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr). Les agents nécessitent également la capacité `ocr`, qui est activée par défaut.
