Il Code Interpreter esegue il codice in una sandbox isolata. Gli agenti lo utilizzano per svolgere calcoli matematici che altrimenti dovrebbero stimare, analizzare un foglio di calcolo caricato, convertire file oppure produrre grafici e documenti. Puoi anche eseguire tu stesso un blocco di codice da un messaggio di chat tramite **Run Code**.

La sandbox è un servizio separato, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (open source, Apache 2.0), che il tuo amministratore distribuisce accanto a LibreChat. Supporta Python, Node.js (JavaScript e TypeScript), Go, C e C++, Java, PHP, Rust e Fortran.

## Concedi a un agente l'esecuzione di codice [#give-an-agent-code-execution]

Nell'Agent Builder, seleziona **Add** accanto a **Tools** e aggiungi **Run Code**. Salva l'agente. Da quel momento in poi è l'agente a decidere quando eseguire il codice; non è necessario richiederlo esplicitamente, anche se "usa il codice per verificarlo" è utile quando desideri una risposta esatta.

Mentre il codice è in esecuzione, il messaggio mostra una riga comprimibile che riporta **Avvio dell'ambiente sandbox** la prima volta, poi **Analisi in corso** e **Analisi completata** al termine. Espandila per visualizzare il codice scritto dall'agente e il relativo **Output**.

## Lavorare con i file [#working-with-files]

Allega un file e scegli **Carica nell'ambiente di codice** per renderlo disponibile alla sandbox per quella conversazione. I file aggiunti nelle impostazioni Esegui codice dell'agente sono disponibili in ogni chat con quell'agente. Prima di ogni esecuzione LibreChat ripristina i file della conversazione nella sandbox; se non è possibile ripristinare nessuno dei file necessari all'esecuzione, l'esecuzione si interrompe e ti chiede di allegarli di nuovo, invece di lavorare con copie obsolete.

I file generati dal codice vengono restituiti come righe nel messaggio. Fai clic su una riga per aprirla nel pannello [Artifacts](/docs/features/artifacts), oppure scaricala. I file HTML, Markdown, testo semplice, codice sorgente, CSV e Office (documenti Word, fogli Excel, OpenDocument, presentazioni e modelli PowerPoint) hanno un'anteprima integrata. I file più grandi non mostrano l'anteprima e restano disponibili solo per il download; la soglia predefinita è di 2 MiB di file sorgente. Le immagini che l'agente legge dalla sandbox (PNG, JPEG, GIF, WebP) vengono visualizzate direttamente fino a 1 MiB; quelle più grandi restano nella sandbox, dove l'agente può comunque elaborarle.

## Esegui un blocco di codice da solo [#run-a-code-block-yourself]

I blocchi di codice nei messaggi della chat hanno un pulsante **Run Code** accanto a **Copy code** quando il linguaggio del blocco è uno di quelli eseguibili dalla sandbox (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust o Fortran). Fai clic su di esso e l'output compare sotto il blocco. Questa funzione funziona in qualsiasi conversazione, non solo con gli agenti.

## Codice a esecuzione prolungata [#long-running-code]

Se il tuo amministratore ha abilitato gli strumenti in background, nelle impostazioni Run Code dell'agente compare **Esecuzione in background**, attiva per impostazione predefinita. L'agente può avviare codice lento, continuare a conversare con te e recuperare l'output e i file quando l'esecuzione termina; per impostazione predefinita il risultato arriva da solo in un messaggio di follow-up. Disattiva l'impostazione per gli agenti che devono sempre attendere il completamento del proprio codice.

La memoria, il tempo di CPU, la dimensione dei caricamenti e l'accesso alla rete sono impostati da chi gestisce il servizio sandbox, non da LibreChat. Se il codice restituisce un errore di risorse, chiedi al tuo amministratore quali sono i limiti.

## Sessioni di codice con stato [#stateful-code-sessions]

Per impostazione predefinita ogni esecuzione è senza stato: non fare affidamento sul fatto che variabili o pacchetti installati sopravvivano all'esecuzione successiva. Le sessioni di codice con stato, una funzionalità sperimentale che il tuo amministratore deve attivare, offrono a un agente un'area di lavoro che conserva i file in `/mnt/data` tra un'esecuzione e l'altra. Ogni esecuzione avvia comunque un nuovo processo, e l'area di lavoro può essere reimpostata in qualsiasi momento, quindi va trattata come un'area di lavoro temporanea e non come un archivio di dati.

Attiva **Stateful code sessions** nelle impostazioni Run Code dell'agente e scegli un **Stateful environment**:

- **Spazio di lavoro utente (consigliato)**: uno spazio di lavoro per te, condiviso da tutti gli agenti stateful che utilizzi.
- **Workspace agente + utente**: uno spazio di lavoro separato per ogni agente.
- **Spazio di lavoro della conversazione**: uno spazio di lavoro nuovo per ogni conversazione.

I nuovi agenti iniziano con l'ambito impostato in **Impostazioni > Dati e privacy > Esecuzione del codice > Area di lavoro stateful predefinita**; modificare questa impostazione non influisce sugli agenti esistenti. I file che l'agente crea o modifica in un'area di lavoro stateful sono elencati in una riga **Modifiche all'area di lavoro** nella sua risposta, con un link per il download di ciascuno.

## Esecuzione del codice sulla propria macchina [#running-code-on-your-own-machine]

Gli amministratori possono anche offrire ambienti di esecuzione del codice: una VM o una workstation che esegue il worker `@librechat/code`, il quale si connette in uscita a LibreChat. In questo caso, il Costruttore di agenti mostra un selettore **Execution environment**, e **Machines available in new chats** permette a un agente di offrire più macchine, così che ogni nuova chat possa sceglierne una tramite **Choose another machine**.

Se hai il permesso di gestire gli ambienti di codice, aggiungine uno tuo in **Impostazioni > Dati e privacy > Esecuzione del codice > Ambienti di codice**: assegnagli un nome, seleziona **Connetti VM** ed esegui sulla tua macchina il comando una tantum che viene mostrato. Se il tuo amministratore ha abilitato la configurazione tramite browser, il comando di configurazione può invece aprire una pagina **Approva configurazione macchina**, dove confermi la richiesta mentre sei connesso.

Su una macchina collegata, l'agente può sfogliare, leggere, cercare e modificare file ed eseguire comandi shell nello spazio di lavoro selezionato. Gli allegati della chat che carichi vengono copiati in `.librechat/attachments` in quello spazio di lavoro prima che l'agente inizi. Poiché queste azioni modificano una macchina reale, il compositore mostra una **Modalità di approvazione del codice** per la conversazione:

- **Chiedi prima delle modifiche**: chiede conferma prima di modificare file ed eseguire comandi.
- **Accetta modifiche**: modifica i file senza chiedere conferma, ma chiede comunque prima di eseguire i comandi.
- **Accesso completo**: modifica ed esegue comandi senza richieste di conferma di routine. I limiti della sandbox sulla macchina restano comunque in vigore.

La modalità selezionabile dipende dalla policy del tuo amministratore. L'associazione di una macchina autentica il worker su LibreChat; non isola nulla, quindi isola il worker come faresti per qualsiasi macchina che esegue codice non attendibile.

## Chiamare gli strumenti MCP dal codice [#calling-mcp-tools-from-code]

Con Programmatic Tool Calling, un agente può chiamare alcuni strumenti MCP dall'interno della sandbox: scrive uno script che cicla sugli input, chiama gli strumenti, filtra i risultati e restituisce solo ciò che conta. Questo evita un passaggio di andata e ritorno attraverso il modello per ogni chiamata a uno strumento. Gli interruttori Programmatic restano disabilitati finché l'agente non ha Run Code, e rimuovendo Run Code vengono azzerati. Mentre lo script è in esecuzione, espandi la sua riga per osservare la traccia **Tool calls**; la traccia non viene conservata dopo il ricaricamento della pagina. Solo gli strumenti registrati nell'agente possono essere chiamati in questo modo. Vedi [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling) per sapere come contrassegnare gli strumenti.

## Setup [#setup]

L'esecuzione del codice richiede che un amministratore distribuisca il servizio Code Interpreter e configuri LibreChat per utilizzarlo; fino ad allora, le esecuzioni non andranno a buon fine. Il pulsante **Run Code** e la funzionalità dell'agente possono anche essere disattivati per ogni ruolo. L'esecuzione in background, le sessioni con stato e gli ambienti di codice sono ciascuno opzionali. Vedi [Configurazione di Code Interpreter](/docs/configuration/tools/code_interpreter).
