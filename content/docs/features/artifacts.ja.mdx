Artifactsを使用すると、LibreChatのAgentは生成されたReactコンポーネント、HTML、SVG、Markdown、およびMermaidコンテンツを専用のインタラクティブなビューでレンダリングできます。ユーザーは会話を継続して結果を修正でき、生成されたコンテンツをチャットの応答とは別に保持することが可能です。

## エージェントでArtifactsを有効にする [#enable-artifacts-for-an-agent]

1. [Agent](/docs/features/agents) を作成または編集します。
2. **Add tools**を開き、**Artifacts**を選択します。
3. アーティファクトの指示モードを選択してください。
4. エージェントを保存します。

利用可能なモードは以下の通りです：

- **Normal**: LibreChatのReact、HTML、SVG、Markdown、およびMermaidアーティファクト用の標準的な指示を注入します。
- **shadcn/ui**: より洗練された生成インターフェースを実現するための、shadcn/ui コンポーネントライブラリのガイダンスを追加します。
- **Custom**: アーティファクトのレンダリングを有効に保ちますが、組み込みの指示は一切挿入しません。エージェントの指示に、希望するアーティファクトの動作を完全に記述してください。

エージェントレベルの設定が推奨されます。これは、各エージェントがその目的に適したモードや指示を使用できるためです。管理者は、`artifacts` [エージェント機能](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)を削除することで、Artifactsを非表示にできます。

## Artifactsのサポート内容 [#what-artifacts-support]

- インタラクティブなReactコンポーネントとHTMLページ
- SVG画像とMermaidダイアグラム
- レンダリングされたMarkdownドキュメント
- フォローアップメッセージによる反復的な更新
- 構成されたエージェントが利用可能な任意のモデル

## プレビューとエクスポート [#preview-and-export]

レンダリングされたアーティファクトプレビューのフルスクリーンコントロールを使用して、ブラウザの表示全体に拡大します。このコントロールはブラウザの Fullscreen API 状態に従い、Escape キーまたはブラウザのコントロールで通常通り終了でき、フルスクリーンが利用できない場合は非表示になります。

デスクトップでは、アーティファクトパネルヘッダーの **Open in new window** を選択すると、パネルを別のブラウザウィンドウに移動できます（例：2つ目の画面に配置する場合など）。アーティファクトはレスポンスのストリーミングに合わせて更新され、保存されていないコードの編集内容や選択中のタブも引き継がれます。パネルをチャットに戻すには、**Dock back to panel** を選択するか、ウィンドウを閉じてください。LibreChatは、次回のためにウィンドウのサイズと位置を記憶します。

- チャットタブを開いたままにしてください。ウィンドウはチャットタブによって制御されており、そのタブを閉じるとウィンドウも閉じます。
- ブラウザがウィンドウをブロックした場合、LibreChatは通知を表示します。サイトのポップアップを許可してから、もう一度試してください。
- このボタンは、狭い（モバイル）レイアウトでは表示されません。

管理者は [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking) を設定することで、ボタンを削除し、アーティファクトをサイドパネルに保持することができます。

Mermaidダイアグラムは、アーティファクトパネルで開くことができるコンパクトなインラインカードとして表示されます。インラインカードまたはパネルのいずれかから、ダイアグラムをSVGまたはPNGとしてエクスポートできます。MermaidのプレビューはSandpackバンドラーを読み込むのではなく直接レンダリングされます。PNGエクスポートでは、巨大なダイアグラムからブラウザを保護するために、境界付きのキャンバスサイズが適用されます。

モデルが作成したアーティファクトは、そのタイトルまたはMarkdown見出しの下に、エクスポートされたコンテンツと一致する拡張子でダウンロードされます。編集されていないファイルベースのアーティファクトは、利用可能な場合は元のファイル名と形式で完全なオリジナルがダウンロードされます。編集済みまたはキャッシュされたプレビューコンテンツをダウンロードする場合は、元のファイルと混同しないように `.preview` 修飾子が使用されます。

## Content-Security-Policy

Artifactsパネルで生成されたHTMLアプリを読み込むために、WebサーバーのContent-Security-Policyを更新して `frame-src 'self' https://*.codesandbox.io` を含める必要がある場合があります。これは [sandpack](https://sandpack.codesandbox.io/) ライブラリの依存関係によるものです。

## Sandpack Bundlerのセルフホスティング [#self-hosting-the-sandpack-bundler]

LibreChatのArtifactsは、CodeSandboxのSandpackライブラリを使用してHTML/JSコードを安全にレンダリングします。デフォルトでは、LibreChatはCodeSandboxのパブリックCDNに接続しますが、これには使用状況に関するテレメトリが送信される可能性があります。

プライバシーの強化、セキュリティコンプライアンス、または隔離されたネットワーク環境のために、[バンドラーをセルフホスト](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)することができます。

### Sandpack Bundlerをセルフホストする理由 [#why-self-host-the-sandpack-bundler]

[Self-hosting the bundler](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler) を行うことには、いくつかの利点があります：

- **プライバシーとセキュリティ**: コード実行を自身のインフラストラクチャ内に保持します
- **信頼性**: 外部サービスへの依存を排除する
- **パフォーマンス**: バンドラーをネットワーク内でホストすることでレイテンシを削減します
- **コンプライアンス**: 組織のデータ取り扱い要件を満たす
- **Control**: 特定のニーズに合わせて構成およびカスタマイズします

### 設定 [#configuration]

セルフホスト型のバンドラーをセットアップしたら、環境変数を設定するだけでLibreChatがそれを使用するように構成できます：

```bash
# `.env` file
SANDPACK_BUNDLER_URL=http://your-bundler-url
```

### 一般的な考慮事項 [#general-considerations]

バンドラーをセルフホストすると、追加のオーバーヘッドが発生します：

- **CORS Configuration**: クロスオリジンリソース共有（CORS）ポリシーを管理する必要があります。
- **Security Management**: バンドラーサービスのセキュリティはお客様の責任となります
- **メンテナンス**: アップデートおよびパッチは手動で適用する必要があります
- **リソース要件**: バンドラーをホストするために追加のサーバーリソースが必要になります。

セルフホスト型バンドラーのセットアップおよび保守に関する詳細な手順については、Sandpackからテレメトリを削除するなど、LibreChatのデプロイ向けに調整された[フォーク済みのCodeSandboxリポジトリ](https://github.com/LibreChat-AI/codesandbox-client)を参照してください。
