Lorsqu'un agent travaille sur un dépôt situé dans un espace de travail de code attaché, LibreChat recherche la pull request correspondant à la branche sur laquelle se trouve l'espace de travail et l'affiche à côté de la conversation. Vous pouvez voir si elle est prête à être fusionnée, si les vérifications passent, et y accéder directement, sans quitter la conversation. Cela fonctionne avec GitHub, GitLab (où elle est appelée merge request) et Bitbucket Cloud, avec un seul fournisseur par déploiement.

Seuls les chats qui exécutent du code dans un espace de travail rattaché peuvent avoir une pull request. Un chat simple, ou un espace de travail qui n'a pas encore signalé de branche, n'affiche rien.

## Dans l'en-tête du chat [#in-the-chat-header]

Sur un écran large, une puce située à gauche de l'en-tête affiche l'icône de la pull request, un petit point de CI dans son coin et le titre de la pull request. Survolez ou placez le focus sur la puce pour ouvrir une carte contenant les détails. La carte reste ouverte tant que votre pointeur ou le focus du clavier se trouve à l'intérieur.

Sur un petit écran, il n'y a pas de puce. Ouvrez le menu à trois points de l'en-tête et choisissez l'entrée `PR #number` (`MR !number` sur GitLab) pour afficher la même carte dans une boîte de dialogue.

L'en-tête se met à jour automatiquement : il vérifie à nouveau environ toutes les 20 secondes tant que des vérifications sont en cours ou que le fournisseur est encore en train de déterminer si la branche peut être fusionnée, et environ toutes les 60 secondes dans le cas contraire. Il s'arrête une fois que la pull request est fusionnée ou fermée et qu'aucun traitement n'est plus en cours.

## Dans la barre latérale [#in-the-sidebar]

Les conversations qui ont une pull request affichent la même icône et le même point CI à la fin de leur ligne. La ligne conserve le titre propre à la conversation. Survolez la ligne, ou placez le focus ou cliquez sur le repère, pour ouvrir la carte à côté de celle-ci ; cliquer sur le repère n'ouvre pas la conversation.

<ThemeImage
  light="/images/pull-requests/side-rows-light.png"
  dark="/images/pull-requests/side-rows-dark.png"
  alt="Lignes de la barre latérale avec marques de demandes de tirage : prêtes à fusionner, conflits avec des vérifications en échec, un brouillon avec des vérifications en cours, et une demande de tirage fusionnée"
/>

La barre latérale n'interroge pas le serveur en continu. Une ligne est aussi récente que la dernière fois que la liste a été chargée, et elle est actualisée lorsque vous revenez sur la fenêtre et que ses données datent de plus d'une minute. Si une actualisation échoue pour une pull request déjà trouvée, le repère reste affiché et la carte indique « Impossible d'actualiser la pull request » avec un bouton **Réessayer**. Une conversation dont la pull request n'a jamais été trouvée n'affiche aucun repère, même lorsque la recherche a échoué.

## Lire la carte [#reading-the-card]

La carte affiche `PR #number` (`MR !number` sur GitLab), les lignes ajoutées en vert et supprimées en rouge, un lien **Open in GitHub**, **Open in GitLab** ou **Open in Bitbucket**, le titre, et deux badges :

- État : Open, Conflicts, Draft, Merged ou Closed. Conflicts remplace Open lorsque la branche ne peut pas être fusionnée proprement.
- Vérifications : Réussie, Échouée, En cours ou Aucune. Sur GitLab, il s'agit du pipeline principal, uniquement s'il a été exécuté pour le commit actuel. Sur Bitbucket, ce sont les statuts de commit.

La couleur de l'icône et le point CI résument la même information d'un coup d'œil :

| Pull request | Icône | Point CI |
| --- | --- | --- |
| Ouverte, peut être fusionnée | Vert | Selon les vérifications |
| Ouverte, fusionnabilité pas encore connue | Neutre | Selon les vérifications |
| Ouverte, conflits de fusion | Rouge | Selon les vérifications |
| Brouillon | Neutre | Selon les vérifications |
| Fusionnée | Violet | Aucun |
| Fermée | Neutre | Aucun |

Le point est vert pour les vérifications réussies, rouge pour les vérifications échouées et orange pour les vérifications en cours. Aucun point n'est affiché lorsque le dépôt ne signale aucune vérification. Une vérification échouée prime sur une vérification encore en cours.

## Quelle pull request vous voyez [#which-pull-request-you-see]

Le workspace indique le dépôt, la branche et le commit sur lesquels le chat a été exécuté en dernier, et LibreChat recherche une pull request provenant de cette branche :

- Si la sortie de commande du chat affiche un lien vers une pull request dans le même dépôt (par exemple l'URL qu'affiche `gh pr create`), cette pull request est utilisée, à condition qu'elle provienne de la branche du chat.
- Sinon, les pull requests ouvertes pour la branche sont privilégiées par rapport aux pull requests fermées, de sorte qu'une ancienne pull request fermée sur un nom de branche réutilisé ne masque pas la pull request actuelle.
- Une pull request ne compte que si elle contient le commit sur lequel le chat a été exécuté en dernier. Supprimer une branche et réutiliser son nom ne restaure pas l'ancienne pull request.
- Une nouvelle branche sans aucun commit ne correspond à rien.

Les dépôts que le serveur n'est pas autorisé à consulter se comportent exactement comme les dépôts sans pull request : aucune marque, aucune erreur.

## Connecter votre propre compte [#connect-your-own-account]

Si votre administrateur l'a configuré, vous pouvez rechercher des pull requests avec votre propre compte GitHub, GitLab ou Bitbucket. Ouvrez **Paramètres**, accédez à **Compte**, puis, sous **Comptes connectés**, cliquez sur **Connecter** à côté de **Compte de pull request**. Une fenêtre de connexion s'ouvre chez le fournisseur ; approuvez-la et la ligne affiche **Connecté**. Si la fenêtre ne s'ouvre pas, autorisez les pop-ups pour LibreChat et réessayez.

Une fois connecté, les recherches utilisent votre compte : vous voyez donc les pull requests de tous les dépôts que vous pouvez lire, avec votre propre limite de débit. **Déconnecter** supprime la connexion, et vous pouvez vous reconnecter à tout moment. Si le serveur ne parvient pas à actualiser votre connexion (par exemple, si le fournisseur est indisponible), vos pull requests s'affichent comme indisponibles au lieu de basculer silencieusement sur le jeton du serveur. Si vous révoquez l'application auprès du fournisseur, LibreChat supprime la connexion et vous revenez à l'état non connecté.

Si la ligne indique **Not in use**, votre administrateur a désactivé les connexions de compte et les recherches n'utilisent plus votre compte. Cliquez sur **Disconnect** pour supprimer la connexion enregistrée.

## Configuration [#setup]

La fonctionnalité est activée par défaut, mais reste masquée tant qu'un administrateur ne fournit pas à LibreChat un jeton et une liste de dépôts qu'il peut consulter, ou ne configure pas une application pour que les utilisateurs puissent connecter leurs propres comptes. Elle nécessite également un espace de travail de code rattaché qui signale sa branche git. Voir [Configuration des Pull Requests](/docs/configuration/pull_requests).
