O Code Interpreter executa código em um sandbox isolado. Agentes o usam para fazer cálculos que, de outra forma, teriam que estimar, analisar uma planilha que você enviou, converter arquivos ou produzir gráficos e documentos. Você também pode executar um bloco de código de uma mensagem do chat por conta própria com **Run Code**.

O sandbox é um serviço separado, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (código aberto, Apache 2.0), que o seu administrador implanta junto com o LibreChat. Ele oferece suporte a Python, Node.js (JavaScript e TypeScript), Go, C e C++, Java, PHP, Rust e Fortran.

## Dê a um agente execução de código [#give-an-agent-code-execution]

No Agent Builder, selecione **Adicionar** ao lado de **Tools** e adicione **Run Code**. Salve o agente. A partir daí, o agente decide quando executar código; você não precisa pedir explicitamente, embora "use código para verificar isso" ajude quando você quiser uma resposta exata.

Enquanto o código é executado, a mensagem exibe uma linha recolhível com o texto **Starting sandbox environment** na primeira vez, depois **Analyzing** e **Finished analyzing** quando a execução termina. Expanda-a para ver o código que o agente escreveu e a sua **Output**.

## Trabalhando com arquivos [#working-with-files]

Anexe um arquivo e escolha **Enviar para o Ambiente de Código** para disponibilizá-lo ao sandbox nessa conversa. Os arquivos adicionados nas configurações Executar Código do agente ficam disponíveis em todas as conversas com esse agente. Antes de cada execução, o LibreChat restaura os arquivos da conversa no sandbox; se nenhum dos arquivos necessários para a execução puder ser restaurado, a execução é interrompida e solicita que você anexe os arquivos novamente, em vez de trabalhar com cópias desatualizadas.

Os arquivos gerados pelo código aparecem como linhas na mensagem. Clique em uma linha para abri-la no painel de [Artefatos](/docs/features/artifacts), ou baixe-a. Arquivos HTML, Markdown, texto simples, código-fonte, CSV e arquivos do Office (Word, Excel, OpenDocument, apresentações e modelos do PowerPoint) recebem uma pré-visualização inline. Arquivos maiores não exibem pré-visualização e permanecem disponíveis apenas para download; o limite padrão é de 2 MiB de arquivo-fonte. As imagens que o agente lê do sandbox (PNG, JPEG, GIF, WebP) são exibidas inline até 1 MiB; imagens maiores permanecem no sandbox, onde o agente ainda pode processá-las.

## Execute um bloco de código você mesmo [#run-a-code-block-yourself]

Blocos de código nas mensagens do chat exibem um botão **Run Code** ao lado de **Copy code** quando a linguagem do bloco é uma que o sandbox consegue executar (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust ou Fortran). Clique nele e a saída aparece abaixo do bloco. Isso funciona em qualquer conversa, não apenas com agentes.

## Código de execução longa [#long-running-code]

Se o seu administrador tiver habilitado as ferramentas em segundo plano, as configurações de Executar código do agente mostram **Execução em segundo plano**, ativada por padrão. O agente pode iniciar códigos demorados, continuar conversando com você e obter a saída e os arquivos quando a execução terminar; por padrão, o resultado chega por conta própria em uma mensagem de acompanhamento. Desative a configuração para agentes que devem sempre aguardar a conclusão do código.

A memória, o tempo de CPU, o tamanho de upload e o acesso à rede são definidos por quem executa o serviço de sandbox, e não pelo LibreChat. Se o código falhar com um erro de recurso, pergunte ao seu administrador quais são os limites.

## Sessões de código com estado [#stateful-code-sessions]

Por padrão, cada execução é stateless: não conte com variáveis ou pacotes instalados sobrevivendo à próxima execução. Sessões de código com estado, um recurso experimental que o seu administrador precisa ativar, oferecem a um agente um workspace que mantém seus arquivos em `/mnt/data` entre execuções. Cada execução ainda inicia um novo processo, e o workspace pode ser redefinido a qualquer momento, portanto trate-o como uma área de rascunho e não como armazenamento.

Ative **Stateful code sessions** nas configurações de Run Code do agente e escolha um **Stateful environment**:

- **Workspace do usuário (recomendado)**: um workspace para você, compartilhado por todos os agentes com estado que você usar.
- **Workspace do agente + usuário**: um workspace separado para cada agente.
- **Espaço de conversa**: um espaço de trabalho novo para cada conversa.

Novos agentes começam com o escopo definido em **Configurações > Dados e Privacidade > Execução de código > Espaço de trabalho stateful padrão**; alterar essa configuração não afeta agentes existentes. Os arquivos que o agente cria ou edita em um espaço de trabalho stateful são listados em uma linha **Alterações no espaço de trabalho** na sua resposta, com um download para cada um.

## Executando código na sua própria máquina [#running-code-on-your-own-machine]

Os administradores também podem oferecer ambientes de código: uma VM ou estação de trabalho executando o worker `@librechat/code`, que se conecta ao LibreChat. Quando isso acontece, o Agent Builder exibe um seletor **Execution environment** e a opção **Machines available in new chats** permite que um agente ofereça várias máquinas, para que cada novo chat possa escolher uma delas com **Choose another machine**.

Se você tiver permissão para gerenciar ambientes de código, adicione o seu próprio em **Settings > Data & Privacy > Code execution > Code environments**: dê um nome a ele, selecione **Connect VM** e execute o comando único que for exibido na sua máquina. Se o seu administrador tiver habilitado a configuração pelo navegador, o comando de configuração pode, em vez disso, abrir uma página **Approve Machine Setup**, na qual você confirma a solicitação enquanto estiver autenticado.

Em uma máquina anexada, o agente pode navegar, ler, pesquisar e editar arquivos e executar comandos de shell no workspace selecionado. Os anexos de chat que você enviar são copiados para `.librechat/attachments` nesse workspace antes de o agente iniciar. Como essas ações alteram uma máquina real, o compositor exibe um **Modo de aprovação de código** para a conversa:

- **Perguntar antes de alterações**: pergunta antes de editar arquivos e executar comandos.
- **Aceitar edições**: edita arquivos sem perguntar, mas ainda pede confirmação antes de comandos.
- **Acesso total**: edita e executa comandos sem solicitações rotineiras. Os limites do sandbox na máquina ainda se aplicam.

Quais modos você pode escolher depende da política do seu administrador. Parear uma máquina autentica o worker no LibreChat; isso não isola nada em sandbox, portanto isole o worker como faria com qualquer máquina que execute código não confiável.

## Chamando ferramentas MCP a partir de código [#calling-mcp-tools-from-code]

Com a Chamada Programática de Ferramentas, um agente pode chamar ferramentas MCP selecionadas de dentro do sandbox: ele escreve um script que percorre as entradas, chama as ferramentas, filtra os resultados e retorna apenas o que importa. Isso evita uma ida e volta pelo modelo a cada chamada de ferramenta. As opções de Programmatic permanecem desativadas até que o agente tenha Run Code, e remover Run Code as limpa. Enquanto o script é executado, expanda a sua linha para acompanhar um rastreamento de **Tool calls**; o rastreamento não é mantido após o recarregamento da página. Somente ferramentas registradas no agente podem ser chamadas dessa forma. Consulte [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling) para saber como marcar ferramentas.

## Configuração [#setup]

A execução de código exige que um administrador implante o serviço Code Interpreter e aponte o LibreChat para ele; até lá, as execuções falham. O botão **Run Code** e a capacidade do agente também podem ser desativados por função. A execução em segundo plano, as sessões com estado e os ambientes de código são, cada um, opcionais. Consulte [Configuração do Code Interpreter](/docs/configuration/tools/code_interpreter).
