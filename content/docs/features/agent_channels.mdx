Agent Channels let you talk to a LibreChat [agent](/docs/features/agents) from Slack, in a channel or direct message. Each person links their own LibreChat account and uses their own permissions, tool connections, and approvals.

<Callout type="warning" title="Beta and opt-in">
An operator must [deploy the Slack gateway](/docs/configuration/channel_gateway) and its database prerequisites first. Installing a Slack app alone does not make an agent available.
</Callout>

## Before you start

Follow the steps for your role:

| Who | What to do |
| --- | --- |
| Deployment operator | [Run the gateway](/docs/configuration/channel_gateway#organization-workspaces) and configure the public HTTPS callback URLs. |
| Organization administrator | [Register a Slack app and connect a workspace](#organization-workspaces), then grant bot management access if needed. |
| Agent manager | [Assign an agent](#assign-an-agent) to the bot or a channel. |
| Each Slack participant | [Link your account](#account-linking), confirm it in Slack, and send a new request. |

Participants need access to the agent and a role that allows using Agents and querying them through Remote Agents (API). Assigning an agent also requires permission to share it and bot management access; installation administrators do not need a separate bot-manager grant. Installing the app or linking an account does not grant these permissions.

If your deployment uses a manually configured Slack app instead of organization workspaces, follow [manual connection setup](#set-up-a-manual-slack-app-connection).

## Organization workspaces

A Slack app provides the bot's identity; installing it grants access to a workspace. Each registered app supports **one active workspace**. Use separate apps for additional workspaces.

### Register an organization’s Slack app

<Steps>
<Step>

**Create the app in Slack.** Open [Your Apps](https://api.slack.com/apps) and create an app from scratch, or use one your organization controls. If Slack shows the **Pick features** wizard, continue without scopes or events, then select **Create → Create Anyway**. Do not install it yet.

</Step>
<Step>

**Register it in LibreChat.** Open **Settings → Account → Slack → Set up** (or **Manage**), then **Add Slack app**. Copy **App ID**, **Client ID**, **Client Secret**, and **Signing Secret** from Slack's **Basic Information → App Credentials**. Select **Show** before copying secrets. The optional **Name** labels the app in LibreChat without renaming the Slack bot. Save the registration.

<ThemeImage
  light="/images/features/agent_channels/org-app-registration-light.jpg"
  dark="/images/features/agent_channels/org-app-registration-dark.jpg"
  alt="Add Slack app dialog with app ID, client ID, client secret, and signing secret fields"
/>

</Step>
<Step>

**Configure its callbacks.** Turn **Socket Mode off** in Slack. Expand the saved app in LibreChat and open the gear button, **Connection settings**. Copy all three URLs into that same Slack app:

| LibreChat value | Slack setting |
| --- | --- |
| OAuth redirect URL | **OAuth & Permissions → Redirect URLs**; add and save |
| Events URL | **Event Subscriptions → Enable Events → Request URL**; wait for **Verified** |
| Interactivity URL | **Interactivity & Shortcuts → Interactivity → Request URL**; save |

Keep the complete URLs, including any base path and organization/app suffixes. The gateway must be running and publicly reachable before Slack can verify the Events URL.

</Step>
<Step>

**Add scopes and events in Slack.** Under **OAuth & Permissions → Bot Token Scopes**, add:

```text
app_mentions:read
chat:write
reactions:read
reactions:write
files:write
im:write
im:history
```

No user-token scopes are needed. Under **Event Subscriptions → Subscribe to bot events**, add `app_mention`, `message.im`, `reaction_added`, `reaction_removed`, `app_uninstalled`, and `tokens_revoked`, then save.

Under **App Home**, enable the **Messages tab** and allow users to send messages from it. Leave token rotation and organization-wide installation disabled. Optional [native Agent sessions](/docs/configuration/channel_gateway#native-agent-ui-and-final-replies) need additional setup.

</Step>
<Step>

**Install the app.** In LibreChat, select **Add to workspace**, choose the intended Slack workspace, and approve installation. Wait for **Connecting to Slack…** to close and **Connected** to appear. **Cancel** abandons a pending installation; **Retry** tries again after failure. Workspace approval policies still apply.

</Step>
</Steps>

LibreChat stores app credentials encrypted; organization setup does not ask for a bot token or app-level token. Use the pencil button, **Edit App**, to update credentials later. Blank secrets keep their saved values; a new client ID requires its matching secret. To change the App ID, register another app.

After changing scopes, reconnect the installed app through LibreChat and approve the new grant; Slack settings alone do not update existing tokens.

## Assign an agent

An administrator grants bot management through the workspace's users button, **Manage access** (**Manage bot access** dialog). This lets someone assign agents through the bot; it does not grant Agent sharing permission and is not needed just to talk to the bot.

<Steps>
<Step>

Save an agent you have permission to share. In the Agent Builder's **Channels** section, select **Add**, then the **Slack** card in the Channel Library.

</Step>
<Step>

Choose a **Slack bot**, then **Continue**. If none appear, ask an administrator to connect a workspace and grant you bot management access.

</Step>
<Step>

Choose **Default** for new direct messages and mentions without a channel-specific assignment. Or choose **Channel Specific** and enter the **Slack channel ID** from Slack's channel details, rather than its name. Select **Assign agent**.

If another agent already owns that destination, **Replace default agent** or **Replace channel agent** asks for confirmation. Existing conversations keep their original agent.

</Step>
</Steps>

## Account linking

Each participant links their own account on first use and may need to link again after expiry, disconnect, or reactivation.

<Steps>
<Step>

Invite the bot to a Slack channel with `/invite @YourBot`, then mention it: `@YourBot hello`. Installation does not invite it to every channel. Or send a direct message when the Messages tab is enabled.

</Step>
<Step>

Select **Link account** in the bot's private message. Sign in to the intended LibreChat account, check the request, and accept it in the browser.

<ThemeImage
  light="/images/features/agent_channels/account-accepted-light.jpg"
  dark="/images/features/agent_channels/account-accepted-dark.jpg"
  alt="One more step in Slack page showing the linked LibreChat account, agent, and instruction to confirm in Slack"
/>

</Step>
<Step>

Return to the same Slack message. It updates to show your account name and **Confirm account**. Confirm from the **same Slack account**. If the message has expired or does not update, mention the bot again to recover the prompt.

</Step>
<Step>

When it shows **Account connected**, send a **new request**; the original is not replayed. A successful answer completes setup. Try a permitted tool to verify tool access too.

</Step>
</Steps>

## Use the agent

Continue in the same Slack thread for follow-up questions. A working message provides **Stop** and, when needed, **Review**. Supported questions and individual tool approvals use private Slack controls; provider sign-in and unsupported forms open the authenticated browser flow. The agent's approval policy still applies.

Answers can contain code, tables, links, files, and charts. Agent authors can opt into richer layouts using the [rich-message format](/docs/configuration/channel_gateway_reference#rich-agent-messages). Optional native Agent status and lifecycle reactions are configured by the deployment operator.

Sharing a Slack thread does not share another person's files, account, pending question, or approval authority. **Stop** cancels your authorized work without undoing effects a tool already performed. Wait for the final status; an acknowledgement alone does not mean work has finished.

## Manage connections

- **Agent assignments:** hover over or focus a connection row and open its gear button, **Manage connection**. Use **Add assignment** for another destination, or **Remove** beside an assignment and confirm. **Delete connection** removes all its assignments after confirmation. Existing threads do not silently move to another agent.
- **Workspace connection:** disabling stops execution while retaining assignments. **Activate channel** confirms the retained assignment; each participant must link and confirm again after reactivation. Removing a manager's access alone does not stop existing assignments or conversations.
- **Your account:** in **Settings → Account → Your channel account links**, rows show the agent name and Slack user/workspace IDs. Hover over the Slack icon to read the link status. Hover over or focus a row, select **Disconnect**, and confirm to withdraw your consent. You can disconnect an unavailable link too; completed actions are not undone.
- **Workspace installation:** in **Settings → Account → Slack → Manage**, use **Disconnect workspace** to retire the installation in LibreChat. This does not uninstall the Slack app. A new installation has a fresh identity and needs new assignments and manager grants. Reconnecting an active installation updates its grant and preserves managers.
- **App registration:** disconnect its workspace first, then use **Remove app** to delete its saved credentials. The app itself remains in Slack. Removing the person who configured it does not delete the organization's installation.

## Set up a manual Slack app connection

Use this path when organization workspaces are not enabled. Your operator must enable manual Channels and [prepare the gateway](/docs/configuration/channel_gateway#configuration-and-prerequisites).

<Steps>
<Step>

Save the agent, then choose **Channels → Add → Slack**. Choose **Per-user accounts** for each participant's own account, or **Channel owner only** to restrict use to the creator. Select **Continue**. Owner-only mode does not lend your account to others.

</Step>
<Step>

In **Create**, select **Create in Slack** to open Slack with the generated manifest. Choose the workspace, create the app, then **Install to Workspace → Allow**. If the link fails, expand **Link not working? Paste the manifest manually**. Make later app changes in Slack's app settings.

<ThemeImage
  light="/images/features/agent_channels/manual-create-light.png"
  dark="/images/features/agent_channels/manual-create-dark.png"
  alt="Manual Slack setup wizard on the Create step, with Create in Slack and the manual manifest fallback"
/>

</Step>
<Step>

In **Credentials**, enter the matching **Slack app ID** and **Bot token**. Webhook mode also requires the **Signing secret**. Select **Continue**, review the values in **Activate**, then select **Activate channel**. LibreChat verifies the bot identity and stores the credentials encrypted.

</Step>
<Step>

Hover over or focus the Slack/status icon in the connection dialog to find the **Connection ID**. Give it to the operator to [start the bound gateway](/docs/configuration/channel_gateway#run-the-slack-gateway). Invite and mention the bot, then complete [account linking](#account-linking).

</Step>
</Steps>


In **Manage connection**, the pencil beside the identity mode changes who can use the connection. An active connection must be disabled first; confirm **Disable and change**, choose the mode, and **Save**. Existing links and pending requests stop working. After saving, reopen **Manage connection → Setup**. Use the existing Slack app, re-enter its bot token (and signing secret for webhooks), then finish the wizard and select **Activate channel**. Each participant must link and confirm again.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Channels or a Slack bot is missing | Save the agent first. Check gateway setup, Agent and Remote Agents permissions, sharing access, and bot management access. |
| Events URL will not verify, or Slack callbacks return `401` | Gateway is running on public HTTPS; the URL and **Signing Secret** belong to the same saved app. Check clock synchronization; do not disable signature checks. |
| The bot does not respond | Invite it to the channel, assign an agent, and check the personal link. For organization workspaces, turn **Socket Mode off** and enable Events with the subscriptions above. Ask the operator to check [gateway readiness](/docs/configuration/channel_gateway#verify-the-gateway). |
| Confirmation, approval, or Stop does nothing | Enable **Interactivity** and save its exact Request URL. The Events URL is a separate callback. |
| Link is awaiting confirmation | Select **Confirm account** in the private Slack message, then send a new request. Mention the bot again to recover the prompt if needed. |
| Permissions are missing after scopes changed | Reconnect through LibreChat and approve the updated grant. Existing tokens do not gain scopes automatically. |

If an approval becomes unavailable after a server restart, ask an administrator to check the [recovery limits](/docs/configuration/channel_gateway_reference#operational-limits). A stale approval does not execute the tool; check the original run before starting the work again.
