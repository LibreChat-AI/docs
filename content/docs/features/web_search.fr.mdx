title: Recherche Web

La fonctionnalité de recherche web de LibreChat vous permet d'effectuer des recherches sur Internet et de récupérer des informations pertinentes pour enrichir vos conversations. Cette fonctionnalité se compose de trois éléments principaux qui fonctionnent ensemble pour fournir des résultats de recherche complets.

## Démarrage rapide [#quick-start]

Pour commencer avec la recherche web, configurez un fournisseur de recherche et un scraper. La plupart des fournisseurs nécessitent des clés API ; Keenable fonctionne sans clé pour la recherche et la récupération de pages, avec une clé optionnelle pour augmenter ses limites de débit public. Le reranking peut utiliser Jina ou Cohere, ou être désactivé avec `rerankerType: "none"`. Vous pouvez configurer la pile de deux manières :

<Callout type="warning" title="Endpoints privés auto-hébergés">
  Les connexions de recherche web, de scraping et de reranking bloquent par défaut les destinations privées, de bouclage (loopback), locales (link-local) et les métadonnées cloud. Si SearXNG, Firecrawl, Jina ou un autre endpoint de fournisseur configuré est privé, ajoutez son hôte et son port exacts à [`webSearch.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers).
</Callout>

1. **Variables d'environnement** (Recommandé pour les administrateurs) :
   ```bash
   # Search Provider (choose one)
   SERPER_API_KEY=your_serper_api_key
   # or
   SEARXNG_INSTANCE_URL=your_searxng_instance_url
   SEARXNG_API_KEY=your_searxng_api_key  # Optional
   # or
   TAVILY_API_KEY=your_tavily_api_key
   # or use Keenable keyless; this optional key raises public rate limits
   KEENABLE_API_KEY=your_keenable_api_key

   # Scraper (choose one)
   FIRECRAWL_API_KEY=your_firecrawl_api_key
   # Optional: Custom Firecrawl API URL
   FIRECRAWL_API_URL=your_firecrawl_api_url
   # Optional: Firecrawl API version (v0 or v1)
   # FIRECRAWL_VERSION=v1
   # or
   TAVILY_API_KEY=your_tavily_api_key
   # or use Keenable keyless with the same optional key

   # Reranker (Optional - choose one, or set rerankerType: "none")
   JINA_API_KEY=your_jina_api_key
   # Optional: Custom Jina API URL
   JINA_API_URL=your_jina_api_url
   # or
   COHERE_API_KEY=your_cohere_api_key
   ```

   L'utilisation de Keenable sans clé d'environnement nécessite tout de même une sélection de fournisseur dans `librechat.yaml` :

   ```yaml filename="librechat.yaml"
   webSearch:
     searchProvider: keenable
     scraperProvider: keenable
     rerankerType: none
   ```

   Consultez la [configuration Keenable complète](/docs/configuration/librechat_yaml/object_structure/web_search#keenablescraperoptions) pour les paramètres optionnels de recherche, de récupération et de limitation de débit.

2. **Interface utilisateur** (Si les variables d'environnement ne sont pas définies) :
   - Les utilisateurs seront invités à saisir les clés API requises lors de leur première utilisation de la fonctionnalité de recherche web.
   - Ils peuvent choisir quel fournisseur de recherche (Serper, SearXNG, Tavily ou Keenable), quel scraper et quel service de reranking (Jina, Cohere ou aucun) utiliser.

Les URL Firecrawl et SearXNG fournies par l'utilisateur ne peuvent pas être associées à la clé API du déploiement. Fournissez votre propre paire URL/clé, ou demandez à un administrateur de configurer les deux. Sinon, Firecrawl ignore l'URL utilisateur optionnelle et utilise son endpoint par défaut ; SearXNG ne peut pas initialiser cette configuration à propriété mixte car son URL est requise. SearXNG sans clé reste pris en charge. Voir [Credential Ownership](/docs/configuration/librechat_yaml/object_structure/web_search#credential-ownership).

## Obtention des clés API [#obtaining-api-keys]

Chaque service externe activé nécessite sa propre clé API. Voici comment les obtenir :

### Fournisseurs de recherche [#search-providers]

#### Serper [#serper]
1. Visitez [Serper.dev](https://serper.dev)
2. Créer un compte
3. Accédez à la section API Key
4. Copiez votre clé API
5. Définissez-le dans vos variables d'environnement ou fournissez-le via l'interface utilisateur

#### SearXNG [#searxng]
1. Suivez les instructions de configuration dans la documentation [Web Search Configuration](/docs/configuration/librechat_yaml/object_structure/web_search#setting-up-searxng)
2. Définissez `SEARXNG_INSTANCE_URL` sur l'URL de votre instance
3. Définissez éventuellement `SEARXNG_API_KEY` si votre instance nécessite une authentification
4. Ajoutez le `host:port` exact de votre instance à [`allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) s'il se trouve sur une adresse privée ou de bouclage (loopback), sinon LibreChat bloquera la connexion.
5. Vous pouvez éventuellement ajuster les moteurs que votre instance interroge avec [`searxngSearchOptions`](/docs/configuration/librechat_yaml/object_structure/web_search#searxngsearchoptions). L'ensemble par défaut ne comprend que trois moteurs et inclut DuckDuckGo, qui envoie des CAPTCHA à la plupart des instances auto-hébergées ; élargir cette sélection aide donc si les recherches ne renvoient aucun résultat.

#### Tavily [#tavily]
1. Visitez [Tavily](https://app.tavily.com/home)
2. Créer un compte
3. Copiez votre clé API
4. Définissez `TAVILY_API_KEY` dans vos variables d'environnement ou fournissez-la via l'interface utilisateur
5. Tavily peut être utilisé à la fois comme fournisseur de recherche et comme fournisseur de scraping.

#### Keenable [#keenable]

1. Sélectionnez Keenable comme fournisseur de recherche, scraper, ou les deux
2. Aucune clé API n'est requise pour les endpoints de recherche et de récupération publics.
3. Optionnellement, définissez `KEENABLE_API_KEY` pour augmenter les limites de débit publiques.
4. Utilisez `KEENABLE_API_URL` uniquement pour remplacer l'endpoint de recherche et `KEENABLE_FETCH_URL` uniquement pour remplacer l'endpoint de récupération de page.

### Scraper : Firecrawl [#scraper-firecrawl]

1. Visitez [Firecrawl.dev](https://docs.firecrawl.dev/introduction#api-key)
2. Créer un compte
3. Accédez à la section API Key
4. Copiez votre clé API
5. Définissez-le dans vos variables d'environnement ou fournissez-le via l'interface utilisateur
6. (Facultatif) Si vous utilisez une instance Firecrawl personnalisée, vous devrez également définir l'URL de l'API

### Rerankers [#rerankers]

#### Jina [#jina]
1. Visitez [Jina.ai](https://jina.ai/api-dashboard/)
2. Créer un compte
3. Accédez au tableau de bord de l'API
4. Copiez votre clé API
5. Définissez-le dans vos variables d'environnement ou fournissez-le via l'interface utilisateur

#### Cohere [#cohere]
1. Visitez le [Cohere Dashboard](https://dashboard.cohere.com/welcome/login)
2. Créer un compte
3. Accédez à la section API Keys
4. Copiez votre clé API
5. Définissez-le dans vos variables d'environnement ou fournissez-le via l'interface utilisateur

## Composants [#components]

### 1. Fournisseurs de recherche [#1-search-providers]

Les fournisseurs de recherche sont responsables d'effectuer la recherche web initiale et de renvoyer les résultats pertinents.

**Fournisseurs disponibles :**
- **Serper** : Une API de recherche Google qui fournit des résultats de recherche de haute qualité
  - Obtenez votre clé API sur [Serper.dev](https://serper.dev/api-keys)
- **SearXNG** : Méta-moteur de recherche open-source et auto-hébergé
  - Auto-hébergez votre propre instance
  - Résultats de recherche axés sur la confidentialité
  - Moteurs configurables, langue des résultats, plage temporelle et délai d'expiration de la requête
- **Tavily** : API de recherche optimisée pour l'IA
  - Obtenez votre clé API depuis [Tavily](https://app.tavily.com/home)
  - Prend en charge une profondeur de recherche configurable, le filtrage par sujet, le filtrage par domaine, et plus encore.
  - Peut également servir de fournisseur de scraper
- **Keenable** : Recherche web sans clé avec authentification à haut débit optionnelle
  - Prend en charge la recherche restreinte par domaine, les limites de résultats, les titres d'attribution et les délais d'expiration des requêtes
  - Peut également servir de fournisseur de scraper

### 2. Scrapers [#2-scrapers]

Les scrapers extraient le contenu réel des pages web renvoyées par le fournisseur de recherche.

**Scrapers disponibles :**
- **Firecrawl** : Un service de web scraping puissant qui extrait le contenu des pages web
  - Obtenez votre clé API sur [Firecrawl.dev](https://docs.firecrawl.dev/introduction#api-key)
  - L'URL de l'API est facultative (par défaut, il s'agit du service hébergé de Firecrawl)

- **Tavily** : Extraction d'URL par lots via l'API Tavily Extract
  - Utilise la même `TAVILY_API_KEY` que le fournisseur de recherche
  - Prend en charge la profondeur d'extraction configurable, l'extraction d'images et l'extraction de favicon

- **Keenable** : Récupération de page sans clé
  - Utilise la même clé API optionnelle que la recherche Keenable
  - Prend en charge les titres d'attribution et les délais d'expiration des requêtes

**Scrapers prévus :**
- **Local Firecrawl** : Version auto-hébergée de Firecrawl
- Services de scraping tiers supplémentaires

### 3. Rerankers [#3-rerankers]

Les Rerankers analysent le contenu extrait pour déterminer les parties les plus pertinentes et les réorganiser afin d'obtenir de meilleurs résultats.

**Rerankers disponibles :**
- **Jina** : service de reranking alimenté par l'IA
  - Obtenez votre clé API sur [Jina.ai](https://jina.ai/api-dashboard/)
  - L'URL de l'API est facultative (par défaut, il s'agit du service hébergé de Jina)
- **Cohere** : Service de reranking avancé
  - Obtenez votre clé API depuis le [Cohere Dashboard](https://dashboard.cohere.com/welcome/login)
- **None** : Ignore le reranking lorsque `rerankerType` est défini sur `"none"`

**Rerankers prévus :**
- **RAG API** : Reranking open-source utilisant RAG (Retrieval-Augmented Generation)
- Services de reranking tiers supplémentaires

## Configuration [#configuration]

### Configuration administrateur [#admin-configuration]

Les administrateurs peuvent configurer la fonctionnalité de recherche web à l'aide de variables d'environnement. La configuration YAML vous permet de spécifier des noms de variables d'environnement personnalisés pour chaque composant.

⚠️ **Important : Ne mettez jamais de clés API ou de valeurs réelles dans le fichier YAML (elles ne fonctionneront pas) - utilisez uniquement les noms des variables d'environnement.**

```yaml
webSearch:
  # Search Provider Configuration
  serperApiKey: "${CUSTOM_SERPER_API_KEY}"  # ✅ Correct: Using environment variable name
  # serperApiKey: "sk-123..."               # ❌ Wrong: Never put actual API keys here
  # or
  searxngInstanceUrl: "${CUSTOM_SEARXNG_INSTANCE_URL}"  # ✅ Correct: Using environment variable name
  searxngApiKey: "${CUSTOM_SEARXNG_API_KEY}"            # ✅ Correct: Using environment variable name
  # searxngInstanceUrl: "http://..."        # ❌ Wrong: Never put actual URLs here
  # searxngApiKey: "sk-123..."              # ❌ Wrong: Never put actual API keys here
  searxngSearchOptions:                     # Query options, not secrets, so real values belong here
    engines: "google,bing,startpage"
    language: "en"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${CUSTOM_TAVILY_API_KEY}"
  tavilySearchUrl: "${CUSTOM_TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${CUSTOM_TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; keyless by default)
  keenableApiKey: "${CUSTOM_KEENABLE_API_KEY}" # Optional; raises rate limits
  keenableApiUrl: "${CUSTOM_KEENABLE_API_URL}" # Optional search URL override
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${CUSTOM_FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${CUSTOM_FIRECRAWL_API_URL}"
  # firecrawlApiKey: "fc-123..."            # ❌ Wrong: Never put actual API keys here
  # firecrawlApiUrl: "https://..."          # ❌ Wrong: Never put actual URLs here

  # Reranker Configuration
  jinaApiKey: "${CUSTOM_JINA_API_KEY}"
  jinaApiUrl: "${CUSTOM_JINA_API_URL}"
  cohereApiKey: "${CUSTOM_COHERE_API_KEY}"
  # jinaApiKey: "jn-123..."                 # ❌ Wrong: Never put actual API keys here
  # jinaApiUrl: "https://..."               # ❌ Wrong: Never put actual URLs here
  # cohereApiKey: "ch-123..."               # ❌ Wrong: Never put actual API keys here

  # General Settings
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
```

**Note :** La configuration YAML ne doit contenir que des noms de variables d'environnement (au format `${VARIABLE_NAME}`). Cette flexibilité permet :
- Utilisation de noms de variables différents dans des environnements différents
- Prise en charge de plusieurs configurations pour différents groupes d'utilisateurs
- Intégration future avec des configurations basées sur les rôles

Si vous souhaitez restreindre le système à l'utilisation de services spécifiques uniquement, vous pouvez spécifier les types de services :

```yaml
webSearch:
  # ... variable configurations ...
  searchProvider: "serper"    # Only use Serper for search
  # searchProvider: "searxng" # Only use SearXNG for search
  # searchProvider: "tavily"  # Only use Tavily for search
  # searchProvider: "keenable" # Use keyless Keenable search
  scraperProvider: "firecrawl"    # Only use Firecrawl for scraping
  # scraperProvider: "tavily" # Only use Tavily for scraping
  # scraperProvider: "keenable" # Use keyless Keenable page fetch
  rerankerType: "jina"        # Options: "jina", "cohere", "none"
```

### Configuration utilisateur [#user-configuration]

Si l'administrateur n'a pas configuré toutes les clés API nécessaires, les utilisateurs seront invités à les fournir via l'interface utilisateur. L'interface permet aux utilisateurs de :

1. Choisissez leur reranker préféré (Jina, Cohere, ou aucun)
2. Saisissez les clés API pour les services requis
3. Configurez l'URL de l'API Firecrawl si nécessaire (optionnel)
4. Configurez l'URL de l'API Jina si nécessaire (optionnel)
5. Configurez les remplacements d'endpoint Tavily ou Keenable si nécessaire (optionnel)

## Utilisation [#usage]

Une fois configuré, vous pouvez utiliser la recherche web de deux manières :

1. **Interface de chat** : Ouvrez la palette **+** dans le [compositeur de messages](/docs/features/composer) et sélectionnez **Web Search** pour l'activer pour la conversation. Il apparaît ensuite sous forme de puce sur le compositeur ; supprimez la puce pour le désactiver. Si des clés API requises sont manquantes, vous serez invité à les saisir.
2. **Agents** : Activez la fonctionnalité **Web Search** [capability](/docs/features/agents#agent-capabilities) pour un agent dans l'Agent Builder afin que l'agent puisse effectuer des recherches sur le web.

### L'option de recherche Web n'est pas visible [#web-search-option-is-not-visible]

Il n'y a pas de bouton de recherche web séparé. L'option se trouve dans la section **Tools** de la palette **+** et n'apparaît que lorsque toutes les conditions suivantes sont remplies :

- L'endpoint sélectionné n'est ni Agents ni Assistants. Les Agents possèdent leur propre configuration d'outils ; pour un agent, vous devez donc activer la recherche Web directement dans le constructeur d'agent (Agent Builder).
- `web_search` est inclus dans [`endpoints.agents.capabilities`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities). Il est inclus par défaut, donc cela n'a d'importance que si vous définissez une liste personnalisée.
- Le rôle de l'utilisateur dispose de l'autorisation de recherche web. Gérez-la dans le [Panneau d'administration](/docs/features/admin_panel) ; [`interface.webSearch`](/docs/configuration/librechat_yaml/object_structure/interface#websearch) ne l'initialise que pour le rôle `USER` par défaut au démarrage.
- La spécification de modèle sélectionnée ne définit pas [`hideBadgeRow: true`](/docs/configuration/librechat_yaml/object_structure/model_specs#hidebadgerow), ce qui masque la section **Outils**.

## Notes [#notes]

- La configuration du fournisseur de recherche et du scraper est requise ; le reranking peut être désactivé avec `rerankerType: "none"`
- L'URL de l'API Firecrawl est facultative et utilise par défaut leur service hébergé.
- L'URL de l'API Jina est facultative et utilise par défaut leur service hébergé.
- Les URLs de l'API Tavily Search and Extract sont facultatives et utilisent par défaut les services hébergés de Tavily.
- La recherche et la récupération de pages sont sans clé par défaut ; une clé optionnelle permet d'augmenter les limites de débit public.
- `KEENABLE_API_URL` remplace uniquement la recherche, tandis que `KEENABLE_FETCH_URL` remplace uniquement la récupération de page
- Associez `searchProvider: "keenable"`, `scraperProvider: "keenable"` et `rerankerType: "none"` pour une pile entièrement sans clé.
- La recherche sécurisée (Safe search) propose trois niveaux de filtrage de contenu : OFF (0), MODERATE (1 - par défaut) et STRICT (2)
- Tavily n'hérite pas du paramètre global `safeSearch` par défaut ; utilisez `tavilySearchOptions.safeSearch` uniquement si votre compte Tavily prend en charge `safe_search`.
- Le délai d'expiration du scraper est défini par défaut sur 7,5 secondes (7500ms).
- Les clés API peuvent être révoquées à tout moment via l'interface utilisateur.
- Les futures mises à jour incluront davantage d'options open-source et auto-hébergées pour tous les composants
- D'autres options de personnalisation sont prévues, notamment :
  - Contrôle sur le nombre de liens à scraper
  - Liste blanche/liste noire de domaines pour le scraping
  - Règles de scraping et filtres personnalisés
  - Options avancées de filtrage et de classement des résultats
  - Contrôles de limitation de débit et de régulation des requêtes
