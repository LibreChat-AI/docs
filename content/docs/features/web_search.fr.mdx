La recherche sur le web donne au modèle un outil `web_search`. Lorsqu'une question nécessite des informations actuelles, le modèle rédige une requête, LibreChat récupère les résultats, lit les pages les plus pertinentes, puis la réponse est renvoyée avec les sources utilisées.

## Activez-le dans une conversation [#turn-it-on-in-a-chat]

Cliquez sur **+** dans le [compositeur de messages](/docs/features/composer) pour ouvrir la palette, puis sélectionnez **Web Search** dans la section **Tools**. Il apparaît sous forme de puce sur le compositeur lorsqu'il est activé ; retirez la puce, ou sélectionnez-le à nouveau dans la palette, pour le désactiver. Vous pouvez l'épingler afin que la puce reste sur le compositeur même lorsqu'il est désactivé.

Avec la recherche web activée, le modèle décide toujours lui-même si un message nécessite une recherche. Poser la question « quelles sont les nouveautés de la dernière version de Node.js ? » déclenchera généralement une recherche ; demander de réécrire un paragraphe n'en déclenchera pas.

Pour les agents, la recherche web est une fonctionnalité que vous activez dans le constructeur d'agents. Toute personne qui discute avec cet agent dispose de l'outil sans avoir à l'activer manuellement.

## Ce que vous voyez dans la réponse [#what-you-see-in-the-answer]

Pendant que l'outil s'exécute, le message affiche sa progression (« Recherche sur le Web », puis « Lecture des résultats »). Une fois l'opération terminée, il se réduit à **Recherche sur le Web effectuée** ; développez-le pour voir les pages trouvées, ou utilisez le bouton **Détails de la recherche** à côté pour voir la requête envoyée par le modèle.

Les citations en ligne dans le texte renvoient à ces pages, ce qui vous permet de vérifier une affirmation par rapport à la page dont elle provient. Lorsque plusieurs agents répondent côte à côte, une ligne **Sources** au-dessus des réponses regroupe également les résultats, avec l'onglet **All**, ainsi que les onglets **News** et **Images** lorsque la recherche les a renvoyés.

## Comment se déroule une recherche [#how-a-search-runs]

Chaque recherche passe par jusqu'à trois services :

- Un fournisseur de recherche renvoie une liste de résultats : Serper, SearXNG, Tavily ou Keenable.
- Un scraper récupère les pages derrière ces résultats et en extrait le texte : Firecrawl, Serper Scrape, Tavily Extract ou Keenable Fetch.
- Un reranker (Jina ou Cohere) sélectionne les passages les plus pertinents pour la requête. Le reranking peut être défini sur **None** pour ignorer cette étape.

Seuls les passages extraits sont transmis au modèle, et non les pages entières. Les pages qui expirent ou qui bloquent le scraping sont ignorées, de sorte qu'une réponse peut citer moins de sources que n'en a renvoyées la recherche.

La recherche sécurisée est réglée sur modérée par défaut. Votre administrateur peut augmenter ou diminuer le niveau pour tous les utilisateurs ; Tavily fait exception et ne filtre que lorsque l'administrateur active son option de recherche sécurisée propre.

## Ajouter vos propres clés API [#adding-your-own-api-keys]

Si votre administrateur n'a pas fourni de clés pour chaque service, l'activation de **Recherche Web** ouvre une boîte de dialogue vous les demandant. Elle comporte une section pour chaque service que l'administrateur a laissé aux utilisateurs, parmi **Fournisseur de recherche**, **Scraper** et **Reranker**. Choisissez un service dans chacune, renseignez les clés (chaque champ renvoie vers la page où en obtenir une), puis cliquez sur **Enregistrer**. SearXNG demande l'URL de votre instance, et sa clé est facultative. Keenable fonctionne sans clé ; en ajouter une augmente seulement ses limites de débit.

Les clés sont stockées avec votre compte et utilisées uniquement pour vos recherches. Pour changer de fournisseur ou remplacer une clé plus tard, ouvrez la palette et cliquez sur **Configure** (l'icône d'engrenage) sur la ligne **Web Search**. Une fois vos clés enregistrées, **Revoke** dans la même boîte de dialogue les supprime. Lorsque l'administrateur a défini toutes les clés sur le serveur, il n'y a ni boîte de dialogue ni icône d'engrenage.

Une URL que vous saisissez n'est jamais associée à une clé définie par l'administrateur sur le serveur. Si l'administrateur a défini une clé Firecrawl ou SearXNG et que vous saisissez votre propre URL pour ce service, saisissez également votre propre clé. Sinon, Firecrawl ignore votre URL et utilise son point de terminaison par défaut, et SearXNG ne fonctionne pas. Une instance SearXNG sans clé fonctionne toujours : lorsqu'aucune clé n'est impliquée, votre URL seule suffit.

## L'option de recherche Web n'est pas visible [#web-search-option-is-not-visible]

Il n'existe pas de bouton de recherche web distinct ; l'option n'apparaît que dans la section **Tools** de la palette. Elle est absente lorsque :

- Vous discutez avec un agent, ou sur le point de terminaison Assistants. Les agents disposent de leurs propres outils, donc la recherche web s'active plutôt dans le Constructeur d'agents.
- Le spec de modèle sélectionné masque la ligne des outils.
- Votre rôle ne dispose pas de l'autorisation Recherche Web. Cela bloque également la recherche intégrée proposée par certains fournisseurs.
- Votre administrateur a retiré `web_search` des capacités de l'agent.

## Configuration [#setup]

La recherche Web est disponible par défaut pour les agents et les conversations, mais elle nécessite un fournisseur de recherche et un scraper avant de renvoyer quoi que ce soit. Un administrateur définit soit les clés sur le serveur, soit laisse les utilisateurs les saisir. Les fournisseurs auto-hébergés sur une adresse privée sont bloqués tant que l'administrateur ne les a pas listés dans [`allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers). Consultez [Configuration de la recherche Web](/docs/configuration/librechat_yaml/object_structure/web_search) pour les fournisseurs, les clés et les options, et [Installation de SearXNG](/docs/configuration/librechat_yaml/object_structure/web_search#setting-up-searxng) pour auto-héberger le fournisseur de recherche.
