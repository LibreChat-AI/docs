MCP (Model Context Protocol) は、ツールをモデルに公開するためのオープンな標準です。MCPサーバーは、モデルにファイルシステム、ブラウザ、データベース、または社内APIへのアクセスを提供できます。LibreChatは、このプロトコルに対応する任意のサーバーを利用できます。通常のチャットにサーバーを添付して手早く使うことも、そのツールをエージェントに追加することもできます。

## チャットでサーバーを使用する [#use-a-server-in-chat]

Agents または Assistants 以外のエンドポイントでは、コンポーザーの **+** パレット(**Attach and tools**)を開き、**MCP Servers** を確認してください。サーバーをクリックすると、その会話でオンになります。コンポーザーにチップとして表示され、そのサーバーが提供するすべてのツールがモデルで利用可能になります。パレットは開いたままなので、複数のサーバーをまとめてオンにできます。サーバーを再度クリックするか、そのチップを削除すると、オフになります。パレットのその他の項目については、[Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) を参照してください。

パレットには一度に数台のサーバーが表示され、各サーバーの状態を示す色付きのドットが付いています。**MCP Servers** ヘッダーの **Show All** をクリックすると、検索フィールドと 3 つのビュー(**All**、**Made by you**、**Favorites**)を備えた全件リストが開きます。

![MCP Servers ダイアログが Show All で開かれ、Github サーバーは Disconnected、Spotify サーバーは Needs Auth と表示されている。All、Made by you、Favorites のフィルターがある](/images/mcp/mcp_servers_catalog.png)

サーバーがまだ接続されていない場合、クリックすると選択されるのではなく、接続が開始されます。ユーザー自身の認証情報が必要なサーバーでは、まず認証情報を入力するためのダイアログが開きます。OAuth を使用するサーバーでは、サインインの画面に移動します。接続が完了すると、LibreChat がそのサーバーを自動的に選択します。

ツール呼び出しに対応したモデルを選んでください。対応していないモデルでは、サーバーのツールが呼び出されることはありません。エージェントとAssistantsは独自のツール設定を持つため、それらのエンドポイントではモデル選択肢は表示されません。また、管理者はチャットから個々のサーバーを非表示にすることができ、その場合そのサーバーはエージェントでのみ利用可能になります。

## エージェントにサーバーを追加する [#add-a-server-to-an-agent]

Agent Builderで、**Tools**の横にある**Add**をクリックして**Tool Library**を開き、**MCP servers**でフィルタリングします。サーバーを追加すると、そのサーバーが公開しているツールが一覧表示されます。エージェントに持たせたいツールは残し、それ以外は削除してください。または**Select all**と**Deselect all**を使用することもできます。ツールが数十個あるサーバーでも、エージェントのツール一覧には1つのエントリとして表示されます。

各 MCP ツールは、エージェント上で独自のオプション（**Defer loading**、**Programmatic**、**Background**、**Intent label**）も持っています。それぞれの変更内容については、[Agents](/docs/features/agents) を参照してください。

一部のサーバーは、チャットリクエストの最中にしか存在しない値に依存しているため、事前にツールを一覧表示することができません。そのようなサーバーについては、ツールライブラリがサーバー全体を添付し、そのツールはチャット中の実行時に解決されることを明記します。

MCP ツールを使用するように設定されたエージェントで、実行開始時にそれらのツールが一つも利用できない場合（サーバーがダウンしている、またはアクセス権を失った場合）、ツールなしで回答するのではなく、接続とアクセス権を確認するよう求めるエラーを表示して実行が停止します。ツール呼び出し中に **Stop** を押すと、MCP サーバーがキャンセルに対応していれば、そのサーバー側の呼び出しもキャンセルされます。

## 接続ステータス [#connection-status]

パレットと**MCP設定**では、ステータスは色付きのドットで表示されます。サーバーが切断されている場合はグレー、サインインが必要な場合はアンバーになります。完全なステータスはスクリーンリーダーで読み上げられ、ツールライブラリと**Show All**リストでは、各サーバーの横にステータスが文字で表示されます。

- **接続済み**: 使用可能です。
- **Needs Auth**: サーバーはOAuthを使用しており、サインインしていないか、サインインの有効期限が切れています。
- **接続中** / **初期化中**: 接続試行が進行中です。
- **切断**または**エラー**: 有効な接続がないか、直前の接続試行が失敗しました。**接続**をクリックして再試行してください。
- **オンデマンド**: サーバーはリクエストごとに個別に接続するため、報告すべき常時接続はありません。
- **不明**: まだステータスが返されていません。

接続に失敗すると、エラーに理由が表示されます。サーバーに到達できなかった、設定されていない変数が必要である（メッセージに変数名が示されます）、または再度サインインが必要である、のいずれかです。原因を解消してから再度接続してください。サーバーを削除して追加し直す必要はありません。また、サーバーは実行中にツールを追加または削除することがあり、その場合 LibreChat は再起動なしで新しいツール一覧を取得します。

接続はユーザーごとに管理されます。OAuthトークンと保存された認証情報が他のユーザーに使用されることはありません。アイドル状態の接続は、デフォルトで15分後に閉じられ、次回そのサーバーを使用する際に再度開かれます。

## OAuth でサインイン [#sign-in-with-oauth]

サーバーで OAuth が必要な場合、接続すると **Connect** ダイアログが開きます。**Continue with OAuth** をクリックすると、プロバイダーのサインインページが新しいタブで開きます。別のデバイスで完了したい場合は、**Copy link** または **Show QR Code** を使用してください。アクセスを承認すると、タブに **Authentication Successful** と表示されて自動的に閉じ、サーバーの状態が **Connected** に切り替わります。

サインインの処理中は、サーバーにスピナーが表示されます。カーソルを合わせるとキャンセルできます。エージェントビルダーの MCP サーバー設定では、同じ目的で **Connect** が **Cancel** に変わります。サインインを完了するまでの制限時間は 10 分です(この時間は管理者が変更できます)。

プロバイダーがリフレッシュトークンを発行する場合、LibreChat はバックグラウンドでアクセス権を更新します。セッション中にサーバーがトークンを拒否した場合は、まず一度リフレッシュと再接続を試み、それでも失敗した場合にのみ再度サインインを求めます。リフレッシュトークンを発行しないプロバイダーでは、トークンの有効期限が切れると再度サインインするよう求められます。

デフォルトでは、サインインのプロンプトはメッセージを送信したときに表示されます。管理者は一部のサーバーを、エージェントが初めてそのツールを呼び出すまで待機するように設定できます。そのため、サーバーが実際に必要になったときにのみサインインを求められます。

## 認証情報と変数 [#credentials-and-variables]

一部のサーバーでは、個人の API キーやプロジェクト ID などの値を各ユーザーごとに必要とします。このようなサーバーに接続する際、LibreChat は接続前にその値の入力を求めます。後から値を変更するには、チャットピッカーまたは **MCP Settings** にあるサーバーの **Configure** を使用してください。各フィールドには **Save** と **Revoke** があります。どちらを使用しても、そのサーバーへの現在の接続は閉じられるため、次回の利用時には新しい値で接続されます。また、**Revoke** を使用すると、現在のチャットでそのサーバーもオフになります。

値はユーザーごとに保存され、入力されたサーバーにのみ送信されます。

## MCP設定パネル [#mcp-settings-panel]

**MCP設定**はサイドパネルに表示され、利用可能なすべてのサーバーを一覧表示します。各サーバーのアイコンには状態を示すステータスドットが付いています。サーバーの状態に応じて、各カードには**接続**、**再接続**、**設定**(ご自身の変数を設定)、または**取り消し**(OAuthトークンを削除)のいずれかが表示されます。編集が許可されているサーバーには**編集**もあります。

## UIからサーバーを作成する [#create-a-server-from-the-ui]

もしお使いの役割で許可されている場合、**MCP Settings**の**Add MCP**(**+**ボタン)をクリックすると、`librechat.yaml`を編集したり再起動したりすることなく、リモートサーバーを登録できます。

<Steps>
<Step>
### サーバーを説明する [#describe-the-server]

必要に応じて**名前**、任意で**説明**、そしてお好みでアイコンを入力してください。**MCP Server URL**を入力し、**トランスポート**を選択します:**Streamable HTTPS**または**SSE**。
</Step>
<Step>
### 認証方式を選択する [#choose-authentication]

**認証**で、次のいずれかを選択してください:

- **None (Auto-detect)**: LibreChat がサーバーを検出し、サーバーが要求した場合に OAuth に切り替えます。
- **API Key**: 共有キーを1つ入力するか、**Each user provides their own key** にチェックを入れると、各ユーザーが **Configure** から自分のキーを入力します。**Header Format** を選択します: **Bearer**、**Basic**、または独自のヘッダー名を指定する **Custom** です。
- **OAuth**：**Client ID**、**Client Secret**、**Authorization URL**、**Token URL**、**Scope** を入力します。プロバイダーが動的クライアント登録に対応している場合は、クライアントに関するフィールドを空欄のままにしてください。**Token Exchange Method** のデフォルトは **Auto** で、プロバイダーが公開している方式を使用し、利用できない場合は Basic 認証ヘッダーにフォールバックします。方式を固定したい場合は、**Default (POST request)** または **Basic authorization header** を選択してください。
- **On-Behalf-Of (OBO)**: 管理者から権限が付与されている場合にのみ表示され、LibreChat が OpenID Connect（例: Entra ID）でユーザーのサインインを行っている場合にのみ動作します。要求するスコープを入力してください。LibreChat は、お使いの OpenID トークンを MCP サーバー向けのスコープ付きトークンに交換します。
</Step>
<Step>
### 作成する [#create-it]

**I trust this application** にチェックを入れ、**Create** をクリックしてください。サーバーはすぐに利用可能になります。OAuth サーバーの場合は、次のダイアログに OAuth プロバイダーへ登録するための **Redirect URI** が表示されます。一度サインインするまで、サーバーは切断された状態のままです。
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="「Add MCP Server」ダイアログで、名前とURLを入力し、Transportを「Streamable HTTPS」に設定、Authenticationを「API Key」に設定し、「Each user provides their own key」にチェックが入っている状態"
/>

このように作成されたサーバーは、リモートURLにしか接続できません。ローカルの `stdio` サーバーは `librechat.yaml` で定義する必要があります。また、サーバーの環境変数やユーザープロフィールのプレースホルダーを使用することはできません。ヘッダーに含まれる `${API_TOKEN}` や `{{LIBRECHAT_USER_EMAIL}}` のような値は、共有サーバーに渡ってしまうのを防ぐため削除されます。後からサーバーのURLや認証方式を変更した場合、自分のキーを入力していたユーザーは再度入力する必要があり、OAuthを使用しているユーザーは再度サインインする必要があります。保存済みのクライアントシークレットがあるサーバーのURLやOAuthエンドポイントを変更する場合は、シークレットも再入力する必要があります。古いバージョンで作成されたAPIキーサーバーが **Needs Auth** の状態のまま止まっている場合は、**Edit** で開いて一度保存してください。

## サーバーを共有する [#share-a-server]

UI で作成されたサーバーは、作成したユーザーに所有されます。所有者は **Edit** ダイアログから、特定のユーザー、グループ、ロール、または全員とサーバーを共有でき、その際に閲覧者（表示および利用が可能）、編集者（さらに変更も可能）、または所有者として権限を設定できます。`librechat.yaml` で定義されたサーバーは、MCP を利用する権限を持つすべてのユーザーが利用できます。権限レベルがどのように組み合わさるかについては、[Access Control](/docs/features/access_control) を参照してください。

## サーバーの手順 [#server-instructions]

管理者はサーバーに指示（instructions）を添付できます。サーバー独自の指示でも、カスタムテキストでも構いません。会話やエージェントがそのサーバーのツールを持っている場合、これらの指示がモデルのコンテキストに追加されます。これは、特定の順序で使用して初めて意味をなすツールを持つサーバーにおいて役立ちます。

## MCP Apps [#mcp-apps]

一部のサーバーは、ツールの結果とともにインタラクティブなビューを返します。MCP Apps が有効になっている場合、ツール呼び出しには **Open app** ボタンが表示され、クリックするとサンドボックス化されたフレーム内にビューが読み込まれます。**Close app** を押すと、ビューは再び非表示になります。同時に開けるアプリは数に限りがあります。上限に達した場合は、先にいずれかのアプリを閉じてください。

アプリは単独で動作することはできません。アプリがツールを実行しようとすると **Run tool from app?** と表示され、メッセージを投稿しようとすると **Send message from app?** と表示されます。承認するまで何も実行されません。メッセージを送信すると現在の会話でモデルの応答が開始されるため、選択されたエージェントとそのツールが使用される場合があります。アプリは共有会話ではレンダリングされません。

## セットアップ [#setup]

MCPには少なくとも1つのサーバーが必要です。管理者は`librechat.yaml`の`mcpServers`の下でサーバーを定義します。この変更を適用するには再起動が必要です。また、権限を持つユーザーは**MCP Settings**からリモートサーバーを追加できます。サーバーのオプション、OAuthコールバックURL、トランスポートについては[MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers)を、許可されたドメインやMCP Appsについては[MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings)を、アプリの制限については[MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox)を、サーバーの利用・作成・共有を許可するユーザーについては[`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)を参照してください。特定のサーバーのセットアップガイドは[MCP Servers](/docs/mcp_servers)にあり、MCPサーバーをスキルとバンドルする方法については[Agent Plugins](/docs/features/agent_plugins)で説明しています。
