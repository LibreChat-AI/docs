Le contrôle d'accès détermine trois choses : quelles fonctionnalités un utilisateur peut utiliser, qui peut voir ou modifier un agent, un prompt, un serveur MCP ou une compétence spécifique partagé par quelqu'un, et qui dispose de pouvoirs d'administration. Une petite équipe peut conserver les paramètres par défaut et partager librement ; un déploiement plus important peut restreindre les fonctionnalités par rôle, partager avec des groupes synchronisés depuis Entra ID, et déléguer une partie de l'administration sans attribuer de comptes administrateur complets.

## Utilisateurs, groupes, rôles et tout le monde [#users-groups-roles-and-everyone]

Les permissions sont accordées à quatre types de principaux :

- Un utilisateur, c'est-à-dire un compte LibreChat.
- Un groupe d'utilisateurs. Les groupes sont créés par les administrateurs ou synchronisés depuis Entra ID lorsque les utilisateurs se connectent via Entra avec la réutilisation des jetons OpenID activée. Le partage avec un groupe ne nécessite qu'une seule entrée, et les modifications d'appartenance dans Entra prennent effet à la prochaine connexion de chaque membre.
- Un rôle. Chaque utilisateur possède exactement un rôle : `USER` par défaut, `ADMIN` pour le premier compte sur une instance mono-locataire, ou un rôle personnalisé créé par un administrateur. Le partage avec un rôle atteint tous les utilisateurs qui détiennent actuellement ce rôle.
- Tout le monde, c'est-à-dire chaque utilisateur connecté à l'instance.

## Autorisations des fonctionnalités [#feature-permissions]

Chaque rôle comporte un ensemble d'interrupteurs activé/désactivé pour chaque fonctionnalité : déterminer si ses utilisateurs peuvent utiliser des agents, en créer, les partager avec des personnes spécifiques ou les partager avec tout le monde, et de même pour les prompts, les serveurs MCP, les compétences et les liens partagés. D'autres interrupteurs contrôlent les conversations planifiées, les mémoires, les signets, le chat temporaire, les conversations multiples, l'interpréteur de code, la recherche web, la recherche de fichiers, les citations, la Place de marché des agents et le sélecteur de personnes.

Lorsqu'un interrupteur est désactivé, la partie correspondante de l'interface disparaît pour ce rôle. Un utilisateur sans droit de création d'agent ne voit pas l'option permettant de créer un agent ; un utilisateur sans droit de « partager avec tout le monde » n'obtient pas le bouton bascule **Partager avec tout le monde**.

Par défaut, les utilisateurs peuvent utiliser et créer des agents, des prompts, des serveurs MCP et des skills, mais ne peuvent pas les partager ; le partage est une option que l'administrateur doit activer. La liste complète avec les valeurs par défaut se trouve sur la page [Configuration du contrôle d'accès](/docs/configuration/access_control#feature-permissions).

Les administrateurs modifient ces paramètres sans redémarrage. Dans LibreChat, les panneaux des agents, des prompts, des serveurs MCP, des mémoires et des compétences disposent d'un bouton **Paramètres d'administration** qui ouvre les commutateurs de cette fonctionnalité, avec un sélecteur de **Rôle** en haut. Le [Panneau d'administration](/docs/features/admin_panel) modifie les mêmes commutateurs pour chaque rôle, y compris les rôles personnalisés.

## Partager une ressource [#sharing-a-resource]

Les agents, prompts, serveurs MCP, skills et liens partagés conservent chacun leur propre liste de personnes autorisées à y accéder. (Les agents utilisés via l'[API Agents](/docs/features/agents_api) et les environnements de code gérés par le déploiement utilisent les mêmes listes, gérées en dehors de la boîte de dialogue de partage.) La personne qui en a créé un en est le propriétaire et décide qui d'autre peut y accéder.

<Steps>
  <Step>Ouvrez la ressource et cliquez sur son bouton **Partager**. Vous ne le voyez que si vous en êtes le propriétaire (ou si vous détenez le rôle Propriétaire sur celle-ci, ou si vous êtes administrateur) et si votre rôle autorise le partage de ce type de ressource.</Step>
<Step>Dans la boîte de dialogue **Partager**, recherchez des personnes ou des groupes par nom ou adresse e-mail. Les rôles apparaissent aussi dans la recherche, sauf si l'administrateur les a masqués.</Step>
<Step>Choisissez un rôle d'accès pour chaque personne ou groupe ajouté.</Step>
<Step>Si votre rôle le permet, activez **Partager avec tout le monde** et choisissez **Niveau d'autorisation de tout le monde**.</Step>
<Step>Cliquez sur **Enregistrer**.</Step>
</Steps>

Les rôles d'accès sont les mêmes pour chaque type de ressource :

| Rôle d'accès | Ce qu'ils peuvent faire |
| ------------ | ----------------------- |
| Viewer | Trouver et utiliser la ressource, par exemple choisir l'agent et discuter avec lui. Ils ne peuvent pas la modifier. |
| Editor | Tout ce que peut faire un Viewer, plus modifier ses paramètres, ses instructions, ses outils et ses fichiers. |
| Owner | Tout ce que peut faire un Editor, plus la supprimer et modifier les personnes avec qui elle est partagée. |

Les liens partagés ne disposent que des rôles Viewer et Owner. Une ressource doit toujours avoir au moins un propriétaire, c'est pourquoi la boîte de dialogue ne vous permet pas de supprimer le dernier.

Les agents disposent d'une autorisation supplémentaire qui ne fait partie d'aucun de ces rôles : **Voir les analyses**, qui permet à une personne pouvant déjà voir l'agent d'ouvrir ses [Analyses](/docs/features/insights). Seuls les administrateurs voient cette option dans la boîte de dialogue de partage, et elle ne peut pas être accordée à tout le monde.

Avant d'accorder à quelqu'un le rôle d'Éditeur ou de Propriétaire sur un agent, rappelez-vous qu'il voit tout ce qui est configuré dessus, y compris ses instructions et les fichiers joints. Même les Lecteurs peuvent faire ressortir le contenu joint via le chat ; ne joignez donc rien à un agent partagé que son public ne devrait pas pouvoir lire.

## Administrateurs et pouvoirs d'administration délégués [#admins-and-delegated-admin-powers]

Les utilisateurs disposant du rôle `ADMIN` peuvent voir et gérer toutes les ressources de l'instance, et modifier les permissions de fonctionnalités de n'importe quel rôle. Ils disposent également d'un lien **Admin Panel** sous **Settings > General** lorsqu'une URL de panneau d'administration est configurée.

Lorsque vous souhaitez confier une partie de l'administration à quelqu'un sans en faire un administrateur complet, accordez-lui plutôt une capacité, comme la gestion des utilisateurs, la gestion des groupes, la modification de la configuration (dans son ensemble ou d'une seule section, comme `interface`), la consultation des Insights de tous les agents ou la modération de tous les agents, prompts, compétences et liens partagés. Les administrateurs délégués ont également besoin de la capacité `access:admin` pour se connecter au Panneau d'administration. Les capacités peuvent être attribuées à un utilisateur, à un groupe ou à un rôle, et elles s'accordent depuis la page **Grants** du Panneau d'administration. La détention d'une capacité « manage » implique la capacité « read » correspondante.

Les administrateurs peuvent également attribuer à un rôle ou à un groupe sa propre configuration, par exemple des endpoints supplémentaires pour un groupe de recherche, superposés à `librechat.yaml`. Cette opération s'effectue également depuis le Panneau d'administration.

## Configuration [#setup]

Les valeurs par défaut fonctionnent sans aucune configuration : le premier compte est le compte administrateur, et tous les autres peuvent utiliser LibreChat sans pouvoir partager. Pour modifier les valeurs par défaut des fonctionnalités dans `librechat.yaml`, limiter ce qu'affiche le sélecteur de personnes, synchroniser les groupes Entra ID, promouvoir un autre administrateur ou migrer une instance mise à niveau depuis une version antérieure à la v0.8.0-rc3, consultez la [configuration du contrôle d'accès](/docs/configuration/access_control). Les rôles personnalisés, les groupes, les autorisations et la configuration par groupe nécessitent le [Panneau d'administration](/docs/features/admin_panel).
