Code Interpreter uruchamia kod w izolowanym środowisku sandbox. Agenci używają go do wykonywania obliczeń matematycznych, które w innym wypadku musieliby oszacować, analizy przesłanego arkusza kalkulacyjnego, konwersji plików lub tworzenia wykresów i dokumentów. Możesz także samodzielnie uruchomić blok kodu z wiadomości czatu, korzystając z przycisku **Run Code**.

Sandbox to oddzielna usługa, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (open source, Apache 2.0), którą administrator wdraża obok LibreChat. Obsługuje Python, Node.js (JavaScript i TypeScript), Go, C i C++, Javę, PHP, Rust oraz Fortran.

## Daj agentowi możliwość wykonywania kodu [#give-an-agent-code-execution]

W Kreatorze agentów wybierz przycisk **Dodaj** obok **Narzędzia** i dodaj **Uruchom kod**. Zapisz agenta. Od tego momentu to agent decyduje, kiedy uruchomić kod; nie musisz o to wprost prosić, choć sformułowanie „użyj kodu, aby to sprawdzić” pomaga, gdy potrzebujesz dokładnej odpowiedzi.

Podczas wykonywania kodu wiadomość wyświetla zwijany wiersz z napisem **Starting sandbox environment** przy pierwszym uruchomieniu, następnie **Analyzing**, a po zakończeniu **Finished analyzing**. Rozwiń go, aby zobaczyć kod napisany przez agenta oraz jego **Output**.

## Praca z plikami [#working-with-files]

Dołącz plik i wybierz **Prześlij do środowiska kodu**, aby udostępnić go piaskownicy w ramach tej rozmowy. Pliki dodane w ustawieniach Uruchamiania kodu agenta są dostępne we wszystkich czatach z tym agentem. Przed każdym uruchomieniem LibreChat przywraca pliki rozmowy w piaskownicy; jeśli nie można przywrócić żadnego z plików potrzebnych do uruchomienia, uruchomienie zostaje zatrzymane i prosi o ponowne dołączenie tych plików, zamiast pracować na nieaktualnych kopiach.

Pliki zapisane przez kod pojawiają się jako wiersze w wiadomości. Kliknij wiersz, aby otworzyć plik w panelu [Artifacts](/docs/features/artifacts), lub pobierz go. Pliki HTML, Markdown, zwykły tekst, kod źródłowy, CSV oraz pliki pakietu Office (Word, Excel, OpenDocument, prezentacje i szablony PowerPoint) są wyświetlane z podglądem w treści. Większe pliki nie mają podglądu i są dostępne wyłącznie do pobrania; domyślny limit wynosi 2 MiB pliku źródłowego. Obrazy odczytywane przez agenta z piaskownicy (PNG, JPEG, GIF, WebP) są wyświetlane w wiadomości do rozmiaru 1 MiB; większe pozostają w piaskownicy, gdzie agent nadal może je przetwarzać.

## Uruchom blok kodu samodzielnie [#run-a-code-block-yourself]

Bloki kodu w wiadomościach czatu mają przycisk **Run Code** obok przycisku **Copy code**, gdy język bloku jest jednym z obsługiwanych przez piaskownicę (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust lub Fortran). Po kliknięciu wynik działania pojawia się pod blokiem. Funkcja działa w każdej rozmowie, nie tylko z agentami.

## Kod działający długo [#long-running-code]

Jeśli administrator włączył narzędzia działające w tle, w ustawieniach Uruchamiania kodu agenta widoczna jest opcja **Wykonywanie w tle**, domyślnie włączona. Agent może uruchomić wolny kod, nadal prowadzić z Tobą rozmowę, a następnie odebrać dane wyjściowe i pliki po zakończeniu działania; domyślnie wynik pojawia się automatycznie w kolejnej wiadomości. Wyłącz to ustawienie dla agentów, które zawsze powinny czekać na zakończenie swojego kodu.

Pamięć, czas procesora, rozmiar przesyłanych plików i dostęp do sieci są ustawiane przez osobę zarządzającą usługą sandbox, a nie przez LibreChat. Jeśli kod zakończy się błędem zasobów, zapytaj swojego administratora, jakie są limity.

## Sesje kodu ze stanem [#stateful-code-sessions]

Domyślnie każde uruchomienie jest bezstanowe: nie należy zakładać, że zmienne lub zainstalowane pakiety przetrwają do następnego uruchomienia. Sesje kodu ze stanem, funkcja eksperymentalna, którą administrator musi włączyć, zapewniają agentowi przestrzeń roboczą, która zachowuje pliki w `/mnt/data` między uruchomieniami. Każde uruchomienie nadal rozpoczyna nowy proces, a przestrzeń roboczą można zresetować w dowolnym momencie, dlatego należy traktować ją jako tymczasowy obszar roboczy, a nie jako miejsce do przechowywania danych.

Włącz **Stateful code sessions** w ustawieniach Run Code agenta i wybierz **Stateful environment**:

- **Obszar roboczy użytkownika (zalecany)**: jeden obszar roboczy dla Ciebie, współdzielony przez wszystkich stanowych agentów, z których korzystasz.
- **Przestrzeń agenta i użytkownika**: oddzielna przestrzeń robocza dla każdego agenta.
- **Przestrzeń robocza rozmowy**: nowa przestrzeń robocza dla każdej rozmowy.

Nowi agenci zaczynają pracę z zakresem ustawionym w **Ustawienia > Dane i prywatność > Wykonywanie kodu > Domyślna trwała przestrzeń robocza**; zmiana tego ustawienia nie wpływa na istniejących agentów. Pliki utworzone lub edytowane przez agenta w trwałej przestrzeni roboczej są wymienione w wierszu **Zmiany w przestrzeni roboczej** w jego odpowiedzi, z możliwością pobrania każdego z nich.

## Uruchamianie kodu na własnym komputerze [#running-code-on-your-own-machine]

Administratorzy mogą również udostępniać środowiska kodu: maszynę wirtualną lub stację roboczą uruchamiającą worker `@librechat/code`, który łączy się z LibreChat. Gdy to zrobią, Kreator agentów wyświetla selektor **Środowisko wykonania**, a opcja **Maszyny dostępne w nowych czatach** pozwala agentowi oferować kilka maszyn, dzięki czemu każdy nowy czat może wybrać jedną z nich za pomocą opcji **Wybierz inną maszynę**.

Jeśli masz uprawnienia do zarządzania środowiskami kodu, dodaj własne w sekcji **Ustawienia > Dane i prywatność > Wykonywanie kodu > Środowiska kodu**: nadaj mu nazwę, wybierz **Połącz VM** i uruchom na swoim komputerze jednorazowe polecenie, które zostanie wyświetlone. Jeśli administrator włączył konfigurację przez przeglądarkę, polecenie konfiguracyjne może zamiast tego otworzyć stronę **Zatwierdź konfigurację maszyny**, na której potwierdzisz żądanie, będąc zalogowanym.

Na podłączonej maszynie agent może przeglądać, odczytywać, wyszukiwać i edytować pliki oraz uruchamiać polecenia powłoki w wybranym obszarze roboczym. Załączniki do czatu, które przesyłasz, są kopiowane do katalogu `.librechat/attachments` w tym obszarze roboczym, zanim agent się uruchomi. Ponieważ te działania zmieniają rzeczywistą maszynę, edytor wiadomości wyświetla dla rozmowy opcję **Tryb zatwierdzania kodu**.

- **Pytaj przed zmianami**: pyta przed edycją plików i uruchamianiem poleceń.
- **Akceptuj zmiany**: edytuje pliki bez pytania, ale nadal pyta przed uruchomieniem poleceń.
- **Pełny dostęp**: edytuje pliki i uruchamia polecenia bez rutynowych monitów. Ograniczenia piaskownicy na maszynie nadal obowiązują.

Dostępne tryby zależą od polityki Twojego administratora. Parowanie maszyny uwierzytelnia workera względem LibreChat; nie tworzy ono żadnej piaskownicy, dlatego worker należy izolować tak, jak każdą maszynę uruchamiającą niezaufany kod.

## Wywoływanie narzędzi MCP z kodu [#calling-mcp-tools-from-code]

Dzięki Programmatic Tool Calling agent może wywoływać wybrane narzędzia MCP z wnętrza sandboxa: pisze skrypt, który iteruje po danych wejściowych, wywołuje narzędzia, filtruje wyniki i zwraca tylko to, co istotne. Pozwala to uniknąć jednego obiegu przez model dla każdego wywołania narzędzia. Przełączniki Programmatic pozostają wyłączone, dopóki agent nie ma włączonego Run Code, a usunięcie Run Code czyści je. Podczas działania skryptu rozwiń jego wiersz, aby obserwować ślad **Tool calls**; ślad nie jest zachowywany po przeładowaniu strony. Tą drogą można wywoływać wyłącznie narzędzia zarejestrowane dla agenta. Informacje o tym, jak oznaczać narzędzia, znajdziesz w sekcji [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling).

## Konfiguracja [#setup]

Wykonywanie kodu wymaga, aby administrator wdrożył usługę Code Interpreter i wskazał jej adres w LibreChat; do tego czasu uruchomienia kończą się niepowodzeniem. Przycisk **Run Code** oraz funkcja agenta mogą być również wyłączone dla poszczególnych ról. Wykonywanie w tle, sesje ze stanem oraz środowiska kodu są każde włączane opcjonalnie. Zobacz [Konfiguracja Code Interpreter](/docs/configuration/tools/code_interpreter).
