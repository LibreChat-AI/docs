# Acciones de mensaje [#message-actions]

Las acciones de mensaje aparecen debajo de un turno de conversación cuando están disponibles. Los turnos del usuario utilizan burbujas alineadas a la derecha, mientras que los turnos del asistente mantienen un diseño de respuesta de ancho completo. Las acciones que no se pueden aplicar a una respuesta mientras esta aún se está transmitiendo permanecen ocultas hasta que la respuesta se completa. En dispositivos con puntero, los metadatos y controles del mensaje se revelan al pasar el cursor o mediante el enfoque del teclado en lugar de requerir un clic.

## Editar y volver a ejecutar [#edit-and-rerun]

Elija **Edit** para cambiar un mensaje de usuario o una respuesta editable del asistente. El editor ofrece dos formas de aplicar el cambio:

- **Save** actualiza el mensaje existente sin generar otra respuesta.
- **Update & rerun** crea una nueva respuesta hermana a partir del mensaje editado.

Las respuestas estructuradas del asistente utilizan un único editor para todas las partes editables de texto y razonamiento. Las llamadas a herramientas, errores, artefactos y el texto adjunto a las llamadas a herramientas permanecen visibles pero son de solo lectura. Las partes editadas vacías no se pueden guardar.

Si cambia más de una parte del asistente, guarde las ediciones sin volver a ejecutar; una sola reejecución puede llevar una parte del asistente editada. Los guardados de varias partes se aplican en orden, y cualquier parte guardada antes de un error permanece reflejada en la conversación.

Volver a ejecutar un mensaje de usuario editado conserva sus archivos, las Skills manuales seleccionadas y el contexto citado. Volver a ejecutar una respuesta del asistente editada reproduce el turno del usuario principal con sus Skills manuales seleccionadas y citas.

Mientras editas, usa `Ctrl`/`Cmd` + `S` para guardar, `Ctrl`/`Cmd` + `Enter` para actualizar y volver a ejecutar, o `Escape` para cancelar.

## Copiar y bifurcar [#copy-and-fork]

**Copiar** escribe el texto del mensaje en el portapapeles y convierte las citas admitidas en referencias legibles. Para las respuestas estructuradas del asistente, LibreChat une solo las partes del texto visibles para el usuario en orden; el razonamiento, las llamadas a herramientas, los errores, los artefactos y el texto adjunto a las llamadas a herramientas se omiten. La acción no está disponible para una respuesta que aún se está transmitiendo o que no tiene texto copiable, por lo que no reemplaza el contenido del portapapeles con un valor parcial o vacío.

Habilite **Copy messages as rich text** en Settings para colocar tanto Markdown sin formato como HTML renderizado en el portapapeles. Aplicaciones como Teams, Outlook y Word podrán conservar los encabezados, listas, tablas y el formato de código al pegar el contenido.

Usa **Fork** para ramificar una conversación desde un mensaje seleccionado. Consulta [Forking Conversations](/docs/features/fork) para obtener más detalles. El endpoint y el estado del mensaje determinan si las acciones de editar, volver a ejecutar, continuar, comentarios, lectura en voz alta y bifurcación (fork) están disponibles.

## Citas de extractos [#quote-excerpts]

Selecciona texto en un mensaje y elige **Add to chat** para prepararlo como contexto citado. Puedes adjuntar hasta 10 fragmentos a un mensaje, con un máximo de 1,500 caracteres por fragmento. LibreChat envía los fragmentos como bloques de cita en Markdown junto con el texto del mensaje y cualquier archivo.

Durante una ejecución activa de un Agente, los fragmentos citados siguen a los mensajes **Steer**, **Queue** e **Interrupt** y permanecen asociados a la acción pendiente tras las reconexiones. En un servidor actual, un mensaje de seguimiento en cola ordinario también conserva sus fragmentos citados tras reinicios de la aplicación y traspasos entre réplicas. Si una réplica anterior no puede aceptar el contexto citado durante un despliegue gradual, LibreChat lo devuelve al compositor en lugar de descartarlo silenciosamente. Las Skills seleccionadas manualmente permanecen preparadas para el siguiente turno completo en lugar de añadirse a un steer durante la ejecución. Consulta [Steering and Queued Messages](/docs/features/agents#steering-and-queued-messages).

## Acciones de bloque de código [#code-block-actions]

Los bloques de código proporcionan acciones para copiar su contenido, ejecutar código compatible a través de [Code Interpreter](/docs/features/code_interpreter) o descargar el bloque como un archivo local. Los nombres de descarga utilizan el lenguaje delimitado cuando es posible, como `code.py` o `code.tsx`; una sugerencia de lenguaje seguro desconocida se convierte en su extensión, y una sugerencia ausente o no válida recurre a `code.txt`. Los bloques de error no muestran la acción de descarga.

## Texto largo pegado [#long-pasted-text]

Cuando la configuración local del navegador **Pegar texto largo como archivo** está habilitada y las [cargas de contexto de Upload as Text](/docs/features/upload_as_text#paste-long-text-as-a-file) están disponibles, las pegadas desde el portapapeles de más de 2,500 caracteres se convierten en un archivo adjunto `pasted-text.txt` en lugar de llenar el campo de entrada. De lo contrario, el texto pegado permanece en línea. Seleccione el archivo adjunto antes de enviarlo para editar el texto en un cuadro de diálogo más grande o elija **Mover de nuevo al mensaje** para devolverlo al campo de entrada.

LibreChat conserva los borradores de texto pegado y la procedencia de los mensajes a través de la restauración normal de borradores. Las ediciones mantienen el archivo adjunto original hasta que el reemplazo esté listo, y al iniciar un **New Chat** explícito se borra el texto pegado junto con el resto del borrador.

## Turnos solo con archivos adjuntos [#attachment-only-turns]

Puedes enviar uno o más archivos adjuntos sin escribir texto de marcador de posición. Los turnos que solo contienen archivos adjuntos siguen siendo válidos al editar y volver a ejecutar un mensaje, y LibreChat utiliza los nombres de archivo de los adjuntos cuando necesita contexto para el título.

Un borrador vacío sin archivos sigue siendo rechazado. Los archivos tampoco sustituyen al texto al responder a un formulario **Ask User** pausado de un Agente, ya que esa ruta de respuesta acepta valores de respuesta en lugar de archivos adjuntos en los mensajes.
