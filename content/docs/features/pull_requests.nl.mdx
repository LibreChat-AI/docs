Wanneer een agent werkt aan een repository in een gekoppelde codewerkruimte, zoekt LibreChat de pull request op voor de branch waarop de werkruimte staat en toont deze naast de chat. Je kunt zien of deze klaar is om samengevoegd te worden, of de controles slagen, en naar de pull request navigeren zonder het gesprek te verlaten. Het werkt met GitHub, GitLab (waar het een merge request wordt genoemd) en Bitbucket Cloud, met één provider per implementatie.

Alleen chats die code uitvoeren in een gekoppelde workspace kunnen een pull request hebben. Een gewone chat, of een workspace die nog geen branch heeft gemeld, toont niets.

## In de chatkop [#in-the-chat-header]

Op een breed scherm toont een chip links in de kop het pull request-pictogram, een kleine CI-stip op de hoek en de titel van de pull request. Beweeg de muis over de chip of zet de focus erop om een kaart met de details te openen. De kaart blijft open zolang uw aanwijzer of toetsenbordfocus zich binnen de kaart bevindt.

Op een klein scherm is er geen chip. Open het driepuntsmenu in de header en kies de optie `PR #number` (`MR !number` op GitLab) om dezelfde kaart in een dialoogvenster te tonen.

De header blijft zichzelf actueel houden: hij controleert ongeveer elke 20 seconden opnieuw zolang er controles lopen of de provider nog bepaalt of de branch kan worden samengevoegd, en ongeveer elke 60 seconden in alle andere gevallen. Zodra de pull request is samengevoegd of gesloten en er niets meer draait, stopt hij.

## In de zijbalk [#in-the-sidebar]

Gesprekken die een pull request hebben, krijgen hetzelfde pictogram en dezelfde CI-stip aan het einde van hun rij. De rij behoudt de eigen titel van het gesprek. Beweeg de muis over de rij, of zet de focus op of klik op de markering, om de kaart ernaast te openen; als je op de markering klikt, wordt het gesprek niet geopend.

<ThemeImage
  light="/images/pull-requests/side-rows-light.png"
  dark="/images/pull-requests/side-rows-dark.png"
  alt="Zijbalkrijen met pull request-markeringen: klaar om samen te voegen, conflicten met mislukte controles, een concept met lopende controles en een samengevoegde pull request"

De zijbalk pollt niet. Een rij is zo actueel als de laatste keer dat de lijst is geladen, en wordt vernieuwd wanneer je terugkeert naar het venster en de gegevens ouder zijn dan een minuut. Als een vernieuwing mislukt voor een pull request dat al gevonden was, blijft de markering staan en toont de kaart de melding "Couldn't refresh the pull request" met een **Retry**-knop. Een gesprek waarvan het pull request nog nooit is gevonden, toont helemaal geen markering, ook niet wanneer de opzoeking is mislukt.

## De kaart lezen [#reading-the-card]

De kaart toont `PR #number` (`MR !number` op GitLab), de regels die in groen zijn toegevoegd en in rood zijn verwijderd, een link **Open in GitHub**, **Open in GitLab** of **Open in Bitbucket**, de titel en twee badges:

- Status: Open, Conflicts, Draft, Merged of Closed. Conflicts vervangt Open wanneer de branch niet schoon kan worden samengevoegd.
- Checks: Passing, Failing, Running of None. Op GitLab is dit de head pipeline, en alleen als deze is uitgevoerd voor de huidige commit. Op Bitbucket zijn dit de commit statussen.

De pictogramkleur en de CI-stip geven in één oogopslag dezelfde informatie weer:

| Pull request                         | Pictogram | CI-stip          |
| ------------------------------------ | --------- | ---------------- |
| Open, kan worden samengevoegd        | Groen     | Uit de checks    |
| Open, samenvoegbaarheid nog niet bekend | Neutraal | Uit de checks  |
| Open, samenvoegconflicten            | Rood      | Uit de checks    |
| Concept                              | Neutraal  | Uit de checks    |
| Samengevoegd                         | Paars     | Geen             |
| Gesloten                             | Neutraal  | Geen             |

De stip is groen voor geslaagde controles, rood voor mislukte controles en oranje voor controles die nog lopen. Er is geen stip wanneer de repository geen controles rapporteert. Een mislukte controle gaat voor op een controle die nog loopt.

## Welke pull request je ziet [#which-pull-request-you-see]

De werkruimte toont de repository, de branch en de commit waarop de chat het laatst is uitgevoerd, en LibreChat zoekt naar een pull request vanaf die branch.

- Als de eigen commando-uitvoer van de chat een link naar een pull request in dezelfde repository heeft afgedrukt (bijvoorbeeld de URL die `gh pr create` afdrukt), wordt dat pull request gebruikt, mits het afkomstig is van de branch van de chat.
- Anders hebben open pull requests voor de branch de voorkeur boven gesloten pull requests, zodat een oude gesloten pull request op een hergebruikte branchnaam de huidige niet verbergt.
- Een pull request telt alleen mee als deze de commit bevat waarop de chat voor het laatst is uitgevoerd. Het verwijderen van een branch en het hergebruiken van de naam ervan herstelt de oude pull request niet.
- Een gloednieuwe branch zonder commits komt nergens mee overeen.

Repositories waarvoor de server niet mag opzoeken, gedragen zich precies zoals repositories zonder pull request: geen markering en geen foutmelding.

## Koppel je eigen account [#connect-your-own-account]

Als uw beheerder dit heeft ingesteld, kunt u pull requests opzoeken met uw eigen GitHub-, GitLab- of Bitbucket-account. Open **Instellingen**, ga naar **Account** en klik onder **Verbonden accounts** op **Verbinden** naast **Pull request-account**. Er wordt een aanmeldvenster geopend bij de provider; keur dit goed en de rij toont **Verbonden**. Als het venster niet opent, sta dan pop-ups toe voor LibreChat en probeer het opnieuw.

Eenmaal verbonden gebruiken zoekopdrachten je eigen account, zodat je pull requests ziet in elke repository die je kunt lezen, onder je eigen rate limit. **Verbreken** verwijdert de verbinding en je kunt altijd opnieuw verbinding maken. Als de server je verbinding niet kan vernieuwen (bijvoorbeeld omdat de provider niet beschikbaar is), worden je pull requests weergegeven als niet beschikbaar in plaats van stilzwijgend over te schakelen naar het token van de server. Als je de app bij de provider intrekt, verwijdert LibreChat de verbinding en ben je weer niet verbonden.

Als de rij **Not in use** vermeldt, heeft je beheerder accountverbindingen uitgeschakeld en gebruiken opzoekacties je account niet meer. Klik op **Disconnect** om de opgeslagen verbinding te verwijderen.

## Setup [#setup]

De functie staat standaard aan, maar blijft verborgen totdat een beheerder LibreChat een token en een lijst met repositories geeft waarin het mag zoeken, of een app instelt zodat gebruikers hun eigen accounts kunnen koppelen. Er is ook een gekoppelde codewerkruimte nodig die de git-branch rapporteert. Zie [Pull Requests-configuratie](/docs/configuration/pull_requests).
