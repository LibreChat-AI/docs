MCP (Model Context Protocol) è uno standard aperto per esporre strumenti a un modello. Un server MCP può fornire al modello un file system, un browser, un database o l'API interna della tua azienda, e LibreChat può utilizzare qualsiasi server che supporti il protocollo. Puoi collegare i server a una chat normale per un utilizzo rapido, oppure aggiungere i loro strumenti a un agente.

## Usa un server nella chat [#use-a-server-in-chat]

Su qualsiasi endpoint diverso da Agents o Assistants, apri la palette **+** del compositore (**Allega e strumenti**) e cerca in **Server MCP**. Fai clic su un server per attivarlo per la conversazione. Comparirà come chip nel compositore e ogni strumento esposto dal server diventerà disponibile per il modello. La palette rimane aperta, quindi puoi attivare più server in una sola volta; fai nuovamente clic su un server, oppure rimuovi il suo chip, per disattivarlo. Consulta [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) per il resto della palette.

La tavolozza mostra alcuni server alla volta, con un punto colorato per lo stato di ciascun server. **Mostra tutti** nell'intestazione **MCP Servers** apre l'elenco completo con un campo di ricerca e tre visualizzazioni: **Tutti**, **Creati da te** e **Preferiti**.

![La finestra di dialogo MCP Servers aperta con Mostra tutti, che elenca un server Github contrassegnato come Disconnected e un server Spotify contrassegnato come Needs Auth, con i filtri Tutti, Creati da te e Preferiti](/images/mcp/mcp_servers_catalog.png)

Se il server non è ancora connesso, cliccandolo viene avviata la connessione invece di selezionarlo immediatamente. Un server che richiede le tue credenziali personali apre una finestra di dialogo in cui inserirle prima; un server che utilizza OAuth ti porta alla procedura di accesso. Una volta connesso, LibreChat lo seleziona automaticamente per te.

Scegli un modello che supporti le chiamate agli strumenti, altrimenti il modello non invocherà mai gli strumenti del server. Agenti e Assistenti dispongono di una propria configurazione degli strumenti, quindi il selettore è nascosto su quegli endpoint, e un amministratore può nascondere singoli server dalla chat in modo che siano disponibili solo agli agenti.

## Aggiungere un server a un agente [#add-a-server-to-an-agent]

Nel Creatore di agenti, fai clic su **Aggiungi** accanto a **Strumenti** per aprire la **Libreria degli strumenti**, quindi filtra per **Server MCP**. Aggiungendo un server vengono elencati gli strumenti che espone: mantieni quelli che l'agente deve avere e rimuovi gli altri, oppure usa **Seleziona tutto** e **Deseleziona tutto**. Un server con decine di strumenti occupa comunque una sola voce nell'elenco degli strumenti dell'agente.

Ogni strumento MCP su un agente ha anche le proprie opzioni (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Vedi [Agents](/docs/features/agents) per sapere cosa modificano.

Alcuni server dipendono da valori che esistono solo durante una richiesta di chat, quindi i loro strumenti non possono essere elencati in anticipo. Per questi, la Tool Library collega l'intero server e indica che i suoi strumenti vengono risolti in fase di esecuzione, durante la chat.

Se un agente è configurato per utilizzare strumenti MCP e nessuno di essi è disponibile all'avvio di un'esecuzione (il server non è attivo o hai perso l'accesso), l'esecuzione si interrompe con un errore che ti invita a verificare la connessione e i tuoi permessi di accesso, anziché rispondere senza gli strumenti. Premere **Stop** durante una chiamata a uno strumento annulla anche la chiamata sul server MCP, purché il server supporti l'annullamento.

## Stato della connessione [#connection-status]

Nella palette e in **MCP Settings**, lo stato è indicato da un punto colorato: grigio quando il server è disconnesso, ambra quando è necessario effettuare l'accesso. Lo stato completo viene letto dagli screen reader, e la Tool Library e l'elenco **Show All** lo indicano esplicitamente accanto a ciascun server:

- **Connesso**: pronto all'uso.
- **Needs Auth**: il server utilizza OAuth e non hai effettuato l'accesso, oppure il tuo accesso è scaduto.
- **Connessione** / **Inizializzazione**: è in corso un tentativo di connessione.
- **Disconnected** o **Error**: non è presente alcuna connessione attiva, oppure l'ultimo tentativo non è riuscito. Usa **Connect** per riprovare.
- **On-demand**: il server si connette separatamente per ogni richiesta, quindi non esiste una connessione persistente da segnalare.
- **Sconosciuto**: non è ancora arrivato alcuno stato.

Quando una connessione non riesce, l'errore indica il motivo: il server non è raggiungibile, richiede variabili che non hai impostato (indicate nel messaggio), oppure richiede di effettuare nuovamente l'accesso. Correggi il problema e riconnettiti; non è necessario rimuovere e aggiungere di nuovo il server. Un server può anche aggiungere o rimuovere strumenti mentre è in esecuzione, e LibreChat recepisce il nuovo elenco senza bisogno di riavviarsi.

Le connessioni sono per utente. I tuoi token OAuth e le credenziali salvate non vengono mai utilizzati da altri, e una connessione inattiva viene chiusa per impostazione predefinita dopo 15 minuti e riaperta la volta successiva in cui utilizzi il server.

## Accedi con OAuth [#sign-in-with-oauth]

Quando un server richiede OAuth, connettendolo viene aperta una finestra di dialogo **Connect**. Fai clic su **Continue with OAuth** per aprire la pagina di accesso del provider in una nuova scheda, oppure usa **Copy link** o **Show QR Code** per completare l'operazione su un altro dispositivo. Dopo aver approvato l'accesso, la scheda mostra **Authentication Successful** e si chiude automaticamente, mentre lo stato del server passa a **Connected**.

Mentre un accesso è in attesa, il server mostra uno spinner; passaci sopra con il mouse per annullare. Nelle impostazioni del server MCP dell'Agent Builder, **Connect** diventa **Cancel** per lo stesso scopo. Hai 10 minuti per completare l'accesso prima che il tentativo scada (l'amministratore può modificare questo limite).

Se il provider emette refresh token, LibreChat rinnova il tuo accesso in background e, quando un server rifiuta il token durante la sessione, tenta un solo refresh e una riconnessione prima di chiederti di effettuare nuovamente l'accesso. I provider che non emettono refresh token ti chiedono di effettuare nuovamente l'accesso quando il token scade.

Per impostazione predefinita, la richiesta di accesso compare quando viene inviato il tuo messaggio. Un amministratore può configurare alcuni server in modo che attendano la prima chiamata di uno dei loro strumenti da parte dell'agente, così ti viene chiesto di accedere solo quando il server è effettivamente necessario.

## Credenziali e variabili [#credentials-and-variables]

Alcuni server richiedono un valore da ogni utente, come una chiave API personale o un ID di progetto. Quando ti connetti a uno di questi, LibreChat chiede i valori prima di stabilire la connessione. Per modificarli in un secondo momento, usa **Configure** sul server nel selettore della chat oppure in **MCP Settings**. Ogni campo ha **Save** e **Revoke**. Entrambe le azioni chiudono la connessione corrente con quel server, quindi il successivo utilizzo si connette con i nuovi valori, e revocare disattiva anche il server nella chat corrente.

I valori sono memorizzati per utente e inviati solo al server per cui sono stati inseriti.

## Pannello delle impostazioni MCP [#mcp-settings-panel]

**Impostazioni MCP** nel pannello laterale elenca tutti i server che puoi utilizzare, con un indicatore di stato su ciascuna icona del server. A seconda dello stato del server, ogni scheda offre **Connetti**, **Riconnetti**, **Configura** (per le tue variabili) oppure **Revoca** (per eliminare i tuoi token OAuth). I server che ti è consentito modificare includono anche **Modifica**.

## Crea un server dall'interfaccia utente [#create-a-server-from-the-ui]

Se il tuo ruolo lo consente, fai clic su **Add MCP** (il pulsante **+**) in **MCP Settings** per registrare un server remoto senza modificare `librechat.yaml` né riavviare l'applicazione.

<Steps>
<Step>
### Descrivi il server [#describe-the-server]

Inserisci un **Nome**, una **Descrizione** facoltativa e un'icona, se lo desideri. Compila l'**URL del server MCP** e scegli un **Trasporto**: **Streamable HTTPS** oppure **SSE**.
</Step>
<Step>
### Scegli l'autenticazione [#choose-authentication]

Nella sezione **Authentication**, scegli una delle seguenti opzioni:

- **Nessuno (rilevamento automatico)**: LibreChat verifica il server e passa a OAuth se il server lo richiede.
- **API Key**: inserisci una chiave condivisa, oppure seleziona **Each user provides their own key** in modo che ogni utente inserisca la propria tramite **Configure**. Scegli il **Header Format**: **Bearer**, **Basic** oppure **Custom** con un nome di header personalizzato.
- **OAuth**: inserisci il **Client ID**, il **Client Secret**, l'**Authorization URL**, il **Token URL** e lo **Scope**. Lascia vuoti i campi del client se il provider supporta la registrazione dinamica del client. Il **Token Exchange Method** è impostato su **Auto** per impostazione predefinita, che utilizza il metodo indicato dal provider e ricorre a un header di autorizzazione Basic in caso contrario; scegli **Default (POST request)** o **Basic authorization header** per forzarne uno.
- **On-Behalf-Of (OBO)**: visibile solo se un amministratore ti ha concesso tale autorizzazione, e funziona solo quando LibreChat autentica gli utenti tramite OpenID Connect (ad esempio Entra ID). Inserisci gli scope da richiedere; LibreChat scambia il tuo token OpenID con uno con scope limitato al server MCP.
</Step>
<Step>
### Crea il modello [#create-it]

Seleziona **Mi fido di questa applicazione** e fai clic su **Crea**. Il server è disponibile immediatamente. Per i server OAuth, la finestra di dialogo successiva mostra il **Redirect URI** da registrare presso il tuo provider OAuth, e il server resta disconnesso finché non effettui l'accesso una volta.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="La finestra di dialogo Aggiungi server MCP con un nome e un URL compilati, Transport impostato su Streamable HTTPS e Authentication impostato su API Key con l'opzione Each user provides their own key selezionata"
/>

I server creati in questo modo possono raggiungere solo URL remoti; i server `stdio` locali devono essere definiti in `librechat.yaml`. Inoltre non possono usare le variabili d'ambiente del server né i segnaposto del profilo utente: valori come `${API_TOKEN}` o `{{LIBRECHAT_USER_EMAIL}}` nei loro header vengono rimossi, poiché un server condiviso li riceverebbe altrimenti. Se in seguito modifichi l'URL o l'autenticazione di un server, gli utenti che avevano inserito una propria chiave devono inserirla di nuovo, e gli utenti OAuth devono effettuare nuovamente l'accesso. Quando cambi l'URL o gli endpoint OAuth di un server con un client secret salvato, devi reinserire anche il secret. Se un server con chiave API creato con una versione precedente resta bloccato su **Needs Auth**, aprilo con **Edit** e salvalo una volta.

## Condividi un server [#share-a-server]

I server creati nell'interfaccia appartengono a chi li ha creati. Il proprietario può condividerne uno dalla finestra di dialogo **Modifica**, con utenti, gruppi, ruoli specifici o con tutti, assegnando il ruolo di visualizzatore (può vedere e usare il server), di editor (può anche modificarlo) o di proprietario. I server definiti in `librechat.yaml` sono disponibili a tutti coloro che hanno il permesso di usare MCP. Consulta [Controllo degli accessi](/docs/features/access_control) per scoprire come si combinano i livelli di permesso.

## Istruzioni del server [#server-instructions]

Un amministratore può collegare delle istruzioni a un server, che siano quelle proprie del server oppure un testo personalizzato. Quando una conversazione o un agente dispone degli strumenti di quel server, le istruzioni vengono aggiunte al contesto del modello, il che è utile per i server i cui strumenti hanno senso solo se utilizzati in un determinato ordine.

## MCP Apps [#mcp-apps]

Alcuni server restituiscono una vista interattiva insieme al risultato di uno strumento. Quando le MCP Apps sono attivate, la chiamata allo strumento mostra un pulsante **Apri app**, che carica la vista in un frame isolato (sandbox), mentre **Chiudi app** la nasconde di nuovo. È possibile avere aperte contemporaneamente solo alcune app; se si raggiunge il limite, chiudine prima una.

Un'app non può agire autonomamente. Quando vuole eseguire uno strumento, vedrai **Eseguire lo strumento dall'app?**, e quando vuole pubblicare un messaggio, **Inviare il messaggio dall'app?**. Non succede nulla finché non approvi. L'invio di un messaggio avvia una risposta del modello nella conversazione corrente, quindi possono essere utilizzati l'agente selezionato e i suoi strumenti. Le app non vengono visualizzate nelle conversazioni condivise.

## Setup [#setup]

MCP richiede almeno un server. Gli amministratori definiscono i server sotto `mcpServers` in `librechat.yaml`, il che richiede un riavvio per essere applicato, mentre gli utenti con i permessi necessari possono aggiungere server remoti da **MCP Settings**. Consulta [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) per le opzioni dei server, l'URL di callback OAuth e i trasporti, [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) per i domini consentiti e le MCP Apps, [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) per i limiti delle app, e [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) per chi può usare, creare e condividere i server. Le guide di configurazione per server specifici si trovano in [MCP Servers](/docs/mcp_servers), mentre [Agent Plugins](/docs/features/agent_plugins) descrive come raggruppare i server MCP con le skill.
