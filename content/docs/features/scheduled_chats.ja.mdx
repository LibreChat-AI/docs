定期チャットは、保存済みのエージェントに対して固定のプロンプトをタイマーに従って送信します。実行のたびに新しい会話が開始されるため、完了した回答を後から確認できます。例えば、朝のニュースブリーフィング、週次レポート、何かを確認してくれるリマインダーなどです。

スケジュールチャットは実験的な機能であり、管理者による有効化が必要です。

## スケジュールを作成する [#create-a-schedule]

<Steps>
  <Step>
    サイドパネルから **Scheduled chats** を開き、**New schedule** をクリックします。
  </Step>
  <Step>
    名前を付けて、プロンプトを書いてください。プロンプトはプレーンテキストとして送信され、コンポーザー変数は展開されません。
  </Step>
  <Step>
    エージェントを選択してください。そのエージェントに対する表示および使用の権限が必要であり、保存済みのエージェントである必要があります。
  </Step>
  <Step>
    頻度、タイムゾーン、そして Chat Projects を使用している場合は新しいチャットを追加するプロジェクトを選択します。保存してください。
  </Step>
</Steps>

### 頻度 [#frequency]

- **毎時**: 時間の経過後、指定した分に実行されます。
- **毎日**: 1日の決まった時刻に。
- **平日**: 1つの時間帯で、月曜日から金曜日まで。
- **毎週**: チェックを入れた曜日に、指定した1つの時刻に実行されます。少なくとも1つの曜日を選択してください。
- **カスタム**: 5つのフィールド(分、時、日、月、曜日)からなるcron式です。入力中、ダイアログに次回以降の実行時刻がいくつか表示されます。`0 9,17 * * 1-5` は平日の9:00と17:00に実行され、`0 9 1 * *` は毎月1日の9:00に実行されます。秒と年のフィールドはサポートされていません。

実行は、管理者がより短い間隔を許可していない限り、少なくとも1時間間隔を空けなければなりません。これはカスタムcronにも適用されます。デフォルト設定では、`*/15 * * * *` は拒否されます。

### タイムゾーン [#time-zone]

新しいスケジュールは、ブラウザのタイムゾーンで開始されます。ブラウザのタイムゾーンと UTC は、リストの上部に固定表示されます。時刻はブラウザの現在地ではなく、スケジュールのタイムゾーンに従います。また、夏時間(サマータイム)にも対応しています。切り替え日に存在しない時刻は、最初の有効な時刻に実行されます。同じ時刻が2回発生する場合は、1回だけ実行されます。

時刻は、[Settings](/docs/features/settings#general) で設定した12時間または24時間形式で表示され、週の開始日も同じ設定に従います。これは表示形式が変わるだけで、実行される時刻は変わりません。

## スケジュールの管理 [#manage-schedules]

各スケジュールカードには、次回の実行時刻、前回の実行結果、そして最新の会話へのリンクが表示されます。カードから、編集、有効化または一時停止、**Run now**、削除を行えます。**Run now** は、スケジュールが一時停止中であっても1回だけ実行を開始します。今後の実行を再び有効にするものではありません。パネルには、許可されたスケジュールのうち何件を使用しているかも表示されます。

実行が質問をしたり、ツール呼び出しの承認を求めたりして停止した場合、そのステータスには**承認が必要**と表示されます。会話を開いて回答すると、実行が再開されます。

## 実行が行われない場合 [#when-a-run-does-not-happen]

スケジュールの実行は、一度に1回のみ行われます。前回の実行がまだ進行中である場合、または残高が不足している場合、その実行は**スキップ**されます。

実行前に、LibreChat はエージェントの MCP サーバーを確認します。これにはサブエージェントが使用するサーバーも含まれます。いずれかのサーバーに接続できない場合、再度サインインが必要な場合、またはそのサーバーへのアクセス権を失っている場合、実行は開始されません。この状態を解消するには、スケジュールで **Open agent to reconnect MCPs** を使用してください。このようにブロックされている間も、スケジュールは編集できます。

スケジュールは、次の条件に該当すると自動的に無効化され、その理由がカードに表示されます:

- 何度か連続して失敗します。
- そのエージェントが削除されたり、無効になったり、アクセスできなくなったり、エージェントを使用する権限を失ったりした場合、
- 残高がなくなると、
- 必要なプロジェクトが見つからないか、削除されています。

原因を修正して、スケジュールを再びオンにしてください。

### 無人実行向けの MCP ツールの認可 [#authorizing-mcp-tools-for-unattended-runs]

いくつかのデプロイ環境では、スケジュールがユーザーの操作なしにそれらのツールを使用できるよう、事前に MCP アクセスの承認が必要です。その場合、スケジュールエディターには **Scheduled MCP authorization** セクションがあります。**Authorization lifetime (hours)** を設定し、**Confirm authorization** をクリックしてください。カードには **Authorized** と正確な有効期限が表示されます。この承認は、そのエージェントと記載されたリソースのみを対象とし、期限が到来すると失効します。また、エージェント、スケジュール、またはリソースを変更すると承認はクリアされ、その後あらためて確認が必要になります。**Revoke authorization** を使うと、いつでも承認を取り消すことができます。

## セットアップ [#setup]

Scheduled Chatsはデフォルトでオフになっています。管理者がこれを有効にし、ユーザーごとのスケジュール数や最小実行間隔などの上限を設定し、複数レプリカでのデプロイ向けにRedisの要件を満たす必要があります。詳しくは[Scheduled Chats configuration](/docs/configuration/scheduled_chats)を参照してください。
