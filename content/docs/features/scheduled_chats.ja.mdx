Scheduled Chats（スケジュールされたチャット）を使用すると、保存されたLibreChat Agentが、提供したプロンプトを使用して自動的に新しい会話を開始できるようになります。定期的なレポート、リマインダー、リサーチ、その他手動でチャットを開始せずに実行すべきAgentのワークフローにご活用ください。

<Callout type="warning" title="実験的であり、デフォルトでは無効になっています">
  Scheduled Chatsは初期の実験段階にあります。その動作、設定、およびデプロイメント要件は大幅に変更される可能性があります。スケジュールされた実行はモデル、ツール、およびCode Interpreterのリソースを消費する可能性があるため、管理者が明示的に有効にしない限り、LibreChatではこの機能は有効になりません。
</Callout>

## スケジュールされたチャットを有効にする [#enable-scheduled-chats]

`librechat.yaml` に `interface.schedules` を追加し、LibreChat を再起動します：

```yaml filename="librechat.yaml"
interface:
  schedules:
    use: true
    create: true
    maxPerUser: 10
    minIntervalMinutes: 60
    autoDisableAfterFailures: 5
    fireConcurrency: 5
    requireProject: false
    # projectId: '000000000000000000000000'
```

`use` および `create` は、起動時に組み込みの `USER` ロールに対して `SCHEDULES` 権限をシードします。管理者は [Admin Panel](/docs/features/admin_panel) でロールごとにそれらの権限を管理できます。残りの値はランタイム制限です：

`schedules` フィールド全体は、デフォルトでは存在しません。`schedules: true` はデフォルトの制限でこの機能を有効にし、`schedules: false` または `schedules: { use: false }` はデプロイ全体で機能を停止します。無効化された基本設定は、ロール、グループ、またはユーザー設定のオーバーライドによって再有効化することはできません。`maxPerUser` は、スロット管理が導入される前に作成された定義を含め、所有するすべてのスケジュールをカウントします。マージおよび権限の動作の詳細については、[`interface.schedules`](/docs/configuration/librechat_yaml/object_structure/interface#schedules) を参照してください。

## スケジュールの作成と管理 [#create-and-manage-a-schedule]

サイドナビゲーションから **Scheduled Chats** を開き、**New schedule** を選択します。スケジュールには以下が必要です：

- 名前とプロンプト
- 表示および使用が可能な保存済みAgent
- 1時間ごと、毎日、平日、毎週、またはカスタムのcron周期
- IANAタイムゾーン
- 管理者が必須設定または固定をしていない限り、オプションのChat Projectの送信先

新しいスケジュールは、現在のブラウザのIANAタイムゾーンで開始されます。サポートされている他のIANAゾーンを選択することも可能で、ブラウザのゾーンとUTCがリストの先頭に固定され、各オプションには現在のGMTオフセットが表示されます。既存のスケジュールは、保存されたゾーンで再度開かれます。`Intl.supportedValuesOf` をサポートしていないブラウザでも、現在のゾーン、UTC、またはスケジュールに保存されたゾーンを使用できます。ゾーンのみを変更した場合はタイミングの変更とみなされ、LibreChatは次の発生時刻を再計算し、デプロイメントの最小間隔に基づいてケイデンス（周期）を再検証します。

構造化されたケイデンスのオプションは以下の通りです：

- **Hourly**: `00` から `59` までの任意の分を選択します。
- **Daily**: 毎日1回、現地時間を選択してください。
- **平日**: 月曜日から金曜日までの間で、現地時間を1つ選択してください。
- **Weekly**: 1つ以上の曜日と現地時間を指定します。少なくとも1つの曜日を選択する必要があります。

時間制御はブラウザの[時計の形式設定](/docs/features/settings#general)に従い、週単位の日次制御とサマリーはブラウザの**週の開始曜日**設定に従います。これらの設定は表示のみを変更するものであり、実行内容は保存されたIANAタイムゾーンと選択された曜日によって決定されます。

**Custom**を選択すると、`minute hour day-of-month month day-of-week`の順序で5つのフィールドからなるcron式を繰り返し入力できます。秒と年のフィールドは拒否され、256文字を超える式や将来の発生がない式も同様です。ダイアログは、サーバーと同じパーサーを使用して、選択されたタイムゾーンでの今後の発生を検証およびプレビューします。例として、平日の09:00と17:00には`0 9,17 * * 1-5`、毎月1日の09:00には`0 9 1 * *`などが挙げられます。すべての周期は引き続き`minIntervalMinutes`を満たす必要があります。例えば、`*/15 * * * *`を使用するには、管理者がデフォルトの60分よりも短い間隔を許可する必要があります。

夏時間の切り替えはタイムゾーンを考慮したままとなります。存在しないローカル時刻は最初の有効な瞬間に移動し、繰り返されるローカル時刻は一度だけ実行されます。間隔の検証は、春の切り替え時の短縮されたリアルタイムのギャップを含め、有効な周期とゾーンを合わせて測定するため、ゾーンを変更すると、それ以外は有効な式であっても設定された下限を下回る可能性があります。スケジュールされたプロンプトはリテラルテキストであり、この形式ではメッセージ作成時の変数挿入は利用できません。

各発生回は、選択されたAgentとの新しい会話を開始します。スケジュールカードには次回の発生予定と最新のステータスが表示され、会話が存在する場合は最新の会話へのリンクが示されます。`SCHEDULES: CREATE`権限を持つユーザーは、スケジュールの編集、有効化/無効化、即時実行、削除を行うことができます。**Run now**を使用すると、将来の発生を有効にすることなく、無効化されたスケジュールを一度だけ開始できますが、その際も権限、デプロイメントの容量、およびグローバル停止設定は適用されます。

実行が「ユーザーへの確認（Ask User）」または「ツール承認（tool approval）」のために一時停止した場合、そのステータスは**承認待ち（Needs approval）**となり、会話を開いて決定を完了させることができます。LibreChatは同じスケジュールの重複実行を防ぎ、別の実行がアクティブな場合やアカウントの残高が不足している場合には、実行をスキップすることがあります。

生成キャパシティを消費する前に、LibreChat はスケジュールされたエージェントおよびその実行可能なサブエージェントグラフで必要とされる、選択済みのすべての MCP ツールを確認します。ツールの欠落、サーバーの利用不可、権限の取り消し、カタログの不完全さ、またはユーザーの操作を必要とする認証フローがあると、実行は阻止され、修復が必要なエージェントが特定されます。スケジュールの UI には **Open agent to reconnect MCPs** という復旧アクションが用意されています。MCP サーバーが利用できない状態でも、無効化されたスケジュールは編集できます。

### スケジュールされた MCP 認可 [#scheduled-mcp-authorization]

`interface.schedules.mcpConsent`が有効なデプロイ環境では、MCPツールを使用するスケジュールを無人で実行する前に、保存済みの**スケジュール済みMCP認可**が必要です。この認可は、記載されたエージェントとリソースに対してのみ、固定の期限まで有効です。プロバイダーの再接続、スケジュールの有効化、書き込み操作の許可は行いません。

スケジュールエディターでは、次のことができます:

- **Authorization lifetime (hours)** を設定します。
- **Confirm authorization**を選択して記録します。その後、カードに**Authorized**と絶対的な有効期限が表示されます。
- 認可を取り消すには、**認可を取り消す**を選択します。

ステータスは、確認するまで**Authorization required**と表示されます。期限を過ぎると**Authorization expired**、取り消し後は**Authorization revoked**と表示されます。Agent、スケジュール、またはリソースのバインディングを変更すると認可は無効になり、内容を再度確認して承認する必要があります。

管理者は、[`interface.schedules`](/docs/configuration/librechat_yaml/object_structure/interface#schedules)でこれを設定します:

- `mcpConsent.enabled` は、この機能を有効にします。
- `mcpConsent.maxLifetimeHours` は認可の有効期間の上限を設定します（1〜8760時間）。
- `mcpConsent.resources` は、認可の対象となりうる MCP リソースを束縛します。
- `mcpConsent.readOnlyPolicy` は、サーバーとアップストリームのツール名をキーとして、信頼された読み取り専用のツール宣言を一覧にします。
- `mcpReceiptRetry.baseMs` と `mcpReceiptRetry.maxMs` は、同意レシートの再試行間隔を指数関数的に増加させる上限付きの値を設定します。この間隔にはジッター（ランダムな揺らぎ）が加えられます。

スケジュールは、繰り返し失敗した場合や、そのAgentが削除された場合、設定が無効である場合、アクセス権が取り消された場合、アカウントの残高が不足している場合、必要なプロジェクトが存在しない場合、あるいは有効なプロジェクトが削除されたかスケジュール所有者が所有していない場合に、自動的に無効化されることがあります。プロジェクトポリシーは実行のたびに再チェックされるため、`requireProject`の制限を強化したりピンを変更したりすると、既存のスケジュールにも適用されます。スケジュールを再度有効にする前に、根本的な問題を修正してください。

オペレーターレベルの `projectId` は、各スケジュールに保存されているプロジェクトを上書きし、`requireProject` を意味します。Chat Projects はユーザーが所有するものであるため、グローバルなピン留めは通常そのプロジェクトの所有者にのみ機能します。異なる所有者が異なるピン留め先を必要とする場合は、ロールまたはユーザー設定のオーバーライドを使用してください。

## Permissions [#permissions]

`SCHEDULES: USE` は、ユーザーが自身のスケジュールを一覧表示および閲覧できるかどうかを制御します。`SCHEDULES: CREATE` はさらに、スケジュールの作成、編集、有効化、実行、および削除を制限します。スケジュール実行時には、ユーザーのAgent機能の権限と、選択されたAgentへの閲覧アクセス権が再確認されます。いずれかのアクセス権を失うと、影響を受けるスケジュールは無効になります。

ロールの権限とリソースのACLについては、[Access Control](/docs/features/access_control) を参照してください。

## Deployment Safety [#deployment-safety]

Scheduled Chatsは、MongoDBのリース、冪等なトリガー配信、および重複防止機能を使用することで、対象となるレプリカが永続的なイベントを調整できるようにします。マルチレプリカ構成のデプロイメントでは、`USE_REDIS_STREAMS=true` を設定してRedisベースの再開可能なストリームを有効にする必要があります。共有ストリームがない場合、他のレプリカが再開または停止できない可能性のある処理を受け入れる代わりに、スケジュール書き込みは失敗（fail closed）します。

「Ask User（ユーザーへの質問）」やツール承認のために一時停止できるスケジュールされたAgentには、共有アクション状態のための `USE_REDIS_STREAMS=true` と、グラフ継続のための永続的な共有チェックポインターが必要です。これは単一プロセスでのデプロイであっても同様です。組み込みのデフォルトであるMongoDBチェックポインターはこの要件を満たしますが、`type: memory` は満たしません。共有ストアのいずれかが利用できない場合、LibreChatはモデルの処理が開始される前に実行を拒否します。

Redisを使用せずにLibreChatプロセスを1つだけ実行するデプロイメントでは、以下を選択できます：

```bash filename=".env"
SCHEDULES_SINGLE_PROCESS=true
```

マルチプロセスまたはマルチレプリカのデプロイメントでは、これを設定しないでください。レガシーな実験的クラスタサーバーエントリーポイントはスケジュールエンジンを有効にしません。水平スケーリングには、Redisバックエンドのストリームを使用したLibreChatの標準サーバーエントリーポイントを使用してください。

デプロイ全体で即座に停止するには、`SCHEDULES_DISABLED=true` を設定します。これにより、スケジュール定義を削除することなく、自動実行および**今すぐ実行**がブロックされます。詳細は[Scheduled Chats environment variables](/docs/configuration/dotenv#scheduled-chats)を参照してください。

[`admissionConcurrency`、`mcpPreflightConcurrency`、および `mcpPreflightTimeoutMs`](/docs/configuration/librechat_yaml/object_structure/interface#schedules) を使用して、生成の同時実行数とは独立して、スケジュールの受け入れおよび MCP の準備作業の制限を設定します。
