Der Code Interpreter führt Code in einer isolierten Sandbox aus. Agenten nutzen ihn, um Berechnungen durchzuführen, für die sie sonst nur raten würden, eine hochgeladene Tabelle zu analysieren, Dateien zu konvertieren oder Diagramme und Dokumente zu erstellen. Sie können außerdem selbst einen Codeblock aus einer Chatnachricht mit **Run Code** ausführen.

Die Sandbox ist ein separater Dienst, [ClickHouse/code-interpreter](https://github.com/ClickHouse/code-interpreter) (Open Source, Apache 2.0), den dein Administrator neben LibreChat bereitstellt. Sie unterstützt Python, Node.js (JavaScript und TypeScript), Go, C und C++, Java, PHP, Rust und Fortran.

## Einem Agenten Codeausführung gewähren [#give-an-agent-code-execution]

Im Agent Builder wählst du neben **Tools** die Option **Add** und fügst **Run Code** hinzu. Speichere den Agenten. Ab diesem Zeitpunkt entscheidet der Agent selbst, wann er Code ausführt; du musst dies nicht ausdrücklich anfordern, auch wenn "use code to check this" hilfreich ist, wenn du eine exakte Antwort möchtest.

Während der Code ausgeführt wird, zeigt die Nachricht eine einklappbare Zeile mit der Beschriftung **Starting sandbox environment** beim ersten Mal, danach **Analyzing** und **Finished analyzing**, sobald die Ausführung abgeschlossen ist. Klappen Sie sie auf, um den vom Agenten geschriebenen Code und dessen **Output** zu sehen.

## Mit Dateien arbeiten [#working-with-files]

Hänge eine Datei an und wähle **In Code-Umgebung hochladen**, um sie für diese Unterhaltung in der Sandbox verfügbar zu machen. Dateien, die du unter den Run-Code-Einstellungen des Agenten hinzufügst, sind in jedem Chat mit diesem Agenten verfügbar. Vor jedem Durchlauf stellt LibreChat die Dateien der Unterhaltung in der Sandbox wieder her; falls keine der für den Durchlauf benötigten Dateien wiederhergestellt werden kann, stoppt der Durchlauf und fordert dich auf, sie erneut anzuhängen, anstatt mit veralteten Kopien zu arbeiten.

Dateien, die der Code erstellt, erscheinen als Zeilen in der Nachricht. Klicken Sie auf eine Zeile, um sie im [Artifacts](/docs/features/artifacts)-Bereich zu öffnen, oder laden Sie sie herunter. HTML, Markdown, Klartext, Quellcode, CSV und Office-Dateien (Word, Excel, OpenDocument, PowerPoint-Präsentationen und -Vorlagen) erhalten eine Vorschau direkt im Chat. Größere Dateien werden nicht in der Vorschau angezeigt und bleiben nur zum Herunterladen verfügbar; die Standardgrenze liegt bei 2 MiB Quelldatei. Bilder, die der Agent aus der Sandbox liest (PNG, JPEG, GIF, WebP), werden bis zu 1 MiB direkt angezeigt; größere Bilder verbleiben in der Sandbox, wo der Agent sie weiterhin verarbeiten kann.

## Einen Codeblock selbst ausführen [#run-a-code-block-yourself]

Codeblöcke in Chatnachrichten haben neben **Copy code** eine Schaltfläche **Run Code**, wenn die Sprache des Blocks von der Sandbox ausgeführt werden kann (Python, JavaScript, TypeScript, Go, C, C++, D, Java, PHP, Rust oder Fortran). Klicken Sie darauf, und die Ausgabe erscheint unter dem Block. Dies funktioniert in jeder Unterhaltung, nicht nur bei Agenten.

## Lang laufender Code [#long-running-code]

Wenn Ihr Administrator Hintergrund-Tools aktiviert hat, zeigen die Einstellungen von Run Code des Agenten **Hintergrundausführung** an, standardmäßig eingeschaltet. Der Agent kann langsamen Code starten, weiterhin mit Ihnen kommunizieren und die Ausgabe sowie die Dateien abrufen, sobald der Lauf abgeschlossen ist; standardmäßig erscheint das Ergebnis von selbst in einer Folgenachricht. Deaktivieren Sie die Einstellung für Agenten, die immer auf ihren Code warten sollen.

Speicher, CPU-Zeit, Upload-Größe und Netzwerkzugriff werden vom Betreiber des Sandbox-Dienstes festgelegt, nicht von LibreChat. Wenn Code mit einem Ressourcenfehler fehlschlägt, fragen Sie Ihren Administrator, welche Grenzwerte gelten.

## Zustandsbehaftete Code-Sitzungen [#stateful-code-sessions]

Standardmäßig ist jeder Durchlauf zustandslos: Verlassen Sie sich nicht darauf, dass Variablen oder installierte Pakete den nächsten Durchlauf überdauern. Zustandsbehaftete Code-Sitzungen, eine experimentelle Funktion, die Ihr Administrator aktivieren muss, stellen einem Agenten einen Arbeitsbereich bereit, der seine Dateien zwischen den Durchläufen unter `/mnt/data` speichert. Jeder Durchlauf startet trotzdem einen neuen Prozess, und der Arbeitsbereich kann jederzeit zurückgesetzt werden. Behandeln Sie ihn daher als Zwischenablage für temporäre Daten und nicht als Speicher.

Aktiviere **Stateful code sessions** in den Run-Code-Einstellungen des Agenten und wähle eine **Stateful environment** aus:

- **Benutzer-Workspace (empfohlen)**: ein Workspace für dich, der von allen zustandsbehafteten Agenten genutzt wird, die du verwendest.
- **Agent + Benutzer-Arbeitsbereich**: ein eigener Arbeitsbereich für jeden Agenten.
- **Gesprächsarbeitsbereich**: ein eigener, neuer Arbeitsbereich für jede Unterhaltung.

Neue Agenten übernehmen den Geltungsbereich, der unter **Einstellungen > Daten & Datenschutz > Codeausführung > Standard-Workspace mit Zustand** festgelegt ist; eine Änderung dieser Einstellung wirkt sich nicht auf bestehende Agenten aus. Dateien, die der Agent in einem Workspace mit Zustand erstellt oder bearbeitet, werden in einer Zeile **Workspace-Änderungen** in seiner Antwort aufgelistet, mit einem Download-Link für jede Datei.

## Code auf deinem eigenen Rechner ausführen [#running-code-on-your-own-machine]

Admins können außerdem Code-Umgebungen anbieten: eine VM oder Workstation, auf der der `@librechat/code`-Worker läuft, der sich nach außen mit LibreChat verbindet. In diesem Fall zeigt der Agent Builder einen **Execution environment**-Auswahlpunkt an, und über **Machines available in new chats** kann ein Agent mehrere Maschinen anbieten, sodass jeder neue Chat mit **Choose another machine** eine davon auswählen kann.

Wenn Sie die Berechtigung zur Verwaltung von Code-Umgebungen besitzen, fügen Sie unter **Einstellungen > Daten & Datenschutz > Codeausführung > Code-Umgebungen** eine eigene hinzu: Geben Sie ihr einen Namen, wählen Sie **VM verbinden** aus und führen Sie auf Ihrem Rechner den einmaligen Befehl aus, den Ihnen angezeigt wird. Wenn Ihr Administrator die Browser-Einrichtung aktiviert hat, kann der Einrichtungsbefehl stattdessen eine Seite **Maschineneinrichtung genehmigen** öffnen, auf der Sie die Anfrage bei angemeldetem Konto bestätigen.

Auf einem angebundenen Rechner kann der Agent im ausgewählten Arbeitsbereich Dateien durchsuchen, lesen, suchen und bearbeiten sowie Shell-Befehle ausführen. Chat-Anhänge, die Sie hochladen, werden vor dem Start des Agenten in `.librechat/attachments` in diesem Arbeitsbereich kopiert. Da diese Aktionen einen realen Rechner verändern, zeigt das Eingabefeld für die Unterhaltung einen **Code-Genehmigungsmodus** an:

- **Vor Änderungen fragen**: fragt vor Dateibearbeitungen und Befehlen nach.
- **Änderungen akzeptieren**: Bearbeitet Dateien ohne Rückfrage, fragt aber weiterhin vor Befehlen nach.
- **Voller Zugriff**: Bearbeitet Dateien und führt Befehle ohne routinemäßige Rückfragen aus. Die Sandbox-Beschränkungen des Rechners gelten weiterhin.

Welche Modi Sie auswählen können, hängt von der Richtlinie Ihres Administrators ab. Das Koppeln eines Rechners authentifiziert den Worker gegenüber LibreChat; es isoliert nichts. Isolieren Sie den Worker daher so, wie Sie jeden Rechner isolieren würden, auf dem nicht vertrauenswürdiger Code ausgeführt wird.

## Tools aus Code über MCP aufrufen [#calling-mcp-tools-from-code]

Mit Programmatic Tool Calling kann ein Agent ausgewählte MCP-Tools aus der Sandbox heraus aufrufen: Er schreibt ein Skript, das über Eingaben iteriert, Tools aufruft, die Ergebnisse filtert und nur das Relevante zurückgibt. Dadurch entfällt für jeden Tool-Aufruf ein Hin- und Rückweg über das Modell. Die Programmatic-Schalter bleiben deaktiviert, bis der Agent Run Code besitzt, und wenn Run Code entfernt wird, werden sie zurückgesetzt. Während das Skript läuft, können Sie seine Zeile aufklappen, um einen **Tool calls**-Verlauf zu verfolgen; dieser Verlauf wird nach einem Neuladen der Seite nicht gespeichert. Auf diese Weise können nur Tools aufgerufen werden, die dem Agenten zugeordnet sind. Informationen dazu, wie Tools markiert werden, finden Sie unter [Programmatic Tool Calling](/docs/features/agents#programmatic-tool-calling).

## Einrichtung [#setup]

Die Codeausführung erfordert, dass ein Administrator den Code-Interpreter-Dienst bereitstellt und LibreChat darauf verweist; bis dahin schlagen Ausführungen fehl. Die Schaltfläche **Run Code** sowie die Agentenfunktion können zudem pro Rolle deaktiviert werden. Hintergrundausführung, zustandsbehaltende Sitzungen und Code-Umgebungen müssen jeweils aktiv eingeschaltet werden. Siehe [Code-Interpreter-Konfiguration](/docs/configuration/tools/code_interpreter).
