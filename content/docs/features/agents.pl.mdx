Agent to zapisana konfiguracja: model, prompt systemowy oraz narzędzia i pliki, z których może korzystać. Tworzysz go raz w Kreatorze agentów, a następnie wybierasz go za każdym razem, gdy rozpoczynasz czat. Agenci działają z każdym skonfigurowanym dostawcą, a nie tylko z OpenAI.

## Utwórz agenta [#create-an-agent]

<Steps>
  <Step>
    Otwórz **Kreator agentów** z panelu bocznego i kliknij **Utwórz nowego agenta**.
  </Step>
  <Step>
    Podaj nazwę, opcjonalny opis i wybierz **Model** oraz **Category**. Model i kategoria są wymagane.
  </Step>
  <Step>
    Napisz instrukcje. Możesz wpisać je bezpośrednio w polu tekstowym lub przełączyć źródło na **Prompt**, aby użyć zapisanego promptu z biblioteki promptów (patrz poniżej).
  </Step>
  <Step>
    Dodaj narzędzia w sekcji **Tools** (zobacz poniżej), a następnie kliknij **Create**.
  </Step>
</Steps>

Przesyłanie plików do wyszukiwania w plikach lub kontekstu pliku działa dopiero po utworzeniu agenta.

Aby rozmawiać z agentem, wybierz go w selektorze modeli, otwórz go z [Marketplace agentów](#agent-marketplace) lub wpisz `@` w polu czatu i wybierz go z listy. W selektorze agentów w kreatorze opcja **Moje agenty** zawęża listę do agentów utworzonych przez Ciebie.

### Instrukcje z zapisanego promptu [#instructions-from-a-saved-prompt]

Przy źródle instrukcji ustawionym na **Prompt** wybierz prompt w sekcji **Select a prompt** oraz **Version**: albo wersję produkcyjną, która podąża za tym, co właściciel promptu oznaczy jako produkcyjną, albo stałą, zapisaną wersję. Aby to zrobić, potrzebujesz dostępu do biblioteki promptów. Jeśli ktoś inny otworzy agenta bez dostępu do powiązanego promptu, kreator wyświetli komunikat **Restricted prompt** i pozwoli mu zastąpić prompt lub wrócić do instrukcji wpisanych bezpośrednio.

Instrukcje, zarówno wbudowane, jak i powiązane linkami, mogą korzystać z `{{current_date}}`, `{{current_datetime}}` i `{{iso_datetime}}`. Wartości te są wypełniane jednorazowo na początku każdej tury i pozostają niezmienione podczas wywołań narzędzi, podagentów oraz pauz oczekujących na zatwierdzenie. Pierwsze dwa używają Twojej strefy czasowej; `{{iso_datetime}}` jest w czasie UTC.

### Parametry modelu [#model-parameters]

Panel modelu udostępnia te same parametry, co zwykły czat dla danego dostawcy (temperatura, maksymalna liczba tokenów wyjściowych itd.), a także **Image Detail** dla wejścia wizualnego. Wartości zapisane w tym miejscu obowiązują we wszystkich rozmowach z agentem.

### Propozycje rozpoczęcia rozmowy [#conversation-starters]

W sekcji **Conversation Starters** możesz dodać maksymalnie cztery podpowiedzi. Pojawiają się one jako przyciski na pustym ekranie czatu, gdy ktoś rozpoczyna nowy czat z agentem, a kliknięcie jednej z nich natychmiast wysyła ją do agenta. Podpowiedzi agenta zastępują wszystkie podpowiedzi zdefiniowane w specyfikacji modelu (model spec) używanej w danym momencie. Pojawiają się również w szczegółach agenta w Marketplace.

### Historia wersji [#version-history]

Każdy zapis zmieniający agenta dodaje wpis do **Historii wersji**, która pokazuje, kiedy zapisano każdą wersję oraz jakie narzędzia i możliwości zawierała. **Przywróć** zastępuje bieżącą konfigurację tą wersją po potwierdzeniu. Tylko użytkownicy, którzy mogą edytować agenta, widzą tę funkcję.

## Narzędzia [#tools]

Kliknij **Add** obok nagłówka **Tools** w kreatorze (wyświetla się **No tools yet**, dopóki nie dodasz narzędzia), aby otworzyć **Tool Library**. Możesz w niej wyszukiwać lub filtrować według **Native**, **Tools**, **MCP servers** lub **Actions**. **Made by you** zbiera serwery MCP i Actions, które utworzyłeś, a **Favorites** przechowuje oznaczone gwiazdką elementy, aby były pod ręką we wszystkich agentach (do 100). Menu **Create new…** pozwala dodać serwer MCP lub Action bez opuszczania okna, o ile Twoja rola na to zezwala. To, co widzisz, zależy od tego, co administrator włączył, oraz od uprawnień Twojej roli; element, który nadal wymaga klucza API, wyświetla status **Needs setup**.

Run Code, File Search i File Context przechowują pliki. Dopóki mają dołączone pliki, ich usunięcie otwiera zamiast tego menedżera plików, a pliki pozostają przypisane do agenta, dopóki nie zostaną usunięte.

### Code Interpreter [#code-interpreter]

Wyświetlane jako **Run Code**. Agent pisze i uruchamia kod w piaskownicy (sandbox), co jest przydatne do obliczeń, analizy danych oraz tworzenia plików, takich jak wykresy czy arkusze kalkulacyjne. Pliki dołączone do tego narzędzia w kreatorze są dostępne w piaskownicy przy każdym uruchomieniu. Jeśli żadnego z plików kodu z danej rozmowy nie uda się przywrócić do piaskownicy, agent zatrzyma się przed wywołaniem modelu i poprosi o ponowne dołączenie tych plików. Zobacz [Code Interpreter](/docs/features/code_interpreter).

#### Sesje kodu ze stanem [#stateful-code-sessions]

Jeśli administrator je włączył, **Stateful code sessions** w ustawieniach Run Code zachowują obszar roboczy sandboxa między uruchomieniami, dzięki czemu pliki i zainstalowane pakiety są przenoszone. **Stateful environment** określa, kto współdzieli ten obszar roboczy: **User workspace (recommended)** dla wszystkich Twoich agentów stateful, **Agent + user workspace** dla jednego obszaru na każdego agenta lub **Conversation workspace** dla jednego obszaru na każdy czat. Nowi agenci zaczynają od **Default stateful workspace** w sekcji **Settings > Data & Privacy > Code execution**. Jeśli administrator skonfigurował kilka backendów, **Execution environment** wybiera, który z nich uruchamia kod, co może obejmować workera sparowanego na Twoim własnym komputerze.

Przestrzeń robocza może zostać zresetowana w dowolnym momencie, dlatego nie należy traktować jej jako pamięci masowej. W środowiskach zarządzanych zapisuj potrzebne wyniki w `/mnt/data`. Pliki, które agent zapisuje za pomocą swoich narzędzi do obsługi plików, są wymienione przy każdej wiadomości w sekcji **Zmiany w przestrzeni roboczej**, skąd można je pobrać. Przy podłączonym środowisku pole tworzenia wiadomości oferuje **Pytaj przed zmianami**, **Akceptuj edycje** lub **Pełny dostęp** jako tryb zatwierdzania dla danego czatu, w granicach ustalonych przez administratora.

Ta funkcja jest w wysokim stopniu eksperymentalna. Szczegóły znajdziesz w sekcji [stateful code sessions](/docs/features/code_interpreter#stateful-code-sessions).

### Wyszukiwanie w sieci [#web-search]

Agent przeszukuje sieć i podaje źródła swoich informacji. Wymaga dostawcy wyszukiwania skonfigurowanego przez administratora lub Twojego własnego klucza, jeśli administrator tak to ustawił. Zobacz [Wyszukiwanie w sieci](/docs/features/web_search).

### Wyszukiwanie plików [#file-search]

Zamienia pliki, które dołączasz, w bazę wiedzy z możliwością przeszukiwania. Agent pobiera najbardziej trafne fragmenty, gdy ich potrzebuje, dzięki czemu radzi sobie z dużymi zbiorami dokumentów. Słabo nadaje się do danych ustrukturyzowanych, takich jak CSV czy Excel, gdzie lepiej sprawdza się Run Code. Wymaga [RAG API](/docs/features/rag_api).

### Kontekst pliku [#file-context]

Pliki dodane w sekcji **File Context** są analizowane pod kątem tekstu jednorazowo, w momencie przesłania, a wyodrębniony tekst trafia do kontekstu agenta przy każdej wiadomości. Używaj tej funkcji dla kilku kluczowych dokumentów, które agent powinien mieć zawsze przed oczami. Ekstrakcja działa tak samo jak w przypadku [Upload as Text](/docs/features/upload_as_text): domyślnie jest to parsowanie zwykłego tekstu, a lepsze wyniki na skanach i obrazach uzyskuje się, jeśli skonfigurowano [OCR](/docs/features/ocr).

Ponieważ tekst jest dołączany do każdej wiadomości, duże pliki w tym miejscu generują koszty tokenów przy każdej turze rozmowy. Każdy, kto może rozmawiać z agentem, może również wydobyć ten tekst z jego odpowiedzi.

### Artifacts [#artifacts]

Pozwala agentowi renderować React, HTML, SVG, Markdown i Mermaid w panelu bocznym, zamiast jako bloki kodu. Ustawienie **Mode** wybiera wbudowane instrukcje: **Normal**, **shadcn/ui** (dodaje instrukcje dotyczące biblioteki komponentów shadcn/ui) lub **Custom**, które nie wstawia niczego, więc Twoje własne instrukcje muszą nauczyć składni artefaktów. Składnię tę opisano w sekcji [Artifacts](/docs/features/artifacts).

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

Serwery MCP skonfigurowane przez administratora lub dodane przez Ciebie samodzielnie pojawiają się w sekcji **MCP servers**. Dodanie serwera przypisuje wszystkie jego narzędzia; rozwiń go w sekcji **Tools in this server**, aby wybrać tylko te, których potrzebuje agent. Zobacz [MCP](/docs/features/mcp).

Niektóre serwery mogą wyświetlić listę swoich narzędzi dopiero podczas czatu, ponieważ zależą od wartości przekazanych w żądaniu. W takim przypadku kreator oferuje jeden wybór dla wszystkich narzędzi serwera zamiast przełączników dla poszczególnych narzędzi. Jeśli wszystkie wybrane przez agenta narzędzia MCP nie zostaną załadowane w momencie rozpoczęcia uruchomienia, uruchomienie zostaje zatrzymane i wyświetla komunikat z prośbą o ponowne połączenie się z serwerem lub zalogowanie do niego, zamiast kontynuować bez nich.

Każde narzędzie MCP ma menu **Opcje narzędzia** z kilkoma przełącznikami dla poszczególnych narzędzi:

- **Defer**: zobacz [Narzędzia odroczone](#deferred-tools). **Odrocz wszystkie narzędzia** robi to dla całego serwera.
- **Programistyczne**: zobacz [Programistyczne wywoływanie narzędzi](#programmatic-tool-calling).
- **Tło**: zobacz [Wywołania narzędzi w tle](#background-tool-calls).
- **Etykieta intencji**: agent zapisuje jednowierszowy opis każdego wywołania, który jest wyświetlany na żywo jako status wywołania zamiast ogólnej etykiety. Dodaje to kilka tokenów do każdego żądania. Narzędzia natywne automatycznie otrzymują etykiety intencji. Nie dotyczy to narzędzi programistycznych.

**Background** i **Intent label** pojawiają się tylko wtedy, gdy administrator je włączył.

### Narzędzia odroczone [#deferred-tools]

Agent z kilkoma serwerami MCP może łatwo mieć kilkadziesiąt definicji narzędzi, a wysyłanie wszystkich z nich przy każdym żądaniu zużywa kontekst i pogarsza zdolność modelu do wybrania właściwego narzędzia. Narzędzie odroczone (deferred tool) nie jest uwzględniane w początkowym żądaniu. Zamiast tego agent otrzymuje narzędzie wyszukiwania narzędzi, które znajduje narzędzia odroczone po nazwie lub opisie, gdy ich potrzebuje, i może używać znalezionego narzędzia przez resztę rozmowy.

### Programowe wywoływanie narzędzi [#programmatic-tool-calling]

Przy włączonym **Programmatic** dla narzędzia MCP (lub całego serwera) model nie wywołuje tego narzędzia bezpośrednio. Zamiast tego pisze kod w piaskownicy Code Interpreter, który wywołuje narzędzie jako funkcję, dzięki czemu może zapętlać operacje, stronicować, ponawiać próby i filtrować wyniki przed udzieleniem odpowiedzi. Ułatwia to zadania takie jak „sprawdź te 40 zgłoszeń i podsumuj otwarte”, które w przeciwnym razie wymagałyby 40 osobnych wywołań narzędzia przez model.

Przełączniki **Programmatic** pozostają wyłączone, dopóki nie włączysz opcji Run Code, a usunięcie Run Code czyści je. Piaskownica może wywoływać wyłącznie narzędzia zarejestrowane w agencie. Podczas działania rozwiń kartę kodu, aby na żywo śledzić każde wewnętrzne wywołanie narzędzia; ślad nie jest zachowywany po przeładowaniu strony. Ta funkcja jest domyślnie wyłączona — aby ją włączyć, musi to zrobić administrator.

### Wywołania narzędzi w tle [#background-tool-calls]

Narzędzie obsługujące działanie w tle zwraca od razu odniesienie do zadania, dzięki czemu agent może kontynuować pracę podczas jego wykonywania. Gdy zadanie się zakończy, wynik jest automatycznie dostarczany w kolejnej turze rozmowy (wyświetlany jako rozwijana karta zadania) lub agent może sprawdzić jego stan za pomocą narzędzia zadań. Dane wyjściowe i pliki z działania w tle pojawiają się przy oryginalnym wywołaniu narzędzia. Narzędzia, które mogą być uruchamiane w tle:

- **Uruchom kod**: kod i polecenia powłoki są domyślnie dozwolone; aby z tego zrezygnować, wyłącz opcję **Wykonywanie w tle** w jej ustawieniach.
- **Narzędzia MCP**: oznacz narzędzie lub cały serwer jako **Tło**.
- **Inne narzędzia i Akcje**: włącz **Wykonywanie w tle**. Akcje korzystające z OAuth tej opcji nie oferują.

Te przełączniki umożliwiają wykonywanie zadań w tle; model i tak decyduje o każdym wywołaniu osobno. Zadania w tle są uruchamiane w procesie serwera, który je rozpoczął, i zostaną utracone, jeśli ten proces przestanie działać. Aby z tej funkcji można było korzystać, administrator musi ją najpierw włączyć.

### Actions [#actions]

Akcje zamieniają specyfikację OpenAPI w narzędzia. Wybierz **Utwórz nowe…**, a następnie **Akcje**, wklej schemat i skonfiguruj **Uwierzytelnianie**, jeśli API tego wymaga. Każda operacja zdefiniowana w specyfikacji staje się narzędziem, którego agent może użyć.

Jeśli używasz modelu OpenAI, dodaj `x-strict: true` do operacji w specyfikacji, a LibreChat zażąda dla niej strict function calling. Tryb strict akceptuje tylko podzbiór JSON Schema; zobacz [przewodnik po structured outputs](https://platform.openai.com/docs/guides/structured-outputs) OpenAI.

Akcje mogą łączyć się wyłącznie z domenami dopuszczonymi przez administratora, a adresy sieci prywatnej są blokowane, chyba że zostaną jawnie zezwolone.

### Umiejętności [#skills]

Sekcja **Skills** w kreatorze określa, z których [Skills](/docs/features/skills) może korzystać agent: **Wyłączone**, **Wszystkie** (każdy aktywny skill, który masz) lub **Wybrane** (tylko te, które dodasz).

### Pamięć [#memory]

**Pamięć** pozwala agentowi zapisywać, aktualizować i usuwać wspomnienia o Tobie, gdy poprosisz go o zapamiętanie lub zapomnienie czegoś. Wymaga to skonfigurowania pamięci na instancji oraz zezwolenia na jej użycie dla Twojej roli. Domyślnie agent udostępnia Twoje osobiste wspomnienia pozostałym czatom; włącz opcję **Keep memories separate for this agent**, aby nadać mu własne wspomnienia, które tylko on odczytuje i zapisuje. Zobacz [Pamięć](/docs/features/memory).

### Zapytaj użytkownika i zatwierdzanie narzędzi [#ask-user-and-tool-approval]

**Zapytaj użytkownika** pozwala agentowi wstrzymać działanie w trakcie wykonywania zadania, aby zadać pytanie i poczekać na odpowiedź. Jedno wstrzymanie może zawierać do czterech pytań, wyświetlanych pojedynczo za pomocą przycisków **Wstecz** i **Dalej**; na każde można odpowiedzieć w dowolnej formie tekstowej lub wybrać jedną z opcji zaproponowanych przez agenta. Przycisk **Pomiń** odrzuca wszystkie pytania. Zadanie wznawia się natychmiast po przesłaniu odpowiedzi, a Twoje odpowiedzi są zachowywane nawet wtedy, gdy zatrzymasz działanie podczas ponownego uruchamiania.

Your admin can also require approval before certain tools run. The run pauses, you review the call in a panel above the message box (approve, reject, or for some tools edit the arguments), and it continues. If the admin has enabled per-agent approval modes, each tool on the agent gets a **Tool approval mode**: **Use inherited policy**, **Always ask**, **Always approve**, **Ask once per chat**, or **Ask once, then always approve**. Admin rules still apply on top, and **Reset my remembered approvals** clears what you have approved before.

### Inne narzędzia [#other-tools]

Kategoria **Tools** zawiera wbudowane integracje, które administrator włączył, takie jak [generowanie obrazów](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search) i [Azure AI Search](/docs/configuration/tools/azure_ai_search). Każda z nich jest konfigurowana osobno; zobacz [Tools](/docs/configuration/tools).

## Praca z innymi agentami [#working-with-other-agents]

**Subagenci** pozwalają agentowi przekazać wyspecjalizowane podzadanie świeżej kopii samego siebie lub innemu agentowi, w oddzielnym oknie kontekstowym. Wraca tylko wynik, dzięki czemu długie dane wyjściowe narzędzi nie trafiają do głównej rozmowy. Zobacz [Subagenci](/docs/features/subagents).

### Przekazania [#handoffs]

**Przekazania** (handoffs) dają agentowi narzędzie przekazania dla każdego wymienionego agenta, dzięki czemu może on przekazać rozmowę specjaliście, gdy temat tego wymaga. Dla każdego przekazania możesz dodać opis (kiedy przekazać) oraz treść przekazywaną dalej (co agent ma wygenerować i przekazać), a także zmienić nazwę parametru, w którym ta treść jest przekazywana (domyślnie `instructions`). Agent może mieć maksymalnie 10 przekazań. Przekazania są zawsze dostępne; nie zależą od ustawienia administratora.

### Łańcuch agentów [#agent-chain]

Łańcuchy agentów są przestarzałe. Istniejące łańcuchy nadal działają, a kreator wyświetla je w sekcji **Ustawienia zaawansowane** z przyciskiem **Usuń łańcuch**, ale nie można tworzyć nowych. Zamiast tego użyj podagentów lub przekazań.

## Maksymalna liczba kroków agenta [#max-agent-steps]

**Ustawienia zaawansowane** zawierają pole **Max Agent Steps**, które ogranicza liczbę kroków, jakie agent może wykonać, zanim będzie musiał udzielić ostatecznej odpowiedzi. Krok to jedno żądanie do modelu lub jedna runda wywołań narzędzi, dlatego pojedyncze wywołanie narzędzia zazwyczaj zużywa trzy kroki: żądanie, rundę narzędzia i kolejne żądanie.

Zostaw to pole puste, aby użyć wartości domyślnej serwera, która wynosi 50, chyba że administrator ją zmienił. Administrator może również ustawić górny limit, którego to pole nie może przekroczyć.

Gdy tura wyczerpie limit kroków, zachowujesz to, co agent zrobił do tej pory, a wiadomość oferuje **Kontynuuj** (nowa tura z nowym budżetem) lub **Odpowiedz teraz** (agent udziela odpowiedzi na podstawie dotychczasowej pracy, bez dalszego używania narzędzi). Jeśli taka sytuacja często występuje przy długich łańcuchach wywołań narzędzi, zwiększ limit.

## Po długim uruchomieniu [#following-a-long-run]

Karty narzędzi pokazują **Preparing** (Przygotowywanie), dopóki wywołanie czeka (na przykład na zatwierdzenie), a następnie **Calling** (Wywoływanie), aż wynik zostanie zwrócony. Dane wyjściowe powłoki są wyświetlane w stylu terminala i zwinięte do ostatnich 15 wierszy; przycisk **Show more** (Pokaż więcej) rozwija je, a polecenie, które zakończyło się niepowodzeniem, pokazuje swój kod wyjścia, sygnał lub informację o przekroczeniu limitu czasu.

### Grupy aktywności [#activity-groups]

Jeśli administrator włączył tę opcję, każdy fragment rozumowania i wywołań narzędzi zwija się pod wygenerowanym jednowierszowym nagłówkiem, dzięki czemu przebieg z 30 wywołaniami narzędzi wygląda jak kilka linii. Aby zobaczyć wywołania wewnątrz nagłówka, rozwiń go. Drugi poziom może łączyć kilka takich grup w fazę z własnym podsumowaniem, co daje długim przebiegom strukturę konspektu. Gdy dwie grupy zostaną zakończone, łączą się od razu, a najnowszy nagłówek zastępuje je do momentu nadejścia podsumowania. Ostateczna odpowiedź zawsze pozostaje poza zwinięciem, a pliki utworzone w ramach fazy są wyświetlane w rzędzie pod nią, zamiast być ukryte. Przy włączonym [Smooth Streaming](/docs/features/smooth_streaming) zwijanie jest animowane, chyba że urządzenie żąda ograniczenia ruchu.

Opcje etykiet na żywo są powiązaną funkcją: zamiast ogólnego nagłówka **Thinking** blok rozumowania pokazuje krótkie, aktualizowane podsumowanie tego, nad czym pracuje model.

Nagłówki, podsumowania etapów i etykiety rozumowania generują dodatkowe wywołania modelu, które są rejestrowane tak jak każde inne użycie. Administratorzy konfigurują je w [grupach aktywności agenta](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) oraz [etykietach rozumowania na żywo](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Sterowanie i kolejkowanie wiadomości [#steering-and-queued-messages]

Podczas gdy agent odpowiada, nadal możesz wysyłać wiadomości:

- **Steer** wstawia wiadomość do bieżącego uruchomienia w najbliższym bezpiecznym punkcie, dzięki czemu agent może się dostosować, zanim zakończy działanie.
- **Przerwanie** anuluje trwające wywołania narzędzi i rozumowanie, zachowuje to, co zostało już wykonane, i kontynuuje z Twoją wiadomością. Efektów, które już wystąpiły poza LibreChat, nie da się cofnąć. Niektórych działań, na przykład tych korzystających z wbudowanego wyszukiwania dostawcy, nie można przerwać — wiadomość czeka wtedy jako korekta w trakcie działania.
- **Kolejka** przechowuje wiadomość i wysyła ją jako zwykłą turę po zakończeniu odpowiedzi.

**Podczas generowania** **Enter zrobi** w sekcji **Ustawienia > Czat** wybiera wartość domyślną, a menu przycisku wysyłania nadpisuje ją dla każdej wiadomości; `Alt + Enter` przerywa. Kolejkowane wiadomości są wyświetlane nad polem wprowadzania, gdzie można je edytować, usuwać, zmieniać ich kolejność, **Wyślij teraz** lub **Przerwij teraz**. Pliki i cytowane fragmenty są dołączane do wiadomości; umiejętności wybrane za pomocą `$` czekają na następną pełną turę. Kolejkowane wiadomości w zapisanym czacie agenta są przechowywane na serwerze i zachowują się nawet po zamknięciu przeglądarki.

Czat może przechowywać do 100 wiadomości w kolejce (każda do 16 000 znaków i 10 plików), a jedno uruchomienie obsługuje do 10 oczekujących poprawek. Szczegółowe informacje o potwierdzeniach i elementach sterujących znajdziesz w sekcji [Composer](/docs/features/composer).

## Pliki w czacie [#files-in-a-chat]

Gdy rozmawiasz z agentem, menu załączania oferuje:

- **Prześlij obraz**: wysyłany do modelu w celu analizy wizualnej.
- **Prześlij jako tekst**: pełny tekst trafia wyłącznie do tej rozmowy. Zobacz [Prześlij jako tekst](/docs/features/upload_as_text).
- **Przesyłanie dla wyszukiwania plików**: indeksowane do wyszukiwania, podobnie jak pliki wyszukiwania plików agenta, ale ograniczone do tego czatu.
- **Prześlij do środowiska kodu**: kopiowany do piaskownicy (sandbox) w celu uruchomienia kodu. Najlepsze dla plików CSV, Excel i JSON.

Opcje pojawiają się tylko wtedy, gdy odpowiednia funkcja jest włączona.

## Udostępnianie i uprawnienia [#sharing-and-permissions]

Agenci są prywatni dla swojego autora, dopóki nie zostaną udostępnieni. Kliknij **Udostępnij** w stopce kreatora, aby przyznać dostęp użytkownikom, grupom lub rolom, z których każdy otrzymuje jedną z trzech ról:

| Rola | Co może robić |
| ---- | ------------- |
| Przeglądający (Viewer) | Rozmawiać z agentem. Nie może otworzyć go w kreatorze ani zobaczyć jego instrukcji, narzędzi czy plików. |
| Edytujący (Editor) | Wszystko, co może przeglądający, oraz zmieniać instrukcje, model, narzędzia i pliki. |
| Właściciel (Owner) | Wszystko, co może edytujący, oraz usuwać agenta i zmieniać listę osób, z którymi jest udostępniony. |

**Udostępnij wszystkim** sprawia, że agent jest dostępny dla każdego użytkownika instancji; wymaga uprawnienia do publicznego udostępniania. Autor oraz administratorzy zawsze zachowują pełną kontrolę.

Widz nie może zobaczyć instrukcji ani plików w kreatorze, ale model nadal może je powtórzyć w rozmowie, jeśli zostanie o to poproszony. Nie umieszczaj w agencie niczego, czego jego widzowie nigdy nie powinni zobaczyć.

Osobno przycisk z ikoną globu (**Remote Access**) określa, kto może wywoływać agenta za pośrednictwem [Agents API](/docs/features/agents_api).

Karty agentów pokazują dane kontaktowe wsparcia ustawione w kreatorze. Jeśli nie zostały ustawione, mogą wyświetlać imię i nazwisko właściciela, ale nigdy adres e-mail właściciela, chyba że został wprowadzony jako kontakt.

Zobacz [Kontrola dostępu](/docs/features/access_control), aby dowiedzieć się, jak użytkownicy, grupy i role współdziałają ze sobą.

### Kontrolki administratora [#administrator-controls]

Czy dana rola może korzystać z agentów, tworzyć je, udostępniać lub udostępniać publicznie, ustawia się dla każdej roli w [Panelu administratora](/docs/features/admin_panel). Administratorzy otrzymują także przycisk **Ustawienia administratora** u dołu Kreatora agentów, z tymi samymi przełącznikami, dla każdej roli. W instancji jednoprocesowej (single-tenant) pierwsze zarejestrowane konto jest kontem administratora; aby dodać kolejnych, zobacz [Nadawanie uprawnień kolejnemu administratorowi](/docs/configuration/access_control#promote-another-admin).

## Marketplace agentów [#agent-marketplace]

**Agent Marketplace** w panelu bocznym wyświetla listę agentów dostępnych dla Ciebie, jeśli Twoja rola pozwala na korzystanie z niego. Możesz wyszukiwać agentów według nazwy lub opisu, filtrować ich według kategorii (**Top Picks**, **All** lub wybranej konkretnej kategorii) oraz zmieniać kolejność za pomocą opcji **Sort by**: **Newest first**, **Oldest first**, **Popular** lub **By creator name**. **My agents** pokazuje wyłącznie Twoich agentów. Wyszukiwanie, sortowanie i filtrowanie są zapisywane w adresie URL, dzięki czemu możesz dodać widok do zakładek lub udostępnić go innej osobie.

Kliknij kartę, aby zobaczyć szczegóły oraz dostępne działania: **Pin** lub **Unpin** (przypnij lub odepnij), **Copy Link** (skopiuj link, który otwiera nowy czat z agentem) oraz **Start Chat** (rozpocznij czat). Kliknięcie jednego z przykładowych początków rozmowy agenta otwiera nowy czat z tekstem promptu w polu wiadomości, bez wysyłania, dzięki czemu można go najpierw edytować.

## Agents API [#agents-api]

Agentów można również wywoływać z poziomu skryptów i innych aplikacji za pośrednictwem API zgodnego z OpenAI, zarządzać nimi za pomocą zaufanych usług oraz uruchamiać w odpowiedzi na zdarzenia z innych systemów. Zobacz [Agents API](/docs/features/agents_api). [Zaplanowane czaty](/docs/features/scheduled_chats) uruchamiają działania agentów według harmonogramu, a [Wtyczki agentów](/docs/features/agent_plugins) pozwalają operatorowi dostarczyć umiejętności i serwery MCP agentom jako jeden pakiet.

## Konfiguracja [#setup]

Agenty są domyślnie włączone. Administratorzy wybierają, które możliwości są udostępniane, limity kroków oraz dozwolonych dostawców w [konfiguracji endpointu agents](/docs/configuration/librechat_yaml/object_structure/agents), a także domeny, do których mogą docierać Actions, w [konfiguracji Actions](/docs/configuration/librechat_yaml/object_structure/actions). Instancje zaktualizowane z wersji wcześniejszych niż v0.8.0-rc3 wymagają [migracji uprawnień](/docs/configuration/access_control#migrating-from-pre-acl-versions).
