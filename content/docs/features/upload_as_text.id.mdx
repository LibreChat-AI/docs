# Unggah File sebagai Teks [#upload-files-as-text]

Pernahkah Anda ingin memberikan PDF, file kode, atau spreadsheet ke AI dan hanya mengatakan _"baca ini"_? Pengunggah terpadu LibreChat mengarahkan file tersebut ke penyedia atau mengekstrak teksnya secara otomatis berdasarkan jenisnya dan endpoint yang dipilih.

Anda melampirkan file, LibreChat mengekstrak teks darinya, dan konten lengkapnya langsung ditempelkan ke dalam percakapan Anda. AI kemudian dapat membaca setiap kata di dalamnya — tanpa plugin, tanpa basis data vektor, tanpa layanan tambahan untuk dikonfigurasi. Fitur ini langsung berfungsi tanpa perlu pengaturan tambahan.

<Callout type="info" title="Tidak perlu pengaturan">
  Upload as Text langsung berfungsi di setiap instance LibreChat. Fitur ini menggunakan parsing teks bawaan — Anda tidak memerlukan OCR, pipeline RAG, atau layanan eksternal apa pun untuk memulai.
</Callout>

---

## Cara menggunakannya [#how-to-use-it]

<Steps>
  <Step>
    ### Buka palet [#open-the-palette]

    Klik **+** di [message composer](/docs/features/composer#add-files). Anda juga dapat menarik file ke dalam composer.
  </Step>
  <Step>
    ### Pilih sumber [#choose-a-source]

    Di bagian **Attach**, pilih **From Local Computer**, atau **From SharePoint** jika sudah dikonfigurasi. Pengunggah default tidak meminta Anda untuk memilih model atau tujuan alat.

    Jika administrator Anda mengaktifkan [`legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), pilih sendiri tujuannya: pilih **More upload options**, lalu **Upload as Text**.
  </Step>
  <Step>
    ### Pilih file Anda [#choose-your-file]

    Pilih file tersebut. LibreChat memilih pengiriman penyedia asli, ekstraksi teks, atau penyimpanan khusus alat berdasarkan jenis file dan kemampuan endpoint.
  </Step>
  <Step>
    ### Ajukan pertanyaan Anda [#ask-your-question]

    Ketik prompt Anda seperti biasa. Alat File Search dan Code yang dipilih hanya akan menerima file tersebut saat mereka membutuhkannya.
  </Step>
</Steps>

Saat Anda memilih beberapa file, LibreChat akan melewati duplikat individual dan file yang melebihi batas ukuran per file, menyebutkan nama file yang dilewati dalam pemberitahuan, serta melanjutkan pengunggahan file yang valid. Batas jumlah file dan total ukuran batch tetap berlaku untuk file yang tersisa; jika batch yang tersisa melebihi salah satu batas tersebut, seluruh batch akan ditolak. Perilaku untuk file tunggal tidak berubah.

<Callout type="warn" title="Tidak melihat opsinya?">
  Dengan `legacyFileUploadUX` diaktifkan, jika **Upload as Text** tidak muncul di bawah **More upload options**, kapabilitas `context` mungkin telah dinonaktifkan oleh admin Anda. Fitur ini aktif secara default, namun jika daftar kapabilitas telah disesuaikan, `context` perlu disertakan secara eksplisit. Lihat [bagian konfigurasi](#the-context-capability) di bawah.
</Callout>

## Tempel teks panjang sebagai file [#paste-long-text-as-a-file]

Di komposer pesan normal, LibreChat dapat mengubah tempelan yang lebih panjang dari 2.500 karakter menjadi lampiran Unggah sebagai Teks (Upload as Text). Hal ini menjaga tempelan besar agar tidak memenuhi input sekaligus tetap menyediakan kontennya ke model melalui konteks percakapan. Lampiran pertama diberi nama `pasted-text.txt`; lampiran teks tempelan tambahan akan menerima nama bernomor.

Pengaturan **Paste long text as a file** (Tempel teks panjang sebagai file) yang bersifat lokal di browser diaktifkan secara default di bawah **Settings > Chat > Sending**. Tempelan teks yang lebih pendek dan teks yang ditempel saat menjawab formulir **Ask User** (Tanya Pengguna) dari Agen akan tetap berada di dalam baris (inline). Jika unggahan konteks tidak tersedia, teks tersebut juga akan tetap berada di dalam baris. Jika unggahan lampiran gagal, LibreChat akan mengembalikan teks tersebut ke komposer jika memungkinkan tanpa menimpa draf yang lebih baru.

Lampiran teks yang ditempel (pasted-text) mengikuti aturan ukuran file, token, dan [`fileTokenLimit`](#token-limits-and-truncation) yang sama seperti file Unggah sebagai Teks (Upload as Text) lainnya.

## Apa yang terjadi di balik layar [#what-happens-under-the-hood]

Saat unggahan diarahkan ke teks, LibreChat tidak membuang byte mentah ke dalam prompt. Unggahan tersebut dijalankan melalui alur pemrosesan untuk mengekstrak teks yang bersih dan dapat dibaca:

1. **Deteksi tipe MIME** — LibreChat memeriksa jenis file yang Anda unggah (PDF, gambar, audio, kode sumber, dll.) dengan memeriksa tipe MIME-nya.
2. **Pemilihan metode** — Berdasarkan jenis file dan layanan apa yang tersedia, sistem akan memilih metode ekstraksi terbaik menggunakan prioritas berikut:

<Tabs items={["Urutan prioritas", "Contoh keputusan"]}>
  <Tabs.Tab>
    | Prioritas | Metode | Kapan digunakan |
    |----------|--------|---------------|
    | 1st | **OCR** | File adalah gambar atau dokumen hasil pindai, _dan_ OCR dikonfigurasi |
    | 2nd | **STT** (Speech-to-Text) | File adalah audio, _dan_ STT dikonfigurasi |
    | 3rd | **Text parsing** | File cocok dengan tipe MIME teks yang dikenal |
    | 4th | **Fallback** | Tidak ada yang cocok di atas — tetap mencoba text parsing |
  </Tabs.Tab>
  <Tabs.Tab>
    **Sebuah `.pdf` pada instans dengan OCR yang dikonfigurasi:**
    → OCR akan aktif. Sangat berguna untuk dokumen hasil pindai dan tata letak yang kompleks.

    **Sebuah `.pdf` pada instans default (tanpa OCR):**
    → Penguraian teks menanganinya. Berfungsi dengan baik untuk PDF yang dibuat secara digital.

    **File Python `.py`:**
    → Langsung ke penguraian teks. Kode sumber sudah berupa teks — tidak perlu konversi.

    **Sebuah `.mp3` pada instans dengan STT yang dikonfigurasi:**
    → Speech-to-Text mentranskripsikannya menjadi teks untuk percakapan tersebut.

    **Sebuah tangkapan layar `.png` tanpa OCR yang dikonfigurasi:**
    → Beralih ke penguraian teks (hasil terbatas — pertimbangkan untuk mengatur OCR untuk gambar).
  </Tabs.Tab>
</Tabs>

3. **Pemotongan token** — Teks yang diekstraksi dipotong hingga `fileTokenLimit` (default: 100.000 token) agar tidak melebihi jendela konteks model.
4. **Prompt injection** — Teks tersebut disertakan ke dalam konteks percakapan, tepat di samping pesan Anda.

Saat Anda melihat pratinjau atau mengunduh lampiran Upload as Text, LibreChat menyajikan teks terekstraksi yang disimpan bersama catatan file tersebut. Unduhan menggunakan nama file `.txt` bahkan ketika OCR atau parser lain menghasilkan teks yang disimpan dan tidak ada file pendukung asli untuk di-stream.

## File apa saja yang didukung [#which-files-are-supported]

<Tabs items={["Teks & kode", "Dokumen", "Gambar", "Audio"]}>
  <Tabs.Tab>
    Ini diurai secara langsung — karena sudah berupa teks, maka tidak diperlukan konversi.

    - Teks biasa (`.txt`), Markdown (`.md`), CSV, JSON, XML, HTML, CSS
    - Bahasa pemrograman — Python, JavaScript, TypeScript, Java, C#, PHP, Ruby, Go, Rust, Kotlin, Swift, Scala, Perl, Lua
    - File konfigurasi — YAML, TOML, INI
    - Skrip shell, file SQL
  </Tabs.Tab>
  <Tabs.Tab>
    Penguraian teks menangani hal ini secara langsung. Jika OCR dikonfigurasi, fitur ini akan mengambil alih untuk akurasi yang lebih baik pada tata letak yang kompleks.

    - **PDF** — digital dan hasil pindai (PDF hasil pindai mendapatkan manfaat dari OCR)
    - **Word** — `.docx`, `.doc`
    - **PowerPoint** — `.pptx`, `.potx`, `.ppt`
    - **Excel** — `.xlsx`, `.xls`
    - Buku **EPUB**
  </Tabs.Tab>
  <Tabs.Tab>
    Gambar **memerlukan OCR** untuk menghasilkan teks yang berguna. Tanpanya, hasilnya akan kurang memuaskan.

    - JPEG, PNG, GIF, WebP
    - HEIC, HEIF (format Apple)
    - Tangkapan layar, foto dokumen, halaman yang dipindai
  </Tabs.Tab>
  <Tabs.Tab>
    File audio **memerlukan STT** untuk dikonfigurasi. Tidak ada fallback — audio tidak dapat "diurai menjadi teks."

    - MP3, WAV, OGG, FLAC
    - M4A, WebM
    - Rekaman suara, klip podcast
  </Tabs.Tab>
</Tabs>

LibreChat menormalisasi varian MIME shell-script yang dilaporkan oleh Chrome di Linux (`application/x-shellscript`) dan libmagic (`text/x-shellscript`) menjadi `application/x-sh` kanonik sebelum memeriksa daftar izin endpoint. Aturan [`supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) kustom harus tetap mengizinkan `application/x-sh`.

## Unggahan terpadu dan penyediaan alat [#unified-uploads-and-tool-provisioning]

Secara default, satu tindakan lampiran menggantikan pemilih tujuan yang lama. LibreChat memutuskan bagaimana file tersebut mencapai model, sementara alat (tools) disediakan secara lazy:

<Cards>
  <Card title="Konteks model" href="#what-happens-under-the-hood">
    File yang didukung mencapai model melalui pengiriman penyedia asli atau teks yang diekstrak, sesuai dengan tipe MIME, kemampuan endpoint, dan konfigurasi deployment.
  </Card>
  <Card title="Unggah untuk Pencarian File (RAG)" href="/docs/features/rag_api">
    Saat File Search dipilih, LibreChat hanya mengindeks lampiran yang memenuhi syarat ketika run memerlukan alat tersebut.
  </Card>
  <Card title="Unggahan Standar" href="/docs/features/agents">
    Saat Code dipilih, LibreChat menyediakan lampiran yang memenuhi syarat ke lingkungan Code hanya saat proses eksekusi membutuhkannya.
  </Card>
</Cards>

Operator dapat memulihkan pemilih tujuan sebelumnya dengan [`fileConfig.legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), atau mengontrol perutean otomatis dengan [`defaultLLMDeliveryPath`](/docs/configuration/librechat_yaml/object_structure/file_config#defaultllmdeliverypath).

**Perutean tipikal:**

| Situasi | Opsi terbaik |
|-----------|-------------|
| _"Baca kontrak 5 halaman ini dan ringkas"_ | Pengiriman PDF asli atau teks yang diekstrak |
| _"Saya punya 50 PDF, temukan yang menyebutkan harga"_ | Penyediaan Lazy File Search |
| _"Apa isi tangkapan layar ini?"_ | Pengiriman gambar asli |
| _"Jalankan skrip Python ini"_ | Penyediaan Lazy Code |
| _"Tinjau file kode ini untuk mencari bug"_ | Teks yang diekstrak |

## Kemampuan `context` [#the-context-capability]

Di balik layar, Upload as Text ditenagai oleh **kapabilitas `context`**. Inilah yang mengontrol apakah fitur tersebut muncul di UI obrolan Anda.

<Callout type="info">
  Kemampuan `context` **diaktifkan secara default**. Anda hanya perlu mengubahnya jika admin Anda telah menyesuaikan daftar kemampuan dan secara tidak sengaja menghilangkannya.
</Callout>

```yaml title="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - "context"  # This is what enables "Upload as Text"
```

Kemampuan `context` yang sama juga mendukung **Agent File Context** (mengunggah file melalui Agent Builder untuk menyematkan teks ke dalam instruksi sistem agen). Perbedaannya terletak pada _di mana_ teks tersebut berakhir:

| | Unggah sebagai Teks | Konteks File Agen |
|---|---|---|
| **Di mana** | Input obrolan (percakapan apa pun) | Panel Agent Builder |
| **Cakupan** | Hanya percakapan saat ini | Bertahan dalam instruksi agen |
| **Kasus penggunaan** | Pertanyaan dokumen sekali pakai | Membangun agen khusus dengan pengetahuan bawaan |

## Batas token dan pemotongan (truncation) [#token-limits-and-truncation]

Ketika sebuah file terlalu panjang untuk dimuat ke dalam jendela konteks model, LibreChat akan memotong teks yang diekstrak agar tetap berada dalam batas yang ditentukan. Hal ini terjadi secara otomatis — Anda tidak perlu mengkhawatirkannya, namun ada baiknya untuk mengetahui cara kerjanya.

```yaml title="librechat.yaml"
fileConfig:
  fileTokenLimit: 100000  # Default: 100,000 tokens
```

<Callout type="warn" title="Pemotongan berarti konten hilang">
  Jika file Anda melebihi batas, teks akan terpotong di bagian akhir. Jika Anda mendapatkan jawaban yang tidak lengkap, mungkin inilah penyebabnya. Anda dapat meningkatkan `fileTokenLimit`, namun perlu diingat bahwa nilai yang lebih besar akan menggunakan lebih banyak token per pesan — yang akan meningkatkan biaya dan mungkin mencapai batas konteks model itu sendiri.
</Callout>

**Aturan praktis:**
- 100k token ≈ buku setebal 300 halaman (lebih dari cukup untuk sebagian besar kasus penggunaan)
- Jika Anda bekerja dengan file yang sangat besar, pertimbangkan [File Search (RAG)](/docs/features/rag_api) sebagai gantinya — fitur ini hanya mengambil bagian yang relevan alih-alih memasukkan semuanya ke dalam konteks.

## Opsional: meningkatkan ekstraksi dengan OCR [#optional-boosting-extraction-with-ocr]

Penguraian teks berfungsi dengan baik untuk dokumen yang dibuat secara digital (PDF yang disimpan dari Word, file kode, teks biasa). Namun, jika Anda mengunggah **dokumen hasil pemindaian, foto halaman, atau gambar yang berisi teks**, pengurai bawaan tidak akan memberikan hasil yang optimal.

Di situlah peran OCR. Saat dikonfigurasi, LibreChat secara otomatis menggunakan OCR untuk jenis file yang memerlukannya — Anda tidak perlu melakukan apa pun secara berbeda sebagai pengguna.

<Accordions>
  <Accordion title="Cara meminta admin Anda untuk mengatur OCR">
    Arahkan mereka ke [dokumentasi konfigurasi OCR](/docs/features/ocr). Versi singkatnya:

    ```yaml title="librechat.yaml"
    ocr:
      strategy: "mistral_ocr"
      apiKey: "${OCR_API_KEY}"
      baseURL: "https://api.mistral.ai/v1"
      mistralModel: "mistral-ocr-latest"
    ```

    Setelah dikonfigurasi, OCR secara otomatis menangani gambar dan PDF hasil pemindaian — tidak ada perubahan yang diperlukan di sisi pengguna.
  </Accordion>
  <Accordion title="Cara meminta admin Anda untuk mengatur STT (untuk file audio)">
    Untuk mentranskripsikan unggahan audio, admin perlu mengonfigurasi layanan Speech-to-Text. Lihat [referensi konfigurasi STT](/docs/configuration/librechat_yaml/object_structure/file_config#stt).
  </Accordion>
</Accordions>

## Referensi konfigurasi penanganan file [#file-handling-configuration-reference]

Bagian ini ditujukan bagi admin yang ingin mengontrol jenis file mana yang diproses dengan metode yang mana. Pengaturan default sudah berfungsi dengan baik — Anda hanya perlu mengubah bagian ini jika ingin menyempurnakan perilakunya.

<Accordions>
  <Accordion title="Contoh fileConfig lengkap">
    ```yaml title="librechat.yaml"
    fileConfig:
      # Max tokens extracted from a single file before truncation
      fileTokenLimit: 100000

      # Files matching these MIME patterns use OCR (if configured)
      ocr:
        supportedMimeTypes:
          - "^image/(jpeg|gif|png|webp|heic|heif)$"
          - "^application/pdf$"
          - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.presentation|spreadsheetml\\.sheet)$"
          - "^application/vnd\\.ms-(word|powerpoint|excel)$"
          - "^application/epub\\+zip$"

      # Files matching these MIME patterns use text parsing
      text:
        supportedMimeTypes:
          - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"

      # Files matching these MIME patterns use STT (if configured)
      stt:
        supportedMimeTypes:
          - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
    ```

    **Pengingat prioritas:** OCR > STT > penguraian teks > fallback.

    Untuk referensi lengkap, lihat [File Config Object Structure](/docs/configuration/librechat_yaml/object_structure/file_config).
  </Accordion>
</Accordions>

## Pemecahan Masalah [#troubleshooting]

<Accordions>
  <Accordion title="Opsi Upload as Text tidak muncul">
    Kemampuan `context` kemungkinan telah dihapus dari konfigurasi Anda. Minta admin Anda untuk menambahkannya kembali:

    ```yaml
    endpoints:
      agents:
        capabilities:
          - "context"
    ```
  </Accordion>
  <Accordion title="Konten file terlihat salah atau sebagian besar kosong">
    Beberapa hal untuk diperiksa:
    - **PDF / gambar yang dipindai** — Dokumen ini memerlukan OCR untuk mengekstrak teks dengan benar. Tanpanya, parser mungkin akan menghasilkan data yang tidak terbaca atau tidak menghasilkan apa pun. Minta admin Anda untuk [mengonfigurasi OCR](/docs/features/ocr).
    - **File audio** — Ini memerlukan STT. Tidak ada cadangan teks untuk audio.
    - **File rusak** — Coba buka file tersebut secara lokal untuk memastikan file tidak rusak.
    - **Format tidak didukung** — Jika tipe MIME tidak cocok dengan pola apa pun yang dikonfigurasi, LibreChat akan mencoba *fallback* penguraian teks, yang mungkin tidak berfungsi untuk format biner.
  </Accordion>
  <Accordion title="Unggahan ditolak karena jenis file tidak didukung">
    LibreChat mengembalikan tipe MIME yang ditolak dalam kesalahan unggahan. Periksa pola [`fileConfig.endpoints.<endpoint>.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) pada endpoint yang aktif dan izinkan tipe kanonik yang ingin Anda terima. Untuk skrip shell, gunakan `application/x-sh`; LibreChat menormalisasi varian umum `application/x-shellscript` dan `text/x-shellscript` sebelum melakukan pencocokan.
  </Accordion>
  <Accordion title="AI tampaknya melewatkan sebagian file saya">
    File Anda mungkin melebihi `fileTokenLimit`. Teks telah dipotong.

    **Opsi:**
    - Minta admin Anda untuk meningkatkan `fileTokenLimit` di `librechat.yaml`
    - Gunakan [File Search (RAG)](/docs/features/rag_api) sebagai gantinya, yang mengambil potongan (chunk) yang relevan alih-alih memuat seluruh file
    - Pecah file menjadi bagian-bagian yang lebih kecil dan unggah secara terpisah
  </Accordion>
  <Accordion title="Gambar berhasil diunggah tetapi AI tidak dapat membaca teks di dalamnya">
    Tanpa OCR, gambar diproses melalui penguraian teks, yang sebenarnya tidak dapat "melihat" teks di dalam gambar. Anda perlu mengonfigurasi OCR agar fitur ini berfungsi. Lihat [OCR for Documents](/docs/features/ocr).

    Sebagai alternatif, gunakan **vision model** dengan unggahan file standar — model tersebut dapat membaca teks dalam gambar.
  </Accordion>
</Accordions>
