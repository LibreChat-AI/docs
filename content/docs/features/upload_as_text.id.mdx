Upload as Text mengambil teks dari sebuah file dan menambahkannya ke pesan Anda, sehingga model membaca seluruh dokumen alih-alih mencarinya. Gunakan fitur ini saat file cukup kecil untuk muat dalam konteks dan Anda ingin setiap baris dipertimbangkan, misalnya kontrak, log, file sumber, atau hasil ekspor spreadsheet.

## Melampirkan file [#attaching-a-file]

Klik **+** di [message composer](/docs/features/composer#add-files) dan pilih **From Local Computer** di bawah **Attach** (atau **From SharePoint**, jika server Anda memilikinya). Anda juga dapat menyeret file ke composer. Anda tidak memilih tujuan: LibreChat memeriksa setiap file dan memutuskan bagaimana model mendapatkannya.

- File teks, kode, Markdown, CSV, JSON, Word, dan Excel dikirim sebagai teks yang telah diekstrak.
- Gambar, audio, video, dan PDF dikirim langsung ke model jika penyedia model tersebut menerimanya. Pada penyedia yang tidak dapat menerima PDF, LibreChat akan mengekstrak teks dari PDF tersebut sebagai gantinya.

Jika Anda mengaktifkan **File Search** atau **Run Code** di palet, alat tersebut hanya menerima file ketika sebuah run benar-benar membutuhkannya.

Jika admin Anda telah mengaktifkan menu tujuan unggah yang lama, Anda memilih secara eksplisit: **Upload as Text** berada berdampingan dengan **Upload to Provider** (atau **Upload Image**) dan **Upload for File Search**. Beberapa di antaranya berada di balik **More upload options**. Menjatuhkan beberapa file ke dalam chat dalam mode ini akan membuka **Select Upload Type** dengan pilihan yang sama.

Ketika Anda melampirkan beberapa file sekaligus, file duplikat dan file yang melebihi batas ukuran per file akan dilewati dan disebutkan namanya dalam pemberitahuan, sedangkan sisanya tetap diunggah. Batas jumlah file dan batas total ukuran tetap berlaku untuk file yang tersisa; jika batch yang tersisa melanggar salah satu dari keduanya, tidak ada satu pun file yang diunggah.

## Menempel teks panjang [#pasting-long-text]

Tempel lebih dari 2.500 karakter ke dalam kotak pesan dan LibreChat akan mengubah teks tempelan tersebut menjadi file teks bernama `pasted-text.txt` (lalu `pasted-text-2.txt` dan seterusnya), yang dilampirkan sebagai teks dan menampilkan **Attached as text**. Kotak pesan Anda tetap mudah dibaca dan model tetap menerima tempelan yang persis sama. Pilih chip file untuk **Edit pasted text**, atau gunakan **Move back into message** untuk memasukkannya kembali secara inline.

Tempelan ke dalam formulir pertanyaan agen tetap inline, dan jika unggahan gagal, LibreChat akan mengembalikan teks tersebut ke kotak pesan. Untuk membuat tempelan panjang tetap inline, nonaktifkan **Paste long text as a file** di **Settings** > **Chat** > **Sending**. Pengaturan ini disimpan di browser Anda.

## Bagaimana teks diekstraksi [#how-the-text-is-extracted]

LibreChat mencoba opsi-opsi berikut secara berurutan dan menggunakan yang pertama yang berlaku:

1. OCR, jika admin Anda telah mengonfigurasi layanan OCR dan jenis file tersebut didukung oleh OCR (gambar, PDF, dokumen Office, EPUB, OpenDocument). Lihat [OCR](/docs/features/ocr).
2. Parser dokumen bawaan untuk file PDF, DOCX, XLS, XLSX, ODT, dan ODS hingga 15 MB. Parser ini hanya membaca lapisan teks.
3. Speech-to-text untuk file audio, jika admin Anda telah mengonfigurasi STT.
4. Membaca teks biasa untuk semua yang sudah berupa teks: kode sumber, Markdown, CSV, JSON, YAML, HTML, dan sebagainya.

File `.doc`, PowerPoint, dan EPUB versi lama tidak didukung oleh parser bawaan; file tersebut memerlukan OCR, atau ekstraksi teks dari RAG API jika admin Anda telah mengaturnya.

Sebuah PDF hasil pindai atau foto halaman tidak memiliki lapisan teks, sehingga tanpa OCR tidak ada yang bisa diekstrak dan unggahan akan gagal dengan pesan yang menyatakan bahwa layanan OCR diperlukan. Model vision dapat membaca gambar tersebut secara langsung sebagai gantinya jika Anda mengirimkannya dengan **Upload to Provider**.

## Seberapa banyak file yang dilihat model [#how-much-of-the-file-the-model-sees]

Setiap teks file dipotong pada batas token file, secara default 100.000 token. Apa pun yang melebihi batas tersebut dibuang tanpa peringatan, jadi jika jawaban tampak mengabaikan bagian akhir dari dokumen yang panjang, inilah kemungkinan penyebabnya. Anda dapat menurunkan atau menaikkan batas ini untuk sebuah percakapan melalui **File Token Limit** di parameter model; batas yang lebih besar akan menambah biaya token pada setiap pesan yang menyertakan file tersebut.

Ketika LibreChat hanya menyimpan teks yang diekstrak dari sebuah file dan bukan file aslinya, mengunduhnya akan memberi Anda teks tersebut dalam bentuk file `.txt`.

Untuk dokumen besar atau banyak file, [pencarian file](/docs/features/rag_api) biasanya lebih cocok: fitur ini mengambil bagian-bagian yang relevan alih-alih mengirim seluruh file pada setiap giliran.

## Pengaturan [#setup]

Unggah sebagai Teks berfungsi langsung tanpa konfigurasi tambahan. Opsi **Unggah sebagai Teks** yang eksplisit bergantung pada kemampuan agen `context`, yang aktif secara default; admin yang menyesuaikan daftar kemampuan harus tetap menyertakannya. Admin mengontrol ekstraksi, batas token, dan gaya menu unggah melalui [`fileConfig`](/docs/configuration/librechat_yaml/object_structure/file_config), serta OCR melalui [konfigurasi `ocr`](/docs/configuration/librechat_yaml/object_structure/ocr).
