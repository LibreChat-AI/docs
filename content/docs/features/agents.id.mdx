Agen adalah pengaturan yang disimpan: sebuah model, sebuah system prompt, serta alat dan file yang dapat digunakannya. Anda membuatnya sekali di Agent Builder, lalu memilihnya setiap kali memulai chat. Agen bekerja dengan provider apa pun yang sudah Anda konfigurasi, tidak hanya OpenAI.

## Membuat agen [#create-an-agent]

<Steps>
  <Step>
    Buka **Agent Builder** dari panel samping dan klik **Create New Agent**.
  </Step>
  <Step>
    Beri nama, deskripsi opsional, dan pilih **Model** dan **Category**. Model dan category wajib diisi.
  </Step>
  <Step>
    Tulis instruksinya. Anda dapat mengetiknya secara langsung (inline), atau beralih sumbernya ke **Prompt** untuk menggunakan prompt tersimpan dari pustaka prompt Anda (lihat di bawah).
  </Step>
  <Step>
    Tambahkan alat di bawah **Tools** (lihat di bawah), lalu klik **Create**.
  </Step>
</Steps>

Mengunggah file untuk File Search atau File Context hanya dapat dilakukan setelah agen dibuat.

Untuk mengobrol dengan agen, pilih agen tersebut di pemilih model, buka dari [Agent Marketplace](#agent-marketplace), atau ketik `@` di kotak chat lalu pilih dari daftar. Di pemilih agen pada builder, **My agents** akan mempersempit daftar hanya ke agen yang Anda buat.

### Instruksi dari prompt yang disimpan [#instructions-from-a-saved-prompt]

Dengan sumber instruksi diatur ke **Prompt**, pilih prompt di bawah **Select a prompt** dan **Version**: baik versi produksi, yang mengikuti penandaan produksi oleh pemilik prompt, atau versi tersimpan tetap. Anda memerlukan akses ke pustaka prompt untuk melakukan ini. Jika orang lain membuka agen tanpa akses ke prompt yang tertaut, builder akan menampilkan **Restricted prompt** dan memungkinkan mereka untuk mengganti prompt tersebut atau kembali ke instruksi inline.

Instruksi, baik inline maupun tertaut, dapat menggunakan `{{current_date}}`, `{{current_datetime}}`, dan `{{iso_datetime}}`. Nilainya diisi sekali di awal setiap giliran dan tetap sama selama panggilan alat, subagen, dan jeda persetujuan. Dua yang pertama menggunakan zona waktu Anda; `{{iso_datetime}}` menggunakan UTC.

### Parameter model [#model-parameters]

Panel model menampilkan parameter yang sama dengan chat normal untuk penyedia tersebut (temperature, maksimum token output, dan sebagainya), ditambah **Image Detail** untuk input visi. Nilai yang disimpan di sini berlaku untuk setiap percakapan dengan agen.

### Pemicu percakapan [#conversation-starters]

Di bawah **Conversation Starters**, Anda dapat menambahkan hingga empat prompt. Prompt tersebut muncul sebagai tombol pada layar chat kosong ketika seseorang memulai chat baru dengan agen, dan saat diklik akan langsung dikirim. Conversation starters milik agen menggantikan starters apa pun yang didefinisikan pada model spec yang sedang digunakan. Starters tersebut juga muncul di detail agen pada Marketplace.

### Riwayat versi [#version-history]

Setiap penyimpanan yang mengubah agen menambahkan entri ke **Riwayat Versi**, yang menampilkan kapan setiap versi disimpan dan alat serta kemampuan apa saja yang dimilikinya. **Pulihkan** menggantikan konfigurasi saat ini dengan versi tersebut setelah konfirmasi. Hanya pengguna yang dapat mengedit agen yang dapat melihat ini.

## Alat [#tools]

Klik **Add** di samping heading **Tools** di builder (tertulis **No tools yet** sampai Anda menambahkan satu) untuk membuka **Tool Library**. Cari di dalamnya, atau filter berdasarkan **Native**, **Tools**, **MCP servers**, atau **Actions**. **Made by you** mengumpulkan MCP server dan Action yang Anda buat, sedangkan **Favorites** menyimpan item yang diberi bintang agar mudah diakses di seluruh agent (hingga 100). Menu **Create new…** menambahkan MCP server atau Action tanpa meninggalkan dialog, jika peran Anda diizinkan untuk membuatnya. Apa yang Anda lihat bergantung pada fitur yang diaktifkan oleh admin Anda dan pada izin peran Anda; item yang masih memerlukan API key akan menampilkan **Needs setup**.

Run Code, File Search, dan File Context menyimpan file. Selama masih ada file yang terlampir, menghapusnya akan membuka pengelola file sebagai gantinya, dan file tersebut tetap berada di agen hingga file-file tersebut dihapus.

### Code Interpreter [#code-interpreter]

Tercantum sebagai **Run Code**. Agen menulis dan menjalankan kode di dalam sandbox, yang sangat berguna untuk perhitungan, analisis data, dan pembuatan file seperti grafik atau spreadsheet. File yang Anda lampirkan ke alat ini di builder tersedia di dalam sandbox pada setiap eksekusi. Jika tidak ada file kode dari suatu percakapan yang dapat dipulihkan ke dalam sandbox, agen akan berhenti sebelum memanggil model dan meminta Anda melampirkan file tersebut kembali. Lihat [Code Interpreter](/docs/features/code_interpreter).

#### Sesi kode yang stateful [#stateful-code-sessions]

Jika admin Anda telah mengaktifkannya, **Sesi kode stateful** di pengaturan Run Code akan mempertahankan ruang kerja sandbox di antara setiap eksekusi, sehingga file dan paket yang sudah terpasang akan tetap tersedia. **Stateful environment** menentukan siapa yang berbagi ruang kerja tersebut: **User workspace (recommended)** untuk semua agen stateful Anda, **Agent + user workspace** untuk satu ruang kerja per agen, atau **Conversation workspace** untuk satu ruang kerja per chat. Agen baru akan memulai dari **Default stateful workspace** di **Settings > Data & Privacy > Code execution**. Jika admin telah menyiapkan beberapa backend, **Execution environment** memilih backend mana yang menjalankan kode, termasuk worker yang dipasangkan pada mesin Anda sendiri.

Workspace dapat direset kapan saja, jadi jangan menganggapnya sebagai penyimpanan. Di lingkungan yang dikelola, simpan output yang Anda butuhkan di bawah `/mnt/data`. File yang ditulis agen dengan alat file-nya dicantumkan per pesan di bawah **Workspace changes**, tempat Anda dapat mengunduhnya. Dengan lingkungan yang terpasang, composer menawarkan **Ask before changes**, **Accept edits**, atau **Full access** sebagai mode persetujuan untuk chat tersebut, dalam batas yang ditetapkan oleh admin Anda.

Fitur ini sangat eksperimental. Lihat [sesi kode stateful](/docs/features/code_interpreter#stateful-code-sessions) untuk detailnya.

### Pencarian Web [#web-search]

Agen mencari di web dan mencantumkan sumbernya. Agen memerlukan penyedia pencarian yang dikonfigurasi oleh admin Anda, atau kunci Anda sendiri jika admin mengaturnya seperti itu. Lihat [Web Search](/docs/features/web_search).

### Pencarian File [#file-search]

Mengubah file yang Anda lampirkan menjadi basis pengetahuan yang dapat dicari. Agen mengambil bagian-bagian yang paling relevan ketika dibutuhkan, sehingga tetap andal menangani kumpulan dokumen yang besar. Fitur ini kurang cocok untuk data terstruktur seperti CSV atau Excel, yang lebih baik ditangani oleh Run Code. Memerlukan [RAG API](/docs/features/rag_api).

### Konteks File [#file-context]

File yang ditambahkan di bawah **File Context** diekstrak teksnya sekali, saat diunggah, dan teks tersebut dimasukkan ke dalam konteks agen pada setiap pesan. Gunakan fitur ini untuk beberapa dokumen kunci yang harus selalu tersedia bagi agen. Ekstraksi bekerja dengan cara yang sama seperti [Upload as Text](/docs/features/upload_as_text): secara default menggunakan parsing teks biasa, dan hasilnya lebih baik untuk hasil pindaian dan gambar jika [OCR](/docs/features/ocr) telah dikonfigurasi.

Karena teks ini ikut terkirim bersama setiap pesan, file besar di sini memakan token pada setiap giliran percakapan. Siapa pun yang dapat mengobrol dengan agen juga dapat membujuk agen tersebut untuk mengeluarkan teks itu.

### Artifacts [#artifacts]

Memungkinkan agent menampilkan React, HTML, SVG, Markdown, dan Mermaid di panel samping alih-alih sebagai blok kode. Pengaturan **Mode** memilih instruksi bawaan: **Normal**, **shadcn/ui** (menambahkan instruksi untuk pustaka komponen shadcn/ui), atau **Custom**, yang tidak menyisipkan apa pun, sehingga instruksi Anda sendiri harus mengajarkan sintaks artefak. Lihat [Artifacts](/docs/features/artifacts) untuk sintaks tersebut.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

Server MCP yang dikonfigurasi oleh admin Anda, atau yang Anda tambahkan sendiri, muncul di bawah **MCP servers**. Menambahkan server akan melampirkan semua alatnya; perluas di bawah **Tools in this server** untuk memilih hanya alat yang dibutuhkan agen. Lihat [MCP](/docs/features/mcp).

Beberapa server hanya dapat mencantumkan tool-nya selama chat, karena bergantung pada nilai dari permintaan. Untuk server tersebut, builder menyediakan satu pilihan untuk semua tool server tersebut, alih-alih sakelar per tool. Jika semua tool MCP yang dipilih untuk sebuah agent gagal dimuat saat run dimulai, run akan dihentikan dan memberi tahu Anda untuk menghubungkan ulang atau masuk ke server, bukan melanjutkan tanpa tool tersebut.

Setiap alat MCP memiliki menu **Tool Options** dengan beberapa sakelar per alat:

- **Defer**: lihat [Deferred tools](#deferred-tools). **Defer all tools** melakukannya untuk seluruh server.
- **Programmatik**: lihat [Pemanggilan tool secara programatik](#programmatic-tool-calling).
- **Latar belakang**: lihat [Panggilan alat latar belakang](#background-tool-calls).
- **Label niat**: agen menulis deskripsi satu baris untuk setiap pemanggilan, yang ditampilkan secara langsung sebagai status pemanggilan alih-alih label generik. Fitur ini menambahkan beberapa token per permintaan. Alat native otomatis mendapatkan label niat. Fitur ini tidak berlaku untuk alat programatik.

**Background** dan **Intent label** hanya muncul jika admin Anda telah mengaktifkannya.

### Alat yang Ditangguhkan [#deferred-tools]

Agen dengan beberapa server MCP dapat dengan mudah membawa puluhan definisi tool, dan mengirimkan semuanya pada setiap permintaan menghabiskan konteks serta membuat model kurang tepat dalam memilih tool yang sesuai. Tool yang ditangguhkan (deferred tool) tidak disertakan dalam permintaan awal. Sebagai gantinya, agen mendapatkan tool pencarian tool, yang menemukan deferred tool berdasarkan nama atau deskripsinya ketika dibutuhkan, dan dapat menggunakan tool yang ditemukan tersebut untuk sisa percakapan.

### Pemanggilan alat secara terprogram [#programmatic-tool-calling]

Dengan **Programmatic** diaktifkan untuk alat MCP (atau seluruh server), model tidak memanggil alat tersebut secara langsung. Sebaliknya, model menulis kode di sandbox Code Interpreter yang memanggil alat tersebut sebagai fungsi, sehingga model dapat melakukan perulangan, paginasi, mencoba ulang, dan menyaring hasil sebelum memberikan jawaban. Hal ini membantu untuk tugas seperti "periksa 40 tiket ini dan ringkas yang masih terbuka", yang jika tidak akan memerlukan 40 pemanggilan alat terpisah melalui model.

Switch **Programmatic** tetap dinonaktifkan hingga Run Code diaktifkan, dan menghapus Run Code akan mengosongkannya. Sandbox hanya dapat memanggil tool yang terdaftar pada agent. Selama proses berjalan, perluas kartu kode untuk melihat jejak langsung (live trace) dari setiap pemanggilan tool internal; jejak ini tidak disimpan setelah Anda memuat ulang halaman. Fitur ini nonaktif secara default; admin Anda harus mengaktifkannya.

### Panggilan alat latar belakang [#background-tool-calls]

Alat yang mendukung latar belakang mengembalikan referensi tugas segera, sehingga agen dapat terus bekerja selama tugas berjalan. Ketika tugas selesai, hasilnya dikirimkan secara otomatis dalam giliran tindak lanjut (ditampilkan sebagai kartu tugas yang dapat diciutkan), atau agen dapat memeriksa statusnya dengan alat tugasnya. Keluaran dan file latar belakang muncul pada panggilan alat asli. Alat yang boleh berjalan di latar belakang:

- **Jalankan Kode**: kode dan perintah shell memenuhi syarat secara default; matikan **Background execution** di pengaturannya untuk keluar.
- **Alat MCP**: tandai alat atau seluruh server sebagai **Latar Belakang**.
- **Alat lain dan Actions**: aktifkan **Background execution**. Actions yang menggunakan OAuth tidak mendukung fitur ini.

Sakelar ini memungkinkan eksekusi di latar belakang; model tetap memutuskan untuk setiap panggilan. Pekerjaan latar belakang berjalan di dalam proses server yang memulainya dan akan hilang jika proses tersebut berhenti. Admin Anda harus mengaktifkan fitur ini.

### Actions [#actions]

Actions mengubah spesifikasi OpenAPI menjadi tools. Pilih **Create new…** lalu **Actions**, tempelkan skema, dan atur **Authentication** jika API memerlukannya. Setiap operasi dalam spesifikasi menjadi tool yang dapat dipanggil oleh agent.

Jika Anda menggunakan model OpenAI, tambahkan `x-strict: true` ke sebuah operasi dalam spesifikasi dan LibreChat akan meminta function calling strict untuk operasi tersebut. Mode strict hanya menerima subset dari JSON Schema; lihat [panduan structured outputs](https://platform.openai.com/docs/guides/structured-outputs) dari OpenAI.

Action hanya dapat mengakses domain yang diizinkan oleh admin Anda, dan alamat jaringan privat akan diblokir kecuali secara eksplisit diizinkan.

### Skills [#skills]

Bagian **Skills** di builder mengontrol [Skills](/docs/features/skills) mana yang dapat digunakan oleh agen: **Off** (nonaktif), **All** (semua skill yang Anda aktifkan), atau **Selected** (hanya skill yang Anda tambahkan).

### Memory [#memory]

**Memori** memungkinkan agen untuk menyimpan, memperbarui, dan menghapus memori tentang Anda ketika Anda meminta untuk mengingat atau melupakan sesuatu. Fitur ini memerlukan pengaturan memori pada instans dan harus diizinkan untuk peran Anda. Secara default, agen membagikan memori pribadi Anda dengan obrolan Anda yang lain; aktifkan **Pisahkan memori untuk agen ini** untuk memberikan agen memorinya sendiri yang hanya dibaca dan ditulis olehnya. Lihat [Memori](/docs/features/memory).

### Persetujuan pengguna dan alat [#ask-user-and-tool-approval]

**Ask User** memungkinkan agen untuk menjeda proses di tengah jalan guna mengajukan pertanyaan kepada Anda dan menunggu jawaban. Satu jeda dapat memuat hingga empat pertanyaan, yang ditampilkan satu per satu dengan tombol **Back** dan **Next**; setiap pertanyaan menerima jawaban bebas atau salah satu pilihan yang diberikan agen. Tombol **Skip** menolak semua pertanyaan tersebut. Proses akan dilanjutkan segera setelah Anda mengirimkan jawaban, dan jawaban Anda tetap tersimpan meskipun Anda menghentikan proses selama proses tersebut dimulai ulang.

Administrator Anda juga dapat mewajibkan persetujuan sebelum tool tertentu dijalankan. Proses akan dijeda, Anda meninjau pemanggilan tersebut melalui panel di atas kotak pesan (setujui, tolak, atau untuk beberapa tool, ubah argumennya), lalu proses dilanjutkan. Jika administrator telah mengaktifkan mode persetujuan per agen, setiap tool pada agen akan memiliki **Mode persetujuan tool**: **Gunakan kebijakan warisan**, **Selalu tanyakan**, **Selalu setujui**, **Tanyakan sekali per chat**, atau **Tanyakan sekali, lalu selalu setujui**. Aturan administrator tetap berlaku di atas pengaturan tersebut, dan **Atur ulang persetujuan yang saya ingat** akan menghapus persetujuan yang sebelumnya telah Anda berikan.

### Alat lainnya [#other-tools]

Kategori **Tools** berisi integrasi bawaan yang telah diaktifkan oleh admin Anda, seperti [pembuatan gambar](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google Search](/docs/configuration/tools/google_search), dan [Azure AI Search](/docs/configuration/tools/azure_ai_search). Setiap integrasi disiapkan secara terpisah; lihat [Tools](/docs/configuration/tools).

## Bekerja dengan agen lain [#working-with-other-agents]

**Subagen** memungkinkan agen menyerahkan subtugas yang terfokus kepada salinan baru dari dirinya sendiri, atau kepada agen lain, dalam jendela konteks yang terpisah. Hanya hasilnya yang dikembalikan, sehingga keluaran alat yang panjang tidak masuk ke dalam percakapan utama. Lihat [Subagen](/docs/features/subagents).

### Handoffs [#handoffs]

**Handoff** memberi agen sebuah alat transfer untuk setiap agen yang Anda cantumkan, sehingga agen dapat meneruskan percakapan ke spesialis ketika topiknya memerlukannya. Untuk setiap handoff, Anda dapat menambahkan deskripsi (kapan harus ditransfer) dan konten passthrough (apa yang harus dihasilkan dan diteruskan oleh agen), serta mengganti nama parameter tempat konten tersebut diteruskan (`instructions` secara default). Sebuah agen dapat memiliki hingga 10 handoff. Handoff selalu tersedia; keberadaannya tidak bergantung pada pengaturan admin.

### Rantai Agen [#agent-chain]

Rantai agen sudah tidak digunakan lagi (deprecated). Rantai yang sudah ada tetap berjalan, dan builder menampilkannya di bawah **Advanced Settings** dengan tombol **Remove chain**, namun Anda tidak dapat membuat rantai baru. Gunakan subagen atau handoff sebagai gantinya.

## Langkah agen maksimum [#max-agent-steps]

**Pengaturan Lanjutan** memiliki kolom **Max Agent Steps** yang membatasi jumlah langkah yang dapat dilakukan agen sebelum harus memberikan jawaban akhir. Satu langkah adalah satu permintaan ke model atau satu putaran pemanggilan alat, sehingga satu pemanggilan alat biasanya membutuhkan tiga langkah: permintaan, putaran alat, dan permintaan lanjutan.

Biarkan kosong untuk menggunakan default server, yaitu 50 kecuali admin Anda telah mengubahnya. Admin Anda juga dapat menetapkan batas maksimum yang tidak boleh dilampaui oleh kolom ini.

Ketika sebuah giliran (turn) kehabisan langkah, Anda tetap menyimpan apa yang sudah dilakukan agent sejauh ini, dan pesan menawarkan **Keep going** (giliran baru dengan anggaran baru) atau **Answer now** (agent menjawab berdasarkan pekerjaan yang sudah dilakukan, tanpa menggunakan tool lagi). Jika hal ini sering terjadi pada rantai tool yang panjang, naikkan batasnya.

## Setelah sesi yang panjang [#following-a-long-run]

Kartu alat menampilkan **Preparing** saat panggilan menunggu (misalnya saat persetujuan) dan kemudian **Calling** hingga hasilnya kembali. Output shell ditampilkan dengan gaya terminal dan diciutkan ke 15 baris terakhir; **Show more** memperluas tampilannya, dan perintah yang gagal menampilkan kode keluarnya, sinyal, atau waktu habis (timeout).

### Grup aktivitas [#activity-groups]

Jika admin Anda telah mengaktifkannya, setiap rangkaian penalaran dan pemanggilan alat akan diciutkan di bawah satu baris header yang dibuat secara otomatis, sehingga sebuah proses dengan 30 pemanggilan alat hanya tampil sebagai beberapa baris saja. Perluas sebuah header untuk melihat pemanggilan di dalamnya. Level kedua dapat mengelompokkan beberapa grup tersebut menjadi sebuah fase dengan ringkasannya sendiri, sehingga proses yang panjang memiliki semacam kerangka. Setelah dua grup selesai, keduanya langsung digabungkan, dan header terbaru akan menggantikan sementara hingga ringkasan tersedia. Jawaban akhir selalu berada di luar lipatan, dan file yang dihasilkan di dalam sebuah fase ditampilkan berderet di bawahnya, bukan disembunyikan. Dengan [Smooth Streaming](/docs/features/smooth_streaming) aktif, lipatan akan dianimasikan, kecuali perangkat Anda meminta pengurangan gerakan (reduced motion).

Label reasoning langsung adalah opsi terkait: alih-alih judul umum **Thinking**, blok penalaran menampilkan ringkasan singkat yang diperbarui tentang apa yang sedang dikerjakan oleh model.

Header, ringkasan fase, dan label penalaran masing-masing memerlukan panggilan model tambahan, yang dicatat seperti penggunaan lainnya. Admin mengonfigurasinya di [grup aktivitas agen](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) dan [label penalaran langsung](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels).

## Pengarahan dan pesan dalam antrean [#steering-and-queued-messages]

Saat agen sedang menjawab, Anda tetap dapat mengirim pesan:

- **Steer** menyisipkan pesan ke dalam proses yang sedang berjalan pada titik aman berikutnya, sehingga agen dapat menyesuaikan diri sebelum proses selesai.
- **Interrupt** membatalkan pemanggilan tool dan penalaran yang sedang berjalan, mempertahankan apa yang sudah selesai, lalu melanjutkan dengan pesan Anda. Efek yang sudah terjadi di luar LibreChat tidak dapat dibatalkan. Beberapa proses, misalnya yang menggunakan fitur pencarian bawaan dari penyedia, tidak dapat diinterupsi, dan pesan akan menunggu sebagai *steer*.
- **Antrean** menyimpan pesan dan mengirimkannya sebagai giliran biasa setelah jawaban selesai.

**Saat menghasilkan respons, Enter akan** di bawah **Settings > Chat** memilih default, dan menu tombol kirim menimpanya per pesan; `Alt + Enter` menginterupsi. Pesan yang masuk antrean ditampilkan di atas composer, tempat Anda dapat mengedit, menghapus, mengurutkan ulang, **Send now**, atau **Interrupt now**. File dan kutipan teks disertakan bersama pesan; skill yang Anda pilih dengan `$` menunggu giliran penuh berikutnya. Pesan yang masuk antrean dalam obrolan agent yang tersimpan disimpan di server dan tetap ada meskipun browser ditutup.

Satu chat dapat menampung hingga 100 pesan yang diantrikan (masing-masing 16.000 karakter dan 10 file), dan satu run dapat menerima hingga 10 steer yang tertunda. Lihat [Composer](/docs/features/composer) untuk rincian tanda terima dan kontrolnya.

## File dalam chat [#files-in-a-chat]

Ketika Anda mengobrol dengan agen, menu lampiran menawarkan:

- **Unggah Gambar**: dikirim ke model untuk pemrosesan visual.
- **Unggah sebagai Teks**: seluruh teks dimasukkan hanya ke dalam percakapan ini. Lihat [Unggah sebagai Teks](/docs/features/upload_as_text).
- **Unggah untuk Pencarian File**: diindeks untuk pengambilan, seperti file Pencarian File milik agen itu sendiri, tetapi dibatasi pada obrolan ini.
- **Unggah ke Lingkungan Kode**: disalin ke dalam sandbox untuk Run Code. Paling cocok untuk CSV, Excel, dan JSON.

Opsi hanya muncul ketika kemampuan yang sesuai diaktifkan.

## Berbagi dan izin [#sharing-and-permissions]

Agent bersifat privat bagi pembuatnya hingga dibagikan. Klik **Share** di footer builder untuk memberikan akses kepada pengguna, grup, atau peran, masing-masing dengan salah satu dari tiga peran:

| Peran | Yang dapat dilakukan |
| ----- | -------------------- |
| Viewer | Mengobrol dengan agen. Tidak dapat membukanya di builder atau melihat instruksi, alat, atau file-nya. |
| Editor | Semua yang dapat dilakukan viewer, ditambah mengubah instruksi, model, alat, dan file. |
| Owner | Semua yang dapat dilakukan editor, ditambah menghapus agen dan mengubah siapa yang dibagikan agen tersebut. |

**Bagikan ke semua orang** membuat agen tersedia untuk setiap pengguna pada instance; fitur ini memerlukan izin berbagi publik. Pembuat dan admin selalu memiliki kendali penuh.

Viewer tidak dapat melihat instruksi atau file di builder, tetapi model tetap dapat mengulanginya dalam percakapan jika diminta. Jangan memasukkan apa pun ke dalam agent yang tidak boleh dilihat oleh viewer-nya.

Secara terpisah, tombol bola dunia (**Remote Access**) mengatur siapa yang dapat memanggil agen melalui [Agents API](/docs/features/agents_api).

Kartu agen menampilkan kontak dukungan yang diatur di pembuat agen. Jika tidak ada, kartu mungkin menampilkan nama pemilik, tetapi tidak akan pernah menampilkan email pemilik kecuali email tersebut dimasukkan sebagai kontak.

Lihat [Access Control](/docs/features/access_control) untuk melihat cara pengguna, grup, dan peran dikombinasikan.

### Kontrol Administrator [#administrator-controls]

Apakah sebuah peran dapat menggunakan, membuat, membagikan, atau membagikan agen secara publik diatur per peran di [Admin Panel](/docs/features/admin_panel). Admin juga mendapatkan tombol **Admin Settings** di bagian bawah Agent Builder dengan sakelar yang sama, per peran. Pada instance single-tenant, akun pertama yang didaftarkan adalah admin; untuk menambahkan admin lainnya, lihat [Promote another admin](/docs/configuration/access_control#promote-another-admin).

## Marketplace Agen [#agent-marketplace]

**Agent Marketplace** di sidebar mencantumkan agen-agen yang tersedia untuk Anda, jika peran Anda diizinkan menggunakannya. Cari berdasarkan nama atau deskripsi, filter berdasarkan kategori (**Top Picks**, **All**, atau kategori tertentu), dan ubah urutannya dengan **Sort by**: **Newest first**, **Oldest first**, **Popular**, atau **By creator name**. **My agents** hanya menampilkan agen milik Anda. Pencarian, pengurutan, dan filter disimpan di URL, sehingga Anda dapat menandai atau membagikan tampilan tersebut.

Klik kartu untuk melihat detail serta tindakan **Pin** atau **Unpin**, **Copy Link** (tautan yang membuka chat baru dengan agen), dan **Start Chat**. Mengklik salah satu conversation starter dari agen di sana akan membuka chat baru dengan prompt di kotak pesan, belum dikirim, sehingga Anda dapat mengeditnya terlebih dahulu.

## Agents API [#agents-api]

Agen juga dapat dipanggil dari skrip dan aplikasi lain melalui API yang kompatibel dengan OpenAI, dikelola oleh layanan tepercaya, dan dipicu oleh peristiwa dari sistem lain. Lihat [Agents API](/docs/features/agents_api). [Scheduled Chats](/docs/features/scheduled_chats) memulai eksekusi agen berdasarkan pengatur waktu, dan [Agent Plugins](/docs/features/agent_plugins) memungkinkan operator mengirimkan skill dan server MCP ke agen sebagai satu paket.

## Pengaturan [#setup]

Agent secara default sudah aktif. Admin memilih kemampuan apa saja yang ditawarkan, batas langkah (step limits), dan penyedia (provider) yang diizinkan dalam [konfigurasi endpoint agents](/docs/configuration/librechat_yaml/object_structure/agents), serta domain mana saja yang boleh diakses oleh Actions dalam [konfigurasi Actions](/docs/configuration/librechat_yaml/object_structure/actions). Instance yang di-upgrade dari versi sebelum v0.8.0-rc3 perlu menjalankan [migrasi permissions](/docs/configuration/access_control#migrating-from-pre-acl-versions).
