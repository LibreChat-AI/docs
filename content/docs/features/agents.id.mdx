# Agen: Membangun Asisten AI Kustom [#agents-build-custom-ai-assistants]

Fitur AI Agents pada LibreChat menyediakan kerangka kerja yang fleksibel untuk membuat asisten AI kustom yang ditenagai oleh berbagai penyedia model.

Fitur ini mirip dengan Assistants API dari OpenAI dan GPTs dari ChatGPT, namun dengan dukungan model yang lebih luas dan implementasi tanpa kode (no-code), memungkinkan Anda membangun asisten canggih dengan kemampuan khusus.

## Memulai [#getting-started]

Untuk membuat agen baru, pilih "Agents" dari menu endpoint dan buka panel Agent Builder yang terdapat di Side Panel.

![Agents - Endpoints Menu](/images/agents/endpoints_menu.png)

Formulir pembuatan mencakup:

- **Avatar**: Unggah avatar kustom untuk mempersonalisasi agen Anda
- **Name**: Pilih nama yang unik untuk agen Anda
- **Description**: Detail opsional mengenai tujuan agen Anda
- **Instruksi**: Instruksi sistem yang menentukan perilaku agen Anda
- **Model**: Pilih dari penyedia dan model yang tersedia
- **Conversation Starters**: Hingga empat prompt yang disarankan yang ditampilkan saat pengguna memulai obrolan baru dengan agen

Kontrol **Tools** dan **Skills** membuka pustaka yang dapat dicari untuk kapabilitas bawaan, tools, server MCP, Actions, dan Skills. Pilih item untuk mengonfigurasinya, lalu simpan agen tersebut.

**Agen yang sudah ada dapat dipilih dari menu tarik-turun di bagian atas Panel Samping.**

- **Juga dengan menyebut "@" di input obrolan.**

![Agents - Mention](/images/agents/mention.png)

### Pustaka Alat [#tool-library]

Agent Builder menyimpan item yang diaktifkan dalam bagian **Tools** dan **Skills** yang terpisah. Buka **Add tools** untuk mencari di seluruh katalog atau memfilternya berdasarkan **Official**, **Tools**, **MCP**, atau **Actions**. **Made by you** mengumpulkan server MCP dan Actions yang Anda buat, sementara **Favorites** menyimpan item yang ditandai bintang agar tersedia di seluruh agen. Setiap pengguna dapat menyimpan hingga 100 favorit pustaka alat.

Pilih item untuk mengonfigurasinya tanpa meninggalkan pembuat (builder). Menu **Create new** hanya muncul ketika pengguna memiliki izin untuk membuat server MCP atau Actions. Menghapus kapabilitas berbasis file seperti File Search, File Context, atau Code Interpreter akan membuka pengelola filenya jika masih ada file terlampir yang perlu ditinjau. Kapabilitas berbasis file akan tetap terpilih dan dipertahankan saat disimpan selama masih memiliki file; hapus atau tetapkan ulang file tersebut sebelum menghapus kapabilitas itu sendiri.

Skills menggunakan pemilihnya sendiri dan dapat dipilih secara individu atau diaktifkan sebagai katalog lengkap yang dapat diakses. Lihat [Skills](/docs/features/skills#agent-scope).

Operator juga dapat menggunakan [Agent Plugins](/docs/features/agent_plugins) eksperimental untuk menggabungkan Skills deployment dan server MCP ke dalam paket yang dimuat saat startup.

### Konfigurasi Model [#model-configuration]

Antarmuka parameter model memungkinkan penyesuaian respons agen Anda:

- Temperature (skala 0-1 untuk kreativitas respons)
- Token konteks maksimal
- Token output maksimum
- Detail gambar (`low`, `auto`, atau `high`) untuk input gambar vision native
- Pengaturan tambahan khusus penyedia

Instruksi agen dapat menggunakan `{{current_date}}`, `{{current_datetime}}`, dan `{{iso_datetime}}`. LibreChat menyelesaikannya dari awal giliran logis yang ditangkap server dan menjaga stempel waktu tersebut tetap stabil di seluruh loop penyedia, inisialisasi Subagent, dan resume human-in-the-loop. Dua yang pertama menggunakan zona waktu permintaan; `{{iso_datetime}}` tetap UTC.

Kegagalan *model-not-found* dan *provider rate-limit* yang terdeteksi akan menampilkan panduan yang dilokalkan. Kesalahan penyedia lainnya tetap mempertahankan teks penyedia yang berguna, namun menghilangkan URL pemecahan masalah LangChain sebelum pesan disimpan. Ketika [model-bound content protection](/docs/configuration/librechat_yaml/object_structure/message_filter#source-aware-filters) diaktifkan, kesalahan umum yang dilindungi tetap menjadi prioritas.

### Riwayat Versi [#version-history]

Pengguna dengan akses edit dapat membuka **Version History** dari Agent Builder untuk memeriksa konfigurasi yang tersimpan dalam linimasa. Setiap entri menunjukkan kapan konfigurasi tersebut disimpan dan merangkum alat serta kapabilitasnya. Memulihkan entri sebelumnya memerlukan konfirmasi dan akan mengganti konfigurasi agen saat ini dengan status yang tersimpan tersebut. Menyimpan akan selalu menerapkan perubahan agen saat ini, bahkan ketika konfigurasi yang dihasilkan cocok dengan entri riwayat terbaru dan LibreChat tidak akan menambahkan entri duplikat.

### Conversation Starters [#conversation-starters]

Conversation starters memberikan cara cepat bagi pengguna untuk memulai obrolan dengan agen. Setiap agen dapat menyimpan hingga empat conversation starters.

1. Di Agent Builder, temukan kolom **Conversation Starters**.
2. Ketik prompt dan tekan **Enter**, atau pilih tombol **+**. Input akan dinonaktifkan setelah empat starter ditambahkan.
3. Edit starter yang tersimpan secara langsung, atau pilih tombol **X** untuk menghapusnya.
4. Simpan agen tersebut.

Saat pengguna membuka obrolan baru dengan agen, *starters* akan muncul sebagai tombol di layar obrolan kosong. Memilih salah satu akan langsung mengirimkannya sebagai pesan pertama. Jika agen memiliki *starters*, maka *starters* tersebut akan diprioritaskan daripada [`conversation_starters`](/docs/configuration/librechat_yaml/object_structure/model_specs#conversation_starters) yang didefinisikan pada Model Specs yang sedang digunakan. *Starters* juga muncul di dialog detail [Marketplace](#agent-marketplace) agen.

## Kemampuan Agen [#agent-capabilities]

> **Catatan:** Semua kapabilitas dapat diaktifkan atau dinonaktifkan melalui file konfigurasi `librechat.yaml`. Lihat [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) untuk informasi lebih lanjut.

### Code Interpreter [#code-interpreter]

Saat diaktifkan, kemampuan Code Interpreter memungkinkan agen Anda untuk:

- Jalankan kode dalam berbagai bahasa, termasuk:
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust, dan Fortran
- Memproses file secara aman melalui API Code Interpreter LibreChat
- Jalankan kode tanpa pengaturan lokal, konfigurasi, atau penerapan sandbox
- Tangani unggahan dan unduhan file dengan lancar
- [Info lebih lanjut tentang API Code Interpreter](/docs/features/code_interpreter)
  - **Diberdayakan oleh layanan [code-interpreter](https://github.com/ClickHouse/code-interpreter) sumber terbuka (di-host sendiri)**

Ketika setiap file Code Interpreter yang diperlukan dari sebuah percakapan gagal dipulihkan ke dalam sandbox saat ini, LibreChat akan menghentikan Agent sebelum memanggil model dan meminta pengguna untuk melampirkan kembali file tersebut. Hal ini mencegah eksekusi berlanjut dengan referensi file yang sudah kedaluwarsa atau tidak dapat diakses.

Ketika file percakapan memiliki nama file Code Interpreter yang sama, LibreChat menetapkan tujuan sandbox yang berbeda dan memberi tahu Agen mengenai path yang telah diselesaikan. Lihat [Seamless File Handling](/docs/features/code_interpreter#seamless-file-handling) untuk perilaku tabrakan dan batasan file pribadi multi-Agen yang tersisa.

#### Sesi Kode Stateful [#stateful-code-sessions]

Sesi kode stateful memungkinkan agen untuk menggunakan kembali ruang kerja sandbox di seluruh eksekusi kode. File, paket yang diinstal, dan status kerja biasanya akan terbawa, yang berguna untuk analisis iteratif dan pengerjaan file multi-langkah. Di dalam Agent Builder, pemilih **Stateful environment** mengontrol siapa yang berbagi ruang kerja tersebut:

- **Ruang kerja pengguna (disarankan):** agen stateful pengguna yang telah masuk berbagi satu ruang kerja
- **Ruang kerja agen + pengguna:** setiap pengguna mendapatkan ruang kerja terpisah untuk setiap agen
- **Ruang kerja percakapan:** setiap pengguna mendapatkan ruang kerja terpisah untuk setiap percakapan

Administrator juga dapat mengonfigurasi backend bernama di bawah [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Jika ada, pemilih **Execution environment** yang terpisah akan memilih Code API terkelola, VM yang terpasang pada operator, atau worker pribadi yang memiliki workspace tersebut; **Deployment default** menggunakan lingkungan eksekusi default yang telah dikonfigurasi. Cakupan berbagi di atas tetap independen dari pilihan backend tersebut.

Saat penerapan mengaktifkan pekerja swalayan (self-service workers), pengguna dengan izin pengelolaan Code Environment dapat membuka **Settings > Code environments** untuk memasangkan pekerja `@librechat/code` keluar (outbound) di VM mereka sendiri, memilihnya di Agent Builder, dan mencabutnya nanti. Lingkungan pribadi terikat pada pemilik dan menggunakan rute yang sama untuk kode, shell, dan Programmatic Tool Calling. Lihat [Attached environments and pairing](/docs/features/code_interpreter#attached-environments-and-pairing) untuk pengaturan eksperimental dan model keamanan.

Di dalam workspace yang dilampirkan, Agent dapat mencantumkan direktori, membaca file, mencari teks, membuat file, dan menjalankan Bash melalui worker yang dipilih. Nama dan email Git per-Agent dapat mengidentifikasi commit yang dibuat di sana tanpa perlu memberikan kredensial repositori. Deployment dapat membatasi worker pribadi baru dengan [`statefulCodeSessions.principalWorkers`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions).

Ketika worker yang terlampir mengiklankan beberapa root workspace, composer chat memerlukan satu pilihan untuk setiap lingkungan terlampir yang digunakan oleh Agent atau Subagent-nya. Percakapan mempertahankan pilihan tersebut di seluruh giliran dan kelanjutan persetujuan; LibreChat memvalidasinya terhadap worker yang aktif dan memblokir pengiriman jika workspace yang diperlukan hilang atau tidak tersedia. Worker yang mengiklankan tepat satu workspace akan dipilih secara otomatis untuk percakapan baru. Lihat [Attached environments and pairing](/docs/features/code_interpreter#attached-environments-and-pairing) untuk detail dan batasan saat ini.

Agen baru pada awalnya menggunakan **Default stateful workspace** pengguna yang masuk dari **Settings > Data Controls > Code execution**. Default pribadi adalah **User workspace** sampai diubah. Memperbarui preferensi ini tidak mengubah Agen yang sudah ada atau mengaktifkan Stateful Code Sessions dengan sendirinya. Administrator dapat membatasi cakupan yang tersedia dengan [`statefulCodeSessions.allowedEnvironments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions); ketika default pribadi yang disimpan tidak lagi diizinkan, Agen baru akan menggunakan cakupan pertama yang diizinkan.

<Callout type="warning" title="Sangat eksperimental">
  Stateful Code Sessions saat ini berada dalam tahap eksperimen awal. Perilaku, konfigurasi, karakteristik persistensi, dan integrasi dasarnya dapat berubah secara substansial. Jangan menganggap implementasi saat ini sebagai kontrak produksi yang stabil.
</Callout>

Fitur ini bersifat opt-in. Administrator harus menambahkan `stateful_code_sessions` ke [agent capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) dan mengonfigurasi rute Code Interpreter stateful khusus melalui [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) atau bernama [`statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Code Interpreter harus diaktifkan pada agen, dan **Stateful code sessions** harus dinyalakan di bawah pengaturan Lanjut (Advanced settings)-nya.

Permintaan stateful tidak akan kembali ke endpoint Code Interpreter stateless normal ketika URL khusus tidak tersedia atau tidak kompatibel. Sesi stateful dan stateless juga tidak berbagi file langsung atau paket yang terinstal. Workspace stateful dapat diatur ulang kapan saja, terlepas dari cakupannya. Di lingkungan Code Interpreter yang dikelola, simpan output penting di bawah `/mnt/data`; workspace yang dilampirkan adalah direktori terpisah yang dimiliki oleh worker. Unggahan chat tidak disalin ke direktori yang dilampirkan tersebut secara default. Jangan mengandalkan status sesi sebagai penyimpanan permanen.

Saat alat `create_file` atau `edit_file` yang bersifat stateful membuat file selama respons, pesan asisten akan menampilkan baris **Workspace changes** yang ringkas. Perluas baris tersebut untuk meninjau jalur yang diubah secara unik dan mengunduh setiap file melalui alur file terautentikasi LibreChat. Ini adalah catatan per-pesan dari file yang dibuat oleh alat-alat tersebut, bukan snapshot permanen dari seluruh workspace; output Code Interpreter yang bersifat stateless tetap menggunakan antarmuka lampiran inline yang biasa.

Untuk lingkungan yang terlampir, composer dapat menampilkan **Ask before changes**, **Accept edits**, dan **Full access** sebagai mode persetujuan Kode tingkat percakapan. Ketersediaan dibatasi oleh skema izin yang ditentukan administrator lingkungan; memilih mode yang lebih permisif tidak akan pernah mengesampingkan pemberian peran, aturan alat eksplisit, hook, atau batasan sandbox. Lihat [Attached-environment tool permissions](/docs/features/code_interpreter#attached-environment-tool-permissions).

### Pencarian File [#file-search]

Kemampuan File Search memungkinkan:

- Fungsionalitas RAG (Retrieval-Augmented Generation)
- Pencarian semantik di seluruh dokumen yang diunggah
- Respons yang sadar konteks berdasarkan isi file
- Dukungan lampiran file baik di tingkat agen maupun utas obrolan

### Konteks File [#file-context]

Kemampuan File Context memungkinkan agen Anda untuk menyimpan teks yang diekstrak dari file sebagai bagian dari instruksi sistemnya:

- Ekstrak teks sambil mempertahankan struktur dan pemformatan dokumen
- Memproses tata letak kompleks termasuk teks multi-kolom dan konten campuran
- Menangani tabel, persamaan, dan konten khusus lainnya
- Bekerja dengan konten multibahasa
- Teks disimpan dalam instruksi agent di dalam database
- **Tidak memerlukan layanan OCR** - Menggunakan penguraian teks secara default dengan metode cadangan
- **Ditingkatkan dengan OCR** - Jika OCR dikonfigurasi, kualitas ekstraksi akan meningkat untuk gambar dan dokumen yang dipindai
- Menggunakan logika pemrosesan yang sama seperti "Upload as Text": **OCR > STT > text parsing**
- [Info lebih lanjut tentang konfigurasi OCR](/docs/features/ocr)

**Catatan:** File Context menyertakan teks yang diekstrak ke dalam instruksi sistem agen. Untuk pertanyaan dokumen sementara dalam percakapan individu, gunakan [Upload as Text](/docs/features/upload_as_text) dari obrolan sebagai gantinya.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP adalah protokol terbuka yang menstandarisasi cara aplikasi menyediakan konteks ke Large Language Models (LLMs), yang bertindak seperti adaptor universal untuk alat AI dan sumber data.

Untuk informasi lebih lanjut, lihat dokumentasi tentang [MCP](/docs/features/mcp).

#### Agen dengan MCP Tools [#agents-with-mcp-tools]

1. Konfigurasikan server MCP di dalam file `librechat.yaml` Anda
2. Mulai ulang LibreChat untuk menginisialisasi koneksi
3. Buat atau edit agen
4. Buka **Add tools** di Agent Builder dan pilih **MCP**
5. Pilih server MCP yang ingin Anda tambahkan; setiap server akan muncul sebagai satu entri
6. Simpan perubahan Anda ke agen

Dalam contoh ini, kami telah menambahkan **[Spotify MCP server](https://github.com/LibreChat-AI/spotify-mcp)** ke sebuah agen.

![Agents - MCP](/images/agents/mcp_tools_v2.png)

#### Mengelola MCP Tools [#managing-mcp-tools]

Setelah server MCP ditambahkan ke agen, Anda dapat menyempurnakan alat spesifik mana yang tersedia:

- Setelah menambahkan server MCP, perluas server tersebut untuk melihat semua alat yang tersedia
- Centang/hapus centang alat individual sesuai kebutuhan
- Sebagai contoh, server MCP Spotify menyediakan ~20 alat (pencarian, kontrol pemutaran, manajemen daftar putar, dll.)
- Kontrol terperinci ini memungkinkan Anda membatasi agen hanya pada alat yang mereka perlukan

Server dengan cakupan permintaan (request-scoped) yang menggunakan `{{LIBRECHAT_BODY_*}}` tidak dapat melakukan enumerasi alat (tools) hingga sebuah chat run menyediakan nilai-nilai tersebut. Oleh karena itu, Agent Builder menampilkan satu pilihan runtime-tools untuk keseluruhan server, alih-alih tombol toggle per-alat; menghapus pilihan tersebut akan melepaskan server. Setelah OAuth, LibreChat menyimpan otorisasi tersebut dan menunggu hingga run pertama yang memenuhi syarat untuk melakukan koneksi.

Jika sebuah Agent secara eksplisit memilih alat MCP tetapi tidak ada yang dapat diselesaikan saat proses berjalan dimulai, LibreChat akan menghentikan proses tersebut dengan panduan koneksi dan akses alih-alih melanjutkannya secara diam-diam tanpa alat tersebut. Sambungkan kembali atau autentikasi server, verifikasi akses alat, dan coba jalankan kembali prosesnya.

### Deferred Tools [#deferred-tools]

Deferred tools memungkinkan agen untuk memiliki akses ke banyak MCP tools tanpa harus memuat semuanya ke dalam konteks LLM di awal. Sebagai gantinya, deferred tools dapat ditemukan saat runtime melalui mekanisme **Tool Search**.

Ini sangat berguna ketika agen memiliki akses ke banyak server MCP dengan puluhan alat—memuat semuanya akan menghabiskan sebagian besar jendela konteks dan menurunkan kualitas respons.

**Cara kerjanya:**

- Tools yang ditandai sebagai "deferred" dikecualikan dari konteks awal LLM
- Sebuah tool `ToolSearch` ditambahkan secara otomatis, yang memungkinkan LLM untuk menemukan dan memuat tool yang ditangguhkan (deferred tools) sesuai permintaan.
- Setelah ditemukan, alat tersebut tersedia untuk sisa percakapan.

**Mengonfigurasi deferred tools:**

1. Buka Agent Builder dan tambahkan alat MCP
2. Klik menu dropdown pada alat MCP mana pun
3. Alihkan "Defer Loading" — alat yang ditangguhkan akan menampilkan ikon jam

**Catatan:** Kemampuan `deferred_tools` diaktifkan secara default. Fitur ini dapat diaktifkan atau dinonaktifkan melalui konfigurasi agen [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).

### Grup Aktivitas [#activity-groups]

Grup aktivitas melipat setiap blok penalaran Agen dan pemanggilan alat yang berurutan di bawah satu header satu baris yang dibuat secara otomatis, sehingga memudahkan pemindaian pada proses yang panjang. Administrator mengaktifkannya dengan `activityLabel` dan dapat menggunakan model yang lebih cepat, endpoint lain yang dikonfigurasi, prompt kustom, dan batas per-eksekusi. Pembuatan header adalah panggilan model terpisah yang token dan biayanya dicatat. Lihat [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups).

Administrator dapat mengaktifkan `activityPhaseLabel` secara mandiri untuk membungkus dua atau lebih aktivitas logis ke dalam ringkasan induk yang diciutkan sebelum jawaban akhir. Hal ini memberikan kerangka tingkat tinggi untuk proses yang panjang sekaligus tetap mempertahankan setiap aktivitas anak. Ringkasan fase menggunakan model, endpoint, prompt, dan batas per-run miliknya sendiri, dengan fallback ke label aktivitas dan pengaturan run.

Segera setelah rangkaian berurutan berisi setidaknya dua grup alat berlabel yang telah selesai, LibreChat melipatnya ke dalam permukaan kartu fase yang sama bahkan sebelum ringkasan fase opsional tiba. Label anak terbaru yang telah selesai bertindak sebagai tajuk sementara sementara penalaran langsung dan pemanggilan alat yang masih berlangsung tetap berada di luar lipatan. Riwayat yang dimuat menggunakan pengelompokan yang sama, dan ringkasan fase yang dihasilkan server di kemudian hari menggantikan tajuk sementara tanpa menutup kartu yang telah dibuka oleh pembaca.

Saat [Smooth Streaming](/docs/features/smooth_streaming) diaktifkan, ringkasan induk yang baru dibuat akan melipat aktivitas yang terlihat ke dalam grup yang diciutkan dengan mulus. Riwayat yang dimuat tidak akan memutar ulang transisi ini, dan LibreChat menghormati preferensi *reduced-motion* pada perangkat.

Teks progres singkat tetap berada di dalam fase induknya. Saat Agen memulai jawaban yang substansial, LibreChat menutup fase sebelum teks tersebut agar hasil yang dilihat pengguna tetap berada di luar ringkasan yang diciutkan. Satu kali proses dapat membuat beberapa fase induk ketika penalaran atau alat (tools) selanjutnya memulai blok aktivitas logis lainnya. Batas fase yang dipertahankan akan diatur ulang (rebased) ketika bagian konten yang cacat atau dihilangkan dipadatkan, sehingga pengelompokan tetap selaras setelah dimuat ulang.

File yang dihasilkan di dalam sebuah fase tetap terlihat di baris media di bawah kartu yang diciutkan, alih-alih disembunyikan di dalamnya. Referensi gambar Markdown yang menggunakan nama file biasa, `/mnt/data/...`, atau jalur `sandbox:` akan terhubung ke lampiran giliran (turn) yang cocok. Sebuah file hanya akan dihilangkan dari baris media jika gambar inline di luar fase yang diciutkan berhasil dimuat, sehingga mencegah duplikasi tanpa harus mengandalkan referensi yang rusak.

Kartu alat Generic Agent dan MCP membedakan antara **Preparing** (sebelum serah terima SDK, yang mungkin mencakup persetujuan atau penantian lainnya) dan **Calling** (serah terima SDK hingga hasil). Kartu yang telah selesai menampilkan kedua interval tersebut; interval panggilan tidak selalu merupakan durasi eksekusi MCP atau ClickHouse di sisi upstream. Pesan yang disimpan sebelumnya serta kartu Code, Bash, file, dan memory khusus tetap mempertahankan durasi langkah eksekusi **Total elapsed** yang diberi label dengan jelas. Langkah yang dihentikan, dibatalkan, gagal, dan selesai tetap mempertahankan status yang berbeda, termasuk setelah pemuatan ulang percakapan.

Saat alat sedang berjalan, panel detail Bash, Execute Code, dan File Authoring yang diperluas akan mengikuti perintah, kode, atau konten pratinjau yang di-stream ke bagian bawah. Menggulir ke atas akan menjeda perilaku mengikuti tersebut sehingga posisi baca saat ini tetap terjaga.

Output Bash dirender sebagai teks bergaya terminal. Output yang panjang diringkas menjadi 15 baris terakhirnya, tempat di mana kesalahan biasanya muncul; gunakan **Show more** dan **Show less** untuk memperluas atau meringkasnya, serta tombol **Copy** untuk menyalin output tersebut. Perintah yang tidak mencetak apa pun akan menampilkan **No output**. Untuk perintah yang dijalankan di [attached workspace](/docs/features/code_interpreter#attached-environments-and-pairing), perintah yang gagal ditandai dengan alasannya (**exit code N**, **terminated by** sinyal seperti `SIGKILL`, atau **timed out**), dan stderr ditata secara terpisah dari stdout. Perintah yang selesai diberi label **Ran command**, dan grup alat yang berisi satu panggilan akan langsung terbuka ke detail panggilan tersebut.

### Label Penalaran Langsung [#live-reasoning-labels]

Label penalaran langsung menggantikan judul **Thinking** atau **Thoughts** generik dengan orientasi singkat yang berkembang seiring dengan aliran penalaran tingkat atas yang cukup panjang. Label ini memperbarui judul penalaran yang ada di tempatnya; label ini tidak menambahkan atau menyusun ulang bagian pesan.

Label penalaran langsung terbaru dan pengatur waktu respons akan berkedip saat pembuatan sedang aktif. Penalaran yang telah selesai, respons saudara yang lebih lama, dan label yang tidak lagi berada di posisi akhir langsung akan tetap statis.

Administrator mengaktifkan fitur ini dengan `reasoningLabel` dan dapat memilih model, endpoint, prompt, ambang batas pembaruan, serta batas panggilan per-run yang terpisah. Setiap revisi merupakan panggilan model tambahan yang token dan biayanya akan dicatat. Lihat [Live Reasoning Labels](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels) untuk nilai default, prioritas perutean, dan pertimbangan privasi.

### Label Intent Alat [#tool-intent-labels]

Label intent tool menggantikan status alat langsung yang umum dengan deskripsi singkat yang ditulis oleh model untuk panggilan spesifik tersebut. Administrator harus menambahkan `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) sebagai opsi. Alat bawaan menggunakan label secara otomatis; di Agent Builder, perluas server MCP dan aktifkan **Intent label** untuk alat individu atau seluruh server.

Untuk Model Specs, [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) dapat mengaktifkan setiap tool yang memenuhi syarat atau memilih ID tool yang telah ditentukan. Bidang intent ditambahkan ke skema tool yang dikirim ke model, sehingga pengaktifan selektif dapat mengurangi overhead token skema.

Label intent tidak berlaku untuk alat MCP yang hanya bersifat programatik karena panggilan yang dilakukan di dalam kode sandbox tidak merender kartu alat secara individual. Eksekusi programatik yang diperluas justru menampilkan jejak langsung (live trace) yang ringkas dari panggilan internalnya.

### Pemanggilan Alat Secara Programatis [#programmatic-tool-calling]

Programmatic Tool Calling (PTC) memungkinkan agen untuk mengeksekusi alat MCP yang dipilih dari dalam sandbox [Code Interpreter](/docs/features/code_interpreter) alih-alih memanggil setiap alat secara langsung dari model. Model menerima alat orkestrasi yang didukung oleh Code Interpreter, menulis kode dalam sandbox yang memanggil fungsi alat yang dihasilkan, serta dapat menggunakan perulangan, kondisional, percobaan ulang, dan pemrosesan hasil sebelum memberikan jawaban.

Ini berguna untuk alur kerja alat multi-langkah seperti melakukan kueri ke beberapa sumber daya, melakukan penomoran halaman melalui hasil, membandingkan output, atau mengubah respons alat sebelum agen menjelaskannya.

**Mengonfigurasi alat terprogram:**

1. Aktifkan `programmatic_tools` dan `execute_code` di dalam [`librechat.yaml` agents capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).
2. Aktifkan Code Interpreter pada agen.
3. Tambahkan alat MCP, perluas server MCP, dan aktifkan **Programmatic** untuk alat individu atau untuk seluruh server. Alat Programmatic menampilkan ikon kode.

Agent Builder menjaga tombol Programmatic tetap dinonaktifkan hingga Code Interpreter dipilih. Menghapus Code Interpreter akan segera menghapus pilihan Programmatic agen tersebut. Saat pembuatan, pembaruan, duplikasi, dan pemulihan versi, server juga akan menghapus opsi pemanggil programatik kapan pun kapabilitas `execute_code` atau alat Code Interpreter tidak tersedia; hal ini memungkinkan Agen lama yang tidak konsisten untuk dibuka dan diperbaiki tanpa mempertahankan konfigurasi yang tidak dapat digunakan.

**Catatan:** `programmatic_tools` bersifat opsional dan tidak disertakan dalam daftar kapabilitas agen default. PTC juga memerlukan deployment Code Interpreter dengan komponen Tool Call Server. Saat runtime, LibreChat mengiris proyeksi kapabilitas pemanggil saat ini dengan registri alat tepercayanya, sehingga data peristiwa dapat mempersempit peta yang tersedia tetapi tidak dapat memberikan alat. Hanya alat terprogram yang aktif dan terdaftar yang dapat dipanggil dari sandbox; panggilan yang tidak terdaftar akan ditolak.

Perluas kartu Code Interpreter selama proses berjalan secara terprogram untuk melihat jejak bergaya terminal dari setiap pemanggilan alat internal, pratinjau argumennya, status, durasi, dan kegagalan apa pun. Jejak ini bersifat langsung untuk sesi browser saat ini dan tidak dipulihkan setelah memuat ulang halaman.

### Panggilan Alat Latar Belakang [#background-tool-calls]

Panggilan alat latar belakang memungkinkan agen untuk memulai Code Interpreter, MCP, Plugin, atau Action yang memenuhi syarat dan berjalan dalam waktu lama, lalu tetap melanjutkan pekerjaannya. Panggilan awal akan segera kembali dengan referensi tugas. Untuk Agen yang disimpan, penyelesaian yang didukung akan dikirimkan secara otomatis dalam kelanjutan tindak lanjut secara default; `check_background_task` tetap tersedia untuk status eksplisit, kontrol, pengumpulan artefak, dan pemulihan.

`check_background_task` melaporkan `started_at` dan `elapsed_ms` saat ini ketika proses kerja lokal sedang berjalan. Setelah selesai, ia juga melaporkan `settled_at` dan membekukan `elapsed_ms` pada durasi yang telah diselesaikan. Hasil akhir yang dipulihkan dari penyimpanan tahan lama (durable storage) mungkin menyertakan `settled_at` tanpa waktu mulai atau durasi yang telah berlalu ketika stempel waktu pengiriman proses lokal asli tidak tersedia.

Untuk menggunakan fitur ini, administrator harus menambahkan kemampuan agen `run_in_background` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) yang bersifat opt-in. Kemudian, konfigurasikan alat yang memenuhi syarat di Agent Builder:

- **Code Interpreter:** Aktifkan Code Interpreter pada agen. Eksekusi kode dan perintah shell secara default memenuhi syarat untuk berjalan di latar belakang; nonaktifkan **Background execution** di pengaturan alatnya untuk memilih keluar.
- **MCP:** Buka server MCP dan tandai alat individual, atau seluruh server, sebagai **Background**.
- **Plugin tools:** Buka alat yang memenuhi syarat dan aktifkan **Background execution**.
- **Actions:** Aktifkan **Background execution** untuk sebuah Action guna memilih setiap operasi yang memenuhi syarat dalam Action tersebut. OAuth Actions tidak menampilkan tombol ini. Sebuah operasi juga akan dikecualikan jika skemanya sendiri sudah mendefinisikan parameter `run_in_background`, untuk menghindari konflik dengan flag dispatch LibreChat.

Pengaturan ini memungkinkan eksekusi latar belakang tetapi tidak memaksakannya. Model memutuskan per panggilan apakah akan menjalankan alat yang memenuhi syarat di latar belakang.

Dalam obrolan LibreChat, ketika kode latar belakang selesai dijalankan, stdout dan file yang dihasilkan akan muncul pada panggilan kode asli, bukan pada polling berikutnya. File yang dihasilkan juga disimpan untuk giliran (turn) berikutnya. Kelanjutan otomatis menyajikan pekerjaan yang telah selesai dalam kartu tugas wake-up yang dapat diciutkan dan ditautkan ke tugas asli.

Saat server memulai kelanjutan tersebut setelah proses latar depan sebelumnya selesai, percakapan yang terbuka akan terhubung ke generasi baru dan menyegarkan output tugas yang telah selesai tanpa memerlukan pemuatan ulang.

Penyelesaian otomatis (automatic completion wakeups) diaktifkan kecuali jika administrator menetapkan [`endpoints.agents.backgroundTasks.completionWakeups: false`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks), yang akan mengembalikan perilaku hanya-polling (poll-only). Host dapat menggabungkan beberapa penyelesaian khusus konten yang memenuhi syarat ke dalam satu kelanjutan. Tugas yang menghasilkan artefak langsung (live artifact) tetap memerlukan polling pada proses yang memiliki eksekusi tersebut.

Administrator juga dapat memilih pembatalan dengan cakupan pemilik (owner-scoped) dengan [`endpoints.agents.backgroundTasks.ordinaryToolCancellation: true`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks). Tugas tersebut melaporkan bahwa pembatalan telah diminta hingga pemanggilan yang mendasarinya selesai, dan kapasitasnya tetap dicadangkan selama interval tersebut. Pembatalan bersifat kooperatif: alat yang mengabaikan sinyal abort mungkin tetap selesai dengan sukses. Kontrol ini berlaku untuk alat latar belakang lokal proses biasa, termasuk Bash yang terlampir, tetapi tidak untuk Subagent terpisah yang dimiliki secara independen.

Hanya alat yang memenuhi syarat yang menampilkan pengaturan tersebut. Eksekusi latar belakang biasa bersifat lokal-proses dan tidak akan bertahan jika proses pekerja (worker process) hilang. Namun, setelah hasil terminal yang hanya berisi konten dipertahankan (persisted), pengiriman otomatis menjadi tahan lama dan dapat berlanjut pada replika lain. Registri lokal-proses membatasi tugas yang berjalan dan payload hasil yang disimpan per percakapan, pengguna, dan proses; registri ini mengeluarkan pekerjaan yang telah selesai jika aman dan mengembalikan hasil kapasitas terbatas ketika pemrosesan yang tertunda mencegah pengeluaran yang aman. Jika sebuah pemanggilan mengabaikan pembatalan, LibreChat berhenti memperbarui sewa produsennya setelah masa tenggang satu menit pasca-pembatalan dan menghentikan pengiriman penyelesaian otomatis tanpa secara keliru menandai pekerjaan eksternal yang tidak pasti sebagai waktu habis (timed out). Detached Subagents menggunakan jalur tugas dan transkrip tahan lama yang terpisah dengan kontrol langsung yang dirutekan melalui Redis; lihat [Detached Subagent Threads](/docs/features/subagents#detached-subagent-threads).

### Minta Persetujuan Pengguna dan Tool [#ask-user-and-tool-approval]

Alat **Ask User** memungkinkan agen untuk menjeda proses (run) guna meminta informasi yang kurang, menyajikan pilihan, atau mengonfirmasi langkah selanjutnya. Satu panggilan dapat mengelompokkan hingga empat pertanyaan terkait. LibreChat menyajikan satu pertanyaan dalam satu waktu dengan tombol Back, Next, dan langkah progres yang dapat diklik; jawaban tetap tersedia saat berpindah antar langkah, dan jawaban pilihan tunggal (single-select) akan berlanjut secara otomatis tanpa perlu menekan tombol kirim. Tombol Submit akan muncul pada langkah terakhir setelah setiap pertanyaan memiliki jawaban, sementara Skip akan membatalkan seluruh rangkaian pertanyaan dari langkah mana pun. Setiap pertanyaan menerima jawaban bentuk bebas atau pilihan tunggal maupun ganda dari agen. Saat model menyiapkan panggilan, LibreChat akan melakukan streaming pertanyaan ke dalam kartu progres; formulir interaktif akan menggantikannya setelah siap. Setelah satu pengiriman, proses yang sama akan dilanjutkan dengan peta jawaban yang lengkap. Tambahkan **Ask User** dari marketplace Tools; administrator dapat menghapus kapabilitas default `ask_user_question` untuk menyembunyikannya.

Menciutkan kartu multi-pertanyaan akan mengembalikan composer ke mode steer-or-queue normalnya sementara kartu yang dijeda tetap berada di dalam thread. Kartu tersebut masih dapat diperluas, dijawab, dilewati, atau dihentikan. Jeda pertanyaan tunggal akan terus menggunakan mode jawaban composer yang terfokus.

Jawaban yang dikirimkan akan disimpan bersama tindakan resume, sehingga berhenti saat proses resume berjalan tidak akan membuang jawaban yang telah diterima.

Setelah catatan pertanyaan selesai, secara default catatan tersebut akan menciut menjadi entri alat satu baris agar jawaban yang panjang tidak mendominasi transkrip. Buka entri tersebut untuk meninjau pertanyaan dan jeda baris yang dipertahankan dalam jawaban. Preferensi **Auto-expand tool details** yang ada juga mengontrol tampilan yang sudah selesai ini; formulir langsung tetap terbuka selama input masih diperlukan.

Setiap pertanyaan menerima judul opsional hingga 80 karakter, teks pertanyaan hingga 2.000 karakter, konteks pendukung opsional hingga 4.000 karakter, dan hingga 12 pilihan. Label pilihan dibatasi hingga 280 karakter, nilai pilihan hingga 500 karakter, dan setiap jawaban yang dikirimkan hingga 16.000 karakter.

Administrator juga dapat mewajibkan peninjauan sebelum pemanggilan tool yang cocok dijalankan. Bergantung pada tool-nya, pengguna dapat menyetujui, menolak, mengedit argumen, atau merespons secara langsung. Eksekusi yang dijeda akan disimpan di checkpoint sehingga dapat dilanjutkan setelah keputusan dibuat, termasuk pada replika lain saat checkpointer MongoDB default digunakan. Persetujuan tool di seluruh deployment dinonaktifkan secara default, sementara Agent yang menggunakan lingkungan Code terlampir akan menerima [kebijakan keamanan ask-by-default](/docs/features/code_interpreter#attached-environment-tool-permissions) kecuali jika administrator menonaktifkannya secara eksplisit. Lihat [`toolApproval` dan `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval).

Saat panel tinjauan composer terbuka untuk persetujuan yang tertunda, kartu utas yang sesuai akan menampilkan permintaan tersebut sebagai catatan alih-alih menduplikasi tombol keputusan. Tinjau panggilan di panel di atas kotak pesan dan pilih **Continue**. Menutup panel dari chip composer akan mengembalikan kontrol kartu utas dengan keputusan Anda tetap tersimpan; membukanya kembali akan mengalihkan tinjauan kembali ke panel. Kartu untuk tindakan lain tetap mempertahankan kontrolnya masing-masing.

### Skills [#skills]

Skills memungkinkan agen memuat instruksi yang dapat digunakan kembali dari definisi `SKILL.md`. Skills dapat dipilih secara manual dari obrolan dengan `$`, ditemukan secara otomatis oleh model melalui katalog skill, atau selalu diterapkan pada setiap giliran. Agent Builder juga dapat mengaktifkan penulisan runtime mandiri: agen dapat membuat Skill tanpa menerima katalog yang ada, atau mengedit Skill yang dipilih saat pengguna memiliki izin yang sesuai.

Untuk detail mengenai penulisan, pemanggilan, dan kontrol akses, lihat [Skills](/docs/features/skills).

### Memory [#memory]

Alat **Memory** memungkinkan agen untuk menyimpan, memperbarui, atau menghapus memori pengguna yang terstruktur ketika pengguna secara eksplisit memintanya untuk mengingat atau melupakan sesuatu. Memory harus dikonfigurasi untuk deployment, diizinkan oleh peran pengguna dan pengaturan personalisasi, serta diaktifkan pada agen tersebut.

Secara default, agen menggunakan kumpulan memori pribadi yang dibagikan oleh pengguna. Aktifkan **Keep memories separate for this agent** untuk memberikan partisi pribadi per-pengguna, per-agen. Agen yang terisolasi tidak akan melihat memori bersama yang sudah ada atau memori yang dibuat oleh agen terisolasi lainnya. Pengguna dapat memfilter panel Memory berdasarkan memori pribadi atau memori khusus agen. Membaca, membuat, atau memperbarui partisi Agen memerlukan akses saat ini ke Agen tersebut; penghapusan masih dapat membersihkan partisi setelah Agennya dihapus. Lihat [User Memory](/docs/features/memory#agent-memory).

### Artifacts [#artifacts]

Kemampuan Artifacts memungkinkan agen Anda untuk membuat dan menampilkan konten interaktif:

- Buat komponen React, kode HTML, dan diagram Mermaid
- Tampilkan konten di panel khusus di samping obrolan, yang dapat diperluas ke layar penuh atau dibuka di jendela peramban tersendiri
- Konfigurasikan instruksi khusus artefak di tingkat agen
- [Info lebih lanjut tentang Artifacts](/docs/features/artifacts)

Saat diaktifkan, pilih salah satu dari tiga mode instruksi:

- **Normal**: Menambahkan instruksi artefak standar untuk React, HTML, SVG, Markdown, dan Mermaid.
- **shadcn/ui**: Menambahkan instruksi standar serta panduan untuk membangun antarmuka dengan pustaka komponen shadcn/ui.
- **Custom**: Membiarkan rendering artefak tetap aktif tetapi tidak menyuntikkan instruksi artefak bawaan, sehingga memberikan kendali penuh kepada instruksi agen itu sendiri.

Mengonfigurasi artifacts di tingkat agen adalah pendekatan yang lebih disarankan, karena memungkinkan kontrol yang lebih terperinci dibandingkan dengan konfigurasi warisan di seluruh aplikasi.

Jika Anda memilih **Custom**, sertakan setidaknya format artefak dasar dalam instruksi Anda.

Berikut adalah contoh sederhana dari instruksi minimum yang diperlukan:

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

### Handoffs [#handoffs]

Handoff memungkinkan agen utama untuk mengalihkan percakapan ke agen spesialis dengan konteks yang relevan. Di **Advanced settings**, buka bagian orchestration dan tambahkan hingga 10 agen handoff. Setiap handoff yang dikonfigurasi akan membuat alat transfer yang dapat dipilih oleh model secara dinamis saat keahlian spesialis diperlukan.

Untuk setiap handoff, Anda dapat menambahkan deskripsi yang membantu model memilih spesialis yang tepat. Anda juga dapat memberikan instruksi passthrough yang menjelaskan konten apa yang harus dihasilkan oleh agen utama untuk spesialis tersebut dan secara opsional mengganti nama parameter konten dari default-nya, `instructions`. Handoff selalu tersedia di Agent Builder; tidak seperti Agent Chain dan Subagents, fitur ini tidak memerlukan kemampuan endpoint untuk diaktifkan. Panggilan alat (tool calls) dari agen handoff yang dapat dijangkau tetap terstruktur pada giliran berikutnya, sehingga penyedia menerima riwayat panggilan alat yang valid alih-alih teks yang diratakan.

### Subagents [#subagents]

Subagents memungkinkan agen untuk mendelegasikan tugas terfokus ke proses anak yang terisolasi atau tim Agen yang tersimpan. Setiap anak mendapatkan konteks dan eksekusi alat yang terisolasi, kemudian mengembalikan hasil yang ringkas kepada induknya alih-alih memenuhi konteks induk dengan setiap langkah perantara. Pekerjaan anak yang terpisah juga disimpan sebagai utas yang dapat dinavigasi dan hanya untuk dilihat.

Subagents berbeda dari Agent Chain: chain runs mengoordinasikan beberapa agen sebagai partisipan grafik, sementara subagents dibuat oleh agen sebagai panggilan alat (tool call) untuk delegasi yang terlingkup. LibreChat mempertahankan riwayat panggilan alat terstruktur yang diperlukan oleh anak yang dapat dijangkau dan anggota tim yang disimpan di seluruh giliran berikutnya, sambil menjaga alat yang tidak tersedia tetap di luar proses yang sedang berjalan. Untuk pengaturan dan batasan, lihat [Subagents](/docs/features/subagents).

### Pengaturan Lanjutan [#advanced-settings]

Pengaturan lanjutan untuk agen Anda (ditemukan di tampilan Advanced pada formulir Agent) di luar "capabilities."

#### Langkah Agen Maksimum [#max-agent-steps]

Pengaturan ini memungkinkan Anda untuk membatasi jumlah langkah yang dapat diambil oleh agen dalam sebuah "run," yang merujuk pada loop agen sebelum respons akhir diberikan.

Jika dibiarkan tanpa konfigurasi, nilai defaultnya adalah 25 langkah, tetapi Anda dapat menyesuaikannya dengan kebutuhan Anda. Untuk admin, Anda dapat menetapkan nilai default global serta nilai maksimum global di dalam file [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit).

Ketika sebuah giliran menggunakan anggaran langkah penuhnya, LibreChat mempertahankan respons parsial dan panggilan alat alih-alih menggantinya dengan kesalahan. Pesan tersebut menawarkan **Keep going**, yang memulai giliran baru dengan anggaran alat yang baru, dan **Answer now**, yang meminta agen untuk menjawab dari pekerjaan yang telah diselesaikan tanpa alat tambahan. Menutup pemberitahuan tersebut hanya memengaruhi tampilan peramban saat ini.

Administrator juga dapat membatasi argumen *tool-call* yang di-*stream* dan *event* delta model dengan [Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers).

"Step" (langkah) merujuk pada permintaan API AI atau satu putaran penggunaan alat (1 atau banyak alat, tergantung pada berapa banyak panggilan alat yang disediakan LLM dari satu permintaan).

Satu respons non-alat adalah 1 langkah. Satu putaran penggunaan alat biasanya terdiri dari 3 langkah:

1. Permintaan API -> 2. Penggunaan Tool (1 atau banyak tool) -> 3. Permintaan API Lanjutan

## Manajemen File [#file-management]

Agents mendukung berbagai cara untuk bekerja dengan file:

### Di Antarmuka Obrolan [#in-chat-interface]

Saat mengobrol dengan agen, Anda memiliki empat opsi unggahan:

1. **Unggah Gambar**
   - Mengunggah gambar untuk dukungan model vision native
   - Mengirim gambar secara langsung ke penyedia model

2. **Unggah sebagai Teks** (memerlukan kapabilitas `context`)
   - Mengekstrak dan menyertakan konten dokumen lengkap dalam percakapan
   - Menggunakan penguraian teks secara default; ditingkatkan dengan OCR jika dikonfigurasi
   - Konten hanya ada dalam percakapan saat ini
   - Lihat [Upload as Text](/docs/features/upload_as_text)

3. **Unggah untuk Pencarian File** (memerlukan kapabilitas `file_search`, diaktifkan ke posisi ON)
   - Menggunakan pencarian semantik (RAG) dengan penyimpanan vektor
   - Mengembalikan potongan yang relevan melalui penggunaan tool
   - Optimal untuk dokumen besar/banyak file
   - Kurang optimal untuk data terstruktur (CSV, Excel, JSON, dll.)

4. **Unggah untuk Code Interpreter** (memerlukan kapabilitas `execute_code`, diaktifkan ke posisi ON)
   - Menambahkan file ke lingkungan code interpreter
   - Optimal untuk data terstruktur (CSV, Excel, JSON, dll.)
   - Info lebih lanjut tentang [Code Interpreter](/docs/features/code_interpreter)

### Di Agent Builder [#in-agent-builder]

Saat mengonfigurasi agen, Anda dapat melampirkan file dalam kategori yang berbeda:

1. **Unggah Gambar**: Untuk konten visual yang dapat dirujuk oleh agen
2. **Unggahan Pencarian File**: Dokumen untuk kapabilitas RAG
3. **Code Interpreter Upload**: File untuk pemrosesan kode
4. **Konteks Berkas**: Dokumen dengan teks yang diekstrak untuk melengkapi instruksi agen

**File Context** menggunakan kapabilitas `context` dan bekerja persis seperti ["Upload as Text"](/docs/features/upload_as_text) - fitur ini menggunakan penguraian teks secara default dan ditingkatkan dengan OCR saat dikonfigurasi. Teks diekstraksi pada saat pengunggahan dan disimpan dalam instruksi agen. Ini sangat ideal untuk memberikan pengetahuan persisten kepada agen dari dokumen, PDF, file kode, atau gambar yang berisi teks.

**Prioritas pemrosesan:** OCR > STT > penguraian teks (sama dengan Unggah sebagai Teks)

**Catatan:** Teks yang diekstraksi disertakan sebagai bagian dari instruksi sistem agen.

## Berbagi dan Izin [#sharing-and-permissions]

Agen menggunakan sistem [access control](/docs/features/access_control) yang terperinci dari LibreChat. Setiap agen memiliki Access Control List (ACL)-nya sendiri, dan dapat dibagikan kepada **pengguna**, **grup**, **peran**, atau **secara publik**, masing-masing dengan tingkat izin yang dipilih.

Layanan tepercaya juga dapat mengelola Agen, file yang dilampirkan, dan Skill melalui [Agent Management API](/docs/features/agents_api#agent-management-api) versi beta. Administrator mengikat setiap klien mesin OIDC ke satu pengguna dan penyewa LibreChat yang sudah ada; setiap permintaan mewarisi kapabilitas peran dan ACL sumber daya pengguna tersebut saat ini, alih-alih menerima akses administratif yang terpisah.

### Peran Akses [#access-roles]

Saat membagikan agen, penerima akan diberikan salah satu dari tiga peran berikut:

| Peran | Apa yang dapat dilakukan penerima hak |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | Menggunakan agen dalam percakapan; tidak dapat membuka builder atau melihat instruksi, tools, atau file yang dilampirkan |
| **Editor** | Melihat + mengubah instruksi, model, tools, dan file agen |
| **Owner**  | Kontrol penuh: melihat, mengedit, menghapus, dan membagikan ulang agen |

Penulis asli dan administrator selalu memegang kendali penuh terlepas dari ACL.

### Berbagi Agen [#sharing-an-agent]

1. Buka agen di Agent Builder
2. Klik tombol **Share** di footer (terlihat saat Anda adalah penulis, admin, atau telah diberikan izin `SHARE` pada agen spesifik tersebut)
3. Cari pengguna, grup, atau peran di pemilih orang (people picker) dan tetapkan peran untuk masing-masing.
4. Secara opsional, aktifkan **Public** untuk membuat agen terlihat oleh semua orang di instance tersebut (memerlukan izin fitur `SHARE_PUBLIC`)

Kartu agen dan tampilan landas menampilkan kontak dukungan yang telah dikonfigurasi. Jika tidak ada yang ditetapkan, LibreChat dapat menggunakan nama tampilan pemilik pertama yang dapat diselesaikan sebagai cadangan, namun tidak akan menampilkan alamat email pemilik kecuali jika dikonfigurasi secara eksplisit sebagai kontak dukungan.

Permukaan percakapan menjaga Agent sebagai identitas yang terlihat dan tidak kembali ke model pendukung atau label model-spec-nya.

Untuk detail lengkap mengenai prinsipal, bit izin, dan bagaimana ACL disusun dengan izin fitur berbasis peran, lihat [Access Control](/docs/features/access_control).

### Agent Marketplace [#agent-marketplace]

**Agent Marketplace** memungkinkan pengguna untuk menelusuri agen yang tersedia bagi mereka. Buka dari **Agent Marketplace** di bilah sisi; entri tersebut hanya muncul bagi pengguna yang perannya diizinkan untuk menggunakan Marketplace.

- **Telusuri dan cari**: Agen muncul dalam bentuk kisi. Gunakan kolom pencarian untuk menemukan agen berdasarkan nama atau deskripsi, dan gunakan pil kategori (seperti **Pilihan Utama**, **Semua**, atau kategori tertentu) untuk mempersempit daftar.
- **Urutkan**: Gunakan **Urutkan berdasarkan** untuk menyusun agen berdasarkan **Terbaru** (default), **Terlama**, **Populer** (paling banyak disematkan), atau **Berdasarkan nama pembuat**.
- **My agents**: Aktifkan **My agents** untuk hanya menampilkan agen yang Anda buat. Mengaktifkannya dari **Top Picks** akan beralih ke **All**.
- **Tampilan yang dapat dibagikan**: Pencarian, pengurutan, dan filter **My agents** disimpan di URL halaman (`?q=`, `?sort=`, `?mine=1`), sehingga tampilan yang telah difilter dapat ditandai (bookmark) atau dibagikan.

Pilih kartu agen untuk membuka dialog detailnya, yang menampilkan deskripsi lengkap dan kontak agen, beserta tindakan-tindakan berikut:

- **Sematkan** atau **Lepas Sematan**: Menambahkan agen ke, atau menghapusnya dari, daftar agen yang Anda sematkan.
- **Salin Tautan**: Salin tautan yang memulai obrolan baru dengan agen.
- **Start Chat**: Memulai percakapan baru dengan agen.
- **Coba pemulai percakapan**: Saat agen memiliki [conversation starters](#conversation-starters), pilih salah satu untuk membuka obrolan baru dengan prompt tersebut yang sudah ada di input pesan. Pesan tidak dikirim secara otomatis, jadi Anda dapat mengeditnya terlebih dahulu.

Administrator dapat mengontrol akses dengan pengaturan [`interface.marketplace`](/docs/configuration/librechat_yaml/object_structure/interface#marketplace) dan izin peran yang dijelaskan dalam [Access Control](/docs/features/access_control).

### Kontrol Administrator [#administrator-controls]

Administrator memiliki akses ke pengaturan izin global di dalam UI pembuat agen:

- Aktifkan/nonaktifkan berbagi agen untuk semua pengguna
- Kontrol izin penggunaan agen
- Kelola hak pembuatan agen
- Konfigurasikan pengaturan seluruh platform

Dalam penyebaran single-tenant tanpa cakupan (unscoped), akun pertama yang dibuat untuk instans tersebut adalah administrator. Penyebaran dengan cakupan tenant (tenant-scoped) tidak secara otomatis mempromosikan pengguna pertama yang terdaftar; sediakan administrator tenant melalui alur administratif tepercaya. Jika Anda perlu menambahkan administrator secara manual, Anda dapat [mengakses MongoDB](/docs/configuration/mongodb/mongodb_auth) dan memperbarui profil pengguna tersebut:

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

Penggunaan agen untuk semua pengguna juga dapat dinonaktifkan melalui konfigurasi, [informasi lebih lanjut](/docs/configuration/librechat_yaml/object_structure/interface).

Izin tingkat fitur (siapa yang dapat _menggunakan_, _membuat_, _membagikan_, atau _membagikan secara publik_ agen) dikelola dari [**LibreChat Admin Panel**](/docs/features/admin_panel) pada setiap peran, termasuk peran kustom apa pun. Blok [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) di dalam `librechat.yaml` masih dapat menetapkan nilai default untuk peran `USER` bawaan saat startup, namun panel admin adalah cara yang direkomendasikan untuk mengeditnya di masa mendatang.

### Berbagi Tingkat Pengguna [#user-level-sharing]

Pengguna individu dapat:

- Bagikan agen mereka kepada pengguna, grup, atau peran tertentu (jika `SHARE` diaktifkan untuk peran mereka)
- Membuat agen terlihat oleh semua orang di instance (jika `SHARE_PUBLIC` diaktifkan)
- Berikan setiap penerima tingkat akses yang berbeda (Viewer / Editor / Owner)
- Bagikan ulang atau cabut akses kapan saja dari dialog berbagi

## Steering dan Pesan yang Diantrekan [#steering-and-queued-messages]

Saat Agent sedang memberikan respons, Anda dapat mengirim pesan lain dari [composer](/docs/features/composer) dengan salah satu dari dua cara berikut:

- **Steer** menyisipkan pesan ke dalam proses yang sedang berjalan pada langkah alat atau agen berikutnya, sehingga agen dapat menyesuaikan pekerjaannya sebelum selesai.
- **Queue** menampung pesan dan mengirimkannya sebagai giliran tindak lanjut normal setelah respons saat ini selesai.

Untuk percakapan Agen yang disimpan di server saat ini, tindak lanjut dalam antrean biasa disimpan di MongoDB. LibreChat mempertahankan urutan FIFO mereka dan membawa teks, lampiran, kutipan, dan Skill yang dipilih secara manual melintasi pemutusan koneksi browser, mulai ulang aplikasi, dan serah terima replika. Pemrosesan menunggu respons sebelumnya selesai sebelum menerima giliran berikutnya. Ketahanan ini bersifat otomatis dan tidak memiliki toggle YAML atau lingkungan; server yang lebih lama dan jendela startup singkat tanpa epoch pembuatan aktif tetap mempertahankan antrean kompatibilitas sisi klien.

Penerimaan server diserialisasi di dalam setiap jalur antrean percakapan. Jika bukti pendahulu atau kepemilikan versi campuran ambigu, LibreChat akan menampilkan **Awaiting reconciliation** dan memblokir atau menggagalkan giliran antrean yang terdampak alih-alih menebak dan memulainya di luar urutan.

**Steer sooner** meminta agen untuk mengambil pesan pada titik aman berikutnya alih-alih menunggu langkah alat (tool) selanjutnya. Jika belum ada teks jawaban atau aktivitas alat yang aman untuk disimpan, LibreChat akan menunggu selama periode tenggang singkat, membuang upaya yang senyap atau hanya berisi penalaran, menyisipkan pesan tersebut, dan memulai ulang model dengan instruksi itu. Setelah teks jawaban dapat disimpan, LibreChat akan berhenti pada batas yang aman bagi penyedia, mempertahankan respons parsial, menyisipkan pesan, dan melanjutkan respons asisten yang sama. Panggilan alat yang sedang berjalan tidak akan dibuang atau diinterupsi oleh steering; pesan tersebut akan diterapkan ketika pekerjaan itu mencapai batas yang aman.

Gunakan **Stop** untuk mengakhiri penalaran aktif dan meminta pembatalan panggilan alat latar depan. Stop meneruskan pembatalan untuk memberi sinyal pada alat latar depan yang sadar sinyal; pekerjaan latar belakang yang terpisah tetap mempertahankan siklus hidupnya yang independen. Gunakan kontrol composer khusus, pilih dari menu tombol kirim, atau tekan `Command/Ctrl + Shift + .`. Tindakan ini akan kembali ke pengarahan biasa jika deployment tidak dapat menginterupsi aliran penyedia yang aktif.

Di bawah **Settings → Chat**, **While generating, Enter will** memilih tindakan default. Menu tombol kirim dapat mengganti pilihan tersebut untuk pesan individu, dan **Steer sooner on Enter** membuat Enter meminta titik aman yang lebih awal saat steering menjadi pilihan default.

File dan [kutipan](/docs/features/message_actions#quote-excerpts) disertakan bersama pesan steer, queue, dan interrupt. Skills yang dipilih secara manual tetap berada dalam status staged untuk giliran penuh berikutnya alih-alih dilampirkan pada steer di tengah proses berjalan.

Steer yang tertunda muncul di akhir balasan streaming, tempat mereka akan mendarat, hingga server memasukkannya ke dalam run. Penerimaannya berproses dari **Sending** ke **Delivered**, kemudian **Steer sooner requested** ketika titik aman yang lebih awal diminta, dan akhirnya **Applied** dengan tanda centang ganda di tepi kanan bawah pesan inline. Resi yang telah dikonfirmasi diterapkan tetap terlihat setelah memuat ulang dan dalam tampilan bagikan atau pencarian; pengiriman yang tidak pasti atau gagal tidak akan pernah menampilkan tanda centang konfirmasi. Setelah diakui, menu pesan dapat mengambil kembali steer untuk diedit, mengubahnya menjadi tindak lanjut dalam antrean, atau membatalkannya dan mengembalikan teks serta lampirannya ke komposer. LibreChat menghindari penimpaan draf yang lebih baru; jika komposer tidak lagi tersedia, LibreChat akan menyimpan pesan yang diambil kembali tersebut di dalam antrean. Steer yang gagal tetap tersedia untuk dicoba kembali, diedit, diantrekan, atau dihapus.

Tindak lanjut dalam antrean muncul dalam daftar di atas komposer. Masing-masing dapat diedit (**Edit message**), dihapus (**Remove message**), dikirim segera dengan **Send now**, atau diurutkan ulang dengan menyeret pegangannya atau menekan tombol panah di atasnya. Tindak lanjut dalam antrean juga dapat diubah menjadi *steer* saat proses masih aktif atau ditingkatkan dengan **Steer sooner**. *Steer* yang sedang berjalan menawarkan peningkatan yang sama saat masih menunggu batas *tool*. Menghapus pesan dalam antrean yang didukung server akan membatalkan sumber permanennya terlebih dahulu, kemudian memulihkannya ke komposer kosong jika memungkinkan. Jika respons sebelumnya dibatalkan atau gagal, LibreChat akan menandai giliran dalam antrean yang terdampak sebagai gagal untuk ditinjau alih-alih mengirimkannya secara diam-diam.

Sebuah percakapan dapat memiliki hingga 100 giliran antrean aktif. Setiap giliran antrean menerima hingga 16.000 karakter dan 10 file. Secara terpisah, satu proses aktif menerima hingga 10 *steer* tertunda; setiap *steer* dapat mencakup hingga 10 file dan dibatasi oleh [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls). **Steer sooner** terus menggunakan jalur *steering* langsung alih-alih memindahkan giliran antrean ke depan jalur FIFO yang tahan lama.

Penyebaran multi-replika yang didukung Redis menegosiasikan protokol generasi v2 secara otomatis. Ikuti [panduan kompatibilitas protokol generasi](/docs/configuration/redis#generation-protocol-compatibility) saat melakukan peningkatan dari rilis yang lebih lama dari `v0.8.8-rc1`.

### Catatan [#notes]

- Instruksi, parameter model, file yang dilampirkan, dan alat hanya akan ditampilkan kepada pengguna jika mereka memiliki izin penyuntingan.
  - Agen dapat membocorkan data apa pun yang dilampirkan, baik instruksi maupun file, melalui percakapan, jadi pastikan instruksi Anda cukup kuat untuk menghadapi hal ini sebelum memberikan akses Editor/Owner atau membuat agen tersebut menjadi publik.
- Hanya penulis asli, administrator, dan penerima dengan izin Owner yang dapat menghapus agen yang dibagikan.
- Agen bersifat pribadi bagi penulis kecuali jika dibagikan

## Pengiriman Acara Agen [#agent-event-delivery]

LibreChat menyertakan lapisan pengiriman netral-sumber untuk peristiwa Agen asinkron. Adaptor milik penyebaran dapat menormalisasi webhook terverifikasi, pesan antrean, peristiwa MCP, peristiwa saluran, atau peristiwa produk internal menjadi eksekusi Agen baru (`fire`), giliran baru pada Agen dan cabang yang tersimpan (`continue`), atau mutasi dari eksekusi aktif (`steer`). Adaptor tetap bertanggung jawab untuk mengautentikasi sumber aslinya, membersihkan payload, dan memilih target tepercaya sebelum memasukkannya ke dalam antrean.

[Endpoint acara Agents API](/docs/features/agents_api#agent-events) versi beta mengekspos akses `fire`, `continue`, dan `steer` yang terautentikasi ke kunci API Remote Agents. Sistem eksternal dapat mengikat aktor sumber ke Agent turunan langsung dan melanjutkan aktor tersebut di seluruh acara tanpa perlu mengaktifkan fitur tambahan. LibreChat memperoleh identitas pengguna, penyewa, dan sumber dari kunci API, menegakkan akses Agent dan filter konten, serta memerlukan kunci idempotensi. Ini bukan penerima webhook tujuan umum yang tidak terautentikasi; adaptor khusus penyedia tetap harus memverifikasi tanda tangan webhook asli sebelum memanggilnya.

Fitur eksperimental [Scheduled Chats](/docs/features/scheduled_chats) adalah produser bawaan pertama LibreChat untuk lapisan ini. Fitur ini membuat pengiriman `fire` berulang untuk Agen yang disimpan dan dinonaktifkan hingga administrator memilih untuk mengaktifkannya. Subagen yang terpisah (Detached Subagents) secara otomatis menggunakan pengiriman `continue` yang idempoten untuk membangunkan Agen induk yang disimpan setelah agen anak selesai; agen anak yang dibatalkan dan Agen induk efemeral tidak disertakan.

MongoDB menyimpan amplop berversi terbatas, kunci idempoten, jalur pengurutan, sewa, riwayat percobaan ulang, tanda terima tahan lama, dan surat mati (dead letters). Pekerja menggunakan pengiriman setidaknya-sekali dengan klaim berpagar dan backoff eksponensial terbatas; tanda terima yang berhasil akan kedaluwarsa setelah 90 hari, sementara surat mati memerlukan antrean ulang tepercaya yang eksplisit. Pengiriman Fire membuat percakapan baru. Pengiriman Continue membuat giliran baru pada cabang percakapan yang tepat dan menunda sementara cabang tersebut berjalan, dijeda, atau diselesaikan. Aktor terikat juga memiliki kotak surat otomatis: satu aktor menunggu hasil penanganan gilirannya saat ini sebelum mengirimkan peristiwa berikutnya, sementara aktor yang berbeda dapat berjalan secara paralel. Pengiriman Steer harus mengidentifikasi percakapan dan generasi yang ada serta menggunakan penerimaan ketat agar percobaan ulang yang ambigu tidak dapat menyuntikkan instruksi yang sama dua kali.

Untuk kelanjutan terikat (bound continuations), keberhasilan pengiriman memulai siklus hidup penanganan yang tahan lama secara terpisah. Pengiriman berkembang dari `started` menjadi `applied`, `completed_no_action`, `failed`, atau `cancelled`. Sumber dapat meminta alat yang tepat dan subset argumen opsional dengan `expectedAction`; LibreChat melaporkan `applied` hanya dari bukti alat yang cocok yang diamati oleh host, bukan dari prosa yang ditulis model. Peristiwa observasional yang kompatibel dapat berbagi batch `coalesce.key` yang terikat sambil tetap mempertahankan satu catatan idempotensi dan tanda terima per peristiwa sumber. Kelanjutan titik pemeriksaan (checkpoint continuation) digunakan jika kompatibel dan jika tidak, akan kembali ke riwayat pesan yang tahan lama.

Bound Event Actors dapat berhenti sejenak untuk Ask User atau persetujuan tool dan melanjutkan pemanggilan actor yang telah ditandatangani secara tepat melalui antarmuka human-in-the-loop normal LibreChat. Kotak surat actor tetap diblokir hingga jeda tersebut dilanjutkan atau diselesaikan, mencegah peristiwa di kemudian hari mendahului keputusan tersebut. Actor ini memerlukan checkpointer MongoDB yang tahan lama (durable). LibreChat memilih kelanjutan checkpoint atau rekonstruksi riwayat yang tahan lama secara otomatis dari status actor dan kapabilitas permintaan; pekerjaan protocol-v1 yang ada tetap berada di jalur riwayat hingga terkuras.

Detached Actions yang dimulai oleh Event Actors diaktifkan secara otomatis ketika penyimpanan generasi bawaan mengiklankan dukungan. Aktor tetap ditangguhkan sampai bukti terminal melanjutkan pemanggilan aslinya, sehingga peluncuran latar belakang saja tidak memenuhi `expectedAction`. Penyimpanan dalam memori menjaga siklus hidup ini tetap koheren selama prosesnya tetap berjalan. Redis menambahkan pemulihan mulai ulang yang tahan lama dan serah terima replika. Pekerjaan penyelesaian yang dimiliki kapabilitas diisolasi dari pekerja yang lebih lama selama pengurasan versi campuran; operator tidak memilih perilaku ini dengan tanda fitur.

Host eksekusi biasanya memanggil listener yang terikat pada proses saat ini. Konfigurasikan [`endpoints.agents.eventDriven.selfUrl`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven) hanya jika jalur masuk internal tepercaya ini harus melewati origin HTTP lain, seperti pintu depan TLS.

## Praktik Terbaik [#best-practices]

- Berikan instruksi yang jelas dan spesifik untuk agen Anda
- Pertimbangkan dengan cermat alat mana yang diperlukan untuk kasus penggunaan Anda
- Atur file dengan tepat di seluruh empat kategori unggahan
- Tinjau pengaturan izin sebelum membagikan agen
- Uji agen Anda secara menyeluruh sebelum menyebarkannya ke pengguna lain

## Rekap [#recap]

1. Pilih "Agents" dari menu tarik-turun endpoint
2. Buka panel Agent Builder
3. Isi detail agen yang diperlukan
4. Konfigurasikan kapabilitas yang diinginkan (Code Interpreter, File Search, File Context, dll.)
5. Tambahkan alat dan file yang diperlukan
6. Atur izin berbagi jika diinginkan
7. Buat dan mulai gunakan agen Anda

Saat mengobrol dengan agen, Anda dapat:

- Gunakan "Upload as Text" untuk menyertakan konten dokumen lengkap dalam percakapan (penguraian teks secara default, ditingkatkan dengan OCR)
- Gunakan "Upload for File Search" untuk pencarian semantik pada dokumen (memerlukan RAG API)
- Tambahkan file ke "File Context" agen untuk menyertakan konten lengkap file sebagai bagian dari instruksi sistem agen

## Migrasi Diperlukan (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="Penting: Migrasi Izin Agen Diperlukan">
  Mulai dari versi v0.8.0-rc3, LibreChat menggunakan sistem izin berbasis Access Control List (ACL) yang baru untuk agen. Jika Anda melakukan peningkatan dari versi sebelumnya, Anda harus menjalankan migrasi izin agen agar agen yang sudah ada tetap dapat diakses.
</Callout>

### Apa yang Dilakukan Migrasi Ini [#what-the-migration-does]

Migrasi izin agen mengalihkan agen Anda dari model kepemilikan sederhana ke sistem berbasis ACL yang canggih dengan berbagai tingkat izin:

- **OWNER**: Kontrol penuh atas agen
- **EDITOR**: Dapat melihat dan mengubah agen
- **VIEWER**: Akses baca-saja ke agen

Tanpa menjalankan migrasi ini, agen yang sudah ada tidak akan dapat diakses melalui endpoint API baru yang mendukung izin (permission-aware).

### Menjalankan Migrasi [#running-the-migration]

Pilih perintah yang sesuai berdasarkan metode deployment Anda:

#### 1. Untuk `docker-compose.yml` default (jika Anda menggunakan `docker compose up` untuk memulai aplikasi): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**Pratinjau perubahan (dry run):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**Jalankan migrasi:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**Ukuran batch kustom (untuk dataset besar):**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. Untuk `deploy-compose.yml` [#2-for-the-deploy-composeyml]

Jika Anda mengikuti [Panduan Docker Ubuntu](/docs/remote/docker_linux):

**Pratinjau perubahan (dry run):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**Jalankan migrasi:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**Ukuran batch kustom (untuk dataset besar):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. Untuk pengembangan lokal (dari root proyek): [#3-for-local-development-from-project-root]

**Pratinjau perubahan (dry run):**

```bash
npm run migrate:agent-permissions:dry-run
```

**Jalankan migrasi:**

```bash
npm run migrate:agent-permissions
```

**Ukuran batch kustom (untuk dataset besar):**

```bash
npm run migrate:agent-permissions:batch
```

### Apa yang Terjadi Selama Migrasi [#what-happens-during-migration]

- **Private Agents**: Tetap hanya dapat diakses oleh pembuatnya (menerima izin OWNER)
- **Shared Agents**: Jika agen sebelumnya telah dibagikan, agen tersebut akan menerima entri ACL yang sesuai sebagai Public Agent (dibagikan kepada semua pengguna)
- **Deteksi Sistem**: LibreChat secara otomatis mendeteksi agen yang belum dimigrasi saat startup dan menampilkan peringatan

Anda dapat menyesuaikan izin agen yang dihasilkan melalui UI Agent Builder.

<Callout type="info" title="Catatan">
  Proses migrasi yang sama berlaku untuk prompt. Jika Anda juga memiliki prompt yang sudah ada, jalankan migrasi izin prompt menggunakan perintah yang sama, tetapi ganti `agent` dengan `prompt` pada nama perintah tersebut.
</Callout>

## Apa selanjutnya? [#whats-next]

Agen LibreChat mengantarkan era baru bagi aplikasi ini di mana alur kerja di masa depan dapat disederhanakan melalui Agen untuk tugas dan alur kerja tertentu di seluruh pengalaman Anda di LibreChat.

Pembaruan di masa mendatang akan mencakup:

- Peningkatan umum pada pengalaman Agent saat ini
- Orkestrasi multi-agen untuk alur kerja yang kompleks
- Kemampuan untuk menyesuaikan agen untuk berbagai fungsi: penjudulan (penamaan utas obrolan), manajemen memori (konteks/riwayat pengguna), dan peningkatan prompt (bantuan/prediksi input)
- Lebih banyak alat, parameter alat yang dapat dikonfigurasi, pembuatan alat secara dinamis.

Selain itu, pembaruan ini memperkenalkan paradigma baru bagi LibreChat, karena arsitektur dasarnya memberikan penyegaran yang sangat dibutuhkan untuk aplikasi ini, mengoptimalkan pengalaman pengguna dan kinerja aplikasi secara keseluruhan.

Sebagai sorotan atas satu optimalisasi penting, pembuatan AI sekitar 1000 token akan mentransfer data sebesar kurang lebih 1 MB menggunakan endpoint tradisional (pada saat penulisan ini, opsi endpoint apa pun selain Agents dan AWS Bedrock).

Menggunakan agen, generasi yang sama akan mentransfer sekitar 52 kb data, pengurangan sebesar 95% dalam transfer data, yang berarti beban yang jauh lebih ringan pada server dan perangkat pengguna.

AI Agents di LibreChat menyediakan cara yang hebat untuk membuat asisten khusus tanpa pengetahuan pemrograman, sekaligus mempertahankan fleksibilitas untuk bekerja dengan model dan penyedia AI pilihan Anda.
