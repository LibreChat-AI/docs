Pencarian web memberikan model sebuah alat `web_search`. Ketika sebuah pertanyaan membutuhkan informasi terkini, model menulis kueri, LibreChat mengambil hasil pencarian, membaca halaman-halaman teratas, lalu jawabannya dikembalikan beserta sumber yang digunakan.

## Aktifkan di dalam chat [#turn-it-on-in-a-chat]

Klik **+** di [message composer](/docs/features/composer) untuk membuka palet, lalu pilih **Web Search** di bagian **Tools**. Fitur ini akan muncul sebagai chip di composer saat aktif; hapus chip tersebut, atau pilih kembali di palet, untuk menonaktifkannya. Anda dapat menyematkan (pin) fitur ini agar chip tetap berada di composer meskipun sedang tidak aktif.

Dengan pencarian web aktif, model tetap memutuskan sendiri apakah sebuah pesan memerlukan pencarian. Menanyakan "apa yang berubah di rilis Node.js terbaru?" biasanya akan memicu pencarian, sedangkan meminta model menulis ulang sebuah paragraf tidak akan memicunya.

Untuk agent, pencarian web adalah kapabilitas yang Anda aktifkan di agent builder. Siapa pun yang mengobrol dengan agent tersebut otomatis mendapatkan alat ini tanpa perlu mengaktifkan apa pun.

## Apa yang Anda lihat dalam jawaban [#what-you-see-in-the-answer]

Selama alat berjalan, pesan menampilkan progresnya ("Searching the web", lalu "Reading results"). Setelah selesai, pesan akan menciutkan diri menjadi **Searched the web**; perluas untuk melihat halaman yang ditemukan, atau gunakan tombol **Search details** di sebelahnya untuk melihat kueri yang dikirim oleh model.

Kutipan sebaris dalam teks mengarah kembali ke halaman-halaman tersebut, sehingga Anda dapat memeriksa suatu klaim dengan halaman asalnya. Ketika beberapa agen menjawab secara berdampingan, baris **Sources** di atas balasan juga mengumpulkan hasilnya, dengan **All**, serta tab **News** dan **Images** jika pencarian mengembalikan hasil tersebut.

## Bagaimana pencarian berjalan [#how-a-search-runs]

Setiap pencarian melewati hingga tiga layanan:

- Penyedia pencarian mengembalikan daftar hasil: Serper, SearXNG, Tavily, atau Keenable.
- Sebuah scraper mengambil halaman-halaman di balik hasil pencarian tersebut dan mengekstrak teksnya: Firecrawl, Serper Scrape, Tavily Extract, atau Keenable Fetch.
- Reranker (Jina atau Cohere) memilih bagian teks yang paling relevan dengan kueri. Reranking dapat diatur ke **None** untuk melewati langkah ini.

Hanya bagian yang diekstrak yang dikirim ke model, bukan seluruh halaman. Halaman yang habis waktu (timeout) atau memblokir pengambilan konten akan dilewati, sehingga jawaban mungkin mengutip lebih sedikit sumber dibandingkan jumlah yang dikembalikan oleh pencarian.

Safe search diatur ke moderat secara default. Admin Anda dapat menaikkan atau menurunkan tingkat untuk semua pengguna; Tavily adalah pengecualian dan hanya memfilter ketika admin mengaktifkan opsi safe search miliknya sendiri.

## Menambahkan API key Anda sendiri [#adding-your-own-api-keys]

Jika admin Anda belum menyediakan kunci untuk setiap layanan, mengaktifkan **Web Search** akan membuka dialog yang meminta kunci tersebut. Dialog ini memiliki bagian untuk setiap layanan yang tidak diatur oleh admin untuk pengguna, dari **Search Provider**, **Scraper**, dan **Reranker**. Pilih layanan di setiap bagian, isi kuncinya (setiap kolom memiliki tautan ke tempat Anda mendapatkannya), lalu klik **Save**. SearXNG meminta URL instance Anda, dan kuncinya bersifat opsional. Keenable dapat digunakan tanpa kunci; menambahkan kunci hanya akan menaikkan batas rate limit-nya.

Kunci disimpan bersama akun Anda dan hanya digunakan untuk pencarian Anda. Untuk mengubah penyedia atau mengganti kunci nanti, buka palet lalu klik **Configure** (ikon roda gigi) pada baris **Web Search**. Setelah Anda menyimpan kunci, **Revoke** pada dialog yang sama akan menghapusnya. Ketika admin telah mengatur setiap kunci di server, tidak ada dialog dan tidak ada ikon roda gigi.

URL yang Anda masukkan tidak pernah dipasangkan dengan kunci yang diatur oleh admin di server. Jika admin telah mengatur kunci Firecrawl atau SearXNG dan Anda memasukkan URL Anda sendiri untuk layanan tersebut, masukkan juga kunci Anda sendiri. Jika tidak, Firecrawl akan mengabaikan URL Anda dan menggunakan endpoint default-nya, dan SearXNG tidak akan berjalan. Instans SearXNG tanpa kunci tetap dapat berfungsi: jika tidak ada kunci yang terlibat, URL Anda saja sudah cukup.

## Opsi Web Search tidak terlihat [#web-search-option-is-not-visible]

Tidak ada tombol pencarian web terpisah; opsi tersebut hanya muncul di bagian **Tools** pada palet. Opsi ini tidak tersedia ketika:

- Anda sedang mengobrol dengan agen, atau di endpoint Assistants. Agen membawa alatnya sendiri, sehingga pencarian web diaktifkan di Agent Builder sebagai gantinya.
- Spesifikasi model yang dipilih menyembunyikan baris alat.
- Peran Anda tidak memiliki izin Web Search. Hal itu juga memblokir fitur pencarian bawaan yang ditawarkan oleh beberapa penyedia.
- Admin Anda telah menghapus `web_search` dari kapabilitas agent.

## Pengaturan [#setup]

Pencarian web tersedia secara default untuk agen dan obrolan, tetapi memerlukan penyedia pencarian dan scraper sebelum dapat mengembalikan hasil apa pun. Admin dapat mengatur kunci di server atau membiarkannya agar pengguna memasukkannya sendiri. Penyedia yang di-self-host pada alamat privat akan diblokir hingga admin mencantumkannya di [`allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers). Lihat [konfigurasi Pencarian Web](/docs/configuration/librechat_yaml/object_structure/web_search) untuk penyedia, kunci, dan opsi, serta [Menyiapkan SearXNG](/docs/configuration/librechat_yaml/object_structure/web_search#setting-up-searxng) untuk meng-host sendiri penyedia pencarian.
