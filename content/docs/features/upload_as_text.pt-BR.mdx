# Fazer upload de arquivos como texto [#upload-files-as-text]

Já quis entregar um PDF, um arquivo de código ou uma planilha para a IA e apenas dizer _"leia isto"_? O carregador unificado do LibreChat encaminha o arquivo para o provedor ou extrai seu texto automaticamente com base no tipo e no endpoint selecionado.

Você anexa um arquivo, o LibreChat extrai o texto dele e o conteúdo completo é colado diretamente na sua conversa. A IA pode então ler cada palavra dele — sem plugins, sem bancos de dados vetoriais, sem serviços extras para configurar. Funciona nativamente.

<Callout type="info" title="Nenhuma configuração necessária">
  Upload as Text funciona imediatamente em qualquer instância do LibreChat. Ele utiliza análise de texto integrada — você não precisa de OCR, um pipeline de RAG ou qualquer serviço externo para começar.
</Callout>

---

## Como usar [#how-to-use-it]

<Steps>
  <Step>
    ### Abra a paleta [#open-the-palette]

    Clique em **+** no [compositor de mensagens](/docs/features/composer#add-files). Você também pode arrastar o arquivo para o compositor.
  </Step>
  <Step>
    ### Escolha uma fonte [#choose-a-source]

    Na seção **Attach**, selecione **From Local Computer** ou **From SharePoint** quando estiver configurado. O uploader padrão não solicita que você escolha um modelo ou destino de ferramenta.

    Se o seu administrador habilitou [`legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), escolha o destino você mesmo: selecione **More upload options**, e então **Upload as Text**.
  </Step>
  <Step>
    ### Escolha seu arquivo [#choose-your-file]

    Selecione o arquivo. O LibreChat escolhe a entrega pelo provedor nativo, extração de texto ou armazenamento apenas para ferramentas, com base no tipo de arquivo e nos recursos do endpoint.
  </Step>
  <Step>
    ### Faça sua pergunta [#ask-your-question]

    Digite seu prompt como de costume. As ferramentas File Search e Code selecionadas recebem o arquivo apenas quando precisam dele.
  </Step>
</Steps>

Ao selecionar vários arquivos, o LibreChat ignora duplicatas individuais e arquivos que excedem o limite de tamanho por arquivo, nomeia os arquivos ignorados em um aviso e continua o upload dos arquivos válidos. Os limites de contagem de arquivos e de tamanho total do lote ainda se aplicam aos arquivos restantes; se o lote resultante exceder qualquer um dos limites, o lote será rejeitado por completo. O comportamento para arquivos únicos permanece inalterado.

<Callout type="warn" title="Não vê a opção?">
  Com `legacyFileUploadUX` ativado, se **Upload as Text** não aparecer em **More upload options**, a capacidade `context` pode ter sido desativada pelo seu administrador. Ela está ativada por padrão, mas se a lista de capacidades foi personalizada, `context` precisa ser incluído explicitamente. Veja a [seção de configuração](#the-context-capability) abaixo.
</Callout>

## Colar texto longo como um arquivo [#paste-long-text-as-a-file]

No compositor de mensagens normal, o LibreChat pode transformar uma colagem maior que 2.500 caracteres em um anexo de Upload como Texto. Isso mantém uma colagem grande fora da entrada, enquanto ainda fornece seu conteúdo ao modelo por meio do contexto da conversa. O primeiro anexo é nomeado `pasted-text.txt`; anexos de texto colado adicionais recebem nomes numerados.

A configuração local do navegador **Colar texto longo como arquivo** está habilitada por padrão em **Configurações > Chat > Envio**. Colagens mais curtas e textos colados enquanto se responde a um formulário **Perguntar ao Usuário** de um Agente permanecem inline. Se os uploads de contexto estiverem indisponíveis, o texto também permanece inline. Se um upload de anexo falhar, o LibreChat restaura o texto para o compositor quando puder fazê-lo sem sobrescrever um rascunho mais recente.

Anexos de texto colado seguem as mesmas regras de tamanho de arquivo, tokens e [`fileTokenLimit`](#token-limits-and-truncation) que outros arquivos de "Upload as Text".

## O que acontece nos bastidores [#what-happens-under-the-hood]

Quando um upload é roteado para texto, o LibreChat não despeja bytes brutos no prompt. Ele passa por um pipeline de processamento para extrair texto limpo e legível:

1. **Detecção de tipo MIME** — O LibreChat verifica que tipo de arquivo você enviou (PDF, imagem, áudio, código-fonte, etc.) inspecionando seu tipo MIME.
2. **Seleção de método** — Com base no tipo de arquivo e nos serviços disponíveis, ele escolhe o melhor método de extração usando esta prioridade:

<Tabs items={["Ordem de prioridade", "Exemplos de decisão"]}>
  <Tabs.Tab>
    | Prioridade | Método | Quando é usado |
    |----------|--------|---------------|
    | 1ª | **OCR** | O arquivo é uma imagem ou documento digitalizado, _e_ o OCR está configurado |
    | 2ª | **STT** (Speech-to-Text) | O arquivo é áudio, _e_ o STT está configurado |
    | 3ª | **Análise de texto** | O arquivo corresponde a um tipo MIME de texto conhecido |
    | 4ª | **Fallback** | Nenhum dos anteriores correspondeu — tenta a análise de texto de qualquer maneira |
  </Tabs.Tab>
  <Tabs.Tab>
    **Um `.pdf` em uma instância com OCR configurado:**
    → O OCR é ativado. Ótimo para documentos digitalizados e layouts complexos.

    **Um `.pdf` em uma instância padrão (sem OCR):**
    → O processamento de texto lida com isso. Funciona bem para PDFs criados digitalmente.

    **Um arquivo Python `.py`:**
    → Direto para a análise de texto. O código-fonte já é texto — nenhuma conversão é necessária.

    **Um `.mp3` em uma instância com STT configurado:**
    → Speech-to-Text transcreve-o em texto para a conversa.

    **Uma captura de tela `.png` sem OCR configurado:**
    → Recorre à análise de texto (resultados limitados — considere configurar o OCR para imagens).
  </Tabs.Tab>
</Tabs>

3. **Truncamento de tokens** — O texto extraído é cortado de acordo com o `fileTokenLimit` (padrão: 100.000 tokens) para que não exceda a janela de contexto do modelo.
4. **Prompt injection** — O texto é incluído no contexto da conversa, exatamente ao lado da sua mensagem.

Ao visualizar ou baixar um anexo como texto (Upload as Text), o LibreChat fornece o texto extraído armazenado com o registro do arquivo. Os downloads usam um nome de arquivo `.txt`, mesmo quando OCR ou outro analisador produziram o texto armazenado e não há um arquivo original de suporte para transmitir.

## Quais arquivos são suportados [#which-files-are-supported]

<Tabs items={["Texto e código", "Documentos", "Imagens", "Áudio"]}>
  <Tabs.Tab>
    Estes são analisados diretamente — eles já são texto, portanto, nenhuma conversão é necessária.

    - Texto simples (`.txt`), Markdown (`.md`), CSV, JSON, XML, HTML, CSS
    - Linguagens de programação — Python, JavaScript, TypeScript, Java, C#, PHP, Ruby, Go, Rust, Kotlin, Swift, Scala, Perl, Lua
    - Arquivos de configuração — YAML, TOML, INI
    - Scripts de shell, arquivos SQL
  </Tabs.Tab>
  <Tabs.Tab>
    A análise de texto lida com isso nativamente. Se o OCR estiver configurado, ele assume o controle para obter melhor precisão em layouts complexos.

    - **PDF** — digital e digitalizado (PDFs digitalizados se beneficiam de OCR)
    - **Word** — `.docx`, `.doc`
    - **PowerPoint** — `.pptx`, `.potx`, `.ppt`
    - **Excel** — `.xlsx`, `.xls`
    - Livros **EPUB**
  </Tabs.Tab>
  <Tabs.Tab>
    Imagens **exigem OCR** para produzir texto útil. Sem isso, os resultados serão insatisfatórios.

    - JPEG, PNG, GIF, WebP
    - HEIC, HEIF (formatos da Apple)
    - Capturas de tela, fotos de documentos, páginas digitalizadas
  </Tabs.Tab>
  <Tabs.Tab>
    Arquivos de áudio **exigem que o STT** esteja configurado. Não há fallback — o áudio não pode ser "analisado como texto".

    - MP3, WAV, OGG, FLAC
    - M4A, WebM
    - Gravações de voz, clipes de podcast
  </Tabs.Tab>
</Tabs>

O LibreChat normaliza variantes MIME de shell-script relatadas pelo Chrome no Linux (`application/x-shellscript`) e pelo libmagic (`text/x-shellscript`) para o `application/x-sh` canônico antes de verificar a lista de permissões do endpoint. Regras personalizadas de [`supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) ainda devem permitir `application/x-sh`.

## Uploads unificados e provisionamento de ferramentas [#unified-uploads-and-tool-provisioning]

Por padrão, uma ação de anexo substitui o antigo seletor de destino. O LibreChat decide como o arquivo chega ao modelo, enquanto as ferramentas são provisionadas de forma preguiçosa (lazily):

<Cards>
  <Card title="Contexto do modelo" href="#what-happens-under-the-hood">
    Os arquivos suportados chegam ao modelo por meio de entrega nativa do provedor ou texto extraído, de acordo com o tipo MIME, a capacidade do endpoint e a configuração de implantação.
  </Card>
  <Card title="Upload para Pesquisa de Arquivos (RAG)" href="/docs/features/rag_api">
    Quando File Search é selecionado, o LibreChat indexa anexos elegíveis apenas quando a execução precisa da ferramenta.
  </Card>
  <Card title="Upload Padrão" href="/docs/features/agents">
    Quando Code é selecionado, o LibreChat disponibiliza anexos elegíveis para o ambiente Code apenas quando a execução precisa deles.
  </Card>
</Cards>

Operadores podem restaurar o seletor de destino anterior com [`fileConfig.legacyFileUploadUX`](/docs/configuration/librechat_yaml/object_structure/file_config#legacyfileuploadux), ou controlar o roteamento automático com [`defaultLLMDeliveryPath`](/docs/configuration/librechat_yaml/object_structure/file_config#defaultllmdeliverypath).

**Roteamento típico:**

| Situação | Melhor opção |
|-----------|-------------|
| _"Leia este contrato de 5 páginas e faça um resumo"_ | Entrega nativa de PDF ou texto extraído |
| _"Tenho 50 PDFs, encontre o que menciona preços"_ | Provisionamento de Lazy File Search |
| _"O que há nesta captura de tela?"_ | Entrega nativa de imagem |
| _"Execute este script Python"_ | Provisionamento de Lazy Code |
| _"Revise este arquivo de código em busca de bugs"_ | Texto extraído |

## A capacidade `context` [#the-context-capability]

Por baixo dos panos, o Upload as Text é alimentado pela **capacidade `context`**. É isso que controla se o recurso aparece na sua interface de chat.

<Callout type="info">
  A funcionalidade `context` está **habilitada por padrão**. Você só precisa alterar isso se o seu administrador tiver personalizado a lista de funcionalidades e a tiver removido acidentalmente.
</Callout>

```yaml title="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - "context"  # This is what enables "Upload as Text"
```

A mesma funcionalidade de `context` também impulsiona o **Agent File Context** (upload de arquivos através do Agent Builder para incorporar texto nas instruções de sistema de um agente). A diferença é _onde_ o texto termina:

| | Upload as Text | Agent File Context |
|---|---|---|
| **Onde** | Entrada de chat (qualquer conversa) | Painel do Agent Builder |
| **Escopo** | Apenas a conversa atual | Persiste nas instruções do agente |
| **Caso de uso** | Perguntas pontuais sobre documentos | Criação de agentes especializados com conhecimento integrado |

## Limites de tokens e truncamento [#token-limits-and-truncation]

Quando um arquivo é longo demais para caber na janela de contexto do modelo, o LibreChat trunca o texto extraído para permanecer dentro dos limites. Isso acontece automaticamente — você não precisa se preocupar com isso, mas é bom saber como funciona.

```yaml title="librechat.yaml"
fileConfig:
  fileTokenLimit: 100000  # Default: 100,000 tokens
```

<Callout type="warn" title="Truncamento significa perda de conteúdo">
  Se o seu arquivo exceder o limite, o texto será cortado no final. Se você estiver recebendo respostas incompletas, este pode ser o motivo. Você pode aumentar o `fileTokenLimit`, mas tenha em mente que valores maiores usam mais tokens por mensagem — o que aumenta o custo e pode atingir o limite de contexto do próprio modelo.
</Callout>

**Regras gerais:**
- 100k tokens ≈ um livro de 300 páginas (o suficiente para a maioria dos casos de uso)
- Se você estiver trabalhando com arquivos muito grandes, considere o [File Search (RAG)](/docs/features/rag_api) — ele recupera apenas as seções relevantes em vez de colocar tudo no contexto.

## Opcional: impulsionando a extração com OCR [#optional-boosting-extraction-with-ocr]

A análise de texto funciona bem para documentos criados digitalmente (PDFs salvos a partir do Word, arquivos de código, texto simples). Mas, se você estiver enviando **documentos digitalizados, fotos de páginas ou imagens com texto**, o analisador integrado não obterá ótimos resultados.

É aí que o OCR entra em ação. Quando configurado, o LibreChat usa automaticamente o OCR para tipos de arquivo que se beneficiam dele — você não precisa fazer nada diferente como usuário.

<Accordions>
  <Accordion title="Como pedir ao seu administrador para configurar o OCR">
    Encaminhe-os para a [documentação de configuração de OCR](/docs/features/ocr). A versão resumida:

    ```yaml title="librechat.yaml"
    ocr:
      strategy: "mistral_ocr"
      apiKey: "${OCR_API_KEY}"
      baseURL: "https://api.mistral.ai/v1"
      mistralModel: "mistral-ocr-latest"
    ```

    Uma vez configurado, o OCR lida automaticamente com imagens e PDFs digitalizados — sem necessidade de alterações por parte do usuário.
  </Accordion>
  <Accordion title="Como solicitar ao seu administrador a configuração de STT (para arquivos de áudio)">
    Para transcrever uploads de áudio, o administrador precisa configurar um serviço de Speech-to-Text. Veja a [referência de configuração de STT](/docs/configuration/librechat_yaml/object_structure/file_config#stt).
  </Accordion>
</Accordions>

## Referência de configuração de manipulação de arquivos [#file-handling-configuration-reference]

Esta seção é para administradores que desejam controlar quais tipos de arquivo são processados por qual método. Os padrões funcionam bem — você só precisa alterar isso se quiser ajustar o comportamento.

<Accordions>
  <Accordion title="Exemplo completo de fileConfig">
    ```yaml title="librechat.yaml"
    fileConfig:
      # Max tokens extracted from a single file before truncation
      fileTokenLimit: 100000

      # Files matching these MIME patterns use OCR (if configured)
      ocr:
        supportedMimeTypes:
          - "^image/(jpeg|gif|png|webp|heic|heif)$"
          - "^application/pdf$"
          - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.presentation|spreadsheetml\\.sheet)$"
          - "^application/vnd\\.ms-(word|powerpoint|excel)$"
          - "^application/epub\\+zip$"

      # Files matching these MIME patterns use text parsing
      text:
        supportedMimeTypes:
          - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"

      # Files matching these MIME patterns use STT (if configured)
      stt:
        supportedMimeTypes:
          - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
    ```

    **Lembrete de prioridade:** OCR > STT > análise de texto > fallback.

    Para a referência completa, veja [File Config Object Structure](/docs/configuration/librechat_yaml/object_structure/file_config).
  </Accordion>
</Accordions>

## Solução de problemas [#troubleshooting]

<Accordions>
  <Accordion title="Opção Upload as Text não aparecendo">
    A capacidade `context` provavelmente foi removida da sua configuração. Peça ao seu administrador para adicioná-la novamente:

    ```yaml
    endpoints:
      agents:
        capabilities:
          - "context"
    ```
  </Accordion>
  <Accordion title="O conteúdo do arquivo parece incorreto ou está praticamente vazio">
    Algumas coisas para verificar:
    - **PDFs / imagens digitalizados** — Estes precisam de OCR para extrair o texto corretamente. Sem isso, o parser pode retornar dados corrompidos ou nada. Peça ao seu administrador para [configurar o OCR](/docs/features/ocr).
    - **Arquivos de áudio** — Estes precisam de STT. Não há fallback de texto para áudio.
    - **Arquivos corrompidos** — Tente abrir o arquivo localmente para garantir que ele não esteja danificado.
    - **Formato não suportado** — Se o tipo MIME não corresponder a nenhum padrão configurado, o LibreChat tenta um fallback de análise de texto, o que pode não funcionar para formatos binários.
  </Accordion>
  <Accordion title="O upload foi rejeitado por ser um tipo de arquivo não suportado">
    O LibreChat retorna o tipo MIME rejeitado no erro de upload. Verifique os padrões de [`fileConfig.endpoints.<endpoint>.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#supportedmimetypes-3) do endpoint ativo e permita o tipo canônico que você pretende aceitar. Para scripts de shell, use `application/x-sh`; o LibreChat normaliza as variantes comuns `application/x-shellscript` e `text/x-shellscript` antes da correspondência.
  </Accordion>
  <Accordion title="A IA parece estar ignorando parte do meu arquivo">
    Seu arquivo provavelmente excedeu o `fileTokenLimit`. O texto foi truncado.

    **Opções:**
    - Peça ao seu administrador para aumentar o `fileTokenLimit` no `librechat.yaml`
    - Use [File Search (RAG)](/docs/features/rag_api) em vez disso, que recupera partes relevantes em vez de carregar o arquivo inteiro
    - Divida o arquivo em partes menores e faça o upload delas separadamente
  </Accordion>
  <Accordion title="Imagens são enviadas, mas a IA não consegue ler o texto nelas">
    Sem OCR, as imagens são processadas através de análise de texto, que não consegue realmente "ver" o texto em uma imagem. Você precisa do OCR configurado para que isso funcione. Veja [OCR para Documentos](/docs/features/ocr).

    Alternativamente, use um **vision model** com upload de arquivo padrão — o próprio modelo pode ler texto em imagens.
  </Accordion>
</Accordions>
