De **RAG (Retrieval-Augmented Generation) API** is een afzonderlijke service die de bestanden indexeert die je in LibreChat uploadt en de passages teruggeeft die het meest relevant zijn voor een vraag, zodat het model kan antwoorden op basis van je documenten in plaats van uitsluitend op basis van zijn trainingsdata.

Het is een Python FastAPI-app gebouwd op LangChain, en slaat embeddings op in PostgreSQL met de pgvector-extensie.

**Om dit in te stellen, zie [RAG API-configuratie](/docs/configuration/rag_api).**

In LibreChat maakt RAG de [Agents](/docs/features/agents#file-search)-functionaliteit **File Search** (`file_search`) mogelijk. Bestanden die aan de File Search van een agent zijn gekoppeld, of aan een run die File Search selecteert, worden door de RAG API geïndexeerd en op verzoek opgehaald. Andere chat-endpoints gebruiken geen RAG-indexering of -ophaling, al kunnen ze de RAG API wel gebruiken om tekst te extraheren, zoals hieronder beschreven.

De RAG API biedt ook een `/text`-route die LibreChat kan gebruiken om tekst uit uploads te extraheren; zie [Upload as Text](/docs/features/upload_as_text#what-happens-under-the-hood) voor wanneer dit van toepassing is.

## Hoe het werkt [#how-it-works]

1. **Indexering.** Wanneer een bestand doorzoekbaar moet zijn (bij het uploaden naar de Bestandszoekfunctie van een agent, of wanneer een chatrun voor het eerst de Bestandszoekfunctie gebruikt op een bijlage), stuurt LibreChat het naar de RAG API. Die splitst de tekst in overlappende fragmenten (`CHUNK_SIZE` en `CHUNK_OVERLAP`), zet elk fragment om in een embedding met de geconfigureerde provider, en slaat de vectoren op in pgvector.
2. **Retrieval.** Wanneer het model File Search aanroept, schrijft het een zoekopdracht. LibreChat vraagt de RAG API om de 5 dichtstbijzijnde fragmenten in elk bijgevoegd bestand op te halen en bewaart vervolgens de 10 dichtstbijzijnde fragmenten in totaal.
3. **Beantwoorden.** Die fragmenten worden met hun bestandsnaam en een relevantiescore teruggestuurd naar het model, dat het antwoord op basis daarvan geeft. Wanneer [bestandsverwijzingen](/docs/configuration/librechat_yaml/object_structure/interface#filecitations) zijn ingeschakeld, kan het antwoord verwijzen naar de bestanden die zijn gebruikt.

Het verwijderen van een bestand in LibreChat verwijdert ook de vectoren ervan uit de RAG API.

Retrieval vindt alleen passages die semantisch dicht bij de zoekopdracht liggen, dus het werkt het best voor het opzoeken van specifieke feiten in grote documenten. Voor vragen waarvoor in één keer een heel document nodig is, zoals het samenvatten ervan, geeft [Upload as Text](/docs/features/upload_as_text) meestal betere resultaten.

## Wat is RAG? [#what-is-rag]

Retrieval-Augmented Generation verankert een taalmodel in een externe kennisbron. In plaats van uitsluitend te vertrouwen op wat het model tijdens de training heeft geleerd, haalt de applicatie eerst relevante fragmenten uit die bron op en voegt deze toe aan de prompt. Het model genereert vervolgens zijn antwoord op basis van deze fragmenten. Omdat de kennis buiten het model wordt opgeslagen, kun je documenten toevoegen of bijwerken zonder iets opnieuw te trainen.
