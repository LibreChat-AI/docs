# 메시지 작업 [#message-actions]

메시지 작업은 사용 가능한 경우 대화 턴 아래에 나타납니다. 사용자 턴은 오른쪽 정렬된 말풍선을 사용하며, 어시스턴트 턴은 전체 너비 응답 레이아웃을 유지합니다. 응답이 스트리밍되는 동안 적용할 수 없는 작업은 응답이 완료될 때까지 숨겨집니다. 포인터 장치에서는 메시지 메타데이터와 컨트롤이 클릭할 필요 없이 마우스를 올리거나 키보드 포커스를 맞추면 나타납니다.

## 편집 및 재실행 [#edit-and-rerun]

**편집**을 선택하여 사용자 메시지나 편집 가능한 어시스턴트 응답을 변경하세요. 편집기에서는 변경 사항을 적용하는 두 가지 방법을 제공합니다:

- **Save**는 다른 응답을 생성하지 않고 기존 메시지를 업데이트합니다.
- **Update & rerun**은 편집된 메시지로부터 새로운 형제 응답을 생성합니다.

구조화된 어시스턴트 응답은 모든 편집 가능한 텍스트 및 추론 부분에 대해 하나의 편집기를 사용합니다. 도구 호출, 오류, 아티팩트 및 도구 호출에 첨부된 텍스트는 계속 표시되지만 읽기 전용으로 유지됩니다. 비어 있는 편집 부분은 저장할 수 없습니다.

둘 이상의 어시스턴트 파트가 변경된 경우, 다시 실행하지 않고 편집 내용을 저장하세요. 한 번의 다시 실행으로 하나의 편집된 어시스턴트 파트만 반영할 수 있습니다. 다중 파트 저장은 순서대로 적용되며, 오류 발생 전에 저장된 파트는 대화에 그대로 반영됩니다.

편집된 사용자 메시지를 다시 실행하면 해당 메시지의 파일, 선택된 수동 Skills, 인용된 컨텍스트가 유지됩니다. 편집된 어시스턴트 응답을 다시 실행하면 선택된 수동 Skills 및 인용문과 함께 상위 사용자 턴이 다시 재생됩니다.

편집하는 동안 `Ctrl`/`Cmd` + `S`를 눌러 저장하거나, `Ctrl`/`Cmd` + `Enter`를 눌러 업데이트 및 재실행하거나, `Escape`를 눌러 취소할 수 있습니다.

## 복사 및 포크 (Copy and Fork) [#copy-and-fork]

**Copy**는 메시지 텍스트를 클립보드에 복사하고 지원되는 인용문을 읽기 쉬운 참조 형식으로 변환합니다. 구조화된 어시스턴트 응답의 경우, LibreChat은 사용자가 볼 수 있는 텍스트 부분만 순서대로 결합합니다. 이때 추론, 도구 호출, 오류, 아티팩트 및 도구 호출에 첨부된 텍스트는 생략됩니다. 이 작업은 응답이 스트리밍 중이거나 복사할 텍스트가 없는 경우에는 사용할 수 없으므로, 클립보드 내용이 부분적이거나 빈 값으로 대체되지 않습니다.

설정에서 **메시지를 서식 있는 텍스트로 복사(Copy messages as rich text)**를 활성화하면 일반 Markdown과 렌더링된 HTML을 모두 클립보드에 저장할 수 있습니다. 이렇게 하면 Teams, Outlook, Word와 같은 앱에 붙여넣을 때 제목, 목록, 표 및 코드 서식이 유지됩니다.

**Fork**을 사용하여 선택한 메시지에서 대화를 분기할 수 있습니다. 자세한 내용은 [Forking Conversations](/docs/features/fork)를 참조하세요. 편집, 재실행, 이어가기, 피드백, 읽어주기 및 포크(fork) 작업의 사용 가능 여부는 endpoint와 메시지 상태에 따라 결정됩니다.

## 인용 발췌 [#quote-excerpts]

메시지에서 텍스트를 선택하고 **Add to chat**을 선택하여 인용된 컨텍스트로 준비하세요. 한 메시지에 최대 10개의 발췌문을 첨부할 수 있으며, 발췌문당 최대 1,500자까지 가능합니다. LibreChat은 메시지 텍스트 및 모든 파일과 함께 발췌문을 Markdown 블록 인용구로 전송합니다.

활성 에이전트 실행 중에 인용된 발췌문은 **Steer**, **Queue**, **Interrupt** 메시지 뒤에 표시되며, 재연결 후에도 대기 중인 작업과 계속 연결된 상태로 유지됩니다. 최신 서버에서는 일반 대기열 후속 메시지도 앱 재시작이나 레플리카 전환 후에 인용된 발췌문을 그대로 유지합니다. 롤링 배포 중 이전 버전의 레플리카가 인용 컨텍스트를 처리할 수 없는 경우, LibreChat은 이를 조용히 버리지 않고 작성기(composer)로 되돌려 줍니다. 수동으로 선택한 Skills는 실행 중간의 steer 메시지에 추가되지 않고, 다음 전체 턴을 위해 대기 상태로 유지됩니다. 자세한 내용은 [Steering and Queued Messages](/docs/features/agents#steering-and-queued-messages)를 참고하세요.

## 코드 블록 작업 [#code-block-actions]

코드 블록은 내용을 복사하거나, [Code Interpreter](/docs/features/code_interpreter)를 통해 지원되는 코드를 실행하거나, 블록을 로컬 파일로 다운로드하는 기능을 제공합니다. 다운로드 파일명은 가능할 경우 `code.py`나 `code.tsx`와 같이 지정된 언어를 사용하며, 알 수 없는 안전한 언어 힌트는 해당 확장자로 지정되고, 힌트가 없거나 유효하지 않은 경우에는 `code.txt`로 대체됩니다. 오류 블록에는 다운로드 작업이 표시되지 않습니다.

## 긴 붙여넣기 텍스트 [#long-pasted-text]

브라우저 로컬 **Paste long text as a file** 설정이 활성화되어 있고 [Upload as Text context uploads](/docs/features/upload_as_text#paste-long-text-as-a-file)를 사용할 수 있는 경우, 2,500자보다 긴 클립보드 붙여넣기는 작성 창을 채우는 대신 `pasted-text.txt` 첨부 파일이 됩니다. 그렇지 않은 경우, 붙여넣기는 인라인으로 유지됩니다. 전송하기 전에 첨부 파일을 선택하여 더 큰 대화 상자에서 텍스트를 편집하거나 **Move back into message**를 선택하여 작성 창으로 되돌릴 수 있습니다.

LibreChat은 일반적인 초안 복원 과정 전반에 걸쳐 붙여넣은 텍스트 초안과 메시지 출처를 보존합니다. 편집 시에는 대체 항목이 준비될 때까지 원래 첨부 파일을 유지하며, 명시적으로 **New Chat**을 시작하면 나머지 초안과 함께 붙여넣은 텍스트가 지워집니다.

## 첨부 파일 전용 턴 (Attachment-Only Turns) [#attachment-only-turns]

자리 표시자 텍스트를 입력하지 않고도 하나 이상의 첨부 파일을 보낼 수 있습니다. 메시지를 수정하고 다시 실행할 때 첨부 파일만 포함된 턴(turn)도 유효하게 유지되며, LibreChat은 제목 컨텍스트가 필요할 때 첨부 파일의 파일명을 사용합니다.

파일이 없는 빈 초안은 여전히 거부됩니다. 또한 에이전트의 일시 중지된 **Ask User** 양식에 응답할 때 파일은 텍스트를 대신할 수 없습니다. 해당 응답 경로는 메시지 첨부 파일이 아닌 답변 값을 허용하기 때문입니다.
