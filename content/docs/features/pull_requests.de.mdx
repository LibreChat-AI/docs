Wenn ein Agent in einem angehängten Code-Workspace an einem Repository arbeitet, findet LibreChat den Pull Request für den Branch, auf dem sich der Workspace befindet, und zeigt ihn neben dem Chat an. Du siehst, ob er bereit zum Mergen ist, ob die Checks bestehen, und kannst direkt dorthin springen, ohne die Unterhaltung zu verlassen. Es funktioniert mit GitHub, GitLab (dort als Merge Request bezeichnet) und Bitbucket Cloud, jeweils ein Anbieter pro Deployment.

Nur Chats, die Code in einem angehängten Workspace ausführen, können einen Pull Request haben. Ein einfacher Chat oder ein Workspace, der noch keinen Branch gemeldet hat, zeigt nichts an.

## In der Chat-Kopfzeile [#in-the-chat-header]

Auf einem breiten Bildschirm zeigt ein Chip auf der linken Seite der Kopfzeile das Pull-Request-Symbol, einen kleinen CI-Punkt an seiner Ecke und den Titel des Pull Requests. Durch Hover oder Fokussieren des Chips öffnet sich eine Karte mit den Details. Die Karte bleibt geöffnet, solange sich Ihr Zeiger oder der Tastaturfokus innerhalb der Karte befindet.

Auf einem kleinen Bildschirm gibt es keinen Chip. Öffne das Dreipunkt-Menü in der Kopfzeile und wähle den Eintrag `PR #number` (`MR !number` auf GitLab), um dieselbe Karte in einem Dialog anzuzeigen.

Der Header hält sich selbst aktuell: Er prüft etwa alle 20 Sekunden erneut, solange Prüfungen laufen oder der Anbieter noch ermittelt, ob der Branch zusammengeführt werden kann, und ansonsten etwa alle 60 Sekunden. Sobald der Pull Request zusammengeführt oder geschlossen wurde und nichts mehr läuft, hört er auf.

## In der Seitenleiste [#in-the-sidebar]

Unterhaltungen, die einen Pull Request haben, erhalten am Ende ihrer Zeile dasselbe Symbol und denselben CI-Punkt. Die Zeile behält den eigenen Titel der Unterhaltung. Wenn Sie die Zeile überfahren oder die Markierung fokussieren bzw. anklicken, öffnet sich die Karte daneben; ein Klick auf die Markierung öffnet die Unterhaltung nicht.

Die Seitenleiste fragt nicht regelmäßig ab. Eine Zeile ist so aktuell wie der letzte Zeitpunkt, zu dem die Liste geladen wurde, und sie wird aktualisiert, wenn Sie zum Fenster zurückkehren und ihre Daten älter als eine Minute sind. Schlägt eine Aktualisierung für einen bereits gefundenen Pull Request fehl, bleibt die Markierung erhalten, und die Karte zeigt „Pull Request konnte nicht aktualisiert werden“ mit einer **Wiederholen**-Schaltfläche an. Eine Unterhaltung, deren Pull Request noch nie gefunden wurde, zeigt keine Markierung an, selbst wenn die Suche fehlgeschlagen ist.

## Die Karte lesen [#reading-the-card]

Die Karte zeigt `PR #number` (`MR !number` auf GitLab), die hinzugefügten Zeilen in Grün und die entfernten in Rot, einen Link **Open in GitHub**, **Open in GitLab** oder **Open in Bitbucket**, den Titel sowie zwei Badges:

- Status: Open, Conflicts, Draft, Merged oder Closed. Conflicts ersetzt Open, wenn der Branch nicht sauber zusammengeführt werden kann.
- Checks: Passing, Failing, Running oder None. Auf GitLab ist dies die Head-Pipeline, und nur dann, wenn sie für den aktuellen Commit ausgeführt wurde. Auf Bitbucket sind es die Commit-Status.

Die Symbolfarbe und der CI-Punkt fassen dieselbe Information auf einen Blick zusammen:

| Pull Request | Symbol | CI-Punkt |
| ------------------------------------ | ------- | --------------- |
| Offen, kann gemergt werden | Grün | Aus den Prüfungen |
| Offen, Mergebarkeit noch nicht bekannt | Neutral | Aus den Prüfungen |
| Offen, Merge-Konflikte | Rot | Aus den Prüfungen |
| Entwurf | Neutral | Aus den Prüfungen |
| Gemergt | Lila | Keiner |
| Geschlossen | Neutral | Keiner |

Der Punkt ist grün bei bestandenen Prüfungen, rot bei fehlgeschlagenen Prüfungen und gelb-orange bei laufenden Prüfungen. Wenn das Repository keine Prüfungen meldet, wird kein Punkt angezeigt. Eine fehlgeschlagene Prüfung hat Vorrang vor einer, die noch läuft.

## Welche Pull Request du siehst [#which-pull-request-you-see]

Der Workspace meldet das Repository, den Branch und den Commit, bei dem der Chat zuletzt ausgeführt wurde, und LibreChat sucht nach einem Pull Request aus diesem Branch:

- Wenn die eigene Befehlsausgabe des Chats einen Link zu einem Pull Request im selben Repository ausgibt (zum Beispiel die URL, die `gh pr create` ausgibt), wird dieser Pull Request verwendet, sofern er vom Branch des Chats stammt.
- Andernfalls werden offene Pull Requests für den Branch gegenüber geschlossenen bevorzugt, sodass ein alter, geschlossener Pull Request mit einem wiederverwendeten Branch-Namen nicht den aktuellen verdeckt.
- Ein Pull Request zählt nur, wenn er den Commit enthält, auf dem der Chat zuletzt ausgeführt wurde. Das Löschen eines Branches und die Wiederverwendung seines Namens bringt den alten Pull Request nicht zurück.
- Ein brandneuer Branch ohne Commits stimmt mit nichts überein.

Repositories, für die der Server keine Abfrage durchführen darf, verhalten sich genau wie Repositories ohne Pull Request: keine Markierung und kein Fehler.

## Eigenes Konto verbinden [#connect-your-own-account]

Falls Ihr Administrator es eingerichtet hat, können Sie Pull Requests mit Ihrem eigenen GitHub-, GitLab- oder Bitbucket-Konto abrufen. Öffnen Sie **Einstellungen**, wechseln Sie zu **Konto** und klicken Sie unter **Verbundene Konten** neben **Pull-Request-Konto** auf **Verbinden**. Es öffnet sich ein Anmeldefenster beim Anbieter; bestätigen Sie es, dann zeigt die Zeile **Verbunden** an. Wenn sich das Fenster nicht öffnet, erlauben Sie Pop-ups für LibreChat und versuchen Sie es erneut.

Sobald die Verbindung hergestellt ist, verwenden Abfragen Ihr Konto, sodass Sie Pull Requests in jedem Repository sehen, das Sie lesen können, und zwar unter Ihrem eigenen Rate-Limit. **Trennen** entfernt die Verbindung, und Sie können sie jederzeit erneut herstellen. Wenn der Server Ihre Verbindung nicht erneuern kann (z. B. weil der Anbieter nicht erreichbar ist), werden Ihre Pull Requests als nicht verfügbar angezeigt, anstatt stillschweigend auf das Token des Servers zurückzugreifen. Wenn Sie die App beim Anbieter widerrufen, entfernt LibreChat die Verbindung, und Sie sind wieder im Status „nicht verbunden“.

Wenn in der Zeile **Not in use** steht, hat Ihr Administrator die Kontoverbindungen deaktiviert, und Suchanfragen verwenden Ihr Konto nicht mehr. Klicken Sie auf **Disconnect**, um die gespeicherte Verbindung zu entfernen.

## Einrichtung [#setup]

Die Funktion ist standardmäßig aktiviert, bleibt jedoch ausgeblendet, bis ein Administrator LibreChat ein Token und eine Liste von Repositories übergibt, die es durchsuchen darf, oder eine App einrichtet, damit Benutzer ihre eigenen Konten verbinden können. Außerdem benötigt sie einen angehängten Code-Workspace, der seinen Git-Branch meldet. Siehe [Pull-Request-Konfiguration](/docs/configuration/pull_requests).
