L'API Agents permet au code extérieur à LibreChat de communiquer avec vos agents. Il suffit de pointer n'importe quel SDK OpenAI vers votre instance, de passer un identifiant d'agent comme modèle, et vous obtenez toute la configuration de l'agent (instructions, outils, fichiers) derrière une API familière. Utilisez-la pour intégrer un agent dans un script, une tâche CI ou un autre produit.

- **Inférence** : Chat Completions et Open Responses, authentifiés avec une clé d'API (ou vos propres jetons OIDC, si l'administrateur a configuré cette option).
- **Événements d'agent** : confiez à un agent un travail provenant d'un autre système, comme un webhook, et suivez s'il a été accompli. Clés API uniquement.
- **Gestion des agents** : créez et modifiez des agents et des compétences depuis un service de confiance, à l'aide de jetons OIDC machine.

## Obtenir une clé API [#get-an-api-key]

Ouvrez **Paramètres**, accédez à **Données et confidentialité**, puis repérez **Clés API d'agent** sous **Clés API**. Cliquez sur **Gérer**, puis sur **Créer une clé API**, donnez-lui un nom et choisissez une expiration (de 7 jours à 1 an, ou jamais). Copiez la clé immédiatement : elle n'est affichée qu'une seule fois.

Une clé agit en votre nom. Tout ce que vous pouvez atteindre via l'API, quiconque détient la clé peut aussi l'atteindre. Supprimez donc les clés que vous n'utilisez plus. La suppression d'une clé coupe immédiatement l'accès aux applications qui l'utilisent.

Si vous ne voyez pas cette section, votre rôle n'a pas reçu l'accès à l'API Agents.

## Quels agents vous pouvez appeler [#which-agents-you-can-call]

Vous pouvez appeler les agents que vous possédez ou que vous pouvez partager. Pour l'agent de quelqu'un d'autre, le propriétaire doit vous accorder l'accès à l'aide du bouton **Accès à distance** (l'icône de globe) dans le pied de page du Créateur d'agents. Cela est distinct du partage normal : pouvoir discuter avec un agent dans LibreChat ne vous permet pas de l'appeler via l'API.

Vous avez besoin de l'identifiant de l'agent, affiché sous **Advanced Settings** dans le constructeur avec un bouton de copie. `GET /api/agents/v1/models` liste les agents que votre clé peut appeler, et `GET /api/agents/v1/models/{model}` en renvoie un.

## Complétions de chat [#chat-completions]

`POST /api/agents/v1/chat/completions` suit le format OpenAI Chat Completions, ainsi les clients OpenAI existants fonctionnent en modifiant simplement l'URL de base :

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-librechat-instance/api/agents/v1",
    api_key="YOUR_API_KEY",
)

stream = client.chat.completions.create(
    model="agent_abc123",
    messages=[{"role": "user", "content": "Summarize yesterday's open tickets."}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

La même requête avec curl :

```bash
curl https://your-librechat-instance/api/agents/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent_abc123",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Réponses ouvertes [#open-responses]

`POST /api/agents/v1/responses` implémente la spécification [Open Responses](https://www.openresponses.org/), conçue pour les charges de travail des agents : le raisonnement, les appels d'outils et les événements diffusés en continu font partie intégrante du format plutôt que d'être ajoutés après coup. C'est l'interface sur laquelle LibreChat s'appuie désormais, c'est pourquoi nous recommandons de l'utiliser pour les nouvelles intégrations.

```bash
curl https://your-librechat-instance/api/agents/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "agent_abc123", "input": "What changed in the last release?"}'
```

`GET /api/agents/v1/responses/{id}` renvoie une réponse enregistrée, et `GET /api/agents/v1/responses/models` liste les agents disponibles ici.

### Vos propres outils de fonction [#your-own-function-tools]

Vous pouvez transmettre des outils `function` standard dans une requête Responses. LibreChat les présente au modèle mais ne les exécute pas : lorsque le modèle en choisit un, la réponse contient un élément `function_call`, et c'est à vous d'exécuter la fonction. Pour continuer, envoyez une nouvelle requête dont le `input` répète cet élément `function_call`, suivi d'un `function_call_output` avec le même `call_id` :

```json
{
  "model": "agent_abc123",
  "input": [
    { "type": "function_call", "call_id": "call_abc123", "name": "lookup_order", "arguments": "{\"order_id\":\"A-42\"}" },
    { "type": "function_call_output", "call_id": "call_abc123", "output": "{\"status\":\"shipped\"}" }
  ]
}
```

Rien n'est maintenu ouvert entre les deux requêtes, et `previous_response_id` seul ne suffit pas : vous devez rejouer l'appel et sa sortie. Les noms d'outils peuvent utiliser des lettres, des chiffres, des tirets bas et des tirets, doivent être uniques, et ne peuvent pas masquer l'un des propres outils de l'agent. Un tour qui appelle l'un de vos outils ne peut pas appeler simultanément les outils de l'agent ; le modèle est invité à réessayer.

### Approbation des outils via l'API [#tool-approval-over-the-api]

Si votre administrateur exige une approbation pour certains outils, les appels d'API ne peuvent pas s'interrompre pour demander l'avis de quiconque. Les outils nécessitant une approbation, ou ceux qui sont refusés, sont alors bloqués. Les administrateurs doivent autoriser explicitement les outils qu'un client sans surveillance est censé exécuter.

## Événements d'agent [#agent-events]

Les événements d'agent permettent à un autre système de confier un travail à un agent, puis de revenir plus tard pour voir ce qui s'est passé. Cette fonctionnalité est en bêta. Les événements utilisent votre clé API Agents, qui vous identifie ainsi que la source ; les configurations reposant uniquement sur OIDC ne peuvent pas les utiliser. Ils disposent également de leur propre limite de débit, [`rateLimits.agentEvents`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

Un événement se présente selon l'un de trois modes :

- `fire` démarre une nouvelle conversation avec l'agent.
- `continue` ajoute un tour à un agent enfant que vous avez lié précédemment (voir ci-dessous).
- `steer` ajoute des consignes à une exécution encore en cours, identifiée par la conversation et la génération renvoyées par un `fire`.

```http
POST /api/agents/v1/events
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: webhook-42-resource-7
Content-Type: application/json

{
  "mode": "fire",
  "event": {
    "id": "resource-7-ready-3",
    "type": "resource.ready",
    "occurredAt": 1786967999000,
    "payload": { "resourceId": "resource-7" }
  },
  "target": { "agentId": "agent_abc123" },
  "input": "Resource resource-7 is ready. Inspect it and report the result.",
  "orderingKey": "resource-7"
}
```

Chaque requête nécessite une seule clé `Idempotency-Key` (de 1 à 256 lettres, chiffres ou `._~:/+=-`). Réutilisez-la lorsque vous réessayez la même livraison ; la réutiliser pour un contenu différent constitue un conflit. LibreChat définit la source de l'événement à partir de votre clé API et ignore toute source que vous envoyez. La charge utile est stockée, donc n'y incluez pas de secrets. Utilisez `orderingKey` lorsque des événements concernant le même élément doivent être traités dans l'ordre.

La réponse est `202 Accepted` avec un identifiant de livraison et un `Location` à interroger avec la même clé :

```http
GET /api/agents/v1/events/{delivery_id}
Authorization: Bearer <SAME_REMOTE_AGENTS_API_KEY>
```

Une livraison est `pending`, `leased`, `succeeded` ou `dead`. Pour un `continue` lié, `succeeded` signifie uniquement que le tour a démarré. Son statut `handling` passe ensuite de `started` à l'un des états suivants : `applied`, `completed_no_action`, `failed` ou `cancelled`. Si vous envoyez un `expectedAction` (un nom d'outil et, éventuellement, certains de ses arguments), `applied` signifie que LibreChat a bien constaté l'appel de cet outil avec des arguments correspondants ; ce que le modèle affirme dans son texte ne compte pas.

Les événements d'agent ne constituent pas un récepteur de webhooks public. Si les événements proviennent d'un fournisseur qui signe ses webhooks, vérifiez la signature dans votre propre adaptateur avant de les transmettre.

### Agents enfants pilotés par les événements [#event-driven-child-agents]

Pour conserver une conversation en cours avec un agent enfant au fil de nombreux événements, liez-le une fois, puis envoyez des événements `continue` à cette liaison :

```http
POST /api/agents/v1/events/bindings
Authorization: Bearer <REMOTE_AGENTS_API_KEY>
Idempotency-Key: championship-7-player-hanae
Content-Type: application/json

{
  "actorId": "hanae-kobayashi",
  "parentConversationId": "director-conversation-id",
  "parentMessageId": "director-message-id",
  "target": { "agentId": "agent_hanae" }
}
```

Le parent doit être une conversation d'agent normale, et la cible doit être l'un des sous-agents directs de cet agent (ou l'agent lui-même, si l'auto-génération est autorisée). `actorId` peut comporter jusqu'à 128 caractères. Une nouvelle liaison renvoie `201`, et une relecture renvoie `200`, les deux avec l'`id` de la liaison. Les tours suivants y font référence :

```json
{
  "mode": "continue",
  "bindingId": "evtbind_...",
  "event": { "id": "game-12-ply-17", "type": "chess.turn.ready", "occurredAt": 1786968000000, "payload": { "gameId": "game-12" } },
  "input": "Your clock is running. Submit one legal move.",
  "expectedAction": { "tool": "submit_move", "arguments": { "gameId": "game-12" } }
}
```

Chaque liaison traite un événement à la fois : le suivant attend que le tour en cours ait un statut de traitement final, tandis que des liaisons différentes s'exécutent en parallèle. Un enfant lié peut se mettre en pause pour une demande à l'utilisateur (Ask User) ou pour une approbation d'outil ; ses événements ultérieurs attendent alors qu'une personne y réponde dans LibreChat. Cela nécessite le point de contrôle MongoDB durable (celui par défaut). Dans la conversation parente, chaque enfant lié apparaît sous forme de ligne sous le message qui possède la liaison et ouvre le panneau d'activité des sous-agents.

Une liaison ne fonctionne qu'avec la clé API, l'utilisateur et le locataire qui l'ont créée. Le fil enfant reste hors de la liste des conversations et est en lecture seule dans l'application.

Pour les événements qui ne sont que des observations, comme « une partie a progressé », donnez-leur la même `coalesce.key` : LibreChat regroupe jusqu'à 8 d'entre eux (dans un délai de 750 ms et une limite de 512 KiB) en un seul tour. Chaque événement reçoit toujours son propre reçu. Ne regroupez pas les commandes, les approbations ni tout élément possédant un `expectedAction`.

## API de gestion des agents [#agent-management-api]

L'API de gestion des agents permet à un service de confiance de créer, modifier et supprimer des agents et des compétences sans session de navigateur. Elle est en version bêta et utilise sa propre authentification : des jetons OIDC machine provenant de clients que l'administrateur répertorie sous [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi). Chaque client est lié à un utilisateur LibreChat existant et à un tenant, et chaque requête agit au nom de cet utilisateur, avec ses permissions et ses accès. Elle ne fait pas de quiconque un administrateur.

| Méthode  | Route                                        | Objectif                            |
| -------- | -------------------------------------------- | ---------------------------------- |
| `POST`   | `/api/agents/v1/agents`                      | Créer un agent                     |
| `GET`    | `/api/agents/v1/agents`                      | Lister les agents accessibles      |
| `GET`    | `/api/agents/v1/agents/{id}`                 | Lire un agent                      |
| `PATCH`  | `/api/agents/v1/agents/{id}`                 | Mettre à jour un agent             |
| `DELETE` | `/api/agents/v1/agents/{id}`                 | Supprimer un agent                 |
| `POST`   | `/api/agents/v1/agents/{id}/files`           | Télécharger et joindre un fichier  |
| `GET`    | `/api/agents/v1/agents/{id}/files`           | Lister les fichiers joints         |
| `DELETE` | `/api/agents/v1/agents/{id}/files/{fileId}`  | Détacher un fichier                |
| `GET`    | `/api/agents/v1/skills`                      | Lister les compétences accessibles |
| `POST`   | `/api/agents/v1/skills`                      | Créer une compétence               |
| `GET`    | `/api/agents/v1/skills/{id}`                 | Lire une compétence                |
| `PATCH`  | `/api/agents/v1/skills/{id}`                 | Mettre à jour une compétence       |
| `DELETE` | `/api/agents/v1/skills/{id}`                 | Supprimer une compétence           |
| `GET`    | `/api/agents/v1/skills/{id}/files`           | Lister les fichiers d'une compétence |
| `GET`    | `/api/agents/v1/skills/{id}/files/{path}`    | Lire un fichier de compétence      |
| `PUT`    | `/api/agents/v1/skills/{id}/files/{path}`    | Créer ou remplacer un fichier de compétence |
| `DELETE` | `/api/agents/v1/skills/{id}/files/{path}`    | Supprimer un fichier de compétence |

```bash
curl -X POST https://your-librechat-instance/api/agents/v1/agents \
  -H "Authorization: Bearer YOUR_MACHINE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Release assistant",
    "provider": "openAI",
    "model": "gpt-5.6",
    "instructions": "Prepare concise release notes from verified changes."
  }'
```

Agent payloads take the same fields as the Agent Builder and reject unknown ones; `model` is required on create. Lists take `limit` (1 to 100, default 20) and a `cursor`; when `has_more` is true, pass the returned `after` as the next cursor. File uploads are `multipart/form-data` with one `file` and a `tool_resource` such as `context`, `file_search`, or `execute_code`, subject to the usual upload limits.

Skill create takes `name`, `description`, `body`, and optionally `displayTitle`, `frontmatter`, `category`, and `alwaysApply`. Updates must send the skill's current version as `expectedVersion`, so two writers cannot overwrite each other silently.

Les erreurs utilisent les codes `invalid_request`, `not_found`, `permission_denied`, `conflict` et `internal_error`. Une ressource à laquelle vous n'avez pas accès peut être renvoyée avec le code `not_found`. Des identifiants incorrects ou manquants renvoient `401`.

Si l'administrateur l'active, une description OpenAPI des routes de gestion est servie à l'adresse `/api/openapi.json`, avec une documentation interactive à `/api/docs`. Elle ne couvre ni l'inférence ni les événements. Voir [`openapi`](/docs/configuration/librechat_yaml/object_structure/config#openapi).

## Utilisation et facturation [#usage-and-billing]

Les requêtes API sont décomptées de votre solde de jetons exactement comme les conversations dans l'application. Les totaux d'utilisation de la réponse incluent les appels de sous-agents, avec une répartition distincte `primary` et `subagent`, ainsi que les jetons de cache et de raisonnement lorsque le fournisseur les signale. Voir [Utilisation des jetons](/docs/configuration/token_usage).

## Configuration [#setup]

L'API Agents est désactivée pour les utilisateurs standard jusqu'à ce qu'un administrateur accorde les permissions Remote Agents à leur rôle, soit dans le [Panneau d'administration](/docs/features/admin_panel), soit avec [`interface.remoteAgents`](/docs/configuration/librechat_yaml/object_structure/interface#remoteagents). Les administrateurs disposent de ces permissions par défaut. L'authentification par clé API est activée par défaut ; pour accepter des jetons émis par votre propre fournisseur OIDC à la place des clés ou en complément de celles-ci, consultez [`remoteApi`](/docs/configuration/librechat_yaml/object_structure/agents#remoteapi). L'API de gestion se configure séparément sous [`managementApi`](/docs/configuration/librechat_yaml/object_structure/agents#managementapi), et les paramètres de diffusion des événements se trouvent sous [`eventDriven`](/docs/configuration/librechat_yaml/object_structure/agents#eventdriven).
