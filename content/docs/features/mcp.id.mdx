Model Context Protocol (MCP) adalah protokol terbuka yang menstandardisasi cara aplikasi menyediakan konteks ke Large Language Models (LLMs). Anggaplah MCP sebagai **"USB-C untuk AI"** - sebagaimana USB-C menyediakan standar koneksi universal untuk perangkat elektronik, MCP menawarkan cara terstandardisasi untuk menghubungkan model AI ke berbagai alat, sumber data, dan layanan.

LibreChat memanfaatkan MCP untuk memperluas kemampuan agen AI Anda secara dramatis, memungkinkan Anda untuk mengintegrasikan segalanya mulai dari akses sistem file, peramban web, API khusus, hingga alat bisnis kustom.

## Mengapa MCP Penting [#why-mcp-matters]

LLM terbatas pada kemampuan bawaan mereka. Dengan MCP, LibreChat mendobrak batasan tersebut dengan:

- **Menghubungkan ke alat atau layanan apa pun** yang menyediakan server MCP
- **Menstandardisasi integrasi** sehingga Anda tidak perlu mengubah kode LibreChat untuk setiap alat
- **Mendukung lingkungan multi-pengguna** dengan autentikasi dan isolasi yang tepat
- **Menambahkan dan memperbarui server saat runtime** dari panel Pengaturan MCP, tanpa perlu mengedit file konfigurasi atau memulai ulang

## Bagaimana MCP Bekerja di LibreChat [#how-mcp-works-in-librechat]

LibreChat menyediakan dua cara untuk menggunakan server MCP, baik di area obrolan maupun dengan agen.

Anda dapat mengonfigurasi server MCP secara manual di dalam file `librechat.yaml` Anda atau dengan menggunakan [smithery.ai](https://smithery.ai) untuk mencari dan menginstal server MCP ke dalam `librechat.yaml` ([lihat contoh di bawah](#basic-configuration)). Setiap kali Anda menambah atau mengedit server di `librechat.yaml`, Anda perlu memulai ulang LibreChat untuk menginisialisasi koneksi. Server yang ditambahkan melalui [panel Pengaturan MCP](#adding-mcp-servers-in-the-ui) akan langsung berlaku tanpa perlu memulai ulang. Server yang dibuat melalui panel dan menggunakan OAuth akan terdaftar saat disimpan, tetapi awalnya dalam status terputus: [autentikasi server tersebut](#step-3-check-connection-status-and-authenticate) sekali untuk menghubungkannya.

### URL Callback OAuth [#oauth-callback-url]

Untuk server MCP yang mengaktifkan OAuth, URL callback LibreChat adalah:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>` adalah kunci yang digunakan di bawah `mcpServers` dalam `librechat.yaml` atau nama server yang dibuat di UI Pengaturan MCP. Sebagai contoh, server bernama `salesforce` dengan `DOMAIN_SERVER=https://chat.example.com` menggunakan `https://chat.example.com/api/mcp/salesforce/oauth/callback`.

Daftarkan URL callback yang tepat ini dengan penyedia OAuth. Instalasi Docker lokal biasanya menggunakan `http://localhost:3080` sebagai URL dasar.

### Di Area Obrolan [#in-chat-area]

![Katalog MCP Servers yang dibuka dari palet composer, menampilkan status koneksi setiap server](/images/mcp/mcp_servers_catalog.png)

LibreChat menampilkan server MCP yang dikonfigurasi langsung di area obrolan saat menggunakan endpoint tradisional (OpenAI, Anthropic, Google, Bedrock, dll.):

- Pilih endpoint non-agen terlebih dahulu, dan model yang kompatibel dengan tool
- Server MCP muncul di bagian **MCP Servers** pada [palet **+** composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers), dan setiap server yang dipilih akan ditampilkan sebagai chip pada composer
- Saat dipilih, semua alat dari server tersebut akan tersedia untuk model Anda saat ini
- Akses cepat ke alat MCP tanpa perlu membuat agen, memungkinkan penggunaan beberapa server sekaligus

Untuk menjaga agar server MCP tidak muncul dalam pilihan obrolan reguler, atur [`chatMenu: false`](/docs/configuration/librechat_yaml/object_structure/mcp_servers#chatmenu) di dalam konfigurasi Anda:

```yaml
mcpServers:
  internal-tools:
    command: npx
    args: ['-y', 'internal-mcp-server']
    chatMenu: false # Not selectable in regular chat
```

Pengaturan ini diberlakukan pada permintaan obrolan serta di dalam pemilih, sehingga pilihan tersimpan yang kedaluwarsa tidak dapat terus menggunakan server yang tersembunyi. Pengaturan ini tidak menghapus server dari Agen yang tersimpan atau dari model spec yang secara eksplisit menetapkannya. LibreChat juga menghilangkan server yang hanya dapat dijangkau pengguna melalui Agen resmi dari pemilih obrolan reguler dan jalur permintaan.

### Dengan Agen [#with-agents]

Server MCP terintegrasi dengan mulus dengan Agen LibreChat:

1. Buat atau edit agen
2. Buka **Add tools** di Agent Builder dan pilih **MCP**
3. Pilih server MCP; setiap server muncul sebagai satu entri katalog
4. Perluas server yang dipilih untuk mengaktifkan atau menonaktifkan alat individual
5. Simpan agen Anda

![MCP Tools in Agent Builder](/images/mcp/mcp_ui_agent.png)

Organisasi tingkat tinggi ini menjaga antarmuka tetap mudah dikelola - bahkan server dengan 20+ alat (seperti Spotify) muncul sebagai entri tunggal yang dapat diperluas untuk kontrol yang lebih terperinci.

### Konfigurasi Dasar [#basic-configuration]

Tambahkan server MCP ke file `librechat.yaml` Anda secara manual:

```yaml
mcpServers:
  # ClickHouse Cloud
  clickhouse-cloud:
    type: streamable-http
    url: https://mcp.clickhouse.cloud/mcp

  # File system access
  filesystem:
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /path/to/your/documents

  # Web browser automation
  puppeteer:
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'

  # Production-ready cloud service
  business-api:
    type: streamable-http
    url: https://api.yourbusiness.com/mcp
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
    serverInstructions: true
```

![Dialog Tambah Server MCP](/images/mcp/mcp_ui_configure.png)

Server baru Anda akan muncul di panel MCP Settings dengan notifikasi konfirmasi.

![MCP Server Created Successfully](/images/mcp/mcp_ui_success_registered.png)

#### Langkah 3: Periksa Status Koneksi dan Autentikasi [#step-3-check-connection-status-and-authenticate]

Tinjau [indikator status koneksi](#connection-status-indicators) untuk server baru Anda. Jika server memerlukan autentikasi OAuth, status akan ditampilkan sebagai terputus (disconnected). Pilih server MCP di palet **+** pada composer untuk memulai alur autentikasi.

![Connection Status - Disconnected](/images/mcp/mcp_ui_unconnected.png)

Setelah dimulai, indikator status akan diperbarui untuk menunjukkan bahwa autentikasi sedang berlangsung.

![Status Koneksi - Mengautentikasi](/images/mcp/mcp_ui_authenticating.png)

#### Langkah 4: Lanjutkan dengan OAuth [#step-4-continue-with-oauth]

LibreChat menampilkan prompt konfirmasi **Connect**. Tinjau tujuan dan pilih **Continue with OAuth** untuk membuka halaman otorisasi penyedia di tab browser baru. Selesaikan alur masuk dan persetujuan penyedia di sana.

Jika alur yang dimulai di peramban ini tertunda, LibreChat akan menjaga server tersebut dalam status authorizing/connecting meskipun status koneksi yang di-cache masih menunjukkan **Connected**. Prompt tidak boleh ditutup hanya karena status lama melaporkan otorisasi yang tahan lama; keberhasilan terminal, kegagalan, waktu habis (timeout), atau pembatalan akan mengakhiri alur yang tertunda. Alur yang dimulai di tab atau peramban lain tidak memiliki status tertunda lokal dalam tampilan ini.

![OAuth Continue Prompt](/images/mcp/mcp_ui_callback_confirm.png)

#### Langkah 5: Autentikasi Berhasil [#step-5-authentication-successful]

Setelah melakukan autentikasi, Anda akan melihat konfirmasi keberhasilan. Jendela ini akan tertutup secara otomatis dan mengarahkan Anda kembali ke LibreChat.

LibreChat mengakui keberhasilan autentikasi dan secara otomatis memilih server MCP untuk digunakan dalam percakapan Anda. Server tersebut kini menampilkan indikator status terhubung dan muncul sebagai chip yang dipilih pada composer.

![MCP Server Authenticated and Auto-Selected](/images/mcp/mcp_ui_done.png)

Server MCP baru Anda juga tersedia di Agent Builder, di mana Anda dapat menambahkan alatnya ke agen mana pun dan menyesuaikan subset alat mana yang diizinkan.

![MCP Server Tersedia di Pembuat Agen](/images/mcp/mcp_ui_agent.png)

#### Variabel Kredensial untuk Server yang Dibuat melalui UI [#credential-variables-for-ui-created-servers]

Saat menambahkan server MCP melalui UI, Anda dapat mewajibkan pengguna untuk menyediakan kunci API mereka sendiri. Di bagian Authentication pada dialog MCP Server Builder, pilih "API Key" dan centang **"User provides key"**. Pilih format header (Bearer, Basic, atau Custom) dan simpan server tersebut.

Di balik layar, LibreChat membuat entri `customUserVars` yang terikat pada tujuan bernama `MCP_API_KEY_<hash>` dan mengonfigurasi header autentikasi yang sesuai. Nama tersebut dikelola secara otomatis; pengguna tetap memasukkan kunci mereka di Dialog Pilih Alat MCP atau panel Pengaturan MCP. Server yang sudah ada mungkin tetap menggunakan nama `MCP_API_KEY` lama selama batas permintaan mereka tidak berubah. Ini menggunakan UI entri kunci yang sama seperti [`customUserVars` yang didefinisikan YAML](#user-provided-credentials).

Mengubah URL server yang dibuat melalui UI (termasuk path atau query), proxy, transport, format otorisasi, header otorisasi kustom, atau klien/tujuan OAuth yang dikonfigurasi mengharuskan setiap pengguna untuk memasukkan kunci untuk batasan baru tersebut. Kunci lama yang tersimpan tidak diteruskan ke tujuan pengganti tersebut. Pengeditan kosmetik, URL yang dinormalisasi secara ekuivalen, dan pengeditan URL keluar yang hanya berupa fragmen akan mempertahankan kunci yang sudah ada. Server yang dibagikan hanya dapat menyelesaikan variabel kredensial yang dideklarasikan oleh konfigurasi saat ini, sehingga editor tidak dapat mereferensikan nama yang dibuat sebelumnya untuk memulihkan kunci terdahulu. Tidak diperlukan migrasi kredensial massal. Tingkatkan **setiap replika API**, termasuk replika yang melayani permintaan pengeditan server, sebelum mengandalkan perlindungan ini; penulis yang lebih lama masih dapat membuat ulang konfigurasi yang tidak terikat.

Ketika kunci API administrator atau pengguna dikonfigurasi, LibreChat memperlakukan server sebagai terautentikasi kunci API dan melewati deteksi otomatis OAuth. Konfigurasi OAuth eksplisit tetap lebih diutamakan. Jika server kunci API yang dibuat melalui UI disimpan oleh versi LibreChat yang lebih lama dan tetap tertahan di **OAuth Required**, edit dan simpan server tersebut satu kali agar metadata koneksi yang tersimpan diperbarui.

<Callout type="warning">
Demi keamanan, server MCP yang dibuat melalui UI (bersumber dari DB) **hanya** dapat menyelesaikan placeholder `customUserVars` (`{{VAR_NAME}}`). Variabel lingkungan sisi server (`${ENV_VAR}`), kolom profil pengguna (`{{LIBRECHAT_USER_*}}`), dan token OIDC (`{{LIBRECHAT_OPENID_*}}`) sengaja diblokir untuk mencegah akses tidak sah ke rahasia server atau data pengguna lain. Untuk dukungan placeholder penuh, konfigurasikan server di `librechat.yaml` sebagai gantinya.
</Callout>

## Manajemen Server MCP [#mcp-server-management]

LibreChat menyediakan alat yang komprehensif untuk mengelola koneksi server MCP dengan pelacakan status koneksi serta dukungan autentikasi dan inisialisasi OAuth di dalam UI.

### Indikator Status Koneksi [#connection-status-indicators]

LibreChat menampilkan ikon status dinamis yang menunjukkan kondisi terkini dari setiap server MCP di palet **+** pada composer dan panel pengaturan:

![Ikon Status Server MCP](/images/mcp/mcp_server_status_icons.png)

**Tipe Status:**

- **Terhubung** (ikon roda gigi hijau): Server telah terhubung dan memiliki customUserVars yang dapat dikonfigurasi
- **OAuth Diperlukan** (kunci amber): Server memerlukan autentikasi OAuth
- **Terputus** (steker oranye): Koneksi server gagal atau terputus
- **Initializing** (pemuat biru): Server sedang memulai atau menyambungkan kembali
- **Error** (segitiga merah): Server mengalami kesalahan
- **Membatalkan** (tanda x merah): Alur OAuth sedang dibatalkan

### Membatalkan OAuth dari Dialog Alat Agen [#cancelling-oauth-from-the-agent-tool-dialog]

Di **Agent Builder → Tool Library → MCP server configuration**, **Connect** berubah menjadi tindakan **Cancel** yang aktif sementara pengelola server bersama melaporkan alur OAuth yang dapat dibatalkan. Ini termasuk alur tertunda yang ditemukan dari panel LibreChat lainnya. Pilih **Cancel** untuk menghentikan alur tersebut, menutup prompt OAuth lokal, dan menghapus pemilihan otomatis alat yang tertunda. Hasil koneksi yang terlambat setelah pembatalan tidak akan melampirkan alat secara otomatis dalam dialog ini. Anda dapat memilih **Connect** lagi untuk mencoba kembali. Inisialisasi yang tidak dapat dibatalkan akan tetap menampilkan status sibuk yang dinonaktifkan alih-alih tindakan pembatalan.

### Inisialisasi Server [#server-initialization]

Anda dapat menginisialisasi atau menginisialisasi ulang server MCP secara langsung dari antarmuka:

**Sekali klik:**

- Inisialisasi sekali klik dengan memilih server di bagian **MCP Servers** pada palet **+** di composer

  <Video src="/videos/mcp_one_click_init.mp4" title="Inisialisasi MCP sekali klik" />

**Dari MCPConfigDialog:**

- Pilih **Configure** pada baris server MCP di palet **+** komposer untuk membuka MCPConfigDialog
- Konfigurasikan variabel pengguna kustom dan klik tombol Authenticate/Initialize tergantung pada tipe autentikasi server

       <Video src="/videos/mcp_config_dialog_auth.mp4" title="Autentikasi dialog konfigurasi MCP" />

  **Dari Panel Pengaturan MCP:**

- Klik server mana pun di bagian daftar server pada Panel Pengaturan MCP untuk mengakses kontrol konfigurasi dan inisialisasi
- Konfigurasikan variabel pengguna kustom dan klik tombol Authenticate/Initialize tergantung pada tipe autentikasi server

  <Video src="/videos/mcp_settings_init.mp4" title="Inisialisasi panel pengaturan MCP" />

Kegagalan inisialisasi kini membedakan antara server yang tidak dapat dijangkau, `customUserVars` yang hilang, koneksi OAuth yang harus diautentikasi ulang, dan kegagalan inisialisasi umum. Gunakan variabel yang hilang atau tindakan autentikasi ulang yang disebutkan dalam pesan sebelum mencoba kembali; server tidak perlu lagi dihapus dan ditambahkan kembali untuk kasus-kasus ini.

Pemuatan katalog pasif menggabungkan upaya penemuan OAuth dan melakukan *back off* secara progresif setelah kegagalan, sehingga integrasi yang terputus tidak mencoba penemuan ulang pada setiap permintaan. Perubahan kredensial dipagari berdasarkan generasi di seluruh replika, mencegah hasil penemuan lama menimpa autentikasi yang lebih baru. Operator dapat menyesuaikan kebijakan pemulihan terbatas di bawah [`mcpSettings.catalogRecovery`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#catalogrecovery); pengaturan bawaan sudah sesuai untuk sebagian besar penyebaran.

Jika sebuah Agent secara eksplisit mengharapkan alat MCP tetapi tidak ada yang dapat diselesaikan saat awal dijalankan, LibreChat akan menggagalkan proses tersebut dengan panduan koneksi dan akses alih-alih menjalankannya secara diam-diam tanpa alat tersebut.

Server MCP yang mengirimkan `notifications/tools/list_changed` dapat memperbarui katalog alat mereka tanpa perlu memulai ulang LibreChat. LibreChat mengambil daftar terkini dari koneksi langsung, memublikasikan alat yang ditambahkan, dan berhenti mengiklankan alat yang dihapus oleh server. Koneksi ulang juga menyinkronkan katalog sebelum koneksi dianggap siap. Penyegaran snapshot terkelola dan penemuan server-dingin berbagi satu gerbang tiga-operasi di seluruh proses. Setelah diizinkan, setiap operasi tetap dibatasi oleh tenggat waktu daftar-alat atau penemuan per-server, termasuk `initTimeout` yang lebih singkat, sehingga pekerjaan katalog yang lambat tidak dapat menahan slot tanpa batas waktu.

Untuk server HTTP yang dapat di-stream, penyambungan kembali (reconnect) dapat secara singkat mengembalikan HTTP `409` ketika server masih menahan stream SSE mandiri yang sudah usang untuk sesi lama. LibreChat menganggap ini sebagai masalah sementara, memutuskan sesi yang usang, dan membangun kembali koneksi secara otomatis; tidak diperlukan tindakan operator saat pemulihan berhasil. Jika koneksi yang dibangun kembali juga gagal, LibreChat akan terus menampilkan kesalahan koneksi yang mendasarinya.

LibreChat mengklasifikasikan respons HTTP yang dapat di-stream (Streamable) berdasarkan tipe media `Content-Type` yang diurai, bukan melalui pencocokan substring. Parameter tidak dapat membuat respons non-SSE tampak sebagai `text/event-stream`, sehingga kesalahan ukuran respons tetap berlanjut melalui jalur penanganan SSE atau non-SSE yang benar.

### Visibilitas Panel Pengaturan MCP [#mcp-settings-panel-visibility]

Panel Pengaturan MCP muncul di bilah sisi kanan ketika LibreChat mendeteksi server MCP yang mungkin memerlukan intervensi pengguna selama inisialisasinya. Panel tersebut akan terlihat ketika server yang dikonfigurasi memenuhi salah satu kriteria berikut:

- **Custom User Variables**: Server memiliki `customUserVars` yang ditentukan yang mungkin berisi kredensial yang disediakan pengguna
- **Autentikasi OAuth**: Server terdeteksi memerlukan autentikasi OAuth selama startup
- **Inisialisasi Manual**: Server memiliki konfigurasi `startup: false`, yang memerlukan inisialisasi manual

## Fitur Spesifik LibreChat [#librechat-specific-features]

Implementasi MCP LibreChat dirancang untuk lingkungan multi-pengguna dunia nyata yang sangat dapat dikonfigurasi.

### Koneksi Spesifik Pengguna [#user-specific-connections]

- Setiap pengguna mendapatkan koneksi terisolasi mereka sendiri ke server MCP
- Autentikasi pengguna dan izin dihormati
- Data pribadi dan konteks tetap bersifat pribadi

### Berbagi MCP Servers [#sharing-mcp-servers]

Server MCP berpartisipasi dalam sistem [kontrol akses granular](/docs/features/access_control) LibreChat. Selain server yang didefinisikan dalam `librechat.yaml` (yang dikelola oleh admin dan diatur oleh izin fitur [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)), server MCP yang dibuat pengguna memiliki ACL sendiri dan dapat dibagikan kepada **pengguna**, **grup**, **peran**, atau **secara publik**, pada tingkat Viewer, Editor, atau Owner.

`USE`, `CREATE`, `SHARE`, dan `SHARE_PUBLIC` feature flags di bawah `interface.mcpServers` mengontrol siapa saja yang diizinkan untuk membuat dan membagikan MCP servers. Lihat [Access Control](/docs/features/access_control) untuk mengetahui bagaimana lapisan izin disusun.

### Konteks Pengguna Dinamis [#dynamic-user-context]

Server MCP dapat mengakses informasi pengguna melalui placeholder di dalam **URL dan header** (untuk transport SSE dan HTTP yang dapat di-stream):

```yaml
mcpServers:
  user-api:
    type: streamable-http
    url: https://api.example.com/users/{{LIBRECHAT_USER_USERNAME}}/mcp
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
      X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
      Authorization: 'Bearer ${API_TOKEN}'
```

Placeholder yang tersedia meliputi:

- `{{LIBRECHAT_USER_ID}}` - Pengidentifikasi pengguna unik
- `{{LIBRECHAT_USER_EMAIL}}` - Alamat email pengguna
- `{{LIBRECHAT_USER_ROLE}}` - Peran pengguna (admin, user, dll.)
- `{{LIBRECHAT_USER_USERNAME}}` - Nama pengguna
- Dan masih banyak lagi (lihat [Konfigurasi Server MCP](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers) untuk daftar lengkapnya)

Server MCP yang didefinisikan dalam YAML juga dapat menggunakan placeholder `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, dan `{{LIBRECHAT_BODY_*}}`. Nilai `{{LIBRECHAT_BODY_*}}` memiliki cakupan permintaan (request-scoped), sehingga LibreChat membuat koneksi untuk proses yang sedang berjalan, menggunakannya kembali di seluruh pemanggilan alat (tool calls) dalam proses tersebut, dan membersihkannya saat permintaan berakhir. Server dengan cakupan permintaan dikecualikan dari cache alat persisten agar header dan URL spesifik permintaan tidak digunakan kembali di luar proses yang sedang berjalan. Karena daftar alatnya tidak dapat diselesaikan sebelum permintaan obrolan ada, Agent Builder mengekspos satu pilihan runtime-tools untuk keseluruhan server dan menyelesaikan alat-alatnya pada saat runtime. Penyelesaian OAuth menyimpan otorisasi tetapi menunda koneksi hingga proses pertama menyediakan konteks permintaan. Placeholder User, OpenID, dan Graph memiliki cakupan pengguna (user-scoped); transport HTTP menyegarkan header yang telah diselesaikan sebelum setiap pemanggilan alat tanpa memerlukan penyambungan ulang secara mandiri.

Operator tepercaya dapat menggunakan `Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'` pada server jarak jauh yang didefinisikan dalam YAML untuk meneruskan token akses OpenID langsung milik pengguna. Autentikasi MCP OAuth eksplisit, pertukaran *on-behalf-of*, dan kunci API administrator memiliki prioritas lebih tinggi. Setelah menerima `401` atau `403`, LibreChat dapat menyegarkan koneksi satu kali, tetapi tidak akan pernah memutar ulang panggilan *tool* yang ditolak secara otomatis. Lihat [referensi placeholder server MCP](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers) untuk panduan pengaturan dan keamanan.

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` menukarkan token akses OpenID yang dapat digunakan kembali milik pengguna melalui alur on-behalf-of Microsoft. [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration) menetapkan cakupan (scopes) yang dipisahkan oleh spasi yang diminta dan secara default bernilai `https://graph.microsoft.com/.default`. Hal ini terpisah dari `OPENID_GRAPH_SCOPES`, yang mengonfigurasi pencarian orang dan grup.

Placeholder `{{LIBRECHAT_BODY_PARENTMESSAGEID}}` diisi untuk obrolan Agent asli, panggilan API Agent yang kompatibel dengan OpenAI, dan eksekusi Assistants versi lama. Open Responses tidak memiliki identitas pesan induk yang setara dan akan gagal (fails closed) jika server MCP memerlukan nilai tersebut. Lihat [referensi placeholder server MCP](/docs/configuration/librechat_yaml/object_structure/mcp_servers#headers).

### Instruksi Server [#server-instructions]

`serverInstructions` adalah fitur LibreChat yang secara dinamis menambahkan instruksi yang dikonfigurasi saat alat apa pun dari server MCP tersebut dipilih:

```yaml
mcpServers:
  filesystem:
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem', '/docs']
    serverInstructions: |
      When accessing files:
      - Always check file permissions first
      - Use absolute paths for reliability
      - Handle errors gracefully
```

Opsi:

- `true`: Gunakan instruksi yang diiklankan oleh server jika tersedia
- `false`: Nonaktifkan instruksi
- `string`: Gunakan instruksi kustom secara verbatim (ditampilkan di atas)

LibreChat menyimpan deklarasi yang dikonfigurasi ini secara terpisah dari instruksi yang diambil saat memeriksa server. Oleh karena itu, deklarasi `true` akan tetap aktif di seluruh pemeriksaan dan pemuatan ulang registri yang di-cache, sementara string kustom tetap menjadi otoritatif.

### Konfigurasi Timeout [#timeout-configuration]

Untuk operasi MCP yang berjalan lama, konfigurasikan batas waktu (timeout) yang sesuai untuk inisialisasi maupun operasi alat (tool).

```yaml
mcpServers:
  data-processor:
    type: streamable-http
    url: https://api.example.com/mcp
    initTimeout: 15000 # 15 seconds for server initialization
    timeout: 60000 # 60 seconds for tool operations
```

**Catatan**: Jika operasi masih terputus, periksa konfigurasi proksi Anda (misalnya, nginx, traefik, dll.) yang mungkin memutus koneksi sebelum waktunya karena batas waktu (timeout) bawaan.

Saat pengguna menekan **Stop** selama pemanggilan alat Agent di latar depan, LibreChat meneruskan sinyal pembatalan eksekusi ke MCP. Untuk server HTTP yang dapat melakukan streaming (Streamable), SDK MCP mengirimkan `notifications/cancelled`; server harus mematuhi notifikasi tersebut untuk menghentikan pekerjaannya sendiri. Panggilan latar belakang yang terlepas (detached) secara sengaja mempertahankan siklus hidup yang terpisah dan tidak dibatalkan bersamaan dengan giliran latar depan.

### Kredensial yang Disediakan Pengguna [#user-provided-credentials]

Anda dapat mengizinkan pengguna untuk menyediakan kredensial mereka sendiri untuk server MCP melalui `customUserVars`. Hal ini memungkinkan autentikasi yang aman dan spesifik bagi pengguna tanpa perlu menyimpan kredensial di dalam file konfigurasi.

```yaml
mcpServers:
  my-api-server:
    type: streamable-http
    url: 'https://api.example.com/mcp'
    headers:
      X-Auth-Token: '{{MY_API_KEY}}' # Uses the user-provided value
    customUserVars:
      MY_API_KEY:
        title: 'API Key'
        description: "Enter your personal API key from <a href='https://example.com/keys' target='_blank'>your account settings</a>"
```

Pengguna dapat mengonfigurasi kredensial ini:

- **Dari Area Obrolan**: Pilih **Configure** pada baris server MCP yang dapat dikonfigurasi di palet **+** pada composer
- **Dari Panel Pengaturan MCP**: Akses "MCP Settings" di panel kanan untuk mengelola kredensial bagi semua server yang telah dikonfigurasi

#### Menginisialisasi Ulang Server MCP dengan Kredensial Pengguna [#reinitializing-mcp-servers-with-user-credentials]

Untuk server MCP yang memerlukan kredensial khusus pengguna sebelum dapat digunakan (contohnya, `PAT_TOKEN` di [server MCP resmi GitHub](https://github.com/github/github-mcp-server)), LibreChat memungkinkan pengguna untuk memberikan kredensial tersebut dan kemudian menginisialisasi ulang server MCP dari dalam UI tanpa perlu memulai ulang seluruh aplikasi:

1. Saat Anda memilih MCP yang menggunakan `customUserVars`, Anda akan dapat **Save** (Simpan) atau **Revoke** (Cabut) nilai `customUserVar` untuk server MCP yang dipilih dari dalam Panel MCP.
2. Setelah menyimpan nilai untuk `customUserVar`, klik tombol inisialisasi ulang (ikon dengan panah melingkar di sebelah setiap nama server di Panel MCP).
3. LibreChat akan mencoba terhubung ke server menggunakan kredensial yang Anda berikan dan memberi tahu Anda melalui toast apakah proses inisialisasi ulang telah berhasil atau gagal.

> _Tip: Jika Anda mengetahui bahwa sebuah server akan memerlukan kredensial yang tidak tersedia pada saat pertama kali dijalankan, Anda dapat menambahkan `startup: false` ke konfigurasinya. Ini memberi tahu LibreChat untuk tidak mencoba terhubung ke server tersebut sampai diinisialisasi ulang secara manual di UI._

**Contoh:**

```yaml
mcpServers:
  github-mcp:
    type: streamable-http
    url: 'https://api.githubcopilot.com/mcp/'
    headers:
      Authorization: '{{PAT_TOKEN}}'
    customUserVars:
      PAT_TOKEN:
        title: 'GitHub PAT Token'
        description: 'GitHub Personal Access Token'
    startup: false
```

### Autentikasi OAuth [#oauth-authentication]

LibreChat mendukung autentikasi OAuth untuk server MCP, mengikuti rekomendasi Anthropic untuk koneksi MCP yang aman. OAuth menyediakan cara yang terstandarisasi dan aman untuk melakukan autentikasi tanpa menyimpan kredensial yang berumur panjang.

#### Alur OAuth yang Didukung [#supported-oauth-flows]

Server MCP LibreChat mendukung OAuth 2.0 dengan:

- **Authorization Code Flow with PKCE**: Direkomendasikan untuk keamanan maksimal
- **Client Discovery**: Pendaftaran klien otomatis jika didukung oleh penyedia OAuth
- **Refresh Tokens**: Pembaruan token otomatis jika tersedia
- **Penemuan token endpoint**: Klien yang telah dikonfigurasi sebelumnya dapat mengetahui apakah penyedia mengharapkan kredensial klien di dalam body POST atau di header otorisasi HTTP Basic

Di MCP Builder, **Token Exchange Method** menawarkan **Auto**, **Default (POST request)**, dan **Basic authorization header**. Auto membiarkan metode tidak diatur agar LibreChat dapat menggunakan metadata penyedia tepercaya, dan kembali ke autentikasi Basic ketika penyedia tidak mengiklankan metode.

#### Contoh Konfigurasi [#configuration-examples]

```yaml
mcpServers:
  # Public remote MCP server for PayPal, uses OAuth Client Discovery
  # ❌ Refresh Tokens: you may need to re-authenticate periodically
  # More info: https://developer.paypal.com/tools/mcp-server/
  paypal:
    type: 'sse'
    initTimeout: 150000 # higher timeout to allow for initial authentication
    url: 'https://mcp.paypal.com/sse'

  # Example self-hosted remote MCP server for Spotify, uses OAuth Client Discovery
  # ✅ Refresh Tokens: refreshes token for authentication automatically
  # Hosted on Cloudflare Workers, more info: https://github.com/LibreChat-AI/spotify-mcp
  spotify:
    type: 'streamable-http'
    initTimeout: 150000
    url: 'https://mcp-spotify-oauth-example.account.workers.dev/mcp'
```

#### Alur Autentikasi OAuth [#oauth-authentication-flow]

Saat Anda pertama kali mengonfigurasi server MCP yang mendukung OAuth:

1. **Koneksi Awal**: LibreChat mencoba untuk terhubung ke server MCP
2. **Autentikasi Diperlukan**: Jika tidak ada token yang valid, Anda akan melihat status autentikasi OAuth untuk server tersebut di palet **+** pada composer.
3. **Mulai Masuk**: Pilih server untuk memulai alur OAuth
4. **Lanjutkan atau gunakan perangkat lain**: Lanjutkan di browser saat ini, salin tautan otorisasi, atau tampilkan kode QR untuk membukanya di perangkat lain
5. **Pengalihan Browser**: Selesaikan autentikasi dengan penyedia OAuth
6. **Penanganan Pengembalian (Return Handling)**: LibreChat secara otomatis memproses callback OAuth setelah Anda melakukan autentikasi
7. **Penyimpanan Token**: LibreChat menyimpan token secara aman untuk penggunaan di masa mendatang
8. **Koneksi Terjalin**: Setelah Anda melakukan autentikasi, MCP server akan terhubung dan Anda dapat menggunakannya dalam obrolan Anda

#### URL Callback OAuth [#oauth-callback-url-1]

Ketika server MCP menggunakan OAuth, LibreChat mengekspos endpoint callback yang akan dituju oleh pengalihan dari penyedia OAuth setelah otorisasi berhasil.

URL callback harus mengikuti format berikut:

`${baseUrl}/api/mcp/${serverName}/oauth/callback`

Di mana `${serverName}` adalah kunci server MCP yang ditentukan dalam konfigurasi `librechat.yaml` Anda. LibreChat menangani pengalihan di endpoint ini, menyelesaikan pertukaran token, dan mengaitkan kredensial dengan server MCP yang sesuai.

<Callout type="info" title="Contoh URL Callback OAuth">
Diberikan konfigurasi server MCP berikut:

```yaml
mcpServers:
  # Example self-hosted remote MCP server for Spotify, uses OAuth Client Discovery
  # ✅ Refresh Tokens: refreshes token for authentication automatically
  # Hosted on Cloudflare Workers, more info: https://github.com/LibreChat-AI/spotify-mcp
  spotify:
    type: 'streamable-http'
    initTimeout: 150000
    url: 'https://mcp-spotify-oauth-example.account.workers.dev/mcp'
```

URL callback-nya adalah `${baseUrl}/api/mcp/spotify/oauth/callback`.

</Callout>

Catatan:

- URL callback harus didaftarkan secara tepat pada penyedia OAuth agar alur tersebut dapat berfungsi.
- Jalur lain seperti `/api/oauth/callback` atau `/api/oauth/openid/callback` tidak valid untuk alur OAuth MCP.

#### Manajemen Token [#token-management]

LibreChat menangani token OAuth secara cerdas:

- **Penyimpanan Aman**: Token dienkripsi dan disimpan dengan aman
- **Penyegaran Otomatis**: Saat token penyegaran tersedia, LibreChat secara otomatis memperbarui token akses yang kedaluwarsa
- **Pemulihan 401 Senyap**: Jika koneksi MCP OAuth menerima penolakan autentikasi di tengah sesi, LibreChat mengoordinasikan satu upaya penyegaran dan penyambungan kembali yang dibatasi per pengguna dan server. Pemanggil konkuren akan berbagi hasil pemulihan tersebut sebelum LibreChat menampilkan permintaan autentikasi baru.
- **Manajemen Sesi**: Setiap pengguna mengelola sesi OAuth mereka sendiri untuk lingkungan multi-pengguna

Jika stream Agent yang tersimpan dimuat ulang atau dilanjutkan saat prompt otorisasi MCP masih tertunda, LibreChat akan merekonstruksi prompt tersebut dari status generasi yang persisten. Prompt yang telah selesai, dibatalkan, gagal, atau kedaluwarsa tidak akan dipulihkan.

Klien dan token OAuth yang tersimpan terikat pada URL server MCP serta pengaturan klien/endpoint OAuth. Mengubah pengaturan tersebut mengharuskan pengguna untuk melakukan autentikasi kembali. Saat menyunting server yang dibuat melalui UI yang menyimpan `client_secret`, masukkan kembali secret tersebut ketika mengubah kolom pengikatan seperti URL server, ID klien, URL otorisasi, URL token, atau metode autentikasi token.

Dalam penyebaran yang diskalakan secara horizontal, status alur OAuth dan kesiapan token yang terikat dapat direkonsiliasi di seluruh pod LibreChat. UI hanya melaporkan server sebagai siap setelah inisialisasi pasca-OAuth berhasil, bahkan ketika callback dan polling status mencapai pod yang berbeda. Callback dari upaya yang digantikan akan ditolak.

Saat Redis diaktifkan, pembuatan katalog MCP tingkat aplikasi dan revisi publikasi dikoordinasikan di seluruh replika. Penyebaran Redis Cluster menggunakan kunci katalog dan pembaruan yang aman terhadap slot (slot-safe), sehingga sinkronisasi saat startup dan penyegaran `tools/list_changed` tidak memerlukan tata letak Redis node tunggal.

Setiap pengguna akan diminta untuk melakukan autentikasi dengan login OAuth mereka sendiri saat pertama kali menggunakan server MCP yang mengaktifkan OAuth. Hal ini memastikan bahwa detail koneksi dan autentikasi bersifat unik untuk setiap pengguna, sehingga menjaga keamanan dan privasi di lingkungan multi-pengguna.

#### Waktu OAuth [#oauth-timing]

Penyelesaian OAuth MCP menggunakan batas waktu (timeout) yang dikonfigurasi oleh servernya sendiri, alih-alih menggunakan kembali `initTimeout` pada server MCP. Secara default, LibreChat menunggu hingga 10 menit bagi pengguna untuk menyelesaikan OAuth MCP dan menyimpan status alur tersebut selama 15 menit.

Gunakan variabel lingkungan ini ketika penyedia OAuth atau alur kerja pengguna membutuhkan waktu lebih lama:

```bash filename=".env"
MCP_OAUTH_HANDLING_TIMEOUT=600000
MCP_OAUTH_FLOW_TTL=900000
```

`MCP_OAUTH_FLOW_TTL` dibatasi agar durasinya lebih lama daripada `MCP_OAUTH_HANDLING_TIMEOUT`, sehingga callback yang mendekati batas waktu masih dapat menemukan status alurnya. Jendela polling server-card MCP mengikuti batas waktu penanganan yang telah dikonfigurasi.

![Alur autentikasi OAuth khusus pengguna](/images/agents/mcp_oauth_flow.png)

> Catatan: Token yang ditampilkan selama startup aplikasi hanya untuk inisialisasi tingkat aplikasi dan tidak digunakan untuk koneksi pengguna individu.

Contoh penyegaran token otomatis:

```bash
[MCP][spotify] Access token missing
[MCP][spotify] Attempting to refresh token
[MCP][spotify] Successfully refreshed and stored OAuth tokens
[MCP][spotify] ✓ Initialized
```

#### Praktik Terbaik [#best-practices]

1. **Gunakan OAuth jika tersedia**: Utamakan OAuth daripada kunci API untuk keamanan yang lebih baik
2. **Konfigurasikan timeout yang sesuai**: Gunakan `MCP_OAUTH_HANDLING_TIMEOUT` dan `MCP_OAUTH_FLOW_TTL` untuk jendela penyelesaian OAuth; gunakan `initTimeout` untuk inisialisasi server
3. **Pantau kedaluwarsa token**: Periksa log untuk masalah autentikasi
4. **Rencana untuk autentikasi ulang**: Beberapa penyedia tidak mendukung token penyegaran (refresh tokens)

## Server Transports [#server-transports]

Server MCP dapat dikonfigurasi untuk menggunakan mekanisme transport yang berbeda:

**Server STDIO**

- Berfungsi dengan baik untuk lingkungan lokal pengguna tunggal
- Tidak dapat diskalakan untuk penerapan jarak jauh atau cloud
- SDK MCP yang disertakan membatasi setiap pesan STDIO individu hingga 10 MB. Hasil tunggal yang lebih besar akan menutup transport dengan kesalahan; batas ini terpisah dari ukuran total sesi atau stream.

**Server-Sent Events (SSE) Servers**

- Mekanisme transport jarak jauh namun tidak direkomendasikan untuk lingkungan produksi

**Server HTTP yang Dapat Di-stream**

- Menggunakan HTTP POST untuk mengirim pesan dan mendukung respons streaming
- Beroperasi sebagai proses independen yang dapat menangani beberapa koneksi klien
- Mendukung permintaan dasar maupun streaming melalui Server-Sent Events (SSE)
- Alternatif yang lebih berkinerja tinggi dibandingkan transport HTTP+SSE warisan
- Mendukung konfigurasi server multi-pengguna yang tepat

**Untuk lingkungan produksi**, hanya server MCP dengan ["Streamable HTTP" transports](https://modelcontextprotocol.io/specification/draft/basic/transports/streamable-http) yang direkomendasikan. Tidak seperti SSE yang mempertahankan koneksi yang berjalan lama, Streamable HTTP menawarkan opsi stateless yang lebih cocok untuk penerapan multi-pengguna yang dapat diskalakan.

LibreChat berada di garis depan dalam mengimplementasikan integrasi server MCP yang fleksibel dan dapat diskalakan untuk mendukung beragam skenario penggunaan serta membantu Anda membangun alur kerja AI masa depan.
