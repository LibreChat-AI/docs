MCP (Model Context Protocol) adalah standar terbuka untuk menyediakan alat (tools) kepada model. Sebuah server MCP dapat memberikan model akses ke sistem berkas, browser, basis data, atau API internal perusahaan Anda, dan LibreChat dapat menggunakan server apa pun yang mendukung protokol tersebut. Anda dapat melampirkan server ke obrolan biasa untuk penggunaan cepat, atau menambahkan alatnya ke sebuah agen.

## Gunakan server di chat [#use-a-server-in-chat]

Pada endpoint selain Agents atau Assistants, buka palet **+** pada composer (**Attach and tools**) dan cari di bagian **MCP Servers**. Klik sebuah server untuk mengaktifkannya dalam percakapan. Server tersebut akan muncul sebagai chip pada composer, dan setiap tool yang disediakan server tersebut menjadi tersedia untuk model. Palet tetap terbuka, sehingga Anda dapat mengaktifkan beberapa server sekaligus; klik server yang sama lagi, atau hapus chip-nya, untuk menonaktifkannya. Lihat [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers) untuk opsi lain pada palet.

Palet menampilkan beberapa server sekaligus, dengan titik berwarna untuk setiap status server. **Show All** pada header **MCP Servers** membuka daftar lengkap dengan kolom pencarian dan tiga tampilan: **All**, **Made by you**, dan **Favorites**.

![Dialog Server MCP dibuka dengan Show All, menampilkan server Github berstatus Disconnected dan server Spotify berstatus Needs Auth, dengan filter All, Made by you, dan Favorites](/images/mcp/mcp_servers_catalog.png)

Jika server belum terhubung, mengkliknya akan memulai koneksi alih-alih langsung memilihnya. Server yang memerlukan kredensial Anda sendiri akan membuka dialog untuk memasukkan kredensial tersebut terlebih dahulu; server yang menggunakan OAuth akan mengarahkan Anda ke proses masuk. Setelah terhubung, LibreChat akan memilihnya untuk Anda.

Pilih model yang mendukung tool call, atau model tidak akan pernah memanggil tool dari server. Agents dan Assistants memiliki pengaturan tool tersendiri, sehingga pemilih model disembunyikan pada endpoint tersebut, dan admin dapat menyembunyikan server tertentu dari chat sehingga hanya tersedia untuk agents.

## Menambahkan server ke agen [#add-a-server-to-an-agent]

Di Agent Builder, klik **Add** di samping **Tools** untuk membuka **Tool Library**, lalu filter ke **MCP servers**. Menambahkan server akan menampilkan daftar tool yang disediakannya; pertahankan yang harus dimiliki agent dan hapus sisanya, atau gunakan **Select all** dan **Deselect all**. Server dengan puluhan tool tetap hanya menggunakan satu entri dalam daftar tool agent.

Setiap alat MCP pada agen juga memiliki opsinya sendiri (**Defer loading**, **Programmatic**, **Background**, **Intent label**). Lihat [Agents](/docs/features/agents) untuk mengetahui apa yang diubah oleh opsi-opsi tersebut.

Beberapa server bergantung pada nilai yang hanya ada selama permintaan chat berlangsung, sehingga tools-nya tidak dapat didaftarkan terlebih dahulu. Untuk server seperti itu, Tool Library melampirkan keseluruhan server dan mencatat bahwa tools-nya diselesaikan saat runtime, selama chat berlangsung.

Jika agen diatur untuk menggunakan alat MCP dan tidak ada satu pun alat tersebut yang tersedia saat proses dimulai (server sedang tidak berjalan, atau akses Anda hilang), proses akan berhenti dengan pesan kesalahan yang meminta Anda memeriksa koneksi dan akses Anda, alih-alih menjawab tanpa alat tersebut. Menekan **Stop** selama pemanggilan alat juga akan membatalkan pemanggilan tersebut di server MCP, selama server mendukung pembatalan.

## Status koneksi [#connection-status]

Di palet dan di **MCP Settings**, status ditampilkan sebagai titik berwarna: abu-abu saat server terputus, dan kuning amber saat server memerlukan Anda untuk masuk. Status lengkap dibacakan kepada pembaca layar, dan Tool Library serta daftar **Show All** menuliskannya secara eksplisit di samping setiap server.

- **Terhubung**: siap digunakan.
- **Needs Auth**: server menggunakan OAuth dan Anda belum masuk, atau sesi masuk Anda telah kedaluwarsa.
- **Menghubungkan** / **Menginisialisasi**: sebuah upaya koneksi sedang berlangsung.
- **Terputus** atau **Error**: tidak ada koneksi aktif, atau percobaan terakhir gagal. Gunakan **Connect** untuk mencoba lagi.
- **Sesuai permintaan**: server terhubung secara terpisah untuk setiap permintaan, sehingga tidak ada koneksi tetap yang dapat dilaporkan.
- **Tidak diketahui**: belum ada status yang dikembalikan.

Ketika koneksi gagal, pesan error menjelaskan penyebabnya: server tidak dapat dihubungi, server memerlukan variabel yang belum Anda atur (yang disebutkan namanya dalam pesan), atau server meminta Anda untuk masuk kembali. Perbaiki hal tersebut lalu hubungkan lagi; tidak perlu menghapus dan menambahkan ulang server. Server juga dapat menambah atau menghapus tool saat sedang berjalan, dan LibreChat akan memuat daftar baru tanpa perlu restart.

Koneksi bersifat per pengguna. Token OAuth dan kredensial tersimpan Anda tidak pernah digunakan untuk pengguna lain, dan koneksi yang tidak aktif akan ditutup secara default setelah 15 menit dan dibuka kembali saat Anda menggunakan server berikutnya.

## Masuk dengan OAuth [#sign-in-with-oauth]

Ketika server membutuhkan OAuth, menghubungkannya akan membuka dialog **Connect**. Klik **Continue with OAuth** untuk membuka halaman login penyedia di tab baru, atau gunakan **Copy link** atau **Show QR Code** untuk menyelesaikannya di perangkat lain. Setelah Anda menyetujui akses, tab akan menampilkan **Authentication Successful** dan menutup sendiri, lalu status server berubah menjadi **Connected**.

Selama proses masuk (sign-in) berlangsung, server menampilkan spinner; arahkan kursor ke spinner tersebut untuk membatalkan. Di pengaturan server MCP pada Agent Builder, tombol **Connect** berubah menjadi **Cancel** dengan tujuan yang sama. Anda memiliki waktu 10 menit untuk menyelesaikan proses masuk sebelum percobaan tersebut kedaluwarsa (admin dapat mengubah pengaturan ini).

Jika penyedia menerbitkan refresh token, LibreChat memperbarui akses Anda di latar belakang. Ketika server menolak token Anda di tengah sesi, LibreChat mencoba satu kali refresh dan koneksi ulang sebelum meminta Anda untuk masuk kembali. Penyedia yang tidak menerbitkan refresh token akan meminta Anda untuk masuk kembali ketika token kedaluwarsa.

Secara default, perintah masuk muncul saat pesan Anda dikirim. Admin dapat mengatur beberapa server agar menunggu hingga agen pertama kali memanggil salah satu alat mereka, sehingga Anda hanya diminta untuk masuk ketika server tersebut benar-benar dibutuhkan.

## Kredensial dan variabel [#credentials-and-variables]

Beberapa server memerlukan nilai dari setiap pengguna, seperti API key pribadi atau ID proyek. Saat Anda menghubungkan salah satu server ini, LibreChat meminta nilai-nilai tersebut sebelum melakukan koneksi. Untuk mengubahnya di kemudian hari, gunakan **Configure** pada server di pemilih chat atau di **MCP Settings**. Setiap kolom memiliki **Save** dan **Revoke**. Keduanya akan menutup koneksi Anda saat ini ke server tersebut, sehingga penggunaan berikutnya akan terhubung dengan nilai yang baru, dan revoke juga menonaktifkan server di chat saat ini.

Nilai disimpan per pengguna dan hanya dikirim ke server tempat nilai tersebut dimasukkan.

## Panel Pengaturan MCP [#mcp-settings-panel]

**Pengaturan MCP** di panel samping mencantumkan setiap server yang dapat Anda gunakan, dengan titik status pada ikon masing-masing server. Bergantung pada kondisi server, setiap kartu menawarkan **Connect**, **Reconnect**, **Configure** (untuk variabel Anda), atau **Revoke** (untuk menghapus token OAuth Anda). Server yang diizinkan untuk Anda ubah juga memiliki **Edit**.

## Buat server dari UI [#create-a-server-from-the-ui]

Jika peran Anda mengizinkannya, klik **Add MCP** (tombol **+**) di **MCP Settings** untuk mendaftarkan server jarak jauh tanpa menyentuh `librechat.yaml` atau memulai ulang.

<Steps>
<Step>
### Jelaskan server [#describe-the-server]

Masukkan **Name**, **Description** (opsional), dan ikon jika Anda menginginkannya. Isi **MCP Server URL** dan pilih **Transport**: **Streamable HTTPS** atau **SSE**.
</Step>
<Step>
### Pilih autentikasi [#choose-authentication]

Di bagian **Authentication**, pilih salah satu:

- **None (Auto-detect)**: LibreChat memeriksa server dan beralih ke OAuth jika server memintanya.
- **API Key**: masukkan satu kunci bersama, atau centang **Each user provides their own key** agar setiap pengguna memasukkan kuncinya sendiri melalui **Configure**. Pilih **Header Format**: **Bearer**, **Basic**, atau **Custom** dengan nama header Anda sendiri.
- **OAuth**: masukkan **Client ID**, **Client Secret**, **Authorization URL**, **Token URL**, dan **Scope**. Kosongkan kolom klien jika penyedia mendukung pendaftaran klien dinamis. **Token Exchange Method** secara default adalah **Auto**, yang menggunakan metode yang diiklankan oleh penyedia dan beralih ke header otorisasi Basic sebagai cadangan; pilih **Default (POST request)** atau **Basic authorization header** untuk memaksa salah satu metode.
- **On-Behalf-Of (OBO)**: hanya ditampilkan jika admin telah memberi Anda izin tersebut, dan hanya berfungsi ketika LibreChat masuk pengguna dengan OpenID Connect (misalnya Entra ID). Masukkan scope yang ingin diminta; LibreChat menukar token OpenID Anda dengan token yang di-scope untuk server MCP.
</Step>
<Step>
### Buat itu [#create-it]

Centang **Saya percaya aplikasi ini** lalu klik **Create**. Server langsung tersedia. Untuk server OAuth, dialog berikutnya menampilkan **Redirect URI** yang perlu didaftarkan ke penyedia OAuth Anda, dan server tetap tidak terhubung hingga Anda masuk sekali.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="Dialog Add MCP Server dengan nama dan URL terisi, Transport diatur ke Streamable HTTPS, dan Authentication diatur ke API Key dengan Each user provides their own key dicentang"
/>

Server yang dibuat dengan cara ini hanya dapat mengakses URL jarak jauh; server `stdio` lokal harus didefinisikan di `librechat.yaml`. Server tersebut juga tidak dapat menggunakan variabel lingkungan server ataupun placeholder profil pengguna: nilai seperti `${API_TOKEN}` atau `{{LIBRECHAT_USER_EMAIL}}` dalam header-nya akan dihapus, karena server bersama jika tidak akan menerima nilai tersebut. Jika Anda mengubah URL atau autentikasi server di kemudian hari, pengguna yang sebelumnya memasukkan kunci mereka sendiri harus memasukkannya kembali, dan pengguna OAuth harus masuk kembali. Ketika Anda mengubah URL atau endpoint OAuth dari server yang memiliki client secret tersimpan, Anda juga harus memasukkan kembali secret tersebut. Jika server dengan API key yang dibuat menggunakan versi lama macet di status **Needs Auth**, buka server tersebut dengan **Edit** dan simpan satu kali.

## Berbagi server [#share-a-server]

Server yang dibuat di UI menjadi milik pembuatnya. Pemilik dapat membagikannya dari dialog **Edit** kepada pengguna, grup, peran, atau semua orang tertentu, sebagai viewer (dapat melihat dan menggunakannya), editor (dapat juga mengubahnya), atau owner. Server yang didefinisikan dalam `librechat.yaml` tersedia untuk semua orang yang memiliki izin untuk menggunakan MCP. Lihat [Access Control](/docs/features/access_control) untuk cara tingkat izin tersebut dikombinasikan.

## Instruksi server [#server-instructions]

Seorang admin dapat melampirkan instruksi ke sebuah server, baik instruksi bawaan milik server tersebut maupun teks kustom. Ketika sebuah percakapan atau agen memiliki alat (tools) dari server tersebut, instruksi akan ditambahkan ke konteks model, yang membantu untuk server yang alatnya hanya masuk akal digunakan dalam urutan tertentu.

## MCP Apps [#mcp-apps]

Beberapa server mengembalikan tampilan interaktif bersama hasil alat. Saat MCP Apps diaktifkan, panggilan alat menampilkan tombol **Open app** yang memuat tampilan tersebut dalam frame yang di-sandbox, dan **Close app** untuk menyembunyikannya kembali. Hanya beberapa aplikasi yang dapat dibuka pada saat yang sama; jika Anda mencapai batasnya, tutup salah satunya terlebih dahulu.

Aplikasi tidak dapat bertindak sendiri. Ketika aplikasi ingin menjalankan alat, Anda akan melihat **Run tool from app?**, dan ketika ingin mengirim pesan, **Send message from app?**. Tidak ada yang terjadi sampai Anda menyetujuinya. Mengirim pesan memulai respons model dalam percakapan saat ini, sehingga agen yang dipilih beserta alat-alatnya mungkin digunakan. Aplikasi tidak ditampilkan dalam percakapan bersama.

## Pengaturan [#setup]

MCP memerlukan setidaknya satu server. Admin mendefinisikan server di bawah `mcpServers` dalam `librechat.yaml`, yang memerlukan restart untuk diterapkan, dan pengguna dengan izin dapat menambahkan server remote dari **MCP Settings**. Lihat [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers) untuk opsi server, URL callback OAuth, dan transport, [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) untuk domain yang diizinkan dan MCP Apps, [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox) untuk batasan aplikasi, dan [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) untuk siapa yang dapat menggunakan, membuat, dan membagikan server. Panduan pengaturan untuk server tertentu tersedia di bawah [MCP Servers](/docs/mcp_servers), dan [Agent Plugins](/docs/features/agent_plugins) membahas cara mengemas server MCP bersama skill.
