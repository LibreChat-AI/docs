子代理（subagent）是智能体在自身工作过程中启动的子运行。子代理拥有一个干净的上下文窗口，负责完成任务（如搜索、读取文件、调用工具），然后只返回其结果。父代理的上下文因此保持精简，这一点很重要，因为中间过程可能产生大量工具输出，而父代理并不需要看到这些内容。

当任务可以拆分为多个各自产生大量中间输出的部分时,例如同时研究多个主题、审阅一组文件,或在给出最终答案前运行工具密集型的检查,就应当使用子代理。

## 为智能体开启此功能 [#turn-it-on-for-an-agent]

<Steps>
  <Step>
    在 Agent Builder 中,点击 **Tools** 旁边的 **Add**,然后从 Tool Library 中添加 **Subagents**。点击 **Subagents** 卡片上的齿轮图标,打开其设置。
  </Step>
  <Step>
    请确保 **Subagents** 开关(标记为 Beta)处于开启状态。**Allow self-spawn** 默认开启:智能体可以为某个子任务启动一个自身的新副本。
  </Step>
  <Step>
    可选地,在 **Additional subagents** 下,点击 **Add subagent**,让其能够委派任务给你可见的其他智能体。然后保存。
  </Step>
</Steps>

当智能体已经配置好、只需要一个干净的会话状态来完成任务时,自我派生(self-spawn)就已经足够。当某个子任务需要不同的模型、不同的指令或不同的工具时,再添加其他智能体,例如用一个廉价快速的模型来执行搜索,或用一个带有严格检查清单的审查智能体。父智能体通过名称和描述来选择这些智能体,因此请为每个智能体编写说明其用途的描述。

子代理只有在父代理实际选中它们时才会被加载,因此列出多个子代理在其中一个运行之前不会产生任何开销。默认情况下,一个代理最多可以列出 10 个子代理。如果你关闭自我派生(self-spawn)且不列出任何代理,那么就没有可派生的对象,构建器会明确提示你这一点。

### 与子代理共享文件 [#sharing-files-with-subagents]

如果管理员已启用此功能,会显示一个**与子代理共享文件**开关。开启后,当前消息中附加的文件可供父代理启动的子代理使用。子代理在沙盒中创建的文件仅对其自身可见,直到它选择将哪些版本交还。

## 你在聊天中看到的内容 [#what-you-see-in-the-chat]

每个子代理（subagent）的运行都会在父级回复中以一行紧凑的记录显示，包含子代理的名称和状态：运行中显示为**正在运行代理**，完成后显示为**已运行代理**。点开该记录即可在活动侧边面板中跟踪子代理的执行过程；也可以直接忽略它，阅读父级的回答。被取消的运行显示为**代理已停止**，运行失败则显示为**代理失败**。以后台方式启动的子代理（参见下文）则会归入**代理活动**区块中显示。

## 运行机制 [#how-it-behaves]

- 子代理以自己的上下文启动。它不会继承父代理的对话历史,也不会继承父代理通过工具搜索发现的工具;它只获得父代理为其编写的任务。
- 子运行（child runs）产生的 token 用量会计入您的余额。在父运行仍在进行时完成的子运行，其用量会计入父运行的总计；而在之后才完成的分离子运行（detached children），则会单独记录。
- 无法再访问的子代理将被跳过。您无法添加自己看不到的代理。在子代理启动时,系统会再次检查其访问权限和已保存的配置;如果二者在运行期间发生了变化,该子代理将不会运行。
- 每个子代理都保留各自的模型、指令、工具、MCP 凭据、技能、文件和记忆。
- 子代理同样受步数上限限制,因此较低的 **Max Agent Steps** 值也会限制子代理能够执行的操作数量。
- 子代理可以启动自己的子代理,最多可嵌套 5 层。

## 已保存的 Agent 团队 [#saved-agent-teams]

父代理还可以启动已保存的团队:将多个代理组合为一个小型工作流,例如由研究员收集结果并交给审阅者。团队作为一个独立的隔离子进程运行,只有结果代理的回答会返回给父代理。一个团队最多可包含 32 名成员。如果任何成员缺失或您无权查看,则会跳过整个团队,而不会部分运行。

团队通过 API 定义,而不是在 Agent Builder 中定义。当你编辑智能体的其他子智能体设置时,Builder 会保持团队配置不变。定义格式请参见 [agents 端点配置](/docs/configuration/librechat_yaml/object_structure/agents#subagents)。

## 分离式子代理线程 (Detached Subagent Threads) [#detached-subagent-threads]

如果您的管理员已启用后台执行功能,父级可以启动子代理并继续工作,无需等待其完成。子代理的工作内容会被保存为只读的会话线程,您可以从父级的活动面板中访问它;该线程不会出现在您的聊天列表或搜索结果中。过长的历史记录会被裁剪,当较早的活动内容未显示时,面板会予以说明。

### 控制正在运行的子进程 [#control-a-running-child]

在分离的子任务运行期间，请在活动面板的输入框中输入内容来引导它：

- **Steer** 会在子任务的下一个安全节点添加你的指导。这是默认选项。
- **Queue** 会将其保留，留待子级的下一轮对话使用。
- **Interrupt** 会停止当前步骤并应用指导。
- 当输入框为空时,发送按钮会变为 **取消任务**。

每条消息都会显示是否已应用。排队中的指导内容可在子任务领取之前点击**撤回**取消。指导内容的大小限制为 4 KB。当直接子任务已完成后,点击**在新聊天中继续**即可将其对话复制到一个普通聊天中继续工作;原始会话线程将保持只读。

共享对话仅显示共享中包含的活动内容，不提供任何控件。

### 自动继续父级内容 [#automatic-parent-continuation]

当分离的子任务完成时,LibreChat 默认会在同一分支上唤醒父代理,并将结果以可折叠的任务卡片形式展示。如果父代理仍在忙碌,唤醒操作会等待其空闲后再进行。已取消的子任务不会唤醒父代理,而且此功能仅适用于已保存的代理,不适用于从模型规范(Model Specs)创建的代理。管理员可以关闭此功能,关闭后父代理需要自行检查子任务的状态。

通过 [Agents API](/docs/features/agents_api#event-driven-child-agents) 由外部系统驱动的子代理，同样会以一行的形式显示在父消息下方，点击后打开相同的面板。

## Subagents 与 Handoffs 的比较 [#subagents-compared-with-handoffs]

子代理会将控制权交回父级:父级提问,子代理回答,然后由父级撰写回复。[交接](/docs/features/agents#working-with-other-agents)会将对话转交给另一个代理,由该代理自行回复。需要完成子任务时使用子代理;需要将请求路由给专家时使用交接。

## 设置 [#setup]

默认情况下，子代理（Subagents）即可使用。管理员可以通过 `subagents` 能力将其关闭，通过 `maxSubagents` 提高每个代理的数量上限，启用文件共享，并通过可选的 `run_in_background` 能力允许分离的子代理，所有这些设置都位于[代理端点配置](/docs/configuration/librechat_yaml/object_structure/agents#subagents)中。自动的父代理继续运行由 [`backgroundTasks`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) 控制。也可以为没有已保存父代理的模型规格（model spec）启用子代理；请参阅 [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs#subagents)。
