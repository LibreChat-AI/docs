Artifacts를 사용하면 LibreChat 에이전트가 생성된 React 컴포넌트, HTML, SVG, Markdown 및 Mermaid 콘텐츠를 전용 대화형 뷰에서 렌더링할 수 있습니다. 사용자는 생성된 콘텐츠를 채팅 응답과 분리하여 유지하면서 대화를 계속하여 결과를 수정할 수 있습니다.

## 에이전트에 Artifacts 활성화하기 [#enable-artifacts-for-an-agent]

1. [Agent](/docs/features/agents)를 생성하거나 편집하세요.
2. **Add tools**를 열고 **Artifacts**를 선택하세요.
3. 아티팩트(artifact) 지침 모드를 선택하세요.
4. 에이전트를 저장하세요.

사용 가능한 모드는 다음과 같습니다:

- **Normal**: LibreChat의 React, HTML, SVG, Markdown 및 Mermaid 아티팩트에 대한 표준 지침을 주입합니다.
- **shadcn/ui**: 더 세련된 생성형 인터페이스를 위한 shadcn/ui 컴포넌트 라이브러리 가이드를 추가합니다.
- **Custom**: 아티팩트 렌더링을 활성화 상태로 유지하지만, 내장된 지침을 주입하지 않습니다. 에이전트의 지침에 원하는 전체 아티팩트 동작을 입력하세요.

각 에이전트는 목적에 맞는 모드와 지침을 사용할 수 있으므로 에이전트 수준의 구성이 권장됩니다. 관리자는 `artifacts` [에이전트 기능](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)을 제거하여 Artifacts를 숨길 수 있습니다.

## Artifacts 지원 내용 [#what-artifacts-support]

- 대화형 React 컴포넌트 및 HTML 페이지
- SVG 이미지 및 Mermaid 다이어그램
- 렌더링된 Markdown 문서
- 후속 메시지를 통한 반복 업데이트
- 구성된 에이전트에서 사용할 수 있는 모든 모델

## 미리보기 및 내보내기 [#preview-and-export]

렌더링된 아티팩트 미리보기의 전체 화면 컨트롤을 사용하여 브라우저 전체 화면으로 확장할 수 있습니다. 이 컨트롤은 브라우저 Fullscreen API 상태를 따르며, Escape 키나 브라우저 컨트롤을 통해 정상적으로 종료할 수 있고, 전체 화면을 사용할 수 없을 때는 숨겨집니다.

데스크톱에서는 아티팩트 패널 헤더에서 **Open in new window**를 선택하여 패널을 별도의 브라우저 창으로 이동할 수 있으며, 예를 들어 이를 두 번째 화면에 배치할 수 있습니다. 아티팩트는 응답이 스트리밍됨에 따라 계속 업데이트되며, 저장되지 않은 코드 수정 사항과 선택된 탭은 그대로 유지됩니다. 패널을 채팅으로 되돌리려면 **Dock back to panel**을 선택하거나 창을 닫으십시오. LibreChat은 다음 사용을 위해 창의 크기와 위치를 기억합니다.

- 채팅 탭을 열어 두세요: 창은 채팅 탭에 의해 제어되며, 해당 탭을 닫으면 창도 함께 닫힙니다.
- 브라우저가 창을 차단하는 경우, LibreChat은 알림을 표시합니다. 해당 사이트에 대한 팝업을 허용하고 다시 시도하세요.
- 좁은(모바일) 레이아웃에서는 버튼이 표시되지 않습니다.

관리자는 [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking)를 설정하여 버튼을 제거하고 사이드 패널에 아티팩트를 유지할 수 있습니다.

Mermaid 다이어그램은 아티팩트 패널에서 열 수 있는 간결한 인라인 카드로 표시됩니다. 인라인 카드나 패널에서 다이어그램을 SVG 또는 PNG로 내보낼 수 있습니다. Mermaid 미리보기는 Sandpack 번들러를 로드하는 대신 직접 렌더링되며, PNG 내보내기 시에는 브라우저가 너무 큰 다이어그램으로 인해 문제가 발생하지 않도록 제한된 캔버스 크기가 적용됩니다.

모델이 작성한 아티팩트는 내보낸 콘텐츠와 일치하는 확장자를 가진 제목 또는 Markdown 헤딩 아래에 다운로드됩니다. 편집되지 않은 파일 기반 아티팩트는 원본 파일명과 형식을 사용할 수 있는 경우 전체 원본을 다운로드합니다. 편집되었거나 캐시된 미리보기 콘텐츠를 다운로드할 때는 원본 파일과 혼동되지 않도록 `.preview` 식별자가 사용됩니다.

## Content-Security-Policy

Artifacts 패널에서 생성된 HTML 앱을 로드하려면 웹 서버의 Content-Security-Policy를 업데이트하여 `frame-src 'self' https://*.codesandbox.io`를 포함해야 할 수도 있습니다. 이는 [sandpack](https://sandpack.codesandbox.io/) 라이브러리의 의존성입니다.

## Sandpack Bundler 자체 호스팅 [#self-hosting-the-sandpack-bundler]

LibreChat의 Artifacts는 CodeSandbox의 Sandpack 라이브러리를 사용하여 HTML/JS 코드를 안전하게 렌더링합니다. 기본적으로 LibreChat은 CodeSandbox의 공개 CDN에 연결되며, 이 과정에서 사용량에 대한 원격 분석(telemetry) 데이터가 전송될 수 있습니다.

향상된 개인정보 보호, 보안 규정 준수 또는 격리된 네트워크 환경을 위해 [번들러를 자체 호스팅](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)할 수 있습니다.

### Sandpack Bundler를 직접 호스팅하는 이유는 무엇인가요? [#why-self-host-the-sandpack-bundler]

[Self-hosting the bundler](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)를 직접 호스팅하면 다음과 같은 몇 가지 이점이 있습니다:

- **개인정보 보호 및 보안**: 코드 실행을 자체 인프라 내에서 유지하세요
- **신뢰성**: 외부 서비스에 대한 의존성 제거
- **성능**: 네트워크 내에서 번들러를 호스팅하여 지연 시간을 줄이십시오.
- **준수(Compliance)**: 조직의 데이터 처리 요구 사항 충족
- **제어(Control)**: 특정 요구 사항에 맞게 구성하고 사용자 지정하세요

### 구성 [#configuration]

자체 호스팅 번들러를 설정한 후, 환경 변수를 설정하여 LibreChat이 이를 사용하도록 구성하기만 하면 됩니다:

```bash
# `.env` file
SANDPACK_BUNDLER_URL=http://your-bundler-url
```

### 일반적인 고려 사항 [#general-considerations]

번들러를 직접 호스팅하면 몇 가지 추가적인 오버헤드가 발생합니다:

- **CORS Configuration**: 교차 출처 리소스 공유(CORS) 정책을 관리해야 합니다.
- **보안 관리**: 귀하는 번들러 서비스의 보안에 대한 책임을 지게 됩니다.
- **유지보수**: 업데이트 및 패치는 수동으로 적용해야 합니다.
- **리소스 요구 사항**: 번들러를 호스팅하려면 추가 서버 리소스가 필요합니다.

자체 호스팅 번들러를 설정하고 유지 관리하는 방법에 대한 자세한 지침은 Sandpack에서 원격 분석(telemetry)을 제거하는 등 LibreChat 배포에 맞게 조정된 [forked CodeSandbox repository](https://github.com/LibreChat-AI/codesandbox-client)를 참조하세요.
