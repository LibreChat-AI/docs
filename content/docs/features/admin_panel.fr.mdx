Le Panneau d'administration est une application web distincte permettant de gérer une instance LibreChat depuis le navigateur. Vous l'utilisez pour gérer les utilisateurs, les groupes et les rôles, définir ce que chaque rôle est autorisé à faire, attribuer des pouvoirs d'administrateur et modifier la configuration (pour tout le monde, ou uniquement pour un rôle ou un groupe spécifique) sans modifier `librechat.yaml` ni redémarrer le service.

Il s'agit d'un service à part entière, doté de sa propre URL, développé dans le dépôt [LibreChat-AI/admin-panel](https://github.com/LibreChat-AI/admin-panel). Il ne conserve aucune donnée propre : chaque modification passe par l'API d'administration de LibreChat et est enregistrée dans la base de données de LibreChat.

## Connexion [#signing-in]

Vous vous connectez avec un compte LibreChat, soit avec son adresse e-mail et son mot de passe, soit via une authentification unique (SSO) configurée sur l'instance, comme OpenID Connect ou Google. Le compte doit disposer du rôle `ADMIN`, ou de la capacité `access:admin` qui lui est accordée (directement, ou via l'un de ses groupes ou de son rôle). LibreChat vérifie cela à chaque requête : le panneau ne peut donc pas s'octroyer plus d'accès que le compte n'en possède. Les sessions se terminent après 30 minutes d'inactivité par défaut. Avec le SSO, le panneau renouvelle votre session LibreChat en arrière-plan, et à chaque renouvellement, il vérifie de nouveau que le compte n'est pas banni et dispose toujours de l'accès administrateur ; la perte de cet accès met fin à la session du panneau.

Une fois qu'une URL de panneau d'administration est configurée, les utilisateurs disposant d'un accès administrateur trouvent également un lien **Admin Panel** dans LibreChat, sous **Settings > General**. Les autres utilisateurs ne le voient pas.

## Ce que vous pouvez faire [#what-you-can-do]

Les sections de la barre latérale correspondent aux principales fonctions :

- **Utilisateurs** : listez et recherchez tous les comptes de l'instance, filtrez par rôle et attribuez ou retirez des rôles aux utilisateurs. (Le panneau propose une action de suppression, mais la version actuelle de LibreChat n'accepte pas encore les suppressions via l'API d'administration ; utilisez plutôt le script de suppression d'utilisateur.)
- **Accès** : créez des rôles personnalisés au-delà de `USER` et `ADMIN`, modifiez les autorisations de fonctionnalités de chaque rôle, puis créez des groupes et gérez leurs membres. Les groupes et rôles créés ici peuvent être sélectionnés dans les boîtes de dialogue de partage de LibreChat.
- **Configuration** : consultez et modifiez les paramètres de LibreChat sous forme de formulaires. Les formulaires sont générés à partir du schéma de configuration propre à LibreChat, de sorte que les nouveaux paramètres apparaissent sans qu'il soit nécessaire de mettre à jour le panneau.
- **Subventions** : accordez des capacités d'administration individuelles, telles que la gestion des utilisateurs ou la modification d'une section de la configuration, à un utilisateur, un groupe ou un rôle, sans en faire un administrateur complet.

Ce que chaque personne voit dans le panneau dépend de ses capacités. Une personne autorisée à gérer uniquement la section `interface`, par exemple, ne voit que cette section. Une personne qui peut seulement lire les rôles voit les rôles mais ne peut pas les modifier ; une personne ne disposant d'aucune des capacités d'accès obtient une page d'accès refusé pour cette section.

## Configuration pour des rôles et groupes spécifiques [#configuration-for-specific-roles-and-groups]

Au-delà du profil de base, qui s'applique à tous, vous pouvez enregistrer un profil de surcharges pour un seul rôle, groupe ou utilisateur. Seuls les paramètres que vous modifiez y sont stockés ; tout le reste est hérité. Chaque profil possède une priorité (par défaut 10 pour les profils de rôle, 20 pour les groupes et 100 pour les utilisateurs). Lorsque LibreChat construit la configuration d'un utilisateur, il part de `librechat.yaml` et du profil de base, puis applique les profils correspondant à cet utilisateur, de la priorité la plus basse à la plus haute. Ainsi, un profil utilisateur l'emporte par défaut sur un profil de groupe ou de rôle. C'est de cette manière qu'un groupe de recherche peut disposer de points de terminaison supplémentaires, ou que des prestataires externes peuvent bénéficier d'une interface plus restrictive, sans avoir à exécuter une seconde instance.

Quelques éléments à connaître lors de la modification de la configuration :

- Les modifications sont vérifiées selon les mêmes règles que `librechat.yaml`. Une modification qui rendrait la configuration invalide est refusée et rien n'est enregistré. Si une mise à niveau rend invalide une valeur enregistrée antérieurement, LibreChat ignore ce champ, revient à la valeur sous-jacente et journalise un avertissement ; vérifiez donc les journaux après la mise à niveau.
- Les clés API et autres secrets que vous saisissez (par exemple pour la recherche web, la synthèse vocale, l'OCR, Langfuse ou les endpoints personnalisés) sont stockés chiffrés et ne sont affichés que masqués par la suite. Si vous modifiez l'adresse vers laquelle une clé enregistrée est envoyée, comme un serveur ou une URL de base, vous devez saisir à nouveau la clé.
- `${ENV_VAR}` ne sont acceptées que pour les variables que LibreChat connaît déjà ou que l'opérateur a autorisées.
- Certains paramètres restent uniquement dans `librechat.yaml` : les serveurs MCP qui exécutent un processus local (`type: stdio`, ou `command`, `args`, `env`) et les en-têtes de la passerelle Langfuse. Le panneau ne peut pas les ajouter, les modifier ni les supprimer. Les serveurs MCP distants peuvent être gérés normalement.

Les permissions de fonctionnalités ne sont pas des substitutions : les interrupteurs qui déterminent si un rôle peut utiliser ou partager des agents, des prompts et le reste se modifient directement sur le rôle lui-même, sous **Accès**. Consultez [Contrôle d'accès](/docs/features/access_control) pour comprendre comment les rôles, les groupes et les capacités s'articulent. L'utilisation par agent est disponible sur le tableau de bord séparé [Insights](/docs/features/insights), dans LibreChat.

## Configuration [#setup]

Le panneau est livré sous forme de service `admin-panel` dans les fichiers `docker-compose.yml` et `deploy-compose.yml` de LibreChat, et il ne démarrera pas tant que vous n'aurez pas défini `ADMIN_PANEL_SESSION_SECRET` dans `.env`. Il nécessite LibreChat v0.8.5 ou une version ultérieure. Les ports, l'hébergement sur son propre domaine, les redirections SSO, toutes les variables d'environnement ainsi que l'API d'administration utilisée par le panneau sont décrits dans [Configuration du panneau d'administration](/docs/configuration/admin_panel).
