Un sous-agent est une exécution enfant qu'un agent lance au milieu de son propre travail. L'enfant reçoit une fenêtre de contexte vierge, accomplit la tâche (recherche, lecture de fichiers, appels d'outils) et ne renvoie que son résultat. Le contexte du parent reste ainsi réduit, ce qui compte lorsque le travail intermédiaire produit des pages de sortie d'outils que le parent n'a jamais besoin de voir.

Faites appel aux sous-agents lorsqu'une tâche se divise en parties qui génèrent chacune beaucoup de bruit : recherche sur plusieurs sujets, revue d'un ensemble de fichiers, ou exécution d'une vérification gourmande en outils avant la réponse principale.

## Activez-le pour un agent [#turn-it-on-for-an-agent]

<Steps>
  <Step>
    Dans le Constructeur d'agents, cliquez sur **Ajouter** à côté de **Tools** et ajoutez **Subagents** depuis la bibliothèque d'outils. Cliquez sur l'engrenage de la carte **Subagents** pour ouvrir ses paramètres.
  </Step>
  <Step>
    Assurez-vous que le commutateur **Subagents** (marqué Bêta) est activé. **Allow self-spawn** est activé par défaut : l'agent peut lancer une nouvelle copie de lui-même pour une sous-tâche.
  </Step>
  <Step>
    Facultativement, sous **Sous-agents supplémentaires**, cliquez sur **Ajouter un sous-agent** pour lui permettre de déléguer des tâches à d'autres agents que vous pouvez voir. Enregistrez ensuite.
  </Step>
</Steps>

L'auto-génération suffit lorsque l'agent est déjà configuré pour la tâche et n'a besoin que d'un contexte vierge. Ajoutez d'autres agents lorsqu'une sous-tâche nécessite un modèle, des instructions ou des outils différents, par exemple un modèle rapide et peu coûteux pour les recherches, ou un agent relecteur doté d'une liste de contrôle stricte. Le parent choisit parmi eux par leur nom et leur description. Donnez donc à chacun une description qui indique à quoi il sert.

Les enfants ne sont chargés que lorsque le parent les sélectionne effectivement. Lister plusieurs enfants ne coûte donc rien tant qu'aucun n'est exécuté. Un agent peut lister jusqu'à 10 sous-agents par défaut. Si vous désactivez l'auto-génération (self-spawn) et ne listez aucun agent, il n'y a rien à générer, et le constructeur vous le signale.

### Partage de fichiers avec les sous-agents [#sharing-files-with-subagents]

Si votre administrateur l'a activé, un interrupteur **Partager les fichiers avec les sous-agents** apparaît. Lorsqu'il est activé, les fichiers joints au message en cours sont accessibles aux sous-agents que l'agent parent démarre. Les fichiers qu'un sous-agent crée dans le bac à sable restent privés pour celui-ci jusqu'à ce qu'il choisisse les versions à restituer.

## Ce que vous voyez dans le chat [#what-you-see-in-the-chat]

Chaque exécution d'un sous-agent apparaît dans la réponse du parent sous la forme d'une ligne compacte indiquant le nom et le statut de l'enfant : **Running agent** pendant son travail, puis **Ran agent** une fois terminée. Ouvrez-la pour suivre l'enfant dans le panneau latéral d'activité, ou ignorez-la et lisez la réponse du parent. Une exécution annulée affiche **Agent stopped**, et une exécution en échec affiche **Agent failed**. Les enfants lancés en arrière-plan (voir ci-dessous) sont regroupés dans un bloc **Agent activity** à la place.

## Comment il se comporte [#how-it-behaves]

- L'enfant démarre avec son propre contexte. Il n'hérite ni de l'historique de conversation du parent, ni des outils que le parent a découverts avec la recherche d'outils ; il reçoit uniquement la tâche que le parent lui rédige.
- Les jetons consommés par les exécutions enfants sont déduits de votre solde. Les enfants qui se terminent pendant que le parent est encore en cours d'exécution sont ajoutés aux totaux du parent ; les enfants détachés qui se terminent plus tard sont enregistrés séparément.
- Un agent enfant auquel vous n'avez plus accès est ignoré. Vous ne pouvez pas ajouter un agent que vous ne voyez pas. L'accès et la configuration enregistrée de l'enfant sont vérifiés à nouveau au moment de son démarrage ; si l'un des deux a changé pendant l'exécution, l'enfant ne s'exécute pas.
- Chaque enfant conserve son propre modèle, ses propres instructions, ses outils, ses identifiants MCP, ses compétences, ses fichiers et sa mémoire.
- La limite d'étapes s'applique également aux sous-agents. Ainsi, une valeur faible de **Max Agent Steps** limite aussi la quantité d'actions qu'un sous-agent peut effectuer.
- Les sous-agents peuvent lancer leurs propres sous-agents, sur jusqu'à 5 niveaux de profondeur.

## Équipes d'agents enregistrées [#saved-agent-teams]

Un parent peut également démarrer une équipe enregistrée : plusieurs agents reliés entre eux comme un petit workflow unique, par exemple un chercheur dont les résultats sont transmis à un relecteur. L'équipe s'exécute comme un enfant isolé unique, et seule la réponse de l'agent de résultat est renvoyée au parent. Une équipe peut compter jusqu'à 32 membres. Si un membre est absent ou si vous ne pouvez pas le voir, l'équipe entière est ignorée plutôt que d'être exécutée partiellement.

Les équipes sont définies via l'API, et non dans l'Agent Builder. Le builder conserve une équipe intacte lorsque vous modifiez les autres paramètres de sous-agent de l'agent. Le format de définition est décrit dans la [configuration de l'endpoint agents](/docs/configuration/librechat_yaml/object_structure/agents#subagents).

## Threads de sous-agents détachés [#detached-subagent-threads]

Si votre administrateur a activé l'exécution en arrière-plan, le parent peut lancer un sous-agent et poursuivre son travail sans attendre sa fin. Le travail de l'enfant est enregistré sous forme de fil en lecture seule, auquel vous accédez depuis le panneau d'activité du parent ; il n'apparaît ni dans votre liste de conversations ni dans la recherche. Les historiques très longs sont tronqués, et le panneau l'indique lorsque l'activité antérieure n'est pas affichée.

### Contrôler un enfant en cours d'exécution [#control-a-running-child]

Pendant l'exécution d'un enfant détaché, saisissez dans le compositeur du panneau d'activité pour le guider :

- **Steer** ajoute vos instructions au prochain point sûr de l'enfant. C'est le comportement par défaut.
- **Queue** le conserve pour le prochain tour de l'enfant.
- **Interrompre** arrête l'étape en cours et applique les instructions.
- Avec rien de saisi, le bouton d'envoi devient **Annuler la tâche**.

Chaque message indique s'il a été appliqué. Les consignes en file d'attente peuvent être retirées avec **Withdraw** avant que l'enfant ne les prenne en compte. Les consignes sont limitées à 4 Ko. Lorsqu'un enfant direct a terminé, **Continue in a new chat** copie sa conversation dans un chat normal dans lequel vous pouvez continuer à travailler ; le fil d'origine reste en lecture seule.

Les conversations partagées n'affichent que l'activité incluse dans le partage, sans aucun contrôle.

### Continuation automatique du parent [#automatic-parent-continuation]

Lorsqu'un enfant détaché se termine, LibreChat réveille par défaut l'agent parent sur la même branche avec le résultat, affiché sous forme de carte de tâche repliable. Si le parent est encore occupé, le réveil attend qu'il se libère. Les enfants annulés ne réveillent pas le parent, et cela ne fonctionne que pour les agents enregistrés, pas pour ceux créés à partir d'une spécification de modèle. Votre administrateur peut désactiver cette fonctionnalité, auquel cas le parent doit vérifier lui-même l'état de l'enfant.

Les sous-agents pilotés par des systèmes externes via l'[API Agents](/docs/features/agents_api#event-driven-child-agents) apparaissent de la même manière, sous la forme d'une ligne sous le message parent qui ouvre le même panneau.

## Sous-agents comparés aux transferts [#subagents-compared-with-handoffs]

Un sous-agent rend le contrôle au parent : le parent pose la question, l'enfant répond, et le parent rédige la réponse. Un [handoff](/docs/features/agents#working-with-other-agents) transmet la conversation à un autre agent, qui répond alors lui-même. Utilisez un sous-agent pour une sous-tâche, et un handoff pour orienter la requête vers un spécialiste.

## Configuration [#setup]

Les sous-agents sont disponibles par défaut. Les administrateurs peuvent les désactiver avec la capacité `subagents`, augmenter la limite par agent avec `maxSubagents`, activer le partage de fichiers et autoriser les enfants détachés grâce à la capacité facultative `run_in_background`, le tout dans la [configuration du point de terminaison des agents](/docs/configuration/librechat_yaml/object_structure/agents#subagents). La poursuite automatique du parent est contrôlée par [`backgroundTasks`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks). Ils peuvent également être activés pour une spécification de modèle (Model Specs) sans agent parent enregistré ; voir [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs#subagents).
