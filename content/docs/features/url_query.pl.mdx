Możesz dodać parametry zapytania do adresu URL czatu, aby wybrać endpoint i model, załadować agenta lub specyfikację modelu (Model Spec), wypełnić prompt lub zmienić ustawienia modelu, zanim rozpocznie się czat. Dzięki temu możesz utworzyć zakładkę, skrót do uruchamiania (Raycast, Alfred, słowo kluczowe w przeglądarce) lub link z innej aplikacji, który przeniesie użytkownika od razu do odpowiedniej konfiguracji.

```
https://chat.example.com/c/new?endpoint=anthropic&model=claude-sonnet-4-5&prompt=Summarize%20this%20article
```

Parametry działają w nowym czacie (`/c/new`) oraz w istniejącym (`/c/<conversation-id>`). Po odczytaniu ich przez LibreChat są usuwane z paska adresu, więc przeładowanie strony nie spowoduje ich ponownego zastosowania.

## Wybierz endpoint i model [#pick-the-endpoint-and-model]

`endpoint` i `model` razem tworzą najbardziej przewidywalną kombinację.

- `endpoint` samo w sobie przełącza na ten endpoint i używa modelu, który ostatnio wybrano w tym endpoincie, albo pierwszego modelu z jego listy.
- `model` samo w sobie przełącza model w obrębie bieżącego endpointu, o ile dany endpoint go obsługuje.

Wbudowane wartości endpointów to `openAI`, `azureOpenAI`, `google`, `anthropic`, `bedrock`, `agents`, `assistants` i `azureAssistants`. Dla [niestandardowego endpointu](/docs/quick_start/custom_endpoints) użyj nazwy z Twojej konfiguracji; dopasowanie nie uwzględnia wielkości liter, więc `endpoint=openrouter` znajdzie endpoint o nazwie `OpenRouter`.

## Załaduj agenta, asystenta lub specyfikację modelu [#load-an-agent-assistant-or-model-spec]

```
/c/new?agent_id=agent_abc123
/c/new?assistant_id=asst_abc123
/c/new?spec=meeting-notes
```

`agent_id` i `assistant_id` ustawiają dla Ciebie endpoint. `spec` ładuje [specyfikację modelu](/docs/configuration/librechat_yaml/object_structure/model_specs) według jej `name`. Wszystkie pozostałe ustawienia w tym samym adresie URL są stosowane na wierzchu presetu specyfikacji. Jeśli Twój administrator wymusza specyfikacje modeli, uwzględnij `spec` w każdym linku i pamiętaj, że wartości samej specyfikacji mają pierwszeństwo przed adresem URL.

## Wypełnij lub wyślij prompt [#fill-in-or-send-the-prompt]

`prompt` (lub krótszy `q`) umieszcza tekst w polu wiadomości. Jeśli oba parametry są obecne, pierwszeństwo ma `prompt`.

Dodaj `submit=true`, aby wysłać wiadomość, gdy tylko czat będzie gotowy:

```
/c/new?endpoint=openAI&model=gpt-4o&prompt=Explain%20quantum%20computing&submit=true
```

Jeśli żądanych ustawień nie uda się zastosować w ciągu kilku sekund, prompt pozostaje w polu wiadomości zamiast zostać wysłany. Administrator może również wyłączyć automatyczne wysyłanie — w takim przypadku `submit=true` tylko wypełnia prompt, a wysłanie wiadomości wykonujesz samodzielnie.

Wartości muszą być zakodowane w formacie URL. W JavaScript robi to funkcja `encodeURIComponent()`:

```js
const url = `/c/new?prompt=${encodeURIComponent('Write a function: def hello()')}`;
// /c/new?prompt=Write%20a%20function%3A%20def%20hello()
```

## Zmiana ustawień modelu [#change-model-settings]

Każdą z tych wartości można dodać do adresu URL. Każda z nich działa wyłącznie w punktach końcowych (endpoints), które ją obsługują, a wartości są sprawdzane przed zastosowaniem; wszystko, co jest nieprawidłowe, jest pomijane bez wyświetlania błędu.

| Endpoint | Parametry |
| --- | --- |
| Dowolny | `maxContextTokens`, `resendFiles`, `promptPrefix` (niestandardowe instrukcje) |
| OpenAI, Azure OpenAI, niestandardowy | `temperature`, `top_p`, `presence_penalty`, `frequency_penalty`, `stop`, `max_tokens`, `reasoning_effort`, `reasoning_summary`, `verbosity`, `useResponsesApi`, `disableStreaming`, `imageDetail` (`low`, `auto`, `high`) |
| OpenAI Responses API | `reasoning_mode` (`standard`, `pro`), `reasoning_context` (`auto`, `current_turn`, `all_turns`) |
| OpenAI, Anthropic, Google | `web_search` (`true`/`false`), `fileTokenLimit` (limit tokenów dla zawartości plików) |
| Anthropic, Google | `temperature`, `topP`, `topK`, `maxOutputTokens`, `thinking`, `thinkingBudget`, `thinkingLevel` |
| Anthropic | `effort` (`low`, `medium`, `high`, `xhigh`, `max`), `thinkingDisplay` (`auto`, `summarized`, `omitted` lub `updates`, czyli wyłącznie notatki o postępie między wywołaniami narzędzi) |
| Anthropic, Bedrock (modele Anthropic), OpenRouter | `promptCache` (`true`/`false`), `promptCacheTtl` (`5m` lub `1h`) |
| Google | `url_context=true` pozwala Gemini odczytywać adresy URL zawarte w Twojej wiadomości |
| Bedrock | `region`, `maxTokens`, `temperature`, `topP`, `reasoning_effort` |
| Assistants | `instructions` (zastępuje instrukcje asystenta na potrzeby tego uruchomienia), `append_current_datetime=true` |

Znaczenie i dozwolone wartości każdego pola są wymienione w [polach presetu specyfikacji modelu](/docs/configuration/librechat_yaml/object_structure/model_specs). Przekazanie wartości odrzucanej przez dostawcę (na przykład `max_tokens` powyżej limitu modelu) spowoduje błąd API podczas wysyłania; aby go wyczyścić, rozpocznij **Nowy czat**.

## Ustaw tryb kolorystyczny [#set-the-color-mode]

Jeśli administrator to włączy, parametr `theme=light`, `theme=dark` lub `theme=system` w linku ustawia tryb kolorystyczny, dzięki czemu aplikacja linkująca do LibreChat może przekazać własny motyw. Ustawienie jest zapisywane jako Twoja preferencja, dopóki jej nie zmienisz w ustawieniach.

## Konfiguracja [#setup]

Parametry zapytania działają bez konfiguracji. Administratorzy mogą zapobiec automatycznemu wysyłaniu `submit=true` za pomocą [`interface.autoSubmitFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#autosubmitfromurl) oraz włączyć parametr `theme` za pomocą [`interface.colorModeFromUrl`](/docs/configuration/librechat_yaml/object_structure/interface#colormodefromurl).
