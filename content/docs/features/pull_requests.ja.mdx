エージェントが、添付されたコードワークスペース内のリポジトリで作業している場合、LibreChat はワークスペースが現在のブランチに対応するプルリクエストを見つけ、チャットの横に表示します。マージ可能かどうか、チェックが通過しているかどうかを確認でき、会話を離れることなくプルリクエストへ移動することもできます。GitHub、GitLab（こちらでは merge request と呼ばれます）、Bitbucket Cloud に対応しており、デプロイごとに 1 つのプロバイダーを使用します。

ワークスペースに接続されたコードを実行するチャットでのみ、プルリクエストを作成できます。通常のチャットや、まだブランチを報告していないワークスペースでは、何も表示されません。

## チャットヘッダー内 [#in-the-chat-header]

ワイド画面では、ヘッダー左側のチップに、プルリクエストのアイコン、その角に表示される小さな CI のドット、そしてプルリクエストのタイトルが表示されます。チップにホバーまたはフォーカスすると、詳細を示すカードが開きます。カードは、ポインターまたはキーボードのフォーカスがカード内にある間は開いたままになります。

<ThemeImage
  light="/images/pull-requests/hdr-ready-light.png"
  dark="/images/pull-requests/hdr-ready-dark.png"
  alt="チャットヘッダーのチップ（オープン中のプルリクエストでチェックがパスしている状態を表示）と、その下に開いているカード"
/>

小さな画面ではチップは表示されません。ヘッダーの三点メニューを開き、`PR #number`の項目(GitLabの場合は`MR !number`)を選択すると、同じカードがダイアログで表示されます。

ヘッダーは自動的に最新の状態を保ちます。チェックの実行中、またはプロバイダーがブランチをマージできるかどうかをまだ判定している間は約20秒ごとに再確認し、それ以外の場合は約60秒ごとに再確認します。プルリクエストがマージされるかクローズされ、実行中のものが何も残っていなくなると、確認を停止します。

## サイドバーで [#in-the-sidebar]

プルリクエストが紐づいている会話にも、行の末尾に同じアイコンとCIのドットが表示されます。行には会話自体のタイトルがそのまま残ります。行にカーソルを合わせるか、マークにフォーカスするかクリックすると、その横にカードが開きます。マークをクリックしても会話は開きません。

<ThemeImage
  light="/images/pull-requests/side-rows-light.png"
  dark="/images/pull-requests/side-rows-dark.png"
  alt="ready to merge、競合あり・チェック失敗、ドラフトでチェック実行中、マージ済みのプルリクエストマークが付いたサイドバーの行"
/>

サイドバーはポーリングを行いません。各行の情報は、リストが最後に読み込まれた時点の鮮度を保ちます。ウィンドウに戻ってきて、そのデータが1分以上古い場合に更新されます。すでに見つかっているプルリクエストの更新が失敗した場合、マークは残り、カードには「プルリクエストを更新できませんでした」と表示され、**再試行**ボタンが表示されます。プルリクエストが一度も見つかっていない会話には、検索が失敗した場合でもマークは表示されません。

## カードの読み方 [#reading-the-card]

カードには `PR #number`(GitLabでは `MR !number`)、追加された行は緑色、削除された行は赤色で表示され、**Open in GitHub**、**Open in GitLab**、または **Open in Bitbucket** のリンク、タイトル、そして2つのバッジが表示されます。

- 状態: Open、Conflicts、Draft、Merged、Closed のいずれか。ブランチがクリーンにマージできない場合は、Open の代わりに Conflicts と表示されます。
- チェック: Passing(成功)、Failing(失敗)、Running(実行中)、None(なし)のいずれか。GitLabでは、現在のコミットに対して実行されたヘッドパイプラインのみが対象となります。Bitbucketではコミットステータスが対象です。

アイコンの色とCIのドットは、同じ情報を一目で示しています:

| プルリクエスト | アイコン | CIドット |
| ------------------------------------ | ------- | --------------- |
| オープン、マージ可能 | 緑 | チェックの結果による |
| オープン、マージ可否は未確定 | 中立 | チェックの結果による |
| オープン、マージコンフリクトあり | 赤 | チェックの結果による |
| ドラフト | 中立 | チェックの結果による |
| マージ済み | 紫 | なし |
| クローズ | 中立 | なし |

ドットは、チェックに合格した場合は緑、失敗した場合は赤、実行中の場合は黄色（アンバー）で表示されます。リポジトリがチェックを報告しない場合は、ドットは表示されません。失敗したチェックは、まだ実行中のチェックより優先されます。

## どのプルリクエストが表示されるか [#which-pull-request-you-see]

ワークスペースには、チャットが最後に実行されたリポジトリ、ブランチ、コミットが表示され、LibreChat はそのブランチからのプルリクエストを検索します。

- もしチャットのコマンド出力に、同じリポジトリ内のプルリクエストへのリンク（例えば `gh pr create` が出力する URL）が含まれていれば、そのプルリクエストが使用されます。ただし、そのプルリクエストがチャットのブランチfrom由来である場合に限ります。
- ほかにブランチのオープンなプルリクエストがある場合は、クローズ済みのものより優先されるため、再利用されたブランチ名に古いクローズ済みのプルリクエストがあっても、現在のプルリクエストが隠れることはありません。
- プルリクエストは、チャットが最後に実行されたコミットを含んでいる場合にのみ有効とみなされます。ブランチを削除して同じ名前を再利用しても、古いプルリクエストが復元されることはありません。
- 新しいコミットのないブランチは、何にも一致しません。

サーバーが参照を許可されていないリポジトリは、プルリクエストが存在しないリポジトリと同じ動作になります。つまり、マークもエラーも表示されません。

## 独自のアカウントを接続する [#connect-your-own-account]

管理者が設定している場合、ご自身の GitHub、GitLab、Bitbucket アカウントを使ってプルリクエストを検索できます。**設定**を開き、**アカウント**に進みます。**接続済みアカウント**の下にある**プルリクエストアカウント**の横の**接続**をクリックしてください。プロバイダーのサインインウィンドウが開くので、承認すると、その行に**接続済み**と表示されます。ウィンドウが開かない場合は、LibreChat のポップアップを許可してから、もう一度お試しください。

接続後は、アカウントを使って検索が行われるため、読み取り権限のある任意のリポジトリのプルリクエストを、ご自身のレート制限の下で確認できます。**切断**を実行すると接続が削除され、いつでも再度接続できます。サーバーが接続を更新できない場合(例えばプロバイダーがダウンしている場合)、サーバーのトークンに黙って切り替えるのではなく、プルリクエストは利用不可として表示されます。プロバイダー側でアプリを取り消した場合、LibreChat は接続を削除し、未接続の状態に戻ります。

もし行に **Not in use** と表示されている場合、管理者がアカウント連携を無効にしており、検索ではもうあなたのアカウントは使用されません。保存された連携情報を削除するには **Disconnect** をクリックしてください。

## セットアップ [#setup]

この機能はデフォルトで有効になっていますが、管理者がLibreChatにトークンと参照を許可するリポジトリの一覧を設定するか、ユーザーが自身のアカウントを接続できるようにアプリを設定するまでは表示されません。また、gitブランチを報告する接続済みのコードワークスペースも必要です。詳細は[プルリクエストの設定](/docs/configuration/pull_requests)を参照してください。
