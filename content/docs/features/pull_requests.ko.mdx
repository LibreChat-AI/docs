채팅이 연결된 워크스페이스에서 코드를 실행하면, 워커는 현재 위치한 git 브랜치와 커밋을 보고합니다. LibreChat은 서버에 보관된 토큰을 사용하여 해당 브랜치와 일치하는 GitHub 풀 리퀘스트를 찾고, 이를 다음 두 곳에 표시합니다:

- **채팅 헤더**: pull request 아이콘과 CI 점이 있는 칩입니다. 마우스를 올리거나 포커스를 맞추면 카드가 열립니다.
- **사이드바 대화 목록**: 행 끝에 동일한 아이콘과 CI 점이 표시됩니다. 행은 대화 고유의 제목을 유지하며, 풀 리퀘스트 제목은 카드에만 나타납니다.

## 요구 사항 [#requirements]

채팅에 풀 리퀘스트가 표시되려면 다음 조건이 모두 충족되어야 합니다:

1. LibreChat은 GitHub 토큰과 저장소 범위를 가지고 있습니다. [Setup](#setup)을 참조하세요.
2. 이 채팅은 단순한 채팅이 아닌 **연결된 코드 작업 공간**(코드 워커)을 사용합니다.
3. 워커는 자신의 브랜치를 보고합니다. 이를 위해서는 `LibreChat-AI/code-interpreter` PR #311 이상에서 빌드된 워커가 필요하며, Code API에 `CODEAPI_BRIDGE_LANE_GIT=true`가 설정되어 있어야 합니다. [Code Interpreter](/docs/features/code_interpreter#attached-environments-and-pairing)를 참조하세요.

요구 사항이 누락된 경우, 채팅에는 단순히 풀 리퀘스트가 표시되지 않으며 사용자에게 오류도 표시되지 않습니다. 단, `token`이 설정되어 있지만 해당 환경 변수가 비어 있거나 누락된 경우는 예외입니다. 이 경우 조회 시 `NOT_CONFIGURED` 오류가 발생하며, 사이드바 행에 재시도 버튼이 포함된 경고 아이콘이 표시됩니다.

## 설정 [#setup]

### 1. 토큰 생성 [#1-create-a-token]

표시하려는 리포지토리로 제한된 세분화된(fine-grained) GitHub 토큰을 사용하고, **읽기 전용(read-only)** 권한을 설정하세요:

- Pull requests
- 확인 사항
- 목차

<Callout type="warning" title="권한 실패 모드">
  **Checks**가 없으면 일치하는 모든 풀 리퀘스트가 로드되지 않습니다. **Contents**가 없으면 마지막 명령 이후 브랜치가 변경된 채팅은 로드되지 않습니다.
</Callout>

### 2. LibreChat에 토큰 제공하기 [#2-give-librechat-the-token]

<Callout type="important" title="대기 중: 아직 출시되지 않음">
  환경 변수 폴백(fallback)은 기본적으로 활성화되는 변경 사항의 일부입니다(LibreChat-AI/LibreChat#16876).
</Callout>

LibreChat은 다음 순서로 토큰을 찾습니다:

1. `token: "${MY_VAR}"` (은/는) `librechat.yaml`에 있습니다. 이는 환경 변수 **참조**이며, YAML은 토큰 자체를 저장하지 않습니다.
2. `token`이 설정되지 않은 경우, `GITHUB_PULL_REQUEST_TOKEN`, `GITHUB_TOKEN`, `GH_TOKEN` 중 설정된 첫 번째 환경 변수가 사용됩니다.
3. 어디에도 토큰이 없는 경우: 이 기능은 비활성 상태로 유지됩니다.

설정되었지만 확인되지 않는(변수가 비어 있거나 누락된) `token`은 `NOT_CONFIGURED` 오류를 발생시킵니다. 이는 위의 세 가지 변수로 대체(fallback)되지 **않습니다**.

<Callout type="info" title="GITHUB_TOKEN은 일반적인 이름입니다">
  배포 환경에서 이미 `GITHUB_TOKEN`을 다른 용도로 사용 중인 경우, 리포지토리 범위(repository scope)가 설정되는 즉시 기본적으로 활성화된 동작이 해당 토큰을 사용하기 시작합니다. 이를 공유하지 않으려면 `token`을 명시적으로 설정하거나 `GITHUB_PULL_REQUEST_TOKEN`을 사용하세요.
</Callout>

**Older versions:** `token` is required when the feature is enabled, and must be a `${NAME}` reference such as `"${GITHUB_PULL_REQUEST_TOKEN}"`. There is no environment variable fallback.

### 3. 검색할 수 있는 저장소 선택 [#3-choose-which-repositories-it-may-look-up]

worker는 자체 저장소를 보고하므로, 서버는 토큰을 사용할 수 있는 저장소를 결정해야 합니다. 범위(scope)가 없으면 이 기능은 비활성화 상태로 유지됩니다. 두 가지 방법이 있습니다:

- `allowedRepositories`: `owner/name` 또는 `owner/*` 항목의 목록입니다(최대 256개). 일치 여부는 대소문자를 구분하지 않습니다. `*/*`, `*`, `owner`와 같은 항목이나 `..`을 포함하는 항목은 스키마에 의해 거부됩니다.
- `allowAllRepositories: true` (**대기 중**): 토큰이 읽을 수 있는 모든 저장소를 조회합니다. 기본값은 `false`입니다.

<Callout type="warning" title="보안: allowAllRepositories">
  이 기능을 켜면, 코드를 실행할 수 있는 모든 사용자가 서버의 토큰을 해당 토큰이 읽을 수 있는 모든 저장소로 지정하여 풀 리퀘스트 제목, 크기 및 확인 상태를 볼 수 있게 됩니다. 표시하려는 저장소로 범위가 지정된 읽기 전용 토큰을 사용하십시오.
</Callout>

### 4. Turn it on [#4-turn-it-on]

<Callout type="important" title="대기 중: 아직 출시되지 않음">
  Default-on 동작은 LibreChat-AI/LibreChat#16876의 일부입니다.
</Callout>

토큰과 저장소 범위가 설정되는 즉시 이 기능이 활성화됩니다. 별도로 설정해야 할 `enabled` 스위치는 없습니다. `enabled: false`로 설정하면 다른 설정과 관계없이 기능이 비활성화됩니다.

**이전 버전:** `enabled: true`가 필수이며, `token`과 비어 있지 않은 `allowedRepositories`가 모두 포함되지 않은 `enabled: true`는 스키마에서 거부됩니다.

### 최소 예시 [#minimal-examples]

서버 환경에 `GITHUB_TOKEN`이 설정된 상태의 기본 활성화 폼(**Pending**):

```yaml filename="librechat.yaml"
endpoints:
  agents:
    pullRequests:
      allowAllRepositories: true
```

특정 저장소로 제한됨 (**대기 중**, 동일 토큰 폴백):

```yaml filename="librechat.yaml"
endpoints:
  agents:
    pullRequests:
      allowedRepositories:
        - 'LibreChat-AI/LibreChat'
        - 'my-org/*'
```

이전 버전에서 작동하는 양식:

```yaml filename="librechat.yaml"
endpoints:
  agents:
    pullRequests:
      enabled: true
      token: '${GITHUB_PULL_REQUEST_TOKEN}'
      allowedRepositories: ['LibreChat-AI/LibreChat']
```

[`pullRequests` 참조](/docs/configuration/librechat_yaml/object_structure/agents#pullrequests)에서 튜닝 옵션을 포함한 모든 키를 확인하세요.

## 사용자가 보는 것 [#what-users-see]

### 채팅 헤더 칩 [#chat-header-chip]

- **Desktop**: 칩은 헤더의 왼쪽, 다른 왼쪽 컨트롤 옆에 위치합니다. 마우스를 올리거나 포커스를 맞추면 오른쪽으로 카드가 열립니다.
- **모바일**: 해당 항목은 헤더의 오버플로우(점 세 개) 메뉴에 있으며, 대화 상자를 엽니다.
- 헤더는 자동으로 새로고침됩니다: 검사가 실행 중이거나 병합 가능 여부가 계산되는 동안에는 약 20초마다, 그 외의 경우에는 약 60초마다 새로고침되며, 풀 리퀘스트가 병합되거나 검사가 실행되지 않은 상태로 닫히면 더 이상 새로고침되지 않습니다.

### 사이드바 표시 [#sidebar-mark]

- CI 점이 있는 pull request 아이콘이 대화 행 끝에 위치합니다. 이 아이콘은 pull request가 있는 대화에만 나타납니다.
- 마우스를 올리거나(hover), 포커스를 맞추거나(focus), 클릭하면 표시(mark) 오른쪽의 동일한 카드가 열립니다. 표시를 클릭해도 대화가 열리지 않습니다.
- 사이드바는 절대 폴링(polling)하지 않습니다. 행(row)의 데이터는 목록이 마지막으로 로드되었을 때의 상태를 유지하며, 창이 다시 포커스를 얻었을 때 데이터가 1분 이상 경과했다면 새로고침됩니다.
- 조회가 실패하면 해당 행의 카드에 재시도 버튼이 포함된 경고 아이콘이 표시되므로, 실패를 "풀 리퀘스트 없음"으로 오인하지 않도록 합니다.

### 카드 [#the-card]

이 카드는 `PR #number`, 녹색으로 표시된 `+additions`, 적색으로 표시된 `-deletions`, GitHub에서 풀 리퀘스트를 여는 링크, 풀 리퀘스트 제목, 그리고 두 개의 배지를 보여줍니다:

- **상태**: Open(열림), Draft(초안), Merged(병합됨) 또는 Closed(닫힘).
- **상태(Checks)**: 통과(Passing), 실패(Failing), 실행 중(Running) 또는 없음(none).

### 아이콘과 점의 의미 [#icon-and-dot-meaning]

| 상황 | 아이콘 색상 | CI 점 |
| --------------------------------------- | ------------------------- | ------------------------------------- |
| 열림, 충돌 없음, 검사 통과 | 녹색 (병합 준비 완료) | 녹색 |
| 열림, 충돌 없음, 검사 없음 | 녹색 | 없음 |
| 열림, 병합 충돌 발생 | 빨간색 (병합 불가) | 검사 기준 |
| 초안 | 중립 | 검사 기준 |
| 병합됨 또는 닫힘 | 중립 | 없음 (검사 진행 중에는 호박색) |

CI 점 색상: 통과 시 녹색, 실패 시 빨간색, 실행 중일 때 호박색(amber), 그리고 검사가 없거나 풀 리퀘스트가 병합 또는 닫혔고 실행 중인 검사가 없을 때는 색상이 표시되지 않습니다. 실패한 검사는 실행 중인 검사보다 우선순위가 높습니다. 읽어 들인 것보다 더 많은 검사 실행이 포함된 롤업은 절대 통과로 보고되지 않습니다.

## 풀 리퀘스트가 매칭되는 방식 [#how-a-pull-request-is-matched]

1. 워커는 채팅이 마지막으로 실행된 리포지토리, 브랜치 및 커밋(head)을 보고합니다.
2. LibreChat은 해당 브랜치의 열린 pull request를 가장 먼저 나열하므로, 재사용된 브랜치 이름의 닫힌 기록이 열린 pull request를 가릴 수 없습니다. 그 다음에는 (커밋을 통해 발견된) 포크에서 발생한 열린 pull request를 확인하고, 마지막으로 닫힌 pull request를 확인합니다.
3. 커밋이 기록되면, 해당 커밋이 헤드(head)이거나 그 위에 빌드된 경우에만 풀 리퀘스트로 간주됩니다. 이는 삭제 후 재사용된 브랜치 이름이 이전 풀 리퀘스트를 표시하지 않도록 방지합니다.
4. 아직 커밋이 없는 브랜치(새롭고 비어 있는 브랜치)는 아무것도 일치하지 않습니다.
5. 결과는 자격 증명, 저장소, 브랜치 및 커밋별로 캐시됩니다.
6. 풀 리퀘스트의 현재 헤드에 대해 체크 실행(check runs)을 읽습니다. 포크에서 생성된 풀 리퀘스트의 경우, 해당 포크의 저장소가 범위 내에 있을 때(목록에 포함되거나 `allowAllRepositories`로 설정된 경우)에만 포크에서 체크를 읽습니다. 그렇지 않은 경우 베이스 저장소를 읽으며, 토큰은 목록에 없는 포크로 전달되지 않습니다.

## 동작 [#behavior]

### 속도 제한 (Rate limits) [#rate-limits]

- 해당 자격 증명에는 GitHub 속도 제한이 적용되므로, 해당 토큰 하위의 모든 브랜치에 대한 조회가 일시 중지됩니다.
- 최소 대기 시간은 10초입니다. 대기 시간이 지정되지 않은 보조 제한은 60초를 대기합니다. GitHub가 지정한 대기 시간은 최대 1시간까지 적용됩니다.
- 일시 중지 중에는 조회가 `RATE_LIMITED`를 반환하며, 행에 재시도 상태가 표시됩니다.

### 롤링 업데이트 (Rolling upgrades) [#rolling-upgrades]

- 사이드바는 서버가 해당 기능을 가지고 있다고 시작 설정(`pullRequestsBatchVersion`)에서 명시할 때만 배치 경로를 요청합니다.
- 경로가 없는 복제본이 404를 반환하면, 클라이언트는 단일 경로로 대체되어 한 번에 하나씩 호출하거나 서버가 광고한 경우 `pullRequestsMaxConcurrentLookups`에 따라 호출합니다. 이는 업그레이드된 복제본으로부터 새로운 시작 플래그를 받은 클라이언트가 해당 경로가 없는 복제본에 도달하는 경우를 처리합니다. 만약 `/api/config`가 플래그가 없는 복제본에 의해 제공되는 경우, 사이드바는 배치 경로를 요청하지 않아 행이 비어 있는 상태로 유지되므로, 사이드바 표시 기능에 의존하기 전에 모든 복제본을 업그레이드하십시오.

### 설정되지 않았을 때의 기본값 [#defaults-when-unset]

- 토큰이나 리포지토리 범위가 없으면 이 기능은 비활성화됩니다. 시작 구성에서 아무것도 알리지 않으며, 기록되는 내용도 없고, 표시되는 내용도 없습니다.
- 설정에서 이 기능을 끄면 기존 채팅은 변경되지 않으며 클라이언트는 새로운 경로를 호출하지 않습니다.

## 보안 모델 [#security-model]

- 토큰은 서버에 상주합니다. 브라우저로 전송되지 않으며, 오류 응답에는 GitHub의 응답 텍스트, 토큰 또는 스택 추적이 포함되지 않습니다.
- 토큰은 범위 내의 리포지토리에 대해서만 사용됩니다. 범위에 포함되지 않은 포크(fork)로는 절대 전송되지 않습니다.
- 두 개의 `/api/convos` 조회 경로는 인증된 사용자가 필요하며 소유자 범위로 제한됩니다. 존재하지 않거나, 만료되었거나, 다른 사용자에게 속한 대화는 풀 리퀘스트가 없는 대화와 동일하게 처리됩니다.
- 공유하려는 리포지토리로만 제한된 읽기 전용의 세분화된(fine-grained) 토큰을 사용하세요.

## 문제 해결 [#troubleshooting]

| 증상 | 예상 원인 | 해결 방법 |
| ------------------------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 칩이 없고 사이드바 표시가 어디에도 없음 | 토큰 없음, 저장소 범위 누락 또는 `enabled: false` | [Setup](#setup)을 확인하세요. 로그인한 상태에서 `/api/config`를 열고 `pullRequestsEnabled: true`인지 확인하세요. |
| 헤더 칩은 작동하지만 사이드바 행에 아무것도 표시되지 않음 | `/api/config`에 `pullRequestsBatchVersion`이 누락됨 (오래된 빌드 또는 캐시된 탭) | 서버를 재빌드하거나 업그레이드하고, 재시작한 뒤 하드 리로드하세요. `pullRequestsBatchVersion: 1`인지 확인하세요. |
| 일부 채팅에만 칩이 나타남 | 브랜치를 보고한 연결된 코드 작업 공간의 채팅에만 레인이 있음 | Code API에서 `CODEAPI_BRIDGE_LANE_GIT=true`인지 확인하고, code-interpreter PR #311 이상에서 빌드된 워커를 사용 중인지 확인하세요. |
| 재시도 아이콘과 함께 경고 표시 | 조회 실패 (속도 제한, GitHub 오류 또는 `NOT_CONFIGURED`) | 재시도하세요. 지속적으로 발생하면 토큰과 권한을 확인하세요. |
| `NOT_CONFIGURED` | `token`은 설정되었으나 해당 변수가 비어 있거나 누락됨 | 변수를 설정하세요. **대기 중:** 또는 `token`을 제거하여 대체 변수를 사용하세요. |
| 풀 리퀘스트는 로드되지만 체크가 잘못 표시되거나 실패함 | 토큰에 Checks 또는 Contents 권한이 없음 | 읽기 전용 Checks 및 Contents 권한을 부여하세요. |
| 포크에서 온 풀 리퀘스트에 체크가 표시되지 않음 | 포크가 범위 내에 없으므로 체크가 기본 저장소에서 읽힘 | 포크 소유자를 `allowedRepositories`에 추가하세요. **대기 중:** 또는 `allowAllRepositories: true`로 설정하세요. |
| 여러 번 재사용된 브랜치 이름에 대한 풀 리퀘스트가 없음 | `maxCandidatePullRequests`, `maxCandidatePages` 또는 `maxHeadComparisons` 값이 이름 재사용 빈도에 비해 너무 낮아 일치하는 풀 리퀘스트에 도달하기 전에 검색이 중단됨 | 해당 값을 높이세요. |
| 프록시 뒤에서 조회가 느리거나 시간 초과됨 | `requestTimeoutSeconds` 값이 너무 낮음 | 값을 높이세요. `HTTPS_PROXY` 및 `NO_PROXY`를 확인하세요. |

## API 참조 [#api-reference]

아래의 `/api/convos` 경로는 모두 인증된 사용자가 필요하며 소유자 범위로 제한됩니다. 시작 구성(startup config) 엔드포인트는 소유자 범위로 제한되지 않습니다.

### 하나의 대화에 대한 풀 리퀘스트 가져오기 [#get-one-conversations-pull-request]

`GET /api/convos/:conversationId/pull-request`

- **200**: `{ "pullRequest": null }` 또는 `{ "pullRequest": { number, title, url, additions, deletions, state, isDraft, mergeable, checks } }`.
- `state`는 `open`, `closed` 또는 `merged`입니다. `mergeable`은 `clean`, `conflicting` 또는 `unknown`입니다. `checks`는 `passing`, `failing`, `running` 또는 `none`입니다.
- **503**: `{ "error": "...", "code": "NOT_CONFIGURED" | "RATE_LIMITED" | "UPSTREAM_ERROR" }`.
- **404**: 잘못된 대화 ID입니다. **500**: 고정 텍스트가 포함된 저장소 오류입니다.

### 여러 대화의 풀 리퀘스트 가져오기 [#get-many-conversations-pull-requests]

`POST /api/convos/pull-requests`

- 본문: `{ "conversationIds": ["..."] }`, 1개에서 50개의 id를 포함합니다. 중복된 항목은 병합됩니다. 그 외의 형식은 400 오류를 반환합니다.
- **200**: `{ "results": [ { "conversationId", "pullRequest" } | { "conversationId", "error": { "code" } } ] }`, 요청된 순서대로입니다. 하나의 조회 실패가 다른 조회를 숨기지 않습니다.
- 토큰이 누락되면 해당 토큰이 필요한 항목만 실패합니다.

### 시작 구성 [#startup-config]

`GET /api/config`는 다음 필드들을 포함합니다. 이 필드들은 서버에 의해 설정되며, 사용자가 변경할 수 있는 설정이 아닙니다.

- `pullRequestsEnabled` (boolean)
- `pullRequestsBatchVersion` (`1`, 기능이 켜져 있을 때만 존재)
- `pullRequestsMaxConcurrentLookups` (숫자, 해당 기능이 켜져 있을 때만 존재)

위에 나열된 오류 코드만 안정적입니다.
