에이전트가 첨부된 코드 워크스페이스의 저장소에서 작업할 때, LibreChat은 워크스페이스가 위치한 브랜치에 대한 풀 리퀘스트를 찾아 채팅 옆에 표시합니다. 대화를 벗어나지 않고도 병합 준비 상태인지, 체크가 통과했는지 확인할 수 있으며, 해당 풀 리퀘스트로 바로 이동할 수 있습니다. GitHub, GitLab(여기서는 머지 리퀘스트라고 부름), Bitbucket Cloud를 지원하며, 배포 환경마다 하나의 제공자를 사용합니다.

작업 공간에 연결된 상태에서 코드를 실행한 채팅만 풀 리퀘스트를 가질 수 있습니다. 일반 채팅이거나 아직 브랜치를 보고하지 않은 작업 공간은 아무것도 표시되지 않습니다.

## 채팅 헤더에서 [#in-the-chat-header]

넓은 화면에서는 헤더 왼쪽의 칩에 풀 리퀘스트 아이콘, 모서리의 작은 CI 점, 그리고 풀 리퀘스트 제목이 표시됩니다. 칩에 마우스를 올리거나 포커스를 맞추면 세부 정보가 담긴 카드가 열립니다. 포인터나 키보드 포커스가 카드 안에 있는 동안에는 카드가 계속 열려 있습니다.

작은 화면에서는 칩이 표시되지 않습니다. 헤더의 점 세 개 메뉴를 열고 `PR #number` 항목(GitLab에서는 `MR !number`)을 선택하면 같은 카드가 대화 상자에 표시됩니다.

헤더는 스스로 최신 상태를 유지합니다. 검사가 실행 중이거나 제공자가 브랜치를 병합할 수 있는지 판단하는 중일 때는 약 20초마다, 그렇지 않은 경우에는 약 60초마다 다시 확인합니다. 풀 리퀘스트가 병합되었거나 닫혔고 실행 중인 작업이 남아 있지 않으면 확인을 멈춥니다.

## 사이드바에서 [#in-the-sidebar]

풀 리퀘스트가 있는 대화에는 행 끝에 같은 아이콘과 CI 점이 표시됩니다. 행에는 해당 대화 고유의 제목이 그대로 유지됩니다. 행에 마우스를 올리거나, 표시를 포커스하거나 클릭하면 옆에 카드가 열립니다. 표시를 클릭해도 대화는 열리지 않습니다.

사이드바는 주기적으로 폴링(polling)하지 않습니다. 각 행은 목록이 마지막으로 로드된 시점의 데이터를 기준으로 표시되며, 창으로 다시 돌아왔을 때 해당 데이터가 1분 이상 지났다면 새로고침됩니다. 이미 찾은 풀 리퀘스트에 대해 새로고침이 실패하면 표시(마크)는 그대로 유지되고, 카드에는 "풀 리퀘스트를 새로고침하지 못했습니다"라는 문구와 **Retry** 버튼이 나타납니다. 풀 리퀘스트를 한 번도 찾지 못한 대화는 조회가 실패했더라도 어떠한 표시도 나타나지 않습니다.

## 카드 읽는 방법 [#reading-the-card]

카드에는 `PR #number`(GitLab에서는 `MR !number`)가 표시되며, 추가된 줄은 초록색, 삭제된 줄은 빨간색으로 나타납니다. 또한 **Open in GitHub**, **Open in GitLab** 또는 **Open in Bitbucket** 링크, 제목, 그리고 두 개의 배지가 포함됩니다.

- 상태: Open, Conflicts, Draft, Merged, Closed. 브랜치가 깔끔하게 병합될 수 없는 경우 Open 대신 Conflicts가 표시됩니다.
- 체크: Passing, Failing, Running 또는 None. GitLab에서는 헤드 파이프라인을 의미하며, 이 파이프라인이 현재 커밋에 대해 실행된 경우에만 표시됩니다. Bitbucket에서는 커밋 상태(commit statuses)를 의미합니다.

아이콘 색상과 CI 점은 한눈에 같은 정보를 요약해 보여 줍니다:

| Pull request | 아이콘 | CI 점 |
| ------------------------------------ | ------- | --------------- |
| 열림, 병합 가능 | 초록색 | 체크 결과에 따름 |
| 열림, 병합 가능 여부 아직 확인되지 않음 | 중립 | 체크 결과에 따름 |
| 열림, 병합 충돌 있음 | 빨간색 | 체크 결과에 따름 |
| 초안 | 중립 | 체크 결과에 따름 |
| 병합됨 | 보라색 | 없음 |
| 닫힘 | 중립 | 없음 |

점이 초록색이면 검사를 통과한 것이고, 빨간색이면 실패한 것이며, 주황색(앰버)이면 실행 중인 것입니다. 저장소에서 보고된 검사가 없으면 점이 표시되지 않습니다. 실패한 검사는 아직 실행 중인 검사보다 우선순위가 높습니다.

## 어떤 Pull Request가 보이는지 [#which-pull-request-you-see]

워크스페이스는 채팅이 마지막으로 실행된 저장소, 브랜치, 커밋을 보고하며, LibreChat은 해당 브랜치에서 풀 리퀘스트를 찾습니다:

- 채팅 자체 명령 출력에 같은 저장소의 풀 리퀘스트 링크(예: `gh pr create`가 출력하는 URL)가 표시되어 있다면, 그 풀 리퀘스트가 채팅의 브랜치에서 생성된 것인 한 해당 풀 리퀘스트가 사용됩니다.
- 그렇지 않으면 같은 브랜치에 대해 열려 있는 풀 리퀘스트가 닫힌 풀 리퀘스트보다 우선되므로, 재사용된 브랜치 이름의 오래된 닫힌 풀 리퀘스트가 현재의 풀 리퀘스트를 가리지 않습니다.
- PR은 채팅이 마지막으로 실행된 커밋을 포함하고 있을 때에만 유효하게 인정됩니다. 브랜치를 삭제하고 같은 이름을 다시 사용한다고 해서 이전 PR이 되살아나지는 않습니다.
- 아직 커밋이 없는 새 브랜치는 아무것과도 일치하지 않습니다.

서버가 조회할 수 없도록 허용되지 않은 저장소는 풀 리퀘스트가 없는 저장소와 똑같이 동작합니다. 표시도 없고 오류도 없습니다.

## 본인 계정 연결하기 [#connect-your-own-account]

관리자가 설정해 둔 경우, 본인의 GitHub, GitLab 또는 Bitbucket 계정으로 풀 리퀘스트를 조회할 수 있습니다. **설정**을 열고 **계정**으로 이동한 후 **연결된 계정**에서 **풀 리퀘스트 계정** 옆의 **연결**을 클릭합니다. 제공업체의 로그인 창이 열리면 승인하세요. 승인이 완료되면 해당 행에 **연결됨**이 표시됩니다. 로그인 창이 열리지 않으면 LibreChat에 대한 팝업을 허용한 후 다시 시도하세요.

연결이 완료되면 조회는 사용자의 계정을 사용하므로, 읽을 수 있는 모든 저장소의 풀 리퀘스트를 본인의 속도 제한 아래에서 확인할 수 있습니다. **연결 해제**를 누르면 연결이 제거되며, 언제든지 다시 연결할 수 있습니다. 서버가 연결을 갱신할 수 없는 경우(예: 제공자 서비스 중단), 서버의 토큰으로 조용히 전환되지 않고 풀 리퀘스트가 사용 불가로 표시됩니다. 제공자에서 앱 권한을 취소하면 LibreChat은 연결을 제거하고 사용자는 다시 미연결 상태로 돌아갑니다.

## 설정 [#setup]

이 기능은 기본적으로 켜져 있지만, 관리자가 LibreChat에 토큰과 조회를 허용할 저장소 목록을 제공하거나, 사용자가 자신의 계정을 연결할 수 있도록 앱을 설정하기 전까지는 숨겨진 상태로 유지됩니다. 또한 git 브랜치를 보고하는 연결된 코드 워크스페이스가 필요합니다. 자세한 내용은 [Pull Requests 구성](/docs/configuration/pull_requests)을 참고하세요.
