LibreChat における応答は、ブラウザの接続状態に依存しません。生成はサーバー側で行われるため、ページを再読み込みしたり、ネットワーク接続が切れたり、タブを閉じたりしても、モデルは処理を続けます。その後で会話を開き直すと、それまでに生成された内容がすべて表示され、残りの部分はストリーミングで続けて表示されます。

## 気づくこと [#what-you-will-notice]

- ページの途中で再読み込みしても、応答が失われることはなくなりました。すでにストリーミングされたテキストは即座に戻り、ストリーミングは引き続き行われます。
- 接続が切れた場合でも再接続され、オフラインの間に届いた内容(ツール呼び出しやエージェントのステップを含む)がすべて補完されます。
- 長い応答を開始した後、別の会話に移動したり、タブを閉じたりしても、戻ってくると完成した回答を確認できます。
- 同じ会話を2つのタブで開いたり、ノートパソコンとスマートフォンで開いたりすると、どちらでも同じレスポンスがストリーミング表示されます。

## 制限 [#limits]

レスポンスは接続ではなく、サーバーの影響を受けずに保持されます。LibreChat の生成処理を担当するプロセスが停止すると、生成も一緒に停止します。

複数の LibreChat インスタンスを実行しているデプロイ環境では、管理者が Redis によるストリーム機能を有効にしている場合に限り、インスタンス間での再開が可能になります。Redis が無効な場合、各インスタンスはストリームを自身のメモリ内に保持するため、別のインスタンスにルーティングされた再接続では応答を再開できません。

## セットアップ [#setup]

単一の LibreChat インスタンスであれば、セットアップは不要です。ストリームはメモリ内に保持され、標準の状態で再開できます。ロードバランサーの背後で複数のインスタンスを運用するデプロイでは Redis が必要です。`USE_REDIS` を有効にすると、ストリームは自動的に Redis を使用します。詳細は [Redis: Resumable Streams](/docs/configuration/redis#resumable-streams) を参照してください。
