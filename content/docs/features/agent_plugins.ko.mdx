Agent Plugins을 사용하면 운영자가 관련 [Skills](/docs/features/skills), [MCP servers](/docs/features/mcp) 및 선택적 명령 훅을 LibreChat 파일 시스템에 함께 패키징할 수 있습니다. LibreChat은 Agent Plugins `1.0.0` 패키지 형식을 구현하며, 시작 시 각 직계 하위 디렉토리를 하나의 플러그인으로 로드합니다.

<Callout type="warning" title="실험적">
  Agent Plugins은 실험적인 기능입니다. 패키지 형식, 지원되는 구성 요소, 구성 및 런타임 동작은 실험 단계 중에 변경될 수 있습니다. 프로덕션 배포에서 사용하기 전에 플러그인을 테스트하십시오.
</Callout>

## 디렉터리 구성하기 [#configure-the-directories]

```bash filename=".env"
# Defaults to ./plugin relative to the LibreChat project root
DEPLOYMENT_PLUGINS_DIR=./plugin

# Persistent data allocated separately for each plugin manifest name
DEPLOYMENT_PLUGIN_DATA_DIR=./data/plugins

# Optional and disabled by default; see Command Hooks below
# DEPLOYMENT_PLUGIN_HOOKS=true
```

상대 경로는 LibreChat 프로젝트 루트를 기준으로 해석됩니다. 기본 `./plugin` 디렉토리가 존재하지 않으면 플러그인 없이 시작이 계속됩니다. `DEPLOYMENT_PLUGINS_DIR`이 명시적으로 설정되었으나 읽을 수 없는 경우, 배포 실수가 조용히 무시되지 않도록 시작이 실패합니다.

플러그인을 추가, 제거 또는 변경한 후에는 LibreChat을 재시작하세요.

## 패키지 레이아웃 [#package-layout]

`DEPLOYMENT_PLUGINS_DIR`의 각 직계 하위 항목은 하나의 플러그인 패키지입니다:

```text
plugin/
  analytics-tools/
    plugin.json
    skills/
      analyze-events/
        SKILL.md
        scripts/
          analyze.py
    mcp.json
    ai.librechat/
      hooks/
        hooks.json
    scripts/
      guard.sh
```

`plugin.json`은 필수입니다. `skills/`, `mcp.json` 및 `ai.librechat/hooks/hooks.json`은 선택 사항이며 독립적으로 실패하므로, 하나의 구성 요소가 유효하지 않다고 해서 동일한 플러그인 내의 다른 유효한 구성 요소가 로드되는 것을 방해하지는 않습니다. 매니페스트가 유효하지 않거나 누락된 경우 전체 플러그인이 거부됩니다. 진단 정보는 LibreChat 시작 로그에 기록됩니다.

## Manifest [#manifest]

매니페스트는 반드시 정확한 Agent Plugins `1.0.0` 스키마 URL을 사용해야 합니다:

```json filename="plugin.json"
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "analytics-tools",
  "version": "1.0.0",
  "description": "Skills and tools for analyzing event data"
}
```

`name`은(는) 플러그인의 영구 데이터 디렉토리에도 사용됩니다. 1~64자여야 하며, 소문자나 숫자로 시작하고 끝나야 합니다. 또한 소문자, 숫자, 하이픈, 마침표만 사용할 수 있으며, `--` 또는 `..` 시퀀스가 연속해서 포함될 수 없습니다. 플러그인 이름은 배포 내에서 고유해야 합니다.

## 번들된 스킬 (Bundled Skills) [#bundled-skills]

각 Skill을 `skills/` 하위의 즉시 자식 디렉토리에 배치하고, 해당 자식 디렉토리의 루트에 `SKILL.md`를 위치시키세요. LibreChat은 유효한 항목을 읽기 전용 배포 Skill로 로드하며, 일반적인 Skills 기능 및 액세스 규칙을 적용합니다.

독립형 [`DEPLOYMENT_SKILLS_DIR`](/docs/features/skills#deployment-skills)은 동일한 이름을 가진 플러그인 Skill보다 우선합니다. 플러그인 디렉토리 내에서는 Skill 이름을 먼저 선점한 패키지가 우선하며, 이후 발생하는 충돌은 경고와 함께 건너뜁니다.

## 번들된 MCP Servers [#bundled-mcp-servers]

`mcp.json` 파일에 정확한 `1.0.0` 스키마 URL을 사용하여 선택적 MCP 서버를 정의하세요:

```json filename="mcp.json"
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "analytics": {
      "type": "stdio",
      "command": "node",
      "args": ["${PLUGIN_ROOT}/server.js"],
      "cwd": "${PLUGIN_ROOT}",
      "env": {
        "PLUGIN_CACHE": "${PLUGIN_DATA}/cache"
      }
    }
  }
}
```

지원되는 전송 방식은 `stdio`, `streamable-http`, `sse`입니다. 원격 HTTP 전송은 루프백 대상을 제외하고 반드시 HTTPS를 사용해야 합니다. 서버 이름은 LibreChat의 MCP 도구 이름 정규화 과정을 거쳐도 변경되지 않아야 하며, 예약된 JavaScript 객체 이름을 사용할 수 없습니다.

`stdio` 서버의 경우, `${PLUGIN_ROOT}`와 `${PLUGIN_DATA}`는 `args`, `env`, `cwd`에서 한 번 확장되며, 두 값 모두 실행된 프로세스 환경에 추가됩니다. 플러그인 MCP 구성은 LibreChat 호스트 환경의 임의 변수를 확장하지 않습니다. `${OPENAI_API_KEY}`와 같은 값은 레지스트리 저장 및 런타임 초기화 과정에서 리터럴(문자열 그대로)로 유지됩니다. 자격 증명은 플러그인 파일 외부에 보관하고, 목적에 맞게 구축된 인증 서비스나 기타 배포 제어 메커니즘을 통해 제공하십시오.

LibreChat는 각 `mcp.json`을 서버를 등록하기 전에 검증합니다:

- `command`은 단일 실행 파일 토큰이어야 합니다. `node`와 같은 단순 이름이거나, 플러그인 내부의 `./` 경로여야 합니다. 셸 문자열과 절대 경로는 거부되며, `command`에서는 `${PLUGIN_ROOT}`가 확장되지 않습니다.
- `cwd`는 `./`, `${PLUGIN_ROOT}`, 또는 `${PLUGIN_DATA}`로 시작해야 하며, 해당 값이 지정한 기준 경로 안에서 해석되어야 합니다.
- `env`에는 `PLUGIN_ROOT` 또는 `PLUGIN_DATA`를 선언할 수 없습니다. 이 두 값은 LibreChat이 설정합니다.
- 원격 `url` 값은 사용자 정보(user information)나 fragment가 없는 절대 `http` 또는 `https` URL이어야 하며, 호스트가 루프백 주소(예: `localhost` 또는 `127.0.0.1`)가 아닌 한 반드시 `https`를 사용해야 합니다.
- 알 수 없는 필드가 포함된 서버 항목은 거부되어 건너뜁니다. 알 수 없는 최상위 필드이거나, 지원되는 `1.0.0` 스키마 URL과 일치하지 않는 `$schema`가 있으면 플러그인 전체에서 MCP가 비활성화됩니다.

`librechat.yaml`에 선언된 MCP 서버는 동일한 이름을 가진 플러그인 서버보다 우선합니다. 중복된 플러그인 서버 이름은 건너뛰며 로그에 기록됩니다.

## 영구 플러그인 데이터 [#persistent-plugin-data]

LibreChat은 `<DEPLOYMENT_PLUGIN_DATA_DIR>/<plugin-name>`에 하나의 디렉토리를 생성하고 이를 `stdio` 컴포넌트에 `${PLUGIN_DATA}`로 노출합니다. 플러그인 소유의 영구 상태(persistent state)를 저장하는 데 사용하십시오. 패키지 콘텐츠로 취급되어야 하는 `${PLUGIN_ROOT}`에는 영구 상태를 기록하지 마십시오.

## Command Hooks [#command-hooks]

Agent Plugins은 Agent 수명 주기 경계에서 `command` 훅 핸들러를 실행할 수 있습니다. 훅 실행은 기본적으로 비활성화되어 있습니다. 이를 명시적으로 활성화하고 LibreChat을 재시작하세요:

```bash filename=".env"
DEPLOYMENT_PLUGIN_HOOKS=true
```

이 변수가 false이거나 설정되지 않은 경우, LibreChat은 훅(hook) 문서를 무시하고 시작 경고를 로그에 기록합니다. 하지만 플러그인의 독립적으로 유효한 Skills 및 MCP 서버는 여전히 로드됩니다.

<Callout type="warning" title="신뢰할 수 있는 코드만 허용">
  명령어 훅(command hook)은 LibreChat API 호스트에서 운영자가 설치한 자식 프로세스를 실행합니다. 제한된 환경은 우발적인 노출을 줄여주지만, 샌드박스는 아닙니다. LibreChat 코드 및 `toolApproval` 훅 모듈과 동일한 수준으로 신뢰하는 플러그인 패키지에 대해서만 훅을 활성화하십시오.
</Callout>

`ai.librechat/hooks/hooks.json`에서 훅(hooks)을 선언하세요:

```json filename="ai.librechat/hooks/hooks.json"
{
  "description": "Reject writes outside the workspace",
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/scripts/guard.sh",
            "timeout": 30,
            "allowedEnvVars": ["WORKSPACE_POLICY"]
          }
        ]
      }
    ]
  }
}
```

### Execution Contract [#execution-contract]

- LibreChat은 플러그인 루트에서 명령을 시작하고 Claude 호환 이벤트 페이로드를 표준 입력으로 JSON 형식으로 전송합니다.
- `${PLUGIN_ROOT}`, `${PLUGIN_DATA}` 및 `${CLAUDE_PLUGIN_ROOT}`는 `command`와 `args` 내에서 한 번 확장되며, 자식 프로세스에서도 사용할 수 있습니다.
- 자식 환경에는 `PATH`, `HOME`, `LANG`, `LC_ALL` 및 존재하는 경우 `TZ`, 세 가지 플러그인 경로 변수, 그리고 `allowedEnvVars`에 명시적으로 나열된 이름만 포함됩니다.
- 종료 코드 `0`은 성공을 의미합니다. 표준 출력으로 작성된 JSON은 이벤트에 적절한 결정과 제한된 컨텍스트를 반환할 수 있으며, 일반 텍스트 출력은 `SessionStart` 및 `UserPromptSubmit`에 대한 추가 컨텍스트로만 처리됩니다.
- 종료 코드 `2`는 해당 작업이나 연속을 차단하며, 표준 오류를 이유로 사용합니다. 그 외의 0이 아닌 종료 코드는 기록되지만 무시됩니다.
- `timeout`은 초 단위이며, 1에서 3600 사이의 정수입니다.
- LibreChat terminates the process when the hook is aborted or times out. On POSIX hosts, commands run through `bash`, which must be available on the API host. On Windows hosts they run through `powershell.exe`, so plugins must provide `commandWindows` or select PowerShell. If the shell cannot start, LibreChat logs a startup warning and blocking hooks fail closed.

LibreChat은 일반적인 Claude 도구 이름인 `Bash`, `Write`, `Edit`, `Read`, `WebSearch`와 해당 파일 인수 이름을 대응하는 LibreChat 도구로 변환합니다. LibreChat의 기본 도구 이름으로 작성된 매처(matcher)는 기본 페이로드 형태를 유지합니다.

지원되는 소스 이벤트는 `RunStart`, `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `SubagentStart`, `Stop`, `StopFailure`, `PreCompact` 및 `PostCompact`입니다. 지원되지 않는 이벤트나 선언은 건너뛰며 시작 진단에 보고됩니다. 이번 릴리스에서는 `command` 핸들러만 실행되며, `prompt`, `http`, `mcp_tool` 및 `agent` 핸들러는 아직 지원되지 않습니다.

`SessionStart` 및 `once: true`가 설정된 핸들러는 제한된 프로세스 로컬 저장소에 의해 대화당 중복 제거됩니다. 다중 복제본 배포 환경에서는 동일한 일회성 핸들러가 각 프로세스에서 한 번씩 실행될 수 있습니다. `ask` 결정은 LibreChat의 재개 가능한 인간 승인 흐름을 필요로 하며, 해당 흐름을 사용할 수 없는 경우 LibreChat은 실행을 재개 경로 없이 일시 중지 상태로 두는 대신 결정을 `deny`로 강화합니다.
