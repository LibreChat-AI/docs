# 消息操作 [#message-actions]

当消息操作可用时，它们会出现在对话轮次下方。用户轮次使用右对齐气泡，而助手轮次则保持全宽响应布局。在响应仍在流式传输时无法应用的操作将被隐藏，直到响应完成。在使用指针设备时，消息元数据和控件会在悬停或键盘聚焦时显示，而无需点击。

## 编辑并重新运行 [#edit-and-rerun]

选择 **Edit** 以更改用户消息或可编辑的助手回复。编辑器提供了两种应用更改的方式：

- **Save** 会更新现有消息，而不会生成新的回复。
- **Update & rerun** 会从编辑后的消息处创建一个新的同级回复。

结构化助手响应使用同一个编辑器来处理所有可编辑的文本和推理部分。工具调用、错误、工件以及附加到工具调用的文本保持可见但为只读状态。空的编辑部分无法保存。

如果更改了多个助手部分，请在不重新运行的情况下保存编辑；一次重新运行只能携带一个已编辑的助手部分。多部分保存将按顺序应用，在错误发生前保存的任何部分仍会反映在对话中。

重新运行编辑后的用户消息会保留其文件、选定的手动 Skills 以及引用的上下文。重新运行编辑后的助手回复会重放其父级用户回合，并保留该回合选定的手动 Skills 和引用。

在编辑时，使用 `Ctrl`/`Cmd` + `S` 保存，`Ctrl`/`Cmd` + `Enter` 更新并重新运行，或使用 `Escape` 取消。

## 复制与分支 (Copy and Fork) [#copy-and-fork]

**复制**功能会将消息文本写入剪贴板，并将受支持的引用转换为可读的参考格式。对于结构化的助手响应，LibreChat 会按顺序仅连接用户可见的文本部分；推理过程、工具调用、错误、工件（artifacts）以及附加到工具调用的文本将被忽略。如果响应仍在生成中或没有可复制的文本，则该操作不可用，因此不会用部分或空值替换剪贴板内容。

在设置中启用 **Copy messages as rich text**，即可将纯 Markdown 和渲染后的 HTML 同时放入剪贴板。这样，当您在 Teams、Outlook 和 Word 等应用程序中粘贴时，便能保留标题、列表、表格和代码格式。

使用 **Fork** 从选定的消息分支出一个对话。详情请参阅 [Forking Conversations](/docs/features/fork)。Endpoint 和消息状态决定了编辑、重新运行、继续、反馈、朗读和 fork 操作是否可用。

## 引用摘录 [#quote-excerpts]

在消息中选中文本并选择 **Add to chat**，将其作为引用上下文进行暂存。每条消息最多可附加 10 个摘录，每个摘录最多 1,500 个字符。LibreChat 会将这些摘录作为 Markdown 引用块与消息文本及任何文件一起发送。

在活动的 Agent 运行期间,引用片段会跟随 **Steer**、**Queue** 和 **Interrupt** 消息显示,并在重新连接后仍与待处理的操作保持关联。在当前服务器上,普通的排队后续消息也会在应用重启和副本切换后保留其引用片段。如果在滚动部署期间,较旧的副本无法接受引用上下文,LibreChat 会将其退回到输入框,而不会静默丢弃。手动选择的 Skills 会保留在下一次完整轮次中待用,而不会添加到运行中途的 steer 中。请参阅 [Steering and Queued Messages](/docs/features/agents#steering-and-queued-messages)。

## 代码块操作 [#code-block-actions]

代码块提供了复制内容、通过 [Code Interpreter](/docs/features/code_interpreter) 运行受支持的代码，或将代码块下载为本地文件的操作。下载的文件名会尽可能使用代码块中指定的语言，例如 `code.py` 或 `code.tsx`；未知的安全语言提示将作为其扩展名，若提示缺失或无效，则回退为 `code.txt`。错误块不会显示下载操作。

## 长文本粘贴 [#long-pasted-text]

当浏览器本地的 **Paste long text as a file** 设置启用且 [Upload as Text context uploads](/docs/features/upload_as_text#paste-long-text-as-a-file) 可用时，超过 2,500 个字符的剪贴板粘贴内容将变为 `pasted-text.txt` 附件，而不是直接填充到输入框中。否则，粘贴的内容将保持为内联文本。在发送前选中该附件，即可在更大的对话框中编辑文本，或选择 **Move back into message** 将其移回输入框。

LibreChat 在正常的草稿恢复过程中会保留粘贴的文本草稿和消息来源。编辑操作会保留原始附件，直到替换内容准备就绪；而启动明确的 **New Chat** 则会清除粘贴的文本以及其余的草稿内容。

## 仅附件轮次 [#attachment-only-turns]

您可以发送一个或多个附件，而无需输入占位符文本。仅包含附件的对话在编辑和重新运行消息时仍然有效，并且 LibreChat 在需要标题上下文时会使用附件的文件名。

即使是一个不包含任何文件的空草稿仍会被拒绝。在回答 Agent 暂停的 **Ask User** 表单时，文件也不能替代文本，因为该响应路径接受的是答案值，而非消息附件。
