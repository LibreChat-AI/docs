MCP(Model Context Protocol)는 도구를 모델에 노출하기 위한 오픈 표준입니다. MCP 서버는 모델에 파일 시스템, 브라우저, 데이터베이스 또는 회사의 내부 API를 제공할 수 있으며, LibreChat은 이 프로토콜을 사용하는 모든 서버를 사용할 수 있습니다. 빠른 사용을 위해 일반 채팅에 서버를 연결하거나, 에이전트에 해당 서버의 도구를 추가할 수 있습니다.

## 채팅에서 서버 사용하기 [#use-a-server-in-chat]

Agents 또는 Assistants가 아닌 다른 엔드포인트에서는 입력창의 **+** 팔레트(**Attach and tools**)를 열고 **MCP Servers** 항목을 확인하세요. 서버를 클릭하면 해당 대화에서 활성화됩니다. 서버는 입력창에 칩(chip)으로 표시되며, 서버가 제공하는 모든 도구를 모델이 사용할 수 있게 됩니다. 팔레트는 열린 상태로 유지되므로 여러 서버를 한 번에 켤 수 있습니다. 서버를 다시 클릭하거나 해당 칩을 제거하면 서버가 꺼집니다. 팔레트의 나머지 기능은 [Composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers)를 참고하세요.

팔레트에는 한 번에 몇 개의 서버가 표시되며, 각 서버의 상태는 색상 점으로 나타납니다. **MCP Servers** 헤더의 **Show All**을 클릭하면 검색 필드와 세 가지 보기(**All**, **Made by you**, **Favorites**)가 포함된 전체 목록이 열립니다.

![MCP Servers 대화 상자가 Show All 상태로 열려 있는 모습. Github 서버는 Disconnected, Spotify 서버는 Needs Auth로 표시되어 있으며, All, Made by you, Favorites 필터가 함께 보입니다](/images/mcp/mcp_servers_catalog.png)

서버가 아직 연결되지 않은 상태라면, 클릭 시 바로 선택되지 않고 연결이 시작됩니다. 사용자 고유의 자격 증명이 필요한 서버는 먼저 이를 입력할 수 있는 대화 상자가 열리며, OAuth를 사용하는 서버는 로그인 절차로 이동합니다. 연결이 완료되면 LibreChat이 해당 서버를 자동으로 선택합니다.

도구 호출을 지원하는 모델을 선택하세요. 그렇지 않으면 모델이 서버의 도구를 절대 호출하지 않습니다. 에이전트와 어시스턴트는 자체 도구 설정을 가지고 있으므로 이러한 엔드포인트에서는 모델 선택기가 숨겨지며, 관리자는 채팅에서 개별 서버를 숨겨 에이전트에서만 사용할 수 있도록 설정할 수 있습니다.

## 에이전트에 서버 추가하기 [#add-a-server-to-an-agent]

Agent Builder에서 **Tools** 옆의 **Add**를 클릭하여 **Tool Library**를 열고, **MCP servers**로 필터링합니다. 서버를 추가하면 해당 서버가 제공하는 도구 목록이 표시됩니다. 에이전트가 사용해야 하는 도구는 유지하고 나머지는 제거하거나, **Select all** 및 **Deselect all**을 사용하세요. 도구가 수십 개인 서버라도 에이전트의 도구 목록에서는 하나의 항목으로 표시됩니다.

각 에이전트의 각 MCP 도구에는 자체 옵션(**Defer loading**, **Programmatic**, **Background**, **Intent label**)도 있습니다. 각 옵션이 무엇을 변경하는지는 [Agents](/docs/features/agents)를 참고하세요.

일부 서버는 채팅 요청 중에만 존재하는 값에 의존하므로, 해당 서버의 도구를 미리 나열할 수 없습니다. 이런 서버의 경우 도구 라이브러리는 서버 전체를 연결하고, 도구가 채팅 중 런타임에 확인된다는 점을 함께 표시합니다.

에이전트가 MCP 도구를 사용하도록 설정되어 있는데 실행이 시작될 때 해당 도구를 하나도 사용할 수 없는 경우(서버가 다운되었거나 접근 권한을 잃은 경우), 도구 없이 답변하는 대신 연결 상태와 접근 권한을 확인하라는 오류 메시지와 함께 실행이 중단됩니다. 또한 도구 호출 중에 **Stop**을 누르면, 서버가 취소를 지원하는 한 MCP 서버에서도 해당 호출이 취소됩니다.

## 연결 상태 [#connection-status]

팔레트와 **MCP Settings**에서 상태는 색깔 점으로 표시됩니다. 서버 연결이 끊어지면 회색, 사용자의 로그인이 필요하면 주황색(앰버)으로 나타납니다. 전체 상태는 스크린 리더에 읽히며, Tool Library와 **Show All** 목록에서는 각 서버 옆에 상태가 텍스트로 풀어서 표시됩니다.

- **연결됨**: 사용할 준비가 되었습니다.
- **Needs Auth**: 서버가 OAuth를 사용하며, 아직 로그인하지 않았거나 로그인이 만료된 상태입니다.
- **Connecting** / **Initializing**: 연결 시도가 진행 중입니다.
- **Disconnected** 또는 **Error**: 활성 연결이 없거나 마지막 연결 시도가 실패했습니다. **Connect**를 사용하여 다시 시도하세요.
- **온디맨드**: 서버는 요청마다 개별적으로 연결하므로, 보고할 상시 연결이 없습니다.
- **알 수 없음**: 아직 상태가 반환되지 않았습니다.

연결이 실패하면 오류 메시지에 그 이유가 나타납니다. 서버에 연결할 수 없는 경우, 설정하지 않은 변수가 필요한 경우(메시지에 변수 이름이 표시됨), 또는 다시 로그인해야 하는 경우입니다. 해당 문제를 해결한 다음 다시 연결하면 됩니다. 서버를 삭제했다가 다시 추가할 필요는 없습니다. 또한 서버는 실행 중에도 도구를 추가하거나 제거할 수 있으며, LibreChat은 재시작 없이 새 목록을 자동으로 반영합니다.

연결은 사용자별로 관리됩니다. 사용자의 OAuth 토큰과 저장된 자격 증명은 다른 사람에게 사용되지 않으며, 기본적으로 15분 동안 유휴 상태인 연결은 종료되고 다음에 서버를 사용할 때 다시 열립니다.

## OAuth로 로그인 [#sign-in-with-oauth]

서버에 OAuth가 필요하면 연결 시 **Connect** 대화 상자가 열립니다. **Continue with OAuth**를 클릭하면 새 탭에서 제공자의 로그인 페이지가 열리며, **Copy link** 또는 **Show QR Code**를 사용하여 다른 기기에서 인증을 완료할 수 있습니다. 액세스를 승인하면 탭에 **Authentication Successful**이 표시되고 스스로 닫히며, 서버 상태가 **Connected**로 바뀝니다.

로그인이 진행 중인 동안 서버에는 스피너가 표시됩니다. 스피너 위에 마우스를 올리면 취소할 수 있습니다. Agent Builder의 MCP 서버 설정에서는 같은 목적으로 **Connect** 버튼이 **Cancel**로 바뀝니다. 로그인을 완료하기 위한 제한 시간은 10분이며, 이 시간이 지나면 시도가 시간 초과됩니다(관리자가 이 시간을 변경할 수 있습니다).

제공자가 리프레시 토큰을 발급하는 경우, LibreChat은 백그라운드에서 액세스 권한을 갱신합니다. 세션 도중 서버가 토큰을 거부하면, 다시 로그인하라고 요청하기 전에 한 번 리프레시와 재연결을 시도합니다. 리프레시 토큰을 발급하지 않는 제공자의 경우, 토큰이 만료되면 다시 로그인하도록 요청합니다.

기본적으로 로그인 안내는 메시지를 보낼 때 표시됩니다. 관리자는 일부 서버가 에이전트가 해당 서버의 도구를 처음 호출할 때까지 기다리도록 설정할 수 있으며, 이렇게 하면 서버가 실제로 필요한 시점에만 로그인하라는 요청을 받게 됩니다.

## 자격 증명 및 변수 [#credentials-and-variables]

일부 서버는 각 사용자로부터 개인 API 키나 프로젝트 ID와 같은 값을 필요로 합니다. 이러한 서버에 연결하면 LibreChat은 연결하기 전에 해당 값을 입력하도록 요청합니다. 나중에 값을 변경하려면 채팅 선택기 또는 **MCP Settings**에서 해당 서버의 **Configure**를 사용하세요. 각 입력 필드에는 **Save**와 **Revoke**가 있습니다. 둘 중 어느 것을 사용하든 해당 서버와의 현재 연결이 끊어지므로, 다음 사용 시 새 값으로 다시 연결됩니다. 또한 **Revoke**를 사용하면 현재 채팅에서 해당 서버도 꺼집니다.

값은 사용자별로 저장되며, 입력된 서버로만 전송됩니다.

## MCP 설정 패널 [#mcp-settings-panel]

**MCP 설정**은 사이드 패널에 사용할 수 있는 모든 서버를 나열하며, 각 서버 아이콘에는 상태 점이 표시됩니다. 서버의 상태에 따라 각 카드에는 **연결**, **다시 연결**, **구성**(사용자 변수 설정), 또는 **해지**(OAuth 토큰 삭제) 버튼이 제공됩니다. 편집이 허용된 서버에는 **편집** 버튼도 함께 표시됩니다.

## UI에서 서버 만들기 [#create-a-server-from-the-ui]

역할이 허용한다면 **MCP Settings**에서 **Add MCP** (**+** 버튼)을 클릭하여 `librechat.yaml`을 수정하거나 재시작하지 않고도 원격 서버를 등록할 수 있습니다.

<Steps>
<Step>
### 서버 설명 [#describe-the-server]

다음 항목을 입력하세요: **이름**, 선택 사항인 **설명**, 원하는 경우 아이콘. **MCP 서버 URL**을 입력하고 **전송 방식**을 선택하세요: **Streamable HTTPS** 또는 **SSE**.
</Step>
<Step>
### 인증 방식 선택 [#choose-authentication]

**인증**에서 다음 중 하나를 선택하세요:

- **없음 (자동 감지)**: LibreChat은 서버를 확인하여 서버가 요청하는 경우 OAuth로 전환합니다.
- **API 키**: 공유 키 하나를 입력하거나, **각 사용자가 자신의 키를 제공** 옵션을 선택하여 모든 사용자가 **Configure**를 통해 자신의 키를 입력하도록 합니다. **헤더 형식**을 선택하십시오: **Bearer**, **Basic**, 또는 직접 헤더 이름을 지정하는 **Custom**.
- **OAuth**: **Client ID**, **Client Secret**, **Authorization URL**, **Token URL**, **Scope**를 입력하세요. 제공업체가 동적 클라이언트 등록을 지원하는 경우 클라이언트 필드는 비워 두세요. **Token Exchange Method**의 기본값은 **Auto**이며, 이 경우 제공업체가 광고하는 방식을 사용하고 필요 시 Basic 인증 헤더로 대체합니다. 특정 방식을 강제하려면 **Default (POST request)** 또는 **Basic authorization header**를 선택하세요.
- **On-Behalf-Of (OBO)**: 관리자가 해당 권한을 부여한 경우에만 표시되며, LibreChat이 OpenID Connect(예: Entra ID)로 사용자를 로그인시킬 때에만 작동합니다. 요청할 스코프(scope)를 입력하면, LibreChat이 사용자의 OpenID 토큰을 MCP 서버용으로 스코프가 지정된 토큰으로 교환합니다.
</Step>
<Step>
### 생성하기 [#create-it]

**I trust this application** 체크박스를 선택하고 **Create**를 클릭하세요. 서버는 즉시 사용할 수 있습니다. OAuth 서버의 경우, 다음 대화 상자에 OAuth 제공자에 등록할 **Redirect URI**가 표시되며, 한 번 로그인하기 전까지 서버는 연결되지 않은 상태로 유지됩니다.
</Step>
</Steps>

<ThemeImage
  light="/images/features/mcp/add-server-dialog-light.png"
  dark="/images/features/mcp/add-server-dialog-dark.png"
  alt="Add MCP Server 대화 상자에서 이름과 URL을 입력하고, 전송 방식을 Streamable HTTPS로 설정하며, 인증을 API Key로 설정하고 Each user provides their own key를 체크한 상태"
/>

이런 방식으로 생성된 서버는 원격 URL에만 연결할 수 있습니다. 로컬 `stdio` 서버는 `librechat.yaml`에 정의해야 합니다. 또한 서버 환경 변수나 사용자 프로필 플레이스홀더를 사용할 수 없습니다. 헤더에 포함된 `${API_TOKEN}` 또는 `{{LIBRECHAT_USER_EMAIL}}` 같은 값은 공유 서버가 이를 수신하게 되므로 제거됩니다. 나중에 서버의 URL이나 인증 방식을 변경하면, 직접 키를 입력했던 사용자는 키를 다시 입력해야 하며, OAuth 사용자는 다시 로그인해야 합니다. 저장된 클라이언트 시크릿이 있는 서버의 URL 또는 OAuth 엔드포인트를 변경하는 경우, 시크릿도 다시 입력해야 합니다. 이전 버전에서 생성된 API 키 서버가 **Needs Auth** 상태에 머물러 있다면, **Edit**으로 열어 한 번 저장하십시오.

## 서버 공유하기 [#share-a-server]

UI에서 만든 서버는 해당 서버를 생성한 사용자의 소유입니다. 소유자는 **Edit** 대화 상자에서 특정 사용자, 그룹, 역할 또는 모든 사용자와 서버를 공유할 수 있으며, 공유 시 뷰어(보기 및 사용 가능), 편집자(변경도 가능), 또는 소유자 권한을 부여할 수 있습니다. `librechat.yaml`에 정의된 서버는 MCP를 사용할 권한이 있는 모든 사용자가 이용할 수 있습니다. 권한 수준이 어떻게 결합되는지는 [Access Control](/docs/features/access_control)을 참고하세요.

## 서버 지침 [#server-instructions]

관리자는 서버에 지침을 연결할 수 있으며, 서버 자체에 내장된 지침이나 직접 작성한 사용자 지정 텍스트를 사용할 수 있습니다. 대화나 에이전트에 해당 서버의 도구가 포함되어 있으면, 그 지침이 모델의 컨텍스트에 추가됩니다. 이는 도구를 특정 순서로 사용해야 의미가 있는 서버에 특히 도움이 됩니다.

## MCP Apps [#mcp-apps]

일부 서버는 도구 결과와 함께 대화형 뷰를 반환합니다. MCP Apps가 켜져 있으면 도구 호출에 **Open app** 버튼이 표시되며, 이 버튼을 누르면 샌드박스된 프레임에 뷰가 로드됩니다. **Close app** 버튼을 누르면 뷰가 다시 숨겨집니다. 동시에 열 수 있는 앱의 수는 제한되어 있으므로, 한도에 도달하면 먼저 앱 하나를 닫아야 합니다.

앱은 스스로 동작할 수 없습니다. 앱이 도구를 실행하려고 하면 **앱에서 도구를 실행하시겠습니까?**가 표시되고, 메시지를 게시하려고 하면 **앱에서 메시지를 보내시겠습니까?**가 표시됩니다. 승인하기 전까지는 아무 일도 일어나지 않습니다. 메시지를 보내면 현재 대화에서 모델 응답이 시작되므로, 선택된 에이전트와 해당 도구가 사용될 수 있습니다. 앱은 공유된 대화에서 렌더링되지 않습니다.

## 설정 [#setup]

MCP에는 최소 하나의 서버가 필요합니다. 관리자는 `librechat.yaml`의 `mcpServers` 아래에 서버를 정의하며, 이 설정은 재시작해야 적용됩니다. 권한이 있는 사용자는 **MCP Settings**에서 원격 서버를 추가할 수 있습니다. 서버 옵션, OAuth 콜백 URL, 전송 방식은 [MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers)를, 허용된 도메인과 MCP Apps는 [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings)를, 앱 제한은 [MCP App Sandbox](/docs/configuration/librechat_yaml/object_structure/mcp_app_sandbox)를, 서버를 사용, 생성, 공유할 수 있는 사용자는 [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)를 참조하세요. 특정 서버의 설정 가이드는 [MCP Servers](/docs/mcp_servers)에 있으며, MCP 서버를 skills와 함께 묶는 방법은 [Agent Plugins](/docs/features/agent_plugins)에서 다룹니다.
