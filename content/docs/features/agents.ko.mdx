에이전트는 모델, 시스템 프롬프트, 그리고 사용할 수 있는 도구와 파일을 저장해 둔 설정입니다. Agent Builder에서 한 번 만들어 두면, 채팅을 시작할 때마다 원하는 에이전트를 선택할 수 있습니다. 에이전트는 OpenAI뿐 아니라 구성해 둔 모든 제공자와 함께 동작합니다.

## 에이전트 만들기 [#create-an-agent]

<Steps>
  <Step>
    사이드 패널에서 **Agent Builder**를 열고 **Create New Agent**를 클릭하세요.
  </Step>
  <Step>
    이름을 지정하고, 선택적으로 설명을 입력한 다음, **Model**과 **Category**를 선택하세요. Model과 Category는 필수 항목입니다.
  </Step>
  <Step>
    지침을 작성하세요. 직접 입력하거나, 소스를 **Prompt**로 전환하여 아래에서 설명하는 프롬프트 라이브러리에 저장된 프롬프트를 사용할 수 있습니다.
  </Step>
  <Step>
    **Tools** (아래 참조)에 도구를 추가한 다음 **Create**를 클릭하세요.
  </Step>
</Steps>

파일 검색(File Search) 또는 파일 컨텍스트(File Context)를 위한 파일 업로드는 에이전트가 생성된 후에만 가능합니다.

에이전트와 채팅하려면 모델 선택기에서 에이전트를 선택하거나, [에이전트 마켓플레이스](#agent-marketplace)에서 열거나, 채팅 입력창에 `@`를 입력한 후 목록에서 선택하면 됩니다. 빌더의 에이전트 선택기에서 **내 에이전트**를 선택하면 직접 만든 에이전트만 목록에 표시됩니다.

### 저장된 프롬프트의 지침 [#instructions-from-a-saved-prompt]

instructions 소스를 **Prompt**로 설정한 뒤, **Select a prompt**에서 프롬프트를 선택하고 **Version**을 지정합니다. 버전은 프롬프트 소유자가 프로덕션으로 표시한 버전을 따르는 **production 버전**이나, 저장된 특정 버전으로 고정할 수 있습니다. 이를 위해서는 프롬프트 라이브러리에 대한 접근 권한이 있어야 합니다. 권한이 없는 다른 사용자가 에이전트를 열면, 빌더에 **Restricted prompt**가 표시되며, 해당 사용자는 프롬프트를 교체하거나 인라인 instructions로 되돌릴 수 있습니다.

지침(인라인 또는 링크된 지침)에는 `{{current_date}}`, `{{current_datetime}}`, `{{iso_datetime}}`를 사용할 수 있습니다. 이 값들은 each 턴이 시작될 때 한 번 채워지며, 도구 호출, 하위 에이전트, 승인 대기 중에도 동일하게 유지됩니다. 앞의 두 값은 사용자의 시간대를 사용하며, `{{iso_datetime}}`은 UTC입니다.

### 모델 매개변수 [#model-parameters]

모델 패널에서는 해당 제공업체의 일반 채팅과 동일한 매개변수(temperature, 최대 출력 토큰 등)를 설정할 수 있으며, 비전 입력을 위한 **Image Detail**도 포함됩니다. 여기에서 저장한 값은 해당 에이전트의 모든 대화에 적용됩니다.

### 대화 시작 예시 [#conversation-starters]

**Conversation Starters** 아래에서 최대 네 개의 프롬프트를 추가할 수 있습니다. 사용자가 에이전트와 새 채팅을 시작하면 빈 채팅 화면에 버튼으로 표시되며, 버튼을 클릭하면 해당 프롬프트가 바로 전송됩니다. 에이전트의 Conversation Starters는 사용 중인 Model Spec에 정의된 Conversation Starters를 대체합니다. 또한 에이전트의 Marketplace 상세 정보에도 표시됩니다.

### 버전 기록 [#version-history]

에이전트를 변경하는 저장 작업마다 **버전 기록**에 항목이 추가되며, 각 버전이 언제 저장되었고 어떤 도구와 기능을 가졌는지 보여줍니다. **복원**을 실행하면 확인 절차를 거친 후 현재 구성이 해당 버전으로 대체됩니다. 이 기능은 에이전트를 편집할 수 있는 사용자에게만 표시됩니다.

## 도구 [#tools]

빌더의 **Tools** 제목 옆에 있는 **Add**를 클릭하면(도구를 추가하기 전에는 **No tools yet**으로 표시됨) **Tool Library**가 열립니다. 여기에서 검색하거나 **Native**, **Tools**, **MCP servers**, **Actions**로 필터링할 수 있습니다. **Made by you**에는 직접 만든 MCP 서버와 Action이 모여 있으며, **Favorites**에는 별표를 표시한 항목(최대 100개)을 에이전트와 관계없이 쉽게 찾을 수 있도록 저장됩니다. **Create new…** 메뉴를 사용하면 권한이 있는 경우 대화상자를 벗어나지 않고 MCP 서버나 Action을 추가할 수 있습니다. 표시되는 내용은 관리자가 활성화한 기능과 사용자 역할의 권한에 따라 달라집니다. API 키 설정이 아직 필요한 항목에는 **Needs setup**이 표시됩니다.

Run Code, File Search, File Context는 파일을 보관합니다. 이들에 첨부된 파일이 남아 있는 동안 해당 기능을 제거하면 대신 파일 관리자가 열리며, 첨부된 파일이 모두 제거될 때까지 기능은 에이전트에 그대로 남아 있습니다.

### Code Interpreter [#code-interpreter]

**Run Code**로 표시됩니다. 에이전트는 샌드박스에서 코드를 작성하고 실행하며, 이는 계산, 데이터 분석, 차트나 스프레드시트 같은 파일 생성에 적합합니다. 빌더에서 이 도구에 첨부한 파일은 매 실행마다 샌드박스에서 사용할 수 있습니다. 대화의 코드 파일을 샌드박스에 복원할 수 없는 경우, 에이전트는 모델을 호출하기 전에 중단하고 파일을 다시 첨부하도록 요청합니다. 자세한 내용은 [Code Interpreter](/docs/features/code_interpreter)를 참조하세요.

#### 상태 유지 코드 세션 [#stateful-code-sessions]

관리자가 활성화한 경우, 실행 코드 설정의 **Stateful code sessions**는 실행 간에 샌드박스 작업 공간을 유지하여 파일과 설치된 패키지가 다음 실행으로 이어지도록 합니다. **Stateful environment**는 이 작업 공간을 누가 공유할지 설정합니다. 모든 stateful 에이전트에 대해 **User workspace (recommended)**, 에이전트마다 하나씩 설정하려면 **Agent + user workspace**, 채팅마다 하나씩 설정하려면 **Conversation workspace**를 선택할 수 있습니다. 새 에이전트는 **Settings > Data & Privacy > Code execution**의 **Default stateful workspace**에서 시작합니다. 관리자가 여러 백엔드를 구성한 경우, **Execution environment**에서 코드를 실행할 백엔드를 선택할 수 있으며, 여기에는 사용자의 컴퓨터에서 페어링한 워커도 포함될 수 있습니다.

작업 공간은 언제든지 초기화될 수 있으므로 저장소로 취급하지 마세요. 관리형 환경에서는 필요한 출력을 `/mnt/data` 아래에 저장하세요. 에이전트가 파일 도구로 작성한 파일은 메시지마다 **Workspace changes**에 표시되며, 여기에서 다운로드할 수 있습니다. 환경이 연결되어 있으면 입력창에서 해당 채팅의 승인 모드로 **Ask before changes**, **Accept edits**, **Full access** 중 하나를 선택할 수 있으며, 선택 가능한 범위는 관리자가 설정한 한도에 따릅니다.

이 기능은 매우 실험적입니다. 자세한 내용은 [상태 저장형 코드 세션](/docs/features/code_interpreter#stateful-code-sessions)을 참조하세요.

### 웹 검색 [#web-search]

에이전트는 웹을 검색하고 출처를 인용합니다. 관리자가 구성한 검색 제공자가 필요하며, 관리자가 그렇게 설정한 경우에는 본인의 키를 사용할 수도 있습니다. [웹 검색](/docs/features/web_search)을 참조하세요.

### File Search [#file-search]

첨부한 파일을 검색 가능한 지식 베이스로 바꿔 줍니다. 에이전트는 필요할 때 가장 관련성 높은 구절을 가져오므로 대용량 문서 세트도 처리할 수 있습니다. CSV나 Excel 같은 구조화된 데이터에는 적합하지 않으며, 이런 경우에는 Run Code가 더 나은 결과를 냅니다. [RAG API](/docs/features/rag_api)가 필요합니다.

### 파일 컨텍스트 [#file-context]

**파일 컨텍스트**에 추가된 파일은 업로드 시점에 텍스트가 한 번 추출되며, 그 텍스트는 모든 메시지마다 에이전트의 컨텍스트에 포함됩니다. 에이전트가 항상 참고해야 하는 몇 가지 핵심 문서에 사용하세요. 추출 방식은 [텍스트로 업로드](/docs/features/upload_as_text)와 동일합니다. 기본적으로는 일반 텍스트 파싱을 사용하며, [OCR](/docs/features/ocr)이 구성되어 있으면 스캔 문서와 이미지에서 더 나은 결과를 얻을 수 있습니다.

텍스트가 모든 메시지에 함께 전달되므로, 여기서 큰 파일을 사용하면 매 턴마다 토큰 비용이 발생합니다. 또한 에이전트와 대화할 수 있는 사람은 누구든 그 텍스트를 에이전트로부터 이끌어낼 수 있습니다.

### Artifacts [#artifacts]

이 기능을 사용하면 에이전트가 React, HTML, SVG, Markdown, Mermaid를 코드 블록 대신 사이드 패널에 렌더링할 수 있습니다. **Mode** 설정으로 내장 지침을 선택합니다: **Normal**, **shadcn/ui**(shadcn/ui 컴포넌트 라이브러리에 대한 지침을 추가), 또는 **Custom**입니다. Custom은 아무 지침도 주입하지 않으므로, 아티팩트 구문을 가르치는 지침을 직접 작성해야 합니다. 해당 구문은 [Artifacts](/docs/features/artifacts)를 참고하세요.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

관리자가 구성했거나 직접 추가한 MCP 서버는 **MCP servers** 아래에 표시됩니다. 서버를 추가하면 해당 서버의 모든 도구가 연결됩니다. 에이전트에 필요한 도구만 선택하려면 **Tools in this server**를 펼치세요. 자세한 내용은 [MCP](/docs/features/mcp)를 참고하세요.

일부 서버는 요청에 담긴 값에 의존하기 때문에 채팅 중에만 도구 목록을 보여줄 수 있습니다. 이런 서버의 경우 빌더는 도구별 스위치 대신 해당 서버의 모든 도구를 한 번에 선택할 수 있는 옵션을 제공합니다. 실행이 시작될 때 에이전트에서 선택한 MCP 도구가 모두 로드되지 않으면, 도구 없이 계속 진행하지 않고 실행을 중단한 뒤 서버에 다시 연결하거나 로그인하라고 안내합니다.

각 MCP 도구에는 몇 가지 도구별 설정 스위치가 있는 **Tool Options** 메뉴가 있습니다:

- **Defer**: [Deferred tools](#deferred-tools)를 참조하세요. **Defer all tools**를 사용하면 서버 전체에 대해 이를 적용합니다.
- **프로그래밍 방식**: [프로그래밍 방식 도구 호출](#programmatic-tool-calling)을 참조하세요.
- **배경**: [배경 도구 호출](#background-tool-calls)을 참고하세요.
- **의도 레이블**: 에이전트가 각 호출에 대한 한 줄 설명을 작성하며, 이 설명은 일반적인 레이블 대신 호출의 상태로 실시간 표시됩니다. 요청당 몇 개의 토큰이 추가로 사용됩니다. 네이티브 도구에는 의도 레이블이 자동으로 적용됩니다. 프로그래매틱 도구에는 적용되지 않습니다.

**Background**과 **Intent label**은 관리자가 활성화한 경우에만 표시됩니다.

### 지연 로딩 도구 [#deferred-tools]

여러 MCP 서버를 연결한 에이전트는 수십 개의 도구 정의를 쉽게 가지게 되며, 매 요청마다 이를 모두 전송하면 컨텍스트를 낭비하고 모델이 올바른 도구를 고르는 능력도 떨어집니다. 지연(deferred) 도구는 초기 요청에서 제외됩니다. 대신 에이전트에게는 도구 검색 도구가 제공되며, 에이전트는 필요할 때 이름이나 설명으로 지연 도구를 찾고, 찾은 도구를 대화가 끝날 때까지 사용할 수 있습니다.

### 프로그래밍 방식 도구 호출 [#programmatic-tool-calling]

MCP 도구(또는 서버 전체)에 **Programmatic** 옵션을 켜면, 모델은 해당 도구를 직접 호출하지 않습니다. 대신 Code Interpreter 샌드박스에서 도구를 함수처럼 호출하는 코드를 작성하므로, 답변을 하기 전에 반복 실행, 페이지네이션, 재시도, 결과 필터링을 수행할 수 있습니다. 이 방식은 "이 티켓 40개를 확인하고 미해결 건을 요약해 줘"와 같은 작업에 도움이 되며, 그렇지 않으면 모델을 거쳐 40번의 개별 도구 호출이 필요했을 작업입니다.

**프로그래밍 방식** 스위치는 코드 실행이 켜져 있을 때까지 비활성화된 상태로 유지되며, 코드 실행을 끄면 이 스위치도 해제됩니다. 샌드박스는 에이전트에 등록된 도구만 호출할 수 있습니다. 실행 중에는 코드 카드를 펼쳐 각 내부 도구 호출의 실시간 추적 기록을 확인할 수 있습니다. 이 추적 기록은 페이지를 새로 고치면 유지되지 않습니다. 이 기능은 기본적으로 꺼져 있으며, 관리자가 활성화해야 합니다.

### 백그라운드 도구 호출 [#background-tool-calls]

백그라운드 실행을 지원하는 도구는 작업 참조(task reference)를 즉시 반환하므로, 에이전트는 작업이 실행되는 동안에도 계속 작업할 수 있습니다. 작업이 완료되면 결과는 후속 턴에서 자동으로 전달되며(접을 수 있는 작업 카드로 표시됨), 또는 에이전트가 작업 도구를 사용해 진행 상황을 확인할 수도 있습니다. 백그라운드 출력과 파일은 원래의 도구 호출에 표시됩니다. 백그라운드에서 실행할 수 있는 도구는 다음과 같습니다:

- **Run Code**: 코드 및 셸 명령은 기본적으로 실행 대상이 됩니다. 실행 대상에서 제외하려면 설정에서 **Background execution**을 끄십시오.
- **MCP 도구**: 도구 또는 서버 전체를 **Background**로 표시합니다.
- **기타 도구 및 작업**: **백그라운드 실행**을 켜세요. OAuth를 사용하는 작업에서는 이 기능을 제공하지 않습니다.

이 스위치는 백그라운드 실행을 허용합니다. 다만 호출마다 모델이 실행 여부를 결정합니다. 백그라운드 작업은 이를 시작한 서버 프로세스에서 실행되며, 해당 프로세스가 종료되면 작업이 유실됩니다. 기능을 사용하려면 관리자가 먼저 활성화해야 합니다.

### Actions [#actions]

액션은 OpenAPI 스펙을 도구로 변환합니다. **Create new…**를 선택한 다음 **Actions**를 선택하고, 스키마를 붙여넣은 후 API에 인증이 필요하면 **Authentication**을 설정하세요. 스펙의 각 작업(operation)은 에이전트가 호출할 수 있는 도구가 됩니다.

OpenAI 모델을 사용하는 경우, 스펙의 작업(operation)에 `x-strict: true`를 추가하면 LibreChat이 해당 작업에 대해 엄격한 함수 호출(strict function calling)을 요청합니다. 엄격 모드(strict mode)는 JSON Schema의 일부만 허용하므로, 자세한 내용은 OpenAI의 [구조화된 출력 가이드](https://platform.openai.com/docs/guides/structured-outputs)를 참고하세요.

Actions는 관리자가 허용한 도메인에만 접근할 수 있으며, 명시적으로 허용하지 않는 한 사설 네트워크 주소는 차단됩니다.

### Skills [#skills]

빌더의 **Skills** 섹션은 에이전트가 사용할 수 있는 [Skills](/docs/features/skills)를 제어합니다: **Off**(끄기), **All**(활성화된 모든 Skill), 또는 **Selected**(추가한 Skill만).

### Memory [#memory]

**메모리**를 사용하면 에이전트가 사용자가 무엇인가를 기억하거나 잊으라고 요청할 때 사용자에 대한 메모리를 저장, 업데이트, 삭제할 수 있습니다. 이를 사용하려면 인스턴스에서 메모리가 설정되어 있고 사용자의 역할에 대해 허용되어 있어야 합니다. 기본적으로 에이전트는 사용자의 개인 메모리를 다른 채팅과 공유합니다. 에이전트에게 자체 메모리를 부여하여 에이전트만 읽고 쓰도록 하려면 **이 에이전트에 대해 메모리를 별도로 유지**를 켜세요. 자세한 내용은 [메모리](/docs/features/memory)를 참조하세요.

### 사용자 질문 및 도구 승인 [#ask-user-and-tool-approval]

**Ask User**는 에이전트가 실행 도중 일시 정지하여 질문을 하고 답변을 기다릴 수 있게 합니다. 한 번의 일시 정지에는 최대 네 개의 질문이 포함될 수 있으며, 질문은 한 번에 하나씩 표시되고 **Back**과 **Next**로 이동할 수 있습니다. 각 질문에는 자유 형식의 답변을 입력하거나 에이전트가 제시한 선택지 중 하나를 고를 수 있습니다. **Skip**을 누르면 모든 질문을 건너뜁니다. 답변을 제출하는 즉시 실행이 재개되며, 재시작 중에 실행을 중지하더라도 입력한 답변은 그대로 유지됩니다.

관리자는 특정 도구가 실행되기 전에 승인을 요구하도록 설정할 수도 있습니다. 이 경우 실행이 일시 중지되며, 메시지 입력창 위의 패널에서 호출 내용을 검토할 수 있습니다(승인, 거부, 또는 일부 도구의 경우 인수 편집). 검토가 끝나면 실행이 계속됩니다. 관리자가 에이전트별 승인 모드를 활성화한 경우, 에이전트의 각 도구에는 **Tool approval mode**가 적용됩니다. 옵션은 **Use inherited policy**, **Always ask**, **Always approve**, **Ask once per chat**, **Ask once, then always approve**입니다. 관리자 규칙은 이 설정 위에 계속 적용되며, **Reset my remembered approvals**를 선택하면 이전에 승인한 내용이 모두 지워집니다.

### 기타 도구 [#other-tools]

**Tools** 카테고리에는 관리자가 활성화한 기본 제공 통합 기능이 포함되어 있습니다. 예를 들어 [이미지 생성](/docs/features/image_gen), [Wolfram](/docs/configuration/tools/wolfram), [Google 검색](/docs/configuration/tools/google_search), [Azure AI Search](/docs/configuration/tools/azure_ai_search) 등이 있습니다. 각 기능은 개별적으로 설정해야 하며, 자세한 내용은 [Tools](/docs/configuration/tools)를 참고하세요.

## 다른 에이전트와 함께 작업하기 [#working-with-other-agents]

**서브에이전트**는 에이전트가 집중된 하위 작업을 별도의 컨텍스트 창에서 자기 자신의 새 복사본이나 다른 에이전트에게 넘길 수 있게 합니다. 결과만 돌아오므로 긴 도구 출력이 기본 대화에 쌓이지 않습니다. 자세한 내용은 [서브에이전트](/docs/features/subagents)를 참조하세요.

### Handoffs [#handoffs]

**핸드오프(Handoffs)**는 나열한 각 에이전트마다 전환 도구(transfer tool)를 에이전트에 제공하므로, 대화 주제에 따라 전문 에이전트에게 대화를 넘길 수 있습니다. 각 핸드오프에는 설명(언제 전환할지)과 패스스루 콘텐츠(에이전트가 생성하여 전달할 내용)를 추가할 수 있으며, 해당 콘텐츠가 전달되는 매개변수 이름을 변경할 수 있습니다(기본값은 `instructions`). 에이전트는 최대 10개의 핸드오프를 가질 수 있습니다. 핸드오프는 항상 사용할 수 있으며, 관리자 설정에 의존하지 않습니다.

### 에이전트 체인 [#agent-chain]

에이전트 체인은 더 이상 사용되지 않습니다(deprecated). 기존 체인은 계속 실행되며, 빌더의 **Advanced Settings** 아래에 **Remove chain** 버튼과 함께 표시되지만, 새로운 체인은 만들 수 없습니다. 대신 서브에이전트(subagents) 또는 핸드오프(handoffs)를 사용하세요.

## 최대 에이전트 단계 [#max-agent-steps]

**고급 설정**에는 에이전트가 최종 답변을 내놓기 전까지 수행할 수 있는 단계 수를 제한하는 **최대 에이전트 단계** 필드가 있습니다. 한 단계는 모델 요청 한 번 또는 도구 호출 한 라운드를 의미하므로, 도구 호출 한 번은 보통 세 단계를 소모합니다. 즉, 요청, 도구 라운드, 그리고 후속 요청입니다.

비워 두면 서버 기본값이 사용되며, 관리자가 값을 변경하지 않았다면 기본값은 50입니다. 관리자는 이 필드에 입력할 수 있는 최대값(상한)도 설정할 수 있습니다.

턴의 단계(step)가 모두 소진되면, 에이전트가 지금까지 수행한 작업은 그대로 유지됩니다. 이때 메시지에는 **계속하기(Keep going)**(새로운 예산으로 새 턴 시작)와 **지금 답변하기(Answer now)**(추가 도구 없이 이미 수행한 작업을 바탕으로 에이전트가 답변) 옵션이 표시됩니다. 긴 도구 체인에서 이런 상황이 자주 발생한다면 제한값을 높이는 것을 고려하세요.

## 긴 실행 이후 따라가기 [#following-a-long-run]

도구 카드는 호출이 대기 중일 때(예: 승인 대기) **Preparing**을 표시하고, 결과가 돌아올 때까지 **Calling**을 표시합니다. 셸 출력은 터미널 스타일로 표시되며 마지막 15줄까지만 접혀 보입니다. **Show more**를 클릭하면 전체 출력이 펼쳐지며, 실패한 명령은 종료 코드, 시그널 또는 타임아웃을 함께 표시합니다.

### 활동 그룹 [#activity-groups]

관리자가 기능을 켜 두었다면, 추론과 도구 호출의 각 구간이 생성된 한 줄 헤더 아래로 접힙니다. 따라서 도구 호출이 30번 있는 실행도 몇 줄의 헤더로 보입니다. 헤더를 펼치면 그 안의 호출을 볼 수 있습니다. 두 번째 수준에서는 여러 그룹을 요약이 포함된 단계로 묶을 수 있어, 긴 실행에 개요가 생깁니다. 두 그룹이 완료되면 요약이 도착할 때까지 가장 최근 헤더가 대신 표시된 상태로 즉시 함께 접힙니다. 최종 답변은 항상 접힘 바깥에 유지되며, 단계 내에서 생성된 파일은 숨겨지지 않고 해당 단계 아래에 한 줄로 표시됩니다. [Smooth Streaming](/docs/features/smooth_streaming)이 켜져 있으면 접힘 동작에 애니메이션이 적용되며, 기기에서 동작 감소를 요청한 경우에는 예외입니다.

실시간 추론 레이블도 관련 옵션입니다. 일반적인 **Thinking** 제목 대신, 추론 블록에 모델이 작업 중인 내용을 짧게 보여주는 요약이 실시간으로 갱신되어 표시됩니다.

헤더, 단계 요약, 추론 레이블은 각각 추가 모델 호출을 발생시키며, 다른 사용량과 마찬가지로 기록됩니다. 관리자는 [에이전트 활동 그룹](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups)과 [실시간 추론 레이블](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#live-reasoning-labels)에서 이를 설정할 수 있습니다.

## 스티어링 및 대기열 메시지 [#steering-and-queued-messages]

에이전트가 답변하는 동안에도 메시지를 계속 보낼 수 있습니다:

- **Steer**는 현재 실행 중인 작업의 다음 안전한 지점에 메시지를 끼워 넣어, 에이전트가 작업이 끝나기 전에 방향을 조정할 수 있도록 합니다.
- **인터럽트**는 진행 중인 도구 호출과 추론을 취소하고, 이미 완료된 작업은 그대로 유지한 채 입력하신 메시지를 이어서 처리합니다. LibreChat 외부에서 이미 발생한 작업의 효과는 되돌릴 수 없습니다. 제공자의 내장 검색을 사용하는 실행 등 일부 실행은 인터럽트할 수 없으며, 이 경우 메시지는 스티어(steer)로 대기합니다.
- **Queue**는 메시지를 보관했다가 답변이 완료되면 일반 턴으로 전송합니다.

**생성 중에** **Enter 키 동작**(**설정 > 채팅**에서 지정)이 기본값을 정하며, 전송 버튼 메뉴에서 메시지별로 이를 재정의할 수 있습니다. `Alt + Enter`는 생성을 중단합니다. 대기 중인 메시지는 입력창 위에 표시되며, 여기에서 편집, 삭제, 순서 변경, **지금 전송**, 또는 **지금 중단**을 할 수 있습니다. 파일과 인용된 발췌문은 메시지와 함께 전송되며, `$`로 선택한 스킬은 다음 전체 턴까지 대기합니다. 저장된 에이전트 채팅에서 대기 중인 메시지는 서버에 저장되므로 브라우저를 닫아도 유지됩니다.

채팅에는 메시지를 최대 100개까지 대기열에 넣을 수 있으며, 각 메시지는 16,000자와 파일 10개까지 포함할 수 있습니다. 실행 하나당 보류 중인 steer는 최대 10개까지 가능합니다. 영수증과 제어 기능에 대한 자세한 내용은 [Composer](/docs/features/composer)를 참고하세요.

## 채팅의 파일 [#files-in-a-chat]

에이전트와 대화할 때, 첨부 메뉴에서 다음 항목을 사용할 수 있습니다:

- **이미지 업로드**: 비전 기능을 위해 모델로 전송됩니다.
- **Upload as Text**: 전체 텍스트는 이 대화에만 포함됩니다. [Upload as Text](/docs/features/upload_as_text)를 참고하세요.
- **File Search용 업로드**: 에이전트의 자체 File Search 파일과 마찬가지로 검색을 위해 인덱싱되지만, 이 채팅으로 범위가 한정됩니다.
- **코드 환경에 업로드**: 코드 실행(Run Code)을 위해 샌드박스에 복사됩니다. CSV, Excel, JSON 파일에 가장 적합합니다.

옵션은 해당 기능이 활성화된 경우에만 표시됩니다.

## 공유 및 권한 [#sharing-and-permissions]

에이전트는 공유하기 전까지 작성자에게만 비공개입니다. 빌더 하단의 **Share**를 클릭하면 사용자, 그룹 또는 역할에게 접근 권한을 부여할 수 있으며, 각각 세 가지 역할 중 하나를 가집니다:

| 역할 | 할 수 있는 작업 |
| ---- | ---------------------------------------------------------------------------------------------------- |
| 뷰어 (Viewer) | 에이전트와 채팅할 수 있습니다. 빌더에서 열거나 에이전트의 지침, 도구, 파일을 볼 수 없습니다. |
| 편집자 (Editor) | 뷰어가 할 수 있는 모든 작업과 더불어 지침, 모델, 도구, 파일을 변경할 수 있습니다. |
| 소유자 (Owner) | 편집자가 할 수 있는 모든 작업과 더불어 에이전트를 삭제하고 공유 대상을 변경할 수 있습니다. |

**모든 사용자와 공유**를 선택하면 해당 에이전트를 인스턴스의 모든 사용자가 사용할 수 있으며, 이 기능을 사용하려면 공개 공유 권한이 필요합니다. 작성자와 관리자는 항상 전체 제어 권한을 유지합니다.

뷰어는 빌더에서 지침과 파일을 볼 수 없지만, 요청하면 모델이 대화에서 이를 그대로 반복할 수 있습니다. 뷰어가 절대 보아서는 안 되는 내용은 에이전트에 넣지 마십시오.

별도로, 지구본 버튼(**Remote Access**)은 [Agents API](/docs/features/agents_api)를 통해 누가 에이전트를 호출할 수 있는지를 제어합니다.

에이전트 카드에는 빌더에서 설정한 지원 연락처가 표시됩니다. 연락처가 없으면 소유자의 이름이 표시될 수 있지만, 연락처로 직접 입력하지 않은 경우 소유자의 이메일은 절대 표시되지 않습니다.

[Access Control](/docs/features/access_control)을 참고하여 사용자, 그룹, 역할이 어떻게 결합되는지 확인하세요.

### 관리자 제어 [#administrator-controls]

역할별로 에이전트를 사용, 생성, 공유, 공개 공유할 수 있는지 여부는 [관리자 패널](/docs/features/admin_panel)에서 역할마다 설정합니다. 관리자는 에이전트 빌더 하단에 있는 **Admin Settings** 버튼을 통해서도 동일한 스위치를 역할별로 설정할 수 있습니다. 단일 테넌트 인스턴스에서는 가장 먼저 등록된 계정이 관리자가 됩니다. 관리자를 추가하려면 [다른 관리자 승격](/docs/configuration/access_control#promote-another-admin)을 참고하세요.

## Agent 마켓플레이스 [#agent-marketplace]

**Agent Marketplace**는 사이드바에 있으며, 사용자의 역할에 권한이 있는 경우 사용 가능한 에이전트 목록을 보여 줍니다. 이름이나 설명으로 검색하고, 카테고리(**Top Picks**, **All**, 또는 특정 카테고리)로 필터링하며, **Sort by**에서 정렬 순서를 **Newest first**, **Oldest first**, **Popular**, **By creator name** 중에서 선택해 변경할 수 있습니다. **My agents**에서는 본인이 만든 에이전트만 표시됩니다. 검색, 정렬, 필터 설정은 URL에 유지되므로 해당 보기를 북마크하거나 공유할 수 있습니다.

카드를 클릭하면 세부 정보와 함께 **Pin**(고정) 또는 **Unpin**(고정 해제), **Copy Link**(에이전트와 새 채팅을 여는 링크 복사), **Start Chat**(채팅 시작) 작업을 사용할 수 있습니다. 에이전트의 대화 시작 문구 중 하나를 클릭하면 해당 프롬프트가 메시지 입력창에 전송되지 않은 상태로 입력된 새 채팅이 열리므로, 전송하기 전에 내용을 수정할 수 있습니다.

## Agents API [#agents-api]

에이전트는 OpenAI 호환 API를 통해 스크립트와 다른 앱에서도 호출할 수 있으며, 신뢰할 수 있는 서비스에 의해 관리되고 다른 시스템의 이벤트에 의해 트리거될 수 있습니다. [Agents API](/docs/features/agents_api)를 참조하세요. [Scheduled Chats](/docs/features/scheduled_chats)는 타이머에 따라 에이전트 실행을 시작하며, [Agent Plugins](/docs/features/agent_plugins)를 사용하면 운영자가 스킬과 MCP 서버를 하나의 패키지로 묶어 에이전트에 배포할 수 있습니다.

## 설정 [#setup]

에이전트는 기본적으로 활성화되어 있습니다. 관리자는 [에이전트 엔드포인트 구성](/docs/configuration/librechat_yaml/object_structure/agents)에서 제공할 기능, 단계 제한, 허용된 제공자를 선택하고, [Actions 구성](/docs/configuration/librechat_yaml/object_structure/actions)에서 Actions가 접근할 수 있는 도메인을 지정할 수 있습니다. v0.8.0-rc3 이전 버전에서 업그레이드한 인스턴스는 [권한 마이그레이션](/docs/configuration/access_control#migrating-from-pre-acl-versions)이 필요합니다.
