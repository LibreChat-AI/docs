---
title: 对话拉取请求
icon: GitPullRequest
description: 在聊天标题栏和侧边栏中查看聊天代码工作区的拉取请求，包括其大小、状态和 CI 检查。
---

当智能体在已附加的代码工作区中处理代码仓库时,LibreChat 会查找该工作区所在分支对应的拉取请求,并将其显示在聊天界面旁边。您无需离开对话,即可查看它是否已准备好合并、检查是否通过,并直接跳转到该请求。它支持 GitHub、GitLab(称为合并请求,即 merge request)以及 Bitbucket Cloud,每个部署实例只能使用一个提供商。

只有在已附加的工作区中运行代码的聊天才能创建拉取请求。普通聊天,或尚未报告分支的工作区,不会显示任何内容。

## 在聊天标题栏中 [#in-the-chat-header]

在宽屏上,标题栏左侧有一个标签(chip),其中显示拉取请求图标、角落上的一个小型 CI 状态点以及拉取请求标题。将鼠标悬停或聚焦于该标签时,会打开一张包含详细信息的卡片。只要指针或键盘焦点仍在卡片内,该卡片就会保持打开状态。

在小屏幕上不会显示标签。请打开页眉的三点菜单,选择 `PR #number` 条目(GitLab 上为 `MR !number`),即可在对话框中显示相同的卡片。

页眉会自动保持最新状态:在检查进行中或服务提供方仍在确认分支能否合并时,大约每 20 秒重新检查一次;其他情况下大约每 60 秒检查一次。拉取请求被合并或关闭且没有任何正在运行的任务后,它将停止检查。

## 在侧边栏中 [#in-the-sidebar]

带有拉取请求的对话在其行末尾同样显示相同的图标和 CI 状态点。该行保留对话自身的标题。将鼠标悬停在该行上,或聚焦或点击该标记,即可在旁边打开卡片;点击该标记不会打开对话。

<ThemeImage
  light="/images/pull-requests/side-rows-light.png"

  alt="侧边栏中带有拉取请求标记的行:可以合并、存在冲突且检查失败、草稿且检查运行中,以及已合并的拉取请求"

侧边栏不会轮询。每一行的新鲜度取决于列表上次加载的时间;当你回到窗口且其数据超过一分钟未更新时,该行会刷新。如果某个已找到的拉取请求刷新失败,标记会保留,卡片会显示"无法刷新拉取请求",并附带一个 **Retry** 按钮。对于从未找到拉取请求的对话,即使查询失败,也不会显示任何标记。

## 阅读卡片 [#reading-the-card]

该卡片显示 `PR #number`(GitLab 上为 `MR !number`),新增行以绿色显示,删除行以红色显示,并包含一个 **Open in GitHub**、**Open in GitLab** 或 **Open in Bitbucket** 链接、标题,以及两个徽章。

- 状态:Open、Conflicts、Draft、Merged 或 Closed。当分支无法干净合并时,Conflicts 会替代 Open。
- Checks:通过(Passing)、失败(Failing)、运行中(Running)或无(None)。在 GitLab 上,这指的是头部流水线(head pipeline),且仅当它针对当前提交运行时才会显示。在 Bitbucket 上,这指的是提交状态(commit statuses)。

图标颜色和 CI 圆点都能一目了然地传达相同的信息:

| 拉取请求 | 图标 | CI 指示点 |
| ------------------------------------ | ------- | --------------- |
| 已打开，可以合并 | 绿色 | 取决于检查结果 |
| 已打开，可合并性尚未确定 | 中性 | 取决于检查结果 |
| 已打开，存在合并冲突 | 红色 | 取决于检查结果 |
| 草稿 | 中性 | 取决于检查结果 |
| 已合并 | 紫色 | 无 |
| 已关闭 | 中性 | 无 |

圆点为绿色表示检查通过,红色表示检查失败,琥珀色表示检查正在运行。当仓库未报告任何检查时不显示圆点。失败的检查优先级高于仍在运行的检查。

## 您看到的是哪个拉取请求 [#which-pull-request-you-see]

工作区会显示聊天最后运行时所在的代码仓库、分支和提交,LibreChat 会查找来自该分支的拉取请求(Pull Request)。

- 如果聊天自身的命令输出中打印了同一仓库中拉取请求的链接(例如 `gh pr create` 打印的 URL),则会使用该拉取请求,前提是它来自该聊天所在的分支。
- 否则，对于同一分支，未关闭的拉取请求优先于已关闭的拉取请求，因此复用分支名称时，较早的已关闭拉取请求不会掩盖当前的拉取请求。
- 只有当拉取请求包含聊天最后一次运行时所对应的提交,该拉取请求才算有效。删除分支并复用其名称,并不会恢复旧的拉取请求。
- 一个全新的、没有任何提交的分支不匹配任何内容。

服务器无权查询的仓库与没有拉取请求的仓库行为完全相同:不显示标记,也不报错。

## 连接您自己的账户 [#connect-your-own-account]

如果您的管理员已完成设置,您可以使用自己的 GitHub、GitLab 或 Bitbucket 账户查询拉取请求(Pull Request)。打开 **Settings**(设置),进入 **Account**(账户),在 **Connected accounts**(已连接的账户)下,点击 **Pull request account**(拉取请求账户)旁的 **Connect**(连接)。此时会在服务提供方打开登录窗口;请授权该窗口,授权完成后该行将显示 **Connected**(已连接)。如果窗口没有打开,请允许 LibreChat 弹出窗口,然后重试。

一旦连接成功,查询将使用您的账户,因此您可以查看任何您有读取权限的仓库中的拉取请求,并使用您自己的速率限制。点击 **Disconnect** 即可断开连接,您随时可以重新连接。如果服务器无法刷新您的连接(例如服务提供商宕机),您的拉取请求将显示为不可用,而不会悄悄切换到服务器的令牌。如果您在服务提供商处撤销了应用授权,LibreChat 会移除该连接,您将恢复为未连接状态。

如果该行显示 **Not in use**,说明您的管理员已关闭账户连接功能,查询不再使用您的账户。点击 **Disconnect** 即可移除已保存的连接。

## 设置 [#setup]

该功能默认开启,但在管理员为 LibreChat 提供令牌和可查询的仓库列表,或设置应用以便用户连接各自的账户之前,它将保持隐藏状态。该功能还需要一个附加的代码工作区,用于报告其 git 分支。请参阅 [Pull Requests 配置](/docs/configuration/pull_requests)。
