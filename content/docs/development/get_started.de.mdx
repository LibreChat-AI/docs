## Umgebung vorbereiten [#prepare-the-environment]

### Node.js und npm [#nodejs-and-npm]

Wenn Sie `nvm` verwenden, installieren und wählen Sie die empfohlene Node.js-Version aus, bevor Sie LibreChat installieren:

```sh filename="Use Node.js 24"
nvm install 24.22.1
nvm use 24.22.1
npm install -g npm@11.16.0
```

Die Datei `.nvmrc` im LibreChat-Repository ist die maßgebliche Quelle für die Node.js-Version; das Ausführen von `nvm use` im Stammverzeichnis des Repositorys wählt diese Version aus.

Überprüfen Sie, ob Ihre Shell die erwarteten Versionen verwendet:

```sh filename="Check Node.js and npm"
node -v
npm -v
```

```txt filename="Expected versions"
v24.22.1
11.16.0
```

### GitHub [#github]

- Forken Sie das LibreChat-Repository: [https://github.com/LibreChat-AI/LibreChat/fork](https://github.com/LibreChat-AI/LibreChat/fork)

- Clone your fork and add the original repository as `upstream`. Contributions branch from and target `dev`; `main` only moves at release time.

```sh filename="Clone your fork and sync dev"
git clone https://github.com/username/LibreChat.git
cd LibreChat
git remote add upstream https://github.com/LibreChat-AI/LibreChat.git
git fetch upstream dev
git checkout -B dev upstream/dev
```

- Erstelle einen aussagekräftigen, schrägstrich-basierten Branch ausgehend von `dev`:

```sh filename="Create your working branch"
git checkout -b new/feature/x
```

> Ersetze `username` und den Branch-Namen durch deine eigenen Angaben. Verwende `npm run update` nicht, um einen Entwicklungs-Branch zu aktualisieren; dieser Befehl ist der Updater für Self-Hosting und wechselt auf `main`.

### In VS Code öffnen [#open-in-vs-code]

- Nach dem Klonen deines Branch:
  ```sh filename="Navigate to LibreChat folder"
  cd LibreChat
  ```
  ```sh filename="Open in VS Code"
  code .
  ```

### LibreChat vorbereiten [#prepare-librechat]

- Öffnen Sie das Terminal in VS Code mit `ctrl`+`shift`+`` ```

  > Alternativ können Sie `ctrl`+`j` verwenden, um den unteren Bereich zu öffnen und das Terminal auszuwählen.

- ```sh filename="Install LibreChat dependencies"
  npm run smart-reinstall
  ```

  > Falls Sie gerade die Node.js- oder npm-Versionen geändert haben, verwenden Sie einmal `npm run reinstall` für eine saubere Neuinstallation.

- ```sh filename="Build all compiled code"
  npm run build
  ```

- .env Konfiguration
  - Erstellen Sie die `.env` Datei. Falls Sie noch keine haben, duplizieren Sie die `.env.example` und konfigurieren Sie diese.

- Git-Hooks
  - `npm install` richtet Husky-Pre-Commit-Prüfungen ein, die den CI-Job Static Checks lokal auf die Dateien jedes Commits ausführen (ESLint, Prettier, Importreihenfolge, zirkuläre Abhängigkeiten). Setze `HUSKY=0`, um dies zu deaktivieren, und führe die Prüfungen manuell mit `npm run static-checks` aus.

<Callout type="warning" title="Warnung">
  Die Standardwerte in `.env.example` sind normalerweise in Ordnung, mit Ausnahme von `MONGO_URI`. Geben Sie Ihren eigenen Wert an.
Stellen Sie sicher, dass Sie MongoDB installieren und `MONGO_URI` korrekt konfigurieren, um eine Verbindung zu Ihrer MongoDB-Instanz herzustellen. Verwenden Sie [MongoDB Community Server](https://www.mongodb.com/try/download/community) oder [MongoDB Atlas Cloud](https://www.mongodb.com/cloud/atlas/register).
</Callout>

### Entwicklungs-Workflow [#development-workflow]

Für effizientes Arbeiten mit LibreChat verwenden Sie diese Befehle:

- **Backend starten:**
  - Verwenden Sie `npm run backend` für den normalen Betrieb.
  - Für die aktive Entwicklung verwenden Sie `npm run backend:dev`, um Änderungen zu überwachen.
  - Zugriff unter `http://localhost:3080/`.

- **Frontend im Entwicklungsmodus ausführen:**
  - **Stellen Sie sicher, dass das Backend läuft.**
  - Verwenden Sie `npm run frontend:dev`, um Frontend-Änderungen zu überwachen.
  - Aufrufen unter `http://localhost:3090/`.

<Callout type="tip" title="Profi-Tipps">
  - Für Echtzeit-Aktualisierungen während der Frontend-Entwicklung führen Sie `npm run frontend:dev` aus, damit Frontend-Änderungen auf Port `3090` aktualisiert werden.
  - Setzen Sie `DEBUG_CONSOLE=true` in der `.env` für ausführliche Server-Ausgaben in der Konsole.
</Callout>

## Commit, Push, Pull Request (PR) [#commit-push-pull-request-pr]

### Einen Commit erstellen [#make-a-commit]

**Commits** markieren logische Checkpoints in der Entwicklung. Verwende Conventional-Commit-Nachrichten, die mit einem Typ wie `feat`, `fix`, `docs` oder `refactor` beginnen, gefolgt von einer kurzen Zusammenfassung.

**Beispiel:**

```bash filename=" "
git add .
git commit -m "feat: Add login functionality"
```

### Änderungen übertragen [#push-changes]

**Push** die Änderungen nach Abschluss eines Features oder der Behebung eines Fehlers in das Remote-Repository.

**Beispiel:**

```bash filename=" "
git push origin feature-branch-name
```

### Einen Pull Request (PR) erstellen [#create-a-pull-request-pr]

**Pull Request** führt Änderungen aus einem Feature-Branch in den `dev`-Branch zusammen.

1. Ziehe die neuesten Änderungen von `dev` und löse Konflikte auf.
2. Aktualisierten Feature-Branch pushen.
3. Stellen Sie sicher, dass der Code den Projektrichtlinien entspricht.

**Beispiel:**

```bash filename=" "
git fetch upstream dev
git checkout feature-branch-name
git rebase upstream/dev
# Resolve conflicts if any
git push origin feature-branch-name
# Open PR on GitHub
```

Rufen Sie Ihren Fork im Browser auf und klicken Sie auf „Contribute“. Stellen Sie dabei sicher, dass der Pull Request auf `dev` ausgerichtet ist.

<Callout type="info" title="Hinweis:">
  Erstellen Sie eine detaillierte PR-Beschreibung, in der die Änderungen und deren Mehrwert erläutert werden. Verweisen Sie auf zugehörige Issues.
</Callout>

<Callout type="tip" title="Tipp">
  Verwenden Sie GitHub Desktop, um Änderungen nachzuverfolgen.
</Callout>

<Callout type="warning" title="Warnung">
  Wenn `git commit` aufgrund von ESLint-Fehlern fehlschlägt, verstehen und beheben Sie das Problem.
</Callout>

## Commits sicher rückgängig machen [#revert-commits-safely]

Um Änderungen in einem Feature-Branch rückgängig zu machen, befolgen Sie diese Schritte mit Vorsicht:

- ```bash filename="1. Update local repository from feature branch:"
  git pull origin feature-branch-name
  ```

- ```bash filename="2. Review commit history to determine commits to revert:"
  git log
  ```

- ```bash filename="3. Start an interactive rebase for 'N' commits to revert:"
  git rebase -i HEAD~N
  ```

  > Ersetzen Sie `pick` durch `drop` für Commits, die entfernt werden sollen. Speichern und schließen Sie den Editor.

- ```bash filename="4. Force push changes to remote repository:"
  git push --force-with-lease origin feature-branch-name
  ```
