## Ortamı Hazırlayın [#prepare-the-environment]

### Node.js ve npm [#nodejs-and-npm]

`nvm` kullanıyorsanız, LibreChat'i yüklemeden önce önerilen Node.js sürümünü yükleyin ve seçin:

```sh filename="Use Node.js 24"
nvm install 24.22.1
nvm use 24.22.1
npm install -g npm@11.13.0
```

`.nvmrc` dosyası, LibreChat deposunda Node.js sürümünün tek doğru kaynağıdır; depo kök dizininde `nvm use` komutunu çalıştırmak bu sürümü seçer.

Kabuğunuzun beklenen sürümleri kullandığını doğrulayın:

```sh filename="Check Node.js and npm"
node -v
npm -v
```

```txt filename="Expected versions"
v24.22.1
11.13.0
```

### GitHub [#github]

- LibreChat deposunu fork'layın: [https://github.com/LibreChat-AI/LibreChat/fork](https://github.com/LibreChat-AI/LibreChat/fork)

- Clone your fork and add the original repository as `upstream`. Contributions branch from and target `dev`; `main` only moves at release time.

```sh filename="Clone your fork and sync dev"
git clone https://github.com/username/LibreChat.git
cd LibreChat
git remote add upstream https://github.com/LibreChat-AI/LibreChat.git
git fetch upstream dev
git checkout -B dev upstream/dev
```

- Açıklayıcı, eğik çizgi (slash) içeren bir dal (branch) oluşturun, kaynak olarak `dev` dalını kullanın:

```sh filename="Create your working branch"
git checkout -b new/feature/x
```

> Değiştirin `username` ve dal adını kendi bilgilerinizle. Bir geliştirme dalını yenilemek için `npm run update` komutunu kullanmayın; bu komut self-host güncelleyicisidir ve `main` dalına geçiş yapar.

### LibreChat'i Hazırlayın [#prepare-librechat]

- VS Code'da terminali `ctrl`+`shift`+`` ` `` ile açın.

  > Alternatif olarak, alt bölmeyi açmak ve terminali seçmek için `ctrl`+`j` tuşlarını kullanın.

- ```sh filename="Install LibreChat dependencies"
  npm run smart-reinstall
  ```

  > Eğer Node.js veya npm sürümlerini yeni değiştirdiyseniz, temiz bir kurulum için bir kez `npm run reinstall` komutunu kullanın.

- ```sh filename="Build all compiled code"
  npm run build
  ```

- .env Yapılandırması
  - `.env` dosyasını oluşturun. Eğer bir tane yoksa, `.env.example` dosyasını kopyalayın ve yapılandırın.

- Git hooks
  - `npm install` komutu, her commit'deki dosyalar üzerinde yerel olarak Static Checks CI işini çalıştıran husky pre-commit kontrollerini kurar (ESLint, Prettier, import sırası, döngüsel bağımlılıklar). Bu kontrolleri devre dışı bırakmak için `HUSKY=0` değerini ayarlayın ve kontrolleri elle çalıştırmak için `npm run static-checks` komutunu kullanın.

<Callout type="warning" title="Uyarı">
  `.env.example` dosyasındaki varsayılan değerler, `MONGO_URI` hariç genellikle uygundur. Kendi değerinizi sağlayın.
  MongoDB'yi yüklediğinizden ve MongoDB örneğinize bağlanmak için `MONGO_URI` değerini doğru şekilde yapılandırdığınızdan emin olun. [MongoDB Community Server](https://www.mongodb.com/try/download/community) veya [MongoDB Atlas Cloud](https://www.mongodb.com/cloud/atlas/register) kullanın.
</Callout>

### Geliştirme İş Akışı [#development-workflow]

LibreChat üzerinde verimli çalışmak için şu komutları kullanın:

- **Backend'i Başlatma:**
  - Normal çalışma için `npm run backend` komutunu kullanın.
  - Aktif geliştirme için, değişiklikleri izlemek üzere `npm run backend:dev` komutunu kullanın.
  - `http://localhost:3080/` adresinden erişin.

- **Frontend'i Geliştirme Modunda Çalıştırma:**
  - **Backend'in çalıştığından emin olun.**
  - Frontend değişikliklerini izlemek için `npm run frontend:dev` komutunu kullanın.
  - `http://localhost:3090/` adresinden görüntüleyin.

<Callout type="tip" title="Profesyonel İpuçları">
  - Frontend geliştirme sırasında gerçek zamanlı güncellemeler için `npm run frontend:dev` komutunu çalıştırın; böylece frontend değişiklikleri `3090` portunda yenilenecektir.
  - Konsolda ayrıntılı sunucu çıktısı almak için `.env` dosyasında `DEBUG_CONSOLE=true` ayarını yapın.
</Callout>

## Commit, Push, Pull Request (PR) [#commit-push-pull-request-pr]

### Bir Commit Yapın [#make-a-commit]

**Commit'ler** geliştirmede mantıksal kontrol noktalarını işaretler. `feat`, `fix`, `docs` veya `refactor` gibi bir tür ile başlayan ve ardından kısa bir özet içeren conventional commit mesajları kullanın.

**Örnek:**

```bash filename=" "
git add .
git commit -m "feat: Add login functionality"
```

### Değişiklikleri Gönder (Push) [#push-changes]

Bir özellik tamamlandıktan veya bir sorun giderildikten sonra değişiklikleri uzak depoya **Push** edin.

**Örnek:**

```bash filename=" "
git push origin feature-branch-name
```

### Bir Pull Request (PR) Oluşturun [#create-a-pull-request-pr]

**Pull Request**, özellik dalındaki değişiklikleri `dev` dalına birleştirir.

1. `dev` dalındaki en son değişiklikleri çekin ve çakışmaları çözün.
2. Güncellenmiş özellik dalını (feature branch) push'layın.
3. Kodun proje yönergelerine uygun olduğundan emin olun.

**Örnek:**

```bash filename=" "
git fetch upstream dev
git checkout feature-branch-name
git rebase upstream/dev
# Resolve conflicts if any
git push origin feature-branch-name
# Open PR on GitHub
```

Fork'unuza bir tarayıcıda erişin ve "Contribute" seçeneğine tıklayın; pull request'in `dev` dalını hedeflediğinden emin olun.

<Callout type="info" title="Not:">
  Değişiklikleri ve bunların değerini açıklayan ayrıntılı bir PR açıklaması sağlayın. İlgili sorunlara (issue) referans verin.
</Callout>

<Callout type="tip" title="İpucu">
  Değişiklikleri takip etmek için GitHub Desktop kullanın.
</Callout>

<Callout type="warning" title="Uyarı">
  Eğer `git commit` işlemi ESLint hataları nedeniyle başarısız olursa, sorunu anlayın ve düzeltin.
</Callout>

## Commit'leri Güvenli Bir Şekilde Geri Alma [#revert-commits-safely]

Bir özellik dalındaki (feature branch) değişiklikleri geri almak için şu adımları dikkatlice izleyin:

- ```bash filename="1. Update local repository from feature branch:"
  git pull origin feature-branch-name
  ```

- ```bash filename="2. Review commit history to determine commits to revert:"
  git log
  ```

- ```bash filename="3. Start an interactive rebase for 'N' commits to revert:"
  git rebase -i HEAD~N
  ```

  > Kaldırılacak commit'ler için `pick` ifadesini `drop` ile değiştirin. Düzenleyiciyi kaydedip çıkın.

- ```bash filename="4. Force push changes to remote repository:"
  git push --force-with-lease origin feature-branch-name
  ```
