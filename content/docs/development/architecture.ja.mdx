## Monorepo 構造 [#monorepo-structure]

LibreChatは、明確に定義されたワークスペースの境界を持つモノレポとして構成されています：

| ワークスペース | 言語 | 側 | 依存関係 | 目的 |
| -------------- | ---- | ---- | -------- | ---- |
| `/api` | JS (legacy) | バックエンド | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Express サーバー — ここでの変更は最小限に抑える |
| `/packages/api` | **TypeScript** | バックエンド | `packages/data-schemas`, `packages/data-provider` | 新しいバックエンドコードはここに置く（TS のみ、`/api` から利用される） |
| `/packages/data-schemas` | TypeScript | バックエンド | `packages/data-provider` | データベースのモデル／スキーマ。バックエンドプロジェクト間で共有可能 |
| `/packages/data-provider` | TypeScript | 共有 | — | 共有 API 型、エンドポイント、data-service — フロントエンドとバックエンドの両方で使用 |
| `/client` | TypeScript/React | フロントエンド | `packages/data-provider`, `packages/client` | フロントエンドの SPA |
| `/packages/client` | TypeScript | フロントエンド | `packages/data-provider` | 共有フロントエンドユーティリティ |
| `/packages/chat` | TypeScript | フロントエンド | `packages/data-provider`, `packages/client` | `@librechat/chat`: チャットの状態、トランスポート、メッセージコンポーネント。`/client` から移行中。アプリ本体を import することは決してない |

### 主要な原則 [#key-principles]

- `/packages/api` 内の**すべての新しいバックエンドコードは TypeScript で記述する必要があります**。
- `/api` への変更は最小限に留めてください。`/packages/api` を呼び出す薄い JS ラッパーにしてください。
- データベース固有の共有ロジックは `/packages/data-schemas` に配置します。
- フロントエンド/バックエンドで共有されるAPIロジック（endpoints、types、data-service）は、`/packages/data-provider` に配置します。

### ビルドとインストール [#build-and-install]

| コマンド | 用途 |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | 依存関係のインストール(lockfile が変更されている場合のみ)と Turborepo によるビルド |
| `npm run reinstall` | Node/npm のバージョンを変更した後、または依存関係の状態が怪しい場合のクリーンインストール |
| `npm run build` | Turborepo によるすべてのコンパイル対象コードのビルド(並列実行、キャッシュ利用) |
| `npm run frontend` | すべてのコンパイル対象コードを順次ビルド(従来方式のフォールバック) |
| `npm run build:data-provider` | 変更後に `packages/data-provider` を再ビルド |
| `npm run backend` | バックエンドサーバーを起動 |
| `npm run backend:dev` | ファイル監視付きでバックエンドを起動(開発用) |
| `npm run frontend:dev` | HMR 付きのフロントエンド開発サーバーを起動(ポート 3090、バックエンドの起動が必要) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- データベース: MongoDB
- バックエンドは `http://localhost:3080/` で、フロントエンドの開発サーバーは `http://localhost:3090/` で実行されます。

## 共有スキーマとコンポーネントの互換性 [#shared-schema-and-component-compatibility]

`v0.8.9-rc1`の共有パッケージはZod 4を使用しています。`librechat-data-provider`のスキーマを組み合わせて利用する場合は、互換性のあるZod 4のAPIを使用し、Zod 3の内部実装に依存するのではなく、エクスポートされたスキーマから入力型と出力型を推論してください。カスタムパッケージの利用者は、まとめて再ビルドしてください。overrideを使ってZod 3を強制することは、互換性のある方法ではありません。

クライアントパッケージは、従来の `Select`、`SelectDropDown`、`Dialog`、`DialogTemplate`、および Radix の `DropdownMenu` コントロールをエクスポートしなくなりました。現在の LibreChat の呼び出し元で使用されている、保守されている Dropdown ベースのセレクターとダイアログプリミティブを使用してください。詳しくは[アップグレードガイド](/docs/configuration/upgrade#shared-package-compatibility)をご覧ください。
