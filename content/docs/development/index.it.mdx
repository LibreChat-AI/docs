Docker è il metodo di installazione preferito per la maggior parte degli utenti, ma lo sviluppo locale di LibreChat dovrebbe utilizzare `npm`. Eseguire l'app direttamente sulla propria macchina offre un feedback più rapido, un debug più chiaro e l'accesso diretto ai workspace del monorepo senza dover ricostruire i container dopo ogni modifica.

## Toolchain consigliata [#recommended-toolchain]

Utilizza questa toolchain per lo sviluppo basato su npm:

| Strumento | Versione |
| --------- | -------- |
| Node.js | `v24.22.1` |
| npm | `v11.13.0` |
| MongoDB | Atlas o Community Server |

Node 24 soddisfa i requisiti di runtime di LibreChat per l'interoperabilità CommonJS con i pacchetti solo ESM, WebCrypto e la Fetch API. Se la tua shell riporta ancora una versione di Node più vecchia, esegui `nvm use 24.22.1` dalla repository di LibreChat prima di installare le dipendenze.

## Lavora nello spazio di lavoro giusto [#work-in-the-right-workspace]

LibreChat è un monorepo. Scegli il workspace più piccolo che gestisce il comportamento che stai modificando:

| Workspace | Da usare per |
| --- | --- |
| `/packages/api` | Nuovi servizi backend TypeScript, controller e logica condivisa lato server |
| `/api` | Integrazione del server Express legacy; mantenere le modifiche minime |
| `/packages/data-schemas` | Modelli di database, schemi e logica condivisa specifica per il database |
| `/packages/data-provider` | Tipi API condivisi, endpoint, query key e funzioni dei servizi dati |
| `/client` | Codice dell'applicazione React |
| `/packages/client` | Utilità frontend condivise |
| `/packages/chat` | `@librechat/chat`: stato della chat, trasporto e componenti dei messaggi |

## Comandi giornalieri [#daily-commands]

| Comando | Scopo |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall`     | Installa le dipendenze quando necessario e compila i workspace |
| `npm run reinstall`           | Installazione pulita dopo aver cambiato le versioni di Node/npm o quando lo stato delle dipendenze è sospetto |
| `npm run backend:dev`         | Avvia il backend con il monitoraggio dei file |
| `npm run frontend:dev`        | Avvia il server di sviluppo del frontend sulla porta `3090` |
| `npm run build:data-provider` | Ricompila il codice condiviso del data-provider dopo modifiche a API/tipi |
| `npm run build`               | Compila tutti i workspace tramite Turborepo |

## Risorse per lo sviluppo [#development-resources]

<Callout type="info" title="Risorse per lo sviluppo">
  - Se non hai familiarità con repository, fork, branch e pull request, inizia con la **[guida allo sviluppo collaborativo di GitHub](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/getting-started/about-collaborative-development-models)**.
  - Leggi le **[Linee guida per i contributori](https://github.com/LibreChat-AI/LibreChat/blob/main/.github/CONTRIBUTING.md)** prima di aprire una PR. Crea il branch a partire da `dev` e indirizza la tua pull request verso `dev`; `main` viene aggiornato solo al momento del rilascio.
  - Utilizza **[Contributor Setup](/docs/development/get_started)** per il flusso completo di configurazione locale.
  - Utilizza **[Code Standards and Conventions](/docs/development/conventions)** per i limiti dell'area di lavoro, l'ordine delle importazioni, la tipizzazione, i test e le regole del frontend.
</Callout>
