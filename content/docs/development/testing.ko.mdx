## 로컬 단위 테스트 [#local-unit-tests]

업데이트를 제출하기 전에 모든 단위 테스트를 통과하는지 확인하세요. 로컬에서 테스트를 실행하려면 다음 단계를 따르세요:

- API 테스트에서 사용하는 예제 테스트 환경 파일을 복사합니다:

  ```bash filename="create api/test/.env.test"
  cp api/test/.env.test.example api/test/.env.test
  ```

- `npm run test:client`
- `npm run test:api`
- `npm run test:packages:api`
- `npm run test:packages:data-provider`
- `npm run test:packages:data-schemas`
- `npm run test:packages:chat`
- `npm run test:all` 명령은 위에 나열된 모든 테스트 스위트를 순서대로 실행합니다.

### 정적 검사 [#static-checks]

커밋 시 husky pre-commit 훅을 통해 Static Checks CI 작업도 로컬에서 실행됩니다(옵트아웃하려면 `HUSKY=0`으로 설정하세요). 직접 실행하려면 `npm run static-checks`를 사용하고, 기준 브랜치와 비교하려면 `npm run static-checks -- --against origin/dev`를 사용하세요. `npm run static-checks:full`은 더 느린 검사 항목(TypeScript, 설정 마이그레이션 테스트, 사용되지 않는 i18n 키, 사용되지 않는 npm 패키지)을 추가로 실행합니다.

### 워크스페이스별 테스트 실행 [#running-tests-per-workspace]

테스트는 각 워크스페이스 디렉토리에서 Jest를 사용하여 실행됩니다. 패턴을 사용하여 특정 테스트 파일을 지정할 수 있습니다:

```bash
cd api && npx jest <pattern>
cd packages/api && npx jest <pattern>
cd packages/data-provider && npx jest <pattern>
cd packages/data-schemas && npx jest <pattern>
cd packages/chat && npx jest <pattern>
cd client && npx jest <pattern>
```

## 테스트 철학 [#testing-philosophy]

- 모의 객체(mock)보다는 실제 로직을 우선하십시오. 외부 HTTP API, 속도 제한이 있는 서비스, 비결정적 시스템 호출과 같이 로컬에서 제어할 수 없는 경우에만 모의 객체를 사용하십시오.
- 실제 함수가 예상된 인자로 호출되었는지 확인해야 할 때는 스파이(spies)를 사용하세요.
- MongoDB 기반 테스트를 위해 `mongodb-memory-server`를 사용하여 쿼리 및 스키마 유효성 검사가 실제 데이터베이스 동작을 기준으로 실행되도록 하세요.
- UI/데이터 흐름에 대한 로딩, 성공 및 오류 상태를 다룹니다.
