## Struktur Monorepo [#monorepo-structure]

LibreChat diatur sebagai monorepo dengan batasan ruang kerja yang terdefinisi dengan jelas:

| Workspace | Language | Sisi | Dependensi | Tujuan |
| --- | --- | --- | --- | --- |
| `/api` | JS (legacy) | Backend | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Server Express — minimalkan perubahan di sini |
| `/packages/api` | **TypeScript** | Backend | `packages/data-schemas`, `packages/data-provider` | Kode backend baru ditempatkan di sini (hanya TS, dikonsumsi oleh `/api`) |
| `/packages/data-schemas` | TypeScript | Backend | `packages/data-provider` | Model/skema database, dapat dibagikan di seluruh proyek backend |
| `/packages/data-provider` | TypeScript | Shared | — | Tipe API bersama, endpoint, data-service — digunakan oleh frontend dan backend |
| `/client` | TypeScript/React | Frontend | `packages/data-provider`, `packages/client` | SPA frontend |
| `/packages/client` | TypeScript | Frontend | `packages/data-provider` | Utilitas frontend bersama |
| `/packages/chat` | TypeScript | Frontend | `packages/data-provider`, `packages/client` | `@librechat/chat`: state chat, transport, dan komponen pesan yang sedang dipindahkan dari `/client`; tidak pernah mengimpor aplikasi |

### Prinsip Utama [#key-principles]

- **Semua kode backend baru harus menggunakan TypeScript** di `/packages/api`.
- Jaga perubahan `/api` seminimal mungkin — pembungkus JS tipis yang memanggil `/packages/api`.
- Logika bersama yang spesifik untuk basis data berada di `/packages/data-schemas`.
- Logika API bersama frontend/backend (endpoint, tipe, data-service) berada di `/packages/data-provider`.

### Membangun dan Menginstal [#build-and-install]

| Perintah | Tujuan |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | Instal dependensi (jika lockfile berubah) + build melalui Turborepo |
| `npm run reinstall` | Instal bersih setelah mengubah versi Node/npm atau ketika status dependensi diragukan |
| `npm run build` | Build semua kode yang dikompilasi melalui Turborepo (paralel, di-cache) |
| `npm run frontend` | Build semua kode yang dikompilasi secara berurutan (fallback lama) |
| `npm run build:data-provider` | Build ulang `packages/data-provider` setelah perubahan |
| `npm run backend` | Menjalankan server backend |
| `npm run backend:dev` | Menjalankan backend dengan pemantauan file (pengembangan) |
| `npm run frontend:dev` | Menjalankan server pengembangan frontend dengan HMR (port 3090, memerlukan backend yang sedang berjalan) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- Basis data: MongoDB
- Backend berjalan pada `http://localhost:3080/`; server pengembangan frontend pada `http://localhost:3090/`

## Kompatibilitas Skema dan Komponen Bersama [#shared-schema-and-component-compatibility]

Paket bersama `v0.8.9-rc1` menggunakan Zod 4. Konsumen yang menyusun skema `librechat-data-provider` sebaiknya menggunakan API Zod 4 yang kompatibel dan menginferensi tipe input/output dari skema yang diekspor, alih-alih mengandalkan internal Zod 3. Bangun ulang konsumen paket kustom secara bersamaan; memaksa Zod 3 melalui override bukanlah jalur kompatibilitas.

Paket klien tidak lagi mengekspor kontrol lama `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate`, atau `DropdownMenu` dari Radix. Gunakan selektor berbasis Dropdown yang dipelihara dan primitif dialog yang digunakan oleh pemanggil LibreChat saat ini. Lihat [panduan peningkatan](/docs/configuration/upgrade#shared-package-compatibility).
