## De omgeving voorbereiden [#prepare-the-environment]

### Node.js en npm [#nodejs-and-npm]

Als je `nvm` gebruikt, installeer en selecteer dan de aanbevolen Node.js-versie voordat je LibreChat installeert:

```sh filename="Use Node.js 24"
nvm install 24.22.1
nvm use 24.22.1
npm install -g npm@11.13.0
```

Het `.nvmrc`-bestand in de LibreChat-repository is de bron van waarheid voor de Node.js-versie; door `nvm use` vanuit de hoofdmap van de repository uit te voeren, wordt die versie geselecteerd.

Controleer of je shell de verwachte versies gebruikt:

```sh filename="Check Node.js and npm"
node -v
npm -v
```

```txt filename="Expected versions"
v24.22.1
11.13.0
```

### GitHub [#github]

- Fork de LibreChat repository: [https://github.com/LibreChat-AI/LibreChat/fork](https://github.com/LibreChat-AI/LibreChat/fork)

- Kloon je fork en voeg de oorspronkelijke repository toe als `upstream`. Bijdragen worden vertakt vanaf en gericht op `dev`; `main` wordt alleen bijgewerkt op het moment van een release.

```sh filename="Clone your fork and sync dev"
git clone https://github.com/username/LibreChat.git
cd LibreChat
git remote add upstream https://github.com/LibreChat-AI/LibreChat.git
git fetch upstream dev
git checkout -B dev upstream/dev
```

- Maak een beschrijvende branch met slashes aan vanaf `dev`:

```sh filename="Create your working branch"
git checkout -b new/feature/x
```

> Vervang `username` en de branchnaam door je eigen gegevens. Gebruik `npm run update` niet om een ontwikkelbranch bij te werken; dit is de updater voor self-hosting en die schakelt over naar `main`.

### LibreChat voorbereiden [#prepare-librechat]

- Open de terminal in VS Code met `ctrl`+`shift`+`` ```

  > Gebruik anders `ctrl`+`j` om het onderste paneel te openen en de terminal te selecteren.

- ```sh filename="Install LibreChat dependencies"
  npm run smart-reinstall
  ```

  > Als je zojuist de Node.js- of npm-versies hebt gewijzigd, gebruik dan eenmaal `npm run reinstall` voor een schone installatie.

- ```sh filename="Build all compiled code"
  npm run build
  ```

- .env Configuratie
  - Maak het `.env` bestand aan. Als je er nog geen hebt, dupliceer dan `.env.example` en configureer het.

- Git-hooks
  - `npm install` zet husky pre-commit checks op, die de Static Checks CI-job lokaal uitvoeren op de bestanden in elke commit (ESLint, Prettier, importvolgorde, circulaire afhankelijkheden). Stel `HUSKY=0` in om dit uit te schakelen, en voer de checks handmatig uit met `npm run static-checks`.

<Callout type="warning" title="Waarschuwing">
  De standaardwaarden in `.env.example` zijn meestal in orde, behalve voor `MONGO_URI`. Geef je eigen waarde op.
  Zorg ervoor dat je MongoDB installeert en `MONGO_URI` correct configureert om verbinding te maken met je MongoDB-instantie. Gebruik [MongoDB Community Server](https://www.mongodb.com/try/download/community) of [MongoDB Atlas Cloud](https://www.mongodb.com/cloud/atlas/register).
</Callout>

### Ontwikkelingsworkflow [#development-workflow]

Gebruik deze commando's voor efficiënt werken met LibreChat:

- **Backend starten:**
  - Gebruik `npm run backend` voor normaal gebruik.
  - Voor actieve ontwikkeling, gebruik `npm run backend:dev` om wijzigingen te monitoren.
  - Toegang via `http://localhost:3080/`.

- **Frontend uitvoeren in ontwikkelmodus:**
  - **Zorg ervoor dat de backend draait.**
  - Gebruik `npm run frontend:dev` om wijzigingen in de frontend te monitoren.
  - Bekijk op `http://localhost:3090/`.

<Callout type="tip" title="Pro-tips">
  - Voor real-time updates tijdens frontend-ontwikkeling, voer `npm run frontend:dev` uit zodat frontend-wijzigingen verversen op poort `3090`.
  - Stel `DEBUG_CONSOLE=true` in in `.env` voor uitgebreide server-output in de console.
</Callout>

## Commit, Push, Pull Request (PR) [#commit-push-pull-request-pr]

### Een commit maken [#make-a-commit]

**Commits** markeren logische controlepunten in de ontwikkeling. Gebruik conventionele commitberichten die beginnen met een type, zoals `feat`, `fix`, `docs` of `refactor`, gevolgd door een korte samenvatting.

**Voorbeeld:**

```bash filename=" "
git add .
git commit -m "feat: Add login functionality"
```

### Wijzigingen pushen [#push-changes]

**Push** wijzigingen naar de remote repository nadat je een feature hebt voltooid of een probleem hebt opgelost.

**Voorbeeld:**

```bash filename=" "
git push origin feature-branch-name
```

### Een Pull Request (PR) aanmaken [#create-a-pull-request-pr]

**Pull Request** voegt wijzigingen uit een feature-branch samen in de `dev`-branch.

1. Haal de nieuwste wijzigingen van `dev` op en los conflicten op.
2. Push de bijgewerkte feature branch.
3. Zorg ervoor dat de code de projectrichtlijnen volgt.

**Voorbeeld:**

```bash filename=" "
git fetch upstream dev
git checkout feature-branch-name
git rebase upstream/dev
# Resolve conflicts if any
git push origin feature-branch-name
# Open PR on GitHub
```

Open je fork in een browser en klik op "Contribute". Zorg ervoor dat de pull request zich richt op `dev`.

<Callout type="info" title="Let op:">
  Zorg voor een gedetailleerde PR-beschrijving waarin de wijzigingen en de waarde ervan worden uitgelegd. Verwijs naar gerelateerde issues.
</Callout>

<Callout type="tip" title="Tip">
  Gebruik GitHub Desktop om wijzigingen bij te houden.
</Callout>

<Callout type="warning" title="Waarschuwing">
  Als `git commit` mislukt vanwege ESLint-fouten, begrijp en verhelp dan het probleem.
</Callout>

## Commits veilig terugdraaien [#revert-commits-safely]

Om wijzigingen in een feature branch ongedaan te maken, volg je deze stappen voorzichtig:

- ```bash filename="1. Update local repository from feature branch:"
  git pull origin feature-branch-name
  ```

- ```bash filename="2. Review commit history to determine commits to revert:"
  git log
  ```

- ```bash filename="3. Start an interactive rebase for 'N' commits to revert:"
  git rebase -i HEAD~N
  ```

  > Vervang `pick` door `drop` voor commits die verwijderd moeten worden. Sla op en sluit de editor.

- ```bash filename="4. Force push changes to remote repository:"
  git push --force-with-lease origin feature-branch-name
  ```
