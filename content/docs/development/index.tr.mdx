Docker çoğu kullanıcı için tercih edilen kurulum yoludur, ancak yerel LibreChat geliştirmesi için `npm` kullanılmalıdır. Uygulamayı doğrudan makinenizde çalıştırmak daha hızlı geri bildirim, daha net hata ayıklama ve her değişiklikten sonra konteynerleri yeniden oluşturmaya gerek kalmadan monorepo çalışma alanlarına doğrudan erişim sağlar.

## Önerilen Araç Zinciri [#recommended-toolchain]

npm tabanlı geliştirme için bu araç zincirini kullanın:

| Araç | Sürüm |
| ------- | ------------------------- |
| Node.js | `v24.22.1` |
| npm | `v11.13.0` |
| MongoDB | Atlas veya Community Server |

Node 24, LibreChat'in çalışma zamanı gereksinimlerini karşılar: ESM-only paketler için CommonJS birlikte çalışabilirliği, WebCrypto ve Fetch API. Kabuğunuz hâlâ daha eski bir Node sürümü bildiriyorsa, bağımlılıkları yüklemeden önce LibreChat deposunun kök dizininden `nvm use 24.22.1` komutunu çalıştırın.

## Doğru Çalışma Alanında Çalışın [#work-in-the-right-workspace]

LibreChat bir monorepo'dur. Değiştirdiğiniz davranışın sahibi olan en küçük çalışma alanını seçin:

| Çalışma Alanı | Kullanım Amacı |
| ------------------------- | --------------------------------------------------------------------- |
| `/packages/api` | Yeni backend TypeScript servisleri, controller'lar ve paylaşılan sunucu mantığı |
| `/api` | Eski Express sunucu entegrasyonu; değişiklikleri küçük ve sınırlı tutun |
| `/packages/data-schemas` | Veritabanı modelleri, şemalar ve veritabanına özgü paylaşılan mantık |
| `/packages/data-provider` | Paylaşılan API türleri, endpoint'ler, query key'ler ve veri servisi fonksiyonları |
| `/client` | React uygulama kodu |
| `/packages/client` | Paylaşılan frontend yardımcı araçları |
| `/packages/chat` | `@librechat/chat`: sohbet durumu, iletim (transport) ve mesaj bileşenleri |

## Günlük Komutlar [#daily-commands]

| Komut                         | Amaç                                                                               |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall`     | Gerektiğinde bağımlılıkları yükler ve derlenmiş çalışma alanlarını oluşturur       |
| `npm run reinstall`           | Node/npm sürümlerini değiştirdikten sonra veya bağımlılık durumu şüpheli olduğunda temiz kurulum yapar |
| `npm run backend:dev`         | Dosya izleme özelliğiyle arka ucu başlatır                                          |
| `npm run frontend:dev`        | `3090` numaralı bağlantı noktasında ön uç geliştirme sunucusunu başlatır            |
| `npm run build:data-provider` | API/tür değişikliklerinden sonra paylaşılan data-provider kodunu yeniden derler      |
| `npm run build`               | Turborepo aracılığıyla tüm derlenmiş çalışma alanlarını oluşturur                   |

## Geliştirme Kaynakları [#development-resources]

<Callout type="info" title="Geliştirme Kaynakları">
  - Depolar (repositories), çatallar (forks), dallar (branches) ve çekme istekleri (pull requests) konusunda yeniyseniz, **[GitHub'ın iş birliğine dayalı geliştirme kılavuzu](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/getting-started/about-collaborative-development-models)** ile başlayın.
  - **[Katkıda Bulunanlar Kılavuzu](https://github.com/LibreChat-AI/LibreChat/blob/main/.github/CONTRIBUTING.md)**'nu bir PR açmadan önce okuyun. `dev` dalından yeni bir dal oluşturun ve pull request'inizi `dev` dalını hedefleyecek şekilde açın; `main` dalı yalnızca sürüm yayınlandığında güncellenir.
  - Tam yerel kurulum akışı için **[Contributor Setup](/docs/development/get_started)** bölümünü kullanın.
  - Çalışma alanı sınırları, içe aktarma sırası, tipleme, test etme ve frontend kuralları için **[Code Standards and Conventions](/docs/development/conventions)** kullanın.
</Callout>
