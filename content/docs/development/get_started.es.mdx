## Preparar el entorno [#prepare-the-environment]

### Node.js y npm [#nodejs-and-npm]

Si utilizas `nvm`, instala y selecciona la versión de Node.js recomendada antes de instalar LibreChat:

```sh filename="Use Node.js 24"
nvm install 24.22.1
nvm use 24.22.1
npm install -g npm@11.16.0
```

El archivo `.nvmrc` en el repositorio de LibreChat es la fuente de verdad para la versión de Node.js; ejecutar `nvm use` desde la raíz del repositorio selecciona dicha versión.

Verifica que tu shell esté utilizando las versiones esperadas:

```sh filename="Check Node.js and npm"
node -v
npm -v
```

```txt filename="Expected versions"
v24.22.1
11.16.0
```

### GitHub [#github]

- Haz un fork del repositorio de LibreChat: [https://github.com/LibreChat-AI/LibreChat/fork](https://github.com/LibreChat-AI/LibreChat/fork)

- Clone your fork and add the original repository as `upstream`. Contributions branch from and target `dev`; `main` only moves at release time.

```sh filename="Clone your fork and sync dev"
git clone https://github.com/username/LibreChat.git
cd LibreChat
git remote add upstream https://github.com/LibreChat-AI/LibreChat.git
git fetch upstream dev
git checkout -B dev upstream/dev
```

- Crea una rama descriptiva, basada en barras diagonales, a partir de `dev`:

```sh filename="Create your working branch"
git checkout -b new/feature/x
```

> Reemplaza `username` y el nombre de la rama con tus datos. No uses `npm run update` para actualizar una rama de desarrollo; es el actualizador para instalaciones self-host y cambia a `main`.

### Abrir en VS Code [#open-in-vs-code]

- Después de clonar tu rama:
  ```sh filename="Navigate to LibreChat folder"
  cd LibreChat
  ```
  ```sh filename="Open in VS Code"
  code .
  ```

### Preparar LibreChat [#prepare-librechat]

- Abre la terminal en VS Code con `ctrl`+`shift`+`` ```

  > Alternativamente, usa `ctrl`+`j` para abrir el panel inferior y selecciona la terminal.

- ```sh filename="Install LibreChat dependencies"
  npm run smart-reinstall
  ```

  > Si acabas de cambiar las versiones de Node.js o npm, usa `npm run reinstall` una vez para una instalación limpia.

- ```sh filename="Build all compiled code"
  npm run build
  ```

- Configuración de .env
  - Cree el archivo `.env`. Si no tiene uno, duplique `.env.example` y configúrelo.

- Ganchos de Git
  - `npm install` configura las comprobaciones previas al commit de husky, que ejecutan localmente el trabajo de CI Static Checks sobre los archivos de cada commit (ESLint, Prettier, orden de importaciones, dependencias circulares). Establece `HUSKY=0` para desactivarlas, y ejecuta las comprobaciones manualmente con `npm run static-checks`.

<Callout type="warning" title="Advertencia">
  Los valores predeterminados en `.env.example` suelen ser correctos, a excepción de `MONGO_URI`. Proporcione el suyo propio.
  Asegúrese de instalar MongoDB y configurar `MONGO_URI` correctamente para conectarse a su instancia de MongoDB. Utilice [MongoDB Community Server](https://www.mongodb.com/try/download/community) o [MongoDB Atlas Cloud](https://www.mongodb.com/cloud/atlas/register).
</Callout>

### Flujo de trabajo de desarrollo [#development-workflow]

Para un trabajo eficiente en LibreChat, utilice estos comandos:

- **Iniciando el backend:**
  - Utilice `npm run backend` para el funcionamiento normal.
  - Para el desarrollo activo, utilice `npm run backend:dev` para monitorear los cambios.
  - Acceda en `http://localhost:3080/`.

- **Ejecución del Frontend en modo de desarrollo:**
  - **Asegúrate de que el backend esté ejecutándose.**
  - Usa `npm run frontend:dev` para monitorear los cambios en el frontend.
  - Ver en `http://localhost:3090/`.

<Callout type="tip" title="Consejos profesionales">
  - Para actualizaciones en tiempo real durante el desarrollo del frontend, ejecuta `npm run frontend:dev` para que los cambios en el frontend se actualicen en el puerto `3090`.
  - Establezca `DEBUG_CONSOLE=true` en `.env` para obtener una salida detallada del servidor en la consola.
</Callout>

## Commit, Push, Pull Request (PR) [#commit-push-pull-request-pr]

### Realizar un commit [#make-a-commit]

**Commits** marcan puntos de control lógicos en el desarrollo. Usa mensajes de commit convencionales que comiencen con un tipo como `feat`, `fix`, `docs` o `refactor`, seguido de un resumen breve.

**Ejemplo:**

```bash filename=" "
git add .
git commit -m "feat: Add login functionality"
```

### Enviar cambios [#push-changes]

**Push** los cambios al repositorio remoto después de completar una funcionalidad o corregir un problema.

**Ejemplo:**

```bash filename=" "
git push origin feature-branch-name
```

### Crear una Pull Request (PR) [#create-a-pull-request-pr]

**Pull Request** fusiona los cambios de una rama de funcionalidad en la rama `dev`.

1. Extrae los cambios más recientes de `dev` y resuelve los conflictos.
2. Envía la rama de características actualizada.
3. Asegúrese de que el código siga las directrices del proyecto.

**Ejemplo:**

```bash filename=" "
git fetch upstream dev
git checkout feature-branch-name
git rebase upstream/dev
# Resolve conflicts if any
git push origin feature-branch-name
# Open PR on GitHub
```

Accede a tu fork en el navegador y haz clic en "Contribute", y asegúrate de que el pull request apunte a `dev`.

<Callout type="info" title="Nota:">
  Proporciona una descripción detallada del PR explicando los cambios y su valor. Haz referencia a los issues relacionados.
</Callout>

<Callout type="tip" title="Consejo">
  Usa GitHub Desktop para realizar un seguimiento de los cambios.
</Callout>

<Callout type="warning" title="Advertencia">
  Si `git commit` falla debido a errores de ESLint, comprende y soluciona el problema.
</Callout>

## Revertir Commits de forma segura [#revert-commits-safely]

Para deshacer cambios en una rama de características (feature branch), siga estos pasos con precaución:

- ```bash filename="1. Update local repository from feature branch:"
  git pull origin feature-branch-name
  ```

- ```bash filename="2. Review commit history to determine commits to revert:"
  git log
  ```

- ```bash filename="3. Start an interactive rebase for 'N' commits to revert:"
  git rebase -i HEAD~N
  ```

  > Reemplace `pick` con `drop` para los commits que desea eliminar. Guarde y salga del editor.

- ```bash filename="4. Force push changes to remote repository:"
  git push --force-with-lease origin feature-branch-name
  ```
