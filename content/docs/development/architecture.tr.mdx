## Monorepo Yapısı [#monorepo-structure]

LibreChat, net bir şekilde tanımlanmış çalışma alanı sınırlarına sahip bir monorepo olarak düzenlenmiştir:

| Çalışma Alanı | Dil | Taraf | Bağımlılık | Amaç |
| ------------------------- | ---------------- | -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `/api` | JS (eski) | Backend | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Express sunucusu — bu alanda değişiklikleri en aza indirin |
| `/packages/api` | **TypeScript** | Backend | `packages/data-schemas`, `packages/data-provider` | Yeni backend kodu burada bulunur (yalnızca TS, `/api` tarafından tüketilir) |
| `/packages/data-schemas` | TypeScript | Backend | `packages/data-provider` | Veritabanı modelleri/şemaları, backend projeleri arasında paylaşılabilir |
| `/packages/data-provider` | TypeScript | Paylaşılan | — | Paylaşılan API türleri, uç noktalar, veri servisi — hem frontend hem backend tarafından kullanılır |
| `/client` | TypeScript/React | Frontend | `packages/data-provider`, `packages/client` | Frontend SPA |
| `/packages/client` | TypeScript | Frontend | `packages/data-provider` | Paylaşılan frontend yardımcı araçları |
| `/packages/chat` | TypeScript | Frontend | `packages/data-provider`, `packages/client` | `@librechat/chat`: sohbet durumu, iletim ve mesaj bileşenleri `/client` dışına taşınıyor; uygulamayı asla içe aktarmaz |

### Temel İlkeler [#key-principles]

- `/packages/api` içindeki **tüm yeni backend kodları TypeScript olmalıdır**.
- `/api` değişikliklerini mutlak minimumda tutun — `/packages/api` dizinini çağıran ince JS sarmalayıcıları (wrappers) kullanın.
- Veritabanına özgü paylaşılan mantık `/packages/data-schemas` içinde yer alır.
- Frontend/backend paylaşımlı API mantığı (endpoints, types, data-service) `/packages/data-provider` dizininde yer almalıdır.

### Oluşturma ve Kurulum [#build-and-install]

| Komut | Amaç |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | Bağımlılıkları yükler (kilit dosyası değiştiyse) ve Turborepo ile derler |
| `npm run reinstall` | Node/npm sürümlerini değiştirdikten sonra veya bağımlılık durumundan şüphelenildiğinde temiz kurulum yapar |
| `npm run build` | Turborepo ile tüm derlenmiş kodu derler (paralel, önbellekli) |
| `npm run frontend` | Tüm derlenmiş kodu sırayla derler (eski yöntem, yedek olarak) |
| `npm run build:data-provider` | Değişikliklerden sonra `packages/data-provider` paketini yeniden derler |
| `npm run backend` | Backend sunucusunu başlatır |
| `npm run backend:dev` | Dosya izleme özelliğiyle backend'i başlatır (geliştirme) |
| `npm run frontend:dev` | HMR özellikli frontend geliştirme sunucusunu başlatır (port 3090, backend'in çalışıyor olmasını gerektirir) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- Veritabanı: MongoDB
- Backend `http://localhost:3080/` adresinde; frontend geliştirme sunucusu ise `http://localhost:3090/` adresinde çalışır.

## Paylaşılan Şema ve Bileşen Uyumluluğu [#shared-schema-and-component-compatibility]

`v0.8.9-rc1` paylaşılan paketleri Zod 4 kullanır. `librechat-data-provider` şemalarını birleştiren tüketiciler, Zod 3 iç yapılarına güvenmek yerine uyumlu Zod 4 API'lerini kullanmalı ve giriş/çıkış türlerini dışa aktarılan şemadan çıkarmalıdır. Özel paket tüketicilerini birlikte yeniden derleyin; Zod 3'ü bir override ile zorlamak bir uyumluluk yolu değildir.

İstemci paketi artık eski `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate` veya Radix `DropdownMenu` kontrollerini dışa aktarmamaktadır. Bunun yerine, güncel LibreChat çağıranları tarafından kullanılan, bakımı yapılan Dropdown tabanlı seçicileri ve dialog temel bileşenlerini kullanın. Bkz. [yükseltme kılavuzu](/docs/configuration/upgrade#shared-package-compatibility).
