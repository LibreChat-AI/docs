## Monorepo-structuur [#monorepo-structure]

LibreChat is georganiseerd als een monorepo met duidelijk gedefinieerde werkruimtegrenzen:

| Workspace | Taal | Kant | Afhankelijkheid | Doel |
| ------------------------- | ---------------- | -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `/api` | JS (legacy) | Backend | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Express-server — beperk wijzigingen hier zoveel mogelijk |
| `/packages/api` | **TypeScript** | Backend | `packages/data-schemas`, `packages/data-provider` | Nieuwe backendcode wordt hier geplaatst (alleen TS, wordt gebruikt door `/api`) |
| `/packages/data-schemas` | TypeScript | Backend | `packages/data-provider` | Databasemodellen/-schema's, deelbaar tussen backendprojecten |
| `/packages/data-provider` | TypeScript | Gedeeld | — | Gedeelde API-types, endpoints, data-service — gebruikt door zowel frontend als backend |
| `/client` | TypeScript/React | Frontend | `packages/data-provider`, `packages/client` | Frontend-SPA |
| `/packages/client` | TypeScript | Frontend | `packages/data-provider` | Gedeelde frontend-hulpprogramma's |
| `/packages/chat` | TypeScript | Frontend | `packages/data-provider`, `packages/client` | `@librechat/chat`: chatstatus, transport en berichtcomponenten die uit `/client` worden verplaatst; importeert nooit de app |

### Kernprincipes [#key-principles]

- **Alle nieuwe backend-code moet TypeScript zijn** in `/packages/api`.
- Houd `/api` wijzigingen tot het absolute minimum — dunne JS-wrappers die `/packages/api` aanroepen.
- Database-specifieke gedeelde logica hoort thuis in `/packages/data-schemas`.
- Gedeelde API-logica voor frontend/backend (endpoints, types, data-service) hoort in `/packages/data-provider`.

### Bouwen en installeren [#build-and-install]

| Commando | Doel |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall`     | Installeer afhankelijkheden (als het lockfile is gewijzigd) + bouw via Turborepo |
| `npm run reinstall`           | Schone installatie na het wijzigen van Node/npm-versies of wanneer de afhankelijkheidsstatus verdacht is |
| `npm run build`               | Bouw alle gecompileerde code via Turborepo (parallel, gecachet) |
| `npm run frontend`            | Bouw alle gecompileerde code sequentieel (verouderde fallback) |
| `npm run build:data-provider` | Herbouw `packages/data-provider` na wijzigingen |
| `npm run backend`             | Start de backendserver |
| `npm run backend:dev`         | Start de backend met bestandsbewaking (ontwikkeling) |
| `npm run frontend:dev`        | Start de frontend-ontwikkelserver met HMR (poort 3090, vereist dat de backend actief is) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- Database: MongoDB
- Backend draait op `http://localhost:3080/`; frontend dev server op `http://localhost:3090/`

## Gedeeld schema en compatibiliteit van componenten [#shared-schema-and-component-compatibility]

De `v0.8.9-rc1` gedeelde pakketten gebruiken Zod 4. Consumenten die `librechat-data-provider`-schema's samenstellen, moeten compatibele Zod 4-API's gebruiken en input-/outputtypen afleiden uit het geëxporteerde schema, in plaats van te vertrouwen op interne Zod 3-onderdelen. Bouw aangepaste pakketconsumenten samen opnieuw; het forceren van Zod 3 via een override is geen compatibel alternatief.

Het clientpakket exporteert de verouderde `Select`-, `SelectDropDown`-, `Dialog`- en `DialogTemplate`-besturingselementen en het Radix `DropdownMenu` niet meer. Gebruik de onderhouden, op Dropdown gebaseerde selectors en dialoogprimitieven die door de huidige LibreChat-aanroepers worden gebruikt. Zie de [upgrade-handleiding](/docs/configuration/upgrade#shared-package-compatibility).
