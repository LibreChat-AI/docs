## Prepara l'ambiente [#prepare-the-environment]

### Node.js e npm [#nodejs-and-npm]

Se utilizzi `nvm`, installa e seleziona la versione di Node.js raccomandata prima di installare LibreChat:

```sh filename="Use Node.js 24"
nvm install 24.22.1
nvm use 24.22.1
npm install -g npm@11.13.0
```

Il file `.nvmrc` nel repository di LibreChat è la fonte di riferimento per la versione di Node.js; eseguire `nvm use` dalla radice del repository seleziona tale versione.

Verifica che la tua shell stia utilizzando le versioni previste:

```sh filename="Check Node.js and npm"
node -v
npm -v
```

```txt filename="Expected versions"
v24.22.1
11.13.0
```

### GitHub [#github]

- Effettua il fork del repository LibreChat: [https://github.com/LibreChat-AI/LibreChat/fork](https://github.com/LibreChat-AI/LibreChat/fork)

- Clona il tuo fork e aggiungi il repository originale come `upstream`. I contributi partono dal branch `dev` e vi fanno riferimento; `main` viene aggiornato solo al momento del rilascio.

```sh filename="Clone your fork and sync dev"
git clone https://github.com/username/LibreChat.git
cd LibreChat
git remote add upstream https://github.com/LibreChat-AI/LibreChat.git
git fetch upstream dev
git checkout -B dev upstream/dev
```

- Crea un ramo descrittivo, basato su barre, a partire da `dev`:

```sh filename="Create your working branch"
git checkout -b new/feature/x
```

> Sostituisci `username` e il nome del branch con i tuoi dati. Non usare `npm run update` per aggiornare un branch di sviluppo: è lo strumento di aggiornamento per l'self-host e effettua il checkout di `main`.

### Apri in VS Code [#open-in-vs-code]

- Dopo aver clonato il tuo branch:
  ```sh filename="Navigate to LibreChat folder"
  cd LibreChat
  ```
  ```sh filename="Open in VS Code"
  code .
  ```

### Preparare LibreChat [#prepare-librechat]

- Apri il terminale in VS Code con `ctrl`+`shift`+`` ` ``

  > In alternativa, usa `ctrl`+`j` per aprire il riquadro inferiore e seleziona il terminale.

- ```sh filename="Install LibreChat dependencies"
  npm run smart-reinstall
  ```

  > Se hai appena modificato le versioni di Node.js o npm, usa `npm run reinstall` una volta per un'installazione pulita.

- ```sh filename="Build all compiled code"
  npm run build
  ```

- Configurazione di .env
  - Crea il file `.env`. Se non ne hai uno, duplica `.env.example` e configuralo.

- Git hooks
  - `npm install` configura i controlli pre-commit di husky, che eseguono localmente il job CI Static Checks sui file di ogni commit (ESLint, Prettier, ordine degli import, dipendenze circolari). Imposta `HUSKY=0` per disattivarli ed esegui i controlli manualmente con `npm run static-checks`.

<Callout type="warning" title="Attenzione">
  I valori predefiniti in `.env.example` sono solitamente corretti, ad eccezione di `MONGO_URI`. Fornisci il tuo.
  Assicurati di installare MongoDB e di configurare `MONGO_URI` correttamente per connetterti alla tua istanza MongoDB. Utilizza [MongoDB Community Server](https://www.mongodb.com/try/download/community) o [MongoDB Atlas Cloud](https://www.mongodb.com/cloud/atlas/register).
</Callout>

### Flusso di lavoro di sviluppo [#development-workflow]

Per un lavoro efficiente su LibreChat, utilizza questi comandi:

- **Avvio del backend:**
  - Usa `npm run backend` per il normale funzionamento.
  - Per lo sviluppo attivo, usa `npm run backend:dev` per monitorare le modifiche.
  - Accedi a `http://localhost:3080/`.

- **Esecuzione del frontend in modalità di sviluppo:**
  - **Assicurati che il backend sia in esecuzione.**
  - Usa `npm run frontend:dev` per monitorare le modifiche al frontend.
  - Visualizza su `http://localhost:3090/`.

<Callout type="tip" title="Suggerimenti utili">
  - Per aggiornamenti in tempo reale durante lo sviluppo del frontend, esegui `npm run frontend:dev` in modo che le modifiche al frontend vengano aggiornate sulla porta `3090`.
  - Imposta `DEBUG_CONSOLE=true` nel file `.env` per un output dettagliato del server nella console.
</Callout>

## Commit, Push, Pull Request (PR) [#commit-push-pull-request-pr]

### Esegui un Commit [#make-a-commit]

**Commit** segnano punti di controllo logici nello sviluppo. Usa messaggi di commit convenzionali che iniziano con un tipo, come `feat`, `fix`, `docs` o `refactor`, seguito da un breve riepilogo.

**Esempio:**

```bash filename=" "
git add .
git commit -m "feat: Add login functionality"
```

### Eseguire il push delle modifiche [#push-changes]

**Esegui il push** delle modifiche al repository remoto dopo aver completato una funzionalità o aver risolto un problema.

**Esempio:**

```bash filename=" "
git push origin feature-branch-name
```

### Crea una Pull Request (PR) [#create-a-pull-request-pr]

**Pull Request** unisce le modifiche da un ramo di funzionalità nel ramo `dev`.

1. Ottieni le ultime modifiche da `dev` e risolvi i conflitti.
2. Esegui il push del branch della funzionalità aggiornato.
3. Assicurati che il codice segua le linee guida del progetto.

**Esempio:**

```bash filename=" "
git fetch upstream dev
git checkout feature-branch-name
git rebase upstream/dev
# Resolve conflicts if any
git push origin feature-branch-name
# Open PR on GitHub
```

Accedi al tuo fork nel browser e clicca su "Contribute", assicurandoti che la pull request sia indirizzata a `dev`.

<Callout type="info" title="Nota:">
  Fornisci una descrizione dettagliata della PR spiegando le modifiche e il loro valore. Fai riferimento alle issue correlate.
</Callout>

<Callout type="tip" title="Suggerimento">
  Usa GitHub Desktop per tenere traccia delle modifiche.
</Callout>

<Callout type="warning" title="Attenzione">
  Se `git commit` fallisce a causa di errori di ESLint, comprendi e risolvi il problema.
</Callout>

## Ripristinare i commit in modo sicuro [#revert-commits-safely]

Per annullare le modifiche in un feature branch, segui questi passaggi con cautela:

- ```bash filename="1. Update local repository from feature branch:"
  git pull origin feature-branch-name
  ```

- ```bash filename="2. Review commit history to determine commits to revert:"
  git log
  ```

- ```bash filename="3. Start an interactive rebase for 'N' commits to revert:"
  git rebase -i HEAD~N
  ```

  > Sostituisci `pick` con `drop` per i commit da rimuovere. Salva ed esci dall'editor.

- ```bash filename="4. Force push changes to remote repository:"
  git push --force-with-lease origin feature-branch-name
  ```
