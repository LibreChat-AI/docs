## Cấu trúc Monorepo [#monorepo-structure]

LibreChat được tổ chức dưới dạng một monorepo với các ranh giới không gian làm việc được xác định rõ ràng:

| Workspace | Language | Side | Dependency | Mục đích |
| --- | --- | --- | --- | --- |
| `/api` | JS (legacy) | Backend | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Máy chủ Express — hạn chế thay đổi tối đa ở đây |
| `/packages/api` | **TypeScript** | Backend | `packages/data-schemas`, `packages/data-provider` | Mã backend mới nằm ở đây (chỉ TS, được `/api` sử dụng) |
| `/packages/data-schemas` | TypeScript | Backend | `packages/data-provider` | Các model/schema cơ sở dữ liệu, có thể chia sẻ giữa các dự án backend |
| `/packages/data-provider` | TypeScript | Dùng chung | — | Kiểu dữ liệu API, endpoint và data-service dùng chung, được cả frontend và backend sử dụng |
| `/client` | TypeScript/React | Frontend | `packages/data-provider`, `packages/client` | SPA frontend |
| `/packages/client` | TypeScript | Frontend | `packages/data-provider` | Các tiện ích frontend dùng chung |
| `/packages/chat` | TypeScript | Frontend | `packages/data-provider`, `packages/client` | `@librechat/chat`: trạng thái chat, lớp truyền tải và các component tin nhắn đang được chuyển ra khỏi `/client`; không bao giờ import ứng dụng |

### Các Nguyên tắc Chính [#key-principles]

- **Tất cả mã backend mới phải là TypeScript** trong `/packages/api`.
- Giữ các thay đổi đối với `/api` ở mức tối thiểu tuyệt đối — các trình bao bọc JS mỏng gọi vào `/packages/api`.
- Logic dùng chung dành riêng cho cơ sở dữ liệu nằm trong `/packages/data-schemas`.
- Logic API dùng chung giữa frontend/backend (endpoints, types, data-service) nằm trong `/packages/data-provider`.

### Xây dựng và Cài đặt [#build-and-install]

| Lệnh | Mục đích |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | Cài đặt các phụ thuộc (nếu lockfile đã thay đổi) + build qua Turborepo |
| `npm run reinstall` | Cài đặt sạch sau khi thay đổi phiên bản Node/npm hoặc khi trạng thái phụ thuộc có nghi ngờ lỗi |
| `npm run build` | Build toàn bộ mã đã biên dịch qua Turborepo (song song, có cache) |
| `npm run frontend` | Build toàn bộ mã đã biên dịch theo tuần tự (phương án dự phòng cũ) |
| `npm run build:data-provider` | Build lại `packages/data-provider` sau khi có thay đổi |
| `npm run backend` | Khởi động máy chủ backend |
| `npm run backend:dev` | Khởi động backend với tính năng theo dõi tệp (môi trường phát triển) |
| `npm run frontend:dev` | Khởi động máy chủ phát triển frontend với HMR (cổng 3090, yêu cầu backend đang chạy) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- Cơ sở dữ liệu: MongoDB
- Backend chạy trên `http://localhost:3080/`; máy chủ phát triển frontend trên `http://localhost:3090/`

## Tương thích Schema và Component dùng chung [#shared-schema-and-component-compatibility]

Các gói dùng chung của `v0.8.9-rc1` sử dụng Zod 4. Những nơi tiêu thụ (consumer) kết hợp các schema của `librechat-data-provider` nên dùng các API tương thích với Zod 4 và suy ra kiểu dữ liệu đầu vào/đầu ra từ schema được xuất ra, thay vì dựa vào các thành phần nội bộ của Zod 3. Hãy build lại đồng thời tất cả các consumer gói tùy chỉnh; việc ép dùng Zod 3 thông qua override không phải là một giải pháp tương thích.

Gói client không còn xuất các thành phần điều khiển cũ `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate` hoặc `DropdownMenu` của Radix. Hãy sử dụng các bộ chọn dựa trên Dropdown và các primitive hộp thoại được duy trì, mà các nơi gọi LibreChat hiện tại đang dùng. Xem [hướng dẫn nâng cấp](/docs/configuration/upgrade#shared-package-compatibility).
