## Monorepo 结构 [#monorepo-structure]

LibreChat 采用 monorepo（单体仓库）结构，并具有明确定义的工作区边界：

| 工作区 | 语言 | 端 | 依赖 | 用途 |
| ------------------------- | ---------------- | -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `/api` | JS (legacy) | 后端 | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Express 服务器 — 尽量减少此处的改动 |
| `/packages/api` | **TypeScript** | 后端 | `packages/data-schemas`, `packages/data-provider` | 新的后端代码位于此处(仅使用 TS,由 `/api` 调用) |
| `/packages/data-schemas` | TypeScript | 后端 | `packages/data-provider` | 数据库模型/模式,可在各后端项目之间共享 |
| `/packages/data-provider` | TypeScript | 共享 | — | 共享的 API 类型、端点、数据服务 — 前端与后端均在使用 |
| `/client` | TypeScript/React | 前端 | `packages/data-provider`, `packages/client` | 前端 SPA |
| `/packages/client` | TypeScript | 前端 | `packages/data-provider` | 共享的前端工具函数 |
| `/packages/chat` | TypeScript | 前端 | `packages/data-provider`, `packages/client` | `@librechat/chat`:聊天状态、传输层及消息组件,正从 `/client` 迁移出来;绝不导入应用本身 |

### 核心原则 [#key-principles]

- **所有新的后端代码必须使用 TypeScript**，位于 `/packages/api` 中。
- 保持 `/api` 的变更在绝对最小范围内 —— 仅保留调用 `/packages/api` 的轻量级 JS 包装器。
- 特定于数据库的共享逻辑应放在 `/packages/data-schemas` 中。
- 前端/后端共享的 API 逻辑（endpoints、types、data-service）应放置在 `/packages/data-provider` 中。

### 构建与安装 [#build-and-install]

| 命令 | 用途 |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | 安装依赖(如果 lockfile 已变更)并通过 Turborepo 进行构建 |
| `npm run reinstall` | 在更改 Node/npm 版本后或怀疑依赖状态异常时进行干净安装 |
| `npm run build` | 通过 Turborepo 构建所有已编译代码(并行执行,带缓存) |
| `npm run frontend` | 按顺序构建所有已编译代码(旧版备用方案) |
| `npm run build:data-provider` | 在修改后重新构建 `packages/data-provider` |
| `npm run backend` | 启动后端服务器 |
| `npm run backend:dev` | 以文件监听模式启动后端(开发环境) |
| `npm run frontend:dev` | 启动带热模块替换(HMR)的前端开发服务器(端口 3090,需要后端已运行) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- 数据库：MongoDB
- 后端运行在 `http://localhost:3080/`；前端开发服务器运行在 `http://localhost:3090/`

## 共享的 Schema 与组件兼容性 [#shared-schema-and-component-compatibility]

`v0.8.9-rc1` 的共享包使用 Zod 4。组合 `librechat-data-provider` schema 的使用方应采用兼容 Zod 4 的 API,并从导出的 schema 推断输入/输出类型,而不要依赖 Zod 3 的内部实现。请一起重新构建自定义包的使用方;通过 override 强制使用 Zod 3 并不是可行的兼容方案。

客户端包不再导出旧版的 `Select`、`SelectDropDown`、`Dialog`、`DialogTemplate` 或 Radix `DropdownMenu` 控件。请使用当前 LibreChat 调用方所采用的、受维护的基于 Dropdown 的选择器和对话框原语。参见[升级指南](/docs/configuration/upgrade#shared-package-compatibility)。
