## 本地单元测试 [#local-unit-tests]

在提交更新之前，请确保它们通过了所有单元测试。请按照以下步骤在本地运行测试：

- 复制 API 测试所使用的示例测试环境文件:

  ```bash filename="create api/test/.env.test"
  cp api/test/.env.test.example api/test/.env.test
  ```

- `npm run test:client`
- `npm run test:api`
- `npm run test:packages:api`
- `npm run test:packages:data-provider`
- `npm run test:packages:data-schemas`
- `npm run test:packages:chat`
- `npm run test:all` 会按顺序运行上述所有测试套件。

### 静态检查 [#static-checks]

提交时也会通过 husky 的 pre-commit 钩子在本地运行 Static Checks CI 任务(设置 `HUSKY=0` 可以选择退出)。你可以使用 `npm run static-checks` 手动运行,或使用 `npm run static-checks -- --against origin/dev` 针对基础分支运行。`npm run static-checks:full` 会额外运行较慢的检查项(TypeScript、配置迁移测试、未使用的 i18n 键、未使用的 npm 包)。

### 按工作区运行测试 [#running-tests-per-workspace]

测试使用 Jest 在各自的工作区目录中运行。通过模式指定特定的测试文件：

```bash
cd api && npx jest <pattern>
cd packages/api && npx jest <pattern>
cd packages/data-provider && npx jest <pattern>
cd packages/data-schemas && npx jest <pattern>
cd packages/chat && npx jest <pattern>
cd client && npx jest <pattern>
```

## 测试理念 [#testing-philosophy]

- 优先使用真实逻辑而非模拟（mock）。仅对无法在本地控制的内容进行模拟，例如外部 HTTP API、受速率限制的服务以及非确定性的系统调用。
- 当你需要断言真实函数是否以预期的参数被调用时，请使用 spies。
- 在基于 MongoDB 的测试中使用 `mongodb-memory-server`，以便查询和模式验证能够针对真实的数据库行为运行。
- 涵盖 UI/数据流的加载、成功和错误状态。

<Callout type="tip" title="提示">
  在前端测试中渲染组件时，请使用 `test/layout-test-utils`。
</Callout>
