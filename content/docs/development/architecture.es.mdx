## Estructura del Monorepo [#monorepo-structure]

LibreChat está organizado como un monorepo con límites de espacio de trabajo claramente definidos:

| Espacio de trabajo | Lenguaje | Lado | Dependencia | Propósito |
| ------------------------- | ---------------- | -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `/api` | JS (legacy) | Backend | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Servidor Express — minimizar los cambios aquí |
| `/packages/api` | **TypeScript** | Backend | `packages/data-schemas`, `packages/data-provider` | El nuevo código del backend vive aquí (solo TS, consumido por `/api`) |
| `/packages/data-schemas` | TypeScript | Backend | `packages/data-provider` | Modelos/esquemas de base de datos, compartibles entre proyectos del backend |
| `/packages/data-provider` | TypeScript | Compartido | — | Tipos de API compartidos, endpoints, servicio de datos — usado tanto por el frontend como por el backend |
| `/client` | TypeScript/React | Frontend | `packages/data-provider`, `packages/client` | SPA del frontend |
| `/packages/client` | TypeScript | Frontend | `packages/data-provider` | Utilidades compartidas del frontend |
| `/packages/chat` | TypeScript | Frontend | `packages/data-provider`, `packages/client` | `@librechat/chat`: estado del chat, transporte y componentes de mensajes que se están trasladando desde `/client`; nunca importa la aplicación |

### Principios clave [#key-principles]

- **Todo el código nuevo del backend debe estar en TypeScript** en `/packages/api`.
- Mantén los cambios en `/api` al mínimo absoluto: envoltorios delgados de JS que llaman a `/packages/api`.
- La lógica compartida específica de la base de datos pertenece a `/packages/data-schemas`.
- La lógica de API compartida entre el frontend y el backend (endpoints, tipos, data-service) pertenece a `/packages/data-provider`.

### Construcción e instalación [#build-and-install]

| Comando | Propósito |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | Instala las dependencias (si el lockfile cambió) y compila mediante Turborepo |
| `npm run reinstall` | Instalación limpia tras cambiar las versiones de Node/npm o cuando el estado de las dependencias es sospechoso |
| `npm run build` | Compila todo el código compilado mediante Turborepo (en paralelo, con caché) |
| `npm run frontend` | Compila todo el código compilado de forma secuencial (alternativa heredada) |
| `npm run build:data-provider` | Recompila `packages/data-provider` después de realizar cambios |
| `npm run backend` | Inicia el servidor backend |
| `npm run backend:dev` | Inicia el backend con vigilancia de archivos (desarrollo) |
| `npm run frontend:dev` | Inicia el servidor de desarrollo del frontend con HMR (puerto 3090, requiere que el backend esté en ejecución) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- Base de datos: MongoDB
- El backend se ejecuta en `http://localhost:3080/`; el servidor de desarrollo del frontend en `http://localhost:3090/`

## Compatibilidad de esquemas y componentes compartidos [#shared-schema-and-component-compatibility]

Los paquetes compartidos de `v0.8.9-rc1` utilizan Zod 4. Los consumidores que componen esquemas de `librechat-data-provider` deben usar APIs compatibles con Zod 4 e inferir los tipos de entrada y salida a partir del esquema exportado, en lugar de depender de los internos de Zod 3. Recompile juntos los consumidores de paquetes personalizados; forzar Zod 3 mediante un override no es una vía de compatibilidad.

El paquete cliente ya no exporta los controles heredados `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate` ni el `DropdownMenu` de Radix. Utiliza los selectores basados en Dropdown y las primitivas de diálogo mantenidos que usan los llamadores actuales de LibreChat. Consulta la [guía de actualización](/docs/configuration/upgrade#shared-package-compatibility).
