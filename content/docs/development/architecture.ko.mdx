## Monorepo 구조 [#monorepo-structure]

LibreChat은 명확하게 정의된 워크스페이스 경계를 가진 모노레포(monorepo)로 구성되어 있습니다:

| 워크스페이스 | 언어 | 구분 | 의존성 | 목적 |
| ------------------------- | ---------------- | -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `/api` | JS (legacy) | 백엔드 | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Express 서버 — 이곳의 변경은 최소화 |
| `/packages/api` | **TypeScript** | 백엔드 | `packages/data-schemas`, `packages/data-provider` | 새로운 백엔드 코드가 위치하는 곳 (TS 전용, `/api`에서 사용) |
| `/packages/data-schemas` | TypeScript | 백엔드 | `packages/data-provider` | 데이터베이스 모델/스키마, 백엔드 프로젝트 간 공유 가능 |
| `/packages/data-provider` | TypeScript | 공유 | — | 공유 API 타입, 엔드포인트, 데이터 서비스 — 프론트엔드와 백엔드 모두에서 사용 |
| `/client` | TypeScript/React | 프론트엔드 | `packages/data-provider`, `packages/client` | 프론트엔드 SPA |
| `/packages/client` | TypeScript | 프론트엔드 | `packages/data-provider` | 공유 프론트엔드 유틸리티 |
| `/packages/chat` | TypeScript | 프론트엔드 | `packages/data-provider`, `packages/client` | `@librechat/chat`: `/client`에서 분리되는 채팅 상태, 전송 계층, 메시지 컴포넌트; 앱을 절대 import하지 않음 |

### 주요 원칙 [#key-principles]

- `/packages/api` 내의 **모든 신규 백엔드 코드는 반드시 TypeScript여야 합니다.**
- `/api` 변경 사항을 최소한으로 유지하세요. `/packages/api`를 호출하는 얇은 JS 래퍼(thin JS wrappers) 형태여야 합니다.
- 데이터베이스 관련 공유 로직은 `/packages/data-schemas`에 위치해야 합니다.
- 프론트엔드/백엔드 공유 API 로직(endpoints, types, data-service)은 `/packages/data-provider`에 위치합니다.

### 빌드 및 설치 [#build-and-install]

| 명령어 | 용도 |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | 잠금 파일(lockfile)이 변경된 경우 의존성 설치 + Turborepo를 통한 빌드 |
| `npm run reinstall` | Node/npm 버전을 변경했거나 의존성 상태가 의심스러울 때 깨끗하게 다시 설치 |
| `npm run build` | Turborepo를 통해 컴파일된 모든 코드 빌드(병렬 실행, 캐시 사용) |
| `npm run frontend` | 컴파일된 모든 코드를 순차적으로 빌드(레거시 대체 방식) |
| `npm run build:data-provider` | 변경 후 `packages/data-provider` 다시 빌드 |
| `npm run backend` | 백엔드 서버 시작 |
| `npm run backend:dev` | 파일 감시 기능과 함께 백엔드 시작(개발용) |
| `npm run frontend:dev` | HMR을 지원하는 프론트엔드 개발 서버 시작(포트 3090, 백엔드가 실행 중이어야 함) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- 데이터베이스: MongoDB
- 백엔드는 `http://localhost:3080/`에서, 프론트엔드 개발 서버는 `http://localhost:3090/`에서 실행됩니다.

## 공유 스키마 및 컴포넌트 호환성 [#shared-schema-and-component-compatibility]

`v0.8.9-rc1` 공유 패키지는 Zod 4를 사용합니다. `librechat-data-provider` 스키마를 조합하는 소비자는 호환되는 Zod 4 API를 사용하고, Zod 3 내부 구현에 의존하는 대신 내보낸 스키마로부터 입력/출력 타입을 추론해야 합니다. 커스텀 패키지 소비자는 함께 다시 빌드하세요. Zod 3를 override로 강제 적용하는 것은 호환성을 확보하는 방법이 아닙니다.

클라이언트 패키지는 더 이상 레거시 `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate` 또는 Radix `DropdownMenu` 컨트롤을 내보내지 않습니다. 현재 LibreChat 호출자가 사용하는 유지 관리되는 Dropdown 기반 선택기 및 대화 상자 프리미티브를 사용하십시오. 자세한 내용은 [업그레이드 가이드](/docs/configuration/upgrade#shared-package-compatibility)를 참조하십시오.
