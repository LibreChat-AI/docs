## Struktura Monorepo [#monorepo-structure]

LibreChat jest zorganizowany jako monorepo z wyraźnie określonymi granicami obszarów roboczych:

| Obszar roboczy | Język | Strona | Zależność | Cel |
| ------------------------- | ---------------- | -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `/api` | JS (legacy) | Backend | `packages/api`, `packages/data-schemas`, `packages/data-provider`, `@librechat/agents` | Serwer Express — ogranicz zmiany do minimum |
| `/packages/api` | **TypeScript** | Backend | `packages/data-schemas`, `packages/data-provider` | Nowy kod backendu znajduje się tutaj (wyłącznie TS, wykorzystywany przez `/api`) |
| `/packages/data-schemas` | TypeScript | Backend | `packages/data-provider` | Modele i schematy bazy danych, możliwe do współdzielenia między projektami backendowymi |
| `/packages/data-provider` | TypeScript | Wspólny | — | Współdzielone typy API, endpointy, data-service — wykorzystywane zarówno przez frontend, jak i backend |
| `/client` | TypeScript/React | Frontend | `packages/data-provider`, `packages/client` | Frontend SPA |
| `/packages/client` | TypeScript | Frontend | `packages/data-provider` | Współdzielone narzędzia frontendowe |
| `/packages/chat` | TypeScript | Frontend | `packages/data-provider`, `packages/client` | `@librechat/chat`: stan czatu, transport i komponenty wiadomości przenoszone z `/client`; nigdy nie importuje aplikacji |

### Kluczowe zasady [#key-principles]

- **Cały nowy kod backendowy musi być w TypeScript** w `/packages/api`.
- Ogranicz zmiany w `/api` do absolutnego minimum — używaj lekkich wrapperów JS wywołujących `/packages/api`.
- Logika współdzielona specyficzna dla bazy danych znajduje się w `/packages/data-schemas`.
- Wspólna logika API dla frontend/backend (endpointy, typy, data-service) znajduje się w `/packages/data-provider`.

### Budowanie i instalacja [#build-and-install]

| Polecenie | Cel |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `npm run smart-reinstall` | Instalacja zależności (jeśli zmienił się lockfile) oraz kompilacja za pomocą Turborepo |
| `npm run reinstall` | Czysta instalacja po zmianie wersji Node/npm lub gdy stan zależności budzi wątpliwości |
| `npm run build` | Kompilacja całego skompilowanego kodu za pomocą Turborepo (równolegle, z buforowaniem) |
| `npm run frontend` | Kompilacja całego skompilowanego kodu sekwencyjnie (rozwiązanie zapasowe, legacy) |
| `npm run build:data-provider` | Ponowna kompilacja `packages/data-provider` po wprowadzeniu zmian |
| `npm run backend` | Uruchomienie serwera backendu |
| `npm run backend:dev` | Uruchomienie backendu z obserwowaniem zmian plików (tryb deweloperski) |
| `npm run frontend:dev` | Uruchomienie serwera deweloperskiego frontendu z HMR (port 3090, wymaga działającego backendu) |

- Node.js: `v24.22.1`
- npm: `v11.13.0`
- Baza danych: MongoDB
- Backend działa na `http://localhost:3080/`; serwer deweloperski frontend na `http://localhost:3090/`

## Zgodność współdzielonego schematu i komponentów [#shared-schema-and-component-compatibility]

Pakiety współdzielone w wersji `v0.8.9-rc1` korzystają z Zod 4. Konsumenci, którzy komponują schematy `librechat-data-provider`, powinni używać API zgodnych z Zod 4 oraz wyprowadzać typy wejściowe i wyjściowe z eksportowanego schematu, zamiast polegać na wewnętrznych elementach Zod 3. Pakiety niestandardowe należy przebudowywać razem; wymuszanie Zod 3 za pomocą override nie jest prawidłową ścieżką zgodności.

Pakiet klienta nie eksportuje już przestarzałych kontrolek `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate` ani `DropdownMenu` z Radix. Użyj utrzymywanych selektorów opartych na Dropdown oraz prymitywów dialogowych, z których korzystają aktualne wywołania w LibreChat. Zobacz [przewodnik aktualizacji](/docs/configuration/upgrade#shared-package-compatibility).
