## ローカルユニットテスト [#local-unit-tests]

更新を送信する前に、すべてのユニットテストに合格することを確認してください。テストをローカルで実行するには、以下の手順に従ってください：

- 以下のテスト用環境変数ファイルのサンプルを、API テストで使用するためにコピーしてください:

  ```bash filename="create api/test/.env.test"
  cp api/test/.env.test.example api/test/.env.test
  ```

- `npm run test:client`
- `npm run test:api`
- `npm run test:packages:api`
- `npm run test:packages:data-provider`
- `npm run test:packages:data-schemas`
- `npm run test:packages:chat`
- `npm run test:all` を実行すると、上記のすべてのテストスイートが順番に実行されます。

### 静的チェック [#static-checks]

コミット時には、husky の pre-commit フックを通じて Static Checks CI ジョブもローカルで実行されます(オプトアウトするには `HUSKY=0` を設定してください)。手動で実行するには `npm run static-checks` を使用するか、ベースブランチを指定して `npm run static-checks -- --against origin/dev` を実行します。`npm run static-checks:full` を使用すると、より時間のかかるチェック(TypeScript、設定マイグレーションのテスト、未使用の i18n キー、未使用の npm パッケージ)が追加されます。

### ワークスペースごとにテストを実行する [#running-tests-per-workspace]

テストは、各ワークスペースディレクトリから Jest を使用して実行されます。パターンを指定して特定のテストファイルをターゲットにすることができます：

```bash
cd api && npx jest <pattern>
cd packages/api && npx jest <pattern>
cd packages/data-provider && npx jest <pattern>
cd packages/data-schemas && npx jest <pattern>
cd packages/chat && npx jest <pattern>
cd client && npx jest <pattern>
```

## テストの哲学 [#testing-philosophy]

- モックよりも実際のロジックを優先してください。モックは、外部HTTP API、レート制限のあるサービス、非決定的なシステムコールなど、ローカルで制御できないものに対してのみ使用してください。
- 実際の関数が期待される引数で呼び出されたことをアサートする必要がある場合は、スパイを使用してください。
- MongoDBベースのテストには `mongodb-memory-server` を使用することで、クエリやスキーマのバリデーションを実際のデータベースの挙動に対して実行できます。
- UI/データフローの読み込み中、成功、およびエラー状態をカバーします。

<Callout type="tip" title="ヒント">
  フロントエンドテストでコンポーネントをレンダリングするには、`test/layout-test-utils` を使用してください。
</Callout>
