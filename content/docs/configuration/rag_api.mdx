The RAG API indexes user-uploaded files and retrieves relevant passages to augment your prompts, giving LibreChat context-aware responses grounded in your documents. It runs as a separate FastAPI service backed by a PostgreSQL + pgvector database.

<Callout type="info" title="What users see">
[Chat with Files](/docs/features/rag_api) covers uploading for file search, reusing files, and file search in agents. This page covers setup and configuration.
</Callout>

## Availability

File search through the RAG API works in [Agents](/docs/features/agents) and in regular chats on every endpoint except Assistants. OpenAI Assistants use OpenAI's own file storage and retrieval instead, and files uploaded there cannot be attached elsewhere.

Users only see **Upload for File Search** when the `file_search` agent capability is enabled (it is by default) and their role has the File Search permission ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Docker Quick Start

For Docker, the RAG API is already wired up in both the default `docker-compose.yml` and `deploy-compose.yml` files, including the `RAG_API_URL` value. You only need to make sure you are running the latest image and compose files. See the [Updating LibreChat guide for Docker](/docs/local/docker#updating-librechat) if you are unsure how to update.

<Callout type="warning" title="Shared .env file">
With the default Docker setup, the `.env` file is shared between LibreChat and the RAG API. Define the RAG variables in that same file. The full list lives in the [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

The default `docker-compose.yml` and `deploy-compose.yml` files set `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` on the `api` service. Environment variables set on the service take precedence over the `.env` file, so you do not need to add `RAG_API_URL` to `.env` for the bundled setup, and setting it there has no effect. To point a Docker deployment at an external RAG API, override the value on the `api` service instead, for example for a RAG API running on the Docker host:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

The `extra_hosts` entry is needed on Linux, where Docker does not define `host.docker.internal` itself.

Compose loads `docker-compose.override.yml` automatically only with the default `docker-compose.yml`. With `deploy-compose.yml`, pass both files: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Outside Docker, set `RAG_API_URL` in your `.env` file.

### Lite vs. full image

Docker uses the "lite" image of the RAG API by default (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), which only supports remote embeddings from OpenAI or a remote HuggingFace/Ollama service you have configured.

For local embeddings, switch the image in the compose file to the full build, `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Make this change in your [Docker Compose Override File](/docs/configuration/docker_override). See `docker-compose.override.yml.example` at the root of the project for an example.

If you want a compose file that includes only the PostgreSQL + pgvector database and the Python API, see `rag.yml` at the root of the project.

### Database storage

The default compose files store the pgvector/PostgreSQL data in the Docker-managed `pgdata2` volume. This is intentional: the database files don't need to be edited directly from the host, and a managed volume avoids common ownership and permission problems. User-facing, editable files (uploads, logs, images, MongoDB data, and NGINX config) are bind-mounted to project folders where direct host access is useful.

## Local Setup

A non-container setup is more hands-on. Follow the instructions in the [RAG API repo](https://github.com/LibreChat-AI/rag-api/).

Set `RAG_API_URL` in your LibreChat `.env` file to wherever the API is reachable from your setup. This differs from the bundled Docker setup, where the value is already set on the `api` service in the default `docker-compose.yml` and `deploy-compose.yml` files.

## Configuration

Set RAG API options through environment variables in an `.env` file accessible to the API. Most are optional, aside from the credentials and paths required by your chosen provider. In the default setup, only `RAG_OPENAI_API_KEY` is required.

## Usage

Once the RAG API is reachable, there is nothing else to switch on in LibreChat. Users upload with **Upload for File Search**, and the model queries the index through the `file_search` tool when a question calls for it. If `RAG_API_URL` is not set or the service is down, those uploads fail; LibreChat logs a warning at startup when it cannot reach the RAG API health check. See [Chat with Files](/docs/features/rag_api) for the user side.

## Troubleshooting

If you run into issues setting up or using the RAG API:

- Confirm all required environment variables are set correctly in your `.env` file.
- Make sure the vector database is configured and accessible.
- Verify that the OpenAI API key or other provider credentials are valid.
- Check both the LibreChat and RAG API logs for errors or warnings.

If the problem persists, refer to the RAG API documentation or ask the LibreChat community on GitHub Discussions or Discord.
