LibreChat은 대화 데이터에 만료 날짜를 설정하고 이를 자동으로 삭제할 수 있습니다. 동일한 메커니즘이 사용자가 직접 시작하는 [임시 채팅](/docs/features/temporary_chat)과 "90일이 지난 모든 채팅 삭제"와 같은 배포 전체 정책도 처리합니다. 이 모든 설정은 `librechat.yaml`의 `interface` 아래에서 구성하며, 각 키는 [interface 참조](/docs/configuration/librechat_yaml/object_structure/interface#retentionmode)에도 나열되어 있습니다.

## 옵션 [#options]

```yaml filename="librechat.yaml"
interface:
  # Seeds the TEMPORARY_CHAT permission for the USER role (manage per role in the Admin Panel)
  temporaryChat: true

  # Which chats expire: "temporary" (default), "all", or "ephemeral"
  retentionMode: 'temporary'

  # Lifetime of temporary chats, in hours. Default 720 (30 days), range 1 to 8760.
  temporaryChatRetention: 720

  # Lifetime of regular chats under retentionMode "all", in hours. Defaults to temporaryChatRetention.
  # generalChatRetention: 2160

  # Under "all" or "ephemeral", keep files uploaded to agents from expiring.
  retainAgentFiles: false
```

`librechat.yaml`에서 1에서 8760 시간 범위를 벗어난 값은 설정 검증에 실패합니다.

`TEMP_CHAT_RETENTION_HOURS` 환경 변수는 지원 중단(deprecated)되었지만, 여전히 임시 채팅의 보존 기간을 설정합니다. 두 설정이 모두 지정된 경우에는 `interface.temporaryChatRetention`이 우선 적용됩니다. 환경 변수 값이 잘못된 경우에는 720으로 대체되며, 허용 범위를 벗어난 값은 1 또는 8760으로 고정(clamp)되고 서버 로그에 경고가 기록됩니다.

## 세 가지 모드 [#the-three-modes]

| 모드 | 만료되는 항목 | 기록 및 검색에 표시 | 사용자 거부(opt-out) 가능 여부 |
| --- | --- | --- | --- |
| `temporary` (기본값) | 사용자가 임시로 표시한 채팅만 | 일반 채팅은 예, 임시 채팅은 아니요 | 예, 채팅별로 가능 |
| `all` | 모든 채팅 | 각 채팅이 만료되기 전까지 예 | 아니요 |
| `ephemeral` | 모든 채팅 | 아니요, 모든 채팅이 임시 채팅임 | 아니요, 토글이 켜진 상태로 잠김 |

**`temporary`**은 기존 동작을 그대로 유지합니다. 사용자가 (토글 또는 **Temporary Chat by default** 설정으로) 임시 채팅으로 표시한 채팅은 기록 및 검색에서 숨겨지고 `temporaryChatRetention` 시간(시간 단위) 이후에 삭제됩니다. 일반 채팅은 만료되지 않습니다.

**`all`**은 모든 대화와 메시지에 만료 날짜를 부여하되, 사용자에게 채팅이 보이는 방식은 바꾸지 않습니다. 채팅은 만료되기 전까지 기록과 검색에 계속 남아 있습니다. 일반 채팅은 `generalChatRetention`을 사용하며, 설정되지 않은 경우 `temporaryChatRetention`을 사용합니다. 사용자가 임시 채팅으로 표시한 대화는 여전히 임시 채팅으로 동작합니다. 업로드된 파일과 공유 링크도 만료되며, 에이전트 리소스 파일은 `retainAgentFiles: true`를 설정한 경우에만 보관됩니다. "N일 동안 모두 보관한 후 삭제"하는 정책을 원할 때 이 옵션을 사용하세요.

**`ephemeral`**은 배포 전체에서 모든 채팅을 임시로 만듭니다. 모든 채팅은 기록과 검색에서 숨겨지고, 자동 생성 제목이 없으며, `temporaryChatRetention` 시간(시간 단위) 후에 삭제됩니다. `generalChatRetention`은 무시됩니다. **임시 채팅** 토글은 `TEMPORARY_CHAT` 권한이 없는 역할을 포함한 모든 사용자에게 켜진 상태로 잠겨 표시되며, 키보드 단축키는 동작하지 않습니다. 서버가 이 설정을 강제하므로, 클라이언트가 채팅을 영구 저장으로 설정하려 해도 무시됩니다. [`langfuse.trace.temporaryChats`](/docs/configuration/langfuse#temporary-chats)를 설정하지 않으면 어떤 채팅도 Langfuse로 추적되지 않습니다.

## 삭제 작동 방식 [#how-deletion-works]

각 대화와 메시지에는 `expiredAt` 날짜가 포함되며, 임시 대화의 경우 `isTemporary: true`로 표시됩니다. 숨겨졌거나 만료된 기록은 삭제되기 전에 대화 기록 목록과 검색 인덱스에서 필터링됩니다.

- 대화, 메시지, 공유 링크는 `expiredAt`에 걸린 MongoDB TTL 인덱스에 의해 삭제됩니다. MongoDB는 이 작업을 백그라운드에서 실행하며, 보통 만료 시점으로부터 약 1분 이내에 처리됩니다.
- 주기적인 정리 작업을 통해 LibreChat에서 파일이 삭제되며, 이때 저장된 파일(로컬 디스크, S3 등)을 먼저 삭제한 다음 해당 레코드를 삭제합니다.

마감일은 레코드가 저장될 때 설정됩니다. 대화를 저장할 때마다 해당 대화의 마감일이 뒤로 연장되므로, 활발히 사용 중인 채팅은 삭제되지 않습니다. 각 메시지는 저장될 때 부여받은 마감일을 그대로 유지합니다.

`all`과 `ephemeral` 설정에서는 채팅 데이터가 기록되는 모든 곳에 보관 정책이 적용됩니다. 여기에는 새 메시지, 재생성 및 분기, 편집, 피드백, 아티팩트 편집, 재개된 응답, 포크, 복제, 가져오기가 포함됩니다.

- `ephemeral` 설정에서는 포크, 복제, 가져오기가 항상 임시 대화로 처리됩니다. `all` 설정에서는 임시 대화의 복사본은 임시 상태를 유지하며, 그 밖의 복사본과 가져오기는 만료 날짜와 함께 표시된 상태로 유지됩니다.
- 공유 링크의 만료 시점은 해당 대화에서 가져오므로, 링크가 대화보다 오래 유지되지 않습니다.
- [Memories](/docs/features/memory)는 만료되지 않으며, 어떤 모드에도 영향을 받지 않습니다.

## 모드 전환 [#switching-modes]

`retentionMode` 또는 보존 기간을 변경하면 이후에 저장되는 레코드에만 적용됩니다. 기존 만료 기한은 다시 계산되지 않습니다.

- **`all` 또는 `ephemeral`로 설정한 경우:** 기존 채팅은 다음에 기록될 때 만료 시점이 설정됩니다. `ephemeral` 설정에서는 새 메시지, 편집, 피드백 또는 브랜치를 받은 이전의 일반 채팅이 즉시 임시 채팅으로 전환됩니다. 이 채팅은 기록과 검색에서 제외되며 북마크도 잃게 됩니다. 아무도 건드리지 않은 채팅은 현재 상태를 그대로 유지합니다.
- **`temporary`로 되돌리기:** `all`로 저장된 채팅은 기존 만료 기한을 유지하며 여전히 삭제됩니다. `ephemeral`로 저장된 채팅은 임시 상태를 유지하며 계속 만료됩니다.

`all` 또는 `ephemeral`을 떠난 후 일반 채팅이 만료되지 않도록 하려면 `mongosh`에서 해당 마감 기한을 삭제하세요:

```js filename="mongosh"
db.conversations.updateMany(
  { isTemporary: false, expiredAt: { $ne: null } },
  { $unset: { expiredAt: 1 } },
)
db.messages.updateMany(
  { isTemporary: false, expiredAt: { $ne: null } },
  { $unset: { expiredAt: 1 } },
)
```

업그레이드 후 `conversations` 및 `messages` 컬렉션에 `_meiliIndex_1_isTemporary_1_expiredAt_1` 인덱스가 생성되면, 두 컬렉션에서 기존의 `_meiliIndex_1_expiredAt_1` 인덱스를 삭제할 수 있습니다. MongoDB는 대체된 인덱스를 자동으로 삭제하지 않습니다.

## 예시 [#examples]

마지막 활동 후 90일이 지나면 모든 채팅을 삭제하며, 그때까지는 채팅이 계속 표시됩니다:

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'all'
  generalChatRetention: 2160 # 90 days for regular chats
  temporaryChatRetention: 24 # 1 day for chats users mark as temporary
```

모든 대화를 임시로 설정하고 24시간 후에 삭제합니다:

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'ephemeral'
  temporaryChatRetention: 24
```

모든 채팅을 일주일 동안 임시로 설정하되, 에이전트에 첨부된 파일은 유지하세요:

```yaml filename="librechat.yaml"
interface:
  retentionMode: 'ephemeral'
  temporaryChatRetention: 168
  retainAgentFiles: true
```
