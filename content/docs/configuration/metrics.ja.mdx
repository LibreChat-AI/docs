## 一般 [#general]

![LibreChatのアクティブユーザー](/images/metrics/librechat-metrics-active-users.png)

LibreChatは、Prometheus互換のメトリクスサーフェスを2つ提供しています。APIに組み込まれた `/metrics` endpointは、Redisのアクティビティやブラウザテレメトリプロキシの結果といった運用状況を報告します。オプションのデータベースエクスポーターは、トークン合計数やアクティブユーザー数など、MongoDBに保存された使用状況データを報告します。

## 組み込みのAPIメトリクス [#built-in-api-metrics]

LibreChatは、APIサーバーから `/metrics` でPrometheusメトリクスを公開しています。`METRICS_SECRET` を設定し、`Authorization: Bearer <METRICS_SECRET>` を使用してエンドポイントをスクレイピングしてください。シークレットが未設定の場合、ヘッダーが欠落している場合、またはトークンが一致しない場合、エンドポイントは `401` を返します。

```yaml filename="prometheus.yml"
scrape_configs:
  - job_name: librechat-api
    scheme: https
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials: your-metrics-secret
    static_configs:
      - targets: ['librechat.example.com']
```

### プロセス、HTTP、リクエストのメトリクス [#process-http-and-request-metrics]

エンドポイントでは、`prom-client` が提供するデフォルトの Node.js およびプロセスのメトリクスに加え、以下のシリーズも公開されます。

| グループ | メトリクス | ラベル |
| --- | --- | --- |
| HTTP | `http_requests_total`, `http_request_duration_seconds` | `method`, `path`, `status` |
| HTTP | `http_requests_in_flight`, `http_request_body_bytes` (`Content-Length` から) | `method`, `path` |
| SSE | `sse_streams_total`, `sse_stream_duration_seconds` | `method`, `path`, `status` |
| SSE | `sse_streams_in_flight` | `method`, `path` |
| アップロード | `upload_requests_total`, `upload_request_duration_seconds` | `method`, `path`, `status` |
| アップロード | `upload_requests_in_flight`, `upload_bytes_total` (`Content-Length` から) | `method`, `path` |
| OpenID | `openid_user_lookup_total`, `openid_user_lookup_duration_seconds` | `result` |
| Mongoose | `mongoose_queries_total`, `mongoose_query_duration_seconds` | `model`, `operation`, `status` |
| 生成ジョブ | `generation_jobs_total` | `store`, `result` |
| 生成ジョブ | `generation_jobs_in_flight` | `store` |
| 生成ストリーム | `generation_stream_subscriptions_total` | `store`, `type`, `result` |
| 生成ストリーム | `generation_stream_resume_pending_events_total`, `generation_stream_early_buffer_overflows_total`, `generation_stream_first_attachment_delay_seconds` | `store` |
| 生成ストリーム | `generation_stream_attachment_outcomes_total` | `store`, `outcome` |
| 生成ストリーム | `generation_stream_recoveries_total`, `generation_stream_recovery_duration_seconds`, `generation_stream_recovery_events`, `generation_stream_recovery_content_parts` | `store`, `method`, `outcome` |
| コンテンツフィルター | `content_filter_locator_traversal_failures_total` | `operation`, `reason` |
| コンテンツフィルター | `content_filter_locator_traversal_size` | `operation`, `reason`, `dimension` |

生成ストリーム復旧メトリクスは、オーバーフローした初期イベントバッファがどのように再構築されるかを説明します。コンテンツフィルターメトリクスは、不完全な解決済みファイルロケーターのトラバーサルの回数を数えます。

### エージェント起動メトリクス [#agent-startup-metrics]

初期のエージェントチャットリクエストは、2つのスタートアップメトリクスを出力します：

- `agent_startup_milestone_duration_seconds{milestone}` は、リクエストの受信から各スタートアップマイルストーンまでの累積レイテンシを測定します。
- `agent_startups_total{result}` は、ターミナルの結果ごとの起動試行回数をカウントします。

マイルストーンは、リクエストの受付、ジョブの作成と承認、会話と履歴の読み込み、クライアントと実行の初期化、ストリームの開始、そして最初のキューに入れられたレスポンスまたはコンテンツイベントをカバーします。結果は、コンテンツのキューイング、コンテンツのデルタなしの完了、重複排除、拒否、一時停止、置換、中止、およびエラーを区別します。

[バックエンドの OpenTelemetry トレース](/docs/configuration/dotenv#opentelemetry-traces-and-logs)が有効な場合、`librechat.agent.startup` スパンは同じマイルストーンをイベントとして報告します。これには、起動の合計所要時間、マイルストーンの数、最終的な結果、および割り当てられている場合は生成ストリーム ID が含まれます。

### Redis メトリクス [#redis-metrics]

Redis-backedキャッシュおよびサービスは、2つの論理操作メトリクスを出力します：

- `redis_operations_total{client,use_case,operation,status}` は操作の回数をカウントします。
- `redis_operation_duration_seconds{client,use_case,operation,status}` はレイテンシを測定します。

`client` は `keyv` または `ioredis` であり、`status` は `success` または `error` です。境界付けられた `use_case` ラベルは、キャッシュ、セッション、レート制限、同時実行、ACLプリンシパル、再開可能なストリームジョブとPub/Sub、MCPレジストリのスキャン、リーダー選出といった作業を識別します。これらのメトリクスは、Redisの内部的なラウンドトリップすべてではなく、LibreChatの論理的な操作をカウントします。接続ライフサイクルのpingやグローバルなメンテナンスは除外され、名前空間のクリアは1つの論理操作としてカウントされます。

[バックエンドの OpenTelemetry トレーシング](/docs/configuration/dotenv#opentelemetry-traces-and-logs)が有効な場合、各 HTTP スパンには、Redis の処理内容を要約した以下の情報も含まれます:

- `librechat.redis.calls`
- `librechat.redis.duration_ms`
- `librechat.redis.errors`
- `librechat.redis.max_call_ms`
- `librechat.redis.operations`
- `librechat.redis.use_cases`

合計期間が最も長い10個のユースケースには、`librechat.redis.<use_case>.*` の下に `calls`、`duration_ms`、`errors`、および `max_call_ms` 属性も付与されます。このリクエストレベルのサマリーにはコマンドレベルの Redis スパンは不要です。個別のコマンドスパンが必要な場合にのみ、`OTEL_IOREDIS_TRACING_ENABLED` を有効にしてください。

### ブラウザRUMプロキシメトリクス [#browser-rum-proxy-metrics]

Browser RUM プロキシの結果は `rum_proxy_requests_total{endpoint,result}` として報告されます。`endpoint` は `traces`、`logs`、または `unknown` です。`result` は `success`、`auth_drop`、`auth_error`、`bad_request`、`not_configured`、`collector_4xx`、`collector_5xx`、`collector_error`、または `collector_timeout` となります。

### エージェントイベントアクターメトリクス [#agent-event-actor-metrics]

Durable bound Agent Eventsは、低カーディナリティの受信およびリカバリメトリクスを公開します：

- `agent_event_actor_receipt_operations_total{operation,outcome,resolution}` は、レシートの読み取り、決済、およびレガシーバックフィルをカウントします。`operation` は `read`、`settle`、または `backfill` です。`outcome` は `hit`、`miss`、`success`、`replay`、または `conflict` です。
- `agent_event_actor_receipts_retained{resolution}` は、`checkpoint_verified`、`action_compensated`、または `history_repaired` の解決によって保持されたリプレイレシートを報告します。
- `agent_event_actor_receipts_expiry_eligible` は、90日間の MongoDB TTL が経過したものの、まだ削除されていない保持済みのレシートを報告します。
- `agent_event_actor_reconciliations_pending` は、終了通知を待機しているアクティブな調整マーカーを報告します。
- `agent_event_actor_oldest_reconciliation_age_seconds` は、最も古いアクティブな調整（reconciliation）の経過時間を報告します。
- `agent_event_actor_deliveries{state}` は、現在 `retry` または `dead` 状態にある配信行を報告します。

ストレージゲージは認証済みスクレイプで収集され、最大60秒間キャッシュされます。単一のスクレイプではなく、持続的な調整の遅延（reconciliation age）、配信不能（dead deliveries）、または期限切れ対象のレシートに基づいてアラートを設定してください。

### 共有リンクのメトリクス [#shared-link-metrics]

`share_link_rejections_total{operation,code}` は、制限付きの作成または更新の失敗をカウントします。`operation` は `create` または `update` です。`code` は、選択されたブランチの末尾が永続化されていない場合は `TARGET_MESSAGE_NOT_FOUND`、会話に永続化されたメッセージがない場合は `NO_MESSAGES` となります。このメトリクスには、会話テキストやユーザーIDは含まれません。

## データベースメトリクスエクスポーター [#database-metrics-exporter]

メトリクスエクスポーターは [virtUOS/librechat_exporter](https://github.com/virtUOS/librechat_exporter) で利用可能です。
これは LibreChat と並行してデプロイする独立したツールです。

### セットアップ [#setup]

exporterをデプロイするには、以下のようにcompose設定に必要なコンテナを追加するだけです：

```yaml
services:
  metrics:
    image: ghcr.io/virtuos/librechat_exporter:main
    depends_on:
      - mongodb
    ports:
      - '8000:8000'
    restart: unless-stopped
```

オプションでエクスポーターを設定することもできます。
しかし通常は、デフォルト設定のままで問題ありません。

```yaml
services:
  metrics:
    environment:
      - MONGODB_URI=mongodb://mongodb:27017/
      - LOGGING_LEVEL=info
```

### 使用方法 [#usage]

これで、Prometheusのスクレイプ設定にエクスポーターを追加できるようになりました：

```yaml
- job_name: librechat
  static_configs:
    - targets:
        - 'librechat.example.com:8000'
```

メトリクスのスクレイピングが開始されたら、`librechat_*` メトリクス（例: `librechat_registered_users`）を探してください。
このエクスポーターはいくつかのメトリクスを提供します。

Grafanaダッシュボードの構築を楽しんでください！
