RAG API는 사용자가 업로드한 파일을 인덱싱하고 관련 구절을 검색하여 프롬프트를 보강함으로써, LibreChat이 문서에 기반한 문맥 인식 응답을 제공할 수 있도록 합니다. 이 서비스는 PostgreSQL + pgvector 데이터베이스를 기반으로 하는 별도의 FastAPI 서비스로 실행됩니다.

<Callout type="info" title="사용자에게 보이는 화면">
[Chat with Files](/docs/features/rag_api)는 파일 검색을 위한 업로드, 파일 재사용, 에이전트에서의 파일 검색을 다룹니다. 이 페이지에서는 설정 및 구성을 다룹니다.
</Callout>

## 가용성 [#availability]

RAG API를 통한 파일 검색은 Assistants를 제외한 모든 엔드포인트의 [에이전트](/docs/features/agents)와 일반 채팅에서 작동합니다. OpenAI Assistants는 대신 OpenAI 자체의 파일 저장소와 검색 기능을 사용하며, 여기에 업로드된 파일은 다른 곳에 첨부할 수 없습니다.

사용자는 `file_search` 에이전트 기능이 활성화되어 있고(기본값으로 활성화됨), 해당 역할에 파일 검색 권한이 있는 경우에만 **파일 검색용 업로드** 옵션을 볼 수 있습니다([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Docker Quick Start [#docker-quick-start]

Docker의 경우, RAG API는 기본 `docker-compose.yml` 및 `deploy-compose.yml` 파일에 이미 연결되어 있으며, `RAG_API_URL` 값도 포함되어 있습니다. 최신 이미지와 compose 파일을 실행 중인지만 확인하면 됩니다. 업데이트 방법이 확실하지 않다면 [Docker용 LibreChat 업데이트 가이드](/docs/local/docker#updating-librechat)를 참고하세요.

<Callout type="warning" title="공유 .env 파일">
기본 Docker 설정에서는 `.env` 파일이 LibreChat과 RAG API 간에 공유됩니다. RAG 변수를 해당 파일에 정의하십시오. 전체 목록은 [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md)에서 확인할 수 있습니다.
</Callout>

기본 `docker-compose.yml` 및 `deploy-compose.yml` 파일은 `api` 서비스에 `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}`을 설정합니다. 서비스에 설정된 환경 변수는 `.env` 파일보다 우선하므로, 번들 설정에서는 `RAG_API_URL`을 `.env`에 추가할 필요가 없으며, 거기에 설정해도 효과가 없습니다. 외부 RAG API를 바라보도록 Docker 배포를 구성하려면 대신 `api` 서비스에서 값을 재정의하십시오. 예를 들어 Docker 호스트에서 실행 중인 RAG API의 경우는 다음과 같습니다:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

`extra_hosts` 항목은 Docker가 `host.docker.internal`을 자체적으로 정의하지 않는 Linux에서 필요합니다.

Compose는 기본 `docker-compose.yml`과 함께 사용할 때만 `docker-compose.override.yml`을 자동으로 불러옵니다. `deploy-compose.yml`을 사용하는 경우에는 두 파일을 모두 지정해야 합니다: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Docker 외부에서 실행하는 경우, `.env` 파일에 `RAG_API_URL`을 설정하세요.

### Lite vs. full image [#lite-vs-full-image]

Docker는 기본적으로 RAG API의 "lite" 이미지(`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`)를 사용하며, 이는 OpenAI의 원격 임베딩이나 사용자가 구성한 원격 HuggingFace/Ollama 서비스만 지원합니다.

로컬 임베딩을 사용하려면, compose 파일의 이미지를 전체 빌드 버전인 `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`로 변경하세요. 이 변경 사항은 [Docker Compose Override File](/docs/configuration/docker_override)에서 적용해야 합니다. 예시는 프로젝트 루트에 있는 `docker-compose.override.yml.example`를 참조하세요.

PostgreSQL + pgvector 데이터베이스와 Python API만 포함하는 compose 파일을 원하신다면, 프로젝트 루트에 있는 `rag.yml`을 확인하세요.

### 데이터베이스 저장소 [#database-storage]

기본 compose 파일은 pgvector/PostgreSQL 데이터를 Docker가 관리하는 `pgdata2` 볼륨에 저장합니다. 이는 의도된 설계입니다. 데이터베이스 파일은 호스트에서 직접 편집할 필요가 없으며, 관리형 볼륨을 사용하면 일반적인 소유권 및 권한 문제를 방지할 수 있기 때문입니다. 사용자가 직접 편집해야 하는 파일(업로드, 로그, 이미지, MongoDB 데이터, NGINX 설정)은 호스트에서 직접 접근하는 것이 유용하므로 프로젝트 폴더에 바인드 마운트(bind-mounted)됩니다.

## 로컬 설정 [#local-setup]

컨테이너를 사용하지 않는 설정은 더 많은 수동 작업이 필요합니다. [RAG API repo](https://github.com/LibreChat-AI/rag-api/)의 지침을 따르세요.

LibreChat `.env` 파일에서 `RAG_API_URL`을 귀하의 환경에서 API에 접근할 수 있는 주소로 설정하십시오. 이는 기본 Docker 설정과 다릅니다. 기본 Docker 설정에서는 기본 `docker-compose.yml` 및 `deploy-compose.yml` 파일의 `api` 서비스에 해당 값이 이미 설정되어 있습니다.

## 사용법 [#usage]

RAG API에 연결할 수 있게 되면 LibreChat에서 따로 켜야 할 설정은 없습니다. 사용자는 **Upload for File Search**로 파일을 업로드하고, 질문에 필요할 때 모델이 `file_search` 도구를 통해 인덱스를 조회합니다. `RAG_API_URL`이 설정되지 않았거나 서비스가 중지되어 있으면 이러한 업로드는 실패하며, LibreChat은 RAG API 상태 확인에 연결할 수 없을 때 시작 시 경고를 기록합니다. 사용자 측 설명은 [Chat with Files](/docs/features/rag_api)를 참고하세요.

## 문제 해결 [#troubleshooting]

RAG API를 설정하거나 사용하는 중에 문제가 발생하면:

- `.env` 파일에 모든 필수 환경 변수가 올바르게 설정되었는지 확인하세요.
- 벡터 데이터베이스가 구성되어 있고 접근 가능한지 확인하세요.
- OpenAI API 키 또는 기타 공급자 자격 증명이 유효한지 확인하세요.
- LibreChat 및 RAG API 로그에서 오류나 경고가 있는지 확인하세요.

문제가 지속되면 RAG API 문서를 참조하거나 GitHub Discussions 또는 Discord의 LibreChat 커뮤니티에 문의하세요.
