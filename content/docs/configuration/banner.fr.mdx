Affichez des messages importants à tous vos utilisateurs en haut de l'application. Idéal pour les annonces, les avis de maintenance ou les mises à jour.

<Callout type="info" title="Aperçu rapide">
  - Seule **une bannière** peut être active à la fois
  - Planifiez l'apparition et la disparition automatique des bannières
  - Choisissez si les utilisateurs peuvent ignorer la bannière ou non
  - Afficher des bannières à tout le monde, ou uniquement aux utilisateurs connectés
</Callout>

---

## Création d'une bannière [#creating-a-banner]

Exécutez cette commande pour créer ou mettre à jour une bannière :

```bash
npm run update-banner
```

Avec Docker, exécutez plutôt le script à l'intérieur du conteneur `api` :

```bash
docker compose exec api npm run update-banner
```

Vous serez guidé à travers quelques invites simples :

```ansi
--------------------------
Update the banner!
--------------------------
Display From (Format: yyyy-mm-ddTHH:MM:SSZ, Default: now):
> 2025-12-02T09:00:00Z

Display To (Format: yyyy-mm-ddTHH:MM:SSZ, Default: not specified):
> 2025-12-31T23:59:59Z

Enter your message (Enter a single dot "." on a new line to finish):
> 🎉 Welcome to LibreChat! Check out our new features.
> .

Is public (y/N):
> n

Is persistable (cannot be dismissed) (y/N):
> n
```

<Callout type="tip" title="Que signifient ces options ?">
  - **Afficher du / au** : Moment où la bannière doit apparaître et disparaître. Appuyez sur Entrée à l'invite pour utiliser « maintenant » et « toujours ».
  - **Is public** : Afficher aux visiteurs qui ne sont pas connectés (comme sur la page de connexion)
  - **Est persistant** : si oui, les utilisateurs ne peuvent pas fermer la bannière (à utiliser pour les avis importants)
</Callout>

<Callout type="warning" title="Réexécuter ceci remplace la bannière existante">

Il n'y a toujours qu'une seule bannière. `update-banner` recherche une bannière existante et l'écrase sur place, n'en créant une que lorsqu'il n'en existe aucune ; vous ne pouvez donc pas mettre en file d'attente une seconde bannière pour une date ultérieure, et vous ne pouvez pas avoir deux fenêtres programmées qui se chevauchent. L'exécution à nouveau de la commande supprime le message et la planification de la bannière précédente.

Pour modifier une bannière, exécutez à nouveau `update-banner`. Pour en retirer une avant son heure de `Display To`, utilisez `delete-banner` ci-dessous.

</Callout>

## Suppression d'une bannière [#deleting-a-banner]

```bash
npm run delete-banner
```

Avec Docker, exécutez `docker compose exec api npm run delete-banner`.

Vous verrez la bannière actuelle et il vous sera demandé de confirmer avant la suppression.

<Callout type="warning" title="Seule une bannière active peut être supprimée">

`delete-banner` ne trouve qu'une bannière actuellement active : son heure `Display From` doit être passée, et son heure `Display To` doit être dans le futur ou ne pas être définie. Une bannière programmée pour une date ultérieure, ou dont `Display To` est déjà passée, est signalée par le message « No banner found to delete » et reste dans la base de données. Pour remplacer une telle bannière, exécutez à nouveau `update-banner`.

</Callout>

Supprimer une bannière de cette manière est également la façon de l'enlever prématurément : il n'existe pas d'indicateur « désactiver ». Une bannière disparaît sinon d'elle-même une fois que la date de `Display To` est passée, et une bannière enregistrée sans `Display To` reste affichée jusqu'à ce que vous la supprimiez.

## Exemples de bannières [#example-banners]

<Tabs items={['Message de bienvenue', 'Avis de maintenance', 'Alerte de sécurité']}>
  <Tabs.Tab>
    Un message de bienvenue simple que les utilisateurs peuvent ignorer :

    ```bash
    npm run update-banner "" "" "👋 Welcome to LibreChat!" "false" "false"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Un avis de maintenance programmée qui ne peut pas être ignoré :

    ```bash
    npm run update-banner "2025-12-20T00:00:00Z" "2025-12-21T06:00:00Z" "⚠️ Scheduled maintenance on Dec 20th, 2-6 AM UTC" "true" "true"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Un avis de sécurité urgent visible par tous :

    ```bash
    npm run update-banner "" "" "🔒 Please update your password by January 1st" "true" "true"
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="info" title="Les arguments de date vides affichent toujours une invite">

Une chaîne vide (`""`) pour une date est considérée comme absente, de sorte que le script demande toujours `Display From` et `Display To` de manière interactive. Appuyez sur Entrée à chaque invite pour accepter la valeur par défaut, ou passez des dates ISO (`yyyy-mm-ddTHH:MM:SSZ`) comme deux premiers arguments pour exécuter la commande sans invites. L'argument message est également requis pour ignorer l'invite de message, et les arguments `isPublic` et `persistable` doivent être fournis sous la forme `true` ou `false` pour ignorer leurs invites.

</Callout>

## Format de date [#date-format]

Utilisez ce format pour les dates : `yyyy-mm-ddTHH:MM:SSZ`

**Exemples :**
- `2025-12-25T09:00:00Z` → 25 décembre 2025 à 9h00 (UTC)
- `2025-01-01T00:00:00Z` → 1er janvier 2025 à minuit (UTC)

Lorsque l'invite s'affiche, appuyez sur Entrée sans saisir de date pour utiliser l'heure actuelle pour `Display From`, ou aucune date de fin pour `Display To`.
