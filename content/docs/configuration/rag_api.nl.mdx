De RAG API indexeert door gebruikers geüploade bestanden en haalt relevante passages op om uw prompts aan te vullen, waardoor LibreChat contextbewuste antwoorden krijgt die gebaseerd zijn op uw documenten. Het draait als een afzonderlijke FastAPI-service die wordt ondersteund door een PostgreSQL + pgvector database.

<Callout type="info" title="Wat gebruikers zien">
[Chat with Files](/docs/features/rag_api) behandelt het uploaden voor bestandszoekopdrachten, het hergebruiken van bestanden en bestandszoekopdrachten in agents. Deze pagina behandelt de installatie en configuratie.
</Callout>

## Beschikbaarheid [#availability]

Bestandszoeken via de RAG API werkt in [Agents](/docs/features/agents) en in reguliere chats op elk endpoint behalve Assistants. OpenAI Assistants gebruiken in plaats daarvan de eigen bestandsopslag en ophaalfunctie van OpenAI, en bestanden die daar zijn geüpload, kunnen niet elders worden gekoppeld.

Gebruikers zien **Upload for File Search** alleen wanneer de agentfunctie `file_search` is ingeschakeld (dat is standaard het geval) en hun rol de File Search-machtiging heeft ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Docker Quick Start [#docker-quick-start]

Voor Docker is de RAG API al ingesteld in zowel het standaard `docker-compose.yml`- als het `deploy-compose.yml`-bestand, inclusief de waarde `RAG_API_URL`. Je hoeft alleen te controleren of je de nieuwste image en compose-bestanden gebruikt. Zie de [Updating LibreChat guide for Docker](/docs/local/docker#updating-librechat) als je niet zeker weet hoe je moet updaten.

<Callout type="warning" title="Gedeeld .env bestand">
Bij de standaard Docker-configuratie wordt het `.env` bestand gedeeld tussen LibreChat en de RAG API. Definieer de RAG-variabelen in datzelfde bestand. De volledige lijst staat in de [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

De standaard `docker-compose.yml`- en `deploy-compose.yml`-bestanden stellen `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` in op de `api`-service. Omgevingsvariabelen die op de service zijn ingesteld, hebben voorrang op het `.env`-bestand, dus je hoeft `RAG_API_URL` niet aan `.env` toe te voegen voor de meegeleverde opstelling, en het instellen ervan daar heeft geen effect. Om een Docker-implementatie naar een externe RAG API te laten verwijzen, overschrijf je in plaats daarvan de waarde op de `api`-service, bijvoorbeeld voor een RAG API die op de Docker-host draait:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

De `extra_hosts`-vermelding is nodig op Linux, waar Docker `host.docker.internal` niet zelf definieert.

Compose laadt `docker-compose.override.yml` automatisch alleen bij het standaardbestand `docker-compose.yml`. Met `deploy-compose.yml` geef je beide bestanden op: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Buiten Docker stel je `RAG_API_URL` in je `.env`-bestand in.

### Lite vs. full image [#lite-vs-full-image]

Docker gebruikt standaard de "lite"-image van de RAG API (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), die alleen ondersteuning biedt voor externe embeddings van OpenAI of een externe HuggingFace/Ollama-service die je hebt geconfigureerd.

Voor lokale embeddings, wijzig de image in het compose-bestand naar de volledige build, `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Breng deze wijziging aan in je [Docker Compose Override File](/docs/configuration/docker_override). Zie `docker-compose.override.yml.example` in de root van het project voor een voorbeeld.

Als je een compose-bestand wilt dat alleen de PostgreSQL + pgvector-database en de Python API bevat, zie dan `rag.yml` in de root van het project.

### Database-opslag [#database-storage]

De standaard compose-bestanden slaan de pgvector/PostgreSQL-gegevens op in het door Docker beheerde `pgdata2` volume. Dit is bewust gedaan: de databasebestanden hoeven niet direct vanaf de host te worden bewerkt, en een beheerd volume voorkomt veelvoorkomende problemen met eigenaarschap en rechten. Bestanden die voor de gebruiker toegankelijk en bewerkbaar zijn (uploads, logs, afbeeldingen, MongoDB-gegevens en NGINX-configuratie) zijn via bind-mounts gekoppeld aan projectmappen waar directe toegang vanaf de host nuttig is.

## Lokale installatie [#local-setup]

Een niet-container installatie is meer hands-on. Volg de instructies in de [RAG API repo](https://github.com/LibreChat-AI/rag-api/).

Stel `RAG_API_URL` in je LibreChat `.env`-bestand in op de locatie waar de API bereikbaar is vanuit jouw opstelling. Dit verschilt van de meegeleverde Docker-opstelling, waarin de waarde al is ingesteld op de `api`-service in de standaardbestanden `docker-compose.yml` en `deploy-compose.yml`.

## Configuratie [#configuration]

## Gebruik [#usage]

Zodra de RAG API bereikbaar is, hoeft er in LibreChat verder niets meer ingeschakeld te worden. Gebruikers uploaden bestanden met **Uploaden voor bestandszoeken**, en het model doorzoekt de index via de `file_search`-tool wanneer een vraag daarom vraagt. Als `RAG_API_URL` niet is ingesteld of de service niet draait, mislukken deze uploads; LibreChat logt bij het opstarten een waarschuwing wanneer de gezondheidscontrole van de RAG API niet kan worden bereikt. Zie [Chat met bestanden](/docs/features/rag_api) voor de gebruikerskant.

## Probleemoplossing [#troubleshooting]

Als je problemen ondervindt bij het instellen of gebruiken van de RAG API:

- Bevestig dat alle vereiste omgevingsvariabelen correct zijn ingesteld in je `.env` bestand.
- Zorg ervoor dat de vector database geconfigureerd en toegankelijk is.
- Controleer of de OpenAI API-sleutel of andere inloggegevens van de provider geldig zijn.
- Controleer zowel de LibreChat- als de RAG API-logs op fouten of waarschuwingen.

Als het probleem aanhoudt, raadpleeg dan de RAG API-documentatie of vraag het aan de LibreChat-community op GitHub Discussions of Discord.
