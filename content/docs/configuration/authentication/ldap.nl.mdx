Je kunt een Lightweight Directory Access Protocol (LDAP) authenticatieserver gebruiken om gebruikers te authenticeren.

## LDAP/AD Server Configuratie [#ldapad-server-configuration]

**Basisconfiguratie**

- `LDAP_URL` en `LDAP_USER_SEARCH_BASE` zijn vereist.
- `LDAP_SEARCH_FILTER` is optioneel; indien niet opgegeven, wordt standaard het `mail` attribuut gebruikt. Indien opgegeven, gebruik de letterlijke `{{username}}` om de opgegeven gebruikersnaam te gebruiken voor de zoekopdracht.

<OptionTable
  options={[
    ['LDAP_URL', 'string', 'LDAP-server-URL.', 'LDAP_URL=ldap://localhost:389'],
    ['LDAP_BIND_DN', 'string', 'Bind DN', 'LDAP_BIND_DN=cn=root'],
    ['LDAP_BIND_CREDENTIALS', 'string', 'Wachtwoord voor bindDN', 'LDAP_BIND_CREDENTIALS=password'],
    [
      'LDAP_USER_SEARCH_BASE',
      'string',
      'LDAP-gebruikerszoekbasis',
      'LDAP_USER_SEARCH_BASE=o=users,o=example.com',
    ],
    ['LDAP_SEARCH_FILTER', 'string', 'LDAP-zoekfilter', 'LDAP_SEARCH_FILTER=mail={{username}}'],
  ]}
/>

**Veldtoewijzingen**

U kunt een mapping opgeven tussen de kenmerken van LibreChat-gebruikers en die van LDAP-gebruikers. Gebruik deze instellingen als de standaard mappings niet naar behoren werken.

<OptionTable
  options={[

/>

**Gebruikersnaam of e-mailadres**

Standaard gebruikt LibreChat een e-mailadres en wachtwoord voor authenticatie.
Dit kan soms problemen veroorzaken met LDAP en het kan wenselijk zijn om in plaats daarvan een gebruikersnaam te gebruiken.
Stel de `LDAP_SEARCH_FILTER` in om te filteren op de gebruikersnaam (bijv. `LDAP_SEARCH_FILTER=uid={{username}}`)
en configureer LibreChat om inloggen via gebruikersnaam te vereisen:

<OptionTable
  options={[
    [
      'LDAP_LOGIN_USES_USERNAME',
      'boolean',
      'Gebruik gebruikersnaam in plaats van e-mail.',
      'LDAP_LOGIN_USES_USERNAME=true',
    ],
  ]}
/>

**Active Directory via SSL**

Om via SSL (ldaps://) te verbinden, bijvoorbeeld voor een bedrijf dat Windows AD gebruikt, geef je het pad naar het interne CA-certificaat op met `LDAP_CA_CERT_PATH`.

`LDAP_TLS_REJECT_UNAUTHORIZED` wordt alleen toegepast wanneer `LDAP_CA_CERT_PATH` is ingesteld. In dat geval staat de certificaatverificatie **uit**, tenzij je expliciet `LDAP_TLS_REJECT_UNAUTHORIZED=true` instelt. Wanneer `LDAP_CA_CERT_PATH` niet is ingesteld, geeft LibreChat geen TLS-opties door en geldt het standaardgedrag van Node.js (het servercertificaat wordt gecontroleerd tegen de systeemtrustore).

<Callout type="warning" title="Certificaatverificatie inschakelen">
  Als u `LDAP_CA_CERT_PATH` instelt zonder `LDAP_TLS_REJECT_UNAUTHORIZED=true`, vertrouwt LibreChat elk certificaat dat door de LDAP-server wordt aangeboden. Hierdoor worden bindingsreferenties en gebruikerswachtwoorden blootgesteld aan man-in-the-middle-aanvallen. Stel `LDAP_TLS_REJECT_UNAUTHORIZED=true` altijd in productieomgevingen in.
</Callout>

<OptionTable
  options={[
    [
      'LDAP_CA_CERT_PATH',
      'string',
      'Pad naar CA-certificaat.',
      'LDAP_CA_CERT_PATH=/path/to/root_ca_cert.crt',
    ],
    [
      'LDAP_TLS_REJECT_UNAUTHORIZED',
      'boolean',
      'Verifieer het LDAP-servercertificaat aan de hand van LDAP_CA_CERT_PATH. Moet true zijn om verificatie in te schakelen; wordt genegeerd wanneer LDAP_CA_CERT_PATH niet is ingesteld.',
      'LDAP_TLS_REJECT_UNAUTHORIZED=true',
    ],
  ]}
/>

**LDAP StartTLS**

Het inschakelen van LDAP StartTLS stelt LibreChat in staat om een onbeveiligde verbinding te upgraden naar een beveiligde TLS-verbinding. Dit is nuttig als u de verbinding wilt beveiligen zonder over te schakelen naar ldaps://.

<OptionTable
    options={[
        [
            'LDAP_STARTTLS',
            'boolean',
            'Schakel LDAP StartTLS in om de verbinding te upgraden naar TLS. Zet op true om deze functie in te schakelen.',
            'LDAP_STARTTLS=true',
        ],
    ]}
/>
