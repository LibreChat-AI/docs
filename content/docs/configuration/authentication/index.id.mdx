> **Catatan:** OpenID dan SAML tidak mendukung kemampuan untuk menonaktifkan pendaftaran saja.

Mengatur `ALLOW_EMAIL_LOGIN=false` akan menyembunyikan formulir masuk email dan menolak permintaan kredensial lokal atau LDAP ke `/api/auth/login`; masuk melalui OAuth, OpenID Connect, dan SAML tidak akan terpengaruh. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` ditujukan hanya untuk integrasi API terkontrol yang masih memerlukan masuk dengan kredensial saat formulir disembunyikan. Setiap penggunaan override akan mencatat IP permintaan, jadi lindungi dan pantau rute tersebut dengan cermat.

Tips Cepat:

- Bahkan dengan pendaftaran dinonaktifkan, Anda dapat menambahkan pengguna secara langsung ke basis data menggunakan [skrip create-user](#create-user-script) yang dirinci di bawah ini.
- Untuk menghapus pengguna, Anda dapat menggunakan [skrip delete-user](#delete-user-script) yang juga dijelaskan secara rinci di bawah ini.

Opsi masuk terkait untuk akun lokal:

- [Passkeys](/docs/configuration/authentication/passkeys): masuk tanpa kata sandi dengan kunci layar perangkat atau kunci keamanan (`ALLOW_PASSKEY_LOGIN`).

## Autentikasi Dua Faktor yang Diperlukan [#required-two-factor-authentication]

Pengguna selalu dapat mengaktifkan autentikasi dua faktor (TOTP) sendiri melalui **Settings > Account**. Untuk menjadikannya wajib, atur:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**Siapa yang terdampak:** akun lokal (email dan kata sandi) dan LDAP. Akun yang masuk melalui OAuth, OpenID Connect, atau SAML tidak terpengaruh, karena penyedia identitas mereka bertanggung jawab atas MFA. Akun federasi yang mencoba masuk dengan kata sandi saat penegakan aktif akan diminta untuk menggunakan penyedia identitas mereka sebagai gantinya.

**Apa yang dilihat pengguna:** pengguna tanpa 2FA yang masuk (dengan kata sandi, kredensial LDAP, atau passkey) tidak akan mendapatkan sesi sampai penyiapan selesai. Mereka akan diarahkan ke layar **Autentikasi Dua Faktor Diperlukan** ("Administrator Anda mewajibkan autentikasi dua faktor. Siapkan sebelum melanjutkan."), memindai kode QR dengan aplikasi autentikator, memasukkan kode untuk verifikasi, dan menyimpan kode cadangan mereka. Pengguna yang sudah masuk akan diarahkan ke penyiapan yang sama saat sesi mereka diperiksa atau disegarkan berikutnya, dan token akses yang diterbitkan sebelum pendaftaran akan berhenti berfungsi. Sesi penyiapan berlangsung selama 10 menit; jika kedaluwarsa, pengguna akan kembali ke halaman masuk dan memulai dari awal.

**Setelah pendaftaran:** kontrol **Disable 2FA** di **Settings > Account** akan menampilkan **Required by administrator**, dan server akan menolak upaya untuk menonaktifkan 2FA selama kebijakan tersebut aktif. Pengguna masih dapat membuat ulang kode cadangan.

- Nilai default: kedaluwarsa sesi: 15 menit, kedaluwarsa token refresh: 7 hari

``` mermaid
    Note over Server: If valid user...
    Server->>Server: Generate access and refresh tokens
    Server->>Database: Store hashed refresh token
    Server-->>Client: Access token and refresh token
    Client->>Client: Store access token in HTTP Header and refresh token in HttpOnly cookie
    Client->>Server: Request with access token from HTTP Header
    Server-->>Client: Requested data
    Note over Client,Server: Access token expires
    Client->>Server: Request with expired access token
    Server-->>Client: Unauthorized
    Client->>Server: Request with refresh token from HttpOnly cookie
    Server->>Database: Retrieve hashed refresh token
    Server->>Server: Compare hash of provided refresh token with stored hash
    Note over Server: If hashes match...
    Server-->>Client: New access token and refresh token
    Client->>Server: Retry request with new access token
    Server-->>Client: Requested data
```

## JWT Secret dan Refresh Secret [#jwt-secret-and-refresh-secret]

Gunakan nilai unik minimal 32 byte. Hasilkan nilai permanen dengan [Credentials Generator](/toolkit/creds_generator), simpan dengan aman, dan berikan nilai yang sama ke setiap replika LibreChat.

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'Kunci rahasia JWT.','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'Kunci rahasia refresh JWT.','JWT_REFRESH_SECRET='],
  ]}
/>

Ketika salah satu nilai kosong, LibreChat dapat membuat dan menggunakan kembali nilai dari file kredensial sementaranya. Stack Docker Compose default mempertahankan file tersebut, namun ini hanya ditujukan sebagai kenyamanan bootstrap. Jika file tersebut hilang atau tidak dapat ditulis, sesi dapat menjadi tidak valid setelah dimulai ulang. Lihat [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) untuk prioritas, persistensi, dan panduan produksi.

## Sistem Moderasi Otomatis (opsional) [#automated-moderation-system-optional]

Sistem Moderasi Otomatis diaktifkan secara default. Sistem ini menggunakan mekanisme penilaian untuk melacak pelanggaran pengguna. Saat pengguna melakukan tindakan seperti login, pendaftaran, atau pengiriman pesan yang berlebihan, mereka akan mengumpulkan skor pelanggaran. Setelah mencapai ambang batas yang ditetapkan, pengguna dan IP mereka akan diblokir sementara. Sistem ini memastikan keamanan platform dengan memantau dan memberikan penalti terhadap aktivitas yang cepat atau mencurigakan.

Untuk menyiapkan sistem mod, tinjau [panduan penyiapan](/docs/configuration/mod_system).

> *Harap Dicatat: Jika Anda ingin ini berfungsi dalam mode pengembangan, Anda perlu membuat file bernama `.env.development` di direktori root dan mengatur `DOMAIN_CLIENT` ke `http://localhost:3090` atau port apa pun yang disediakan oleh vite saat menjalankan `npm run frontend-dev`*

## Skrip Manajemen Pengguna [#user-management-scripts]

### Membuat User Script [#create-user-script]

Skrip create-user memungkinkan Anda untuk menambahkan pengguna langsung ke basis data, bahkan saat pendaftaran dinonaktifkan. Berikut cara menggunakannya:

1. Untuk `docker-compose.yml` default (jika Anda menggunakan `docker compose up` untuk menjalankan aplikasi):
   ```bash
   docker compose exec api npm run create-user
   ```

2. Untuk `deploy-compose.yml` (jika Anda mengikuti [Panduan Docker Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Untuk pengembangan lokal (dari root proyek):
   ```bash
   npm run create-user
   ```

Ikuti perintah untuk memasukkan email dan kata sandi pengguna baru.

### Skrip Hapus Pengguna [#delete-user-script]

Untuk menghapus pengguna, Anda dapat menggunakan skrip delete-user:

1. Untuk `docker-compose.yml` default (jika Anda menggunakan `docker compose up` untuk menjalankan aplikasi):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Untuk `deploy-compose.yml` (jika Anda mengikuti [Panduan Docker Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Untuk pengembangan lokal (dari root proyek):
   ```bash
   npm run delete-user email@domain.com
   ```

Ganti `email@domain.com` dengan email pengguna yang ingin Anda hapus.
