`ALLOW_EMAIL_LOGIN=false` ayarını yapmak, e-posta giriş formunu gizler ve `/api/auth/login` adresine yapılan yerel veya LDAP kimlik bilgisi isteklerini reddeder; OAuth, OpenID Connect ve SAML ile giriş işlemleri bundan etkilenmez. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` ayarı, yalnızca form gizliyken kimlik bilgisi ile girişe ihtiyaç duyan kontrollü bir API entegrasyonu için tasarlanmıştır. Her geçersiz kılma (override) kullanımı istek IP'sini günlüğe kaydeder, bu nedenle bu rotayı dikkatlice koruyun ve izleyin.

Hızlı İpuçları:

- Kayıt özelliği devre dışı bırakılmış olsa bile, aşağıda detaylandırılan [create-user script](#create-user-script) kullanarak kullanıcıları doğrudan veritabanına ekleyebilirsiniz.
- Bir kullanıcıyı silmek için aşağıda da detaylandırılan [delete-user script](#delete-user-script) aracını kullanabilirsiniz.

Yerel hesaplar için ilgili oturum açma seçenekleri:

- [Passkeys](/docs/configuration/authentication/passkeys): cihaz ekran kilidi veya güvenlik anahtarı ile parolasız oturum açma (`ALLOW_PASSKEY_LOGIN`).
- [E-posta adresi değişikliği](/docs/configuration/authentication/email#email-address-change): kullanıcıların kayıtlı e-posta adreslerini **Ayarlar > Hesap** (`ALLOW_EMAIL_CHANGE`, varsayılan olarak açık) üzerinden değiştirmelerine olanak tanır.

## Zorunlu İki Faktörlü Kimlik Doğrulama [#required-two-factor-authentication]

Kullanıcılar iki faktörlü kimlik doğrulamayı (TOTP) her zaman **Ayarlar > Hesap** kısmından kendileri açabilirler. Bunu zorunlu kılmak için şunu ayarlayın:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**Kimler için geçerlidir:** yerel (e-posta ve parola) ve LDAP hesapları. OAuth, OpenID Connect veya SAML aracılığıyla giriş yapan hesaplar, kimlik sağlayıcıları MFA'dan sorumlu olduğu için bu durumdan etkilenmez. Zorunlu tutma özelliği açıkken parola ile giriş yapmaya çalışan bir federasyon hesabı, bunun yerine kimlik sağlayıcısını kullanması konusunda uyarılır.

**Kullanıcıların gördükleri:** 2FA'sı olmayan ve giriş yapan (parola, LDAP kimlik bilgileri veya bir geçiş anahtarı ile) bir kullanıcı, kurulum tamamlanana kadar oturum açamaz. Kullanıcı, **İki Faktörlü Kimlik Doğrulama Gerekli** ekranına yönlendirilir ("Yöneticiniz iki faktörlü kimlik doğrulama gerektiriyor. Devam etmeden önce kurulumu yapın."), bir kimlik doğrulayıcı uygulamasıyla QR kodunu tarar, doğrulamak için bir kod girer ve yedek kodlarını kaydeder. Hali hazırda oturum açmış olan kullanıcılar, oturumları bir sonraki kontrol edilişinde veya yenilendiğinde aynı kuruluma yönlendirilir ve kayıt öncesinde verilen erişim belirteçleri (access tokens) çalışmayı durdurur. Kurulum oturumu 10 dakika sürer; süresi dolarsa kullanıcı giriş sayfasına döner ve işleme yeniden başlar.

**Kayıttan sonra:** **Ayarlar > Hesap** bölümündeki **2FA'yı Devre Dışı Bırak** kontrolü **Yönetici tarafından zorunlu tutulmuştur** şeklinde görünür ve sunucu, politika etkinken 2FA'yı devre dışı bırakma girişimlerini reddeder. Kullanıcılar yedek kodlarını yeniden oluşturmaya devam edebilirler.

## Oturum Zaman Aşımı ve Yenileme Belirteci [#session-expiry-and-refresh-token]

- Varsayılan değerler: oturum süresi: 15 dakika, yenileme belirteci süresi: 7 gün

``` mermaid
sequenceDiagram
    Client->>Server: Login request with credentials
    Server->>Passport: Use authentication strategy (e.g., 'local', 'google', etc.)
    Passport-->>Server: User object or false/error
    Note over Server: If valid user...
    Server->>Server: Generate access and refresh tokens
    Server->>Database: Store hashed refresh token
    Server-->>Client: Access token and refresh token
    Client->>Client: Store access token in HTTP Header and refresh token in HttpOnly cookie
    Client->>Server: Request with access token from HTTP Header
    Server-->>Client: Requested data
    Note over Client,Server: Access token expires
    Client->>Server: Request with expired access token
    Server-->>Client: Unauthorized
    Client->>Server: Request with refresh token from HttpOnly cookie
    Server->>Database: Retrieve hashed refresh token
    Server->>Server: Compare hash of provided refresh token with stored hash
    Note over Server: If hashes match...
    Server-->>Client: New access token and refresh token
    Client->>Server: Retry request with new access token
    Server-->>Client: Requested data
```

## JWT Secret ve Refresh Secret [#jwt-secret-and-refresh-secret]

En az 32 baytlık benzersiz değerler kullanın. [Credentials Generator](/toolkit/creds_generator) ile kalıcı değerler oluşturun, bunları güvenli bir şekilde saklayın ve her bir LibreChat kopyasına aynı değerleri sağlayın.

<OptionTable
  options={[

  ]}

Her iki değer de boş olduğunda, LibreChat geçici kimlik bilgileri dosyasından bir değer oluşturabilir ve yeniden kullanabilir. Varsayılan Docker Compose yığınları bu dosyayı kalıcı hale getirir, ancak bu yalnızca bir önyükleme kolaylığı olarak amaçlanmıştır. Dosya kaybolursa veya yazılamazsa, yeniden başlatmanın ardından oturumlar geçersiz hale gelebilir. Öncelik, kalıcılık ve üretim ortamı rehberliği için [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) bölümüne bakın.

## Otomatik Denetleme Sistemi (isteğe bağlı) [#automated-moderation-system-optional]

Otomatik Denetleme Sistemi varsayılan olarak etkindir. Kullanıcı ihlallerini takip etmek için bir puanlama mekanizması kullanır. Kullanıcılar aşırı giriş, kayıt veya mesajlaşma gibi eylemlerde bulundukça ihlal puanları biriktirirler. Belirlenen bir eşiğe ulaşıldığında, kullanıcı ve IP adresi geçici olarak yasaklanır. Bu sistem, hızlı veya şüpheli etkinlikleri izleyip cezalandırarak platform güvenliğini sağlar.

Mod sistemini kurmak için [kurulum kılavuzunu](/docs/configuration/mod_system) inceleyin.

> *Lütfen Dikkat: Bunun geliştirme modunda çalışmasını istiyorsanız, kök dizinde `.env.development` adında bir dosya oluşturmanız ve `DOMAIN_CLIENT` değerini `http://localhost:3090` olarak veya `npm run frontend-dev` çalıştırıldığında vite tarafından sağlanan port neyse ona ayarlamanız gerekecektir.*

## Kullanıcı Yönetim Betikleri [#user-management-scripts]

### Kullanıcı Betiği Oluştur [#create-user-script]

create-user betiği, kayıt özelliği devre dışı bırakılmış olsa bile kullanıcıları doğrudan veritabanına eklemenize olanak tanır. Nasıl kullanılacağı aşağıdadır:

1. Varsayılan `docker-compose.yml` için (uygulamayı başlatmak üzere `docker compose up` kullanıyorsanız):
   ```bash
   docker compose exec api npm run create-user
   ```

2. `deploy-compose.yml` için ([Ubuntu Docker Rehberi](/docs/remote/docker_linux) kısmını takip ettiyseniz):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Yerel geliştirme için (proje kök dizininden):
   ```bash
   npm run create-user
   ```

Yeni kullanıcının e-postasını ve şifresini girmek için komutları izleyin.

### Kullanıcı Silme Betiği [#delete-user-script]

Bir kullanıcıyı silmek için delete-user betiğini kullanabilirsiniz:

1. Varsayılan `docker-compose.yml` için (uygulamayı başlatmak üzere `docker compose up` kullanıyorsanız):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. `deploy-compose.yml` için ([Ubuntu Docker Rehberi](/docs/remote/docker_linux) kısmını takip ettiyseniz):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Yerel geliştirme için (proje kök dizininden):
   ```bash
   npm run delete-user email@domain.com
   ```

`email@domain.com` ifadesini silmek istediğiniz kullanıcının e-posta adresiyle değiştirin.
