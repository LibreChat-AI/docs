> **Nota:** OpenID y SAML no admiten la capacidad de deshabilitar solo el registro.

Configurar `ALLOW_EMAIL_LOGIN=false` oculta el formulario de inicio de sesión por correo electrónico y rechaza las solicitudes de credenciales locales o LDAP a `/api/auth/login`; el inicio de sesión mediante OAuth, OpenID Connect y SAML no se ve afectado. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` está destinado únicamente a una integración de API controlada que aún necesita el inicio de sesión con credenciales mientras el formulario está oculto. Cada uso de la anulación registra la IP de la solicitud, así que proteja y supervise esa ruta cuidadosamente.

Consejos rápidos:

- Incluso con el registro deshabilitado, puede agregar usuarios directamente a la base de datos utilizando [el script create-user](#create-user-script) detallado a continuación.
- Para eliminar un usuario, puede utilizar [el script delete-user](#delete-user-script) que también se detalla a continuación.

## Expiración de sesión y token de actualización [#session-expiry-and-refresh-token]

- Valores predeterminados: expiración de la sesión: 15 minutos, expiración del token de actualización: 7 días
  - Para más información: **[GitHub PR #927 - Refresh Token](https://github.com/LibreChat-AI/LibreChat/pull/927)**

## JWT Secret y Refresh Secret [#jwt-secret-and-refresh-secret]

Utilice valores únicos de al menos 32 bytes. Genere valores permanentes con el [Credentials Generator](/toolkit/creds_generator), almacénelos de forma segura y proporcione los mismos valores a cada réplica de LibreChat.

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'Clave secreta JWT.','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'Clave secreta de actualización JWT.','JWT_REFRESH_SECRET='],
  ]}
/>

Cuando cualquiera de los valores está en blanco, LibreChat puede generar y reutilizar un valor desde su archivo de credenciales temporales. Las pilas de Docker Compose predeterminadas persisten ese archivo, pero esto está destinado únicamente como una conveniencia de arranque. Si el archivo se pierde o no se puede escribir, las sesiones pueden invalidarse después de reiniciar. Consulta [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) para obtener información sobre precedencia, persistencia y orientación para producción.

## Sistema de moderación automatizado (opcional) [#automated-moderation-system-optional]

El Sistema de Moderación Automatizado está habilitado de forma predeterminada. Utiliza un mecanismo de puntuación para realizar un seguimiento de las infracciones de los usuarios. A medida que los usuarios realizan acciones como inicios de sesión, registros o envío de mensajes excesivos, acumulan puntuaciones de infracción. Al alcanzar un umbral establecido, el usuario y su IP son bloqueados temporalmente. Este sistema garantiza la seguridad de la plataforma mediante la supervisión y penalización de actividades rápidas o sospechosas.

Para configurar el sistema de moderación, revisa [la guía de configuración](/docs/configuration/mod_system).

> *Nota: Si deseas que esto funcione en modo de desarrollo, deberás crear un archivo llamado `.env.development` en el directorio raíz y establecer `DOMAIN_CLIENT` en `http://localhost:3090` o en cualquier puerto que proporcione vite al ejecutar `npm run frontend-dev`*

## Scripts de gestión de usuarios [#user-management-scripts]

### Crear script de usuario [#create-user-script]

El script create-user le permite añadir usuarios directamente a la base de datos, incluso cuando el registro está deshabilitado. Aquí le explicamos cómo usarlo:

1. Para el `docker-compose.yml` predeterminado (si utiliza `docker compose up` para iniciar la aplicación):
   ```bash
   docker compose exec api npm run create-user
   ```

2. Para el `deploy-compose.yml` (si seguiste la [Guía de Docker en Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Para el desarrollo local (desde la raíz del proyecto):
   ```bash
   npm run create-user
   ```

Sigue las instrucciones para ingresar el correo electrónico y la contraseña del nuevo usuario.

### Script para eliminar usuario [#delete-user-script]

Para eliminar un usuario, puedes usar el script delete-user:

1. Para el `docker-compose.yml` predeterminado (si utiliza `docker compose up` para iniciar la aplicación):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Para el `deploy-compose.yml` (si seguiste la [Guía de Docker en Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Para el desarrollo local (desde la raíz del proyecto):
   ```bash
   npm run delete-user email@domain.com
   ```

Reemplace `email@domain.com` con el correo electrónico del usuario que desea eliminar.
