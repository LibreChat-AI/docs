> **Nota:** OpenID e SAML não oferecem suporte à capacidade de desabilitar apenas o registro.

Definir `ALLOW_EMAIL_LOGIN=false` oculta o formulário de login por e-mail e rejeita solicitações de credenciais locais ou LDAP para `/api/auth/login`; o login via OAuth, OpenID Connect e SAML não é afetado. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` destina-se apenas a uma integração de API controlada que ainda precisa de login por credenciais enquanto o formulário está oculto. Cada uso do override registra o IP da solicitação, portanto, proteja e monitore essa rota cuidadosamente.

Dicas Rápidas:

- Mesmo com o registro desativado, você pode adicionar usuários diretamente ao banco de dados usando [o script create-user](#create-user-script) detalhado abaixo.
- Para excluir um usuário, você pode usar [o script delete-user](#delete-user-script), também detalhado abaixo.

Opções de login relacionadas para contas locais:

- [Passkeys](/docs/configuration/authentication/passkeys): login sem senha com bloqueio de tela do dispositivo ou chave de segurança (`ALLOW_PASSKEY_LOGIN`).
- [Alteração de endereço de e-mail](/docs/configuration/authentication/email#email-address-change): permite que os usuários alterem seu e-mail registrado em **Configurações > Conta** (`ALLOW_EMAIL_CHANGE`, ativado por padrão).

## Autenticação de Dois Fatores Obrigatória [#required-two-factor-authentication]

Os usuários sempre podem ativar a autenticação de dois fatores (TOTP) por conta própria em **Configurações > Conta**. Para torná-la obrigatória, defina:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**A quem se aplica:** contas locais (e-mail e senha) e LDAP. Contas que fazem login via OAuth, OpenID Connect ou SAML não são afetadas, pois seu provedor de identidade é responsável pelo MFA. Uma conta federada que tenta fazer login com senha enquanto a imposição está ativada é instruída a usar seu provedor de identidade.

**O que os usuários veem:** um usuário sem 2FA que faz login (com senha, credenciais LDAP ou uma passkey) não obtém uma sessão até que a configuração seja concluída. Eles são direcionados para uma tela de **Autenticação de Dois Fatores Necessária** ("Seu administrador exige autenticação de dois fatores. Configure-a antes de continuar."), escaneiam um código QR com um aplicativo autenticador, inserem um código para verificar e salvam seus códigos de backup. Usuários que já estão logados são movidos para a mesma configuração na próxima vez que sua sessão for verificada ou atualizada, e os tokens de acesso emitidos antes da inscrição param de funcionar. A sessão de configuração dura 10 minutos; se expirar, o usuário retorna à página de login e começa novamente.

**Após a inscrição:** o controle **Desativar 2FA** em **Configurações > Conta** exibe **Obrigatório pelo administrador**, e o servidor rejeita tentativas de desativar o 2FA enquanto a política estiver ativa. Os usuários ainda podem regenerar códigos de backup.

<Callout type="info" title="Apenas ambiente">
`ENFORCE_TWO_FACTOR_AUTHENTICATION` e os limites `TWO_FACTOR_TEMP_*` e `TWO_FACTOR_SETUP_*` são configurações de `.env` de nível de processo. Eles são aplicados antes que uma solicitação ou configuração de tenant esteja disponível, portanto, não podem ser definidos em `librechat.yaml` ou por tenant. Defina os mesmos valores em cada réplica. O orçamento separado para gerenciar a 2FA a partir das configurações é [`rateLimits.twoFactorManagement`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).
</Callout>

## JWT Secret e Refresh Secret [#jwt-secret-and-refresh-secret]

Use valores únicos de pelo menos 32 bytes. Gere valores permanentes com o [Credentials Generator](/toolkit/creds_generator), armazene-os com segurança e forneça os mesmos valores para cada réplica do LibreChat.

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'Chave secreta JWT.','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'Chave secreta de atualização JWT.','JWT_REFRESH_SECRET='],
  ]}
/>

Quando qualquer um dos valores estiver em branco, o LibreChat pode gerar e reutilizar um valor a partir de seu arquivo de credenciais temporárias. As stacks padrão do Docker Compose persistem esse arquivo, mas isso destina-se apenas como uma conveniência de inicialização. Se o arquivo for perdido ou não puder ser gravado, as sessões podem se tornar inválidas após a reinicialização. Consulte [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) para precedência, persistência e orientações de produção.

## Sistema de Moderação Automatizado (opcional) [#automated-moderation-system-optional]

O Automated Moderation System está habilitado por padrão. Ele utiliza um mecanismo de pontuação para rastrear violações dos usuários. À medida que os usuários realizam ações como excesso de logins, registros ou envio de mensagens, eles acumulam pontuações de violação. Ao atingir um limite definido, o usuário e seu IP são banidos temporariamente. Este sistema garante a segurança da plataforma ao monitorar e penalizar atividades rápidas ou suspeitas.

Para configurar o sistema de moderação, revise [o guia de configuração](/docs/configuration/mod_system).

> *Observação: Se você deseja que isso funcione no modo de desenvolvimento, será necessário criar um arquivo chamado `.env.development` no diretório raiz e definir `DOMAIN_CLIENT` como `http://localhost:3090` ou qualquer porta fornecida pelo vite ao executar `npm run frontend-dev`*

## Scripts de Gerenciamento de Usuários [#user-management-scripts]

### Criar Script de Usuário [#create-user-script]

O script create-user permite que você adicione usuários diretamente ao banco de dados, mesmo quando o registro estiver desativado. Veja como usá-lo:

1. Para o `docker-compose.yml` padrão (se você usar `docker compose up` para iniciar o aplicativo):
   ```bash
   docker compose exec api npm run create-user
   ```

2. Para o `deploy-compose.yml` (se você seguiu o [Guia do Docker no Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Para desenvolvimento local (a partir da raiz do projeto):
   ```bash
   npm run create-user
   ```

Siga as instruções para inserir o e-mail e a senha do novo usuário.

### Script para Excluir Usuário [#delete-user-script]

Para excluir um usuário, você pode usar o script delete-user:

1. Para o `docker-compose.yml` padrão (se você usar `docker compose up` para iniciar o aplicativo):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Para o `deploy-compose.yml` (se você seguiu o [Guia do Docker no Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Para desenvolvimento local (a partir da raiz do projeto):
   ```bash
   npm run delete-user email@domain.com
   ```

Substitua `email@domain.com` pelo e-mail do usuário que você deseja excluir.
