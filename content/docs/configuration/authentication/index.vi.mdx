## Tổng quan [#general]

Để có cái nhìn tổng quan nhanh, hãy tham khảo hướng dẫn sử dụng được cung cấp tại đây: [Authentication](/docs/features/authentication)

Việc thiết lập `ALLOW_EMAIL_LOGIN=false` sẽ ẩn biểu mẫu đăng nhập bằng email và từ chối các yêu cầu xác thực cục bộ hoặc LDAP tới `/api/auth/login`; các phương thức đăng nhập OAuth, OpenID Connect và SAML sẽ không bị ảnh hưởng. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` chỉ dành cho việc tích hợp API có kiểm soát, nơi vẫn cần đăng nhập bằng thông tin xác thực trong khi biểu mẫu đã bị ẩn. Mọi lần sử dụng ghi đè đều sẽ ghi lại IP của yêu cầu, vì vậy hãy bảo vệ và giám sát lộ trình đó một cách cẩn thận.

Mẹo nhanh:

- Ngay cả khi tính năng đăng ký đã bị vô hiệu hóa, bạn vẫn có thể thêm người dùng trực tiếp vào cơ sở dữ liệu bằng cách sử dụng [tập lệnh create-user](#create-user-script) được trình bày chi tiết dưới đây.
- Để xóa người dùng, bạn có thể sử dụng [tập lệnh delete-user](#delete-user-script) cũng được trình bày chi tiết bên dưới.

Các tùy chọn đăng nhập liên quan cho tài khoản cục bộ:

- [Passkeys](/docs/configuration/authentication/passkeys): đăng nhập không cần mật khẩu bằng khóa màn hình thiết bị hoặc khóa bảo mật (`ALLOW_PASSKEY_LOGIN`).
- [Thay đổi địa chỉ email](/docs/configuration/authentication/email#email-address-change): cho phép người dùng thay đổi email đã đăng ký từ **Settings > Account** (`ALLOW_EMAIL_CHANGE`, được bật theo mặc định).

## Yêu cầu xác thực hai yếu tố [#required-two-factor-authentication]

Người dùng luôn có thể tự bật xác thực hai yếu tố (TOTP) từ **Settings > Account**. Để bắt buộc thực hiện việc này, hãy thiết lập:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**Đối tượng áp dụng:** các tài khoản cục bộ (email và mật khẩu) và LDAP. Các tài khoản đăng nhập thông qua OAuth, OpenID Connect hoặc SAML sẽ không bị ảnh hưởng, vì nhà cung cấp danh tính của họ chịu trách nhiệm về MFA. Một tài khoản liên kết cố gắng đăng nhập bằng mật khẩu trong khi tính năng thực thi đang bật sẽ được thông báo sử dụng nhà cung cấp danh tính của họ thay thế.

**Những gì người dùng thấy:** một người dùng chưa bật 2FA khi đăng nhập (bằng mật khẩu, thông tin xác thực LDAP hoặc passkey) sẽ không có phiên làm việc cho đến khi quá trình thiết lập hoàn tất. Họ sẽ được chuyển đến màn hình **Yêu cầu xác thực hai yếu tố** ("Quản trị viên của bạn yêu cầu xác thực hai yếu tố. Hãy thiết lập trước khi tiếp tục."), quét mã QR bằng ứng dụng xác thực, nhập mã để xác minh và lưu mã dự phòng của họ. Những người dùng đã đăng nhập sẽ được chuyển vào quy trình thiết lập tương tự vào lần tiếp theo phiên làm việc của họ được kiểm tra hoặc làm mới, và các mã truy cập (access tokens) được cấp trước khi đăng ký sẽ ngừng hoạt động. Phiên thiết lập kéo dài 10 phút; nếu hết hạn, người dùng sẽ quay lại trang đăng nhập và bắt đầu lại từ đầu.

**Sau khi đăng ký:** điều khiển **Disable 2FA** trong **Settings > Account** sẽ hiển thị **Required by administrator**, và máy chủ sẽ từ chối các nỗ lực tắt 2FA khi chính sách này đang được bật. Người dùng vẫn có thể tạo lại mã dự phòng.

``` mermaid
    Passport-->>Server: User object or false/error

    Server->>Server: Generate access and refresh tokens

    Server-->>Client: Access token and refresh token
    Client->>Client: Store access token in HTTP Header and refresh token in HttpOnly cookie
    Client->>Server: Request with access token from HTTP Header
    Server-->>Client: Requested data
    Note over Client,Server: Access token expires
    Client->>Server: Request with expired access token
    Server-->>Client: Unauthorized
    Client->>Server: Request with refresh token from HttpOnly cookie
    Server->>Database: Retrieve hashed refresh token
    Server->>Server: Compare hash of provided refresh token with stored hash
    Note over Server: If hashes match...
    Server-->>Client: New access token and refresh token
    Client->>Server: Retry request with new access token
    Server-->>Client: Requested data
```

## JWT Secret và Refresh Secret [#jwt-secret-and-refresh-secret]

Sử dụng các giá trị duy nhất có độ dài ít nhất 32 byte. Tạo các giá trị vĩnh viễn bằng [Credentials Generator](/toolkit/creds_generator), lưu trữ chúng một cách an toàn và cung cấp cùng các giá trị đó cho mọi bản sao LibreChat.

Khi một trong hai giá trị bị để trống, LibreChat có thể tạo và tái sử dụng giá trị từ tệp thông tin xác thực tạm thời của nó. Các ngăn xếp Docker Compose mặc định sẽ lưu giữ tệp đó, nhưng điều này chỉ nhằm mục đích thuận tiện cho việc khởi động (bootstrap). Nếu tệp bị mất hoặc không thể ghi, các phiên làm việc có thể trở nên không hợp lệ sau khi khởi động lại. Xem [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) để biết về thứ tự ưu tiên, tính bền vững và hướng dẫn cho môi trường production.

## Hệ thống kiểm duyệt tự động (tùy chọn) [#automated-moderation-system-optional]

Hệ thống Kiểm duyệt Tự động được bật theo mặc định. Nó sử dụng cơ chế chấm điểm để theo dõi các vi phạm của người dùng. Khi người dùng thực hiện các hành động như đăng nhập, đăng ký hoặc gửi tin nhắn quá mức, họ sẽ tích lũy điểm vi phạm. Khi đạt đến ngưỡng đã thiết lập, người dùng và địa chỉ IP của họ sẽ bị cấm tạm thời. Hệ thống này đảm bảo tính bảo mật của nền tảng bằng cách giám sát và xử phạt các hoạt động nhanh hoặc đáng ngờ.

Để thiết lập hệ thống mod, hãy xem qua [hướng dẫn thiết lập](/docs/configuration/mod_system).

> *Lưu ý: Nếu bạn muốn tính năng này hoạt động ở chế độ phát triển (development mode), bạn sẽ cần tạo một tệp có tên là `.env.development` trong thư mục gốc và đặt `DOMAIN_CLIENT` thành `http://localhost:3090` hoặc bất kỳ cổng nào được vite cung cấp khi chạy `npm run frontend-dev`*

## Các tập lệnh quản lý người dùng [#user-management-scripts]

### Tạo User Script [#create-user-script]

Script create-user cho phép bạn thêm người dùng trực tiếp vào cơ sở dữ liệu, ngay cả khi tính năng đăng ký đã bị vô hiệu hóa. Dưới đây là cách sử dụng:

1. Đối với `docker-compose.yml` mặc định (nếu bạn sử dụng `docker compose up` để khởi chạy ứng dụng):
   ```bash
   docker compose exec api npm run create-user
   ```

2. Đối với `deploy-compose.yml` (nếu bạn đã làm theo [Hướng dẫn Docker trên Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Đối với phát triển cục bộ (từ thư mục gốc của dự án):
   ```bash
   npm run create-user
   ```

Làm theo các gợi ý để nhập email và mật khẩu của người dùng mới.

### Tập lệnh xóa người dùng [#delete-user-script]

Để xóa một người dùng, bạn có thể sử dụng tập lệnh delete-user:

1. Đối với `docker-compose.yml` mặc định (nếu bạn sử dụng `docker compose up` để khởi chạy ứng dụng):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Đối với `deploy-compose.yml` (nếu bạn đã làm theo [Hướng dẫn Docker trên Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Đối với phát triển cục bộ (từ thư mục gốc của dự án):
   ```bash
   npm run delete-user email@domain.com
   ```

Thay thế `email@domain.com` bằng email của người dùng mà bạn muốn xóa.
