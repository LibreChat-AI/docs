## 일반 설정 [#general-setup]

LibreChat은(는) 여러 이메일 제공업체를 지원합니다:
- **Mailgun API** - SMTP 포트를 차단하는 서버에 권장됨
- **SMTP 서비스** - Gmail, Outlook 또는 사용자 지정 메일 서버를 통한 기존 이메일 전송 방식

## Mailgun을 사용한 설정 [#setup-with-mailgun]

Mailgun을 설정하려면 다음 단계를 따르세요:

1. [mailgun.com](https://www.mailgun.com/)에서 Mailgun 계정에 가입하세요.
2. Mailgun 대시보드에서 도메인을 추가하고 인증하세요
3. API Keys 섹션으로 이동하여 Private API key를 복사하세요.
4. `.env` 파일에서 변수를 다음과 같이 수정하세요:

<OptionTable
  options={[    
    ['MAILGUN_API_KEY', 'string', 'Mailgun 개인 API 키', 'MAILGUN_API_KEY=your-mailgun-api-key'],
    ['MAILGUN_DOMAIN', 'string', '인증된 Mailgun 도메인', 'MAILGUN_DOMAIN=mg.yourdomain.com'],
    ['EMAIL_FROM', 'string', '발신자 이메일 주소', 'EMAIL_FROM=noreply@yourdomain.com'],
    ['EMAIL_FROM_NAME', 'string', '발신자 이름', 'EMAIL_FROM_NAME=LibreChat'],
    ['MAILGUN_HOST', 'string', '(선택 사항) EU 지역의 경우', 'MAILGUN_HOST=https://api.eu.mailgun.net'],
  ]}
/>

<Callout type="info" title="참고">
Mailgun 계정이 EU 지역에 있는 경우, `MAILGUN_HOST=https://api.eu.mailgun.net`으로 설정해야 합니다.
</Callout>

## Gmail을 사용한 설정 [#setup-with-gmail]

Gmail을 설정하려면 다음 단계를 따르세요:

1. Google 계정을 만들고 2단계 인증을 활성화하세요.
2. **[Google 계정 설정](https://myaccount.google.com/)**에서 "보안" 탭을 클릭하고 "2단계 인증"을 엽니다.
3. 아래로 스크롤하여 "App passwords"를 엽니다. 앱으로 "Mail"을 선택하고 기기로 "Other"를 선택한 다음, 임의의 이름을 지정하세요.
4. "Generate"를 클릭하여 비밀번호를 생성하고, 생성된 비밀번호를 복사하세요.
5. `.env` 파일에서 변수를 다음과 같이 수정하세요:

<OptionTable

## 전체 구성 예시 [#complete-configuration-examples]

### 예시 1: Mailgun 구성 [#example-1-mailgun-configuration]

```bash
# ===================================
# Email Configuration - Mailgun
# ===================================
# Mailgun is recommended for servers that block SMTP ports

# Required Mailgun settings
MAILGUN_API_KEY=your-mailgun-api-key
MAILGUN_DOMAIN=mg.yourdomain.com

# Optional: For EU region
# MAILGUN_HOST=https://api.eu.mailgun.net

# Common email settings
EMAIL_FROM=noreply@yourdomain.com
EMAIL_FROM_NAME=LibreChat

# Enable password reset functionality
ALLOW_PASSWORD_RESET=true
```

### 예시 2: Gmail SMTP 구성 [#example-2-gmail-smtp-configuration]

```bash
# ===================================
# Email Configuration - Gmail SMTP
# ===================================
# Traditional SMTP configuration

# Gmail service configuration
EMAIL_SERVICE=gmail
EMAIL_USERNAME=your-email@gmail.com
EMAIL_PASSWORD=your-app-password

# Common email settings
EMAIL_FROM=your-email@gmail.com
EMAIL_FROM_NAME=LibreChat

# Enable password reset functionality
ALLOW_PASSWORD_RESET=true
```

### 예시 3: 사용자 지정 SMTP 서버 구성 [#example-3-custom-smtp-server-configuration]

```bash
# ===================================
# Email Configuration - Custom SMTP
# ===================================
# For custom mail servers

# SMTP server details
EMAIL_HOST=smtp.example.com
EMAIL_PORT=587
EMAIL_ENCRYPTION=starttls
EMAIL_USERNAME=username@example.com
EMAIL_PASSWORD=your-password

# Optional settings
# EMAIL_ENCRYPTION_HOSTNAME=
# EMAIL_ALLOW_SELFSIGNED=false

# Common email settings
EMAIL_FROM=noreply@example.com
EMAIL_FROM_NAME=LibreChat

# Enable password reset functionality
ALLOW_PASSWORD_RESET=true
```

## 이메일 주소 변경 [#email-address-change]

로컬(이메일 및 비밀번호) 계정을 사용하는 사용자는 **Settings > Account**에서 등록된 이메일 주소를 직접 변경할 수 있습니다. 이 기능은 기본적으로 활성화되어 있으며, 정상적으로 작동하는 이메일 전송(위에서 구성한 Mailgun 또는 SMTP)이 필요합니다. 이메일 전송이 설정되지 않은 경우 해당 옵션은 숨겨집니다.

### 사용자 흐름 [#user-flow]

1. **Settings > Account**에서 **Email address** 옆의 **Change**를 선택합니다.
2. **이메일 주소 변경** 대화 상자에서 **새 이메일 주소**와 **현재 비밀번호**를 입력한 다음, **인증 링크 보내기**를 선택합니다.
3. LibreChat은 먼저 현재 주소로 요청된 주소와 요청 IP가 포함된 보안 알림("Email change requested")을 보냅니다. 이 알림은 비밀번호를 확인하기 전에 발송되므로, 계정 소유자는 거부된 시도를 포함한 모든 시도에 대해 알 수 있습니다. 요청이 아래의 확인 절차를 통과하면, 새로운 주소로 인증 링크가 발송됩니다.
4. 주소는 링크가 열릴 때만 변경됩니다. 그 후 이전 주소와 새 주소 모두 "Your email address was changed" 알림을 받게 되며, 새 주소는 인증된 것으로 표시됩니다.

비밀번호가 틀렸거나, 새 주소가 현재 주소와 같거나, 새 주소가 이미 다른 계정에 속해 있거나, 해당 도메인이 [`registration.allowedDomains`](/docs/configuration/librechat_yaml/object_structure/registration#alloweddomains)에 포함되지 않은 경우 요청이 거부됩니다. OAuth, OpenID Connect, SAML 또는 LDAP을 통해 로그인하는 계정은 이 흐름을 사용할 수 없습니다.

인증 링크는 일회용이며 `tokenTTLSeconds`(기본값 15분) 후에 만료됩니다. 또한 링크를 열기 전에 계정의 비밀번호나 이메일이 변경되면 작동이 중지됩니다. 변경을 완료하면 이전 주소로 발급된 모든 비밀번호 재설정 링크는 무효화됩니다.

### 구성 [#configuration]

<OptionTable
  options={[
    [
      'ALLOW_EMAIL_CHANGE',
      'boolean',
      '로컬 계정 사용자가 이메일 주소를 변경할 수 있도록 허용합니다. 생략 시 활성화됩니다. librechat.yaml의 emailChange.enabled 설정에 의해 재정의됩니다.',
      '# ALLOW_EMAIL_CHANGE=true',
    ],
  ]}
/>

`librechat.yaml`에서 `emailChange` 블록은 `ALLOW_EMAIL_CHANGE`보다 우선하며 링크의 유효 기간도 설정합니다:

```yaml filename="librechat.yaml"
emailChange:
  enabled: true
  tokenTTLSeconds: 900 # 60 to 86400, default 900 (15 minutes)
```

각 필드는 독립적으로 대체됩니다: `enabled`는 `ALLOW_EMAIL_CHANGE`로, 그 다음에는 `true`로 대체됩니다; `tokenTTLSeconds`는 `900`으로 대체됩니다. 변경 요청 및 링크 열기에 대한 속도 제한은 [`rateLimits.emailChange` 및 `rateLimits.emailChangeConfirm`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits) 하위에서 설정하거나, 대응하는 [환경 변수](/docs/configuration/dotenv#email-change-rate-limiting)를 사용하여 설정할 수 있습니다.

<Callout type="warning" title="다중 노드 롤아웃">
모든 노드가 이 기능을 포함하는 버전으로 실행될 때까지 `ALLOW_EMAIL_CHANGE=false` (또는 `emailChange.enabled: false`)로 설정하세요. 이전 버전의 노드는 주소에 귀속되지 않는 비밀번호 재설정 링크를 발행하고 수락하므로, 이전 주소 소유자가 가지고 있는 링크가 변경 후에도 유효하여 이름이 변경된 계정을 재설정할 위험이 있습니다.
</Callout>

## 문제 해결 [#troubleshooting]

### Mailgun 문제 [#mailgun-issues]

1. **인증 실패**: Mailgun API 키가 올바른지, 그리고 발송 권한이 있는지 확인하세요.
2. **도메인을 찾을 수 없음**: Mailgun 계정에서 Mailgun 도메인이 올바르게 구성되었는지 확인하세요.
3. **EU 지역 문제**: Mailgun 계정이 EU 지역에 있는 경우, `MAILGUN_HOST=https://api.eu.mailgun.net`으로 설정해야 합니다.
4. **SMTP로 대체**: `MAILGUN_API_KEY` 또는 `MAILGUN_DOMAIN` 중 하나만 설정된 경우, 시스템은 SMTP 구성으로 대체됩니다.

### SMTP 문제 [#smtp-issues]

1. **Connection Refused**: 지정된 포트에서 서버가 아웃바운드 SMTP 연결을 허용하는지 확인하세요.
2. **인증 실패**: 사용자 이름과 비밀번호가 올바른지 확인하세요
3. **Gmail 앱 비밀번호**: Gmail의 경우, 일반 비밀번호가 아닌 앱 전용 비밀번호를 사용해야 합니다.
4. **자체 서명 인증서(Self-signed Certificates)**: 메일 서버가 자체 서명 인증서를 사용하는 경우, `EMAIL_ALLOW_SELFSIGNED=true`로 설정하세요.

### 일반적인 문제 [#general-issues]

1. **이메일이 발송되지 않음**: LibreChat 로그에서 오류 메시지를 확인하세요.
2. **보안되지 않은 비밀번호 재설정**: 이는 Mailgun이나 SMTP가 올바르게 구성되지 않았을 때 발생합니다.
3. **From 주소 문제**: `EMAIL_FROM` 주소가 유효하며 메일 서비스에서 발송하도록 승인되었는지 확인하세요.
