### Pamięć podręczna użytkownika OpenID JWT [#openid-jwt-user-cache]

Wdrożenia z dużą częstotliwością zapytań mogą ustawić `AUTH_USER_CACHE_MODE=on`, aby buforować dokument użytkownika rozpoznany dla uwierzytelniania OpenID JWT przez pięć sekund. Zmniejsza to liczbę powtarzających się odczytów z bazy danych podczas krótkich serii zapytań, bez wydłużania czasu życia tokena uwierzytelniającego.

Pamięć podręczna jest domyślnie wyłączona i wymaga ustawienia `USE_REDIS=true` z przestrzenią nazw `AUTH_USER_DOC` obsługiwaną przez Redis. LibreChat wyłącza ten tryb i rejestruje ostrzeżenie, gdy te wymagania nie są spełnione. Dokumenty w pamięci podręcznej są czyszczone przed zapisaniem i unieważniane w momencie aktualizacji użytkownika.

```bash filename=".env"
USE_REDIS=true
AUTH_USER_CACHE_MODE=on
```

## Rozwiązywanie problemów z OpenID Connect [#troubleshooting-openid-connect]

Jeśli napotkasz problemy z uwierzytelnianiem OpenID Connect:

1. **Włącz debugowanie nagłówków**: Ustaw `DEBUG_OPENID_REQUESTS=true` w swoich zmiennych środowiskowych, aby logować nagłówki żądań oprócz adresów URL (z zamaskowanymi danymi wrażliwymi). Pamiętaj, że adresy URL żądań są zawsze logowane na poziomie debugowania.
2. **Sprawdź identyfikatory URI przekierowania**: Upewnij się, że Twój adres URL wywołania zwrotnego (callback URL) jest dokładnie taki sam w konfiguracji dostawcy oraz w LibreChat
3. **Weryfikacja zakresów (Scopes)**: Upewnij się, że wszystkie wymagane zakresy są poprawnie skonfigurowane
4. **Przejrzyj logi dostawcy**: Sprawdź logi swojego dostawcy tożsamości pod kątem błędów uwierzytelniania
5. **Weryfikacja tokenów**: Upewnij się, że Twój dostawca wydaje poprawne tokeny z oczekiwanymi oświadczeniami (claims)
6. **Upewnij się, że _nonce_ jest generowane**: Niektórzy dostawcy tożsamości generują parametr adresu URL `nonce`, jeśli brakuje go w żądaniu. Ustaw `OPENID_GENERATE_NONCE=true`, aby wymusić na openid-client jego wygenerowanie.

### Ponowne próby wykrywania [#discovery-retries]

Jeśli dostawca tożsamości jest niedostępny w momencie uruchamiania LibreChat, można ponowić wykrywanie OpenID (OpenID discovery). `OPENID_DISCOVERY_RETRY_ATTEMPTS` określa liczbę prób wykonanych przed kontynuowaniem uruchamiania (od 0 do 100, domyślnie 1; `0` ponawia próby wyłącznie w tle), a `OPENID_DISCOVERY_RETRY_DELAY_MS` określa opóźnienie między próbami (domyślnie 5000). Wartości ustawione w sekcji `registration.openidDiscovery` w pliku `librechat.yaml` mają pierwszeństwo. Informacje o tych kluczach oraz o `oauthStateTtlMs`, który określa, jak długo rozpoczęte logowanie przez usługi społecznościowe może trwać do momentu powrotu na adres zwrotny (domyślnie 10 minut), znajdziesz w sekcji [registration](/docs/configuration/librechat_yaml/object_structure/registration).

### Pochodzenie awatarów profilu [#profile-avatar-origins]

Podczas pobierania awatara profilu użytkownika LibreChat wysyła token dostępu wyłącznie do źródeł (origin) wystawcy (issuer) i punktu userinfo dostawcy. Jeśli awatar jest udostępniany z innego źródła, które wymaga tokenu, dodaj je do `OPENID_AVATAR_AUTHORIZED_ORIGINS` jako listę adresów URL oddzieloną przecinkami lub spacjami.

```bash filename=".env"
OPENID_AVATAR_AUTHORIZED_ORIGINS=https://graph.example.com,https://photos.example.com
```

### Przekierowania panelu administratora [#admin-panel-redirects]

If the Admin Panel is hosted on a separate URL from LibreChat, set [`ADMIN_PANEL_URL`](/docs/configuration/admin_panel#redirect-url) in the LibreChat API environment. This tells LibreChat where to send admins after the admin OAuth or SSO callback completes.
