### Cache Pengguna OpenID JWT [#openid-jwt-user-cache]

Penyebaran dengan tingkat permintaan tinggi dapat mengatur `AUTH_USER_CACHE_MODE=on` untuk menyimpan dokumen pengguna yang diselesaikan untuk autentikasi JWT OpenID selama lima detik. Hal ini mengurangi pembacaan basis data yang berulang selama lonjakan permintaan singkat tanpa memperpanjang masa berlaku token autentikasi.

Cache dinonaktifkan secara default dan memerlukan `USE_REDIS=true` dengan namespace `AUTH_USER_DOC` yang didukung oleh Redis. LibreChat menonaktifkan mode ini dan mencatat peringatan saat persyaratan tersebut tidak terpenuhi. Dokumen yang di-cache akan dibersihkan (sanitized) sebelum disimpan dan dibatalkan validasinya saat pengguna diperbarui.

```bash filename=".env"
USE_REDIS=true
AUTH_USER_CACHE_MODE=on
```

## Pemecahan Masalah OpenID Connect [#troubleshooting-openid-connect]

Jika Anda mengalami masalah dengan autentikasi OpenID Connect:

1. **Aktifkan Logging Debug Header**: Atur `DEBUG_OPENID_REQUESTS=true` di variabel lingkungan Anda untuk mencatat header permintaan selain URL (dengan data sensitif disamarkan). Catatan: URL permintaan selalu dicatat pada level debug.
2. **Periksa URI Pengalihan**: Pastikan URL callback Anda sama persis antara penyedia Anda dan konfigurasi LibreChat
3. **Verifikasi Scope**: Pastikan semua scope yang diperlukan telah dikonfigurasi dengan benar
4. **Tinjau Log Penyedia**: Periksa log penyedia identitas Anda untuk melihat kesalahan autentikasi
5. **Validasi Token**: Pastikan penyedia Anda menerbitkan token yang valid dengan klaim yang diharapkan
6. **Pastikan _nonce_ dibuat**: Beberapa penyedia identitas membuat parameter url `nonce` jika parameter tersebut tidak ada dalam permintaan. Atur `OPENID_GENERATE_NONCE=true` untuk memaksa openid-client membuatnya.

### Percobaan Ulang Penemuan [#discovery-retries]

Jika identity provider Anda tidak dapat dijangkau saat LibreChat dimulai, penemuan OpenID dapat dicoba ulang. `OPENID_DISCOVERY_RETRY_ATTEMPTS` menetapkan jumlah percobaan yang dilakukan sebelum proses startup dilanjutkan (0 hingga 100, default 1; `0` hanya mencoba ulang di latar belakang), dan `OPENID_DISCOVERY_RETRY_DELAY_MS` menetapkan jeda waktu di antara setiap percobaan (default 5000). Nilai yang diatur di bawah `registration.openidDiscovery` dalam `librechat.yaml` memiliki prioritas lebih tinggi. Lihat [registration](/docs/configuration/librechat_yaml/object_structure/registration) untuk kunci-kunci tersebut dan untuk `oauthStateTtlMs`, yang mengontrol berapa lama proses login sosial yang sudah dimulai boleh mencapai callback-nya (default 10 menit).

### Asal Usul Avatar Profil [#profile-avatar-origins]

Saat mengambil avatar profil pengguna, LibreChat hanya mengirimkan access token ke origin issuer dan userinfo milik penyedia. Jika avatar disajikan dari origin lain yang memerlukan token tersebut, tambahkan origin itu ke `OPENID_AVATAR_AUTHORIZED_ORIGINS` sebagai daftar URL yang dipisahkan dengan koma atau spasi.

```bash filename=".env"
OPENID_AVATAR_AUTHORIZED_ORIGINS=https://graph.example.com,https://photos.example.com
```

### Pengalihan Panel Admin [#admin-panel-redirects]

Jika Admin Panel dihosting pada URL yang terpisah dari LibreChat, atur [`ADMIN_PANEL_URL`](/docs/features/admin_panel#librechat-redirect-url) di lingkungan API LibreChat. Ini memberi tahu LibreChat ke mana harus mengarahkan admin setelah callback OAuth atau SSO admin selesai.
