### OpenID JWT ユーザーキャッシュ [#openid-jwt-user-cache]

高リクエストレートのデプロイメントでは、`AUTH_USER_CACHE_MODE=on` を設定することで、OpenID JWT認証のために解決されたユーザードキュメントを5秒間キャッシュできます。これにより、認証トークンの有効期間を延長することなく、短期間のリクエストバースト中におけるデータベースの読み取り回数を削減できます。

キャッシュはデフォルトでオフになっており、Redisでバックアップされた `AUTH_USER_DOC` 名前空間で `USE_REDIS=true` を設定する必要があります。LibreChatは、これらの要件が満たされていない場合、このモードを無効にし、警告をログに記録します。キャッシュされたドキュメントは保存前にサニタイズされ、ユーザーが更新されると無効化されます。

```bash filename=".env"
USE_REDIS=true
AUTH_USER_CACHE_MODE=on
```

## OpenID Connect のトラブルシューティング [#troubleshooting-openid-connect]

OpenID Connect認証で問題が発生した場合：

1. **ヘッダーデバッグログの有効化**: 環境変数に `DEBUG_OPENID_REQUESTS=true` を設定すると、URLに加えてリクエストヘッダーもログに記録されます（機密データはマスクされます）。なお、リクエストURLは常にデバッグレベルでログに記録されることに注意してください。
2. **リダイレクトURIの確認**: プロバイダー側とLibreChatの設定側で、コールバックURLが完全に一致していることを確認してください。
3. **スコープの検証**: 必要なすべてのスコープが適切に設定されていることを確認してください
4. **プロバイダーログの確認**: 認証エラーがないか、IDプロバイダーのログを確認してください
5. **トークンの検証**: プロバイダーが期待されるクレームを含む有効なトークンを発行していることを確認してください。
6. **_nonce_ が生成されることを確認する**: 一部のアイデンティティプロバイダーは、リクエスト内に `nonce` URL パラメーターがない場合に生成を行います。`OPENID_GENERATE_NONCE=true` を設定して、openid-client に強制的に生成させるようにしてください。

### 検出の再試行 [#discovery-retries]

LibreChatの起動時にIDプロバイダーに接続できない場合、OpenIDのディスカバリーを再試行できます。`OPENID_DISCOVERY_RETRY_ATTEMPTS`は起動を続行するまでに行う試行回数を設定します（0〜100、デフォルトは1。`0`の場合はバックグラウンドでのみ再試行します）。`OPENID_DISCOVERY_RETRY_DELAY_MS`は試行間の遅延時間を設定します（デフォルトは5000）。`librechat.yaml`の`registration.openidDiscovery`で設定された値が優先されます。これらのキーおよび、ソーシャルログインの開始からコールバックに到達するまでの許容時間を制御する`oauthStateTtlMs`（デフォルトは10分）については、[registration](/docs/configuration/librechat_yaml/object_structure/registration)を参照してください。

### プロフィールアバターの由来 [#profile-avatar-origins]

LibreChat は、ユーザープロフィールのアバターを取得する際、アクセストークンをプロバイダーの issuer および userinfo のオリジンにのみ送信します。アバターが、トークンを必要とする別のオリジンから配信されている場合は、URL のカンマ区切りまたはスペース区切りのリストとして `OPENID_AVATAR_AUTHORIZED_ORIGINS` に追加してください。

```bash filename=".env"
OPENID_AVATAR_AUTHORIZED_ORIGINS=https://graph.example.com,https://photos.example.com
```

### 管理パネルのリダイレクト [#admin-panel-redirects]

LibreChat とは別の URL で Admin Panel をホストしている場合は、LibreChat API の環境変数に [`ADMIN_PANEL_URL`](/docs/configuration/admin_panel#redirect-url) を設定してください。これにより、管理者の OAuth または SSO コールバックが完了した後にリダイレクトする先を LibreChat に伝えることができます。
