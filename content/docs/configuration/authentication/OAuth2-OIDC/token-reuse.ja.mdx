LibreChatは、ユーザー認証状態を管理するために、OpenID Connectプロバイダー（Azure Entra IDやAuth0など）によって発行されたアクセストークンおよびリフレッシュトークンの再利用をサポートしています。この機能が有効な場合、クッキーとしてユーザーに渡されるリフレッシュトークンはLibreChatではなくOpenIDプロバイダーによって発行されるため、LibreChatサーバーはそれをリフレッシュし、プロバイダーからアクセストークンを要求できるようになります。

## 前提条件 [#prerequisites]

- 設定済みのOpenID Connectプロバイダー（Azure Entra ID、Auth0など）
- 基本的なOpenID Connectのセットアップが完了しました

## 設定手順 [#configuration-steps]

1. 環境変数に `OPENID_REUSE_TOKENS=true` を設定してください。

## プロバイダー固有の設定 [#provider-specific-configuration]

### Auth0 設定 [#auth0-configuration]

<Callout type="warning" title="Auth0にとって重要">
  Auth0でトークンの再利用を使用する場合、`OPENID_AUDIENCE`環境変数を**必ず**設定する必要があります。これを設定しないと、Auth0はLibreChatで検証できない不透明なトークンを返し、無限リフレッシュループが発生します。
</Callout>

Auth0の場合、以下の手順が必要です：

1. Auth0でAPIを作成します（JWTアクセストークンに必要です）：
   - **Auth0 Dashboard** → **Applications** → **APIs** に移動します。
   - **"Create API"** をクリックします
   - **Identifier**（例: `https://api.librechat.com`）を設定します。
   - API設定で **"Allow Offline Access"** を有効にします

2. 必要な環境変数を設定します：
   ```bash filename=".env"
   # Required for Auth0
   OPENID_AUDIENCE=https://api.librechat.com  # Your API identifier from Auth0
   OPENID_SCOPE=openid profile email offline_access
   ```

Auth0の詳細な設定については、以下を参照してください： [Auth0 OpenID Connect Configuration](/docs/configuration/authentication/OAuth2-OIDC/auth0)

### Azure Entra ID の設定 [#azure-entra-id-configuration]

2. OpenIDプロバイダーを設定します（例としてAzure Entra IDを使用）：
   - Azure Portalにアクセスし、アプリの登録（app registration）に移動します。
   - 左側のメニューにある「Expose API」をクリックします
   - 「Application ID URI」の横にある「Add」をクリックします
   - API URI（例: "api://librechat"）を入力して保存してください。

![image](https://github.com/user-attachments/assets/95bcd3ef-ed54-4002-9c74-a98d15673e71)

3. APIスコープを作成する:
   - 「Expose API」セクションで、「Add a scope」をクリックします。
   - 適切な権限でスコープを設定します
   - スコープ設定を保存

![image](https://github.com/user-attachments/assets/6f7a7170-92cd-4816-a1a8-dcacb592c893)

4. API権限の設定:
   - 左側のメニューにある「API permissions」に移動します
   - 「Add a permission」をクリックします
   - 「APIs my organization uses」の下で、アプリを検索してください
   - 「Delegated permissions」を選択し、適切なスコープ（例: 「access_user」）を選択します。

![image](https://github.com/user-attachments/assets/d0b23d65-ae39-4eb8-9f4d-97f18c627045)

![image](https://github.com/user-attachments/assets/67d09375-5b80-45e2-89e6-3bd0a00288e4)

![image](https://github.com/user-attachments/assets/1f85ae5e-4be2-4a68-b663-4152f32fa108)

5. 環境に必要なスコープを設定します：

   ```bash filename=".env"
   OPENID_SCOPE=api://librechat/.default openid profile email offline_access
   ```

   注: リフレッシュトークンを再利用するために取得するには、`offline_access` スコープが必要です。

6. 管理者同意を付与:
   - Azure Portalの「エンタープライズ アプリケーション (Enterprise Applications)」に移動します
   - LibreChat アプリケーションを見つける
   - Security > Permissions に移動します
   - 「Grant admin consent」をクリックします

![image](https://github.com/user-attachments/assets/d3a8b1f3-0f0a-4a90-92d9-9df91e665c8d)

7. ポップアップで要求された権限を許可してください

![image](https://github.com/user-attachments/assets/cc3eb15a-994e-49fb-b212-f94260d787d3)

8. LibreChatのキャッシュをクリアして、サービスを再起動します。

<Callout type="info" title="Microsoft Graph API 統合">
  トークンの再利用で Azure Entra ID を使用する場合、Microsoft Graph API 統合を有効にして、ユーザーおよびグループの検索機能を強化することもできます。詳細については、「[Microsoft Graph API 統合](/docs/configuration/authentication/OAuth2-OIDC/azure#advanced-microsoft-graph-api-integration)」を参照してください。
</Callout>

## 環境変数 [#environment-variables]

```bash filename=".env"
# OpenID Token Reuse Configuration
OPENID_REUSE_TOKENS=true
OPENID_SCOPE=api://librechat/.default openid profile email offline_access
OPENID_REUSE_MAX_SESSION_AGE_MS=900000  # 15 minutes in milliseconds
# OPENID_REFRESH_BRIDGE_GRACE_MS=60000  # 1-minute rotation recovery window

# Required for Auth0 (use your API identifier)
# OPENID_AUDIENCE=https://api.librechat.com
# OPENID_REFRESH_AUDIENCE=https://api.librechat.com

# Caching Configuration
OPENID_JWKS_URL_CACHE_ENABLED=true
OPENID_JWKS_URL_CACHE_TIME=600000  # 10 minutes in milliseconds (default: 60000, 1 minute)

# Azure-specific Configuration
OPENID_ON_BEHALF_FLOW_FOR_USERINFO_REQUIRED=true
OPENID_ON_BEHALF_FLOW_USERINFO_SCOPE=user.read
# Optional scope for Microsoft Graph tokens inserted into MCP configuration
# GRAPH_API_SCOPES=https://graph.microsoft.com/.default

# Logout Configuration
OPENID_USE_END_SESSION_ENDPOINT=true

# Maximum logout URL length before using logout_hint instead of id_token_hint (default: 2000)
# OPENID_MAX_LOGOUT_URL_LENGTH=2000
```

## 追加の設定オプション [#additional-configuration-options]

- `OPENID_AUDIENCE`: JWT検証および認可リクエストのためのオーディエンス値。**Auth0で**不透明トークンではなくJWTアクセストークンを受け取るために**必須**です。JWT検証にはカンマ区切りの値を使用でき、認可リクエストには最初の空でない値が使用されます。
- `OPENID_REFRESH_AUDIENCE`: リフレッシュトークンのリクエスト時に送信される任意の audience です。通常は `OPENID_AUDIENCE` と同じ値を指定します。カスタム API がリフレッシュをまたいで audience を維持する必要がある場合に、Auth0 などのプロバイダーで必要になります。
- `OPENID_REUSE_MAX_SESSION_AGE_MS`: 再利用されたOpenIDセッショントークンが、LibreChatによってIdPの強制リフレッシュが行われるまでに提供される最大有効期間（デフォルト: 900000 ms / 15分）。`60 * 60 * 24 * 1000` のような算術式を受け付けます。プロバイダーがリフレッシュのたびに以前のアクセストークンを無効化する場合は、IdPのアクセストークンの有効期間に合わせてこの値を増やしてください。
- `OPENID_REFRESH_BRIDGE_GRACE_MS`: ローテーションされたリフレッシュトークンのための短いリカバリウィンドウ。LibreChatがリフレッシュされたセッションを公開するまでの間有効です（デフォルト: 60000 ms / 1分）。算術式を受け付けます。セッションの永続化が遅い場合や、レプリカ間での公開により多くの時間が必要な場合にのみ値を増やしてください。
- `OPENID_JWKS_URL_CACHE_ENABLED`: 署名鍵をキャッシュして、JWKS エンドポイントへの過剰な HTTP リクエストを防ぎます。この変数が未設定の場合はキャッシュが有効になります。`true` 以外の値を設定すると、キャッシュは無効になります。
- `OPENID_JWKS_URL_CACHE_TIME`: キャッシュの有効期間（ミリ秒単位）（デフォルト: 60000 ms / 1 分）
- `OPENID_ON_BEHALF_FLOW_FOR_USERINFO_REQUIRED`: ユーザー情報取得のために on-behalf-of フローを有効にします（Azure 固有）
- `OPENID_ON_BEHALF_FLOW_USERINFO_SCOPE`: On-behalf-ofフローにおけるユーザー情報のスコープ（Azure固有）
- `GRAPH_API_SCOPES`: YAMLで定義されたMCPサーバー内で `{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` を解決する際に要求される、スペース区切りのMicrosoft Graphスコープ。デフォルトは `https://graph.microsoft.com/.default` です。これは、ユーザーやグループの検索に使用される `OPENID_GRAPH_SCOPES` とは別個のものです。
- `OPENID_USE_END_SESSION_ENDPOINT`: ログアウト時にエンドセッションエンドポイントの使用を有効にします
- `OPENID_MAX_LOGOUT_URL_LENGTH`: URIが長すぎるエラーを防ぐために `id_token_hint` の代わりに `logout_hint` を使用するまでの最大URL長（デフォルト: 2000）

## セキュリティに関する考慮事項 [#security-considerations]

- 適切なトークンの保存と取り扱いを確実にしてください
- 適切なトークン更新メカニズムを実装する
- トークン使用量を監視し、必要に応じてレート制限を実装してください。
- クライアントシークレットを定期的にローテーションする
- トークンストレージにはセキュアなクッキー設定を使用してください
- LibreChatは、ベアラートークンの再利用にアクセストークンが必要な場合、IDトークンを拒否します。要求されたオーディエンスとスコープに対して実際のアクセストークンを発行するようにプロバイダーを設定してください。
- `expires_in` の値が欠落している、無効である、または過剰であるトークンレスポンスは、キャッシュされたトークンを不当に延長するのではなく、その認証情報の安全な有効期限内に制限されます。
- LibreChatは、ライブセッションからMCPおよびMicrosoft Graph用のOpenID認証情報を解決し、レプリカ間でのリフレッシュを調整します。また、ログアウト処理をフェンス（保護）することで、遅延したリフレッシュによってサインアウト済みのセッションが再作成されることを防ぎます。

## トラブルシューティング [#troubleshooting]

トークンの再利用で問題が発生した場合：

1. 必要なすべてのスコープが適切に設定されていることを確認してください
2. 管理者による同意が付与されていることを確認してください
3. APIの権限が正しく設定されていることを確認してください
4. トークンキャッシュが期待通りに動作していることを確認する
5. アプリケーションログで認証エラーが発生していないか確認してください
6. 環境変数で `DEBUG_OPENID_REQUESTS=true` を設定して詳細な OpenID リクエストヘッダーのログ出力を有効にすると、URL に加えてリクエストヘッダーを確認できます（機密データはマスクされます）。
