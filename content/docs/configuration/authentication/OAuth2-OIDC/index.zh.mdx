### OpenID JWT 用户缓存 [#openid-jwt-user-cache]

在高请求速率的部署中，可以设置 `AUTH_USER_CACHE_MODE=on`，以便将用于 OpenID JWT 身份验证的已解析用户文档缓存五秒。这可以在不延长身份验证令牌生命周期的情况下，减少短时间请求激增期间的重复数据库读取。

缓存默认处于关闭状态，需要设置 `USE_REDIS=true` 并使用由 Redis 支持的 `AUTH_USER_DOC` 命名空间。当不满足这些要求时，LibreChat 会禁用该模式并记录一条警告。缓存的文档在存储前会经过清理，并在用户更新时失效。

```bash filename=".env"
USE_REDIS=true
AUTH_USER_CACHE_MODE=on
```

## 排查 OpenID Connect 问题 [#troubleshooting-openid-connect]

如果您在使用 OpenID Connect 身份验证时遇到问题：

1. **启用 Header 调试日志记录**：在环境变量中设置 `DEBUG_OPENID_REQUESTS=true`，以便在记录 URL 的同时记录请求头（敏感数据会被屏蔽）。请注意：请求 URL 始终会在调试级别进行记录。
2. **检查重定向 URI**：确保您的回调 URL 在您的提供商和 LibreChat 配置之间完全一致
3. **验证作用域 (Verify Scopes)**：确保所有必需的作用域均已正确配置
4. **查看提供商日志**：检查您的身份提供商日志以查找身份验证错误
5. **验证令牌 (Validate Tokens)**：确保您的提供商正在颁发带有预期声明的有效令牌
6. **确保生成 _nonce_**：某些身份提供商会在请求中缺少 `nonce` URL 参数时自动生成该参数。设置 `OPENID_GENERATE_NONCE=true` 以强制 openid-client 生成它。

### 发现重试 [#discovery-retries]

如果 LibreChat 启动时无法连接到您的身份提供商,可以重试 OpenID 发现。`OPENID_DISCOVERY_RETRY_ATTEMPTS` 用于设置启动继续前的尝试次数(0 到 100,默认值为 1;`0` 表示仅在后台重试),`OPENID_DISCOVERY_RETRY_DELAY_MS` 用于设置两次尝试之间的延迟(默认值为 5000)。`librechat.yaml` 中 `registration.openidDiscovery` 下设置的值优先生效。有关这些键以及 `oauthStateTtlMs`(用于控制已启动的社交登录到达回调地址所允许的时长,默认值为 10 分钟)的说明,请参阅 [registration](/docs/configuration/librechat_yaml/object_structure/registration)。

### 个人资料头像来源 [#profile-avatar-origins]

当获取用户的个人资料头像时,LibreChat 仅会将访问令牌发送至身份提供方的 issuer 和 userinfo 源。如果头像由其他需要该令牌的源提供,请将其添加到 `OPENID_AVATAR_AUTHORIZED_ORIGINS` 中,并使用逗号或空格分隔的 URL 列表进行配置。

```bash filename=".env"
OPENID_AVATAR_AUTHORIZED_ORIGINS=https://graph.example.com,https://photos.example.com
```

### 管理面板重定向 [#admin-panel-redirects]

如果管理面板托管在与 LibreChat 不同的 URL 上,请在 LibreChat API 环境变量中设置 [`ADMIN_PANEL_URL`](/docs/configuration/admin_panel#redirect-url)。这会告诉 LibreChat 在管理员 OAuth 或 SSO 回调完成后,将其重定向到何处。
