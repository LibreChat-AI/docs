> **注意：** OpenID 和 SAML 不支持仅禁用注册的功能。

设置 `ALLOW_EMAIL_LOGIN=false` 将隐藏电子邮件登录表单，并拒绝发往 `/api/auth/login` 的本地或 LDAP 凭据请求；OAuth、OpenID Connect 和 SAML 登录不受影响。`ALLOW_EMAIL_LOGIN_OVERRIDE=true` 仅旨在用于在表单隐藏时仍需要凭据登录的受控 API 集成。每次使用覆盖功能都会记录请求 IP，因此请务必小心保护和监控该路由。

快速提示：

- 即使禁用了注册功能，您也可以使用下文详述的 [create-user script](#create-user-script) 将用户直接添加到数据库中。
- 要删除用户，您可以使用下文详述的 [delete-user 脚本](#delete-user-script)。

本地账户的相关登录选项：

- [Passkeys](/docs/configuration/authentication/passkeys)：使用设备屏幕锁定或安全密钥进行无密码登录 (`ALLOW_PASSKEY_LOGIN`)。

## 强制双重身份验证 [#required-two-factor-authentication]

用户始终可以自行在 **Settings > Account** 中开启双重身份验证 (TOTP)。若要强制执行，请设置：

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**适用对象：** 本地（电子邮件和密码）账户及 LDAP 账户。通过 OAuth、OpenID Connect 或 SAML 登录的账户不受影响，因为其身份提供商负责 MFA。如果联合账户在强制执行期间尝试使用密码登录，系统会提示其改用身份提供商进行登录。

**用户看到的界面：** 未启用 2FA 的用户在登录时（通过密码、LDAP 凭据或通行密钥），在设置完成前不会获得会话。他们会进入**需要双重身份验证**页面（“您的管理员要求进行双重身份验证。请在继续前完成设置。”），使用身份验证器应用扫描二维码，输入验证码进行验证，并保存备份代码。已登录的用户在下次检查或刷新会话时会被引导至相同的设置流程，且在注册前颁发的访问令牌将失效。设置会话有效期为 10 分钟；如果过期，用户将返回登录页面并重新开始。

**注册后：** **设置 > 账户** 中的 **禁用 2FA** 控件将显示 **由管理员强制要求**，且当策略开启时，服务器会拒绝禁用 2FA 的请求。用户仍然可以重新生成备份代码。

`ENFORCE_TWO_FACTOR_AUTHENTICATION` 以及 `TWO_FACTOR_TEMP_*` 和 `TWO_FACTOR_SETUP_*` 限制是进程范围的 `.env` 设置。它们在请求或租户配置可用之前生效，因此无法在 `librechat.yaml` 或每个租户中进行设置。请在每个副本上设置相同的值。用于从设置中管理 2FA 的独立预算是 [`rateLimits.twoFactorManagement`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits)。

## 会话过期与刷新令牌 [#session-expiry-and-refresh-token]

- 默认值：会话过期时间：15 分钟，刷新令牌过期时间：7 天
  - 更多信息请参阅：**[GitHub PR #927 - Refresh Token](https://github.com/LibreChat-AI/LibreChat/pull/927)**

``` mermaid
sequenceDiagram
    Client->>Server: Login request with credentials
    Server->>Passport: Use authentication strategy (e.g., 'local', 'google', etc.)
    Passport-->>Server: User object or false/error
    Note over Server: If valid user...
    Server->>Server: Generate access and refresh tokens
    Server->>Database: Store hashed refresh token
    Server-->>Client: Access token and refresh token
    Client->>Client: Store access token in HTTP Header and refresh token in HttpOnly cookie
    Client->>Server: Request with access token from HTTP Header
    Server-->>Client: Requested data
    Note over Client,Server: Access token expires
    Client->>Server: Request with expired access token
    Server-->>Client: Unauthorized
    Client->>Server: Request with refresh token from HttpOnly cookie
    Server->>Database: Retrieve hashed refresh token
    Server->>Server: Compare hash of provided refresh token with stored hash
    Note over Server: If hashes match...
    Server-->>Client: New access token and refresh token
    Client->>Server: Retry request with new access token
    Server-->>Client: Requested data
```

## JWT Secret 和 Refresh Secret [#jwt-secret-and-refresh-secret]

使用至少 32 字节的唯一值。使用 [Credentials Generator](/toolkit/creds_generator) 生成永久值，将其安全存储，并为每个 LibreChat 副本提供相同的值。

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'JWT 密钥。','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'JWT 刷新密钥。','JWT_REFRESH_SECRET='],
  ]}
/>

当任一值为空时，LibreChat 可以从其临时凭据文件中生成并重用一个值。默认的 Docker Compose 堆栈会持久化该文件，但这仅旨在作为引导便利。如果文件丢失或无法写入，会话可能会在重启后失效。有关优先级、持久性和生产环境指南，请参阅 [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration)。

## 自动化审核系统 (optional) [#automated-moderation-system-optional]

自动审核系统（Automated Moderation System）默认处于启用状态。它使用评分机制来跟踪用户的违规行为。当用户执行诸如频繁登录、注册或发送消息等操作时，他们会积累违规分数。一旦达到设定的阈值，该用户及其 IP 地址将被暂时封禁。该系统通过监控并惩罚快速或可疑的活动来确保平台安全。

要设置 mod 系统，请查看[设置指南](/docs/configuration/mod_system)。

> *请注意：如果您希望此功能在开发模式下正常工作，您需要在根目录下创建一个名为 `.env.development` 的文件，并将 `DOMAIN_CLIENT` 设置为 `http://localhost:3090`，或者设置为运行 `npm run frontend-dev` 时 vite 所提供的端口。*

## 用户管理脚本 [#user-management-scripts]

### 创建用户脚本 [#create-user-script]

create-user 脚本允许您直接向数据库添加用户，即使在禁用了注册功能的情况下也是如此。使用方法如下：

1. 对于默认的 `docker-compose.yml`（如果您使用 `docker compose up` 来启动应用）：
   ```bash
   docker compose exec api npm run create-user
   ```

2. 对于 `deploy-compose.yml`（如果你遵循了 [Ubuntu Docker Guide](/docs/remote/docker_linux)）：
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. 对于本地开发（从项目根目录）：
   ```bash
   npm run create-user
   ```

按照提示输入新用户的电子邮件和密码。

### 删除用户脚本 [#delete-user-script]

要删除用户，您可以使用 delete-user 脚本：

1. 对于默认的 `docker-compose.yml`（如果您使用 `docker compose up` 来启动应用）：
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. 对于 `deploy-compose.yml`（如果你遵循了 [Ubuntu Docker Guide](/docs/remote/docker_linux)）：
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. 对于本地开发（从项目根目录）：
   ```bash
   npm run delete-user email@domain.com
   ```

将 `email@domain.com` 替换为您想要删除的用户的电子邮件地址。
