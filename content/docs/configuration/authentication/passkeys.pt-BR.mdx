Passkeys permitem que usuários com uma conta local (e-mail e senha) façam login com o bloqueio de tela do dispositivo, um gerenciador de senhas ou uma chave de segurança de hardware em vez de digitar uma senha. O LibreChat os implementa com WebAuthn. Eles estão desativados por padrão.

Use passkeys quando desejar um login sem senha e resistente a phishing para contas locais. Contas que fazem login via OAuth, OpenID Connect, SAML ou LDAP continuam usando seus provedores e não podem adicionar passkeys.

## Habilitar passkeys [#enable-passkeys]

<Steps>
<Step>

**Sirva o LibreChat via HTTPS.** Os navegadores permitem WebAuthn apenas em um contexto seguro. `http://localhost` é uma exceção, portanto, testes locais funcionam sem TLS.

</Step>
<Step>

**Ative o recurso no `.env`.** Para uma implantação padrão, esta é a única configuração necessária. O ID da parte confiável (relying party ID) e as origens permitidas são derivados de `DOMAIN_CLIENT` e `DOMAIN_SERVER`.

```bash filename=".env"
ALLOW_PASSKEY_LOGIN=true
```

</Step>
<Step>

**Fixe o relying party ID (recomendado).** Cada passkey é permanentemente vinculada ao RP ID sob o qual foi criada. Se o `DOMAIN_CLIENT` puder mudar futuramente, defina o `PASSKEY_RP_ID` agora para que as passkeys existentes continuem funcionando.

```bash filename=".env"
PASSKEY_RP_ID=chat.example.com
```

</Step>
<Step>

**Reinicie o LibreChat.** A página de login exibirá **Sign in with a passkey** e **Settings > Account** mostrará uma seção **Passkeys**.

</Step>
</Steps>

### Limite por usuário no `librechat.yaml` [#per-user-limit-in-librechatyaml]

Você também pode definir o limite de matrículas no `librechat.yaml`:

```yaml filename="librechat.yaml"
passkeys:
  perUserMax: 10
```

O limite é resolvido nesta ordem: `passkeys.perUserMax` no `librechat.yaml`, depois `MAX_PASSKEYS_PER_USER`, e então o padrão de `20`. Valores fora do intervalo de `1` a `100` são ignorados e a próxima fonte é utilizada. Quando um usuário atinge o limite, **Configurações > Conta** exibe "You have reached the maximum number of passkeys". Veja [`passkeys`](/docs/configuration/librechat_yaml/object_structure/config#passkeys) na referência de configuração.

## O que os usuários veem [#what-users-see]

**Adicionando uma passkey**

1. Abra **Settings > Account**, encontre **Passkeys** e selecione **Manage**.
2. Selecione **Add passkey**.
3. Insira a senha da conta na caixa de diálogo **Confirm your password**. Uma passkey é um método de login completo por si só, portanto, o LibreChat solicita a senha antes de criar uma.
4. Conclua o prompt do navegador ou dispositivo. A nova chave de acesso (passkey) aparece na lista com um nome padrão, como **Este dispositivo**, **Telefone ou tablet** ou **Chave de segurança**.

Cada entrada mostra quando foi adicionada e usada pela última vez, e um selo **Synced** quando o autenticador informa que a passkey possui backup (por exemplo, por um gerenciador de senhas). Os usuários podem renomear uma passkey, e a remoção de uma (**Remove passkey**) também solicita a senha da conta.

**Entrando**

Na página de login, os usuários selecionam **Sign in with a passkey** e aprovam o prompt do dispositivo. Se a conta tiver a autenticação de dois fatores ativada, o LibreChat ainda solicitará o código 2FA posteriormente, exatamente como faz após um login com senha.

## Comportamento e ressalvas [#behavior-and-caveats]

- **Apenas contas locais.** O registro e o login com Passkey são limitados a contas locais. Contas criadas por meio de um provedor de identidade ou LDAP devem continuar se autenticando através desse provedor.
- **Funciona com o login por e-mail desativado.** O botão **Sign in with a passkey** e suas rotas dependem apenas de `ALLOW_PASSKEY_LOGIN`. Com `ALLOW_EMAIL_LOGIN=false`, usuários locais existentes ainda podem entrar com passkeys que registraram anteriormente.
- **Autenticação de dois fatores.** O login com Passkey passa pelo mesmo portal de 2FA que o login com senha. Com [`ENFORCE_TWO_FACTOR_AUTHENTICATION=true`](/docs/configuration/authentication#required-two-factor-authentication), um usuário que não se inscreveu no 2FA é enviado para o fluxo de configuração após fazer login com uma passkey.
- **Alterar o RP ID torna as passkeys órfãs.** Passkeys criadas sob um RP ID nunca funcionam sob outro. Alterar `PASSKEY_RP_ID`, ou alterar `DOMAIN_CLIENT` enquanto `PASSKEY_RP_ID` não estiver definido, torna todas as passkeys existentes inutilizáveis; os usuários devem entrar de outra forma e se registrar novamente.
- **As origens devem corresponder.** Se os usuários acessarem o LibreChat em uma origem não coberta por `PASSKEY_ORIGINS` (ou pelos padrões derivados), o navegador exibirá "Passkeys are not available on this domain". Adicione todas as origens públicas a `PASSKEY_ORIGINS` ao servir o LibreChat em mais de uma.
- **A redefinição de senha remove as passkeys.** Uma redefinição de senha concluída desconecta a conta de todos os lugares e exclui todas as suas passkeys, portanto, uma passkey registrada antes da redefinição não pode mais ser usada para acessar a conta. Os usuários devem registrá-las novamente após o processo.
