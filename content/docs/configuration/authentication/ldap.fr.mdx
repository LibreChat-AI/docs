Vous pouvez utiliser un serveur d'authentification Lightweight Directory Access Protocol (LDAP) pour authentifier les utilisateurs.

## Configuration du serveur LDAP/AD [#ldapad-server-configuration]

**Configuration de base**

- `LDAP_URL` et `LDAP_USER_SEARCH_BASE` sont requis.
- `LDAP_SEARCH_FILTER` est facultatif ; s'il n'est pas spécifié, l'attribut `mail` est utilisé par défaut. S'il est spécifié, utilisez le littéral `{{username}}` pour utiliser le nom d'utilisateur fourni pour la recherche.

<OptionTable
  options={[
    ['LDAP_URL', 'string', 'URL du serveur LDAP.', 'LDAP_URL=ldap://localhost:389'],
    ['LDAP_BIND_DN', 'string', 'DN de liaison', 'LDAP_BIND_DN=cn=root'],
    ['LDAP_BIND_CREDENTIALS', 'string', 'Mot de passe pour bindDN', 'LDAP_BIND_CREDENTIALS=password'],
    [
      'LDAP_USER_SEARCH_BASE',
      'string',
      'Base de recherche d\'utilisateurs LDAP',
      'LDAP_USER_SEARCH_BASE=o=users,o=example.com',
    ],
    ['LDAP_SEARCH_FILTER', 'string', 'Filtre de recherche LDAP', 'LDAP_SEARCH_FILTER=mail={{username}}'],
  ]}
/>

**Mappages de champs**

Vous pouvez spécifier une correspondance entre les attributs des utilisateurs LibreChat et ceux des utilisateurs LDAP. Utilisez ces paramètres si les correspondances par défaut ne fonctionnent pas correctement.

<OptionTable
  options={[
    [
      'LDAP_ID',
      'string',
      'Spécifiez un identifiant utilisateur unique. Par défaut, uid ou sAMAccountName, mail est utilisé.',
      'LDAP_ID=uid',
    ],
    [
      'LDAP_USERNAME',
      'string',
      'Par défaut, il utilise givenName ou mail.',
      'LDAP_USERNAME=givenName',
    ],
    [
      'LDAP_EMAIL',
      'string',
      'Par défaut, il utilise mail.',
      'LDAP_EMAIL=userPrincipalName',
    ],
    [
      'LDAP_FULL_NAME',
      'string',

      'LDAP_FULL_NAME=givenName,surname',
    ],
  ]}
/>

**Nom d'utilisateur ou e-mail**

Par défaut, LibreChat utilise une adresse e-mail et un mot de passe pour l'authentification.
Cela peut parfois poser problème avec LDAP et vous pourriez souhaiter utiliser un nom d'utilisateur à la place.
Définissez `LDAP_SEARCH_FILTER` pour filtrer par nom d'utilisateur (par exemple `LDAP_SEARCH_FILTER=uid={{username}}`)
et configurez LibreChat pour demander la connexion via un nom d'utilisateur :

<OptionTable
  options={[
    [
      'LDAP_LOGIN_USES_USERNAME',
      'boolean',
      'Utiliser le nom d\'utilisateur au lieu de l\'e-mail.',
      'LDAP_LOGIN_USES_USERNAME=true',
    ],
  ]}
/>

**Active Directory via SSL**

Pour vous connecter via SSL (ldaps://), par exemple dans une entreprise utilisant Windows AD, indiquez le chemin vers le certificat de l'autorité de certification interne avec `LDAP_CA_CERT_PATH`.

`LDAP_TLS_REJECT_UNAUTHORIZED` n'est appliqué que lorsque `LDAP_CA_CERT_PATH` est défini. Dans ce cas, la vérification du certificat est **désactivée** tant que vous ne définissez pas explicitement `LDAP_TLS_REJECT_UNAUTHORIZED=true`. Lorsque `LDAP_CA_CERT_PATH` n'est pas défini, LibreChat ne transmet aucune option TLS et le comportement par défaut de Node.js s'applique (le certificat du serveur est vérifié par rapport au magasin de confiance du système).

<Callout type="warning" title="Activer la vérification des certificats">
  Si vous définissez `LDAP_CA_CERT_PATH` sans `LDAP_TLS_REJECT_UNAUTHORIZED=true`, LibreChat fait confiance à tout certificat présenté par le serveur LDAP, ce qui expose les identifiants de liaison et les mots de passe des utilisateurs à des attaques de type homme du milieu. Définissez toujours `LDAP_TLS_REJECT_UNAUTHORIZED=true` en production.
</Callout>

<OptionTable
  options={[
    [
      'LDAP_CA_CERT_PATH',
      'string',
      'Chemin du certificat CA.',
      'LDAP_CA_CERT_PATH=/path/to/root_ca_cert.crt',
    ],
    [
      'LDAP_TLS_REJECT_UNAUTHORIZED',
      'boolean',
      'Vérifiez le certificat du serveur LDAP par rapport à LDAP_CA_CERT_PATH. Doit être défini sur true pour activer la vérification ; ignoré lorsque LDAP_CA_CERT_PATH n\'est pas défini.',
      'LDAP_TLS_REJECT_UNAUTHORIZED=true',
    ],
  ]}
/>

**LDAP StartTLS**

L'activation de LDAP StartTLS permet à LibreChat de mettre à niveau une connexion non sécurisée vers une connexion TLS sécurisée. Ceci est utile si vous souhaitez sécuriser la connexion sans passer par ldaps://.

<OptionTable
    options={[
        [
            'LDAP_STARTTLS',
            'boolean',
            'Activez LDAP StartTLS pour mettre à niveau la connexion vers TLS. Définissez sur true pour activer cette fonctionnalité.',
            'LDAP_STARTTLS=true',
        ],
    ]}
/>
