Passkeys를 사용하면 로컬(이메일 및 비밀번호) 계정을 가진 사용자가 비밀번호를 입력하는 대신 기기 화면 잠금, 비밀번호 관리자 또는 하드웨어 보안 키를 사용하여 로그인할 수 있습니다. LibreChat은 WebAuthn을 사용하여 이를 구현합니다. 기본적으로 비활성화되어 있습니다.

로컬 계정에 대해 피싱에 강하고 비밀번호가 필요 없는 로그인을 원할 경우 패스키(passkeys)를 사용하세요. OAuth, OpenID Connect, SAML 또는 LDAP을 통해 로그인하는 계정은 기존 제공업체를 계속 사용하며 패스키를 추가할 수 없습니다.

## 패스키(passkeys) 활성화 [#enable-passkeys]

<Steps>
<Step>

**LibreChat을 HTTPS로 서비스하세요.** 브라우저는 보안 컨텍스트에서만 WebAuthn을 허용합니다. `http://localhost`는 예외이므로 TLS 없이도 로컬 테스트가 가능합니다.

</Step>
<Step>

**Turn the feature on in `.env`.** For a standard deployment, this is the only required setting. The relying party ID and allowed origins are derived from `DOMAIN_CLIENT` and `DOMAIN_SERVER`.

```bash filename=".env"
ALLOW_PASSKEY_LOGIN=true
```

</Step>
<Step>

**Relying party ID 고정 (권장).** 각 패스키는 생성된 RP ID에 영구적으로 바인딩됩니다. `DOMAIN_CLIENT`가 변경될 가능성이 있다면, 기존 패스키가 계속 작동하도록 지금 `PASSKEY_RP_ID`를 설정하십시오.

```bash filename=".env"
PASSKEY_RP_ID=chat.example.com
```

</Step>
<Step>

**LibreChat을 재시작합니다.** 로그인 페이지에 **Sign in with a passkey**가 표시되며, **Settings > Account**에서 **Passkeys** 섹션을 확인할 수 있습니다.

</Step>
</Steps>

### `librechat.yaml`의 사용자별 제한 [#per-user-limit-in-librechatyaml]

`librechat.yaml`에서 등록 제한(enrollment cap)을 설정할 수도 있습니다:

```yaml filename="librechat.yaml"
passkeys:
  perUserMax: 10
```

이 제한은 `librechat.yaml`의 `passkeys.perUserMax`, 그 다음 `MAX_PASSKEYS_PER_USER`, 마지막으로 기본값인 `20` 순서로 결정됩니다. `1`에서 `100` 범위를 벗어나는 값은 무시되며 다음 소스가 사용됩니다. 사용자가 제한에 도달하면 **설정 > 계정**에 "패스키 최대 개수에 도달했습니다"라는 메시지가 표시됩니다. 구성 참조의 [`passkeys`](/docs/configuration/librechat_yaml/object_structure/config#passkeys)를 확인하세요.

## 사용자가 보는 것 [#what-users-see]

**패스키 추가하기**

1. **Settings > Account**을 열고 **Passkeys**를 찾은 다음 **Manage**를 선택하세요.
2. **Add passkey**를 선택하세요.
3. **Confirm your password** 대화 상자에 계정 비밀번호를 입력하세요. 패스키는 그 자체로 완전한 로그인 수단이므로, LibreChat은 패스키를 생성하기 전에 비밀번호를 요구합니다.
4. 브라우저 또는 기기 프롬프트를 완료하세요. 새 패스키가 **이 기기**, **휴대전화 또는 태블릿**, 또는 **보안 키**와 같은 기본 이름으로 목록에 나타납니다.

각 항목에는 추가된 날짜와 마지막으로 사용된 날짜가 표시되며, 인증자가 패스키가 백업되었음을 보고할 때(예: 비밀번호 관리자를 통해) **Synced** 배지가 표시됩니다. 사용자는 패스키의 이름을 변경할 수 있으며, 패스키를 제거(**Remove passkey**)할 때는 계정 비밀번호를 요구합니다.

**로그인**

로그인 페이지에서 사용자는 **Sign in with a passkey**를 선택하고 기기 프롬프트를 승인합니다. 계정에 2단계 인증(2FA)이 활성화되어 있는 경우, LibreChat은 비밀번호 로그인 후와 동일하게 이후에 2FA 코드를 요청합니다.

## 동작 및 주의 사항 [#behavior-and-caveats]

- **로컬 계정 전용.** 패스키 등록 및 로그인은 로컬 계정으로 제한됩니다. ID 공급자(identity provider)나 LDAP을 통해 생성된 계정은 해당 공급자를 통해 계속 인증해야 합니다.
- **이메일 로그인이 비활성화된 상태에서도 작동합니다.** **Sign in with a passkey** 버튼과 해당 경로는 오직 `ALLOW_PASSKEY_LOGIN` 설정에만 의존합니다. `ALLOW_EMAIL_LOGIN=false`로 설정되어 있더라도, 기존 로컬 사용자는 이전에 등록한 패스키를 사용하여 계속 로그인할 수 있습니다.
- **2단계 인증.** 패스키(Passkey) 로그인은 비밀번호 로그인과 동일한 2FA 관문을 거칩니다. [`ENFORCE_TWO_FACTOR_AUTHENTICATION=true`](/docs/configuration/authentication#required-two-factor-authentication) 설정이 활성화된 경우, 2FA를 등록하지 않은 사용자는 패스키로 로그인한 후 설정 흐름으로 이동하게 됩니다.
- **RP ID를 변경하면 패스키가 고아 상태가 됩니다.** 한 RP ID 하에서 생성된 패스키는 다른 RP ID에서는 작동하지 않습니다. `PASSKEY_RP_ID`를 변경하거나 `PASSKEY_RP_ID`가 설정되지 않은 상태에서 `DOMAIN_CLIENT`를 변경하면 기존의 모든 패스키를 사용할 수 없게 됩니다. 사용자는 다른 방식으로 로그인한 후 다시 등록해야 합니다.
- **Origins must match.** 사용자가 `PASSKEY_ORIGINS`(또는 파생된 기본값)에 포함되지 않은 오리진에서 LibreChat에 접속하면, 브라우저에 "Passkeys are not available on this domain"이라는 메시지가 표시됩니다. LibreChat을 둘 이상의 오리진에서 서비스하는 경우, 모든 공개 오리진을 `PASSKEY_ORIGINS`에 추가하십시오.
- **비밀번호 재설정 시 패스키(passkeys)가 삭제됩니다.** 비밀번호 재설정이 완료되면 모든 곳에서 계정이 로그아웃되고 해당 계정의 모든 패스키가 삭제되므로, 재설정 전에 등록된 패스키는 더 이상 로그인에 사용할 수 없습니다. 사용자는 재설정 이후에 패스키를 다시 등록해야 합니다.
