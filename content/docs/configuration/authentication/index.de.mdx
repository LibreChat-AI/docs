Zugehörige Anmeldeoptionen für lokale Konten:

- [Passkeys](/docs/configuration/authentication/passkeys): passwortlose Anmeldung mit einer Bildschirmsperre des Geräts oder einem Sicherheitsschlüssel (`ALLOW_PASSKEY_LOGIN`).

## Erforderliche Zwei-Faktor-Authentifizierung [#required-two-factor-authentication]

Benutzer können die Zwei-Faktor-Authentifizierung (TOTP) jederzeit selbst unter **Einstellungen > Konto** aktivieren. Um sie verpflichtend zu machen, setzen Sie:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**Für wen es gilt:** lokale Konten (E-Mail und Passwort) sowie LDAP-Konten. Konten, die sich über OAuth, OpenID Connect oder SAML anmelden, sind nicht betroffen, da ihr Identitätsanbieter für MFA verantwortlich ist. Ein föderiertes Konto, das versucht, sich bei aktivierter Durchsetzung mit einem Passwort anzumelden, wird angewiesen, stattdessen seinen Identitätsanbieter zu verwenden.

**Was Benutzer sehen:** Ein Benutzer ohne 2FA, der sich anmeldet (mit einem Passwort, LDAP-Anmeldedaten oder einem Passkey), erhält keine Sitzung, bis die Einrichtung abgeschlossen ist. Sie gelangen auf einen Bildschirm mit der Meldung **Two-Factor Authentication Required** („Ihr Administrator erfordert eine Zwei-Faktor-Authentifizierung. Richten Sie diese ein, bevor Sie fortfahren.“), scannen einen QR-Code mit einer Authenticator-App, geben einen Code zur Bestätigung ein und speichern ihre Backup-Codes. Benutzer, die bereits angemeldet sind, werden bei der nächsten Überprüfung oder Aktualisierung ihrer Sitzung in denselben Einrichtungsprozess geleitet, und vor der Registrierung ausgestellte Zugriffstoken funktionieren nicht mehr. Die Einrichtungssitzung dauert 10 Minuten; läuft sie ab, kehrt der Benutzer zur Anmeldeseite zurück und beginnt von vorn.

**Nach der Registrierung:** Das Steuerelement **2FA deaktivieren** unter **Einstellungen > Konto** zeigt **Vom Administrator erforderlich** an, und der Server lehnt Versuche ab, 2FA zu deaktivieren, während die Richtlinie aktiv ist. Benutzer können weiterhin Backup-Codes neu generieren.

<Callout type="info" title="Nur Umgebung">
`ENFORCE_TWO_FACTOR_AUTHENTICATION` sowie die `TWO_FACTOR_TEMP_*`- und `TWO_FACTOR_SETUP_*`-Limits sind prozessweite `.env`-Einstellungen. Sie werden angewendet, bevor eine Anfrage oder eine Mandantenkonfiguration verfügbar ist, daher können sie nicht in `librechat.yaml` oder pro Mandant festgelegt werden. Legen Sie auf jedem Replikat dieselben Werte fest. Das separate Budget für die Verwaltung von 2FA über die Einstellungen ist [`rateLimits.twoFactorManagement`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits).

- Standardwerte: Sitzungsablauf: 15 Minuten, Ablauf des Refresh-Tokens: 7 Tage

## JWT Secret und Refresh Secret [#jwt-secret-and-refresh-secret]

Verwenden Sie eindeutige Werte mit mindestens 32 Bytes. Generieren Sie dauerhafte Werte mit dem [Credentials Generator](/toolkit/creds_generator), speichern Sie diese sicher und stellen Sie jedem LibreChat-Replikat dieselben Werte bereit.

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'JWT-Geheimschlüssel.','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'JWT-Refresh-Secret-Key.','JWT_REFRESH_SECRET='],
  ]}
/>

Wenn einer der beiden Werte leer ist, kann LibreChat einen Wert aus seiner temporären Anmeldedatei generieren und wiederverwenden. Die standardmäßigen Docker Compose-Stacks speichern diese Datei dauerhaft, dies ist jedoch nur als Bootstrap-Hilfe gedacht. Wenn die Datei verloren geht oder nicht geschrieben werden kann, können Sitzungen nach einem Neustart ungültig werden. Siehe [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) für Informationen zu Priorität, Persistenz und Empfehlungen für die Produktion.

## Automatisiertes Moderationssystem (optional) [#automated-moderation-system-optional]

Das Automated Moderation System ist standardmäßig aktiviert. Es verwendet einen Bewertungsmechanismus, um Benutzerverstöße zu verfolgen. Wenn Benutzer Aktionen wie übermäßige Anmeldungen, Registrierungen oder Nachrichtenversand durchführen, sammeln sie Verstößepunkte an. Beim Erreichen eines festgelegten Schwellenwerts werden der Benutzer und seine IP-Adresse vorübergehend gesperrt. Dieses System gewährleistet die Plattformsicherheit, indem es schnelle oder verdächtige Aktivitäten überwacht und sanktioniert.

Um das Mod-System einzurichten, lesen Sie [die Einrichtungsanleitung](/docs/configuration/mod_system).

> *Bitte beachten: Wenn Sie möchten, dass dies im Entwicklungsmodus funktioniert, müssen Sie eine Datei namens `.env.development` im Stammverzeichnis erstellen und `DOMAIN_CLIENT` auf `http://localhost:3090` oder den Port setzen, der von vite beim Ausführen von `npm run frontend-dev` bereitgestellt wird.*

## Benutzerverwaltungsskripte [#user-management-scripts]

### Benutzerskript erstellen [#create-user-script]

Das create-user Skript ermöglicht es Ihnen, Benutzer direkt zur Datenbank hinzuzufügen, selbst wenn die Registrierung deaktiviert ist. So verwenden Sie es:

1. Für die standardmäßige `docker-compose.yml` (falls Sie `docker compose up` verwenden, um die App zu starten):
   ```bash
   docker compose exec api npm run create-user
   ```

2. Für die `deploy-compose.yml` (falls Sie dem [Ubuntu Docker Guide](/docs/remote/docker_linux) gefolgt sind):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Für die lokale Entwicklung (vom Projektstammverzeichnis aus):
   ```bash
   npm run create-user
   ```

Befolgen Sie die Anweisungen, um die E-Mail-Adresse und das Passwort des neuen Benutzers einzugeben.

### Benutzer-Skript löschen [#delete-user-script]

Um einen Benutzer zu löschen, können Sie das delete-user Skript verwenden:

1. Für die standardmäßige `docker-compose.yml` (falls Sie `docker compose up` verwenden, um die App zu starten):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Für die `deploy-compose.yml` (falls Sie dem [Ubuntu Docker Guide](/docs/remote/docker_linux) gefolgt sind):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Für die lokale Entwicklung (vom Projektstammverzeichnis aus):
   ```bash
   npm run delete-user email@domain.com
   ```

Ersetzen Sie `email@domain.com` durch die E-Mail-Adresse des Benutzers, den Sie löschen möchten.
