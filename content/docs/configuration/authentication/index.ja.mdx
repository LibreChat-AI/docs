概要については、こちらで提供されているユーザーガイドを参照してください: [Authentication](/docs/features/authentication)

> **注:** OpenID および SAML は、登録のみを無効にする機能をサポートしていません。

`ALLOW_EMAIL_LOGIN=false` を設定すると、メールログインフォームが非表示になり、`/api/auth/login` へのローカルまたはLDAP認証リクエストが拒否されます。OAuth、OpenID Connect、およびSAMLサインインには影響しません。`ALLOW_EMAIL_LOGIN_OVERRIDE=true` は、フォームが非表示の状態でも認証ログインを必要とする制御されたAPI統合のためにのみ意図されています。オーバーライドを使用するたびにリクエスト元のIPがログに記録されるため、そのルートを慎重に保護および監視してください。

- 登録が無効になっている場合でも、以下で詳述する [the create-user script](#create-user-script) を使用して、データベースに直接ユーザーを追加できます。
- ユーザーを削除するには、以下で詳しく説明されている[delete-userスクリプト](#delete-user-script)を使用できます。

ローカルアカウントに関連するサインインオプション:

- [Passkeys](/docs/configuration/authentication/passkeys): デバイスの画面ロックやセキュリティキーを使用したパスワードレスサインイン (`ALLOW_PASSKEY_LOGIN`)。
- [Email address change](/docs/configuration/authentication/email#email-address-change): ユーザーが登録済みのメールアドレスを **Settings > Account** から変更できるようにします (`ALLOW_EMAIL_CHANGE`、デフォルトで有効)。

## 必須の二要素認証 [#required-two-factor-authentication]

ユーザーはいつでも **Settings > Account** から自身で二要素認証（TOTP）を有効にできます。これを強制するには、以下を設定してください：

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**対象:** local（メールアドレスとパスワード）およびLDAPアカウント。OAuth、OpenID Connect、またはSAMLを通じてサインインするアカウントは、MFAの責任が各アイデンティティプロバイダーにあるため、影響を受けません。強制適用中にパスワードでサインインしようとしたフェデレーションアカウントには、代わりにアイデンティティプロバイダーを使用するよう通知されます。

**ユーザーへの表示:** 2FAを設定していないユーザーが（パスワード、LDAP認証情報、またはパスキーを使用して）サインインした場合、設定が完了するまでセッションは開始されません。ユーザーは**「二要素認証が必要です」**という画面（「管理者が二要素認証を要求しています。続行する前に設定してください。」）に遷移し、認証アプリでQRコードをスキャンし、コードを入力して検証を行い、バックアップコードを保存します。すでにサインインしているユーザーは、次回セッションが確認または更新された際に同じ設定画面へ誘導され、登録前に発行されたアクセストークンは無効になります。設定セッションの有効期限は10分間です。期限が切れた場合、ユーザーはログインページに戻り、最初からやり直す必要があります。

**登録後:** **設定 > アカウント** 内の **2FAを無効化** コントロールには **管理者によって必須化されています** と表示され、ポリシーが有効な間はサーバーが2FAを無効化する試みを拒否します。ユーザーは引き続きバックアップコードの再生成を行うことができます。

`ENFORCE_TWO_FACTOR_AUTHENTICATION` および `TWO_FACTOR_TEMP_*` と `TWO_FACTOR_SETUP_*` の制限は、プロセス全体に適用される `.env` 設定です。これらはリクエストやテナント設定が利用可能になる前に適用されるため、`librechat.yaml` やテナントごとに設定することはできません。すべてのレプリカで同じ値を設定してください。設定から2FAを管理するための個別の予算については、[`rateLimits.twoFactorManagement`](/docs/configuration/librechat_yaml/object_structure/config#ratelimits) を参照してください。
</Callout>

``` mermaid
    Server-->>Client: Requested data
    Note over Client,Server: Access token expires
    Client->>Server: Request with expired access token
    Server-->>Client: Unauthorized

    Server->>Server: Compare hash of provided refresh token with stored hash

    Client->>Server: Retry request with new access token
    Server-->>Client: Requested data
```

## JWT Secret および Refresh Secret [#jwt-secret-and-refresh-secret]

少なくとも32バイトのユニークな値を使用してください。[Credentials Generator](/toolkit/creds_generator) を使用して永続的な値を生成し、安全に保管した上で、すべての LibreChat レプリカに同じ値を提供してください。

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'JWTシークレットキー','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'JWTリフレッシュシークレットキー','JWT_REFRESH_SECRET='],
  ]}
/>

いずれかの値が空の場合、LibreChatは一時的な認証情報ファイルから値を生成して再利用できます。デフォルトのDocker Composeスタックはそのファイルを永続化しますが、これはあくまでブートストラップの利便性を目的としたものです。ファイルが失われたり書き込みができない場合、再起動後にセッションが無効になる可能性があります。優先順位、永続化、および本番環境でのガイダンスについては、[Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) を参照してください。

## 自動モデレーションシステム (オプション) [#automated-moderation-system-optional]

自動モデレーションシステムはデフォルトで有効になっています。このシステムはスコアリングメカニズムを使用して、ユーザーの違反を追跡します。ユーザーが過度なログイン、登録、メッセージ送信などの行為を行うと、違反スコアが蓄積されます。設定されたしきい値に達すると、そのユーザーおよびIPアドレスは一時的に禁止されます。このシステムは、急激な活動や疑わしい活動を監視および制限することで、プラットフォームのセキュリティを確保します。

mod systemをセットアップするには、[セットアップガイド](/docs/configuration/mod_system)を確認してください。

> *注意: 開発モードで動作させるには、ルートディレクトリに `.env.development` という名前のファイルを作成し、`DOMAIN_CLIENT` を `http://localhost:3090`、または `npm run frontend-dev` を実行した際に vite によって提供されるポート番号に設定する必要があります。*

## ユーザー管理スクリプト [#user-management-scripts]

### ユーザー・スクリプトを作成する [#create-user-script]

create-user スクリプトを使用すると、登録が無効になっている場合でも、データベースに直接ユーザーを追加できます。使用方法は以下の通りです：

1. デフォルトの `docker-compose.yml` の場合（`docker compose up` を使用してアプリを起動する場合）:
   ```bash
   docker compose exec api npm run create-user
   ```

2. `deploy-compose.yml` については（[Ubuntu Docker Guide](/docs/remote/docker_linux) に従った場合）：
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. ローカル開発用（プロジェクトルートから）:
   ```bash
   npm run create-user
   ```

プロンプトに従って、新しいユーザーのメールアドレスとパスワードを入力してください。

### ユーザー削除スクリプト [#delete-user-script]

ユーザーを削除するには、delete-userスクリプトを使用できます：

1. デフォルトの `docker-compose.yml` の場合（`docker compose up` を使用してアプリを起動する場合）:
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. `deploy-compose.yml` については（[Ubuntu Docker Guide](/docs/remote/docker_linux) に従った場合）：
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. ローカル開発用（プロジェクトルートから）:
   ```bash
   npm run delete-user email@domain.com
   ```

`email@domain.com` を、削除したいユーザーのメールアドレスに置き換えてください。
