- 등록이 비활성화된 상태에서도 아래에 자세히 설명된 [create-user 스크립트](#create-user-script)를 사용하여 데이터베이스에 사용자를 직접 추가할 수 있습니다.
- 사용자를 삭제하려면 아래에 자세히 설명된 [delete-user 스크립트](#delete-user-script)를 사용할 수 있습니다.

로컬 계정에 대한 관련 로그인 옵션:

- [Passkeys](/docs/configuration/authentication/passkeys): 기기 화면 잠금 또는 보안 키를 사용한 비밀번호 없는 로그인 (`ALLOW_PASSKEY_LOGIN`).
- [Email address change](/docs/configuration/authentication/email#email-address-change): 사용자가 **Settings > Account**에서 등록된 이메일을 변경할 수 있도록 합니다(`ALLOW_EMAIL_CHANGE`, 기본값은 켜짐).

## 필수 2단계 인증 [#required-two-factor-authentication]

사용자는 언제든지 **설정 > 계정**에서 직접 이중 인증(TOTP)을 활성화할 수 있습니다. 이를 필수로 설정하려면 다음을 지정하세요:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**적용 대상:** 로컬(이메일 및 비밀번호) 계정 및 LDAP 계정. OAuth, OpenID Connect 또는 SAML을 통해 로그인하는 계정은 MFA를 담당하는 ID 공급자가 별도로 존재하므로 영향을 받지 않습니다. MFA가 강제된 상태에서 비밀번호로 로그인을 시도하는 페더레이션 계정은 대신 ID 공급자를 사용하라는 안내를 받게 됩니다.

**사용자가 보는 화면:** 2FA를 설정하지 않은 사용자가 (비밀번호, LDAP 자격 증명 또는 패스키를 사용하여) 로그인하면 설정이 완료될 때까지 세션이 생성되지 않습니다. 사용자는 **Two-Factor Authentication Required** 화면("관리자가 2단계 인증을 요구합니다. 계속하기 전에 설정하십시오.")으로 이동하며, 인증 앱으로 QR 코드를 스캔하고, 코드를 입력하여 확인한 뒤, 백업 코드를 저장하게 됩니다. 이미 로그인된 사용자는 다음 번 세션 확인 또는 새로고침 시 동일한 설정 화면으로 이동하며, 등록 이전에 발급된 액세스 토큰은 작동이 중지됩니다. 설정 세션은 10분 동안 유지되며, 만료될 경우 사용자는 로그인 페이지로 돌아가 처음부터 다시 시작해야 합니다.

**등록 후:** **설정 > 계정**의 **2FA 비활성화** 컨트롤에 **관리자에 의해 필수 설정됨**이 표시되며, 정책이 활성화된 동안 서버는 2FA 비활성화 시도를 거부합니다. 사용자는 여전히 백업 코드를 재생성할 수 있습니다.

``` mermaid
    Server-->>Client: Access token and refresh token
    Client->>Client: Store access token in HTTP Header and refresh token in HttpOnly cookie
    Client->>Server: Request with access token from HTTP Header
    Server-->>Client: Requested data
    Note over Client,Server: Access token expires
    Client->>Server: Request with expired access token
    Server-->>Client: Unauthorized
    Client->>Server: Request with refresh token from HttpOnly cookie
    Server->>Database: Retrieve hashed refresh token
    Server->>Server: Compare hash of provided refresh token with stored hash
    Note over Server: If hashes match...
    Server-->>Client: New access token and refresh token
    Client->>Server: Retry request with new access token
    Server-->>Client: Requested data
```

## JWT Secret 및 Refresh Secret [#jwt-secret-and-refresh-secret]

최소 32바이트 이상의 고유한 값을 사용하세요. [Credentials Generator](/toolkit/creds_generator)를 사용하여 영구적인 값을 생성하고, 이를 안전하게 저장한 뒤 모든 LibreChat 복제본에 동일한 값을 제공하세요.

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'JWT 비밀 키.','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'JWT 리프레시 비밀 키.','JWT_REFRESH_SECRET='],
  ]}

두 값 중 하나라도 비어 있으면, LibreChat은 임시 자격 증명 파일에서 값을 생성하고 재사용할 수 있습니다. 기본 Docker Compose 스택은 해당 파일을 유지하지만, 이는 부트스트랩 편의를 위한 용도일 뿐입니다. 파일이 손실되거나 기록할 수 없는 경우, 재시작 후 세션이 유효하지 않게 될 수 있습니다. 우선순위, 지속성 및 프로덕션 지침에 대해서는 [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration)을 참조하세요.

## 자동화된 조정 시스템 (선택 사항) [#automated-moderation-system-optional]

자동화된 중재 시스템(Automated Moderation System)은 기본적으로 활성화되어 있습니다. 이 시스템은 점수 매기기 메커니즘을 사용하여 사용자 위반 사항을 추적합니다. 사용자가 과도한 로그인, 등록 또는 메시지 전송과 같은 행동을 하면 위반 점수가 누적됩니다. 설정된 임계값에 도달하면 해당 사용자와 IP는 일시적으로 차단됩니다. 이 시스템은 급격하거나 의심스러운 활동을 모니터링하고 제재함으로써 플랫폼 보안을 보장합니다.

mod system을 설정하려면 [설정 가이드](/docs/configuration/mod_system)를 검토하세요.

> *참고: 개발 모드에서 작동하게 하려면 루트 디렉토리에 `.env.development`라는 파일을 생성하고 `DOMAIN_CLIENT`를 `http://localhost:3090` 또는 `npm run frontend-dev` 실행 시 vite가 제공하는 포트로 설정해야 합니다.*

## 사용자 관리 스크립트 [#user-management-scripts]

### 사용자 스크립트 생성 [#create-user-script]

create-user 스크립트를 사용하면 등록 기능이 비활성화된 경우에도 데이터베이스에 사용자를 직접 추가할 수 있습니다. 사용 방법은 다음과 같습니다:

1. 기본 `docker-compose.yml`의 경우 (앱을 시작하기 위해 `docker compose up`을 사용하는 경우):
   ```bash
   docker compose exec api npm run create-user
   ```

2. `deploy-compose.yml`의 경우 ([Ubuntu Docker 가이드](/docs/remote/docker_linux)를 따랐다면):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. 로컬 개발을 위해 (프로젝트 루트에서):
   ```bash
   npm run create-user
   ```

프롬프트에 따라 새 사용자의 이메일과 비밀번호를 입력하세요.

### 사용자 삭제 스크립트 [#delete-user-script]

사용자를 삭제하려면 delete-user 스크립트를 사용할 수 있습니다:

1. 기본 `docker-compose.yml`의 경우 (앱을 시작하기 위해 `docker compose up`을 사용하는 경우):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. `deploy-compose.yml`의 경우 ([Ubuntu Docker 가이드](/docs/remote/docker_linux)를 따랐다면):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. 로컬 개발을 위해 (프로젝트 루트에서):
   ```bash
   npm run delete-user email@domain.com
   ```

`email@domain.com`을 삭제하려는 사용자의 이메일 주소로 바꾸세요.
