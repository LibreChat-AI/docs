Passkeys ermöglichen es Benutzern mit einem lokalen Konto (E-Mail und Passwort), sich mit der Bildschirmsperre ihres Geräts, einem Passwort-Manager oder einem Hardware-Sicherheitsschlüssel anzumelden, anstatt ein Passwort einzugeben. LibreChat implementiert diese mittels WebAuthn. Sie sind standardmäßig deaktiviert.

Verwenden Sie Passkeys, wenn Sie eine phishing-resistente, passwortlose Anmeldung für lokale Konten wünschen. Konten, die sich über OAuth, OpenID Connect, SAML oder LDAP anmelden, verwenden weiterhin ihren Anbieter und können keine Passkeys hinzufügen.

## Passkeys aktivieren [#enable-passkeys]

<Steps>
<Step>

**Stellen Sie LibreChat über HTTPS bereit.** Browser erlauben WebAuthn nur in einem sicheren Kontext. `http://localhost` ist davon ausgenommen, daher funktioniert lokales Testen auch ohne TLS.

</Step>
<Step>

**Aktiviere die Funktion in der `.env`.** Für eine Standardbereitstellung ist dies die einzige erforderliche Einstellung. Die Relying-Party-ID und die erlaubten Ursprünge (allowed origins) werden von `DOMAIN_CLIENT` und `DOMAIN_SERVER` abgeleitet.

```bash filename=".env"
ALLOW_PASSKEY_LOGIN=true
```

</Step>
<Step>

**Die Relying Party ID festlegen (empfohlen).** Jeder Passkey ist dauerhaft an die RP ID gebunden, unter der er erstellt wurde. Falls sich `DOMAIN_CLIENT` jemals ändern sollte, legen Sie jetzt `PASSKEY_RP_ID` fest, damit bestehende Passkeys weiterhin funktionieren.

```bash filename=".env"
PASSKEY_RP_ID=chat.example.com
```

</Step>
<Step>

**Starten Sie LibreChat neu.** Die Anmeldeseite zeigt **Sign in with a passkey** an, und unter **Settings > Account** wird ein Bereich für **Passkeys** angezeigt.

</Step>
</Steps>

### Benutzerbezogenes Limit in `librechat.yaml` [#per-user-limit-in-librechatyaml]

Sie können das Registrierungslimit auch in `librechat.yaml` festlegen:

```yaml filename="librechat.yaml"
passkeys:
  perUserMax: 10
```

Das Limit wird in dieser Reihenfolge aufgelöst: `passkeys.perUserMax` in `librechat.yaml`, dann `MAX_PASSKEYS_PER_USER`, gefolgt vom Standardwert `20`. Werte außerhalb des Bereichs von `1` bis `100` werden ignoriert und die nächste Quelle wird verwendet. Wenn ein Benutzer das Limit erreicht, wird unter **Einstellungen > Konto** „Sie haben die maximale Anzahl an Passkeys erreicht“ angezeigt. Siehe [`passkeys`](/docs/configuration/librechat_yaml/object_structure/config#passkeys) in der Konfigurationsreferenz.

## Was Benutzer sehen [#what-users-see]

**Hinzufügen eines Passkeys**

1. Öffnen Sie **Settings > Account**, suchen Sie **Passkeys** und wählen Sie **Manage** aus.
2. Wählen Sie **Passkey hinzufügen**.
3. Geben Sie das Kontopasswort im Dialog **Confirm your password** ein. Ein Passkey ist eine eigenständige, vollständige Anmeldung, daher fragt LibreChat vor der Erstellung nach dem Passwort.
4. Schließen Sie die Browser- oder Geräteaufforderung ab. Der neue Hauptschlüssel (Passkey) erscheint in der Liste mit einem Standardnamen wie **Dieses Gerät**, **Telefon oder Tablet** oder **Sicherheitsschlüssel**.

Jeder Eintrag zeigt an, wann er hinzugefügt und zuletzt verwendet wurde, sowie ein **Synced**-Abzeichen, wenn der Authentifikator meldet, dass der Passkey gesichert ist (zum Beispiel durch einen Passwort-Manager). Benutzer können einen Passkey umbenennen, und das Entfernen eines Passkeys (**Remove passkey**) erfordert ebenfalls die Eingabe des Kontopassworts.

**Anmelden**

Auf der Anmeldeseite wählen Benutzer **Sign in with a passkey** aus und bestätigen die Geräteaufforderung. Wenn für das Konto die Zwei-Faktor-Authentifizierung aktiviert ist, fragt LibreChat anschließend dennoch nach dem 2FA-Code, genau wie nach einer Anmeldung mit Passwort.

## Verhalten und Vorbehalte [#behavior-and-caveats]

- **Nur lokale Konten.** Die Registrierung und Anmeldung mit Passkeys ist auf lokale Konten beschränkt. Konten, die über einen Identitätsanbieter oder LDAP erstellt wurden, müssen sich weiterhin über diesen Anbieter authentifizieren.
- **Funktioniert bei deaktivierter E-Mail-Anmeldung.** Die Schaltfläche **Sign in with a passkey** und ihre Routen hängen nur von `ALLOW_PASSKEY_LOGIN` ab. Bei `ALLOW_EMAIL_LOGIN=false` können sich bestehende lokale Benutzer weiterhin mit Passkeys anmelden, die sie zuvor registriert haben.
- **Zwei-Faktor-Authentifizierung.** Die Anmeldung per Passkey durchläuft denselben 2FA-Prozess wie die Anmeldung per Passwort. Mit [`ENFORCE_TWO_FACTOR_AUTHENTICATION=true`](/docs/configuration/authentication#required-two-factor-authentication) wird ein Benutzer, der 2FA noch nicht eingerichtet hat, nach der Anmeldung mit einem Passkey zum Einrichtungsablauf weitergeleitet.
- **Das Ändern der RP ID macht Passkeys unbrauchbar.** Passkeys, die unter einer RP ID erstellt wurden, funktionieren niemals unter einer anderen. Das Ändern von `PASSKEY_RP_ID` oder das Ändern von `DOMAIN_CLIENT`, während `PASSKEY_RP_ID` nicht gesetzt ist, macht jeden bestehenden Passkey unbrauchbar; Benutzer müssen sich auf andere Weise anmelden und erneut registrieren.
- **Ursprünge müssen übereinstimmen.** Wenn Benutzer LibreChat über einen Ursprung erreichen, der nicht von `PASSKEY_ORIGINS` (oder den abgeleiteten Standardwerten) abgedeckt wird, zeigt der Browser „Passkeys are not available on this domain“ an. Fügen Sie jeden öffentlichen Ursprung zu `PASSKEY_ORIGINS` hinzu, wenn Sie LibreChat über mehr als einen Ursprung bereitstellen.
- **Das Zurücksetzen des Passworts entfernt Passkeys.** Ein abgeschlossenes Zurücksetzen des Passworts meldet das Konto überall ab und löscht alle zugehörigen Passkeys, sodass ein vor dem Zurücksetzen registrierter Passkey nicht mehr für die Anmeldung verwendet werden kann. Benutzer müssen sich danach erneut registrieren.
