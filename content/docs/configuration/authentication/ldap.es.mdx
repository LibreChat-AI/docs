Puede utilizar un servidor de autenticación Lightweight Directory Access Protocol (LDAP) para autenticar a los usuarios.

## Configuración del servidor LDAP/AD [#ldapad-server-configuration]

**Configuración básica**

- `LDAP_URL` y `LDAP_USER_SEARCH_BASE` son obligatorios.
- `LDAP_SEARCH_FILTER` es opcional; si no se especifica, se utiliza el atributo `mail` de forma predeterminada. Si se especifica, utilice el literal `{{username}}` para usar el nombre de usuario proporcionado para la búsqueda.

<OptionTable
  options={[
    ['LDAP_URL', 'string', 'URL del servidor LDAP.', 'LDAP_URL=ldap://localhost:389'],
    ['LDAP_BIND_DN', 'string', 'DN de enlace', 'LDAP_BIND_DN=cn=root'],
    ['LDAP_BIND_CREDENTIALS', 'string', 'Contraseña para bindDN', 'LDAP_BIND_CREDENTIALS=password'],
    [
      'LDAP_USER_SEARCH_BASE',
      'string',
      'Base de búsqueda de usuarios LDAP',
      'LDAP_USER_SEARCH_BASE=o=users,o=example.com',
    ],
    ['LDAP_SEARCH_FILTER', 'string', 'Filtro de búsqueda LDAP', 'LDAP_SEARCH_FILTER=mail={{username}}'],
  ]}
/>

**Asignaciones de campos**

Puede especificar una asignación entre los atributos de los usuarios de LibreChat y los de los usuarios de LDAP. Utilice estos ajustes si las asignaciones predeterminadas no funcionan correctamente.

<OptionTable
  options={[

/>

**Nombre de usuario o correo electrónico**

De forma predeterminada, LibreChat utiliza una dirección de correo electrónico y una contraseña para la autenticación.
Esto a veces puede causar problemas con LDAP y es posible que desee utilizar un nombre de usuario en su lugar.
Configure `LDAP_SEARCH_FILTER` para filtrar por el nombre de usuario (por ejemplo, `LDAP_SEARCH_FILTER=uid={{username}}`)
y configure LibreChat para solicitar el inicio de sesión mediante nombre de usuario:

<OptionTable
  options={[
    [
      'LDAP_LOGIN_USES_USERNAME',
      'boolean',
      'Usar nombre de usuario en lugar de correo electrónico.',
      'LDAP_LOGIN_USES_USERNAME=true',
    ],
  ]}
/>

**Active Directory sobre SSL**

Para conectarse mediante SSL (ldaps://), como en una empresa que usa Windows AD, especifique la ruta al certificado de la CA interna con `LDAP_CA_CERT_PATH`.

`LDAP_TLS_REJECT_UNAUTHORIZED` solo se aplica cuando `LDAP_CA_CERT_PATH` está definido. En ese caso, la verificación del certificado está **desactivada** a menos que establezcas explícitamente `LDAP_TLS_REJECT_UNAUTHORIZED=true`. Cuando `LDAP_CA_CERT_PATH` no está definido, LibreChat no pasa ninguna opción TLS y se aplica el comportamiento predeterminado de Node.js (el certificado del servidor se verifica contra el almacén de confianza del sistema).

<Callout type="warning" title="Habilitar la verificación de certificados">
  Si configura `LDAP_CA_CERT_PATH` sin `LDAP_TLS_REJECT_UNAUTHORIZED=true`, LibreChat confía en cualquier certificado presentado por el servidor LDAP, lo que expone las credenciales de enlace y las contraseñas de los usuarios a ataques de tipo "man-in-the-middle". Configure siempre `LDAP_TLS_REJECT_UNAUTHORIZED=true` en producción.
</Callout>

<OptionTable
  options={[
    [
      'LDAP_CA_CERT_PATH',
      'string',
      'Ruta del certificado CA.',
      'LDAP_CA_CERT_PATH=/path/to/root_ca_cert.crt',
    ],
    [
      'LDAP_TLS_REJECT_UNAUTHORIZED',
      'boolean',
      'Verifica el certificado del servidor LDAP con LDAP_CA_CERT_PATH. Debe ser true para habilitar la verificación; se ignora cuando LDAP_CA_CERT_PATH no está definido.',
      'LDAP_TLS_REJECT_UNAUTHORIZED=true',
    ],
  ]}
/>

**LDAP StartTLS**

Habilitar LDAP StartTLS permite a LibreChat actualizar una conexión insegura a una conexión TLS segura. Esto es útil si desea asegurar la conexión sin cambiar a ldaps://.

<OptionTable

            'LDAP_STARTTLS=true',
        ],
    ]}
/>
