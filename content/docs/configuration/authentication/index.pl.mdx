Ustawienie `ALLOW_EMAIL_LOGIN=false` ukrywa formularz logowania przez e-mail i odrzuca żądania poświadczeń lokalnych lub LDAP do `/api/auth/login`; logowanie przez OAuth, OpenID Connect i SAML pozostaje bez zmian. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` jest przeznaczone wyłącznie do kontrolowanej integracji API, która nadal wymaga logowania poświadczeniami, mimo że formularz jest ukryty. Każde użycie obejścia rejestruje adres IP żądania, dlatego należy chronić i monitorować tę ścieżkę z dużą ostrożnością.

Szybkie wskazówki:

- Nawet przy wyłączonej rejestracji możesz dodawać użytkowników bezpośrednio do bazy danych, korzystając ze [skryptu create-user](#create-user-script) opisanego poniżej.
- Aby usunąć użytkownika, możesz użyć [skryptu delete-user](#delete-user-script), który został również szczegółowo opisany poniżej.

Powiązane opcje logowania dla kont lokalnych:

- [Passkeys](/docs/configuration/authentication/passkeys): logowanie bez hasła przy użyciu blokady ekranu urządzenia lub klucza bezpieczeństwa (`ALLOW_PASSKEY_LOGIN`).
- [Zmiana adresu e-mail](/docs/configuration/authentication/email#email-address-change): pozwala użytkownikom na zmianę zarejestrowanego adresu e-mail w sekcji **Ustawienia > Konto** (`ALLOW_EMAIL_CHANGE`, domyślnie włączone).

## Wymagane uwierzytelnianie dwuskładnikowe [#required-two-factor-authentication]

Użytkownicy mogą zawsze samodzielnie włączyć uwierzytelnianie dwuskładnikowe (TOTP) w sekcji **Ustawienia > Konto**. Aby uczynić je obowiązkowym, ustaw:

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**Kogo to dotyczy:** kont lokalnych (e-mail i hasło) oraz kont LDAP. Konta logujące się przez OAuth, OpenID Connect lub SAML nie są objęte tym wymogiem, ponieważ za MFA odpowiada ich dostawca tożsamości. Jeśli konto federacyjne spróbuje zalogować się hasłem przy włączonym wymuszeniu, otrzyma informację, aby skorzystać ze swojego dostawcy tożsamości.

**Co widzą użytkownicy:** użytkownik bez 2FA, który się loguje (za pomocą hasła, danych uwierzytelniających LDAP lub klucza dostępu), nie uzyskuje sesji, dopóki konfiguracja nie zostanie zakończona. Trafia on na ekran **Wymagane uwierzytelnianie dwuskładnikowe** („Twój administrator wymaga uwierzytelniania dwuskładnikowego. Skonfiguruj je przed kontynuowaniem.”), skanuje kod QR za pomocą aplikacji uwierzytelniającej, wprowadza kod w celu weryfikacji i zapisuje swoje kody zapasowe. Użytkownicy, którzy są już zalogowani, zostaną przeniesieni do tej samej konfiguracji przy następnym sprawdzeniu lub odświeżeniu sesji, a tokeny dostępu wydane przed rejestracją przestaną działać. Sesja konfiguracji trwa 10 minut; jeśli wygaśnie, użytkownik wraca do strony logowania i zaczyna od nowa.

**Po rejestracji:** kontrolka **Disable 2FA** w **Settings > Account** wyświetla komunikat **Required by administrator**, a serwer odrzuca próby wyłączenia 2FA, gdy polityka jest aktywna. Użytkownicy mogą nadal generować kody zapasowe.

## JWT Secret i Refresh Secret [#jwt-secret-and-refresh-secret]

Użyj unikalnych wartości o długości co najmniej 32 bajtów. Wygeneruj stałe wartości za pomocą [Credentials Generator](/toolkit/creds_generator), przechowuj je bezpiecznie i podaj te same wartości każdej replice LibreChat.

<OptionTable
  options={[

    ['JWT_REFRESH_SECRET', 'string (hex)', 'Klucz tajny odświeżania JWT.','JWT_REFRESH_SECRET='],
  ]}
/>

Gdy którakolwiek z tych wartości jest pusta, LibreChat może wygenerować i ponownie wykorzystać wartość z tymczasowego pliku poświadczeń. Domyślne stosy Docker Compose utrwalają ten plik, ale służy to jedynie jako wygoda podczas uruchamiania (bootstrap). Jeśli plik zostanie utracony lub nie będzie można go zapisać, sesje mogą stać się nieważne po restarcie. Zobacz [Konfiguracja poświadczeń](/docs/configuration/dotenv#credentials-configuration), aby uzyskać informacje o pierwszeństwie, trwałości i wskazówki dotyczące środowiska produkcyjnego.

## Zautomatyzowany system moderacji (opcjonalnie) [#automated-moderation-system-optional]

Zautomatyzowany system moderacji (Automated Moderation System) jest domyślnie włączony. Wykorzystuje on mechanizm punktacji do śledzenia naruszeń użytkowników. Gdy użytkownicy wykonują działania takie jak nadmierna liczba logowań, rejestracji lub wysyłanie wiadomości, gromadzą punkty naruszeń. Po osiągnięciu określonego progu użytkownik oraz jego adres IP są tymczasowo blokowani. System ten zapewnia bezpieczeństwo platformy poprzez monitorowanie i karanie gwałtownych lub podejrzanych aktywności.

Aby skonfigurować system modów, zapoznaj się z [przewodnikiem konfiguracji](/docs/configuration/mod_system).

> *Uwaga: Jeśli chcesz, aby to działało w trybie deweloperskim, musisz utworzyć plik o nazwie `.env.development` w katalogu głównym i ustawić `DOMAIN_CLIENT` na `http://localhost:3090` lub inny port udostępniony przez vite podczas uruchamiania `npm run frontend-dev`*

## Skrypty zarządzania użytkownikami [#user-management-scripts]

### Utwórz skrypt użytkownika [#create-user-script]

Skrypt create-user umożliwia dodawanie użytkowników bezpośrednio do bazy danych, nawet gdy rejestracja jest wyłączona. Oto jak go użyć:

1. Dla domyślnego `docker-compose.yml` (jeśli używasz `docker compose up`, aby uruchomić aplikację):
   ```bash
   docker compose exec api npm run create-user
   ```

2. Dla `deploy-compose.yml` (jeśli postępowałeś zgodnie z [Przewodnikiem Docker dla Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Do lokalnego programowania (z katalogu głównego projektu):
   ```bash
   npm run create-user
   ```

Postępuj zgodnie z instrukcjami, aby wprowadzić adres e-mail i hasło nowego użytkownika.

### Skrypt usuwania użytkownika [#delete-user-script]

Aby usunąć użytkownika, możesz użyć skryptu delete-user:

1. Dla domyślnego `docker-compose.yml` (jeśli używasz `docker compose up`, aby uruchomić aplikację):
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Dla `deploy-compose.yml` (jeśli postępowałeś zgodnie z [Przewodnikiem Docker dla Ubuntu](/docs/remote/docker_linux)):
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Do lokalnego programowania (z katalogu głównego projektu):
   ```bash
   npm run delete-user email@domain.com
   ```

Zastąp `email@domain.com` adresem e-mail użytkownika, którego chcesz usunąć.
