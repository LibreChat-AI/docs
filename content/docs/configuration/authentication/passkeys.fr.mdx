Les Passkeys permettent aux utilisateurs disposant d'un compte local (e-mail et mot de passe) de se connecter avec le verrouillage d'écran de leur appareil, un gestionnaire de mots de passe ou une clé de sécurité matérielle au lieu de saisir un mot de passe. LibreChat les implémente avec WebAuthn. Ils sont désactivés par défaut.

Utilisez des passkeys lorsque vous souhaitez une connexion sans mot de passe et résistante au hameçonnage pour les comptes locaux. Les comptes qui se connectent via OAuth, OpenID Connect, SAML ou LDAP continuent d'utiliser leur fournisseur et ne peuvent pas ajouter de passkeys.

## Activer les passkeys [#enable-passkeys]

<Steps>
<Step>

**Servez LibreChat via HTTPS.** Les navigateurs n'autorisent WebAuthn que dans un contexte sécurisé. `http://localhost` est exempté, donc les tests locaux fonctionnent sans TLS.

</Step>
<Step>

**Activez la fonctionnalité dans `.env`.** Pour un déploiement standard, il s'agit du seul paramètre requis. L'identifiant de la partie de confiance (relying party ID) et les origines autorisées sont dérivés de `DOMAIN_CLIENT` et `DOMAIN_SERVER`.

```bash filename=".env"
ALLOW_PASSKEY_LOGIN=true
```

</Step>
<Step>

**Épingler l'ID de la partie utilisatrice (recommandé).** Chaque passkey est lié de manière permanente à l'ID de la partie utilisatrice (RP ID) sous lequel il a été créé. Si `DOMAIN_CLIENT` est susceptible de changer, définissez `PASSKEY_RP_ID` dès maintenant afin que les passkeys existants continuent de fonctionner.

```bash filename=".env"
PASSKEY_RP_ID=chat.example.com
```

</Step>
<Step>

**Redémarrez LibreChat.** La page de connexion affiche **Se connecter avec une clé d'accès**, et **Paramètres > Compte** affiche une section **Clés d'accès**.

</Step>
</Steps>

### Limite par utilisateur dans `librechat.yaml` [#per-user-limit-in-librechatyaml]

Vous pouvez également définir la limite d'inscription dans `librechat.yaml` :

```yaml filename="librechat.yaml"
passkeys:
  perUserMax: 10
```

La limite est résolue dans cet ordre : `passkeys.perUserMax` dans `librechat.yaml`, puis `MAX_PASSKEYS_PER_USER`, et enfin la valeur par défaut de `20`. Les valeurs en dehors de la plage `1` à `100` sont ignorées et la source suivante est utilisée. Lorsqu'un utilisateur atteint la limite, **Paramètres > Compte** affiche "You have reached the maximum number of passkeys". Voir [`passkeys`](/docs/configuration/librechat_yaml/object_structure/config#passkeys) dans la référence de configuration.

## Ce que voient les utilisateurs [#what-users-see]

**Ajout d'une clé d'accès**

1. Ouvrez **Settings > Account**, trouvez **Passkeys**, et sélectionnez **Manage**.
2. Sélectionnez **Add passkey**.
3. Saisissez le mot de passe du compte dans la boîte de dialogue **Confirm your password**. Une passkey constitue une connexion complète à elle seule, c'est pourquoi LibreChat demande le mot de passe avant d'en créer une.
4. Terminez l'invite du navigateur ou de l'appareil. La nouvelle clé d'accès apparaît dans la liste avec un nom par défaut tel que **Cet appareil**, **Téléphone ou tablette**, ou **Clé de sécurité**.

Chaque entrée indique quand elle a été ajoutée et utilisée pour la dernière fois, ainsi qu'un badge **Synced** lorsque l'authentificateur signale que la clé d'accès est sauvegardée (par exemple, par un gestionnaire de mots de passe). Les utilisateurs peuvent renommer une clé d'accès, et la suppression d'une clé (**Remove passkey**) demande également le mot de passe du compte.

**Connexion**

Sur la page de connexion, les utilisateurs sélectionnent **Sign in with a passkey** et approuvent l'invite sur l'appareil. Si l'authentification à deux facteurs est activée pour le compte, LibreChat demande toujours le code 2FA par la suite, exactement comme il le fait après une connexion par mot de passe.

## Comportement et mises en garde [#behavior-and-caveats]

- **Comptes locaux uniquement.** L'inscription et la connexion par clé d'accès (passkey) sont limitées aux comptes locaux. Les comptes créés via un fournisseur d'identité ou LDAP doivent continuer à s'authentifier via ce fournisseur.
- **Fonctionne avec la connexion par e-mail désactivée.** Le bouton **Sign in with a passkey** et ses routes dépendent uniquement de `ALLOW_PASSKEY_LOGIN`. Avec `ALLOW_EMAIL_LOGIN=false`, les utilisateurs locaux existants peuvent toujours se connecter avec les passkeys qu'ils ont enregistrés précédemment.
- **Authentification à deux facteurs.** La connexion par clé d'accès (passkey) passe par la même porte d'authentification à deux facteurs (2FA) que la connexion par mot de passe. Avec [`ENFORCE_TWO_FACTOR_AUTHENTICATION=true`](/docs/configuration/authentication#required-two-factor-authentication), un utilisateur qui n'a pas activé la 2FA est redirigé vers le flux de configuration après s'être connecté avec une clé d'accès.
- **Changer l'ID RP rend les passkeys orphelins.** Les passkeys créés sous un ID RP ne fonctionnent jamais sous un autre. Changer `PASSKEY_RP_ID`, ou changer `DOMAIN_CLIENT` alors que `PASSKEY_RP_ID` n'est pas défini, rend tous les passkeys existants inutilisables ; les utilisateurs doivent se connecter par un autre moyen et s'inscrire à nouveau.
- **Les origines doivent correspondre.** Si les utilisateurs accèdent à LibreChat via une origine non couverte par `PASSKEY_ORIGINS` (ou les valeurs par défaut dérivées), le navigateur affichera « Passkeys are not available on this domain ». Ajoutez chaque origine publique à `PASSKEY_ORIGINS` lorsque vous servez LibreChat sur plus d'une origine.
- **La réinitialisation du mot de passe supprime les passkeys.** Une réinitialisation de mot de passe terminée déconnecte le compte partout et supprime toutes ses passkeys ; par conséquent, une passkey enregistrée avant la réinitialisation ne peut plus être utilisée pour se connecter. Les utilisateurs doivent les enregistrer à nouveau par la suite.
