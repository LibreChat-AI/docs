> **Note :** OpenID et SAML ne prennent pas en charge la possibilité de désactiver uniquement l'inscription.

Définir `ALLOW_EMAIL_LOGIN=false` masque le formulaire de connexion par e-mail et rejette les demandes d'identifiants locaux ou LDAP vers `/api/auth/login` ; les connexions OAuth, OpenID Connect et SAML ne sont pas affectées. `ALLOW_EMAIL_LOGIN_OVERRIDE=true` est destiné uniquement à une intégration API contrôlée qui nécessite toujours une connexion par identifiants alors que le formulaire est masqué. Chaque utilisation de la dérogation enregistre l'adresse IP de la requête, veillez donc à protéger et surveiller cette route avec attention.

Astuces rapides :

- Même si l'inscription est désactivée, vous pouvez ajouter des utilisateurs directement dans la base de données en utilisant [le script create-user](#create-user-script) détaillé ci-dessous.
- Pour supprimer un utilisateur, vous pouvez utiliser [le script delete-user](#delete-user-script) également détaillé ci-dessous.

Options de connexion associées pour les comptes locaux :

- [Passkeys](/docs/configuration/authentication/passkeys) : connexion sans mot de passe avec un verrouillage d'écran d'appareil ou une clé de sécurité (`ALLOW_PASSKEY_LOGIN`).
- [Changement d'adresse e-mail](/docs/configuration/authentication/email#email-address-change) : permet aux utilisateurs de modifier leur adresse e-mail enregistrée depuis **Paramètres > Compte** (`ALLOW_EMAIL_CHANGE`, activé par défaut).

## Authentification à deux facteurs requise [#required-two-factor-authentication]

Les utilisateurs peuvent toujours activer eux-mêmes l'authentification à deux facteurs (TOTP) depuis **Settings > Account**. Pour la rendre obligatoire, définissez :

```bash filename=".env"
ENFORCE_TWO_FACTOR_AUTHENTICATION=true
```

**À qui cela s'applique :** aux comptes locaux (e-mail et mot de passe) et LDAP. Les comptes qui se connectent via OAuth, OpenID Connect ou SAML ne sont pas concernés, car leur fournisseur d'identité est responsable de la MFA. Un compte fédéré qui tente de se connecter avec un mot de passe alors que l'application est activée est invité à utiliser son fournisseur d'identité à la place.

**Ce que voient les utilisateurs :** un utilisateur sans 2FA qui se connecte (avec un mot de passe, des identifiants LDAP ou une clé d'accès) n'obtient aucune session tant que la configuration n'est pas terminée. Il est redirigé vers un écran **Authentification à deux facteurs requise** (« Votre administrateur exige une authentification à deux facteurs. Configurez-la avant de continuer. »), scanne un code QR avec une application d'authentification, saisit un code pour vérifier, et enregistre ses codes de secours. Les utilisateurs déjà connectés sont redirigés vers la même configuration lors de la prochaine vérification ou actualisation de leur session, et les jetons d'accès émis avant l'inscription cessent de fonctionner. La session de configuration dure 10 minutes ; si elle expire, l'utilisateur revient à la page de connexion et recommence.

**Après l'inscription :** le contrôle **Désactiver la 2FA** dans **Paramètres > Compte** affiche **Requis par l'administrateur**, et le serveur rejette les tentatives de désactivation de la 2FA tant que la politique est active. Les utilisateurs peuvent toujours régénérer des codes de secours.

## Expiration de session et jeton de rafraîchissement [#session-expiry-and-refresh-token]

- Valeurs par défaut : expiration de la session : 15 minutes, expiration du jeton de rafraîchissement : 7 jours

## JWT Secret et Refresh Secret [#jwt-secret-and-refresh-secret]

Utilisez des valeurs uniques d'au moins 32 octets. Générez des valeurs permanentes avec le [Credentials Generator](/toolkit/creds_generator), stockez-les de manière sécurisée et fournissez les mêmes valeurs à chaque réplique de LibreChat.

<OptionTable
  options={[
    ['JWT_SECRET', 'string (hex)', 'Clé secrète JWT.','JWT_SECRET='],
    ['JWT_REFRESH_SECRET', 'string (hex)', 'Clé secrète de rafraîchissement JWT.','JWT_REFRESH_SECRET='],
  ]}
/>

Lorsque l'une ou l'autre de ces valeurs est vide, LibreChat peut générer et réutiliser une valeur à partir de son fichier d'identifiants temporaires. Les piles Docker Compose par défaut conservent ce fichier, mais cela n'est prévu que comme une commodité d'amorçage. Si le fichier est perdu ou ne peut pas être écrit, les sessions peuvent devenir invalides après un redémarrage. Voir [Credentials Configuration](/docs/configuration/dotenv#credentials-configuration) pour la priorité, la persistance et les conseils de mise en production.

## Système de modération automatisé (optionnel) [#automated-moderation-system-optional]

Le système de modération automatisé est activé par défaut. Il utilise un mécanisme de notation pour suivre les violations des utilisateurs. À mesure que les utilisateurs effectuent des actions telles que des connexions, des inscriptions ou des envois de messages excessifs, ils accumulent des scores de violation. Une fois un seuil défini atteint, l'utilisateur et son adresse IP sont temporairement bannis. Ce système garantit la sécurité de la plateforme en surveillant et en pénalisant les activités rapides ou suspectes.

Pour configurer le système de modération, consultez [le guide de configuration](/docs/configuration/mod_system).

> *Veuillez noter : Si vous souhaitez que cela fonctionne en mode développement, vous devrez créer un fichier nommé `.env.development` dans le répertoire racine et définir `DOMAIN_CLIENT` sur `http://localhost:3090` ou sur le port fourni par vite lors de l'exécution de `npm run frontend-dev`*

## Scripts de gestion des utilisateurs [#user-management-scripts]

### Créer un script utilisateur [#create-user-script]

Le script create-user vous permet d'ajouter des utilisateurs directement dans la base de données, même lorsque l'inscription est désactivée. Voici comment l'utiliser :

1. Pour le `docker-compose.yml` par défaut (si vous utilisez `docker compose up` pour démarrer l'application) :
   ```bash
   docker compose exec api npm run create-user
   ```

2. Pour le `deploy-compose.yml` (si vous avez suivi le [Guide Docker Ubuntu](/docs/remote/docker_linux)) :
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run create-user"
   ```

3. Pour le développement local (depuis la racine du projet) :
   ```bash
   npm run create-user
   ```

Suivez les instructions pour saisir l'e-mail et le mot de passe du nouvel utilisateur.

### Script de suppression d'utilisateur [#delete-user-script]

Pour supprimer un utilisateur, vous pouvez utiliser le script delete-user :

1. Pour le `docker-compose.yml` par défaut (si vous utilisez `docker compose up` pour démarrer l'application) :
   ```bash
   docker compose exec api npm run delete-user email@domain.com
   ```

2. Pour le `deploy-compose.yml` (si vous avez suivi le [Guide Docker Ubuntu](/docs/remote/docker_linux)) :
   ```bash
   docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run delete-user email@domain.com"
   ```

3. Pour le développement local (depuis la racine du projet) :
   ```bash
   npm run delete-user email@domain.com
   ```

Remplacez `email@domain.com` par l'adresse e-mail de l'utilisateur que vous souhaitez supprimer.
