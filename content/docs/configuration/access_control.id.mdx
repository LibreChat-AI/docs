Bagaimana peran, grup, dan berbagi berfungsi bagi pengguna dijelaskan pada halaman fitur [Access Control](/docs/features/access_control). Halaman ini membahas apa yang diatur oleh admin.

## Izin fitur [#feature-permissions]

Setiap peran memiliki satu set sakelar untuk setiap jenis izin. Anda dapat mengubahnya di tiga tempat:

- Di LibreChat, melalui tombol **Admin Settings** pada panel agents, prompts, MCP servers, memories, dan skills (khusus admin).
- Di [Admin Panel](/docs/features/admin_panel), di bawah **Access**, untuk peran apa pun termasuk peran kustom.
- Di dalam blok [`interface`](/docs/configuration/librechat_yaml/object_structure/interface) pada `librechat.yaml`. Kunci-kunci ini hanya menentukan izin dari peran `USER` bawaan saat startup, sehingga tidak dapat menyatakan pengaturan yang berbeda untuk setiap peran kustom.

Tabel ini mencantumkan setiap jenis izin, kunci `interface` yang menjadi sumbernya, tindakannya, dan tindakan mana yang dimiliki oleh peran `USER` secara default.

| Tipe izin | Kunci `interface` | Tindakan | Aktif secara default untuk `USER` |
| --------- | ----------------- | -------- | --------------------------------- |
| `AGENTS` | `agents` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `PROMPTS` | `prompts` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `MCP_SERVERS` | `mcpServers` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC`, `CONFIGURE_OBO` | `USE`, `CREATE` |
| `SKILLS` | `skills` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `REMOTE_AGENTS` | `remoteAgents` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | tidak ada |
| `SHARED_LINKS` | `sharedLinks` | `CREATE`, `SHARE`, `SHARE_PUBLIC` | `CREATE`, `SHARE` |
| `SCHEDULES` | `schedules` | `USE`, `CREATE` | `USE`, `CREATE` |
| `MEMORIES` | `memories` | `USE`, `CREATE`, `UPDATE`, `READ`, `OPT_OUT` | semua |
| `BOOKMARKS` | `bookmarks` | `USE` | `USE` |
| `MULTI_CONVO` | `multiConvo` | `USE` | `USE` |
| `TEMPORARY_CHAT` | `temporaryChat` | `USE` | `USE` |
| `RUN_CODE` | `runCode` | `USE` | `USE` |
| `WEB_SEARCH` | `webSearch` | `USE` | `USE` |
| `FILE_SEARCH` | `fileSearch` | `USE` | `USE` |
| `FILE_CITATIONS` | `fileCitations` | `USE` | `USE` |
| `MARKETPLACE` | `marketplace` | `USE` | tidak ada |
| `PEOPLE_PICKER` | `peoplePicker` | `VIEW_USERS`, `VIEW_GROUPS`, `VIEW_ROLES` | semua |

`SHARE` memungkinkan sebuah peran berbagi dengan pengguna, grup, atau peran tertentu; `SHARE_PUBLIC` memungkinkan peran tersebut berbagi dengan semua orang di instance. `CONFIGURE_OBO` memungkinkan pengaturan pertukaran token On-Behalf-Of pada server MCP, yang meneruskan token terdelegasi milik pengguna ke server tersebut, sehingga fitur ini nonaktif secara default.

## Pemilih orang [#people-picker]

Tindakan `PEOPLE_PICKER` mengontrol jenis principal yang dapat ditemukan oleh suatu peran dalam pencarian pada dialog berbagi. Penyembunyian peran umum dilakukan ketika berbagi berdasarkan peran sebaiknya tetap menjadi tanggung jawab admin:

```yaml filename="librechat.yaml"
interface:
  peoplePicker:
    users: true
    groups: true
    roles: false
```

Ini hanya mengubah apa yang ditampilkan oleh pencarian. Berbagi yang sudah ada dengan tipe prinsipal yang disembunyikan tetap berfungsi. Lihat [`interface.peoplePicker`](/docs/configuration/librechat_yaml/object_structure/interface#peoplepicker).

## Sinkronisasi grup Entra ID [#entra-id-group-sync]

Grup dari Microsoft Entra ID disinkronkan ke LibreChat ketika pengguna masuk melalui OpenID Connect dengan Entra dan `OPENID_REUSE_TOKENS=true`. LibreChat membaca keanggotaan grup pengguna dari Microsoft Graph pada setiap login dan menyimpan setiap grup dengan object ID Entra-nya, sehingga grup yang dibagikan tetap menjadi grup yang sama meskipun namanya diubah. Siapkan penyedia dengan [Azure / Entra ID](/docs/configuration/authentication/OAuth2-OIDC/azure) dan penggunaan ulang token dengan [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse).

## Mempromosikan admin lain [#promote-another-admin]

Dalam deployment single-tenant, akun pertama yang didaftarkan akan mendapatkan peran `ADMIN`. Deployment yang dibatasi per tenant tidak pernah menaikkan pengguna pertamanya; sediakan admin tenant melalui alur administratif tepercaya. Untuk menjadikan pengguna lain yang sudah ada sebagai admin, gunakan halaman **Users** di Admin Panel, atau atur peran secara langsung di MongoDB:

```js filename="mongosh"
db.users.updateOne({ email: 'USER_EMAIL_ADDRESS' }, { $set: { role: 'ADMIN' } })
```

Minta pengguna untuk keluar dan masuk kembali setelahnya. Dengan OpenID Connect, Anda juga dapat menetapkan `ADMIN` dari peran atau grup IdP dengan `OPENID_ADMIN_ROLE`; lihat [referensi .env](/docs/configuration/dotenv#openid-connect).

## Kemampuan admin [#admin-capabilities]

Kapabilitas diberikan kepada pengguna, grup, atau peran dari halaman **Grants** di Admin Panel. Pengguna dengan peran `ADMIN` memiliki semua kapabilitas tersebut secara implisit; pengguna lain memerlukan `access:admin` di samping kapabilitas untuk bagian yang mereka kelola. Setiap kapabilitas `manage:` mencakup kapabilitas `read:` yang sesuai, termasuk per bagian: `manage:configs:endpoints` juga memberikan `read:configs:endpoints`. Seseorang yang hanya memiliki akses konfigurasi terbatas pada bagian tertentu akan menerima respons konfigurasi yang difilter ke bagian-bagian yang dapat mereka baca; tanpa akses baca konfigurasi sama sekali, mereka akan menerima `403`.

| Kemampuan | Mengizinkan |
| ---------- | ------ |
| `access:admin` | Masuk ke Panel Admin |
| `read:users`, `manage:users` | Melihat dan mengubah akun pengguna |
| `read:groups`, `manage:groups` | Melihat dan mengubah grup beserta anggotanya |
| `read:roles`, `manage:roles` | Melihat dan mengubah peran beserta izinnya |
| `read:configs`, `manage:configs` | Melihat dan mengubah konfigurasi; `read:configs:<section>` dan `manage:configs:<section>` membatasinya ke satu bagian tingkat atas `librechat.yaml` |
| `assign:configs:user`, `assign:configs:group`, `assign:configs:role` | Menetapkan penggantian konfigurasi ke jenis prinsipal tersebut |
| `read:agents`, `manage:agents` | Melihat dan memoderasi setiap agen |
| `read:prompts`, `manage:prompts` | Melihat dan memoderasi setiap prompt |
| `read:skills`, `manage:skills` | Melihat dan memoderasi setiap skill |
| `read:sharedlinks`, `manage:sharedlinks` | Melihat dan memoderasi setiap tautan bersama |
| `manage:mcpservers` | Mengelola server MCP di seluruh instans |
| `manage:code_environments` | Mendaftarkan dan mencabut pekerja eksekusi kode yang dimiliki oleh deployment |
| `read:usage` | Melihat data penggunaan |
| `read:insights` | Melihat [Insights](/docs/features/insights) untuk setiap agen |
| `read:audit_log` | Melihat, memverifikasi, dan mengekspor log audit pemberian izin. Log ini bersifat append-only, sehingga tidak ada padanan `manage:`-nya |

`read:assistants` dan `manage:assistants` juga ada tetapi dicadangkan; belum ada yang menegakkannya.

## Cache keanggotaan grup [#group-membership-cache]

Untuk memeriksa izin, LibreChat mencari grup mana saja yang dimiliki seorang pengguna dan menyimpan hasilnya di cache selama lima menit. Perubahan keanggotaan grup akan langsung menghapus entri yang terdampak. Peran pengguna tidak di-cache. Kegagalan cache atau lock akan beralih ke database dan tidak pernah menghalangi pemeriksaan izin.

## Wawasan Admin [#admin-insights]

Dasbor [Insights](/docs/features/insights) nonaktif secara default. Atur `ENABLE_INSIGHTS=true` di `.env` dan mulai ulang LibreChat; selama fitur ini nonaktif, rute Insights akan merespons `404` dan entri sidebar tetap tersembunyi.

Admin dapat membukanya segera setelah fitur ini diaktifkan. Untuk memberi akses kepada pengguna lain, Anda dapat memberikan izin `read:insights` (untuk setiap agen) dari Admin Panel, atau mengaktifkan **View insights** untuk orang atau grup tertentu di dialog berbagi agen. Hanya admin yang dapat memberikan **View insights**, orang tersebut juga harus memiliki akses ke agen itu sendiri, dan izin ini tidak dapat diberikan kepada semua orang. Insights menampilkan nama, alamat email, dan pesan pertama dari percakapan terbaru, jadi berikan izin ini dengan hati-hati.

Setiap kueri Insights dibatasi pada tenant pengguna yang sedang melihat, dan rentang tanggal kustom dibatasi hingga 30 hari.

## Bermigrasi dari versi sebelum ACL [#migrating-from-pre-acl-versions]

Versi sebelum v0.8.0-rc3 menggunakan model kepemilikan yang lebih sederhana untuk agen dan prompt. Setelah melakukan upgrade, jalankan migrasi agar agen dan prompt yang sudah ada tetap dapat diakses; LibreChat akan memberikan peringatan saat startup jika menemukan agen yang belum dimigrasikan. Tautan bersama kemudian dipindahkan ke sistem yang sama, sehingga instance yang memiliki tautan bersama dari sebelum perubahan tersebut juga harus menjalankan migrasi tautan bersama.

Mulai dengan uji coba (dry run) untuk melihat apa yang akan berubah, lalu jalankan migrasi. Varian `:batch` memproses 50 record sekaligus, yang membantu pada database berukuran besar.
