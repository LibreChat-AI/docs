Diese Seite behandelt die Administratorseite von [Artifacts](/docs/features/artifacts). Benutzer aktivieren Artifacts pro Agent im Agent Builder; die Einstellungen hier legen fest, ob diese Option überhaupt verfügbar ist und von wo die Vorschauen geladen werden.

## Artefakte aktivieren [#enabling-artifacts]

Artifacts sind eine Agenten-Funktion. `artifacts` ist in der Standardliste von [`endpoints.agents.capabilities`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) enthalten und daher verfügbar, sofern du keine eigene Liste ohne diesen Eintrag festlegst. Wenn du `capabilities` überschreibst, füge `artifacts` hinzu, damit die Option im Agent Builder erhalten bleibt.

Um Modellspezifikations-Artefakte ohne Erstellung eines Agenten bereitzustellen, setzen Sie [`artifacts`](/docs/configuration/librechat_yaml/object_structure/model_specs#artifacts) in der Spezifikation. `true` verwendet den Standardmodus; Sie können auch einen Modusnamen übergeben: `default`, `shadcnui` oder `custom`.

## Öffnen des Panels in einem neuen Fenster [#opening-the-panel-in-a-new-window]

Das Panel verfügt über eine Schaltfläche **In neuem Fenster öffnen**, mit der es in ein separates Browserfenster verschoben wird. Sie ist standardmäßig aktiviert. Wenn Pop-ups in der Umgebung, in der Ihre Bereitstellung läuft, nicht funktionieren, etwa in einer eingebetteten Webview, deaktivieren Sie sie mit [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking); das angedockte Panel funktioniert weiterhin.

## Content-Security-Policy

LibreChats eigene CSP erlaubt HTTPS-Frames, sodass der Standard-Bundler von CodeSandbox ohne Änderungen geladen wird. Wenn ein Reverse Proxy oder ein CDN vor LibreChat eine strengere `Content-Security-Policy` setzt, erlauben Sie den Bundler-Ursprung in `frame-src`: `https://*.codesandbox.io` für den öffentlichen Bundler oder Ihre eigenen Bundler-URLs, falls Sie selbst hosten. Wenn Sie nur die integrierte Richtlinie von LibreChat erweitern müssen, verwenden Sie `CSP_FRAME_SRC_EXTRA`.

React-Vorschauen laden Tailwind außerdem von `cdn.tailwindcss.com`. Daher muss dieser Host von den Browsern der Benutzer aus erreichbar sein.

## Self-Hosting des Sandpack-Bundlers [#self-hosting-the-sandpack-bundler]

Vorschauen werden von [Sandpack](https://sandpack.codesandbox.io/) gerendert, das standardmäßig seinen Bundler vom öffentlichen CDN von CodeSandbox lädt. Dieses CDN sendet außerdem Nutzungstelemetrie. Für private Netzwerke, Compliance-Anforderungen oder um die Abhängigkeit von einem externen Dienst zu entfernen, [hosten Sie den Bundler selbst](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler).

[LibreChat-AI/codesandbox-client](https://github.com/LibreChat-AI/codesandbox-client) ist ein für LibreChat vorbereiteter Fork, bei dem die Telemetrie-Anfragen entfernt wurden, einschließlich der Container-Images.

LibreChat verwendet zwei Bundler. `SANDPACK_BUNDLER_URL` stellt React-Artefakte bereit, und `SANDPACK_STATIC_BUNDLER_URL` stellt die statische Vorlage bereit, die hinter den Vorschauen für HTML, SVG, Markdown, Code und Office-Dateien steht. Setze beide, wenn du selbst hostest: Ist nur einer gesetzt, werden die anderen Artefakttypen weiterhin über das öffentliche CDN geladen. Beide sind in der [`.env`-Referenz](/docs/configuration/dotenv#artifacts) aufgeführt. Mermaid-Diagramme werden direkt in der Seite gerendert und verwenden keinen der beiden Bundler.

Der Betrieb eines eigenen Bundlers bedeutet, dass Sie für dessen CORS-Einstellungen, Sicherheitsupdates und Hosting-Ressourcen selbst verantwortlich sind. Starten Sie LibreChat nach dem Ändern dieser Variablen neu, da die URLs im Startup-Config an den Browser gesendet werden.
