RAG API lập chỉ mục các tệp do người dùng tải lên và truy xuất các đoạn văn bản liên quan để tăng cường cho các prompt của bạn, giúp LibreChat đưa ra các phản hồi có nhận thức về ngữ cảnh dựa trên tài liệu của bạn. Nó chạy như một dịch vụ FastAPI riêng biệt được hỗ trợ bởi cơ sở dữ liệu PostgreSQL + pgvector.

<Callout type="info" title="Những gì người dùng nhìn thấy">
[Chat với Tệp](/docs/features/rag_api) đề cập đến việc tải lên để tìm kiếm trong tệp, tái sử dụng tệp và tìm kiếm trong tệp trong agents. Trang này đề cập đến việc thiết lập và cấu hình.
</Callout>

## Tính khả dụng [#availability]

Tìm kiếm tệp thông qua RAG API hoạt động trong [Agents](/docs/features/agents) và trong các cuộc trò chuyện thông thường trên mọi endpoint, ngoại trừ Assistants. OpenAI Assistants sử dụng dịch vụ lưu trữ và truy xuất tệp riêng của OpenAI thay thế, và các tệp được tải lên ở đó không thể được đính kèm ở nơi khác.

Người dùng chỉ thấy **Upload for File Search** khi khả năng agent `file_search` được bật (mặc định là bật) và vai trò của họ có quyền File Search ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Docker Quick Start [#docker-quick-start]

Đối với Docker, RAG API đã được cấu hình sẵn trong cả hai tệp `docker-compose.yml` và `deploy-compose.yml` mặc định, bao gồm cả giá trị `RAG_API_URL`. Bạn chỉ cần đảm bảo đang chạy image và các tệp compose mới nhất. Xem [hướng dẫn Cập nhật LibreChat cho Docker](/docs/local/docker#updating-librechat) nếu bạn chưa chắc cách cập nhật.

<Callout type="warning" title="Tệp .env dùng chung">
Với thiết lập Docker mặc định, tệp `.env` được chia sẻ giữa LibreChat và RAG API. Hãy định nghĩa các biến RAG trong cùng tệp đó. Danh sách đầy đủ nằm trong [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

Các tệp `docker-compose.yml` và `deploy-compose.yml` mặc định đặt `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` trên dịch vụ `api`. Các biến môi trường được đặt trên dịch vụ sẽ được ưu tiên hơn tệp `.env`, vì vậy bạn không cần thêm `RAG_API_URL` vào `.env` cho cấu hình đi kèm, và việc đặt giá trị này ở đó không có tác dụng. Để trỏ một triển khai Docker tới một RAG API bên ngoài, hãy ghi đè giá trị trên dịch vụ `api` thay thế, ví dụ đối với một RAG API chạy trên máy chủ Docker:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

Mục `extra_hosts` là cần thiết trên Linux, vì Docker không tự định nghĩa `host.docker.internal`.

Compose tự động nạp `docker-compose.override.yml` chỉ khi dùng `docker-compose.yml` mặc định. Với `deploy-compose.yml`, hãy truyền cả hai tệp: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Bên ngoài Docker, hãy đặt `RAG_API_URL` trong tệp `.env` của bạn.

### Lite so với full image [#lite-vs-full-image]

Docker sử dụng image "lite" của RAG API theo mặc định (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), image này chỉ hỗ trợ các embedding từ xa từ OpenAI hoặc một dịch vụ HuggingFace/Ollama từ xa mà bạn đã cấu hình.

Đối với local embeddings, hãy chuyển đổi image trong file compose sang bản build đầy đủ, `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Hãy thực hiện thay đổi này trong [Docker Compose Override File](/docs/configuration/docker_override) của bạn. Xem `docker-compose.override.yml.example` tại thư mục gốc của dự án để biết ví dụ.

Nếu bạn muốn một tệp compose chỉ bao gồm cơ sở dữ liệu PostgreSQL + pgvector và Python API, hãy xem `rag.yml` tại thư mục gốc của dự án.

### Lưu trữ cơ sở dữ liệu [#database-storage]

Các tệp compose mặc định lưu trữ dữ liệu pgvector/PostgreSQL trong volume `pgdata2` do Docker quản lý. Điều này là có chủ đích: các tệp cơ sở dữ liệu không cần phải chỉnh sửa trực tiếp từ máy chủ (host) và volume được quản lý giúp tránh các vấn đề phổ biến về quyền sở hữu và quyền truy cập. Các tệp mà người dùng có thể chỉnh sửa (tệp tải lên, nhật ký, hình ảnh, dữ liệu MongoDB và cấu hình NGINX) được bind-mount vào các thư mục dự án nơi việc truy cập trực tiếp từ máy chủ là hữu ích.

## Thiết lập cục bộ [#local-setup]

Thiết lập không sử dụng container đòi hỏi thao tác thủ công nhiều hơn. Hãy làm theo các hướng dẫn trong [RAG API repo](https://github.com/LibreChat-AI/rag-api/).

Đặt `RAG_API_URL` trong tệp `.env` của LibreChat thành địa chỉ mà API có thể truy cập được từ thiết lập của bạn. Điều này khác với cấu hình Docker đi kèm, nơi giá trị này đã được thiết lập sẵn trên dịch vụ `api` trong các tệp `docker-compose.yml` và `deploy-compose.yml` mặc định.

## Cấu hình [#configuration]

Thiết lập các tùy chọn RAG API thông qua các biến môi trường trong tệp `.env` mà API có thể truy cập. Hầu hết các tùy chọn này là không bắt buộc, ngoại trừ thông tin xác thực và đường dẫn được yêu cầu bởi nhà cung cấp mà bạn đã chọn. Trong thiết lập mặc định, chỉ cần `RAG_OPENAI_API_KEY` là bắt buộc.

## Cách sử dụng [#usage]

Khi RAG API có thể truy cập được, không cần bật thêm gì khác trong LibreChat. Người dùng tải tệp lên bằng **Upload for File Search**, và mô hình sẽ truy vấn chỉ mục thông qua công cụ `file_search` khi câu hỏi cần đến nó. Nếu `RAG_API_URL` chưa được thiết lập hoặc dịch vụ không hoạt động, các lần tải tệp lên sẽ thất bại; LibreChat ghi cảnh báo khi khởi động nếu không thể kết nối đến kiểm tra tình trạng (health check) của RAG API. Xem [Chat with Files](/docs/features/rag_api) để biết phần dành cho người dùng.

## Khắc phục sự cố [#troubleshooting]

Nếu bạn gặp sự cố khi thiết lập hoặc sử dụng RAG API:

- Xác nhận tất cả các biến môi trường bắt buộc đã được thiết lập chính xác trong tệp `.env` của bạn.
- Hãy đảm bảo rằng cơ sở dữ liệu vector đã được cấu hình và có thể truy cập được.
- Xác minh rằng khóa API OpenAI hoặc thông tin xác thực của nhà cung cấp khác là hợp lệ.
- Kiểm tra cả nhật ký của LibreChat và RAG API để tìm lỗi hoặc cảnh báo.

Nếu sự cố vẫn tiếp diễn, hãy tham khảo tài liệu RAG API hoặc hỏi cộng đồng LibreChat trên GitHub Discussions hoặc Discord.
