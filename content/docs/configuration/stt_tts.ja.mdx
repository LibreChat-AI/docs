## 音声機能の導入 [#speech-introduction]

Speech Configurationには、音声認識（STT）と音声合成（TTS）の両方の設定が、統合された `speech:` セクションの下に含まれています。さらに、ユーザー固有の設定用に新しい `speechTab` メニューが追加されました。

> **関連項目:** YAML設定スキーマの詳細および利用可能なすべてのオプションについては、[Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech)のドキュメントを参照してください。

### 環境変数 [#environment-variables]

クラウドベースのSTT/TTSサービスを使用する場合は、`.env`ファイルにAPIキーを設定する必要があります：

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

これらのキーは、`librechat.yaml` 設定内で `${STT_API_KEY}` および `${TTS_API_KEY}` を使用して参照されます。

### 1サービスにつき1プロバイダー [#one-provider-per-service]

`speech.stt` と `speech.tts` はそれぞれ、最大で1つのプロバイダーブロックしか設定できません。どちらのセクションも省略可能で、省略した場合はそのサービスにブラウザのエンジンが使われます。セクション内に複数のプロバイダーが設定されている場合、リクエストは "Multiple providers are set. Please set only one provider." というエラーで失敗します。

### セルフホストされたエンジンには allowedAddresses エントリが必要です [#self-hosted-engines-need-an-allowedaddresses-entry]

`speech.stt` と `speech.tts` はどちらも `allowedAddresses` リストを受け入れます。アウトバウンドの音声リクエストは、解決されたIPアドレスに対して検証され、プライベート、ループバック、およびリンクローカルアドレス空間への到達がブロックされます。そのため、`localhost`、LANアドレス、または Docker サービス名でホストされているエンジンは、リストに明示的に追加しない限り到達できません。

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

エントリは `host:port` のペアのみで構成されます。スキームやパスは含めず、ポート番号が必須であり、IPv6は `[::1]:8080` のようにブラケットで囲む必要があります。また、IPリテラルはプライベートアドレスである必要があります。OpenAI、Azure、ElevenLabsなどのパブリッククラウドのendpointにはエントリは不要です。このガードはホスト名ではなく解決されたIPに対して機能するため、Private Link、プライベートDNS、またはVPN経由で到達するクラウドのendpointはプライベートアドレス空間に解決されることになり、他のプライベートターゲットと同様に正確な `host:port` をリストに含める必要があります。同じフィールドとルールが `speech.stt` にも適用されます。エントリの完全な形式については、[SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) を参照してください。

## Speech タブ (オプション) [#speech-tab-optional]

`speechTab` メニューでは、会話モードや高度なモードのカスタマイズオプションに加え、STTおよびTTSの詳細設定を行うことができます。ここで設定した内容は、ユーザーのデフォルト設定として適用されます。

組み込みのブラウザ音声を使用する場合は `browser` を、以下で設定するサーバーサイドプロバイダーを使用する場合は `external` を使用してください。互換性のために以前のプロバイダー固有のデフォルト設定も引き続き受け入れられ、それらは `external` に正規化されます。一致する外部サービスが利用できない場合、LibreChat は `browser` にフォールバックします。

例:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` はユーザーが最初に目にする初期値を設定します。各設定は、ユーザーが音声設定タブでいつでも変更可能です。

## STT (Speech-to-Text) [#stt-speech-to-text]

Speech-to-Text (STT) 機能は、話し言葉を書き言葉のテキストに変換します。STT を有効にするには、STT ボタン(送信ボタンの近く)をクリックするか、キーの組み合わせ ++Shift+Alt+L++ を使用して文字起こしを開始します。

### 利用可能なSTTサービス [#available-stt-services]

- **ローカル STT**
  - ブラウザベース
  - Whisper (LocalAIでテスト済み)
- **クラウド STT**
  - OpenAI Whisper
  - Azure Whisper
  - その他のOpenAI互換STTサービス

### ローカルSTTの設定 [#configuring-local-stt]

- #### Browser-based
  セットアップは不要です。音声設定タブの「Speech To Text」スイッチが有効になっていること、およびエンジン設定のドロップダウンで「Browser」が選択されていることを確認してください。

- #### Whisper Local [#whisper-local]
  ローカルのWhisperインスタンスが必要です。

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

`apiKey` フィールドは、ローカルのものを含むすべての OpenAI 互換 STT ブロックで必須です。サーバーがキーを確認しない場合は、任意のプレースホルダー値を使用してください。

### Cloud STTの設定 [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Azure エンドポイントドメインのサポート">
`instanceName` フィールドは、以下の両方の Azure OpenAI ドメイン形式をサポートしています。
- **新しい形式**: `.cognitiveservices.azure.com` (例: `my-instance.cognitiveservices.azure.com`)
- **レガシー形式**: `.openai.azure.com` (例: `my-instance.openai.azure.com`)

完全なドメインまたはインスタンス名のみを指定できます。`.azure.com` を含む完全なドメインを指定した場合は、そのまま使用されます。それ以外の場合は、後方互換性のために従来の `.openai.azure.com` 形式が適用されます。
</Callout>

- #### OpenAI 互換 [#openai-compatible]

OpenAI Whisderのセクションを参照し、必要に応じて`url`と`model`を調整してください。`apiKey`フィールドは引き続き必須です。

例
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

Text-to-Speech (TTS) 機能は、書き込まれたテキストを音声に変換します。さまざまな TTS サービスが利用可能です：

### 利用可能なTTSサービス [#available-tts-services]

- **ローカルTTS**
  - ブラウザベース
  - Piper (LocalAIでテスト済み)
  - Coqui (LocalAIでテスト済み)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - その他のOpenAI/ElevenLabs互換のTTSサービス

`speech.tts.maxInputChars`(デフォルト:20000文字)を超えるテキストは、読み上げの前に切り詰められます。詳細は[Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech)を参照してください。

### ローカルTTSの設定 [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

セットアップは不要です。音声設定タブの「Text To Speech」スイッチが有効になっていること、およびエンジン設定のドロップダウンで「Browser」が選択されていることを確認してください。

- #### Piper [#piper]

ローカルのPiperインスタンスが必要です。

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

ローカルのCoquiインスタンスが必要です。

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Cloud TTSの設定 [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Azure エンドポイントドメインのサポート">
`instanceName` フィールドは、以下の両方の Azure OpenAI ドメイン形式をサポートしています。
- **新しい形式**: `.cognitiveservices.azure.com` (例: `my-instance.cognitiveservices.azure.com`)
- **レガシー形式**: `.openai.azure.com` (例: `my-instance.openai.azure.com`)

完全なドメインまたはインスタンス名のみを指定できます。`.azure.com` を含む完全なドメインを指定した場合は、そのまま使用されます。それ以外の場合は、後方互換性のために従来の `.openai.azure.com` 形式が適用されます。
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

ElevenLabs固有の追加パラメータは、以下のように追加できます：

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### OpenAI 互換 [#openai-compatible-1]

OpenAI TTSセクションを参照し、必要に応じて `url` 変数を調整してください。

例:

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### ElevenLabs 互換 [#elevenlabs-compatible]

ElevenLabs セクションを参照し、必要に応じて `url` 変数を調整してください。

例:

```yaml
speech:
  tts:
    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```
