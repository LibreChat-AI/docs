## v0.8.9-rc1 준비하기 [#preparing-for-v089-rc1]

로컬 설치 시 Node.js **24.22.1**을 사용하세요. 버전을 변경하기 전에 MongoDB, `librechat.yaml`, 그리고 암호화 자격 증명을 백업하세요. `CREDS_KEY`와 `CREDS_IV`는 유지하세요. 이를 교체하는 것은 마이그레이션이 아닙니다. 구성 `1.3.18`은 이 후보 버전을 설명하며, 추가된 설정은 [구성 변경 로그](/changelog/config_v1.3.18)를 참조하세요.

모든 LibreChat API 레플리카를 업그레이드한 후에 이전 레플리카가 적용할 수 없는 기능을 활성화하십시오. 호환되는 클라이언트, Code API 서비스, 연결된 워커는 별도로 업데이트하십시오. LibreChat 이미지는 독립적으로 배포된 Code API나 설치된 언어 패키지를 업그레이드하지 않습니다.

### 혼합 버전 호환성 [#mixed-version-compatibility]

| 표면 | 호환되지 않는 레플리카 또는 클라이언트가 남아 있는 동안 | 롤아웃 이후 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 저장된 사용자 자격 증명 | 모든 레플리카의 배포 YAML에서 `credentials.writeFormat: legacy`를 설정합니다. | 재정의를 제거하여 값마다 무작위 IV를 사용하는 `v3` 쓰기를 사용합니다. 두 형식 모두 이 릴리스에서 계속 읽을 수 있습니다. |
| 2단계 인증 백업 코드 | 이전 백엔드나 클라이언트가 강력한 코드를 읽을 수 없는 경우, 모든 레플리카에서 `TWO_FACTOR_BACKUP_CODE_FORMAT=legacy`를 설정합니다. | 제거하면 128비트 무작위, 개별적으로 솔트 처리된 코드가 발급됩니다. 기존 레거시 코드는 다시 생성될 때까지 계속 유효합니다. |
| 이메일 주소 변경 | `emailChange.enabled: false` 또는 `ALLOW_EMAIL_CHANGE=false`를 설정합니다. YAML 플래그가 우선합니다. | 모든 노드가 주소에 바인딩된 비밀번호 재설정 링크를 지원한 이후에만 활성화합니다. 그렇지 않으면 이전 노드가 발급한 링크가 이메일 변경 이후에도 유효할 수 있습니다. |
| 채팅별 머신 선택 | `CODE_ENVIRONMENT_DECISION_VERSION=0` 또는 `endpoints.agents.statefulCodeSessions.allowEnvironmentSelection: false`를 설정합니다. | 결정 프로토콜 v1과 머신 선택은 기본적으로 활성화되지만, 명시적인 머신 허용 목록이 있는 에이전트만 선택지를 제공할 수 있습니다. |
| 저장된 채팅의 워크스페이스 변경 | `statefulCodeSessions.conversationMoves.enabled`를 꺼 둡니다. `allowAttachDetach`는 별도의 옵트인 설정입니다. | 모든 API 레플리카와 호환되는 Code API/워커에서 프로토콜 v1을 사용할 때만 활성화합니다. 이후 클라이언트를 새로 고칩니다. |
| 기억된 도구 승인 | `endpoints.agents.toolApproval.agentModes: false`를 유지합니다. | 모든 레플리카가 해당 모드를 지원한 후 명시적으로 옵트인합니다. 관리자의 확인/거부 규칙은 계속 우선 적용됩니다. |
| 일괄 처리된 백그라운드 완료 | 이전 레플리카가 트래픽을 처리하는 동안 `endpoints.agents.backgroundTasks.completionReceiptBatching: false`를 설정합니다. | 재정의를 제거하면 준비된 결과를 함께 전달합니다. |
| 실행 중인 채팅 이름 변경 | 이전 제목 생성 작업이 모두 처리될 때까지 `interface.runningChatRename: false`를 설정합니다. | 재정의를 제거하면 실행 중이거나 임시 제목이 붙은 채팅의 이름을 변경할 수 있습니다. |

쓰기 형식 스위치를 되돌린다고 해서 이미 저장된 데이터가 변환되지는 않습니다. 이전 릴리스는 v3 형식으로 저장된 자격 증명이나 새로 발급된 강력한 백업 코드를 읽을 수 없습니다. 롤백하기 전에 암호화 키를 교체하는 대신, 호환되지 않는 데이터를 의도적으로 교체하거나 마이그레이션하십시오.

### 인증 및 보안 정책 [#authentication-and-security-policy]

[Passkey 로그인](/docs/configuration/authentication)은 `ALLOW_PASSKEY_LOGIN=true`를 통해 선택적으로 활성화하며, 프로덕션 환경에서는 HTTPS가 필요합니다. 등록 정보가 무효화되지 않도록 Relying Party ID를 일정하게 유지하세요. `PASSKEY_RP_ID`를 변경하면 기존 등록이 무효화될 수 있습니다. `passkeys.perUserMax`는 `MAX_PASSKEYS_PER_USER`보다 우선 적용되며, 기본값은 20입니다.

`ENFORCE_TWO_FACTOR_AUTHENTICATION`의 기본값은 `false`입니다. 이 값을 활성화하면 이메일/비밀번호 및 LDAP 계정은 전체 세션을 받기 전에 반드시 등록을 완료해야 합니다. 연합(federated) 공급자는 자체 MFA를 계속 담당합니다. 임시 코드 시도 한도(`TWO_FACTOR_TEMP_MAX`, `TWO_FACTOR_TEMP_WINDOW`)는 설정 단계 시도 한도(`TWO_FACTOR_SETUP_MAX`, `TWO_FACTOR_SETUP_WINDOW`)와 별도로 관리됩니다.

시스템 권한 부여(system-grant) 할당과 리소스 공유 범위를 넓히는 변경은 변경 전 감사(audit) 기록 쓰기가 실패하면 기본적으로 fail closed(안전하게 차단)됩니다. 폐기(revocation)는 감사 장애에 의해 차단되지 않습니다. `AUDIT_LOG_FAIL_CLOSED=false`를 설정할 때에만 이러한 기본 보호 동작이 비활성화됩니다. 그 밖의 관리자 변경 작업은 작업별로 정의된 감사 순서를 따르므로, 감사 오류가 항상 롤백을 의미하는 것은 아닙니다.

### 관리자 설정 및 시크릿 [#admin-configuration-and-secrets]

활성 데이터베이스 Base 프로필은 Base의 숫자 우선순위와 관계없이 배포 YAML보다 먼저 적용되며, 역할, 그룹, 사용자 프로필보다도 우선합니다. 그 밖의 활성 프로필은 오름차순 우선순위에 따라 병합되며, 우선순위가 같은 경우에도 결정적인 순서로 처리됩니다. 재정의를 제거하면 상속이 복원되고, 툼스톤(tombstone)은 상속된 값을 숨깁니다. 일반 배열은 전체가 숨겨지며, 지원되는 키 기반 컬렉션에서는 이름이 지정된 개별 항목만 숨길 수도 있습니다. 해당 툼스톤을 제거하면 상속이 다시 복원됩니다.

관리자 설정 `changes` 엔드포인트는 하나의 프로필에 대한 일괄 변경 사항을 원자적으로 적용합니다. `dryRun`을 사용하여 검증하고, `expectedRevision`을 사용하여 낙관적 동시성을 제어합니다. 리비전이 오래된 경우 `409`를 반환합니다. 보호된 설정은 전체 일괄 처리를 거부하지 않고 적용되지 않은 상태로 남을 수 있으므로, 무시된 결과를 반드시 확인하세요. 이 보장은 역할 이름 변경이나 기타 여러 문서에 걸친 관리자 작업을 원자적으로 만들지는 않습니다.

관리자가 작성한 `${ENV_VAR}` 참조는 배포 YAML에서 참조된 이름, 내장 엔드포인트 자격 증명, 그리고 `CONFIG_OVERRIDE_ENV_ALLOWLIST`(쉼표 또는 공백으로 구분)에 포함된 이름으로만 제한됩니다. 허용되지 않은 참조는 저장 시 거부되며, 런타임에는 아무 값으로도 확인되지 않습니다. Vertex AI 재정의는 더 엄격하게 적용됩니다. `endpoints.anthropic.vertex`는 배포 YAML의 Vertex 구성 자체에서 참조된 환경 변수 이름만 사용할 수 있으며, 일반 허용 목록에 있는 다른 이름은 사용할 수 없습니다. `interface`, `modelSpecs`, 엔드포인트 제목/활동/추론 레이블 프롬프트, 요약 프롬프트, 메모리 지침, Firecrawl 변경 추적 프롬프트에서 사용되는 텍스트는 그대로 사용되므로 이 제한의 적용을 받지 않습니다.

저장된 웹 검색, MCP, Azure 자격 증명은 해당 대상(destination)에 바인딩됩니다. 바인딩된 대상을 변경하거나 제거하는 쓰기 작업은 같은 쓰기 요청에서 저장된 키를 다시 입력하거나, 키를 함께 제거해야 합니다. `secret_reentry_required`를 처리할 때는 필요한 비밀 값을 다시 입력받아야 하며, 이전 키를 새 URL에 대해 조용히 재시도해서는 안 됩니다. 환경이 소유한 자격 증명과 사용자가 소유한 자격 증명은 관리자 프로필을 통해 다른 대상으로 리디렉션할 수 없습니다.

`CONFIG_REDERIVE_ENDPOINTS`는 이번 릴리스에서 기본적으로 꺼져 있습니다. Azure 그룹의 프로필 재정의, `endpoints.anthropic.vertex`, 그리고 Azure Assistants 스위치는 저장된 상태로 남아 있지만, 운영자가 이를 활성화하기 전까지는 아무런 효과가 없습니다. 이 기능을 모든 레플리카에서 활성화하기 전에, 영향을 받는 프로필과 해결할 수 없는 그룹에 대한 시작 진단 정보를 검토하십시오. 프로필의 Vertex 설정은 배포 YAML에서 Vertex가 구성된 경우에만 적용되며, 이때 배포가 소유한 키 파일과 리전을 사용합니다.

사용자 지정 역할의 이름을 변경하면 해당 역할의 구성원, 구성 프로필, 권한 부여, ACL 항목이 같은 테넌트 안에서 함께 이동합니다. 역할을 삭제하면 구성원은 `USER`로 재할당되고, 종속된 구성과 권한 부여는 제거됩니다. 이러한 여러 문서에 걸친 변경은 하나의 원자적 트랜잭션으로 처리되지 않습니다. 실패한 후에는 재시도하기 전에 현재 상태를 먼저 확인하십시오. 이미 취소된 접근 권한은 취소된 상태로 남아 있을 수 있습니다.

### 엄격한 테넌트 인증 [#strict-tenant-authentication]

`TENANT_ISOLATION_STRICT=true`일 때, 인증 및 계정 라우트는 사용자를 조회하기 전에 실제 시스템이 아닌 유효한 테넌트가 필요합니다. 테넌트 컨텍스트가 없으면 `403`과 `TENANT_CONTEXT_REQUIRED`로 요청이 거부되며, OAuth 플로우는 실패 리디렉션을 사용합니다. 로그인 및 토큰 갱신 라우트를 포함하여 테넌트 라우팅을 신뢰할 수 있는 프록시 또는 인증 경계에서 검증하십시오. strict isolation을 비활성화하거나 임의의 공개 헤더를 신뢰하는 방식으로 테넌트 누락을 우회하지 마십시오.

배포 전체에 걸친 시작 시 점검, 인덱스 동기화, 권한 마이그레이션은 명시적인 시스템 범위에서 실행됩니다. 마이그레이션이 리소스를 기록할 때는 해당 리소스의 테넌트 파티션을 유지합니다. 이러한 점검은 일반 인증 요청에 시스템 테넌트 대체(fallback)를 허용하지 않습니다.

### 공유 패키지 호환성 [#shared-package-compatibility]

공유 패키지가 새로 갱신되어 Zod 4를 사용합니다. LibreChat 스키마를 가져와 조합하는 커스텀 통합은 Zod 사용 방식을 업데이트하고, 일치하는 패키지 버전에 맞춰 다시 빌드해야 합니다. 이러한 패키지를 Zod 3으로 다시 덮어쓰지 마십시오. 이번 릴리스는 생략된 선택적 구성 필드와 검증 진단 정보를 그대로 유지하며, 라이브러리 마이그레이션을 위해 새로운 YAML 버전 증가나 전체 구성 재작성은 필요하지 않습니다.

커스텀 프론트엔드에서 제거된 레거시 `@librechat/client` 컨트롤을 가져오는 경우, 유지 관리되는 컨트롤로 마이그레이션해야 합니다. 특히 `Select`, `SelectDropDown`, `Dialog`, `DialogTemplate`, 그리고 Radix `DropdownMenu` 내보내기는 더 이상 제공되지 않습니다. 대화상자에는 `OGDialog`/`OGDialogTemplate`을, 단일 값 선택기에는 `Dropdown`을, 작업 메뉴에는 `DropdownPopup` 또는 Ariakit 기본 요소를 사용하십시오. LibreChat 자체의 호출 코드는 이미 마이그레이션되었습니다. 이는 개발자 통합 변경 사항이며, 자체 호스팅 배포의 설정을 다시 작성해야 한다는 요구 사항은 아닙니다.

### 브라우저 텔레메트리 [#browser-telemetry]

RUM, 클라이언트 로그, 세션 리플레이는 각각 독립적으로 활성화하는 옵트인 기능입니다. YAML의 `telemetry.rum.enabled`와 `telemetry.rum.sessionReplay.enabled`는 환경 변수 대체 설정보다 우선합니다. 해당 키를 생략하면 환경 설정이 그대로 유지되며, 빈 YAML `sessionReplay: {}`는 세션 리플레이를 비활성화합니다.

- `RUM_CLIENT_LOGS=true`는 인증된 프록시 모드에서만 민감 정보가 제거된(scrubbed) 클라이언트 진단 로그를 활성화합니다.
- `RUM_SESSION_REPLAY_ENABLED=true`는 RUM이 활성화된 경우 리플레이를 사용하도록 설정합니다. 이 설정은 더 이상 사용되지 않는(deprecated) 반대 의미의 `RUM_DISABLE_REPLAY` 폴백을 대체합니다.
- `RUM_PROXY_BODY_LIMIT`의 기본값은 `3mb`입니다. 트레이스와 로그는 인증된 사용자 예산을 공유합니다: `RUM_PROXY_USER_WINDOW=1`분당 `RUM_PROXY_USER_MAX=240`입니다. 초과된 요청은 `429`를 반환합니다.
- Replay는 텍스트와 입력 값을 마스킹하고 인증 화면을 제외하지만, **범용 DLP(데이터 유출 방지) 기능은 아닙니다**. 실제 사용자를 녹화하기 전에 합성 데이터로 검증하십시오. 공개 토큰을 통한 직접 수집은 서버의 Replay 필터링을 우회하므로, 별도의 수집기 정책이 필요합니다.

`LOG_REDACTION_MAX_NODES=5000`은 서버 로그 레코드 하나당 수행되는 마스킹 작업량을 제한합니다. 객체와 문자열은 길이에 따라 가중치가 부여되며 이 예산을 소모합니다. 예산을 초과하는 필드는 마스킹 없이 내보내지 않고 대체됩니다. 이 프로세스 수준 설정은 로거가 초기화될 때 읽힙니다.

### 연결된 코딩 및 MCP 앱 [#connected-coding-and-mcp-apps]

Stateful Code 세션은 여전히 매우 실험적인 기능입니다. 브라우저에서 승인된 등록(enrollment)만으로는 모든 에이전트가 머신에 접근할 수 있는 권한이 부여되지 않습니다. 연결된 환경을 구성하고, principal-worker 등록 및 별도의 `browserSetup.enabled` 옵트인(opt-in)을 활성화하고, 표준 공개 `instance`를 설정하고, 호환되는 워커를 시작한 다음, 에이전트의 명시적인 머신 허용 목록(allowlist)을 저장하십시오. 새 채팅에서는 해당 허용 목록에서만 선택할 수 있으며, 기존 대화는 기록된 결정을 그대로 유지합니다.

선택 사항인 `endpoints.agents.pullRequests` 연동을 사용하려면 git 상태를 보고하는 호환 워커, `CODEAPI_BRIDGE_LANE_GIT=true` 설정의 Code API, 저장소 범위, 그리고 적절한 범위로 지정된 제공자 토큰이 필요합니다. GitHub는 Pull requests, Checks, Contents에 대한 읽기 전용 접근 권한이 필요합니다. GitLab과 Bitbucket은 각 제공자별 자격 증명을 사용합니다. 사용자별 OAuth 연결은 별도로 명시적으로 활성화해야 하는 옵션입니다.

새로운 MCP 앱을 사용하려면 `mcpSettings.apps: true`가 필요합니다. 이 설정을 생략하면 기존의 인라인 HTML 동작이 유지되며, `false`로 설정하면 두 기능이 모두 비활성화됩니다. MCP 앱 샌드박스는 `/api/mcp/sandbox`로 라우팅되는 전용 오리진(origin)에 배포하세요. 배포 샌드박스 정책은 역할(role), 그룹(group), 사용자(user) 단위의 재정의가 아닙니다. 샌드박스 오리진 및 빌드 시점 설정은 [MCP 구성 가이드](/docs/configuration/librechat_yaml/object_structure/mcp_settings)를 참고하여 적용하세요.

### 파일 정리 롤아웃 [#file-cleanup-rollout]

`fileConfig.retainedFileCleanup`은 기본적으로 꺼져 있습니다. 모든 레플리카와 롤백 대상이 보관된 파일 대상을 지원한 이후에만 활성화하십시오. 벡터 정리에는 `fileConfig.vectorOwnershipTrackingStart`도 필요합니다. 이 값은 레거시 벡터 작성자와 롤백 대상이 모두 퇴역한 후에 선택한 UTC 기준 시점이며, 해당 시점 이후 파일에 대한 소유권 증명이 완전히 기록되어 있어야 합니다. 삭제를 진행시키기 위해 기준 시점을 과거로 되돌리거나 과거 파일의 소유권을 추정하지 마십시오.

모호하거나 컷오프 이전의 기록은 실패 시 안전하게 차단(fail closed)됩니다. 보조 정리가 확인될 때까지 기본 파일은 계속 읽을 수 있는 상태로 유지됩니다. `fileConfig.vectorDeletionConcurrency`의 기본값은 `4`이며, 파일당 `1`–`16`개의 네임스페이스 삭제를 허용합니다. 이 설정을 활성화하기 전에 [파일 정리 제어](/docs/configuration/librechat_yaml/object_structure/file_config#retained-file-and-vector-cleanup)를 참고하세요.

### 그 밖에 변경된 기본값 [#other-changed-defaults]

- 기본적으로 Enter 키를 누르면 메시지가 전송됩니다. 사용자는 설정에서 이 옵션을 변경할 수 있습니다.
- 브라우저 이미지 리사이징은 `fileConfig.clientImageResize.enabled`를 생략하면 기본적으로 활성화됩니다. 명시적으로 `true` 또는 `false`를 설정하면 배포 전체에 대한 선택이 강제 적용됩니다.
- `interface.retentionMode: ephemeral`는 모든 채팅을 임시 채팅으로 강제합니다. `temporary`로 되돌리기 전에, 더 이상 만료되지 않아야 하는 레코드의 보관 기한을 제거하십시오. 기존 보관 기한은 자동으로 마이그레이션되지 않습니다.
- 임시 채팅(일회성 모드 채팅 포함)은 `langfuse.trace.temporaryChats`가 활성화되지 않는 한 추적되거나 피드백 점수가 매겨지지 않습니다.
- `interface.historyCacheTtlMs`의 기본값은 `60000`이고, `historyCacheRecent`의 기본값은 `1`입니다. 추가로 `historyCacheMaxBytes` 예산은 `8388608`바이트로, 최근에 벗어난 대화 기록이 캐시에 머무는 기간을 제한합니다.
- `toolCallPreviews`는 미리보기를 요청하는 클라이언트에 대해 기본적으로 제한된 미리보기를 사용합니다. `outputChars`와 `argsChars`의 기본값은 `512`입니다. 내보내기 및 미리보기를 요청하지 않는 클라이언트는 전체 내용을 그대로 유지합니다.

기존 옵션은 [인터페이스 레퍼런스](/docs/configuration/librechat_yaml/object_structure/interface), [에이전트 레퍼런스](/docs/configuration/librechat_yaml/object_structure/agents), 그리고 [환경 변수 레퍼런스](/docs/configuration/dotenv)를 참고하세요.
