Selamat datang di panduan komprehensif untuk mengonfigurasi lingkungan aplikasi Anda dengan file `.env`. Dokumen ini adalah sumber daya lengkap Anda untuk memahami dan menyesuaikan variabel lingkungan yang akan membentuk perilaku aplikasi Anda dalam berbagai konteks.

Meskipun pengaturan default menyediakan fondasi yang kuat untuk instalasi `docker` standar, mendalami panduan ini akan mengungkap potensi penuh LibreChat. Panduan ini memberdayakan Anda untuk menyesuaikan LibreChat dengan kebutuhan spesifik Anda. Temukan cara mengatur ketersediaan model bahasa, mengintegrasikan login sosial, mengelola sistem moderasi otomatis, dan banyak lagi. Semuanya bertujuan untuk memberikan Anda kendali dalam menyempurnakan LibreChat demi pengalaman pengguna yang optimal.

> **Pengingat: Harap mulai ulang LibreChat agar perubahan konfigurasi diterapkan**

Sebagai alternatif, Anda dapat membuat file baru bernama `docker-compose.override.yml` di direktori yang sama dengan file utama `docker-compose.yml` untuk LibreChat, di mana Anda dapat mengatur variabel .env sesuai kebutuhan di bawah `environment`, atau memodifikasi konfigurasi default yang disediakan oleh `docker-compose.yml` utama, tanpa perlu mengedit secara langsung atau menduplikasi seluruh file tersebut.

### Batas Waktu Server HTTP [#http-server-timeouts]

Nilai-nilai opsional ini mengonfigurasi server HTTP Node.js. Biarkan tidak disetel untuk mempertahankan pengaturan default Node. Nilai `0` akan menonaktifkan batas waktu tersebut.

      '# HTTP_KEEP_ALIVE_TIMEOUT_MS=70000',
    ],
    [
      'HTTP_KEEP_ALIVE_TIMEOUT_BUFFER_MS',
      'integer',
      'Buffer batas waktu soket tambahan dalam milidetik. Default Node: 1000.',
      '# HTTP_KEEP_ALIVE_TIMEOUT_BUFFER_MS=5000',
    ],
    [
      'HTTP_HEADERS_TIMEOUT_MS',
      'integer',
      'Waktu yang diizinkan untuk menerima header permintaan lengkap. Default Node: 60000.',
      '# HTTP_HEADERS_TIMEOUT_MS=80000',
    ],
    [
      'HTTP_REQUEST_TIMEOUT_MS',
      'integer',
      'Waktu yang diizinkan untuk menerima permintaan lengkap. Default Node: 300000.',
      '# HTTP_REQUEST_TIMEOUT_MS=300000',
    ],

Nilai harus berupa bilangan bulat aman non-negatif; nilai yang tidak valid akan diabaikan. Ketika batas waktu header dan permintaan diaktifkan, LibreChat akan membatasi batas waktu header agar tidak melebihi batas waktu permintaan jika nilainya lebih tinggi. Node memeriksa kedaluwarsa header dan permintaan pada pemindaian koneksi 30 detik, sehingga nilai di bawah `30000` tidak diberlakukan dengan presisi milidetik yang tepat. Bun saat ini menerima pengaturan ini tetapi tidak memberlakukannya; LibreChat mencatat peringatan saat server API berjalan di bawah Bun.

### Trust proxy [#trust-proxy]

Gunakan alamat yang paling banyak berjarak n lompatan dari aplikasi Express.
req.socket.remoteAddress adalah lompatan pertama, dan sisanya dicari di header X-Forwarded-For dari kanan ke kiri.
Nilai 0 berarti alamat pertama yang tidak tepercaya adalah req.socket.remoteAddress, yaitu tidak ada reverse proxy.
Variabel lingkungan `TRUST_PROXY` secara default diatur ke `1`.

Lihat [Express.js - trust proxy](https://expressjs.com/en/guide/behind-proxies.html) untuk informasi lebih lanjut mengenai hal ini.

<OptionTable
  options={[['TRUST_PROXY', 'number', 'Menentukan jumlah hop.', 'TRUST_PROXY=1']]}
/>

### Header Tenant Terpercaya [#trusted-tenant-header]

`TRUST_TENANT_HEADER` mengontrol apakah LibreChat menerima `X-Tenant-Id` sebelum autentikasi pada *tree* rute `/oauth`, `/api/auth`, dan `/api/share`. Fitur ini dinonaktifkan secara *default*; saat dinonaktifkan, rute-rute tersebut akan mengabaikan *header* tersebut.

<OptionTable
  options={[
    [
      'TRUST_TENANT_HEADER',
      'boolean',
      'Percayai X-Tenant-Id pada rute pra-autentikasi. Aktifkan hanya di balik proksi tepercaya yang menggantikan nilai yang diberikan klien.',
      'TRUST_TENANT_HEADER=false',
    ],
  ]}
/>

<Callout type="warning" title="Jangan percaya header tenant yang disediakan klien">
  Aktifkan pengaturan ini hanya jika reverse proxy tepercaya menghapus setiap nilai `X-Tenant-Id` yang masuk dan menetapkan ID tenant yang otoritatif itu sendiri. Jika tidak, klien yang tidak tepercaya dapat memilih konteks tenant yang digunakan sebelum autentikasi. LibreChat mencatat peringatan keamanan saat pengaturan ini diaktifkan.
</Callout>

Ketika `TENANT_ISOLATION_STRICT` diaktifkan tetapi `TRUST_TENANT_HEADER` dinonaktifkan, LibreChat akan memberikan peringatan saat startup bahwa header tenant pra-autentikasi akan diabaikan.

### Konfigurasi Kredensial [#credentials-configuration]

LibreChat menggunakan `CREDS_KEY` dan `CREDS_IV` untuk mengenkripsi kredensial yang didukung yang disimpan di dalam basis data. Konfigurasikan nilai yang tetap dan unik untuk produksi serta gunakan nilai yang sama di setiap replika.

<OptionTable
  options={[
    [
      'CREDS_KEY',
      'string',
      'Kunci 32-byte (64 karakter heksadesimal) untuk menyimpan kredensial secara aman.',
      'CREDS_KEY=',
    ],
    [
      'CREDS_IV',
      'string',
      'IV 16-byte (32 karakter heksadesimal) untuk menyimpan kredensial secara aman.',
      'CREDS_IV=',
    ],
    [
      'LIBRECHAT_TEMP_CREDENTIALS_PATH',
      'string',
      'Jalur yang digunakan untuk menyimpan kredensial sementara yang dibuat secara otomatis. Defaultnya adalah `.env.temp` di direktori kerja proses.',
      '# LIBRECHAT_TEMP_CREDENTIALS_PATH=/app/data/.env.temp',
    ],
  ]}
/>

Ketika salah satu dari `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, atau `JWT_REFRESH_SECRET` kosong, LibreChat akan terlebih dahulu menggunakan kembali nilai yang valid dari file kredensial sementara. Jika tidak ada, LibreChat akan menghasilkan nilai acak secara kriptografis dan menulis file tersebut dengan izin akses hanya untuk pemilik. Nilai lingkungan (environment) yang eksplisit akan selalu diutamakan. LibreChat menolak untuk menggunakan `.env` atau `.env.example` sebagai jalur file yang dihasilkan, guna mencegah penggantian yang tidak disengaja pada salah satu file konfigurasi tersebut.

LibreChat juga menolak untuk memulai ketika `JWT_SECRET` atau `JWT_REFRESH_SECRET` masih menggunakan salah satu nilai default yang sudah tidak digunakan lagi, baik nilai tersebut berasal dari environment maupun file kredensial sementara. Hasilkan pengganti yang unik alih-alih membawa contoh secret lama ke dalam deployment.

File Docker Compose yang dibundel menyimpan `/app/data/.env.temp` di dalam volume `librechat-data`, sehingga satu deployment Compose dapat dimulai ulang tanpa mengubah nilai-nilai yang dihasilkan ini. Jika file tidak dapat disimpan, nilai-nilai tersebut bersifat lokal terhadap proses dan sesi atau catatan terenkripsi mungkin menjadi tidak dapat diakses setelah dimulai ulang.

<Callout type="warning" title="Tetapkan nilai permanen untuk produksi">
  Pembuatan sementara adalah kemudahan untuk bootstrap, bukan sistem rotasi kredensial. Sebelum penggunaan produksi, buat nilai permanen dengan [Credentials Generator](/toolkit/creds_generator), simpan di manajer rahasia Anda, dan berikan nilai yang sama ke setiap replika. Mengubah kunci yang sudah ada tidak akan mengenkripsi ulang catatan yang ada. LibreChat mencatat sidik jari kredensial di basis data dan memberikan peringatan saat nilai aktif berubah; jangan menimpa penanda tersebut alih-alih melakukan migrasi yang terkontrol.
</Callout>

### Header Keamanan dan Content Security Policy [#security-headers-and-content-security-policy]

LibreChat mengirimkan header HSTS, framing, content-type, opener, resource, dan referrer dasar secara default. `SECURITY_HEADERS=false` menonaktifkan semuanya dan juga berfungsi sebagai tombol pemutus CSP global.

CSP berbasis nonce bersifat opt-in terpisah dengan `CSP_ENABLED=true` dan secara default berada dalam mode report-only. Mulailah dengan `CSP_REPORT_ONLY=true`, periksa pelanggaran, dan tambahkan hanya origin yang diperlukan oleh deployment Anda sebelum melakukan penegakan. Saat CSP aktif, shell SPA selalu dikirim dengan `Cache-Control: no-store` sehingga nonce per-responsnya tidak dapat digunakan kembali dari cache.

Lihat [HTTP Security Headers](/docs/configuration/security_headers) untuk setiap variabel baseline dan CSP, nilai yang diterima, default, penggantian source-list, dan panduan peluncuran.

      'ENABLE_STATIC_ASSET_BROTLI=true',
    ],
  ]}
/>

**Perilaku:**

Mengatur header [Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Cache-Control) untuk file statis. Konfigurasi ini hanya akan dipicu ketika `NODE_ENV` diatur ke `production`.

- Hapus tanda komentar pada `STATIC_CACHE_MAX_AGE` untuk mengubah `max-age` lokal bagi file statis. Secara default, nilai ini diatur ke 2 hari (172800 detik).
- Hapus tanda komentar pada `STATIC_CACHE_S_MAX_AGE` untuk mengatur `s-maxage` bagi cache bersama (CDN dan proxy). Secara default, ini diatur ke 1 hari (86400 detik).
- Hapus tanda komentar pada `DISABLE_COMPRESSION` untuk menonaktifkan kompresi bagi file statis. Secara default, kompresi diaktifkan.
- Hapus tanda komentar pada `ENABLE_IMAGE_OUTPUT_GZIP_SCAN` untuk mengaktifkan pemindaian dan penyajian versi gambar yang di-gzip jika gambar tersebut telah dikompresi sebelumnya di folder yang sama, dengan nama yang sama dan ekstensi .gz. Secara default, pemindaian gzip untuk gambar yang diunggah dinonaktifkan.
- Hapus tanda komentar pada `ENABLE_STATIC_ASSET_BROTLI` untuk menyajikan versi `.br` yang telah dikompresi sebelumnya dari aset aplikasi statis jika tersedia. Saat diaktifkan, Brotli lebih diutamakan daripada gzip untuk file statis yang disajikan oleh API.

<Callout type="warning" title="Peringatan">
  - Ini hanya memengaruhi file statis yang disajikan oleh server API dan tidak berlaku untuk _Firebase_, _NGINX_, atau konfigurasi lainnya.
</Callout>

<Callout type="note" title="Catatan">

### Mencegah Mesin Pencari Publik Melakukan Pengindeksan [#prevent-public-search-engines-indexing]

Secara default, situs web Anda tidak akan diindeks oleh mesin pencari publik (misalnya Google, Bing, …). Ini berarti orang tidak akan dapat menemukan situs web Anda melalui mesin pencari tersebut. Jika Anda ingin membuat situs web Anda lebih terlihat dan dapat dicari, Anda dapat mengubah pengaturan berikut menjadi `false`

<OptionTable
  options={[
    [
      'NO_INDEX',
      'boolean',
      'Mencegah mesin pencari publik mengindeks situs web Anda.',
      'NO_INDEX=true',
    ],
  ]}
/>

❗**Catatan:** Metode ini tidak dijamin berfungsi untuk semua mesin pencari, dan beberapa mesin pencari mungkin tetap mengindeks situs web atau halaman web Anda untuk tujuan lain, seperti caching atau pengarsipan. Oleh karena itu, Anda tidak boleh hanya mengandalkan metode ini untuk melindungi informasi sensitif atau rahasia di situs web atau halaman web Anda.

LibreChat memeriksa `Content-Length` yang dideklarasikan dan byte yang benar-benar dialirkan, sehingga batas tersebut tetap berlaku meskipun server jarak jauh menghilangkan atau salah menyatakan panjangnya. ### Endpoint Code Interpreter Stateful [#stateful-code-interpreter-endpoint]

[`stateful_code_sessions`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) sangat eksperimental dan memerlukan rute Code Interpreter terpisah. Konfigurasikan rute default dengan `LIBRECHAT_CODE_BASEURL_STATEFUL`, atau tentukan backend terkelola (managed) atau terlampir (attached) bernama di bawah [`endpoints.agents.statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Layanan yang dipilih harus menjalankan profil `stateful`; LibreChat mengirimkan `X-CodeAPI-Expected-Profile: stateful` bersama permintaan stateful.

Permintaan stateful tidak akan pernah kembali ke `LIBRECHAT_CODE_BASEURL`. Jika lingkungan bernama yang dipilih tidak tersedia, atau baik default bernama maupun `LIBRECHAT_CODE_BASEURL_STATEFUL` tidak dikonfigurasi, LibreChat akan menghentikan eksekusi Agent dengan kesalahan konfigurasi. Agent stateless akan terus menggunakan `LIBRECHAT_CODE_BASEURL`, dan kedua profil eksekusi tersebut tidak berbagi ruang kerja (workspace) yang sama.

Setiap Agent dapat menentukan cakupan ruang kerja stateful-nya ke pengguna yang masuk, pengguna dan Agent secara bersamaan, atau pengguna dan percakapan. Lihat [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions) untuk pengaturan dan batasan persistensi.

Lingkungan terlampir bernama juga dapat mengekspos bidang kontrol pemasangan swalayan dengan `pairing.allowPrincipalWorkers: true`. Pengguna yang berwenang mengelola pekerja yang terikat pemilik tersebut di bawah **Settings > Code environments**; entri khusus pemasangan tidak menggantikan `LIBRECHAT_CODE_BASEURL_STATEFUL` dan tidak dapat berfungsi sebagai default penyebaran.

Jalur pemesanan berbasis MongoDB, kotak surat aktor, tanda terima, sewa, percobaan ulang, dan dead letters mendukung pekerja di seluruh replika. Lihat [Agent Event Delivery](/docs/features/agents#agent-event-delivery) dan [Agents API - Agent Events](/docs/features/agents_api#agent-events) untuk perilaku dan contohnya.

#### Mengelola Saldo [#managing-balances]

- Jalankan `npm run add-balance` untuk menambahkan saldo secara manual.
  - Anda juga dapat menentukan email dan jumlah kredit token yang akan ditambahkan, contohnya: `npm run add-balance example@example.com 1000`
- Jalankan `npm run set-balance` untuk mengatur saldo secara manual, mirip dengan `add-balance`.
- Jalankan `npm run list-balances` untuk menampilkan saldo setiap pengguna.

> **Catatan:** 1000 kredit = $0.001 (1 mill USD)

Catatan:

- Saat `USE_REDIS=true`, Anda harus menyediakan `REDIS_URI` atau aplikasi akan memberikan error.
- Klien LibreChat saat ini menegosiasikan protokol generasi v2 secara otomatis. Variabel `GENERATION_PROTOCOL_VERSION` yang sudah tidak digunakan lagi tidak akan dibaca lagi. Lihat [Generation Protocol Compatibility](/docs/configuration/redis#generation-protocol-compatibility) sebelum mencampur versi rilis atau melakukan rollback.
- Aktifkan `STREAM_DELTA_COALESCE_MS` hanya setelah setiap replika mendukung bingkai batch. Pelanggan versi lama akan membuang bingkai yang digabungkan. Lihat [Stream Delta Coalescing](/docs/configuration/redis#stream-delta-coalescing).
- Untuk mode Redis Cluster, berikan beberapa URI: `redis://node1:7001,redis://node2:7002,redis://node3:7003` (mode cluster akan terdeteksi secara otomatis).
- Untuk layanan Redis terkelola dengan endpoint tunggal yang melakukan sharding kunci secara internal, pertahankan `USE_REDIS_CLUSTER=false` dan atur `REDIS_CLUSTER_SAFE_DELETE=true` jika pembersihan cache gagal dengan error `CROSSSLOT`.
- `REDIS_READONLY_RECOVERY_INTERVAL` melakukan debounce pada upaya penyambungan kembali Keyv setelah failover meninggalkan soket terbuka yang terpasang ke replika read-only yang diturunkan pangkatnya. Klien Redis Cluster menggunakan penanganan topologi asli mereka sebagai gantinya.
- `REDIS_PING_INTERVAL` mengontrol heartbeat opsional pada klien ioredis utama; pelanggan pub/sub khusus menggunakan `REDIS_SUBSCRIBER_PING_INTERVAL` agar soket yang tidak aktif dapat terdeteksi. Keduanya menggunakan `REDIS_PING_TIMEOUT` sebagai batas waktu respons dan melakukan koneksi ulang saat batas waktu tersebut berakhir.
- Gunakan protokol `rediss://` untuk koneksi TLS dan atur `REDIS_CA` jika CA Anda tidak dipercaya secara publik.
- `REDIS_KEY_PREFIX_VAR` dan `REDIS_KEY_PREFIX` bersifat eksklusif satu sama lain.
- **AWS Elasticache dengan TLS**: Elasticache mungkin perlu menggunakan dnsLookup alternatif untuk koneksi TLS. Atur `REDIS_USE_ALTERNATIVE_DNS_LOOKUP=true` jika menggunakan Elasticache dengan TLS. Lihat [dokumentasi ioredis](https://www.npmjs.com/package/ioredis) untuk detail lebih lanjut.
