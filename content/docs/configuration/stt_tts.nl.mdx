## Introductie van spraak [#speech-introduction]

De Speech Configuration bevat instellingen voor zowel Speech-to-Text (STT) als Text-to-Speech (TTS) onder een geünificeerde `speech:` sectie. Daarnaast is er een nieuw `speechTab` menu voor gebruikersspecifieke instellingen.

> **Zie ook:** Voor het gedetailleerde YAML-configuratieschema en alle beschikbare opties, zie de [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech) documentatie.

### Omgevingsvariabelen [#environment-variables]

Wanneer je cloud-gebaseerde STT/TTS-services gebruikt, moet je API-sleutels instellen in je `.env` bestand:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Deze sleutels worden vervolgens in uw `librechat.yaml` configuratie verwezen met `${STT_API_KEY}` en `${TTS_API_KEY}`.

### Eén provider per service [#one-provider-per-service]

Elk van `speech.stt` en `speech.tts` accepteert maximaal één providerblok, en elk van beide secties kan worden weggelaten om de browserengine voor die service te behouden. Als een sectie meer dan één provider bevat, mislukken verzoeken met de foutmelding "Multiple providers are set. Please set only one provider."

### Self-hosted engines hebben een allowedAddresses-vermelding nodig [#self-hosted-engines-need-an-allowedaddresses-entry]

Zowel `speech.stt` als `speech.tts` accepteren een `allowedAddresses` lijst. Uitgaande spraakverzoeken worden gevalideerd op basis van hun opgeloste IP-adres en worden geblokkeerd voor toegang tot private, loopback- en link-local adresruimtes. Hierdoor is een zelf-gehoste engine op `localhost`, een LAN-adres of een Docker-servicenaam onbereikbaar totdat je deze toevoegt aan de lijst:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

Invoerwaarden zijn kale `host:port` paren: geen schema of pad, poort is vereist, IPv6 moet tussen haakjes staan als `[::1]:8080`, en IP-literals moeten privé zijn. Publieke cloud-endpoints zoals OpenAI, Azure en ElevenLabs hebben geen invoer nodig. De beveiliging werkt op het opgeloste IP-adres, niet op de hostnaam, dus een cloud-endpoint dat wordt bereikt via Private Link, private DNS of een VPN wordt omgezet naar een privé-adresruimte en moet wel degelijk met zijn exacte `host:port` worden vermeld, net als elk ander privédoel. Hetzelfde veld en dezelfde regels zijn van toepassing onder `speech.stt`. Zie [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) voor het volledige invoerformaat.

## Tabblad Spraak (optioneel) [#speech-tab-optional]

Het `speechTab` menu biedt aanpasbare opties voor conversatie- en geavanceerde modi, evenals gedetailleerde instellingen voor STT en TTS. Dit zal de standaardinstellingen voor gebruikers bepalen.

Gebruik `browser` voor ingebouwde browser-spraak of `external` voor een server-side provider die hieronder is geconfigureerd. Oudere provider-specifieke standaardinstellingen blijven geaccepteerd voor compatibiliteit en worden genormaliseerd naar `external`; als de overeenkomende externe service niet beschikbaar is, valt LibreChat terug op `browser`.

voorbeeld:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` stelt de initiële waarden in die gebruikers zien; elk blijft per gebruiker wijzigbaar in het tabblad met spraakinstellingen.

## STT (Speech-to-Text) [#stt-speech-to-text]

De Spraak-naar-tekst (STT)-functie zet gesproken woorden om in geschreven tekst. Om STT in te schakelen, klik je op de STT-knop (naast de verzendknop) of gebruik je de toetscombinatie ++Shift+Alt+L++ om de transcriptie te starten.

### Beschikbare STT-services [#available-stt-services]

- **Lokale STT**
  - Browser-gebaseerd
  - Whisper (getest op LocalAI)
- **Cloud STT**
  - OpenAI Whisper
  - Azure Whisper
  - Andere OpenAI-compatibele STT-services

### Lokale STT configureren [#configuring-local-stt]

- #### Browser-based
  Geen configuratie vereist. Zorg ervoor dat de "Speech To Text"-schakelaar in het tabblad met spraakinstellingen is ingeschakeld en dat "Browser" is geselecteerd in de vervolgkeuzelijst voor de engine.

- #### Whisper Local [#whisper-local]
  Vereist een lokale Whisper-instantie.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

Het veld `apiKey` is verplicht voor elk OpenAI-compatibel STT-blok, ook voor lokale blokken. Als je server geen sleutels controleert, gebruik dan een willekeurige tijdelijke waarde.

### Cloud STT configureren [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Ondersteuning voor Azure Endpoint-domeinen">
Het `instanceName` veld ondersteunt beide Azure OpenAI domeinformaten:
- **Nieuw formaat**: `.cognitiveservices.azure.com` (bijv. `my-instance.cognitiveservices.azure.com`)
- **Legacy-indeling**: `.openai.azure.com` (bijv. `my-instance.openai.azure.com`)

Je kunt ofwel het volledige domein of alleen de instancenaam opgeven. Als je een volledig domein inclusief `.azure.com` opgeeft, wordt dit ongewijzigd gebruikt. Anders wordt het verouderde `.openai.azure.com` formaat toegepast voor achterwaartse compatibiliteit.
</Callout>

- #### OpenAI compatibel [#openai-compatible]

Raadpleeg de sectie over OpenAI Whisper en pas de `url` en het `model` indien nodig aan. Het veld `apiKey` is nog steeds vereist.

voorbeeld
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

De Text-to-Speech (TTS) functie zet geschreven tekst om in gesproken woorden. Er zijn verschillende TTS-services beschikbaar:

### Beschikbare TTS-services [#available-tts-services]

- **Lokale TTS**
  - Browser-gebaseerd
  - Piper (getest op LocalAI)
  - Coqui (getest op LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Andere OpenAI/ElevenLabs-compatibele TTS-services

Tekst die langer is dan `speech.tts.maxInputChars` (standaard 20000 tekens) wordt afgekapt voordat deze wordt voorgelezen. Zie de [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech) voor details.

### Lokale TTS configureren [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

Geen configuratie vereist. Zorg ervoor dat de "Text To Speech" schakelaar in het tabblad spraakinstellingen is ingeschakeld en dat "Browser" is geselecteerd in het dropdownmenu voor de engine.

- #### Piper [#piper]

Vereist een lokale Piper-instantie.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Vereist een lokale Coqui-instantie.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Cloud TTS configureren [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Ondersteuning voor Azure Endpoint-domeinen">
Het `instanceName` veld ondersteunt beide Azure OpenAI domeinformaten:
- **Nieuw formaat**: `.cognitiveservices.azure.com` (bijv. `my-instance.cognitiveservices.azure.com`)
- **Legacy-indeling**: `.openai.azure.com` (bijv. `my-instance.openai.azure.com`)

Je kunt ofwel het volledige domein of alleen de instancenaam opgeven. Als je een volledig domein inclusief `.azure.com` opgeeft, wordt dit ongewijzigd gebruikt. Anders wordt het verouderde `.openai.azure.com` formaat toegepast voor achterwaartse compatibiliteit.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Aanvullende ElevenLabs-specifieke parameters kunnen als volgt worden toegevoegd:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### OpenAI compatibel [#openai-compatible-1]

Raadpleeg de OpenAI TTS sectie en pas de `url` variabele aan waar nodig

voorbeeld:

```yaml
speech:

    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### ElevenLabs compatibel [#elevenlabs-compatible]

voorbeeld:

```yaml

    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
```
