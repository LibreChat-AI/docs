Toon belangrijke berichten aan al je gebruikers bovenaan de app. Perfect voor aankondigingen, onderhoudsmeldingen of updates.

<Callout type="info" title="Snel overzicht">
  - Er kan slechts **één banner** tegelijk actief zijn
  - Plan banners in om automatisch te verschijnen en te verdwijnen
  - Kies of gebruikers de banner kunnen sluiten of niet
  - Toon banners aan iedereen, of alleen aan ingelogde gebruikers
</Callout>

---

## Een banner maken [#creating-a-banner]

Voer dit commando uit om een banner aan te maken of bij te werken:

```bash
npm run update-banner
```

Met Docker kun je het script in plaats daarvan uitvoeren binnen de `api`-container:

```bash
docker compose exec api npm run update-banner
```

Je wordt door een paar eenvoudige prompts geleid:

```ansi
--------------------------
Update the banner!
--------------------------
Display From (Format: yyyy-mm-ddTHH:MM:SSZ, Default: now):
> 2025-12-02T09:00:00Z

Display To (Format: yyyy-mm-ddTHH:MM:SSZ, Default: not specified):
> 2025-12-31T23:59:59Z

Enter your message (Enter a single dot "." on a new line to finish):
> 🎉 Welcome to LibreChat! Check out our new features.
> .

Is public (y/N):
> n

Is persistable (cannot be dismissed) (y/N):
> n
```

<Callout type="tip" title="Wat betekenen deze opties?">
  - **Weergave Van/Tot**: Wanneer de banner moet verschijnen en verdwijnen. Druk bij de prompt op Enter om "nu" en "voor altijd" te gebruiken
  - **Is public**: Tonen aan bezoekers die niet zijn ingelogd (zoals op de inlogpagina)
  - **Is persistable**: Indien ja, kunnen gebruikers de banner niet sluiten (gebruik dit voor belangrijke mededelingen)
</Callout>

<Callout type="warning" title="Het opnieuw uitvoeren hiervan vervangt de bestaande banner">

Er is altijd slechts één banner. `update-banner` zoekt naar een bestaande banner en overschrijft deze op de huidige locatie, waarbij er alleen een wordt aangemaakt als er nog geen bestaat. Je kunt dus geen tweede banner in de wachtrij plaatsen voor een latere datum, en je kunt geen twee geplande vensters laten overlappen. Het opnieuw uitvoeren van het commando verwijdert het bericht en het schema van de vorige banner.

Om een banner te wijzigen, voer je `update-banner` opnieuw uit. Om er een te verwijderen vóór de ingestelde `Display To`-tijd, gebruik je `delete-banner` hieronder.

</Callout>

## Een banner verwijderen [#deleting-a-banner]

```bash
npm run delete-banner
```

Met Docker voer je `docker compose exec api npm run delete-banner` uit.

Je ziet de huidige banner en wordt gevraagd om te bevestigen voordat je deze verwijdert.

<Callout type="warning" title="Alleen een actieve banner kan worden verwijderd">

`delete-banner` vindt alleen een banner die momenteel actief is: de `Display From`-tijd moet al verstreken zijn, en de `Display To`-tijd moet in de toekomst liggen of niet ingesteld zijn. Een banner die voor een latere datum is gepland, of waarvan de `Display To`-tijd al verstreken is, wordt gerapporteerd als "No banner found to delete" en blijft in de database staan. Om zo'n banner te vervangen, voer je `update-banner` opnieuw uit.

</Callout>

Het verwijderen van een banner op deze manier is ook hoe je er voortijdig een weghaalt: er is geen "disable" vlag. Een banner verdwijnt anders vanzelf zodra `Display To` is verstreken, en een banner die is opgeslagen zonder `Display To` blijft staan totdat je deze verwijdert.

## Voorbeeldbanners [#example-banners]

<Tabs items={['Welkomstbericht', 'Onderhoudsmelding', 'Beveiligingswaarschuwing']}>
  <Tabs.Tab>
    Een eenvoudig welkomstbericht dat gebruikers kunnen wegklikken:

    ```bash
    npm run update-banner "" "" "👋 Welcome to LibreChat!" "false" "false"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Een geplande onderhoudsmelding die niet kan worden weggeklikt:

    ```bash
    npm run update-banner "2025-12-20T00:00:00Z" "2025-12-21T06:00:00Z" "⚠️ Scheduled maintenance on Dec 20th, 2-6 AM UTC" "true" "true"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Een dringende beveiligingsmelding die voor iedereen zichtbaar is:

    ```bash
    npm run update-banner "" "" "🔒 Please update your password by January 1st" "true" "true"
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="info" title="Lege datumargumenten vragen nog steeds om invoer">

Een lege string (`""`) voor een datum wordt als ontbrekend beschouwd, dus het script vraagt nog steeds interactief om `Display From` en `Display To`. Druk bij elke prompt op Enter om de standaardwaarde te accepteren, of geef ISO-datums (`yyyy-mm-ddTHH:MM:SSZ`) als de eerste twee argumenten op om de opdracht zonder prompts uit te voeren. Het argument voor het bericht is ook verplicht om de berichtprompt over te slaan, en de argumenten `isPublic` en `persistable` moeten worden opgegeven als `true` of `false` om hun prompts over te slaan.

</Callout>

## Datumnotatie [#date-format]

Gebruik dit formaat voor datums: `yyyy-mm-ddTHH:MM:SSZ`

**Voorbeelden:**
- `2025-12-25T09:00:00Z` → 25 december 2025 om 09:00 uur (UTC)
- `2025-01-01T00:00:00Z` → 1 januari 2025 om middernacht (UTC)

Wanneer hierom wordt gevraagd, drukt u op Enter zonder een datum in te typen om de huidige tijd te gebruiken voor `Display From`, of geen einddatum voor `Display To`.
