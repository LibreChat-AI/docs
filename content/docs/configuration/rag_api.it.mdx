L'API RAG indicizza i file caricati dagli utenti e recupera i passaggi pertinenti per arricchire i tuoi prompt, fornendo a LibreChat risposte consapevoli del contesto e basate sui tuoi documenti. Viene eseguita come un servizio FastAPI separato supportato da un database PostgreSQL + pgvector.

<Callout type="info" title="Ciò che vedono gli utenti">
[Chat with Files](/docs/features/rag_api) descrive il caricamento per la ricerca nei file, il riutilizzo dei file e la ricerca nei file negli agenti. Questa pagina illustra la configurazione e l'impostazione.
</Callout>

## Disponibilità [#availability]

La ricerca di file tramite la RAG API funziona negli [Agenti](/docs/features/agents) e nelle chat normali su ogni endpoint tranne Assistants. Gli OpenAI Assistants utilizzano invece l'archiviazione e il recupero file nativi di OpenAI, e i file caricati lì non possono essere allegati altrove.

Gli utenti vedono **Upload for File Search** solo quando la capacità dell'agente `file_search` è abilitata (lo è per impostazione predefinita) e il loro ruolo dispone del permesso File Search ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Avvio rapido con Docker [#docker-quick-start]

Per Docker, l'API RAG è già configurata sia nel file predefinito `docker-compose.yml` sia in `deploy-compose.yml`, incluso il valore `RAG_API_URL`. Devi solo assicurarti di eseguire l'immagine e i file compose più recenti. Consulta la [guida all'aggiornamento di LibreChat per Docker](/docs/local/docker#updating-librechat) se non sei sicuro di come aggiornare.

<Callout type="warning" title="File .env condiviso">
Con la configurazione Docker predefinita, il file `.env` è condiviso tra LibreChat e la RAG API. Definisci le variabili RAG nello stesso file. L'elenco completo si trova nel [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

Il file `docker-compose.yml` e il file `deploy-compose.yml` predefiniti impostano `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` sul servizio `api`. Le variabili d'ambiente impostate sul servizio hanno la precedenza sul file `.env`; pertanto, per la configurazione inclusa non è necessario aggiungere `RAG_API_URL` al file `.env`, e impostarla lì non ha alcun effetto. Per configurare un deployment Docker in modo che punti a un'API RAG esterna, sovrascrivi invece il valore sul servizio `api`, ad esempio per un'API RAG in esecuzione sull'host Docker:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

L'elemento `extra_hosts` è necessario su Linux, dove Docker non definisce autonomamente `host.docker.internal`.

Compose carica automaticamente `docker-compose.override.yml` solo con il file predefinito `docker-compose.yml`. Con `deploy-compose.yml`, passa entrambi i file: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Al di fuori di Docker, imposta `RAG_API_URL` nel tuo file `.env`.

### Lite vs. full image [#lite-vs-full-image]

Docker utilizza l'immagine "lite" della RAG API per impostazione predefinita (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), che supporta solo embedding remoti da OpenAI o da un servizio remoto HuggingFace/Ollama che hai configurato.

Per gli embedding locali, sostituisci l'immagine nel file compose con la build completa, `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Apporta questa modifica nel tuo [Docker Compose Override File](/docs/configuration/docker_override). Consulta `docker-compose.override.yml.example` nella root del progetto per un esempio.

Se desideri un file compose che includa solo il database PostgreSQL + pgvector e l'API Python, consulta `rag.yml` nella root del progetto.

### Archiviazione database [#database-storage]

I file compose predefiniti memorizzano i dati di pgvector/PostgreSQL nel volume `pgdata2` gestito da Docker. Questa è una scelta intenzionale: i file del database non devono essere modificati direttamente dall'host e un volume gestito evita comuni problemi di proprietà e permessi. I file modificabili dall'utente (upload, log, immagini, dati MongoDB e configurazione NGINX) sono montati tramite bind-mount nelle cartelle del progetto, dove l'accesso diretto dall'host è utile.

## Configurazione Locale [#local-setup]

Una configurazione non basata su container è più pratica. Segui le istruzioni nel [repository RAG API](https://github.com/LibreChat-AI/rag-api/).

Imposta `RAG_API_URL` nel tuo file `.env` di LibreChat con l'indirizzo in cui l'API è raggiungibile dalla tua configurazione. Questo è diverso dalla configurazione Docker predefinita, in cui il valore è già impostato sul servizio `api` nei file `docker-compose.yml` e `deploy-compose.yml` predefiniti.

## Configurazione [#configuration]

Imposta le opzioni dell'API RAG tramite variabili d'ambiente in un file `.env` accessibile all'API. La maggior parte sono facoltative, a parte le credenziali e i percorsi richiesti dal provider scelto. Nella configurazione predefinita, è richiesto solo `RAG_OPENAI_API_KEY`.

## Utilizzo [#usage]

Una volta che la RAG API è raggiungibile, non c'è nient'altro da attivare in LibreChat. Gli utenti caricano i file con **Upload for File Search** e il modello interroga l'indice tramite lo strumento `file_search` quando una domanda lo richiede. Se `RAG_API_URL` non è impostato o il servizio non è attivo, questi caricamenti non riescono; LibreChat registra un avviso all'avvio quando non riesce a raggiungere il controllo di integrità della RAG API. Per il lato utente, vedi [Chat with Files](/docs/features/rag_api).

## Risoluzione dei problemi [#troubleshooting]

Se riscontri problemi durante la configurazione o l'utilizzo della RAG API:

- Assicurati che tutte le variabili d'ambiente richieste siano impostate correttamente nel tuo file `.env`.
- Assicurati che il database vettoriale sia configurato e accessibile.
- Verifica che la chiave API di OpenAI o le credenziali di altri provider siano valide.
- Controlla sia i log di LibreChat che quelli dell'API RAG per eventuali errori o avvisi.

Se il problema persiste, consulta la documentazione della RAG API o chiedi alla community di LibreChat su GitHub Discussions o Discord.
