## Wprowadzenie do mowy [#speech-introduction]

Konfiguracja mowy (Speech Configuration) obejmuje ustawienia zarówno dla zamiany mowy na tekst (STT), jak i tekstu na mowę (TTS) w ramach ujednoliconej sekcji `speech:`. Dodatkowo dostępna jest nowa karta `speechTab` w menu ustawień użytkownika.

> **Zobacz także:** Szczegółowy schemat konfiguracji YAML oraz wszystkie dostępne opcje znajdują się w dokumentacji [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech).

### Zmienne środowiskowe [#environment-variables]

Podczas korzystania z usług STT/TTS opartych na chmurze, należy ustawić klucze API w pliku `.env`:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Te klucze są następnie przywoływane w konfiguracji `librechat.yaml` przy użyciu `${STT_API_KEY}` oraz `${TTS_API_KEY}`.

### Jeden dostawca na usługę [#one-provider-per-service]

Każda z sekcji `speech.stt` i `speech.tts` przyjmuje co najwyżej jeden blok dostawcy, a każdą z tych sekcji można pominąć, aby zachować silnik przeglądarki dla danej usługi. Jeśli sekcja zawiera więcej niż jednego dostawcę, żądania kończą się błędem: "Multiple providers are set. Please set only one provider."

### Samodzielnie hostowane silniki wymagają wpisu allowedAddresses [#self-hosted-engines-need-an-allowedaddresses-entry]

Zarówno `speech.stt`, jak i `speech.tts` akceptują listę `allowedAddresses`. Wychodzące żądania mowy są weryfikowane pod kątem ich rozpoznanego adresu IP i blokowane przed dostępem do prywatnej przestrzeni adresowej, pętli zwrotnej (loopback) oraz adresów link-local, więc samodzielnie hostowany silnik na `localhost`, adresie LAN lub nazwie usługi Docker jest nieosiągalny, dopóki nie zostanie wymieniony na liście:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

Wpisy to surowe pary `host:port`: bez schematu i ścieżki, port jest wymagany, adresy IPv6 muszą być w nawiasach kwadratowych jak `[::1]:8080`, a literały IP muszą być prywatne. Publiczne punkty końcowe w chmurze, takie jak OpenAI, Azure i ElevenLabs, nie wymagają wpisu. Mechanizm ochronny działa na podstawie rozpoznanego adresu IP, a nie nazwy hosta, więc punkt końcowy w chmurze osiągany przez Private Link, prywatny DNS lub VPN jest rozpoznawany jako prywatna przestrzeń adresowa i wymaga podania dokładnego `host:port`, tak jak każdy inny prywatny cel. To samo pole i te same zasady mają zastosowanie w `speech.stt`. Zobacz [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers), aby poznać pełny format wpisu.

## Karta mowy (opcjonalne) [#speech-tab-optional]

Menu `speechTab` zapewnia konfigurowalne opcje dla trybów konwersacji i zaawansowanego, a także szczegółowe ustawienia dla STT i TTS. Pozwoli to na określenie domyślnych ustawień dla użytkowników.

Użyj `browser` dla wbudowanej obsługi mowy w przeglądarce lub `external` dla dostawcy po stronie serwera skonfigurowanego poniżej. Starsze wartości domyślne specyficzne dla dostawców są nadal akceptowane w celu zachowania kompatybilności i są normalizowane do `external`; jeśli pasująca usługa zewnętrzna jest niedostępna, LibreChat powraca do `browser`.

przykład:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` ustawia wartości początkowe widoczne dla użytkowników; każda z nich pozostaje możliwa do zmiany przez użytkownika w zakładce ustawień mowy.

## STT (Speech-to-Text) [#stt-speech-to-text]

Funkcja zamiany mowy na tekst (STT, Speech-to-Text) przekształca wypowiadane słowa w tekst pisemny. Aby włączyć STT, kliknij przycisk STT (obok przycisku wysyłania) lub użyj kombinacji klawiszy ++Shift+Alt+L++, aby rozpocząć transkrypcję.

### Dostępne usługi STT [#available-stt-services]

- **Lokalne STT**
  - Oparte na przeglądarce
  - Whisper (przetestowano na LocalAI)
- **Cloud STT**
  - OpenAI Whisper
  - Azure Whisper
  - Inne usługi STT kompatybilne z OpenAI

### Konfigurowanie lokalnego STT [#configuring-local-stt]

- #### Browser-based
  Nie wymaga konfiguracji. Upewnij się, że przełącznik "Speech To Text" w zakładce ustawień mowy jest włączony, a w menu rozwijanym silnika wybrano opcję "Browser".

- #### Whisper Local [#whisper-local]
  Wymaga lokalnej instancji Whisper.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

Pole `apiKey` jest wymagane dla każdego bloku STT zgodnego z OpenAI, także dla lokalnych. Jeśli Twój serwer nie sprawdza kluczy, użyj dowolnej wartości zastępczej.

### Konfigurowanie Cloud STT [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Obsługa domeny endpointu Azure">
Pole `instanceName` obsługuje oba formaty domen Azure OpenAI:
- **Nowy format**: `.cognitiveservices.azure.com` (np. `my-instance.cognitiveservices.azure.com`)
- **Starszy format**: `.openai.azure.com` (np. `my-instance.openai.azure.com`)

Możesz podać pełną domenę lub tylko nazwę instancji. Jeśli podasz pełną domenę, w tym `.azure.com`, zostanie ona użyta w niezmienionej formie. W przeciwnym razie, dla zachowania kompatybilności wstecznej, zostanie zastosowany starszy format `.openai.azure.com`.
</Callout>

- #### Kompatybilne z OpenAI [#openai-compatible]

Zapoznaj się z sekcją OpenAI Whisper, dostosowując `url` i `model` w razie potrzeby. Pole `apiKey` nadal jest wymagane.

przykład
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

Funkcja Text-to-Speech (TTS) przekształca tekst pisany na słowa mówione. Dostępne są różne usługi TTS:

### Dostępne usługi TTS [#available-tts-services]

- **Lokalny TTS**
  - Oparte na przeglądarce
  - Piper (przetestowano na LocalAI)
  - Coqui (przetestowano na LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Inne usługi TTS kompatybilne z OpenAI/ElevenLabs

Tekst dłuższy niż `speech.tts.maxInputChars` (domyślnie 20000 znaków) jest skracany przed odczytaniem na głos. Szczegółowe informacje znajdziesz w sekcji [Struktura obiektu Speech](/docs/configuration/librechat_yaml/object_structure/speech).

### Konfigurowanie lokalnego TTS [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

Nie jest wymagana żadna konfiguracja. Upewnij się, że przełącznik "Text To Speech" w zakładce ustawień mowy jest włączony, a w menu rozwijanym silnika wybrano opcję "Browser".

- #### Piper [#piper]

Wymaga lokalnej instancji Piper.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Wymaga lokalnej instancji Coqui.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Konfigurowanie Cloud TTS [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Obsługa domeny endpointu Azure">
Pole `instanceName` obsługuje oba formaty domen Azure OpenAI:
- **Nowy format**: `.cognitiveservices.azure.com` (np. `my-instance.cognitiveservices.azure.com`)
- **Starszy format**: `.openai.azure.com` (np. `my-instance.openai.azure.com`)

Możesz podać pełną domenę lub tylko nazwę instancji. Jeśli podasz pełną domenę, w tym `.azure.com`, zostanie ona użyta w niezmienionej formie. W przeciwnym razie, dla zachowania kompatybilności wstecznej, zostanie zastosowany starszy format `.openai.azure.com`.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Dodatkowe parametry specyficzne dla ElevenLabs można dodać w następujący sposób:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### Kompatybilne z OpenAI [#openai-compatible-1]

Zapoznaj się z sekcją OpenAI TTS, dostosowując zmienną `url` w razie potrzeby

przykład:

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Kompatybilne z ElevenLabs [#elevenlabs-compatible]

Zapoznaj się z sekcją ElevenLabs, dostosowując zmienną `url` w razie potrzeby

przykład:

```yaml
speech:
  tts:
    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```
