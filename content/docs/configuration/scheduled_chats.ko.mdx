[Scheduled Chats](/docs/features/scheduled_chats)는 실험적 기능이며, 사용자가 직접 활성화하기 전까지는 꺼져 있습니다. 예약된 실행은 아무도 지켜보지 않는 상태에서 모델, 도구, Code Interpreter 리소스를 사용하므로, 기능을 활성화하기 전에 아래의 배포 요구 사항을 반드시 확인하세요.

## 활성화 [#enable]

`librechat.yaml`에 `interface.schedules`를 추가한 후 LibreChat을 재시작하세요:

```yaml filename="librechat.yaml"
interface:
  schedules:
    use: true
    create: true
    maxPerUser: 10
    minIntervalMinutes: 60
    autoDisableAfterFailures: 5
    fireConcurrency: 5
    requireProject: false
    # projectId: '000000000000000000000000'
```

`use`와 `create`는 서버 시작 시 기본 `USER` 역할의 `SCHEDULES` 권한을 설정합니다. 이후에는 [관리자 패널](/docs/features/admin_panel)에서 역할별로 관리합니다. `use`는 사용자가 자신의 스케줄을 볼 수 있게 합니다. `create`는 여기에 더해 스케줄을 생성, 편집, 활성화, 실행, 삭제할 수 있게 합니다. 나머지 키는 런타임 제한입니다.

`schedules: true`는 이 기본값과 함께 기능을 활성화합니다. `schedules: false` 또는 `use: false`는 역할, 그룹, 사용자별 재정의로도 해제할 수 없는 배포 전체 중지입니다.

프로젝트 규칙은 매 실행 시마다 다시 확인됩니다. `requireProject`를 더 이상 충족하지 않거나 프로젝트가 삭제된 일정은 프로젝트 범위가 지정되지 않은 대화를 시작하는 대신 스스로 비활성화됩니다. 채팅 프로젝트는 한 사용자에게 속하므로, 배포 전체에 적용되는 `projectId`는 해당 프로젝트의 소유자에게만 작동합니다. 소유자마다 서로 다른 대상이 필요한 경우에는 역할 또는 사용자 재정의에서 이를 설정하십시오.

전체 필드 목록은 `admissionConcurrency`, `mcpPreflightConcurrency`, `mcpPreflightTimeoutMs`를 포함하며, 이는 생성 작업과 별도로 승인(admission) 및 MCP 준비 상태 점검을 제한하는 데 사용됩니다. 해당 목록은 [`interface.schedules`](/docs/configuration/librechat_yaml/object_structure/interface#schedules)에서 확인할 수 있습니다.

## 무인 MCP 액세스 [#unattended-mcp-access]

LibreChat는 실행을 시작하기 전에 예약된 에이전트와 그 하위 에이전트가 필요로 하는 모든 MCP 도구를 확인합니다. 대화형 로그인이 필요한 실행은 시작되지 않으며, 일정 화면에 주의가 필요한 에이전트가 표시됩니다.

사용자가 무인 실행을 위해 MCP 도구를 승인할 수 있도록 하려면 `interface.schedules.mcpConsent`를 켜십시오:

- `mcpConsent.enabled`는 이 기능을 활성화합니다.
- `mcpConsent.maxLifetimeHours`는 권한 부여가 유지되는 최대 기간을 제한하며, 값의 범위는 1에서 8760시간입니다.
- `mcpConsent.resources`는 인가(authorize)될 수 있는 MCP 리소스를 나열합니다.
- `mcpConsent.readOnlyPolicy`는 서버와 업스트림 도구 이름을 키로 사용하여 신뢰할 수 있는 읽기 전용 도구 선언 목록을 정의합니다.
- `mcpReceiptRetry.baseMs`와 `mcpReceiptRetry.maxMs`는 동의 영수증(consent receipt) 재시도에 대한 백오프(backoff)를 설정합니다.

사용자는 이후 스케줄 편집기에서 **예약된 MCP 권한 부여** 섹션을 보게 됩니다. 권한 부여는 기한이 만료될 때까지 명시된 에이전트와 리소스에만 적용되며, 쓰기 작업은 절대 허용되지 않습니다.

## 배포 요구 사항 [#deployment-requirements]

예약된 채팅은 MongoDB 리스(lease)를 통해 조율되므로, 여러 레플리카가 작업을 나눠서 처리할 수 있습니다. 또한 다음이 필요합니다:

- **다중 레플리카 배포에서의 Redis 스트림.** `USE_REDIS_STREAMS=true`로 설정하십시오. 공유 스트림이 없으면 다른 레플리카가 재개하거나 중지할 수 없는 작업을 시작하는 대신 스케줄 저장이 실패합니다.
- **일시 중지가 가능한 에이전트를 위한 영속적 체크포인터.** 예약된 에이전트가 Ask User를 사용하거나 도구 승인이 필요한 경우, 단일 프로세스에서 실행하더라도 Redis 스트림과 공유 체크포인터가 필요합니다. 기본 MongoDB [`checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#checkpointer)는 동작하지만, `type: memory`는 동작하지 않습니다. 둘 중 하나라도 없으면 LibreChat은 모델 호출 이전에 해당 실행을 거부합니다.
- **표준 서버 진입점입니다.** 레거시 실험적 클러스터 진입점은 스케줄 엔진을 시작하지 않습니다.

두 개의 환경 변수가 엔진을 제어합니다([dotenv](/docs/configuration/dotenv#scheduled-chats)에도 나열되어 있습니다):
