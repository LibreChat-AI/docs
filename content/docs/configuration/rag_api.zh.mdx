RAG API 会对用户上传的文件进行索引，并检索相关段落以增强您的提示词，从而使 LibreChat 能够根据您的文档提供具有上下文感知能力的回复。它作为一个独立的 FastAPI 服务运行，并由 PostgreSQL + pgvector 数据库提供支持。

<Callout type="info" title="用户所见">
[Chat with Files](/docs/features/rag_api) 介绍了用于文件搜索的上传、文件复用以及智能体中的文件搜索功能。本页介绍设置与配置。
</Callout>

## 可用性 [#availability]

通过 RAG API 进行的文件搜索可在[智能体](/docs/features/agents)以及除 Assistants 之外的所有端点的常规聊天中使用。OpenAI Assistants 改用 OpenAI 自有的文件存储和检索功能,在该处上传的文件无法在其他地方附加使用。

只有当 `file_search` 智能体功能已启用(默认已启用)且用户的角色拥有文件搜索权限([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch))时,用户才会看到 **上传以进行文件搜索** 选项。

## Docker 快速入门 [#docker-quick-start]

对于 Docker,RAG API 已在默认的 `docker-compose.yml` 和 `deploy-compose.yml` 文件中配置完成,包括 `RAG_API_URL` 的值。您只需确保正在运行最新的镜像和 Compose 文件即可。如果您不确定如何更新,请参阅 [Docker 版 LibreChat 更新指南](/docs/local/docker#updating-librechat)。

<Callout type="warning" title="共享的 .env 文件">
在使用默认的 Docker 设置时，`.env` 文件会在 LibreChat 和 RAG API 之间共享。请在同一个文件中定义 RAG 变量。完整列表请参阅 [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md)。
</Callout>

默认的 `docker-compose.yml` 和 `deploy-compose.yml` 文件在 `api` 服务上设置了 `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}`。在服务上设置的环境变量优先于 `.env` 文件,因此对于内置的部署方式,您无需在 `.env` 中添加 `RAG_API_URL`,在那里设置它也不会生效。要让 Docker 部署指向外部的 RAG API,应改为在 `api` 服务上覆盖该值,例如对于运行在 Docker 宿主机上的 RAG API:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

`extra_hosts` 条目在 Linux 上是必需的,因为 Docker 本身不会定义 `host.docker.internal`。

Compose 仅在与默认的 `docker-compose.yml` 一起使用时才会自动加载 `docker-compose.override.yml`。若使用 `deploy-compose.yml`,则需同时指定两个文件:`docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`。

在 Docker 之外运行时,请在 `.env` 文件中设置 `RAG_API_URL`。

### Lite 与完整镜像对比 [#lite-vs-full-image]

Docker 默认使用 RAG API 的 "lite" 镜像（`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`），该镜像仅支持来自 OpenAI 或您已配置的远程 HuggingFace/Ollama 服务的远程嵌入。

对于本地 embeddings，请将 compose 文件中的镜像切换为完整构建版本：`registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`。请在您的 [Docker Compose Override File](/docs/configuration/docker_override) 中进行此更改。有关示例，请参阅项目根目录下的 `docker-compose.override.yml.example`。

如果您需要一个仅包含 PostgreSQL + pgvector 数据库和 Python API 的 compose 文件，请参阅项目根目录下的 `rag.yml`。

### 数据库存储 [#database-storage]

默认的 compose 文件将 pgvector/PostgreSQL 数据存储在 Docker 管理的 `pgdata2` 卷中。这是有意为之的：数据库文件无需直接从宿主机进行编辑，且使用托管卷可以避免常见的归属权和权限问题。面向用户且可编辑的文件（上传内容、日志、图像、MongoDB 数据和 NGINX 配置）则通过绑定挂载（bind-mounted）到项目文件夹中，以便在需要时从宿主机直接访问。

## 本地设置 [#local-setup]

非容器化安装需要更多手动操作。请遵循 [RAG API repo](https://github.com/LibreChat-AI/rag-api/) 中的说明。

在您的 LibreChat `.env` 文件中,将 `RAG_API_URL` 设置为您的环境中可以访问该 API 的地址。这与内置的 Docker 配置不同:在默认的 `docker-compose.yml` 和 `deploy-compose.yml` 文件中,该值已经在 `api` 服务上设置好了。

## 配置 [#configuration]

通过 `.env` 文件中 API 可访问的环境变量来设置 RAG API 选项。除了您所选提供商所需的凭据和路径外，大多数选项都是可选的。在默认设置中，仅需 `RAG_OPENAI_API_KEY`。

## 使用方法 [#usage]

一旦 RAG API 可以访问,LibreChat 中就无需再开启其他设置。用户通过 **Upload for File Search** 上传文件,当问题需要时,模型会通过 `file_search` 工具查询索引。如果未设置 `RAG_API_URL` 或服务已停止运行,这些上传将会失败;当 LibreChat 无法连接 RAG API 健康检查时,会在启动时记录警告。用户端的相关说明请参阅[与文件对话](/docs/features/rag_api)。

## 故障排除 [#troubleshooting]

如果您在设置或使用 RAG API 时遇到问题：

- 请确认所有必需的环境变量已在您的 `.env` 文件中正确设置。
- 确保向量数据库已配置且可访问。
- 验证 OpenAI API 密钥或其他提供商凭据是否有效。
- 检查 LibreChat 和 RAG API 日志中是否有错误或警告。

如果问题仍然存在，请参考 RAG API 文档，或在 GitHub Discussions 或 Discord 上向 LibreChat 社区寻求帮助。
