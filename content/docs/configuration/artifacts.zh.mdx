本页介绍 [Artifacts](/docs/features/artifacts) 的管理员设置。用户可以在 Agent Builder 中为每个智能体单独开启 Artifacts;此处的设置决定该选项是否存在,以及预览内容从何处加载。

## 启用 Artifacts [#enabling-artifacts]

Artifacts 是一种智能体能力。`artifacts` 包含在默认的 [`endpoints.agents.capabilities`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) 列表中，因此除非你自行设置了不包含它的列表，否则该功能默认可用。如果你覆盖了 `capabilities`，请务必包含 `artifacts`，以保留 Agent Builder 中的该选项。

要在不构建智能体的情况下为模型规格提供 artifacts,请在规格上设置 [`artifacts`](/docs/configuration/librechat_yaml/object_structure/model_specs#artifacts)。`true` 表示使用默认模式;您也可以传入模式名称:`default`、`shadcnui` 或 `custom`。

## 在新窗口中打开面板 [#opening-the-panel-in-a-new-window]

面板上有一个**在新窗口中打开**按钮,点击后会将面板移动到单独的浏览器窗口中。该功能默认开启。如果你的部署环境不支持弹出窗口(例如嵌入式 webview),请通过 [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking) 将其关闭;关闭后,停靠的面板仍可正常使用。

## Content-Security-Policy

LibreChat 自身的 CSP 允许 HTTPS 框架,因此默认的 CodeSandbox 打包器无需修改即可加载。如果 LibreChat 前面的反向代理或 CDN 设置了更严格的 `Content-Security-Policy`,请在 `frame-src` 中允许打包器的来源:公共打包器使用 `https://*.codesandbox.io`,如果您自行托管,则使用您自己的打包器 URL。如果您只需要扩展 LibreChat 内置的策略,请使用 `CSP_FRAME_SRC_EXTRA`。

React 预览同样会从 `cdn.tailwindcss.com` 加载 Tailwind，因此用户的浏览器必须能够访问该主机。

## 自托管 Sandpack 打包器 [#self-hosting-the-sandpack-bundler]

Previews 由 [Sandpack](https://sandpack.codesandbox.io/) 渲染,默认情况下,Sandpack 会从 CodeSandbox 的公共 CDN 获取其打包器(bundler)。该 CDN 还会发送使用遥测数据。对于私有网络、合规要求,或者希望消除对外部服务的依赖的情况,请[自行托管打包器](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)。

[LibreChat-AI/codesandbox-client](https://github.com/LibreChat-AI/codesandbox-client) 是为 LibreChat 准备的一个分支,已移除了遥测请求,包括容器镜像中的相关请求。

LibreChat 使用两个打包器。`SANDPACK_BUNDLER_URL` 用于提供 React 构件,`SANDPACK_STATIC_BUNDLER_URL` 用于提供 HTML、SVG、Markdown、代码和 Office 文件预览所依赖的静态模板。自行托管时请同时设置这两个变量:如果只设置其中一个,其他类型的构件仍会从公共 CDN 加载。两者都列在 [`.env` 参考](/docs/configuration/dotenv#artifacts) 中。Mermaid 图表直接在页面中渲染,不使用这两个打包器中的任何一个。

运行你自己的打包器意味着你需要自行负责其 CORS 设置、安全更新和托管资源。修改这些变量后请重启 LibreChat;这些 URL 会在启动配置中发送给浏览器。
