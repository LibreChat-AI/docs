### Umum [#general]

LibreChat memiliki pencatatan log terpusat yang terintegrasi ke dalam backend (api)-nya.

- Dengan instalasi **docker**, file log disimpan di `/logs`

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="logs" defaultOpen>
      <FileTree.File name="debug-2024-01-01.log" active />
      <FileTree.File name="error-2024-01-01.log" active />
      <FileTree.File name="meiliSync-2024-01-01.log" active />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

- Dengan instalasi **npm**, file log disimpan di `/api/logs`

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="api" defaultOpen>
      <FileTree.Folder name="logs" defaultOpen>
        <FileTree.File name="debug-2024-01-01.log" active />
        <FileTree.File name="error-2024-01-01.log" active />
        <FileTree.File name="meiliSync-2024-01-01.log" active />
      </FileTree.Folder>
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

Log error disimpan secara default. File log debug hanya ditulis ketika `DEBUG_LOGGING=true`; `.env.example` yang disediakan mengaturnya ke `true`, tetapi jika variabel tidak diatur, tidak ada file debug yang dibuat.

Ini memungkinkan Anda untuk memantau server Anda melalui alat eksternal yang memeriksa file log, seperti **[the ELK stack](https://aws.amazon.com/what-is/elk-stack/)**.

Log debug sangat penting untuk pekerjaan pengembang dan perbaikan masalah. Jika Anda mengalami kendala saat menjalankan LibreChat, reproduksi masalah sedekat mungkin, dan **[laporkan masalah tersebut](https://github.com/LibreChat-AI/LibreChat/issues)** dengan menyertakan log Anda yang ditemukan di `./api/logs/debug-%DATE%.log`.

Log kesalahan juga disimpan di lokasi yang sama: `./api/logs/error-%DATE%.log`. Jika Anda telah mengonfigurasi Meilisearch, terdapat file log terpisah untuk ini juga.

<Callout type="note" title="Catatan:">
  Berkas log dirotasi setiap hari: berkas baru dimulai setiap hari, dan berkas juga dipisah setelah mencapai 20 MB. Berkas yang telah dirotasi dikompresi dengan gzip dan disimpan selama 14 hari. Error juga terdapat di berkas log debug, tetapi berkas log error memberikan stack trace dan detail yang lebih lengkap.
</Callout>

### Pengaturan [#setup]

- File log debug hanya ditulis ketika variabel ini diatur ke `true`. Jika tidak diatur atau diatur ke nilai lain, tidak ada file debug yang dibuat.

<OptionTable
  options={[['DEBUG_LOGGING', 'boolean', 'Tulis log debug ke file. Diperlukan agar file log debug dapat dibuat.', 'DEBUG_LOGGING=true']]}
/>

> Disarankan untuk tetap menonaktifkan log debug di lingkungan produksi.

- Untuk output server yang lebih mendetail di konsol/terminal, Anda dapat mengatur hal berikut ke `TRUE`:

<OptionTable
  options={[
    [
      'DEBUG_CONSOLE',
      'boolean',
      'Aktifkan log konsol/stdout verbose dalam format yang sama dengan log debug file.',
      'DEBUG_CONSOLE=false',
    ],
  ]}
/>

Namun, hal ini tidak disarankan karena output yang dihasilkan bisa jadi sangat panjang. Fitur ini dinonaktifkan secara default dan sebaiknya hanya diaktifkan jika benar-benar diperlukan.

- Saat menangani log konsol dalam deployment cloud (seperti GCP atau AWS), mengaktifkan ini akan mencetak log dengan stempel waktu UTC dan memformatnya sebagai JSON.

<OptionTable
  options={[
    [
      'CONSOLE_JSON',
      'boolean',
      'Aktifkan log konsol/stdout JSON verbose yang sesuai untuk penyebaran cloud seperti GCP/AWS.',
      'CONSOLE_JSON=false',
    ],
  ]}
/>

Secara default, panjang string JSON dipotong hingga 255 karakter. Anda dapat mengonfigurasinya dengan variabel lingkungan berikut:

<OptionTable
  options={[
    [
      'CONSOLE_JSON_STRING_LENGTH',
      'number',
      'Konfigurasikan ukuran pemotongan untuk nilai string dalam log konsol/stdout JSON. Default: 255.',
      '# CONSOLE_JSON_STRING_LENGTH=255',
    ],
  ]}
/>

- Verbositas konsol dapat diatur dengan `CONSOLE_LOG_LEVEL` (`error`, `warn`, `info`, `http`, `verbose`, `debug`, `activity`, `silly`, atau `silent`). `silent` menonaktifkan output konsol tanpa menonaktifkan pencatatan log ke file. Nilai yang tidak valid akan kembali ke nilai default dengan peringatan.

<OptionTable
  options={[
    [
      'CONSOLE_LOG_LEVEL',
      'string',
      'Verbositas konsol. Defaultnya adalah info, atau debug saat DEBUG_CONSOLE=true; nilai yang eksplisit akan diutamakan.',
      '# CONSOLE_LOG_LEVEL=info',
    ],
  ]}
/>

- Pesan log debug dipotong menjadi 150 karakter secara default, dan redaksi log dibatasi hingga 5000 nilai per record. Anda dapat menyesuaikannya dengan `DEBUG_MESSAGE_LENGTH` dan `LOG_REDACTION_MAX_NODES`.

<OptionTable
  options={[
    [
      'DEBUG_MESSAGE_LENGTH',
      'number',
      'Panjang maksimum pesan log debug sebelum dipotong. Default: 150.',
      '# DEBUG_MESSAGE_LENGTH=150',
    ],
    [
      'LOG_REDACTION_MAX_NODES',
      'number',
      'Jumlah maksimum nilai yang dapat disunting dalam satu catatan log sebelum sisanya diganti. Default: 5000.',
      '# LOG_REDACTION_MAX_NODES=5000',
    ],
  ]}
/>

- Untuk menulis file log ke lokasi selain lokasi default, atur `LIBRECHAT_LOG_DIR`. Lihat [Logging](/docs/configuration/dotenv#logging) di referensi `.env`.

- Transport log berbasis file diaktifkan secara default. Atur `LOG_TO_FILE=false` jika deployment Anda hanya perlu mengeluarkan log ke stdout/stderr.

<OptionTable
  options={[
    [
      'LOG_TO_FILE',
      'boolean',
      'Atur ke false untuk menonaktifkan transport Winston berbasis file.',
      'LOG_TO_FILE=true',
    ],
  ]}
/>

### OpenTelemetry Tracing [#opentelemetry-tracing]

LibreChat dapat memancarkan trace OpenTelemetry backend untuk visibilitas server, database, Redis, dan HTTP keluar. Span tingkat perintah Redis bersifat opsional (opt-in) sehingga trace default tetap berada pada tingkat tinggi. Hal ini terpisah dari Langfuse, yang tetap menjadi opsi yang direkomendasikan untuk observabilitas prompt dan model khusus GenAI.
