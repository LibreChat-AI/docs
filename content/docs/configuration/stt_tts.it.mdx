## Introduzione alla sintesi vocale [#speech-introduction]

La configurazione vocale include impostazioni sia per Speech-to-Text (STT) che per Text-to-Speech (TTS) all'interno di una sezione `speech:` unificata. Inoltre, è presente un nuovo menu `speechTab` per le impostazioni specifiche dell'utente.

> **Vedi anche:** Per lo schema di configurazione YAML dettagliato e tutte le opzioni disponibili, consulta la documentazione [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech).

### Variabili d'ambiente [#environment-variables]

Quando utilizzi servizi STT/TTS basati su cloud, dovrai impostare le chiavi API nel tuo file `.env`:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Queste chiavi vengono quindi referenziate nella configurazione del tuo `librechat.yaml` utilizzando `${STT_API_KEY}` e `${TTS_API_KEY}`.

### Un provider per servizio [#one-provider-per-service]

Ciascuno di `speech.stt` e `speech.tts` accetta al massimo un blocco di provider, ed entrambe le sezioni possono essere omesse per mantenere il motore del browser per quel servizio. Se una sezione ha più di un provider, le richieste non vanno a buon fine con l'errore "Multiple providers are set. Please set only one provider."

### I motori self-hosted necessitano di una voce allowedAddresses [#self-hosted-engines-need-an-allowedaddresses-entry]

Sia `speech.stt` che `speech.tts` accettano un elenco `allowedAddresses`. Le richieste vocali in uscita vengono convalidate rispetto al loro IP risolto e bloccate dal raggiungere spazi di indirizzi privati, di loopback e link-local, pertanto un motore self-hosted su `localhost`, un indirizzo LAN o un nome di servizio Docker non è raggiungibile finché non lo si elenca:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

Le voci sono coppie `host:port` semplici: senza schema o percorso, porta obbligatoria, IPv6 tra parentesi quadre come `[::1]:8080`, e i letterali IP devono essere privati. Gli endpoint cloud pubblici come OpenAI, Azure e ElevenLabs non necessitano di alcuna voce. La protezione opera sull'IP risolto, non sull'hostname, quindi un endpoint cloud raggiunto tramite Private Link, DNS privato o VPN viene risolto in uno spazio di indirizzi privati e richiede che il suo `host:port` esatto sia elencato come qualsiasi altro target privato. Lo stesso campo e le stesse regole si applicano sotto `speech.stt`. Vedi [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) per il formato completo della voce.

## Scheda Speech (opzionale) [#speech-tab-optional]

Il menu `speechTab` fornisce opzioni personalizzabili per le modalità conversazione e avanzata, oltre a impostazioni dettagliate per STT e TTS. Questo definirà le impostazioni predefinite per gli utenti.

Usa `browser` per la sintesi vocale integrata del browser o `external` per un provider lato server configurato di seguito. I valori predefiniti specifici del provider meno recenti rimangono accettati per compatibilità e vengono normalizzati a `external`; se il servizio esterno corrispondente non è disponibile, LibreChat ripiega su `browser`.

esempio:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` imposta i valori iniziali visualizzati dagli utenti; ciascuno rimane modificabile per utente nella scheda delle impostazioni vocali.

## STT (Speech-to-Text) [#stt-speech-to-text]

La funzionalità Speech-to-Text (STT) converte le parole pronunciate in testo scritto. Per abilitare STT, fai clic sul pulsante STT (vicino al pulsante di invio) oppure usa la combinazione di tasti ++Shift+Alt+L++ per avviare la trascrizione.

### Servizi STT disponibili [#available-stt-services]

- **STT locale**
  - Basato su browser
  - Whisper (testato su LocalAI)
- **Cloud STT**
  - OpenAI Whisper
  - Azure Whisper
  - Altri servizi STT compatibili con OpenAI

### Configurazione di STT locale [#configuring-local-stt]

- #### Browser-based
  Nessuna configurazione richiesta. Assicurati che l'interruttore "Speech To Text" nella scheda delle impostazioni vocali sia attivo e che "Browser" sia selezionato nel menu a tendina del motore.

- #### Whisper Locale [#whisper-local]
  Richiede un'istanza locale di Whisper.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

Il campo `apiKey` è obbligatorio per ogni blocco STT compatibile con OpenAI, inclusi quelli locali. Se il tuo server non verifica le chiavi, puoi usare un valore segnaposto qualsiasi.

### Configurazione di Cloud STT [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Supporto dominio endpoint Azure">
Il campo `instanceName` supporta entrambi i formati di dominio di Azure OpenAI:
- **Nuovo formato**: `.cognitiveservices.azure.com` (ad es., `my-instance.cognitiveservices.azure.com`)
- **Formato legacy**: `.openai.azure.com` (es. `my-instance.openai.azure.com`)

È possibile specificare il dominio completo o solo il nome dell'istanza. Se si fornisce un dominio completo che include `.azure.com`, questo verrà utilizzato così com'è. In caso contrario, verrà applicato il formato legacy `.openai.azure.com` per garantire la compatibilità con le versioni precedenti.
</Callout>

- #### Compatibile con OpenAI [#openai-compatible]

Fare riferimento alla sezione OpenAI Whisper, adattando `url` e `model` secondo necessità. Il campo `apiKey` è comunque obbligatorio.

esempio
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

La funzionalità Text-to-Speech (TTS) converte il testo scritto in parole parlate. Sono disponibili vari servizi TTS:

### Servizi TTS disponibili [#available-tts-services]

- **TTS Locale**
  - Basato su browser
  - Piper (testato su LocalAI)
  - Coqui (testato su LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Altri servizi TTS compatibili con OpenAI/ElevenLabs

Il testo più lungo di `speech.tts.maxInputChars` (valore predefinito 20000 caratteri) viene troncato prima di essere letto ad alta voce. Per maggiori dettagli, consulta la [Struttura dell'oggetto Speech](/docs/configuration/librechat_yaml/object_structure/speech).

### Configurazione di TTS locale [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

Nessuna configurazione richiesta. Assicurati che l'interruttore "Text To Speech" nella scheda delle impostazioni vocali sia abilitato e che "Browser" sia selezionato nel menu a discesa del motore.

- #### Piper [#piper]

Richiede un'istanza locale di Piper.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Richiede un'istanza locale di Coqui.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Configurazione di Cloud TTS [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Supporto dominio endpoint Azure">
Il campo `instanceName` supporta entrambi i formati di dominio di Azure OpenAI:
- **Nuovo formato**: `.cognitiveservices.azure.com` (ad es., `my-instance.cognitiveservices.azure.com`)
- **Formato legacy**: `.openai.azure.com` (es. `my-instance.openai.azure.com`)

È possibile specificare il dominio completo o solo il nome dell'istanza. Se si fornisce un dominio completo che include `.azure.com`, questo verrà utilizzato così com'è. In caso contrario, verrà applicato il formato legacy `.openai.azure.com` per garantire la compatibilità con le versioni precedenti.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Ulteriori parametri specifici per ElevenLabs possono essere aggiunti come segue:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### Compatibile con OpenAI [#openai-compatible-1]

Fare riferimento alla sezione OpenAI TTS, regolando la variabile `url` come necessario

esempio:

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Compatibile con ElevenLabs [#elevenlabs-compatible]

Fare riferimento alla sezione ElevenLabs, regolando la variabile `url` come necessario

esempio:

```yaml
speech:
  tts:
    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
```
