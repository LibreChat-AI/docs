Bienvenido a la guía completa para configurar el entorno de su aplicación con el archivo `.env`. Este documento es su recurso integral para comprender y personalizar las variables de entorno que definirán el comportamiento de su aplicación en diferentes contextos.

Si bien la configuración predeterminada proporciona una base sólida para una instalación estándar de `docker`, profundizar en esta guía revelará todo el potencial de LibreChat. Esta guía le permite adaptar LibreChat a sus necesidades precisas. Descubra cómo ajustar la disponibilidad de modelos de lenguaje, integrar inicios de sesión sociales, gestionar el sistema de moderación automática y mucho más. Se trata de darle el control para ajustar LibreChat y lograr una experiencia de usuario óptima.

> **Recordatorio: Por favor, reinicie LibreChat para que los cambios de configuración surtan efecto**

Alternativamente, puedes crear un nuevo archivo llamado `docker-compose.override.yml` en el mismo directorio que tu archivo principal `docker-compose.yml` para LibreChat, donde puedes establecer tus variables de .env según sea necesario bajo `environment`, o modificar la configuración predeterminada proporcionada por el `docker-compose.yml` principal, sin la necesidad de editar directamente o duplicar todo el archivo.

Para más información, consulta:

## Configuración del servidor [#server-configuration]

- El servidor escucha en un puerto específico.
- La variable de entorno `PORT` establece el puerto donde escucha el servidor. De forma predeterminada, está configurada en `3080`.

### Tiempos de espera del servidor HTTP [#http-server-timeouts]

Estos valores opcionales configuran el servidor HTTP de Node.js. Déjelos sin establecer para conservar los valores predeterminados de Node. Un valor de `0` deshabilita ese tiempo de espera.

      '# HTTP_KEEP_ALIVE_TIMEOUT_MS=70000',

    ],
    [
      'HTTP_HEADERS_TIMEOUT_MS',
      'integer',

Los valores deben ser enteros seguros no negativos; los valores no válidos se ignoran. Cuando tanto los tiempos de espera de cabecera como de solicitud están habilitados, LibreChat limita el tiempo de espera de cabecera al tiempo de espera de solicitud si este es mayor. Node verifica la expiración de la cabecera y la solicitud en un barrido de conexión de 30 segundos, por lo que los valores inferiores a `30000` no se aplican con una precisión exacta de milisegundos. Actualmente, Bun acepta estos ajustes pero no los aplica; LibreChat registra una advertencia cuando el servidor de API se ejecuta bajo Bun.

### Trust proxy [#trust-proxy]

Utilice la dirección que esté a una distancia máxima de n saltos de la aplicación Express.
req.socket.remoteAddress es el primer salto, y el resto se buscan en el encabezado X-Forwarded-For de derecha a izquierda.
Un valor de 0 significa que la primera dirección no confiable sería req.socket.remoteAddress, es decir, no hay un proxy inverso.
El valor predeterminado de la variable de entorno `TRUST_PROXY` está establecido en `1`.

Consulte [Express.js - trust proxy](https://expressjs.com/en/guide/behind-proxies.html) para obtener más información al respecto.

<OptionTable
  options={[['TRUST_PROXY', 'number', 'Especifica el número de saltos.', 'TRUST_PROXY=1']]}
/>

### Encabezado de inquilino de confianza (Trusted Tenant Header) [#trusted-tenant-header]

`TRUST_TENANT_HEADER` controla si LibreChat acepta `X-Tenant-Id` antes de la autenticación en los árboles de rutas `/oauth`, `/api/auth` y `/api/share`. Está desactivado de forma predeterminada; mientras está desactivado, esas rutas ignoran el encabezado.

<OptionTable
  options={[
    [
      'TRUST_TENANT_HEADER',
      'boolean',
      'Confiar en X-Tenant-Id en rutas de pre-autenticación. Habilitar solo detrás de un proxy de confianza que reemplace los valores proporcionados por el cliente.',
      'TRUST_TENANT_HEADER=false',
    ],
  ]}
/>

<Callout type="warning" title="No confíe en los encabezados de inquilino proporcionados por el cliente">
  Habilite esta configuración solo cuando un proxy inverso de confianza elimine todos los valores `X-Tenant-Id` entrantes y establezca el ID de inquilino autoritativo por sí mismo. De lo contrario, un cliente no confiable podría elegir el contexto de inquilino utilizado antes de la autenticación. LibreChat registra una advertencia de seguridad cuando esta configuración está habilitada.
</Callout>

Cuando `TENANT_ISOLATION_STRICT` está habilitado pero `TRUST_TENANT_HEADER` está deshabilitado, LibreChat advierte al inicio que los encabezados de inquilino de pre-autenticación serán ignorados.

### Configuración de credenciales [#credentials-configuration]

LibreChat utiliza `CREDS_KEY` y `CREDS_IV` para cifrar las credenciales compatibles almacenadas en la base de datos. Configure valores fijos y únicos para producción y comparta los mismos valores en cada réplica.

<OptionTable
  options={[
    [
      'CREDS_KEY',
      'string',
      'Clave de 32 bytes (64 caracteres hexadecimales) para almacenar credenciales de forma segura.',
      'CREDS_KEY=',
    ],
    [
      'CREDS_IV',
      'string',
      'IV de 16 bytes (32 caracteres hexadecimales) para almacenar credenciales de forma segura.',
      'CREDS_IV=',
    ],
    [
      'LIBRECHAT_TEMP_CREDENTIALS_PATH',
      'string',
      'Ruta utilizada para persistir las credenciales temporales generadas automáticamente. El valor predeterminado es `.env.temp` en el directorio de trabajo del proceso.',
      '# LIBRECHAT_TEMP_CREDENTIALS_PATH=/app/data/.env.temp',
    ],
  ]}
/>

Cuando cualquiera de `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET` o `JWT_REFRESH_SECRET` está vacío, LibreChat primero reutiliza un valor válido del archivo de credenciales temporales. Si no existe ninguno, genera un valor criptográficamente aleatorio y escribe el archivo con permisos exclusivos para el propietario. Los valores de entorno explícitos siempre tienen prioridad. LibreChat se niega a utilizar `.env` o `.env.example` como la ruta del archivo generado, evitando el reemplazo accidental de cualquiera de los archivos de configuración.

LibreChat también se niega a iniciarse cuando `JWT_SECRET` o `JWT_REFRESH_SECRET` todavía utilizan uno de los valores predeterminados publicados y retirados, independientemente de si el valor proviene del entorno o del archivo de credenciales temporales. Genere reemplazos únicos en lugar de trasladar antiguos secretos de ejemplo a una implementación.

Los archivos Docker Compose incluidos persisten `/app/data/.env.temp` en el volumen `librechat-data`, por lo que una única implementación de Compose puede reiniciarse sin cambiar estos valores generados. Si el archivo no puede persistirse, los valores serán locales al proceso y las sesiones o los registros cifrados podrían volverse inaccesibles después de un reinicio.

<Callout type="warning" title="Establecer valores permanentes para producción">
  La generación temporal es una conveniencia de arranque, no un sistema de rotación de credenciales. Antes de su uso en producción, genere valores permanentes con el [Credentials Generator](/toolkit/creds_generator), almacénelos en su gestor de secretos y proporcione los mismos valores a cada réplica. Cambiar una clave establecida no vuelve a cifrar los registros existentes. LibreChat registra las huellas digitales de las credenciales en la base de datos y advierte cuando los valores activos cambian; no sobrescriba ese marcador en lugar de realizar una migración controlada.
</Callout>

### Encabezados de seguridad y política de seguridad de contenido (Content Security Policy) [#security-headers-and-content-security-policy]

LibreChat envía encabezados base de HSTS, framing, content-type, opener, resource y referrer de forma predeterminada. `SECURITY_HEADERS=false` los deshabilita todos y también actúa como el interruptor global de CSP.

El CSP basado en nonce es una opción que se activa por separado con `CSP_ENABLED=true` y, de forma predeterminada, se encuentra en modo de solo informe. Comience con `CSP_REPORT_ONLY=true`, inspeccione las infracciones y añada solo los orígenes que requiera su despliegue antes de aplicar la política. Cuando el CSP está activo, el shell de la SPA siempre se envía con `Cache-Control: no-store` para que su nonce por respuesta no pueda ser reutilizado desde la caché.

Consulta [HTTP Security Headers](/docs/configuration/security_headers) para conocer todas las variables de línea base y CSP, los valores aceptados, los valores predeterminados, las anulaciones de listas de origen y la guía de implementación.

      'ENABLE_IMAGE_OUTPUT_GZIP_SCAN=true',
    ],
    [
      'ENABLE_STATIC_ASSET_BROTLI',
      'boolean',
      'Habilita el servicio de versiones Brotli precomprimidas de los activos estáticos de la aplicación cuando estén disponibles.',
      'ENABLE_STATIC_ASSET_BROTLI=true',
    ],
  ]}
/>

**Comportamiento:**

Establece los encabezados [Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Cache-Control) para archivos estáticos. Estas configuraciones solo se activan cuando `NODE_ENV` está configurado en `production`.

- Descomente `STATIC_CACHE_MAX_AGE` para cambiar el `max-age` local de los archivos estáticos. Por defecto, esto está configurado en 2 días (172800 segundos).
- Descomente `STATIC_CACHE_S_MAX_AGE` para establecer el `s-maxage` para cachés compartidas (CDNs y proxies). Por defecto, esto está configurado en 1 día (86400 segundos).
- Descomente `DISABLE_COMPRESSION` para desactivar la compresión de archivos estáticos. De forma predeterminada, la compresión está habilitada.
- Descomente `ENABLE_IMAGE_OUTPUT_GZIP_SCAN` para habilitar el escaneo y la entrega de versiones comprimidas en gzip de las imágenes si han sido precomprimidas en la misma carpeta, con el mismo nombre y una extensión .gz. De forma predeterminada, el escaneo gzip para imágenes subidas está deshabilitado.
- Descomente `ENABLE_STATIC_ASSET_BROTLI` para servir versiones `.br` precomprimidas de los activos estáticos de la aplicación cuando existan. Cuando está habilitado, se prefiere Brotli sobre gzip para los archivos estáticos servidos por la API.

<Callout type="warning" title="Advertencia">
  - Esto solo afecta a los archivos estáticos servidos por el servidor de la API y no es aplicable a _Firebase_, _NGINX_ o cualquier otra configuración.
</Callout>

**Comportamiento:**

Controla los encabezados de caché específicamente para la respuesta index.html. De forma predeterminada, estos ajustes evitan el almacenamiento en caché para garantizar que los usuarios siempre obtengan la versión más reciente de la aplicación.

<Callout type="note" title="Nota">
  A diferencia de los activos estáticos que se almacenan en caché para mejorar el rendimiento, los encabezados de caché del archivo index.html se configuran por separado para garantizar que los usuarios siempre obtengan el shell de la aplicación más reciente.
</Callout>

### Evitar que los motores de búsqueda públicos indexen el sitio [#prevent-public-search-engines-indexing]

De forma predeterminada, su sitio web no será indexado por motores de búsqueda públicos (por ejemplo, Google, Bing, ...). Esto significa que las personas no podrán encontrar su sitio web a través de estos motores de búsqueda. Si desea hacer que su sitio web sea más visible y fácil de encontrar, puede cambiar la siguiente configuración a `false`

<OptionTable
  options={[
    [
      'NO_INDEX',
      'boolean',
      'Evita que los motores de búsqueda públicos indexen tu sitio web.',
      'NO_INDEX=true',
    ],
  ]}
/>

❗**Nota:** No se garantiza que este método funcione para todos los motores de búsqueda, y algunos motores de búsqueda aún podrían indexar su sitio web o página web para otros fines, como el almacenamiento en caché o el archivo. Por lo tanto, no debe confiar únicamente en este método para proteger información sensible o confidencial en su sitio web o página web.

### Registro [#logging]

LibreChat tiene un sistema de registro central integrado, consulta [Logging System](/docs/configuration/logging) para más información.

#### Archivos de registro [#log-files]

- El registro de depuración (debug logging) está habilitado de forma predeterminada y es crucial para el desarrollo.
- Para reportar problemas, reproduzca el error y envíe los registros de `./api/logs/debug-%DATE%.log` en: **[LibreChat GitHub Issues](https://github.com/LibreChat-AI/LibreChat/issues)**
- Los registros de error se almacenan en la misma ubicación.

### Endpoint de Intérprete de Código con Estado [#stateful-code-interpreter-endpoint]

[`stateful_code_sessions`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) es altamente experimental y requiere una ruta de Code Interpreter independiente. Configure la ruta predeterminada con `LIBRECHAT_CODE_BASEURL_STATEFUL`, o defina backends gestionados o adjuntos con nombre bajo [`endpoints.agents.statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). El servicio seleccionado debe ejecutar el perfil `stateful`; LibreChat envía `X-CodeAPI-Expected-Profile: stateful` con las solicitudes stateful.

Las solicitudes con estado (stateful) nunca recurren a `LIBRECHAT_CODE_BASEURL`. Si el entorno nombrado seleccionado no está disponible, o si no se ha configurado ni un valor predeterminado nombrado ni `LIBRECHAT_CODE_BASEURL_STATEFUL`, LibreChat detiene la ejecución del Agente con un error de configuración. Los agentes sin estado (stateless) continúan utilizando `LIBRECHAT_CODE_BASEURL`, y ambos perfiles de ejecución no comparten un espacio de trabajo activo.

Cada Agent puede limitar su espacio de trabajo con estado al usuario que ha iniciado sesión, al usuario y al Agent juntos, o al usuario y la conversación. Consulta [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions) para conocer la configuración y las limitaciones de persistencia.

Los entornos adjuntos con nombre también pueden exponer un plano de control de emparejamiento de autoservicio con `pairing.allowPrincipalWorkers: true`. Los usuarios autorizados gestionan esos trabajadores vinculados al propietario en **Settings > Code environments**; las entradas exclusivas de emparejamiento no reemplazan a `LIBRECHAT_CODE_BASEURL_STATEFUL` y no pueden servir como el valor predeterminado de despliegue.

Los permisos de rol ahora controlan quién puede crear enlaces compartidos, compartirlos con usuarios autenticados o hacerlos visibles para todos; consulte [`interface.sharedLinks`](/docs/configuration/librechat_yaml/object_structure/interface#sharedlinks). `ALLOW_SHARED_LINKS_PUBLIC` solo controla si los enlaces compartidos públicamente pueden verse sin autenticación. `SHARED_LINKS_SNAPSHOT_FILES` es una anulación global para las instantáneas de archivos de enlaces compartidos y puede deshabilitar el servicio de instantáneas para cada enlace cuando se establece en `false`.

Cada lectura de un enlace compartido utiliza el bucket de IP porque los enlaces públicos son accesibles sin autenticación. Los usuarios que han iniciado sesión también utilizan el bucket de usuario. Superar cualquiera de los límites devuelve un HTTP 429; un `SHARE_VIOLATION_SCORE` distinto de cero registra el evento en el sistema de infracciones existente.

### Moderación [#moderation]

El Sistema de Moderación Automatizado utiliza un mecanismo de puntuación para realizar un seguimiento de las infracciones de los usuarios. Este sistema garantiza la seguridad de la plataforma mediante la supervisión y penalización de actividades rápidas o sospechosas.

#### Gestión de saldos [#managing-balances]

- Ejecuta `npm run add-balance` para añadir saldos manualmente.
  - También puede especificar el correo electrónico y la cantidad de créditos de token a añadir, por ejemplo: `npm run add-balance example@example.com 1000`
- Ejecuta `npm run set-balance` para establecer saldos manualmente, de forma similar a `add-balance`.
- Ejecuta `npm run list-balances` para listar el saldo de cada usuario.

> **Nota:** 1000 créditos = $0.001 (1 mil USD)

**Todo lo siguiente debe estar configurado para que la integración con SharePoint funcione:**

- **`OPENID_REUSE_TOKENS=true`** es obligatorio (utiliza el flujo de token on-behalf-of)
- `OPENID_SCOPE` debe incluir el scope de la API de tu aplicación LibreChat, por ejemplo `api://<client-id>/access_as_user`
- `OPENID_ON_BEHALF_FLOW_FOR_USERINFO_REQUIRED=true` es necesario cuando se utiliza ese scope de app-audience con Azure Entra ID
- Su registro de aplicación de Azure debe tener permisos de SharePoint y Graph API
- El registro de tu aplicación Azure debe exponer el ámbito (scope) de la API de LibreChat utilizado en `OPENID_SCOPE`
- Las cuatro variables de entorno de SharePoint deben estar configuradas
- HTTPS es obligatorio en entornos de producción
</Callout>

<Callout type="info" title="Capacidades de las funciones">
  Cuando está habilitado, los usuarios pueden:
- Acceder a archivos desde bibliotecas de documentos de SharePoint y OneDrive for Business
- Seleccionar varios archivos a la vez (máximo predeterminado: 10 archivos)
- Ver el progreso de descarga en tiempo real
  - Los archivos se descargan y se adjuntan a la conversación como archivos subidos normales
</Callout>

- Los clientes actuales de LibreChat negocian el protocolo de generación v2 automáticamente. La variable retirada `GENERATION_PROTOCOL_VERSION` ya no se lee. Consulte [Generation Protocol Compatibility](/docs/configuration/redis#generation-protocol-compatibility) antes de mezclar versiones de lanzamiento o realizar reversiones.
- Habilite `STREAM_DELTA_COALESCE_MS` solo después de que cada réplica admita tramas por lotes. Los suscriptores más antiguos descartan las tramas fusionadas. Consulte [Stream Delta Coalescing](/docs/configuration/redis#stream-delta-coalescing).
- Para el modo Redis Cluster, proporcione múltiples URIs: `redis://node1:7001,redis://node2:7002,redis://node3:7003` (el modo cluster se detecta automáticamente).
- Para servicios de Redis gestionados de punto de conexión único que fragmentan claves internamente, mantenga `USE_REDIS_CLUSTER=false` y establezca `REDIS_CLUSTER_SAFE_DELETE=true` si los borrados de caché fallan con errores `CROSSSLOT`.
- `REDIS_READONLY_RECOVERY_INTERVAL` aplica un debounce a los intentos de reconexión de Keyv después de que una conmutación por error (failover) deje un socket abierto conectado a una réplica de solo lectura degradada. Los clientes de Redis Cluster utilizan su propio manejo de topología en su lugar.
- `REDIS_PING_INTERVAL` controla el heartbeat opcional en el cliente principal de ioredis; los suscriptores dedicados de pub/sub utilizan `REDIS_SUBSCRIBER_PING_INTERVAL` para que se detecte un socket inactivo que de otro modo parecería estar muerto. Ambos utilizan `REDIS_PING_TIMEOUT` como fecha límite de respuesta y se reconectan cuando esta expira.
- Utilice el protocolo `rediss://` para conexiones TLS y configure `REDIS_CA` si su CA no es de confianza pública.
- `REDIS_KEY_PREFIX_VAR` y `REDIS_KEY_PREFIX` son mutuamente excluyentes.
- **AWS Elasticache con TLS**: Es posible que Elasticache necesite usar un dnsLookup alternativo para conexiones TLS. Establezca `REDIS_USE_ALTERNATIVE_DNS_LOOKUP=true` si utiliza Elasticache con TLS. Consulte la [documentación de ioredis](https://www.npmjs.com/package/ioredis) para obtener más detalles.
