RAG API, kullanıcı tarafından yüklenen dosyaları indeksler ve istemlerinizi zenginleştirmek için ilgili pasajları getirerek LibreChat'in belgelerinize dayalı, bağlama duyarlı yanıtlar vermesini sağlar. PostgreSQL + pgvector veritabanı tarafından desteklenen ayrı bir FastAPI servisi olarak çalışır.

<Callout type="info" title="Kullanıcıların gördükleri">
[Dosyalarla Sohbet](/docs/features/rag_api) dosya yükleme, dosya arama için yeniden kullanım ve agent'larda dosya arama konularını kapsar. Bu sayfa kurulum ve yapılandırmayı ele alır.
</Callout>

## Kullanılabilirlik [#availability]

RAG API üzerinden dosya arama, [Agents](/docs/features/agents) ve Assistants dışındaki tüm uç noktalardaki normal sohbetlerde çalışır. OpenAI Assistants, bunun yerine OpenAI'ın kendi dosya depolama ve geri getirme sistemini kullanır; bu nedenle orada yüklenen dosyalar başka yerlerde eklenemez.

Kullanıcılar, yalnızca `file_search` ajan yeteneği etkinleştirildiğinde (varsayılan olarak etkindir) ve rollerinin Dosya Arama izni bulunduğunda **Dosya Arama için Yükle** seçeneğini görür ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Docker ile Hızlı Başlangıç [#docker-quick-start]

Docker için RAG API, varsayılan `docker-compose.yml` ve `deploy-compose.yml` dosyalarında `RAG_API_URL` değeri dahil olmak üzere zaten yapılandırılmıştır. Yalnızca en son imaj ve compose dosyalarını çalıştırdığınızdan emin olmanız gerekir. Güncelleme konusunda emin değilseniz, [Docker için LibreChat'i güncelleme kılavuzuna](/docs/local/docker#updating-librechat) bakabilirsiniz.

<Callout type="warning" title="Paylaşılan .env dosyası">
Varsayılan Docker kurulumunda, `.env` dosyası LibreChat ve RAG API arasında paylaşılır. RAG değişkenlerini aynı dosya içinde tanımlayın. Listenin tamamı [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md) dosyasında yer almaktadır.
</Callout>

The default `docker-compose.yml` and `deploy-compose.yml` files set `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` on the `api` service. Environment variables set on the service take precedence over the `.env` file, so you do not need to add `RAG_API_URL` to `.env` for the bundled setup, and setting it there has no effect. To point a Docker deployment at an external RAG API, override the value on the `api` service instead, for example for a RAG API running on the Docker host:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

`extra_hosts` girdisi Linux'ta gereklidir, çünkü Docker bu ortamda `host.docker.internal` adresini kendiliğinden tanımlamaz.

Compose, `docker-compose.override.yml` dosyasını yalnızca varsayılan `docker-compose.yml` ile birlikte otomatik olarak yükler. `deploy-compose.yml` kullanırken her iki dosyayı da belirtmeniz gerekir: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Docker dışında, `.env` dosyanızda `RAG_API_URL` değerini ayarlayın.

### Lite ve tam sürüm imajı [#lite-vs-full-image]

Docker, varsayılan olarak RAG API'sinin "lite" imajını (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`) kullanır; bu imaj yalnızca OpenAI'dan gelen uzak yerleştirmeleri (embeddings) veya yapılandırdığınız uzak bir HuggingFace/Ollama hizmetini destekler.

Yerel yerleştirmeler (embeddings) için, compose dosyasındaki imajı tam yapılandırma olan `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest` ile değiştirin. Bu değişikliği [Docker Compose Override File](/docs/configuration/docker_override) dosyanızda yapın. Bir örnek için projenin kök dizinindeki `docker-compose.override.yml.example` dosyasına bakın.

Yalnızca PostgreSQL + pgvector veritabanını ve Python API'sini içeren bir compose dosyası istiyorsanız, projenin kök dizinindeki `rag.yml` dosyasına bakın.

### Veritabanı depolama [#database-storage]

Varsayılan compose dosyaları, pgvector/PostgreSQL verilerini Docker tarafından yönetilen `pgdata2` biriminde (volume) saklar. Bu kasıtlı bir durumdur: veritabanı dosyalarının doğrudan ana bilgisayardan (host) düzenlenmesine gerek yoktur ve yönetilen bir birim, yaygın sahiplik ve izin sorunlarını önler. Kullanıcıya dönük, düzenlenebilir dosyalar (yüklemeler, günlükler, görseller, MongoDB verileri ve NGINX yapılandırması), doğrudan ana bilgisayar erişiminin yararlı olduğu proje klasörlerine bind-mount yöntemiyle bağlanır.

## Yerel Kurulum [#local-setup]

Konteyner dışı bir kurulum daha fazla manuel işlem gerektirir. [RAG API repo](https://github.com/LibreChat-AI/rag-api/) içindeki talimatları izleyin.

`RAG_API_URL` değerini, RAG API'sine kurulumunuzdan erişilebilecek adres olacak şekilde LibreChat `.env` dosyanızda ayarlayın. Bu, değerin varsayılan `docker-compose.yml` ve `deploy-compose.yml` dosyalarında `api` servisinde zaten ayarlandığı paketlenmiş Docker kurulumundan farklıdır.

## Kullanım [#usage]

RAG API erişilebilir hale geldiğinde LibreChat'te başka bir şeyi etkinleştirmeniz gerekmez. Kullanıcılar **Dosya Araması için Yükle** seçeneğiyle dosya yükler ve bir soru gerektirdiğinde model, `file_search` aracı aracılığıyla dizine sorgu gönderir. `RAG_API_URL` ayarlanmamışsa veya hizmet çalışmıyorsa bu yüklemeler başarısız olur; LibreChat, RAG API sağlık kontrolüne ulaşamadığında başlangıçta bir uyarı kaydeder. Kullanıcı tarafı için bkz. [Dosyalarla Sohbet](/docs/features/rag_api).

## Sorun Giderme [#troubleshooting]

RAG API'sini kurarken veya kullanırken sorunlarla karşılaşırsanız:

- `.env` dosyanızda gerekli tüm ortam değişkenlerinin doğru şekilde ayarlandığından emin olun.
- Vektör veritabanının yapılandırıldığından ve erişilebilir olduğundan emin olun.
- OpenAI API anahtarının veya diğer sağlayıcı kimlik bilgilerinin geçerli olduğunu doğrulayın.
- Hatalar veya uyarılar için hem LibreChat hem de RAG API günlüklerini kontrol edin.

Sorun devam ederse, RAG API dokümantasyonuna başvurun veya GitHub Discussions ya da Discord üzerindeki LibreChat topluluğuna sorun.
