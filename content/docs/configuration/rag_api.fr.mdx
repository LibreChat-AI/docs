L'API RAG indexe les fichiers téléchargés par les utilisateurs et récupère les passages pertinents pour enrichir vos prompts, offrant ainsi à LibreChat des réponses contextuelles basées sur vos documents. Elle fonctionne en tant que service FastAPI distinct, soutenu par une base de données PostgreSQL + pgvector.

<Callout type="info" title="Ce que voient les utilisateurs">
[Discuter avec des fichiers](/docs/features/rag_api) explique le téléversement de fichiers pour la recherche dans les fichiers, la réutilisation de fichiers et la recherche dans les fichiers au sein des agents. Cette page traite de l'installation et de la configuration.
</Callout>

## Disponibilité [#availability]

La recherche de fichiers via l'API RAG fonctionne dans les [Agents](/docs/features/agents) et dans les conversations classiques sur tous les endpoints, à l'exception d'Assistants. Les Assistants OpenAI utilisent à la place le stockage et la récupération de fichiers propres à OpenAI, et les fichiers téléversés à cet endroit ne peuvent pas être joints ailleurs.

Les utilisateurs ne voient **Upload for File Search** que lorsque la capacité d'agent `file_search` est activée (ce qui est le cas par défaut) et que leur rôle dispose de l'autorisation File Search ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Démarrage rapide avec Docker [#docker-quick-start]

Pour Docker, l'API RAG est déjà configurée dans les fichiers `docker-compose.yml` et `deploy-compose.yml` par défaut, y compris la valeur `RAG_API_URL`. Vous devez seulement vous assurer d'utiliser la dernière image et les derniers fichiers compose. Consultez le [guide de mise à jour de LibreChat pour Docker](/docs/local/docker#updating-librechat) si vous ne savez pas comment effectuer la mise à jour.

<Callout type="warning" title="Fichier .env partagé">
Avec la configuration Docker par défaut, le fichier `.env` est partagé entre LibreChat et l'API RAG. Définissez les variables RAG dans ce même fichier. La liste complète se trouve dans le [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

Les fichiers `docker-compose.yml` et `deploy-compose.yml` par défaut définissent `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` sur le service `api`. Les variables d'environnement définies sur le service sont prioritaires sur le fichier `.env` ; vous n'avez donc pas besoin d'ajouter `RAG_API_URL` à `.env` pour la configuration fournie, et l'ajouter là n'a aucun effet. Pour faire pointer un déploiement Docker vers une API RAG externe, remplacez plutôt la valeur sur le service `api`, par exemple pour une API RAG exécutée sur l'hôte Docker :

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

L'entrée `extra_hosts` est nécessaire sous Linux, où Docker ne définit pas lui-même `host.docker.internal`.

Compose charge automatiquement `docker-compose.override.yml` uniquement avec le fichier par défaut `docker-compose.yml`. Avec `deploy-compose.yml`, passez les deux fichiers : `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

En dehors de Docker, définissez `RAG_API_URL` dans votre fichier `.env`.

### Lite vs. full image [#lite-vs-full-image]

Docker utilise par défaut l'image « lite » de l'API RAG (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), qui ne prend en charge que les embeddings distants provenant d'OpenAI ou d'un service HuggingFace/Ollama distant que vous avez configuré.

Pour les embeddings locaux, remplacez l'image dans le fichier compose par la version complète, `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Effectuez ce changement dans votre [Fichier de remplacement Docker Compose](/docs/configuration/docker_override). Consultez `docker-compose.override.yml.example` à la racine du projet pour un exemple.

Si vous souhaitez un fichier compose qui inclut uniquement la base de données PostgreSQL + pgvector et l'API Python, consultez `rag.yml` à la racine du projet.

### Stockage de base de données [#database-storage]

Les fichiers compose par défaut stockent les données pgvector/PostgreSQL dans le volume `pgdata2` géré par Docker. C'est intentionnel : les fichiers de la base de données n'ont pas besoin d'être modifiés directement depuis l'hôte, et un volume géré évite les problèmes courants de propriété et de permissions. Les fichiers modifiables par l'utilisateur (téléversements, journaux, images, données MongoDB et configuration NGINX) sont montés via des bind-mounts dans les dossiers du projet où un accès direct depuis l'hôte est utile.

## Configuration locale [#local-setup]

Une installation sans conteneur est plus manuelle. Suivez les instructions dans le [dépôt RAG API](https://github.com/LibreChat-AI/rag-api/).

Définissez `RAG_API_URL` dans votre fichier `.env` de LibreChat avec l'adresse à laquelle l'API est accessible depuis votre configuration. Cela diffère de la configuration Docker fournie, où la valeur est déjà définie sur le service `api` dans les fichiers `docker-compose.yml` et `deploy-compose.yml` par défaut.

## Configuration [#configuration]

Définissez les options de l'API RAG via des variables d'environnement dans un fichier `.env` accessible à l'API. La plupart sont facultatives, à l'exception des identifiants et des chemins requis par le fournisseur que vous avez choisi. Dans la configuration par défaut, seule `RAG_OPENAI_API_KEY` est requise.

## Utilisation [#usage]

Une fois l'API RAG accessible, il n'y a rien d'autre à activer dans LibreChat. Les utilisateurs téléversent leurs fichiers via **Upload for File Search**, et le modèle interroge l'index à l'aide de l'outil `file_search` lorsqu'une question le nécessite. Si `RAG_API_URL` n'est pas défini ou si le service est arrêté, ces téléversements échouent ; LibreChat journalise un avertissement au démarrage lorsqu'il ne parvient pas à joindre le point de contrôle de santé de l'API RAG. Pour le côté utilisateur, consultez [Chat with Files](/docs/features/rag_api).

## Dépannage [#troubleshooting]

Si vous rencontrez des problèmes lors de la configuration ou de l'utilisation de l'API RAG :

- Assurez-vous que toutes les variables d'environnement requises sont correctement définies dans votre fichier `.env`.
- Assurez-vous que la base de données vectorielle est configurée et accessible.
- Vérifiez que la clé API OpenAI ou les autres identifiants de fournisseur sont valides.
- Vérifiez les journaux de LibreChat et de l'API RAG pour détecter d'éventuelles erreurs ou avertissements.

Si le problème persiste, consultez la documentation de l'API RAG ou demandez à la communauté LibreChat sur GitHub Discussions ou Discord.
