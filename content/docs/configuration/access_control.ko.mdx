사용자에게 역할, 그룹, 공유가 어떻게 작동하는지는 [Access Control](/docs/features/access_control) 기능 페이지에 설명되어 있습니다. 이 페이지에서는 관리자가 설정하는 내용을 다룹니다.

## 기능 권한 [#feature-permissions]

각 역할은 권한 유형별로 하나의 설정 스위치 세트를 가집니다. 다음 세 곳에서 이 설정을 변경할 수 있습니다.

- LibreChat에서 에이전트, 프롬프트, MCP 서버, 메모리, 스킬 패널의 **관리자 설정** 버튼을 통해 설정합니다(관리자 전용).
- 관리자 패널([Admin Panel](/docs/features/admin_panel))에서 **Access** 아래, 사용자 지정 역할을 포함한 모든 역할에 대해.
- In the [`interface`](/docs/configuration/librechat_yaml/object_structure/interface) block of `librechat.yaml`. 이 키들은 시작 시에만 기본 `USER` 역할의 권한을 설정하므로, 사용자 지정 역할마다 다른 설정을 적용할 수는 없습니다.

이 표는 각 권한 유형, 이를 설정하는 `interface` 키, 해당 작업들, 그리고 `USER` 역할이 기본적으로 가지고 있는 작업을 나열합니다.

| 권한 유형 | `interface` 키 | 작업 | `USER`에 기본 활성화 |
| --------------- | --------------- | ------- | ------------------------ |
| `AGENTS` | `agents` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `PROMPTS` | `prompts` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `MCP_SERVERS` | `mcpServers` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC`, `CONFIGURE_OBO` | `USE`, `CREATE` |
| `SKILLS` | `skills` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `REMOTE_AGENTS` | `remoteAgents` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | 없음 |
| `SHARED_LINKS` | `sharedLinks` | `CREATE`, `SHARE`, `SHARE_PUBLIC` | `CREATE`, `SHARE` |
| `SCHEDULES` | `schedules` | `USE`, `CREATE` | `USE`, `CREATE` |
| `MEMORIES` | `memories` | `USE`, `CREATE`, `UPDATE`, `READ`, `OPT_OUT` | 전체 |
| `BOOKMARKS` | `bookmarks` | `USE` | `USE` |
| `MULTI_CONVO` | `multiConvo` | `USE` | `USE` |
| `TEMPORARY_CHAT` | `temporaryChat` | `USE` | `USE` |
| `RUN_CODE` | `runCode` | `USE` | `USE` |
| `WEB_SEARCH` | `webSearch` | `USE` | `USE` |
| `FILE_SEARCH` | `fileSearch` | `USE` | `USE` |
| `FILE_CITATIONS` | `fileCitations` | `USE` | `USE` |
| `MARKETPLACE` | `marketplace` | `USE` | 없음 |
| `PEOPLE_PICKER` | `peoplePicker` | `VIEW_USERS`, `VIEW_GROUPS`, `VIEW_ROLES` | 전체 |

`SHARE`는 역할이 특정 사용자, 그룹 또는 역할과 공유할 수 있도록 합니다. `SHARE_PUBLIC`은 인스턴스의 모든 사용자와 공유할 수 있도록 합니다. `CONFIGURE_OBO`는 MCP 서버에서 On-Behalf-Of 토큰 교환을 설정할 수 있도록 하며, 이를 통해 사용자의 위임된 토큰이 해당 서버로 전달됩니다. 따라서 이 기능은 기본적으로 비활성화되어 있습니다.

## 사람 선택기 [#people-picker]

`PEOPLE_PICKER` 액션은 공유 대화상자의 검색에서 역할(role)이 찾을 수 있는 주체(principal)의 종류를 제어합니다. 역할별 공유는 관리자의 영역으로 남겨 두어야 하는 경우가 많으므로, 역할을 숨기는 설정이 흔히 사용됩니다.

```yaml filename="librechat.yaml"
interface:
  peoplePicker:
    users: true
    groups: true
    roles: false
```

이것은 검색 결과에 표시되는 내용만 변경합니다. 숨겨진 주체 유형(principal type)이 있는 기존 공유는 계속 작동합니다. [`interface.peoplePicker`](/docs/configuration/librechat_yaml/object_structure/interface#peoplepicker)를 참조하세요.

## Entra ID 그룹 동기화 [#entra-id-group-sync]

Microsoft Entra ID의 그룹은 `OPENID_REUSE_TOKENS=true` 설정으로 Entra를 통해 OpenID Connect 로그인을 할 때 LibreChat에 동기화됩니다. LibreChat은 로그인할 때마다 Microsoft Graph에서 사용자의 그룹 멤버십을 읽고, 각 그룹을 Entra 객체 ID와 함께 저장합니다. 따라서 그룹의 이름이 바뀌더라도 공유된 그룹은 동일한 그룹으로 유지됩니다. 공급자 설정은 [Azure / Entra ID](/docs/configuration/authentication/OAuth2-OIDC/azure)를, 토큰 재사용 설정은 [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse)를 참고하여 구성하세요.

## 다른 관리자 승격하기 [#promote-another-admin]

단일 테넌트 배포에서는 가장 먼저 등록된 계정이 `ADMIN` 역할을 받습니다. 테넌트 범위 배포에서는 첫 번째 사용자가 자동으로 관리자로 승격되지 않습니다. 테넌트 관리자는 신뢰할 수 있는 관리 절차를 통해 프로비저닝하세요. 기존 다른 사용자를 관리자로 지정하려면 관리 패널의 **Users** 페이지를 사용하거나, MongoDB에서 직접 역할을 설정하세요:

```js filename="mongosh"
db.users.updateOne({ email: 'USER_EMAIL_ADDRESS' }, { $set: { role: 'ADMIN' } })
```

사용자가 로그아웃했다가 다시 로그인하도록 하세요. OpenID Connect를 사용하면 `OPENID_ADMIN_ROLE`을 통해 IdP 역할 또는 그룹에서 `ADMIN` 권한을 부여할 수도 있습니다. 자세한 내용은 [.env 참조](/docs/configuration/dotenv#openid-connect)를 확인하세요.

## 관리자 기능 [#admin-capabilities]

기능(Capabilities)은 Admin Panel의 **Grants** 페이지에서 사용자, 그룹 또는 역할에 부여됩니다. `ADMIN` 역할을 가진 사용자는 이 모든 기능을 암묵적으로 보유합니다. 그 외의 사용자는 관리하는 대상에 해당하는 기능과 함께 `access:admin`이 필요합니다. 각 `manage:` 기능은 대응하는 `read:` 기능을 함께 부여하며, 섹션별로도 마찬가지입니다. 예를 들어 `manage:configs:endpoints`는 `read:configs:endpoints`도 부여합니다. 섹션 단위의 설정 접근 권한만 가진 사용자는 자신이 읽을 수 있는 섹션으로 필터링된 설정 응답을 받으며, 설정 읽기 권한이 전혀 없으면 `403`을 받습니다.

| 권한 | 허용 범위 |
| ---------- | ------ |
| `access:admin` | 관리자 패널 로그인 |
| `read:users`, `manage:users` | 사용자 계정 조회 및 변경 |
| `read:groups`, `manage:groups` | 그룹 및 그룹 멤버 조회 및 변경 |
| `read:roles`, `manage:roles` | 역할 및 역할 권한 조회 및 변경 |
| `read:configs`, `manage:configs` | 구성 조회 및 변경; `read:configs:<section>` 및 `manage:configs:<section>`은 하나의 최상위 `librechat.yaml` 섹션으로 범위를 제한 |
| `assign:configs:user`, `assign:configs:group`, `assign:configs:role` | 해당 유형의 주체에 구성 재정의 할당 |
| `read:agents`, `manage:agents` | 모든 에이전트 조회 및 관리 |
| `read:prompts`, `manage:prompts` | 모든 프롬프트 조회 및 관리 |
| `read:skills`, `manage:skills` | 모든 스킬 조회 및 관리 |
| `read:sharedlinks`, `manage:sharedlinks` | 모든 공유 링크 조회 및 관리 |
| `manage:mcpservers` | 인스턴스 전체의 MCP 서버 관리 |
| `manage:code_environments` | 배포 소유 코드 실행 워커 등록 및 해지 |
| `read:usage` | 사용량 데이터 조회 |
| `read:insights` | 모든 에이전트의 [Insights](/docs/features/insights) 조회 |
| `read:audit_log` | 권한 감사 로그 조회, 검증 및 내보내기. 추가 전용(append-only)이므로 `manage:` 대응 권한은 없음 |

`read:assistants` 및 `manage:assistants`도 존재하지만 예약되어 있으며, 아직 이를 강제하는 기능은 없습니다.

## 그룹 멤버십 캐시 [#group-membership-cache]

권한을 확인하기 위해 LibreChat은 사용자가 속한 그룹을 조회하고 그 결과를 5분 동안 캐시합니다. 그룹 구성원이 변경되면 영향을 받는 항목은 즉시 캐시에서 삭제됩니다. 사용자의 역할(role)은 캐시되지 않습니다. 캐시 또는 잠금(lock) 오류가 발생하면 데이터베이스로 대체 조회하며, 이 경우에도 권한 확인이 차단되지는 않습니다.

## 관리자 인사이트 [#admin-insights]

[Insights](/docs/features/insights) 대시보드는 기본적으로 꺼져 있습니다. `.env`에서 `ENABLE_INSIGHTS=true`로 설정한 뒤 LibreChat을 재시작하세요. 이 설정이 꺼져 있는 동안에는 Insights 라우트가 `404`를 응답하고, 사이드바 항목은 계속 숨겨진 상태로 유지됩니다.

관리자는 기능이 활성화되면 바로 열어 볼 수 있습니다. 다른 사용자에게도 열람 권한을 주려면 관리자 패널에서 `read:insights`(모든 에이전트 대상)를 부여하거나, 특정 사용자 또는 그룹에 대해 에이전트의 공유 대화상자에서 **View insights**를 켜면 됩니다. **View insights**는 관리자만 부여할 수 있으며, 해당 사용자는 에이전트 자체에 대한 접근 권한도 있어야 합니다. 또한 모든 사용자에게 부여할 수는 없습니다. Insights에는 이름, 이메일 주소, 최근 대화의 첫 메시지가 표시되므로 이를 고려하여 신중하게 권한을 부여하시기 바랍니다.

모든 Insights 쿼리는 조회자의 테넌트 범위로 제한되며, 사용자 지정 날짜 범위는 30일로 제한됩니다.

## pre-ACL 버전에서 마이그레이션 [#migrating-from-pre-acl-versions]

이전 버전(v0.8.0-rc3 이전)에서는 에이전트와 프롬프트에 대해 더 단순한 소유권 모델을 사용했습니다. 업그레이드한 후에는 마이그레이션을 실행하여 기존 에이전트와 프롬프트에 계속 접근할 수 있도록 하십시오. LibreChat은 마이그레이션되지 않은 에이전트를 발견하면 시작 시 경고를 표시합니다. 공유 링크는 이후에 동일한 시스템으로 이전되었으므로, 그 이전에 생성된 공유 링크가 있는 인스턴스는 공유 링크 마이그레이션도 실행해야 합니다.

먼저 드라이 런(dry run)을 실행해 어떤 변경이 적용될지 확인한 다음 마이그레이션을 실행하세요. `:batch` 변형은 한 번에 50개의 레코드를 처리하므로 대용량 데이터베이스에서 도움이 됩니다.
