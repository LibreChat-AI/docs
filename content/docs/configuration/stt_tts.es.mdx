## Introducción a la voz [#speech-introduction]

La configuración de voz (Speech Configuration) incluye ajustes tanto para la conversión de voz a texto (STT) como de texto a voz (TTS) bajo una sección unificada `speech:`. Además, hay un nuevo menú `speechTab` para los ajustes específicos del usuario.

> **Véase también:** Para obtener el esquema de configuración YAML detallado y todas las opciones disponibles, consulte la documentación de [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech).

### Variables de entorno [#environment-variables]

Al utilizar servicios de STT/TTS basados en la nube, necesitará configurar las claves de API en su archivo `.env`:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Estas claves se referencian entonces en su configuración de `librechat.yaml` utilizando `${STT_API_KEY}` y `${TTS_API_KEY}`.

### Un proveedor por servicio [#one-provider-per-service]

Cada uno de `speech.stt` y `speech.tts` acepta como máximo un bloque de proveedor, y cualquiera de las dos secciones puede omitirse para mantener el motor del navegador para ese servicio. Si una sección tiene más de un proveedor, las solicitudes fallan con el error "Multiple providers are set. Please set only one provider."

### Los motores autohospedados necesitan una entrada allowedAddresses [#self-hosted-engines-need-an-allowedaddresses-entry]

Tanto `speech.stt` como `speech.tts` aceptan una lista `allowedAddresses`. Las solicitudes de voz salientes se validan contra su IP resuelta y se bloquea su acceso a espacios de direcciones privadas, de bucle local (loopback) y de enlace local (link-local), por lo que un motor autohospedado en `localhost`, una dirección LAN o un nombre de servicio de Docker no será accesible hasta que lo incluyas en la lista:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

Las entradas son pares `host:port` simples: sin esquema ni ruta, el puerto es obligatorio, las direcciones IPv6 deben ir entre corchetes como `[::1]:8080`, y los literales IP deben ser privados. Los endpoints de nube pública como OpenAI, Azure y ElevenLabs no necesitan entrada. La protección funciona sobre la IP resuelta, no sobre el nombre de host, por lo que un endpoint de nube al que se accede a través de Private Link, DNS privado o una VPN se resuelve en un espacio de direcciones privadas y sí necesita que su `host:port` exacto aparezca listado como cualquier otro destino privado. El mismo campo y las mismas reglas se aplican en `speech.stt`. Consulta [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) para ver el formato completo de la entrada.

## Pestaña de voz (opcional) [#speech-tab-optional]

El menú `speechTab` ofrece opciones personalizables para los modos de conversación y avanzado, así como ajustes detallados para STT y TTS. Esto establecerá la configuración predeterminada para los usuarios.

Use `browser` para la síntesis de voz del navegador integrada o `external` para un proveedor del lado del servidor configurado a continuación. Los valores predeterminados específicos de proveedores antiguos siguen siendo aceptados por compatibilidad y se normalizan a `external`; si el servicio externo correspondiente no está disponible, LibreChat recurre a `browser`.

ejemplo:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` establece los valores iniciales que ven los usuarios; cada uno permanece modificable por el usuario en la pestaña de configuración de voz.

## STT (Speech-to-Text) [#stt-speech-to-text]

La función de Voz a Texto (STT, por sus siglas en inglés) convierte las palabras habladas en texto escrito. Para habilitar STT, haz clic en el botón STT (cerca del botón de enviar) o usa la combinación de teclas ++Shift+Alt+L++ para iniciar la transcripción.

### Servicios de STT disponibles [#available-stt-services]

- **STT local**
  - Basado en navegador
  - Whisper (probado en LocalAI)
- **Cloud STT**
  - OpenAI Whisper
  - Azure Whisper
  - Otros servicios STT compatibles con OpenAI

### Configuración de STT local [#configuring-local-stt]

- #### Browser-based
  No se requiere configuración. Asegúrese de que el interruptor "Speech To Text" en la pestaña de configuración de voz esté activado y que "Browser" esté seleccionado en el menú desplegable del motor.

- #### Whisper Local [#whisper-local]
  Requiere una instancia local de Whisper.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

El campo `apiKey` es obligatorio en cada bloque STT compatible con OpenAI, incluidos los locales. Si tu servidor no verifica las claves, usa cualquier valor de marcador de posición.

### Configuración de Cloud STT [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Soporte para dominio de endpoint de Azure">
El campo `instanceName` admite ambos formatos de dominio de Azure OpenAI:
- **Nuevo formato**: `.cognitiveservices.azure.com` (p. ej., `my-instance.cognitiveservices.azure.com`)
- **Formato heredado**: `.openai.azure.com` (p. ej., `my-instance.openai.azure.com`)

Puede especificar el dominio completo o solo el nombre de la instancia. Si proporciona un dominio completo que incluya `.azure.com`, se utilizará tal cual. De lo contrario, se aplicará el formato heredado `.openai.azure.com` para la compatibilidad con versiones anteriores.
</Callout>

- #### Compatible con OpenAI [#openai-compatible]

Consulte la sección de OpenAI Whisper, ajustando la `url` y el `model` según sea necesario. El campo `apiKey` sigue siendo obligatorio.

ejemplo
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Texto a voz) [#tts-text-to-speech]

La función de Text-to-Speech (TTS) convierte texto escrito en palabras habladas. Hay varios servicios de TTS disponibles:

### Servicios de TTS disponibles [#available-tts-services]

- **TTS Local**
  - Basado en navegador
  - Piper (probado en LocalAI)
  - Coqui (probado en LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Otros servicios de TTS compatibles con OpenAI/ElevenLabs

El texto más largo que `speech.tts.maxInputChars` (por defecto 20000 caracteres) se trunca antes de leerse en voz alta. Consulta la [Estructura del objeto Speech](/docs/configuration/librechat_yaml/object_structure/speech) para más detalles.

### Configuración de TTS local [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

No se requiere configuración. Asegúrese de que el interruptor "Text To Speech" en la pestaña de configuración de voz esté activado y que "Browser" esté seleccionado en el menú desplegable del motor.

- #### Piper [#piper]

Requiere una instancia local de Piper.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Requiere una instancia local de Coqui.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Configuración de Cloud TTS [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Soporte para dominio de endpoint de Azure">
El campo `instanceName` admite ambos formatos de dominio de Azure OpenAI:
- **Nuevo formato**: `.cognitiveservices.azure.com` (p. ej., `my-instance.cognitiveservices.azure.com`)
- **Formato heredado**: `.openai.azure.com` (p. ej., `my-instance.openai.azure.com`)

Puede especificar el dominio completo o solo el nombre de la instancia. Si proporciona un dominio completo que incluya `.azure.com`, se utilizará tal cual. De lo contrario, se aplicará el formato heredado `.openai.azure.com` para la compatibilidad con versiones anteriores.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Se pueden añadir parámetros adicionales específicos de ElevenLabs de la siguiente manera:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### Compatible con OpenAI [#openai-compatible-1]

Consulte la sección OpenAI TTS, ajustando la variable `url` según sea necesario

ejemplo:

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Compatible con ElevenLabs [#elevenlabs-compatible]

ejemplo:

```yaml

    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
```
