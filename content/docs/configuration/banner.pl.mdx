Wyświetlaj ważne komunikaty wszystkim użytkownikom na górze aplikacji. Idealne rozwiązanie do ogłoszeń, powiadomień o konserwacji lub aktualizacjach.

<Callout type="info" title="Szybki przegląd">
  - Tylko **jeden baner** może być aktywny jednocześnie
  - Zaplanuj automatyczne wyświetlanie i ukrywanie banerów
  - Wybierz, czy użytkownicy mogą zamknąć baner, czy nie
  - Wyświetlaj banery wszystkim lub tylko zalogowanym użytkownikom
</Callout>

---

## Tworzenie banera [#creating-a-banner]

Uruchom to polecenie, aby utworzyć lub zaktualizować baner:

```bash
npm run update-banner
```

W Dockerze uruchom skrypt wewnątrz kontenera `api`:

```bash
docker compose exec api npm run update-banner
```

Zostaniesz przeprowadzony przez kilka prostych monitów:

```ansi
--------------------------
Update the banner!
--------------------------
Display From (Format: yyyy-mm-ddTHH:MM:SSZ, Default: now):
> 2025-12-02T09:00:00Z

Display To (Format: yyyy-mm-ddTHH:MM:SSZ, Default: not specified):
> 2025-12-31T23:59:59Z

Enter your message (Enter a single dot "." on a new line to finish):
> 🎉 Welcome to LibreChat! Check out our new features.
> .

Is public (y/N):
> n

Is persistable (cannot be dismissed) (y/N):
> n
```

<Callout type="tip" title="Co oznaczają te opcje?">
  - **Wyświetlanie od/do**: Kiedy baner ma się pojawić i zniknąć. Naciśnij Enter w wierszu poleceń, aby użyć wartości „now” (teraz) i „forever” (na zawsze)
  - **Is public**: Pokaż odwiedzającym, którzy nie są zalogowani (np. na stronie logowania)
  - **Jest trwały**: Jeśli tak, użytkownicy nie mogą zamknąć banera (używaj go do ważnych komunikatów)
</Callout>

<Callout type="warning" title="Ponowne uruchomienie tego zastępuje istniejący baner">

Zawsze może istnieć tylko jeden baner. `update-banner` wyszukuje istniejący baner i nadpisuje go w miejscu, tworząc nowy tylko wtedy, gdy żaden nie istnieje, więc nie można ustawić w kolejce drugiego banera na późniejszy termin ani dopuścić do nakładania się dwóch zaplanowanych okien. Ponowne uruchomienie polecenia powoduje odrzucenie wiadomości i harmonogramu poprzedniego banera.

Aby zmienić baner, uruchom ponownie `update-banner`. Aby usunąć go przed czasem określonym w `Display To`, użyj `delete-banner` poniżej.

</Callout>

## Usuwanie banera [#deleting-a-banner]

```bash
npm run delete-banner
```

Dzięki Docker uruchom polecenie `docker compose exec api npm run delete-banner`.

Zobaczysz bieżący baner i zostaniesz poproszony o potwierdzenie przed usunięciem.

<Callout type="warning" title="Tylko aktywny baner może zostać usunięty">

`delete-banner` znajduje tylko baner, który jest aktualnie aktywny: jego czas `Display From` musi już minąć, a czas `Display To` musi być w przyszłości lub nie może być ustawiony. Baner zaplanowany na późniejszą datę lub baner, którego `Display To` już minęło, jest zgłaszany jako "No banner found to delete" i pozostaje w bazie danych. Aby zastąpić taki baner, ponownie uruchom `update-banner`.

</Callout>

Usunięcie banera w ten sposób jest również sposobem na jego wcześniejsze zdjęcie: nie ma flagi "disable". W przeciwnym razie baner znika samoczynnie po upływie daty `Display To`, a baner zapisany bez ustawionej daty `Display To` pozostaje widoczny, dopóki go nie usuniesz.

## Przykładowe banery [#example-banners]

<Tabs items={['Wiadomość powitalna', 'Powiadomienie o konserwacji', 'Alert bezpieczeństwa']}>
  <Tabs.Tab>
    Prosty komunikat powitalny, który użytkownicy mogą zamknąć:

    ```bash
    npm run update-banner "" "" "👋 Welcome to LibreChat!" "false" "false"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Powiadomienie o planowanej konserwacji, którego nie można zamknąć:

    ```bash
    npm run update-banner "2025-12-20T00:00:00Z" "2025-12-21T06:00:00Z" "⚠️ Scheduled maintenance on Dec 20th, 2-6 AM UTC" "true" "true"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Ważna informacja dotycząca bezpieczeństwa widoczna dla wszystkich:

    ```bash
    npm run update-banner "" "" "🔒 Please update your password by January 1st" "true" "true"
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="info" title="Puste argumenty daty nadal wyświetlają monit">

Pusty ciąg znaków (`""`) podany jako data jest traktowany jako brakująca wartość, więc skrypt nadal interaktywnie pyta o `Display From` i `Display To`. Naciśnij Enter przy każdym pytaniu, aby zaakceptować wartość domyślną, lub podaj daty w formacie ISO (`yyyy-mm-ddTHH:MM:SSZ`) jako pierwsze dwa argumenty, aby uruchomić polecenie bez pytań. Argument wiadomości jest również wymagany, aby pominąć pytanie o wiadomość, a argumenty `isPublic` i `persistable` muszą być podane jako `true` lub `false`, aby pominąć ich pytania.

</Callout>

## Format daty [#date-format]

Użyj tego formatu dla dat: `yyyy-mm-ddTHH:MM:SSZ`

**Przykłady:**
- `2025-12-25T09:00:00Z` → 25 grudnia 2025 r. o godz. 9:00 (UTC)
- `2025-01-01T00:00:00Z` → 1 stycznia 2025 o północy (UTC)

Gdy pojawi się monit, naciśnij Enter bez wpisywania daty, aby użyć bieżącego czasu dla `Display From` lub braku daty końcowej dla `Display To`.
