## Umum [#general]

![Pengguna aktif di LibreChat](/images/metrics/librechat-metrics-active-users.png)

LibreChat menyediakan dua antarmuka metrik yang kompatibel dengan Prometheus. Endpoint `/metrics` bawaan API melaporkan perilaku operasional seperti aktivitas Redis dan hasil proksi telemetri peramban. Eksportir basis data opsional melaporkan data penggunaan yang disimpan di MongoDB, termasuk total token dan jumlah pengguna aktif.

## Metrik API Bawaan [#built-in-api-metrics]

LibreChat mengekspos metrik Prometheus dari server API di `/metrics`. Atur `METRICS_SECRET` dan lakukan scrape pada endpoint tersebut dengan `Authorization: Bearer <METRICS_SECRET>`. Endpoint akan mengembalikan `401` jika secret tidak diatur, header tidak ada, atau token tidak cocok.

```yaml filename="prometheus.yml"
scrape_configs:
  - job_name: librechat-api
    scheme: https
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials: your-metrics-secret
    static_configs:
      - targets: ['librechat.example.com']
```

### Metrik Proses, HTTP, dan Permintaan [#process-http-and-request-metrics]

Endpoint ini juga mengekspos metrik default Node.js dan proses dari `prom-client`, serta seri berikut.

| Grup | Metrik | Label |
| --- | --- | --- |
| HTTP | `http_requests_total`, `http_request_duration_seconds` | `method`, `path`, `status` |
| HTTP | `http_requests_in_flight`, `http_request_body_bytes` (dari `Content-Length`) | `method`, `path` |
| SSE | `sse_streams_total`, `sse_stream_duration_seconds` | `method`, `path`, `status` |
| SSE | `sse_streams_in_flight` | `method`, `path` |
| Unggahan | `upload_requests_total`, `upload_request_duration_seconds` | `method`, `path`, `status` |
| Unggahan | `upload_requests_in_flight`, `upload_bytes_total` (dari `Content-Length`) | `method`, `path` |
| OpenID | `openid_user_lookup_total`, `openid_user_lookup_duration_seconds` | `result` |
| Mongoose | `mongoose_queries_total`, `mongoose_query_duration_seconds` | `model`, `operation`, `status` |
| Job generasi | `generation_jobs_total` | `store`, `result` |
| Job generasi | `generation_jobs_in_flight` | `store` |
| Aliran generasi | `generation_stream_subscriptions_total` | `store`, `type`, `result` |
| Aliran generasi | `generation_stream_resume_pending_events_total`, `generation_stream_early_buffer_overflows_total`, `generation_stream_first_attachment_delay_seconds` | `store` |
| Aliran generasi | `generation_stream_attachment_outcomes_total` | `store`, `outcome` |
| Aliran generasi | `generation_stream_recoveries_total`, `generation_stream_recovery_duration_seconds`, `generation_stream_recovery_events`, `generation_stream_recovery_content_parts` | `store`, `method`, `outcome` |
| Filter konten | `content_filter_locator_traversal_failures_total` | `operation`, `reason` |
| Filter konten | `content_filter_locator_traversal_size` | `operation`, `reason`, `dimension` |

Metrik pemulihan aliran generasi menggambarkan bagaimana buffer peristiwa awal yang meluap direkonstruksi. Metrik filter konten menghitung penelusuran penunjuk file yang telah diselesaikan namun belum lengkap.

### Metrik Startup Agen [#agent-startup-metrics]

Permintaan chat Agen awal memancarkan dua metrik startup:

- `agent_startup_milestone_duration_seconds{milestone}` mengukur latensi kumulatif dari masuknya permintaan hingga ke setiap milestone startup.
- `agent_startups_total{result}` menghitung upaya startup berdasarkan hasil terminal.

Milestones mencakup penerimaan permintaan, pembuatan dan pengakuan tugas, pemuatan percakapan dan riwayat, inisialisasi klien dan eksekusi, permulaan stream, serta respons atau peristiwa konten pertama yang diantrekan. Hasil membedakan antara konten yang diantrekan, penyelesaian tanpa delta konten, deduplikasi, penolakan, jeda, penggantian, pembatalan, dan kesalahan.

Ketika [pelacakan OpenTelemetry sisi backend](/docs/configuration/dotenv#opentelemetry-traces-and-logs) diaktifkan, span `librechat.agent.startup` melaporkan tonggak (milestone) yang sama sebagai event. Span ini mencakup total durasi startup, jumlah milestone, hasil akhir, dan ID stream generasi ketika ID tersebut ditetapkan.

### Metrik Redis [#redis-metrics]

Cache dan layanan yang didukung Redis memancarkan dua metrik operasi logis:

- `redis_operations_total{client,use_case,operation,status}` menghitung operasi.
- `redis_operation_duration_seconds{client,use_case,operation,status}` mengukur latensi.

`client` adalah `keyv` atau `ioredis`, dan `status` adalah `success` atau `error`. Label `use_case` yang dibatasi mengidentifikasi pekerjaan seperti cache, sesi, batas laju (rate limits), konkurensi, prinsipal ACL, pekerjaan stream yang dapat dilanjutkan (resumable stream jobs) dan pub/sub, pemindaian registri MCP, serta pemilihan pemimpin (leader election). Metrik ini menghitung operasi logis LibreChat alih-alih setiap perjalanan pulang-pergi (round trip) Redis internal. Ping siklus hidup koneksi dan pemeliharaan global dikecualikan, dan pembersihan namespace dihitung sebagai satu operasi logis.

Ketika [pelacakan OpenTelemetry backend](/docs/configuration/dotenv#opentelemetry-traces-and-logs) diaktifkan, setiap span HTTP juga merangkum pekerjaan Redis-nya dengan:

- `librechat.redis.calls`
- `librechat.redis.duration_ms`
- `librechat.redis.errors`
- `librechat.redis.max_call_ms`
- `librechat.redis.operations`
- `librechat.redis.use_cases`

Sepuluh kasus penggunaan dengan durasi total tertinggi juga menerima atribut `calls`, `duration_ms`, `errors`, dan `max_call_ms` di bawah `librechat.redis.<use_case>.*`. Ringkasan tingkat permintaan ini tidak memerlukan rentang (span) Redis tingkat perintah; aktifkan `OTEL_IOREDIS_TRACING_ENABLED` hanya jika rentang perintah individual diperlukan.

### Metrik Proxy RUM Browser [#browser-rum-proxy-metrics]

Hasil proxy RUM browser dilaporkan sebagai `rum_proxy_requests_total{endpoint,result}`. `endpoint` bisa berupa `traces`, `logs`, atau `unknown`; `result` bisa berupa `success`, `auth_drop`, `auth_error`, `bad_request`, `not_configured`, `collector_4xx`, `collector_5xx`, `collector_error`, atau `collector_timeout`.

### Metrik Aktor Peristiwa Agen [#agent-event-actor-metrics]

Durable bound Agent Events mengekspos metrik penerimaan dan pemulihan dengan kardinalitas rendah:

- `agent_event_actor_receipt_operations_total{operation,outcome,resolution}` menghitung pembacaan tanda terima, penyelesaian, dan backfill warisan. `operation` adalah `read`, `settle`, atau `backfill`; `outcome` adalah `hit`, `miss`, `success`, `replay`, atau `conflict`.
- `agent_event_actor_receipts_retained{resolution}` melaporkan tanda terima pemutaran ulang yang dipertahankan oleh resolusi `checkpoint_verified`, `action_compensated`, atau `history_repaired`.
- `agent_event_actor_receipts_expiry_eligible` melaporkan tanda terima yang disimpan yang TTL MongoDB 90 harinya telah berlalu tetapi belum dihapus.
- `agent_event_actor_reconciliations_pending` melaporkan penanda rekonsiliasi aktif yang sedang menunggu tanda terima terminal.
- `agent_event_actor_oldest_reconciliation_age_seconds` melaporkan usia rekonsiliasi aktif tertua.
- `agent_event_actor_deliveries{state}` melaporkan baris pengiriman yang saat ini dalam status `retry` atau `dead`.

Pengukur penyimpanan dikumpulkan pada *scrape* yang terautentikasi dan di-*cache* hingga 60 detik. Berikan peringatan pada usia rekonsiliasi yang berkelanjutan, pengiriman yang mati, atau tanda terima yang memenuhi syarat kedaluwarsa alih-alih pada satu *scrape* saja.

### Metrik Tautan-Berbagi [#shared-link-metrics]

`share_link_rejections_total{operation,code}` menghitung kegagalan pembuatan atau pembaruan yang dibatasi. `operation` adalah `create` atau `update`; `code` adalah `TARGET_MESSAGE_NOT_FOUND` ketika ujung cabang yang dipilih tidak dipertahankan, atau `NO_MESSAGES` ketika percakapan tidak memiliki pesan yang dipertahankan. Metrik ini tidak berisi teks percakapan atau identitas pengguna.

## Eksportir Metrik Basis Data [#database-metrics-exporter]

Metrics exporter tersedia di [virtUOS/librechat_exporter](https://github.com/virtUOS/librechat_exporter).
Ini adalah alat terpisah yang Anda deploy bersama LibreChat.

### Pengaturan [#setup]

Untuk men-deploy exporter, cukup tambahkan container yang diperlukan ke konfigurasi compose Anda seperti ini:

```yaml
services:
  metrics:
    image: ghcr.io/virtuos/librechat_exporter:main
    depends_on:
      - mongodb
    ports:
      - '8000:8000'
    restart: unless-stopped
```

Anda juga dapat mengonfigurasi exporter secara opsional.
Namun biasanya, pengaturan default sudah cukup baik.

```yaml
services:
  metrics:
    environment:
      - MONGODB_URI=mongodb://mongodb:27017/
      - LOGGING_LEVEL=info
```

### Penggunaan [#usage]

Anda sekarang dapat menambahkan eksportir ke konfigurasi scrape Prometheus Anda:

```yaml
- job_name: librechat
  static_configs:
    - targets:
        - 'librechat.example.com:8000'
```

Setelah pengambilan metrik dimulai, cari metrik `librechat_*` (contoh: `librechat_registered_users`).
Exporter ini menyediakan beberapa metrik.

Selamat bersenang-senang dalam membangun dasbor Grafana Anda!
