### 常规 [#general]

LibreChat 在其后端 (api) 中内置了中央日志记录功能。

- 使用 **Docker** 安装时，日志文件保存在 `/logs` 中

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="logs" defaultOpen>
      <FileTree.File name="debug-2024-01-01.log" active />
      <FileTree.File name="error-2024-01-01.log" active />
      <FileTree.File name="meiliSync-2024-01-01.log" active />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

- 使用 **npm** 安装时，日志文件会保存在 `/api/logs` 中

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="api" defaultOpen>
      <FileTree.Folder name="logs" defaultOpen>
        <FileTree.File name="debug-2024-01-01.log" active />
        <FileTree.File name="error-2024-01-01.log" active />
        <FileTree.File name="meiliSync-2024-01-01.log" active />
      </FileTree.Folder>
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

错误日志默认会被保存。只有当 `DEBUG_LOGGING=true` 时才会写入调试日志文件；提供的 `.env.example` 将其设置为 `true`，但如果未设置该变量，则不会创建调试文件。

这允许您通过检查日志文件的外部工具（例如 **[the ELK stack](https://aws.amazon.com/what-is/elk-stack/)**）来监控您的服务器。

调试日志对于开发工作和修复问题至关重要。如果您在运行 LibreChat 时遇到任何问题，请尽可能复现该问题，并**[报告问题](https://github.com/LibreChat-AI/LibreChat/issues)**，同时附上您在 `./api/logs/debug-%DATE%.log` 中找到的日志。

错误日志也保存在相同的位置：`./api/logs/error-%DATE%.log`。如果您配置了 Meilisearch，也会有一个单独的日志文件用于记录相关信息。

<Callout type="note" title="注意：">
  日志文件每天轮换：每天都会启动一个新文件；当文件达到 20 MB 时也会进行拆分。轮换后的文件会进行 gzip 压缩，并保留 14 天。错误信息同样会出现在调试日志文件中，但错误日志文件提供堆栈跟踪和更详细的信息。
</Callout>

### 设置 [#setup]

- 仅当此变量设置为 `true` 时才会写入调试日志文件。如果未设置该变量或将其设置为其他任何值，则不会创建调试文件。

<OptionTable
  options={[['DEBUG_LOGGING', 'boolean', '将调试日志写入文件。需要此项才能创建调试日志文件。', 'DEBUG_LOGGING=true']]}
/>

> 注意:建议在生产环境中禁用调试日志。

- 若要在控制台/终端中查看详细的服务器输出，您可以将以下内容设置为 `TRUE`：

<OptionTable
  options={[
    [
      'DEBUG_CONSOLE',
      'boolean',
      '启用与文件调试日志格式相同的详细控制台/stdout日志。',
      'DEBUG_CONSOLE=false',
    ],
  ]}
/>

但不建议这样做，因为输出可能会非常冗长。此功能默认处于禁用状态，应谨慎启用。

- 在云部署（如 GCP 或 AWS）中处理控制台日志时，启用此选项将以 UTC 时间戳转储日志并将其格式化为 JSON。

<OptionTable
  options={[
    [
      'CONSOLE_JSON',
      'boolean',
      '启用适用于 GCP/AWS 等云部署环境的详细 JSON 控制台/stdout 日志。',
      'CONSOLE_JSON=false',
    ],
  ]}
/>

默认情况下，JSON 字符串长度会被截断为 255 个字符。您可以通过以下环境变量进行配置：

<OptionTable
  options={[
    [
      'CONSOLE_JSON_STRING_LENGTH',
      'number',
      '配置 JSON 控制台/stdout 日志中字符串值的截断长度。默认值：255。',
      '# CONSOLE_JSON_STRING_LENGTH=255',
    ],
  ]}
/>

- 控制台日志的详细程度可以通过 `CONSOLE_LOG_LEVEL` 设置(`error`、`warn`、`info`、`http`、`verbose`、`debug`、`activity`、`silly` 或 `silent`)。`silent` 会关闭控制台输出,但不会禁用文件日志。无效的值将回退为默认值,并输出一条警告。

<OptionTable
  options={[
    [
      'CONSOLE_LOG_LEVEL',
      'string',
      '控制台日志级别。默认为 info,若设置 DEBUG_CONSOLE=true 则默认为 debug;显式设置的值优先。',
      '# CONSOLE_LOG_LEVEL=info',
    ],
  ]}
/>

- 调试日志消息默认截断为 150 个字符,日志脱敏的处理范围限制为每条记录 5000 个值。可以通过 `DEBUG_MESSAGE_LENGTH` 和 `LOG_REDACTION_MAX_NODES` 对这些参数进行调整。

<OptionTable
  options={[
    [
      'DEBUG_MESSAGE_LENGTH',
      'number',
      '调试日志消息在被截断之前的最大长度。默认值:150。',
      '# DEBUG_MESSAGE_LENGTH=150',
    ],
    [
      'LOG_REDACTION_MAX_NODES',
      'number',
      '一条日志记录中可脱敏的最大值数量，超出部分将被替换。默认值：5000。',
      '# LOG_REDACTION_MAX_NODES=5000',
    ],
  ]}
/>

- 要将日志文件写入默认位置以外的其他位置,请设置 `LIBRECHAT_LOG_DIR`。参见 `.env` 参考文档中的 [Logging](/docs/configuration/dotenv#logging)。

- 默认启用基于文件的日志传输。如果您的部署仅需将日志输出到 stdout/stderr，请设置 `LOG_TO_FILE=false`。

<OptionTable
  options={[
    [
      'LOG_TO_FILE',
      'boolean',
      '设置为 false 以禁用基于文件的 Winston 传输。',
      'LOG_TO_FILE=true',
    ],
  ]}
/>

### OpenTelemetry Tracing [#opentelemetry-tracing]

LibreChat 可以为服务器、数据库、Redis 和出站 HTTP 可见性发出后端 OpenTelemetry 追踪。Redis 命令级别的 span 是可选的，因此默认追踪保持在高层级。这与 Langfuse 不同，后者仍然是针对 GenAI 特定提示词和模型可观测性的推荐选项。
