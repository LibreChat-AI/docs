LibreChat 使用四个主要的配置文件。每个文件控制应用程序的不同方面,从环境变量到自定义 AI 端点,再到 Docker 服务覆盖配置。

## 常见变更工作流程 [#common-change-workflow]

大多数配置更改都遵循相同的模式：

1. 编辑 `.env` 以设置密钥、API 密钥和服务器级功能标志。
2. 编辑 `librechat.yaml` 以配置自定义 endpoint、Model Specs、界面设置、MCP 服务器、智能体以及高级应用行为。
3. 对于 Docker，请确保在期望 LibreChat 读取 `librechat.yaml` 之前，已通过 `docker-compose.override.yml` 将其挂载。
4. 每次修改配置后，请重启 LibreChat。
5. 如果更改未在 UI 中显示，请检查 API 日志。

例如，要启用 OpenRouter，你需要将 `OPENROUTER_KEY` 添加到 `.env` 中，在 `librechat.yaml` 中添加一个 OpenRouter endpoint，确保 Docker 挂载了 `librechat.yaml`，重启服务，然后从 endpoint 选择器中选择 OpenRouter。

## 配置文件 [#configuration-files]

**`.env`**:服务器级设置:API 密钥、数据库连接字符串、功能开关和身份验证密钥。这是大多数部署的主要配置文件。有关所有可用变量,请参阅 [.env 参考](/docs/configuration/dotenv)。

**`librechat.yaml`**:自定义 AI 端点、模型设置、界面选项,以及 MCP 服务器和智能体等高级功能。此文件为可选项。若不存在该文件,LibreChat 将使用默认配置正常运行。有关设置说明,请参阅 [librechat.yaml 指南](/docs/configuration/librechat_yaml)。

**`docker-compose.yml`**:定义 Docker 服务(`api`、`admin-panel`、`mongodb`、`meilisearch`、`vectordb` 和 `rag_api`)。请勿直接编辑此文件,而应使用覆盖文件(override file),这样您的更改在更新后仍会保留。

**`docker-compose.override.yml`**:你对 Docker 服务的本地自定义配置,包括卷挂载、端口映射和环境变量覆盖。Docker Compose 会自动将其与主文件合并。请参阅 [Docker 覆盖配置指南](/docs/configuration/docker_override)。

## 应用更改 [#applying-changes]

<Callout type="warning" title="需要重启">

在编辑任何配置文件后，您必须重启 LibreChat 才能使更改生效。

<Tabs items={['Docker', '本地']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

停止正在运行的进程 (Ctrl+C) 并重启：

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

</Callout>
