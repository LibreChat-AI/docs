Mostra messaggi importanti a tutti i tuoi utenti nella parte superiore dell'app. Perfetto per annunci, avvisi di manutenzione o aggiornamenti.

<Callout type="info" title="Panoramica rapida">
  - Solo **un banner** può essere attivo alla volta
  - Pianifica la visualizzazione e la scomparsa automatica dei banner
  - Scegli se gli utenti possono ignorare il banner o meno
  - Mostra banner a tutti, o solo agli utenti che hanno effettuato l'accesso
</Callout>

---

## Creazione di un Banner [#creating-a-banner]

Esegui questo comando per creare o aggiornare un banner:

```bash
npm run update-banner
```

Con Docker, esegui invece lo script all'interno del container `api`:

```bash
docker compose exec api npm run update-banner
```

Sarai guidato attraverso alcuni semplici prompt:

```ansi
--------------------------
Update the banner!
--------------------------
Display From (Format: yyyy-mm-ddTHH:MM:SSZ, Default: now):
> 2025-12-02T09:00:00Z

Display To (Format: yyyy-mm-ddTHH:MM:SSZ, Default: not specified):
> 2025-12-31T23:59:59Z

Enter your message (Enter a single dot "." on a new line to finish):
> 🎉 Welcome to LibreChat! Check out our new features.
> .

Is public (y/N):
> n

Is persistable (cannot be dismissed) (y/N):
> n
```

<Callout type="tip" title="Cosa significano queste opzioni?">
  - **Visualizza Da/A**: Quando il banner deve comparire e scomparire. Premi Invio al prompt per usare "now" e "forever"
  - **È pubblico**: Mostra ai visitatori che non hanno effettuato l'accesso (come nella pagina di login)
  - **È persistente**: se sì, gli utenti non possono chiudere il banner (usalo per avvisi importanti)
</Callout>

<Callout type="warning" title="Eseguire di nuovo questa operazione sostituisce il banner esistente">

Esiste sempre un solo banner. `update-banner` cerca un banner esistente e lo sovrascrive sul posto, creandone uno solo quando non ne esiste alcuno; pertanto, non è possibile mettere in coda un secondo banner per una data successiva e non è possibile avere due finestre pianificate che si sovrappongono. L'esecuzione del comando una seconda volta elimina il messaggio e la pianificazione del banner precedente.

Per modificare un banner, esegui nuovamente `update-banner`. Per rimuoverne uno prima del suo orario di `Display To`, utilizza `delete-banner` qui sotto.

</Callout>

## Eliminazione di un Banner [#deleting-a-banner]

```bash
npm run delete-banner
```

Con Docker, esegui `docker compose exec api npm run delete-banner`.

Vedrai il banner attuale e ti verrà chiesto di confermare prima dell'eliminazione.

<Callout type="warning" title="Solo un banner attivo può essere eliminato">

`delete-banner` trova solo un banner attualmente attivo: il suo orario `Display From` deve essere già trascorso e il suo orario `Display To` deve essere nel futuro oppure non essere impostato. Un banner programmato per una data successiva, oppure un banner il cui `Display To` è già scaduto, viene segnalato come "No banner found to delete" e rimane nel database. Per sostituire un banner di questo tipo, esegui di nuovo `update-banner`.

</Callout>

Rimuovere un banner in questo modo è anche il metodo per toglierlo in anticipo: non esiste un flag di "disabilitazione". Un banner altrimenti scompare da solo una volta superata la data di `Display To`, mentre uno salvato senza `Display To` rimane visibile finché non lo si elimina.

## Esempio di banner [#example-banners]

<Tabs items={['Messaggio di benvenuto', 'Avviso di manutenzione', 'Avviso di sicurezza']}>
  <Tabs.Tab>
    Un semplice messaggio di benvenuto che gli utenti possono ignorare:

    ```bash
    npm run update-banner "" "" "👋 Welcome to LibreChat!" "false" "false"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Un avviso di manutenzione programmata che non può essere ignorato:

    ```bash
    npm run update-banner "2025-12-20T00:00:00Z" "2025-12-21T06:00:00Z" "⚠️ Scheduled maintenance on Dec 20th, 2-6 AM UTC" "true" "true"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Un avviso di sicurezza urgente visibile a tutti:

    ```bash
    npm run update-banner "" "" "🔒 Please update your password by January 1st" "true" "true"
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="info" title="Gli argomenti di data vuoti richiedono comunque un input">

Una stringa vuota (`""`) per una data viene trattata come mancante, quindi lo script chiede comunque interattivamente `Display From` e `Display To`. Premi Invio a ogni richiesta per accettare il valore predefinito, oppure passa le date in formato ISO (`yyyy-mm-ddTHH:MM:SSZ`) come primi due argomenti per eseguire il comando senza richieste. Anche l'argomento del messaggio è obbligatorio per saltare la richiesta del messaggio, e gli argomenti `isPublic` e `persistable` devono essere forniti come `true` o `false` per saltare le rispettive richieste.

</Callout>

## Formato data [#date-format]

Utilizza questo formato per le date: `yyyy-mm-ddTHH:MM:SSZ`

**Esempi:**
- `2025-12-25T09:00:00Z` → 25 dicembre 2025 alle 9:00 (UTC)
- `2025-01-01T00:00:00Z` → 1 gennaio 2025 a mezzanotte (UTC)

Quando richiesto, premi Invio senza digitare una data per usare l'ora corrente per `Display From`, oppure nessuna data di fine per `Display To`.
