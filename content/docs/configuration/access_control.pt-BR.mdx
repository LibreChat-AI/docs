Como funções, grupos e compartilhamento se comportam para os usuários está descrito na página de recurso [Controle de Acesso](/docs/features/access_control). Esta página aborda o que um administrador configura.

## Permissões de recursos [#feature-permissions]

Cada função possui um conjunto de permissões por tipo de permissão. Você pode alterá-las em três locais:

- No painel de agentes, prompts, servidores MCP, memórias e habilidades (somente administradores), por meio do botão **Admin Settings** no LibreChat.
- No painel de [Admin Panel](/docs/features/admin_panel), em **Access**, para qualquer função, incluindo as personalizadas.
- No bloco [`interface`](/docs/configuration/librechat_yaml/object_structure/interface) do `librechat.yaml`. Essas chaves definem as permissões do papel `USER` integrado somente na inicialização, portanto não podem expressar configurações diferentes para cada papel personalizado.

A tabela lista cada tipo de permissão, a chave `interface` que a define, suas ações e quais ações a função `USER` tem por padrão.

| Tipo de permissão | Chave `interface` | Ações | Ativado por padrão para `USER` |
| --------------- | --------------- | ------- | ------------------------ |
| `AGENTS` | `agents` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `PROMPTS` | `prompts` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `MCP_SERVERS` | `mcpServers` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC`, `CONFIGURE_OBO` | `USE`, `CREATE` |
| `SKILLS` | `skills` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | `USE`, `CREATE` |
| `REMOTE_AGENTS` | `remoteAgents` | `USE`, `CREATE`, `SHARE`, `SHARE_PUBLIC` | nenhum |
| `SHARED_LINKS` | `sharedLinks` | `CREATE`, `SHARE`, `SHARE_PUBLIC` | `CREATE`, `SHARE` |
| `SCHEDULES` | `schedules` | `USE`, `CREATE` | `USE`, `CREATE` |
| `MEMORIES` | `memories` | `USE`, `CREATE`, `UPDATE`, `READ`, `OPT_OUT` | todos |
| `BOOKMARKS` | `bookmarks` | `USE` | `USE` |
| `MULTI_CONVO` | `multiConvo` | `USE` | `USE` |
| `TEMPORARY_CHAT` | `temporaryChat` | `USE` | `USE` |
| `RUN_CODE` | `runCode` | `USE` | `USE` |
| `WEB_SEARCH` | `webSearch` | `USE` | `USE` |
| `FILE_SEARCH` | `fileSearch` | `USE` | `USE` |
| `FILE_CITATIONS` | `fileCitations` | `USE` | `USE` |
| `MARKETPLACE` | `marketplace` | `USE` | nenhum |
| `PEOPLE_PICKER` | `peoplePicker` | `VIEW_USERS`, `VIEW_GROUPS`, `VIEW_ROLES` | todos |

`SHARE` permite que uma função compartilhe com usuários, grupos ou funções específicos; `SHARE_PUBLIC` permite que ela compartilhe com todos na instância. `CONFIGURE_OBO` permite configurar a troca de tokens On-Behalf-Of em um servidor MCP, que encaminha os tokens delegados dos usuários para esse servidor; por isso, ela vem desativada por padrão.

## Seletor de pessoas [#people-picker]

As ações `PEOPLE_PICKER` controlam quais tipos de principal uma função pode encontrar na busca da caixa de diálogo de compartilhamento. Ocultar funções é comum quando o compartilhamento por função deve continuar sendo uma responsabilidade do administrador.

```yaml filename="librechat.yaml"
interface:
  peoplePicker:
    users: true
    groups: true
    roles: false
```

Isso altera apenas o que a busca exibe. Compartilhamentos existentes com um tipo de principal oculto continuam funcionando. Consulte [`interface.peoplePicker`](/docs/configuration/librechat_yaml/object_structure/interface#peoplepicker).

## Sincronização de grupos do Entra ID [#entra-id-group-sync]

Os grupos do Microsoft Entra ID são sincronizados com o LibreChat quando um usuário faz login por meio de OpenID Connect com o Entra e `OPENID_REUSE_TOKENS=true`. O LibreChat lê as associações de grupo do usuário no Microsoft Graph a cada login e armazena cada grupo com o seu ID de objeto do Entra; assim, um grupo compartilhado continua sendo o mesmo grupo mesmo que seja renomeado. Configure o provedor com [Azure / Entra ID](/docs/configuration/authentication/OAuth2-OIDC/azure) e a reutilização de token com [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse).

## Promover outro administrador [#promote-another-admin]

Em uma implantação de locatário único, a primeira conta registrada recebe a função `ADMIN`. Implantações com escopo de locatário nunca promovem o primeiro usuário; provisione os administradores de locatário por meio de um fluxo administrativo confiável. Para tornar outro usuário existente um administrador, use a página **Users** do Painel de Administração ou defina a função diretamente no MongoDB:

```js filename="mongosh"
db.users.updateOne({ email: 'USER_EMAIL_ADDRESS' }, { $set: { role: 'ADMIN' } })
```

Peça ao usuário que saia da conta e entre novamente depois. Com OpenID Connect, você também pode atribuir `ADMIN` a partir de uma função ou grupo do IdP com `OPENID_ADMIN_ROLE`; veja a [referência do .env](/docs/configuration/dotenv#openid-connect).

## Recursos de administrador [#admin-capabilities]

As capacidades são concedidas a um usuário, grupo ou função na página **Grants** do Painel de Administração. Usuários com a função `ADMIN` possuem todas elas implicitamente; qualquer outra pessoa precisa de `access:admin`, além das capacidades referentes ao que ela gerencia. Cada capacidade `manage:` implica a capacidade `read:` correspondente, inclusive por seção: `manage:configs:endpoints` também concede `read:configs:endpoints`. Quem tem apenas acesso de configuração limitado a seções recebe respostas de configuração filtradas para as seções que pode ler; sem nenhum acesso de leitura às configurações, recebe `403`.

| Capacidade | Permite |
| ---------- | ------- |
| `access:admin` | Entrar no Painel de Administração |
| `read:users`, `manage:users` | Visualizar e alterar contas de usuário |
| `read:groups`, `manage:groups` | Visualizar e alterar grupos e seus membros |
| `read:roles`, `manage:roles` | Visualizar e alterar funções e suas permissões |
| `read:configs`, `manage:configs` | Visualizar e alterar a configuração; `read:configs:<section>` e `manage:configs:<section>` limitam o acesso a uma única seção de nível superior do `librechat.yaml` |
| `assign:configs:user`, `assign:configs:group`, `assign:configs:role` | Atribuir substituições de configuração a esse tipo de entidade |
| `read:agents`, `manage:agents` | Visualizar e moderar todos os agentes |
| `read:prompts`, `manage:prompts` | Visualizar e moderar todos os prompts |
| `read:skills`, `manage:skills` | Visualizar e moderar todas as skills |
| `read:sharedlinks`, `manage:sharedlinks` | Visualizar e moderar todos os links compartilhados |
| `manage:mcpservers` | Gerenciar servidores MCP em toda a instância |
| `manage:code_environments` | Registrar e revogar workers de execução de código pertencentes à implantação |
| `read:usage` | Visualizar dados de uso |
| `read:insights` | Visualizar os [Insights](/docs/features/insights) de todos os agentes |
| `read:audit_log` | Visualizar, verificar e exportar o log de auditoria de concessões. Ele é somente de anexação, por isso não há uma contraparte `manage:` |

`read:assistants` e `manage:assistants` também existem, mas estão reservados; nada os aplica ainda.

## Cache de associação a grupos [#group-membership-cache]

Para verificar permissões, o LibreChat consulta a quais grupos um usuário pertence e armazena o resultado em cache por cinco minutos. Alterações na associação a grupos limpam imediatamente as entradas afetadas. A função do usuário não é armazenada em cache. Falhas no cache ou no bloqueio recorrem ao banco de dados e nunca impedem uma verificação de permissão.

## Insights do Administrador [#admin-insights]

O painel [Insights](/docs/features/insights) vem desativado por padrão. Defina `ENABLE_INSIGHTS=true` no `.env` e reinicie o LibreChat; enquanto estiver desativado, as rotas do Insights respondem com `404` e a entrada na barra lateral permanece oculta.

Administradores podem abri-lo assim que ele estiver habilitado. Para permitir o acesso a outras pessoas, conceda `read:insights` (todos os agentes) pelo Painel do Administrador ou ative **Ver insights** para pessoas ou grupos específicos no diálogo de compartilhamento de um agente. Somente administradores podem conceder **Ver insights**, a pessoa também precisa ter acesso ao próprio agente, e essa permissão não pode ser concedida a todos. Os insights mostram nomes, endereços de e-mail e a primeira mensagem de conversas recentes, portanto conceda-a com cuidado.

Toda consulta de Insights é restrita ao tenant do usuário que a visualiza, e os intervalos de datas personalizados são limitados a 30 dias.

## Migrando de versões anteriores ao ACL [#migrating-from-pre-acl-versions]

Versões anteriores à v0.8.0-rc3 usavam um modelo de propriedade mais simples para agentes e prompts. Após a atualização, execute as migrações para que os agentes e prompts existentes continuem acessíveis; o LibreChat exibe um aviso na inicialização quando encontra agentes não migrados. Os links compartilhados passaram a usar o mesmo sistema posteriormente, portanto, instâncias que possuam links compartilhados criados antes dessa mudança também devem executar a migração de links compartilhados.

Comece com uma execução de teste (dry run) para ver o que seria alterado e, em seguida, execute a migração. As variantes `:batch` processam 50 registros por vez, o que ajuda em bancos de dados grandes.
