API RAG indeksuje przesłane przez użytkownika pliki i pobiera odpowiednie fragmenty w celu wzbogacenia Twoich promptów, zapewniając LibreChat odpowiedzi uwzględniające kontekst i oparte na Twoich dokumentach. Działa jako oddzielna usługa FastAPI wspierana przez bazę danych PostgreSQL + pgvector.

<Callout type="info" title="Co widzą użytkownicy">
[Rozmowa z plikami](/docs/features/rag_api) obejmuje przesyłanie plików do wyszukiwania w plikach, ponowne wykorzystanie plików oraz wyszukiwanie w plikach w agentach. Ta strona opisuje konfigurację i ustawienia.
</Callout>

## Dostępność [#availability]

Wyszukiwanie plików za pośrednictwem RAG API działa w [Agentach](/docs/features/agents) oraz w zwykłych czatach na każdym endpoincie oprócz Assistants. OpenAI Assistants korzystają zamiast tego z własnego magazynu plików i wyszukiwania OpenAI, a pliki przesłane tam nie mogą być dołączane w innych miejscach.

Użytkownicy widzą opcję **Upload for File Search** tylko wtedy, gdy włączona jest funkcja agenta `file_search` (domyślnie jest włączona) oraz ich rola ma uprawnienie File Search ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Szybki start z Docker [#docker-quick-start]

Dla Dockera API RAG jest już połączone zarówno w domyślnym pliku `docker-compose.yml`, jak i w `deploy-compose.yml`, w tym z wartością `RAG_API_URL`. Wystarczy upewnić się, że używasz najnowszego obrazu i plików compose. Jeśli nie wiesz, jak zaktualizować LibreChat, zobacz [przewodnik aktualizacji LibreChat dla Dockera](/docs/local/docker#updating-librechat).

<Callout type="warning" title="Współdzielony plik .env">
W domyślnej konfiguracji Docker, plik `.env` jest współdzielony między LibreChat a RAG API. Zdefiniuj zmienne RAG w tym samym pliku. Pełna lista znajduje się w [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

Domyślne pliki `docker-compose.yml` i `deploy-compose.yml` ustawiają `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` w usłudze `api`. Zmienne środowiskowe ustawione w usłudze mają pierwszeństwo przed plikiem `.env`, dlatego w standardowej konfiguracji nie trzeba dodawać `RAG_API_URL` do `.env` — ustawienie go tam nie ma żadnego efektu. Aby wskazać wdrożenie Docker na zewnętrzne RAG API, nadpisz tę wartość w usłudze `api`, na przykład dla RAG API działającego na hoście Docker:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

Wpis `extra_hosts` jest potrzebny w systemie Linux, ponieważ Docker sam nie definiuje `host.docker.internal`.

Compose automatycznie wczytuje `docker-compose.override.yml` tylko wraz z domyślnym plikiem `docker-compose.yml`. Przy użyciu `deploy-compose.yml` należy podać oba pliki: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Poza Dockerem ustaw `RAG_API_URL` w pliku `.env`.

### Wersja Lite a pełny obraz [#lite-vs-full-image]

Docker domyślnie używa obrazu „lite” dla RAG API (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), który obsługuje wyłącznie zdalne embeddingi z OpenAI lub skonfigurowanej zdalnej usługi HuggingFace/Ollama.

W przypadku lokalnych osadzeń (embeddings), zmień obraz w pliku compose na pełną kompilację: `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Wprowadź tę zmianę w swoim [pliku Docker Compose Override](/docs/configuration/docker_override). Przykład znajduje się w `docker-compose.override.yml.example` w katalogu głównym projektu.

Jeśli chcesz plik compose, który zawiera tylko bazę danych PostgreSQL + pgvector oraz API w języku Python, zobacz `rag.yml` w katalogu głównym projektu.

### Przechowywanie w bazie danych [#database-storage]

Domyślne pliki compose przechowują dane pgvector/PostgreSQL w zarządzanym przez Docker wolumenie `pgdata2`. Jest to zamierzone: plików bazy danych nie trzeba edytować bezpośrednio z poziomu hosta, a zarządzany wolumen pozwala uniknąć typowych problemów z własnością i uprawnieniami. Pliki dostępne dla użytkownika, które można edytować (przesłane pliki, logi, obrazy, dane MongoDB oraz konfiguracja NGINX), są montowane jako bind-mount do folderów projektu, gdzie bezpośredni dostęp z hosta jest przydatny.

## Konfiguracja lokalna [#local-setup]

Konfiguracja bez użycia kontenerów wymaga więcej pracy ręcznej. Postępuj zgodnie z instrukcjami w [repozytorium RAG API](https://github.com/LibreChat-AI/rag-api/).

Ustaw `RAG_API_URL` w pliku `.env` LibreChat na adres, pod którym API jest dostępne w Twojej konfiguracji. Różni się to od dołączonej konfiguracji Docker, w której wartość jest już ustawiona w usłudze `api` w domyślnych plikach `docker-compose.yml` i `deploy-compose.yml`.

## Konfiguracja [#configuration]

Ustaw opcje RAG API za pomocą zmiennych środowiskowych w pliku `.env` dostępnym dla API. Większość z nich jest opcjonalna, poza danymi uwierzytelniającymi i ścieżkami wymaganymi przez wybranego dostawcę. W domyślnej konfiguracji wymagany jest tylko `RAG_OPENAI_API_KEY`.

## Użycie [#usage]

Gdy API RAG będzie osiągalne, w LibreChat nie trzeba już nic więcej włączać. Użytkownicy przesyłają pliki za pomocą **Upload for File Search**, a model odpytuje indeks przy użyciu narzędzia `file_search`, gdy pytanie tego wymaga. Jeśli `RAG_API_URL` nie jest ustawione lub usługa nie działa, przesyłanie plików kończy się błędem; LibreChat wyświetla przy starcie ostrzeżenie, gdy nie może połączyć się z kontrolą stanu API RAG. Informacje o stronie użytkownika znajdziesz w sekcji [Chat with Files](/docs/features/rag_api).

## Rozwiązywanie problemów [#troubleshooting]

Jeśli napotkasz problemy z konfiguracją lub używaniem RAG API:

- Upewnij się, że wszystkie wymagane zmienne środowiskowe są poprawnie ustawione w pliku `.env`.
- Upewnij się, że baza danych wektorowych jest skonfigurowana i dostępna.
- Zweryfikuj, czy klucz API OpenAI lub inne dane uwierzytelniające dostawcy są poprawne.
- Sprawdź zarówno logi LibreChat, jak i RAG API pod kątem błędów lub ostrzeżeń.

Jeśli problem nadal występuje, zapoznaj się z dokumentacją RAG API lub zapytaj społeczność LibreChat na GitHub Discussions lub Discordzie.
