Die RAG API indiziert vom Benutzer hochgeladene Dateien und ruft relevante Passagen ab, um Ihre Prompts zu erweitern, wodurch LibreChat kontextbezogene Antworten erhält, die auf Ihren Dokumenten basieren. Sie läuft als separater FastAPI-Dienst, der durch eine PostgreSQL + pgvector Datenbank unterstützt wird.

<Callout type="info" title="Was Benutzer sehen">
[Chat mit Dateien](/docs/features/rag_api) behandelt das Hochladen zur Dateisuche, das Wiederverwenden von Dateien und die Dateisuche in Agenten. Diese Seite behandelt die Einrichtung und Konfiguration.
</Callout>

## Verfügbarkeit [#availability]

Die Dateisuche über die RAG-API funktioniert in [Agents](/docs/features/agents) sowie in regulären Chats bei allen Endpunkten außer Assistants. OpenAI Assistants verwenden stattdessen den eigenen Dateispeicher und die Abruffunktion von OpenAI, und dort hochgeladene Dateien können nicht an anderer Stelle angehängt werden.

## Docker Quick Start [#docker-quick-start]

Für Docker ist die RAG-API bereits in den Standarddateien `docker-compose.yml` und `deploy-compose.yml` eingebunden, einschließlich des Werts `RAG_API_URL`. Du musst nur sicherstellen, dass du das neueste Image und die aktuellen Compose-Dateien verwendest. Falls du dir unsicher bist, wie du aktualisierst, findest du Hinweise im [Leitfaden zur Aktualisierung von LibreChat für Docker](/docs/local/docker#updating-librechat).

<Callout type="warning" title="Geteilte .env Datei">
Bei der standardmäßigen Docker-Einrichtung wird die `.env` Datei zwischen LibreChat und der RAG API geteilt. Definieren Sie die RAG-Variablen in derselben Datei. Die vollständige Liste finden Sie in der [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

Die Standarddateien `docker-compose.yml` und `deploy-compose.yml` setzen `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` für den `api`-Dienst. Auf dem Dienst gesetzte Umgebungsvariablen haben Vorrang vor der `.env`-Datei. Für das mitgelieferte Setup musst du `RAG_API_URL` daher nicht in `.env` hinzufügen, und eine Angabe dort hat keine Wirkung. Um eine Docker-Bereitstellung auf eine externe RAG-API zu verweisen, überschreibe stattdessen den Wert im `api`-Dienst, zum Beispiel für eine RAG-API, die auf dem Docker-Host läuft:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

Der Eintrag `extra_hosts` ist unter Linux erforderlich, da Docker `host.docker.internal` dort nicht selbst definiert.

Compose lädt `docker-compose.override.yml` automatisch nur zusammen mit der Standarddatei `docker-compose.yml`. Bei Verwendung von `deploy-compose.yml` müssen beide Dateien angegeben werden: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Außerhalb von Docker die Variable `RAG_API_URL` in deiner `.env`-Datei setzen.

### Lite vs. Vollständiges Image [#lite-vs-full-image]

Docker verwendet standardmäßig das "lite"-Image der RAG API (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), das nur Remote-Embeddings von OpenAI oder einem von Ihnen konfigurierten Remote-HuggingFace/Ollama-Dienst unterstützt.

Für lokale Embeddings ändern Sie das Image in der Compose-Datei auf den vollständigen Build: `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Nehmen Sie diese Änderung in Ihrer [Docker Compose Override File](/docs/configuration/docker_override) vor. Ein Beispiel finden Sie in der `docker-compose.override.yml.example` im Stammverzeichnis des Projekts.

Wenn Sie eine compose-Datei wünschen, die nur die PostgreSQL + pgvector-Datenbank und die Python-API enthält, siehe `rag.yml` im Stammverzeichnis des Projekts.

### Datenbankspeicherung [#database-storage]

Die standardmäßigen Compose-Dateien speichern die pgvector/PostgreSQL-Daten im von Docker verwalteten `pgdata2`-Volume. Dies ist beabsichtigt: Die Datenbankdateien müssen nicht direkt vom Host aus bearbeitet werden, und ein verwaltetes Volume vermeidet häufige Probleme mit Eigentumsrechten und Berechtigungen. Benutzerseitige, bearbeitbare Dateien (Uploads, Protokolle, Bilder, MongoDB-Daten und NGINX-Konfiguration) werden per Bind-Mount in Projektordner eingebunden, wo ein direkter Zugriff vom Host aus nützlich ist.

## Lokale Einrichtung [#local-setup]

Eine Einrichtung ohne Container ist arbeitsintensiver. Befolgen Sie die Anweisungen im [RAG API repo](https://github.com/LibreChat-AI/rag-api/).

Setze `RAG_API_URL` in deiner LibreChat-`.env`-Datei auf die Adresse, unter der die API von deinem Setup aus erreichbar ist. Dies unterscheidet sich vom mitgelieferten Docker-Setup, in dem der Wert bereits im Dienst `api` der Standarddateien `docker-compose.yml` und `deploy-compose.yml` gesetzt ist.

## Konfiguration [#configuration]

Legen Sie RAG API-Optionen über Umgebungsvariablen in einer `.env`-Datei fest, auf die die API zugreifen kann. Die meisten sind optional, abgesehen von den Anmeldeinformationen und Pfaden, die von Ihrem gewählten Anbieter benötigt werden. In der Standardkonfiguration ist nur `RAG_OPENAI_API_KEY` erforderlich.

## Verwendung [#usage]

Sobald die RAG-API erreichbar ist, muss in LibreChat nichts weiter aktiviert werden. Nutzer laden Dateien über **Upload for File Search** hoch, und das Modell fragt den Index über das Tool `file_search` ab, wenn eine Frage dies erfordert. Ist `RAG_API_URL` nicht gesetzt oder der Dienst nicht erreichbar, schlagen diese Uploads fehl; LibreChat protokolliert beim Start eine Warnung, wenn die Health-Check-Prüfung der RAG-API nicht erreicht werden kann. Die Nutzerperspektive finden Sie unter [Chat with Files](/docs/features/rag_api).

## Fehlerbehebung [#troubleshooting]

Falls Probleme bei der Einrichtung oder Verwendung der RAG API auftreten:

- Stellen Sie sicher, dass alle erforderlichen Umgebungsvariablen korrekt in Ihrer `.env` Datei gesetzt sind.
- Stellen Sie sicher, dass die Vektordatenbank konfiguriert und erreichbar ist.
- Überprüfen Sie, ob der OpenAI API-Schlüssel oder andere Anbieter-Anmeldeinformationen gültig sind.
- Überprüfen Sie sowohl die LibreChat- als auch die RAG-API-Protokolle auf Fehler oder Warnungen.

Falls das Problem weiterhin besteht, lesen Sie die RAG API Dokumentation oder fragen Sie die LibreChat Community auf GitHub Discussions oder Discord.
