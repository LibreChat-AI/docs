  Ce document explique comment utiliser la fonctionnalité de journalisation de
  LibreChat, qui enregistre les journaux d'erreurs et de débogage dans le
  dossier `/api/logs`. Vous pouvez utiliser ces journaux pour résoudre les
  problèmes, surveiller votre serveur et signaler des bogues. Les journaux de
  débogage ne sont écrits que si vous les activez explicitement avec
  DEBUG_LOGGING=true.

### Général [#general]

LibreChat dispose d'une journalisation centrale intégrée à son backend (api).

- Avec l'installation **Docker**, les fichiers journaux sont enregistrés dans `/logs`

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="logs" defaultOpen>
      <FileTree.File name="debug-2024-01-01.log" active />
      <FileTree.File name="error-2024-01-01.log" active />
      <FileTree.File name="meiliSync-2024-01-01.log" active />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

- Avec l'installation **npm**, les fichiers journaux sont enregistrés dans `/api/logs`

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="api" defaultOpen>
      <FileTree.Folder name="logs" defaultOpen>
        <FileTree.File name="debug-2024-01-01.log" active />
        <FileTree.File name="error-2024-01-01.log" active />
        <FileTree.File name="meiliSync-2024-01-01.log" active />
      </FileTree.Folder>
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

Les journaux d'erreurs sont enregistrés par défaut. Les fichiers journaux de débogage ne sont écrits que lorsque `DEBUG_LOGGING=true` ; le fichier `.env.example` fourni le définit à `true`, mais si la variable n'est pas définie, aucun fichier de débogage n'est créé.

Cela vous permet de surveiller votre serveur via des outils externes qui inspectent les fichiers journaux, tels que **[la pile ELK](https://aws.amazon.com/what-is/elk-stack/)**.

Les journaux de débogage sont essentiels au travail des développeurs et à la résolution des problèmes. Si vous rencontrez des difficultés lors de l'exécution de LibreChat, reproduisez-les aussi fidèlement que possible et **[signalez le problème](https://github.com/LibreChat-AI/LibreChat/issues)** en joignant vos journaux situés dans `./api/logs/debug-%DATE%.log`.

Les journaux d'erreurs sont également enregistrés au même emplacement : `./api/logs/error-%DATE%.log`. Si vous avez configuré Meilisearch, il existe également un fichier journal distinct pour celui-ci.

<Callout type="note" title="Remarque :">
  Les fichiers journaux sont mis en rotation quotidiennement : un nouveau fichier est créé chaque jour, et un fichier est également scindé dès qu'il atteint 20 Mo. Les fichiers mis en rotation sont compressés au format gzip et conservés pendant 14 jours. Les erreurs figurent également dans les fichiers journaux de débogage, mais les fichiers journaux d'erreurs fournissent les traces de pile et davantage de détails.
</Callout>

### Configuration [#setup]

- Les fichiers journaux de débogage ne sont écrits que lorsque cette variable est définie à `true`. Si elle n'est pas définie ou si elle est définie à une autre valeur, aucun fichier de débogage n'est créé.

<OptionTable
  options={[['DEBUG_LOGGING', 'boolean', 'Écrire les journaux de débogage dans un fichier. Obligatoire pour que les fichiers journaux de débogage soient créés.', 'DEBUG_LOGGING=true']]}
/>

> Note : il est recommandé de désactiver les journaux de débogage dans un environnement de production.

- Pour une sortie serveur détaillée dans la console/le terminal, vous pouvez définir ce qui suit sur `TRUE` :

<OptionTable
  options={[
    [
      'DEBUG_CONSOLE',
      'boolean',
      'Activer les logs détaillés de la console/stdout dans le même format que les logs de débogage des fichiers.',
      'DEBUG_CONSOLE=false',
    ],
  ]}
/>

Ceci n'est cependant pas recommandé, car les sorties peuvent être assez verbeuses. C'est désactivé par défaut et devrait être activé avec parcimonie.

- Lors de la gestion des journaux de console dans les déploiements cloud (tels que GCP ou AWS), l'activation de cette option permettra d'exporter les journaux avec un horodatage UTC et de les formater au format JSON.

<OptionTable
  options={[
    [
      'CONSOLE_JSON',
      'boolean',
      'Activer les journaux console/stdout JSON détaillés adaptés aux déploiements cloud comme GCP/AWS.',
      'CONSOLE_JSON=false',
    ],
  ]}
/>

Par défaut, la longueur de la chaîne JSON est tronquée à 255 caractères. Vous pouvez configurer cela avec la variable d'environnement suivante :

<OptionTable
  options={[
    [
      'CONSOLE_JSON_STRING_LENGTH',
      'number',
      'Configurez la taille de troncature pour les valeurs de chaîne dans les journaux de console/stdout JSON. Par défaut : 255.',
      '# CONSOLE_JSON_STRING_LENGTH=255',
    ],
  ]}
/>

- La verbosité de la console peut être définie avec `CONSOLE_LOG_LEVEL` (`error`, `warn`, `info`, `http`, `verbose`, `debug`, `activity`, `silly` ou `silent`). `silent` désactive la sortie console sans désactiver la journalisation dans les fichiers. Les valeurs invalides reviennent à la valeur par défaut avec un avertissement.

<OptionTable
  options={[
    [
      'CONSOLE_LOG_LEVEL',
      'string',
      'Verbosité de la console. Par défaut à info, ou à debug lorsque DEBUG_CONSOLE=true ; une valeur explicite est prioritaire.',
      '# CONSOLE_LOG_LEVEL=info',
    ],
  ]}
/>

- Les messages de journalisation de débogage sont tronqués à 150 caractères par défaut, et la rédaction des journaux est limitée à 5000 valeurs par enregistrement. Ajustez ces valeurs avec `DEBUG_MESSAGE_LENGTH` et `LOG_REDACTION_MAX_NODES`.

<OptionTable
  options={[
    [
      'DEBUG_MESSAGE_LENGTH',
      'number',
      'Longueur maximale d\'un message de journal de débogage avant qu\'il ne soit tronqué. Par défaut : 150.',
      '# DEBUG_MESSAGE_LENGTH=150',
    ],
    [
      'LOG_REDACTION_MAX_NODES',
      'number',
      'Nombre maximal de valeurs qu\'un enregistrement de journal peut masquer avant que le reste ne soit remplacé. Par défaut : 5000.',
      '# LOG_REDACTION_MAX_NODES=5000',
    ],
  ]}
/>

- Pour écrire les fichiers journaux à un emplacement autre que celui par défaut, définissez `LIBRECHAT_LOG_DIR`. Consultez la section [Logging](/docs/configuration/dotenv#logging) dans la référence du `.env`.

- Les transports de journaux basés sur des fichiers sont activés par défaut. Définissez `LOG_TO_FILE=false` si votre déploiement ne doit émettre des journaux que vers stdout/stderr.

<OptionTable
  options={[
    [
      'LOG_TO_FILE',
      'boolean',
      'Définir sur false pour désactiver les transports Winston basés sur des fichiers.',
      'LOG_TO_FILE=true',
    ],
  ]}
/>

### Traçage OpenTelemetry [#opentelemetry-tracing]

LibreChat peut émettre des traces OpenTelemetry backend pour la visibilité du serveur, de la base de données, de Redis et des requêtes HTTP sortantes. Les spans au niveau des commandes Redis sont optionnelles afin que les traces par défaut restent de haut niveau. Ceci est distinct de Langfuse, qui demeure l'option recommandée pour l'observabilité des prompts et des modèles GenAI.
