La API de RAG indexa los archivos subidos por el usuario y recupera pasajes relevantes para aumentar sus prompts, brindando a LibreChat respuestas con conciencia del contexto basadas en sus documentos. Se ejecuta como un servicio de FastAPI independiente respaldado por una base de datos PostgreSQL + pgvector.

<Callout type="info" title="Lo que ven los usuarios">
[Chat con archivos](/docs/features/rag_api) cubre la carga de archivos para búsqueda de archivos, la reutilización de archivos y la búsqueda de archivos en agentes. Esta página cubre la configuración y la configuración inicial.
</Callout>

## Disponibilidad [#availability]

La búsqueda de archivos a través de la API de RAG funciona en [Agents](/docs/features/agents) y en los chats normales en todos los endpoints excepto Assistants. Los OpenAI Assistants utilizan en su lugar el almacenamiento y la recuperación de archivos propios de OpenAI, y los archivos subidos allí no pueden adjuntarse en otros lugares.

Los usuarios solo ven **Upload for File Search** cuando la capacidad de agente `file_search` está habilitada (lo está por defecto) y su rol tiene el permiso de File Search ([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch)).

## Inicio rápido con Docker [#docker-quick-start]

Para Docker, la API de RAG ya está configurada tanto en los archivos `docker-compose.yml` como `deploy-compose.yml` por defecto, incluido el valor de `RAG_API_URL`. Solo necesitas asegurarte de que estás ejecutando la imagen y los archivos de Compose más recientes. Consulta la [guía de actualización de LibreChat para Docker](/docs/local/docker#updating-librechat) si no estás seguro de cómo actualizarlo.

<Callout type="warning" title="Archivo .env compartido">
Con la configuración predeterminada de Docker, el archivo `.env` se comparte entre LibreChat y la RAG API. Define las variables de RAG en ese mismo archivo. La lista completa se encuentra en el [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md).
</Callout>

The default `docker-compose.yml` and `deploy-compose.yml` files set `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` on the `api` service. Las variables de entorno definidas en el servicio tienen prioridad sobre el archivo `.env`, por lo que no es necesario añadir `RAG_API_URL` a `.env` para la configuración incluida, y definirla allí no tiene ningún efecto. Para apuntar un despliegue de Docker a una API RAG externa, sobrescribe el valor en el servicio `api`, por ejemplo, para una API RAG que se ejecuta en el host de Docker:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

La entrada `extra_hosts` es necesaria en Linux, ya que Docker no define `host.docker.internal` por sí mismo.

Compose carga `docker-compose.override.yml` automáticamente solo con el `docker-compose.yml` predeterminado. Con `deploy-compose.yml`, pase ambos archivos: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`.

Fuera de Docker, establece `RAG_API_URL` en tu archivo `.env`.

### Lite vs. full image [#lite-vs-full-image]

Docker utiliza la imagen "lite" de la RAG API de forma predeterminada (`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`), la cual solo admite embeddings remotos de OpenAI o de un servicio remoto de HuggingFace/Ollama que hayas configurado.

Para embeddings locales, cambie la imagen en el archivo compose a la compilación completa, `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest`. Realice este cambio en su [Docker Compose Override File](/docs/configuration/docker_override). Consulte `docker-compose.override.yml.example` en la raíz del proyecto para ver un ejemplo.

Si deseas un archivo compose que incluya solo la base de datos PostgreSQL + pgvector y la API de Python, consulta `rag.yml` en la raíz del proyecto.

### Almacenamiento de base de datos [#database-storage]

Los archivos compose predeterminados almacenan los datos de pgvector/PostgreSQL en el volumen `pgdata2` gestionado por Docker. Esto es intencional: los archivos de la base de datos no necesitan ser editados directamente desde el host, y un volumen gestionado evita problemas comunes de propiedad y permisos. Los archivos editables orientados al usuario (cargas, registros, imágenes, datos de MongoDB y configuración de NGINX) están montados mediante bind-mount en las carpetas del proyecto donde el acceso directo desde el host es útil.

## Configuración local [#local-setup]

Una configuración sin contenedores requiere más intervención manual. Sigue las instrucciones en el [RAG API repo](https://github.com/LibreChat-AI/rag-api/).

Configura `RAG_API_URL` en tu archivo `.env` de LibreChat con la dirección donde la API sea accesible desde tu entorno. Esto difiere de la configuración Docker incluida, donde el valor ya está establecido en el servicio `api` de los archivos `docker-compose.yml` y `deploy-compose.yml` predeterminados.

## Configuración [#configuration]

Configure las opciones de la API de RAG a través de variables de entorno en un archivo `.env` accesible para la API. La mayoría son opcionales, aparte de las credenciales y rutas requeridas por el proveedor que elija. En la configuración predeterminada, solo se requiere `RAG_OPENAI_API_KEY`.

## Uso [#usage]

Una vez que la API de RAG sea accesible, no hay nada más que activar en LibreChat. Los usuarios suben archivos con **Upload for File Search** y el modelo consulta el índice mediante la herramienta `file_search` cuando una pregunta lo requiere. Si `RAG_API_URL` no está definida o el servicio no está disponible, esas subidas fallan; LibreChat registra una advertencia al iniciarse cuando no puede conectarse a la comprobación de estado (health check) de la API de RAG. Para el lado del usuario, consulta [Chat with Files](/docs/features/rag_api).

## Solución de problemas [#troubleshooting]

Si tienes problemas al configurar o utilizar la RAG API:

- Confirme que todas las variables de entorno requeridas estén configuradas correctamente en su archivo `.env`.
- Asegúrate de que la base de datos vectorial esté configurada y accesible.
- Verifique que la clave de API de OpenAI u otras credenciales de proveedor sean válidas.
- Revisa los registros de LibreChat y de la API de RAG en busca de errores o advertencias.

Si el problema persiste, consulta la documentación de la RAG API o pregunta a la comunidad de LibreChat en GitHub Discussions o Discord.
