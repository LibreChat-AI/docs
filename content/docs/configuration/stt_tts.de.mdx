## Einführung zur Sprachausgabe [#speech-introduction]

Die Sprachkonfiguration umfasst Einstellungen für sowohl Speech-to-Text (STT) als auch Text-to-Speech (TTS) unter einem vereinheitlichten `speech:`-Abschnitt. Zusätzlich gibt es ein neues `speechTab`-Menü für benutzerspezifische Einstellungen.

> **Siehe auch:** Für ein detailliertes YAML-Konfigurationsschema und alle verfügbaren Optionen siehe die Dokumentation zur [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech).

### Umgebungsvariablen [#environment-variables]

Wenn Sie cloudbasierte STT/TTS-Dienste verwenden, müssen Sie die API-Schlüssel in Ihrer `.env` Datei festlegen:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Diese Schlüssel werden dann in Ihrer `librechat.yaml` Konfiguration unter Verwendung von `${STT_API_KEY}` und `${TTS_API_KEY}` referenziert.

### Ein Anbieter pro Dienst [#one-provider-per-service]

Jeder der Abschnitte `speech.stt` und `speech.tts` akzeptiert höchstens einen Anbieterblock. Beide Abschnitte können weggelassen werden, um für diesen Dienst weiterhin die Browser-Engine zu verwenden. Wenn ein Abschnitt mehr als einen Anbieter enthält, schlagen Anfragen mit der Fehlermeldung „Multiple providers are set. Please set only one provider." fehl.

### Selbstgehostete Engines benötigen einen allowedAddresses-Eintrag [#self-hosted-engines-need-an-allowedaddresses-entry]

Sowohl `speech.stt` als auch `speech.tts` akzeptieren eine `allowedAddresses`-Liste. Ausgehende Sprachanfragen werden anhand ihrer aufgelösten IP validiert und daran gehindert, private, Loopback- und Link-Local-Adressbereiche zu erreichen. Daher ist eine selbst gehostete Engine auf `localhost`, einer LAN-Adresse oder einem Docker-Dienstnamen nicht erreichbar, bis Sie diese auflisten:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

Einträge sind reine `host:port`-Paare: kein Schema oder Pfad, Port erforderlich, IPv6 in Klammern als `[::1]:8080`, und IP-Literale müssen privat sein. Öffentliche Cloud-endpoints wie OpenAI, Azure und ElevenLabs benötigen keinen Eintrag. Der Schutzmechanismus arbeitet mit der aufgelösten IP, nicht mit dem Hostnamen. Daher wird ein Cloud-endpoint, der über Private Link, privates DNS oder ein VPN erreicht wird, in einen privaten Adressraum aufgelöst und muss wie jedes andere private Ziel mit seinem exakten `host:port` aufgeführt werden. Dasselbe Feld und dieselben Regeln gelten unter `speech.stt`. Siehe [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) für das vollständige Format der Einträge.

## Tab "Sprache" (optional) [#speech-tab-optional]

Das `speechTab`-Menü bietet anpassbare Optionen für Konversations- und erweiterte Modi sowie detaillierte Einstellungen für STT und TTS. Dies legt die Standardeinstellungen für Benutzer fest.

Verwenden Sie `browser` für die integrierte Browser-Sprachausgabe oder `external` für einen unten konfigurierten serverseitigen Anbieter. Ältere anbieterspezifische Standardeinstellungen werden aus Kompatibilitätsgründen weiterhin akzeptiert und zu `external` normalisiert; falls der entsprechende externe Dienst nicht verfügbar ist, greift LibreChat auf `browser` zurück.

Beispiel:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` legt die Anfangswerte fest, die Benutzer sehen; jeder Wert bleibt pro Benutzer im Tab für Spracheinstellungen änderbar.

## STT (Speech-to-Text) [#stt-speech-to-text]

Die Funktion Sprache-zu-Text (STT) wandelt gesprochene Wörter in geschriebenen Text um. Um STT zu aktivieren, klicken Sie auf die STT-Schaltfläche (neben der Senden-Schaltfläche) oder verwenden Sie die Tastenkombination ++Shift+Alt+L++, um die Transkription zu starten.

### Verfügbare STT-Dienste [#available-stt-services]

- **Lokale STT**
  - Browser-basiert
  - Whisper (getestet auf LocalAI)
- **Cloud-STT**
  - OpenAI Whisper
  - Azure Whisper
  - Andere OpenAI-kompatible STT-Dienste

### Lokale STT konfigurieren [#configuring-local-stt]

- #### Browser-based
  Keine Einrichtung erforderlich. Stellen Sie sicher, dass der Schalter "Speech To Text" im Tab für Spracheinstellungen aktiviert ist und im Engine-Dropdown-Menü "Browser" ausgewählt ist.

- #### Whisper Lokal [#whisper-local]
  Erfordert eine lokale Whisper-Instanz.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

Das Feld `apiKey` ist für jeden OpenAI-kompatiblen STT-Block erforderlich, auch für lokale. Falls Ihr Server keine Schlüssel prüft, verwenden Sie einen beliebigen Platzhalterwert.

### Konfiguration von Cloud STT [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Unterstützung für Azure Endpoint-Domains">
Das Feld `instanceName` unterstützt beide Azure OpenAI-Domainformate:
- **Neues Format**: `.cognitiveservices.azure.com` (z. B. `my-instance.cognitiveservices.azure.com`)
- **Legacy-Format**: `.openai.azure.com` (z. B. `my-instance.openai.azure.com`)

Sie können entweder die vollständige Domain oder nur den Instanznamen angeben. Wenn Sie eine vollständige Domain einschließlich `.azure.com` angeben, wird diese unverändert verwendet. Andernfalls wird aus Gründen der Abwärtskompatibilität das ältere Format `.openai.azure.com` angewendet.
</Callout>

- #### OpenAI-kompatibel [#openai-compatible]

Siehe den Abschnitt zu OpenAI Whisper und passe `url` und `model` bei Bedarf an. Das Feld `apiKey` ist weiterhin erforderlich.

Beispiel
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

Die Text-to-Speech (TTS)-Funktion wandelt geschriebenen Text in gesprochene Worte um. Es stehen verschiedene TTS-Dienste zur Verfügung:

### Verfügbare TTS-Dienste [#available-tts-services]

- **Lokale TTS**
  - Browser-basiert
  - Piper (getestet auf LocalAI)
  - Coqui (getestet auf LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Andere mit OpenAI/ElevenLabs kompatible TTS-Dienste

Text, der länger als `speech.tts.maxInputChars` ist (Standardwert 20000 Zeichen), wird vor dem Vorlesen gekürzt. Details finden Sie in der [Speech-Objektstruktur](/docs/configuration/librechat_yaml/object_structure/speech).

### Lokales TTS konfigurieren [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

Keine Einrichtung erforderlich. Stellen Sie sicher, dass der Schalter "Text To Speech" im Tab für Spracheinstellungen aktiviert ist und "Browser" im Dropdown-Menü für die Engine ausgewählt wurde.

- #### Piper [#piper]

Erfordert eine lokale Piper-Instanz.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Erfordert eine lokale Coqui-Instanz.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Konfigurieren von Cloud TTS [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Unterstützung für Azure Endpoint-Domains">
Das Feld `instanceName` unterstützt beide Azure OpenAI-Domainformate:
- **Neues Format**: `.cognitiveservices.azure.com` (z. B. `my-instance.cognitiveservices.azure.com`)
- **Legacy-Format**: `.openai.azure.com` (z. B. `my-instance.openai.azure.com`)

Sie können entweder die vollständige Domain oder nur den Instanznamen angeben. Wenn Sie eine vollständige Domain einschließlich `.azure.com` angeben, wird diese unverändert verwendet. Andernfalls wird aus Gründen der Abwärtskompatibilität das ältere Format `.openai.azure.com` angewendet.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Zusätzliche ElevenLabs-spezifische Parameter können wie folgt hinzugefügt werden:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### OpenAI-kompatibel [#openai-compatible-1]

Siehe den OpenAI TTS Abschnitt und passe die `url` Variable nach Bedarf an.

Beispiel:

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### ElevenLabs-kompatibel [#elevenlabs-compatible]

Siehe den Abschnitt ElevenLabs und passe die Variable `url` nach Bedarf an.

Beispiel:

```yaml
speech:
  tts:
    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```
