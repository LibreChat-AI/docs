## 음성 기능 소개 [#speech-introduction]

음성 구성(Speech Configuration)에는 통합된 `speech:` 섹션 하위에 음성 인식(STT) 및 음성 합성(TTS)을 위한 설정이 포함되어 있습니다. 또한, 사용자별 설정을 위한 새로운 `speechTab` 메뉴가 추가되었습니다.

> **참고:** 자세한 YAML 구성 스키마 및 사용 가능한 모든 옵션은 [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech) 문서를 참조하세요.

### 환경 변수 [#environment-variables]

클라우드 기반 STT/TTS 서비스를 사용할 때는 `.env` 파일에 API 키를 설정해야 합니다:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

그런 다음 이 키들은 `${STT_API_KEY}` 및 `${TTS_API_KEY}`를 사용하여 `librechat.yaml` 구성에서 참조됩니다.

### 서비스당 하나의 제공자 [#one-provider-per-service]

`speech.stt`와 `speech.tts`는 각각 최대 하나의 제공자 블록만 받을 수 있으며, 두 섹션 중 어느 쪽이든 생략하여 해당 서비스에 브라우저 엔진을 그대로 사용할 수 있습니다. 한 섹션에 제공자가 둘 이상 설정되어 있으면 요청이 실패하고 "Multiple providers are set. Please set only one provider." 오류가 발생합니다.

### 자체 호스팅 엔진에는 allowedAddresses 항목이 필요합니다 [#self-hosted-engines-need-an-allowedaddresses-entry]

`speech.stt`와 `speech.tts` 모두 `allowedAddresses` 목록을 허용합니다. 아웃바운드 음성 요청은 확인된 IP를 기준으로 검증되며, 사설(private), 루프백(loopback), 링크 로컬(link-local) 주소 공간으로의 접근이 차단됩니다. 따라서 `localhost`, LAN 주소 또는 Docker 서비스 이름에 호스팅된 엔진은 다음 목록에 추가하기 전까지는 접근할 수 없습니다:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

항목은 `host:port` 쌍으로만 구성되어야 합니다. 스키마나 경로는 포함하지 않으며 포트가 필수입니다. IPv6는 `[::1]:8080`과 같이 대괄호로 묶어야 하며, IP 리터럴은 반드시 사설 IP여야 합니다. OpenAI, Azure, ElevenLabs와 같은 퍼블릭 클라우드 endpoint는 별도의 항목이 필요하지 않습니다. 이 가드는 호스트 이름이 아닌 확인된 IP를 기반으로 작동하므로, Private Link, 사설 DNS 또는 VPN을 통해 연결된 클라우드 endpoint는 사설 주소 공간으로 확인되며 다른 사설 대상과 마찬가지로 정확한 `host:port`를 나열해야 합니다. 동일한 필드와 규칙이 `speech.stt`에도 적용됩니다. 전체 항목 형식은 [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers)을 참조하세요.

## Speech 탭 (선택 사항) [#speech-tab-optional]

`speechTab` 메뉴는 대화 및 고급 모드에 대한 사용자 지정 옵션과 STT 및 TTS에 대한 상세 설정을 제공합니다. 이는 사용자들을 위한 기본 설정을 지정합니다.

내장 브라우저 음성 기능을 사용하려면 `browser`를, 아래에 구성된 서버 측 제공업체를 사용하려면 `external`을 사용하세요. 호환성을 위해 이전의 제공업체별 기본값도 계속 허용되며, 이는 `external`로 정규화됩니다. 일치하는 외부 서비스를 사용할 수 없는 경우, LibreChat은 `browser`로 대체됩니다.

예시:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab`은 사용자가 보게 될 초기 값을 설정하며, 각 값은 음성 설정 탭에서 사용자별로 변경할 수 있습니다.

## STT (Speech-to-Text) [#stt-speech-to-text]

음성-텍스트 변환(STT) 기능은 음성을 문자 텍스트로 변환합니다. STT를 사용하려면 전송 버튼 근처에 있는 STT 버튼을 클릭하거나 ++Shift+Alt+L++ 키 조합을 사용하여 전사를 시작하세요.

### 사용 가능한 STT 서비스 [#available-stt-services]

- **로컬 STT**
  - 브라우저 기반
  - Whisper (LocalAI에서 테스트됨)
- **클라우드 STT**
  - OpenAI Whisper
  - Azure Whisper
  - 기타 OpenAI 호환 STT 서비스

### 로컬 STT 구성하기 [#configuring-local-stt]

- #### Browser-based
  별도의 설정이 필요하지 않습니다. 음성 설정 탭에서 "Speech To Text" 스위치가 활성화되어 있는지 확인하고, 엔진 드롭다운에서 "Browser"가 선택되어 있는지 확인하세요.

- #### Whisper Local [#whisper-local]
  로컬 Whisper 인스턴스가 필요합니다.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

`apiKey` 필드는 로컬 서버를 포함한 모든 OpenAI 호환 STT 블록에서 필수입니다. 서버가 키를 검증하지 않는 경우에는 아무 자리표시자 값이나 사용하면 됩니다.

### Cloud STT 구성하기 [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Azure 엔드포인트 도메인 지원">
`instanceName` 필드는 다음 두 가지 Azure OpenAI 도메인 형식을 모두 지원합니다:
- **새로운 형식**: `.cognitiveservices.azure.com` (예: `my-instance.cognitiveservices.azure.com`)
- **레거시 형식**: `.openai.azure.com` (예: `my-instance.openai.azure.com`)

전체 도메인 또는 인스턴스 이름 중 하나를 지정할 수 있습니다. `.azure.com`을 포함한 전체 도메인을 제공하면 그대로 사용됩니다. 그렇지 않은 경우, 하위 호환성을 위해 레거시 `.openai.azure.com` 형식이 적용됩니다.
</Callout>

- #### OpenAI 호환 [#openai-compatible]

OpenAI Whisper 섹션을 참고하여 `url`과 `model`을 필요에 따라 조정하세요. `apiKey` 필드는 여전히 필수입니다.

예시
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

Text-to-Speech (TTS) 기능은 작성된 텍스트를 음성으로 변환합니다. 다양한 TTS 서비스를 사용할 수 있습니다:

### 사용 가능한 TTS 서비스 [#available-tts-services]

- **로컬 TTS**
  - 브라우저 기반
  - Piper (LocalAI에서 테스트됨)
  - Coqui (LocalAI에서 테스트됨)
- **클라우드 TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - 기타 OpenAI/ElevenLabs 호환 TTS 서비스

`speech.tts.maxInputChars`(기본값 20000자)를 초과하는 텍스트는 음성으로 읽어 주기 전에 잘립니다. 자세한 내용은 [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech)를 참고하세요.

### 로컬 TTS 구성하기 [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

별도의 설정이 필요하지 않습니다. 음성 설정 탭에서 "Text To Speech" 스위치가 활성화되어 있는지 확인하고, 엔진 드롭다운에서 "Browser"가 선택되어 있는지 확인하세요.

- #### Piper [#piper]

로컬 Piper 인스턴스가 필요합니다.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

로컬 Coqui 인스턴스가 필요합니다.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Cloud TTS 구성하기 [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Azure 엔드포인트 도메인 지원">
`instanceName` 필드는 다음 두 가지 Azure OpenAI 도메인 형식을 모두 지원합니다:
- **새로운 형식**: `.cognitiveservices.azure.com` (예: `my-instance.cognitiveservices.azure.com`)
- **레거시 형식**: `.openai.azure.com` (예: `my-instance.openai.azure.com`)

전체 도메인 또는 인스턴스 이름 중 하나를 지정할 수 있습니다. `.azure.com`을 포함한 전체 도메인을 제공하면 그대로 사용됩니다. 그렇지 않은 경우, 하위 호환성을 위해 레거시 `.openai.azure.com` 형식이 적용됩니다.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

다음과 같이 ElevenLabs 관련 추가 매개변수를 추가할 수 있습니다:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### OpenAI 호환 [#openai-compatible-1]

OpenAI TTS 섹션을 참조하여 필요에 따라 `url` 변수를 조정하세요.

예시:

