Cette page couvre le côté administrateur des [Artifacts](/docs/features/artifacts). Les utilisateurs activent les artifacts par agent dans l'Agent Builder ; les paramètres présentés ici déterminent si cette option existe et depuis où les aperçus sont chargés.

## Activation des artefacts [#enabling-artifacts]

Les artefacts sont une fonctionnalité des agents. `artifacts` figure dans la liste par défaut de [`endpoints.agents.capabilities`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), elle est donc disponible sauf si vous définissez votre propre liste sans elle. Si vous remplacez `capabilities`, incluez `artifacts` pour conserver l'option dans le Constructeur d'agents.

Pour donner des artefacts de spécification de modèle sans créer d'agent, définissez [`artifacts`](/docs/configuration/librechat_yaml/object_structure/model_specs#artifacts) sur la spécification. `true` utilise le mode par défaut ; vous pouvez également transmettre un nom de mode : `default`, `shadcnui` ou `custom`.

## Ouvrir le panneau dans une nouvelle fenêtre [#opening-the-panel-in-a-new-window]

Le panneau comporte un bouton **Ouvrir dans une nouvelle fenêtre** qui le déplace dans une fenêtre de navigateur distincte. Il est activé par défaut. Si votre déploiement s'exécute dans un environnement où les fenêtres popup ne fonctionnent pas, comme une webview intégrée, désactivez-le avec [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking) ; le panneau ancré continuera de fonctionner.

## Content-Security-Policy

LibreChat lui-même autorise les frames HTTPS dans sa politique CSP, de sorte que le bundler CodeSandbox par défaut se charge sans modification. Si un reverse proxy ou un CDN placé devant LibreChat définit une `Content-Security-Policy` plus stricte, autorisez l'origine du bundler dans `frame-src` : `https://*.codesandbox.io` pour le bundler public, ou vos propres URL de bundler si vous l'hébergez vous-même. Lorsque vous avez seulement besoin d'étendre la politique intégrée de LibreChat, utilisez `CSP_FRAME_SRC_EXTRA`.

Les aperçus React chargent également Tailwind depuis `cdn.tailwindcss.com`. Cet hôte doit donc être accessible depuis les navigateurs des utilisateurs.

## Auto-hébergement du bundler Sandpack [#self-hosting-the-sandpack-bundler]

Les aperçus sont rendus par [Sandpack](https://sandpack.codesandbox.io/), qui, par défaut, récupère son bundler depuis le CDN public de CodeSandbox. Ce CDN envoie également des données de télémétrie d'utilisation. Pour les réseaux privés, les exigences de conformité, ou pour supprimer la dépendance à un service externe, [hébergez vous-même le bundler](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler).

[LibreChat-AI/codesandbox-client](https://github.com/LibreChat-AI/codesandbox-client) est un fork préparé pour LibreChat, dans lequel les requêtes de télémétrie ont été supprimées, y compris celles des images de conteneurs.

LibreChat utilise deux bundlers. `SANDPACK_BUNDLER_URL` sert les artefacts React, et `SANDPACK_STATIC_BUNDLER_URL` sert le modèle statique derrière les aperçus HTML, SVG, Markdown, code et fichiers Office. Définissez les deux lors d'un auto-hébergement : si une seule est définie, les autres types d'artefacts se chargeront quand même depuis le CDN public. Les deux sont listées dans la [référence `.env`](/docs/configuration/dotenv#artifacts). Les diagrammes Mermaid s'affichent directement dans la page et n'utilisent aucun des deux bundlers.

Exécuter votre propre bundler signifie que vous êtes responsable de ses paramètres CORS, de ses mises à jour de sécurité et de ses ressources d'hébergement. Redémarrez LibreChat après avoir modifié ces variables ; les URL sont envoyées au navigateur dans la configuration de démarrage.
