## 일반 [#general]

![LibreChat의 활성 사용자](/images/metrics/librechat-metrics-active-users.png)

LibreChat은 Prometheus와 호환되는 두 가지 메트릭 인터페이스를 제공합니다. API에 내장된 `/metrics` endpoint는 Redis 활동 및 브라우저 텔레메트리 프록시 결과와 같은 운영 동작을 보고합니다. 선택적으로 사용할 수 있는 데이터베이스 익스포터는 토큰 합계 및 활성 사용자 수를 포함하여 MongoDB에 저장된 사용 데이터를 보고합니다.

## 내장 API 메트릭 [#built-in-api-metrics]

LibreChat은 `/metrics`에서 API 서버의 Prometheus 메트릭을 노출합니다. `METRICS_SECRET`을 설정하고 `Authorization: Bearer <METRICS_SECRET>` 헤더를 사용하여 엔드포인트를 스크랩하십시오. 시크릿이 설정되지 않았거나, 헤더가 누락되었거나, 토큰이 일치하지 않는 경우 엔드포인트는 `401`을 반환합니다.

```yaml filename="prometheus.yml"
scrape_configs:
  - job_name: librechat-api
    scheme: https
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials: your-metrics-secret
    static_configs:
      - targets: ['librechat.example.com']
```

### 프로세스, HTTP 및 요청 메트릭 [#process-http-and-request-metrics]

엔드포인트는 `prom-client`의 기본 Node.js 및 프로세스 메트릭과 함께 다음 시리즈도 노출합니다.

| 그룹 | 지표 | 레이블 |
| --- | --- | --- |
| HTTP | `http_requests_total`, `http_request_duration_seconds` | `method`, `path`, `status` |
| HTTP | `http_requests_in_flight`, `http_request_body_bytes` (`Content-Length` 기준) | `method`, `path` |
| SSE | `sse_streams_total`, `sse_stream_duration_seconds` | `method`, `path`, `status` |
| SSE | `sse_streams_in_flight` | `method`, `path` |
| 업로드 | `upload_requests_total`, `upload_request_duration_seconds` | `method`, `path`, `status` |
| 업로드 | `upload_requests_in_flight`, `upload_bytes_total` (`Content-Length` 기준) | `method`, `path` |
| OpenID | `openid_user_lookup_total`, `openid_user_lookup_duration_seconds` | `result` |
| Mongoose | `mongoose_queries_total`, `mongoose_query_duration_seconds` | `model`, `operation`, `status` |
| 생성 작업 | `generation_jobs_total` | `store`, `result` |
| 생성 작업 | `generation_jobs_in_flight` | `store` |
| 생성 스트림 | `generation_stream_subscriptions_total` | `store`, `type`, `result` |
| 생성 스트림 | `generation_stream_resume_pending_events_total`, `generation_stream_early_buffer_overflows_total`, `generation_stream_first_attachment_delay_seconds` | `store` |
| 생성 스트림 | `generation_stream_attachment_outcomes_total` | `store`, `outcome` |
| 생성 스트림 | `generation_stream_recoveries_total`, `generation_stream_recovery_duration_seconds`, `generation_stream_recovery_events`, `generation_stream_recovery_content_parts` | `store`, `method`, `outcome` |
| 콘텐츠 필터 | `content_filter_locator_traversal_failures_total` | `operation`, `reason` |
| 콘텐츠 필터 | `content_filter_locator_traversal_size` | `operation`, `reason`, `dimension` |

생성 스트림 복구 지표는 오버플로된 초기 이벤트 버퍼가 어떻게 재구성되는지를 설명합니다. 콘텐츠 필터 지표는 불완전하게 해석된 파일 로케이터 순회 횟수를 집계합니다.

### 에이전트 시작 메트릭 [#agent-startup-metrics]

초기 에이전트 채팅 요청은 두 가지 시작 메트릭을 내보냅니다:

- `agent_startup_milestone_duration_seconds{milestone}`는 요청 유입부터 각 시작 마일스톤까지의 누적 지연 시간을 측정합니다.
- `agent_startups_total{result}`는 터미널 결과에 따른 에이전트 시작 시도 횟수를 집계합니다.

마일스톤은 요청 승인, 작업 생성 및 확인, 대화 및 기록 로드, 클라이언트 및 실행 초기화, 스트림 시작, 그리고 첫 번째 대기열 응답 또는 콘텐츠 이벤트를 다룹니다. 결과는 대기열에 추가된 콘텐츠, 콘텐츠 델타 없는 완료, 중복 제거, 거부, 일시 중지, 대체, 중단 및 오류를 구분합니다.

[백엔드 OpenTelemetry 트레이싱](/docs/configuration/dotenv#opentelemetry-traces-and-logs)이 활성화되면, `librechat.agent.startup` 스팬은 동일한 마일스톤을 이벤트로 보고합니다. 여기에는 전체 시작 소요 시간, 마일스톤 개수, 최종 결과, 그리고 할당된 경우 생성 스트림 ID가 포함됩니다.

### Redis 메트릭 [#redis-metrics]

Redis 기반 캐시 및 서비스는 두 가지 논리적 작업 메트릭을 내보냅니다:

- `redis_operations_total{client,use_case,operation,status}`는 작업 횟수를 집계합니다.
- `redis_operation_duration_seconds{client,use_case,operation,status}`는 지연 시간을 측정합니다.

`client`는 `keyv` 또는 `ioredis`이며, `status`는 `success` 또는 `error`입니다. 제한된 `use_case` 레이블은 캐시, 세션, 속도 제한, 동시성, ACL 주체, 재개 가능한 스트림 작업 및 pub/sub, MCP 레지스트리 스캔, 리더 선출과 같은 작업을 식별합니다. 이러한 메트릭은 모든 내부 Redis 왕복이 아닌 LibreChat의 논리적 작업을 계산합니다. 연결 수명 주기 핑과 전역 유지 관리는 제외되며, 네임스페이스를 지우는 작업은 하나의 논리적 작업으로 계산됩니다.

OpenTelemetry 추적([백엔드 OpenTelemetry 추적](/docs/configuration/dotenv#opentelemetry-traces-and-logs))이 활성화되면, 각 HTTP 스팬은 Redis 작업 요약을 다음과 같이 함께 기록합니다:

- `librechat.redis.calls`
- `librechat.redis.duration_ms`
- `librechat.redis.errors`
- `librechat.redis.max_call_ms`
- `librechat.redis.operations`
- `librechat.redis.use_cases`

총 지속 시간이 가장 긴 10개의 사용 사례는 `librechat.redis.<use_case>.*` 하위에 `calls`, `duration_ms`, `errors` 및 `max_call_ms` 속성도 제공받습니다. 이 요청 수준 요약은 명령 수준의 Redis 스팬(span)을 필요로 하지 않으므로, 개별 명령 스팬이 필요한 경우에만 `OTEL_IOREDIS_TRACING_ENABLED`를 활성화하십시오.

### 브라우저 RUM 프록시 메트릭 [#browser-rum-proxy-metrics]

Browser RUM 프록시 결과는 `rum_proxy_requests_total{endpoint,result}`로 보고됩니다. `endpoint`는 `traces`, `logs` 또는 `unknown`이며, `result`는 `success`, `auth_drop`, `auth_error`, `bad_request`, `not_configured`, `collector_4xx`, `collector_5xx`, `collector_error` 또는 `collector_timeout`이 될 수 있습니다.

### 에이전트 이벤트 액터 메트릭(Agent Event Actor Metrics) [#agent-event-actor-metrics]

Durable bound Agent Events는 낮은 카디널리티의 수신 및 복구 메트릭을 노출합니다:

- `agent_event_actor_receipt_operations_total{operation,outcome,resolution}`은 수신 읽기, 정산 및 레거시 백필을 카운트합니다. `operation`은 `read`, `settle` 또는 `backfill`이며, `outcome`은 `hit`, `miss`, `success`, `replay` 또는 `conflict`입니다.
- `agent_event_actor_receipts_retained{resolution}`은 `checkpoint_verified`, `action_compensated` 또는 `history_repaired` 해결(resolution)에 의해 유지된 리플레이 영수증을 보고합니다.
- `agent_event_actor_receipts_expiry_eligible`는 90일 MongoDB TTL이 경과했으나 아직 제거되지 않은 보관된 영수증을 보고합니다.
- `agent_event_actor_reconciliations_pending`는 최종 수신 확인을 기다리는 활성 조정 마커를 보고합니다.
- `agent_event_actor_oldest_reconciliation_age_seconds`는 가장 오래된 활성 조정(reconciliation)의 경과 시간을 보고합니다.
- `agent_event_actor_deliveries{state}`는 현재 `retry` 또는 `dead` 상태인 전달 행(delivery rows)을 보고합니다.

스토리지 게이지는 인증된 스크랩에서 수집되며 최대 60초 동안 캐시됩니다. 단일 스크랩보다는 지속적인 조정 지연(reconciliation age), 전달 실패(dead deliveries) 또는 만료 대상 영수증에 대해 알림을 설정하십시오.

### 공유 링크 메트릭 [#shared-link-metrics]

`share_link_rejections_total{operation,code}`는 제한된 생성 또는 업데이트 실패 횟수를 집계합니다. `operation`은 `create` 또는 `update`이며, `code`는 선택된 브랜치 끝이 지속되지 않은 경우 `TARGET_MESSAGE_NOT_FOUND`이거나, 대화에 지속된 메시지가 없는 경우 `NO_MESSAGES`입니다. 이 메트릭에는 대화 텍스트나 사용자 식별 정보가 포함되지 않습니다.

## 데이터베이스 메트릭 익스포터 [#database-metrics-exporter]

메트릭스 익스포터는 [virtUOS/librechat_exporter](https://github.com/virtUOS/librechat_exporter)에서 이용할 수 있습니다.
이는 LibreChat과 함께 배포하는 별도의 도구입니다.

### 설정 [#setup]

exporter를 배포하려면, 다음과 같이 compose 구성에 필요한 컨테이너를 추가하기만 하면 됩니다:

```yaml
services:
  metrics:
    image: ghcr.io/virtuos/librechat_exporter:main
    depends_on:
      - mongodb
    ports:
      - '8000:8000'
    restart: unless-stopped
```

선택적으로 exporter를 구성할 수도 있습니다.
하지만 일반적으로는 기본값으로도 충분합니다.

```yaml
services:
  metrics:
    environment:
      - MONGODB_URI=mongodb://mongodb:27017/
      - LOGGING_LEVEL=info
```

### 사용법 [#usage]

이제 Prometheus 스크랩 구성에 exporter를 추가할 수 있습니다:

```yaml
- job_name: librechat
  static_configs:
    - targets:
        - 'librechat.example.com:8000'
```

메트릭 스크래핑이 시작되면 `librechat_*` 메트릭(예: `librechat_registered_users`)을 확인하세요.
이 익스포터는 여러 메트릭을 제공합니다.

Grafana 대시보드를 즐겁게 구축해 보세요!
