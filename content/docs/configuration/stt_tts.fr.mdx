## Introduction à la synthèse vocale [#speech-introduction]

La configuration vocale inclut des paramètres pour la conversion parole-texte (STT) et texte-parole (TTS) sous une section `speech:` unifiée. De plus, un nouveau menu `speechTab` est disponible pour les paramètres spécifiques à l'utilisateur.

> **Voir aussi :** Pour le schéma de configuration YAML détaillé et toutes les options disponibles, consultez la documentation [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech).

### Variables d'environnement [#environment-variables]

Lorsque vous utilisez des services STT/TTS basés sur le cloud, vous devrez définir les clés API dans votre fichier `.env` :

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Ces clés sont ensuite référencées dans votre configuration `librechat.yaml` en utilisant `${STT_API_KEY}` et `${TTS_API_KEY}`.

### Un fournisseur par service [#one-provider-per-service]

Chacun de `speech.stt` et `speech.tts` accepte au maximum un seul bloc de fournisseur, et l'une ou l'autre section peut être omise afin de conserver le moteur du navigateur pour ce service. Si une section contient plusieurs fournisseurs, les requêtes échouent avec l'erreur « Multiple providers are set. Please set only one provider. »

### Les moteurs auto-hébergés nécessitent une entrée allowedAddresses [#self-hosted-engines-need-an-allowedaddresses-entry]

`speech.stt` et `speech.tts` acceptent tous deux une liste `allowedAddresses`. Les requêtes vocales sortantes sont validées par rapport à leur adresse IP résolue et sont empêchées d'atteindre les espaces d'adressage privés, de bouclage (loopback) et locaux au lien (link-local). Par conséquent, un moteur auto-hébergé sur `localhost`, une adresse LAN ou un nom de service Docker est inaccessible tant que vous ne l'avez pas listé :

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

Les entrées sont des paires `host:port` brutes : aucun schéma ou chemin, port requis, IPv6 entre crochets comme `[::1]:8080`, et les adresses IP littérales doivent être privées. Les endpoints de cloud public tels que OpenAI, Azure et ElevenLabs ne nécessitent aucune entrée. La protection fonctionne sur l'IP résolue, et non sur le nom d'hôte ; ainsi, un endpoint cloud atteint via Private Link, un DNS privé ou un VPN se résout dans un espace d'adressage privé et nécessite que son `host:port` exact soit listé comme toute autre cible privée. Le même champ et les mêmes règles s'appliquent sous `speech.stt`. Voir [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) pour le format complet de l'entrée.

## Onglet Speech (optionnel) [#speech-tab-optional]

Le menu `speechTab` propose des options personnalisables pour les modes conversation et avancé, ainsi que des paramètres détaillés pour STT et TTS. Cela définira les paramètres par défaut pour les utilisateurs.

Utilisez `browser` pour la synthèse vocale intégrée au navigateur ou `external` pour un fournisseur côté serveur configuré ci-dessous. Les anciennes valeurs par défaut spécifiques aux fournisseurs restent acceptées pour des raisons de compatibilité et sont normalisées vers `external` ; si le service externe correspondant est indisponible, LibreChat revient à `browser`.

exemple :

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` définit les valeurs initiales que les utilisateurs voient ; chacune reste modifiable par utilisateur dans l'onglet des paramètres vocaux.

`engineSTT` / `engineTTS` choisissent uniquement le moteur avec lequel l'interface utilisateur démarre. Toute valeur autre que `browser` nécessite toujours que le fournisseur correspondant soit configuré sous `speech.stt` ou `speech.tts`. Voir les sections ci-dessous.

## STT (Speech-to-Text) [#stt-speech-to-text]

La fonctionnalité de reconnaissance vocale (Speech-to-Text, STT) convertit la parole en texte écrit. Pour activer la reconnaissance vocale, cliquez sur le bouton STT (à côté du bouton d'envoi) ou utilisez la combinaison de touches ++Shift+Alt+L++ pour démarrer la transcription.

### Services STT disponibles [#available-stt-services]

- **STT local**
  - Basé sur le navigateur
  - Whisper (testé sur LocalAI)
- **Cloud STT**
  - OpenAI Whisper
  - Azure Whisper
  - Autres services STT compatibles avec OpenAI

### Configuration de STT local [#configuring-local-stt]

- #### Browser-based
  Aucune configuration requise. Assurez-vous que l'option « Speech To Text » est activée dans l'onglet des paramètres vocaux et que « Browser » est sélectionné dans le menu déroulant du moteur.

- #### Whisper Local [#whisper-local]
  Nécessite une instance Whisper locale.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

Le champ `apiKey` est obligatoire pour chaque bloc STT compatible OpenAI, y compris les blocs locaux. Si votre serveur ne vérifie pas les clés, utilisez n'importe quelle valeur factice.

### Configuration de Cloud STT [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Prise en charge du domaine de l'endpoint Azure">
Le champ `instanceName` prend en charge les deux formats de domaine Azure OpenAI :
- **Nouveau format** : `.cognitiveservices.azure.com` (par ex. `my-instance.cognitiveservices.azure.com`)
- **Format hérité** : `.openai.azure.com` (par ex. `my-instance.openai.azure.com`)

Vous pouvez spécifier soit le domaine complet, soit simplement le nom de l'instance. Si vous fournissez un domaine complet incluant `.azure.com`, il sera utilisé tel quel. Sinon, le format hérité `.openai.azure.com` sera appliqué pour assurer la compatibilité ascendante.
</Callout>

- #### Compatible avec OpenAI [#openai-compatible]

Reportez-vous à la section OpenAI Whisper, en adaptant `url` et `model` selon vos besoins. Le champ `apiKey` reste obligatoire.

exemple
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

La fonctionnalité de synthèse vocale (TTS) convertit le texte écrit en mots parlés. Divers services TTS sont disponibles :

### Services TTS disponibles [#available-tts-services]

- **TTS local**
  - Basé sur le navigateur
  - Piper (testé sur LocalAI)
  - Coqui (testé sur LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Autres services TTS compatibles OpenAI/ElevenLabs

Le texte dont la longueur dépasse `speech.tts.maxInputChars` (valeur par défaut : 20000 caractères) est tronqué avant d'être lu à voix haute. Consultez la [structure de l'objet Speech](/docs/configuration/librechat_yaml/object_structure/speech) pour plus de détails.

### Configuration de la TTS locale [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

Aucune configuration requise. Assurez-vous que l'option "Text To Speech" est activée dans l'onglet des paramètres vocaux et que "Browser" est sélectionné dans le menu déroulant du moteur.

- #### Piper [#piper]

Nécessite une instance Piper locale.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Nécessite une instance Coqui locale.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Configuration de Cloud TTS [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Prise en charge du domaine de l'endpoint Azure">
Le champ `instanceName` prend en charge les deux formats de domaine Azure OpenAI :
- **Nouveau format** : `.cognitiveservices.azure.com` (par ex. `my-instance.cognitiveservices.azure.com`)
- **Format hérité** : `.openai.azure.com` (par ex. `my-instance.openai.azure.com`)

Vous pouvez spécifier soit le domaine complet, soit simplement le nom de l'instance. Si vous fournissez un domaine complet incluant `.azure.com`, il sera utilisé tel quel. Sinon, le format hérité `.openai.azure.com` sera appliqué pour assurer la compatibilité ascendante.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Des paramètres supplémentaires spécifiques à ElevenLabs peuvent être ajoutés comme suit :

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### Compatible avec OpenAI [#openai-compatible-1]

Reportez-vous à la section OpenAI TTS, en ajustant la variable `url` si nécessaire

exemple :

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Compatible avec ElevenLabs [#elevenlabs-compatible]

Reportez-vous à la section ElevenLabs, en ajustant la variable `url` si nécessaire

exemple :

```yaml

  tts:
    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
```
