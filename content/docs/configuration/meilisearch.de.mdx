Meilisearch ist eine Open-Source-Suchmaschine, die die Konversationssuche von LibreChat antreibt und Volltextsuche, Fehlertoleranz sowie sofortige Ergebnisse für vergangene Konversationen ermöglicht. Einen Überblick über die Funktionen finden Sie unter [Search in LibreChat](/docs/features/search).

<Callout type="info" title="Wie es sich verbindet">
LibreChat kommuniziert mit Meilisearch über HTTP unter Verwendung einiger Umgebungsvariablen. Das Docker-Setup liefert Meilisearch als Dienst für Sie mit. Bei einer Quellcode-Installation verweisen Sie LibreChat auf einen Meilisearch-Prozess, den Sie selbst ausführen.
</Callout>

## Meilisearch konfigurieren [#configure-meilisearch]

<Tabs items={['Docker', 'npm']}>
<Tabs.Tab value="Docker">

Die standardmäßige `docker-compose.yml` enthält bereits einen `meilisearch`-Dienst, daher müssen Sie lediglich die Suche aktivieren und einen Master-Key in Ihrer `.env`-Datei festlegen.

<Steps>
<Step>

**Generieren Sie einen Master-Key.** Verwenden Sie eine ausreichend lange, zufällige Zeichenfolge (16 Bytes oder mehr). Zum Beispiel:

```bash filename="terminal"
openssl rand -base64 32
```

</Step>
<Step>

**Fügen Sie die Suchvariablen zu `.env` hinzu.** Die Compose-Datei setzt `MEILI_HOST` auf die interne Dienstadresse für den `api`-Container, daher legen Sie den Host hier nicht fest. Der mitgelieferte `meilisearch`-Dienst liest `MEILI_MASTER_KEY` aus derselben Datei, sodass LibreChat und Meilisearch ohne weitere Überschreibung denselben Schlüssel verwenden.

```bash filename=".env"
SEARCH=true
MEILI_NO_ANALYTICS=true
MEILI_MASTER_KEY=<your_master_key>
```

</Step>
<Step>

**Starte den Stack.** Compose startet Meilisearch zusammen mit LibreChat.

```bash filename="terminal"
docker compose up -d
```

</Step>
</Steps>

<Callout type="warning" title="Port intern halten">
Container erreichen Meilisearch über das interne Docker-Netzwerk, daher ist es nicht erforderlich, Port `7700` auf dem Host freizugeben. Eine öffentliche Bereitstellung kann Ihre Suchdaten gefährden.
</Callout>

</Tabs.Tab>
<Tabs.Tab value="npm">

Wenn Sie LibreChat aus dem Quellcode ausführen, starten Sie die Meilisearch-Binärdatei als separaten Prozess und verweisen Sie LibreChat darauf.

<Steps>
<Step>

**Laden Sie Meilisearch herunter.** Holen Sie sich die neueste Version für Ihr Betriebssystem von der [Meilisearch releases page](https://github.com/meilisearch/meilisearch/releases), zum Beispiel `meilisearch-linux-amd64.tar.gz` (Linux), `meilisearch-macos-amd64` (macOS) oder `meilisearch-windows-amd64.zip` (Windows). Entpacken Sie diese in ein Verzeichnis Ihrer Wahl. Für Installationen über Paketmanager siehe den [Meilisearch installation guide](https://www.meilisearch.com/docs/learn/getting_started/installation).

</Step>
<Step>

**Machen Sie die Binärdatei ausführbar (Linux/macOS).** Führen Sie dies aus dem Verzeichnis aus, in das Sie sie extrahiert haben:

```bash filename="terminal"
chmod +x meilisearch
```

</Step>
<Step>

**Generieren Sie einen Master-Key.** Meilisearch kann einen für Sie generieren:

```bash filename="terminal"
./meilisearch --generate-master-key
```

Kopieren Sie den generierten Schlüssel; Sie verwenden ihn in den nächsten Schritten wieder.

</Step>
<Step>

**Starten Sie Meilisearch.** Führen Sie es mit Ihrem Master-Key aus. Es lauscht standardmäßig auf Port `7700`.

```bash filename="terminal"
./meilisearch --master-key=<your_master_key>
```

</Step>
<Step>

**Fügen Sie die Suchvariablen zur `.env` hinzu.** Verweisen Sie `MEILI_HOST` auf den Meilisearch-Prozess und verwenden Sie denselben Master-Key, den Sie oben festgelegt haben.

```bash filename=".env"
SEARCH=true
MEILI_NO_ANALYTICS=true
MEILI_HOST=http://localhost:7700
MEILI_MASTER_KEY=<your_master_key>
```

</Step>
<Step>

**LibreChat starten.** Starten oder starten Sie die App neu, damit sie die neue Konfiguration übernimmt.

```bash filename="terminal"
npm run backend
```

</Step>
</Steps>

<Callout type="info" title="Meilisearch am Laufen halten">
Die Konversationssuche funktioniert nur, während Meilisearch ausgeführt wird. Führen Sie es als verwalteten Dienst oder Container aus, damit es über Neustarts hinweg aktiv bleibt.
</Callout>

</Tabs.Tab>

Sobald LibreChat konfiguriert ist, indiziert es Unterhaltungen und Nachrichten in Meilisearch, und die Suchleiste liefert Volltext-Ergebnisse mit Fehlertoleranz.

### Neuindizierung nach v0.8.8-rc2 [#reindexing-after-v088-rc2]

LibreChat v0.8.8-rc2 fügt Unterhaltungen und Nachrichten eine interne indexed-projection-Version hinzu. Bei der ersten Synchronisierung nach dem Upgrade werden bestehende Dokumente ohne die aktuelle Markierung als veraltet behandelt und automatisch neu indiziert, damit neuere durchsuchbare Felder, einschließlich der nachrichtenbasierten Ergebnisse in der Seitenleiste, in Meilisearch vorhanden sind.

Für diese Migration ist kein manuelles Zurücksetzen erforderlich. Bei großen Installationen kann es vorübergehend zu einer erhöhten Auslastung von MongoDB, Meilisearch und dem indexing-worker kommen, während die veralteten Dokumente verarbeitet werden. Bei einer Bereitstellung mit mehreren Knoten sollte die Synchronisierung gemäß der nachstehenden Beschreibung nur auf einem einzigen LibreChat-Knoten aktiviert bleiben.

## Umgebungsvariablen [#environment-variables]

| Variable | Beschreibung |
| --- | --- |
| `SEARCH` | Aktiviert die Konversationssuchfunktion. Auf `true` setzen. |
| `MEILI_HOST` | URL, unter der LibreChat Meilisearch erreicht. In Docker ist dies `http://meilisearch:7700` (durch Compose festgelegt); aus dem Quellcode ist es typischerweise `http://localhost:7700`. |
| `MEILI_MASTER_KEY` | Gemeinsames Geheimnis (Shared Secret), das zur Authentifizierung bei Meilisearch verwendet wird. Muss mit dem Schlüssel übereinstimmen, mit dem Meilisearch gestartet wird. |
| `MEILI_NO_ANALYTICS` | Deaktiviert die anonyme Telemetrie von Meilisearch. Auf `true` setzen. |
| `MEILI_NO_SYNC` | Siehe [Multi-Node-Setups](#disable-sync-in-a-multi-node-setup). |

## Deaktivieren der Synchronisierung in einem Multi-Node-Setup [#disable-sync-in-a-multi-node-setup]

Wenn Sie LibreChat als Node-Cluster oder Multi-Node-Deployment betreiben, lassen Sie die Synchronisierung auf einer Instanz aktiviert und setzen Sie `MEILI_NO_SYNC=true` auf allen anderen Instanzen. Dies verhindert redundante Indexierungsarbeiten über die Nodes hinweg.

```bash filename=".env"
MEILI_NO_SYNC=true
```

## Synchronisierung zurücksetzen [#reset-synchronization]

Wenn Meilisearch-Daten gelöscht oder beschädigt wurden oder LibreChat alles als synchronisiert betrachtet, obwohl dies nicht der Fall ist (zum Beispiel nach einem Upgrade von Meilisearch oder dem Löschen seiner Datendateien), verwenden Sie das Reset-Skript, um eine vollständige erneute Synchronisierung zu erzwingen. Es setzt die Synchronisierungs-Flags in MongoDB zurück, was LibreChat dazu veranlasst, beim nächsten Start oder bei der nächsten Synchronisierungsprüfung alle Unterhaltungen und Nachrichten neu zu indizieren.

<Steps>
<Step>

**Führen Sie das Reset-Skript aus.** Verwenden Sie den Befehl, der zu Ihrem Setup passt.

```bash filename="terminal"
# Local development
npm run reset-meili-sync

# Docker (default setup)
docker compose exec -it api npm run reset-meili-sync

# Docker (deployment setup)
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run reset-meili-sync"
```

</Step>
<Step>

**Starten Sie LibreChat neu.** Die Neusynchronisierung beginnt, sobald die App neu gestartet wurde.

</Step>
</Steps>

Das Skript fragt vor jeder Änderung nach einer Bestätigung (`y/N`). Führe es daher in einem interaktiven Terminal aus. Es setzt das Flag `_meiliIndex` bei allen Nachrichten und Unterhaltungen in MongoDB auf `false` zurück und gibt anschließend aus, wie viele Dokumente zurückgesetzt wurden und wie viele noch synchronisiert werden müssen.

**Wann man es verwendet:**

- Nach dem Löschen der Meilisearch-Datendateien
- Beim Upgrade von Meilisearch auf eine Version, die eine Neuindizierung erfordert
- Wenn LibreChat Unterhaltungen als vollständig synchronisiert anzeigt, aber in Meilisearch Daten fehlen
- Nach dem Wiederherstellen eines MongoDB-Backups ohne übereinstimmende Meilisearch-Daten

**Erweiterte Synchronisierungsoptionen.** Steuern Sie nach dem Zurücksetzen das Synchronisierungsverhalten mit diesen Umgebungsvariablen:

| Variable | Default | Beschreibung |
| --- | --- | --- |
| `MEILI_SYNC_BATCH_SIZE` | `100` | Anzahl der Dokumente, die pro Batch synchronisiert werden. Das Reset-Skript verwendet diesen Wert ebenfalls für die Größe seiner Flag-Reset-Batches, dort standardmäßig `1000`. |
| `MEILI_SYNC_DELAY_MS` | `100` | Verzögerung zwischen den Sync-Batches in Millisekunden. Wird auch zwischen den Batches des Reset-Skripts verwendet. |
| `MEILI_SYNC_THRESHOLD` | `1000` | Mindestanzahl nicht synchronisierter Dokumente, ab der eine Synchronisierung ausgelöst wird. |
