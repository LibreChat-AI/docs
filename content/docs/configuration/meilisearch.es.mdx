Meilisearch es un motor de búsqueda de código abierto que potencia la búsqueda de conversaciones de LibreChat, añadiendo búsqueda de texto completo, tolerancia a errores tipográficos y resultados instantáneos en todas las conversaciones pasadas. Para obtener una descripción general de la función, consulta [Search in LibreChat](/docs/features/search).

<Callout type="info" title="Cómo se conecta">
LibreChat se comunica con Meilisearch a través de HTTP utilizando algunas variables de entorno. La configuración de Docker incluye Meilisearch como un servicio para usted. Una instalación desde el código fuente apunta LibreChat a un proceso de Meilisearch que usted mismo ejecuta.
</Callout>

## Configurar Meilisearch [#configure-meilisearch]

<Tabs items={['Docker', 'npm']}>
<Tabs.Tab value="Docker">

El `docker-compose.yml` predeterminado ya incluye un servicio de `meilisearch`, por lo que solo necesitas habilitar la búsqueda y establecer una clave maestra en tu archivo `.env`.

<Steps>
<Step>

**Genera una master key.** Utiliza cualquier cadena aleatoria lo suficientemente larga (16 bytes o más). Por ejemplo:

```bash filename="terminal"
openssl rand -base64 32
```

</Step>
<Step>

**Agrega las variables de búsqueda a `.env`.** El archivo Compose establece `MEILI_HOST` con la dirección interna del servicio para el contenedor `api`, por lo que aquí no debes configurar el host. El servicio `meilisearch` incluido lee `MEILI_MASTER_KEY` de este mismo archivo, de modo que LibreChat y Meilisearch usan la misma clave sin necesidad de ninguna sobrescritura.

```bash filename=".env"
SEARCH=true
MEILI_NO_ANALYTICS=true
MEILI_MASTER_KEY=<your_master_key>
```

</Step>
<Step>

**Inicia el stack.** Compose inicia Meilisearch junto con LibreChat.

```bash filename="terminal"
docker compose up -d
```

</Step>
</Steps>

<Callout type="warning" title="Mantener el puerto interno">
Los contenedores acceden a Meilisearch a través de la red interna de Docker, por lo que no es necesario publicar el puerto `7700` en el host. Exponerlo públicamente puede dejar sus datos de búsqueda vulnerables.
</Callout>

</Tabs.Tab>
<Tabs.Tab value="npm">

Cuando ejecutes LibreChat desde el código fuente, ejecuta el binario de Meilisearch como un proceso independiente y apunta LibreChat hacia él.

<Steps>
<Step>

**Descarga Meilisearch.** Obtén la versión más reciente para tu sistema operativo desde la [página de lanzamientos de Meilisearch](https://github.com/meilisearch/meilisearch/releases), por ejemplo `meilisearch-linux-amd64.tar.gz` (Linux), `meilisearch-macos-amd64` (macOS) o `meilisearch-windows-amd64.zip` (Windows). Extráelo en el directorio de tu elección. Para instalaciones mediante gestores de paquetes, consulta la [guía de instalación de Meilisearch](https://www.meilisearch.com/docs/learn/getting_started/installation).

</Step>
<Step>

**Haz que el binario sea ejecutable (Linux/macOS).** Desde el directorio donde lo extrajiste:

```bash filename="terminal"
chmod +x meilisearch
```

</Step>
<Step>

**Genera una master key.** Meilisearch puede generar una por ti:

```bash filename="terminal"
./meilisearch --generate-master-key
```

Copia la clave generada; la reutilizarás en los siguientes pasos.

</Step>
<Step>

**Inicia Meilisearch.** Ejecútalo con tu master key. Escucha en el puerto `7700` de forma predeterminada.

```bash filename="terminal"
./meilisearch --master-key=<your_master_key>
```

</Step>
<Step>

**Agregue las variables de búsqueda a `.env`.** Apunte `MEILI_HOST` al proceso de Meilisearch y utilice la misma clave maestra que configuró anteriormente.

```bash filename=".env"
SEARCH=true
MEILI_NO_ANALYTICS=true
MEILI_HOST=http://localhost:7700
MEILI_MASTER_KEY=<your_master_key>
```

</Step>
<Step>

**Inicia LibreChat.** Inicia o reinicia la aplicación para que detecte la nueva configuración.

```bash filename="terminal"
npm run backend
```

</Step>
</Steps>

<Callout type="info" title="Mantener Meilisearch en ejecución">
La búsqueda de conversaciones solo funciona mientras Meilisearch está en ejecución. Ejecútelo como un servicio administrado o contenedor para que permanezca activo tras los reinicios.
</Callout>

</Tabs.Tab>
</Tabs>

Una vez configurado, LibreChat indexa las conversaciones y los mensajes en Meilisearch, y la barra de búsqueda devuelve resultados de texto completo con tolerancia a errores tipográficos.

### Reindexación después de v0.8.8-rc2 [#reindexing-after-v088-rc2]

LibreChat v0.8.8-rc2 añade una versión de proyección indexada interna a las conversaciones y mensajes. En la primera sincronización tras la actualización, los documentos existentes que no tengan el marcador actual se tratarán como obsoletos y se volverán a indexar automáticamente para que los campos de búsqueda más recientes, incluidos los resultados de la barra lateral respaldados por mensajes, estén presentes en Meilisearch.

No se requiere un restablecimiento manual para esta migración. Las instalaciones grandes pueden experimentar una carga temporalmente elevada en MongoDB, Meilisearch y el indexing-worker mientras se procesan los documentos obsoletos. En una implementación de múltiples nodos, mantenga la sincronización habilitada en un solo nodo de LibreChat como se describe a continuación.

## Variables de entorno [#environment-variables]

| Variable | Description |
| --- | --- |
| `SEARCH` | Habilita la función de búsqueda de conversaciones. Establézcalo en `true`. |
| `MEILI_HOST` | URL donde LibreChat accede a Meilisearch. En Docker es `http://meilisearch:7700` (configurado por Compose); desde el código fuente suele ser `http://localhost:7700`. |
| `MEILI_MASTER_KEY` | Secreto compartido utilizado para autenticarse con Meilisearch. Debe coincidir con la clave con la que se inicia Meilisearch. |
| `MEILI_NO_ANALYTICS` | Deshabilita la telemetría anónima de Meilisearch. Establézcalo en `true`. |
| `MEILI_NO_SYNC` | Ver [configuraciones de múltiples nodos](#disable-sync-in-a-multi-node-setup). |

## Deshabilitar la sincronización en una configuración de múltiples nodos [#disable-sync-in-a-multi-node-setup]

Si ejecutas LibreChat como un clúster de nodos o una implementación de múltiples nodos, deja la sincronización habilitada en una instancia y establece `MEILI_NO_SYNC=true` en todas las demás instancias. Esto evita el trabajo de indexación redundante entre nodos.

```bash filename=".env"
MEILI_NO_SYNC=true
```

## Restablecer sincronización [#reset-synchronization]

Si los datos de Meilisearch se eliminan o se corrompen, o si LibreChat trata todo como sincronizado cuando no lo está (por ejemplo, después de actualizar Meilisearch o eliminar sus archivos de datos), utilice el script de restablecimiento para forzar una resincronización completa. Esto restablece las banderas de sincronización en MongoDB, lo que hace que LibreChat vuelva a indexar todas las conversaciones y mensajes en el siguiente inicio o verificación de sincronización.

<Steps>
<Step>

**Ejecuta el script de reinicio.** Usa el comando que corresponda a tu configuración.

```bash filename="terminal"
# Local development
npm run reset-meili-sync

# Docker (default setup)
docker compose exec -it api npm run reset-meili-sync

# Docker (deployment setup)
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run reset-meili-sync"
```

</Step>
<Step>

**Reinicia LibreChat.** La resincronización comienza una vez que la aplicación se reinicia.

</Step>
</Steps>

El script solicita confirmación (`y/N`) antes de realizar cualquier cambio, por lo que debes ejecutarlo en una terminal interactiva. Restablece el indicador `_meiliIndex` a `false` para todos los mensajes y conversaciones en MongoDB y, a continuación, informa cuántos documentos se restablecieron y cuántos quedan por sincronizar.

**Cuándo usarlo:**

- Después de eliminar los archivos de datos de Meilisearch
- Al actualizar Meilisearch a una versión que requiere reindexación
- Cuando LibreChat muestra las conversaciones como totalmente sincronizadas pero a Meilisearch le faltan datos
- Después de restaurar una copia de seguridad de MongoDB sin los datos correspondientes de Meilisearch

**Opciones de sincronización avanzadas.** Después de restablecer, controle el comportamiento de sincronización con estas variables de entorno:

| Variable | Default | Description |
| --- | --- | --- |
| `MEILI_SYNC_BATCH_SIZE` | `100` | Número de documentos sincronizados por lote. El script de reinicio también usa este valor para el tamaño de sus lotes de reinicio de indicadores, con un valor predeterminado de `1000` en ese caso. |
| `MEILI_SYNC_DELAY_MS` | `100` | Retardo entre los lotes de sincronización, en milisegundos. También se usa entre los lotes del script de reinicio. |
| `MEILI_SYNC_THRESHOLD` | `1000` | Número mínimo de documentos no sincronizados necesario para que se active una sincronización. |
