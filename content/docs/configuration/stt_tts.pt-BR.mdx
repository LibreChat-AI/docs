## Introdução à Fala [#speech-introduction]

A Configuração de Fala inclui definições tanto para Speech-to-Text (STT) quanto para Text-to-Speech (TTS) sob uma seção `speech:` unificada. Adicionalmente, há um novo menu `speechTab` para configurações específicas do usuário.

> **Veja também:** Para o esquema detalhado de configuração YAML e todas as opções disponíveis, consulte a documentação [Speech Object Structure](/docs/configuration/librechat_yaml/object_structure/speech).

### Variáveis de Ambiente [#environment-variables]

Ao usar serviços de STT/TTS baseados em nuvem, você precisará definir as chaves de API no seu arquivo `.env`:

```bash filename=".env"
# Speech-to-Text API key (e.g., OpenAI Whisper)
STT_API_KEY=your-stt-api-key

# Text-to-Speech API key (e.g., OpenAI TTS, ElevenLabs)
TTS_API_KEY=your-tts-api-key
```

Essas chaves são então referenciadas em sua configuração `librechat.yaml` usando `${STT_API_KEY}` e `${TTS_API_KEY}`.

### Um provedor por serviço [#one-provider-per-service]

Cada um de `speech.stt` e `speech.tts` aceita no máximo um bloco de provedor, e qualquer uma das seções pode ser omitida para manter o mecanismo do navegador para esse serviço. Se uma seção tiver mais de um provedor, as requisições falham com o erro "Multiple providers are set. Please set only one provider."

### Motores auto-hospedados precisam de uma entrada allowedAddresses [#self-hosted-engines-need-an-allowedaddresses-entry]

Tanto `speech.stt` quanto `speech.tts` aceitam uma lista `allowedAddresses`. As solicitações de fala de saída são validadas em relação ao seu IP resolvido e impedidas de alcançar espaços de endereço privados, de loopback e link-local, portanto, um mecanismo auto-hospedado em `localhost`, um endereço LAN ou um nome de serviço Docker fica inacessível até que você o liste:

```yaml filename="librechat.yaml"
speech:
  tts:
    allowedAddresses:
      - 'host.docker.internal:8080'
    localai:
      url: 'http://host.docker.internal:8080/tts'
      # ...
```

As entradas são pares `host:port` simples: sem esquema ou caminho, porta obrigatória, IPv6 entre colchetes como `[::1]:8080`, e literais de IP devem ser privados. Endpoints de nuvem pública como OpenAI, Azure e ElevenLabs não precisam de entrada. A proteção funciona no IP resolvido, não no hostname, portanto, um endpoint de nuvem acessado via Private Link, DNS privado ou VPN é resolvido em um espaço de endereço privado e precisa ter seu `host:port` exato listado como qualquer outro destino privado. O mesmo campo e regras se aplicam em `speech.stt`. Veja [SSRF protection](/docs/configuration/librechat_yaml/object_structure/web_search#ssrf-protection-and-private-providers) para o formato completo da entrada.

## Aba Speech (opcional) [#speech-tab-optional]

O menu `speechTab` oferece opções personalizáveis para conversação e modos avançados, bem como configurações detalhadas para STT e TTS. Isso definirá as configurações padrão para os usuários.

Use `browser` para a fala do navegador integrada ou `external` para um provedor do lado do servidor configurado abaixo. Padrões específicos de provedores mais antigos permanecem aceitos para compatibilidade e são normalizados para `external`; se o serviço externo correspondente estiver indisponível, o LibreChat retornará para `browser`.

exemplo:

```yaml
speech:
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText:
      engineSTT: "external"
      languageSTT: "English (US)"
      autoTranscribeAudio: true
      decibelValue: -45
      autoSendText: 0
    textToSpeech:
      engineTTS: "external"
      voice: "alloy"
      languageTTS: "en"
      automaticPlayback: true
      playbackRate: 1.0
      cacheTTS: true
```

`speechTab` define os valores iniciais que os usuários veem; cada um permanece alterável por usuário na aba de configurações de fala.

## STT (Speech-to-Text) [#stt-speech-to-text]

O recurso de Conversão de Fala em Texto (STT) converte palavras faladas em texto escrito. Para ativar o STT, clique no botão STT (próximo ao botão de enviar) ou use a combinação de teclas ++Shift+Alt+L++ para iniciar a transcrição.

### Serviços de STT Disponíveis [#available-stt-services]

- **STT Local**
  - Baseado no navegador
  - Whisper (testado no LocalAI)
- **Cloud STT**
  - OpenAI Whisper
  - Azure Whisper
  - Outros serviços de STT compatíveis com OpenAI

### Configurando STT Local [#configuring-local-stt]

- #### Browser-based
  Nenhuma configuração é necessária. Certifique-se de que a opção "Speech To Text" na aba de configurações de voz esteja ativada e que "Browser" esteja selecionado no menu suspenso de engine.

- #### Whisper Local [#whisper-local]
  Requer uma instância local do Whisper.

```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```

O campo `apiKey` é obrigatório em todo bloco STT compatível com OpenAI, inclusive nos locais. Se o seu servidor não validar chaves, use qualquer valor de espaço reservado.

### Configurando o Cloud STT [#configuring-cloud-stt]

- #### OpenAI Whisper [#openai-whisper]

```yaml
speech:
  stt:
    openai:
      apiKey: '${STT_API_KEY}'
      model: 'whisper-1'
```

- #### Azure Whisper [#azure-whisper]

```yaml
speech:
  stt:
    azureOpenAI:
      instanceName: 'instanceName'
      apiKey: '${STT_API_KEY}'
      deploymentName: 'deploymentName'
      apiVersion: 'apiVersion'
```

<Callout type="info" title="Suporte a Domínio de Endpoint Azure">
O campo `instanceName` suporta ambos os formatos de domínio do Azure OpenAI:
- **Novo formato**: `.cognitiveservices.azure.com` (por exemplo, `my-instance.cognitiveservices.azure.com`)
- **Formato legado**: `.openai.azure.com` (por exemplo, `my-instance.openai.azure.com`)

Você pode especificar o domínio completo ou apenas o nome da instância. Se você fornecer um domínio completo incluindo `.azure.com`, ele será usado como está. Caso contrário, o formato legado `.openai.azure.com` será aplicado para compatibilidade retroativa.
</Callout>

- #### Compatível com OpenAI [#openai-compatible]

Consulte a seção OpenAI Whisper, ajustando o `url` e o `model` conforme necessário. O campo `apiKey` continua sendo obrigatório.

exemplo
  
```yaml
speech:
  stt:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/transcriptions'
      apiKey: '${STT_API_KEY}'
      model: 'whisper'
```


## TTS (Text-to-Speech) [#tts-text-to-speech]

O recurso de Text-to-Speech (TTS) converte texto escrito em palavras faladas. Vários serviços de TTS estão disponíveis:

### Serviços de TTS Disponíveis [#available-tts-services]

- **TTS Local**
  - Baseado no navegador
  - Piper (testado no LocalAI)
  - Coqui (testado no LocalAI)
- **Cloud TTS**
  - OpenAI TTS
  - Azure OpenAI
  - ElevenLabs
  - Outros serviços de TTS compatíveis com OpenAI/ElevenLabs

O texto mais longo que `speech.tts.maxInputChars` (padrão de 20000 caracteres) é truncado antes de ser lido em voz alta. Consulte a [Estrutura do Objeto Speech](/docs/configuration/librechat_yaml/object_structure/speech) para mais detalhes.

### Configurando TTS Local [#configuring-local-tts]

- #### Browser-based [#browser-based-1]

Nenhuma configuração é necessária. Certifique-se de que a opção "Text To Speech" na aba de configurações de fala esteja ativada e que "Browser" esteja selecionado no menu suspenso de mecanismo.

- #### Piper [#piper]

Requer uma instância local do Piper.

```yaml
speech:
  tts:
    localai:
      url: "http://host.docker.internal:8080/tts"
      apiKey: "EMPTY"
      voices: [
        "en-us-amy-low.onnx",
        "en-us-danny-low.onnx",
        "en-us-libritts-high.onnx",
        "en-us-ryan-high.onnx",
      ]
      backend: "piper"
```

- #### Coqui [#coqui]

Requer uma instância local do Coqui.

```yaml
speech:
  tts:
    localai:
      url: 'http://localhost:8080/v1/audio/synthesize'
      voices: ['tts_models/en/ljspeech/glow-tts', 'tts_models/en/ljspeech/tacotron2', 'tts_models/en/ljspeech/waveglow']
      backend: 'coqui'
```

### Configurando Cloud TTS [#configuring-cloud-tts]

- #### OpenAI TTS [#openai-tts]

```yaml
speech:
  tts:
    openai:
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

- #### Azure OpenAI [#azure-openai]

```yaml
speech:
  tts:
    azureOpenAI:
      instanceName: ''
      apiKey: '${TTS_API_KEY}'
      deploymentName: ''
      apiVersion: ''
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

<Callout type="info" title="Suporte a Domínio de Endpoint Azure">
O campo `instanceName` suporta ambos os formatos de domínio do Azure OpenAI:
- **Novo formato**: `.cognitiveservices.azure.com` (por exemplo, `my-instance.cognitiveservices.azure.com`)
- **Formato legado**: `.openai.azure.com` (por exemplo, `my-instance.openai.azure.com`)

Você pode especificar o domínio completo ou apenas o nome da instância. Se você fornecer um domínio completo incluindo `.azure.com`, ele será usado como está. Caso contrário, o formato legado `.openai.azure.com` será aplicado para compatibilidade retroativa.
</Callout>

- #### ElevenLabs [#elevenlabs]

```yaml
speech:
  tts:
    elevenlabs:
      apiKey: '${TTS_API_KEY}'
      model: 'eleven_multilingual_v2'
      voices: ['202898wioas09d2', 'addwqr324tesfsf', '3asdasr3qrq44w', 'adsadsa']
```

Parâmetros adicionais específicos do ElevenLabs podem ser adicionados da seguinte forma:

```yaml
      voice_settings:
        similarity_boost: 0.75 # number
        stability: 0.5 # number
        style: 0 # number
        use_speaker_boost: true # boolean
      pronunciation_dictionary_locators: [''] # list of strings (array)
```

- #### Compatível com OpenAI [#openai-compatible-1]

Consulte a seção OpenAI TTS, ajustando a variável `url` conforme necessário

exemplo:

```yaml
speech:
  tts:
    openai:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
      apiKey: '${TTS_API_KEY}'
      model: 'tts-1'
      voices: ['alloy', 'echo', 'fable', 'onyx', 'nova', 'shimmer']
```

exemplo:

```yaml

    elevenlabs:
      url: 'http://host.docker.internal:8080/v1/audio/synthesize'
```
