Exiba mensagens importantes para todos os seus usuários no topo do aplicativo. Perfeito para anúncios, avisos de manutenção ou atualizações.

<Callout type="info" title="Visão Geral Rápida">
  - Apenas **um banner** pode estar ativo por vez
  - Agende banners para aparecer e desaparecer automaticamente
  - Escolha se os usuários podem ou não dispensar o banner
  - Exibir banners para todos ou apenas para usuários logados
</Callout>

---

## Criando um Banner [#creating-a-banner]

Execute este comando para criar ou atualizar um banner:

```bash
npm run update-banner
```

Com o Docker, execute o script dentro do contêiner `api`:

```bash
docker compose exec api npm run update-banner
```

Você será guiado por alguns prompts simples:

```ansi
--------------------------
Update the banner!
--------------------------
Display From (Format: yyyy-mm-ddTHH:MM:SSZ, Default: now):
> 2025-12-02T09:00:00Z

Display To (Format: yyyy-mm-ddTHH:MM:SSZ, Default: not specified):
> 2025-12-31T23:59:59Z

Enter your message (Enter a single dot "." on a new line to finish):
> 🎉 Welcome to LibreChat! Check out our new features.
> .

Is public (y/N):
> n

Is persistable (cannot be dismissed) (y/N):
> n
```

<Callout type="tip" title="O que significam estas opções?">
  - **Exibir de/até**: Quando o banner deve aparecer e desaparecer. Pressione Enter no prompt para usar "now" e "forever"
  - **Is public**: Mostrar para visitantes que não estão logados (como na página de login)
  - **É persistente**: Se sim, os usuários não podem dispensar o banner (use-o para avisos importantes)
</Callout>

<Callout type="warning" title="Executar isso novamente substitui o banner existente">

Existe apenas um banner por vez. O `update-banner` procura por um banner existente e o sobrescreve no local, criando um apenas quando nenhum existe, portanto, você não pode enfileirar um segundo banner para uma data posterior e não pode ter duas janelas agendadas sobrepostas. Executar o comando novamente descarta a mensagem e o agendamento do banner anterior.

Para alterar um banner, execute `update-banner` novamente. Para remover um antes do seu horário de `Display To`, use `delete-banner` abaixo.

</Callout>

## Excluindo um Banner [#deleting-a-banner]

```bash
npm run delete-banner
```

Com o Docker, execute `docker compose exec api npm run delete-banner`.

Você verá o banner atual e será solicitado a confirmar antes de excluir.

<Callout type="warning" title="Apenas um banner ativo pode ser excluído">

`delete-banner` só encontra um banner que está atualmente ativo: o horário de `Display From` já deve ter passado, e o horário de `Display To` deve estar no futuro ou não estar definido. Um banner agendado para uma data posterior, ou cujo `Display To` já tenha passado, é reportado como "No banner found to delete" e permanece no banco de dados. Para substituir esse banner, execute `update-banner` novamente.

</Callout>

Remover um banner desta forma é também como você o retira antes do tempo: não existe uma flag de "desativar". Caso contrário, um banner desaparece por conta própria assim que o `Display To` expira, e um banner salvo sem `Display To` permanece ativo até que você o exclua.

## Exemplo de Banners [#example-banners]

<Tabs items={['Mensagem de Boas-vindas', 'Aviso de Manutenção', 'Alerta de Segurança']}>
  <Tabs.Tab>
    Uma mensagem de boas-vindas simples que os usuários podem dispensar:

    ```bash
    npm run update-banner "" "" "👋 Welcome to LibreChat!" "false" "false"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Um aviso de manutenção agendada que não pode ser dispensado:

    ```bash
    npm run update-banner "2025-12-20T00:00:00Z" "2025-12-21T06:00:00Z" "⚠️ Scheduled maintenance on Dec 20th, 2-6 AM UTC" "true" "true"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Um aviso de segurança urgente visível para todos:

    ```bash
    npm run update-banner "" "" "🔒 Please update your password by January 1st" "true" "true"
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="info" title="Argumentos de data vazios ainda exibem prompt">

Uma string vazia (`""`) para uma data é tratada como ausente, portanto o script ainda solicita `Display From` e `Display To` de forma interativa. Pressione Enter em cada prompt para aceitar o padrão, ou passe datas ISO (`yyyy-mm-ddTHH:MM:SSZ`) como os dois primeiros argumentos para executar o comando sem prompts. O argumento de mensagem também é obrigatório para pular o prompt de mensagem, e os argumentos `isPublic` e `persistable` devem ser informados como `true` ou `false` para pular os respectivos prompts.

</Callout>

## Formato de Data [#date-format]

Use este formato para datas: `yyyy-mm-ddTHH:MM:SSZ`

**Exemplos:**
- `2025-12-25T09:00:00Z` → 25 de dezembro de 2025 às 9:00 (UTC)
- `2025-01-01T00:00:00Z` → 1 de janeiro de 2025 à meia-noite (UTC)

Quando solicitado, pressione Enter sem digitar uma data para usar o horário atual em `Display From`, ou nenhuma data final em `Display To`.
