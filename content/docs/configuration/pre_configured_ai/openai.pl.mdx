Aby uzyskać swój klucz API OpenAI, musisz:

- Przejdź do **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Utwórz konto lub zaloguj się za pomocą istniejącego
- Dodaj metodę płatności do swojego konta
- Przejdź do https://platform.openai.com/api-keys, aby uzyskać klucz.
- Będziesz musiał ustawić poniższą zmienną środowiskową na swój klucz lub możesz ustawić ją na `user_provided`, aby użytkownicy mogli podać własny.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Gdzie użytkownicy wprowadzają własny klucz">

W przypadku `user_provided` nie podajesz żadnego klucza: każdy użytkownik wprowadza własny z poziomu interfejsu czatu. Otwórz menu endpoint i obok **OpenAI** znajdziesz ikonę koła zębatego oznaczoną jako **Set API Key**. Kliknięcie jej otwiera okno dialogowe z polem na klucz oraz listą rozwijaną określającą czas jego przechowywania: 30 minut, 2 godziny, 12 godzin (wartość domyślna), 1 dzień, 7 dni, 30 dni lub nigdy nie wygasa.

Klucz jest szyfrowany i przechowywany po stronie serwera w powiązaniu z kontem danego użytkownika, dzięki czemu wprowadza się go raz, a nie dla każdej konwersji z osobna, i nigdy nie jest on udostępniany innym użytkownikom. To samo okno dialogowe zawiera akcję **Revoke** (Unieważnij), a także **Revoke All** (Unieważnij wszystko), aby usunąć każdy klucz zapisany przez tego użytkownika.

Jeśli menu endpoint jest ukryte, na przykład dlatego, że Model Specs wyłącza `modelSelect`, to samo okno dialogowe jest dostępne w **Ustawieniach** w sekcji **Kontrola danych**, w sekcji **Klucze API**.

Dopóki użytkownik nie ustawi klucza, endpoint jest dla niego widoczny, ale bezużyteczny.

</Callout>

- Możesz określić, które modele mają być dostępne, używając `OPENAI_MODELS`
  - Gdy `OPENAI_API_KEY` jest ustawione na `user_provided` → dostępne będą tylko modele umieszczone na tej liście
    - ⚠️Nowe modele nie pojawią się automatycznie; musisz najpierw dodać je do tej listy
  - Gdy `OPENAI_API_KEY` jest ustawiony na rzeczywistą wartość klucza API → dopóki `OPENAI_MODELS` pozostaje zakomentowane, zostanie wykonane wywołanie API w celu sprawdzenia, jakie modele są dostępne, co powinno obejmować wszystkie nowe modele.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Uwagi:**

- GPT-6.1 Sol (`gpt-6.1-sol`) dołącza do kanonicznych katalogów OpenAI i Agents, a nie Assistants. Do momentu dodania jawnych wpisów, dziedziczy on limity kontekstu/wyjściowe oraz cennik GPT-6 Sol; są to wartości zastępcze dla rodziny modeli, a nie niezależnie potwierdzony cennik GPT-6.1.
- Wydania punktowe GPT bez pasującego wpisu dla konkretnego wydania dziedziczą limity kontekstu/wyjściowe, cennik oraz ustawienia rozumowania swojej rozpoznanej rodziny. Jawne wpisy mają pierwszeństwo. Na przykład `gpt-6.1-sol` nie korzysta już z ogólnego budżetu kontekstu 32K. Wydania punktowe bez daty w natywnym OpenAI mogą również dziedziczyć politykę odpowiedzi (Responses policy) danej rodziny; migawki z datą zachowują dziedziczenie polityki wieloznacznej (wildcard-policy), Azure pozostaje specyficzny dla wdrożenia, a niestandardowe endpoint nie są przełączane automatycznie.

- Wewnętrzne ustawienia domyślne OpenAI obejmują `gpt-6-astra` dla kanonicznych endpointów OpenAI oraz Agents. LibreChat kieruje każde żądanie Astra przez Responses API, ponieważ jego wywołania narzędzi (tool calls) dotyczą wyłącznie Responses, usuwa nieobsługiwane parametry próbkowania i stosuje okno kontekstowe o wielkości 1 050 000 tokenów z maksymalnym wyjściem wynoszącym 128 000 tokenów. Astra jest celowo wykluczona z domyślnych katalogów Assistants, Azure Assistants oraz Azure OpenAI.
- Wewnętrzne ustawienia domyślne OpenAI obejmują `gpt-5.6`, `gpt-5.6-terra` oraz `gpt-5.6-luna`, a po nich następuje istniejący katalog GPT-5. `gpt-5.6` to alias warstwy Sol; LibreChat przypisuje wszystkim trzem warstwom GPT-5.6 okno kontekstowe o wielkości 1 050 000 tokenów oraz maksymalną liczbę 128 000 tokenów wyjściowych. Przestarzałe ustawienia domyślne nie są już uwzględniane, chyba że dodasz je jawnie za pomocą `OPENAI_MODELS`.
- GPT-5.6 obsługuje wartości `standard` i `pro` dla parametru `reasoning_mode` dostępnego wyłącznie w Responses API, a także wartości `auto`, `current_turn` i `all_turns` dla parametru `reasoning_context`. Można je skonfigurować w [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode).
- Dla modelu GPT-5.6 z parametrem `reasoning_effort` innym niż `none`, LibreChat domyślnie kieruje kanoniczny endpoint OpenAI do Responses API, aby narzędzia funkcyjne pozostały kompatybilne. Jawne ustawienie `useResponsesApi: false` zachowuje Chat Completions. Azure OpenAI, OpenRouter oraz niestandardowe lub oparte na reverse-proxy adresy URL nie są przełączane automatycznie.
- Wybór modelu wizyjnego dla wiadomości z załącznikami nie jest konieczny, ponieważ zostanie on przełączony automatycznie w tle. Jeśli nie wybrano modelu wizyjnego bezpośrednio, zostanie on użyty tylko do żądania wizyjnego, a po pomyślnym zakończeniu żądania nadal powinieneś widzieć wybrany wcześniej model niewizyjny.
- Modele OpenAI Vision pozwalają na przesyłanie wiadomości bez załączników
- Endpoint OpenAI obsługuje wszystkie [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) za pośrednictwem pliku konfiguracyjnego `librechat.yaml`, w tym `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` oraz `titleEndpoint`
