Para obtener tu API key de OpenAI, necesitas:

- Ve a **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Crea una cuenta o inicia sesión con la que ya tienes
- Agregue un método de pago a su cuenta
- Ve a https://platform.openai.com/api-keys para obtener una clave.
- Deberá configurar la siguiente variable de entorno con su clave, o puede establecerla en `user_provided` para que los usuarios proporcionen la suya propia.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Donde los usuarios ingresan su propia clave">

Con `user_provided`, no proporcionas ninguna clave: cada usuario ingresa la suya desde la interfaz de chat. Abre el menú de endpoint y, junto a **OpenAI**, hay un icono de engranaje etiquetado como **Set API Key**. Al hacer clic en él, se abre un cuadro de diálogo con un campo para la clave y un menú desplegable para determinar cuánto tiempo debe conservarse: 30 minutos, 2 horas, 12 horas (el valor predeterminado), 1 día, 7 días, 30 días o nunca expirar.

La clave se cifra y se almacena en el lado del servidor vinculada a la cuenta de ese usuario, por lo que se introduce una sola vez en lugar de por cada conversación, y nunca se comparte con otros usuarios. El mismo diálogo cuenta con una acción de **Revoke**, además de **Revoke All** para borrar todas las claves que ese usuario haya almacenado.

Si el menú de endpoint está oculto, por ejemplo porque un Model Specs deshabilita `modelSelect`, se puede acceder al mismo diálogo desde **Settings** en **Data controls**, en la sección **API keys**.

Hasta que un usuario configure una clave, el endpoint es visible pero inutilizable para él.

</Callout>

- Puedes determinar qué modelos te gustaría tener disponibles con `OPENAI_MODELS`
  - Cuando `OPENAI_API_KEY` se establece en `user_provided` → solo estarán disponibles los modelos incluidos en esta lista
    - ⚠️Los nuevos modelos no aparecerán automáticamente; primero deberás agregarlos a esta lista
  - Cuando `OPENAI_API_KEY` se establece con el valor real de la clave API → siempre que `OPENAI_MODELS` se deje comentado, realizará una llamada a la API para averiguar qué modelos están disponibles, lo cual debería incluir cualquiera nuevo.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Notas:**

- GPT-6.1 Sol (`gpt-6.1-sol`) se une a los catálogos predeterminados canónicos de OpenAI y Agents, no a Assistants. Hasta que se añadan entradas explícitas, hereda los límites de contexto/salida y los precios de GPT-6 Sol; estos son valores de respaldo de la familia, no precios de GPT-6.1 confirmados de forma independiente.
- Las versiones puntuales de GPT que no tienen una entrada correspondiente por versión heredan los límites de contexto/salida, los precios y la configuración de razonamiento de su familia reconocida. Las entradas explícitas tienen prioridad. Por ejemplo, `gpt-6.1-sol` ya no recurre al presupuesto de contexto genérico de 32K. Las versiones puntuales sin fecha en OpenAI nativo también pueden heredar la política de respuestas de la familia; las instantáneas con fecha conservan la herencia de política comodín, Azure permanece específico de la implementación y los endpoints personalizados no se cambian automáticamente.

- Los valores predeterminados internos de OpenAI incluyen `gpt-6-astra` para los endpoints canónicos de OpenAI y Agents. LibreChat enruta cada solicitud de Astra a través de la API de Responses porque sus llamadas a herramientas son solo para Responses, elimina los parámetros de muestreo no compatibles y aplica una ventana de contexto de 1,050,000 tokens con un máximo de 128,000 tokens de salida. Astra está excluido intencionalmente de los catálogos predeterminados de Assistants, Azure Assistants y Azure OpenAI.
- Los valores predeterminados internos de OpenAI incluyen `gpt-5.6`, `gpt-5.6-terra` y `gpt-5.6-luna`, seguidos por el catálogo existente de GPT-5. `gpt-5.6` es el alias del nivel Sol; LibreChat asigna a los tres niveles de GPT-5.6 una ventana de contexto de 1,050,000 tokens y una salida máxima de 128,000 tokens. Los valores predeterminados heredados y obsoletos ya no se incluyen a menos que los añada explícitamente con `OPENAI_MODELS`.
- GPT-5.6 admite los valores `standard` y `pro` exclusivos de la API de respuestas para `reasoning_mode`, además de los valores `auto`, `current_turn` y `all_turns` para `reasoning_context`. Estos pueden configurarse en [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode).
- Para un modelo GPT-5.6 con un `reasoning_effort` distinto de `none`, LibreChat utiliza de forma predeterminada el endpoint canónico de OpenAI hacia la Responses API para que las herramientas de función sigan siendo compatibles. Un `useResponsesApi: false` explícito mantiene Chat Completions. Azure OpenAI, OpenRouter y las URLs base personalizadas o de proxy inverso no se cambian automáticamente.
- No es necesario seleccionar un modelo de visión para los mensajes con archivos adjuntos, ya que se cambiará automáticamente en segundo plano. Si no seleccionaste explícitamente un modelo de visión, este solo se utilizará para la solicitud de visión y deberías seguir viendo el modelo sin visión que habías seleccionado una vez que la solicitud se complete con éxito.
- Los modelos Vision de OpenAI permiten mensajes sin archivos adjuntos
- El endpoint de OpenAI admite todas las [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) a través del archivo de configuración `librechat.yaml`, incluyendo `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` y `titleEndpoint`.
