Para obter sua chave de API da OpenAI, você precisa:

- Vá para **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Crie uma conta ou faça login com a sua já existente
- Adicione uma forma de pagamento à sua conta
- Vá para https://platform.openai.com/api-keys para obter uma chave.
- Você precisará definir a seguinte variável de ambiente com sua chave, ou você pode defini-la como `user_provided` para que os usuários forneçam as suas próprias.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Onde os usuários inserem sua própria chave">

Com `user_provided`, você não fornece nenhuma chave: cada usuário insere a sua própria a partir da interface de chat. Abra o menu de endpoint e, ao lado de **OpenAI**, há um ícone de engrenagem rotulado como **Set API Key**. Clicar nele abre uma caixa de diálogo com um campo para a chave e um menu suspenso para definir por quanto tempo ela deve ser mantida: 30 minutos, 2 horas, 12 horas (o padrão), 1 dia, 7 dias, 30 dias ou nunca expirar.

A chave é criptografada e armazenada no lado do servidor vinculada à conta do usuário, portanto, ela é inserida uma única vez em vez de por conversa, e nunca é compartilhada com outros usuários. A mesma caixa de diálogo possui uma ação **Revogar**, além de **Revogar Tudo** para limpar todas as chaves que aquele usuário armazenou.

Se o menu de endpoint estiver oculto, por exemplo, porque um Model Specs desativa o `modelSelect`, a mesma caixa de diálogo pode ser acessada em **Configurações** (Settings) em **Controles de dados** (Data controls), na seção **Chaves de API** (API keys).

Até que um usuário defina uma chave, o endpoint fica visível, mas inutilizável para ele.

</Callout>

- Você pode determinar quais modelos deseja disponibilizar com `OPENAI_MODELS`
  - Quando `OPENAI_API_KEY` estiver definido como `user_provided` → apenas os modelos colocados nesta lista estarão disponíveis
    - ⚠️Novos modelos não aparecerão automaticamente; você precisará adicioná-los a esta lista primeiro
  - Quando `OPENAI_API_KEY` é definida com o valor real da chave de API → desde que `OPENAI_MODELS` seja deixada comentada, ela fará uma chamada de API para descobrir quais modelos estão disponíveis, o que deve incluir quaisquer modelos novos.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Notas:**

- O GPT-6.1 Sol (`gpt-6.1-sol`) junta-se aos catálogos padrão canônicos da OpenAI e Agents, não aos Assistants. Até que entradas explícitas sejam adicionadas, ele herda os limites de contexto/saída e os preços do GPT-6 Sol; estes são fallbacks de família, não preços do GPT-6.1 confirmados de forma independente.
- Versões pontuais do GPT sem uma entrada correspondente por versão herdam os limites de contexto/saída, preços e configurações de raciocínio da sua família reconhecida. Entradas explícitas têm precedência. Por exemplo, `gpt-6.1-sol` não recorre mais ao orçamento de contexto genérico de 32K. Versões pontuais sem data no OpenAI nativo também podem herdar a política de Respostas da família; snapshots com data mantêm a herança de política curinga, o Azure permanece específico da implantação e endpoints personalizados não são alterados automaticamente.

- Os padrões internos da OpenAI incluem `gpt-6-astra` para os endpoints canônicos da OpenAI e Agents. O LibreChat roteia todas as solicitações do Astra através da API de Responses, pois suas chamadas de ferramenta são apenas para Responses, remove parâmetros de amostragem não suportados e aplica uma janela de contexto de 1.050.000 tokens com um máximo de 128.000 tokens de saída. O Astra é intencionalmente excluído dos catálogos padrão de Assistants, Azure Assistants e Azure OpenAI.
- Os padrões internos da OpenAI incluem `gpt-5.6`, `gpt-5.6-terra` e `gpt-5.6-luna`, seguidos pelo catálogo existente do GPT-5. `gpt-5.6` é o alias da camada Sol; o LibreChat atribui a todas as três camadas do GPT-5.6 uma janela de contexto de 1.050.000 tokens e um limite máximo de saída de 128.000 tokens. Padrões legados obsoletos não estão mais incluídos, a menos que você os adicione explicitamente com `OPENAI_MODELS`.
- O GPT-5.6 suporta os valores `standard` e `pro` exclusivos da Responses API para `reasoning_mode`, além dos valores `auto`, `current_turn` e `all_turns` para `reasoning_context`. Eles podem ser configurados em [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode).
- Para um modelo GPT-5.6 com um `reasoning_effort` diferente de `none`, o LibreChat define o endpoint canônico da OpenAI como padrão para a Responses API, para que as ferramentas de função permaneçam compatíveis. Um `useResponsesApi: false` explícito mantém o Chat Completions. Azure OpenAI, OpenRouter e URLs base personalizadas ou de proxy reverso não são alternados automaticamente.
- Não é necessário selecionar um modelo de visão para mensagens com anexos, pois ele será alternado automaticamente nos bastidores para você. Se você não selecionou explicitamente um modelo de visão, ele será usado apenas para a solicitação de visão e você ainda deverá ver o modelo sem visão que havia selecionado após a conclusão bem-sucedida da solicitação.
- Os modelos Vision da OpenAI permitem mensagens sem anexos
- O endpoint OpenAI suporta todas as [Configurações de Endpoint Compartilhadas](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) via o arquivo de configuração `librechat.yaml`, incluindo `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` e `titleEndpoint`
