要获取您的 OpenAI API key，您需要：

- 前往 **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- 创建账户或使用现有账户登录
- 为您的账户添加付款方式
- 前往 https://platform.openai.com/api-keys 获取密钥。
- 您需要将以下环境变量设置为您的密钥，或者将其设置为 `user_provided` 以便用户提供他们自己的密钥。

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="用户输入其自有密钥的位置">

使用 `user_provided` 时，您无需提供任何密钥：每位用户都可以在聊天界面中输入自己的密钥。打开 endpoint 菜单，在 **OpenAI** 旁边有一个标有 **Set API Key** 的齿轮图标。点击它会打开一个对话框，其中包含用于输入密钥的字段，以及一个用于选择密钥保留时长的下拉菜单：30 分钟、2 小时、12 小时（默认）、1 天、7 天、30 天或永不过期。

该密钥会被加密并存储在服务器端该用户的账户下，因此只需输入一次，无需针对每次对话重复输入，且绝不会与其他用户共享。同一对话框中提供了 **Revoke**（撤销）操作，以及 **Revoke All**（全部撤销）功能，用于清除该用户存储的所有密钥。

如果端点菜单被隐藏（例如因为 Model Specs 禁用了 `modelSelect`），您仍然可以在 **Settings** 下的 **Data controls** 中，通过 **API keys** 部分访问同一个对话框。

在用户设置密钥之前，该 endpoint 对他们可见但无法使用。

</Callout>

- 您可以使用 `OPENAI_MODELS` 来确定您希望可用的模型。
  - 当 `OPENAI_API_KEY` 设置为 `user_provided` 时 → 只有放入此列表中的模型才可用
    - ⚠️新模型不会自动显示；您需要先将它们添加到此列表中
  - 当 `OPENAI_API_KEY` 设置为实际的 API 密钥值时 → 只要 `OPENAI_MODELS` 保持注释状态，它就会进行 API 调用以查明哪些模型可用，这应该会包含任何新模型。

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**注意：**

- GPT-6.1 Sol (`gpt-6.1-sol`) 加入了 OpenAI 和 Agents 的默认规范目录，而非 Assistants。在添加明确的条目之前，它将继承 GPT-6 Sol 的上下文/输出限制和定价；这些是系列回退值，并非独立确认的 GPT-6.1 定价。
- 没有匹配特定版本条目的 GPT 小版本更新将继承其所属系列已识别的上下文/输出限制、定价和推理设置。明确的条目具有优先权。例如，`gpt-6.1-sol` 不再回退到通用的 32K 上下文预算。原生 OpenAI 上未标注日期的点版本更新也可以继承该系列的响应策略；带日期的快照保留通配符策略继承，Azure 保持部署特定，自定义 endpoint 不会自动切换。

- 内部 OpenAI 默认设置包括用于规范 OpenAI 和 Agents endpoint 的 `gpt-6-astra`。LibreChat 通过 Responses API 路由所有 Astra 请求，因为其工具调用仅限于 Responses，并移除了不受支持的采样参数，同时应用了 1,050,000 token 的上下文窗口和 128,000 token 的最大输出限制。Astra 被特意排除在 Assistants、Azure Assistants 和 Azure OpenAI 的默认目录之外。
- 内部 OpenAI 默认模型包括 `gpt-5.6`、`gpt-5.6-terra` 和 `gpt-5.6-luna`，随后是现有的 GPT-5 目录。`gpt-5.6` 是 Sol 层级的别名；LibreChat 为所有三个 GPT-5.6 层级分配了 1,050,000 token 的上下文窗口和 128,000 token 的最大输出限制。已弃用的旧版默认模型不再包含在内，除非您通过 `OPENAI_MODELS` 显式添加它们。
- GPT-5.6 支持仅限 Responses API 的 `reasoning_mode` 值 `standard` 和 `pro`，以及 `reasoning_context` 值 `auto`、`current_turn` 和 `all_turns`。这些可以在 [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode) 中进行配置。
- 对于具有非 `none` 的 `reasoning_effort` 的 GPT-5.6 模型，LibreChat 默认将规范的 OpenAI endpoint 指向 Responses API，以确保函数工具保持兼容。显式设置 `useResponsesApi: false` 则会保留使用 Chat Completions。Azure OpenAI、OpenRouter 以及自定义或反向代理的 base URL 不会自动切换。
- 当消息包含附件时，无需手动选择视觉模型，系统会在后台为您自动切换。如果您没有直接选择视觉模型，它将仅用于视觉请求；在请求成功后，您仍会看到您之前选择的非视觉模型。
- OpenAI Vision 模型允许在没有附件的情况下发送消息
- OpenAI endpoint 支持通过 `librechat.yaml` 配置文件使用所有 [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings)，包括 `streamRate`、`headers`、`titleModel`、`titleMethod`、`titlePrompt`、`titlePromptTemplate` 和 `titleEndpoint`。
