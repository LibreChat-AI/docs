Um Ihren OpenAI API-Schlüssel zu erhalten, müssen Sie:

- Gehen Sie zu **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Erstellen Sie ein Konto oder melden Sie sich mit Ihrem bestehenden Konto an
- Fügen Sie Ihrem Konto eine Zahlungsmethode hinzu
- Gehe zu https://platform.openai.com/api-keys, um einen Schlüssel zu erhalten.
- Sie müssen die folgende Umgebungsvariable auf Ihren Schlüssel setzen, oder Sie können sie auf `user_provided` setzen, damit Benutzer ihre eigenen Schlüssel angeben können.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Wo Benutzer ihren eigenen Schlüssel eingeben">

Bei `user_provided` geben Sie überhaupt keinen Schlüssel an: Jeder Benutzer gibt seinen eigenen über die Chat-Benutzeroberfläche ein. Öffnen Sie das endpoint-Menü; neben **OpenAI** befindet sich ein Zahnradsymbol mit der Beschriftung **Set API Key**. Ein Klick darauf öffnet ein Dialogfeld mit einem Feld für den Schlüssel und einem Dropdown-Menü, in dem festgelegt werden kann, wie lange er gespeichert bleiben soll: 30 Minuten, 2 Stunden, 12 Stunden (Standard), 1 Tag, 7 Tage, 30 Tage oder niemals ablaufen.

Der Schlüssel wird verschlüsselt und serverseitig mit dem Konto des jeweiligen Benutzers gespeichert, sodass er nur einmal und nicht pro Konversation eingegeben werden muss und niemals mit anderen Benutzern geteilt wird. Dasselbe Dialogfeld enthält eine **Revoke**-Aktion sowie **Revoke All**, um alle vom Benutzer gespeicherten Schlüssel zu löschen.

Wenn das endpoint-Menü ausgeblendet ist, zum Beispiel weil eine Model Specs `modelSelect` deaktiviert, ist dasselbe Dialogfeld unter **Einstellungen** im Bereich **Datenkontrolle** im Abschnitt **API keys** erreichbar.

Bis ein Benutzer einen Schlüssel festlegt, ist der endpoint für ihn zwar sichtbar, aber nicht verwendbar.

</Callout>

- Sie können mit `OPENAI_MODELS` festlegen, welche Modelle verfügbar sein sollen.
  - Wenn `OPENAI_API_KEY` auf `user_provided` gesetzt ist → sind nur die in dieser Liste aufgeführten Modelle verfügbar
    - ⚠️Neue Modelle erscheinen nicht automatisch; du musst sie zuerst zu dieser Liste hinzufügen
  - Wenn `OPENAI_API_KEY` auf den tatsächlichen API-Schlüsselwert gesetzt ist → solange `OPENAI_MODELS` auskommentiert bleibt, wird ein API-Aufruf getätigt, um herauszufinden, welche Modelle verfügbar sind, was auch alle neuen Modelle einschließen sollte.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Hinweise:**

- GPT-6.1 Sol (`gpt-6.1-sol`) wird in die kanonischen Standardkataloge von OpenAI und Agents aufgenommen, nicht in die von Assistants. Bis explizite Einträge hinzugefügt werden, erbt es die Kontext-/Ausgabelimits und die Preisgestaltung von GPT-6 Sol; dies sind Familien-Fallbacks, keine unabhängig bestätigten Preise für GPT-6.1.
- GPT-Point-Releases ohne passenden Eintrag pro Release übernehmen die Kontext-/Ausgabelimits, Preise und Reasoning-Einstellungen ihrer erkannten Familie. Explizite Einträge haben Vorrang. Zum Beispiel greift `gpt-6.1-sol` nicht mehr auf das generische 32K-Kontextbudget zurück. Undatierte Point-Releases bei nativem OpenAI können ebenfalls die Responses-Richtlinie der Familie übernehmen; datierte Snapshots behalten die Wildcard-Richtlinien-Vererbung bei, Azure bleibt bereitstellungsspezifisch und benutzerdefinierte Endpoints werden nicht automatisch umgestellt.

- Zu den internen OpenAI-Standardwerten gehört `gpt-6-astra` für die kanonischen OpenAI- und Agents-endpoints. LibreChat leitet jede Astra-Anfrage über die Responses API, da deren Tool-Aufrufe ausschließlich auf Responses basieren, entfernt nicht unterstützte Sampling-Parameter und wendet ein Kontextfenster von 1.050.000 Token mit einer maximalen Ausgabe von 128.000 Token an. Astra ist absichtlich von den Standardkatalogen für Assistants, Azure Assistants und Azure OpenAI ausgeschlossen.
- Die internen OpenAI-Standardeinstellungen umfassen `gpt-5.6`, `gpt-5.6-terra` und `gpt-5.6-luna`, gefolgt vom bestehenden GPT-5-Katalog. `gpt-5.6` ist der Alias für die Sol-Stufe; LibreChat weist allen drei GPT-5.6-Stufen ein Kontextfenster von 1.050.000 Token und eine maximale Ausgabe von 128.000 Token zu. Veraltete Legacy-Standardeinstellungen sind nicht mehr enthalten, es sei denn, Sie fügen sie explizit mit `OPENAI_MODELS` hinzu.
- GPT-5.6 unterstützt die Responses API-spezifischen `reasoning_mode`-Werte `standard` und `pro` sowie die `reasoning_context`-Werte `auto`, `current_turn` und `all_turns`. Diese können in [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode) konfiguriert werden.
- Für ein GPT-5.6-Modell mit einem `reasoning_effort`-Wert ungleich `none` verwendet LibreChat standardmäßig den kanonischen OpenAI-endpoint für die Responses API, damit Funktionstools kompatibel bleiben. Ein explizites `useResponsesApi: false` behält Chat Completions bei. Azure OpenAI, OpenRouter sowie benutzerdefinierte oder Reverse-Proxy-Basis-URLs werden nicht automatisch umgestellt.
- Die Auswahl eines Vision-Modells für Nachrichten mit Anhängen ist nicht erforderlich, da dies im Hintergrund automatisch für Sie erledigt wird. Wenn Sie nicht explizit ein Vision-Modell ausgewählt haben, wird es nur für die Vision-Anfrage verwendet, und Sie sollten nach erfolgreichem Abschluss der Anfrage weiterhin das von Ihnen gewählte Nicht-Vision-Modell sehen.
- OpenAI Vision-Modelle erlauben Nachrichten ohne Anhänge
- Der OpenAI endpoint unterstützt alle [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) über die Konfigurationsdatei `librechat.yaml`, einschließlich `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` und `titleEndpoint`.
