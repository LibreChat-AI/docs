OpenAI API 키를 얻으려면 다음을 수행해야 합니다:

- **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**로 이동하세요.
- 계정을 생성하거나 기존 계정으로 로그인하세요
- 계정에 결제 수단을 추가하세요
- https://platform.openai.com/api-keys 로 이동하여 키를 받으세요.
- 다음 환경 변수를 귀하의 키로 설정해야 합니다. 또는 사용자가 직접 자신의 키를 입력하도록 하려면 `user_provided`로 설정할 수 있습니다.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="사용자가 자신의 키를 입력하는 곳">

`user_provided`를 사용하면 키를 전혀 제공하지 않아도 됩니다. 각 사용자가 채팅 UI에서 직접 자신의 키를 입력하게 됩니다. 엔드포인트 메뉴를 열면 **OpenAI** 옆에 **Set API Key**라고 표시된 톱니바퀴 아이콘이 있습니다. 이를 클릭하면 키를 입력할 필드와 키 유지 기간을 선택할 수 있는 드롭다운 메뉴가 포함된 대화 상자가 나타납니다. 유지 기간은 30분, 2시간, 12시간(기본값), 1일, 7일, 30일 또는 만료 없음 중에서 선택할 수 있습니다.

키는 암호화되어 해당 사용자의 계정에 서버 측으로 저장되므로, 대화마다 입력할 필요 없이 한 번만 입력하면 되며 다른 사용자와 절대 공유되지 않습니다. 동일한 대화 상자에 **Revoke**(취소) 작업이 있으며, 사용자가 저장한 모든 키를 삭제할 수 있는 **Revoke All**(모두 취소) 기능도 제공됩니다.

endpoint 메뉴가 숨겨져 있는 경우(예: Model Specs에서 `modelSelect`를 비활성화한 경우), 동일한 대화 상자에 **설정(Settings)**의 **데이터 제어(Data controls)** 아래에 있는 **API 키(API keys)** 섹션에서 접근할 수 있습니다.

사용자가 키를 설정하기 전까지는 해당 endpoint가 사용자에게 표시되지만 사용할 수는 없습니다.

</Callout>

- `OPENAI_MODELS`를 사용하여 사용 가능한 모델을 결정할 수 있습니다.
  - `OPENAI_API_KEY`가 `user_provided`로 설정된 경우 → 이 목록에 포함된 모델만 사용할 수 있습니다.
    - ⚠️새로운 모델은 자동으로 표시되지 않습니다. 먼저 이 목록에 추가해야 합니다.
  - `OPENAI_API_KEY`가 실제 API 키 값으로 설정된 경우 → `OPENAI_MODELS`가 주석 처리된 상태로 유지되는 한, 사용 가능한 모델을 확인하기 위해 API 호출을 수행하며, 여기에는 새로 추가된 모델도 포함됩니다.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**참고:**

- GPT-6.1 Sol(`gpt-6.1-sol`)이 Assistants가 아닌 표준 OpenAI 및 Agents 기본 카탈로그에 추가되었습니다. 명시적인 항목이 추가되기 전까지는 GPT-6 Sol의 컨텍스트/출력 제한 및 가격 정책을 상속받습니다. 이는 패밀리 폴백(family fallbacks)이며, 독립적으로 확인된 GPT-6.1 가격이 아닙니다.
- 일치하는 릴리스별 항목이 없는 GPT 포인트 릴리스는 해당 제품군(family)의 컨텍스트/출력 제한, 가격 책정 및 추론 설정을 상속받습니다. 명시적인 항목이 우선합니다. 예를 들어, `gpt-6.1-sol`은 더 이상 일반적인 32K 컨텍스트 예산으로 대체되지 않습니다. 네이티브 OpenAI의 날짜가 지정되지 않은 포인트 릴리스도 해당 제품군의 응답 정책(Responses policy)을 상속받을 수 있습니다. 날짜가 지정된 스냅샷은 와일드카드 정책 상속을 유지하며, Azure는 배포별 설정을 유지하고, 사용자 지정 endpoint는 자동으로 전환되지 않습니다.

- 내부 OpenAI 기본값에는 canonical OpenAI 및 Agents endpoint를 위한 `gpt-6-astra`가 포함되어 있습니다. LibreChat은 모든 Astra 요청을 Responses API를 통해 라우팅하는데, 이는 도구 호출이 Responses 전용이기 때문입니다. 또한 지원되지 않는 샘플링 매개변수를 제거하고 128,000 토큰의 최대 출력과 함께 1,050,000 토큰의 컨텍스트 윈도우를 적용합니다. Astra는 Assistants, Azure Assistants 및 Azure OpenAI 기본 카탈로그에서 의도적으로 제외되었습니다.
- 내부 OpenAI 기본값에는 `gpt-5.6`, `gpt-5.6-terra`, `gpt-5.6-luna`가 포함되며, 그 뒤를 이어 기존 GPT-5 카탈로그가 제공됩니다. `gpt-5.6`은 Sol 티어 별칭입니다. LibreChat은 세 가지 GPT-5.6 티어 모두에 1,050,000 토큰의 컨텍스트 윈도우와 128,000 토큰의 최대 출력 제한을 할당합니다. 더 이상 사용되지 않는 레거시 기본값은 `OPENAI_MODELS`를 사용하여 명시적으로 추가하지 않는 한 포함되지 않습니다.
- GPT-5.6는 Responses API 전용 `reasoning_mode` 값인 `standard` 및 `pro`와 `reasoning_context` 값인 `auto`, `current_turn`, `all_turns`를 지원합니다. 이는 [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode)에서 구성할 수 있습니다.
- `none`이 아닌 `reasoning_effort`를 사용하는 GPT-5.6 모델의 경우, LibreChat은 함수 도구(function tools)와의 호환성을 유지하기 위해 기본적으로 표준 OpenAI endpoint를 Responses API로 설정합니다. `useResponsesApi: false`를 명시적으로 설정하면 Chat Completions를 계속 사용할 수 있습니다. Azure OpenAI, OpenRouter, 그리고 사용자 지정 또는 리버스 프록시(reverse-proxy) base URL은 자동으로 전환되지 않습니다.
- 첨부 파일이 포함된 메시지를 위해 비전 모델을 직접 선택할 필요는 없습니다. 백그라운드에서 자동으로 전환되기 때문입니다. 비전 모델을 명시적으로 선택하지 않은 경우, 해당 모델은 비전 요청에만 사용되며 요청이 성공한 후에는 이전에 선택했던 비전 기능이 없는 모델이 그대로 유지되는 것을 확인할 수 있습니다.
- OpenAI Vision 모델은 첨부 파일이 없는 메시지를 허용합니다
- OpenAI endpoint는 `librechat.yaml` 구성 파일을 통해 `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate`, `titleEndpoint`를 포함한 모든 [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings)을 지원합니다.
