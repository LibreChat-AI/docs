Para el endpoint de Google, puedes usar la **Gemini API a través de Google AI Studio** o la **Vertex AI API**.

La Generative Language API utiliza una API key, la cual puedes obtener en **Google AI Studio**.

Para Vertex AI, necesitas un archivo de clave JSON de Service Account, con el acceso adecuado configurado.

A continuación se proporcionan instrucciones para ambos.

## Generative Language API (Gemini) [#generative-language-api-gemini]

**[Consulta aquí los precios y límites de tasa de la API de Gemini](https://ai.google.dev/pricing)**

⚠️ Aunque los modelos de Google son gratuitos, utilizan tus entradas/salidas para ayudar a mejorar el modelo, con datos desidentificados de tu cuenta de Google y tu clave API.
⚠️ Durante este período, tus mensajes “pueden ser accesibles para revisores capacitados”.

Para usar modelos de Gemini a través de Google AI Studio, necesitarás una API key. Si aún no tienes una, crea una clave en Google AI Studio.

Obtén una API key aquí: **[aistudio.google.com](https://aistudio.google.com/app/apikey)**

Una vez que tengas tu clave, proporciónala en tu archivo .env, lo cual permite que todos los usuarios de tu instancia la utilicen.

```bash filename=".env"
GOOGLE_KEY=mY_SeCreT_w9347w8_kEY
```

O bien, puede hacer que los usuarios lo proporcionen desde el frontend configurando lo siguiente:

```bash filename=".env"
GOOGLE_KEY=user_provided
```

Algunos proxies inversos no admiten la cabecera `X-goog-api-key`. Puede configurar LibreChat para que utilice la cabecera `Authorization` en su lugar:

```bash filename=".env"
GOOGLE_AUTH_HEADER=true
```

Dado que la obtención de la lista de modelos aún no es compatible, debes configurar los modelos que deseas utilizar en el archivo .env.

Por ejemplo, los siguientes modelos actuales pueden configurarse para la Gemini API:

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash,gemini-2.0-flash-lite
```

You can also set the list in `librechat.yaml` with `endpoints.google.models`, an array of model IDs. A list configured there replaces `GOOGLE_MODELS`. It is read from the configuration resolved for each request, so a configuration override applied to a role or group can narrow it for those users.

<Callout type="note" title="Notas:">

- Gemini 3.8 Flash, Gemini 3.7 Flash, Gemini 3.6 Flash, Gemini 3.5 Flash y Gemini 3.5 Flash-Lite son compatibles tanto a través de Google AI Studio como de Google Cloud Gemini Enterprise Agent Platform. LibreChat les asigna a cada uno una ventana de contexto de 1,048,576 tokens; Gemini 3.8 Flash admite hasta 65,536 tokens de salida.
- LibreChat establece por defecto Gemini 3.8 Flash, Gemini 3.7 Flash, Gemini 3.6 Flash y Gemini 3.5 Flash en `MEDIUM` thinking, y Gemini 3.5 Flash-Lite en `MINIMAL`. Gemini 3.8 y 3.7 Flash rechazan `MINIMAL`, por lo que LibreChat sustituye este valor por `LOW` cuando se solicita dicho nivel; otros valores explícitos de `thinkingLevel` compatibles se conservan.
- Para estos modelos, LibreChat elimina los parámetros de muestreo y penalización no compatibles (`temperature`, `topP`, `topK`, `presencePenalty` y `frequencyPenalty`), ignora el `thinkingBudget` numérico más antiguo y utiliza `thinkingLevel` en su lugar.
- Los modelos Gemini Flash a partir de la versión 3.6 no admiten el prellenado (prefill) del asistente. LibreChat evita que las respuestas editadas del asistente se vuelvan a enviar como un turno de rol de modelo final no compatible.
- Las estimaciones de costos integradas utilizan las tarifas introductorias de Gemini 3.6/3.7/3.8 Flash hasta el 31 de diciembre de 2026: $0.75 de entrada, $3.75 de salida y $0.075 de entrada en caché por millón de tokens. A partir del 1 de enero de 2027, las tarifas son de $1.50, $7.50 y $0.15 respectivamente.
- Con el endpoint de Google, no puede utilizar Vertex AI y Generative Language API al mismo tiempo. Debe elegir uno u otro.

</Callout>

## Contexto de URL [#url-context]

La herramienta URL Context de Google permite que los modelos Gemini compatibles lean las URLs incluidas en el mensaje del usuario, tales como páginas web, imágenes y archivos PDF. En LibreChat, habilítela con el parámetro `url_context` del endpoint de Google.

```yaml filename="modelSpecs / list / preset"
preset:
  endpoint: google
  model: gemini-2.5-flash
  url_context: true
```

También puedes habilitarlo para un endpoint personalizado con formato Google mediante `addParams` o parámetros predeterminados:

```yaml filename="endpoints / custom"
custom:
  - name: 'Google Gateway'
    apiKey: '${GOOGLE_KEY}'
    baseURL: 'https://gateway.example.com/v1'
    models:
      default: ['gemini-2.5-flash']
    customParams:
      defaultParamsEndpoint: google
    addParams:
      url_context: true
```

`url_context` está disponible en los modelos de texto de Gemini compatibles, incluyendo los modelos Gemini 2.5+ y Gemini 3.x. Los enlaces de YouTube se gestionan por separado con la comprensión de video nativa de Gemini cuando `url_context` está habilitado, debido a que la herramienta URL Context de Google no admite URLs de YouTube directamente.

## Vertex AI [#vertex-ai]

**[Consulta aquí los precios y límites de tasa de la API de Vertex](https://cloud.google.com/vertex-ai/generative-ai/pricing)**

Para configurar los LLMs de Google (a través de Google Cloud Vertex AI), primero, regístrate en Google Cloud: **[cloud.google.com](https://cloud.google.com/)**

Por lo general, puedes obtener **$300 de crédito inicial**, lo que hace que esta opción sea gratuita durante 90 días.

1. Una vez registrado, habilite la Vertex AI API en Google Cloud:
   - Ve a la **[página de Vertex AI en Google Cloud console](https://console.cloud.google.com/vertex-ai)**
   - Haz clic en `Enable API` si se te solicita
2. Cree una cuenta de servicio con el rol de Vertex AI:
   - **[Haz clic aquí para crear una cuenta de servicio](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts/create?walkthrough_id=iam--create-service-account#step_index=1)**
   - **Seleccionar o crear un proyecto**
   - Ingrese un ID de cuenta de servicio (obligatorio), el nombre y la descripción son opcionales
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/0c5cd177-029b-44fa-a398-a794aeb09de6)
   - Haz clic en "Create and Continue" para asignar al menos el rol "Vertex AI User"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/22d3a080-e71e-446e-8485-bcc5bf558dbb)
   - **Haz clic en "Continue/Done"**
3. Cree una clave JSON para guardar en su directorio de proyecto:
   - Regresa a [la página de Service Accounts](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts)
   - **Seleccione su cuenta de servicio**
   - Haz clic en "Keys"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/735a7bbe-25a6-4b4c-9bb5-e0d8aa91be3d)
   - Haz clic en "Add Key" y luego en "Create new key"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/cfbb20d3-94a8-4cd1-ac39-f9cd8c2fceaa)
   - **Elige JSON como el tipo de clave y haz clic en "Create"**
   - **Descargue el archivo de clave y cámbiele el nombre a 'auth.json'**
   - **Guárdalo dentro del directorio del proyecto, en `/api/data/`**
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/f5b8bcb5-1b20-4751-81a1-d3757a4b3f2f)

<Callout type="info" title="Alternativa: Usar GOOGLE_SERVICE_KEY_FILE">
  En lugar de guardar el archivo de clave en `/api/data/auth.json`, puede utilizar la variable de entorno `GOOGLE_SERVICE_KEY_FILE` para especificar la ruta a su archivo de clave de cuenta de servicio. Esto proporciona más flexibilidad en la forma en que gestiona sus credenciales. Consulte la sección de variables de entorno a continuación para obtener más detalles.
</Callout>

**Guardar su archivo de clave JSON en el directorio del proyecto, lo cual permite que todos los usuarios de su instancia de LibreChat lo utilicen.**

Alternativamente, puede hacer que los usuarios lo proporcionen desde el frontend configurando lo siguiente:

```bash filename=".env"
# Note: this configures both the Vertex AI Service Account JSON key file
# and the Generative Language API key to be provided from the frontend.
GOOGLE_KEY=user_provided
```

También puede especificar el archivo de clave de cuenta de servicio utilizando la variable de entorno `GOOGLE_SERVICE_KEY_FILE`:

```bash filename=".env"
# Path to the service account JSON key file
GOOGLE_SERVICE_KEY_FILE=/path/to/auth.json

# Or provide as a URL
GOOGLE_SERVICE_KEY_FILE=https://example.com/path/to/auth.json

# Or provide as stringified JSON
GOOGLE_SERVICE_KEY_FILE='{"type":"service_account","project_id":"your-project",...}'

# Or provide as base64 encoded JSON
GOOGLE_SERVICE_KEY_FILE=eyJ0eXBlIjogInNlcnZpY2VfYWNjb3VudCIsICJwcm9qZWN0X2lkIjogInlvdXItcHJvamVjdC1pZCIsIC4uLn0=
```

Esto es particularmente útil para funciones que requieren autenticación de Vertex AI, como las capacidades de OCR.

También puede especificar la ubicación de Google Cloud para las solicitudes de la API de Vertex AI:

```bash filename=".env"
# Google Cloud region for Vertex AI (defaults to us-central1)
# The multi-region locations us, eu, and global are also accepted.
GOOGLE_LOC=us-central1

# Alternative region for Gemini Image Generation (defaults to global)
GOOGLE_CLOUD_LOCATION=global
```

Dado que la obtención de la lista de modelos aún no es compatible, debes configurar los modelos que deseas utilizar en el archivo .env.

Para Vertex AI, utilice los IDs de modelo de Vertex cuando difieran de la Gemini API:

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash-001,gemini-2.0-flash-lite-001
```

En Vertex AI, `gemini-4-argon` se sirve únicamente desde los endpoints multirregionales `global`, `us` y `eu`, no desde ubicaciones regionales como `us-central1`. Con `GOOGLE_LOC` sin definir, LibreChat usa `global` para este modelo. Si `GOOGLE_LOC` se establece en una región `us-` o `europe-`, LibreChat traslada la solicitud al multirregional `us` o `eu` para que los datos permanezcan en la misma geografía. Una región fuera de `us` y `eu` se mantiene tal como está configurada, y la solicitud fallará a menos que establezca `GOOGLE_LOC` en `global`, `us` o `eu`.

Los Agentes guardados que utilizan el proveedor `vertexai` también usan este catálogo compartido de modelos de Google en el Agent Builder y durante la ejecución. Si el despliegue proporciona un catálogo de modelos `vertexai` explícito, esa lista específica del proveedor tiene prioridad; de lo contrario, se utiliza `GOOGLE_MODELS` para la selección y validación de Vertex AI.

<Callout type="note" title="Si está utilizando Docker">
If you're using docker and want to provide the `auth.json` file, you will need to also mount the volume in docker-compose.override.yml

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./api/data/auth.json
        target: /app/api/data/auth.json
```

</Callout>

## Configuración de seguridad de Google [#google-safety-settings]

Para configurar los ajustes de seguridad tanto para Vertex AI como para Generative Language API, puedes establecer lo siguiente en tu archivo .env:

```bash filename=".env"
GOOGLE_SAFETY_SEXUALLY_EXPLICIT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HATE_SPEECH=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HARASSMENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_DANGEROUS_CONTENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_CIVIC_INTEGRITY=BLOCK_ONLY_HIGH
```

También puede excluir los ajustes de seguridad configurando lo siguiente en su archivo .env, lo cual utilizará los valores predeterminados del proveedor. Esto puede ser útil si tiene problemas con ajustes de seguridad específicos.

```bash filename=".env"
GOOGLE_EXCLUDE_SAFETY_SETTINGS=true
```

Las categorías que no configures se envían con el umbral `HARM_BLOCK_THRESHOLD_UNSPECIFIED`, lo que mantiene el valor predeterminado del proveedor. La excepción es `GOOGLE_SAFETY_CIVIC_INTEGRITY`, que toma el valor predeterminado `BLOCK_NONE` cuando no está definida.

NOTA: Tu cuenta de Google no tiene acceso a la configuración `BLOCK_NONE` de forma predeterminada, por lo que las solicitudes pueden ser rechazadas si se envía (por ejemplo, a través del valor predeterminado de integridad cívica). En ese caso, establece `GOOGLE_SAFETY_CIVIC_INTEGRITY` en otro umbral, o establece `GOOGLE_EXCLUDE_SAFETY_SETTINGS=true`.
Para usar esta configuración restringida de `HarmBlockThreshold`, necesitarás hacer una de las siguientes acciones:

- (a) Obtenga acceso a través de una lista de permitidos mediante su equipo de cuenta de Google
- (b) Cambie su tipo de cuenta a facturación mensual siguiendo estas instrucciones:
  https://cloud.google.com/billing/docs/how-to/invoiced-billing

**Notas:**

- El endpoint de Google admite todos los [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) a través del archivo de configuración `librechat.yaml`, incluyendo `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` y `titleEndpoint`.
