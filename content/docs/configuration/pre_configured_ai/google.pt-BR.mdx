Para o endpoint Google, você pode usar a **Gemini API através do Google AI Studio** ou a **Vertex AI API**.

A Generative Language API utiliza uma API key, que você pode obter no **Google AI Studio**.

Para o Vertex AI, você precisa de um arquivo de chave JSON da Service Account, com o acesso apropriado configurado.

As instruções para ambos são fornecidas abaixo.

## Generative Language API (Gemini) [#generative-language-api-gemini]

**[Veja aqui os preços e limites de taxa da API do Gemini](https://ai.google.dev/pricing)**

⚠️ Embora os modelos do Google sejam gratuitos, eles utilizam suas entradas/saídas para ajudar a melhorar o modelo, com dados desidentificados da sua Conta Google e chave de API.
⚠️ Durante este período, suas mensagens “podem estar acessíveis a revisores treinados.”

Para usar modelos Gemini através do Google AI Studio, você precisará de uma API key. Se você ainda não possui uma, crie uma chave no Google AI Studio.

Obtenha uma chave de API aqui: **[aistudio.google.com](https://aistudio.google.com/app/apikey)**

Assim que tiver sua chave, forneça-a em seu arquivo .env, o que permite que todos os usuários da sua instância a utilizem.

```bash filename=".env"
GOOGLE_KEY=mY_SeCreT_w9347w8_kEY
```

Ou, você pode permitir que os usuários forneçam isso a partir do frontend definindo o seguinte:

```bash filename=".env"
GOOGLE_KEY=user_provided
```

Alguns proxies reversos não suportam o cabeçalho `X-goog-api-key`. Você pode configurar o LibreChat para usar o cabeçalho `Authorization` em vez disso:

```bash filename=".env"
GOOGLE_AUTH_HEADER=true
```

Como a busca da lista de modelos ainda não é suportada, você deve definir os modelos que deseja usar no arquivo .env.

Por exemplo, os seguintes modelos atuais podem ser configurados para a Gemini API:

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash,gemini-2.0-flash-lite
```

Você também pode definir a lista no `librechat.yaml` com `endpoints.google.models`, um array de IDs de modelos. Uma lista configurada ali substitui `GOOGLE_MODELS`. Ela é lida a partir da configuração resolvida para cada requisição, então uma sobrescrita de configuração aplicada a um papel ou grupo pode restringi-la para esses usuários.

<Callout type="note" title="Notas:">

- Gemini 3.8 Flash, Gemini 3.7 Flash, Gemini 3.6 Flash, Gemini 3.5 Flash e Gemini 3.5 Flash-Lite são suportados tanto pelo Google AI Studio quanto pela Google Cloud Gemini Enterprise Agent Platform. O LibreChat atribui a cada um uma janela de contexto de 1.048.576 tokens; o Gemini 3.8 Flash suporta até 65.536 tokens de saída.
- O LibreChat define como padrão o `MEDIUM` thinking para Gemini 3.8 Flash, Gemini 3.7 Flash, Gemini 3.6 Flash e Gemini 3.5 Flash, e `MINIMAL` para o Gemini 3.5 Flash-Lite. O Gemini 3.8 e 3.7 Flash rejeitam `MINIMAL`, portanto o LibreChat substitui por `LOW` quando esse nível é solicitado; outros valores explícitos de `thinkingLevel` suportados são preservados.
- Para esses modelos, o LibreChat remove parâmetros de amostragem e penalidade não suportados (`temperature`, `topP`, `topK`, `presencePenalty` e `frequencyPenalty`), ignora o `thinkingBudget` numérico mais antigo e usa `thinkingLevel` em seu lugar.
- Modelos Gemini Flash a partir da versão 3.6 não suportam preenchimento de assistente (assistant prefill). O LibreChat impede que respostas editadas do assistente sejam reenviadas como um turno de função de modelo (model-role) final não suportado.
- As estimativas de custo integradas utilizam as taxas introdutórias do Gemini 3.6/3.7/3.8 Flash até 31 de dezembro de 2026: $0,75 para entrada, $3,75 para saída e $0,075 para entrada em cache por milhão de tokens. A partir de 1º de janeiro de 2027, as taxas serão de $1,50, $7,50 e $0,15, respectivamente.
- Com o endpoint Google, você não pode usar o Vertex AI e a Generative Language API ao mesmo tempo. Você deve escolher um ou outro.

</Callout>

## Contexto de URL [#url-context]

A ferramenta URL Context do Google permite que modelos Gemini compatíveis leiam URLs incluídas na mensagem do usuário, como páginas da web, imagens e PDFs. No LibreChat, habilite-a com o parâmetro `url_context` do endpoint Google.

```yaml filename="modelSpecs / list / preset"
preset:
  endpoint: google
  model: gemini-2.5-flash
  url_context: true
```

Você também pode habilitá-lo para um endpoint personalizado no formato do Google com `addParams` ou padrões de parâmetros:

```yaml filename="endpoints / custom"
custom:
  - name: 'Google Gateway'
    apiKey: '${GOOGLE_KEY}'
    baseURL: 'https://gateway.example.com/v1'
    models:
      default: ['gemini-2.5-flash']
    customParams:
      defaultParamsEndpoint: google
    addParams:
      url_context: true
```

`url_context` está disponível em modelos de texto Gemini compatíveis, incluindo modelos Gemini 2.5+ e Gemini 3.x. Links do YouTube são tratados separadamente com a compreensão de vídeo nativa do Gemini quando `url_context` está ativado, pois a ferramenta URL Context do Google não oferece suporte direto a URLs do YouTube.

## Vertex AI [#vertex-ai]

**[Veja aqui os preços e limites de taxa da Vertex API](https://cloud.google.com/vertex-ai/generative-ai/pricing)**

Para configurar LLMs do Google (via Google Cloud Vertex AI), primeiro, inscreva-se no Google Cloud: **[cloud.google.com](https://cloud.google.com/)**

Você geralmente consegue **$300 em crédito inicial**, o que torna esta opção gratuita por 90 dias.

1. Após se inscrever, ative a Vertex AI API no Google Cloud:
   - Vá para a **[página do Vertex AI no console do Google Cloud](https://console.cloud.google.com/vertex-ai)**
   - Clique em `Enable API` se solicitado
2. Crie uma Service Account com a função Vertex AI:
   - **[Clique aqui para criar uma Service Account](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts/create?walkthrough_id=iam--create-service-account#step_index=1)**
   - **Selecione ou crie um projeto**
   - Insira um ID de conta de serviço (obrigatório), o nome e a descrição são opcionais
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/0c5cd177-029b-44fa-a398-a794aeb09de6)
   - Clique em "Create and Continue" para atribuir pelo menos a função "Vertex AI User"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/22d3a080-e71e-446e-8485-bcc5bf558dbb)
   - **Clique em "Continue/Done"**
3. Crie uma chave JSON para salvar no seu Diretório de Projeto:
   - **Volte para [a página de Contas de Serviço](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts)**
   - **Selecione sua conta de serviço**
   - Clique em "Keys"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/735a7bbe-25a6-4b4c-9bb5-e0d8aa91be3d)
   - Clique em "Add Key" e depois em "Create new key"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/cfbb20d3-94a8-4cd1-ac39-f9cd8c2fceaa)
   - **Escolha JSON como o tipo de chave e clique em "Create"**
   - **Baixe o arquivo de chave e renomeie-o para 'auth.json'**
   - **Salve-o dentro do diretório do projeto, em `/api/data/`**
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/f5b8bcb5-1b20-4751-81a1-d3757a4b3f2f)

<Callout type="info" title="Alternativa: Usando GOOGLE_SERVICE_KEY_FILE">
  Em vez de salvar o arquivo de chave em `/api/data/auth.json`, você pode usar a variável de ambiente `GOOGLE_SERVICE_KEY_FILE` para especificar o caminho para o seu arquivo de chave da conta de serviço. Isso oferece mais flexibilidade na forma como você gerencia suas credenciais. Veja a seção de variáveis de ambiente abaixo para mais detalhes.
</Callout>

**Salvar seu arquivo de chave JSON no diretório do projeto, o que permite que todos os usuários da sua instância do LibreChat o utilizem.**

Alternativamente, você pode permitir que os usuários forneçam isso a partir do frontend definindo o seguinte:

```bash filename=".env"
# Note: this configures both the Vertex AI Service Account JSON key file
# and the Generative Language API key to be provided from the frontend.
GOOGLE_KEY=user_provided
```

Você também pode especificar o arquivo de chave da conta de serviço usando a variável de ambiente `GOOGLE_SERVICE_KEY_FILE`:

```bash filename=".env"
# Path to the service account JSON key file
GOOGLE_SERVICE_KEY_FILE=/path/to/auth.json

# Or provide as a URL
GOOGLE_SERVICE_KEY_FILE=https://example.com/path/to/auth.json

# Or provide as stringified JSON
GOOGLE_SERVICE_KEY_FILE='{"type":"service_account","project_id":"your-project",...}'

# Or provide as base64 encoded JSON
GOOGLE_SERVICE_KEY_FILE=eyJ0eXBlIjogInNlcnZpY2VfYWNjb3VudCIsICJwcm9qZWN0X2lkIjogInlvdXItcHJvamVjdC1pZCIsIC4uLn0=
```

Isso é particularmente útil para recursos que exigem autenticação do Vertex AI, como recursos de OCR.

Você também pode especificar a localização do Google Cloud para solicitações da API Vertex AI:

```bash filename=".env"
# Google Cloud region for Vertex AI (defaults to us-central1)
# The multi-region locations us, eu, and global are also accepted.
GOOGLE_LOC=us-central1

# Alternative region for Gemini Image Generation (defaults to global)
GOOGLE_CLOUD_LOCATION=global
```

Como a busca da lista de modelos ainda não é suportada, você deve definir os modelos que deseja usar no arquivo .env.

Para o Vertex AI, use os IDs de modelo do Vertex onde eles diferirem da API do Gemini:

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash-001,gemini-2.0-flash-lite-001
```

No Vertex AI, o `gemini-4-argon` é servido apenas pelos endpoints multirregionais `global`, `us` e `eu`, e não por localizações regionais como `us-central1`. Com `GOOGLE_LOC` não definido, o LibreChat usa `global` para este modelo. Se `GOOGLE_LOC` estiver definido como uma região `us-` ou `europe-`, o LibreChat direciona a requisição para o multirregional `us` ou `eu`, para que os dados permaneçam na mesma geografia. Uma região fora de `us` e `eu` é mantida conforme configurada, e a requisição falhará a menos que você defina `GOOGLE_LOC` como `global`, `us` ou `eu`.

Agentes salvos usando o provedor `vertexai` também utilizam este catálogo compartilhado de modelos do Google no Agent Builder e em tempo de execução. Se a implantação fornecer um catálogo de modelos `vertexai` explícito, essa lista específica do provedor terá precedência; caso contrário, `GOOGLE_MODELS` será usado para a seleção e validação do Vertex AI.

<Callout type="note" title="Se você estiver usando Docker">
Se você estiver usando Docker e quiser fornecer o arquivo `auth.json`, você também precisará montar o volume no docker-compose.override.yml

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./api/data/auth.json
        target: /app/api/data/auth.json
```

</Callout>

## Configurações de Segurança do Google [#google-safety-settings]

Para definir as configurações de segurança tanto para o Vertex AI quanto para a Generative Language API, você pode definir o seguinte no seu arquivo .env:

```bash filename=".env"
GOOGLE_SAFETY_SEXUALLY_EXPLICIT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HATE_SPEECH=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HARASSMENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_DANGEROUS_CONTENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_CIVIC_INTEGRITY=BLOCK_ONLY_HIGH
```

Você também pode excluir as configurações de segurança definindo o seguinte em seu arquivo .env, o que usará os padrões do provedor. Isso pode ser útil se você estiver tendo problemas com configurações de segurança específicas.

```bash filename=".env"
GOOGLE_EXCLUDE_SAFETY_SETTINGS=true
```

As categorias que você não define são enviadas com o limite `HARM_BLOCK_THRESHOLD_UNSPECIFIED`, o que mantém o padrão do provedor. A exceção é `GOOGLE_SAFETY_CIVIC_INTEGRITY`, que assume `BLOCK_NONE` por padrão quando não está definida.

NOTA: Sua conta do Google não tem acesso à configuração `BLOCK_NONE` por padrão, portanto as solicitações podem ser rejeitadas se ela for enviada (por exemplo, por meio do padrão de integridade cívica). Nesse caso, defina `GOOGLE_SAFETY_CIVIC_INTEGRITY` com outro limite ou defina `GOOGLE_EXCLUDE_SAFETY_SETTINGS=true`.
Para usar essa configuração restrita de `HarmBlockThreshold`, você precisará de uma das seguintes opções:

- (a) Obtenha acesso através de uma allowlist via sua equipe de conta Google
- (b) Altere o tipo da sua conta para faturamento mensal seguindo estas instruções:
  https://cloud.google.com/billing/docs/how-to/invoiced-billing

**Notas:**

- O endpoint Google suporta todas as [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) via o arquivo de configuração `librechat.yaml`, incluindo `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` e `titleEndpoint`
