对于 Google endpoint，你可以使用 **通过 Google AI Studio 的 Gemini API** 或 **Vertex AI API**。

Generative Language API 使用 API 密钥，您可以从 **Google AI Studio** 获取该密钥。

对于 Vertex AI，你需要一个已配置适当访问权限的 Service Account JSON 密钥文件。

以下提供了两者的说明。

## Generative Language API (Gemini) [#generative-language-api-gemini]

**[点击此处查看 Gemini API 定价和速率限制](https://ai.google.dev/pricing)**

⚠️ 虽然 Google 模型是免费的，但它们会使用您的输入/输出内容来帮助改进模型，且数据已从您的 Google 账户和 API key 中去标识化。
⚠️ 在此期间，您的消息“可能会被经过培训的审核人员访问”。

要通过 Google AI Studio 使用 Gemini 模型，你需要一个 API key。如果你还没有，请在 Google AI Studio 中创建一个 key。

在此处获取 API 密钥：**[aistudio.google.com](https://aistudio.google.com/app/apikey)**

获取密钥后，请将其填入您的 .env 文件中，这将允许您实例的所有用户使用该密钥。

```bash filename=".env"
GOOGLE_KEY=mY_SeCreT_w9347w8_kEY
```

或者，您可以通过设置以下内容，让用户从前端提供它：

```bash filename=".env"
GOOGLE_KEY=user_provided
```

某些反向代理不支持 `X-goog-api-key` 请求头。您可以配置 LibreChat 改为使用 `Authorization` 请求头：

```bash filename=".env"
GOOGLE_AUTH_HEADER=true
```

由于目前尚不支持获取模型列表，您应该在 .env 文件中设置您想要使用的模型。

例如，以下当前模型可针对 Gemini API 进行配置：

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash,gemini-2.0-flash-lite
```

你还可以通过 `librechat.yaml` 中的 `endpoints.google.models` 设置该列表,它是一个模型 ID 数组。在此处配置的列表会替代 `GOOGLE_MODELS`。该列表会从每个请求所解析的配置中读取,因此应用于某个角色或用户组的配置覆盖可以为这些用户缩小可用模型的范围。

<Callout type="note" title="注意：">

- Gemini 3.8 Flash、Gemini 3.7 Flash、Gemini 3.6 Flash、Gemini 3.5 Flash 和 Gemini 3.5 Flash-Lite 均可通过 Google AI Studio 和 Google Cloud Gemini Enterprise Agent Platform 获得支持。LibreChat 为每个模型分配了 1,048,576 个 token 的上下文窗口；Gemini 3.8 Flash 支持最多 65,536 个输出 token。
- LibreChat 将 Gemini 3.8 Flash、Gemini 3.7 Flash、Gemini 3.6 Flash 和 Gemini 3.5 Flash 的默认思维模式设置为 `MEDIUM`，并将 Gemini 3.5 Flash-Lite 设置为 `MINIMAL`。Gemini 3.8 和 3.7 Flash 会拒绝 `MINIMAL`，因此当请求该级别时，LibreChat 会将其替换为 `LOW`；其他受支持的显式 `thinkingLevel` 值将保持不变。
- 对于这些模型，LibreChat 会移除不支持的采样和惩罚参数（`temperature`、`topP`、`topK`、`presencePenalty` 和 `frequencyPenalty`），忽略旧的数值型 `thinkingBudget`，并改用 `thinkingLevel`。
- 从 3.6 版本开始，Gemini Flash 模型不再支持 assistant prefill。LibreChat 会阻止将编辑后的 assistant 回复作为不受支持的尾随模型角色轮次重新提交。
- 内置成本估算使用 Gemini 3.6/3.7/3.8 Flash 截至 2026 年 12 月 31 日的优惠费率：每百万 token 输入 $0.75，输出 $3.75，缓存输入 $0.075。自 2027 年 1 月 1 日起，费率分别为 $1.50、$7.50 和 $0.15。
- 使用 Google endpoint 时，你不能同时使用 Vertex AI 和 Generative Language API。你必须二选一。

</Callout>

在 .env 文件中设置 `GOOGLE_KEY=user_provided`，即可将 Vertex AI 服务账号 JSON 密钥文件和 Generative Language API 密钥设置为由前端提供，具体如下：

## URL Context [#url-context]

Google 的 URL Context 工具允许受支持的 Gemini 模型读取用户消息中包含的 URL，例如网页、图像和 PDF。在 LibreChat 中，可以通过 Google endpoint 参数 `url_context` 来启用它。

```yaml filename="modelSpecs / list / preset"
preset:
  endpoint: google
  model: gemini-2.5-flash
  url_context: true
```

您也可以通过 `addParams` 或参数默认值将其用于 Google 风格的自定义 endpoint：

```yaml filename="endpoints / custom"
custom:
  - name: 'Google Gateway'
    apiKey: '${GOOGLE_KEY}'
    baseURL: 'https://gateway.example.com/v1'
    models:
      default: ['gemini-2.5-flash']
    customParams:
      defaultParamsEndpoint: google
    addParams:
      url_context: true
```

`url_context` 可用于受支持的 Gemini 文本模型，包括 Gemini 2.5+ 和 Gemini 3.x 模型。当启用 `url_context` 时，YouTube 链接将通过 Gemini 原生的视频理解功能单独处理，因为 Google 的 URL Context 工具不支持直接处理 YouTube URL。

## Vertex AI [#vertex-ai]

**[点击此处查看 Vertex API 定价和速率限制](https://cloud.google.com/vertex-ai/generative-ai/pricing)**

要设置 Google LLMs（通过 Google Cloud Vertex AI），首先请注册 Google Cloud：**[cloud.google.com](https://cloud.google.com/)**

你通常可以获得 **$300 的初始额度**，这使得该选项在 90 天内免费。

1. 注册完成后，在 Google Cloud 上启用 Vertex AI API：
   - 前往 **[Google Cloud 控制台上的 Vertex AI 页面](https://console.cloud.google.com/vertex-ai)**
   - 如果出现提示，请点击 `Enable API`
2. 创建一个具有 Vertex AI 角色的服务账号：
   - **[点击此处创建服务账号](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts/create?walkthrough_id=iam--create-service-account#step_index=1)**
   - **选择或创建一个项目**
   - 输入服务账号 ID（必填），名称和描述为选填。
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/0c5cd177-029b-44fa-a398-a794aeb09de6)
   - 点击“创建并继续”以至少授予“Vertex AI User”角色
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/22d3a080-e71e-446e-8485-bcc5bf558dbb)
   - **点击“继续/完成”**
3. 创建一个 JSON 密钥并保存到您的项目目录中：
   - **返回 [Service Accounts 页面](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts)**
   - **选择您的服务账号**
   - 点击“Keys”
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/735a7bbe-25a6-4b4c-9bb5-e0d8aa91be3d)
   - 点击“Add Key”，然后点击“Create new key”
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/cfbb20d3-94a8-4cd1-ac39-f9cd8c2fceaa)
   - **选择 JSON 作为密钥类型并点击“Create”**
   - **下载密钥文件并将其重命名为 'auth.json'**
   - **将其保存在项目目录下的 `/api/data/` 中**
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/f5b8bcb5-1b20-4751-81a1-d3757a4b3f2f)

<Callout type="info" title="替代方案：使用 GOOGLE_SERVICE_KEY_FILE">
  除了将密钥文件保存到 `/api/data/auth.json` 之外，您还可以使用 `GOOGLE_SERVICE_KEY_FILE` 环境变量来指定服务账号密钥文件的路径。这为您管理凭据提供了更大的灵活性。有关更多详细信息，请参阅下方的环境变量部分。
</Callout>

将您的 JSON 密钥文件保存在项目目录中，这将允许您的 LibreChat 实例的所有用户使用它。

或者，您可以通过设置以下内容，让用户从前端提供它：

```bash filename=".env"
# Note: this configures both the Vertex AI Service Account JSON key file
# and the Generative Language API key to be provided from the frontend.
GOOGLE_KEY=user_provided
```

您也可以使用 `GOOGLE_SERVICE_KEY_FILE` 环境变量来指定服务账号密钥文件：

```bash filename=".env"
# Path to the service account JSON key file
GOOGLE_SERVICE_KEY_FILE=/path/to/auth.json

# Or provide as a URL
GOOGLE_SERVICE_KEY_FILE=https://example.com/path/to/auth.json

# Or provide as stringified JSON
GOOGLE_SERVICE_KEY_FILE='{"type":"service_account","project_id":"your-project",...}'

# Or provide as base64 encoded JSON
GOOGLE_SERVICE_KEY_FILE=eyJ0eXBlIjogInNlcnZpY2VfYWNjb3VudCIsICJwcm9qZWN0X2lkIjogInlvdXItcHJvamVjdC1pZCIsIC4uLn0=
```

这对于需要 Vertex AI 身份验证的功能（例如 OCR 功能）特别有用。

您也可以为 Vertex AI API 请求指定 Google Cloud 位置：

```bash filename=".env"
# Google Cloud region for Vertex AI (defaults to us-central1)
# The multi-region locations us, eu, and global are also accepted.
GOOGLE_LOC=us-central1

# Alternative region for Gemini Image Generation (defaults to global)
GOOGLE_CLOUD_LOCATION=global
```

由于目前尚不支持获取模型列表，您应该在 .env 文件中设置您想要使用的模型。

对于 Vertex AI，如果 Vertex 模型 ID 与 Gemini API 不同，请使用 Vertex 模型 ID：

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash-001,gemini-2.0-flash-lite-001
```

在 Vertex AI 上,`gemini-4-argon` 仅通过 `global`、`us` 和 `eu` 多区域端点提供服务,不支持 `us-central1` 等区域端点。未设置 `GOOGLE_LOC` 时,LibreChat 会为该模型使用 `global`。如果将 `GOOGLE_LOC` 设置为 `us-` 或 `europe-` 开头的区域,LibreChat 会将请求转移到 `us` 或 `eu` 多区域,以确保数据保留在相同的地理区域内。`us` 和 `eu` 之外的区域将保持原有配置,除非您将 `GOOGLE_LOC` 设置为 `global`、`us` 或 `eu`,否则请求将失败。

使用 `vertexai` 提供程序的已保存 Agent 也会在 Agent Builder 和运行时使用此共享的 Google 模型目录。如果部署提供了明确的 `vertexai` 模型目录，则该提供程序特定的列表优先；否则将使用 `GOOGLE_MODELS` 进行 Vertex AI 的选择和验证。

<Callout type="note" title="如果您正在使用 Docker">
如果您正在使用 Docker 并希望提供 `auth.json` 文件，则还需要在 docker-compose.override.yml 中挂载该卷。

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./api/data/auth.json
        target: /app/api/data/auth.json
```

</Callout>

## Google 安全设置 [#google-safety-settings]

要为 Vertex AI 和 Generative Language API 设置安全设置，您可以在 .env 文件中设置以下内容：

```bash filename=".env"
GOOGLE_SAFETY_SEXUALLY_EXPLICIT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HATE_SPEECH=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HARASSMENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_DANGEROUS_CONTENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_CIVIC_INTEGRITY=BLOCK_ONLY_HIGH
```

您也可以通过在 .env 文件中设置以下内容来排除安全设置，这将使用提供商的默认设置。如果您在使用特定的安全设置时遇到问题，这可能会有所帮助。

```bash filename=".env"
GOOGLE_EXCLUDE_SAFETY_SETTINGS=true
```

分类如果未设置，将使用 `HARM_BLOCK_THRESHOLD_UNSPECIFIED` 阈值，即保留服务提供商的默认设置。例外情况是 `GOOGLE_SAFETY_CIVIC_INTEGRITY`，未设置时默认为 `BLOCK_NONE`。

注意:您的 Google 账户默认无权访问 `BLOCK_NONE` 设置,因此如果发送该设置(例如通过 civic integrity 默认值),请求可能会被拒绝。在这种情况下,请将 `GOOGLE_SAFETY_CIVIC_INTEGRITY` 设置为其他阈值,或设置 `GOOGLE_EXCLUDE_SAFETY_SETTINGS=true`。
要使用此受限的 `HarmBlockThreshold` 设置,您需要执行以下任一操作:

- (a) 通过您的 Google 账户团队获取允许列表 (allowlist) 访问权限
- (b) 按照此说明将您的账户类型切换为月度发票结算：
  https://cloud.google.com/billing/docs/how-to/invoiced-billing

**注意：**

- Google endpoint 支持通过 `librechat.yaml` 配置文件使用所有 [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings)，包括 `streamRate`、`headers`、`titleModel`、`titleMethod`、`titlePrompt`、`titlePromptTemplate` 和 `titleEndpoint`。
