Om je OpenAI API key te verkrijgen, moet je:

- Ga naar **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Maak een account aan of log in met je bestaande account
- Voeg een betaalmethode toe aan je account
- Ga naar https://platform.openai.com/api-keys om een sleutel te verkrijgen.
- Je zult de volgende omgevingsvariabele moeten instellen op jouw sleutel, of je kunt deze instellen op `user_provided` zodat gebruikers hun eigen sleutel kunnen opgeven.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Waar gebruikers hun eigen sleutel invoeren">

Met `user_provided` verstrek je helemaal geen sleutel: elke gebruiker voert zijn eigen sleutel in vanuit de chat-UI. Open het endpoint-menu en naast **OpenAI** staat een tandwielpictogram met het label **Set API Key**. Als je hierop klikt, wordt een dialoogvenster geopend met een veld voor de sleutel en een vervolgkeuzemenu voor hoe lang deze bewaard moet blijven: 30 minuten, 2 uur, 12 uur (de standaard), 1 dag, 7 dagen, 30 dagen, of nooit laten verlopen.

De sleutel wordt versleuteld en aan de serverzijde opgeslagen bij het account van die gebruiker, zodat deze eenmalig wordt ingevoerd in plaats van per gesprek, en deze wordt nooit gedeeld met andere gebruikers. Hetzelfde dialoogvenster bevat een **Revoke**-actie, plus **Revoke All** om elke sleutel die de gebruiker heeft opgeslagen te wissen.

Als het endpoint menu verborgen is, bijvoorbeeld omdat een Model Specs `modelSelect` uitschakelt, is hetzelfde dialoogvenster bereikbaar via **Settings** onder **Data controls**, in de sectie **API keys**.

Totdat een gebruiker een sleutel instelt, is het endpoint zichtbaar maar onbruikbaar voor hen.

</Callout>

- Je kunt bepalen welke modellen je beschikbaar wilt hebben met `OPENAI_MODELS`
  - Wanneer `OPENAI_API_KEY` is ingesteld op `user_provided` → zullen alleen de modellen in deze lijst beschikbaar zijn
    - ⚠️Nieuwe modellen verschijnen niet automatisch; je moet ze eerst aan deze lijst toevoegen
  - Wanneer `OPENAI_API_KEY` is ingesteld op de daadwerkelijke API-sleutelwaarde → zolang `OPENAI_MODELS` uitgeschakeld (gecommentarieerd) blijft, zal het een API-aanroep doen om te achterhalen welke modellen beschikbaar zijn, wat ook alle nieuwe modellen zou moeten bevatten.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Opmerkingen:**

- GPT-6.1 Sol (`gpt-6.1-sol`) wordt toegevoegd aan de canonieke OpenAI- en Agents-standaardcatalogi, niet aan Assistants. Totdat er expliciete vermeldingen zijn toegevoegd, neemt het de context-/outputlimieten en prijzen van GPT-6 Sol over; dit zijn familie-fallbacks, geen onafhankelijk bevestigde GPT-6.1-prijzen.
- GPT point-releases zonder bijbehorende per-release vermelding nemen de context/output-limieten, prijzen en redeneerinstellingen van hun herkende familie over. Expliciete vermeldingen krijgen voorrang. Bijvoorbeeld: `gpt-6.1-sol` valt niet langer terug op het algemene contextbudget van 32K. Niet-gedateerde point-releases op native OpenAI kunnen ook het Responses-beleid van de familie overnemen; gedateerde snapshots behouden overerving van wildcard-beleid, Azure blijft deployment-specifiek en aangepaste endpoints worden niet automatisch omgeschakeld.

- Interne OpenAI-standaarden bevatten `gpt-6-astra` voor de canonieke OpenAI- en Agents-endpoints. LibreChat routeert elk Astra-verzoek via de Responses API omdat de tool-aanroepen uitsluitend Responses zijn, verwijdert niet-ondersteunde sampling-parameters en past een contextvenster van 1.050.000 tokens toe met een maximale output van 128.000 tokens. Astra is opzettelijk uitgesloten van de standaardcatalogi voor Assistants, Azure Assistants en Azure OpenAI.
- Interne OpenAI-standaarden omvatten `gpt-5.6`, `gpt-5.6-terra` en `gpt-5.6-luna`, gevolgd door de bestaande GPT-5-catalogus. `gpt-5.6` is de alias voor de Sol-laag; LibreChat wijst aan alle drie de GPT-5.6-lagen een contextvenster van 1.050.000 tokens en een maximale output van 128.000 tokens toe. Verouderde legacy-standaarden zijn niet langer inbegrepen, tenzij je ze expliciet toevoegt met `OPENAI_MODELS`.
- GPT-5.6 ondersteunt de Responses API-only `reasoning_mode` waarden `standard` en `pro`, plus `reasoning_context` waarden `auto`, `current_turn` en `all_turns`. Deze kunnen worden geconfigureerd in [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode).
- Voor een GPT-5.6-model met een `reasoning_effort` die niet `none` is, stelt LibreChat standaard het canonieke OpenAI endpoint in op de Responses API, zodat functietools compatibel blijven. Een expliciete `useResponsesApi: false` behoudt Chat Completions. Azure OpenAI, OpenRouter en aangepaste of reverse-proxy basis-URL's worden niet automatisch omgeschakeld.
- Het selecteren van een vision-model voor berichten met bijlagen is niet nodig, aangezien dit achter de schermen voor je wordt gewisseld. Als je niet expliciet een vision-model hebt geselecteerd, wordt dit alleen gebruikt voor het vision-verzoek en zou je na een succesvol verzoek nog steeds het niet-vision-model moeten zien dat je had geselecteerd.
- OpenAI Vision-modellen staan berichten zonder bijlagen toe
- Het OpenAI endpoint ondersteunt alle [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) via het `librechat.yaml` configuratiebestand, inclusief `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` en `titleEndpoint`
