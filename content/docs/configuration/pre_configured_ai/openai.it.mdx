Per ottenere la tua API key di OpenAI, devi:

- Vai su **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Crea un account o accedi con quello esistente
- Aggiungi un metodo di pagamento al tuo account
- Vai su https://platform.openai.com/api-keys per ottenere una chiave.
- Dovrai impostare la seguente variabile d'ambiente con la tua chiave, oppure puoi impostarla su `user_provided` per consentire agli utenti di fornire la propria.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Dove gli utenti inseriscono la propria chiave">

Con `user_provided`, non fornisci alcuna chiave: ogni utente inserisce la propria dall'interfaccia di chat. Apri il menu dell'endpoint e, accanto a **OpenAI**, troverai un'icona a forma di ingranaggio etichettata **Set API Key**. Cliccandoci sopra si aprirà una finestra di dialogo con un campo per la chiave e un menu a tendina per scegliere per quanto tempo debba essere conservata: 30 minuti, 2 ore, 12 ore (impostazione predefinita), 1 giorno, 7 giorni, 30 giorni o mai scadere.

La chiave viene crittografata e archiviata lato server nell'account dell'utente, quindi viene inserita una sola volta anziché per ogni conversazione e non viene mai condivisa con altri utenti. La stessa finestra di dialogo dispone di un'azione **Revoke**, oltre a **Revoke All** per eliminare ogni chiave archiviata dall'utente.

Se il menu endpoint è nascosto, ad esempio perché una Model Specs disabilita `modelSelect`, la stessa finestra di dialogo è raggiungibile da **Settings** sotto **Data controls**, nella sezione **API keys**.

Finché un utente non imposta una chiave, l'endpoint è visibile ma inutilizzabile per lui.

</Callout>

- Puoi determinare quali modelli desideri avere a disposizione con `OPENAI_MODELS`
  - Quando `OPENAI_API_KEY` è impostato su `user_provided` → saranno disponibili solo i modelli inseriti in questo elenco
    - ⚠️I nuovi modelli non verranno visualizzati automaticamente; dovrai prima aggiungerli a questo elenco
  - Quando `OPENAI_API_KEY` è impostata sul valore effettivo della chiave API → finché `OPENAI_MODELS` viene lasciato commentato, verrà effettuata una chiamata API per scoprire quali modelli sono disponibili, il che dovrebbe includere tutti quelli nuovi.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Note:**

- GPT-6.1 Sol (`gpt-6.1-sol`) si aggiunge ai cataloghi predefiniti canonici di OpenAI e Agents, non a quelli di Assistants. Fino a quando non verranno aggiunte voci esplicite, eredita i limiti di contesto/output e i prezzi di GPT-6 Sol; si tratta di fallback di famiglia, non di prezzi di GPT-6.1 confermati in modo indipendente.
- Le release puntuali di GPT senza una voce corrispondente per release ereditano i limiti di contesto/output, i prezzi e le impostazioni di ragionamento della loro famiglia riconosciuta. Le voci esplicite hanno la precedenza. Ad esempio, `gpt-6.1-sol` non ricade più sul budget di contesto generico da 32K. Le release puntuali senza data su OpenAI nativo possono anche ereditare la policy Responses della famiglia; gli snapshot con data mantengono l'ereditarietà della wildcard-policy, Azure rimane specifico per il deployment e gli endpoint personalizzati non vengono commutati automaticamente.

- Le impostazioni predefinite interne di OpenAI includono `gpt-6-astra` per gli endpoint canonici OpenAI e Agents. LibreChat instrada ogni richiesta Astra attraverso la Responses API poiché le sue chiamate di funzione (tool calls) sono solo di tipo Responses, rimuove i parametri di campionamento non supportati e applica una finestra di contesto di 1.050.000 token con un output massimo di 128.000 token. Astra è intenzionalmente escluso dai cataloghi predefiniti di Assistants, Azure Assistants e Azure OpenAI.
- Le impostazioni predefinite interne di OpenAI includono `gpt-5.6`, `gpt-5.6-terra` e `gpt-5.6-luna`, seguiti dal catalogo GPT-5 esistente. `gpt-5.6` è l'alias del livello Sol; LibreChat assegna a tutti e tre i livelli GPT-5.6 una finestra di contesto di 1.050.000 token e un output massimo di 128.000 token. Le impostazioni predefinite legacy deprecate non sono più incluse a meno che non vengano aggiunte esplicitamente con `OPENAI_MODELS`.
- GPT-5.6 supporta i valori `standard` e `pro` per `reasoning_mode` esclusivamente tramite la Responses API, oltre ai valori `auto`, `current_turn` e `all_turns` per `reasoning_context`. Questi possono essere configurati nelle [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode).
- Per un modello GPT-5.6 con un `reasoning_effort` diverso da `none`, LibreChat imposta per impostazione predefinita l'endpoint canonico OpenAI sulle Responses API, in modo che gli strumenti di funzione rimangano compatibili. Un `useResponsesApi: false` esplicito mantiene le Chat Completions. Azure OpenAI, OpenRouter e gli URL di base personalizzati o reverse-proxy non vengono commutati automaticamente.
- Non è necessario selezionare un modello vision per i messaggi con allegati, poiché verrà sostituito automaticamente per te. Se non hai selezionato esplicitamente un modello vision, questo verrà utilizzato solo per la richiesta vision e dovresti comunque vedere il modello non-vision che avevi selezionato dopo che la richiesta è stata completata con successo.
- I modelli OpenAI Vision consentono messaggi senza allegati
- L'endpoint OpenAI supporta tutte le [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) tramite il file di configurazione `librechat.yaml`, inclusi `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` e `titleEndpoint`
