Pour l'endpoint Google, vous pouvez utiliser soit l'**API Gemini via Google AI Studio**, soit l'**API Vertex AI**.

L'API Generative Language utilise une clé API, que vous pouvez obtenir depuis **Google AI Studio**.

Pour Vertex AI, vous avez besoin d'un fichier de clé JSON de compte de service, avec les accès appropriés configurés.

Les instructions pour les deux sont données ci-dessous.

## Generative Language API (Gemini) [#generative-language-api-gemini]

**[Voir ici pour la tarification et les limites de débit de l'API Gemini](https://ai.google.dev/pricing)**

⚠️ Bien que les modèles Google soient gratuits, ils utilisent vos entrées/sorties pour aider à améliorer le modèle, avec des données anonymisées vis-à-vis de votre compte Google et de votre clé API.
⚠️ Durant cette période, vos messages « peuvent être accessibles à des réviseurs formés ».

Pour utiliser les modèles Gemini via Google AI Studio, vous aurez besoin d'une clé API. Si vous n'en avez pas déjà une, créez une clé dans Google AI Studio.

Obtenez une clé API ici : **[aistudio.google.com](https://aistudio.google.com/app/apikey)**

Une fois que vous avez votre clé, fournissez-la dans votre fichier .env, ce qui permet à tous les utilisateurs de votre instance de l'utiliser.

```bash filename=".env"
GOOGLE_KEY=mY_SeCreT_w9347w8_kEY
```

Ou, vous pouvez permettre aux utilisateurs de le fournir depuis l'interface en configurant ce qui suit :

```bash filename=".env"
GOOGLE_KEY=user_provided
```

Certains proxies inverses ne prennent pas en charge l'en-tête `X-goog-api-key`. Vous pouvez configurer LibreChat pour utiliser l'en-tête `Authorization` à la place :

```bash filename=".env"
GOOGLE_AUTH_HEADER=true
```

Puisque la récupération de la liste des modèles n'est pas encore prise en charge, vous devez définir les modèles que vous souhaitez utiliser dans le fichier .env.

Par exemple, les modèles actuels suivants peuvent être configurés pour l'API Gemini :

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash,gemini-2.0-flash-lite
```

Vous pouvez également définir la liste dans `librechat.yaml` avec `endpoints.google.models`, un tableau d'identifiants de modèles. Une liste configurée à cet endroit remplace `GOOGLE_MODELS`. Elle est lue à partir de la configuration résolue pour chaque requête, de sorte qu'une surcharge de configuration appliquée à un rôle ou à un groupe peut la restreindre pour ces utilisateurs.

<Callout type="note" title="Notes :">

- Gemini 3.8 Flash, Gemini 3.7 Flash, Gemini 3.6 Flash, Gemini 3.5 Flash et Gemini 3.5 Flash-Lite sont pris en charge à la fois via Google AI Studio et la plateforme Google Cloud Gemini Enterprise Agent. LibreChat leur attribue à chacun une fenêtre de contexte de 1 048 576 jetons ; Gemini 3.8 Flash prend en charge jusqu'à 65 536 jetons de sortie.
- LibreChat définit par défaut Gemini 3.8 Flash, Gemini 3.7 Flash, Gemini 3.6 Flash et Gemini 3.5 Flash sur `MEDIUM` thinking, et Gemini 3.5 Flash-Lite sur `MINIMAL`. Gemini 3.8 et 3.7 Flash rejettent `MINIMAL`, donc LibreChat substitue `LOW` lorsque ce niveau est demandé ; les autres valeurs explicites `thinkingLevel` prises en charge sont conservées.
- Pour ces modèles, LibreChat supprime les paramètres d'échantillonnage et de pénalité non pris en charge (`temperature`, `topP`, `topK`, `presencePenalty` et `frequencyPenalty`), ignore l'ancien `thinkingBudget` numérique et utilise `thinkingLevel` à la place.
- Les modèles Gemini Flash à partir de la version 3.6 ne prennent pas en charge le préremplissage de l'assistant (assistant prefill). LibreChat empêche les réponses de l'assistant modifiées d'être soumises à nouveau en tant que tour de rôle de modèle final non pris en charge.
- Les estimations de coûts intégrées utilisent les tarifs de lancement de Gemini 3.6/3.7/3.8 Flash jusqu'au 31 décembre 2026 : 0,75 $ en entrée, 3,75 $ en sortie et 0,075 $ par million de jetons pour l'entrée en cache. À partir du 1er janvier 2027, les tarifs seront respectivement de 1,50 $, 7,50 $ et 0,15 $.
- Avec l'endpoint Google, vous ne pouvez pas utiliser Vertex AI et Generative Language API en même temps. Vous devez choisir l'un ou l'autre.

</Callout>

Définir `GOOGLE_KEY=user_provided` dans votre fichier .env permet à la fois à la clé du compte de service Vertex AI (fichier JSON) et à la clé API Generative Language d'être fournies depuis l'interface comme suit :

## Contexte d'URL [#url-context]

L'outil URL Context de Google permet aux modèles Gemini pris en charge de lire les URL incluses dans le message de l'utilisateur, telles que les pages web, les images et les PDF. Dans LibreChat, activez-le avec le paramètre `url_context` du endpoint Google.

```yaml filename="modelSpecs / list / preset"
preset:
  endpoint: google
  model: gemini-2.5-flash
  url_context: true
```

Vous pouvez également l'activer pour un endpoint personnalisé de type Google avec `addParams` ou des paramètres par défaut :

```yaml filename="endpoints / custom"
custom:
  - name: 'Google Gateway'
    apiKey: '${GOOGLE_KEY}'
    baseURL: 'https://gateway.example.com/v1'
    models:
      default: ['gemini-2.5-flash']
    customParams:
      defaultParamsEndpoint: google
    addParams:
      url_context: true
```

`url_context` est disponible sur les modèles de texte Gemini pris en charge, y compris les modèles Gemini 2.5+ et Gemini 3.x. Les liens YouTube sont traités séparément avec la compréhension vidéo native de Gemini lorsque `url_context` est activé, car l'outil URL Context de Google ne prend pas directement en charge les URL YouTube.

## Vertex AI [#vertex-ai]

**[Voir ici pour la tarification et les limites de débit de l'API Vertex](https://cloud.google.com/vertex-ai/generative-ai/pricing)**

Pour configurer les LLM de Google (via Google Cloud Vertex AI), inscrivez-vous d'abord à Google Cloud : **[cloud.google.com](https://cloud.google.com/)**

Vous pouvez généralement obtenir **300 $ de crédit de départ**, ce qui rend cette option gratuite pendant 90 jours.

1. Une fois inscrit, activez l'API Vertex AI sur Google Cloud :
   - Allez sur la **[page Vertex AI de la console Google Cloud](https://console.cloud.google.com/vertex-ai)**
   - Cliquez sur `Enable API` si vous y êtes invité
2. Créez un compte de service avec le rôle Vertex AI :
   - **[Cliquez ici pour créer un compte de service](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts/create?walkthrough_id=iam--create-service-account#step_index=1)**
   - **Sélectionner ou créer un projet**
   - Saisissez un ID de compte de service (requis), le nom et la description sont facultatifs
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/0c5cd177-029b-44fa-a398-a794aeb09de6)
   - Cliquez sur "Create and Continue" pour attribuer au moins le rôle "Vertex AI User"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/22d3a080-e71e-446e-8485-bcc5bf558dbb)
   - **Cliquez sur "Continue/Done"**
3. Créez une clé JSON à enregistrer dans votre répertoire de projet :
   - **Retournez à [la page des comptes de service](https://console.cloud.google.com/projectselector/iam-admin/serviceaccounts)**
   - **Sélectionnez votre compte de service**
   - Cliquez sur "Keys"
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/735a7bbe-25a6-4b4c-9bb5-e0d8aa91be3d)
   - Cliquez sur « Add Key » puis sur « Create new key »
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/cfbb20d3-94a8-4cd1-ac39-f9cd8c2fceaa)
   - **Choisissez JSON comme type de clé et cliquez sur "Create"**
   - **Téléchargez le fichier de clé et renommez-le 'auth.json'**
   - **Enregistrez-le dans le répertoire du projet, dans `/api/data/`**
     - ![image](https://github.com/danny-avila/LibreChat/assets/110412045/f5b8bcb5-1b20-4751-81a1-d3757a4b3f2f)

<Callout type="info" title="Alternative : Utilisation de GOOGLE_SERVICE_KEY_FILE">
  Au lieu d'enregistrer le fichier de clé dans `/api/data/auth.json`, vous pouvez utiliser la variable d'environnement `GOOGLE_SERVICE_KEY_FILE` pour spécifier le chemin d'accès à votre fichier de clé de compte de service. Cela offre plus de flexibilité dans la gestion de vos identifiants. Consultez la section sur les variables d'environnement ci-dessous pour plus de détails.
</Callout>

**Enregistrer votre fichier de clé JSON dans le répertoire du projet, ce qui permet à tous les utilisateurs de votre instance LibreChat de l'utiliser.**

Alternativement, vous pouvez permettre aux utilisateurs de le fournir depuis l'interface en configurant ce qui suit :

```bash filename=".env"
# Note: this configures both the Vertex AI Service Account JSON key file
# and the Generative Language API key to be provided from the frontend.
GOOGLE_KEY=user_provided
```

Vous pouvez également spécifier le fichier de clé de compte de service en utilisant la variable d'environnement `GOOGLE_SERVICE_KEY_FILE` :

```bash filename=".env"
# Path to the service account JSON key file
GOOGLE_SERVICE_KEY_FILE=/path/to/auth.json

# Or provide as a URL
GOOGLE_SERVICE_KEY_FILE=https://example.com/path/to/auth.json

# Or provide as stringified JSON
GOOGLE_SERVICE_KEY_FILE='{"type":"service_account","project_id":"your-project",...}'

# Or provide as base64 encoded JSON
GOOGLE_SERVICE_KEY_FILE=eyJ0eXBlIjogInNlcnZpY2VfYWNjb3VudCIsICJwcm9qZWN0X2lkIjogInlvdXItcHJvamVjdC1pZCIsIC4uLn0=
```

Ceci est particulièrement utile pour les fonctionnalités qui nécessitent une authentification Vertex AI, telles que les capacités OCR.

Vous pouvez également spécifier l'emplacement Google Cloud pour les requêtes de l'API Vertex AI :

```bash filename=".env"
# Google Cloud region for Vertex AI (defaults to us-central1)
# The multi-region locations us, eu, and global are also accepted.
GOOGLE_LOC=us-central1

# Alternative region for Gemini Image Generation (defaults to global)
GOOGLE_CLOUD_LOCATION=global
```

Puisque la récupération de la liste des modèles n'est pas encore prise en charge, vous devez définir les modèles que vous souhaitez utiliser dans le fichier .env.

Pour Vertex AI, utilisez les identifiants de modèle Vertex lorsqu'ils diffèrent de l'API Gemini :

```bash filename=".env"
GOOGLE_MODELS=gemini-4-argon,gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-pro-preview,gemini-3.1-pro-preview-customtools,gemini-3.1-flash-lite-preview,gemini-2.5-pro,gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash-001,gemini-2.0-flash-lite-001
```

Sur Vertex AI, `gemini-4-argon` n'est servi que depuis les points de terminaison multi-régionaux `global`, `us` et `eu`, et non depuis des emplacements régionaux tels que `us-central1`. Lorsque `GOOGLE_LOC` n'est pas défini, LibreChat utilise `global` pour ce modèle. Si `GOOGLE_LOC` est défini sur une région `us-` ou `europe-`, LibreChat redirige la requête vers la multi-région `us` ou `eu` afin que les données restent dans la même zone géographique. Une région située en dehors de `us` et `eu` est conservée telle que configurée, et la requête échouera à moins que vous ne définissiez `GOOGLE_LOC` sur `global`, `us` ou `eu`.

Les Agents enregistrés utilisant le fournisseur `vertexai` utilisent également ce catalogue de modèles Google partagé dans l'Agent Builder et lors de l'exécution. Si le déploiement fournit un catalogue de modèles `vertexai` explicite, cette liste spécifique au fournisseur prévaut ; sinon, `GOOGLE_MODELS` est utilisé pour la sélection et la validation de Vertex AI.

<Callout type="note" title="Si vous utilisez Docker">
If you're using docker and want to provide the `auth.json` file, you will need to also mount the volume in docker-compose.override.yml

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./api/data/auth.json
        target: /app/api/data/auth.json
```

</Callout>

## Paramètres de sécurité Google [#google-safety-settings]

Pour définir les paramètres de sécurité pour Vertex AI et Generative Language API, vous pouvez configurer les éléments suivants dans votre fichier .env :

```bash filename=".env"
GOOGLE_SAFETY_SEXUALLY_EXPLICIT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HATE_SPEECH=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_HARASSMENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_DANGEROUS_CONTENT=BLOCK_ONLY_HIGH
GOOGLE_SAFETY_CIVIC_INTEGRITY=BLOCK_ONLY_HIGH
```

Vous pouvez également exclure les paramètres de sécurité en définissant ce qui suit dans votre fichier .env, ce qui utilisera les paramètres par défaut du fournisseur. Cela peut être utile si vous rencontrez des problèmes avec des paramètres de sécurité spécifiques.

```bash filename=".env"
GOOGLE_EXCLUDE_SAFETY_SETTINGS=true
```

Les catégories que vous ne définissez pas sont envoyées avec le seuil `HARM_BLOCK_THRESHOLD_UNSPECIFIED`, ce qui conserve la valeur par défaut du fournisseur. L'exception est `GOOGLE_SAFETY_CIVIC_INTEGRITY`, qui vaut `BLOCK_NONE` par défaut lorsqu'elle n'est pas définie.

NOTE: Votre compte Google n'a pas accès par défaut au paramètre `BLOCK_NONE`, de sorte que les requêtes peuvent être rejetées si ce paramètre est envoyé (par exemple via la valeur par défaut de l'intégrité civique). Dans ce cas, définissez `GOOGLE_SAFETY_CIVIC_INTEGRITY` avec un autre seuil, ou définissez `GOOGLE_EXCLUDE_SAFETY_SETTINGS=true`.
Pour utiliser ce paramètre `HarmBlockThreshold` restreint, vous devez soit :

- (a) Obtenez l'accès via une liste d'autorisation (allowlist) par l'intermédiaire de votre équipe de compte Google
- (b) Basculez votre type de compte vers une facturation mensuelle sur facture en suivant ces instructions :
  https://cloud.google.com/billing/docs/how-to/invoiced-billing

**Notes :**

- L'endpoint Google prend en charge tous les [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) via le fichier de configuration `librechat.yaml`, y compris `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` et `titleEndpoint`.
