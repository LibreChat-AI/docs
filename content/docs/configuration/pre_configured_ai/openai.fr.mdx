Pour obtenir votre clé API OpenAI, vous devez :

- Allez sur **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)**
- Créez un compte ou connectez-vous avec votre compte existant
- Ajouter un moyen de paiement à votre compte
- Allez sur https://platform.openai.com/api-keys pour obtenir une clé.
- Vous devrez définir la variable d'environnement suivante avec votre clé, ou vous pouvez la définir sur `user_provided` pour permettre aux utilisateurs de fournir la leur.

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="Où les utilisateurs saisissent leur propre clé">

Avec `user_provided`, vous ne fournissez aucune clé : chaque utilisateur saisit la sienne depuis l'interface de chat. Ouvrez le menu endpoint, et à côté de **OpenAI**, vous trouverez une icône d'engrenage intitulée **Set API Key**. Cliquer dessus ouvre une boîte de dialogue avec un champ pour la clé et un menu déroulant pour définir sa durée de conservation : 30 minutes, 2 heures, 12 heures (la valeur par défaut), 1 jour, 7 jours, 30 jours, ou ne jamais expirer.

La clé est chiffrée et stockée côté serveur sur le compte de cet utilisateur ; elle est donc saisie une seule fois plutôt que par conversation, et n'est jamais partagée avec d'autres utilisateurs. La même boîte de dialogue dispose d'une action **Révoquer**, ainsi que de **Tout révoquer** pour effacer toutes les clés stockées par cet utilisateur.

Si le menu endpoint est masqué, par exemple parce qu'un Model Specs désactive `modelSelect`, la même boîte de dialogue est accessible depuis **Settings** sous **Data controls**, dans la section **API keys**.

Jusqu'à ce qu'un utilisateur définisse une clé, l'endpoint est visible mais inutilisable pour lui.

</Callout>

- Vous pouvez déterminer quels modèles vous souhaitez rendre disponibles avec `OPENAI_MODELS`
  - Lorsque `OPENAI_API_KEY` est défini sur `user_provided` → seuls les modèles inclus dans cette liste seront disponibles
    - ⚠️Les nouveaux modèles n'apparaîtront pas automatiquement ; vous devrez d'abord les ajouter à cette liste
  - Lorsque `OPENAI_API_KEY` est défini avec la valeur réelle de la clé API → tant que `OPENAI_MODELS` reste commenté, un appel API sera effectué pour découvrir quels modèles sont disponibles, ce qui devrait inclure tous les nouveaux modèles.

```bash filename=".env"
OPENAI_MODELS=gpt-6.1-sol,gpt-6-sol,gpt-6-luna,gpt-6-astra,gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**Notes :**

- GPT-6.1 Sol (`gpt-6.1-sol`) rejoint les catalogues par défaut canoniques d'OpenAI et des Agents, et non celui des Assistants. Jusqu'à ce que des entrées explicites soient ajoutées, il hérite des limites de contexte/sortie et de la tarification de GPT-6 Sol ; il s'agit de valeurs de repli pour la famille, et non d'une tarification de GPT-6.1 confirmée indépendamment.
- Les versions mineures de GPT sans entrée spécifique par version héritent des limites de contexte/sortie, de la tarification et des paramètres de raisonnement de leur famille reconnue. Les entrées explicites ont la priorité. Par exemple, `gpt-6.1-sol` ne revient plus au budget de contexte générique de 32K. Les versions mineures sans date sur OpenAI natif peuvent également hériter de la politique de réponses de la famille ; les instantanés datés conservent l'héritage de politique générique (wildcard), Azure reste spécifique au déploiement et les endpoints personnalisés ne sont pas commutés automatiquement.

- Les valeurs par défaut internes d'OpenAI incluent `gpt-6-astra` pour les endpoints canoniques OpenAI et Agents. LibreChat achemine chaque requête Astra via l'API Responses car ses appels d'outils sont limités aux Responses uniquement, supprime les paramètres d'échantillonnage non pris en charge et applique une fenêtre de contexte de 1 050 000 jetons avec une sortie maximale de 128 000 jetons. Astra est intentionnellement exclu des catalogues par défaut Assistants, Azure Assistants et Azure OpenAI.
- Les valeurs par défaut internes d'OpenAI incluent `gpt-5.6`, `gpt-5.6-terra` et `gpt-5.6-luna`, suivies du catalogue GPT-5 existant. `gpt-5.6` est l'alias du niveau Sol ; LibreChat attribue aux trois niveaux GPT-5.6 une fenêtre de contexte de 1 050 000 jetons et une sortie maximale de 128 000 jetons. Les valeurs par défaut héritées et obsolètes ne sont plus incluses, sauf si vous les ajoutez explicitement avec `OPENAI_MODELS`.
- GPT-5.6 prend en charge les valeurs `standard` et `pro` pour le paramètre `reasoning_mode` de l'API Responses, ainsi que les valeurs `auto`, `current_turn` et `all_turns` pour `reasoning_context`. Celles-ci peuvent être configurées dans les [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode).
- Pour un modèle GPT-5.6 avec un `reasoning_effort` différent de `none`, LibreChat utilise par défaut l'endpoint OpenAI canonique vers l'API Responses afin que les outils de fonction restent compatibles. Un `useResponsesApi: false` explicite maintient l'utilisation de Chat Completions. Azure OpenAI, OpenRouter, ainsi que les URLs de base personnalisées ou de reverse-proxy ne sont pas commutés automatiquement.
- Il n'est pas nécessaire de sélectionner un modèle de vision pour les messages avec pièces jointes, car le changement s'effectuera automatiquement en arrière-plan. Si vous n'avez pas explicitement sélectionné un modèle de vision, celui-ci sera utilisé uniquement pour la requête de vision et vous devriez toujours voir le modèle sans vision que vous aviez sélectionné une fois la requête terminée avec succès.
- Les modèles OpenAI Vision permettent des messages sans pièces jointes
- L'endpoint OpenAI prend en charge tous les [Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings) via le fichier de configuration `librechat.yaml`, y compris `streamRate`, `headers`, `titleModel`, `titleMethod`, `titlePrompt`, `titlePromptTemplate` et `titleEndpoint`.
