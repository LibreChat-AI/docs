### 일반 [#general]

LibreChat은 백엔드(api)에 중앙 집중식 로깅 기능이 내장되어 있습니다.

- **Docker** 설치 시, 로그 파일은 `/logs`에 저장됩니다.

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="logs" defaultOpen>
      <FileTree.File name="debug-2024-01-01.log" active />
      <FileTree.File name="error-2024-01-01.log" active />
      <FileTree.File name="meiliSync-2024-01-01.log" active />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

- **npm** 설치 시, 로그 파일은 `/api/logs`에 저장됩니다.

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="api" defaultOpen>
      <FileTree.Folder name="logs" defaultOpen>
        <FileTree.File name="debug-2024-01-01.log" active />
        <FileTree.File name="error-2024-01-01.log" active />
        <FileTree.File name="meiliSync-2024-01-01.log" active />
      </FileTree.Folder>
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

기본적으로 오류 로그는 저장됩니다. 디버그 로그 파일은 `DEBUG_LOGGING=true`일 때만 기록되며, 제공되는 `.env.example`은 이 값을 `true`로 설정합니다. 하지만 변수가 설정되지 않은 경우에는 디버그 파일이 생성되지 않습니다.

이를 통해 **[the ELK stack](https://aws.amazon.com/what-is/elk-stack/)**과 같이 로그 파일을 검사하는 외부 도구를 사용하여 서버를 모니터링할 수 있습니다.

디버그 로그는 개발 작업과 문제 해결에 필수적입니다. LibreChat을 실행하는 동안 문제가 발생하면, 가능한 한 동일한 상황을 재현한 뒤 `./api/logs/debug-%DATE%.log`에서 찾을 수 있는 로그와 함께 **[이슈를 보고](https://github.com/LibreChat-AI/LibreChat/issues)**해 주시기 바랍니다.

오류 로그 또한 동일한 위치인 `./api/logs/error-%DATE%.log`에 저장됩니다. Meilisearch를 구성한 경우, 이를 위한 별도의 로그 파일도 생성됩니다.

<Callout type="note" title="참고:">
  로그 파일은 매일 교체됩니다. 하루가 지날 때마다 새 파일이 시작되며, 파일 크기가 20 MB에 도달하면 해당 파일도 분할됩니다. 교체된 파일은 gzip으로 압축되어 14일 동안 보관됩니다. 오류는 디버그 로그 파일에도 기록되지만, 오류 로그 파일에는 스택 트레이스와 더 자세한 정보가 포함되어 있습니다.
</Callout>

### 설정 [#setup]

- 디버그 로그 파일은 이 변수가 `true`로 설정된 경우에만 기록됩니다. 변수가 설정되지 않았거나 다른 값으로 설정된 경우에는 디버그 파일이 생성되지 않습니다.

<OptionTable
  options={[['DEBUG_LOGGING', 'boolean', '디버그 로그를 파일에 기록합니다. 디버그 로그 파일이 생성되려면 필수입니다.', 'DEBUG_LOGGING=true']]}
/>

> 참고: 프로덕션 환경에서는 디버그 로그를 비활성화해 두는 것을 권장합니다.

- 콘솔/터미널에서 상세한 서버 출력을 확인하려면 다음을 `TRUE`로 설정할 수 있습니다:

<OptionTable
  options={[
    [
      'DEBUG_CONSOLE',
      'boolean',
      '파일 디버그 로그와 동일한 형식으로 상세 콘솔/stdout 로그를 활성화합니다.',
      'DEBUG_CONSOLE=false',
    ],
  ]}
/>

하지만 출력값이 매우 장황해질 수 있으므로 권장되지 않습니다. 기본적으로 비활성화되어 있으며 꼭 필요한 경우에만 활성화해야 합니다.

- 클라우드 배포(GCP 또는 AWS 등)에서 콘솔 로그를 처리할 때, 이 옵션을 활성화하면 UTC 타임스탬프와 함께 로그를 JSON 형식으로 덤프합니다.

<OptionTable
  options={[
    [
      'CONSOLE_JSON',
      'boolean',
      'GCP/AWS와 같은 클라우드 배포에 적합한 상세 JSON 콘솔/stdout 로그를 활성화합니다.',
      'CONSOLE_JSON=false',
    ],
  ]}
/>

기본적으로 JSON 문자열 길이는 255자로 잘립니다. 다음 환경 변수를 사용하여 이를 구성할 수 있습니다:

<OptionTable
  options={[
    [
      'CONSOLE_JSON_STRING_LENGTH',
      'number',
      'JSON 콘솔/stdout 로그의 문자열 값에 대한 잘림 크기를 설정합니다. 기본값: 255.',
      '# CONSOLE_JSON_STRING_LENGTH=255',
    ],
  ]}
/>

- 콘솔 출력의 상세 수준은 `CONSOLE_LOG_LEVEL`로 설정할 수 있습니다 (`error`, `warn`, `info`, `http`, `verbose`, `debug`, `activity`, `silly`, 또는 `silent`). `silent`은 파일 로깅을 비활성화하지 않고 콘솔 출력만 끕니다. 잘못된 값은 경고와 함께 기본값으로 대체됩니다.

<OptionTable
  options={[
    [
      'CONSOLE_LOG_LEVEL',
      'string',
      '콘솔 출력 수준. 기본값은 info이며, DEBUG_CONSOLE=true이면 debug가 됩니다. 명시적으로 설정된 값이 우선합니다.',
      '# CONSOLE_LOG_LEVEL=info',
    ],
  ]}
/>

- 디버그 로그 메시지는 기본적으로 150자로 잘리며, 로그 마스킹(redaction)은 레코드당 5000개의 값으로 제한됩니다. 이 값들은 `DEBUG_MESSAGE_LENGTH`와 `LOG_REDACTION_MAX_NODES`로 조정할 수 있습니다.

<OptionTable
  options={[
    [
      'DEBUG_MESSAGE_LENGTH',
      'number',
      '디버그 로그 메시지가 잘리기 전의 최대 길이입니다. 기본값: 150.',
      '# DEBUG_MESSAGE_LENGTH=150',
    ],
    [
      'LOG_REDACTION_MAX_NODES',
      'number',
      '한 로그 레코드에서 마스킹할 수 있는 최대 값 개수입니다. 이 개수를 초과하는 나머지 값은 대체됩니다. 기본값: 5000.',
      '# LOG_REDACTION_MAX_NODES=5000',
    ],
  ]}
/>

- 기본 위치가 아닌 다른 곳에 로그 파일을 기록하려면 `LIBRECHAT_LOG_DIR`을 설정하세요. 자세한 내용은 `.env` 참조 문서의 [Logging](/docs/configuration/dotenv#logging)을 확인하세요.

- 파일 기반 로그 전송은 기본적으로 활성화되어 있습니다. 배포 시 로그를 stdout/stderr로만 출력하려면 `LOG_TO_FILE=false`로 설정하세요.

  options={[
    [
      'LOG_TO_FILE',
      'boolean',
      'file-backed Winston 전송을 비활성화하려면 false로 설정하세요.',
      'LOG_TO_FILE=true',
    ],
  ]}
/>

### OpenTelemetry Tracing [#opentelemetry-tracing]

LibreChat은 서버, 데이터베이스, Redis 및 아웃바운드 HTTP 가시성을 위한 백엔드 OpenTelemetry 추적을 내보낼 수 있습니다. Redis 명령 수준 스팬(span)은 선택 사항이므로 기본 추적은 상위 수준으로 유지됩니다. 이는 GenAI 관련 프롬프트 및 모델 관측 가능성을 위해 권장되는 옵션인 Langfuse와는 별개입니다.
