Willkommen zum umfassenden Leitfaden für die Konfiguration der Umgebung Ihrer Anwendung mit der `.env` Datei. Dieses Dokument ist Ihre zentrale Anlaufstelle, um die Umgebungsvariablen zu verstehen und anzupassen, die das Verhalten Ihrer Anwendung in verschiedenen Kontexten bestimmen.

Während die Standardeinstellungen eine solide Grundlage für eine normale `docker`-Installation bieten, wird Ihnen diese Anleitung das volle Potenzial von LibreChat erschließen. Dieser Leitfaden ermöglicht es Ihnen, LibreChat genau an Ihre Bedürfnisse anzupassen. Entdecken Sie, wie Sie die Verfügbarkeit von Sprachmodellen anpassen, soziale Logins integrieren, das automatische Moderationssystem verwalten und vieles mehr. Es geht darum, Ihnen die Kontrolle zu geben, LibreChat für eine optimale Benutzererfahrung fein abzustimmen.

> **Hinweis: Bitte starten Sie LibreChat neu, damit die Konfigurationsänderungen wirksam werden.**

Alternativ können Sie eine neue Datei namens `docker-compose.override.yml` im selben Verzeichnis wie Ihre Hauptdatei `docker-compose.yml` für LibreChat erstellen, in der Sie Ihre .env-Variablen nach Bedarf unter `environment` festlegen oder die Standardkonfiguration der Hauptdatei `docker-compose.yml` ändern können, ohne die gesamte Datei direkt bearbeiten oder duplizieren zu müssen.

### HTTP-Server-Timeouts [#http-server-timeouts]

Diese optionalen Werte konfigurieren den Node.js HTTP-Server. Lassen Sie sie nicht gesetzt, um die Standardwerte von Node beizubehalten. Ein Wert von `0` deaktiviert das entsprechende Timeout.

<OptionTable
  options={[
    [
      'HTTP_KEEP_ALIVE_TIMEOUT_MS',
      'integer',
      'Leerlauf-Keep-Alive-Timeout in Millisekunden. Setzen Sie diesen Wert höher als den Leerlauf-Timeout des Load Balancers, um zu vermeiden, dass wiederverwendete Verbindungen mit dem Schließen des Servers kollidieren. Node-Standard: 5000.',
      '# HTTP_KEEP_ALIVE_TIMEOUT_MS=70000',
    ],
    [
      'HTTP_KEEP_ALIVE_TIMEOUT_BUFFER_MS',
      'integer',
      'Zusätzlicher Socket-Timeout-Puffer in Millisekunden. Node-Standard: 1000.',
      '# HTTP_KEEP_ALIVE_TIMEOUT_BUFFER_MS=5000',
    ],
    [
      'HTTP_HEADERS_TIMEOUT_MS',
      'integer',
      'Zeitlimit für den Empfang vollständiger Anfrage-Header. Node-Standard: 60000.',
      '# HTTP_HEADERS_TIMEOUT_MS=80000',
    ],
    [
      'HTTP_REQUEST_TIMEOUT_MS',
      'integer',
      'Zeitlimit für den Empfang der vollständigen Anfrage. Node-Standard: 300000.',
      '# HTTP_REQUEST_TIMEOUT_MS=300000',
    ],
  ]}
/>

Werte müssen nicht-negative, sichere Ganzzahlen sein; ungültige Werte werden ignoriert. Wenn sowohl Header- als auch Request-Timeouts aktiviert sind, begrenzt LibreChat das Header-Timeout auf das Request-Timeout, falls dieses höher ist. Node überprüft den Ablauf von Headern und Requests bei einem Verbindungs-Sweep alle 30 Sekunden, daher werden Werte unter `30000` nicht mit exakter Millisekunden-Präzision durchgesetzt. Bun akzeptiert diese Einstellungen derzeit, setzt sie jedoch nicht durch; LibreChat protokolliert eine Warnung, wenn der API-Server unter Bun ausgeführt wird.

### Trust proxy [#trust-proxy]

Verwenden Sie die Adresse, die höchstens n Hops von der Express-Anwendung entfernt ist.
req.socket.remoteAddress ist der erste Hop, und die restlichen werden im X-Forwarded-For-Header von rechts nach links gesucht.
Ein Wert von 0 bedeutet, dass die erste nicht vertrauenswürdige Adresse req.socket.remoteAddress wäre, d. h. es gibt keinen Reverse-Proxy.
Der Standardwert der Umgebungsvariablen `TRUST_PROXY` ist auf `1` gesetzt.

Weitere Informationen hierzu finden Sie unter [Express.js - trust proxy](https://expressjs.com/en/guide/behind-proxies.html).

<OptionTable
  options={[['TRUST_PROXY', 'number', 'Gibt die Anzahl der Hops an.', 'TRUST_PROXY=1']]}
/>

### Trusted Tenant Header [#trusted-tenant-header]

`TRUST_TENANT_HEADER` steuert, ob LibreChat den `X-Tenant-Id`-Header vor der Authentifizierung auf den Routen-Bäumen `/oauth`, `/api/auth` und `/api/share` akzeptiert. Diese Funktion ist standardmäßig deaktiviert; solange sie deaktiviert ist, ignorieren diese Routen den Header.

<OptionTable
  options={[
    [
      'TRUST_TENANT_HEADER',
      'boolean',
      'Vertraue der X-Tenant-Id auf Pre-Authentifizierungs-Routen. Nur hinter einem vertrauenswürdigen Proxy aktivieren, der vom Client bereitgestellte Werte ersetzt.',
      'TRUST_TENANT_HEADER=false',
    ],
  ]}
/>

<Callout type="warning" title="Vertrauen Sie keinen vom Client bereitgestellten Tenant-Headern">
  Aktivieren Sie diese Einstellung nur, wenn ein vertrauenswürdiger Reverse-Proxy jeden eingehenden `X-Tenant-Id`-Wert entfernt und die maßgebliche Tenant-ID selbst setzt. Andernfalls könnte ein nicht vertrauenswürdiger Client den vor der Authentifizierung verwendeten Tenant-Kontext wählen. LibreChat protokolliert eine Sicherheitswarnung, wenn diese Einstellung aktiviert ist.
</Callout>

Wenn `TENANT_ISOLATION_STRICT` aktiviert, aber `TRUST_TENANT_HEADER` deaktiviert ist, warnt LibreChat beim Start, dass Pre-Authentication-Tenant-Header ignoriert werden.

### Anmeldedaten-Konfiguration [#credentials-configuration]

LibreChat verwendet `CREDS_KEY` und `CREDS_IV`, um unterstützte Anmeldedaten, die in der Datenbank gespeichert sind, zu verschlüsseln. Konfigurieren Sie feste, eindeutige Werte für die Produktion und verwenden Sie dieselben Werte für jedes Replikat.

<OptionTable
  options={[
    [
      'CREDS_KEY',
      'string',
      '32-Byte-Schlüssel (64 hexadezimale Zeichen) zur sicheren Speicherung von Anmeldedaten.',
      'CREDS_KEY=',
    ],
    [
      'CREDS_IV',
      'string',
      '16-Byte-IV (32 hexadezimale Zeichen) zur sicheren Speicherung von Anmeldedaten.',
      'CREDS_IV=',
    ],
    [
      'LIBRECHAT_TEMP_CREDENTIALS_PATH',
      'string',
      'Pfad, der zum Speichern automatisch generierter temporärer Anmeldedaten verwendet wird. Standardmäßig `.env.temp` im Arbeitsverzeichnis des Prozesses.',
      '# LIBRECHAT_TEMP_CREDENTIALS_PATH=/app/data/.env.temp',
    ],
  ]}
/>

Wenn einer der Werte `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET` oder `JWT_REFRESH_SECRET` leer ist, verwendet LibreChat zunächst einen gültigen Wert aus der temporären Anmeldedatei. Falls keiner existiert, generiert es einen kryptografisch zufälligen Wert und schreibt die Datei mit Berechtigungen, die nur dem Eigentümer zugänglich sind. Explizite Umgebungswerte haben immer Vorrang. LibreChat verweigert die Verwendung von `.env` oder `.env.example` als Pfad für die generierte Datei, um ein versehentliches Ersetzen einer der beiden Konfigurationsdateien zu verhindern.

LibreChat verweigert ebenfalls den Start, wenn `JWT_SECRET` oder `JWT_REFRESH_SECRET` noch einen der zurückgezogenen veröffentlichten Standardwerte verwendet, unabhängig davon, ob der Wert aus der Umgebung oder der temporären Anmeldedatei stammt. Generieren Sie eindeutige Ersatzwerte, anstatt alte Beispiel-Secrets in eine Bereitstellung zu übernehmen.

Die mitgelieferten Docker Compose-Dateien speichern `/app/data/.env.temp` dauerhaft im `librechat-data`-Volume, sodass eine einzelne Compose-Bereitstellung neu gestartet werden kann, ohne dass sich diese generierten Werte ändern. Wenn die Datei nicht dauerhaft gespeichert werden kann, sind die Werte prozesslokal und Sitzungen oder verschlüsselte Datensätze könnten nach einem Neustart unzugänglich werden.

<Callout type="warning" title="Permanente Werte für die Produktion festlegen">
  Die temporäre Generierung ist eine Bootstrap-Annehmlichkeit, kein System zur Rotation von Anmeldedaten. Generieren Sie vor dem produktiven Einsatz permanente Werte mit dem [Credentials Generator](/toolkit/creds_generator), speichern Sie diese in Ihrem Secret-Manager und stellen Sie jedem Replikat dieselben Werte bereit. Das Ändern eines etablierten Schlüssels führt nicht zu einer erneuten Verschlüsselung bestehender Datensätze. LibreChat speichert Fingerabdrücke von Anmeldedaten in der Datenbank und warnt, wenn aktive Werte abweichen; überschreiben Sie diese Markierung nicht, anstatt eine kontrollierte Migration durchzuführen.
</Callout>

### Sicherheits-Header und Content Security Policy [#security-headers-and-content-security-policy]

LibreChat sendet standardmäßig grundlegende HSTS-, Framing-, Content-Type-, Opener-, Resource- und Referrer-Header. `SECURITY_HEADERS=false` deaktiviert diese alle und fungiert zudem als globaler Kill-Switch für die CSP.

Nonce-basiertes CSP ist separat über `CSP_ENABLED=true` opt-in und standardmäßig im Report-Only-Modus. Beginnen Sie mit `CSP_REPORT_ONLY=true`, untersuchen Sie Verstöße und fügen Sie nur die Ursprünge hinzu, die Ihre Bereitstellung erfordert, bevor Sie die Durchsetzung aktivieren. Wenn CSP aktiv ist, wird die SPA-Shell immer mit `Cache-Control: no-store` gesendet, sodass ihr Nonce pro Antwort nicht aus dem Cache wiederverwendet werden kann.

Siehe [HTTP Security Headers](/docs/configuration/security_headers) für alle Basis- und CSP-Variablen, akzeptierte Werte, Standardwerte, Source-List-Overrides und Anleitungen zur Einführung.

      'ENABLE_IMAGE_OUTPUT_GZIP_SCAN=true',
    ],
    [
      'ENABLE_STATIC_ASSET_BROTLI',
      'boolean',
      'Ermöglicht die Bereitstellung vorkomprimierter Brotli-Versionen statischer App-Assets, sofern verfügbar.',
      'ENABLE_STATIC_ASSET_BROTLI=true',
    ],
  ]}
/>

**Verhalten:**

Legt die [Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Cache-Control)-Header für statische Dateien fest. Diese Konfigurationen werden nur ausgelöst, wenn `NODE_ENV` auf `production` gesetzt ist.

- Entkommentieren Sie `STATIC_CACHE_MAX_AGE`, um das lokale `max-age` für statische Dateien zu ändern. Standardmäßig ist dies auf 2 Tage (172800 Sekunden) eingestellt.
- Entkommentieren Sie `STATIC_CACHE_S_MAX_AGE`, um das `s-maxage` für gemeinsam genutzte Caches (CDNs und Proxys) festzulegen. Standardmäßig ist dies auf 1 Tag (86400 Sekunden) eingestellt.
- Entkommentieren Sie `DISABLE_COMPRESSION`, um die Komprimierung für statische Dateien zu deaktivieren. Standardmäßig ist die Komprimierung aktiviert.
- Entkommentieren Sie `ENABLE_IMAGE_OUTPUT_GZIP_SCAN`, um das Scannen und Bereitstellen von gzipped-Versionen von Bildern zu aktivieren, sofern diese im selben Ordner mit demselben Namen und einer .gz-Erweiterung vorkomprimiert wurden. Standardmäßig ist der gzip-Scan für hochgeladene Bilder deaktiviert.
- Entkommentieren Sie `ENABLE_STATIC_ASSET_BROTLI`, um vorkomprimierte `.br`-Versionen statischer App-Assets bereitzustellen, sofern diese vorhanden sind. Wenn diese Option aktiviert ist, wird Brotli gegenüber gzip für über die API bereitgestellte statische Dateien bevorzugt.

<Callout type="warning" title="Warnung">
  - Dies betrifft nur statische Dateien, die vom API-Server bereitgestellt werden, und ist nicht auf _Firebase_, _NGINX_ oder andere Konfigurationen anwendbar.
</Callout>

**Verhalten:**

Steuert Caching-Header speziell für die index.html-Antwort. Standardmäßig verhindern diese Einstellungen das Caching, um sicherzustellen, dass Benutzer immer die neueste Version der Anwendung erhalten.

<Callout type="note" title="Hinweis">
  Im Gegensatz zu statischen Assets, die zur Leistungsoptimierung zwischengespeichert werden, sind die Cache-Header der index.html-Datei separat konfiguriert, um sicherzustellen, dass Benutzer immer die neueste Anwendungsoberfläche (Application Shell) erhalten.
</Callout>

### Verhindern, dass öffentliche Suchmaschinen indexieren [#prevent-public-search-engines-indexing]

Standardmäßig wird Ihre Website nicht von öffentlichen Suchmaschinen (z. B. Google, Bing, …) indexiert. Das bedeutet, dass Personen Ihre Website nicht über diese Suchmaschinen finden können. Wenn Sie Ihre Website sichtbarer und durchsuchbarer machen möchten, können Sie die folgende Einstellung auf `false` ändern.

<OptionTable
  options={[
    [
      'NO_INDEX',
      'boolean',
      'Verhindert, dass öffentliche Suchmaschinen Ihre Website indexieren.',
      'NO_INDEX=true',
    ],
  ]}
/>

❗**Hinweis:** Es gibt keine Garantie, dass diese Methode für alle Suchmaschinen funktioniert. Einige Suchmaschinen könnten Ihre Website oder Webseite dennoch für andere Zwecke indexieren, wie etwa zum Caching oder Archivieren. Daher sollten Sie sich nicht allein auf diese Methode verlassen, um sensible oder vertrauliche Informationen auf Ihrer Website oder Webseite zu schützen.

### Stateful Code Interpreter Endpoint [#stateful-code-interpreter-endpoint]

[`stateful_code_sessions`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) ist hochgradig experimentell und erfordert eine separate Code Interpreter-Route. Konfigurieren Sie die Standard-Route mit `LIBRECHAT_CODE_BASEURL_STATEFUL` oder definieren Sie benannte verwaltete oder angehängte Backends unter [`endpoints.agents.statefulCodeSessions.environments`](/docs/configuration/librechat_yaml/object_structure/agents#statefulcodesessions). Der ausgewählte Dienst muss das `stateful`-Profil ausführen; LibreChat sendet bei zustandsbehafteten Anfragen `X-CodeAPI-Expected-Profile: stateful` mit.

Stateful-Anfragen greifen niemals auf `LIBRECHAT_CODE_BASEURL` zurück. Wenn die ausgewählte benannte Umgebung nicht verfügbar ist oder weder ein benannter Standardwert noch `LIBRECHAT_CODE_BASEURL_STATEFUL` konfiguriert ist, stoppt LibreChat die Agent-Ausführung mit einem Konfigurationsfehler. Stateless-Agenten verwenden weiterhin `LIBRECHAT_CODE_BASEURL`, und die beiden Ausführungsprofile teilen sich keinen aktiven Arbeitsbereich.

Jeder Agent kann seinen zustandsbehafteten Arbeitsbereich auf den angemeldeten Benutzer, den Benutzer und den Agenten gemeinsam oder auf den Benutzer und das Gespräch beschränken. Siehe [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions) für Informationen zur Einrichtung und zu Einschränkungen bei der Persistenz.

Benannte angehängte Umgebungen können auch eine Self-Service-Pairing-Steuerungsebene mit `pairing.allowPrincipalWorkers: true` bereitstellen. Autorisierte Benutzer verwalten diese besitzergebundenen Worker unter **Einstellungen > Code-Umgebungen**; Einträge, die nur für das Pairing vorgesehen sind, ersetzen nicht `LIBRECHAT_CODE_BASEURL_STATEFUL` und können nicht als Standard für die Bereitstellung dienen.

Gebundene untergeordnete Fortsetzungen (child continuations), losgelöste übergeordnete Subagent-Fortsetzungen und der Abschluss losgelöster Event-Actor-Aktionen erfolgen automatisch. Die veralteten Variablen `ENABLE_AGENT_EVENT_CHILD_TURNS`, `ENABLE_SUBAGENT_COMPLETION_WAKEUPS` und `AGENT_TRIGGERS_DETACHED_ACTIONS_PRODUCER_ENABLED` werden nicht mehr gelesen.

Der In-Memory-Generierungsspeicher unterstützt prozesslokale, vom Event-Actor entkoppelte Vervollständigungen, solange der Prozess aktiv bleibt. Redis-Generierungs-Streams fügen eine dauerhafte Neustart-Wiederherstellung sowie eine Replikat-Übergabe hinzu. Siehe [Generation Protocol Compatibility](/docs/configuration/redis#generation-protocol-compatibility) vor einer Bereitstellung mit gemischten Versionen.

LibreChat stellt eine authentifizierte Agent Events API bereit; es wird kein nicht authentifizierter Webhook bereitgestellt. Die Identität über API-Schlüssel, Berechtigungen für Remote Agents, Zielzugriff, Idempotenz und das dedizierte Ratenlimit für Agent Events schützen den Eingang. Auf MongoDB basierende Warteschlangen, Akteur-Postfächer, Empfangsbestätigungen, Leases, Wiederholungsversuche und Dead-Letter-Queues unterstützen Worker über Replikate hinweg. Siehe [Agent Event Delivery](/docs/features/agents#agent-event-delivery) und [Agents API - Agent Events](/docs/features/agents_api#agent-events) für Verhalten und Beispiele.

#### Guthaben verwalten [#managing-balances]

- Führen Sie `npm run add-balance` aus, um Guthaben manuell hinzuzufügen.
  - Sie können auch die E-Mail-Adresse und den Token-Guthabenbetrag angeben, der hinzugefügt werden soll, z. B.: `npm run add-balance example@example.com 1000`
- Führen Sie `npm run set-balance` aus, um Guthaben manuell festzulegen, ähnlich wie bei `add-balance`.
- Führen Sie `npm run list-balances` aus, um das Guthaben jedes Benutzers aufzulisten.

> **Hinweis:** 1000 Credits = $0,001 (1 Mill USD)

Hinweise:

- Wenn `USE_REDIS=true` gesetzt ist, müssen Sie `REDIS_URI` angeben, andernfalls wird die Anwendung einen Fehler ausgeben.
- Aktuelle LibreChat-Clients verhandeln das Generation-Protokoll v2 automatisch. Die veraltete Variable `GENERATION_PROTOCOL_VERSION` wird nicht mehr gelesen. Siehe [Generation Protocol Compatibility](/docs/configuration/redis#generation-protocol-compatibility), bevor Sie Release-Versionen mischen oder ein Rollback durchführen.
- Aktivieren Sie `STREAM_DELTA_COALESCE_MS` erst, nachdem jedes Replikat Batch-Frames unterstützt. Ältere Abonnenten verwerfen zusammengeführte Frames. Siehe [Stream Delta Coalescing](/docs/configuration/redis#stream-delta-coalescing).
- Für den Redis-Cluster-Modus geben Sie mehrere URIs an: `redis://node1:7001,redis://node2:7002,redis://node3:7003` (der Clustermodus wird automatisch erkannt).
- Für verwaltete Redis-Dienste mit einem einzelnen Endpoint, die Keys intern sharden, behalten Sie `USE_REDIS_CLUSTER=false` bei und setzen Sie `REDIS_CLUSTER_SAFE_DELETE=true`, falls Cache-Löschungen mit `CROSSSLOT`-Fehlern fehlschlagen.
- `REDIS_READONLY_RECOVERY_INTERVAL` entprellt Keyv-Wiederverbindungsversuche, nachdem ein Failover einen offenen Socket hinterlässt, der an ein herabgestuftes schreibgeschütztes Replikat gebunden ist. Redis Cluster-Clients verwenden stattdessen ihre native Topologie-Verwaltung.
- `REDIS_PING_INTERVAL` steuert den optionalen Heartbeat auf dem ioredis-Hauptclient; dedizierte Pub/Sub-Abonnenten verwenden `REDIS_SUBSCRIBER_PING_INTERVAL`, damit ein ansonsten inaktiver, toter Socket erkannt wird. Beide verwenden `REDIS_PING_TIMEOUT` als Antwortfrist und stellen die Verbindung wieder her, wenn diese abläuft.
- Verwenden Sie das `rediss://`-Protokoll für TLS-Verbindungen und setzen Sie `REDIS_CA`, falls Ihre CA nicht öffentlich vertrauenswürdig ist.
- `REDIS_KEY_PREFIX_VAR` und `REDIS_KEY_PREFIX` schließen sich gegenseitig aus.
- **AWS Elasticache mit TLS**: Elasticache erfordert möglicherweise ein alternatives dnsLookup für TLS-Verbindungen. Setzen Sie `REDIS_USE_ALTERNATIVE_DNS_LOOKUP=true`, wenn Sie Elasticache mit TLS verwenden. Weitere Details finden Sie in der [ioredis documentation](https://www.npmjs.com/package/ioredis).
