Meilisearchは、LibreChatの会話検索を強化するオープンソースの検索エンジンであり、過去の会話全体に対する全文検索、あいまい検索（typo tolerance）、およびインスタント検索機能を追加します。機能の概要については、[Search in LibreChat](/docs/features/search) を参照してください。

<Callout type="info" title="接続方法">
LibreChatは、いくつかの環境変数を使用してHTTP経由でMeilisearchと通信します。Dockerセットアップでは、Meilisearchがサービスとして同梱されています。ソースインストールでは、自身で実行するMeilisearchプロセスに対してLibreChatを設定します。
</Callout>

## Meilisearch の設定 [#configure-meilisearch]

<Tabs items={['Docker', 'npm']}>
<Tabs.Tab value="Docker">

デフォルトの `docker-compose.yml` にはすでに `meilisearch` サービスが含まれているため、検索を有効にして `.env` ファイルにマスターキーを設定するだけで済みます。

<Steps>
<Step>

**マスターキーを生成します。** 十分な長さのランダムな文字列（16バイト以上）を使用してください。例：

```bash filename="terminal"
openssl rand -base64 32
```

</Step>
<Step>

**`.env` に検索用の変数を追加します。** Compose ファイルでは `MEILI_HOST` が `api` コンテナの内部サービスアドレスに設定されているため、ここでホストを設定する必要はありません。同梱の `meilisearch` サービスはこの同じファイルから `MEILI_MASTER_KEY` を読み込むため、オーバーライドなしで LibreChat と Meilisearch が同じキーを使用します。

```bash filename=".env"
SEARCH=true
MEILI_NO_ANALYTICS=true
MEILI_MASTER_KEY=<your_master_key>
```

</Step>
<Step>

**スタックを起動します。** Compose が LibreChat と一緒に Meilisearch を起動します。

```bash filename="terminal"
docker compose up -d
```

</Step>
</Steps>

<Callout type="warning" title="ポートを内部に維持する">
コンテナは内部の Docker ネットワーク経由で Meilisearch に到達するため、ポート `7700` をホストに公開する必要はありません。公開すると、検索データが脆弱になる可能性があります。
</Callout>

</Tabs.Tab>
<Tabs.Tab value="npm">

ソースからLibreChatを実行する場合は、Meilisearchバイナリを別のプロセスとして実行し、LibreChatからそのプロセスを指定してください。

<Steps>
<Step>

**Meilisearchをダウンロードします。** [Meilisearch releases page](https://github.com/meilisearch/meilisearch/releases) から、お使いのオペレーティングシステム用の最新リリースを取得してください。例として、`meilisearch-linux-amd64.tar.gz` (Linux)、`meilisearch-macos-amd64` (macOS)、または `meilisearch-windows-amd64.zip` (Windows) などがあります。任意のディレクトリに展開してください。パッケージマネージャーを使用したインストールについては、[Meilisearch installation guide](https://www.meilisearch.com/docs/learn/getting_started/installation) を参照してください。

</Step>
<Step>

**バイナリを実行可能にします (Linux/macOS)。** 抽出先のディレクトリから、以下を実行してください：

```bash filename="terminal"
chmod +x meilisearch
```

</Step>
<Step>

**マスターキーを生成します。** Meilisearchは自動的に生成することができます：

```bash filename="terminal"
./meilisearch --generate-master-key
```

生成されたキーをコピーしてください。次のステップで再利用します。

</Step>
<Step>

**Meilisearchを起動します。** マスターキーを指定して実行してください。デフォルトではポート `7700` でリッスンします。

```bash filename="terminal"
./meilisearch --master-key=<your_master_key>
```

</Step>
<Step>

**Add the search variables to `.env`.** Point `MEILI_HOST` at the Meilisearch process and use the same master key you set above.

```bash filename=".env"
SEARCH=true
MEILI_NO_ANALYTICS=true
MEILI_HOST=http://localhost:7700
MEILI_MASTER_KEY=<your_master_key>
```

</Step>
<Step>

**LibreChatを起動します。** アプリを起動または再起動して、新しい設定を反映させます。

```bash filename="terminal"
npm run backend
```

</Step>
</Steps>

<Callout type="info" title="Meilisearchを起動し続ける">
会話検索はMeilisearchが実行されている間のみ機能します。再起動後も継続して動作するように、マネージドサービスまたはコンテナとして実行してください。
</Callout>

</Tabs.Tab>
</Tabs>

設定が完了すると、LibreChatは会話やメッセージをMeilisearchにインデックスし、検索バーからタイプミスを許容する全文検索結果が返されるようになります。

### v0.8.8-rc2 以降の再インデックス作成 [#reindexing-after-v088-rc2]

LibreChat v0.8.8-rc2 では、会話およびメッセージに内部的なインデックス投影バージョンが追加されました。アップグレード後の最初の同期時に、現在のマーカーを持たない既存のドキュメントは古いものとして扱われ、自動的に再インデックス化されます。これにより、メッセージベースのサイドバー結果を含む新しい検索可能なフィールドが Meilisearch に反映されます。

この移行に手動のリセットは必要ありません。大規模なインストール環境では、古いドキュメントが処理される間、MongoDB、Meilisearch、およびindexing-workerの負荷が一時的に上昇する可能性があります。マルチノード環境でデプロイしている場合は、以下に説明するように、1つのLibreChatノードでのみ同期を有効にしてください。

## 環境変数 [#environment-variables]

| 変数 | 説明 |
| --- | --- |
| `SEARCH` | 会話検索機能を有効にします。`true` に設定してください。 |
| `MEILI_HOST` | LibreChatがMeilisearchに接続するためのURLです。Dockerでは `http://meilisearch:7700` （Composeで設定）となり、ソースから実行する場合は通常 `http://localhost:7700` となります。 |
| `MEILI_MASTER_KEY` | Meilisearchとの認証に使用される共有シークレットです。Meilisearchの起動時に指定したキーと一致させる必要があります。 |
| `MEILI_NO_ANALYTICS` | Meilisearchの匿名テレメトリを無効にします。`true` に設定してください。 |
| `MEILI_NO_SYNC` | [マルチノードセットアップでの同期無効化](#disable-sync-in-a-multi-node-setup) を参照してください。 |

## 検索結果の上限 [#search-result-limits]

各検索では、Meilisearch に最大 1,000 件のヒットを要求します。これは Meilisearch のデフォルトの `pagination.maxTotalHits` です。サイドバーの検索は、チャット一覧を読み込む前に、会話インデックス(タイトルとタグ)とメッセージインデックスの両方からの一致を組み合わせます。そのため、非常に一般的な単語では、表示される件数より多くの会話が一致する場合があります。Meilisearch インデックスの `maxTotalHits` を引き上げても、LibreChat が使用する 1,000 件のヒット要求サイズは増えません。

## マルチノード構成で同期を無効にする [#disable-sync-in-a-multi-node-setup]

LibreChatをノードクラスターまたはマルチノードデプロイメントとして実行する場合は、1つのインスタンスで同期を有効にしたまま、他のすべてのインスタンスで `MEILI_NO_SYNC=true` を設定してください。これにより、ノード間での冗長なインデックス作成作業を防ぐことができます。

```bash filename=".env"
MEILI_NO_SYNC=true
```

## 同期の再設定 [#reset-synchronization]

Meilisearchのデータが削除または破損した場合、あるいはLibreChatが実際には同期されていないにもかかわらずすべて同期済みとして扱う場合（Meilisearchのアップグレード後やデータファイルの削除後など）、リセットスクリプトを使用して強制的に完全再同期を行ってください。これによりMongoDB内の同期フラグがリセットされ、次回の起動時または同期チェック時にLibreChatがすべての会話とメッセージを再インデックスするようになります。

<Steps>
<Step>

**リセットスクリプトを実行します。** セットアップ環境に一致するコマンドを使用してください。

```bash filename="terminal"
# Local development
npm run reset-meili-sync

# Docker (default setup)
docker compose exec -it api npm run reset-meili-sync

# Docker (deployment setup)
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run reset-meili-sync"
```

</Step>
<Step>

**LibreChatを再起動します。** アプリが再起動すると、再同期が開始されます。

</Step>
</Steps>

スクリプトは、何かを変更する前に確認を求めます(`y/N`)。そのため、対話型のターミナルで実行してください。MongoDB内のすべてのメッセージと会話について`_meiliIndex`フラグを`false`にリセットし、リセットされたドキュメント数と、まだ同期されていないドキュメント数を報告します。

**使用するタイミング:**

- Meilisearchのデータファイルを削除した後
- Meilisearchを再インデックスが必要なバージョンにアップグレードする場合
- LibreChatで会話が完全に同期されていると表示されるにもかかわらず、Meilisearchのデータが欠落している場合
- Meilisearchのデータと一致しないMongoDBのバックアップを復元した後

**高度な同期オプション。** リセット後、以下の環境変数を使用して同期の動作を制御できます：

| Variable | Default | Description |
| --- | --- | --- |
| `MEILI_SYNC_BATCH_SIZE` | `100` | 同期ごとに同期されるドキュメントの数です。リセットスクリプトもこの値をフラグリセット用バッチのサイズとして使用し、そちらでのデフォルトは `1000` です。 |
| `MEILI_SYNC_DELAY_MS` | `100` | 同期バッチ間の遅延時間（ミリ秒）です。リセットスクリプトのバッチ間でも使用されます。 |
| `MEILI_SYNC_THRESHOLD` | `1000` | 同期がトリガーされるまでに必要な未同期ドキュメントの最小数です。 |
