  このドキュメントでは、LibreChatのロギング機能の使い方を説明します。この機能はエラーログとデバッグログを`/api/logs`フォルダに保存します。これらのログを使用して、問題のトラブルシューティング、サーバーの監視、バグの報告を行うことができます。デバッグログは、DEBUG_LOGGING=trueを設定して明示的に有効にした場合にのみ書き込まれます。

### 一般 [#general]

LibreChatには、バックエンド（api）に組み込まれた一元的なロギング機能があります。

- **Docker** インストールでは、ログファイルは `/logs` に保存されます。

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="logs" defaultOpen>
      <FileTree.File name="debug-2024-01-01.log" active />
      <FileTree.File name="error-2024-01-01.log" active />
      <FileTree.File name="meiliSync-2024-01-01.log" active />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

- **npm** インストールでは、ログファイルは `/api/logs` に保存されます。

<FileTree>
  <FileTree.Folder name="librechat" defaultOpen>
    <FileTree.Folder name="api" defaultOpen>
      <FileTree.Folder name="logs" defaultOpen>
        <FileTree.File name="debug-2024-01-01.log" active />
        <FileTree.File name="error-2024-01-01.log" active />
        <FileTree.File name="meiliSync-2024-01-01.log" active />
      </FileTree.Folder>
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

デフォルトでエラーログは保存されます。デバッグログファイルは `DEBUG_LOGGING=true` の場合にのみ書き込まれます。提供されている `.env.example` では `true` に設定されていますが、変数が未設定の場合はデバッグファイルは作成されません。

これにより、**[the ELK stack](https://aws.amazon.com/what-is/elk-stack/)** のような、ログファイルを検査する外部ツールを通じてサーバーを監視できるようになります。

デバッグログは、開発作業や問題の修正に不可欠です。LibreChatの実行中に何らかの問題が発生した場合は、可能な限りその状況を再現し、`./api/logs/debug-%DATE%.log` にあるログを添えて **[問題を報告](https://github.com/LibreChat-AI/LibreChat/issues)** してください。

エラーログも同じ場所に保存されます: `./api/logs/error-%DATE%.log`。Meilisearchを設定している場合、それ専用のログファイルも別途作成されます。

<Callout type="note" title="注:">
  ログファイルは毎日ローテーションされます。日付が変わるたびに新しいファイルが作成され、ファイルが20 MBに達した時点でも分割されます。ローテーションされたファイルはgzipで圧縮され、14日間保存されます。エラーはデバッグログファイルにも記録されますが、エラーログファイルにはスタックトレースや、より詳細な情報が含まれています。
</Callout>

### セットアップ [#setup]

- デバッグログファイルは、この変数が`true`に設定されている場合にのみ書き込まれます。未設定の場合や、それ以外の値に設定されている場合は、デバッグファイルは作成されません。

<OptionTable
  options={[['DEBUG_LOGGING', 'boolean', 'デバッグログをファイルに書き込む。デバッグログファイルを作成するには必須。', 'DEBUG_LOGGING=true']]}
/>

> 注意: 本番環境ではデバッグログを無効のままにしておくことを推奨します。

- コンソール/ターミナルで詳細なサーバー出力を表示するには、以下を `TRUE` に設定します。

<OptionTable
  options={[
    [
      'DEBUG_CONSOLE',
      'boolean',
      'ファイルデバッグログと同じ形式で、詳細なコンソール/stdoutログを有効にします。',
      'DEBUG_CONSOLE=false',
    ],
  ]}
/>

ただし、出力が非常に冗長になる可能性があるため、これは推奨されません。デフォルトでは無効になっており、必要な場合にのみ有効にしてください。

- クラウドデプロイメント（GCPやAWSなど）でコンソールログを扱う際、これを有効にすると、ログがUTCタイムスタンプ付きでJSON形式として出力されます。

<OptionTable
  options={[
    [
      'CONSOLE_JSON',
      'boolean',
      'GCPやAWSなどのクラウドデプロイに適した、詳細なJSON形式のコンソール/stdoutログを有効にします。',
      'CONSOLE_JSON=false',
    ],
  ]}
/>

デフォルトでは、JSON文字列の長さは255文字に切り詰められます。これは以下の環境変数で設定できます：

<OptionTable
  options={[
    [
      'CONSOLE_JSON_STRING_LENGTH',
      'number',
      'JSONコンソール/stdoutログ内の文字列値の切り捨てサイズを設定します。デフォルト: 255。',
      '# CONSOLE_JSON_STRING_LENGTH=255',
    ],
  ]}
/>

- コンソールの詳細度は`CONSOLE_LOG_LEVEL`で設定できます(`error`、`warn`、`info`、`http`、`verbose`、`debug`、`activity`、`silly`、または`silent`)。`silent`を指定するとファイルへのログ出力は無効にせず、コンソール出力のみを停止します。無効な値が指定された場合は、警告を表示したうえでデフォルト値にフォールバックします。

<OptionTable
  options={[
    [
      'CONSOLE_LOG_LEVEL',
      'string',
      'コンソールの詳細度。デフォルトは info で、DEBUG_CONSOLE=true の場合は debug になります。明示的に指定された値が優先されます。',
      '# CONSOLE_LOG_LEVEL=info',
    ],
  ]}
/>

- デバッグログメッセージは、デフォルトで150文字に切り詰められます。また、ログのリダクション処理は、1レコードあたり5000個の値に制限されています。これらは `DEBUG_MESSAGE_LENGTH` と `LOG_REDACTION_MAX_NODES` で調整できます。

<OptionTable
  options={[
    [
      'DEBUG_MESSAGE_LENGTH',
      'number',
      'デバッグログメッセージが切り詰められるまでの最大長です。デフォルト: 150。',
      '# DEBUG_MESSAGE_LENGTH=150',
    ],
    [
      'LOG_REDACTION_MAX_NODES',
      'number',
      '1回のログレコードでマスク(redact)できる値の最大数。上限を超えた残りの値は置き換えられます。デフォルト: 5000。',
      '# LOG_REDACTION_MAX_NODES=5000',
    ],
  ]}
/>

- デフォルトの場所以外にログファイルを書き込むには、`LIBRECHAT_LOG_DIR` を設定します。詳しくは `.env` リファレンスの[Logging](/docs/configuration/dotenv#logging)を参照してください。

- ファイルベースのログ転送はデフォルトで有効になっています。デプロイメントでログをstdout/stderrのみに出力する必要がある場合は、`LOG_TO_FILE=false` を設定してください。

<OptionTable
  options={[
    [
      'LOG_TO_FILE',
      'boolean',
      'ファイルベースのWinstonトランスポートを無効にするにはfalseに設定します。',
      'LOG_TO_FILE=true',
    ],
  ]}
/>

### OpenTelemetry Tracing [#opentelemetry-tracing]

LibreChatは、サーバー、データベース、Redis、およびアウトバウンドHTTPの可視化のために、バックエンドのOpenTelemetryトレースを出力できます。Redisコマンドレベルのスパンはオプトイン形式であるため、デフォルトのトレースは高レベルに保たれます。これは、GenAI固有のプロンプトおよびモデルのオブザーバビリティとして推奨されるオプションであるLangfuseとは別個のものです。
