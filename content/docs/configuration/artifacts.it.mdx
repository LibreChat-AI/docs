Questa pagina descrive il lato amministrativo di [Artifacts](/docs/features/artifacts). Gli utenti attivano gli artifact per ogni agente nell'Agent Builder; le impostazioni qui riportate determinano se tale opzione è disponibile e da dove vengono caricate le anteprime.

## Abilitare gli artifact [#enabling-artifacts]

Gli artefatti sono una funzionalità degli agenti. `artifacts` è presente nell'elenco predefinito di [`endpoints.agents.capabilities`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), quindi è disponibile a meno che non si imposti un elenco personalizzato che lo escluda. Se si sovrascrive `capabilities`, includere `artifacts` per mantenere l'opzione nell'Agent Builder.

Per fornire ad una model spec gli artefatti senza creare un agente, imposta [`artifacts`](/docs/configuration/librechat_yaml/object_structure/model_specs#artifacts) sulla spec. Il valore `true` utilizza la modalità predefinita; puoi anche passare il nome di una modalità: `default`, `shadcnui` o `custom`.

## Apertura del pannello in una nuova finestra [#opening-the-panel-in-a-new-window]

Il pannello include un pulsante **Apri in una nuova finestra** che lo sposta in una finestra separata del browser. È attivo per impostazione predefinita. Se la tua installazione viene eseguita in un ambiente in cui i pop-up non funzionano, ad esempio una webview incorporata, disattivalo con [`interface.artifactUndocking: false`](/docs/configuration/librechat_yaml/object_structure/interface#artifactundocking); il pannello agganciato continuerà a funzionare.

## Content-Security-Policy

LibreChat stesso consente i frame HTTPS nella propria CSP, quindi il bundler predefinito di CodeSandbox si carica senza modifiche. Se un reverse proxy o una CDN posta davanti a LibreChat imposta un `Content-Security-Policy` più restrittivo, consenti l'origine del bundler in `frame-src`: `https://*.codesandbox.io` per il bundler pubblico, oppure gli URL dei tuoi bundler se li ospiti autonomamente. Quando ti serve solo estendere la policy integrata di LibreChat, usa `CSP_FRAME_SRC_EXTRA`.

Le anteprime React caricano anche Tailwind da `cdn.tailwindcss.com`, quindi questo host deve essere raggiungibile dai browser degli utenti.

## Self-hosting del bundler Sandpack [#self-hosting-the-sandpack-bundler]

Le anteprime vengono visualizzate tramite [Sandpack](https://sandpack.codesandbox.io/), che per impostazione predefinita scarica il proprio bundler dalla CDN pubblica di CodeSandbox. Tale CDN invia anche dati di telemetria sull'utilizzo. Per reti private, requisiti di conformità o per eliminare la dipendenza da un servizio esterno, [ospita tu stesso il bundler](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler).

[LibreChat-AI/codesandbox-client](https://github.com/LibreChat-AI/codesandbox-client) è un fork preparato per LibreChat, con le richieste di telemetria rimosse, incluse quelle relative alle immagini dei container.

LibreChat utilizza due bundler. `SANDPACK_BUNDLER_URL` serve gli artifact React, mentre `SANDPACK_STATIC_BUNDLER_URL` serve il template statico alla base delle anteprime di HTML, SVG, Markdown, codice e file Office. Imposta entrambi quando esegui un self-hosting: con solo uno dei due impostato, gli altri tipi di artifact continuano a caricarsi dal CDN pubblico. Entrambi sono elencati nel [riferimento `.env`](/docs/configuration/dotenv#artifacts). I diagrammi Mermaid vengono renderizzati direttamente nella pagina e non utilizzano nessuno dei due bundler.

Eseguire un proprio bundler significa gestire direttamente le sue impostazioni CORS, gli aggiornamenti di sicurezza e le risorse di hosting. Riavvia LibreChat dopo aver modificato queste variabili; gli URL vengono inviati al browser nella configurazione di avvio.
