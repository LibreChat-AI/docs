RAG APIは、ユーザーがアップロードしたファイルをインデックス化し、関連するパッセージを検索してプロンプトを補強することで、LibreChatがドキュメントに基づいたコンテキストを認識した回答を提供できるようにします。これは、PostgreSQL + pgvectorデータベースをバックエンドとする独立したFastAPIサービスとして実行されます。

<Callout type="info" title="ユーザーに表示される内容">
[Chat with Files](/docs/features/rag_api)では、ファイル検索用のアップロード、ファイルの再利用、エージェントでのファイル検索について説明しています。このページではセットアップと設定について説明します。
</Callout>

## 可用性 [#availability]

RAG API を使ったファイル検索は、[Agents](/docs/features/agents) を含め、Assistants 以外のすべてのエンドポイントの通常のチャットで動作します。OpenAI Assistants は代わりに OpenAI 独自のファイルストレージと検索機能を使用し、そこでアップロードされたファイルは他の場所に添付することはできません。

ユーザーに **Upload for File Search** が表示されるのは、`file_search` エージェント機能が有効になっており(デフォルトで有効)、かつユーザーのロールに File Search の権限が付与されている場合のみです([`interface.fileSearch`](/docs/configuration/librechat_yaml/object_structure/interface#filesearch))。

## Docker クイックスタート [#docker-quick-start]

Dockerの場合、RAG APIは既定の`docker-compose.yml`と`deploy-compose.yml`の両方にすでに組み込まれており、`RAG_API_URL`の値も含まれています。必要なのは、最新のイメージとComposeファイルを使用していることを確認することだけです。更新方法がわからない場合は、[DockerでのLibreChatの更新ガイド](/docs/local/docker#updating-librechat)を参照してください。

<Callout type="warning" title="共有 .env ファイル">
デフォルトの Docker セットアップでは、`.env` ファイルは LibreChat と RAG API 間で共有されます。RAG 変数はその同じファイル内で定義してください。完全なリストは [RAG API README](https://github.com/LibreChat-AI/rag-api/blob/main/README.md) に記載されています。
</Callout>

The default `docker-compose.yml` and `deploy-compose.yml` files set `RAG_API_URL=http://rag_api:${RAG_PORT:-8000}` on the `api` service. サービスに設定された環境変数は `.env` ファイルより優先されるため、同梱のセットアップでは `.env` に `RAG_API_URL` を追加する必要はなく、そこに設定しても効果はありません。Docker デプロイメントを外部の RAG API に向けるには、代わりに `api` サービス上で値を上書きしてください。例えば、Docker ホスト上で動作する RAG API の場合は次のようになります:

```yaml filename="docker-compose.override.yml"
services:
  api:
    environment:
      - RAG_API_URL=http://host.docker.internal:8000
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

`extra_hosts` エントリは、Docker が `host.docker.internal` を自動で定義しない Linux で必要になります。

Compose は、デフォルトの `docker-compose.yml` を使用する場合にのみ `docker-compose.override.yml` を自動的に読み込みます。`deploy-compose.yml` を使用する場合は、両方のファイルを指定してください: `docker compose -f deploy-compose.yml -f docker-compose.override.yml up -d`。

Docker の外で実行する場合は、`.env` ファイルで `RAG_API_URL` を設定してください。

### Lite版とフル版のイメージ [#lite-vs-full-image]

DockerはデフォルトでRAG APIの「lite」イメージ（`registry.librechat.ai/librechat-ai/librechat-rag-api-dev-lite:latest`）を使用します。これは、OpenAIからのリモート埋め込み、または設定済みのリモートHuggingFace/Ollamaサービスのみをサポートしています。

ローカル埋め込み（embeddings）を使用するには、composeファイル内のイメージをフルビルド版である `registry.librechat.ai/librechat-ai/librechat-rag-api-dev:latest` に切り替えてください。この変更は [Docker Compose Override File](/docs/configuration/docker_override) で行ってください。例については、プロジェクトのルートにある `docker-compose.override.yml.example` を参照してください。

PostgreSQL + pgvector データベースと Python API のみを含む compose ファイルが必要な場合は、プロジェクトのルートにある `rag.yml` を参照してください。

### データベースストレージ [#database-storage]

デフォルトのcomposeファイルは、pgvector/PostgreSQLのデータをDocker管理下の `pgdata2` ボリュームに保存します。これは意図的な仕様です。データベースファイルはホストから直接編集する必要がなく、管理されたボリュームを使用することで、所有権や権限に関する一般的な問題を回避できるためです。ユーザーが直接編集するファイル（アップロード、ログ、画像、MongoDBデータ、NGINX設定）については、ホストからの直接アクセスが有用であるため、プロジェクトフォルダにバインドマウントされています。

## ローカルセットアップ [#local-setup]

コンテナを使用しないセットアップは、より手作業が必要になります。[RAG API repo](https://github.com/LibreChat-AI/rag-api/) の手順に従ってください。

LibreChat の `.env` ファイルで、お使いの環境から API に到達できる場所を指すように `RAG_API_URL` を設定してください。これは、デフォルトの `docker-compose.yml` および `deploy-compose.yml` ファイルの `api` サービスですでに値が設定されている、付属の Docker 構成とは異なります。

## 設定 [#configuration]

APIがアクセス可能な `.env` ファイル内の環境変数を通じて、RAG APIオプションを設定します。選択したプロバイダーが必要とする認証情報やパスを除き、ほとんどはオプションです。デフォルト設定では、`RAG_OPENAI_API_KEY` のみが必須となります。

## 使用方法 [#usage]

RAG APIが到達可能になれば、LibreChat側で有効にする必要のある設定はこれ以上ありません。ユーザーは**Upload for File Search**でファイルをアップロードし、質問の内容に応じて、モデルが`file_search`ツールを通じてインデックスを検索します。`RAG_API_URL`が設定されていない場合やサービスが停止している場合、これらのアップロードは失敗します。また、LibreChatはRAG APIのヘルスチェックに到達できない場合、起動時に警告をログに出力します。ユーザー側の操作については、[Chat with Files](/docs/features/rag_api)を参照してください。

## トラブルシューティング [#troubleshooting]

RAG APIのセットアップや使用中に問題が発生した場合は、以下を参照してください：

- `.env` ファイルに必要な環境変数がすべて正しく設定されていることを確認してください。
- ベクトルデータベースが設定され、アクセス可能であることを確認してください。
- OpenAI APIキーまたはその他のプロバイダーの認証情報が有効であることを確認してください。
- LibreChat と RAG API の両方のログで、エラーや警告を確認してください。

問題が解決しない場合は、RAG APIのドキュメントを参照するか、GitHub DiscussionsまたはDiscordのLibreChatコミュニティで質問してください。
