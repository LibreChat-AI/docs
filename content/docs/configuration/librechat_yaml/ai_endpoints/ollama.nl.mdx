Ollama draait open modellen lokaal en stelt een OpenAI-compatibele API beschikbaar, zodat je LibreChat naar je eigen machine kunt laten wijzen. Download modellen met `ollama run <model>` en bekijk wat er beschikbaar is in de [Ollama Library](https://ollama.com/library).

## Configuratie [#configuration]

Ollama negeert de API-sleutel, maar verwacht nog steeds dat het veld aanwezig is, dus stel het in op een willekeurige placeholder. Wijs `baseURL` naar je Ollama-server. Voeg het endpoint toe aan de `custom` lijst onder `endpoints` in je `librechat.yaml`. Als je bestand al een `endpoints.custom` lijst heeft, plak dan alleen het `- name:` item erin en behoud dezelfde inspringing:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## Opmerkingen [#notes]

- Stel `titleModel` in op `"current_model"` zodat het genereren van titels het model van het gesprek hergebruikt in plaats van een tweede model te laden. Dit zorgt ervoor dat Ollama beperkt blijft tot één geladen model per gesprek.
- De `default` array hierboven is een voorbeeldlijst van populaire modellen. Met `fetch: true` haalt LibreChat de volledige lijst op van je server.

<Callout type="tip" title="Ollama -> llama3">

Zodra `stop` was verwijderd uit de [default parameters](/docs/configuration/librechat_yaml/object_structure/default_params), zou het onderstaande probleem niet langer moeten optreden.

Als `llama3` blijft genereren zonder te stoppen, voeg dan een `addParams` blok toe met de stop-sequenties:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Als je alleen `llama3` met Ollama gebruikt, is het instellen van `stop` op configuratieniveau via `addParams` prima. Wanneer je meerdere modellen gebruikt, voeg dan stop-sequenties toe vanuit de frontend via gespreksinstellingen en presets, en laat `addParams` weg:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

Stel de stopsequenties in bij de gespreksinstellingen (en sla deze op als een preset). Open een gesprek op het Ollama endpoint, open het rechter instellingenpaneel en voeg elke sequentie toe onder **Stop Sequences**:

![LibreChat paneel met gespreksinstellingen met vier llama3 stop-sequenties ingevoerd in het veld Stop Sequences](https://github.com/danny-avila/LibreChat/assets/110412045/57460b8c-308a-4d21-9dfe-f48a2ac85099)

</Callout>

## Probleemoplossing [#troubleshooting]

### Ollama verschijnt niet, of de modellijst is leeg [#ollama-does-not-appear-or-the-model-list-is-empty]

Doorloop deze in volgorde:

1. **Controleer of het endpoint bereikbaar is vanuit LibreChat, niet vanuit je shell.** Als LibreChat in Docker draait, is `localhost` de API-container zelf, niet je host. Gebruik `http://host.docker.internal:11434/v1/` op Docker Desktop, of het LAN-adres van de host op Linux waar `host.docker.internal` mogelijk niet beschikbaar is. LibreChat buiten Docker draaien is het enige geval waarin `http://localhost:11434/v1/` correct is.
2. **Bevestig dat Ollama luistert buiten loopback.** Standaard bindt Ollama aan `127.0.0.1`, wat een container niet kan bereiken. Stel `OLLAMA_HOST=0.0.0.0` in de eigen omgeving van Ollama in en herstart deze.

   <Callout type="warning" title="Binding aan 0.0.0.0 stelt Ollama bloot op elke interface">
   De API van Ollama is niet geauthenticeerd. Het binden ervan aan `0.0.0.0` op een machine met een LAN- of publieke interface geeft iedereen die poort 11434 kan bereiken toegang tot modellen, evenals de mogelijkheid om modellen te downloaden en te verwijderen. Geef er de voorkeur aan om alleen te binden aan het adres dat de LibreChat-container daadwerkelijk bereikt, wat de gateway is van het compose-netwerk (`docker network inspect <network>` rapporteert dit), en beveilig poort 11434 met een firewall zodat niemand anders deze kan bereiken.
   </Callout>
3. **Weet wat de wijzigingen in de endpoint-naam inhouden.** LibreChat benadert de eigen `/api/tags` van Ollama alleen wanneer de `name` van het endpoint begint met `ollama`, ongeacht hoofdletters of kleine letters. Elke andere naam, of een fout in die eigen aanroep, valt terug op de generieke OpenAI-compatibele `/v1/models` aanvraag. Huidige Ollama-versies beantwoorden die ook op de bovenstaande `/v1/` basis-URL, dus een hernoemd endpoint retourneert meestal nog steeds een modellijst. Het voorvoegsel is van belang wanneer je specifiek de eigen tags-route nodig hebt, en een gehoste proxy die `/v1/models` bedient maar geen `/api/tags`, kan beter zonder.
4. **Stel `apiKey` in op een willekeurige niet-lege placeholder.** Ollama negeert de waarde, maar een aangepast endpoint zonder `apiKey` wordt verwijderd bij het laden van de configuratie.
5. **Lees de API-logs.** `docker compose logs api` rapporteert de verbindingsfout en de URL die daadwerkelijk werd geprobeerd.

### Een externe of gehoste Ollama-server gebruiken [#using-a-remote-or-hosted-ollama-server]

Niets is locatie-specifiek behalve de URL: wijs `baseURL` naar het OpenAI-compatibele pad van de externe server en plaats de inloggegevens in `apiKey` in plaats van de tijdelijke aanduiding. Geef het een naam naar keuze: het ophalen van modellen valt terug op de OpenAI-compatibele `/v1/models` route, wat meestal is wat een gehoste proxy blootstelt.

`apiKey` wordt alleen verzonden als `Authorization: Bearer <key>`, en alleen wanneer uw `headers` blok nog geen `Authorization` header heeft ingesteld. Als uw gehoste proxy een ander schema verwacht, zoals `X-API-Key` of Basic auth, plaats dan de werkelijke inloggegevens in `headers`: een `Authorization` vermelding daar vervangt de Bearer fallback, en elke andere header wordt daarnaast verzonden. `apiKey` moet in beide gevallen niet-leeg zijn, omdat een endpoint zonder waarde wordt genegeerd bij het laden van de configuratie.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
