Ollama는 오픈 모델을 로컬에서 실행하고 OpenAI 호환 API를 노출하므로, LibreChat을 자신의 컴퓨터로 연결할 수 있습니다. `ollama run <model>` 명령어로 모델을 다운로드하고 [Ollama Library](https://ollama.com/library)에서 사용 가능한 모델을 찾아보세요.

## 구성 [#configuration]

Ollama는 API 키를 무시하지만 여전히 해당 필드가 존재하기를 기대하므로, 아무 자리 표시자(placeholder) 값으로 설정하십시오. `baseURL`을 Ollama 서버로 지정하십시오. `librechat.yaml`의 `endpoints` 아래에 있는 `custom` 목록에 해당 엔드포인트를 추가하십시오. 파일에 이미 `endpoints.custom` 목록이 있는 경우, 동일한 들여쓰기를 유지하면서 `- name:` 항목만 붙여넣으십시오:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## 참고 사항 [#notes]

- `titleModel`을 `"current_model"`로 설정하면 제목 생성 시 두 번째 모델을 로드하는 대신 대화의 모델을 재사용하게 됩니다. 이를 통해 Ollama는 대화당 하나의 모델만 로드된 상태를 유지할 수 있습니다.
- 위의 `default` 배열은 인기 있는 모델들의 샘플 목록입니다. `fetch: true`를 설정하면, LibreChat은 서버에서 전체 목록을 가져옵니다.

<Callout type="tip" title="Ollama -> llama3">

[default parameters](/docs/configuration/librechat_yaml/object_structure/default_params)에서 `stop`이 제거되면 아래 문제는 더 이상 발생하지 않습니다.

`llama3`가 멈추지 않고 계속 생성한다면, `addParams` 블록에 정지 시퀀스(stop sequences)를 추가하세요:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Ollama에서 `llama3`만 실행하는 경우, `addParams`를 통해 설정 수준에서 `stop`을 설정해도 괜찮습니다. 여러 모델을 실행할 때는 대신 대화 매개변수와 프리셋을 통해 프론트엔드에서 정지 시퀀스(stop sequences)를 추가하고, `addParams`는 생략하세요:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

대화 매개변수에서 정지 시퀀스(stop sequences)를 설정하고(프리셋으로 저장하세요). Ollama endpoint에서 대화를 열고, 오른쪽 매개변수 패널을 연 다음, **Stop Sequences** 아래에 각 시퀀스를 추가하세요:

## 문제 해결 [#troubleshooting]

### Ollama가 나타나지 않거나 모델 목록이 비어 있음 [#ollama-does-not-appear-or-the-model-list-is-empty]

다음 순서대로 진행하세요:

1. **LibreChat에서 엔드포인트에 도달할 수 있는지 확인하십시오(셸에서 확인하는 것이 아닙니다).** LibreChat이 Docker에서 실행 중인 경우, `localhost`는 호스트가 아닌 API 컨테이너 자체를 의미합니다. Docker Desktop에서는 `http://host.docker.internal:11434/v1/`을 사용하거나, `host.docker.internal`을 사용할 수 없는 Linux 환경에서는 호스트의 LAN 주소를 사용하십시오. LibreChat을 Docker 외부에서 실행하는 경우에만 `http://localhost:11434/v1/`이 올바른 설정입니다.
2. **Ollama가 루프백 외부에서도 수신 대기 중인지 확인하세요.** 기본적으로 Ollama는 `127.0.0.1`에 바인딩되는데, 이는 컨테이너에서 접근할 수 없습니다. Ollama 자체 환경 변수에 `OLLAMA_HOST=0.0.0.0`을 설정하고 재시작하세요.

   <Callout type="warning" title="0.0.0.0에 바인딩하면 모든 인터페이스에서 Ollama가 노출됩니다">
   Ollama의 API는 인증되지 않습니다. LAN 또는 공용 인터페이스가 있는 머신에서 이를 `0.0.0.0`에 바인딩하면 포트 11434에 접근할 수 있는 누구에게나 모델 접근 권한은 물론, 모델을 가져오거나 삭제할 수 있는 권한까지 부여하게 됩니다. LibreChat 컨테이너가 실제로 도달하는 주소, 즉 compose 네트워크의 게이트웨이(`docker network inspect <network>` 명령어로 확인 가능)에만 바인딩하고, 다른 곳에서 접근할 수 없도록 포트 11434에 방화벽을 설정하는 것을 권장합니다.
   </Callout>
3. **엔드포인트 이름 변경 사항을 숙지하세요.** LibreChat은 엔드포인트 `name`이 대소문자 구분 없이 `ollama`로 시작하는 경우에만 Ollama의 네이티브 `/api/tags` 경로를 호출합니다. 다른 이름을 사용하거나 해당 네이티브 호출이 실패할 경우, 일반적인 OpenAI 호환 `/v1/models` 요청으로 대체됩니다. 현재 Ollama 버전은 위에서 언급한 `/v1/` 기본 URL에서도 해당 요청에 응답하므로, 엔드포인트 이름을 변경하더라도 일반적으로 모델 목록은 계속 반환됩니다. 접두사는 네이티브 태그 경로가 특별히 필요할 때 중요하며, `/api/tags`는 지원하지 않고 `/v1/models`만 제공하는 호스팅 프록시를 사용하는 경우에는 접두사를 사용하지 않는 것이 좋습니다.
4. `apiKey`를 비어 있지 않은 임의의 플레이스홀더로 설정하세요. Ollama는 해당 값을 무시하지만, `apiKey`가 없는 사용자 지정 endpoint는 구성 로드 시 삭제됩니다.
5. **API 로그를 확인하세요.** `docker compose logs api`는 연결 오류와 실제로 시도된 URL을 보고합니다.

### 원격 또는 호스팅된 Ollama 서버 사용하기 [#using-a-remote-or-hosted-ollama-server]

URL을 제외하고는 로컬에 특화된 설정은 없습니다. `baseURL`을 원격 서버의 OpenAI 호환 경로로 지정하고, 자리 표시자 대신 `apiKey`에 자격 증명을 입력하세요. 이름은 원하는 대로 지정할 수 있습니다. 모델 가져오기는 일반적으로 호스팅된 프록시가 노출하는 OpenAI 호환 `/v1/models` 경로로 대체됩니다.

`apiKey`는 항상 `Authorization: Bearer <key>`로만 전송되며, `headers` 블록에서 `Authorization` 헤더를 별도로 설정하지 않은 경우에만 전송됩니다. 호스팅된 프록시가 `X-API-Key`나 Basic auth와 같은 다른 스키마를 요구하는 경우, 실제 자격 증명을 `headers`에 넣으십시오. 그곳의 `Authorization` 항목은 Bearer 폴백을 대체하며, 다른 모든 헤더는 그와 함께 전송됩니다. 어느 경우든 `apiKey`는 비어 있지 않아야 합니다. 값이 없는 엔드포인트는 설정 로드 시 삭제되기 때문입니다.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
