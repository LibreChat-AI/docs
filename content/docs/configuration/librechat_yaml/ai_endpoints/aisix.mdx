[AISIX](https://github.com/api7/aisix) is an Apache-2.0-licensed open-source AI gateway maintained by API7.ai. LibreChat can use AISIX as an OpenAI-compatible custom endpoint while AISIX manages provider credentials, caller access, model aliases, and gateway policies.

## Before you start

Prepare:

- an AISIX gateway that LibreChat can reach;
- an AISIX caller API key dedicated to LibreChat; and
- at least one chat-capable model alias allowed for that caller key.

Follow the [AISIX open-source gateway quickstart](https://docs.api7.ai/ai-gateway/getting-started/gateway-quickstart) if you do not have a running gateway. Confirm the key can discover its allowed aliases before configuring LibreChat:

```bash
curl -sS "${AISIX_BASE_URL}/models" \
  -H "Authorization: Bearer ${AISIX_API_KEY}"
```

`AISIX_BASE_URL` must be the OpenAI-compatible API root ending in `/v1`. With Docker Desktop, `http://host.docker.internal:3000/v1` reaches AISIX running on the host. With Docker Engine on Linux, configure a host-gateway mapping or place both containers on a shared network and use the AISIX service name.

## Configuration

Add the gateway URL and caller key to your `.env` file:

```bash filename=".env"
AISIX_BASE_URL=http://host.docker.internal:3000/v1
AISIX_API_KEY=YOUR_AISIX_CALLER_API_KEY
```

Add AISIX under `endpoints.custom` in your `librechat.yaml`. Replace `prod-chat` with a chat-capable AISIX model alias that the caller key can access:

```yaml filename="librechat.yaml"
    - name: "AISIX"
      apiKey: "${AISIX_API_KEY}"
      baseURL: "${AISIX_BASE_URL}"
      models:
        default: ["prod-chat"]
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "AISIX AI Gateway"
```

Restart LibreChat after updating the files, select **AISIX**, choose an allowed model alias, and send a message. A successful setup shows the alias in LibreChat's model selector and renders a complete assistant response.

## Notes

- With `fetch: true`, LibreChat requests `GET /v1/models`. AISIX returns the model aliases available to the supplied caller key; `models.default` provides the initial selection.
- The value in `AISIX_API_KEY` is an AISIX caller key, not an upstream provider key. AISIX keeps provider credentials on the gateway side.
- This server-level configuration shares one AISIX caller identity, model allowlist, and discovered model list across LibreChat users who can use the endpoint. Use separate endpoint configurations or another identity design when users require different gateway permissions.
- LibreChat custom endpoints use the OpenAI-compatible Chat Completions path by default. Streaming and tool calling also depend on the selected AISIX model and its upstream provider adapter.
- If LibreChat and AISIX run in separate containers, use a shared-network service name instead of `localhost`. In production, use a reachable HTTPS endpoint.
- A missing or invalid caller key is rejected before an upstream request, and a caller key that requests a disallowed model alias receives `403`. Upstream authentication can also surface as `401`, so use the error body and AISIX logs rather than the status code alone when troubleshooting. See the [AISIX endpoint reference](https://docs.api7.ai/ai-gateway/endpoints/overview) for the supported API surface.
