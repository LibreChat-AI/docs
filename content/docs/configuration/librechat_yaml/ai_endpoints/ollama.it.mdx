Ollama esegue modelli aperti localmente ed espone un'API compatibile con OpenAI, così puoi puntare LibreChat alla tua macchina. Scarica i modelli con `ollama run <model>` e sfoglia quelli disponibili nella [Ollama Library](https://ollama.com/library).

## Configurazione [#configuration]

Ollama ignora la chiave API ma richiede comunque che il campo sia presente, quindi impostalo su un segnaposto qualsiasi. Punta `baseURL` al tuo server Ollama. Aggiungi l'endpoint alla lista `custom` sotto `endpoints` nel tuo `librechat.yaml`. Se il tuo file ha già una lista `endpoints.custom`, incolla al suo interno solo la voce `- name:`, mantenendo la stessa indentazione:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## Note [#notes]

- Imposta `titleModel` su `"current_model"` in modo che la generazione del titolo riutilizzi il modello della conversazione invece di caricarne un secondo. Questo mantiene Ollama su un singolo modello caricato per conversazione.
- L'array `default` qui sopra è un elenco di esempio di modelli popolari. Con `fetch: true`, LibreChat estrae l'elenco completo dal tuo server.

<Callout type="tip" title="Ollama -> llama3">

Una volta rimosso `stop` dai [parametri predefiniti](/docs/configuration/librechat_yaml/object_structure/default_params), il problema sottostante non dovrebbe più verificarsi.

Se `llama3` continua a generare senza fermarsi, aggiungi un blocco `addParams` con le sequenze di stop:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Se esegui solo `llama3` con Ollama, impostare `stop` a livello di configurazione tramite `addParams` va bene. Quando esegui diversi modelli, aggiungi invece le sequenze di stop dal frontend tramite i parametri di conversazione e i preset, e ometti `addParams`:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

Imposta le sequenze di stop nei parametri della conversazione (e salvale come preset). Apri una conversazione sull'endpoint Ollama, apri il pannello dei parametri a destra e aggiungi ogni sequenza sotto **Stop Sequences**:

![Pannello dei parametri di conversazione di LibreChat con quattro sequenze di stop di llama3 inserite nel campo Stop Sequences](https://github.com/danny-avila/LibreChat/assets/110412045/57460b8c-308a-4d21-9dfe-f48a2ac85099)

</Callout>

## Risoluzione dei problemi [#troubleshooting]

### Ollama non appare, o l'elenco dei modelli è vuoto [#ollama-does-not-appear-or-the-model-list-is-empty]

Segui questi passaggi in ordine:

1. **Verifica che l'endpoint sia raggiungibile da LibreChat, non dalla tua shell.** Se LibreChat è in esecuzione in Docker, `localhost` è il container dell'API stesso, non il tuo host. Usa `http://host.docker.internal:11434/v1/` su Docker Desktop, oppure l'indirizzo LAN dell'host su Linux, dove `host.docker.internal` potrebbe non essere disponibile. Eseguire LibreChat al di fuori di Docker è l'unico caso in cui `http://localhost:11434/v1/` è corretto.
2. **Conferma che Ollama sia in ascolto oltre il loopback.** Per impostazione predefinita, Ollama si associa a `127.0.0.1`, che un container non può raggiungere. Imposta `OLLAMA_HOST=0.0.0.0` nell'ambiente di Ollama e riavvialo.

   <Callout type="warning" title="Il binding a 0.0.0.0 espone Ollama su ogni interfaccia">
   L'API di Ollama non è autenticata. Associare l'API a `0.0.0.0` su una macchina con una LAN o un'interfaccia pubblica fornisce l'accesso al modello, nonché la possibilità di scaricare ed eliminare modelli, a chiunque possa raggiungere la porta 11434. È preferibile associare l'API solo all'indirizzo effettivamente raggiunto dal container LibreChat, ovvero il gateway della sua rete compose (riportato da `docker network inspect <network>`), e configurare il firewall sulla porta 11434 in modo che nessun altro possa raggiungerla.
   </Callout>
3. **Sappi cosa comporta la modifica del nome dell'endpoint.** LibreChat utilizza il percorso nativo `/api/tags` di Ollama solo quando il `name` dell'endpoint inizia con `ollama`, senza distinzione tra maiuscole e minuscole. Qualsiasi altro nome, o un fallimento di quella chiamata nativa, ricade sulla richiesta generica `/v1/models` compatibile con OpenAI. Le versioni attuali di Ollama rispondono anche a quella richiesta all'URL di base `/v1/` indicato sopra, quindi un endpoint rinominato solitamente restituisce comunque un elenco di modelli. Il prefisso è importante quando hai specificamente bisogno del percorso nativo per i tag, mentre un proxy ospitato che serve `/v1/models` ma non `/api/tags` funziona meglio senza di esso.
4. **Imposta `apiKey` su un qualsiasi segnaposto non vuoto.** Ollama ignora il valore, ma un endpoint personalizzato senza `apiKey` viene scartato al caricamento della configurazione.
5. **Leggi i log dell'API.** `docker compose logs api` riporta l'errore di connessione e l'URL che ha effettivamente tentato di raggiungere.

### Utilizzo di un server Ollama remoto o ospitato [#using-a-remote-or-hosted-ollama-server]

Nulla è specifico per il locale, eccetto l'URL: punta `baseURL` al percorso compatibile con OpenAI del server remoto e inserisci le credenziali in `apiKey` al posto del segnaposto. Chiamalo come preferisci: il recupero del modello ricade sulla rotta `/v1/models` compatibile con OpenAI, che è solitamente ciò che un proxy ospitato espone.

`apiKey` viene inviato solo come `Authorization: Bearer <key>` e solo quando il blocco `headers` non ha già impostato un'intestazione `Authorization`. Se il tuo proxy ospitato prevede uno schema diverso, come `X-API-Key` o l'autenticazione Basic, inserisci la credenziale reale in `headers`: una voce `Authorization` lì sostituisce il fallback Bearer e qualsiasi altra intestazione viene inviata insieme ad essa. `apiKey` deve comunque essere non vuota in entrambi i casi, poiché un endpoint senza di essa viene scartato al caricamento della configurazione.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
