O Ollama executa modelos abertos localmente e expõe uma API compatível com OpenAI, para que você possa apontar o LibreChat para sua própria máquina. Baixe modelos com `ollama run <model>` e navegue pelo que está disponível na [Ollama Library](https://ollama.com/library).

## Configuração [#configuration]

O Ollama ignora a chave de API, mas ainda espera que o campo esteja presente, portanto, defina-o como qualquer placeholder. Aponte `baseURL` para o seu servidor Ollama. Adicione o endpoint à lista `custom` em `endpoints` no seu `librechat.yaml`. Se o seu arquivo já possuir uma lista `endpoints.custom`, cole apenas a entrada `- name:` nela, mantendo o mesmo recuo:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## Notas [#notes]

- Defina `titleModel` como `"current_model"` para que a geração de títulos reutilize o modelo da conversa em vez de carregar um segundo. Isso mantém o Ollama limitado a um único modelo carregado por conversa.
- O array `default` acima é uma lista de exemplo de modelos populares. Com `fetch: true`, o LibreChat obtém a lista completa do seu servidor.

<Callout type="tip" title="Ollama -> llama3">

Uma vez que `stop` foi removido dos [parâmetros padrão](/docs/configuration/librechat_yaml/object_structure/default_params), o problema abaixo não deve mais ocorrer.

Se o `llama3` continuar gerando sem parar, adicione um bloco `addParams` com as sequências de parada:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Se você executar apenas o `llama3` com o Ollama, definir `stop` no nível de configuração via `addParams` é aceitável. Quando você executar vários modelos, adicione sequências de parada a partir do frontend através de parâmetros de conversa e predefinições, e omita o `addParams`:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

Defina as sequências de parada nos parâmetros da conversa (e salve-as como uma predefinição). Abra uma conversa no endpoint Ollama, abra o painel de parâmetros à direita e adicione cada sequência em **Stop Sequences**:

</Callout>

## Solução de problemas [#troubleshooting]

### O Ollama não aparece, ou a lista de modelos está vazia [#ollama-does-not-appear-or-the-model-list-is-empty]

Siga estas etapas em ordem:

1. **Verifique se o endpoint é acessível a partir do LibreChat, e não do seu shell.** Se o LibreChat estiver sendo executado no Docker, `localhost` é o próprio container da API, não o seu host. Use `http://host.docker.internal:11434/v1/` no Docker Desktop, ou o endereço LAN do host no Linux, onde `host.docker.internal` pode não estar disponível. Executar o LibreChat fora do Docker é o único caso em que `http://localhost:11434/v1/` está correto.
2. **Confirme se o Ollama está escutando além do loopback.** Por padrão, o Ollama vincula-se ao `127.0.0.1`, que um container não consegue alcançar. Defina `OLLAMA_HOST=0.0.0.0` no ambiente do próprio Ollama e reinicie-o.

   <Callout type="warning" title="Vincular ao 0.0.0.0 expõe o Ollama em todas as interfaces">
   A API do Ollama não possui autenticação. Vincular a `0.0.0.0` em uma máquina com uma interface LAN ou pública concede acesso ao modelo, além da capacidade de baixar e excluir modelos, a qualquer pessoa que consiga acessar a porta 11434. Prefira vincular apenas ao endereço que o container do LibreChat realmente alcança, que é o gateway da sua rede compose (`docker network inspect <network>` informa isso), e configure um firewall na porta 11434 para que nada mais possa acessá-la.
   </Callout>
3. **Saiba como as alterações no nome do endpoint funcionam.** O LibreChat busca o `/api/tags` nativo do Ollama apenas quando o `name` do endpoint começa com `ollama`, ignorando maiúsculas e minúsculas. Qualquer outro nome, ou uma falha nessa chamada nativa, recorre à solicitação genérica `/v1/models` compatível com OpenAI. As versões atuais do Ollama também respondem a essa solicitação na URL base `/v1/` mencionada acima, portanto, um endpoint renomeado geralmente ainda retorna uma lista de modelos. O prefixo é importante quando você precisa especificamente da rota de tags nativa, e um proxy hospedado que serve `/v1/models`, mas não `/api/tags`, funciona melhor sem ele.
4. **Defina `apiKey` como qualquer placeholder não vazio.** O Ollama ignora o valor, mas um endpoint personalizado sem `apiKey` é descartado no carregamento da configuração.
5. **Leia os logs da API.** `docker compose logs api` relata o erro de conexão e a URL que ele realmente tentou acessar.

### Usando um servidor Ollama remoto ou hospedado [#using-a-remote-or-hosted-ollama-server]

Nada é específico do local, exceto a URL: aponte `baseURL` para o caminho compatível com OpenAI do servidor remoto e coloque a credencial em `apiKey` em vez do espaço reservado. Nomeie como desejar: a busca de modelos recorre à rota `/v1/models` compatível com OpenAI, que geralmente é o que um proxy hospedado expõe.

`apiKey` é sempre enviado apenas como `Authorization: Bearer <key>`, e apenas quando o seu bloco `headers` ainda não tiver definido um cabeçalho `Authorization`. Se o seu proxy hospedado esperar um esquema diferente, como `X-API-Key` ou autenticação Basic, coloque a credencial real em `headers`: uma entrada `Authorization` lá substitui o fallback Bearer, e qualquer outro cabeçalho é enviado juntamente com ele. `apiKey` ainda precisa ser não vazio de qualquer maneira, porque um endpoint sem um é descartado no carregamento da configuração.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
