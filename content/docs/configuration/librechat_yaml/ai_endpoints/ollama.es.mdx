Ollama ejecuta modelos abiertos localmente y expone una API compatible con OpenAI, por lo que puedes apuntar LibreChat a tu propia máquina. Descarga modelos con `ollama run <model>` y explora lo que está disponible en la [Ollama Library](https://ollama.com/library).

## Configuración [#configuration]

Ollama ignora la API key pero aún espera que el campo esté presente, así que establécelo con cualquier marcador de posición. Apunta `baseURL` a tu servidor de Ollama. Agrega el endpoint a la lista `custom` bajo `endpoints` en tu `librechat.yaml`. Si tu archivo ya tiene una lista `endpoints.custom`, pega solo la entrada `- name:` dentro de ella, manteniendo la misma sangría:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## Notas [#notes]

- Establezca `titleModel` en `"current_model"` para que la generación de títulos reutilice el modelo de la conversación en lugar de cargar uno segundo. Esto mantiene a Ollama en un único modelo cargado por conversación.
- La matriz `default` anterior es una lista de muestra de modelos populares. Con `fetch: true`, LibreChat extrae la lista completa desde su servidor.

<Callout type="tip" title="Ollama -> llama3">

Una vez que se eliminó `stop` de los [parámetros predeterminados](/docs/configuration/librechat_yaml/object_structure/default_params), el problema a continuación ya no debería ocurrir.

Si `llama3` sigue generando sin detenerse, añade un bloque `addParams` con las secuencias de parada:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Si solo ejecutas `llama3` con Ollama, configurar `stop` a nivel de configuración mediante `addParams` está bien. Cuando ejecutes varios modelos, añade las secuencias de parada desde la interfaz a través de los parámetros de conversación y los ajustes preestablecidos (presets) en su lugar, y omite `addParams`:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

Establezca las secuencias de parada en los parámetros de la conversación (y guárdelas como un ajuste preestablecido). Abra una conversación en el endpoint de Ollama, abra el panel de parámetros de la derecha y añada cada secuencia en **Stop Sequences**:

![Panel de parámetros de conversación de LibreChat con cuatro secuencias de parada de llama3 ingresadas en el campo Stop Sequences](https://github.com/danny-avila/LibreChat/assets/110412045/57460b8c-308a-4d21-9dfe-f48a2ac85099)

</Callout>

## Solución de problemas [#troubleshooting]

### Ollama no aparece, o la lista de modelos está vacía [#ollama-does-not-appear-or-the-model-list-is-empty]

Sigue estos pasos en orden:

1. **Comprueba que el endpoint sea accesible desde LibreChat, no desde tu shell.** Si LibreChat se ejecuta en Docker, `localhost` es el propio contenedor de la API, no tu máquina anfitriona. Usa `http://host.docker.internal:11434/v1/` en Docker Desktop, o la dirección LAN del anfitrión en Linux donde `host.docker.internal` podría no estar disponible. Ejecutar LibreChat fuera de Docker es el único caso en el que `http://localhost:11434/v1/` es correcto.
2. **Confirma que Ollama esté escuchando más allá del loopback.** De forma predeterminada, Ollama se vincula a `127.0.0.1`, al cual un contenedor no puede acceder. Establece `OLLAMA_HOST=0.0.0.0` en el propio entorno de Ollama y reinícialo.

   <Callout type="warning" title="Vincular a 0.0.0.0 expone Ollama en todas las interfaces">
   La API de Ollama no está autenticada. Vincularla a `0.0.0.0` en una máquina con una interfaz LAN o pública otorga acceso al modelo, así como la capacidad de descargar y eliminar modelos, a cualquier persona que pueda acceder al puerto 11434. Es preferible vincularla únicamente a la dirección a la que realmente llega el contenedor de LibreChat, que es la puerta de enlace de su red de compose (`docker network inspect <network>` lo indica), y configurar el firewall en el puerto 11434 para que nadie más pueda acceder a él.
   </Callout>
3. **Conozca los cambios en el nombre del endpoint.** LibreChat accede a la ruta nativa `/api/tags` de Ollama solo cuando el `name` del endpoint comienza con `ollama`, sin distinguir entre mayúsculas y minúsculas. Cualquier otro nombre, o un fallo en esa llamada nativa, recurre a la solicitud genérica `/v1/models` compatible con OpenAI. Las versiones actuales de Ollama también responden a esa solicitud en la URL base `/v1/` mencionada anteriormente, por lo que un endpoint renombrado generalmente sigue devolviendo una lista de modelos. El prefijo es importante cuando necesita específicamente la ruta de etiquetas nativa, y un proxy alojado que sirve `/v1/models` pero no `/api/tags` funciona mejor sin él.
4. **Establece `apiKey` en cualquier marcador de posición que no esté vacío.** Ollama ignora el valor, pero un endpoint personalizado sin `apiKey` se descarta al cargar la configuración.
5. **Lea los registros de la API.** `docker compose logs api` informa sobre el error de conexión y la URL que realmente intentó utilizar.

### Uso de un servidor Ollama remoto o alojado [#using-a-remote-or-hosted-ollama-server]

Nada es específico de la configuración local excepto la URL: apunte `baseURL` a la ruta compatible con OpenAI del servidor remoto y coloque la credencial en `apiKey` en lugar del marcador de posición. Asígnele el nombre que desee: la obtención de modelos recurre a la ruta `/v1/models` compatible con OpenAI, que es lo que normalmente expone un proxy alojado.

`apiKey` solo se envía como `Authorization: Bearer <key>`, y únicamente cuando su bloque `headers` no haya establecido ya un encabezado `Authorization`. Si su proxy alojado espera un esquema diferente, como `X-API-Key` o autenticación básica, coloque la credencial real en `headers`: una entrada `Authorization` allí reemplaza el respaldo Bearer, y cualquier otro encabezado se envía junto con él. `apiKey` debe seguir siendo no vacío de cualquier manera, porque un endpoint sin uno se descarta al cargar la configuración.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
