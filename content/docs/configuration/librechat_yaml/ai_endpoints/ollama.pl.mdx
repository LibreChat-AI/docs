Ollama uruchamia otwarte modele lokalnie i udostępnia API zgodne z OpenAI, dzięki czemu możesz skierować LibreChat na własną maszynę. Pobieraj modele za pomocą `ollama run <model>` i przeglądaj dostępne opcje w [Ollama Library](https://ollama.com/library).

## Konfiguracja [#configuration]

Ollama ignoruje klucz API, ale nadal wymaga obecności tego pola, więc ustaw je na dowolny symbol zastępczy. Skieruj `baseURL` na swój serwer Ollama. Dodaj endpoint do listy `custom` w sekcji `endpoints` w pliku `librechat.yaml`. Jeśli Twój plik posiada już listę `endpoints.custom`, wklej do niej tylko wpis `- name:`, zachowując to samo wcięcie:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## Uwagi [#notes]

- Ustaw `titleModel` na `"current_model"`, aby generowanie tytułu wykorzystywało model używany w konwersacji zamiast ładowania drugiego. Dzięki temu Ollama utrzymuje tylko jeden załadowany model na konwersację.
- Powyższa tablica `default` to przykładowa lista popularnych modeli. Dzięki `fetch: true`, LibreChat pobiera pełną listę z Twojego serwera.

<Callout type="tip" title="Ollama -> llama3">

Gdy `stop` zostało usunięte z [parametrów domyślnych](/docs/configuration/librechat_yaml/object_structure/default_params), poniższy problem nie powinien już występować.

Jeśli `llama3` generuje tekst bez zatrzymywania się, dodaj blok `addParams` z sekwencjami zatrzymania:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Jeśli używasz tylko `llama3` z Ollama, ustawienie `stop` na poziomie konfiguracji poprzez `addParams` jest w porządku. Gdy uruchamiasz kilka modeli, dodawaj sekwencje stop z poziomu interfejsu użytkownika poprzez parametry konwersacji i presety, a `addParams` pomiń:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

Ustaw sekwencje stop w parametrach konwersacji (i zapisz je jako preset). Otwórz konwersację w endpoint Ollama, otwórz prawy panel parametrów i dodaj każdą sekwencję w sekcji **Stop Sequences**:

![Panel parametrów konwersacji LibreChat z czterema sekwencjami zatrzymania llama3 wprowadzonymi w polu Stop Sequences](https://github.com/danny-avila/LibreChat/assets/110412045/57460b8c-308a-4d21-9dfe-f48a2ac85099)

</Callout>

## Rozwiązywanie problemów [#troubleshooting]

### Ollama nie pojawia się lub lista modeli jest pusta [#ollama-does-not-appear-or-the-model-list-is-empty]

Wykonaj te kroki w podanej kolejności:

1. **Sprawdź, czy endpoint jest osiągalny z poziomu LibreChat, a nie z Twojej powłoki (shell).** Jeśli LibreChat działa w Docker, `localhost` oznacza sam kontener API, a nie hosta. Użyj `http://host.docker.internal:11434/v1/` w Docker Desktop lub adresu LAN hosta w systemie Linux, gdzie `host.docker.internal` może być niedostępny. Uruchomienie LibreChat poza Docker to jedyny przypadek, w którym `http://localhost:11434/v1/` jest poprawnym adresem.
2. **Upewnij się, że Ollama nasłuchuje poza interfejsem loopback.** Domyślnie Ollama wiąże się z adresem `127.0.0.1`, do którego kontener nie ma dostępu. Ustaw `OLLAMA_HOST=0.0.0.0` w środowisku Ollama i zrestartuj ją.

   <Callout type="warning" title="Powiązanie z 0.0.0.0 udostępnia Ollama na każdym interfejsie">
   API Ollama jest nieuwierzytelnione. Powiązanie go z `0.0.0.0` na maszynie z interfejsem LAN lub publicznym daje dostęp do modeli, a także możliwość ich pobierania i usuwania, każdemu, kto ma dostęp do portu 11434. Preferowane jest powiązanie tylko z adresem, do którego faktycznie dociera kontener LibreChat, czyli bramą jego sieci compose (raportuje to `docker network inspect <network>`), oraz zabezpieczenie portu 11434 firewallem, aby nikt inny nie mógł uzyskać do niego dostępu.
   </Callout>
3. **Wiedz, co zmienia nazwa endpoint.** LibreChat sięga po natywny endpoint Ollama `/api/tags` tylko wtedy, gdy `name` endpointu zaczyna się od `ollama` (wielkość liter nie ma znaczenia). Każda inna nazwa lub niepowodzenie tego natywnego wywołania powoduje przejście do ogólnego żądania `/v1/models` zgodnego z OpenAI. Obecne wersje Ollama odpowiadają również na to żądanie pod powyższym adresem bazowym `/v1/`, więc zmieniony endpoint zazwyczaj nadal zwraca listę modeli. Prefiks ma znaczenie, gdy konkretnie potrzebujesz natywnej ścieżki tagów, a hostowany proxy, który obsługuje `/v1/models`, ale nie `/api/tags`, lepiej działa bez niego.
4. **Ustaw `apiKey` na dowolny niepusty symbol zastępczy.** Ollama ignoruje tę wartość, ale niestandardowy endpoint bez `apiKey` jest odrzucany podczas ładowania konfiguracji.
5. **Przeczytaj logi API.** `docker compose logs api` zgłasza błąd połączenia oraz adres URL, z którym faktycznie próbowano się połączyć.

### Korzystanie ze zdalnego lub hostowanego serwera Ollama [#using-a-remote-or-hosted-ollama-server]

Nic nie jest specyficzne dla lokalnego środowiska poza adresem URL: skieruj `baseURL` na ścieżkę zgodną z OpenAI na zdalnym serwerze i umieść poświadczenia w `apiKey` zamiast symbolu zastępczego. Nazwij to, jak chcesz: pobieranie modeli korzysta z domyślnej ścieżki `/v1/models` zgodnej z OpenAI, którą zazwyczaj udostępnia hostowane proxy.

`apiKey` jest zawsze wysyłany jako `Authorization: Bearer <key>` i tylko wtedy, gdy Twój blok `headers` nie ustawił już nagłówka `Authorization`. Jeśli Twój hostowany serwer proxy oczekuje innego schematu, takiego jak `X-API-Key` lub uwierzytelnianie Basic, umieść właściwe dane uwierzytelniające w `headers`: wpis `Authorization` w tym miejscu zastępuje mechanizm zastępczy Bearer, a każdy inny nagłówek jest wysyłany wraz z nim. `apiKey` w obu przypadkach musi być niepusty, ponieważ punkt końcowy (endpoint) bez niego jest odrzucany podczas wczytywania konfiguracji.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
