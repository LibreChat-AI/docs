Ollama menjalankan model terbuka secara lokal dan mengekspos API yang kompatibel dengan OpenAI, sehingga Anda dapat mengarahkan LibreChat ke mesin Anda sendiri. Unduh model dengan `ollama run <model>` dan telusuri apa yang tersedia di [Ollama Library](https://ollama.com/library).

## Konfigurasi [#configuration]

Ollama mengabaikan API key namun tetap mengharapkan kolom tersebut ada, jadi atur ke placeholder apa pun. Arahkan `baseURL` ke server Ollama Anda. Tambahkan endpoint ke daftar `custom` di bawah `endpoints` dalam `librechat.yaml` Anda. Jika file Anda sudah memiliki daftar `endpoints.custom`, tempelkan hanya entri `- name:` ke dalamnya, dengan tetap mempertahankan indentasi yang sama:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      # use 'host.docker.internal' instead of localhost if running LibreChat in a docker container
      baseURL: "http://localhost:11434/v1/" 
      models:
        default: [
          "llama2",
          "mistral",
          "codellama",
          "dolphin-mixtral",
          "mistral-openorca"
          ]
        # fetching list of models is supported but the `name` field must start
        # with `ollama` (case-insensitive), as it does in this example.
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
```

## Catatan [#notes]

- Atur `titleModel` ke `"current_model"` agar pembuatan judul menggunakan kembali model percakapan alih-alih memuat model kedua. Hal ini menjaga Ollama agar tetap menggunakan satu model yang dimuat per percakapan.
- Array `default` di atas adalah contoh daftar model populer. Dengan `fetch: true`, LibreChat akan menarik daftar lengkap dari server Anda.

<Callout type="tip" title="Ollama -> llama3">

Setelah `stop` dihapus dari [default parameters](/docs/configuration/librechat_yaml/object_structure/default_params), masalah di bawah ini seharusnya tidak lagi terjadi.

Jika `llama3` terus menghasilkan teks tanpa berhenti, tambahkan blok `addParams` dengan urutan berhenti (stop sequences):

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: [
          "llama3"
        ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      summarize: false
      summaryModel: "current_model"
      modelDisplayLabel: "Ollama"
      addParams:
          "stop": [
              "<|start_header_id|>",
              "<|end_header_id|>",
              "<|eot_id|>",
              "<|reserved_special_token"
          ]
```

Jika Anda hanya menjalankan `llama3` dengan Ollama, mengatur `stop` di tingkat konfigurasi melalui `addParams` sudah cukup. Saat Anda menjalankan beberapa model, tambahkan urutan berhenti (stop sequences) dari frontend melalui parameter percakapan dan preset sebagai gantinya, dan hilangkan `addParams`:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/" 
      models:
        default: [
          "llama3:latest",
          "mistral"
          ]
        fetch: false # pinned to the list above; set true to discover models from the server
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "Ollama"
```

Atur urutan berhenti (stop sequences) dalam parameter percakapan (dan simpan sebagai preset). Buka percakapan pada endpoint Ollama, buka panel parameter di sisi kanan, dan tambahkan setiap urutan di bawah **Stop Sequences**:

![Panel parameter percakapan LibreChat dengan empat urutan berhenti llama3 dimasukkan di kolom Stop Sequences](https://github.com/danny-avila/LibreChat/assets/110412045/57460b8c-308a-4d21-9dfe-f48a2ac85099)

</Callout>

## Pemecahan Masalah [#troubleshooting]

### Ollama tidak muncul, atau daftar model kosong [#ollama-does-not-appear-or-the-model-list-is-empty]

Kerjakan langkah-langkah ini secara berurutan:

1. **Pastikan endpoint dapat dijangkau dari LibreChat, bukan dari shell Anda.** Jika LibreChat berjalan di Docker, `localhost` adalah container API itu sendiri, bukan host Anda. Gunakan `http://host.docker.internal:11434/v1/` pada Docker Desktop, atau alamat LAN host di Linux di mana `host.docker.internal` mungkin tidak tersedia. Menjalankan LibreChat di luar Docker adalah satu-satunya kasus di mana `http://localhost:11434/v1/` adalah benar.
2. **Pastikan Ollama mendengarkan di luar loopback.** Secara default, Ollama melakukan binding ke `127.0.0.1`, yang tidak dapat dijangkau oleh container. Atur `OLLAMA_HOST=0.0.0.0` di lingkungan Ollama itu sendiri dan mulai ulang (restart) aplikasinya.

   <Callout type="warning" title="Melakukan binding ke 0.0.0.0 akan mengekspos Ollama di setiap antarmuka">
   API Ollama tidak memiliki autentikasi. Mengikatnya ke `0.0.0.0` pada mesin dengan antarmuka LAN atau publik akan memberikan akses model, serta kemampuan untuk menarik dan menghapus model, kepada siapa pun yang dapat menjangkau port 11434. Sebaiknya ikat hanya ke alamat yang benar-benar dijangkau oleh kontainer LibreChat, yaitu gateway dari jaringan compose-nya (`docker network inspect <network>` akan menampilkannya), dan pasang firewall pada port 11434 agar tidak ada pihak lain yang dapat menjangkaunya.
   </Callout>
3. **Ketahui perubahan nama endpoint.** LibreChat hanya akan mengakses `/api/tags` bawaan Ollama jika `name` endpoint diawali dengan `ollama`, tanpa mempedulikan huruf besar atau kecil. Nama lain, atau kegagalan panggilan bawaan tersebut, akan beralih ke permintaan `/v1/models` yang kompatibel dengan OpenAI secara umum. Versi Ollama saat ini juga menjawab permintaan tersebut di URL dasar `/v1/` di atas, sehingga endpoint yang diganti namanya biasanya tetap mengembalikan daftar model. Awalan tersebut penting ketika Anda secara khusus memerlukan rute tag bawaan, dan proxy yang dihosting yang melayani `/v1/models` tetapi tidak melayani `/api/tags` akan lebih baik jika tidak menggunakan awalan tersebut.
4. **Set `apiKey` ke placeholder apa pun yang tidak kosong.** Ollama mengabaikan nilai tersebut, tetapi endpoint kustom tanpa `apiKey` akan dibatalkan saat pemuatan konfigurasi.
5. **Baca log API.** `docker compose logs api` melaporkan kesalahan koneksi dan URL yang sebenarnya dicoba.

### Menggunakan server Ollama jarak jauh atau yang di-host [#using-a-remote-or-hosted-ollama-server]

Tidak ada yang spesifik secara lokal kecuali URL: arahkan `baseURL` ke jalur yang kompatibel dengan OpenAI di server jarak jauh dan masukkan kredensial ke dalam `apiKey` sebagai pengganti placeholder. Beri nama apa pun yang Anda suka: pengambilan model akan kembali ke rute `/v1/models` yang kompatibel dengan OpenAI, yang biasanya merupakan apa yang diekspos oleh proksi yang dihosting.

`apiKey` is only ever sent as `Authorization: Bearer <key>`, and only when your `headers` block has not already set an `Authorization` header. If your hosted proxy expects a different scheme, such as `X-API-Key` or Basic auth, put the real credential in `headers`: an `Authorization` entry there replaces the Bearer fallback, and any other header is sent alongside it. `apiKey` still has to be non-empty either way, because an endpoint without one is dropped at config load.

```yaml filename="excerpt of librechat.yaml"
- name: "Ollama"
  apiKey: "unused"
  baseURL: "https://ollama.example.com/v1/"
  headers:
    X-API-Key: "${OLLAMA_PROXY_KEY}"
  models:
    default: ["llama3:latest"]
    fetch: true
```
