VoltageGPU provides an OpenAI-compatible endpoint that you can add to LibreChat through `endpoints.custom`. Its models run in a trusted execution environment (Intel TDX guests with confidential-computing GPUs), and every model ID ends in `-TEE`.

## Get an API key

Create an API key from the [VoltageGPU API keys page](https://voltagegpu.com/api-keys). Add it to your `.env` file:

```bash filename=".env"
VOLTAGEGPU_API_KEY=your-api-key
```

## Configuration

Add the endpoint to the `custom` list under `endpoints` in your `librechat.yaml`. If your file already has an `endpoints.custom` list, paste only the `- name:` entry into it, keeping the same indentation:

```yaml filename="librechat.yaml"
endpoints:
  custom:
    - name: "VoltageGPU"
      apiKey: "${VOLTAGEGPU_API_KEY}"
      baseURL: "https://api.voltagegpu.com/v1"
      models:
        default:
          - "Qwen/Qwen3.8-27B-TEE"
          - "deepseek-ai/DeepSeek-V3.2-TEE"
        fetch: true
      titleConvo: true
      titleModel: "Qwen/Qwen3.8-27B-TEE"
      modelDisplayLabel: "VoltageGPU"
```

To let each user supply their own key through the LibreChat UI instead of reading one from `.env`, set `apiKey: "user_provided"`.

## Notes

- With `fetch: true`, LibreChat loads the model list from VoltageGPU's OpenAI-compatible `/v1/models` endpoint. The `default` array is only the initial selection.
- Use model IDs exactly as they appear in the [model list](https://api.voltagegpu.com/v1/models). The API only accepts IDs ending in `-TEE`.
- Each entry in `/v1/models` carries a live `status.state` (`available`, `busy`, `saturated` or `unavailable`) and its price per million tokens. If a selected model is unavailable, choose another chat-capable model from the list.
- `GET /v1/attestation?model=<id>&nonce=<64 hex characters>` returns the Intel TDX quotes and NVIDIA GPU evidence of that model's running instances, bound to your nonce, for you to verify. See the [VoltageGPU documentation](https://docs.voltagegpu.com) for details.
