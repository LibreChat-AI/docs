`webSearch` 設定では、LibreChat 内のウェブ検索機能（検索プロバイダー、コンテンツスクレイパー、結果の再ランキング機能など）をカスタマイズできます。

## 概要 [#overview]

ウェブ検索機能は、主に3つのコンポーネントで構成されています。

1. **Search Providers**: 初期ウェブ検索を実行するサービス
2. **Scrapers**: Webページからコンテンツを抽出するサービス
3. **Rerankers**: 検索結果をより関連性の高い順に並べ替えるサービス

## 例 [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## SSRF Protection and Private Providers [#ssrf-protection-and-private-providers]

LibreChatは、ウェブ検索、スクレイピング、およびリランキングのために開く各接続を検証します。プライベート、ループバック、リンクローカル、およびクラウドメタデータの宛先は、リダイレクトホップや接続時にプライベートアドレスに解決されるホスト名を含め、デフォルトでブロックされます。

設定済みのSearXNG、Firecrawl、Jina、Tavily互換、Keenable互換、または関連するプロバイダーのendpointが意図的にプライベートである場合は、`webSearch.allowedAddresses`を使用してください：

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

このフィールドはSSRF除外リストであり、厳格な許可リストではありません。パブリックな宛先は引き続き利用可能です。エントリは正確な `host:port`、`private.ip:port`、または `[ipv6]:port` のペアである必要があります。URL、パス、CIDR範囲、ホスト名やIPアドレス単体、およびパブリックIPリテラルは拒否されます。除外されたホスト名は、そのポートで解決されるプライベートIPを信頼するため、プライベートIPリテラルを優先し、DNSを自身で管理している名前のみをリストしてください。

LibreChatは、設定されたHTTP(S)フォワードプロキシエンドポイントを自動的に除外するため、そのエンドポイントに到達可能です。プロキシがリクエストを運ぶ際、宛先を解決し、宛先へのエグレス（送信）をプロキシ自身で強制する必要があります。`NO_PROXY` を使用するとリクエストを直接送信できますが、その場合でもLibreChatの接続ガードが適用されます。このガードはLibreChatがプロバイダーAPIに対して開く接続を対象としていますが、サードパーティのスクレイパーがリクエストデータとして受け取り、独自のインフラストラクチャ上でフェッチするページURLを制限することはできません。

## 認証情報の所有権 [#credential-ownership]

ユーザーが提供したFirecrawl、SearXNG、またはJinaのURLに対して、サーバー所有のAPIキーを渡してはなりません。SSRF検証を行っても、公開されているユーザー選択型エンドポイントがデプロイメントの認証情報を受け取るのに安全になるわけではありません。URLとキーは管理者所有の設定としてセットで構成するか、ユーザー自身にペアを提供させるようにしてください。なお、SearXNGはキーなしで実行することも可能です。

保存されたユーザーURLがサーバーのキーと組み合わされる場合、LibreChatはFirecrawlのオプションURLを無視し、デフォルトのendpointを使用します。SearXNGのインスタンスURLは必須であるため、所有者が混在する構成は認証されず、検索ツールは初期化されません。サーバーのキーを使用するセルフホスト環境では、ユーザーが保存したURLに依存するのではなく、そのキーと併せて `FIRECRAWL_API_URL` または `SEARXNG_INSTANCE_URL` を設定してください。プライベートendpointには、引き続き [`allowedAddresses`](#ssrf-protection-and-private-providers) が必要です。

```yaml filename="webSearch"
webSearch:
```

```yaml filename="webSearch"
    engines: "google, bing, startpage, qwant"
```

#### エンジンの選択 [#choosing-engines]

エンジン名は、自身のインスタンスで有効になっているエンジンと一致している必要があり、それには以下の2つのことが伴います。

- SearXNGは、認識できないエンジンをエラーとして報告するのではなく無視します。タイプミスやインスタンスで無効化されているエンジンがある場合、失敗するのではなく、結果が少なく表示されます。
- 有効な名前はインスタンス固有のものです。有効なすべてのエンジンを含むJSONを返す `https://your-instance/config` で有効なリストを確認するか、インスタンスの設定ページの **Engines** タブを開いてください。

デフォルトは `google,bing,duckduckgo` です。SearXNGは選択されたエンジンが返す結果をすべて集約するため、1つのエンジンがブロックされても応答全体が失われるのではなく、そのエンジン分の結果が失われるだけです。検索結果が空になるのは、選択されたすべてのエンジンが失敗したか、何も返さなかった場合のみです。

DuckDuckGoは、デフォルトのセットの中で最もブロックされる可能性が高いエンジンです。これは、ほとんどのセルフホストインスタンスに対してCAPTCHAを表示するためです。セット内にエンジンが3つしかない場合、レート制限のかかったGoogleやBingと同時に使用できなくなると、結果が全く得られなくなることがよくあります。`engines`を明示的に設定し、DuckDuckGoを除外し、3つ以上のエンジンをリストアップすることで、そのリスクを軽減できます。

応答が速く、セルフホストのトラフィックを許容するエンジンが最適な初期セットとなります。例：

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

エンジンを追加すると検索範囲は広がりますが、SearXNGはセット内の最も遅いエンジンの応答を待ってから返答するため、すべての検索が遅くなります。リストを増やす際は `timeout` に注意してください。

#### これらのオプションが制御しないもの [#what-these-options-do-not-control]

- **Safe search** はこのブロックの一部ではありません。これはトップレベルの [`safeSearch`](#safesearch) キーから取得され、`safesearch` として SearXNG に転送されます。
- **Result categories**はLibreChatによってクエリごとに選択され、検索タイプを`general`、`images`、`videos`、または`news`にマッピングします。これらはここで上書きすることはできません。
- **ページ番号と結果の形式**は固定されています。LibreChatは常にJSON形式で1ページ目を要求するため、インスタンスの`formats`設定で`json`を有効にする必要があります。

## 注記 [#notes]

- API keysは、以下の2つの方法で設定できます：
  1. YAML設定で指定された環境変数を設定します
  2. 環境変数が設定されていない場合、ユーザーはUI経由でAPIキーを入力するよう求められます。
- この設定は、各コンポーネント（プロバイダー、スクレイパー、リランカー）に対して複数のサービスをサポートしています。
- 特定のサービスタイプが指定されていない場合、システムはそのカテゴリ内の利用可能なすべてのサービスを試行します。
- セーフサーチには、OFF (0)、MODERATE (1)、STRICT (2) という3段階のコンテンツフィルタリングレベルが用意されています。
- Tavilyはデフォルトではグローバルなセーフサーチ設定を継承しません。Tavilyアカウントが `safe_search` をサポートしている場合にのみ、`tavilySearchOptions.safeSearch` を明示的に設定してください。
- Keenableはキーレス検索とページ取得をサポートしています。オプションのキーを設定することでパブリックなレート制限を引き上げることができ、フェッチURLのオーバーライドは環境変数でのみ可能です。
- SearXNGのクエリ動作（エンジン、言語、期間、リクエストタイムアウト）は `searxngSearchOptions` で設定されます。検索結果が空で返ってくる場合は、[Choosing engines](#choosing-engines) を参照してください。
- 実際のAPIキーをYAML設定に記述しないでください。環境変数名のみを使用してください。

## SearXNG のセットアップ [#setting-up-searxng]

SearXNGは、セルフホスト可能なプライバシー重視のメタ検索エンジンです。
詳細については、[公式SearXNGドキュメント](https://docs.searxng.org/)を参照してください。

LibreChatで使用するために独自のSearXNGインスタンスをセットアップする手順は以下の通りです：

### Docker Desktop を使用する [#using-docker-desktop]

1. **公式のSearXNGイメージを検索する**
   - Docker Desktop を開く
   - **Images** タブで `searxng/searxng` を検索します
   - 公式イメージの **Run** をクリックすると、そのイメージのコンテナが自動的にプルされ、実行されます。

2. **コンテナの実行**
   - ダウンロードが完了した後に表示されるパネルの **Optional Settings** ドロップダウンを展開します。
   - 希望する設定の詳細（ポート番号、コンテナ名など）を設定します。
   - **Run**をクリックしてコンテナを開始します

3. **LibreChat 用に SearXNG を設定する**
   - Docker Desktopの `Files` タブに移動します
   - `/etc/searxng/settings.yaml` に移動します
   - ファイルエディターを開く
   - `formats` セクションに移動します
   - `json` を許容されるフォーマットとして追加し、LibreChat があなたのインスタンスと通信できるようにします。
   - ファイルを保存

4. **コンテナを再起動します**
   - 変更を反映させるには、コンテナを再起動してください。

### LibreChatでSearXNGを使用するように設定する [#configuring-librechat-to-use-searxng]

LibreChatでは、UI内または `librechat.yaml` を通じてSearXNGを設定できます。

#### UI設定 [#ui-configuration]

1. **[メッセージコンポーザー](/docs/features/composer)の + をクリックしてパレットを開きます**

2. **ToolsセクションのWeb Search行にあるConfigureを選択します**

3. **検索プロバイダーのドロップダウンからSearXNGを選択します**
![SearXNG dropdown selection](/images/web-search/searxng_dropdown_highlight.png)

4. **設定の詳細（インスタンスURL、スクレーパーの種類など）を入力し、保存をクリックします**
![Web検索設定を保存](/images/web-search/web_search_save.png)

5. **パレットのToolsセクションでWeb Searchを選択します**

6. **Web Searchチップがコンポーザー上に表示されるようになり、クエリでWeb検索を利用できるようになりました**

#### YAML 設定 [#yaml-configuration]

インスタンス上のすべてのユーザーに対してSearXNGを設定するには（ユーザーごとではなく）、`librechat.yaml` に同じ値を設定します：

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

URLとキーは引き続き環境変数から読み込まれるため、上記の構成と以下を組み合わせてください：

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="プライベートインスタンスには allowedAddresses エントリが必要です">
`localhost:55011` はループバックアドレスであり、LibreChatの [SSRF protection](#ssrf-protection-and-private-providers) によって接続時にブロックされます。一致する `allowedAddresses` エントリがない場合、SearXNGが正常であっても検索は失敗します。このエントリは、インスタンスURLの正確な `host:port` ペアである必要があります。

LibreChat 自体が Docker 内で実行されている場合、`localhost` は LibreChat コンテナを指し、SearXNG コンテナを指すわけではありません。コンテナが到達可能なホスト名（compose サービス名など）を使用し、代わりにそれを除外してください：

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

このブロックが受け入れるすべてのサブキーについては、[`searxngSearchOptions`](#searxngsearchoptions) を参照してください。

#### 空の結果のトラブルシューティング [#troubleshooting-empty-results]

SearXNGの検索結果が何も返されない場合、それはLibreChatが結果を破棄しているのではなく、リクエストが正常に動作しているインスタンスに到達していないことがほとんどです。以下の手順を順番に確認してください：

1. **インスタンスがプライベートアドレスであり、`allowedAddresses` エントリが存在しません。** LibreChatは接続時にループバックおよびプライベート宛先をブロックするため、セルフホストインスタンスでは、その正確な `host:port` を [`allowedAddresses`](#ssrf-protection-and-private-providers) にリストする必要があります。これにより、空の結果セットを返すのではなく、リクエストが完全にブロックされます。
2. **`json` が `formats` に含まれていません。** LibreChat は結果を JSON として要求します。インスタンス設定ファイルの `formats` セクションに `json` が記載されていない場合、インスタンスはエラーページを返し、すべての検索結果が空になります。これは上記の Docker セットアップのステップ 3 です。
3. **選択されたすべてのエンジンが失敗しました。** SearXNGは応答があったエンジンのみを統合するため、空の応答はどのエンジンからも何も返ってこなかったことを意味します。DuckDuckGoはデフォルトのセット（`google,bing,duckduckgo`）に含まれていますが、ほとんどのセルフホストインスタンスに対してCAPTCHAを要求するため、検索を実行できるエンジンが2つだけになってしまいます。`searxngSearchOptions.engines`を明示的に設定し、DuckDuckGoを除外した上で、他のエンジンをいくつかリストに追加してください。
4. **インスタンス上にエンジン名が存在しません。** SearXNGは認識できないエンジンを警告なしにスキップするため、タイプミスがあると単に結果が少なくなるだけです。リストを `https://your-instance/config` と比較してください。
5. **インスタンスがタイムアウトよりも低速です。** インスタンスが多くのエンジンにクエリを送信している場合や、低速なネットワーク経由で接続されている場合は、`searxngSearchOptions.timeout` をデフォルトの `10000` より高い値に設定してください。

LibreChatが送信する内容を再現するには、インスタンスを直接呼び出します：

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

これは自身のマシンから実行されるため、LibreChatの接続ガードを完全にバイパスします。ここで `results` 配列が空であれば、問題がSearXNG側にあることが確認できます。ここで結果が表示されるにもかかわらずLibreChatで何も見つからない場合は、`allowedAddresses` に原因があることを示しています。
