## maxProviderErrorChars

Mengontrol seberapa banyak teks kesalahan penyedia yang dipertahankan oleh LibreChat ketika kegagalan Agen tidak dapat diklasifikasikan. Defaultnya adalah `2000` karakter. Atur ke `0` untuk menghilangkan teks penyedia; nilai maksimumnya adalah `1000000`.

```yaml filename="endpoints / agents / maxProviderErrorChars"
maxProviderErrorChars: 2000
```

## repositoryInstructions

Mengontrol penemuan instruksi repositori untuk lingkungan Kode yang dilampirkan. `timeoutMs` membatasi permintaan pemuatan instruksi dari `100` hingga `30000` milidetik dan secara default bernilai `2000`.

```yaml filename="endpoints / agents / repositoryInstructions"
repositoryInstructions:
  timeoutMs: 2000
```

## Pemutus arus stream [#stream-circuit-breakers]

Pengaturan ini menghentikan eksekusi Agent ketika aliran (stream) penyedia tampak menghasilkan argumen alat yang tidak terkendali atau urutan peristiwa delta yang tidak terbatas.

<OptionTable
  options={[
    [
      'maxToolCallArgBytes',
      'Number',
      'Batas maksimum akumulasi byte untuk argumen satu panggilan tool yang di-stream. Atur ke 0 untuk menonaktifkan pelindung global.',
      '65536',
    ],
    [
      'maxDeltaEventsPerTurn',
      'Number',
      'Jumlah maksimum peristiwa yang dialirkan untuk satu giliran pembuatan model. Atur ke 0 atau abaikan untuk menonaktifkan pelindung ini.',
      '0 (disabled)',
    ],
    [
      'maxToolCallArgBytesByTool',
      'Object',
      'Penggantian byte argumen per-alat yang dikunci berdasarkan nama alat yang menghadap model. Nilai 0 menonaktifkan pelindung untuk alat tersebut.',
      'create_file: 131072',
    ],
  ]}
/>

LibreChat menggunakan batas argumen global 64 KiB dan menyertakan penggantian (override) 128 KiB untuk `create_file`, yang payload sahnya sering kali lebih besar. Entri dalam `maxToolCallArgBytesByTool` akan menggabungkan penggantian bawaan tersebut. Jika salah satu batasan terlampaui, LibreChat akan membatalkan stream penyedia yang sedang berjalan dan melaporkan batas mana yang terlampaui.

```yaml filename="endpoints / agents / stream circuit breakers"
maxToolCallArgBytes: 65536
maxDeltaEventsPerTurn: 100000
maxToolCallArgBytesByTool:
  create_file: 262144
  large_import: 524288
```

Untuk menonaktifkan setiap penjaga ukuran argumen, atur batas global dan penggantian `create_file` bawaan ke `0`:

```yaml
maxToolCallArgBytes: 0
maxToolCallArgBytesByTool:
  create_file: 0
```

## activityLabel

Atur `activityLabel: true` untuk mengelompokkan setiap blok penalaran Agen dan panggilan alat di bawah satu header satu baris yang dibuat secara otomatis. Gunakan `activityModel`, `activityEndpoint`, `activityPrompt`, `activityMaxPerRun`, dan `activityCharLimit` untuk mengontrol panggilan model tambahan beserta biayanya. Lihat [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) untuk referensi bidang lengkap dan aturan prioritas.

```yaml filename="endpoints / agents / activity groups"
activityLabel: true
activityEndpoint: openAI
activityModel: gpt-4.1-nano
activityMaxPerRun: 20
activityCharLimit: 600
activityPhaseLabel: true
activityPhaseMaxPerRun: 5
```

`activityPhaseLabel` dapat secara independen menambahkan satu ringkasan induk yang diciutkan di sekitar setiap fase proses yang berisi setidaknya dua aktivitas logis. Gunakan `activityPhaseModel`, `activityPhaseEndpoint`, `activityPhasePrompt`, dan `activityPhaseMaxPerRun` untuk menyesuaikan panggilan tersebut; `activityCharLimit` digunakan bersama dengan label aktivitas anak.

## capabilities

<OptionTable
  options={[
    [
      'capabilities',
      'Array/List of Strings',

      'Defines the agent capabilities that are available to all users for the agents endpoint. You can omit the capabilities you wish to exclude from the list.',
    ],

**Default:** `["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "ocr"]`

`programmatic_tools`, `stateful_code_sessions`, `run_in_background`, dan `tool_intents` bersifat opt-in dan harus ditambahkan secara eksplisit. Programmatic tools dan stateful sessions juga memerlukan `execute_code` serta deployment Code Interpreter yang kompatibel; untuk `programmatic_tools`, itu berarti deployment yang memiliki komponen Tool Call Server. Agent Builder menonaktifkan pilihan Programmatic MCP tanpa Code Interpreter, dan server menghapus opsi caller programmatic yang sudah usang ketika eksekusi kode tidak tersedia. `run_in_background` membuat tool Code Interpreter memenuhi syarat secara default dan memungkinkan opt-in per-tool untuk tool MCP, Plugin, dan Action yang memenuhi syarat; eksekusi kode di latar belakang juga memerlukan `execute_code` dan Code Interpreter.

`stateful_code_sessions` masih sangat eksperimental. Fitur ini memerlukan rute Code Interpreter dengan profil `stateful` terpisah yang dikonfigurasi dengan [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) atau [`statefulCodeSessions.environments`](#statefulcodesessions). Permintaan stateful akan gagal secara tertutup (fail closed) alih-alih beralih ke layanan stateless normal. Di dalam Agent Builder, setiap Agen yang diaktifkan memilih cakupan ruang kerja pengguna (user), agen-dan-pengguna (agent-and-user), atau percakapan (conversation) dan, jika backend bernama dikonfigurasi, lingkungan eksekusi. Agen baru dimulai dengan cakupan default pribadi pengguna dan lingkungan eksekusi default penyebaran.

**Contoh:**

```yaml filename="endpoints / agents / capabilities"
capabilities:
  - 'deferred_tools'
  # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
  # Requires execute_code and a Code Interpreter deployment with the Tool Call Server component.
  # - 'programmatic_tools'
  - 'execute_code'
  - 'file_search'
  - 'web_search'
  - 'artifacts'
  - 'subagents'
  - 'actions'
  - 'context'
  - 'skills'
  - 'memory'
  - 'ask_user_question'
  - 'tools'
  - 'ocr'
  # Optional and highly experimental: reuse a user-, agent-and-user-, or
  # conversation-scoped workspace. Requires LIBRECHAT_CODE_BASEURL_STATEFUL
  # or a named statefulCodeSessions environment.
  # - 'stateful_code_sessions'
  # Optional: allow eligible Code Interpreter, MCP, Plugin, and Action tools to run as background tasks.
  # - 'run_in_background'
  # Optional: show live model-written intent labels for native and selected MCP tools.
  # - 'tool_intents'
```

**Catatan:** Bidang ini bersifat opsional. Jika diabaikan, perilaku defaultnya adalah menyertakan semua kapabilitas yang tercantum dalam default.

`chain`, `hide_sequential_outputs`, dan `end_after_tools` adalah nilai lama. Nilai-nilai ini masih diterima agar konfigurasi lama tetap valid, tetapi nilai tersebut tidak termasuk dalam daftar default. `chain` sudah tidak digunakan lagi (deprecated): penulisan chain telah dihentikan dan nilai ini tidak memiliki efek apa pun.

Lingkungan yang dilampirkan menerima `environments[].configSchema.limits.maxQueueWaitMs`, yang mengontrol berapa lama permintaan boleh mencoba kembali menunggu kapasitas ruang kerja. Nilai default dan maksimumnya adalah `300000` milidetik (5 menit). Atur ke `0` untuk menonaktifkan percobaan ulang klien setelah upaya penerimaan awal; ini tidak membatalkan pekerjaan yang sudah diterima atau sedang berjalan. Bidang-bidang ini termasuk di bawah `configSchema.limits`, **bukan** `userConfig.bash`.

`environments[].configSchema.limits.maxRequestTimeoutMs` secara opsional membatasi **total waktu HTTP untuk satu panggilan alat ruang kerja**, termasuk admisi, eksekusi, penyelesaian, dan pengiriman. Nilai ini menerima `1` hingga `610000` ms, namun konfigurasi akan menolak anggaran yang terlalu kecil untuk menyisakan waktu eksekusi perintah setelah admisi dan cadangan penyelesaian/pengiriman selama 10 detik. Tanpanya, admisi tetap memiliki anggaran 30 detik per percobaan; `maxQueueWaitMs` tetap menjadi cakrawala percobaan ulang yang terpisah. **Jangan aktifkan admisi yang lebih lama** sampai setiap replika API LibreChat memahami kolom ini, rute API Kode menghormati alokasi antrean per permintaan, dan batas waktu terpendek di seluruh jalur proksi/ingress yang aktif telah diukur. Mutasi yang kedaluwarsa mungkin telah selesai di pekerja, jadi LibreChat tidak melakukan percobaan ulang untuk batas waktu yang ambigu.

Dengan anggaran permintaan total, `environments[].configSchema.limits.minCommandAdmissionMs` menyediakan waktu bagi sebuah perintah untuk masuk ke worker sebelum eksekusi dimulai. Nilai default-nya adalah `10000` ms; nilai yang dapat diatur berkisar dari `1000` hingga `300000` ms. Anggaran permintaan harus **melebihi** alokasi ini ditambah 10000 ms untuk masa tenggang penyelesaian/pengiriman. Tanpa anggaran total, pengaturan ini tidak berpengaruh. Batas eksekusi Bash yang ditampilkan kepada Agent adalah nilai yang lebih kecil antara batas yang dikonfigurasi atau batas atas dari upstream, dan waktu yang tersisa setelah cadangan-cadangan tersebut. Sebagai contoh, anggaran permintaan 90000 ms dengan batas perintah 80000 ms dan cadangan default akan menampilkan perintah dengan batas paling tinggi 70000 ms.

`environments[].configSchema.admission` mengontrol bagaimana lingkungan yang terpasang menunggu kapasitas workspace. Opsi ini bersifat ketat, sehingga kunci yang tidak dikenal akan gagal pada validasi.

      name: Personal Code Workers
      type: attached

        # edits:

        permissions:

`allowedEnvironments` wajib ada kapan pun blok tersebut disertakan dan harus mencakup setidaknya satu cakupan ruang kerja (workspace scope). Hilangkan seluruh blok untuk mengizinkan ketiga cakupan tersebut dan terus merutekan pekerjaan stateful melalui [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint). Default pribadi dan Agent Builder hanya mengizinkan nilai yang diperbolehkan. Jika administrator memperketat kebijakan, default pribadi yang tersimpan akan tetap terlihat namun dinonaktifkan, dan Agen baru akan menggunakan cakupan pertama yang diperbolehkan. Agen yang sudah diaktifkan akan tetap mempertahankan cakupan yang tersimpan, namun cakupan yang kini tidak diperbolehkan akan gagal secara tertutup (fails closed) saat runtime hingga Agen dikonfigurasi ulang.

`conversationMoves.enabled: true` memungkinkan pemilik percakapan secara eksplisit memindahkan ruang kerja terlampir yang tersegel ke lingkungan yang kompatibel dan memulihkan ruang kerja yang hilang tanpa mengganti riwayat chat maupun memulihkan file ruang kerja lama. Untuk juga mengizinkan chat tersimpan untuk **melampirkan** ruang kerja atau **melepaskan** ruang kerja agar kembali ke chat biasa, atur `conversationMoves.allowAttachDetach: true`. Kedua sakelar ini nonaktif secara default; mengaktifkan moves saja tetap mempertahankan perilaku hanya-pindah. Decision protocol versi 1 diiklankan secara default. Dalam rolling upgrade dari rilis yang belum memilikinya, atur [`CODE_ENVIRONMENT_DECISION_VERSION=0`](/docs/configuration/dotenv#code-interpreter) sebelum replika yang telah ditingkatkan pertama kali dijalankan, tingkatkan **semua** replika API, lalu hapus variabel tersebut (atau atur ke `1`) dan segarkan klien sebelum mengaktifkan opt-in. Kepemilikan, akses target, pekerjaan aktif, dan kebijakan saat ini diperiksa ulang pada saat transisi; generasi yang sedang berjalan tidak dapat dipindahkan.

```yaml filename="endpoints / agents / statefulCodeSessions / conversationMoves"
statefulCodeSessions:
  allowedEnvironments: ['user', 'agent-user', 'conversation']
  conversationMoves:
    enabled: true
    allowAttachDetach: true
```

`principalWorkers` mengontrol pendaftaran mandiri untuk pekerja (worker) pribadi yang terlampir. Nilai yang dihilangkan akan dianggap sebagai `enabled: true` dan `maxPerUser: 5`; atur `enabled: false` atau `maxPerUser: 0` untuk menghentikan pendaftaran baru. Batas tersebut menghitung setiap lingkungan pribadi yang terdaftar untuk pengguna tersebut di seluruh control plane yang dikonfigurasi, termasuk pekerja yang sedang offline. Menurunkan batas atau menonaktifkan pendaftaran tidak akan mencabut lingkungan yang sudah ada.

Deployment YAML adalah batas maksimal yang mutlak. Penggantian konfigurasi peran, grup, atau pengguna dapat menonaktifkan pendaftaran atau menurunkan `maxPerUser`, tetapi tidak dapat menaikkan nilai deployment. Pengguna hanya akan melihat control plane yang mengaktifkan pairing jika batas efektif lebih besar dari nol, [`pairing.allowPrincipalWorkers`](#statefulcodesessions) diaktifkan pada control plane tersebut, autentikasi utama tersedia, dan pengguna memiliki izin pengelolaan Code Environment.

Ketika `environments` tidak kosong, setiap entri memerlukan `id` yang unik, `name` tampilan, `type` berupa `managed` atau `attached`, serta `baseURL` HTTP(S) tanpa string kueri atau fragmen. Jika daftar tersebut berisi lingkungan yang dapat dieksekusi, tepat satu dari entri tersebut harus menetapkan `default: true`. Agent Builder kemudian akan menambahkan pemilih **Execution environment**; membiarkannya pada **Deployment default** akan menggunakan entri default tersebut. Daftar yang hanya berisi control plane pemasangan swalayan tidak memerlukan default. Agen yang menamai lingkungan yang kemudian dihapus atau tidak lagi dapat diakses akan gagal secara tertutup (fails closed) alih-alih beralih ke backend lain.

- `managed` mengarah langsung ke Code API stateful yang dikelola operator.
- `attached` mengarah ke backend `remote-bridge` Code API yang kompatibel yang menyewakan pekerjaan ke worker `@librechat/code` outbound. Worker tersebut tidak memerlukan port publik inbound, tetapi endpoint eksekusi lokalnya tetap memerlukan isolasi yang sesuai.
- `workerId` secara opsional merutekan lingkungan yang terlampir ke satu worker keluar. Ini hanya untuk sisi server dan tidak diekspos melalui konfigurasi startup klien.
- `owner` secara default adalah `deployment`. Lingkungan yang dimiliki oleh principal dibuat melalui API Code Environments LibreChat yang terautentikasi, dilindungi oleh ACL, dan digabungkan hanya untuk permintaan yang diotorisasi; jangan letakkan URL yang disediakan klien di dalam YAML deployment.
- `pairing` bersifat opsional dan hanya valid untuk entri `attached` yang dimiliki oleh deployment. `pairing.workerId` mengidentifikasi worker yang dikelola operator untuk didaftarkan, sementara `pairing.allowPrincipalWorkers: true` memungkinkan pengguna yang berwenang untuk mendaftarkan worker yang terikat dengan pemilik ke control plane tersebut. Setidaknya salah satu dari kolom tersebut wajib diisi jika `pairing` disertakan.
- `pairing.tokenEnv` menamai variabel lingkungan yang berisi token administrator bridge; variabel ini tidak pernah berisi token itu sendiri. Pairing memerlukan HTTPS kecuali untuk pengembangan loopback.
- `configSchema.permissions` secara opsional memungkinkan pemilik yang berwenang untuk memilih kebijakan `fileWrite` dan `commandExecution` untuk lingkungan pribadi di bawah **Settings > Code environments**. Setiap kolom memerlukan daftar `allowed` yang tidak kosong yang berisi `allow`, `ask`, dan/atau `deny`; `default` adalah `ask` jika dihilangkan dan harus muncul di dalam `allowed`. LibreChat akan menolak nilai tersimpan yang berada di luar daftar administrator.
- `configSchema.limits.maxCommandTimeoutMs` menetapkan batas waktu Bash terbesar yang boleh diminta oleh model untuk lingkungan tersebut. Nilai ini menerima `1` hingga `300000` ms; jika dihilangkan, maka akan menggunakan nilai default 30 detik. Dengan total anggaran permintaan, batas waktu perintah yang diiklankan juga menyesuaikan dengan sisa waktu setelah penerimaan, penyelesaian, dan pengiriman perintah. Ini adalah batas atas penerapan dan tidak dapat dikonfigurasi oleh pengguna.
- `configSchema.workspaces.linkedWorktrees` mengontrol penjadwalan per-worktree untuk workspace terlampir yang mengiklankan `git_linked_worktree`. Jika dihilangkan, fitur ini diizinkan; `false` membuat setiap permintaan tetap dibatasi pada lane root checkout. Pengaturan ini tidak berpengaruh kecuali worker mengiklankan cakupan tersebut, yang memerlukan Code API yang mendukung lane linked-worktree dan worker yang dijalankan dengan `--linked-worktree-lanes`. Tingkatkan LibreChat **sebelum** worker mengiklankan cakupan ini. Operasi file yang menargetkan path di dalam `.worktrees/<name>` dan perintah Bash dengan `cwd` di sana menggunakan lane tersebut dan mengembalikan path relatif terhadap checkout. Perintah yang melakukan `cd` di dalam teks perintahnya, operasi root checkout, instance workspace percakapan, dan aksi environment tetap dibatasi pada root.
- `configSchema.workspaces.allowCheckoutSelection: true` mengizinkan pilihan checkout eksplisit per percakapan setelah setiap replika API mendukungnya. Jika dihilangkan (`false`), isolasi worker otomatis tetap dipertahankan dan pemilih (selector) disembunyikan.
- `configSchema.limits.defaultCommandTimeoutMs` menetapkan batas waktu (timeout) Bash di latar depan yang digunakan ketika sebuah panggilan tidak menyertakan `timeoutMs`. Nilai yang diterima berada pada rentang `1` hingga `300000` ms; jika tidak diisi, nilai tetap 30 detik, dan batas maksimum perintah yang efektif dapat menurunkannya.
- `configSchema.limits.defaultReadFileLines` menentukan jendela baris `read_file` yang dilampirkan ketika `max_lines` dihilangkan. Nilai yang diterima adalah `1` hingga `500`; jika dihilangkan, nilai tetap 200 baris, dan anggaran byte dapat memotong hasil lebih awal.
- `configSchema.limits.maxRunTimeoutMs` menetapkan batas waktu panggilan keseluruhan yang terpisah untuk kredensial, backoff, dan percobaan HTTP. Nilainya diterima dari `1` hingga `610000` ms; jika dihilangkan, `maxRequestTimeoutMs` tetap menjadi total anggaran waktu. Aturan cadangan yang sama dengan `maxRequestTimeoutMs` berlaku.
- `configSchema.admission` mengatur bagaimana lingkungan yang terpasang menunggu kapasitas; lihat tabel di bawah.
- `configSchema.edits.tolerantMatching` mengizinkan fallback yang toleran terhadap spasi secara default pada worker terlampir yang mengiklankan `tolerant_match`; atur ke `false` untuk mewajibkan pencocokan yang tepat, termasuk pratinjau edit yang dilindungi. Pencocokan harus tetap unik kecuali jika edit secara eksplisit mengatur `replace_all`. Worker yang lebih lama tidak menerima bidang pencocokan baru; `replace_all` yang terlampir akan ditolak sebelum pengiriman kecuali worker mengiklankannya. Kemampuan ini memerlukan Code API yang kompatibel dan build worker yang mengimplementasikan [Code Interpreter #271](https://github.com/LibreChat-AI/code-interpreter/pull/271).
- Jangan konfigurasikan `settings` di dalam deployment YAML. LibreChat menyediakan field dengan cakupan permintaan (request-scoped) tersebut dari preferensi pemilik yang terautentikasi dan tervalidasi oleh server.
- Hanya kebijakan penulisan file dan eksekusi perintah yang dapat dikonfigurasi oleh pengguna. Isolasi, jaringan, pemasangan (mounts), eksekusi istimewa (privileged execution), ingress, egress, dan rahasia (secrets) tetap dikendalikan oleh administrator.
- Jika `workerId` tingkat atas dan `pairing.workerId` keduanya ada, keduanya harus cocok. Entri dengan `allowPrincipalWorkers: true` dan tidak ada ID pekerja yang bersifat khusus-pasangan (pairing-only): entri tersebut dihilangkan dari pemilih eksekusi dan tidak dapat menetapkan `default: true`.

Eksekusi terlampir secara otomatis mengaktifkan garis dasar persetujuan yang aman: penulisan file serta eksekusi perintah atau kode akan meminta konfirmasi, sementara operasi baca-saja dan pencarian tetap berjalan di bawah kebijakan alat reguler. Garis dasar ini dicakupkan ke Agen yang menggunakan lingkungan terlampir. Jika tidak ada pengaturan pengguna yang tersedia, LibreChat menggunakan `ask`; [`toolApproval.enabled: false`](#toolapproval) adalah penggantian darurat administrator yang menonaktifkan garis dasar lingkungan terlampir ini. Pemanggil tanpa dukungan persetujuan dan resume akan gagal secara tertutup (fail closed) kecuali penggantian eksplisit tersebut diatur.

Eksekusi terlampir memerlukan build remote-bridge Code Interpreter eksperimental yang cocok. Penyandingan mengautentikasi koneksi worker keluar; ini tidak menggantikan isolasi sandbox atau VM. Pengguna dengan izin manajemen Code Environment melakukan penyandingan, mengonfigurasi kebijakan alat yang diizinkan, dan mencabut worker pribadi di bawah **Settings > Code environments**. Lihat [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions).

Kelanjutan turunan terikat bersifat otomatis. Bidang `childTurns`, `completionWakeups`, `coalescing`, `actorMailbox`, `checkpointForks`, dan `durableReceipts` yang lebih lama di bawah `eventDriven` bukan lagi merupakan sakelar konfigurasi dan harus dihapus. Setel hanya jika penerimaan pemicu internal tepercaya harus melintasi origin HTTP(S) lain, seperti pintu depan TLS. `AGENT_TRIGGERS_SELF_URL` tetap menjadi cadangan kompatibilitas saat kolom ini dihilangkan. `eventDriven.idlePolling` membatasi polling pemulihan per replika ketika tidak ada yang siap: `deliveryMaxIntervalMs` secara default bernilai `15000` (nilai valid `1000` hingga `300000`), `queuedTurnMaxIntervalMs` dan `maintenanceMaxIntervalMs` masing-masing secara default bernilai `120000` (nilai valid `30000` hingga `300000`), dan `completionWaitMaxIntervalMs` secara default bernilai `60000` (nilai valid `5000` hingga `300000`). Yang terakhir ini membatasi pemeriksaan ulang selama hasil dari latar belakang atau Subagent masih tertunda atau turn induknya sedang sibuk. Event kesiapan mempercepat pengiriman; batas-batas ini mempertahankan fallback lintas-replika dan pemulihan setelah crash, bukan menentukan latensi penyelesaian normal.

```yaml filename="endpoints / agents / eventDriven / idlePolling"
eventDriven:
  idlePolling:
    deliveryMaxIntervalMs: 15000
    queuedTurnMaxIntervalMs: 120000
    maintenanceMaxIntervalMs: 120000
    completionWaitMaxIntervalMs: 60000
```

Penyelesaian Action yang terlepas (detached) dari Event Actor dipilih secara otomatis dari penyimpanan generasi bawaan. Eksekusi dalam memori bersifat lokal terhadap proses; stream generasi Redis menambahkan pemulihan restart yang tahan lama dan serah terima replika. Tidak diperlukan switch `librechat.yaml` atau flag fitur environment. Lihat [Agent Event Runtime](/docs/configuration/dotenv#agent-event-runtime).

<Callout type="note">
  Batas ini bersifat menyeluruh untuk proses dan berasal dari `librechat.yaml`. Penggantian basis data per pengguna atau per grup untuk `endpoints.agents.maxSubagents` tercermin dalam konfigurasi yang disajikan, namun tidak diterapkan oleh validasi permintaan.
</Callout>

## Kemampuan Agen [#agent-capabilities]

Kolom `capabilities` memungkinkan Anda untuk mengaktifkan atau menonaktifkan fungsionalitas tertentu untuk agen. Kapabilitas yang tersedia adalah:

- **deferred_tools**: Memungkinkan agen untuk menemukan MCP tools yang ditangguhkan (deferred) saat runtime alih-alih memuat setiap tool ke dalam konteks di awal.
- **programmatic_tools**: Mengaktifkan Pemanggilan Alat Programatis (Programmatic Tool Calling) untuk alat MCP yang ditandai sebagai Programmatic di Agent Builder. Memerlukan `execute_code` dan deployment Code Interpreter dengan komponen Tool Call Server. Kemampuan ini bersifat opt-in dan tidak diaktifkan secara default.
- **execute_code**: Mengizinkan agen untuk mengeksekusi kode.
- **stateful_code_sessions**: Memungkinkan agen yang memilih untuk ikut serta menggunakan kembali satu ruang kerja Code Interpreter pada cakupan pengguna, agen-dan-pengguna, atau percakapan. Memerlukan `execute_code`, deployment Code Interpreter yang kompatibel, dan pengaturan Lanjutan per-agen. Agen baru menggunakan cakupan pilihan pengguna yang telah masuk. Kemampuan ini sangat eksperimental, tidak diaktifkan secara default, dan dapat berubah secara substansial selama eksperimen; jangan anggap perilaku atau konfigurasinya saat ini sebagai kontrak produksi yang stabil.
- **file_search**: Memungkinkan agen untuk mencari dan berinteraksi dengan file. Saat diaktifkan, perilaku sitasi dikendalikan oleh pengaturan `maxCitations`, `maxCitationsPerFile`, dan `minRelevanceScore`.
- **web_search**: Mengaktifkan fungsionalitas pencarian web untuk agen, memungkinkan mereka untuk mencari dan mengambil informasi dari internet.
- **artifacts**: Memungkinkan agen untuk menghasilkan artefak interaktif (komponen React, HTML, diagram Mermaid).
- **subagents**: Mengaktifkan eksekusi agen anak dengan konteks terisolasi. Lihat [Subagents](/docs/features/subagents).
- **actions**: Mengizinkan agen untuk melakukan tindakan yang telah ditentukan sebelumnya.
- **context**: Mengaktifkan fungsionalitas "Upload as Text" dalam obrolan, dan "File Context" untuk agen, yang memungkinkan pengguna untuk mengunggah file dan kontennya diekstraksi serta disertakan secara langsung ke dalam percakapan.
- **skills**: Mengaktifkan Skills di panel samping, pemanggilan manual `$`, skills yang dipanggil model, dan daftar izin (allowlist) skill agen. Lihat [Skills](/docs/features/skills).
- **memory**: Menawarkan Memory di Agent Builder, sehingga agen dapat menggunakan `set_memory` dan `delete_memory`. Hanya berlaku ketika memory telah dikonfigurasi dan pengguna memiliki akses melalui izin peran serta pengaturan personalisasi; dihapus saat runtime ketika memory dinonaktifkan. Lihat [Memory](/docs/features/memory).
- **ask_user_question**: Menawarkan Ask User di Agent Builder, yang memungkinkan agen menjeda eksekusi untuk mengajukan satu hingga empat pertanyaan terkait dalam satu formulir dan melanjutkan eksekusi dengan jawabannya.
- **tools**: Memberikan agen akses ke berbagai tools.
- **chain**: Sudah tidak digunakan (deprecated) dan tidak memiliki efek. Tetap diterima agar konfigurasi lama tetap valid.
- **ocr**: Secara opsional meningkatkan fitur "Upload as Text" dalam obrolan, dan "File Context" untuk agen, yang memungkinkan file diunggah dan diproses dengan OCR. **Memerlukan layanan OCR untuk dikonfigurasi.**
- **run_in_background**: Membuat eksekusi Code Interpreter dan alat shell memenuhi syarat untuk berjalan di latar belakang secara default dan mengaktifkan keikutsertaan latar belakang per-alat untuk alat MCP, Plugin, dan Action yang memenuhi syarat. Tombol tingkat Action akan mengikutsertakan setiap operasi yang memenuhi syarat; Action OAuth dan operasi yang telah menentukan parameter `run_in_background` dikecualikan. Agen dapat secara eksplisit mengeluarkan Code Interpreter dari fitur ini. Pengaturan ini mengizinkan eksekusi latar belakang; model memutuskan per panggilan apakah akan menggunakannya atau tidak. Memerlukan `execute_code` dan deployment Code Interpreter yang telah dikonfigurasi untuk kode. Kemampuan ini tidak diaktifkan secara default.
- **tool_intents**: Menambahkan label intent yang ditulis oleh model secara langsung ke panggilan tool yang memenuhi syarat. Tool bawaan, termasuk tool Code Interpreter, ikut serta secara otomatis; tool MCP dapat diaktifkan satu per satu atau secara massal di Agent Builder. Model specs menggunakan `describeIntent`. Kemampuan ini tidak diaktifkan secara default.

Dengan menentukan kapabilitas, Anda dapat mengontrol fitur yang tersedia bagi pengguna saat berinteraksi dengan agen.

## Contoh Konfigurasi [#example-configuration]

Berikut adalah contoh konfigurasi endpoint `agents` dengan kemampuan kustom dan pengaturan sitasi file:

```yaml filename="Agents Endpoint"
endpoints:
  agents:
    disableBuilder: false
    # File citation configuration
    maxCitations: 20
    maxCitationsPerFile: 5
    minRelevanceScore: 0.6
    # Custom capabilities
    capabilities:
      # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
      # - 'programmatic_tools'
      - 'execute_code'
      # Optional: makes Code Interpreter background-eligible and enables selected MCP, Plugin, and Action tools.
      # - 'run_in_background'
      # Optional: enables live intent labels for native and selected MCP tools.
      # - 'tool_intents'
      - 'file_search'
      - 'skills'
      - 'subagents'
      - 'actions'
      - 'artifacts'
      - 'context'
      - 'ocr'
      - 'web_search'
```

Dalam contoh ini:

- Antarmuka builder telah diaktifkan
- Kutipan file dibatasi hingga total 20, dengan maksimal 5 per file
- Hanya sumber dengan relevansi 60%+ yang disertakan
- Agen LibreChat memiliki akses ke eksekusi kode, pencarian file (dengan sitasi), Skills, Subagents, actions, artifacts, konteks file, layanan ocr jika dikonfigurasi, dan kemampuan pencarian web.
- Programmatic Tool Calling tetap dinonaktifkan kecuali Anda menambahkan kapabilitas `programmatic_tools` bersama dengan `execute_code`
- Panggilan alat latar belakang tetap dinonaktifkan kecuali Anda menambahkan `run_in_background`; alat Code Interpreter kemudian akan memenuhi syarat secara default, sementara alat MCP, Plugin, dan Action yang memenuhi syarat masih memerlukan pemilihan.
- Label intent alat tetap dinonaktifkan kecuali Anda menambahkan `tool_intents`; alat bawaan kemudian akan ikut serta secara otomatis, sementara alat MCP masih memerlukan pemilihan per alat.

## managementApi

API Manajemen Agen versi beta memungkinkan klien mesin tepercaya untuk membuat, mencantumkan, membaca, memperbarui, dan menghapus Agen, mengelola file mereka, serta menemukan atau mengedit Skill yang dapat diakses. API ini terpisah dari [`remoteApi`](#remoteapi): rute manajemen hanya menerima identitas mesin OIDC yang terikat pada deployment dan tidak menerima kunci API LibreChat Remote Agents atau sesi browser.

```yaml filename="endpoints / agents / managementApi"
endpoints:
  agents:
    managementApi:
      auth:
        oidc:
          enabled: true
          issuer: https://identity.example.com/
          audience: https://librechat.example.com/agents
          # jwksUri: https://identity.example.com/.well-known/jwks.json
        clients:
          - clientId: machine-client-id
            # subject: provider-specific-service-principal-subject
            userId: 507f1f77bcf86cd799439011
            tenantId: tenant-id
            enabled: true
```

## Subagents [#subagents]

[Subagen](/docs/features/subagents) tersedia kapan pun kapabilitas `subagents` tercantum. Batas per agen adalah [`maxSubagents`](#maxsubagents) dan berbagi file adalah [`fileSharing`](#filesharing). Batas-batas lainnya bersifat tetap:

- Maksimal 5 tingkat subagen bersarang di bawah agen utama.
- Maksimal 50 target subagen yang berbeda dimuat dalam satu kali eksekusi.
- Maksimal 100 konfigurasi subagen yang diperluas (expanded) tertanam dalam satu permintaan run.
- Maksimal 32 anggota dalam satu tim Agent yang disimpan.

## Catatan [#notes]

- Tidak disarankan untuk menonaktifkan antarmuka builder kecuali Anda menggunakan [modelSpecs](/docs/configuration/librechat_yaml/object_structure/model_specs) untuk menentukan daftar agen yang dapat dipilih.
- Konfigurasi sitasi file (`maxCitations`, `maxCitationsPerFile`, `minRelevanceScore`) hanya berlaku ketika kapabilitas `file_search` diaktifkan.
- Skor relevansi dihitung menggunakan kesamaan vektor, di mana 1.0 merepresentasikan kecocokan sempurna dan 0.0 merepresentasikan tidak ada kesamaan.
- Batas sitasi membantu menyeimbangkan pengambilan informasi yang komprehensif dengan kualitas dan performa respons.
- Kemampuan `context` berfungsi tanpa konfigurasi OCR menggunakan metode penguraian teks. OCR meningkatkan kualitas ekstraksi saat dikonfigurasi.
- Kemampuan `ocr` memerlukan layanan OCR untuk dikonfigurasi (lihat [Konfigurasi OCR](/docs/configuration/librechat_yaml/object_structure/ocr)).
- `maxSubagents` membatasi berapa banyak subagen yang dapat direferensikan oleh satu agen. Pengaturan ini tidak mengubah batas kedalaman maupun batas graf yang tercantum di [Subagents](#subagents).
