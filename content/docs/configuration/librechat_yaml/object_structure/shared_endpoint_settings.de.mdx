Diese Seite beschreibt die gemeinsamen Konfigurationseinstellungen für alle endpoints. Die hier hervorgehobenen Einstellungen sind für alle Konfigurationen unter dem Feld ["Endpoints"](/docs/configuration/librechat_yaml/object_structure/config#endpoints) verfügbar, sofern nicht anders angegeben.

## Beispielkonfiguration [#example-configuration]

```yaml filename="Shared Endpoint Settings"
endpoints:
  # Individual endpoint configurations
  openAI:
    streamRate: 25
    titleModel: 'gpt-4o-mini'
    titleMethod: 'completion'
    titleTiming: 'immediate'
    titlePrompt: "Create a concise title for this conversation:\n\n{convo}"
    headers:
      X-Gateway-Metadata: '{"user_email":"{{LIBRECHAT_USER_EMAIL}}"}'

  azureOpenAI:
    streamRate: 35
    titleModel: 'grok-3'
    titleMethod: 'structured'
    titlePrompt: |
      Analyze this conversation and provide:
      1. A concise title in the detected language (5 words or less, no punctuation or quotation)
      2. Always provide a relevant emoji at the start of the title

      {convo}
    titleConvo: true

  anthropic:
    streamRate: 25
    titleModel: 'claude-3-5-haiku-20241022'
    titleMethod: 'completion'
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'

  bedrock:
    streamRate: 25
    titleModel: 'us.amazon.nova-lite-v1:0'
    titleEndpoint: 'anthropic'

  google:
    streamRate: 25
    titleModel: 'gemini-2.0-flash-lite'
    titlePromptTemplate: "Human: {input}\nAssistant: {output}"
    headers:
      X-Gateway-Metadata: '{"user_id":"{{LIBRECHAT_USER_ID}}"}'

  assistants:
    streamRate: 30

  azureAssistants:
    streamRate: 30

  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5

  # Global configuration using 'all' - this applies shared settings across endpoints.
  # Most defined values override endpoint defaults; headers are merged and endpoint values win on collisions.
  all:
    headers:
      X-App: 'librechat'
    titleConvo: true
    titleModel: 'gpt-4.1-nano'
    titleTiming: 'immediate'
    titlePrompt: |
      Analyze this conversation and provide:
      1. The detected language of the conversation
      2. A concise title in the detected language (5 words or less, no punctuation or quotation)
      3. Always provide a relevant emoji at the start of the title
      {convo}
```

> **Wichtig:** Wenn Sie die `all`-Konfiguration verwenden, gelten die meisten von Ihnen definierten gemeinsamen Eigenschaften für alle endpoints. Im obigen Beispiel würde die `all`-Konfiguration `titleConvo`, `titleModel` und `titlePrompt` auf alle endpoints anwenden, während individuelle `streamRate`-Einstellungen beibehalten würden, da diese nicht in `all` definiert sind. `headers` werden separat zusammengeführt: Werte aus `endpoints.all.headers` gelten global, und endpoint-spezifische Header haben bei Schlüsselkollisionen Vorrang. Aktivitätseinstellungen werden Feld für Feld in der gleichen Reihenfolge aufgelöst, sodass eine unabhängige `all`-Einstellung nicht die Aktivitätskonfiguration eines endpoints verbirgt.

## streamRate

**Schlüssel:**

<OptionTable
  options={[
    [
      'streamRate',
      'Number',
      'Die Rate, mit der Daten vom endpoint gestreamt werden. Nützlich, um das Tempo des Daten-Streamings zu steuern.',
      'streamRate: 25',
    ],
  ]}
/>

**Standard:** Anbieterabhängig. OpenAI, benutzerdefinierte endpoints, Anthropic, Google, Bedrock und durch das Agents SDK unterstützte Streams verwenden adaptives Smoothing mit einem Zielwert von 25 ms. Legacy Assistants und Ollama-Handler behalten ihr verhaltensspezifisches Chunking pro Anbieter bei, mit einem Standardwert von 1 ms.

Adaptives Smoothing gibt das erste Text-Token ohne Verzögerung aus, erhöht die Chunk-Größe, wenn ein Stream zurückfällt, und bewahrt die Reihenfolge von Tool-Aufrufen und Metadaten. Setzen Sie `streamRate` auf einen nicht-negativen Zielwert in Millisekunden; `streamRate: 0` deaktiviert das adaptive Smoothing bei den oben aufgeführten SDK-gestützten Providern.

Ein endpoint-spezifischer Wert bleibt erhalten, wenn `endpoints.all` ohne `streamRate` existiert. Die Definition von `endpoints.all.streamRate` überschreibt endpoint-Werte, einschließlich einer expliziten `0`.

**Standard:** Titel werden generiert, sofern dies nicht auf `false` gesetzt ist.

**Hinweise:**

- Titel verwenden die konfigurierten Titeleinstellungen. Wenn `titleModel` nicht angegeben ist, wird das Modell der Unterhaltung verwendet.


## titleTiming

**Schlüssel:**

<OptionTable
  options={[
    [
      'titleTiming',
      'String',
      'Steuert, wann Konversationstitel generiert werden. Gültige Werte: "immediate" oder "final".',
      'titleTiming: "immediate"',
    ],
  ]}
/>

**Standard:** `"immediate"`

**Verfügbare Werte:**

- **`"immediate"`** - Generiert den Titel, sobald die Anfrage beginnt, parallel zur Antwort des Modells, unter Verwendung der ersten Nachricht des Benutzers. Titel erscheinen normalerweise innerhalb einer Sekunde oder zwei.
- **`"final"`** - Verschiebt die Titelgenerierung, bis die vollständige Antwort abgeschlossen ist. Dies bewahrt das ursprüngliche Verhalten.

**Beispiel:**

```yaml filename="titleTiming"
endpoints:
  all:
    titleTiming: 'immediate'
```

## Agent-Aktivitätsgruppen [#agent-activity-groups]

Aktivitätsgruppen machen lange Agenten-Ausführungen leichter überschaubar, indem sie jeden zusammenhängenden Block aus Überlegungen und Tool-Aufrufen unter einer generierten einzeiligen Überschrift zusammenfassen. Die Generierung der Überschrift erfolgt außerhalb des Hauptpfads der Modellantwort, ist jedoch weiterhin ein Modellaufruf, dessen Nutzung aufgezeichnet und abgerechnet wird.

Wenn übergeordnete Phasenbezeichnungen (parent phase labels) aktiviert sind, bleibt kurzer Fortschrittstext innerhalb der aktiven Phase. Eine Phase wird vor umfangreichem Antworttext geschlossen, sodass das Ergebnis außerhalb der eingeklappten Zusammenfassung verbleibt, und ein späterer Block mit Überlegungen oder Tool-Aufrufen kann eine weitere Phase im selben Durchlauf beginnen. LibreChat führt zudem ein Rebase der gespeicherten Phasengrenzen durch, wenn fehlerhafte oder ausgelassene Inhalte komprimiert werden, wodurch deren Ausrichtung nach dem Neuladen erhalten bleibt.

```yaml filename="endpoints / agents / activity groups"
endpoints:
  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5
```

Sie können diese Felder auch unter `endpoints.all` oder einem unterstützenden Anbieter bzw. benutzerdefinierten endpoint festlegen. Die Werte werden unabhängig aufgelöst, wobei der zuerst definierte Wert in dieser Reihenfolge Vorrang hat: `endpoints.all`, der öffentliche `agents` endpoint, dann der unterstützende Anbieter oder benutzerdefinierte endpoint. Wenn `activityEndpoint` unbekannt ist, protokolliert LibreChat eine Warnung und verwendet stattdessen den Anbieter des Agents.

Zusammenfassungen der übergeordneten Phase sind unabhängig von den Aktivitätsbezeichnungen der untergeordneten Phasen: `activityPhaseLabel` kann mit oder ohne `activityLabel` aktiviert werden. LibreChat verwendet einen Modellaufruf für eine Phasenzusammenfassung nur dann, wenn eine Phase mindestens zwei logische Aktivitäten enthält. `activityCharLimit` begrenzt zudem die für Phasenzusammenfassungen verwendeten Nachweise. Die Modellauswahl für Phasen erfolgt über `activityPhaseModel`, `activityModel`, das `titleModel` des ursprünglichen endpoint, und schließlich das Modell der aktuellen Ausführung; die Auswahl des Phasen-endpoint erfolgt über `activityPhaseEndpoint`, `activityEndpoint` und schließlich den Agent-Anbieter. Ein unbekannter konfigurierter Phasen-endpoint protokolliert eine Warnung und greift auf den Agent-Anbieter zurück.

## Live Reasoning Labels [#live-reasoning-labels]

Live-Reasoning-Labels ersetzen die allgemeine Überschrift **Thinking** oder **Thoughts** durch eine kurze, sich entwickelnde Orientierungshilfe für ausreichend lange Agenten-Überlegungen auf oberster Ebene. LibreChat aktualisiert die bestehende Reasoning-Überschrift direkt an Ort und Stelle und fügt keine Nachrichteninhalte hinzu oder verschiebt diese. Verschachtelte Subagent-Überlegungen werden durch diese Einstellung nicht beschriftet.

```yaml filename="endpoints / agents / live reasoning labels"
  agents:
    reasoningLabel: true

    reasoningLabelMaxPerRun: 8
```

Sie können diese Felder unter `endpoints.all`, dem öffentlichen `agents`-Endpunkt oder einem zugrunde liegenden Anbieter/benutzerdefinierten Endpunkt festlegen. Jedes Feld wird unabhängig aufgelöst, wobei der zuerst definierte Wert in dieser Reihenfolge gewinnt: `endpoints.all`, `endpoints.agents`, dann der zugrunde liegende Anbieter oder benutzerdefinierte Endpunkt.

Die Modellauswahl erfolgt über `reasoningLabelModel`, `activityModel`, das `titleModel` des ursprünglichen endpoint, und anschließend das Modell des aktuellen Agent-Durchlaufs. Die endpoint-Auswahl erfolgt über `reasoningLabelEndpoint`, `activityEndpoint` und anschließend den Agent-Anbieter. Ein unbekannter Label-endpoint protokolliert eine Warnung und greift auf den Agent-Anbieter zurück.

Jeder Aufruf sendet maximal 4.000 Zeichen sichtbares Reasoning an den aufgelösten Label-endpoint, welcher ein anderer Anbieter als der Agent sein kann. Labels sind auf 120 Zeichen begrenzt. Streaming-Revisionen beachten sowohl die Zeichen- als auch die Intervall-Schwellenwerte; bei Abschluss kann ein aussagekräftiger Rest von mindestens 120 neuen Zeichen sofort eine finale Neufassung auslösen. Jeder Revisionsversuch zählt zu `reasoningLabelMaxPerRun` und ist ein separater Modellaufruf mit eigenem Token-Verbrauch und eigenen Kosten.

Wenn das Langfuse-Tracing aktiviert ist, wird der Snapshot des begrenzten Schlussfolgerns (bounded reasoning) als Eingabe für die Label-Generierung aufgezeichnet, es sei denn, die aktive Schwärzungsrichtlinie unterdrückt den Label-Aufruf. Überprüfen Sie den Ziel-endpoint und die Tracing-Richtlinie, bevor Sie diese Funktion für sensible Schlussfolgerungsinhalte aktivieren.

## headers

**Schlüssel:**

<OptionTable
  options={[
    [
      'headers',
      'Object/Dictionary',
      'Benutzerdefinierte Anfrage-Header, die an unterstützte integrierte Provider-endpoints weitergeleitet werden.',
      'Useful for AI gateways and reverse proxies that consume metadata headers while LibreChat keeps provider-native request formatting.',
    ],
  ]}
/>

**Unterstützte endpoints:** `openAI`, `anthropic`, `google` und `all`.

**Beispiel:**

```yaml filename="endpoints / headers"
endpoints:
  all:
    headers:
      X-App: 'librechat'
  anthropic:
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
```

**Hinweise:**

- Werte unterstützen `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}` sowie Platzhalter für den Request-Body wie `{{LIBRECHAT_BODY_CONVERSATIONID}}`.
- Agent-Modellanfragen unterstützen zusätzlich `{{LIBRECHAT_USER_TENANT_ID}}` und `{{LIBRECHAT_USER_TENANTID}}`. Beide werden aus dem maßgeblichen, anfragebezogenen Tenant für Root-Agents, Subagents, Aktivitäts-Labels, Speicher- und Zusammenfassungsaufrufe aufgelöst und werden zu einer leeren Zeichenfolge, wenn der Lauf keinen Tenant hat. Dieser Tenant-Wert ist absichtlich auf Modell-Header beschränkt und wird nicht zu allgemeinen Benutzer-Platzhalter-Consumern hinzugefügt.
- Beim letzten Schritt der ausgehenden Auflösung werden erkannte Platzhalter für user, request-body und OpenID, die keinen Wert haben, zu leeren Zeichenfolgen, anstatt als Vorlagentext weitergeleitet zu werden. Unbekannte Platzhalternamen bleiben unverändert, damit Konfigurationsfehler sichtbar sind.
- Header auf Endpoint-Ebene überschreiben `endpoints.all.headers` bei Schlüsselkollisionen.
- Vom Anbieter verwaltete Authentifizierung und erforderliche Beta-/Protokoll-Header bleiben maßgeblich. Anthropic-Beta-Werte werden zusammengeführt, sodass benutzerdefinierte Beta-Flags keine erforderlichen Anbieter-Flags überschreiben.
- Header werden auch für unterstützte Modelllisten-Anfragen von Providern weitergeleitet.
- Verwenden Sie Metadaten-Header hinter einem Gateway oder Reverse-Proxy, der diese verarbeitet. Native Provider-APIs ignorieren in der Regel unbekannte Header.

---

**Hinweise:**

- Alle auf dieser Seite gezeigten Einstellungen können individuell pro endpoint oder global über den `all` Schlüssel konfiguriert werden.
- Bei Verwendung der `all` Konfiguration werden die entsprechenden Einstellungen in ALLEN einzelnen endpoint überschrieben.
- Der `all`-Schlüssel akzeptiert kein `baseURL`
- Der Endpunkt `azureOpenAI` akzeptiert nur eine Teilmenge dieser Einstellungen. Er akzeptiert `titleEndpoint`, `headers` oder `maxToolResultChars` nicht. Siehe [Azure OpenAI](/docs/configuration/librechat_yaml/object_structure/azure_openai).
- Einstellungen, die nicht unter `all` definiert sind, behalten ihre individuellen endpoint-Werte bei.
- Für `streamRate`: Werte zwischen 25-40 werden empfohlen, wenn eine endpoint-spezifische Glättung gewünscht ist.
- Die Verwendung einer höheren Stream-Rate ist ein Muss, wenn die App für viele Benutzer in großem Maßstab bereitgestellt wird.

**Beispiel für das Override-Verhalten:**

```yaml
endpoints:
  openAI:
    streamRate: 25 # This will be preserved
    titleModel: 'gpt-4' # This will be overridden
    titleConvo: false # This will be overridden

  all:
    titleConvo: true
    titleModel: 'gpt-3.5-turbo'
    # streamRate not defined here, so individual values are kept
```
