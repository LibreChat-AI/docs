## 개요 [#overview]

`summarization` 구성은 대화 요약 및 컨텍스트 가지치기에 대한 중앙 집중식 제어를 제공합니다. 이는 이전에 사용자 지정 및 Azure OpenAI 엔드포인트에서 사용할 수 있었던 엔드포인트별 `summarize` 및 `summaryModel` 필드를 대체합니다.

대화가 모델의 컨텍스트 윈도우를 초과하면, 요약 시스템이 자동으로 이전 메시지들을 간결한 체크포인트 요약으로 압축합니다. 이는 이후 대화를 위한 컨텍스트 공간을 확보해주지만, 요약은 정보 손실이 발생할 수 있으며 세부 사항이 생략될 수 있습니다. 정확한 문구나 이전 도구 결과가 중요한 경우에는 원본 대화 기록을 확인하십시오. 또한 시스템에는 **context pruning** 기능이 포함되어 있어, 요약이 필요하기 전에 이전 메시지의 방대한 도구 결과를 점진적으로 축소하여 토큰 공간을 확보합니다.

요약 턴 이후, 컨텍스트 사용량 게이지는 폐기된 요약 이전 기록을 다시 계산하는 대신 유지된 요약 기준점과 요약 이후의 턴을 사용합니다. 누적 사용량 및 비용 합계에는 여전히 전체 브랜치 지출이 포함됩니다.

## 수동 컨텍스트 압축 (Manual Context Compaction) [#manual-context-compaction]

`summarization.enabled`가 `false`로 설정되지 않은 경우, 에이전트 대화는 대화 제어 메뉴에서 **Compact context(컨텍스트 압축)** 기능을 제공합니다. 이 기능은 현재 브랜치 리프(leaf)에서 요약 전용 턴을 시작합니다. LibreChat은 적격한 대화 기록을 요약하고, 새로운 요약 체크포인트를 저장한 뒤, 기본 에이전트나 하위 에이전트에게 답변을 생성하도록 요청하지 않고 종료합니다.

이전 메시지는 대화 기록에 계속 표시되지만, 이후의 모델 호출은 압축된 요약과 [`retainRecent`](#retainrecent)에 의해 유지된 콘텐츠를 사용합니다. 결과적으로 생성된 마커는 사용자가 시작한 압축을 식별하며, 요약기에서 발생한 토큰 사용량은 별도로 기록됩니다. 새로운 대화, 활성 생성 중인 대화, 요약할 대상이 없는 분기, 또는 요약 기능이 비활성화된 배포 환경에서는 압축을 사용할 수 없습니다. 요약기가 실패하거나 요약을 생성하지 못하는 경우, LibreChat은 이전 컨텍스트를 변경하지 않고 유지하며 그 이유를 보고합니다.

## 예시 [#example]

```yaml filename="summarization"
summarization:
  provider: 'openAI'
  model: 'gpt-4o-mini'
  maxSummaryTokens: 4096
  reserveRatio: 0.05
  trigger:
    type: 'token_ratio'
    value: 0.8
  retainRecent:
    turns: 2
    tokens: 2000
  contextPruning:
    enabled: true
    keepLastAssistants: 3
    softTrimRatio: 0.3
    hardClearRatio: 0.5
    minPrunableToolChars: 50000
    softTrim:
      maxChars: 4000
      headChars: 1500
      tailChars: 1500
    hardClear:
      enabled: true
      placeholder: '[Old tool result content cleared]'
```

## contextPruning

<OptionTable

      '',
    ],
  ]}
/>

Context pruning은 요약(summarization)과는 독립적으로 작동하는 선택적 기능입니다. 이 기능은 이전 메시지에 포함된 대규모 도구 호출(tool call) 결과를 대상으로 하며, 두 가지 단계적 과정을 적용합니다:

1. **Soft trim** — 도구 결과의 앞부분과 뒷부분만 남기고 중간을 생략 부호로 대체하여 자릅니다.
2. **Hard clear** — 전체 도구 결과를 짧은 자리 표시자로 대체합니다

두 단계 모두 위치 기반입니다. 대화의 시작 부분에 가까운(오래된) 메시지부터 먼저 정리됩니다.

Agent 컨텍스트 프루닝(pruning)이 활성화되면, LibreChat은 각 Agent에 대해 선택된 압축 적응형 페이딩(compact adaptive fading) 계층을 유지하고 이를 이후 실행에 시드(seed)합니다. 이는 턴, 인간 개입(human-in-the-loop) 재개, 중단, 분기 및 복제본 핸드오프 전반에 걸쳐 공급자 전용 프로젝션을 안정적으로 유지하며, 이를 통해 Anthropic 프롬프트 캐시 재사용률을 향상시킵니다. 저장된 대화 메시지와 도구 결과는 완전하게 유지되며, 페이드된 프로젝션이 정식 기록(canonical history) 위에 덮어쓰여지지 않습니다.

## 엔드포인트별 설정에서의 마이그레이션 [#migration-from-per-endpoint-settings]

이전에 사용자 지정 또는 Azure OpenAI endpoint에서 `summarize` 및 `summaryModel`을 사용했다면:

```yaml filename="Before (removed)"
endpoints:
  custom:
    - name: 'My Endpoint'
      summarize: true
      summaryModel: 'gpt-3.5-turbo'
```

이 필드들은 제거되었습니다. 대신 최상위 `summarization` 설정을 사용하세요:

```yaml filename="After"
summarization:
  model: 'gpt-4o-mini'
```

## 참고 사항 [#notes]

- 요약(Summarization)은 엔드포인트별이 아닌 전역적으로 구성됩니다.
- 사용자 지정 endpoint 및 Azure OpenAI endpoint의 `summarize` 및 `summaryModel` 필드는 더 이상 지원되지 않습니다.
- `provider`와 `model`이 생략되면, 에이전트 자체의 provider와 model이 요약에 사용됩니다.
- `retainRecent`는 요약 외부에 최근의 축어적 꼬리말을 유지하며, `turns`는 `0-20` 사이의 값을 허용하고 `tokens`는 양수여야 합니다.
- Context pruning은 기본적으로 비활성화되어 있으며 `contextPruning.enabled: true`를 통해 명시적으로 활성화해야 합니다.
- Context pruning은 `minPrunableToolChars`를 초과하는 도구 호출 결과에만 영향을 미치며, 더 작은 결과는 절대 pruning되지 않습니다.
- `keepLastAssistants` 설정은 trim/clear 비율과 관계없이 최근 턴이 삭제되지 않도록 보호합니다.
- 사용자 지정 `prompt` 및 `updatePrompt` 값은 내장 프롬프트를 완전히 대체하므로 주의해서 사용하세요.
- `.env` 파일에 `AGENT_DEBUG_LOGGING=true`를 설정하여 토큰 수 및 컨텍스트 정리 진단에 대한 상세 로깅을 활성화하세요.
