## Ikhtisar [#overview]

Objek `fileConfig` memungkinkan Anda untuk mengonfigurasi pengaturan penanganan file untuk aplikasi, termasuk batas ukuran dan pembatasan tipe MIME. Bagian ini memberikan rincian mendalam mengenai struktur objek `fileConfig`.

Bidang utama di bawah `fileConfig` yang dibahas di sini:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**Catatan:**

- Pada saat penulisan ini, endpoint Assistants [mendukung tipe file dari daftar ini](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google, dan endpoint Custom mendukung file melalui [RAG API.](../../rag_api.mdx)
- OpenAI, Azure OpenAI, Anthropic, Google, AWS Bedrock, dan endpoint kustom mendukung unggahan file langsung melalui [Upload to Provider](/docs/features/ocr#upload-to-provider-instead).
- Bagian `ocr` dan `text` mengatur pemrosesan file untuk fitur-fitur seperti [Upload as Text](/docs/features/upload_as_text) dan [OCR](/docs/features/ocr)
- Endpoint lain yang tidak disebutkan, seperti Plugins, belum mendukung unggahan file (untuk saat ini).
- Endpoint Assistants memiliki nilai endpoint yang ditentukan yaitu `assistants`. Semua endpoint lainnya menggunakan nilai yang ditentukan yaitu `default`
  - Untuk endpoint non-asisten, Anda dapat menyesuaikan pengaturan file untuk semuanya di bawah `default`
  - Jika Anda ingin menyesuaikan pengaturan untuk endpoint tertentu, Anda dapat mencantumkan nama endpoint yang sesuai:
    - `assistants`
        - tidak menggunakan "default" karena memiliki default yang ditentukan secara terpisah dari yang lain.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Anda dapat mengabaikan nilai-nilai tersebut, dalam hal ini, aplikasi akan menggunakan nilai default sebagaimana ditentukan per tipe endpoint yang tercantum di bawah ini.
- LibreChat menghitung 1 megabyte sebagai berikut: `1 x 1024 x 1024`
- Streaming respons unggahan yang berjalan lama dan batas pengambilan URL jarak jauh sisi server dikonfigurasi dengan variabel lingkungan [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS`, dan `REMOTE_FILE_FETCH_MAX_BYTES`](/docs/configuration/dotenv#file-uploads).

## Contoh [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="Sintaks pola MIME">
  LibreChat mengevaluasi pola `supportedMimeTypes` yang dikonfigurasi administrator di server dengan mesin ekspresi reguler waktu-linear yang kompatibel dengan RE2. Backreference dan lookaround tidak didukung. Setiap pola dikompilasi dengan mesin aktif selama validasi konfigurasi; pola yang tidak didukung akan menolak konfigurasi alih-alih dilewati secara diam-diam.
</Callout>

## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Pengaturan untuk impor Skill, yang diunggah sebagai file `.md`, `.zip`, atau `.skill`.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` mendukung tiga parameter:

- `fileSizeLimit` (Number)
  - Ukuran maksimum dari satu unggahan Skill, ditentukan dalam megabyte (MB).
  - **Default:** `50`
- `importCleanupConcurrency` (Bilangan Bulat)
  - Operasi pembersihan serentak maksimum setelah impor arsip Skill yang gagal. Gunakan `1` untuk pembersihan serial.
  - **Default:** `8`
- `deletionCleanupConcurrency` (Integer)
  - Jumlah maksimum operasi pembersihan yang berjalan bersamaan saat sebuah Skill dihapus. Gunakan `1` untuk pembersihan secara berurutan (serial).
  - **Default:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Lihat [Skills](/docs/features/skills) untuk aturan impor lainnya, seperti batas per-file dan entri arsip.

## imageGeneration

<OptionTable
  options={[

`imageGeneration` mendukung parameter berikut:

- `percentage` (Number)
  - Ukuran output dari gambar yang dihasilkan dinyatakan sebagai persentase (contoh: `100` berarti 100% dari ukuran dasar).
  - Gunakan ini untuk menskalakan gambar keluaran relatif terhadap ukuran default atau ukuran asli.

- `px` (Number)
  - Menentukan dimensi gambar keluaran dalam piksel (contoh: `1024`).

Contoh konfigurasi:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Mengontrol pengubahan ukuran gambar di sisi klien sebelum diunggah, yang mencegah kesalahan unggah akibat gambar berukuran terlalu besar. Pengguna dapat mengaktifkan atau menonaktifkan pengubahan ukuran di Settings > Chat. Mengatur `enabled` di sini akan menimpa pilihan tersebut untuk semua pengguna dan mengunci sakelar; hilangkan opsi ini agar pengguna tetap dapat mengendalikannya.

- `enabled` (Boolean)
  - Pengubahan ukuran paksa diaktifkan (`true`) atau dinonaktifkan (`false`) untuk semua pengguna. Jika dihilangkan, setiap pengguna dapat memutuskan sendiri, dengan pengubahan ukuran aktif secara default.
- `maxWidth` (Number)
  - Lebar maksimum gambar yang diubah ukurannya, dalam piksel. Minimum `1`. **Default:** `1900`
- `maxHeight` (Number)
  - Tinggi maksimum gambar yang diubah ukurannya, dalam piksel. Minimum `1`. **Default:** `1900`
- `quality` (Number)
  - Kualitas kompresi JPEG dari `0` hingga `1`. **Default:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## textFallbackWithoutTools

Ketika unggahan diarahkan ke `none` (disimpan, hanya tersedia untuk alat) dan giliran tersebut tidak menjalankan alat yang dapat membacanya, LibreChat dapat mengirimkan teks yang diekstrak dari file tersebut sebagai gantinya. Atur `textFallbackWithoutTools: true` untuk mengaktifkannya. Pengaturan ini dapat ditetapkan secara global di bawah `fileConfig`, atau per entri di bawah `fileConfig.endpoints` (termasuk `default`); nilai endpoint memiliki prioritas lebih tinggi daripada nilai global.

**Default:** `false`

Hanya berlaku untuk lampiran pesan yang rutenya disimpulkan secara otomatis; tujuan yang dipilih secara eksplisit oleh pengguna tidak pernah ditentukan ulang, dan file yang disimpan pada tool resources milik sebuah agent tidak pernah masuk ke dalam prompt. Hanya ekstraktor dokumen dan teks biasa bawaan yang dijalankan, sehingga tidak ada panggilan RAG atau OCR yang dilakukan untuk file yang ditujukan untuk sebuah tool. File yang sudah ada tanpa teks hasil ekstraksi tidak diisi ulang.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

File yang disediakan ke lingkungan eksekusi kode dalam jendela waktu ini (dalam milidetik) melewati pemeriksaan ketersediaan langsung sebelum digunakan kembali. Minimum `0`.

**Default:** `21600000` (6 jam)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

Berapa lama, dalam milidetik, proses priming menunggu pemeriksaan ketersediaan File Search versi lama sebelum tetap melakukan embedding pada file. Minimum `1`.

**Default:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', 'Pengaturan untuk penguraian file teks langsung tanpa OCR.', 'Configures which file types are processed as plain text files for direct content extraction.'],
  ]}
/>

**Deskripsi:** Bagian `text` mengonfigurasi jenis file mana yang harus diproses menggunakan ekstraksi teks langsung.

**Catatan:** Penguraian teks adalah metode default yang digunakan oleh fitur "Upload as Text" (dikendalikan oleh kapabilitas `context`). Lihat [Upload as Text](/docs/features/upload_as_text) untuk informasi lebih lanjut.

- Daftar default mencocokkan setiap tipe MIME yang terbentuk dengan benar. File yang sudah berupa teks (`text/*`, JSON, YAML, XML, SQL, skrip shell, `.eml` email, dan sejenisnya) dibaca secara langsung. Tipe biner lain yang tidak memiliki parser akan ditolak alih-alih didekode menjadi data yang tidak berarti.
- Jika Anda mempersempit daftar dan RAG API telah dikonfigurasi (`RAG_API_URL`), file yang cocok dengannya akan dikirim ke ekstraksi teks RAG API. Jika RAG API tidak tersedia, LibreChat akan beralih ke parser dokumen bawaannya.

## stt

`fileConfig.stt` tidak dibaca dalam versi LibreChat saat ini; blok `stt` di sini akan diabaikan. File audio yang ditambahkan sebagai teks akan ditranskripsi ketika penyedia speech-to-text telah dikonfigurasi di [`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech), menggunakan daftar jenis audio bawaan: audio MP3, MPEG, WAV, OGG, Vorbis, MP4 dan M4A, FLAC, WebM, AAC, WMA, dan Opus.

## Prioritas Pemrosesan File [#file-processing-priority]

Ketika sebuah file ditambahkan sebagai teks (Upload as Text, tempelan panjang, atau File Context agen), LibreChat menggunakan langkah pertama yang berlaku:

1. **OCR**: sebuah bagian `ocr` ada di `librechat.yaml` dan file tersebut cocok dengan `fileConfig.ocr.supportedMimeTypes`. Jika layanan OCR gagal, parser dokumen bawaan akan dicoba berikutnya.
2. **Ekstraksi teks RAG API**: `text.supportedMimeTypes` telah dipersempit dari nilai default, RAG API sudah dikonfigurasi, dan file cocok dengan daftar tersebut.
3. **Parser dokumen bawaan**: File PDF, DOCX, XLS dan XLSX, ODT, dan ODS. Hanya membaca lapisan teks.
4. **Speech-to-text**: file audio, ketika penyedia STT telah dikonfigurasi.
5. **Pengurai teks**: file yang cocok dengan `text.supportedMimeTypes`.

Gambar atau PDF hasil pindai tanpa konfigurasi OCR tidak memiliki teks yang dapat diekstraksi, dan unggahan akan gagal dengan pesan yang menyatakan bahwa layanan OCR diperlukan.

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', 'Bagaimana file yang dilampirkan sampai ke model ketika pengguna tidak memilih tujuan.', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

Saya tidak memiliki teks yang perlu diterjemahkan. Pesan Anda hanya berisi instruksi "Translate the following into Bahasa Indonesia" tanpa konten dokumen yang menyertainya. Silakan tempelkan teks atau blok Markdown/MDX LibreChat yang ingin diterjemahkan.

- `provider`: file tersebut dikirim ke model sebagai lampiran native (input gambar, PDF, audio, atau video).
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`: file disimpan dan tersedia untuk tools seperti eksekusi kode atau pencarian file, tetapi tidak dikirim ke model.

`overrides` memetakan tipe MIME, atau wildcard `type/*`, ke sebuah nilai. `fallback` berlaku untuk semua yang tidak tercantum. LibreChat memeriksa override endpoint, kemudian fallback endpoint, kemudian override tingkat atas, kemudian fallback tingkat atas, dan terakhir nilai default bawaan.

Bawaan default bawaan (built-in) mengirim gambar, audio, video, dan PDF ke penyedia (provider) dan semua jenis lainnya sebagai teks. Default ini juga menyesuaikan diri dengan endpoint: PDF pada penyedia yang tidak dapat membaca PDF akan dikirim sebagai teks, audio atau video pada penyedia tanpa dukungan media akan ditranskripsikan atau tidak disertakan dalam prompt, AWS Bedrock menerima tipe dokumen yang didukungnya secara native, dan tipe yang tidak memiliki cara untuk mengekstrak teks (misalnya arsip) diatur ke `none`. Nilai yang Anda konfigurasi akan digunakan sebagaimana tertulis, tanpa penyesuaian-penyesuaian ini.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## endpoints

<OptionTable
  options={[
    ['endpoints', 'Record/Object', 'Mengonfigurasi pengaturan penanganan file untuk endpoint individual, memungkinkan kustomisasi berdasarkan basis per endpoint.', 'Specifies file handling configurations for individual endpoints, allowing customization per endpoint basis.'],
  ]}
/>

**Deskripsi:** Setiap objek di bawah endpoints adalah record yang dapat memiliki pengaturan berikut:

### Gambaran Umum [#overview-1]

  - `disabled`
      - Apakah penanganan file dinonaktifkan untuk endpoint tersebut.
  - `fileLimit`
      - Jumlah maksimum file yang diizinkan per permintaan unggahan.
  - `fileSizeLimit`
      - Ukuran maksimum untuk satu file. Dalam satuan MB (contoh: gunakan `20` untuk 20 megabyte)
  - `totalSizeLimit`
      - Ukuran maksimum total untuk semua file dalam satu permintaan. Dalam satuan MB (contoh: gunakan `20` untuk 20 megabyte)
  - `defaultLLMDeliveryPath`, `legacyFileUploadUX`, dan `textFallbackWithoutTools`
      - Penggantian per-endpoint dari pengaturan global dengan nama yang sama seperti dijelaskan di atas.
  - `supportedMimeTypes`
      - Daftar [Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression) yang menentukan tipe MIME apa saja yang diizinkan untuk diunggah. Ini dapat disesuaikan untuk membatasi tipe file.

LibreChat menormalisasi alias MIME umum sebelum menerapkan pola-pola ini. Secara khusus, `application/x-shellscript` (dilaporkan oleh Chrome di Linux) dan `text/x-shellscript` (dilaporkan oleh libmagic) menjadi `application/x-sh`. Oleh karena itu, daftar izin (allowlist) kustom yang menerima skrip shell harus mengizinkan tipe kanonik `application/x-sh`. Unggahan yang ditolak akan mengembalikan tipe yang tidak didukung yang dilaporkan ke klien, alih-alih kesalahan server generik.

## Pembersihan File dan Vektor yang Dipertahankan [#retained-file-and-vector-cleanup]

Penghapusan file mempertahankan primary yang dapat dibaca hingga pembersihan penyimpanan sekunder dikonfirmasi. `fileConfig.retainedFileCleanup` memiliki nilai default `false`: file yang disematkan dan tujuan Code Interpreter yang dipertahankan tidak dibersihkan secara destruktif hingga fitur ini diaktifkan secara eksplisit. Aktifkan hanya setelah setiap replika dan target rollback membaca tujuan file yang dipertahankan.

| Field | Default | Arti |
| ----- | ------- | ---- |
| `retainedFileCleanup` | `false` | Pilih untuk mengaktifkan pembersihan menggunakan metadata tujuan yang dipertahankan setelah peluncuran reader. |
| `vectorOwnershipTrackingStart` | Tidak diatur | Batas waktu date-time UTC yang dipilih setelah setiap penulis vektor lama dan target rollback telah dihentikan. |
| `vectorDeletionConcurrency` | `4` | Bilangan bulat `1` hingga `16`; jumlah maksimum penghapusan namespace yang berjalan bersamaan per file. |

Penghapusan vektor juga memerlukan kepemilikan yang tercatat lengkap dan bukti waktu penyisipan pada atau setelah batas waktu (cutoff) penulis yang aman. Bukti yang hilang, tidak valid, berasal dari masa depan, atau mendahului cutoff akan gagal secara aman (fail closed) dan membiarkan file beserta vektornya tetap berada di tempatnya. Menetapkan cutoff tidak memperbaiki metadata kepemilikan yang lebih lama, dan cutoff tidak boleh dimundurkan untuk membuat file lama yang ambigu menjadi memenuhi syarat.

Target pembersihan mencakup setiap namespace entitas yang tercatat dan namespace tanpa cakupan (unscoped). Sebuah namespace dinyatakan telah dibersihkan setelah respons DELETE berhasil. Respons `404` hanya diterima sebagai bukti ketiadaan setelah pemeriksaan inventaris dalam namespace yang sama berhasil dan mengecualikan file tersebut. Jika ada sekunder atau namespace yang tidak dapat dikonfirmasi tidak ada, primary tetap tersedia untuk dicoba ulang. Pengaturan ini tidak mengisi ulang (backfill) rekaman lama; rencanakan rekonsiliasi yang diverifikasi secara terpisah untuk file historis yang ambigu.
