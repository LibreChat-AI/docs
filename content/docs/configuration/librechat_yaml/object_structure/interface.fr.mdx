## Vue d'ensemble [#overview]

L'objet `interface` permet la personnalisation de divers éléments de l'interface utilisateur au sein de l'application, incluant les paramètres de visibilité et de comportement pour des composants tels que les menus, les panneaux et les liens. Cette section fournit une analyse détaillée de la structure de l'objet `interface`.

Voici les champs sous `interface` :

- `theme`
- `mcpServers`
- `privacyPolicy`
- `termsOfService`
- `modelSelect`
- `agentSelectorLimit`
- `parameters`
- `contextUsage`
- `contextCost`
- `currency`
- `presets`
- `prompts`
- `bookmarks`
- `memories`
- `multiConvo`
- `agents`
- `remoteAgents`
- `skills`
- `sharedLinks`
- `schedules`
- `temporaryChat`
- `temporaryChatRetention`
- `generalChatRetention`
- `retentionMode`
- `retainAgentFiles`
- `autoSubmitFromUrl`
- `customWelcome`
- `codeHighlightThrottleMs`
- `artifactUndocking`
- `runCode`
- `webSearch`
- `fileSearch`
- `fileCitations`
- `feedback`
- `replyNotifications`
- `defaultPinnedTools`
- `composerRecentFiles`
- `steerArmConfirmationTimeoutMs`
- `queuedTurnReconciliationTimeoutMs`
- `queuedSendLockTimeoutMs`
- `peoplePicker`
- `marketplace`

**Notes :**

- Les configurations `interface` sont appliquées globalement au sein de l'application.
- Des valeurs par défaut sont fournies pour la plupart des paramètres, mais elles peuvent être remplacées en fonction de besoins ou de conditions spécifiques.
- La logique conditionnelle dans l'application peut modifier davantage ces paramètres en fonction d'autres configurations telles que les Model Specs.

<Callout type="warning" title="Obsolète : champs d'effets secondaires de permission">
Plusieurs champs ci-dessous (`mcpServers`, `prompts`, `bookmarks`, `memories`, `multiConvo`, `agents`, `remoteAgents`, `skills`, `sharedLinks`, `schedules`, `temporaryChat`, `runCode`, `webSearch`, `fileSearch`, `fileCitations`, `peoplePicker`, `marketplace`) ne se contentent pas d'activer ou désactiver l'interface utilisateur, ils initialisent les permissions de rôle dans la base de données au démarrage, et ce uniquement pour le rôle `USER` intégré.

Pour une gestion continue, utilisez le [**LibreChat Admin Panel**](/docs/features/admin_panel), qui modifie directement la matrice des permissions sur chaque rôle (y compris les rôles personnalisés). Ces champs YAML restent pris en charge pour l'initialisation d'une nouvelle instance ou pour les déploiements entièrement pilotés par fichier, mais ne devraient plus être utilisés comme méthode principale pour gérer les permissions des fonctionnalités.

Consultez [Access Control](/docs/features/access_control) pour le modèle de permission complet.

</Callout>

```yaml filename="interface"
  modelSelect: false
  agentSelectorLimit: 10
  parameters: true
  contextUsage: true
  contextCost: true
  currency:
    code: EUR
    rate: 0.92
  presets: false
  prompts:
    use: true
    create: true
    share: true
    public: false
  bookmarks: true
  multiConvo: true
  agents:
    use: true
    create: true
    share: true
    public: false
  skills:
    use: true
    create: true
    share: false
    public: false
    defaultActiveOnShare: false
  sharedLinks:

    share: true
    public: false
    snapshotFiles: true
  schedules:

    minIntervalMinutes: 60
    autoDisableAfterFailures: 5

  customWelcome: 'Hey {{user.name}}! Welcome to LibreChat'
  codeHighlightThrottleMs: 300
  artifactUndocking: true

  webSearch: true
  fileSearch: true
  fileCitations: true
  feedback: true
  defaultPinnedTools:
    - artifacts

```

## theme

Définit le thème de déploiement appliqué à chaque utilisateur, en mode clair comme en mode sombre. Il peut s'agir soit du nom d'un thème intégré (`librechat` ou `clickhouse`), soit d'une définition de thème en ligne avec ses propres couleurs, rayons, polices, ombres et animations.

Il supplante les couleurs définies au moment de la compilation `REACT_APP_THEME_*` ainsi que les thèmes enregistrés par les utilisateurs, s'efface devant les modes à contraste élevé et n'est jamais enregistré dans le navigateur de l'utilisateur. Sa suppression rétablit le thème propre à chaque utilisateur, ou les couleurs `REACT_APP_THEME_*` si le client a été compilé avec celles-ci.

**Clé :**

<OptionTable
  options={[
    [
      'theme',
      'String or Object',
      'Un nom de thème groupé, ou une définition de thème en ligne avec `version`, `name`, `modes` et `brands`.',
      'theme: clickhouse',
    ],
  ]}
/>

**Par défaut :** _Aucun (le thème LibreChat par défaut, ou le thème propre à l'utilisateur)_

**Exemple :**

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

Consultez [Theme](/docs/configuration/librechat_yaml/object_structure/theme) pour le format de définition en ligne, chaque clé d'apparence avec sa valeur par défaut, le thème de référence ClickHouse et la façon dont les liens partagés choisissent leur thème.

### Où les liens de politique apparaissent [#where-the-policy-links-appear]

Sur les écrans de connexion et d'inscription, les politiques publiées apparaissent sous forme de phrase de consentement : « En continuant, vous acceptez les Conditions d'utilisation et reconnaissez la Politique de confidentialité. » Si une seule politique est publiée, la phrase ne mentionne que celle-ci. Sur l'écran d'inscription, elle se situe sous le bouton de soumission ; sur l'écran de connexion, elle se situe en dessous des options de connexion.

Dans le chat, les liens vers la politique apparaissent sous la zone de message sur l'écran d'accueil d'un nouveau chat, et sont masqués une fois qu'une conversation commence.

Une politique dont l'attribut `externalUrl` est vide ou non renseigné est considérée comme non publiée et n'est jamais affichée. Lorsque `termsOfService.modalAcceptance` est défini sur `true`, les écrans d'authentification affichent des liens de politique simples au lieu de la phrase de consentement, car les utilisateurs acceptent explicitement les conditions dans la boîte de dialogue après s'être connectés.

Lorsque l'acceptation des modalités est activée, LibreChat enregistre à la fois l'état d'acceptation et l'heure à laquelle elle a été acceptée. Après la mise à niveau d'un déploiement existant, exécutez `npm run migrate:terms-timestamp` pour compléter les utilisateurs ayant accepté mais ne disposant pas d'horodatage. La migration demande une confirmation, traite tous les locataires, utilise l'heure de création du compte de chaque utilisateur comme valeur de secours et se termine avec un code non nul si un lot échoue. L'exécution de `npm run reset-terms` efface à la fois l'état d'acceptation et son horodatage, obligeant ainsi les utilisateurs à accepter à nouveau.

## prompts

> **Obsolète pour la gestion des permissions.** Initialise les permissions de rôle `PROMPTS` au démarrage uniquement pour le rôle `USER` par défaut. Préférez le [Panneau d'administration](/docs/features/admin_panel) pour gérer les permissions des prompts par rôle/groupe/utilisateur.

**Clé :**

<OptionTable
  options={[
    [
      'prompts',
      'Boolean or Object',
      'Contrôle les fonctionnalités liées aux prompts pour tous les utilisateurs. Peut être un booléen pour une activation/désactivation simple, ou un objet pour un contrôle granulaire sur l\'utilisation, la création, le partage et la visibilité publique.',
      'When set to `false`, users will not have access to create, edit, or use custom prompts.',
    ],
  ]}
/>

**Par défaut :** `true`

**Important : Configuration booléenne vs objet**

- **Booléen (`prompts: true`)** : Met uniquement à jour l'autorisation `use`. Les valeurs d'autorisation `create`, `share` et `public` existantes sont **préservées** dans la base de données. - **Objet** : Met à jour uniquement les sous-autorisations explicitement spécifiées. Toutes les autorisations non incluses dans la configuration sont conservées telles qu'elles sont dans la base de données.

## agentSelectorLimit

Limite le sélecteur du panneau des Agents non recherchés à `10` Agents par défaut. Définissez un nombre entier compris entre `1` et `100` pour modifier le nombre d'éléments listés avant que l'utilisateur ne commence à taper. La recherche permet toujours d'accéder à tous les Agents accessibles ; cette limite n'est pas un paramètre de contrôle d'accès.


## temporaryChatRetention

La configuration `temporaryChatRetention` vous permet de personnaliser la durée de conservation des conversations temporaires avant qu'elles ne soient automatiquement supprimées. Sous `retentionMode: "ephemeral"`, chaque conversation est temporaire ; cette valeur représente donc la durée de vie de chaque conversation.

**Clé :**

<OptionTable
  options={[
    [
      'temporaryChatRetention',
      'Number',

      'temporaryChatRetention: 168',
    ],
  ]}
/>

**Règles de validation :**

- **Minimum** : 1 heure (empêche la suppression immédiate)
- **Maximum** : 8760 heures (rétention maximale de 1 an)
- **Par défaut** : 720 heures (30 jours)

**Méthodes de configuration :**

1. **LibreChat.yaml** (recommandé) : `interface.temporaryChatRetention: 168`
2. **Variable d'environnement** (obsolète) : `TEMP_CHAT_RETENTION_HOURS=168`

> **Note :** La variable d'environnement `TEMP_CHAT_RETENTION_HOURS` est obsolète. Veuillez utiliser l'option de configuration `interface.temporaryChatRetention` dans `librechat.yaml` à la place. La valeur du fichier de configuration est prioritaire sur la variable d'environnement.

**Exemple :**

```yaml filename="interface / temporaryChatRetention"
interface:

  retentionMode: 'temporary'
```

**Périodes de rétention courantes :**

- **1 heure** : `temporaryChatRetention: 1` (rétention minimale)
- **24 heures** : `temporaryChatRetention: 24` (1 jour)
- **168 heures** : `temporaryChatRetention: 168` (1 semaine)
- **720 heures** : `temporaryChatRetention: 720` (30 jours - par défaut)
- **8760 heures** : `temporaryChatRetention: 8760` (1 an - maximum)

## retentionMode

Contrôle quelles données reçoivent des délais de rétention, et si chaque chat est forcé d'être temporaire.

**Clé :**

<OptionTable
  options={[
    [
      'retentionMode',
      'String',
      'Politique de rétention. « temporary » applique la rétention uniquement aux discussions que les utilisateurs marquent comme temporaires ; « all » applique la rétention à chaque conversation et message tout en les gardant visibles ; « ephemeral » force chaque discussion à être temporaire (masquée de l\'historique et de la recherche, bascule verrouillée).',

## fileCitations

Contrôle la disponibilité globale de la fonctionnalité de citations de fichiers. Lorsqu'elle est désactivée, elle supprime effectivement l'autorisation `FILE_CITATIONS` pour tous les utilisateurs, empêchant l'affichage de toute citation de fichier lors de l'utilisation de la recherche de fichiers, indépendamment des autorisations individuelles des utilisateurs.

> **Obsolète pour la gestion des permissions.** Initialise/active globalement la permission de rôle `FILE_CITATIONS` au démarrage. Privilégiez le [Panneau d'administration](/docs/features/admin_panel) pour gérer les permissions de citations par rôle/groupe/utilisateur.

**Remarque :**

- Ce paramètre agit comme un commutateur global pour le système de permissions `FILE_CITATIONS` à l'échelle de l'instance.
- Lorsque défini sur `false`, aucun utilisateur ne verra les citations de fichiers, même s'ils ont reçu l'autorisation via des rôles.
- Les citations de fichiers nécessitent que la fonctionnalité `fileSearch` soit activée.
- Lors de l'utilisation d'agents avec une capacité de recherche de fichiers, le comportement des citations (quantité et qualité) peut être configuré via la [configuration de l'endpoint Agents](/docs/configuration/librechat_yaml/object_structure/agents#file-citation-configuration-examples).

## feedback

Contrôle si les boutons pouce levé / pouce baissé sont affichés sous les réponses. Lorsqu'il est défini sur `false`, les boutons sont supprimés de la ligne d'action du message et le serveur rejette les écritures de feedback ; ainsi, un déploiement qui masque ces contrôles ne stocke également aucune évaluation.

**Notes :**

- Les autres actions sur les messages (lecture à voix haute, copier, modifier, forker et régénérer) ne sont pas affectées, et la ligne d'actions se réorganise sans laisser d'espace vide.
- Lorsque les retours (feedback) sont désactivés, `PUT /api/messages/:conversationId/:messageId/feedback` répond avec `403` et `{"error": "Feedback is disabled"}` avant que quoi que ce soit ne soit écrit dans la base de données ou exporté.
- Les évaluations collectées pendant que la fonctionnalité était activée restent sur les messages existants. Le flag arrête les nouvelles écritures, il ne supprime pas les retours stockés.
- Les évaluations ne sont consommées en dehors de LibreChat que lorsque le suivi Langfuse est configuré, chaque évaluation étant envoyée en tant que score `user-feedback`. Voir [Scores de rétroaction des messages](/docs/configuration/langfuse#message-feedback-scores).
- Il s'agit d'un indicateur d'interface simple plutôt que d'une autorisation de rôle, il n'y a donc rien à accorder par rôle dans le [Admin Panel](/docs/features/admin_panel).

**Clé :**

**Par défaut :** `true`

**Exemple :**
