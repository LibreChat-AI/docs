## Übersicht [#overview]

Das `interface` Objekt ermöglicht die Anpassung verschiedener Benutzeroberflächenelemente innerhalb der Anwendung, einschließlich Sichtbarkeits- und Verhaltenseinstellungen für Komponenten wie Menüs, Panels und Links. Dieser Abschnitt bietet eine detaillierte Aufschlüsselung der Struktur des `interface` Objekts.

Dies sind Felder unter `interface`:

- `theme`
- `mcpServers`
- `privacyPolicy`
- `termsOfService`
- `modelSelect`
- `agentSelectorLimit`
- `parameters`
- `contextUsage`
- `contextCost`
- `currency`
- `presets`
- `prompts`
- `bookmarks`
- `memories`
- `multiConvo`
- `agents`
- `remoteAgents`
- `skills`
- `sharedLinks`
- `schedules`
- `temporaryChat`
- `temporaryChatRetention`
- `generalChatRetention`
- `retentionMode`
- `retainAgentFiles`
- `autoSubmitFromUrl`
- `customWelcome`
- `codeHighlightThrottleMs`
- `artifactUndocking`
- `runCode`
- `webSearch`
- `fileSearch`
- `fileCitations`
- `feedback`
- `replyNotifications`
- `defaultPinnedTools`
- `composerRecentFiles`
- `steerArmConfirmationTimeoutMs`
- `queuedTurnReconciliationTimeoutMs`
- `queuedSendLockTimeoutMs`
- `peoplePicker`
- `marketplace`

**Hinweise:**

- Die `interface`-Konfigurationen werden global innerhalb der Anwendung angewendet.
- Für die meisten Einstellungen sind Standardwerte vorgesehen, diese können jedoch basierend auf spezifischen Anforderungen oder Bedingungen überschrieben werden.
- Die bedingte Logik in der Anwendung kann diese Einstellungen basierend auf anderen Konfigurationen, wie z. B. Model Specs, weiter modifizieren.

<Callout type="warning" title="Veraltet: Felder für Berechtigungs-Seiteneffekte">
Mehrere Felder unten (`mcpServers`, `prompts`, `bookmarks`, `memories`, `multiConvo`, `agents`, `remoteAgents`, `skills`, `sharedLinks`, `schedules`, `temporaryChat`, `runCode`, `webSearch`, `fileSearch`, `fileCitations`, `peoplePicker`, `marketplace`) schalten nicht nur die Benutzeroberfläche um, sondern initialisieren beim Start Rollenberechtigungen in der Datenbank, und zwar nur für die integrierte `USER`-Rolle.

Für die laufende Verwaltung verwenden Sie das [**LibreChat Admin Panel**](/docs/features/admin_panel), das die Berechtigungsmatrix direkt für jede Rolle (einschließlich benutzerdefinierter Rollen) bearbeitet. Diese YAML-Felder werden weiterhin für das Bootstrapping einer neuen Instanz oder für vollständig dateibasierte Bereitstellungen unterstützt, sollten jedoch nicht mehr als primäre Methode zur Verwaltung von Funktionsberechtigungen verwendet werden.

Siehe [Access Control](/docs/features/access_control) für das vollständige Berechtigungsmodell.

</Callout>

## theme

Legt das Deployment-Theme fest, das für jeden Benutzer sowohl im hellen als auch im dunklen Modus angewendet wird. Entweder der Name eines gebündelten Themes (`librechat` oder `clickhouse`) oder eine Inline-Theme-Definition mit eigenen Farben, Radien, Schriftarten, Schatten und Bewegungen.

Es hat Vorrang vor den zur Build-Zeit festgelegten `REACT_APP_THEME_*`-Farben sowie den gespeicherten Designs der Benutzer, ordnet sich den Kontrastmodi unter und wird niemals im Browser des Benutzers gespeichert. Das Entfernen stellt das jeweils gespeicherte Design des Benutzers wieder her oder die `REACT_APP_THEME_*`-Farben, sofern der Client mit diesen erstellt wurde.

**Schlüssel:**

<OptionTable
  options={[
    [
      'theme',
      'String or Object',
      'Ein gebündelter Themenname oder eine Inline-Themendefinition mit `version`, `name`, `modes` und `brands`.',
      'theme: clickhouse',
    ],
  ]}
/>

**Standard:** _Keine (das Standard-LibreChat-Theme oder das eigene Theme des Benutzers)_

**Beispiel:**

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

Siehe [Theme](/docs/configuration/librechat_yaml/object_structure/theme) für das Inline-Definitionsformat, jeden Appearance-Key mit seinem Standardwert, das ClickHouse-Referenz-Theme und wie geteilte Links ihr Theme auswählen.

### Wo die Richtlinien-Links erscheinen [#where-the-policy-links-appear]

Auf den Anmelde- und Registrierungsbildschirmen erscheinen veröffentlichte Richtlinien als Zustimmungssatz: "Durch das Fortfahren stimmen Sie den Terms of Service zu und erkennen die Privacy Policy an." Wenn nur eine Richtlinie veröffentlicht ist, nennt der Satz nur diese eine. Auf dem Registrierungsbildschirm befindet er sich unter der Schaltfläche zum Absenden; auf dem Anmeldebildschirm befindet er sich unter den Anmeldeoptionen.

Im Chat erscheinen die Richtlinien-Links unter dem Nachrichtenfeld auf dem Begrüßungsbildschirm eines neuen Chats und werden ausgeblendet, sobald eine Unterhaltung beginnt.

Eine Richtlinie, deren `externalUrl` leer oder nicht vorhanden ist, wird als nicht veröffentlicht behandelt und niemals angezeigt. Wenn `termsOfService.modalAcceptance` auf `true` gesetzt ist, zeigen die Authentifizierungsbildschirme einfache Richtlinien-Links anstelle des Zustimmungssatzes, da die Benutzer den Bedingungen nach der Anmeldung explizit im Dialog zustimmen.

Wenn die Modal-Akzeptanz aktiviert ist, protokolliert LibreChat sowohl den Akzeptanzstatus als auch den Zeitpunkt der Akzeptanz. Führen Sie nach dem Upgrade einer bestehenden Bereitstellung `npm run migrate:terms-timestamp` aus, um akzeptierte Benutzer nachzutragen, die keinen Zeitstempel haben. Die Migration fragt nach einer Bestätigung, verarbeitet alle Mandanten, verwendet den Zeitpunkt der Kontoerstellung des jeweiligen Benutzers als Fallback und beendet den Vorgang mit einem Status ungleich Null, falls ein Batch fehlschlägt. Das Ausführen von `npm run reset-terms` löscht sowohl den Akzeptanzstatus als auch den Zeitstempel, sodass Benutzer erneut zustimmen müssen.

## prompts

> **Veraltet für die Berechtigungsverwaltung.** Initialisiert die `PROMPTS`-Rollenberechtigungen beim Start nur für die Standard-`USER`-Rolle. Verwenden Sie bevorzugt das [Admin Panel](/docs/features/admin_panel), um Prompt-Berechtigungen pro Rolle/Gruppe/Benutzer zu verwalten.

**Schlüssel:**

<OptionTable
  options={[
    [
      'prompts',
      'Boolean or Object',
      'Steuert Prompt-bezogene Funktionen für alle Benutzer. Kann ein Boolean für einfaches Aktivieren/Deaktivieren sein oder ein Objekt für eine granulare Steuerung von Nutzung, Erstellung, Teilen und öffentlicher Sichtbarkeit.',
      'When set to `false`, users will not have access to create, edit, or use custom prompts.',
    ],
  ]}
/>

**Standard:** `true`

**Wichtig: Boolean vs. Objekt-Konfiguration**

- **Boolean (`prompts: true`)**: Aktualisiert nur die `use`-Berechtigung. Bestehende `create`-, `share`- und `public`-Berechtigungswerte werden aus der Datenbank **beibehalten**. Verwenden Sie dies als einfachen Funktionsschalter, ohne andere Einstellungen zu beeinflussen, die über das Admin-Panel konfiguriert wurden.

- **Objekt**: Aktualisiert nur die Unterberechtigungen, die explizit angegeben sind. Alle Berechtigungen, die nicht in der Konfiguration enthalten sind, werden aus der Datenbank beibehalten.

Bei Verwendung der Objektstruktur:

**Untergeordnete Schlüssel:**

## temporaryChatRetention

Die `temporaryChatRetention`-Konfiguration ermöglicht es Ihnen anzupassen, wie lange temporäre Chats aufbewahrt werden, bevor sie automatisch gelöscht werden. Unter `retentionMode: "ephemeral"` ist jeder Chat temporär, daher entspricht dieser Wert der Lebensdauer jedes Chats.

**Schlüssel:**

    ],
  ]}
/>

**Validierungsregeln:**

- **Minimum**: 1 Stunde (verhindert sofortiges Löschen)
- **Maximum**: 8760 Stunden (maximal 1 Jahr Aufbewahrungsdauer)
- **Standard**: 720 Stunden (30 Tage)

**Konfigurationsmethoden:**

1. **LibreChat.yaml** (empfohlen): `interface.temporaryChatRetention: 168`
2. **Umgebungsvariable** (veraltet): `TEMP_CHAT_RETENTION_HOURS=168`

  retentionMode: 'temporary'

**Gängige Aufbewahrungsfristen:**

- **1 Stunde**: `temporaryChatRetention: 1` (minimale Aufbewahrungsdauer)
- **24 Stunden**: `temporaryChatRetention: 24` (1 Tag)
- **168 Stunden**: `temporaryChatRetention: 168` (1 Woche)
- **720 Stunden**: `temporaryChatRetention: 720` (30 Tage – Standard)
- **8760 Stunden**: `temporaryChatRetention: 8760` (1 Jahr - Maximum)

## retentionMode

Steuert, welche Daten Aufbewahrungsfristen erhalten und ob jeder Chat zwangsweise als temporär festgelegt wird.

**Schlüssel:**

<OptionTable
  options={[
    [
      'retentionMode',
      'String',
      'Aufbewahrungsrichtlinie. „temporary“ wendet die Aufbewahrung nur auf Chats an, die Benutzer als temporär markieren; „all“ wendet die Aufbewahrung auf jede Konversation und Nachricht an, während diese sichtbar bleiben; „ephemeral“ erzwingt, dass jeder Chat temporär ist (aus Verlauf und Suche ausgeblendet, Umschalter gesperrt).',

## fileCitations

Steuert die globale Verfügbarkeit der Dateizitat-Funktionalität. Wenn diese deaktiviert ist, wird die `FILE_CITATIONS`-Berechtigung für alle Benutzer effektiv entfernt, wodurch verhindert wird, dass Dateizitate bei der Verwendung der Dateisuche angezeigt werden, unabhängig von individuellen Benutzerberechtigungen.

> **Veraltet für die Berechtigungsverwaltung.** Legt beim Start die `FILE_CITATIONS` Rollenberechtigung global fest (Seeds/Globally Gates). Bevorzugen Sie das [Admin Panel](/docs/features/admin_panel) für die Verwaltung von Zitatberechtigungen pro Rolle/Gruppe/Benutzer.

**Hinweis:**

- Diese Einstellung fungiert als globaler Schalter für das `FILE_CITATIONS`-Berechtigungssystem im gesamten System.
- Wenn dies auf `false` gesetzt ist, sehen keine Benutzer Dateizitate, selbst wenn ihnen die Berechtigung durch Rollen erteilt wurde.
- Für Dateizitate muss die Funktion `fileSearch` aktiviert sein.
- Wenn Sie Agenten mit Dateisuchfunktion verwenden, kann das Zitierverhalten (Quantität und Qualität) über die [Agents endpoint configuration](/docs/configuration/librechat_yaml/object_structure/agents#file-citation-configuration-examples) konfiguriert werden.

**Schlüssel:**

<OptionTable
  options={[
    [
      'fileCitations',
      'Boolean',
      'Aktiviert oder deaktiviert global die FILE_CITATIONS-Berechtigung für alle Benutzer und steuert, ob Suchergebnisse von Dateien Quellenangaben enthalten dürfen.',
    ],
  ]}
/>

**Standard:** `true`

**Beispiel:**

```yaml filename="interface / fileCitations"
interface:
  fileCitations: true
```

## feedback

Steuert, ob die „Daumen hoch“ / „Daumen runter“-Schaltflächen unter den Antworten angezeigt werden. Wenn dies auf `false` gesetzt ist, werden die Schaltflächen aus der Nachrichten-Aktionsleiste entfernt und der Server lehnt Feedback-Schreibvorgänge ab. Eine Bereitstellung, die diese Steuerelemente ausblendet, speichert also auch keine Bewertungen.

**Hinweise:**

- Die anderen Nachrichtenaktionen (vorlesen, kopieren, bearbeiten, forken und neu generieren) sind davon nicht betroffen, und die Aktionsleiste fließt um, ohne eine Lücke zu hinterlassen.
- Wenn Feedback deaktiviert ist, antwortet `PUT /api/messages/:conversationId/:messageId/feedback` mit `403` und `{"error": "Feedback is disabled"}`, bevor etwas in die Datenbank geschrieben oder exportiert wird.
- Bewertungen, die während der Aktivierung der Funktion gesammelt wurden, bleiben bei bestehenden Nachrichten erhalten. Das Flag stoppt neue Schreibvorgänge, es löscht jedoch kein gespeichertes Feedback.
- Bewertungen werden außerhalb von LibreChat nur dann verarbeitet, wenn das Langfuse-Tracing konfiguriert ist; in diesem Fall wird jede Bewertung als `user-feedback`-Score gesendet. Siehe [Message Feedback Scores](/docs/configuration/langfuse#message-feedback-scores).
- Dies ist eher ein Flag für die Benutzeroberfläche als eine Rollenberechtigung, daher gibt es im [Admin Panel](/docs/features/admin_panel) nichts pro Rolle zu gewähren.

**Schlüssel:**

<OptionTable
  options={[
    [
      'feedback',
      'Boolean',
      'Zeigt oder verbirgt die Feedback-Schaltflächen „Daumen hoch“/„Daumen runter“ bei Antworten.',
      'When disabled, the buttons are removed for every user and the feedback endpoint rejects writes with a 403.',
    ],
  ]}
/>

**Standard:** `true`

**Beispiel:**

```yaml filename="interface / feedback"
interface:
  feedback: false
```

## replyNotifications

Steuert, welche Benachrichtigungen bei ungelesenen Antworten Benutzer aktivieren dürfen. Wenn eine Antwort abgeschlossen wird, während ein Benutzer einen anderen Chat betrachtet, markiert LibreChat diesen Chat als ungelesen. Benutzer wählen ihre eigenen Benachrichtigungen unter **Einstellungen > Allgemein > Benachrichtigungen** aus; diese Optionen legen lediglich fest, welche dieser Benachrichtigungen angeboten werden.

Die ungelesen-Punkte in der Chat-Liste und die Aktion **Als ungelesen markieren** sind immer verfügbar und werden von dieser Einstellung nicht beeinflusst.

**Schlüssel:**

      '',
    ],
  ]}
/>

**Untergeordnete Schlüssel:**

<OptionTable
  options={[
    ['tabBadge', 'Boolean', 'Erlaubt die Anzeige der ungelesenen Nachrichten im Browsertab-Titel und -Icon. Standard: true.', 'tabBadge: true'],

    ['sound', 'Boolean', 'Erlaubt Benutzern, einen Ton für neue Antworten zu aktivieren. Standard: true.', 'sound: true'],
    ['pollLimit', 'Number', 'Anzahl der letzten Konversationen, die bei jeder Hintergrundprüfung berücksichtigt werden. Bereich 1 bis 100. Standard: 100.', 'pollLimit: 100'],
    ['pollIntervalMs', 'Number', 'Millisekunden zwischen den Prüfungen, während sich der Tab im Hintergrund befindet und eine Warnung aktiv ist. Bereich 10000 bis 600000. Standard: 30000.', 'pollIntervalMs: 30000'],

Das Setzen von `tabBadge`, `desktop` oder `sound` auf `false` blendet diese Option in den Benutzereinstellungen aus. Was der jeweilige Benutzer aktiviert, wird pro Gerät gespeichert. Siehe [Settings](/docs/features/settings) für die Benutzerseite.

## defaultPinnedTools

Legt die anfänglichen angehefteten Tools in der Prompt-Leiste für Benutzer fest, die ihren Status für angeheftete Tools noch nicht angepasst haben. Sobald ein Benutzer ein Tool anheftet oder löst, speichert LibreChat die Wahl dieses Benutzers.

**Schlüssel:**

<OptionTable
  options={[
    [
      'defaultPinnedTools',
      'Array of strings',
      'Integrierte Tool-Keys, die für neue oder nicht angepasste Benutzer standardmäßig in der Composer-Leiste angeheftet sein sollten.',
      'When omitted, built-in tools start unpinned.',
    ],
  ]}
/>

**Unterstützte Werte:**

- Integrierte Tool-Schlüssel: `artifacts`, `execute_code`, `web_search`, `file_search`, `skills`

Das Schlüsselwort `mcp` und MCP-Servernamen werden aus Kompatibilitätsgründen weiterhin akzeptiert, aber der neu gestaltete [composer](/docs/features/composer) heftet MCP-Server nicht mehr an die Leiste an. Benutzer aktivieren Server stattdessen über den Bereich **MCP Servers** in der Palette.

**Beispiel:**

```yaml filename="interface / defaultPinnedTools"
interface:
  defaultPinnedTools:
    - artifacts
    - execute_code
```

## composerRecentFiles

Wie viele kürzlich verwendete Dateien die [composer](/docs/features/composer)-Palette für ihren **Your files**-Bereich anfordert, bevor der Benutzer eine Suche durchführt.

**Schlüssel:**

<OptionTable
  options={[
    [
      'composerRecentFiles',
      'Number',
      'Anzahl der kürzlich verwendeten Dateien, die in der Composer-Palette angezeigt werden. Bereich 0 bis 100. 0 blendet die Liste aus.',
      'composerRecentFiles: 5',
    ],
  ]}
/>

**Standard:** `5`

Die Palette zeigt maximal fünf davon an, daher haben Werte über `5` keine sichtbare Auswirkung; verwenden Sie einen niedrigeren Wert, um die Liste zu verkürzen, oder `0`, um sie auszublenden. Die Suche in der Palette oder **Alle anzeigen** erreicht weiterhin jede Datei. Der Wert wird außerdem durch das übergeordnete [`fileListLimit`](/docs/configuration/librechat_yaml/object_structure/config#filelistlimit) begrenzt.

```yaml filename="interface / composerRecentFiles"
interface:
  composerRecentFiles: 10
```

## Warteschlangen- und Steuerungstimeouts [#queue-and-steer-timeouts]

Drei Timeouts steuern, wie der Client Nachrichten verarbeitet, die gesendet werden, während eine Antwort noch gestreamt wird (in die Warteschlange eingereihte Nachrichten und Steer-Befehle, siehe [Agents](/docs/features/agents)). Die Standardwerte sind für die meisten Bereitstellungen geeignet; erhöhen Sie diese, wenn ein langsamer Proxy oder ein verzögertes Datenbank-Replikat dazu führt, dass Nachrichten in der Warteschlange als unbestätigt angezeigt werden.

<OptionTable
  options={[
    [
      'steerArmConfirmationTimeoutMs',
      'Number',
      'Wie lange der Client in Millisekunden auf die Bestätigung eines Steer durch den Server wartet, bevor er den Vorgang abbricht. Standard: 10000.',
      'steerArmConfirmationTimeoutMs: 10000',
    ],
    [
      'queuedTurnReconciliationTimeoutMs',
      'Number',
      'Wie lange der Client in Millisekunden prüft, ob eine Nachricht in der Warteschlange, deren Zustellung ungewiss ist, empfangen wurde. Standard: 60000.',
      'queuedTurnReconciliationTimeoutMs: 60000',
    ],
    [
      'queuedSendLockTimeoutMs',
      'Number',
      'Wie lange eine in der Warteschlange befindliche Nachricht den Chat beim Starten blockieren darf, in Millisekunden, bevor die Blockierung aufgehoben wird. Ein erfolgreicher Start hebt sie sofort auf; dies begrenzt nur einen Start, der im Hintergrund fehlgeschlagen ist. Standard: 60000.',
      'queuedSendLockTimeoutMs: 60000',
    ],
  ]}
/>

Alle drei müssen positive Ganzzahlen sein.

```yaml filename="interface / queue and steer timeouts"
interface:
  queuedTurnReconciliationTimeoutMs: 120000
```
