## Vue d'ensemble [#overview]

Les MCP Apps sont des interfaces interactives qu'un serveur MCP renvoie avec un résultat d'outil. LibreChat les affiche chacune dans un cadre sandboxé servi depuis une origine distincte, de sorte que le contenu des Apps ne peut pas atteindre la page LibreChat. L'objet `mcpAppSandbox` configure ce sandbox ainsi que les limites appliquées aux Apps.

Les MCP Apps sont activées avec [`mcpSettings.apps`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#apps). Chaque clé sous `mcpAppSandbox` est facultative et possède une valeur par défaut.

## Exemple [#example]

```yaml filename="mcpAppSandbox"
mcpAppSandbox:
  url: https://mcp-sandbox.example.com/api/mcp/sandbox
  maxActiveViews: 3
  maxPersistedAppBytes: 1048576
  maxAdmissionRequestsPerMinute: 240
  operationLimits:
    maxBytes: 4194304
    timeoutMs: 30000
    maxActive: 16
```

## Héberger le bac à sable [#hosting-the-sandbox]

La page de bac à sable est servie par LibreChat lui-même à l'adresse `/api/mcp/sandbox`. Attribuez-lui une origine dédiée, par exemple un second nom d'hôte dont le reverse proxy redirige vers le même serveur LibreChat, et définissez `url` sur cette route au sein de l'origine dédiée.

La page du bac à sable refuse d'être intégrée tant que l'origine de LibreChat n'est pas autorisée à l'encadrer. Définissez [`MCP_SANDBOX_FRAME_ANCESTORS`](/docs/configuration/dotenv#mcp-server-configuration) avec l'origine sur laquelle les utilisateurs ouvrent LibreChat, par exemple `MCP_SANDBOX_FRAME_ANCESTORS=https://chat.example.com`. Lorsqu'elle n'est pas définie, la page est servie avec `frame-ancestors 'none'` et les cadres des applications restent vides.
