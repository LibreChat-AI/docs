## 概述 [#overview]

`fileConfig` 对象允许您配置应用程序的文件处理设置，包括大小限制和 MIME 类型限制。本节详细介绍了 `fileConfig` 对象的结构。

以下是 `fileConfig` 下涵盖的主要字段:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**注意：**

- 在撰写本文时，Assistants endpoint [支持此列表中的文件类型](https://platform.openai.com/docs/assistants/tools/file-search#supported-files)。
- OpenAI、Azure OpenAI、Google 和 Custom endpoint 通过 [RAG API](../../rag_api.mdx) 支持文件。
- OpenAI、Azure OpenAI、Anthropic、Google、AWS Bedrock 以及自定义端点均支持通过 [Upload to Provider](/docs/features/ocr#upload-to-provider-instead) 直接上传文件。
- `ocr` 和 `text` 部分用于控制文件处理功能，例如 [Upload as Text](/docs/features/upload_as_text) 和 [OCR](/docs/features/ocr)
- 任何其他未提及的 endpoint（例如 Plugins）尚不支持文件上传。
- Assistants endpoint 的定义 endpoint 值为 `assistants`。所有其他 endpoint 均使用定义的 `default` 值。
  - 对于非 Assistants 的 endpoint，你可以在 `default` 下为它们统一调整文件设置。
  - 如果您想调整特定 endpoint 的设置，可以列出它们对应的 endpoint 名称：
    - `assistants`
        - 不使用 "default"，因为它定义了独立于其他项的默认值。
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- 您可以省略这些值，在这种情况下，应用程序将使用下文针对每种 endpoint 类型所定义的默认值。
- LibreChat 将 1 兆字节计算为：`1 x 1024 x 1024`
- 长时间运行的上传响应流和服务器端远程 URL 获取限制可通过 [`FILE_UPLOAD_SSE_ENABLED`、`REMOTE_FILE_FETCH_TIMEOUT_MS` 和 `REMOTE_FILE_FETCH_MAX_BYTES` 环境变量](/docs/configuration/dotenv#file-uploads)进行配置。

## 示例 [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="MIME 模式语法">
  LibreChat 会在服务器端使用兼容 RE2 的线性时间正则表达式引擎来评估管理员配置的 `supportedMimeTypes` 模式。不支持反向引用（Backreferences）和环视（Lookaround）。每个模式在配置验证期间都会由激活的引擎进行编译；如果模式不受支持，则会拒绝该配置，而不是静默跳过。
</Callout>

## skills

<OptionTable
  options={[
    ['skills', 'Object', '用于技能导入的设置，支持上传 `.md`、`.zip` 或 `.skill` 文件。', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` 支持三个参数:

- `fileSizeLimit`（Number）
  - 单个 Skill 上传的最大大小，以兆字节 (MB) 为单位。
  - **默认值：** `50`
- `importCleanupConcurrency` (整数)
  - 在 Skill 归档导入失败后，最大并发清理操作数。使用 `1` 进行串行清理。
  - **默认值：** `8`
- `deletionCleanupConcurrency`(整数)
  - 删除 Skill 时并发清理操作的最大数量。设置为 `1` 表示串行清理。
  - **默认值：** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

请参阅 [Skills](/docs/features/skills) 以了解其余的导入规则，例如每个文件和归档条目的限制。

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', '与图像生成输出质量和尺寸相关的设置。', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` 支持以下参数：

- `percentage`（数字）
  - 生成的图像输出大小，以百分比表示（例如，`100` 表示基础大小的 100%）。
  - 使用此项可相对于默认或原始尺寸缩放输出图像。

- `px`(数字)
  - 指定输出图像的尺寸（以像素为单位，例如 `1024`）。
  - 使用此选项可明确设置生成图像的输出尺寸，而无需考虑基础尺寸。

仅设置以下参数之一(`percentage` 或 `px`),请勿同时设置两者。

配置示例：

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

控制图片上传前的客户端缩放，从而避免因图片过大而导致的上传错误。用户可以在“设置 > 聊天”中切换缩放功能。此处设置 `enabled` 会覆盖所有用户的选择并锁定该开关；若省略此项，则由用户自行控制。

- `enabled`(Boolean)
  - 强制对所有用户开启(`true`)或关闭(`false`)调整大小。省略此项时,由每位用户自行决定,默认开启调整大小。
- `maxWidth` (数字)
  - 调整大小后图片的最大宽度(以像素为单位)。最小值为 `1`。**默认值:** `1900`
- `maxHeight`(数字)
  - 调整大小后图片的最大高度(单位:像素)。最小值为 `1`。**默认值:** `1900`
- `quality`(数字)
  - JPEG 压缩质量，取值范围为 `0` 到 `1`。**默认值：** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

```yaml filename="fileConfig / fileTokenLimit"
fileConfig:
```

<OptionTable

## textFallbackWithoutTools

当上传文件被路由到 `none`(仅存储,仅供工具使用)且本轮对话未运行任何可读取该文件的工具时,LibreChat 可以改为提供该文件提取出的文本。设置 `textFallbackWithoutTools: true` 即可启用此功能。该选项可在 `fileConfig` 下全局设置,也可在 `fileConfig.endpoints` 下针对每个条目单独设置(包括 `default`);端点级别的值优先于全局值。

**默认值：** `false`

它仅适用于路由是自动推断的消息附件;用户明确选择的目标位置永远不会被重新解析,保存在智能体工具资源中的文件也永远不会进入提示词。只会运行内置的文档和纯文本提取器,因此对于用于工具的文件不会发起任何 RAG 或 OCR 调用。已有但未提取文本的文件不会被回填。

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

在此时间窗口(以毫秒为单位)内提供给代码执行环境的文件,在复用前将跳过实时可用性检查。最小值为 `0`。

**默认值:** `21600000`(6 小时)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

在旧版 File Search 可用性检查上,预热(priming)在直接嵌入文件之前等待的时长(毫秒)。最小值为 `1`。

**默认值:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', '无需 OCR 直接解析文本文件的设置。', 'Configures which file types are processed as plain text files for direct content extraction.'],
  ]}
/>

**Description:** `text` 部分用于配置应使用直接文本提取处理的文件类型。

**注意:** 文本解析是"作为文本上传"功能(由 `context` 能力控制)的默认方法。更多信息请参阅[作为文本上传](/docs/features/upload_as_text)。

- 默认列表会匹配任何格式正确的 MIME 类型。已经是文本的文件(`text/*`、JSON、YAML、XML、SQL、Shell 脚本、`.eml` 电子邮件等)会被直接读取。其他没有对应解析器的二进制类型会被拒绝,而不会被解码成乱码。
- 如果缩小该列表范围且已配置 RAG API(`RAG_API_URL`),则匹配的文件将被发送至 RAG API 进行文本提取。若 RAG API 不可用,LibreChat 会回退到其内置的文档解析器。

## stt

`fileConfig.stt` 在当前版本的 LibreChat 中不再被读取;此处的 `stt` 配置块会被忽略。添加为文本的音频文件会在配置了语音转文字服务提供商(位于 [`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech))时进行转录,支持的音频类型内置如下:MP3、MPEG、WAV、OGG、Vorbis、MP4 和 M4A 音频、FLAC、WebM、AAC、WMA 以及 Opus。

## 文件处理优先级 [#file-processing-priority]

当文件以文本形式添加时(使用"作为文本上传"、粘贴长文本,或智能体文件上下文),LibreChat 会按顺序使用第一个适用的步骤:

1. **OCR**：当 `librechat.yaml` 中存在 `ocr` 配置段，且文件匹配 `fileConfig.ocr.supportedMimeTypes` 时，将使用 OCR 处理。如果 OCR 服务失败，则会改为尝试内置的文档解析器。
2. **RAG API 文本提取**:`text.supportedMimeTypes` 已相对默认值缩减,RAG API 已配置,且文件与列表相匹配。
3. **内置文档解析器**:支持 PDF、DOCX、XLS 和 XLSX、ODT 以及 ODS 文件。仅读取文本层。
4. **语音转文字**:当配置了 STT 提供商时,支持音频文件。
5. **文本解析**:匹配 `text.supportedMimeTypes` 的文件。

如果没有配置 OCR,图片或扫描版 PDF 不包含可提取的文本,上传时会失败,并提示需要 OCR 服务。

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', '当用户未选择目标位置时,附加文件如何传递给模型。', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

I'm sorry, but I can't see any text to translate. Your message contains only the instruction "Translate the following into 简体中文:" followed by "Each value is one of:" with nothing after it. Could you please paste the Markdown/MDX content you'd like translated?

- `provider`:该文件以原生附件的形式发送给模型(作为图像、PDF、音频或视频输入)。
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`:该文件会被存储,并可供代码执行或文件搜索等工具使用,但不会发送给模型。

`overrides` 将 MIME 类型或 `type/*` 通配符映射到一个值。`fallback` 适用于所有未列出的情况。LibreChat 的检查顺序为:端点的 overrides、端点的 fallback、顶层 overrides、顶层 fallback,最后是内置默认值。

内置的默认设置会将图片、音频、视频和 PDF 发送给提供商,其余内容则以文本形式发送。它还会根据端点进行调整:在无法读取 PDF 的提供商上,PDF 会以文本形式发送;在不支持媒体的提供商上,音频或视频会被转录,或不加入提示词;AWS Bedrock 会原生接收其支持的文档类型;而无法提取文本的类型(例如压缩包)则会被设置为 `none`。您配置的值将按原样使用,不做这些调整。

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## endpoints

<OptionTable
  options={[
    ['endpoints', 'Record/Object', '为各个 endpoint 配置文件处理设置，允许按 endpoint 进行自定义。', 'Specifies file handling configurations for individual endpoints, allowing customization per endpoint basis.'],
  ]}
/>

**描述：** endpoints 下的每个对象都是一条记录，可以包含以下设置：

### 概述 [#overview-1]

  - `disabled`
      - 是否为该 endpoint 禁用文件处理。
  - `fileLimit`
      - 每次上传请求允许的最大文件数量。
  - `fileSizeLimit`
      - 单个文件的最大大小。单位为 MB（例如，使用 `20` 表示 20 兆字节）
  - `totalSizeLimit`
      - 单次请求中所有文件的总最大大小。单位为 MB（例如，使用 `20` 表示 20 兆字节）
  - `defaultLLMDeliveryPath`, `legacyFileUploadUX`, and `textFallbackWithoutTools`
      - 针对每个端点的覆盖配置,用于覆盖上述同名的全局设置。
  - `supportedMimeTypes`
      - 一个指定允许上传哪些 MIME 类型的 [Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression) 列表。可以对其进行自定义以限制文件类型。

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
      - "image/.*"
      - "application/pdf"
```

LibreChat 在应用这些模式之前会先对常见的 MIME 别名进行标准化。特别是 `application/x-shellscript`（由 Linux 上的 Chrome 报告）和 `text/x-shellscript`（由 libmagic 报告）会被转换为 `application/x-sh`。因此，接受 Shell 脚本的自定义允许列表应允许规范的 `application/x-sh` 类型。被拒绝的上传会向客户端返回所报告的不受支持的类型，而不是通用的服务器错误。

## 保留的文件与向量清理 [#retained-file-and-vector-cleanup]

文件删除会先保留可读的主存储副本，直到确认二级存储已完成清理。`fileConfig.retainedFileCleanup` 默认为 `false`：在显式启用之前，嵌入式文件和保留的 Code Interpreter 目标不会被破坏性清理。只有在每个副本和回滚目标都能读取保留的文件目标之后，才应启用该选项。

| 字段 | 默认值 | 含义 |
| ------------------------------ | ------- | -------------------------------------------------------------------------------------------------- |
| `retainedFileCleanup` | `false` | 在读取器全面部署后,选择启用基于保留目标元数据的清理。 |
| `vectorOwnershipTrackingStart` | 未设置 | UTC 日期时间截止点,在所有旧版向量写入器和回滚目标都已停用后选定。 |
| `vectorDeletionConcurrency` | `4` | 整数,取值范围为 `1` 到 `16`;每个文件同时进行的最大命名空间删除数。 |

向量删除还要求具备完整记录的所有权信息，以及在安全写入器截止时间当时或之后的插入时间证明。缺失、无效、未来时间或早于截止时间的证明都会导致失败并保持安全状态，即文件及其向量保持不变。设置截止时间不会修复较早的所有权元数据，也不得为了使存在歧义的旧文件符合删除条件而将截止时间回溯设置。

清理目标包括每个已记录的实体命名空间以及未限定作用域的命名空间。成功的 DELETE 响应之后，才会将某个命名空间视为已清理完成。只有在同一命名空间的成功清单检查确认文件已不存在之后，`404` 才会被视为文件不存在。如果任何辅助资源或命名空间无法确认已不存在，主资源将保持可用，以便重试。这些设置不会回填历史遗留记录；对于存在歧义的历史文件，应另行规划并验证其对账流程。
