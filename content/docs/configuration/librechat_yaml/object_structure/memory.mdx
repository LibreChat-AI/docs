## Overview

The `memory` object turns on [User Memory](/docs/features/memory) and sets its limits. Adding the section is what enables memory: saved entries are then added to each user's conversations, users can manage them in the Memories panel, and the Memory tool (`set_memory` and `delete_memory`) is offered in chats and agents, as long as the `memory` capability is enabled for the agents endpoint (it is by default).

Automatic memory extraction, where a separate memory agent reviews every exchange and saves facts without being asked, is a separate opt-in: set `agent.enabled: true` and give it a model.

## Example

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Configures the optional automatic memory agent. Can be either a reference to an existing agent by ID or a complete agent configuration.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

Configures the automatic memory agent. It only runs when `enabled` is `true`; an `agent` block without `enabled` is ignored and LibreChat logs a warning at startup.

When enabled, the memory agent runs at the start of every chat request, alongside the main response. It reviews the last `messageWindowSize` messages (capped at `maxInputTokens`) and saves or deletes entries on its own. It is given until the main response finishes plus up to 3 seconds; if it is still running after that, its result is dropped for that request.

The `agent` field supports two different configuration formats:

### Agent by ID

When you have a pre-configured agent, you can reference it by its ID:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Custom Agent Configuration

For more control, you can define a complete agent configuration:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Complete Configuration Example

An example using every memory option:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Using Custom Endpoints

The memory feature supports custom endpoints. When using a custom endpoint, the `provider` field should match the custom endpoint's `name` exactly. Custom headers with environment variables and user placeholders are properly resolved.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- See [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) for all available placeholders

## Notes

- `personalize` controls whether users can opt out, not whether memory is on. Use `disabled` to turn memory off.
- `maxInputTokens` bounds the chat context sent to the automatic memory agent, while `tokenLimit` caps the total size of stored memories.
- Custom `instructions` replace the default memory instructions and are mainly useful together with `validKeys`.
- Access is also controlled per role through the memory permissions (use, create, read, update, opt out). See [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), the [Admin Panel](/docs/features/admin_panel), or the admin settings at the bottom of the Memories panel.

## Troubleshooting

**Memory does nothing.** Check that the `memory` section exists and `disabled` is not `true`, that the user's role has permission to use memories, and that the user has not turned off **Reference saved memories**. For the Memory tool, the `memory` capability must be in the agents endpoint `capabilities` list if you set one.

**Nothing is saved automatically.** Automatic extraction needs `agent.enabled: true` and a valid `id`, or `provider` and `model`. Without it, entries are only saved when a user asks the model to remember something with the Memory tool on, or adds them by hand.

**The memory agent fails on a custom endpoint.** `provider` must match the custom endpoint `name` exactly. Confirm the endpoint works for normal chats first, then check that the environment variables its headers reference are set; header placeholders are resolved the same way for memory as for chat.

**Token usage is high.** Lower `maxInputTokens` or `messageWindowSize` to send less chat to the memory agent, lower `tokenLimit` to keep the stored memories (which are added to every request) small, and restrict `validKeys`.
