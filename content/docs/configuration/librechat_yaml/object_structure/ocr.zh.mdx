## 概述 [#overview]

`ocr` 对象允许您为应用程序配置光学字符识别 (OCR) 设置，从而实现从图像中提取文本的功能。本节详细介绍了 `ocr` 对象的结构。

有 5 个字段位于 `ocr` 之下:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**注意：**

- OCR is only active when `librechat.yaml` has an `ocr` section. Setting `OCR_API_KEY` alone does not turn it on. For Mistral's hosted API, `strategy: "mistral_ocr"` plus `OCR_API_KEY` in `.env` is enough, since `apiKey` and `baseURL` default to `${OCR_API_KEY}` and `${OCR_BASEURL}` (or `https://api.mistral.ai/v1` when that is unset).
- OCR 会对作为文本添加的文件运行:在聊天中使用"作为文本上传",以及在 Agent Builder 中使用"文件上下文"。Agent 还需要在 `endpoints.agents.capabilities` 中配置 `ocr` 能力,该能力默认已包含。若未启用此能力,已配置的 OCR 策略将拒绝上传,并提示"OCR capability is not enabled for Agents"。
- 哪些文件类型会进入 OCR 处理,由 [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr) 控制。
- 默认策略为 `mistral_ocr`。当 `mistralModel` 为空时,将使用 `mistral-ocr-latest`。
- 通过将策略设置为 `azure_mistral_ocr`，可以使用部署在 Azure 上的 Mistral OCR 模型。
- 通过将策略设置为 `vertexai_mistral_ocr`，可以使用 Google Vertex AI 部署的 Mistral OCR 模型。
  - 需要设置 `GOOGLE_SERVICE_KEY_FILE` 环境变量，并提供服务账号凭据。
  - 服务密钥可以通过以下方式提供：文件路径、URL、base64 编码的 JSON 或原始 JSON 字符串
  - 项目 ID 和位置将从服务账号凭据中自动提取
- 通过 `document_parser` 即可进行本地文本提取,支持 PDF、DOCX、XLS/XLSX、ODT 和 ODS 文件,单个文件大小最大为 15 MB,无需任何外部 API。
  - 使用本地的 `pdfjs-dist`、`mammoth` 和 `SheetJS`,无需 API 密钥或基础 URL
  - 只有 `strategy` 字段是必需的；`apiKey`、`baseURL` 和 `mistralModel` 将被忽略。
- `custom_ocr` 已被架构接受,但目前尚未实现。
- 支持对 `apiKey`、`baseURL` 和 `mistralModel` 参数进行环境变量解析。

## 自动文档解析（无需配置） [#automatic-document-parsing-no-configuration-required]

内置的 `document_parser` 会针对智能体文件上传自动运行，**即使您的 `librechat.yaml` 中未配置 `ocr` 块**也是如此。这意味着 PDF、DOCX、XLS/XLSX 和 ODS 文件无需任何设置即可直接解析。

解析逻辑的工作方式如下：

1. **未配置 `ocr`**:当上传代理上下文文件且其 MIME 类型匹配受支持的文档类型(PDF、DOCX、Excel、ODS)时,将直接使用 `document_parser`。无需为代理检查 OCR 功能。

2. **`ocr` 配置存在**:系统会首先尝试已配置的策略(例如 `mistral_ocr`)。如果已配置的策略在运行时**失败**,则会使用 `document_parser` 作为回退方案,以确保受支持的文档类型仍能成功提取文本。

3. **两者均失败**:如果配置的策略和文档解析器均失败(例如文件是没有嵌入文本的纯图像 PDF),系统将返回错误,提示需要 OCR 服务。

<Callout type="info">
`document_parser` 仅处理基于文本的文档。对于基于图像的 PDF 或扫描文档，您仍然需要配置 OCR 策略（例如 `mistral_ocr`）来从这些文件中的图像提取文本。
</Callout>

## 示例 [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

使用 Azure Mistral OCR 的示例：

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

使用 Google Vertex AI Mistral OCR 的示例：

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

对于 Vertex AI,请在您的 Google Cloud 项目中部署 Mistral OCR 模型,创建一个可以调用 Vertex AI 端点的服务账号,并将 `GOOGLE_SERVICE_KEY_FILE` 指向其密钥。该变量接受文件路径、用于获取密钥的 URL、Base64 编码的 JSON,或原始 JSON 字符串:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

使用本地文档解析器的示例（无需外部 API）：

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      '用于 OCR 连接时 SSRF 检查的受信任私有 host:port 例外。公共目标保持可用。条目必须包含端口，且不能是 URL、路径、CIDR 范围、裸主机名或公共 IP 字面量。',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

OCR 请求在连接时会阻止私有地址、回环地址、链路本地地址和云元数据目标，并禁用重定向。`allowedAddresses` 是一个豁免列表，用于精确指定受信任的私有 `host:port`、`private.ip:port` 或 `[ipv6]:port` 目标；它不会限制对公共目标的访问。

<Callout type="warning" title="谨慎设置信任豁免">
  仅在您控制的私有 OCR 服务中使用 `allowedAddresses`。被豁免的主机名会信任其在该端口上解析出的任何私有地址，因此在可能的情况下，请优先使用私有 IP 字面量。在使用正向代理时，代理必须强制执行目标 SSRF 策略；除非明确豁免，否则字面量私有目标地址仍将被阻止。
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', '要使用的 OCR 策略。', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**可用策略：**

- `mistral_ocr`:通过标准 Mistral API 使用 Mistral 的 OCR 功能。
- `azure_mistral_ocr`:使用部署在 Azure AI Foundry 上的 Mistral OCR 模型。将 `mistralModel` 设置为您的部署名称,并将 `baseURL` 设置为部署端点。
- `vertexai_mistral_ocr`:使用部署在 Google Cloud Vertex AI 上的 Mistral OCR 模型,通过 `GOOGLE_SERVICE_KEY_FILE` 进行身份验证。
- `document_parser`：使用本地文本提取功能处理 PDF、DOCX、XLS/XLSX 和 OpenDocument 文件。无需外部 API。当未配置 `ocr` 时，它也会自动为智能体（agent）文件上传运行，并作为已配置 OCR 策略失败时的回退方案。
- `custom_ocr`：保留用于在 `baseURL` 处配置的自定义 OCR 服务。目前尚未实现。
