Cette page décrit les paramètres de configuration partagés pour tous les endpoint. Les paramètres mis en évidence ici sont disponibles pour toutes les configurations sous le champ ["Endpoints"](/docs/configuration/librechat_yaml/object_structure/config#endpoints), sauf indication contraire.

## Exemple de configuration [#example-configuration]

```yaml filename="Shared Endpoint Settings"
endpoints:
  # Individual endpoint configurations
  openAI:
    streamRate: 25
    titleModel: 'gpt-4o-mini'
    titleMethod: 'completion'
    titleTiming: 'immediate'
    titlePrompt: "Create a concise title for this conversation:\n\n{convo}"
    headers:
      X-Gateway-Metadata: '{"user_email":"{{LIBRECHAT_USER_EMAIL}}"}'

  azureOpenAI:
    streamRate: 35
    titleModel: 'grok-3'
    titleMethod: 'structured'
    titlePrompt: |
      Analyze this conversation and provide:
      1. A concise title in the detected language (5 words or less, no punctuation or quotation)
      2. Always provide a relevant emoji at the start of the title

      {convo}
    titleConvo: true

  anthropic:
    streamRate: 25
    titleModel: 'claude-3-5-haiku-20241022'
    titleMethod: 'completion'
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'

  bedrock:
    streamRate: 25
    titleModel: 'us.amazon.nova-lite-v1:0'
    titleEndpoint: 'anthropic'

  google:
    streamRate: 25
    titleModel: 'gemini-2.0-flash-lite'
    titlePromptTemplate: "Human: {input}\nAssistant: {output}"
    headers:
      X-Gateway-Metadata: '{"user_id":"{{LIBRECHAT_USER_ID}}"}'

  assistants:
    streamRate: 30

  azureAssistants:
    streamRate: 30

  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5

  # Global configuration using 'all' - this applies shared settings across endpoints.
  # Most defined values override endpoint defaults; headers are merged and endpoint values win on collisions.
  all:
    headers:
      X-App: 'librechat'
    titleConvo: true
    titleModel: 'gpt-4.1-nano'
    titleTiming: 'immediate'
    titlePrompt: |
      Analyze this conversation and provide:
      1. The detected language of the conversation
      2. A concise title in the detected language (5 words or less, no punctuation or quotation)
      3. Always provide a relevant emoji at the start of the title
      {convo}
```

> **Important :** Lorsque vous utilisez la configuration `all`, la plupart des propriétés partagées que vous définissez s'appliquent à tous les endpoint. Dans l'exemple ci-dessus, la configuration `all` appliquerait `titleConvo`, `titleModel` et `titlePrompt` à tous les endpoint, tandis que les paramètres individuels de `streamRate` seraient préservés puisqu'ils ne sont pas définis dans `all`. Les `headers` sont fusionnés séparément : les valeurs provenant de `endpoints.all.headers` s'appliquent globalement, et les headers au niveau de l'endpoint prévalent en cas de conflit de clés. Les paramètres d'activité sont résolus champ par champ dans le même ordre, de sorte qu'un paramètre `all` sans rapport ne masque pas la configuration d'activité d'un endpoint.

## streamRate

**Clé :**

<OptionTable
  options={[
    [
      'streamRate',
      'Number',
      'La vitesse à laquelle les données sont diffusées depuis l\'endpoint. Utile pour contrôler le rythme de diffusion des données.',
      'streamRate: 25',
    ],
  ]}
/>

**Par défaut :** Dépend du fournisseur. Les flux OpenAI, les endpoints personnalisés, Anthropic, Google, Bedrock et ceux pris en charge par le SDK Agents utilisent un lissage adaptatif avec une cible de 25 ms. Les gestionnaires des Assistants hérités et d'Ollama conservent leur comportement par fragment (chunk) spécifique au fournisseur, avec une valeur par défaut de 1 ms.

Le lissage adaptatif émet le premier jeton de texte sans délai, augmente la taille des segments lorsqu'un flux prend du retard et préserve l'ordre des appels d'outils et des métadonnées. Définissez `streamRate` sur une cible en millisecondes non négative ; `streamRate: 0` désactive le lissage adaptatif sur les fournisseurs pris en charge par le SDK listés ci-dessus.

Une valeur spécifique à un endpoint est préservée lorsque `endpoints.all` existe sans `streamRate`. Définir `endpoints.all.streamRate` remplace les valeurs des endpoints, y compris un `0` explicite.

## titleConvo

**Clé :**

<OptionTable
  options={[
    [
      'titleConvo',
      'Boolean',
      'Contrôle la génération automatique du titre de conversation pour cet endpoint. Définissez sur false pour la désactiver.',
      'titleConvo: true',
    ],
  ]}
/>

**Par défaut :** Les titres sont générés automatiquement, sauf si cette option est définie sur `false`.

**Notes :**

- Les titres utilisent les paramètres de titre configurés. Lorsque `titleModel` est omis, le modèle de la conversation est utilisé.
- La génération de titres est également désactivée globalement lorsque la variable d'environnement `TITLE_CONVO` est désactivée.

**Exemple :**

```yaml filename="titleConvo"
titleConvo: true
```

## titleTiming

**Clé :**

<OptionTable
  options={[
    [
      'titleTiming',
      'String',
      'Contrôle le moment où les titres des conversations sont générés. Valeurs valides : "immediate" ou "final".',
      'titleTiming: "immediate"',
    ],
  ]}
/>

**Par défaut :** `"immediate"`

**Valeurs disponibles :**

- **`"immediate"`** - Génère le titre dès que la requête commence, en parallèle de la réponse du modèle, en utilisant le premier message de l'utilisateur. Les titres apparaissent généralement en une ou deux secondes.
- **`"final"`** - Diffère la génération du titre jusqu'à ce que la réponse complète soit terminée. Cela préserve le comportement hérité.

**Exemple :**

```yaml filename="titleTiming"
endpoints:
  all:
    titleTiming: 'immediate'
```

## titleMethod

**Clé :**

<OptionTable
  options={[
    [
      'titleMethod',

**Par défaut :** `"completion"`

```yaml filename="titleMethod"
titleMethod: 'completion'
```

## Groupes d'activité des agents [#agent-activity-groups]

Les groupes d'activité facilitent la lecture des exécutions longues d'Agents en réduisant chaque bloc contigu de raisonnement et d'appels d'outils sous un en-tête généré sur une seule ligne. La génération de l'en-tête s'exécute en dehors du chemin principal de réponse du modèle, mais il s'agit toujours d'un appel au modèle dont l'utilisation est enregistrée et facturée.

Avec les étiquettes de phase parent activées, le texte de progression court reste à l'intérieur de la phase active. Une phase se ferme avant le texte de réponse substantiel afin que le résultat reste en dehors du résumé réduit, et un bloc ultérieur de raisonnement ou d'appels d'outils peut commencer une autre phase dans la même exécution. LibreChat réinitialise également les limites de phase enregistrées lorsque le contenu mal formé ou omis est compacté, préservant ainsi leur alignement après le rechargement.

```yaml filename="endpoints / agents / activity groups"
endpoints:
  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5
```

Vous pouvez également définir ces champs sous `endpoints.all` ou un fournisseur de support/point de terminaison personnalisé. Les valeurs sont résolues indépendamment, la première valeur définie l'emportant dans cet ordre : `endpoints.all`, le point de terminaison public `agents`, puis le fournisseur de support ou le point de terminaison personnalisé. Si `activityEndpoint` est inconnu, LibreChat enregistre un avertissement et utilise le fournisseur de l'Agent à la place.

Les résumés de phase parent sont indépendants des étiquettes d'activité enfant : `activityPhaseLabel` peut être activé avec ou sans `activityLabel`. LibreChat n'utilise un appel de modèle de résumé de phase que pour une phase contenant au moins deux activités logiques. `activityCharLimit` limite également les preuves utilisées pour les résumés de phase. La sélection du modèle de phase se résout via `activityPhaseModel`, `activityModel`, le `titleModel` du endpoint d'origine, puis le modèle d'exécution actuel ; la sélection du endpoint de phase se résout via `activityPhaseEndpoint`, `activityEndpoint`, puis le fournisseur de l'Agent. Un endpoint de phase configuré inconnu enregistre un avertissement et revient au fournisseur de l'Agent.

## Étiquettes de raisonnement en direct [#live-reasoning-labels]

Les étiquettes de raisonnement en direct remplacent l'en-tête générique **Thinking** ou **Thoughts** par une orientation courte et évolutive pour le raisonnement de l'Agent de niveau supérieur suffisamment long. LibreChat met à jour l'en-tête de raisonnement existant sur place et n'ajoute ni ne déplace les parties de contenu du message. Le raisonnement des sous-agents imbriqués n'est pas étiqueté par ce paramètre.

```yaml filename="endpoints / agents / live reasoning labels"
    reasoningLabelMaxPerRun: 8
```

Vous pouvez définir ces champs sous `endpoints.all`, le point de terminaison public `agents`, ou un fournisseur sous-jacent/point de terminaison personnalisé. Chaque champ est résolu indépendamment, la première valeur définie l'emportant dans cet ordre : `endpoints.all`, `endpoints.agents`, puis le fournisseur sous-jacent ou le point de terminaison personnalisé.

La sélection du modèle se résout via `reasoningLabelModel`, `activityModel`, le `titleModel` du endpoint d'origine, puis le modèle d'exécution actuel de l'Agent. La sélection du endpoint se résout via `reasoningLabelEndpoint`, `activityEndpoint`, puis le fournisseur de l'Agent. Un endpoint d'étiquette inconnu enregistre un avertissement et revient au fournisseur de l'Agent.

Chaque appel envoie au maximum 4 000 caractères de raisonnement visible au point de terminaison (endpoint) de libellé résolu, qui peut être un fournisseur différent de celui de l'Agent. Les libellés sont limités à 120 caractères. Les révisions en streaming respectent à la fois les seuils de caractères et d'intervalle ; à la fin, une fin significative d'au moins 120 nouveaux caractères peut déclencher une réécriture finale immédiate. Chaque tentative de révision compte pour `reasoningLabelMaxPerRun` et constitue un appel de modèle distinct avec sa propre utilisation de jetons et son propre coût.

Lorsque le suivi Langfuse est activé, l'instantané du raisonnement limité est enregistré comme entrée de la génération d'étiquettes, à moins que la politique de rédaction active ne supprime l'appel d'étiquette. Vérifiez l'endpoint de destination et la politique de suivi avant d'activer cette fonctionnalité pour du contenu de raisonnement sensible.

## headers

**Clé :**

<OptionTable
  options={[
    [
      'headers',
      'Object/Dictionary',
      'En-têtes de requête personnalisés transmis aux endpoints des fournisseurs intégrés pris en charge.',
      'Useful for AI gateways and reverse proxies that consume metadata headers while LibreChat keeps provider-native request formatting.',
    ],
  ]}
/>

**Points de terminaison pris en charge :** `openAI`, `anthropic`, `google` et `all`.

**Exemple :**

```yaml filename="endpoints / headers"
endpoints:
  all:
    headers:
      X-App: 'librechat'
  anthropic:
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
```

**Notes :**

- Les valeurs prennent en charge `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}` et les espaces réservés du corps de la requête tels que `{{LIBRECHAT_BODY_CONVERSATIONID}}`.
- Les requêtes de modèle d'Agent prennent également en charge `{{LIBRECHAT_USER_TENANT_ID}}` et `{{LIBRECHAT_USER_TENANTID}}`. Les deux sont résolus à partir du locataire (tenant) faisant autorité au niveau de la requête pour les Agents racines, les sous-agents, les étiquettes d'activité, la mémoire et les appels de résumé, et deviennent une chaîne vide lorsque l'exécution n'a pas de locataire. Cette valeur de locataire est intentionnellement limitée aux en-têtes de modèle et n'est pas ajoutée aux consommateurs de variables de remplacement utilisateur généraux.
- À l'étape finale de résolution sortante, les espaces réservés reconnus pour l'utilisateur, le corps de la requête (request-body) et OpenID sans valeur deviennent des chaînes vides au lieu d'être transmis sous forme de texte de modèle. Les noms d'espaces réservés inconnus restent inchangés afin que les erreurs de frappe dans la configuration soient visibles.
- Les en-têtes au niveau de l'endpoint remplacent `endpoints.all.headers` en cas de collision de clés.
- L'authentification gérée par le fournisseur et les en-têtes bêta/protocole requis restent faisant autorité. Les valeurs bêta d'Anthropic sont fusionnées afin que les indicateurs bêta personnalisés n'écrasent pas les indicateurs requis par le fournisseur.
- Les en-têtes sont également transmis pour les requêtes de liste de modèles des fournisseurs pris en charge.
- Utilisez des en-têtes de métadonnées derrière une passerelle ou un proxy inverse qui les consomme. Les API des fournisseurs natifs ignorent généralement les en-têtes inconnus.

---

**Notes :**

- Tous les paramètres affichés sur cette page peuvent être configurés individuellement par endpoint ou globalement en utilisant la clé `all`
- Lors de l'utilisation de la configuration `all`, celle-ci remplacera les paramètres correspondants dans TOUS les endpoint individuels.
- La clé `all` n'accepte pas `baseURL`
- Le endpoint `azureOpenAI` n'accepte qu'un sous-ensemble de ces paramètres. Il n'accepte pas `titleEndpoint`, `headers` ni `maxToolResultChars`. Voir [Azure OpenAI](/docs/configuration/librechat_yaml/object_structure/azure_openai).
- Les paramètres non définis dans `all` conserveront leurs valeurs de endpoint individuelles
- Pour `streamRate` : Des valeurs comprises entre 25 et 40 sont recommandées lorsqu'un lissage spécifique à l'endpoint est souhaité.
- L'utilisation d'un taux de streaming plus élevé est indispensable lors de la mise à disposition de l'application à de nombreux utilisateurs à grande échelle.

**Exemple de comportement de remplacement :**

```yaml
endpoints:
  openAI:
    streamRate: 25 # This will be preserved
    titleModel: 'gpt-4' # This will be overridden
    titleConvo: false # This will be overridden

  all:
    titleConvo: true
    titleModel: 'gpt-3.5-turbo'
    # streamRate not defined here, so individual values are kept
```
