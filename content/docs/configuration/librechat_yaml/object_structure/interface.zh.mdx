## 概述 [#overview]

`interface` 对象允许对应用程序内的各种用户界面元素进行自定义，包括菜单、面板和链接等组件的可见性和行为设置。本节详细介绍了 `interface` 对象的结构。

这些是 `interface` 下的字段：

- `theme`
- `mcpServers`
- `privacyPolicy`
- `termsOfService`
- `modelSelect`
- `agentSelectorLimit`
- `parameters`
- `contextUsage`
- `contextCost`
- `currency`
- `presets`
- `prompts`
- `bookmarks`
- `memories`
- `multiConvo`
- `agents`
- `remoteAgents`
- `skills`
- `sharedLinks`
- `schedules`
- `temporaryChat`
- `temporaryChatRetention`
- `generalChatRetention`
- `retentionMode`
- `retainAgentFiles`
- `autoSubmitFromUrl`
- `customWelcome`
- `codeHighlightThrottleMs`
- `artifactUndocking`
- `runCode`
- `webSearch`
- `fileSearch`
- `fileCitations`
- `feedback`
- `replyNotifications`
- `defaultPinnedTools`
- `composerRecentFiles`
- `steerArmConfirmationTimeoutMs`
- `queuedTurnReconciliationTimeoutMs`
- `queuedSendLockTimeoutMs`
- `peoplePicker`
- `marketplace`

**注意：**

- `interface` 配置在应用程序中全局应用。
- 大多数设置都提供了默认值，但可以根据特定需求或条件进行覆盖。
- 应用程序中的条件逻辑可以根据 Model Specs 等其他配置进一步修改这些设置。

<Callout type="warning" title="已弃用：权限副作用字段">
以下几个字段（`mcpServers`、`prompts`、`bookmarks`、`memories`、`multiConvo`、`agents`、`remoteAgents`、`skills`、`sharedLinks`、`schedules`、`temporaryChat`、`runCode`、`webSearch`、`fileSearch`、`fileCitations`、`peoplePicker`、`marketplace`）不仅用于切换 UI，它们还在启动时将角色权限植入数据库，且仅针对内置的 `USER` 角色生效。

对于日常管理，请使用 [**LibreChat Admin Panel**](/docs/features/admin_panel)，它可直接编辑每个角色（包括自定义角色）的权限矩阵。这些 YAML 字段仍然支持用于引导全新的实例或完全由文件驱动的部署，但不应再作为管理功能权限的主要方式。

请参阅 [Access Control](/docs/features/access_control) 以了解完整的权限模型。

</Callout>

## theme

设置应用于所有用户的部署主题，包括浅色和深色模式。可以是内置主题的名称（`librechat` 或 `clickhouse`），也可以是包含自定义颜色、圆角、字体、阴影和动画的内联主题定义。

它的优先级高于 `REACT_APP_THEME_*` 构建时颜色和用户保存的主题，会受高对比度模式的影响，且永远不会保存到用户的浏览器中。移除它将恢复每个用户各自保存的主题，或者在客户端构建时包含 `REACT_APP_THEME_*` 颜色时恢复这些颜色。

**密钥：**

<OptionTable
  options={[
    [
      'theme',
      'String or Object',
      '一个捆绑的主题名称，或包含 `version`、`name`、`modes` 和 `brands` 的内联主题定义。',
      'theme: clickhouse',
    ],
  ]}
/>

**默认：** _无（LibreChat 的默认主题，或用户自定义的主题）_

**示例：**

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

请参阅 [Theme](/docs/configuration/librechat_yaml/object_structure/theme) 以了解内联定义格式、每个外观键及其默认值、ClickHouse 参考主题以及共享链接如何选择其主题。

### 策略链接出现的位置 [#where-the-policy-links-appear]

在登录和注册页面上，已发布的政策会以同意声明的形式显示：“继续即表示您同意《服务条款》并确认《隐私政策》。”如果仅发布了一项政策，则该句子仅提及该项政策。在注册页面上，它位于提交按钮下方；在登录页面上，它位于登录选项下方。

在聊天界面中，政策链接显示在新建聊天欢迎屏幕的消息框下方，一旦对话开始，这些链接就会被隐藏。

如果策略的 `externalUrl` 为空或空白，则该策略被视为未发布，且永远不会显示。当 `termsOfService.modalAcceptance` 为 `true` 时，身份验证屏幕会显示纯文本策略链接，而不是同意语句，因为用户在登录后会在对话框中明确接受条款。

## prompts

> **已弃用，建议使用权限管理。** 仅在启动时为默认的 `USER` 角色植入 `PROMPTS` 角色权限。建议优先使用 [Admin Panel](/docs/features/admin_panel) 来管理各角色/组/用户的提示词权限。

**密钥：**

<OptionTable
  options={[
    [
      'prompts',
      'Boolean or Object',
      '控制所有用户的提示词相关功能。可以是用于简单启用/禁用的布尔值，也可以是用于精细控制使用、创建、共享和公开可见性的对象。',
      'When set to `false`, users will not have access to create, edit, or use custom prompts.',
    ],
  ]}
/>

**默认值：** `true`

**重要：布尔值与对象配置的区别**

- **布尔值 (`prompts: true`)**：仅更新 `use` 权限。现有的 `create`、`share` 和 `public` 权限值将从数据库中**保留**。将其用作简单的功能开关，而不会影响通过管理面板配置的其他设置。

- **Object**: 仅更新明确指定的子权限。配置中未包含的任何权限都将从数据库中保留。

## fileCitations

控制文件引用功能的全局可用性。禁用时，它实际上会移除所有用户的 `FILE_CITATIONS` 权限，从而防止在使用文件搜索时显示任何文件引用，无论个人用户权限如何。

> **已弃用，建议使用权限管理。** 在启动时为 `FILE_CITATIONS` 角色权限设置种子/全局门控。建议优先使用 [Admin Panel](/docs/features/admin_panel) 来管理针对角色/组/用户的引用权限。

**注意：**

- 此设置充当系统范围内 `FILE_CITATIONS` 权限的全局开关。
- 当设置为 `false` 时，即使已通过角色授予权限，所有用户也都将无法看到文件引用。
- 文件引用功能需要启用 `fileSearch` 特性。
- 当使用具有文件搜索功能的 Agent 时，可以通过 [Agents endpoint configuration](/docs/configuration/librechat_yaml/object_structure/agents#file-citation-configuration-examples) 来配置引用行为（数量和质量）。

**密钥：**

    ],
  ]}
/>

**默认值：** `true`

**示例：**

## feedback

控制是否在回复下方显示点赞/点踩按钮。当设置为 `false` 时，这些按钮将从消息操作栏中移除，且服务器会拒绝反馈写入，因此隐藏该控件的部署也将不会存储任何评分。

**注意：**

- 其他消息操作（朗读、复制、编辑、分支和重新生成）不受影响，操作栏会自动重排，不会留下空隙。
- 当禁用反馈功能时，`PUT /api/messages/:conversationId/:messageId/feedback` 会在写入数据库或导出之前返回 `403` 和 `{"error": "Feedback is disabled"}`。
- 在启用该功能期间收集的评分将保留在现有消息中。该标志仅停止新的写入操作，不会删除已存储的反馈。
- 当配置了 Langfuse 追踪时，评分才会在 LibreChat 之外被使用，此时每个评分都会作为 `user-feedback` 分数发送。请参阅 [Message Feedback Scores](/docs/configuration/langfuse#message-feedback-scores)。
- 这是一个纯粹的界面标志，而非角色权限，因此在 [Admin Panel](/docs/features/admin_panel) 中无需针对每个角色进行授权。

**密钥：**

<OptionTable
  options={[
    [
      'feedback',
      'Boolean',
      '显示或隐藏回复上的点赞/点踩反馈按钮。',
      'When disabled, the buttons are removed for every user and the feedback endpoint rejects writes with a 403.',
    ],
  ]}
/>

**默认值：** `true`

**示例：**

```yaml filename="interface / feedback"
interface:
  feedback: false
```
