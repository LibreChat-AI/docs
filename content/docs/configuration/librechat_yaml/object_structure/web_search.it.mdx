La configurazione `webSearch` ti consente di personalizzare la funzionalità di ricerca web all'interno di LibreChat, inclusi i provider di ricerca, gli scraper di contenuti e i reranker dei risultati.

## Panoramica [#overview]

La funzionalità di ricerca web è composta da tre componenti principali:

1. **Search Providers**: Servizi che eseguono la ricerca web iniziale
2. **Scrapers**: Servizi che estraggono contenuti dalle pagine web
3. **Rerankers**: Servizi che riordinano i risultati di ricerca per una migliore pertinenza

## Esempio [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## Protezione SSRF e Provider Privati [#ssrf-protection-and-private-providers]

LibreChat convalida ogni connessione che apre per la ricerca web, lo scraping e il reranking. Le destinazioni private, loopback, link-local e cloud-metadata sono bloccate per impostazione predefinita, inclusi i redirect hop e i nomi host che si risolvono in un indirizzo privato al momento della connessione.

Utilizza `webSearch.allowedAddresses` quando un endpoint configurato per SearXNG, Firecrawl, Jina, compatibile con Tavily, compatibile con Keenable o un provider correlato è deliberatamente privato:

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

Questo campo è un elenco di esenzione SSRF, non una whitelist rigorosa. Le destinazioni pubbliche rimangono disponibili. Le voci devono essere coppie esatte `host:port`, `private.ip:port` o `[ipv6]:port`; URL, percorsi, intervalli CIDR, host/IP semplici e letterali IP pubblici vengono rifiutati. Un hostname esentato si fida di qualsiasi IP privato a cui si risolve su quella porta, quindi preferisci un letterale IP privato ed elenca solo i nomi di cui controlli il DNS.

LibreChat esenta automaticamente un endpoint forward-proxy HTTP(S) configurato in modo che possa essere raggiunto. Quando il proxy gestisce una richiesta, risolve la destinazione e deve applicare autonomamente l'egress verso la destinazione. `NO_PROXY` può rendere una richiesta diretta, dove la protezione della connessione di LibreChat rimane applicabile. La protezione copre le connessioni che LibreChat apre verso le API dei provider; non può limitare un URL di pagina che uno scraper di terze parti riceve come dati di richiesta e recupera sulla propria infrastruttura.

## Proprietà delle credenziali [#credential-ownership]

Un URL Firecrawl, SearXNG o Jina fornito dall'utente non deve ricevere una chiave API di proprietà del server. La convalida SSRF non rende sicuro un endpoint pubblico selezionato dall'utente per ricevere le credenziali della distribuzione. Configura l'URL e la chiave insieme come impostazioni di proprietà dell'amministratore, oppure lascia che l'utente fornisca la propria coppia; SearXNG può anche essere eseguito senza una chiave.

Se un URL salvato dall'utente verrebbe altrimenti abbinato alla chiave del server, LibreChat ignora l'URL opzionale di Firecrawl e utilizza il suo endpoint predefinito. L'URL dell'istanza di SearXNG è obbligatorio, pertanto la configurazione a proprietà mista non viene autenticata e lo strumento di ricerca non viene inizializzato. Per un deployment self-hosted che utilizza la chiave del server, configura `FIRECRAWL_API_URL` o `SEARXNG_INSTANCE_URL` insieme a tale chiave invece di fare affidamento sull'URL salvato dall'utente. Gli endpoint privati richiedono comunque [`allowedAddresses`](#ssrf-protection-and-private-providers).

#### Scelta dei motori [#choosing-engines]

I nomi dei motori devono corrispondere a quelli abilitati sulla tua istanza, e da ciò conseguono due cose:

- SearXNG ignora un motore che non riconosce invece di segnalare un errore. Un errore di battitura, o un motore disabilitato sulla tua istanza, si traduce in un minor numero di risultati anziché in un fallimento.
- I nomi validi sono specifici dell'istanza. Controlla l'elenco abilitato su `https://your-instance/config`, che restituisce un JSON contenente ogni motore abilitato, oppure apri la scheda **Engines** nella pagina delle preferenze della tua istanza.

L'impostazione predefinita è `google,bing,duckduckgo`. SearXNG aggrega tutto ciò che i motori selezionati restituiscono, quindi un motore bloccato ti costa solo la sua quota di risultati anziché l'intera risposta, e una ricerca restituisce un risultato vuoto solo quando ogni motore selezionato fallisce o non restituisce nulla.

DuckDuckGo è il motore di ricerca nel set predefinito che più probabilmente verrà bloccato, poiché presenta CAPTCHA alla maggior parte delle istanze self-hosted. Con soli tre motori nel set, perderlo contemporaneamente a un Google o Bing con limitazioni di frequenza è un modo comune per ritrovarsi senza alcun risultato. Impostare `engines` in modo esplicito, escludendo DuckDuckGo ed elencando più di tre motori, riduce tale rischio.

I motori che rispondono rapidamente e tollerano il traffico self-hosted costituiscono il miglior set iniziale, ad esempio:

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

Aggiungere più motori amplia la copertura ma rallenta anche ogni ricerca, poiché SearXNG attende il motore più lento del set prima di rispondere. Tieni a mente il `timeout` quando espandi l'elenco.

#### Cosa non controllano queste opzioni [#what-these-options-do-not-control]

- **Safe search** non fa parte di questo blocco. Proviene dalla chiave di primo livello [`safeSearch`](#safesearch) e viene inoltrato a SearXNG come `safesearch`.
- Le **categorie dei risultati** vengono scelte per ogni query da LibreChat, che associa il tipo di ricerca a `general`, `images`, `videos` o `news`. Non possono essere sovrascritte qui.
- Il **numero di pagina e il formato dei risultati** sono fissi. LibreChat richiede sempre la pagina 1 in formato JSON, motivo per cui la tua istanza deve avere `json` abilitato sotto `formats`.

## Note [#notes]

- Le API keys possono essere configurate in due modi:
  1. Imposta le variabili d'ambiente specificate nella configurazione YAML
  2. Se le variabili d'ambiente non sono impostate, agli utenti verrà richiesto di fornire le API key tramite l'interfaccia utente.
- La configurazione supporta molteplici servizi per ogni componente (providers, scrapers, rerankers)
- Se non viene specificato un tipo di servizio particolare, il sistema proverà tutti i servizi disponibili in quella categoria
- Safe search fornisce tre livelli di filtro dei contenuti: OFF (0), MODERATE (1) e STRICT (2)
- Tavily non eredita l'impostazione globale di ricerca sicura per impostazione predefinita; imposta `tavilySearchOptions.safeSearch` esplicitamente solo quando il tuo account Tavily supporta `safe_search`
- Keenable supporta la ricerca senza chiavi e il recupero delle pagine; la sua chiave opzionale aumenta i limiti di velocità pubblici e il suo override dell'URL di recupero è solo per l'ambiente.
- Il comportamento delle query di SearXNG (motori, lingua, intervallo temporale, timeout della richiesta) viene configurato in `searxngSearchOptions`; vedi [Choosing engines](#choosing-engines) se le ricerche non restituiscono risultati.
- Non inserire mai chiavi API reali nella configurazione YAML: utilizza solo i nomi delle variabili d'ambiente

## Configurazione di SearXNG [#setting-up-searxng]

SearXNG è un meta-motore di ricerca incentrato sulla privacy che puoi ospitare autonomamente. 
Per ulteriori informazioni, consulta la [documentazione ufficiale di SearXNG](https://docs.searxng.org/).

Ecco i passaggi per configurare la tua istanza SearXNG da utilizzare con LibreChat:

### Utilizzo di Docker Desktop [#using-docker-desktop]

1. **Cerca l'immagine ufficiale di SearXNG**
   - Apri Docker Desktop
   - Cerca `searxng/searxng` nella scheda **Images**
   - Fai clic su **Run** sull'immagine ufficiale per scaricare ed eseguire automaticamente un container dell'immagine

2. **Esecuzione del container**
   - Espandi il menu a tendina **Optional Settings** nel pannello successivo che appare una volta completato il download.
   - Imposta i dettagli di configurazione desiderati (numero di porta, nome del container, ecc.)
   - Fai clic su **Run** per avviare il container

3. **Configurare SearXNG per LibreChat**
   - Vai alla scheda `Files` in Docker Desktop
   - Vai a `/etc/searxng/settings.yaml`
   - Apri l'editor di file
   - Passa alla sezione `formats`
   - Aggiungi `json` come formato accettabile in modo che LibreChat possa comunicare con la tua istanza
   - Salva il file

4. **Riavvia il container**
   - Riavvia il container affinché le modifiche abbiano effetto

#### Configurazione YAML [#yaml-configuration]

Per configurare SearXNG per tutti gli utenti dell'istanza invece che per singolo utente, imposta gli stessi valori in `librechat.yaml`:

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

L'URL e la chiave vengono ancora letti dall'ambiente, quindi abbina la configurazione di cui sopra con:

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Le istanze private necessitano di una voce allowedAddresses">
`localhost:55011` è un indirizzo di loopback, che la [protezione SSRF](#ssrf-protection-and-private-providers) di LibreChat blocca al momento della connessione. Senza la voce `allowedAddresses` corrispondente, la ricerca fallisce anche quando SearXNG è integro. La voce deve essere l'esatta coppia `host:port` proveniente dall'URL della tua istanza.

Quando LibreChat stesso viene eseguito in Docker, `localhost` è il container di LibreChat, non quello di SearXNG. Utilizza un hostname che il container possa raggiungere, come il nome del servizio compose, ed esenta quello invece:

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

Vedi [`searxngSearchOptions`](#searxngsearchoptions) per ogni sottochiave accettata da questo blocco.

#### Risoluzione dei problemi relativi ai risultati vuoti [#troubleshooting-empty-results]

Una ricerca SearXNG che non restituisce alcun risultato è quasi sempre dovuta al fatto che la richiesta non raggiunge un'istanza funzionante, piuttosto che a LibreChat che scarta i risultati. Segui questi passaggi in ordine:

1. **L'istanza è un indirizzo privato senza alcuna voce `allowedAddresses`.** LibreChat blocca le destinazioni loopback e private al momento della connessione, pertanto un'istanza self-hosted deve avere il suo `host:port` esatto elencato sotto [`allowedAddresses`](#ssrf-protection-and-private-providers). Questo blocca la richiesta direttamente invece di restituire un set di risultati vuoto.
2. **`json` manca da `formats`.** LibreChat richiede i risultati in formato JSON. Se la sezione `formats` del file delle impostazioni della tua istanza non elenca `json`, l'istanza risponderà con una pagina di errore e ogni ricerca restituirà un risultato vuoto. Questo è il passaggio 3 della configurazione Docker sopra indicata.
3. **Ogni motore selezionato ha fallito.** SearXNG unisce i motori che hanno risposto, quindi una risposta vuota significa che nessuno di essi ha restituito nulla. DuckDuckGo è nel set predefinito (`google,bing,duckduckgo`) e presenta CAPTCHA alla maggior parte delle istanze self-hosted, il che lascia solo due motori a gestire la ricerca. Imposta `searxngSearchOptions.engines` esplicitamente, escludi DuckDuckGo ed elenca qualche altro motore.
4. **Un nome di motore non esiste sulla tua istanza.** SearXNG ignora silenziosamente i motori che non riconosce, quindi un errore di battitura significa semplicemente meno risultati. Confronta il tuo elenco con `https://your-instance/config`.
5. **L'istanza è più lenta del timeout.** Aumenta `searxngSearchOptions.timeout` oltre il valore predefinito `10000` se la tua istanza interroga molti motori o si trova dietro un percorso di rete lento.

Puoi riprodurre ciò che LibreChat invia chiamando direttamente l'istanza:

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

Questo viene eseguito dalla tua macchina, quindi aggira completamente il connection guard di LibreChat. Un array `results` vuoto qui conferma che il problema è lato SearXNG; se invece ottieni dei risultati qui mentre LibreChat continua a non trovarne, il problema è riconducibile a `allowedAddresses`.
