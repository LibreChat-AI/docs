## Übersicht [#overview]

Das `speech`-Objekt ermöglicht es Ihnen, Text-to-Speech (TTS)- und Speech-to-Text (STT)-Anbieter direkt in Ihrer `librechat.yaml`-Konfigurationsdatei zu konfigurieren. Dies ermöglicht serverseitige Sprachdienste, ohne dass Benutzer ihre eigenen API-Schlüssel konfigurieren müssen.

**Felder unter `speech`:**

- `tts` - Konfigurationen für Text-to-Speech-Anbieter
- `stt` – Konfigurationen für Speech-to-Text-Anbieter
- `speechTab` - Standard-UI-Einstellungen für Sprachfunktionen

**Hinweise:**

- Mehrere Anbieter können gleichzeitig konfiguriert werden
- Benutzer können ihren bevorzugten Anbieter aus den verfügbaren Optionen auswählen.
- API-Schlüssel in der Konfigurationsdatei sollten aus Sicherheitsgründen Umgebungsvariablen-Referenzen verwenden

## Beispiel [#example]

```yaml filename="speech"
speech:
  tts:
    allowedAddresses: ["tts.internal:8080"]
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["voice-id-1", "voice-id-2"]
  stt:
    allowedAddresses: ["stt.internal:8080"]
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText: true
    textToSpeech: true
```

## SSRF-Schutz [#ssrf-protection]

LibreChat schützt vom Betreiber bereitgestellte STT- und TTS-URLs zum Zeitpunkt der Verbindung. Private, Loopback-, Link-Local- und Cloud-Metadata-Ziele werden standardmäßig blockiert und Weiterleitungen für Sprachanfragen sind deaktiviert.

`speech.tts.allowedAddresses` und `speech.stt.allowedAddresses` sind separate Ausnahmelisten, keine strikten Positivlisten (Allowlists). Fügen Sie einen exakten privaten `host:port`, `private.ip:port` oder `[ipv6]:port` nur dann hinzu, wenn dieser Abschnitt einen vertrauenswürdigen selbst gehosteten Dienst erreichen muss. Verwenden Sie keine URL, keinen Pfad, keinen CIDR-Bereich, keinen reinen Host/IP oder eine öffentliche IP-Adresse. Standard-Ports werden normalisiert, daher wird eine HTTPS-URL ohne expliziten Port als Port `443` geprüft.

Ein ausgenommener Hostname vertraut jeder privaten Adresse, zu der er auf diesem Port aufgelöst wird. Bevorzugen Sie nach Möglichkeit ein privates IP-Literal und listen Sie nur Namen auf, deren DNS Sie kontrollieren und die nicht von einem Angreifer umgeleitet werden können.

Wenn ein Forward-Proxy eine Hostnamen-Anfrage weiterleitet, führt der Proxy die Ziel-DNS-Auflösung und den Egress durch, weshalb der Proxy seine eigene SSRF-Richtlinie durchsetzen muss. Ein buchstäbliches privates Ziel wird weiterhin vor der Proxy-Verarbeitung blockiert, es sei denn, seine genaue Adresse und sein Port sind ausgenommen.

## Hinweise [#notes]

- Verwenden Sie in Konfigurationsdateien immer Umgebungsvariablen-Referenzen (z. B. `${API_KEY}`) für API-Schlüssel.
- Es können mehrere TTS-Anbieter konfiguriert werden; Benutzer wählen ihre bevorzugte Option in der UI aus.
- Die `speechTab`-Einstellungen definieren Standardwerte, die Benutzer in ihren persönlichen Einstellungen überschreiben können.
- `browser` verwendet die integrierte Sprachunterstützung des Browsers; `external` verwendet die serverseitigen Anbieter, die unter `speech.stt` oder `speech.tts` konfiguriert sind.
- Bestehende `openai`- und `azureOpenAI`-STT-Standardeinstellungen sowie `openai`-, `azureOpenAI`-, `elevenlabs`- und `localai`-TTS-Standardeinstellungen werden zu `external` migriert; eine nicht verfügbare externe Engine greift auf `browser` zurück.
- Für eine detaillierte Funktionsdokumentation siehe [Speech to Text & Text to Speech](/docs/configuration/stt_tts)
