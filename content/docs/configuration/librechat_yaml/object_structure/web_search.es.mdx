La configuración `webSearch` le permite personalizar la funcionalidad de búsqueda web dentro de LibreChat, incluyendo proveedores de búsqueda, scrapers de contenido y rerankers de resultados.

## Descripción general [#overview]

La función de búsqueda web consta de tres componentes principales:

1. **Proveedores de búsqueda**: Servicios que realizan la búsqueda web inicial
2. **Scrapers**: Servicios que extraen contenido de páginas web
3. **Rerankers**: Servicios que reordenan los resultados de búsqueda para una mejor relevancia

## Ejemplo [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## Protección SSRF y Proveedores Privados [#ssrf-protection-and-private-providers]

LibreChat valida cada conexión que abre para la búsqueda web, el scraping y el reranking. Los destinos privados, de loopback, link-local y de metadatos en la nube están bloqueados de forma predeterminada, incluyendo los saltos de redirección y los nombres de host que se resuelven en una dirección privada en el momento de la conexión.

Utilice `webSearch.allowedAddresses` cuando un endpoint configurado de SearXNG, Firecrawl, Jina, compatible con Tavily, compatible con Keenable o un proveedor relacionado sea deliberadamente privado:

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

Este campo es una lista de exención de SSRF, no una lista de permitidos estricta. Los destinos públicos permanecen disponibles. Las entradas deben ser pares exactos de `host:port`, `private.ip:port` o `[ipv6]:port`; se rechazan las URL, rutas, rangos CIDR, hosts/IPs sin puerto y literales de IP pública. Un nombre de host exento confía en cualquier IP privada a la que se resuelva en ese puerto, por lo que se prefiere un literal de IP privada y listar solo los nombres cuyo DNS usted controle.

LibreChat exime automáticamente un endpoint de proxy de reenvío HTTP(S) configurado para que pueda ser alcanzado. Cuando el proxy gestiona una solicitud, resuelve el destino y debe aplicar la salida (egress) de destino por sí mismo. `NO_PROXY` puede hacer que una solicitud sea directa, donde la protección de conexión de LibreChat aún se aplica. La protección cubre las conexiones que LibreChat abre hacia las API de los proveedores; no puede restringir una URL de página que un scraper de terceros reciba como datos de solicitud y obtenga en su propia infraestructura.

## Propiedad de las credenciales [#credential-ownership]

Una URL de Firecrawl, SearXNG o Jina proporcionada por el usuario no debe recibir una clave API propiedad del servidor. La validación SSRF no hace que un endpoint público seleccionado por el usuario sea seguro para recibir las credenciales del despliegue. Configure la URL y la clave juntas como ajustes propiedad del administrador, o permita que el usuario proporcione su propio par; SearXNG también puede ejecutarse sin una clave.

Si una URL de usuario guardada se emparejara de otro modo con la clave del servidor, LibreChat ignora la URL opcional de Firecrawl y utiliza su endpoint predeterminado. La URL de la instancia de SearXNG es obligatoria, por lo que esa configuración de propiedad mixta no se autentica y la herramienta de búsqueda no se inicializa. Para una implementación autohospedada que utilice la clave del servidor, configure `FIRECRAWL_API_URL` o `SEARXNG_INSTANCE_URL` junto con esa clave en lugar de depender de una URL guardada por el usuario. Los endpoints privados aún necesitan [`allowedAddresses`](#ssrf-protection-and-private-providers).

#### Elegir motores [#choosing-engines]

Los nombres de los motores deben coincidir con los motores que están habilitados en su propia instancia, y de esto se derivan dos cosas:

- SearXNG ignora un motor que no reconoce en lugar de informar un error. Un error tipográfico, o un motor que está deshabilitado en su instancia, se muestra como una menor cantidad de resultados en lugar de como un fallo.
- Los nombres válidos son específicos de cada instancia. Consulta la lista habilitada en `https://your-instance/config`, la cual devuelve un JSON que incluye cada motor habilitado, o abre la pestaña **Engines** de la página de preferencias de tu instancia.

El valor predeterminado es `google,bing,duckduckgo`. SearXNG agrega lo que devuelvan los motores seleccionados, por lo que un motor bloqueado solo le cuesta su parte de los resultados en lugar de la respuesta completa, y una búsqueda solo devuelve un resultado vacío cuando todos los motores seleccionados fallan o no devuelven nada.

DuckDuckGo es el motor de ese conjunto predeterminado con mayor probabilidad de ser bloqueado, ya que presenta CAPTCHAs a la mayoría de las instancias autohospedadas. Con solo tres motores en el conjunto, perderlo al mismo tiempo que Google o Bing debido a una limitación de tasa es una forma común de terminar sin resultados. Definir `engines` explícitamente, excluyendo a DuckDuckGo y enumerando más de tres motores, reduce ese riesgo.

Los motores que responden rápidamente y toleran el tráfico autohospedado constituyen el mejor conjunto inicial, por ejemplo:

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

Agregar más motores amplía la cobertura pero también ralentiza cada búsqueda, ya que SearXNG espera al motor más lento del conjunto antes de responder. Ten en cuenta el `timeout` cuando amplíes la lista.

#### Lo que estas opciones no controlan [#what-these-options-do-not-control]

- **Safe search** no forma parte de este bloque. Proviene de la clave de nivel superior [`safeSearch`](#safesearch) y se reenvía a SearXNG como `safesearch`.
- Las **Result categories** son elegidas por consulta por LibreChat, el cual asigna el tipo de búsqueda a `general`, `images`, `videos` o `news`. No pueden ser anuladas aquí.
- El **número de página y el formato de resultado** son fijos. LibreChat siempre solicita la página 1 en formato JSON, razón por la cual su instancia debe tener `json` habilitado en `formats`.

## Notas [#notes]

- Las API keys se pueden configurar de dos maneras:
  1. Establezca las variables de entorno especificadas en la configuración YAML
  2. Si las variables de entorno no están configuradas, se solicitará a los usuarios que proporcionen las claves de API a través de la interfaz de usuario.
- La configuración admite múltiples servicios para cada componente (providers, scrapers, rerankers)
- Si no se especifica un tipo de servicio concreto, el sistema probará todos los servicios disponibles en esa categoría.
- La búsqueda segura ofrece tres niveles de filtrado de contenido: OFF (0), MODERATE (1) y STRICT (2)
- Tavily no hereda la configuración global de búsqueda segura de forma predeterminada; establezca `tavilySearchOptions.safeSearch` explícitamente solo cuando su cuenta de Tavily sea compatible con `safe_search`
- Keenable admite búsqueda sin clave y obtención de páginas; su clave opcional aumenta los límites de tasa públicos, y su anulación de URL de obtención es solo para el entorno.
- El comportamiento de las consultas de SearXNG (motores, idioma, rango de tiempo, tiempo de espera de la solicitud) se configura en `searxngSearchOptions`; consulte [Choosing engines](#choosing-engines) si las búsquedas no devuelven resultados.
- Nunca coloque claves de API reales en la configuración YAML; utilice únicamente nombres de variables de entorno.

## Configuración de SearXNG [#setting-up-searxng]

SearXNG es un metabuscador centrado en la privacidad que puedes alojar por tu cuenta. 
Para más información, consulta la [documentación oficial de SearXNG](https://docs.searxng.org/).

Aquí tienes los pasos para configurar tu propia instancia de SearXNG para usarla con LibreChat:

### Uso de Docker Desktop [#using-docker-desktop]

1. **Busca la imagen oficial de SearXNG**
   - Abra Docker Desktop
   - Busque `searxng/searxng` en la pestaña **Images**
   - Haz clic en **Run** en la imagen oficial para descargar y ejecutar automáticamente un contenedor de la imagen.

2. **Ejecutando el contenedor**
   - Expanda el menú desplegable **Optional Settings** en el panel siguiente que aparece una vez que se completa la descarga.
   - Establezca los detalles de configuración deseados (número de puerto, nombre del contenedor, etc.)
   - Haz clic en **Run** para iniciar el contenedor

3. **Configurar SearXNG para LibreChat**
   - Navegue a la pestaña `Files` en Docker Desktop
   - Ve a `/etc/searxng/settings.yaml`
   - Abrir el editor de archivos
   - Navegue a la sección `formats`
   - Agregue `json` como formato aceptable para que LibreChat pueda comunicarse con su instancia
   - Guarda el archivo

4. **Reiniciar el contenedor**
   - Reinicie el contenedor para que los cambios surtan efecto

### Configuración de LibreChat para usar SearXNG [#configuring-librechat-to-use-searxng]

2. **Elija Configure en la fila Web Search en la sección Tools**

4. **Ingrese los detalles de su configuración (p. ej., URL de la instancia, tipo de scraper, etc.) y haga clic en guardar**
![Guardar configuración de búsqueda web](/images/web-search/web_search_save.png)

5. **Selecciona Web Search en la sección Tools de la paleta**

6. **Un chip de Web Search ahora aparece en el compositor, lo que significa que sus consultas ahora pueden utilizar la búsqueda web**

#### Configuración YAML [#yaml-configuration]

Para configurar SearXNG para todos en la instancia en lugar de por usuario, establezca los mismos valores en `librechat.yaml`:

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

La URL y la clave todavía se leen desde el entorno, así que combine la configuración anterior con:

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Las instancias privadas necesitan una entrada allowedAddresses">
`localhost:55011` es una dirección de loopback, la cual la [protección SSRF](#ssrf-protection-and-private-providers) de LibreChat bloquea al momento de la conexión. Sin la entrada `allowedAddresses` correspondiente, la búsqueda fallará incluso cuando SearXNG esté en buen estado. La entrada debe ser el par exacto `host:port` de la URL de su instancia.

Cuando LibreChat se ejecuta en Docker, `localhost` es el contenedor de LibreChat, no el de SearXNG. Utilice un nombre de host al que el contenedor pueda acceder, como el nombre del servicio de compose, y excluya ese en su lugar:

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

Consulta [`searxngSearchOptions`](#searxngsearchoptions) para ver todas las subclaves que acepta este bloque.

#### Solución de problemas de resultados vacíos [#troubleshooting-empty-results]

Una búsqueda en SearXNG que no devuelve resultados casi siempre se debe a que la solicitud nunca llega a una instancia funcional, en lugar de que LibreChat descarte los resultados. Siga estos pasos en orden:

1. **La instancia es una dirección privada sin ninguna entrada en `allowedAddresses`.** LibreChat bloquea los destinos de loopback y privados en el momento de la conexión, por lo que una instancia autohospedada necesita que su `host:port` exacto aparezca bajo [`allowedAddresses`](#ssrf-protection-and-private-providers). Esto bloquea la solicitud directamente en lugar de devolver un conjunto de resultados vacío.
2. **`json` falta en `formats`.** LibreChat solicita resultados en formato JSON. Si la sección `formats` de su archivo de configuración de instancia no incluye `json`, la instancia responderá con una página de error y cada búsqueda devolverá resultados vacíos. Este es el paso 3 de la configuración de Docker mencionada anteriormente.
3. **Todos los motores seleccionados fallaron.** SearXNG combina los motores que sí respondieron, por lo que una respuesta vacía significa que ninguno de ellos devolvió nada. DuckDuckGo está en el conjunto predeterminado (`google,bing,duckduckgo`) y sirve CAPTCHAs a la mayoría de las instancias autohospedadas, lo que deja solo dos motores para realizar la búsqueda. Configure `searxngSearchOptions.engines` explícitamente, excluya a DuckDuckGo y enumere algunos motores más.
4. **Un nombre de motor no existe en su instancia.** SearXNG omite silenciosamente los motores que no reconoce, por lo que un error tipográfico simplemente significa menos resultados. Compare su lista con `https://your-instance/config`.
5. **La instancia es más lenta que el tiempo de espera.** Aumente `searxngSearchOptions.timeout` por encima del valor predeterminado `10000` si su instancia consulta muchos motores o se encuentra detrás de una ruta de red lenta.

Puedes reproducir lo que LibreChat envía llamando a la instancia directamente:

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

Esto se ejecuta desde tu propia máquina, por lo que evita por completo el guardián de conexión de LibreChat. Un array `results` vacío aquí confirma que el problema está del lado de SearXNG; si obtienes resultados aquí mientras LibreChat sigue sin encontrar nada, el problema apunta a `allowedAddresses`.
