이 페이지는 모든 endpoint에 대한 공유 구성 설정을 설명합니다. 여기에 강조된 설정은 별도로 명시되지 않는 한 ["Endpoints"](/docs/configuration/librechat_yaml/object_structure/config#endpoints) 필드 아래의 모든 구성에서 사용할 수 있습니다.

## 예시 구성 [#example-configuration]

```yaml filename="Shared Endpoint Settings"
endpoints:
  # Individual endpoint configurations
  openAI:
    streamRate: 25
    titleModel: 'gpt-4o-mini'
    titleMethod: 'completion'
    titleTiming: 'immediate'
    titlePrompt: "Create a concise title for this conversation:\n\n{convo}"
    headers:
      X-Gateway-Metadata: '{"user_email":"{{LIBRECHAT_USER_EMAIL}}"}'

  azureOpenAI:
    streamRate: 35
    titleModel: 'grok-3'
    titleMethod: 'structured'
    titlePrompt: |
      Analyze this conversation and provide:
      1. A concise title in the detected language (5 words or less, no punctuation or quotation)
      2. Always provide a relevant emoji at the start of the title

      {convo}
    titleConvo: true

  anthropic:
    streamRate: 25
    titleModel: 'claude-3-5-haiku-20241022'
    titleMethod: 'completion'
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'

  bedrock:
    streamRate: 25
    titleModel: 'us.amazon.nova-lite-v1:0'
    titleEndpoint: 'anthropic'

  google:
    streamRate: 25
    titleModel: 'gemini-2.0-flash-lite'
    titlePromptTemplate: "Human: {input}\nAssistant: {output}"
    headers:
      X-Gateway-Metadata: '{"user_id":"{{LIBRECHAT_USER_ID}}"}'

  assistants:
    streamRate: 30

  azureAssistants:
    streamRate: 30

  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5

  # Global configuration using 'all' - this applies shared settings across endpoints.
  # Most defined values override endpoint defaults; headers are merged and endpoint values win on collisions.
  all:
    headers:
      X-App: 'librechat'
    titleConvo: true
    titleModel: 'gpt-4.1-nano'
    titleTiming: 'immediate'
    titlePrompt: |
      Analyze this conversation and provide:
      1. The detected language of the conversation
      2. A concise title in the detected language (5 words or less, no punctuation or quotation)
      3. Always provide a relevant emoji at the start of the title
      {convo}
```

> **중요:** `all` 구성을 사용할 때, 정의한 대부분의 공유 속성은 모든 endpoint에 적용됩니다. 위 예시에서 `all` 구성은 `titleConvo`, `titleModel`, `titlePrompt`를 모든 endpoint에 적용하는 반면, `streamRate`는 `all`에 정의되지 않았으므로 개별 설정이 유지됩니다. `headers`는 별도로 병합됩니다. `endpoints.all.headers`의 값은 전역적으로 적용되며, 키가 충돌할 경우 endpoint 수준의 헤더가 우선합니다. 활동(Activity) 설정은 동일한 순서로 필드별로 해결되므로, 관련 없는 `all` 설정이 endpoint의 활동 구성을 숨기지 않습니다.

## streamRate

**키:**

<OptionTable
  options={[
    [
      'streamRate',
      'Number',
      'endpoint에서 데이터가 스트리밍되는 속도입니다. 스트리밍 데이터의 속도를 제어하는 데 유용합니다.',
      'streamRate: 25',
    ],
  ]}
/>

**기본값:** 공급자(Provider)에 따라 다릅니다. OpenAI, 사용자 지정 endpoint, Anthropic, Google, Bedrock 및 Agents SDK 기반 스트림은 25ms를 목표로 하는 적응형 스무딩(adaptive smoothing)을 사용합니다. 레거시 Assistants 및 Ollama 핸들러는 공급자별 청크 동작을 유지하며, 기본값은 1ms입니다.

적응형 스무딩(Adaptive smoothing)은 첫 번째 텍스트 토큰을 지연 없이 출력하고, 스트림이 뒤처질 경우 청크 크기를 늘리며, 도구 호출 및 메타데이터 순서를 보존합니다. `streamRate`를 음수가 아닌 밀리초 단위의 목표값으로 설정하십시오. `streamRate: 0`으로 설정하면 위에서 언급된 SDK 기반 제공업체에서 적응형 스무딩이 비활성화됩니다.

`streamRate`가 없는 `endpoints.all`이 존재할 때 endpoint별 값은 유지됩니다. `endpoints.all.streamRate`를 정의하면 명시적인 `0`을 포함하여 endpoint 값을 재정의합니다.

## 에이전트 활동 그룹 [#agent-activity-groups]

Activity groups는 연속적인 추론 및 도구 호출 블록을 생성된 한 줄 헤더 아래로 접어 긴 Agent 실행 과정을 더 쉽게 훑어볼 수 있게 합니다. 헤더 생성은 메인 모델 응답 경로 외부에서 실행되지만, 여전히 모델 호출이 발생하며 해당 사용량은 기록되고 과금됩니다.

상위 단계 레이블(parent phase labels)이 활성화되면, 짧은 진행 텍스트는 활성 단계 내부에 유지됩니다. 단계는 실질적인 답변 텍스트 이전에 닫히므로 결과는 접힌 요약 외부로 남게 되며, 이후의 추론 블록이나 도구 호출은 동일한 실행 내에서 다른 단계를 시작할 수 있습니다. 또한 LibreChat은 형식이 잘못되었거나 생략된 콘텐츠가 압축될 때 저장된 단계 경계를 재배치(rebase)하여, 다시 로드한 후에도 정렬 상태를 유지합니다.

`endpoints.all` 또는 백엔드 제공자/사용자 지정 endpoint 아래에 이러한 필드를 설정할 수도 있습니다. 값은 독립적으로 결정되며, `endpoints.all`, 공개 `agents` endpoint, 그리고 백엔드 제공자 또는 사용자 지정 endpoint 순서로 먼저 정의된 값이 우선합니다. `activityEndpoint`를 알 수 없는 경우, LibreChat은 경고를 기록하고 대신 Agent의 제공자를 사용합니다.

상위 단계 요약은 하위 활동 레이블과 독립적입니다. `activityPhaseLabel`은 `activityLabel` 유무와 관계없이 활성화할 수 있습니다. LibreChat은 최소 두 개의 논리적 활동을 포함하는 단계에 대해서만 단계 요약 모델 호출을 수행합니다. `activityCharLimit` 또한 단계 요약에 사용되는 증거의 범위를 제한합니다. 단계 모델 선택은 `activityPhaseModel`, `activityModel`, 원본 endpoint의 `titleModel`, 그리고 현재 실행 모델 순으로 결정됩니다. 단계 endpoint 선택은 `activityPhaseEndpoint`, `activityEndpoint`, 그리고 Agent 제공자 순으로 결정됩니다. 구성된 단계 endpoint를 알 수 없는 경우 경고가 기록되며 Agent 제공자로 대체됩니다.

## 실시간 추론 레이블 (Live Reasoning Labels) [#live-reasoning-labels]

`endpoints.all`, 공개 `agents` 엔드포인트 또는 백엔드 제공업체/사용자 지정 엔드포인트 아래에 이러한 필드를 설정할 수 있습니다. 각 필드는 독립적으로 확인되며, `endpoints.all`, `endpoints.agents`, 그 다음으로 백엔드 제공업체 또는 사용자 지정 엔드포인트 순서로 먼저 정의된 값이 우선 적용됩니다.

모델 선택은 `reasoningLabelModel`, `activityModel`, 발신 endpoint의 `titleModel`, 그리고 현재 Agent 실행 모델 순으로 결정됩니다. Endpoint 선택은 `reasoningLabelEndpoint`, `activityEndpoint`, 그리고 Agent 제공자 순으로 결정됩니다. 알 수 없는 레이블 endpoint는 경고를 기록하고 Agent 제공자로 대체됩니다.

각 호출은 최대 4,000자의 가시적인 추론(visible reasoning)을 해결된 라벨 endpoint로 전송하며, 이는 Agent와는 다른 제공업체일 수 있습니다. 라벨은 120자로 제한됩니다. 스트리밍 수정은 문자 및 간격 임계값을 모두 준수하며, 완료 시 최소 120자의 새로운 문자로 구성된 의미 있는 끝부분이 즉시 최종 재작성을 트리거할 수 있습니다. 시도된 모든 수정은 `reasoningLabelMaxPerRun`에 포함되며, 자체 토큰 사용량과 비용이 발생하는 별도의 모델 호출입니다.

Langfuse 추적(tracing)이 활성화되면, 활성 수정 정책(redaction policy)이 레이블 호출을 억제하지 않는 한, 제한된 추론 스냅샷이 레이블 생성의 입력으로 기록됩니다. 민감한 추론 콘텐츠에 대해 이 기능을 활성화하기 전에 대상 endpoint와 추적 정책을 검토하십시오.

## headers

**키:**

<OptionTable
  options={[
    [
      'headers',
      'Object/Dictionary',
      '지원되는 내장 공급자 endpoint로 전달되는 사용자 지정 요청 헤더입니다.',
      'Useful for AI gateways and reverse proxies that consume metadata headers while LibreChat keeps provider-native request formatting.',
    ],
  ]}
/>

**지원되는 endpoint:** `openAI`, `anthropic`, `google`, 및 `all`.

**예시:**

```yaml filename="endpoints / headers"
endpoints:
  all:
    headers:
      X-App: 'librechat'
  anthropic:
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
```

**참고:**

- 값은 `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}` 및 `{{LIBRECHAT_BODY_CONVERSATIONID}}`와 같은 요청 본문(request-body) 플레이스홀더를 지원합니다.
- 에이전트 모델 요청은 `{{LIBRECHAT_USER_TENANT_ID}}` 및 `{{LIBRECHAT_USER_TENANTID}}`를 추가로 지원합니다. 두 변수 모두 루트 에이전트, 하위 에이전트, 활동 레이블, 메모리 및 요약 호출에 대해 권한 있는 요청 범위의 테넌트로부터 확인되며, 실행에 테넌트가 없는 경우 빈 문자열이 됩니다. 이 테넌트 값은 의도적으로 모델 헤더로 제한되며 일반 사용자 플레이스홀더 소비자에게는 추가되지 않습니다.
- 최종 아웃바운드 해결 단계에서, 인식된 사용자, 요청 본문 및 OpenID 플레이스홀더 중 값이 없는 항목은 템플릿 텍스트로 전달되는 대신 빈 문자열로 처리됩니다. 알 수 없는 플레이스홀더 이름은 구성 오타를 확인할 수 있도록 변경되지 않은 상태로 유지됩니다.
- Endpoint 수준의 헤더는 키 충돌 시 `endpoints.all.headers`를 덮어씁니다.
- 공급자 관리형 인증 및 필수 beta/protocol 헤더가 우선합니다. Anthropic beta 값은 병합되므로 사용자 지정 beta 플래그가 필수 공급자 플래그를 덮어쓰지 않습니다.
- 지원되는 공급자 모델 목록 요청에 대해서도 헤더가 전달됩니다.
- 게이트웨이 또는 이를 소비하는 리버스 프록시 뒤에서 메타데이터 헤더를 사용하세요. 네이티브 제공업체 API는 일반적으로 알 수 없는 헤더를 무시합니다.

---

**참고:**

- 이 페이지에 표시된 모든 설정은 각 endpoint별로 개별적으로 구성하거나 `all` 키를 사용하여 전역적으로 구성할 수 있습니다.
- `all` 구성을 사용할 경우, 모든 개별 endpoint의 해당 설정을 덮어씁니다.
- `all` 키는 `baseURL`을 허용하지 않습니다.
- `azureOpenAI` 엔드포인트는 이러한 설정 중 일부만 허용합니다. `titleEndpoint`, `headers`, `maxToolResultChars`는 허용되지 않습니다. [Azure OpenAI](/docs/configuration/librechat_yaml/object_structure/azure_openai)를 참조하세요.
- `all`에 정의되지 않은 설정은 각 endpoint의 개별 값을 유지합니다.
- `streamRate`의 경우: 엔드포인트별로 부드러운 출력을 원할 때 25-40 사이의 값을 권장합니다.
- 많은 사용자에게 대규모로 앱을 서비스할 때는 더 높은 스트림 속도를 사용하는 것이 필수적입니다.

**재정의(Override) 동작 예시:**

```yaml
endpoints:
  openAI:
    streamRate: 25 # This will be preserved
    titleModel: 'gpt-4' # This will be overridden
    titleConvo: false # This will be overridden

  all:
    titleConvo: true
    titleModel: 'gpt-3.5-turbo'
    # streamRate not defined here, so individual values are kept
```
