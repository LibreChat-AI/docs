Każdy element w `models` jest częścią listy rekordów, będącą wartością logiczną (boolean) lub obiektem:

**Podczas określania modelu jako obiektu:**

Obiekt umożliwia szczegółową konfigurację modelu, w tym jego `deploymentName`, `version` oraz/lub flagę `assistants`. Ten tryb służy do bardziej precyzyjnej kontroli nad modelami, szczególnie podczas pracy z wieloma wersjami lub wdrożeniami w ramach jednej instancji lub grupy zasobów.

**Przykład**:
```yaml filename="endpoints / azureOpenAI / groups / {group_item} / models / {model_item=Object}"
models:
  gpt-4-vision-preview:
    deploymentName: "gpt-4-vision-preview"
    version: "2024-02-15-preview"
```

**Uwagi:**
- **Deployment Names** oraz **Versions** mają kluczowe znaczenie dla zapewnienia użycia właściwego modelu.
    - Sprawdź dokładnie te wartości pod kątem poprawności, aby zapobiec nieoczekiwanemu zachowaniu.

### deploymentName

**Klucz:**
<OptionTable
  options={[
    ['deploymentName', 'String', 'Nazwa wdrożenia dla modelu. Identyfikuje wdrożenie modelu w ramach Azure.', 'This does not have to be the matching OpenAI model name as is convention, but must match the actual name of your deployment on Azure.'],
  ]}
/>

**Wymagane:** nie. Gdy zostanie pominięte, używana jest wartość `deploymentName` z grupy. W przypadku grup bez trybu serverless wartość musi być ustawiona w modelu lub w grupie.

**Przykład:**
```yaml filename="endpoints / azureOpenAI / groups / {group_item} / models / {model_item=Object} / deploymentName"
deploymentName: "gpt-4-vision-preview"
```

**Przykład:**
```yaml filename="endpoints / azureOpenAI / groups / {group_item} / models / {model_item=Object} / version"

```

