## langfuse

<OptionTable
  options={[
    [
      'langfuse',
      'Object',
      'Configura la conexión cifrada de Langfuse y los encabezados de solicitud propiedad del despliegue.',
      '',
    ],
  ]}
/>

**Subclaves:**

<OptionTable
  options={[
    ['enabled', 'Boolean', 'Habilita o deshabilita el rastreo de Langfuse para este ámbito de configuración.', ''],
    ['publicKey', 'String', 'Clave pública del proyecto Langfuse.', ''],
    ['secretKey', 'String', 'Clave secreta del proyecto Langfuse cifrada.', ''],
    ['projectId', 'String', 'Identidad del proyecto Langfuse verificada.', ''],
    ['secretKeyPreview', 'String', 'Vista previa enmascarada generada por el servidor de la clave secreta almacenada.', ''],
    [
      'destination',
      'String',
      'Selecciona una clave de destino de Langfuse aprobada para el despliegue.',
      '',
    ],
    [
      'headers',
      'Object/Map of Strings',
      'Cabeceras propiedad del despliegue enviadas a un origen de Langfuse configurado para autenticación de proxy o gateway. Admite referencias a `${ENV_VAR}`.',
      '',
    ],
  ]}
/>

Administre los campos de conexión a través de **Settings → Langfuse** o un cliente de configuración de administrador autorizado. El flujo de Settings verifica la conexión y deriva el `projectId`; el administrador autorizado escribe el `secretKey` cifrado, genera el `secretKeyPreview` y redacta el secreto de las lecturas. Los valores de `secretKey` en texto plano colocados directamente en `librechat.yaml` no son aceptados por la ruta de conexión en tiempo de ejecución. Los campos heredados `displaySecretKey` y `fanout.enabled` ya no forman parte del esquema.

`headers` es diferente: es infraestructura de despliegue y solo puede configurarse en `librechat.yaml`. La configuración de administrador rechaza tanto el mapa completo como las rutas de encabezado individuales, por lo que las credenciales de la puerta de enlace no se almacenan ni se devuelven a través de la configuración respaldada por Mongo. Los valores admiten la interpolación `${ENV_VAR}`; utilice referencias de entorno en lugar de literales. LibreChat descarta las variables no resueltas, las referencias a secretos de infraestructura protegidos, los valores en blanco y los nombres de encabezado HTTP no válidos, mostrando una advertencia.

Los encabezados personalizados se envían en el rastreo y la exportación de medios, las solicitudes de puntuación de comentarios, la búsqueda de proyectos y la verificación de credenciales de administrador solo cuando el despliegue resuelve exactamente un origen de Langfuse. Si la configuración central, de inquilino o de recopilador produce múltiples orígenes, LibreChat no envía encabezados personalizados y registra una advertencia porque el mapa no puede identificar de forma segura a un destinatario. No pueden utilizar marcadores de posición `{{...}}` por usuario, y el recopilador de distribución (fanout) solo reenvía `Authorization` al flujo ascendente.

```yaml filename="langfuse / headers"
langfuse:
  headers:
    CF-Access-Client-Id: '${CF_ACCESS_CLIENT_ID}'
    CF-Access-Client-Secret: '${CF_ACCESS_CLIENT_SECRET}'
```

`langfuse` es una sección de configuración base únicamente. Las anulaciones de configuración de roles, grupos y usuarios no pueden reemplazarla ni eliminarla.

Consulte [Langfuse Configuration](/docs/configuration/langfuse) para conocer las reglas de disponibilidad, la configuración de proxy autenticado, las credenciales gestionadas por el entorno y el despliegue opcional de fanout.

## fileStrategy

- **Opciones**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategy',
      'String',
      'Determina dónde guardar los archivos subidos o generados por el usuario. El valor predeterminado es `"local"` si se omite.',
      'fileStrategy: "firebase"',
    ],
  ]}
/>

- **Notas**:
  - `"cloudfront"` almacena archivos en S3 y devuelve URLs de CloudFront para una entrega de medios estable, cookies firmadas y descargas firmadas.
  - `"firebase"` sirve archivos a través de Firebase Storage y las ubicaciones perimetrales (edge locations) de Firebase Hosting.
  - S3 sirve archivos a través de **presigned URLs** (tokens firmados temporales) que caducan. Una vez caducados, cualquier imagen o avatar que haga referencia a esa URL aparecerá roto en la UI. Esto hace que S3 no sea adecuado como estrategia principal para activos visuales. Consulta la [related discussion](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) para más detalles.
  - Para obtener el mejor rendimiento de imágenes y avatares, utilice `"cloudfront"` o `"firebase"`, o configure `fileStrategies` para dirigir `avatar` e `image` a una estrategia respaldada por una CDN.
  - Consulte la [documentación de File Storage & CDN](/docs/configuration/cdn) para obtener detalles sobre la configuración.

## fileStrategies

Permite un control granular sobre las estrategias de almacenamiento de archivos para diferentes tipos de archivos.

- **Estrategias disponibles**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategies',
      'Object',
      'Configura diferentes estrategias de almacenamiento para distintos tipos de archivos. Más flexible que la opción de fileStrategy única.',
      '',
    ],
  ]}
/>

**Sub-claves:**

<OptionTable
  options={[
    [
      'default',
      'String',
      'Estrategia de almacenamiento de respaldo cuando no se define un tipo específico. El valor predeterminado es "local".',
      '',
    ],
    [
      'avatar',
      'String',
      'Estrategia de almacenamiento para imágenes de avatar de usuario y agente. Se recomienda utilizar una estrategia respaldada por CDN (`"cloudfront"` o `"firebase"`) para obtener el mejor rendimiento.',
      '',
    ],
    [
      'image',
      'String',
      'Estrategia de almacenamiento para imágenes subidas en chats. Se recomienda utilizar una estrategia respaldada por CDN (`"cloudfront"` o `"firebase"`) para obtener el mejor rendimiento.',
      '',
    ],
    ['document', 'String', 'Estrategia de almacenamiento para la carga de documentos (PDFs, archivos de texto, etc.).', ''],
    ['skills', 'String', 'Estrategia de almacenamiento para archivos incluidos con Skills.', ''],
  ]}
/>

- **Notas**:
  - Esta configuración tiene prioridad sobre la opción única `fileStrategy`
  - Si un tipo de archivo específico no está configurado, recurre a `default`, luego a `fileStrategy` y, finalmente, a `"local"`.
  - Las imágenes y los avatares necesitan URLs persistentes y estables para renderizarse correctamente en toda la interfaz de usuario. Las URLs prefirmadas de S3 caducan (límite de AWS: 7 días para usuarios de IAM, horas para credenciales basadas en STS/roles), lo que provoca que las imágenes se rompan en el selector de modelos y en la interfaz de chat. Consulta la [discusión relacionada](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) para obtener el contexto completo. Utiliza `"cloudfront"` o `"firebase"` para `avatar` e `image` para evitar esto.
  - S3 y Azure Blob Storage son adecuados para el almacenamiento de `document`, donde las URLs de descarga prefirmadas de corta duración son apropiadas.
  - Consulte la [documentación de File Storage & CDN](/docs/configuration/cdn) para obtener detalles de configuración para cada proveedor de almacenamiento.

**Ejemplos:**

```yaml filename="fileStrategies - All in one place"
# Use a single strategy for all file types
fileStrategies:
  default: 's3'
```

```yaml filename="fileStrategies - Mixed strategies"
# Route images and avatars to CDN, keep documents in object storage
fileStrategies:
  avatar: 'cloudfront' # CDN delivery for avatars
  image: 'cloudfront' # CDN delivery for generated/uploaded images
  document: 's3' # Object storage for documents
```

```yaml filename="fileStrategies - Partial configuration"
# Only configure specific types, others use default
fileStrategies:
  default: 'local'
  avatar: 'firebase' # Only avatars use Firebase CDN, everything else is local
```

## secureImageLinks

<OptionTable
  options={[
    [
      'secureImageLinks',
      'Boolean',
      'Requiere autorización para enlaces de imágenes alojados localmente por la aplicación. Predeterminado: true.',
      'secureImageLinks: true',
    ],
  ]}
/>

Las imágenes locales están protegidas cuando se omite este campo. Las imágenes de conversaciones privadas requieren una sesión activa y acceso de propietario. Los avatares de usuario almacenados requieren un espectador autenticado en el mismo inquilino (tenant). Los avatares de Agente siguen la ACL de vista del Agente, incluida la visibilidad pública, mientras que los avatares de Asistente requieren el mismo inquilino además de la política efectiva de uso compartido del endpoint o de gestión de Asistentes. Los fallos en la autorización y en la búsqueda de configuración se cierran de forma segura (fail closed).

Establezca `secureImageLinks: false` solo como una opción de compatibilidad para implementaciones que exponen intencionalmente URLs de imágenes locales sin autenticación. Las anulaciones de configuración de roles y usuarios se resuelven a partir de la configuración efectiva del propietario de la imagen.

      'maxHeight: 1900',
    ],

      'quality',
      'Number',
      'Calidad del codificador del navegador de 0 a 1. Los valores más altos suelen preservar más detalles y producir archivos más grandes. Predeterminado: 0.92.',
      'quality: 0.92',

  ]}

**Descripción:**

La configuración `clientImageResize` controla la reducción de escala del lado del cliente antes de la carga. Esta función ayuda a:

- **Evitar errores de carga** debido a archivos de imagen grandes que exceden los límites del servidor
- **Reduce el uso de ancho de banda** comprimiendo las imágenes antes de su transmisión
- **Mejora el rendimiento de carga** con tamaños de archivo más pequeños
- **Mantener la calidad de la imagen** mientras se optimiza el tamaño del archivo

Cuando el cambio de tamaño está habilitado, las imágenes compatibles que exceden `maxWidth` o `maxHeight` se reducen en el navegador antes de cargarse. LibreChat conserva la relación de aspecto, nunca amplía imágenes más pequeñas y mantiene el archivo original cuando el resultado codificado no sería más pequeño.

Si se omite `enabled`, los usuarios pueden activar o desactivar **Resize images before upload** en **Settings > Chat**. La preferencia se almacena en ese navegador y está desactivada de forma predeterminada. Establecer `enabled: true` o `enabled: false` en `librechat.yaml` anula la preferencia de todos los usuarios y deshabilita el interruptor.

**Ejemplo:**

```yaml filename="clientImageResize"
fileConfig:
  clientImageResize:
    # Omit enabled so each user can choose under Settings > Chat.
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

Para aplicar un comportamiento específico en la implementación, añade `enabled: true` o `enabled: false` al mismo bloque.

**Notas:**

- La canalización de redimensionamiento es compatible con JPEG, PNG y WebP en navegadores con las API de Canvas requeridas.
- Los archivos PNG y WebP animados se envían sin cambios, por lo que el cambio de tamaño no descarta la animación.
- La salida mantiene el formato de origen. No existe una configuración `compressFormat`.
- Los codificadores del navegador pueden ignorar `quality` para formatos sin pérdida como PNG.
- Un fallo en el cambio de tamaño recurre al archivo original; los límites normales de carga del servidor siguen aplicándose.

## mcpSettings

**Clave:**

<OptionTable
  options={[
    [
      'mcpSettings',
      'Object',
      'Define la configuración global para los servidores de Model Context Protocol (MCP)',
      '',
    ],
  ]}
/>

**Subclaves:**

<OptionTable
  options={[
    [
      'allowedDomains',
      'Array of Strings',
      'Lista blanca estricta de dominios para conexiones de servidores MCP. Cuando se configura, solo se puede acceder a las entradas listadas.',
      '',
    ],
    [
      'allowedAddresses',
      'Array of Strings',
      'Lista de exención de SSRF (solo espacio IP privado). Permite servicios específicos de host:puerto privados sin cambiar `allowedDomains` al modo de lista blanca estricta.',
      '',
    ],
    [
      'catalogRecovery',
      'Object',
      'Limita la detección pasiva de MCP, la recuperación de OAuth y la protección de autorización entre réplicas. Consulta la referencia de MCP Settings para conocer los campos y valores predeterminados.',
      '',
    ],
  ]}
/>

- **Notas**:
  - Esta es una función de seguridad para proteger contra el abuso / uso indebido de direcciones internas a través de servidores MCP
  - De forma predeterminada, LibreChat restringe que los servidores MCP se conecten a direcciones de red internas, locales o privadas.
  - Los servidores MCP que utilizan direcciones IP locales o dominios pueden añadirse a la lista blanca estricta `allowedDomains` (que se convierte entonces en el único conjunto accesible), o bien, para mantener accesibles los destinos públicos, pueden excluirse como servicios exactos de host:puerto mediante `allowedAddresses`.
  - Como ocurre con todos los cambios de configuración en yaml, es necesario reiniciar LibreChat para que surtan efecto.
  - Admite dominios, subdominios comodín (`*.example.com`), dominios Docker y direcciones IP

**Ejemplo:**

```yaml filename="mcpSettings"
mcpSettings:
  # Strict whitelist mode:
  # allowedDomains:
  #   - "example.com"           # Specific domain
  #   - "*.example.com"         # All subdomains
  #   - "http://mcp-server:3000" # Internal service, explicitly whitelisted

  # Default SSRF mode with private service exemptions:
  allowedAddresses:
    - 'host.docker.internal:8080' # Permit one private host on one port
    - '10.0.0.5:8000' # Permit one private IP on one port
```

## mcpServers

**Clave:**

<OptionTable
  options={[
    [
      'mcpServers',
      'Object',
      'Define la configuración para los servidores del Model Context Protocol (MCP), permitiendo la integración dinámica de servidores MCP dentro de la aplicación.',
      '',
    ],
  ]}
/>

**Subclaves:**

<OptionTable
  options={[
    [
      '<serverName>',
      'Object',
      'Cada clave bajo `mcpServers` representa una configuración individual de servidor MCP, identificada por un nombre único.',
      '',
    ],
  ]}
/>

- **Notas**:
  - La inicialización ocurre al iniciar, y la aplicación debe reiniciarse para que los cambios surtan efecto.
  - El `<serverName>` es un identificador único para cada configuración de servidor MCP.
  - Cada servidor MCP puede configurarse utilizando uno de los cuatro tipos de conexión:
    - `stdio`
    - `websocket`
    - `sse`
    - `streamable-http`
  - El campo `type` especifica el tipo de conexión al servidor MCP.
  - Si se omite `type`, se establece de forma predeterminada según la presencia y el formato de `url` o `command`:
    - Si se especifica `url` y comienza con `http` o `https`, `type` se establece de forma predeterminada en `sse`.
    - Si se especifica `url` y comienza con `ws` o `wss`, `type` se establece de forma predeterminada en `websocket`.
    - Si se especifica `command`, `type` toma `stdio` como valor predeterminado.
  - Las opciones de configuración adicionales incluyen:
    - `timeout`: Tiempo de espera en milisegundos para las solicitudes al servidor MCP. Determina cuánto tiempo esperar una respuesta para las solicitudes de herramientas.
    - `initTimeout`: Tiempo de espera en milisegundos para la inicialización del servidor MCP. Determina cuánto tiempo esperar a que el servidor se inicialice.
    - `serverInstructions`: Controla si las instrucciones del servidor se incluyen en el contexto del agente. Puede ser `true` (usar las proporcionadas por el servidor), `false` (deshabilitado) o una cadena personalizada (anula las proporcionadas por el servidor).
    - `customUserVars`: (Opcional) Define variables personalizadas (por ejemplo, claves de API, URLs) que los usuarios individuales pueden configurar para un servidor MCP. Estos valores por usuario, proporcionados a través de la interfaz de usuario, pueden ser referenciados en las configuraciones de `headers` o `env` del servidor utilizando la sintaxis `{{VARIABLE_NAME}}`. Esto permite la autenticación o personalización por usuario para las herramientas MCP.
  - ver: [Estructura del objeto MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers)

**Ejemplo:**

```yaml filename="mcpServers"
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
    timeout: 30000
    initTimeout: 10000
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    timeout: 30000
    initTimeout: 10000
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-example:
    type: streamable-http
    url: https://example.com/mcp
    headers:
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
  per-user-crendentials-example:
    type: sse
    url: 'https//some.mcp/sse'
    headers:
      X-Custom-Auth-Token: '{{USER_API_KEY}}' # Placeholder for the user-provided API key, defined in `customUserVars` below.
    customUserVars:
      USER_API_KEY:
        title: 'Service API Key'
        description: "Your personal API key for this service. You can get it <a href='https://example.com/api-keys' target='_blank'>here</a>."
    serverInstructions: true
```
