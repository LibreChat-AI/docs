## **概述** [#overview]

`modelSpecs` 对象可帮助您为应用程序中的 AI 模型提供更简洁的 UI 体验。

`modelSpecs` 下有 3 个主要字段：

- `enforce` (可选；默认值：false)
- `prioritize` (可选；默认值：true)
- `list` (必填)
- `addedEndpoints` (可选)

**注意：**

- 如果 `enforce` 设置为 true，Model Specs 可能会与 `modelSelect`、`presets` 和 `parameters` 等其他界面设置发生冲突。
- `list` 数组包含每个模型的详细配置，其中包括规定特定行为、外观和功能的预设。
- 如果未在配置中指定 [interface](interface.mdx) 字段，拥有 Model Specs 列表将禁用以下界面元素：
  - `modelSelect`
  - `parameters`
  - `presets`
- 如果您希望在启用 Model Specs 的同时启用这些界面元素，可以将 `interface` 对象中的它们设置为 `true`。

<Callout type="info" title="使用 Model Specs 管理用户提供的 API 密钥">
  当 Model Specs 禁用 `modelSelect` 时，端点下拉菜单以及用于打开 **Set API Key** 对话框的齿轮图标将被隐藏。用户仍然可以通过 **Settings → Data controls → API keys** 为任何配置了 `apiKey: "user_provided"` 的端点设置或轮换密钥。

  该列表的作用域限定为用户实际可以访问的 endpoint：即您的 Model Specs 所引用的 endpoint，以及任何 [`addedEndpoints`](#addedendpoints)。当 `agents` endpoint 可达时，它还会包含 agent 的 [`allowedProviders`](/docs/configuration/librechat_yaml/object_structure/agents#allowedproviders)（或者在未设置 `allowedProviders` 时包含所有已配置的提供商）。
</Callout>

## 示例 [#example]

```yaml filename="modelSpecs"
modelSpecs:
  enforce: true
  prioritize: true
  list:
    - name: 'meeting-notes-gpt4'
      label: 'Meeting Notes Assistant (GPT4)'
      softDefault: true
      description: 'Generate meeting notes by simply pasting in the transcript from a Teams recording.'
      iconURL: 'https://example.com/icon.png'
      showOnLanding: true
      conversation_starters:
        - 'Summarize this meeting transcript'
        - 'Extract action items and owners'
      hideBadgeRow: true
      skills:
        - 'brand-guidelines'
        - 'meeting-notes'
      subagents:
        enabled: true
        allowSelf: true
        agent_ids: []
      preset:
        endpoint: 'azureOpenAI'
        model: 'gpt-4-turbo-1106-preview'
        maxContextTokens: 128000 # Maximum context tokens
        max_tokens: 4096 # Maximum output tokens
        temperature: 0.2
        modelLabel: 'Meeting Summarizer'
        greeting: |
          This assistant creates meeting notes based on transcripts of Teams recordings.
          To start, simply paste the transcript into the chat box.
        promptPrefix: |
          Based on the transcript, create coherent meeting minutes for a business meeting. Include the following sections:
          - Date and Attendees
          - Agenda
          - Minutes
          - Action Items

          Focus on what items were discussed and/or resolved. List any open action items.
          The format should be a bulleted list of high level topics in chronological order, and then one or more concise sentences explaining the details.
          Each high level topic should have at least two sub topics listed, but add as many as necessary to support the high level topic. 

          - Do not start items with the same opening words.

          Take a deep breath and be sure to think step by step.
```

### softDefault

<OptionTable
  options={[
    [
      'softDefault',
      'Boolean',
      '指定此 Model Specs 是否仅应为尚未选择模型、Model Specs 或智能体的首次使用用户进行选择。',
      '',
    ],
  ]}
/>

**描述：**

指定首次运行时的默认值，且不会覆盖用户后续的选择。当您希望引导新用户使用精选的 Spec，同时在用户选择其他模型、Spec 或 Agent 后保留其选择时，请使用 `softDefault`。

查看使用软默认（soft-default）Model Specs 的旧对话时，如果用户已经进行了其他选择，系统不会将该 Model Specs 重新设为用户的默认选项。

如果用户保存的选择指向了一个不再有效的 Agent，LibreChat 会重新启用软默认设置，以便新对话仍有可用的选择。加载 Agent 列表时的临时故障不会清除已保存的选择，也不会触发该回退机制。

**示例：**

```yaml filename="modelSpecs / softDefault"
modelSpecs:
  list:
    - name: 'general-assistant'
      label: 'General Assistant'
      softDefault: true
      preset:
        endpoint: 'openAI'
        model: 'gpt-4o-mini'
```

### conversation_starters

<OptionTable
  options={[
    [
      'conversation_starters',
      'Array of Strings',
      '当选中此 Model Specs 时，在聊天着陆页上显示为可点击卡片的建议起始提示词。',
      'No default. Optional.',
    ],
  ]}
/>

**描述：**
对话启动器（Conversation starters）为 Model Specs 提供精选的初始提示词。它们显示在所选 spec 的空聊天页面上，特别适用于 `showOnLanding` 品牌推广。点击启动器会将其作为新对话的第一条消息提交。

- 如果该 Model Specs 的预设指向了一个定义了自身对话启动器的 Agent 或 Assistant，则这些启动器具有优先权。

**示例：**

```yaml filename="modelSpecs / conversation_starters"
modelSpecs:
  list:
    - name: 'meeting-notes'
      label: 'Meeting Notes'
      showOnLanding: true
      conversation_starters:
        - 'Summarize this meeting transcript'
        - 'Create action items with owners and due dates'
      preset:
        endpoint: 'agents'
        model: 'gpt-4o'
```

### group

<OptionTable
  options={[
    [
      'group',
      'String',
      '用于在 UI 选择器中组织 Model Specs 的可选组名。控制该规范在菜单层级中的显示位置。',
      'No default. Optional.',
    ],
    [
      'groupIcon',
      'String',
      '自定义分组的可选图标。可以是 URL 或内置的 endpoint 键（例如 "openAI", "groq"）。每个分组中仅使用第一个带有 groupIcon 的 spec。',
      'No default. Optional.',
    ],
  ]}
/>

**描述：**
用于在 UI 选择器中组织 Model Specs 的可选组名。`group` 字段提供了对 Model Specs 组织方式的灵活控制：

- **如果 `group` 与 endpoint 名称匹配**（例如 `"openAI"`、`"groq"`）：Model Specs 将显示在选择器菜单中该 endpoint 下方的嵌套位置。
- **如果 `group` 是自定义名称**（不匹配任何 endpoint）：将创建一个带有该名称的独立可折叠部分。你可以选择使用 `groupIcon` 为该部分设置自定义图标（URL 或内置键，例如 `"openAI"`）。
- **如果省略 `group`**：Model Specs 将作为顶级项目单独显示。

当您希望在不破坏选择器菜单组织结构的情况下为模型添加描述时，此功能特别有用。

### runInBackground

<OptionTable
  options={[
    [
      'runInBackground',
      'Boolean or Array of Strings',
      '控制哪些附加到 Model Specs 的合格工具可以作为后台任务运行。',
      'Unset (background-native code defaults apply)',
    ],
  ]}
/>

需要启用端点级别的 `run_in_background` 功能。在具备该功能且 `executeCode: true` 的情况下，Code Interpreter 执行和 shell 调用默认符合后台运行条件。设置 `runInBackground: false` 或 `[]` 可将其禁用，设置为 `true` 可启用附加到该规范的所有符合条件的工具，或者通过提供一组已解析的工具 ID 来仅启用这些工具。选择 `execute_code` 或 `bash_tool` 将同时选中这两个原生代码工具；列表中省略它们则表示将其禁用。不支持或拼写错误的选项将被记录到日志中。

模型可以启动符合条件的工具并继续工作。对于已保存的 Agents，支持的内容补全默认会自动交付；`check_background_task` 仍可用于状态、控制、实时工件和恢复。已完成的代码输出和生成的文件会附加到原始代码调用中。普通执行是进程局部的，不会在工作进程丢失后存活，但持久化的终端结果可能会从另一个副本交付。管理员可以通过 [`endpoints.agents.backgroundTasks.completionWakeups: false`](/docs/configuration/librechat_yaml/object_structure/agents#backgroundtasks) 恢复仅轮询行为。

```yaml filename="modelSpecs / runInBackground"
modelSpecs:
  list:
    - name: 'operations-assistant'
      mcpServers: ['operations']
      executeCode: true
      runInBackground:
        - 'execute_code'
        - 'slow_report_mcp_operations'
      preset:
        endpoint: 'openAI'
        model: 'gpt-4o-mini'
```

### Agent 选项 [#agent-options]

请注意，这些选项仅在使用 `agents` endpoint 时适用。

您应该排除任何模型选项，并遵循 UI 中定义的智能体配置。

<Callout type="info" title="智能体访问过滤 (v0.8.0+)">
从 v0.8.0 版本开始，LibreChat 为 Agent 使用了基于 ACL（访问控制列表）的权限系统。当 Model Specs 被配置为使用 Agent 时，即使用户在 Model Specs 中配置了某些 Agent，只要用户没有访问权限，这些 Agent 也会被自动过滤掉。这确保了用户只能看到并使用他们拥有相应权限的 Agent。

服务器还会解析有效的 Model Specs 并授权其持久化的 `agent_id`，然后再加载或运行该 Agent。调用者无法在通过此访问检查后，通过请求字段或预设不匹配来替换为其他 Agent。

有关 ACL 权限系统的更多信息，请参阅 [Agents 文档](/docs/features/agents#migration-required-v080-rc3)。

</Callout>

#### thinkingBudget

> **支持的平台：** `google`, `anthropic`, `bedrock` (Anthropic 模型)

<OptionTable
  options={[
    [
      'thinkingBudget',
      'Number or String',
      '控制模型可用于内部推理的思维 token 数量。更大的预算可以提高复杂问题的响应质量。',
      '',
    ],
  ]}
/>

**默认值：** `"Auto (-1)"` (Google), `2000` (Anthropic, Bedrock (Anthropic models))

对于 Gemini 2.5 模型，Google 设置具有模型感知能力：Pro 接受 `128`-`32768`，Flash 接受 `0`-`24576`，Flash-Lite 接受 `512`-`24576`。`-1` 保持为自动设置。Gemini 3+ 模型使用 [`thinkingLevel`](#thinkinglevel) 而非数值预算。

**示例：**

```yaml
preset:
  thinkingBudget: '2000'
```

#### thinkingDisplay

> **支持：** `anthropic`, `bedrock` (Anthropic 模型)

<OptionTable
  options={[
    [
      'thinkingDisplay',
      'String',
      '控制是否在模型响应中返回推理内容。Claude Opus 4.7+ 及 Claude Fable/Mythos 类模型默认省略思考内容；此设置允许您选择加入推理摘要或显式禁止它们。',
      '',
    ],
  ]}
/>

**选项：** `"auto"`（默认）、`"summarized"`、`"omitted"`

- `"auto"` — LibreChat 决定：对于默认省略思考过程的模型（Opus 4.7+ 和 Fable/Mythos 级别），选择 `"summarized"`，对于旧模型则不设置该字段。
- `"summarized"` — 始终请求对推理过程进行事后总结
- `"omitted"` — 始终抑制推理内容（延迟略低）

**默认值：** `"auto"`

**示例：**

```yaml
preset:
  thinkingDisplay: 'summarized'
```
