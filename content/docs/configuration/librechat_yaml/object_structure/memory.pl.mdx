## Przegląd [#overview]

Obiekt `memory` włącza [Pamięć użytkownika](/docs/features/memory) i ustawia jej limity. Dodanie tej sekcji jest tym, co uruchamia pamięć: zapisane wpisy są wtedy dołączane do rozmów każdego użytkownika, użytkownicy mogą nimi zarządzać w panelu Pamięci, a narzędzie Memory (`set_memory` i `delete_memory`) jest udostępniane w czatach i agentach, o ile możliwość `memory` jest włączona dla endpointu agents (domyślnie jest).

Automatyczne wyodrębnianie pamięci, w którym osobny agent pamięci analizuje każdą wymianę wiadomości i zapisuje fakty bez proszenia o to, jest osobną opcją wymagającą świadomego włączenia: ustaw `agent.enabled: true` i podaj model.

## Przykład [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Konfiguruje opcjonalnego agenta pamięci automatycznej. Może być odniesieniem do istniejącego agenta według ID lub pełną konfiguracją agenta.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],

Konfiguruje automatycznego agenta pamięci. Jest uruchamiany tylko wtedy, gdy `enabled` ma wartość `true`; blok `agent` bez `enabled` jest ignorowany, a LibreChat zapisuje ostrzeżenie w logach podczas uruchamiania.

Po włączeniu agent pamięci uruchamia się na początku każdego żądania czatu, równolegle z główną odpowiedzią. Analizuje ostatnie `messageWindowSize` wiadomości (ograniczone do `maxInputTokens`) i samodzielnie zapisuje lub usuwa wpisy. Ma czas do zakończenia głównej odpowiedzi plus maksymalnie 3 sekundy; jeśli nadal działa po tym czasie, jego wynik zostaje odrzucony dla danego żądania.

Pole `agent` obsługuje dwa różne formaty konfiguracji:

### Agent według ID [#agent-by-id]

Gdy masz wstępnie skonfigurowanego agenta, możesz odwołać się do niego za pomocą jego ID:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Konfiguracja niestandardowego agenta [#custom-agent-configuration]

Aby uzyskać większą kontrolę, możesz zdefiniować pełną konfigurację agenta:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Kompletny przykład konfiguracji [#complete-configuration-example]

Przykład wykorzystujący wszystkie opcje pamięci:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Korzystanie z niestandardowych endpointów [#using-custom-endpoints]

Funkcja pamięci obsługuje niestandardowe endpointy. W przypadku korzystania z niestandardowego endpointu, pole `provider` powinno dokładnie odpowiadać `name` niestandardowego endpointu. Niestandardowe nagłówki ze zmiennymi środowiskowymi oraz symbolami zastępczymi użytkownika są poprawnie rozpoznawane.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- Zobacz [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers), aby uzyskać listę wszystkich dostępnych symboli zastępczych.

## Uwagi [#notes]

- `personalize` kontroluje, czy użytkownicy mogą zrezygnować, a nie czy pamięć jest włączona. Użyj `disabled`, aby wyłączyć pamięć.
- `maxInputTokens` ogranicza kontekst czatu wysyłany do automatycznego agenta pamięci, natomiast `tokenLimit` ogranicza łączny rozmiar zapisanych wspomnień.
- Niestandardowe `instructions` zastępują domyślne instrukcje pamięci i są przydatne głównie w połączeniu z `validKeys`.
- Dostęp jest również kontrolowany dla każdej roli za pomocą uprawnień do pamięci (użycie, tworzenie, odczyt, aktualizacja, rezygnacja). Zobacz [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), [Panel administracyjny](/docs/features/admin_panel) lub ustawienia administratora na dole panelu Pamięci.

## Rozwiązywanie problemów [#troubleshooting]

**Pamięć nie działa.** Sprawdź, czy sekcja `memory` istnieje i czy `disabled` nie ma wartości `true`, czy rola użytkownika ma uprawnienia do korzystania z pamięci oraz czy użytkownik nie wyłączył opcji **Reference saved memories**. W przypadku narzędzia Memory, jeśli ustawiasz listę `capabilities` dla endpointu agentów, musi się w niej znajdować możliwość `memory`.

**Nic nie jest zapisywane automatycznie.** Automatyczna ekstrakcja wymaga ustawienia `agent.enabled: true` oraz poprawnego `id`, lub `provider` i `model`. Bez tego wpisy są zapisywane tylko wtedy, gdy użytkownik poprosi model o zapamiętanie czegoś przy włączonym narzędziu Memory, albo gdy dodaje je ręcznie.

**Agent pamięci kończy się niepowodzeniem na niestandardowym endpoincie.** Wartość `provider` musi dokładnie odpowiadać `name` niestandardowego endpointu. Najpierw upewnij się, że endpoint działa w zwykłych czatach, a następnie sprawdź, czy zmienne środowiskowe, do których odwołują się jego nagłówki, są ustawione; symbole zastępcze w nagłówkach są rozwiązywane w taki sam sposób dla pamięci, jak dla czatu.

**Zużycie tokenów jest wysokie.** Zmniejsz wartość `maxInputTokens` lub `messageWindowSize`, aby wysyłać mniej czatu do agenta pamięci, zmniejsz `tokenLimit`, aby zachowane wspomnienia (które są dodawane do każdego żądania) pozostawały małe, oraz ogranicz `validKeys`.
