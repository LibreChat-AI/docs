本页面介绍了所有 endpoint 的共享配置设置。除非另有说明，否则此处突出显示的设置适用于 ["Endpoints"](/docs/configuration/librechat_yaml/object_structure/config#endpoints) 字段下的所有配置。

## 示例配置 [#example-configuration]

```yaml filename="Shared Endpoint Settings"
endpoints:
  # Individual endpoint configurations
  openAI:
    streamRate: 25
    titleModel: 'gpt-4o-mini'
    titleMethod: 'completion'
    titleTiming: 'immediate'
    titlePrompt: "Create a concise title for this conversation:\n\n{convo}"
    headers:
      X-Gateway-Metadata: '{"user_email":"{{LIBRECHAT_USER_EMAIL}}"}'

  azureOpenAI:
    streamRate: 35
    titleModel: 'grok-3'
    titleMethod: 'structured'
    titlePrompt: |
      Analyze this conversation and provide:
      1. A concise title in the detected language (5 words or less, no punctuation or quotation)
      2. Always provide a relevant emoji at the start of the title

      {convo}
    titleConvo: true

  anthropic:
    streamRate: 25
    titleModel: 'claude-3-5-haiku-20241022'
    titleMethod: 'completion'
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'

  bedrock:
    streamRate: 25
    titleModel: 'us.amazon.nova-lite-v1:0'
    titleEndpoint: 'anthropic'

  google:
    streamRate: 25
    titleModel: 'gemini-2.0-flash-lite'
    titlePromptTemplate: "Human: {input}\nAssistant: {output}"
    headers:
      X-Gateway-Metadata: '{"user_id":"{{LIBRECHAT_USER_ID}}"}'

  assistants:
    streamRate: 30

  azureAssistants:
    streamRate: 30

  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5

  # Global configuration using 'all' - this applies shared settings across endpoints.
  # Most defined values override endpoint defaults; headers are merged and endpoint values win on collisions.
  all:
    headers:
      X-App: 'librechat'
    titleConvo: true
    titleModel: 'gpt-4.1-nano'
    titleTiming: 'immediate'
    titlePrompt: |
      Analyze this conversation and provide:
      1. The detected language of the conversation
      2. A concise title in the detected language (5 words or less, no punctuation or quotation)
      3. Always provide a relevant emoji at the start of the title
      {convo}
```

> **重要提示：** 当使用 `all` 配置时，您定义的大多数共享属性将应用于所有 endpoint。在上面的示例中，`all` 配置会将 `titleConvo`、`titleModel` 和 `titlePrompt` 应用于所有 endpoint，而各个 endpoint 的 `streamRate` 设置将被保留，因为它们未在 `all` 中定义。`headers` 会被单独合并：来自 `endpoints.all.headers` 的值将全局应用，且在键冲突时，endpoint 级别的 header 优先级更高。Activity 设置会按相同顺序逐字段解析，因此不相关的 `all` 设置不会覆盖 endpoint 的 activity 配置。

## streamRate

**密钥：**

<OptionTable
  options={[
    [
      'streamRate',
      'Number',
      '从 endpoint 流式传输数据的速率。用于控制流式数据的传输速度。',
      'streamRate: 25',
    ],
  ]}
/>

**默认值：** 取决于提供商。OpenAI、自定义 endpoint、Anthropic、Google、Bedrock 以及由 Agents SDK 支持的流式传输使用目标为 25 毫秒的自适应平滑处理。旧版 Assistants 和 Ollama 处理程序保留其各自的每块（per-provider-chunk）行为，默认值为 1 毫秒。

自适应平滑（Adaptive smoothing）可在无延迟的情况下输出第一个文本 token，在流式传输滞后时增加分块大小，并保留工具调用和元数据的顺序。将 `streamRate` 设置为非负的毫秒目标值；`streamRate: 0` 将禁用上述 SDK 支持的提供商的自适应平滑功能。

当 `endpoints.all` 存在且没有 `streamRate` 时，特定 endpoint 的值会被保留。定义 `endpoints.all.streamRate` 会覆盖 endpoint 的值，包括显式的 `0`。


## titleTiming

**密钥：**

<OptionTable
  options={[
    [
      'titleTiming',
      'String',
      '控制何时生成对话标题。有效值为 "immediate" 或 "final"。',
      'titleTiming: "immediate"',
    ],
  ]}
/>

**默认值：** `"immediate"`

**可用值：**

- **`"immediate"`** - 在请求开始时立即生成标题，与模型响应并行，使用用户的第一条消息。标题通常会在一两秒内出现。
- **`"final"`** - 将标题生成推迟到完整响应完成后进行。这保留了旧有的行为。

**示例：**

```yaml filename="titleTiming"
endpoints:
  all:
    titleTiming: 'immediate'
```

## 智能体活动组 [#agent-activity-groups]

活动组（Activity groups）通过将每个连续的推理和工具调用块折叠在生成的单行标题下，使长 Agent 运行更易于浏览。标题生成在主模型响应路径之外运行，但它仍然是一个模型调用，其使用量会被记录并计费。

启用父阶段标签后，简短的进度文本将保留在当前活跃阶段内。一个阶段会在实质性回答文本之前关闭，因此结果会保留在折叠的摘要之外，而后续的推理或工具调用块可以在同一运行中开启另一个阶段。当格式错误或省略的内容被压缩时，LibreChat 还会重新调整保存的阶段边界，从而在重新加载后保持其对齐状态。

```yaml filename="endpoints / agents / activity groups"
endpoints:
  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5
```

您也可以在 `endpoints.all` 或后端提供商/自定义 endpoint 下设置这些字段。值会独立解析，并按以下顺序优先采用第一个定义的值：`endpoints.all`、公共 `agents` endpoint，然后是后端提供商或自定义 endpoint。如果 `activityEndpoint` 未知，LibreChat 将记录一条警告并改用 Agent 的提供商。

父级阶段摘要独立于子级活动标签：`activityPhaseLabel` 可以在启用或不启用 `activityLabel` 的情况下启用。LibreChat 仅针对包含至少两个逻辑活动的阶段消耗一次阶段摘要模型调用。`activityCharLimit` 也限制了用于阶段摘要的证据。阶段模型选择通过 `activityPhaseModel`、`activityModel`、原始 endpoint 的 `titleModel`，然后是当前运行模型来解析；阶段 endpoint 选择通过 `activityPhaseEndpoint`、`activityEndpoint`，然后是 Agent 提供程序来解析。如果配置了未知的阶段 endpoint，系统会记录警告并回退到 Agent 提供程序。

## 实时推理标签 (Live Reasoning Labels) [#live-reasoning-labels]

实时推理标签将通用的 **Thinking** 或 **Thoughts** 标题替换为针对足够长的顶级 Agent 推理过程的简短、动态的导向信息。LibreChat 会在原地更新现有的推理标题，而不会添加或移动消息内容部分。嵌套的子 Agent 推理不受此设置标记。

```yaml filename="endpoints / agents / live reasoning labels"
    reasoningLabel: true

    reasoningLabelMaxPerRun: 8
```

您可以在 `endpoints.all`、公共 `agents` endpoint 或后端提供商/自定义 endpoint 下设置这些字段。每个字段独立解析，优先级顺序为：`endpoints.all`、`endpoints.agents`，最后是后端提供商或自定义 endpoint，以最先定义的值为准。

模型选择通过 `reasoningLabelModel`、`activityModel`、原始 endpoint 的 `titleModel`，然后是当前的 Agent 运行模型来解析。Endpoint 选择通过 `reasoningLabelEndpoint`、`activityEndpoint`，然后是 Agent 提供商来解析。未知的标签 endpoint 会记录一条警告并回退到 Agent 提供商。

每次调用最多向已解析的 label endpoint 发送 4,000 个可见推理字符，该 endpoint 可以是与 Agent 不同的提供商。标签限制为 120 个字符。流式修订会同时遵守字符数和间隔阈值；在完成时，至少 120 个新字符的有意义尾部可以立即触发最终重写。每次尝试的修订都会计入 `reasoningLabelMaxPerRun`，并且是独立的模型调用，具有各自的 token 用量和成本。

当启用 Langfuse 追踪时，受限推理快照（bounded reasoning snapshot）将被记录为标签生成的输入，除非启用了主动脱敏策略（redaction policy）来抑制标签调用。在为敏感推理内容启用此功能之前，请务必检查目标 endpoint 和追踪策略。

## headers

**密钥：**

<OptionTable
  options={[
    [
      'headers',
      'Object/Dictionary',
      '转发至受支持的内置提供商 endpoint 的自定义请求标头。',
      'Useful for AI gateways and reverse proxies that consume metadata headers while LibreChat keeps provider-native request formatting.',
    ],
  ]}
/>

**支持的 endpoint：** `openAI`、`anthropic`、`google` 和 `all`。

**示例：**

```yaml filename="endpoints / headers"
endpoints:
  all:
    headers:
      X-App: 'librechat'
  anthropic:
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
```

**注意：**

- 值支持 `${ENV_VAR}`、`{{LIBRECHAT_USER_*}}` 以及请求体占位符，例如 `{{LIBRECHAT_BODY_CONVERSATIONID}}`。
- Agent 模型请求额外支持 `{{LIBRECHAT_USER_TENANT_ID}}` 和 `{{LIBRECHAT_USER_TENANTID}}`。两者均从根 Agent、子 Agent、活动标签、记忆和摘要调用的权威请求范围租户中解析，当运行没有租户时，它们将变为空字符串。此租户值被特意限制在模型标头中，不会添加到通用的用户占位符消费者中。
- 在最终的出站解析步骤中，已识别的 user、request-body 和 OpenID 占位符如果未提供值，将变为空字符串，而不是作为模板文本转发。未知的占位符名称将保持不变，以便能够发现配置中的拼写错误。
- Endpoint 级别的 headers 会在键冲突时覆盖 `endpoints.all.headers`。
- 由提供商管理的身份验证以及必需的 beta/protocol 标头仍然具有权威性。Anthropic beta 值会进行合并，因此自定义 beta 标志不会覆盖必需的提供商标志。
- 对于受支持的提供商模型列表请求，请求头也会被转发。
- 在网关或反向代理后使用元数据标头，并由其进行处理。原生提供商 API 通常会忽略未知的标头。

---

**注意：**

- 此页面上显示的所有设置都可以针对每个 endpoint 单独配置，也可以使用 `all` 键进行全局配置。
- 当使用 `all` 配置时，它将覆盖所有独立 endpoint 中的相应设置。
- `all` 键不支持 `baseURL`
- `azureOpenAI` 端点只接受这些设置中的一部分。它不接受 `titleEndpoint`、`headers` 或 `maxToolResultChars`。请参阅 [Azure OpenAI](/docs/configuration/librechat_yaml/object_structure/azure_openai)。
- 未在 `all` 中定义的设置将保留其各自 endpoint 的值
- 对于 `streamRate`：如果需要针对特定 endpoint 进行平滑处理，建议设置在 25-40 之间的值。
- 当在大规模环境下为众多用户提供服务时，必须使用更高的流式传输速率。

**覆盖行为示例：**

```yaml
endpoints:
  openAI:
    streamRate: 25 # This will be preserved
    titleModel: 'gpt-4' # This will be overridden
    titleConvo: false # This will be overridden

  all:
    titleConvo: true
    titleModel: 'gpt-3.5-turbo'
    # streamRate not defined here, so individual values are kept
```
