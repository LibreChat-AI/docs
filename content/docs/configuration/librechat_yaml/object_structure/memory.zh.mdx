## 概述 [#overview]

`memory` 对象用于开启[用户记忆](/docs/features/memory)并设置其限制。添加此部分即可启用记忆功能:保存的条目会被添加到每个用户的对话中,用户可以在"记忆"面板中管理这些条目,并且只要智能体端点已启用 `memory` 能力(默认已启用),聊天和智能体中就会提供记忆工具(`set_memory` 和 `delete_memory`)。

自动记忆提取是一项单独的可选功能:独立的记忆代理会审阅每一轮对话,并在无需用户请求的情况下保存事实。要启用它,请设置 `agent.enabled: true` 并为其指定一个模型。

## 示例 [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      '配置可选的自动记忆智能体。可以是现有智能体的 ID 引用，也可以是完整的智能体配置。',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

配置自动记忆代理。仅当 `enabled` 为 `true` 时才会运行;没有 `enabled` 的 `agent` 块将被忽略,LibreChat 会在启动时记录一条警告。

当启用后,记忆代理会在每个聊天请求开始时与主响应同时运行。它会审查最近的 `messageWindowSize` 条消息(以 `maxInputTokens` 为上限),并自行保存或删除条目。它的运行时间最多为主响应完成后再加 3 秒;若超过该时间仍在运行,则本次请求的结果将被丢弃。

`agent` 字段支持两种不同的配置格式：

### 按 ID 获取 Agent [#agent-by-id]

当您拥有一个预配置的 agent 时，可以通过其 ID 来引用它：

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### 自定义 Agent 配置 [#custom-agent-configuration]

若需更多控制权，您可以定义完整的智能体配置：

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## 完整配置示例 [#complete-configuration-example]

一个使用所有记忆选项的示例:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## 使用自定义 endpoint [#using-custom-endpoints]

Memory 功能支持自定义 endpoint。使用自定义 endpoint 时，`provider` 字段必须与自定义 endpoint 的 `name` 完全匹配。包含环境变量和用户占位符的自定义请求头会被正确解析。

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- 请参阅 [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) 以获取所有可用的占位符。

## 注意事项 [#notes]

- `personalize` 控制的是用户是否可以选择退出，而不是记忆功能是否开启。若要关闭记忆功能，请使用 `disabled`。
- `maxInputTokens` 限制发送给自动记忆代理的聊天上下文长度,而 `tokenLimit` 则限制已存储记忆的总大小。
- 自定义 `instructions` 会替换默认的记忆指令,主要在与 `validKeys` 配合使用时才有用。
- 通过记忆权限（使用、创建、读取、更新、退出）也可以按角色控制访问权限。请参阅 [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories)、[管理面板](/docs/features/admin_panel)，或记忆面板底部的管理员设置。

## 故障排除 [#troubleshooting]

**Memory 没有任何作用。** 请检查以下几点：`memory` 配置段是否存在且 `disabled` 不为 `true`，用户的角色是否有权使用记忆功能，以及用户是否关闭了 **Reference saved memories（引用已保存的记忆）**。对于 Memory 工具，如果你设置了 agents 端点的 `capabilities` 列表，则其中必须包含 `memory` 功能。

**不会自动保存任何内容。** 自动提取需要设置 `agent.enabled: true` 并提供有效的 `id`，或者提供 `provider` 和 `model`。否则，只有当用户开启 Memory 工具并要求模型记住某些内容，或者用户手动添加时，条目才会被保存。

**记忆代理在自定义端点上失败。** `provider` 必须与自定义端点的 `name` 完全一致。请先确认该端点可用于普通聊天，然后检查其请求头所引用的环境变量是否已设置；记忆功能中的请求头占位符与聊天中的解析方式相同。

**Token 用量较高。** 降低 `maxInputTokens` 或 `messageWindowSize`，以减少发送给记忆代理的聊天内容；降低 `tokenLimit`，以控制存储的记忆（这些记忆会added到每个请求中）的大小；并限制 `validKeys`。
