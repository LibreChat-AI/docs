            allowPrincipalWorkers: true

    #   selfUrl: https://librechat.internal

## maxProviderErrorChars

Controla la cantidad de texto de error del proveedor que LibreChat conserva cuando no se puede clasificar un fallo del Agente. El valor predeterminado es `2000` caracteres. Establézcalo en `0` para omitir el texto del proveedor; el máximo es `1000000`.

```yaml filename="endpoints / agents / maxProviderErrorChars"
maxProviderErrorChars: 2000
```

## repositoryInstructions

Controla el descubrimiento de instrucciones del repositorio para entornos de código adjuntos. `timeoutMs` limita la solicitud de carga de instrucciones desde `100` hasta `30000` milisegundos y su valor predeterminado es `2000`.

```yaml filename="endpoints / agents / repositoryInstructions"
repositoryInstructions:
  timeoutMs: 2000
```

## Disyuntores de flujo (Stream circuit breakers) [#stream-circuit-breakers]

Estos ajustes detienen la ejecución de un Agent cuando el flujo de un proveedor parece estar produciendo argumentos de herramienta descontrolados o una secuencia ilimitada de eventos delta.

<OptionTable
  options={[
    [
      'maxToolCallArgBytes',
      'Number',
      'Máximo de bytes acumulados para los argumentos de una llamada a herramienta transmitida. Establezca en 0 para desactivar la protección global.',
      '65536',
    ],
    [
      'maxDeltaEventsPerTurn',
      'Number',
      'Máximo de eventos transmitidos para un turno de generación de modelo. Establézcalo en 0 u omítalo para desactivar esta protección.',
      '0 (disabled)',
    ],
    [
      'maxToolCallArgBytesByTool',
      'Object',
      'Anulaciones de bytes de argumento por herramienta, indexadas por el nombre de la herramienta que ve el modelo. Un valor de 0 deshabilita la protección para esa herramienta.',
      'create_file: 131072',
    ],
  ]}
/>

LibreChat utiliza un límite global de argumentos de 64 KiB y ofrece una anulación de 128 KiB para `create_file`, cuyos payloads legítimos suelen ser más grandes. Las entradas en `maxToolCallArgBytesByTool` se fusionan sobre esa anulación integrada. Si cualquiera de los límites se supera, LibreChat aborta el flujo del proveedor en curso e informa qué límite fue excedido.

```yaml filename="endpoints / agents / stream circuit breakers"
maxToolCallArgBytes: 65536
maxDeltaEventsPerTurn: 100000
maxToolCallArgBytesByTool:
  create_file: 262144
  large_import: 524288
```

Para deshabilitar cada protección de tamaño de argumento, establezca tanto el límite global como la anulación `create_file` incluida en `0`:

```yaml
maxToolCallArgBytes: 0
maxToolCallArgBytesByTool:
  create_file: 0
```

## activityLabel

Establezca `activityLabel: true` para agrupar cada bloque de razonamiento del Agente y llamadas a herramientas bajo un encabezado generado de una sola línea. Utilice `activityModel`, `activityEndpoint`, `activityPrompt`, `activityMaxPerRun` y `activityCharLimit` para controlar la llamada al modelo adicional y su costo. Consulte [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) para obtener la referencia completa de los campos y las reglas de precedencia.

```yaml filename="endpoints / agents / activity groups"
activityLabel: true
activityEndpoint: openAI
activityModel: gpt-4.1-nano
activityMaxPerRun: 20
activityCharLimit: 600
activityPhaseLabel: true
activityPhaseMaxPerRun: 5
```

`activityPhaseLabel` puede agregar de forma independiente un resumen principal contraído alrededor de cada fase de ejecución que contenga al menos dos actividades lógicas. Utilice `activityPhaseModel`, `activityPhaseEndpoint`, `activityPhasePrompt` y `activityPhaseMaxPerRun` para ajustar esas llamadas; `activityCharLimit` se comparte con las etiquetas de actividad secundarias.

## capabilities

<OptionTable
  options={[
    [
      'capabilities',
      'Array/List of Strings',
      'Especifica las capacidades de agente disponibles para todos los usuarios para el endpoint de agentes.',
      'Defines the agent capabilities that are available to all users for the agents endpoint. You can omit the capabilities you wish to exclude from the list.',
    ],
  ]}
/>

**Predeterminado:** `["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]`

`programmatic_tools`, `stateful_code_sessions`, `run_in_background` y `tool_intents` son opcionales y deben añadirse explícitamente. Las herramientas programáticas y las sesiones con estado también requieren `execute_code` y un despliegue de Code Interpreter compatible. El Agent Builder deshabilita las selecciones de MCP programáticas sin Code Interpreter, y el servidor elimina las opciones de llamadas programáticas obsoletas cuando la ejecución de código no está disponible. `run_in_background` hace que las herramientas de Code Interpreter sean elegibles de forma predeterminada y permite la activación por herramienta para herramientas MCP, Plugins y Actions elegibles; la ejecución de código en segundo plano también requiere `execute_code` y Code Interpreter.

`stateful_code_sessions` es altamente experimental. Requiere una ruta de Intérprete de Código con perfil `stateful` configurada con [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) o [`statefulCodeSessions.environments`](#statefulcodesessions). Las solicitudes con estado fallan de forma cerrada en lugar de recurrir al servicio sin estado normal. En el Agent Builder, cada Agente habilitado elige un ámbito de espacio de trabajo de usuario, agente-y-usuario, o conversación y, cuando se configuran backends con nombre, un entorno de ejecución. Los nuevos Agentes comienzan con el ámbito personal predeterminado del usuario y el entorno de ejecución predeterminado del despliegue.

**Ejemplo:**

```yaml filename="endpoints / agents / capabilities"
capabilities:
  - 'deferred_tools'
  # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
  # Requires execute_code and a Code Interpreter deployment with the Tool Call Server component.
  # - 'programmatic_tools'
  - 'execute_code'
  - 'file_search'
  - 'web_search'
  - 'artifacts'
  - 'subagents'
  - 'actions'
  - 'context'
  - 'skills'
  - 'memory'
  - 'ask_user_question'
  - 'tools'
  - 'chain'
  - 'ocr'
  # Optional and highly experimental: reuse a user-, agent-and-user-, or
  # conversation-scoped workspace. Requires LIBRECHAT_CODE_BASEURL_STATEFUL
  # or a named statefulCodeSessions environment.
  # - 'stateful_code_sessions'
  # Optional: allow eligible Code Interpreter, MCP, Plugin, and Action tools to run as background tasks.
  # - 'run_in_background'
  # Optional: show live model-written intent labels for native and selected MCP tools.
  # - 'tool_intents'
```

**Nota:** Este campo es opcional. Si se omite, el comportamiento predeterminado es incluir todas las capacidades enumeradas en el valor predeterminado.

## statefulCodeSessions

Configura los alcances de uso compartido y los backends de ejecución opcionales para espacios de trabajo de Code Interpreter con estado altamente experimentales.

<Callout type="warning" title="Altamente experimental">
  Stateful Code Sessions, entornos de ejecución con nombre, workers adjuntos y el emparejamiento se encuentran en una fase de experimentación temprana. Su comportamiento, configuración, características de persistencia y protocolo de integración pueden cambiar sustancialmente.
</Callout>

<OptionTable

    [
      'principalWorkers',
      'Object',
      'Límite de despliegue opcional para la inscripción de trabajadores personales. `enabled` tiene como valor predeterminado true y `maxPerUser` tiene como valor predeterminado 5.',
      '{ enabled: true, maxPerUser: 5 }',
    ],
    [
      'conversationMoves',
      'Object',
      'Transiciones de espacio de trabajo autorizadas por el propietario con opción de participación para conversaciones guardadas. `allowAttachDetach` permite adicionalmente adjuntar o abandonar un espacio de trabajo adjunto.',

    ],

/>

Los entornos adjuntos aceptan `environments[].configSchema.limits.maxQueueWaitMs`, lo cual controla cuánto tiempo puede una solicitud reintentar la espera por capacidad en el espacio de trabajo. El valor predeterminado y máximo es `300000` milisegundos (5 minutos). Establézcalo en `0` para deshabilitar los reintentos del cliente después del intento de admisión inicial; esto no cancela el trabajo que ya ha sido admitido o que se está ejecutando. Estos campos pertenecen a `configSchema.limits`, **no** a `userConfig.bash`.

`environments[].configSchema.limits.maxRequestTimeoutMs` limita opcionalmente el **tiempo HTTP total para una llamada de herramienta de espacio de trabajo**, incluyendo la admisión, ejecución, liquidación y entrega. Acepta de `1` a `610000` ms, pero la configuración rechaza presupuestos demasiado pequeños que no dejen tiempo de ejecución de comandos después de la admisión y la reserva de 10 segundos para liquidación/entrega. Sin esto, la admisión sigue teniendo un presupuesto de 30 segundos por intento; `maxQueueWaitMs` sigue siendo un horizonte de reintento independiente. **No habilite una admisión más larga** hasta que cada réplica de la API de LibreChat entienda este campo, la ruta de la API de código respete las asignaciones de cola por solicitud y se haya medido el tiempo de espera más corto a través de la ruta de proxy/ingress en vivo. Una mutación expirada puede haberse completado en el trabajador, por lo que LibreChat no reintenta un tiempo de espera ambiguo.

Con un presupuesto total de solicitud, `environments[].configSchema.limits.minCommandAdmissionMs` reserva tiempo para que un comando entre al trabajador antes de que comience la ejecución. El valor predeterminado es `10000` ms; establezca un valor entre `1000` y `300000` ms. El presupuesto de solicitud debe **exceder** esta asignación más 10000 ms de margen de liquidación/entrega; sin un presupuesto total, la configuración no tiene efecto. El límite de ejecución de Bash anunciado a un Agente es el menor entre su límite configurado o el límite superior ascendente y el tiempo restante después de esas reservas. Por ejemplo, un presupuesto de solicitud de 90000 ms con un límite de comando de 80000 ms y la reserva predeterminada anuncia como máximo un comando de 70000 ms.

```yaml filename="endpoints / agents / statefulCodeSessions"
statefulCodeSessions:
  allowedEnvironments:
    - 'user'
    - 'agent-user'
    - 'conversation'
  principalWorkers:
    enabled: true
    maxPerUser: 5
  environments:
    - id: managed-default
      name: Managed Code API
      type: managed
      baseURL: https://code.example.com/v1
      default: true
    - id: engineering-vm
      name: Engineering VM
      type: attached
      baseURL: https://code-bridge.example.com/v1
      owner: deployment
      pairing:
        workerId: engineering-vm
        tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
    - id: personal-workers
      name: Personal Code Workers
      type: attached
      baseURL: https://code-bridge.example.com/v1
      owner: deployment
      configSchema:
        limits:
          maxCommandTimeoutMs: 120000
          # Before enabling, verify Code API queue allowances and the live proxy deadline.
          # maxRequestTimeoutMs: 160000
          # minCommandAdmissionMs: 10000
          # maxQueueWaitMs: 300000
        # After upgrading Code API and opting in the worker with --linked-worktree-lanes:
        # workspaces:
        #   linkedWorktrees: true
        # Optional: require exact matching even on workers supporting tolerant edits.
        # edits:
        #   tolerantMatching: false
        permissions:
          fileWrite:
            allowed: [allow, ask, deny]
            default: ask
          commandExecution:
            allowed: [ask, deny]
            default: ask
      pairing:
        allowPrincipalWorkers: true
        tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
```

`allowedEnvironments` es obligatorio siempre que el bloque esté presente y debe incluir al menos un ámbito de espacio de trabajo (workspace scope). Omita el bloque completo para permitir los tres ámbitos y continuar enrutando el trabajo con estado a través de [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint). El valor predeterminado personal y el Agent Builder solo permiten valores autorizados. Si un administrador endurece la política, un valor predeterminado personal guardado permanece visible pero deshabilitado, y los nuevos Agents utilizan el primer ámbito permitido. Los Agents habilitados existentes conservan su ámbito guardado, pero un ámbito ahora no permitido fallará de forma segura (fails closed) en tiempo de ejecución hasta que el Agent sea reconfigurado.

`conversationMoves.enabled: true` permite que el propietario de la conversación mueva explícitamente un espacio de trabajo adjunto sellado a un entorno compatible y recupere un espacio de trabajo faltante sin reemplazar el historial del chat ni restaurar archivos antiguos del espacio de trabajo. Para permitir adicionalmente que un chat guardado **adjunte** un espacio de trabajo o **abandone** uno para un chat normal, establezca `conversationMoves.allowAttachDetach: true`. Ambos interruptores están desactivados de forma predeterminada; habilitar solo los movimientos mantiene el comportamiento de solo movimiento. Actualice **todas** las réplicas de la API y luego habilite [`CODE_ENVIRONMENT_DECISION_VERSION=1`](/docs/configuration/dotenv#code-interpreter) antes de optar por participar. La propiedad, el acceso al destino, el trabajo activo y la política actual se vuelven a verificar en la transición; una generación en ejecución no puede ser movida.

```yaml filename="endpoints / agents / statefulCodeSessions / conversationMoves"
statefulCodeSessions:
  allowedEnvironments: ['user', 'agent-user', 'conversation']
  conversationMoves:
    enabled: true
    allowAttachDetach: true
```

`principalWorkers` controla la inscripción de autoservicio para trabajadores personales adjuntos. Los valores omitidos se resuelven como `enabled: true` y `maxPerUser: 5`; establezca `enabled: false` o `maxPerUser: 0` para detener nuevas inscripciones. El límite cuenta cada entorno personal registrado para ese usuario en todos los planos de control configurados, incluidos los trabajadores fuera de línea. Reducir el límite o deshabilitar la inscripción no revoca los entornos existentes.

El YAML de despliegue es el límite máximo absoluto. Una anulación de configuración de rol, grupo o usuario puede deshabilitar la inscripción o reducir `maxPerUser`, pero no puede aumentar el valor del despliegue. Un usuario ve los planos de control con emparejamiento habilitado solo cuando el límite efectivo es mayor que cero, [`pairing.allowPrincipalWorkers`](#statefulcodesessions) está habilitado en ese plano de control, la autenticación principal está disponible y el usuario tiene permiso de gestión de Code Environment.

Cuando `environments` no está vacío, cada entrada requiere un `id` único, un `name` para mostrar, un `type` de `managed` o `attached`, y una `baseURL` HTTP(S) sin cadena de consulta ni fragmento. Si la lista contiene entornos ejecutables, exactamente una de esas entradas debe establecer `default: true`. El Agent Builder añade entonces un selector de **Execution environment**; dejarlo en **Deployment default** utiliza esa entrada predeterminada. Una lista que solo contiene planos de control de emparejamiento de autoservicio no necesita un valor predeterminado. Un agente que nombre un entorno que posteriormente se elimine o deje de ser accesible fallará de forma segura en lugar de recurrir a otro backend.

- `managed` apunta directamente a una API de código con estado gestionada por el operador.
- `attached` apunta a un backend `remote-bridge` de la Code API compatible que asigna trabajo a un worker `@librechat/code` saliente. El worker no requiere un puerto público entrante, pero su endpoint de ejecución local aún necesita el aislamiento adecuado.
- `workerId` enruta opcionalmente un entorno adjunto a un trabajador de salida. Es solo para el servidor y no se expone a través de la configuración de inicio del cliente.
- `owner` tiene como valor predeterminado `deployment`. Los entornos propiedad del principal se crean a través de la API de Entornos de Código autenticada de LibreChat, protegida por ACL, y se fusionan solo para solicitudes autorizadas; no coloque URLs proporcionadas por el cliente en el YAML de despliegue.
- `pairing` es opcional y solo es válido para entradas `attached` propiedad de la implementación. `pairing.workerId` identifica a un trabajador gestionado por el operador para inscribirse, mientras que `pairing.allowPrincipalWorkers: true` permite a los usuarios autorizados inscribir trabajadores vinculados al propietario en ese plano de control. Al menos uno de esos campos es obligatorio cuando `pairing` está presente.
- `pairing.tokenEnv` nombra la variable de entorno que contiene el token del administrador del puente; nunca contiene el token en sí. El emparejamiento requiere HTTPS, excepto para el desarrollo en loopback.
- `configSchema.permissions` permite opcionalmente a los propietarios autorizados elegir la política de `fileWrite` y `commandExecution` para entornos personales en **Settings > Code environments**. Cada campo requiere una lista `allowed` no vacía que contenga `allow`, `ask` y/o `deny`; `default` es `ask` cuando se omite y debe aparecer en `allowed`. LibreChat rechaza los valores almacenados que estén fuera de la lista del administrador.
- `configSchema.limits.maxCommandTimeoutMs` establece el tiempo de espera máximo de Bash que el modelo puede solicitar para ese entorno. Acepta valores de `1` a `300000` ms; la omisión conserva el valor predeterminado de 30 segundos. Con un presupuesto total de solicitud, el tiempo de espera de comando anunciado también se ajusta al tiempo restante después de la admisión, resolución y entrega del comando. Este es un límite de despliegue y no es configurable por el usuario.
- `configSchema.workspaces.linkedWorktrees: true` habilita la programación por worktree solo para espacios de trabajo adjuntos que anuncien `git_linked_worktree`; la omisión mantiene todas las solicitudes en el carril raíz del checkout. Actualice LibreChat **antes** de que un worker anuncie este ámbito, implemente una API de código que admita carriles de linked-worktree y, a continuación, inicie el worker con `--linked-worktree-lanes` antes de habilitar la configuración YAML. Las operaciones de archivo dirigidas a una ruta dentro de `.worktrees/<name>` y los comandos Bash con un `cwd` allí utilizan ese carril y devuelven rutas relativas al checkout. Los comandos que hacen `cd` dentro de su texto de comando, las operaciones en la raíz del checkout, las instancias de espacio de trabajo de conversación y las acciones de entorno permanecen con ámbito en la raíz.
- `configSchema.edits.tolerantMatching` permite por defecto una alternativa tolerante a espacios en blanco en los workers adjuntos que anuncien `tolerant_match`; establézcalo en `false` para requerir una coincidencia exacta, incluyendo las vistas previas de edición protegidas. La coincidencia debe seguir siendo única a menos que la edición establezca explícitamente `replace_all`. Los workers más antiguos no reciben nuevos campos de coincidencia; los `replace_all` adjuntos se rechazan antes del envío a menos que el worker los anuncie. Estas capacidades requieren una API de código y compilaciones de worker compatibles que implementen [Code Interpreter #271](https://github.com/LibreChat-AI/code-interpreter/pull/271).
- No configure `settings` en el YAML de despliegue. LibreChat suministra ese campo de ámbito de solicitud a partir de las preferencias validadas por el servidor del propietario autenticado.
- Solo la política de escritura de archivos y ejecución de comandos es configurable por el usuario. El aislamiento, las redes, los montajes, la ejecución privilegiada, el ingreso, el egreso y los secretos permanecen bajo el control del administrador.
- Si tanto el `workerId` de nivel superior como `pairing.workerId` están presentes, deben coincidir. Una entrada con `allowPrincipalWorkers: true` y sin ninguno de los dos ID de trabajador es solo de emparejamiento: se omite de los selectores de ejecución y no puede establecer `default: true`.

La ejecución adjunta habilita automáticamente una línea base de aprobación segura: las escrituras de archivos y la ejecución de comandos o código solicitan confirmación, mientras que las operaciones de solo lectura y búsqueda continúan bajo la política de herramientas habitual. La línea base está limitada al Agent que utiliza el entorno adjunto. Si no hay una configuración de usuario disponible, LibreChat utiliza `ask`; [`toolApproval.enabled: false`](#toolapproval) es la anulación de emergencia del administrador que deshabilita esta línea base del entorno adjunto. Las llamadas sin soporte de aprobación y reanudación fallan de forma cerrada a menos que se establezca esa anulación explícita.

La ejecución adjunta requiere una compilación experimental de remote-bridge de Code Interpreter que coincida. El emparejamiento autentica la conexión del trabajador saliente; no reemplaza el aislamiento de sandbox o VM. Los usuarios con permiso de gestión de Code Environment pueden emparejar, configurar la política de herramientas permitidas y revocar trabajadores personales en **Settings > Code environments**. Consulte [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions).

## eventDriven

Configura el origen interno de confianza utilizado para la entrega de eventos de Agent. La mayoría de las implementaciones deben omitir este bloque y utilizar el listener vinculado al proceso actual.

<OptionTable
  options={[
    [
      'selfUrl',
      'URL',
      'Anula el oyente vinculado al proceso actual para la admisión de activadores internos de confianza. Úselo solo cuando la entrega deba atravesar otro origen HTTP de confianza.',
      '',
    ],
    [
      'idlePolling',
      'Object',
      'Limita los escaneos de recuperación de MongoDB en espera y las verificaciones de finalización de espera. Los eventos locales pueden activar un escaneo antes.',
      'See defaults below',
    ],
  ]}
/>

```yaml filename="endpoints / agents / eventDriven"
endpoints:
  agents:
    eventDriven:
      selfUrl: https://librechat.internal
```

Las continuaciones de hijos vinculados son automáticas. Los campos antiguos `childTurns`, `completionWakeups`, `coalescing`, `actorMailbox`, `checkpointForks` y `durableReceipts` bajo `eventDriven` ya no son interruptores de configuración y deben eliminarse. El tiempo de ejecución ahora aplica esas garantías de entrega directamente. El campo separado [`backgroundTasks.completionWakeups`](#backgroundtasks) controla la entrega conversacional para herramientas en segundo plano completadas y Subagents separados.

Deje `selfUrl` sin configurar para la ruta normal de escucha vinculada. Configúrelo solo cuando la admisión de disparadores internos de confianza deba atravesar otro origen HTTP(S), como una puerta de enlace TLS. `AGENT_TRIGGERS_SELF_URL` permanece como una alternativa de compatibilidad cuando se omite este campo. Consulte [Eventos de la API de agentes](/docs/features/agents_api#agent-events) y [Continuación automática de padres](/docs/features/subagents#automatic-parent-continuation).

`eventDriven.idlePolling` limita el sondeo de recuperación por réplica cuando no hay nada listo: `deliveryMaxIntervalMs` tiene un valor predeterminado de `15000` (válido de `1000` a `300000`), `queuedTurnMaxIntervalMs` y `maintenanceMaxIntervalMs` tienen cada uno un valor predeterminado de `120000` (válido de `30000` a `300000`), y `completionWaitMaxIntervalMs` tiene un valor predeterminado de `60000` (válido de `5000` a `300000`). Este último limita las verificaciones cuando un resultado en segundo plano o de un Subagente está pendiente o su turno principal está ocupado. Los eventos de preparación aceleran la entrega; estos límites mantienen alternativas entre réplicas y de recuperación ante fallos en lugar de definir la latencia de finalización normal.

```yaml filename="endpoints / agents / eventDriven / idlePolling"
eventDriven:
  idlePolling:
    deliveryMaxIntervalMs: 15000
    queuedTurnMaxIntervalMs: 120000
    maintenanceMaxIntervalMs: 120000
    completionWaitMaxIntervalMs: 60000
```

La finalización de la Action del Event Actor detached se selecciona automáticamente desde el almacén de generación integrado. La ejecución en memoria es local al proceso; los flujos de generación de Redis añaden recuperación de reinicio duradera y transferencia de réplicas. No se requiere ningún interruptor en `librechat.yaml` ni flag de característica en el entorno. Consulte [Agent Event Runtime](/docs/configuration/dotenv#agent-event-runtime).

## toolApproval

Controla la revisión humana para las llamadas a herramientas de los agentes. La política a nivel de despliegue se deshabilita cuando se omite este bloque. Un agente que utiliza un entorno de código adjunto es la excepción: LibreChat habilita su política de seguridad de solicitud por defecto (ask-by-default) a menos que el administrador establezca explícitamente `enabled: false`. Cuando se aplica la revisión, las llamadas coincidentes se pausan hasta que el usuario envía una decisión permitida, como aprobar, rechazar o editar los argumentos.

<OptionTable
  options={[
    [
      'enabled',
      'Boolean',
      'Habilita la aprobación de herramientas a nivel de despliegue. Un valor false explícito también deshabilita la línea base de seguridad del entorno de código adjunto.',
      'Omitted',
    ],
    [
      'mode',
      'String',
      'Establece el comportamiento para llamadas no coincidentes: `default` pregunta, `dontAsk` deniega y `bypass` aprueba a menos que se deniegue.',
      'default',
    ],
    ['allow', 'Array of strings', 'Patrones glob para llamadas que pueden ejecutarse sin solicitar confirmación.', ''],
    ['deny', 'Array of strings', 'Patrones glob para llamadas que siempre se deniegan. Las reglas de denegación tienen prioridad.', ''],
    ['ask', 'Array of strings', 'Patrones glob para llamadas que siempre requieren revisión.', ''],
    [
      'reason',
      'String',
      'Explicación opcional que se muestra en el aviso de aprobación. Usa `{tool}` para insertar el nombre de la herramienta.',
      '',
    ],
    [
      'hooks',
      'Array of objects',
      'Módulos de políticas programáticas de confianza para decisiones conscientes del contexto. Los Hooks solo pueden restringir la política estática.',
      '',
    ],
  ]}
/>

Los patrones utilizan coincidencia glob. Las herramientas MCP pueden ser delimitadas con `mcp:<server>:<tool>`; por ejemplo, `mcp:github:*` coincide con todas las herramientas del servidor `github`. LibreChat aplica reglas estáticas y comparadores de hooks a los nombres de tiempo de ejecución de MCP y a los alias orientados al modelo, incluyendo herramientas accesibles a través de Subagentes anidados. Las reglas estáticas se evalúan en el orden `deny`, `ask`, y luego `allow` antes de que el modo seleccionado proporcione el respaldo. Por lo tanto, una regla de denegación siempre prevalece, incluso en el modo `bypass`.

```yaml filename="endpoints / agents / toolApproval"
toolApproval:
  enabled: true
  mode: default
  allow:
    - 'mcp:analytics:read_*'
  deny:
    - 'mcp:*:delete_*'
  ask:
    - 'mcp:*:*'
  reason: 'Review {tool} before it runs.'
```

Los Hooks se cargan una vez al iniciar el servidor y se ejecutan en el proceso de LibreChat. Cada entrada acepta un `module`, un `matcher` regex opcional para el nombre de la herramienta y un objeto `options` opcional que se pasa al constructor del módulo. Solo cargue código en el que confíe. Las anulaciones por rol o inquilino no recargan los módulos de hook; implemente el comportamiento contextual dentro del hook.

```yaml filename="endpoints / agents / toolApproval / hooks"
toolApproval:
  enabled: true
  hooks:
    - module: '@acme/librechat-approval-hook'
      matcher: '^mcp:production:'
      options:
        requireTicket: true
```

## fileSharing

`fileSharing` es una función de uso compartido opcional y con alcance de ejecución para el trabajo delegado de Agentes. Establezca `enabled: true` aquí y habilite `subagents.shareFiles` en cada Agente delegante. Las entradas son de solo lectura para los destinatarios; las salidas permanecen privadas a menos que se publiquen explícitamente, y los archivos publicados siguen siendo descargables después de la ejecución.

```yaml filename="endpoints / agents / fileSharing"
endpoints:
  agents:
    fileSharing:
      enabled: true
      allowSiblingSharing: false
      maxFiles: 100
      maxPrivateBytes: 268435456
      ttlMs: 3600000
```

`allowSiblingSharing` permite destinatarios hermanos o descendientes explícitamente nombrados. `maxFiles` varía de `1` a `1000`; `maxPrivateBytes` limita las instantáneas de salida privadas retenidas; y `ttlMs` es el tiempo de vida activo del manifiesto, limitado a 24 horas. Omitir este bloque deja el uso compartido deshabilitado.

## Capacidades de los agentes [#agent-capabilities]

El campo `capabilities` le permite habilitar o deshabilitar funcionalidades específicas para los agentes. Las capacidades disponibles son:

- **deferred_tools**: Permite a los agentes descubrir herramientas MCP diferidas en tiempo de ejecución en lugar de cargar cada herramienta en el contexto por adelantado.
- **programmatic_tools**: Habilita la llamada a herramientas programáticas (Programmatic Tool Calling) para herramientas MCP marcadas como Programmatic en el Agent Builder. Requiere `execute_code` y un despliegue de Code Interpreter con el componente Tool Call Server. Esta capacidad es opcional y no está habilitada de forma predeterminada.
- **execute_code**: Permite al agente ejecutar código.
- **stateful_code_sessions**: Permite que los agentes que han optado por esta función reutilicen un espacio de trabajo de Code Interpreter en el ámbito de usuario, agente-y-usuario, o conversación. Requiere `execute_code`, un despliegue compatible de Code Interpreter y la configuración avanzada por agente. Los nuevos agentes utilizan el ámbito preferido del usuario que ha iniciado sesión. Esta capacidad es altamente experimental, no está habilitada de forma predeterminada y puede cambiar sustancialmente durante la experimentación; no trate su comportamiento o configuración actual como un contrato de producción estable.
- **file_search**: Permite al agente buscar e interactuar con archivos. Cuando está habilitado, el comportamiento de las citas se controla mediante los ajustes `maxCitations`, `maxCitationsPerFile` y `minRelevanceScore`.
- **web_search**: Habilita la funcionalidad de búsqueda web para los agentes, permitiéndoles buscar y recuperar información de internet.
- **artifacts**: Permite al agente generar artefactos interactivos (componentes de React, HTML, diagramas de Mermaid).
- **subagents**: Habilita ejecuciones de agentes secundarios con contexto aislado. Consulta [Subagents](/docs/features/subagents).
- **actions**: Permite al agente realizar acciones predefinidas.
- **context**: Habilita la funcionalidad "Subir como texto" en el chat y "Contexto de archivo" para los agentes, permitiendo a los usuarios subir archivos y que su contenido sea extraído e incluido directamente en la conversación.
- **skills**: Habilita Skills en el panel lateral, invocación manual mediante `$`, skills invocadas por el modelo y listas de permitidos de skills para agentes. Consulta [Skills](/docs/features/skills).
- **memory**: Permite a los agentes usar `set_memory` y `delete_memory` cuando la memoria está configurada y el usuario tiene acceso. Habilitado de forma predeterminada; se elimina en tiempo de ejecución cuando la memoria está desactivada.
- **ask_user_question**: Permite que los agentes hagan una pausa para realizar de una a cuatro preguntas relacionadas en un solo formulario y continuar con las respuestas. Habilitado de forma predeterminada.
- **tools**: Otorga al agente acceso a varias herramientas.
- **chain**: Habilita la función beta para el encadenamiento de agentes, también conocido como flujos de trabajo Mixture-of-Agents (MoA).
- **ocr**: Mejora opcionalmente "Subir como texto" en el chat y el "Contexto de archivo" para los agentes, permitiendo que los archivos sean subidos y procesados con OCR. **Requiere que se configure un servicio de OCR.**
- **run_in_background**: Hace que la ejecución de Code Interpreter y las herramientas de shell sean elegibles para ejecutarse en segundo plano de forma predeterminada y habilita la opción de segundo plano por herramienta para MCP, Plugins y herramientas de Action elegibles. Un interruptor a nivel de Action habilita todas las operaciones elegibles; las OAuth Actions y las operaciones que ya definen un parámetro `run_in_background` están excluidas. Un agente puede excluir explícitamente a Code Interpreter. La configuración permite la ejecución en segundo plano; el modelo decide por cada llamada si la utiliza. Requiere `execute_code` y un despliegue de Code Interpreter configurado para el código. Esta capacidad no está habilitada de forma predeterminada.
- **tool_intents**: Añade etiquetas de intención escritas por el modelo en tiempo real a las llamadas de herramientas elegibles. Las herramientas nativas, incluyendo las herramientas de Code Interpreter, se activan automáticamente; las herramientas MCP pueden habilitarse individualmente o de forma masiva en el Agent Builder. Model specs utiliza `describeIntent`. Esta capacidad no está habilitada de forma predeterminada.

Al especificar las capacidades, puedes controlar las funciones disponibles para los usuarios al interactuar con agentes.

## Ejemplo de configuración [#example-configuration]

Aquí hay un ejemplo de cómo configurar el endpoint `agents` con capacidades personalizadas y ajustes de citación de archivos:

```yaml filename="Agents Endpoint"
endpoints:
  agents:
    disableBuilder: false
    # File citation configuration
    maxCitations: 20
    maxCitationsPerFile: 5
    minRelevanceScore: 0.6
    # Custom capabilities
    capabilities:
      # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
      # - 'programmatic_tools'
      - 'execute_code'
      # Optional: makes Code Interpreter background-eligible and enables selected MCP, Plugin, and Action tools.
      # - 'run_in_background'
      # Optional: enables live intent labels for native and selected MCP tools.
      # - 'tool_intents'
      - 'file_search'
      - 'skills'
      - 'subagents'
      - 'actions'
      - 'artifacts'
      - 'context'
      - 'ocr'
      - 'web_search'
```

En este ejemplo:

- La interfaz del constructor está habilitada
- Las citas de archivos están limitadas a un total de 20, con un máximo de 5 por archivo
- Solo se incluyen las fuentes con una relevancia del 60% o superior
- Los agentes de LibreChat tienen acceso a ejecución de código, búsqueda de archivos (con citas), Skills, Subagentes, acciones, artefactos, contexto de archivos, servicios de OCR si están configurados, y capacidades de búsqueda web.
- La invocación de herramientas programática permanece deshabilitada a menos que añada la capacidad `programmatic_tools` junto con `execute_code`
- Las llamadas a herramientas en segundo plano permanecen deshabilitadas a menos que añadas `run_in_background`; las herramientas de Code Interpreter se vuelven elegibles por defecto, mientras que las herramientas MCP, Plugin y Action elegibles aún requieren selección.
- Las etiquetas de intención de herramientas permanecen desactivadas a menos que añadas `tool_intents`; las herramientas nativas se activan automáticamente, mientras que las herramientas MCP aún requieren una selección por herramienta.

## managementApi

La API de gestión de agentes en beta permite a clientes de máquina de confianza crear, listar, leer, actualizar y eliminar agentes, gestionar sus archivos y descubrir o editar habilidades accesibles. Es independiente de [`remoteApi`](#remoteapi): las rutas de gestión solo aceptan identidades de máquina OIDC vinculadas a la implementación y no aceptan claves de API de LibreChat Remote Agents ni sesiones de navegador.

```yaml filename="endpoints / agents / managementApi"
endpoints:
  agents:
    managementApi:
      auth:
        oidc:
          enabled: true
          issuer: https://identity.example.com/
          audience: https://librechat.example.com/agents
          # jwksUri: https://identity.example.com/.well-known/jwks.json
        clients:
          - clientId: machine-client-id
            # subject: provider-specific-service-principal-subject
            userId: 507f1f77bcf86cd799439011
            tenantId: tenant-id
            enabled: true
```

## Notas [#notes]

- No se recomienda deshabilitar la interfaz del generador a menos que esté utilizando [modelSpecs](/docs/configuration/librechat_yaml/object_structure/model_specs) para definir una lista de agentes para elegir.
- La configuración de citas de archivos (`maxCitations`, `maxCitationsPerFile`, `minRelevanceScore`) solo se aplica cuando la capacidad `file_search` está habilitada.
- La puntuación de relevancia se calcula utilizando similitud vectorial, donde 1.0 representa una coincidencia perfecta y 0.0 representa ninguna similitud.
- Los límites de citas ayudan a equilibrar la recuperación integral de información con la calidad y el rendimiento de la respuesta.
- La capacidad `context` funciona sin configuración de OCR utilizando métodos de análisis de texto. El OCR mejora la calidad de la extracción cuando está configurado.
- La capacidad `ocr` requiere que se configure un servicio de OCR (consulte [Configuración de OCR](/docs/configuration/librechat_yaml/object_structure/ocr)).
- `maxSubagents` limita cuántos subagentes puede referenciar un solo agente. No cambia los límites de profundidad o de grafo documentados en [Subagents](/docs/features/subagents#limits).
