      'destination',

      '',
    ],
  ]}
/>

**Settings → Langfuse** または権限のある管理者設定クライアントを通じて接続フィールドを管理します。設定フローは接続を検証し、`projectId` を導出します。権限のある管理者は `secretKey` を暗号化して書き込み、`secretKeyPreview` を生成し、読み取り時にシークレットを編集（redact）します。`librechat.yaml` に直接配置されたプレーンテキストの `secretKey` 値は、ランタイムの接続パスでは受け入れられません。レガシーな `displaySecretKey` および `fanout.enabled` フィールドは、スキーマの一部ではなくなりました。

`headers` は異なります。これはデプロイメントインフラストラクチャであり、`librechat.yaml` でのみ設定可能です。管理者設定による書き込みでは、マップ全体および個別のヘッダーパスの両方が拒否されるため、ゲートウェイの認証情報はMongoベースの設定を通じて保存または返されることはありません。値は `${ENV_VAR}` の補間をサポートしています。リテラルの代わりに環境変数の参照を使用してください。LibreChatは、解決できない変数、保護されたインフラストラクチャのシークレット参照、空の値、および無効なHTTPヘッダー名を警告とともに破棄します。

カスタムヘッダーは、デプロイメントが正確に1つのLangfuseオリジンを解決する場合にのみ、トレースおよびメディアのエクスポート、フィードバックスコアのリクエスト、プロジェクトの検索、および管理者資格情報の検証時に送信されます。central、tenant、またはcollectorの設定によって複数のオリジンが生成される場合、LibreChatはカスタムヘッダーを送信せず、マップが受信者を安全に特定できないため警告をログに記録します。これらにはユーザーごとの `{{...}}` プレースホルダーを使用することはできず、ファンアウトコレクターは `Authorization` のみをアップストリームに転送します。

```yaml filename="langfuse / headers"
langfuse:
  headers:
    CF-Access-Client-Id: '${CF_ACCESS_CLIENT_ID}'
    CF-Access-Client-Secret: '${CF_ACCESS_CLIENT_SECRET}'
```

`langfuse` はベース設定専用のセクションです。ロール、グループ、およびユーザー設定のオーバーライドによって置き換えたり、無効化（tombstone）したりすることはできません。

利用可能性ルール、認証済みプロキシ設定、環境管理された認証情報、およびオプションのファンアウトデプロイメントについては、[Langfuse Configuration](/docs/configuration/langfuse) を参照してください。

## fileStrategy

- **Options**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategy',
      'String',
      'ユーザーがアップロードまたは生成したファイルの保存先を決定します。省略された場合は `"local"` がデフォルトとなります。',
      'fileStrategy: "firebase"',
    ],
  ]}
/>

- **注記**:
  - `"cloudfront"` はファイルをS3に保存し、安定したメディア配信、署名付きCookie、および署名付きダウンロードのためにCloudFront URLを返します。
  - `"firebase"` は、Firebase Storage および Firebase Hosting のエッジロケーションを通じてファイルを配信します。
  - S3は、有効期限のある**署名付きURL**（一時的な署名トークン）を介してファイルを配信します。有効期限が切れると、そのURLを参照している画像やアバターはUI上で表示されなくなります。このため、S3はビジュアルアセットの主要な保存先としては適していません。詳細については、[関連するディスカッション](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903)を参照してください。
  - 画像やアバターのパフォーマンスを最適化するには、`"cloudfront"` または `"firebase"` を使用するか、`fileStrategies` を設定して `avatar` および `image` をCDNベースの戦略にルーティングしてください。
  - セットアップの詳細については、[File Storage & CDN documentation](/docs/configuration/cdn) を参照してください。

- **利用可能な戦略**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

**サブキー:**

<OptionTable
  options={[
    [

      'String',
      '特定のタイプが定義されていない場合のフォールバックストレージ戦略。デフォルトは "local" です。',
      '',
    ],
    [
      'avatar',
      'String',
      'ユーザーおよびエージェントのアバター画像のストレージ戦略。パフォーマンスを最適化するため、CDNを利用した戦略（`"cloudfront"` または `"firebase"`）の使用を推奨します。',
      '',
    ],
    [
      'image',
      'String',
      'チャットでアップロードされた画像のストレージ戦略。パフォーマンスを最適化するため、CDNを利用した戦略（`"cloudfront"` または `"firebase"`）の使用を推奨します。',
      '',
    ],
    ['document', 'String', 'ドキュメントアップロード（PDF、テキストファイルなど）のストレージ戦略。', ''],
    ['skills', 'String', 'Skillsにバンドルされたファイルのストレージ戦略', ''],
  ]}
/>

- **注記**:
  - この設定は、単一の `fileStrategy` オプションよりも優先されます。
  - 特定のファイルタイプが設定されていない場合、`default`、次に `fileStrategy`、最後に `"local"` へとフォールバックされます。
  - 画像やアバターがUI全体で正しくレンダリングされるためには、永続的で安定したURLが必要です。S3の署名付きURLは期限切れになるため（AWSの制限：IAMユーザーの場合は最大7日間、STS/ロールベースの認証情報の場合は数時間）、モデルセレクターやチャットUIで画像が壊れて表示される原因となります。詳細については、[関連するディスカッション](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903)を参照してください。これを回避するには、`avatar`および`image`の設定に `"cloudfront"` または `"firebase"` を使用してください。
  - S3 および Azure Blob Storage は、短期間有効な署名付きダウンロード URL が適している `document` ストレージに最適です。
  - 各ストレージプロバイダーの設定詳細については、[File Storage & CDN documentation](/docs/configuration/cdn) を参照してください。

**例:**

```yaml filename="fileStrategies - All in one place"
# Use a single strategy for all file types
fileStrategies:
  default: 's3'
```

```yaml filename="fileStrategies - Mixed strategies"
# Route images and avatars to CDN, keep documents in object storage
fileStrategies:
  avatar: 'cloudfront' # CDN delivery for avatars
  image: 'cloudfront' # CDN delivery for generated/uploaded images
  document: 's3' # Object storage for documents
```

```yaml filename="fileStrategies - Partial configuration"
# Only configure specific types, others use default
fileStrategies:
  default: 'local'
  avatar: 'firebase' # Only avatars use Firebase CDN, everything else is local
```

## secureImageLinks

<OptionTable
  options={[
    [
      'secureImageLinks',
      'Boolean',
      'アプリによってローカルホストされた画像リンクには認証が必要です。デフォルト: true。',
      'secureImageLinks: true',
    ],

/>

このフィールドが省略された場合、ローカル画像は保護されます。プライベートな会話の画像には、アクティブなセッションと所有者のアクセス権が必要です。保存されたユーザーアバターには、同じテナント内の認証済み閲覧者が必要です。エージェントのアバターは、公開設定を含むエージェントの閲覧ACLに従いますが、アシスタントのアバターには、同じテナントに加え、有効なendpoint共有またはアシスタント管理ポリシーが必要です。認可および設定の検索に失敗した場合は、アクセスを拒否（fail closed）します。

`secureImageLinks: false` は、認証なしでローカル画像URLを意図的に公開するデプロイメント向けの互換性オプトアウトとしてのみ設定してください。ロールおよびユーザー設定のオーバーライドは、画像所有者の有効な設定から解決されます。

**説明:**

`clientImageResize` 設定は、アップロード前のクライアントサイドでの縮小を制御します。この機能は以下に役立ちます：

- **アップロードの失敗を防ぐ**（サーバーの制限を超える大きな画像ファイルが原因の場合）
- **帯域幅の使用量を削減**するために、送信前に画像を圧縮します
- **アップロードパフォーマンスを向上させる**（ファイルサイズを小さくする）
- ファイルサイズを最適化しつつ、**画質を維持する**

リサイズが有効な場合、`maxWidth` または `maxHeight` を超えるサポート対象の画像は、アップロード前にブラウザ側で縮小されます。LibreChatはアスペクト比を維持し、小さい画像を拡大することは決してありません。また、エンコード後の結果が元のファイルより小さくならない場合は、元のファイルを保持します。

`enabled` が省略された場合、ユーザーは **設定 > チャット** から **アップロード前に画像をリサイズ** のオン/オフを切り替えることができます。この設定はブラウザに保存され、デフォルトはオフです。`librechat.yaml` で `enabled: true` または `enabled: false` を設定すると、すべてのユーザー設定が上書きされ、トグルが無効になります。

**例:**

```yaml filename="clientImageResize"
fileConfig:
  clientImageResize:
    # Omit enabled so each user can choose under Settings > Chat.
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

デプロイメントに対して特定の動作を強制するには、同じブロックに `enabled: true` または `enabled: false` を追加してください。

**注記:**

- リサイズパイプラインは、必要なCanvas APIを備えたブラウザにおいて、JPEG、PNG、およびWebPをサポートしています。
- アニメーション付きのPNGおよびWebPファイルは変更されずに送信されるため、リサイズによってアニメーションが破棄されることはありません。
- 出力はソース形式を維持します。`compressFormat` 設定はありません。
- ブラウザのエンコーダーは、PNGのようなロスレス形式の場合、`quality`を無視することがあります。
- リサイズに失敗した場合は元のファイルにフォールバックされます。通常のサーバーアップロード制限は引き続き適用されます。

**キー:**

<OptionTable

    [

      'Object',
      'Model Context Protocol (MCP) サーバーの構成を定義し、アプリケーション内での MCP サーバーの動的な統合を可能にします。',
      '',
    ],

**サブキー:**

<OptionTable
  options={[
    [
      '<serverName>',
      'Object',
      '`mcpServers` 配下の各キーは、一意の名前で識別される個別の MCP サーバー設定を表します。',
      '',
    ],
  ]}
/>

- **注記**:
  - 初期化は起動時に行われるため、変更を反映させるにはアプリを再起動する必要があります。
  - `<serverName>` は、各 MCP サーバー設定の一意の識別子です。
  - 各MCPサーバーは、4つの接続タイプのいずれかを使用して設定できます：
    - `stdio`
    - `websocket`
    - `sse`
    - `streamable-http`
  - `type` フィールドは、MCP サーバーへの接続タイプを指定します。
  - `type` が省略された場合、`url` または `command` の有無と形式に基づいてデフォルト値が設定されます。
    - `url` が指定されており、かつ `http` または `https` で始まる場合、`type` はデフォルトで `sse` になります。
    - `url` が指定されており、かつ `ws` または `wss` で始まる場合、`type` はデフォルトで `websocket` になります。
    - `command` が指定されている場合、`type` はデフォルトで `stdio` になります。
  - その他の設定オプションには以下が含まれます：
    - `timeout`: MCPサーバーリクエストのタイムアウト時間（ミリ秒）。ツールリクエストに対する応答を待機する時間を決定します。
    - `initTimeout`: MCPサーバーの初期化に対するミリ秒単位のタイムアウト。サーバーの初期化を待機する時間を決定します。
    - `serverInstructions`: エージェントのコンテキストにサーバーの指示を含めるかどうかを制御します。`true`（サーバー提供のものを使用）、`false`（無効）、またはカスタム文字列（サーバー提供のものを上書き）を指定できます。
    - `customUserVars`: (オプション) 個々のユーザーがMCPサーバーに対して設定できるカスタム変数（APIキーやURLなど）を定義します。UIを通じて提供されるこれらのユーザーごとの値は、サーバーの `headers` または `env` 設定内で `{{VARIABLE_NAME}}` 構文を使用して参照できます。これにより、MCPツールに対してユーザーごとの認証やカスタマイズが可能になります。
  - 参照: [MCP Servers Object Structure](/docs/configuration/librechat_yaml/object_structure/mcp_servers)

**例:**

```yaml filename="mcpServers"
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
    timeout: 30000
    initTimeout: 10000
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    timeout: 30000
    initTimeout: 10000
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-example:
    type: streamable-http
    url: https://example.com/mcp
    headers:
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
  per-user-crendentials-example:
    type: sse
    url: 'https//some.mcp/sse'
    headers:
      X-Custom-Auth-Token: '{{USER_API_KEY}}' # Placeholder for the user-provided API key, defined in `customUserVars` below.
    customUserVars:
      USER_API_KEY:
        title: 'Service API Key'
        description: "Your personal API key for this service. You can get it <a href='https://example.com/api-keys' target='_blank'>here</a>."
    serverInstructions: true
```
