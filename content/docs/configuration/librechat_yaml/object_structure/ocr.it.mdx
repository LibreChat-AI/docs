## Panoramica [#overview]

L'oggetto `ocr` ti consente di configurare le impostazioni di Optical Character Recognition (OCR) per l'applicazione, abilitando l'estrazione di testo dalle immagini. Questa sezione fornisce un'analisi dettagliata della struttura dell'oggetto `ocr`.

Ci sono 5 campi sotto `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Note:**

- L'OCR è attivo solo quando `librechat.yaml` contiene una sezione `ocr`. Impostare `OCR_API_KEY` da solo non lo attiva. Per l'API ospitata di Mistral, sono sufficienti `strategy: "mistral_ocr"` e `OCR_API_KEY` nel file `.env`, poiché `apiKey` e `baseURL` assumono per impostazione predefinita `${OCR_API_KEY}` e `${OCR_BASEURL}` (oppure `https://api.mistral.ai/v1` se quest'ultima non è impostata).
- OCR viene eseguito sui file aggiunti come testo: Upload as Text nella chat e File Context nell'Agent Builder. Anche gli agenti necessitano della capacità `ocr` in `endpoints.agents.capabilities`, che è inclusa per impostazione predefinita. Senza di essa, una strategia OCR configurata rifiuta il caricamento con il messaggio "OCR capability is not enabled for Agents".
- Quali tipi di file vengono inviati all'OCR è controllato da [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr).
- La strategia predefinita è `mistral_ocr`. Quando `mistralModel` è vuoto, viene utilizzato `mistral-ocr-latest`.
- I modelli Mistral OCR distribuiti su Azure possono essere utilizzati impostando la strategia su `azure_mistral_ocr`.
- I modelli Mistral OCR distribuiti su Google Vertex AI possono essere utilizzati impostando la strategia su `vertexai_mistral_ocr`.
  - Richiede che la variabile d'ambiente `GOOGLE_SERVICE_KEY_FILE` sia impostata con le credenziali dell'account di servizio
  - La service key può essere fornita come: percorso del file, URL, stringa JSON codificata in base64 o stringa JSON non elaborata
  - L'ID del progetto e la posizione vengono estratti automaticamente dalle credenziali dell'account di servizio
- L'estrazione del testo in locale è disponibile tramite `document_parser`, che estrae il testo da file PDF, DOCX, XLS/XLSX, ODT e ODS fino a 15 MB senza alcuna API esterna.
  - Utilizza `pdfjs-dist`, `mammoth` e `SheetJS` in locale, senza bisogno di una chiave API o di un URL base
  - Solo il campo `strategy` è obbligatorio; `apiKey`, `baseURL` e `mistralModel` vengono ignorati
- `custom_ocr` è accettato dallo schema ma non ha ancora un'implementazione.
- Il parsing delle variabili d'ambiente è supportato per i parametri `apiKey`, `baseURL` e `mistralModel`.

## Analisi automatica dei documenti (nessuna configurazione richiesta) [#automatic-document-parsing-no-configuration-required]

Il `document_parser` integrato viene eseguito automaticamente per i caricamenti di file degli agenti **anche quando non è configurato alcun blocco `ocr`** nel tuo `librechat.yaml`. Ciò significa che i file PDF, DOCX, XLS/XLSX e ODS vengono analizzati immediatamente senza alcuna configurazione.

La logica di risoluzione funziona come segue:

1. **Nessuna configurazione `ocr` presente**: Quando un file di contesto dell'agente viene caricato e il suo tipo MIME corrisponde a un tipo di documento supportato (PDF, DOCX, Excel, ODS), viene utilizzato direttamente il `document_parser`. Non è necessario alcun controllo della capacità OCR per l'agente.

2. **`ocr` config esiste**: La strategia configurata (ad esempio `mistral_ocr`) viene provata per prima. Se la strategia configurata **fallisce durante l'esecuzione**, viene utilizzato `document_parser` come soluzione di riserva, in modo che l'estrazione del testo abbia comunque successo per i tipi di documento supportati.

3. **Nessuna delle due riesce**: se sia la strategia configurata sia il parser del documento falliscono (ad esempio, il file è un PDF contenente solo immagini senza testo incorporato), viene restituito un errore che suggerisce la necessità di un servizio OCR.

<Callout type="info">
Il `document_parser` gestisce solo documenti basati su testo. Per PDF basati su immagini o documenti scansionati, è comunque necessaria una strategia OCR configurata (come `mistral_ocr`) per estrarre il testo dalle immagini all'interno di quei file.
</Callout>

## Esempio [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Esempio con Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Esempio con Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Per Vertex AI, distribuisci un modello Mistral OCR nel tuo progetto Google Cloud, crea un account di servizio in grado di chiamare l'endpoint Vertex AI e imposta `GOOGLE_SERVICE_KEY_FILE` in modo che punti alla sua chiave. La variabile accetta un percorso di file, un URL da cui recuperare la chiave, JSON codificato in base64 oppure la stringa JSON grezza:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Esempio con parser di documenti locale (nessuna API esterna necessaria):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Eccezioni host:porta privati attendibili per i controlli SSRF al momento della connessione OCR. Le destinazioni pubbliche rimangono disponibili. Le voci richiedono una porta e non possono essere URL, percorsi, intervalli CIDR, host semplici o letterali IP pubblici.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

Le richieste OCR bloccano le destinazioni private, di loopback, link-local e i metadati cloud al momento della connessione e disabilitano i reindirizzamenti. `allowedAddresses` è un elenco di esenzione per target `host:port`, `private.ip:port` o `[ipv6]:port` privati attendibili ed esatti; non limita l'accesso alle destinazioni pubbliche.

<Callout type="warning" title="Gestisci le eccezioni di attendibilità con cautela">
  Usa `allowedAddresses` solo per un servizio OCR privato che controlli. Un hostname esentato si fida di qualsiasi indirizzo privato a cui viene risolto su quella porta, quindi preferisci un indirizzo IP privato letterale quando possibile. Con un forward proxy, il proxy deve applicare la policy SSRF di destinazione; le destinazioni private letterali rimangono bloccate a meno che non siano esplicitamente esentate.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'La strategia OCR da utilizzare.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Strategie disponibili:**

- `mistral_ocr`: Utilizza l'OCR di Mistral tramite la normale API di Mistral.
- `azure_mistral_ocr`: Utilizza i modelli OCR di Mistral distribuiti su Azure AI Foundry. Imposta `mistralModel` con il nome della tua distribuzione e `baseURL` con l'endpoint della distribuzione.
- `vertexai_mistral_ocr`: Utilizza i modelli Mistral OCR distribuiti su Google Cloud Vertex AI, autenticati tramite `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Utilizza l'estrazione di testo locale per file PDF, DOCX, XLS/XLSX e OpenDocument. Non è richiesta alcuna API esterna. Viene inoltre eseguito automaticamente per i caricamenti di file degli agenti quando non è presente alcuna configurazione `ocr` e come fallback quando una strategia OCR configurata fallisce.
- `custom_ocr`: Riservato a un servizio OCR personalizzato su `baseURL`. Non ancora implementato.
