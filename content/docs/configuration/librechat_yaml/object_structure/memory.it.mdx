## Panoramica [#overview]

L'oggetto `memory` attiva la [Memoria utente](/docs/features/memory) e ne imposta i limiti. Aggiungere la sezione è ciò che abilita la memoria: le voci salvate vengono quindi aggiunte alle conversazioni di ciascun utente, gli utenti possono gestirle nel pannello Memorie e lo strumento Memoria (`set_memory` e `delete_memory`) viene offerto nelle chat e negli agenti, purché la funzionalità `memory` sia abilitata per l'endpoint degli agenti (lo è per impostazione predefinita).

L'estrazione automatica della memoria, in cui un agente di memoria separato esamina ogni scambio e salva i fatti senza che venga richiesto, è un'opzione separata che va attivata esplicitamente: impostare `agent.enabled: true` e assegnarle un modello.

## Esempio [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Configura l\'agente di memoria automatico opzionale. Può essere un riferimento a un agente esistente tramite ID o una configurazione completa dell\'agente.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],

/>

Configura l'agente di memoria automatica. Viene eseguito solo quando `enabled` è `true`; un blocco `agent` senza `enabled` viene ignorato e LibreChat registra un avviso all'avvio.

Quando abilitato, l'agente di memoria viene eseguito all'inizio di ogni richiesta di chat, in parallelo alla risposta principale. Esamina gli ultimi `messageWindowSize` messaggi (limitati a `maxInputTokens`) e salva o elimina autonomamente le voci. Ha tempo fino al completamento della risposta principale più un massimo di 3 secondi; se è ancora in esecuzione dopo tale limite, il suo risultato viene scartato per quella richiesta.

Il campo `agent` supporta due diversi formati di configurazione:

### Agent per ID [#agent-by-id]

Quando hai un agente preconfigurato, puoi farvi riferimento tramite il suo ID:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Configurazione Agente Personalizzato [#custom-agent-configuration]

Per un maggiore controllo, puoi definire una configurazione completa dell'agente:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Esempio di configurazione completa [#complete-configuration-example]

Un esempio che utilizza ogni opzione di memoria:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Utilizzo di endpoint personalizzati [#using-custom-endpoints]

La funzionalità di memoria supporta gli endpoint personalizzati. Quando si utilizza un endpoint personalizzato, il campo `provider` deve corrispondere esattamente al `name` dell'endpoint personalizzato. Le intestazioni personalizzate con variabili d'ambiente e segnaposto utente vengono risolte correttamente.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- Vedi [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) per tutti i segnaposto disponibili

## Note [#notes]

- `personalize` controlla se gli utenti possono disattivare la funzione, non se la memoria è attiva. Usa `disabled` per disattivare la memoria.
- `maxInputTokens` limita il contesto della chat inviato all'agente di memoria automatica, mentre `tokenLimit` limita la dimensione totale delle memorie archiviate.
- Le `instructions` personalizzate sostituiscono le istruzioni predefinite per la memoria e sono utili principalmente in combinazione con `validKeys`.
- L'accesso è controllato anche per ruolo tramite le autorizzazioni della memoria (utilizzo, creazione, lettura, aggiornamento, rinuncia). Vedi [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), il [Pannello di amministrazione](/docs/features/admin_panel), oppure le impostazioni di amministrazione in fondo al pannello Memorie.

## Risoluzione dei problemi [#troubleshooting]

**La memoria non fa nulla.** Verifica che la sezione `memory` esista e che `disabled` non sia `true`, che il ruolo dell'utente abbia il permesso di usare le memorie e che l'utente non abbia disattivato **Reference saved memories**. Per lo strumento Memory, la capacità `memory` deve essere presente nell'elenco `capabilities` dell'endpoint agents, se ne hai impostato uno.

**Nulla viene salvato automaticamente.** L'estrazione automatica richiede `agent.enabled: true` e un `id` valido, oppure `provider` e `model`. Senza questi, le voci vengono salvate solo quando un utente chiede al modello di ricordare qualcosa con lo strumento Memory attivo, oppure vengono aggiunte manualmente.

**L'agente di memoria non funziona su un endpoint personalizzato.** `provider` deve corrispondere esattamente al `name` dell'endpoint personalizzato. Verifica prima che l'endpoint funzioni per le normali chat, poi controlla che le variabili d'ambiente a cui fanno riferimento le sue intestazioni siano impostate; i segnaposto delle intestazioni vengono risolti allo stesso modo per la memoria e per la chat.

**Il consumo di token è elevato.** Riduci `maxInputTokens` o `messageWindowSize` per inviare meno chat all'agente di memoria, riduci `tokenLimit` per mantenere piccole le memorie salvate (che vengono aggiunte a ogni richiesta) e limita `validKeys`.
