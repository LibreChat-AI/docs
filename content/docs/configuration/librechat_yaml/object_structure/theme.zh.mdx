## 概述 [#overview]

`interface.theme` 用于设置部署的主题：即所有用户在亮色和暗色模式下所看到的颜色、形状、排版、阴影和动态效果。它既可以接受 LibreChat 内置的主题名称，也可以接受内联的主题定义。

<Callout type="info" title="可用性">
  `interface.theme` 以及本页面描述的外观缩放功能目前仅存在于 LibreChat 的 `canary` 分支中，尚未包含在任何已发布的版本中。
</Callout>

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

当 `interface.theme` 未设置时，LibreChat 的行为与之前保持一致：用户将看到默认的 LibreChat 主题，或者适用于他们的任何构建时颜色或已存储的主题。

本页面涵盖了操作员在 `librechat.yaml` 中设置的内容。主题引擎本身（包括完整的令牌列表以及每个令牌如何映射到 Tailwind 工具类）记录在 LibreChat 仓库的 [theme README](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/client/src/theme/README.md) 中。

## 主题的选择方式 [#how-the-theme-is-chosen]

客户端会选择一个主题，优先级最高者优先：

1. **高对比度模式。** 选择 `high-contrast-light` 或 `high-contrast-dark` 的用户，或者系统设置解析为高对比度的用户，将始终获得内置的无障碍调色板。
2. 来自 `librechat.yaml` 的 **`interface.theme`**。
3. **`REACT_APP_THEME_*`** 构建时颜色。请参阅 [Theme Colors](/docs/configuration/dotenv#theme-colors)。
4. **用户浏览器中存储的主题**。

部署主题设置了颜色、形状、字体、阴影和动画，但不会设置模式：每个用户仍然可以自行选择浅色、深色或系统模式。

部署主题永远不会写入用户的浏览器存储。如果您移除 `interface.theme`，用户将恢复使用他们自己存储的主题（或者在构建设置了 `REACT_APP_THEME_*` 颜色时使用这些颜色）。

该主题是预登录配置的一部分，因此登录和注册页面已经应用了该主题。

### 共享链接 [#shared-links]

共享链接会呈现拥有该链接的租户的主题，而不是查看者的主题。如果拥有该链接的租户未设置 `interface.theme`，或者其共享链接配置加载失败，则共享页面将不显示任何部署主题，而不是回退到查看者的主题。离开共享页面后，查看者的主题将恢复。

## 内置主题 [#bundled-themes]

| 名称 | 主题 |
| --- | --- |
| `librechat` | 默认的 LibreChat 配色方案和形状。显式设置此项也会覆盖 `REACT_APP_THEME_*` 颜色以及用户存储的主题。 |
| `clickhouse` | 基于 ClickHouse 的 Click UI 设计令牌构建的参考主题。请参阅 [ClickHouse theme](#clickhouse-theme)。 |

如果名称不属于上述列表，则会被忽略：服务器会记录该日志并丢弃 `interface.theme`（参见 [Validation](#validation)），应用将回退到上述列表中的下一个来源。

### ClickHouse 主题 [#clickhouse-theme]

`interface.theme: clickhouse` 同时改变颜色和形状：

- **调色板 (Palette)。** 每个颜色标记都在 Click UI 的浅色和深色标记模式中进行了定义，因此不会回退到 LibreChat 的调色板。部分数值已根据 Click UI 的色阶进行了调整，以修正原数值未达到 WCAG AA 对比度标准的问题。
- **强调色 (Accent)。** 浅色模式下为接近黑色的 `#151515`，深色模式下为 ClickHouse 黄色 `#faff69`，用于强调色和提交按钮。焦点环使用 Click UI 的轮廓颜色：浅色模式下为蓝色 `#437eef`，深色模式下为 `#faff69`。
- **按钮。** 主按钮在浅色模式下为 `#302e32`，在深色模式下为 `#faff69`，并带有 Click UI 的悬停效果。
- **Radii.** 采用 Click UI 的 `border.radii` 中更为紧凑的比例：控件、菜单、工具提示、标签页以及 `sm` 到 `lg` 为 `0.25rem`；界面以及 `xl`/`2xl` 为 `0.5rem`；大型界面以及 `3xl` 为 `0.75rem`。
- **阴影。** 点击 UI 在每个凸起表面、菜单和拖拽项目上使用单一高度阴影，在浅色模式下不透明度为 0.15，在深色模式下为 0.6，对于 `2xs` 到 `sm` 级别使用细线阴影。工具提示（Tooltips）没有阴影。
- **控件。** 按钮和字段高度为 2rem，控件内边距为 `1rem`，图标间距为 `0.5rem`，标签字重为常规 (`400`)。字段为填充式 (`fieldFillStyle: fill`)，并在聚焦时切换边缘颜色 (`fieldFocusStyle: border`)；标签大小为 `0.75rem`，字重为 `500`。禁用状态的控件使用 `fill` 样式及其各自的禁用颜色，开关大小为紧凑的 2rem x 1rem，表格行具有 1px 的分割线。
- **对话框。** 1px 边框，`2rem` 侧边内边距，标题字号为 `1.25rem`，字重为 `700`，使用 Inter 字体栈。所有对话框遮罩的不透明度均为 0.75。
- **字体。** UI 字体保持为 Inter。代码使用 Click UI 的等宽字体栈：`"Inconsolata", Consolas, "SFMono Regular", monospace`；LibreChat 内置了 Inconsolata。标题优先使用 Basier Square，由于未内置该字体，除非查看者已安装，否则将以 Inter 渲染。

## 内联主题定义 [#inline-theme-definition]

`interface.theme` 不仅可以设置为名称，还可以包含一个主题定义。任何您未定义的属性都将回退到 LibreChat 在该模式下的默认值，因此定义中只需包含您想要更改的值即可。

```yaml filename="interface / theme"
interface:
  theme:
    version: 1
    name: acme
    modes:
      light:
        colors:
          rgb-accent-primary: '29 78 216'
          rgb-accent-primary-hover: '30 64 175'
          rgb-ring-primary: '29 78 216'
          rgb-surface-submit: '29 78 216'
          rgb-surface-submit-hover: '30 64 175'
          rgb-link: '29 78 216'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.2)'
      dark:
        colors:
          rgb-accent-primary: '96 165 250'
          rgb-accent-primary-hover: '147 197 253'
          rgb-ring-primary: '96 165 250'
          rgb-surface-submit: '37 99 235'
          rgb-surface-submit-hover: '29 78 216'
          rgb-link: '96 165 250'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.5)'
    brands:
      provider-openai: '#10a37f'
```

| 键 | 类型 | 描述 |
| --- | --- | --- |
| `version` | Number | 必填。必须为 `1`。 |
| `name` | String | 必填。主题的非空名称。 |
| `modes` | Object | 必填。包含 `light` 和/或 `dark`。省略的模式将使用 LibreChat 的默认设置。 |
| `modes.<mode>.colors` | Object | 该模式的颜色标记。键为 `rgb-*` 标记名称，值为 `R G B` 三元组。请参阅 [Colors](#colors)。 |
| `modes.<mode>.appearance` | Object | 该模式的形状、控件、排版、遮罩、阴影和动态值。请参阅 [Appearance](#appearance)。 |
| `modes.<mode>.brands` | Object | 该模式的提供商品牌颜色。会覆盖主题范围内的 `brands`。 |
| `brands` | Object | 两种模式的提供商品牌颜色。请参阅 [Brands](#brands)。 |

### 验证 [#validation]

当 `librechat.yaml` 加载时以及每次配置重新加载时，服务器会使用浏览器渲染前所应用的相同规则来检查 `interface.theme`。

**如果 `interface.theme` 未设置，则无效的主题将被丢弃。** 错误的 `version`、缺失的 `name`、非 `light` 或 `dark` 的模式、定义格式中不存在的字段（在顶层，如 `css`，或在模式内部，除 `colors`、`appearance` 和 `brands` 之外的任何内容）、未知的品牌令牌（brand token），或任何令牌的值类型错误，都会导致该主题无法使用。LibreChat 会移除 `interface.theme`，针对每个问题记录一行警告日志，并照常加载其余配置，因此主题错误绝不会导致服务器停止运行。随后，用户将获取 [How the theme is chosen](#how-the-theme-is-chosen) 中定义的下一个来源：`REACT_APP_THEME_*` 颜色或其已存储的主题，若两者皆不适用，则使用 LibreChat 的默认主题。日志将此称为默认主题：

```text
Ignoring interface.theme in /app/librechat.yaml; the default theme applies instead:
- interface.theme.modes.dark.colors.rgb-surface-primary: Invalid RGB value for rgb-surface-primary: 300 16 32
```

如果指定了一个不存在的内置主题名称，系统会以相同方式处理（`Unknown bundled theme "<name>", expected one of: librechat, clickhouse`）。

通过配置覆盖（针对 [Admin Panel](/docs/features/admin_panel#configuration-management) 中的角色、组或用户）设置的主题遵循相同的规则，但有一个区别：无效的覆盖主题会回退到 `librechat.yaml` 中的基础 `interface.theme`，而不是默认主题。这些日志行以 `[getAppConfig]` 开头，例如 `[getAppConfig] Ignoring interface.theme from a config override; the base theme applies instead:`。

`colors` 和 `appearance` 映射的工作方式与它们周围的字段不同。

**未知令牌会被忽略，其余主题设置将正常应用。** `colors` 或 `appearance` 内部如果包含当前版本 LibreChat 无法识别的键（无论是拼写错误还是在更新版本中添加的令牌），仅该键本身会失效。服务器会记录日志，并将未知的颜色从发送给浏览器的主题中剔除：

```text
interface.theme in /app/librechat.yaml names tokens this version ignores:
- interface.theme.modes.light.colors.rgb-surfce-secondary: Unknown light color token ignored: rgb-surfce-secondary
```

未知 token 仍会进行形状检查：颜色名称必须是仅包含小写字母、数字和 `-` 的纯 token，并对应一个 `R G B` 值；外观名称必须是 camelCase 格式，且对应的值不能包含 `;`、`{`、`}`、`<`、`>` 或 `url()`。任何其他情况都会导致错误，并使整个主题回退到默认设置。更改主题后请检查服务器日志，因为拼写错误的 token 只会在日志中报告。

浏览器会对接收到的主题应用相同的规则，如果仍然必须拒绝某个主题（例如当旧的缓存客户端遇到较新的服务器时），它会记录 `[DeploymentTheme] Ignoring invalid interface.theme: ...`。

### 颜色 [#colors]

颜色使用与主题引擎相同的标记名称：`rgb-` 后跟标记名称，例如 `rgb-surface-primary`、`rgb-text-primary`、`rgb-border-medium`、`rgb-accent-primary` 或 `rgb-status-error-subtle`。这 130 个标记的完整列表是 [`packages/data-provider/src/theme.ts`](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/data-provider/src/theme.ts) 中的 `themeColorTokens`，服务器和浏览器都会读取该文件，每个标记都在 [`packages/client/src/theme/types/index.ts`](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/client/src/theme/types/index.ts) 的 `IThemeRGB` 接口中进行了描述。

除了 surface、text、border、status 和 syntax 面板之外，这些角色还允许主题重新定义特定的交互状态和组件：

| 角色 | Tokens | 绘制 (Paints) |
| --- | --- | --- |
| 焦点 | `rgb-focus-outline`, `rgb-focus-control` | 整个应用中的键盘焦点轮廓，以及共享控件的焦点环 |
| 按下 | `rgb-surface-pressed`, `rgb-surface-inverted-pressed` | 中性及反色控件在按下时的状态 |
| 反色与固定 | `rgb-surface-inverted`, `rgb-surface-inverted-hover`, `rgb-text-inverted`, `rgb-surface-fixed`, `rgb-surface-fixed-hover`, `rgb-text-fixed` | 以相反模式颜色绘制的控件，以及在两种模式下保持单一颜色的控件 |
| 禁用 | `rgb-surface-disabled`, `rgb-text-disabled`, `rgb-border-disabled` | 禁用状态的控件，当 `disabledStyle` 为 `fill` 时（参见 [Appearance](#appearance)） |
| 控件边框 | `rgb-border-control` | 输入框、选择触发器和一次性代码槽的边缘，与静默分隔符分开，因为它需要 3:1 的对比度 |
| 字段 | `rgb-border-field-focus`, `rgb-field-fill`, `rgb-field-text` | 当 `fieldFocusStyle` 为 `border` 时聚焦字段的边缘（遵循 `rgb-focus-control`），当 `fieldFillStyle` 为 `fill` 时字段的填充（遵循 `rgb-surface-primary`），以及输入的文本值（遵循 `rgb-text-primary`） |
| 主按钮 | `rgb-button-primary`, `rgb-button-primary-hover` | 主按钮的填充和悬停状态；遵循 `rgb-surface-inverted` 和 `rgb-surface-inverted-hover`，复选框和开关也会持续使用这些值 |
| 墨色 | `rgb-dialog-title`, `rgb-badge-label` | 对话框标题和徽章标签；两者均遵循 `rgb-text-primary` |
| 遮罩 | `rgb-surface-overlay` | 对话框背后的颜色；其强度由 [Appearance](#appearance) 中的遮罩不透明度设置 |
| 媒体覆盖 | `rgb-surface-media-overlay`, `rgb-text-on-media` | 绘制在用户自身图像（灯箱、图像预览、上传进度）之上的遮罩、芯片和进度条，以及其上的文本。捆绑主题在两种模式下均保持黑白 |
| 头像 | `rgb-avatar-fill`, `rgb-avatar-text`, `rgb-avatar-placeholder`, `rgb-avatar-edge` | 默认用户头像的填充和字形（字形遵循 `rgb-text-primary`），加载中或透明智能体/助手头像背后的背景（在浅色模式下遵循 `rgb-surface-secondary`，在深色模式下遵循 `rgb-surface-tertiary`），以及默认头像周围的细线 |
| 文件磁贴 | `rgb-file-document`, `rgb-file-sheet`, `rgb-file-code`, `rgb-file-artifact`, `rgb-file-audio`, `rgb-file-video`, `rgb-file-generic`, `rgb-file-ink` | 每种文件类型对应一种填充，以及绘制在每个磁贴上的字形 |
| 插图 | `rgb-illustration-subtle`, `rgb-illustration`, `rgb-illustration-strong` | 应用内艺术作品的三种色调，例如文件拖放区的插图 |
| 开关 | `rgb-switch-unchecked`, `rgb-switch-thumb` | 未选中状态的开关轨道，以及两种状态下的旋钮 |
| 表格 | `rgb-table-header-text`, `rgb-table-header-fill` | 列名，以及粘性表头的非透明填充 |
| 图表序列 | `rgb-series-1` 到 `rgb-series-8` | 按顺序排列的分类图表颜色 |

每个值都是一个原始的 `R G B` 三元组，每个通道的取值范围从 `0` 到 `255`，例如 `'255 255 255'`。十六进制值和 `rgb(...)` 格式将被拒绝。请使用引号包裹该值，以便 YAML 将其读取为字符串。

当您省略某些 token 时，它们会跟随您设置的相关 token，从而使部分调色板保持连贯。例如，`rgb-text-muted` 跟随 `rgb-text-tertiary`，`rgb-surface-composer-hover` 和 `rgb-surface-pressed` 跟随 `rgb-surface-hover`，`rgb-focus-outline` 跟随 `rgb-ring-primary`，`rgb-focus-control` 跟随 `rgb-text-primary`，`rgb-border-control` 跟随 `rgb-border-light`，`rgb-switch-thumb` 跟随 `rgb-surface-primary`，`rgb-table-header-text` 跟随 `rgb-text-secondary`，以及 `rgb-table-header-fill` 跟随 `rgb-surface-dialog`。

### 外观 [#appearance]

外观值是**按模式**设置的，如果某个模式未设置这些值，则会使用下方的默认值。除了 `menuShadow` 和 `tooltipShadow` 在深色模式下更重之外，两种模式的默认值相同。若要在两种模式下更改形状，请像上面的示例一样，在 `light` 和 `dark` 下重复设置这些值。

| `tabRadius` | 标签页触发器的圆角半径 | `0.185rem` |
| `radiusSm` | 应用中使用的 `rounded-sm` 步长 | `calc(0.5rem - 4px)` |

默认设置会重现 LibreChat 的外观，因此如果不设置这些键中的任何一个，主题将不会改变任何形状。

接受的值：

- **Radii、`controlHeight`、`controlPaddingX`、`controlGap`、按钮和字段大小、间距、文本和标签大小，以及对话框长度（`dialogStroke`、`dialogPaddingX`、`dialogHeaderGap`、`dialogTitleSize`）：** `0`，或以 `px`、`rem` 或 `em` 为单位的数值（例如 `0.25rem`），或两个此类长度的单个 `calc()` 计算值（例如 `calc(0.5rem - 2px)`）。
- **`switchWidth` 和 `switchHeight`：** 以 `px` 或 `rem` 为单位的正数长度。两者必须使用相同的单位（如果省略其中一个，则默认使用 `rem`），宽度必须超过高度以便滑块移动，且高度必须留出 4px 的轨道边框空间（大于 `4px`，或至少 `0.5rem`）。
- **`tableCellSpaceY` 和 `tableRowStroke`：** `0`，或以 `px` 或 `rem` 为单位的长度值。
- **`focusRingWidth`:** 一个以 `px` 或 `rem` 为单位的正长度值，确保焦点指示器永远不会消失。
- **`focusRingOffset`:** `0`，或以 `px` 或 `rem` 为单位的长度值，该值可以是负数（将轮廓绘制在元素边缘内部）。
- **`disabledStyle`:** `dim` 或 `fill`。
- **`fieldFocusStyle`:** `ring` 或 `border`。
- **`fieldFillStyle`:** `transparent` 或 `fill`。
- **字体粗细 (`controlFontWeight`, `dialogTitleFontWeight`):** `1` 到 `1000` 之间的整数。`labelFontWeight` 也接受 `inherit`。
- **行高（`leading*` 步长、`labelLeading` 和 `dialogTitleLeading`）：** 一个无单位的数字（例如 `1.5`）、一个除以两个数字的单个 `calc()`（例如 `calc(1.25 / 0.875)`）或一个长度值。
- **遮罩不透明度 (Scrim opacities)：**一个从 `0` 到 `1` 的数字。
- **字体族：** 任何不包含 `;`、`{` 或 `}` 的非空 `font-family` 列表。该字体必须可供浏览器使用：LibreChat 内置了 Inter、Roboto Mono 和 Inconsolata，因此任何其他字体族都必须安装在查看者的机器上，或由您的部署环境提供，否则将使用列表中的下一个字体族。
- **Shadow steps (`shadow2xs` 到 `shadow2xl`)、`menuShadow`、`tooltipShadow` 和 `elevationDrag`：** 一个具体的 `box-shadow` 列表，或 `none`。不支持 `var()`、`env()`、`attr()` 和 `url()`。
- **`elevationSurface`:** 任何不包含 `;`、`{`、`}` 或 `url()` 的非空 `box-shadow` 值。
- **Motion:** 一个以 `ms` 或 `s` 为单位的持续时间，例如 `120ms`。

所有 appearance 值都必须是字符串。请为字体粗细、行高和遮罩不透明度等数字加上引号（例如 `'500'`、`'1.5'`、`'0.8'`）；未加引号的 YAML 数字会被拒绝。

### 品牌 [#brands]

`brands` 用于重新为模型旁显示的提供商图标着色。它可以在顶层设置一次以同时应用于两种模式，也可以在 `modes.<mode>.brands` 下针对特定模式进行覆盖。

| `provider-openai` | `#19C37D` |
| `provider-openai-gpt4` | `#AB68FF` |
| `provider-openai-reasoning` | `#000000` |
| `provider-anthropic` | `#d09a74` |

## 在 LibreChat 之外使用主题 [#using-the-theme-outside-librechat]

`@librechat/client` 包将主题发布为样式表，因此构建在其组件之上的其他应用程序可以使用相同的令牌（tokens）进行渲染。请在导入 Tailwind 的样式表中导入 `@librechat/client/theme.css`：

```css filename="app.css"
@import 'tailwindcss';
@import '@librechat/client/theme.css';
```

它包含了语义颜色标记及其 Tailwind 映射、每个颜色和外观标记的默认值，以及针对 Inter、Roboto Mono 和 Inconsolata 的 `@font-face` 规则。字体文件作为 `@librechat/client/fonts/*` 包含在包中，因此应用程序的打包工具（Vite、webpack 或 esbuild）必须解析并输出它们；如果设置是在没有打包工具的情况下提供编译后的 CSS，则必须自行提供这些路径。只有在文本以某种字体渲染时，该字体才会被下载。
