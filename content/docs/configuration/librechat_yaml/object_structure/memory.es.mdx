## Descripción general [#overview]

El objeto `memory` activa la [Memoria de usuario](/docs/features/memory) y define sus límites. Añadir la sección es lo que habilita la memoria: las entradas guardadas se incorporan entonces a las conversaciones de cada usuario, los usuarios pueden gestionarlas en el panel de Memorias, y la herramienta de memoria (`set_memory` y `delete_memory`) se ofrece en los chats y en los agentes, siempre que la capacidad `memory` esté habilitada para el endpoint de agentes (lo está de forma predeterminada).

La extracción automática de memoria, en la que un agente de memoria independiente revisa cada intercambio y guarda datos sin que se le pida, es una función aparte que requiere activación explícita: establezca `agent.enabled: true` y asígnele un modelo.

## Ejemplo [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Configura el agente de memoria automático opcional. Puede ser una referencia a un agente existente por ID o una configuración de agente completa.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

Configura el agente de memoria automática. Solo se ejecuta cuando `enabled` es `true`; un bloque `agent` sin `enabled` se ignora y LibreChat registra una advertencia al iniciar.

Cuando está habilitado, el agente de memoria se ejecuta al inicio de cada solicitud de chat, en paralelo con la respuesta principal. Revisa los últimos `messageWindowSize` mensajes (limitados a `maxInputTokens`) y guarda o elimina entradas por su cuenta. Dispone de tiempo hasta que termine la respuesta principal más un máximo de 3 segundos; si sigue en ejecución después de ese plazo, su resultado se descarta para esa solicitud.

El campo `agent` admite dos formatos de configuración diferentes:

### Agente por ID [#agent-by-id]

Cuando tengas un agente preconfigurado, puedes hacer referencia a él mediante su ID:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Configuración de Agentes Personalizados [#custom-agent-configuration]

Para un mayor control, puede definir una configuración completa del agente:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Ejemplo de configuración completa [#complete-configuration-example]

Un ejemplo que utiliza todas las opciones de memoria:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Uso de endpoints personalizados [#using-custom-endpoints]

La función de memoria es compatible con endpoints personalizados. Al utilizar un endpoint personalizado, el campo `provider` debe coincidir exactamente con el `name` del endpoint personalizado. Los encabezados personalizados con variables de entorno y marcadores de posición de usuario se resuelven correctamente.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- Consulta [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) para ver todos los marcadores de posición disponibles

## Notas [#notes]

- `personalize` controla si los usuarios pueden desactivarla, no si la memoria está activada. Usa `disabled` para desactivar la memoria.
- `maxInputTokens` limita el contexto de chat enviado al agente de memoria automática, mientras que `tokenLimit` restringe el tamaño total de las memorias almacenadas.
- Las `instructions` personalizadas reemplazan las instrucciones de memoria predeterminadas y son útiles principalmente junto con `validKeys`.
- El acceso también se controla por rol mediante los permisos de memoria (usar, crear, leer, actualizar, optar por no participar). Consulta [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), el [Panel de administración](/docs/features/admin_panel), o la configuración de administrador en la parte inferior del panel de Memorias.

## Solución de problemas [#troubleshooting]

**La memoria no hace nada.** Comprueba que la sección `memory` exista y que `disabled` no sea `true`, que el rol del usuario tenga permiso para usar memorias y que el usuario no haya desactivado **Reference saved memories**. Para la herramienta de memoria, la capacidad `memory` debe estar incluida en la lista `capabilities` del endpoint de agentes si has definido una.

**Nada se guarda automáticamente.** La extracción automática necesita `agent.enabled: true` y un `id` válido, o bien `provider` y `model`. Sin ello, las entradas solo se guardan cuando un usuario pide al modelo que recuerde algo con la herramienta de memoria activada, o cuando las añade manualmente.

**El agente de memoria falla en un endpoint personalizado.** `provider` debe coincidir exactamente con el `name` del endpoint personalizado. Primero confirma que el endpoint funciona para los chats normales y, después, comprueba que las variables de entorno a las que hacen referencia sus encabezados estén definidas; los marcadores de posición de los encabezados se resuelven de la misma forma para la memoria que para el chat.

**El uso de tokens es alto.** Reduce `maxInputTokens` o `messageWindowSize` para enviar menos chat al agente de memoria, reduce `tokenLimit` para mantener pequeñas las memorias almacenadas (que se añaden a cada solicitud) y restringe `validKeys`.
