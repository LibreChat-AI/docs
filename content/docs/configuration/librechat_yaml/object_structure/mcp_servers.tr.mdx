## Örnek [#example]

```yaml filename="MCP Servers Object Structure"
# Example MCP Servers Object Structure
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
  googlesheets:
    type: sse
    url: https://mcp.composio.dev/googlesheets/some-endpoint
    requiresOAuth: true
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-API-Key: '${SOME_API_KEY}'
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
    # The “wrench” icon shows up if no icon is provided as it is the default rendering.
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-server:
    type: streamable-http
    url: https://example.com/api/
    proxy: '${MCP_PROXY_URL}'
  per-user-credentials-example:
    type: streamable-http
    url: 'https://example.com/api/'
    headers:
      X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    customUserVars:
      MY_SERVICE_API_KEY:
        title: 'My Service API Key'
        description: "Enter your personal API key for the service. You can generate one at <a href='https://myservice.example.com/developer/keys' target='_blank'>Service Developer Portal</a>."
        sensitive: true
      MY_SERVICE_PROJECT:
        title: 'Project ID'
        description: 'Enter the project ID used by this service.'
        sensitive: false
  oauth-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      authorization_url: https://example.com/oauth/authorize
      token_url: https://example.com/oauth/token
      client_id: your_client_id
      client_secret: your_client_secret
      redirect_uri: http://localhost:3080/api/mcp/oauth-example/oauth/callback
      scope: 'read execute'
  obo-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    obo:
      scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
```

<Callout type="warning" title="İşlem destekli sunucular operatör sahiplidir">
  `type: stdio` kullanan veya `command`, `args`, `env`, `cwd` ya da `stderr` gibi süreç alanlarını kullanan MCP sunucuları `librechat.yaml` içinde yapılandırılmalıdır. Yönetici yapılandırma API'si süreç destekli girdileri reddeder ve veritabanı veya temel ilke (per-principal) geçersiz kılmaları, mevcut süreç destekli bir sunucuyu değiştiremez veya kaldıramaz. Uzak MCP sunucuları normal yapılandırma geçersiz kılma önceliğini izlemeye devam eder.
</Callout>

#### `title` [#title]

- **Tür:** String (İsteğe bağlı)
- **Açıklama:** Arayüzde MCP sunucusu için özel görünen ad. Belirtilmezse, sunucu anahtar adı kullanılır.
- **Doğrulama:** Bir Unicode harfi veya rakamı ile başlamalıdır. Geriye kalan karakterler Unicode harflerini, rakamları, birleştirme işaretlerini, boşlukları, kısa çizgileri ve düz veya kıvrımlı kesme işaretlerini içerebilir.
- **Örnek:**
  ```yaml
  my-server:
    title: 'File System Access'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `description` [#description]

- **Tür:** String (İsteğe bağlı)
- **Açıklama:** Kullanıcıların amacını ve yeteneklerini anlamalarına yardımcı olmak için arayüzde görüntülenen MCP sunucusunun açıklaması.
- **Örnek:**
  ```yaml
  my-server:
    title: 'File System Access'
    description: 'Provides read/write access to local files and directories'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `type` [#type]

- **Tür:** String
- **Açıklama:** MCP sunucusuna bağlantı türünü belirtir. Geçerli seçenekler `"stdio"`, `"websocket"`, `"streamable-http"` veya `"sse"` şeklindedir. `"http"`, `"streamable-http"` için bir takma ad (alias) olarak kabul edilir.
- **Varsayılan Değer:** `url` veya `command` öğesinin varlığına ve biçimine göre belirlenir.

#### `command` [#command]

- **Tür:** String
- **Açıklama:** (`stdio` türü için) MCP sunucusunu başlatmak üzere çalıştırılacak komut veya yürütülebilir dosya.

#### `args` [#args]

- **Tür:** Dizi (Array of Strings)
- **Açıklama:** (`stdio` türü için) `command` komutuna iletilecek komut satırı argümanları. `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}` ve `{{CUSTOM_VARIABLE_NAME}}` gibi yer tutucular, tıpkı `env` içinde olduğu gibi her argümanda çözümlenir.

#### `url` [#url]

- **Tür:** String
- **Açıklama:** (`websocket`, `streamable-http` veya `sse` türü için) MCP sunucusuna bağlanılacak URL. Dinamik kullanıcı alanı yer tutucularını (`{{LIBRECHAT_USER_*}}`) ve ortam değişkeni değiştirmeyi (`${ENV_VAR}`) destekler.
- **Notlar:**
  - `sse` türü için URL, `http://` veya `https://` ile başlamalıdır.
  - `streamable-http` türü için URL, `http://` veya `https://` ile başlamalıdır.
  - `websocket` türü için URL, `ws://` veya `wss://` ile başlamalıdır.

#### `proxy` [#proxy]

- **Tür:** String (`sse` ve `streamable-http` türleri için isteğe bağlı)
- **Açıklama:** Bu uzak MCP sunucusu için giden (outbound) proxy URL'si. Değer, `${ENV_VAR}` ile ortam değişkenlerine referans verebilir.
- **Desteklenen protokoller:** `http://`, `https://`, `socks://` ve `socks5://`
- **Güvenlik notu:** `proxy` yönetici kontrollüdür. Ortam değişkenlerini çözümler, ancak `{{LIBRECHAT_USER_ID}}` veya `customUserVars` gibi kullanıcı kontrollü yer tutucuları çözümlemez.
- **Örnek:**
  ```yaml
  mcpServers:
    remote-api:
      type: streamable-http
      url: https://api.example.com/mcp
      proxy: '${MCP_PROXY_URL}'
  ```

#### `headers` [#headers]

- **Tür:** Nesne (İsteğe bağlı, `sse` ve `streamable-http` türleri için)
- **Açıklama:** İstekle birlikte gönderilecek özel başlıklar. Dinamik değer değişimi için çeşitli yer tutucu türlerini destekler.
- **Yer Tutucu Desteği:**
  - `{{LIBRECHAT_USER_ID}}`: Mevcut kullanıcının kimliği ile değiştirilecek olup çoklu kullanıcı desteğini etkinleştirir.
  - `{{LIBRECHAT_USER_*}}`: Dinamik kullanıcı alanı yer tutucuları. `*` yerine izin verilen herhangi bir alanın BÜYÜK HARFLİ sürümünü yazın.
  - `{{LIBRECHAT_OPENID_*}}`: YAML ile tanımlanan sunucular için OpenID belirteci/oturum yer tutucuları.
  - `{{LIBRECHAT_GRAPH_*}}`: YAML ile tanımlanan sunucular için Microsoft Graph belirteç (token) yer tutucuları.
  - `{{LIBRECHAT_BODY_*}}`: YAML ile tanımlanmış sunucular için mevcut `conversationId`, `parentMessageId` veya `messageId` gibi istek gövdesi yer tutucuları.
  - `{{CUSTOM_VARIABLE_NAME}}`: `customUserVars` içinde tanımlanan bir değişken için kullanıcı tarafından sağlanan değerle değiştirilir (örneğin, `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: Ortam değişkeni `ENV_VAR` değeriyle değiştirilecektir.

`{{LIBRECHAT_BODY_*}}` yer tutucuları istek kapsamlıdır (request-scoped). LibreChat, aktif çalışma için MCP bağlantısını oluşturur, bu bağlantıyı çalışma içerisindeki araç çağrılarında yeniden kullanır ve istek sona erdiğinde temizler. İstek kapsamlı sunucular kalıcı araç önbelleğinden hariç tutulur, böylece isteğe özel başlıklar ve URL'ler aktif çalışma dışında yeniden kullanılmaz. Agent Builder, tüm sunucuyu tek bir çalışma zamanı araçları seçimiyle ekler ve bir çalışma gövde değerlerini sağladıktan sonra araçlarını çözümler. OAuth'u tamamlamak yetkilendirmeyi saklar ancak bağlantıyı o istek bağlamı oluşana kadar erteler. `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}` ve `{{LIBRECHAT_GRAPH_*}}` yer tutucuları sunucuyu hala kullanıcı kapsamlı (user-scoped) yapar, ancak HTTP aktarımları, kendi başlarına yeniden bağlanmaya zorlamadan önce her araç çağrısından önce çözümlenmiş başlıkları yeniler.

`{{LIBRECHAT_BODY_PARENTMESSAGEID}}`, yerel Agent sohbetlerinde, OpenAI uyumlu Agents API isteklerinde ve eski Assistants çalıştırmalarında kök-dönüş (root-turn) üst mesajını alır. Open Responses isteklerinin uyumlu bir üst mesaj modeli yoktur, bu nedenle bu yer tutucuyu gerektiren bir sunucu bu arayüzde başarısız olur; `previous_response_id` bunun yerine ikame edilmez.

OpenID erişim ve kimlik (ID) belirteçlerinin (token) süreleri birbirinden bağımsız olarak dolar. `{{LIBRECHAT_OPENID_ACCESS_TOKEN}}` ve eski `{{LIBRECHAT_OPENID_TOKEN}}`, depolanan erişim belirteci süresini kullanırken, `{{LIBRECHAT_OPENID_ID_TOKEN}}` güncel bir ID belirteci gerektirir. Bir kimlik bilgisi belirteci mevcut değilse veya süresi dolmuşsa, LibreChat boş veya değişmez bir taşıyıcı (bearer) değeri göndermek yerine işlem yapılabilir bir `401` yeniden kimlik doğrulama hatası döndürür; yeniden denemeden önce tekrar giriş yapın. OpenID kimliği olmayan bir istek için, bu çözümlenmemiş kimlik bilgisi yer tutucularından birini içeren bir başlık tamamen atlanır. Kimlik meta verisi yer tutucuları, mevcut boş değer davranışlarını korur.

Güvenilir operatörler, oturum açmış kullanıcının canlı OpenID erişim belirtecini doğrudan YAML ile tanımlanmış uzak bir MCP sunucusuna iletebilir:

```yaml
mcpServers:
  trusted-api:
    type: streamable-http
    url: https://mcp.example.com/mcp
    headers:
      Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'
```

Doğrudan geçişi (direct passthrough) yalnızca MCP sunucusunun kullanıcının yukarı yönlü (upstream) erişim belirtecini alması konusunda güvenilir olduğu durumlarda kullanın. Açık MCP OAuth, [adına işlem yapma değişimi (on-behalf-of exchange)](#obo) ve yönetici API anahtarı kimlik doğrulaması, bu başlıktan önceliklidir. LibreChat, bağlanmadan önce canlı oturum belirtecini çözer ve bir `401` veya `403` hatasından sonra bağlantıyı bir kez yeniler. Sunucu aracı çağrısını zaten yürütmüş olabileceğinden, reddedilen aracı çağrısını otomatik olarak tekrar oynatmaz; kurtarma işlemi başarılı olduktan sonra aracı çağrısını bilinçli olarak yeniden deneyin. Belirteç yenilenemezse, kullanıcının tekrar giriş yapması gerekir.

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}`, kullanıcının yeniden kullanılabilir OpenID erişim belirtecini, on-behalf-of akışı aracılığıyla bir Microsoft Graph belirteci ile değiştirir. İstenen kapsamlar [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration) ortam değişkeninden alınır; bu değişkenin varsayılan değeri `https://graph.microsoft.com/.default` olup, kişi ve grup aramasında kullanılan `OPENID_GRAPH_SCOPES` değişkeninden ayrıdır.

- **Örnek:**
  ```yaml
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-API-Key: '${SOME_API_KEY}'
    Authorization: 'Bearer ${SOME_AUTH_TOKEN}'
  ```

#### `requestHeaders` [#requestheaders]

- **Tür:** Nesne (İsteğe bağlı, `sse` ve `streamable-http` türleri için)
- **Açıklama:** Başlıklar yalnızca aktif bir sohbet isteği için çözümlenir. `headers` ile aynı yer tutucuları kullanırlar, `headers` üzerine birleştirilirler ve her iki nesne de aynı adı tanımladığında öncelik kazanırlar.
- **Keşif davranışı:** Araç keşfi `requestHeaders` kısmını tamamen atlar, bu nedenle `{{LIBRECHAT_BODY_*}}` gibi yalnızca isteğe bağlı değerler sunucunun araç kataloğunu gizlemez. Aktif çalışma, bağlantı kurulduğunda bunları çözer ve gönderir.

```yaml
requestHeaders:
  X-Conversation-ID: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
  X-Schedule-ID: '{{LIBRECHAT_BODY_SCHEDULEID}}'
```

#### `apiKey` [#apikey]

- **Tür:** Nesne (İsteğe bağlı, `sse` ve `streamable-http` türleri için)
- **Açıklama:** MCP sunucusu için API anahtarı kimlik doğrulama yapılandırması. API anahtarı tabanlı kimlik doğrulamayı yapılandırmak için yapılandırılmış bir yol sağlar.
- **Alt anahtarlar:**
  - `source`: String (Gerekli) - API anahtarının nereden alınacağını belirtir. Seçenekler:
    - `"admin"`: API anahtarı, yönetici tarafından `key` ile yapılandırılır
    - `"user"`: API anahtarı, kullanıcı tarafından arayüz (UI) aracılığıyla sağlanır
  - `key`: String - (`source: "admin"` için) Tüm kullanıcılar tarafından paylaşılan API anahtarı değeri. `${ENV_VAR}` başvurularını destekler. `source: "admin"` ile `key` atlandığında hiçbir üstbilgi (header) gönderilmez.
  - `authorization_type`: String (Zorunlu) - API anahtarının isteklerde nasıl gönderileceği. Seçenekler:
    - `"bearer"`: `Authorization: Bearer <key>` olarak gönderilir
    - `"basic"`: `Authorization: Basic <key>` olarak gönderilir
    - `"custom"`: Özel bir başlıkta gönderilir (`custom_header` gerektirir)
  - `custom_header`: String - (`authorization_type` değeri `"custom"` olduğunda kullanılır) API anahtarı için kullanılacak başlık adı. Belirtilmediğinde varsayılan olarak `X-Api-Key` kullanılır.
- **Örnek:**

  ```yaml
  # Admin-provided API key with Bearer auth
  my-server:
    type: streamable-http
    url: https://api.example.com/mcp
    apiKey:
      source: 'admin'
      key: '${MY_SERVER_API_KEY}'
      authorization_type: 'bearer'

  # User-provided API key with custom header
  another-server:
    type: sse
    url: https://api.example.com/sse
    apiKey:
      source: 'user'
      authorization_type: 'custom'
      custom_header: 'X-API-Key'
  ```

Kullanıcı arayüzünden oluşturulan, `apiKey.source: user` kullanan paylaşımlı sunucularda, kaydedilen anahtarlar normalleştirilmiş istek hedefine bağlanır. URL yolu veya sorgusu, proxy, taşıma (transport), yetkilendirme biçimi veya başlığı ya da yapılandırılmış OAuth istemcisi/hedefi değiştirildiğinde, kullanıcıların yeni anahtarlar girmesi gerekir; eşdeğer veya yalnızca görsel değişiklikler ise anahtarları korur. Mevcut eski anahtarlar, değiştirilmemiş sınırlarında çalışmaya devam eder. Yalnızca şu anda tanımlanmış kimlik bilgisi değişkenleri, `requestHeaders` dahil olmak üzere yerine konabilir; eski, enjekte edilmiş bir oluşturulmuş ad, anahtarını yeniden kullanamaz. Yükseltme, yapılandırma yazıcıları dahil **her API replikasında** tamamlanmalıdır. Kullanıcıların ne gördüğü için bkz. [Kullanıcı arayüzünden bir sunucu oluşturma](/docs/features/mcp#create-a-server-from-the-ui).

#### `iconPath` [#iconpath]

- **Tür:** String (İsteğe bağlı)
- **Açıklama:** Araç seçim iletişim kutusunda gösterilen aracın görüntü simgesini tanımlar.

#### `chatMenu` [#chatmenu]

- **Tür:** Boolean (İsteğe bağlı)
- **Açıklama:** `false` olarak ayarlandığında sunucu sohbet oluşturucusundaki **MCP Sunucuları** bölümünden çıkarılır ve bu sunucuyu adıyla belirten sohbet istekleri reddedilir. Agent'lar bu sunucuyu kullanmaya devam edebilir; sunucuyu listeleyen bir Model Spec da kullanmaya devam edebilir.
- **Varsayılan Değer:** `true`
- **Örnek:**
  ```yaml
  mcpServers:
    internal-tools:
      command: npx
      args: ['-y', 'internal-mcp-server']
      chatMenu: false # only available in the Agent Builder
  ```

#### `serverInstructions` [#serverinstructions]

- **Tür:** Boolean veya String (İsteğe bağlı)
- **Açıklama:** MCP sunucu talimatlarının aracı bağlamına nasıl ekleneceğini kontrol eder. Sunucu talimatları, bireysel araç açıklamalarını tamamlayarak tüm MCP sunucusu için üst düzey kullanım rehberliği sağlar.
- **Seçenekler:**
  - **`undefined`** (varsayılan): Hiçbir talimat dahil edilmez
  - **`true`**: Sunucu tarafından sağlanan talimatları kullanır (eğer mevcutsa) - kapsamlı rehberliğe sahip, iyi belgelendirilmiş sunucular için idealdir
  - **`false`**: Talimatları açıkça devre dışı bırakır - bağlam belirteçlerinden (context tokens) tasarruf etmek veya araçlar kendi kendini açıklayıcı olduğunda kullanışlıdır
  - **`string`**: Özel talimatları kullanın (sunucu tarafından sağlananları geçersiz kılar) - uygulamaya özel iş akışları veya sunucu talimatlarının yetersiz kaldığı durumlar için en iyisidir
- **Varsayılan Değer:** `undefined` (talimat içermez)
- **Notlar:**
  - `serverInstructions` yapılandırıldığında ve sunucunun araçları aracı için kullanılabilir olduğunda talimatlar otomatik olarak eklenir.
  - Birden fazla sunucu, her biri aracı bağlamına talimatlar katkıda bulunabilir
  - LibreChat, sunucu tarafından bildirilen metni yapılandırılmış beyandan ayrı olarak saklar. İnceleme (inspection), `true` değerini veya operatör tarafından yazılmış bir dizgiyi değiştirmez ve önceki sürümlerden kalan Redis destekli kayıt defteri girdileri, başlatma sırasında otomatik olarak yenilenir.
- **Örnek:**

  ```yaml
  # Use server-provided instructions
  serverInstructions: true

  # Use custom instructions
  serverInstructions: |
    When using this filesystem server:
    1. Always use absolute paths for file operations
    2. Check file permissions before attempting write operations

  # Explicitly disable instructions
  serverInstructions: false
  ```

#### `env` [#env]

- **Tür:** Nesne (İsteğe bağlı, yalnızca `stdio` türü)
- **Açıklama:** Süreç başlatılırken kullanılacak ortam değişkenleri.
- **Yer Tutucu Desteği:**
  - `{{LIBRECHAT_USER_ID}}`: Mevcut kullanıcının kimliği (ID) ile değiştirilir.
  - `{{LIBRECHAT_USER_*}}`: Dinamik kullanıcı alanı yer tutucuları (örneğin, `{{LIBRECHAT_USER_EMAIL}}`).
  - `{{CUSTOM_VARIABLE_NAME}}`: `customUserVars` içinde tanımlanan bir değişken için kullanıcı tarafından sağlanan değerle değiştirilir (örneğin, `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: Sunucu tarafındaki `ENV_VAR` ortam değişkeninin değeriyle değiştirilir.

#### `timeout` [#timeout]

- **Tür:** Tamsayı (İsteğe bağlı)
- **Açıklama:** MCP sunucu istekleri, araç çağrıları dahil, için milisaniye cinsinden zaman aşımı. Negatif olmayan bir tam sayı olmalıdır.
- **Varsayılan Değer:** `60000` (60 saniye)
- **Not:** Uzun araç çağrıları hâlâ kesiliyorsa, LibreChat veya MCP sunucusunun önünde çalışan herhangi bir ters proxy'nin (nginx, Traefik vb.) zaman aşımı (timeout) ayarlarını kontrol edin.
- **Örnek:**
  ```yaml
  mcpServers:
    data-processor:
      type: streamable-http
      url: https://api.example.com/mcp
      initTimeout: 15000 # 15 seconds to connect
      timeout: 60000 # 60 seconds per tool call
  ```

#### `initTimeout` [#inittimeout]

- **Tür:** Tamsayı (İsteğe bağlı)
- **Açıklama:** MCP sunucusu başlatma işlemi için milisaniye cinsinden zaman aşımı. Negatif olmayan bir tam sayı olmalıdır. Bu değer, bir kullanıcının OAuth oturum açma işlemini tamamlamak için ne kadar süreye sahip olacağını sınırlamaz; bu süre `MCP_OAUTH_HANDLING_TIMEOUT` ile belirlenir (bkz. [OAuth geri çağırma URL'si](#oauth-callback-url)).
- **Varsayılan Değer:** `30000` (30 saniye)

#### `requiresOAuth` [#requiresoauth]

- **Tür:** Boolean (İsteğe bağlı, yalnızca uzak aktarımlar: `sse`, `streamable-http`, `websocket`)
- **Açıklama:** Bu sunucunun OAuth kimlik doğrulaması gerektirip gerektirmediği. Belirtilmezse, sunucu başlatılırken otomatik olarak algılanacaktır. İsteğe bağlı olsa da, sunucunun OAuth gerektirip gerektirmediğini biliyorsanız bu değeri açıkça ayarlamak en iyisidir.
- **Varsayılan Değer:** Belirtilmediği takdirde otomatik olarak algılanır
- **Notlar:**
  - Uzak (URL tabanlı) taşıyıcılar için geçerlidir: `sse`, `streamable-http` ve `websocket`. Kimlik doğrulaması yapılacak bir URL'ye sahip olmayan `stdio` sunucuları üzerinde hiçbir etkisi yoktur.
  - Otomatik algılama sunucu başlatma sırasında gerçekleşir, bu da başlatma süresini uzatabilir
  - Açık yapılandırma, algılamayı atlayarak başlatma performansını iyileştirir
  - Yalnızca statik bir `Authorization` başlığı (örneğin bir Bearer API anahtarı) ile korunan sunucular için `requiresOAuth: false` ayarını yapın. Otomatik algılama, sunucuyu yapılandırılmış başlıklarınız *olmadan* sorgular; bu nedenle `WWW-Authenticate: Bearer` uyarısı ile `401` yanıtı veren bir sunucu, yanlışlıkla OAuth korumalı olarak sınıflandırılabilir. Bu bayrak, söz konusu sorguyu atlar ve statik başlığınızın bağlantıyı normal şekilde doğrulamasına olanak tanır.
  - Gelişmiş bağlantı yönetimi için MCP OAuth ortam değişkenleri (`MCP_OAUTH_ON_AUTH_ERROR`, `MCP_OAUTH_DETECTION_TIMEOUT`, `MCP_OAUTH_HANDLING_TIMEOUT`, `MCP_OAUTH_FLOW_TTL`) ile çalışır

#### OAuth yenileme koordinasyonu [#oauth-refresh-coordination]

Çoklu replika dağıtımlarında, `oauthRefreshCoordination: true` token yenilemelerini paylaşılan Redis örneği üzerinden sıraya koyar. `oauthRefreshWaitTimeout`, bir replikanın yenileme sonucunu ne kadar süre bekleyeceğini, `oauthPersistenceWaitTimeout` ise yenilenmiş kimlik bilgilerinin okunabilir hale gelmesi için ne kadar süre bekleyeceğini kontrol eder; her ikisinin varsayılan değeri `15000` milisaniyedir. `oauthRefreshWaitTimeout` en fazla `30000` ile sınırlandırılır, `oauthPersistenceWaitTimeout` ise en fazla `840000` (14 dakika) kabul eder.

Koordinasyonu yalnızca her bir kopya (replica) yükseltildikten ve aynı Redis dağıtımına bağlandıktan sonra etkinleştirin. Her bir kopya üzerinde aynı değerleri kullanın, ayarı değiştirmeden önce aktif istekleri boşaltın (drain) ve kademeli dağıtım (rolling deployment) sırasında bu ayarı açıp kapatmaktan kaçının.

#### `stderr` [#stderr]

- **Tür:** String veya Integer (İsteğe bağlı, yalnızca `stdio` türü için)
- **Açıklama:** Alt sürecin `stderr` çıktısının nasıl işleneceği. Bu, Node'un [`child_process.spawn`](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options) semantiği ile eşleşir. Geçerli dize değerleri: `"pipe"`, `"ignore"`, `"inherit"`. Alternatif olarak, dosya tanımlayıcısı olarak negatif olmayan bir tam sayı kullanılabilir.
- **Varsayılan Değer:** `"inherit"` (`stderr` mesajları ana sürecin `stderr` çıktısına yazdırılacaktır).

#### `customUserVars` [#customuservars]

- **Tür:** Nesne (İsteğe bağlı)
- **Açıklama:** Bu MCP sunucusu için kullanıcıların ayarlayabileceği özel değişkenleri tanımlar. Bu, yöneticilerin her kullanıcının ayrı ayrı yapılandırması gereken değişkenleri (örneğin, API anahtarları, URL'ler) belirlemesine olanak tanır. Kullanıcı tarafından sağlanan bu değerler daha sonra `headers` veya `env` yapılandırmasında kullanılabilir. `customUserVars` içeren sunucular, uygulama düzeyindeki bağlantılardan otomatik olarak hariç tutulur; bu da kullanıcıya özel kimlik bilgilerinin her zaman çalışma zamanında çözümlenmesini sağlar.
- **Yapı:**
  - `customUserVars` nesnesi, her bir anahtarın bir değişken adını (örneğin `MY_API_KEY`) temsil ettiği anahtarlar içerir. Bu ad, `{{MY_API_KEY}}` gibi yer tutucularda kullanılacaktır.
  - Her değişken adı, aşağıdaki alt anahtarlara sahip bir nesnedir:
    - `title`: String (Gerekli) - Yapılandırma arayüzünde görüntülenen, değişken için kullanıcı dostu bir başlık.
    - `description`: String (Zorunlu) - Değişken için bir açıklama veya talimat olup kullanıcıya yol göstermek amacıyla arayüzde de görüntülenir. Bu alanda HTML kullanılabilir (ör. bir bağlantı oluşturmak için: `<a href="https://example.com" target="_blank">More info</a>`).
    - `sensitive`: Boolean (İsteğe bağlı) - Değerin gizli olarak ele alınıp kullanıcı arayüzünde maskelenip maskelenmeyeceğini kontrol eder. Belirtilmediğinde varsayılan olarak maskelenmiş/gizli davranır; proje kimlikleri veya temel URL'ler gibi gizli olmayan alanlar için `false` olarak ayarlayın.
- **`headers` ve `env` içinde kullanım:**
  - `customUserVars` altında tanımlandıktan sonra, bu değişkenlere `headers` ( `sse` ve `streamable-http` türleri için) veya `env` (`stdio` türü için) bölümlerinde `{{VARIABLE_NAME}}` sözdizimi kullanılarak başvurulabilir.
  - Kullanıcılar bu değerleri sunucuya ilk bağlandıklarında girer ve daha sonra sohbet giriş alanındaki **Configure** veya **MCP Settings** içinden değiştirebilir. Bkz. [Credentials and variables](/docs/features/mcp#credentials-and-variables).
  - Bu kullanıcı tarafından sağlanan değerler kullanıcı ve MCP sunucusu bazında saklanır ve çalışma zamanında yerine konur.
  - Eğer LibreChat başlatıldığında değişkenler kullanılabilir değilse (örneğin bir GitHub kişisel erişim belirteci), kullanıcı bağlanana kadar LibreChat'in bağlanmaya çalışmaması için [`startup: false`](#startup) ayarını da yapabilirsiniz.
- **Örnek:**
  ```yaml
  customUserVars:
    MY_SERVICE_API_KEY:
      title: 'My Service API Key'
      description: "Your personal API access key for My Service. Find it at <a href='https://myservice.example.com/settings/api' target='_blank'>My Service API Settings</a>."
      sensitive: true
    SOME_OTHER_VAR:
      title: 'Some Other Variable'
      description: 'The specific value for some other configuration (e.g., a specific path or identifier).'
      sensitive: false
  ```
  `headers` içinde kullanım:
  ```yaml
  headers:
    X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    X-Some-Other-Config: '{{SOME_OTHER_VAR}}'
  ```
  `env` içinde kullanım (`stdio` türü için):
  ```yaml
  env:
    API_KEY: '{{MY_SERVICE_API_KEY}}'
  ```

#### `obo` [#obo]

- **Tür:** Nesne (İsteğe bağlı, yalnızca `sse` ve `streamable-http` türleri için)
- **Açıklama:** Bir MCP sunucusu için OAuth 2.0 On-Behalf-Of (adına hareket etme) belirteç değişimini yapılandırır. LibreChat, oturum açmış kullanıcının OpenID erişim belirtecini yapılandırılmış kapsamlarla temsilci bir alt akış belirteci ile değiştirir ve ardından bu belirteci bir `Authorization: Bearer ...` başlığı olarak MCP sunucusuna iletir.
- **Gerekli Alt Anahtarlar:**
  - `scopes`: String - Aşağı yönlü (downstream) token değişimi için talep edilen boş olmayan kapsamlar.
- **Doğrulama:**
  - `obo`, yalnızca `sse` ve `streamable-http` MCP sunucuları için geçerlidir.
  - `obo`, `stdio` ve `websocket` sunucuları için reddedilir.
  - Kullanıcıların bu alanı yapılandırabilmesi için `MCP_SERVERS.CONFIGURE_OBO` rol iznine sahip olması gerekir. Bunu [`interface.mcpServers.configureObo`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) ile başlatın veya yönetici panelinden yönetin.
- **Ön koşullar:**
  - OpenID kimlik doğrulaması, yeniden kullanılabilir erişim belirteçleri (access tokens) ile yapılandırılmalıdır.
  - Kimlik sağlayıcınız ve alt uygulamanız, talep edilen yetkilendirilmiş kapsama (delegated scope) izin vermelidir.
- **Örnek:**
  ```yaml
  mcpServers:
    enterprise-tools:
      type: streamable-http
      url: https://api.example.com/mcp/
      obo:
        scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
  ```

İlgili token yeniden kullanımı ve yetkilendirilmiş token kurulumu için [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse) ve [SharePoint Integration](/docs/configuration/sharepoint) bölümlerine bakın.

#### `oauth` [#oauth]

- **Tür:** Nesne (İsteğe bağlı)
- **Açıklama:** MCP sunucusu ile kimlik doğrulaması için OAuth2 yapılandırması. Yapılandırıldığında, kullanıcılar MCP sunucusu kullanılmadan önce OAuth akışı aracılığıyla kimlik doğrulaması yapmaya yönlendirilecektir. Eğer bir client id ve client secret sağlanmazsa, Dinamik İstemci Kaydı (DCR) kullanılacaktır.
- **Alt anahtarlar:** Tüm `oauth` alt anahtarları isteğe bağlıdır. Uç noktalar otomatik olarak keşfedilebilir ve Dinamik İstemci Kaydı (Dynamic Client Registration) aracılığıyla bir istemci elde edilebilir.
  - `authorization_url`: String - OAuth yetkilendirme endpoint URL'i
  - `token_url`: String - OAuth belirteç (token) uç noktası URL'si
  - `client_id`: String - OAuth istemci tanımlayıcısı
  - `client_secret`: String - OAuth istemci gizli anahtarı
  - `redirect_uri`: String - [OAuth yönlendirme URI'si](#oauth-callback-url) (ör. `http://localhost:3080/api/mcp/${serverName}/oauth/callback`)
  - `scope`: String - OAuth kapsamları (boşlukla ayrılmış)
- **Ek Alt Anahtarlar:**
  - `grant_types_supported`: Dizi (Array) - Desteklenen yetkilendirme türleri (varsayılan olarak `["authorization_code", "refresh_token"]`)
  - `token_endpoint_auth_methods_supported`: Dizi (Array) - Desteklenen token uç noktası kimlik doğrulama yöntemleri (varsayılan olarak `["client_secret_basic", "client_secret_post"]`)
  - `token_exchange_method`: String - İsteğe bağlı token değişimi geçersiz kılma. İstemci kimlik bilgilerini form kodlu POST gövdesinde göndermek için `default_post` değerini veya bunları bir HTTP Basic yetkilendirme başlığında göndermek için `basic_auth_header` değerini kullanın. Belirtilmediğinde, LibreChat sağlayıcının duyurduğu token uç noktası kimlik doğrulama yöntemlerini keşfeder ve hiçbir yöntem duyurulmamışsa varsayılan olarak Basic auth yöntemini kullanır.
  - `response_types_supported`: Dizi (Array) - Desteklenen yanıt türleri (varsayılan olarak `["code"]`)
  - `code_challenge_methods_supported`: Dizi (Array) - Desteklenen PKCE kod doğrulama yöntemleri (varsayılan olarak `["S256", "plain"]`)
  - `skip_code_challenge_check`: Boolean - OAuth sağlayıcısının PKCE desteğini duyurup duyurmadığının kontrolünü atlar. S256'yı destekleyen ancak bunu meta verilerinde duyurmayan AWS Cognito gibi sağlayıcılar için kullanışlıdır. (varsayılan değer `false`)
  - `revocation_endpoint`: String - Token iptal (revocation) endpoint URL'si. Atlandığında otomatik olarak keşfedilir.
  - `revocation_endpoint_auth_methods_supported`: Dizi (Array) of String - İptal (revocation) uç noktasının desteklediği kimlik doğrulama yöntemleri. Atlandığında otomatik olarak keşfedilir.
  - `audience`: String - Yetkilendirme isteğinde `audience` parametresi olarak gönderilir; bu, yalnızca bir audience talep edildiğinde API'ye yönelik belirteçler (token) veren Auth0 gibi sağlayıcılar için kullanılır. Yalnızca yönetici tarafından ayarlanabilir: kullanıcıların arayüzde oluşturduğu sunucular için reddedilir.
  - `forward_audience_on_refresh`: Boolean - `audience` değerinin `refresh_token` grant isteğinde de gönderilip gönderilmeyeceğini belirler. Varsayılan değeri `true`'dur; bu, Auth0'ın gereksinimidir. Ekstra parametreyi reddeden AWS Cognito gibi katı token endpoint'lerine sahip sağlayıcılar için `false` olarak ayarlayın. `audience` ayarlanmadığında yok sayılır. Yalnızca yönetici tarafından ayarlanabilir.
  - `send_resource_parameter`: Boolean - RFC 8707 `resource` parametresinin yetkilendirme isteğinde, kod değişiminde ve yenileme (refresh) isteğinde gönderilip gönderilmeyeceğini belirler. Varsayılan değeri `true`tur. Bu parametreyi reddeden sağlayıcılar için `false` olarak ayarlayın; örneğin `resource` ve `scope` birlikte gönderildiğinde `AADSTS9010010` hatası veren Microsoft Entra ID v2.0 bunlara örnektir. Bunun yerine API'ye özgü bir token elde etmek için `scope` veya `audience` kullanın. Yalnızca yönetici tarafından ayarlanabilir.
- **Ortam değişkenleri:** `authorization_url`, `token_url`, `redirect_uri` ve `revocation_endpoint` dahil olmak üzere YAML ile tanımlanmış OAuth URL alanları, `${ENV_VAR}` referanslarını kullanabilir. LibreChat, URL doğrulamasından önce ortam değerini çözümler. Kullanıcı tarafından yönetilen ve arayüz üzerinden gönderilen OAuth uç nokta URL'leri gerçek URL'ler olmalı ve `${ENV_VAR}` yer tutucularını reddetmelidir.
- **Örnek:**

  ```yaml
  oauth-api-server:
    authorization_url: https://api.example.com/oauth/authorize
    token_url: https://api.example.com/oauth/token
    client_id: your_client_id
    client_secret: your_client_secret
    redirect_uri: http://localhost:3080/api/mcp/oauth-api-server/oauth/callback
    scope: 'read execute'
    grant_types_supported: ['authorization_code', 'refresh_token']
    token_endpoint_auth_methods_supported: ['client_secret_post']
    token_exchange_method: default_post
    response_types_supported: ['code']
    code_challenge_methods_supported: ['S256', 'plain']
  ```

  Auth0 örneği:

  ```yaml
  auth0-server:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      audience: https://api.example.com
      scope: 'read:data offline_access'
  ```

`token_exchange_method` ve `token_endpoint_auth_methods_supported` öğelerinin her ikisi de önceden yapılandırılmış bir istemci sırrı (client secret) için atlandığında, LibreChat korumalı kaynak ve yetkilendirme sunucusu meta veri keşfi için beş saniyeye kadar süre tanır. Yalnızca keşfedilen token uç noktası yapılandırılmış `token_url` ile tam olarak eşleştiğinde duyurulan yetenekleri kullanır; keşif, yapılandırılmış istemci kimlik bilgilerini başka bir uç noktaya yönlendiremez. Bir sağlayıcı kullanılabilir meta veriler yayınlamadığında veya zorunlu bir yöntem gerektiğinde `token_exchange_method` değerini açıkça ayarlayın.

Sunucu taraflı OAuth keşif, kayıt, belirteç ve iptal HTTP istekleri, orijinal URL izin verilmiş olsa dahi yönlendirmeleri (redirects) takip **etmez**. Yönlendirme yapıldığında, sağlayıcının nihai endpoint adresini doğrudan yapılandırın. Özel IP-değişmez (IP-literal) hedefler, yöneticinin güvenilir ana bilgisayar veya tam adres-ve-port politikası tarafından açıkça izin verilmediği sürece engellenir. Bu kısıtlama sunucu taraflı OAuth HTTP istekleri için geçerlidir; kullanıcının tarayıcısının normal yetkilendirme sayfası yönlendirmesini tamamlamasını engellemez.

#### `oauth_headers` [#oauth_headers]

- **Tür:** Nesne (İsteğe bağlı)
- **Açıklama:** Özellikle OAuth akış istekleri için kullanılan başlıklar. Bu başlıklar, dinamik istemci kaydı ve belirteç değişimi gibi OAuth kimlik doğrulaması sırasında kullanılır ve normal MCP sunucusu iletişimi sırasında gönderilmez.
- **Yaygın Kullanım Durumları:**
  - Dinamik istemci kaydı uç noktalarına, `Authorization: Bearer ${DCR_API_KEY}` gibi kimlik doğrulama ekleme
  - OAuth akışları için gerekli olan özel sağlayıcıya özgü başlıkların dahil edilmesi
  - OAuth token uç noktaları tarafından ihtiyaç duyulan başlıkları ayarlama
- **Yer Tutucu Desteği:** Değerler, `oauth` altındaki metin alanlarının yanı sıra `{{LIBRECHAT_USER_*}}` yer tutucularını ve `${ENV_VAR}` başvurularını kabul eder.
- **`headers` ile Temel Farklar:**
  - **`headers`**: Kimlik doğrulama tamamlandıktan sonra düzenli MCP sunucu istekleriyle birlikte gönderilir
  - **`oauth_headers`**: Yalnızca OAuth kimlik doğrulama akışları sırasında gönderilir
- **Örnek:**
  ```yaml
  oauth_headers:
    Authorization: "Bearer ${DCR_API_KEY}"
    X-Custom-Header: "custom_value"
  ```

#### `oauthPrompt` [#oauthprompt]

- **Tür:** String (İsteğe bağlı)
- **Açıklama:** Kullanıcının OAuth ile korunan bir sunucuya ne zaman giriş yapması gerektiğini belirler.
  - `on_start`: oturum açma istemi, konuşma turu başladığında, agent çalışmadan önce görüntülenir.
  - `on_use`: Tur bir istem olmadan başlar ve agent, sunucunun araçlarını araç arama yoluyla bulur. İstem, agent sunucunun araçlarından birini ilk kez çağırdığında görüntülenir ve çalışma, kullanıcının oturum açmasını bekler.
- **Varsayılan Değer:** `on_start`
- **Notlar:**
  - `on_use` yalnızca, ajanın sunucudan seçtiği her aracın [ertelenmiş](/docs/features/agents#deferred-tools) ("Defer" açık) olması durumunda uygulanır. Seçilen araçlardan herhangi biri başta yüklenirse veya ajan bireysel araçlar yerine tüm sunucuyu seçerse, istem tur başında kalır.
  - Kullanıcıya ilişkin öneri: `deferred_tools` [ajan yeteneği](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) etkinleştirilmiş olmalıdır. `run_in_background` yeteneği etkinleştirildiğinde, arka planda çalışmayı tercih eden seçili bir araç, tur başlangıcında istemi korur; çünkü ayrılmış (detached) bir çağrı oturum açmayı bekleyemez.
  - `on_use` requires a declared [`oauthToolCatalog`](#oauthtoolcatalog). Without one, the server keeps the turn-start prompt, even for a user who has connected before.
  - Oturum açılmadan önce sunulan araçlar, seçilen her aracı içermelidir; aksi halde istem tur başlangıcında kalır. Bu, bildirilen katalog veya daha önceki bir bağlantının geride bıraktığı kullanıcıya ait araç listesidir.
  - Yalnızca operatör tarafından yapılandırılmış sunucular bu kapsama girer: `librechat.yaml` içinde tanımlananlar veya [yönetici yapılandırma geçersiz kılmaları](/docs/configuration/admin_panel#configuration-overrides) üzerinden eklenenler. Kullanıcıların arayüzde oluşturduğu sunucular, tur başlangıcındaki istemi korur. Bağlantı ayarlarında `obo`, `customUserVars`, `requestHeaders` veya kullanıcıya ya da isteğe özgü yer tutucular (`{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, `{{LIBRECHAT_BODY_*}}`) kullanan bir sunucu için istem tur başlangıcında kalır.
  - Bu durum, OAuth'un önceden yapılandırılması (`oauth`, `requiresOAuth: true`) veya sunucunun bağlantıyı reddettiği anda tespit edilmesi durumlarının ikisi için de geçerlidir.
  - Kullanıcıların arayüzde oluşturduğu sunucularda kullanılamaz.
- **Örnek:**
  ```yaml
  mcpServers:
    google-sheets:
      type: streamable-http
      url: https://sheets.example.com/mcp
      requiresOAuth: true
      oauthPrompt: on_use
      oauthToolCatalog:
        - name: read_sheet
          description: Read the values in a spreadsheet range
  ```

#### `oauthToolCatalog` [#oauthtoolcatalog]

- **Tür:** Nesnelerden oluşan dizi (İsteğe bağlı)
- **Açıklama:** Bir `oauthPrompt: on_use` sunucusunun, kullanıcı oturum açmadan önce araç aramasına sunduğu araçlar. LibreChat, oturum açmamış bir kullanıcı için korumalı bir sunucunun araçlarını listeleyemez; bu nedenle bu araçlar burada operatör tarafından tanımlanır. Katalog tüm kullanıcılar için aynıdır; hiçbir kullanıcının bağlantısı, diğer kullanıcıların ajanlarının neleri göreceğini belirlemez. Kullanıcı oturum açtıktan sonra sunucunun kendi araç tanımları kullanılır ve sunucu her çağrıyı doğrular.
- **Giriş alanları:**
  - `name`: String (Zorunlu) - Araç adı, sunucudaki adıdır; agent bu adı seçer.
  - `description`: String (İsteğe bağlı) - Aracın ne yaptığı; araç aramasında ve modele gösterilir.
  - `inputSchema`: Object (İsteğe bağlı) - Aracın parametreleri:
    - `type`: değer `object` olmalıdır
    - `properties`: parametre adından özellik şemasına eşleyen bir harita
    - `required`: gerekli parametre adlarından oluşan dizi (array)
- **Özellik şeması:** Yalnızca şu anahtarlara izin veren, sınırlandırılmış bir JSON Schema alt kümesi:
  - `type`: `string`, `number`, `integer`, `boolean`, `object`, `array`, `null` değerlerinden biri veya bunlardan oluşan boş olmayan bir liste olabilir.
  - `description`: String
  - `enum`: boş olmayan, dizeler, sayılar, boolean değerler veya `null` içeren bir dizi
  - `default`: string, number, boolean veya `null`
  - `items`: diziler için `type`, `description` ve `enum` içeren bir nesne
- **Notlar:**
  - Doğrulama katıdır. Yanlış yazılmış bir giriş anahtarı (örneğin `input_schema`) veya sınırlı şema dışındaki bir anahtar sözcük (örneğin `minLength`, `pattern` veya `$ref`) yoksayılmak yerine yapılandırma doğrulamasının başarısız olmasına neden olur.
  - Önceki bağlantısında bir araç listesi bırakmış olan bir kullanıcıya, bunun yerine o liste sunulur; her iki durumda da bu listede, aracının sunucudan seçtiği tüm araçlar bulunmalıdır, aksi halde istem tur başlangıcında kalır.
  - Kullanıcıların arayüzde oluşturduğu sunucularda kullanılamaz.
- **Örnek:**
  ```yaml
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
  ```

#### `startup` [#startup]

- **Tür:** Boolean (İsteğe bağlı)
- **Açıklama:** `false` olarak ayarlandığında, bu MCP sunucusu uygulama başlangıcında bağlanmayacaktır. Bu, bağlanmadan önce kullanıcı girişi veya yapılandırma gerektiren sunucular veya sunucunun ne zaman başlatılacağını kontrol etmek istediğiniz durumlar için kullanışlıdır.
- **Varsayılan Değer:** `true`
- **Örnek:**
  ```yaml
  mcpServers:
    my-mcp-server:
      type: streamable-http
      url: 'https://api.example.com/mcp/'
      startup: false
  ```

### Notlar [#notes]

- **Tür Çıkarımı:**
  - `type` atlanırsa:
    - `url` belirtilmişse ve `http://` veya `https://` ile başlıyorsa, `type` varsayılan olarak `sse` olur.
    - `url` belirtilmişse ve `ws://` veya `wss://` ile başlıyorsa, `type` varsayılan olarak `websocket` olur.
    - `command` belirtilmişse, `type` varsayılan olarak `stdio` değerini alır.
- **Bağlantı Türleri:**
  - **`stdio`**: Bir MCP sunucusunu alt işlem (child process) olarak başlatır ve standart girdi/çıktı (standard input/output) aracılığıyla iletişim kurar.
  - **`websocket`**: Bir WebSocket aracılığıyla harici bir MCP sunucusuna bağlanır.
  - **`sse`**: Server-Sent Events (SSE) aracılığıyla harici bir MCP sunucusuna bağlanır.
  - **`streamable-http`**: Yanıt akışını destekleyen HTTP aracılığıyla harici bir MCP sunucusuna bağlanır.
  - `stdio`, LibreChat sunucusunda tek bir süreç çalıştırır ve yerel, tek kullanıcılı kurulumlar için uygundur. `sse` ise eski bir uzak aktarım protokolüdür. Çok kullanıcılı veya üretim ortamı dağıtımlarında `streamable-http` kullanın.
- **Dahili/Yerel Adresler:**
  - **Önemli**: Dahili IP adreslerini (örneğin `172.24.1.165`, `192.168.1.100`) veya yerel alan adlarını (örneğin `mcp-server`, `host.docker.internal`) kullanan MCP sunucularına açıkça izin **verilmelidir**. Genel hedeflerin erişilebilir kalmasını istediğinizde belirli özel host:port servisleri için [`mcpSettings.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#allowedaddresses) seçeneğini veya katı bir beyaz liste istediğinizde [`mcpSettings.allowedDomains`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#alloweddomains) seçeneğini kullanın.
  - Yapılandırma ayrıntıları için [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) bölümüne bakın.

## OAuth geri çağırma URL'si [#oauth-callback-url]

Bir sunucu OAuth kullandığında, sağlayıcı kullanıcıyı şu adrese geri yönlendirir:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>`, `mcpServers` altındaki anahtardır. Örneğin, `DOMAIN_SERVER=https://chat.example.com` ayarına sahip `salesforce` adlı bir sunucu `https://chat.example.com/api/mcp/salesforce/oauth/callback` adresini kullanır. Yerel bir Docker kurulumu genellikle temel adres olarak `http://localhost:3080` kullanır. Kullanıcı arayüzünde oluşturulan sunucular için, sunucunun ürettiği tanımlayıcı anahtarın yerini alır ve LibreChat, sunucu oluşturulduktan sonra tam **Redirect URI** değerini gösterir.

Bu tam URL'yi OAuth sağlayıcısına kaydedin. `/api/oauth/callback` veya `/api/oauth/openid/callback` gibi diğer LibreChat geri çağırma yolları MCP için çalışmaz.

Sağlayıcı dinamik istemci kaydını destekliyorsa, sunucu için hiçbir `oauth` bloğuna ihtiyaç yoktur; kullanıcı ilk kez bağlandığında LibreChat kendini bir istemci olarak kaydeder:

```yaml
mcpServers:
  # No refresh tokens: users sign in again when the token expires
  paypal:
    type: sse
    url: https://mcp.paypal.com/sse
    initTimeout: 150000
  # Issues refresh tokens: LibreChat renews access automatically
  spotify:
    type: streamable-http
    url: https://mcp-spotify-oauth-example.account.workers.dev/mcp
    initTimeout: 150000
```

Kullanıcıların oturum açmayı tamamlamak için 10 dakikası vardır ve LibreChat bekleyen akışı 15 dakika boyunca saklar. Bu değerleri `.env` dosyasındaki `MCP_OAUTH_HANDLING_TIMEOUT` ve `MCP_OAUTH_FLOW_TTL` ile değiştirebilirsiniz (bkz. [MCP ortam değişkenleri](/docs/configuration/dotenv#mcp-model-context-protocol)). Akış TTL değeri, her zaman işlem zaman aşımından en az bir dakika daha uzun tutulur; böylece son süreye yakın gelen bir geri çağırma isteği, kendi akışını hâlâ bulabilir.

## UI'da oluşturulan sunucular [#servers-created-in-the-ui]

Rolü `CREATE` iznine sahip olan kullanıcılar (bkz. [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)), bu dosyayı düzenlemeden **MCP Ayarları** bölümünden sunucu ekleyebilir. Bu sunucular veritabanında saklanır ve YAML sunucularından birkaç yönden farklıdır:

- Yalnızca uzak taşıma protokolleri (`streamable-http` ve `sse`) kullanılabilir. `stdio` sunucuları burada tanımlanmalıdır.
- `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}` ve `{{LIBRECHAT_BODY_*}}` yer tutucuları, sunucu birden fazla kullanıcı tarafından paylaşılabileceği için başlıklarından kaldırılır. Yalnızca `customUserVars` yer tutucuları korunur.
- OAuth endpoint URL'leri gerçek (literal) URL'ler olmalıdır; `${ENV_VAR}` referansları reddedilir.
- Kullanıcının her biri tarafından sağlanan bir API anahtarı seçmek, `MCP_API_KEY_<hash>` adında bir `customUserVars` girdisi ve buna karşılık gelen başlığı oluşturur. Bu değişiklikten önce kaydedilen sunucular, URL'leri veya kimlik doğrulamaları değişene kadar eski `MCP_API_KEY` adını koruyabilir. Kullanıcıların anahtarlarını yeniden girmesini gerektiren düzenlemeler için [`apiKey`](#apikey) bölümüne bakın.
- Bir API anahtarına (paylaşılan veya kullanıcı başına) sahip bir sunucu, API anahtarıyla kimlik doğrulanmış olarak kabul edilir ve OAuth yapılandırması da bulunmadığı sürece OAuth otomatik algılamasını atlar. Eski bir sürüm tarafından kaydedilmiş bir API anahtarlı sunucu **Kimlik Doğrulama Gerekiyor** durumunda kalırsa, depolanan meta verilerini yenilemek için sunucuyu bir kez düzenleyip kaydedin.
- Kaydedilmiş OAuth istemcileri ve belirteçler sunucu URL'sine, OAuth istemci ayarlarına ve uç nokta ayarlarına bağlıdır. Bu ayarlar değiştirildiğinde kullanıcıların yeniden oturum açması gerekir. Ayrıca URL, istemci kimliği, yetkilendirme URL'si, belirteç URL'si veya belirteç değişim yöntemi değiştirildiğinde, düzenleyicinin kayıtlı bir istemci gizli anahtarını yeniden girmesi gerekir.
- `oauthPrompt` ve `oauthToolCatalog` kullanılamıyor.
- [`mcpSettings`](/docs/configuration/librechat_yaml/object_structure/mcp_settings) alan ve adres kısıtlamaları geçerlidir.
- Yeni eklenen ve düzenlenen sunucular yeniden başlatma gerekmeden etkin hale gelir. Bir OAuth sunucusu, bir kullanıcı oturum açana kadar bağlantısı kesilmiş olarak kaydedilir.

Tam yer tutucu kümesi için sunucuyu `librechat.yaml` dosyasında tanımlayın.

## Sunucuları bulma [#finding-servers]

[Smithery](https://smithery.ai), herkese açık MCP sunucularını listeler. Bir sunucunun sayfasında yer alan **Connect** bölümü, LibreChat istemcisi için bir kurulum komutu oluşturabilir; bu komut girişi `librechat.yaml` dosyasına yazar. Bundan sonra LibreChat'i yeniden başlatın. Belirli sunucuların kurulumunu adım adım anlatan rehberler için [MCP Servers guides](/docs/mcp_servers) sayfasına bakabilirsiniz.

## Örnekler [#examples]

### Dahili Adreslerle Yapılandırma [#configuration-with-internal-addresses]

Dahili/yerel MCP sunucuları kullanılırken ve katı bir alan adı beyaz listesine ihtiyaç duyulmadığında, `mcpSettings.allowedAddresses` kısmını tam ana bilgisayar (host) ve bağlantı noktası (port) ile yapılandırın:

```yaml filename="Complete MCP Configuration with Internal Servers"
# MCP Settings - Required for internal/local addresses
mcpSettings:
  allowedAddresses:
    - '172.24.1.165:8000' # Internal IP and port
    - 'mcp-prod:8001' # Docker container and port
    - 'host.docker.internal:8080' # Docker host and port

# MCP Servers - Individual configurations
mcpServers:
  prod-mcp:
    type: streamable-http
    url: http://172.24.1.165:8000/mcp
    timeout: 120000

  test-mcp:
    type: streamable-http
    url: http://mcp-prod:8001/mcp
    timeout: 120000
```

### `stdio` MCP Sunucusu [#stdio-mcp-server]

```yaml filename="stdio MCP Server"
puppeteer:
  type: stdio
  command: npx
  args:
    - -y
    - '@modelcontextprotocol/server-puppeteer'
  timeout: 30000
  initTimeout: 10000
  env:
    NODE_ENV: 'production'
    USER_EMAIL: '{{LIBRECHAT_USER_EMAIL}}'
    USER_ROLE: '{{LIBRECHAT_USER_ROLE}}'
  stderr: inherit
```

```yaml filename="MCP Server with User Fields"
user-aware-server:
  type: sse
  url: https://api.example.com/users/{{LIBRECHAT_USER_USERNAME}}/stream
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-Email-Verified: '{{LIBRECHAT_USER_EMAILVERIFIED}}'

```

### `customUserVars` ile Kullanıcı Bazlı Kimlik Bilgilerine Sahip MCP Server [#mcp-server-with-per-user-credentials-via-customuservars]

```yaml filename="MCP Server with customUserVars"
my-mcp-server:
  type: streamable-http
  url: 'https://api.example-service.com/api/' # Example URL
  headers:
    X-Auth-Token: '{{API_KEY}}' # Uses the API_KEY defined below
  customUserVars:
    API_KEY: # This key will be used as {{API_KEY}} in headers/url
      title: 'API Key' # This is the label shown above the input field
      description: "Get your API key <a href='https://example.com/api-keys' target='_blank'>here</a>." # This description appears below the input
```

[Kimlik bilgileri ve değişkenler](/docs/features/mcp#credentials-and-variables) bölümüne bakın; bu bölümde `customUserVars` ile bir sunucuya bağlanan kullanıcıların neleri gördüğü açıklanmaktadır.

### OAuth Kimlik Doğrulamalı MCP Server [#mcp-server-with-oauth-authentication]

```yaml filename="MCP Server with OAuth"
oauth-api-server:
  type: streamable-http
  url: https://api.example.com/mcp/
  oauth:
    authorization_url: https://api.example.com/oauth/authorize
    token_url: https://api.example.com/oauth/token
    client_id: your_client_id
    client_secret: your_client_secret
    redirect_uri: http://localhost:3080/api/mcp/oauth-api-server/oauth/callback
    scope: 'read execute'
  oauth_headers:
    X-Custom-Header: 'custom_value'
```

### MCP Sunucusu ile İlk Araç Kullanımında OAuth Girişi [#mcp-server-with-oauth-sign-in-on-first-tool-use]

```yaml filename="MCP Server with oauthPrompt: on_use"
google-sheets:
  type: streamable-http
  url: https://sheets.example.com/mcp
  requiresOAuth: true
  # Ask users to sign in when the agent first calls one of this server's tools.
  # Every tool the agent selects from this server must be deferred.
  oauthPrompt: on_use
  # Offered to tool search until a user signs in; without it the turn-start prompt is kept.
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
```

### Sunucu Talimatları ile MCP Server [#mcp-server-with-server-instructions]

```yaml filename="MCP Server with Instructions"
# Server that uses its own provided instructions
web-search:
  type: streamable-http
  url: https://example.com/mcp/search
  serverInstructions: true

# Server with instructions explicitly disabled
filesystem:
  command: npx
  args:
    - -y
    - '@modelcontextprotocol/server-filesystem'
    - /home/user/documents/
  serverInstructions: false

# Server with custom instructions
puppeteer:
  type: stdio
  command: npx
  args:
    - -y
    - '@modelcontextprotocol/server-puppeteer'
  serverInstructions: |
    Browser automation security and best practices:
    1. Be cautious with local file access and internal IP addresses
    2. Take screenshots to verify successful page interactions
    3. Wait for page elements to load before interacting with them
    4. Use specific CSS selectors for reliable element targeting
    5. Check console logs for JavaScript errors when troubleshooting
```

### OAuth Etkinleştirilmiş MCP Sunucusu (Eski requiresOAuth) [#oauth-enabled-mcp-server-legacy-requiresoauth]

```yaml filename="OAuth-Enabled MCP Server"
composio-googlesheets:
  type: sse
  url: https://mcp.composio.dev/googlesheets/sse-endpoint
  requiresOAuth: true
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-API-Key: '${COMPOSIO_API_KEY}'
  timeout: 45000
  initTimeout: 15000
```

**İlgili Ortam Değişkenleri (İsteğe Bağlı):** Tüm MCP ayarları için [Ortam Değişkenleri](/docs/configuration/dotenv) sayfasına bakın.

```bash
# OAuth configuration for MCP servers
MCP_OAUTH_ON_AUTH_ERROR=true
MCP_OAUTH_DETECTION_TIMEOUT=5000
MCP_OAUTH_HANDLING_TIMEOUT=600000
MCP_OAUTH_FLOW_TTL=900000

# API key for the service
COMPOSIO_API_KEY=your_composio_api_key_here
```

**MCP Sunucu Yapılandırmalarını İçe Aktarma**

`mcpServers` yapılandırmaları, LibreChat'in çeşitli MCP sunucularıyla dinamik olarak etkileşime girmesine olanak tanır; bu sunucular uygulama içinde özel görevler gerçekleştirebilir veya belirli işlevler sağlayabilir. Bu modüler yaklaşım, yalnızca sunucu yapılandırmaları ekleyerek veya değiştirerek uygulamanın yeteneklerini genişletmeyi kolaylaştırır.

## Ek Bilgiler [#additional-information]

- **Varsayılan Davranış:**
  - `librechat.yaml` içindeki sunucular başlangıçta başlatılır, bu nedenle bu dosyadaki değişikliklerin uygulanması için yeniden başlatma gerekir. Arayüzde oluşturulan sunucularda ise bu gerekli değildir.
  - Bağlantı kuran sunucular çalışırken `notifications/tools/list_changed` bildirimi göndererek araç ekleyebilir veya kaldırabilir; LibreChat, yeniden başlatma gerektirmeden canlı bağlantıdan araç listesini yeniden alır.
  - Bir kullanıcı bir araç çağrısı sırasında **Durdur** düğmesine bastığında, LibreChat MCP isteğini iptal eder. Streamable HTTP sunucuları `notifications/cancelled` bildirimini alır ve kendi işlerini durdurmak için bu bildirime uymak zorundadır. Arka planda çalışan araç çağrıları iptal edilmez.
  - Hem `url` hem de `command` belirtilmişse, belirsizliği önlemek için `type` açıkça tanımlanmalıdır.
- **Çok Kullanıcılı Destek:**
  - MCPManager artık kullanıcı düzeyinde ve uygulama düzeyinde ayrı bağlantıları destekleyerek, kullanıcı başına düzgün bağlantı yönetimi sağlar.
  - Kullanıcı bağlantıları ayrı ayrı izlenir ve yönetilir; uygun kurulum ve temizleme işlemleri gerçekleştirilir.
  - Redis etkinleştirildiğinde, OAuth akış durumu ve MCP araç kataloğu, Redis Cluster dağıtımları dahil olmak üzere kopyalar (replica) arasında paylaşılır. Kopyalar arasında token yenileme için [OAuth yenileme koordinasyonu](#oauth-refresh-coordination) bölümüne bakın.
  - Başlıklarda, URL'lerde ve ortam değişkenlerinde dinamik kullanıcı alanı yer tutucularını kullanın:
    - `{{LIBRECHAT_USER_ID}}` - Kullanıcının benzersiz tanımlayıcısı
    - `{{LIBRECHAT_USER_EMAIL}}` - Kullanıcının e-posta adresi
    - `{{LIBRECHAT_USER_USERNAME}}` - Kullanıcının kullanıcı adı
    - `{{LIBRECHAT_USER_ROLE}}` - Kullanıcının rolü (örneğin, "user", "admin")
    - Ve daha birçok alan (tam liste için başlıklar bölümüne bakın)
- **Kullanıcı Boşta Kalma Yönetimi:**
  - Kullanıcı bağlantıları etkinlik açısından izlenir ve 15 dakika boyunca etkinlik olmazsa bağlantıları kesilir. Bunu `MCP_USER_CONNECTION_IDLE_TIMEOUT` (milisaniye cinsinden) ile değiştirebilirsiniz.
- **Ortam Değişkenleri:**
  - **`env` içinde (`stdio` türü için):** MCP sunucu süreci tarafından gerekli olan belirli çalışma zamanı ortamlarını veya yapılandırmalarını ayarlamak için kullanışlıdır.
  - **`headers` içinde (`sse` ve `streamable-http` türleri için):** Başlık değerlerinde ortam değişkenlerine referans vermek için `${ENV_VAR}` sözdizimini kullanın.
- **Dinamik Kullanıcı Alanları:**
  - Kullanıcı alanı yer tutucuları, çalışma zamanında kimliği doğrulanmış kullanıcının bilgileriyle değiştirilir
  - Yalnızca hassas olmayan alanlar mevcuttur (şifreler ve diğer hassas veriler hariç tutulmuştur)
  - Eksik alanlar varsayılan olarak boş dizelere ayarlanır
  - Boolean alanlar, dize gösterimlerine ("true" veya "false") dönüştürülür.
- **Hata İşleme (`stderr`):**
  - `stderr` yapılandırması, MCP sunucu sürecinden gelen hata mesajlarının nasıl yönetileceğini belirlemenize olanak tanır. Varsayılan `"inherit"` değeri, hataların üst sürecin `stderr` kısmına yazdırılacağı anlamına gelir.
- **Sunucu Talimatları:**
  - MCP sunucu araçları kullanıldığında talimatlar otomatik olarak ajanın sistem mesajına eklenir.
  - Özel talimatlar (string değerleri), sunucu tarafından sağlanan talimatlara göre önceliklidir
  - Birden fazla MCP sunucusu, her biri kendi talimatlarını aracı bağlamına (agent context) katkıda bulunabilir
  - Talimatlar, yalnızca ilgili MCP sunucusunun araçları gerçekten aracı için kullanılabilir olduğunda dahil edilir
- **OAuth Kimlik Doğrulaması:**
  - MCP sunucuları ile güvenli kimlik doğrulama için OAuth2 akışı desteklenmektedir
  - MCP sunucusu kullanılmadan önce kullanıcılardan OAuth aracılığıyla kimlik doğrulaması yapmaları istenecektir.
