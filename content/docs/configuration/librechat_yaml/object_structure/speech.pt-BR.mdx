## Visão geral [#overview]

O objeto `speech` permite que você configure provedores de Text-to-Speech (TTS) e Speech-to-Text (STT) diretamente no seu arquivo de configuração `librechat.yaml`. Isso habilita serviços de voz no lado do servidor sem exigir que os usuários configurem suas próprias chaves de API.

**Campos sob `speech`:**

- `tts` - Configurações do provedor de Text-to-Speech
- `stt` - Configurações do provedor de Speech-to-Text
- `speechTab` - Configurações padrão da interface para recursos de fala

**Notas:**

- Vários provedores podem ser configurados simultaneamente
- Os usuários podem selecionar seu provedor preferido entre as opções disponíveis.
- As chaves de API no arquivo de configuração devem usar referências de variáveis de ambiente por segurança

## Exemplo [#example]

```yaml filename="speech"
speech:
  tts:
    allowedAddresses: ["tts.internal:8080"]
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["voice-id-1", "voice-id-2"]
  stt:
    allowedAddresses: ["stt.internal:8080"]
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText: true
    textToSpeech: true
```

## Proteção SSRF [#ssrf-protection]

O LibreChat protege URLs de STT e TTS fornecidas pelo operador no momento da conexão. Destinos privados, loopback, link-local e de metadados de nuvem são bloqueados por padrão, e redirecionamentos são desativados para solicitações de fala.

`speech.tts.allowedAddresses` e `speech.stt.allowedAddresses` são listas de exceção separadas, não listas de permissão estritas. Adicione um `host:port`, `private.ip:port` ou `[ipv6]:port` privado exato apenas quando essa seção precisar acessar um serviço auto-hospedado confiável. Não use uma URL, caminho, intervalo CIDR, host/IP puro ou literal de IP público. As portas padrão são normalizadas, portanto, uma URL HTTPS sem uma porta explícita é verificada como porta `443`.

Um hostname isento confia em qualquer endereço privado para o qual ele seja resolvido nessa porta. Prefira um literal de IP privado quando possível e liste apenas nomes cujo DNS você controla e que não possam ser redirecionados por um atacante.

Quando um forward proxy processa uma solicitação de hostname, o proxy realiza o DNS de destino e a saída (egress), portanto, o proxy deve aplicar sua própria política de SSRF. Um destino privado literal ainda é bloqueado antes do processamento pelo proxy, a menos que seu endereço e porta exatos sejam isentos.

## Notas [#notes]

- Sempre utilize referências de variáveis de ambiente (por exemplo, `${API_KEY}`) para chaves de API em arquivos de configuração
- Vários provedores de TTS podem ser configurados; os usuários selecionam sua opção preferida na interface.
- As configurações `speechTab` definem padrões que os usuários podem substituir em suas configurações pessoais
- `browser` usa o suporte de fala nativo do navegador; `external` usa os provedores do lado do servidor configurados em `speech.stt` ou `speech.tts`
- Os padrões de STT existentes para `openai` e `azureOpenAI`, e os padrões de TTS para `openai`, `azureOpenAI`, `elevenlabs` e `localai`, foram migrados para `external`; um mecanismo externo indisponível recorre ao `browser`.
- Para documentação detalhada de recursos, veja [Speech to Text & Text to Speech](/docs/configuration/stt_tts)
