```yaml filename="Agents Endpoint"
    # (optional) Agent Capabilities available to all users. Omit the ones you wish to exclude. Defaults to list below.
    # Opt-in capabilities: "programmatic_tools", "stateful_code_sessions", "run_in_background", and "tool_intents".
    # capabilities: ["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]
    # (optional) File citation configuration for file_search capability

    maxCitationsPerFile: 7 # Maximum citations from each file (1-10)
    minRelevanceScore: 0.45 # Minimum relevance score threshold (0.0-1.0)

      environments:
        - id: managed-default
          name: Managed Code API
          type: managed

        - id: engineering-vm
          name: Engineering VM

            workerId: engineering-vm

            allowPrincipalWorkers: true
            tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
    # eventDriven:
    #   selfUrl: https://librechat.internal
    backgroundTasks:
      completionWakeups: true
      ordinaryToolCancellation: false
    toolApproval:
      enabled: true
      mode: default

      auth:
        oidc:
          enabled: false
```

## maxProviderErrorChars

Kiểm soát lượng văn bản lỗi từ nhà cung cấp mà LibreChat sẽ giữ lại khi không thể phân loại lỗi của Agent. Giá trị mặc định là `2000` ký tự. Đặt thành `0` để bỏ qua văn bản từ nhà cung cấp; giá trị tối đa là `1000000`.

```yaml filename="endpoints / agents / maxProviderErrorChars"
maxProviderErrorChars: 2000
```

## repositoryInstructions

Kiểm soát việc khám phá hướng dẫn kho lưu trữ cho các môi trường Code được đính kèm. `timeoutMs` giới hạn yêu cầu tải hướng dẫn từ `100` đến `30000` mili giây và mặc định là `2000`.

```yaml filename="endpoints / agents / repositoryInstructions"
repositoryInstructions:
  timeoutMs: 2000
```

## Bộ ngắt mạch luồng (Stream circuit breakers) [#stream-circuit-breakers]

Các cài đặt này sẽ dừng quá trình chạy Agent khi luồng dữ liệu từ nhà cung cấp có dấu hiệu tạo ra các đối số công cụ không kiểm soát được hoặc một chuỗi sự kiện delta vô hạn.

      'maxToolCallArgBytes',
      'Number',
      'Số byte tích lũy tối đa cho các đối số của một lệnh gọi công cụ được truyền phát. Đặt thành 0 để tắt tính năng bảo vệ toàn cục.',
      '65536',
    ],
    [
      'maxDeltaEventsPerTurn',
      'Number',
      'Số lượng sự kiện truyền phát tối đa cho một lượt tạo mô hình. Đặt thành 0 hoặc bỏ qua để tắt tính năng bảo vệ này.',
      '0 (disabled)',
    ],
    [
      'maxToolCallArgBytesByTool',
      'Object',
      'Ghi đè byte đối số theo từng công cụ, được khóa bằng tên công cụ hiển thị với model. Giá trị 0 sẽ vô hiệu hóa cơ chế bảo vệ cho công cụ đó.',
      'create_file: 131072',
    ],
  ]}
/>

LibreChat sử dụng giới hạn đối số toàn cục 64 KiB và cung cấp mức ghi đè 128 KiB cho `create_file`, vì các payload hợp lệ của hàm này thường lớn hơn. Các mục trong `maxToolCallArgBytesByTool` sẽ hợp nhất đè lên mức ghi đè tích hợp sẵn đó. Nếu một trong hai cơ chế bảo vệ bị kích hoạt, LibreChat sẽ hủy luồng nhà cung cấp đang chạy và báo cáo giới hạn nào đã bị vượt quá.

```yaml filename="endpoints / agents / stream circuit breakers"
maxToolCallArgBytes: 65536
maxDeltaEventsPerTurn: 100000
maxToolCallArgBytesByTool:
  create_file: 262144
  large_import: 524288
```

Để vô hiệu hóa mọi cơ chế bảo vệ kích thước đối số (argument-size guard), hãy đặt cả giới hạn toàn cục và ghi đè `create_file` mặc định thành `0`:

```yaml
maxToolCallArgBytes: 0
maxToolCallArgBytesByTool:
  create_file: 0
```

## activityLabel

Đặt `activityLabel: true` để nhóm từng khối suy luận của Agent và các lệnh gọi công cụ dưới một tiêu đề một dòng được tạo tự động. Sử dụng `activityModel`, `activityEndpoint`, `activityPrompt`, `activityMaxPerRun` và `activityCharLimit` để kiểm soát lệnh gọi model bổ sung và chi phí của nó. Xem [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) để biết tài liệu tham khảo đầy đủ về các trường và quy tắc ưu tiên.

```yaml filename="endpoints / agents / activity groups"
activityLabel: true
activityEndpoint: openAI
activityModel: gpt-4.1-nano
activityMaxPerRun: 20
activityCharLimit: 600
activityPhaseLabel: true
activityPhaseMaxPerRun: 5
```

`activityPhaseLabel` có thể tự động thêm một bản tóm tắt cha đã thu gọn xung quanh mỗi giai đoạn chạy (run phase) chứa ít nhất hai hoạt động logic. Sử dụng `activityPhaseModel`, `activityPhaseEndpoint`, `activityPhasePrompt` và `activityPhaseMaxPerRun` để tinh chỉnh các lệnh gọi đó; `activityCharLimit` được chia sẻ với các nhãn hoạt động con.

## capabilities

<OptionTable
  options={[
    [
      'capabilities',
      'Array/List of Strings',

**Mặc định:** `["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]`

`programmatic_tools`, `stateful_code_sessions`, `run_in_background`, và `tool_intents` là các tính năng tùy chọn và phải được thêm một cách rõ ràng. Các công cụ lập trình (programmatic tools) và phiên làm việc có trạng thái (stateful sessions) cũng yêu cầu `execute_code` và một triển khai Code Interpreter tương thích. Agent Builder sẽ vô hiệu hóa các lựa chọn MCP lập trình nếu không có Code Interpreter, và máy chủ sẽ loại bỏ các tùy chọn gọi lập trình cũ khi tính năng thực thi mã không khả dụng. `run_in_background` giúp các công cụ Code Interpreter đủ điều kiện theo mặc định và cho phép tùy chọn chọn tham gia cho từng công cụ đối với các công cụ MCP, Plugin và Action đủ điều kiện; việc thực thi mã trong nền cũng yêu cầu `execute_code` và Code Interpreter.

`stateful_code_sessions` hiện đang ở giai đoạn thử nghiệm cao. Tính năng này yêu cầu một tuyến đường Code Interpreter có cấu hình `stateful`-profile riêng biệt thông qua [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) hoặc [`statefulCodeSessions.environments`](#statefulcodesessions). Các yêu cầu stateful sẽ thất bại thay vì tự động chuyển sang dịch vụ stateless thông thường. Trong Agent Builder, mỗi Agent được kích hoạt sẽ chọn phạm vi không gian làm việc là user, agent-and-user, hoặc conversation và, khi các backend được đặt tên được cấu hình, sẽ chọn một môi trường thực thi. Các Agent mới bắt đầu với phạm vi mặc định cá nhân của người dùng và môi trường thực thi mặc định của bản triển khai.

**Ví dụ:**

```yaml filename="endpoints / agents / capabilities"
capabilities:
  - 'deferred_tools'
  # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
  # Requires execute_code and a Code Interpreter deployment with the Tool Call Server component.
  # - 'programmatic_tools'
  - 'execute_code'
  - 'file_search'
  - 'web_search'
  - 'artifacts'
  - 'subagents'
  - 'actions'
  - 'context'
  - 'skills'
  - 'memory'
  - 'ask_user_question'
  - 'tools'
  - 'chain'
  - 'ocr'
  # Optional and highly experimental: reuse a user-, agent-and-user-, or
  # conversation-scoped workspace. Requires LIBRECHAT_CODE_BASEURL_STATEFUL
  # or a named statefulCodeSessions environment.
  # - 'stateful_code_sessions'
  # Optional: allow eligible Code Interpreter, MCP, Plugin, and Action tools to run as background tasks.
  # - 'run_in_background'
  # Optional: show live model-written intent labels for native and selected MCP tools.
  # - 'tool_intents'
```

**Lưu ý:** Trường này là tùy chọn. Nếu bỏ qua, hành vi mặc định là bao gồm tất cả các khả năng được liệt kê trong phần mặc định.

## statefulCodeSessions

Cấu hình phạm vi chia sẻ và các backend thực thi tùy chọn cho các không gian làm việc Code Interpreter có trạng thái mang tính thử nghiệm cao.

<Callout type="warning" title="Rất thử nghiệm">
  Stateful Code Sessions, các môi trường thực thi được đặt tên, worker đính kèm và tính năng ghép nối đang trong giai đoạn thử nghiệm sớm. Hành vi, cấu hình, đặc điểm duy trì và giao thức tích hợp của chúng có thể thay đổi đáng kể.
</Callout>

Các môi trường đính kèm chấp nhận `environments[].configSchema.limits.maxQueueWaitMs`, tham số này kiểm soát thời gian một yêu cầu có thể thử lại trong khi chờ dung lượng không gian làm việc. Giá trị mặc định và tối đa là `300000` mili giây (5 phút). Đặt thành `0` để tắt tính năng thử lại của máy khách sau lần thử tiếp nhận ban đầu; thao tác này không hủy công việc đã được tiếp nhận hoặc đang chạy. Các trường này thuộc về `configSchema.limits`, **không phải** `userConfig.bash`.

`environments[].configSchema.limits.maxRequestTimeoutMs` tùy chọn giới hạn **tổng thời gian HTTP cho một lệnh gọi công cụ trong không gian làm việc**, bao gồm tiếp nhận, thực thi, giải quyết và phân phối. Nó chấp nhận giá trị từ `1` đến `610000` ms, nhưng cấu hình sẽ từ chối các ngân sách quá nhỏ, không để lại thời gian thực thi lệnh sau khi tiếp nhận và khoản dự phòng 10 giây cho việc giải quyết/phân phối. Nếu không có tham số này, việc tiếp nhận vẫn có ngân sách 30 giây cho mỗi lần thử; `maxQueueWaitMs` vẫn là một khoảng thời gian thử lại riêng biệt. **Đừng bật thời gian tiếp nhận dài hơn** cho đến khi mọi bản sao LibreChat API hiểu được trường này, tuyến đường Code API tuân thủ các hạn mức hàng đợi trên mỗi yêu cầu và thời gian chờ ngắn nhất trên đường dẫn proxy/ingress trực tiếp đã được đo lường. Một thay đổi (mutation) đã hết hạn có thể đã hoàn tất trên worker, vì vậy LibreChat không thử lại đối với một lỗi timeout không xác định.

Với tổng ngân sách yêu cầu, `environments[].configSchema.limits.minCommandAdmissionMs` dành riêng thời gian để một lệnh đi vào worker trước khi quá trình thực thi bắt đầu. Giá trị mặc định là `10000` ms; hãy đặt trong khoảng `1000`–`300000` ms. Tổng ngân sách yêu cầu phải **vượt quá** mức cho phép này cộng với 10000 ms thời gian chờ xử lý/phân phối; nếu không có tổng ngân sách, cài đặt này sẽ không có hiệu lực. Giới hạn thực thi Bash được thông báo cho một Agent là giá trị nhỏ hơn giữa mức trần đã cấu hình hoặc mức trần từ upstream và thời gian còn lại sau khi trừ đi các khoản dự phòng đó. Ví dụ, với ngân sách yêu cầu 90000 ms, mức trần lệnh 80000 ms và mức dự phòng mặc định, thời gian lệnh tối đa được thông báo là 70000 ms.

```yaml filename="endpoints / agents / statefulCodeSessions"
statefulCodeSessions:
  allowedEnvironments:
    - 'user'
    - 'agent-user'
    - 'conversation'
  principalWorkers:

    - id: personal-workers
      name: Personal Code Workers
      type: attached
      baseURL: https://code-bridge.example.com/v1

        limits:
```

`allowedEnvironments` là bắt buộc bất cứ khi nào khối này xuất hiện và phải bao gồm ít nhất một phạm vi workspace. Hãy bỏ qua toàn bộ khối này để cho phép cả ba phạm vi và tiếp tục định tuyến công việc có trạng thái thông qua [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint). Mặc định cá nhân và Agent Builder chỉ cho phép các giá trị được cho phép. Nếu quản trị viên thắt chặt chính sách, mặc định cá nhân đã lưu vẫn hiển thị nhưng bị vô hiệu hóa, và các Agent mới sẽ sử dụng phạm vi được cho phép đầu tiên. Các Agent đã được kích hoạt hiện có vẫn giữ nguyên phạm vi đã lưu của chúng, nhưng một phạm vi không còn được cho phép sẽ bị chặn tại thời điểm chạy cho đến khi Agent được cấu hình lại.

`conversationMoves.enabled: true` cho phép chủ sở hữu cuộc trò chuyện di chuyển một workspace đã đính kèm bị khóa sang một môi trường tương thích và khôi phục workspace bị thiếu mà không cần thay thế lịch sử trò chuyện hoặc khôi phục các tệp workspace cũ. Để cho phép thêm một cuộc trò chuyện đã lưu **đính kèm** (attach) một workspace hoặc **rời khỏi** (leave) một workspace cho trò chuyện bình thường, hãy đặt `conversationMoves.allowAttachDetach: true`. Cả hai tùy chọn này đều bị tắt theo mặc định; việc chỉ bật tính năng di chuyển sẽ giữ nguyên hành vi chỉ di chuyển. Hãy nâng cấp **tất cả** các bản sao API, sau đó bật [`CODE_ENVIRONMENT_DECISION_VERSION=1`](/docs/configuration/dotenv#code-interpreter) trước khi chọn tham gia. Quyền sở hữu, quyền truy cập mục tiêu, công việc đang hoạt động và chính sách hiện tại sẽ được kiểm tra lại tại thời điểm chuyển đổi; một quá trình tạo nội dung đang chạy không thể bị di chuyển.

```yaml filename="endpoints / agents / statefulCodeSessions / conversationMoves"
statefulCodeSessions:
  allowedEnvironments: ['user', 'agent-user', 'conversation']
  conversationMoves:
    enabled: true
    allowAttachDetach: true
```

`principalWorkers` kiểm soát việc tự đăng ký cho các worker cá nhân được đính kèm. Các giá trị bị bỏ qua sẽ mặc định là `enabled: true` và `maxPerUser: 5`; hãy đặt `enabled: false` hoặc `maxPerUser: 0` để dừng việc đăng ký mới. Giới hạn này tính trên mọi môi trường cá nhân đã đăng ký của người dùng đó trên các control plane đã cấu hình, bao gồm cả các worker ngoại tuyến. Việc giảm giới hạn hoặc vô hiệu hóa đăng ký sẽ không thu hồi các môi trường hiện có.

Deployment YAML là giới hạn tối đa cứng. Cấu hình ghi đè cho vai trò, nhóm hoặc người dùng có thể vô hiệu hóa việc đăng ký hoặc giảm `maxPerUser`, nhưng không thể tăng giá trị triển khai. Người dùng chỉ nhìn thấy các control plane đã bật tính năng ghép nối khi giới hạn hiệu dụng lớn hơn không, [`pairing.allowPrincipalWorkers`](#statefulcodesessions) được bật trên control plane đó, xác thực chính (principal authentication) khả dụng và người dùng có quyền quản lý Code Environment.

Khi `environments` không trống, mỗi mục nhập yêu cầu một `id` duy nhất, một `name` hiển thị, một `type` là `managed` hoặc `attached`, và một `baseURL` HTTP(S) không chứa chuỗi truy vấn hoặc đoạn mã (fragment). Nếu danh sách chứa các môi trường có thể thực thi, chính xác một trong các mục nhập đó phải đặt `default: true`. Agent Builder sau đó sẽ thêm bộ chọn **Execution environment**; việc để ở chế độ **Deployment default** sẽ sử dụng mục nhập mặc định đó. Một danh sách chỉ chứa các control plane ghép nối tự phục vụ (self-service pairing) thì không cần mặc định. Một Agent chỉ định một môi trường sau đó bị xóa hoặc không còn truy cập được sẽ thất bại ở trạng thái đóng (fails closed) thay vì chuyển sang một backend khác.

- `managed` trỏ trực tiếp đến một Code API có trạng thái do operator quản lý.
- `attached` trỏ đến một backend `remote-bridge` của Code API tương thích, thực hiện cấp phát công việc cho một worker `@librechat/code` gửi đi. Worker này không yêu cầu cổng công khai gửi đến, nhưng endpoint thực thi cục bộ của nó vẫn cần sự cô lập thích hợp.
- `workerId` tùy chọn định tuyến một môi trường được đính kèm đến một worker gửi đi. Nó chỉ dành cho máy chủ và không được hiển thị thông qua cấu hình khởi động của client.
- `owner` mặc định là `deployment`. Các môi trường do chủ sở hữu quản lý được tạo thông qua Code Environments API đã xác thực của LibreChat, được bảo vệ bởi ACL và chỉ được hợp nhất cho các yêu cầu được ủy quyền; không đặt các URL do khách hàng cung cấp vào tệp deployment YAML.
- `pairing` là tùy chọn và chỉ hợp lệ cho các mục `attached` thuộc quyền sở hữu của quá trình triển khai. `pairing.workerId` xác định một worker do người vận hành quản lý để đăng ký, trong khi `pairing.allowPrincipalWorkers: true` cho phép người dùng được ủy quyền đăng ký các worker bị ràng buộc với chủ sở hữu vào control plane đó. Ít nhất một trong các trường này là bắt buộc khi `pairing` xuất hiện.
- `pairing.tokenEnv` đặt tên cho biến môi trường chứa mã thông báo quản trị viên bridge; nó không bao giờ chứa chính mã thông báo đó. Việc ghép nối yêu cầu HTTPS ngoại trừ đối với quá trình phát triển loopback.
- `configSchema.permissions` cho phép tùy chọn các chủ sở hữu được ủy quyền chọn chính sách `fileWrite` và `commandExecution` cho các môi trường cá nhân trong **Settings > Code environments**. Mỗi trường yêu cầu một danh sách `allowed` không trống chứa `allow`, `ask` và/hoặc `deny`; `default` sẽ là `ask` khi bị bỏ qua và phải xuất hiện trong `allowed`. LibreChat sẽ từ chối các giá trị được lưu trữ nằm ngoài danh sách của quản trị viên.
- `configSchema.limits.maxCommandTimeoutMs` thiết lập thời gian chờ Bash tối đa mà model có thể yêu cầu cho môi trường đó. Nó chấp nhận giá trị từ `1` đến `300000` ms; nếu bỏ qua, hệ thống sẽ giữ nguyên giá trị mặc định là 30 giây. Với tổng ngân sách yêu cầu, thời gian chờ lệnh được quảng cáo cũng sẽ khớp với thời gian còn lại sau khi tiếp nhận, xử lý và gửi lệnh. Đây là giới hạn triển khai và người dùng không thể tự cấu hình.
- `configSchema.workspaces.linkedWorktrees: true` cho phép lập lịch theo từng worktree chỉ đối với các workspace được đính kèm có quảng bá `git_linked_worktree`; việc bỏ qua thiết lập này sẽ giữ tất cả các yêu cầu trong lane gốc của checkout. Hãy nâng cấp LibreChat **trước khi** worker quảng bá phạm vi này, triển khai Code API hỗ trợ các lane linked-worktree, sau đó khởi chạy worker với `--linked-worktree-lanes` trước khi kích hoạt thiết lập YAML. Các thao tác tệp nhắm mục tiêu vào một đường dẫn bên trong `.worktrees/<name>` và các lệnh Bash có `cwd` tại đó sẽ sử dụng lane đó và trả về các đường dẫn tương đối với checkout. Các lệnh thực hiện `cd` bên trong văn bản lệnh, các thao tác tại gốc checkout, các instance workspace của cuộc hội thoại và các hành động môi trường vẫn giữ phạm vi gốc.
- `configSchema.edits.tolerantMatching` cho phép dự phòng linh hoạt với khoảng trắng theo mặc định trên các worker được đính kèm có quảng bá `tolerant_match`; hãy đặt nó thành `false` để yêu cầu khớp chính xác, bao gồm cả các bản xem trước chỉnh sửa được bảo vệ. Việc khớp phải duy nhất trừ khi chỉnh sửa đặt rõ ràng `replace_all`. Các worker cũ hơn sẽ không nhận được các trường khớp mới; `replace_all` được đính kèm sẽ bị từ chối trước khi gửi trừ khi worker quảng bá tính năng đó. Các khả năng này yêu cầu Code API tương thích và các bản dựng worker triển khai [Code Interpreter #271](https://github.com/LibreChat-AI/code-interpreter/pull/271).
- Không cấu hình `settings` trong YAML triển khai. LibreChat cung cấp trường có phạm vi yêu cầu đó từ các tùy chọn ưu tiên đã được máy chủ xác thực của chủ sở hữu.
- Chỉ có chính sách ghi tệp và thực thi lệnh là người dùng có thể cấu hình. Các thiết lập về cô lập, mạng, mount, thực thi đặc quyền, ingress, egress và secrets vẫn do quản trị viên kiểm soát.
- Nếu cả `workerId` cấp cao nhất và `pairing.workerId` đều hiện diện, chúng phải khớp nhau. Một mục có `allowPrincipalWorkers: true` và không có worker ID nào là chỉ dành cho ghép nối (pairing-only): nó sẽ bị loại khỏi các bộ chọn thực thi và không thể đặt `default: true`.

Thực thi đính kèm tự động kích hoạt cơ sở phê duyệt an toàn: các thao tác ghi tệp và thực thi lệnh hoặc mã sẽ yêu cầu xác nhận, trong khi các thao tác chỉ đọc và tìm kiếm vẫn tiếp tục theo chính sách công cụ thông thường. Cơ sở này được giới hạn phạm vi cho Agent sử dụng môi trường đính kèm. Nếu không có cài đặt người dùng nào khả dụng, LibreChat sẽ sử dụng `ask`; [`toolApproval.enabled: false`](#toolapproval) là ghi đè khẩn cấp của quản trị viên giúp vô hiệu hóa cơ sở môi trường đính kèm này. Các trình gọi không có hỗ trợ phê duyệt và tiếp tục sẽ bị từ chối trừ khi ghi đè rõ ràng đó được thiết lập.

Việc thực thi đính kèm yêu cầu một bản dựng experimental Code Interpreter remote-bridge tương ứng. Việc ghép nối sẽ xác thực kết nối worker gửi đi; nó không thay thế sandbox hoặc cách ly VM. Người dùng có quyền quản lý Code Environment sẽ thực hiện ghép nối, định cấu hình chính sách công cụ được phép và thu hồi các worker cá nhân trong **Settings > Code environments**. Xem [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions).

Các phần tiếp nối con (child continuations) được liên kết là tự động. Trường riêng biệt [`backgroundTasks.completionWakeups`](#backgroundtasks) kiểm soát việc phân phối hội thoại cho các công cụ nền đã hoàn thành và các Subagent tách rời.

Để `selfUrl` ở trạng thái không thiết lập cho đường dẫn bound-listener thông thường. Chỉ thiết lập nó khi việc tiếp nhận trigger nội bộ đáng tin cậy phải đi qua một origin HTTP(S) khác, chẳng hạn như TLS front door. `AGENT_TRIGGERS_SELF_URL` vẫn là phương án dự phòng tương thích khi trường này bị bỏ qua. Xem [Agents API events](/docs/features/agents_api#agent-events) và [Automatic Parent Continuation](/docs/features/subagents#automatic-parent-continuation).

`eventDriven.idlePolling` giới hạn việc thăm dò khôi phục trên mỗi bản sao (replica) khi không có gì sẵn sàng: `deliveryMaxIntervalMs` có giá trị mặc định là `15000` (hợp lệ từ `1000`–`300000`), `queuedTurnMaxIntervalMs` và `maintenanceMaxIntervalMs` mỗi giá trị có mặc định là `120000` (hợp lệ từ `30000`–`300000`), và `completionWaitMaxIntervalMs` có giá trị mặc định là `60000` (hợp lệ từ `5000`–`300000`). Giá trị sau cùng giới hạn việc kiểm tra lại trong khi kết quả của tác vụ nền hoặc Subagent đang chờ xử lý hoặc lượt (turn) cha của nó đang bận. Các sự kiện sẵn sàng sẽ đẩy nhanh quá trình phân phối; các giới hạn này duy trì cơ chế dự phòng giữa các bản sao và khôi phục sau sự cố thay vì xác định độ trễ hoàn thành thông thường.

```yaml filename="endpoints / agents / eventDriven / idlePolling"
eventDriven:
  idlePolling:
    deliveryMaxIntervalMs: 15000
    queuedTurnMaxIntervalMs: 120000
    maintenanceMaxIntervalMs: 120000
    completionWaitMaxIntervalMs: 60000
```

Event Actor detached Action completion được chọn tự động từ kho lưu trữ generation tích hợp sẵn. Việc thực thi trong bộ nhớ (in-memory) là cục bộ theo tiến trình; các luồng generation của Redis bổ sung khả năng khôi phục sau khi khởi động lại và chuyển giao bản sao một cách bền vững. Không cần chuyển đổi `librechat.yaml` hoặc cờ tính năng môi trường. Xem [Agent Event Runtime](/docs/configuration/dotenv#agent-event-runtime).

Các tác vụ có artifact trực tiếp vẫn yêu cầu thăm dò (polling) trên lượt chạy sở hữu. Các Subagent tách rời (Detached Subagents) giữ bản ghi bền vững và đường dẫn kết quả cuối cùng riêng biệt của chúng. Việc thăm dò thủ công vẫn khả dụng cho trạng thái, điều khiển và khôi phục ở cả hai chế độ. Xem [Background Tool Calls](/docs/features/agents#background-tool-calls) và [Automatic Parent Continuation](/docs/features/subagents#automatic-parent-continuation).

```yaml filename="endpoints / agents / toolApproval"
toolApproval:
```

```yaml filename="endpoints / agents / toolApproval / hooks"
      matcher: '^mcp:production:'
      options:

```

## maxSubagents

<OptionTable
  options={[
    [

**Mặc định:** `10`

**Phạm vi:** `1-50`

**Ví dụ:**

```yaml filename="endpoints / agents / maxSubagents"
endpoints:
  agents:
    maxSubagents: 20
```

Hãy tăng giá trị này khi một triển khai chạy các tác nhân nặng về điều phối (orchestration-heavy agents) cần ủy quyền cho hơn mười tác nhân con. Giá trị này được đọc khi khởi động và được thực thi tại ba nơi:

- Các yêu cầu tạo, cập nhật và sao chép Agent, dành cho `subagents.agent_ids` và `subagents.graphs`
- Danh sách cho phép `subagents.agent_ids` trong Model Specs, được xác thực trong cùng một lượt cấu hình
- Bảng Agent Builder, nơi ngừng chấp nhận các mục nhập subagent mới tại giá trị đã định cấu hình

Model specs chỉ chấp nhận `enabled`, `allowSelf`, và `agent_ids` trong `subagents`. Các `graphs` của subagent là một tính năng ở cấp độ agent: khóa `graphs` trên một model spec sẽ bị loại bỏ khi cấu hình được phân tích cú pháp mà không báo lỗi.

<Callout type="warning">
  `maxSubagents` phải là một số nguyên từ 1 đến 50. Một giá trị nằm ngoài phạm vi đó sẽ khiến quá trình xác thực `librechat.yaml` thất bại, và LibreChat sẽ ghi lại lỗi rồi thoát khi khởi động thay vì quay về giá trị mặc định. Việc khởi động với `CONFIG_BYPASS_VALIDATION=true` sẽ bỏ qua việc thoát, nhưng toàn bộ cấu hình tùy chỉnh sẽ bị loại bỏ trong trường hợp đó, vì vậy giới hạn sẽ quay về `10`. Để quay lại giá trị mặc định một cách chủ động, hãy xóa khóa này: một `maxSubagents` bị lược bỏ sẽ mặc định là `10` mà không gây ra lỗi.
</Callout>

<Callout type="note">
  Giới hạn này áp dụng trên toàn bộ tiến trình và được lấy từ `librechat.yaml`. Việc ghi đè `endpoints.agents.maxSubagents` trong cơ sở dữ liệu cho mỗi người dùng hoặc mỗi nhóm sẽ được phản ánh trong cấu hình được phục vụ nhưng không được áp dụng bởi quá trình xác thực yêu cầu.
</Callout>

Việc tăng giá trị này chỉ thay đổi số lượng subagent mà một agent có thể tham chiếu. Các giới hạn về độ sâu, nút đồ thị và cấu hình chạy không bị ảnh hưởng. Xem [Subagents](/docs/features/subagents#limits).

## fileSharing

`fileSharing` là tính năng chia sẻ theo phạm vi chạy (run-scoped), tùy chọn (opt-in) dành cho công việc của Agent được ủy quyền. Hãy đặt `enabled: true` tại đây và bật `subagents.shareFiles` trên mỗi Agent ủy quyền. Các đầu vào là chỉ đọc đối với người nhận; các đầu ra vẫn ở chế độ riêng tư trừ khi được xuất bản công khai, và các tệp đã xuất bản vẫn có thể tải xuống sau khi quá trình chạy kết thúc.

```yaml filename="endpoints / agents / fileSharing"
endpoints:
  agents:
    fileSharing:
      enabled: true
      allowSiblingSharing: false
      maxFiles: 100
      maxPrivateBytes: 268435456
      ttlMs: 3600000
```

`allowSiblingSharing` cho phép các đối tượng nhận là anh em hoặc hậu duệ được chỉ định rõ ràng. `maxFiles` nằm trong khoảng từ `1` đến `1000`; `maxPrivateBytes` giới hạn các bản chụp đầu ra riêng tư được lưu giữ; và `ttlMs` là thời gian tồn tại của manifest đang hoạt động, tối đa là 24 giờ. Việc bỏ qua khối này sẽ khiến tính năng chia sẻ bị vô hiệu hóa.

## Khả năng của Agent [#agent-capabilities]

Trường `capabilities` cho phép bạn bật hoặc tắt các chức năng cụ thể cho các tác nhân (agents). Các khả năng khả dụng bao gồm:

- **deferred_tools**: Cho phép các agent khám phá các MCP tool bị trì hoãn (deferred) tại thời điểm chạy thay vì tải mọi tool vào ngữ cảnh ngay từ đầu.
- **programmatic_tools**: Cho phép Gọi Công cụ Lập trình (Programmatic Tool Calling) đối với các công cụ MCP được đánh dấu là Programmatic trong Agent Builder. Yêu cầu `execute_code` và một triển khai Code Interpreter với thành phần Tool Call Server. Tính năng này là tùy chọn và không được bật theo mặc định.
- **execute_code**: Cho phép tác nhân (agent) thực thi mã.
- **stateful_code_sessions**: Cho phép các agent đã chọn tham gia sử dụng lại một workspace Code Interpreter theo phạm vi người dùng, agent-và-người dùng, hoặc cuộc hội thoại. Yêu cầu `execute_code`, một triển khai Code Interpreter tương thích và cài đặt Advanced cho từng agent. Các Agent mới sử dụng phạm vi ưu tiên của người dùng đã đăng nhập. Tính năng này mang tính thử nghiệm cao, không được bật theo mặc định và có thể thay đổi đáng kể trong quá trình thử nghiệm; đừng coi hành vi hoặc cấu hình hiện tại của nó là một hợp đồng sản xuất ổn định.
- **file_search**: Cho phép agent tìm kiếm và tương tác với các tệp tin. Khi được bật, hành vi trích dẫn sẽ được kiểm soát bởi các cài đặt `maxCitations`, `maxCitationsPerFile` và `minRelevanceScore`.
- **web_search**: Kích hoạt chức năng tìm kiếm web cho các tác nhân (agents), cho phép chúng tìm kiếm và truy xuất thông tin từ internet.
- **artifacts**: Cho phép tác nhân tạo ra các artifacts tương tác (các thành phần React, HTML, sơ đồ Mermaid).
- **subagents**: Cho phép chạy các agent con trong ngữ cảnh biệt lập. Xem [Subagents](/docs/features/subagents).
- **actions**: Cho phép tác nhân thực hiện các hành động được xác định trước.
- **context**: Kích hoạt chức năng "Upload as Text" (Tải lên dưới dạng văn bản) trong trò chuyện và "File Context" (Ngữ cảnh tệp) cho các tác nhân (agents), cho phép người dùng tải lên các tệp tin để nội dung của chúng được trích xuất và đưa trực tiếp vào cuộc trò chuyện.
- **skills**: Kích hoạt Skills trong bảng điều khiển bên, gọi thủ công bằng `$`, các kỹ năng do model gọi và danh sách cho phép kỹ năng của agent. Xem [Skills](/docs/features/skills).
- **memory**: Cho phép các agent sử dụng `set_memory` và `delete_memory` khi memory được cấu hình và người dùng có quyền truy cập. Được bật theo mặc định; bị loại bỏ tại thời điểm chạy khi memory bị vô hiệu hóa.
- **ask_user_question**: Cho phép các agent tạm dừng để đặt từ một đến bốn câu hỏi liên quan trong một biểu mẫu duy nhất và tiếp tục với các câu trả lời. Được bật theo mặc định.
- **tools**: Cấp cho tác nhân quyền truy cập vào các công cụ khác nhau.
- **chain**: Kích hoạt tính năng Beta cho việc tạo chuỗi tác nhân (agent chaining), còn được gọi là quy trình làm việc Mixture-of-Agents (MoA).
- **ocr**: Tùy chọn nâng cao tính năng "Tải lên dưới dạng văn bản" (Upload as Text) trong trò chuyện và "Ngữ cảnh tệp" (File Context) cho các tác nhân (agents), cho phép tải tệp lên và xử lý bằng OCR. **Yêu cầu phải cấu hình một dịch vụ OCR.**
- **run_in_background**: Cho phép thực thi Code Interpreter và các công cụ shell chạy ngầm theo mặc định, đồng thời kích hoạt tùy chọn chạy ngầm cho từng công cụ đối với các công cụ MCP, Plugin và Action đủ điều kiện. Một công tắc ở cấp độ Action sẽ chọn tham gia cho mọi thao tác đủ điều kiện; các OAuth Action và các thao tác đã xác định tham số `run_in_background` sẽ bị loại trừ. Một tác nhân (agent) có thể chọn không sử dụng Code Interpreter một cách rõ ràng. Cài đặt này cho phép thực thi ngầm; mô hình sẽ quyết định việc có sử dụng tính năng này hay không cho mỗi lần gọi. Yêu cầu `execute_code` và một triển khai Code Interpreter đã được cấu hình cho mã nguồn. Khả năng này không được bật theo mặc định.
- **tool_intents**: Thêm các nhãn ý định (intent labels) do mô hình viết trực tiếp vào các lệnh gọi công cụ đủ điều kiện. Các công cụ gốc, bao gồm cả công cụ Code Interpreter, sẽ tự động tham gia; các công cụ MCP có thể được bật riêng lẻ hoặc hàng loạt trong Agent Builder. Model specs sử dụng `describeIntent`. Tính năng này không được bật theo mặc định.

Bằng cách chỉ định các capabilities, bạn có thể kiểm soát các tính năng khả dụng cho người dùng khi tương tác với các agent.

## Cấu hình ví dụ [#example-configuration]

Dưới đây là ví dụ về cách cấu hình endpoint `agents` với các khả năng tùy chỉnh và cài đặt trích dẫn tệp:

```yaml filename="Agents Endpoint"
endpoints:
  agents:
    disableBuilder: false
    # File citation configuration
    maxCitations: 20
    maxCitationsPerFile: 5
    minRelevanceScore: 0.6
    # Custom capabilities
    capabilities:
      # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
      # - 'programmatic_tools'
      - 'execute_code'
      # Optional: makes Code Interpreter background-eligible and enables selected MCP, Plugin, and Action tools.
      # - 'run_in_background'
      # Optional: enables live intent labels for native and selected MCP tools.
      # - 'tool_intents'
      - 'file_search'
      - 'skills'
      - 'subagents'
      - 'actions'
      - 'artifacts'
      - 'context'
      - 'ocr'
      - 'web_search'
```

Trong ví dụ này:

- Giao diện trình tạo đã được bật
- Các trích dẫn tệp bị giới hạn ở mức 20 trích dẫn, với tối đa 5 trích dẫn cho mỗi tệp
- Chỉ các nguồn có độ liên quan từ 60% trở lên mới được bao gồm
- Các Agent của LibreChat có quyền truy cập vào thực thi mã, tìm kiếm tệp (có trích dẫn), Skills, Subagents, actions, artifacts, ngữ cảnh tệp, các dịch vụ ocr nếu được cấu hình và khả năng tìm kiếm web.
- Programmatic Tool Calling vẫn bị vô hiệu hóa trừ khi bạn thêm khả năng `programmatic_tools` cùng với `execute_code`
- Các lệnh gọi công cụ trong nền vẫn bị vô hiệu hóa trừ khi bạn thêm `run_in_background`; các công cụ Code Interpreter sau đó sẽ mặc định trở nên đủ điều kiện, trong khi các công cụ MCP, Plugin và Action đủ điều kiện vẫn yêu cầu phải được chọn.
- Các nhãn ý định công cụ (tool intent labels) vẫn bị vô hiệu hóa trừ khi bạn thêm `tool_intents`; các công cụ gốc (native tools) sau đó sẽ tự động chọn tham gia, trong khi các công cụ MCP vẫn yêu cầu lựa chọn cho từng công cụ.

## managementApi

API Quản lý Agent bản beta cho phép các máy khách đáng tin cậy tạo, liệt kê, đọc, cập nhật và xóa các Agent, quản lý tệp của chúng, cũng như khám phá hoặc chỉnh sửa các Skill có thể truy cập.           - clientId: machine-client-id

```yaml filename="endpoints / agents / managementApi"
            tenantId: tenant-id
            enabled: true
```

**Ví dụ - Chỉ OIDC:**

```yaml filename="endpoints / agents / remoteApi"
endpoints:

          enabled: false
        oidc:
          enabled: true
          issuer: https://auth.example.com/realms/myrealm
          audience: my-client-id
```

**Ví dụ - OIDC với dự phòng API key:**

```yaml filename="endpoints / agents / remoteApi"
endpoints:
  agents:
    remoteApi:
      auth:
        apiKey:
          enabled: true
        oidc:
          enabled: true
          issuer: https://auth.example.com/realms/myrealm
          # jwksUri is optional and auto-discovered if omitted
          jwksUri: https://auth.example.com/realms/myrealm/protocol/openid-connect/certs
          audience: my-client-id
```

<Callout type="info">
  Thứ tự ưu tiên phân giải JWKS URI là `jwksUri` tường minh, sau đó đến `OPENID_JWKS_URL`, và cuối cùng là tự động khám phá thông qua `{issuer}/.well-known/openid-configuration`.
</Callout>

<Callout type="info">
  Việc khớp người dùng OIDC sử dụng claim `sub` làm phương thức tra cứu chính, với phương thức dự phòng là các claim `email`, `preferred_username`, hoặc `upn`. Người dùng được khớp phải đã tồn tại trong LibreChat.
</Callout>

## Ghi chú [#notes]

- Không khuyến khích việc vô hiệu hóa giao diện trình tạo (builder interface) trừ khi bạn đang sử dụng [modelSpecs](/docs/configuration/librechat_yaml/object_structure/model_specs) để xác định danh sách các tác nhân (agents) để lựa chọn.
- Cấu hình trích dẫn tệp (`maxCitations`, `maxCitationsPerFile`, `minRelevanceScore`) chỉ áp dụng khi khả năng `file_search` được bật.
- Điểm mức độ liên quan được tính toán bằng cách sử dụng độ tương đồng vector, trong đó 1.0 đại diện cho một kết quả khớp hoàn hảo và 0.0 đại diện cho không có sự tương đồng nào.
- Các giới hạn trích dẫn giúp cân bằng giữa việc truy xuất thông tin toàn diện với chất lượng và hiệu suất phản hồi.
- Khả năng `context` hoạt động mà không cần cấu hình OCR bằng cách sử dụng các phương thức phân tích văn bản. OCR giúp nâng cao chất lượng trích xuất khi được cấu hình.
- Tính năng `ocr` yêu cầu phải cấu hình một dịch vụ OCR (xem [OCR Configuration](/docs/configuration/librechat_yaml/object_structure/ocr)).
- `maxSubagents` giới hạn số lượng subagent mà một agent đơn lẻ có thể tham chiếu. Nó không thay đổi độ sâu hoặc các giới hạn đồ thị đã được ghi lại trong [Subagents](/docs/features/subagents#limits).
