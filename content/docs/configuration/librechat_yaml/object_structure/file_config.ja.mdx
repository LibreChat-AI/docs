## 概要 [#overview]

`fileConfig` オブジェクトを使用すると、サイズ制限やMIMEタイプの制限など、アプリケーションのファイル処理設定を構成できます。このセクションでは、`fileConfig` オブジェクトの構造について詳しく解説します。

以下の `fileConfig` の主なフィールドについて説明します:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**注記:**

- 執筆時点で、Assistants endpoint は [こちらのリストにあるファイルタイプをサポートしています](https://platform.openai.com/docs/assistants/tools/file-search#supported-files)。
- OpenAI、Azure OpenAI、Google、およびカスタムのendpointは、[RAG API](../../rag_api.mdx)を通じてファイルをサポートしています。
- OpenAI、Azure OpenAI、Anthropic、Google、AWS Bedrock、およびカスタムエンドポイントは、[Upload to Provider](/docs/features/ocr#upload-to-provider-instead)を通じた直接のファイルアップロードに対応しています。
- `ocr` および `text` セクションは、[テキストとしてアップロード](/docs/features/upload_as_text)や[OCR](/docs/features/ocr)などの機能におけるファイル処理を制御します。
- Pluginsなど、言及されていないその他のendpointは、（現時点では）ファイルアップロードをサポートしていません。
- Assistants endpoint は、定義された endpoint 値として `assistants` を使用します。その他のすべての endpoint は、定義された値 `default` を使用します。
  - アシスタント以外のendpointについては、`default`の下ですべてのファイル設定を調整できます。
  - 特定の endpoint の設定を調整したい場合は、対応する endpoint 名をリストアップすることができます。
    - `assistants`
        - 他のものとは別にデフォルトが定義されているため、"default" は使用しません。
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- 値を省略することも可能です。その場合、アプリは以下に記載されている各endpointタイプごとに定義されたデフォルト値を使用します。
- LibreChatでは、1メガバイトを `1 x 1024 x 1024` として計算します。
- 長時間実行されるアップロードレスポンスのストリーミングおよびサーバーサイドのリモートURLフェッチ制限は、[`FILE_UPLOAD_SSE_ENABLED`、`REMOTE_FILE_FETCH_TIMEOUT_MS`、および `REMOTE_FILE_FETCH_MAX_BYTES` 環境変数](/docs/configuration/dotenv#file-uploads)で設定されます。

## 例 [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="MIMEパターンの構文">
  LibreChatは、管理者が設定した `supportedMimeTypes` パターンを、RE2互換の線形時間正規表現エンジンを使用してサーバー上で評価します。後方参照（backreferences）および先読み・戻り読み（lookaround）はサポートされていません。すべてのパターンは設定の検証時にアクティブなエンジンでコンパイルされます。サポートされていないパターンが含まれている場合、その設定は無視されることなく拒否されます。
</Callout>

## skills

<OptionTable
  options={[
    ['skills', 'Object', '`.md`、`.zip`、または `.skill` ファイルとしてアップロードされるスキルインポートの設定。', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` は3つのパラメータをサポートします:

- `fileSizeLimit` (Number)
  - 単一のSkillアップロードの最大サイズ（メガバイト（MB）単位）。
  - **デフォルト:** `50`
- `importCleanupConcurrency` (整数)
  - Skillアーカイブのインポート失敗後の最大同時クリーンアップ操作数。シリアル（逐次）クリーンアップを行う場合は `1` を使用してください。
  - **デフォルト:** `8`
- `deletionCleanupConcurrency` (整数)
  - Skill が削除されたときに同時に実行されるクリーンアップ処理の最大数です。直列でクリーンアップする場合は `1` を指定してください。
  - **デフォルト:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

ファイルごとの制限やアーカイブエントリの制限など、その他のインポートルールについては[Skills](/docs/features/skills)を参照してください。

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', '画像生成の出力品質および寸法に関する設定。', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` は以下のパラメータをサポートしています：

- `percentage` (Number)
  - 生成された画像の出力サイズをパーセンテージで表したもの（例: `100` は基本サイズの100%を意味します）。
  - デフォルトまたは元のサイズに対して出力画像を拡大・縮小するには、これを使用します。

- `px`(数値)
  - 出力画像の寸法をピクセル単位で指定します（例: `1024`）。
  - ベースサイズに関係なく、生成される画像の出力サイズを明示的に設定するためにこれを使用します。

1つのパラメータのみを設定してください(`percentage` または `px` のどちらか)。両方を設定しないでください。

設定例:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

クライアント側でのアップロード前の画像リサイズを制御します。これにより、サイズの大きすぎる画像によるアップロードエラーを防ぎます。ユーザーは「設定 > チャット」でリサイズのオン/オフを切り替えられます。ここで`enabled`を設定すると、その選択はすべてのユーザーに対して上書きされ、切り替えスイッチはロックされます。省略した場合は、ユーザーが自分で制御できます。

- `enabled` (Boolean)
  - 強制的にリサイズを有効(`true`)または無効(`false`)にし、全ユーザーに適用します。省略した場合は、各ユーザーが設定を選択でき、デフォルトではリサイズが有効になります。
- `maxWidth` (Number)
  - リサイズ後の画像の最大幅（ピクセル単位）。最小値は `1`。**デフォルト:** `1900`
- `maxHeight` (Number)
  - リサイズされた画像の最大の高さ（ピクセル単位）。最小値は `1`。**デフォルト:** `1900`
- `quality` (Number)
  - JPEG圧縮品質（`0`から`1`まで）。**デフォルト:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## fileContextSizeLimit

<OptionTable
  options={[
    ['fileContextSizeLimit', 'Number', '1つのAgentターンで許可される、モデルに関連付けられた添付ファイルの合計最大サイズ（メガバイト単位）。', '128'],

/>

**デフォルト:** `128` MB。これはターンごとのプロンプト安全上限であり、アップロードストレージの制限とは別個のものです。埋め込みファイル検索リソース、コードワークスペースの参照、およびモデルコンテキストに入らないファイルは除外されます。設定されたエンドポイントの `totalSizeLimit` により、そのエンドポイントに対してより低い合計バイト制限を課すことができます。

```yaml filename="fileConfig / fileContextSizeLimit"
fileConfig:
  fileContextSizeLimit: 128
```

## fileContextCharLimit

<OptionTable
  options={[
    ['fileContextCharLimit', 'Number', '1つのAgentターンで許容される抽出テキストの最大合計文字数。', '1000000'],
  ]}
/>

**デフォルト:** `1000000`。LibreChatは、保持された会話の添付ファイルやAgentスコープのファイルコンテキストを含む、Agentのプロンプトに入力される抽出テキストに対してこの制限を適用します。繰り返し注入される場合は、それを受け取る各Agentごとにカウントされます。いずれかのコンテキスト制限を超過した場合、モデルが呼び出される前に添付ファイル制限エラーが発生し、ターンが停止します。

```yaml filename="fileConfig / fileContextCharLimit"
fileConfig:
  fileContextCharLimit: 1000000
```

## textFallbackWithoutTools

アップロードが `none`（保存のみ、ツールからのみ利用可能）にルーティングされ、そのターンで内容を読み取れるツールが実行されない場合、LibreChat は代わりにファイルから抽出されたテキストを提供できます。これを有効にするには `textFallbackWithoutTools: true` を設定します。`fileConfig` の下でグローバルに設定することも、`fileConfig.endpoints`（`default` を含む）の各エントリごとに設定することもできます。エンドポイントの値はグローバルの値よりも優先されます。

**デフォルト:** `false`

これは、ルートが推論された（自動判定された）メッセージ添付ファイルにのみ適用されます。ユーザーが明示的に選択した宛先は再判定されることはなく、エージェントのツールリソースに保持されたファイルがプロンプトに渡されることもありません。ツール向けのファイルについては、組み込みのドキュメントおよびプレーンテキスト抽出機能のみが実行されるため、RAGやOCRの呼び出しは行われません。抽出済みテキストを持たない既存のファイルに対して、後から遡ってテキストが生成されることはありません。

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

コード実行環境にプロビジョニングされたファイルのうち、このウィンドウ(ミリ秒単位)内のものは、再利用前のライブ可用性チェックをスキップします。最小値は `0` です。

**デフォルト:** `21600000`(6時間)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

ミリ秒単位で、プライミングがレガシーのFile Searchの利用可能性チェックを待つ時間を指定します。この時間を過ぎると、ファイルを埋め込み処理します。最小値は`1`です。

**デフォルト:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', 'OCRを使用しない直接的なテキストファイル解析のための設定。', 'Configures which file types are processed as plain text files for direct content extraction.'],
  ]}
/>

**説明:** `text` セクションでは、直接的なテキスト抽出を使用して処理するファイルタイプを設定します。

**注意:** テキスト解析は、「テキストとしてアップロード」機能(`context` 機能によって制御)で使用されるデフォルトの方法です。詳細は[テキストとしてアップロード](/docs/features/upload_as_text)を参照してください。

- デフォルトのリストには、整形式のすべてのMIMEタイプが一致します。すでにテキストであるファイル(`text/*`、JSON、YAML、XML、SQL、シェルスクリプト、`.eml`メールなど)は直接読み込まれます。パーサーのないその他のバイナリタイプは、文字化けしたデータにデコードされるのではなく、拒否されます。
- RAG API が設定されている場合（`RAG_API_URL`）、リストを絞り込むと、一致するファイルは RAG API のテキスト抽出に送信されます。RAG API が利用できない場合、LibreChat は組み込みのドキュメントパーサーにフォールバックします。

## stt

`fileConfig.stt` は、現在のバージョンの LibreChat では読み込まれません。ここに `stt` ブロックを記述しても無視されます。テキストとして追加された音声ファイルは、[`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech) で音声認識プロバイダーが設定されている場合に文字起こしされます。対象となる音声形式は、組み込みのリストで定義されており、MP3、MPEG、WAV、OGG、Vorbis、MP4 および M4A 音声、FLAC、WebM、AAC、WMA、Opus です。

## ファイル処理の優先順位 [#file-processing-priority]

ファイルがテキストとして追加される場合（「テキストとしてアップロード」、長いペースト、またはエージェントのファイルコンテキスト）、LibreChat は該当する最初のステップを使用します。

1. **OCR**: `librechat.yaml` に `ocr` セクションが存在し、ファイルが `fileConfig.ocr.supportedMimeTypes` に一致する場合に使用されます。OCR サービスが失敗した場合は、次に組み込みのドキュメントパーサーが試行されます。
2. **RAG API テキスト抽出**: `text.supportedMimeTypes` がデフォルトから絞り込まれており、RAG API が設定されていて、ファイルがそのリストに一致する場合。
3. **組み込みのドキュメントパーサー**: PDF、DOCX、XLS、XLSX、ODT、ODS ファイルに対応しています。テキストレイヤーのみを読み取ります。
4. **音声からテキストへの変換 (Speech-to-text)**: STTプロバイダーが設定されている場合、音声ファイル。
5. **テキスト解析**: `text.supportedMimeTypes` に一致するファイル。

OCR が設定されていない場合、画像やスキャンされた PDF からはテキストを抽出できないため、アップロードは失敗し、OCR サービスが必要であることを示すメッセージが表示されます。

  options={[

**説明:** デフォルトでは、添付メニューに**ローカルコンピュータから**が表示され、LibreChatは`defaultLLMDeliveryPath`に従って、ファイルごとにモデルへの渡し方を決定します。ファイル検索およびコードのリソースは、選択されたツールがファイルを必要とする場合にのみプロビジョニングされます。`legacyFileUploadUX: true`を指定すると、ユーザーが自身でアップロード先を選択でき、アップロードは直ちにその先へ送られ、明示的な**テキストとしてアップロード**オプションが表示されます。エンドポイント単位の値は、トップレベルの値より優先されます。

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
  endpoints:
    anthropic:
      legacyFileUploadUX: false
```

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', 'ユーザーが送信先を選択しなかった場合に、添付ファイルがモデルへどのように届くか。', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

次の内容を日本語に翻訳してください:

各値は次のいずれかです:

- `provider`: ファイルはネイティブな添付ファイルとしてモデルに送信されます(画像、PDF、音声、または動画の入力)。
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`: ファイルは保存され、コード実行やファイル検索などのツールから利用できますが、モデルには送信されません。

`overrides` は MIME タイプ、または `type/*` 形式のワイルドカードを値にマッピングします。`fallback` は、リストに含まれないすべてのものに適用されます。LibreChat は、エンドポイントの overrides、次にエンドポイントの fallback、続いてトップレベルの overrides、次にトップレベルの fallback、最後に組み込みのデフォルトの順に確認します。

デフォルトの組み込み設定では、画像、音声、動画、PDF はプロバイダーに送信され、それ以外のファイルはテキストとして送信されます。また、エンドポイントに応じて調整が行われます。PDF を読み取れないプロバイダーでは、PDF はテキストとして送信されます。メディア対応のないプロバイダーでは、音声や動画は文字起こしされるか、プロンプトから除外されます。AWS Bedrock は、対応するドキュメントタイプをネイティブに受け取ります。テキストを抽出する手段がない種類のファイル(たとえばアーカイブ)は `none` に設定されます。設定した値は、これらの調整を行わずに、記述どおりにそのまま使用されます。

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

  - `disabled`

  - `fileLimit`

  - `totalSizeLimit`

## 保持されたファイルとベクトルのクリーンアップ [#retained-file-and-vector-cleanup]

ファイルの削除では、セカンダリストレージのクリーンアップが確認されるまで、読み取り可能なプライマリを保持します。`fileConfig.retainedFileCleanup` の既定値は `false` です。明示的に有効化されるまで、埋め込みファイルおよび保持された Code Interpreter の保存先は破壊的にクリーンアップされません。すべてのレプリカとロールバック対象が保持されたファイルの保存先を読み取れるようになった後にのみ、有効化してください。

| フィールド | デフォルト | 意味 |
| ------------------------------ | ------- | -------------------------------------------------------------------------------------------------- |
| `retainedFileCleanup` | `false` | リーダーのロールアウト後に、保持された宛先メタデータを使用したクリーンアップを有効にします(オプトイン)。 |
| `vectorOwnershipTrackingStart` | 未設定 | すべての従来のベクトル書き込み処理および巻き戻し先が廃止された後に選択される、UTC 形式の日時のカットオフ。 |
| `vectorDeletionConcurrency` | `4` | 整数 `1` から `16`。ファイルごとに同時に実行される名前空間削除の最大数。 |

ベクトルの削除には、さらに、安全なライター切り替え時刻（safe writer cutoff）以降に記録された完全な所有権情報と挿入時の証明が必要です。証明が欠落している、無効である、未来の時刻である、または切り替え時刻より前である場合は、フェイルクローズド（安全側に失敗）となり、ファイルとそのベクトルは削除されずに残ります。切り替え時刻を設定しても古い所有権メタデータは修復されず、曖昧なレガシーファイルを対象にするために切り替え時刻を過去に遡って設定してはなりません。

クリーンアップの対象は、記録された各エンティティの名前空間と、名前空間なしのスコープです。名前空間は、DELETE レスポンスが成功した時点でクリーンアップ済みとみなされます。`404` は、同じ名前空間のインベントリ確認が成功し、そのファイルが除外されていることを確認できた場合にのみ、不在として扱われます。セカンダリまたは名前空間のいずれかが不在であることを確認できない場合、プライマリは再試行のために引き続き利用可能な状態に保たれます。これらの設定は従来のレコードへのバックフィルは行いません。曖昧な履歴ファイルについては、別途検証された再照合を計画してください。
