## 概要 [#overview]

`fileConfig` オブジェクトを使用すると、サイズ制限やMIMEタイプの制限など、アプリケーションのファイル処理設定を構成できます。このセクションでは、`fileConfig` オブジェクトの構造について詳しく解説します。

`fileConfig` の主なフィールドは以下のとおりです:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`
  - `stt`

**注記:**

- 執筆時点で、Assistants endpoint は [こちらのリストにあるファイルタイプをサポートしています](https://platform.openai.com/docs/assistants/tools/file-search#supported-files)。
- OpenAI、Azure OpenAI、Google、およびカスタムのendpointは、[RAG API](../../rag_api.mdx)を通じてファイルをサポートしています。
- OpenAI、Azure OpenAI、Anthropic、Google、およびAWS Bedrockの各endpointは、[Upload to Provider](/docs/features/ocr#5-upload-files-to-provider-direct) を介した直接的なファイルアップロードをサポートしています。
- `ocr`、`text`、および `stt` セクションは、[Upload as Text](/docs/features/upload_as_text) や [OCR](/docs/features/ocr) といった機能のファイル処理を制御します。
- Pluginsなど、言及されていないその他のendpointは、（現時点では）ファイルアップロードをサポートしていません。
- Assistants endpoint は、定義された endpoint 値として `assistants` を使用します。その他のすべての endpoint は、定義された値 `default` を使用します。
  - アシスタント以外のendpointについては、`default`の下ですべてのファイル設定を調整できます。
  - 特定の endpoint の設定を調整したい場合は、対応する endpoint 名をリストアップすることができます。
    - `assistants`
        - 他のものとは別にデフォルトが定義されているため、"default" は使用しません。
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- 値を省略することも可能です。その場合、アプリは以下に記載されている各endpointタイプごとに定義されたデフォルト値を使用します。
- LibreChatでは、1メガバイトを `1 x 1024 x 1024` として計算します。
- 長時間実行されるアップロードレスポンスのストリーミングおよびサーバーサイドのリモートURLフェッチ制限は、[`FILE_UPLOAD_SSE_ENABLED`、`REMOTE_FILE_FETCH_TIMEOUT_MS`、および `REMOTE_FILE_FETCH_MAX_BYTES` 環境変数](/docs/configuration/dotenv#file-uploads)で設定されます。

## 例 [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

<Callout type="info" title="MIMEパターンの構文">
  LibreChatは、管理者が設定した `supportedMimeTypes` パターンを、RE2互換の線形時間正規表現エンジンを使用してサーバー上で評価します。後方参照（backreferences）および先読み・戻り読み（lookaround）はサポートされていません。すべてのパターンは設定の検証時にアクティブなエンジンでコンパイルされます。サポートされていないパターンが含まれている場合、その設定は無視されることなく拒否されます。
</Callout>
## skills

<OptionTable
  options={[
    ['skills', 'Object', '`.md`、`.zip`、または `.skill` ファイルとしてアップロードされるスキルインポートの設定。', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` は3つのパラメータをサポートします:

- `fileSizeLimit` (Number)
  - 単一のSkillアップロードの最大サイズ（メガバイト（MB）単位）。
  - **デフォルト:** `50`
- `importCleanupConcurrency` (整数)
  - Skillアーカイブのインポート失敗後の最大同時クリーンアップ操作数。シリアル（逐次）クリーンアップを行う場合は `1` を使用してください。
  - **デフォルト:** `8`
- `deletionCleanupConcurrency` (整数)
  - Skill が削除されたときに同時に実行されるクリーンアップ処理の最大数です。直列でクリーンアップする場合は `1` を指定してください。
  - **デフォルト:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

ファイルごとの制限やアーカイブエントリの制限など、その他のインポートルールについては[Skills](/docs/features/skills)を参照してください。

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', '画像生成の出力品質および寸法に関する設定。', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` は以下のパラメータをサポートしています：

- `percentage` (Number)
  - 生成された画像の出力サイズをパーセンテージで表したもの（例: `100` は基本サイズの100%を意味します）。
  - デフォルトまたは元のサイズに対して出力画像を拡大・縮小するには、これを使用します。

- `px`(数値)
  - 出力画像の寸法をピクセル単位で指定します（例: `1024`）。
  - ベースサイズに関係なく、生成される画像の出力サイズを明示的に設定するためにこれを使用します。

1つのパラメータのみを設定してください(`percentage` または `px` のどちらか)。両方を設定しないでください。

設定例:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

クライアント側でのアップロード前の画像リサイズを制御します。これにより、サイズの大きすぎる画像によるアップロードエラーを防ぎます。ユーザーは「設定 > チャット」でリサイズのオン/オフを切り替えられます。ここで`enabled`を設定すると、その選択はすべてのユーザーに対して上書きされ、切り替えスイッチはロックされます。省略した場合は、ユーザーが自分で制御できます。

- `enabled` (Boolean)
  - 強制的にリサイズを有効(`true`)または無効(`false`)にし、全ユーザーに適用します。省略した場合は、各ユーザーが設定を選択でき、デフォルトではリサイズが有効になります。
- `maxWidth` (Number)
  - リサイズ後の画像の最大幅（ピクセル単位）。最小値は `1`。**デフォルト:** `1900`
- `maxHeight` (Number)
  - リサイズされた画像の最大の高さ（ピクセル単位）。最小値は `1`。**デフォルト:** `1900`
- `quality` (Number)
  - JPEG圧縮品質（`0`から`1`まで）。**デフォルト:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## defaultLLMDeliveryPath

明示的に選択された宛先がないアップロードが、どのようにモデルコンテキストに入るかを制御します。`fileConfig` の下でグローバルに設定するか、`fileConfig.endpoints` の下で名前付きエントリに対して上書き設定します。

- `provider` は、モデルプロバイダーのネイティブなファイルまたはメディアパスを通じて元のファイルを送信します。
- `text` は、サポートされているコンテンツを抽出または文字起こしし、その結果をコンテキストに追加します。
- `none` は、ファイルをモデルのコンテキストに直接配置せずに保存します。選択されたツールが必要に応じてそのファイルを提供できます。

`fallback` は、一致しない MIME タイプを処理します。`overrides` は `application/pdf` のような完全一致の MIME タイプや、`image/*` のようなワイルドカードを受け入れます。解決順序は、endpoint の overrides と fallback が優先され、次にグローバル値が適用されます。明示的な設定がない場合、画像、音声、動画、および PDF はネイティブプロバイダーによる配信が優先され、その他の復元可能なコンテンツはテキストとして扱われます。LibreChat は、抽出が可能な場合はサポートされていないネイティブパスをテキストにダウングレードし、それ以外の場合は `none` に設定します。

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## legacyFileUploadUX

デフォルトの統合アップローダーは、モデルの配信を自動的に選択し、選択されたツールが必要とする場合にのみFile SearchまたはCodeリソースをプロビジョニングします。`legacyFileUploadUX: true`をグローバル、またはエンドポイントごとに設定することで、送信先選択機能と、ユーザーが選択したアップロード動作を復元できます。

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
```

## textFallbackWithoutTools

アップロードが `none`（保存のみ、ツールからのみ利用可能）にルーティングされ、そのターンで内容を読み取れるツールが実行されない場合、LibreChat は代わりにファイルから抽出されたテキストを提供できます。これを有効にするには `textFallbackWithoutTools: true` を設定します。`fileConfig` の下でグローバルに設定することも、`fileConfig.endpoints`（`default` を含む）の各エントリごとに設定することもできます。エンドポイントの値はグローバルの値よりも優先されます。

**デフォルト:** `false`

これは、ルートが推論された（自動判定された）メッセージ添付ファイルにのみ適用されます。ユーザーが明示的に選択した宛先は再判定されることはなく、エージェントのツールリソースに保持されたファイルがプロンプトに渡されることもありません。ツール向けのファイルについては、組み込みのドキュメントおよびプレーンテキスト抽出機能のみが実行されるため、RAGやOCRの呼び出しは行われません。抽出済みテキストを持たない既存のファイルに対して、後から遡ってテキストが生成されることはありません。

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

コード実行環境にプロビジョニングされたファイルのうち、このウィンドウ(ミリ秒単位)内のものは、再利用前のライブ可用性チェックをスキップします。最小値は `0` です。

**デフォルト:** `21600000`(6時間)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

ミリ秒単位で、プライミングがレガシーのFile Searchの利用可能性チェックを待つ時間を指定します。この時間を過ぎると、ファイルを埋め込み処理します。最小値は`1`です。

**デフォルト:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

**説明:** `stt` セクションでは、音声をテキストに変換する Speech-to-Text 機能を使用して処理する音声ファイルの種類を設定します。

### supportedMimeTypes [#supportedmimetypes-2]

<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'STTで文字起こしを行う音声ファイルのMIMEタイプパターンのリスト。', 'Uses regular expressions to match audio file types.'],
  ]}
/>

**デフォルト:** 一般的なオーディオ形式

```yaml filename="fileConfig / stt / supportedMimeTypes"
fileConfig:
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

**注記:**
- `text` パターンに一致するファイルは、単純なテキスト抽出で処理されます。
- `ocr` パターンに一致するファイルは、提供された OCR サービスで処理されます。
- `stt` パターンに一致するファイルは、Speech-to-Text（音声文字起こし）で処理されます。
- **処理の優先順位: OCR > STT > テキスト解析 > フォールバック**
- どのパターンにも一致しないファイルは、テキスト解析にフォールバックされます。

## ファイル処理の優先順位 [#file-processing-priority]

LibreChatは、以下の**優先順位**に従ってMIMEタイプの照合に基づき、アップロードされたファイルを処理します。

1. **OCR** - ファイルが `ocr.supportedMimeTypes` に一致し、かつ OCR が設定されている場合
2. **STT** - ファイルが `stt.supportedMimeTypes` に一致し、かつ STT が設定されている場合
3. **テキスト解析** - ファイルが `text.supportedMimeTypes` に一致する場合
4. **フォールバック** - 最終手段としてのテキスト解析

この処理順序により、特殊なサービス（OCR/STT）が設定されていない場合でも機能を維持しつつ、最適な抽出品質が保証されます。

### 処理の例 [#processing-examples]

**OCRが設定されたPDFファイル:**
- ファイルは `ocr.supportedMimeTypes` に一致します
- **OCRを使用して**テキストを抽出します
- スキャンされたPDFや画像に対するより高い品質

**OCRが設定されていないPDFファイル:**
- ファイルが `text.supportedMimeTypes` に一致する（またはフォールバックを使用する）
- **テキスト解析**ライブラリを使用します
- テキスト選択可能なデジタルPDFでうまく機能します

**Pythonファイル:**
- `text.supportedMimeTypes` に一致するファイル
- **テキスト解析を使用** (OCRは不要)
- 直接テキスト抽出

**STTが設定された音声ファイル:**
- ファイルは `stt.supportedMimeTypes` に一致します
- **STTを使用して**音声をテキストに文字起こしします

**OCRが設定されていない画像ファイル:**
- ファイルは `ocr.supportedMimeTypes` に一致しますが、OCRは利用できません
- **テキスト解析にフォールバックします**
- OCRなしでは抽出機能が制限されます

この優先順位システムにより、「テキストとしてアップロード」のような機能はOCR設定を必要とせずに動作しつつ、利用可能な場合にはOCRを活用して抽出品質を向上させることができます。

## endpoints

<OptionTable
  options={[
    ['endpoints', 'Record/Object', '個々のendpointのファイル処理設定を構成し、endpointごとにカスタマイズできるようにします。', 'Specifies file handling configurations for individual endpoints, allowing customization per endpoint basis.'],
  ]}
/>

**説明:** endpoints 配下の各オブジェクトは、以下の設定を持つことができるレコードです。

### 概要 [#overview-1]

  - `disabled`
      - エンドポイントに対してファイル処理が無効になっているかどうか。
  - `fileLimit`
      - 1回のリクエストでアップロード可能なファイルの最大数。
  - `fileSizeLimit`
      - 1つのファイルの最大サイズ。単位はMBです（例：20メガバイトの場合は `20` と指定します）
  - `totalSizeLimit`
      - 1回のリクエストにおける全ファイルの合計最大サイズ。単位はMBです（例：20メガバイトの場合は `20` と指定してください）。
  - `defaultLLMDeliveryPath`, `legacyFileUploadUX`, `textFallbackWithoutTools`
      - エンドポイントごとの上書き設定。上記で説明した、同名のグローバル設定をエンドポイント単位で上書きします。
  - `supportedMimeTypes`
      - アップロードを許可するMIMEタイプを指定する[Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression)のリストです。これは、ファイルタイプを制限するためにカスタマイズ可能です。

## supportedMimeTypes [#supportedmimetypes-3]

**キー:**
<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'アップロードが許可されるMIMEタイプを定義する正規表現のリスト。', 'Each pattern must compile with the active server regex engine or configuration validation fails.'],
  ]}
/>

**デフォルト:** endpointにより異なります

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
assistants:
  supportedMimeTypes:
      - "image/.*"
      - "application/pdf"
```

LibreChatは、これらのパターンを適用する前に一般的なMIMEエイリアスを正規化します。特に、`application/x-shellscript`（Linux上のChromeで報告される）および`text/x-shellscript`（libmagicで報告される）は、`application/x-sh`に変換されます。したがって、シェルスクリプトを許可するカスタム許可リストでは、正規の`application/x-sh`タイプを許可する必要があります。アップロードが拒否された場合、汎用的なサーバーエラーではなく、報告されたサポート対象外のタイプがクライアントに返されます。
