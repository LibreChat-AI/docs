`webSearch` 구성을 통해 LibreChat 내의 웹 검색 기능을 사용자 정의할 수 있으며, 여기에는 검색 제공자, 콘텐츠 스크레이퍼, 결과 리랭커가 포함됩니다.

## 개요 [#overview]

웹 검색 기능은 세 가지 주요 구성 요소로 이루어져 있습니다:

1. **Search Providers**: 초기 웹 검색을 수행하는 서비스
2. **Scrapers**: 웹 페이지에서 콘텐츠를 추출하는 서비스
3. **Rerankers**: 검색 결과를 더 높은 관련성으로 재정렬하는 서비스

## 예시 [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## SSRF 보호 및 비공개 제공자 (Private Providers) [#ssrf-protection-and-private-providers]

LibreChat은 웹 검색, 스크래핑 및 리랭킹을 위해 여는 각 연결을 검증합니다. 프라이빗, 루프백, 링크 로컬 및 클라우드 메타데이터 대상은 기본적으로 차단되며, 여기에는 리다이렉트 홉과 연결 시점에 프라이빗 주소로 확인되는 호스트 이름도 포함됩니다.

구성된 SearXNG, Firecrawl, Jina, Tavily 호환, Keenable 호환 또는 관련 제공업체 endpoint가 의도적으로 비공개인 경우 `webSearch.allowedAddresses`를 사용하세요:

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

이 필드는 엄격한 허용 목록(allowlist)이 아니라 SSRF 예외 목록입니다. 공개 대상은 계속해서 사용할 수 있습니다. 항목은 반드시 정확한 `host:port`, `private.ip:port` 또는 `[ipv6]:port` 쌍이어야 합니다. URL, 경로, CIDR 범위, 호스트/IP 단독, 공개 IP 리터럴은 거부됩니다. 예외 처리된 호스트 이름은 해당 포트에서 확인되는 모든 사설 IP를 신뢰하게 되므로, 사설 IP 리터럴을 사용하는 것을 권장하며 DNS를 직접 제어하는 이름만 나열하십시오.

LibreChat은 구성된 HTTP(S) 포워드 프록시 엔드포인트가 도달 가능하도록 자동으로 예외 처리합니다. 프록시가 요청을 전달할 때, 대상 주소를 확인하고 자체적으로 대상 송신(egress)을 강제해야 합니다. `NO_PROXY`를 사용하면 요청을 직접 보낼 수 있으며, 이때 LibreChat의 연결 가드(connection guard)가 여전히 적용됩니다. 이 가드는 LibreChat이 공급자 API에 대해 여는 연결을 보호합니다. 타사 스크레이퍼가 요청 데이터로 수신하여 자체 인프라에서 가져오는 페이지 URL은 제한할 수 없습니다.

## 자격 증명 소유권 (Credential Ownership) [#credential-ownership]

사용자가 제공한 Firecrawl, SearXNG 또는 Jina URL에 서버 소유의 API 키를 전달해서는 안 됩니다. SSRF 유효성 검사를 수행하더라도 사용자가 선택한 공개 엔드포인트가 배포 환경의 자격 증명을 받기에 안전해지는 것은 아닙니다. URL과 키를 관리자 소유 설정으로 함께 구성하거나, 사용자가 직접 자신의 키 쌍을 제공하도록 하십시오. SearXNG는 키 없이도 실행할 수 있습니다.

저장된 사용자 URL이 서버의 키와 페어링되는 경우, LibreChat은 Firecrawl의 선택적 URL을 무시하고 기본 endpoint를 사용합니다. SearXNG의 인스턴스 URL은 필수이므로, 혼합 소유권 구성은 인증되지 않으며 검색 도구는 초기화되지 않습니다. 서버의 키를 사용하는 자체 호스팅 배포의 경우, 사용자가 저장한 URL에 의존하는 대신 해당 키와 함께 `FIRECRAWL_API_URL` 또는 `SEARXNG_INSTANCE_URL`을 구성하십시오. 비공개 endpoint는 여전히 [`allowedAddresses`](#ssrf-protection-and-private-providers) 설정이 필요합니다.

```yaml filename="webSearch"
webSearch:
  searxngSearchOptions:
```


#### 엔진 선택하기 [#choosing-engines]

엔진 이름은 자신의 인스턴스에서 활성화된 엔진과 일치해야 하며, 그에 따라 다음 두 가지 사항이 따릅니다:

- SearXNG는 인식할 수 없는 엔진이 있을 경우 오류를 보고하는 대신 해당 엔진을 무시합니다. 오타가 있거나 인스턴스에서 비활성화된 엔진이 있는 경우, 오류가 발생하는 대신 결과 수가 적게 표시됩니다.
- 유효한 이름은 인스턴스마다 다릅니다. `https://your-instance/config`에서 활성화된 목록을 확인하세요. 해당 페이지는 활성화된 모든 엔진이 포함된 JSON을 반환합니다. 또는 인스턴스 환경 설정 페이지의 **Engines** 탭을 열어 확인할 수 있습니다.

기본값은 `google,bing,duckduckgo`입니다. SearXNG는 선택된 엔진이 반환하는 모든 결과를 집계하므로, 엔진 하나가 차단되더라도 전체 응답이 아닌 해당 엔진의 결과만큼만 손실되며, 모든 선택된 엔진이 실패하거나 아무것도 반환하지 않을 때만 검색 결과가 비어 있게 됩니다.

DuckDuckGo는 기본 설정에서 차단될 가능성이 가장 높은 엔진인데, 이는 대부분의 자체 호스팅 인스턴스에 CAPTCHA를 제공하기 때문입니다. 설정에 엔진이 3개뿐인 경우, 속도 제한이 걸린 Google이나 Bing과 동시에 DuckDuckGo까지 사용할 수 없게 되면 결과가 전혀 나오지 않는 상황이 흔히 발생합니다. `engines`를 명시적으로 설정하여 DuckDuckGo를 제외하고 3개 이상의 엔진을 나열하면 이러한 위험을 모두 줄일 수 있습니다.

빠르게 응답하고 자체 호스팅 트래픽을 허용하는 엔진이 가장 좋은 시작 세트가 됩니다. 예를 들면 다음과 같습니다:

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

더 많은 엔진을 추가하면 검색 범위는 넓어지지만, SearXNG가 응답하기 전에 설정된 엔진 중 가장 느린 엔진을 기다려야 하므로 모든 검색 속도가 느려집니다. 목록을 늘릴 때는 `timeout`을 고려하십시오.

#### 이 옵션들이 제어하지 않는 것 [#what-these-options-do-not-control]

- **Safe search**는 이 블록의 일부가 아닙니다. 이는 최상위 [`safeSearch`](#safesearch) 키에서 가져오며 `safesearch`로 SearXNG에 전달됩니다.
- **Result categories**는 LibreChat이 쿼리마다 선택하며, 검색 유형을 `general`, `images`, `videos` 또는 `news`로 매핑합니다. 여기에서 재정의할 수 없습니다.
- **페이지 번호 및 결과 형식**은 고정되어 있습니다. LibreChat은 항상 JSON 형식으로 1페이지를 요청하므로, 인스턴스의 `formats` 아래에 `json`이 활성화되어 있어야 합니다.

## 참고 사항 [#notes]

- API 키는 두 가지 방법으로 구성할 수 있습니다:
  1. YAML 구성에 지정된 환경 변수를 설정합니다.
  2. 환경 변수가 설정되어 있지 않으면, 사용자는 UI를 통해 API 키를 입력하라는 메시지를 받게 됩니다.
- 이 구성은 각 구성 요소(providers, scrapers, rerankers)에 대해 다중 서비스를 지원합니다.
- 특정 서비스 유형이 지정되지 않은 경우, 시스템은 해당 카테고리에 있는 모든 사용 가능한 서비스를 시도합니다.
- Safe search는 세 가지 수준의 콘텐츠 필터링을 제공합니다: OFF (0), MODERATE (1), STRICT (2)
- Tavily는 기본적으로 전역 세이프 서치 설정을 상속하지 않습니다. Tavily 계정이 `safe_search`를 지원하는 경우에만 `tavilySearchOptions.safeSearch`를 명시적으로 설정하십시오.
- Keenable은 키리스(keyless) 검색 및 페이지 가져오기를 지원합니다. 선택 사항인 키를 사용하면 공개 속도 제한(public rate limits)이 상향되며, 가져오기 URL 재정의(fetch URL override)는 환경 변수 전용입니다.
- SearXNG 쿼리 동작(엔진, 언어, 시간 범위, 요청 시간 제한)은 `searxngSearchOptions` 아래에서 구성됩니다. 검색 결과가 비어 있는 경우 [Choosing engines](#choosing-engines)를 참조하세요.
- 실제 API 키를 YAML 구성에 절대 넣지 마십시오. 환경 변수 이름만 사용해야 합니다.

## SearXNG 설정하기 [#setting-up-searxng]

SearXNG는 직접 호스팅할 수 있는 개인정보 보호 중심의 메타 검색 엔진입니다. 
더 자세한 정보는 [공식 SearXNG 문서](https://docs.searxng.org/)를 참조하세요.

LibreChat에서 사용할 나만의 SearXNG 인스턴스를 설정하는 단계는 다음과 같습니다:

### Docker Desktop 사용하기 [#using-docker-desktop]

1. **공식 SearXNG 이미지 검색**
   - Docker Desktop 열기
   - **Images** 탭에서 `searxng/searxng`를 검색하세요.
   - 공식 이미지에서 **Run**을 클릭하여 해당 이미지의 컨테이너를 자동으로 가져오고 실행하세요.

2. **컨테이너 실행하기**
   - 다운로드가 완료된 후 나타나는 진행 패널에서 **Optional Settings** 드롭다운을 확장하세요.
   - 원하는 구성 세부 정보(포트 번호, 컨테이너 이름 등)를 설정하세요.
   - **Run**을 클릭하여 컨테이너를 시작하세요

3. **LibreChat용 SearXNG 구성**
   - Docker Desktop의 `Files` 탭으로 이동합니다.
   - `/etc/searxng/settings.yaml`로 이동하세요.
   - 파일 편집기 열기
   - `formats` 섹션으로 이동하세요
   - `json`을 허용되는 형식으로 추가하여 LibreChat이 귀하의 인스턴스와 통신할 수 있도록 하십시오.
   - 파일을 저장하세요

4. **컨테이너 재시작**
   - 변경 사항을 적용하려면 컨테이너를 다시 시작하세요.

### LibreChat에서 SearXNG를 사용하도록 구성하기 [#configuring-librechat-to-use-searxng]

LibreChat 내의 UI 또는 `librechat.yaml`을 통해 SearXNG를 구성할 수 있습니다.

#### UI 구성 [#ui-configuration]

1. [메시지 작성기](/docs/features/composer)에서 +를 클릭하여 팔레트를 엽니다.

2. **Tools 섹션의 Web Search 행에서 Configure를 선택하세요**

3. **검색 제공자(Search Provider) 드롭다운에서 SearXNG를 선택하세요**
![SearXNG 드롭다운 선택](/images/web-search/searxng_dropdown_highlight.png)

4. **구성 세부 정보(예: 인스턴스 URL, 스크레이퍼 유형 등)를 입력하고 저장을 클릭하세요.**
![웹 검색 구성 저장](/images/web-search/web_search_save.png)

5. **팔레트의 도구(Tools) 섹션에서 웹 검색(Web Search)을 선택하세요**

6. **이제 컴포저에 Web Search 칩이 표시되므로, 쿼리에 웹 검색을 사용할 수 있습니다.**

#### YAML 구성 [#yaml-configuration]

사용자별 설정 대신 인스턴스의 모든 사용자를 위해 SearXNG를 구성하려면 `librechat.yaml`에 동일한 값을 설정하세요:

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

URL과 키는 여전히 환경 변수에서 읽어오므로, 위의 설정을 다음과 같이 조합하세요:

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Private instances는 allowedAddresses 항목이 필요합니다">
`localhost:55011`은 루프백 주소이며, LibreChat의 [SSRF protection](#ssrf-protection-and-private-providers)이 연결 시점에 이를 차단합니다. 일치하는 `allowedAddresses` 항목이 없으면 SearXNG가 정상 상태여도 검색이 실패합니다. 해당 항목은 인스턴스 URL의 정확한 `host:port` 쌍이어야 합니다.

LibreChat 자체가 Docker에서 실행될 때, `localhost`는 SearXNG 컨테이너가 아닌 LibreChat 컨테이너를 가리킵니다. 컨테이너가 접근할 수 있는 호스트 이름(예: compose 서비스 이름)을 사용하고, 대신 해당 이름을 제외(exempt)하십시오:

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

이 블록에서 허용하는 모든 하위 키에 대해서는 [`searxngSearchOptions`](#searxngsearchoptions)를 참조하세요.

#### 빈 결과 문제 해결 [#troubleshooting-empty-results]

SearXNG 검색 결과가 아무것도 반환되지 않는다면, 이는 LibreChat이 결과를 누락한 것이 아니라 요청이 작동 중인 인스턴스에 도달하지 못한 경우일 가능성이 거의 확실합니다. 다음 순서대로 문제를 해결해 보세요:

1. **해당 인스턴스는 `allowedAddresses` 항목이 없는 사설 주소입니다.** LibreChat은 연결 시점에 루프백 및 사설 목적지를 차단하므로, 자체 호스팅 인스턴스는 정확한 `host:port`를 [`allowedAddresses`](#ssrf-protection-and-private-providers) 아래에 나열해야 합니다. 이는 빈 결과 집합을 반환하는 대신 요청을 즉시 차단합니다.
2. **`json`이 `formats`에서 누락되었습니다.** LibreChat은 결과를 JSON 형식으로 요청합니다. 인스턴스 설정 파일의 `formats` 섹션에 `json`이 나열되어 있지 않으면, 인스턴스는 오류 페이지로 응답하며 모든 검색 결과가 비어 있게 됩니다. 이는 위 Docker 설정의 3단계입니다.
3. **선택한 모든 엔진이 실패했습니다.** SearXNG는 응답한 엔진들을 병합하므로, 빈 응답은 그중 아무것도 결과를 반환하지 않았음을 의미합니다. DuckDuckGo는 기본 설정(`google,bing,duckduckgo`)에 포함되어 있으며 대부분의 자체 호스팅 인스턴스에 CAPTCHA를 제공하므로, 검색을 수행할 엔진이 두 개만 남게 됩니다. `searxngSearchOptions.engines`를 명시적으로 설정하고, DuckDuckGo를 제외한 뒤, 몇 가지 엔진을 더 추가하십시오.
4. **인스턴스에 존재하지 않는 엔진 이름입니다.** SearXNG는 인식하지 못하는 엔진을 자동으로 건너뛰므로, 오타가 있으면 결과가 적게 나올 뿐입니다. 귀하의 목록을 `https://your-instance/config`와 비교해 보십시오.
5. **인스턴스가 타임아웃보다 느립니다.** 인스턴스가 많은 엔진을 쿼리하거나 느린 네트워크 경로 뒤에 있는 경우 `searxngSearchOptions.timeout` 값을 기본값인 `10000`보다 높이십시오.

LibreChat이 전송하는 내용을 직접 인스턴스를 호출하여 재현할 수 있습니다:

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

이 작업은 사용자의 로컬 머신에서 실행되므로 LibreChat의 연결 가드(connection guard)를 완전히 우회합니다. 여기서 `results` 배열이 비어 있다면 문제가 SearXNG 측에 있다는 것을 의미하며, 여기서 결과가 나오는데도 LibreChat에서 아무것도 찾지 못한다면 `allowedAddresses` 설정 문제일 가능성이 높습니다.
