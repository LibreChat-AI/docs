## Vue d'ensemble [#overview]

`interface.theme` définit le thème du déploiement : les couleurs, la forme, la typographie, les ombres et le mouvement que chaque utilisateur voit, aussi bien en mode clair qu'en mode sombre. Il accepte soit le nom d'un thème fourni avec LibreChat, soit une définition de thème en ligne.

<Callout type="info" title="Disponibilité">
  `interface.theme` et les échelles d'apparence décrites sur cette page se trouvent sur la branche `canary` de LibreChat et ne font pas encore partie d'une version taguée.
</Callout>

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

Lorsque `interface.theme` n'est pas défini, LibreChat se comporte comme auparavant : les utilisateurs voient le thème LibreChat par défaut, ou les couleurs définies lors de la compilation ou le thème enregistré qui leur est appliqué.

Cette page couvre ce qu'un opérateur définit dans `librechat.yaml`. Le moteur de thème lui-même, incluant la liste complète des jetons et la manière dont chaque jeton correspond aux utilitaires Tailwind, est documenté dans le [README du thème](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/client/src/theme/README.md) dans le dépôt LibreChat.

## Comment le thème est choisi [#how-the-theme-is-chosen]

Le client choisit un thème, par ordre de priorité décroissante :

1. **Modes à contraste élevé.** Un utilisateur qui choisit `high-contrast-light` ou `high-contrast-dark`, ou dont les paramètres système correspondent à un contraste élevé, obtient toujours la palette accessible intégrée.
2. **`interface.theme`** de `librechat.yaml`.
3. **`REACT_APP_THEME_*`** couleurs au moment de la compilation. Voir [Couleurs du thème](/docs/configuration/dotenv#theme-colors).
4. **Le thème enregistré de l'utilisateur** dans son navigateur.

Le thème de déploiement définit les couleurs, la forme, les polices, les ombres et le mouvement, mais pas le mode : chaque utilisateur choisit toujours lui-même le mode clair, sombre ou système.

Le thème de déploiement n'est jamais écrit dans le stockage du navigateur de l'utilisateur. Si vous supprimez `interface.theme`, les utilisateurs retrouvent leur propre thème stocké (ou les couleurs `REACT_APP_THEME_*`, lorsque la compilation les définit).

Le thème fait partie de la configuration pré-connexion, de sorte que les pages de connexion et d'inscription s'affichent déjà avec celui-ci.

### Liens partagés [#shared-links]

Un lien partagé affiche le thème du locataire (tenant) qui possède le lien, et non le thème de la personne qui le consulte. Si le locataire propriétaire ne définit aucun `interface.theme`, ou si sa configuration de lien partagé échoue à se charger, la page partagée n'affiche aucun thème de déploiement au lieu de revenir à celui du visiteur. Quitter la page partagée restaure le thème du visiteur.

## Thèmes intégrés [#bundled-themes]

| Nom | Thème |
| --- | --- |
| `librechat` | La palette et la forme par défaut de LibreChat. Le définir explicitement remplace également les couleurs `REACT_APP_THEME_*` et les thèmes enregistrés des utilisateurs. |
| `clickhouse` | Un thème de référence construit à partir des jetons de conception de l'interface utilisateur de ClickHouse. Voir [Thème ClickHouse](#clickhouse-theme). |

Un nom qui ne figure pas parmi ceux-ci est ignoré : le serveur le consigne dans les logs et abandonne `interface.theme` (voir [Validation](#validation)), et l'application revient à la source suivante dans la liste ci-dessus.

### Thème ClickHouse [#clickhouse-theme]

`interface.theme: clickhouse` modifie à la fois la couleur et la forme :

- **Palette.** Chaque jeton de couleur est défini dans les deux modes à partir des jetons clairs et sombres de Click UI, de sorte que rien ne revient à la palette LibreChat. Quelques valeurs ont été déplacées le long de leurs rampes Click UI là où la valeur textuelle ne respectait pas le contraste WCAG AA.
- **Accent.** Presque noir `#151515` en mode clair et jaune ClickHouse `#faff69` en mode sombre, utilisé pour l'accentuation et le bouton d'envoi. L'anneau de focus est la couleur de contour de l'interface Click : bleu `#437eef` en mode clair, `#faff69` en mode sombre.
- **Boutons.** Le bouton principal est `#302e32` en mode clair et `#faff69` en mode sombre, avec les étapes de survol de Click UI.
- **Radii.** Une échelle plus serrée tirée de `border.radii` de Click UI : contrôles, menus, infobulles, onglets et `sm` à `lg` à `0.25rem`, surfaces et `xl`/`2xl` à `0.5rem`, grandes surfaces et `3xl` à `0.75rem`.
- **Ombres.** Appliquez l'ombre d'élévation unique de l'interface utilisateur sur chaque surface surélevée, les menus et les éléments déplacés, avec une opacité de 0,15 en mode clair et de 0,6 en mode sombre, avec une ombre fine pour les niveaux `2xs` à `sm`. Les infobulles n'ont pas d'ombre.
- **Contrôles.** Les boutons et les champs mesurent 2rem de hauteur, les contrôles ont une marge intérieure de `1rem` avec un espacement d'icône de `0.5rem` et une graisse de libellé normale (`400`). Les champs sont remplis (`fieldFillStyle: fill`) et changent la couleur de leur bordure lors de la mise au point (`fieldFocusStyle: border`) ; les libellés sont de `0.75rem` avec une graisse de `500`. Les contrôles désactivés utilisent le style `fill` avec leurs propres couleurs désactivées, l'interrupteur est compact avec des dimensions de 2rem par 1rem, et les lignes de tableau bénéficient d'une règle de 1px.
- **Dialogs.** Une bordure de 1px, un espacement latéral de `2rem`, et des titres à `1.25rem`, épaisseur `700`, dans la police Inter. Chaque voile (scrim) de dialogue est à une opacité de 0.75.
- **Polices.** La police de l'interface utilisateur reste Inter. Le code utilise la pile mono de Click UI, `"Inconsolata", Consolas, "SFMono Regular", monospace` ; LibreChat inclut Inconsolata. Les titres demandent Basier Square en priorité, qui n'est pas inclus, ils s'affichent donc en Inter à moins que l'utilisateur ne l'ait installé.

## Définition de thème en ligne [#inline-theme-definition]

Au lieu d'un nom, `interface.theme` peut contenir une définition de thème. Tout ce que vous omettez revient aux valeurs par défaut de LibreChat pour ce mode ; une définition n'a donc besoin que des valeurs que vous souhaitez modifier.

```yaml filename="interface / theme"
interface:
  theme:
    version: 1
    name: acme
    modes:
      light:
        colors:
          rgb-accent-primary: '29 78 216'
          rgb-accent-primary-hover: '30 64 175'
          rgb-ring-primary: '29 78 216'
          rgb-surface-submit: '29 78 216'
          rgb-surface-submit-hover: '30 64 175'
          rgb-link: '29 78 216'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.2)'
      dark:
        colors:
          rgb-accent-primary: '96 165 250'
          rgb-accent-primary-hover: '147 197 253'
          rgb-ring-primary: '96 165 250'
          rgb-surface-submit: '37 99 235'
          rgb-surface-submit-hover: '29 78 216'
          rgb-link: '96 165 250'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.5)'
    brands:
      provider-openai: '#10a37f'
```

| Clé | Type | Description |
| --- | --- | --- |
| `version` | Number | Requis. Doit être `1`. |
| `name` | String | Requis. Un nom non vide pour le thème. |
| `modes` | Object | Requis. Contient `light` et/ou `dark`. Un mode que vous omettez utilise les valeurs par défaut de LibreChat pour ce mode. |
| `modes.<mode>.colors` | Object | Jetons de couleur pour ce mode. Les clés sont des noms de jetons `rgb-*`, les valeurs sont des triplets `R G B`. Voir [Colors](#colors). |
| `modes.<mode>.appearance` | Object | Valeurs de forme, contrôle, typographie, scrim, ombre et mouvement pour ce mode. Voir [Appearance](#appearance). |
| `modes.<mode>.brands` | Object | Couleurs de marque du fournisseur pour ce mode. Remplace les `brands` à l'échelle du thème. |
| `brands` | Object | Couleurs de marque du fournisseur pour les deux modes. Voir [Brands](#brands). |

### Validation [#validation]

Le serveur vérifie `interface.theme` avec les mêmes règles que celles appliquées par le navigateur avant son rendu, lors du chargement de `librechat.yaml` et à chaque rechargement de la configuration.

**Un thème invalide est ignoré comme si `interface.theme` n'était pas défini.** Une `version` erronée, un `name` manquant, un mode autre que `light` ou `dark`, un champ que le format de définition ne possède pas (au niveau racine, tel que `css`, ou à l'intérieur d'un mode, tout ce qui n'est pas `colors`, `appearance` et `brands`), un jeton de marque inconnu ou une valeur d'un type incorrect pour n'importe quel jeton rend le thème inutilisable. LibreChat supprime `interface.theme`, enregistre un avertissement avec une ligne par problème, et charge le reste de la configuration comme d'habitude, de sorte qu'une erreur de thème n'arrête jamais le serveur. Les utilisateurs obtiennent alors la source suivante dans [Comment le thème est choisi](#how-the-theme-is-chosen) : les couleurs `REACT_APP_THEME_*` ou leur thème enregistré, ou le thème par défaut de LibreChat lorsque ni l'un ni l'autre ne s'applique. Le journal appelle cela le thème par défaut :

```text
Ignoring interface.theme in /app/librechat.yaml; the default theme applies instead:
- interface.theme.modes.dark.colors.rgb-surface-primary: Invalid RGB value for rgb-surface-primary: 300 16 32
```

Un nom de thème groupé qui n'existe pas est traité de la même manière (`Unknown bundled theme "<name>", expected one of: librechat, clickhouse`).

Un thème défini via une substitution de configuration (pour un rôle, un groupe ou un utilisateur dans le [Admin Panel](/docs/features/admin_panel#configuration-management)) suit les mêmes règles, avec une différence : une substitution de thème invalide revient au `interface.theme` de base défini dans `librechat.yaml`, et non au thème par défaut. Ces lignes de journal commencent par `[getAppConfig]`, par exemple `[getAppConfig] Ignoring interface.theme from a config override; the base theme applies instead:`.

Les maps `colors` et `appearance` fonctionnent différemment des champs qui les entourent.

**Un jeton inconnu est ignoré et le reste du thème est appliqué.** Une clé à l'intérieur de `colors` ou `appearance` que cette version de LibreChat ne reconnaît pas, qu'il s'agisse d'une faute de frappe ou d'un jeton ajouté dans une version plus récente, n'affecte que lui-même. Le serveur le consigne dans les journaux et exclut les couleurs inconnues du thème qu'il envoie au navigateur :

```text
interface.theme in /app/librechat.yaml names tokens this version ignores:
- interface.theme.modes.light.colors.rgb-surfce-secondary: Unknown light color token ignored: rgb-surfce-secondary
```

Un jeton inconnu est toujours vérifié pour sa forme : un nom de couleur doit être un jeton en minuscules simple (lettres, chiffres et `-`) contenant une valeur `R G B`, et un nom d'apparence doit être en camelCase contenant une valeur simple sans `;`, `{`, `}`, `<`, `>` ou `url()`. Tout autre élément constitue une erreur et le thème entier est réinitialisé. Vérifiez le journal du serveur après avoir modifié un thème, car un jeton mal orthographié n'y est signalé que là.

Le navigateur applique les mêmes règles au thème qu'il reçoit et enregistre `[DeploymentTheme] Ignoring invalid interface.theme: ...` s'il doit tout de même en rejeter un, par exemple lorsqu'un client mis en cache plus ancien rencontre un serveur plus récent.

### Couleurs [#colors]

Les couleurs utilisent les mêmes noms de jetons que le moteur de thème : `rgb-` suivi du jeton, tels que `rgb-surface-primary`, `rgb-text-primary`, `rgb-border-medium`, `rgb-accent-primary` ou `rgb-status-error-subtle`. La liste complète des 130 jetons est `themeColorTokens` dans [`packages/data-provider/src/theme.ts`](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/data-provider/src/theme.ts), que le serveur et le navigateur lisent tous deux, et chaque jeton est décrit dans l'interface `IThemeRGB` dans [`packages/client/src/theme/types/index.ts`](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/client/src/theme/types/index.ts).

Au-delà des palettes de surface, de texte, de bordure, de statut et de syntaxe, ces rôles permettent à un thème de redéfinir le style d'états d'interaction et de composants spécifiques :

| Rôle | Jetons | Peintures |
| --- | --- | --- |
| Focus | `rgb-focus-outline`, `rgb-focus-control` | Le contour de focus clavier dans toute l'application, et l'anneau de focus des contrôles partagés |
| Pressé | `rgb-surface-pressed`, `rgb-surface-inverted-pressed` | Contrôles neutres et inversés lorsqu'ils sont pressés |
| Inversé et fixe | `rgb-surface-inverted`, `rgb-surface-inverted-hover`, `rgb-text-inverted`, `rgb-surface-fixed`, `rgb-surface-fixed-hover`, `rgb-text-fixed` | Contrôles dessinés avec les couleurs du mode opposé, et contrôles qui conservent une couleur dans les deux modes |
| Désactivé | `rgb-surface-disabled`, `rgb-text-disabled`, `rgb-border-disabled` | Contrôles désactivés, lorsque `disabledStyle` est `fill` (voir [Apparence](#appearance)) |
| Bordure de contrôle | `rgb-border-control` | Le bord des entrées, des déclencheurs de sélection et des emplacements de code à usage unique, maintenu séparé des séparateurs discrets car il nécessite un contraste de 3:1 |
| Champs | `rgb-border-field-focus`, `rgb-field-fill`, `rgb-field-text` | Le bord d'un champ focalisé lorsque `fieldFocusStyle` est `border` (suit `rgb-focus-control`), le remplissage d'un champ lorsque `fieldFillStyle` est `fill` (suit `rgb-surface-primary`), et la valeur saisie (suit `rgb-text-primary`) |
| Bouton principal | `rgb-button-primary`, `rgb-button-primary-hover` | Le remplissage et le survol du bouton principal ; suivent `rgb-surface-inverted` et `rgb-surface-inverted-hover`, que les cases à cocher et les commutateurs continuent d'utiliser |
| Encres | `rgb-dialog-title`, `rgb-badge-label` | Titres de dialogue et étiquettes de badge ; les deux suivent `rgb-text-primary` |
| Scrim | `rgb-surface-overlay` | La couleur derrière les dialogues ; son intensité est définie par les opacités de scrim dans [Apparence](#appearance) |
| Superposition média | `rgb-surface-media-overlay`, `rgb-text-on-media` | Scrims, puces et progression dessinés sur les propres images de l'utilisateur (lightbox, aperçu d'image, téléchargements en cours), et le texte sur ceux-ci. Les thèmes groupés les gardent en noir et blanc dans les deux modes |
| Avatar | `rgb-avatar-fill`, `rgb-avatar-text`, `rgb-avatar-placeholder`, `rgb-avatar-edge` | Le remplissage et le glyphe de l'avatar utilisateur par défaut (le glyphe suit `rgb-text-primary`), la toile de fond derrière un avatar d'agent ou d'assistant en chargement ou transparent (suit `rgb-surface-secondary` en mode clair et `rgb-surface-tertiary` en mode sombre), et le filet autour de l'avatar par défaut |
| Tuiles de fichiers | `rgb-file-document`, `rgb-file-sheet`, `rgb-file-code`, `rgb-file-artifact`, `rgb-file-audio`, `rgb-file-video`, `rgb-file-generic`, `rgb-file-ink` | Un remplissage par type de fichier, et le glyphe dessiné sur chaque tuile |
| Illustration | `rgb-illustration-subtle`, `rgb-illustration`, `rgb-illustration-strong` | Les trois tons des illustrations dans l'application, comme l'illustration de la zone de dépôt de fichiers |
| Commutateur | `rgb-switch-unchecked`, `rgb-switch-thumb` | La piste du commutateur non coché, et le bouton dans les deux états |
| Tableau | `rgb-table-header-text`, `rgb-table-header-fill` | Noms des colonnes, et le remplissage opaque d'un en-tête de tableau fixe |
| Série de graphiques | `rgb-series-1` à `rgb-series-8` | Couleurs catégorielles des graphiques, dans l'ordre |

Chaque valeur est un triplet `R G B` brut avec chaque canal allant de `0` à `255`, par exemple `'255 255 255'`. Les valeurs hexadécimales et `rgb(...)` sont rejetées. Mettez la valeur entre guillemets pour que YAML la lise comme une chaîne de caractères.

Quelques jetons suivent un jeton associé que vous avez défini lorsque vous les omettez, afin qu'une palette partielle reste cohérente. Par exemple, `rgb-text-muted` suit `rgb-text-tertiary`, `rgb-surface-composer-hover` et `rgb-surface-pressed` suivent `rgb-surface-hover`, `rgb-focus-outline` suit `rgb-ring-primary`, `rgb-focus-control` suit `rgb-text-primary`, `rgb-border-control` suit `rgb-border-light`, `rgb-switch-thumb` suit `rgb-surface-primary`, `rgb-table-header-text` suit `rgb-text-secondary`, et `rgb-table-header-fill` suit `rgb-surface-dialog`.

| `shadowLg` | L'étape `shadow-lg` | `0 10px 15px -3px rgb(0 0 0 / 0.1), 0 4px 6px -4px rgb(0 0 0 / 0.1)` |
| `shadowXl` | L'étape `shadow-xl` | `0 20px 25px -5px rgb(0 0 0 / 0.1), 0 8px 10px -6px rgb(0 0 0 / 0.1)` |
| `shadow2xl` | L'étape `shadow-2xl` | `0 25px 50px -12px rgb(0 0 0 / 0.25)` |
| `menuShadow` | Ombre des panneaux de menu ; en mode clair, suit `shadowLg` si non défini | Clair : `0 10px 15px -3px rgb(0 0 0 / 0.1), 0 4px 6px -4px rgb(0 0 0 / 0.1)` ; sombre : `0 10px 15px -3px rgb(0 0 0 / 0.25), 0 4px 6px -4px rgb(0 0 0 / 0.1)` |
| `tooltipShadow` | Ombre des infobulles | Clair : `0 2px 4px 0 rgb(0 0 0 / 0.25)` ; sombre : `0 1px 2px 0 rgb(0 0 0 / 0.35)` |
| `motionFast` | Durée des transitions rapides | `150ms` |
| `motionNormal` | Durée des transitions normales | `200ms` |

Les valeurs par défaut reproduisent l'apparence de LibreChat, donc un thème qui ne définit aucune de ces clés ne modifie aucune forme.

Valeurs acceptées :

- **Radii, `controlHeight`, `controlPaddingX`, `controlGap`, tailles des boutons et des champs, espacement, tailles du texte et des étiquettes, et les longueurs de dialogue (`dialogStroke`, `dialogPaddingX`, `dialogHeaderGap`, `dialogTitleSize`) :** `0`, ou un nombre en `px`, `rem` ou `em` (tel que `0.25rem`), ou un `calc()` unique de deux longueurs de ce type (tel que `calc(0.5rem - 2px)`).
- **`switchWidth` et `switchHeight` :** une longueur positive en `px` ou `rem`. Les deux doivent utiliser la même unité (un côté que vous omettez utilise sa valeur par défaut en `rem`), la largeur doit dépasser la hauteur pour que le bouton puisse se déplacer, et la hauteur doit dégager la bordure de piste de 4px (plus de `4px`, ou au moins `0.5rem`).
- **`tableCellSpaceY` et `tableRowStroke` :** `0`, ou une longueur en `px` ou `rem`.
- **`focusRingWidth` :** une longueur positive en `px` ou `rem`, afin que l'indicateur de focus ne disparaisse jamais.
- **`focusRingOffset` :** `0`, ou une longueur en `px` ou `rem` qui peut être négative (dessinant le contour à l'intérieur du bord de l'élément).
- **`disabledStyle` :** `dim` ou `fill`.
- **`fieldFocusStyle` :** `ring` ou `border`.
- **`fieldFillStyle` :** `transparent` ou `fill`.
- **Graisses de police (`controlFontWeight`, `dialogTitleFontWeight`) :** un nombre entier de `1` à `1000`. `labelFontWeight` accepte également `inherit`.
- **Hauteurs de ligne (les étapes `leading*`, `labelLeading` et `dialogTitleLeading`) :** un nombre sans unité (tel que `1.5`), un `calc()` unique divisant deux nombres (tel que `calc(1.25 / 0.875)`), ou une longueur.
- **Opacités du scrim :** un nombre compris entre `0` et `1`.
- **Familles de polices :** toute liste `font-family` non vide sans `;`, `{` ou `}`. La police doit être disponible pour le navigateur : LibreChat inclut Inter, Roboto Mono et Inconsolata, donc toute autre famille doit être installée sur la machine de l'utilisateur ou servie par votre déploiement, faute de quoi la famille suivante dans la liste sera utilisée.
- **Shadow steps (`shadow2xs` à `shadow2xl`), `menuShadow`, `tooltipShadow` et `elevationDrag` :** une liste concrète de `box-shadow`, ou `none`. `var()`, `env()`, `attr()` et `url()` sont rejetés.
- **`elevationSurface` :** toute valeur `box-shadow` non vide sans `;`, `{`, `}` ou `url()`.
- **Motion :** une durée en `ms` ou `s`, telle que `120ms`.

Chaque valeur d'apparence doit être une chaîne de caractères. Mettez entre guillemets les nombres tels que les graisses de police, les hauteurs de ligne et les opacités de masque (`'500'`, `'1.5'`, `'0.8'`) ; un nombre YAML sans guillemets sera rejeté.

### Marques [#brands]

`brands` recolore les icônes des fournisseurs affichées à côté des modèles. Il peut être défini une fois au niveau supérieur pour les deux modes, et remplacé par mode sous `modes.<mode>.brands`.

| Clé | Par défaut |
| --- | --- |
| `provider-openai` | `#19C37D` |
| `provider-openai-gpt4` | `#AB68FF` |
| `provider-openai-reasoning` | `#000000` |
| `provider-anthropic` | `#d09a74` |
| `provider-azure` | `linear-gradient(0.375turn, #61bde2, #4389d0)` |
| `provider-bedrock` | `#268672` |

Les valeurs sont des couleurs hexadécimales (`#rgb`, `#rrggbb` ou `#rrggbbaa`). Les remplissages peuvent également être un `linear-gradient(...)` ; `provider-foreground`, la couleur du glyphe de l'icône, doit être une couleur hexadécimale.

## Utiliser le thème en dehors de LibreChat [#using-the-theme-outside-librechat]

Le package `@librechat/client` publie le thème sous forme de feuille de style, afin qu'une autre application construite sur ses composants puisse utiliser les mêmes jetons. Importez `@librechat/client/theme.css` dans la feuille de style qui importe Tailwind :

```css filename="app.css"
@import 'tailwindcss';
@import '@librechat/client/theme.css';
```

Il contient les jetons de couleur sémantiques et leurs mappages Tailwind, la valeur par défaut de chaque jeton de couleur et d'apparence, ainsi que les règles `@font-face` pour Inter, Roboto Mono et Inconsolata. Les fichiers de police sont fournis dans le package sous `@librechat/client/fonts/*`, le bundler de l'application (Vite, webpack ou esbuild) doit donc les résoudre et les émettre ; une configuration qui sert du CSS compilé sans bundler doit servir ces chemins elle-même. Une police n'est téléchargée que lorsque du texte est rendu avec celle-ci.
