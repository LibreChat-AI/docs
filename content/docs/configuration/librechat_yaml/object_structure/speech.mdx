## Overview

The `speech` object allows you to configure Text-to-Speech (TTS) and Speech-to-Text (STT) providers directly in your `librechat.yaml` configuration file. This enables server-side speech services without requiring users to configure their own API keys.

**Fields under `speech`:**

- `tts` - Text-to-Speech provider configurations
- `stt` - Speech-to-Text provider configurations
- `speechTab` - Default UI settings for speech features

**Notes:**

- Multiple providers can be configured simultaneously
- Users can select their preferred provider from the available options
- API keys in the config file should use environment variable references for security

## Example

```yaml filename="speech"
speech:
  tts:
    allowedAddresses: ["tts.internal:8080"]
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["voice-id-1", "voice-id-2"]
  stt:
    allowedAddresses: ["stt.internal:8080"]
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText: true
    textToSpeech: true
```

## SSRF Protection

LibreChat guards operator-provided STT and TTS URLs at connect time. Private, loopback, link-local, and cloud-metadata destinations are blocked by default, and redirects are disabled for speech requests.

`speech.tts.allowedAddresses` and `speech.stt.allowedAddresses` are separate exemption lists, not strict allowlists. Add an exact private `host:port`, `private.ip:port`, or `[ipv6]:port` only when that section must reach a trusted self-hosted service. Do not use a URL, path, CIDR range, bare host/IP, or public IP literal. Default ports are normalized, so an HTTPS URL without an explicit port is checked as port `443`.

An exempted hostname trusts whatever private address it resolves to on that port. Prefer a private IP literal when possible, and list only names whose DNS you control and which cannot be repointed by an attacker.

When a forward proxy carries a hostname request, the proxy performs destination DNS and egress, so the proxy must enforce its own SSRF policy. A literal private destination is still blocked before proxy handling unless its exact address and port are exempted.

### openai

OpenAI STT configuration for `whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-transcribe`, and OpenAI-compatible endpoints.

<OptionTable
  options={[
    ['url', 'String', 'Custom API URL (optional). Use for OpenAI-compatible endpoints.', ''],
    ['apiKey', 'String', 'OpenAI API key. Use environment variable reference.', 'Required'],
    ['model', 'String', 'STT model for recorded dictation (e.g., "whisper-1", "gpt-4o-transcribe", "gpt-transcribe").', 'Required'],
    ['prompt', 'String', 'Pending. Free-form context about the audio, such as the subject or vocabulary to expect. Sent with every transcription, to every model.', ''],
    ['keywords', 'Array of Strings', 'Pending. Names, acronyms and other literal terms the model should spell exactly. Sent only to `gpt-transcribe` and `gpt-live-transcribe` models. Entries cannot contain `<`, `>` or line breaks.', ''],
    ['languages', 'Array of Strings', 'Pending. Languages to expect, as ISO 639-1 or 639-3 codes with an optional region (e.g., "de", "zh-tw").     ['realtime', 'Object', 'Pending. Enables live dictation over the Realtime API. See [realtime](#realtime) below.', ''],
  ]}
/>

`gpt-transcribe` and `gpt-live-transcribe` models, including dated snapshots, take `languages` instead of the singular `language` field. LibreChat sends them `prompt`, `keywords` and `languages`. Older models (Whisper, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`) receive `prompt` and the user's speech language as `language`, as before.

**Example:**
```yaml filename="speech / stt / openai"
stt:
  openai:
    apiKey: "${STT_API_KEY}"
    model: "gpt-transcribe"
    prompt: "Internal retail and software terminology may be used."
    keywords: ["LibreChat", "OpenShift"]
    languages: ["de", "en"]
```

#### realtime

**Pending.** Live dictation streams microphone audio to a Realtime transcription session over WebRTC, so text appears in the composer while the user speaks. With this block set, users can pick **Live** under **Settings > Speech > Engine**. Recorded dictation (the **External** engine) keeps using `model`.

<OptionTable
  options={[
    ['model', 'String', 'Realtime transcription model, such as "gpt-live-transcribe". Older models such as "gpt-4o-transcribe" also work, but return text only after the user stops.', 'Required'],
    ['url', 'String', 'Realtime API base URL. LibreChat calls `{url}/realtime/client_secrets` and `{url}/realtime/calls`. For Azure OpenAI, use `https://<resource>.openai.azure.com/openai/v1`.', 'https://api.openai.com/v1'],
    ['delay', 'String', 'Latency preset for `gpt-live-transcribe` models: "minimal", "low", "medium", "high" or "xhigh". Not sent to other models.', ''],
  ]}
/>

- Live dictation uses `stt.openai.apiKey`, `prompt`, `keywords` and `languages`. `stt.openai.url` applies only to recorded dictation.
- **Live** is offered only when `stt` configures exactly one provider and that provider is `openai`. The `azureOpenAI` provider does not enable it.
- The API key never reaches the browser. For each recording, the server uses it to create a client secret that expires after 60 seconds, then spends that secret on the WebRTC connection setup itself. The browser receives only the connection answer.
- `stt.allowedAddresses` and the proxy settings apply to both requests the server makes.
- Live audio and transcripts travel directly between the browser and the provider. `filters` rules for the `transcript` field do not see them; message filters still apply once the text is sent.
- Realtime sessions are billed per minute while the microphone is open.

**Example:**
```yaml filename="speech / stt / openai / realtime"
stt:
  openai:
    apiKey: "${STT_API_KEY}"
    model: "gpt-transcribe"
    keywords: ["LibreChat", "OpenShift"]
    realtime:
      model: "gpt-live-transcribe"
      delay: "low"
```

## Notes

- Always use environment variable references (e.g., `${API_KEY}`) for API keys in configuration files
- Multiple TTS providers can be configured; users select their preferred option in the UI
- The `speechTab` settings define defaults that users can override in their personal settings
- `browser` uses the browser's built-in speech support; `external` uses the server-side providers configured under `speech.stt` or `speech.tts`
- Existing `openai` and `azureOpenAI` STT defaults, and `openai`, `azureOpenAI`, `elevenlabs`, and `localai` TTS defaults, are migrated to `external`; an unavailable external engine falls back to `browser`
- `realtime` (**Pending**) is the **Live** engine. If live dictation is not available, a `realtime` default or a user's saved **Live** choice falls back to `external`, or to `browser` when no external engine is available either
- For detailed feature documentation, see [Speech to Text & Text to Speech](/docs/configuration/stt_tts)
