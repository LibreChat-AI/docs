## 概要 [#overview]

`skillSync` オブジェクトを使用すると、管理者は外部ソースから Skills をミラーリングできます。サポートされているプロバイダーは GitHub です。

GitHub Skill Syncは、設定されたリポジトリパスから`SKILL.md`ファイルおよびそのバンドルファイルを読み込み、それらを`source: "github"`を持つSkillとして保存します。また、その後の同期時に、ミラーリングされた行をアップストリームのリポジトリと同期させます。

## 例 [#example]

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
        # credentialKey: production-skills
        # tenantId: your-tenant-id
```

<Callout type="warning" title="認証情報">
  各ソースに対して `token` または `credentialKey` のいずれかを使用し、両方を同時に使用しないでください。`token` は `${GITHUB_SKILLS_TOKEN}` のような環境変数参照である必要があります。選択したリポジトリに対して、Contents（コンテンツ）および Metadata（メタデータ）の読み取り専用権限を持つ GitHub のファイングレイン個人アクセストークンを使用してください。
</Callout>

### ソースID [#source-identity]

`id` フィールドはミラーアイデンティティの一部です。これを安定させてください。ソースを名前変更されたリポジトリや新しい ref に再指定しても、ミラーリングされた Skill は同じソース ID にリンクされたままになりますが、ソース ID を変更すると新しいミラーが作成されます。

`tenantId` が設定されている場合、同期の読み取りおよび書き込みはそのテナントの分離コンテキスト内で実行されます。`tenantId` はソースIDに対して不変（イミュータブル）として扱ってください。後から変更、追加、または削除を行うと、以前にミラーリングされたスキルが古いテナントに残されたままになります。

## 同期動作 [#sync-behavior]

GitHub Skill Sync:

- 設定された各パスの下にある `SKILL.md` ファイルを検出します。
- `SKILL.md` の本文、フロントマター、およびバンドルされたファイルをインポートします。
- ソースID、オーナー、リポジトリ、ref、スキルパス、コミットSHA、blob SHAなどのソースメタデータを保存します。
- アップストリームのファイルが変更されたときに、ミラーリングされたSkillsを更新します。
- 設定されたソースから削除された、ミラーリングされたSkillsおよびファイルを削除します。
- スキルを個別に検証および公開するため、1つの無効または競合するスキルが原因で、同じソースからの有効なスキルが非表示になることはありません。
- スキップされたSkillの最後に確認された正常なミラーを保持し、そのSkillに対する不完全な書き込みをロールバックします。
- 少なくとも1つのSkillを公開した一方で別のSkillをスキップした場合に実行を `partial` とマークし、管理者ステータス読み取り用に制限付きのスキップ数と詳細を記録します。
- 同期ロックを使用するため、一度に1つのGitHub同期実行のみが進行します。

不明な `SKILL.md` のフロントマターキーは、その値が境界内かつJSONセーフな拡張制限内に収まっている限り受け入れられます。認識されたフィールドの無効な値、安全でない拡張値、重複する名前、および所有権の競合が発生した場合は、影響を受けるSkillのみがスキップされます。認証、レート制限、ロックの喪失、リポジトリへのアクセス、およびロールバックの失敗は、引き続きソースレベルの失敗として扱われます。

## Skill の削除 [#skill-deletion]

トップレベルの `skillDeletion` オブジェクトは、Skill の削除を完了させ、保存されたファイルをクリーンアップするバックグラウンド処理と、放棄された Skill アップロードの整理を制御します。`skillSync` とは別のものであり、すべての Skill に適用されます。不明なキーは拒否されます。

```yaml filename="librechat.yaml"
skillDeletion:
  finalizationEnabled: true
  sweepIntervalMs: 60000
  claimLeaseMs: 120000
  batchSize: 100
  recheckIntervalMs: 3600000
```

## ディスクからのデプロイスキル [#deployment-skills-from-disk]

`skillSync`とは別に、LibreChatはサーバー上のディレクトリからSkillsを起動時に読み込みます。各Skillは`SKILL.md`と同梱ファイルを含むフォルダです。ディレクトリはプロジェクトルートの`./skill`ですが、`.env`で`DEPLOYMENT_SKILLS_DIR`を設定した場合はそのパスが使われます([dotenv](/docs/configuration/dotenv)を参照)。

デプロイメントスキルは、スキル機能を持つすべてのユーザーに表示され、UIでは読み取り専用です。同じ名前のユーザー作成スキルは非表示になります。スキルは起動時に一度だけ読み込まれるため、ファイルを追加、削除、または編集した後はLibreChatを再起動してください。[エージェントプラグイン](/docs/configuration/agent_plugins)でもデプロイメントスキルを提供できます。このディレクトリ内のスキルは、同じ名前のプラグインスキルより優先されます。
