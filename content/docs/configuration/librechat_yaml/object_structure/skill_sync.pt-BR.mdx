## Visão geral [#overview]

O objeto `skillSync` permite que administradores sincronizem Skills a partir de fontes externas. O GitHub é o provedor suportado.

O GitHub Skill Sync lê arquivos `SKILL.md` e seus arquivos agrupados a partir de caminhos de repositório configurados, armazena-os como Skills com `source: "github"` e mantém as linhas espelhadas alinhadas com o repositório upstream em sincronizações posteriores.

## Exemplo [#example]

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
        # credentialKey: production-skills
        # tenantId: your-tenant-id
```

<Callout type="warning" title="Credenciais">
  Use `token` ou `credentialKey` para cada fonte, não ambos. `token` deve ser uma referência de variável de ambiente, como `${GITHUB_SKILLS_TOKEN}`. Use um fine-grained personal access token do GitHub com escopo para o repositório selecionado, com permissões de leitura apenas para Contents e Metadata.
</Callout>

### Identidade da Fonte [#source-identity]

O campo `id` é parte da identidade do espelho. Mantenha-o estável. Redirecionar uma fonte para um repositório renomeado ou uma nova referência mantém as Skills espelhadas vinculadas ao mesmo id de fonte, enquanto alterar o id de fonte cria um novo espelho.

Quando `tenantId` é definido, as leituras e gravações de sincronização são executadas dentro do contexto de isolamento desse tenant. Trate `tenantId` como imutável para um source id: alterá-lo, adicioná-lo ou removê-lo posteriormente deixará Skills espelhadas anteriormente no tenant antigo.

## Comportamento de Sincronização [#sync-behavior]

Sincronização de Habilidades do GitHub:

- Descobre arquivos `SKILL.md` abaixo de cada caminho configurado.
- Importa o corpo, o frontmatter e os arquivos agrupados do `SKILL.md`.
- Armazena metadados da fonte, como source id, owner, repo, ref, skill path, commit SHA e blob SHA.
- Atualiza as Skills espelhadas quando o arquivo upstream é alterado.
- Exclui Skills e arquivos espelhados que foram removidos da fonte configurada.
- Valida e publica Skills de forma independente, para que uma Skill inválida ou conflitante não oculte Skills válidas da mesma fonte.
- Preserva o último espelho conhecido como bom de uma Skill ignorada e reverte gravações incompletas para essa Skill.
- Marca uma execução como `partial` quando ela publica pelo menos uma Skill, mas ignora outra, e registra uma contagem limitada de itens ignorados e detalhes para leituras de status do administrador.
- Usa um bloqueio de sincronização para que apenas uma execução de sincronização do GitHub ocorra por vez.

Chaves de frontmatter `SKILL.md` desconhecidas são aceitas quando seus valores permanecem dentro dos limites de extensão seguros para JSON. Campos reconhecidos inválidos, valores de extensão inseguros, nomes duplicados e conflitos de propriedade ignoram apenas a Skill afetada. Falhas de autenticação, limite de taxa (rate-limit), perda de bloqueio (lock-loss), acesso ao repositório e reversão permanecem como falhas de nível de origem.

## Exclusão de Skill [#skill-deletion]

O objeto de nível superior `skillDeletion` controla o processo em segundo plano que conclui a exclusão de Skills e limpa seus arquivos armazenados, além de uploads de Skills abandonados. Ele é separado de `skillSync` e se aplica a todas as Skills. Chaves desconhecidas são rejeitadas.

```yaml filename="librechat.yaml"
skillDeletion:
  finalizationEnabled: true
  sweepIntervalMs: 60000
  claimLeaseMs: 120000
  batchSize: 100
  recheckIntervalMs: 3600000
```

## Habilidades de Implantação a partir do Disco [#deployment-skills-from-disk]

Separadamente do `skillSync`, o LibreChat carrega Skills de um diretório no servidor durante a inicialização. Cada skill é uma pasta com um `SKILL.md` e quaisquer arquivos adicionais incluídos. O diretório é `./skill` na raiz do projeto, a menos que você defina `DEPLOYMENT_SKILLS_DIR` no `.env` (veja [dotenv](/docs/configuration/dotenv)).

Skills de implantação são exibidas a todos os usuários que possuem a capacidade de Skills, são somente leitura na interface e ocultam qualquer skill criada pelo usuário com o mesmo nome. Elas são lidas uma única vez na inicialização, portanto reinicie o LibreChat após adicionar, remover ou editar arquivos. [Plugins de Agente](/docs/configuration/agent_plugins) também podem fornecer Skills de implantação; uma Skill neste diretório prevalece sobre uma Skill de plugin com o mesmo nome.
