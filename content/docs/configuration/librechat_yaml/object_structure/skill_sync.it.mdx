## Panoramica [#overview]

L'oggetto `skillSync` consente agli amministratori di replicare le Skill da fonti esterne. GitHub è il provider supportato.

GitHub Skill Sync legge i file `SKILL.md` e i relativi file in bundle dai percorsi del repository configurati, li archivia come Skill con `source: "github"` e mantiene le righe rispecchiate allineate con il repository upstream nelle sincronizzazioni successive.

## Esempio [#example]

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
        # credentialKey: production-skills
        # tenantId: your-tenant-id
```

<Callout type="warning" title="Credenziali">
  Usa `token` oppure `credentialKey` per ogni sorgente, non entrambi. `token` deve essere un riferimento a una variabile d'ambiente come `${GITHUB_SKILLS_TOKEN}`. Usa un personal access token GitHub "fine-grained" limitato al repository selezionato con permessi di sola lettura per Contents e Metadata.
</Callout>

### Identità della sorgente [#source-identity]

Il campo `id` fa parte dell'identità del mirror. Mantienilo stabile. Reindirizzare una sorgente verso un repository rinominato o un nuovo ref mantiene gli Skill mirrorati collegati allo stesso id sorgente, mentre modificare l'id sorgente crea un nuovo mirror.

Quando `tenantId` è impostato, le operazioni di lettura e scrittura della sincronizzazione vengono eseguite all'interno del contesto di isolamento di quel tenant. Considera `tenantId` come immutabile per un id di origine: modificarlo, aggiungerlo o rimuoverlo in seguito lascerà le Skill precedentemente replicate nel vecchio tenant.

## Comportamento di sincronizzazione [#sync-behavior]

Sincronizzazione competenze GitHub:

- Rileva i file `SKILL.md` sotto ogni percorso configurato.
- Importa il corpo, il frontmatter e i file in bundle di `SKILL.md`.
- Memorizza i metadati della sorgente come source id, owner, repo, ref, skill path, commit SHA e blob SHA.
- Aggiorna le Skills replicate quando il file upstream viene modificato.
- Elimina le Skills e i file rispecchiati che sono stati rimossi dalla sorgente configurata.
- Valida e pubblica le Skills in modo indipendente, in modo che una Skill non valida o in conflitto non nasconda le Skills valide provenienti dalla stessa fonte.
- Preserva l'ultimo mirror valido noto di una Skill saltata ed esegue il rollback delle scritture incomplete per quella Skill.
- Contrassegna un'esecuzione come `partial` quando pubblica almeno una Skill ma ne salta un'altra, e registra un conteggio limitato di elementi saltati e i dettagli per la lettura dello stato da parte dell'amministratore.
- Utilizza un blocco di sincronizzazione in modo che venga eseguita solo una sincronizzazione GitHub alla volta.

Le chiavi di frontmatter `SKILL.md` sconosciute vengono accettate quando i loro valori rimangono entro i limiti di estensione delimitati e JSON-safe. I campi riconosciuti non validi, i valori di estensione non sicuri, i nomi duplicati e i conflitti di proprietà ignorano solo la Skill interessata. Gli errori di autenticazione, limitazione della frequenza (rate-limit), perdita di blocco (lock-loss), accesso al repository e rollback rimangono errori a livello di origine.

## Eliminazione di una Skill [#skill-deletion]

L'oggetto di primo livello `skillDeletion` controlla il processo in background che completa l'eliminazione delle Skill e pulisce i relativi file archiviati, insieme ai caricamenti di Skill abbandonati. È separato da `skillSync` e si applica a tutte le Skill. Le chiavi sconosciute vengono rifiutate.

```yaml filename="librechat.yaml"
skillDeletion:
  finalizationEnabled: true
  sweepIntervalMs: 60000
  claimLeaseMs: 120000
  batchSize: 100
  recheckIntervalMs: 3600000
```
