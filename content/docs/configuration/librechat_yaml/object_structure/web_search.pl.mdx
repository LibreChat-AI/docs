title: Konfiguracja wyszukiwania w sieci

Konfiguracja `webSearch` pozwala na dostosowanie funkcjonalności wyszukiwania w sieci w ramach LibreChat, w tym dostawców wyszukiwania, skraperów treści oraz mechanizmów zmiany rangi wyników (rerankers).

## Przegląd [#overview]

Funkcja wyszukiwania w sieci składa się z trzech głównych komponentów:

1. **Dostawcy wyszukiwania**: Usługi, które wykonują wstępne wyszukiwanie w sieci
2. **Scrapers**: Usługi, które wyodrębniają zawartość ze stron internetowych
3. **Rerankers**: Usługi, które zmieniają kolejność wyników wyszukiwania w celu uzyskania lepszej trafności

## Przykład [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## Ochrona przed SSRF i prywatni dostawcy [#ssrf-protection-and-private-providers]

LibreChat weryfikuje każde połączenie, które otwiera w celu wyszukiwania w sieci, scrapingu oraz rerankingu. Miejsca docelowe typu private, loopback, link-local oraz cloud-metadata są domyślnie blokowane, wliczając w to przekierowania (redirect hops) oraz nazwy hostów, które w momencie łączenia są rozpoznawane jako adresy prywatne.

Użyj `webSearch.allowedAddresses`, gdy skonfigurowany punkt końcowy SearXNG, Firecrawl, Jina, kompatybilny z Tavily, kompatybilny z Keenable lub powiązany dostawca jest celowo prywatny:

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

To pole jest listą wyjątków SSRF, a nie ścisłą listą dozwolonych adresów (allowlist). Publiczne miejsca docelowe pozostają dostępne. Wpisy muszą być dokładnymi parami `host:port`, `private.ip:port` lub `[ipv6]:port`; adresy URL, ścieżki, zakresy CIDR, same nazwy hostów/adresy IP oraz publiczne literały IP są odrzucane. Wykluczona nazwa hosta ufa każdemu prywatnemu adresowi IP, na który rozwiązuje się na danym porcie, dlatego preferuj używanie literałów prywatnych adresów IP i wymieniaj tylko te nazwy, których DNS kontrolujesz.

LibreChat automatycznie wyklucza skonfigurowany punkt końcowy forward-proxy HTTP(S), aby zapewnić możliwość połączenia z nim. Gdy proxy obsługuje żądanie, rozwiązuje ono adres docelowy i musi samodzielnie wymusić egresję (ruch wychodzący) do miejsca docelowego. `NO_PROXY` może sprawić, że żądanie zostanie wysłane bezpośrednio, gdzie nadal obowiązuje mechanizm ochrony połączeń LibreChat. Ochrona ta obejmuje połączenia otwierane przez LibreChat do API dostawców; nie może ona ograniczać adresu URL strony, który zewnętrzny scraper otrzymuje jako dane żądania i pobiera na własnej infrastrukturze.

## Własność poświadczeń [#credential-ownership]

Adres URL Firecrawl, SearXNG lub Jina dostarczony przez użytkownika nie może otrzymać klucza API należącego do serwera. Walidacja SSRF nie sprawia, że publiczny punkt końcowy wybrany przez użytkownika jest bezpieczny do otrzymywania poświadczeń wdrożenia. Skonfiguruj adres URL i klucz razem jako ustawienia należące do administratora lub pozwól użytkownikowi na podanie własnej pary; SearXNG może również działać bez klucza.

Jeśli zapisany adres URL użytkownika miałby zostać powiązany z kluczem serwera, LibreChat ignoruje opcjonalny adres URL Firecrawl i używa swojego domyślnego endpoint. Adres URL instancji SearXNG jest wymagany, aby konfiguracja o mieszanej własności nie była uwierzytelniona, a narzędzie wyszukiwania nie zostało zainicjowane. W przypadku wdrożenia self-hosted korzystającego z klucza serwera, skonfiguruj `FIRECRAWL_API_URL` lub `SEARXNG_INSTANCE_URL` obok tego klucza, zamiast polegać na zapisanym adresie URL użytkownika. Prywatne endpoint nadal wymagają [`allowedAddresses`](#ssrf-protection-and-private-providers).

#### Wybór silników [#choosing-engines]

Nazwy silników muszą być zgodne z silnikami włączonymi w Twojej własnej instancji, co pociąga za sobą dwie następujące kwestie:

- SearXNG ignoruje silnik, którego nie rozpoznaje, zamiast zgłaszać błąd. Literówka lub silnik wyłączony w Twojej instancji skutkuje mniejszą liczbą wyników zamiast awarią.
- Prawidłowe nazwy są specyficzne dla danej instancji. Sprawdź listę włączonych silników pod adresem `https://your-instance/config`, który zwraca plik JSON zawierający każdy włączony silnik, lub otwórz kartę **Engines** na stronie preferencji swojej instancji.

Domyślną wartością jest `google,bing,duckduckgo`. SearXNG agreguje wszystko, co zwracają wybrane wyszukiwarki, więc zablokowanie jednej z nich powoduje jedynie utratę jej części wyników, a nie całej odpowiedzi. Wyszukiwanie kończy się niepowodzeniem tylko wtedy, gdy każda z wybranych wyszukiwarek zawiedzie lub nie zwróci żadnych wyników.

DuckDuckGo jest silnikiem w tym domyślnym zestawie, który najprawdopodobniej zostanie zablokowany, ponieważ wyświetla CAPTCHA większości instancji hostowanych samodzielnie. Przy zaledwie trzech silnikach w zestawie, utrata go w tym samym czasie co ograniczonego limitami Google lub Bing jest częstym powodem braku jakichkolwiek wyników. Jawne ustawienie `engines`, pominięcie DuckDuckGo oraz wymienienie więcej niż trzech silników zmniejsza to ryzyko.

Silniki, które odpowiadają szybko i tolerują ruch z własnych serwerów (self-hosted), stanowią najlepszy zestaw startowy, na przykład:

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

Dodanie większej liczby silników zwiększa zasięg, ale jednocześnie spowalnia każde wyszukiwanie, ponieważ SearXNG czeka na najwolniejszy silnik w zestawie przed udzieleniem odpowiedzi. Pamiętaj o parametrze `timeout`, gdy powiększasz listę.

#### Czego te opcje nie kontrolują [#what-these-options-do-not-control]

- **Safe search** nie jest częścią tego bloku. Pochodzi on z klucza najwyższego poziomu [`safeSearch`](#safesearch) i jest przekazywany do SearXNG jako `safesearch`.
- **Kategorie wyników** są wybierane dla każdego zapytania przez LibreChat, który przypisuje typ wyszukiwania do `general`, `images`, `videos` lub `news`. Nie można ich tutaj nadpisać.
- **Numer strony i format wyniku** są stałe. LibreChat zawsze żąda strony 1 w formacie JSON, dlatego Twoja instancja musi mieć włączony `json` w sekcji `formats`.

## Uwagi [#notes]

- Klucze API można skonfigurować na dwa sposoby:
  1. Ustaw zmienne środowiskowe określone w konfiguracji YAML
  2. Jeśli zmienne środowiskowe nie są ustawione, użytkownicy zostaną poproszeni o podanie kluczy API za pośrednictwem interfejsu użytkownika.
- Konfiguracja obsługuje wiele usług dla każdego komponentu (dostawców, scraperów, rerankerów)
- Jeśli określony typ usługi nie zostanie wskazany, system spróbuje użyć wszystkich dostępnych usług w tej kategorii
- Safe search zapewnia trzy poziomy filtrowania treści: OFF (0), MODERATE (1) oraz STRICT (2)
- Tavily domyślnie nie dziedziczy globalnego ustawienia bezpiecznego wyszukiwania; ustaw `tavilySearchOptions.safeSearch` jawnie tylko wtedy, gdy Twoje konto Tavily obsługuje `safe_search`.
- Keenable obsługuje wyszukiwanie bezkluczowe i pobieranie stron; jego opcjonalny klucz zwiększa publiczne limity zapytań, a jego nadpisanie adresu URL pobierania jest dostępne tylko w środowisku.
- Zachowanie zapytań SearXNG (silniki, język, zakres czasu, limit czasu żądania) jest konfigurowane w `searxngSearchOptions`; zobacz [Wybieranie silników](#choosing-engines), jeśli wyniki wyszukiwania są puste.
- Nigdy nie umieszczaj rzeczywistych kluczy API w konfiguracji YAML - używaj wyłącznie nazw zmiennych środowiskowych

## Konfiguracja SearXNG [#setting-up-searxng]

SearXNG to zorientowana na prywatność metawyszukiwarka, którą możesz hostować samodzielnie. 
Więcej informacji znajdziesz w [oficjalnej dokumentacji SearXNG](https://docs.searxng.org/).

Oto kroki, które należy wykonać, aby skonfigurować własną instancję SearXNG do użytku z LibreChat:

### Używanie Docker Desktop [#using-docker-desktop]

1. **Wyszukaj oficjalny obraz SearXNG**
   - Otwórz Docker Desktop
   - Wyszukaj `searxng/searxng` w zakładce **Images**.
   - Kliknij **Run** przy oficjalnym obrazie, aby automatycznie pobrać i uruchomić kontener z tym obrazem

2. **Uruchamianie kontenera**
   - Rozwiń listę rozwijaną **Optional Settings** w panelu, który pojawi się po zakończeniu pobierania.
   - Ustaw żądane szczegóły konfiguracji (numer portu, nazwę kontenera itp.)
   - Kliknij **Run**, aby uruchomić kontener

3. **Konfiguracja SearXNG dla LibreChat**
   - Przejdź do karty `Files` w Docker Desktop
   - Przejdź do `/etc/searxng/settings.yaml`
   - Otwórz edytor plików
   - Przejdź do sekcji `formats`
   - Dodaj `json` jako akceptowalny format, aby LibreChat mógł komunikować się z Twoją instancją
   - Zapisz plik

4. **Zrestartuj kontener**
   - Zrestartuj kontener, aby zmiany weszły w życie

#### Konfiguracja YAML [#yaml-configuration]

Aby skonfigurować SearXNG dla wszystkich użytkowników instancji zamiast dla każdego z osobna, ustaw te same wartości w `librechat.yaml`:

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

Adres URL oraz klucz są nadal odczytywane ze środowiska, więc połącz powyższą konfigurację z:

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Prywatne instancje wymagają wpisu allowedAddresses">
`localhost:55011` to adres zwrotny (loopback), który LibreChat blokuje w momencie łączenia w ramach [ochrony SSRF](#ssrf-protection-and-private-providers). Bez pasującego wpisu `allowedAddresses` wyszukiwanie zakończy się niepowodzeniem, nawet jeśli SearXNG działa poprawnie. Wpis musi być dokładną parą `host:port` z adresu URL Twojej instancji.

Kiedy LibreChat działa w Docker, `localhost` odnosi się do kontenera LibreChat, a nie SearXNG. Użyj nazwy hosta, do której kontener ma dostęp, takiej jak nazwa usługi w compose, i zamiast tego wyklucz ją:

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

Zobacz [`searxngSearchOptions`](#searxngsearchoptions), aby poznać wszystkie podklucze akceptowane przez ten blok.

#### Rozwiązywanie problemów z pustymi wynikami [#troubleshooting-empty-results]

Wyszukiwanie SearXNG, które nie zwraca żadnych wyników, prawie zawsze oznacza, że żądanie nie dociera do działającej instancji, a nie że LibreChat odrzuca wyniki. Przeanalizuj poniższe punkty w podanej kolejności:

1. **Instancja jest adresem prywatnym bez wpisu `allowedAddresses`.** LibreChat blokuje adresy zwrotne (loopback) oraz prywatne miejsca docelowe w momencie nawiązywania połączenia, dlatego samodzielnie hostowana instancja musi mieć swój dokładny `host:port` wymieniony w sekcji [`allowedAddresses`](#ssrf-protection-and-private-providers). Blokuje to żądanie całkowicie, zamiast zwracać pusty zestaw wyników.
2. **`json` brakuje w `formats`.** LibreChat żąda wyników w formacie JSON. Jeśli sekcja `formats` w pliku ustawień instancji nie zawiera `json`, instancja odpowiada stroną z błędem, a każde wyszukiwanie kończy się pustym wynikiem. Jest to krok 3 powyższej konfiguracji Docker.
3. **Każdy wybrany silnik zawiódł.** SearXNG łączy wyniki z silników, które odpowiedziały, więc pusta odpowiedź oznacza, że żaden z nich nic nie zwrócił. DuckDuckGo znajduje się w domyślnym zestawie (`google,bing,duckduckgo`) i wyświetla CAPTCHA większości instancji self-hosted, co pozostawia tylko dwa silniki do obsługi wyszukiwania. Ustaw `searxngSearchOptions.engines` jawnie, pomiń DuckDuckGo i wymień kilka innych silników.
4. **Nazwa silnika nie istnieje w Twojej instancji.** SearXNG pomija po cichu silniki, których nie rozpoznaje, więc literówka oznacza po prostu mniej wyników. Porównaj swoją listę z `https://your-instance/config`.
5. **Instancja jest wolniejsza niż limit czasu.** Zwiększ `searxngSearchOptions.timeout` powyżej domyślnej wartości `10000`, jeśli Twoja instancja odpytuje wiele silników lub znajduje się za wolnym łączem sieciowym.

Możesz odtworzyć to, co wysyła LibreChat, wywołując instancję bezpośrednio:

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

Uruchamia się to z Twojej własnej maszyny, więc całkowicie omija mechanizm ochrony połączeń LibreChat. Pusta tablica `results` w tym miejscu potwierdza, że problem leży po stronie SearXNG; jeśli wyniki się pojawiają, a LibreChat nadal nic nie znajduje, wskazuje to na `allowedAddresses`.
