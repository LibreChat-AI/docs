Konfigurasi `webSearch` memungkinkan Anda untuk menyesuaikan fungsionalitas pencarian web di dalam LibreChat, termasuk penyedia pencarian, pengikis konten (content scrapers), dan pemeringkat ulang hasil (result rerankers).

## Ikhtisar [#overview]

Fitur pencarian web terdiri dari tiga komponen utama:

1. **Penyedia Pencarian**: Layanan yang melakukan pencarian web awal
2. **Scrapers**: Layanan yang mengekstrak konten dari halaman web
3. **Rerankers**: Layanan yang menyusun ulang hasil pencarian untuk relevansi yang lebih baik

## Contoh [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## Perlindungan SSRF dan Penyedia Pribadi [#ssrf-protection-and-private-providers]

LibreChat memvalidasi setiap koneksi yang dibukanya untuk pencarian web, scraping, dan reranking. Destinasi privat, loopback, link-local, dan cloud-metadata diblokir secara default, termasuk hop pengalihan (redirect hops) dan nama host yang teresolusi ke alamat privat pada saat koneksi.

Gunakan `webSearch.allowedAddresses` ketika endpoint penyedia SearXNG, Firecrawl, Jina, yang kompatibel dengan Tavily, yang kompatibel dengan Keenable, atau penyedia terkait yang dikonfigurasi bersifat privat secara sengaja:

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

Bidang ini adalah daftar pengecualian SSRF, bukan daftar izin (allowlist) yang ketat. Destinasi publik tetap tersedia. Entri harus berupa pasangan `host:port`, `private.ip:port`, atau `[ipv6]:port` yang tepat; URL, path, rentang CIDR, host/IP mentah, dan literal IP publik akan ditolak. Nama host yang dikecualikan akan memercayai IP privat mana pun yang diselesaikan pada port tersebut, jadi lebih disarankan menggunakan literal IP privat dan hanya mencantumkan nama yang DNS-nya Anda kendalikan.

LibreChat secara otomatis mengecualikan endpoint forward-proxy HTTP(S) yang dikonfigurasi agar dapat dijangkau. Ketika proxy membawa permintaan, ia menyelesaikan tujuan dan harus menegakkan egress tujuan itu sendiri. `NO_PROXY` dapat membuat permintaan menjadi langsung, di mana pelindung koneksi LibreChat tetap berlaku. Pelindung ini mencakup koneksi yang dibuka LibreChat ke API penyedia; ia tidak dapat membatasi URL halaman yang diterima oleh scraper pihak ketiga sebagai data permintaan dan diambil pada infrastrukturnya sendiri.

## Kepemilikan Kredensial [#credential-ownership]

URL Firecrawl, SearXNG, atau Jina yang disediakan pengguna tidak boleh menerima kunci API milik server. Validasi SSRF tidak membuat endpoint yang dipilih pengguna secara publik aman untuk menerima kredensial deployment. Konfigurasikan URL dan kunci secara bersamaan sebagai pengaturan milik administrator, atau biarkan pengguna menyediakan pasangan mereka sendiri; SearXNG juga dapat dijalankan tanpa kunci.

Jika URL pengguna yang disimpan akan dipasangkan dengan kunci server, LibreChat akan mengabaikan URL opsional Firecrawl dan menggunakan endpoint default-nya. URL instance SearXNG diperlukan, sehingga konfigurasi kepemilikan campuran tidak diautentikasi dan alat pencarian tidak diinisialisasi. Untuk penyebaran yang di-host sendiri (self-hosted) menggunakan kunci server, konfigurasikan `FIRECRAWL_API_URL` atau `SEARXNG_INSTANCE_URL` bersama kunci tersebut alih-alih mengandalkan URL yang disimpan pengguna. Endpoint pribadi tetap memerlukan [`allowedAddresses`](#ssrf-protection-and-private-providers).

#### Memilih engine [#choosing-engines]

Nama engine harus sesuai dengan engine yang diaktifkan pada instance Anda sendiri, dan dua hal berikut berlaku dari ketentuan tersebut:

- SearXNG mengabaikan mesin yang tidak dikenali alih-alih melaporkan kesalahan. Kesalahan pengetikan, atau mesin yang dinonaktifkan pada instans Anda, akan muncul sebagai hasil yang lebih sedikit alih-alih sebagai kegagalan.
- Nama yang valid bersifat spesifik untuk setiap instance. Periksa daftar yang diaktifkan di `https://your-instance/config`, yang akan mengembalikan JSON termasuk setiap engine yang diaktifkan, atau buka tab **Engines** di halaman preferensi instance Anda.

Defaultnya adalah `google,bing,duckduckgo`. SearXNG mengagregasi apa pun yang dikembalikan oleh mesin pencari yang dipilih, sehingga satu mesin yang diblokir hanya akan mengurangi sebagian hasil pencarian Anda, bukan keseluruhan respons, dan pencarian hanya akan kembali kosong jika setiap mesin yang dipilih gagal atau tidak mengembalikan hasil apa pun.

DuckDuckGo adalah mesin pencari dalam set default yang paling mungkin diblokir, karena ia menyajikan CAPTCHA ke sebagian besar instance yang di-host sendiri (self-hosted). Dengan hanya tiga mesin dalam set tersebut, kehilangannya di saat yang sama dengan Google atau Bing yang terkena limitasi kecepatan (rate-limited) adalah cara umum yang menyebabkan tidak ada hasil sama sekali. Mengatur `engines` secara eksplisit, tidak menyertakan DuckDuckGo, dan mencantumkan lebih dari tiga mesin, semuanya mengurangi risiko tersebut.

Mesin yang menjawab dengan cepat dan mampu menangani lalu lintas yang di-host sendiri (self-hosted) merupakan pilihan awal terbaik, sebagai contoh:

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

Menambahkan lebih banyak mesin pencari akan memperluas cakupan, tetapi juga memperlambat setiap pencarian, karena SearXNG menunggu mesin terlambat dalam set tersebut sebelum memberikan respons. Perhatikan `timeout` saat Anda menambah daftar tersebut.

#### Apa yang tidak dikendalikan oleh opsi-opsi ini [#what-these-options-do-not-control]

- **Safe search** bukan bagian dari blok ini. Fitur ini berasal dari kunci tingkat atas [`safeSearch`](#safesearch) dan diteruskan ke SearXNG sebagai `safesearch`.
- **Kategori hasil** dipilih per kueri oleh LibreChat, yang memetakan jenis pencarian ke `general`, `images`, `videos`, atau `news`. Kategori ini tidak dapat diganti di sini.
- **Nomor halaman dan format hasil** bersifat tetap. LibreChat selalu meminta halaman 1 dalam format JSON, itulah sebabnya instans Anda harus mengaktifkan `json` di bawah `formats`.

## Catatan [#notes]

- API keys dapat dikonfigurasi dengan dua cara:
  1. Atur variabel lingkungan yang ditentukan dalam konfigurasi YAML
  2. Jika variabel lingkungan tidak diatur, pengguna akan diminta untuk memberikan kunci API melalui UI
- Konfigurasi ini mendukung beberapa layanan untuk setiap komponen (providers, scrapers, rerankers)
- Jika jenis layanan tertentu tidak ditentukan, sistem akan mencoba semua layanan yang tersedia dalam kategori tersebut
- Safe search menyediakan tiga tingkat penyaringan konten: OFF (0), MODERATE (1), dan STRICT (2)
- Tavily tidak mewarisi pengaturan pencarian aman (safe search) global secara default; atur `tavilySearchOptions.safeSearch` secara eksplisit hanya jika akun Tavily Anda mendukung `safe_search`
- Keenable mendukung pencarian tanpa kunci (keyless search) dan pengambilan halaman (page fetch); kuncinya yang bersifat opsional dapat meningkatkan batas tarif publik, dan penggantian URL pengambilan (fetch URL override) hanya berlaku untuk lingkungan (environment-only).
- Perilaku kueri SearXNG (mesin pencari, bahasa, rentang waktu, batas waktu permintaan) dikonfigurasi di bawah `searxngSearchOptions`; lihat [Choosing engines](#choosing-engines) jika hasil pencarian kosong
- Jangan pernah memasukkan API key yang sebenarnya ke dalam konfigurasi YAML - gunakan hanya nama variabel lingkungan

## Menyiapkan SearXNG [#setting-up-searxng]

SearXNG adalah mesin pencari meta yang berfokus pada privasi yang dapat Anda host sendiri. 
Untuk informasi lebih lanjut, lihat [dokumentasi resmi SearXNG](https://docs.searxng.org/).

Berikut adalah langkah-langkah untuk menyiapkan instans SearXNG Anda sendiri untuk digunakan dengan LibreChat:

### Menggunakan Docker Desktop [#using-docker-desktop]

1. **Cari image resmi SearXNG**
   - Buka Docker Desktop
   - Cari `searxng/searxng` di tab **Images**
   - Klik **Run** pada image resmi untuk menarik (pull) dan menjalankan container dari image tersebut secara otomatis

2. **Menjalankan container**
   - Perluas menu tarik-turun **Optional Settings** di panel selanjutnya yang muncul setelah pengunduhan selesai.
   - Atur detail konfigurasi yang Anda inginkan (nomor port, nama kontainer, dll.)
   - Klik **Run** untuk memulai container

3. **Konfigurasi SearXNG untuk LibreChat**
   - Buka tab `Files` di Docker Desktop
   - Buka `/etc/searxng/settings.yaml`
   - Buka editor file
   - Navigasikan ke bagian `formats`
   - Tambahkan `json` sebagai format yang dapat diterima agar LibreChat dapat berkomunikasi dengan instans Anda
   - Simpan file tersebut

4. **Mulai ulang container**
   - Mulai ulang container agar perubahan diterapkan

#### Konfigurasi YAML [#yaml-configuration]

Untuk mengonfigurasi SearXNG bagi semua orang di instans alih-alih per pengguna, tetapkan nilai yang sama di `librechat.yaml`:

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

URL dan kunci tersebut masih dibaca dari lingkungan, jadi pasangkan konfigurasi di atas dengan:

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Instans privat memerlukan entri allowedAddresses">
`localhost:55011` adalah alamat loopback, yang diblokir oleh [SSRF protection](#ssrf-protection-and-private-providers) LibreChat pada saat koneksi. Tanpa entri `allowedAddresses` yang sesuai, pencarian akan gagal meskipun SearXNG dalam keadaan sehat. Entri tersebut harus berupa pasangan `host:port` yang tepat dari URL instans Anda.

Saat LibreChat itu sendiri berjalan di Docker, `localhost` adalah kontainer LibreChat, bukan kontainer SearXNG. Gunakan nama host yang dapat dijangkau oleh kontainer, seperti nama layanan compose, dan kecualikan itu sebagai gantinya:

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

Lihat [`searxngSearchOptions`](#searxngsearchoptions) untuk setiap subkunci yang diterima blok ini.

#### Pemecahan masalah hasil kosong [#troubleshooting-empty-results]

Pencarian SearXNG yang tidak menghasilkan apa pun hampir selalu disebabkan oleh permintaan yang tidak pernah mencapai instans yang berfungsi, bukan karena LibreChat membuang hasil pencarian. Lakukan langkah-langkah berikut secara berurutan:

1. **Instans tersebut adalah alamat privat tanpa entri `allowedAddresses`.** LibreChat memblokir loopback dan destinasi privat pada saat koneksi, sehingga instans yang di-host sendiri memerlukan `host:port` yang tepat untuk dicantumkan di bawah [`allowedAddresses`](#ssrf-protection-and-private-providers). Hal ini akan memblokir permintaan secara langsung alih-alih mengembalikan kumpulan hasil yang kosong.
2. **`json` tidak ada di dalam `formats`.** LibreChat meminta hasil dalam format JSON. Jika bagian `formats` pada file pengaturan instance Anda tidak mencantumkan `json`, maka instance tersebut akan memberikan halaman galat dan setiap pencarian akan kembali kosong. Ini adalah langkah ke-3 dari pengaturan Docker di atas.
3. **Setiap mesin yang dipilih gagal.** SearXNG menggabungkan mesin yang memberikan jawaban, jadi respons kosong berarti tidak ada satu pun mesin yang memberikan hasil. DuckDuckGo ada dalam set default (`google,bing,duckduckgo`) dan menyajikan CAPTCHA ke sebagian besar instans yang di-host sendiri (self-hosted), yang hanya menyisakan dua mesin untuk melakukan pencarian. Tetapkan `searxngSearchOptions.engines` secara eksplisit, hapus DuckDuckGo, dan cantumkan beberapa mesin lainnya.
4. **Nama engine tidak ada pada instance Anda.** SearXNG secara diam-diam akan melewati engine yang tidak dikenali, jadi kesalahan pengetikan hanya berarti hasil pencarian yang lebih sedikit. Bandingkan daftar Anda dengan `https://your-instance/config`.
5. **Instans tersebut lebih lambat dari batas waktu (timeout).** Tingkatkan `searxngSearchOptions.timeout` di atas nilai default `10000` jika instans Anda melakukan kueri ke banyak mesin pencari atau berada di belakang jalur jaringan yang lambat.

Anda dapat mereproduksi apa yang dikirim oleh LibreChat dengan memanggil instans tersebut secara langsung:

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

Ini berjalan dari mesin Anda sendiri, sehingga sepenuhnya melewati *connection guard* LibreChat. *Array* `results` yang kosong di sini mengonfirmasi bahwa masalahnya ada di sisi SearXNG; jika terdapat hasil di sini sementara LibreChat tetap tidak menemukan apa pun, maka masalahnya terletak pada `allowedAddresses`.
