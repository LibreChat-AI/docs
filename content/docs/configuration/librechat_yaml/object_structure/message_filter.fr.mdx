## Vue d'ensemble [#overview]

LibreChat fournit deux configurations de filtre côté serveur :

- `filters` applique une politique sensible à la source aux champs sélectionnés dans les messages, prompts, agents, fichiers, compétences, mémoires, outils et autres contenus réutilisables.
- `messageFilter` est l'ancien filtre de texte de message. Les déploiements existants peuvent continuer à l'utiliser pendant la migration vers `filters.messages`.

Les deux sont facultatifs. Lorsque les deux sont configurés, les deux politiques s'appliquent.

<Callout type="warning" title="Configuration de base uniquement">
  `filters` est chargé uniquement à partir du `librechat.yaml` de base. Les remplacements au niveau de la base de données, des rôles, des groupes et des utilisateurs ne peuvent pas l'ajouter, le modifier ou le supprimer. Dans un déploiement multi-répliques, déployez ou redémarrez chaque réplique simultanément et vérifiez que chacune a chargé la même configuration de base avant de considérer la politique comme active.
</Callout>

## Filtres sensibles à la source [#source-aware-filters]

Chaque source dispose d'une politique `pii` optionnelle. Omettez `filters`, une source ou son bloc `pii` pour laisser cette portée désactivée.

```yaml filename="librechat.yaml"
filters:
  messages:
    unattributedAssistantContent: model_output
    pii:
      action: audit
      fields: [text, summary, attachment_reference]
      starterPatterns: [sk_prefix, bearer_header, api_key_header]
      customPatterns:
        - id: organization_identifier
          label: Organization identifier
          regex: 'ORG-[A-Z0-9]{12}'
  files:
    pii:
      fields: [name, content, extracted_text, transcript]
      uninspectable: block
  skills:
    pii:
      fields: [name, description, instructions, imported_text, file_text]
```

### Configuration des modèles [#pattern-configuration]

Pour chaque source activée :

- Omettez `action` ou définissez-le sur `block` pour rejeter les correspondances. Définissez `action: audit` pour un déploiement progressif (shadow rollout) qui enregistre les résultats sans rejeter, modifier ni masquer le contenu. Définissez `action: redact` pour activer la rédaction (voir [Rédaction](#redaction)).
- Omettez `fields` pour inspecter tous les champs pris en charge pour cette source. Une liste explicite doit contenir entre 1 et 256 noms de champs pris en charge.
- Omettez `starterPatterns` pour activer le catalogue complet des starters. Définissez-le sur `[]` pour désactiver les modèles de starter tout en conservant les `customPatterns` éventuels.
- Configurez `customPatterns` avec un `id`, un `label` visible par l'utilisateur et une `regex`. Vous pouvez éventuellement définir `category` avec l'une des valeurs suivantes : `email`, `phone`, `name`, `credential` ou `custom`.
- `maxCharacters` (1 à 262144, valeur par défaut 65536) limite le nombre total de caractères de texte analysés par session de transformation, et `maxMatches` (1 à 4096, valeur par défaut 256) limite le nombre de correspondances par session. Les deux s'appliquent à `redact`.

Le mode audit évalue tous les fragments et toutes les règles configurés afin que les opérateurs puissent mesurer les résultats avant l'application. Chaque enregistrement d'audit de niveau info identifie l'action, le détecteur, la règle, le libellé, la source, le champ et la provenance, mais n'inclut jamais le texte correspondant ni le contenu source. En mode `audit`, rien n'est modifié ni masqué. Les valeurs d'action autres que `block`, `audit` et `redact` sont rejetées au chargement de la configuration.

Les Actions sont configurées indépendamment par source, de sorte qu'une source peut effectuer un audit tandis qu'une autre bloque. `filters.files.pii.uninspectable: block` demeure une règle indépendante de sécurité par défaut (fail-closed) pour le contenu de fichier sélectionné qui est opaque ou trop volumineux, même lorsque l'action de modèle de cette source est `audit`.

### Rédaction [#redaction]

`action: redact` transforme les correspondances dans les soumissions de chat Agent interactives, nouvelles et en texte seul, qui contiennent un `clientRequestId`. Les modifications, les reprises, les fichiers, les citations, les autres endpoints et les autres champs continuent d'utiliser des vérifications bloquantes.

La rédaction nécessite un `CREDS_KEY` valide. Le texte original est stocké dans un champ chiffré et non indexé, qui est supprimé ou expire avec le message ; conservez donc le même `CREDS_KEY` pour permettre au propriétaire de récupérer les originaux. Si vous le modifiez, les originaux existants deviennent inaccessibles. Le texte du message reste la version canonique et est filtré dans les exports ordinaires.

```yaml filename="librechat.yaml"
filters:
  messages:
    pii:
      action: redact
      maxCharacters: 65536
      maxMatches: 256
      customPatterns:
        - id: organization_identifier
          label: Organization identifier
          regex: 'ORG-[A-Z0-9]{12}'
          category: custom
```

Les IDs de modèles de démarrage intégrés sont :

- `sk_prefix` : préfixes de jetons de style `sk-`.
- `bearer_header` : jetons bearer dans le texte.
- `api_key_header` : texte au format en-tête `api-key`.

Les modèles personnalisés utilisent la syntaxe d'expression régulière à temps linéaire et bornée de RE2JS. Les références arrière (backreferences) et les lookarounds ne sont pas pris en charge, et certains caractères d'échappement diffèrent des expressions régulières JavaScript. LibreChat rejette les modèles invalides ou non pris en charge lors du chargement de la configuration.

### Provenance des messages [#message-provenance]

`filters.messages.unattributedAssistantContent` contrôle la manière dont le contenu d'assistant hérité sans provenance est classé :

- `model_output` (par défaut) : préserve le comportement hérité en traitant le contenu de l'assistant non attribué comme une sortie de modèle.
- `inspect` : traite le contenu de l'assistant autrement non attribué, y compris les projections de pièces jointes sélectionnées, comme du contenu soumis. Le contenu de l'assistant explicitement marqué comme sortie du modèle reste exempté.

Cette classification peut affecter une politique héritée `messageFilter.pii` activée, même lorsque `filters.messages.pii` est omis. Inventoriez ou migrez les anciens enregistrements avant de vous fier à une inspection rétroactive.

### Fichiers non inspectables [#uninspectable-files]

`filters.files.pii.uninspectable` contrôle le contenu des fichiers sélectionnés que LibreChat ne peut pas inspecter, y compris le contenu opaque ou trop volumineux :

- `allow` (par défaut) : préserve la compatibilité et autorise le contenu.
- `block` : le rejette avant les effets secondaires du fournisseur ou du stockage.

Déployez `block` avec précaution. Cela peut rendre d'anciens fichiers indisponibles pour une réutilisation tant qu'un texte inspectable n'est pas présent.

### Contenu stocké et réutilisé [#stored-and-reused-content]

L'activation ou la modification d'une politique ne réécrit ni ne supprime les enregistrements stockés. LibreChat applique la politique actuelle lorsque du contenu protégé est soumis, copié, partagé, réutilisé ou devient lié à un modèle.

Les modifications de métadonnées sécurisées peuvent toujours aboutir, de sorte que les enregistrements bloqués restent réparables. Dans les vues de gestion, les champs de prompt ou de preset bloqués peuvent être vides avec `contentFilterBlocked: true` ; les groupes de prompts bloqués renvoient une erreur lors de la récupération directe et sont omis des réponses de collection et de réutilisation. Une mise à jour de mémoire d'arrière-plan rejetée peut être ignorée tandis que la réponse principale du chat se poursuit.

Les correspondances de texte détectées par la source renvoient une erreur HTTP `400` avec `content_filter_block`. Les rejets de fichiers non inspectables utilisent `content_filter_uninspectable`.

### Limites [#limits]

- Jusqu'à 256 champs, modèles de démarrage ou modèles personnalisés par source.
- Jusqu'à 256 modèles personnalisés sur l'ensemble de la configuration.
- IDs de modèle jusqu'à 256 caractères, étiquettes jusqu'à 512 caractères et regex jusqu'à 512 caractères.
- Jusqu'à 8 192 caractères regex au total et 8 192 instructions de filtrage compilées.

## `messageFilter` hérité [#legacy-messagefilter]

`messageFilter.pii` rejette le texte du message fourni par l'appelant correspondant avant la modération, les requêtes au modèle ou la persistance avec `message_filter_pii_block`. Il reste limité au blocage uniquement et n'accepte pas `action`. Il n'inspecte pas le contenu des fichiers ni les autres sources réutilisables couvertes par `filters`.

```yaml filename="librechat.yaml"
messageFilter:
  pii:
    starterPatterns:
      - sk_prefix
      - bearer_header
      - api_key_header
    customPatterns:
      - id: anthropic_api_key
        label: Anthropic API key
        regex: 'sk-ant-[A-Za-z0-9_-]{20,}'
```

Le filtre hérité vérifie le texte de l'utilisateur sur la route de chat et le texte fourni par l'appelant pour tous les rôles dans les requêtes de Chat Completions et de Responses compatibles avec OpenAI. Il utilise les mêmes identifiants intégrés et les mêmes règles de regex personnalisées à temps linéaire décrits ci-dessus.
