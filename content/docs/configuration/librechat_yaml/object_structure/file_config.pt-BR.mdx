## Visão geral [#overview]

O objeto `fileConfig` permite que você configure as definições de manipulação de arquivos para a aplicação, incluindo limites de tamanho e restrições de tipo MIME. Esta seção fornece um detalhamento da estrutura do objeto `fileConfig`.

Os principais campos em `fileConfig` abordados aqui:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**Notas:**

- No momento da redação, o endpoint Assistants [suporta tipos de arquivo desta lista](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google e endpoints personalizados suportam arquivos através da [RAG API.](../../rag_api.mdx)
- OpenAI, Azure OpenAI, Anthropic, Google, AWS Bedrock e endpoints personalizados oferecem suporte a uploads diretos de arquivos por meio de [Upload to Provider](/docs/features/ocr#upload-to-provider-instead).
- As seções `ocr` e `text` controlam o processamento de arquivos para recursos como [Enviar como Texto](/docs/features/upload_as_text) e [OCR](/docs/features/ocr)
- Quaisquer outros endpoints não mencionados, como Plugins, não suportam uploads de arquivos (ainda).
- O endpoint Assistants possui um valor de endpoint definido como `assistants`. Todos os outros endpoints usam o valor definido `default`.
  - Para endpoints que não são assistants, você pode ajustar as configurações de arquivo para todos eles em `default`
  - Se você quiser ajustar as configurações para um endpoint específico, você pode listar seus nomes de endpoint correspondentes:
    - `assistants`
        - não usa "default", pois possui padrões definidos separadamente dos outros.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Você pode omitir valores, caso em que o aplicativo usará os valores padrão conforme definido por tipo de endpoint listado abaixo.
- O LibreChat conta 1 megabyte da seguinte forma: `1 x 1024 x 1024`
- O streaming de resposta de upload de longa duração e os limites de busca de URL remota no lado do servidor são configurados com as variáveis de ambiente [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` e `REMOTE_FILE_FETCH_MAX_BYTES`](/docs/configuration/dotenv#file-uploads).

## Exemplo [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="Sintaxe de padrão MIME">
  O LibreChat avalia os padrões de `supportedMimeTypes` configurados pelo administrador no servidor com um mecanismo de expressão regular de tempo linear compatível com RE2. Referências retroativas (backreferences) e lookaround não são suportados. Cada padrão é compilado com o mecanismo ativo durante a validação da configuração; um padrão não suportado rejeita a configuração em vez de ser ignorado silenciosamente.
</Callout>

## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Configurações para importações de Skill, que são carregadas como arquivos `.md`, `.zip` ou `.skill`.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` oferece suporte a três parâmetros:

- `fileSizeLimit` (Número)
  - Tamanho máximo de um único upload de Skill, especificado em megabytes (MB).
  - **Padrão:** `50`
- `importCleanupConcurrency` (Inteiro)
  - Máximo de operações de limpeza simultâneas após uma falha na importação de arquivo de Skill. Use `1` para limpeza serial.
  - **Padrão:** `8`
- `deletionCleanupConcurrency` (Integer)
  - Máximo de operações de limpeza simultâneas quando uma Skill é excluída. Use `1` para limpeza serial.
  - **Padrão:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Veja [Skills](/docs/features/skills) para o restante das regras de importação, como os limites por arquivo e por entrada de arquivo.

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', 'Configurações relacionadas à qualidade e dimensões da saída de geração de imagens.', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` suporta os seguintes parâmetros:

- `percentage` (Número)
  - O tamanho de saída da imagem gerada expresso como uma porcentagem (por exemplo, `100` significa 100% do tamanho base).
  - Use isso para ajustar a escala da imagem de saída em relação a um tamanho padrão ou original.

- `px` (Número)
  - Especifica a dimensão da imagem de saída em pixels (por exemplo, `1024`).
  - Use isso para definir explicitamente o tamanho da saída da imagem gerada, independentemente do tamanho base.

Defina apenas um destes parâmetros (`percentage` ou `px`), e não ambos.

Exemplo de configuração:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Controla o redimensionamento no lado do cliente de imagens antes do upload, o que evita erros de upload causados por imagens muito grandes. Os usuários podem ativar ou desativar o redimensionamento em Configurações > Chat. Definir `enabled` aqui substitui essa escolha para todos e bloqueia a opção; omita-o para deixar os usuários no controle.

- `enabled` (Booleano)
  - Forçar redimensionamento ativado (`true`) ou desativado (`false`) para todos. Quando omitido, cada usuário decide, com o redimensionamento ativado por padrão.
- `maxWidth` (Número)
  - Largura máxima das imagens redimensionadas, em pixels. Mínimo `1`. **Padrão:** `1900`
- `maxHeight` (Number)
  - Altura máxima das imagens redimensionadas, em pixels. Mínimo `1`. **Padrão:** `1900`
- `quality` (Número)
  - Qualidade de compressão JPEG de `0` a `1`. **Padrão:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## fileTokenLimit

<OptionTable
  options={[

**Descrição:** Ao anexar conteúdo de texto, o LibreChat trunca o texto em tempo de execução até o limite de tokens configurado, logo antes da construção do prompt. fileConfig:
```yaml filename="fileConfig / fileTokenLimit"
  fileTokenLimit: 100000
```

## textFallbackWithoutTools

Quando um upload é direcionado para `none` (armazenado, disponível apenas para ferramentas) e o turno não executa nenhuma ferramenta capaz de lê-lo, o LibreChat pode entregar, em vez disso, o texto extraído do arquivo. Defina `textFallbackWithoutTools: true` para habilitar essa opção. Ela pode ser configurada globalmente em `fileConfig` ou por entrada em `fileConfig.endpoints` (incluindo `default`); um valor de endpoint tem precedência sobre o valor global.

**Padrão:** `false`

Aplica-se apenas aos anexos de mensagens cuja rota foi inferida; um destino escolhido explicitamente pelo usuário nunca é resolvido novamente, e os arquivos mantidos nos recursos de ferramenta de um agente nunca chegam a um prompt. Somente os extratores integrados de documentos e de texto simples são executados, portanto nenhuma chamada de RAG ou OCR é feita para um arquivo destinado a uma ferramenta. Arquivos existentes sem texto extraído não são preenchidos retroativamente.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

Arquivos provisionados no ambiente de execução de código dentro desta janela (em milissegundos) ignoram a verificação de disponibilidade em tempo real antes de serem reutilizados. Mínimo `0`.

**Padrão:** `21600000` (6 horas)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

Por quanto tempo, em milissegundos, a inicialização aguarda uma verificação de disponibilidade legada do File Search antes de incorporar o arquivo mesmo assim. Mínimo `1`.

**Padrão:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', 'Configurações para análise direta de arquivos de texto sem OCR.', 'Configures which file types are processed as plain text files for direct content extraction.'],

**Descrição:** A seção `text` configura quais tipos de arquivo devem ser processados usando extração direta de texto.

**Nota:** A análise de texto é o método padrão usado pelo recurso "Upload as Text" (controlado pela capacidade `context`). Consulte [Upload as Text](/docs/features/upload_as_text) para mais informações.

## stt

`fileConfig.stt` não é lido nas versões atuais do LibreChat; um bloco `stt` aqui é ignorado. Arquivos de áudio adicionados como texto são transcritos quando um provedor de conversão de fala em texto está configurado em [`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech), usando uma lista integrada de tipos de áudio: áudio MP3, MPEG, WAV, OGG, Vorbis, MP4 e M4A, FLAC, WebM, AAC, WMA e Opus.

## Prioridade de Processamento de Arquivos [#file-processing-priority]

Quando um arquivo é adicionado como texto (Upload as Text, uma colagem longa ou Contexto de Arquivo do agente), o LibreChat usa a primeira etapa que se aplicar:

1. **OCR**: uma seção `ocr` existe em `librechat.yaml` e o arquivo corresponde a `fileConfig.ocr.supportedMimeTypes`. Se o serviço de OCR falhar, o analisador de documentos integrado é tentado em seguida.
2. **Extração de texto da RAG API**: `text.supportedMimeTypes` foi restringido em relação ao padrão, a RAG API está configurada e o arquivo corresponde à lista.
3. **Analisador de documentos integrado**: arquivos PDF, DOCX, XLS e XLSX, ODT e ODS. Ele lê apenas as camadas de texto.
4. **Conversão de fala em texto**: arquivos de áudio, quando um provedor de STT estiver configurado.
5. **Análise de texto**: arquivos que correspondem a `text.supportedMimeTypes`.

Uma imagem ou um PDF digitalizado sem OCR configurado não possui texto extraível, e o envio falha com uma mensagem informando que é necessário um serviço de OCR.

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', 'Como um arquivo anexado chega ao modelo quando o usuário não escolheu um destino.', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

I need the text you want translated. Your message contains only the instructions and no content to translate. Please paste the LibreChat documentation (Markdown/MDX) you'd like me to translate into Português (Brasil).

- `provider`: o arquivo é enviado ao modelo como um anexo nativo (entrada de imagem, PDF, áudio ou vídeo).
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`: o arquivo é armazenado e fica disponível para ferramentas como execução de código ou pesquisa em arquivos, mas não é enviado ao modelo.

`overrides` mapeia um tipo MIME, ou um curinga `type/*`, para um valor. `fallback` se aplica a tudo que não estiver listado. O LibreChat verifica os overrides do endpoint, depois o fallback do endpoint, depois os overrides de nível superior, depois o fallback de nível superior e, por fim, o padrão integrado.

O padrão embutido envia imagens, áudio, vídeo e PDFs ao provedor e todo o restante como texto. Ele também se ajusta ao endpoint: um PDF em um provedor que não consegue ler PDFs é enviado como texto, áudio ou vídeo em um provedor sem suporte a mídia é transcrito ou removido do prompt, o AWS Bedrock recebe os tipos de documento suportados nativamente, e tipos sem forma de extrair texto (arquivos compactados, por exemplo) são definidos como `none`. Os valores que você configurar são usados exatamente como escritos, sem esses ajustes.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## supportedMimeTypes [#supportedmimetypes-2]

**Chave:**
<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Uma lista de expressões regulares que definem os tipos MIME permitidos para upload.', 'Each pattern must compile with the active server regex engine or configuration validation fails.'],
  ]}
/>

**Padrão:** Varia conforme o endpoint

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
assistants:
  supportedMimeTypes:
      - "image/.*"
      - "application/pdf"
```

O LibreChat normaliza aliases MIME comuns antes de aplicar esses padrões. Em particular, `application/x-shellscript` (relatado pelo Chrome no Linux) e `text/x-shellscript` (relatado pelo libmagic) tornam-se `application/x-sh`. Uma lista de permissões personalizada que aceite scripts de shell deve, portanto, permitir o tipo canônico `application/x-sh`. Uploads rejeitados retornam o tipo não suportado relatado ao cliente em vez de um erro genérico do servidor.

## Limpeza de Arquivos e Vetores Retidos [#retained-file-and-vector-cleanup]

A exclusão de arquivos preserva o primário legível até que a limpeza do armazenamento secundário seja confirmada. `fileConfig.retainedFileCleanup` tem como padrão `false`: arquivos incorporados e destinos retidos do Code Interpreter não são limpos de forma destrutiva até que essa opção seja explicitamente habilitada. Habilite-a somente após todas as réplicas e alvos de rollback lerem os destinos de arquivos retidos.

| Campo | Padrão | Significado |
| ------------------------------ | ------- | -------------------------------------------------------------------------------------------------- |
| `retainedFileCleanup` | `false` | Ative a limpeza usando os metadados de destino retidos após a implantação do leitor. |
| `vectorOwnershipTrackingStart` | Não definido | Data e hora UTC de corte, escolhida após a aposentadoria de todos os gravadores legados de vetores e de todos os alvos de rollback. |
| `vectorDeletionConcurrency` | `4` | Inteiro de `1` a `16`; número máximo de exclusões de namespaces em andamento por arquivo. |

A exclusão de vetores exige, adicionalmente, prova completa e registrada de propriedade e de inserção no momento da escrita, em ou após o ponto de corte do escritor seguro. Prova ausente, inválida, futura ou anterior ao ponto de corte falha de forma segura e mantém o arquivo e seus vetores no lugar. Definir o ponto de corte não corrige metadados de propriedade antigos, e ele não deve ser retroativamente alterado para tornar arquivos legados ambíguos elegíveis.

Os alvos de limpeza abrangem cada namespace de entidade registrado e o namespace sem escopo. Um namespace é aceito como limpo após uma resposta DELETE bem-sucedida. Um `404` é aceito como ausência somente após uma verificação de inventário bem-sucedida, no mesmo namespace, que confirme a exclusão do arquivo. Se qualquer item secundário ou namespace não puder ser confirmado como ausente, o item primário permanece disponível para nova tentativa. Essas configurações não preenchem retroativamente registros legados; planeje uma reconciliação separadamente verificada para arquivos históricos ambíguos.
