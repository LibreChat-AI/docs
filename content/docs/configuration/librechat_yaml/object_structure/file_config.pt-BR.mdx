## Visão geral [#overview]

O objeto `fileConfig` permite que você configure as definições de manipulação de arquivos para a aplicação, incluindo limites de tamanho e restrições de tipo MIME. Esta seção fornece um detalhamento da estrutura do objeto `fileConfig`.

Os principais campos em `fileConfig` são:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`
  - `stt`

**Notas:**

- No momento da redação, o endpoint Assistants [suporta tipos de arquivo desta lista](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google e endpoints personalizados suportam arquivos através da [RAG API.](../../rag_api.mdx)
- Os endpoints OpenAI, Azure OpenAI, Anthropic, Google e AWS Bedrock suportam uploads diretos de arquivos via [Upload to Provider](/docs/features/ocr#5-upload-files-to-provider-direct).
- As seções `ocr`, `text` e `stt` controlam o processamento de arquivos para recursos como [Upload as Text](/docs/features/upload_as_text) e [OCR](/docs/features/ocr)
- Quaisquer outros endpoints não mencionados, como Plugins, não suportam uploads de arquivos (ainda).
- O endpoint Assistants possui um valor de endpoint definido como `assistants`. Todos os outros endpoints usam o valor definido `default`.
  - Para endpoints que não são assistants, você pode ajustar as configurações de arquivo para todos eles em `default`
  - Se você quiser ajustar as configurações para um endpoint específico, você pode listar seus nomes de endpoint correspondentes:
    - `assistants`
        - não usa "default", pois possui padrões definidos separadamente dos outros.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Você pode omitir valores, caso em que o aplicativo usará os valores padrão conforme definido por tipo de endpoint listado abaixo.
- O LibreChat conta 1 megabyte da seguinte forma: `1 x 1024 x 1024`
- O streaming de resposta de upload de longa duração e os limites de busca de URL remota no lado do servidor são configurados com as variáveis de ambiente [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` e `REMOTE_FILE_FETCH_MAX_BYTES`](/docs/configuration/dotenv#file-uploads).

## Exemplo [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

<Callout type="info" title="Sintaxe de padrão MIME">
  O LibreChat avalia os padrões de `supportedMimeTypes` configurados pelo administrador no servidor com um mecanismo de expressão regular de tempo linear compatível com RE2. Referências retroativas (backreferences) e lookaround não são suportados. Cada padrão é compilado com o mecanismo ativo durante a validação da configuração; um padrão não suportado rejeita a configuração em vez de ser ignorado silenciosamente.
</Callout>
## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Configurações para importações de Skill, que são carregadas como arquivos `.md`, `.zip` ou `.skill`.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` oferece suporte a três parâmetros:

- `fileSizeLimit` (Número)
  - Tamanho máximo de um único upload de Skill, especificado em megabytes (MB).
  - **Padrão:** `50`
- `importCleanupConcurrency` (Inteiro)
  - Máximo de operações de limpeza simultâneas após uma falha na importação de arquivo de Skill. Use `1` para limpeza serial.
  - **Padrão:** `8`
- `deletionCleanupConcurrency` (Integer)
  - Máximo de operações de limpeza simultâneas quando uma Skill é excluída. Use `1` para limpeza serial.
  - **Padrão:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Veja [Skills](/docs/features/skills) para o restante das regras de importação, como os limites por arquivo e por entrada de arquivo.

## imageGeneration

<OptionTable
  options={[

`imageGeneration` suporta os seguintes parâmetros:

- `percentage` (Número)
  - O tamanho de saída da imagem gerada expresso como uma porcentagem (por exemplo, `100` significa 100% do tamanho base).

  - Especifica a dimensão da imagem de saída em pixels (por exemplo, `1024`).

Defina apenas um destes parâmetros (`percentage` ou `px`), e não ambos.

Exemplo de configuração:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Controla o redimensionamento no lado do cliente de imagens antes do upload, o que evita erros de upload causados por imagens muito grandes. Os usuários podem ativar ou desativar o redimensionamento em Configurações > Chat. Definir `enabled` aqui substitui essa escolha para todos e bloqueia a opção; omita-o para deixar os usuários no controle.

- `enabled` (Booleano)
  - Forçar redimensionamento ativado (`true`) ou desativado (`false`) para todos. Quando omitido, cada usuário decide, com o redimensionamento ativado por padrão.
- `maxWidth` (Número)
  - Largura máxima das imagens redimensionadas, em pixels. Mínimo `1`. **Padrão:** `1900`
- `maxHeight` (Number)
  - Altura máxima das imagens redimensionadas, em pixels. Mínimo `1`. **Padrão:** `1900`
- `quality` (Número)
  - Qualidade de compressão JPEG de `0` a `1`. **Padrão:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## defaultLLMDeliveryPath

Controla como um upload sem um destino explicitamente selecionado entra no contexto do modelo. Configure-o globalmente em `fileConfig` ou substitua-o para uma entrada nomeada em `fileConfig.endpoints`.

- `provider` envia o arquivo original através do caminho de arquivo ou mídia nativo do provedor do modelo.
- `text` extrai ou transcreve conteúdo suportado e adiciona o texto resultante ao contexto.
- `none` armazena o arquivo sem colocá-lo diretamente no contexto do modelo; ferramentas selecionadas ainda podem disponibilizá-lo quando necessário.

`fallback` lida com tipos MIME não correspondentes. `overrides` aceita tipos MIME exatos, como `application/pdf`, ou curingas, como `image/*`. A resolução prefere substituições (overrides) e fallback do endpoint, seguidos pelos valores globais. Sem uma configuração explícita, imagens, áudio, vídeo e PDFs preferem a entrega nativa do provedor; outros conteúdos recuperáveis usam texto. O LibreChat rebaixa caminhos nativos não suportados para texto quando a extração é possível, ou para `none` caso contrário.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## legacyFileUploadUX

O uploader unificado padrão escolhe a entrega do modelo automaticamente e provisiona recursos de File Search ou Code apenas quando as ferramentas selecionadas precisam deles. Defina `legacyFileUploadUX: true` globalmente ou para um endpoint para restaurar o seletor de destino e o comportamento de upload imediato selecionado pelo usuário.

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
```

## textFallbackWithoutTools

Quando um upload é direcionado para `none` (armazenado, disponível apenas para ferramentas) e o turno não executa nenhuma ferramenta capaz de lê-lo, o LibreChat pode entregar, em vez disso, o texto extraído do arquivo. Defina `textFallbackWithoutTools: true` para habilitar essa opção. Ela pode ser configurada globalmente em `fileConfig` ou por entrada em `fileConfig.endpoints` (incluindo `default`); um valor de endpoint tem precedência sobre o valor global.

**Padrão:** `false`

Aplica-se apenas aos anexos de mensagens cuja rota foi inferida; um destino escolhido explicitamente pelo usuário nunca é resolvido novamente, e os arquivos mantidos nos recursos de ferramenta de um agente nunca chegam a um prompt. Somente os extratores integrados de documentos e de texto simples são executados, portanto nenhuma chamada de RAG ou OCR é feita para um arquivo destinado a uma ferramenta. Arquivos existentes sem texto extraído não são preenchidos retroativamente.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

Arquivos provisionados no ambiente de execução de código dentro desta janela (em milissegundos) ignoram a verificação de disponibilidade em tempo real antes de serem reutilizados. Mínimo `0`.

**Padrão:** `21600000` (6 horas)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

Por quanto tempo, em milissegundos, a inicialização aguarda uma verificação de disponibilidade legada do File Search antes de incorporar o arquivo mesmo assim. Mínimo `1`.

**Padrão:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Lista de padrões de tipo MIME para arquivos de áudio que devem ser transcritos com STT.', 'Uses regular expressions to match audio file types.'],
  ]}
/>

**Padrão:** Formatos de áudio comuns

```yaml filename="fileConfig / stt / supportedMimeTypes"

  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

**Notas:**
- Arquivos que correspondem aos padrões `text` são processados com extração de texto simples
- Arquivos que correspondem aos padrões `ocr` são processados com o serviço de OCR fornecido
- Arquivos que correspondem aos padrões `stt` são processados com transcrição de Speech-to-Text.
- **Precedência de processamento: OCR > STT > análise de texto > fallback**
- Arquivos que não corresponderem a nenhum padrão usarão a análise de texto como fallback

## Prioridade de Processamento de Arquivos [#file-processing-priority]

O LibreChat processa arquivos enviados com base na correspondência de tipo MIME com a seguinte **ordem de prioridade**:

1. **OCR** - Se o arquivo corresponder a `ocr.supportedMimeTypes` E o OCR estiver configurado
2. **STT** - Se o arquivo corresponder a `stt.supportedMimeTypes` E o STT estiver configurado
3. **Análise de Texto** - Se o arquivo corresponder a `text.supportedMimeTypes`
4. **Fallback** - Análise de texto como último recurso

Esta ordem de processamento garante uma qualidade de extração ideal, mantendo a funcionalidade mesmo quando serviços especializados (OCR/STT) não estão configurados.

### Exemplos de Processamento [#processing-examples]

**Arquivo PDF com OCR configurado:**
- O arquivo corresponde a `ocr.supportedMimeTypes`
- **Usa OCR** para extrair texto
- Melhor qualidade para PDFs digitalizados e imagens

**Arquivo PDF sem OCR configurado:**
- O arquivo corresponde a `text.supportedMimeTypes` (ou usa o fallback)
- **Usa a biblioteca** de análise de texto
- Funciona bem para PDFs digitais com texto selecionável

**Arquivo Python:**
- O arquivo corresponde a `text.supportedMimeTypes`
- **Usa análise de texto** (não é necessário OCR)
- Extração direta de texto

**Arquivo de áudio com STT configurado:**
- O arquivo corresponde a `stt.supportedMimeTypes`
- **Usa STT** para transcrever áudio para texto

**Arquivo de imagem sem OCR configurado:**
- O arquivo corresponde a `ocr.supportedMimeTypes`, mas o OCR não está disponível
- **Recorre à análise de texto**
- Capacidade de extração limitada sem OCR

Este sistema de prioridade permite que recursos como "Upload as Text" funcionem sem exigir configuração de OCR, enquanto ainda aproveita o OCR quando disponível para uma melhor qualidade de extração.

## supportedMimeTypes [#supportedmimetypes-3]

**Chave:**
<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Uma lista de expressões regulares que definem os tipos MIME permitidos para upload.', 'Each pattern must compile with the active server regex engine or configuration validation fails.'],
  ]}
/>

**Padrão:** Varia conforme o endpoint

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
assistants:
  supportedMimeTypes:
      - "image/.*"
      - "application/pdf"
```

O LibreChat normaliza aliases MIME comuns antes de aplicar esses padrões. Em particular, `application/x-shellscript` (relatado pelo Chrome no Linux) e `text/x-shellscript` (relatado pelo libmagic) tornam-se `application/x-sh`. Uma lista de permissões personalizada que aceite scripts de shell deve, portanto, permitir o tipo canônico `application/x-sh`. Uploads rejeitados retornam o tipo não suportado relatado ao cliente em vez de um erro genérico do servidor.
