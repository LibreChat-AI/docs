Setiap endpoint dalam array `custom` harus memiliki struktur berikut:

## Contoh [#example]

```yaml filename="Endpoint Object Structure"
endpoints:
  custom:
    # Example using Mistral AI API
    - name: 'Mistral'
      apiKey: '${YOUR_ENV_VAR_KEY}'
      baseURL: 'https://api.mistral.ai/v1'
      models:
        default: ['mistral-tiny', 'mistral-small', 'mistral-medium', 'mistral-large-latest']
      titleConvo: true
      titleTiming: 'immediate'
      titleModel: 'mistral-tiny'
      modelDisplayLabel: 'Mistral'
      # customParams:
      #   reasoningFormat: reasoning_object
      #   reasoningKey: reasoning_content
      # tokenConfig:
      #   mistral-large-latest:
      #     prompt: 2
      #     completion: 6
      #     context: 128000
      # addParams:
      #   safe_prompt: true # Mistral specific value for moderating messages
      # NOTE: For Mistral, it is necessary to drop the following parameters or you will encounter a 422 Error:
      dropParams: ['stop', 'user', 'frequency_penalty', 'presence_penalty']

    # xAI Grok 4.7 through the OpenAI-compatible API
    - name: 'xai'
      apiKey: '${XAI_API_KEY}'
      baseURL: 'https://api.x.ai/v1'
      models:
        default: ['grok-4.7']
        fetch: true
      titleConvo: true
      titleModel: 'grok-4.7'
      modelDisplayLabel: 'xAI'

    # Example using the native Anthropic Messages API
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5', 'claude-opus-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
      modelDisplayLabel: 'Claude (Compatible)'
```

## tenantId

Cakupan tenant opsional untuk endpoint kustom YAML. Hilangkan `tenantId` untuk mempertahankan ketersediaan di seluruh deployment. Dengan sebuah nilai, endpoint tersebut, kredensial yang dikelola deployment, dan Model Specs yang merujuk padanya hanya tersedia dalam konfigurasi efektif tenant tersebut. Tenant permintaan yang terautentikasi lebih diutamakan daripada ID tenant yang mungkin kedaluwarsa pada catatan pengguna. Permintaan tanpa tenant tidak akan menerima endpoint yang dicakup.

Nilai tersebut harus berupa ID penyewa yang sudah ada dan tepat, antara 1 hingga 128 karakter, hanya menggunakan huruf, angka, tanda hubung, garis bawah, atau titik. Spasi dan sentinel `__SYSTEM__` yang dicadangkan akan ditolak. Bidang ini memilih cakupan; bidang ini tidak membuat penyewa atau memberikan keanggotaan. Tingkatkan **setiap replika API sebelum menambahkan entri YAML yang dicakup oleh penyewa**. Replika yang lebih lama tidak menerapkan bidang baru ini dan masih dapat memperlakukan endpoint sebagai cakupan seluruh penyebaran (deployment-wide).

```yaml filename="endpoints / custom / tenantId"
endpoints:
  custom:
    - name: 'Acme Gateway'
      tenantId: 'acme'
      apiKey: '${ACME_GATEWAY_API_KEY}'
      baseURL: 'https://gateway.example.com/v1'
      models:
        default: ['gpt-6-sol']
        fetch: false
```

Scoping diterapkan sebelum penimpaan konfigurasi dan augmentasi runtime, serta tetap diberlakukan pada cache hits, pembacaan YAML-saja, dan pembacaan fallback. Penimpaan parsial tidak dapat mewarisi kredensial gateway penyewa lain. Jika pemfilteran menghapus Model Specs terakhir, kontrol model normal akan dipulihkan kecuali jika pengaturan YAML eksplisit atau antarmuka basis data menimpanya. Endpoint yang tidak dicakup (unscoped) tetap tersedia seperti sebelumnya.

**Wajib**

**Contoh:**

```yaml filename="endpoints / custom / baseURL"

```

atau

```yaml filename="endpoints / custom / baseURL"

```

atau

```yaml filename="endpoints / custom / baseURL"

```

**Catatan:**

- Jika `baseURL` yang Anda tetapkan adalah endpoint penyelesaian penuh, Anda dapat mengatur kolom [directEndpoint](#directendpoint) ke `true` untuk menggunakannya secara langsung.
  - Ini diperlukan karena aplikasi secara default menambahkan "/chat/completions" atau "/completion" ke `baseURL`.
- Saat menggunakan [`provider: anthropic`](#provider), atur `baseURL` ke root API yang harus dipanggil oleh SDK Anthropic, seperti `https://api.anthropic.com` atau root gateway Anda. LibreChat menggunakan path `/v1/messages` Anthropic bawaan untuk provider tersebut.
- Pada endpoint kustom yang kompatibel dengan OpenAI, ID model yang mengandung `claude` menggunakan batasan dokumen Claude: PDF dan dokumen teks diterima, sementara tipe dokumen biner non-PDF akan dilewati sebelum permintaan dikirim.

## provider

**Kunci:**

<OptionTable
  options={[
    [
      'provider',
      'String',
      'Mengarahkan endpoint kustom melalui klien penyedia asli alih-alih klien yang kompatibel dengan OpenAI standar.',
      'Currently supports `anthropic`.',
    ],
  ]}
/>

**Default:** dihilangkan, yang menggunakan jalur endpoint kustom yang kompatibel dengan OpenAI.

**Nilai yang Didukung:**

- **`"anthropic"`** - Menggunakan klien asli Anthropic `/v1/messages` dengan `baseURL`, `apiKey`, `headers`, `addParams`, `dropParams`, dan `customParams.paramDefinitions` milik endpoint ini.

**Contoh:**

```yaml filename="endpoints / custom / provider"
endpoints:
  custom:
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default:
          - 'claude-sonnet-4-5'
          - 'claude-opus-4-5'
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
      modelDisplayLabel: 'Claude (Compatible)'
```

**Catatan:**

- Gunakan `provider: anthropic` untuk Anthropic itu sendiri atau gateway yang kompatibel dengan Anthropic yang menggunakan Messages API asli.
- Cantumkan model secara eksplisit di bawah `models.default`; `models.fetch` gaya OpenAI tidak digunakan untuk endpoint kustom Anthropic bawaan.
- Penyedia menyiratkan parameter UI Anthropic kecuali Anda secara eksplisit menetapkan `customParams.defaultParamsEndpoint` yang berbeda.
- endpoint tanpa `provider` tetap mempertahankan perilaku yang kompatibel dengan OpenAI.

- Untuk menggunakan gambar kustom, atur `iconURL` ke URL gambar atau jalur yang disajikan oleh LibreChat, seperti `/assets/my-icon.svg`.
- Terdapat juga "known endpoints" (tidak peka huruf besar/kecil), yang telah disediakan ikonnya. Jika `name` endpoint Anda cocok dengan nama-nama berikut, Anda harus menghilangkan kolom ini:

**Format Penalaran:**

- **`reasoning_effort`** - Mengirim parameter `reasoning_effort` versi lama.
- **`reasoning_object`** - Mengirim objek `reasoning`, seperti `{ effort, summary }`, untuk penyedia yang mengikuti bentuk yang kompatibel dengan OpenAI yang lebih baru.
- **`disabled`** - Menekan parameter penalaran (reasoning) bahkan ketika pengguna atau Model Specs memilih penalaran.

**Pemutaran ulang penalaran (Reasoning replay):**

- Gunakan `includeReasoningContent: true` untuk penyedia yang kompatibel dengan OpenAI yang memerlukan `reasoning_content` asisten untuk diputar ulang selama giliran pemanggilan alat (tool-call).
- Gunakan `includeReasoningHistory: true` hanya untuk penyedia yang juga memerlukan `reasoning_content` yang direkonstruksi dari riwayat yang dipertahankan di seluruh giliran berikutnya, seperti beberapa gateway yang kompatibel dengan Xiaomi MiMo atau Kimi.

**Catatan penyedia Anthropic:**

Gunakan [`provider: anthropic`](#provider) ketika endpoint kustom harus menggunakan API Messages Anthropic asli. Gunakan `customParams.defaultParamsEndpoint: anthropic` tanpa `provider` hanya ketika Anda masih memerlukan jalur endpoint kustom yang kompatibel dengan OpenAI tetapi menginginkan metadata parameter dan adaptasi permintaan bergaya Anthropic.

**Contoh:**

```yaml filename="endpoints / custom / customParams"
customParams:
  reasoningFormat: reasoning_object
  reasoningKey: reasoning_content
  includeReasoningContent: true
```

**Contoh:**

```yaml filename="endpoints / custom / headers"
headers:
  x-api-key: '${ENVIRONMENT_VARIABLE}'
  Content-Type: 'application/json'
  X-User-ID: '{{LIBRECHAT_USER_ID}}'
  X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
```

**Catatan:** Mendukung nilai variabel lingkungan dinamis, yang menggunakan format: `"${VARIABLE_NAME}"`.

Pada langkah resolusi keluar akhir, `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_BODY_*}}`, dan `{{LIBRECHAT_OPENID_*}}` yang dikenali tanpa nilai akan menjadi string kosong alih-alih diteruskan sebagai teks templat. Nama placeholder yang tidak dikenal akan tetap tidak berubah sehingga kesalahan pengetikan konfigurasi dapat terlihat.

Ketika `models.fetch: true` digunakan, header-header ini juga diselesaikan dan diteruskan ke permintaan daftar model untuk URL dasar yang dikontrol admin. Header `Authorization` yang dikonfigurasi lebih diutamakan daripada fallback `apiKey` endpoint, yang berguna untuk proksi yang sadar autentikasi yang mengembalikan daftar model per pengguna. Jika `baseURL: "user_provided"` dikonfigurasi, LibreChat tidak meneruskan templat header yang dikonfigurasi ke tujuan yang disediakan pengguna. Untuk `provider: anthropic`, header diteruskan melalui klien Anthropic asli alih-alih klien yang kompatibel dengan OpenAI.
