## 例 [#example]

```yaml filename="MCP Servers Object Structure"
# Example MCP Servers Object Structure
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
  googlesheets:
    type: sse
    url: https://mcp.composio.dev/googlesheets/some-endpoint
    requiresOAuth: true
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-API-Key: '${SOME_API_KEY}'
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
    # The “wrench” icon shows up if no icon is provided as it is the default rendering.
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-server:
    type: streamable-http
    url: https://example.com/api/
    proxy: '${MCP_PROXY_URL}'
  per-user-credentials-example:
    type: streamable-http
    url: 'https://example.com/api/'
    headers:
      X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    customUserVars:
      MY_SERVICE_API_KEY:
        title: 'My Service API Key'
        description: "Enter your personal API key for the service. You can generate one at <a href='https://myservice.example.com/developer/keys' target='_blank'>Service Developer Portal</a>."
        sensitive: true
      MY_SERVICE_PROJECT:
        title: 'Project ID'
        description: 'Enter the project ID used by this service.'
        sensitive: false
  oauth-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      authorization_url: https://example.com/oauth/authorize
      token_url: https://example.com/oauth/token
      client_id: your_client_id
      client_secret: your_client_secret
      redirect_uri: http://localhost:3080/api/mcp/oauth-example/oauth/callback
      scope: 'read execute'
  obo-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    obo:
      scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
```

<Callout type="warning" title="プロセスベースのサーバーはオペレーターが所有します">
  `type: stdio` を使用するMCPサーバー、または `command`、`args`、`env`、`cwd`、`stderr` といったプロセス関連フィールドを使用するMCPサーバーは、`librechat.yaml` で設定する必要があります。管理者設定APIはプロセスベースのエントリを拒否し、データベースやプリンシパルごとのオーバーライドによって既存のプロセスベースのサーバーを置き換えたり削除したりすることはできません。リモートのMCPサーバーは、引き続き通常の構成オーバーライドの優先順位に従います。
</Callout>

  モデル向けのツールキーは、英数字、`_`、`.`、`-` を保持し、サーバー名のその他の文字は `_` に置換されます。LibreChat はそれらの正規化されたキーを設定済みの名前にマッピングし直し、以前に保存されたエージェントのツール参照を修復します。`Sales Force` と `Sales:Force` のように、正規化すると同じ値になる2つの名前は避けてください。これらのツールキーは曖昧であるため、LibreChat は警告を表示し、誤ったサーバーへの呼び出しをルーティングするリスクを避けるために、隠蔽された（shadowed）サーバーのツールを除外します。
</Callout>

#### `title` [#title]

- **型:** 文字列 (オプション)
- **説明:** UI上でMCPサーバーに表示されるカスタム名。指定がない場合は、サーバーのキー名が使用されます。
- **バリデーション:** Unicodeの文字または数字で始まる必要があります。それ以降の文字には、Unicodeの文字、数字、結合マーク、スペース、ハイフン、およびストレートまたはカーリーアポストロフィを含めることができます。
- **例:**
  ```yaml
  my-server:
    title: 'File System Access'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `description` [#description]

- **型:** 文字列 (オプション)
- **Description:** MCPサーバーの説明。ユーザーがその目的や機能を理解できるよう、UI上に表示されます。
- **例:**
  ```yaml
  my-server:
    title: 'File System Access'
    description: 'Provides read/write access to local files and directories'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `type` [#type]

- **型:** String
- **説明:** MCPサーバーへの接続タイプを指定します。有効な値は `"stdio"`、`"websocket"`、`"streamable-http"`、または `"sse"` です。`"http"` は `"streamable-http"` の別名として受け付けられます。
- **デフォルト値:** `url` または `command` の有無と形式に基づいて決定されます。

#### `command` [#command]

- **型:** String
- **説明:** (`stdio` タイプの場合) MCPサーバーを起動するために実行するコマンドまたは実行ファイル。

#### `args` [#args]

- **型:** 文字列の配列
- **説明:** (`stdio` タイプの場合) `command` に渡すコマンドライン引数です。`${ENV_VAR}`、`{{LIBRECHAT_USER_*}}`、`{{CUSTOM_VARIABLE_NAME}}` などのプレースホルダーは、`env` と同様に各引数内で解決されます。

#### `url` [#url]

- **型:** String
- **説明:** (`websocket`、`streamable-http`、または `sse` タイプの場合) MCP サーバーに接続するための URL です。動的なユーザーフィールドのプレースホルダー (`{{LIBRECHAT_USER_*}}`) および環境変数の置換 (`${ENV_VAR}`) をサポートしています。
- **注記:**
  - `sse` 型の場合、URL は `http://` または `https://` で始まる必要があります。
  - `streamable-http` タイプの場合、URL は `http://` または `https://` で始まる必要があります。
  - `websocket` 型の場合、URLは `ws://` または `wss://` で始まる必要があります。

#### `proxy` [#proxy]

- **型:** String (任意、`sse` および `streamable-http` 型の場合)
- **説明:** このリモート MCP サーバーの送信プロキシ URL です。値には `${ENV_VAR}` を使用して環境変数を参照できます。
- **サポートされているプロトコル:** `http://`, `https://`, `socks://`, および `socks5://`
- **セキュリティ上の注意:** `proxy` は管理者によって制御されます。環境変数は解決されますが、`{{LIBRECHAT_USER_ID}}` や `customUserVars` といったユーザーが制御可能なプレースホルダーは解決されません。
- **例:**
  ```yaml
  mcpServers:
    remote-api:
      type: streamable-http
      url: https://api.example.com/mcp
      proxy: '${MCP_PROXY_URL}'
  ```

#### `headers` [#headers]

- **型:** Object (任意、`sse` および `streamable-http` 型の場合)
- **説明:** リクエストと共に送信するカスタムヘッダー。動的な値の置換のために、さまざまなプレースホルダータイプをサポートしています。
- **プレースホルダーのサポート:**
  - `{{LIBRECHAT_USER_ID}}`: 現在のユーザーIDに置き換えられ、マルチユーザーサポートを有効にします。
  - `{{LIBRECHAT_USER_*}}`: 動的なユーザーフィールドのプレースホルダー。`*` を許可された任意のフィールドの大文字バージョンに置き換えてください。
  - `{{LIBRECHAT_OPENID_*}}`: YAMLで定義されたサーバー用のOpenIDトークン/セッションプレースホルダー。
  - `{{LIBRECHAT_GRAPH_*}}`: YAMLで定義されたサーバー用のMicrosoft Graphトークンプレースホルダー。
  - `{{LIBRECHAT_BODY_*}}`: YAMLで定義されたサーバー用のリクエストボディプレースホルダー。現在の `conversationId`、`parentMessageId`、または `messageId` などに使用されます。
  - `{{CUSTOM_VARIABLE_NAME}}`: `customUserVars` で定義された変数に対してユーザーが提供した値に置き換えられます（例: `{{MY_API_KEY}}`）。
  - `${ENV_VAR}`: 環境変数 `ENV_VAR` の値に置き換えられます。

**利用可能なユーザーフィールドのプレースホルダー:**

| プレースホルダー | ユーザーフィールド | 型 | 説明 |
| ------------------------------------- | ------------------ | ---------------- | ----------------------------------------------------------- |
| `{{LIBRECHAT_USER_NAME}}`             | `name`             | String           | ユーザーの表示名 |
| `{{LIBRECHAT_USER_USERNAME}}`         | `username`         | String           | ユーザーのユーザー名 |
| `{{LIBRECHAT_USER_EMAIL}}`            | `email`            | String           | ユーザーのメールアドレス |
| `{{LIBRECHAT_USER_PROVIDER}}`         | `provider`         | String           | 認証プロバイダー (例: "email", "google", "github") |
| `{{LIBRECHAT_USER_ROLE}}`             | `role`             | String           | ユーザーのロール (例: "user", "admin") |
| `{{LIBRECHAT_USER_GOOGLEID}}`         | `googleId`         | String           | GoogleアカウントID |
| `{{LIBRECHAT_USER_FACEBOOKID}}`       | `facebookId`       | String           | FacebookアカウントID |
| `{{LIBRECHAT_USER_OPENIDID}}`         | `openidId`         | String           | OpenIDアカウントID |
| `{{LIBRECHAT_USER_SAMLID}}`           | `samlId`           | String           | SAMLアカウントID |
| `{{LIBRECHAT_USER_LDAPID}}`           | `ldapId`           | String           | LDAPアカウントID |
| `{{LIBRECHAT_USER_GITHUBID}}`         | `githubId`         | String           | GitHubアカウントID |
| `{{LIBRECHAT_USER_DISCORDID}}`        | `discordId`        | String           | DiscordアカウントID |
| `{{LIBRECHAT_USER_APPLEID}}`          | `appleId`          | String           | AppleアカウントID |

**注:** 不足しているフィールドは空の文字列に置き換えられます。

`{{LIBRECHAT_BODY_*}}` プレースホルダーはリクエストスコープです。LibreChat はアクティブな実行のために MCP 接続を作成し、その実行内のツール呼び出し間で再利用し、リクエスト終了時にクリーンアップします。リクエストスコープのサーバーは永続的なツールキャッシュから除外されるため、リクエスト固有のヘッダーや URL がアクティブな実行外で再利用されることはありません。Agent Builder は、1 つのランタイムツール選択を通じてサーバー全体をアタッチし、実行がボディ値を提供した後にそのツールを解決します。OAuth を完了すると認可は保存されますが、そのリクエストコンテキストが存在するまで接続は保留されます。`{{LIBRECHAT_USER_*}}`、`{{LIBRECHAT_OPENID_*}}`、および `{{LIBRECHAT_GRAPH_*}}` プレースホルダーは引き続きサーバーをユーザースコープにしますが、HTTP トランスポートは各ツール呼び出しの前に解決されたヘッダーを更新し、それ自体で強制的に再接続することはありません。

`{{LIBRECHAT_BODY_PARENTMESSAGEID}}` は、ネイティブのAgentチャット、OpenAI互換のAgents APIリクエスト、およびレガシーなAssistants実行において、ルートターンの親メッセージを受け取ります。Open Responsesリクエストには互換性のある親メッセージモデルが存在しないため、このプレースホルダーを必須とするサーバーはそのインターフェース上で失敗（クローズ）します。`previous_response_id` はこれの代わりとして置換されません。

OpenIDのアクセストークンとIDトークンは、それぞれ個別に有効期限が切れます。`{{LIBRECHAT_OPENID_ACCESS_TOKEN}}` および従来の `{{LIBRECHAT_OPENID_TOKEN}}` は保存されたアクセストークンの有効期限を使用しますが、`{{LIBRECHAT_OPENID_ID_TOKEN}}` は現在のIDトークンを必要とします。認証トークンが利用できない、または期限切れの場合、LibreChatは空の値やリテラルのBearer値を送信する代わりに、アクション可能な `401` 再認証エラーを返します。再試行する前に再度サインインしてください。OpenID IDを持たないリクエストの場合、それらの未解決の認証情報プレースホルダーを含むヘッダーは完全に省略されます。IDメタデータのプレースホルダーは、既存の空値の動作を維持します。

信頼できるオペレーターは、サインインしたユーザーのライブOpenIDアクセストークンを、YAMLで定義されたリモートMCPサーバーに直接渡すことができます：

```yaml
mcpServers:
  trusted-api:
    type: streamable-http
    url: https://mcp.example.com/mcp
    headers:
      Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'
```

MCPサーバーがユーザーのアップストリームアクセストークンを受け取ることを信頼できる場合にのみ、直接パススルーを使用してください。明示的なMCP OAuth、[on-behalf-of exchange](#obo)、および管理者APIキー認証が、このヘッダーよりも優先されます。LibreChatは接続前にライブセッショントークンを解決し、`401`または`403`エラーが発生した後に一度だけ接続をリフレッシュします。サーバーがすでにツール呼び出しを実行している可能性があるため、拒否されたツール呼び出しは自動的に再試行されません。復旧が成功した後に、意図的にツールを再試行してください。トークンをリフレッシュできない場合は、ユーザーは再度サインインする必要があります。

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` は、ユーザーの再利用可能な OpenID アクセストークンを、on-behalf-of フローを通じて Microsoft Graph トークンに交換します。要求されるスコープは [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration) から取得されます。このデフォルト値は `https://graph.microsoft.com/.default` で、`OPENID_GRAPH_SCOPES`（人物およびグループ検索）とは別のものです。

- **例:**
  ```yaml
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-API-Key: '${SOME_API_KEY}'
    Authorization: 'Bearer ${SOME_AUTH_TOKEN}'
  ```

#### `requestHeaders` [#requestheaders]

- **型:** Object (任意、`sse` および `streamable-http` 型の場合)
- **説明:** ヘッダーはアクティブなチャットリクエストに対してのみ解決されます。これらは `headers` と同じプレースホルダーを使用し、`headers` にマージされます。両方のオブジェクトで同じ名前が定義されている場合は、こちらが優先されます。
- **検出動作:** ツール検出は `requestHeaders` を完全に省略するため、`{{LIBRECHAT_BODY_*}}` のようなリクエスト専用の値がサーバーのツールカタログを隠すことはありません。アクティブな実行は、接続時にそれらを解決して送信します。

```yaml
requestHeaders:
  X-Conversation-ID: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
  X-Schedule-ID: '{{LIBRECHAT_BODY_SCHEDULEID}}'
```

#### `apiKey` [#apikey]

- **型:** Object (任意、`sse` および `streamable-http` 型の場合)
- **説明:** MCPサーバーのAPIキー認証設定です。APIキーベースの認証を設定するための構造化された方法を提供します。
- **サブキー:**
  - `source`: 文字列(必須) - APIキーの取得元。指定可能な値:
    - `"admin"`: API キーは管理者が `key` で設定します
    - `"user"`: APIキーはユーザーがUIを通じて提供します
  - `key`: String - (`source: "admin"` の場合) すべてのユーザーで共有される API キーの値です。`${ENV_VAR}` 形式の環境変数参照に対応しています。`source: "admin"` の場合、`key` を省略するとヘッダーは送信されません。
  - `authorization_type`: 文字列(必須) - APIキーをリクエストで送信する方法。オプション:
    - `"bearer"`: `Authorization: Bearer <key>` として送信されます
    - `"basic"`: `Authorization: Basic <key>` として送信されます
    - `"custom"`: カスタムヘッダーで送信されます（`custom_header`が必要です）
  - `custom_header`: 文字列 - (`authorization_type` が `"custom"` の場合に使用)APIキーに使用するヘッダー名。省略された場合は `X-Api-Key` がデフォルトとなります。
- **例:**

  ```yaml
  # Admin-provided API key with Bearer auth
  my-server:
    type: streamable-http
    url: https://api.example.com/mcp
    apiKey:
      source: 'admin'
      key: '${MY_SERVER_API_KEY}'
      authorization_type: 'bearer'

  # User-provided API key with custom header
  another-server:
    type: sse
    url: https://api.example.com/sse
    apiKey:
      source: 'user'
      authorization_type: 'custom'
      custom_header: 'X-API-Key'
  ```

UI作成の共有サーバーで `apiKey.source: user` を使用している場合、保存されたキーは正規化されたリクエスト先に紐づけられます。URLのパスやクエリ、プロキシ、トランスポート、認証の形式やヘッダー、または設定されたOAuthクライアントや接続先を変更すると、ユーザーは新しいキーを入力する必要があります。実質的に同等の変更や見た目だけの変更の場合は、キーはそのまま保持されます。既存のレガシーキーは、変更されていない接続先のままであれば引き続き機能します。置換できるのは現在宣言されている認証情報変数のみであり、これには `requestHeaders` 内の変数も含まれます。古い生成名が注入されても、そのキーを再利用することはできません。すべての **APIレプリカ** でアップグレードを完了させてください。設定を書き込むものも含みます。ユーザーに表示される内容については、[UIからサーバーを作成する](/docs/features/mcp#create-a-server-from-the-ui) を参照してください。

#### `iconPath` [#iconpath]

- **型:** 文字列 (オプション)
- **説明:** ツール選択ダイアログに表示されるツールの表示アイコンを定義します。

#### `chatMenu` [#chatmenu]

- **型:** Boolean (オプション)
- **説明:** `false` に設定すると、そのサーバーはチャット入力欄の **MCP Servers** セクションから除外され、サーバーを指定したチャットリクエストは拒否されます。エージェントは引き続きこのサーバーを使用でき、このサーバーを指定しているモデルスペックも同様に使用できます。
- **デフォルト値:** `true`
- **例:**
  ```yaml
  mcpServers:
    internal-tools:
      command: npx
      args: ['-y', 'internal-mcp-server']
      chatMenu: false # only available in the Agent Builder
  ```

#### `serverInstructions` [#serverinstructions]

- **型:** Boolean または String (任意)
- **説明:** MCPサーバーの指示がエージェントのコンテキストにどのように注入されるかを制御します。サーバーの指示は、個々のツールの説明を補完し、MCPサーバー全体に対する高レベルな使用ガイダンスを提供します。
- **オプション:**
  - **`undefined`** (デフォルト): 指示は含まれません
  - **`true`**: サーバーが提供する指示（利用可能な場合）を使用します。包括的なガイダンスを備えた、ドキュメントが整備されたサーバーに最適です。
  - **`false`**: 指示を明示的に無効にします。コンテキストトークンの節約や、ツールが自明である場合に便利です。
  - **`string`**: カスタム指示を使用します（サーバーから提供された指示を上書きします）。アプリケーション固有のワークフローや、サーバーの指示では不十分な場合に最適です。
- **デフォルト値:** `undefined` (指示は含まれません)
- **注記:**
  - `serverInstructions` が設定され、サーバーのツールがエージェントで利用可能な場合、指示は自動的に注入されます。
  - 複数のサーバーがそれぞれエージェントのコンテキストに指示を提供できます
  - LibreChatは、サーバーがアドバタイズするテキストを、設定された宣言とは別に保存します。インスペクションは `true` やオペレーターが作成した文字列を置き換えることはなく、以前のビルドからのRedisバックエンドのレジストリエントリは、初期化中に自動的に更新されます。
- **例:**

  ```yaml
  # Use server-provided instructions
  serverInstructions: true

  # Use custom instructions
  serverInstructions: |
    When using this filesystem server:
    1. Always use absolute paths for file operations
    2. Check file permissions before attempting write operations

  # Explicitly disable instructions
  serverInstructions: false
  ```

#### `env` [#env]

- **型:** Object (オプション、`stdio` 型のみ)
- **説明:** プロセスを生成する際に使用する環境変数。
- **プレースホルダーのサポート:**
  - `{{LIBRECHAT_USER_ID}}`: 現在のユーザーのIDに置き換えられます。
  - `{{LIBRECHAT_USER_*}}`: 動的なユーザーフィールドのプレースホルダー（例: `{{LIBRECHAT_USER_EMAIL}}`）。
  - `{{CUSTOM_VARIABLE_NAME}}`: `customUserVars` で定義された変数に対してユーザーが提供した値に置き換えられます（例: `{{MY_API_KEY}}`）。
  - `${ENV_VAR}`: サーバー側の環境変数 `ENV_VAR` の値に置き換えられます。

#### `timeout` [#timeout]

- **型:** 整数 (オプション)
- **説明:** MCP サーバーへのリクエスト(ツール呼び出しを含む)のタイムアウト時間(ミリ秒)。0 以上の整数である必要があります。
- **デフォルト値:** `60000`(60秒)
- **注:** 長時間のツール呼び出しが途中で打ち切られる場合は、LibreChat または MCP サーバーの前段にあるリバースプロキシ(nginx、Traefik など)のタイムアウト設定を確認してください。
- **例:**
  ```yaml
  mcpServers:
    data-processor:
      type: streamable-http
      url: https://api.example.com/mcp
      initTimeout: 15000 # 15 seconds to connect
      timeout: 60000 # 60 seconds per tool call
  ```

#### `initTimeout` [#inittimeout]

- **型:** 整数 (オプション)
- **説明:** MCPサーバーの初期化にかかるタイムアウト時間（ミリ秒）です。0以上の整数を指定する必要があります。ユーザーがOAuthサインインを完了するまでの制限時間は設定しません。その制限時間は `MCP_OAUTH_HANDLING_TIMEOUT` で指定します（[OAuthコールバックURL](#oauth-callback-url) を参照）。
- **デフォルト値:** `30000` (30秒)

#### `requiresOAuth` [#requiresoauth]

- **型:** Boolean (オプション、リモートトランスポートのみ: `sse`, `streamable-http`, `websocket`)
- **説明:** このサーバーが OAuth 認証を必要とするかどうか。指定がない場合、サーバーの起動時に自動検出されます。オプションですが、サーバーが OAuth を必要とするかどうかがわかっている場合は、この値を明示的に設定することをお勧めします。
- **デフォルト値:** 指定がない場合は自動検出されます
- **注記:**
  - リモート（URLベース）トランスポートである `sse`、`streamable-http`、および `websocket` に適用されます。認証対象のURLを持たない `stdio` サーバーには影響しません。
  - 自動検出はサーバーの起動中に行われるため、初期化時間が増加する可能性があります。
  - 明示的な設定を行うことで、検出処理をスキップし、起動パフォーマンスが向上します。
  - 静的な `Authorization` ヘッダー（例: Bearer APIキー）のみで保護されているサーバーの場合は、`requiresOAuth: false` を設定してください。自動検出機能は設定されたヘッダーを*使用せずに*サーバーをプローブするため、`WWW-Authenticate: Bearer` チャレンジを伴う `401` を返すサーバーが、誤ってOAuth保護されていると分類される可能性があります。このフラグはそのプローブをバイパスし、静的ヘッダーが通常通り接続を認証できるようにします。
  - 強化された接続管理のために、MCP OAuth環境変数 (`MCP_OAUTH_ON_AUTH_ERROR`, `MCP_OAUTH_DETECTION_TIMEOUT`, `MCP_OAUTH_HANDLING_TIMEOUT`, `MCP_OAUTH_FLOW_TTL`) と連携します。

#### OAuth リフレッシュの調整 [#oauth-refresh-coordination]

複数レプリカによるデプロイでは、`oauthRefreshCoordination: true` を設定すると、トークンの更新は共有 Redis インスタンスを介して直列化されます。`oauthRefreshWaitTimeout` は、レプリカが更新結果を待つ時間を制御し、`oauthPersistenceWaitTimeout` は、更新された認証情報が読み取り可能になるまで待つ時間を制御します。どちらのデフォルト値も `15000` ミリ秒です。`oauthRefreshWaitTimeout` の上限は `30000` に制限され、`oauthPersistenceWaitTimeout` に設定できる値は最大 `840000`(14 分)です。

すべてのレプリカがアップグレードされ、同じ Redis デプロイメントに接続された後にのみ、コーディネーションを有効にしてください。すべてのレプリカで同一の値を使用し、設定を変更する前にアクティブなリクエストをドレイン（排出）してください。また、ローリングデプロイメント中にこの設定を切り替えることは避けてください。

#### `stderr` [#stderr]

- **型:** 文字列または整数 (オプション、`stdio` 型のみ)
- **説明:** 子プロセスの `stderr` をどのように処理するかを指定します。これは Node.js の [`child_process.spawn`](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options) のセマンティクスと一致します。有効な文字列値は `"pipe"`、`"ignore"`、`"inherit"` です。あるいは、負ではない整数をファイル記述子として使用することもできます。
- **デフォルト値:** `"inherit"` (`stderr` へのメッセージは親プロセスの `stderr` に出力されます)。

#### `customUserVars` [#customuservars]

- **型:** Object (オプション)
- **説明:** このMCPサーバーに対してユーザーが設定できるカスタム変数を定義します。これにより、管理者は各ユーザーが個別に設定する必要がある変数（例: APIキー、URLなど）を指定できます。これらのユーザーが提供した値は、`headers` または `env` 設定で使用できます。`customUserVars` を持つサーバーは、アプリレベルの接続から自動的に除外されるため、ユーザーごとの認証情報が実行時に確実に解決されるようになります。
- **構造:**
  - `customUserVars` オブジェクトにはキーが含まれており、各キーは変数名（例: `MY_API_KEY`）を表します。この名前は `{{MY_API_KEY}}` のようなプレースホルダーで使用されます。
  - 各変数名は、以下のサブキーを持つオブジェクトです。
    - `title`: String (必須) - 設定UIに表示される、変数用のユーザーフレンドリーなタイトル。
    - `description`: String (必須) - 変数の説明または指示です。UI にも表示され、ユーザーへの案内として使われます。この項目では HTML を使用できます(例: リンクを作成する場合: `<a href="https://example.com" target="_blank">More info</a>`)。
    - `sensitive`: Boolean (オプション) - 値をシークレットとして扱い、UI上でマスクするかどうかを制御します。省略した場合はデフォルトでマスク/シークレットとして扱われます。プロジェクトIDやベースURLなどの非シークレットフィールドには `false` を設定してください。
- **`headers` および `env` での使用:**
  - `customUserVars` で定義された変数は、`{{VARIABLE_NAME}}` 構文を使用して、`headers`（`sse` および `streamable-http` タイプの場合）または `env`（`stdio` タイプの場合）セクションで参照できます。
  - ユーザーは、初めてサーバーに接続する際にこれらの値を入力します。その後、チャット入力欄の **Configure** または **MCP Settings** から変更できます。詳細は [Credentials and variables](/docs/features/mcp#credentials-and-variables) を参照してください。
  - これらのユーザー提供の値は、ユーザーごと・MCPサーバーごとに保存され、実行時に置換されます。
  - 起動時に変数が利用できない場合（例: GitHub の個人アクセストークン）、[`startup: false`](#startup) を設定することもできます。こうすると、ユーザーが接続するまで LibreChat は接続を試みません。
- **例:**
  ```yaml
  customUserVars:
    MY_SERVICE_API_KEY:
      title: 'My Service API Key'
      description: "Your personal API access key for My Service. Find it at <a href='https://myservice.example.com/settings/api' target='_blank'>My Service API Settings</a>."
      sensitive: true
    SOME_OTHER_VAR:
      title: 'Some Other Variable'
      description: 'The specific value for some other configuration (e.g., a specific path or identifier).'
      sensitive: false
  ```
  `headers` での使用:
  ```yaml
  headers:
    X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    X-Some-Other-Config: '{{SOME_OTHER_VAR}}'
  ```
  `env` での使用方法 (`stdio` タイプの場合):
  ```yaml
  env:
    API_KEY: '{{MY_SERVICE_API_KEY}}'
  ```

#### `obo` [#obo]

- **型:** Object (任意、`sse` および `streamable-http` 型でのみ使用)
- **説明:** MCPサーバーのOAuth 2.0 On-Behalf-Ofトークン交換を設定します。LibreChatは、ログイン中のユーザーのOpenIDアクセストークンを、設定されたスコープを持つ委任されたダウンストリームトークンと交換し、そのトークンを `Authorization: Bearer ...` ヘッダーとしてMCPサーバーに転送します。
- **必須のサブキー:**
  - `scopes`: String - ダウンストリームのトークン交換のために要求される、空ではないスコープ。
- **検証:**
  - `obo` は `sse` および `streamable-http` MCP サーバーに対してのみ有効です。
  - `obo` は `stdio` および `websocket` サーバーでは拒否されます。
  - ユーザーがこのフィールドを設定するには、`MCP_SERVERS.CONFIGURE_OBO` ロールの権限が必要です。[`interface.mcpServers.configureObo`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) を使用してシードするか、管理パネルから管理してください。
- **前提条件:**
  - OpenID認証は、再利用可能なアクセストークンを使用して構成する必要があります。
  - IDプロバイダーおよびダウンストリームアプリケーションは、要求された委任スコープを許可する必要があります。
- **例:**
  ```yaml
  mcpServers:
    enterprise-tools:
      type: streamable-http
      url: https://api.example.com/mcp/
      obo:
        scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
  ```

関連するトークンの再利用および委任トークンの設定については、[OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse) および [SharePoint Integration](/docs/configuration/sharepoint) を参照してください。

#### `oauth` [#oauth]

- **型:** Object (オプション)
- **説明:** MCPサーバーで認証を行うためのOAuth2設定です。設定を行うと、ユーザーはMCPサーバーを使用する前にOAuthフローを通じて認証を求められるようになります。クライアントIDとクライアントシークレットが提供されない場合は、動的クライアント登録（DCR）が使用されます。
- **Subkeys:** すべての `oauth` のサブキーは任意です。エンドポイントは自動検出され、クライアントは Dynamic Client Registration を通じて取得できます。
  - `authorization_url`: String - OAuth 認可エンドポイントの URL
  - `token_url`: String - OAuth トークン endpoint URL
  - `client_id`: String - OAuth クライアント識別子
  - `client_secret`: 文字列 - OAuth クライアントシークレット
  - `redirect_uri`: String - [OAuth リダイレクト URI](#oauth-callback-url)(例: `http://localhost:3080/api/mcp/${serverName}/oauth/callback`)
  - `scope`: String - OAuth スコープ（スペース区切り）
- **追加のサブキー:**
  - `grant_types_supported`: 文字列の配列 - サポートされている認可タイプ（デフォルトは `["authorization_code", "refresh_token"]`）
  - `token_endpoint_auth_methods_supported`: 文字列の配列 - サポートされているトークンエンドポイント認証メソッド（デフォルトは `["client_secret_basic", "client_secret_post"]`）
  - `token_exchange_method`: String - オプションのトークン交換オーバーライド。`default_post` を使用するとクライアント資格情報をフォームエンコードされた POST ボディで送信し、`basic_auth_header` を使用すると HTTP Basic 認証ヘッダーで送信します。省略した場合、LibreChat はプロバイダーがアドバタイズするトークンエンドポイントの認証メソッドを検出し、何もアドバタイズされていない場合はデフォルトで Basic 認証を使用します。
  - `response_types_supported`: 文字列の配列 - サポートされているレスポンスタイプ（デフォルトは `["code"]`）
  - `code_challenge_methods_supported`: 文字列の配列 - サポートされている PKCE コードチャレンジメソッド（デフォルトは `["S256", "plain"]`）
  - `skip_code_challenge_check`: Boolean - OAuthプロバイダーがPKCEサポートをアドバタイズしているかどうかのチェックをスキップします。S256をサポートしているものの、メタデータ内でそれをアドバタイズしないAWS Cognitoのようなプロバイダーで役立ちます。（デフォルトは `false`）
  - `revocation_endpoint`: String - トークン失効エンドポイントのURL。省略された場合は自動検出されます。
  - `revocation_endpoint_auth_methods_supported`: 文字列の配列 - 失効エンドポイントがサポートする認証方式。省略された場合は自動検出されます。
  - `audience`: 文字列 - 認可リクエストの `audience` パラメータとして送信されます。API スコープのトークンを、audience が指定された場合にのみ発行する Auth0 などのプロバイダー向けです。管理者専用で、ユーザーが UI で作成したサーバーでは拒否されます。
  - `forward_audience_on_refresh`: Boolean - `audience` を `refresh_token` グラントでも送信するかどうかを指定します。デフォルトは `true` で、これは Auth0 に必要な設定です。追加のパラメータを拒否する AWS Cognito などの厳格なトークンエンドポイントを持つプロバイダーでは、`false` に設定してください。`audience` が設定されていない場合は無視されます。管理者のみ設定可能です。
  - `send_resource_parameter`: Boolean - Whether the RFC 8707 `resource` parameter is sent on the authorization request, the code exchange, and the refresh grant. Defaults to `true`. Set to `false` for providers that reject it, such as Microsoft Entra ID v2.0, which fails with `AADSTS9010010` when `resource` and `scope` are both sent. Use `scope` or `audience` to obtain an API-scoped token instead. Admin-only.
- **環境変数:** `authorization_url`、`token_url`、`redirect_uri`、`revocation_endpoint` を含む YAML で定義された OAuth URL フィールドでは、`${ENV_VAR}` 参照を使用できます。LibreChat は URL の検証前に環境変数の値を解決します。UI を通じて送信されるユーザー管理の OAuth エンドポイント URL はリテラルの URL である必要があり、`${ENV_VAR}` プレースホルダーは拒否されます。
- **例:**

  ```yaml
  oauth-api-server:
    authorization_url: https://api.example.com/oauth/authorize
    token_url: https://api.example.com/oauth/token
    client_id: your_client_id
    client_secret: your_client_secret
    redirect_uri: http://localhost:3080/api/mcp/oauth-api-server/oauth/callback
    scope: 'read execute'
    grant_types_supported: ['authorization_code', 'refresh_token']
    token_endpoint_auth_methods_supported: ['client_secret_post']
    token_exchange_method: default_post
    response_types_supported: ['code']
    code_challenge_methods_supported: ['S256', 'plain']
  ```

  Auth0の例:

  ```yaml
  auth0-server:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      audience: https://api.example.com
      scope: 'read:data offline_access'
  ```

`token_exchange_method` と `token_endpoint_auth_methods_supported` の両方が事前設定されたクライアントシークレットに対して省略されている場合、LibreChat は保護リソースおよび認可サーバーのメタデータ検出に最大5秒間待機します。LibreChat は、検出されたトークンエンドポイントが設定済みの `token_url` と完全に一致する場合にのみ、アドバタイズされた機能を使用します。検出によって、設定済みのクライアント資格情報を別のエンドポイントにリダイレクトすることはできません。プロバイダーが使用可能なメタデータを公開していない場合や、強制的なメソッドが必要な場合は、`token_exchange_method` を明示的に設定してください。

サーバーサイドのOAuth検出、登録、トークン、および取り消しのHTTPリクエストは、元のURLが許可されている場合でも、リダイレクトに**従いません**。リダイレクトが発生する場合は、プロバイダーの最終的なendpointを直接設定してください。プライベートIPリテラルの宛先は、管理者の信頼されたホストまたは正確なアドレスとポートのポリシーによって明示的に許可されていない限り、ブロックされます。この制限はサーバーサイドのOAuth HTTPリクエストに適用されます。ユーザーのブラウザが通常の認証ページへのリダイレクトを完了することを妨げるものではありません。

#### `oauth_headers` [#oauth_headers]

- **型:** Object (オプション)
- **説明:** OAuthフローのリクエストに特化して使用されるヘッダーです。これらのヘッダーは、動的クライアント登録やトークン交換といったOAuth認証中に使用され、通常のMCPサーバー通信中には送信されません。
- **一般的なユースケース:**
  - `Authorization: Bearer ${DCR_API_KEY}` のような、動的クライアント登録エンドポイントへの認証の追加。
  - OAuthフローに必要なカスタムプロバイダー固有のヘッダーを含める
  - OAuthトークンエンドポイントで必要なヘッダーの設定
- **プレースホルダーのサポート:** 値には `{{LIBRECHAT_USER_*}}` プレースホルダーと `${ENV_VAR}` 参照を指定できます。`oauth` 配下の文字列フィールドも同様です。
- **`headers` との主な違い:**
  - **`headers`**: 認証完了後、通常のMCPサーバーリクエストと共に送信されます
  - **`oauth_headers`**: OAuth認証フロー中にのみ送信されます
- **例:**
  ```yaml
  oauth_headers:
    Authorization: "Bearer ${DCR_API_KEY}"
    X-Custom-Header: "custom_value"
  ```

#### `oauthPrompt` [#oauthprompt]

- **型:** 文字列 (オプション)
- **説明:** ユーザーに OAuth で保護されたサーバーへのサインインを求めるタイミングを制御します。
  - `on_start`: サインインプロンプトは、エージェントが実行される前に、会話のターンが開始されたときに表示されます。
  - `on_use`: ターンはプロンプトなしで開始され、エージェントはツール検索によってサーバーのツールを見つけます。エージェントがそのサーバーのツールを初めて呼び出したときにプロンプトが表示され、実行はユーザーがサインインするまで待機します。
- **デフォルト値:** `on_start`
- **注記:**
  - `on_use` は、エージェントがサーバーから選択したすべてのツールが[遅延読み込み](/docs/features/agents#deferred-tools)（「Defer」がオン）の場合にのみ適用されます。選択したツールのいずれかが最初から読み込まれる場合、またはエージェントが個別のツールではなくサーバー全体を選択している場合、プロンプトはターン開始時に留まります。
  - The [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) `deferred_tools` must be enabled. When the `run_in_background` capability is enabled, a selected tool that opts into background execution keeps the prompt at turn start, since a detached call cannot wait for a sign-in.
  - `on_use` には、宣言された [`oauthToolCatalog`](#oauthtoolcatalog) が必要です。これがない場合、ユーザーが以前に接続していても、サーバーはターン開始時のプロンプトを維持します。
  - ログイン前に提供されるツールには、選択されたすべてのツールが含まれていなければならず、そうでない場合はプロンプトはターン開始時点のままとなります。これは宣言されたカタログ、または以前の接続でユーザー自身のツールリストが残されている場合はそのリストです。
  - 運用者が設定したサーバーのみが対象となります。対象となるのは、`librechat.yaml` で定義されたサーバー、または[管理者設定の上書き](/docs/configuration/admin_panel#configuration-overrides)で追加されたサーバーです。UI上でユーザーが作成したサーバーは、ターン開始時のプロンプトが維持されます。接続設定に `obo`、`customUserVars`、`requestHeaders`、またはユーザーごと・リクエストごとのプレースホルダー(`{{LIBRECHAT_USER_*}}`、`{{LIBRECHAT_OPENID_*}}`、`{{LIBRECHAT_GRAPH_*}}`、`{{LIBRECHAT_BODY_*}}`)を使用するサーバーの場合も、ターン開始時のプロンプトは維持されます。
  - OAuth が事前に設定されている場合（`oauth`、`requiresOAuth: true`）でも、接続時にサーバーが拒否したことで検出された場合でも、この内容が適用されます。
  - UI で作成されたサーバーでは利用できません。
- **例:**
  ```yaml
  mcpServers:
    google-sheets:
      type: streamable-http
      url: https://sheets.example.com/mcp
      requiresOAuth: true
      oauthPrompt: on_use
      oauthToolCatalog:
        - name: read_sheet
          description: Read the values in a spreadsheet range
  ```

#### `oauthToolCatalog` [#oauthtoolcatalog]

- **型:** オブジェクトの配列 (任意)
- **説明:** `oauthPrompt: on_use` サーバーが、ユーザーのサインイン前にツール検索へ提供するツールです。LibreChat は、サインインしていないユーザーに対して保護されたサーバーのツールを一覧表示できないため、運用者がここでツールを宣言します。このカタログはすべてのユーザーに共通であり、いずれかのユーザーの接続状態が他のユーザーのエージェントに見えるものを決めることはありません。ユーザーがサインインすると、サーバー自身のツール定義が使用され、サーバーはすべての呼び出しを検証します。
- **入力フィールド:**
  - `name`: String (必須) - エージェントが選択する際に、サーバー上でのツールの名前です。
  - `description`: String (任意) - ツールの機能の説明です。ツール検索とモデルに表示されます。
  - `inputSchema`: Object(省略可能) - ツールのパラメータ。
    - `type`: `object` である必要があります
    - `properties`: パラメータ名からプロパティスキーマへのマップ
    - `required`: 必須パラメータ名の配列
- **プロパティスキーマ:** 以下のキーのみを持つ、JSON Schema の限定されたサブセットです:
  - `type`: `string`、`number`、`integer`、`boolean`、`object`、`array`、`null` のいずれか、またはこれらを含む空でないリスト
  - `description`: 文字列
  - `enum`: 文字列、数値、真偽値、または `null` からなる空でない配列
  - `default`: 文字列、数値、真偽値、または`null`
  - `items`: 配列の場合、`type`、`description`、`enum` を含むオブジェクト
- **注記:**
  - 検証は厳格です。スペルミスのあるエントリキー(例: `input_schema`)や、限定されたスキーマの範囲外にあるキーワード(例: `minLength`、`pattern`、`$ref`)は、無視されるのではなく、設定の検証に失敗します。
  - ツールリストが残っている以前の接続を持つユーザーには、代わりにそのリストが提示されます。いずれの場合も、エージェントがサーバーから選択したすべてのツールが含まれている必要があり、含まれていない場合はターン開始時のままプロンプトが維持されます。
  - UI で作成されたサーバーでは利用できません。
- **例:**
  ```yaml
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
  ```

#### `startup` [#startup]

- **型:** Boolean (オプション)
- **説明:** `false` に設定すると、この MCP サーバーはアプリケーション起動時に接続されません。これは、接続前にユーザーの入力や設定が必要なサーバーや、サーバーの初期化タイミングを制御したい場合に便利です。
- **デフォルト値:** `true`
- **例:**
  ```yaml
  mcpServers:
    my-mcp-server:
      type: streamable-http
      url: 'https://api.example.com/mcp/'
      startup: false
  ```

### 注記 [#notes]

- **型推論:**
  - `type` が省略された場合:
    - `url` が指定されており、かつ `http://` または `https://` で始まる場合、`type` はデフォルトで `sse` になります。
    - `url` が指定されており、かつ `ws://` または `wss://` で始まる場合、`type` はデフォルトで `websocket` になります。
    - `command` が指定されている場合、`type` はデフォルトで `stdio` になります。
- **接続タイプ:**
  - **`stdio`**: MCPサーバーを子プロセスとして起動し、標準入出力経由で通信します。
  - **`websocket`**: WebSocket経由で外部のMCPサーバーに接続します。
  - **`sse`**: Server-Sent Events (SSE) を介して外部の MCP サーバーに接続します。
  - **`streamable-http`**: ストリーミングレスポンスをサポートし、HTTP経由で外部のMCPサーバーに接続します。
  - `stdio` は LibreChat ホスト上で 1 つのプロセスを実行し、ローカルかつ単一ユーザーの構成に適しています。`sse` は古いリモート向けトランスポートです。複数ユーザーや本番環境でのデプロイには、`streamable-http` を使用してください。
- **内部/ローカルアドレス:**
  - **重要**: 内部IPアドレス（例: `172.24.1.165`、`192.168.1.100`）やローカルドメイン（例: `mcp-server`、`host.docker.internal`）を使用するMCPサーバーは、明示的に許可する**必要があります**。パブリックな宛先へのアクセスを維持しつつ特定のプライベートなホスト:ポートサービスを許可したい場合は [`mcpSettings.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#allowedaddresses) を使用し、厳格なホワイトリストを作成したい場合は [`mcpSettings.allowedDomains`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#alloweddomains) を使用してください。
  - 設定の詳細については、[MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) を参照してください。

## OAuth コールバック URL [#oauth-callback-url]

サーバーがOAuthを使用している場合、プロバイダーは次のURLにリダイレクトして LibreChat に戻ります:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>` は `mcpServers` の下にあるキーです。例えば、`DOMAIN_SERVER=https://chat.example.com` を設定した `salesforce` という名前のサーバーでは、`https://chat.example.com/api/mcp/salesforce/oauth/callback` を使用します。ローカルの Docker インストールでは、通常ベースとして `http://localhost:3080` を使用します。UI で作成されたサーバーの場合は、キーの代わりにサーバーが生成した識別子が使用され、サーバー作成後に LibreChat に完全な **Redirect URI** が表示されます。

このURLを OAuth プロバイダーに正確に登録してください。`/api/oauth/callback` や `/api/oauth/openid/callback` など、他の LibreChat のコールバックパスは MCP では動作しません。

もしプロバイダーが動的クライアント登録をサポートしている場合、サーバーに`oauth`ブロックは一切不要です。ユーザーが初めて接続するとき、LibreChatが自ら クライアントとして登録されます:

```yaml
mcpServers:
  # No refresh tokens: users sign in again when the token expires
  paypal:
    type: sse
    url: https://mcp.paypal.com/sse
    initTimeout: 150000
  # Issues refresh tokens: LibreChat renews access automatically
  spotify:
    type: streamable-http
    url: https://mcp-spotify-oauth-example.account.workers.dev/mcp
    initTimeout: 150000
```

ユーザーはサインインを完了するまでに10分の猶予があり、LibreChatは保留中のフローを15分間保持します。これらは `.env` 内の `MCP_OAUTH_HANDLING_TIMEOUT` と `MCP_OAUTH_FLOW_TTL` で変更できます([MCP環境変数](/docs/configuration/dotenv#mcp-model-context-protocol)を参照)。フローのTTLは常に処理タイムアウトより少なくとも1分長く保たれるため、期限直前に届いたコールバックでも対応するフローを見つけることができます。

## UIで作成されたサーバー [#servers-created-in-the-ui]

ロールに `CREATE` 権限を持つユーザー(詳細は[`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)を参照)は、この設定ファイルを編集することなく、**MCP Settings**からサーバーを追加できます。これらのサーバーはデータベースに保存され、YAMLで定義されたサーバーとは次のいくつかの点で異なります。

- リモートトランスポート（`streamable-http` および `sse`）のみが利用可能です。`stdio` サーバーはここで定義する必要があります。
- `${ENV_VAR}`、`{{LIBRECHAT_USER_*}}`、`{{LIBRECHAT_OPENID_*}}`、`{{LIBRECHAT_GRAPH_*}}`、`{{LIBRECHAT_BODY_*}}` のプレースホルダーは、サーバーが他のユーザーと共有される可能性があるため、ヘッダーから削除されます。`customUserVars` のプレースホルダーのみが保持されます。
- OAuth のエンドポイント URL は、リテラルな URL で指定する必要があります。`${ENV_VAR}` 形式の参照は拒否されます。
- ユーザーごとに提供する API キーを選択すると、`customUserVars` に `MCP_API_KEY_<hash>` という名前のエントリと、対応するヘッダーが作成されます。この変更より前に保存されたサーバーは、URL または認証設定が変更されるまで、従来の `MCP_API_KEY` という名前のままになる場合があります。どの編集でユーザーが再度キーを入力する必要があるかについては、[`apiKey`](#apikey) を参照してください。
- APIキー（共有またはユーザーごと）を持つサーバーは、APIキー認証として扱われ、OAuthの自動検出はスキップされます。ただし、OAuth設定も含まれている場合はこの限りではありません。古いバージョンで保存されたAPIキーサーバーが**Needs Auth**のままになっている場合は、一度編集して保存し、保存済みのメタデータを更新してください。
- 保存された OAuth クライアントとトークンは、サーバー URL および OAuth クライアントとエンドポイントの設定に紐付けられています。これらを変更すると、ユーザーは再度サインインする必要があります。また、サーバー URL、クライアント ID、認可 URL、トークン URL、またはトークン交換方式を変更する場合、編集者は保存済みのクライアントシークレットを再入力する必要があります。
- `oauthPrompt` と `oauthToolCatalog` は利用できません。
- [`mcpSettings`](/docs/configuration/librechat_yaml/object_structure/mcp_settings) のドメインおよびアドレスの制限が適用されます。
- 新規作成および編集されたサーバーは、再起動なしで有効になります。OAuth サーバーは、ユーザーがサインインするまで未接続の状態で保存されます。

完全なプレースホルダーのセットを使用するには、`librechat.yaml`でサーバーを定義してください。

## サーバーの検索 [#finding-servers]

[Smithery](https://smithery.ai) では、公開されている MCP サーバーの一覧を確認できます。各サーバーのページにある **Connect** セクションでは、`librechat.yaml` にエントリを書き込む LibreChat クライアント用のインストールコマンドを生成できます。その後、LibreChat を再起動してください。特定のサーバーのセットアップ方法については、[MCP Servers ガイド](/docs/mcp_servers)をご覧ください。

## 例 [#examples]

### 内部アドレスを使用した設定 [#configuration-with-internal-addresses]

内部/ローカルのMCPサーバーを使用しており、厳格なドメインホワイトリストが不要な場合は、`mcpSettings.allowedAddresses` に正確なホストとポートを設定してください：

```yaml filename="Complete MCP Configuration with Internal Servers"
# MCP Settings - Required for internal/local addresses
mcpSettings:
  allowedAddresses:
    - '172.24.1.165:8000' # Internal IP and port
    - 'mcp-prod:8001' # Docker container and port
    - 'host.docker.internal:8080' # Docker host and port

# MCP Servers - Individual configurations
mcpServers:
  prod-mcp:
    type: streamable-http
    url: http://172.24.1.165:8000/mcp
    timeout: 120000

  test-mcp:
    type: streamable-http
    url: http://mcp-prod:8001/mcp
    timeout: 120000
```

### `stdio` MCP Server [#stdio-mcp-server]

```yaml filename="stdio MCP Server"
puppeteer:
  type: stdio
  command: npx
  args:
```

**MCPサーバー設定のインポート**

`mcpServers` 設定により、LibreChat はさまざまな MCP サーバーと動的に対話できるようになります。これにより、アプリケーション内で専門的なタスクを実行したり、特定の機能を提供したりすることが可能になります。このモジュール式のアプローチにより、サーバー設定を追加または変更するだけで、アプリケーションの機能を簡単に拡張できます。

## 追加情報 [#additional-information]

- **デフォルトの動作:**
  - `librechat.yaml` 内のサーバーは起動時に初期化されるため、このファイルを変更した場合は再起動が必要です。UI で作成したサーバーは再起動の必要はありません。
  - `notifications/tools/list_changed` を送信するサーバーは、実行中にツールを追加または削除できます。LibreChat は、再起動することなく、稼働中の接続からツールリストを再取得します。
  - ユーザーがツール呼び出し中に **Stop** を押すと、LibreChat は MCP リクエストをキャンセルします。Streamable HTTP サーバーは `notifications/cancelled` を受け取り、自身の処理を停止するためにこれを尊重する必要があります。バックグラウンドで実行されているツール呼び出しはキャンセルされません。
  - `url` と `command` の両方が指定されている場合、曖昧さを避けるために `type` を明示的に定義する必要があります。
- **マルチユーザーサポート:**
  - MCPManagerは、ユーザーレベルおよびアプリレベルの個別の接続をサポートするようになり、ユーザーごとに適切な接続管理が可能になりました。
  - ユーザー接続は個別に追跡および管理され、適切な確立とクリーンアップが行われます。
  - Redisが有効な場合、OAuthフローの状態とMCPツールカタログは、Redis Clusterデプロイメントを含め、レプリカ間で共有されます。レプリカ間でのトークン更新については、[OAuth refresh coordination](#oauth-refresh-coordination)を参照してください。
  - ヘッダー、URL、および環境変数で動的なユーザーフィールドプレースホルダーを使用します：
    - `{{LIBRECHAT_USER_ID}}` - ユーザーの一意の識別子
    - `{{LIBRECHAT_USER_EMAIL}}` - ユーザーのメールアドレス
    - `{{LIBRECHAT_USER_USERNAME}}` - ユーザーのユーザー名
    - `{{LIBRECHAT_USER_ROLE}}` - ユーザーのロール（例: "user", "admin"）
    - その他多数のフィールド（完全なリストについてはヘッダーのセクションを参照してください）
- **ユーザーアイドル管理:**
  - ユーザー接続はアクティビティが監視されており、15分間非アクティブな状態が続くと切断されます。この時間は `MCP_USER_CONNECTION_IDLE_TIMEOUT`（ミリ秒）で変更できます。
- **環境変数:**
  - **`env` 内（`stdio` タイプの場合）:** MCP サーバープロセスに必要な特定のランタイム環境や設定を構築する際に役立ちます。
  - **`headers` 内（`sse` および `streamable-http` タイプの場合）:** `${ENV_VAR}` 構文を使用して、ヘッダー値内の環境変数を参照します。
- **動的ユーザーフィールド:**
  - ユーザーフィールドのプレースホルダーは、実行時に認証されたユーザーの情報に置き換えられます。
  - 機密性の低いフィールドのみが利用可能です（パスワードやその他の機密データは除外されます）
  - 欠落しているフィールドは空文字列にデフォルト設定されます
  - Boolean フィールドは文字列形式 ("true" または "false") に変換されます。
- **エラーハンドリング (`stderr`):**
  - `stderr` を設定することで、MCP サーバープロセスからのエラーメッセージの処理方法を管理できます。デフォルトの `"inherit"` は、エラーが親プロセスの `stderr` に出力されることを意味します。
- **サーバー指示:**
  - MCPサーバーのツールが使用される際、指示は自動的にエージェントのシステムメッセージに注入されます。
  - カスタム指示（文字列値）は、サーバーから提供される指示よりも優先されます。
  - 複数のMCPサーバーが、それぞれ独自の指示をエージェントのコンテキストに追加できます。
  - Instructionsは、対応するMCPサーバーのツールが実際にエージェントに対して利用可能な場合にのみ含まれます。
- **OAuth 認証:**
  - MCPサーバーとの安全な認証のために、OAuth2フローがサポートされています。
  - MCPサーバーを使用する前に、ユーザーはOAuth経由で認証を行うよう求められます。
