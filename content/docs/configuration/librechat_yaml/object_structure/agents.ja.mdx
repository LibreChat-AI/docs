    # capabilities: ["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]
    # (optional) File citation configuration for file_search capability

      maxCatalogSkills: 20

      environments:
        - id: managed-default
          name: Managed Code API

          default: true
        - id: engineering-vm

            allowPrincipalWorkers: true

    # eventDriven:
    #   selfUrl: https://librechat.internal
    backgroundTasks:
      completionWakeups: true

    toolApproval:

      auth:
        oidc:

## maxProviderErrorChars

エージェントの障害が分類できない場合に、LibreChatが保持するプロバイダーのエラーテキストの量を制御します。デフォルトは `2000` 文字です。プロバイダーのテキストを省略するには `0` に設定してください。最大値は `1000000` です。

```yaml filename="endpoints / agents / maxProviderErrorChars"
maxProviderErrorChars: 2000
```

## repositoryInstructions

添付された Code 環境のリポジトリ命令の検出を制御します。`timeoutMs` は命令読み込みリクエストの制限時間を `100` から `30000` ミリ秒の間で設定し、デフォルト値は `2000` です。

```yaml filename="endpoints / agents / repositoryInstructions"
repositoryInstructions:
  timeoutMs: 2000
```

## ストリームサーキットブレーカー [#stream-circuit-breakers]

これらの設定は、プロバイダーのストリームが暴走したツール引数や制限のないデルタイベントのシーケンスを生成していると思われる場合に、Agentの実行を停止します。

<OptionTable
  options={[
    [
      'maxToolCallArgBytes',
      'Number',
      '1回のストリーミングツール呼び出しの引数に対する累積バイト数の上限。0に設定するとグローバルガードが無効になります。',
      '65536',
    ],
    [
      'maxDeltaEventsPerTurn',
      'Number',
      '1回のモデル生成ターンにおける最大ストリーミングイベント数。0に設定するか省略すると、このガードは無効になります。',
      '0 (disabled)',
    ],
    [
      'maxToolCallArgBytesByTool',
      'Object',
      'モデル向けのツール名でキー指定された、ツールごとの引数バイト数のオーバーライド。値を0にすると、そのツールのガードが無効になります。',
      'create_file: 131072',
    ],
  ]}
/>

LibreChatは64 KiBのグローバル引数制限を使用しており、正当なペイロードがこれより大きくなることが多い`create_file`に対しては128 KiBのオーバーライドを提供しています。`maxToolCallArgBytesByTool`内のエントリは、その組み込みオーバーライドにマージされます。いずれかのガードが作動した場合、LibreChatは実行中のプロバイダストリームを中断し、どの制限を超過したかを報告します。

```yaml filename="endpoints / agents / stream circuit breakers"
maxToolCallArgBytes: 65536
maxDeltaEventsPerTurn: 100000
maxToolCallArgBytesByTool:
  create_file: 262144
  large_import: 524288
```

すべての引数サイズのガードを無効にするには、グローバル制限と同梱されている `create_file` オーバーライドの両方を `0` に設定します。

```yaml
maxToolCallArgBytes: 0
maxToolCallArgBytesByTool:
  create_file: 0
```

## titleTiming

<OptionTable
  options={[
    [
      'titleTiming',
      'String',
      'agents endpointの会話タイトルが生成されるタイミングを制御します。有効な値: "immediate" または "final"。',
      'Defaults to "immediate".',
    ],
  ]}
/>

**デフォルト:** `"immediate"`

**利用可能な値:**

- **`"immediate"`**: リクエストが開始されると同時に、ユーザーの最初のメッセージを使用して、モデルの応答と並行してタイトルを生成します。
- **`"final"`**: タイトルの生成を完全な応答が完了するまで延期します。これは従来の動作を維持します。

**例:**

```yaml filename="endpoints / agents / titleTiming"
titleTiming: immediate
```

## activityLabel

`activityLabel: true` を設定すると、エージェントの推論とツール呼び出しの各ブロックが、生成された1行のヘッダーの下にグループ化されます。追加のモデル呼び出しとそのコストを制御するには、`activityModel`、`activityEndpoint`、`activityPrompt`、`activityMaxPerRun`、および `activityCharLimit` を使用します。フィールドの完全なリファレンスと優先順位のルールについては、[Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups) を参照してください。

```yaml filename="endpoints / agents / activity groups"
activityLabel: true
activityEndpoint: openAI
activityModel: gpt-4.1-nano
activityMaxPerRun: 20
activityCharLimit: 600
activityPhaseLabel: true
activityPhaseMaxPerRun: 5
```

`activityPhaseLabel` は、少なくとも2つの論理的なアクティビティを含む各実行フェーズの周囲に、折りたたみ可能な親サマリーを個別に付加できます。これらの呼び出しを調整するには `activityPhaseModel`、`activityPhaseEndpoint`、`activityPhasePrompt`、および `activityPhaseMaxPerRun` を使用してください。`activityCharLimit` は子アクティビティラベルと共有されます。

## capabilities

<OptionTable
  options={[
    [
      'capabilities',
      'Array/List of Strings',
      'agents endpointのすべてのユーザーが利用可能なエージェント機能を指定します。',
      'Defines the agent capabilities that are available to all users for the agents endpoint. You can omit the capabilities you wish to exclude from the list.',
    ],
  ]}
/>

**デフォルト:** `["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]`

`programmatic_tools`、`stateful_code_sessions`、`run_in_background`、および `tool_intents` はオプトイン形式であり、明示的に追加する必要があります。Programmatic tools および stateful sessions を使用するには、`execute_code` と互換性のある Code Interpreter のデプロイメントも必要です。Agent Builder は Code Interpreter がない場合、Programmatic MCP の選択を無効にし、サーバーはコード実行が利用できない場合に古い programmatic caller オプションを削除します。`run_in_background` は Code Interpreter ツールをデフォルトで有効にし、対象となる MCP、Plugin、および Action ツールに対してツールごとのオプトインを可能にします。バックグラウンドでのコード実行にも `execute_code` と Code Interpreter が必要です。

`stateful_code_sessions` は非常に実験的な機能です。これには、[`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) または [`statefulCodeSessions.environments`](#statefulcodesessions) で設定された、個別の `stateful` プロファイルの Code Interpreter ルートが必要です。ステートフルなリクエストは、通常のステートレスなサービスにフォールバックすることなく、失敗した場合は閉じた状態（fail closed）になります。Agent Builder では、有効化された各エージェントがユーザー、エージェントとユーザー、または会話のワークスペーススコープを選択し、名前付きバックエンドが設定されている場合は実行環境を選択します。新しいエージェントは、ユーザーの個人スコープのデフォルト値と、デプロイメントのデフォルト実行環境で開始されます。

**例:**

```yaml filename="endpoints / agents / capabilities"
capabilities:
  - 'deferred_tools'
  # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
  # Requires execute_code and a Code Interpreter deployment with the Tool Call Server component.
  # - 'programmatic_tools'
  - 'execute_code'
  - 'file_search'
  - 'web_search'
  - 'artifacts'
  - 'subagents'
  - 'actions'
  - 'context'
  - 'skills'
  - 'memory'
  - 'ask_user_question'
  - 'tools'
  - 'chain'
  - 'ocr'
  # Optional and highly experimental: reuse a user-, agent-and-user-, or
  # conversation-scoped workspace. Requires LIBRECHAT_CODE_BASEURL_STATEFUL
  # or a named statefulCodeSessions environment.
  # - 'stateful_code_sessions'
  # Optional: allow eligible Code Interpreter, MCP, Plugin, and Action tools to run as background tasks.
  # - 'run_in_background'
  # Optional: show live model-written intent labels for native and selected MCP tools.
  # - 'tool_intents'
```

**注:** このフィールドは任意です。省略した場合、デフォルトの動作として、デフォルトでリストされているすべての機能が含まれます。

## statefulCodeSessions

非常に実験的なステートフルな Code Interpreter ワークスペースの共有スコープとオプションの実行バックエンドを設定します。

<Callout type="warning" title="非常に実験的">
  Stateful Code Sessions、名前付き実行環境、アタッチされたワーカー、およびペアリングは、初期の実験段階にあります。それらの動作、構成、永続性の特性、および統合プロトコルは、大幅に変更される可能性があります。
</Callout>

<OptionTable
  options={[
    [
      'allowedEnvironments',
      'Array/List of Strings',
      '許可されたステートフルワークスペーススコープ: `user`、`agent-user`、および/または `conversation`。',
      '["user", "agent-user", "会話"]',
    ],
    [
      'environments',
      'Array of Objects',
      'Agent Builderに表示される、オプションの名前付き管理型またはアタッチ済みのCode API環境。',
      'Unset; LIBRECHAT_CODE_BASEURL_STATEFUL remains the stateful endpoint',
    ],
    [
      'principalWorkers',
      'Object',
      '個人ワーカー登録のオプションのデプロイ上限。`enabled` はデフォルトで true、`maxPerUser` はデフォルトで 5 に設定されます。',
      '{ enabled: true, maxPerUser: 5 }',
    ],
    [
      'conversationMoves',
      'Object',
      '保存された会話のワークスペース移行をオーナーが許可するオプトイン設定です。`allowAttachDetach` は、ワークスペースへの参加や離脱も追加で許可します。',
      'Disabled',
    ],
  ]}
/>

Attached environments は `environments[].configSchema.limits.maxQueueWaitMs` を受け付けます。これは、リクエストがワークスペースの容量を待機して再試行できる時間を制御します。デフォルト値および最大値は `300000` ミリ秒（5分）です。`0` に設定すると、最初の承認試行後のクライアントによる再試行が無効になります。ただし、すでに承認済みまたは実行中の作業はキャンセルされません。これらのフィールドは `userConfig.bash` ではなく、`configSchema.limits` の下に配置する必要があります。

`environments[].configSchema.limits.maxRequestTimeoutMs` は、**1つのワークスペースツール呼び出しにかかるHTTP合計時間**（受付、実行、決済、配信を含む）を任意で制限します。`1` から `610000` ms の範囲で指定可能ですが、受付後のコマンド実行時間と10秒間の決済/配信の予備時間を確保できないほど小さい予算値は、設定によって拒否されます。この設定がない場合、受付には試行ごとに30秒の予算が割り当てられます。`maxQueueWaitMs` は引き続き個別のリトライ期間として扱われます。すべての LibreChat API レプリカがこのフィールドを認識し、Code API ルートがリクエストごとのキュー許容量を尊重し、ライブプロキシ/イングレスパス全体で最短のタイムアウトが測定されるまで、**受付時間を長く設定しないでください**。期限切れのミューテーションがワーカー上で完了している可能性があるため、LibreChat は曖昧なタイムアウトに対してリトライを行いません。

合計リクエスト予算において、`environments[].configSchema.limits.minCommandAdmissionMs` は、コマンドが実行を開始する前にワーカーに入るための時間を確保します。デフォルトは `10000` ms です。`1000` ～ `300000` ms の間で設定してください。リクエスト予算は、この許容時間に 10000 ms の決済/配信猶予時間を加えた値を超えている必要があります。合計予算がない場合、この設定は無効です。エージェントに通知される Bash 実行制限は、設定された上限またはアップストリームの上限のいずれか小さい方から、これらの確保時間を差し引いた残り時間となります。例えば、90000 ms のリクエスト予算、80000 ms のコマンド上限、およびデフォルトの確保時間の場合、通知されるコマンド制限は最大で 70000 ms となります。

```yaml filename="endpoints / agents / statefulCodeSessions"
statefulCodeSessions:
  allowedEnvironments:
    - 'user'
    - 'agent-user'
    - 'conversation'
  principalWorkers:
    enabled: true
    maxPerUser: 5
  environments:
    - id: managed-default
      name: Managed Code API
      type: managed
      baseURL: https://code.example.com/v1
      default: true
    - id: engineering-vm
      name: Engineering VM
      type: attached
      baseURL: https://code-bridge.example.com/v1
      owner: deployment
      pairing:
        workerId: engineering-vm
        tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
    - id: personal-workers
      name: Personal Code Workers
      type: attached
      baseURL: https://code-bridge.example.com/v1
      owner: deployment
      configSchema:
        limits:
          maxCommandTimeoutMs: 120000
          # Before enabling, verify Code API queue allowances and the live proxy deadline.
          # maxRequestTimeoutMs: 160000
          # minCommandAdmissionMs: 10000
          # maxQueueWaitMs: 300000
        # After upgrading Code API and opting in the worker with --linked-worktree-lanes:
        # workspaces:
        #   linkedWorktrees: true
        # Optional: require exact matching even on workers supporting tolerant edits.
        # edits:
        #   tolerantMatching: false
        permissions:
          fileWrite:
            allowed: [allow, ask, deny]
            default: ask
          commandExecution:
            allowed: [ask, deny]
            default: ask
      pairing:
        allowPrincipalWorkers: true
        tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
```

`allowedEnvironments` は、ブロックが存在する場合は必須であり、少なくとも1つのワークスペーススコープを含める必要があります。ブロック全体を省略すると、3つすべてのスコープが許可され、ステートフルな作業は引き続き [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) を通じてルーティングされます。個人のデフォルト設定およびAgent Builderでは、許可された値のみが使用可能です。管理者がポリシーを厳格化した場合、保存済みの個人のデフォルト設定は表示されたままとなりますが無効化され、新しいAgentは許可された最初のスコープを使用します。既存の有効なAgentは保存されたスコープを保持しますが、許可されなくなったスコープは実行時に失敗（フェイルクローズ）するため、Agentの再設定が必要となります。

`conversationMoves.enabled: true` を設定すると、会話の所有者は、シールされた添付ワークスペースを互換性のある環境へ明示的に移動したり、チャット履歴を置き換えたり古いワークスペースファイルを復元したりすることなく、欠落したワークスペースを回復したりできるようになります。保存されたチャットに対して、ワークスペースの**添付**や、通常のチャットへの**離脱**を許可するには、`conversationMoves.allowAttachDetach: true` を設定します。両方のスイッチはデフォルトでオフになっています。移動のみを有効にすると、移動専用の動作が維持されます。**すべて**の API レプリカをアップグレードしてから、[`CODE_ENVIRONMENT_DECISION_VERSION=1`](/docs/configuration/dotenv#code-interpreter) を有効にしてオプトインしてください。所有権、ターゲットへのアクセス権、アクティブな作業、および現在のポリシーは移行時に再チェックされます。生成中のプロセスを移動することはできません。

```yaml filename="endpoints / agents / statefulCodeSessions / conversationMoves"
statefulCodeSessions:
  allowedEnvironments: ['user', 'agent-user', 'conversation']
  conversationMoves:
    enabled: true
    allowAttachDetach: true
```

`principalWorkers` は、個人用アタッチ済みワーカーのセルフサービス登録を制御します。値を省略した場合、`enabled: true` および `maxPerUser: 5` として解決されます。新しい登録を停止するには、`enabled: false` または `maxPerUser: 0` に設定してください。この制限は、オフラインのワーカーを含め、構成されたすべてのコントロールプレーン全体で、そのユーザーに対して登録されたすべての個人用環境をカウントします。制限を引き下げたり登録を無効にしたりしても、既存の環境は取り消されません。

Deployment YAMLは上限を決定する絶対的な基準です。ロール、グループ、またはユーザー設定のオーバーライドによって登録を無効化したり`maxPerUser`を引き下げたりすることは可能ですが、Deployment YAMLで設定された値を引き上げることはできません。ユーザーがペアリング有効なコントロールプレーンを確認できるのは、有効な制限が0より大きく、そのコントロールプレーンで[`pairing.allowPrincipalWorkers`](#statefulcodesessions)が有効であり、プリンシパル認証が利用可能で、かつユーザーがCode Environmentの管理権限を持っている場合のみです。

`environments` が空でない場合、すべてのエントリには一意の `id`、表示用の `name`、`managed` または `attached` のいずれかの `type`、およびクエリ文字列やフラグメントを含まない HTTP(S) の `baseURL` が必要です。リストに実行環境が含まれている場合、それらのエントリのうち正確に1つを `default: true` に設定する必要があります。Agent Builder はその後 **Execution environment** セレクターを追加します。これを **Deployment default** のままにすると、そのデフォルトエントリが使用されます。セルフサービスペアリングのコントロールプレーンのみを含むリストには、デフォルトは不要です。環境を指定しているエージェントが、後に削除されたりアクセスできなくなったりした場合、別のバックエンドにフォールバックすることなく、安全に失敗（fails closed）します。

- `managed` は、オペレーターが管理するステートフルな Code API を直接指し示します。
- `attached` は、互換性のある Code API `remote-bridge` バックエンドを指し示しており、これがアウトバウンドの `@librechat/code` ワーカーにタスクをリースします。ワーカーはインバウンドのパブリックポートを必要としませんが、そのローカル実行エンドポイントには依然として適切な分離（isolation）が必要です。
- `workerId` は、接続された環境を1つのアウトバウンドワーカーにオプションでルーティングします。これはサーバー専用であり、クライアントの起動設定を通じて公開されることはありません。
- `owner` のデフォルト値は `deployment` です。プリンシパルが所有する環境は、LibreChat の認証済み Code Environments API を通じて作成され、ACL によって保護されており、承認されたリクエストに対してのみマージされます。クライアントから提供された URL を deployment YAML に配置しないでください。
- `pairing` はオプションであり、デプロイメント所有の `attached` エントリに対してのみ有効です。`pairing.workerId` は登録するオペレーター管理のワーカーを識別し、`pairing.allowPrincipalWorkers: true` は権限を持つユーザーが所有者バインドされたワーカーをそのコントロールプレーンに対して登録できるようにします。`pairing` が存在する場合、これらのフィールドのうち少なくとも1つが必須となります。
- `pairing.tokenEnv` は、ブリッジ管理者トークンを含む環境変数の名前を指定します。これ自体にトークンが含まれることはありません。ペアリングには、ループバック開発を除き、HTTPSが必要です。
- `configSchema.permissions` は、権限を持つオーナーが **Settings > Code environments** で個人環境向けの `fileWrite` および `commandExecution` ポリシーを任意で選択できるようにします。各フィールドには、`allow`、`ask`、および `deny` を含む空ではない `allowed` リストが必要です。`default` は省略された場合は `ask` となり、`allowed` 内に含まれている必要があります。LibreChat は、管理者が設定したリスト外の保存された値を拒否します。
- `configSchema.limits.maxCommandTimeoutMs` は、その環境に対してモデルが要求できる最大のBashタイムアウトを設定します。`1` から `300000` ms の値を受け付けます。省略した場合は、デフォルトの30秒が維持されます。合計リクエスト予算がある場合、通知されるコマンドタイムアウトは、コマンドの承認、確定、配信後の残り時間にも適合します。これはデプロイメント上の上限であり、ユーザーが設定することはできません。
- `configSchema.workspaces.linkedWorktrees: true` は、`git_linked_worktree` をアドバタイズする接続済みワークスペースに対してのみ、ワークツリーごとのスケジューリングを有効にします。省略した場合、すべてのリクエストはチェックアウトのルートレーンに保持されます。ワーカーがこのスコープをアドバタイズする**前**に LibreChat をアップグレードし、リンクされたワークツリーレーンをサポートする Code API をデプロイしてから、YAML 設定を有効にする前に `--linked-worktree-lanes` を指定してワーカーを起動してください。`.worktrees/<name>` 内のパスを対象とするファイル操作や、そこで `cwd` を指定した Bash コマンドは、そのレーンを使用し、チェックアウト相対パスを返します。コマンドテキスト内で `cd` を実行するコマンド、チェックアウトルート操作、会話ワークスペースインスタンス、および環境アクションは、ルートスコープのままとなります。
- `configSchema.edits.tolerantMatching` は、`tolerant_match` をアドバタイズする接続済みワーカーにおいて、デフォルトで空白文字を許容するフォールバックを許可します。これを `false` に設定すると、保護された編集プレビューを含め、完全一致が必須となります。編集で明示的に `replace_all` が設定されていない限り、マッチングは一意である必要があります。古いワーカーは新しいマッチングフィールドを受け取りません。また、ワーカーが `replace_all` をアドバタイズしていない場合、ディスパッチ前にその要求は拒否されます。これらの機能には、[Code Interpreter #271](https://github.com/LibreChat-AI/code-interpreter/pull/271) を実装した互換性のある Code API およびワーカービルドが必要です。
- デプロイメントのYAMLで `settings` を設定しないでください。LibreChatは、認証された所有者のサーバーで検証済みの設定から、そのリクエストスコープのフィールドを提供します。
- ユーザーが設定可能なのは、ファイル書き込みおよびコマンド実行ポリシーのみです。分離、ネットワーク、マウント、特権実行、イングレス、エグレス、およびシークレットは、引き続き管理者が制御します。
- トップレベルの `workerId` と `pairing.workerId` の両方が存在する場合、それらは一致している必要があります。`allowPrincipalWorkers: true` が設定されており、どちらの worker ID もペアリング専用ではないエントリは、実行セレクターから除外され、`default: true` を設定することはできません。

Attached executionは、安全な承認ベースラインを自動的に有効にします。ファイル書き込みやコマンド・コード実行には確認が求められますが、読み取り専用操作や検索操作は通常のツールポリシーの下で継続されます。このベースラインは、Attached environmentを使用するAgentにスコープされます。ユーザー設定がない場合、LibreChatは `ask` を使用します。[`toolApproval.enabled: false`](#toolapproval) は、このAttached environmentのベースラインを無効にする管理者の緊急オーバーライドです。その明示的なオーバーライドが設定されていない限り、承認および再開（resume）をサポートしない呼び出し元は、安全側に倒して（fail closed）失敗します。

Attached executionには、対応する実験的なCode Interpreterのremote-bridgeビルドが必要です。ペアリングはアウトバウンドのワーカー接続を認証するものであり、サンドボックスやVMの分離を置き換えるものではありません。Code Environment管理権限を持つユーザーは、**Settings > Code environments**からペアリング、許可されたツールポリシーの設定、および個人用ワーカーの取り消しを行うことができます。詳細は[Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions)を参照してください。

`eventDriven.idlePolling` は、準備が整っていない場合のレプリカごとのリカバリポーリングに上限を設けます。`deliveryMaxIntervalMs` のデフォルトは `15000`（有効範囲 `1000`–`300000`）、`queuedTurnMaxIntervalMs` および `maintenanceMaxIntervalMs` はそれぞれデフォルトで `120000`（有効範囲 `30000`–`300000`）、そして `completionWaitMaxIntervalMs` のデフォルトは `60000`（有効範囲 `5000`–`300000`）です。後者は、バックグラウンド処理やサブエージェントの結果が保留中であるか、その親ターンがビジー状態である間の再チェックを制限します。準備完了イベントは配信を迅速化しますが、これらの上限は通常の完了レイテンシを定義するものではなく、レプリカ間およびクラッシュリカバリのフォールバックを維持するためのものです。

```yaml filename="endpoints / agents / eventDriven / idlePolling"
eventDriven:
  idlePolling:
    deliveryMaxIntervalMs: 15000
    queuedTurnMaxIntervalMs: 120000
    maintenanceMaxIntervalMs: 120000
    completionWaitMaxIntervalMs: 60000
```

Event Actor detached Action completion は、組み込みの生成ストアから自動的に選択されます。インメモリ実行はプロセスローカルですが、Redis 生成ストリームを追加することで、永続的な再起動リカバリとレプリカへのハンドオフが可能になります。`librechat.yaml` のスイッチや環境変数の機能フラグは必要ありません。[Agent Event Runtime](/docs/configuration/dotenv#agent-event-runtime) を参照してください。

このブロックを省略した場合でも、自動補完配信は有効になります。エージェントが `check_background_task` を通じてすべての結果を収集するようにするには、`completionWakeups: false` を設定してください。

`ordinaryToolCancellation: true` を設定すると、通常のバックグラウンドツールに対してオーナー権限によるキャンセルを公開できます。キャンセルは協調的であり、プロセスローカルに留まり、呼び出しが完了するまでタスクをアクティブに保ち、容量を確保します。これは、切り離された（detached）Subagents をキャンセルするものではありません。

通常のバックグラウンドツール実行は、プロセスローカルのままです。正常なシャットダウンの間、LibreChatはシャットダウンの猶予期間内にタスクが完了するのを待ち、その後未完了の作業を中断して結果を記録します。突然のワーカーの喪失では、実行中のタスクを保持することはできません。コンテンツのみのターミナル結果が永続化されると、その配信は永続的となり、別のレプリカで継続される可能性があります。ライブアーティファクトを持つタスクは、引き続き所有する実行環境でのポーリングを必要とします。デタッチされたSubagentsは、個別の永続的なトランスクリプトとターミナル結果のパスを保持します。ステータス、制御、および復旧のための手動ポーリングは、どちらのモードでも引き続き利用可能です。[Background Tool Calls](/docs/features/agents#background-tool-calls) および [Automatic Parent Continuation](/docs/features/subagents#automatic-parent-continuation) を参照してください。

## toolApproval

エージェントのツール呼び出しに対する人間によるレビューを制御します。このブロックが省略された場合、デプロイメント全体のポリシーは無効になります。アタッチされたCode環境を使用するエージェントは例外であり、管理者が明示的に `enabled: false` を設定しない限り、LibreChatはスコープ付きのデフォルトで確認を求める安全ポリシーを有効にします。レビューが適用される場合、一致する呼び出しは、ユーザーが承認、拒否、または引数の編集といった許可の決定を送信するまで一時停止されます。

パターンはglobマッチングを使用します。MCPツールは `mcp:<server>:<tool>` でスコープを指定できます。例えば、`mcp:github:*` は `github` サーバーのすべてのツールに一致します。LibreChatは、ネストされたサブエージェントを通じて到達可能なツールを含め、MCPランタイム名およびモデル向けのエイリアスに対して静的ルールとフックマッチャーを適用します。静的ルールは、選択されたモードがフォールバックを提供する前に、`deny`、`ask`、`allow` の順序で評価されます。したがって、`bypass` モードを含め、拒否（deny）ルールが常に優先されます。

```yaml filename="endpoints / agents / toolApproval"
toolApproval:
  enabled: true
  mode: default
  allow:
    - 'mcp:analytics:read_*'
  deny:
    - 'mcp:*:delete_*'
  ask:
    - 'mcp:*:*'
  reason: 'Review {tool} before it runs.'
```

Hooksはサーバー起動時に一度だけ読み込まれ、LibreChatプロセス内で実行されます。各エントリは `module`、オプションのツール名 `matcher` 正規表現、およびモジュールのビルダーに渡されるオプションの `options` オブジェクトを受け入れます。信頼できるコードのみを読み込んでください。ロールごとやテナントごとのオーバーライドではフックモジュールは再読み込みされません。コンテキストに応じた動作はフック内部で実装してください。

```yaml filename="endpoints / agents / toolApproval / hooks"
toolApproval:
  enabled: true
  hooks:
    - module: '@acme/librechat-approval-hook'
      matcher: '^mcp:production:'
      options:
        requireTicket: true
```

## maxSubagents

<OptionTable
  options={[
    [
      'maxSubagents',
      'Number',

    maxSubagents: 20

デプロイメントで10個を超える子エージェントへの委任が必要な、オーケストレーションを多用するエージェントを実行する場合にこれを引き上げてください。この値は起動時に読み取られ、以下の3箇所で適用されます：

- `subagents.agent_ids` および `subagents.graphs` に対する、エージェントの作成、更新、および複製リクエスト
- Model spec `subagents.agent_ids` の許可リスト。同じ設定パスで検証されます。

<Callout type="warning">
  `maxSubagents` は1から50の間の整数である必要があります。この範囲外の値は `librechat.yaml` のバリデーションで失敗し、LibreChatはデフォルト値にフォールバックする代わりにエラーをログに記録して起動時に終了します。`CONFIG_BYPASS_VALIDATION=true` を指定して起動すると終了は回避されますが、その場合はカスタム設定全体が破棄されるため、上限は `10` に戻ります。意図的にデフォルトに戻すには、キーを削除してください。`maxSubagents` を省略すると、エラーなしで `10` に解決されます。
</Callout>

<Callout type="note">
  この上限はプロセス全体に適用されるもので、`librechat.yaml` から読み込まれます。ユーザー単位またはグループ単位のデータベースによる `endpoints.agents.maxSubagents` の上書きは、提供される設定には反映されますが、リクエストの検証には適用されません。
</Callout>

これを上げても、1つのエージェントが参照できるサブエージェントの数のみが変更されます。深さ、グラフノード、および実行構成の制限には影響しません。詳細は [Subagents](/docs/features/subagents#limits) を参照してください。

## fileSharing

`fileSharing` は、委任されたエージェントの作業のための、実行スコープのオプトイン型共有機能です。ここで `enabled: true` を設定し、各委任元エージェントで `subagents.shareFiles` を有効にしてください。入力は受信者に対して読み取り専用となり、出力は明示的に公開されない限り非公開のままとなります。また、公開されたファイルは実行終了後もダウンロード可能です。

```yaml filename="endpoints / agents / fileSharing"
endpoints:
  agents:
    fileSharing:
      enabled: true
      allowSiblingSharing: false
      maxFiles: 100
      maxPrivateBytes: 268435456
      ttlMs: 3600000
```

`allowSiblingSharing` は、明示的に指定された兄弟または子孫の受信者を許可します。`maxFiles` は `1` から `1000` の範囲で指定し、`maxPrivateBytes` は保持されるプライベート出力スナップショットのサイズを制限します。また、`ttlMs` はアクティブなマニフェストの有効期間であり、最大24時間に制限されています。このブロックを省略した場合、共有は無効になります。

## エージェントの機能 [#agent-capabilities]

`capabilities` フィールドを使用すると、エージェントの特定の機能を有効または無効にできます。利用可能な機能は以下の通りです：

- **deferred_tools**: エージェントが実行時に MCP ツールを遅延検出できるようにし、すべてのツールを事前にコンテキストへ読み込む必要をなくします。
- **programmatic_tools**: Agent BuilderでProgrammaticとマークされたMCPツールに対して、Programmatic Tool Callingを有効にします。これには `execute_code` およびTool Call Serverコンポーネントを備えたCode Interpreterのデプロイメントが必要です。この機能はオプトインであり、デフォルトでは有効になっていません。
- **execute_code**: エージェントがコードを実行できるようにします。
- **stateful_code_sessions**: オプトインしたエージェントが、ユーザー単位、エージェントとユーザーの組み合わせ単位、または会話単位で、単一のCode Interpreterワークスペースを再利用できるようにします。これには `execute_code`、互換性のあるCode Interpreterのデプロイメント、およびエージェントごとの詳細設定が必要です。新しいエージェントは、サインインしているユーザーの優先スコープを使用します。この機能は非常に実験的なものであり、デフォルトでは有効になっておらず、実験中に大幅に変更される可能性があります。現在の動作や設定を安定した本番環境向けの契約として扱わないでください。
- **file_search**: エージェントがファイルを検索し、操作できるようにします。有効にすると、引用の動作は `maxCitations`、`maxCitationsPerFile`、および `minRelevanceScore` の設定によって制御されます。
- **web_search**: エージェントのウェブ検索機能を有効にし、インターネット上の情報を検索および取得できるようにします。
- **artifacts**: エージェントがインタラクティブなアーティファクト（Reactコンポーネント、HTML、Mermaidダイアグラム）を生成できるようにします。
- **subagents**: 隔離されたコンテキストでの子エージェントの実行を有効にします。詳細は [Subagents](/docs/features/subagents) を参照してください。
- **actions**: エージェントが定義済みの操作を実行することを許可します。
- **context**: チャットでの「テキストとしてアップロード」機能およびエージェントの「ファイルコンテキスト」を有効にします。これにより、ユーザーはファイルをアップロードし、その内容を抽出して会話に直接含めることができるようになります。
- **skills**: サイドパネルでのSkillsの有効化、手動での `$` 呼び出し、モデルによるSkillsの呼び出し、およびエージェントのSkill許可リストを有効にします。詳細は [Skills](/docs/features/skills) を参照してください。
- **memory**: メモリが設定されており、ユーザーがアクセス権を持っている場合に、エージェントが `set_memory` および `delete_memory` を使用できるようにします。デフォルトで有効になっており、メモリが無効な場合は実行時に削除されます。
- **ask_user_question**: エージェントが一時停止し、単一のフォームで1〜4つの関連する質問を行い、回答を得てから再開できるようにします。デフォルトで有効になっています。
- **tools**: エージェントに様々なツールへのアクセス権を付与します。
- **chain**: エージェントチェーン（Mixture-of-Agents (MoA) ワークフローとも呼ばれます）のベータ機能を有効にします。
- **ocr**: チャットでの「テキストとしてアップロード」およびエージェントの「ファイルコンテキスト」をオプションで強化し、ファイルをアップロードしてOCRで処理できるようにします。**OCRサービスの設定が必要です。**
- **run_in_background**: Code Interpreterの実行およびシェルツールをデフォルトでバックグラウンド実行の対象とし、対象となるMCP、Plugin、およびActionツールに対してツール単位でのバックグラウンド実行のオプトインを有効にします。Actionレベルのスイッチにより、対象となるすべての操作がオプトインされます。ただし、OAuth Actionおよびすでに `run_in_background` パラメータが定義されている操作は除外されます。エージェントはCode Interpreterを明示的にオプトアウトできます。この設定はバックグラウンド実行を許可するものであり、実際に使用するかどうかはモデルが呼び出しごとに判断します。コードの実行には `execute_code` および設定済みのCode Interpreterデプロイメントが必要です。この機能はデフォルトでは有効になっていません。
- **tool_intents**: 適切なツール呼び出しに対して、モデルが記述したライブインテントラベルを追加します。Code Interpreterツールを含むネイティブツールは自動的にオプトインされます。MCPツールは、Agent Builderで個別または一括で有効にできます。Model Specsでは `describeIntent` を使用します。この機能はデフォルトでは有効になっていません。

capabilitiesを指定することで、エージェントと対話する際にユーザーが利用できる機能を制御できます。

## 設定例 [#example-configuration]

以下は、カスタム機能とファイル引用設定を使用して `agents` endpoint を構成する例です：

```yaml filename="Agents Endpoint"
endpoints:
  agents:
    disableBuilder: false
    # File citation configuration
    maxCitations: 20
    maxCitationsPerFile: 5
    minRelevanceScore: 0.6
    # Custom capabilities
    capabilities:
      # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
      # - 'programmatic_tools'
      - 'execute_code'
      # Optional: makes Code Interpreter background-eligible and enables selected MCP, Plugin, and Action tools.
      # - 'run_in_background'
      # Optional: enables live intent labels for native and selected MCP tools.
      # - 'tool_intents'
      - 'file_search'
      - 'skills'
      - 'subagents'
      - 'actions'
      - 'artifacts'
      - 'context'
      - 'ocr'
      - 'web_search'
```

この例では：

- ビルダーインターフェースが有効になっています
- ファイル引用は合計20件まで、1ファイルにつき最大5件までとなります。
- 関連度が60%以上のソースのみが含まれます
- LibreChat Agentsは、コード実行、ファイル検索（引用付き）、Skills、Subagents、actions、artifacts、ファイルコンテキスト、設定済みの場合はOCRサービス、およびウェブ検索機能にアクセスできます。
- `execute_code` と併せて `programmatic_tools` 機能を有効にしない限り、Programmatic Tool Calling は無効のままとなります。
- バックグラウンドツール呼び出しは、`run_in_background` を追加しない限り無効のままです。Code Interpreterツールはデフォルトで対象となりますが、対象となるMCP、Plugin、およびActionツールは引き続き選択が必要です。
- `tool_intents` を追加しない限り、ツールインテントのラベルは無効のままです。ネイティブツールは自動的にオプトインされますが、MCPツールは引き続きツールごとの選択が必要です。

## managementApi

ベータ版の Agent Management API を使用すると、信頼されたマシンクライアントが Agent の作成、一覧表示、読み取り、更新、削除、ファイルの管理、およびアクセス可能な Skill の検出や編集を行うことができます。これは [`remoteApi`](#remoteapi) とは別個のものです。管理ルートはデプロイメントに紐付けられた OIDC マシンアイデンティティのみを受け入れ、LibreChat Remote Agents API キーやブラウザセッションは受け入れません。

```yaml filename="endpoints / agents / managementApi"
endpoints:
  agents:
    managementApi:
      auth:
        oidc:
          enabled: true
          issuer: https://identity.example.com/
          audience: https://librechat.example.com/agents
          # jwksUri: https://identity.example.com/.well-known/jwks.json
        clients:
          - clientId: machine-client-id
            # subject: provider-specific-service-principal-subject
            userId: 507f1f77bcf86cd799439011
            tenantId: tenant-id
            enabled: true
```

## 注記 [#notes]

- [modelSpecs](/docs/configuration/librechat_yaml/object_structure/model_specs) を使用して選択可能なエージェントのリストを定義している場合を除き、ビルダーインターフェースを無効にすることは推奨されません。
- ファイル引用設定（`maxCitations`、`maxCitationsPerFile`、`minRelevanceScore`）は、`file_search`機能が有効な場合にのみ適用されます。
- 関連性スコアはベクトル類似性を使用して計算され、1.0は完全一致、0.0は類似性がないことを表します。
- 引用制限は、包括的な情報検索と応答の品質およびパフォーマンスのバランスを取るのに役立ちます。
- `context`機能は、OCR設定なしでもテキスト解析メソッドを使用して動作します。OCRを設定すると、抽出品質が向上します。
- `ocr` 機能を使用するには、OCR サービスの設定が必要です（[OCR Configuration](/docs/configuration/librechat_yaml/object_structure/ocr) を参照してください）。
- `maxSubagents` は、単一のエージェントが参照できるサブエージェントの数を制限します。これは、[Subagents](/docs/features/subagents#limits) で文書化されている深さやグラフの制限を変更するものではありません。
