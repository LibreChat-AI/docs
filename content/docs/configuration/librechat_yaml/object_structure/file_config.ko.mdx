## 개요 [#overview]

`fileConfig` 객체를 사용하면 크기 제한 및 MIME 유형 제한을 포함하여 애플리케이션의 파일 처리 설정을 구성할 수 있습니다. 이 섹션에서는 `fileConfig` 객체 구조에 대한 자세한 분석을 제공합니다.

The main fields under `fileConfig` covered here:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**참고:**

- 이 글을 작성하는 시점 기준으로, Assistants endpoint는 [이 목록에 있는 파일 형식들을 지원합니다](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google 및 Custom endpoint는 [RAG API](../../rag_api.mdx)를 통해 파일을 지원합니다.
- OpenAI, Azure OpenAI, Anthropic, Google, AWS Bedrock, 그리고 커스텀 endpoint는 [Upload to Provider](/docs/features/ocr#upload-to-provider-instead)를 통해 파일을 직접 업로드하는 것을 지원합니다.
- `ocr` 및 `text` 섹션은 [텍스트로 업로드](/docs/features/upload_as_text) 및 [OCR](/docs/features/ocr)과 같은 기능의 파일 처리를 제어합니다.
- Plugins과 같이 언급되지 않은 다른 endpoint들은 (아직) 파일 업로드를 지원하지 않습니다.
- Assistants endpoint는 `assistants`라는 정의된 endpoint 값을 가집니다. 다른 모든 endpoint는 `default`라는 정의된 값을 사용합니다.
  - 어시스턴트가 아닌 endpoint의 경우, `default` 아래에서 모든 endpoint에 대한 파일 설정을 조정할 수 있습니다.
  - 특정 endpoint에 대한 설정을 조정하려면 해당 endpoint 이름을 나열할 수 있습니다:
    - `assistants`
        - 다른 것들과 별도로 정의된 기본값을 가지고 있으므로 "default"를 사용하지 않습니다.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- 값을 생략할 수 있으며, 이 경우 앱은 아래 나열된 endpoint 유형별로 정의된 기본값을 사용합니다.
- LibreChat은 1메가바이트를 다음과 같이 계산합니다: `1 x 1024 x 1024`
- 장기 실행 업로드 응답 스트리밍 및 서버 측 원격 URL 가져오기 제한은 [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` 및 `REMOTE_FILE_FETCH_MAX_BYTES` 환경 변수](/docs/configuration/dotenv#file-uploads)를 통해 구성됩니다.

## 예시 [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="MIME 패턴 구문">
  LibreChat은 관리자가 구성한 `supportedMimeTypes` 패턴을 서버에서 RE2 호환 선형 시간 정규식 엔진으로 평가합니다. 역참조(backreferences)와 룩어라운드(lookaround)는 지원되지 않습니다. 모든 패턴은 구성 유효성 검사 중에 활성 엔진으로 컴파일되며, 지원되지 않는 패턴이 있을 경우 구성을 무시하고 넘어가는 대신 거부합니다.
</Callout>

## skills

<OptionTable
  options={[

  ]}

`skills` 는 세 가지 매개변수를 지원합니다:

- `fileSizeLimit` (숫자)
  - 단일 Skill 업로드의 최대 크기(메가바이트(MB) 단위).
  - **기본값:** `50`
- `importCleanupConcurrency` (정수)
  - 실패한 Skill 아카이브 가져오기 후의 최대 동시 정리 작업 수입니다. 직렬 정리를 수행하려면 `1`을 사용하세요.
  - **기본값:** `8`
- `deletionCleanupConcurrency` (정수)
  - 삭제된 Skill에 대해 동시에 실행되는 정리 작업의 최대 개수입니다. 순차 정리를 원하면 `1`을 사용하세요.
  - **기본값:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

파일당 제한 및 아카이브 항목 제한과 같은 나머지 가져오기 규칙은 [Skills](/docs/features/skills)를 참조하세요.

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', '이미지 생성 출력 품질 및 크기 관련 설정입니다.', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],

`imageGeneration`은(는) 다음 매개변수를 지원합니다:

- `percentage` (Number)

  - 기본 크기 또는 원본 크기를 기준으로 출력 이미지의 배율을 조정하려면 이 설정을 사용하세요.

- `px` (Number)
  - 출력 이미지의 크기를 픽셀 단위로 지정합니다(예: `1024`).
  - 기본 크기와 관계없이 생성된 이미지의 출력 크기를 명시적으로 설정하려면 이를 사용하세요.

설정 예시:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

클라이언트 측에서 업로드 전에 이미지 크기를 조정하는 기능을 제어하며, 이를 통해 크기가 지나치게 큰 이미지로 인한 업로드 오류를 방지합니다. 사용자는 설정 > 채팅에서 크기 조정 기능을 켜거나 끌 수 있습니다. 여기서 `enabled`를 설정하면 모든 사용자에 대해 해당 선택이 무시되고 토글이 잠깁니다. 이 항목을 생략하면 사용자가 직접 설정을 제어할 수 있습니다.

- `enabled` (Boolean)
  - 모든 사용자에 대해 크기 조정을 강제로 켜거나(`true`) 끕니다(`false`). 생략하면 각 사용자가 직접 결정하며, 기본적으로 크기 조정은 켜져 있습니다.
- `maxWidth` (Number)
  - 리사이즈된 이미지의 최대 너비(픽셀 단위)입니다. 최소값은 `1`입니다. **기본값:** `1900`
- `maxHeight` (Number)
  - resized images의 최대 높이(픽셀 단위)입니다. 최솟값은 `1`입니다. **기본값:** `1900`
- `quality` (숫자)
  - JPEG 압축 품질은 `0`부터 `1`까지입니다. **기본값:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

**기본값:** `100000`

```yaml filename="fileConfig / fileTokenLimit"
fileConfig:
  fileTokenLimit: 100000
```

## textFallbackWithoutTools

업로드가 `none`(저장되며 도구에서만 사용 가능)으로 라우팅되고 해당 턴에서 이를 읽을 수 있는 도구가 실행되지 않으면, LibreChat은 대신 파일에서 추출한 텍스트를 전달할 수 있습니다. 이 기능을 활성화하려면 `textFallbackWithoutTools: true`를 설정하세요. 전역적으로 `fileConfig` 아래에서 설정하거나, `fileConfig.endpoints`(`default` 포함)의 항목별로 설정할 수 있습니다. 엔드포인트 값이 전역 값보다 우선합니다.

**기본값:** `false`

이는 라우트가 추론된 메시지 첨부 파일에만 적용됩니다. 사용자가 명시적으로 선택한 대상은 다시 판단되지 않으며, 에이전트의 도구 리소스에 보관된 파일은 프롬프트에 전달되지 않습니다. 도구용 파일에 대해서는 내장 문서 및 일반 텍스트 추출기만 실행되므로 RAG나 OCR 호출은 이루어지지 않습니다. 추출된 텍스트가 없는 기존 파일은 소급하여 채워지지 않습니다.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

코드 실행 환경에 이 기간(밀리초 단위) 내에 프로비저닝된 파일은 재사용 전에 실시간 가용성 확인을 건너뜁니다. 최솟값은 `0`입니다.

**기본값:** `21600000` (6시간)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

priming이 레거시 File Search 가용성 확인을 기다리는 시간(밀리초)으로, 그 이후에는 확인 결과와 관계없이 파일을 임베딩합니다. 최소값은 `1`입니다.

**기본값:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', 'OCR을 사용하지 않는 직접적인 텍스트 파일 파싱 설정.', 'Configures which file types are processed as plain text files for direct content extraction.'],
  ]}
/>

**설명:** `text` 섹션은 직접적인 텍스트 추출을 사용하여 처리할 파일 형식을 구성합니다.

**참고:** 텍스트 파싱은 "텍스트로 업로드" 기능(`context` 기능으로 제어됨)에서 사용되는 기본 방식입니다. 자세한 내용은 [텍스트로 업로드](/docs/features/upload_as_text)를 참조하세요.

- 기본 목록은 형식이 올바른 모든 MIME 타입과 일치합니다. 이미 텍스트인 파일(`text/*`, JSON, YAML, XML, SQL, 셸 스크립트, `.eml` 이메일 등)은 직접 읽힙니다. 파서가 없는 다른 바이너리 타입은 잘못 디코딩되어 깨진 내용이 되지 않도록 거부됩니다.
- 목록을 좁히고 RAG API가 구성되어 있다면(`RAG_API_URL`), 해당 조건에 맞는 파일은 RAG API의 텍스트 추출 기능으로 전송됩니다. RAG API를 사용할 수 없는 경우에는 LibreChat이 내장된 문서 파서로 대체하여 처리합니다.

## stt

`fileConfig.stt`는 현재 버전의 LibreChat에서 읽히지 않으며, 여기에 있는 `stt` 블록은 무시됩니다. 텍스트로 추가된 오디오 파일은 [`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech)에서 음성-텍스트 변환(STT) 제공자가 구성되어 있을 때 전사되며, 이때 다음과 같은 내장 오디오 유형 목록이 사용됩니다: MP3, MPEG, WAV, OGG, Vorbis, MP4 및 M4A 오디오, FLAC, WebM, AAC, WMA, Opus.

## 파일 처리 우선순위 [#file-processing-priority]

LibreChat는 파일이 텍스트로 추가될 때(텍스트로 업로드, 긴 붙여넣기, 또는 에이전트 파일 컨텍스트), 해당되는 첫 번째 단계를 사용합니다:

1. **OCR**: `librechat.yaml`에 `ocr` 섹션이 있고 파일이 `fileConfig.ocr.supportedMimeTypes`와 일치하는 경우 OCR이 사용됩니다. OCR 서비스가 실패하면 다음으로 내장 문서 파서가 시도됩니다.
2. **RAG API 텍스트 추출**: `text.supportedMimeTypes`가 기본값에서 축소되어 있고, RAG API가 구성되어 있으며, 파일이 목록과 일치하는 경우입니다.
3. **내장 문서 파서**: PDF, DOCX, XLS, XLSX, ODT, ODS 파일을 지원합니다. 텍스트 레이어만 읽습니다.
4. **음성-텍스트 변환**: STT 제공자가 구성된 경우 오디오 파일을 지원합니다.
5. **텍스트 파싱**: `text.supportedMimeTypes`와 일치하는 파일.

OCR이 설정되지 않은 상태에서 이미지나 스캔된 PDF를 업로드하면 추출 가능한 텍스트가 없으므로, OCR 서비스가 필요하다는 메시지와 함께 업로드가 실패합니다.

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', '사용자가 대상을 선택하지 않았을 때 첨부 파일이 모델에 전달되는 방식.', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

Each value is one of:

- `provider`: 파일이 모델에 네이티브 첨부 파일(이미지, PDF, 오디오 또는 비디오 입력)로 전송됩니다.
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`: 파일이 저장되며 코드 실행이나 파일 검색과 같은 도구에서 사용할 수 있지만, 모델에는 전송되지 않습니다.

`overrides`는 MIME 타입 또는 `type/*` 와일드카드를 값에 매핑합니다. `fallback`은 나열되지 않은 모든 항목에 적용됩니다. LibreChat은 엔드포인트 overrides, 엔드포인트 fallback, 최상위 overrides, 최상위 fallback, 그리고 내장 기본값 순서로 확인합니다.

기본 제공 기본값은 이미지, 오디오, 비디오, PDF를 제공자에게 전송하고, 그 밖의 모든 항목은 텍스트로 전송합니다. 또한 엔드포인트에 따라 조정합니다. PDF를 읽을 수 없는 제공자에게는 PDF가 텍스트로 전송되고, 미디어를 지원하지 않는 제공자에게 전달되는 오디오나 비디오는 전사되거나 프롬프트에서 제외됩니다. AWS Bedrock은 지원되는 문서 유형을 기본 형식 그대로 받으며, 아카이브처럼 텍스트를 추출할 방법이 없는 유형은 `none`으로 설정됩니다. 직접 구성한 값은 이러한 조정 없이 적은 그대로 사용됩니다.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

LibreChat은 이러한 패턴을 적용하기 전에 일반적인 MIME 별칭을 정규화합니다. 특히 `application/x-shellscript`(Linux의 Chrome에서 보고됨)와 `text/x-shellscript`(libmagic에서 보고됨)는 `application/x-sh`로 변환됩니다. 따라서 셸 스크립트를 허용하는 사용자 지정 허용 목록(allowlist)은 표준 `application/x-sh` 유형을 허용해야 합니다. 업로드가 거부되면 일반적인 서버 오류 대신 보고된 지원되지 않는 유형이 클라이언트에 반환됩니다.

## 보존된 파일 및 벡터 정리 [#retained-file-and-vector-cleanup]

파일 삭제 시 보조 스토리지 정리가 확인될 때까지 읽기 가능한 기본 사본을 유지합니다. `fileConfig.retainedFileCleanup`의 기본값은 `false`입니다. 이 값을 명시적으로 활성화하기 전까지 임베디드 파일과 보관된 Code Interpreter 대상은 파괴적으로 정리되지 않습니다. 모든 복제본과 롤백 대상이 보관된 파일 대상을 읽을 수 있게 된 후에만 활성화하십시오.

| Field                          | Default | Meaning                                                                                            |
| ------------------------------ | ------- | -------------------------------------------------------------------------------------------------- |
| `retainedFileCleanup`          | `false` | 리더 롤아웃 이후 보존된 대상 메타데이터를 사용한 정리에 대해 옵트인합니다.                          |
| `vectorOwnershipTrackingStart` | Unset   | 모든 레거시 벡터 작성기와 롤백 대상이 폐기된 후 선택한 UTC 날짜-시간 기준점입니다.                    |
| `vectorDeletionConcurrency`    | `4`     | 정수 `1`부터 `16`까지; 파일당 진행 중인 최대 네임스페이스 삭제 수입니다.                              |

벡터 삭제에는 안전한 작성기 기준 시점(safe writer cutoff) 이후 또는 해당 시점에 기록된 완전한 소유권 정보와 삽입 시점 증명이 추가로 필요합니다. 증명이 없거나, 유효하지 않거나, 미래 시점이거나, 기준 시점 이전인 경우에는 실패로 처리되며(fail closed), 파일과 해당 벡터는 그대로 유지됩니다. 기준 시점을 설정해도 이전의 소유권 메타데이터가 복구되지는 않으며, 모호한 레거시 파일을 삭제 대상으로 만들기 위해 기준 시점을 소급하여 변경해서는 안 됩니다.

정리 대상에는 기록된 각 엔티티 네임스페이스와 네임스페이스가 지정되지 않은(unscoped) 네임스페이스가 포함됩니다. 네임스페이스는 DELETE 응답이 성공적으로 반환된 후에 정리 완료로 간주합니다. `404` 응답은 같은 네임스페이스에 대한 인벤토리 확인이 성공적으로 이루어져 해당 파일이 목록에서 제외된 것을 확인한 후에만 부재(absence)로 인정합니다. 보조 네임스페이스나 네임스페이스 중 하나라도 부재를 확인할 수 없는 경우, 기본(primary) 항목은 재시도를 위해 계속 사용 가능한 상태로 남습니다. 이러한 설정은 레거시 레코드를 소급하여 채우지 않습니다. 모호한 과거 파일에 대해서는 별도로 검증된 재조정(reconciliation) 계획을 수립하십시오.
