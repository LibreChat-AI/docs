## 개요 [#overview]

`fileConfig` 객체를 사용하면 크기 제한 및 MIME 유형 제한을 포함하여 애플리케이션의 파일 처리 설정을 구성할 수 있습니다. 이 섹션에서는 `fileConfig` 객체 구조에 대한 자세한 분석을 제공합니다.

`fileConfig`의 주요 필드는 다음과 같습니다:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`
  - `stt`

**참고:**

- 이 글을 작성하는 시점 기준으로, Assistants endpoint는 [이 목록에 있는 파일 형식들을 지원합니다](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google 및 Custom endpoint는 [RAG API](../../rag_api.mdx)를 통해 파일을 지원합니다.
- OpenAI, Azure OpenAI, Anthropic, Google 및 AWS Bedrock endpoint는 [Upload to Provider](/docs/features/ocr#5-upload-files-to-provider-direct)를 통한 직접 파일 업로드를 지원합니다.
- `ocr`, `text`, 및 `stt` 섹션은 [Upload as Text](/docs/features/upload_as_text) 및 [OCR](/docs/features/ocr)과 같은 기능을 위한 파일 처리를 제어합니다.
- Plugins과 같이 언급되지 않은 다른 endpoint들은 (아직) 파일 업로드를 지원하지 않습니다.
- Assistants endpoint는 `assistants`라는 정의된 endpoint 값을 가집니다. 다른 모든 endpoint는 `default`라는 정의된 값을 사용합니다.
  - 어시스턴트가 아닌 endpoint의 경우, `default` 아래에서 모든 endpoint에 대한 파일 설정을 조정할 수 있습니다.
  - 특정 endpoint에 대한 설정을 조정하려면 해당 endpoint 이름을 나열할 수 있습니다:
    - `assistants`
        - 다른 것들과 별도로 정의된 기본값을 가지고 있으므로 "default"를 사용하지 않습니다.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- 값을 생략할 수 있으며, 이 경우 앱은 아래 나열된 endpoint 유형별로 정의된 기본값을 사용합니다.
- LibreChat은 1메가바이트를 다음과 같이 계산합니다: `1 x 1024 x 1024`
- 장기 실행 업로드 응답 스트리밍 및 서버 측 원격 URL 가져오기 제한은 [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` 및 `REMOTE_FILE_FETCH_MAX_BYTES` 환경 변수](/docs/configuration/dotenv#file-uploads)를 통해 구성됩니다.

## 예시 [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

<Callout type="info" title="MIME 패턴 구문">
  LibreChat은 관리자가 구성한 `supportedMimeTypes` 패턴을 서버에서 RE2 호환 선형 시간 정규식 엔진으로 평가합니다. 역참조(backreferences)와 룩어라운드(lookaround)는 지원되지 않습니다. 모든 패턴은 구성 유효성 검사 중에 활성 엔진으로 컴파일되며, 지원되지 않는 패턴이 있을 경우 구성을 무시하고 넘어가는 대신 거부합니다.
</Callout>

`skills` 는 세 가지 매개변수를 지원합니다:

- `fileSizeLimit` (숫자)
  - 단일 Skill 업로드의 최대 크기(메가바이트(MB) 단위).
  - **기본값:** `50`
- `importCleanupConcurrency` (정수)
  - 실패한 Skill 아카이브 가져오기 후의 최대 동시 정리 작업 수입니다. 직렬 정리를 수행하려면 `1`을 사용하세요.
  - **기본값:** `8`
- `deletionCleanupConcurrency` (정수)
  - 삭제된 Skill에 대해 동시에 실행되는 정리 작업의 최대 개수입니다. 순차 정리를 원하면 `1`을 사용하세요.
  - **기본값:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

파일당 제한 및 아카이브 항목 제한과 같은 나머지 가져오기 규칙은 [Skills](/docs/features/skills)를 참조하세요.

## clientImageResize

클라이언트 측에서 업로드 전에 이미지 크기를 조정하는 기능을 제어하며, 이를 통해 크기가 지나치게 큰 이미지로 인한 업로드 오류를 방지합니다. 사용자는 설정 > 채팅에서 크기 조정 기능을 켜거나 끌 수 있습니다. 여기서 `enabled`를 설정하면 모든 사용자에 대해 해당 선택이 무시되고 토글이 잠깁니다. 이 항목을 생략하면 사용자가 직접 설정을 제어할 수 있습니다.

- `enabled` (Boolean)
  - 모든 사용자에 대해 크기 조정을 강제로 켜거나(`true`) 끕니다(`false`). 생략하면 각 사용자가 직접 결정하며, 기본적으로 크기 조정은 켜져 있습니다.
- `maxWidth` (Number)
  - 리사이즈된 이미지의 최대 너비(픽셀 단위)입니다. 최소값은 `1`입니다. **기본값:** `1900`
- `maxHeight` (Number)
  - resized images의 최대 높이(픽셀 단위)입니다. 최솟값은 `1`입니다. **기본값:** `1900`
- `quality` (숫자)
  - JPEG 압축 품질은 `0`부터 `1`까지입니다. **기본값:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## defaultLLMDeliveryPath

명시적으로 선택된 대상이 없는 업로드가 모델 컨텍스트로 들어가는 방식을 제어합니다. `fileConfig` 하위에서 전역적으로 구성하거나, `fileConfig.endpoints` 하위의 명명된 항목에 대해 재정의할 수 있습니다.

- `provider`는 원본 파일을 모델 제공자의 네이티브 파일 또는 미디어 경로를 통해 전송합니다.
- `text`는 지원되는 콘텐츠를 추출하거나 전사하여 결과 텍스트를 컨텍스트에 추가합니다.
- `none`은 파일을 모델 컨텍스트에 직접 배치하지 않고 저장하며, 선택된 도구가 필요할 때 이를 가져와 사용할 수 있습니다.

`fallback`은 일치하지 않는 MIME 타입을 처리합니다. `overrides`는 `application/pdf`와 같은 정확한 MIME 타입이나 `image/*`와 같은 와일드카드를 허용합니다. 해결 과정에서는 endpoint overrides와 fallback을 우선시하며, 그 다음으로 전역 값을 사용합니다. 명시적인 설정이 없는 경우, 이미지, 오디오, 비디오 및 PDF는 기본 제공자(native provider) 전달을 우선하며, 기타 복구 가능한 콘텐츠는 텍스트를 사용합니다. LibreChat은 추출이 가능한 경우 지원되지 않는 기본 경로를 텍스트로, 그렇지 않은 경우에는 `none`으로 다운그레이드합니다.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## legacyFileUploadUX

기본 통합 업로더는 모델 전달 방식을 자동으로 선택하며, 선택된 도구가 필요할 때만 File Search 또는 Code 리소스를 프로비저닝합니다. `legacyFileUploadUX: true`를 전역으로 설정하거나 특정 endpoint에 설정하면 대상 선택기 및 사용자가 직접 선택하는 이전 업로드 동작을 복원할 수 있습니다.

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
```

## textFallbackWithoutTools

업로드가 `none`(저장되며 도구에서만 사용 가능)으로 라우팅되고 해당 턴에서 이를 읽을 수 있는 도구가 실행되지 않으면, LibreChat은 대신 파일에서 추출한 텍스트를 전달할 수 있습니다. 이 기능을 활성화하려면 `textFallbackWithoutTools: true`를 설정하세요. 전역적으로 `fileConfig` 아래에서 설정하거나, `fileConfig.endpoints`(`default` 포함)의 항목별로 설정할 수 있습니다. 엔드포인트 값이 전역 값보다 우선합니다.

**기본값:** `false`

이는 라우트가 추론된 메시지 첨부 파일에만 적용됩니다. 사용자가 명시적으로 선택한 대상은 다시 판단되지 않으며, 에이전트의 도구 리소스에 보관된 파일은 프롬프트에 전달되지 않습니다. 도구용 파일에 대해서는 내장 문서 및 일반 텍스트 추출기만 실행되므로 RAG나 OCR 호출은 이루어지지 않습니다. 추출된 텍스트가 없는 기존 파일은 소급하여 채워지지 않습니다.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

코드 실행 환경에 이 기간(밀리초 단위) 내에 프로비저닝된 파일은 재사용 전에 실시간 가용성 확인을 건너뜁니다. 최솟값은 `0`입니다.

**기본값:** `21600000` (6시간)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

priming이 레거시 File Search 가용성 확인을 기다리는 시간(밀리초)으로, 그 이후에는 확인 결과와 관계없이 파일을 임베딩합니다. 최소값은 `1`입니다.

**기본값:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## 파일 처리 우선순위 [#file-processing-priority]

LibreChat은 다음 **우선순위**에 따라 MIME 유형 매칭을 기반으로 업로드된 파일을 처리합니다:

1. **OCR** - 파일이 `ocr.supportedMimeTypes`와 일치하고 OCR이 구성된 경우
2. **STT** - 파일이 `stt.supportedMimeTypes`와 일치하고 STT가 구성된 경우
3. **텍스트 파싱** - 파일이 `text.supportedMimeTypes`와 일치하는 경우
4. **Fallback** - 최후의 수단으로 텍스트 파싱

이 처리 순서는 특수 서비스(OCR/STT)가 구성되지 않은 경우에도 기능을 유지하면서 최적의 추출 품질을 보장합니다.

### 처리 예시 [#processing-examples]

**OCR이 구성된 PDF 파일:**
- 파일이 `ocr.supportedMimeTypes`와 일치합니다
- **OCR을 사용하여** 텍스트를 추출합니다
- 스캔된 PDF 및 이미지에 대한 더 나은 품질

**OCR이 구성되지 않은 PDF 파일:**
- `text.supportedMimeTypes`와 일치하는 파일(또는 대체 항목 사용)
- **텍스트 파싱** 라이브러리를 사용합니다
- 텍스트 선택이 가능한 디지털 PDF에 잘 작동합니다

**Python 파일:**
- `text.supportedMimeTypes`와 일치하는 파일
- **텍스트 파싱 사용** (OCR 불필요)
- 직접 텍스트 추출

**STT가 구성된 오디오 파일:**
- `stt.supportedMimeTypes`와 일치하는 파일
- **STT를 사용하여** 오디오를 텍스트로 변환합니다

**OCR이 구성되지 않은 이미지 파일:**
- 파일이 `ocr.supportedMimeTypes`와 일치하지만 OCR을 사용할 수 없습니다
- **텍스트 파싱으로 대체**
- OCR 없는 제한된 추출 기능

이 우선순위 시스템을 통해 "Upload as Text"와 같은 기능이 OCR 구성 없이도 작동할 수 있으며, 동시에 OCR을 사용할 수 있는 경우 이를 활용하여 추출 품질을 향상시킬 수 있습니다.

## 보존된 파일 및 벡터 정리 [#retained-file-and-vector-cleanup]

파일 삭제 시 보조 스토리지 정리가 확인될 때까지 읽기 가능한 기본 사본을 유지합니다. `fileConfig.retainedFileCleanup`의 기본값은 `false`입니다. 이 값을 명시적으로 활성화하기 전까지 임베디드 파일과 보관된 Code Interpreter 대상은 파괴적으로 정리되지 않습니다. 모든 복제본과 롤백 대상이 보관된 파일 대상을 읽을 수 있게 된 후에만 활성화하십시오.

| Field | Default | 의미 |
| ----- | ------- | ---- |
| `retainedFileCleanup` | `false` | 리더 롤아웃 이후 보존된 대상 메타데이터를 사용한 정리를 활성화하도록 선택합니다. |
| `vectorOwnershipTrackingStart` | 미설정 | 모든 레거시 벡터 작성기와 롤백 대상이 폐기된 후 선택한 UTC 날짜-시간 기준점입니다. |
| `vectorDeletionConcurrency` | `4` | 정수 `1`–`16`; 파일당 동시에 진행할 수 있는 최대 네임스페이스 삭제 수입니다. |

벡터 삭제에는 안전한 작성기 기준 시점(safe writer cutoff) 이후 또는 해당 시점에 기록된 완전한 소유권 정보와 삽입 시점 증명이 추가로 필요합니다. 증명이 없거나, 유효하지 않거나, 미래 시점이거나, 기준 시점 이전인 경우에는 실패로 처리되며(fail closed), 파일과 해당 벡터는 그대로 유지됩니다. 기준 시점을 설정해도 이전의 소유권 메타데이터가 복구되지는 않으며, 모호한 레거시 파일을 삭제 대상으로 만들기 위해 기준 시점을 소급하여 변경해서는 안 됩니다.

정리 대상에는 기록된 각 엔티티 네임스페이스와 네임스페이스가 지정되지 않은(unscoped) 네임스페이스가 포함됩니다. 네임스페이스는 DELETE 응답이 성공적으로 반환된 후에 정리 완료로 간주합니다. `404` 응답은 같은 네임스페이스에 대한 인벤토리 확인이 성공적으로 이루어져 해당 파일이 목록에서 제외된 것을 확인한 후에만 부재(absence)로 인정합니다. 보조 네임스페이스나 네임스페이스 중 하나라도 부재를 확인할 수 없는 경우, 기본(primary) 항목은 재시도를 위해 계속 사용 가능한 상태로 남습니다. 이러한 설정은 레거시 레코드를 소급하여 채우지 않습니다. 모호한 과거 파일에 대해서는 별도로 검증된 재조정(reconciliation) 계획을 수립하십시오.
