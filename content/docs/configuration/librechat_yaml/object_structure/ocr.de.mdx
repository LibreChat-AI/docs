## Übersicht [#overview]

Das `ocr` Objekt ermöglicht es Ihnen, die Einstellungen für die optische Zeichenerkennung (OCR) der Anwendung zu konfigurieren, wodurch die Extraktion von Text aus Bildern ermöglicht wird. Dieser Abschnitt bietet eine detaillierte Aufschlüsselung der Struktur des `ocr` Objekts.

Es gibt 5 Felder unter `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Hinweise:**

- OCR ist nur aktiv, wenn `librechat.yaml` einen `ocr`-Abschnitt enthält. Das Setzen von `OCR_API_KEY` allein aktiviert es nicht. Für die gehostete API von Mistral reichen `strategy: "mistral_ocr"` und `OCR_API_KEY` in `.env` aus, da `apiKey` und `baseURL` standardmäßig auf `${OCR_API_KEY}` und `${OCR_BASEURL}` (bzw. `https://api.mistral.ai/v1`, falls dieser Wert nicht gesetzt ist) verweisen.
- OCR wird für Dateien ausgeführt, die als Text hinzugefügt werden: Upload as Text im Chat und File Context im Agent Builder. Agents benötigen außerdem die Fähigkeit `ocr` in `endpoints.agents.capabilities`, die standardmäßig enthalten ist. Ohne sie lehnt eine konfigurierte OCR-Strategie den Upload mit der Meldung „OCR capability is not enabled for Agents“ ab.
- Welche Dateitypen an OCR übergeben werden, wird über [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr) gesteuert.
- Die Standardstrategie ist `mistral_ocr`. Wenn `mistralModel` leer ist, wird `mistral-ocr-latest` verwendet.
- Azure-bereitgestellte Mistral OCR-Modelle können verwendet werden, indem die Strategie auf `azure_mistral_ocr` gesetzt wird.
- In Google Vertex AI bereitgestellte Mistral OCR-Modelle können verwendet werden, indem die Strategie auf `vertexai_mistral_ocr` gesetzt wird.
  - Erfordert, dass die Umgebungsvariable `GOOGLE_SERVICE_KEY_FILE` mit den Anmeldedaten des Dienstkontos festgelegt wird.
  - Der Service-Key kann wie folgt bereitgestellt werden: als Dateipfad, URL, base64-kodierter JSON-String oder als roher JSON-String.
  - Die Projekt-ID und der Standort werden automatisch aus den Anmeldeinformationen des Dienstkontos extrahiert.
- Die lokale Textextraktion ist über `document_parser` verfügbar, das Text aus PDF-, DOCX-, XLS/XLSX-, ODT- und ODS-Dateien bis zu 15 MB extrahiert, ohne dass eine externe API benötigt wird.
  - Verwendet `pdfjs-dist`, `mammoth` und `SheetJS` lokal, es ist kein API-Schlüssel oder Basis-URL erforderlich
  - Nur das Feld `strategy` ist erforderlich; `apiKey`, `baseURL` und `mistralModel` werden ignoriert.
- `custom_ocr` wird vom Schema akzeptiert, hat aber noch keine Implementierung.
- Die Analyse von Umgebungsvariablen wird für die Parameter `apiKey`, `baseURL` und `mistralModel` unterstützt.

## Automatische Dokumentenanalyse (Keine Konfiguration erforderlich) [#automatic-document-parsing-no-configuration-required]

Der integrierte `document_parser` wird für Datei-Uploads von Agents automatisch ausgeführt, **selbst wenn kein `ocr`-Block** in Ihrer `librechat.yaml` konfiguriert ist. Das bedeutet, dass PDF-, DOCX-, XLS/XLSX- und ODS-Dateien ohne jegliche Einrichtung sofort verarbeitet werden können.

Die Auflösungslogik funktioniert wie folgt:

1. **Keine `ocr`-Konfiguration vorhanden**: Wenn eine Kontextdatei eines Agenten hochgeladen wird und ihr MIME-Typ einem unterstützten Dokumenttyp entspricht (PDF, DOCX, Excel, ODS), wird der `document_parser` direkt verwendet. Eine Prüfung der OCR-Funktionalität für den Agenten ist nicht erforderlich.

2. **`ocr`-Konfiguration vorhanden**: Die konfigurierte Strategie (z. B. `mistral_ocr`) wird zuerst versucht. Schlägt die konfigurierte Strategie **zur Laufzeit fehl**, wird der `document_parser` als Fallback verwendet, sodass die Textextraktion für unterstützte Dokumenttypen dennoch erfolgreich ist.

3. **Keines von beiden gelingt**: Wenn sowohl die konfigurierte Strategie als auch der Dokumentenparser fehlschlagen (z. B. wenn es sich um eine PDF-Datei handelt, die nur Bilder und keinen eingebetteten Text enthält), wird ein Fehler zurückgegeben, der darauf hinweist, dass ein OCR-Dienst benötigt wird.

<Callout type="info">
Der `document_parser` verarbeitet ausschließlich textbasierte Dokumente. Für bildbasierte PDFs oder gescannte Dokumente benötigen Sie weiterhin eine konfigurierte OCR-Strategie (wie z. B. `mistral_ocr`), um den Text aus den Bildern innerhalb dieser Dateien zu extrahieren.
</Callout>

## Beispiel [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Beispiel mit Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Beispiel mit Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Für Vertex AI stellen Sie ein Mistral-OCR-Modell in Ihrem Google-Cloud-Projekt bereit, erstellen ein Dienstkonto, das den Vertex-AI-Endpunkt aufrufen kann, und verweisen `GOOGLE_SERVICE_KEY_FILE` auf dessen Schlüssel. Die Variable akzeptiert einen Dateipfad, eine URL, von der der Schlüssel abgerufen wird, base64-kodiertes JSON oder die reine JSON-Zeichenfolge:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Beispiel mit lokalem Dokument-Parser (keine externe API erforderlich):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Vertrauenswürdige private Host:Port-Ausnahmen für OCR-Verbindungs-SSRF-Prüfungen. Öffentliche Ziele bleiben verfügbar. Einträge erfordern einen Port und dürfen keine URLs, Pfade, CIDR-Bereiche, bloße Hosts oder öffentliche IP-Literale sein.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

OCR-Anfragen blockieren zum Zeitpunkt der Verbindung Ziele in privaten Netzwerken, Loopback-Adressen, Link-Local-Adressen sowie Cloud-Metadaten-Dienste und deaktivieren Weiterleitungen. `allowedAddresses` ist eine Ausnahmeliste für exakte, vertrauenswürdige private `host:port`-, `private.ip:port`- oder `[ipv6]:port`-Ziele; sie schränkt den Zugriff auf öffentliche Ziele nicht ein.

<Callout type="warning" title="Vertrauen Sie Ausnahmen mit Vorsicht">
  Verwenden Sie `allowedAddresses` nur für einen privaten OCR-Dienst, den Sie selbst kontrollieren. Ein ausgenommener Hostname vertraut jeder privaten Adresse, zu der er auf diesem Port aufgelöst wird; bevorzugen Sie daher nach Möglichkeit ein privates IP-Literal. Bei einem Forward-Proxy muss der Proxy die Ziel-SSRF-Richtlinie durchsetzen; literale private Ziele bleiben blockiert, sofern sie nicht explizit ausgenommen sind.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'Die zu verwendende OCR-Strategie.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Verfügbare Strategien:**

- `mistral_ocr`: Verwendet die OCR von Mistral über die Standard-Mistral-API.
- `azure_mistral_ocr`: Verwendet Mistral-OCR-Modelle, die in Azure AI Foundry bereitgestellt sind. Setze `mistralModel` auf deinen Bereitstellungsnamen und `baseURL` auf den Endpunkt der Bereitstellung.
- `vertexai_mistral_ocr`: Verwendet Mistral-OCR-Modelle, die auf Google Cloud Vertex AI bereitgestellt sind, und authentifiziert sich mit `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Nutzt lokale Textextraktion für PDF-, DOCX-, XLS/XLSX- und OpenDocument-Dateien. Es ist keine externe API erforderlich. Wird außerdem automatisch für Datei-Uploads von Agents ausgeführt, wenn keine `ocr`-Konfiguration vorhanden ist, sowie als Fallback, wenn eine konfigurierte OCR-Strategie fehlschlägt.
- `custom_ocr`: Für einen benutzerdefinierten OCR-Dienst unter `baseURL` reserviert. Noch nicht implementiert.
