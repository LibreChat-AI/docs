## Vue d'ensemble [#overview]

Le objet `memory` active la [mémoire utilisateur](/docs/features/memory) et définit ses limites. L'ajout de cette section est ce qui permet la mémoire : les entrées enregistrées sont ensuite ajoutées aux conversations de chaque utilisateur, celles-ci peuvent les gérer dans le panneau Mémoires, et l'outil Mémoire (`set_memory` et `delete_memory`) est proposé dans les chats et les agents, à condition que la capacité `memory` soit activée pour le endpoint agents (c'est le cas par défaut).

L'extraction automatique de la mémoire, par laquelle un agent de mémoire distinct examine chaque échange et enregistre des faits sans y être invité, est une option distincte qui doit être activée explicitement : définissez `agent.enabled: true` et indiquez-lui un modèle.

## Exemple [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Configure l\'agent de mémoire automatique optionnel. Peut être soit une référence à un agent existant par ID, soit une configuration d\'agent complète.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

Configure l'agent de mémoire automatique. Il ne s'exécute que lorsque `enabled` vaut `true` ; un bloc `agent` sans `enabled` est ignoré et LibreChat journalise un avertissement au démarrage.

Lorsqu'il est activé, l'agent de mémoire s'exécute au début de chaque requête de conversation, en parallèle de la réponse principale. Il examine les derniers `messageWindowSize` messages (limité à `maxInputTokens`) et enregistre ou supprime des entrées de manière autonome. Il dispose d'un délai allant jusqu'à la fin de la réponse principale, plus 3 secondes au maximum ; s'il est toujours en cours d'exécution après ce délai, son résultat est abandonné pour cette requête.

Le champ `agent` prend en charge deux formats de configuration différents :

### Agent par ID [#agent-by-id]

Lorsque vous disposez d'un agent préconfiguré, vous pouvez y faire référence par son ID :

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Configuration d'agent personnalisé [#custom-agent-configuration]

Pour plus de contrôle, vous pouvez définir une configuration d'agent complète :

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Exemple de configuration complète [#complete-configuration-example]

Un exemple utilisant toutes les options de mémoire :

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Utilisation d'endpoints personnalisés [#using-custom-endpoints]

La fonctionnalité de mémoire prend en charge les endpoints personnalisés. Lors de l'utilisation d'un endpoint personnalisé, le champ `provider` doit correspondre exactement au `name` de l'endpoint personnalisé. Les en-têtes personnalisés avec des variables d'environnement et des espaces réservés utilisateur sont correctement résolus.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- Consultez [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) pour voir tous les espaces réservés disponibles

## Notes [#notes]

- `personalize` contrôle si les utilisateurs peuvent se désinscrire, et non si la mémoire est activée. Utilisez `disabled` pour désactiver la mémoire.
- `maxInputTokens` limite le contexte de conversation envoyé à l'agent de mémoire automatique, tandis que `tokenLimit` plafonne la taille totale des souvenirs enregistrés.
- Les `instructions` personnalisées remplacent les instructions de mémoire par défaut et sont principalement utiles avec `validKeys`.
- L'accès est également contrôlé par rôle via les permissions de mémoire (utiliser, créer, lire, mettre à jour, se désinscrire). Voir [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), le [Panneau d'administration](/docs/features/admin_panel), ou les paramètres d'administration en bas du panneau Mémoires.

## Dépannage [#troubleshooting]

**La mémoire ne fait rien.** Vérifiez que la section `memory` existe et que `disabled` n'est pas `true`, que le rôle de l'utilisateur dispose de l'autorisation d'utiliser la mémoire, et que l'utilisateur n'a pas désactivé l'option **Reference saved memories**. Pour l'outil Memory, la capacité `memory` doit figurer dans la liste `capabilities` de l'endpoint agents si vous en définissez une.

**Rien n'est enregistré automatiquement.** L'extraction automatique nécessite `agent.enabled: true` ainsi qu'un `id` valide, ou un `provider` et un `model`. Sans cela, les entrées ne sont enregistrées que lorsqu'un utilisateur demande au modèle de mémoriser quelque chose avec l'outil Memory activé, ou lorsqu'elles sont ajoutées manuellement.

**L'agent de mémoire échoue sur un endpoint personnalisé.** `provider` doit correspondre exactement au `name` de l'endpoint personnalisé. Vérifiez d'abord que l'endpoint fonctionne pour les conversations normales, puis contrôlez que les variables d'environnement référencées dans ses en-têtes sont définies ; les espaces réservés des en-têtes sont résolus de la même manière pour la mémoire que pour le chat.

**L'utilisation de jetons est élevée.** Réduisez `maxInputTokens` ou `messageWindowSize` pour envoyer moins de conversation à l'agent de mémoire, réduisez `tokenLimit` pour garder les souvenirs stockés (ajoutés à chaque requête) à une taille réduite, et restreignez `validKeys`.
