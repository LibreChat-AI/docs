## Ikhtisar [#overview]

Objek `ocr` memungkinkan Anda untuk mengonfigurasi pengaturan Optical Character Recognition (OCR) untuk aplikasi, yang memungkinkan ekstraksi teks dari gambar. Bagian ini memberikan rincian mendalam mengenai struktur objek `ocr`.

Terdapat 5 kolom di bawah `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Catatan:**

- OCR hanya aktif ketika `librechat.yaml` memiliki bagian `ocr`. Mengatur `OCR_API_KEY` saja tidak akan mengaktifkannya. Untuk API hosted Mistral, `strategy: "mistral_ocr"` ditambah `OCR_API_KEY` di `.env` sudah cukup, karena `apiKey` dan `baseURL` secara default menggunakan `${OCR_API_KEY}` dan `${OCR_BASEURL}` (atau `https://api.mistral.ai/v1` jika nilai tersebut tidak diatur).
- OCR berjalan pada file yang ditambahkan sebagai teks: Upload as Text di chat dan File Context di Agent Builder. Agent juga memerlukan kapabilitas `ocr` di `endpoints.agents.capabilities`, yang disertakan secara default. Tanpa kapabilitas tersebut, strategi OCR yang telah dikonfigurasi akan menolak unggahan dengan pesan "OCR capability is not enabled for Agents".
- Jenis file mana yang dikirim ke OCR dikendalikan oleh [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr).
- Strategi default adalah `mistral_ocr`. Ketika `mistralModel` kosong, `mistral-ocr-latest` akan digunakan.
- Model Mistral OCR yang di-deploy di Azure dapat digunakan dengan mengatur strategi ke `azure_mistral_ocr`.
- Model Mistral OCR yang di-deploy di Google Vertex AI dapat digunakan dengan mengatur strategi ke `vertexai_mistral_ocr`.
  - Memerlukan variabel lingkungan `GOOGLE_SERVICE_KEY_FILE` untuk diatur dengan kredensial akun layanan
  - Service key dapat disediakan sebagai: file path, URL, JSON yang dienkode base64, atau string JSON mentah
  - Project ID dan lokasi diekstraksi secara otomatis dari kredensial akun layanan.
- Ekstraksi teks lokal tersedia melalui `document_parser`, yang mengekstrak teks dari file PDF, DOCX, XLS/XLSX, ODT, dan ODS dengan ukuran hingga 15 MB tanpa memerlukan API eksternal.
  - Menggunakan `pdfjs-dist`, `mammoth`, dan `SheetJS` secara lokal, tanpa memerlukan API key atau base URL
  - Hanya kolom `strategy` yang wajib diisi; `apiKey`, `baseURL`, dan `mistralModel` akan diabaikan.
- `custom_ocr` diterima oleh skema, tetapi belum memiliki implementasi.
- Penguraian variabel lingkungan didukung untuk parameter `apiKey`, `baseURL`, dan `mistralModel`.

## Penguraian Dokumen Otomatis (Tanpa Konfigurasi) [#automatic-document-parsing-no-configuration-required]

`document_parser` bawaan berjalan secara otomatis untuk unggahan file agen **bahkan ketika tidak ada blok `ocr` yang dikonfigurasi** di dalam `librechat.yaml` Anda. Ini berarti file PDF, DOCX, XLS/XLSX, dan ODS diurai secara langsung tanpa perlu pengaturan apa pun.

Logika resolusi bekerja sebagai berikut:

1. **Tidak ada konfigurasi `ocr`**: Ketika file konteks agen diunggah dan tipe MIME-nya cocok dengan jenis dokumen yang didukung (PDF, DOCX, Excel, ODS), `document_parser` digunakan secara langsung. Tidak diperlukan pemeriksaan kemampuan OCR untuk agen.

2. **`ocr` config ada**: Strategi yang dikonfigurasi (misalnya `mistral_ocr`) dicoba terlebih dahulu. Jika strategi yang dikonfigurasi **gagal saat runtime**, `document_parser` digunakan sebagai fallback sehingga ekstraksi teks tetap berhasil untuk jenis dokumen yang didukung.

3. **Keduanya gagal**: Jika strategi yang dikonfigurasi dan parser dokumen sama-sama gagal (misalnya, file berupa PDF yang hanya berisi gambar tanpa teks tertanam), akan dikembalikan sebuah error yang menyarankan bahwa layanan OCR diperlukan.

<Callout type="info">
`document_parser` hanya menangani dokumen berbasis teks. Untuk PDF berbasis gambar atau dokumen hasil pemindaian, Anda tetap memerlukan strategi OCR yang dikonfigurasi (seperti `mistral_ocr`) untuk mengekstrak teks dari gambar di dalam file tersebut.
</Callout>

## Contoh [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Contoh dengan Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Contoh dengan Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Untuk Vertex AI, deploy model Mistral OCR di project Google Cloud Anda, buat service account yang dapat memanggil endpoint Vertex AI, lalu arahkan `GOOGLE_SERVICE_KEY_FILE` ke file kuncinya. Variabel ini menerima path file, URL untuk mengambil kunci, JSON yang dienkode base64, atau string JSON mentah:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Contoh dengan pengurai dokumen lokal (tidak memerlukan API eksternal):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Pengecualian host:port pribadi tepercaya untuk pemeriksaan SSRF waktu koneksi OCR. Destinasi publik tetap tersedia. Entri memerlukan port dan tidak boleh berupa URL, path, rentang CIDR, host kosong, atau literal IP publik.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

Permintaan OCR memblokir tujuan privat, loopback, link-local, dan cloud-metadata pada saat koneksi serta menonaktifkan pengalihan. `allowedAddresses` adalah daftar pengecualian untuk target `host:port`, `private.ip:port`, atau `[ipv6]:port` privat tepercaya yang tepat; daftar ini tidak membatasi akses ke tujuan publik.

<Callout type="warning" title="Berikan pengecualian dengan hati-hati">
  Gunakan `allowedAddresses` hanya untuk layanan OCR privat yang Anda kendalikan. Nama host yang dikecualikan akan memercayai alamat privat apa pun yang diselesaikan pada port tersebut, jadi lebih disarankan untuk menggunakan literal IP privat jika memungkinkan. Dengan forward proxy, proxy tersebut harus menegakkan kebijakan SSRF tujuan; tujuan privat literal akan tetap diblokir kecuali jika dikecualikan secara eksplisit.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'Strategi OCR yang akan digunakan.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Strategi yang Tersedia:**

- `mistral_ocr`: Menggunakan OCR Mistral melalui API Mistral standar.
- `azure_mistral_ocr`: Menggunakan model Mistral OCR yang di-deploy di Azure AI Foundry. Atur `mistralModel` ke nama deployment Anda dan `baseURL` ke endpoint deployment.
- `vertexai_mistral_ocr`: Menggunakan model Mistral OCR yang di-deploy di Google Cloud Vertex AI, diautentikasi dengan `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Menggunakan ekstraksi teks lokal untuk file PDF, DOCX, XLS/XLSX, dan OpenDocument. Tidak memerlukan API eksternal. Juga berjalan secara otomatis untuk unggahan file agen ketika tidak ada konfigurasi `ocr` yang tersedia, dan sebagai cadangan ketika strategi OCR yang dikonfigurasi gagal.
- `custom_ocr`: Disediakan untuk layanan OCR kustom di `baseURL`. Belum diimplementasikan.
