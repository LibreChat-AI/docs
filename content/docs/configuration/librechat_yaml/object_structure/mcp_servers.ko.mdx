## 예시 [#example]

```yaml filename="MCP Servers Object Structure"
# Example MCP Servers Object Structure
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
  googlesheets:
    type: sse
    url: https://mcp.composio.dev/googlesheets/some-endpoint
    requiresOAuth: true
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-API-Key: '${SOME_API_KEY}'
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
    # The “wrench” icon shows up if no icon is provided as it is the default rendering.
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-server:
    type: streamable-http
    url: https://example.com/api/
    proxy: '${MCP_PROXY_URL}'
  per-user-credentials-example:
    type: streamable-http
    url: 'https://example.com/api/'
    headers:
      X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    customUserVars:
      MY_SERVICE_API_KEY:
        title: 'My Service API Key'
        description: "Enter your personal API key for the service. You can generate one at <a href='https://myservice.example.com/developer/keys' target='_blank'>Service Developer Portal</a>."
        sensitive: true
      MY_SERVICE_PROJECT:
        title: 'Project ID'
        description: 'Enter the project ID used by this service.'
        sensitive: false
  oauth-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      authorization_url: https://example.com/oauth/authorize
      token_url: https://example.com/oauth/token
      client_id: your_client_id
      client_secret: your_client_secret
      redirect_uri: http://localhost:3080/api/mcp/oauth-example/oauth/callback
      scope: 'read execute'
  obo-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    obo:
      scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
```

<Callout type="warning" title="프로세스 기반 서버는 운영자가 소유합니다">
  `type: stdio`를 사용하거나 `command`, `args`, `env`, `cwd` 또는 `stderr`와 같은 프로세스 필드를 사용하는 MCP 서버는 `librechat.yaml`에서 구성해야 합니다. 관리자 구성 API는 프로세스 기반 항목을 거부하며, 데이터베이스 또는 주체별(per-principal) 재정의를 통해 기존 프로세스 기반 서버를 대체하거나 제거할 수 없습니다. 원격 MCP 서버는 기존의 일반적인 구성 재정의 우선순위를 따릅니다.
</Callout>

</Callout>

#### `title` [#title]

- **유형:** 문자열 (선택 사항)
- **설명:** UI에서 MCP 서버에 표시될 사용자 지정 이름입니다. 지정하지 않으면 서버 키 이름이 사용됩니다.
- **유효성 검사:** 유니코드 문자 또는 숫자로 시작해야 합니다. 나머지 문자에는 유니코드 문자, 숫자, 결합 표시, 공백, 하이픈, 직선 또는 곡선 아포스트로피가 포함될 수 있습니다.
- **예시:**
  ```yaml
  my-server:
    title: 'File System Access'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `description` [#description]

- **유형:** 문자열 (선택 사항)
- **Description:** MCP 서버에 대한 설명으로, 사용자가 해당 서버의 목적과 기능을 이해할 수 있도록 UI에 표시됩니다.
- **예시:**
  ```yaml
  my-server:
    title: 'File System Access'
    description: 'Provides read/write access to local files and directories'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `type` [#type]

- **유형:** String
- **설명:** MCP 서버에 대한 연결 유형을 지정합니다. 유효한 옵션은 `"stdio"`, `"websocket"`, `"streamable-http"`, 또는 `"sse"`입니다. `"http"`는 `"streamable-http"`의 별칭으로 허용됩니다.
- **기본값:** `url` 또는 `command`의 존재 여부와 형식에 따라 결정됩니다.

#### `command` [#command]

- **유형:** String
- **설명:** (`stdio` 유형의 경우) MCP 서버를 시작하기 위해 실행할 명령어 또는 실행 파일입니다.

#### `args` [#args]

- **유형:** 문자열 배열
- **설명:** (`stdio` 유형의 경우) `command`에 전달할 명령줄 인수입니다. `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}`, `{{CUSTOM_VARIABLE_NAME}}`과 같은 플레이스홀더는 `env`와 마찬가지로 각 인수에서 확인(해석)됩니다.

#### `url` [#url]

- **유형:** String
- **설명:** (`websocket`, `streamable-http` 또는 `sse` 유형의 경우) MCP 서버에 연결하기 위한 URL입니다. 동적 사용자 필드 플레이스홀더(`{{LIBRECHAT_USER_*}}`) 및 환경 변수 치환(`${ENV_VAR}`)을 지원합니다.
- **참고:**
  - `sse` 유형의 경우, URL은 `http://` 또는 `https://`로 시작해야 합니다.
  - `streamable-http` 유형의 경우, URL은 반드시 `http://` 또는 `https://`로 시작해야 합니다.
  - `websocket` 유형의 경우, URL은 `ws://` 또는 `wss://`로 시작해야 합니다.

#### `proxy` [#proxy]

- **유형:** 문자열 (선택 사항, `sse` 및 `streamable-http` 유형의 경우)
- **설명:** 이 원격 MCP 서버를 위한 아웃바운드 프록시 URL입니다. 값은 `${ENV_VAR}`을 사용하여 환경 변수를 참조할 수 있습니다.
- **지원되는 프로토콜:** `http://`, `https://`, `socks://`, 및 `socks5://`
- **보안 참고:** `proxy`는 관리자가 제어합니다. 환경 변수는 해석하지만, `{{LIBRECHAT_USER_ID}}`나 `customUserVars`와 같이 사용자가 제어하는 플레이스홀더는 해석하지 않습니다.
- **예시:**
  ```yaml
  mcpServers:
    remote-api:
      type: streamable-http
      url: https://api.example.com/mcp
      proxy: '${MCP_PROXY_URL}'
  ```

#### `headers` [#headers]

- **유형:** Object (선택 사항, `sse` 및 `streamable-http` 유형의 경우)
- **설명:** 요청과 함께 전송할 사용자 지정 헤더입니다. 동적 값 대체를 위한 다양한 플레이스홀더 유형을 지원합니다.
- **Placeholder 지원:**
  - `{{LIBRECHAT_USER_ID}}`: 현재 사용자의 ID로 대체되어 다중 사용자 지원을 활성화합니다.
  - `{{LIBRECHAT_USER_*}}`: 동적 사용자 필드 플레이스홀더입니다. `*`를 허용된 필드의 대문자 버전으로 바꾸십시오.
  - `{{LIBRECHAT_OPENID_*}}`: YAML로 정의된 서버를 위한 OpenID 토큰/세션 플레이스홀더입니다.
  - `{{LIBRECHAT_GRAPH_*}}`: YAML로 정의된 서버를 위한 Microsoft Graph 토큰 플레이스홀더입니다.
  - `{{LIBRECHAT_BODY_*}}`: YAML로 정의된 서버를 위한 요청 본문(request body) 플레이스홀더로, 현재의 `conversationId`, `parentMessageId` 또는 `messageId` 등이 포함됩니다.
  - `{{CUSTOM_VARIABLE_NAME}}`: `customUserVars`에 정의된 변수에 대해 사용자가 제공한 값으로 대체됩니다 (예: `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: 환경 변수 `ENV_VAR`의 값으로 대체됩니다.

`{{LIBRECHAT_BODY_*}}` 플레이스홀더는 요청 범위(request-scoped)로 지정됩니다. LibreChat은 활성 실행(active run)을 위해 MCP 연결을 생성하고, 해당 실행 내의 도구 호출 전반에서 이를 재사용하며, 요청이 종료되면 연결을 정리합니다. 요청 범위 서버는 영구 도구 캐시에서 제외되므로, 요청별 헤더와 URL이 활성 실행 외부에서 재사용되지 않습니다. Agent Builder는 하나의 런타임 도구 선택을 통해 전체 서버를 연결하며, 실행이 본문 값을 제공한 후에 도구를 확인합니다. OAuth를 완료하면 권한 부여가 저장되지만, 해당 요청 컨텍스트가 존재할 때까지 연결이 지연됩니다. `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}` 플레이스홀더는 여전히 서버를 사용자 범위(user-scoped)로 만들지만, HTTP 전송은 각 도구 호출 전에 확인된 헤더를 새로 고치며 자체적으로 재연결을 강제하지는 않습니다.

`{{LIBRECHAT_BODY_PARENTMESSAGEID}}`는 네이티브 Agent 채팅, OpenAI 호환 Agents API 요청, 그리고 레거시 Assistants 실행에서 루트 턴(root-turn) 부모 메시지를 수신합니다. Open Responses 요청에는 호환되는 부모 메시지 모델이 없으므로, 이 플레이스홀더를 요구하는 서버는 해당 인터페이스에서 실패하며 `previous_response_id`로 대체되지 않습니다.

OpenID 액세스 토큰과 ID 토큰은 독립적으로 만료됩니다. `{{LIBRECHAT_OPENID_ACCESS_TOKEN}}` 및 레거시 `{{LIBRECHAT_OPENID_TOKEN}}`은 저장된 액세스 토큰 만료 시간을 사용하며, `{{LIBRECHAT_OPENID_ID_TOKEN}}`은 현재 유효한 ID 토큰을 필요로 합니다. 자격 증명 토큰을 사용할 수 없거나 만료된 경우, LibreChat은 빈 값이나 리터럴 bearer 값을 보내는 대신 조치 가능한 `401` 재인증 오류를 반환합니다. 재시도하기 전에 다시 로그인하십시오. OpenID ID가 없는 요청의 경우, 해결되지 않은 자격 증명 플레이스홀더를 포함하는 헤더는 완전히 생략됩니다. ID 메타데이터 플레이스홀더는 기존의 빈 값 동작을 유지합니다.

신뢰할 수 있는 운영자는 로그인한 사용자의 실시간 OpenID 액세스 토큰을 YAML로 정의된 원격 MCP 서버로 직접 전달할 수 있습니다:

```yaml
mcpServers:
  trusted-api:
    type: streamable-http
    url: https://mcp.example.com/mcp
    headers:
      Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'
```

MCP 서버가 사용자의 업스트림 액세스 토큰을 수신할 수 있도록 신뢰할 수 있는 경우에만 직접 패스스루(direct passthrough)를 사용하십시오. 명시적 MCP OAuth, [on-behalf-of exchange](#obo) 및 관리자 API 키 인증이 이 헤더보다 우선합니다. LibreChat은 연결하기 전에 라이브 세션 토큰을 확인하며, `401` 또는 `403` 오류 발생 시 연결을 한 번 새로 고칩니다. 서버가 이미 도구 호출을 실행했을 수 있으므로 거부된 도구 호출을 자동으로 재시도하지 않습니다. 복구가 성공한 후 의도적으로 도구를 다시 시도하십시오. 토큰을 새로 고칠 수 없는 경우, 사용자는 다시 로그인해야 합니다.

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}`는 사용자의 재사용 가능한 OpenID 액세스 토큰을 on-behalf-of 흐름을 통해 Microsoft Graph 토큰으로 교환합니다. 요청되는 스코프는 [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration)에서 가져오며, 기본값은 `https://graph.microsoft.com/.default`입니다. 이 값은 사람 및 그룹 검색에 사용되는 `OPENID_GRAPH_SCOPES`와는 별개입니다.

- **예시:**
  ```yaml
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-API-Key: '${SOME_API_KEY}'
    Authorization: 'Bearer ${SOME_AUTH_TOKEN}'
  ```

#### `requestHeaders` [#requestheaders]

- **유형:** Object (선택 사항, `sse` 및 `streamable-http` 유형의 경우)
- **설명:** 헤더는 활성 채팅 요청에 대해서만 확인됩니다. `headers`와 동일한 플레이스홀더를 사용하며, `headers` 위에 병합되고, 두 객체 모두 동일한 이름을 정의할 경우 우선순위를 갖습니다.
- **Discovery 동작:** 도구 검색(Tool discovery)은 `requestHeaders`를 완전히 생략하므로, `{{LIBRECHAT_BODY_*}}`와 같이 요청 전용 값은 서버의 도구 카탈로그를 숨기지 않습니다. 활성 실행(active run)은 연결 시 이를 확인하고 전송합니다.

```yaml
requestHeaders:
  X-Conversation-ID: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
  X-Schedule-ID: '{{LIBRECHAT_BODY_SCHEDULEID}}'
```

#### `apiKey` [#apikey]

- **유형:** Object (선택 사항, `sse` 및 `streamable-http` 유형의 경우)
- **설명:** MCP 서버를 위한 API 키 인증 구성입니다. API 키 기반 인증을 구성하는 구조화된 방법을 제공합니다.
- **하위 키:**
  - `source`: 문자열 (필수) - API 키의 출처입니다. 옵션:
    - `"admin"`: API 키는 관리자가 `key`로 구성합니다.
    - `"user"`: API 키는 사용자가 UI를 통해 제공합니다
  - `key`: 문자열 - (`source: "admin"`인 경우) 모든 사용자가 공유하는 API 키 값입니다. `${ENV_VAR}` 참조를 지원합니다. `source: "admin"`인 경우 `key`를 생략하면 헤더가 전송되지 않습니다.
  - `authorization_type`: 문자열(필수) - 요청에서 API 키를 전송하는 방식입니다. 옵션:
    - `"bearer"`: `Authorization: Bearer <key>`로 전송됨
    - `"basic"`: `Authorization: Basic <key>`로 전송됨
    - `"custom"`: 사용자 지정 헤더로 전송됨 (`custom_header` 필요)
  - `custom_header`: 문자열 - (`authorization_type`이 `"custom"`일 때 사용됨) API 키에 사용할 헤더 이름입니다. 생략하면 기본값은 `X-Api-Key`입니다.
- **예시:**

  ```yaml
  # Admin-provided API key with Bearer auth
  my-server:
    type: streamable-http
    url: https://api.example.com/mcp
    apiKey:
      source: 'admin'
      key: '${MY_SERVER_API_KEY}'
      authorization_type: 'bearer'

  # User-provided API key with custom header
  another-server:
    type: sse
    url: https://api.example.com/sse
    apiKey:
      source: 'user'
      authorization_type: 'custom'
      custom_header: 'X-API-Key'
  ```

UI에서 생성하고 `apiKey.source: user`를 사용하는 공유 서버의 경우, 저장된 키는 정규화된 요청 대상에 바인딩됩니다. URL 경로 또는 쿼리, 프록시, 전송 방식, 인증 형식/헤더, 또는 구성된 OAuth 클라이언트/대상을 변경하면 사용자가 새 키를 입력해야 합니다. 동일하거나 외형만 바뀐 수정은 기존 키를 유지합니다. 기존 레거시 키는 변경되지 않은 경계에서 계속 작동합니다. 현재 선언된 자격 증명 변수만 대체할 수 있으며, `requestHeaders`에서도 마찬가지입니다. 주입된 이전 생성 이름은 해당 키를 재사용할 수 없습니다. 구성 작성자를 포함한 **모든 API 복제본**에서 업그레이드를 완료하세요. 사용자에게 표시되는 내용은 [UI에서 서버 생성하기](/docs/features/mcp#create-a-server-from-the-ui)를 참조하세요.

#### `iconPath` [#iconpath]

- **유형:** 문자열 (선택 사항)
- **설명:** 도구 선택 대화 상자에 표시되는 도구의 아이콘을 정의합니다.

#### `chatMenu` [#chatmenu]

- **유형:** Boolean (선택 사항)
- **설명:** `false`로 설정하면 해당 서버는 채팅 입력창의 **MCP Servers** 섹션에서 제외되며, 해당 서버를 지정한 채팅 요청은 거부됩니다. 에이전트는 여전히 이 서버를 사용할 수 있으며, 이 서버를 목록에 포함한 모델 사양(Model Specs)도 계속 사용할 수 있습니다.
- **기본값:** `true`
- **예시:**
  ```yaml
  mcpServers:
    internal-tools:
      command: npx
      args: ['-y', 'internal-mcp-server']
      chatMenu: false # only available in the Agent Builder
  ```

#### `serverInstructions` [#serverinstructions]

- **유형:** Boolean 또는 String (선택 사항)
- **설명:** MCP 서버 지침이 에이전트 컨텍스트에 주입되는 방식을 제어합니다. 서버 지침은 개별 도구 설명을 보완하며, 전체 MCP 서버에 대한 상위 수준의 사용 지침을 제공합니다.
- **옵션:**
  - **`undefined`** (기본값): 지침이 포함되지 않습니다.
  - **`true`**: 서버에서 제공하는 지침을 사용합니다(사용 가능한 경우). 포괄적인 가이드를 갖춘 잘 문서화된 서버에 이상적입니다.
  - **`false`**: 지침을 명시적으로 비활성화합니다. 컨텍스트 토큰을 절약하거나 도구가 자체적으로 설명 가능한 경우에 유용합니다.
  - **`string`**: 사용자 지정 지침(서버 제공 지침을 재정의함)을 사용합니다. 애플리케이션별 워크플로우나 서버 지침이 충분하지 않을 때 가장 적합합니다.
- **기본값:** `undefined` (지침 포함 안 됨)
- **참고:**
  - `serverInstructions`가 구성되어 있고 서버의 도구를 에이전트가 사용할 수 있을 때 지침이 자동으로 주입됩니다.
  - 여러 서버가 각각 에이전트 컨텍스트에 지침을 제공할 수 있습니다.
  - LibreChat은 서버에서 광고하는 텍스트를 구성된 선언과 별도로 저장합니다. 검사(Inspection)는 `true`나 운영자가 작성한 문자열을 대체하지 않으며, 이전 빌드에서 생성된 Redis 기반 레지스트리 항목은 초기화 중에 자동으로 새로 고쳐집니다.
- **예시:**

  ```yaml
  # Use server-provided instructions
  serverInstructions: true

  # Use custom instructions
  serverInstructions: |
    When using this filesystem server:
    1. Always use absolute paths for file operations
    2. Check file permissions before attempting write operations

  # Explicitly disable instructions
  serverInstructions: false
  ```

#### `env` [#env]

- **유형:** 객체 (선택 사항, `stdio` 유형만 해당)
- **설명:** 프로세스를 생성할 때 사용할 환경 변수입니다.
- **Placeholder 지원:**
  - `{{LIBRECHAT_USER_ID}}`: 현재 사용자의 ID로 대체됩니다.
  - `{{LIBRECHAT_USER_*}}`: 동적 사용자 필드 플레이스홀더 (예: `{{LIBRECHAT_USER_EMAIL}}`).
  - `{{CUSTOM_VARIABLE_NAME}}`: `customUserVars`에 정의된 변수에 대해 사용자가 제공한 값으로 대체됩니다 (예: `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: 서버 측 환경 변수 `ENV_VAR`의 값으로 대체됩니다.

#### `timeout` [#timeout]

- **유형:** 정수 (선택 사항)
- **설명:** MCP 서버 요청(도구 호출 포함)의 타임아웃 시간(밀리초 단위)입니다. 0 이상의 정수여야 합니다.
- **기본값:** `60000` (60초)
- **참고:** 긴 도구 호출이 여전히 중간에 끊긴다면, LibreChat 또는 MCP 서버 앞에 있는 리버스 프록시(nginx, Traefik 등)의 타임아웃 설정을 확인하세요.
- **예시:**
  ```yaml
  mcpServers:
    data-processor:
      type: streamable-http
      url: https://api.example.com/mcp
      initTimeout: 15000 # 15 seconds to connect
      timeout: 60000 # 60 seconds per tool call
  ```

#### `initTimeout` [#inittimeout]

- **유형:** 정수 (선택 사항)
- **설명:** MCP 서버 초기화를 위한 제한 시간(밀리초 단위)입니다. 0 이상의 정수여야 합니다. 사용자가 OAuth 로그인을 완료할 수 있는 시간을 제한하지는 않으며, 이는 `MCP_OAUTH_HANDLING_TIMEOUT`에서 설정합니다(자세한 내용은 [OAuth 콜백 URL](#oauth-callback-url) 참조).
- **기본값:** `30000` (30초)

#### `requiresOAuth` [#requiresoauth]

- **유형:** Boolean (선택 사항, 원격 전송 전용: `sse`, `streamable-http`, `websocket`)
- **설명:** 이 서버가 OAuth 인증을 요구하는지 여부입니다. 지정하지 않으면 서버 시작 중에 자동으로 감지됩니다. 선택 사항이지만, 서버가 OAuth를 요구하는지 여부를 알고 있다면 이 값을 명시적으로 설정하는 것이 가장 좋습니다.
- **기본값:** 지정되지 않은 경우 자동 감지됨
- **참고:**
  - 원격(URL 기반) 전송 방식인 `sse`, `streamable-http`, `websocket`에 적용됩니다. 인증할 URL이 없는 `stdio` 서버에는 아무런 영향을 미치지 않습니다.
  - 자동 감지는 서버 시작 중에 발생하며, 이로 인해 초기화 시간이 추가될 수 있습니다.
  - 명시적 구성은 감지 단계를 건너뛰어 시작 성능을 향상시킵니다.
  - 정적 `Authorization` 헤더(예: Bearer API 키)로만 보호되는 서버의 경우 `requiresOAuth: false`로 설정하세요. 자동 감지 기능은 구성된 헤더 *없이* 서버를 프로브(probe)하므로, `WWW-Authenticate: Bearer` 챌린지와 함께 `401` 응답을 반환하는 서버는 OAuth 보호 서버로 잘못 분류될 수 있습니다. 이 플래그는 해당 프로브를 우회하여 정적 헤더가 연결을 정상적으로 인증할 수 있도록 합니다.
  - 향상된 연결 관리를 위해 MCP OAuth 환경 변수(`MCP_OAUTH_ON_AUTH_ERROR`, `MCP_OAUTH_DETECTION_TIMEOUT`, `MCP_OAUTH_HANDLING_TIMEOUT`, `MCP_OAUTH_FLOW_TTL`)와 함께 작동합니다.

#### OAuth 새로 고침 조정 [#oauth-refresh-coordination]

다중 레플리카 배포에서 `oauthRefreshCoordination: true`는 공유 Redis 인스턴스를 통해 토큰 갱신을 직렬화합니다. `oauthRefreshWaitTimeout`은 레플리카가 갱신 결과를 기다리는 시간을 제어하고, `oauthPersistenceWaitTimeout`은 갱신된 자격 증명을 읽을 수 있을 때까지 기다리는 시간을 제어합니다. 두 값의 기본값은 모두 `15000`밀리초입니다. `oauthRefreshWaitTimeout`은 최대 `30000`으로 제한되며, `oauthPersistenceWaitTimeout`은 최대 `840000`(14분)까지 허용됩니다.

모든 복제본이 업그레이드되고 동일한 Redis 배포에 연결된 후에만 조정을 활성화하십시오. 모든 복제본에서 동일한 값을 사용하고, 설정을 변경하기 전에 활성 요청을 비우며, 롤링 배포 중에 이 설정을 전환하지 마십시오.

#### `stderr` [#stderr]

- **유형:** 문자열 또는 정수 (선택 사항, `stdio` 유형만 해당)
- **설명:** 자식 프로세스의 `stderr`를 처리하는 방법입니다. 이는 Node의 [`child_process.spawn`](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options) 의미론과 일치합니다. 유효한 문자열 값: `"pipe"`, `"ignore"`, `"inherit"`. 또는 음수가 아닌 정수를 파일 디스크립터로 사용할 수 있습니다.
- **기본값:** `"inherit"` ( `stderr`로 전송되는 메시지는 부모 프로세스의 `stderr`로 출력됩니다).

#### `customUserVars` [#customuservars]

- **유형:** 객체 (선택 사항)
- **설명:** 이 MCP 서버에 대해 사용자가 설정할 수 있는 사용자 지정 변수를 정의합니다. 이를 통해 관리자는 각 사용자가 개별적으로 구성해야 하는 변수(예: API 키, URL)를 지정할 수 있습니다. 이렇게 사용자가 제공한 값은 `headers` 또는 `env` 구성에서 사용할 수 있습니다. `customUserVars`가 있는 서버는 앱 수준 연결에서 자동으로 제외되므로, 사용자별 자격 증명이 항상 런타임에 해결되도록 보장합니다.
- **구조:**
  - `customUserVars` 객체는 키를 포함하며, 각 키는 변수 이름(예: `MY_API_KEY`)을 나타냅니다. 이 이름은 `{{MY_API_KEY}}`와 같은 플레이스홀더에 사용됩니다.
  - 각 변수 이름은 다음 하위 키를 포함하는 객체입니다:
    - `title`: String (Required) - 구성 UI에 표시되는 변수의 사용자 친화적인 제목입니다.
    - `description`: 문자열 (필수) - 해당 변수에 대한 설명 또는 지침으로, UI에도 표시되어 사용자를 안내합니다. 이 필드에서는 HTML을 사용할 수 있습니다 (예: 링크 생성: `<a href="https://example.com" target="_blank">More info</a>`).
    - `sensitive`: Boolean (선택 사항) - 값이 비밀로 취급되어 UI에서 마스킹될지 여부를 제어합니다. 생략 시 기본적으로 마스킹/비밀 처리되며, 프로젝트 ID나 기본 URL과 같이 비밀이 아닌 필드의 경우 `false`로 설정하십시오.
- **`headers` 및 `env`에서의 사용법:**
  - `customUserVars` 아래에 정의된 변수는 `{{VARIABLE_NAME}}` 구문을 사용하여 `headers` (`sse` 및 `streamable-http` 유형의 경우) 또는 `env` (`stdio` 유형의 경우) 섹션에서 참조할 수 있습니다.
  - 사용자는 서버에 처음 연결할 때 이 값을 입력하며, 이후 채팅 입력창의 **Configure** 또는 **MCP Settings**에서 언제든지 변경할 수 있습니다. [Credentials and variables](/docs/features/mcp#credentials-and-variables)를 참조하세요.
  - 이 사용자 제공 값은 사용자별, MCP 서버별로 저장되며 런타임에 대체됩니다.
  - 변수가 LibreChat 시작 시 사용할 수 없는 경우(예: GitHub 개인 액세스 토큰), [`startup: false`](#startup)를 설정하면 사용자가 연결을 요청할 때까지 LibreChat이 연결을 시도하지 않도록 할 수도 있습니다.
- **예시:**
  ```yaml
  customUserVars:
    MY_SERVICE_API_KEY:
      title: 'My Service API Key'
      description: "Your personal API access key for My Service. Find it at <a href='https://myservice.example.com/settings/api' target='_blank'>My Service API Settings</a>."
      sensitive: true
    SOME_OTHER_VAR:
      title: 'Some Other Variable'
      description: 'The specific value for some other configuration (e.g., a specific path or identifier).'
      sensitive: false
  ```
  `headers`에서의 사용법:
  ```yaml
  headers:
    X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    X-Some-Other-Config: '{{SOME_OTHER_VAR}}'
  ```
  `env`에서의 사용법 (`stdio` 유형의 경우):
  ```yaml
  env:
    API_KEY: '{{MY_SERVICE_API_KEY}}'
  ```

#### `obo` [#obo]

- **유형:** Object (선택 사항, `sse` 및 `streamable-http` 유형에만 해당)
- **설명:** MCP 서버를 위한 OAuth 2.0 On-Behalf-Of 토큰 교환을 구성합니다. LibreChat은 로그인한 사용자의 OpenID 액세스 토큰을 구성된 범위(scope)를 가진 위임된 다운스트림 토큰으로 교환한 다음, 해당 토큰을 `Authorization: Bearer ...` 헤더로 MCP 서버에 전달합니다.
- **필수 하위 키:**
  - `scopes`: String - 다운스트림 토큰 교환을 위해 요청된 비어 있지 않은 범위(scope)입니다.
- **유효성 검사:**
  - `obo`는 `sse` 및 `streamable-http` MCP 서버에서만 유효합니다.
  - `obo`는 `stdio` 및 `websocket` 서버에서 거부됩니다.
  - 사용자는 이 필드를 구성하기 위해 `MCP_SERVERS.CONFIGURE_OBO` 역할 권한이 필요합니다. [`interface.mcpServers.configureObo`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)를 사용하여 시드(seed)하거나 관리자 패널에서 관리할 수 있습니다.
- **사전 요구 사항:**
  - OpenID 인증은 재사용 가능한 액세스 토큰으로 구성되어야 합니다.
  - 귀하의 ID 공급자 및 다운스트림 애플리케이션은 요청된 위임된 범위를 허용해야 합니다.
- **예시:**
  ```yaml
  mcpServers:
    enterprise-tools:
      type: streamable-http
      url: https://api.example.com/mcp/
      obo:
        scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
  ```

관련 토큰 재사용 및 위임된 토큰 설정에 대해서는 [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse) 및 [SharePoint Integration](/docs/configuration/sharepoint)을 참조하세요.

#### `oauth` [#oauth]

- **유형:** 객체 (선택 사항)
- **설명:** MCP 서버 인증을 위한 OAuth2 구성입니다. 구성이 완료되면, 사용자는 MCP 서버를 사용하기 전에 OAuth 흐름을 통해 인증하라는 메시지를 받게 됩니다. 클라이언트 ID와 클라이언트 시크릿이 제공되지 않으면 동적 클라이언트 등록(DCR)이 사용됩니다.
- **Subkeys:** 모든 `oauth` 하위 키는 선택 사항입니다. 엔드포인트는 자동으로 탐색될 수 있으며, Dynamic Client Registration을 통해 클라이언트를 발급받을 수 있습니다.
  - `authorization_url`: String - OAuth 인증 엔드포인트 URL
  - `token_url`: String - OAuth 토큰 endpoint URL
  - `client_id`: String - OAuth 클라이언트 식별자
  - `client_secret`: 문자열 - OAuth 클라이언트 시크릿
  - `redirect_uri`: String - [OAuth 리디렉션 URI](#oauth-callback-url) (예: `http://localhost:3080/api/mcp/${serverName}/oauth/callback`)
  - `scope`: String - OAuth 스코프 (공백으로 구분)
- **추가 하위 키:**
  - `grant_types_supported`: 문자열 배열 - 지원되는 권한 부여 유형 (기본값: `["authorization_code", "refresh_token"]`)
  - `token_endpoint_auth_methods_supported`: 문자열 배열 - 지원되는 토큰 엔드포인트 인증 방식 (기본값: `["client_secret_basic", "client_secret_post"]`)
  - `token_exchange_method`: String - 선택 사항인 토큰 교환 재정의입니다. 클라이언트 자격 증명을 폼 인코딩된 POST 본문으로 보내려면 `default_post`를 사용하고, HTTP Basic 인증 헤더로 보내려면 `basic_auth_header`를 사용하세요. 생략할 경우, LibreChat은 공급자가 알리는 토큰 엔드포인트 인증 방법을 검색하며, 아무것도 알리지 않는 경우 기본적으로 Basic 인증을 사용합니다.
  - `response_types_supported`: 문자열 배열 - 지원되는 응답 유형 (기본값은 `["code"]`)
  - `code_challenge_methods_supported`: 문자열 배열 - 지원되는 PKCE 코드 챌린지 메서드 (기본값: `["S256", "plain"]`)
  - `skip_code_challenge_check`: Boolean - OAuth 제공자가 PKCE 지원을 알리는지 확인하는 과정을 건너뜁니다. S256을 지원하지만 메타데이터에서 이를 알리지 않는 AWS Cognito와 같은 제공자에게 유용합니다. (기본값: `false`)
  - `revocation_endpoint`: String - 토큰 폐기(revocation) 엔드포인트 URL입니다. 생략하면 자동으로 검색됩니다.
  - `revocation_endpoint_auth_methods_supported`: 문자열 배열 - 취소(revocation) 엔드포인트가 지원하는 인증 방법입니다. 생략하면 자동으로 검색됩니다.
  - `audience`: 문자열 - 인증 요청의 `audience` 매개변수로 전송됩니다. 요청된 경우에만 API 범위 토큰을 발급하는 Auth0와 같은 제공자에서 사용합니다. 관리자 전용이며, 사용자가 UI에서 생성한 서버에서는 거부됩니다.
  - `forward_audience_on_refresh`: Boolean - `refresh_token` 그랜트에서도 `audience`를 함께 전송할지 여부입니다. 기본값은 `true`이며, 이는 Auth0에서 필요한 설정입니다. 추가 파라미터를 거부하는 AWS Cognito와 같이 엄격한 토큰 엔드포인트를 사용하는 공급자의 경우 `false`로 설정하세요. `audience`가 설정되지 않은 경우 이 값은 무시됩니다. 관리자만 설정할 수 있습니다.
  - `send_resource_parameter`: 불리언 - RFC 8707 `resource` 파라미터를 인증 요청, 코드 교환, 그리고 refresh grant에 전송할지 여부입니다. 기본값은 `true`입니다. `resource`와 `scope`를 함께 보내면 `AADSTS9010010` 오류로 실패하는 Microsoft Entra ID v2.0과 같이 이 파라미터를 거부하는 제공자에서는 `false`로 설정하세요. 대신 API 범위 토큰을 얻으려면 `scope` 또는 `audience`를 사용하세요. 관리자 전용입니다.
- **환경 변수:** `authorization_url`, `token_url`, `redirect_uri`, `revocation_endpoint`를 포함한 YAML 정의 OAuth URL 필드는 `${ENV_VAR}` 참조를 사용할 수 있습니다. LibreChat은 URL 유효성 검사 전에 환경 값을 확인합니다. UI를 통해 제출된 사용자 관리 OAuth 엔드포인트 URL은 리터럴 URL이어야 하며 `${ENV_VAR}` 플레이스홀더는 거부됩니다.
- **예시:**

  ```yaml
  oauth-api-server:
    authorization_url: https://api.example.com/oauth/authorize
    token_url: https://api.example.com/oauth/token
    client_id: your_client_id
    client_secret: your_client_secret
    redirect_uri: http://localhost:3080/api/mcp/oauth-api-server/oauth/callback
    scope: 'read execute'
    grant_types_supported: ['authorization_code', 'refresh_token']
    token_endpoint_auth_methods_supported: ['client_secret_post']
    token_exchange_method: default_post
    response_types_supported: ['code']
    code_challenge_methods_supported: ['S256', 'plain']
  ```

  Auth0 예시:

  ```yaml
  auth0-server:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      audience: https://api.example.com
      scope: 'read:data offline_access'
  ```

`token_exchange_method`와 `token_endpoint_auth_methods_supported`가 모두 생략된 사전 구성된 클라이언트 시크릿의 경우, LibreChat은 보호된 리소스 및 인증 서버 메타데이터 검색을 위해 최대 5초까지 허용합니다. 검색된 토큰 엔드포인트가 구성된 `token_url`과 정확히 일치할 때만 광고된 기능을 사용하며, 검색 과정에서 구성된 클라이언트 자격 증명을 다른 엔드포인트로 리디렉션할 수 없습니다. 공급자가 사용 가능한 메타데이터를 게시하지 않거나 강제적인 메서드가 필요한 경우 `token_exchange_method`를 명시적으로 설정하십시오.

서버 측 OAuth 검색, 등록, 토큰 및 취소 HTTP 요청은 원래 URL이 허용되더라도 리디렉션을 따르지 **않습니다**. 리디렉션이 발생하는 경우 공급자의 최종 endpoint를 직접 구성하십시오. 사설 IP 리터럴 대상은 관리자의 신뢰할 수 있는 호스트 또는 정확한 주소 및 포트 정책에 의해 명시적으로 허용되지 않는 한 차단됩니다. 이 제한은 서버 측 OAuth HTTP 요청에 적용되며, 사용자의 브라우저가 일반적인 인증 페이지 리디렉션을 완료하는 것을 방해하지는 않습니다.

#### `oauth_headers` [#oauth_headers]

- **유형:** 객체 (선택 사항)
- **설명:** OAuth 흐름 요청에 특별히 사용되는 헤더입니다. 이 헤더들은 동적 클라이언트 등록 및 토큰 교환과 같은 OAuth 인증 중에 사용되며, 일반적인 MCP 서버 통신 중에는 전송되지 않습니다.
- **일반적인 사용 사례:**
  - `Authorization: Bearer ${DCR_API_KEY}`와 같은 동적 클라이언트 등록(dynamic client registration) 엔드포인트에 인증 추가하기
  - OAuth 흐름에 필요한 사용자 지정 공급자별 헤더 포함
  - OAuth 토큰 엔드포인트에 필요한 헤더 설정
- **플레이스홀더 지원:** 값은 `{{LIBRECHAT_USER_*}}` 플레이스홀더와 `${ENV_VAR}` 참조를 허용하며, `oauth` 아래의 문자열 필드도 마찬가지입니다.
- **`headers`와의 주요 차이점:**
  - **`headers`**: 인증이 완료된 후 일반 MCP 서버 요청과 함께 전송됩니다.
  - **`oauth_headers`**: OAuth 인증 흐름 중에만 전송됩니다
- **예시:**
  ```yaml
  oauth_headers:
    Authorization: "Bearer ${DCR_API_KEY}"
    X-Custom-Header: "custom_value"
  ```

#### `oauthPrompt` [#oauthprompt]

- **유형:** 문자열 (선택 사항)
- **설명:** 사용자가 OAuth로 보호되는 서버에 로그인하라는 요청을 받는 시점을 제어합니다.
  - `on_start`: 대화 턴이 시작될 때, 에이전트가 실행되기 전에 로그인 안내 메시지가 표시됩니다.
  - `on_use`: 턴이 프롬프트 없이 시작되며, 에이전트는 도구 검색을 통해 서버의 도구를 찾습니다. 에이전트가 서버의 도구 중 하나를 처음 호출할 때 프롬프트가 나타나고, 실행은 사용자가 로그인할 때까지 대기합니다.
- **기본값:** `on_start`
- **참고:**
  - `on_use`는 에이전트가 해당 서버에서 선택한 도구가 모두 [지연 로드](/docs/features/agents#deferred-tools)("Defer" 켜짐)로 설정된 경우에만 적용됩니다. 선택한 도구 중 하나라도 처음부터 로드되거나, 에이전트가 개별 도구가 아닌 서버 전체를 선택한 경우에는 프롬프트가 턴 시작 시점에 그대로 유지됩니다.
  - `deferred_tools` [에이전트 기능](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)이 활성화되어 있어야 합니다. `run_in_background` 기능이 활성화된 경우, 백그라운드 실행을 선택한 도구는 턴 시작 시 프롬프트를 유지합니다. 분리된 호출은 로그인을 기다릴 수 없기 때문입니다.
  - `on_use`는 선언된 [`oauthToolCatalog`](#oauthtoolcatalog)가 필요합니다. 선언되지 않은 경우, 이전에 연결한 적이 있는 사용자라도 서버는 턴 시작 시의 프롬프트를 그대로 유지합니다.
  - 선택된 모든 도구가 로그인 전에 제공된 도구 목록에 포함되어야 하며, 그렇지 않으면 프롬프트는 턴 시작 상태에 머무릅니다. 이는 선언된 카탈로그이거나, 이전 연결에서 남겨진 사용자 자신의 도구 목록입니다.
  - 오직 운영자가 구성한 서버만 해당됩니다. 즉, `librechat.yaml`에 정의되었거나 [관리자 구성 재정의](/docs/configuration/admin_panel#configuration-overrides)를 통해 추가된 서버입니다. 사용자가 UI에서 만든 서버는 턴 시작 시 프롬프트를 유지합니다. 연결 설정에 `obo`, `customUserVars`, `requestHeaders`, 또는 사용자별·요청별 플레이스홀더(`{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, `{{LIBRECHAT_BODY_*}}`)를 사용하는 서버의 경우 프롬프트는 턴 시작 시에 그대로 남아 있습니다.
  - 이 설정은 OAuth가 사전에 구성된 경우(`oauth`, `requiresOAuth: true`)든, 서버가 연결을 거부할 때 자동으로 감지된 경우든 모두 적용됩니다.
  - UI에서 사용자가 만든 서버에서는 사용할 수 없습니다.
- **예시:**
  ```yaml
  mcpServers:
    google-sheets:
      type: streamable-http
      url: https://sheets.example.com/mcp
      requiresOAuth: true
      oauthPrompt: on_use
      oauthToolCatalog:
        - name: read_sheet
          description: Read the values in a spreadsheet range
  ```

#### `oauthToolCatalog` [#oauthtoolcatalog]

- **유형:** 객체 배열 (선택 사항)
- **설명:** `oauthPrompt: on_use` 서버가 사용자 로그인 전에 도구 검색(tool search)에 제공하는 도구입니다. LibreChat은 로그인하지 않은 사용자에게 보호된 서버의 도구 목록을 가져올 수 없으므로, 운영자가 여기에 도구를 선언합니다. 이 카탈로그는 모든 사용자에게 동일하며, 어떤 사용자의 연결 상태도 다른 사용자의 에이전트가 보는 내용을 결정하지 않습니다. 사용자가 로그인하면 서버 자체의 도구 정의가 사용되며, 서버는 모든 호출을 검증합니다.
- **입력 항목:**
  - `name`: 문자열(필수) - 서버에서 도구의 이름이며, 에이전트가 이 이름으로 도구를 선택합니다.
  - `description`: 문자열(선택 사항) - 도구가 수행하는 작업을 설명하며, 도구 검색과 모델에 표시됩니다.
  - `inputSchema`: Object (선택 사항) - 도구의 매개변수입니다.
    - `type`: 반드시 `object`여야 합니다
    - `properties`: 매개변수 이름을 속성 스키마에 매핑하는 맵
    - `required`: 필수 매개변수 이름의 배열
- **속성 스키마:** 다음 키만 허용되는 JSON Schema의 제한된 부분집합:
  - `type`: `string`, `number`, `integer`, `boolean`, `object`, `array`, `null` 중 하나 또는 이들의 비어 있지 않은 목록
  - `description`: String
  - `enum`: 문자열, 숫자, 불리언 또는 `null`로 이루어진 비어 있지 않은 배열
  - `default`: 문자열, 숫자, 불리언, 또는 `null`
  - `items`: 배열의 경우 `type`, `description`, `enum`을 포함하는 객체
- **참고:**
  - 검증은 엄격합니다. 잘못 입력된 항목 키(예: `input_schema`)나 제한된 스키마 범위를 벗어난 키워드(예: `minLength`, `pattern`, `$ref`)는 무시되지 않고 설정 검증에 실패합니다.
  - 이전 연결에서 도구 목록이 남아 있는 사용자에게는 대신 그 목록이 제공됩니다. 어느 경우든 목록에는 에이전트가 서버에서 선택한 모든 도구가 포함되어야 하며, 그렇지 않으면 프롬프트는 턴 시작 상태에 머무릅니다.
  - UI에서 사용자가 만든 서버에서는 사용할 수 없습니다.
- **예시:**
  ```yaml
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
  ```

#### `startup` [#startup]

- **유형:** Boolean (선택 사항)
- **설명:** `false`로 설정하면, 이 MCP 서버는 애플리케이션 시작 시 연결되지 않습니다. 이는 연결 전에 사용자 입력이나 구성이 필요한 서버나, 서버 초기화 시점을 직접 제어하려는 경우에 유용합니다.
- **기본값:** `true`
- **예시:**
  ```yaml
  mcpServers:
    my-mcp-server:
      type: streamable-http
      url: 'https://api.example.com/mcp/'
      startup: false
  ```

### 참고 사항 [#notes]

- **유형 추론(Type Inference):**
  - `type`이 생략된 경우:
    - `url`이 지정되어 있고 `http://` 또는 `https://`로 시작하는 경우, `type`은 기본적으로 `sse`로 설정됩니다.
    - `url`이 지정되어 있고 `ws://` 또는 `wss://`로 시작하는 경우, `type`은 기본적으로 `websocket`으로 설정됩니다.
    - `command`가 지정된 경우, `type`은 기본적으로 `stdio`로 설정됩니다.
- **연결 유형:**
  - **`stdio`**: MCP 서버를 자식 프로세스로 시작하고 표준 입출력(standard input/output)을 통해 통신합니다.
  - **`websocket`**: WebSocket을 통해 외부 MCP 서버에 연결합니다.
  - **`sse`**: Server-Sent Events(SSE)를 통해 외부 MCP 서버에 연결합니다.
  - **`streamable-http`**: 스트리밍 응답을 지원하며 HTTP를 통해 외부 MCP 서버에 연결합니다.
  - `stdio`는 LibreChat 호스트에서 하나의 프로세스를 실행하며, 로컬 단일 사용자 환경에 적합합니다. `sse`는 이전 세대의 원격 전송 방식입니다. 다중 사용자 또는 프로덕션 배포에는 `streamable-http`를 사용하세요.
- **내부/로컬 주소:**
  - **중요**: 내부 IP 주소(예: `172.24.1.165`, `192.168.1.100`) 또는 로컬 도메인(예: `mcp-server`, `host.docker.internal`)을 사용하는 MCP 서버는 명시적으로 허용**해야** 합니다. 공개 대상에 대한 접근성을 유지하면서 특정 사설 host:port 서비스를 허용하려면 [`mcpSettings.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#allowedaddresses)를 사용하고, 엄격한 화이트리스트가 필요한 경우에는 [`mcpSettings.allowedDomains`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#alloweddomains)를 사용하세요.
  - 구성 세부 정보는 [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings)를 참조하세요.

## OAuth 콜백 URL [#oauth-callback-url]

서버가 OAuth를 사용하는 경우, 제공자는 다음 주소로 LibreChat에 리디렉션합니다:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>`은 `mcpServers` 아래에 있는 키입니다. 예를 들어, `DOMAIN_SERVER=https://chat.example.com`이 설정된 `salesforce`라는 서버는 `https://chat.example.com/api/mcp/salesforce/oauth/callback`을 사용합니다. 로컬 Docker 설치에서는 일반적으로 기본 주소로 `http://localhost:3080`을 사용합니다. UI에서 생성한 서버의 경우, 생성된 서버 식별자가 키를 대신하며, 서버를 생성한 후 LibreChat에 전체 **Redirect URI**가 표시됩니다.

이 정확한 URL을 OAuth 공급자에 등록하세요. `/api/oauth/callback` 또는 `/api/oauth/openid/callback`과 같은 다른 LibreChat 콜백 경로는 MCP에서 작동하지 않습니다.

제공자가 동적 클라이언트 등록을 지원하는 경우, 서버에 `oauth` 블록이 전혀 필요하지 않습니다. 사용자가 처음으로 연결할 때 LibreChat이 스스로를 클라이언트로 등록합니다:

```yaml
mcpServers:
  # No refresh tokens: users sign in again when the token expires
  paypal:
    type: sse
    url: https://mcp.paypal.com/sse
    initTimeout: 150000
  # Issues refresh tokens: LibreChat renews access automatically
  spotify:
    type: streamable-http
    url: https://mcp-spotify-oauth-example.account.workers.dev/mcp
    initTimeout: 150000
```

사용자는 로그인을 마치는 데 10분의 시간이 있으며, LibreChat은 대기 중인 인증 흐름을 15분 동안 유지합니다. 이 값은 `.env` 파일의 `MCP_OAUTH_HANDLING_TIMEOUT` 및 `MCP_OAUTH_FLOW_TTL`로 변경할 수 있습니다([MCP 환경 변수](/docs/configuration/dotenv#mcp-model-context-protocol) 참조). 흐름 TTL은 항상 처리 제한 시간보다 최소 1분 이상 길게 유지되므로, 마감 시각에 가까운 시점에 도착한 콜백도 해당 흐름을 찾을 수 있습니다.

## UI에서 생성된 서버 [#servers-created-in-the-ui]

`CREATE` 권한이 있는 사용자(자세한 내용은 [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) 참조)는 이 파일을 수정하지 않고도 **MCP Settings**에서 서버를 추가할 수 있습니다. 이렇게 추가된 서버는 데이터베이스에 저장되며, YAML에 정의된 서버와 몇 가지 점에서 차이가 있습니다:

- 원격 전송 방식(`streamable-http` 및 `sse`)만 사용할 수 있습니다. `stdio` 서버는 여기에서 정의해야 합니다.
- `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, `{{LIBRECHAT_BODY_*}}` 플레이스홀더는 서버가 다른 사용자와 공유될 수 있으므로 헤더에서 제거됩니다. `customUserVars` 플레이스홀더만 유지됩니다.
- OAuth 엔드포인트 URL은 리터럴 URL이어야 하며, `${ENV_VAR}` 참조는 거부됩니다.
- 사용자마다 직접 입력하는 API 키를 선택하면 `customUserVars` 항목이 `MCP_API_KEY_<hash>` 이름으로 생성되고, 이에 대응하는 헤더가 함께 설정됩니다. 이 변경 이전에 저장된 서버는 URL이나 인증 방식이 변경되기 전까지 기존 `MCP_API_KEY` 이름을 그대로 유지할 수 있습니다. 어떤 수정이 사용자에게 키를 다시 입력하도록 요구하는지는 [`apiKey`](#apikey)를 참고하세요.
- API 키(공유 또는 사용자별)가 설정된 서버는 API 키 인증 방식으로 처리되며, OAuth 구성이 함께 있지 않은 한 OAuth 자동 감지를 건너뜁니다. 이전 버전에서 저장된 API 키 서버가 여전히 **Needs Auth** 상태로 남아 있다면, 한 번 편집하고 저장하여 저장된 메타데이터를 새로 고치세요.
- 저장된 OAuth 클라이언트와 토큰은 서버 URL과 OAuth 클라이언트 및 엔드포인트 설정에 연결됩니다. 이러한 설정을 변경하면 사용자는 다시 로그인해야 하며, URL, 클라이언트 ID, 인증 URL, 토큰 URL 또는 토큰 교환 방식을 변경할 때 편집자는 저장된 클라이언트 시크릿을 다시 입력해야 합니다.
- `oauthPrompt` 및 `oauthToolCatalog`는 사용할 수 없습니다.
- [`mcpSettings`](/docs/configuration/librechat_yaml/object_structure/mcp_settings) 도메인 및 주소 제한이 적용됩니다.
- 새로 추가하거나 수정한 서버는 재시작 없이 바로 적용됩니다. OAuth 서버는 사용자가 로그인할 때까지 연결되지 않은 상태로 저장됩니다.

전체 플레이스홀더 세트를 사용하려면 `librechat.yaml`에서 서버를 정의하세요.

## 서버 찾기 [#finding-servers]

[Smithery](https://smithery.ai)는 공개 MCP 서버 목록을 제공합니다. 서버 페이지의 **Connect** 섹션에서 `librechat.yaml`에 항목을 기록하는 LibreChat 클라이언트용 설치 명령어를 생성할 수 있습니다. 이후 LibreChat을 재시작하세요. 특정 서버 설정 방법은 [MCP Servers 가이드](/docs/mcp_servers)를 참고하세요.

## 예시 [#examples]

### 내부 주소를 사용한 구성 [#configuration-with-internal-addresses]

내부/로컬 MCP 서버를 사용하고 엄격한 도메인 화이트리스트가 필요하지 않은 경우, `mcpSettings.allowedAddresses`를 정확한 호스트 및 포트로 구성하세요:

```yaml filename="Complete MCP Configuration with Internal Servers"
# MCP Settings - Required for internal/local addresses
mcpSettings:
  allowedAddresses:
    - '172.24.1.165:8000' # Internal IP and port
    - 'mcp-prod:8001' # Docker container and port
    - 'host.docker.internal:8080' # Docker host and port

# MCP Servers - Individual configurations
mcpServers:
  prod-mcp:
    type: streamable-http
    url: http://172.24.1.165:8000/mcp
    timeout: 120000

  test-mcp:
    type: streamable-http
    url: http://mcp-prod:8001/mcp
    timeout: 120000
```

puppeteer:

    USER_ROLE: '{{LIBRECHAT_USER_ROLE}}'

```

  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-Email-Verified: '{{LIBRECHAT_USER_EMAILVERIFIED}}'
    Authorization: 'Bearer ${API_TOKEN}'
```

### `customUserVars`를 통한 사용자별 자격 증명이 포함된 MCP Server [#mcp-server-with-per-user-credentials-via-customuservars]

```yaml filename="MCP Server with customUserVars"
my-mcp-server:
  type: streamable-http
  url: 'https://api.example-service.com/api/' # Example URL
  headers:
    X-Auth-Token: '{{API_KEY}}' # Uses the API_KEY defined below
  customUserVars:
    API_KEY: # This key will be used as {{API_KEY}} in headers/url
      title: 'API Key' # This is the label shown above the input field
      description: "Get your API key <a href='https://example.com/api-keys' target='_blank'>here</a>." # This description appears below the input
```

[Credentials and variables](/docs/features/mcp#credentials-and-variables)에서 `customUserVars`를 사용해 서버를 연결할 때 사용자에게 표시되는 내용을 확인하세요.

### 첫 번째 도구 사용 시 OAuth 로그인이 필요한 MCP 서버 [#mcp-server-with-oauth-sign-in-on-first-tool-use]

```yaml filename="MCP Server with oauthPrompt: on_use"
google-sheets:
  type: streamable-http
  url: https://sheets.example.com/mcp
  requiresOAuth: true
  # Ask users to sign in when the agent first calls one of this server's tools.
  # Every tool the agent selects from this server must be deferred.
  oauthPrompt: on_use
  # Offered to tool search until a user signs in; without it the turn-start prompt is kept.
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
```

`mcpServers` 구성을 통해 LibreChat은 다양한 MCP 서버와 동적으로 상호작용할 수 있으며, 이를 통해 애플리케이션 내에서 전문화된 작업을 수행하거나 특정 기능을 제공할 수 있습니다. 이러한 모듈식 접근 방식은 서버 구성을 간단히 추가하거나 수정함으로써 애플리케이션의 기능을 쉽게 확장할 수 있도록 합니다.

## 추가 정보 [#additional-information]

- **기본 동작:**
  - `librechat.yaml`에 정의된 서버는 시작 시 초기화되므로, 이 파일을 변경하면 재시작이 필요합니다. UI에서 생성한 서버는 그렇지 않습니다.
  - 서버가 실행 중에 도구를 추가하거나 제거할 수 있는 경우 `notifications/tools/list_changed`를 전송하며, LibreChat은 재시작 없이 활성 연결에서 도구 목록을 다시 가져옵니다.
  - 사용자가 도구 호출 중에 **중지**를 누르면 LibreChat은 MCP 요청을 취소합니다. Streamable HTTP 서버는 `notifications/cancelled`를 수신하며, 자체 작업을 중단하려면 이를 반드시 처리해야 합니다. 백그라운드에서 실행 중인 도구 호출은 취소되지 않습니다.
  - `url`과 `command`가 모두 지정된 경우, 모호함을 피하기 위해 `type`을 명시적으로 정의해야 합니다.
- **다중 사용자 지원:**
  - MCPManager는 이제 사용자 수준 및 앱 수준의 개별 연결을 지원하여, 사용자별로 적절한 연결 관리가 가능해졌습니다.
  - 사용자 연결은 별도로 추적 및 관리되며, 적절한 설정과 정리 과정이 수행됩니다.
  - Redis가 활성화되면 OAuth 흐름 상태와 MCP 도구 카탈로그가 Redis Cluster 배포를 포함한 여러 레플리카 간에 공유됩니다. 레플리카 간 토큰 갱신에 대해서는 [OAuth refresh coordination](#oauth-refresh-coordination)을 참조하십시오.
  - 헤더, URL 및 환경 변수에서 동적 사용자 필드 플레이스홀더를 사용하세요:
    - `{{LIBRECHAT_USER_ID}}` - 사용자의 고유 식별자
    - `{{LIBRECHAT_USER_EMAIL}}` - 사용자의 이메일 주소
    - `{{LIBRECHAT_USER_USERNAME}}` - 사용자의 사용자 이름
    - `{{LIBRECHAT_USER_ROLE}}` - 사용자의 역할 (예: "user", "admin")
    - 그리고 더 많은 필드들 (전체 목록은 헤더 섹션 참조)
- **사용자 유휴 상태 관리:**
  - 사용자 연결은 활동이 모니터링되며, 15분 동안 활동이 없으면 연결이 끊어집니다. 이 값은 `MCP_USER_CONNECTION_IDLE_TIMEOUT`(밀리초 단위)으로 변경할 수 있습니다.
- **환경 변수:**
  - **`env` 내 ( `stdio` 유형의 경우):** MCP 서버 프로세스에 필요한 특정 런타임 환경이나 구성을 설정하는 데 유용합니다.
  - **`headers` 내 ( `sse` 및 `streamable-http` 유형의 경우):** 헤더 값에서 환경 변수를 참조하려면 `${ENV_VAR}` 구문을 사용하세요.
- **동적 사용자 필드(Dynamic User Fields):**
  - 사용자 필드 플레이스홀더는 런타임에 인증된 사용자의 정보로 대체됩니다.
  - 민감하지 않은 필드만 사용할 수 있습니다 (비밀번호 및 기타 민감한 데이터는 제외됨)
  - 누락된 필드는 기본적으로 빈 문자열로 설정됩니다.
  - Boolean 필드는 문자열 표현("true" 또는 "false")으로 변환됩니다.
- **오류 처리 (`stderr`):**
  - `stderr`를 구성하면 MCP 서버 프로세스에서 발생하는 오류 메시지를 처리하는 방법을 관리할 수 있습니다. 기본값인 `"inherit"`은 오류가 부모 프로세스의 `stderr`로 출력됨을 의미합니다.
- **Server Instructions:**
  - MCP 서버 도구가 사용될 때 지침이 에이전트의 시스템 메시지에 자동으로 삽입됩니다.
  - 사용자 지정 지침(문자열 값)이 서버에서 제공된 지침보다 우선합니다.
  - 여러 MCP 서버가 각각 자신의 지침을 에이전트 컨텍스트에 기여할 수 있습니다.
  - 지침은 해당 MCP 서버의 도구가 실제로 에이전트에게 사용 가능한 경우에만 포함됩니다.
- **OAuth 인증:**
  - MCP 서버와의 안전한 인증을 위해 OAuth2 flow가 지원됩니다.
  - MCP 서버를 사용하기 전에 사용자는 OAuth를 통해 인증하라는 메시지를 받게 됩니다.
