## Visão geral [#overview]

O objeto `ocr` permite que você configure as definições de Reconhecimento Óptico de Caracteres (OCR) para a aplicação, possibilitando a extração de texto a partir de imagens. Esta seção fornece um detalhamento da estrutura do objeto `ocr`.

Existem 5 campos em `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Notas:**

- A posição OCR só fica ativa quando o `librechat.yaml` possui uma seção `ocr`. Definir apenas `OCR_API_KEY` não a ativa. Para a API hospedada da Mistral, `strategy: "mistral_ocr"` mais `OCR_API_KEY` no `.env` é suficiente, pois `apiKey` e `baseURL` usam por padrão `${OCR_API_KEY}` e `${OCR_BASEURL}` (ou `https://api.mistral.ai/v1` quando este último não estiver definido).
- O OCR é executado em arquivos adicionados como texto: Upload as Text no chat e File Context no Agent Builder. Os agentes também precisam da capacidade `ocr` em `endpoints.agents.capabilities`, que já vem incluída por padrão. Sem ela, uma estratégia de OCR configurada rejeita o upload com a mensagem "OCR capability is not enabled for Agents".
- Quais tipos de arquivo são enviados para OCR é controlado por [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr).
- A estratégia padrão é `mistral_ocr`. Quando `mistralModel` estiver vazio, `mistral-ocr-latest` é utilizado.
- Modelos Mistral OCR implantados no Azure podem ser usados definindo a estratégia como `azure_mistral_ocr`.
- Modelos Mistral OCR implantados no Google Vertex AI podem ser usados definindo a estratégia como `vertexai_mistral_ocr`.
  - Requer que a variável de ambiente `GOOGLE_SERVICE_KEY_FILE` seja definida com as credenciais da conta de serviço
  - A service key pode ser fornecida como: caminho de arquivo, URL, JSON codificado em base64 ou string JSON bruta
  - O ID do projeto e a localização são extraídos automaticamente das credenciais da conta de serviço
- A extração de texto local está disponível através do `document_parser`, que extrai texto de arquivos PDF, DOCX, XLS/XLSX, ODT e ODS de até 15 MB, sem necessidade de qualquer API externa.
  - Usa `pdfjs-dist`, `mammoth` e `SheetJS` localmente, sem necessidade de chave de API ou URL base
  - Apenas o campo `strategy` é obrigatório; `apiKey`, `baseURL` e `mistralModel` são ignorados
- `custom_ocr` é aceito pelo schema, mas ainda não possui implementação.
- O parsing de variáveis de ambiente é suportado para os parâmetros `apiKey`, `baseURL` e `mistralModel`.

## Análise Automática de Documentos (Nenhuma Configuração Necessária) [#automatic-document-parsing-no-configuration-required]

O `document_parser` integrado é executado automaticamente para uploads de arquivos de agentes, **mesmo quando nenhum bloco `ocr` está configurado** no seu `librechat.yaml`. Isso significa que arquivos PDF, DOCX, XLS/XLSX e ODS são analisados nativamente, sem necessidade de configuração.

A lógica de resolução funciona da seguinte forma:

1. **Nenhuma configuração `ocr` existe**: quando um arquivo de contexto de agente é enviado e seu tipo MIME corresponde a um tipo de documento suportado (PDF, DOCX, Excel, ODS), o `document_parser` é usado diretamente. Nenhuma verificação de capacidade de OCR é necessária para o agente.

2. **`ocr` config exists**: A estratégia configurada (por exemplo, `mistral_ocr`) é tentada primeiro. Se a estratégia configurada **falhar em tempo de execução**, o `document_parser` é usado como fallback, para que a extração de texto ainda seja bem-sucedida nos tipos de documento suportados.

3. **Nenhuma das duas tem sucesso**: se tanto a estratégia configurada quanto o analisador de documentos falharem (por exemplo, o arquivo é um PDF somente com imagens, sem texto incorporado), é retornado um erro sugerindo que um serviço de OCR é necessário.

<Callout type="info">
O `document_parser` lida apenas com documentos baseados em texto. Para PDFs baseados em imagem ou documentos digitalizados, você ainda precisa de uma estratégia de OCR configurada (como `mistral_ocr`) para extrair texto das imagens dentro desses arquivos.
</Callout>

## Exemplo [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Exemplo com Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Exemplo com Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Para o Vertex AI, implante um modelo Mistral OCR no seu projeto do Google Cloud, crie uma conta de serviço que possa chamar o endpoint do Vertex AI e aponte `GOOGLE_SERVICE_KEY_FILE` para a chave dela. A variável aceita um caminho de arquivo, uma URL de onde a chave será obtida, JSON codificado em base64 ou a string JSON bruta:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Exemplo com o processador de documentos local (nenhuma API externa necessária):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Isenções de host:porta privados confiáveis para verificações de SSRF no momento da conexão de OCR. Destinos públicos permanecem disponíveis. As entradas exigem uma porta e não podem ser URLs, caminhos, intervalos CIDR, hosts simples ou literais de IP público.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

As solicitações de OCR bloqueiam destinos privados, loopback, link-local e de metadados de nuvem no momento da conexão e desativam redirecionamentos. `allowedAddresses` é uma lista de exceções para destinos confiáveis exatos no formato `host:port`, `private.ip:port` ou `[ipv6]:port`; ela não restringe o acesso a destinos públicos.

<Callout type="warning" title="Confie nas isenções com cuidado">
  Use `allowedAddresses` apenas para um serviço de OCR privado que você controla. Um nome de host isento confia em qualquer endereço privado para o qual ele seja resolvido nessa porta; portanto, prefira um IP privado literal quando possível. Com um proxy de encaminhamento, o proxy deve aplicar a política de SSRF de destino; destinos privados literais permanecem bloqueados, a menos que sejam explicitamente isentos.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'A estratégia de OCR a ser utilizada.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Estratégias Disponíveis:**

- `mistral_ocr`: Usa o OCR da Mistral por meio da API padrão da Mistral.
- `azure_mistral_ocr`: Usa os modelos Mistral OCR implantados no Azure AI Foundry. Defina `mistralModel` com o nome da sua implantação e `baseURL` com o endpoint da implantação.
- `vertexai_mistral_ocr`: Usa os modelos Mistral OCR implantados no Google Cloud Vertex AI, autenticados com `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Usa extração de texto local para arquivos PDF, DOCX, XLS/XLSX e OpenDocument. Nenhuma API externa é necessária. Também é executado automaticamente para uploads de arquivos de agentes quando nenhuma configuração de `ocr` está presente, e como um fallback quando uma estratégia de OCR configurada falha.
- `custom_ocr`: Reservado para um serviço de OCR personalizado em `baseURL`. Ainda não implementado.
