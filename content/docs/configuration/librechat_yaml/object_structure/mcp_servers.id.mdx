## Contoh [#example]

```yaml filename="MCP Servers Object Structure"
# Example MCP Servers Object Structure
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
  googlesheets:
    type: sse
    url: https://mcp.composio.dev/googlesheets/some-endpoint
    requiresOAuth: true
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-API-Key: '${SOME_API_KEY}'
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
    # The “wrench” icon shows up if no icon is provided as it is the default rendering.
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-server:
    type: streamable-http
    url: https://example.com/api/
    proxy: '${MCP_PROXY_URL}'
  per-user-credentials-example:
    type: streamable-http
    url: 'https://example.com/api/'
    headers:
      X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    customUserVars:
      MY_SERVICE_API_KEY:
        title: 'My Service API Key'
        description: "Enter your personal API key for the service. You can generate one at <a href='https://myservice.example.com/developer/keys' target='_blank'>Service Developer Portal</a>."
        sensitive: true
      MY_SERVICE_PROJECT:
        title: 'Project ID'
        description: 'Enter the project ID used by this service.'
        sensitive: false
  oauth-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      authorization_url: https://example.com/oauth/authorize
      token_url: https://example.com/oauth/token
      client_id: your_client_id
      client_secret: your_client_secret
      redirect_uri: http://localhost:3080/api/mcp/oauth-example/oauth/callback
      scope: 'read execute'
  obo-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    obo:
      scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
```

<Callout type="warning" title="Server yang didukung proses adalah milik operator">
  Server MCP yang menggunakan `type: stdio` atau kolom proses seperti `command`, `args`, `env`, `cwd`, atau `stderr` harus dikonfigurasi di dalam `librechat.yaml`. API konfigurasi admin akan menolak entri berbasis proses, dan database atau penggantian (override) per-principal tidak dapat menggantikan atau menghapus server berbasis proses yang sudah ada. Server MCP jarak jauh tetap mengikuti prioritas penggantian konfigurasi yang normal.
</Callout>

#### `title` [#title]

- **Tipe:** String (Opsional)
- **Deskripsi:** Nama tampilan kustom untuk server MCP di UI. Jika tidak ditentukan, nama kunci server akan digunakan.
- **Validasi:** Harus dimulai dengan huruf atau angka Unicode. Karakter sisanya dapat mencakup huruf Unicode, angka, tanda penggabung (combining marks), spasi, tanda hubung, serta apostrof lurus atau melengkung.
- **Contoh:**
  ```yaml
  my-server:
    title: 'File System Access'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `description` [#description]

- **Tipe:** String (Opsional)
- **Deskripsi:** Deskripsi server MCP, ditampilkan di UI untuk membantu pengguna memahami tujuan dan kemampuannya.
- **Contoh:**
  ```yaml
  my-server:
    title: 'File System Access'
    description: 'Provides read/write access to local files and directories'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `type` [#type]

- **Tipe:** String
- **Deskripsi:** Menentukan jenis koneksi ke server MCP. Opsi yang valid adalah `"stdio"`, `"websocket"`, `"streamable-http"`, atau `"sse"`. `"http"` diterima sebagai alias dari `"streamable-http"`.
- **Nilai Default:** Ditentukan berdasarkan keberadaan dan format `url` atau `command`.

#### `command` [#command]

- **Tipe:** String
- **Deskripsi:** (Untuk tipe `stdio`) Perintah atau executable yang dijalankan untuk memulai server MCP.

#### `args` [#args]

- **Tipe:** Larik String
- **Deskripsi:** (Untuk tipe `stdio`) Argumen baris perintah yang akan diteruskan ke `command`. Placeholder seperti `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}`, dan `{{CUSTOM_VARIABLE_NAME}}` akan diselesaikan pada setiap argumen, sama seperti pada `env`.

#### `url` [#url]

- **Tipe:** String
- **Deskripsi:** (Untuk tipe `websocket`, `streamable-http`, atau `sse`) URL untuk terhubung ke server MCP. Mendukung placeholder kolom pengguna dinamis (`{{LIBRECHAT_USER_*}}`) dan substitusi variabel lingkungan (`${ENV_VAR}`).
- **Catatan:**
  - Untuk tipe `sse`, URL harus diawali dengan `http://` atau `https://`.
  - Untuk tipe `streamable-http`, URL harus dimulai dengan `http://` atau `https://`.
  - Untuk tipe `websocket`, URL harus diawali dengan `ws://` atau `wss://`.

#### `proxy` [#proxy]

- **Tipe:** String (Opsional, untuk tipe `sse` dan `streamable-http`)
- **Deskripsi:** URL proksi keluar untuk server MCP jarak jauh ini. Nilai ini dapat merujuk pada variabel lingkungan dengan `${ENV_VAR}`.
- **Protokol yang didukung:** `http://`, `https://`, `socks://`, dan `socks5://`
- **Catatan keamanan:** `proxy` dikontrol oleh admin. Ini menyelesaikan variabel lingkungan, tetapi tidak menyelesaikan placeholder yang dikontrol pengguna seperti `{{LIBRECHAT_USER_ID}}` atau `customUserVars`.
- **Contoh:**
  ```yaml
  mcpServers:
    remote-api:
      type: streamable-http
      url: https://api.example.com/mcp
      proxy: '${MCP_PROXY_URL}'
  ```

#### `headers` [#headers]

- **Tipe:** Objek (Opsional, untuk tipe `sse` dan `streamable-http`)
- **Deskripsi:** Header kustom untuk dikirim bersama permintaan. Mendukung berbagai jenis placeholder untuk substitusi nilai dinamis.
- **Dukungan Placeholder:**
  - `{{LIBRECHAT_USER_ID}}`: Akan diganti dengan ID pengguna saat ini, yang memungkinkan dukungan multi-pengguna.
  - `{{LIBRECHAT_USER_*}}`: Placeholder kolom pengguna dinamis. Ganti `*` dengan versi HURUF BESAR dari kolom apa pun yang diizinkan.
  - `{{LIBRECHAT_OPENID_*}}`: Placeholder token/sesi OpenID untuk server yang didefinisikan dalam YAML.
  - `{{LIBRECHAT_GRAPH_*}}`: Placeholder token Microsoft Graph untuk server yang didefinisikan dalam YAML.
  - `{{LIBRECHAT_BODY_*}}`: Placeholder isi permintaan untuk server yang didefinisikan dalam YAML, seperti `conversationId`, `parentMessageId`, atau `messageId` saat ini.
  - `{{CUSTOM_VARIABLE_NAME}}`: Diganti dengan nilai yang diberikan oleh pengguna untuk variabel yang didefinisikan dalam `customUserVars` (contoh: `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: Akan diganti dengan nilai dari variabel lingkungan `ENV_VAR`.

**Placeholder Bidang Pengguna yang Tersedia:**

| Placeholder                           | User Field         | Type             | Description                                                 |
| ------------------------------------- | ------------------ | ---------------- | ----------------------------------------------------------- |
| `{{LIBRECHAT_USER_NAME}}`             | `name`             | String           | Nama tampilan pengguna                                      |
| `{{LIBRECHAT_USER_USERNAME}}`         | `username`         | String           | Nama pengguna                                               |
| `{{LIBRECHAT_USER_EMAIL}}`            | `email`            | String           | Alamat email pengguna                                       |
| `{{LIBRECHAT_USER_PROVIDER}}`         | `provider`         | String           | Penyedia autentikasi (contoh: "email", "google", "github")  |
| `{{LIBRECHAT_USER_ROLE}}`             | `role`             | String           | Peran pengguna (contoh: "user", "admin")                    |
| `{{LIBRECHAT_USER_GOOGLEID}}`         | `googleId`         | String           | ID akun Google                                              |
| `{{LIBRECHAT_USER_FACEBOOKID}}`       | `facebookId`       | String           | ID akun Facebook                                            |
| `{{LIBRECHAT_USER_OPENIDID}}`         | `openidId`         | String           | ID akun OpenID                                              |
| `{{LIBRECHAT_USER_SAMLID}}`           | `samlId`           | String           | ID akun SAML                                                |

**Catatan:** Bidang yang kosong akan diganti dengan string kosong.

Placeholder `{{LIBRECHAT_BODY_*}}` memiliki cakupan permintaan (request-scoped). LibreChat membuat koneksi MCP untuk proses yang sedang berjalan (active run), menggunakannya kembali di seluruh pemanggilan alat (tool calls) dalam proses tersebut, dan membersihkannya saat permintaan berakhir. Server dengan cakupan permintaan dikecualikan dari cache alat persisten sehingga header dan URL yang spesifik untuk permintaan tidak digunakan kembali di luar proses yang sedang berjalan. Agent Builder melampirkan server lengkap melalui satu pemilihan runtime-tools dan menyelesaikan alat-alatnya setelah proses tersebut menyediakan nilai-nilai body. Penyelesaian OAuth menyimpan otorisasi tetapi menunda koneksi hingga konteks permintaan tersebut ada. Placeholder `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, dan `{{LIBRECHAT_GRAPH_*}}` tetap membuat server memiliki cakupan pengguna (user-scoped), namun transport HTTP menyegarkan header yang telah diselesaikan sebelum setiap pemanggilan alat tanpa memaksa penyambungan ulang (reconnect) dengan sendirinya.

`{{LIBRECHAT_BODY_PARENTMESSAGEID}}` menerima pesan induk root-turn dalam obrolan Agen asli, permintaan API Agen yang kompatibel dengan OpenAI, dan eksekusi Assistants lama. Permintaan Open Responses tidak memiliki model pesan induk yang kompatibel, sehingga server yang memerlukan placeholder ini akan gagal (fail closed) pada antarmuka tersebut; `previous_response_id` tidak disubstitusikan untuknya.

Akses OpenID dan token ID kedaluwarsa secara independen. `{{LIBRECHAT_OPENID_ACCESS_TOKEN}}` dan `{{LIBRECHAT_OPENID_TOKEN}}` versi lama menggunakan masa kedaluwarsa access-token yang tersimpan, sementara `{{LIBRECHAT_OPENID_ID_TOKEN}}` memerlukan token ID yang masih berlaku. Jika token kredensial tidak tersedia atau kedaluwarsa, LibreChat akan mengembalikan error autentikasi ulang `401` yang dapat ditindaklanjuti alih-alih mengirimkan nilai bearer yang kosong atau literal; silakan masuk kembali sebelum mencoba lagi. Untuk permintaan tanpa identitas OpenID, header yang berisi salah satu placeholder kredensial yang belum terselesaikan tersebut akan dihilangkan sepenuhnya. Placeholder metadata identitas tetap mempertahankan perilaku nilai kosongnya yang sudah ada.

Operator tepercaya dapat meneruskan token akses OpenID pengguna yang sedang masuk secara langsung ke server MCP jarak jauh yang ditentukan dalam YAML:

```yaml
mcpServers:
  trusted-api:
    type: streamable-http
    url: https://mcp.example.com/mcp
    headers:
      Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'
```

Gunakan *direct passthrough* hanya jika server MCP dipercaya untuk menerima *upstream access token* pengguna. MCP OAuth eksplisit, [pertukaran on-behalf-of](#obo), dan autentikasi API-key administrator lebih diutamakan daripada header ini. LibreChat menyelesaikan *live session token* sebelum menghubungkan dan menyegarkan koneksi satu kali setelah `401` atau `403`. LibreChat tidak secara otomatis memutar ulang panggilan *tool* yang ditolak karena server mungkin telah mengeksekusinya; lakukan percobaan ulang *tool* secara sengaja setelah pemulihan berhasil. Jika token tidak dapat disegarkan, pengguna harus masuk kembali.

- **Contoh:**
  ```yaml
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-API-Key: '${SOME_API_KEY}'
    Authorization: 'Bearer ${SOME_AUTH_TOKEN}'
  ```

#### `requestHeaders` [#requestheaders]

- **Tipe:** Objek (Opsional, untuk tipe `sse` dan `streamable-http`)
- **Deskripsi:** Header hanya diselesaikan untuk permintaan obrolan yang aktif. Header ini menggunakan placeholder yang sama seperti `headers`, digabungkan di atas `headers`, dan akan diutamakan jika kedua objek mendefinisikan nama yang sama.
- **Perilaku penemuan:** Penemuan alat mengabaikan `requestHeaders` sepenuhnya, sehingga nilai khusus permintaan seperti `{{LIBRECHAT_BODY_*}}` tidak menyembunyikan katalog alat server. Eksekusi aktif akan menyelesaikan dan mengirimkannya saat terhubung.

```yaml
requestHeaders:
  X-Conversation-ID: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
  X-Schedule-ID: '{{LIBRECHAT_BODY_SCHEDULEID}}'
```

#### `apiKey` [#apikey]

- **Tipe:** Objek (Opsional, untuk tipe `sse` dan `streamable-http`)
- **Deskripsi:** Konfigurasi autentikasi kunci API untuk server MCP. Menyediakan cara terstruktur untuk mengonfigurasi autentikasi berbasis kunci API.
- **Sub-kunci:**
  - `source`: String (Wajib) - Sumber dari mana API key berasal. Opsi:
    - `"admin"`: Kunci API dikonfigurasi oleh administrator dengan `key`
    - `"user"`: Kunci API disediakan oleh pengguna melalui UI
  - `key`: String - (Untuk `source: "admin"`) Nilai API key, dibagikan oleh semua pengguna. Mendukung referensi `${ENV_VAR}`. Dengan `source: "admin"`, tidak ada header yang dikirim jika `key` dihilangkan.
  - `authorization_type`: String (Wajib) - Cara kunci API dikirim dalam permintaan. Opsi:
    - `"bearer"`: Dikirim sebagai `Authorization: Bearer <key>`
    - `"basic"`: Dikirim sebagai `Authorization: Basic <key>`
    - `"custom"`: Dikirim dalam header kustom (memerlukan `custom_header`)
  - `custom_header`: String - (Digunakan ketika `authorization_type` bernilai `"custom"`) Nama header yang akan digunakan untuk API key. Secara default menggunakan `X-Api-Key` jika tidak diisi.
- **Contoh:**

  ```yaml
  # Admin-provided API key with Bearer auth
  my-server:
    type: streamable-http
    url: https://api.example.com/mcp
    apiKey:
      source: 'admin'
      key: '${MY_SERVER_API_KEY}'
      authorization_type: 'bearer'

  # User-provided API key with custom header
  another-server:
    type: sse
    url: https://api.example.com/sse
    apiKey:
      source: 'user'
      authorization_type: 'custom'
      custom_header: 'X-API-Key'
  ```

Untuk server yang dibuat melalui UI dan dibagikan menggunakan `apiKey.source: user`, kunci yang disimpan terikat pada tujuan permintaan yang dinormalisasi. Mengubah jalur URL atau kueri, proxy, transport, format/header otorisasi, atau klien/tujuan OAuth yang dikonfigurasi mengharuskan pengguna untuk memasukkan kunci baru; pengeditan yang setara atau bersifat kosmetik akan tetap mempertahankan kunci tersebut. Kunci lama yang sudah ada akan tetap berfungsi pada batasnya yang tidak berubah. Hanya variabel kredensial yang dideklarasikan saat ini yang dapat disubstitusi, termasuk di dalam `requestHeaders`; nama yang dihasilkan lama yang disuntikkan tidak dapat menggunakan kembali kuncinya. Selesaikan peningkatan pada **setiap replika API**, termasuk penulis konfigurasi. Lihat [Credential Variables for UI-Created Servers](/docs/features/mcp#credential-variables-for-ui-created-servers) untuk alur entri kunci yang ada.

#### `iconPath` [#iconpath]

- **Tipe:** String (Opsional)
- **Deskripsi:** Menentukan ikon tampilan alat yang diperlihatkan dalam dialog pemilihan alat.

#### `chatMenu` [#chatmenu]

- **Tipe:** Boolean (Opsional)
- **Deskripsi:** Jika diatur ke `false`, server MCP akan dikecualikan dari pemilih obrolan reguler dan permintaan obrolan yang disediakan oleh pemilih. Server tersebut tetap tersedia bagi Agen yang disimpan dan Model Specs yang menetapkannya secara eksplisit.
- **Nilai Default:** `true` (Server MCP dapat dipilih dalam obrolan reguler)

#### `serverInstructions` [#serverinstructions]

- **Tipe:** Boolean atau String (Opsional)
- **Deskripsi:** Mengontrol bagaimana instruksi server MCP disuntikkan ke dalam konteks agen. Instruksi server memberikan panduan penggunaan tingkat tinggi untuk keseluruhan server MCP, melengkapi deskripsi alat individu.
- **Opsi:**
  - **`undefined`** (default): Tidak ada instruksi yang disertakan
  - **`true`**: Gunakan instruksi yang disediakan server (jika tersedia) - ideal untuk server yang terdokumentasi dengan baik dengan panduan yang komprehensif
  - **`false`**: Menonaktifkan instruksi secara eksplisit - berguna untuk menghemat token konteks atau saat alat (tools) sudah cukup jelas dengan sendirinya
  - **`string`**: Gunakan instruksi kustom (menggantikan instruksi yang disediakan server) - terbaik untuk alur kerja khusus aplikasi atau saat instruksi server tidak mencukupi
- **Nilai Default:** `undefined` (tidak ada instruksi yang disertakan)
- **Catatan:**
  - Instruksi akan disuntikkan secara otomatis saat `serverInstructions` dikonfigurasi dan alat (tools) server tersedia untuk agen tersebut
  - Beberapa server masing-masing dapat memberikan instruksi ke konteks agen
  - LibreChat menyimpan teks yang diiklankan server secara terpisah dari deklarasi yang dikonfigurasi. Inspeksi tidak menggantikan `true` atau string yang dibuat oleh operator, dan entri registri yang didukung Redis dari build sebelumnya akan diperbarui secara otomatis selama inisialisasi.
- **Contoh:**

  ```yaml
  # Use server-provided instructions
  serverInstructions: true

  # Use custom instructions
  serverInstructions: |
    When using this filesystem server:
    1. Always use absolute paths for file operations
    2. Check file permissions before attempting write operations

  # Explicitly disable instructions
  serverInstructions: false
  ```

#### `env` [#env]

- **Tipe:** Objek (Opsional, hanya tipe `stdio`)
- **Deskripsi:** Variabel lingkungan yang digunakan saat menjalankan proses.
- **Dukungan Placeholder:**
  - `{{LIBRECHAT_USER_ID}}`: Diganti dengan ID pengguna saat ini.
  - `{{LIBRECHAT_USER_*}}`: Placeholder bidang pengguna dinamis (contoh: `{{LIBRECHAT_USER_EMAIL}}`).
  - `{{CUSTOM_VARIABLE_NAME}}`: Diganti dengan nilai yang diberikan oleh pengguna untuk variabel yang didefinisikan dalam `customUserVars` (contoh: `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: Diganti dengan nilai dari variabel lingkungan sisi server `ENV_VAR`.

#### `timeout` [#timeout]

- **Tipe:** Integer (Opsional)
- **Deskripsi:** Batas waktu (timeout) dalam milidetik untuk permintaan ke server MCP. Harus berupa bilangan bulat non-negatif. Untuk koneksi `sse`, nilai yang sama juga membatasi koneksi awal, yang menunggu hingga 120000 ms (2 menit) jika `timeout` tidak diatur.
- **Nilai Default:** `60000` (60 detik)

#### `initTimeout` [#inittimeout]

- **Tipe:** Integer (Opsional)
- **Deskripsi:** Batas waktu dalam milidetik untuk inisialisasi server MCP. Harus berupa bilangan bulat non-negatif.
- **Nilai Default:** `30000` (30 detik)

#### `sseReadTimeout` [#ssereadtimeout]

- **Tipe:** Integer (Opsional, untuk tipe `sse` dan `streamable-http`)
- **Deskripsi:** Batas waktu (timeout) dalam milidetik untuk body dari stream SSE `GET` yang berumur panjang. Jika tidak ada data yang diterima dalam rentang waktu ini, stream akan dibatalkan. Nilainya harus berupa bilangan bulat positif.
- **Nilai Default:** `300000` (5 menit)

#### `requiresOAuth` [#requiresoauth]

- **Tipe:** Boolean (Opsional, hanya untuk transport jarak jauh: `sse`, `streamable-http`, `websocket`)
- **Deskripsi:** Apakah server ini memerlukan autentikasi OAuth. Jika tidak ditentukan, akan dideteksi secara otomatis selama startup server. Meskipun opsional, sebaiknya tetapkan nilai ini secara eksplisit jika Anda mengetahui apakah server tersebut memerlukan OAuth atau tidak.
- **Nilai Default:** Terdeteksi otomatis jika tidak ditentukan
- **Catatan:**
  - Berlaku untuk transport jarak jauh (berbasis URL): `sse`, `streamable-http`, dan `websocket`. Pengaturan ini tidak berpengaruh pada server `stdio`, yang tidak memiliki URL untuk proses autentikasi.
  - Deteksi otomatis terjadi selama startup server, yang dapat menambah waktu inisialisasi
  - Konfigurasi eksplisit meningkatkan performa startup dengan melewati deteksi
  - Atur `requiresOAuth: false` untuk server yang hanya dilindungi oleh header `Authorization` statis (contohnya: kunci API Bearer). Deteksi otomatis akan melakukan probe ke server _tanpa_ header yang Anda konfigurasi, sehingga server yang merespons dengan tantangan `401` dan `WWW-Authenticate: Bearer` dapat salah diklasifikasikan sebagai server yang dilindungi OAuth; flag ini akan melewati probe tersebut dan membiarkan header statis Anda mengautentikasi koneksi secara normal.
  - Bekerja dengan variabel lingkungan MCP OAuth (`MCP_OAUTH_ON_AUTH_ERROR`, `MCP_OAUTH_DETECTION_TIMEOUT`, `MCP_OAUTH_HANDLING_TIMEOUT`, `MCP_OAUTH_FLOW_TTL`) untuk manajemen koneksi yang ditingkatkan

#### Koordinasi refresh OAuth [#oauth-refresh-coordination]

Untuk deployment multi-replika, `oauthRefreshCoordination: true` memastikan proses refresh token berjalan secara berurutan melalui instance Redis bersama. `oauthRefreshWaitTimeout` mengontrol berapa lama sebuah replika menunggu hasil refresh, dan `oauthPersistenceWaitTimeout` mengontrol berapa lama replika tersebut menunggu hingga kredensial yang telah di-refresh dapat dibaca; keduanya memiliki nilai default `15000` milidetik. `oauthRefreshWaitTimeout` dibatasi hingga maksimum `30000`, sedangkan `oauthPersistenceWaitTimeout` menerima nilai paling besar `840000` (14 menit).

Aktifkan koordinasi hanya setelah setiap replika ditingkatkan dan terhubung ke deployment Redis yang sama. Gunakan nilai yang identik pada setiap replika, kosongkan permintaan aktif sebelum mengubah pengaturan, dan hindari mengubahnya selama deployment bergulir (rolling deployment).

#### `stderr` [#stderr]

- **Tipe:** String atau Integer (Opsional, hanya untuk tipe `stdio`)
- **Deskripsi:** Cara menangani `stderr` dari proses anak. Ini sesuai dengan semantik [`child_process.spawn`](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options) milik Node. Nilai string yang valid: `"pipe"`, `"ignore"`, `"inherit"`. Sebagai alternatif, bilangan bulat non-negatif dapat digunakan sebagai deskriptor file.
- **Nilai Default:** `"inherit"` (pesan ke `stderr` akan dicetak ke `stderr` proses induk).

#### `customUserVars` [#customuservars]

- **Tipe:** Objek (Opsional)
- **Deskripsi:** Mendefinisikan variabel kustom yang dapat diatur pengguna untuk server MCP ini. Hal ini memungkinkan administrator untuk menentukan variabel (misalnya, kunci API, URL) yang harus dikonfigurasi oleh setiap pengguna secara individu. Nilai yang disediakan pengguna ini kemudian dapat digunakan dalam konfigurasi `headers` atau `env`. Server dengan `customUserVars` secara otomatis dikecualikan dari koneksi tingkat aplikasi, memastikan kredensial per pengguna selalu diselesaikan pada saat runtime.
- **Struktur:**
  - Objek `customUserVars` berisi kunci-kunci, di mana setiap kunci merepresentasikan nama variabel (contohnya, `MY_API_KEY`). Nama ini akan digunakan dalam placeholder seperti `{{MY_API_KEY}}`.
  - Setiap nama variabel adalah objek dengan subkunci berikut:
    - `title`: String (Wajib) - Judul yang mudah dipahami pengguna untuk variabel tersebut, ditampilkan di UI konfigurasi.
    - `description`: String (Wajib) - Deskripsi atau instruksi untuk variabel, juga ditampilkan di UI untuk memandu pengguna. HTML dapat digunakan dalam kolom ini (misalnya, untuk membuat tautan: `<a href="https://example.com" target="_blank">More info</a>`).
    - `sensitive`: Boolean (Opsional) - Mengontrol apakah nilai tersebut diperlakukan sebagai rahasia dan disamarkan di UI. Secara default akan disamarkan/dianggap rahasia jika diabaikan; atur ke `false` untuk kolom yang bukan rahasia seperti ID proyek atau URL dasar.
- **Penggunaan dalam `headers` dan `env`:**
  - Setelah didefinisikan di bawah `customUserVars`, variabel-variabel ini dapat direferensikan di bagian `headers` (untuk tipe `sse` dan `streamable-http`) atau `env` (untuk tipe `stdio`) menggunakan sintaks `{{VARIABLE_NAME}}`.
  - Pengguna memberikan nilai-nilai ini melalui UI. Pengaturan ini dapat diakses dengan dua cara:
    - **Dari Input Obrolan**: Di bagian **MCP Servers** pada [palet **+** composer](/docs/features/composer#turn-on-tools-skills-and-mcp-servers), server yang dapat dikonfigurasi memiliki kontrol **Configure** pada barisnya. Memilihnya akan membuka dialog untuk mengelola kredensial untuk server tersebut. Memilih server yang masih memerlukan kredensial akan membuka dialog yang sama.
      <img
        src="/images/mcp/mcp_per_user_vars_assistant_dialog.png"
        alt="Konfigurasi Variabel Per-Pengguna MCP - Dialog Akses Asisten"
        width={800}
      />
    - **Dari Panel Pengaturan**: Bagian "MCP Settings" khusus di panel kanan mencantumkan semua server MCP dengan variabel kustom yang dapat ditentukan. Pengguna dapat mengeklik server untuk membuka dialog konfigurasi guna mengatur atau memperbarui kredensial mereka untuk server MCP spesifik tersebut.
      <img
        src="/images/mcp/mcp_per_user_vars_side_panel.png"
        alt="Konfigurasi Variabel Per-Pengguna MCP - Akses Panel Pengaturan"
        width={300}
      />
  - Server yang dibuat di UI hanya me-resolve variabel yang dideklarasikan di `customUserVars`. Server tersebut tidak me-resolve referensi `${ENV_VAR}` maupun placeholder `{{LIBRECHAT_USER_*}}`.
  - Nilai-nilai yang disediakan pengguna ini disimpan dengan aman, dikaitkan dengan pengguna individu dan server MCP tertentu, serta disubstitusikan pada saat runtime.
- **Contoh:**
  ```yaml
  customUserVars:
    MY_SERVICE_API_KEY:
      title: 'My Service API Key'
      description: "Your personal API access key for My Service. Find it at <a href='https://myservice.example.com/settings/api' target='_blank'>My Service API Settings</a>."
      sensitive: true
    SOME_OTHER_VAR:
      title: 'Some Other Variable'
      description: 'The specific value for some other configuration (e.g., a specific path or identifier).'
      sensitive: false
  ```
  Penggunaan dalam `headers`:
  ```yaml
  headers:
    X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    X-Some-Other-Config: '{{SOME_OTHER_VAR}}'
  ```
  Usage in `env` (for `stdio` type):
  ```yaml
  env:
    API_KEY: '{{MY_SERVICE_API_KEY}}'
  ```

#### `obo` [#obo]

- **Tipe:** Objek (Opsional, hanya untuk tipe `sse` dan `streamable-http`)
- **Deskripsi:** Mengonfigurasi pertukaran token OAuth 2.0 On-Behalf-Of untuk server MCP. LibreChat menukarkan token akses OpenID pengguna yang sedang masuk dengan token hilir (downstream) yang didelegasikan dengan cakupan (scope) yang dikonfigurasi, kemudian meneruskan token tersebut ke server MCP sebagai header `Authorization: Bearer ...`.
- **Subkey yang Diperlukan:**
  - `scopes`: String - Scope tidak kosong yang diminta untuk pertukaran token hilir (downstream).
- **Validasi:**
  - `obo` hanya valid untuk server MCP `sse` dan `streamable-http`.
  - `obo` ditolak untuk server `stdio` dan `websocket`.
  - Pengguna memerlukan izin peran `MCP_SERVERS.CONFIGURE_OBO` untuk mengonfigurasi kolom ini. Lakukan seeding dengan [`interface.mcpServers.configureObo`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) atau kelola dari panel admin.
- **Prasyarat:**
  - Autentikasi OpenID harus dikonfigurasi dengan access token yang dapat digunakan kembali.
  - Penyedia identitas dan aplikasi hilir Anda harus mengizinkan cakupan delegasi yang diminta.
- **Contoh:**
  ```yaml
  mcpServers:
    enterprise-tools:
      type: streamable-http
      url: https://api.example.com/mcp/
      obo:
        scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
  ```

Lihat [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse) dan [SharePoint Integration](/docs/configuration/sharepoint) untuk pengaturan terkait penggunaan kembali token (token-reuse) dan token yang didelegasikan.

#### `oauth` [#oauth]

- **Tipe:** Objek (Opsional)
- **Deskripsi:** Konfigurasi OAuth2 untuk autentikasi dengan server MCP. Saat dikonfigurasi, pengguna akan diminta untuk melakukan autentikasi melalui alur OAuth sebelum server MCP dapat digunakan. Jika client id & client secret tidak disediakan, Dynamic Client Registration (DCR) akan digunakan.
- **Subkey:** Semua subkey `oauth` bersifat opsional. Endpoint dapat ditemukan secara otomatis, dan client dapat diperoleh melalui Dynamic Client Registration.
  - `authorization_url`: String - URL endpoint otorisasi OAuth
  - `token_url`: String - URL endpoint token OAuth
  - `client_id`: String - Pengidentifikasi klien OAuth
  - `client_secret`: String - Rahasia klien OAuth. Memerlukan `client_id`, dan `client_id` dengan `client_secret` juga memerlukan `authorization_url` dan `token_url`.
  - `redirect_uri`: String - [URI redirect OAuth](/docs/features/mcp#oauth-callback-url). Secara default bernilai `/api/mcp/{serverName}/oauth/callback`.
  - `scope`: String - OAuth scopes (dipisahkan dengan spasi)
- **Subkunci Tambahan:**
  - `grant_types_supported`: Array of Strings - Tipe grant yang didukung (default ke `["authorization_code", "refresh_token"]`)
  - `token_endpoint_auth_methods_supported`: Array of Strings - Metode autentikasi endpoint token yang didukung (default ke `["client_secret_basic", "client_secret_post"]`)
  - `token_exchange_method`: String - Penggantian (override) pertukaran token opsional. Gunakan `default_post` untuk mengirim kredensial klien dalam body POST yang di-encode sebagai form, atau `basic_auth_header` untuk mengirimnya di dalam header otorisasi HTTP Basic. Jika dihilangkan, LibreChat akan mendeteksi metode otorisasi endpoint token yang diiklankan oleh penyedia dan secara default menggunakan Basic auth jika tidak ada yang diiklankan.
  - `response_types_supported`: Array of Strings - Tipe respons yang didukung (default ke `["code"]`)
  - `code_challenge_methods_supported`: Array of Strings - Metode code challenge PKCE yang didukung (default ke `["S256", "plain"]`)
  - `skip_code_challenge_check`: Boolean - Melewati pemeriksaan apakah penyedia OAuth mengiklankan dukungan PKCE. Berguna untuk penyedia seperti AWS Cognito yang mendukung S256 tetapi tidak mengiklankannya dalam metadata mereka. (default ke `false`)
  - `revocation_endpoint`: String - URL endpoint pencabutan token. Ditemukan secara otomatis jika dihilangkan.
  - `revocation_endpoint_auth_methods_supported`: Array of Strings - Metode autentikasi yang didukung oleh endpoint revocation. Ditemukan secara otomatis jika dihilangkan.
  - `audience`: String - Dikirim sebagai parameter `audience` pada permintaan otorisasi, untuk penyedia seperti Auth0 yang hanya menerbitkan token dengan cakupan API ketika audience diminta. Khusus admin: ditolak untuk server yang dibuat pengguna melalui UI.
  - `forward_audience_on_refresh`: Boolean - Menentukan apakah `audience` juga dikirim pada grant `refresh_token`. Nilai default-nya adalah `true`, yang diperlukan oleh Auth0. Atur ke `false` untuk penyedia dengan endpoint token yang ketat, seperti AWS Cognito, yang menolak parameter tambahan tersebut. Diabaikan jika `audience` tidak diatur. Hanya untuk admin.
  - `send_resource_parameter`: Boolean - Menentukan apakah parameter `resource` RFC 8707 dikirim pada permintaan otorisasi, pertukaran kode, dan refresh grant. Nilai default-nya adalah `true`. Atur ke `false` untuk penyedia yang menolak parameter ini, seperti Microsoft Entra ID v2.0, yang gagal dengan `AADSTS9010010` ketika `resource` dan `scope` dikirim bersamaan. Gunakan `scope` atau `audience` sebagai gantinya untuk memperoleh token dengan cakupan API. Hanya dapat diatur oleh admin.
- **Variabel lingkungan:** Bidang URL OAuth yang didefinisikan dalam YAML, termasuk `authorization_url`, `token_url`, `redirect_uri`, dan `revocation_endpoint`, dapat menggunakan referensi `${ENV_VAR}`. LibreChat akan menyelesaikan nilai lingkungan tersebut sebelum validasi URL. URL endpoint OAuth yang dikelola pengguna dan dikirimkan melalui UI harus berupa URL literal dan akan menolak placeholder `${ENV_VAR}`.
- **Contoh:**

  ```yaml
  oauth-api-server:
    authorization_url: https://api.example.com/oauth/authorize
    token_url: https://api.example.com/oauth/token
    client_id: your_client_id
    client_secret: your_client_secret
    redirect_uri: http://localhost:3080/api/mcp/oauth-api-server/oauth/callback
    scope: 'read execute'
    grant_types_supported: ['authorization_code', 'refresh_token']
    token_endpoint_auth_methods_supported: ['client_secret_post']
    token_exchange_method: default_post
    response_types_supported: ['code']
    code_challenge_methods_supported: ['S256', 'plain']
  ```

  Contoh Auth0:

  ```yaml
  auth0-server:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      audience: https://api.example.com
      scope: 'read:data offline_access'
  ```

Ketika `token_exchange_method` dan `token_endpoint_auth_methods_supported` keduanya dihilangkan untuk client secret yang telah dikonfigurasi sebelumnya, LibreChat memberikan waktu hingga lima detik untuk penemuan metadata protected-resource dan authorization-server. LibreChat hanya menggunakan kapabilitas yang diiklankan jika token endpoint yang ditemukan sama persis dengan `token_url` yang dikonfigurasi; penemuan tidak dapat mengalihkan kredensial klien yang dikonfigurasi ke endpoint lain. Tetapkan `token_exchange_method` secara eksplisit jika penyedia tidak memublikasikan metadata yang dapat digunakan atau memerlukan metode paksa.

Permintaan HTTP penemuan, pendaftaran, token, dan pencabutan OAuth sisi server **tidak** mengikuti pengalihan (redirect), meskipun URL asli diizinkan. Konfigurasikan endpoint akhir penyedia secara langsung saat melakukan pengalihan. Destinasi literal IP privat diblokir kecuali diizinkan secara eksplisit oleh kebijakan host tepercaya atau kebijakan alamat-dan-port yang tepat dari administrator. Pembatasan ini berlaku untuk permintaan HTTP OAuth sisi server; hal ini tidak mencegah browser pengguna untuk menyelesaikan pengalihan halaman otorisasi yang normal.

#### `oauth_headers` [#oauth_headers]

- **Tipe:** Objek (Opsional)
- **Deskripsi:** Header yang digunakan secara khusus untuk permintaan alur OAuth. Header ini digunakan selama autentikasi OAuth, seperti pendaftaran klien dinamis dan pertukaran token, dan tidak dikirim selama komunikasi server MCP reguler.
- **Kasus Penggunaan Umum:**
  - Menambahkan autentikasi ke endpoint pendaftaran klien dinamis, seperti `Authorization: Bearer ${DCR_API_KEY}`
  - Menyertakan header khusus penyedia yang diperlukan untuk alur OAuth
  - Mengatur header yang diperlukan oleh endpoint token OAuth
- **Dukungan Placeholder:** Nilai menerima placeholder `{{LIBRECHAT_USER_*}}` dan referensi `${ENV_VAR}`, begitu pula dengan kolom string di bawah `oauth`.
- **Perbedaan Utama dari `headers`:**
  - **`headers`**: Dikirim bersama permintaan server MCP reguler setelah autentikasi selesai
  - **`oauth_headers`**: Dikirim hanya selama alur autentikasi OAuth
- **Contoh:**
  ```yaml
  oauth_headers:
    Authorization: "Bearer ${DCR_API_KEY}"
    X-Custom-Header: "custom_value"
  ```

#### `oauthPrompt` [#oauthprompt]

- **Tipe:** String (Opsional)
- **Deskripsi:** Mengatur kapan pengguna diminta untuk masuk ke server yang dilindungi OAuth.
  - `on_start`: prompt masuk muncul saat giliran percakapan dimulai, sebelum agen dijalankan.
  - `on_use`: giliran dimulai tanpa prompt, dan agen menemukan tool dari server tersebut melalui pencarian tool. Prompt muncul saat agen pertama kali memanggil salah satu tool server tersebut, dan eksekusi menunggu pengguna untuk masuk.
- **Nilai Default:** `on_start`
- **Catatan:**
  - `on_use` hanya berlaku ketika setiap tool yang dipilih agen dari server tersebut adalah [deferred](/docs/features/agents#deferred-tools) (opsi "Defer" aktif). Jika ada tool yang dipilih dimuat di awal, atau agen memilih seluruh server alih-alih tool individual, prompt tetap ditampilkan pada awal giliran.
  - Capability `deferred_tools` [agent](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) harus diaktifkan. Ketika capability `run_in_background` diaktifkan, alat yang dipilih dan memilih untuk eksekusi di latar belakang tetap menampilkan prompt pada awal giliran, karena panggilan yang terpisah tidak dapat menunggu proses masuk (sign-in).
  - `on_use` memerlukan [`oauthToolCatalog`](#oauthtoolcatalog) yang dideklarasikan. Tanpa itu, server mempertahankan prompt saat awal giliran, meskipun untuk pengguna yang sudah pernah terhubung sebelumnya.
  - Alat yang ditawarkan sebelum masuk harus mencakup setiap alat yang dipilih, atau prompt tetap berada di awal giliran. Itu adalah katalog yang dideklarasikan, atau daftar alat milik pengguna ketika koneksi sebelumnya meninggalkannya.
  - Hanya server yang dikonfigurasi operator yang memenuhi syarat: server yang didefinisikan dalam `librechat.yaml` atau yang ditambahkan melalui [penggantian konfigurasi admin](/docs/features/admin_panel#configuration-management). Server yang dibuat pengguna di UI tetap menggunakan prompt saat awal giliran. Prompt tetap berada di awal giliran untuk server yang menggunakan `obo`, `customUserVars`, `requestHeaders`, atau placeholder per pengguna atau per permintaan (`{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, `{{LIBRECHAT_BODY_*}}`) dalam pengaturan koneksinya.
  - Berlaku baik ketika OAuth dikonfigurasi di awal (`oauth`, `requiresOAuth: true`) maupun ketika terdeteksi saat server menolak koneksi.
  - Tidak tersedia pada server yang dibuat pengguna melalui UI.
- **Contoh:**
  ```yaml
  mcpServers:
    google-sheets:
      type: streamable-http
      url: https://sheets.example.com/mcp
      requiresOAuth: true
      oauthPrompt: on_use
      oauthToolCatalog:
        - name: read_sheet
          description: Read the values in a spreadsheet range
  ```

#### `oauthToolCatalog` [#oauthtoolcatalog]

- **Tipe:** Array of Objects (Opsional)
- **Deskripsi:** Daftar alat yang ditawarkan server `oauthPrompt: on_use` ke pencarian alat sebelum pengguna masuk. LibreChat tidak dapat menampilkan alat dari server yang dilindungi untuk pengguna yang belum masuk, sehingga operator mendeklarasikannya di sini. Katalog ini sama untuk setiap pengguna; koneksi seorang pengguna tidak menentukan apa yang dilihat agen pengguna lain. Setelah pengguna masuk, definisi alat milik server itu sendiri yang digunakan, dan server memvalidasi setiap panggilan.
- **Kolom masukan:**
  - `name`: String (Wajib) - Nama alat pada server, sebagaimana dipilih oleh agen.
  - `description`: String (Opsional) - Apa yang dilakukan alat ini, ditampilkan ke pencarian alat dan model.
  - `inputSchema`: Object (Opsional) - Parameter dari tool:
    - `type`: harus berupa `object`
    - `properties`: peta dari nama parameter ke skema properti
    - `required`: array dari nama parameter yang wajib diisi
- **Skema properti:** subset terbatas dari JSON Schema yang hanya memiliki kunci-kunci berikut:
  - `type`: salah satu dari `string`, `number`, `integer`, `boolean`, `object`, `array`, `null`, atau daftar tidak kosong dari nilai-nilai tersebut
  - `description`: String
  - `enum`: array tidak kosong berisi string, angka, boolean, atau `null`
  - `default`: string, number, boolean, atau `null`
  - `items`: untuk array, sebuah objek dengan `type`, `description`, dan `enum`
- **Catatan:**
  - Validasi bersifat ketat. Kunci entri yang salah eja (misalnya `input_schema`) atau kata kunci di luar skema terbatas (misalnya `minLength`, `pattern`, atau `$ref`) akan menggagalkan validasi konfigurasi, alih-alih diabaikan.
  - Pengguna yang koneksi sebelumnya masih menyisakan daftar tool akan ditawarkan daftar tersebut sebagai gantinya; dalam kedua kasus, daftar harus mencakup setiap tool yang dipilih agen dari server, atau prompt akan tetap berada di awal giliran.
  - Tidak tersedia pada server yang dibuat pengguna melalui UI.
- **Contoh:**
  ```yaml
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
  ```

#### `startup` [#startup]

- **Tipe:** Boolean (Opsional)
- **Deskripsi:** Jika diatur ke `false`, server MCP ini tidak akan terhubung saat aplikasi dimulai. Ini berguna untuk server yang memerlukan input atau konfigurasi pengguna sebelum terhubung, atau untuk kasus di mana Anda ingin mengontrol kapan server diinisialisasi.
- **Nilai Default:** `true`
- **Contoh:**
  ```yaml
  mcpServers:
    my-mcp-server:
      type: streamable-http
      url: 'https://api.example.com/mcp/'
      startup: false
  ```

### Catatan [#notes]

- **Inferensi Tipe:**
  - Jika `type` dihilangkan:
    - Jika `url` ditentukan dan diawali dengan `http://` atau `https://`, maka `type` secara default akan menjadi `sse`.
    - Jika `url` ditentukan dan diawali dengan `ws://` atau `wss://`, maka `type` secara default akan menjadi `websocket`.
    - Jika `command` ditentukan, `type` secara default akan menjadi `stdio`.
- **Tipe Koneksi:**
  - **`stdio`**: Memulai server MCP sebagai proses anak dan berkomunikasi melalui input/output standar.
  - **`websocket`**: Terhubung ke server MCP eksternal melalui WebSocket.
  - **`sse`**: Terhubung ke server MCP eksternal melalui Server-Sent Events (SSE).
  - **`streamable-http`**: Terhubung ke server MCP eksternal melalui HTTP dengan dukungan untuk respons streaming.
- **Alamat Internal/Lokal:**
  - **Penting**: Server MCP yang menggunakan alamat IP internal (contoh: `172.24.1.165`, `192.168.1.100`), atau domain lokal (contoh: `mcp-server`, `host.docker.internal`) **harus** diizinkan secara eksplisit. Gunakan [`mcpSettings.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#allowedaddresses) untuk layanan host:port privat yang spesifik ketika Anda ingin tujuan publik tetap dapat diakses, atau [`mcpSettings.allowedDomains`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#alloweddomains) ketika Anda menginginkan daftar putih (whitelist) yang ketat.
  - Lihat [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) untuk detail konfigurasi.

## Contoh [#examples]

### Konfigurasi dengan Alamat Internal [#configuration-with-internal-addresses]

Saat menggunakan server MCP internal/lokal dan tidak diperlukan daftar putih domain yang ketat, konfigurasikan `mcpSettings.allowedAddresses` dengan host dan port yang tepat:

```yaml filename="Complete MCP Configuration with Internal Servers"
# MCP Settings - Required for internal/local addresses
mcpSettings:
  allowedAddresses:
    - '172.24.1.165:8000' # Internal IP and port
    - 'mcp-prod:8001' # Docker container and port
    - 'host.docker.internal:8080' # Docker host and port

# MCP Servers - Individual configurations
mcpServers:
  prod-mcp:
    type: streamable-http
    url: http://172.24.1.165:8000/mcp
    timeout: 120000

  test-mcp:
    type: streamable-http
    url: http://mcp-prod:8001/mcp
    timeout: 120000
```

## Informasi Tambahan [#additional-information]

- **Perilaku Default:**
  - Inisialisasi terjadi saat startup, dan aplikasi harus dimulai ulang agar perubahan dapat diterapkan.
  - Jika `url` dan `command` keduanya ditentukan, `type` harus didefinisikan secara eksplisit untuk menghindari ambiguitas.
- **Dukungan Multi-Pengguna:**
  - MCPManager kini mendukung koneksi tingkat pengguna dan tingkat aplikasi yang terpisah, sehingga memungkinkan pengelolaan koneksi yang tepat per pengguna.
  - Koneksi pengguna dilacak dan dikelola secara terpisah, dengan pembentukan dan pembersihan yang tepat.
  - Gunakan placeholder kolom pengguna dinamis di header, URL, dan variabel lingkungan:
    - `{{LIBRECHAT_USER_ID}}` - Pengidentifikasi unik pengguna
    - `{{LIBRECHAT_USER_EMAIL}}` - Alamat email pengguna
    - `{{LIBRECHAT_USER_USERNAME}}` - Nama pengguna (username) pengguna
    - `{{LIBRECHAT_USER_ROLE}}` - Peran pengguna (contoh: "user", "admin")
    - Dan masih banyak kolom lainnya (lihat bagian headers untuk daftar lengkapnya)
- **Manajemen Idle Pengguna:**
  - Koneksi pengguna dipantau untuk aktivitas dan akan diputuskan setelah 15 menit tidak ada aktivitas.
- **Variabel Lingkungan:**
  - **Di `env` (untuk tipe `stdio`):** Berguna untuk menyiapkan lingkungan runtime atau konfigurasi spesifik yang diperlukan oleh proses server MCP.
  - **Dalam `headers` (untuk tipe `sse` dan `streamable-http`):** Gunakan sintaks `${ENV_VAR}` untuk mereferensikan variabel lingkungan dalam nilai header.
- **Bidang Pengguna Dinamis:**
  - Placeholder kolom pengguna diganti saat runtime dengan informasi pengguna yang terautentikasi
  - Hanya kolom non-sensitif yang tersedia (kata sandi dan data sensitif lainnya dikecualikan)
  - Bidang yang hilang akan dianggap sebagai string kosong secara default
  - Bidang boolean dikonversi menjadi representasi string ("true" atau "false")
- **Penanganan Kesalahan (`stderr`):**
  - Mengonfigurasi `stderr` memungkinkan Anda untuk mengelola bagaimana pesan kesalahan dari proses server MCP ditangani. Nilai default `"inherit"` berarti bahwa kesalahan akan dicetak ke `stderr` proses induk.
- **Instruksi Server:**
  - Instruksi secara otomatis disuntikkan ke dalam pesan sistem agen saat alat server MCP digunakan
  - Instruksi kustom (nilai string) lebih diutamakan daripada instruksi yang disediakan oleh server
  - Beberapa server MCP masing-masing dapat memberikan instruksi mereka sendiri ke dalam konteks agen
  - Instruksi hanya disertakan jika alat server MCP yang terkait benar-benar tersedia untuk agen tersebut
- **Autentikasi OAuth:**
  - Alur OAuth2 didukung untuk autentikasi aman dengan server MCP
  - Pengguna akan diminta untuk melakukan autentikasi melalui OAuth sebelum server MCP dapat digunakan
