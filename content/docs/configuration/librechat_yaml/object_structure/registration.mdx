The `registration` block controls the social login buttons and allowed email domains. It also sets login timing and OpenID back-channel logout behavior. Turning registration and social login on or off is done with environment variables; see [Authentication](/docs/configuration/authentication).

## Example

```yaml filename="Registration Object Structure"
# Example Registration Object Structure
registration:
  socialLogins: ["google", "facebook", "github", "discord", "openid"]
  allowedDomains:
    - "gmail.com"
    - "protonmail.com"
  oauthStateTtlMs: 600000
  openidDiscovery:
    startupAttempts: 1
    retryDelayMs: 5000
```

## openidDiscovery

Controls how LibreChat retries fetching the OpenID provider's discovery document. Each unset field falls back to its environment variable (`OPENID_DISCOVERY_RETRY_ATTEMPTS`, `OPENID_DISCOVERY_RETRY_DELAY_MS`), then to the default.

**Keys:**
<OptionTable
  options={[
    ['startupAttempts', 'Number', 'Discovery attempts made before startup continues.', 'Between 0 and 100. 0 skips the startup attempts and only retries in the background. Default: 1.'],
    ['retryDelayMs', 'Number', 'Milliseconds between startup and background discovery attempts.', 'Between 100 and 3600000. Default: 5000.'],
  ]}
/>

**Example:**
```yaml filename="registration / openidDiscovery"
openidDiscovery:
  startupAttempts: 3
  retryDelayMs: 5000
```

## openidBackchannelLogout

When the OpenID provider reports a logout, LibreChat refuses the next restoration or renewal of the matching session. This requires a LibreChat build that includes the back-channel logout changes. See the [setup, mode behavior, and rollout guide](/docs/configuration/authentication/OAuth2-OIDC/backchannel-logout) before enabling it.

The feature is off by default. Start with the example below, then follow the guide to test `record` before using `enforce`. All fields belong to `registration.openidBackchannelLogout`. Restart every LibreChat server after changing them.

```yaml filename="registration / openidBackchannelLogout"
registration:
  openidBackchannelLogout:
    mode: off
    algorithms: [RS256]
    clockToleranceSec: 60
    maxTokenAgeSec: 120
    maxBodyBytes: 16384
    rateLimit:
      windowMs: 60000
      max: 60
    processingTimeoutMs: 5000
    # Defaults to at least registration.oauthStateTtlMs:
    # callbackGraceMs: 600000
```

| Key | Default | Description |
| --- | --- | --- |
| `mode` | `off` | `off`, `record`, or `enforce`. Both enabled modes deny known revoked sessions. See the guide for missing bindings, missing records, and temporary failures. |
| `algorithms` | `[RS256]` | Nonempty list of allowed logout-token signing algorithms. Accepted values: `RS256`, `RS384`, `RS512`, `PS256`, `PS384`, `PS512`, `ES256`, `ES384`, `ES512`. |
| `clockToleranceSec` | `60` | Allowed clock difference in seconds when checking token times. Integer from 0 to 3600. |
| `maxTokenAgeSec` | `120` | Maximum time since the logout token was issued (`iat`), with clock tolerance added. Integer from 1 to 3600 seconds. |
| `maxBodyBytes` | `16384` | Maximum form-encoded request body size. Integer from 1 to 1000000 bytes. |
| `rateLimit.windowMs` | `60000` | Time window for counting requests. Integer from 1000 to 3600000 milliseconds. |
| `rateLimit.max` | `60` | Maximum rejected requests (HTTP status 400 or higher) per IP in each window. Valid notifications are not counted, so a provider can send many logouts at once. Uses LibreChat's configured rate-limit storage. Integer from 1 to 100000. |
| `processingTimeoutMs` | `5000` | Maximum time to validate and store a logout before returning 503. Integer from 1 to 60000 milliseconds. A database write can still finish after this response. |
| `callbackGraceMs` | `oauthStateTtlMs` (normally `600000`) | How long to cover a pending login when its logout notification arrives first. Configured integer from 0 to 3600000 milliseconds. The effective value is never below `registration.oauthStateTtlMs`. |
