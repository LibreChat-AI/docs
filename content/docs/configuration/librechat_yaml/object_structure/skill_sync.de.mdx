## Übersicht [#overview]

Das Objekt `skillSync` ermöglicht Administratoren, Skills aus externen Quellen zu spiegeln. GitHub ist der unterstützte Anbieter.

GitHub Skill Sync liest `SKILL.md`-Dateien und die dazugehörigen gebündelten Dateien aus konfigurierten Repository-Pfaden, speichert sie als Skills mit `source: "github"` und hält gespiegelte Zeilen bei späteren Synchronisierungen mit dem Upstream-Repository synchron.

## Beispiel [#example]

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
        # credentialKey: production-skills
        # tenantId: your-tenant-id
```

<Callout type="warning" title="Anmeldedaten">
  Verwenden Sie entweder `token` oder `credentialKey` für jede Quelle, nicht beides. `token` muss ein Verweis auf eine Umgebungsvariable sein, wie z. B. `${GITHUB_SKILLS_TOKEN}`. Verwenden Sie ein fein abgestimmtes persönliches Zugriffstoken (fine-grained personal access token) von GitHub, das auf das ausgewählte Repository beschränkt ist und über schreibgeschützte Berechtigungen für Inhalte (Contents) und Metadaten (Metadata) verfügt.
</Callout>

### Quellidentität [#source-identity]

Das Feld `id` ist Teil der Spiegel-Identität. Halten Sie es stabil. Das Umleiten einer Quelle auf ein umbenanntes Repository oder eine neue Referenz behält die gespiegelten Skills mit derselben Quell-ID verknüpft, während das Ändern der Quell-ID einen neuen Spiegel erstellt.

Wenn `tenantId` festgelegt ist, werden Synchronisierungs-Lese- und Schreibvorgänge innerhalb des Isolationskontexts dieses Tenants ausgeführt. Betrachten Sie `tenantId` für eine Quell-ID als unveränderlich: Das nachträgliche Ändern, Hinzufügen oder Entfernen führt dazu, dass zuvor gespiegelte Skills im alten Tenant verbleiben.

## Synchronisierungsverhalten [#sync-behavior]

GitHub Skill Sync:

- Durchsucht `SKILL.md`-Dateien unterhalb jedes konfigurierten Pfads.
- Importiert den `SKILL.md` Body, das Frontmatter und die gebündelten Dateien.
- Speichert Quell-Metadaten wie source id, owner, repo, ref, skill path, commit SHA und blob SHA.
- Aktualisiert gespiegelte Skills, wenn sich die Upstream-Datei ändert.
- Löscht gespiegelte Skills und Dateien, die aus der konfigurierten Quelle entfernt wurden.
- Validiert und veröffentlicht Skills unabhängig voneinander, sodass ein ungültiger oder in Konflikt stehender Skill keine gültigen Skills aus derselben Quelle verbirgt.
- Bewahrt den zuletzt bekannten guten Spiegel eines übersprungenen Skills auf und macht unvollständige Schreibvorgänge für diesen Skill rückgängig.
- Markiert einen Durchlauf als `partial`, wenn mindestens ein Skill veröffentlicht, aber ein anderer übersprungen wird, und zeichnet eine begrenzte Anzahl übersprungener Elemente sowie Details für den Statusabruf durch Administratoren auf.
- Verwendet eine Synchronisierungssperre, sodass jeweils nur ein GitHub-Synchronisierungsvorgang ausgeführt wird.

Unbekannte `SKILL.md` Frontmatter-Schlüssel werden akzeptiert, solange ihre Werte innerhalb der begrenzten, JSON-sicheren Erweiterungsgrenzen bleiben. Ungültige erkannte Felder, unsichere Erweiterungswerte, doppelte Namen und Eigentumskonflikte führen nur zum Überspringen der betroffenen Skill. Fehler bei Authentifizierung, Ratenbegrenzung, Lock-Loss, Repository-Zugriff und Rollback bleiben Fehler auf Quellenebene.

## Skill-Löschung [#skill-deletion]

Das oberste Objekt `skillDeletion` steuert den Hintergrundprozess, der das Löschen von Skills abschließt und deren gespeicherte Dateien sowie verwaiste Skill-Uploads bereinigt. Es ist von `skillSync` getrennt und gilt für alle Skills. Unbekannte Schlüssel werden abgelehnt.

```yaml filename="librechat.yaml"
skillDeletion:
  finalizationEnabled: true
  sweepIntervalMs: 60000
  claimLeaseMs: 120000
  batchSize: 100
  recheckIntervalMs: 3600000
```
