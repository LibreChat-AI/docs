## Übersicht [#overview]

Das `memory`-Objekt aktiviert das [Benutzergedächtnis](/docs/features/memory) und legt dessen Grenzwerte fest. Das Hinzufügen dieses Abschnitts aktiviert das Gedächtnis: Gespeicherte Einträge werden anschließend den Unterhaltungen jedes Benutzers hinzugefügt, Benutzer können sie im Bereich „Memories“ verwalten, und das Memory-Tool (`set_memory` und `delete_memory`) wird in Chats und Agenten angeboten, sofern die Fähigkeit `memory` für den Agents-Endpunkt aktiviert ist (das ist standardmäßig der Fall).

Die automatische Speicherextraktion, bei der ein separater Speicher-Agent jeden Austausch überprüft und Fakten ohne Aufforderung speichert, ist eine eigene Opt-in-Funktion: Setzen Sie `agent.enabled: true` und geben Sie ihr ein Modell an.

## Beispiel [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Konfiguriert den optionalen automatischen Memory-Agenten. Kann entweder ein Verweis auf einen bestehenden Agenten per ID oder eine vollständige Agentenkonfiguration sein.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

Konfiguriert den automatischen Speicher-Agenten. Er wird nur ausgeführt, wenn `enabled` auf `true` gesetzt ist; ein `agent`-Block ohne `enabled` wird ignoriert, und LibreChat protokolliert beim Start eine Warnung.

Wenn aktiviert, läuft der Speicher-Agent zu Beginn jeder Chat-Anfrage parallel zur Hauptantwort. Er prüft die letzten `messageWindowSize` Nachrichten (begrenzt auf `maxInputTokens`) und speichert oder löscht Einträge eigenständig. Ihm steht Zeit bis zum Abschluss der Hauptantwort plus maximal 3 Sekunden zur Verfügung; läuft er danach noch, wird sein Ergebnis für diese Anfrage verworfen.

Das `agent` Feld unterstützt zwei verschiedene Konfigurationsformate:

### Agent nach ID [#agent-by-id]

Wenn Sie einen vorkonfigurierten Agenten haben, können Sie ihn über seine ID referenzieren:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Benutzerdefinierte Agentenkonfiguration [#custom-agent-configuration]

Für mehr Kontrolle können Sie eine vollständige Agentenkonfiguration definieren:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Vollständiges Konfigurationsbeispiel [#complete-configuration-example]

Ein Beispiel mit allen Speicheroptionen:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Verwendung von benutzerdefinierten Endpoints [#using-custom-endpoints]

Die Memory-Funktion unterstützt benutzerdefinierte endpoints. Bei der Verwendung eines benutzerdefinierten endpoints sollte das Feld `provider` exakt mit dem `name` des benutzerdefinierten endpoints übereinstimmen. Benutzerdefinierte Header mit Umgebungsvariablen und Benutzer-Platzhaltern werden korrekt aufgelöst.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- Siehe [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) für alle verfügbaren Platzhalter

## Hinweise [#notes]

- `personalize` steuert, ob Benutzer sich abmelden können, nicht ob das Gedächtnis aktiviert ist. Verwenden Sie `disabled`, um das Gedächtnis zu deaktivieren.
- `maxInputTokens` begrenzt den Chat-Kontext, der an den automatischen Speicher-Agenten gesendet wird, während `tokenLimit` die Gesamtgröße der gespeicherten Erinnerungen begrenzt.
- Benutzerdefinierte `instructions` ersetzen die standardmäßigen Speicheranweisungen und sind vor allem in Verbindung mit `validKeys` nützlich.
- Der Zugriff wird außerdem pro Rolle über die Speicherberechtigungen gesteuert (verwenden, erstellen, lesen, aktualisieren, abmelden). Siehe [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), das [Admin-Panel](/docs/features/admin_panel) oder die Admin-Einstellungen unten im Speicher-Panel.

## Fehlerbehebung [#troubleshooting]

**Memory tut nichts.** Prüfe, ob der Abschnitt `memory` vorhanden ist und `disabled` nicht auf `true` gesetzt ist, ob die Rolle des Benutzers die Berechtigung hat, Erinnerungen zu verwenden, und ob der Benutzer **Gespeicherte Erinnerungen referenzieren** nicht deaktiviert hat. Für das Memory-Tool muss die Fähigkeit `memory` in der Liste `capabilities` des Agents-Endpunkts enthalten sein, falls du eine festgelegt hast.

**Es wird nichts automatisch gespeichert.** Die automatische Extraktion erfordert `agent.enabled: true` sowie eine gültige `id` oder `provider` und `model`. Ohne diese Einstellungen werden Einträge nur gespeichert, wenn ein Benutzer das Modell bittet, sich etwas zu merken, während das Memory-Tool aktiviert ist, oder wenn sie manuell hinzugefügt werden.

**Der Memory-Agent schlägt bei einem benutzerdefinierten Endpoint fehl.** `provider` muss exakt mit dem `name` des benutzerdefinierten Endpoints übereinstimmen. Stellen Sie zuerst sicher, dass der Endpoint für normale Chats funktioniert, und prüfen Sie dann, ob die Umgebungsvariablen gesetzt sind, auf die seine Header verweisen. Platzhalter in Headern werden für Memory genauso aufgelöst wie für Chats.

**Der Token-Verbrauch ist hoch.** Senken Sie `maxInputTokens` oder `messageWindowSize`, um weniger Chat an den Memory-Agenten zu senden, senken Sie `tokenLimit`, damit die gespeicherten Erinnerungen (die jeder Anfrage hinzugefügt werden) klein bleiben, und beschränken Sie `validKeys`.
