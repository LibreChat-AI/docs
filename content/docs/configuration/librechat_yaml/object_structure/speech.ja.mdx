## 概要 [#overview]

`speech` オブジェクトを使用すると、`librechat.yaml` 設定ファイル内で直接 Text-to-Speech (TTS) および Speech-to-Text (STT) プロバイダーを設定できます。これにより、ユーザーが各自の API キーを設定することなく、サーバーサイドの音声サービスを利用できるようになります。

**`speech` 配下のフィールド:**

- `tts` - Text-to-Speech プロバイダーの設定
- `stt` - Speech-to-Text プロバイダーの設定
- `speechTab` - 音声機能のデフォルトUI設定

**注記:**

- 複数のプロバイダーを同時に設定できます
- ユーザーは利用可能なオプションから好みのプロバイダーを選択できます。
- configファイル内のAPIキーは、セキュリティ上の理由から環境変数参照を使用する必要があります。

## 例 [#example]

```yaml filename="speech"
speech:
  tts:
    allowedAddresses: ["tts.internal:8080"]
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["voice-id-1", "voice-id-2"]
  stt:
    allowedAddresses: ["stt.internal:8080"]
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText: true
    textToSpeech: true
```

## SSRF Protection [#ssrf-protection]

LibreChatは、接続時にオペレーターが提供したSTTおよびTTSのURLを保護します。プライベート、ループバック、リンクローカル、およびクラウドメタデータの宛先はデフォルトでブロックされ、音声リクエストに対するリダイレクトは無効化されています。

`speech.tts.allowedAddresses` および `speech.stt.allowedAddresses` は、厳格な許可リストではなく、個別の除外リストです。そのセクションが信頼されたセルフホストサービスに到達する必要がある場合にのみ、正確なプライベート `host:port`、`private.ip:port`、または `[ipv6]:port` を追加してください。URL、パス、CIDR範囲、ホスト/IP単体、またはパブリックIPリテラルは使用しないでください。デフォルトのポートは正規化されるため、明示的なポートのないHTTPS URLはポート `443` としてチェックされます。

除外されたホスト名は、そのポートで解決されるプライベートアドレスを信頼します。可能な限りプライベートIPリテラルを使用し、DNSを自身で制御しており、攻撃者によって再指定される可能性のない名前のみをリストしてください。

フォワードプロキシがホスト名リクエストを運ぶ際、プロキシは宛先のDNS解決とエグレス（外部送信）を実行するため、プロキシ自身が独自のSSRFポリシーを強制する必要があります。リテラルなプライベート宛先は、その正確なアドレスとポートが除外設定されていない限り、プロキシによる処理の前に引き続きブロックされます。

## tts

`tts` オブジェクトは、Text-to-Speech（テキスト読み上げ）プロバイダーを設定します。複数のプロバイダーを設定でき、ユーザーは使用するプロバイダーを選択できます。

## 完全な例 [#complete-example]

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true

speech:
  tts:
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1-hd"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["21m00Tcm4TlvDq8ikWAM", "AZnzlk1XvdvUeBnXmlld"]
      voice_settings:
        stability: 0.5
        similarity_boost: 0.75
  stt:
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: false
    advancedMode: false
    speechToText: true
    textToSpeech:
      engineTTS: "external"
      voice: "nova"
      automaticPlayback: false
```

## 注記 [#notes]

- 設定ファイル内のAPIキーには、常に環境変数参照（例: `${API_KEY}`）を使用してください。
- 複数のTTSプロバイダーを設定でき、ユーザーはUI上で好みのオプションを選択できます。
- `speechTab` 設定は、ユーザーが個人設定で上書きできるデフォルト値を定義します。
- `browser` はブラウザ組み込みの音声サポートを使用します。`external` は `speech.stt` または `speech.tts` の下で設定されたサーバーサイドのプロバイダーを使用します。
- 既存の `openai` および `azureOpenAI` の STT デフォルト、ならびに `openai`、`azureOpenAI`、`elevenlabs`、`localai` の TTS デフォルトは `external` に移行されました。利用できない外部エンジンは `browser` にフォールバックします。
- 詳細な機能ドキュメントについては、[Speech to Text & Text to Speech](/docs/configuration/stt_tts) を参照してください。
