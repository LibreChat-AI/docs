## 개요 [#overview]

`memory` 객체는 [사용자 메모리](/docs/features/memory)를 활성화하고 그 한도를 설정합니다. 이 섹션을 추가하는 것이 메모리 기능을 켜는 방법입니다. 그러면 저장된 항목이 각 사용자의 대화에 추가되고, 사용자는 메모리 패널에서 이를 관리할 수 있으며, `memory` 기능이 agents 엔드포인트에서 활성화되어 있는 한(기본적으로 활성화되어 있습니다) 채팅과 에이전트에서 메모리 도구(`set_memory` 및 `delete_memory`)가 제공됩니다.

자동 메모리 추출은 별도의 메모리 에이전트가 모든 대화 교환을 검토하고, 요청하지 않아도 사실을 저장하는 기능으로, 별도로 옵트인하여 활성화해야 합니다. `agent.enabled: true`로 설정하고 모델을 지정하세요.

## 예시 [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [

      '선택적 자동 메모리 에이전트를 구성합니다. ID를 통한 기존 에이전트 참조 또는 전체 에이전트 구성 중 하나를 사용할 수 있습니다.',

자동 메모리 에이전트를 설정합니다. `enabled`가 `true`일 때만 실행되며, `enabled` 없이 `agent` 블록만 있으면 무시되고 LibreChat은 시작 시 경고를 기록합니다.

활성화되면, 메모리 에이전트는 모든 채팅 요청이 시작될 때 기본 응답과 함께 실행됩니다. 마지막 `messageWindowSize`개의 메시지(`maxInputTokens`로 제한됨)를 검토하고, 스스로 항목을 저장하거나 삭제합니다. 기본 응답이 끝날 때까지, 그리고 그 이후 최대 3초까지 실행 시간이 주어집니다. 그 시간이 지나도 여전히 실행 중이라면, 해당 요청에 대한 결과는 버려집니다.

`agent` 필드는 두 가지 서로 다른 구성 형식을 지원합니다:

### ID별 에이전트 [#agent-by-id]

사전 구성된 에이전트가 있는 경우, 해당 ID를 사용하여 참조할 수 있습니다:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### 사용자 지정 에이전트 구성 [#custom-agent-configuration]

더 많은 제어 권한을 원하신다면, 전체 에이전트 구성을 정의할 수 있습니다:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## 전체 구성 예시 [#complete-configuration-example]

모든 메모리 옵션을 사용한 예시:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## 사용자 지정 endpoint 사용하기 [#using-custom-endpoints]

memory 기능은 사용자 지정 endpoint를 지원합니다. 사용자 지정 endpoint를 사용할 때 `provider` 필드는 사용자 지정 endpoint의 `name`과 정확히 일치해야 합니다. 환경 변수 및 사용자 플레이스홀더가 포함된 사용자 지정 헤더는 올바르게 해석됩니다.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- 사용 가능한 모든 플레이스홀더는 [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers)를 참조하세요.

## 참고 사항 [#notes]

- `personalize`는 사용자가 메모리 기능을 거부(옵트아웃)할 수 있는지 여부를 제어하며, 메모리 기능의 켜짐/꺼짐 자체를 제어하지는 않습니다. 메모리를 끄려면 `disabled`를 사용하세요.
- `maxInputTokens`는 자동 메모리 에이전트로 전송되는 채팅 컨텍스트의 크기를 제한하고, `tokenLimit`은 저장된 메모리의 전체 크기를 제한합니다.
- 사용자 지정 `instructions`는 기본 메모리 지침을 대체하며, 주로 `validKeys`와 함께 사용할 때 유용합니다.
- 역할별로 메모리 권한(사용, 생성, 읽기, 업데이트, 옵트아웃)을 통해서도 액세스를 제어할 수 있습니다. [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), [관리자 패널](/docs/features/admin_panel), 또는 메모리 패널 하단의 관리자 설정을 참조하세요.

## 문제 해결 [#troubleshooting]

**메모리가 아무 동작도 하지 않습니다.** `memory` 섹션이 존재하고 `disabled`가 `true`가 아닌지 확인하세요. 사용자의 역할에 메모리를 사용할 권한이 있는지, 그리고 사용자가 **Reference saved memories**를 끄지 않았는지도 확인하세요. Memory 도구의 경우, 에이전트 엔드포인트 `capabilities` 목록을 설정했다면 그 목록에 `memory` 기능이 포함되어 있어야 합니다.

**아무것도 자동으로 저장되지 않습니다.** 자동 추출을 사용하려면 `agent.enabled: true`와 유효한 `id`, 또는 `provider`와 `model`이 필요합니다. 이 설정이 없으면 항목은 Memory 도구가 켜진 상태에서 사용자가 모델에게 무언가를 기억하도록 요청하거나, 사용자가 직접 추가한 경우에만 저장됩니다.

**메모리 에이전트가 커스텀 엔드포인트에서 실패합니다.** `provider`는 커스텀 엔드포인트의 `name`과 정확히 일치해야 합니다. 먼저 해당 엔드포인트가 일반 채팅에서 정상 작동하는지 확인한 다음, 헤더가 참조하는 환경 변수가 설정되어 있는지 확인하십시오. 헤더 플레이스홀더는 메모리와 채팅에서 동일한 방식으로 해석됩니다.

**토큰 사용량이 많습니다.** 메모리 에이전트로 전송되는 채팅 양을 줄이려면 `maxInputTokens` 또는 `messageWindowSize`를 낮추세요. 모든 요청에 추가되는 저장된 메모리를 작게 유지하려면 `tokenLimit`을 낮추고, `validKeys`를 제한하세요.
