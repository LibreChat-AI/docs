La configuration `webSearch` vous permet de personnaliser la fonctionnalité de recherche web au sein de LibreChat, y compris les fournisseurs de recherche, les scrapers de contenu et les rerankers de résultats.

## Vue d'ensemble [#overview]

La fonctionnalité de recherche web se compose de trois éléments principaux :

1. **Fournisseurs de recherche** : Services qui effectuent la recherche web initiale
2. **Scrapers** : Services qui extraient du contenu à partir de pages web
3. **Rerankers** : Services qui réordonnent les résultats de recherche pour une meilleure pertinence

## Exemple [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## Protection SSRF et fournisseurs privés [#ssrf-protection-and-private-providers]

LibreChat valide chaque connexion qu'il ouvre pour la recherche web, le scraping et le reranking. Les destinations privées, de bouclage (loopback), locales au lien (link-local) et les métadonnées cloud sont bloquées par défaut, y compris les redirections et les noms d'hôtes qui se résolvent en une adresse privée au moment de la connexion.

Utilisez `webSearch.allowedAddresses` lorsqu'un endpoint configuré pour SearXNG, Firecrawl, Jina, compatible avec Tavily, compatible avec Keenable ou un fournisseur associé est délibérément privé :

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

Ce champ est une liste d'exemption SSRF, et non une liste d'autorisation stricte. Les destinations publiques restent disponibles. Les entrées doivent être des paires exactes `host:port`, `private.ip:port` ou `[ipv6]:port` ; les URL, chemins, plages CIDR, hôtes/IP nus et adresses IP publiques littérales sont rejetés. Un nom d'hôte exempté fait confiance à l'adresse IP privée vers laquelle il se résout sur ce port ; privilégiez donc une adresse IP privée littérale et ne listez que les noms dont vous contrôlez le DNS.

LibreChat exempte automatiquement un endpoint de proxy de transfert HTTP(S) configuré afin qu'il puisse être atteint. Lorsque le proxy achemine une requête, il résout la destination et doit appliquer lui-même la sortie vers cette destination. `NO_PROXY` peut rendre une requête directe, là où la protection de connexion de LibreChat s'applique toujours. Cette protection couvre les connexions que LibreChat ouvre vers les API des fournisseurs ; elle ne peut pas restreindre une URL de page qu'un scraper tiers reçoit en tant que données de requête et qu'il récupère sur sa propre infrastructure.

## Propriété des identifiants [#credential-ownership]

Une URL Firecrawl, SearXNG ou Jina fournie par l'utilisateur ne doit pas recevoir de clé API appartenant au serveur. La validation SSRF ne rend pas un endpoint public sélectionné par l'utilisateur sûr pour recevoir les identifiants du déploiement. Configurez l'URL et la clé ensemble en tant que paramètres appartenant à l'administrateur, ou laissez l'utilisateur fournir sa propre paire ; SearXNG peut également fonctionner sans clé.

Si une URL utilisateur enregistrée devait être associée à la clé du serveur, LibreChat ignore l'URL optionnelle de Firecrawl et utilise son endpoint par défaut. L'URL d'instance de SearXNG est requise, de sorte que la configuration à propriété mixte ne soit pas authentifiée et que l'outil de recherche ne soit pas initialisé. Pour un déploiement auto-hébergé utilisant la clé du serveur, configurez `FIRECRAWL_API_URL` ou `SEARXNG_INSTANCE_URL` parallèlement à cette clé au lieu de vous fier à l'URL enregistrée d'un utilisateur. Les endpoints privés nécessitent toujours [`allowedAddresses`](#ssrf-protection-and-private-providers).

#### Choisir les moteurs [#choosing-engines]

Les noms des moteurs doivent correspondre aux moteurs activés sur votre propre instance, et deux choses en découlent :

- SearXNG ignore un moteur qu'il ne reconnaît pas au lieu de signaler une erreur. Une faute de frappe, ou un moteur désactivé sur votre instance, se traduit par un nombre de résultats réduit plutôt que par un échec.
- Les noms valides sont spécifiques à l'instance. Vérifiez la liste activée sur `https://your-instance/config`, qui renvoie un JSON incluant chaque moteur activé, ou ouvrez l'onglet **Engines** de la page des préférences de votre instance.

La valeur par défaut est `google,bing,duckduckgo`. SearXNG agrège tout ce que les moteurs sélectionnés renvoient ; ainsi, un moteur bloqué vous coûte seulement sa part des résultats plutôt que la réponse entière, et une recherche ne revient vide que lorsque chaque moteur sélectionné échoue ou ne renvoie rien.

DuckDuckGo est le moteur de cet ensemble par défaut le plus susceptible d'être bloqué, car il présente des CAPTCHA à la plupart des instances auto-hébergées. Avec seulement trois moteurs dans l'ensemble, le perdre en même temps qu'un Google ou Bing limité par le débit est un moyen courant de se retrouver sans aucun résultat. Définir explicitement `engines`, en excluant DuckDuckGo, et lister plus de trois moteurs permettent tous de réduire ce risque.

Les moteurs qui répondent rapidement et tolèrent le trafic auto-hébergé constituent le meilleur ensemble de départ, par exemple :

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

Ajouter plus de moteurs élargit la couverture mais ralentit également chaque recherche, car SearXNG attend le moteur le plus lent de l'ensemble avant de répondre. Gardez le `timeout` à l'esprit lorsque vous agrandissez la liste.

#### Ce que ces options ne contrôlent pas [#what-these-options-do-not-control]

- **Safe search** ne fait pas partie de ce bloc. Il provient de la clé de premier niveau [`safeSearch`](#safesearch) et est transmis à SearXNG en tant que `safesearch`.
- Les **catégories de résultats** sont choisies par requête par LibreChat, qui fait correspondre le type de recherche à `general`, `images`, `videos` ou `news`. Elles ne peuvent pas être remplacées ici.
- Le **numéro de page et le format de résultat** sont fixes. LibreChat demande toujours la page 1 au format JSON, c'est pourquoi votre instance doit avoir `json` activé sous `formats`.

## Notes [#notes]

- Les clés API peuvent être configurées de deux manières :
  1. Définissez les variables d'environnement spécifiées dans la configuration YAML
  2. Si les variables d'environnement ne sont pas définies, les utilisateurs seront invités à fournir les clés API via l'interface utilisateur.
- La configuration prend en charge plusieurs services pour chaque composant (providers, scrapers, rerankers)
- Si aucun type de service spécifique n'est précisé, le système essaiera tous les services disponibles dans cette catégorie.
- La recherche sécurisée (Safe search) propose trois niveaux de filtrage de contenu : OFF (0), MODERATE (1) et STRICT (2)
- Tavily n'hérite pas du paramètre de recherche sécurisée global par défaut ; définissez `tavilySearchOptions.safeSearch` explicitement uniquement lorsque votre compte Tavily prend en charge `safe_search`.
- Keenable prend en charge la recherche sans clé et la récupération de pages ; sa clé optionnelle augmente les limites de débit public, et sa substitution d'URL de récupération est réservée à l'environnement.
- Le comportement des requêtes SearXNG (moteurs, langue, plage temporelle, délai d'expiration de la requête) est configuré sous `searxngSearchOptions` ; voir [Choosing engines](#choosing-engines) si les recherches ne renvoient aucun résultat.
- Ne mettez jamais de clés API réelles dans la configuration YAML - utilisez uniquement des noms de variables d'environnement

## Configuration de SearXNG [#setting-up-searxng]

SearXNG est un méta-moteur de recherche axé sur la confidentialité que vous pouvez auto-héberger. 
Pour plus d'informations, consultez la [documentation officielle de SearXNG](https://docs.searxng.org/).

Voici les étapes pour configurer votre propre instance SearXNG à utiliser avec LibreChat :

### Utilisation de Docker Desktop [#using-docker-desktop]

1. **Rechercher l'image officielle de SearXNG**
   - Ouvrez Docker Desktop
   - Recherchez `searxng/searxng` dans l'onglet **Images**
   - Cliquez sur **Run** sur l'image officielle pour automatiquement télécharger et exécuter un conteneur de l'image

2. **Exécution du conteneur**
   - Développez le menu déroulant **Optional Settings** dans le panneau qui apparaît une fois le téléchargement terminé.
   - Définissez les détails de configuration souhaités (numéro de port, nom du conteneur, etc.)
   - Cliquez sur **Run** pour démarrer le conteneur

3. **Configurer SearXNG pour LibreChat**
   - Accédez à l'onglet `Files` dans Docker Desktop
   - Allez dans `/etc/searxng/settings.yaml`
   - Ouvrir l'éditeur de fichiers
   - Accédez à la section `formats`
   - Ajoutez `json` comme format acceptable afin que LibreChat puisse communiquer avec votre instance
   - Enregistrez le fichier

4. **Redémarrer le conteneur**
   - Redémarrez le conteneur pour que les modifications prennent effet

#### Configuration YAML [#yaml-configuration]

Pour configurer SearXNG pour tout le monde sur l'instance au lieu de le faire par utilisateur, définissez les mêmes valeurs dans `librechat.yaml` :

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

L'URL et la clé sont toujours lues depuis l'environnement, donc associez la configuration ci-dessus avec :

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Les instances privées nécessitent une entrée allowedAddresses">
`localhost:55011` est une adresse de bouclage (loopback), que la [protection SSRF](#ssrf-protection-and-private-providers) de LibreChat bloque au moment de la connexion. Sans l'entrée `allowedAddresses` correspondante, la recherche échoue même si SearXNG est opérationnel. L'entrée doit être la paire `host:port` exacte provenant de l'URL de votre instance.

Lorsque LibreChat lui-même s'exécute dans Docker, `localhost` correspond au conteneur LibreChat, et non à celui de SearXNG. Utilisez un nom d'hôte que le conteneur peut atteindre, tel que le nom du service compose, et excluez-le plutôt :

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

Voir [`searxngSearchOptions`](#searxngsearchoptions) pour toutes les sous-clés acceptées par ce bloc.

#### Dépannage des résultats vides [#troubleshooting-empty-results]

Une recherche SearXNG qui ne renvoie rien signifie presque toujours que la requête n'atteint jamais une instance fonctionnelle, plutôt que LibreChat ne rejette les résultats. Suivez ces étapes dans l'ordre :

1. **L'instance est une adresse privée sans entrée `allowedAddresses`.** LibreChat bloque les destinations de bouclage (loopback) et privées au moment de la connexion ; une instance auto-hébergée doit donc avoir son `host:port` exact listé sous [`allowedAddresses`](#ssrf-protection-and-private-providers). Cela bloque la requête immédiatement plutôt que de renvoyer un jeu de résultats vide.
2. **`json` est manquant dans `formats`.** LibreChat demande des résultats au format JSON. Si la section `formats` de votre fichier de configuration d'instance ne liste pas `json`, l'instance répond avec une page d'erreur et chaque recherche revient vide. Il s'agit de l'étape 3 de la configuration Docker ci-dessus.
3. **Tous les moteurs sélectionnés ont échoué.** SearXNG fusionne les moteurs qui ont répondu, donc une réponse vide signifie qu'aucun d'entre eux n'a rien renvoyé. DuckDuckGo fait partie de l'ensemble par défaut (`google,bing,duckduckgo`) et présente des CAPTCHA à la plupart des instances auto-hébergées, ce qui ne laisse que deux moteurs pour effectuer la recherche. Définissez `searxngSearchOptions.engines` explicitement, excluez DuckDuckGo et listez quelques moteurs supplémentaires.
4. **Un nom de moteur n'existe pas sur votre instance.** SearXNG ignore silencieusement les moteurs qu'il ne reconnaît pas, donc une faute de frappe signifie simplement moins de résultats. Comparez votre liste avec `https://your-instance/config`.
5. **L'instance est plus lente que le délai d'expiration.** Augmentez `searxngSearchOptions.timeout` au-delà de la valeur par défaut `10000` si votre instance interroge de nombreux moteurs ou se trouve derrière un chemin réseau lent.

Vous pouvez reproduire ce que LibreChat envoie en appelant l'instance directement :

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

Ceci s'exécute depuis votre propre machine, ce qui contourne entièrement la protection de connexion de LibreChat. Un tableau `results` vide ici confirme que le problème vient du côté de SearXNG ; si des résultats apparaissent ici alors que LibreChat ne trouve toujours rien, cela indique un problème avec `allowedAddresses`.
