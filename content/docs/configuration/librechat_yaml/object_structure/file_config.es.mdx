## Descripción general [#overview]

El objeto `fileConfig` le permite configurar los ajustes de manejo de archivos para la aplicación, incluyendo límites de tamaño y restricciones de tipos MIME. Esta sección proporciona un desglose detallado de la estructura del objeto `fileConfig`.

Los campos principales bajo `fileConfig` son:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`
  - `stt`

**Notas:**

- En el momento de escribir este artículo, el endpoint Assistants [admite los tipos de archivo de esta lista](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google y los endpoints personalizados admiten archivos a través de la [RAG API.](../../rag_api.mdx)
- Los endpoints de OpenAI, Azure OpenAI, Anthropic, Google y AWS Bedrock admiten la carga directa de archivos a través de [Upload to Provider](/docs/features/ocr#5-upload-files-to-provider-direct).
- Las secciones `ocr`, `text` y `stt` controlan el procesamiento de archivos para funciones como [Upload as Text](/docs/features/upload_as_text) y [OCR](/docs/features/ocr)
- Cualquier otro endpoint no mencionado, como Plugins, no admite (todavía) la carga de archivos.
- El endpoint Assistants tiene un valor de endpoint definido como `assistants`. Todos los demás endpoints utilizan el valor definido `default`.
  - Para los endpoints que no son assistants, puedes ajustar la configuración de archivos para todos ellos bajo `default`
  - Si deseas ajustar la configuración para un endpoint específico, puedes listar sus nombres de endpoint correspondientes:
    - `assistants`
        - no utiliza "default" ya que tiene valores predeterminados definidos por separado de los demás.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Puede omitir valores, en cuyo caso, la aplicación utilizará los valores predeterminados según se define para cada tipo de endpoint listado a continuación.
- LibreChat cuenta 1 megabyte de la siguiente manera: `1 x 1024 x 1024`
- La transmisión de respuestas de carga de larga duración y los límites de obtención de URL remotas del lado del servidor se configuran con las variables de entorno [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` y `REMOTE_FILE_FETCH_MAX_BYTES`](/docs/configuration/dotenv#file-uploads).

## Ejemplo [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

<Callout type="info" title="Sintaxis de patrones MIME">
  LibreChat evalúa los patrones de `supportedMimeTypes` configurados por el administrador en el servidor con un motor de expresiones regulares de tiempo lineal compatible con RE2. No se admiten referencias hacia atrás (backreferences) ni previsualizaciones (lookaround). Cada patrón se compila con el motor activo durante la validación de la configuración; un patrón no admitido rechaza la configuración en lugar de omitirse silenciosamente.
</Callout>
## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Configuración para las importaciones de Skill, que se cargan como archivos `.md`, `.zip` o `.skill`.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` admite tres parámetros:

- `fileSizeLimit` (Número)
  - Tamaño máximo de una carga de Skill individual, especificado en megabytes (MB).
  - **Predeterminado:** `50`
- `importCleanupConcurrency` (Entero)
  - Máximo de operaciones de limpieza simultáneas después de una importación fallida de archivo de Skill. Use `1` para una limpieza en serie.
  - **Predeterminado:** `8`
- `deletionCleanupConcurrency` (Entero)
  - Máximo de operaciones de limpieza simultáneas al eliminar una Skill. Usa `1` para la limpieza en serie.
  - **Predeterminado:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Consulta [Skills](/docs/features/skills) para conocer el resto de las reglas de importación, tales como los límites por archivo y por entrada de archivo.

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', 'Configuración relacionada con la calidad y las dimensiones de la salida de generación de imágenes.', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}

`imageGeneration` admite los siguientes parámetros:

- `percentage` (Número)
  - El tamaño de salida de la imagen generada expresado como un porcentaje (por ejemplo, `100` significa el 100% del tamaño base).
  - Utilice esto para escalar la imagen de salida en relación con un tamaño predeterminado u original.

- `px` (Número)
  - Especifica la dimensión de la imagen de salida en píxeles (p. ej., `1024`).
  - Utilice esto para establecer explícitamente el tamaño de salida de la imagen generada, independientemente del tamaño base.

Establece solo uno de estos parámetros (`percentage` o `px`), no ambos.

Ejemplo de configuración:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Controla el redimensionamiento del lado del cliente de las imágenes antes de cargarlas, lo que evita errores de carga causados por imágenes demasiado grandes. Los usuarios pueden activar o desactivar el redimensionamiento en Configuración > Chat. Establecer `enabled` aquí sobrescribe esa elección para todos los usuarios y bloquea el interruptor; omítalo para que los usuarios mantengan el control.

- `enabled` (Booleano)
  - Forzar el cambio de tamaño activado (`true`) o desactivado (`false`) para todos. Si se omite, cada usuario decide, y el cambio de tamaño está activado de forma predeterminada.
- `maxWidth` (Número)
  - Ancho máximo de las imágenes redimensionadas, en píxeles. Mínimo `1`. **Valor predeterminado:** `1900`
- `maxHeight` (Número)
  - Altura máxima de las imágenes redimensionadas, en píxeles. Mínimo `1`. **Predeterminado:** `1900`
- `quality` (Número)
  - Calidad de compresión JPEG de `0` a `1`. **Predeterminado:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## defaultLLMDeliveryPath

Controla cómo una carga sin un destino seleccionado explícitamente entra en el contexto del modelo. Configúrelo globalmente bajo `fileConfig` o anúlelo para una entrada nombrada bajo `fileConfig.endpoints`.

- `provider` envía el archivo original a través de la ruta de archivo o multimedia nativa del proveedor del modelo.
- `text` extrae o transcribe el contenido admitido y añade el texto resultante al contexto.
- `none` almacena el archivo sin colocarlo directamente en el contexto del modelo; las herramientas seleccionadas aún pueden proporcionarlo cuando sea necesario.

`fallback` maneja tipos MIME no coincidentes. `overrides` acepta tipos MIME exactos como `application/pdf` o comodines como `image/*`. La resolución prefiere las anulaciones (overrides) y el fallback del endpoint, seguidos de los valores globales. Sin una configuración explícita, las imágenes, el audio, el video y los archivos PDF prefieren la entrega nativa del proveedor; otro contenido recuperable utiliza texto. LibreChat degrada las rutas nativas no compatibles a texto cuando la extracción es posible, o a `none` en caso contrario.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## legacyFileUploadUX

El cargador unificado predeterminado elige la entrega del modelo automáticamente y aprovisiona recursos de File Search o Code solo cuando las herramientas seleccionadas los necesitan. Establezca `legacyFileUploadUX: true` globalmente o para un endpoint para restaurar el selector de destino y el comportamiento de carga anticipada seleccionado por el usuario.

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
```

## textFallbackWithoutTools

Cuando una carga se enruta a `none` (almacenada, disponible solo para las herramientas) y el turno no ejecuta ninguna herramienta que pueda leerla, LibreChat puede entregar en su lugar el texto extraído del archivo. Establezca `textFallbackWithoutTools: true` para habilitar esta opción. Puede configurarse de forma global en `fileConfig`, o por entrada en `fileConfig.endpoints` (incluida `default`); un valor de endpoint tiene prioridad sobre el valor global.

**Predeterminado:** `false`

Se aplica únicamente a los archivos adjuntos de los mensajes cuya ruta fue inferida; un destino que el usuario eligió explícitamente nunca se vuelve a resolver, y los archivos guardados en los recursos de herramientas de un agente nunca llegan a un prompt. Solo se ejecutan los extractores integrados de documentos y de texto plano, por lo que no se realiza ninguna llamada a RAG u OCR para un archivo destinado a una herramienta. Los archivos existentes sin texto extraído no se rellenan retroactivamente.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

Los archivos aprovisionados en el entorno de ejecución de código dentro de esta ventana (en milisegundos) omiten la verificación de disponibilidad en tiempo real antes de reutilizarse. Mínimo `0`.

**Por defecto:** `21600000` (6 horas)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

Cuánto tiempo, en milisegundos, espera el proceso de preparación (priming) a una verificación de disponibilidad de File Search heredada antes de incrustar el archivo de todos modos. Mínimo `1`.

**Predeterminado:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

### supportedMimeTypes [#supportedmimetypes-2]

<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Lista de patrones de tipo MIME para archivos de audio que deben ser transcritos con STT.', 'Uses regular expressions to match audio file types.'],
  ]}
/>

**Predeterminado:** Formatos de audio comunes

```yaml filename="fileConfig / stt / supportedMimeTypes"
fileConfig:
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

**Notas:**
- Los archivos que coinciden con los patrones `text` se procesan con extracción de texto simple
- Los archivos que coinciden con los patrones `ocr` se procesan con el servicio de OCR proporcionado
- Los archivos que coinciden con los patrones `stt` se procesan con transcripción de voz a texto (Speech-to-Text).
- **Precedencia de procesamiento: OCR > STT > análisis de texto > fallback**
- Los archivos que no coincidan con ningún patrón recurrirán al análisis de texto.

## Prioridad de procesamiento de archivos [#file-processing-priority]

LibreChat procesa los archivos subidos basándose en la coincidencia de tipo MIME con el siguiente **orden de prioridad**:

1. **OCR** - Si el archivo coincide con `ocr.supportedMimeTypes` Y OCR está configurado
2. **STT** - Si el archivo coincide con `stt.supportedMimeTypes` Y STT está configurado
3. **Análisis de texto** - Si el archivo coincide con `text.supportedMimeTypes`
4. **Fallback** - Análisis de texto como último recurso

Este orden de procesamiento garantiza una calidad de extracción óptima mientras mantiene la funcionalidad incluso cuando los servicios especializados (OCR/STT) no están configurados.

### Ejemplos de procesamiento [#processing-examples]

**Archivo PDF con OCR configurado:**
- El archivo coincide con `ocr.supportedMimeTypes`
- **Utiliza OCR** para extraer texto
- Mejor calidad para PDFs escaneados e imágenes

**Archivo PDF sin OCR configurado:**
- El archivo coincide con `text.supportedMimeTypes` (o utiliza el respaldo)
- **Utiliza la biblioteca** de análisis de texto
- Funciona bien para PDFs digitales con texto seleccionable

**Archivo de Python:**
- El archivo coincide con `text.supportedMimeTypes`
- **Utiliza análisis de texto** (no se requiere OCR)
- Extracción directa de texto

**Archivo de audio con STT configurado:**
- El archivo coincide con `stt.supportedMimeTypes`
- **Utiliza STT** para transcribir audio a texto

**Archivo de imagen sin OCR configurado:**
- El archivo coincide con `ocr.supportedMimeTypes` pero OCR no está disponible
- **Recurre al análisis de texto**
- Capacidad de extracción limitada sin OCR

Este sistema de prioridad permite que funciones como "Upload as Text" funcionen sin necesidad de una configuración de OCR, al mismo tiempo que aprovecha el OCR cuando está disponible para una mejor calidad de extracción.

### Descripción general [#overview-1]

  - `disabled`

      - El tamaño máximo total para todos los archivos en una sola solicitud. En unidades de MB (por ejemplo, use `20` para 20 megabytes)

      - Una lista de [Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression) que especifica qué tipos MIME están permitidos para la carga. Esto se puede personalizar para restringir los tipos de archivo.

## supportedMimeTypes [#supportedmimetypes-3]

**Clave:**
<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Una lista de expresiones regulares que definen los tipos MIME permitidos para la carga.', 'Each pattern must compile with the active server regex engine or configuration validation fails.'],
  ]}
/>

**Predeterminado:** Varía según el endpoint

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
assistants:
  supportedMimeTypes:
      - "image/.*"
      - "application/pdf"
```

LibreChat normaliza los alias MIME comunes antes de aplicar estos patrones. En particular, `application/x-shellscript` (reportado por Chrome en Linux) y `text/x-shellscript` (reportado por libmagic) se convierten en `application/x-sh`. Por lo tanto, una lista de permitidos personalizada que acepte scripts de shell debe permitir el tipo canónico `application/x-sh`. Las cargas rechazadas devuelven el tipo no admitido reportado al cliente en lugar de un error genérico del servidor.
