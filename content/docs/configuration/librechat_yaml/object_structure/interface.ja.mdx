## 概要 [#overview]

`interface` オブジェクトを使用すると、メニュー、パネル、リンクなどのコンポーネントの表示設定や動作設定を含め、アプリケーション内のさまざまなユーザーインターフェース要素をカスタマイズできます。このセクションでは、`interface` オブジェクトの構造について詳しく解説します。

これらは `interface` 配下のフィールドです：

- `theme`
- `mcpServers`
- `privacyPolicy`
- `termsOfService`
- `modelSelect`
- `agentSelectorLimit`
- `parameters`
- `contextUsage`
- `contextCost`
- `currency`
- `presets`
- `prompts`
- `bookmarks`
- `memories`
- `multiConvo`
- `agents`
- `remoteAgents`
- `skills`
- `sharedLinks`
- `schedules`
- `temporaryChat`
- `temporaryChatRetention`
- `generalChatRetention`
- `retentionMode`
- `retainAgentFiles`
- `autoSubmitFromUrl`
- `customWelcome`
- `codeHighlightThrottleMs`
- `artifactUndocking`
- `runCode`
- `webSearch`
- `fileSearch`
- `fileCitations`
- `feedback`
- `replyNotifications`
- `defaultPinnedTools`
- `composerRecentFiles`
- `steerArmConfirmationTimeoutMs`
- `queuedTurnReconciliationTimeoutMs`
- `queuedSendLockTimeoutMs`
- `peoplePicker`
- `marketplace`

**注記:**

- `interface` 設定は、アプリケーション全体にグローバルに適用されます。
- ほとんどの設定にはデフォルト値が提供されていますが、特定の要件や条件に基づいて上書きすることが可能です。
- アプリケーション内の条件付きロジックは、Model Specsのような他の設定に基づいて、これらの設定をさらに変更することができます。

<Callout type="warning" title="非推奨：権限の副作用フィールド">
以下のいくつかのフィールド（`mcpServers`、`prompts`、`bookmarks`、`memories`、`multiConvo`、`agents`、`remoteAgents`、`skills`、`sharedLinks`、`schedules`、`temporaryChat`、`runCode`、`webSearch`、`fileSearch`、`fileCitations`、`peoplePicker`、`marketplace`）は、単にUIを切り替えるだけでなく、起動時に組み込みの `USER` ロールに対してのみデータベース内のロール権限をシードします。

継続的な管理には、各ロール（カスタムロールを含む）の権限マトリックスを直接編集できる [**LibreChat Admin Panel**](/docs/features/admin_panel) を使用してください。これらのYAMLフィールドは、新規インスタンスのブートストラップや完全にファイル駆動型のデプロイメントでは引き続きサポートされますが、機能権限を管理する主要な方法として使用すべきではありません。

完全な権限モデルについては、[Access Control](/docs/features/access_control) を参照してください。

</Callout>

## theme

すべてのユーザーに適用されるデプロイメントテーマを、ライトモードとダークモードの両方で設定します。バンドルされているテーマの名前（`librechat` または `clickhouse`）、あるいは独自のカラー、半径、フォント、シャドウ、モーションを備えたインラインテーマ定義のいずれかを指定します。

これは `REACT_APP_THEME_*` のビルド時カラーやユーザーが保存したテーマよりも優先されますが、ハイコントラストモードには従い、ユーザーのブラウザには一切保存されません。これを削除すると、各ユーザーが保存したテーマ、あるいはクライアントのビルド時に `REACT_APP_THEME_*` カラーが設定されていた場合はその色が復元されます。

**キー:**

<OptionTable
  options={[
    [
      'theme',
      'String or Object',
      'バンドルされたテーマ名、または `version`、`name`、`modes`、`brands` を含むインラインテーマ定義。',
      'theme: clickhouse',
    ],
  ]}
/>

**デフォルト:** _なし (LibreChatのデフォルトテーマ、またはユーザー自身のテーマ)_

**例:**

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

インライン定義の形式、デフォルト値を持つすべての外観キー、ClickHouseリファレンステーマ、および共有リンクがどのようにテーマを選択するかについては、[Theme](/docs/configuration/librechat_yaml/object_structure/theme) を参照してください。

### ポリシーリンクの表示場所 [#where-the-policy-links-appear]

サインインおよび登録画面では、公開されたポリシーが「続行することで、利用規約に同意し、プライバシーポリシーを承認したものとみなされます。」という同意文として表示されます。ポリシーが1つだけ公開されている場合は、そのポリシーのみが文中に記載されます。登録画面では送信ボタンの下に、サインイン画面ではサインインオプションの下に配置されます。

チャットでは、ポリシーへのリンクは新しいチャットのウェルカム画面のメッセージボックスの下に表示され、会話が始まると非表示になります。

`externalUrl` が空または空白のポリシーは、公開されていないものとして扱われ、表示されることはありません。`termsOfService.modalAcceptance` が `true` の場合、ユーザーはサインイン後にダイアログで明示的に利用規約に同意するため、認証画面には同意文の代わりに通常のポリシーリンクが表示されます。

## prompts

> **権限管理のため非推奨となりました。** 起動時にデフォルトの `USER` ロールに対してのみ `PROMPTS` ロールの権限をシードします。ロール、グループ、ユーザーごとのプロンプト権限の管理には、[Admin Panel](/docs/features/admin_panel) を使用することを推奨します。

**キー:**

<OptionTable
  options={[
    [
      'prompts',
      'Boolean or Object',
      '全ユーザーのプロンプト関連機能を制御します。単純な有効/無効の切り替えにはブール値を、使用、作成、共有、公開範囲のきめ細かな制御にはオブジェクトを使用できます。',
      'When set to `false`, users will not have access to create, edit, or use custom prompts.',
    ],
  ]}
/>

**デフォルト:** `true`

**重要: ブール値とオブジェクトの設定について**

- **Boolean (`prompts: true`)**: `use` 権限のみを更新します。既存の `create`、`share`、および `public` 権限の値はデータベースから**保持**されます。管理パネルを通じて設定された他の設定に影響を与えることなく、シンプルな機能トグルとしてこれを使用してください。

- **Object**: 明示的に指定されたサブ権限のみを更新します。設定に含まれていない権限は、データベース内の既存の値が保持されます。

オブジェクト構造を使用する場合：

**サブキー:**

<OptionTable
  options={[
    ['use', 'Boolean', 'ユーザーがプロンプトを使用できるかどうかを制御します。', 'true'],
    ['create', 'Boolean', 'ユーザーが新しいプロンプトを作成できるかどうかを制御します。', 'true'],
    [
      'share',
      'Boolean',
      'ユーザーが特定のユーザーやグループとプロンプトを共有できるかどうかを制御します。',
      'false',
    ],
    [
      'public',
      'Boolean',
      'ユーザーがプロンプトを公開（全ユーザーに表示）できるかどうかを制御します。',
      'false',
    ],
  ]}
/>

**例 (boolean - シンプルな機能トグル):**

```yaml filename="interface / prompts (boolean)"
interface:
  prompts: true # Only updates USE; create/share/public remain unchanged
```

**例 (オブジェクト - 詳細な制御):**

```yaml filename="interface / prompts (object)"
interface:
  prompts:
    use: true
    create: false # Disable creation while allowing use
    # share and public not specified - preserves existing values
```

**例 (オブジェクト - 完全な制御):**

```yaml filename="interface / prompts (object)"
interface:
  prompts:
    use: true
    create: true
    share: true
    public: false
```

## autoSubmitFromUrl

  ]}
/>

**デフォルト:** `true` (明示的に無効化されない限り、既存の動作が維持されます)。

**注記:**
