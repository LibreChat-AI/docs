## Overzicht [#overview]

Het `ocr` object stelt je in staat om Optical Character Recognition (OCR) instellingen voor de applicatie te configureren, waardoor het extraheren van tekst uit afbeeldingen mogelijk wordt. Dit gedeelte biedt een gedetailleerd overzicht van de structuur van het `ocr` object.

There are 5 fields under `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Opmerkingen:**

- OCR is alleen actief wanneer `librechat.yaml` een `ocr`-sectie bevat. Alleen `OCR_API_KEY` instellen schakelt het niet in. Voor de gehoste API van Mistral is `strategy: "mistral_ocr"` plus `OCR_API_KEY` in `.env` voldoende, omdat `apiKey` en `baseURL` standaard `${OCR_API_KEY}` en `${OCR_BASEURL}` gebruiken (of `https://api.mistral.ai/v1` wanneer die niet is ingesteld).
- OCR wordt uitgevoerd op bestanden die als tekst zijn toegevoegd: Upload as Text in de chat en File Context in de Agent Builder. Agents hebben ook de `ocr`-capability nodig in `endpoints.agents.capabilities`, die standaard is opgenomen. Zonder deze capability wordt een geconfigureerde OCR-strategie de upload afwijzen met de melding "OCR capability is not enabled for Agents".
- Welke bestandstypen naar OCR worden gestuurd, wordt bepaald door [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr).
- De standaardstrategie is `mistral_ocr`. Wanneer `mistralModel` leeg is, wordt `mistral-ocr-latest` gebruikt.
- Azure-deployed Mistral OCR-modellen kunnen worden gebruikt door de strategie in te stellen op `azure_mistral_ocr`.
- Google Vertex AI-geïmplementeerde Mistral OCR-modellen kunnen worden gebruikt door de strategie in te stellen op `vertexai_mistral_ocr`.
  - Vereist dat de `GOOGLE_SERVICE_KEY_FILE` omgevingsvariabele is ingesteld met service account-inloggegevens
  - De service key kan worden verstrekt als: bestandspad, URL, base64-gecodeerde JSON of onbewerkte JSON-string
  - Project ID en locatie worden automatisch geëxtraheerd uit de service account-referenties
- Lokale tekstextractie is beschikbaar via `document_parser`, dat tekst extraheert uit PDF-, DOCX-, XLS/XLSX-, ODT- en ODS-bestanden tot 15 MB zonder externe API.
  - Gebruikt `pdfjs-dist`, `mammoth` en `SheetJS` lokaal, er is geen API-sleutel of basis-URL nodig
  - Alleen het `strategy` veld is vereist; `apiKey`, `baseURL` en `mistralModel` worden genegeerd
- `custom_ocr` wordt geaccepteerd door het schema, maar heeft nog geen implementatie.
- Omgevingsvariabele-parsing wordt ondersteund voor `apiKey`, `baseURL` en `mistralModel` parameters.

## Automatische documentverwerking (Geen configuratie vereist) [#automatic-document-parsing-no-configuration-required]

De ingebouwde `document_parser` wordt automatisch uitgevoerd voor het uploaden van bestanden door agents, **zelfs wanneer er geen `ocr` blok is geconfigureerd** in je `librechat.yaml`. Dit betekent dat PDF-, DOCX-, XLS/XLSX- en ODS-bestanden direct uit de doos worden geparseerd zonder enige configuratie.

De resolutielogica werkt als volgt:

1. **Geen `ocr`-configuratie aanwezig**: Wanneer een agent-contextbestand wordt geüpload en het MIME-type overeenkomt met een ondersteund documenttype (PDF, DOCX, Excel, ODS), wordt de `document_parser` direct gebruikt. Er is geen controle van de OCR-mogelijkheid voor de agent vereist.

2. **`ocr`-configuratie aanwezig**: De geconfigureerde strategie (bijvoorbeeld `mistral_ocr`) wordt eerst geprobeerd. Als de geconfigureerde strategie **tijdens runtime faalt**, wordt de `document_parser` als fallback gebruikt, zodat de tekstextractie nog steeds slaagt voor ondersteunde documenttypen.

3. **Geen van beide slaagt**: Als zowel de geconfigureerde strategie als de documentparser mislukken (bijvoorbeeld wanneer het bestand een pdf is die alleen afbeeldingen bevat zonder ingesloten tekst), wordt een foutmelding teruggegeven die aangeeft dat een OCR-service nodig is.

<Callout type="info">
De `document_parser` verwerkt alleen tekstgebaseerde documenten. Voor op afbeeldingen gebaseerde PDF's of gescande documenten heb je nog steeds een geconfigureerde OCR-strategie nodig (zoals `mistral_ocr`) om tekst uit de afbeeldingen in die bestanden te extraheren.
</Callout>

## Voorbeeld [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Voorbeeld met Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Voorbeeld met Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Voor Vertex AI implementeert u een Mistral OCR-model in uw Google Cloud-project, maakt u een serviceaccount aan dat het Vertex AI-endpoint kan aanroepen, en laat u `GOOGLE_SERVICE_KEY_FILE` verwijzen naar de sleutel ervan. De variabele accepteert een bestandspad, een URL waaruit de sleutel wordt opgehaald, base64-gecodeerde JSON, of de ruwe JSON-string:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Voorbeeld met lokale documentparser (geen externe API nodig):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Vertrouwde private host:poort uitzonderingen voor OCR connect-time SSRF-controles. Publieke bestemmingen blijven beschikbaar. Invoeren vereisen een poort en mogen geen URL\'s, paden, CIDR-bereiken, kale hosts of publieke IP-literals zijn.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

OCR-verzoeken blokkeren private, loopback, link-local en cloud-metadata bestemmingen op het moment van verbinding en schakelen redirects uit. `allowedAddresses` is een vrijstellingslijst voor exacte vertrouwde private `host:port`, `private.ip:port`, of `[ipv6]:port` doelen; het beperkt de toegang tot publieke bestemmingen niet.

<Callout type="warning" title="Vertrouw uitzonderingen zorgvuldig">
  Gebruik `allowedAddresses` alleen voor een private OCR-service die je zelf beheert. Een vrijgestelde hostnaam vertrouwt elk privaat adres waarnaar het op die poort wordt omgezet, dus geef waar mogelijk de voorkeur aan een privaat IP-literaal. Bij een forward proxy moet de proxy het SSRF-beleid voor de bestemming afdwingen; letterlijke private bestemmingen blijven geblokkeerd, tenzij ze expliciet zijn vrijgesteld.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'De te gebruiken OCR-strategie.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Beschikbare strategieën:**

- `mistral_ocr`: Gebruikt de OCR van Mistral via de standaard Mistral API.
- `azure_mistral_ocr`: Gebruikt Mistral OCR-modellen die zijn gedeployd op Azure AI Foundry. Stel `mistralModel` in op je deploymentnaam en `baseURL` op het deploymenteindpoint.
- `vertexai_mistral_ocr`: Maakt gebruik van Mistral OCR-modellen die zijn geïmplementeerd op Google Cloud Vertex AI, geauthenticeerd met `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Gebruikt lokale tekstextractie voor PDF-, DOCX-, XLS/XLSX- en OpenDocument-bestanden. Geen externe API nodig. Draait ook automatisch voor bestandsuploads van agents wanneer er geen `ocr` configuratie aanwezig is, en als fallback wanneer een geconfigureerde OCR-strategie faalt.
- `custom_ocr`: Gereserveerd voor een aangepaste OCR-service op `baseURL`. Nog niet geïmplementeerd.
