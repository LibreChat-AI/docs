## Voorbeeld [#example]

```yaml filename="MCP Servers Object Structure"
# Example MCP Servers Object Structure
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
  googlesheets:
    type: sse
    url: https://mcp.composio.dev/googlesheets/some-endpoint
    requiresOAuth: true
    headers:
      X-User-ID: '{{LIBRECHAT_USER_ID}}'
      X-API-Key: '${SOME_API_KEY}'
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
    # The “wrench” icon shows up if no icon is provided as it is the default rendering.
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-server:
    type: streamable-http
    url: https://example.com/api/
    proxy: '${MCP_PROXY_URL}'
  per-user-credentials-example:
    type: streamable-http
    url: 'https://example.com/api/'
    headers:
      X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    customUserVars:
      MY_SERVICE_API_KEY:
        title: 'My Service API Key'
        description: "Enter your personal API key for the service. You can generate one at <a href='https://myservice.example.com/developer/keys' target='_blank'>Service Developer Portal</a>."
        sensitive: true
      MY_SERVICE_PROJECT:
        title: 'Project ID'
        description: 'Enter the project ID used by this service.'
        sensitive: false
  oauth-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      authorization_url: https://example.com/oauth/authorize
      token_url: https://example.com/oauth/token
      client_id: your_client_id
      client_secret: your_client_secret
      redirect_uri: http://localhost:3080/api/mcp/oauth-example/oauth/callback
      scope: 'read execute'
  obo-example:
    type: streamable-http
    url: https://api.example.com/mcp/
    obo:
      scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
```

<Callout type="warning" title="Door processen ondersteunde servers zijn eigendom van de operator">
  MCP-servers die `type: stdio` gebruiken of procesvelden zoals `command`, `args`, `env`, `cwd` of `stderr` moeten worden geconfigureerd in `librechat.yaml`. De admin-configuratie-API wijst op processen gebaseerde vermeldingen af, en database- of per-principal-overschrijvingen kunnen een bestaande op processen gebaseerde server niet vervangen of verwijderen. Externe MCP-servers blijven de normale prioriteitsvolgorde voor configuratie-overschrijvingen volgen.
</Callout>

  Model-facing tool keys behouden letters, cijfers, `_`, `.`, en `-`; andere tekens in een servernaam worden vervangen door `_`. #### `title` [#title]

- **Type:** String (Optioneel)
- **Beschrijving:** Aangepaste weergavenaam voor de MCP server in de UI. Indien niet opgegeven, wordt de naam van de serversleutel gebruikt.
- **Validatie:** Moet beginnen met een Unicode-letter of -cijfer. De overige tekens mogen bestaan uit Unicode-letters, cijfers, combinatietekens, spaties, koppeltekens en rechte of gekrulde apostrofs.
- **Voorbeeld:**
  ```yaml
  my-server:
    title: 'File System Access'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `description` [#description]

- **Type:** String (Optioneel)
- **Beschrijving:** Beschrijving van de MCP server, die in de UI wordt weergegeven om gebruikers te helpen het doel en de mogelijkheden ervan te begrijpen.
- **Voorbeeld:**
  ```yaml
  my-server:
    title: 'File System Access'
    description: 'Provides read/write access to local files and directories'
    command: npx
    args: ['-y', '@modelcontextprotocol/server-filesystem']
  ```

#### `type` [#type]

- **Type:** String
- **Beschrijving:** Specificeert het verbindingstype met de MCP-server. Geldige opties zijn `"stdio"`, `"websocket"`, `"streamable-http"` of `"sse"`. `"http"` wordt geaccepteerd als alias van `"streamable-http"`.
- **Standaardwaarde:** Bepaald op basis van de aanwezigheid en het formaat van `url` of `command`.

#### `command` [#command]

- **Type:** String
- **Beschrijving:** (Voor het `stdio` type) Het commando of uitvoerbaar bestand dat moet worden uitgevoerd om de MCP server te starten.

#### `args` [#args]

- **Type:** Array of Strings
- **Beschrijving:** (Voor het `stdio`-type) Opdrachtregelargumenten die aan de `command` worden doorgegeven. Placeholders zoals `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}` en `{{CUSTOM_VARIABLE_NAME}}` worden in elk argument opgelost, net als in `env`.

#### `url` [#url]

- **Type:** String
- **Beschrijving:** (Voor `websocket`, `streamable-http` of `sse` type) De URL om verbinding te maken met de MCP server. Ondersteunt dynamische placeholders voor gebruikersvelden (`{{LIBRECHAT_USER_*}}`) en vervanging van omgevingsvariabelen (`${ENV_VAR}`).
- **Opmerkingen:**
  - Voor het type `sse` moet de URL beginnen met `http://` of `https://`.
  - Voor het type `streamable-http` moet de URL beginnen met `http://` of `https://`.
  - Voor het type `websocket` moet de URL beginnen met `ws://` of `wss://`.

#### `proxy` [#proxy]

- **Type:** String (Optioneel, voor `sse` en `streamable-http` types)
- **Beschrijving:** Outbound proxy-URL voor deze externe MCP-server. De waarde kan verwijzen naar omgevingsvariabelen met `${ENV_VAR}`.
- **Ondersteunde protocollen:** `http://`, `https://`, `socks://` en `socks5://`
- **Beveiligingsopmerking:** `proxy` wordt beheerd door de beheerder. Het lost omgevingsvariabelen op, maar lost geen door de gebruiker beheerde tijdelijke aanduidingen zoals `{{LIBRECHAT_USER_ID}}` of `customUserVars` op.
- **Voorbeeld:**
  ```yaml
  mcpServers:
    remote-api:
      type: streamable-http
      url: https://api.example.com/mcp
      proxy: '${MCP_PROXY_URL}'
  ```

#### `headers` [#headers]

- **Type:** Object (Optioneel, voor `sse` en `streamable-http` types)
- **Beschrijving:** Aangepaste headers om mee te sturen met het verzoek. Ondersteunt verschillende typen tijdelijke aanduidingen voor dynamische waardesubstitutie.
- **Ondersteuning voor tijdelijke aanduidingen (Placeholders):**
  - `{{LIBRECHAT_USER_ID}}`: Wordt vervangen door de ID van de huidige gebruiker, wat ondersteuning voor meerdere gebruikers mogelijk maakt.
  - `{{LIBRECHAT_USER_*}}`: Dynamische placeholders voor gebruikersvelden. Vervang `*` door de HOOFDLETTER-versie van elk toegestaan veld.
  - `{{LIBRECHAT_OPENID_*}}`: OpenID token/sessie-placeholders voor in YAML gedefinieerde servers.
  - `{{LIBRECHAT_GRAPH_*}}`: Microsoft Graph token-placeholders voor in YAML gedefinieerde servers.
  - `{{LIBRECHAT_BODY_*}}`: Request body placeholders voor in YAML gedefinieerde servers, zoals de huidige `conversationId`, `parentMessageId` of `messageId`.
  - `{{CUSTOM_VARIABLE_NAME}}`: Wordt vervangen door de waarde die door de gebruiker is opgegeven voor een variabele gedefinieerd in `customUserVars` (bijv. `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: Wordt vervangen door de waarde van de omgevingsvariabele `ENV_VAR`.

**Beschikbare tijdelijke aanduidingen voor gebruikersvelden:**

| Placeholder                           | User Field         | Type             | Description                                                 |

**Let op:** Ontbrekende velden worden vervangen door lege strings.

`{{LIBRECHAT_BODY_*}}` placeholders zijn request-scoped. LibreChat creëert de MCP-verbinding voor de actieve run, hergebruikt deze voor tool-aanroepen binnen die run en ruimt deze op wanneer het verzoek eindigt. Request-scoped servers worden uitgesloten van de persistente tool-cache, zodat verzoekspecifieke headers en URL's niet buiten de actieve run worden hergebruikt. Agent Builder koppelt de volledige server via één runtime-tools selectie en lost de tools op nadat een run body-waarden levert. Het voltooien van OAuth slaat de autorisatie op, maar stelt de verbinding uit totdat die request-context bestaat. `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}` en `{{LIBRECHAT_GRAPH_*}}` placeholders maken de server nog steeds user-scoped, maar HTTP-transports verversen opgeloste headers vóór elke tool-aanroep zonder zelf een herverbinding af te dwingen.

`{{LIBRECHAT_BODY_PARENTMESSAGEID}}` ontvangt het root-turn bovenliggende bericht in native Agent-chats, OpenAI-compatibele Agents API-verzoeken en legacy Assistants-runs. Open Responses-verzoeken hebben geen compatibel bovenliggend berichtmodel, dus een server die deze placeholder vereist, faalt gesloten op die interface; `previous_response_id` wordt er niet voor in de plaats gesteld.

OpenID access- en ID-tokens verlopen onafhankelijk van elkaar. `{{LIBRECHAT_OPENID_ACCESS_TOKEN}}` en het verouderde `{{LIBRECHAT_OPENID_TOKEN}}` gebruiken de opgeslagen verloopdatum van het access-token, terwijl `{{LIBRECHAT_OPENID_ID_TOKEN}}` een geldig ID-token vereist. Als een credential-token niet beschikbaar of verlopen is, retourneert LibreChat een actiegerichte `401` herauthenticatiefout in plaats van een lege of letterlijke bearer-waarde te verzenden; meld u opnieuw aan voordat u het opnieuw probeert. Voor een verzoek zonder OpenID-identiteit wordt een header die een van deze niet-opgeloste credential-placeholders bevat, volledig weggelaten. Identiteits-metadata-placeholders behouden hun bestaande gedrag voor lege waarden.

Vertrouwde operators kunnen het live OpenID-toegangstoken van de ingelogde gebruiker rechtstreeks doorgeven aan een in YAML gedefinieerde externe MCP-server:

```yaml
mcpServers:
  trusted-api:
    type: streamable-http
    url: https://mcp.example.com/mcp
    headers:
      Authorization: 'Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}'
```

Gebruik direct passthrough alleen wanneer de MCP server wordt vertrouwd om het upstream toegangstoken van de gebruiker te ontvangen. Expliciete MCP OAuth, [on-behalf-of exchange](#obo), en administrator API-key authenticatie krijgen voorrang op deze header. LibreChat lost het live sessietoken op voordat er verbinding wordt gemaakt en ververst de verbinding één keer na een `401` of `403`. Het voert de geweigerde tool-aanroep niet automatisch opnieuw uit, omdat de server deze mogelijk al heeft uitgevoerd; voer de tool bewust opnieuw uit nadat het herstel is geslaagd. Als het token niet kan worden ververst, moet de gebruiker opnieuw inloggen.

`{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` wisselt het herbruikbare OpenID-toegangstoken van de gebruiker uit voor een Microsoft Graph-token via de on-behalf-of-flow. De gevraagde scopes komen uit [`GRAPH_API_SCOPES`](/docs/configuration/dotenv#microsoft-graph-api--entra-id-integration), dat standaard `https://graph.microsoft.com/.default` is en los staat van `OPENID_GRAPH_SCOPES` (zoeken naar personen en groepen).

- **Voorbeeld:**
  ```yaml
  headers:
    X-User-ID: '{{LIBRECHAT_USER_ID}}'
    X-User-Email: '{{LIBRECHAT_USER_EMAIL}}'
    X-User-Role: '{{LIBRECHAT_USER_ROLE}}'
    X-API-Key: '${SOME_API_KEY}'
    Authorization: 'Bearer ${SOME_AUTH_TOKEN}'
  ```

#### `requestHeaders` [#requestheaders]

- **Type:** Object (Optioneel, voor `sse` en `streamable-http` types)
- **Beschrijving:** Headers worden alleen opgelost voor een actief chatverzoek. Ze gebruiken dezelfde placeholders als `headers`, worden samengevoegd over `headers` heen, en krijgen voorrang wanneer beide objecten dezelfde naam definiëren.
- **Discovery-gedrag:** Tool-discovery laat `requestHeaders` volledig weg, waardoor waarden die alleen voor verzoeken bedoeld zijn, zoals `{{LIBRECHAT_BODY_*}}`, de tool-catalogus van de server niet verbergen. De actieve run lost deze op en verstuurt ze wanneer er verbinding wordt gemaakt.

```yaml
requestHeaders:
  X-Conversation-ID: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
  X-Schedule-ID: '{{LIBRECHAT_BODY_SCHEDULEID}}'
```

#### `apiKey` [#apikey]

- **Type:** Object (Optioneel, voor `sse` en `streamable-http` types)
- **Beschrijving:** Configuratie van API-sleutelauthenticatie voor de MCP server. Biedt een gestructureerde manier om authenticatie op basis van API-sleutels te configureren.
- **Sub-keys:**
  - `source`: String (Required) - Where the API key comes from. Options:
    - `"admin"`: API-sleutel wordt geconfigureerd door de beheerder met `key`
    - `"user"`: API-sleutel wordt door de gebruiker verstrekt via de UI
  - `key`: String - (Voor `source: "admin"`) De API-sleutelwaarde, gedeeld door alle gebruikers. Ondersteunt `${ENV_VAR}`-verwijzingen. Bij `source: "admin"` wordt geen header verzonden wanneer `key` wordt weggelaten.
  - `authorization_type`: String (Verplicht) - Hoe de API-sleutel in verzoeken wordt verzonden. Opties:
    - `"bearer"`: Verzonden als `Authorization: Bearer <key>`
    - `"basic"`: Wordt verzonden als `Authorization: Basic <key>`
    - `"custom"`: Verzonden in een aangepaste header (vereist `custom_header`)
  - `custom_header`: String - (Wordt gebruikt wanneer `authorization_type` gelijk is aan `"custom"`) De naam van de header die voor de API-sleutel wordt gebruikt. Standaard `X-Api-Key` wanneer deze wordt weggelaten.
- **Voorbeeld:**

  ```yaml
  # Admin-provided API key with Bearer auth
  my-server:
    type: streamable-http
    url: https://api.example.com/mcp
    apiKey:
      source: 'admin'
      key: '${MY_SERVER_API_KEY}'
      authorization_type: 'bearer'

  # User-provided API key with custom header
  another-server:
    type: sse
    url: https://api.example.com/sse
    apiKey:
      source: 'user'
      authorization_type: 'custom'
      custom_header: 'X-API-Key'
  ```

Voor via de UI aangemaakte, gedeelde servers die `apiKey.source: user` gebruiken, zijn opgeslagen sleutels gekoppeld aan de genormaliseerde bestemming van het verzoek. Het wijzigen van het URL-pad of de query, de proxy, het transport, het autorisatieformaat of de autorisatieheader, of de geconfigureerde OAuth-client/-bestemming vereist dat gebruikers nieuwe sleutels invoeren; equivalente of cosmetische wijzigingen behouden ze. Bestaande legacy-sleutels blijven werken op hun ongewijzigde grens. Alleen momenteel gedeclareerde credentialvariabelen kunnen worden gesubstitueerd, ook in `requestHeaders`; een geïnjecteerde oude gegenereerde naam kan zijn sleutel niet hergebruiken. Voltooi de upgrade op **elke API-replica**, inclusief de configuratieschrijvers. Zie [Een server aanmaken vanuit de UI](/docs/features/mcp#create-a-server-from-the-ui) voor wat gebruikers zien.

#### `iconPath` [#iconpath]

- **Type:** String (Optioneel)
- **Beschrijving:** Definieert het weergave-icoon van de tool dat wordt getoond in het dialoogvenster voor toolselectie.

#### `chatMenu` [#chatmenu]

- **Type:** Boolean (Optioneel)
- **Beschrijving:** Wanneer ingesteld op `false`, wordt de server weggelaten uit de sectie **MCP Servers** van de chatcomposer, en worden chatverzoeken die de server noemen geweigerd. Agents kunnen de server nog steeds gebruiken, net als een modelspecificatie die de server vermeldt.
- **Standaardwaarde:** `true`
- **Voorbeeld:**
  ```yaml
  mcpServers:
    internal-tools:
      command: npx
      args: ['-y', 'internal-mcp-server']
      chatMenu: false # only available in the Agent Builder
  ```

#### `serverInstructions` [#serverinstructions]

- **Type:** Boolean of String (Optioneel)
- **Beschrijving:** Bepaalt hoe MCP server-instructies worden geïnjecteerd in de context van de agent. Server-instructies bieden gebruiksrichtlijnen op hoog niveau voor de gehele MCP server, als aanvulling op de individuele tool-beschrijvingen.
- **Opties:**
  - **`undefined`** (standaard): Er zijn geen instructies opgenomen
  - **`true`**: Gebruik door de server verstrekte instructies (indien beschikbaar) - ideaal voor goed gedocumenteerde servers met uitgebreide richtlijnen
  - **`false`**: Schakel instructies expliciet uit - handig om context-tokens te besparen of wanneer tools voor zichzelf spreken
  - **`string`**: Gebruik aangepaste instructies (overschrijft de door de server verstrekte instructies) - het beste voor applicatiespecifieke workflows of wanneer serverinstructies onvoldoende zijn
- **Standaardwaarde:** `undefined` (geen instructies inbegrepen)
- **Opmerkingen:**
  - Instructies worden automatisch geïnjecteerd wanneer `serverInstructions` is geconfigureerd en de tools van de server beschikbaar zijn voor de agent.
  - Meerdere servers kunnen elk instructies bijdragen aan de agent-context
  - LibreChat slaat door de server geadverteerde tekst apart op van de geconfigureerde declaratie. Inspectie vervangt `true` of een door de operator geschreven string niet, en Redis-ondersteunde registervermeldingen van eerdere builds worden automatisch ververst tijdens de initialisatie.
- **Voorbeeld:**

  ```yaml
  # Use server-provided instructions
  serverInstructions: true

  # Use custom instructions
  serverInstructions: |
    When using this filesystem server:
    1. Always use absolute paths for file operations
    2. Check file permissions before attempting write operations

  # Explicitly disable instructions
  serverInstructions: false
  ```

#### `env` [#env]

- **Type:** Object (Optioneel, alleen `stdio` type)
- **Beschrijving:** Omgevingsvariabelen die moeten worden gebruikt bij het starten van het proces.
- **Ondersteuning voor tijdelijke aanduidingen (Placeholders):**
  - `{{LIBRECHAT_USER_ID}}`: Vervangen door het ID van de huidige gebruiker.
  - `{{LIBRECHAT_USER_*}}`: Dynamische tijdelijke aanduidingen voor gebruikersvelden (bijv. `{{LIBRECHAT_USER_EMAIL}}`).
  - `{{CUSTOM_VARIABLE_NAME}}`: Wordt vervangen door de waarde die door de gebruiker is opgegeven voor een variabele gedefinieerd in `customUserVars` (bijv. `{{MY_API_KEY}}`).
  - `${ENV_VAR}`: Wordt vervangen door de waarde van de server-side omgevingsvariabele `ENV_VAR`.

#### `timeout` [#timeout]

- **Type:** Geheel getal (Optioneel)
- **Beschrijving:** Time-out in milliseconden voor verzoeken aan de MCP-server, inclusief toolaanroepen. Moet een niet-negatief geheel getal zijn.
- **Standaardwaarde:** `60000` (60 seconden)
- **Opmerking:** Als lange toolaanroepen nog steeds worden afgekapt, controleer dan de time-outs van elke reverse proxy die voor LibreChat of de MCP-server staat (nginx, Traefik, enzovoort).
- **Voorbeeld:**
  ```yaml
  mcpServers:
    data-processor:
      type: streamable-http
      url: https://api.example.com/mcp
      initTimeout: 15000 # 15 seconds to connect
      timeout: 60000 # 60 seconds per tool call
  ```

#### `initTimeout` [#inittimeout]

- **Type:** Geheel getal (Optioneel)
- **Beschrijving:** Timeout in milliseconden voor de initialisatie van de MCP-server. Moet een niet-negatief geheel getal zijn. Deze waarde beperkt niet hoe lang een gebruiker heeft om een OAuth-aanmelding te voltooien; dat is `MCP_OAUTH_HANDLING_TIMEOUT` (zie [OAuth callback URL](#oauth-callback-url)).
- **Standaardwaarde:** `30000` (30 seconden)

#### `requiresOAuth` [#requiresoauth]

- **Type:** Boolean (Optioneel, alleen voor externe transports: `sse`, `streamable-http`, `websocket`)
- **Beschrijving:** Of deze server OAuth-authenticatie vereist. Indien niet gespecificeerd, wordt dit automatisch gedetecteerd tijdens het opstarten van de server. Hoewel optioneel, is het het beste om deze waarde expliciet in te stellen als u weet of de server OAuth vereist of niet.
- **Standaardwaarde:** Automatisch gedetecteerd indien niet gespecificeerd
- **Opmerkingen:**
  - Van toepassing op remote (URL-gebaseerde) transports: `sse`, `streamable-http` en `websocket`. Het heeft geen effect op `stdio` servers, die geen URL hebben om tegen te authenticeren.
  - Auto-detectie vindt plaats tijdens het opstarten van de server, wat de initialisatietijd kan verlengen.
  - Expliciete configuratie verbetert de opstartprestaties door detectie over te slaan
  - Stel `requiresOAuth: false` in voor servers die alleen worden beveiligd door een statische `Authorization` header (bijv. een Bearer API-sleutel). Automatische detectie onderzoekt de server _zonder_ uw geconfigureerde headers, waardoor een server die antwoordt met een `401` met een `WWW-Authenticate: Bearer` challenge onterecht als OAuth-beveiligd kan worden geclassificeerd; deze vlag omzeilt die controle en laat uw statische header de verbinding normaal verifiëren.
  - Werkt met MCP OAuth omgevingsvariabelen (`MCP_OAUTH_ON_AUTH_ERROR`, `MCP_OAUTH_DETECTION_TIMEOUT`, `MCP_OAUTH_HANDLING_TIMEOUT`, `MCP_OAUTH_FLOW_TTL`) voor verbeterd verbindingsbeheer

#### OAuth-verversingscoördinatie [#oauth-refresh-coordination]

Voor deployments met meerdere replica's serialiseert `oauthRefreshCoordination: true` het vernieuwen van tokens via de gedeelde Redis-instantie. `oauthRefreshWaitTimeout` bepaalt hoe lang een replica wacht op het resultaat van het vernieuwen, en `oauthPersistenceWaitTimeout` bepaalt hoe lang een replica wacht totdat de vernieuwde credentials leesbaar zijn; beide hebben standaard de waarde `15000` milliseconden. `oauthRefreshWaitTimeout` wordt beperkt tot een maximum van `30000`, en `oauthPersistenceWaitTimeout` accepteert maximaal `840000` (14 minuten).

Schakel coördinatie pas in nadat elke replica is geüpgraded en verbonden met dezelfde Redis-implementatie. Gebruik identieke waarden op elke replica, voer actieve verzoeken af voordat de instelling wordt gewijzigd en vermijd het in- of uitschakelen tijdens een rolling deployment.

#### `stderr` [#stderr]

- **Type:** String of Integer (Optioneel, alleen `stdio` type)
- **Beschrijving:** Hoe om te gaan met `stderr` van het onderliggende proces. Dit komt overeen met de semantiek van Node's [`child_process.spawn`](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options). Geldige stringwaarden: `"pipe"`, `"ignore"`, `"inherit"`. Als alternatief kan een niet-negatief geheel getal worden gebruikt als bestandsdescriptor.
- **Standaardwaarde:** `"inherit"` (berichten naar `stderr` worden afgedrukt naar de `stderr` van het bovenliggende proces).

#### `customUserVars` [#customuservars]

- **Type:** Object (Optioneel)
- **Beschrijving:** Definieert aangepaste variabelen die gebruikers kunnen instellen voor deze MCP server. Hiermee kunnen beheerders variabelen opgeven (bijv. API-sleutels, URL's) die elke gebruiker individueel moet configureren. Deze door de gebruiker verstrekte waarden kunnen vervolgens worden gebruikt in `headers` of `env` configuratie. Servers met `customUserVars` worden automatisch uitgesloten van verbindingen op app-niveau, waardoor wordt gegarandeerd dat inloggegevens per gebruiker altijd tijdens runtime worden opgelost.
- **Structuur:**
  - Het `customUserVars` object bevat keys, waarbij elke key een variabelenaam vertegenwoordigt (bijv. `MY_API_KEY`). Deze naam wordt gebruikt in placeholders zoals `{{MY_API_KEY}}`.
  - Elke variabelenaam is een object met de volgende subkeys:
    - `title`: String (Vereist) - Een gebruiksvriendelijke titel voor de variabele, weergegeven in de configuratie-UI.
    - `description`: String (Verplicht) - Een beschrijving of instructies voor de variabele, die ook in de gebruikersinterface wordt weergegeven om de gebruiker te begeleiden. HTML kan in dit veld worden gebruikt (bijvoorbeeld om een link te maken: `<a href="https://example.com" target="_blank">More info</a>`).
    - `sensitive`: Boolean (Optioneel) - Bepaalt of de waarde als een geheim wordt behandeld en gemaskeerd in de UI. Standaard is dit gemaskeerd/geheim wanneer weggelaten; zet op `false` voor niet-geheime velden zoals project-ID's of basis-URL's.
- **Gebruik in `headers` en `env`:**
  - Zodra deze variabelen zijn gedefinieerd onder `customUserVars`, kunnen ze worden verwezen in de `headers` (voor `sse` en `streamable-http` types) of `env` (voor `stdio` type) secties met behulp van de `{{VARIABLE_NAME}}` syntaxis.
  - Gebruikers vullen deze waarden in wanneer ze voor het eerst verbinding maken met de server, en kunnen ze later wijzigen met **Configure** in de chatinvoer of in **MCP Settings**. Zie [Credentials and variables](/docs/features/mcp#credentials-and-variables).
  - Deze door de gebruiker opgegeven waarden worden per gebruiker en per MCP-server opgeslagen en tijdens runtime ingevuld.
  - Als de variabelen niet beschikbaar zijn wanneer LibreChat start (bijvoorbeeld een GitHub personal access token), kun je ook [`startup: false`](#startup) instellen, zodat LibreChat pas probeert verbinding te maken wanneer een gebruiker dat doet.
- **Voorbeeld:**
  ```yaml
  customUserVars:
    MY_SERVICE_API_KEY:
      title: 'My Service API Key'
      description: "Your personal API access key for My Service. Find it at <a href='https://myservice.example.com/settings/api' target='_blank'>My Service API Settings</a>."
      sensitive: true
    SOME_OTHER_VAR:
      title: 'Some Other Variable'
      description: 'The specific value for some other configuration (e.g., a specific path or identifier).'
      sensitive: false
  ```
  Gebruik in `headers`:
  ```yaml
  headers:
    X-Auth-Token: '{{MY_SERVICE_API_KEY}}'
    X-Some-Other-Config: '{{SOME_OTHER_VAR}}'
  ```
  Usage in `env` (for `stdio` type):
  ```yaml
  env:
    API_KEY: '{{MY_SERVICE_API_KEY}}'
  ```

#### `obo` [#obo]

- **Type:** Object (Optioneel, alleen voor `sse` en `streamable-http` types)
- **Beschrijving:** Configureert OAuth 2.0 On-Behalf-Of token-uitwisseling voor een MCP server. LibreChat wisselt het OpenID-toegangstoken van de ingelogde gebruiker in voor een gedelegeerd downstream-token met de geconfigureerde scopes, en stuurt dat token vervolgens door naar de MCP server als een `Authorization: Bearer ...` header.
- **Vereiste subkeys:**
  - `scopes`: String - Niet-lege scopes aangevraagd voor de downstream token-uitwisseling.
- **Validatie:**
  - `obo` is alleen geldig voor `sse` en `streamable-http` MCP servers.
  - `obo` wordt geweigerd voor `stdio` en `websocket` servers.
  - Gebruikers hebben de `MCP_SERVERS.CONFIGURE_OBO` roltoestemming nodig om dit veld te configureren. Voorzie het van een beginwaarde met [`interface.mcpServers.configureObo`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers) of beheer het vanuit het beheerderspaneel.
- **Vereisten:**
  - OpenID-authenticatie moet worden geconfigureerd met herbruikbare toegangstokens.
  - Je identiteitsprovider en downstream-applicatie moeten het gevraagde gedelegeerde bereik toestaan.
- **Voorbeeld:**
  ```yaml
  mcpServers:
    enterprise-tools:
      type: streamable-http
      url: https://api.example.com/mcp/
      obo:
        scopes: 'api://mcp-server-id/Mcp.Tools.ReadWrite'
  ```

Zie [OpenID Connect Token Reuse](/docs/configuration/authentication/OAuth2-OIDC/token-reuse) en [SharePoint Integration](/docs/configuration/sharepoint) voor gerelateerde instellingen voor token-hergebruik en gedelegeerde tokens.

#### `oauth` [#oauth]

- **Type:** Object (Optioneel)
- **Beschrijving:** OAuth2-configuratie voor authenticatie met de MCP server. Wanneer geconfigureerd, worden gebruikers gevraagd om te authenticeren via een OAuth-flow voordat de MCP server kan worden gebruikt. Als er geen client id & client secret worden verstrekt, zal Dynamic Client Registration (DCR) worden gebruikt.
- **Subkeys:** Alle `oauth`-subkeys zijn optioneel. Endpoints kunnen automatisch worden ontdekt en een client kan worden verkregen via Dynamic Client Registration.
  - `authorization_url`: String - De URL van het OAuth-autorisatie-endpoint
  - `token_url`: String - De OAuth token endpoint URL
  - `client_id`: String - OAuth client-identificatie
  - `client_secret`: String - OAuth-clientgeheim
  - `redirect_uri`: String - [OAuth redirect-URI](#oauth-callback-url) (bijv. `http://localhost:3080/api/mcp/${serverName}/oauth/callback`)
  - `scope`: String - OAuth scopes (gescheiden door spaties)
- **Aanvullende subsleutels:**
  - `grant_types_supported`: Array of Strings - Ondersteunde grant types (standaard `["authorization_code", "refresh_token"]`)
  - `token_endpoint_auth_methods_supported`: Array of Strings - Ondersteunde authenticatiemethoden voor het token-endpoint (standaard ingesteld op `["client_secret_basic", "client_secret_post"]`)
  - `token_exchange_method`: String - Optionele overschrijving voor token-uitwisseling. Gebruik `default_post` om client-inloggegevens in de form-encoded POST-body te verzenden, of `basic_auth_header` om ze in een HTTP Basic-autorisatieheader te verzenden. Indien weggelaten, detecteert LibreChat de geadverteerde authenticatiemethoden voor het token-eindpunt van de provider en gebruikt standaard Basic auth als er geen worden geadverteerd.
  - `response_types_supported`: Array of Strings - Ondersteunde responstypes (standaard `["code"]`)
  - `code_challenge_methods_supported`: Array van Strings - Ondersteunde PKCE code challenge methoden (standaard `["S256", "plain"]`)
  - `skip_code_challenge_check`: Boolean - Sla het controleren of de OAuth-provider PKCE-ondersteuning adverteert over. Handig voor providers zoals AWS Cognito die S256 ondersteunen, maar dit niet adverteren in hun metadata. (standaard is `false`)
  - `revocation_endpoint`: String - Token-intrekkingsendpoint-URL. Wordt automatisch ontdekt wanneer deze wordt weggelaten.
  - `revocation_endpoint_auth_methods_supported`: Array van Strings - Authenticatiemethoden die worden ondersteund door het revocation endpoint. Wordt automatisch ontdekt wanneer dit wordt weggelaten.
  - `audience`: String - Wordt verzonden als de `audience`-parameter in het autorisatieverzoek, voor providers zoals Auth0 die alleen API-gebonden tokens uitgeven wanneer een audience wordt opgevraagd. Alleen voor beheerders: wordt geweigerd voor servers die gebruikers in de UI aanmaken.
  - `forward_audience_on_refresh`: Boolean - Of `audience` ook wordt meegestuurd bij de `refresh_token`-grant. Standaard `true`, wat Auth0 nodig heeft. Stel in op `false` voor providers met strikte token-endpoints, zoals AWS Cognito, die de extra parameter afwijzen. Wordt genegeerd wanneer `audience` niet is ingesteld. Alleen voor beheerders.
  - `send_resource_parameter`: Boolean - Of de RFC 8707-parameter `resource` wordt meegestuurd bij het autorisatieverzoek, de uitwisseling van de code en de refresh-grant. Standaard `true`. Stel in op `false` voor providers die deze parameter weigeren, zoals Microsoft Entra ID v2.0, dat faalt met `AADSTS9010010` wanneer zowel `resource` als `scope` worden meegestuurd. Gebruik in plaats daarvan `scope` of `audience` om een API-gescopeerd token te verkrijgen. Alleen voor beheerders.
- **Omgevingsvariabelen:** YAML-gedefinieerde OAuth URL-velden, inclusief `authorization_url`, `token_url`, `redirect_uri` en `revocation_endpoint`, kunnen `${ENV_VAR}` referenties gebruiken. LibreChat lost de omgevingswaarde op vóór URL-validatie. Door de gebruiker beheerde OAuth endpoint URL's die via de UI worden ingediend, moeten letterlijke URL's zijn en wijzen `${ENV_VAR}` placeholders af.
- **Voorbeeld:**

  ```yaml
  oauth-api-server:
    authorization_url: https://api.example.com/oauth/authorize
    token_url: https://api.example.com/oauth/token
    client_id: your_client_id
    client_secret: your_client_secret
    redirect_uri: http://localhost:3080/api/mcp/oauth-api-server/oauth/callback
    scope: 'read execute'
    grant_types_supported: ['authorization_code', 'refresh_token']
    token_endpoint_auth_methods_supported: ['client_secret_post']
    token_exchange_method: default_post
    response_types_supported: ['code']
    code_challenge_methods_supported: ['S256', 'plain']
  ```

  Auth0-voorbeeld:

  ```yaml
  auth0-server:
    type: streamable-http
    url: https://api.example.com/mcp/
    oauth:
      audience: https://api.example.com
      scope: 'read:data offline_access'
  ```

Wanneer zowel `token_exchange_method` als `token_endpoint_auth_methods_supported` worden weggelaten voor een vooraf geconfigureerd client secret, staat LibreChat maximaal vijf seconden toe voor het ontdekken van metadata voor protected-resource en authorization-server. Het gebruikt geadverteerde mogelijkheden alleen wanneer het ontdekte token-endpoint exact overeenkomt met de geconfigureerde `token_url`; discovery kan de geconfigureerde client-referenties niet omleiden naar een ander endpoint. Stel `token_exchange_method` expliciet in wanneer een provider geen bruikbare metadata publiceert of een geforceerde methode vereist.

Server-side OAuth discovery, registratie, token en intrekking HTTP-verzoeken volgen **geen** redirects, zelfs niet als de oorspronkelijke URL is toegestaan. Configureer het uiteindelijke endpoint van de provider direct wanneer deze doorverwijst. Bestemmingen met private IP-literals worden geblokkeerd, tenzij expliciet toegestaan door het beleid van de beheerder voor vertrouwde hosts of exacte adres-en-poortcombinaties. Deze beperking is van toepassing op server-side OAuth HTTP-verzoeken; het verhindert de browser van de gebruiker niet om de normale autorisatiepagina-redirect te voltooien.

#### `oauth_headers` [#oauth_headers]

- **Type:** Object (Optioneel)
- **Beschrijving:** Headers die specifiek worden gebruikt voor OAuth-stroomverzoeken. Deze headers worden gebruikt tijdens OAuth-authenticatie, zoals dynamische clientregistratie en token-uitwisseling, en worden niet verzonden tijdens reguliere MCP-servercommunicatie.
- **Veelvoorkomende gebruiksscenario's:**
  - Authenticatie toevoegen aan dynamic client registration endpoints, zoals `Authorization: Bearer ${DCR_API_KEY}`
  - Inclusief aangepaste provider-specifieke headers die vereist zijn voor OAuth-flows
  - Headers instellen die nodig zijn voor OAuth-token-endpoints
- **Placeholder-ondersteuning:** Waarden accepteren `{{LIBRECHAT_USER_*}}`-placeholders en `${ENV_VAR}`-verwijzingen, net als de tekstvelden onder `oauth`.
- **Belangrijkste verschillen met `headers`:**
  - **`headers`**: Wordt verzonden met reguliere MCP-serververzoeken nadat de authenticatie is voltooid
  - **`oauth_headers`**: Wordt alleen verzonden tijdens OAuth-authenticatiestromen
- **Voorbeeld:**
  ```yaml
  oauth_headers:
    Authorization: "Bearer ${DCR_API_KEY}"
    X-Custom-Header: "custom_value"
  ```

#### `oauthPrompt` [#oauthprompt]

- **Type:** String (Optioneel)
- **Beschrijving:** Bepaalt wanneer een gebruiker wordt gevraagd in te loggen bij een server die beveiligd is met OAuth.
  - `on_start`: de inlogprompt verschijnt wanneer de gespreksbeurt begint, voordat de agent wordt uitgevoerd.
  - `on_use`: de beurt begint zonder prompt, en de agent vindt de tools van de server via tool search. De prompt verschijnt wanneer de agent voor het eerst een van de tools van de server aanroept, en de run wacht tot de gebruiker is ingelogd.
- **Standaardwaarde:** `on_start`
- **Opmerkingen:**
  - `on_use` is alleen van toepassing wanneer elke tool die de agent uit de server heeft geselecteerd [uitgesteld](/docs/features/agents#deferred-tools) is ("Defer" aan). Als een geselecteerde tool vooraf wordt geladen, of de agent de volledige server selecteert in plaats van afzonderlijke tools, blijft de prompt bij de start van de beurt.
  - De `deferred_tools` [agentfunctie](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) moet zijn ingeschakeld. Wanneer de functie `run_in_background` is ingeschakeld, behoudt een geselecteerde tool die kiest voor achtergronduitvoering de prompt aan het begin van de beurt, omdat een losgekoppelde aanroep niet kan wachten op een aanmelding.
  - `on_use` vereist een gedeclareerde [`oauthToolCatalog`](#oauthtoolcatalog). Zonder die catalogus behoudt de server de prompt aan het begin van de beurt, ook voor een gebruiker die eerder verbinding heeft gemaakt.
  - De tools die vóór het inloggen worden aangeboden, moeten elke geselecteerde tool bevatten, anders blijft de prompt bij de start van de beurt. Dat is de gedeclareerde catalogus, of de eigen toollijst van de gebruiker wanneer een eerdere verbinding er een heeft achtergelaten.
  - Alleen door de operator geconfigureerde servers komen hiervoor in aanmerking: servers die zijn gedefinieerd in `librechat.yaml` of die zijn toegevoegd via [beheerdersconfiguratie-overschrijvingen](/docs/configuration/admin_panel#configuration-overrides). Servers die gebruikers in de UI aanmaken, behouden de prompt aan het begin van de beurt. De prompt blijft aan het begin van de beurt staan voor een server die `obo`, `customUserVars`, `requestHeaders` of placeholders per gebruiker of per verzoek (`{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, `{{LIBRECHAT_BODY_*}}`) gebruikt in de verbindingsinstellingen.
  - Geldt of OAuth vooraf is geconfigureerd (`oauth`, `requiresOAuth: true`) of wordt gedetecteerd wanneer de server de verbinding weigert.
  - Niet beschikbaar op servers die gebruikers in de UI aanmaken.
- **Voorbeeld:**
  ```yaml
  mcpServers:
    google-sheets:
      type: streamable-http
      url: https://sheets.example.com/mcp
      requiresOAuth: true
      oauthPrompt: on_use
      oauthToolCatalog:
        - name: read_sheet
          description: Read the values in a spreadsheet range
  ```

#### `oauthToolCatalog` [#oauthtoolcatalog]

- **Type:** Array van objecten (optioneel)
- **Beschrijving:** De tools die een `oauthPrompt: on_use`-server aanbiedt aan tool search voordat een gebruiker zich aanmeldt. LibreChat kan de tools van een beveiligde server niet tonen aan een gebruiker die zich nog niet heeft aangemeld, daarom geeft de beheerder ze hier op. De catalogus is voor elke gebruiker hetzelfde; de verbinding van geen enkele gebruiker bepaalt welke agents van andere gebruikers zien. Zodra een gebruiker zich heeft aangemeld, worden de eigen tooldefinities van de server gebruikt, en de server valideert elke aanroep.
- **Invoervelden:**
  - `name`: String (Verplicht) - De naam van de tool op de server, zoals de agent deze selecteert.
  - `description`: String (Optioneel) - Wat de tool doet, wordt getoond aan de toolzoekfunctie en het model.
  - `inputSchema`: Object (Optioneel) - De parameters van de tool:
    - `type`: moet `object` zijn
    - `properties`: map van parameternaam naar een eigenschapsschema
    - `required`: array met verplichte parameternamen
- **Eigenschappenschema:** een begrensde subset van JSON Schema met uitsluitend deze sleutels:
  - `type`: een van `string`, `number`, `integer`, `boolean`, `object`, `array`, `null`, of een niet-lege lijst daarvan
  - `description`: String
  - `enum`: niet-lege array van strings, numbers, booleans of `null`
  - `default`: een string, getal, boolean of `null`
  - `items`: voor arrays, een object met `type`, `description` en `enum`
- **Opmerkingen:**
  - Validatie is strikt. Een verkeerd gespelde invoersleutel (zoals `input_schema`) of een trefwoord buiten het begrensde schema (zoals `minLength`, `pattern` of `$ref`) veroorzaakt een fout bij de configuratievalidatie in plaats van dat het wordt genegeerd.
  - Een gebruiker wiens eerdere verbinding een toollijst heeft achtergelaten, krijgt in plaats daarvan die lijst aangeboden; in beide gevallen moet deze alle tools bevatten die de agent van de server heeft geselecteerd, anders blijft de prompt bij het begin van de beurt staan.
  - Niet beschikbaar op servers die gebruikers in de UI aanmaken.
- **Voorbeeld:**
  ```yaml
  oauthToolCatalog:
    - name: read_sheet
      description: Read the values in a spreadsheet range
      inputSchema:
        type: object
        properties:
          range: { type: string }
        required: [range]
  ```

#### `startup` [#startup]

- **Type:** Boolean (Optioneel)
- **Beschrijving:** Wanneer ingesteld op `false`, zal deze MCP server niet worden verbonden bij het opstarten van de applicatie. Dit is nuttig voor servers die gebruikersinvoer of configuratie vereisen voordat ze verbinding maken, of voor gevallen waarin u wilt bepalen wanneer de server wordt geïnitialiseerd.
- **Standaardwaarde:** `true`
- **Voorbeeld:**
  ```yaml
  mcpServers:
    my-mcp-server:
      type: streamable-http
      url: 'https://api.example.com/mcp/'
      startup: false
  ```

### Opmerkingen [#notes]

- **Type-inferentie:**
  - Als `type` wordt weggelaten:
    - Als `url` is opgegeven en begint met `http://` of `https://`, dan is de standaardwaarde voor `type` `sse`.
    - Als `url` is opgegeven en begint met `ws://` of `wss://`, dan is `type` standaard `websocket`.
    - Als `command` is opgegeven, is de standaardwaarde voor `type` `stdio`.
- **Verbindingstypen:**
  - **`stdio`**: Start een MCP-server als een onderliggend proces en communiceert via standaard invoer/uitvoer.
  - **`websocket`**: Maakt verbinding met een externe MCP-server via WebSocket.
  - **`sse`**: Maakt verbinding met een externe MCP-server via Server-Sent Events (SSE).
  - **`streamable-http`**: Maakt verbinding met een externe MCP-server via HTTP met ondersteuning voor streaming-antwoorden.
  - `stdio` draait één proces op de LibreChat-host en is geschikt voor lokale installaties met één gebruiker. `sse` is de oudere externe transportmethode. Voor installaties met meerdere gebruikers of productieomgevingen gebruik je `streamable-http`.
- **Interne/Lokale Adressen:**
  - **Belangrijk**: MCP-servers die interne IP-adressen (bijv. `172.24.1.165`, `192.168.1.100`) of lokale domeinen (bijv. `mcp-server`, `host.docker.internal`) gebruiken, **moeten** expliciet worden toegestaan. Gebruik [`mcpSettings.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#allowedaddresses) voor specifieke private host:port-services wanneer je wilt dat publieke bestemmingen bereikbaar blijven, of [`mcpSettings.allowedDomains`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#alloweddomains) wanneer je een strikte whitelist wilt hanteren.
  - Zie [MCP Settings](/docs/configuration/librechat_yaml/object_structure/mcp_settings) voor configuratiedetails.

## OAuth callback-URL [#oauth-callback-url]

Wanneer een server OAuth gebruikt, stuurt de provider terug naar LibreChat op:

```text
${DOMAIN_SERVER}/api/mcp/<server-name>/oauth/callback
```

`<server-name>` is de sleutel onder `mcpServers`. Bijvoorbeeld: een server met de naam `salesforce` en `DOMAIN_SERVER=https://chat.example.com` gebruikt `https://chat.example.com/api/mcp/salesforce/oauth/callback`. Een lokale Docker-installatie gebruikt meestal `http://localhost:3080` als basis. Voor servers die in de UI zijn aangemaakt, neemt de gegenereerde identifier van de server de plaats van de sleutel in, en LibreChat toont de volledige **Redirect URI** nadat de server is aangemaakt.

Registreer deze exacte URL bij de OAuth-provider. Andere LibreChat-callbackpaden, zoals `/api/oauth/callback` of `/api/oauth/openid/callback`, werken niet voor MCP.

Als de provider dynamische clientregistratie ondersteunt, hoeft de server helemaal geen `oauth`-blok te bevatten; LibreChat registreert zichzelf als client de eerste keer dat een gebruiker verbinding maakt:

```yaml
mcpServers:
  # No refresh tokens: users sign in again when the token expires
  paypal:
    type: sse
    url: https://mcp.paypal.com/sse
    initTimeout: 150000
  # Issues refresh tokens: LibreChat renews access automatically
  spotify:
    type: streamable-http
    url: https://mcp-spotify-oauth-example.account.workers.dev/mcp
    initTimeout: 150000
```

Gebruikers hebben 10 minuten de tijd om het inloggen af te ronden, en LibreChat bewaart de openstaande flow gedurende 15 minuten. Pas deze waarden aan met `MCP_OAUTH_HANDLING_TIMEOUT` en `MCP_OAUTH_FLOW_TTL` in `.env` (zie [MCP-omgevingsvariabelen](/docs/configuration/dotenv#mcp-model-context-protocol)). De flow-TTL blijft altijd minstens één minuut langer dan de verwerkingstimeout, zodat een callback die vlak voor de deadline binnenkomt, nog steeds zijn flow vindt.

## Servers aangemaakt in de UI [#servers-created-in-the-ui]

Gebruikers van wie de rol de `CREATE`-permissie heeft (zie [`interface.mcpServers`](/docs/configuration/librechat_yaml/object_structure/interface#mcpservers)) kunnen servers toevoegen via **MCP-instellingen** zonder dit bestand te bewerken. Deze servers worden opgeslagen in de database en verschillen op een paar punten van YAML-servers:

- Alleen externe transporten (`streamable-http` en `sse`) zijn beschikbaar. `stdio`-servers moeten hier worden gedefinieerd.
- `${ENV_VAR}`, `{{LIBRECHAT_USER_*}}`, `{{LIBRECHAT_OPENID_*}}`, `{{LIBRECHAT_GRAPH_*}}`, en `{{LIBRECHAT_BODY_*}}`-placeholders worden uit hun headers verwijderd, omdat de server mogelijk met andere gebruikers wordt gedeeld. Alleen `customUserVars`-placeholders blijven behouden.
- OAuth-endpoint-URL's moeten letterlijke URL's zijn; `${ENV_VAR}`-verwijzingen worden geweigerd.
- Het kiezen van een API-sleutel die elke gebruiker zelf opgeeft, maakt een `customUserVars`-item aan met de naam `MCP_API_KEY_<hash>` en de bijbehorende header. Servers die vóór deze wijziging zijn opgeslagen, kunnen de oude naam `MCP_API_KEY` behouden totdat hun URL of authenticatie verandert. Zie [`apiKey`](#apikey) voor welke wijzigingen ervoor zorgen dat gebruikers hun sleutel opnieuw moeten invoeren.
- Een server met een API-sleutel (gedeeld of per gebruiker) wordt behandeld als API-sleutelauthenticatie en slaat OAuth-automatische detectie over, tenzij deze ook een OAuth-configuratie heeft. Als een server met API-sleutel die door een oudere versie is opgeslagen op **Needs Auth** blijft staan, bewerk en sla deze dan één keer op om de opgeslagen metadata te vernieuwen.
- Opgeslagen OAuth-clients en tokens zijn gekoppeld aan de server-URL en de instellingen van de OAuth-client en het endpoint. Als deze wijzigen, moeten gebruikers opnieuw inloggen. Bovendien moet de editor een opgeslagen clientgeheim opnieuw invoeren wanneer de URL, de client-ID, de autorisatie-URL, de token-URL of de tokenuitwisselingsmethode wordt gewijzigd.
- `oauthPrompt` en `oauthToolCatalog` zijn niet beschikbaar.
- [`mcpSettings`](/docs/configuration/librechat_yaml/object_structure/mcp_settings) domein- en adresbeperkingen zijn van toepassing.
- Nieuwe en gewijzigde servers worden van kracht zonder dat een herstart nodig is. Een OAuth-server wordt opgeslagen in de niet-verbonden staat totdat een gebruiker zich aanmeldt.

Voor de volledige set placeholders definieert u de server in `librechat.yaml`.

```yaml filename="Complete MCP Configuration with Internal Servers"
    timeout: 120000

  test-mcp:
    type: streamable-http
    url: http://mcp-prod:8001/mcp
    timeout: 120000
```

## Aanvullende informatie [#additional-information]

- **Standaardgedrag:**
  - Servers in `librechat.yaml` worden bij het opstarten geïnitialiseerd, dus wijzigingen in dit bestand vereisen een herstart. Servers die in de UI zijn aangemaakt, doen dat niet.
  - Servers die `notifications/tools/list_changed` verzenden, kunnen tijdens het draaien tools toevoegen of verwijderen; LibreChat haalt de toollijst dan opnieuw op via de actieve verbinding, zonder herstart.
  - Wanneer een gebruiker tijdens een toolaanroep op **Stop** drukt, annuleert LibreChat het MCP-verzoek. Streamable HTTP-servers ontvangen `notifications/cancelled` en moeten dit respecteren om hun eigen werk te stoppen. Toolaanroepen die op de achtergrond worden uitgevoerd, worden niet geannuleerd.
  - Als zowel `url` als `command` zijn opgegeven, moet het `type` expliciet worden gedefinieerd om ambiguïteit te voorkomen.
- **Multi-User Support:**
  - De MCPManager ondersteunt nu afzonderlijke verbindingen op gebruikersniveau en app-niveau, wat een correct beheer van verbindingen per gebruiker mogelijk maakt.
  - Gebruikersverbindingen worden afzonderlijk bijgehouden en beheerd, met een correcte totstandbrenging en opschoning.
  - Met Redis ingeschakeld worden de OAuth-stroomstatus en de MCP-toolcatalogus gedeeld tussen replica's, inclusief Redis Cluster-implementaties. Zie [OAuth-refreshcoördinatie](#oauth-refresh-coordination) voor het vernieuwen van tokens over replica's heen.
  - Gebruik dynamische gebruikersveld-placeholders in headers, URL's en omgevingsvariabelen:
    - `{{LIBRECHAT_USER_ID}}` - Unieke identificatiecode van de gebruiker
    - `{{LIBRECHAT_USER_EMAIL}}` - E-mailadres van de gebruiker
    - `{{LIBRECHAT_USER_USERNAME}}` - Gebruikersnaam van de gebruiker
    - `{{LIBRECHAT_USER_ROLE}}` - Rol van de gebruiker (bijv. "user", "admin")
    - En nog veel meer velden (zie de sectie headers voor de volledige lijst)
- **Gebruikersinactiviteitsbeheer:**
  - Gebruikersverbindingen worden gecontroleerd op activiteit en worden na 15 minuten inactiviteit verbroken. Wijzig dit met `MCP_USER_CONNECTION_IDLE_TIMEOUT` (milliseconden).
- **Omgevingsvariabelen:**
  - **In `env` (voor `stdio` type):** Handig voor het instellen van specifieke runtime-omgevingen of configuraties die vereist zijn voor het MCP serverproces.
  - **In `headers` (voor `sse` en `streamable-http` types):** Gebruik de `${ENV_VAR}` syntaxis om te verwijzen naar omgevingsvariabelen in headerwaarden.
- **Dynamische gebruikersvelden:**
  - Gebruikersveld-placeholders worden tijdens runtime vervangen door de informatie van de geauthenticeerde gebruiker.
  - Alleen niet-gevoelige velden zijn beschikbaar (wachtwoorden en andere gevoelige gegevens zijn uitgesloten)
  - Ontbrekende velden worden standaard ingesteld op lege strings
  - Boolean-velden worden geconverteerd naar string-representaties ("true" of "false")
- **Foutafhandeling (`stderr`):**
  - Het configureren van `stderr` stelt u in staat om te beheren hoe foutmeldingen van het MCP serverproces worden afgehandeld. De standaardwaarde `"inherit"` betekent dat de fouten worden afgedrukt naar de `stderr` van het bovenliggende proces.
- **Server-instructies:**
  - Instructies worden automatisch in het systeembericht van de agent geïnjecteerd wanneer MCP server-tools worden gebruikt
  - Aangepaste instructies (stringwaarden) krijgen voorrang op instructies die door de server worden verstrekt
  - Meerdere MCP servers kunnen elk hun eigen instructies bijdragen aan de agent-context
  - Instructies worden alleen opgenomen wanneer de tools van de bijbehorende MCP server daadwerkelijk beschikbaar zijn voor de agent
- **OAuth-authenticatie:**
  - OAuth2 flow wordt ondersteund voor veilige authenticatie met MCP servers
  - Gebruikers worden gevraagd om te authenticeren via OAuth voordat de MCP server kan worden gebruikt
