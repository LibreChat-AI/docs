      '',

    [
      'headers',
      'Object/Map of Strings',
      'Proxy veya ağ geçidi kimlik doğrulaması için yapılandırılmış bir Langfuse kaynağına gönderilen, dağıtımın sahip olduğu başlıklar. `${ENV_VAR}` referanslarını destekler.',

Bağlantı alanlarını **Ayarlar → Langfuse** veya yetkili bir yönetici yapılandırma istemcisi aracılığıyla yönetin. Ayarlar akışı bağlantıyı doğrular ve `projectId` değerini türetir; yetkili yönetici `secretKey` değerini şifreler, `secretKeyPreview` oluşturur ve okuma işlemlerinde gizli anahtarı maskeler. Doğrudan `librechat.yaml` içine yerleştirilen düz metin `secretKey` değerleri, çalışma zamanı bağlantı yolu tarafından kabul edilmez. Eski `displaySecretKey` ve `fanout.enabled` alanları artık şemanın bir parçası değildir.

`headers` farklıdır: dağıtım altyapısıdır ve yalnızca `librechat.yaml` içinde ayarlanabilir. Yönetici yapılandırması yazma işlemleri, hem haritanın tamamını hem de bireysel başlık yollarını reddeder; böylece ağ geçidi kimlik bilgileri Mongo destekli yapılandırma aracılığıyla depolanmaz veya döndürülmez. Değerler `${ENV_VAR}` enterpolasyonunu destekler; değişmez değerler yerine ortam referanslarını kullanın. LibreChat, çözümlenmemiş değişkenleri, korumalı altyapı-gizli referanslarını, boş değerleri ve geçersiz HTTP başlık adlarını bir uyarı ile birlikte atar.

Özel başlıklar (custom headers); yalnızca dağıtım tam olarak bir Langfuse kaynağıyla eşleştiğinde izleme (trace) ve medya dışa aktarma, geri bildirim puanı (feedback-score) istekleri, proje arama ve yönetici kimlik bilgisi doğrulama işlemlerinde gönderilir. Eğer merkezi, kiracı veya toplayıcı (collector) yapılandırması birden fazla kaynak oluşturursa, LibreChat hiçbir özel başlık göndermez ve eşleme güvenli bir alıcıyı tanımlayamadığı için bir uyarı günlüğü kaydeder. Bu başlıklar kullanıcı bazlı `{{...}}` yer tutucularını kullanamaz ve fanout toplayıcısı yalnızca `Authorization` başlığını yukarı yöne (upstream) iletir.

```yaml filename="langfuse / headers"
langfuse:
  headers:
    CF-Access-Client-Id: '${CF_ACCESS_CLIENT_ID}'
    CF-Access-Client-Secret: '${CF_ACCESS_CLIENT_SECRET}'
```

`langfuse`, yalnızca temel yapılandırmaya (base-configuration) ait bir bölümdür. Rol, grup ve kullanıcı yapılandırması geçersiz kılmaları (overrides) bu bölümün yerini alamaz veya onu devre dışı bırakamaz (tombstone).

Kullanılabilirlik kuralları, kimlik doğrulamalı proxy kurulumu, ortam tarafından yönetilen kimlik bilgileri ve isteğe bağlı fanout dağıtımı için [Langfuse Configuration](/docs/configuration/langfuse) bölümüne bakın.

- **Seçenekler**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[

      'fileStrategy: "firebase"',

- **Notlar**:
  - `"cloudfront"`, dosyaları S3'te depolar ve kararlı medya dağıtımı, imzalı çerezler ve imzalı indirmeler için CloudFront URL'leri döndürür.
  - `"firebase"`, dosyaları Firebase Storage ve Firebase Hosting uç noktaları (edge locations) üzerinden sunar.
  - S3, dosyaları süresi dolan **presigned URL'ler** (geçici imzalı belirteçler) aracılığıyla sunar. Süre dolduğunda, bu URL'ye başvuran herhangi bir görsel veya avatar arayüzde bozuk görünecektir. Bu durum, S3'ü görsel varlıklar için birincil strateji olarak uygunsuz kılar. Ayrıntılar için [ilgili tartışmaya](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) bakın.
  - Görseller ve avatarlar için en iyi performans adına `"cloudfront"` veya `"firebase"` kullanın ya da `avatar` ve `image` öğelerini CDN destekli bir stratejiye yönlendirmek için `fileStrategies` yapılandırmasını yapın.
  - Kurulum ayrıntıları için lütfen [File Storage & CDN documentation](/docs/configuration/cdn) bölümüne bakın.

S3 imzalı URL'lerin süresi dolar (AWS sınırı: IAM kullanıcıları için 7 gün, STS/rol tabanlı kimlik bilgileri için saatler), bu da model seçicide ve sohbet arayüzünde bozuk görsellere neden olur. Bunu önlemek için `avatar` ve `image` için `"cloudfront"` veya `"firebase"` kullanın.
  - S3 ve Azure Blob Storage, kısa ömürlü önceden imzalanmış indirme URL'lerinin uygun olduğu `document` depolama için oldukça uygundur.
  - Her bir depolama sağlayıcısının kurulum detayları için lütfen [File Storage & CDN documentation](/docs/configuration/cdn) bölümüne bakın.

**Örnekler:**

```yaml filename="fileStrategies - All in one place"
# Use a single strategy for all file types
fileStrategies:
  default: 's3'
```

```yaml filename="fileStrategies - Mixed strategies"
# Route images and avatars to CDN, keep documents in object storage
fileStrategies:
  avatar: 'cloudfront' # CDN delivery for avatars
  image: 'cloudfront' # CDN delivery for generated/uploaded images
  document: 's3' # Object storage for documents
```

```yaml filename="fileStrategies - Partial configuration"
# Only configure specific types, others use default
fileStrategies:
  default: 'local'
  avatar: 'firebase' # Only avatars use Firebase CDN, everything else is local
```

## secureImageLinks

<OptionTable
  options={[
    [
      'secureImageLinks',
      'Boolean',
      'Uygulama tarafından yerel olarak barındırılan görsel bağlantıları için yetkilendirme gerektirir. Varsayılan: true.',
      'secureImageLinks: true',
    ],
  ]}
/>

Bu alan atlandığında yerel görseller korunur. Özel sohbet görselleri, aktif bir oturum ve sahip erişimi gerektirir. Depolanan kullanıcı avatarları, aynı kiracıda kimliği doğrulanmış bir görüntüleyici gerektirir. Temsilci (Agent) avatarları, herkese açık görünürlük dahil olmak üzere Temsilcinin görüntüleme ACL'sini takip ederken, Asistan avatarları aynı kiracının yanı sıra geçerli endpoint paylaşımı veya Asistan yönetimi politikasını gerektirir. Yetkilendirme ve yapılandırma arama hataları, güvenli tarafta kalarak (fail closed) reddedilir.

`secureImageLinks: false` ayarını yalnızca, yerel resim URL'lerini kimlik doğrulaması olmadan kasıtlı olarak dışa açan dağıtımlar için bir uyumluluk seçeneği olarak devre dışı bırakın. Rol ve kullanıcı yapılandırması geçersiz kılmaları, resim sahibinin geçerli yapılandırmasından çözümlenir.

**Açıklama:**

`clientImageResize` yapılandırması, yükleme öncesinde istemci tarafındaki küçültme işlemini kontrol eder. Bu özellik şunlara yardımcı olur:

- Sunucu sınırlarını aşan büyük görsel dosyaları nedeniyle oluşan **yükleme hatalarını önleyin**
- **Bant genişliği kullanımını azaltmak** için görüntüleri iletimden önce sıkıştırın
- **Yükleme performansını** daha küçük dosya boyutlarıyla **iyileştirin**
- Dosya boyutunu optimize ederken **görüntü kalitesini koruyun**

Yeniden boyutlandırma etkinleştirildiğinde, `maxWidth` veya `maxHeight` değerlerini aşan desteklenen görseller, yükleme öncesinde tarayıcıda küçültülür. LibreChat en boy oranını korur, daha küçük görselleri asla büyütmez ve kodlanmış sonuç daha küçük olmayacaksa orijinal dosyayı tutar.

`enabled` atlanırsa, kullanıcılar **Ayarlar > Sohbet** altında **Yüklemeden önce görüntüleri yeniden boyutlandır** seçeneğini açıp kapatabilirler. Tercih o tarayıcıda saklanır ve varsayılan olarak kapalıdır. `librechat.yaml` içinde `enabled: true` veya `enabled: false` ayarını yapmak, tüm kullanıcıların tercihlerini geçersiz kılar ve geçiş düğmesini devre dışı bırakır.

**Örnek:**

```yaml filename="clientImageResize"
fileConfig:
  clientImageResize:
    # Omit enabled so each user can choose under Settings > Chat.
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

Dağıtım için tek bir davranışı zorunlu kılmak istiyorsanız, aynı bloğa `enabled: true` veya `enabled: false` ekleyin.

**Notlar:**

- Yeniden boyutlandırma işlem hattı, gerekli Canvas API'lerine sahip tarayıcılarda JPEG, PNG ve WebP formatlarını destekler.
- Animasyonlu PNG ve WebP dosyaları değiştirilmeden gönderilir, böylece yeniden boyutlandırma işlemi animasyonu bozmaz.
- Çıktı, kaynak biçimini korur. Herhangi bir `compressFormat` ayarı bulunmamaktadır.
- Tarayıcı kodlayıcıları, PNG gibi kayıpsız formatlar için `quality` değerini yok sayabilir.
- Yeniden boyutlandırma hatası durumunda orijinal dosyaya geri dönülür; normal sunucu yükleme sınırları geçerliliğini korur.

  - `<serverName>`, her bir MCP sunucusu yapılandırması için benzersiz bir tanımlayıcıdır.
  - Her bir MCP sunucusu, dört bağlantı türünden biri kullanılarak yapılandırılabilir:
    - `stdio`
    - `websocket`
    - `sse`
    - `streamable-http`

    - `command` belirtilmişse, `type` varsayılan olarak `stdio` değerini alır.
  - Ek yapılandırma seçenekleri şunları içerir:
    - `timeout`: MCP sunucusu istekleri için milisaniye cinsinden zaman aşımı. Araç istekleri için yanıtın ne kadar bekleneceğini belirler.
    - `initTimeout`: MCP sunucusu başlatma işlemi için milisaniye cinsinden zaman aşımı süresi. Sunucunun başlatılması için ne kadar bekleneceğini belirler.
    - `serverInstructions`: Sunucu talimatlarının aracı bağlamına dahil edilip edilmeyeceğini kontrol eder. `true` (sunucu tarafından sağlananları kullan), `false` (devre dışı) veya özel bir metin (sunucu tarafından sağlananları geçersiz kılar) olabilir.
    - `customUserVars`: (İsteğe bağlı) Bireysel kullanıcıların bir MCP sunucusu için ayarlayabileceği özel değişkenleri (örneğin, API anahtarları, URL'ler) tanımlar. Arayüz aracılığıyla sağlanan bu kullanıcı bazlı değerler, daha sonra sunucunun `headers` veya `env` yapılandırmalarında `{{VARIABLE_NAME}}` sözdizimi kullanılarak referans gösterilebilir. Bu, MCP araçları için kullanıcı bazlı kimlik doğrulamaya veya özelleştirmeye olanak tanır.
  - bkz: [MCP Servers Object Structure](/docs/configuration/librechat_yaml/object_structure/mcp_servers)

**Örnek:**

```yaml filename="mcpServers"
mcpServers:
  everything:

    url: http://localhost:3001/sse
    timeout: 30000
    initTimeout: 10000
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    timeout: 30000
    initTimeout: 10000
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-example:
    type: streamable-http
    url: https://example.com/mcp
    headers:
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
  per-user-crendentials-example:
    type: sse
    url: 'https//some.mcp/sse'
    headers:
      X-Custom-Auth-Token: '{{USER_API_KEY}}' # Placeholder for the user-provided API key, defined in `customUserVars` below.
    customUserVars:
      USER_API_KEY:
        title: 'Service API Key'
        description: "Your personal API key for this service. You can get it <a href='https://example.com/api-keys' target='_blank'>here</a>."
    serverInstructions: true
```
