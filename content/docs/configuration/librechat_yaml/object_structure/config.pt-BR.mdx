## langfuse

<OptionTable
  options={[
    [
      'langfuse',
      'Object',
      'Configura a conexão criptografada do Langfuse e os cabeçalhos de solicitação de propriedade da implantação.',
      '',
    ],
  ]}
/>

**Subchaves:**

<OptionTable
  options={[
    ['enabled', 'Boolean', 'Ativa ou desativa o rastreamento do Langfuse para este escopo de configuração.', ''],
    ['publicKey', 'String', 'Chave pública do projeto Langfuse.', ''],
    ['secretKey', 'String', 'Chave secreta do projeto Langfuse criptografada.', ''],
    ['projectId', 'String', 'Identidade do projeto Langfuse verificada.', ''],
    ['secretKeyPreview', 'String', 'Visualização mascarada gerada pelo servidor da chave secreta armazenada.', ''],
    [
      'destination',
      'String',
      'Seleciona uma chave de destino do Langfuse aprovada para implantação.',
      '',
    ],
    [
      'headers',
      'Object/Map of Strings',
      'Cabeçalhos de propriedade da implantação enviados para uma origem Langfuse configurada para autenticação de proxy ou gateway. Suporta referências `${ENV_VAR}`.',
      '',
    ],
  ]}
/>

Gerencie os campos de conexão através de **Settings → Langfuse** ou de um cliente de configuração de administrador autorizado. O fluxo de Settings verifica a conexão e deriva o `projectId`; o administrador autorizado escreve o `secretKey` criptografado, gera o `secretKeyPreview` e oculta o segredo de leituras. Valores de `secretKey` em texto simples colocados diretamente no `librechat.yaml` não são aceitos pelo caminho de conexão em tempo de execução. Os campos legados `displaySecretKey` e `fanout.enabled` não fazem mais parte do esquema.

`headers` é diferente: trata-se de infraestrutura de implantação e só pode ser definido no `librechat.yaml`. A configuração de administrador rejeita tanto o mapa completo quanto caminhos de cabeçalho individuais, para que as credenciais de gateway não sejam armazenadas ou retornadas por meio da configuração baseada em Mongo. Os valores suportam interpolação `${ENV_VAR}`; use referências de ambiente em vez de literais. O LibreChat descarta variáveis não resolvidas, referências de segredos de infraestrutura protegidos, valores em branco e nomes de cabeçalho HTTP inválidos, emitindo um aviso.

Cabeçalhos personalizados são enviados apenas em rastreamento e exportação de mídia, solicitações de pontuação de feedback, pesquisa de projeto e verificação de credenciais de administrador quando a implantação resolve exatamente uma origem Langfuse. Se a configuração central, de locatário ou de coletor produzir múltiplas origens, o LibreChat não envia cabeçalhos personalizados e registra um aviso, pois o mapa não consegue identificar um destinatário com segurança. Eles não podem usar espaços reservados `{{...}}` por usuário, e o coletor fanout encaminha apenas o `Authorization` para o upstream.

```yaml filename="langfuse / headers"
langfuse:
  headers:
    CF-Access-Client-Id: '${CF_ACCESS_CLIENT_ID}'
    CF-Access-Client-Secret: '${CF_ACCESS_CLIENT_SECRET}'
```

`langfuse` é uma seção apenas de configuração base. Substituições de configuração de função, grupo e usuário não podem substituí-la ou desativá-la.

Veja [Configuração do Langfuse](/docs/configuration/langfuse) para regras de disponibilidade, configuração de proxy autenticado, credenciais gerenciadas por ambiente e implantação opcional de fanout.

## fileStrategy

- **Opções**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategy',
      'String',
      'Determina onde salvar arquivos enviados/gerados pelo usuário. O padrão é `"local"` se omitido.',
      'fileStrategy: "firebase"',
    ],
  ]}
/>

- **Notas**:
  - `"cloudfront"` armazena arquivos no S3 e retorna URLs do CloudFront para entrega estável de mídia, cookies assinados e downloads assinados.
  - `"firebase"` serve arquivos através do Firebase Storage e locais de borda (edge locations) do Firebase Hosting.
  - O S3 serve arquivos via **presigned URLs** (tokens assinados temporários) que expiram. Uma vez expirados, qualquer imagem ou avatar que referencie essa URL aparecerá como quebrado na interface. Isso torna o S3 inadequado como estratégia principal para ativos visuais. Veja a [discussão relacionada](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) para mais detalhes.
  - Para obter o melhor desempenho de imagens e avatares, use `"cloudfront"` ou `"firebase"`, ou configure `fileStrategies` para rotear `avatar` e `image` para uma estratégia baseada em CDN.
  - Consulte a [documentação de File Storage & CDN](/docs/configuration/cdn) para detalhes de configuração

## fileStrategies

Permite controle granular sobre estratégias de armazenamento de arquivos para diferentes tipos de arquivo.

- **Estratégias Disponíveis**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategies',
      'Object',
      'Configura diferentes estratégias de armazenamento para diferentes tipos de arquivo. Mais flexível que a opção única fileStrategy.',
      '',
    ],
  ]}
/>

**Sub-chaves:**

<OptionTable
  options={[
    [
      'default',
      'String',
      'Estratégia de armazenamento de fallback quando um tipo específico não está definido. O padrão é "local".',
      '',
    ],
    [
      'avatar',
      'String',
      'Estratégia de armazenamento para imagens de avatar de usuários e agentes. É recomendado usar uma estratégia com suporte de CDN (`"cloudfront"` ou `"firebase"`) para obter o melhor desempenho.',
      '',
    ],
    [
      'image',
      'String',
      'Estratégia de armazenamento para imagens enviadas em chats. Recomendado usar uma estratégia com suporte a CDN (`"cloudfront"` ou `"firebase"`) para melhor desempenho.',
      '',
    ],
    ['document', 'String', 'Estratégia de armazenamento para uploads de documentos (PDFs, arquivos de texto, etc.).', ''],
    ['skills', 'String', 'Estratégia de armazenamento para arquivos agrupados com Skills.', ''],
  ]}
/>

- **Notas**:
  - Esta configuração tem precedência sobre a opção única `fileStrategy`
  - Se um tipo de arquivo específico não estiver configurado, ele recorre a `default`, depois a `fileStrategy` e, finalmente, a `"local"`.
  - Imagens e avatares precisam de URLs persistentes e estáveis para serem renderizados corretamente em toda a UI. URLs pré-assinadas do S3 expiram (limite da AWS: 7 dias para usuários IAM, horas para credenciais baseadas em STS/funções), causando imagens quebradas no seletor de modelos e na UI de chat. Veja a [discussão relacionada](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) para o contexto completo. Use `"cloudfront"` ou `"firebase"` para `avatar` e `image` para evitar isso.
  - O S3 e o Azure Blob Storage são adequados para armazenamento de `document`, onde URLs de download pré-assinadas de curta duração são apropriadas.
  - Consulte a [documentação de File Storage & CDN](/docs/configuration/cdn) para detalhes de configuração de cada provedor de armazenamento.

**Exemplos:**

```yaml filename="fileStrategies - All in one place"
# Use a single strategy for all file types
fileStrategies:
  default: 's3'
```

```yaml filename="fileStrategies - Mixed strategies"
# Route images and avatars to CDN, keep documents in object storage
fileStrategies:
  avatar: 'cloudfront' # CDN delivery for avatars
  image: 'cloudfront' # CDN delivery for generated/uploaded images
  document: 's3' # Object storage for documents
```

```yaml filename="fileStrategies - Partial configuration"
# Only configure specific types, others use default
fileStrategies:
  default: 'local'
  avatar: 'firebase' # Only avatars use Firebase CDN, everything else is local
```

## secureImageLinks

<OptionTable
  options={[
    [
      'secureImageLinks',
      'Boolean',
      'Requer autorização para links de imagem hospedados localmente pelo aplicativo. Padrão: true.',
      'secureImageLinks: true',
    ],
  ]}
/>

Imagens locais são protegidas quando este campo é omitido. Imagens de conversas privadas exigem uma sessão ativa e acesso de proprietário. Avatares de usuário armazenados exigem um visualizador autenticado no mesmo tenant. Avatares de Agent seguem a ACL de visualização do Agent, incluindo visibilidade pública, enquanto avatares de Assistant exigem o mesmo tenant, além da política de compartilhamento de endpoint efetiva ou de gerenciamento de Assistant. Falhas de autorização e de busca de configuração resultam em falha bloqueada (fail closed).

Defina `secureImageLinks: false` apenas como uma opção de compatibilidade para implantações que expõem intencionalmente URLs de imagens locais sem autenticação. As substituições de configuração de função e usuário são resolvidas a partir da configuração efetiva do proprietário da imagem.

      'quality: 0.92',

**Descrição:**

A configuração `clientImageResize` controla o redimensionamento (downscaling) no lado do cliente antes do upload. Este recurso ajuda a:

- **Evite falhas de upload** devido a arquivos de imagem grandes que excedem os limites do servidor
- **Reduza o uso de largura de banda** comprimindo imagens antes da transmissão
- **Melhore o desempenho de upload** com tamanhos de arquivo menores
- **Mantenha a qualidade da imagem** enquanto otimiza o tamanho do arquivo

Quando o redimensionamento está ativado, imagens suportadas que excedem `maxWidth` ou `maxHeight` são reduzidas no navegador antes do upload. O LibreChat preserva a proporção, nunca aumenta imagens menores e mantém o arquivo original quando o resultado codificado não for menor.

Se `enabled` for omitido, os usuários podem ativar ou desativar **Redimensionar imagens antes do upload** em **Configurações > Chat**. A preferência é armazenada no navegador e, por padrão, está desativada. Definir `enabled: true` ou `enabled: false` no `librechat.yaml` substitui a preferência de todos os usuários e desativa o botão de alternância.

**Exemplo:**

```yaml filename="clientImageResize"
fileConfig:
  clientImageResize:
    # Omit enabled so each user can choose under Settings > Chat.
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

Para aplicar um comportamento específico à implantação, adicione `enabled: true` ou `enabled: false` ao mesmo bloco.

**Notas:**

- O pipeline de redimensionamento oferece suporte a JPEG, PNG e WebP em navegadores com as APIs de Canvas necessárias.
- Arquivos PNG e WebP animados são enviados sem alterações, portanto, o redimensionamento não descarta a animação.
- A saída mantém o formato de origem. Não existe uma configuração `compressFormat`.
- Codificadores de navegador podem ignorar `quality` para formatos sem perdas, como PNG.
- Uma falha no redimensionamento reverte para o arquivo original; os limites normais de upload do servidor ainda se aplicam.

- **Notas**:
  - Este é um recurso de segurança para proteger contra abuso / uso indevido de endereços internos via servidores MCP
  - Por padrão, o LibreChat restringe a conexão de servidores MCP a endereços de rede internos, locais ou privados.

**Exemplo:**

```yaml filename="mcpSettings"
mcpSettings:
  # Strict whitelist mode:
  # allowedDomains:
  #   - "example.com"           # Specific domain
  #   - "*.example.com"         # All subdomains
  #   - "http://mcp-server:3000" # Internal service, explicitly whitelisted

  # Default SSRF mode with private service exemptions:
  allowedAddresses:
    - 'host.docker.internal:8080' # Permit one private host on one port
    - '10.0.0.5:8000' # Permit one private IP on one port
```

## mcpServers

**Chave:**

<OptionTable
  options={[
    [
      'mcpServers',
      'Object',
      'Define a configuração para servidores do Model Context Protocol (MCP), permitindo a integração dinâmica de servidores MCP dentro da aplicação.',
      '',
    ],
  ]}
/>

**Subchaves:**

<OptionTable
  options={[
    [
      '<serverName>',
      'Object',
      'Cada chave em `mcpServers` representa uma configuração individual de servidor MCP, identificada por um nome único.',
      '',
    ],
  ]}
/>

- **Notas**:
  - A inicialização ocorre na inicialização, e o aplicativo deve ser reiniciado para que as alterações entrem em vigor.
  - O `<serverName>` é um identificador único para cada configuração de servidor MCP.
  - Cada servidor MCP pode ser configurado usando um dos quatro tipos de conexão:
    - `stdio`
    - `websocket`
    - `sse`
    - `streamable-http`
  - O campo `type` especifica o tipo de conexão com o servidor MCP.
  - Se `type` for omitido, ele assume um padrão com base na presença e no formato de `url` ou `command`:
    - Se `url` for especificado e começar com `http` ou `https`, `type` assume `sse` como padrão.
    - Se `url` for especificado e começar com `ws` ou `wss`, `type` assume `websocket` como padrão.
    - Se `command` for especificado, `type` assume `stdio` como padrão.
  - Opções de configuração adicionais incluem:
    - `timeout`: Timeout em milissegundos para requisições de servidor MCP. Determina quanto tempo aguardar por uma resposta para requisições de ferramentas.
    - `initTimeout`: Tempo limite em milissegundos para a inicialização do servidor MCP. Determina quanto tempo aguardar pela inicialização do servidor.
    - `serverInstructions`: Controla se as instruções do servidor são incluídas no contexto do agente. Pode ser `true` (usa as fornecidas pelo servidor), `false` (desativado) ou uma string personalizada (substitui as fornecidas pelo servidor).
    - `customUserVars`: (Opcional) Define variáveis personalizadas (por exemplo, chaves de API, URLs) que usuários individuais podem definir para um servidor MCP. Esses valores por usuário, fornecidos através da interface, podem então ser referenciados nas configurações de `headers` ou `env` do servidor usando a sintaxe `{{VARIABLE_NAME}}`. Isso permite autenticação ou personalização por usuário para ferramentas MCP.
  - veja: [Estrutura do Objeto MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers)

**Exemplo:**

```yaml filename="mcpServers"
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
    timeout: 30000
    initTimeout: 10000
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    timeout: 30000
    initTimeout: 10000
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-example:
    type: streamable-http
    url: https://example.com/mcp
    headers:
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
  per-user-crendentials-example:
    type: sse
    url: 'https//some.mcp/sse'
    headers:
      X-Custom-Auth-Token: '{{USER_API_KEY}}' # Placeholder for the user-provided API key, defined in `customUserVars` below.
    customUserVars:
      USER_API_KEY:
        title: 'Service API Key'
        description: "Your personal API key for this service. You can get it <a href='https://example.com/api-keys' target='_blank'>here</a>."
    serverInstructions: true
```
