## 概述 [#overview]

`summarization` 配置提供了对对话摘要和上下文修剪的集中控制。这取代了之前在自定义和 Azure OpenAI endpoint 上可用的每个 endpoint 的 `summarize` 和 `summaryModel` 字段。

当对话超出模型的上下文窗口时，摘要系统会自动将较早的消息压缩为简洁的检查点摘要。这可以为后续的对话轮次释放上下文空间，但摘要是有损的，可能会遗漏细节。当确切的措辞或先前的工具结果很重要时，请查看原始记录。该系统还包含**上下文修剪 (context pruning)** 功能，它会在需要摘要之前，逐步降级较早消息中大型工具的结果，以回收 Token 空间。

在一次总结轮次后，上下文使用量仪表会使用持久化的总结基准加上总结后的轮次，而不是重新计算已丢弃的总结前历史记录。累计使用量和成本总额仍包含完整分支的支出。

## 手动上下文压缩 [#manual-context-compaction]

当 `summarization.enabled` 未设置为 `false` 时，Agent 对话会在对话控件中显示 **Compact context**（精简上下文）。它会在当前分支末端启动一个仅用于总结的轮次：LibreChat 会总结符合条件的记录，存储新的总结检查点，并在不要求主 Agent 或任何子 Agent 生成回答的情况下结束。

之前的消息在对话记录中仍然可见，但后续的模型调用会使用压缩后的摘要以及由 [`retainRecent`](#retainrecent) 保留的内容。生成的标记用于标识用户发起的压缩，且来自摘要生成器的 Token 使用量会被单独记录。对于新对话、正在进行的生成、没有符合摘要条件的分支，或禁用了摘要功能的部署，压缩功能不可用。如果摘要生成器失败或未生成摘要，LibreChat 将保持原有上下文不变并报告原因。

## 示例 [#example]

```yaml filename="summarization"
summarization:
  provider: 'openAI'
  model: 'gpt-4o-mini'
  maxSummaryTokens: 4096
  reserveRatio: 0.05
  trigger:
    type: 'token_ratio'
    value: 0.8
  retainRecent:
    turns: 2
    tokens: 2000
  contextPruning:
    enabled: true
    keepLastAssistants: 3
    softTrimRatio: 0.3
    hardClearRatio: 0.5
    minPrunableToolChars: 50000
    softTrim:
      maxChars: 4000
      headChars: 1500
      tailChars: 1500
    hardClear:
      enabled: true
      placeholder: '[Old tool result content cleared]'
```

## contextPruning

<OptionTable
  options={[
    [
      'contextPruning',
      'Object',
      '配置基于位置的工具结果降级。较早消息中的大型工具结果会被逐步修剪或清除，以回收 Token 空间。',
      '',
    ],
  ]}
/>

上下文修剪（Context pruning）是一项可选功能，其运行独立于摘要功能。它针对旧消息中大型工具调用的结果，并应用两个渐进阶段：

1. **Soft trim** — 截断工具结果，仅保留头部和尾部内容，并在中间添加省略号
2. **Hard clear** — 使用简短的占位符替换整个工具结果

这两个阶段都是基于位置的：对话开始时（较旧）的消息会被优先修剪。

当启用 Agent 上下文修剪（Agent context pruning）时，LibreChat 会保留为每个 Agent 选择的紧凑自适应衰减层（compact adaptive fading tier），并将其植入后续的运行中。这使得仅限提供商的投影（provider-only projection）在多轮对话、人工介入恢复、停止、分支和副本切换过程中保持稳定，从而提高了 Anthropic 提示词缓存（prompt-cache）的复用率。存储的对话消息和工具结果保持完整；衰减后的投影不会覆盖原始历史记录。

## 从各 endpoint 设置迁移 [#migration-from-per-endpoint-settings]

如果您之前在自定义或 Azure OpenAI endpoint 上使用了 `summarize` 和 `summaryModel`：

```yaml filename="Before (removed)"
endpoints:
  custom:
    - name: 'My Endpoint'
      summarize: true
      summaryModel: 'gpt-3.5-turbo'
```

这些字段已被移除。请改用顶层的 `summarization` 配置：

```yaml filename="After"
summarization:
  model: 'gpt-4o-mini'
```

## 注意事项 [#notes]

- 摘要功能是全局配置的，而不是针对每个 endpoint 进行配置。
- 自定义 endpoint 和 Azure OpenAI endpoint 上的 `summarize` 和 `summaryModel` 字段已不再受支持。
- 当省略 `provider` 和 `model` 时，将使用智能体自身的 provider 和 model 进行摘要。
- `retainRecent` 会在摘要之外保留最近的逐字尾部；`turns` 接受 `0-20`，且 `tokens` 必须为正数
- 上下文修剪（Context pruning）默认处于禁用状态，必须通过 `contextPruning.enabled: true` 显式启用。
- 上下文修剪仅影响超过 `minPrunableToolChars` 的工具调用结果——较小的结果永远不会被修剪。
- `keepLastAssistants` 设置可保护最近的对话轮次不被修剪，无论修剪/清除比例如何。
- 自定义 `prompt` 和 `updatePrompt` 值会完全替换内置提示词 —— 请谨慎使用
- 在您的 `.env` 文件中设置 `AGENT_DEBUG_LOGGING=true` 以启用关于 token 计数和上下文修剪诊断的详细日志记录。
