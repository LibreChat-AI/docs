## 개요 [#overview]

`interface.theme`는 배포 테마를 설정합니다: 라이트 모드와 다크 모드 모두에서 모든 사용자가 보게 될 색상, 모양, 타이포그래피, 그림자 및 모션을 결정합니다. LibreChat에 번들로 포함된 테마의 이름이나 인라인 테마 정의 중 하나를 사용할 수 있습니다.

<Callout type="info" title="가용성">
  `interface.theme` 및 이 페이지에 설명된 외관 스케일은 LibreChat의 `canary` 브랜치에 있으며, 아직 태그가 지정된 릴리스에는 포함되어 있지 않습니다.
</Callout>

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

`interface.theme`가 설정되지 않은 경우, LibreChat은 이전과 동일하게 동작합니다. 즉, 사용자는 기본 LibreChat 테마를 보거나, 빌드 시점에 적용된 색상 또는 사용자에게 저장된 테마가 적용됩니다.

이 페이지는 운영자가 `librechat.yaml`에서 설정하는 내용을 다룹니다. 전체 토큰 목록과 각 토큰이 Tailwind 유틸리티에 매핑되는 방식을 포함한 테마 엔진 자체에 대한 내용은 LibreChat 저장소의 [theme README](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/client/src/theme/README.md)에 문서화되어 있습니다.

## 테마가 선택되는 방식 [#how-the-theme-is-chosen]

클라이언트는 다음 순서대로 우선순위가 가장 높은 테마 하나를 선택합니다:

1. **고대비 모드.** `high-contrast-light` 또는 `high-contrast-dark`를 선택하거나 시스템 설정이 고대비로 지정된 사용자는 항상 내장된 접근성 팔레트를 제공받습니다.
2. `librechat.yaml`의 **`interface.theme`**.
3. **`REACT_APP_THEME_*`** 빌드 타임 색상. [테마 색상](/docs/configuration/dotenv#theme-colors)을 참조하세요.
4. 브라우저에 저장된 **사용자의 테마**입니다.

배포 테마는 색상, 모양, 글꼴, 그림자 및 동작을 설정하지만 모드는 설정하지 않습니다. 각 사용자는 여전히 라이트, 다크 또는 시스템 모드 중 하나를 직접 선택합니다.

배포 테마는 사용자의 브라우저 저장소에 기록되지 않습니다. `interface.theme`를 제거하면 사용자는 이전에 저장했던 테마(또는 빌드 시 설정된 경우 `REACT_APP_THEME_*` 색상)를 다시 사용하게 됩니다.

테마는 로그인 전 구성의 일부이므로, 로그인 및 등록 페이지는 이미 해당 테마로 렌더링됩니다.

### 공유 링크 [#shared-links]

공유 링크는 해당 링크를 소유한 테넌트의 테마를 따르며, 이를 보는 사람의 테마를 따르지 않습니다. 소유 테넌트가 `interface.theme`를 설정하지 않았거나 공유 링크 구성 로드에 실패한 경우, 공유 페이지는 뷰어의 테마로 대체되지 않고 배포 테마가 없는 상태로 표시됩니다. 공유 페이지를 나가면 뷰어의 테마가 복원됩니다.

## 번들 테마 [#bundled-themes]

| 이름 | 테마 |
| --- | --- |
| `librechat` | 기본 LibreChat 팔레트 및 형태입니다. 이를 명시적으로 설정하면 `REACT_APP_THEME_*` 색상 및 사용자가 저장한 테마도 재정의됩니다. |
| `clickhouse` | ClickHouse의 Click UI 디자인 토큰을 기반으로 구축된 참조 테마입니다. [ClickHouse 테마](#clickhouse-theme)를 참조하세요. |

이 목록에 없는 이름은 무시됩니다. 서버는 이를 로그에 기록하고 `interface.theme`를 삭제하며([Validation](#validation) 참조), 앱은 위 목록의 다음 소스로 대체합니다.

### ClickHouse 테마 [#clickhouse-theme]

`interface.theme: clickhouse`는 색상과 모양을 모두 변경합니다:

- **팔레트.** 모든 색상 토큰은 Click UI의 라이트 및 다크 토큰으로부터 두 모드 모두에서 정의되므로, LibreChat 팔레트로 대체되는 항목은 없습니다. 일부 값은 그대로 사용했을 때 WCAG AA 대비 기준을 충족하지 못하여 Click UI 램프를 따라 조정되었습니다.
- **Accent.** 라이트 모드에서는 거의 검은색인 `#151515`, 다크 모드에서는 ClickHouse 노란색인 `#faff69`를 사용하며, 액센트 및 제출 버튼에 적용됩니다. 포커스 링은 Click UI의 외곽선 색상을 사용합니다: 라이트 모드에서는 파란색 `#437eef`, 다크 모드에서는 `#faff69`입니다.
- **버튼.** 기본 버튼은 라이트 모드에서 `#302e32`, 다크 모드에서 `#faff69`이며, Click UI의 호버 단계를 따릅니다.
- **Radii.** Click UI의 `border.radii`에서 가져온 더 촘촘한 스케일입니다: 컨트롤, 메뉴, 툴팁, 탭 및 `sm`에서 `lg`까지는 `0.25rem`, 표면 및 `xl`/`2xl`은 `0.5rem`, 대형 표면 및 `3xl`은 `0.75rem`으로 제어합니다.
- **그림자(Shadows).** UI의 모든 돌출된 표면, 메뉴, 드래그된 항목에 단일 고도 그림자를 적용합니다. 라이트 모드에서는 0.15 불투명도, 다크 모드에서는 0.6 불투명도를 사용하며, `2xs`부터 `sm` 단계까지는 아주 얇은(hairline) 그림자를 적용합니다. 툴팁에는 그림자가 없습니다.
- **컨트롤.** 버튼과 필드는 높이가 2rem이며, 컨트롤은 `1rem`의 패딩과 `0.5rem`의 아이콘 간격, 그리고 일반(`400`) 두께의 라벨을 가집니다. 필드는 채워진 형태(`fieldFillStyle: fill`)이며 포커스 시 가장자리 색상이 변경됩니다(`fieldFocusStyle: border`); 라벨은 `0.75rem` 크기에 `500` 두께입니다. 비활성화된 컨트롤은 자체 비활성화 색상이 적용된 `fill` 스타일을 사용하며, 스위치는 2rem x 1rem의 컴팩트한 크기이고, 테이블 행에는 1px의 구분선이 적용됩니다.
- **대화 상자(Dialogs).** 1px 테두리, `2rem` 측면 패딩, Inter 스택을 사용한 `1.25rem` 크기 및 `700` 굵기의 제목. 모든 대화 상자 스크림(scrim)의 불투명도는 0.75입니다.
- **글꼴.** UI 글꼴은 Inter를 유지합니다. 코드는 Click UI의 모노 스택인 `"Inconsolata", Consolas, "SFMono Regular", monospace`를 사용하며, LibreChat은 Inconsolata를 번들로 포함합니다. 제목은 Basier Square를 우선적으로 요청하지만, 이는 번들로 포함되어 있지 않으므로 사용자가 해당 글꼴을 설치하지 않은 경우 Inter로 렌더링됩니다.

## 인라인 테마 정의 [#inline-theme-definition]

이름 대신 `interface.theme`에 테마 정의를 담을 수 있습니다. 생략된 항목은 해당 모드에 대한 LibreChat의 기본값으로 대체되므로, 변경하려는 값만 정의하면 됩니다.

```yaml filename="interface / theme"
interface:
  theme:
    version: 1
    name: acme
    modes:
      light:
        colors:
          rgb-accent-primary: '29 78 216'
          rgb-accent-primary-hover: '30 64 175'
          rgb-ring-primary: '29 78 216'
          rgb-surface-submit: '29 78 216'
          rgb-surface-submit-hover: '30 64 175'
          rgb-link: '29 78 216'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.2)'
      dark:
        colors:
          rgb-accent-primary: '96 165 250'
          rgb-accent-primary-hover: '147 197 253'
          rgb-ring-primary: '96 165 250'
          rgb-surface-submit: '37 99 235'
          rgb-surface-submit-hover: '29 78 216'
          rgb-link: '96 165 250'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.5)'
    brands:
      provider-openai: '#10a37f'
```

| 키 | 유형 | 설명 |
| --- | --- | --- |
| `version` | Number | 필수. `1`이어야 합니다. |
| `name` | String | 필수. 테마의 이름(비어 있지 않아야 함). |
| `modes` | Object | 필수. `light` 및/또는 `dark`를 포함합니다. 생략된 모드는 해당 모드에 대한 LibreChat의 기본값을 사용합니다. |
| `modes.<mode>.colors` | Object | 해당 모드에 대한 색상 토큰입니다. 키는 `rgb-*` 토큰 이름이며, 값은 `R G B` 삼중항입니다. [Colors](#colors)를 참조하세요. |
| `modes.<mode>.appearance` | Object | 해당 모드에 대한 모양, 컨트롤, 타이포그래피, 스크림(scrim), 그림자 및 모션 값입니다. [Appearance](#appearance)를 참조하세요. |
| `modes.<mode>.brands` | Object | 해당 모드에 대한 공급자 브랜드 색상입니다. 테마 전체의 `brands`를 재정의합니다. |
| `brands` | Object | 두 모드 모두에 대한 공급자 브랜드 색상입니다. [Brands](#brands)를 참조하세요. |

### 유효성 검사 [#validation]

서버는 `librechat.yaml`이 로드될 때와 설정이 다시 로드될 때마다 브라우저가 화면을 그리기 전에 적용하는 것과 동일한 규칙으로 `interface.theme`를 확인합니다.

**유효하지 않은 테마는 `interface.theme`가 설정되지 않은 것처럼 삭제됩니다.** 잘못된 `version`, 누락된 `name`, `light` 또는 `dark` 이외의 모드, 정의 형식에 없는 필드(최상위 수준의 `css` 등, 또는 모드 내부의 `colors`, `appearance`, `brands` 이외의 모든 항목), 알 수 없는 브랜드 토큰, 또는 토큰에 적합하지 않은 유형의 값은 테마를 사용할 수 없게 만듭니다. LibreChat은 `interface.theme`를 제거하고 문제당 한 줄씩 경고를 기록한 뒤 나머지 구성을 평소와 같이 로드하므로, 테마 오류로 인해 서버가 중단되는 일은 없습니다. 이후 사용자는 [How the theme is chosen](#how-the-theme-is-chosen)에 따라 다음 소스를 적용받게 됩니다: `REACT_APP_THEME_*` 색상 또는 사용자가 저장한 테마, 혹은 둘 다 해당하지 않을 경우 LibreChat의 기본 테마가 적용됩니다. 로그에서는 이를 기본 테마라고 지칭합니다:

```text
Ignoring interface.theme in /app/librechat.yaml; the default theme applies instead:
- interface.theme.modes.dark.colors.rgb-surface-primary: Invalid RGB value for rgb-surface-primary: 300 16 32
```

존재하지 않는 번들 테마 이름은 동일한 방식으로 처리됩니다 (`Unknown bundled theme "<name>", expected one of: librechat, clickhouse`).

([관리자 패널](/docs/features/admin_panel#configuration-management)의 역할, 그룹 또는 사용자에 대해) 설정 재정의를 통해 지정된 테마도 동일한 규칙을 따르지만, 한 가지 차이점이 있습니다. 유효하지 않은 재정의 테마는 기본 테마가 아닌 `librechat.yaml`의 기본 `interface.theme`으로 대체됩니다. 해당 로그 줄은 `[getAppConfig]`로 시작하며, 예시는 다음과 같습니다: `[getAppConfig] Ignoring interface.theme from a config override; the base theme applies instead:`.

`colors` 및 `appearance` 맵은 주변 필드와 다르게 작동합니다.

**알 수 없는 토큰은 무시되며, 테마의 나머지 부분은 그대로 적용됩니다.** `colors` 또는 `appearance` 내부에 있는 키 중 현재 버전의 LibreChat이 인식하지 못하는 키는(오타이거나 더 최신 버전에서 추가된 토큰인 경우 등) 해당 키만 무시됩니다. 서버는 이를 로그에 기록하고 알 수 없는 색상을 브라우저로 전송되는 테마에서 제외합니다:

```text
interface.theme in /app/librechat.yaml names tokens this version ignores:
- interface.theme.modes.light.colors.rgb-surfce-secondary: Unknown light color token ignored: rgb-surfce-secondary
```

알 수 없는 토큰도 여전히 형태를 확인합니다. 색상 이름은 `R G B` 값을 포함하는 일반 소문자 토큰(문자, 숫자 및 `-`)이어야 하며, 외관(appearance) 이름은 `;`, `{`, `}`, `<`, `>` 또는 `url()`이 포함되지 않은 일반 값을 가진 camelCase여야 합니다. 그 외의 모든 것은 오류로 간주되어 전체 테마가 기본값으로 되돌아갑니다. 잘못 입력된 토큰은 서버 로그에만 보고되므로 테마를 변경한 후에는 서버 로그를 확인하십시오.

브라우저는 수신한 테마에 동일한 규칙을 적용하며, 예를 들어 이전 버전의 캐시된 클라이언트가 최신 서버를 만나는 경우와 같이 테마를 거부해야 할 때 `[DeploymentTheme] Ignoring invalid interface.theme: ...`를 로그에 기록합니다.

### 색상 [#colors]

색상은 테마 엔진과 동일한 토큰 이름을 사용합니다. `rgb-` 뒤에 토큰이 붙는 형식으로, `rgb-surface-primary`, `rgb-text-primary`, `rgb-border-medium`, `rgb-accent-primary` 또는 `rgb-status-error-subtle` 등이 있습니다. 130개 토큰의 전체 목록은 [`packages/data-provider/src/theme.ts`](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/data-provider/src/theme.ts)의 `themeColorTokens`에 정의되어 있으며, 서버와 브라우저 모두 이 파일을 읽습니다. 각 토큰에 대한 설명은 [`packages/client/src/theme/types/index.ts`](https://github.com/LibreChat-AI/LibreChat/blob/canary/packages/client/src/theme/types/index.ts)의 `IThemeRGB` 인터페이스에서 확인할 수 있습니다.

표면, 텍스트, 테두리, 상태 및 구문 팔레트 외에도, 이러한 역할들을 통해 테마는 특정 상호작용 상태와 컴포넌트의 스타일을 재정의할 수 있습니다:

| 역할 | 토큰 | 페인트 |
| --- | --- | --- |
| Focus | `rgb-focus-outline`, `rgb-focus-control` | 앱 전체의 키보드 포커스 아웃라인 및 공유 컨트롤의 포커스 링 |
| Pressed | `rgb-surface-pressed`, `rgb-surface-inverted-pressed` | 눌렸을 때의 중립 및 반전 컨트롤 |
| Inverted and fixed | `rgb-surface-inverted`, `rgb-surface-inverted-hover`, `rgb-text-inverted`, `rgb-surface-fixed`, `rgb-surface-fixed-hover`, `rgb-text-fixed` | 반대 모드 색상으로 그려지는 컨트롤 및 두 모드에서 동일한 색상을 유지하는 컨트롤 |
| Disabled | `rgb-surface-disabled`, `rgb-text-disabled`, `rgb-border-disabled` | `disabledStyle`이 `fill`일 때의 비활성화된 컨트롤 ( [Appearance](#appearance) 참조) |
| Control border | `rgb-border-control` | 입력창, 선택 트리거 및 일회용 코드 슬롯의 가장자리. 3:1 대비가 필요하므로 일반 구분선과 분리됨 |
| Fields | `rgb-border-field-focus`, `rgb-field-fill`, `rgb-field-text` | `fieldFocusStyle`이 `border`일 때 포커스된 필드의 가장자리(`rgb-focus-control`을 따름), `fieldFillStyle`이 `fill`일 때 필드의 채우기(`rgb-surface-primary`를 따름), 그리고 입력된 값(`rgb-text-primary`를 따름) |
| Primary button | `rgb-button-primary`, `rgb-button-primary-hover` | 기본 버튼의 채우기 및 호버 상태. 체크박스와 스위치가 계속 사용하는 `rgb-surface-inverted` 및 `rgb-surface-inverted-hover`를 따름 |
| Inks | `rgb-dialog-title`, `rgb-badge-label` | 대화 상자 제목 및 배지 라벨. 둘 다 `rgb-text-primary`를 따름 |
| Scrim | `rgb-surface-overlay` | 대화 상자 뒤의 색상. 강도는 [Appearance](#appearance)의 스크림 불투명도 설정에 따름 |
| Media overlay | `rgb-surface-media-overlay`, `rgb-text-on-media` | 사용자의 이미지(라이트박스, 이미지 미리보기, 업로드 진행 중) 위에 그려지는 스크림, 칩, 진행률 및 그 위의 텍스트. 번들 테마는 두 모드 모두에서 흑백으로 유지됨 |
| Avatar | `rgb-avatar-fill`, `rgb-avatar-text`, `rgb-avatar-placeholder`, `rgb-avatar-edge` | 기본 사용자 아바타의 채우기 및 글리프(글리프는 `rgb-text-primary`를 따름), 로딩 중이거나 투명한 에이전트/어시스턴트 아바타 뒤의 배경(라이트 모드에서는 `rgb-surface-secondary`, 다크 모드에서는 `rgb-surface-tertiary`를 따름), 기본 아바타 주변의 가는 선 |
| File tiles | `rgb-file-document`, `rgb-file-sheet`, `rgb-file-code`, `rgb-file-artifact`, `rgb-file-audio`, `rgb-file-video`, `rgb-file-generic`, `rgb-file-ink` | 파일 종류별 채우기 하나와 모든 타일에 그려지는 글리프 |
| Illustration | `rgb-illustration-subtle`, `rgb-illustration`, `rgb-illustration-strong` | 파일 드롭 영역의 일러스트레이션과 같은 앱 내 아트워크의 세 가지 톤 |
| Switch | `rgb-switch-unchecked`, `rgb-switch-thumb` | 체크되지 않은 스위치 트랙 및 두 상태 모두에서의 노브 |
| Table | `rgb-table-header-text`, `rgb-table-header-fill` | 열 이름 및 고정된 테이블 헤더의 불투명 채우기 |
| Chart series | `rgb-series-1` ~ `rgb-series-8` | 순서대로 나열된 범주형 차트 색상 |

각 값은 `0`에서 `255` 사이의 채널을 가진 `R G B` 삼중항(triplet)이어야 하며, 예시는 `'255 255 255'`와 같습니다. Hex 값과 `rgb(...)` 형식은 허용되지 않습니다. YAML이 문자열로 읽을 수 있도록 값을 따옴표로 감싸십시오.

일부 토큰을 생략하면 설정한 관련 토큰을 따르므로 부분 팔레트가 일관성을 유지합니다. 예를 들어, `rgb-text-muted`는 `rgb-text-tertiary`를 따르고, `rgb-surface-composer-hover`와 `rgb-surface-pressed`는 `rgb-surface-hover`를 따르며, `rgb-focus-outline`은 `rgb-ring-primary`를, `rgb-focus-control`은 `rgb-text-primary`를, `rgb-border-control`은 `rgb-border-light`를, `rgb-switch-thumb`은 `rgb-surface-primary`를, `rgb-table-header-text`는 `rgb-text-secondary`를, `rgb-table-header-fill`은 `rgb-surface-dialog`를 따릅니다.

허용되는 값:

- **Radii, `controlHeight`, `controlPaddingX`, `controlGap`, 버튼 및 필드 크기, 간격, 텍스트 및 레이블 크기, 그리고 대화 상자 길이(`dialogStroke`, `dialogPaddingX`, `dialogHeaderGap`, `dialogTitleSize`):** `0`, 또는 `px`, `rem`, `em` 단위의 숫자(예: `0.25rem`), 또는 이러한 두 길이의 단일 `calc()` 연산(예: `calc(0.5rem - 2px)`).
- **`switchWidth` 및 `switchHeight`:** `px` 또는 `rem` 단위의 양수 길이입니다. 둘 다 동일한 단위를 사용해야 하며(생략된 쪽은 `rem` 기본값이 사용됨), 너비는 노브가 이동할 수 있도록 높이보다 커야 하고, 높이는 4px 트랙 테두리를 확보해야 합니다(`4px` 초과 또는 최소 `0.5rem`).
- **`tableCellSpaceY` 및 `tableRowStroke`:** `0`, 또는 `px`나 `rem` 단위의 길이.
- **`focusRingWidth`:** `px` 또는 `rem` 단위의 양수 길이로, 포커스 표시기가 사라지지 않도록 합니다.
- **`focusRingOffset`:** `0`, 또는 `px`나 `rem` 단위의 길이(음수일 수 있으며, 이 경우 요소의 가장자리 안쪽으로 윤곽선이 그려집니다).
- **`disabledStyle`:** `dim` 또는 `fill`.
- **`fieldFocusStyle`:** `ring` 또는 `border`.
- **`fieldFillStyle`:** `transparent` 또는 `fill`.
- **글꼴 굵기 (`controlFontWeight`, `dialogTitleFontWeight`):** `1`에서 `1000` 사이의 정수입니다. `labelFontWeight`는 `inherit`도 허용합니다.
- **줄 간격(line heights) (`leading*` 단계, `labelLeading` 및 `dialogTitleLeading`):** 단위가 없는 숫자(예: `1.5`), 두 숫자를 나누는 단일 `calc()`(예: `calc(1.25 / 0.875)`), 또는 길이 값입니다.
- **Scrim opacities:** `0`에서 `1` 사이의 숫자입니다.
- **Font families:** `;`, `{` 또는 `}`가 포함되지 않은 비어 있지 않은 모든 `font-family` 목록입니다. 해당 폰트는 브라우저에서 사용할 수 있어야 합니다. LibreChat은 Inter, Roboto Mono 및 Inconsolata를 번들로 제공하므로, 다른 폰트 패밀리를 사용하려면 사용자의 기기에 설치되어 있거나 배포 환경에서 제공되어야 하며, 그렇지 않은 경우 목록의 다음 폰트 패밀리가 사용됩니다.
- **Shadow steps (`shadow2xs` through `shadow2xl`), `menuShadow`, `tooltipShadow` 및 `elevationDrag`:** 구체적인 `box-shadow` 목록이거나 `none`이어야 합니다. `var()`, `env()`, `attr()` 및 `url()`은 허용되지 않습니다.
- **`elevationSurface`:** `;`, `{`, `}`, `url()`을 포함하지 않는 비어 있지 않은 모든 `box-shadow` 값.
- **Motion:** `120ms`와 같이 `ms` 또는 `s` 단위로 된 지속 시간입니다.

모든 appearance 값은 문자열이어야 합니다. 글꼴 두께, 줄 높이, 스크림 불투명도와 같은 숫자는 따옴표로 묶으십시오(`'500'`, `'1.5'`, `'0.8'`); 따옴표가 없는 YAML 숫자는 거부됩니다.

## LibreChat 외부에서 테마 사용하기 [#using-the-theme-outside-librechat]

`@librechat/client` 패키지는 테마를 스타일시트로 게시하므로, 해당 컴포넌트를 기반으로 구축된 다른 앱에서도 동일한 토큰을 적용할 수 있습니다. Tailwind를 가져오는 스타일시트에서 `@librechat/client/theme.css`를 가져오세요:

```css filename="app.css"
@import 'tailwindcss';
@import '@librechat/client/theme.css';
```

이는 의미론적 색상 토큰과 그에 대응하는 Tailwind 매핑, 모든 색상 및 외관 토큰의 기본값, 그리고 Inter, Roboto Mono, Inconsolata에 대한 `@font-face` 규칙을 포함합니다. 폰트 파일은 `@librechat/client/fonts/*`로 패키지에 포함되어 제공되므로, 앱의 번들러(Vite, webpack 또는 esbuild)가 이를 해석하고 내보내야 합니다. 번들러 없이 컴파일된 CSS를 제공하는 설정의 경우, 해당 경로를 직접 서비스해야 합니다. 폰트는 해당 폰트로 텍스트가 렌더링될 때만 다운로드됩니다.
