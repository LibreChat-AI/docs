## Visão geral [#overview]

O objeto `interface` permite a personalização de vários elementos da interface do usuário dentro da aplicação, incluindo configurações de visibilidade e comportamento para componentes como menus, painéis e links. Esta seção fornece um detalhamento da estrutura do objeto `interface`.

Estes são os campos em `interface`:

- `theme`
- `mcpServers`
- `privacyPolicy`
- `termsOfService`
- `modelSelect`
- `agentSelectorLimit`
- `parameters`
- `contextUsage`
- `contextCost`
- `currency`
- `presets`
- `prompts`
- `bookmarks`
- `memories`
- `multiConvo`
- `agents`
- `remoteAgents`
- `skills`
- `sharedLinks`
- `schedules`
- `temporaryChat`
- `temporaryChatRetention`
- `generalChatRetention`
- `retentionMode`
- `retainAgentFiles`
- `autoSubmitFromUrl`
- `customWelcome`
- `codeHighlightThrottleMs`
- `artifactUndocking`
- `runCode`
- `webSearch`
- `fileSearch`
- `fileCitations`
- `feedback`
- `replyNotifications`
- `defaultPinnedTools`
- `composerRecentFiles`
- `steerArmConfirmationTimeoutMs`
- `queuedTurnReconciliationTimeoutMs`
- `queuedSendLockTimeoutMs`
- `peoplePicker`
- `marketplace`

**Notas:**

- As configurações de `interface` são aplicadas globalmente dentro da aplicação.
- Valores padrão são fornecidos para a maioria das configurações, mas podem ser substituídos com base em requisitos ou condições específicas.
- A lógica condicional na aplicação pode modificar ainda mais essas configurações com base em outras configurações, como Model Specs.

<Callout type="warning" title="Obsoleto: campos de efeito colateral de permissão">
Vários campos abaixo (`mcpServers`, `prompts`, `bookmarks`, `memories`, `multiConvo`, `agents`, `remoteAgents`, `skills`, `sharedLinks`, `schedules`, `temporaryChat`, `runCode`, `webSearch`, `fileSearch`, `fileCitations`, `peoplePicker`, `marketplace`) não apenas alternam a interface, eles definem permissões de função no banco de dados na inicialização, e apenas para a função `USER` integrada.

Para o gerenciamento contínuo, use o [**LibreChat Admin Panel**](/docs/features/admin_panel), que edita a matriz de permissões diretamente em cada função (incluindo funções personalizadas). Estes campos YAML permanecem suportados para inicializar uma nova instância ou para implantações totalmente baseadas em arquivos, mas não devem mais ser usados como a forma principal de gerenciar permissões de recursos.

Veja [Access Control](/docs/features/access_control) para o modelo de permissão completo.

</Callout>

## theme

Define o tema de implantação aplicado a cada usuário, tanto no modo claro quanto no escuro. Pode ser o nome de um tema incluído (`librechat` ou `clickhouse`) ou uma definição de tema embutida com suas próprias cores, raios, fontes, sombras e movimento.

Ele supera as cores de tempo de compilação `REACT_APP_THEME_*` e os temas armazenados dos usuários, cede aos modos de alto contraste e nunca é salvo no navegador do usuário. Removê-lo restaura o tema armazenado de cada usuário, ou as cores `REACT_APP_THEME_*` quando o cliente foi compilado com elas.

### Onde os links da política aparecem [#where-the-policy-links-appear]

Nas telas de login e registro, as políticas publicadas aparecem como uma frase de consentimento: "Ao continuar, você concorda com os Termos de Serviço e reconhece a Política de Privacidade." Se apenas uma política estiver publicada, a frase nomeia apenas essa. Na tela de registro, ela fica abaixo do botão de envio; na tela de login, ela fica abaixo das opções de login.

No chat, os links da política aparecem abaixo da caixa de mensagem na tela de boas-vindas de um novo chat e são ocultados assim que uma conversa é iniciada.

Uma política cujo `externalUrl` esteja vazio ou em branco é tratada como não publicada e nunca é exibida. Quando `termsOfService.modalAcceptance` é `true`, as telas de autenticação exibem links de política simples em vez da frase de consentimento, pois os usuários aceitam os termos explicitamente na caixa de diálogo após fazerem login.

Quando a aceitação modal está ativada, o LibreChat registra tanto o estado de aceitação quanto o horário em que foi aceita. Após atualizar uma implantação existente, execute `npm run migrate:terms-timestamp` para preencher os usuários aceitos que não possuem um registro de data e hora. A migração solicita confirmação, processa todos os tenants, utiliza o horário de criação da conta de cada usuário como fallback e encerra com um código diferente de zero se qualquer lote falhar. Executar `npm run reset-terms` limpa tanto o estado de aceitação quanto seu registro de data e hora, para que os usuários precisem aceitar novamente.

## prompts

> **Obsoleto para gerenciamento de permissões.** Inicializa as permissões de função `PROMPTS` na inicialização apenas para a função `USER` padrão. Prefira o [Painel de Administração](/docs/features/admin_panel) para gerenciar permissões de prompts por função/grupo/usuário.

**Chave:**

<OptionTable
  options={[
    [
      'prompts',
      'Boolean or Object',
      'Controla recursos relacionados a prompts para todos os usuários. Pode ser um booleano para habilitar/desabilitar de forma simples, ou um objeto para controle granular sobre uso, criação, compartilhamento e visibilidade pública.',
      'When set to `false`, users will not have access to create, edit, or use custom prompts.',
    ],
  ]}
/>

**Padrão:** `true`

**Importante: Configuração Booleana vs Objeto**

- **Boolean (`prompts: true`)**: Atualiza apenas a permissão `use`. Os valores de permissão `create`, `share` e `public` existentes são **preservados** do banco de dados. Use isso como um simples seletor de recursos (feature toggle) sem afetar outras configurações definidas através do painel administrativo.

- **Objeto**: Atualiza apenas as subpermissões que são explicitamente especificadas. Quaisquer permissões não incluídas na configuração são preservadas a partir do banco de dados.

## agentSelectorLimit

Limita o seletor do painel de Agentes não pesquisados a `10` Agentes por padrão. Defina um número inteiro de `1` a `100` para alterar quantos são listados antes que o usuário comece a digitar. A pesquisa ainda alcança todos os Agentes acessíveis; o limite não é uma configuração de controle de acesso.

```yaml filename="interface / agentSelectorLimit"
interface:
  agentSelectorLimit: 10
```

## retentionMode

Controla quais dados recebem prazos de retenção e se todos os chats são forçados a serem temporários.

**Chave:**

<OptionTable
  options={[

      'String',

</Callout>

```yaml filename="interface / retentionMode"
interface:
  temporaryChatRetention: 168
  generalChatRetention: 2160
  retentionMode: 'all'
```

## autoSubmitFromUrl

## feedback

Controla se os botões de curtir / não curtir são exibidos abaixo das respostas. Quando definido como `false`, os botões são removidos da linha de ação da mensagem e o servidor rejeita gravações de feedback, portanto, uma implantação que oculta os controles também não armazena classificações.

**Notas:**

- As outras ações de mensagem (ler em voz alta, copiar, editar, bifurcar e regenerar) não são afetadas, e a linha de ação é reorganizada sem deixar lacunas.
- Com o feedback desativado, `PUT /api/messages/:conversationId/:messageId/feedback` responde com `403` e `{"error": "Feedback is disabled"}` antes que qualquer coisa seja gravada no banco de dados ou exportada.
- As avaliações coletadas enquanto o recurso estava ativado permanecem nas mensagens existentes. A flag interrompe novas gravações, ela não exclui o feedback armazenado.
- As avaliações só são consumidas fora do LibreChat quando o rastreamento do Langfuse está configurado, onde cada uma é enviada como uma pontuação `user-feedback`. Veja [Message Feedback Scores](/docs/configuration/langfuse#message-feedback-scores).
- Esta é uma flag de interface simples, em vez de uma permissão de função, portanto não há nada para conceder por função no [Admin Panel](/docs/features/admin_panel).

**Chave:**

<OptionTable
  options={[
    [
      'feedback',
      'Boolean',
      'Exibe ou oculta os botões de feedback de curtir/descurtir nas respostas.',
      'When disabled, the buttons are removed for every user and the feedback endpoint rejects writes with a 403.',
    ],
  ]}
/>

**Padrão:** `true`

**Exemplo:**

```yaml filename="interface / feedback"
interface:
  feedback: false
```
