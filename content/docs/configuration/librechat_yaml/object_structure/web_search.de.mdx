Die `webSearch`-Konfiguration ermöglicht es Ihnen, die Websuchfunktion innerhalb von LibreChat anzupassen, einschließlich Suchanbietern, Content-Scrapern und Ergebnis-Rerankern.

## Übersicht [#overview]

Die Websuchfunktion besteht aus drei Hauptkomponenten:

1. **Suchanbieter**: Dienste, die die anfängliche Websuche durchführen
2. **Scrapers**: Dienste, die Inhalte von Webseiten extrahieren
3. **Rerankers**: Dienste, die Suchergebnisse für eine bessere Relevanz neu sortieren

## Beispiel [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## SSRF-Schutz und private Anbieter [#ssrf-protection-and-private-providers]

LibreChat validiert jede Verbindung, die es für die Websuche, das Scraping und das Reranking öffnet. Private, Loopback-, Link-Local- und Cloud-Metadata-Ziele sind standardmäßig blockiert, einschließlich Redirect-Hops und Hostnamen, die zum Zeitpunkt der Verbindung in eine private Adresse aufgelöst werden.

Verwenden Sie `webSearch.allowedAddresses`, wenn ein konfigurierter SearXNG-, Firecrawl-, Jina-, Tavily-kompatibler, Keenable-kompatibler oder ein verwandter Provider-endpoint bewusst privat ist:

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

Dieses Feld ist eine SSRF-Ausnahmeliste, keine strikte Positivliste. Öffentliche Ziele bleiben erreichbar. Einträge müssen exakte `host:port`-, `private.ip:port`- oder `[ipv6]:port`-Paare sein; URLs, Pfade, CIDR-Bereiche, reine Hosts/IPs und öffentliche IP-Literale werden abgelehnt. Ein ausgenommener Hostname vertraut der privaten IP, zu der er an diesem Port aufgelöst wird. Bevorzugen Sie daher ein privates IP-Literal und listen Sie nur Namen auf, deren DNS Sie kontrollieren.

LibreChat nimmt einen konfigurierten HTTP(S)-Forward-Proxy-Endpunkt automatisch aus, damit dieser erreicht werden kann. Wenn der Proxy eine Anfrage weiterleitet, löst er das Ziel auf und muss die Ziel-Egress-Beschränkungen selbst durchsetzen. `NO_PROXY` kann eine Anfrage direkt stellen, wobei der Verbindungsschutz von LibreChat weiterhin greift. Der Schutz deckt Verbindungen ab, die LibreChat zu Anbieter-APIs öffnet; er kann keine Seiten-URL einschränken, die ein Drittanbieter-Scraper als Anfragedaten erhält und auf seiner eigenen Infrastruktur abruft.

## Anmeldeinformations-Besitz [#credential-ownership]

Eine vom Benutzer bereitgestellte Firecrawl-, SearXNG- oder Jina-URL darf keinen servereigenen API-Schlüssel erhalten. Eine SSRF-Validierung macht einen vom Benutzer gewählten öffentlichen endpoint nicht sicher für den Empfang der Anmeldedaten der Bereitstellung. Konfigurieren Sie die URL und den Schlüssel gemeinsam als vom Administrator verwaltete Einstellungen oder lassen Sie den Benutzer sein eigenes Paar bereitstellen; SearXNG kann auch ohne Schlüssel betrieben werden.

Wenn eine gespeicherte Benutzer-URL ansonsten mit dem Schlüssel des Servers gepaart würde, ignoriert LibreChat die optionale URL von Firecrawl und verwendet dessen Standard-endpoint. Die Instanz-URL von SearXNG ist erforderlich, damit eine Konfiguration mit gemischtem Besitz nicht authentifiziert wird und das Such-Tool nicht initialisiert wird. Konfigurieren Sie für eine selbst gehostete Bereitstellung, die den Schlüssel des Servers verwendet, `FIRECRAWL_API_URL` oder `SEARXNG_INSTANCE_URL` zusammen mit diesem Schlüssel, anstatt sich auf die gespeicherte URL eines Benutzers zu verlassen. Private endpoints benötigen weiterhin [`allowedAddresses`](#ssrf-protection-and-private-providers).


#### Auswahl von Engines [#choosing-engines]

Die Namen der Engines müssen mit den Engines übereinstimmen, die auf Ihrer eigenen Instanz aktiviert sind, und daraus ergeben sich zwei Dinge:

- SearXNG ignoriert eine Engine, die es nicht erkennt, anstatt einen Fehler zu melden. Ein Tippfehler oder eine Engine, die auf Ihrer Instanz deaktiviert ist, führt zu weniger Ergebnissen anstatt zu einem Fehler.
- Die gültigen Namen sind instanzspezifisch. Überprüfen Sie die Liste der aktivierten Engines unter `https://your-instance/config`, welche ein JSON mit jeder aktivierten Engine zurückgibt, oder öffnen Sie den Tab **Engines** auf der Einstellungsseite Ihrer Instanz.

Der Standardwert ist `google,bing,duckduckgo`. SearXNG aggregiert die Ergebnisse aller ausgewählten Suchmaschinen. Wenn also eine Suchmaschine blockiert ist, entfällt lediglich deren Anteil an den Ergebnissen, anstatt die gesamte Antwort zu beeinträchtigen. Eine Suche liefert nur dann keine Ergebnisse, wenn jede ausgewählte Suchmaschine fehlschlägt oder nichts zurückgibt.

DuckDuckGo ist die Engine in diesem Standard-Set, die am wahrscheinlichsten blockiert wird, da sie für die meisten selbst gehosteten Instanzen CAPTCHAs ausgibt. Da das Set nur drei Engines enthält, führt der gleichzeitige Ausfall von DuckDuckGo und einer ratenbegrenzten Google- oder Bing-Suche häufig dazu, dass überhaupt keine Ergebnisse mehr erzielt werden. Das explizite Festlegen von `engines`, das Weglassen von DuckDuckGo und das Auflisten von mehr als drei Engines verringern dieses Risiko.

Engines, die schnell antworten und selbst gehosteten Traffic tolerieren, bilden das beste Start-Set, zum Beispiel:

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

Das Hinzufügen weiterer Engines erweitert die Abdeckung, verlangsamt jedoch auch jede Suche, da SearXNG auf die langsamste Engine im Set wartet, bevor eine Antwort erfolgt. Beachten Sie den `timeout`, wenn Sie die Liste erweitern.

#### Was diese Optionen nicht steuern [#what-these-options-do-not-control]

- **Safe search** ist nicht Teil dieses Blocks. Es stammt vom [`safeSearch`](#safesearch)-Schlüssel auf oberster Ebene und wird als `safesearch` an SearXNG weitergeleitet.
- **Ergebniskategorien** werden pro Abfrage von LibreChat ausgewählt, das den Suchtyp auf `general`, `images`, `videos` oder `news` abbildet. Sie können hier nicht überschrieben werden.
- **Seitenzahl und Ergebnisformat** sind festgelegt. LibreChat fordert immer Seite 1 im JSON-Format an, weshalb Ihre Instanz `json` unter `formats` aktiviert haben muss.

## Hinweise [#notes]

- API-Schlüssel können auf zwei Arten konfiguriert werden:
  1. Legen Sie die in der YAML-Konfiguration angegebenen Umgebungsvariablen fest
  2. Wenn Umgebungsvariablen nicht gesetzt sind, werden Benutzer dazu aufgefordert, die API-Schlüssel über die UI einzugeben.
- Die Konfiguration unterstützt mehrere Dienste für jede Komponente (Anbieter, Scraper, Reranker)
- Wenn kein spezifischer Diensttyp angegeben ist, versucht das System, alle verfügbaren Dienste in dieser Kategorie zu verwenden.
- Safe Search bietet drei Stufen der Inhaltsfilterung: OFF (0), MODERATE (1) und STRICT (2)
- Tavily übernimmt standardmäßig nicht die globale Einstellung für die sichere Suche (Safe Search); setzen Sie `tavilySearchOptions.safeSearch` nur dann explizit, wenn Ihr Tavily-Konto `safe_search` unterstützt.
- Keenable unterstützt schlüssellose Suche und Seitenabruf; der optionale Schlüssel erhöht die öffentlichen Ratenbegrenzungen, und die URL-Überschreibung für den Abruf ist nur über die Umgebung konfigurierbar.
- Das Suchverhalten von SearXNG (Engines, Sprache, Zeitbereich, Request-Timeout) wird unter `searxngSearchOptions` konfiguriert; siehe [Choosing engines](#choosing-engines), falls Suchanfragen keine Ergebnisse liefern.
- Geben Sie niemals echte API-Schlüssel in die YAML-Konfiguration ein – verwenden Sie nur die Namen der Umgebungsvariablen.

## Einrichten von SearXNG [#setting-up-searxng]

SearXNG ist eine datenschutzorientierte Metasuchmaschine, die Sie selbst hosten können. 
Weitere Informationen finden Sie in der [offiziellen SearXNG-Dokumentation](https://docs.searxng.org/).

Hier sind die Schritte zur Einrichtung Ihrer eigenen SearXNG-Instanz zur Verwendung mit LibreChat:

### Verwendung von Docker Desktop [#using-docker-desktop]

1. **Suche nach dem offiziellen SearXNG-Image**
   - Öffnen Sie Docker Desktop
   - Suchen Sie nach `searxng/searxng` im Tab **Images**
   - Klicken Sie auf **Run** beim offiziellen Image, um automatisch einen Container des Images herunterzuladen und auszuführen.

2. **Ausführen des Containers**
   - Erweitern Sie das Dropdown-Menü **Optional Settings** im darauf folgenden Bereich, der erscheint, sobald der Download abgeschlossen ist.
   - Legen Sie Ihre gewünschten Konfigurationsdetails fest (Portnummer, Container-Name usw.)
   - Klicken Sie auf **Run**, um den Container zu starten

3. **Konfiguration von SearXNG für LibreChat**
   - Navigieren Sie zum Tab `Files` in Docker Desktop
   - Gehe zu `/etc/searxng/settings.yaml`
   - Öffnen Sie den Datei-Editor
   - Navigieren Sie zum Abschnitt `formats`
   - Fügen Sie `json` als akzeptables Format hinzu, damit LibreChat mit Ihrer Instanz kommunizieren kann.
   - Speichere die Datei

4. **Starten Sie den Container neu**
   - Starten Sie den Container neu, damit die Änderungen wirksam werden.

#### YAML-Konfiguration [#yaml-configuration]

Um SearXNG für alle auf der Instanz anstatt pro Benutzer zu konfigurieren, legen Sie dieselben Werte in der `librechat.yaml` fest:

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

Die URL und der Schlüssel werden weiterhin aus der Umgebung gelesen, kombinieren Sie also die obige Konfiguration mit:

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="Private Instanzen benötigen einen allowedAddresses-Eintrag">
`localhost:55011` ist eine Loopback-Adresse, die von LibreChat beim Verbindungsaufbau durch den [SSRF-Schutz](#ssrf-protection-and-private-providers) blockiert wird. Ohne den passenden `allowedAddresses`-Eintrag schlägt die Suche fehl, selbst wenn SearXNG einwandfrei funktioniert. Der Eintrag muss exakt dem `host:port`-Paar Ihrer Instanz-URL entsprechen.

Wenn LibreChat selbst in Docker ausgeführt wird, ist `localhost` der LibreChat-Container, nicht der von SearXNG. Verwenden Sie einen Hostnamen, den der Container erreichen kann, wie zum Beispiel den Namen des Compose-Dienstes, und schließen Sie stattdessen diesen aus:

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

Siehe [`searxngSearchOptions`](#searxngsearchoptions) für jeden Unter-Key, den dieser Block akzeptiert.

#### Fehlerbehebung bei leeren Ergebnissen [#troubleshooting-empty-results]

Eine SearXNG-Suche, die keine Ergebnisse liefert, liegt fast immer daran, dass die Anfrage keine funktionierende Instanz erreicht, anstatt dass LibreChat Ergebnisse verwirft. Gehen Sie diese Punkte der Reihe nach durch:

1. **Die Instanz ist eine private Adresse ohne `allowedAddresses`-Eintrag.** LibreChat blockiert Loopback- und private Ziele zum Zeitpunkt der Verbindung. Daher muss eine selbst gehostete Instanz mit ihrem genauen `host:port` unter [`allowedAddresses`](#ssrf-protection-and-private-providers) aufgeführt sein. Dies blockiert die Anfrage vollständig, anstatt ein leeres Ergebnisset zurückzugeben.
2. **`json` fehlt in `formats`.** LibreChat fordert Ergebnisse als JSON an. Wenn der Abschnitt `formats` in Ihrer Instanz-Konfigurationsdatei `json` nicht auflistet, antwortet die Instanz mit einer Fehlerseite und jede Suche liefert keine Ergebnisse. Dies ist Schritt 3 der oben genannten Docker-Einrichtung.
3. **Jede ausgewählte Engine ist fehlgeschlagen.** SearXNG führt die Engines zusammen, die geantwortet haben; eine leere Antwort bedeutet also, dass keine von ihnen etwas zurückgegeben hat. DuckDuckGo ist im Standard-Set (`google,bing,duckduckgo`) enthalten und liefert für die meisten selbst gehosteten Instanzen CAPTCHAs aus, wodurch nur zwei Engines für die Suche übrig bleiben. Legen Sie `searxngSearchOptions.engines` explizit fest, lassen Sie DuckDuckGo weg und listen Sie einige weitere Engines auf.
4. **Ein Engine-Name existiert auf Ihrer Instanz nicht.** SearXNG überspringt Engines, die es nicht erkennt, stillschweigend; ein Tippfehler führt also lediglich zu weniger Ergebnissen. Vergleichen Sie Ihre Liste mit `https://your-instance/config`.
5. **Die Instanz ist langsamer als das Timeout.** Erhöhen Sie `searxngSearchOptions.timeout` über den Standardwert `10000`, wenn Ihre Instanz viele Engines abfragt oder sich hinter einer langsamen Netzwerkverbindung befindet.

Sie können reproduzieren, was LibreChat sendet, indem Sie die Instanz direkt aufrufen:

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

Dies läuft von Ihrem eigenen Rechner aus, umgeht also den Verbindungsschutz von LibreChat vollständig. Ein leeres `results`-Array an dieser Stelle bestätigt, dass das Problem auf der Seite von SearXNG liegt; Ergebnisse hier, während LibreChat weiterhin nichts findet, deuten auf `allowedAddresses` hin.
