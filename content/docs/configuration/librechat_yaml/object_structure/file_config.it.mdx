## Panoramica [#overview]

L'oggetto `fileConfig` ti consente di configurare le impostazioni di gestione dei file per l'applicazione, inclusi i limiti di dimensione e le restrizioni sui tipi MIME. Questa sezione fornisce un'analisi dettagliata della struttura dell'oggetto `fileConfig`.

I campi principali sotto `fileConfig` trattati qui:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**Note:**

- Al momento della stesura, l'endpoint Assistants [supporta i tipi di file da questo elenco](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google e gli endpoint personalizzati supportano i file tramite la [RAG API.](../../rag_api.mdx)
- OpenAI, Azure OpenAI, Anthropic, Google, AWS Bedrock e gli endpoint personalizzati supportano il caricamento diretto dei file tramite [Upload to Provider](/docs/features/ocr#upload-to-provider-instead).
- Le sezioni `ocr` e `text` controllano l'elaborazione dei file per funzionalità come [Carica come testo](/docs/features/upload_as_text) e [OCR](/docs/features/ocr)
- Qualsiasi altro endpoint non menzionato, come i Plugins, non supporta (ancora) il caricamento di file.
- L'endpoint Assistants ha un valore di endpoint definito come `assistants`. Tutti gli altri endpoint utilizzano il valore definito `default`
  - Per gli endpoint non-assistants, è possibile regolare le impostazioni dei file per tutti loro sotto `default`
  - Se desideri regolare le impostazioni per un endpoint specifico, puoi elencare i nomi degli endpoint corrispondenti:
    - `assistants`
        - non utilizza "default" poiché ha definito impostazioni predefinite separate dalle altre.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Puoi omettere i valori; in tal caso, l'app utilizzerà i valori predefiniti come definito per tipo di endpoint elencato di seguito.
- LibreChat conta 1 megabyte come segue: `1 x 1024 x 1024`
- I limiti per lo streaming delle risposte di caricamento a lunga durata e per il recupero di URL remoti lato server sono configurati con le variabili d'ambiente [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` e `REMOTE_FILE_FETCH_MAX_BYTES`](/docs/configuration/dotenv#file-uploads).

## Esempio [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="Sintassi del pattern MIME">
  LibreChat valuta i pattern `supportedMimeTypes` configurati dall'amministratore sul server con un motore di espressioni regolari a tempo lineare compatibile con RE2. I backreference e i lookaround non sono supportati. Ogni pattern viene compilato con il motore attivo durante la convalida della configurazione; un pattern non supportato rifiuta la configurazione invece di essere ignorato silenziosamente.
</Callout>

## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Impostazioni per le importazioni di Skill, che vengono caricate come file `.md`, `.zip` o `.skill`.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` supporta tre parametri:

- `fileSizeLimit` (Number)
  - Dimensione massima di un singolo caricamento di Skill, specificata in megabyte (MB).
  - **Predefinito:** `50`
- `importCleanupConcurrency` (Intero)
  - Numero massimo di operazioni di pulizia simultanee dopo un'importazione fallita di un archivio Skill. Utilizzare `1` per una pulizia seriale.
  - **Predefinito:** `8`
- `deletionCleanupConcurrency` (Integer)
  - Numero massimo di operazioni di pulizia simultanee quando un Skill viene eliminata. Usa `1` per una pulizia seriale.
  - **Predefinito:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Vedi [Skills](/docs/features/skills) per il resto delle regole di importazione, come i limiti per singolo file e per voce d'archivio.

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', 'Impostazioni relative alla qualità e alle dimensioni dell\'output della generazione di immagini.', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` supporta i seguenti parametri:

- `percentage` (Number)
  - La dimensione di output dell'immagine generata espressa come percentuale (ad esempio, `100` significa il 100% della dimensione base).
  - Utilizzalo per ridimensionare l'immagine di output rispetto a una dimensione predefinita o originale.

- `px` (Numero)
  - Specifica la dimensione dell'immagine in output in pixel (ad esempio, `1024`).
  - Utilizzalo per impostare esplicitamente la dimensione di output dell'immagine generata, indipendentemente dalla dimensione di base.

Imposta solo uno di questi parametri (`percentage` o `px`), non entrambi.

Esempio di configurazione:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Controlla il ridimensionamento lato client delle immagini prima del caricamento, il che previene gli errori di caricamento dovuti a immagini troppo grandi. Gli utenti possono attivare o disattivare il ridimensionamento in Impostazioni > Chat. Impostare `enabled` qui sovrascrive tale scelta per tutti e blocca l'interruttore; ometterlo lascia gli utenti liberi di decidere.

- `enabled` (Booleano)
  - Forza il ridimensionamento attivato (`true`) o disattivato (`false`) per tutti. Se omesso, ogni utente decide, con il ridimensionamento attivo per impostazione predefinita.
- `maxWidth` (Number)
  - Larghezza massima delle immagini ridimensionate, in pixel. Minimo `1`. **Predefinito:** `1900`
- `maxHeight` (Number)
  - Altezza massima delle immagini ridimensionate, in pixel. Minimo `1`. **Predefinito:** `1900`
- `quality` (Number)
  - Qualità di compressione JPEG da `0` a `1`. **Predefinito:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```


## textFallbackWithoutTools

Quando un caricamento viene instradato verso `none` (archiviato, disponibile solo per gli strumenti) e il turno non esegue alcuno strumento in grado di leggerlo, LibreChat può invece inviare il testo estratto del file. Per abilitare questa funzione, imposta `textFallbackWithoutTools: true`. Può essere impostata globalmente in `fileConfig` oppure per singola voce in `fileConfig.endpoints` (incluso `default`); un valore specifico dell'endpoint ha la precedenza su quello globale.

**Predefinito:** `false`

Si applica solo agli allegati dei messaggi il cui percorso è stato dedotto; una destinazione scelta esplicitamente dall'utente non viene mai rivalutata, e i file conservati nelle risorse degli strumenti di un agente non arrivano mai a un prompt. Vengono eseguiti solo gli estrattori integrati per documenti e testo semplice, quindi non viene effettuata alcuna chiamata RAG o OCR per un file destinato a uno strumento. I file esistenti privi di testo estratto non vengono retroattivamente elaborati.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

I file forniti all'ambiente di esecuzione del codice entro questa finestra (in millisecondi) saltano il controllo di disponibilità in tempo reale prima del riutilizzo. Minimo `0`.

**Predefinito:** `21600000` (6 ore)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

Per quanti millisecondi la fase di priming attende un controllo di disponibilità legacy di File Search prima di incorporare comunque il file. Minimo `1`.

**Predefinito:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', 'Impostazioni per l\'analisi diretta di file di testo senza OCR.', 'Configures which file types are processed as plain text files for direct content extraction.'],
  ]}
/>

**Descrizione:** La sezione `text` configura quali tipi di file devono essere elaborati utilizzando l'estrazione diretta del testo.

**Nota:** L'analisi del testo è il metodo predefinito utilizzato dalla funzione "Carica come testo" (controllata dalla capacità `context`). Per maggiori informazioni, consulta [Carica come testo](/docs/features/upload_as_text).

- L'elenco predefinito corrisponde a qualsiasi tipo MIME ben formato. I file già in formato testo (`text/*`, JSON, YAML, XML, SQL, script shell, email `.eml` e simili) vengono letti direttamente. Gli altri tipi binari privi di un parser vengono rifiutati anziché decodificati in dati illeggibili.
- Se restringi l'elenco e l'API RAG è configurata (`RAG_API_URL`), i file corrispondenti vengono inviati all'estrazione del testo dell'API RAG. Se l'API RAG non è disponibile, LibreChat ricorre al parser di documenti integrato.

## stt

`fileConfig.stt` non viene letto nelle versioni attuali di LibreChat; un blocco `stt` in questo punto viene ignorato. I file audio caricati come testo vengono trascritti quando un provider di speech-to-text è configurato in [`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech), utilizzando un elenco predefinito di tipi audio: audio MP3, MPEG, WAV, OGG, Vorbis, MP4 e M4A, FLAC, WebM, AAC, WMA e Opus.

## Priorità di elaborazione dei file [#file-processing-priority]

Quando un file viene aggiunto come testo (Carica come testo, un incollaggio lungo o Contesto file dell'agente), LibreChat utilizza il primo passaggio applicabile:

1. **OCR**: esiste una sezione `ocr` in `librechat.yaml` e il file corrisponde a `fileConfig.ocr.supportedMimeTypes`. Se il servizio OCR non riesce, viene provato successivamente il parser di documenti integrato.
2. **Estrazione del testo con RAG API**: `text.supportedMimeTypes` è stato ridotto rispetto al valore predefinito, la RAG API è configurata e il file corrisponde all'elenco.
3. **Parser di documenti integrato**: file PDF, DOCX, XLS e XLSX, ODT e ODS. Legge solo gli strati di testo.
4. **Speech-to-text**: file audio, quando è configurato un provider STT.
5. **Analisi del testo**: file corrispondenti a `text.supportedMimeTypes`.

Un'immagine o un PDF scansionato senza OCR configurato non contiene testo estraibile, quindi il caricamento non riesce e viene visualizzato un messaggio che indica la necessità di un servizio OCR.

## legacyFileUploadUX

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', 'Come un file allegato raggiunge il modello quando l\'utente non ha scelto una destinazione.', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

Ogni valore è uno dei seguenti:

- `provider`: il file viene inviato al modello come allegato nativo (input immagine, PDF, audio o video).
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`: il file viene archiviato e reso disponibile a strumenti come l'esecuzione di codice o la ricerca nei file, ma non viene inviato al modello.

`overrides` associa un MIME type, oppure un wildcard `type/*`, a un valore. `fallback` si applica a tutto ciò che non è elencato. LibreChat controlla prima gli override dell'endpoint, poi il fallback dell'endpoint, poi gli override di primo livello, poi il fallback di primo livello, e infine il valore predefinito integrato.

Il valore predefinito integrato invia immagini, audio, video e PDF al provider e tutto il resto come testo. Inoltre si adatta all'endpoint: un PDF su un provider che non è in grado di leggere i PDF viene inviato come testo, l'audio o il video su un provider senza supporto multimediale vengono trascritti oppure esclusi dal prompt, AWS Bedrock riceve nativamente i tipi di documento supportati e i tipi per i quali non è possibile estrarre il testo (ad esempio gli archivi) vengono impostati su `none`. I valori configurati vengono utilizzati così come sono scritti, senza questi adattamenti.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

<OptionTable
  options={[

**Descrizione:** Ogni oggetto sotto endpoints è un record che può avere le seguenti impostazioni:

### Panoramica [#overview-1]

  - `disabled`
      - Se la gestione dei file è disabilitata per l'endpoint.
  - `fileLimit`
      - Il numero massimo di file consentiti per richiesta di caricamento.

      - La dimensione massima totale per tutti i file in una singola richiesta. In unità di MB (ad esempio, usa `20` per 20 megabyte)

  - `supportedMimeTypes`
      - Un elenco di [Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression) che specifica quali tipi MIME sono consentiti per il caricamento. Questo può essere personalizzato per limitare i tipi di file.

## supportedMimeTypes [#supportedmimetypes-2]

**Chiave:**
<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Un elenco di espressioni regolari che definisce i tipi MIME consentiti per il caricamento.', 'Each pattern must compile with the active server regex engine or configuration validation fails.'],
  ]}
/>

**Predefinito:** Varia in base all'endpoint

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
assistants:
  supportedMimeTypes:
      - "image/.*"
      - "application/pdf"
```

LibreChat normalizza gli alias MIME comuni prima di applicare questi pattern. In particolare, `application/x-shellscript` (riportato da Chrome su Linux) e `text/x-shellscript` (riportato da libmagic) diventano `application/x-sh`. Una allowlist personalizzata che accetta script shell dovrebbe quindi consentire il tipo canonico `application/x-sh`. I caricamenti rifiutati restituiscono al client il tipo non supportato segnalato, invece di un errore generico del server.

## Pulizia dei file e dei vettori conservati [#retained-file-and-vector-cleanup]

L'eliminazione di un file preserva la copia primaria leggibile fino a quando la pulizia dell'archiviazione secondaria non viene confermata. `fileConfig.retainedFileCleanup` ha come valore predefinito `false`: i file incorporati e le destinazioni conservate di Code Interpreter non vengono eliminati in modo distruttivo finché questa opzione non viene abilitata esplicitamente. Abilitarla solo dopo che ogni replica e ogni destinazione di rollback legge le destinazioni dei file conservati.

| Campo | Predefinito | Significato |
| ----- | ----------- | ----------- |
| `retainedFileCleanup` | `false` | Attiva la pulizia utilizzando i metadati di destinazione conservati dopo il rollout del lettore. |
| `vectorOwnershipTrackingStart` | Non impostato | Data e ora UTC di soglia scelta dopo che tutti i writer vettoriali legacy e i target di rollback sono stati dismessi. |
| `vectorDeletionConcurrency` | `4` | Intero da `1` a `16`; numero massimo di eliminazioni di namespace in corso per file. |

La cancellazione dei vettori richiede inoltre una prova completa e registrata della proprietà e dell'inserimento, effettuato alla data del cutoff sicuro del writer o successivamente. Una prova mancante, non valida, futura o precedente al cutoff fa fallire la procedura in modo sicuro e lascia il file e i relativi vettori al loro posto. Impostare il cutoff non ripara i metadati di proprietà più vecchi e non deve essere retrodatato per rendere eleggibili i file legacy ambigui.

Le destinazioni della pulizia riguardano ogni namespace di entità registrato e il namespace senza ambito. Un namespace è considerato pulito dopo una risposta DELETE riuscita. Un `404` è accettato come assenza solo dopo che un controllo dell'inventario riuscito, nello stesso namespace, esclude il file. Se un secondario o un namespace non può essere confermato come assente, il primario rimane disponibile per un nuovo tentativo. Queste impostazioni non popolano retroattivamente i record legacy; pianifica una riconciliazione verificata separatamente per i file storici ambigui.
