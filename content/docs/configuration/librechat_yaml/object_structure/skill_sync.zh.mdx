## 概述 [#overview]

`skillSync` 对象允许管理员从外部来源同步 Skills。目前支持的提供方为 GitHub。

GitHub Skill Sync 会从配置的仓库路径中读取 `SKILL.md` 文件及其捆绑文件，将它们存储为 `source: "github"` 的 Skills，并在后续同步时保持镜像行与上游仓库同步。

## 示例 [#example]

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
        # credentialKey: production-skills
        # tenantId: your-tenant-id
```

<Callout type="warning" title="凭据">
  每个源请使用 `token` 或 `credentialKey` 中的一个，不要同时使用。`token` 必须是环境变量引用，例如 `${GITHUB_SKILLS_TOKEN}`。请使用针对所选仓库设置的 GitHub 精细化个人访问令牌（fine-grained personal access token），并授予其只读的 Contents 和 Metadata 权限。
</Callout>

### 源身份 [#source-identity]

`id` 字段是镜像标识的一部分。请保持其稳定。将源指向重命名后的仓库或新的 ref 会使镜像的 Skills 继续链接到同一个源 id，而更改源 id 则会创建一个新的镜像。

当设置了 `tenantId` 时，同步读写操作将在该租户的隔离上下文中运行。请将 `tenantId` 视为特定源 ID 的不可变属性：后续对其进行更改、添加或移除，会导致之前镜像的 Skills 保留在旧租户中。

## 同步行为 [#sync-behavior]

GitHub Skill Sync:

- 发现每个配置路径下的 `SKILL.md` 文件。
- 导入 `SKILL.md` 正文、frontmatter 和捆绑文件。
- 存储源元数据，例如 source id、owner、repo、ref、skill path、commit SHA 和 blob SHA。
- 当上游文件发生更改时，更新镜像的 Skills。
- 删除已从配置源中移除的镜像 Skills 和文件。
- 独立验证并发布 Skills，因此某个无效或冲突的 Skill 不会掩盖来自同一来源的有效 Skills。
- 保留已跳过 Skill 的最后已知良好镜像，并回滚该 Skill 的不完整写入。
- 当运行发布了至少一个 Skill 但跳过了另一个时，将其标记为 `partial`，并记录有限的跳过计数和详细信息，以供管理员状态读取。
- 使用同步锁，确保同一时间只有一个 GitHub 同步任务在运行。

当 `SKILL.md` 的 frontmatter 键值保持在有界的、JSON 安全的扩展限制内时，系统会接受未知的键。无效的已识别字段、不安全的扩展值、重复的名称以及所有权冲突只会导致受影响的 Skill 被跳过。身份验证、速率限制、锁丢失、存储库访问和回滚失败仍属于源级别的故障。

## 删除技能 [#skill-deletion]

顶层 `skillDeletion` 对象用于控制后台进程，该进程负责完成 Skill 的删除并清理其存储文件，以及被放弃的 Skill 上传文件。它独立于 `skillSync`，适用于所有 Skill。未知的键会被拒绝。

```yaml filename="librechat.yaml"
skillDeletion:
  finalizationEnabled: true
  sweepIntervalMs: 60000
  claimLeaseMs: 120000
  batchSize: 100
  recheckIntervalMs: 3600000
```

## 从磁盘部署技能 [#deployment-skills-from-disk]

与 `skillSync` 相互独立,LibreChat 会在启动时从服务器上的一个目录加载 Skills。每个 Skill 都是一个文件夹,其中包含一个 `SKILL.md` 以及所有附带的文件。除非你在 `.env` 中设置了 `DEPLOYMENT_SKILLS_DIR`(参见 [dotenv](/docs/configuration/dotenv)),否则该目录默认为项目根目录下的 `./skill`。

部署技能（Deployment Skills）会显示给每一位拥有技能功能权限的用户，在界面中为只读，并且会隐藏与其同名的用户自建技能。这些技能在启动时读取一次，因此在添加、删除或编辑文件后，请重启 LibreChat。[智能体插件](/docs/configuration/agent_plugins)同样可以附带部署技能；此目录中的技能与插件技能同名时，以此目录中的技能为准。
