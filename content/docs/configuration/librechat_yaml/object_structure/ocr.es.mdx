## Descripción general [#overview]

El objeto `ocr` le permite configurar los ajustes de Reconocimiento Óptico de Caracteres (OCR) para la aplicación, permitiendo la extracción de texto a partir de imágenes. Esta sección proporciona un desglose detallado de la estructura del objeto `ocr`.

Hay 5 campos bajo `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Notas:**

- La OCR solo está activa cuando `librechat.yaml` tiene una sección `ocr`. Definir `OCR_API_KEY` por sí solo no la activa. Para la API alojada de Mistral, basta con `strategy: "mistral_ocr"` más `OCR_API_KEY` en `.env`, ya que `apiKey` y `baseURL` toman por defecto `${OCR_API_KEY}` y `${OCR_BASEURL}` (o `https://api.mistral.ai/v1` cuando esta última no está definida).
- El OCR se ejecuta en los archivos añadidos como texto: en Upload as Text en el chat y en File Context en el Agent Builder. Los agentes también necesitan la capacidad `ocr` en `endpoints.agents.capabilities`, que se incluye por defecto. Sin ella, una estrategia de OCR configurada rechaza la carga con el mensaje "OCR capability is not enabled for Agents".
- Qué tipos de archivo se envían a OCR se controla mediante [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr).
- La estrategia predeterminada es `mistral_ocr`. Cuando `mistralModel` está vacío, se usa `mistral-ocr-latest`.
- Los modelos Mistral OCR desplegados en Azure pueden utilizarse configurando la estrategia en `azure_mistral_ocr`.
- Los modelos Mistral OCR desplegados en Google Vertex AI pueden utilizarse configurando la estrategia en `vertexai_mistral_ocr`.
  - Requiere que la variable de entorno `GOOGLE_SERVICE_KEY_FILE` esté configurada con las credenciales de la cuenta de servicio
  - La clave de servicio puede proporcionarse como: ruta de archivo, URL, JSON codificado en base64 o cadena JSON sin formato
  - El ID del proyecto y la ubicación se extraen automáticamente de las credenciales de la cuenta de servicio
- La extracción de texto local está disponible mediante `document_parser`, que extrae texto de archivos PDF, DOCX, XLS/XLSX, ODT y ODS de hasta 15 MB sin necesidad de ninguna API externa.
  - Usa `pdfjs-dist`, `mammoth` y `SheetJS` de forma local; no se necesita clave de API ni URL base.
  - Solo el campo `strategy` es obligatorio; `apiKey`, `baseURL` y `mistralModel` son ignorados
- `custom_ocr` está aceptado por el esquema, pero todavía no tiene implementación.
- El análisis de variables de entorno es compatible con los parámetros `apiKey`, `baseURL` y `mistralModel`.

## Análisis automático de documentos (No requiere configuración) [#automatic-document-parsing-no-configuration-required]

El `document_parser` integrado se ejecuta automáticamente para las cargas de archivos de agentes **incluso cuando no hay ningún bloque `ocr` configurado** en tu `librechat.yaml`. Esto significa que los archivos PDF, DOCX, XLS/XLSX y ODS se analizan de forma predeterminada sin necesidad de configuración adicional.

La lógica de resolución funciona de la siguiente manera:

1. **Sin configuración de `ocr`**: Cuando se sube un archivo de contexto de agente y su tipo MIME coincide con un tipo de documento compatible (PDF, DOCX, Excel, ODS), se utiliza directamente el `document_parser`. No se requiere ninguna verificación de la capacidad de OCR para el agente.

2. **`ocr` configurado**: Se intenta primero la estrategia configurada (por ejemplo, `mistral_ocr`). Si la estrategia configurada **falla en tiempo de ejecución**, se utiliza `document_parser` como alternativa para que la extracción de texto siga teniendo éxito en los tipos de documento compatibles.

3. **Ninguno tiene éxito**: si tanto la estrategia configurada como el analizador de documentos fallan (por ejemplo, si el archivo es un PDF solo con imágenes y sin texto incrustado), se devuelve un error que sugiere que se necesita un servicio de OCR.

<Callout type="info">
El `document_parser` maneja únicamente documentos basados en texto. Para archivos PDF basados en imágenes o documentos escaneados, aún necesita una estrategia de OCR configurada (como `mistral_ocr`) para extraer el texto de las imágenes dentro de esos archivos.
</Callout>

## Ejemplo [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Ejemplo con Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Ejemplo con Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Para Vertex AI, despliega un modelo Mistral OCR en tu proyecto de Google Cloud, crea una cuenta de servicio que pueda llamar al endpoint de Vertex AI y apunta `GOOGLE_SERVICE_KEY_FILE` a su clave. La variable acepta una ruta de archivo, una URL desde la que obtener la clave, JSON codificado en base64 o la cadena JSON sin procesar:

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Ejemplo con analizador de documentos local (no se requiere API externa):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Exenciones de host:puerto privado de confianza para comprobaciones SSRF de tiempo de conexión OCR. Los destinos públicos permanecen disponibles. Las entradas requieren un puerto y no pueden ser URLs, rutas, rangos CIDR, hosts simples o literales de IP pública.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

Las solicitudes de OCR bloquean destinos privados, de bucle local (loopback), de enlace local (link-local) y de metadatos en la nube en el momento de la conexión y desactivan las redirecciones. `allowedAddresses` es una lista de exención para destinos de confianza exactos de tipo `host:port`, `private.ip:port` o `[ipv6]:port`; no restringe el acceso a destinos públicos.

<Callout type="warning" title="Confíe en las excepciones con precaución">
  Use `allowedAddresses` solo para un servicio de OCR privado que usted controle. Un nombre de host exento confía en cualquier dirección privada a la que se resuelva en ese puerto, por lo que es preferible usar un literal de IP privada cuando sea posible. Con un proxy de reenvío (forward proxy), el proxy debe aplicar la política SSRF de destino; los destinos privados literales permanecen bloqueados a menos que se eximan explícitamente.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'La estrategia de OCR a utilizar.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Estrategias disponibles:**

- `mistral_ocr`: Utiliza el OCR de Mistral a través de la API estándar de Mistral.
- `azure_mistral_ocr`: Utiliza los modelos Mistral OCR desplegados en Azure AI Foundry. Establece `mistralModel` con el nombre de tu despliegue y `baseURL` con el endpoint del despliegue.
- `vertexai_mistral_ocr`: Usa los modelos Mistral OCR desplegados en Google Cloud Vertex AI, autenticados con `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Utiliza extracción de texto local para archivos PDF, DOCX, XLS/XLSX y OpenDocument. No requiere API externa. También se ejecuta automáticamente para las cargas de archivos de agentes cuando no hay una configuración de `ocr` presente, y como respaldo cuando una estrategia de OCR configurada falla.
- `custom_ocr`: Reservado para un servicio OCR personalizado en `baseURL`. Aún no implementado.
