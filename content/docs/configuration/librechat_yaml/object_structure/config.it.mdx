## langfuse

<OptionTable
  options={[
    [
      'langfuse',
      'Object',
      'Configura la connessione crittografata a Langfuse e le intestazioni di richiesta di proprietà della distribuzione.',
      '',
    ],
  ]}
/>

**Sottochiavi:**

<OptionTable
  options={[
    ['enabled', 'Boolean', 'Abilita o disabilita il tracciamento Langfuse per questo ambito di configurazione.', ''],
    ['publicKey', 'String', 'Chiave pubblica del progetto Langfuse.', ''],
    ['secretKey', 'String', 'Chiave segreta del progetto Langfuse crittografata.', ''],
    ['projectId', 'String', 'Identità del progetto Langfuse verificata.', ''],
    ['secretKeyPreview', 'String', 'Anteprima mascherata generata dal server della chiave segreta memorizzata.', ''],
    [
      'destination',
      'String',
      'Seleziona una chiave di destinazione Langfuse approvata per la distribuzione.',
      '',
    ],
    [
      'headers',
      'Object/Map of Strings',
      'Intestazioni di proprietà del deployment inviate a un\'origine Langfuse configurata per l\'autenticazione tramite proxy o gateway. Supporta riferimenti `${ENV_VAR}`.',
      '',
    ],
  ]}
/>

Gestisci i campi di connessione tramite **Settings → Langfuse** o un client di configurazione amministratore autorizzato. Il flusso delle impostazioni verifica la connessione e deriva `projectId`; l'amministratore autorizzato scrive `secretKey` crittografata, genera `secretKeyPreview` e oscura il segreto durante la lettura. I valori `secretKey` in testo semplice inseriti direttamente in `librechat.yaml` non sono accettati dal percorso di connessione in fase di runtime. I campi legacy `displaySecretKey` e `fanout.enabled` non fanno più parte dello schema.

`headers` è diverso: si tratta di infrastruttura di deployment e può essere impostato solo in `librechat.yaml`. La configurazione dell'amministratore rifiuta sia l'intera mappa che i singoli percorsi degli header, in modo che le credenziali del gateway non vengano archiviate o restituite tramite la configurazione basata su Mongo. I valori supportano l'interpolazione `${ENV_VAR}`; utilizza riferimenti alle variabili d'ambiente invece di valori letterali. LibreChat scarta le variabili non risolte, i riferimenti a segreti dell'infrastruttura protetti, i valori vuoti e i nomi di header HTTP non validi, emettendo un avviso.

Gli header personalizzati vengono inviati solo durante il tracciamento e l'esportazione di file multimediali, le richieste di feedback-score, la ricerca di progetti e la verifica delle credenziali di amministrazione quando la distribuzione risolve esattamente una origine Langfuse. Se la configurazione centrale, del tenant o del collector produce origini multiple, LibreChat non invia alcun header personalizzato e registra un avviso poiché la mappa non può identificare in modo sicuro un destinatario. Non è possibile utilizzare segnaposto `{{...}}` per utente e il collector fanout inoltra a monte solo l'intestazione `Authorization`.

```yaml filename="langfuse / headers"
langfuse:
  headers:
    CF-Access-Client-Id: '${CF_ACCESS_CLIENT_ID}'
    CF-Access-Client-Secret: '${CF_ACCESS_CLIENT_SECRET}'
```

`langfuse` è una sezione di sola configurazione di base. Le sostituzioni della configurazione di ruolo, gruppo e utente non possono sostituirla o eliminarla.

Consulta [Langfuse Configuration](/docs/configuration/langfuse) per le regole di disponibilità, la configurazione del proxy autenticato, le credenziali gestite dall'ambiente e il deployment opzionale fanout.

## fileStrategy

- **Opzioni**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategy',
      'String',
      'Determina dove salvare i file caricati/generati dagli utenti. Se omesso, il valore predefinito è `"local"`.',
      'fileStrategy: "firebase"',
    ],
  ]}
/>

- **Note**:
  - `"cloudfront"` archivia i file in S3 e restituisce URL CloudFront per una distribuzione multimediale stabile, cookie firmati e download firmati.
  - `"firebase"` serve i file tramite le posizioni edge di Firebase Storage e Firebase Hosting.
  - S3 serve i file tramite **presigned URLs** (token temporanei firmati) che scadono. Una volta scaduti, qualsiasi immagine o avatar che faccia riferimento a quell'URL apparirà interrotto nell'interfaccia utente. Questo rende S3 inadatto come strategia primaria per le risorse visive. Vedi la [discussione correlata](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) per i dettagli.
  - Per ottenere le migliori prestazioni con immagini e avatar, utilizza `"cloudfront"` o `"firebase"`, oppure configura `fileStrategies` per instradare `avatar` e `image` verso una strategia basata su CDN.
  - Si prega di fare riferimento alla [documentazione su File Storage & CDN](/docs/configuration/cdn) per i dettagli sulla configurazione.

## fileStrategies

Consente un controllo granulare sulle strategie di archiviazione dei file per diversi tipi di file.

- **Strategie disponibili**: "local" | "firebase" | "s3" | "azure_blob" | "cloudfront"

<OptionTable
  options={[
    [
      'fileStrategies',
      'Object',
      'Configura diverse strategie di archiviazione per diversi tipi di file. Più flessibile della singola opzione fileStrategy.',
      '',
    ],
  ]}
/>

**Sotto-chiavi:**

<OptionTable
  options={[
    [
      'default',
      'String',
      'Strategia di archiviazione di fallback quando non è definito un tipo specifico. L\'impostazione predefinita è "local".',
      '',
    ],
    [
      'avatar',
      'String',
      'Strategia di archiviazione per le immagini degli avatar di utenti e agenti. Si consiglia di utilizzare una strategia basata su CDN (`"cloudfront"` o `"firebase"`) per prestazioni ottimali.',
      '',
    ],
    [
      'image',
      'String',
      'Strategia di archiviazione per le immagini caricate nelle chat. Si consiglia di utilizzare una strategia basata su CDN (`"cloudfront"` o `"firebase"`) per prestazioni ottimali.',
      '',
    ],
    ['document', 'String', 'Strategia di archiviazione per il caricamento di documenti (PDF, file di testo, ecc.).', ''],
    ['skills', 'String', 'Strategia di archiviazione per i file inclusi negli Skills.', ''],
  ]}
/>

- **Note**:
  - Questa impostazione ha la precedenza sulla singola opzione `fileStrategy`
  - Se un tipo di file specifico non è configurato, viene utilizzato il fallback su `default`, poi su `fileStrategy` e infine su `"local"`.
  - Le immagini e gli avatar necessitano di URL persistenti e stabili per essere visualizzati correttamente nell'interfaccia utente. Gli URL presigned di S3 scadono (limite AWS: 7 giorni per utenti IAM, ore per credenziali basate su STS/ruoli), causando la rottura delle immagini nel selettore dei modelli e nell'interfaccia di chat. Consulta la [discussione correlata](https://github.com/LibreChat-AI/LibreChat/discussions/10280#discussioncomment-14803903) per il contesto completo. Utilizza `"cloudfront"` o `"firebase"` per `avatar` e `image` per evitare questo problema.
  - S3 e Azure Blob Storage sono adatti per l'archiviazione di `document`, dove gli URL di download pre-firmati a breve termine sono appropriati.
  - Si prega di fare riferimento alla [documentazione su File Storage & CDN](/docs/configuration/cdn) per i dettagli di configurazione di ciascun provider di archiviazione.

**Esempi:**

```yaml filename="fileStrategies - All in one place"
# Use a single strategy for all file types
fileStrategies:
  default: 's3'
```

```yaml filename="fileStrategies - Mixed strategies"
# Route images and avatars to CDN, keep documents in object storage
fileStrategies:
  avatar: 'cloudfront' # CDN delivery for avatars
  image: 'cloudfront' # CDN delivery for generated/uploaded images
  document: 's3' # Object storage for documents
```

```yaml filename="fileStrategies - Partial configuration"
# Only configure specific types, others use default
fileStrategies:
  default: 'local'
  avatar: 'firebase' # Only avatars use Firebase CDN, everything else is local
```

## secureImageLinks

<OptionTable
  options={[
    [
      'secureImageLinks',
      'Boolean',
      'Richiede l\'autorizzazione per i link alle immagini ospitati localmente dall\'app. Predefinito: true.',
      'secureImageLinks: true',
    ],
  ]}
/>

Le immagini locali sono protette quando questo campo viene omesso. Le immagini delle conversazioni private richiedono una sessione attiva e l'accesso da parte del proprietario. Gli avatar degli utenti archiviati richiedono un visualizzatore autenticato nello stesso tenant. Gli avatar degli Agent seguono l'ACL di visualizzazione dell'Agent, inclusa la visibilità pubblica, mentre gli avatar degli Assistant richiedono lo stesso tenant oltre alla condivisione dell'endpoint effettiva o alla policy di gestione dell'Assistant. I fallimenti nell'autorizzazione e nella ricerca della configurazione comportano un blocco dell'accesso (fail closed).

Imposta `secureImageLinks: false` solo come opzione di compatibilità per distribuzioni che espongono intenzionalmente URL di immagini locali senza autenticazione. Le sostituzioni della configurazione di ruolo e utente vengono risolte a partire dalla configurazione effettiva del proprietario dell'immagine.

**Descrizione:**

La configurazione `clientImageResize` controlla il ridimensionamento lato client prima del caricamento. Questa funzionalità aiuta a:

- **Previeni errori di caricamento** dovuti a file immagine di grandi dimensioni che superano i limiti del server
- **Riduci l'utilizzo della larghezza di banda** comprimendo le immagini prima della trasmissione
- **Migliora le prestazioni di caricamento** con dimensioni dei file ridotte
- **Mantieni la qualità dell'immagine** ottimizzando al contempo le dimensioni del file

Quando il ridimensionamento è abilitato, le immagini supportate che superano `maxWidth` o `maxHeight` vengono ridotte nel browser prima del caricamento. LibreChat preserva le proporzioni, non esegue mai l'upscaling di immagini più piccole e mantiene il file originale quando il risultato codificato non risulterebbe più piccolo.

Se `enabled` viene omesso, gli utenti possono attivare o disattivare **Ridimensiona immagini prima del caricamento** in **Impostazioni > Chat**. La preferenza viene memorizzata nel browser e, per impostazione predefinita, è disattivata. L'impostazione di `enabled: true` o `enabled: false` in `librechat.yaml` sovrascrive la preferenza di ogni utente e disabilita l'interruttore.

**Esempio:**

```yaml filename="clientImageResize"
fileConfig:
  clientImageResize:
    # Omit enabled so each user can choose under Settings > Chat.
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

Per imporre un comportamento per il deployment, aggiungi `enabled: true` oppure `enabled: false` allo stesso blocco.

**Note:**

- La pipeline di ridimensionamento supporta JPEG, PNG e WebP nei browser dotati delle API Canvas richieste.
- I file PNG e WebP animati vengono inviati senza modifiche, in modo che il ridimensionamento non elimini l'animazione.
- L'output mantiene il formato originale. Non esiste un'impostazione `compressFormat`.
- I codificatori del browser potrebbero ignorare `quality` per formati senza perdita di dati come PNG.
- Un errore nel ridimensionamento comporta il ripiegamento sul file originale; i normali limiti di caricamento del server rimangono validi.

**Chiave:**

<OptionTable

/>

**Sottochiavi:**

<OptionTable
  options={[
    [
      'allowedDomains',
      'Array of Strings',
      'Whitelist rigorosa dei domini per le connessioni al server MCP. Quando impostata, sono raggiungibili solo le voci elencate.',
      '',
    ],
    [
      'allowedAddresses',
      'Array of Strings',
      'Elenco di esenzione SSRF (solo spazio IP privato). Consente specifici servizi host:porta privati senza attivare la modalità strict-whitelist in `allowedDomains`.',
      '',
    ],
    [
      'catalogRecovery',
      'Object',

      '',
    ],
  ]}
/>

- **Note**:
  - Questa è una funzionalità di sicurezza per proteggere da abusi / utilizzi impropri di indirizzi interni tramite server MCP
  - Per impostazione predefinita, LibreChat impedisce ai server MCP di connettersi a indirizzi di rete interni, locali o privati.
  - I server MCP che utilizzano indirizzi IP locali o domini possono essere aggiunti alla whitelist rigorosa `allowedDomains` (che diventa quindi l'unico insieme raggiungibile), oppure, per mantenere raggiungibili le destinazioni pubbliche, possono essere esentati come servizi host:porta esatti tramite `allowedAddresses`
  - Come per tutte le modifiche alla configurazione yaml, è necessario riavviare LibreChat affinché abbiano effetto.
  - Supporta domini, sottodomini wildcard (`*.example.com`), domini Docker e indirizzi IP

**Esempio:**

```yaml filename="mcpSettings"
mcpSettings:
  # Strict whitelist mode:
  # allowedDomains:
  #   - "example.com"           # Specific domain
  #   - "*.example.com"         # All subdomains
  #   - "http://mcp-server:3000" # Internal service, explicitly whitelisted

  # Default SSRF mode with private service exemptions:
  allowedAddresses:
    - 'host.docker.internal:8080' # Permit one private host on one port
    - '10.0.0.5:8000' # Permit one private IP on one port
```

## mcpServers

**Chiave:**

<OptionTable
  options={[
    [
      'mcpServers',
      'Object',
      'Definisce la configurazione per i server Model Context Protocol (MCP), consentendo l\'integrazione dinamica dei server MCP all\'interno dell\'applicazione.',
      '',
    ],
  ]}
/>

**Sottochiavi:**

<OptionTable
  options={[
    [
      '<serverName>',
      'Object',
      'Ogni chiave sotto `mcpServers` rappresenta una configurazione individuale di un server MCP, identificata da un nome univoco.',
      '',
    ],
  ]}
/>

- **Note**:
  - L'inizializzazione avviene all'avvio e l'app deve essere riavviata affinché le modifiche abbiano effetto.
  - `<serverName>` è un identificatore univoco per ogni configurazione del server MCP.
  - Ogni server MCP può essere configurato utilizzando uno dei quattro tipi di connessione:
    - `stdio`
    - `websocket`
    - `sse`
    - `streamable-http`
  - Il campo `type` specifica il tipo di connessione al server MCP.
  - Se `type` viene omesso, viene impostato come predefinito in base alla presenza e al formato di `url` o `command`:
    - Se `url` è specificato e inizia con `http` o `https`, `type` è impostato come `sse` per impostazione predefinita.
    - Se `url` è specificato e inizia con `ws` o `wss`, `type` è impostato per impostazione predefinita su `websocket`.
    - Se `command` è specificato, `type` è impostato come `stdio` per impostazione predefinita.
  - Ulteriori opzioni di configurazione includono:
    - `timeout`: Timeout in millisecondi per le richieste al server MCP. Determina quanto tempo attendere una risposta per le richieste di strumenti (tool).
    - `initTimeout`: Timeout in millisecondi per l'inizializzazione del server MCP. Determina quanto tempo attendere affinché il server si inizializzi.
    - `serverInstructions`: Controlla se le istruzioni del server sono incluse nel contesto dell'agente. Può essere `true` (usa quelle fornite dal server), `false` (disabilitato) o una stringa personalizzata (sovrascrive quelle fornite dal server).
    - `customUserVars`: (Opzionale) Definisce variabili personalizzate (ad esempio, chiavi API, URL) che i singoli utenti possono impostare per un server MCP. Questi valori per utente, forniti tramite l'interfaccia utente, possono quindi essere referenziati nelle configurazioni `headers` o `env` del server utilizzando la sintassi `{{VARIABLE_NAME}}`. Ciò consente l'autenticazione o la personalizzazione per utente per gli strumenti MCP.
  - vedi: [Struttura dell'oggetto MCP Servers](/docs/configuration/librechat_yaml/object_structure/mcp_servers)

**Esempio:**

```yaml filename="mcpServers"
mcpServers:
  everything:
    # type: sse # type can optionally be omitted
    url: http://localhost:3001/sse
    timeout: 30000
    initTimeout: 10000
    serverInstructions: true # Use server-provided instructions
  puppeteer:
    type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-puppeteer'
    timeout: 30000
    initTimeout: 10000
    serverInstructions: 'Do not access any local files or local/internal IP addresses'
  filesystem:
    # type: stdio
    command: npx
    args:
      - -y
      - '@modelcontextprotocol/server-filesystem'
      - /home/user/LibreChat/
    iconPath: /home/user/LibreChat/client/public/assets/logo.svg
  mcp-obsidian:
    command: npx
    args:
      - -y
      - 'mcp-obsidian'
      - /path/to/obsidian/vault
  streamable-http-example:
    type: streamable-http
    url: https://example.com/mcp
    headers:
      Authorization: 'Bearer ${API_TOKEN}'
    timeout: 30000
  per-user-crendentials-example:
    type: sse
    url: 'https//some.mcp/sse'
    headers:
      X-Custom-Auth-Token: '{{USER_API_KEY}}' # Placeholder for the user-provided API key, defined in `customUserVars` below.
    customUserVars:
      USER_API_KEY:
        title: 'Service API Key'
        description: "Your personal API key for this service. You can get it <a href='https://example.com/api-keys' target='_blank'>here</a>."
    serverInstructions: true
```
