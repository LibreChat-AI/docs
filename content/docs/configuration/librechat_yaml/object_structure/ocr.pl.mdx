## Przegląd [#overview]

Obiekt `ocr` pozwala na skonfigurowanie ustawień optycznego rozpoznawania znaków (OCR) dla aplikacji, umożliwiając ekstrakcję tekstu z obrazów. Ta sekcja zawiera szczegółowy opis struktury obiektu `ocr`.

Istnieje 5 pól w sekcji `ocr`:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**Uwagi:**

- OCR jest aktywne tylko wtedy, gdy plik `librechat.yaml` zawiera sekcję `ocr`. Samo ustawienie `OCR_API_KEY` nie włącza tej funkcji. W przypadku hostowanego API Mistral wystarczy `strategy: "mistral_ocr"` oraz `OCR_API_KEY` w pliku `.env`, ponieważ `apiKey` i `baseURL` domyślnie przyjmują wartości `${OCR_API_KEY}` oraz `${OCR_BASEURL}` (lub `https://api.mistral.ai/v1`, gdy ta zmienna nie jest ustawiona).
- OCR jest uruchamiany dla plików dodanych jako tekst: Upload as Text w czacie oraz File Context w Agent Builder. Agenci potrzebują także możliwości `ocr` w `endpoints.agents.capabilities`, która jest domyślnie uwzględniona. Bez niej skonfigurowana strategia OCR odrzuca przesłany plik z komunikatem "OCR capability is not enabled for Agents".
- Typy plików, które są kierowane do OCR, kontroluje [`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr).
- Domyślną strategią jest `mistral_ocr`. Gdy `mistralModel` jest pusty, używany jest `mistral-ocr-latest`.
- Modele Mistral OCR wdrożone w Azure mogą być używane poprzez ustawienie strategii na `azure_mistral_ocr`.
- Modele Mistral OCR wdrożone w Google Vertex AI mogą być używane poprzez ustawienie strategii na `vertexai_mistral_ocr`.
  - Wymaga ustawienia zmiennej środowiskowej `GOOGLE_SERVICE_KEY_FILE` z danymi uwierzytelniającymi konta serwisowego
  - Klucz usługi można podać jako: ścieżkę do pliku, URL, ciąg JSON zakodowany w base64 lub surowy ciąg JSON
  - Identyfikator projektu (Project ID) oraz lokalizacja są automatycznie pobierane z poświadczeń konta serwisowego.
- Lokalne wyodrębnianie tekstu jest dostępne za pomocą `document_parser`, który wyodrębnia tekst z plików PDF, DOCX, XLS/XLSX, ODT i ODS o rozmiarze do 15 MB, bez korzystania z żadnego zewnętrznego API.
  - Używa lokalnie `pdfjs-dist`, `mammoth` i `SheetJS`, nie wymaga klucza API ani adresu bazowego
  - Tylko pole `strategy` jest wymagane; `apiKey`, `baseURL` oraz `mistralModel` są ignorowane
- `custom_ocr` jest akceptowany przez schemat, ale nie ma jeszcze implementacji.
- Parsowanie zmiennych środowiskowych jest obsługiwane dla parametrów `apiKey`, `baseURL` oraz `mistralModel`.

## Automatyczne parsowanie dokumentów (bez wymaganej konfiguracji) [#automatic-document-parsing-no-configuration-required]

Wbudowany `document_parser` uruchamia się automatycznie dla plików przesyłanych przez agenta, **nawet jeśli w `librechat.yaml` nie skonfigurowano bloku `ocr`**. Oznacza to, że pliki PDF, DOCX, XLS/XLSX oraz ODS są analizowane od razu po instalacji, bez konieczności dodatkowej konfiguracji.

Logika rozdzielania działa w następujący sposób:

1. **Brak konfiguracji `ocr`**: Gdy plik kontekstowy agenta zostanie przesłany, a jego typ MIME odpowiada obsługiwanemu typowi dokumentu (PDF, DOCX, Excel, ODS), używany jest bezpośrednio `document_parser`. Nie jest wymagane sprawdzanie możliwości OCR dla agenta.

2. **`ocr` config exists**: Skonfigurowana strategia (np. `mistral_ocr`) jest próbowana jako pierwsza. Jeśli skonfigurowana strategia **zawiedzie podczas działania**, jako rezerwa używany jest `document_parser`, dzięki czemu ekstrakcja tekstu nadal się powiedzie dla obsługiwanych typów dokumentów.

3. **Żadna z metod nie powiedzie się**: Jeśli zarówno skonfigurowana strategia, jak i parser dokumentów zawiodą (np. plik to PDF zawierający wyłącznie obrazy, bez osadzonego tekstu), zwracany jest błąd sugerujący konieczność użycia usługi OCR.

<Callout type="info">
`document_parser` obsługuje wyłącznie dokumenty tekstowe. W przypadku plików PDF opartych na obrazach lub zeskanowanych dokumentów, nadal wymagana jest skonfigurowana strategia OCR (taka jak `mistral_ocr`), aby wyodrębnić tekst z obrazów zawartych w tych plikach.
</Callout>

## Przykład [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Przykład z Azure Mistral OCR:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Przykład z Google Vertex AI Mistral OCR:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Dla Vertex AI wdróż model Mistral OCR w swoim projekcie Google Cloud, utwórz konto usługi, które może wywoływać endpoint Vertex AI, i ustaw `GOOGLE_SERVICE_KEY_FILE` tak, aby wskazywało na jego klucz. Zmienna akceptuje ścieżkę do pliku, adres URL, z którego klucz zostanie pobrany, zakodowany w base64 JSON lub surowy ciąg JSON.

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

Przykład z lokalnym parserem dokumentów (nie jest wymagane zewnętrzne API):

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'Zaufane prywatne hosty:porty wyłączone z kontroli SSRF podczas łączenia OCR. Publiczne miejsca docelowe pozostają dostępne. Wpisy wymagają podania portu i nie mogą być adresami URL, ścieżkami, zakresami CIDR, samymi hostami ani publicznymi adresami IP.',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

Żądania OCR blokują miejsca docelowe typu private, loopback, link-local oraz cloud-metadata w momencie łączenia i wyłączają przekierowania. `allowedAddresses` to lista wyjątków dla zaufanych, dokładnych adresów `host:port`, `private.ip:port` lub `[ipv6]:port`; nie ogranicza ona dostępu do publicznych miejsc docelowych.

<Callout type="warning" title="Ufaj wyłączeniom ostrożnie">
  Używaj `allowedAddresses` wyłącznie w przypadku prywatnej usługi OCR, którą kontrolujesz. Wykluczona nazwa hosta ufa każdemu prywatnemu adresowi, na który rozwiązuje się na danym porcie, dlatego w miarę możliwości preferuj bezpośredni adres IP. W przypadku użycia forward proxy, serwer proxy musi wymuszać politykę SSRF dla miejsc docelowych; bezpośrednie prywatne miejsca docelowe pozostają zablokowane, chyba że zostaną wyraźnie wykluczone.
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', 'Strategia OCR do użycia.', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**Dostępne strategie:**

- `mistral_ocr`: Korzysta z usługi OCR Mistral poprzez standardowe API Mistral.
- `azure_mistral_ocr`: Wykorzystuje modele Mistral OCR wdrożone w Azure AI Foundry. Ustaw `mistralModel` na nazwę swojego wdrożenia oraz `baseURL` na endpoint tego wdrożenia.
- `vertexai_mistral_ocr`: Korzysta z modeli OCR Mistral wdrożonych w Google Cloud Vertex AI, uwierzytelnianych za pomocą `GOOGLE_SERVICE_KEY_FILE`.
- `document_parser`: Wykorzystuje lokalną ekstrakcję tekstu dla plików PDF, DOCX, XLS/XLSX oraz OpenDocument. Nie wymaga zewnętrznego API. Uruchamia się również automatycznie w przypadku przesyłania plików przez agenta, gdy nie skonfigurowano `ocr`, oraz jako mechanizm awaryjny, gdy skonfigurowana strategia OCR zawiedzie.
- `custom_ocr`: Zarezerwowane dla niestandardowej usługi OCR pod adresem `baseURL`. Jeszcze niezaimplementowane.
