## 概要 [#overview]

`ocr` オブジェクトを使用すると、アプリケーションの光学式文字認識（OCR）設定を構成でき、画像からテキストを抽出できるようになります。このセクションでは、`ocr` オブジェクトの構造について詳しく解説します。

`ocr` の下には5つのフィールドがあります:

  - `mistralModel`
  - `apiKey`
  - `baseURL`
  - `strategy`
  - `allowedAddresses`

**注記:**

- OCRは、`librechat.yaml`に`ocr`セクションがある場合にのみ有効になります。`OCR_API_KEY`を設定しただけでは有効になりません。Mistralのホスト型APIの場合は、`.env`に`strategy: "mistral_ocr"`と`OCR_API_KEY`を設定すれば十分です。`apiKey`と`baseURL`はデフォルトで`${OCR_API_KEY}`と`${OCR_BASEURL}`になり(未設定の場合は`https://api.mistral.ai/v1`)、この値が使用されます。
- OCRは、チャットの「テキストとしてアップロード」およびAgent Builderの「ファイルコンテキスト」で追加されたファイルに対して実行されます。エージェントでは、`endpoints.agents.capabilities`に`ocr`機能も必要です。この機能はデフォルトで含まれています。この機能がない場合、設定済みのOCR戦略は「OCR capability is not enabled for Agents」というメッセージとともにアップロードを拒否します。
- どのファイルタイプがOCRに送られるかは、[`fileConfig.ocr.supportedMimeTypes`](/docs/configuration/librechat_yaml/object_structure/file_config#ocr)によって制御されます。
- デフォルトの戦略は `mistral_ocr` です。`mistralModel` が空の場合は、`mistral-ocr-latest` が使用されます。
- AzureにデプロイされたMistral OCRモデルは、strategyを`azure_mistral_ocr`に設定することで使用できます。
- Google Vertex AIにデプロイされたMistral OCRモデルは、strategyを`vertexai_mistral_ocr`に設定することで使用できます。
  - `GOOGLE_SERVICE_KEY_FILE` 環境変数をサービスアカウントの認証情報で設定する必要があります。
  - サービスキーは、ファイルパス、URL、base64エンコードされたJSON、または生のJSON文字列として提供できます。
  - プロジェクトIDとロケーションは、サービスアカウントの認証情報から自動的に抽出されます。
- ローカルのテキスト抽出は`document_parser`を通じて利用できます。外部APIを使用せずに、15 MB以下のPDF、DOCX、XLS/XLSX、ODT、ODSファイルからテキストを抽出できます。
  - `pdfjs-dist`、`mammoth`、`SheetJS` をローカルで使用し、API キーやベース URL は不要です
  - `strategy` フィールドのみが必須です。`apiKey`、`baseURL`、および `mistralModel` は無視されます。
- `custom_ocr` はスキーマで受け入れられますが、まだ実装されていません。
- `apiKey`、`baseURL`、および `mistralModel` パラメータに対して、環境変数のパースがサポートされています。

## 自動ドキュメント解析（設定不要） [#automatic-document-parsing-no-configuration-required]

組み込みの `document_parser` は、`librechat.yaml` に `ocr` ブロックが設定されていない場合でも、エージェントへのファイルアップロードに対して自動的に実行されます。つまり、PDF、DOCX、XLS/XLSX、ODSファイルは、設定なしでそのまま解析されます。

解決ロジックは以下の通りです：

1. **`ocr` 設定が存在しない場合**: エージェントのコンテキストファイルがアップロードされ、そのMIMEタイプがサポートされているドキュメント形式(PDF、DOCX、Excel、ODS)に一致する場合、`document_parser` が直接使用されます。エージェントに対するOCR機能のチェックは不要です。

2. **`ocr` 設定が存在する場合**: 設定された戦略(例: `mistral_ocr`)が最初に試行されます。設定された戦略が**実行時に失敗した**場合、サポートされているドキュメントタイプのテキスト抽出が引き続き成功するよう、`document_parser` がフォールバックとして使用されます。

3. **いずれも失敗する場合**: 設定された戦略とドキュメントパーサーの両方が失敗した場合(例: テキストが埋め込まれていない画像のみのPDFなど)、OCRサービスが必要であることを示唆するエラーが返されます。

<Callout type="info">
`document_parser` はテキストベースのドキュメントのみを処理します。画像ベースのPDFやスキャンされたドキュメントの場合は、それらのファイル内の画像からテキストを抽出するために、設定済みのOCR戦略（`mistral_ocr` など）が引き続き必要です。
</Callout>

## 例 [#example]

```yaml filename="ocr"
ocr:
  mistralModel: "mistral-ocr-latest"
  apiKey: "your-mistral-api-key"
  strategy: "mistral_ocr"
```

Azure Mistral OCR を使用した例:

```yaml filename="ocr with Azure Mistral OCR"
ocr:
  mistralModel: "deployed-mistral-ocr-2503" # should match deployment name on Azure
  apiKey: "${AZURE_MISTRAL_OCR_API_KEY}" # arbitrary .env var reference
  baseURL: "https://your-deployed-endpoint.models.ai.azure.com/v1" # hardcoded, can also be .env var reference
  strategy: "azure_mistral_ocr"
```

Google Vertex AI Mistral OCR を使用した例:

```yaml filename="ocr with Google Vertex AI Mistral OCR"
ocr:
  mistralModel: "mistral-ocr-2505" # model name as deployed in Vertex AI
  strategy: "vertexai_mistral_ocr"
```

Vertex AIの場合は、Google CloudプロジェクトにMistral OCRモデルをデプロイし、Vertex AIエンドポイントを呼び出せるサービスアカウントを作成して、そのキーファイルを`GOOGLE_SERVICE_KEY_FILE`で指定します。この変数には、ファイルパス、キーを取得するURL、base64エンコードされたJSON、またはJSON文字列そのものを指定できます。

```bash filename=".env"
GOOGLE_SERVICE_KEY_FILE=/path/to/service-account-key.json
```

ローカルドキュメントパーサーを使用した例（外部APIは不要です）:

```yaml filename="ocr with document parser"
ocr:
  strategy: "document_parser"
```

## allowedAddresses

<OptionTable
  options={[
    [
      'allowedAddresses',
      'Array of Strings',
      'OCR接続時のSSRFチェックに対する信頼されたプライベートなhost:portの除外設定。パブリックな宛先は引き続き利用可能です。各エントリにはポートが必要であり、URL、パス、CIDR範囲、ホスト名のみ、またはパブリックIPリテラルは指定できません。',
      'allowedAddresses: ["ocr.internal:8080"]',
    ],
  ]}
/>

OCRリクエストは、接続時にプライベート、ループバック、リンクローカル、およびクラウドメタデータの宛先をブロックし、リダイレクトを無効にします。`allowedAddresses` は、信頼された特定の `host:port`、`private.ip:port`、または `[ipv6]:port` ターゲットに対する例外リストであり、パブリックな宛先へのアクセスを制限するものではありません。

<Callout type="warning" title="信頼できる例外を慎重に設定してください">
  `allowedAddresses` は、自身で管理しているプライベートな OCR サービスに対してのみ使用してください。除外されたホスト名は、そのポートで解決されるあらゆるプライベートアドレスを信頼するため、可能な限りプライベート IP リテラルを使用することを推奨します。フォワードプロキシを使用する場合、プロキシ側で宛先の SSRF ポリシーを強制する必要があります。明示的に除外されない限り、リテラルなプライベート宛先はブロックされたままとなります。
</Callout>


```yaml filename="ocr / allowedAddresses"
ocr:
  strategy: "mistral_ocr"
  baseURL: "http://ocr.internal:8080/v1"
  apiKey: "${INTERNAL_OCR_KEY}"
  allowedAddresses:
    - "ocr.internal:8080"
```

## strategy

<OptionTable
  options={[
    ['strategy', 'String', '使用するOCR戦略。', 'Determines which OCR service to use. Options are "mistral_ocr", "azure_mistral_ocr", "vertexai_mistral_ocr", "document_parser", or "custom_ocr". Defaults to "mistral_ocr".'],
  ]}
/>

```yaml filename="ocr / strategy"
ocr:
  strategy: "document_parser"
```

**利用可能な戦略:**

- `mistral_ocr`: 標準の Mistral API を通じて Mistral の OCR を使用します。
- `azure_mistral_ocr`: Azure AI Foundry にデプロイされた Mistral OCR モデルを使用します。`mistralModel` にデプロイ名を、`baseURL` にデプロイのエンドポイントを設定してください。
- `vertexai_mistral_ocr`: Google Cloud Vertex AI にデプロイされた Mistral OCR モデルを使用します。認証には `GOOGLE_SERVICE_KEY_FILE` を使用します。
- `document_parser`: PDF、DOCX、XLS/XLSX、およびOpenDocumentファイルに対してローカルでのテキスト抽出を使用します。外部APIは不要です。また、`ocr`設定が存在しない場合のエージェントによるファイルアップロード時や、設定されたOCR戦略が失敗した際のフォールバックとしても自動的に実行されます。
- `custom_ocr`: `baseURL` にあるカスタム OCR サービス用に予約されています。まだ実装されていません。
