## Przegląd [#overview]

Aplikacje MCP to interaktywne interfejsy, które serwer MCP zwraca wraz z wynikiem narzędzia. LibreChat renderuje każdą z nich w izolowanej ramce (sandbox) serwowanej z osobnego źródła (origin), dzięki czemu zawartość aplikacji nie może mieć dostępu do strony LibreChat. Obiekt `mcpAppSandbox` konfiguruje tę izolację oraz limity stosowane wobec aplikacji.

MCP Apps są włączane za pomocą [`mcpSettings.apps`](/docs/configuration/librechat_yaml/object_structure/mcp_settings#apps). Każdy klucz w `mcpAppSandbox` jest opcjonalny i ma wartość domyślną.

## Przykład [#example]

```yaml filename="mcpAppSandbox"
mcpAppSandbox:
  url: https://mcp-sandbox.example.com/api/mcp/sandbox
  maxActiveViews: 3
  maxPersistedAppBytes: 1048576
  maxAdmissionRequestsPerMinute: 240
  operationLimits:
    maxBytes: 4194304
    timeoutMs: 30000
    maxActive: 16
```

## Hostowanie piaskownicy [#hosting-the-sandbox]

Strona piaskownicy jest udostępniana przez sam LibreChat pod adresem `/api/mcp/sandbox`. Przypisz jej dedykowany origin, na przykład drugą nazwę hosta, której reverse proxy przekierowuje ruch na ten sam serwer LibreChat, i ustaw `url` na tę ścieżkę w dedykowanym originie.

Strona piaskownicy odmawia osadzenia, dopóki origin LibreChat nie zostanie dopuszczony do wyświetlania jej w ramce. Ustaw [`MCP_SANDBOX_FRAME_ANCESTORS`](/docs/configuration/dotenv#mcp-server-configuration) na origin, pod którym użytkownicy otwierają LibreChat, na przykład `MCP_SANDBOX_FRAME_ANCESTORS=https://chat.example.com`. Gdy zmienna nie jest ustawiona, strona jest serwowana z nagłówkiem `frame-ancestors 'none'` i ramki aplikacji pozostają puste.
