## Übersicht [#overview]

Das `fileConfig`-Objekt ermöglicht es Ihnen, die Einstellungen für die Dateiverarbeitung der Anwendung zu konfigurieren, einschließlich Größenbeschränkungen und MIME-Typ-Einschränkungen. Dieser Abschnitt bietet eine detaillierte Aufschlüsselung der Struktur des `fileConfig`-Objekts.

Die wichtigsten Felder unter `fileConfig`, die hier behandelt werden:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`

**Hinweise:**

- Zum Zeitpunkt der Erstellung dieses Dokuments unterstützt der Assistants endpoint [Dateitypen aus dieser Liste](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google und benutzerdefinierte endpoints unterstützen Dateien über die [RAG API.](../../rag_api.mdx)
- OpenAI, Azure OpenAI, Anthropic, Google, AWS Bedrock und benutzerdefinierte Endpunkte unterstützen direkte Datei-Uploads über [Upload to Provider](/docs/features/ocr#upload-to-provider-instead).
- Die Abschnitte `ocr` und `text` steuern die Dateiverarbeitung für Funktionen wie [Als Text hochladen](/docs/features/upload_as_text) und [OCR](/docs/features/ocr)
- Alle anderen nicht erwähnten endpoints, wie Plugins, unterstützen (noch) keine Datei-Uploads.
- Der Assistants endpoint hat einen definierten endpoint-Wert von `assistants`. Alle anderen endpoints verwenden den definierten Wert `default`.
  - Für Endpunkte, die keine Assistants sind, können Sie die Dateieinstellungen für alle unter `default` anpassen.
  - Wenn Sie Einstellungen für ein bestimmtes endpoint anpassen möchten, können Sie die entsprechenden endpoint-Namen auflisten:
    - `assistants`
        - verwendet nicht "default", da es separate Standardwerte definiert, die sich von den anderen unterscheiden.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Sie können Werte weglassen; in diesem Fall verwendet die App die Standardwerte, wie sie für den jeweiligen endpoint-Typ unten aufgeführt sind.
- LibreChat berechnet 1 Megabyte wie folgt: `1 x 1024 x 1024`
- Die Limits für das Streaming von Datei-Upload-Antworten mit langer Laufzeit sowie für das Abrufen von Remote-URLs auf der Serverseite werden über die Umgebungsvariablen [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` und `REMOTE_FILE_FETCH_MAX_BYTES` konfiguriert](/docs/configuration/dotenv#file-uploads).

## Beispiel [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

<Callout type="info" title="MIME-Muster-Syntax">
  LibreChat evaluiert die vom Administrator konfigurierten `supportedMimeTypes`-Muster auf dem Server mit einer RE2-kompatiblen Regular-Expression-Engine mit linearer Laufzeit. Rückwärtsreferenzen (Backreferences) und Lookaround werden nicht unterstützt. Jedes Muster wird während der Konfigurationsvalidierung mit der aktiven Engine kompiliert; ein nicht unterstütztes Muster führt zur Ablehnung der Konfiguration, anstatt stillschweigend übersprungen zu werden.
</Callout>

## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Einstellungen für Skill-Importe, die als `.md`-, `.zip`- oder `.skill`-Dateien hochgeladen werden.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` unterstützt drei Parameter:

- `fileSizeLimit` (Zahl)
  - Maximale Größe eines einzelnen Skill-Uploads, angegeben in Megabyte (MB).
  - **Standard:** `50`
- `importCleanupConcurrency` (Ganzzahl)
  - Maximale Anzahl gleichzeitiger Bereinigungsvorgänge nach einem fehlgeschlagenen Skill-Archiv-Import. Verwenden Sie `1` für eine serielle Bereinigung.
  - **Standard:** `8`
- `deletionCleanupConcurrency` (Integer)
  - Maximale Anzahl gleichzeitiger Bereinigungsvorgänge, wenn ein Skill gelöscht wird. Verwenden Sie `1` für eine serielle Bereinigung.
  - **Standard:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Siehe [Skills](/docs/features/skills) für die restlichen Importregeln, wie z. B. die Limits pro Datei und Archiv-Eintrag.

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', 'Einstellungen bezüglich der Qualität und Dimensionen der Bildgenerierungsausgabe.', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` unterstützt die folgenden Parameter:

- `percentage` (Zahl)
  - Die Ausgabegröße des generierten Bildes, ausgedrückt als Prozentsatz (z. B. bedeutet `100` 100 % der Basisgröße).
  - Verwenden Sie dies, um die Ausgabegröße des Bildes relativ zu einer Standard- oder Originalgröße zu skalieren.

- `px` (Zahl)
  - Gibt die Ausgabebilddimension in Pixeln an (z. B. `1024`).
  - Verwenden Sie dies, um die Ausgabegröße des generierten Bildes unabhängig von der Basisgröße explizit festzulegen.

Setze nur einen dieser Parameter (`percentage` oder `px`), nicht beide.

Beispielkonfiguration:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Steuert die clientseitige Größenanpassung von Bildern vor dem Hochladen, wodurch Upload-Fehler durch zu große Bilder verhindert werden. Benutzer können die Größenanpassung unter Einstellungen > Chat ein- und ausschalten. Wenn `enabled` hier gesetzt wird, überschreibt dies die Auswahl für alle Benutzer und sperrt den Schalter. Lassen Sie den Wert weg, behalten die Benutzer die Kontrolle.

- `enabled` (Boolean)
  - Erzwingt die Größenänderung für alle Benutzer ein (`true`) oder aus (`false`). Wenn dieser Wert weggelassen wird, entscheidet jeder Benutzer selbst, wobei die Größenänderung standardmäßig eingeschaltet ist.
- `maxWidth` (Zahl)
  - Maximale Breite skalierter Bilder in Pixeln. Minimum `1`. **Standard:** `1900`
- `maxHeight` (Zahl)
  - Maximale Höhe skalierter Bilder in Pixeln. Minimum `1`. **Standard:** `1900`
- `quality` (Zahl)
  - JPEG-Komprimierungsqualität von `0` bis `1`. **Standard:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## fileTokenLimit

<OptionTable
  options={[
    ['fileTokenLimit', 'Number', 'Maximale Anzahl an Tokens aus Textdateien, die vor dem Kürzen in Prompts einbezogen werden sollen.', 'fileTokenLimit: 100000'],
  ]}
/>

**Beschreibung:** Beim Anhängen von Textinhalten kürzt LibreChat den Text zur Laufzeit kurz vor der Prompt-Erstellung auf das konfigurierte Token-Limit. Das Limit gilt für jede Datei einzeln. Benutzer können es für eine Konversation mit dem Modellparameter **File Token Limit** überschreiben. Wenn Sie ihn auf `0` setzen, wird der Text angehängter Dateien gar nicht erst in den Prompt aufgenommen.

**Standard:** `100000`

```yaml filename="fileConfig / fileTokenLimit"
fileConfig:
  fileTokenLimit: 100000
```

## fileContextSizeLimit

<OptionTable
  options={[
    ['fileContextSizeLimit', 'Number', 'Maximale Gesamtgröße in Megabyte von modellgebundenen Anhängen, die in einem Agent-Turn zugelassen sind.', '128'],
  ]}
/>

**Standard:** `128` MB. Dies ist eine Obergrenze für die Prompt-Sicherheit pro Turn, die unabhängig von den Speicherlimits für Uploads ist. Ressourcen für die eingebettete Dateisuche, Referenzen für Code-Arbeitsbereiche und Dateien, die nicht in den Modellkontext gelangen, sind ausgeschlossen. Ein konfiguriertes `totalSizeLimit` für einen endpoint kann ein niedrigeres aggregiertes Byte-Limit für diesen endpoint festlegen.

```yaml filename="fileConfig / fileContextSizeLimit"
fileConfig:
  fileContextSizeLimit: 128
```

## fileContextCharLimit

<OptionTable
  options={[
    ['fileContextCharLimit', 'Number', 'Maximale Anzahl an extrahierten Textzeichen, die in einem Agent-Turn zulässig sind.', '1000000'],
  ]}
/>

**Standard:** `1000000`. LibreChat wendet diese Begrenzung auf extrahierten Text an, der in den Agent-Prompt einfließt, einschließlich beibehaltener Konversationsanhänge und dem Dateikontext auf Agent-Ebene. Wiederholte Injektionen werden für jeden Agenten gezählt, der sie empfängt. Das Überschreiten eines der Kontextlimits stoppt den Vorgang mit einem attachment-limit-Fehler, bevor das Modell aufgerufen wird.

```yaml filename="fileConfig / fileContextCharLimit"
fileConfig:
  fileContextCharLimit: 1000000
```

## textFallbackWithoutTools

Wenn ein Upload an `none` weitergeleitet wird (gespeichert und nur für Tools verfügbar) und der Durchlauf kein Tool ausführt, das ihn lesen kann, kann LibreChat stattdessen den extrahierten Text der Datei bereitstellen. Setze `textFallbackWithoutTools: true`, um dies zu aktivieren. Die Option kann global unter `fileConfig` oder pro Eintrag unter `fileConfig.endpoints` (einschließlich `default`) gesetzt werden; ein Wert auf Endpoint-Ebene hat Vorrang vor dem globalen Wert.

**Standard:** `false`

Es gilt nur für Nachrichtenanhänge, deren Verarbeitungsweg abgeleitet wurde; ein vom Benutzer ausdrücklich gewähltes Ziel wird niemals neu aufgelöst, und Dateien, die in den Tool-Ressourcen eines Agenten gespeichert sind, gelangen niemals in einen Prompt. Es werden nur die integrierten Extraktoren für Dokumente und Klartext ausgeführt, sodass für eine Datei, die für ein Tool bestimmt ist, kein RAG- oder OCR-Aufruf erfolgt. Bestehende Dateien ohne extrahierten Text werden nicht nachträglich verarbeitet.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

Dateien, die innerhalb dieses Zeitfensters (in Millisekunden) in der Code-Ausführungsumgebung bereitgestellt wurden, überspringen vor der Wiederverwendung die Live-Verfügbarkeitsprüfung. Minimum `0`.

**Standard:** `21600000` (6 Stunden)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

Wie lange (in Millisekunden) das Priming auf eine Verfügbarkeitsprüfung der veralteten File Search wartet, bevor die Datei trotzdem eingebettet wird. Mindestwert `1`.

**Standard:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## text

<OptionTable
  options={[
    ['text', 'Object', 'Einstellungen für die direkte Textdateianalyse ohne OCR.', 'Configures which file types are processed as plain text files for direct content extraction.'],
  ]}
/>

**Beschreibung:** Der `text`-Abschnitt konfiguriert, welche Dateitypen mittels direkter Textextraktion verarbeitet werden sollen.

**Hinweis:** Die Textanalyse ist die Standardmethode der Funktion „Als Text hochladen“ (gesteuert durch die `context`-Fähigkeit). Weitere Informationen finden Sie unter [Als Text hochladen](/docs/features/upload_as_text).

- Die Standardliste stimmt mit jedem wohlgeformten MIME-Typ überein. Dateien, die bereits Text sind (`text/*`, JSON, YAML, XML, SQL, Shell-Skripte, `.eml`-E-Mails und ähnliche), werden direkt gelesen. Andere Binärtypen ohne Parser werden abgelehnt, anstatt sie in unbrauchbare Zeichen zu dekodieren.
- Wenn Sie die Liste eingrenzen und die RAG-API konfiguriert ist (`RAG_API_URL`), werden passende Dateien an die Textextraktion der RAG-API gesendet. Ist die RAG-API nicht verfügbar, greift LibreChat auf den integrierten Dokumentenparser zurück.

### supportedMimeTypes [#supportedmimetypes-1]

<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Liste der MIME-Typ-Muster für Dateien, die als Klartext geparst werden sollen.', 'Uses regular expressions to match file types.'],
  ]}
/>

**Standard:** `^[\w.-]+/[\w.-]+$` (jeder MIME-Typ)

```yaml filename="fileConfig / text / supportedMimeTypes"
fileConfig:
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
```

## stt

`fileConfig.stt` wird in aktuellen Versionen von LibreChat nicht gelesen; ein `stt`-Block an dieser Stelle wird ignoriert. Audiodateien, die als Text hinzugefügt werden, werden transkribiert, sofern ein Speech-to-Text-Anbieter unter [`speech.stt`](/docs/configuration/librechat_yaml/object_structure/speech) konfiguriert ist. Dabei wird eine integrierte Liste von Audiotypen verwendet: MP3-, MPEG-, WAV-, OGG-, Vorbis-, MP4- und M4A-Audio, FLAC, WebM, AAC, WMA und Opus.

## Priorität der Dateiverarbeitung [#file-processing-priority]

Wenn eine Datei als Text hinzugefügt wird (Als Text hochladen, ein langer Einfügevorgang oder Dateikontext eines Agenten), verwendet LibreChat den ersten zutreffenden Schritt:

1. **OCR**: Ein `ocr`-Abschnitt existiert in `librechat.yaml`, und die Datei entspricht `fileConfig.ocr.supportedMimeTypes`. Schlägt der OCR-Dienst fehl, wird anschließend der integrierte Dokumentenparser versucht.
2. **RAG-API-Textextraktion**: `text.supportedMimeTypes` wurde gegenüber dem Standard eingeschränkt, die RAG-API ist konfiguriert und die Datei entspricht der Liste.
3. **Integrierter Dokumentenparser**: PDF-, DOCX-, XLS- und XLSX-, ODT- und ODS-Dateien. Es werden nur Textebenen gelesen.
4. **Sprache-zu-Text**: Audiodateien, wenn ein STT-Anbieter konfiguriert ist.
5. **Textanalyse**: Dateien, die mit `text.supportedMimeTypes` übereinstimmen.

Ein Bild oder ein gescanntes PDF ohne konfiguriertes OCR enthält keinen extrahierbaren Text, und der Upload schlägt mit einer Meldung fehl, dass ein OCR-Dienst erforderlich ist.

## legacyFileUploadUX

<OptionTable
  options={[
    ['legacyFileUploadUX', 'Boolean', 'Zeigt das ältere Anhangmenü, in dem Benutzer für jeden Upload ein Ziel auswählen (Zu Anbieter hochladen oder Bild hochladen, Als Text hochladen, Für Dateisuche hochladen, Zur Code-Umgebung hochladen).', 'Default: false. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints.'],
  ]}
/>

**Beschreibung:** Standardmäßig bietet das Anhang-Menü **Vom lokalen Computer** an, und LibreChat entscheidet für jede Datei anhand von `defaultLLMDeliveryPath`, wie das Modell sie erhält. Ressourcen für Dateisuche und Code werden nur bereitgestellt, wenn ein ausgewähltes Tool die Datei benötigt. Mit `legacyFileUploadUX: true` wählen Benutzer das Ziel selbst aus, Uploads werden sofort an dieses Ziel übertragen, und die explizite Option **Als Text hochladen** erscheint. Ein Wert pro Endpunkt überschreibt den übergeordneten Wert.

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
  endpoints:
    anthropic:
      legacyFileUploadUX: false
```

## defaultLLMDeliveryPath

<OptionTable
  options={[
    ['defaultLLMDeliveryPath', 'Object', 'Wie eine angehängte Datei das Modell erreicht, wenn der Benutzer kein Ziel ausgewählt hat.', 'Has two optional keys: fallback and overrides. Can be set at the top level of fileConfig or per endpoint under fileConfig.endpoints. Ignored when legacyFileUploadUX is true.'],
  ]}
/>

I can't see the text you'd like translated. Your message contains only the instruction "Translate the following into Deutsch:" followed by "Each value is one of:" with nothing after it.

Please paste the Markdown/MDX content you want translated, and I'll translate it following the rules.

- `provider`: Die Datei wird dem Modell als native Anhang gesendet (Bild-, PDF-, Audio- oder Video-Eingabe).
- `text`: the file's text is extracted and added to the prompt, as with Upload as Text.
- `none`: Die Datei wird gespeichert und steht Tools wie der Codeausführung oder der Dateisuche zur Verfügung, wird aber nicht an das Modell gesendet.

`overrides` ordnet einen MIME-Typ oder einen `type/*`-Platzhalter einem Wert zu. `fallback` gilt für alles, was nicht aufgeführt ist. LibreChat prüft zuerst die Endpunkt-Overrides, dann den Endpunkt-Fallback, danach die globalen Overrides, anschließend den globalen Fallback und zuletzt den integrierten Standardwert.

Der integrierte Standardwert sendet Bilder, Audio, Video und PDFs an den Anbieter und alles andere als Text. Er passt zudem die Einstellung an den Endpoint an: Ein PDF bei einem Anbieter, der keine PDFs lesen kann, wird als Text gesendet, Audio oder Video bei einem Anbieter ohne Medienunterstützung wird transkribiert oder nicht in den Prompt aufgenommen, AWS Bedrock erhält seine unterstützten Dokumenttypen nativ, und Typen, aus denen sich kein Text extrahieren lässt (zum Beispiel Archive), werden auf `none` gesetzt. Von Ihnen konfigurierte Werte werden unverändert verwendet, ohne diese Anpassungen.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## endpoints

<OptionTable
  options={[
    ['endpoints', 'Record/Object', 'Konfiguriert die Dateiverarbeitungseinstellungen für einzelne endpoints und ermöglicht eine Anpassung auf Basis des jeweiligen endpoints.', 'Specifies file handling configurations for individual endpoints, allowing customization per endpoint basis.'],
  ]}
/>

**Beschreibung:** Jedes Objekt unter endpoints ist ein Datensatz, der die folgenden Einstellungen enthalten kann:

### Übersicht [#overview-1]

  - `disabled`
      - Ob die Dateiverarbeitung für den endpoint deaktiviert ist.
  - `fileLimit`
      - Die maximale Anzahl an Dateien, die pro Upload-Anfrage erlaubt sind.
  - `fileSizeLimit`
      - Die maximale Größe für eine einzelne Datei. In Einheiten von MB (z. B. `20` für 20 Megabyte verwenden)
  - `totalSizeLimit`
      - Die maximale Gesamtgröße für alle Dateien in einer einzelnen Anfrage. In Einheiten von MB (verwenden Sie z. B. `20` für 20 Megabyte)
  - `defaultLLMDeliveryPath`, `legacyFileUploadUX` und `textFallbackWithoutTools`
      - Überschreibungen pro Endpunkt der globalen Einstellungen mit demselben Namen, wie oben beschrieben.
  - `supportedMimeTypes`
      - Eine Liste von [Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression), die festlegt, welche MIME-Typen für den Upload zulässig sind. Dies kann angepasst werden, um Dateitypen einzuschränken.

LibreChat normalisiert gängige MIME-Aliase, bevor diese Muster angewendet werden. Insbesondere werden `application/x-shellscript` (von Chrome unter Linux gemeldet) und `text/x-shellscript` (von libmagic gemeldet) zu `application/x-sh`. Eine benutzerdefinierte Positivliste (Allowlist), die Shell-Skripte akzeptiert, sollte daher den kanonischen Typ `application/x-sh` zulassen. Abgelehnte Uploads geben den gemeldeten nicht unterstützten Typ an den Client zurück, anstatt einen allgemeinen Serverfehler auszugeben.

## Beibehaltene Datei- und Vektorbereinigung [#retained-file-and-vector-cleanup]

Die Löschung einer Datei erhält das lesbare Primärobjekt, bis die Bereinigung des Sekundärspeichers bestätigt wurde. `fileConfig.retainedFileCleanup` ist standardmäßig auf `false` gesetzt: Eingebettete Dateien und beibehaltene Ziele des Code Interpreters werden nicht destruktiv bereinigt, bis diese Option explizit aktiviert wird. Aktivieren Sie sie erst, nachdem alle Replikate und Rollback-Ziele die beibehaltenen Dateiziele lesen können.

| Feld | Standard | Bedeutung |
| ------------------------------ | ------- | -------------------------------------------------------------------------------------------------- |
| `retainedFileCleanup` | `false` | Aktiviert die Bereinigung anhand der gespeicherten Zielmetadaten nach dem Rollout für Leser. |
| `vectorOwnershipTrackingStart` | Nicht gesetzt | UTC-Datum-Uhrzeit-Grenzwert, der gewählt wird, nachdem alle älteren Vektor-Schreiber und Rollback-Ziele außer Betrieb genommen wurden. |
| `vectorDeletionConcurrency` | `4` | Ganzzahl von `1` bis `16`; maximale Anzahl gleichzeitig laufender Namespace-Löschungen pro Datei. |

Die Vektorlöschung erfordert zusätzlich einen vollständigen, aufgezeichneten Eigentumsnachweis sowie einen Einfügezeitnachweis zum oder nach dem sicheren Schreiber-Stichtag. Fehlende, ungültige, zukünftige oder vor dem Stichtag liegende Nachweise führen zu einem Fail-Closed-Verhalten, wodurch die Datei und ihre Vektoren erhalten bleiben. Das Setzen des Stichtags repariert keine älteren Eigentumsmetadaten, und er darf nicht rückdatiert werden, um mehrdeutige Altdateien zur Löschung zuzulassen.

Bereinigungsziele umfassen jeden erfassten Entitäts-Namespace sowie den nicht zugeordneten Namespace. Ein Namespace gilt erst dann als bereinigt, wenn eine erfolgreiche DELETE-Antwort vorliegt. Eine `404`-Antwort wird nur dann als Abwesenheit akzeptiert, wenn eine erfolgreiche Bestandsprüfung innerhalb desselben Namespace die Datei ausschließt. Kann für einen Sekundär- oder Namespace nicht bestätigt werden, dass er nicht mehr vorhanden ist, bleibt der Primärwert für einen erneuten Versuch verfügbar. Diese Einstellungen übernehmen keine Altdatensätze nachträglich; für unklare historische Dateien ist eine separat verifizierte Abstimmung zu planen.
