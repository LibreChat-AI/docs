## Übersicht [#overview]

Das `fileConfig`-Objekt ermöglicht es Ihnen, die Einstellungen für die Dateiverarbeitung der Anwendung zu konfigurieren, einschließlich Größenbeschränkungen und MIME-Typ-Einschränkungen. Dieser Abschnitt bietet eine detaillierte Aufschlüsselung der Struktur des `fileConfig`-Objekts.

Die wichtigsten Felder unter `fileConfig` sind:

  - `endpoints`
  - `skills`
  - `serverFileSizeLimit`
  - `avatarSizeLimit`
  - `imageGeneration`
  - `clientImageResize`
  - `fileTokenLimit`
  - `fileContextSizeLimit`
  - `fileContextCharLimit`
  - `defaultLLMDeliveryPath`
  - `legacyFileUploadUX`
  - `textFallbackWithoutTools`
  - `codeEnvLivenessSafeWindowMs`
  - `legacySearchProbeTimeoutMs`
  - `ocr`
  - `text`
  - `stt`

**Hinweise:**

- Zum Zeitpunkt der Erstellung dieses Dokuments unterstützt der Assistants endpoint [Dateitypen aus dieser Liste](https://platform.openai.com/docs/assistants/tools/file-search#supported-files).
- OpenAI, Azure OpenAI, Google und benutzerdefinierte endpoints unterstützen Dateien über die [RAG API.](../../rag_api.mdx)
- OpenAI, Azure OpenAI, Anthropic, Google und AWS Bedrock endpoints unterstützen direkte Datei-Uploads über [Upload to Provider](/docs/features/ocr#5-upload-files-to-provider-direct).
- Die Abschnitte `ocr`, `text` und `stt` steuern die Dateiverarbeitung für Funktionen wie [Upload as Text](/docs/features/upload_as_text) und [OCR](/docs/features/ocr)
- Alle anderen nicht erwähnten endpoints, wie Plugins, unterstützen (noch) keine Datei-Uploads.
- Der Assistants endpoint hat einen definierten endpoint-Wert von `assistants`. Alle anderen endpoints verwenden den definierten Wert `default`.
  - Für Endpunkte, die keine Assistants sind, können Sie die Dateieinstellungen für alle unter `default` anpassen.
  - Wenn Sie Einstellungen für ein bestimmtes endpoint anpassen möchten, können Sie die entsprechenden endpoint-Namen auflisten:
    - `assistants`
        - verwendet nicht "default", da es separate Standardwerte definiert, die sich von den anderen unterscheiden.
    - `openAI`
    - `azureOpenAI`
    - `google`
    - `bedrock`
    - `YourCustomEndpointName`
- Sie können Werte weglassen; in diesem Fall verwendet die App die Standardwerte, wie sie für den jeweiligen endpoint-Typ unten aufgeführt sind.
- LibreChat berechnet 1 Megabyte wie folgt: `1 x 1024 x 1024`
- Die Limits für das Streaming von Datei-Upload-Antworten mit langer Laufzeit sowie für das Abrufen von Remote-URLs auf der Serverseite werden über die Umgebungsvariablen [`FILE_UPLOAD_SSE_ENABLED`, `REMOTE_FILE_FETCH_TIMEOUT_MS` und `REMOTE_FILE_FETCH_MAX_BYTES` konfiguriert](/docs/configuration/dotenv#file-uploads).

## Beispiel [#example]

```yaml filename="fileConfig"
fileConfig:
  endpoints:
    assistants:
      fileLimit: 5
      fileSizeLimit: 10
      totalSizeLimit: 50
      supportedMimeTypes:
        - "image/.*"
        - "application/pdf"
    openAI:
      disabled: true
    default:
      totalSizeLimit: 20
      defaultLLMDeliveryPath:
        fallback: text
        overrides:
          "image/*": provider
    YourCustomEndpointName:
      fileLimit: 5
      fileSizeLimit: 1000
      supportedMimeTypes:
        - "image/.*"
  serverFileSizeLimit: 1000
  avatarSizeLimit: 2
  fileTokenLimit: 100000
  skills:
    fileSizeLimit: 50
  fileContextSizeLimit: 128
  fileContextCharLimit: 1000000
  legacyFileUploadUX: false
  imageGeneration:
    percentage: 100
  clientImageResize:
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
  ocr:
    supportedMimeTypes:
      - "^image/(jpeg|gif|png|webp|heic|heif)$"
      - "^application/pdf$"
      - "^application/vnd\\.openxmlformats-officedocument\\.(wordprocessingml\\.document|presentationml\\.(presentation|template)|spreadsheetml\\.sheet)$"
      - "^application/vnd\\.ms-(word|powerpoint|excel)$"
      - "^application/epub\\+zip$"
  text:
    supportedMimeTypes:
      - "^text/(plain|markdown|csv|json|xml|html|css|javascript|typescript|x-python|x-java|x-csharp|x-php|x-ruby|x-go|x-rust|x-kotlin|x-swift|x-scala|x-perl|x-lua|x-shell|x-sql|x-yaml|x-toml)$"
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

<Callout type="info" title="MIME-Muster-Syntax">
  LibreChat evaluiert die vom Administrator konfigurierten `supportedMimeTypes`-Muster auf dem Server mit einer RE2-kompatiblen Regular-Expression-Engine mit linearer Laufzeit. Rückwärtsreferenzen (Backreferences) und Lookaround werden nicht unterstützt. Jedes Muster wird während der Konfigurationsvalidierung mit der aktiven Engine kompiliert; ein nicht unterstütztes Muster führt zur Ablehnung der Konfiguration, anstatt stillschweigend übersprungen zu werden.
</Callout>
## skills

<OptionTable
  options={[
    ['skills', 'Object', 'Einstellungen für Skill-Importe, die als `.md`-, `.zip`- oder `.skill`-Dateien hochgeladen werden.', 'Only applies to the Skills import endpoint, not to chat file uploads.'],
  ]}
/>

`skills` unterstützt drei Parameter:

- `fileSizeLimit` (Zahl)
  - Maximale Größe eines einzelnen Skill-Uploads, angegeben in Megabyte (MB).
  - **Standard:** `50`
- `importCleanupConcurrency` (Ganzzahl)
  - Maximale Anzahl gleichzeitiger Bereinigungsvorgänge nach einem fehlgeschlagenen Skill-Archiv-Import. Verwenden Sie `1` für eine serielle Bereinigung.
  - **Standard:** `8`
- `deletionCleanupConcurrency` (Integer)
  - Maximale Anzahl gleichzeitiger Bereinigungsvorgänge, wenn ein Skill gelöscht wird. Verwenden Sie `1` für eine serielle Bereinigung.
  - **Standard:** `8`

```yaml filename="fileConfig / skills"
fileConfig:
  skills:
    fileSizeLimit: 50
    importCleanupConcurrency: 8
    deletionCleanupConcurrency: 8
```

Siehe [Skills](/docs/features/skills) für die restlichen Importregeln, wie z. B. die Limits pro Datei und Archiv-Eintrag.

## imageGeneration

<OptionTable
  options={[
    ['imageGeneration', 'Object', 'Einstellungen bezüglich der Qualität und Dimensionen der Bildgenerierungsausgabe.', 'Allows configuration of either output size as a percentage relative to some base size or as an explicit pixel dimension.'],
  ]}
/>

`imageGeneration` unterstützt die folgenden Parameter:

- `percentage` (Zahl)
  - Die Ausgabegröße des generierten Bildes, ausgedrückt als Prozentsatz (z. B. bedeutet `100` 100 % der Basisgröße).
  - Verwenden Sie dies, um die Ausgabegröße des Bildes relativ zu einer Standard- oder Originalgröße zu skalieren.

- `px` (Zahl)
  - Gibt die Ausgabebilddimension in Pixeln an (z. B. `1024`).
  - Verwenden Sie dies, um die Ausgabegröße des generierten Bildes unabhängig von der Basisgröße explizit festzulegen.

Setze nur einen dieser Parameter (`percentage` oder `px`), nicht beide.

Beispielkonfiguration:

```yaml filename="fileConfig / imageGeneration"
fileConfig:
  imageGeneration:
    percentage: 100
```

## clientImageResize

Steuert die clientseitige Größenanpassung von Bildern vor dem Hochladen, wodurch Upload-Fehler durch zu große Bilder verhindert werden. Benutzer können die Größenanpassung unter Einstellungen > Chat ein- und ausschalten. Wenn `enabled` hier gesetzt wird, überschreibt dies die Auswahl für alle Benutzer und sperrt den Schalter. Lassen Sie den Wert weg, behalten die Benutzer die Kontrolle.

- `enabled` (Boolean)
  - Erzwingt die Größenänderung für alle Benutzer ein (`true`) oder aus (`false`). Wenn dieser Wert weggelassen wird, entscheidet jeder Benutzer selbst, wobei die Größenänderung standardmäßig eingeschaltet ist.
- `maxWidth` (Zahl)
  - Maximale Breite skalierter Bilder in Pixeln. Minimum `1`. **Standard:** `1900`
- `maxHeight` (Zahl)
  - Maximale Höhe skalierter Bilder in Pixeln. Minimum `1`. **Standard:** `1900`
- `quality` (Zahl)
  - JPEG-Komprimierungsqualität von `0` bis `1`. **Standard:** `0.92`

```yaml filename="fileConfig / clientImageResize"
fileConfig:
  clientImageResize:
    enabled: true
    maxWidth: 1900
    maxHeight: 1900
    quality: 0.92
```

## fileContextCharLimit

<OptionTable
  options={[
    ['fileContextCharLimit', 'Number', 'Maximale Anzahl an extrahierten Textzeichen, die in einem Agent-Turn zulässig sind.', '1000000'],
  ]}
/>

**Standard:** `1000000`. LibreChat wendet diese Begrenzung auf extrahierten Text an, der in den Agent-Prompt einfließt, einschließlich beibehaltener Konversationsanhänge und dem Dateikontext auf Agent-Ebene. fileConfig:


## defaultLLMDeliveryPath

Steuert, wie ein Upload ohne explizit ausgewähltes Ziel in den Modellkontext gelangt. Konfigurieren Sie dies global unter `fileConfig` oder überschreiben Sie es für einen benannten Eintrag unter `fileConfig.endpoints`.

- `provider` sendet die ursprüngliche Datei über den nativen Datei- oder Medienpfad des Modellanbieters.
- `text` extrahiert oder transkribiert unterstützte Inhalte und fügt den resultierenden Text dem Kontext hinzu.
- `none` speichert die Datei, ohne sie direkt in den Modellkontext einzufügen; ausgewählte Tools können sie bei Bedarf dennoch bereitstellen.

`fallback` verarbeitet nicht übereinstimmende MIME-Typen. `overrides` akzeptiert exakte MIME-Typen wie `application/pdf` oder Platzhalter wie `image/*`. Die Auflösung bevorzugt endpoint-spezifische Überschreibungen und Fallbacks, gefolgt von globalen Werten. Ohne explizite Konfiguration bevorzugen Bilder, Audio, Video und PDFs die native Bereitstellung durch den Anbieter; andere wiederherstellbare Inhalte verwenden Text. LibreChat stuft nicht unterstützte native Pfade auf Text herab, wenn eine Extraktion möglich ist, andernfalls auf `none`.

```yaml filename="fileConfig / defaultLLMDeliveryPath"
fileConfig:
  defaultLLMDeliveryPath:
    fallback: text
    overrides:
      'image/*': provider
      'video/*': none
  endpoints:
    openAI:
      defaultLLMDeliveryPath:
        overrides:
          application/pdf: provider
```

## legacyFileUploadUX

Der standardmäßige vereinheitlichte Uploader wählt die Modellbereitstellung automatisch aus und stellt File Search- oder Code-Ressourcen nur dann bereit, wenn ausgewählte Tools diese benötigen. Setzen Sie `legacyFileUploadUX: true` global oder für einen endpoint, um die Zielauswahl und das proaktive, benutzerdefinierte Upload-Verhalten wiederherzustellen.

```yaml filename="fileConfig / legacyFileUploadUX"
fileConfig:
  legacyFileUploadUX: true
```

## textFallbackWithoutTools

Wenn ein Upload an `none` weitergeleitet wird (gespeichert und nur für Tools verfügbar) und der Durchlauf kein Tool ausführt, das ihn lesen kann, kann LibreChat stattdessen den extrahierten Text der Datei bereitstellen. Setze `textFallbackWithoutTools: true`, um dies zu aktivieren. Die Option kann global unter `fileConfig` oder pro Eintrag unter `fileConfig.endpoints` (einschließlich `default`) gesetzt werden; ein Wert auf Endpoint-Ebene hat Vorrang vor dem globalen Wert.

**Standard:** `false`

Es gilt nur für Nachrichtenanhänge, deren Verarbeitungsweg abgeleitet wurde; ein vom Benutzer ausdrücklich gewähltes Ziel wird niemals neu aufgelöst, und Dateien, die in den Tool-Ressourcen eines Agenten gespeichert sind, gelangen niemals in einen Prompt. Es werden nur die integrierten Extraktoren für Dokumente und Klartext ausgeführt, sodass für eine Datei, die für ein Tool bestimmt ist, kein RAG- oder OCR-Aufruf erfolgt. Bestehende Dateien ohne extrahierten Text werden nicht nachträglich verarbeitet.

```yaml filename="fileConfig / textFallbackWithoutTools"
fileConfig:
  textFallbackWithoutTools: true
  endpoints:
    openAI:
      textFallbackWithoutTools: false
```

## codeEnvLivenessSafeWindowMs

Dateien, die innerhalb dieses Zeitfensters (in Millisekunden) in der Code-Ausführungsumgebung bereitgestellt wurden, überspringen vor der Wiederverwendung die Live-Verfügbarkeitsprüfung. Minimum `0`.

**Standard:** `21600000` (6 Stunden)

```yaml filename="fileConfig / codeEnvLivenessSafeWindowMs"
fileConfig:
  codeEnvLivenessSafeWindowMs: 21600000
```

## legacySearchProbeTimeoutMs

Wie lange (in Millisekunden) das Priming auf eine Verfügbarkeitsprüfung der veralteten File Search wartet, bevor die Datei trotzdem eingebettet wird. Mindestwert `1`.

**Standard:** `5000`

```yaml filename="fileConfig / legacySearchProbeTimeoutMs"
fileConfig:
  legacySearchProbeTimeoutMs: 5000
```

## stt

<OptionTable
  options={[
    ['stt', 'Object', 'Einstellungen für die Verarbeitung von Speech-to-Text (STT)-Audiodateien.', 'Configures which audio file types are processed using STT for transcription.'],
  ]}
/>

**Beschreibung:** Der `stt` Abschnitt konfiguriert, welche Audiodateitypen mithilfe der Speech-to-Text-Funktionalität für die Umwandlung von Audio in Text verarbeitet werden sollen.

### supportedMimeTypes [#supportedmimetypes-2]

<OptionTable
  options={[
    ['supportedMimeTypes', 'Array of Strings', 'Liste der MIME-Typ-Muster für Audiodateien, die mit STT transkribiert werden sollen.', 'Uses regular expressions to match audio file types.'],
  ]}
/>

**Standard:** Gängige Audioformate

```yaml filename="fileConfig / stt / supportedMimeTypes"
fileConfig:
  stt:
    supportedMimeTypes:
      - "^audio/(mp3|mpeg|mpeg3|wav|wave|x-wav|ogg|vorbis|mp4|x-m4a|flac|x-flac|webm)$"
```

**Hinweise:**
- Dateien, die `text`-Mustern entsprechen, werden mit einfacher Textextraktion verarbeitet
- Dateien, die den `ocr`-Mustern entsprechen, werden mit dem bereitgestellten OCR-Dienst verarbeitet
- Dateien, die den `stt`-Mustern entsprechen, werden mit Speech-to-Text-Transkription verarbeitet
- **Verarbeitungspriorität: OCR > STT > Text-Parsing > Fallback**
- Dateien, die keinem Muster entsprechen, werden auf die Textanalyse zurückgreifen.

## Priorität der Dateiverarbeitung [#file-processing-priority]

LibreChat verarbeitet hochgeladene Dateien basierend auf dem MIME-Typ-Abgleich in der folgenden **Prioritätsreihenfolge**:

1. **OCR** – Wenn die Datei `ocr.supportedMimeTypes` entspricht UND OCR konfiguriert ist
2. **STT** - Wenn die Datei `stt.supportedMimeTypes` entspricht UND STT konfiguriert ist
3. **Text-Parsing** – Wenn die Datei `text.supportedMimeTypes` entspricht
4. **Fallback** – Text-Parsing als letzter Ausweg

Diese Verarbeitungsreihenfolge stellt eine optimale Extraktionsqualität sicher und erhält gleichzeitig die Funktionalität aufrecht, selbst wenn spezialisierte Dienste (OCR/STT) nicht konfiguriert sind.

### Verarbeitungsbeispiele [#processing-examples]

**PDF-Datei mit konfigurierter OCR:**
- Datei entspricht `ocr.supportedMimeTypes`
- **Verwendet OCR**, um Text zu extrahieren
- Bessere Qualität für gescannte PDFs und Bilder

**PDF-Datei ohne konfigurierte OCR:**
- Die Datei entspricht `text.supportedMimeTypes` (oder verwendet einen Fallback)
- **Verwendet die** Text-Parsing-Bibliothek
- Funktioniert gut für digitale PDFs mit auswählbarem Text

**Python-Datei:**
- Datei entspricht `text.supportedMimeTypes`
- **Verwendet Text-Parsing** (kein OCR erforderlich)
- Direkte Textextraktion

**Audiodatei mit konfiguriertem STT:**
- Datei entspricht `stt.supportedMimeTypes`
- **Verwendet STT**, um Audio in Text zu transkribieren

**Bilddatei ohne konfiguriertes OCR:**
- Datei entspricht `ocr.supportedMimeTypes`, aber OCR ist nicht verfügbar
- **Fällt auf Text-Parsing zurück**
- Eingeschränkte Extraktionsfähigkeit ohne OCR

Dieses Prioritätssystem ermöglicht es Funktionen wie „Upload as Text“, ohne OCR-Konfiguration zu funktionieren, während gleichzeitig OCR genutzt wird, sofern verfügbar, um die Extraktionsqualität zu verbessern.

## endpoints

<OptionTable
  options={[
    ['endpoints', 'Record/Object', 'Konfiguriert die Dateiverarbeitungseinstellungen für einzelne endpoints und ermöglicht eine Anpassung auf Basis des jeweiligen endpoints.', 'Specifies file handling configurations for individual endpoints, allowing customization per endpoint basis.'],
  ]}

**Beschreibung:** Jedes Objekt unter endpoints ist ein Datensatz, der die folgenden Einstellungen enthalten kann:

### Übersicht [#overview-1]

  - `disabled`
      - Ob die Dateiverarbeitung für den endpoint deaktiviert ist.
  - `fileLimit`
      - Die maximale Anzahl an Dateien, die pro Upload-Anfrage erlaubt sind.
  - `fileSizeLimit`
      - Die maximale Größe für eine einzelne Datei. In Einheiten von MB (z. B. `20` für 20 Megabyte verwenden)
  - `totalSizeLimit`
      - Die maximale Gesamtgröße für alle Dateien in einer einzelnen Anfrage. In Einheiten von MB (verwenden Sie z. B. `20` für 20 Megabyte)
  - `defaultLLMDeliveryPath`, `legacyFileUploadUX` und `textFallbackWithoutTools`
      - Überschreibungen pro Endpunkt der globalen Einstellungen mit demselben Namen, wie oben beschrieben.
  - `supportedMimeTypes`
      - Eine Liste von [Regular Expressions](https://en.wikipedia.org/wiki/Regular_expression), die festlegt, welche MIME-Typen für den Upload zulässig sind. Dies kann angepasst werden, um Dateitypen einzuschränken.

```yaml filename="fileConfig / endpoints / {endpoint_record} / supportedMimeTypes"
      - "image/.*"

```

LibreChat normalisiert gängige MIME-Aliase, bevor diese Muster angewendet werden. Insbesondere werden `application/x-shellscript` (von Chrome unter Linux gemeldet) und `text/x-shellscript` (von libmagic gemeldet) zu `application/x-sh`. Eine benutzerdefinierte Positivliste (Allowlist), die Shell-Skripte akzeptiert, sollte daher den kanonischen Typ `application/x-sh` zulassen. Abgelehnte Uploads geben den gemeldeten nicht unterstützten Typ an den Client zurück, anstatt einen allgemeinen Serverfehler auszugeben.
