## 概述 [#overview]

`speech` 对象允许您直接在 `librechat.yaml` 配置文件中配置文本转语音 (TTS) 和语音转文本 (STT) 提供商。这使得无需用户配置自己的 API 密钥即可启用服务器端语音服务。

**`speech` 下的字段：**

- `tts` - Text-to-Speech 提供商配置
- `stt` - Speech-to-Text 提供商配置
- `speechTab` - 语音功能的默认 UI 设置

**注意：**

- 可以同时配置多个提供商
- 用户可以从可用选项中选择他们偏好的提供商
- 配置文件中的 API keys 应使用环境变量引用以确保安全

## 示例 [#example]

```yaml filename="speech"
speech:
  tts:
    allowedAddresses: ["tts.internal:8080"]
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["voice-id-1", "voice-id-2"]
  stt:
    allowedAddresses: ["stt.internal:8080"]
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText: true
    textToSpeech: true
```

## SSRF 防护 [#ssrf-protection]

LibreChat 会在连接时保护运营商提供的 STT 和 TTS URL。私有地址、回环地址、链路本地地址以及云元数据目标地址默认会被拦截，且语音请求的重定向功能已被禁用。

`speech.tts.allowedAddresses` 和 `speech.stt.allowedAddresses` 是独立的豁免列表，而非严格的白名单。仅当该部分必须访问受信任的自托管服务时，才添加精确的私有 `host:port`、`private.ip:port` 或 `[ipv6]:port`。请勿使用 URL、路径、CIDR 范围、裸主机名/IP 或公网 IP 字面量。默认端口会被标准化，因此未指定端口的 HTTPS URL 将被检查为 `443` 端口。

被豁免的主机名会信任其在该端口上解析到的任何私有地址。请尽可能优先使用私有 IP 字面量，并仅列出您拥有 DNS 控制权且无法被攻击者重定向的主机名。

当正向代理携带主机名请求时，代理会执行目标 DNS 解析和出口流量转发，因此代理必须强制执行其自身的 SSRF 策略。在代理处理之前，字面意义上的私有目标地址仍会被拦截，除非其确切的地址和端口已被豁免。

version: 1.3.17

  tts:

      engineTTS: "external"

## 注意事项 [#notes]

- 在配置文件中，请始终使用环境变量引用（例如 `${API_KEY}`）来设置 API 密钥。
- 可以配置多个 TTS 提供商；用户可以在 UI 中选择其首选选项。
- `speechTab` 设置定义了用户可以在其个人设置中覆盖的默认值
- `browser` 使用浏览器内置的语音支持；`external` 使用在 `speech.stt` 或 `speech.tts` 下配置的服务器端提供商。
- 现有的 `openai` 和 `azureOpenAI` STT 默认配置，以及 `openai`、`azureOpenAI`、`elevenlabs` 和 `localai` TTS 默认配置，已迁移至 `external`；若外部引擎不可用，则会回退至 `browser`。
- 有关详细的功能文档，请参阅 [Speech to Text & Text to Speech](/docs/configuration/stt_tts)
