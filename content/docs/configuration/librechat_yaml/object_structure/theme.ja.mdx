## 概要 [#overview]

`interface.theme` はデプロイメントのテーマを設定します。これは、ライトモードとダークモードの両方で、すべてのユーザーに表示される色、形状、タイポグラフィ、影、および動きを定義します。LibreChatに同梱されているテーマの名前、またはインラインのテーマ定義のいずれかを受け取ります。

<Callout type="important" title="保留中：未リリース">
  `interface.theme` およびこのページの表示スケールは LibreChat の `dev` ブランチにマージされましたが、まだタグ付けされたリリースには含まれていません。v0.8.8 以前のバージョンではこれらは読み込まれません。
</Callout>

```yaml filename="interface / theme"
interface:
  theme: clickhouse
```

`interface.theme` が設定されていない場合、LibreChat は以前と同様に動作します。つまり、ユーザーにはデフォルトの LibreChat テーマ、またはビルド時に設定された色や保存済みのテーマが適用されます。

このページでは、オペレーターが `librechat.yaml` で設定する内容について説明します。完全なトークンリストや各トークンがどのようにTailwindユーティリティにマッピングされるかを含むテーマエンジン自体については、LibreChatリポジトリ内の [theme README](https://github.com/LibreChat-AI/LibreChat/blob/dev/packages/client/src/theme/README.md) に記載されています。

## テーマの選択方法 [#how-the-theme-is-chosen]

クライアントは以下の優先順位に従って、1つのテーマを選択します（最優先順位が最初）：

1. **ハイコントラストモード。** `high-contrast-light` または `high-contrast-dark` を選択したユーザー、あるいはシステム設定がハイコントラストに設定されているユーザーには、常に組み込みのアクセシブルなパレットが適用されます。
2. `librechat.yaml` の **`interface.theme`**。
3. **`REACT_APP_THEME_*`** ビルド時のカラー設定。詳細は [Theme Colors](/docs/configuration/dotenv#theme-colors) を参照してください。
4. ブラウザに**保存されたユーザーのテーマ**。

デプロイメントのテーマは色、形状、フォント、影、動きを設定しますが、モードは設定しません。各ユーザーは引き続き、ライトモード、ダークモード、またはシステム設定のいずれかを自身で選択します。

デプロイメントのテーマは、ユーザーのブラウザストレージには一切書き込まれません。`interface.theme` を削除すると、ユーザーは自身の保存済みテーマ（またはビルド時に設定された `REACT_APP_THEME_*` カラー）に戻ります。

テーマはログイン前の設定の一部であるため、ログインページと登録ページにはすでに適用された状態でレンダリングされます。

### 共有リンク [#shared-links]

共有リンクは、そのリンクを所有するテナントのテーマを反映するものであり、閲覧者のテーマを反映するものではありません。所有側のテナントで `interface.theme` が設定されていない場合、あるいは共有リンクの設定の読み込みに失敗した場合、共有ページは閲覧者のテーマにフォールバックするのではなく、デプロイメントのテーマを表示しません。共有ページから離れると、閲覧者のテーマが復元されます。

## バンドルされているテーマ [#bundled-themes]

| Name | Theme |
| ---- | ----- |
| `librechat` | LibreChat のデフォルトのパレットと形状です。明示的に設定すると、`REACT_APP_THEME_*` の色やユーザーが保存したテーマも上書きされます。 |
| `clickhouse` | ClickHouse の Click UI デザイントークンから作成されたリファレンステーマです。[ClickHouse テーマ](#clickhouse-theme)を参照してください。 |

これら以外の名前は無視されます。サーバーはログに記録し、`interface.theme` を破棄します（[Validation](#validation) を参照）。そして、アプリは上記のリストの次のソースにフォールバックします。

### ClickHouse テーマ [#clickhouse-theme]

`interface.theme: clickhouse` は色と形状の両方を変更します：

- **パレット。** すべてのカラー・トークンは、Click UIのライトおよびダーク・トークンから両方のモードで定義されているため、LibreChatのパレットにフォールバックされることはありません。値はClick UI独自のものであり、ペアリングがWCAG AAのコントラスト比を下回る場合でも同様です。より高いコントラストを必要とするユーザーは、組み込みのアクセシブル・パレットを常に使用するハイコントラスト・モードを選択できます（[テーマの選択方法](#how-the-theme-is-chosen)を参照してください）。
- **アクセント。** ライトモードではほぼ黒の `#151515`、ダークモードでは ClickHouse イエローの `#faff69` を使用し、アクセントおよび送信ボタンに適用されます。フォーカスリングは Click UI のアウトラインカラーで、ライトモードでは青の `#437eef`、ダークモードでは `#faff69` となります。
- **ボタン。** プライマリボタンは、ライトモードでは `#302e32`、ダークモードでは `#faff69` であり、Click UI のホバーステップが適用されます。
- **Radii.** Click UIの `border.radii` から採用されたよりタイトなスケールです。コントロール、メニュー、ポップオーバー、ツールチップ、タブ、コンポーザーのアクションボタン、および `sm` から `lg` までは `0.25rem`、サーフェスおよび `xl`/`2xl` は `0.5rem`、大きなサーフェスおよび `3xl` は `0.75rem` で制御されます。
- **境界線。** コントロールやチップの装飾的なアウトライン、およびストロークされた表面内のヘアラインは非表示になります（`chromeBorderAlpha` と `insetBorderAlpha` が `0`）。そのため、表面は塗りつぶしによって区切られます。フィールドの端とニュートラルボタンの境界線はそのまま維持されます。破壊的なアクションには `soft` スタイルが使用されます。
- **シャドウ。** UIの単一の浮き上がったシャドウを、すべての隆起した表面、メニュー、およびドラッグされたアイテムに適用します。不透明度はライトモードで0.15、ダークモードで0.6とし、`2xs`から`sm`までのステップには極細のシャドウを使用します。ツールチップにはシャドウを適用しません。
- **コントロール。** ボタンとフィールドの高さは2remです（サインインフィールドと送信ボタンを含みます。このテーマでは `authFieldHeight` と `authButtonHeight` を `2rem` に設定しており、デフォルトはそれぞれ `2.75rem` と `3rem` です）。コントロールのパディングは `1rem`、アイコンの間隔は `0.5rem`、ラベルのウェイトはレギュラー（`400`）です。フィールドは塗りつぶし（`fieldFillStyle: fill`）で、フォーカス時にエッジの色が切り替わります（`fieldFocusStyle: border`）。ラベルは `0.75rem`、ウェイトは `500` です。無効化されたコントロールは `fill` スタイルと専用の無効色を使用し、スイッチは2rem x 1remのコンパクトなサイズで、テーブルの行には1pxの罫線が引かれます。
- **ダイアログ.** 1pxの境界線、`2rem`の左右パディング、タイトルは`1.25rem`、ウェイト`700`で、Interフォントスタックを使用します。すべてのダイアログのスクリム（背景の暗転）は不透明度0.75です。
- **フォント。** UIフォントはInterのままです。コードにはClick UIのモノスペーススタックである `"Inconsolata", Consolas, "SFMono Regular", monospace` を使用します。LibreChatにはInconsolataがバンドルされています。見出しにはBasier Squareが優先的に指定されていますが、これはバンドルされていないため、閲覧者がインストールしていない限りInterでレンダリングされます。

## インラインテーマの定義 [#inline-theme-definition]

`interface.theme`には、名前の代わりにテーマ定義を記述することもできます。省略した項目は、そのモードにおけるLibreChatのデフォルト値が適用されるため、変更したい値のみを定義すれば問題ありません。

```yaml filename="interface / theme"
interface:
  theme:
    version: 1
    name: acme
    modes:
      light:
        colors:
          rgb-accent-primary: '29 78 216'
          rgb-accent-primary-hover: '30 64 175'
          rgb-ring-primary: '29 78 216'
          rgb-surface-submit: '29 78 216'
          rgb-surface-submit-hover: '30 64 175'
          rgb-link: '29 78 216'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.2)'
      dark:
        colors:
          rgb-accent-primary: '96 165 250'
          rgb-accent-primary-hover: '147 197 253'
          rgb-ring-primary: '96 165 250'
          rgb-surface-submit: '37 99 235'
          rgb-surface-submit-hover: '29 78 216'
          rgb-link: '96 165 250'
        appearance:
          controlRadius: '0.375rem'
          radiusLg: '0.375rem'
          radiusXl: '0.5rem'
          shadowLg: '0 8px 16px -4px rgb(0 0 0 / 0.5)'
    brands:
      provider-openai: '#10a37f'
```

| キー | 型 | 説明 |
| ---- | ---- | ---- |
| `version` | Number | 必須。値は `1` である必要があります。 |
| `name` | String | 必須。テーマの空でない名前。 |
| `modes` | Object | 必須。`light` および/または `dark` を保持します。省略したモードは、そのモードに対する LibreChat のデフォルト値を使用します。 |
| `modes.<mode>.colors` | Object | そのモードのカラートークン。キーは `rgb-*` トークン名、値は `R G B` の3つ組です。[Colors](#colors) を参照してください。 |
| `modes.<mode>.appearance` | Object | そのモードの形状、コントロール、タイポグラフィ、スクリム、シャドウ、モーションの値。[Appearance](#appearance) を参照してください。 |
| `modes.<mode>.brands` | Object | そのモードのプロバイダーブランドカラー。テーマ全体の `brands` を上書きします。 |
| `brands` | Object | 両方のモードに対するプロバイダーブランドカラー。[Brands](#brands) を参照してください。 |

### 検証 [#validation]

サーバーは、`librechat.yaml` が読み込まれた際および設定がリロードされるたびに、ブラウザが描画前に適用するのと同じルールで `interface.theme` をチェックします。

**無効なテーマは、`interface.theme` が設定されていないものとして破棄されます。** 間違った `version`、欠落した `name`、`light` または `dark` 以外のモード、定義形式に存在しないフィールド（トップレベルの `css` など、またはモード内の `colors`、`appearance`、`brands` 以外のもの）、不明なブランドトークン、あるいはトークンに対して不適切な種類の値が指定されている場合、そのテーマは使用できません。LibreChat は `interface.theme` を削除し、問題ごとに1行の警告をログに記録した上で、残りの設定を通常通り読み込みます。そのため、テーマの誤りによってサーバーが停止することはありません。その場合、ユーザーは [How the theme is chosen](#how-the-theme-is-chosen) に記載されている次のソース、つまり `REACT_APP_THEME_*` カラー、保存されたテーマ、あるいはそれらのいずれも適用されない場合は LibreChat のデフォルトテーマが適用されます。ログでは、これをデフォルトテーマと呼びます：

```text
Ignoring interface.theme in /app/librechat.yaml; the default theme applies instead:
- interface.theme.modes.dark.colors.rgb-surface-primary: Invalid RGB value for rgb-surface-primary: 300 16 32
```

存在しないバンドルテーマ名が指定された場合も同様に処理されます（`Unknown bundled theme "<name>", expected one of: librechat, clickhouse`）。

（[Admin Panel](/docs/features/admin_panel#configuration-management) でロール、グループ、またはユーザーに対して）設定オーバーライドを通じて設定されたテーマは、同じルールに従いますが、1点だけ違いがあります。無効なオーバーライドテーマが指定された場合、デフォルトのテーマではなく、`librechat.yaml` のベースとなる `interface.theme` にフォールバックされます。そのログ行は `[getAppConfig]` で始まり、例えば `[getAppConfig] Ignoring interface.theme from a config override; the base theme applies instead:` のようになります。

`colors` および `appearance` マップは、その周囲のフィールドとは異なる動作をします。

**未知のトークンは無視され、テーマの残りの部分は適用されます。** `colors` または `appearance` 内のキーで、このバージョンの LibreChat が認識できないもの（タイプミスや新しいバージョンで追加されたトークンなど）は、そのキーのみが無効となります。サーバーはそれをログに記録し、未知のカラーをブラウザに送信するテーマから除外します：

```text
interface.theme in /app/librechat.yaml names tokens this version ignores:
- interface.theme.modes.light.colors.rgb-surfce-secondary: Unknown light color token ignored: rgb-surfce-secondary
```

不明なトークンであっても形状のチェックは行われます。色名は `R G B` 値を保持するプレーンな小文字のトークン（英数字および `-`）である必要があり、外観名は `;`、`{`、`}`、`<`、`>`、または `url()` を含まないプレーンな値を保持する camelCase である必要があります。それ以外はエラーとなり、テーマ全体がフォールバックされます。スペルミスのあるトークンはサーバーログにのみ報告されるため、テーマを変更した後は必ずサーバーログを確認してください。

ブラウザは受け取ったテーマに対して同じルールを適用し、例えば古いキャッシュ済みのクライアントが新しいサーバーと通信する場合など、テーマを拒否しなければならない場合には `[DeploymentTheme] Ignoring invalid interface.theme: ...` とログを出力します。

### 色 [#colors]

カラーは、テーマエンジンと同じトークン名を使用します。`rgb-` に続けてトークンを指定します。例えば `rgb-surface-primary`、`rgb-text-primary`、`rgb-border-medium`、`rgb-accent-primary`、`rgb-status-error-subtle` のようになります。169 個のトークンすべての一覧は、[`packages/data-provider/src/theme.ts`](https://github.com/LibreChat-AI/LibreChat/blob/dev/packages/data-provider/src/theme.ts) の `themeColorTokens` にあり、サーバーとブラウザの両方がこれを読み込みます。各トークンの説明は、[`packages/client/src/theme/types/index.ts`](https://github.com/LibreChat-AI/LibreChat/blob/dev/packages/client/src/theme/types/index.ts) の `IThemeRGB` インターフェースに記載されています。

表面的なテキスト、境界線、ステータス、構文のパレットに加え、これらの役割によってテーマは特定のインタラクション状態やコンポーネントを再スタイル化できます：

| 役割 | トークン | 用途 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| フォーカス | `rgb-focus-outline`, `rgb-focus-control` | アプリ全体のキーボードフォーカスアウトラインと、共有コントロールのフォーカスリング |
| 押下時 | `rgb-surface-pressed`, `rgb-surface-inverted-pressed` | 押下中のニュートラルおよび反転コントロール |
| 反転および固定 | `rgb-surface-inverted`, `rgb-surface-inverted-hover`, `rgb-text-inverted`, `rgb-surface-fixed`, `rgb-surface-fixed-hover`, `rgb-text-fixed` | 反対のモードの色で描画されるコントロールと、両モードで一定の色を保つコントロール |
| 無効 | `rgb-surface-disabled`, `rgb-text-disabled`, `rgb-border-disabled` | `disabledStyle` が `fill` の場合の無効化されたコントロール([外観](#appearance)を参照) |
| コントロールの境界線 | `rgb-border-control` | 入力欄、セレクトトリガー、ワンタイムコードスロットの縁。3:1のコントラストが必要なため、控えめな区切り線とは別に扱われます |
| フィールド | `rgb-border-field-focus`, `rgb-field-fill`, `rgb-field-text` | `fieldFocusStyle` が `border` の場合のフォーカスされたフィールドの縁(`rgb-focus-control` に従う)、`fieldFillStyle` が `fill` の場合のフィールドの塗りつぶし(`rgb-surface-primary` に従う)、入力された値(`rgb-text-primary` に従う) |
| チェックボックス | `rgb-checkbox-fill` | `checkboxFillStyle` が `fill` の場合の未チェックのチェックボックスの塗りつぶし(`rgb-surface-primary` に従う) |
| プライマリボタン | `rgb-button-primary`, `rgb-button-primary-hover` | プライマリボタンの塗りつぶしとホバー。チェックボックスやスイッチが引き続き使用する `rgb-surface-inverted` と `rgb-surface-inverted-hover` に従う |
| インク | `rgb-dialog-title`, `rgb-badge-label` | ダイアログのタイトルとバッジのラベル。いずれも `rgb-text-primary` に従う |
| スクリム | `rgb-surface-overlay` | ダイアログの背後の色。その強さは[外観](#appearance)のスクリム不透明度によって設定される |
| メディアオーバーレイ | `rgb-surface-media-overlay`, `rgb-text-on-media` | ユーザー自身の画像の上に描画されるスクリム、チップ、進捗表示(ライトボックス、画像プレビュー、アップロード中のファイル)と、その上のテキスト。付属のテーマでは、両モードで黒と白のまま保たれます |
| アバター | `rgb-avatar-fill`, `rgb-avatar-text`, `rgb-avatar-placeholder`, `rgb-avatar-edge` | デフォルトのユーザーアバターの塗りつぶしとグリフ(グリフは `rgb-text-primary` に従う)、読み込み中または透明なエージェントやアシスタントのアバターの背景(ライトモードでは `rgb-surface-secondary`、ダークモードでは `rgb-surface-tertiary` に従う)、デフォルトアバターの周囲の細い線 |
| ファイルタイル | `rgb-file-document`, `rgb-file-sheet`, `rgb-file-code`, `rgb-file-artifact`, `rgb-file-audio`, `rgb-file-video`, `rgb-file-generic`, `rgb-file-ink` | ファイルの種類ごとの塗りつぶしと、すべてのタイルに描かれるグリフ |
| イラスト | `rgb-illustration-subtle`, `rgb-illustration`, `rgb-illustration-strong` | ファイルドロップゾーンのイラストなど、アプリ内のアートワークの3つのトーン |
| スイッチ | `rgb-switch-unchecked`, `rgb-switch-thumb` | 未チェック状態のスイッチのトラックと、両状態でのノブ |
| テーブル | `rgb-table-header-text`, `rgb-table-header-fill` | 列名と、固定ヘッダーの不透明な塗りつぶし |
| チャートの系列 | `rgb-series-1` から `rgb-series-8` まで | カテゴリカルなチャートの色(順番どおり) |

各値は `0` から `255` までの各チャンネルを持つ、装飾のない `R G B` の3つ組である必要があります（例: `'255 255 255'`）。16進数値や `rgb(...)` 形式は受け付けられません。YAMLが文字列として読み込めるよう、値を引用符で囲んでください。

一部のトークンは、省略した場合に設定した関連トークンに従うため、部分的なパレットに一貫性が保たれます。例えば、`rgb-text-muted` は `rgb-text-tertiary` に、`rgb-surface-composer-hover` および `rgb-surface-pressed` は `rgb-surface-hover` に、`rgb-focus-outline` は `rgb-ring-primary` に、`rgb-focus-control` は `rgb-text-primary` に、`rgb-border-control` は `rgb-border-light` に、`rgb-switch-thumb` は `rgb-surface-primary` に、`rgb-table-header-text` は `rgb-text-secondary` に、そして `rgb-table-header-fill` は `rgb-surface-dialog` に従います。

### 外観 [#appearance]

外観の値は**モードごとに**設定され、設定がないモードでは以下のデフォルト値が使用されます。デフォルト値は、ダークモードでより強調される `menuShadow` と `tooltipShadow`、およびダークモードで不透明になる `buttonNeutralBorderOpacity` を除き、両モードで共通です。両方のモードで形状を変更するには、上記の例のように `light` と `dark` の両方の下に値を記述してください。

| Key | Controls | Default |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `controlRadius` | ボタンや入力欄などのコントロールの角丸 | `0.75rem` |
| `roundControlRadius` | 完全に丸いコントロールの半径 | `9999px` |
| `surfaceRadius` | カードやメニューなどのサーフェスの半径 | `1rem` |
| `largeSurfaceRadius` | ダイアログなどの大きなサーフェスの半径 | `1.5rem` |
| `menuRadius` | メニューパネルの角丸 | `0.7rem` |
| `menuPanelRadius` | モデル選択メニュー、ホバーカード、コンポーザーのメニューの角丸。未設定時は `radiusXl` に従う | `0.75rem` |

許容される値:

- **Radii、`controlHeight`、`controlPaddingX`、`buttonPaddingX`、`controlGap`、`buttonHeight`、`buttonHeightSm`、`fieldHeight`、`fieldPaddingY`、spacing、tooltipのpaddingとtext size、textとlabelのsizes、およびdialogのlengths（`dialogStroke`、`dialogPaddingX`、`dialogHeaderGap`、`dialogTitleSize`）：** `0`、または `px`、`rem`、`em` 単位の数値（`0.25rem` など）、あるいはそれら2つの長さを用いた単一の `calc()`（`calc(0.5rem - 2px)` など）。
- **`buttonHeightXs`、`buttonHeightLg`、`buttonHeightCompact`、`iconButtonSizeSm`、`fieldHeightLg`、`authFieldHeight`、`authButtonHeight` および `authActionHeight`:** 最小ポインターターゲットサイズである `24px` (`1.5rem`) 以上の `px` または `rem` 単位の長さ。
- **`iconSize`:** `12px` から `20px` (`0.75rem` から `1.25rem`)。 **`iconSizeMd`:** `20px` から `24px`。 **`iconSizeLg`:** `16px` から `32px`。 **`checkboxSize`:** `16px` から `24px`。 **`listMaxHeight`:** `128px` から `640px` (`8rem` から `40rem`)。それぞれ `px` または `rem` 単位の長さです。
- **`tabMinWidth` および `listMinWidth`:** `0`、または `px` か `rem` 単位の長さ。
- **`switchWidth` および `switchHeight`:** `px` または `rem` で指定する正の長さ。両方とも同じ単位を使用する必要があります（片方を省略した場合は `rem` がデフォルトとして使用されます）。ノブが移動できるように幅は高さよりも大きくする必要があり、高さは 4px のトラック境界線をクリアできる必要があります（`4px` より大きい、または少なくとも `0.5rem`）。
- **`tableCellSpaceY` および `tableRowStroke`:** `0`、または `px` か `rem` 単位の長さ。
- **`focusRingWidth`:** `px` または `rem` 単位の正の長さ。フォーカスインジケーターが消えないようにします。
- **`focusRingOffset`:** `0`、または `px` や `rem` 単位の長さ（負の値を指定すると、要素の境界線の内側にアウトラインが描画されます）。
- **`disabledStyle`:** `dim` または `fill`。
- **`fieldFocusStyle`:** `ring` または `border`。
- **`fieldFillStyle`:** `transparent` または `fill`。
- **`checkboxFillStyle`:** `transparent` または `fill`。
- **フォントウェイト (`controlFontWeight`, `dialogTitleFontWeight`, `inlineCodeWeight`):** `1` から `1000` までの整数。`labelFontWeight` は `inherit` も受け付けます。
- **行の高さ (`leading*` ステップ、`labelLeading`、および `dialogTitleLeading`):** 単位のない数値（`1.5` など）、2つの数値を割る単一の `calc()`（`calc(1.25 / 0.875)` など）、または長さのいずれか。
- **Scrim opacities, `buttonNeutralBorderOpacity`, `chromeBorderAlpha` および `insetBorderAlpha`:** `0` から `1` までの数値。
- **`destructiveStyle`:** `fill` または `soft`。
- **フォントファミリー:** `;`、`{`、または `}` を含まない空ではない `font-family` リスト。フォントはブラウザから利用可能である必要があります。LibreChat には Inter、Roboto Mono、Inconsolata がバンドルされているため、それ以外のファミリーを使用する場合は、閲覧者のマシンにインストールされているか、デプロイメントによって提供されている必要があります。そうでない場合は、リスト内の次のファミリーが使用されます。
- **Shadow steps (`shadow2xs` through `shadow2xl`), `menuShadow`, `tooltipShadow` および `elevationDrag`:** 具体的な `box-shadow` のリスト、または `none`。`var()`、`env()`、`attr()` および `url()` は使用できません。
- **`elevationSurface`:** `;`, `{`, `}` または `url()` を含まない、空ではない任意の `box-shadow` 値。
- **Motion:** `ms` または `s` 単位の期間（例: `120ms`）。

すべてのappearanceの値は文字列である必要があります。フォントの太さ、行の高さ、不透明度などの数値は引用符で囲んでください（`'500'`、`'1.5'`、`'0.8'`）。引用符で囲まれていないYAMLの数値は拒否されます。

### ブランド [#brands]

`brands` は、モデルの横に表示されるプロバイダーアイコンの色を変更します。これは両方のモードに対してトップレベルで一度設定することも、`modes.<mode>.brands` の下でモードごとに上書きすることも可能です。

| キー | デフォルト |
| --- | --- |
| `provider-openai` | `#19C37D` |
| `provider-openai-gpt4` | `#AB68FF` |
| `provider-openai-reasoning` | `#000000` |
| `provider-anthropic` | `#d09a74` |
| `provider-azure` | `linear-gradient(0.375turn, #61bde2, #4389d0)` |

値は16進数のカラーコード（`#rgb`、`#rrggbb`、または `#rrggbbaa`）です。塗りつぶしには `linear-gradient(...)` を使用することもできます。アイコンのグリフ色である `provider-foreground` は、16進数のカラーコードである必要があります。

## LibreChat 以外でテーマを使用する [#using-the-theme-outside-librechat]

`@librechat/client` パッケージはテーマをスタイルシートとして公開しているため、そのコンポーネントに基づいて構築された別のアプリでも同じトークンを適用できます。Tailwind をインポートするスタイルシートで `@librechat/client/theme.css` をインポートしてください：

```css filename="app.css"
@import 'tailwindcss';
@import '@librechat/client/theme.css';
```

これには、セマンティックカラーのトークンとそのTailwindマッピング、すべての色および外観トークンのデフォルト値、そしてInter、Roboto Mono、Inconsolataの`@font-face`ルールが含まれています。フォントファイルはパッケージ内に`@librechat/client/fonts/*`として同梱されているため、アプリのバンドラー（Vite、webpack、またはesbuild）がこれらを解決して出力する必要があります。バンドラーを使用せずにコンパイル済みのCSSを提供するセットアップの場合は、それらのパス自体を配信する必要があります。フォントは、そのフォントでテキストがレンダリングされる際にのみダウンロードされます。
