## Visão geral [#overview]

O objeto `memory` ativa a [Memória do Usuário](/docs/features/memory) e define seus limites. Adicionar a seção é o que habilita a memória: as entradas salvas passam a ser incluídas nas conversas de cada usuário, os usuários podem gerenciá-las no painel de Memórias, e a ferramenta de Memória (`set_memory` e `delete_memory`) é oferecida nos chats e agentes, desde que a capacidade `memory` esteja habilitada para o endpoint de agentes (o que ocorre por padrão).

A extração automática de memória, em que um agente de memória separado analisa cada troca e salva fatos sem que isso seja solicitado, é uma opção separada que precisa ser ativada: defina `agent.enabled: true` e informe um modelo.

## Exemplo [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'Configura o agente de memória automático opcional. Pode ser uma referência a um agente existente por ID ou uma configuração completa de agente.',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

Configura o agente de memória automática. Ele só é executado quando `enabled` está definido como `true`; um bloco `agent` sem `enabled` é ignorado e o LibreChat registra um aviso na inicialização.

Quando habilitado, o agente de memória é executado no início de cada requisição de chat, em paralelo com a resposta principal. Ele analisa as últimas `messageWindowSize` mensagens (limitadas a `maxInputTokens`) e salva ou exclui entradas por conta própria. Ele tem até o término da resposta principal mais até 3 segundos; se ainda estiver em execução após esse período, o seu resultado é descartado para aquela requisição.

O campo `agent` suporta dois formatos de configuração diferentes:

### Agente por ID [#agent-by-id]

Quando você tiver um agente pré-configurado, você pode referenciá-lo pelo seu ID:

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### Configuração de Agente Personalizado [#custom-agent-configuration]

Para maior controle, você pode definir uma configuração completa de agente:

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## Exemplo Completo de Configuração [#complete-configuration-example]

Um exemplo usando todas as opções de memória:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## Usando Custom Endpoints [#using-custom-endpoints]

O recurso de memória suporta endpoints personalizados. Ao usar um endpoint personalizado, o campo `provider` deve corresponder exatamente ao `name` do endpoint personalizado. Cabeçalhos personalizados com variáveis de ambiente e placeholders de usuário são resolvidos corretamente.

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- Veja [Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) para todos os placeholders disponíveis

## Notas [#notes]

- `personalize` controla se os usuários podem optar por sair, e não se a memória está ativada. Use `disabled` para desativar a memória.
- `maxInputTokens` limita o contexto do chat enviado ao agente de memória automática, enquanto `tokenLimit` limita o tamanho total das memórias armazenadas.
- Instruções personalizadas em `instructions` substituem as instruções de memória padrão e são úteis principalmente em conjunto com `validKeys`.
- O acesso também é controlado por função por meio das permissões de memória (usar, criar, ler, atualizar, optar por não participar). Consulte [`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories), o [Painel de Administração](/docs/features/admin_panel), ou as configurações de administrador na parte inferior do painel de Memórias.

## Solução de problemas [#troubleshooting]

**A memória não faz nada.** Verifique se a seção `memory` existe e se `disabled` não é `true`, se a função do usuário tem permissão para usar memórias e se o usuário não desativou **Reference saved memories**. Para a ferramenta Memory, a capacidade `memory` deve estar na lista `capabilities` do endpoint de agents, caso você tenha definido uma.

**Nada é salvo automaticamente.** A extração automática requer `agent.enabled: true` e um `id` válido, ou `provider` e `model`. Sem isso, as entradas só são salvas quando um usuário pede ao modelo para lembrar de algo com a ferramenta Memory ativada, ou quando as adiciona manualmente.

**O agente de memória falha em um endpoint personalizado.** `provider` deve corresponder exatamente ao `name` do endpoint personalizado. Primeiro, confirme que o endpoint funciona para conversas normais e, em seguida, verifique se as variáveis de ambiente referenciadas em seus headers estão definidas; os placeholders dos headers são resolvidos da mesma forma para a memória e para o chat.

**O uso de tokens está alto.** Reduza `maxInputTokens` ou `messageWindowSize` para enviar menos conversa ao agente de memória, reduza `tokenLimit` para manter pequenas as memórias armazenadas (que são adicionadas a cada requisição) e restrinja `validKeys`.
