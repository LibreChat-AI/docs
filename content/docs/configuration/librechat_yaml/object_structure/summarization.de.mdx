## Übersicht [#overview]

Die `summarization`-Konfiguration bietet eine zentralisierte Kontrolle über die Zusammenfassung von Konversationen und das Kürzen von Kontext. Dies ersetzt die pro-endpoint `summarize`- und `summaryModel`-Felder, die zuvor für benutzerdefinierte und Azure OpenAI-endpoints verfügbar waren.

Wenn eine Konversation das Kontextfenster des Modells überschreitet, komprimiert das Zusammenfassungssystem ältere Nachrichten automatisch in eine prägnante Checkpoint-Zusammenfassung. Dies schafft Kontextspeicherplatz für spätere Interaktionen, aber Zusammenfassungen sind verlustbehaftet und können Details auslassen. Überprüfen Sie das ursprüngliche Transkript, wenn der genaue Wortlaut oder ein früheres Tool-Ergebnis wichtig ist. Das System umfasst außerdem **Kontext-Kürzung** (context pruning), die große Tool-Ergebnisse in älteren Nachrichten schrittweise reduziert, um Token-Speicherplatz zurückzugewinnen, bevor eine Zusammenfassung erforderlich ist.

Nach einem Zusammenfassungs-Turn verwendet die Anzeige für die Kontextnutzung die gespeicherte Zusammenfassungs-Basislinie zuzüglich der Turns nach der Zusammenfassung, anstatt den verworfenen Verlauf vor der Zusammenfassung erneut zu zählen. Die kumulativen Nutzungs- und Kostensummen beinhalten weiterhin die Gesamtausgaben des Zweigs.

## Manuelle Kontextkomprimierung [#manual-context-compaction]

Wenn `summarization.enabled` nicht auf `false` gesetzt ist, bieten Agent-Konversationen über die Konversationssteuerung **Kompakten Kontext** (Compact context). Dies startet einen reinen Zusammenfassungs-Turn am aktuellen Verzweigungsblatt: LibreChat fasst den relevanten Verlauf zusammen, speichert den neuen Zusammenfassungs-Checkpoint und beendet den Vorgang, ohne den primären Agenten oder einen Subagenten zur Erstellung einer Antwort aufzufordern.

Frühere Nachrichten bleiben im Transkript sichtbar, aber spätere Modellaufrufe verwenden die komprimierte Zusammenfassung zuzüglich der durch [`retainRecent`](#retainrecent) beibehaltenen Inhalte. Die resultierende Markierung identifiziert eine vom Benutzer initiierte Komprimierung, und der Token-Verbrauch durch den Summarizer wird separat aufgezeichnet. Die Komprimierung ist für eine neue Konversation, eine aktive Generierung, einen Zweig, der nichts für eine Zusammenfassung Geeignetes enthält, oder eine Bereitstellung, bei der die Zusammenfassung deaktiviert ist, nicht verfügbar. Wenn der Summarizer fehlschlägt oder keine Zusammenfassung erstellt, lässt LibreChat den vorherigen Kontext unverändert und meldet den Grund.

## Beispiel [#example]

```yaml filename="summarization"
summarization:
  provider: 'openAI'
  model: 'gpt-4o-mini'
  maxSummaryTokens: 4096
  reserveRatio: 0.05
  trigger:
    type: 'token_ratio'
    value: 0.8
  retainRecent:
    turns: 2
    tokens: 2000
  contextPruning:
    enabled: true
    keepLastAssistants: 3
    softTrimRatio: 0.3
    hardClearRatio: 0.5
    minPrunableToolChars: 50000
    softTrim:
      maxChars: 4000
      headChars: 1500
      tailChars: 1500
    hardClear:
      enabled: true
      placeholder: '[Old tool result content cleared]'
```

## contextPruning

<OptionTable
  options={[
    [
      'contextPruning',
      'Object',
      'Konfiguriert die positionsbasierte Verschlechterung von Tool-Ergebnissen. Große Tool-Ergebnisse in älteren Nachrichten werden schrittweise gekürzt oder gelöscht, um Token-Speicherplatz zurückzugewinnen.',
      '',
    ],
  ]}
/>

Context pruning ist eine optionale Funktion, die unabhängig von der Zusammenfassung (Summarization) arbeitet. Sie zielt auf große Tool-Call-Ergebnisse in älteren Nachrichten ab und wendet dabei zwei progressive Stufen an:

1. **Soft trim** — Kürzt Tool-Ergebnisse, sodass nur der Anfangs- und Endbereich beibehalten wird, mit einer Ellipse dazwischen
2. **Hard clear** — Ersetzt das gesamte Tool-Ergebnis durch einen kurzen Platzhalter

Beide Stufen sind positionsbasiert: Nachrichten, die sich näher am Anfang der Konversation befinden (älter), werden zuerst entfernt.

Wenn die Agent-Kontextkürzung (Agent context pruning) aktiviert ist, behält LibreChat die für jeden Agenten gewählte kompakte adaptive Fading-Stufe bei und verwendet sie in späteren Durchläufen. Dies hält die reine Provider-Projektion über Gesprächsrunden, Human-in-the-Loop-Wiederaufnahmen, Stopps, Verzweigungen und Replika-Übergaben hinweg stabil, was die Wiederverwendung des Anthropic Prompt-Caches verbessert. Gespeicherte Konversationsnachrichten und Tool-Ergebnisse bleiben vollständig; die ausgeblendete Projektion wird nicht über den kanonischen Verlauf zurückgeschrieben.

## Migration von Per-Endpoint-Einstellungen [#migration-from-per-endpoint-settings]

Wenn Sie zuvor `summarize` und `summaryModel` für benutzerdefinierte oder Azure OpenAI endpoints verwendet haben:

```yaml filename="Before (removed)"
endpoints:
  custom:
    - name: 'My Endpoint'
      summarize: true
      summaryModel: 'gpt-3.5-turbo'
```

Diese Felder wurden entfernt. Verwenden Sie stattdessen die `summarization`-Konfiguration auf oberster Ebene:

```yaml filename="After"
summarization:
  model: 'gpt-4o-mini'
```

## Hinweise [#notes]

- Die Zusammenfassung wird global und nicht pro endpoint konfiguriert.
- Die Felder `summarize` und `summaryModel` bei benutzerdefinierten endpoints und Azure OpenAI endpoints werden nicht mehr unterstützt.
- Wenn `provider` und `model` weggelassen werden, werden der eigene Provider und das eigene Modell des Agenten für die Zusammenfassung verwendet.
- `retainRecent` behält einen aktuellen, wortgetreuen Anhang außerhalb der Zusammenfassung bei; `turns` akzeptiert `0-20` und `tokens` muss positiv sein
- Das Kontext-Pruning ist standardmäßig deaktiviert und muss explizit mit `contextPruning.enabled: true` aktiviert werden.
- Das Context Pruning wirkt sich nur auf Tool-Call-Ergebnisse aus, die `minPrunableToolChars` überschreiten – kleinere Ergebnisse werden niemals gekürzt.
- Die Einstellung `keepLastAssistants` schützt aktuelle Gesprächsverläufe vor dem Kürzen, unabhängig von den Trim-/Lösch-Verhältnissen.
- Benutzerdefinierte `prompt`- und `updatePrompt`-Werte ersetzen die integrierten Prompts vollständig – mit Vorsicht verwenden
- Setzen Sie `AGENT_DEBUG_LOGGING=true` in Ihrer `.env` Datei, um die ausführliche Protokollierung von Token-Anzahlen und Diagnosen zur Kontextkürzung zu aktivieren.
