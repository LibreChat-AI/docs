`webSearch` 配置允许您自定义 LibreChat 中的网络搜索功能，包括搜索提供商、内容抓取工具和结果重排序器。

## 概述 [#overview]

Web search 功能由三个主要组件组成：

1. **搜索提供商 (Search Providers)**：执行初始网络搜索的服务
2. **Scrapers**: 从网页中提取内容的服务
3. **Rerankers**：对搜索结果进行重新排序以提高相关性的服务

## 示例 [#example]

```yaml filename="webSearch"
webSearch:
  # Search Provider Configuration
  serperApiKey: "${SERPER_API_KEY}"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngApiKey: "${SEARXNG_API_KEY}"
  searchProvider: "serper" # Options: "serper", "searxng", "tavily", "keenable"

  # Optional: query options sent to a SearXNG instance
  searxngSearchOptions:
    engines: "google,bing,startpage" # Default: "google,bing,duckduckgo"
    language: "en" # Default: "all"

  # Tavily Configuration (search and/or scraper)
  tavilyApiKey: "${TAVILY_API_KEY}"
  # Optional: custom Tavily-compatible endpoints
  tavilySearchUrl: "${TAVILY_SEARCH_URL}"
  tavilyExtractUrl: "${TAVILY_EXTRACT_URL}"

  # Keenable Configuration (search and/or scraper; all credentials optional)
  keenableApiKey: "${KEENABLE_API_KEY}"
  keenableApiUrl: "${KEENABLE_API_URL}"
  keenableSearchOptions:
    maxResults: 8
    site: "example.com"
    attributionTitle: "LibreChat"
    timeout: 15000
  keenableScraperOptions:
    attributionTitle: "LibreChat"
    timeout: 15000

  # Scraper Configuration
  firecrawlApiKey: "${FIRECRAWL_API_KEY}"
  firecrawlApiUrl: "${FIRECRAWL_API_URL}"
  firecrawlVersion: "${FIRECRAWL_VERSION}"
  scraperProvider: "firecrawl" # Options: "firecrawl", "serper", "tavily", "keenable"

  # Reranker Configuration
  jinaApiKey: "${JINA_API_KEY}"
  jinaApiUrl: "${JINA_API_URL}"
  cohereApiKey: "${COHERE_API_KEY}"
  rerankerType: "jina" # Options: "jina", "cohere", "none"

  # General Settings
  scraperTimeout: 7500 # Timeout in milliseconds for scraper requests (default: 7500)
  safeSearch: 1 # Options: 0 (OFF), 1 (MODERATE - default), 2 (STRICT)
  # Required for deliberately private self-hosted provider endpoints
  allowedAddresses:
    - "searxng:8080"
```

## SSRF Protection and Private Providers [#ssrf-protection-and-private-providers]

LibreChat 会验证其为网络搜索、抓取和重排序所建立的每一个连接。私有地址、回环地址、链路本地地址以及云元数据目标地址默认会被拦截，包括重定向跳转以及在连接时解析为私有地址的主机名。

当配置的 SearXNG、Firecrawl、Jina、兼容 Tavily、兼容 Keenable 或相关提供商 endpoint 特意设为私有时，请使用 `webSearch.allowedAddresses`：

```yaml filename="webSearch / allowedAddresses"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  allowedAddresses:
    - "searxng:8080"
    - "10.0.0.5:3002"
    - "[fd00::5]:8080"
```

此字段是一个 SSRF 免除列表，而非严格的允许列表。公共目标地址仍然可用。条目必须是精确的 `host:port`、`private.ip:port` 或 `[ipv6]:port` 对；URL、路径、CIDR 范围、裸主机名/IP 以及公共 IP 字面量将被拒绝。被免除的主机名会信任其在该端口上解析出的任何私有 IP，因此建议优先使用私有 IP 字面量，并仅列出您可控制 DNS 的主机名。

LibreChat 会自动豁免已配置的 HTTP(S) 正向代理端点，以便能够访问该端点。当代理执行请求时，它会解析目标地址并必须自行强制执行目标出口限制。`NO_PROXY` 可以使请求直接发送，此时 LibreChat 的连接防护机制仍然适用。该防护机制涵盖了 LibreChat 向提供商 API 发起的连接；它无法约束第三方抓取工具作为请求数据接收并在其自身基础设施上获取的页面 URL。

## 凭据所有权 [#credential-ownership]

用户提供的 Firecrawl、SearXNG 或 Jina URL 不得接收服务器拥有的 API 密钥。SSRF 验证并不能使公共用户选择的 endpoint 安全地接收部署的凭据。请将 URL 和密钥配置为管理员拥有的设置，或者让用户提供他们自己的配对；SearXNG 也可以在没有密钥的情况下运行。

如果保存的用户 URL 本应与服务器的密钥配对，LibreChat 将忽略 Firecrawl 的可选 URL 并使用其默认 endpoint。SearXNG 的实例 URL 是必需的，因此混合所有权配置不会被验证，搜索工具也不会被初始化。对于使用服务器密钥的自托管部署，请配置 `FIRECRAWL_API_URL` 或 `SEARXNG_INSTANCE_URL` 以及该密钥，而不是依赖用户保存的 URL。私有 endpoint 仍然需要 [`allowedAddresses`](#ssrf-protection-and-private-providers)。

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
```

`engines` 也接受 SearXNG 本身使用的逗号分隔格式，因此这与上面的列表等效：

```yaml filename="webSearch"
webSearch:
  searxngSearchOptions:
    engines: "google, bing, startpage, qwant"
```

#### 选择引擎 [#choosing-engines]

引擎名称必须与您实例中启用的引擎相匹配，由此得出以下两点：

- SearXNG 会忽略其无法识别的引擎，而不是报告错误。拼写错误或在您的实例上禁用的引擎只会导致搜索结果减少，而不会导致失败。
- 有效的名称取决于具体的实例。请检查 `https://your-instance/config` 处的已启用列表（该页面会返回包含每个已启用引擎的 JSON），或打开您实例偏好设置页面中的 **Engines** 选项卡。

默认值为 `google,bing,duckduckgo`。SearXNG 会聚合所选搜索引擎返回的所有结果，因此如果某个引擎被屏蔽，您只会损失该引擎提供的部分结果，而不是整个响应；只有当所有选定的引擎都失败或未返回任何内容时，搜索结果才会为空。

DuckDuckGo 是该默认集合中最容易被封锁的引擎，因为它会向大多数自托管实例提供验证码（CAPTCHA）。由于该集合中仅包含三个引擎，如果它与受到速率限制的 Google 或 Bing 同时失效，通常会导致完全无法获取结果。显式设置 `engines`、排除 DuckDuckGo 并列出超过三个引擎，都可以降低这种风险。

响应迅速且能够容纳自托管流量的引擎是最佳的入门选择，例如：

```yaml filename="webSearch"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - brave
      - startpage
      - qwant
```

添加更多的引擎可以扩大覆盖范围，但也会拖慢每次搜索的速度，因为 SearXNG 会在响应前等待集合中最慢的引擎。在增加列表时，请留意 `timeout` 设置。

#### 这些选项无法控制的内容 [#what-these-options-do-not-control]

- **Safe search** 不属于此区块。它来自顶层的 [`safeSearch`](#safesearch) 键，并作为 `safesearch` 转发给 SearXNG。
- **Result categories** 由 LibreChat 根据查询内容自动选择，它会将搜索类型映射为 `general`、`images`、`videos` 或 `news`。此处无法覆盖这些设置。
- **页码和结果格式**是固定的。LibreChat 始终以 JSON 格式请求第 1 页，这就是为什么您的实例必须在 `formats` 下启用 `json` 的原因。

## 注意事项 [#notes]

- API keys 可以通过两种方式进行配置：
  1. 设置 YAML 配置中指定的环境变量
  2. 如果未设置环境变量，系统将提示用户通过 UI 提供 API 密钥。
- 该配置支持每个组件（providers、scrapers、rerankers）的多种服务。
- 如果未指定特定的服务类型，系统将尝试该类别下的所有可用服务。
- 安全搜索提供三个级别的内容过滤：OFF (0)、MODERATE (1) 和 STRICT (2)
- Tavily 默认不会继承全局安全搜索设置；仅当您的 Tavily 账户支持 `safe_search` 时，才显式设置 `tavilySearchOptions.safeSearch`。
- Keenable 支持无密钥搜索和页面抓取；其可选密钥可提高公共速率限制，且其抓取 URL 覆盖仅限环境配置。
- SearXNG 查询行为（引擎、语言、时间范围、请求超时）在 `searxngSearchOptions` 下进行配置；如果搜索结果为空，请参阅 [Choosing engines](#choosing-engines)。
- 切勿在 YAML 配置中放入真实的 API 密钥 - 仅使用环境变量名称

## 设置 SearXNG [#setting-up-searxng]

SearXNG 是一个注重隐私的元搜索引擎，您可以自行托管。
有关更多信息，请参阅 [SearXNG 官方文档](https://docs.searxng.org/)。

以下是为 LibreChat 设置您自己的 SearXNG 实例的步骤：

### 使用 Docker Desktop [#using-docker-desktop]

1. **搜索官方 SearXNG 镜像**
   - 打开 Docker Desktop
   - 在 **Images** 选项卡中搜索 `searxng/searxng`
   - 点击官方镜像上的 **Run**，即可自动拉取并运行该镜像的容器。

2. **运行容器**
   - 在下载完成后出现的后续面板中，展开 **Optional Settings** 下拉菜单
   - 设置您所需的配置详情（端口号、容器名称等）
   - 点击 **Run** 以启动容器

3. **配置 LibreChat 的 SearXNG**
   - 在 Docker Desktop 中导航至 `Files` 选项卡
   - 前往 `/etc/searxng/settings.yaml`
   - 打开文件编辑器
   - 导航至 `formats` 部分
   - 添加 `json` 作为可接受的格式，以便 LibreChat 能够与您的实例进行通信
   - 保存文件

4. **重启容器**
   - 重启容器以使更改生效

#### YAML 配置 [#yaml-configuration]

若要为实例上的所有用户配置 SearXNG，而不是按用户单独配置，请在 `librechat.yaml` 中设置相同的值：

```yaml filename="librechat.yaml"
webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  # searxngApiKey: "${SEARXNG_API_KEY}" # Only if your instance requires authentication
  # Required: a self-hosted instance is a private destination, so exempt it from the connection guard
  allowedAddresses:
    - "localhost:55011"
  searxngSearchOptions:
    engines:
      - google
      - bing
      - startpage
      - qwant
    language: "en"
    timeout: 10000
```

URL 和密钥仍然从环境变量中读取，因此请将上述配置与以下内容配对：

```bash filename=".env"
SEARXNG_INSTANCE_URL=http://localhost:55011
# SEARXNG_API_KEY=your_api_key
```

<Callout type="warning" title="私有实例需要一个 allowedAddresses 条目">
`localhost:55011` 是一个回环地址，LibreChat 的 [SSRF protection](#ssrf-protection-and-private-providers) 会在连接时对其进行拦截。如果没有匹配的 `allowedAddresses` 条目，即使 SearXNG 运行正常，搜索也会失败。该条目必须与您实例 URL 中的 `host:port` 完全一致。

当 LibreChat 本身在 Docker 中运行时，`localhost` 指的是 LibreChat 容器，而不是 SearXNG 容器。请使用容器可以访问的主机名（例如 compose 服务名称），并改为豁免该主机名：

```yaml filename="librechat.yaml"
webSearch:
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}" # SEARXNG_INSTANCE_URL=http://searxng:8080
  allowedAddresses:
    - "searxng:8080"
```
</Callout>

请参阅 [`searxngSearchOptions`](#searxngsearchoptions) 以了解此代码块支持的所有子键。

#### 排查空结果问题 [#troubleshooting-empty-results]

如果 SearXNG 搜索未返回任何结果，几乎总是因为请求未到达可用的实例，而不是 LibreChat 丢弃了结果。请按顺序排查以下内容：

1. **该实例是一个私有地址，且没有 `allowedAddresses` 条目。** LibreChat 会在连接时拦截回环地址和私有目标地址，因此自托管实例需要在 [`allowedAddresses`](#ssrf-protection-and-private-providers) 下列出其确切的 `host:port`。这会直接阻止请求，而不是返回空结果集。
2. **`json` 在 `formats` 中缺失。** LibreChat 要求以 JSON 格式返回结果。如果您的实例配置文件中的 `formats` 部分未列出 `json`，则实例会返回错误页面，且每次搜索的结果都为空。这是上述 Docker 设置的第 3 步。
3. **所有选定的引擎均失败。** SearXNG 会合并那些有响应的引擎，因此返回空结果意味着没有任何引擎返回任何内容。DuckDuckGo 包含在默认集合（`google,bing,duckduckgo`）中，但它会向大多数自托管实例提供验证码，这导致只剩下两个引擎来执行搜索。请显式设置 `searxngSearchOptions.engines`，移除 DuckDuckGo，并列出更多引擎。
4. **您的实例上不存在该引擎名称。** SearXNG 会静默跳过它无法识别的引擎，因此拼写错误只会导致搜索结果减少。请将您的列表与 `https://your-instance/config` 进行对比。
5. **该实例的响应速度慢于超时限制。** 如果您的实例查询了多个引擎或处于较慢的网络路径中，请将 `searxngSearchOptions.timeout` 的值调高至默认的 `10000` 以上。

您可以通过直接调用实例来重现 LibreChat 发送的内容：

```bash
curl -s "http://localhost:55011/search?q=librechat&format=json&engines=google,bing,startpage" | head -c 500
```

这会在您自己的机器上运行，因此它完全绕过了 LibreChat 的连接保护。如果此处返回一个空的 `results` 数组，则确认问题出在 SearXNG 一侧；如果此处有结果而 LibreChat 仍然找不到任何内容，则说明问题指向 `allowedAddresses`。
