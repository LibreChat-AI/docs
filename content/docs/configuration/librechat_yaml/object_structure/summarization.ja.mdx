## 概要 [#overview]

`summarization` 設定は、会話の要約とコンテキストの剪定（pruning）を一元管理します。これは、以前カスタムおよび Azure OpenAI エンドポイントで利用可能だったエンドポイントごとの `summarize` および `summaryModel` フィールドに代わるものです。

会話がモデルのコンテキストウィンドウを超えると、要約システムは古いメッセージを自動的に簡潔なチェックポイント要約へと圧縮します。これにより、後のやり取りのためにコンテキストの空き容量が確保されますが、要約は情報を損失する可能性があり、詳細が省略される場合があります。正確な文言や以前のツール結果が重要な場合は、元のトランスクリプトを確認してください。また、システムには**コンテキストプルーニング（context pruning）**も含まれており、要約が必要になる前に、古いメッセージ内の大きなツール結果を段階的に削減してトークンの空き容量を再確保します。

要約のターンが実行された後、コンテキスト使用量ゲージは、破棄された要約前の履歴を再カウントする代わりに、永続化された要約ベースラインと要約後のターンを使用します。累積使用量とコストの合計には、引き続きブランチ全体の支出が含まれます。

## 手動コンテキスト圧縮 [#manual-context-compaction]

`summarization.enabled` が `false` に設定されていない場合、エージェントとの会話では会話コントロールから **Compact context（コンテキストの圧縮）** を利用できます。これは現在のブランチの末尾で要約のみを行うターンを開始します。LibreChat は対象となる履歴を要約し、新しい要約チェックポイントを保存します。この際、メインのエージェントやサブエージェントに応答を求めることはありません。

それ以前のメッセージはトランスクリプト内で引き続き表示されますが、その後のモデル呼び出しでは、要約された内容と [`retainRecent`](#retainrecent) によって保持されたコンテンツが使用されます。生成されたマーカーはユーザーが開始した圧縮であることを示し、要約ツールによるトークン使用量は個別に記録されます。圧縮機能は、新規の会話、アクティブな生成中、要約対象が存在しないブランチ、または要約機能が無効化されているデプロイメントでは利用できません。要約ツールが失敗したか、要約が生成されなかった場合、LibreChatは以前のコンテキストを変更せず、その理由を報告します。

## 例 [#example]

```yaml filename="summarization"
summarization:
  provider: 'openAI'
  model: 'gpt-4o-mini'
  maxSummaryTokens: 4096
  reserveRatio: 0.05
  trigger:
    type: 'token_ratio'
    value: 0.8
  retainRecent:
    turns: 2
    tokens: 2000
  contextPruning:
    enabled: true
    keepLastAssistants: 3
    softTrimRatio: 0.3
    hardClearRatio: 0.5
    minPrunableToolChars: 50000
```

## contextPruning

<OptionTable
  options={[
    [
      'contextPruning',
      'Object',
      '位置ベースのツール結果の劣化を設定します。古いメッセージ内の大きなツール結果は、トークン領域を再確保するために段階的にトリミングまたは削除されます。',
      '',
    ],
  ]}
/>

Context pruningは、要約とは独立して動作するオプトイン機能です。古いメッセージ内の大規模なツール呼び出し結果を対象とし、以下の2つの段階的なステップを適用します。

1. **ソフトトリム**: ツールの結果を先頭と末尾の部分のみに切り詰め、その間に省略記号（…）を挿入します
2. **ハードクリア**: ツール結果全体を短いプレースホルダーに置き換えます

どちらのステージも位置ベースであり、会話の最初の方（古いもの）に近いメッセージから先に削除されます。

エージェントのコンテキストプルーニング（context pruning）が有効な場合、LibreChatは各エージェントに対して選択されたコンパクトな適応型フェージング階層を保持し、それを以降の実行にシードします。これにより、プロバイダー専用のプロジェクションが、ターン間、ヒューマン・イン・ザ・ループの再開、停止、分岐、およびレプリカの引き継ぎを通じて安定し、Anthropicのプロンプトキャッシュの再利用が向上します。保存された会話メッセージとツール結果は完全なまま維持され、フェードされたプロジェクションが正規の履歴に上書きされることはありません。

/>

`contextPruning` は、`enabled: true` を設定しない限り無効です。他のフィールドを省略した場合は、Agents SDK のデフォルト値が適用されます。上記で挙げたキーのみが受け付けられます。`softTrim` や `hardClear` のサブオブジェクトなど、それ以外のキーは無視されます。

**例:**

```yaml filename="summarization / contextPruning"
summarization:
  contextPruning:
    enabled: true
    keepLastAssistants: 5
    softTrimRatio: 0.25
    hardClearRatio: 0.6
    minPrunableToolChars: 30000
```

## エンドポイントごとの設定からの移行 [#migration-from-per-endpoint-settings]

カスタムまたは Azure OpenAI エンドポイントで以前に `summarize` および `summaryModel` を使用していた場合：

```yaml filename="Before (removed)"
endpoints:
  custom:
    - name: 'My Endpoint'
      summarize: true
      summaryModel: 'gpt-3.5-turbo'
```

これらのフィールドは削除されました。代わりにトップレベルの `summarization` 設定を使用してください：

```yaml filename="After"
summarization:
  model: 'gpt-4o-mini'
```

## 注記 [#notes]

- 要約機能はエンドポイントごとではなく、グローバルに設定されます。
- カスタムエンドポイントおよびAzure OpenAIエンドポイントにおける `summarize` および `summaryModel` フィールドは、現在サポートされていません。
- `provider` と `model` が省略された場合、エージェント自身の provider と model が要約に使用されます。
- `retainRecent` は要約の外側に直近の逐語的な末尾を保持します。`turns` は `0-20` を受け入れ、`tokens` は正の数である必要があります。
- Context pruningはデフォルトで無効になっており、`contextPruning.enabled: true` を指定して明示的に有効にする必要があります。
- コンテキストのプルーニングは、`minPrunableToolChars` を超えるツール呼び出しの結果にのみ適用されます(これより小さい結果は一切プルーニングされません)
- `keepLastAssistants` 設定は、トリミングやクリアの比率に関係なく、直近のターンを削除から保護します。
- カスタムの `prompt` と `updatePrompt` の値は、組み込みのプロンプトを完全に置き換えるため、取り扱いには注意してください
- `.env` ファイルで `AGENT_DEBUG_LOGGING=true` を設定すると、トークン数やコンテキストの剪定に関する診断情報の詳細なログ出力を有効にできます。
