## Descripción general [#overview]

El objeto `skillSync` permite a los administradores replicar Skills desde fuentes externas. GitHub es el proveedor compatible.

GitHub Skill Sync lee los archivos `SKILL.md` y sus archivos adjuntos desde las rutas del repositorio configuradas, los almacena como Skills con `source: "github"` y mantiene las filas reflejadas alineadas con el repositorio original en sincronizaciones posteriores.

## Ejemplo [#example]

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
        # credentialKey: production-skills
        # tenantId: your-tenant-id
```

<Callout type="warning" title="Credenciales">
  Utilice `token` o `credentialKey` para cada fuente, pero no ambos. `token` debe ser una referencia a una variable de entorno como `${GITHUB_SKILLS_TOKEN}`. Utilice un personal access token de GitHub de tipo fine-grained con alcance al repositorio seleccionado y con permisos de solo lectura para Contents y Metadata.
</Callout>

### Identidad de origen [#source-identity]

El campo `id` es parte de la identidad del espejo. Mantenlo estable. Redirigir una fuente a un repositorio renombrado o a una nueva referencia mantiene las Skills espejadas vinculadas al mismo id de fuente, mientras que cambiar el id de la fuente crea un nuevo espejo.

Cuando `tenantId` está configurado, las lecturas y escrituras de sincronización se ejecutan dentro del contexto de aislamiento de ese inquilino. Trate `tenantId` como inmutable para un id de origen: cambiarlo, añadirlo o eliminarlo posteriormente deja las Skills reflejadas anteriormente en el inquilino antiguo.

## Comportamiento de sincronización [#sync-behavior]

Sincronización de habilidades de GitHub:

- Descubre archivos `SKILL.md` debajo de cada ruta configurada.
- Importa el cuerpo, el frontmatter y los archivos incluidos de `SKILL.md`.
- Almacena metadatos de origen como source id, owner, repo, ref, skill path, commit SHA y blob SHA.
- Actualiza las Skills reflejadas cuando el archivo original cambia.
- Elimina las Skills y archivos reflejados que fueron eliminados de la fuente configurada.
- Valida y publica Skills de forma independiente, de modo que una Skill no válida o en conflicto no oculte las Skills válidas de la misma fuente.
- Preserva el último espejo en buen estado de una Skill omitida y revierte las escrituras incompletas para esa Skill.
- Marca una ejecución como `partial` cuando publica al menos una Skill pero omite otra, y registra un conteo limitado de omisiones y detalles para las lecturas de estado del administrador.
- Utiliza un bloqueo de sincronización para que solo se ejecute una sincronización de GitHub a la vez.

Las claves de frontmatter `SKILL.md` desconocidas se aceptan cuando sus valores permanecen dentro de los límites de extensión acotados y seguros para JSON. Los campos reconocidos no válidos, los valores de extensión inseguros, los nombres duplicados y los conflictos de propiedad omiten solo la Skill afectada. Los fallos de autenticación, límite de tasa (rate-limit), pérdida de bloqueo (lock-loss), acceso al repositorio y reversión (rollback) siguen siendo fallos a nivel de fuente.

## Eliminación de habilidades [#skill-deletion]

El objeto de nivel superior `skillDeletion` controla el proceso en segundo plano que termina de eliminar las Skills y limpia sus archivos almacenados, junto con las cargas de Skills abandonadas. Es independiente de `skillSync` y se aplica a todas las Skills. Las claves desconocidas se rechazan.

```yaml filename="librechat.yaml"
skillDeletion:
  finalizationEnabled: true
  sweepIntervalMs: 60000
  claimLeaseMs: 120000
  batchSize: 100
  recheckIntervalMs: 3600000
```

## Habilidades de despliegue desde el disco [#deployment-skills-from-disk]

Por separado de `skillSync`, LibreChat carga las Skills desde un directorio del servidor al iniciarse. Cada skill es una carpeta con un `SKILL.md` y cualquier archivo adicional incluido. El directorio es `./skill` en la raíz del proyecto, a menos que establezcas `DEPLOYMENT_SKILLS_DIR` en `.env` (consulta [dotenv](/docs/configuration/dotenv)).

Las Skills de despliegue se muestran a todos los usuarios que tienen la capacidad de Skills, son de solo lectura en la interfaz y ocultan cualquier Skill creada por el usuario con el mismo nombre. Se leen una sola vez al iniciar, por lo que debes reiniciar LibreChat después de agregar, eliminar o editar archivos. [Agent Plugins](/docs/configuration/agent_plugins) también pueden incluir Skills de despliegue; una Skill en este directorio tiene prioridad sobre una Skill de plugin con el mismo nombre.
