## Przegląd [#overview]

Obiekt `speech` umożliwia konfigurację dostawców zamiany tekstu na mowę (TTS) oraz mowy na tekst (STT) bezpośrednio w pliku konfiguracyjnym `librechat.yaml`. Pozwala to na korzystanie z usług głosowych po stronie serwera bez konieczności konfigurowania przez użytkowników własnych kluczy API.

**Pola w `speech`:**

- `tts` - Konfiguracje dostawców Text-to-Speech
- `stt` - Konfiguracje dostawcy Speech-to-Text
- `speechTab` - Domyślne ustawienia interfejsu użytkownika dla funkcji mowy

**Uwagi:**

- Wiele dostawców może być skonfigurowanych jednocześnie
- Użytkownicy mogą wybrać preferowanego dostawcę spośród dostępnych opcji
- Klucze API w pliku konfiguracyjnym powinny używać odniesień do zmiennych środowiskowych ze względów bezpieczeństwa

## Przykład [#example]

```yaml filename="speech"
speech:
  tts:
    allowedAddresses: ["tts.internal:8080"]
    openai:
      apiKey: "${TTS_API_KEY}"
      model: "tts-1"
      voices: ["alloy", "echo", "fable", "onyx", "nova", "shimmer"]
    elevenlabs:
      apiKey: "${ELEVENLABS_API_KEY}"
      model: "eleven_multilingual_v2"
      voices: ["voice-id-1", "voice-id-2"]
  stt:
    allowedAddresses: ["stt.internal:8080"]
    openai:
      apiKey: "${STT_API_KEY}"
      model: "whisper-1"
  speechTab:
    conversationMode: true
    advancedMode: false
    speechToText: true
    textToSpeech: true
```

## Ochrona SSRF [#ssrf-protection]

LibreChat chroni dostarczone przez operatora adresy URL STT i TTS w momencie nawiązywania połączenia. Miejsca docelowe typu private, loopback, link-local oraz cloud-metadata są domyślnie blokowane, a przekierowania dla żądań mowy są wyłączone.

`speech.tts.allowedAddresses` oraz `speech.stt.allowedAddresses` to oddzielne listy wyjątków, a nie ścisłe listy dozwolonych adresów (allowlists). Dodawaj dokładny prywatny `host:port`, `private.ip:port` lub `[ipv6]:port` tylko wtedy, gdy dana sekcja musi uzyskać dostęp do zaufanej usługi hostowanej samodzielnie. Nie używaj adresu URL, ścieżki, zakresu CIDR, samego hosta/IP ani publicznego literału IP. Domyślne porty są normalizowane, więc adres URL HTTPS bez jawnie podanego portu jest sprawdzany jako port `443`.

Wyłączona z ograniczeń nazwa hosta ufa każdemu prywatnemu adresowi, na który rozwiązuje się na danym porcie. Jeśli to możliwe, preferuj literał prywatnego adresu IP i wymieniaj tylko te nazwy, których DNS kontrolujesz i których nie można przekierować przez atakującego.

Gdy serwer proxy przekazuje żądanie z nazwą hosta, wykonuje on rozpoznawanie DNS miejsca docelowego oraz ruch wychodzący, dlatego musi egzekwować własną politykę SSRF. Literalny prywatny adres docelowy jest nadal blokowany przed przetworzeniem przez proxy, chyba że jego dokładny adres i port zostaną wyłączone z tego ograniczenia.

## Uwagi [#notes]

- Zawsze używaj odwołań do zmiennych środowiskowych (np. `${API_KEY}`) dla kluczy API w plikach konfiguracyjnych
- Można skonfigurować wielu dostawców TTS; użytkownicy wybierają preferowaną opcję w interfejsie użytkownika.
- Ustawienia `speechTab` definiują wartości domyślne, które użytkownicy mogą nadpisać w swoich ustawieniach osobistych.
- `browser` korzysta z wbudowanej obsługi mowy w przeglądarce; `external` korzysta z dostawców po stronie serwera skonfigurowanych w `speech.stt` lub `speech.tts`
- Istniejące domyślne ustawienia STT dla `openai` i `azureOpenAI` oraz domyślne ustawienia TTS dla `openai`, `azureOpenAI`, `elevenlabs` i `localai` zostały przeniesione do `external`; w przypadku niedostępności zewnętrznego silnika następuje powrót do `browser`.
- Aby uzyskać szczegółową dokumentację funkcji, zobacz [Speech to Text & Text to Speech](/docs/configuration/stt_tts)
