## 概要 [#overview]

`memory` オブジェクトは [ユーザーメモリ](/docs/features/memory) を有効にし、その上限を設定します。このセクションを追加することでメモリが有効になります。保存されたエントリは各ユーザーの会話に追加され、ユーザーは Memories パネルでそれらを管理できます。また、`memory` 機能が agents エンドポイントで有効になっている限り(デフォルトで有効)、Memory ツール(`set_memory` と `delete_memory`)がチャットおよびエージェントで提供されます。

自動メモリ抽出（別のメモリエージェントがすべてのやり取りを確認し、依頼されなくても事実を保存する機能）は、個別にオプトインする機能です。`agent.enabled: true` を設定し、モデルを指定してください。

## 例 [#example]

```yaml filename="memory"
memory:
  disabled: false
  validKeys: ['user_preferences', 'conversation_context', 'personal_info']
  tokenLimit: 2000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 5
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a helpful assistant that remembers user preferences and context.'
    model_parameters:
      temperature: 0.7
      max_tokens: 1000
```

## agent

<OptionTable
  options={[
    [
      'agent',
      'Object | Union',
      'オプションの自動メモリ・エージェントを設定します。既存のエージェントのIDへの参照、または完全なエージェント設定のいずれかを指定できます。',
      'agent: { enabled: true, provider: "openAI", model: "gpt-4" }',
    ],
  ]}
/>

自動メモリエージェントを設定します。`enabled` が `true` の場合にのみ実行されます。`enabled` を指定せずに `agent` ブロックを記述した場合は無視され、LibreChat は起動時に警告をログに出力します。

有効にすると、メモリエージェントはすべてのチャットリクエストの開始時に、メインの応答と並行して実行されます。最後の `messageWindowSize` 件のメッセージ(`maxInputTokens` を上限とする)を確認し、エントリの保存や削除を自動的に行います。メインの応答が完了するまで、さらに最大3秒間実行できます。その時点でもまだ実行中の場合、そのリクエストに対する結果は破棄されます。

`agent` フィールドは、2つの異なる設定フォーマットをサポートしています：

### IDによるエージェント [#agent-by-id]

事前に設定されたエージェントがある場合、そのIDを使用して参照できます：

```yaml filename="memory / agent (by ID)"
memory:
  agent:
    enabled: true
    id: 'memory-agent-001'
```

### カスタムエージェントの設定 [#custom-agent-configuration]

より詳細な制御を行うには、完全なエージェント設定を定義することができます：

```yaml filename="memory / agent (custom)"
memory:
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: 'You are a memory assistant that helps maintain conversation context and user preferences.'
    model_parameters:
      temperature: 0.3
      max_tokens: 1500
      top_p: 0.9
```

## 完全な設定例 [#complete-configuration-example]

すべてのメモリオプションを使用した例:

```yaml filename="librechat.yaml"
version: 1.3.18
cache: true

memory:
  disabled: false
  validKeys:
    - 'user_preferences'
    - 'conversation_context'
    - 'learned_facts'
    - 'personal_information'
  tokenLimit: 3000
  charLimit: 10000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 8
  agent:
    enabled: true
    provider: 'openAI'
    model: 'gpt-4'
    instructions: |
      Store memory using only the specified validKeys. For user_preferences: save 
      explicitly stated preferences about communication style, topics of interest, 
      or workflow preferences. For conversation_context: save important facts or 
      ongoing projects mentioned. For learned_facts: save objective information 
      about the user. For personal_information: save only what the user explicitly 
      shares about themselves. Delete outdated or incorrect information promptly.
    model_parameters:
      temperature: 0.2
      max_tokens: 2000
      top_p: 0.8
      frequency_penalty: 0.1
```

## カスタム endpoint の使用 [#using-custom-endpoints]

memory機能はカスタムendpointをサポートしています。カスタムendpointを使用する場合、`provider`フィールドはカスタムendpointの`name`と完全に一致している必要があります。環境変数やユーザープレースホルダーを含むカスタムヘッダーは、適切に解決されます。

```yaml filename="librechat.yaml with custom endpoint for memory"

endpoints:
  custom:
    - name: 'Custom Memory Endpoint'
      apiKey: 'dummy'
      baseURL: 'https://api.gateway.ai/v1'
      headers:
        x-gateway-api-key: '${GATEWAY_API_KEY}'
        x-gateway-virtual-key: '${GATEWAY_OPENAI_VIRTUAL_KEY}'
        X-User-Identifier: '{{LIBRECHAT_USER_EMAIL}}'
        X-Application-Identifier: 'LibreChat - Test'
        api-key: '${TEST_CUSTOM_API_KEY}'
      models:
        default:
          - 'gpt-4o-mini'
          - 'gpt-4o'
        fetch: false

memory:
  disabled: false
  tokenLimit: 3000
  maxInputTokens: 12000
  personalize: true
  messageWindowSize: 10
  agent:
    enabled: true
    provider: 'Custom Memory Endpoint'
    model: 'gpt-4o-mini'
```

- 利用可能なすべてのプレースホルダーについては、[Custom Endpoint Headers](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#headers) を参照してください。

## 注記 [#notes]

- `personalize` は、ユーザーがオプトアウトできるかどうかを制御するものであり、メモリが有効かどうかを制御するものではありません。メモリをオフにするには `disabled` を使用してください。
- `maxInputTokens` は自動メモリエージェントに送信されるチャットコンテキストの上限を制限し、`tokenLimit` は保存されるメモリの合計サイズに上限を設けます。
- カスタムの`instructions`はデフォルトのメモリ指示を置き換えるものであり、主に`validKeys`と併用すると役立ちます。
- ロールごとに、メモリの権限（使用、作成、読み取り、更新、オプトアウト）によってアクセスを制御することもできます。[`interface.memories`](/docs/configuration/librechat_yaml/object_structure/interface#memories)、[管理パネル](/docs/features/admin_panel)、またはメモリパネル下部の管理者設定を参照してください。

## トラブルシューティング [#troubleshooting]

**メモリが機能しない。** `memory` セクションが存在し、`disabled` が `true` になっていないこと、ユーザーのロールにメモリを使用する権限があること、そしてユーザーが **Reference saved memories** をオフにしていないことを確認してください。メモリツールについては、エージェントエンドポイントの `capabilities` リストを設定している場合、そのリストに `memory` 機能が含まれている必要があります。

**何も自動的には保存されません。** 自動抽出には `agent.enabled: true` と有効な `id`、または `provider` と `model` が必要です。これらがない場合、エントリは、Memory ツールが有効な状態でユーザーがモデルに何かを覚えるよう依頼した場合、または手動で追加した場合にのみ保存されます。

**カスタムエンドポイントでメモリーエージェントが失敗する場合。** `provider` はカスタムエンドポイントの `name` と完全に一致している必要があります。まず、そのエンドポイントが通常のチャットで動作することを確認してください。次に、そのヘッダーが参照している環境変数が設定されているかを確認してください。ヘッダーのプレースホルダーは、メモリーでもチャットと同じ方法で解決されます。

**トークン使用量が多い場合は、** メモリエージェントに送信するチャット量を減らすために `maxInputTokens` または `messageWindowSize` を下げてください。また、すべてのリクエストに追加される保存済みメモリを小さく保つために `tokenLimit` を下げ、`validKeys` を制限してください。
