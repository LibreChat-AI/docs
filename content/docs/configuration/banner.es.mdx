Muestre mensajes importantes a todos sus usuarios en la parte superior de la aplicación. Perfecto para anuncios, avisos de mantenimiento o actualizaciones.

<Callout type="info" title="Resumen rápido">
  - Solo puede haber **un banner** activo a la vez
  - Programar banners para que aparezcan y desaparezcan automáticamente
  - Elija si los usuarios pueden descartar el banner o no
  - Mostrar banners a todos, o solo a los usuarios que han iniciado sesión
</Callout>

---

## Crear un banner [#creating-a-banner]

Ejecuta este comando para crear o actualizar un banner:

```bash
npm run update-banner
```

Con Docker, ejecuta el script dentro del contenedor `api` en su lugar:

```bash
docker compose exec api npm run update-banner
```

Se le guiará a través de unas cuantas instrucciones sencillas:

```ansi
--------------------------
Update the banner!
--------------------------
Display From (Format: yyyy-mm-ddTHH:MM:SSZ, Default: now):
> 2025-12-02T09:00:00Z

Display To (Format: yyyy-mm-ddTHH:MM:SSZ, Default: not specified):
> 2025-12-31T23:59:59Z

Enter your message (Enter a single dot "." on a new line to finish):
> 🎉 Welcome to LibreChat! Check out our new features.
> .

Is public (y/N):
> n

Is persistable (cannot be dismissed) (y/N):
> n
```

<Callout type="tip" title="¿Qué significan estas opciones?">
  - **Mostrar desde/hasta**: Cuándo debe aparecer y desaparecer el banner. Presione Enter en el mensaje para usar "now" y "forever"
  - **Es público**: Mostrar a los visitantes que no han iniciado sesión (como en la página de inicio de sesión)
  - **Es persistible**: Si es así, los usuarios no pueden descartar el banner (úselo para avisos importantes)
</Callout>

<Callout type="warning" title="Ejecutar esto de nuevo reemplaza el banner existente">

Solo puede haber un banner a la vez. `update-banner` busca un banner existente y lo sobrescribe en el mismo lugar, creando uno solo cuando no existe ninguno, por lo que no puedes poner en cola un segundo banner para una fecha posterior, y no puedes tener dos ventanas programadas que se superpongan. Ejecutar el comando de nuevo descarta el mensaje y la programación del banner anterior.

Para cambiar un banner, ejecute `update-banner` de nuevo. Para retirar uno antes de su tiempo de `Display To`, utilice `delete-banner` a continuación.

</Callout>

## Eliminación de un banner [#deleting-a-banner]

```bash
npm run delete-banner
```

Con Docker, ejecuta `docker compose exec api npm run delete-banner`.

Verás el banner actual y se te pedirá que confirmes antes de eliminar.

<Callout type="warning" title="Solo se puede eliminar un banner activo">

`delete-banner` solo encuentra un banner que esté actualmente activo: su hora de `Display From` debe haber pasado, y su hora de `Display To` debe estar en el futuro o no estar definida. Un banner programado para una fecha posterior, o cuyo `Display To` ya haya pasado, se informa como "No banner found to delete" y permanece en la base de datos. Para reemplazar un banner de este tipo, ejecuta `update-banner` de nuevo.

</Callout>

Eliminar un banner de esta manera es también la forma en que se retira antes de tiempo: no existe una bandera de "deshabilitar". De lo contrario, un banner desaparece por sí solo una vez que pasa la fecha de `Display To`, y uno guardado sin `Display To` permanece visible hasta que lo eliminas.

## Banners de ejemplo [#example-banners]

<Tabs items={['Mensaje de bienvenida', 'Aviso de mantenimiento', 'Alerta de seguridad']}>
  <Tabs.Tab>
    Un mensaje de bienvenida sencillo que los usuarios pueden descartar:

    ```bash
    npm run update-banner "" "" "👋 Welcome to LibreChat!" "false" "false"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Un aviso de mantenimiento programado que no se puede descartar:

    ```bash
    npm run update-banner "2025-12-20T00:00:00Z" "2025-12-21T06:00:00Z" "⚠️ Scheduled maintenance on Dec 20th, 2-6 AM UTC" "true" "true"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Un aviso de seguridad urgente visible para todos:

    ```bash
    npm run update-banner "" "" "🔒 Please update your password by January 1st" "true" "true"
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="info" title="Los argumentos de fecha vacíos aún muestran el aviso">

Una cadena vacía (`""`) para una fecha se trata como ausente, por lo que el script seguirá pidiendo `Display From` y `Display To` de forma interactiva. Pulse Enter en cada pregunta para aceptar el valor predeterminado, o pase fechas ISO (`yyyy-mm-ddTHH:MM:SSZ`) como los dos primeros argumentos para ejecutar el comando sin preguntas. El argumento del mensaje también es obligatorio para omitir la pregunta del mensaje, y los argumentos `isPublic` y `persistable` deben indicarse como `true` o `false` para omitir sus respectivas preguntas.

</Callout>

## Formato de fecha [#date-format]

Utilice este formato para las fechas: `yyyy-mm-ddTHH:MM:SSZ`

**Ejemplos:**
- `2025-12-25T09:00:00Z` → 25 de diciembre de 2025 a las 9:00 AM (UTC)
- `2025-01-01T00:00:00Z` → 1 de enero de 2025 a medianoche (UTC)

Cuando se le solicite, presione Enter sin escribir una fecha para usar la hora actual en `Display From`, o sin fecha de fin para `Display To`.
