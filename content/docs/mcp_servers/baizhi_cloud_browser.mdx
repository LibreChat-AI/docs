[Baizhi Cloud Browser](https://baizhibrowser.cloud/), also known as CapyBrowser, provides hosted MCP tools for cloud browser runs, saved browser state, human handoff, and downloads. Its management MCP does not navigate or click pages: your agent also needs a separate compatible CDP client for page actions.

This guide adds an optional remote server to an existing LibreChat deployment. No local browser-service package or OAuth setup is needed.

## Prerequisites

- A running LibreChat instance that loads `librechat.yaml`.
- A browser-service key obtained through the provider's [setup guide](https://capybrowser.app.baizhi.cloud/docs/installation.md).
- Permission to change your LibreChat deployment's configuration.

Baizhi Cloud Browser and Baizhi Cloud Agent Toolkit are separate services. Check which service a key authorizes; do not assume a Toolkit application key applies to the browser.

## Configure a per-user connection

Merge this entry into the existing `mcpServers` map in `librechat.yaml`. Preserve other servers; if this name already exists, inspect that entry before changing it.

```yaml filename="librechat.yaml"
mcpServers:
  baizhi-cloud-browser:
    type: streamable-http
    url: https://capybrowser.app.baizhi.cloud/mcp
    startup: false
    requiresOAuth: false
    headers:
      Authorization: 'Bearer {{BAIZHI_BROWSER_API_KEY}}'
    customUserVars:
      BAIZHI_BROWSER_API_KEY:
        title: Baizhi Cloud Browser key
        description: Enter your complete browser-service key, without the Bearer prefix.
        sensitive: true
```

`customUserVars` keeps the key specific to the user connecting the server. Do not replace it with a shared deployment credential on a multi-user instance. `requiresOAuth: false` selects the configured Bearer credential instead of OAuth detection. `startup: false` avoids connecting this entry during application startup.

If your deployment uses `mcpSettings.allowedDomains`, add `capybrowser.app.baizhi.cloud` to its existing list. Restart LibreChat to reload the configuration.

## Connect and check discovery

1. Open **MCP Settings** or the composer's **+** palette and find **MCP Servers**.
2. Connect `baizhi-cloud-browser` and enter your complete key in the **Baizhi Cloud Browser key** field. Enter the key alone: the configuration adds `Bearer` and the required space. The resulting header is `Authorization: Bearer YOUR_KEY`, not just `Bearer` or `Authorization=Bearer`.
3. Inspect the discovered tools. Discovery checks the connection; it does not establish that every tool is permitted or that a complete browser task works.
4. Before agent use, review tool permissions. Keep confirmation for tools that create runs, change state, or incur charges. If you only need an initial read-only account check, use `browser_auth_check`; do not create a run to test authentication.

Browser startup and runtime are billed. Check your account and current prices before creating a run. The service receives tool inputs; page actions also reach the sites you visit. Review the provider's terms and privacy information before use.

## Rotate credentials and stop using the connection

Disconnect this server before replacing its saved per-user key in MCP Settings. Reconnect and inspect discovery after saving the replacement. To remove the deployment entry, remove only `mcpServers.baizhi-cloud-browser` and reload LibreChat; preserve other entries. Removing the local connection does not revoke the provider key.

Disconnecting the MCP server or closing LibreChat does not end cloud browser runs or stop their billing. Explicitly end the runs you created through the browser service's tools or [console](https://capybrowser.app.baizhi.cloud/). Check resource release and final charges separately. During a human handoff, pause agent actions and resume the same run after control returns.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Authentication fails | Confirm the exact `/mcp` URL, key applicability, and complete key. Keep one `Bearer` prefix and one space. |
| LibreChat tries OAuth | Keep `requiresOAuth: false` on this static Bearer configuration and reload it. |
| Requests are blocked by domain policy | Extend the existing `mcpSettings.allowedDomains` list with the provider host. |
| Management tools appear, but page navigation is unavailable | Add a separate compatible CDP client; this guide only configures management MCP. |
| A cloud run remains active after disconnecting | End your own run in the browser service; client disconnection is not run termination. |

See [MCP configuration](/docs/configuration/librechat_yaml/object_structure/mcp_servers) for other connection options.
