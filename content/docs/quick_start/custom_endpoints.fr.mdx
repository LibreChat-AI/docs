title: Endpoints personnalisés
icon: Plug
description: >-
  Ajoutez des fournisseurs d'IA personnalisés comme OpenRouter, Ollama et des
  passerelles compatibles avec Anthropic à LibreChat en utilisant librechat.yaml
---

LibreChat prend en charge les services compatibles avec l'API OpenAI en tant qu'endpoints personnalisés. Il prend également en charge les endpoints personnalisés compatibles avec Anthropic avec `provider: "anthropic"`. Vous configurez les endpoints dans `librechat.yaml`, stockez les clés API dans `.env` et montez la configuration via `docker-compose.override.yml` pour les déploiements Docker.

<Callout type="info" title="Quel fichier fait quoi ?">

La configuration d'un endpoint personnalisé implique trois fichiers, chacun ayant un rôle spécifique :

1. **`librechat.yaml`** -- Définit vos endpoints personnalisés (nom, URL de l'API, modèles, paramètres d'affichage)
2. **`.env`** -- Stocke les valeurs sensibles telles que les clés API (référencées depuis librechat.yaml en utilisant la syntaxe `${VAR_NAME}`)
3. **`docker-compose.override.yml`** -- Monte `librechat.yaml` dans le conteneur Docker (utilisateurs Docker uniquement)

Pour un aperçu complet de la manière dont ces fichiers fonctionnent ensemble, consultez la [Configuration Overview](/docs/configuration).

</Callout>

<Callout type="warning" title="Avant de commencer">

Ce guide suppose que vous avez LibreChat installé et en cours d'exécution. Si ce n'est pas le cas, terminez d'abord l'installation avec [Docker setup](/docs/local/docker).

</Callout>

## Étape 1. Monter librechat.yaml (Docker uniquement) [#step-1-mount-librechatyaml-docker-only]

Les utilisateurs de Docker doivent monter `librechat.yaml` en tant que volume afin que le conteneur puisse le lire. Ignorez cette étape si vous exécutez LibreChat localement sans Docker.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Modifiez `docker-compose.override.yml` et assurez-vous que le montage de volume est décommenté :

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

En savoir plus : [Guide de remplacement Docker](/docs/configuration/docker_override)

## Étape 2. Configurer librechat.yaml [#step-2-configure-librechatyaml]

Créez un fichier `librechat.yaml` à la racine du projet (s'il n'existe pas) et ajoutez votre configuration d'endpoint. Consultez le [guide librechat.yaml](/docs/configuration/librechat_yaml) pour des instructions de configuration détaillées.

Voici un exemple avec **OpenRouter**, **Ollama** et une passerelle compatible Anthropic :

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

Parcourez tous les fournisseurs compatibles dans la section [AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints). Pour la référence complète des champs, consultez [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

<Callout type="note" title="Endpoints compatibles avec Anthropic">

Utilisez `provider: "anthropic"` uniquement pour les endpoints qui utilisent l'API native Anthropic Messages. Pour les passerelles compatibles OpenAI qui exposent simplement des modèles Anthropic, omettez `provider` et utilisez la structure d'endpoint personnalisé compatible OpenAI standard.

</Callout>

<Callout type="warning" title="Configuration de la clé API">

Lors de la configuration des clés API dans les endpoints personnalisés, vous avez trois options :

1. **Variable d'environnement** (recommandé) : `apiKey: '${OPENROUTER_KEY}'` lit une clé partagée depuis `.env`, la clé doit donc avoir une entrée correspondante dans [Step 3](#step-3-set-environment-variables).
2. `apiKey: 'user_provided'` demande à chaque utilisateur sa propre clé dans l'interface utilisateur de LibreChat au lieu d'en lire une depuis `.env`. Aucune entrée `.env` n'est nécessaire pour la clé elle-même. LibreChat stocke la clé de chaque utilisateur de manière chiffrée et la demande la première fois qu'ils sélectionnent l'endpoint.
3. **Valeur directe** (non recommandé) : `apiKey: 'sk-your-actual-key'` code la clé en dur dans `librechat.yaml` en texte brut.

`baseURL` accepte `user_provided` de la même manière, ce qui permet à chaque utilisateur de pointer l'endpoint vers sa propre passerelle.

L'exemple ci-dessus mélange délibérément les styles : OpenRouter et la passerelle compatible Anthropic utilisent l'option 1, tandis qu'Ollama transmet la chaîne littérale `'ollama'` car un serveur Ollama local ignore totalement la clé.

</Callout>

## Étape 3. Définir les variables d'environnement [#step-3-set-environment-variables]

Cette étape couvre chaque référence `${VARIABLE_NAME}` dans votre `librechat.yaml`, qu'elle se trouve dans une valeur `apiKey`, `baseURL` ou `headers`. Si rien de ce que vous avez ajouté n'utilise cette forme, passez à l'[étape 4](#step-4-restart-and-verify).

Ajoutez chaque variable référencée dans votre `librechat.yaml` au fichier `.env`. L'exemple ci-dessus en référence deux :

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

Chaque `${VARIABLE_NAME}` dans `librechat.yaml` nécessite une entrée correspondante. Une entrée manquante ne supprime pas l'endpoint : il apparaît toujours dans le sélecteur, et le problème ne survient que lorsqu'un utilisateur envoie un message via celui-ci. Une `apiKey` non résolue échoue avec `Missing API Key for <endpoint>`, et une `baseURL` non résolue avec `Missing Base URL for <endpoint>`. Une valeur `headers` non résolue se comporte différemment : elle est envoyée en amont sous forme de texte littéral `${VARIABLE_NAME}`, l'échec provient donc du fournisseur plutôt que de LibreChat.

## Étape 4. Redémarrer et vérifier [#step-4-restart-and-verify]

Après avoir modifié les fichiers de configuration, vous devez redémarrer LibreChat pour que les changements prennent effet.

<Tabs items={['Docker', 'Local']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

Arrêtez le processus en cours (Ctrl+C) et redémarrez :

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

Ouvrez LibreChat dans votre navigateur. Vos endpoints personnalisés devraient apparaître dans le menu déroulant de sélection des endpoints.

<Callout type="warning" title="Vous ne voyez pas votre endpoint ? Un bloc incomplet est ignoré silencieusement">

Commencez par les journaux du serveur :

```bash
docker compose logs api
```

**Mais ne vous arrêtez pas là.** LibreChat ne conserve un endpoint personnalisé que si `name`, `baseURL`, `apiKey` et `models` sont tous présents, et que `models` possède soit `fetch: true`, soit une liste `default` non vide. Une entrée ne satisfaisant pas cette vérification est supprimée de la liste des endpoints **sans erreur et sans aucune ligne de journal** : le fournisseur n'apparaît tout simplement jamais, et les journaux semblent propres.

Donc, lorsqu'un endpoint est manquant, vérifiez le bloc lui-même avant de chercher dans les logs :

- `name`, `baseURL`, `apiKey` et `models` sont-ils tous orthographiés correctement ? Une seule faute de frappe invalide l'entrée entière.
- `models` a-t-il `fetch: true` ou au moins une entrée sous `default` ?
- Le bloc est-il indenté **à l'intérieur** de la liste `endpoints.custom`, plutôt qu'au niveau racine ?
- Le `name` est-il unique ? Un second endpoint portant le même nom (sans distinction de casse) remplace silencieusement le premier.

Comparez votre bloc avec la référence [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

Notez également qu'une erreur de schéma **n'importe où** dans `librechat.yaml` arrête le serveur plutôt que de désactiver une seule section ; ainsi, un bloc incorrect ailleurs peut entraîner la mise hors service de tous les endpoint personnalisés. Validez la syntaxe avec le [YAML Validator](/docs/toolkit/yaml-validator), qui vérifie uniquement la syntaxe YAML, et non le schéma de LibreChat.

</Callout>

### OpenRouter ne s'affiche toujours pas [#openrouter-still-does-not-show-up]

Pour OpenRouter spécifiquement, vérifiez la chaîne de trois fichiers :

1. `.env` contient `OPENROUTER_KEY=...`
2. `librechat.yaml` contient `apiKey: "${OPENROUTER_KEY}"` sous l'endpoint personnalisé OpenRouter
3. Les utilisateurs de Docker ont monté `librechat.yaml` dans `docker-compose.override.yml`

Ensuite, redémarrez avec :

```bash
docker compose down && docker compose up -d
```

Si le endpoint apparaît mais renvoie `402 Payment Required`, la requête a bien atteint OpenRouter et le problème est généralement lié aux crédits du compte, à la facturation ou à la disponibilité du modèle sur OpenRouter.
