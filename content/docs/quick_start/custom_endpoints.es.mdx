LibreChat admite servicios compatibles con la API de OpenAI como endpoints personalizados. También admite endpoints personalizados compatibles con Anthropic con `provider: "anthropic"`. Los endpoints se configuran en `librechat.yaml`, las claves de API se almacenan en `.env` y la configuración se monta a través de `docker-compose.override.yml` para implementaciones en Docker.

<Callout type="info" title="¿Qué archivo hace qué?">

La configuración de un endpoint personalizado implica tres archivos, cada uno con una función específica:

1. **`librechat.yaml`** -- Define sus endpoints personalizados (nombre, URL de la API, modelos, ajustes de visualización)
2. **`.env`** -- Almacena valores sensibles como claves de API (referenciados desde librechat.yaml usando la sintaxis `${VAR_NAME}`)
3. **`docker-compose.override.yml`** -- Monta `librechat.yaml` en el contenedor de Docker (solo para usuarios de Docker)

Para obtener una visión general completa de cómo funcionan estos archivos en conjunto, consulte la [Configuration Overview](/docs/configuration).

</Callout>

<Callout type="warning" title="Antes de empezar">

Esta guía asume que tienes LibreChat instalado y en funcionamiento. Si no es así, completa primero la [configuración de Docker](/docs/local/docker).

</Callout>

## Paso 1. Montar librechat.yaml (Solo Docker) [#step-1-mount-librechatyaml-docker-only]

Los usuarios de Docker necesitan montar `librechat.yaml` como un volumen para que el contenedor pueda leerlo. Omita este paso si está ejecutando LibreChat localmente sin Docker.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Edite `docker-compose.override.yml` y asegúrese de que el montaje del volumen no esté comentado:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Más información: [Guía de anulación de Docker](/docs/configuration/docker_override)

## Paso 2. Configurar librechat.yaml [#step-2-configure-librechatyaml]

Cree un archivo `librechat.yaml` en la raíz del proyecto (si no existe) y añada su configuración de endpoint. Consulte la [guía de librechat.yaml](/docs/configuration/librechat_yaml) para obtener instrucciones de configuración detalladas.

Aquí hay un ejemplo con **OpenRouter**, **Ollama** y una pasarela compatible con Anthropic:

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

Explore todos los proveedores compatibles en la sección de [AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints). Para obtener la referencia completa de los campos, consulte [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

<Callout type="note" title="Endpoints compatibles con Anthropic">

Utilice `provider: "anthropic"` solo para endpoints que utilicen la API nativa de Anthropic Messages. Para gateways compatibles con OpenAI que simplemente exponen modelos de Anthropic, omita `provider` y utilice la estructura de endpoint personalizado compatible con OpenAI estándar.

</Callout>

<Callout type="warning" title="Configuración de la API Key">

Al configurar claves de API en endpoints personalizados, tienes tres opciones:

1. **Variable de entorno** (recomendado): `apiKey: '${OPENROUTER_KEY}'` lee una clave compartida desde `.env`, por lo que la clave necesita una entrada coincidente en [Step 3](#step-3-set-environment-variables).
2. `apiKey: 'user_provided'` solicita a cada usuario su propia clave en la interfaz de usuario de LibreChat en lugar de leerla desde `.env`. No se necesita ninguna entrada en `.env` para la clave en sí. LibreChat almacena la clave de cada usuario cifrada y la solicita la primera vez que seleccionan el endpoint.
3. **Valor directo** (no recomendado): `apiKey: 'sk-your-actual-key'` codifica la clave de forma rígida en `librechat.yaml` en texto plano.

`baseURL` acepta `user_provided` de la misma manera, lo que permite a cada usuario apuntar el endpoint a su propia puerta de enlace (gateway).

El ejemplo anterior mezcla estilos deliberadamente: OpenRouter y la pasarela compatible con Anthropic utilizan la opción 1, mientras que Ollama pasa la cadena literal `'ollama'` porque un servidor local de Ollama ignora la clave por completo.

</Callout>

## Paso 3. Configurar variables de entorno [#step-3-set-environment-variables]

Este paso cubre cada referencia `${VARIABLE_NAME}` en tu `librechat.yaml`, ya sea que se encuentre en `apiKey`, `baseURL` o en un valor de `headers`. Si nada de lo que agregaste utiliza ese formato, salta al [Step 4](#step-4-restart-and-verify).

Agregue cada variable a la que hace referencia su `librechat.yaml` en `.env`. El ejemplo anterior hace referencia a dos:

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

Cada `${VARIABLE_NAME}` en `librechat.yaml` necesita una entrada correspondiente. Si falta una, el endpoint no se elimina: sigue apareciendo en el selector y el problema solo surge una vez que alguien envía un mensaje a través de él. Un `apiKey` no resuelto falla con `Missing API Key for <endpoint>`, y un `baseURL` no resuelto con `Missing Base URL for <endpoint>`. Un valor de `headers` no resuelto se comporta de manera diferente: se envía al proveedor como el texto literal `${VARIABLE_NAME}`, por lo que el error proviene del proveedor en lugar de LibreChat.

## Paso 4. Reiniciar y verificar [#step-4-restart-and-verify]

Después de editar los archivos de configuración, debes reiniciar LibreChat para que los cambios surtan efecto.

<Tabs items={['Docker', 'Local']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

Detenga el proceso en ejecución (Ctrl+C) y reinicie:

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

Abre LibreChat en tu navegador. Tus endpoints personalizados deberían aparecer en el menú desplegable del selector de endpoint.

<Callout type="warning" title="¿No ves tu endpoint? Un bloque incompleto se descarta silenciosamente">

Comience con los registros del servidor:

```bash
docker compose logs api
```

**Pero no se detenga ahí.** LibreChat mantiene un endpoint personalizado solo si `name`, `baseURL`, `apiKey` y `models` están presentes, y `models` tiene `fetch: true` o una lista `default` no vacía. Una entrada que no cumpla con esa verificación se elimina de la lista de endpoints **sin error y sin ninguna línea de registro**: el proveedor simplemente nunca aparece y los registros se ven limpios.

Así que cuando falte un endpoint, revisa el bloque en sí antes de buscar en los logs:

- ¿Están `name`, `baseURL`, `apiKey` y `models` escritos correctamente? Un solo error tipográfico invalida toda la entrada.
- ¿Tiene `models` configurado `fetch: true` o al menos una entrada bajo `default`?
- ¿Está el bloque sangrado **dentro** de la lista `endpoints.custom`, en lugar de estar en el nivel superior?
- ¿Es el `name` único? Un segundo endpoint con el mismo nombre (sin distinguir entre mayúsculas y minúsculas) reemplaza silenciosamente al primero.

Compara tu bloque con la referencia de [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

Ten en cuenta también que un error de esquema en **cualquier parte** de `librechat.yaml` detiene el servidor en lugar de deshabilitar una sola sección, por lo que un bloque incorrecto en otro lugar puede hacer que todos los endpoint personalizados dejen de funcionar. Valida la sintaxis con el [YAML Validator](/docs/toolkit/yaml-validator), el cual verifica solo la sintaxis YAML, no el esquema de LibreChat.

</Callout>

### OpenRouter aún no aparece [#openrouter-still-does-not-show-up]

Para OpenRouter específicamente, verifique la cadena de tres archivos:

1. `.env` tiene `OPENROUTER_KEY=...`
2. `librechat.yaml` tiene `apiKey: "${OPENROUTER_KEY}"` bajo el endpoint personalizado de OpenRouter
3. Los usuarios de Docker montaron `librechat.yaml` en `docker-compose.override.yml`

Luego reinicia con:

```bash
docker compose down && docker compose up -d
```

Si el endpoint aparece pero devuelve `402 Payment Required`, la solicitud llegó a OpenRouter correctamente y el problema suele estar relacionado con los créditos de la cuenta, la facturación o la disponibilidad del modelo en OpenRouter.
