LibreChat은 OpenAI API 호환 서비스를 사용자 지정 endpoint로 지원합니다. 또한 `provider: "anthropic"`을 사용하여 Anthropic 호환 사용자 지정 endpoint도 지원합니다. `librechat.yaml`에서 endpoint를 구성하고, `.env`에 API 키를 저장하며, Docker 배포를 위해 `docker-compose.override.yml`을 통해 구성을 마운트합니다.

<Callout type="info" title="어떤 파일이 어떤 역할을 하나요?">

Custom endpoint 설정에는 각각 고유한 역할을 하는 세 개의 파일이 포함됩니다:

1. **`librechat.yaml`** -- 사용자 지정 endpoint(이름, API URL, 모델, 표시 설정)를 정의합니다.
2. **`.env`** -- API 키와 같은 민감한 값을 저장합니다 (librechat.yaml에서 `${VAR_NAME}` 구문을 사용하여 참조).
3. **`docker-compose.override.yml`** -- `librechat.yaml`을 Docker 컨테이너에 마운트합니다 (Docker 사용자 전용)

이 파일들이 어떻게 함께 작동하는지에 대한 전체적인 개요는 [Configuration Overview](/docs/configuration)를 참조하세요.

</Callout>

<Callout type="warning" title="시작하기 전에">

이 가이드는 LibreChat이 설치되어 실행 중이라고 가정합니다. 그렇지 않은 경우, 먼저 [Docker setup](/docs/local/docker)을 완료하세요.

</Callout>

## Step 1. librechat.yaml 마운트하기 (Docker 전용) [#step-1-mount-librechatyaml-docker-only]

Docker 사용자는 컨테이너가 `librechat.yaml`을 읽을 수 있도록 볼륨으로 마운트해야 합니다. Docker 없이 LibreChat을 로컬에서 실행 중이라면 이 단계를 건너뛰십시오.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

`docker-compose.override.yml` 파일을 수정하고 볼륨 마운트의 주석 처리가 해제되어 있는지 확인하세요:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

더 알아보기: [Docker Override Guide](/docs/configuration/docker_override)

## 2단계. librechat.yaml 구성하기 [#step-2-configure-librechatyaml]

프로젝트 루트에 `librechat.yaml` 파일이 없다면 생성하고, 해당 파일에 endpoint 구성을 추가하세요. 자세한 설정 방법은 [librechat.yaml 가이드](/docs/configuration/librechat_yaml)를 참조하세요.

다음은 **OpenRouter**, **Ollama** 및 Anthropic 호환 게이트웨이를 사용한 예시입니다:

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

[AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints) 섹션에서 호환되는 모든 제공업체를 살펴보세요. 전체 필드 참조는 [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint)를 확인하세요.

<Callout type="note" title="Anthropic 호환 endpoint">

`provider: "anthropic"`은 Anthropic Messages API를 기본적으로 지원하는 엔드포인트에만 사용하세요. Anthropic 모델을 단순히 노출하는 OpenAI 호환 게이트웨이의 경우, `provider`를 생략하고 일반적인 OpenAI 호환 커스텀 엔드포인트 형식을 사용하세요.

</Callout>

<Callout type="warning" title="API 키 구성">

사용자 지정 endpoint에서 API 키를 구성할 때, 세 가지 옵션이 있습니다:

1. **환경 변수** (권장): `apiKey: '${OPENROUTER_KEY}'`는 `.env`에서 하나의 공유 키를 읽어오므로, 해당 키는 [3단계](#step-3-set-environment-variables)에 일치하는 항목이 있어야 합니다.
2. `apiKey: 'user_provided'`는 `.env`에서 키를 읽는 대신 LibreChat UI에서 각 사용자에게 자신의 키를 입력하도록 요청합니다. 키 자체에 대한 `.env` 항목은 필요하지 않습니다. LibreChat은 각 사용자의 키를 암호화하여 저장하며, 사용자가 해당 endpoint를 처음 선택할 때 키를 입력하라는 메시지를 표시합니다.
3. **직접 값 입력** (권장하지 않음): `apiKey: 'sk-your-actual-key'`는 `librechat.yaml`에 키를 일반 텍스트로 하드코딩합니다.

`baseURL`도 동일한 방식으로 `user_provided`를 허용하며, 이를 통해 각 사용자가 엔드포인트를 자신의 게이트웨이로 지정할 수 있습니다.

위의 예시는 의도적으로 스타일을 혼합했습니다. OpenRouter와 Anthropic 호환 게이트웨이는 옵션 1을 사용하지만, Ollama는 로컬 Ollama 서버가 해당 키를 완전히 무시하기 때문에 리터럴 문자열 `'ollama'`를 전달합니다.

</Callout>

## 3단계. 환경 변수 설정 [#step-3-set-environment-variables]

이 단계에서는 `apiKey`, `baseURL`, 또는 `headers` 값에 위치하든 상관없이 `librechat.yaml` 내의 모든 `${VARIABLE_NAME}` 참조를 다룹니다. 추가한 내용 중 해당 형식을 사용하는 것이 없다면 [4단계](#step-4-restart-and-verify)로 건너뛰십시오.

`librechat.yaml`에서 참조하는 각 변수를 `.env`에 추가하세요. 위의 예시에서는 두 가지를 참조합니다:

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

`librechat.yaml` 내의 모든 `${VARIABLE_NAME}`에는 일치하는 항목이 필요합니다. 항목이 누락되어도 엔드포인트가 삭제되지는 않습니다. 선택기에는 여전히 나타나며, 누군가 해당 엔드포인트를 통해 메시지를 보낼 때만 문제가 발생합니다. 해결되지 않은 `apiKey`는 `Missing API Key for <endpoint>` 오류를 발생시키며, 해결되지 않은 `baseURL`은 `Missing Base URL for <endpoint>` 오류를 발생시킵니다. 해결되지 않은 `headers` 값은 다르게 동작합니다. 해당 값은 리터럴 텍스트 `${VARIABLE_NAME}`로 업스트림에 전송되므로, 오류는 LibreChat이 아닌 공급자로부터 반환됩니다.

## 4단계. 재시작 및 확인 [#step-4-restart-and-verify]

구성 파일을 편집한 후에는 변경 사항을 적용하기 위해 LibreChat을 다시 시작해야 합니다.

<Tabs items={['Docker', '로컬']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

실행 중인 프로세스를 중단하고(Ctrl+C) 다시 시작하세요:

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

브라우저에서 LibreChat을 엽니다. 사용자 지정 endpoint가 endpoint 선택 드롭다운에 나타나야 합니다.

<Callout type="warning" title="엔드포인트가 보이지 않나요? 불완전한 블록은 조용히 삭제됩니다">

서버 로그부터 확인하세요:

```bash
docker compose logs api
```

**하지만 여기서 멈추지 마십시오.** LibreChat은 `name`, `baseURL`, `apiKey`, `models`가 모두 존재하고, `models`에 `fetch: true`가 설정되어 있거나 비어 있지 않은 `default` 목록이 있는 경우에만 사용자 지정 endpoint를 유지합니다. 해당 검사를 통과하지 못한 항목은 **오류나 로그 기록 없이** endpoint 목록에서 제거됩니다. 즉, 해당 공급자(provider)가 단순히 나타나지 않으며 로그는 깨끗하게 유지됩니다.

따라서 endpoint가 누락된 경우, 로그를 뒤지기 전에 해당 블록 자체를 먼저 확인하세요:

- `name`, `baseURL`, `apiKey`, `models`의 철자가 모두 정확한가요? 오타가 하나라도 있으면 해당 항목 전체가 작동하지 않습니다.
- `models`에 `fetch: true`가 설정되어 있거나 `default` 아래에 최소 하나의 항목이 있나요?
- 해당 블록이 최상위 레벨이 아닌 `endpoints.custom` 리스트 **내부**에 들여쓰기 되어 있나요?
- `name`은 고유한가요? 동일한 이름(대소문자 구분 없음)을 가진 두 번째 endpoint는 첫 번째 endpoint를 자동으로 대체합니다.

[Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) 참조를 통해 귀하의 블록을 비교해 보세요.

또한 `librechat.yaml`의 **어느 곳에서든** 스키마 오류가 발생하면 특정 섹션만 비활성화되는 것이 아니라 서버가 중단되므로, 다른 곳의 잘못된 블록 하나가 모든 커스텀 endpoint를 다운시킬 수 있다는 점을 유의하세요. [YAML Validator](/docs/toolkit/yaml-validator)를 사용하여 구문을 검증하세요. 이 도구는 LibreChat의 스키마가 아닌 YAML 구문만 확인합니다.

</Callout>

### OpenRouter가 여전히 표시되지 않음 [#openrouter-still-does-not-show-up]

OpenRouter의 경우, 특히 다음 세 파일 체인을 확인하세요:

1. `.env` 파일에 `OPENROUTER_KEY=...`가 있습니다.
2. `librechat.yaml`의 OpenRouter 커스텀 endpoint 아래에는 `apiKey: "${OPENROUTER_KEY}"`가 있습니다.
3. Docker 사용자는 `docker-compose.override.yml`에서 `librechat.yaml`을 마운트했습니다.

그런 다음 다음 명령어로 재시작하세요:

```bash
docker compose down && docker compose up -d
```

endpoint가 나타나지만 `402 Payment Required`를 반환한다면, 요청이 OpenRouter에 성공적으로 도달한 것이며, 문제는 일반적으로 OpenRouter의 계정 크레딧, 결제 또는 모델 가용성과 관련이 있습니다.
