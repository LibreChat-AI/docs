LibreChatは、OpenAI API互換サービスをカスタムendpointとしてサポートしています。また、`provider: "anthropic"` を指定することで、Anthropic互換のカスタムendpointもサポートしています。endpointの設定は `librechat.yaml` で行い、APIキーは `.env` に保存し、Dockerデプロイメントの場合は `docker-compose.override.yml` を介して設定をマウントします。

<Callout type="info" title="どのファイルが何をするのか？">

Custom endpointの設定には、それぞれ特定の役割を持つ3つのファイルが必要です。

1. **`librechat.yaml`** -- カスタムエンドポイント（名前、API URL、モデル、表示設定）を定義します。
2. **`.env`** -- APIキーなどの機密情報を保存します（librechat.yaml から `${VAR_NAME}` 構文を使用して参照されます）
3. **`docker-compose.override.yml`** -- `librechat.yaml` を Docker コンテナにマウントします（Docker ユーザーのみ）

これらのファイルがどのように連携するかの全体像については、[Configuration Overview](/docs/configuration) を参照してください。

</Callout>

<Callout type="warning" title="始める前に">

このガイドは、LibreChatがインストールされ、実行されていることを前提としています。まだの場合は、先に[Docker setup](/docs/local/docker)を完了してください。

</Callout>

## Step 1. librechat.yaml をマウントする (Docker のみ) [#step-1-mount-librechatyaml-docker-only]

Dockerユーザーは、コンテナが読み取れるように `librechat.yaml` をボリュームとしてマウントする必要があります。Dockerを使用せずにLibreChatをローカルで実行している場合は、この手順をスキップしてください。

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

`docker-compose.override.yml` を編集し、ボリュームマウントのコメントアウトが解除されていることを確認してください：

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

詳細はこちら: [Docker Override Guide](/docs/configuration/docker_override)

## ステップ 2. librechat.yaml の設定 [#step-2-configure-librechatyaml]

プロジェクトのルートディレクトリに `librechat.yaml` ファイルを作成し（存在しない場合）、endpoint の設定を追加してください。詳細なセットアップ手順については、[librechat.yaml ガイド](/docs/configuration/librechat_yaml) を参照してください。

以下は、**OpenRouter**、**Ollama**、および Anthropic 互換ゲートウェイを使用した例です：

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

互換性のあるすべてのプロバイダーについては、[AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints) セクションを参照してください。フィールドの完全なリファレンスについては、[Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) を参照してください。

<Callout type="note" title="Anthropic互換のendpoint">

`provider: "anthropic"` は、ネイティブの Anthropic Messages API を使用するエンドポイントに対してのみ使用してください。Anthropic のモデルを公開しているだけの OpenAI 互換ゲートウェイの場合は、`provider` を省略し、通常の OpenAI 互換カスタムエンドポイントの形式を使用してください。

</Callout>

<Callout type="warning" title="APIキーの設定">

カスタムエンドポイントでAPIキーを設定する場合、3つの選択肢があります：

1. **Environment variable**（推奨）: `apiKey: '${OPENROUTER_KEY}'` は `.env` から共有キーを1つ読み込むため、[Step 3](#step-3-set-environment-variables) でキーに対応するエントリが必要です。
2. `apiKey: 'user_provided'` は、`.env` から読み込む代わりに、LibreChat UI 上で各ユーザーに自身のキーの入力を求めます。キー自体に対して `.env` エントリは不要です。LibreChat は各ユーザーのキーを暗号化して保存し、ユーザーが初めてその endpoint を選択した際にキーの入力を促します。
3. **直接指定**（非推奨）: `apiKey: 'sk-your-actual-key'` は、`librechat.yaml` 内にキーをプレーンテキストでハードコードします。

`baseURL` も同様に `user_provided` を受け入れることができ、各ユーザーがエンドポイントを独自のゲートウェイに向けることが可能になります。

上記の例では、意図的にスタイルを混在させています。OpenRouterとAnthropic互換ゲートウェイはオプション1を使用していますが、OllamaはローカルのOllamaサーバーがキーを完全に無視するため、リテラル文字列 `'ollama'` を渡しています。

</Callout>

## Step 3. 環境変数の設定 [#step-3-set-environment-variables]

このステップでは、`apiKey`、`baseURL`、または `headers` 値のいずれにあるかにかかわらず、`librechat.yaml` 内のすべての `${VARIABLE_NAME}` 参照をカバーします。追加した項目でこの形式を使用していない場合は、[ステップ 4](#step-4-restart-and-verify) にスキップしてください。

`librechat.yaml` が参照する各変数を `.env` に追加します。上記の例では、以下の2つを参照しています。

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

`librechat.yaml` 内のすべての `${VARIABLE_NAME}` には、対応するエントリが必要です。エントリが欠落していてもエンドポイント自体は削除されず、セレクターには表示され続けますが、そのエンドポイントを通じて誰かがメッセージを送信した時点で問題が表面化します。解決されない `apiKey` は `Missing API Key for <endpoint>` というエラーになり、解決されない `baseURL` は `Missing Base URL for <endpoint>` というエラーになります。解決されない `headers` 値の挙動は異なり、リテラルテキスト `${VARIABLE_NAME}` としてアップストリームに送信されるため、エラーは LibreChat ではなくプロバイダー側から返されます。

## Step 4. 再起動と確認 [#step-4-restart-and-verify]

設定ファイルを編集した後は、変更を反映させるためにLibreChatを再起動する必要があります。

<Tabs items={['Docker', 'ローカル']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

実行中のプロセスを停止し (Ctrl+C)、再起動します:

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

ブラウザでLibreChatを開きます。カスタムendpointがendpointセレクターのドロップダウンに表示されるはずです。

<Callout type="warning" title="エンドポイントが表示されませんか？不完全なブロックは通知なく破棄されます">

サーバーログから開始します：

```bash
docker compose logs api
```

**しかし、そこで終わらせないでください。** LibreChatは、`name`、`baseURL`、`apiKey`、および `models` のすべてが存在し、かつ `models` に `fetch: true` または空ではない `default` リストが含まれている場合にのみ、カスタムendpointを保持します。このチェックに失敗したエントリは、**エラーやログ行が一切出力されることなく**endpointリストから削除されます。つまり、プロバイダーが表示されず、ログには何も異常がないように見えます。

そのため、endpointが見当たらない場合は、ログを詳しく調べる前にブロック自体を確認してください。

- `name`、`baseURL`、`apiKey`、`models` のスペルはすべて正しいですか？1文字でもタイプミスがあると、エントリ全体が無効になります。
- `models` に `fetch: true` が設定されているか、あるいは `default` の下に少なくとも1つのエントリが存在しますか？
- そのブロックはトップレベルではなく、`endpoints.custom` リストの**内側**にインデントされていますか？
- `name` は一意である必要がありますか？同じ名前（大文字と小文字を区別しない）を持つ2つ目の endpoint は、1つ目を警告なしに置き換えます。

[Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) リファレンスとブロックを比較してください。

また、`librechat.yaml` の**どこか**にスキーマエラーがあると、特定のセクションが無効になるのではなくサーバーが停止してしまうため、他の場所にある1つの不正なブロックがすべてのカスタム endpoint をダウンさせる可能性があることにも注意してください。構文の検証には [YAML Validator](/docs/toolkit/yaml-validator) を使用してください。ただし、これは YAML の構文のみをチェックするものであり、LibreChat のスキーマをチェックするものではありません。

</Callout>

### OpenRouter が表示されない場合 [#openrouter-still-does-not-show-up]

OpenRouterに関しては、特に以下の3つのファイルのチェーンを確認してください：

1. `.env` には `OPENROUTER_KEY=...` が含まれています。
2. `librechat.yaml` の OpenRouter カスタム endpoint 配下には `apiKey: "${OPENROUTER_KEY}"` が設定されています
3. Dockerユーザーは `docker-compose.override.yml` で `librechat.yaml` をマウントしました。

次に以下で再起動します：

```bash
docker compose down && docker compose up -d
```

endpointが表示されているにもかかわらず `402 Payment Required` が返される場合、リクエストはOpenRouterに正常に到達しています。この問題は通常、OpenRouter上のアカウントクレジット、請求、またはモデルの利用可能性に関連しています。
