O LibreChat oferece suporte a serviços compatíveis com a API da OpenAI como endpoints personalizados. Ele também oferece suporte a endpoints personalizados compatíveis com a Anthropic com `provider: "anthropic"`. Você configura os endpoints no `librechat.yaml`, armazena as chaves de API no `.env` e monta a configuração via `docker-compose.override.yml` para implantações Docker.

<Callout type="info" title="Qual arquivo faz o quê?">

A configuração de um endpoint personalizado envolve três arquivos, cada um com uma função específica:

1. **`librechat.yaml`** -- Define seus endpoints personalizados (nome, URL da API, modelos, configurações de exibição)
2. **`.env`** -- Armazena valores sensíveis como chaves de API (referenciados a partir do librechat.yaml usando a sintaxe `${VAR_NAME}`)
3. **`docker-compose.override.yml`** -- Monta o `librechat.yaml` no container Docker (apenas para usuários Docker)

Para uma visão geral completa de como esses arquivos funcionam em conjunto, consulte a [Visão Geral da Configuração](/docs/configuration).

</Callout>

<Callout type="warning" title="Antes de começar">

Este guia pressupõe que você tenha o LibreChat instalado e em execução. Caso contrário, conclua a [configuração do Docker](/docs/local/docker) primeiro.

</Callout>

## Passo 1. Monte o librechat.yaml (Apenas Docker) [#step-1-mount-librechatyaml-docker-only]

Usuários de Docker precisam montar o `librechat.yaml` como um volume para que o container possa lê-lo. Pule esta etapa se você estiver executando o LibreChat localmente sem Docker.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Edite o `docker-compose.override.yml` e certifique-se de que a montagem de volume esteja descomentada:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Saiba mais: [Guia de Substituição do Docker](/docs/configuration/docker_override)

## Passo 2. Configurar o librechat.yaml [#step-2-configure-librechatyaml]

Crie um arquivo `librechat.yaml` na raiz do projeto (caso ele não exista) e adicione a configuração do seu endpoint. Consulte o [guia do librechat.yaml](/docs/configuration/librechat_yaml) para instruções detalhadas de configuração.

Aqui está um exemplo com **OpenRouter**, **Ollama** e um gateway compatível com Anthropic:

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

Navegue por todos os provedores compatíveis na seção [AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints). Para a referência completa dos campos, consulte [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

<Callout type="note" title="Endpoints compatíveis com Anthropic">

Use `provider: "anthropic"` apenas para endpoints que utilizam a API nativa de Messages da Anthropic. Para gateways compatíveis com OpenAI que apenas expõem modelos da Anthropic, omita o `provider` e utilize o formato de endpoint personalizado compatível com OpenAI padrão.

</Callout>

<Callout type="warning" title="Configuração de Chave de API">

Ao configurar chaves de API em endpoints personalizados, você tem três opções:

1. **Variável de ambiente** (recomendado): `apiKey: '${OPENROUTER_KEY}'` lê uma chave compartilhada do arquivo `.env`, portanto, a chave precisa de uma entrada correspondente no [Passo 3](#step-3-set-environment-variables).
2. `apiKey: 'user_provided'` solicita a cada usuário sua própria chave na interface do LibreChat em vez de ler uma do `.env`. Nenhuma entrada no `.env` é necessária para a chave em si. O LibreChat armazena a chave de cada usuário criptografada e a solicita na primeira vez que eles selecionam o endpoint.
3. **Valor direto** (não recomendado): `apiKey: 'sk-your-actual-key'` codifica a chave diretamente no `librechat.yaml` em texto simples.

`baseURL` aceita `user_provided` da mesma forma, o que permite que cada usuário aponte o endpoint para seu próprio gateway.

O exemplo acima mistura estilos deliberadamente: o OpenRouter e o gateway compatível com Anthropic usam a opção 1, enquanto o Ollama passa a string literal `'ollama'` porque um servidor Ollama local ignora a chave completamente.

</Callout>

## Passo 3. Definir Variáveis de Ambiente [#step-3-set-environment-variables]

Esta etapa cobre todas as referências `${VARIABLE_NAME}` no seu `librechat.yaml`, estejam elas em `apiKey`, `baseURL` ou em um valor de `headers`. Se nada do que você adicionou utiliza esse formato, pule para o [Passo 4](#step-4-restart-and-verify).

Adicione cada variável que seu `librechat.yaml` referencia ao `.env`. O exemplo acima referencia duas:

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

Cada `${VARIABLE_NAME}` no `librechat.yaml` precisa de uma entrada correspondente. Uma entrada ausente não remove o endpoint: ele ainda aparece no seletor, e o problema só surge quando alguém envia uma mensagem através dele. Uma `apiKey` não resolvida falha com `Missing API Key for <endpoint>`, e uma `baseURL` não resolvida com `Missing Base URL for <endpoint>`. Um valor de `headers` não resolvido se comporta de forma diferente: ele é enviado para o upstream como o texto literal `${VARIABLE_NAME}`, portanto, a falha retorna do provedor em vez de vir do LibreChat.

## Passo 4. Reinicie e Verifique [#step-4-restart-and-verify]

Após editar os arquivos de configuração, você deve reiniciar o LibreChat para que as alterações entrem em vigor.

<Tabs items={['Docker', 'Local']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

Interrompa o processo em execução (Ctrl+C) e reinicie:

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

Abra o LibreChat no seu navegador. Seus endpoints personalizados devem aparecer no menu suspenso de seleção de endpoint.

<Callout type="warning" title="Não está vendo seu endpoint? Um bloco incompleto é descartado silenciosamente">

Comece com os logs do servidor:

```bash
docker compose logs api
```

**Mas não pare por aí.** O LibreChat mantém um endpoint personalizado apenas se todos os campos `name`, `baseURL`, `apiKey` e `models` estiverem presentes, e se `models` tiver `fetch: true` ou uma lista `default` não vazia. Uma entrada que falhe nessa verificação é removida da lista de endpoints **sem erro e sem nenhuma linha de log**: o provedor simplesmente nunca aparece e os logs parecem limpos.

Portanto, quando um endpoint estiver faltando, verifique o próprio bloco antes de procurar nos logs:

- Todos os campos `name`, `baseURL`, `apiKey` e `models` estão escritos corretamente? Um único erro de digitação invalida toda a entrada.
- O `models` possui `fetch: true` ou pelo menos uma entrada em `default`?
- O bloco está recuado **dentro** da lista `endpoints.custom`, em vez de estar no nível superior?
- O `name` é único? Um segundo endpoint com o mesmo nome (sem diferenciar maiúsculas de minúsculas) substitui silenciosamente o primeiro.

Compare o seu bloco com a referência da [Estrutura de Objeto de Endpoint Personalizado](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

Observe também que um erro de esquema **em qualquer lugar** do `librechat.yaml` interrompe o servidor em vez de desativar apenas uma seção, portanto, um bloco incorreto em outro lugar pode derrubar todos os endpoint personalizados junto com ele. Valide a sintaxe com o [YAML Validator](/docs/toolkit/yaml-validator), que verifica apenas a sintaxe YAML, não o esquema do LibreChat.

</Callout>

### OpenRouter Ainda Não Aparece [#openrouter-still-does-not-show-up]

Para o OpenRouter especificamente, verifique a cadeia de três arquivos:

1. O `.env` contém `OPENROUTER_KEY=...`
2. `librechat.yaml` tem `apiKey: "${OPENROUTER_KEY}"` sob o endpoint personalizado do OpenRouter
3. Usuários do Docker montaram o `librechat.yaml` no `docker-compose.override.yml`

Em seguida, reinicie com:

```bash
docker compose down && docker compose up -d
```

Se o endpoint aparecer, mas retornar `402 Payment Required`, a solicitação alcançou o OpenRouter com sucesso e o problema geralmente está relacionado a créditos da conta, faturamento ou disponibilidade de modelo no OpenRouter.
