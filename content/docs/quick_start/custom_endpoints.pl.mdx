LibreChat obsługuje usługi kompatybilne z API OpenAI jako niestandardowe endpointy. Obsługuje również niestandardowe endpointy kompatybilne z Anthropic przy użyciu `provider: "anthropic"`. Endpointy konfiguruje się w `librechat.yaml`, klucze API przechowuje w `.env`, a konfigurację montuje poprzez `docker-compose.override.yml` w przypadku wdrożeń Docker.

<Callout type="info" title="Który plik za co odpowiada?">

Konfiguracja niestandardowego endpoint obejmuje trzy pliki, z których każdy pełni określoną rolę:

1. **`librechat.yaml`** -- Definiuje twoje niestandardowe endpointy (nazwę, adres URL API, modele, ustawienia wyświetlania)
2. **`.env`** -- Przechowuje poufne wartości, takie jak klucze API (do których odwołuje się plik librechat.yaml przy użyciu składni `${VAR_NAME}`)
3. **`docker-compose.override.yml`** -- Montuje `librechat.yaml` wewnątrz kontenera Docker (tylko dla użytkowników Docker)

Aby uzyskać pełny przegląd tego, jak te pliki ze sobą współpracują, zobacz [Configuration Overview](/docs/configuration).

</Callout>

<Callout type="warning" title="Zanim zaczniesz">

Ten przewodnik zakłada, że masz zainstalowany i uruchomiony LibreChat. Jeśli nie, najpierw ukończ [konfigurację Docker](/docs/local/docker).

</Callout>

## Krok 1. Zamontuj librechat.yaml (tylko Docker) [#step-1-mount-librechatyaml-docker-only]

Użytkownicy Docker muszą zamontować `librechat.yaml` jako wolumen, aby kontener mógł go odczytać. Pomiń ten krok, jeśli uruchamiasz LibreChat lokalnie bez Docker.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Edytuj `docker-compose.override.yml` i upewnij się, że montowanie wolumenu jest odkomentowane:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Dowiedz się więcej: [Przewodnik nadpisywania Docker](/docs/configuration/docker_override)

## Krok 2. Skonfiguruj librechat.yaml [#step-2-configure-librechatyaml]

Utwórz plik `librechat.yaml` w katalogu głównym projektu (jeśli jeszcze nie istnieje) i dodaj swoją konfigurację endpoint. Szczegółowe instrukcje konfiguracji znajdziesz w [przewodniku po librechat.yaml](/docs/configuration/librechat_yaml).

Oto przykład z **OpenRouter**, **Ollama** oraz bramką kompatybilną z Anthropic:

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

Przeglądaj wszystkich kompatybilnych dostawców w sekcji [AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints). Pełną dokumentację pól znajdziesz w [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

<Callout type="note" title="Punkty końcowe zgodne z Anthropic">

Używaj `provider: "anthropic"` tylko dla endpointów, które obsługują natywne API Anthropic Messages. W przypadku bramek kompatybilnych z OpenAI, które jedynie udostępniają modele Anthropic, pomiń `provider` i użyj standardowego formatu niestandardowego endpointu kompatybilnego z OpenAI.

</Callout>

<Callout type="warning" title="Konfiguracja klucza API">

Podczas konfigurowania kluczy API w niestandardowych endpointach masz trzy opcje:

1. **Zmienna środowiskowa** (zalecane): `apiKey: '${OPENROUTER_KEY}'` odczytuje jeden współdzielony klucz z pliku `.env`, więc klucz musi mieć pasujący wpis w [Kroku 3](#step-3-set-environment-variables).
2. `apiKey: 'user_provided'` prosi każdego użytkownika o podanie własnego klucza w interfejsie LibreChat zamiast odczytywania go z pliku `.env`. Dla samego klucza nie jest wymagany żaden wpis w `.env`. LibreChat przechowuje klucz każdego użytkownika w zaszyfrowanej formie i prosi o jego podanie przy pierwszym wybraniu danego endpoint.
3. **Wartość bezpośrednia** (niezalecane): `apiKey: 'sk-your-actual-key'` zapisuje klucz na sztywno w pliku `librechat.yaml` w postaci zwykłego tekstu.

`baseURL` akceptuje `user_provided` w ten sam sposób, co pozwala każdemu użytkownikowi skierować endpoint na własną bramę.

Powyższy przykład celowo miesza style: OpenRouter oraz bramka kompatybilna z Anthropic używają opcji 1, podczas gdy Ollama przekazuje dosłowny ciąg znaków `'ollama'`, ponieważ lokalny serwer Ollama całkowicie ignoruje ten klucz.

</Callout>

## Krok 3. Ustaw zmienne środowiskowe [#step-3-set-environment-variables]

Ten krok obejmuje każde odniesienie `${VARIABLE_NAME}` w Twoim `librechat.yaml`, niezależnie od tego, czy znajduje się ono w `apiKey`, `baseURL`, czy w wartości `headers`. Jeśli nic, co dodałeś, nie używa tej formy, przejdź do [Kroku 4](#step-4-restart-and-verify).

Dodaj każdą zmienną, do której odwołuje się Twój `librechat.yaml`, do pliku `.env`. Powyższy przykład odwołuje się do dwóch:

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

Każde `${VARIABLE_NAME}` w `librechat.yaml` wymaga pasującego wpisu. Brakujący wpis nie powoduje usunięcia endpoint: nadal pojawia się on w selektorze, a problem ujawnia się dopiero w momencie wysłania przez niego wiadomości. Nierozwiązany `apiKey` kończy się błędem `Missing API Key for <endpoint>`, a nierozwiązany `baseURL` błędem `Missing Base URL for <endpoint>`. Nierozwiązana wartość `headers` zachowuje się inaczej: jest wysyłana do dostawcy jako dosłowny tekst `${VARIABLE_NAME}`, więc błąd pochodzi od dostawcy, a nie z LibreChat.

## Krok 4. Restart i weryfikacja [#step-4-restart-and-verify]

Po edycji plików konfiguracyjnych należy zrestartować LibreChat, aby zmiany weszły w życie.

<Tabs items={['Docker', 'Lokalny']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

Zatrzymaj uruchomiony proces (Ctrl+C) i uruchom ponownie:

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

Otwórz LibreChat w swojej przeglądarce. Twoje niestandardowe endpoint powinny pojawić się na liście rozwijanej wyboru endpoint.

<Callout type="warning" title="Nie widzisz swojego endpoint? Niekompletny blok jest pomijany bez powiadomienia">

Zacznij od logów serwera:

```bash
docker compose logs api
```

**Ale na tym nie poprzestawaj.** LibreChat zachowuje niestandardowy endpoint tylko wtedy, gdy wszystkie pola `name`, `baseURL`, `apiKey` oraz `models` są obecne, a pole `models` zawiera albo `fetch: true`, albo niepustą listę `default`. Wpis, który nie przejdzie tej weryfikacji, jest usuwany z listy endpointów **bez żadnego błędu i bez żadnego wpisu w logach**: dostawca po prostu się nie pojawia, a logi wyglądają na czyste.

Więc jeśli brakuje endpoint, sprawdź sam blok, zanim zaczniesz przeszukiwać logi:

- Czy każdy z elementów `name`, `baseURL`, `apiKey`, `models` jest napisany poprawnie? Pojedyncza literówka powoduje odrzucenie całego wpisu.
- Czy `models` ma `fetch: true` lub przynajmniej jeden wpis w `default`?
- Czy blok jest wcięty **wewnątrz** listy `endpoints.custom`, zamiast znajdować się na najwyższym poziomie?
- Czy `name` jest unikalne? Drugi endpoint o tej samej nazwie (bez rozróżniania wielkości liter) po cichu zastępuje pierwszy.

Porównaj swój blok z dokumentacją [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

Zwróć również uwagę, że błąd schematu **w dowolnym miejscu** pliku `librechat.yaml` zatrzymuje serwer, zamiast wyłączać tylko jedną sekcję, więc jeden błędny blok w innym miejscu może spowodować wyłączenie wszystkich niestandardowych endpoint. Zweryfikuj składnię za pomocą [YAML Validator](/docs/toolkit/yaml-validator), który sprawdza tylko składnię YAML, a nie schemat LibreChat.

</Callout>

### OpenRouter nadal się nie pojawia [#openrouter-still-does-not-show-up]

W przypadku OpenRouter w szczególności, zweryfikuj łańcuch trzech plików:

1. `.env` zawiera `OPENROUTER_KEY=...`
2. `librechat.yaml` posiada `apiKey: "${OPENROUTER_KEY}"` w sekcji niestandardowego endpointu OpenRouter
3. Użytkownicy Docker zamontowali `librechat.yaml` w `docker-compose.override.yml`

Następnie uruchom ponownie za pomocą:

```bash
docker compose down && docker compose up -d
```

Jeśli endpoint się pojawia, ale zwraca `402 Payment Required`, oznacza to, że żądanie dotarło do OpenRouter pomyślnie, a problem zazwyczaj dotyczy środków na koncie, płatności lub dostępności modelu w OpenRouter.
