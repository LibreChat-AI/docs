LibreChat unterstützt OpenAI API-kompatible Dienste als benutzerdefinierte endpoints. Es unterstützt außerdem Anthropic-kompatible benutzerdefinierte endpoints mit `provider: "anthropic"`. Sie konfigurieren endpoints in `librechat.yaml`, speichern API-Schlüssel in `.env` und binden die Konfiguration über `docker-compose.override.yml` für Docker-Bereitstellungen ein.

<Callout type="info" title="Welche Datei bewirkt was?">

Die Einrichtung eines benutzerdefinierten endpoint umfasst drei Dateien, von denen jede eine spezifische Rolle spielt:

1. **`librechat.yaml`** -- Definiert Ihre benutzerdefinierten endpoints (Name, API-URL, Modelle, Anzeigeeinstellungen)
2. **`.env`** -- Speichert sensible Werte wie API-Schlüssel (referenziert aus der librechat.yaml unter Verwendung der `${VAR_NAME}`-Syntax)
3. **`docker-compose.override.yml`** -- Bindet `librechat.yaml` in den Docker-Container ein (nur für Docker-Benutzer)

Für einen vollständigen Überblick darüber, wie diese Dateien zusammenarbeiten, siehe die [Konfigurationsübersicht](/docs/configuration).

</Callout>

<Callout type="warning" title="Bevor Sie beginnen">

Diese Anleitung setzt voraus, dass LibreChat installiert ist und ausgeführt wird. Falls nicht, schließen Sie zuerst die [Docker-Einrichtung](/docs/local/docker) ab.

</Callout>

## Schritt 1. librechat.yaml einbinden (nur Docker) [#step-1-mount-librechatyaml-docker-only]

Docker-Benutzer müssen `librechat.yaml` als Volume einbinden, damit der Container darauf zugreifen kann. Überspringen Sie diesen Schritt, wenn Sie LibreChat lokal ohne Docker ausführen.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Bearbeiten Sie `docker-compose.override.yml` und stellen Sie sicher, dass die Volume-Einbindung nicht auskommentiert ist:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Mehr erfahren: [Docker Override Guide](/docs/configuration/docker_override)

## Schritt 2. Konfigurieren der librechat.yaml [#step-2-configure-librechatyaml]

Erstellen Sie eine `librechat.yaml` Datei im Projektstammverzeichnis (falls diese noch nicht existiert) und fügen Sie Ihre endpoint Konfiguration hinzu. Siehe den [librechat.yaml guide](/docs/configuration/librechat_yaml) für detaillierte Einrichtungsanweisungen.

Hier ist ein Beispiel mit **OpenRouter**, **Ollama** und einem Anthropic-kompatiblen Gateway:

```yaml filename="librechat.yaml"
version: 1.3.17
cache: true
endpoints:
  custom:
    - name: 'OpenRouter'
      apiKey: '${OPENROUTER_KEY}'
      baseURL: 'https://openrouter.ai/api/v1'
      models:
        default: ['meta-llama/llama-3-70b-instruct']
        fetch: true
      titleConvo: true
      titleModel: 'meta-llama/llama-3-70b-instruct'
      dropParams: ['stop']
      modelDisplayLabel: 'OpenRouter'
    - name: 'Ollama'
      apiKey: 'ollama'
      baseURL: 'http://host.docker.internal:11434/v1/'
      models:
        default: ['llama3:latest', 'command-r', 'mixtral', 'phi3']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
    - name: 'Claude-Compatible'
      provider: 'anthropic'
      apiKey: '${ANTHROPIC_API_KEY}'
      baseURL: 'https://api.anthropic.com'
      headers:
        anthropic-version: '2023-06-01'
      models:
        default: ['claude-sonnet-4-5']
        fetch: false
      titleConvo: true
      titleModel: 'claude-sonnet-4-5'
```

Durchsuchen Sie alle kompatiblen Anbieter im Abschnitt [AI Endpoints](/docs/configuration/librechat_yaml/ai_endpoints). Die vollständige Feldreferenz finden Sie unter [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

<Callout type="note" title="Anthropic-kompatible Endpoints">

Verwenden Sie `provider: "anthropic"` nur für Endpunkte, die die native Anthropic Messages API unterstützen. Für OpenAI-kompatible Gateways, die lediglich Anthropic-Modelle bereitstellen, lassen Sie `provider` weg und verwenden Sie das reguläre, OpenAI-kompatible Format für benutzerdefinierte Endpunkte.

</Callout>

<Callout type="warning" title="API-Schlüssel-Konfiguration">

Bei der Konfiguration von API-Schlüsseln in benutzerdefinierten endpoints haben Sie drei Optionen:

1. **Umgebungsvariable** (empfohlen): `apiKey: '${OPENROUTER_KEY}'` liest einen gemeinsam genutzten Schlüssel aus der `.env`, daher benötigt der Schlüssel einen entsprechenden Eintrag in [Schritt 3](#step-3-set-environment-variables).
2. **User provided**: `apiKey: 'user_provided'` fordert jeden Benutzer in der LibreChat UI zur Eingabe seines eigenen Schlüssels auf, anstatt diesen aus der `.env` zu lesen. Für den Schlüssel selbst ist kein `.env`-Eintrag erforderlich. LibreChat speichert den Schlüssel jedes Benutzers verschlüsselt und fragt beim ersten Auswählen des endpoint danach.
3. **Direkter Wert** (nicht empfohlen): `apiKey: 'sk-your-actual-key'` kodiert den Schlüssel im Klartext fest in die `librechat.yaml`.

`baseURL` akzeptiert `user_provided` auf die gleiche Weise, was es jedem Benutzer ermöglicht, den endpoint auf sein eigenes Gateway zu verweisen.

Das obige Beispiel mischt bewusst Stile: OpenRouter und das Anthropic-kompatible Gateway verwenden Option 1, während Ollama den literalen String `'ollama'` übergibt, da ein lokaler Ollama-Server den Schlüssel vollständig ignoriert.

</Callout>

## Schritt 3. Umgebungsvariablen festlegen [#step-3-set-environment-variables]

Dieser Schritt deckt jede `${VARIABLE_NAME}`-Referenz in Ihrer `librechat.yaml` ab, unabhängig davon, ob sie sich in einem `apiKey`-, `baseURL`- oder `headers`-Wert befindet. Wenn nichts, was Sie hinzugefügt haben, diese Form verwendet, fahren Sie mit [Schritt 4](#step-4-restart-and-verify) fort.

Fügen Sie jede Variable, auf die Ihre `librechat.yaml` verweist, zu `.env` hinzu. Das obige Beispiel verweist auf zwei:

```bash filename=".env"
OPENROUTER_KEY=your_openrouter_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

Jede `${VARIABLE_NAME}` in der `librechat.yaml` benötigt einen passenden Eintrag. Ein fehlender Eintrag führt nicht dazu, dass der endpoint entfernt wird: Er erscheint weiterhin im Auswahlmenü, und das Problem tritt erst auf, sobald jemand eine Nachricht darüber sendet. Ein nicht aufgelöster `apiKey` führt zu dem Fehler `Missing API Key for <endpoint>`, und ein nicht aufgelöster `baseURL` zu `Missing Base URL for <endpoint>`. Ein nicht aufgelöster `headers`-Wert verhält sich anders: Er wird als wörtlicher Text `${VARIABLE_NAME}` an den Upstream gesendet, sodass der Fehler vom Anbieter und nicht von LibreChat zurückgegeben wird.

## Schritt 4. Neustart und Überprüfung [#step-4-restart-and-verify]

Nach dem Bearbeiten der Konfigurationsdateien müssen Sie LibreChat neu starten, damit die Änderungen wirksam werden.

<Tabs items={['Docker', 'Lokal']}>
  <Tabs.Tab>

```bash
docker compose down && docker compose up -d
```

  </Tabs.Tab>
  <Tabs.Tab>

Stoppen Sie den laufenden Prozess (Strg+C) und starten Sie ihn neu:

```bash
npm run backend
```

  </Tabs.Tab>
</Tabs>

Öffnen Sie LibreChat in Ihrem Browser. Ihre benutzerdefinierten endpoints sollten im Dropdown-Menü der endpoint-Auswahl erscheinen.

<Callout type="warning" title="Siehst du deinen endpoint nicht? Ein unvollständiger Block wird stillschweigend verworfen">

Beginnen Sie mit den Server-Logs:

```bash
docker compose logs api
```

**Aber hören Sie hier nicht auf.** LibreChat behält einen benutzerdefinierten endpoint nur bei, wenn `name`, `baseURL`, `apiKey` und `models` vorhanden sind und `models` entweder `fetch: true` oder eine nicht leere `default`-Liste enthält. Ein Eintrag, der diese Prüfung nicht besteht, wird ohne **Fehlermeldung und ohne jegliche Protokollzeile** aus der endpoint-Liste entfernt: Der Anbieter erscheint einfach nicht, und die Protokolle sehen sauber aus.

Wenn also ein endpoint fehlt, überprüfen Sie den Block selbst, bevor Sie die Protokolle durchsuchen:

- Sind `name`, `baseURL`, `apiKey` und `models` jeweils korrekt geschrieben? Ein einziger Tippfehler führt dazu, dass der gesamte Eintrag verworfen wird.
- Hat `models` den Wert `fetch: true` oder mindestens einen Eintrag unter `default`?
- Ist der Block **innerhalb** der `endpoints.custom`-Liste eingerückt, anstatt auf der obersten Ebene zu stehen?
- Ist der `name` eindeutig? Ein zweiter endpoint mit demselben Namen (unter Ignorierung der Groß-/Kleinschreibung) ersetzt den ersten stillschweigend.

Vergleiche deinen Block mit der Referenz zur [Custom Endpoint Object Structure](/docs/configuration/librechat_yaml/object_structure/custom_endpoint).

Beachten Sie auch, dass ein Schemafehler **an einer beliebigen Stelle** in der `librechat.yaml` den Server anhält, anstatt nur einen Abschnitt zu deaktivieren. Ein fehlerhafter Block an anderer Stelle kann also dazu führen, dass alle benutzerdefinierten endpoint-Konfigurationen ausfallen. Überprüfen Sie die Syntax mit dem [YAML Validator](/docs/toolkit/yaml-validator), der nur die YAML-Syntax prüft, nicht jedoch das Schema von LibreChat.

</Callout>

### OpenRouter erscheint weiterhin nicht [#openrouter-still-does-not-show-up]

Für OpenRouter im Speziellen, überprüfen Sie die Drei-Dateien-Kette:

1. `.env` enthält `OPENROUTER_KEY=...`
2. `librechat.yaml` hat `apiKey: "${OPENROUTER_KEY}"` unter dem benutzerdefinierten OpenRouter-endpoint
3. Docker-Benutzer haben `librechat.yaml` in `docker-compose.override.yml` gemountet

Starten Sie dann neu mit:

```bash
docker compose down && docker compose up -d
```

Wenn der endpoint erscheint, aber `402 Payment Required` zurückgibt, hat die Anfrage OpenRouter erfolgreich erreicht und das Problem liegt in der Regel an Kontoguthaben, Abrechnung oder der Modellverfügbarkeit auf OpenRouter.
