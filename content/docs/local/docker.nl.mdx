Voor de meeste scenario's is Docker Compose de aanbevolen installatiemethode vanwege de eenvoud, het gebruiksgemak en de betrouwbaarheid.

## Vereisten [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop wordt aanbevolen voor de meeste gebruikers. Voor installaties op externe servers, zie de [Ubuntu Docker Deployment Guide](/docs/remote/docker_linux).

### Systeemvereisten [#system-requirements]

LibreChat draait zelf geen AI-modellen; het stuurt verzoeken naar de providers die je configureert, dus het heeft geen GPU nodig.

LibreChat's containers hebben minimaal 1 GiB RAM en 1 vCPU nodig, dezelfde [minimumvereisten](/docs/remote#minimum-requirements) als op een server. Het standaard Docker Compose-bestand start MongoDB, Meilisearch (gesprekszoekfunctie) en de RAG API met een PostgreSQL/pgvector-database (bestandszoekfunctie) naast LibreChat. Het definieert ook het beheerdersdashboard, dat pas start wanneer `ADMIN_PANEL_SESSION_SECRET` is ingesteld in `.env` (zie [Admin Panel](/docs/features/admin_panel)). Wanneer alles draait, zorg dan voor minimaal 2 GB geheugen voor Docker voor een soepelere werking.

Als je Docker Desktop gebruikt, draait het containers binnen de eigen virtuele machine, dus je computer moet ook voldoen aan de vereisten van Docker Desktop. Op het moment van schrijven zijn dat minimaal 4 GB systeemgeheugen op [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) en [Linux](https://docs.docker.com/desktop/setup/install/linux/), en 8 GB op [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), plus hardwarevirtualisatie. Raadpleeg de gekoppelde pagina's voor de actuele vereisten. Het geheugen dat beschikbaar is voor containers wordt ingesteld in de [resource-instellingen](https://docs.docker.com/desktop/settings-and-maintenance/settings/) van Docker Desktop op macOS, Linux en Windows met Hyper-V. Bij de Windows WSL 2-backend wordt het ingesteld op de WSL 2-virtuele machine (zie [de WSL-richtlijnen van Docker](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine die rechtstreeks op Linux is geïnstalleerd, draait containers op de host zelf en heeft geen aparte virtuele machine.

Als je LibreChat koppelt aan modellen die op dezelfde machine draaien, zoals [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), dimensioneer dan de hardware op basis van het model dat je kiest. Die modelruntime heeft veel meer geheugen nodig, en vaak een GPU, dan LibreChat zelf.

<Callout type="warn" title="CPU's zonder AVX-ondersteuning">

De MongoDB-image die wordt gebruikt in de standaard Docker Compose-configuratie van LibreChat vereist een CPU met AVX-instructies. Op oudere x86-CPU's zonder AVX (en op sommige virtuele machines die AVX niet beschikbaar maken voor het gastsysteem) crasht MongoDB bij het opstarten.

**Oplossing:** Maak een `docker-compose.override.yml` aan om een oudere MongoDB-image te gebruiken die geen AVX vereist:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Zie de [Docker Override handleiding](/docs/configuration/docker_override) voor meer details.

</Callout>

## Installatie [#installation]

<Steps>
  <Step>

### Kloon de repository [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Maak je omgevingsbestand aan [#create-your-environment-file]

```bash
cp .env.example .env
```

Het standaard `.env` bestand werkt direct voor een basisinstallatie. Voor uitgebreide configuratie, zie de [.env reference](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

Gebruik op Windows `copy .env.example .env` als `cp` niet beschikbaar is.

</Callout>

  </Step>
  <Step>

### Start LibreChat [#start-librechat]

```bash
docker compose up -d
```

De eerste keer opstarten haalt Docker images op en kan enkele minuten duren. Daaropvolgende starts zijn veel sneller.

  </Step>
  <Step>

### Verifiëren en inloggen [#verify-and-log-in]

Open je browser en ga naar [http://localhost:3080](http://localhost:3080). Je zou de inlogpagina van LibreChat moeten zien.

<Callout type="info" title="Eerste account = Admin in Single-Tenant implementaties">

In een niet-afgebakende single-tenant implementatie wordt het eerste account dat je registreert het beheerdersaccount. Er zijn geen standaardreferenties; je maakt je eigen gebruikersnaam en wachtwoord aan tijdens de registratie. Tenant-afgebakende implementaties promoveren niet automatisch de eerste gebruiker in elke tenant; richt tenantbeheerders in via een vertrouwde beheerprocedure.

</Callout>

Klik op **Sign up** om je account aan te maken en volg daarna [Your First Chat](/docs/quick_start/first_chat) om een model-API-sleutel toe te voegen en je eerste bericht te versturen.

  </Step>
</Steps>

## Mounting librechat.yaml [#mounting-librechatyaml]

Om een aangepast `librechat.yaml` configuratiebestand te gebruiken met Docker, moet je het als een volume mounten zodat de container er toegang toe heeft.

Kopieer het voorbeeld-override-bestand en bewerk het:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Zorg ervoor dat de librechat.yaml volume mount niet is uitgeschakeld (uncommented) in `docker-compose.override.yml`:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Start opnieuw op om de wijzigingen door te voeren:

```bash
docker compose down && docker compose up -d
```

Voor volledige installatie-instructies, inclusief het vanaf nul aanmaken van het bestand, zie de [librechat.yaml guide](/docs/configuration/librechat_yaml). Voor meer override-opties, zie de [Docker override guide](/docs/configuration/docker_override).

## LibreChat bijwerken [#updating-librechat]

De volgende commando's halen de laatste LibreChat projectwijzigingen op, inclusief alle noodzakelijke wijzigingen aan de docker compose bestanden, evenals de nieuwste vooraf gebouwde images.

<Callout type="info" title="Rechten">

Mogelijk moet je opdrachten voorzien van het voorvoegsel `sudo`, afhankelijk van de rechten in jouw omgeving.

</Callout>

<Callout type="info" title="Updatescript">

Het script `npm run update:docker` van de repository bouwt lokaal gebouwde images opnieuw, maar haalt niet de vooraf gebouwde images op die het standaard `docker-compose.yml` gebruikt. Volg daarom de onderstaande handmatige stappen om een standaardinstallatie bij te werken.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Probleemoplossing [#troubleshooting]

### Poort al in gebruik [#port-already-in-use]

Als je een foutmelding ziet zoals `bind: address already in use` voor poort 3080, dan gebruikt een andere applicatie die poort.

Stop de conflicterende applicatie, of wijzig de poort die LibreChat gebruikt. Het standaard `docker-compose.yml` publiceert `"${PORT}:${PORT}"`, en poorten die in een override-bestand worden toegevoegd, worden aan die lijst toegevoegd in plaats van deze te vervangen. Een override alleen geeft poort 3080 daarom niet vrij.

De eenvoudigste oplossing is om `PORT` in je `.env`-bestand in te stellen. Dit wijzigt zowel de poort waarop LibreChat luistert als de gepubliceerde poort:

```bash filename=".env"
PORT=3081
```

Als alternatief kun je met Docker Compose 2.24.4 of later de gepubliceerde poort in `docker-compose.override.yml` vervangen door de `!override`-tag (de container blijft luisteren op 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Herstart met `docker compose down && docker compose up -d`, en bezoek vervolgens `http://localhost:3081`.

### Container crasht bij het opstarten [#container-crashes-on-startup]

Als containers onmiddellijk na het opstarten afsluiten, controleer dan de logs:

```bash
docker compose logs api
```

Veelvoorkomende oorzaken:

- Ongeldige `librechat.yaml`-syntaxis: valideer met de [YAML-validator](/toolkit/yaml_checker)
- Ontbrekend `.env` bestand -- zorg ervoor dat `.env` in de hoofdmap van het project aanwezig is
- Docker draait niet -- zorg ervoor dat Docker Desktop geopend is en draait

### Ontbrekende omgevingsvariabelen [#missing-environment-variables]

Als functies niet werken zoals verwacht, controleer dan of de vereiste omgevingsvariabelen zijn ingesteld in je `.env` bestand.

```bash
docker compose exec api env | grep -i "your_variable"
```

Zie de [.env reference](/docs/configuration/dotenv) voor alle beschikbare variabelen en hun standaardwaarden.
