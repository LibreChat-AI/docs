Por favor, siga esta guía para desplegar LibreChat en Kubernetes usando Helm, ajustándola según sea necesario para su caso de uso específico. Otros Helm charts aportados por la comunidad se enumeran a continuación en la sección [Community Helm Charts](#community-helm-charts).

## Requisitos previos [#prerequisites]

* Un clúster de Kubernetes en ejecución
* Instalaciones _locales_ de `kubectl` y Helm

## Configuración [#configuration]

1. Utilice el [Credentials Generator](/toolkit/creds_generator) para generar valores seguros para `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET` y `MEILI_MASTER_KEY`.
Colóquelos en un Kubernetes Secret como este (si cambia el nombre del secret, recuerde actualizar sus valores de Helm):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

Utilice valores permanentes y monte el mismo Secret en cada réplica. No dependa de credenciales locales del proceso o del sistema de archivos efímero en Kubernetes: cambiar estos valores puede invalidar sesiones y hacer que los registros cifrados existentes sean ilegibles.

El Secret nombrado por `global.librechat.existingSecretName` debe existir antes de que el contenedor de LibreChat se inicie. Un Secret nombrado faltante o mal escrito bloquea el inicio del pod en lugar de recurrir a credenciales temporales locales del pod. El chart no valida las claves dentro de él, así que asegúrese de que contenga `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET` y `JWT_REFRESH_SECRET`.

Establezca `global.librechat.existingSecretName: ""` solo cuando todas las credenciales de LibreChat se suministren de otra manera. `librechat.configEnv` acepta valores de cadena para datos de ConfigMap, mientras que `global.librechat.env` acepta entradas de entorno de Kubernetes como `valueFrom.secretKeyRef`. Prefiera las referencias a Secret para producción.

El Meilisearch incluido tiene una dependencia separada en `meilisearch.auth.existingMasterKeySecret`, que por defecto es `librechat-credentials-env` y debe contener la misma `MEILI_MASTER_KEY` proporcionada a LibreChat. Borrar la referencia del Secret de LibreChat no borra esta referencia de Meilisearch. Si el Meilisearch incluido está desactivado, configure el servicio de búsqueda externo y sus credenciales por separado.

2. Añada a este mismo secret cualquier clave de API necesaria para los proveedores de LLM:

kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
. . . .

  OPENAI_API_KEY: <your secret value>

## Instalar Helm Chart [#install-helm-chart]

Para instalar el helm chart, ejecuta:

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>Versión de desarrollo</summary>

En el directorio raíz del repositorio, ejecuta:

`helm install <deployment-name> ./helm/librechat`
</details>

Al igual que otros Helm charts, existe un [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) que describe la configuración predeterminada e indica qué opciones de configuración se pueden modificar.

Cree un archivo `values.yaml` completado con los valores que desea modificar a partir de los predeterminados.

Instale el Helm chart: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

Una vez que la versión esté publicada y el servicio sea accesible, sigue [Tu primer chat](/docs/quick_start/first_chat) para registrar una cuenta, añadir una API key de modelo y enviar tu primer mensaje.

## Desinstalar el Helm Chart [#uninstall-the-helm-chart]

Para desinstalar el Helm Chart: `helm uninstall <deployment-name>`

Ejemplo: `helm uninstall librechat`

## Migrar 1.x -> 2.x [#migrate-1x---2x]
Si utilizó el chart antes de la versión 2.x, es posible que deba actualizar la estructura de `value`.

1. Mover la configuración a librechat.configEnv:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. Consolide todos los valores de Secret en un único Secret como se describe en [Configuration Step 1](#configuration).
3. Para aprovechar una instancia externa de MongoDB, consulte el [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) del Chart, desactive los componentes correspondientes y cambie el FQDN de la instancia de MongoDB. Esto se recomienda si ya existen datos en esta instancia de MongoDB gestionada externamente.
