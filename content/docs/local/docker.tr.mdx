Çoğu senaryo için, basitliği, kullanım kolaylığı ve güvenilirliği nedeniyle Docker Compose önerilen kurulum yöntemidir.

## Ön Koşullar [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Çoğu kullanıcı için Docker Desktop önerilir. Uzak sunucu kurulumları için [Ubuntu Docker Deployment Guide](/docs/remote/docker_linux) bölümüne bakın.

### Sistem Gereksinimleri [#system-requirements]

LibreChat kendisi yapay zeka modellerini çalıştırmaz; yapılandırdığınız sağlayıcılara istek gönderir, bu nedenle bir GPU'ya ihtiyaç duymaz.

LibreChat'in konteynerleri en az 1 GiB RAM ve 1 vCPU gerektirir; bu, bir sunucudaki [minimum gereksinimlerle](/docs/remote#minimum-requirements) aynıdır. Varsayılan Docker Compose dosyası, LibreChat ile birlikte MongoDB, Meilisearch (konuşma araması) ve PostgreSQL/pgvector veritabanına sahip RAG API'yi (dosya araması) başlatır. Ayrıca yönetici panelini tanımlar; bu panel yalnızca `.env` dosyasında `ADMIN_PANEL_SESSION_SECRET` ayarlandığında başlar (bkz. [Yönetici Paneli](/docs/features/admin_panel)). Her şey çalışırken, daha sorunsuz bir işleyiş için Docker'a en az 2 GB bellek ayırın.

Docker Desktop kullanıyorsanız, konteynerler kendi sanal makinesi içinde çalışır; bu nedenle bilgisayarınızın da Docker Desktop'ın gereksinimlerini karşılaması gerekir. Bu yazının yazıldığı tarih itibarıyla bunlar, [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) ve [Linux](https://docs.docker.com/desktop/setup/install/linux/) için en az 4 GB sistem RAM'i, [Windows](https://docs.docker.com/desktop/setup/install/windows-install/) için 8 GB RAM'dir ve ayrıca donanım sanallaştırması gerekir. Güncel gereksinimler için bağlantılı sayfaları kontrol edin. Konteynerlerin kullanabileceği bellek, macOS, Linux ve Hyper-V kullanan Windows'ta Docker Desktop'ın [kaynak ayarları](https://docs.docker.com/desktop/settings-and-maintenance/settings/) üzerinden belirlenir; Windows WSL 2 arka ucu kullanılıyorsa bunun yerine WSL 2 sanal makinesi üzerinden ayarlanır (bkz. [Docker'ın WSL kılavuzu](https://docs.docker.com/desktop/features/wsl/best-practices/)). Doğrudan Linux'a kurulan Docker Engine ise konteynerleri ana makinede çalıştırır ve ayrı bir sanal makineye sahip değildir.

LibreChat'i aynı makinede çalışan modellere bağlarsanız, örneğin [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), donanımı seçtiğiniz modele göre boyutlandırın. Bu model çalışma ortamı, LibreChat'ten çok daha fazla bellek ve çoğu zaman bir GPU gerektirir.

<Callout type="warn" title="AVX desteği olmayan CPU'lar">

LibreChat'in varsayılan Docker Compose kurulumunda kullanılan MongoDB imajı, AVX komutlarını destekleyen bir CPU gerektirir. AVX desteği olmayan eski x86 CPU'larda (ve AVX'i misafir sistemine sunmayan bazı sanal makinelerde), MongoDB başlatma sırasında çöker.

**Düzeltme:** AVX gerektirmeyen daha eski bir MongoDB imajını kullanmak için bir `docker-compose.override.yml` dosyası oluşturun:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Daha fazla ayrıntı için [Docker Override kılavuzuna](/docs/configuration/docker_override) bakın.

</Callout>

## Kurulum [#installation]

<Steps>
  <Step>

### Depoyu Klonlayın [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Ortam Dosyanızı Oluşturun [#create-your-environment-file]

```bash
cp .env.example .env
```

Varsayılan `.env` dosyası, temel bir kurulum için kutudan çıktığı haliyle çalışır. Kapsamlı yapılandırma için [.env referansına](/docs/configuration/dotenv) bakın.

<Callout type="info" title="Windows">

On Windows, use `copy .env.example .env` if `cp` is not available.

</Callout>

  </Step>
  <Step>

### LibreChat'i Başlatın [#start-librechat]

```bash
docker compose up -d
```

İlk başlatma Docker imajlarını çeker ve birkaç dakika sürebilir. Sonraki başlatmalar çok daha hızlıdır.

  </Step>
  <Step>

### Doğrulama ve Giriş Yapma [#verify-and-log-in]

Tarayıcınızı açın ve [http://localhost:3080](http://localhost:3080) adresini ziyaret edin. LibreChat giriş sayfasını görmelisiniz.

<Callout type="info" title="Tek Kiracılı Dağıtımlarda İlk Hesap = Yönetici">

Kapsamsız tek kiracılı bir dağıtımda, kaydettiğiniz ilk hesap yönetici hesabı olur. Varsayılan kimlik bilgisi yoktur; kayıt sırasında kendi kullanıcı adınızı ve parolanızı oluşturursunuz. Kiracıya bağlı (tenant-scoped) dağıtımlar, her kiracıdaki ilk kullanıcıyı otomatik olarak yönetici yapmaz; kiracı yöneticilerini güvenilir bir yönetim akışı üzerinden sağlayın.

</Callout>

Hesabınızı oluşturmak için **Sign up** seçeneğine tıklayın, ardından bir model API anahtarı ekleyip ilk mesajınızı göndermek için [Your First Chat](/docs/quick_start/first_chat) bölümünü izleyin.

  </Step>
</Steps>

## librechat.yaml dosyasını bağlama [#mounting-librechatyaml]

Docker ile özel bir `librechat.yaml` yapılandırma dosyası kullanmak için, dosyayı konteynerin erişebilmesi adına bir birim (volume) olarak bağlamanız gerekir.

Örnek geçersiz kılma (override) dosyasını kopyalayın ve düzenleyin:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

`docker-compose.override.yml` dosyasında librechat.yaml birim bağlamasının (volume mount) açıklama satırı olmaktan çıkarıldığından emin olun:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Değişikliklerin geçerli olması için yeniden başlatın:

```bash
docker compose down && docker compose up -d
```

Sıfırdan dosya oluşturma dahil tam kurulum talimatları için [librechat.yaml kılavuzuna](/docs/configuration/librechat_yaml) bakın. Daha fazla geçersiz kılma (override) seçeneği için [Docker geçersiz kılma kılavuzuna](/docs/configuration/docker_override) bakın.

## LibreChat'i Güncelleme [#updating-librechat]

Aşağıdaki komutlar, docker compose dosyalarındaki gerekli değişiklikler de dahil olmak üzere en son LibreChat proje değişikliklerini ve en son önceden oluşturulmuş (prebuilt) imajları getirecektir.

<Callout type="info" title="İzinler">

Ortam izinlerinize bağlı olarak komutların başına `sudo` eklemeniz gerekebilir.

</Callout>

<Callout type="info" title="Güncelleme betiği">

Depo içindeki `npm run update:docker` betiği, yerel olarak oluşturulan imajları yeniden derler; ancak varsayılan `docker-compose.yml` dosyasının kullandığı önceden derlenmiş imajları çekmez. Bu nedenle varsayılan kurulumu güncellemek için aşağıdaki manuel adımları izleyin.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Sorun Giderme [#troubleshooting]

### Bağlantı Noktası (Port) Zaten Kullanımda [#port-already-in-use]

3080 numaralı bağlantı noktası için `bind: address already in use` gibi bir hata görürseniz, başka bir uygulama bu bağlantı noktasını kullanıyordur.

Çakışan uygulamayı durdurun veya LibreChat'in kullandığı portu değiştirin. Varsayılan `docker-compose.yml` dosyası `"${PORT}:${PORT}"` portunu yayımlar ve bir override dosyasına eklenen portlar bu listeye yeni eleman olarak eklenir, mevcut listenin yerini almaz. Bu nedenle yalnızca bir override dosyası kullanmak 3080 portunu serbest bırakmaz.

En basit çözüm, `.env` dosyanızda `PORT` değerini ayarlamaktır; bu, hem LibreChat'in dinlediği portu hem de yayımlanan portu değiştirir:

```bash filename=".env"
PORT=3081
```

Alternatif olarak, Docker Compose 2.24.4 veya daha yeni bir sürümle, `docker-compose.override.yml` dosyasındaki yayımlanmış portu `!override` etiketiyle değiştirebilirsiniz (konteyner 3080 portunu dinlemeye devam eder):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Yeniden başlatmak için `docker compose down && docker compose up -d` komutunu çalıştırın, ardından bunun yerine `http://localhost:3081` adresini ziyaret edin.

### Konteyner Başlangıçta Çöküyor [#container-crashes-on-startup]

Kapsayıcılar başladıktan hemen sonra kapanıyorsa, günlükleri kontrol edin:

```bash
docker compose logs api
```

Yaygın nedenler:

- Geçersiz `librechat.yaml` sözdizimi: [YAML Doğrulayıcı](/toolkit/yaml_checker) ile doğrulayın
- `.env` dosyası eksik -- `.env` dosyasının proje kök dizininde bulunduğundan emin olun
- Docker çalışmıyor -- Docker Desktop'ın açık ve çalışır durumda olduğundan emin olun

### Eksik Ortam Değişkenleri [#missing-environment-variables]

Özellikler beklendiği gibi çalışmıyorsa, gerekli ortam değişkenlerinin `.env` dosyanızda ayarlanmış olduğunu kontrol edin.

```bash
docker compose exec api env | grep -i "your_variable"
```

Tüm mevcut değişkenler ve varsayılan değerleri için [.env referansına](/docs/configuration/dotenv) bakın.
