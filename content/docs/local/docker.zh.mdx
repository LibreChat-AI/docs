对于大多数场景，Docker Compose 是推荐的安装方式，因为它简单、易用且可靠。

## 先决条件 [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

对于大多数用户，推荐使用 Docker Desktop。对于远程服务器安装，请参阅 [Ubuntu Docker 部署指南](/docs/remote/docker_linux)。

### 系统要求 [#system-requirements]

LibreChat 本身不运行 AI 模型,它会将请求发送到您配置的服务提供商,因此不需要 GPU。

LibreChat 的容器至少需要 1 GiB 内存和 1 vCPU,与服务器上的[最低要求](/docs/remote#minimum-requirements)相同。默认的 Docker Compose 文件会在启动 LibreChat 的同时,启动 MongoDB、Meilisearch(会话搜索)以及带有 PostgreSQL/pgvector 数据库的 RAG API(文件搜索)。它还定义了管理面板,但只有在 `.env` 中设置了 `ADMIN_PANEL_SESSION_SECRET` 后才会启动(参见[管理面板](/docs/features/admin_panel))。所有服务都运行时,为 Docker 分配至少 2 GB 内存,可以让运行更加流畅。

如果您使用 Docker Desktop,它会在自己的虚拟机中运行容器,因此您的计算机也必须满足 Docker Desktop 的要求。撰写本文时,这些要求包括:在 [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) 和 [Linux](https://docs.docker.com/desktop/setup/install/linux/) 上至少需要 4 GB 系统内存,在 [Windows](https://docs.docker.com/desktop/setup/install/windows-install/) 上需要 8 GB,并且需要启用硬件虚拟化。请查阅相关链接页面以获取最新要求。在 macOS、Linux 以及使用 Hyper-V 的 Windows 上,容器可用的内存在 Docker Desktop 的[资源设置](https://docs.docker.com/desktop/settings-and-maintenance/settings/)中配置;而使用 Windows WSL 2 后端时,则需要在 WSL 2 虚拟机上进行设置(参见 [Docker 的 WSL 指南](https://docs.docker.com/desktop/features/wsl/best-practices/))。直接安装在 Linux 上的 Docker Engine 会在主机上运行容器,没有单独的虚拟机。

如果您将 LibreChat 连接到在同一台机器上运行的模型,例如 [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama),请根据您所选模型来配置硬件。该模型运行时所需的内存远多于 LibreChat 本身,通常还需要 GPU。

<Callout type="warn" title="不支持 AVX 的 CPU">

LibreChat 默认 Docker Compose 配置中使用的 MongoDB 镜像需要 CPU 支持 AVX 指令集。在不支持 AVX 的旧款 x86 CPU 上(以及某些未向虚拟机客户机暴露 AVX 的虚拟机上),MongoDB 会在启动时崩溃。

**修复方法：** 创建 `docker-compose.override.yml` 文件，使用不需要 AVX 指令集的旧版 MongoDB 镜像：

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

请参阅 [Docker Override guide](/docs/configuration/docker_override) 以获取更多详细信息。

</Callout>

## 安装 [#installation]

<Steps>
  <Step>

### 克隆仓库 [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### 创建您的环境文件 [#create-your-environment-file]

```bash
cp .env.example .env
```

默认的 `.env` 文件可直接用于基本设置。如需深入配置，请参阅 [.env 参考](/docs/configuration/dotenv)。

<Callout type="info" title="Windows">

在 Windows 上，如果无法使用 `cp`，请使用 `copy .env.example .env`。

</Callout>

  </Step>
  <Step>

### 启动 LibreChat [#start-librechat]

```bash
docker compose up -d
```

首次启动会拉取 Docker 镜像，可能需要几分钟时间。后续启动速度会快得多。

  </Step>
  <Step>

### 验证并登录 [#verify-and-log-in]

打开您的浏览器并访问 [http://localhost:3080](http://localhost:3080)。您应该会看到 LibreChat 登录页面。

<Callout type="info" title="单租户部署中的第一个账户即为管理员">

在未限定范围的单租户部署中,你注册的第一个账户将成为管理员账户。系统不存在默认凭据;你在注册时自行创建用户名和密码。限定租户范围的部署不会自动将每个租户中的第一个用户提升为管理员;请通过受信任的管理流程来设置租户管理员。

</Callout>

点击 **Sign up** 创建您的账户,然后按照 [Your First Chat](/docs/quick_start/first_chat) 的指引添加模型 API 密钥并发送您的第一条消息。

  </Step>
</Steps>

## 挂载 librechat.yaml [#mounting-librechatyaml]

若要配合 Docker 使用自定义的 `librechat.yaml` 配置文件，你需要将其挂载为数据卷，以便容器能够访问它。

复制示例覆盖文件并进行编辑：

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

确保 `docker-compose.override.yml` 中的 librechat.yaml 卷挂载已取消注释：

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

重启以使更改生效：

```bash
docker compose down && docker compose up -d
```

有关包括从零开始创建文件在内的完整设置说明，请参阅 [librechat.yaml guide](/docs/configuration/librechat_yaml)。有关更多覆盖选项，请参阅 [Docker override guide](/docs/configuration/docker_override)。

## 更新 LibreChat [#updating-librechat]

以下命令将获取最新的 LibreChat 项目更改，包括对 docker compose 文件所做的任何必要更改，以及最新的预构建镜像。

<Callout type="info" title="权限">

根据您的环境权限，您可能需要在命令前加上 `sudo`。

</Callout>

<Callout type="info" title="更新脚本">

仓库中的 `npm run update:docker` 脚本会重新构建本地构建的镜像,但不会拉取默认 `docker-compose.yml` 所使用的预构建镜像,因此请按照以下手动步骤更新默认安装。

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## 故障排除 [#troubleshooting]

### 端口已被占用 [#port-already-in-use]

如果您看到类似 `bind: address already in use` 且涉及端口 3080 的错误，说明另一个应用程序正在占用该端口。

要么停止冲突的应用程序,要么更改 LibreChat 使用的端口。默认的 `docker-compose.yml` 会发布 `"${PORT}:${PORT}"`,而在覆盖文件中添加的端口会追加到该列表中,而不是替换它,因此仅使用覆盖文件并不能释放端口 3080。

最简单的解决方法是在 `.env` 文件中设置 `PORT`,这会同时更改 LibreChat 监听的端口和对外发布的端口:

```bash filename=".env"
PORT=3081
```

或者,如果使用 Docker Compose 2.24.4 或更高版本,可以在 `docker-compose.override.yml` 中使用 `!override` 标签替换已发布的端口(容器仍监听 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

使用 `docker compose down && docker compose up -d` 重新启动,然后改为访问 `http://localhost:3081`。

### 容器启动时崩溃 [#container-crashes-on-startup]

如果容器在启动后立即退出，请检查日志：

```bash
docker compose logs api
```

常见原因：

- 无效的 `librechat.yaml` 语法:请使用 [YAML 验证器](/toolkit/yaml_checker) 进行验证
- 缺少 `.env` 文件 —— 请确保项目根目录下存在 `.env` 文件
- Docker 未运行 -- 请确保 Docker Desktop 已打开并正在运行

### 缺少环境变量 [#missing-environment-variables]

如果功能未按预期运行，请检查 `.env` 文件中是否已设置所需的环境变量。

```bash
docker compose exec api env | grep -i "your_variable"
```

请参阅 [.env reference](/docs/configuration/dotenv) 以获取所有可用变量及其默认值。
