Volg deze richtlijnen om LibreChat te implementeren op Kubernetes met behulp van Helm, en pas deze naar behoefte aan voor jouw specifieke use case. Andere Helm charts die door de community zijn bijgedragen, staan hieronder vermeld in de sectie [Community Helm Charts](#community-helm-charts).

## Vereisten [#prerequisites]

* Een draaiend Kubernetes-cluster
* _Lokale_ installaties van `kubectl` en Helm

## Configuratie [#configuration]

1. Gebruik de [Credentials Generator](/toolkit/creds_generator) om veilige waarden te genereren voor `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET` en `MEILI_MASTER_KEY`.
Plaats deze in een Kubernetes Secret zoals hieronder (als je de naam van de secret wijzigt, vergeet dan niet om je Helm-waarden bij te werken):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

Gebruik permanente waarden en mount hetzelfde Secret in elke replica. Vertrouw niet op proces-lokale of kortstondige bestandssysteem-referenties in Kubernetes: het wijzigen van deze waarden kan sessies ongeldig maken en bestaande versleutelde records onleesbaar maken.

Het Secret met de naam `global.librechat.existingSecretName` moet bestaan voordat de LibreChat container start. Een ontbrekend of verkeerd gespeld Secret blokkeert het opstarten van de pod in plaats van terug te vallen op tijdelijke pod-lokale inloggegevens. De chart valideert de sleutels erin niet, dus zorg ervoor dat deze `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET` en `JWT_REFRESH_SECRET` bevat.

Stel `global.librechat.existingSecretName: ""` alleen in wanneer elke LibreChat-referentie op een andere manier wordt verstrekt. `librechat.configEnv` accepteert stringwaarden voor ConfigMap-data, terwijl `global.librechat.env` Kubernetes-omgevingsvermeldingen zoals `valueFrom.secretKeyRef` accepteert. Geef de voorkeur aan Secret-verwijzingen voor productie.

Gebundelde Meilisearch heeft een afzonderlijke afhankelijkheid van `meilisearch.auth.existingMasterKeySecret`, die standaard is ingesteld op `librechat-credentials-env` en dezelfde `MEILI_MASTER_KEY` moet bevatten die aan LibreChat is verstrekt. Het wissen van de LibreChat Secret-referentie wist deze Meilisearch-referentie niet. Als gebundelde Meilisearch is uitgeschakeld, configureer dan de externe zoekservice en de bijbehorende inloggegevens afzonderlijk.
2. Voeg aan dit zelfde secret alle vereiste API-sleutels voor LLM-providers toe:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <same generated value as above>
  CREDS_IV: <same generated value as above>
  JWT_SECRET: <same generated value as above>
  JWT_REFRESH_SECRET: <same generated value as above>
  MEILI_MASTER_KEY: <same generated value as above>
  OPENAI_API_KEY: <your secret value>
```
3. Pas het Secret toe op het Cluster:

Sla het volledige Secret-manifest op als `librechat-credentials.yaml`, gebruik de beoogde namespace en pas het vervolgens toe:

```bash
kubectl apply -f librechat-credentials.yaml
```

## Installeer Helm Chart [#install-helm-chart]

<Callout type="warning" title="Grafiek 2.0.16: lege config map">
De v0.8.8 chart-bron stelt `librechat.configEnv` standaard in op null. Als je geen ConfigMap-omgevingsoverschrijvingen hebt, stel deze dan expliciet in op `{}` in je values-bestand, of geef `--set-json 'librechat.configEnv={}'` mee aan `helm install` of `helm template`; anders kunnen de `dig`-lookups van de template mislukken. Bewaar inloggegevens in het benoemde Secret. Dit is een rendering-workaround, geen reden om de Secret-vereiste uit te schakelen.
</Callout>

Om de helm chart te installeren, voer je het volgende uit:

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>Ontwikkelingsversie</summary>

Voer in de hoofdmap van de repo het volgende uit:

`helm install <deployment-name> ./helm/librechat`
</details>

Net als bij andere Helm charts bestaat er een [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) die de standaardinstellingen beschrijft en aangeeft welke configuratieopties kunnen worden gewijzigd.

Maak een `values.yaml` bestand aan gevuld met de waarden die je wilt aanpassen ten opzichte van de standaardwaarden.

Installeer de Helm chart: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

Zodra de release live is en de service bereikbaar is, volg je [Your First Chat](/docs/quick_start/first_chat) om een account te registreren, een model API-sleutel toe te voegen en je eerste bericht te versturen.

## De Helm Chart verwijderen [#uninstall-the-helm-chart]

Om de Helm Chart te verwijderen: `helm uninstall <deployment-name>`

Voorbeeld: `helm uninstall librechat`

## Migreren van 1.x naar 2.x [#migrate-1x---2x]
Als je de chart vóór versie 2.x hebt gebruikt, moet je mogelijk de `value` structuur bijwerken.

1. Verplaats configuratie naar librechat.configEnv:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. Consolideer alle Secret-waarden naar één enkel Secret zoals beschreven in [Configuration Step 1](#configuration).
3. Om gebruik te maken van een externe MongoDB-instantie, raadpleeg je het [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) van de Chart, deactiveer je de componenten dienovereenkomstig en wijzig je de FQDN van de Mongodb-instantie. Dit wordt aanbevolen als er al gegevens bestaan in deze extern beheerde MongoDB-instantie.
