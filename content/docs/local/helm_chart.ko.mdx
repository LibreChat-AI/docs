Helm을 사용하여 Kubernetes에 LibreChat을 배포하려면 이 지침을 따르되, 특정 사용 사례에 맞게 필요에 따라 조정하십시오. 커뮤니티에서 제공한 다른 Helm 차트는 아래 [Community Helm Charts](#community-helm-charts) 섹션에 나열되어 있습니다.

## 필수 조건 [#prerequisites]

* 실행 중인 Kubernetes 클러스터
* `kubectl` 및 Helm의 _로컬_ 설치

## 구성 [#configuration]

1. [Credentials Generator](/toolkit/creds_generator)를 사용하여 `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET` 및 `MEILI_MASTER_KEY`에 대한 보안 값을 생성하세요.
다음과 같이 Kubernetes Secret에 배치하세요 (Secret 이름을 변경하는 경우 Helm values를 업데이트하는 것을 잊지 마세요):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

영구적인 값을 사용하고 동일한 Secret을 모든 복제본(replica)에 마운트하십시오. Kubernetes에서 프로세스 로컬 또는 일시적인 파일 시스템 자격 증명에 의존하지 마십시오. 이러한 값을 변경하면 세션이 무효화되고 기존의 암호화된 레코드를 읽을 수 없게 될 수 있습니다.

`global.librechat.existingSecretName`으로 지정된 Secret은 LibreChat 컨테이너가 시작되기 전에 존재해야 합니다. 지정된 Secret이 없거나 이름이 잘못된 경우, 임시 파드 로컬 자격 증명으로 대체되지 않고 파드 시작이 차단됩니다. 차트는 내부 키를 검증하지 않으므로 `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET`이 포함되어 있는지 확인하십시오.

모든 LibreChat 자격 증명이 다른 방식으로 제공되는 경우에만 `global.librechat.existingSecretName: ""`를 설정하십시오. `librechat.configEnv`는 ConfigMap 데이터를 위한 문자열 값을 허용하며, `global.librechat.env`는 `valueFrom.secretKeyRef`와 같은 Kubernetes 환경 항목을 허용합니다. 프로덕션 환경에서는 Secret 참조를 사용하는 것을 권장합니다.

번들로 제공되는 Meilisearch는 `meilisearch.auth.existingMasterKeySecret`에 대한 별도의 의존성을 가지며, 기본값은 `librechat-credentials-env`입니다. 이 값은 LibreChat에 제공된 `MEILI_MASTER_KEY`와 동일해야 합니다. LibreChat Secret 참조를 삭제해도 이 Meilisearch 참조는 삭제되지 않습니다. 번들로 제공되는 Meilisearch를 비활성화한 경우, 외부 검색 서비스와 해당 자격 증명을 별도로 구성하십시오.

2. 동일한 Secret에 LLM 공급자에 필요한 API 키를 추가하십시오:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
. . . .

  OPENAI_API_KEY: <your secret value>
```

## Helm Chart 설치 [#install-helm-chart]

helm chart를 설치하려면 다음을 실행하세요:

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>개발 버전</summary>

저장소의 루트 디렉토리에서 다음을 실행하세요:

`helm install <deployment-name> ./helm/librechat`
</details>

다른 Helm 차트와 마찬가지로, 기본 설정을 설명하고 수정 가능한 구성 옵션을 나타내는 [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml)이 존재합니다.

기본값에서 수정하려는 값들로 채워진 `values.yaml` 파일을 생성하세요.

Helm 차트 설치: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

릴리스가 완료되고 서비스에 접속할 수 있게 되면, [첫 채팅 시작하기](/docs/quick_start/first_chat)를 따라 계정을 등록하고, 모델 API 키를 추가한 뒤 첫 메시지를 보내보세요.

## Helm Chart 제거하기 [#uninstall-the-helm-chart]

Helm Chart를 제거하려면 다음 명령어를 실행하세요: `helm uninstall <deployment-name>`

예시: `helm uninstall librechat`

## 1.x -> 2.x 마이그레이션 [#migrate-1x---2x]
2.x 버전 이전의 차트를 사용했다면 `value` 구조를 업데이트해야 할 수도 있습니다.

1. 설정을 librechat.configEnv로 이동:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. [Configuration Step 1](#configuration)에 설명된 대로 모든 Secret 값을 단일 Secret으로 통합하세요.
3. 외부 MongoDB 인스턴스를 활용하려면 Chart의 [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml)을 참조하여 해당 구성 요소를 비활성화하고 Mongodb 인스턴스의 FQDN을 변경하십시오. 이 방법은 외부에서 관리되는 MongoDB 인스턴스에 이미 데이터가 존재하는 경우 권장됩니다.
