Silakan ikuti panduan ini untuk men-deploy LibreChat pada Kubernetes menggunakan Helm, dengan menyesuaikan kebutuhan sesuai kasus penggunaan spesifik Anda. Helm chart lain yang dikontribusikan oleh komunitas tercantum di bawah ini pada bagian [Community Helm Charts](#community-helm-charts).

## Prasyarat [#prerequisites]

* Klaster Kubernetes yang sedang berjalan
* Instalasi _lokal_ `kubectl` dan Helm

## Konfigurasi [#configuration]

1. Gunakan [Credentials Generator](/toolkit/creds_generator) untuk membuat nilai aman bagi `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET`, dan `MEILI_MASTER_KEY`.
Tempatkan nilai-nilai tersebut ke dalam Kubernetes Secret seperti ini (jika Anda mengubah nama secret, jangan lupa untuk memperbarui nilai Helm Anda):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

Gunakan nilai permanen dan mount Secret yang sama ke setiap replika. Jangan mengandalkan kredensial sistem berkas lokal proses atau ephemeral di Kubernetes: mengubah nilai-nilai ini dapat membatalkan sesi dan membuat catatan terenkripsi yang ada menjadi tidak dapat dibaca.

Secret yang diberi nama oleh `global.librechat.existingSecretName` harus ada sebelum kontainer LibreChat dimulai. Secret yang hilang atau salah penulisan akan menghalangi startup pod alih-alih kembali ke kredensial lokal pod sementara. Chart ini tidak memvalidasi kunci di dalamnya, jadi pastikan Secret tersebut berisi `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, dan `JWT_REFRESH_SECRET`.

Atur `global.librechat.existingSecretName: ""` hanya jika setiap kredensial LibreChat disediakan melalui cara lain. `librechat.configEnv` menerima nilai string untuk data ConfigMap, sementara `global.librechat.env` menerima entri lingkungan Kubernetes seperti `valueFrom.secretKeyRef`. Gunakan referensi Secret untuk produksi.

Meilisearch yang dibundel memiliki dependensi terpisah pada `meilisearch.auth.existingMasterKeySecret`, yang secara default adalah `librechat-credentials-env` dan harus berisi `MEILI_MASTER_KEY` yang sama dengan yang diberikan ke LibreChat. Menghapus referensi Secret LibreChat tidak menghapus referensi Meilisearch ini. Jika Meilisearch yang dibundel dinonaktifkan, konfigurasikan layanan pencarian eksternal dan kredensialnya secara terpisah.
2. Tambahkan ke secret yang sama ini semua kunci API yang diperlukan untuk penyedia LLM:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
. . . .

  OPENAI_API_KEY: <your secret value>
```

## Instal Helm Chart [#install-helm-chart]

Untuk menginstal helm chart, jalankan:

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>Versi pengembangan</summary>

Di direktori root repo, jalankan:

`helm install <deployment-name> ./helm/librechat`
</details>

Mirip dengan chart Helm lainnya, terdapat [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) yang menguraikan pengaturan default dan menunjukkan opsi konfigurasi mana yang dapat dimodifikasi.

Buat file `values.yaml` yang diisi dengan nilai-nilai yang ingin Anda ubah dari nilai default.

Instal Helm chart: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

Setelah rilis aktif dan layanan dapat diakses, ikuti [Obrolan Pertama Anda](/docs/quick_start/first_chat) untuk mendaftarkan akun, menambahkan API key model, dan mengirim pesan pertama Anda.

## Menghapus Helm Chart [#uninstall-the-helm-chart]

Untuk menghapus Helm Chart: `helm uninstall <deployment-name>`

Contoh: `helm uninstall librechat`

## Migrasi 1.x -> 2.x [#migrate-1x---2x]
Jika Anda menggunakan chart sebelum versi 2.x, Anda mungkin perlu memperbarui struktur `value`.

1. Pindahkan Konfigurasi ke librechat.configEnv:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. Gabungkan semua nilai Secret menjadi satu Secret sebagaimana dijelaskan dalam [Configuration Step 1](#configuration).
3. Untuk memanfaatkan instans MongoDB eksternal, lihat [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) dari Chart tersebut, nonaktifkan komponen yang sesuai, dan ubah FQDN dari instans MongoDB. Hal ini direkomendasikan jika data sudah ada di dalam instans MongoDB yang dikelola secara eksternal ini.
