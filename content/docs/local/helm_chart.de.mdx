Bitte befolge diese Anleitung, um LibreChat mit Helm auf Kubernetes bereitzustellen, und passe sie bei Bedarf an deinen spezifischen Anwendungsfall an. Weitere von der Community bereitgestellte Helm Charts sind unten im Abschnitt [Community Helm Charts](#community-helm-charts) aufgeführt.

## Voraussetzungen [#prerequisites]

* Ein laufender Kubernetes-Cluster
* _Lokale_ Installationen von `kubectl` und Helm

## Konfiguration [#configuration]

1. Verwenden Sie den [Credentials Generator](/toolkit/creds_generator), um sichere Werte für `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET` und `MEILI_MASTER_KEY` zu generieren.
Platzieren Sie diese wie folgt in einem Kubernetes Secret (wenn Sie den Namen des Secrets ändern, denken Sie daran, Ihre Helm-Werte zu aktualisieren):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

Verwenden Sie permanente Werte und mounten Sie dasselbe Secret in jedes Replikat. Verlassen Sie sich in Kubernetes nicht auf prozesslokale oder ephemere Dateisystem-Anmeldeinformationen: Das Ändern dieser Werte kann Sitzungen ungültig machen und bestehende verschlüsselte Datensätze unlesbar machen.

Das unter `global.librechat.existingSecretName` angegebene Secret muss existieren, bevor der LibreChat-Container startet. Ein fehlendes oder falsch geschriebenes Secret blockiert den Pod-Start, anstatt auf temporäre, Pod-lokale Anmeldedaten zurückzugreifen. Das Chart validiert die darin enthaltenen Schlüssel nicht; stellen Sie daher sicher, dass es `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET` und `JWT_REFRESH_SECRET` enthält.

Setzen Sie `global.librechat.existingSecretName: ""` nur dann, wenn alle LibreChat-Anmeldedaten auf andere Weise bereitgestellt werden. `librechat.configEnv` akzeptiert String-Werte für ConfigMap-Daten, während `global.librechat.env` Kubernetes-Umgebungseinträge wie `valueFrom.secretKeyRef` akzeptiert. Bevorzugen Sie Secret-Referenzen für die Produktion.

Das gebündelte Meilisearch hat eine separate Abhängigkeit von `meilisearch.auth.existingMasterKeySecret`, die standardmäßig auf `librechat-credentials-env` eingestellt ist und denselben `MEILI_MASTER_KEY` enthalten muss, der auch für LibreChat bereitgestellt wurde. Das Löschen der LibreChat-Secret-Referenz löscht diese Meilisearch-Referenz nicht. Wenn das gebündelte Meilisearch deaktiviert ist, konfigurieren Sie den externen Suchdienst und dessen Anmeldedaten separat.
2. Fügen Sie demselben Secret alle erforderlichen API-Schlüssel für LLM-Anbieter hinzu:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
. . . .

  OPENAI_API_KEY: <your secret value>
```

## Helm Chart installieren [#install-helm-chart]

Um das helm chart zu installieren, führen Sie Folgendes aus:

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>Entwicklungsversion</summary>

Führen Sie im Stammverzeichnis des Repositories Folgendes aus:

`helm install <deployment-name> ./helm/librechat`
</details>

Ähnlich wie bei anderen Helm-Charts gibt es eine [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml), die die Standardeinstellungen beschreibt und angibt, welche Konfigurationsoptionen geändert werden können.

Erstellen Sie eine `values.yaml`-Datei, die mit den Werten gefüllt ist, die Sie gegenüber den Standardwerten ändern möchten.

Installieren Sie das Helm-Chart: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

Sobald das Release bereitgestellt und der Dienst erreichbar ist, folgen Sie [Your First Chat](/docs/quick_start/first_chat), um ein Konto zu registrieren, einen Modell-API-Schlüssel hinzuzufügen und Ihre erste Nachricht zu senden.

## Deinstallieren des Helm Charts [#uninstall-the-helm-chart]

Um das Helm Chart zu deinstallieren: `helm uninstall <deployment-name>`

Beispiel: `helm uninstall librechat`

## Migration von 1.x -> 2.x [#migrate-1x---2x]
Wenn Sie das Chart vor der Version 2.x verwendet haben, müssen Sie möglicherweise die `value`-Struktur aktualisieren.

1. Verschiebe die Konfiguration nach librechat.configEnv:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. Fassen Sie alle Secret-Werte zu einem einzigen Secret zusammen, wie in [Konfigurationsschritt 1](#configuration) beschrieben.
3. Um eine externe MongoDB-Instanz zu nutzen, beziehen Sie sich auf die [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) des Charts, deaktivieren Sie die entsprechenden Komponenten und ändern Sie den FQDN der MongoDB-Instanz. Dies wird empfohlen, wenn bereits Daten in dieser extern verwalteten MongoDB-Instanz vorhanden sind.
