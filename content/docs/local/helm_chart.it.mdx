Si prega di seguire questa guida per distribuire LibreChat su Kubernetes utilizzando Helm, apportando le modifiche necessarie per il proprio caso d'uso specifico. Altri Helm chart forniti dalla community sono elencati di seguito nella sezione [Community Helm Charts](#community-helm-charts).

## Prerequisiti [#prerequisites]

* Un cluster Kubernetes in esecuzione
* Installazioni _locali_ di `kubectl` e Helm

## Configurazione [#configuration]

1. Utilizza il [Credentials Generator](/toolkit/creds_generator) per generare valori sicuri per `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, `JWT_REFRESH_SECRET` e `MEILI_MASTER_KEY`.
Inseriscili in un Kubernetes Secret come questo (se modifichi il nome del secret, ricordati di aggiornare i tuoi valori Helm):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

Utilizza valori permanenti e monta lo stesso Secret in ogni replica. Non fare affidamento su credenziali locali al processo o su file system effimeri in Kubernetes: la modifica di questi valori può invalidare le sessioni e rendere illeggibili i record crittografati esistenti.

Il Secret denominato da `global.librechat.existingSecretName` deve esistere prima dell'avvio del container LibreChat. Un Secret mancante o con un nome errato blocca l'avvio del pod invece di ripiegare su credenziali temporanee locali al pod. Il chart non convalida le chiavi al suo interno, quindi assicurati che contenga `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET` e `JWT_REFRESH_SECRET`.

Imposta `global.librechat.existingSecretName: ""` solo quando ogni credenziale di LibreChat viene fornita in un altro modo. `librechat.configEnv` accetta valori stringa per i dati della ConfigMap, mentre `global.librechat.env` accetta voci di ambiente Kubernetes come `valueFrom.secretKeyRef`. Per la produzione, preferisci i riferimenti ai Secret.

Il Meilisearch in bundle ha una dipendenza separata su `meilisearch.auth.existingMasterKeySecret`, che ha come valore predefinito `librechat-credentials-env` e deve contenere la stessa `MEILI_MASTER_KEY` fornita a LibreChat. La cancellazione del riferimento al Secret di LibreChat non cancella questo riferimento di Meilisearch. Se il Meilisearch in bundle è disabilitato, configura il servizio di ricerca esterno e le sue credenziali separatamente.
2. Aggiungi a questo stesso secret tutte le chiavi API richieste per i provider LLM:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <same generated value as above>
  CREDS_IV: <same generated value as above>
  JWT_SECRET: <same generated value as above>
  JWT_REFRESH_SECRET: <same generated value as above>
  MEILI_MASTER_KEY: <same generated value as above>
  OPENAI_API_KEY: <your secret value>
```
3. Applica il Secret al Cluster:

Salva il manifest Secret completo come `librechat-credentials.yaml`, utilizzando il namespace previsto, quindi applicalo:

```bash
kubectl apply -f librechat-credentials.yaml
```

## Installa Helm Chart [#install-helm-chart]

<Callout type="warning" title="Chart 2.0.16: mappa di configurazione vuota">
Il chart v0.8.8 imposta `librechat.configEnv` su null come valore predefinito. Se non hai override dell'ambiente tramite ConfigMap, impostalo esplicitamente su `{}` nel tuo file values, oppure passa `--set-json 'librechat.configEnv={}'` a `helm install` o `helm template`; in caso contrario, le ricerche `dig` del template potrebbero fallire. Mantieni le credenziali nel Secret denominato. Questo è un workaround di rendering, non un motivo per disabilitare il requisito del Secret.
</Callout>

Per installare l'helm chart esegui:

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>Versione di sviluppo</summary>

Nella directory root del repository, esegui:

`helm install <deployment-name> ./helm/librechat`
</details>

Similmente ad altri Helm chart, esiste un [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) che delinea le impostazioni predefinite e indica quali opzioni di configurazione possono essere modificate.

Crea un file `values.yaml` popolato con i valori che desideri modificare rispetto a quelli predefiniti.

Installa l'Helm chart: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

Una volta che la release è attiva e il servizio è raggiungibile, segui [La tua prima chat](/docs/quick_start/first_chat) per registrare un account, aggiungere una API key del modello e inviare il tuo primo messaggio.

## Disinstallare l'Helm Chart [#uninstall-the-helm-chart]

Per disinstallare l'Helm Chart: `helm uninstall <deployment-name>`

Esempio: `helm uninstall librechat`

## Migrazione da 1.x a 2.x [#migrate-1x---2x]
Se hai utilizzato il chart prima della versione 2.x, potresti dover aggiornare la struttura `value`.

1. Sposta la configurazione in librechat.configEnv:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. Consolidare tutti i valori Secret in un unico Secret come descritto nel [Passaggio di configurazione 1](#configuration).
3. Per utilizzare un'istanza MongoDB esterna, fare riferimento al [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml) del Chart, disattivare i componenti di conseguenza e modificare l'FQDN dell'istanza MongoDB. Questa operazione è consigliata se i dati esistono già in questa istanza MongoDB gestita esternamente.
