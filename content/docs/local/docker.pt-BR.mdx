Para a maioria dos cenários, o Docker Compose é o método de instalação recomendado devido à sua simplicidade, facilidade de uso e confiabilidade.

## Pré-requisitos [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

O Docker Desktop é recomendado para a maioria dos usuários. Para instalações em servidores remotos, consulte o [Guia de Implantação do Docker no Ubuntu](/docs/remote/docker_linux).

### Requisitos do Sistema [#system-requirements]

O LibreChat não executa modelos de IA por conta própria; ele envia requisições aos provedores que você configura, por isso não precisa de uma GPU.

Os contêineres do LibreChat precisam de pelo menos 1 GiB de RAM e 1 vCPU, o mesmo [mínimo](/docs/remote#minimum-requirements) exigido em um servidor. O arquivo padrão do Docker Compose inicia o MongoDB, o Meilisearch (pesquisa de conversas) e a RAG API com um banco de dados PostgreSQL/pgvector (pesquisa em arquivos) junto com o LibreChat. Ele também define o painel de administração, que só é iniciado depois que `ADMIN_PANEL_SESSION_SECRET` for definido no `.env` (consulte [Admin Panel](/docs/features/admin_panel)). Com tudo em execução, disponibilize pelo menos 2 GB de memória para o Docker para um funcionamento mais estável.

Se você usa o Docker Desktop, ele executa os contêineres dentro de sua própria máquina virtual, então seu computador também precisa atender aos requisitos do Docker Desktop. No momento da redação, eles exigem pelo menos 4 GB de RAM do sistema no [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) e no [Linux](https://docs.docker.com/desktop/setup/install/linux/), e 8 GB no [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), além de virtualização de hardware. Consulte as páginas vinculadas para ver os requisitos atuais. A memória disponível para os contêineres é definida nas [configurações de recursos](https://docs.docker.com/desktop/settings-and-maintenance/settings/) do Docker Desktop no macOS, no Linux e no Windows com Hyper-V; com o backend WSL 2 do Windows, ela é definida na máquina virtual do WSL 2 (veja [as orientações do Docker sobre WSL](https://docs.docker.com/desktop/features/wsl/best-practices/)). O Docker Engine instalado diretamente no Linux executa os contêineres no host e não possui uma máquina virtual separada.

Se você conectar o LibreChat a modelos executados na mesma máquina, como o [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), dimensione o hardware de acordo com o modelo escolhido. O runtime do modelo precisa de muito mais memória, e frequentemente de uma GPU, do que o próprio LibreChat.

<Callout type="warn" title="CPUs sem suporte a AVX">

A imagem do MongoDB usada na configuração padrão do Docker Compose do LibreChat requer uma CPU com suporte às instruções AVX. Em CPUs x86 mais antigas, sem AVX (e em algumas máquinas virtuais que não expõem AVX para o sistema convidado), o MongoDB falha ao iniciar.

**Correção:** Crie um `docker-compose.override.yml` para usar uma imagem mais antiga do MongoDB que não exige AVX:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Veja o [guia de Docker Override](/docs/configuration/docker_override) para mais detalhes.

</Callout>

## Instalação [#installation]

<Steps>
  <Step>

### Clone o Repositório [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Crie seu arquivo de ambiente [#create-your-environment-file]

```bash
cp .env.example .env
```

O arquivo `.env` padrão funciona imediatamente para uma configuração básica. Para uma configuração detalhada, consulte a [referência do .env](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

No Windows, use `copy .env.example .env` se o comando `cp` não estiver disponível.

</Callout>

  </Step>
  <Step>

### Iniciar o LibreChat [#start-librechat]

```bash
docker compose up -d
```

A primeira inicialização baixa as imagens Docker e pode levar alguns minutos. As inicializações subsequentes são muito mais rápidas.

  </Step>
  <Step>

### Verificar e Fazer Login [#verify-and-log-in]

Abra seu navegador e acesse [http://localhost:3080](http://localhost:3080). Você deverá ver a página de login do LibreChat.

<Callout type="info" title="Primeira conta = Admin em implantações de locatário único">

Em uma implantação de locatário único sem escopo, a primeira conta que você registrar se torna a conta de administrador. Não há credenciais padrão; você cria seu próprio nome de usuário e senha durante o registro. Implantações com escopo de locatário não promovem automaticamente o primeiro usuário de cada locatário; provisione os administradores de locatário por meio de um fluxo administrativo confiável.

</Callout>

Clique em **Sign up** para criar sua conta e, em seguida, siga [Your First Chat](/docs/quick_start/first_chat) para adicionar uma chave de API de modelo e enviar sua primeira mensagem.

  </Step>
</Steps>

## Montando o librechat.yaml [#mounting-librechatyaml]

Para usar um arquivo de configuração `librechat.yaml` personalizado com Docker, você precisa montá-lo como um volume para que o container possa acessá-lo.

Copie o arquivo de exemplo de substituição (override) e edite-o:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Certifique-se de que a montagem de volume do librechat.yaml esteja descomentada em `docker-compose.override.yml`:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Reinicie para que as alterações entrem em vigor:

```bash
docker compose down && docker compose up -d
```

Para instruções completas de configuração, incluindo a criação do arquivo do zero, consulte o [guia do librechat.yaml](/docs/configuration/librechat_yaml). Para mais opções de substituição, consulte o [guia de substituição do Docker](/docs/configuration/docker_override).

## Atualizando o LibreChat [#updating-librechat]

Os comandos a seguir buscarão as alterações mais recentes do projeto LibreChat, incluindo quaisquer mudanças necessárias nos arquivos docker compose, bem como as imagens pré-compiladas mais recentes.

<Callout type="info" title="Permissões">

Você pode precisar prefixar comandos com `sudo` de acordo com as permissões do seu ambiente.

</Callout>

<Callout type="info" title="Script de atualização">

O script `npm run update:docker` do repositório reconstrói as imagens criadas localmente, mas não baixa as imagens pré-construídas que o `docker-compose.yml` padrão utiliza. Por isso, siga os passos manuais abaixo para atualizar uma instalação padrão.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Solução de problemas [#troubleshooting]

### Porta Já em Uso [#port-already-in-use]

Se você vir um erro como `bind: address already in use` para a porta 3080, outro aplicativo está usando essa porta.

Pare a aplicação que causa o conflito ou altere a porta usada pelo LibreChat. O `docker-compose.yml` padrão publica `"${PORT}:${PORT}"`, e as portas adicionadas em um arquivo de substituição (override) são acrescentadas a essa lista em vez de substituí-la; por isso, um arquivo de override sozinho não libera a porta 3080.

A solução mais simples é definir `PORT` no seu arquivo `.env`, o que altera tanto a porta em que o LibreChat escuta quanto a porta publicada:

```bash filename=".env"
PORT=3081
```

Alternativamente, com o Docker Compose 2.24.4 ou posterior, substitua a porta publicada em `docker-compose.override.yml` pela tag `!override` (o contêiner continua escutando na porta 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Reinicie com `docker compose down && docker compose up -d` e, em seguida, acesse `http://localhost:3081`.

### O container trava na inicialização [#container-crashes-on-startup]

Se os containers encerrarem imediatamente após a inicialização, verifique os logs:

```bash
docker compose logs api
```

Causas comuns:

- Sintaxe inválida no `librechat.yaml`: valide com o [Validador de YAML](/toolkit/yaml_checker)
- Arquivo `.env` ausente -- certifique-se de que o `.env` exista na raiz do projeto
- Docker não está em execução -- certifique-se de que o Docker Desktop esteja aberto e em execução

### Variáveis de Ambiente Ausentes [#missing-environment-variables]

Se os recursos não estiverem funcionando como esperado, verifique se as variáveis de ambiente necessárias estão definidas no seu `.env` file.

```bash
docker compose exec api env | grep -i "your_variable"
```

Veja a [referência do .env](/docs/configuration/dotenv) para todas as variáveis disponíveis e seus valores padrão.
