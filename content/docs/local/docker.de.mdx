Für die meisten Szenarien ist Docker Compose aufgrund seiner Einfachheit, Benutzerfreundlichkeit und Zuverlässigkeit die empfohlene Installationsmethode.

## Voraussetzungen [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop wird für die meisten Benutzer empfohlen. Für Installationen auf Remote-Servern siehe den [Ubuntu Docker Deployment Guide](/docs/remote/docker_linux).

### Systemanforderungen [#system-requirements]

LibreChat führt KI-Modelle nicht selbst aus; es sendet Anfragen an die von Ihnen konfigurierten Anbieter, daher wird keine GPU benötigt.

LibreChat-Container benötigen mindestens 1 GiB RAM und 1 vCPU, dasselbe [Minimum](/docs/remote#minimum-requirements) wie auf einem Server. Die Standard-Docker-Compose-Datei startet neben LibreChat auch MongoDB, Meilisearch (Konversationssuche) und die RAG API mit einer PostgreSQL/pgvector-Datenbank (Dateisuche). Außerdem definiert sie das Admin-Panel, das erst gestartet wird, wenn `ADMIN_PANEL_SESSION_SECRET` in `.env` gesetzt ist (siehe [Admin Panel](/docs/features/admin_panel)). Wenn alle Dienste laufen, sollten Sie Docker für einen reibungsloseren Betrieb mindestens 2 GB Arbeitsspeicher zur Verfügung stellen.

Wenn Sie Docker Desktop verwenden, werden Container innerhalb einer eigenen virtuellen Maschine ausgeführt. Daher muss auch Ihr Computer die Anforderungen von Docker Desktop erfüllen. Zum Zeitpunkt der Erstellung dieser Dokumentation sind das mindestens 4 GB Systemspeicher unter [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) und [Linux](https://docs.docker.com/desktop/setup/install/linux/) sowie 8 GB unter [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), zusätzlich zur Hardware-Virtualisierung. Die aktuellen Anforderungen finden Sie auf den verlinkten Seiten. Der den Containern zur Verfügung stehende Arbeitsspeicher wird unter macOS, Linux und Windows mit Hyper-V in den [Ressourceneinstellungen](https://docs.docker.com/desktop/settings-and-maintenance/settings/) von Docker Desktop festgelegt. Mit dem Windows-WSL-2-Backend wird er stattdessen für die WSL-2-virtuelle Maschine konfiguriert (siehe [Dockers WSL-Empfehlungen](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine, die direkt unter Linux installiert ist, führt Container auf dem Host aus und besitzt keine separate virtuelle Maschine.

Wenn du LibreChat mit Modellen verbindest, die auf derselben Maschine laufen, etwa [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), dimensioniere die Hardware passend zu dem Modell, das du auswählst. Die Laufzeitumgebung des Modells benötigt deutlich mehr Arbeitsspeicher, und oft eine GPU, als LibreChat selbst.

<Callout type="warn" title="CPUs ohne AVX-Unterstützung">

Das MongoDB-Image, das im Standard-Docker-Compose-Setup von LibreChat verwendet wird, benötigt eine CPU mit AVX-Befehlssatzerweiterungen. Auf älteren x86-CPUs ohne AVX (sowie auf einigen virtuellen Maschinen, die AVX nicht an das Gastsystem weitergeben) stürzt MongoDB beim Start ab.

**Fix:** Erstellen Sie eine `docker-compose.override.yml`, um ein älteres MongoDB-Image zu verwenden, das kein AVX benötigt:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Weitere Details finden Sie im [Docker Override guide](/docs/configuration/docker_override).

</Callout>

## Installation [#installation]

<Steps>
  <Step>

### Das Repository klonen [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Erstellen Ihrer Umgebungsdatei [#create-your-environment-file]

```bash
cp .env.example .env
```

Die standardmäßige `.env` Datei funktioniert für eine grundlegende Einrichtung sofort. Für eine detaillierte Konfiguration siehe die [.env Referenz](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

Verwenden Sie unter Windows `copy .env.example .env`, falls `cp` nicht verfügbar ist.

</Callout>

  </Step>
  <Step>

### LibreChat starten [#start-librechat]

```bash
docker compose up -d
```

Der erste Start lädt Docker-Images herunter und kann einige Minuten dauern. Nachfolgende Starts sind wesentlich schneller.

  </Step>
  <Step>

### Überprüfen und Anmelden [#verify-and-log-in]

Öffnen Sie Ihren Browser und besuchen Sie [http://localhost:3080](http://localhost:3080). Sie sollten die Anmeldeseite von LibreChat sehen.

<Callout type="info" title="Erstes Konto = Admin bei Single-Tenant-Bereitstellungen">

In einer nicht eingeschränkten Single-Tenant-Bereitstellung wird das erste registrierte Konto zum Administratorkonto. Es gibt keine Standardzugangsdaten; Sie erstellen Ihren eigenen Benutzernamen und Ihr eigenes Passwort während der Registrierung. Mandantenbezogene Bereitstellungen stufen den ersten Benutzer jedes Mandanten nicht automatisch hoch; stellen Sie Mandantenadministratoren stattdessen über einen vertrauenswürdigen administrativen Ablauf bereit.

</Callout>

Klicken Sie auf **Sign up**, um Ihr Konto zu erstellen, und folgen Sie anschließend [Your First Chat](/docs/quick_start/first_chat), um einen Modell-API-Schlüssel hinzuzufügen und Ihre erste Nachricht zu senden.

  </Step>
</Steps>

## Einbinden der librechat.yaml [#mounting-librechatyaml]

Um eine benutzerdefinierte `librechat.yaml` Konfigurationsdatei mit Docker zu verwenden, müssen Sie diese als Volume einbinden, damit der Container darauf zugreifen kann.

Kopieren Sie die Beispiel-Override-Datei und bearbeiten Sie diese:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Stellen Sie sicher, dass die librechat.yaml Volume-Einbindung in `docker-compose.override.yml` auskommentiert ist:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Starten Sie neu, damit die Änderungen wirksam werden:

```bash
docker compose down && docker compose up -d
```

Für vollständige Einrichtungsanweisungen, einschließlich der Erstellung der Datei von Grund auf, siehe den [librechat.yaml guide](/docs/configuration/librechat_yaml). Weitere Überschreibungsoptionen finden Sie im [Docker override guide](/docs/configuration/docker_override).

## Aktualisieren von LibreChat [#updating-librechat]

Die folgenden Befehle rufen die neuesten Änderungen am LibreChat-Projekt ab, einschließlich aller notwendigen Änderungen an den Docker-Compose-Dateien sowie der neuesten vorab erstellten Images.

<Callout type="info" title="Berechtigungen">

Möglicherweise müssen Sie Befehle gemäß Ihren Berechtigungen in der Umgebung mit `sudo` voranstellen.

</Callout>

<Callout type="info" title="Update-Skript">

Das Skript `npm run update:docker` des Repositorys erstellt lokal gebaute Images neu, lädt jedoch nicht die vorgefertigten Images, die die Standard-`docker-compose.yml` verwendet. Befolge daher die folgenden manuellen Schritte, um eine Standardinstallation zu aktualisieren.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Fehlerbehebung [#troubleshooting]

### Port wird bereits verwendet [#port-already-in-use]

Wenn Sie einen Fehler wie `bind: address already in use` für Port 3080 sehen, verwendet eine andere Anwendung diesen Port.

Entweder die kollidierende Anwendung beenden oder den Port ändern, den LibreChat verwendet. Die Standard-`docker-compose.yml` veröffentlicht `"${PORT}:${PORT}"`, und Ports, die in einer Override-Datei hinzugefügt werden, werden an diese Liste angehängt, anstatt sie zu ersetzen. Ein Override allein gibt daher Port 3080 nicht frei.

Der einfachste Weg ist, `PORT` in deiner `.env`-Datei zu setzen. Dadurch ändern sich sowohl der Port, auf dem LibreChat lauscht, als auch der veröffentlichte Port:

```bash filename=".env"
PORT=3081
```

Alternativ kannst du bei Docker Compose 2.24.4 oder neuer den veröffentlichten Port in `docker-compose.override.yml` mit dem Tag `!override` ersetzen (der Container lauscht weiterhin auf 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Starte neu mit `docker compose down && docker compose up -d` und rufe dann stattdessen `http://localhost:3081` auf.

### Container stürzt beim Start ab [#container-crashes-on-startup]

Wenn Container unmittelbar nach dem Start beendet werden, überprüfen Sie die Logs:

```bash
docker compose logs api
```

Häufige Ursachen:

- Ungültige `librechat.yaml`-Syntax: Validiere sie mit dem [YAML Validator](/toolkit/yaml_checker)
- Fehlende `.env`-Datei -- stellen Sie sicher, dass `.env` im Projektstammverzeichnis vorhanden ist
- Docker läuft nicht – stelle sicher, dass Docker Desktop geöffnet ist und läuft

### Fehlende Umgebungsvariablen [#missing-environment-variables]

Wenn Funktionen nicht wie erwartet funktionieren, überprüfen Sie, ob die erforderlichen Umgebungsvariablen in Ihrer `.env` Datei gesetzt sind.

```bash
docker compose exec api env | grep -i "your_variable"
```

Siehe die [.env reference](/docs/configuration/dotenv) für alle verfügbaren Variablen und deren Standardwerte.
