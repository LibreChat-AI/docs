Đối với hầu hết các trường hợp, Docker Compose là phương pháp cài đặt được khuyến nghị nhờ sự đơn giản, dễ sử dụng và độ tin cậy của nó.

## Điều kiện tiên quyết [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop được khuyến nghị cho hầu hết người dùng. Đối với các cài đặt trên máy chủ từ xa, hãy xem [Hướng dẫn triển khai Docker trên Ubuntu](/docs/remote/docker_linux).

### Yêu cầu hệ thống [#system-requirements]

LibreChat không tự chạy các mô hình AI; nó gửi yêu cầu đến các nhà cung cấp mà bạn đã cấu hình, vì vậy không cần GPU.

LibreChat của bạn cần ít nhất 1 GiB RAM và 1 vCPU cho các container, giống với [yêu cầu tối thiểu](/docs/remote#minimum-requirements) trên máy chủ. Tệp Docker Compose mặc định khởi động MongoDB, Meilisearch (tìm kiếm cuộc trò chuyện) và RAG API cùng với cơ sở dữ liệu PostgreSQL/pgvector (tìm kiếm tệp) bên cạnh LibreChat. Tệp này cũng định nghĩa bảng quản trị, bảng này chỉ khởi động sau khi `ADMIN_PANEL_SESSION_SECRET` được thiết lập trong `.env` (xem [Admin Panel](/docs/features/admin_panel)). Khi mọi thứ đang chạy, hãy đảm bảo Docker có sẵn ít nhất 2 GB bộ nhớ để hoạt động ổn định hơn.

Nếu bạn sử dụng Docker Desktop, ứng dụng này chạy các container bên trong máy ảo riêng của nó, vì vậy máy tính của bạn cũng phải đáp ứng các yêu cầu của Docker Desktop. Tại thời điểm viết tài liệu này, các yêu cầu tối thiểu là 4 GB RAM hệ thống trên [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) và [Linux](https://docs.docker.com/desktop/setup/install/linux/), 8 GB trên [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), cùng với hỗ trợ ảo hóa phần cứng. Hãy kiểm tra các trang liên kết để biết yêu cầu hiện hành. Dung lượng bộ nhớ dành cho container được thiết lập trong [cài đặt tài nguyên](https://docs.docker.com/desktop/settings-and-maintenance/settings/) của Docker Desktop trên macOS, Linux và Windows với Hyper-V; còn với backend WSL 2 trên Windows, dung lượng này được thiết lập trên máy ảo WSL 2 thay thế (xem [hướng dẫn WSL của Docker](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine được cài đặt trực tiếp trên Linux sẽ chạy container trên máy chủ và không có máy ảo riêng biệt.

Nếu bạn kết nối LibreChat với các mô hình chạy trên cùng một máy, chẳng hạn như [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), hãy chọn cấu hình phần cứng phù hợp với mô hình bạn sử dụng. Môi trường chạy mô hình đó cần bộ nhớ lớn hơn nhiều, và thường cần GPU, so với LibreChat.

<Callout type="warn" title="CPU không hỗ trợ AVX">

Image MongoDB được sử dụng trong cấu hình Docker Compose mặc định của LibreChat yêu cầu CPU hỗ trợ các lệnh AVX. Trên các CPU x86 đời cũ không có AVX (và trên một số máy ảo không cung cấp AVX cho hệ khách), MongoDB sẽ bị lỗi và dừng ngay khi khởi động.

**Cách khắc phục:** Tạo tệp `docker-compose.override.yml` để sử dụng phiên bản image MongoDB cũ hơn không yêu cầu AVX:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Xem [hướng dẫn Docker Override](/docs/configuration/docker_override) để biết thêm chi tiết.

</Callout>

## Cài đặt [#installation]

<Steps>
  <Step>

### Sao chép Repository [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Tạo tệp môi trường của bạn [#create-your-environment-file]

```bash
cp .env.example .env
```

Tệp `.env` mặc định hoạt động ngay lập tức cho thiết lập cơ bản. Để biết cấu hình chuyên sâu, hãy xem [tham chiếu .env](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

Trên Windows, hãy sử dụng `copy .env.example .env` nếu `cp` không khả dụng.

</Callout>

  </Step>
  <Step>

### Khởi chạy LibreChat [#start-librechat]

```bash
docker compose up -d
```

Lần khởi chạy đầu tiên sẽ tải xuống các Docker image và có thể mất vài phút. Các lần khởi động sau đó sẽ nhanh hơn nhiều.

  </Step>
  <Step>

### Xác minh và Đăng nhập [#verify-and-log-in]

Mở trình duyệt của bạn và truy cập [http://localhost:3080](http://localhost:3080). Bạn sẽ thấy trang đăng nhập LibreChat.

<Callout type="info" title="Tài khoản đầu tiên = Quản trị viên trong triển khai Single-Tenant">

Trong một triển khai single-tenant không có phạm vi (unscoped), tài khoản đầu tiên bạn đăng ký sẽ trở thành tài khoản quản trị viên (admin). Không có thông tin đăng nhập mặc định; bạn tự tạo tên người dùng và mật khẩu của mình trong quá trình đăng ký. Các triển khai có phạm vi theo tenant (tenant-scoped) không tự động nâng quyền người dùng đầu tiên trong mỗi tenant; hãy cấp quyền quản trị viên tenant thông qua một luồng quản trị đáng tin cậy.

</Callout>

Nhấp vào **Sign up** để tạo tài khoản của bạn, sau đó làm theo [Your First Chat](/docs/quick_start/first_chat) để thêm khóa API của mô hình và gửi tin nhắn đầu tiên.

  </Step>
</Steps>

## Gắn librechat.yaml [#mounting-librechatyaml]

Để sử dụng tệp cấu hình `librechat.yaml` tùy chỉnh với Docker, bạn cần mount nó dưới dạng một volume để container có thể truy cập được.

Sao chép tệp ghi đè mẫu và chỉnh sửa nó:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Đảm bảo rằng mount volume của librechat.yaml đã được bỏ chú thích trong `docker-compose.override.yml`:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Khởi động lại để các thay đổi có hiệu lực:

```bash
docker compose down && docker compose up -d
```

Để biết hướng dẫn thiết lập đầy đủ bao gồm cả việc tạo tệp từ đầu, hãy xem [hướng dẫn librechat.yaml](/docs/configuration/librechat_yaml). Để biết thêm các tùy chọn ghi đè, hãy xem [hướng dẫn ghi đè Docker](/docs/configuration/docker_override).

## Cập nhật LibreChat [#updating-librechat]

Các lệnh sau đây sẽ lấy các thay đổi mới nhất của dự án LibreChat, bao gồm mọi thay đổi cần thiết đối với các tệp docker compose, cũng như các image được xây dựng sẵn mới nhất.

<Callout type="info" title="Quyền hạn">

Bạn có thể cần thêm tiền tố `sudo` vào các lệnh tùy theo quyền hạn trong môi trường của bạn.

</Callout>

<Callout type="info" title="Script cập nhật">

Script `npm run update:docker` của repository sẽ build lại các image được build cục bộ, nhưng không pull các image dựng sẵn mà `docker-compose.yml` mặc định sử dụng. Vì vậy, để cập nhật một bản cài đặt mặc định, hãy làm theo các bước thủ công bên dưới.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Khắc phục sự cố [#troubleshooting]

### Cổng đã được sử dụng [#port-already-in-use]

Nếu bạn thấy lỗi như `bind: address already in use` cho cổng 3080, thì một ứng dụng khác đang sử dụng cổng đó.

Hoặc dừng ứng dụng đang xung đột, hoặc thay đổi cổng mà LibreChat sử dụng. Tệp `docker-compose.yml` mặc định công bố `"${PORT}:${PORT}"`, và các cổng được thêm trong tệp ghi đè (override) sẽ được nối thêm vào danh sách đó thay vì thay thế nó, nên chỉ riêng tệp ghi đè không đủ để giải phóng cổng 3080.

Cách đơn giản nhất là đặt `PORT` trong tệp `.env` của bạn, việc này sẽ thay đổi cả cổng mà LibreChat lắng nghe lẫn cổng được công bố.

```bash filename=".env"
PORT=3081
```

Ngoài ra, với Docker Compose 2.24.4 trở lên, hãy thay thế cổng được publish trong `docker-compose.override.yml` bằng thẻ `!override` (container vẫn lắng nghe trên 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Khởi động lại bằng `docker compose down && docker compose up -d`, sau đó truy cập `http://localhost:3081` thay thế.

### Container bị treo khi khởi động [#container-crashes-on-startup]

Nếu các container thoát ngay lập tức sau khi khởi động, hãy kiểm tra nhật ký (logs):

```bash
docker compose logs api
```

Các nguyên nhân phổ biến:

- Cú pháp `librechat.yaml` không hợp lệ: hãy kiểm tra bằng [YAML Validator](/toolkit/yaml_checker)
- Thiếu tệp `.env` -- hãy đảm bảo `.env` tồn tại trong thư mục gốc của dự án
- Docker không chạy -- hãy đảm bảo Docker Desktop đã được mở và đang chạy

### Các biến môi trường bị thiếu [#missing-environment-variables]

Nếu các tính năng không hoạt động như mong đợi, hãy kiểm tra xem các biến môi trường bắt buộc đã được thiết lập trong tệp `.env` của bạn hay chưa.

```bash
docker compose exec api env | grep -i "your_variable"
```

Xem [.env reference](/docs/configuration/dotenv) để biết tất cả các biến khả dụng và giá trị mặc định của chúng.
