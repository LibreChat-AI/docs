请遵循本指南使用 Helm 在 Kubernetes 上部署 LibreChat，并根据您的具体用例进行调整。社区贡献的其他 Helm chart 列在下方的 [Community Helm Charts](#community-helm-charts) 部分。

## 先决条件 [#prerequisites]

* 一个正在运行的 Kubernetes 集群
* _本地_ 安装的 `kubectl` 和 Helm

## 配置 [#configuration]

1. 使用 [Credentials Generator](/toolkit/creds_generator) 为 `CREDS_KEY`、`CREDS_IV`、`JWT_SECRET`、`JWT_REFRESH_SECRET` 和 `MEILI_MASTER_KEY` 生成安全值。
将它们放入 Kubernetes Secret 中，如下所示（如果您更改了 secret 名称，请记得更新您的 Helm values）：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

请使用永久值并将相同的 Secret 挂载到每个副本中。不要在 Kubernetes 中依赖进程本地或临时文件系统的凭据：更改这些值可能会导致会话失效，并使现有的加密记录无法读取。

在 LibreChat 容器启动之前，必须存在由 `global.librechat.existingSecretName` 指定的 Secret。如果指定的 Secret 缺失或拼写错误，将会阻塞 Pod 启动，而不是回退到临时的 Pod 本地凭据。该 chart 不会验证其中的键，因此请确保它包含 `CREDS_KEY`、`CREDS_IV`、`JWT_SECRET` 和 `JWT_REFRESH_SECRET`。

仅在所有 LibreChat 凭据都通过其他方式提供时，才设置 `global.librechat.existingSecretName: ""`。`librechat.configEnv` 接受 ConfigMap 数据的字符串值，而 `global.librechat.env` 接受 Kubernetes 环境变量条目，例如 `valueFrom.secretKeyRef`。在生产环境中，优先使用 Secret 引用。

捆绑的 Meilisearch 对 `meilisearch.auth.existingMasterKeySecret` 有单独的依赖，其默认值为 `librechat-credentials-env`，且必须包含提供给 LibreChat 的相同 `MEILI_MASTER_KEY`。清除 LibreChat Secret 引用不会清除此 Meilisearch 引用。如果禁用了捆绑的 Meilisearch，请单独配置外部搜索服务及其凭据。

2. 将任何所需的 LLM 提供商 API 密钥添加到此相同的 secret 中：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <same generated value as above>
  CREDS_IV: <same generated value as above>
  JWT_SECRET: <same generated value as above>
  JWT_REFRESH_SECRET: <same generated value as above>
  MEILI_MASTER_KEY: <same generated value as above>
  OPENAI_API_KEY: <your secret value>
```
3. 将 Secret 应用到集群：

将完整的 Secret 清单保存为 `librechat-credentials.yaml`，并使用预期的命名空间，然后应用它：

```bash
kubectl apply -f librechat-credentials.yaml
```

4. 将探针指向专用端点。该 Chart 的默认探针使用 `/health`,即使 Redis 不可用,它仍返回 `200`,因此无法完成登录的 Pod 仍会持续接收流量。请在 values 文件中覆盖这些探针,使就绪探针依据 Redis 状态判断,而存活探针则不受其影响:

```yaml
livenessProbe:
  httpGet:
    path: /livez
    port: 3080
readinessProbe:
  httpGet:
    path: /readyz
    port: 3080
```

请参阅 [Redis 健康检查](/docs/configuration/redis#health-checks) 了解每个端点的报告内容。

## 安装 Helm Chart [#install-helm-chart]

要安装 helm chart，请运行：

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>开发版本</summary>

在仓库的根目录下，运行：

`helm install <deployment-name> ./helm/librechat`
</details>

与其他 Helm chart 类似，这里存在一个 [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml)，它概述了默认设置并指出了可以修改的配置选项。

创建一个 `values.yaml` 文件，并填入你想要从默认配置中修改的值。

安装 Helm Chart:`helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-file>`

一旦发布版本已启动且服务可以访问,请按照[您的第一次对话](/docs/quick_start/first_chat)的指引创建账户、添加模型 API 密钥,并发送您的第一条消息。

## 卸载 Helm Chart [#uninstall-the-helm-chart]

要卸载 Helm Chart，请运行：`helm uninstall <deployment-name>`

示例：`helm uninstall librechat`

## 升级到 chart 3.x [#upgrading-to-chart-3x]

Chart 3.0.0 默认在内置的 MongoDB 和 Redis 上启用身份验证。它们生成的密码保存在子图表的 Secret 中,并通过 `secretKeyRef`(`MONGODB_ROOT_PASSWORD`、`REDIS_PASSWORD`)传递给 LibreChat,`MONGO_URI` 则在 Deployment 中拼接生成。若要使用您自己的数据库,请设置 `librechat.configEnv.MONGO_URI`(或 `REDIS_URI`)。仅当需要恢复旧的未认证行为时,才将 `mongodb.auth.enabled=false` 或 `redis.auth.enabled=false` 设置为 false。自定义 root 密码必须是 URL 安全的,因为它们会被放入 `MONGO_URI` 中。

如果 `MONGO_URI`、`REDIS_URI` 或 `REDIS_PASSWORD` 来自由 `global.librechat.existingSecretName` 指定的 Secret,请设置 `librechat.injectBundledCredentials.mongodb=false`(对应 `MONGO_URI`)或 `librechat.injectBundledCredentials.redis=false`(对应 `REDIS_URI` 或 `REDIS_PASSWORD`)。Chart 无法读取该 Secret 的内容,否则生成的值会覆盖 Secret 中的配置。这两个设置相互独立。如果保留内置的 MongoDB 或 Redis,则其密码必须与 Secret 中的密码一致:将 `mongodb.auth.existingSecret` 或 `redis.auth.existingSecret` 指向该 Secret,或设置对应的 `auth` 密码;否则数据库会保留自动生成的密码,LibreChat 将无法通过身份验证。凭据在 Pod 启动时读取,因此轮换数据库密码后,请使用 `kubectl rollout restart deployment/<release>-librechat` 重启所有读取该密码的 Deployment。

### 在升级过程中保留生成的密码 [#keeping-the-generated-passwords-across-upgrades]

使用默认配置时,子 chart 会在首次安装时生成密码,而 MongoDB 子 chart 会拒绝后续未重复提供这些密码的升级(报错“PASSWORDS ERROR”)。请读取当前的 values,并在每次执行 `helm upgrade` 时传入这些值;或者将 `mongodb.auth.existingSecret` 和 `redis.auth.existingSecret` 指向您自行管理的 Secret。

```bash
kubectl get secret <release>-mongodb -o jsonpath='{.data.mongodb-root-password}' | base64 -d
helm upgrade <release> ... --set-string mongodb.auth.rootPassword=<password>
```

Redis 同样需要使用 `--set-string redis.auth.password=<password>`(密码取自 `<release>-redis` Secret 中的 `redis-password`)。当 `mongodb.architecture=replicaset` 时,还需保留副本集密钥:从同一个 Secret 中读取 `mongodb-replica-set-key`,并通过 `--set-string mongodb.auth.replicaSetKey=<key>` 传入。

### 从未启用身份验证的内置 MongoDB 升级 [#upgrading-from-an-unauthenticated-bundled-mongodb]

在认证成为默认设置之前安装的版本，其数据卷中没有 root 用户，并且升级时不会重新初始化已持久化的数据，因此执行 `helm upgrade` 之后 LibreChat 将无法完成认证。请选择以下其中一种方案：

1. 保持旧的行为:`--set mongodb.auth.enabled=false`。
2. 在运行中的升级前 Pod 上先创建 root 用户。在该 Pod 中执行 `mongosh admin --eval 'db.createUser({user: "<rootUser>", pwd: "<password>", roles: ["root"]})'`(`<rootUser>` 即 `mongodb.auth.rootUser`,默认为 `root`)。然后使用 `--set-string mongodb.auth.rootPassword=<password>`(需为 URL 安全字符)以及相同的 `mongodb.auth.rootUser`(如果你修改过该值)进行升级。此后每次升级都必须保持相同的密码。如果升级时未提供 `mongodb.auth.rootPassword`,MongoDB 子 Chart 会拒绝该次升级并报 "PASSWORDS ERROR",因为此时尚不存在 Secret。

图表在渲染时无法检测到这种情况,因此在启用身份验证的情况下,每次升级时 `NOTES.txt` 都会打印一条提示。

### Ingress TLS [#ingress-tls]

默认情况下启用 Ingress。对于任何非本地安装,请设置 `ingress.tls`(包括 `secretName` 和 `hosts`);对于每个未被任何 `ingress.tls` 条目覆盖的 Ingress 主机,`helm install` 都会输出警告。

### 管理面板 URL [#admin-panel-url]

将 `librechat.adminPanelUrl` 设置为用于 OAuth/SSO 重定向的管理面板基础 URL。该 URL 可以包含路径,但不能以 `/` 结尾。参见 [管理面板](/docs/features/admin_panel)。

```yaml
librechat:
  adminPanelUrl: https://admin.example.com/admin
```

## 迁移 1.x -> 2.x [#migrate-1x---2x]
如果您在 2.x 版本之前使用过该 chart，您可能需要更新 `value` 结构。

1. 将配置移动到 librechat.configEnv：
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. 将所有 Secret 值合并为一个 Secret，如 [Configuration Step 1](#configuration) 所述。
3. 若要使用外部 MongoDB 实例，请参考该 Chart 的 [values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml)，相应地停用组件并更改 Mongodb 实例的 FQDN。如果该外部管理的 MongoDB 实例中已存在数据，则建议采用此方法。
