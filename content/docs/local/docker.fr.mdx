Pour la plupart des scénarios, Docker Compose est la méthode d'installation recommandée en raison de sa simplicité, de sa facilité d'utilisation et de sa fiabilité.

## Prérequis [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop est recommandé pour la plupart des utilisateurs. Pour les installations sur serveur distant, consultez le [Guide de déploiement Docker sur Ubuntu](/docs/remote/docker_linux).

### Configuration système requise [#system-requirements]

LibreChat n'exécute pas lui-même les modèles d'IA ; il envoie des requêtes aux fournisseurs que vous configurez, il n'a donc pas besoin de GPU.

LibreChat, les conteneurs ont besoin d'au moins 1 GiB de RAM et 1 vCPU, soit la même [configuration minimale](/docs/remote#minimum-requirements) que sur un serveur. Le fichier Docker Compose par défaut démarre MongoDB, Meilisearch (recherche de conversations) et l'API RAG avec une base de données PostgreSQL/pgvector (recherche de fichiers) en complément de LibreChat. Il définit également le panneau d'administration, qui ne démarre qu'une fois `ADMIN_PANEL_SESSION_SECRET` défini dans `.env` (voir [Panneau d'administration](/docs/features/admin_panel)). Avec l'ensemble des services en cours d'exécution, mettez au moins 2 Go de mémoire à la disposition de Docker pour un fonctionnement plus fluide.

Si vous utilisez Docker Desktop, celui-ci exécute les conteneurs dans sa propre machine virtuelle. Votre ordinateur doit donc également satisfaire aux exigences de Docker Desktop. Au moment de la rédaction de ce document, celles-ci sont d'au moins 4 Go de RAM système sur [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) et [Linux](https://docs.docker.com/desktop/setup/install/linux/), et 8 Go sur [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), ainsi que la prise en charge de la virtualisation matérielle. Consultez les pages liées pour connaître les exigences actuelles. La mémoire disponible pour les conteneurs se configure dans les [paramètres de ressources](https://docs.docker.com/desktop/settings-and-maintenance/settings/) de Docker Desktop sur macOS, Linux et Windows avec Hyper-V. Avec le backend WSL 2 de Windows, elle se configure plutôt sur la machine virtuelle WSL 2 (voir les [recommandations de Docker concernant WSL](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine installé directement sur Linux exécute les conteneurs sur l'hôte et n'utilise pas de machine virtuelle séparée.

Si vous connectez LibreChat à des modèles exécutés sur la même machine, comme [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), dimensionnez le matériel en fonction du modèle que vous choisissez. Le moteur d'exécution du modèle nécessite bien plus de mémoire, et souvent un GPU, que LibreChat lui-même.

<Callout type="warn" title="CPU sans support AVX">

L'image MongoDB utilisée par la configuration Docker Compose par défaut de LibreChat nécessite un processeur prenant en charge les instructions AVX. Sur les anciens processeurs x86 sans AVX (ainsi que sur certaines machines virtuelles qui n'exposent pas AVX à l'invité), MongoDB plante au démarrage.

**Correctif :** Créez un fichier `docker-compose.override.yml` pour utiliser une image MongoDB plus ancienne qui ne nécessite pas AVX :

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Consultez le [guide de remplacement Docker](/docs/configuration/docker_override) pour plus de détails.

</Callout>

## Installation [#installation]

<Steps>
  <Step>

### Cloner le dépôt [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Créer votre fichier d'environnement [#create-your-environment-file]

```bash
cp .env.example .env
```

Le fichier `.env` par défaut fonctionne immédiatement pour une configuration de base. Pour une configuration approfondie, consultez la [référence .env](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

On Windows, use `copy .env.example .env` if `cp` is not available.

</Callout>

  </Step>
  <Step>

### Démarrer LibreChat [#start-librechat]

```bash
docker compose up -d
```

Le premier lancement télécharge les images Docker et peut prendre quelques minutes. Les démarrages suivants sont beaucoup plus rapides.

  </Step>
  <Step>

### Vérifier et se connecter [#verify-and-log-in]

Ouvrez votre navigateur et visitez [http://localhost:3080](http://localhost:3080). Vous devriez voir la page de connexion de LibreChat.

<Callout type="info" title="Premier compte = Administrateur dans les déploiements à locataire unique">

Dans un déploiement mono-locataire sans périmètre (unscoped), le premier compte que vous enregistrez devient le compte administrateur. Il n'existe aucun identifiant par défaut ; vous créez votre propre nom d'utilisateur et mot de passe lors de l'inscription. Les déploiements avec périmètre par locataire (tenant-scoped) ne promeuvent pas automatiquement le premier utilisateur de chaque locataire ; provisionnez les administrateurs de locataire via un flux d'administration de confiance.

</Callout>

Cliquez sur **Sign up** pour créer votre compte, puis suivez [Your First Chat](/docs/quick_start/first_chat) pour ajouter une clé API de modèle et envoyer votre premier message.

  </Step>
</Steps>

## Montage de librechat.yaml [#mounting-librechatyaml]

Pour utiliser un fichier de configuration `librechat.yaml` personnalisé avec Docker, vous devez le monter en tant que volume afin que le conteneur puisse y accéder.

Copiez l'exemple de fichier de remplacement et modifiez-le :

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Assurez-vous que le montage de volume librechat.yaml est décommenté dans `docker-compose.override.yml` :

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Redémarrez pour que les modifications prennent effet :

```bash
docker compose down && docker compose up -d
```

Pour des instructions de configuration complètes, y compris la création du fichier à partir de zéro, consultez le [guide librechat.yaml](/docs/configuration/librechat_yaml). Pour plus d'options de remplacement, consultez le [guide de remplacement Docker](/docs/configuration/docker_override).

## Mise à jour de LibreChat [#updating-librechat]

Les commandes suivantes récupéreront les dernières modifications du projet LibreChat, y compris tous les changements nécessaires aux fichiers docker compose, ainsi que les dernières images pré-construites.

<Callout type="info" title="Autorisations">

Il se peut que vous deviez faire précéder les commandes de `sudo` en fonction des permissions de votre environnement.

</Callout>

<Callout type="info" title="Script de mise à jour">

Le script `npm run update:docker` du dépôt reconstruit les images créées localement, mais il ne récupère pas les images préconstruites utilisées par défaut par `docker-compose.yml`. Suivez donc les étapes manuelles ci-dessous pour mettre à jour une installation par défaut.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Dépannage [#troubleshooting]

### Port déjà utilisé [#port-already-in-use]

Si vous voyez une erreur telle que `bind: address already in use` pour le port 3080, une autre application utilise ce port.

Soit arrêter l'application en conflit, soit modifier le port utilisé par LibreChat. Le fichier `docker-compose.yml` par défaut publie `"${PORT}:${PORT}"`, et les ports ajoutés dans un fichier de surcharge (override) sont ajoutés à cette liste au lieu de la remplacer. Un fichier de surcharge seul ne libère donc pas le port 3080.

La solution la plus simple consiste à définir `PORT` dans votre fichier `.env`, ce qui modifie à la fois le port sur lequel LibreChat écoute et le port publié :

```bash filename=".env"
PORT=3081
```

Vous pouvez également, avec Docker Compose 2.24.4 ou une version ultérieure, remplacer le port publié dans `docker-compose.override.yml` par le tag `!override` (le conteneur continue d'écouter sur le port 3080) :

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Redémarrez avec `docker compose down && docker compose up -d`, puis accédez à `http://localhost:3081` à la place.

### Le conteneur plante au démarrage [#container-crashes-on-startup]

Si les conteneurs s'arrêtent immédiatement après le démarrage, vérifiez les journaux :

```bash
docker compose logs api
```

Causes courantes :

- Syntaxe `librechat.yaml` invalide : validez-la avec le [Validateur YAML](/toolkit/yaml_checker)
- Fichier `.env` manquant -- assurez-vous que `.env` existe à la racine du projet
- Docker n'est pas en cours d'exécution -- assurez-vous que Docker Desktop est ouvert et en cours d'exécution

### Variables d'environnement manquantes [#missing-environment-variables]

Si les fonctionnalités ne fonctionnent pas comme prévu, vérifiez que les variables d'environnement requises sont définies dans votre fichier `.env`.

```bash
docker compose exec api env | grep -i "your_variable"
```

Consultez la [référence .env](/docs/configuration/dotenv) pour toutes les variables disponibles et leurs valeurs par défaut.
