Untuk sebagian besar skenario, Docker Compose adalah metode instalasi yang direkomendasikan karena kesederhanaan, kemudahan penggunaan, dan keandalannya.

## Prasyarat [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop direkomendasikan untuk sebagian besar pengguna. Untuk instalasi server jarak jauh, lihat [Panduan Deployment Docker Ubuntu](/docs/remote/docker_linux).

### Persyaratan Sistem [#system-requirements]

LibreChat tidak menjalankan model AI sendiri; ia mengirimkan permintaan ke penyedia yang Anda konfigurasi, sehingga tidak memerlukan GPU.

Kontainer LibreChat memerlukan setidaknya 1 GiB RAM dan 1 vCPU, sama dengan [minimum](/docs/remote#minimum-requirements) pada server. File Docker Compose default memulai MongoDB, Meilisearch (pencarian percakapan), dan RAG API dengan database PostgreSQL/pgvector (pencarian file) bersama LibreChat. File ini juga mendefinisikan panel admin, yang hanya akan berjalan setelah `ADMIN_PANEL_SESSION_SECRET` diatur di `.env` (lihat [Admin Panel](/docs/features/admin_panel)). Dengan semua layanan berjalan, sediakan setidaknya 2 GB memori untuk Docker agar operasinya lebih lancar.

Jika Anda menggunakan Docker Desktop, aplikasi ini menjalankan container di dalam mesin virtual miliknya sendiri, sehingga komputer Anda juga harus memenuhi persyaratan Docker Desktop. Saat tulisan ini dibuat, persyaratan tersebut adalah minimal 4 GB RAM sistem di [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) dan [Linux](https://docs.docker.com/desktop/setup/install/linux/), dan 8 GB di [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), ditambah virtualisasi perangkat keras. Periksa halaman yang ditautkan untuk persyaratan terbaru. Memori yang tersedia untuk container diatur di [pengaturan sumber daya](https://docs.docker.com/desktop/settings-and-maintenance/settings/) Docker Desktop pada macOS, Linux, dan Windows dengan Hyper-V; dengan backend WSL 2 di Windows, memori diatur pada mesin virtual WSL 2 (lihat [panduan WSL dari Docker](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine yang dipasang langsung di Linux menjalankan container di host dan tidak memiliki mesin virtual terpisah.

Jika Anda menghubungkan LibreChat ke model yang berjalan di mesin yang sama, seperti [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), sesuaikan perangkat keras dengan model yang Anda pilih. Runtime model tersebut membutuhkan memori jauh lebih besar, dan seringkali GPU, dibandingkan dengan LibreChat itu sendiri.

<Callout type="warn" title="CPU tanpa dukungan AVX">

Image MongoDB yang digunakan dalam pengaturan Docker Compose default LibreChat memerlukan CPU dengan instruksi AVX. Pada CPU x86 lama yang tidak memiliki AVX (dan pada beberapa mesin virtual yang tidak menyediakan AVX ke guest), MongoDB akan crash saat startup.

**Perbaikan:** Buat `docker-compose.override.yml` untuk menggunakan image MongoDB yang lebih lama yang tidak memerlukan AVX:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Lihat [panduan Docker Override](/docs/configuration/docker_override) untuk detail selengkapnya.

</Callout>

## Instalasi [#installation]

<Steps>
  <Step>

### Kloning Repositori [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Buat File Environment Anda [#create-your-environment-file]

```bash
cp .env.example .env
```

File `.env` bawaan dapat langsung digunakan untuk pengaturan dasar. Untuk konfigurasi mendalam, lihat [referensi .env](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

Di Windows, gunakan `copy .env.example .env` jika `cp` tidak tersedia.

</Callout>

  </Step>
  <Step>

### Mulai LibreChat [#start-librechat]

```bash
docker compose up -d
```

Peluncuran pertama akan menarik Docker images dan mungkin memakan waktu beberapa menit. Peluncuran berikutnya akan jauh lebih cepat.

  </Step>
  <Step>

### Verifikasi dan Masuk [#verify-and-log-in]

Buka browser Anda dan kunjungi [http://localhost:3080](http://localhost:3080). Anda seharusnya melihat halaman login LibreChat.

<Callout type="info" title="Akun Pertama = Admin dalam Deployment Single-Tenant">

Dalam penerapan single-tenant tanpa cakupan (unscoped), akun pertama yang Anda daftarkan akan menjadi akun admin. Tidak ada kredensial default; Anda membuat username dan password sendiri selama proses registrasi. Penerapan yang menggunakan cakupan tenant tidak secara otomatis menjadikan pengguna pertama di setiap tenant sebagai admin; sediakan administrator tenant melalui alur administratif tepercaya.

</Callout>

Klik **Sign up** untuk membuat akun Anda, lalu ikuti [Your First Chat](/docs/quick_start/first_chat) untuk menambahkan API key model dan mengirim pesan pertama Anda.

  </Step>
</Steps>

## Memasang librechat.yaml [#mounting-librechatyaml]

Untuk menggunakan file konfigurasi `librechat.yaml` kustom dengan Docker, Anda perlu memasangnya sebagai volume agar container dapat mengaksesnya.

Salin file contoh override dan edit file tersebut:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Pastikan volume mount librechat.yaml tidak dikomentari di dalam `docker-compose.override.yml`:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Mulai ulang agar perubahan diterapkan:

```bash
docker compose down && docker compose up -d
```

Untuk instruksi pengaturan lengkap termasuk membuat file dari awal, lihat [panduan librechat.yaml](/docs/configuration/librechat_yaml). Untuk opsi penggantian (override) lainnya, lihat [panduan Docker override](/docs/configuration/docker_override).

## Memperbarui LibreChat [#updating-librechat]

Perintah berikut akan mengambil perubahan proyek LibreChat terbaru, termasuk perubahan apa pun yang diperlukan pada file docker compose, serta image pra-bangun terbaru.

<Callout type="info" title="Izin">

Anda mungkin perlu menambahkan awalan `sudo` pada perintah sesuai dengan izin lingkungan Anda.

</Callout>

<Callout type="info" title="Skrip Pembaruan">

Skrip `npm run update:docker` pada repositori ini membangun ulang image yang dibangun secara lokal, tetapi tidak menarik (pull) image prebuilt yang digunakan oleh `docker-compose.yml` default. Oleh karena itu, ikuti langkah manual di bawah ini untuk memperbarui instalasi default.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Pemecahan Masalah [#troubleshooting]

### Port Sudah Digunakan [#port-already-in-use]

Jika Anda melihat kesalahan seperti `bind: address already in use` untuk port 3080, aplikasi lain sedang menggunakan port tersebut.

Hentikan aplikasi yang bentrok, atau ubah port yang digunakan LibreChat. `docker-compose.yml` default mempublikasikan `"${PORT}:${PORT}"`, dan port yang ditambahkan dalam file override akan ditambahkan ke daftar tersebut, bukan menggantikannya, sehingga override saja tidak akan membebaskan port 3080.

Cara termudah adalah mengatur `PORT` di file `.env` Anda, yang mengubah port tempat LibreChat mendengarkan sekaligus port yang dipublikasikan:

```bash filename=".env"
PORT=3081
```

Sebagai alternatif, dengan Docker Compose 2.24.4 atau yang lebih baru, ganti port yang dipublikasikan di `docker-compose.override.yml` dengan tag `!override` (kontainer tetap mendengarkan di 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Mulai ulang dengan `docker compose down && docker compose up -d`, lalu buka `http://localhost:3081` sebagai gantinya.

### Container Mengalami Crash saat Startup [#container-crashes-on-startup]

Jika container keluar segera setelah dimulai, periksa log:

```bash
docker compose logs api
```

Penyebab umum:

- Sintaks `librechat.yaml` tidak valid: validasi dengan [YAML Validator](/toolkit/yaml_checker)
- File `.env` tidak ditemukan -- pastikan `.env` ada di root proyek
- Docker tidak berjalan -- pastikan Docker Desktop sudah terbuka dan berjalan

### Variabel Lingkungan yang Hilang [#missing-environment-variables]

Jika fitur tidak berfungsi sebagaimana mestinya, periksa apakah variabel lingkungan yang diperlukan telah diatur di dalam file `.env` Anda.

```bash
docker compose exec api env | grep -i "your_variable"
```

Lihat [.env reference](/docs/configuration/dotenv) untuk semua variabel yang tersedia dan nilai default-nya.
