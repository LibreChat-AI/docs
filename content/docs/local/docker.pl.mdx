W większości scenariuszy Docker Compose jest zalecaną metodą instalacji ze względu na swoją prostotę, łatwość użycia i niezawodność.

## Wymagania wstępne [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop jest zalecany dla większości użytkowników. W przypadku instalacji na zdalnym serwerze, zobacz [Przewodnik wdrażania Docker na Ubuntu](/docs/remote/docker_linux).

### Wymagania systemowe [#system-requirements]

LibreChat nie uruchamia samodzielnie modeli AI; wysyła żądania do skonfigurowanych przez Ciebie dostawców, dlatego nie potrzebuje procesora graficznego (GPU).

LibreChat-owe kontenery wymagają co najmniej 1 GiB pamięci RAM i 1 vCPU, czyli tego samego [minimum](/docs/remote#minimum-requirements) co na serwerze. Domyślny plik Docker Compose uruchamia obok LibreChat bazę MongoDB, Meilisearch (wyszukiwanie rozmów) oraz RAG API z bazą PostgreSQL/pgvector (wyszukiwanie w plikach). Definiuje on także panel administracyjny, który uruchamia się dopiero po ustawieniu `ADMIN_PANEL_SESSION_SECRET` w pliku `.env` (zobacz [Panel administracyjny](/docs/features/admin_panel)). Przy działaniu wszystkich usług udostępnij Dockerowi co najmniej 2 GB pamięci, aby zapewnić płynniejsze działanie.

Jeśli używasz Docker Desktop, uruchamia on kontenery wewnątrz własnej maszyny wirtualnej, dlatego komputer musi również spełniać wymagania Docker Desktop. W chwili pisania tego tekstu są to co najmniej 4 GB pamięci RAM systemu w [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) i [Linux](https://docs.docker.com/desktop/setup/install/linux/) oraz 8 GB w [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), a także sprzętowa wirtualizacja. Aktualne wymagania sprawdź na podlinkowanych stronach. Pamięć dostępna dla kontenerów ustawiana jest w [ustawieniach zasobów](https://docs.docker.com/desktop/settings-and-maintenance/settings/) Docker Desktop w systemach macOS, Linux oraz Windows z Hyper-V; w przypadku backendu Windows WSL 2 ustawia się ją natomiast na maszynie wirtualnej WSL 2 (zobacz [wskazówki Dockera dotyczące WSL](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine zainstalowany bezpośrednio w systemie Linux uruchamia kontenery na hoście i nie posiada osobnej maszyny wirtualnej.

Jeśli połączysz LibreChat z modelami działającymi na tej samej maszynie, na przykład [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), dobierz sprzęt do wybranego modelu. Środowisko uruchomieniowe modelu wymaga znacznie więcej pamięci, a często także GPU, niż sam LibreChat.

<Callout type="warn" title="Procesory bez obsługi AVX">

Obraz MongoDB używany w domyślnej konfiguracji Docker Compose w LibreChat wymaga procesora obsługującego instrukcje AVX. W przypadku starszych procesorów x86 bez AVX (a także niektórych maszyn wirtualnych, które nie udostępniają AVX systemowi gościa), MongoDB ulega awarii podczas uruchamiania.

**Poprawka:** Utwórz plik `docker-compose.override.yml`, aby użyć starszego obrazu MongoDB, który nie wymaga AVX:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Zobacz [przewodnik Docker Override](/docs/configuration/docker_override), aby uzyskać więcej szczegółów.

</Callout>

## Instalacja [#installation]

<Steps>
  <Step>

### Sklonuj repozytorium [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Utwórz swój plik środowiskowy [#create-your-environment-file]

```bash
cp .env.example .env
```

Domyślny plik `.env` działa od razu po instalacji w przypadku podstawowej konfiguracji. Aby uzyskać szczegółowe informacje, zobacz [.env reference](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

W systemie Windows użyj `copy .env.example .env`, jeśli polecenie `cp` nie jest dostępne.

</Callout>

  </Step>
  <Step>

### Uruchom LibreChat [#start-librechat]

```bash
docker compose up -d
```

Pierwsze uruchomienie pobiera obrazy Docker i może potrwać kilka minut. Kolejne uruchomienia są znacznie szybsze.

  </Step>
  <Step>

### Weryfikacja i logowanie [#verify-and-log-in]

Otwórz przeglądarkę i przejdź pod adres [http://localhost:3080](http://localhost:3080). Powinieneś zobaczyć stronę logowania LibreChat.

<Callout type="info" title="Pierwsze konto = Administrator w wdrożeniach jednonajemnych (Single-Tenant)">

W jednoosobowym wdrożeniu bez zakresu (unscoped single-tenant) pierwsze zarejestrowane konto staje się kontem administratora. Nie istnieją domyślne dane uwierzytelniające; nazwę użytkownika i hasło tworzysz samodzielnie podczas rejestracji. Wdrożenia z zakresem dla najemców (tenant-scoped) nie awansują automatycznie pierwszego użytkownika w każdym najemcy; administratorów najemców należy tworzyć za pomocą zaufanego procesu administracyjnego.

</Callout>

Kliknij **Sign up**, aby utworzyć swoje konto, a następnie postępuj zgodnie z [Your First Chat](/docs/quick_start/first_chat), aby dodać klucz API modelu i wysłać pierwszą wiadomość.

  </Step>
</Steps>

## Montowanie librechat.yaml [#mounting-librechatyaml]

Aby użyć niestandardowego pliku konfiguracyjnego `librechat.yaml` z Docker, musisz zamontować go jako wolumin, aby kontener miał do niego dostęp.

Skopiuj przykładowy plik nadpisujący (override) i edytuj go:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Upewnij się, że montowanie wolumenu librechat.yaml jest odkomentowane w `docker-compose.override.yml`:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Zrestartuj, aby zmiany weszły w życie:

```bash
docker compose down && docker compose up -d
```

Pełne instrukcje konfiguracji, w tym tworzenie pliku od zera, znajdują się w [przewodniku po librechat.yaml](/docs/configuration/librechat_yaml). Więcej opcji nadpisywania można znaleźć w [przewodniku po nadpisywaniu Docker](/docs/configuration/docker_override).

## Aktualizacja LibreChat [#updating-librechat]

Poniższe polecenia pobiorą najnowsze zmiany w projekcie LibreChat, w tym wszelkie niezbędne zmiany w plikach docker compose, a także najnowsze gotowe obrazy.

<Callout type="info" title="Uprawnienia">

Może być konieczne poprzedzenie poleceń komendą `sudo`, w zależności od uprawnień w Twoim środowisku.

</Callout>

<Callout type="info" title="Skrypt aktualizacji">

Skrypt `npm run update:docker` w repozytorium przebudowuje lokalnie zbudowane obrazy, ale nie pobiera gotowych obrazów, z których korzysta domyślny plik `docker-compose.yml`. Aby zaktualizować domyślną instalację, wykonaj dlatego poniższe kroki ręcznie.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Rozwiązywanie problemów [#troubleshooting]

### Port jest już używany [#port-already-in-use]

Jeśli widzisz błąd typu `bind: address already in use` dla portu 3080, oznacza to, że inna aplikacja korzysta z tego portu.

Albo zatrzymaj konfliktującą aplikację, albo zmień port, którego używa LibreChat. Domyślny `docker-compose.yml` publikuje `"${PORT}:${PORT}"`, a porty dodane w pliku nadpisującym (override) są dopisywane do tej listy, zamiast ją zastępować, więc sam plik nadpisujący nie zwalnia portu 3080.

Najprostszym rozwiązaniem jest ustawienie `PORT` w pliku `.env`, co zmienia zarówno port, na którym nasłuchuje LibreChat, jak i opublikowany port.

```bash filename=".env"
PORT=3081
```

Alternatywnie, przy użyciu Docker Compose w wersji 2.24.4 lub nowszej, zastąp opublikowany port w `docker-compose.override.yml` tagiem `!override` (kontener nadal nasłuchuje na porcie 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Uruchom ponownie za pomocą `docker compose down && docker compose up -d`, a następnie otwórz `http://localhost:3081`.

### Awaria kontenera podczas uruchamiania [#container-crashes-on-startup]

Jeśli kontenery wyłączają się natychmiast po uruchomieniu, sprawdź logi:

```bash
docker compose logs api
```

Typowe przyczyny:

- Nieprawidłowa składnia pliku `librechat.yaml`: sprawdź ją za pomocą [Walidatora YAML](/toolkit/yaml_checker)
- Brak pliku `.env` -- upewnij się, że `.env` znajduje się w katalogu głównym projektu
- Docker nie jest uruchomiony -- upewnij się, że Docker Desktop jest otwarty i działa

### Brakujące zmienne środowiskowe [#missing-environment-variables]

Jeśli funkcje nie działają zgodnie z oczekiwaniami, sprawdź, czy wymagane zmienne środowiskowe są ustawione w pliku `.env`.

```bash
docker compose exec api env | grep -i "your_variable"
```

Zobacz [.env reference](/docs/configuration/dotenv), aby uzyskać listę wszystkich dostępnych zmiennych oraz ich wartości domyślnych.
