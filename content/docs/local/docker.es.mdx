Para la mayoría de los escenarios, Docker Compose es el método de instalación recomendado debido a su simplicidad, facilidad de uso y confiabilidad.

## Requisitos previos [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

Docker Desktop es recomendado para la mayoría de los usuarios. Para instalaciones en servidores remotos, consulte la [Guía de despliegue de Docker en Ubuntu](/docs/remote/docker_linux).

### Requisitos del sistema [#system-requirements]

LibreChat no ejecuta modelos de IA por sí mismo; envía solicitudes a los proveedores que configures, por lo que no necesita una GPU.

Los contenedores de LibreChat necesitan al menos 1 GiB de RAM y 1 vCPU, el mismo [mínimo](/docs/remote#minimum-requirements) que en un servidor. El archivo predeterminado de Docker Compose inicia MongoDB, Meilisearch (búsqueda de conversaciones) y la RAG API con una base de datos PostgreSQL/pgvector (búsqueda de archivos) junto con LibreChat. También define el panel de administración, que solo se inicia una vez que `ADMIN_PANEL_SESSION_SECRET` está configurado en `.env` (consulta [Panel de administración](/docs/features/admin_panel)). Con todos los servicios en ejecución, asigne al menos 2 GB de memoria a Docker para un funcionamiento más fluido.

Si utilizas Docker Desktop, este ejecuta los contenedores dentro de su propia máquina virtual, por lo que tu equipo también debe cumplir los requisitos de Docker Desktop. En el momento de redactar esto, estos requisitos son de al menos 4 GB de RAM del sistema en [macOS](https://docs.docker.com/desktop/setup/install/mac-install/) y [Linux](https://docs.docker.com/desktop/setup/install/linux/), y 8 GB en [Windows](https://docs.docker.com/desktop/setup/install/windows-install/), además de virtualización por hardware. Consulta las páginas enlazadas para conocer los requisitos actuales. La memoria disponible para los contenedores se configura en la [configuración de recursos](https://docs.docker.com/desktop/settings-and-maintenance/settings/) de Docker Desktop en macOS, Linux y Windows con Hyper-V; con el backend WSL 2 de Windows, se configura en la máquina virtual de WSL 2 (consulta la [guía de WSL de Docker](https://docs.docker.com/desktop/features/wsl/best-practices/)). Docker Engine instalado directamente en Linux ejecuta los contenedores en el host y no tiene una máquina virtual independiente.

Si conectas LibreChat a modelos que se ejecutan en la misma máquina, como [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), dimensiona el hardware según el modelo que elijas. El entorno de ejecución del modelo necesita mucha más memoria, y con frecuencia una GPU, que LibreChat.

<Callout type="warn" title="CPUs sin soporte para AVX">

La imagen de MongoDB utilizada en la configuración predeterminada de Docker Compose de LibreChat requiere una CPU con instrucciones AVX. En CPUs x86 antiguas sin AVX (y en algunas máquinas virtuales que no exponen AVX al sistema invitado), MongoDB falla al iniciarse.

**Solución:** Crea un archivo `docker-compose.override.yml` para usar una imagen más antigua de MongoDB que no requiera AVX:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

Consulta la [guía de Docker Override](/docs/configuration/docker_override) para obtener más detalles.

</Callout>

## Instalación [#installation]

<Steps>
  <Step>

### Clonar el repositorio [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### Cree su archivo de entorno [#create-your-environment-file]

```bash
cp .env.example .env
```

El archivo `.env` predeterminado funciona de inmediato para una configuración básica. Para una configuración detallada, consulte la [referencia de .env](/docs/configuration/dotenv).

<Callout type="info" title="Windows">

En Windows, utiliza `copy .env.example .env` si `cp` no está disponible.

</Callout>

  </Step>
  <Step>

### Iniciar LibreChat [#start-librechat]

```bash
docker compose up -d
```

El primer inicio descarga las imágenes de Docker y puede tardar unos minutos. Los inicios posteriores son mucho más rápidos.

  </Step>
  <Step>

### Verificar e iniciar sesión [#verify-and-log-in]

Abre tu navegador y visita [http://localhost:3080](http://localhost:3080). Deberías ver la página de inicio de sesión de LibreChat.

<Callout type="info" title="La primera cuenta = Administrador en implementaciones de inquilino único">

En un despliegue de inquilino único sin ámbito (unscoped single-tenant), la primera cuenta que registres se convierte en la cuenta de administrador. No existen credenciales predeterminadas; creas tu propio nombre de usuario y contraseña durante el registro. Los despliegues con ámbito por inquilino (tenant-scoped) no promueven automáticamente al primer usuario de cada inquilino; aprovisiona los administradores de inquilino a través de un flujo administrativo de confianza.

</Callout>

Haga clic en **Sign up** para crear su cuenta y, a continuación, siga [Your First Chat](/docs/quick_start/first_chat) para agregar una clave de API de modelo y enviar su primer mensaje.

  </Step>
</Steps>

## Montaje de librechat.yaml [#mounting-librechatyaml]

Para usar un archivo de configuración `librechat.yaml` personalizado con Docker, necesitas montarlo como un volumen para que el contenedor pueda acceder a él.

Copia el archivo de ejemplo de anulación y edítalo:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

Asegúrate de que el montaje de volumen de librechat.yaml esté descomentado en `docker-compose.override.yml`:

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Reinicie para que los cambios surtan efecto:

```bash
docker compose down && docker compose up -d
```

Para obtener instrucciones de configuración completas, incluyendo la creación del archivo desde cero, consulta la [guía de librechat.yaml](/docs/configuration/librechat_yaml). Para más opciones de anulación, consulta la [guía de anulación de Docker](/docs/configuration/docker_override).

## Actualizando LibreChat [#updating-librechat]

Los siguientes comandos obtendrán los cambios más recientes del proyecto LibreChat, incluyendo cualquier modificación necesaria en los archivos docker compose, así como las imágenes precompiladas más recientes.

<Callout type="info" title="Permisos">

Es posible que necesites anteponer `sudo` a los comandos según los permisos de tu entorno.

</Callout>

<Callout type="info" title="Script de actualización">

El script `npm run update:docker` del repositorio reconstruye las imágenes compiladas localmente, pero no descarga las imágenes preconstruidas que utiliza el `docker-compose.yml` predeterminado; por lo tanto, sigue los pasos manuales a continuación para actualizar una instalación predeterminada.

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## Solución de problemas [#troubleshooting]

### Puerto ya en uso [#port-already-in-use]

Si ves un error como `bind: address already in use` para el puerto 3080, otra aplicación está utilizando ese puerto.

O detenga la aplicación en conflicto o cambie el puerto que usa LibreChat. El `docker-compose.yml` predeterminado publica `"${PORT}:${PORT}"`, y los puertos añadidos en un archivo de sobrescritura (override) se agregan a esa lista en lugar de reemplazarla, por lo que una sobrescritura por sí sola no libera el puerto 3080.

La solución más sencilla es establecer `PORT` en tu archivo `.env`, lo que cambia tanto el puerto en el que escucha LibreChat como el puerto publicado:

```bash filename=".env"
PORT=3081
```

Alternativamente, con Docker Compose 2.24.4 o posterior, reemplaza el puerto publicado en `docker-compose.override.yml` por la etiqueta `!override` (el contenedor sigue escuchando en el puerto 3080):

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports: !override
      - "3081:3080"
```

Reinicia con `docker compose down && docker compose up -d` y, después, visita `http://localhost:3081` en su lugar.

### El contenedor se cierra al iniciar [#container-crashes-on-startup]

Si los contenedores se cierran inmediatamente después de iniciarse, revisa los registros:

```bash
docker compose logs api
```

Causas comunes:

- Sintaxis de `librechat.yaml` no válida: valídala con el [Validador de YAML](/toolkit/yaml_checker)
- Falta el archivo `.env`: asegúrese de que `.env` exista en la raíz del proyecto
- Docker no se está ejecutando -- asegúrate de que Docker Desktop esté abierto y en ejecución

### Variables de entorno faltantes [#missing-environment-variables]

Si las funciones no funcionan como se espera, verifique que las variables de entorno requeridas estén configuradas en su archivo `.env`.

```bash
docker compose exec api env | grep -i "your_variable"
```

Consulta la [.env reference](/docs/configuration/dotenv) para ver todas las variables disponibles y sus valores predeterminados.
