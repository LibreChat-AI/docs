Helmを使用してKubernetes上にLibreChatをデプロイするには、以下のガイダンスに従ってください。必要に応じて、特定のユースケースに合わせて調整してください。コミュニティによって提供されたその他のHelmチャートは、以下の[Community Helm Charts](#community-helm-charts)セクションに記載されています。

## 前提条件 [#prerequisites]

* 実行中のKubernetesクラスター
* `kubectl` および Helm の _ローカル_ インストール

## 設定 [#configuration]

1. [Credentials Generator](/toolkit/creds_generator) を使用して、`CREDS_KEY`、`CREDS_IV`、`JWT_SECRET`、`JWT_REFRESH_SECRET`、および `MEILI_MASTER_KEY` の安全な値を生成します。
以下のように Kubernetes Secret に配置します（シークレット名を変更した場合は、Helm の値を更新することを忘れないでください）：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <generated value>
  CREDS_IV: <generated value>
  JWT_SECRET: <generated value>
  JWT_REFRESH_SECRET: <generated value>
  MEILI_MASTER_KEY: <generated value>
```

永続的な値を使用し、すべてのレプリカに同じSecretをマウントしてください。Kubernetesにおいてプロセスローカルやエフェメラルなファイルシステムの認証情報に依存しないでください。これらの値を変更すると、セッションが無効になり、既存の暗号化されたレコードが読み取れなくなる可能性があります。

`global.librechat.existingSecretName` で指定された Secret は、LibreChat コンテナが起動する前に存在している必要があります。指定された Secret が存在しない、または名前が間違っている場合、一時的なポッドローカルの認証情報にフォールバックすることなく、ポッドの起動がブロックされます。このチャートは内部のキーを検証しないため、`CREDS_KEY`、`CREDS_IV`、`JWT_SECRET`、および `JWT_REFRESH_SECRET` が含まれていることを確認してください。

すべてのLibreChatの認証情報が他の方法で提供されている場合にのみ、`global.librechat.existingSecretName: ""` を設定してください。`librechat.configEnv` はConfigMapデータ用の文字列値を受け入れますが、`global.librechat.env` は `valueFrom.secretKeyRef` のようなKubernetes環境エントリを受け入れます。本番環境ではSecret参照を使用することを推奨します。

バンドルされているMeilisearchは、`meilisearch.auth.existingMasterKeySecret` に個別の依存関係を持っており、デフォルトでは `librechat-credentials-env` が設定されています。これには、LibreChatに提供されるものと同じ `MEILI_MASTER_KEY` が含まれている必要があります。LibreChatのシークレット参照をクリアしても、このMeilisearchの参照はクリアされません。バンドルされているMeilisearchが無効になっている場合は、外部の検索サービスとその認証情報を個別に設定してください。

2. LLMプロバイダーに必要なAPIキーを、この同じシークレットに追加します：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: librechat-credentials-env
  namespace: <librechat-chart-namespace>
type: Opaque
stringData:
  CREDS_KEY: <same generated value as above>
  CREDS_IV: <same generated value as above>
  JWT_SECRET: <same generated value as above>
  JWT_REFRESH_SECRET: <same generated value as above>
  MEILI_MASTER_KEY: <same generated value as above>
  OPENAI_API_KEY: <your secret value>
```
3. シークレットをクラスターに適用する:

完全なSecretマニフェストを `librechat-credentials.yaml` として保存し、対象のネームスペースを指定した上で適用します：

```bash
kubectl apply -f librechat-credentials.yaml
```

## Helm Chartのインストール [#install-helm-chart]

<Callout type="warning" title="Chart 2.0.16: 空のconfig map">
v0.8.8 チャートのソースでは、`librechat.configEnv` はデフォルトで null に設定されています。ConfigMap による環境変数のオーバーライドがない場合は、values ファイル内で明示的に `{}` に設定するか、`helm install` または `helm template` に `--set-json 'librechat.configEnv={}'` を渡してください。そうしないと、テンプレート内の `dig` ルックアップが失敗する可能性があります。認証情報は名前付きの Secret に保持してください。これはレンダリング上の回避策であり、Secret の要件を無効にする理由ではありません。
</Callout>

helm chartをインストールするには、以下を実行してください：

`helm install <deployment-name> oci://ghcr.io/librechat-ai/librechat-chart/librechat`

<details>
  <summary>開発バージョン</summary>

リポジトリのルートディレクトリで、以下を実行してください：

`helm install <deployment-name> ./helm/librechat`
</details>

他のHelmチャートと同様に、デフォルト設定の概要と変更可能な設定オプションを示す[valuesファイル](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml)が存在します。

デフォルトから変更したい値を設定した `values.yaml` ファイルを作成します。

Helmチャートをインストールします: `helm install librechat oci://ghcr.io/librechat-ai/librechat-chart/librechat --values <values-override-filel>`

リリースが完了し、サービスにアクセスできるようになったら、[Your First Chat](/docs/quick_start/first_chat) に従ってアカウントを登録し、モデルのAPIキーを追加して、最初のメッセージを送信してください。

## Helm Chart をアンインストールする [#uninstall-the-helm-chart]

Helm Chartをアンインストールするには、`helm uninstall <deployment-name>` を実行します。

例: `helm uninstall librechat`

## 1.x から 2.x への移行 [#migrate-1x---2x]
バージョン 2.x より前のチャートを使用していた場合、`value` 構造を更新する必要があるかもしれません。

1. 設定を librechat.configEnv に移動する:
```diff
- env:
-     ALLOW_EMAIL_LOGIN: "true"
-     ALLOW_REGISTRATION: "true"
+ librechat:
+   configEnv:
+     ALLOW_REGISTRATION: "true"
+     ALLOW_EMAIL_LOGIN: "true"
```

2. [Configuration Step 1](#configuration) で説明されているように、すべての Secret 値を単一の Secret に統合します。
3. 外部のMongoDBインスタンスを活用するには、Chartの[values file](https://github.com/LibreChat-AI/LibreChat/blob/main/helm/librechat/values.yaml)を参照し、それに応じてコンポーネントを無効化し、MongodbインスタンスのFQDNを変更してください。この外部管理されているMongoDBインスタンスに既にデータが存在する場合は、この方法が推奨されます。
