## What's Changed

This release follows [v0.8.9-rc1](/changelog/v0.8.9-rc1). Operator configuration changes in the release candidate are described in [Config v1.3.18](/changelog/config_v1.3.18).

### 🏞️ Highlights

- Chat Projects with shared instructions and reference files
- Passkeys, email changes, and stronger account protection
- Deployment themes and polished chat controls, notifications, and right-to-left layouts
- Opt-in Slack Agents with linked accounts, background responses, approvals, and feedback
- MCP Apps, clearer tool approvals, and deferred system tools through Tool Search
- Highly experimental BYOM: machine enrollment, per-chat workspaces, attachment copies, and PR status
- Inline Ask User questions and more reliable pause, resume, stop, steer, and queue controls
- Recoverable Subagent transcripts and clearer background-task progress
- Langfuse prompts in the catalog, slash command, and Agent instructions
- GPT-6.1 Terra, Claude Fable/Mythos 5.2, GPT Image 2.6 Sunburst/Flare, and approved-access GPT-6 Cyber
- Draft restoration, thinking settings, compaction recovery, and streaming Read Aloud
- Faster chat loading, deferred MCP UI/export libraries, and fewer composer re-renders
- Stronger request, authentication, file-handling, and tool safeguards

### Upgrade Notes

Slack Channels and background Responses are opt-in and require a configured gateway, shared service credentials, and transaction-capable MongoDB. Shared Slack workspace setup additionally requires public HTTPS callbacks. GPT-6 Cyber requires approved provider access. Stateful Code sessions remain highly experimental and require compatible services.
