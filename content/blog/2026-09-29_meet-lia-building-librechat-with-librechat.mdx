I want to introduce Lia. Her name stands for *Libre Inteligencia Artificial*, and she is powered by LibreChat.

Giving an agent a name and an avatar is easy. What matters to me is that I now do much of my agentic coding work on LibreChat **in LibreChat**. The project we have spent years building is becoming a place where we can build the project itself.

When I first described our mission as “AI for Everyone,” I was thinking primarily about people who do not write software or use developer tools in their daily work. I still am. But engineers are part of everyone, too. They should be able to choose their models, control their tools and infrastructure, and see what an agent is doing as it works.

Lia brings those ideas together. She is not a separate product or a claim that the work is finished. She is a way to show what LibreChat's agents can already do, and a direction for the many kinds of agents we want the platform to support.

Every iteration on LibreChat, every new capability gained, can be personified as an extension of Lia's abilities and identity.

## A workspace for agent work

Agentic coding needs more than an agent that can run commands. It needs a code workspace, ways to ask questions and delegate work, boundaries around sensitive actions, and a clear record of what happened.

That is the agent workspace we have been building. Agents can work with [attached code workspaces](/changelog/v0.8.8-rc4), use Skills and tools, ask for clarification, and continue longer-running work. People can follow activity, steer a run, and review execution when approval is required. Attached workspaces remain **highly experimental**; they are useful today, and we are still refining how they work.

We are also developing [durable Agent Events](/changelog/v0.8.8-rc2), including ways for work to reach an agent from outside an active chat. Paired with background execution, this opens the door to agents that respond to an event, do useful work, and report an outcome without requiring someone to start and poll every run manually.

## What the recent releases made possible

The [August](/changelog/v0.8.8-rc1) and [September](/changelog/v0.8.8-rc2) release candidates brought changes that make more sense together than as a long list of features:

- **Agent work is easier to follow.** Activity phases and a [conversation Trace Viewer](/changelog/v0.8.8-rc4) show what happened during a run, including tool steps and costs.
- **People have more ways to participate.** Agents can ask related questions together. Steering and queued follow-ups let people redirect ongoing work, while code approvals establish boundaries before sensitive execution.
- **Longer tasks have better continuity.** Subagents, background work, and context improvements help an agent carry work forward when a task outlasts a single exchange.
- **Coding has a place to happen.** Stateful code sessions and attached workspaces let agents inspect files and work in a chosen environment.
- **LibreChat is easier to extend.** The [Agent Management API](/changelog/v0.8.8-rc3), currently in beta, supports programmatic Agent management, while Skill authoring makes reusable instructions easier to create.

These are highlights, not a substitute for the [full changelog](/changelog). They are the pieces coming together in the work I am doing with Lia.

## A roadmap you can follow

I have not shared enough with the community outside changelogs. I want to change both the visibility of our work and the rhythm in which we discuss it.

We are targeting a release candidate every week and one stable release each month. Those are goals, and we will hold back a stable release when there are known blockers. With each stable release, I also want to hold a virtual town hall where we can discuss what shipped, what did not, and what should come next.

**Our first town hall is Friday, October 2, 2026.** We will share the time and joining details through our [Discord](https://discord.librechat.ai), [X](https://x.com/LibreChatAI), and [LinkedIn](https://www.linkedin.com/company/librechat/) channels. I hope you will join us.

You can follow our priorities and work in progress on the [public roadmap](https://github.com/orgs/LibreChat-AI/projects/1). Our [earlier 2026 roadmap](/blog/2026-02-18_2026_roadmap) focused on nearer-term commitments; the project board gives that conversation a place to keep moving.

## The database direction

One important direction is making **PostgreSQL LibreChat's primary database**, with MongoDB support moving toward maintenance mode. PostgreSQL as the primary database is a **target for v1**, not an announcement that existing deployments must migrate today.

This is partly an open-source consideration, but it is also about what the agent runtime needs. As agent work becomes more durable and concurrent, atomic operations and transactions matter more to the foundation we build on.

We will publish the migration path and the precise support policy for MongoDB before asking operators to act on this direction. Until then, maintenance mode describes our intended direction, not a change to deployment requirements today.

## Beyond chat-shaped AI

I also think we are at an interesting turning point in how AI fits into software. The recent attention around [TypeSafe AI's Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) and the open-weight [Laya](https://github.com/NandhaKishorM/laya) points to a useful distinction: not every model needs to write a response for a person to read. Some can instead make a structured decision that software can act on.

Consider an incoming support request. A generative agent might investigate it and draft a response. A decision model could first classify the request, route it to a queue, or flag it for human review. I am interested in where these approaches produce measurable improvements, and how they might complement the agents people already build in LibreChat.

Openness matters across this whole stack. It includes the ability to choose models and infrastructure, inspect what agents do, and decide where data lives. Better ClickHouse integration for features such as memory and conversation search is part of that longer-term work. So is being candid about database choices and the controls needed for agents that can take action.

Lia is a glimpse of where we are going: a LibreChat that helps people do substantial work with AI while keeping them in control of the process. We are using it to build LibreChat. I want the next stage of that work to be more visible and more open to everyone who wants to help.
